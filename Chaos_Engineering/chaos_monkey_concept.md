# Концепция Chaos Monkey

## Определения

**Chaos Monkey** — это специализированный инструмент и архитектурный паттерн, предназначенный для случайного отключения экземпляров инфраструктуры (виртуальных машин, контейнеров, процессов) в промышленной среде. 

Это основополагающий элемент **[Chaos Engineering](chaos_engineering_overview.md)**, созданный компанией Netflix для проверки способности системы выдерживать отказы отдельных узлов без прерывания обслуживания пользователей.

## Основные концепции

### Ключевые принципы

*   **Устойчивое состояние (Steady State):** Перед началом эксперимента необходимо определить нормальное поведение системы (например, пропускная способность, уровень ошибок, задержка). Если система уже нестабильна, проводить хаос-эксперимент бессмысленно.
*   **Гипотеза:** Формулируется ожидаемое поведение при потере ресурсов. 
    *   *Пример:* «Даже при случайном удалении 20% подов в кластере, 95-й перцентиль задержки (p95) не вырастет более чем на 10%».
*   **Случайность и регулярность:** Отказы происходят в непредсказуемое время в течение рабочего дня. Это вынуждает инженеров проектировать системы, которые по умолчанию готовы к сбою, а не полагаться на ручное вмешательство.
*   **Радиус поражения (Blast Radius):** Масштаб воздействия эксперимента. Chaos Monkey должен начинать с минимально возможного радиуса (один инстанс, один микросервис) и расширять его только после подтверждения устойчивости.
*   **Автоматизация:** Процесс внесения сбоев полностью автономен и интегрирован в жизненный цикл инфраструктуры.

### Виды имитируемых сбоев

| Категория сбоя | Примеры вмешательства | Проверяемые свойства |
|---|---|---|
| **Вычислительные ресурсы** | Удаление VM/подов, SIGKILL процесса, выключение ноды | Самовосстановление (Self-healing), репликация, работа балансировщиков (L4/L7) |
| **Сеть** | Задержки (latency), потеря пакетов, ограничение пропускной способности | Корректность таймаутов, настройки повторных попыток (retries), Circuit Breaker |
| **Хранилище** | Отключение диска, замедление I/O, переполнение раздела | Устойчивость к State-loss, поведение приложений при RO-файловой системе |

## Практические сценарии

### Пример: PodDisruptionBudget и удаление пода в Kubernetes

В Kubernetes «Дух Chaos Monkey» реализуется через ограничение влияния на доступность с помощью `PodDisruptionBudget` (PDB). Подробнее см. [Высокая доступность в Kubernetes](../Kubernetes/Base/high_availability.md) и [PodDisruptionBudget](../Kubernetes/Autoscaling/pod_disruption_budget.md).

**1. Ограничение недоступности (PDB):**
Гарантирует, что Chaos Monkey (или плановые работы) не удалят слишком много реплик одновременно.

```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: frontend-pdb
spec:
  minAvailable: 2 # Минимум 2 пода должны всегда работать
  selector:
    matchLabels:
      app: frontend
```

**2. Реализация нативными средствами (CronJob):**
Простейший вариант имитации Chaos Monkey, который раз в час удаляет случайный под приложения.

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: chaos-monkey-trigger
spec:
  schedule: "0 * * * *"
  jobTemplate:
    spec:
      template:
        spec:
          serviceAccountName: chaos-operator
          containers:
          - name: pod-killer
            image: bitnami/kubectl:latest
            command: ["sh", "-c", "POD=$(kubectl get po -l app=frontend -o jsonpath='{.items[*].metadata.name}' | tr ' ' '\n' | shuf -n1) && kubectl delete pod $POD --wait=false"]
          restartPolicy: OnFailure
```

### Современные реализации для Kubernetes

Вместо самописных скриптов рекомендуется использовать специализированные инструменты, реализующие паттерн Monkey:

1.  **kube-monkey:** Реализация Chaos Monkey для Kubernetes, которая удаляет поды на основе аннотаций в Deployment.
2.  **PowerfulSeal:** Инструмент от Bloomberg, который может убивать поды и ноды, а также проверять состояние кластера после сбоя.
3.  **Chaos Mesh / Litmus:** Полноценные платформы хаос-инженерии с поддержкой CRD.

## Дополнительная информация

### Исторический контекст: Netflix Simian Army

Chaos Monkey был первым «животным» в «Армии обезьян» Netflix. Другие участники:
*   **Latency Monkey:** Имитирует задержки в REST-вызовах.
*   **Janitor Monkey:** Очищает неиспользуемые ресурсы.
*   **Conformity Monkey:** Находит инстансы, не соответствующие стандартам конфигурации.
*   **Chaos Gorilla:** Симулирует отказ целой зоны доступности (Availability Zone).

### Безопасность и мониторинг

*   **Наблюдаемость (Observability):** Эксперимент не имеет смысла без детальных графиков в Prometheus/Grafana. Вы должны видеть отклонение метрик в реальном времени.
*   **SLO-гейты:** Автоматическая остановка (Stop-switch) эксперимента, если уровень ошибок (Error Rate) превышает допустимый порог.
*   **Runbook:** Всегда имейте план ручного восстановления, если автоматика самовосстановления не сработала.
