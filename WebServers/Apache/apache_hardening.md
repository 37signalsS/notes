# Укрепление безопасности Apache

## Определения

**Укрепление безопасности Apache (Apache hardening)** — это процесс настройки веб-сервера с целью уменьшения его поверхности атаки и защиты от распространенных уязвимостей. Основная задача — минимизировать риски путем отключения ненужных функций, ограничения доступа и контроля над ресурсами.

## Основные концепции

### Расположение конфигурационных файлов

- **Основной конфиг (Debian/Ubuntu):** `/etc/apache2/apache2.conf`
- **Основной конфиг (RHEL/CentOS):** `/etc/httpd/conf/httpd.conf`
- **Виртуальные хосты (Debian/Ubuntu):** `/etc/apache2/sites-available/`
- **Виртуальные хосты (RHEL/CentOS):** `/etc/httpd/conf.d/`

### Ключевые модули безопасности

- **`mod_security`** — WAF (Web Application Firewall) для Apache, обеспечивает защиту от SQLi, XSS и других атак на уровне приложений.
- **`mod_headers`** — управление HTTP-заголовками, необходим для реализации CSP, HSTS и других заголовков безопасности.
- **`mod_ssl`** — поддержка SSL/TLS, настройка шифрования и сертификатов.
- **`mod_evasive`** — защита от DoS-атак и brute-force, автоматическая блокировка подозрительных IP.
- **`mod_reqtimeout`** — защита от медленных соединений (Slowloris-атаки), устанавливает таймауты для запросов.

### MPM и безопасность

Apache использует многопоточные модули обработки (MPM), которые влияют на безопасность и производительность:

- **`prefork`** — один процесс на соединение, изоляция запросов, высокое потребление памяти.
- **`worker`** — многопоточная модель, эффективнее по памяти, но сбой в одном потоке может повлиять на другие.
- **`event`** — развитие `worker`, оптимизирован для keep-alive соединений, рекомендуется для высокой нагрузки.

Выбор MPM влияет на поверхность атаки и поведение сервера при DoS-атаках. Подробнее о MPM — в [Обзор Apache](./apache_overview.md).

## Практические сценарии

### Отключение листинга каталогов

**Проблема:** По умолчанию Apache выводит содержимое директорий, если в них отсутствуют индексные файлы (`index.html`, `index.php`). Это раскрывает структуру проекта и упрощает злоумышленнику поиск резервных копий, скриптов и других конфиденциальных файлов.

**Решение:** Отключить листинг каталогов с помощью директивы `Options -Indexes`.

В основном конфигурационном файле (`httpd.conf` или `apache2.conf`) или в файле виртуального хоста добавьте или измените параметр:

```apache
<Directory /var/www/html>
    Options -Indexes
</Directory>
```

### Защита конфиденциальных каталогов

**Проблема:** Служебные страницы, такие как `/server-status` и `/server-info`, предоставляют детальную [мониторинговую информацию](../../Concepts/Observability_and_Monitoring/observability_definitions.md) о работе сервера. Публичный доступ к ним дает злоумышленнику ценные сведения для подготовки атак.

**Решение:** Ограничить доступ к этим URL, разрешив его только для доверенных IP-адресов и, опционально, добавив базовую аутентификацию.

```apache
<Location "/server-status">
  Require ip 192.168.0.0/24
  AuthType Basic
  AuthName "Server status"
  AuthUserFile /etc/apache2/.htpasswd
  Require valid-user
</Location>

<Location "/server-info">
  Require ip 192.168.0.0/24
  AuthType Basic
  AuthName "Server info"
  AuthUserFile /etc/apache2/.htpasswd
  Require valid-user
</Location>
```

### Ограничение размера запроса

**Проблема:** Отправка чрезмерно больших HTTP-запросов может привести к исчерпанию ресурсов сервера (DoS-атака) или переполнению буфера.

**Решение:** Ограничить максимальный размер тела запроса с помощью директивы `LimitRequestBody`.

```apache
<VirtualHost *:80>
    ServerName example.com

    # Ограничение для всего сайта — 100 КБ
    LimitRequestBody 102400

    <Directory "/var/www/uploads">
        # Для каталога загрузки увеличиваем лимит до 10 МБ
        LimitRequestBody 10485760
    </Directory>
</VirtualHost>
```

### Использование пользовательских страниц ошибок

**Проблема:** Стандартные страницы ошибок Apache (404, 500) могут раскрывать техническую информацию, такую как версия сервера или пути в файловой системе.

**Решение:** Заменить стандартные ответы собственными страницами с помощью директивы `ErrorDocument`. Это не только скрывает детали, но и улучшает пользовательский опыт.

```apache
# Пользовательская страница для ошибки 404 (страница не найдена)
ErrorDocument 404 /custom404.html

# Пользовательская страница для ошибки 500 (внутренняя ошибка сервера)
ErrorDocument 500 /custom500.html
```

### Настройка и анализ журналов

**Проблема:** Без детального логирования невозможно отслеживать подозрительную активность, расследовать инциденты и своевременно обнаруживать атаки.

**Решение:** Настроить запись журналов доступа (`AccessLog`) и ошибок (`ErrorLog`), а также их отправку во внешние системы анализа, такие как [SIEM](../../Security/Tools/wazuh.md) или централизованное хранилище логов. Это позволяет проводить глубокий [анализ логов](../../Linux/SystemAdministration/Logging/logging_overview.md).

Для интеграции с SIEM-системами через [syslog](../../Linux/SystemAdministration/Logging/rsyslog.md) можно использовать следующие настройки.

**Формат и уровень логирования (в `httpd.conf` или `apache2.conf`):**

```apache
LogFormat "%h \"%{X-Forwarded-For}i\" %A %p %u %f %t %m %V %U \"%q\" %H %>s %b \"%{Referer}i\" \"%{User-Agent}i\""  tosiem
ErrorLogFormat "[%t] [%l] [pid %P] [client\ %a] %M% , \"%{Referer}i\""
LogLevel info
ErrorLog syslog:local4
```

**Отправка логов доступа в syslog (внутри блока `<VirtualHost>`):**

```apache
CustomLog "|/usr/bin/logger -p local4.info -t apache"  tosiem # Для Ubuntu/Debian
CustomLog "|/usr/bin/logger -p local4.info -t httpd"  tosiem # Для CentOS/RHEL
```

### Скрытие информации о сервере

**Проблема:** По умолчанию Apache может раскрывать в HTTP-заголовках свою версию, тип операционной системы и список подключенных модулей. Эта информация упрощает злоумышленнику подбор эксплоитов под известные уязвимости.

**Решение:** Минимизировать объем отдаваемой информации с помощью директив `ServerTokens` и `ServerSignature`.

В основном конфигурационном файле (`httpd.conf` или `apache2.conf`) добавьте:

```apache
# Устанавливает минимальный уровень детализации в заголовке Server (например, "Server: Apache")
ServerTokens Prod
# Отключает добавление подписи с версией на страницы, генерируемые сервером (например, страницы ошибок)
ServerSignature Off
```

### Реализация политики безопасности контента (CSP)

**Проблема:** Атаки типа Cross-Site Scripting (XSS) позволяют злоумышленникам внедрять вредоносные скрипты на страницы вашего сайта, что может привести к краже данных пользователей.

**Решение:** Использовать HTTP-заголовок `Content-Security-Policy` для строгого контроля над тем, какие ресурсы (скрипты, стили, изображения) браузер может загружать и исполнять.

Для реализации CSP в Apache используется модуль `mod_headers`. Директиву можно размещать как в основном конфигурационном файле, так и внутри виртуального хоста или блока `<Directory>`.

```apache
<Directory "/var/www/html/admin">
    Header set Content-Security-Policy "default-src 'self'; script-src 'self'; object-src 'none'"
</Directory>
```

- `default-src 'self'`: Разрешает загрузку ресурсов только с текущего домена.
- `script-src 'self'`: Разрешает выполнение скриптов только с текущего домена.
- `object-src 'none'`: Запрещает загрузку плагинов (например, Flash), что является хорошей практикой безопасности.

**Важно:** Слишком строгая политика может заблокировать работу легитимных сторонних виджетов или аналитики. Внедряйте CSP постепенно, тестируя конфигурацию.

### Настройка надежной конфигурации SSL/TLS

**Проблема:** Использование устаревших протоколов (SSLv3, TLS 1.0, TLS 1.1) и слабых шифров делает HTTPS-соединение уязвимым для атак "человек посередине" (MitM).

**Решение:** Разрешить только современные, безопасные протоколы и наборы шифров, а также настроить принудительное перенаправление всего трафика на HTTPS.

В файле конфигурации SSL (часто `ssl.conf` или внутри `<VirtualHost *:443>`) укажите:

```apache
# Разрешить все протоколы, но явно запретить старые и уязвимые
SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1
# Использовать только надежные наборы шифров, исключая небезопасные
SSLCipherSuite HIGH:!aNULL:!MD5
```

Для перенаправления с HTTP на HTTPS добавьте в конфигурацию виртуального хоста для 80-го порта:

```apache
<VirtualHost *:80>
    ServerName example.com
    Redirect "/" "https://example.com/"
</VirtualHost>
```

### Отключение ненужных HTTP-методов

**Проблема:** Методы, такие как `TRACE`, `PUT`, `DELETE`, редко требуются для обычного веб-сайта, но могут быть использованы для атак (например, Cross-Site Tracing).

**Решение:** Явно разрешить только необходимые методы (`GET`, `POST`, `HEAD`) с помощью блока `<LimitExcept>`.

```apache
<Directory "/var/www/html">
    <LimitExcept GET POST HEAD>
        Require all denied
    </LimitExcept>
</Directory>
```

Это правило запретит все методы, кроме перечисленных, для указанной директории, снижая поверхность атаки.
