# Apache HTTP Server

## Определения

**Apache HTTP Server** (часто называемый просто Apache) — это один из самых популярных веб-серверов в мире, известный своей гибкостью, мощностью и широким набором функций. Он обрабатывает запросы клиентов по протоколам [HTTP/HTTPS](../../Networking/Protocols/HTTP/http_versions.md) и отдает им веб-контент.

## Основные концепции

### Конфигурационные файлы

Основная конфигурация Apache находится в текстовых файлах. Расположение зависит от операционной системы:

* **Ubuntu/Debian:** `/etc/apache2/apache2.conf`
* **CentOS/RHEL:** `/etc/httpd/conf/httpd.conf`

**Структура конфигурации:**

* **/etc/httpd/conf/httpd.conf**: Основной файл конфигурации.
* **/etc/httpd/conf.d/**: Директория для дополнительных конфигурационных файлов (`.conf`). Apache автоматически подгружает все файлы из этой директории. Это стандартная практика для разделения конфигурации на логические части (например, для каждого сайта).

**Ключевые директивы в `httpd.conf`:**

* **`ServerRoot`**: Определяет корневую директорию, где хранятся конфигурационные файлы сервера, логи и другие ресурсы. По умолчанию часто `/etc/httpd`.
* **`Listen`**: Указывает IP-адрес и порт, на котором Apache будет прослушивать входящие соединения. По умолчанию `Listen 80`.
* **`User apache`, `Group apache`**: Пользователь и группа, от имени которых будут работать дочерние процессы Apache. В системах с SELinux, корректный [контекст безопасности](../../Linux/Security/Mechanisms/SELinux.md) является критически важным для доступа к файлам.
* **`DocumentRoot`**: Определяет корневую директорию для файлов веб-сайта. По умолчанию `/var/www/html`.
* **`Include`** / **`IncludeOptional`**: Позволяет включать другие конфигурационные файлы (например, `IncludeOptional conf.d/*.conf`), что используется для модульной организации, например, для виртуальных хостов.

### Виртуальные хосты

Для размещения нескольких сайтов на одном сервере используются **виртуальные хосты**. Их конфигурации обычно размещаются в отдельных файлах в директории `conf.d/`.

**Пример файла `/etc/httpd/conf.d/site1.conf`:**

```apacheconf
<VirtualHost *:8080>
    ServerName site1.example.com
    DocumentRoot /var/www/site1
</VirtualHost>
```

Чтобы Apache начал слушать дополнительный порт, необходимо также добавить директиву `Listen 8080` в основной `httpd.conf`.

### Файлы `.htaccess`

Файлы `.htaccess` — это распределенные конфигурационные файлы, которые позволяют управлять настройками сервера на уровне отдельных директорий.

* **Преимущества:** Позволяют делегировать управление частью конфигурации разработчикам без доступа к основным файлам.
* **Недостатки:** Снижают производительность, так как Apache ищет и обрабатывает `.htaccess` в каждой директории при каждом запросе.

В отличие от Apache, Nginx не поддерживает аналог `.htaccess`. Вся конфигурация для Nginx должна быть явно прописана в основных файлах конфигурации, что делает его более производительным, но менее гибким для хостинг-сред.

## Практические сценарии

### Установка

**CentOS/RHEL:**

```bash
sudo yum install httpd
# или
sudo dnf install httpd

```

**Ubuntu/Debian:**

```bash
sudo apt update && sudo apt -y install apache2
```

Установка и базовая настройка могут быть автоматизированы с помощью [Ansible](../../Ansible/PlaybookStructure/basics.md).

### Управление службой

После установки служба `httpd` не запускается автоматически (на CentOS/RHEL). Для управления ею используется [systemctl](../../Linux/Core/systemd/service_management.md).

1. **Проверить статус службы:**

    ```bash
    sudo systemctl status httpd
    # ● httpd.service - The Apache HTTP Server
    #    Loaded: loaded (/usr/lib/systemd/system/httpd.service; disabled; vendor preset: disabled)
    #    Active: inactive (dead)
    ```

    Статус `inactive (dead)` означает, что служба установлена, но не запущена.

2. **Запустить службу:**

    ```bash
    sudo systemctl start httpd      # Запустить (на Debian/Ubuntu служба называется apache2)
    ```

3. **Проверить, что служба слушает 80-й порт:** Подробнее об утилите см. [**`ss`**](../../Linux/Diagnostics/Networking/ss.md).

    ```bash
    sudo ss -tlpn | grep httpd
    # LISTEN    0      128          *:80                   *:*      users:(("httpd",pid=...))
    ```

4. **Включить автозапуск при загрузке системы:**

    ```bash
    sudo systemctl enable httpd     # Добавить в автозагрузку
    ```

    Другие команды:

    ```bash
    sudo systemctl stop httpd       # Остановить
    sudo systemctl restart httpd    # Перезапустить
    sudo systemctl reload httpd     # Перечитать конфигурацию
    sudo systemctl disable httpd    # Убрать из автозагрузки
    ```

*Примечание: На Ubuntu и Debian службы обычно запускаются и добавляются в автозагрузку автоматически после установки.*

### Настройка Firewall (CentOS)

```bash
sudo firewall-cmd --permanent --zone=public --add-service=http --add-service=https
sudo firewall-cmd --reload
```

### Проверка работы

Откройте IP-адрес сервера в браузере — должна отобразиться стартовая страница Apache.

## Дополнительная информация

### Архитектура и Multi-Processing Modules (MPM)

Apache использует модульную архитектуру для обработки клиентских запросов — **Multi-Processing Modules (MPM)**.

* **`Prefork`**: Создает дочерние процессы, каждый из которых обрабатывает одно соединение. Стабилен, но потребляет много памяти при большом количестве соединений.
* **`Worker`**: Использует дочерние процессы, каждый из которых запускает несколько потоков. Каждый поток обрабатывает одно соединение. Более эффективен по памяти, чем `Prefork`.
* **`Event`**: Развитие `Worker` MPM, оптимизированное для обработки keep-alive соединений. Он использует асинхронный подход, позволяя одному потоку обрабатывать несколько неактивных соединений, что значительно улучшает масштабируемость.
