# Мониторинг Angie — возможности Angie Pro

## Определения

**Angie Pro** — коммерческая версия веб-сервера Angie, включающая расширенный функционал мониторинга, динамического управления конфигурацией и приоритетную техническую поддержку. Предназначена для enterprise-решений, требующих высокой доступности и гибкого управления трафиком.

## Базовые концепции

### Ключевые отличия мониторинга в Angie Pro

| Функция | Open Source | Angie Pro |
|:--------|:------------|:----------|
| Динамическое управление upstream | Нет | Да, через API с `write=on` |
| Время ответа от апстрима (`upstream response time`) | Модуль `metric` | Встроено в API |
| Активные проверки (`health_check`) | Модуль `check` | Встроено (`health_check`) |
| Продвинутая балансировка (`feedback`) | Нет | Да |
| Модуль `metric` (пользовательские метрики) | Да | Да |
| Console Lite | Да | Да |

### Динамическое управление upstream

Параметр `write=on` в директиве `api` позволяет изменять состояние групп серверов в реальном времени. Это исключает необходимость выполнения `reload` при выводе серверов из ротации или изменении их весов, что критично для систем с высокой нагрузкой.

### Расширенные метрики производительности

Angie Pro предоставляет детальную статистику по времени ответа вышестоящих серверов (`upstream_response_time`). В отличие от Open Source версии, где для этого требуется настройка пользовательских метрик, в Pro-версии эти данные доступны в API по умолчанию для всех зон статуса.

### Продвинутые алгоритмы балансировки

Метод **feedback** позволяет выбирать сервер на основе его текущей производительности (время ответа) или системных показателей (Load Average). Это обеспечивает более интеллектуальное распределение нагрузки по сравнению со стандартными алгоритмами.

## Практические сценарии

### Сценарий 1: Управление состоянием сервера через API

Включение режима записи в конфигурации:

```nginx
http {
    api write=on;

    upstream app_servers {
        zone app_servers 64k;
        server 192.168.1.10:8080;
        server 192.168.1.11:8080;
    }
}
```

Вывод сервера из эксплуатации (drain):

```bash
curl -X POST http://monitor.example.com:8888/status/upstreams/app_servers/servers/192.168.1.11:8080/drain
# → { "state": "drain" }
```

### Сценарий 2: Плавное изменение веса сервера

```bash
curl -X PUT http://monitor.example.com:8888/status/upstreams/app_servers/servers/192.168.1.10:8080 \
  -H "Content-Type: application/json" \
  -d '{"weight": 10}'
# → { "weight": 10, "state": "up" }
```

### Сценарий 3: Настройка активных проверок (health_check)

В Angie Pro используется синтаксис, совместимый с Nginx Plus, для фонового мониторинга бэкендов:

```nginx
upstream api_cluster {
    zone api_cluster 64k;
    server 10.0.0.1:8080;
    
    # Активная проверка по эндпоинту /health
    health_check interval=5s fails=3 passes=2 uri=/health;
}
```

## Дополнительная информация

### Версионность и доступность

- Динамическое управление через API — доступно с Angie Pro 1.5.0.
- Метрики времени ответа — доступны с Angie Pro 1.6.0.
- Совместимость: Angie Pro полностью поддерживает конфигурации Open Source версии.

### Сравнение с Open Source

Для реализации схожего функционала в бесплатной версии используются альтернативные механизмы:

- Активные проверки: модуль `check` (сторонний или встроенный в сборку).
- Метрики времени ответа: через [создание пользовательских метрик](./angie_monitoring_custom_metrics.md).
