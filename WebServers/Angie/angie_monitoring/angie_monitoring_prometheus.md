# Мониторинг Angie — интеграция с Prometheus

## Определения

**Prometheus** — система мониторинга с открытым исходным кодом, использующая модель сбора данных (pull model) и язык запросов PromQL.

**Нативный экспорт метрик** — встроенная в ядро Angie функциональность (`ngx_http_prometheus_module`), позволяющая отдавать статистику сервера напрямую в формате Prometheus. Это исключает необходимость использования внешних экспортеров или скриптов на `njs`.

**Модуль `metric`** — компонент Angie (начиная с версии 1.11.0), позволяющий создавать произвольные метрики, гистограммы и рассчитывать APDEX на основе переменных сервера в реальном времени.

## Базовые концепции

### Архитектура сбора данных

```
Angie (экспорт) → Prometheus (хранение) → Grafana (визуализация)
```

1. **Angie:** Собирает данные из зон разделяемой памяти (`status_zone`, `metric_zone`) и формирует текстовый ответ в формате OpenMetrics.
2. **Prometheus:** Периодически опрашивает (scrape) эндпоинт Angie (обычно `/p8s` или `/metrics`), сохраняя данные в TSDB.
3. **Grafana:** Визуализирует данные, используя Prometheus как источник.

### Шаблоны и директивы

Для работы экспорта необходимо два условия:
- **`include prometheus_all.conf;`** — подключает стандартные определения метрик (поставляется с пакетом `angie`). Без этого директива `prometheus` не будет знать, какие данные собирать.
- **Директива `prometheus`** — активирует отдачу данных в конкретном `location`.

### Поддерживаемые типы данных

- **HTTP (L7):** Статистика по `status_zone` (запросы, коды ответов, время обработки).
- **Stream (L4):** Статистика по `status_zone` в контексте `stream` (соединения, байты).
- **Кастомные метрики:** Гистограммы времени ответа, счетчики специфических событий через `metric_zone`.

## Практические сценарии

### Сценарий 1: Базовая настройка эндпоинта (HTTP)

Активация сбора всех стандартных метрик для сервера.

```nginx
http {
    # 1. Подключаем шаблоны метрик (обычно в http контексте)
    include prometheus_all.conf;

    server {
        listen 80;
        server_name example.com;
        
        # 2. Объявляем зону для сбора статистики
        status_zone server_zone;

        # 3. Эндпоинт для Prometheus
        location = /p8s {
            prometheus all;
            
            # Безопасность
            allow 192.168.1.50; # IP Prometheus
            deny all;
        }
    }
}
```

### Сценарий 2: Мониторинг TCP/UDP (Stream)

Angie позволяет отдавать метрики L4-трафика через тот же HTTP-эндпоинт.

```nginx
stream {
    upstream dns_servers {
        zone dns_zone 64k;
        server 8.8.8.8:53;
    }

    server {
        listen 53 udp;
        status_zone dns_frontend;
        proxy_pass dns_servers;
    }
}
```
*После настройки эндпоинта из Сценария 1, метрики `angie_stream_server_*` появятся автоматически.*

### Сценарий 3: Создание гистограмм и расчет APDEX

Использование `metric_zone` для отслеживания распределения времени ответа.

```nginx
http {
    # Определяем зону-гистограмму с бакетами (в секундах)
    metric_zone rt_hist:10m histogram 0.1 0.5 1.0 5.0;

    server {
        listen 80;
        
        # Записываем время ответа в зону
        metric rt_hist $server_name = $request_time;

        location / {
            proxy_pass http://backend;
        }
    }
}
```

### Сценарий 4: Визуализация в Grafana

1. **Dashboard ID:** Используйте официальный дашборд для Angie — **20719**.
2. **PromQL для APDEX:**
   ```promql
   (sum(rate(angie_metric_rt_hist_bucket{le="0.5"}[5m])) + 
    sum(rate(angie_metric_rt_hist_bucket{le="2.0"}[5m]))) / 2 / 
    sum(rate(angie_metric_rt_hist_count[5m]))
   ```

## Дополнительная информация

### Сравнение с Nginx

| Характеристика | Nginx (OSS) | Angie (OSS) |
|:---|:---|:---|
| **Экспорт** | Требует `nginx-prometheus-exporter` | Нативный (модуль `prometheus`) |
| **Кастомные метрики** | Через `njs` (сложно) | Нативные `metric_zone` (просто) |
| **Производительность** | Накладные расходы на парсинг /status | Прямое чтение из Shared Memory |

### Безопасность и фильтрация

Директива `prometheus` позволяет фильтровать отдаваемые данные для экономии ресурсов:
- `prometheus all status=404;` — отдаст только метрики, связанные с 404 ошибками.
- **Рекомендация:** Всегда используйте TLS и базовую аутентификацию, если эндпоинт `/p8s` доступен вне доверенной сети.
