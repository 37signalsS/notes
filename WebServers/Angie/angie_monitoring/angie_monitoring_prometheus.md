# Мониторинг Angie — Интеграция с Prometheus

## Определения

**Prometheus Exporter** — компонент, преобразующий внутренние метрики приложения в формат, понятный системе мониторинга Prometheus. В Angie экспорт метрик реализован **нативно** на уровне ядра и не требует использования внешних модулей или скриптов (в отличие от NGINX, где для аналогичной задачи применяется `njs` или отдельный `nginx-exporter`).

**Scrape** — процесс сбора метрик сервером Prometheus с настроенных эндпоинтов целевых систем.

## Базовые концепции

### Архитектура интеграции

```
Angie (/metrics) → Prometheus (scrape) → Grafana (визуализация)
```

1. **Angie** предоставляет метрики через HTTP-эндпоинт в формате, совместимом с Prometheus
2. **Prometheus** периодически опрашивает (scrape) этот эндпоинт и сохраняет временные ряды
3. **Grafana** подключается к Prometheus как к источнику данных и строит дашборды

### Модуль prometheus.conf

Для работы экспорта метрик необходимо, чтобы в основном конфигурационном файле `angie.conf` был подключён шаблон `prometheus.conf`. Этот шаблон определяет набор доступных метрик и их форматирование.

### Доступные метрики

Angie предоставляет следующие категории метрик:

- **HTTP-запросы:** количество запросов, статус-коды, время ответа
- **Соединения:** активные соединения, чтение/запись, ожидание
- **Upstream-серверы:** состояние бэкендов, время отклика, ошибки
- **Кэш:** hit/miss/expire, размер кэша
- **TLS:** количество рукопожатий, ошибки сертификатов

## Практический сценарий: Настройка интеграции

### Шаг 1: Настройка эндпоинта в Angie

Создайте защищённый `location`, который будет экспортировать метрики в формате Prometheus. Доступ к эндпоинту следует ограничить по IP-адресу сервера Prometheus.

```nginx
server {
    listen 80;
    # ...
    location = /metrics {
        prometheus all; # Экспорт всех метрик из шаблона "all"
        allow 127.0.0.1; # IP-адрес сервера Prometheus
        deny all;
    }
}
```

> **Примечание:** убедитесь, что в `angie.conf` подключён шаблон `prometheus.conf`.

### Шаг 2: Настройка Prometheus

Добавьте в `prometheus.yml` новую задачу для сбора метрик с сервера Angie.

```yaml
scrape_configs:
  - job_name: 'angie'
    metrics_path: /metrics
    scrape_interval: 15s
    static_configs:
      - targets: ['localhost:80'] # Адрес сервера Angie
```

Параметр `scrape_interval` определяет частоту опроса. Значение `15s` является стандартным для большинства сценариев.

### Шаг 3: Визуализация в Grafana

1. Подключите Prometheus как источник данных в Grafana
2. Импортируйте официальный дашборд Angie, используя ID `2719` из [репозитория Grafana](https://grafana.com/grafana/dashboards/2719)
3. При необходимости настройте алерты на критические метрики (ошибки 5xx, время отклика upstream)

## Дополнительная информация

### Безопасность эндпоинта метрик

Эндпоинт `/metrics` раскрывает внутреннюю структуру сервера. Обязательные меры защиты:

- Ограничение доступа по IP (`allow`/`deny`)
- При передаче через ненадёжную сеть — использование TLS (`https://`)
- Не размещать эндпоинт в публичном доступе без аутентификации

### Отличия от NGINX

| Характеристика | NGINX | Angie |
|:---|:---|:---|
| Экспорт метрик | Требуется `njs` или внешний `nginx-prometheus-exporter` | Нативная директива `prometheus` |
| Зависимости | Внешние модули, отдельный процесс | Встроено в ядро |
| Производительность | Дополнительные накладные расходы | Минимальное влияние |
