# Мониторинг Angie — интеграция с Prometheus

## Определения

**Prometheus** — система мониторинга с открытым исходным кодом, использующая модель сбора данных (pull model) и язык запросов PromQL.

**Нативный экспорт метрик** — встроенная в ядро Angie функциональность для предоставления статистики в формате Prometheus. В отличие от Nginx, Angie не требует использования внешних модулей (njs) или сторонних утилит-экспортеров.

**Scrape (сбор)** — процесс периодического опроса эндпоинта Angie сервером Prometheus для получения актуальных значений метрик.

## Базовые концепции

### Архитектура сбора данных

```
Angie (экспорт) → Prometheus (хранение) → Grafana (визуализация)
```

1. **Angie:** собирает внутреннюю статистику в разделяемой памяти и отдает ее через HTTP по запросу.
2. **Prometheus:** выполняет HTTP-запрос (scrape) к эндпоинту Angie, парсит данные и сохраняет их в свою базу данных временных рядов (TSDB).
3. **Grafana:** запрашивает данные из Prometheus и отображает их на графиках и дашбордах.

### Конфигурационные шаблоны

Для работы экспорта в Angie используется механизм шаблонов. Основной шаблон `prometheus.conf` (обычно поставляется в комплекте с пакетом) определяет структуру и набор экспортируемых метрик. Для активации необходимо подключить этот шаблон в `angie.conf`.

### Группы метрик

Angie экспортирует широкий спектр данных:

- **Состояние соединений:** активные, принятые, сброшенные.
- **HTTP-статистика:** количество запросов по статус-кодам (2xx, 4xx, 5xx), трафик.
- **Upstream-группы:** доступность бэкендов, время ответа, количество активных соединений с ними.
- **Кэширование:** эффективность попадания в кэш (hit/miss), использование памяти.

## Практические сценарии

### Сценарий 1: Настройка эндпоинта экспорта в Angie

Необходимо создать `location` и активировать в нем экспорт. Рекомендуется ограничить доступ только для сервера мониторинга.

```nginx
server {
    listen 80;
    server_name monitor.local;

    location /metrics {
        # 'all' — стандартное имя шаблона в prometheus.conf
        prometheus all;
        
        # Ограничение доступа
        allow 192.168.1.50; # IP сервера Prometheus
        deny all;
    }
}
```

### Сценарий 2: Настройка сбора в Prometheus

Добавьте конфигурацию в `prometheus.yml` для опроса сервера Angie:

```yaml
scrape_configs:
  - job_name: 'angie_production'
    metrics_path: '/metrics'
    scrape_interval: 15s
    static_configs:
      - targets: ['angie-node-01.local:80']
```

### Сценарий 3: Визуализация в Grafana

1. Добавьте Prometheus как источник данных (Data Source).
2. Используйте готовый дашборд из репозитория Grafana (например, ID `2719`).
3. Настройте алерты (например, на рост количества 5xx ошибок или увеличение времени ответа апстримов).

## Дополнительная информация

### Сравнение с Nginx

| Функция | Nginx | Angie |
|:---|:---|:---|
| Способ экспорта | Внешний экспортер или njs | Нативный (ядро) |
| Конфигурация | Сложная (сторонние зависимости) | Простая (одна директива) |
| Производительность | Выше накладные расходы | Минимальное влияние |

### Безопасность

Метрики содержат чувствительную информацию об инфраструктуре (IP-адреса апстримов, пути запросов). Эндпоинт метрик **не должен** быть доступен из публичной сети. В случае передачи данных через интернет используйте HTTPS и базовую аутентификацию.
