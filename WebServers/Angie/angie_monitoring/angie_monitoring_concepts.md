# Мониторинг Angie — основные концепции

## Определения

**Мониторинг Angie** — процесс сбора и анализа метрик состояния веб-сервера в режиме реального времени. В отличие от базового модуля `stub_status` в Nginx, Angie предоставляет расширенный HTTP API, отдающий данные в формате JSON (JavaScript Object Notation).

**Зона статуса (status_zone)** — именованная область в разделяемой памяти (Shared Memory), предназначенная для хранения статистических данных. Без объявления зоны сбор детальных метрик для конкретных объектов (серверов, локаций, апстримов) не производится.

## Базовые концепции

### Сравнение API и анализа логов

Традиционный мониторинг через парсинг логов (например, с помощью `grok` или `vector`) имеет ряд ограничений, которые решает встроенный API:

1. **Мгновенный отклик:** Логи записываются только после завершения запроса. API позволяет видеть активные (inflight) запросы в момент их обработки.
2. **Внутреннее состояние:** API открывает доступ к метрикам, которые не попадают в логи: состояние зон разделяемой памяти, эффективность кэширования в реальном времени, статусы рабочих процессов.
3. **Точность:** Встроенный сбор метрик производится непосредственно в ядре сервера, что исключает ошибки парсинга и задержки, характерные для лог-менеджмента.

### Типы собираемых данных

Для активации сбора статистики необходимо определить зоны в соответствующих блоках конфигурации:

- **Виртуальные серверы и локации:** директива `status_zone` активирует счетчики запросов, ответов, трафика и времени обработки.
- **Группы вышестоящих серверов (upstream):** директива `zone` в блоке `upstream` позволяет отслеживать состояние каждого бэкенда, количество ошибок и время отклика.
- **Кэширование:** параметр `keys_zone` в `proxy_cache_path` позволяет мониторить hit/miss коэффициент и заполнение дискового кэша.

### Инструменты визуализации

1. **Интерактивный уровень:** [Angie Console Lite](./angie_monitoring_console.md) предоставляет веб-интерфейс для оперативной диагностики и мониторинга «в один клик».
2. **Уровень аналитики:** [Интеграция с Prometheus](./angie_monitoring_prometheus.md) и Grafana используется для долгосрочного хранения метрик, построения трендов и настройки системы оповещений.

## Практические сценарии

### Сценарий 1: Активация мониторинга для виртуального сервера

Для сбора статистики по всему серверу необходимо добавить `status_zone` в блок `server`:

```nginx
server {
    listen 80;
    server_name example.com;

    # Имя зоны будет отображаться в API и Console Lite
    status_zone server_example_com;

    location / {
        proxy_pass http://backend;
    }
}
```

### Сценарий 2: Детальный мониторинг критического пути

Если необходимо отслеживать конкретную локацию отдельно от общего сервера:

```nginx
server {
    status_zone main_api;

    location /api/v2/payments {
        # Статистика по платежам будет выделена в отдельный блок в API
        status_zone payments_api;
        proxy_pass http://payment_gate;
    }
}
```

### Сценарий 3: Контроль состояния апстримов

```nginx
upstream backend_cluster {
    # Зона обязательна для работы расширенных алгоритмов балансировки
    zone backend_cluster_zone 64k;
    server 10.0.0.1:8080;
    server 10.0.0.2:8080;
}
```

## Дополнительная информация

### Ресурсы и ограничения

- **Разделяемая память:** Каждая зона потребляет фиксированный объем памяти. Размер зоны (например, `64k`) определяет, сколько записей о состоянии объектов может храниться одновременно.
- **Производительность:** Сбор метрик через `status_zone` оптимизирован и оказывает минимальное влияние на задержки (overhead) при обработке трафика.
