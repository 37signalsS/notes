# Мониторинг Angie — основные концепции

## Определения

**Мониторинг Angie** — комплексный процесс непрерывного сбора, агрегации и визуализации метрик состояния веб-сервера. В отличие от традиционного модуля `stub_status` в Nginx, Angie предоставляет полноценный REST API и нативный механизм экспорта данных, что позволяет интегрировать сервер в современные Observability-стеки без использования внешних агентов-экспортеров.

**Зона статуса (status_zone)** — именованный сегмент в разделяемой памяти (Shared Memory), предназначенный для хранения атомарных счетчиков и структур данных мониторинга. Директива `status_zone` активирует сбор метрик для конкретных виртуальных хостов, локаций или групп апстримов.

**Shared Memory (Разделяемая память)** — область оперативной памяти, доступная всем рабочим процессам (worker processes) сервера. Это критически важный компонент для согласованности метрик, так как каждый воркер инкрементирует счетчики в общей области, что позволяет получать единую картину состояния всего сервера.

## Базовые концепции

### Сравнение API-мониторинга и анализа логов

В архитектуре SRE-мониторинга Angie встроенный API решает задачи, недоступные классическому анализу Access-логов:

1. **In-flight запросы:** Возможность видеть количество запросов, которые обрабатываются прямо сейчас. Логи фиксируют событие только по факту завершения транзакции.
2. **Здоровье бэкендов:** Прямой мониторинг состояния серверов в `upstream` (up/down/unhealthy/draining), включая результаты активных проверок.
3. **Эффективность кэша:** Real-time статистика попаданий в кэш (`HIT/MISS/EXPIRED/STALE`), доступная до записи в лог.
4. **Низкий Overhead:** Сбор метрик в памяти требует значительно меньше CPU и I/O ресурсов по сравнению с записью и последующим парсингом текстовых файлов.

### Архитектура сбора данных

Мониторинг в Angie организован по иерархическому принципу:
- **L4 (Stream):** Метрики транспортного уровня (соединения, байты, ошибки TCP/UDP).
- **L7 (HTTP):** Метрики прикладного уровня (HTTP-методы, коды ответов, задержки).
- **Внутреннее состояние:** Версия сервера, аптайм, нагрузка на зоны памяти и состояние поколений конфигурации.

### Расчет ресурсов разделяемой памяти

Размер зоны (например, `zone status_zone 64k`) является важным параметром тюнинга.
- Минимальный размер зоны в Angie составляет 64 КБ.
- В зоне объемом 64 КБ может храниться статистика примерно для 20–30 уникальных объектов (например, серверов в апстриме).
- Для крупных инсталляций (сотни апстримов) рекомендуется выделять от 1 МБ до 10 МБ на зону.

## Практические сценарии

### Сценарий 1: Глобальный мониторинг HTTP сервера

Активация сбора базовых метрик (запросы, трафик, коды ответов) для всего виртуального хоста.

```nginx
server {
    listen 80;
    server_name production.example.com;

    # Активация сбора статистики для данного сервера
    status_zone production_vhost;

    location / {
        proxy_pass http://app_cluster;
    }
}
```

### Сценарий 2: Детализация метрик по критическим локациям

Позволяет отделить статистику API от статического контента в рамках одного сервера.

```nginx
server {
    status_zone main_site;

    location /api/v1/ {
        # Данная локация будет иметь собственные счетчики в API
        status_zone api_v1_critical;
        proxy_pass http://api_backend;
    }

    location /static/ {
        # Статика учитывается только в main_site
        root /var/www/static;
    }
}
```

### Сценарий 3: Мониторинг групп апстримов (L7)

Обязательное условие для отображения бэкендов в [Console Light](./angie_monitoring_console.md).

```nginx
upstream app_cluster {
    # Зона разделяемой памяти для всей группы
    zone app_cluster 128k;
    
    server 10.0.0.1:8080 weight=5;
    server 10.0.0.2:8080 weight=1;
    
    # Режим вывода сервера из эксплуатации через API
    server 10.0.0.3:8080 backup;
}
```

### Сценарий 4: Контроль состояния TCP/UDP сервисов (L4)

```nginx
stream {
    server {
        listen 5432; # PostgreSQL Proxy
        status_zone postgres_proxy;
        proxy_pass pg_cluster;
    }
}
```

## Дополнительная информация

### Инструменты визуализации и интеграции

- **[Console Light](./angie_monitoring_console.md):** Встроенный веб-интерфейс для оперативного контроля "здесь и сейчас".
- **[Prometheus](./angie_monitoring_prometheus.md):** Нативный экспорт метрик для долгосрочного хранения и алертинг.
- **[OpenTelemetry](./angie_monitoring_otel.md):** Интеграция трассировки и метрик в распределенные системы.

### Рекомендации по эксплуатации

1. **Именование зон:** Используйте префиксы (`http_`, `stream_`, `up_`) для быстрого поиска зон в больших JSON-ответах API.
2. **Безопасность:** Доступ к API (`location /api`) всегда должен быть ограничен по IP или защищен аутентификацией.
3. **Персистентность:** Помните, что метрики в разделяемой памяти сбрасываются при полной остановке сервера (stop/start), но сохраняются при `reload`.
