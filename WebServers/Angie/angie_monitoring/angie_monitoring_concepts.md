# Мониторинг Angie — основные концепции

## Определения

**Мониторинг Angie** — процесс сбора и анализа метрик состояния веб-сервера в режиме реального времени. В отличие от базового модуля `stub_status` в Nginx, Angie предоставляет расширенный HTTP API и нативный экспорт в формате Prometheus.

**Зона статуса (status_zone)** — именованная область в разделяемой памяти (Shared Memory), предназначенная для хранения статистических данных. Без объявления зоны сбор детальных метрик для конкретных объектов (серверов, локаций, апстримов) не производится. Зоны могут быть созданы как для HTTP (L7), так и для Stream (L4) контекстов.

**Нативный экспорт Prometheus** — встроенный функционал Angie (`ngx_http_prometheus_module`), позволяющий отдавать метрики в формате, понятном Prometheus, без использования сторонних экспортеров (например, `nginx-prometheus-exporter`).

## Базовые концепции

### Сравнение API и анализа логов

Традиционный мониторинг через парсинг логов (например, с помощью `grok` или `vector`) имеет ряд ограничений, которые решает встроенный API:

1. **Мгновенный отклик:** Логи записываются только после завершения запроса. API позволяет видеть активные (inflight) запросы в момент их обработки.
2. **Внутреннее состояние:** API открывает доступ к метрикам, которые не попадают в логи: состояние зон разделяемой памяти, эффективность кэширования в реальном времени, статус поколений (generation) рабочих процессов.
3. **Точность:** Встроенный сбор метрик производится непосредственно в ядре сервера, что исключает ошибки парсинга и задержки, характерные для лог-менеджмента.

### Типы собираемых данных

Для активации сбора статистики необходимо определить зоны в соответствующих блоках конфигурации:

- **Виртуальные серверы и локации (HTTP):** директива `status_zone` активирует счетчики запросов, ответов, трафика и времени обработки.
- **TCP/UDP серверы (Stream):** директива `status_zone` в блоке `server` контекста `stream` позволяет отслеживать количество соединений и объем переданного трафика на уровне L4.
- **Группы вышестоящих серверов (upstream):** директива `zone` в блоке `upstream` позволяет отслеживать состояние каждого бэкенда, количество ошибок и время отклика.
- **Кэширование:** параметр `keys_zone` в `proxy_cache_path` позволяет мониторить hit/miss коэффициент и заполнение дискового кэша.

### Уровни визуализации

1. **Оперативный (Real-time):** [Angie Console Light](./angie_monitoring_console.md) предоставляет встроенный веб-интерфейс для мгновенной диагностики состояния узла.
2. **Аналитический (Time-series):** [Интеграция с Prometheus](./angie_monitoring_prometheus.md) позволяет собирать исторические данные, строить графики в Grafana и настраивать алертинг.

## Практические сценарии

### Сценарий 1: Активация мониторинга для HTTP сервера

Для сбора статистики по всему серверу необходимо добавить `status_zone` в блок `server`:

```nginx
server {
    listen 80;
    server_name example.com;

    # Имя зоны будет отображаться в API и Console Light
    status_zone server_example_com;

    location / {
        proxy_pass http://backend;
    }
}
```

### Сценарий 2: Мониторинг TCP/UDP потоков (L4)

В контексте `stream` зона статуса позволяет видеть нагрузку на конкретные порты.

```nginx
stream {
    server {
        listen 12345;
        # Создает зону для мониторинга L4 трафика
        status_zone stream_gateway;
        proxy_pass backend_cluster;
    }
}
```

### Сценарий 3: Детальный мониторинг критического пути (HTTP)

Если необходимо отслеживать конкретную локацию отдельно от общего сервера:

```nginx
server {
    status_zone main_api;

    location /api/v2/payments {
        # Статистика по платежам будет выделена в отдельный блок в API
        status_zone payments_api;
        proxy_pass http://payment_gate;
    }
}
```

### Сценарий 4: Активация нативного эндпоинта Prometheus

Для отдачи метрик напрямую в Prometheus используется директива `prometheus`.

```nginx
http {
    # Подключение стандартных шаблонов метрик Angie
    include prometheus_all.conf;

    server {
        listen 8080;
        
        location /metrics {
            # Активация экспорта всех собранных метрик
            prometheus all;
        }
    }
}
```

## Дополнительная информация

### Ресурсы и ограничения

- **Разделяемая память:** Каждая зона потребляет фиксированный объем памяти. Размер зоны (например, `zone backend_zone 64k`) определяет, сколько записей о состоянии объектов может храниться одновременно.
- **Производительность:** Сбор метрик через `status_zone` высоко оптимизирован и оказывает минимальное влияние на задержки (overhead) при обработке трафика, так как выполняется в рамках основного цикла обработки событий.
- **Масштабирование:** Метрики собираются локально для каждого узла Angie. В кластерных инсталляциях требуется агрегация данных через системы класса Prometheus.
