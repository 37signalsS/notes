# Мониторинг Angie — Console Light и API

## Определения

**Angie Console Light** — официальный встроенный веб-интерфейс (часто называемый Console Lite) для интерактивного мониторинга метрик Angie в режиме реального времени. Позволяет визуализировать данные из HTTP API без необходимости развертывания внешних систем сбора данных.

**HTTP API мониторинга** — программный интерфейс Angie, предоставляющий статистику о работе сервера в формате JSON (JavaScript Object Notation). Включает данные о запросах, соединениях, состоянии upstream-групп, кэше, зонах разделяемой памяти и конфигурационных файлах.

## Базовые концепции

### Архитектура взаимодействия

Console Light представляет собой набор статических файлов (HTML/JavaScript), которые исполняются в браузере пользователя и с заданной периодичностью (по умолчанию — 1 секунда) запрашивают данные у эндпоинта API.

```
┌─────────────┐      ┌───────────────┐      ┌─────────────┐
│   Browser   │─────>│ Console Light │─────>│  Angie API  │
│  (UI)       │      │  (Static)     │      │  (/status/) │
└─────────────┘      └───────────────┘      └─────────────┘
```

### Безопасность и ограничение доступа

Поскольку API предоставляет доступ к внутренним метрикам инфраструктуры, его публикация в открытый доступ запрещена. Для защиты эндпоинтов используются следующие механизмы:

- **Списки контроля доступа (ACL):** ограничение по IP-адресам через директивы `allow` и `deny`.
- **Шифрование:** использование протокола TLS (Transport Layer Security).
- **Изоляция:** размещение интерфейса мониторинга на отдельном порту или внутреннем адресе.

### Сравнение с Prometheus

| Характеристика | Console Light / API | Prometheus |
|:---------------|:--------------------|:-----------|
| **Тип данных** | Текущее состояние | Исторические ряды |
| **Обновление** | Реал-тайм (~1 сек) | Интервал сбора (15–60 сек) |
| **Хранение** | Нет (только в памяти) | База данных (TSDB) |
| **Назначение** | Оперативная отладка | Анализ трендов, алертинг |

## Практические сценарии

### Сценарий 1: Установка и базовая настройка

Установка пакета Console Light производится отдельно от основного веб-сервера.

```bash
# Для Ubuntu/Debian
sudo apt-get install angie-console-light

# Для RHEL/AlmaLinux
sudo dnf install angie-console-light

# Для коммерческой версии
sudo apt-get install angie-pro-console-light
```

Файлы интерфейса размещаются в директории `/usr/share/angie-console-light/html`.

### Сценарий 2: Настройка эндпоинтов в конфигурации

Для корректной работы консоли необходимо создать `server` блок, в котором будут определены пути к API и статическим файлам. 

**Важно про CORS:** Чтобы браузер мог выполнять запросы к API с того же домена/порта, на котором открыта консоль, используется проксирование внутри локации консоли.

```nginx
server {
    listen 8888;
    server_name monitor.local;

    # Ограничение доступа только для доверенной сети
    allow 192.168.1.0/24;
    deny all;

    # Интерфейс Console Light
    location /console {
        alias /usr/share/angie-console-light/html;
        index index.html;

        # Проксирование запросов консоли к API для обхода CORS
        # Консоль ожидает эндпоинт API по относительному пути /api/
        location /console/api/ {
            api /status/;
        }
    }

    # Прямой эндпоинт API (для curl/Prometheus)
    location /status/ {
        api;
    }
}
```

### Сценарий 3: Активация вкладки просмотрщика конфигурации (Configs)

В Console Light доступна вкладка для просмотра активных файлов конфигурации. Для ее работы необходимо в контексте `http` включить экспорт файлов:

```nginx
http {
    api_config_files on; # Активирует сбор данных о файлах для API
    ...
}
```

### Сценарий 4: Мониторинг времени ответа (Response Time)

Начиная с версии **1.8.0**, Console Light отображает время ответа от вышестоящих серверов (`upstream_response_time`). Это позволяет визуально отслеживать деградацию производительности конкретных бэкендов в реальном времени. Данные доступны как для HTTP, так и для TCP/UDP (Stream) апстримов, если для них настроены зоны статуса.

### Сценарий 5: Получение метрик через интерфейс командной строки

К API можно обращаться напрямую с помощью утилиты `curl` для автоматизации или быстрой проверки.

```bash
# Получение общего состояния сервера
curl -s http://127.0.0.1:8888/status/ | jq

# Проверка состояния конкретной группы HTTP upstream
curl -s http://127.0.0.1:8888/status/http/upstreams/backend_cluster/ | jq

# Статистика активных соединений
curl -s http://127.0.0.1:8888/status/connections/
# → {"active": 124, "idle": 15, "accepted": 4502, "dropped": 0}
```

## Дополнительная информация

### Версионность и ограничения

- **История:** Данные в консоли не сохраняются после перезапуска сервера или закрытия вкладки браузера (визуализация только текущего состояния памяти).
- **Масштабирование:** При использовании кластера Angie консоль показывает данные только для того узла, к которому выполнен запрос.
- **Обновление:** Рекомендуется поддерживать версии `angie` и `angie-console-light` идентичными для корректного отображения всех доступных метрик.

### Возможности Angie Pro

В коммерческой версии API поддерживает метод записи (`write=on`), что позволяет динамически через интерфейс Console Light управлять параметрами серверов (изменение весов, перевод в `down`, `drain`) без перезагрузки конфигурации.

Подробнее: [Возможности Angie Pro](./angie_monitoring_pro.md).
