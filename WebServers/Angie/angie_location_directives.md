# Директивы `location` в Angie

## Определения

**Директива `location`** — ключевой элемент конфигурации Angie, определяющий правила маршрутизации и обработки HTTP-запросов на основе URI (Uniform Resource Identifier). Она позволяет задавать специфические настройки для разных путей внутри виртуального сервера (`server`).

## Основные концепции

### Совместимость и SSoT

Поскольку Angie является форком Nginx, логика выбора наиболее подходящего блока `location` (префиксные vs регулярные выражения), модификаторы и их приоритеты **полностью идентичны**.

**SSoT (Единый источник истины) для базовой логики:**
*   **[Директива location в Nginx — полный справочник](../Nginx/Core/Location/basics.md)** — алгоритмы выбора, модификаторы и приоритеты.
*   **[Лучшие практики и отладка location](../Nginx/Core/Location/best_practices.md)** — советы по оптимизации и типичные ошибки.

### Краткий обзор приоритетов

| Модификатор | Описание | Приоритет |
| :--- | :--- | :--- |
| `=` | Точное совпадение | 1 (Наивысший) |
| `^~` | Приоритетный префикс | 2 (Останавливает поиск регулярных выражений) |
| `~` | Regex (регистрозависимый) | 3 (По порядку в файле) |
| `~*` | Regex (регистронезависимый) | 3 (По порядку в файле) |
| (нет) | Обычный префикс | 4 (Самый длинный префикс) |

## Практические сценарии

В Angie директива `location` расширена специфическими функциями для мониторинга и управления трафиком.

### Мониторинг через `status_zone`

В отличие от стандартного Nginx, Angie позволяет собирать детальную статистику по конкретным локациям без сторонних модулей. Директива `status_zone` создает именованную область в памяти для хранения счетчиков.

```nginx
location /api/v1/ {
    # Сбор статистики именно для этого пути
    status_zone api_v1_stats;
    
    proxy_pass http://backend_api;
}
```
Метрики из этой зоны будут доступны через HTTP API Angie в формате JSON. Подробнее: **[Мониторинг Angie: концепции](./angie_monitoring/angie_monitoring_concepts.md)**.

### Нативный экспорт метрик Prometheus

Angie поддерживает прямую отдачу метрик в формате Prometheus. Это избавляет от необходимости использовать внешние экспортеры или сложные скрипты.

```nginx
location /p8s {
    # Ограничение доступа к метрикам (Pro-tip)
    allow 192.168.1.0/24; # IP сервера Prometheus
    allow 127.0.0.1;
    deny all;

    # Зона статистики для самого эндпоинта
    status_zone prometheus_metrics;
    
    # Включение нативного экспорта
    prometheus on;
    
    # (Опционально) Отключение логирования запросов мониторинга
    access_log off;
}
```

### Настройка обратного прокси и балансировки

Локации часто используются как точки входа для проксирования трафика.

```nginx
location /app/ {
    # Параметры балансировки и проксирования
    proxy_pass http://app_upstream;
    
    # Продвинутые функции Angie
    proxy_set_header X-Real-IP $remote_addr;
    
    # См. также: [Балансировка нагрузки в Angie](./angie_http_load_balancing.md)
}
```

## Дополнительная информация

### Рекомендации по оптимизации

1.  **Приоритет префиксов:** Используйте `^~` для статического контента (изображения, стили). Это предотвратит ненужную проверку регулярных выражений и ускорит обработку запроса.
2.  **Точное совпадение:** Для часто запрашиваемых путей (например, `/` или `/login`) используйте `location = /`, чтобы минимизировать время поиска.
3.  **Безопасность:** Всегда ограничивайте доступ к техническим локациям (`/metrics`, `/api`, `/status`) с помощью директив `allow` и `deny`.
