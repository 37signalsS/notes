# Директивы `location` в Angie

## Определения

**Директива `location`** — ключевой элемент конфигурации Angie (и Nginx), позволяющий управлять обработкой HTTP-запросов в зависимости от URI. Задаёт правила маршрутизации внутри блока `server`.

## Базовые концепции

### Совместимость с Nginx

Angie является форком Nginx и **полностью совместим** с ним в части синтаксиса и логики работы директивы `location`. Все модификаторы, приоритеты и алгоритмы выбора идентичны:

- Точное совпадение: `=`
- Приоритетный префикс: `^~`
- Регулярные выражения: `~` (с учётом регистра), `~*` (без учёта)
- Префиксное совпадение: без модификатора

Подробное описание алгоритма выбора, приоритетов и примеров использования содержится в основном руководстве: [Директива location в Nginx](../Nginx/Core/Location/basics.md).

## Практические сценарии

### Типичное использование в Angie

Директива `location` применяется в следующих сценариях Angie:

- **Обратный прокси-сервер** — передача запросов на backend-серверы через `proxy_pass` ([подробнее](./angie_reverse_proxy.md))
- **Перенаправления и перезапись URI** — использование `return`, `rewrite` внутри `location` ([подробнее](./angie_redirects_and_rewrites.md))
- **Балансировка нагрузки** — распределение запросов между upstream-группами ([подробнее](./angie_http_load_balancing.md))
- **Клиентская аутентификация** — проверка клиентских TLS-сертификатов в определённом `location` ([подробнее](./angie_client_cert_auth.md))
- **Мониторинг** — нативный экспорт метрик Prometheus без использования njs ([подробнее](./angie_monitoring/angie_monitoring_prometheus.md))

### Пример: защищённый endpoint для метрик

```nginx
location /metrics {
    allow 127.0.0.1;
    allow 10.0.0.0/8;
    deny all;

    status_zone metrics_access;
    prometheus on;
}
```

Этот `location` демонстрирует нативную особенность Angie — встроенную поддержку Prometheus без необходимости использования njs-скриптов.

## Дополнительные сведения

### Рекомендации по использованию

1. **Не дублируйте логику** — базовый алгоритм выбора `location` одинаков для Angie и Nginx, обращайтесь к основному руководству при необходимости
2. **Проверяйте конфигурацию** после изменений: `angie -t`
3. **Используйте `^~` для статики** — чтобы исключить проверку регулярных выражений для часто запраемых путей
