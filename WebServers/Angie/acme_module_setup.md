# Автоматизация получения SSL-сертификатов с помощью ACME в Angie

Angie включает в себя встроенный модуль `acme`, который позволяет автоматически получать и обновлять SSL/TLS сертификаты от удостоверяющих центров, поддерживающих протокол ACME (Automated Certificate Management Environment), таких как Let's Encrypt. Это избавляет от необходимости использовать внешние утилиты, такие как Certbot или acme.sh, и полностью интегрирует процесс управления сертификатами в конфигурацию веб-сервера.

## 1. Преимущества встроенного модуля `acme`

-   **Полная автоматизация:** Настройте один раз, и Angie будет самостоятельно получать и продлевать сертификаты, включая перезагрузку конфигурации для их применения.
-   **Нет внешних зависимостей:** Не нужно устанавливать и настраивать дополнительные скрипты или пакеты типа Certbot. Вся логика встроена в веб-сервер.
-   **Простота конфигурации:** Управление сертификатами осуществляется декларативно через директивы в конфигурационных файлах Angie.
-   **Поддержка разных типов верификации:** Модуль поддерживает как `http-01`, так и `dns-01` проверку, что позволяет выпускать обычные и Wildcard-сертификаты.

## 2. Настройка для `http-01` верификации (стандартные сертификаты)

Это самый простой и распространенный способ, который подходит для большинства случаев. Он требует, чтобы ваш сервер был доступен из интернета по 80-му порту.

### Шаг 1: Определение ACME-клиента

Сначала в блоке `http` вашего `angie.conf` необходимо определить "клиента", который будет взаимодействовать с Let's Encrypt, и `resolver` для DNS-запросов.

```nginx
# /etc/angie/angie.conf
http {
    # ...

    # Определяем DNS-резолвер для ACME-клиента
    resolver 1.1.1.1 8.8.8.8 valid=300s;

    # Определяем клиента для Let's Encrypt
    acme_client letsencrypt {
        directory "https://acme-v02.api.letsencrypt.org/directory";
        # Для тестирования используйте staging-окружение:
        # directory "https://acme-staging-v02.api.letsencrypt.org/directory";
    }

    # ...
}
```
- `resolver`: Необходим для взаимодействия с ACME-сервером. Можно использовать публичные DNS, например, Cloudflare (`1.1.1.1`) или Google (`8.8.8.8`).
- `acme_client`: Блок, описывающий ACME-клиента. `letsencrypt` — это произвольное имя, которое вы будете использовать далее.
- `directory`: URL директории ACME-сервера.

### Шаг 2: Настройка сервера для получения сертификата

Теперь в конфигурации вашего `server` укажите, что он должен использовать ACME для получения сертификата.

```nginx
# /etc/angie/sites-enabled/default
server {
    listen 80;
    listen 443 ssl;
    server_name example.com www.example.com;

    # Указываем, где хранить полученный сертификат и ключ
    ssl_certificate /etc/angie/ssl/example.com.crt;
    ssl_certificate_key /etc/angie/ssl/example.com.key;

    # Включаем ACME для этого сервера, ссылаясь на ранее определенного клиента
    acme on;
    acme_client letsencrypt;

    # ... остальная конфигурация
}
```
- **Важно:** Angie должен иметь доступ по 80-му порту для прохождения `http-01` верификации. Никаких специальных `location /.well-known/acme-challenge` создавать не нужно — Angie обрабатывает это автоматически "под капотом".
- При первом запуске или перезагрузке Angie обнаружит отсутствие файлов сертификата, инициирует процесс их получения, и после успешной верификации сохранит их по указанным путям и применит к конфигурации.
- Продление сертификатов также происходит автоматически.

## 3. Настройка для `dns-01` верификации (Wildcard-сертификаты)

Для получения Wildcard-сертификатов (например, `*.example.com`) требуется подтверждение владения доменом через DNS. Модуль `acme` в Angie поддерживает и этот способ.

### Шаг 1: Настройка `acme_client` для DNS

```nginx
# /etc/angie/angie.conf
http {
    # ...
    resolver 1.1.1.1;

    acme_client letsencrypt_dns {
        directory "https://acme-v02.api.letsencrypt.org/directory";
        # Указываем, что для верификации будет использоваться DNS
        challenge_type dns-01;
    }
    # ...
}
```

### Шаг 2: Настройка сервера

```nginx
# /etc/angie/sites-enabled/wildcard
server {
    listen 443 ssl;
    server_name *.example.com;

    ssl_certificate /etc/angie/ssl/wildcard.example.com.crt;
    ssl_certificate_key /etc/angie/ssl/wildcard.example.com.key;

    # Включаем ACME для этого сервера
    acme on;
    acme_client letsencrypt_dns;

    # Настраиваем обработчик DNS-запросов
    # Angie будет отвечать на DNS-запросы от Let's Encrypt для подтверждения владения доменом
    acme_dns_server {
        listen 53 udp;
        listen 53; # TCP
    }
}
```
- `challenge_type dns-01`: Указывает клиенту использовать DNS-верификацию.
- `acme_dns_server`: Эта директива заставляет Angie работать как мини-DNS-сервер на 53 порту для ответа на верификационные запросы от Let's Encrypt.

Для того чтобы это работало, вам необходимо делегировать обработку `_acme-challenge.example.com` на тот сервер, где запущен Angie. Это делается путем создания NS-записи в настройках вашего домена.

```dns
# В настройках зоны example.com
_acme-challenge.example.com. IN NS ns1.acme.example.com.
ns1.acme.example.com.       IN A  <IP-адрес вашего Angie-сервера>
```

В качестве альтернативы, если вы не хотите делегировать DNS-зону, можно использовать `acme_dns_hook` для вызова внешнего скрипта, который будет взаимодействовать с API вашего DNS-провайдера для создания необходимых TXT-записей.

## 4. Мониторинг и отладка

- **Логи:** Вся информация о процессе получения и обновления сертификатов записывается в `error.log` на уровне `notice`.
- **Статус:** Мониторить состояние можно через стандартные средства мониторинга Angie.
