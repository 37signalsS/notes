# Аутентификация клиентов в Angie с помощью TLS-сертификатов (mTLS)

## 1. Определения и базовые концепции

**Взаимная аутентификация TLS (Mutual TLS, mTLS)** — это механизм безопасности, при котором не только клиент проверяет подлинность сервера с помощью его TLS-сертификата, но и сервер, в свою очередь, проверяет подлинность клиента по его сертификату. Это обеспечивает значительно более высокий уровень безопасности по сравнению с традиционными методами (логин/пароль), так как доступ могут получить только клиенты, обладающие валидным сертификатом, выданным доверенным центром сертификации (CA).

Этот подход является стандартным для организации безопасного межсервисного взаимодействия в [микросервисных архитектурах](../../Concepts/monolith_vs_microservices.md) и для защиты критически важных внутренних API.

### Ключевые директивы в Angie

-   `ssl_verify_client on;`: Включает обязательную проверку сертификата клиента. Если клиент не предоставляет валидный сертификат, соединение разрывается.
-   `ssl_client_certificate /path/to/ca.crt;`: Указывает путь к файлу корневого сертификата (CA), который будет использоваться для проверки подписи клиентских сертификатов.
-   `ssl_crl /path/to/crl.pem;`: (Опционально) Указывает путь к списку отозванных сертификатов (Certificate Revocation List).

> Для получения исчерпывающей информации о теории TLS, всех директивах и продвинутых сценариях настройки, обратитесь к основному руководству: **[Оптимальная настройка TLS/SSL в Nginx](../Nginx/Security/nginx_tls_ssl_configuration.md)**.

В данном руководстве мы рассмотрим сквозной практический пример настройки mTLS в [Angie](./angie_overview.md) с использованием утилиты **Easy-RSA** для создания необходимой инфраструктуры открытых ключей (PKI).

## 2. Практический сценарий: Настройка с Easy-RSA

### 2.1. Шаг 1: Установка и инициализация Easy-RSA

Easy-RSA — это утилита командной строки для управления PKI. Она является удобной оберткой над OpenSSL.

1.  **Установка Easy-RSA:**
    ```bash
    sudo apt update
    sudo apt install easy-rsa
    ```

2.  **Создание и инициализация PKI:**
    Создайте директорию для вашего центра сертификации и инициализируйте ее.
    ```bash
    # Создаем директорию
    mkdir ~/easy-rsa-ca
    cd ~/easy-rsa-ca

    # Копируем скрипты easy-rsa
    ln -s /usr/share/easy-rsa/* .

    # Инициализируем PKI
    ./easyrsa init-pki
    ```
    Это создаст структуру каталогов `pki/`, где будут храниться все ключи и сертификаты.

### 2.2. Шаг 2: Создание Центра Сертификации (CA)

Теперь создадим корневой ключ и сертификат для нашего CA.

```bash
# Создаем CA без пароля для ключа (для автоматизации)
# Для большей безопасности можно убрать опцию nopass
./easyrsa build-ca nopass
```
Вам будет предложено ввести `Common Name` (CN) для вашего CA. Это имя будет отображаться как издатель всех сертификатов.

### 2.3. Шаг 3: Генерация сертификатов для сервера и клиента

1.  **Создание сертификата и ключа для сервера Angie:**
    ```bash
    # `server` - это имя файла для сертификата и ключа
    ./easyrsa build-server-full server nopass
    ```
    Система запросит подтверждение `Common Name` (по умолчанию `server`). На этом этапе вы можете указать реальный домен вашего сервера.

2.  **Создание сертификата и ключа для клиента:**
    ```bash
    # `client` - это имя файла
    ./easyrsa build-client-full client nopass
    ```

3.  **Создание списка отозванных сертификатов (CRL):**
    Этот файл необходим, чтобы блокировать доступ для скомпрометированных сертификатов.
    ```bash
    ./easyrsa gen-crl
    ```

После выполнения этих шагов в директории `pki/` появятся все необходимые файлы:
-   `pki/ca.crt` — Корневой сертификат CA.
-   `pki/issued/server.crt` — Сертификат сервера.
-   `pki/private/server.key` — Приватный ключ сервера.
-   `pki/issued/client.crt` — Сертификат клиента.
-   `pki/private/client.key` — Приватный ключ клиента.
-   `pki/crl.pem` — Список отозванных сертификатов.

### 2.4. Шаг 4: Настройка Angie

1.  **Скопируйте необходимые файлы на сервер с Angie:**
    ```bash
    # Создадим директорию для сертификатов
    sudo mkdir -p /etc/angie/ssl

    # Копируем сертификаты и ключи
    sudo cp pki/ca.crt /etc/angie/ssl/
    sudo cp pki/issued/server.crt /etc/angie/ssl/
    sudo cp pki/private/server.key /etc/angie/ssl/
    sudo cp pki/crl.pem /etc/angie/ssl/
    ```

2.  **Настройте виртуальный хост в Angie:**
    Создайте или отредактируйте файл конфигурации вашего сайта (например, `/etc/angie/sites-available/default`).

    ```nginx
    server {
        listen 443 ssl http2;
        server_name your.domain.com; # Укажите ваш домен

        # --- Базовые настройки TLS ---
        ssl_certificate /etc/angie/ssl/server.crt;
        ssl_certificate_key /etc/angie/ssl/server.key;

        # --- НАСТРОЙКИ mTLS ---
        # 1. Сертификат CA для проверки клиентов
        ssl_client_certificate /etc/angie/ssl/ca.crt;
        # 2. Список отозванных сертификатов
        ssl_crl /etc/angie/ssl/crl.pem;
        # 3. Включаем обязательную проверку
        ssl_verify_client on;

        root /var/www/html;
        index index.html;

        # Для отладки можно добавить переменные в заголовки
        add_header X-SSL-Client-Verify $ssl_client_verify;
        add_header X-SSL-Client-DN $ssl_client_s_dn;

        location / {
            try_files $uri $uri/ =404;
        }
    }
    ```

3.  **Проверьте и перезагрузите Angie:**
    ```bash
    sudo angie -t
    sudo systemctl reload angie
    ```

### 2.5. Шаг 5: Тестирование и использование

#### Тестирование с помощью `curl`

-   **Попытка подключения без сертификата (должна завершиться ошибкой):**
    ```bash
    curl https://your.domain.com --insecure
    # Вывод: curl: (35) ... OpenSSL SSL_read: error:14094412:SSL routines:ssl3_read_bytes:sslv3 alert bad certificate
    # В логах Angie: "client SSL certificate required"
    ```

-   **Успешное подключение с клиентским сертификатом:**
    Скопируйте `client.crt` и `client.key` на машину, с которой будете выполнять тест.
    ```bash
    curl https://your.domain.com --insecure \
      --cert client.crt \
      --key client.key
    ```
    `--insecure` используется, так как наш серверный сертификат подписан самодельным CA, которому система по умолчанию не доверяет. В ответ вы должны получить содержимое вашего сайта.

#### Использование в браузере

Браузеры требуют сертификат и ключ в едином файле формата **PKCS#12 (`.p12` или `.pfx`)**.

1.  **Конвертируйте клиентский сертификат и ключ в формат `.p12`:**
    ```bash
    openssl pkcs12 -export -out client.p12 -inkey pki/private/client.key -in pki/issued/client.crt -certfile pki/ca.crt
    ```
    Вам будет предложено задать пароль для экспорта, который понадобится при импорте в браузер.

2.  **Импортируйте `client.p12` в ваш браузер:**
    -   **Chrome/Edge:** `Настройки` → `Конфиденциальность и безопасность` → `Безопасность` → `Управление сертификатами устройства` → `Импорт`.
    -   **Firefox:** `Настройки` → `Приватность и Защита` → `Сертификаты` → `Просмотр сертификатов` → `Ваши сертификаты` → `Импортировать`.

После импорта браузер будет автоматически предлагать использовать этот сертификат при доступе к сайту `your.domain.com`. Вы также должны добавить ваш корневой сертификат `ca.crt` в доверенные в браузере или ОС, чтобы избежать предупреждений о небезопасном соединении.
