# Настройка Angie для высоких нагрузок и защиты от атак

## Определения

**Оптимизация производительности (Performance Optimization)** — комплекс мер, направленных на повышение эффективности использования серверных ресурсов (CPU, RAM, Disk I/O, Network) и сокращение времени отклика.

**Высокая нагрузка (High Load)** — состояние системы, при котором объем входящего трафика или сложность обработки запросов приближаются к пределам пропускной способности инфраструктуры.

**Защита от DoS-атак (Denial of Service)** — набор техник для обеспечения доступности сервиса при попытках злоумышленников исчерпать ресурсы системы.

---

## Базовые концепции

### Особенности Angie для High Load

Angie (форк Nginx) включает ряд уникальных возможностей, критичных для высоконагруженных систем:

- **Сохранение индекса кэша (Cache Index Persistence):** Возможность сохранять зону разделяемой памяти кэша на диск. Это исключает этап "разогрева" (cache loading) после перезапуска сервера, позволяя сразу обрабатывать трафик на полной скорости.
- **Интеллектуальная балансировка:** Поддержка метода `least_time` (балансировка по минимальному времени ответа) в Open Source версии.
- **Грациозное обслуживание (Server Draining):** Режим `drain` для upstream-серверов позволяет плавно выводить узлы из эксплуатации, дообслуживая существующие сессии.
- **Полноценный HTTP/3:** Стабильная поддержка протокола на стороне клиента и бэкендов (upstream).
- **Zstandard (zstd):** Нативная поддержка сжатия Zstd, обеспечивающая лучший баланс между степенью сжатия и нагрузкой на CPU по сравнению с Gzip.

### Подходы к оптимизации

- **Серверная (Server-side):** Тюнинг параметров ядра ОС, эффективное распределение процессов по ядрам CPU (`affinity`), оптимизация работы с сокетами и дисковым кэшем.
- **Клиентская (Client-side):** Использование современных протоколов (HTTP/2, HTTP/3), агрессивное кэширование, сжатие контента и минимизация количества запросов.

### Принципы тестирования (Benchmarking)

- **Изоляция изменений:** Тестируйте по одной настройке за раз.
- **Инструментарий:**
  - Для RPS-тестов: `wrk`, `wrkx`, `h2load`.
  - Для комплексных сценариев: `Яндекс.Танк`, `k6`.
  - Подробнее: [Инструменты для бенчмарка веб-сервера](../../webserver_benchmarking.md).

## Практические сценарии

### Оптимизация производительности

Настройка параметров Angie для максимальной пропускной способности: тюнинг сетевого стека, Keep-Alive, буферизация и кэширование.

Подробнее: [Оптимизация производительности](./performance_optimization.md).

### Защита от DoS-атак

Методы противодействия флуду на уровне L7: ограничение частоты запросов (`limit_req`), соединений (`limit_conn`), фильтрация по GeoIP и User-Agent.

Подробнее: [Защита от DoS-атак](./dos_protection.md).

### Мониторинг и наблюдаемость (Observability)

Angie предоставляет расширенные возможности для мониторинга под нагрузкой:
- **Нативный экспорт в Prometheus:** Встроенный модуль `metrics` позволяет отдавать статистику в формате Prometheus без сторонних экспортеров.
- **Интерактивная консоль:** Веб-интерфейс для визуализации состояния сервера и апстримов в реальном времени.
- **API управления:** Динамическое управление конфигурацией (например, изменение весов апстримов) через HTTP API.

## Дополнительная информация

### Автоматизация безопасности (ACME)

Angie поддерживает встроенный модуль ACME для автоматического получения и продления TLS-сертификатов (Let's Encrypt и др.). Это критично для High Load систем, так как позволяет избежать простоев из-за просроченных сертификатов и упрощает масштабирование.

### Тюнинг ядра и TLS

- **Ядро Linux:** Настройка `sysctl` для управления очередями соединений (`somaxconn`) и буферами TCP. Подробнее: [sysctl](../../../Linux/Core/kernel/sysctl.md).
- **TLS/SSL:** Использование TLS 1.3, сессионных тикетов и Kernel TLS (kTLS) для снижения нагрузки на CPU. Подробнее: [Настройка TLS в Angie](../angie_tls_setup.md).
