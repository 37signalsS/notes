# Защита от DoS-атак в Angie

## Определения

**Защита от DoS-атак (Denial of Service — «отказ в обслуживании») на прикладном уровне (L7)** — комплекс архитектурных и конфигурационных мер, направленных на фильтрацию аномального трафика и ограничение потребления ресурсов. В условиях 2026 года эффективная защита подразумевает не просто блокировку по IP, а поведенческий анализ, использование криптографических вызовов (Proof-of-Work) и кластерную синхронизацию состояния.

**Rate Limiting (Ограничение скорости)** — механизм управления входящим потоком запросов, предотвращающий перегрузку бэкендов и истощение пула соединений. Использует алгоритм *Leaky Bucket* (дырявое ведро).

**Cluster Zone Sync** — технология синхронизации разделяемой памяти (shared memory) между узлами кластера Angie, позволяющая применять «честные» лимиты к распределенным атакам, где каждый отдельный бот не превышает локальный порог.

---

## Базовые концепции

Angie предоставляет расширенный набор инструментов для противодействия атакам прикладного уровня, включая возможности, которые в стандартном Nginx доступны только в коммерческих версиях или через сложные внешние модули.

### Типы угроз и методы защиты (SSoT Matrix)

| Тип угрозы | Метод защиты | Директива / Модуль |
| :--- | :--- | :--- |
| **HTTP-флуд с одного IP** | Ограничение частоты запросов | `limit_req`, `limit_req_zone` |
| **Исчерпание соединений** | Ограничение числа соединений | `limit_conn`, `limit_conn_zone` |
| **Кластерный DoS** | Синхронизация лимитов в кластере | Параметр `sync` в зонах + `stream` |
| **Slowloris (Медленные атаки)** | Агрессивные таймауты | `client_header_timeout`, `client_body_timeout` |
| **Монополизация канала** | Ограничение пропускной способности | `limit_rate` |
| **Атаки по регионам** | Блокировка по GeoIP | `ngx_http_geoip2_module` |
| **Автоматизированные боты** | Challenge (PoW / JS / Cookie) | `njs`, `ngx_http_testcookie_module` |
| **QUIC Reflection / Flood** | Валидация адреса и GSO | `quic_retry`, `quic_gso` |

### Принцип эшелонированной защиты (2026)

Эффективная защита строится на трех этапах:
1.  **Идентификация (Зоны):** Создание областей в разделяемой памяти для хранения состояний клиентов по ключу (IP, Cookie, Fingerprint). В Angie зоны могут достигать гигабайтных размеров для хранения миллионов отпечатков.
2.  **Синхронизация (Cluster Sync):** Состояние зон синхронизируется между всеми Edge-узлами в реальном времени, создавая единый источник истины о поведении клиента во всей инфраструктуре.
3.  **Действие:** Применение ограничений с возможностью мягкого тестирования (`dry_run`) или немедленной блокировки с кодом `429` (Too Many Requests).

## Практические сценарии

### 1. Ограничение частоты запросов с кластерной синхронизацией

В отличие от Nginx OSS, Angie позволяет синхронизировать счетчики `limit_req` между узлами кластера.

**Настройка синхронизации (`stream` блок):**
```nginx
stream {
    # Активация модуля синхронизации зон
    zone_sync;
    
    server {
        listen 127.0.0.1:9000;
        zone_sync_server node1.internal:9000;
        zone_sync_server node2.internal:9000;
    }
}
```

**Конфигурация лимитов (`http` блок):**
```nginx
http {
    # Зона с синхронизацией. 20m хранит ~320 000 состояний IP.
    limit_req_zone $binary_remote_addr zone=api_cluster:20m rate=10r/s sync;

    limit_req_status 429;
    limit_req_log_level warn;

    server {
        location /api/v2/ {
            # burst=20: разрешаем всплеск до 20 запросов
            # nodelay: обрабатываем всплеск немедленно без искусственных задержек
            limit_req zone=api_cluster burst=20 nodelay;
        }
    }
}
```

---

### 2. Ограничение одновременных соединений (limit_conn)

Защищает от атак, пытающихся занять все доступные слоты соединений (worker_connections).

```nginx
http {
    # Ограничение по IP (с синхронизацией)
    limit_conn_zone $binary_remote_addr zone=perip:10m sync;
    # Ограничение по виртуальному серверу (общий лимит на сайт)
    limit_conn_zone $server_name zone=perserver:1m;

    limit_conn_status 429;

    server {
        # Не более 20 активных соединений с одного IP
        limit_conn perip 20;
        # Не более 5000 соединений на весь виртуальный сервер
        limit_conn perserver 5000;
    }
}
```

---

### 3. Защита от медленных атак (Slowloris) и тюнинг таймаутов

Атаки Slowloris удерживают соединения открытыми, отправляя данные крайне медленно.

```nginx
http {
    # Время ожидания заголовков и тела (2026: рекомендуем 5-10s)
    client_header_timeout 10s;
    client_body_timeout   10s;
    
    # Время ожидания при передаче ответа клиенту
    send_timeout          10s;
    
    # Ограничение времени жизни keep-alive соединений
    # Второе значение (20s) отправляется в заголовке Keep-Alive для клиента
    keepalive_timeout     65s 20s;
    
    # Максимальное количество запросов в одном соединении (защита от reuse-флуда)
    keepalive_requests    1000;
}
```

---

### 4. Защита протоколов HTTP/2 и HTTP/3 (QUIC)

Современные протоколы требуют специфических настроек безопасности против атак типа "Rapid Reset" и UDP-амплификации.

```nginx
http {
    server {
        listen 443 quic reuseport;
        listen 443 ssl;
        http2 on;
        http3 on;

        # Защита от UDP-спуфинга: сервер требует Retry пакет перед выделением ресурсов
        quic_retry on;
        # Использование GSO для снижения нагрузки на CPU при UDP-флуде
        quic_gso on;

        # Ограничение параллельных потоков (защита от исчерпания ресурсов внутри сессии)
        http2_max_concurrent_streams 64;
        http3_max_concurrent_streams 64;
    }
}
```

---

### 5. Тюнинг буферов и заголовков

Ограничение размеров предотвращает атаки на переполнение памяти и парсер заголовков (HPACK Bomb).

```nginx
http {
    client_header_buffer_size 1k;
    large_client_header_buffers 4 8k;
    
    # Ограничение количества заголовков (защита от Flood атак, Angie 1.4+)
    max_headers 50;
    
    # Максимальный размер тела запроса (предотвращает заливку мусорных данных)
    client_max_body_size 10m;
}
```

---

### 6. Географическая и поведенческая блокировка (GeoIP2)

Использование GeoIP2 для отсечения трафика из нецелевых регионов.

```nginx
http {
    geoip2 /etc/angie/geo/Country.mmdb {
        $geoip2_country_code default=RU country iso_code;
    }

    map $geoip2_country_code $is_blocked {
        default 0;
        CN      1;
        US      1;
    }

    server {
        if ($is_blocked) {
            return 403; # Доступ запрещен
        }
    }
}
```

---

### 7. Наблюдаемость и мониторинг защиты

Angie позволяет отслеживать эффективность лимитов через `status_zone` и встроенный API.

**Конфигурация мониторинга:**
```nginx
http {
    server {
        status_zone server_stats;
        
        location /api/ {
            api; # Включение API Angie
            allow 127.0.0.1;
            deny all;
        }
    }
}
```

**Переменные состояния лимитов:**
Для использования в логировании доступны переменные:
*   `$limit_req_status`: принимает значения `passed`, `delayed`, `rejected`, `delayed_dry_run`, `rejected_dry_run`.
*   `$limit_conn_status`: принимает значения `passed`, `rejected`.

**Проверка через API (curl):**
```bash
# Получение статистики по зоне ограничения запросов
curl http://localhost/api/v1/http/limit_reqs/api_cluster
```
