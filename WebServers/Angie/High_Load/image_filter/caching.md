# Модуль image_filter в Angie: стратегии кэширования

## Определения

**Proxy Cache (Прокси-кэш)** — механизм временного хранения обработанного контента на диске. В Angie он дополнен функциями сохранения индекса, что критично для высоконагруженных систем с большим объемом кэша.

**Сохранение индекса (Persistence)** — уникальная функция Angie, позволяющая сохранять метаданные зон разделяемой памяти (индекс кэша) в файл при выключении и мгновенно загружать их при старте, исключая фазу сканирования диска.

## Базовые концепции

Трансформация изображений (resize, convert, sharpen) — это ресурсоемкая операция, сильно нагружающая CPU. Без эффективного кэширования сервер быстро исчерпает ресурсы при росте трафика.

### Архитектурный подход: Двойное проксирование

Стандартное использование `image_filter` и `proxy_cache` в одном `location` часто приводит к кэшированию **оригинала** ответа бэкенда, в то время как фильтр срабатывает *после* извлечения из кэша. Для кэширования именно **результата обработки** рекомендуется использовать схему с внутренним уровнем трансформации.

1.  **Внешний уровень (Кэширующий):** Принимает запрос от клиента, проверяет наличие готового (обработанного) изображения в кэше. Если его нет — проксирует запрос на внутренний уровень.
2.  **Внутренний уровень (Трансформирующий):** Запрашивает оригинал у бэкенда, применяет `image_filter` и отдает результат внешнему уровню.

### Сравнение методов хранения

| Метод | Управление | Преимущества | Применение |
|:------|:-----------|:-------------|:-----------|
| **Proxy Cache** | Автоматическое (LRU, TTL) | Persistence, мгновенный старт, мониторинг через API. | Основной метод для большинства систем. |
| **Proxy Store** | Ручное / Файловая система | Постоянное хранение, работа как со статикой. | Статические архивы, CDN-узлы. |

## Практические сценарии

### Настройка кэша с сохранением индекса (Persistence)

Использование параметра `file=` позволяет избежать "замирания" сервера при перезагрузке, если объем кэша составляет сотни гигабайт.

```nginx
http {
    # Определение пути и зоны с сохранением индекса
    # file=/var/lib/angie/img_zone.bin — путь к файлу индекса
    proxy_cache_path /var/cache/angie/images 
                     levels=1:2 
                     keys_zone=img_cache:100m:file=/var/lib/angie/img_zone.bin 
                     max_size=10g 
                     inactive=24h 
                     use_temp_path=off;
}
```

### Реализация схемы «Двойного проксирования»

Этот сценарий гарантирует, что CPU будет тратиться на ресайз только один раз для каждого уникального размера.

```nginx
# Внешний сервер (Кэширование результата)
server {
    listen 80;

    location /img/resize/ {
        proxy_cache img_cache;
        proxy_cache_valid 200 30d;
        proxy_cache_key $host$uri$is_args$args;
        
        # Защита от "стада бизонов" (Cache Stampede)
        proxy_cache_lock on; 
        
        # Передача на внутренний уровень обработки
        proxy_pass http://127.0.0.1:8081;
    }
}

# Внутренний сервер (Трансформация)
server {
    listen 127.0.0.1:8081;

    location /img/resize/ {
        # Запрос оригинала у хранилища
        proxy_pass http://storage_backend;
        
        image_filter resize 300 -;
        image_filter_webp_quality 80;
        image_filter_buffer 15M;
    }
}
```

### Мониторинг состояния кэша

В Angie статистика кэша доступна через встроенный API и может быть визуализирована в Console Light.

```nginx
server {
    listen 127.0.0.1:8080;

    location /status/ {
        # Включает API Angie для сбора метрик кэша
        api /status/;
        allow 127.0.0.1;
        deny all;
    }
}
```
*Метрики кэша доступны по эндпоинту `/status/http/caches/img_cache`.*

## Дополнительная информация

### Оптимизация производительности

1.  **`proxy_cache_background_update on`**: Позволяет отдавать старую версию изображения из кэша, пока Angie в фоне запрашивает обновление у бэкенда. Это минимизирует задержки для пользователя.
2.  **`proxy_cache_use_stale updating`**: Работает в связке с фоновым обновлением, предотвращая ожидание генерации изображения.
3.  **`proxy_cache_min_uses`**: Установите значение `2` или выше, чтобы не засорять кэш изображениями, которые запрашиваются крайне редко (например, ботами).

### Ограничения

- **Инвалидация:** В Angie PRO доступна очистка кэша через API. В версии OSS инвалидация обычно требует удаления файла с диска или использования сторонних модулей.
- **CPU Affinity:** При интенсивном ресайзе важно корректно настроить `worker_cpu_affinity` для равномерного распределения нагрузки по ядрам.
