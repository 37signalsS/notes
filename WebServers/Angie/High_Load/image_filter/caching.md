# Модуль image_filter в Angie: кэширование

## Определения

**Proxy Cache** — временное хранение сгенерированных изображений с автоматическим управлением по алгоритму LRU (Least Recently Used — наименее недавно использованный).

**Proxy Store** — постоянное хранение сгенерированных изображений с ручным управлением.

## Базовые концепции

Модуль `image_filter` генерирует изображения «на лету», что создаёт нагрузку на CPU при каждом запросе. Кэширование решает эту проблему двумя способами:

1. **Proxy Cache** — временное хранение с автоматической очисткой по алгоритму LRU (Least Recently Used). Angie сам управляет жизненным циклом файлов.

2. **Proxy Store** — постоянное хранение с ручным управлением. Файлы сохраняются один раз и не удаляются автоматически.

**Когда кэшировать:**

- Любые трансформации изображений (resize, crop, rotate)
- Изображения, запрашиваемые повторно
- Контент с высокой посещаемостью

**Когда НЕ кэшировать:**

- Изображения для A/B-тестирования с коротким жизненным циклом
- Контент, изменяемый чаще, чем интервал кэширования

## Практические сценарии

### Сценарий: Кэширование через Proxy Cache

**Proxy Cache (временное хранение):**

```nginx
http {
    proxy_cache_path /var/cache/angie/image_cache
        levels=1:2
        keys_zone=image_cache:10m
        max_size=1g
        inactive=24h
        use_temp_path=off;
}

server {
    location @resize {
        proxy_pass http://127.0.0.1:8081$request_uri;

        proxy_cache image_cache;
        proxy_cache_key $host$uri;
        proxy_cache_valid 200 14d;
        proxy_cache_min_uses 2;  # Кэшировать после 2 запросов
        proxy_cache_use_stale updating error timeout http_500;
        proxy_cache_background_update on;
        proxy_cache_lock on;
    }
}
```

**Proxy Store (постоянное хранение):**

```nginx
location @resize {
    proxy_pass http://127.0.0.1:8081$request_uri;
    proxy_store /var/www/images$uri;
    proxy_store_access user:rw group:rw all:r;
}
```

**Сравнение подходов:**

| Параметр | Proxy Cache | Proxy Store |
|----------|-------------|-------------|
| Хранение | Временное (inactive) | Постоянное |
| Управление | Автоматическое (LRU) | Ручное |
| Дисковое пространство | Ограничено max_size | Не ограничено |
| Гибкость | Высокая | Низкая |
| Подходит для | Частого обновления | Статичного контента |

**Рекомендация:** для большинства сценариев обработки изображений подходит Proxy Cache с `inactive=24h` — это балансирует между производительностью и использованием дискового пространства.

## Дополнительная информация

### Выбор стратегии кэширования

- **Proxy Cache** — для динамически изменяемых изображений, A/B тестирования, временных преобразований
- **Proxy Store** — для однократной обработки изображений с долгосрочным хранением результатов

### Производительность

- `proxy_cache_lock on` предотвращает параллельную генерацию одного и того же изображения (thundering herd problem)
- `proxy_cache_background_update on` позволяет обновлять кэш в фоне без блокировки клиентов
- `proxy_cache_min_uses` снижает нагрузку на диск, кэшируя только популярные изображения
