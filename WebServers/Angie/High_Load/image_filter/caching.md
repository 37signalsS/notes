# Модуль image_filter в Angie: кэширование

## Определения

**Proxy Cache** — механизм временного хранения ответов бэкенда на диске с автоматическим управлением жизненным циклом файлов по алгоритму LRU (Least Recently Used).

**Proxy Store** — механизм сохранения ответов бэкенда в виде статических файлов на диске для постоянного хранения без автоматического удаления.

## Базовые концепции

Обработка изображений через `image_filter` является ресурсоёмкой операцией для CPU. Кэширование позволяет избежать повторной генерации одного и того же изображения при каждом запросе.

### Когда использовать кэширование

- **Любые трансформации:** resize, crop, rotate.
- **Популярный контент:** изображения с высокой частотой запросов.
- **Статичные исходники:** если оригинальное изображение редко меняется.

### Выбор метода

| Метод | Описание | Применение |
|:------|:---------|:-----------|
| **Proxy Cache** | Автоматическое управление, TTL, очистка по размеру. | Оптимально для большинства сценариев. |
| **Proxy Store** | Сохранение «навсегда», требует ручной очистки. | Для архивов или когда место на диске не критично. |

Подробное описание общих механизмов кэширования приведено в [серверном кэшировании Nginx](../../../../Nginx/Performance/Caching/proxy_caching.md).

## Практические сценарии

### Сценарий: Временное кэширование (Proxy Cache)

Этот подход позволяет Angie автоматически удалять редко запрашиваемые изображения и ограничивать общий размер кэша.

```nginx
http {
    # Определение зоны кэша
    proxy_cache_path /var/cache/angie/image_cache
        levels=1:2
        keys_zone=image_cache:10m
        max_size=1g
        inactive=24h
        use_temp_path=off;
}

server {
    location @resize {
        proxy_pass http://127.0.0.1:8081$request_uri;

        proxy_cache image_cache;
        proxy_cache_key $host$uri;
        proxy_cache_valid 200 14d;
        proxy_cache_min_uses 2;
        proxy_cache_lock on;
        proxy_cache_use_stale error timeout updating;
        proxy_cache_background_update on;
    }
}
```

### Сценарий: Постоянное хранение (Proxy Store)

Используется, если необходимо сохранить обработанное изображение как обычный статический файл.

```nginx
location @resize {
    proxy_pass http://127.0.0.1:8081$request_uri;
    
    # Сохранение по пути, соответствующему URI
    proxy_store /var/www/images$uri;
    proxy_store_access user:rw group:rw all:r;
}
```

## Дополнительная информация

### Оптимизация производительности

- **`proxy_cache_lock on`** — предотвращает «стадо бизонов» (thundering herd), когда при одновременных запросах только один поток уходит на генерацию изображения.
- **`proxy_cache_background_update on`** — позволяет отдавать клиенту старую версию из кэша, пока в фоне выполняется обновление.
- **`proxy_cache_min_uses`** — защищает кэш от заполнения изображениями, которые запрашиваются только один раз.

### Ограничения

- `Proxy Cache` требует настройки `proxy_cache_path` в контексте `http`.
- `Proxy Store` не поддерживает автоматическую инвалидацию и ограничение по размеру каталога.
