# Модуль image_filter в Angie: изменение размеров и трансформация

## Определения

**Resize (Изменение размера)** — операция пропорционального масштабирования изображения для его вписывания в заданные границы.
**Crop (Обрезка)** — операция масштабирования изображения с последующей обрезкой лишних краев для точного соответствия целевым размерам.
**Convert (Конвертация)** — функциональность Angie, позволяющая "на лету" изменять формат изображения (например, из JPEG в AVIF или WebP).

## Базовые концепции

Модуль `image_filter` в Angie значительно расширен по сравнению со стандартным Nginx. Он поддерживает современные форматы сжатия и позволяет выполнять сложные цепочки трансформаций в рамках одного запроса.

### Основные операции трансформации

| Операция | Описание | Синтаксис |
|:---------|:---------|:----------|
| Изменение размера | Масштабирование с сохранением пропорций (вписывание) | `image_filter resize <w> <h>` |
| Обрезка | Масштабирование и центрирование (заполнение) | `image_filter crop <w> <h>` |
| Конвертация | Принудительное изменение выходного формата | `image_filter convert <type>` |
| Поворот | Вращение изображения (90, 180, 270 градусов) | `image_filter rotate <deg>` |

### Поддерживаемые форматы

Angie поддерживает чтение и запись следующих форматов (при наличии соответствующих библиотек в системе):
- **Классические:** JPEG, PNG, GIF.
- **Современные:** WebP, AVIF, HEIC.

### Управление качеством и сжатием

Для каждого формата предусмотрены индивидуальные настройки, что позволяет тонко балансировать между размером файла и визуальным качеством:

- `image_filter_jpeg_quality`: Качество JPEG (1–100).
- `image_filter_webp_quality`: Качество WebP (1–100).
- `image_filter_avif_quality`: Качество AVIF (1–100).
- `image_filter_avif_speed`: Скорость кодирования AVIF (0–10, выше = быстрее).
- `image_filter_sharpen`: Коэффициент резкости (0–100). Рекомендуется `1–3` при уменьшении.

## Практические сценарии

### Динамический ресайз с конвертацией в AVIF

Этот сценарий позволяет отдавать изображения в современном формате AVIF, динамически меняя их размер на основе параметров запроса.

```nginx
location ~* ^/resize/(?<width>\d+)/(?<image>.+)$ {
    proxy_pass http://storage_backend/$image;
    
    # Установка буфера обработки (важно для исходников > 1MB)
    image_filter_buffer 20M;
    
    # Изменение размера по ширине, высота — авто
    image_filter resize $width -;
    
    # Конвертация в AVIF для экономии трафика
    image_filter convert avif;
    image_filter_avif_quality 60;
    
    # Обработка ошибок (если файл не является изображением)
    error_page 415 = /fallback_static;
}
```

### Создание квадратных миниатюр (Crop)

Для плиточных интерфейсов часто требуются изображения строго заданных размеров без пустых полей.

```nginx
location /thumbnails/ {
    image_filter crop 200 200;
    image_filter_webp_quality 75;
    image_filter_sharpen 2;
    
    # Рекомендуется использовать кэширование результата
    proxy_cache thumbnails_cache;
    proxy_cache_valid 200 30d;
}
```

### Только изменение формата (без ресайза)

Полезно для автоматической оптимизации библиотеки изображений без изменения их физических размеров.

```nginx
location /optimize/ {
    image_filter convert webp;
    image_filter_webp_quality 80;
    
    # Проверка, что файл действительно является изображением
    image_filter test;
}
```

## Дополнительная информация

### Важные рекомендации

1.  **Буферизация:** Директива `image_filter_buffer` критически важна. Если размер исходного изображения превышает установленный буфер (по умолчанию 1M), Angie вернет ошибку `415 Unsupported Media Type`. Для современных камер рекомендуется устанавливать `10M`–`20M`.
2.  **Цепочки команд:** В Angie можно комбинировать команды. Например, `resize` + `rotate` + `convert`.
3.  **Безопасность:** Никогда не позволяйте пользователям передавать произвольные размеры без валидации в регулярных выражениях или `map`. Это может привести к DoS-атаке через исчерпание CPU и RAM.
4.  **Производительность:** Операции с изображениями потребляют много ресурсов CPU. Всегда используйте `proxy_cache` для сохранения результатов трансформации, чтобы не пересчитывать их при каждом запросе.
