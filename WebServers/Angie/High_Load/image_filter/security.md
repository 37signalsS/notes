# Модуль image_filter в Angie: безопасность и защита от DoS

## Определения

**DoS-атака на image_filter** — злонамеренная генерация запросов с произвольными размерами изображений, вызывающая высокую нагрузку на CPU сервера.

## Основные концепции

### Уязвимость image_filter

Модуль image_filter выполняет ресурсоёмкие операции (конвертация форматов, resize), что делает его потенциальной мишенью для DoS-атак. Злоумышленник может:

- Генерировать запросы с произвольными размерами, вызывая повторную обработку изображений
- Создавать нагрузку на CPU, отправляя запросы на большие разрешения
- Обходить кэш, изменяя параметры URL, что приводит к постоянной генерации новых версий

### Методы защиты

1. **Валидация размеров** — разрешать только предопределённые размеры через `map` или regex
2. **Ограничение частоты запросов** — использовать `limit_req` для IP-адресов (см. [защиту от DoS](../dos_protection.md))
3. **Кэширование** — минимизировать повторную обработку одних и тех же изображений
4. **Изоляция нагрузки** — выносить image_filter на отдельный хост/контейнер (см. [производительность](./performance.md))

## Практические сценарии

### Сценарий: Ограничение допустимых размеров через map

**Проблема:** Злоумышленник может генерировать запросы с произвольными размерами, вызывая нагрузку на CPU.

**Решение:** Использовать директиву `map` для создания белых списков разрешённых размеров:

```nginx
# Разрешенные размеры
map $arg_size $valid_size {
    default 0;
    "100x100" 1;
    "200x200" 1;
    "300x300" 1;
    "400x400" 1;
    "800x800" 1;
}

location ~* ^/img/ {
    if ($valid_size = 0) {
        return 400;
    }

    # Обработка изображения...
}
```

### Сценарий: Валидация размеров через regex в location

**Альтернативное решение:** Использовать именованные параметры в regex для жёсткого контроля размеров:

```nginx
location ~* ^/img/(100|200|300)x(100|200|300)(/.+)$ {
    # Только разрешенные размеры (100x100, 200x200, 300x300 и комбинации)
    # Запросы с другими размерами не попадут в этот location
}
```

**Преимущества regex-подхода:**

- Не требует дополнительных проверок `if`
- Более читаемая конфигурация
- Запросы с неразрешёнными размерами автоматически не обрабатываются

## Дополнительная информация

### Комбинирование методов защиты

Для production-окружения рекомендуется комбинировать несколько методов:

1. **Валидация размеров** — блокирует запросы с нестандартными параметрами
2. **Rate limiting** — ограничивает частоту запросов с одного IP (`limit_req`)
3. **Кэширование** — снижает нагрузку на CPU при повторных запросах
4. **Мониторинг** — отслеживание аномальной нагрузки на CPU (см. [мониторинг Angie](../../angie_monitoring/))
