# Модуль image_filter в Angie: производительность и масштабирование

## Определения

**Производительность image_filter** — совокупная характеристика эффективности обработки изображений, измеряемая временем задержки (latency) на операцию и пропускной способностью (throughput) системы при различных типах трансформаций.

## Базовые концепции

### Факторы влияния на задержку

Время обработки одного изображения напрямую зависит от вычислительной сложности алгоритмов и характеристик исходного файла:

- **Формат и сжатие:** Декодирование PNG (особенно с LOSSLESS сжатием) требует значительно больше ресурсов CPU, чем JPEG.
- **Тип трансформации:** Операция `crop` обычно выполняется быстрее, чем `resize`, так как не требует пересчета всех пикселей изображения.
- **Целевой формат:** Кодирование в WebP или AVIF — наиболее ресурсоёмкий этап.
  - **AVIF Tuning:** В Angie скорость кодирования AVIF регулируется директивой `image_filter_avif_speed`. Значение `0` дает максимальное сжатие, но требует огромных ресурсов CPU; значение `10` обеспечивает быструю обработку при чуть большем размере файла.
- **Ориентировочные задержки:**
  - JPEG → WebP: ~40–60 мс.
  - JPEG → AVIF (speed 6): ~150–300 мс.
  - PNG → WebP: ~80–120 мс.
  - Resize: добавляет ~10–20 мс к базовой обработке.

### Стратегии масштабирования

Поскольку `image_filter` является CPU-интенсивным процессом, при росте нагрузки требуется масштабирование:

1. **Вертикальное (Scale Up):** Увеличение количества ядер CPU и выделение большего числа `worker_processes`. Обязательно настраивайте `worker_cpu_affinity` для исключения переключений контекста.
2. **Горизонтальное (Scale Out):** Вынос функционала фильтрации на отдельные инстансы (Dedicated Image Filter Nodes) за балансировщиком нагрузки. В Angie Pro можно использовать метод балансировки `feedback` для выбора наименее загруженного узла на основе времени ответа.
3. **Изоляция в контейнерах:** Использование Docker/Kubernetes для ограничения ресурсов и независимого масштабирования узлов обработки.

## Практические сценарии

### Сценарий: Тюнинг скорости кодирования AVIF

Баланс между качеством сжатия и нагрузкой на CPU для современных форматов.

```nginx
location /img/avif/ {
    image_filter convert avif;
    image_filter_avif_quality 65;
    
    # Ускорение кодирования для снижения Latency (0-10, выше = быстрее)
    image_filter_avif_speed 8; 
    
    image_filter_buffer 20M;
}
```

### Сценарий: Предотвращение «эффекта стада» (Thundering Herd)

При одновременном обращении множества пользователей к одному и тому же отсутствующему в кэше изображению, сервер может попытаться сгенерировать его параллельно во многих потоках, что приведет к CPU Spike.

```nginx
location / {
    proxy_cache image_cache;
    
    # Только один запрос уходит на генерацию, остальные ждут результата
    proxy_cache_lock on;
    proxy_cache_lock_timeout 5s;
    
    # Позволяет отдавать старую версию из кэша, пока обновляется новая
    proxy_cache_use_stale updating;
    
    proxy_pass http://image_filter_backend;
}
```

### Мониторинг через status_zone в Angie

Использование встроенных зон статуса позволяет получать детальную статистику по каждому типу трансформации.

```nginx
server {
    listen 80;
    
    location /resize/ {
        status_zone image_resize;
        proxy_pass http://127.0.0.1:8081;
    }
}
```

**Метрики для анализа:**
- **Requests per second:** На конкретной `status_zone`.
- **Response time distribution:** Время обработки на внутреннем сервере.
- **Discarded requests:** Количество запросов, отсеченных лимитами или упавших по таймауту обработки.

## Дополнительная информация

### Тюнинг и ограничения

- **Последовательная обработка:** В рамках одного рабочего процесса изображения обрабатываются последовательно. Параллелизм достигается только за счет множества `worker_processes`.
- **Общие настройки производительности:** Глобальные параметры оптимизации (CPU affinity, лимиты файлов) описаны в [общем руководстве по производительности](../performance_optimization.md).
- **Альтернативы:** При экстремальных нагрузках (десятки тысяч запросов в секунду) рассмотрите специализированные микросервисы (Thumbor, Imaginary) или CDN с поддержкой Image Optimization.
