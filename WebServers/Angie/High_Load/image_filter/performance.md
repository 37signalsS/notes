# Модуль image_filter в Angie: производительность и масштабирование

## Определения

**Производительность image_filter** — время обработки изображений, зависящее от формата, размера и типа операции (конвертация, resize).

## Основные концепции

### Производительность

**Время обработки (ориентировочно):**

- JPEG → WebP: ~40-60 мс
- PNG → WebP: ~80-120 мс (LOSSLESS формат)
- С resize: +10-20 мс

**Рекомендации:**

1. Всегда используйте кэширование
2. Для высоких нагрузок — отдельный хост/контейнер для image_filter
3. Ограничьте допустимые размеры
4. Используйте `proxy_cache_min_uses 2` для исключения одноразовых запросов

### Масштабирование

1. **Отдельный хост:** Image_filter на другом сервере с доступом к общему хранилищу
2. **Контейнеризация:** Запуск в Docker для изоляции нагрузки
3. **Горизонтальное масштабирование:** Несколько инстансов за балансировщиком

## Практические сценарии

### Проверка работы

```bash
# Проверка формата (должен быть WebP)
curl -I https://images.example.com/img/photo.jpg | grep Content-Type

# Проверка времени ответа (первый запрос медленный, последующие из кэша)
curl -w "@curl-format.txt" -o /dev/null -s https://images.example.com/img/photo.jpg

# curl-format.txt:
# time_namelookup:  %{time_namelookup}\n
# time_connect:     %{time_connect}\n
# time_starttransfer: %{time_starttransfer}\n
# ----------\n
# time_total:       %{time_total}\n
```
