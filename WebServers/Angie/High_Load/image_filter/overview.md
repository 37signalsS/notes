# Модуль image_filter в Angie: обзор возможностей

## Определения

**Модуль image_filter** — высокопроизводительный динамический модуль Angie, предназначенный для трансформации изображений в режиме реального времени. Он является глубоко переработанной версией стандартного модуля Nginx, расширенной инженерами Angie для поддержки современных форматов сжатия и гибкого управления качеством.

## Базовые концепции

Модуль `ngx_http_image_filter_module` является фундаментом для построения систем адаптивной доставки контента (Adaptive Image Delivery). Его использование позволяет хранить на диске только оригиналы изображений высокого качества, генерируя необходимые вариации (размеры, форматы) по запросу.

### Ключевые преимущества Angie

1.  **Поддержка форматов нового поколения:** В отличие от базового Nginx, Angie нативно поддерживает чтение и запись **AVIF**, **WebP** и **HEIC**.
2.  **Директива Convert:** Позволяет менять формат (например, JPEG → AVIF) без изменения геометрии изображения, что критично для оптимизации трафика без потери композиции.
3.  **Тонкий тюнинг кодеков:** Специализированные директивы (например, `image_filter_avif_speed`) позволяют балансировать между нагрузкой на CPU и степенью сжатия.
4.  **Прогрессивная загрузка:** Поддержка `image_filter_interlace` для JPEG, что улучшает пользовательский опыт на медленных каналах связи.
5.  **Нативная наблюдаемость:** Интеграция с `status_zone` позволяет отслеживать метрики трансформаций через API в реальном времени.

### Архитектура системы обработки

Для обеспечения стабильности под высокой нагрузкой (High Load) обязательным является использование схемы **двухуровневого проксирования**.

#### Схема динамической обработки

```
Клиент (Accept: image/avif) → [Фронтенд: Проверка кэша] 
                                ↓
                                MISS → [Внутренний прокси: Трансформация]
                                          ↓
                                          [Запрос оригинала у хранилища]
                                          ↓
                                          [Применение image_filter: Resize/Convert]
                                          ↓
                                HIT ← [Кэширование результата + Vary: Accept]
```

**Ключевые аспекты архитектуры:**
- **Изоляция:** Тяжелые операции обработки (особенно AVIF) выносятся на внутренние воркеры или отдельные инстансы, чтобы не блокировать быструю отдачу статики.
- **Управление кэшем:** Обязательная передача заголовка `Vary: Accept`, чтобы разные браузеры получали подходящие им форматы (AVIF для Chrome, JPEG для старых Safari) по одному URL.
- **Эффективность:** В `proxy_cache` сохраняется готовый результат. Оригинал запрашивается только один раз при промахе кэша (cache miss).

## Практические сценарии

### Выбор стратегии трансформации

| Параметр | Динамическая (image_filter) | Статическая (Pre-generated) |
|:---------|:----------------------------|:----------------------------|
| **Дисковое место** | Минимальное (только оригинал) | Высокое (копии всех размеров) |
| **Нагрузка на CPU** | Высокая (при заполнении кэша) | Минимальная (только IO) |
| **Гибкость** | Любой размер по запросу | Только фиксированный набор |
| **Latency (первый запрос)** | Зависит от формата (AVIF — долго) | Минимальная |

### Базовые операции

- **`resize`**: Масштабирование изображения с сохранением пропорций.
- **`crop`**: Обрезка краев для достижения точного соответствия заданным размерам.
- **`convert`**: Принудительная смена формата.
- **`rotate`**: Поворот на 90, 180 или 270 градусов.

## Дополнительная информация

### Установка и подключение

Модуль поставляется в виде динамической библиотеки и подключается в основном контексте `angie.conf`:

```nginx
load_module modules/ngx_http_image_filter_module.so;
```

### Технические ограничения и особенности

1.  **Буферизация (`image_filter_buffer`):** По умолчанию лимит составляет 1 MB. Для современных фотографий высокого разрешения этот параметр необходимо увеличивать до 10–20 MB, иначе сервер вернет ошибку `415 Unsupported Media Type`.
2.  **Зависимость от libgd:** Поддержка форматов (WebP, AVIF) зависит от версии системной библиотеки `libgd`. Перед использованием проверьте поддержку через `angie -V`.
3.  **Безопасность:** Параметры трансформации в URL должны валидироваться. Прямой проброс размеров без ограничений позволяет злоумышленникам вызвать CPU DoS.
4.  **Ресурсоемкость AVIF:** Кодирование AVIF требует в 10–50 раз больше ресурсов CPU, чем JPEG. Используйте `image_filter_avif_speed` со значением `8–10` для баланса производительности.
