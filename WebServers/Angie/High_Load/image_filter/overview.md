# Модуль image_filter в Angie: обзор возможностей

## Определения

**Модуль image_filter** — динамический модуль Angie, предназначенный для трансформации изображений в режиме реального времени. В отличие от базовых реализаций, версия в Angie поддерживает современные стандарты сжатия и расширенные команды управления форматами.

## Базовые концепции

Модуль `ngx_http_image_filter_module` в Angie является ключевым компонентом для построения систем адаптивной доставки контента, позволяя экономить дисковое пространство и сетевой трафик.

### Ключевые отличия Angie от стандартного Nginx

1.  **Расширенная поддержка форматов:** Помимо JPEG, PNG и GIF, Angie нативно поддерживает **AVIF**, **WebP** и **HEIC** как для чтения, так и для записи.
2.  **Директива Convert:** Позволяет принудительно изменить формат изображения (например, PNG → AVIF) без изменения его размеров.
3.  **Управление качеством и скоростью:** Индивидуальные директивы для настройки качества и скорости кодирования (например, `image_filter_avif_speed`).
4.  **Нативная наблюдаемость:** Полная интеграция с `status_zone` и API Angie для мониторинга производительности трансформаций.

### Архитектура системы обработки

Для обеспечения стабильности и производительности под высокой нагрузкой рекомендуется использовать схему **двухуровневого проксирования**.

#### Схема динамической обработки

```
Клиент → [Фронтенд: Проверка кэша] 
            ↓
            MISS → [Внутренний прокси: Трансформация]
                      ↓
                      [Запрос оригинала у хранилища]
                      ↓
                      [Применение image_filter: Resize/Convert]
                      ↓
            HIT ← [Кэширование результата обработки]
```

**Преимущества такой архитектуры:**
- **Изоляция:** Тяжелые операции обработки не блокируют воркеры, отвечающие за TLS и доставку кэшированного контента.
- **Эффективность кэша:** В зоне `proxy_cache` сохраняется уже готовый результат трансформации (например, AVIF нужного размера), а не оригинал.
- **Отказоустойчивость:** При сбоях модуля трансформации фронтенд может отдать оригинал или заглушку.

## Практические сценарии

### Выбор стратегии трансформации

| Параметр | Динамическая (image_filter) | Статическая (Pre-generated) |
|:---------|:----------------------------|:----------------------------|
| **Дисковое место** | Минимальное (только оригинал) | Высокое (копии всех размеров) |
| **Нагрузка на CPU** | Высокая (при заполнении кэша) | Минимальная (только IO) |
| **Гибкость** | Любой размер по запросу | Только фиксированный набор |
| **Latency (первый запрос)** | Выше (время обработки) | Минимальная |

### Базовые операции

Модуль поддерживает следующие типы манипуляций, которые можно комбинировать:
- **`resize`**: Уменьшение до заданных границ с сохранением пропорций.
- **`crop`**: Масштабирование и обрезка краев для точного размера.
- **`convert`**: Смена формата (например, для конвертации всех JPEG в WebP на лету).
- **`rotate`**: Поворот изображения на фиксированные углы.

## Дополнительная информация

### Установка и подключение

Модуль устанавливается как отдельный пакет и требует явной загрузки в основной конфигурации:

```nginx
# В начале angie.conf
load_module modules/ngx_http_image_filter_module.so;
```
Подробности установки описаны в [руководстве по установке](./installation.md).

### Технические ограничения и особенности

1.  **Зависимость от libgd:** Функциональность модуля напрямую зависит от версии библиотеки `libgd` и включенной в ней поддержки форматов в ОС.
2.  **Буферизация:** По умолчанию буфер для обработки составляет 1MB. Для современных фотографий его необходимо увеличивать через `image_filter_buffer`.
3.  **Безопасность:** Использование параметров размера напрямую из URL без валидации открывает вектор для DoS-атак. Обязательно ограничивайте допустимые значения через регулярные выражения, `map` или механизмы подписи ссылок (`secure_link`).
4.  **Ресурсоемкость:** Операции с AVIF требуют значительно больше времени CPU. Рекомендуется использовать `image_filter_avif_speed` для оптимизации Latency.
