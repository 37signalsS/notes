# Модуль image_filter в Angie: обзор

## Определения

**Модуль image_filter** — динамический модуль Angie для обработки изображений на лету: конвертация форматов (WebP, AVIF), изменение размеров (resize), оптимизация качества.

## Основные концепции

### Отличия от Nginx

В Nginx модуль `ngx_http_image_filter_module` имеет ограниченную функциональность:

- Поддерживает JPEG, WebP
- **Не умеет конвертировать** форматы
- Требует компиляции

В Angie модуль image_filter расширен:

- **Конвертация форматов:** JPEG/PNG/GIF → WebP/AVIF
- **Resize:** Изменение размеров с сохранением пропорций
- **Динамическая обработка:** Отдача оптимизированных изображений на лету
- **Пакетная установка:** Модуль доступен из репозитория без компиляции

> **Важно:** Поддержка AVIF требует libavif.

### Архитектура решения

Существует два основных подхода к оптимизации изображений:

1. **Статическая генерация (рекомендуется):**
   - Заранее создаются 2-3 версии каждого изображения (JPEG/PNG, WebP, AVIF)
   - Веб-сервер выбирает формат по заголовку `Accept`
   - Максимальная производительность, нет нагрузки на CPU при запросе
   - Требует места на диске для хранения всех версий

2. **Динамическая обработка (image_filter):**
   - Обработка происходит на лету при первом запросе
   - Экономия дискового пространства (нет дубликатов)
   - Нагрузка на CPU при генерации (~40-100 мс на изображение)
   - Требует кэширования результатов

> **Рекомендация:** Для production используйте статическую генерацию. Image_filter подходит для:
>
> - Пользовательского контента (загружаемые файлы)
> - Динамических изображений с параметрами
> - Средних нагрузок с правильным кэшированием

### Схема работы

```
Клиент → Image Front (порт 80/443) → Проверка кэша
                                     ↓
                                     MISS → Proxy → Image Filter (порт 8081)
                                                      ↓
                                              Обработка + Resize
                                                      ↓
                                              Конвертация в WebP/AVIF
                                                      ↓
                                     HIT ← Кэширование ← Сохранение
```

**Компоненты:**

1. **Image Front:** Основной сайт, раздает изображения, кэширует результаты
2. **Image Filter:** Внутренний сервер на порту 8081, обрабатывает изображения
3. **Proxy Cache:** Хранит сгенерированные версии на диске или в памяти

## Практические сценарии

### Когда использовать image_filter

**Подходит для:**

- Пользовательского контента (загружаемые файлы)
- Динамических изображений с параметрами
- Средних нагрузок с правильным кэшированием

**Не подходит для:**

- Высоконагруженных production-систем (рекомендуется статическая генерация)
- Изображений с жесткими требованиями к скорости отдачи
- Сценариев без возможности кэширования

### Примеры URL

```
# Прямая отдача (конвертация в WebP на лету)
https://images.example.com/img/photo.jpg

# С изменением размера
https://images.example.com/img/100x100/photo.jpg

# Только ширина
https://images.example.com/img/200x-/photo.jpg

# AVIF (если поддерживается)
https://images.example.com/avif/img/photo.jpg
```

## Дополнительная информация

### Установка

```bash
# Установка Angie и модуля image_filter (Debian/Ubuntu)
apt install angie angie-module-image-filter
```

Модуль доступен из официального репозитория Angie — компиляция не требуется.

**Загрузка модуля:**

```nginx
load_module modules/ngx_http_image_filter_module.so;
```

### Ограничения

- Нет конвертации без resize в некоторых конфигурациях (требует отладки)
- AVIF требует libavif (может отсутствовать в дистрибутивах)
- Нагрузка на CPU при обработке
- Нет апскейла (защита от некорректных запросов)
