# Модуль image_filter в Angie: обзор

## Определения

**Модуль image_filter** — динамический модуль Angie для обработки изображений в режиме реального времени. Позволяет изменять размеры (resize), обрезать (crop), поворачивать изображения и конвертировать их в современные форматы (WebP, AVIF).

## Базовые концепции

### Отличия от Nginx

В стандартном Nginx модуль `ngx_http_image_filter_module` обладает базовой функциональностью:

- Поддержка JPEG, GIF, PNG и WebP.
- Отсутствие встроенной конвертации между форматами.
- Часто требует ручной компиляции с `libgd`.

В Angie возможности модуля существенно расширены:

- **Конвертация на лету:** JPEG/PNG/GIF → WebP/AVIF.
- **Улучшенный Resize:** Высокая производительность при изменении размеров.
- **Готовые пакеты:** Установка из репозитория без необходимости сборки из исходников.

### Архитектура решения

Оптимизация изображений в высоконагруженных системах обычно строится по одной из двух схем:

1. **Статическая генерация (рекомендуется):**
   - Все версии изображений (WebP, AVIF) создаются заранее.
   - Выбор формата осуществляется через заголовок `Accept` или расширение.
   - Минимальная нагрузка на CPU, максимальная скорость отдачи.
   - Требует значительного дискового пространства.

2. **Динамическая обработка (image_filter):**
   - Изображения генерируются при первом обращении.
   - Экономия места на диске (хранится только оригинал).
   - Требует обязательного кэширования для предотвращения перегрузки CPU.

### Схема работы динамической обработки

```
Клиент → Image Front (порт 80/443) → Проверка кэша
                                     ↓
                                     MISS → Proxy → Image Filter (порт 8081)
                                                      ↓
                                              Обработка (Resize/Crop)
                                                      ↓
                                              Конвертация (WebP/AVIF)
                                                      ↓
                                     HIT ← Кэширование ← Сохранение
```

**Компоненты системы:**

- **Image Front:** Фронтенд-сервер, отвечающий за SSL, проверку кэша и проксирование запросов.
- **Image Filter:** Внутренний инстанс, выполняющий ресурсоёмкие операции трансформации.
- **Proxy Cache:** Зона кэширования для хранения результатов обработки.

## Практические сценарии

### Выбор метода обработки

**Используйте image_filter, если:**

- У вас огромный объем пользовательского контента (User Generated Content), который нецелесообразно хранить в нескольких копиях.
- Требуется динамическое изменение размеров под произвольные сетки устройств.
- Настроено эффективное многоуровневое кэширование.

**Избегайте image_filter, если:**

- Критична минимальная задержка (Latency) при первом запросе.
- Ресурсы CPU ограничены и нет возможности горизонтального масштабирования инстансов фильтрации.

### Примеры структуры URL

Для организации обработки часто используются следующие паттерны URL:

```bash
# Изменение размера под конкретный прямоугольник
https://images.example.com/resize/200x200/path/to/image.jpg

# Пропорциональное изменение по ширине
https://images.example.com/resize/400x-/path/to/image.jpg

# Принудительная конвертация в AVIF
https://images.example.com/convert/avif/path/to/image.jpg
```

## Дополнительная информация

### Установка и настройка

Модуль поставляется в виде динамического пакета. Инструкции по установке и подключению модуля доступны в файле [Установка и настройка](./installation.md).

### Ограничения и особенности

- **Поддержка AVIF:** Требует наличия `libavif` в системе.
- **Производительность:** Обработка одного изображения может занимать от 20 до 150 мс.
- **Апскейл:** По умолчанию модуль не увеличивает изображения, размеры которых меньше целевых (защита качества).
- **Буферизация:** Требует настройки `image_filter_buffer_size` для работы с большими файлами.
