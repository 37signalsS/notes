# Оптимизация производительности Angie

## Определения

**Оптимизация производительности (Performance Optimization)** — комплекс конфигурационных и архитектурных мер, направленных на повышение пропускной способности сервера (RPS — Requests Per Second) и минимизацию задержек (Latency, TTFB — Time To First Byte) при наиболее эффективном использовании аппаратных ресурсов (CPU, RAM, Disk I/O, Network).

## Базовые концепции

Angie (форк Nginx) расширяет возможности стандартного веб-сервера, включая в себя инструменты, которые позволяют эффективно масштабировать нагрузку и обеспечивать прозрачность работы системы.

### Ключевые области оптимизации

1.  **Вычислительные ресурсы:** Управление рабочими процессами, привязка к ядрам CPU (Affinity) и использование пулов потоков для тяжелых операций.
2.  **Сетевая подсистема:** Тюнинг стека TCP/IP на уровне ядра ОС и использование эффективных алгоритмов обработки соединений (eBPF для QUIC).
3.  **Дисковая подсистема:** Минимизация блокировок воркеров при операциях чтения/записи через асинхронный ввод-вывод (AIO).
4.  **Прикладной уровень (L7):** Оптимизация протоколов (HTTP/2, HTTP/3), эффективное сжатие (Zstd) и кэширование.
5.  **Наблюдаемость (Observability):** Использование встроенных метрик для выявления узких мест без накладных расходов на внешние экспортеры.

## Практические сценарии

### Сценарий 1: Системный тюнинг (sysctl)

Максимальная производительность Angie невозможна без настройки параметров ядра Linux, управляющих сетевым стеком.

**Пример конфигурации `/etc/sysctl.d/90-angie.conf`:**

```bash
# Увеличение очереди прослушиваемых сокетов (согласовать с backlog в Angie)
net.core.somaxconn = 65535

# Расширение диапазона эфемерных портов для исходящих соединений
net.ipv4.ip_local_port_range = 1024 65535

# Быстрое переиспользование сокетов в состоянии TIME_WAIT
net.ipv4.tcp_tw_reuse = 1

# Запрет сброса Slow Start после простоя (важно для Keep-Alive)
net.ipv4.tcp_slow_start_after_idle = 0

# Использование алгоритма BBR для управления перегрузкой (требует ядра 4.9+)
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
```

Применение: `sysctl --system`. Подробнее см. в разделе **[Тюнинг параметров ядра (sysctl)](../../../Linux/Core/kernel/sysctl.md)**.

### Сценарий 2: Многопоточность и асинхронный I/O

В Angie можно вынести блокирующие операции чтения файлов в отдельные пулы потоков, чтобы основной воркер не простаивал в ожидании диска.

```nginx
# В контексте main
# threads=32: количество потоков в пуле
# max_queue=65536: размер очереди задач
thread_pool default threads=32 max_queue=65536;

http {
    sendfile on;
    tcp_nopush on;
    
    # Включаем использование пула потоков для чтения
    aio threads;
    
    # Ограничение размера чанка при sendfile (предотвращает монополизацию воркера)
    sendfile_max_chunk 512k;

    server {
        location /video/ {
            aio threads=default;
            # Рекомендуется использовать с directio для больших файлов
            directio 8m;
        }
    }
}
```

### Сценарий 3: Оптимизация HTTP/3 и eBPF

В отличие от стандартного Nginx, Angie использует eBPF (`quic_bpf`) для стабильной маршрутизации UDP-пакетов между рабочими процессами, что предотвращает разрыв QUIC-сессий при перезагрузке конфигурации.

### Сценарий 5: Оптимизация взаимодействия с бэкендами

Angie OS позволяет использовать алгоритмы балансировки, минимизирующие время ответа.

```nginx
upstream backend_cluster {
    # Балансировка по минимальному времени ответа
    # header: время получения заголовков
    # last_byte: время получения всего ответа
    least_time header;
    
    server 10.0.0.1:8080;
    server 10.0.0.2:8080;
    
    # Держим открытыми 64 соединения на каждый воркер
    keepalive 64;
    # Используем HTTP/1.1 для keep-alive к бэкендам
    keepalive_prober on; 
}
```

### Сценарий 6: Наблюдаемость через status_zone

Нативная поддержка метрик позволяет отслеживать производительность без внешних экспортеров.

```nginx
http {
    server {
        listen 80;
        status_zone server_traffic;

        location /api/ {
            status_zone api_traffic;
            proxy_pass http://backend_cluster;
        }
    }

    # Сервер мониторинга
    server {
        listen 127.0.0.1:8080;
        location /status {
            # Включает встроенный API Angie
            api /status/;
            allow 127.0.0.1;
            deny all;
        }
    }
}
```

## Дополнительная информация

### Рекомендации по тюнингу

1.  **PCRE JIT:** Всегда включайте `pcre_jit on;` в контексте `main` для ускорения обработки регулярных выражений в `location` и `rewrite`.
2.  **Worker Shutdown Timeout:** При высокой нагрузке на Keep-Alive используйте `worker_shutdown_timeout 10s;`, чтобы предотвратить бесконечное ожидание старых воркеров при релоаде.
3.  **Open File Cache:** Используйте `open_file_cache` для снижения количества системных вызовов `open` и `stat` при раздаче статики.
4.  **Бенчмаркинг:** Для тестирования производительности используйте современные инструменты: `wrk`, `k6` или `h2load`.
