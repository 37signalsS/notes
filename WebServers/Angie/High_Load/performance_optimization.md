# Оптимизация производительности Angie

## Определения

**Оптимизация производительности** веб-сервера — это комплекс мер по настройке операционной системы и программного обеспечения для наиболее эффективного использования ресурсов (центральный процессор (CPU), оперативная память, дисковая и сетевая подсистемы) и повышения пропускной способности.

## Базовые концепции

### Подходы к оптимизации

- **Серверная производительность:** Эффективное использование ресурсов сервера. Цели: минимизация потребления ресурсов, повышение пропускной способности (количество запросов в секунду — RPS, Requests Per Second).
- **Клиентская производительность:** Ускорение загрузки и отрисовки контента в браузере клиента. Цели: сокращение трафика, оптимизация кэширования, снижение задержек (время до первого байта — TTFB, Time To First Byte).

### Связь с Nginx

[Angie](../angie_overview.md) является форком Nginx с сохранением полной совместимости. Большинство методов оптимизации идентичны для обоих серверов.

Основной источник по тюнингу параметров: **[Оптимизация производительности Nginx](../../Nginx/Performance/nginx_performance_tuning.md)**.

## Практические сценарии

### Сценарий 1: Базовая настройка сервера под высокую нагрузку

Приведенные ниже параметры являются критически важными для обработки большого потока соединений. Подробное описание механизмов их работы см. в [руководстве по тюнингу Nginx](../../Nginx/Performance/nginx_performance_tuning.md).

#### Системные ресурсы и процессы

- **`worker_processes auto;`**: Создает по одному рабочему процессу на каждое ядро CPU.
- **`worker_cpu_affinity auto;`**: Привязывает процессы к ядрам процессора для оптимизации использования кэша.
- **`worker_rlimit_nofile 100000;`**: Увеличивает лимит открытых файловых дескрипторов.
- **`events { worker_connections 20000; }`**: Максимальное число соединений на один процесс.

#### Сетевые параметры

- **`sendfile on;`**: Использование системного вызова для прямой передачи файлов в сокет. Требует включения Kernel TLS для работы по протоку передачи гипертекста с шифрованием (HTTPS). См. [Kernel TLS в Nginx](../../Nginx/Performance/nginx_performance_tuning.md#kernel-tls-ktls).
- **`tcp_nopush on;` и `tcp_nodelay on;`**: Оптимизация формирования и отправки сетевых пакетов.
- **`listen 443 ssl reuseport;`**: Ускоряет распределение входящих соединений между процессами на многоядерных системах.
- **`keepalive_timeout 120s;`**: Увеличение времени удержания постоянного соединения.

### Сценарий 2: Использование серверного кэширования

Кэширование ответов от бэкендов значительно снижает нагрузку на приложение и ускоряет ответ клиенту.

Ключевые директивы для высоконагруженных систем:

- **`proxy_cache_lock on;`**: Предотвращает лавинообразную нагрузку на бэкенд при отсутствии элемента в кэше («стадо бизонов»).
- **`proxy_cache_background_update on;`**: Позволяет отдавать клиенту устаревший контент немедленно, пока Angie обновляет его в фоновом режиме.

Полное руководство: **[Серверное кэширование в Nginx](../../Nginx/Performance/Caching/proxy_caching.md)**.

---

### Сценарий 3: Клиентская оптимизация и сжатие

Для ускорения взаимодействия с браузером используются современные протоколы и алгоритмы сжатия данных.

- **Версии протокола HTTP:** Включайте HTTP/2 и HTTP/3 для параллельной загрузки ресурсов. Подробнее: [Настройка версий HTTP в Nginx](../../Nginx/Performance/nginx_http_versions.md).
- **Сжатие контента:** Используйте **Zstd** для динамических данных и **Brotli** для статичных файлов. См. [Сжатие в Nginx](../../Nginx/Performance/nginx_compression.md).

### Сценарий 4: Специфические оптимизации в Angie

Angie включает в себя функции, доступные в коммерческой версии Nginx (Plus), а также уникальные разработки для повышения производительности и наблюдаемости.

- **Встроенный мониторинг:** Поддержка экспорта метрик в формате системы мониторинга Prometheus позволяет отслеживать производительность в реальном времени без сторонних модулей.
- **Оптимизация HTTP/3 (QUIC) через BPF:**
  - Директива `quic_bpf on;` использует механизм фильтрации пакетов в ядре (BPF, Berkeley Packet Filter) для эффективного распределения датаграмм протокола пользовательских датаграмм (UDP, User Datagram Protocol) между рабочими процессами. Это критически важно для стабильности QUIC (Quick UDP Internet Connections) при высоких нагрузках.
- **Управление анонсированием HTTP/3:**
  - При использовании заголовка `Alt-Svc` учитывайте параметр `ma` (max-age). Клиенты кэшируют доступность порта UDP на указанное время. Если порт станет недоступен раньше, клиенты могут испытывать задержки.
