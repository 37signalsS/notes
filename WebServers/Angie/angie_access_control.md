# Контроль доступа в Angie

В [Angie](./angie_overview.md), как и в Nginx, существует несколько встроенных и сторонних механизмов для управления доступом к сайтам и их отдельным частям (locations). Эти механизмы позволяют гибко настраивать правила, по которым пользователи и системы могут получать доступ к ресурсам.

В этом руководстве рассмотрены четыре основных способа контроля доступа:
1.  Ограничение по IP-адресу.
2.  Базовая аутентификация (логин/пароль).
3.  Аутентификация через подзапрос к бэкенду.
4.  Аутентификация с помощью системных пользователей (PAM).

## 1. Ограничение по IP-адресу (`ngx_http_access_module`)

Это самый простой способ ограничить доступ, разрешив его только для определённых IP-адресов или подсетей.

### Конфигурация

Директивы `allow` и `deny` обрабатываются последовательно, сверху вниз. Первое совпавшее правило определяет результат.

```nginx
location /protected/ {
    # 1. Разрешаем доступ из локальной сети
    allow 192.168.1.0/24;
    
    # 2. Разрешаем доступ с конкретного IP
    allow 203.0.113.5;

    # 3. Запрещаем доступ всем остальным
    deny all;

    # ... остальная конфигурация
}
```

-   **`allow`**: Разрешает доступ для указанной сети или адреса.
-   **`deny all`**: Запрещает доступ всем, кто не подпал под предыдущие правила `allow`.

> **Примечание:** Этот и другие механизмы контроля доступа подробно описаны в общем руководстве по безопасности: **[Руководство по безопасности веб-сервера Nginx](../Nginx/Security/nginx_security_guide.md)**.

## 2. Базовая аутентификация (`ngx_http_auth_basic_module`)

Этот метод позволяет защитить ресурс с помощью стандартного окна ввода логина и пароля в браузере.

### Конфигурация

1.  **Создание файла с паролями:**
    Для создания файла с пользователями и паролями используется утилита `htpasswd` (обычно из пакета `apache2-utils`).
    ```bash
    # Создать файл и добавить первого пользователя
    sudo htpasswd -c /etc/angie/htpasswd-users admin

    # Добавить еще одного пользователя (без флага -c)
    sudo htpasswd /etc/angie/htpasswd-users guest
    ```

2.  **Настройка Angie:**
    В блоке `location` или `server` необходимо указать путь к файлу с паролями.
    ```nginx
    location /admin/ {
        auth_basic "Administrator Area";
        auth_basic_user_file /etc/angie/htpasswd-users;
    }
    ```
    - `auth_basic "Administrator Area"`: Текст, который увидит пользователь в диалоговом окне.
    - `auth_basic_user_file`: Путь к файлу с паролями.

**Ограничения:**
-   Все пользователи, перечисленные в файле `auth_basic_user_file`, будут иметь доступ. Для разграничения прав для разных `location` необходимо создавать разные файлы с паролями.
-   **Безопасность:** Данные передаются в кодировке Base64, поэтому базовую аутентификацию **необходимо** использовать только совместно с [шифрованием TLS (HTTPS)](./angie_tls_setup.md).

### Комбинирование с ограничением по IP (`satisfy`)

Директива `satisfy` позволяет комбинировать несколько методов аутентификации.

-   `satisfy all;` (по умолчанию): Требует, чтобы **все** условия (IP-адрес и пароль) были выполнены.
-   `satisfy any;`: Требует, чтобы **хотя бы одно** из условий было выполнено.

**Пример:** Разрешить доступ либо из локальной сети, либо по паролю.
```nginx
location /admin/ {
    satisfy any; # Разрешить, если выполнено любое из правил

    # Правило 1: ограничение по IP
    allow 192.168.1.0/24;
    deny all;

    # Правило 2: базовая аутентификация
    auth_basic "Admin Area";
    auth_basic_user_file /etc/angie/htpasswd-users;
}
```

## 3. Аутентификация через подзапрос (`ngx_http_auth_request_module`)

Это наиболее гибкий метод, позволяющий делегировать принятие решения о доступе внешнему сервису (бэкенду). Angie отправляет на специальный "авторизующий" `location` подзапрос, и на основе полученного кода ответа принимает решение.

-   Код ответа `200 OK`: Доступ разрешен.
-   Коды ответа `401 Unauthorized` или `403 Forbidden`: Доступ запрещен.

### Практический пример с использованием `njs`

В этом примере логика авторизации реализована на JavaScript с помощью модуля `njs`.

1.  **Настройка Angie:**
    ```nginx
    # /etc/angie/angie.conf
    http {
        # ...
        # Импортируем js-модуль с логикой авторизации
        js_import /etc/angie/scripts/auth.js;
    }

    # /etc/angie/sites-available/default
    server {
        # ...

        # 1. Location, который будет проверять подзапросы
        location = /_auth_request {
            internal; # Доступен только для внутренних запросов
            js_content auth.authorize; # Вызываем функцию authorize из импортированного модуля
        }

        # 2. Защищаемый location
        location /secure/ {
            auth_request /_auth_request; # Включаем проверку
            
            # Переменные из модуля auth_request можно передать бэкенду
            # proxy_set_header X-User-ID $upstream_http_x_user_id;
            
            proxy_pass http://my_backend;
        }
    }
    ```

2.  **Скрипт `auth.js` с логикой авторизации:**
    ```javascript
    // /etc/angie/scripts/auth.js

    function authorize(r) {
        // Пример: проверяем наличие и значение заголовка Authorization
        const authHeader = r.headersIn['Authorization'];

        if (authHeader && authHeader.startsWith('Bearer ') && authHeader.substring(7) === 'secret_token') {
            // Если токен верный, возвращаем 204 No Content (эквивалентно 200 OK для auth_request)
            // и можем передать данные бэкенду через заголовки
            r.headersOut['X-User-ID'] = '123';
            r.return(204);
            return;
        }

        // В противном случае запрещаем доступ
        r.return(401, "Authorization Required");
    }

    export default { authorize };
    ```
Этот подход позволяет реализовать любую, сколь угодно сложную логику авторизации (проверка JWT, сессий, API-ключей и т.д.), не перегружая основной конфигурационный файл Angie.

## 4. Аутентификация через PAM (`ngx_http_auth_pam_module`)

Этот сторонний модуль позволяет аутентифицировать пользователей через стандартный механизм **Pluggable Authentication Modules (PAM)** в Linux. Это означает, что для доступа к сайту можно использовать системных пользователей и их пароли.

### Конфигурация

1.  **Установка модуля:**
    Для Angie Pro модуль устанавливается пакетом `angie-pro-module-pam`. Для Open Source версии может потребоваться самостоятельная сборка.

2.  **Подключение модуля:**
    В `angie.conf` необходимо добавить директиву `load_module`.
    ```nginx
    # /etc/angie/angie.conf
    load_module modules/ngx_http_auth_pam_module.so;
    ```

3.  **Создание конфигурации сервиса PAM:**
    Создайте файл `/etc/pam.d/angie` со следующим содержимым:
    ```
    # /etc/pam.d/angie
    auth    required    pam_unix.so
    account required    pam_unix.so
    ```
    Это указывает PAM использовать для аутентификации стандартный модуль `pam_unix`, который проверяет пользователей по `/etc/passwd` и `/etc/shadow`.

4.  **Настройка Angie:**
    ```nginx
    location /private/ {
        auth_pam "System Login Required";
        auth_pam_service_name "angie"; # Имя сервиса, созданного на шаге 3
    }
    ```
    Теперь при доступе к `/private/` Angie запросит логин и пароль и проверит их через системную базу пользователей Linux.

## 5. Другие модули

Существуют и другие модули для более специфических задач аутентификации, которые доступны для Angie, например:
-   **`auth-jwt`**: Для валидации [JSON Web Tokens (JWT)](../../Security/Concepts/jwt.md).
-   **LDAP**: Для интеграции с корпоративными каталогами.

Выбор конкретного метода зависит от требований к безопасности, гибкости и существующей инфраструктуры.
