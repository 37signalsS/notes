# Настройка TLS в Angie: безопасность и скорость

В этом руководстве рассматривается настройка безопасного и производительного TLS (HTTPS) для сайта на веб-сервере Angie.

## 1. Глобальные настройки в блоке `http`

Эти настройки применяются ко всему серверу и оптимизируют работу TLS. Их следует размещать в файле `angie.conf` внутри блока `http`.

### 1.1. Keep-Alive соединения

Длительные keep-alive соединения позволяют клиентам повторно использовать одно TCP-соединение для нескольких HTTP-запросов, что значительно сокращает задержки, связанные с установкой новых соединений и TLS-рукопожатий (handshake).

```nginx
http {
    # ...
    keepalive_timeout 120s;
    keepalive_requests 10000;
    # ...
}
```
- `keepalive_timeout`: Устанавливает таймаут для keep-alive соединения.
- `keepalive_requests`: Максимальное количество запросов, которое можно сделать через одно keep-alive соединение.

### 1.2. Кэширование сессий TLS

Кэширование параметров сессии TLS позволяет клиентам быстро возобновлять сессии, пропуская полное рукопожатие.

#### Для TLS 1.2 и ниже (`ssl_session_cache`)

```nginx
http {
    # ...
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 24h;
    # ...
}
```
- `ssl_session_cache shared:SSL:10m`: Создает разделяемую между всеми worker-процессами кэш-память размером 10 МБ для хранения сессий.
- `ssl_session_timeout 24h`: Устанавливает время жизни сессии в кэше.

#### Для TLS 1.3 (`ssl_session_tickets`)

TLS 1.3 использует механизм "session tickets". Эта директива включена по умолчанию.
```nginx
http {
    # ...
    ssl_session_tickets on; # Включено по умолчанию
    # ...
}
```
Для кластера из нескольких серверов Angie можно настроить общий ключ для шифрования "session tickets", чтобы сессии могли возобновляться на любом из серверов.

```nginx
http {
    # ...
    # Генерируется командой: openssl rand 80 > /path/to/ticket.key
    ssl_session_ticket_key /etc/angie/ticket.key;
    # ...
}
```

### 1.3. Протоколы и шифры

Современные версии Angie по умолчанию используют безопасные настройки.

```nginx
http {
    # ...
    # Эта настройка является дефолтной для современных версий
    ssl_protocols TLSv1.2 TLSv1.3;
    # ...
}
```
Настройки шифров (`ssl_ciphers`) и порядка их предпочтения (`ssl_prefer_server_ciphers`) также имеют разумные значения по умолчанию. Для TLS 1.3 набор шифров стандартизирован и не требует настройки.

**Дополнительные настройки:**
*   **`ssl_buffer_size`**: По умолчанию 16k. Это оптимальное значение для большинства случаев, так как оно соответствует размеру TLS-записи и позволяет избежать фрагментации, что повышает производительность. Изменение этого значения обычно не требуется.
*   **`ssl_ciphers`**: Для TLS 1.2 можно явно указать предпочтительные шифры. Однако для TLS 1.3 набор шифров стандартизирован и определяется самим протоколом, поэтому явное указание `ssl_ciphers` для TLS 1.3 не требуется и игнорируется. Порядок шифров (`ssl_prefer_server_ciphers`) также по умолчанию отдается на выбор клиенту, что обычно является оптимальным.

Если требуется поддержка старых клиентов или особая конфигурация, можно воспользоваться генератором [Mozilla SSL Configuration Generator](https://ssl-config.mozilla.org/).

## 2. Настройка виртуального хоста (`server`)

Эти настройки применяются к конкретному сайту.

### 2.1. Базовая конфигурация HTTPS

```nginx
server {
    listen 443 ssl;
    server_name your_domain.com;

    ssl_certificate /path/to/your_cert.pem;
    ssl_certificate_key /path/to/your_key.pem;

    # ... остальная конфигурация сайта
}
```
- `listen 443 ssl`: Указывает Angie слушать порт 443 и использовать SSL/TLS.
- `ssl_certificate`: Путь к файлу сертификата (включая промежуточные).
- `ssl_certificate_key`: Путь к файлу приватного ключа.

### 2.2. Использование EC и RSA сертификатов

Для максимальной производительности и совместимости рекомендуется использовать сертификаты на основе эллиптических кривых (ECDSA). Однако для поддержки очень старых клиентов может потребоваться RSA-сертификат. Angie позволяет указать оба типа сертификатов одновременно.

```nginx
server {
    # ...
    # EC сертификат (предпочтительный)
    ssl_certificate /path/to/your_ec_cert.pem;
    ssl_certificate_key /path/to/your_ec_key.pem;

    # RSA сертификат (для совместимости)
    ssl_certificate /path/to/your_rsa_cert.pem;
    ssl_certificate_key /path/to/your_rsa_key.pem;
    # ...
}
```
Angie автоматически выберет подходящий сертификат в зависимости от того, что поддерживает клиент.

## 3. Перенаправление с HTTP на HTTPS

Для SEO и безопасности важно, чтобы основной версией сайта была HTTPS-версия. Все HTTP-запросы должны перенаправляться с кодом `301 Moved Permanently`.

```nginx
server {
    listen 80;
    server_name your_domain.com www.your_domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl; # ... и далее конфигурация HTTPS
    # ...
}
```

## 4. Включение HTTP/2 и HTTP/3

Современные протоколы HTTP/2 и HTTP/3 (на базе QUIC) значительно ускоряют загрузку сайтов.

### 4.1. Конфигурация

```nginx
server {
    listen 443 ssl http2; # Включаем HTTP/2
    listen 443 quic reuseport; # Включаем QUIC (HTTP/3)

    # ...
    ssl_certificate /path/to/your_cert.pem;
    ssl_certificate_key /path/to/your_key.pem;
    # ...

    # Директива для HTTP/3
    http3 on;

    # Заголовок для обнаружения поддержки HTTP/3
    add_header Alt-Svc 'h3=":443"; ma=86400';
}
```
- `http2`: Включает поддержку HTTP/2 для TCP-сокета.
- `listen 443 quic reuseport`: Указывает Angie слушать UDP-порт 443 для протокола QUIC. `reuseport` необходим для производительности на многоядерных системах.
- `http3 on`: Включает поддержку HTTP/3.
- `add_header Alt-Svc`: Сообщает браузеру, что сайт доступен по HTTP/3. Браузер кэширует эту информацию на `max-age` секунд (в примере — 24 часа).

### 4.2. DNS-запись типа HTTPS

Еще один способ сообщить браузеру о поддержке HTTP/3 — это специальная DNS-запись типа `HTTPS`.

```dns
your_domain.com. IN HTTPS 1 . alpn="h2,h3"
```
Эта запись информирует клиент, что домен поддерживает протоколы HTTP/2 (`h2`) и HTTP/3 (`h3`), что позволяет браузеру сразу установить соединение по самому современному протоколу.

## 5. Повышение безопасности с помощью заголовков

### 5.1. Strict-Transport-Security (HSTS)

Этот заголовок заставляет браузер общаться с сайтом только по HTTPS, предотвращая атаки с понижением протокола.

```nginx
server {
    # ...
    # Добавлять только после полной уверенности в работе HTTPS
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    # ...
}
```
**Внимание:** Используйте этот заголовок с осторожностью. Если HTTPS настроен неверно, сайт станет недоступен для пользователей, чей браузер запомнил этот заголовок, и отменить это будет очень сложно.

## 6. Проверка конфигурации

### 6.1. Командная строка

- **Проверка синтаксиса:**
  ```bash
  sudo angie -t
  ```
- **Проверка открытых портов:**
  ```bash
  # Проверка TCP и UDP портов 443
  sudo ss -tlpn | grep 443
  # Для UDP-портов (например, для HTTP/3 QUIC)
  # Обратите внимание, что при использовании 'reuseport' может быть несколько записей для одного порта,
  # по одной на каждый worker-процесс Angie.
  sudo ss -ulpn | grep 443
  ```
- **Проверка TLS-соединения:**
  ```bash
  openssl s_client -connect your_domain.com:443 -servername your_domain.com
  ```
  Эта команда покажет детали TLS-рукопожатия и информацию о сертификате.
  Параметр `-servername` (Server Name Indication, SNI) критически важен, если на одном IP-адресе размещено несколько HTTPS-сайтов, чтобы Angie мог выбрать правильный сертификат.

### 6.2. Браузер

В инструментах разработчика (DevTools) на вкладке "Network" можно увидеть используемую версию протокола (HTTP/1.1, H2, H3) для каждого запроса. На вкладке "Security" можно посмотреть детали сертификата и TLS-соединения.
