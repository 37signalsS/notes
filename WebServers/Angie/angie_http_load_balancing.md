# Балансировка нагрузки HTTP в Angie

## Определения

**Балансировка нагрузки HTTP в Angie** — это процесс распределения входящего L7-трафика (HTTP/HTTPS) между несколькими бэкенд-серверами для повышения производительности и отказоустойчивости. Angie, являясь форком Nginx, наследует его мощные возможности балансировки, расширяя их функциями, ранее доступными только в платной версии Nginx Plus.

## Основные концепции

Основы балансировки HTTP-трафика в Angie, включая архитектуру, базовые алгоритмы (`round-robin`, `least_conn`) и ключевые директивы, полностью идентичны Nginx.

Данный документ фокусируется на ключевых возможностях, которые доступны в Open Source версии Angie "из коробки" и расширяют функциональность Nginx Open Source.

## Ключевые возможности и сценарии в Angie

### 1. Встроенный модуль `sticky` (Прилипание сессий)
Angie включает в себя полнофункциональный модуль для "прилипания" сессий, который в Nginx Open Source требует установки стороннего модуля. Это позволяет направлять запросы одного и того же клиента на один и тот же бэкенд-сервер, используя режимы `cookie` и `route` без дополнительной компиляции.

Подробнее о механизме см. раздел [Sticky Sessions в основной статье](../Nginx/Proxy/nginx_load_balancing.md#43-sticky-sessions-прилипание-сессий).

### 2. Плавное управление серверами (`slow_start`, `drain`)
-   **Сценарий "прогрева" сервера:** Параметр `slow_start=T` позволяет плавно вводить "холодный" бэкенд в ротацию, постепенно наращивая его вес от 0 до номинального значения в течение времени `T`. Это защищает только что запущенные сервисы от лавины запросов.
-   **Сценарий вывода на обслуживание:** Параметр `drain` позволяет плавно выводить сервер из ротации. Angie перестает направлять на него новые запросы (кроме "прилипших"), давая возможность безболезненно обработать текущие перед выключением.

### 3. Динамическое разрешение DNS (`resolve`)
Параметр `resolve` у директивы `server` позволяет Angie периодически перечитывать DNS-записи для upstream-серверов. Это критически важно для динамических окружений типа Docker или Kubernetes, где IP-адреса контейнеров могут меняться.

### 4. Динамические группы серверов
Angie поддерживает [динамическую конфигурацию upstream-серверов](./dynamic_upstreams.md) с помощью SRV-записей или через API, что упрощает автоматизированное управление бэкендами без перезагрузки конфигурации.
