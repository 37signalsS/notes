# Мониторинг Angie

## 1. Определения и подходы

В Angie, в отличие от устаревшего модуля `stub_status` в NGINX, который предоставлял лишь базовую информацию о соединениях, встроен мощный JSON API, открывающий доступ к сотням метрик.

Существует два основных подхода к мониторингу Angie:

1.  **Интерактивный мониторинг в реальном времени**: Использование встроенного веб-интерфейса **Angie Console Lite** и прямого доступа к **HTTP API**. Идеально для быстрого обзора состояния сервера.
2.  **Долгосрочный мониторинг и аналитика**: Сбор, хранение и визуализация метрик с помощью связки [**Prometheus**](../../Prometheus/overview.md) и [**Grafana**](../../Grafana/grafana_overview.md). Этот метод используется для анализа тенденций и настройки оповещений.

## 2. Базовая концепция: Зоны мониторинга

Чтобы API начал отдавать подробные метрики, необходимо в основной конфигурации определить **зоны** — именованные области для сбора статистики. Это ключевой механизм, позволяющий Angie агрегировать данные по различным компонентам.

-   **Для `server` блока:**
    ```nginx
    server {
        listen 80;
        status_zone server_example; # Имя зоны для этого виртуального сервера
    }
    ```
-   **Для `location` блока:**
    ```nginx
    location /api/v2/ {
        status_zone api_v2; # Имя зоны для конкретного location
    }
    ```
-   **Для `upstream` группы:**
    ```nginx
    upstream backend {
        zone upstream_backend 64k; # Зона разделяемой памяти для метрик и состояния апстримов
    }
    ```
-   **Для кэша:**
    ```nginx
    proxy_cache_path /var/cache/angie/proxy_cache keys_zone=my_cache:10m;
    ```
    Зона `my_cache` будет автоматически доступна для мониторинга.

Обзор использования всей разделяемой памяти (`Shared Zones`) критически важен для диагностики нехватки ресурсов.

## 3. Практические сценарии

### 3.1. Сценарий 1: Настройка Console Lite и API

#### Шаг 1: Установка Console Lite

Пакет `angie-console-lite` содержит статические файлы веб-интерфейса. Установка производится через стандартный пакетный менеджер после [базовой установки Angie](./angie_installation.md).

#### Шаг 2: Настройка эндпоинтов

Рекомендуется создать отдельный `server` блок для мониторинга, защитив его от публичного доступа.

```nginx
server {
    listen 8888 ssl;
    server_name monitor.example.com;

    # Защита доступа по IP
    allow 127.0.0.1;
    deny all;

    # Настройка для обслуживания файлов Angie Console Lite
    location / {
        root /usr/share/angie-console-lite/html; # Путь может отличаться
    }

    # Настройка для Angie API
    location /api/ {
        api;
    }
}
```

#### Шаг 3: Анализ данных

После настройки зон в интерфейсе Console Lite (`https://monitor.example.com:8888`) появятся вкладки со статистикой по HTTP-зонам, апстримам, кэшу и т.д.

Для прямой интеграции можно обращаться к API:
```bash
# Получение всех метрик в формате JSON
curl -s https://monitor.example.com:8888/api/ | jq

# Получение конкретной группы метрик
curl -s https://monitor.example.com:8888/api/http/ | jq
```

### 3.2. Сценарий 2: Настройка сбора метрик в Prometheus

#### Шаг 1: Настройка эндпоинта в Angie

Angie может самостоятельно экспортировать метрики в формате Prometheus. Для этого необходимо создать защищенный `location`.

```nginx
server {
    # ...
    location = /p8s {
        prometheus all; # Экспорт всех метрик из подключенного шаблона
        allow 127.0.0.1; # IP-адрес сервера Prometheus
        deny all;
    }
}
```
Перед этим убедитесь, что в `angie.conf` подключен шаблон `prometheus.conf`.

#### Шаг 2: Настройка Prometheus

Добавьте в `prometheus.yml` новую задачу для сбора метрик (scraping).

```yaml
scrape_configs:
  - job_name: 'angie'
    metrics_path: /p8s
    static_configs:
      - targets: ['localhost:80'] # Адрес сервера, где настроен эндпоинт /p8s
```

#### Шаг 3: Визуализация в Grafana

1.  Подключите Prometheus как источник данных в Grafana.
2.  Импортируйте официальный дашборд Angie через ID `2719`.

## 4. Продвинутые детали и возможности Angie Pro

-   **Управление апстримами**: В Angie Pro через API и Console Lite можно динамически изменять состояние серверов в `upstream` группах, что полезно при настройке [обратного HTTP-прокси](./angie_reverse_proxy.md). Это включается параметром `write=on` в директиве `api`.
-   **Расширенные метрики**: Некоторые ключевые метрики, например, **время ответа от апстрима (`upstream response time`)**, доступны только в коммерческой версии [Angie Pro](./angie_pro_features.md) и не экспортируются в Open Source версии.
