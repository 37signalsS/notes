# Мониторинг Angie

Это руководство описывает основные способы мониторинга веб-сервера Angie:
1.  **Встроенный Console Lite и HTTP API**: для визуального наблюдения в реальном времени и интеграции с собственными системами.
2.  **Prometheus и Grafana**: для сбора, хранения и анализа метрик с течением времени.

Оба подхода основаны на мощном API Angie, который отдает сотни метрик в формате JSON.

## 1. Мониторинг с помощью Console Lite и API

Этот метод идеально подходит для быстрого обзора состояния сервера в реальном времени.

### Ограничения `stub_status`

Исторически NGINX предоставлял базовый модуль `stub_status` для мониторинга. Он предоставляет минимальный набор метрик, в основном касающихся только общего состояния подключений (активные, ожидающие и т.д.), и не включает информацию о запросах, кодах ответа или состоянии апстримов. Для более детального мониторинга требовались сторонние модули или парсинг access-логов, что неудобно и создает дополнительную нагрузку.

В Angie встроен мощный API для мониторинга, который заменяет этот устаревший модуль.

### 1.1. Установка Angie Console Lite

Пакет для Angie Console Lite называется `angie-console-lite`. Для Angie Pro — `angie-pro-console-lite`. Он содержит статические HTML/JS файлы веб-интерфейса. Установка производится через стандартный пакетный менеджер вашего дистрибутива.

### 1.2. Настройка API и Console Lite

Настройка включает два шага:
1.  Настройка `location` для доступа к API.
2.  Настройка `location` для обслуживания статических файлов Console Lite.

Рекомендуется выделять для мониторинга отдельный `server` блок, слушающий на другом порту или домене, чтобы защитить его от публичного доступа.

#### Пример конфигурации

```nginx
server {
    listen 8888 ssl;
    server_name monitor.example.com;

    # Защита доступа
    allow 127.0.0.1;
    deny all;
    # Или можно использовать базовую аутентификацию
    # auth_basic "Restricted Area";
    # auth_basic_user_file /etc/angie/conf.d/.htpasswd;

    ssl_certificate /etc/angie/ssl/monitor.example.com.crt;
    ssl_certificate_key /etc/angie/ssl/monitor.example.com.key;

    # Настройка для обслуживания файлов Angie Console Lite
    location / {
        root /usr/share/angie-console-lite/html; # Путь может отличаться
    }

    # Настройка для Angie API
    location /api/ {
        api; # В Angie 1.5.0+ можно использовать write=on/off для управления апстримами
    }
}
```

### 1.3. Зоны мониторинга

Чтобы API начал отдавать подробные метрики, необходимо определить "зоны" для сбора статистики в вашей основной конфигурации.

-   **Для `server` блока:**
    ```nginx
    server {
        listen 80;
        server_name example.com;
        status_zone server_example; # Имя зоны для этого сервера
        # ...
    }
    ```
-   **Для `location` блока:**
    ```nginx
    location /api/v2/ {
        status_zone api_v2; # Имя зоны для этого location
        # ...
    }
    ```
-   **Для `upstream` группы:**
    ```nginx
    upstream backend {
        zone upstream_backend 64k; # Зона разделяемой памяти для хранения состояния и метрик
        server 127.0.0.1:8080;
    }
    ```
-   **Для кэша:**
    ```nginx
    proxy_cache_path /var/cache/angie/proxy_cache keys_zone=my_cache:10m;
    ```
    Зона `my_cache` будет автоматически доступна для мониторинга.

### 1.4. Обзор интерфейса Console Lite

После настройки зон в веб-интерфейсе Console Lite (например, `https://monitor.example.com:8888`) появятся соответствующие вкладки:

-   **Dashboard:** Общая сводка (версия Angie, аптайм, статистика по соединениям).
-   **HTTP Zones:** Статистика по `status_zone` (запросы/c, трафик, коды ответов).
-   **HTTP Upstreams:** Состояние и метрики `upstream` групп (статус серверов, ошибки, трафик).
-   **TCP/UDP Upstreams:** Аналогично для L4-балансировки.
-   **Caches:** Статистика по зонам кэширования (`hit ratio`, использование диска).
-   **Shared Zones:** Обзор использования всей разделяемой памяти. Критически важно для диагностики нехватки памяти.
-   **Resolvers:** Статистика для DNS-резолверов.

В версии **Angie Pro** через этот же интерфейс можно динамически управлять состоянием апстримов.

### 1.5. Использование API напрямую

Веб-консоль работает через JSON API, который можно использовать напрямую для интеграции с любой системой мониторинга (Zabbix, Nagios).

-   **Получение всех метрик:**
    ```bash
    curl -s https://monitor.example.com:8888/api/ | jq
    ```
-   **Получение конкретной группы метрик:**
    ```bash
    curl -s https://monitor.example.com:8888/api/http/ | jq
    ```

## 2. Мониторинг с помощью Prometheus и Grafana

Этот подход используется для долгосрочного хранения, агрегации и визуализации метрик.

### 2.1. Настройка Angie для экспорта метрик

Angie может самостоятельно экспортировать метрики в формате Prometheus.

1.  **Убедитесь, что подключен шаблон `prometheus.conf`** в основном `angie.conf`.
2.  **Создайте эндпоинт для метрик** в конфигурации вашего сайта, ограничив к нему доступ.

    ```nginx
    server {
        listen 80;
        server_name your_domain.com;

        # ...

        location = /p8s {
            prometheus all; # Экспорт всех метрик из шаблона
            allow 127.0.0.1;
            deny all;
        }
    }
    ```
3.  **Примените конфигурацию:**
    ```bash
    sudo angie -t && sudo systemctl reload angie
    ```
4.  **Проверьте эндпоинт:**
    ```bash
    curl http://localhost/p8s
    ```

### 2.2. Настройка Prometheus для сбора метрик

Добавьте в `prometheus.yml` новую задачу для сбора метрик с Angie.

```yaml
scrape_configs:
  - job_name: 'angie'
    metrics_path: /p8s
    static_configs:
      - targets: ['localhost:80'] # Укажите адрес вашего сервера
```

После этого перезапустите Prometheus и проверьте появление цели `angie` в его веб-интерфейсе (вкладка **Status -> Targets**).

### 2.3. Настройка Grafana и импорт дашборда

1.  **Добавьте Prometheus как источник данных** в Grafana.
2.  **Импортируйте официальный дашборд Angie.** Перейдите в **Dashboards -> New -> Import** и введите ID `2719`.

Импортированный дашборд предоставляет те же ключевые метрики, что и Console Lite, но с возможностями Grafana для анализа и оповещений.

**Важное замечание:** Одна из ключевых метрик — **время ответа от апстрима (`upstream response time`)** — доступна только в коммерческой версии [Angie Pro](./angie_pro_features.md) и, соответственно, не отображается на дашборде для Open Source версии.
