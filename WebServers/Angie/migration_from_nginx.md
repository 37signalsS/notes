# Миграция с Nginx на Angie

Миграция с Nginx на Angie — это безопасный и простой процесс, который можно выполнить с минимальным временем простоя. Ключевые принципы миграции:

-   **Полная совместимость:** Angie полностью совместим с конфигурацией Nginx.
-   **Параллельная установка:** Пакеты Angie не конфликтуют с пакетами Nginx, что позволяет установить оба сервера на одной системе.
-   **Быстрый откат:** Если что-то пойдет не так, вы можете мгновенно вернуть в работу Nginx, остановив Angie.

Это руководство описывает пошаговый процесс плавной миграции с работающего веб-сервера Nginx на Angie.

## Шаг 1: Предварительное исследование (анализ текущей конфигурации Nginx)

Перед началом миграции необходимо тщательно изучить текущую конфигурацию Nginx, чтобы понять, какие компоненты и настройки нужно перенести.

1.  **Определить версию и модули Nginx:**
    Выполните команду `nginx -V`, чтобы увидеть версию, параметры сборки и подключенные модули.
    ```bash
    nginx -V
    ```
    Обратите внимание на:
    *   **Версию Nginx:** Свежие версии (1.25+) имеют более совместимый синтаксис с Angie.
    *   **Библиотеку SSL:** Может использоваться нестандартная (например, BoringSSL).
    *   **Сторонние модули:** В выводе могут быть указаны статически скомпилированные модули (например, `--add-module=../nginx-module-brotli`). Запишите их, чтобы установить аналог для Angie.

2.  **Проверить динамические модули:**
    Команда `nginx -T` покажет всю конфигурацию, включая директивы `load_module` для динамических модулей.
    ```bash
    nginx -T
    ```

3.  **Найти все файлы конфигурации:**
    Используйте `grep` для поиска всех `include` директив, чтобы найти все подключаемые файлы. Особое внимание уделите путям, выходящим за пределы `/etc/nginx`.
    ```bash
    grep -Erni 'include' /etc/nginx/
    ```
    Это поможет найти все части конфигурации, включая `sites-enabled`, `conf.d` и другие кастомные включения.

4.  **Изучить основной файл `nginx.conf`:**
    Проанализируйте `/etc/nginx/nginx.conf` на предмет кастомных настроек:
    *   Пользователь (`user www-data;`)
    *   Настройки `events` (`worker_connections`)
    *   Глобальные настройки `http` (keepalive, ssl, gzip, brotli)
    *   Пути к логам (`access_log`, `error_log`)

## Шаг 2: Установка Angie и подготовка

Nginx продолжает работать, пока мы устанавливаем и настраиваем Angie.

1.  **Установите Angie и необходимые модули:**
    Установите Angie и модули, которые вы обнаружили на первом шаге (например, `brotli`).
    ```bash
    # Пример для Ubuntu/Debian
    sudo apt-get install angie angie-module-brotli
    ```

2.  **Проверьте статус Angie:**
    После установки Angie попытается запуститься, но не сможет, так как порты 80 и 443 уже заняты Nginx.
    ```bash
    sudo systemctl status angie
    # Вывод покажет ошибку "address already in use"
    ```

3.  **Отключите автозагрузку Angie (Важно!):**
    Чтобы избежать конфликтов при перезагрузке сервера, временно отключите автозагрузку Angie. Мы включим ее обратно после завершения миграции.
    ```bash
    sudo systemctl disable angie
    ```

## Шаг 3: Миграция конфигурации

Теперь перенесем конфигурацию из `/etc/nginx` в `/etc/angie`.

1.  **Перенос основных настроек:**
    *   Откройте `/etc/angie/angie.conf` и `/etc/nginx/nginx.conf`.
    *   Перенесите кастомные настройки из `http` блока Nginx в `http` блок Angie (например, `keepalive_timeout`, `ssl_protocols`, `gzip`, `brotli`).
    *   **Смените пользователя:** Убедитесь, что директива `user` в `angie.conf` соответствует пользователю в `nginx.conf` (например, `user www-data;`) для избежания проблем с правами доступа.
    *   Добавьте директивы `load_module` для динамических модулей в начало `angie.conf`, если они используются.

2.  **Копирование директорий с конфигурациями сайтов:**
    Скопируйте директории `sites-available` и `sites-enabled` из `/etc/nginx` в `/etc/angie`, если вы используете их.
    ```bash
    sudo cp -r /etc/nginx/sites-available /etc/angie/
    sudo cp -r /etc/nginx/sites-enabled /etc/angie/
    # Также скопируйте conf.d и другие директории с вашими конфигами
    sudo cp -r /etc/nginx/conf.d /etc/angie/
    ```

3.  **Исправление символических ссылок (если используется `sites-enabled`):**
    Символические ссылки в `/etc/angie/sites-enabled` все еще указывают на файлы в `/etc/nginx/sites-available`. Их нужно пересоздать. Это можно сделать с помощью скрипта:
    ```bash
    # Перейдите в директорию с сайтами Angie
    cd /etc/angie/sites-enabled

    # Сгенерируйте скрипт для исправления ссылок (проверьте его перед запуском)
    find . -type l -exec sh -c 'echo "ln -snf /etc/angie/sites-available/$(basename {}) $(basename {})"' \; > fix_links.sh

    # Запустите скрипт
    sudo sh fix_links.sh
    ```
    Проверьте, что ссылки теперь ведут на `/etc/angie/sites-available`.

4.  **Замена путей внутри конфигурационных файлов:**
    Внутри скопированных файлов все еще могут быть пути, ведущие к `/etc/nginx` или `/var/log/nginx`. Их нужно заменить на `/etc/angie` и `/var/log/angie`.
    ```bash
    # Найдите все файлы, где упоминается старый путь
    sudo grep -r /etc/nginx /etc/angie/

    # Используйте find и sed для автоматической замены
    sudo find /etc/angie/ -type f -exec sed -i 's|/etc/nginx|/etc/angie|g' {} +
    sudo find /etc/angie/ -type f -exec sed -i 's|/var/log/nginx|/var/log/angie|g' {} +
    ```

5.  **Копирование SSL-сертификатов и других файлов:**
    Не забудьте скопировать все остальные ресурсы, на которые ссылается конфигурация:
    *   SSL-сертификаты: `sudo cp -r /etc/nginx/ssl /etc/angie/`
    *   Файл `dhparam.pem`: `sudo cp /etc/nginx/dhparam.pem /etc/angie/`
    *   Файлы для базовой аутентификации (`.htpasswd`) и т.д.

## Шаг 4: Тестирование и переключение

1.  **Проверьте конфигурацию Angie:**
    Запустите тест конфигурации. Исправляйте ошибки, пока команда не выполнится успешно.
    ```bash
    sudo angie -t
    ```
    Частые ошибки на этом этапе — забытые файлы (SSL, dhparam) или неправильные пути.

2.  **Выполните переключение:**
    Это самая ответственная операция. Она выполняется одной командой, чтобы минимизировать время простоя.
    ```bash
    sudo systemctl stop nginx && sudo systemctl start angie
    ```
    Эта команда сначала остановит Nginx, и только в случае успеха запустит Angie.

3.  **Проверьте работу сайта:**
    *   Откройте сайт в браузере и убедитесь, что он работает.
    *   Проверьте заголовки ответа сервера (в DevTools), чтобы убедиться, что ответ отдает `Server: angie`.
    *   Протестируйте основной функционал сайта.

## Шаг 5: Завершение миграции

После успешного переключения и тестирования необходимо закрепить изменения.

1.  **Отключите автозагрузку Nginx:**
    ```bash
    sudo systemctl disable nginx
    ```

2.  **Включите автозагрузку Angie:**
    ```bash
    sudo systemctl enable angie
    ```

Теперь при перезагрузке сервера будет стартовать Angie. Пакет `nginx` можно оставить в системе на случай, если потребуется быстрый откат, или удалить позже.

## Миграция в Docker

Процесс миграции для Docker-контейнеров следует тому же принципу "установить, настроить, переключить", но с использованием инструментов контейнеризации.

1.  **Подготовка нового образа или `docker-compose` сервиса:**
    *   Создайте новый `Dockerfile` для Angie, если вам нужна кастомная сборка. В большинстве случаев достаточно использовать официальный образ `docker.ngsoftware/angie:latest`.
    *   В вашем `docker-compose.yml` добавьте новый сервис для Angie, дублируя конфигурацию сервиса Nginx.

    **Пример `docker-compose.yml` до миграции:**
    ```yaml
    version: '3.8'
    services:
      nginx:
        image: nginx:1.25
        ports:
          - "80:80"
          - "443:443"
        volumes:
          - ./nginx/conf:/etc/nginx
          - ./nginx/ssl:/etc/ssl/private
          - ./www:/var/www/html
    ```

2.  **Запуск Angie для тестирования:**
    *   Добавьте сервис Angie в `docker-compose.yml`, но на альтернативных портах, чтобы избежать конфликта с работающим Nginx.
    *   Скопируйте существующую конфигурацию Nginx в новую директорию для Angie.

    ```bash
    # Копируем конфигурацию для Angie
    cp -r ./nginx ./angie
    ```

    **Пример `docker-compose.yml` с сервисом Angie для теста:**
    ```yaml
    services:
      nginx:
        # ... (конфигурация Nginx остается без изменений)

      angie:
        image: docker.ngsoftware/angie:latest
        ports:
          - "8080:80" # Тестируем на порту 8080
          - "8443:443"
        volumes:
          - ./angie/conf:/etc/angie # Монтируем конфигурацию Angie
          - ./angie/ssl:/etc/ssl/private
          - ./www:/var/www/html
    ```

3.  **Адаптация конфигурации для Angie:**
    *   В скопированной конфигурации (`./angie/conf`) необходимо заменить все пути, ведущие к `/etc/nginx`, на `/etc/angie`.
        ```bash
        # Пример замены путей
        sudo find ./angie/conf/ -type f -exec sed -i 's|/etc/nginx|/etc/angie|g' {} +
        ```
    *   Убедитесь, что в `angie.conf` директива `user` соответствует пользователю внутри контейнера Angie (обычно `angie` или `root`).
    *   Подключите необходимые динамические модули с помощью `load_module`, если они требуются.

4.  **Тестирование Angie:**
    *   Запустите только сервис Angie:
        ```bash
        docker-compose up -d angie
        ```
    *   Проверьте логи контейнера на наличие ошибок:
        ```bash
        docker-compose logs angie
        ```
    *   Протестируйте работу сайта через альтернативный порт (в нашем примере `http://localhost:8080`).

5.  **Переключение трафика:**
    *   Когда вы будете уверены, что конфигурация Angie работает корректно, выполните переключение.
    *   Остановите контейнер Nginx.
    *   Перезапустите контейнер Angie на стандартных портах.

    **Финальный `docker-compose.yml`:**
    ```yaml
    services:
      # nginx:
      #   # ... (сервис Nginx закомментирован или удален)

      angie:
        image: docker.ngsoftware/angie:latest
        ports:
          - "80:80"   # Используем стандартные порты
          - "443:443"
        volumes:
          - ./angie/conf:/etc/angie
          - ./angie/ssl:/etc/ssl/private
          - ./www:/var/www/html
        restart: unless-stopped
    ```
    **Команды для переключения:**
    ```bash
    # Останавливаем и удаляем старый сервис Nginx
    docker-compose stop nginx
    docker-compose rm nginx

    # Останавливаем тестовый сервис Angie
    docker-compose stop angie

    # Запускаем Angie с обновленной конфигурацией портов
    docker-compose up -d angie
    ```

## Дополнительные рекомендации

*   **Псевдонимы для сервисов:** Если вам не подходит новое название директории конфигов или название сервиса, можно попробовать создать псевдонимы для сервиса `angie` на `nginx`, чтобы работали старые утилиты или скрипты, заточенные под `nginx`. Однако обычно это не рекомендуется, так как может привести к путанице.
*   **Проверка после миграции:** После успешной миграции важно тщательно протестировать все аспекты работы сайта, включая функциональность, производительность и мониторинг.
