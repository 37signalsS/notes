# Миграция с Nginx на Angie

## 1. Определения и Концепции

**Angie** — это эффективный и масштабируемый веб-сервер, который является форком [Nginx](../Nginx/Core/nginx_overview.md). Он был создан с целью расширения исходной функциональности при сохранении полной обратной совместимости. Подробнее об Angie, его особенностях и [причинах для миграции](./angie_why_migrate.md) можно узнать в [общем обзоре](./angie_overview.md).

Ключевые принципы, лежащие в основе миграции:

-   **Полная совместимость:** Angie полностью совместим с конфигурацией Nginx.
-   **Параллельная установка:** Пакеты Angie не конфликтуют с пакетами Nginx, что позволяет установить оба сервера на одной системе.
-   **Быстрый откат:** В случае возникновения проблем можно мгновенно вернуть в работу Nginx.

## 2. Практический сценарий: Миграция

### Шаг 1: Анализ конфигурации Nginx

1.  **Определить версию и модули Nginx:**
    Выполните `nginx -V`, чтобы увидеть версию, параметры сборки и подключенные статические модули (например, `--add-module=../nginx-module-brotli`).
    ```bash
    nginx -V
    ```
    Обратите внимание на:
    *   **Версию Nginx:** Свежие версии (1.25+) имеют более совместимый синтаксис с Angie.
    *   **Библиотеку SSL:** Может использоваться нестандартная (например, BoringSSL).
    *   **Сторонние модули:** В выводе могут быть указаны статически скомпилированные модули (например, `--add-module=../nginx-module-brotli`). Запишите их, чтобы установить аналог для Angie.

2.  **Проверить динамические модули:**
    Команда `nginx -T` покажет всю конфигурацию, включая директивы `load_module`.
    ```bash
    nginx -T
    ```

3.  **Найти все файлы конфигурации:**
    Используйте `grep` для поиска всех `include` директив, чтобы найти все подключаемые файлы, особенно за пределами `/etc/nginx`.
    ```bash
    grep -Erni 'include' /etc/nginx/
    ```

4.  **Изучить основной файл `nginx.conf`:**
    Проанализируйте `/etc/nginx/nginx.conf` на предмет кастомных настроек: пользователь (`user`), `events`, глобальные параметры `http` (keepalive, ssl, gzip) и пути к логам.

### Шаг 2: Установка и подготовка Angie

1.  **Установите Angie и необходимые модули:**
    Процесс [установки Angie](./angie_installation.md) подробно описан в соответствующем руководстве. Установите пакеты Angie и модули, которые вы обнаружили на первом шаге.
    ```bash
    # Пример для Ubuntu/Debian
    sudo apt-get install angie angie-module-brotli
    ```

2.  **Проверьте статус Angie:**
    После установки Angie попытается запуститься, но не сможет из-за конфликта портов (80 и 443), которые уже заняты Nginx.
    ```bash
    sudo systemctl status angie
    # Вывод покажет ошибку "address already in use"
    ```

3.  **Отключите автозагрузку Angie (Важно!):**
    Чтобы избежать конфликтов при перезагрузке сервера, временно отключите автозагрузку Angie.
    ```bash
    sudo systemctl disable angie
    ```

### Шаг 3: Миграция конфигурации

1.  **Перенос основных настроек:**
    *   Перенесите кастомные настройки из `http` блока `/etc/nginx/nginx.conf` в `/etc/angie/angie.conf`.
    *   Убедитесь, что директива `user` в `angie.conf` соответствует пользователю в `nginx.conf`.
    *   Добавьте директивы `load_module` для динамических модулей.

2.  **Копирование конфигураций сайтов:**
    Скопируйте директории `sites-available`, `sites-enabled`, `conf.d` и другие из `/etc/nginx` в `/etc/angie`.
    ```bash
    sudo cp -r /etc/nginx/sites-available /etc/angie/
    sudo cp -r /etc/nginx/sites-enabled /etc/angie/
    sudo cp -r /etc/nginx/conf.d /etc/angie/
    ```

3.  **Исправление символических ссылок:**
    Если вы используете `sites-enabled`, пересоздайте символические ссылки, чтобы они указывали на `/etc/angie/sites-available`.
    ```bash
    # Скрипт для исправления ссылок
    cd /etc/angie/sites-enabled
    find . -type l -exec sh -c 'echo "ln -snf /etc/angie/sites-available/$(basename {}) $(basename {})"' \; | sudo sh
    ```

4.  **Замена путей внутри конфигурационных файлов:**
    Замените пути `/etc/nginx` и `/var/log/nginx` на `/etc/angie` и `/var/log/angie` во всех конфигурационных файлах.
    ```bash
    # Найдите все файлы, где упоминается старый путь
    sudo grep -r /etc/nginx /etc/angie/

    # Используйте find и sed для автоматической замены
    sudo find /etc/angie/ -type f -exec sed -i 's|/etc/nginx|/etc/angie|g' {} +
    sudo find /etc/angie/ -type f -exec sed -i 's|/var/log/nginx|/var/log/angie|g' {} +
    ```

5.  **Копирование SSL-сертификатов и других файлов:**
    Скопируйте все зависимые ресурсы: SSL-сертификаты, `dhparam.pem`, файлы базовой аутентификации (`.htpasswd`). Детально процесс описан в руководстве по [настройке TLS в Angie](./angie_tls_setup.md).
    ```bash
    sudo cp -r /etc/nginx/ssl /etc/angie/
    sudo cp /etc/nginx/dhparam.pem /etc/angie/
    ```

### Шаг 4: Тестирование и переключение

1.  **Проверьте конфигурацию Angie:**
    Исправляйте ошибки до тех пор, пока тест конфигурации не будет пройден успешно.
    ```bash
    sudo angie -t
    ```

2.  **Выполните переключение:**
    Эта атомарная операция минимизирует время простоя.
    ```bash
    sudo systemctl stop nginx && sudo systemctl start angie
    ```

3.  **Проверьте работу сайта:**
    *   Откройте сайт в браузере и убедитесь, что он работает.
    *   Проверьте заголовки ответа сервера (в DevTools), чтобы убедиться, что ответ отдает `Server: angie`.
    *   Протестируйте основной функционал сайта.

### Шаг 5: Завершение миграции

1.  **Отключите автозагрузку Nginx:**
    ```bash
    sudo systemctl disable nginx
    ```

2.  **Включите автозагрузку Angie:**
    ```bash
    sudo systemctl enable angie
    ```

## 3. Миграция в Docker

Процесс миграции для контейнеров, управляемых через [Docker](../../../Docker/docker_overview.md), следует тому же принципу "установить, настроить, переключить".

1.  **Подготовка:**
    *   Создайте новый `Dockerfile` или, что более вероятно, новый сервис в `docker-compose.yml`.
    *   Используйте официальный образ `docker.ngsoftware/angie:latest`.
    *   Скопируйте существующую конфигурацию Nginx (`./nginx`) в новую директорию для Angie (`./angie`).

2.  **Адаптация и тестирование:**
    *   В `docker-compose.yml` добавьте сервис `angie`, дублируя конфигурацию `nginx`, но с маппингом на альтернативные порты (например, `8080:80`).
    *   В скопированной конфигурации (`./angie/conf`) замените пути `s|/etc/nginx|/etc/angie|g`.
    *   Запустите сервис `angie` (`docker-compose up -d angie`) и протестируйте его работу через альтернативный порт.

3.  **Переключение:**
    Когда корректная работа будет подтверждена, остановите сервис `nginx` и перезапустите `angie` на стандартных портах (`80:80`, `443:443`).
    ```bash
    docker-compose stop nginx && docker-compose rm -f nginx
    # Обновите docker-compose.yml, чтобы открыть стандартные порты для angie
    docker-compose up -d angie
    ```

## 4. Продвинутые детали и следующие шаги

*   **Псевдонимы:** Создавать псевдонимы для сервиса `angie` на `nginx` не рекомендуется, так как это может привести к путанице.
*   **Мониторинг:** После миграции тщательно протестируйте все аспекты работы сайта, включая производительность и мониторинг.
*   **Дальнейшая настройка:** После успешной миграции можно приступить к настройке более сложных сценариев, например, использованию Angie в качестве [обратного прокси](./angie_reverse_proxy.md).
