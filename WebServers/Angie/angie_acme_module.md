# Автоматические TLS-сертификаты в Angie: Обзор модуля ACME

Модуль `acme` в Angie — это встроенное решение для автоматического получения и обновления [SSL/TLS сертификатов](../../Networking/Protocols/tls.md) от центров сертификации, использующих протокол ACME (Automated Certificate Management Environment), таких как Let's Encrypt. Это избавляет от необходимости использовать внешние утилиты и интегрирует процесс управления сертификатами непосредственно в конфигурацию веб-сервера. Данный функционал особенно полезен при использовании Angie в качестве **[обратного прокси](./angie_reverse_proxy.md)**.

## 1. Let's Encrypt: Повсеместный HTTPS и бесплатные сертификаты

Let's Encrypt — это некоммерческий центр сертификации, предоставляющий бесплатные SSL/TLS сертификаты. Он был создан при поддержке крупных игроков индустрии (Google, Mozilla и др.) с целью сделать использование HTTPS повсеместным, устранив финансовые и технические барьеры.

### 1.1. Преимущества Let's Encrypt:

*   **Бесплатность:** Основное преимущество, позволяющее владельцам любых сайтов (от хобби-проектов до крупных порталов) использовать шифрование.
*   **Широкая доступность:** Сертификаты Let's Encrypt работают во всех основных операционных системах, браузерах и устройствах.
*   **Поддержка разных типов криптографии:** Поддерживает как традиционные RSA, так и современные эллиптические (ECDSA) сертификаты. Angie может использовать оба типа для максимальной совместимости и производительности.
*   **Wildcard-сертификаты:** Позволяет выпускать Wildcard-сертификаты (например, `*.example.com`), покрывающие неограниченное количество субдоменов третьего уровня.
*   **Короткий срок действия (90 дней):** Сертификаты выдаются на 90 дней. Это сделано для стимулирования автоматизации процесса обновления, что снижает риски в случае компрометации ключей. При правильной настройке автоматизация делает этот процесс прозрачным для пользователя.
*   **Протокол ACME:** Основан на протоколе ACME, который позволяет автоматизировать весь процесс взаимодействия с центром сертификации.

## 2. Преимущества встроенного модуля ACME в Angie

Модуль `acme` в Angie предоставляет ряд существенных преимуществ по сравнению с использованием внешних утилит:

*   **Полная автоматизация:** Angie самостоятельно инициирует получение, продлевает сертификаты и перезагружает конфигурацию для их применения. Настройте один раз, и Angie будет самостоятельно получать и продлевать сертификаты, включая перезагрузку конфигурации для их применения.
*   **Отсутствие внешних зависимостей:** Вся логика встроена в веб-сервер, нет необходимости устанавливать и поддерживать сторонние скрипты или пакеты (например, Certbot, acme.sh).
*   **Простота конфигурации:** Управление сертификатами осуществляется декларативно через директивы в конфигурационных файлах Angie.
*   **Гибкость:** Поддержка обоих методов верификации (http-01 и dns-01) позволяет получать как обычные, так и Wildcard-сертификаты.
*   **Единый источник истины:** Не нужно поддерживать список доменов в разных местах. Конфигурация Angie становится единственным источником для управления доменами и их сертификатами.
*   **Бесшовная перезагрузка:** Обновление сертификатов происходит без полного перезапуска веб-сервера, что особенно важно для высоконагруженных систем с большим количеством доменов.
*   **Простота:** Конфигурация становится проще, так как исчезает необходимость в сторонних скриптах, cron-заданиях и сложных хуках для перезагрузки сервера.
*   **Мониторинг:** Информация о процессе получения и обновления сертификатов записывается в `error.log`.

## 3. Методы верификации домена (ACME Challenges)

Для подтверждения владения доменом ACME протокол использует "вызовы" (challenges), позволяющие центру сертификации убедиться, что запрашивающий сертификат действительно контролирует домен. Модуль `acme` в Angie поддерживает два основных метода.

### 3.1. HTTP-01 Challenge

*   **Принцип:** Центр сертификации предоставляет уникальный токен. Веб-сервер должен разместить этот токен по определенному URL (например, `http://your-domain.com/.well-known/acme-challenge/YOUR_TOKEN`).
*   **Проверка:** Центр сертификации отправляет HTTP-запрос по этому URL. Если он получает ожидаемый токен, владение доменом считается подтвержденным.
*   **Требования:** Веб-сервер должен быть доступен из интернета по 80-му порту.
*   **Ограничения:** Не подходит для Wildcard-сертификатов.
*   **В Angie:** Модуль `acme` обрабатывает этот тип проверки "под капотом", не требуя создания специальных `location` блоков.

### 3.2. DNS-01 Challenge

*   **Принцип:** Центр сертификации предоставляет токен, который необходимо добавить в виде TXT-записи в DNS-записи вашего домена (например, `_acme-challenge.your-domain.com IN TXT "YOUR_TOKEN"`).
*   **Проверка:** Центр сертификации выполняет DNS-запрос для этой TXT-записи. Если он получает ожидаемый токен, владение доменом считается подтвержденным.
*   **Преимущества:** Единственный способ получить Wildcard-сертификаты (например, `*.example.com`). Не требует доступности веб-сервера извне.
*   **Особенности:** Требует автоматизированного управления DNS-записями (через API DNS-провайдера) или делегирования DNS. Модуль ACME Angie поддерживает работу в качестве мини-DNS-сервера для таких запросов (`acme_dns_server`) или вызов внешних скриптов (`acme_dns_hook`).

## 4. Практический сценарий: Настройка HTTP-01 верификации

Это самый простой и распространенный способ, который подходит для большинства случаев. Он требует, чтобы ваш сервер был доступен из интернета по 80-му порту.

**Шаг 1: Глобальная настройка (в блоке `http`)**

В `angie.conf` необходимо определить ACME-клиента и `resolver` для DNS-запросов.

```nginx
# /etc/angie/angie.conf
http {
    # ...

    # Определяем DNS-резолвер для ACME-клиента (обязательно)
    # Можно использовать публичные DNS, например, Cloudflare (1.1.1.1) или Google (8.8.8.8).
    resolver 1.1.1.1 8.8.8.8 valid=300s;
    resolver_timeout 5s;

    # Определяем клиента для Let's Encrypt
    acme_client letsencrypt {
        directory "https://acme-v02.api.letsencrypt.org/directory";
        # Для тестирования используйте staging-окружение, чтобы не исчерпать лимиты:
        # directory "https://acme-staging-v02.api.letsencrypt.org/directory";
    }

    # Можно определить несколько клиентов, например, для RSA и ECDSA ключей
    acme_client letsencrypt_rsa {
        directory "https://acme-v02.api.letsencrypt.org/directory";
        key_type rsa;
    }
    # ...
}
```

**Шаг 2: Настройка сервера (в блоке `server`)**

Теперь в конфигурации вашего `server` укажите, что он должен использовать ACME для получения сертификата.

```nginx
# /etc/angie/sites-enabled/default (пример)
# Или /etc/angie/http.d/example.com.conf
server {
    listen 80;
    server_name example.com www.example.com;

    # Для HTTP-01 challenge Angie автоматически обрабатывает .well-known/acme-challenge.
    # Убедитесь, что 80-й порт открыт и доступен.
    # Можно использовать редирект, но listen 80 должен быть активен.
    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name example.com www.example.com;

    # Метод 1: Современный способ с использованием переменных Angie (рекомендуется)
    # Указываем, что сертификат и ключ будут предоставлены модулем ACME через переменные.
    ssl_certificate $acme_cert_letsencrypt;
    ssl_certificate_key $acme_cert_key_letsencrypt;
    # Включаем ACME, ссылаясь на ранее определенного клиента. Angie автоматически
    # управляет файлами сертификатов.
    acme letsencrypt; # или letsencrypt_rsa

    # Метод 2: Классический способ с явным указанием путей к файлам (также поддерживается)
    # Angie создаст файлы сертификатов по указанным путям при первом запуске.
    # ssl_certificate /etc/angie/ssl/example.com.crt;
    # ssl_certificate_key /etc/angie/ssl/example.com.key;
    # Включаем ACME и указываем клиента, если явно прописаны пути к сертификатам.
    # acme on;
    # acme_client letsencrypt;

    # ... остальная конфигурация HTTPS
    # Общие принципы настройки TLS описаны в руководстве
    # [Настройка TLS в Angie: безопасность и скорость](./angie_tls_setup.md)
}
```

## 5. Практический пример: Несколько доменов

Рассмотрим реальный пример с двумя поддоменами: `mail.zeroxzed.ru` и `webmail.zeroxzed.ru`.

**Шаг 1: Глобальная настройка (в блоке `http`)**

Для каждого домена (или группы доменов, которые будут в одном сертификате) необходимо определить своего клиента.

```nginx
# /etc/angie/angie.conf
http {
    # ...
    resolver 62.76.76.62 62.76.62.76;

    # Создаем по одному клиенту на каждый домен
    acme_client webmail {
        directory "https://acme-v02.api.letsencrypt.org/directory";
    }
    acme_client mail {
        directory "https://acme-v02.api.letsencrypt.org/directory";
    }
    # ...
}
```

**Шаг 2: Настройка серверов**

Создаем отдельные конфигурационные файлы для каждого хоста.

```nginx
# /etc/angie/http.d/webmail.conf
server {
    listen 443 ssl;
    server_name webmail.zeroxzed.ru;

    root /var/www/webmail;
    index index.php index.html;

    # Используем переменные, связанные с именем клиента
    acme webmail;
    ssl_certificate $acme_cert_webmail;
    ssl_certificate_key $acme_cert_key_webmail;

    # ...
}

server {
    listen 80;
    server_name webmail.zeroxzed.ru;
    return 301 https://$host$request_uri;
}
```

```nginx
# /etc/angie/http.d/mail.conf
server {
    listen 443 ssl;
    server_name mail.zeroxzed.ru;

    root /var/www/mail;
    index index.html;

    acme mail;
    ssl_certificate $acme_cert_mail;
    ssl_certificate_key $acme_cert_key_mail;

    # ...
}

server {
    listen 80;
    server_name mail.zeroxzed.ru;
    return 301 https://$host$request_uri;
}
```

После перезапуска Angie в логах можно будет увидеть процесс получения сертификатов, а сами файлы появятся в директории `/var/lib/angie/acme/`.

## 6. Настройка для DNS-01 верификации (Wildcard-сертификаты)

Для получения Wildcard-сертификатов (например, `*.example.com`) требуется подтверждение владения доменом через DNS. Модуль `acme` в Angie поддерживает и этот способ.

**Шаг 1: Настройка `acme_client` для DNS**

```nginx
# /etc/angie/angie.conf
http {
    # ...
    resolver 1.1.1.1; # Или другие DNS-серверы

    acme_client letsencrypt_dns {
        directory "https://acme-v02.api.letsencrypt.org/directory";
        # Указываем, что для верификации будет использоваться DNS
        challenge_type dns-01;
    }
    # ...
}
```

**Шаг 2: Настройка сервера**

```nginx
# /etc/angie/sites-enabled/wildcard (пример)
server {
    listen 443 ssl;
    server_name *.example.com;

    ssl_certificate /etc/angie/ssl/wildcard.example.com.crt;
    ssl_certificate_key /etc/angie/ssl/wildcard.example.com.key;

    # Включаем ACME для этого сервера
    acme on;
    acme_client letsencrypt_dns;

    # Настраиваем обработчик DNS-запросов
    # Angie будет работать как мини-DNS-сервер на 53 порту для ответа на верификационные запросы
    acme_dns_server {
        listen 53 udp;
        listen 53; # TCP
    }
}
```

Для того чтобы это работало, вам необходимо делегировать обработку `_acme-challenge.example.com` на тот сервер, где запущен Angie. Это делается путем создания NS-записи в настройках вашего домена.

```
# В настройках зоны example.com
_acme-challenge.example.com. IN NS ns1.acme.example.com.
ns1.acme.example.com.       IN A  <IP-адрес вашего Angie-сервера>
```

В качестве альтернативы, если вы не хотите делегировать DNS-зону, можно использовать `acme_dns_hook` для вызова внешнего скрипта, который будет взаимодействовать с API вашего DNS-провайдера для создания необходимых TXT-записей.

## 7. Ограничения Let's Encrypt и их учет

Let's Encrypt имеет определенные лимиты на количество выдаваемых сертификатов, количество некорректных попыток и т.д. (например, 50 сертификатов на домен в неделю, 5 ошибок авторизации в час). Для тестирования рекомендуется использовать staging-окружение Let's Encrypt, чтобы не исчерпать "боевые" лимиты.

## 8. Нерешенные вопросы и ограничения модуля ACME в Angie

*   **Один клиент на несколько доменов:** На данный момент, судя по документации и практике, нет элегантного способа использовать одного `acme_client` для выпуска разных сертификатов для разных `server_name`. Приходится создавать по одному клиенту на каждый сертификат, что может приводить к дублированию конфигурации.
*   **Отсутствие хуков после обновления:** Встроенный модуль ACME не предоставляет механизма "хуков" (hooks) для выполнения произвольных команд после успешного обновления сертификата. Это становится проблемой, если сертификаты используются не только веб-сервером, но и другими службами (например, Postfix, Dovecot). В этом случае им необходимо "сообщить" о новом сертификате.
    *   **Возможное решение:** Использовать внешние инструменты, такие как `incron` или `systemd.path`, для отслеживания изменений в директории `/var/lib/angie/acme/` и запуска скрипта, который будет перезагружать зависимые службы. Однако это усложняет первоначальную простую настройку.

## 9. Альтернативы и смежные решения

До появления встроенных решений, таких как модуль ACME в [Angie](./angie_overview.md), для работы с Let's Encrypt использовался ряд внешних инструментов, которые остаются популярными и сегодня.

*   **Certbot и acme.sh:** Это классические утилиты командной строки, которые автоматизируют процесс получения и обновления сертификатов.
    *   **Certbot** предлагает плагины для автоматической интеграции с веб-серверами, включая Nginx. Подробное руководство можно найти в заметке **[Использование Let's Encrypt с Nginx в Docker](../Nginx/Scenarios/nginx_with_letsencrypt.md)**.
    *   **acme.sh** — легковесный скрипт, известный широкой поддержкой API различных DNS-провайдеров, что делает его удобным для получения Wildcard-сертификатов.

*   **Traefik:** Современный обратный прокси, который имеет встроенную и полностью автоматизированную поддержку Let's Encrypt. Это популярное решение в экосистеме Docker. Детали можно найти в **[обзоре Traefik](../Traefik/traefik_overview.md)**.

*   **Cert-manager:** Стандарт де-факто для управления TLS-сертификатами в Kubernetes. Он автоматически получает и продлевает сертификаты от различных источников, включая Let's Encrypt, для сервисов внутри кластера. Подробнее в заметке **[Cert-manager для Kubernetes](../../Kubernetes/ToolsUtilities/cert_manager.md)**.

Модуль `acme` в Angie является современной альтернативой, которая интегрирует эту функциональность непосредственно в веб-сервер, устраняя необходимость во внешних зависимостях для базовых сценариев.

## 10. Продвинутые детали и отладка

*   **Логи:** Вся информация о процессе получения и обновления сертификатов записывается в `error.log` на уровне `notice`. Для отладки может потребоваться временно повысить уровень логирования. Подробнее о работе с логами можно узнать в документе **[Логирование в Angie](./angie_logging.md)**.
*   **Статус:** Мониторить состояние можно через стандартные средства, описанные в руководстве **[Мониторинг Angie](./angie_monitoring.md)**.
*   **Расположение файлов:** По умолчанию сертификаты хранятся в `/var/lib/angie/acme/<client_name>/`. Путь можно изменить директивой `acme_path`.
*   **Автоматическое обновление:** Angie отслеживает срок действия сертификатов и обновляет их примерно за 30 дней до истечения.
*   **Лимиты Let's Encrypt:** Для тестирования конфигурации настоятельно рекомендуется использовать staging-окружение (`directory "https://acme-staging-v02.api.letsencrypt.org/directory"`), чтобы не исчерпать "боевые" лимиты на количество запросов.
