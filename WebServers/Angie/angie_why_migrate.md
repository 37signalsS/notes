# Почему стоит переходить на Angie

Angie — это форк веб-сервера Nginx, созданный и поддерживаемый основной командой его оригинальных разработчиков. Переход на Angie предоставляет пользователям Nginx не только полную совместимость и безболезненную миграцию, но и целый ряд существенных преимуществ, доступных "из коробки" в Open Source версии.

## 1. Более динамичное развитие и сильная команда

Ключевая команда, стоявшая за разработкой Nginx на протяжении многих лет, теперь развивает Angie. Это обеспечивает более быстрое внедрение новых функций, исправление ошибок и общее развитие продукта по сравнению с оригинальным Nginx, который после смены владельца (F5) существенно замедлил темпы разработки.

Подробнее об истории проекта и команде можно прочитать в [общем обзоре Angie](./angie_overview.md).

## 2. Расширенная функциональность в Open Source

Многие функции, которые в Nginx были эксклюзивны для платной версии Nginx Plus (или не существовали вовсе), в Angie доступны бесплатно.

-   **Встроенный расширенный мониторинг:**
    -   **API в формате JSON:** Удобный доступ к сотням метрик для интеграции с любыми системами мониторинга.
    -   **Веб-консоль (Console Lite):** Наглядный веб-интерфейс для отслеживания состояния сервера, апстримов, кэша и зон памяти в реальном времени.
    -   **Prometheus Exporter:** Встроенный эндпоинт (`/p8s`) для отдачи метрик в формате Prometheus, готовый к интеграции с Grafana.
    -   См. [Мониторинг с помощью Console и API](./angie_monitoring_with_console_api.md) и [Мониторинг с помощью Prometheus](./monitoring_with_prometheus_and_grafana.md).

-   **Продвинутая балансировка нагрузки:**
    -   **`sticky sessions`:** Привязка сессий клиента к определенному бэкенду на основе cookie или параметра в запросе.
    -   **`slow_start` и `drain`:** Плавный ввод и вывод серверов из балансировки, что предотвращает их перегрузку и позволяет корректно завершать обработку текущих запросов.
    -   **Проксирование по HTTP/3 к бэкендам:** Angie умеет проксировать запросы к апстримам, используя протокол HTTP/3.
    -   См. [Балансировка нагрузки HTTP(S)](./angie_http_load_balancing.md).

## 3. Простота и удобство использования

-   **Автоматизация SSL-сертификатов (ACME):** Встроенный клиент для Let's Encrypt позволяет полностью автоматизировать получение и обновление SSL-сертификатов без использования сторонних утилит (таких как certbot). См. [Настройка ACME](./acme_module_setup.md).

-   **Готовые пакеты сторонних модулей:** Десятки популярных модулей (Brotli, ModSecurity, Zstd, Redis, Postgres и др.) уже собраны, протестированы и доступны для установки из официального репозитория Angie. Это избавляет от необходимости ручной компиляции. См. [Установка Angie](./angie_installation.md).

-   **Упрощенная конфигурация:**
    -   **Объединение `location`:** Несколько блоков `location` с одинаковой конфигурацией можно объединить в один для уменьшения дублирования.
    -   **Понятное версионирование:** Отсутствие путаницы между `stable` и `mainline` ветками. Все релизы Angie стабильны и основаны на последней `mainline` версии Nginx.

## 4. Открытая и доступная поддержка

-   **Прямой контакт с разработчиками:** В официальном Telegram-чате можно напрямую задать вопрос разработчикам Angie и получить квалифицированную помощь.
-   **Коммерческая поддержка в РФ:** Для бизнеса доступна полноценная коммерческая поддержка и продукты, включенные в реестр отечественного ПО ([Angie Pro](./angie_pro_features.md)).

## 5. Легкая и безопасная миграция

Пакеты Angie не конфликтуют с Nginx, что позволяет установить его параллельно, перенести и протестировать конфигурацию, а затем переключить сервисы с минимальным или нулевым временем простоя.

Подробнее о процессе перехода читайте в руководстве по [миграции с Nginx на Angie](./migration_from_nginx.md).

В итоге, переход на Angie — это логичный шаг для тех, кто хочет получить от своего веб-сервера больше функциональности, производительности и удобства, оставаясь в привычной экосистеме Nginx.
