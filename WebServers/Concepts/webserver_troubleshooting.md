# Диагностика веб-сервера после перезагрузки

## Определения

**Troubleshooting (Поиск и устранение неисправностей)** — систематический процесс выявления причин, по которым система не перешла в рабочее состояние после изменения конфигурации или перезапуска ОС (Operating System).

**Post-reboot failure (Сбой после перезагрузки)** — ситуация, когда сервис корректно работал до перезагрузки, но не запустился или работает некорректно после неё. Часто указывает на проблемы в конфигурации автозапуска, отсутствие сохраняемости настроек или недоступность внешних ресурсов в момент старта.

## Основные концепции

### Алгоритм первичной диагностики

Если после рестарта HTTP (HyperText Transfer Protocol) сервер (Nginx, Apache, Angie) не работает, следуйте цепочке проверки:

1. **Проверка статуса службы:** Запущен ли процесс?
2. **Анализ логов (журналов):** Почему он не запустился или завершился с ошибкой?
3. **Проверка портов:** Слушает ли он нужный порт (например, 80 или 443)?
4. **Проверка сетевого пути:** Не блокирует ли трафик межсетевой экран (Firewall)?
5. **Проверка зависимостей:** Доступны ли БД (Базы Данных), SSL (Secure Sockets Layer) / TLS (Transport Layer Security) сертификаты, сетевые хранилища?

## Практические сценарии

### Сценарий: Веб-сервер не запустился после рестарта

**1. Проверка состояния через systemd**

```bash
systemctl status nginx
```

Если статус `inactive` или `failed`, смотрим причину в выводе или через `journalctl` (системный журнал):

```bash
journalctl -xeu nginx
```

**2. Проверка синтаксиса конфигурации**
Возможно, перед рестартом были внесены изменения, которые не проверялись:

```bash
nginx -t
# или для Apache
apachectl configtest
```

**3. Проверка занятых портов**
Возможно, порт занят другим процессом или дублирующей службой:

```bash
ss -tlpn | grep :80
```

**4. Проверка прав на файлы и логи**
Иногда после обновлений или манипуляций с пользователями сервер не может прочитать SSL/TLS сертификаты или записать логи:

```bash
ls -l /etc/nginx/ssl/
ls -l /var/log/nginx/
```

**5. Проверка внешних зависимостей**
Если сервер использует сетевые диски для корня сайта или хранилища логов, они могли не примонтироваться автоматически. Необходимо проверить `/etc/fstab` (file systems table) и выполнить `mount -a`.

**6. Проверка автозапуска**
Если процесс не запущен, но ошибок в журналах нет — возможно, он не добавлен в автозагрузку:

```bash
systemctl is-enabled nginx
# Если disabled, исправить:
systemctl enable nginx
```

## Дополнительная информация

### Типичные ошибки после перезагрузки

- **Слетевшие права на временные папки:** `/var/lib/nginx` и аналогичные директории.
- **Проблемы с DNS (Domain Name System):** Если в конфигурации указаны имена бэкендов, которые не резолвятся в момент старта сервера (например, из-за задержки старта сетевой подсистемы).
- **SELinux (Security-Enhanced Linux):** Может блокировать доступ к новым путям или портам после перезагрузки. Для проверки можно временно переключить в режим `Permissive` командой `setenforce 0`.
- **Изменение IP (Internet Protocol) адреса:** Если сервер привязан к конкретному адресу, который изменился после перезагрузки (например, при использовании DHCP — Dynamic Host Configuration Protocol).
