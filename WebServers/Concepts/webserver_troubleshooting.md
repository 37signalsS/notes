# Диагностика веб-сервера после перезагрузки

## Определения → Базовые концепции → Практические сценарии → Дополнительная информация

## Определения

**Troubleshooting (Поиск и устранение неисправностей)** — процесс выявления причин, по которым система не перешла в рабочее состояние после изменения или перезапуска.

**Post-reboot failure** — ситуация, когда сервис корректно работал до перезагрузки, но не запустился или работает некорректно после неё. Часто указывает на проблемы в конфигурации автозапуска или сохранении состояния.

## Базовые концепции

### Алгоритм первичной диагностики

Если после рестарта HTTP-сервер (Nginx, Apache, Angie) не работает, следуйте цепочке:

1. **Проверка статуса службы:** Запущен ли процесс?
2. **Анализ логов:** Почему он не запустился или упал?
3. **Проверка портов:** Слушает ли он нужный порт?
4. **Проверка сетевого пути:** Не блокирует ли файрвол?
5. **Проверка зависимостей:** Доступны ли БД, сертификаты, сетевые хранилища?

## Практические сценарии

### Сценарий: Веб-сервер не запустился после рестарта

**1. Проверка состояния через systemd**

```bash
systemctl status nginx
```

Если статус `inactive` или `failed`, смотрим причину в выводе или через `journalctl`:

```bash
journalctl -xeu nginx
```

**2. Проверка синтаксиса конфигурации**
Возможно, перед рестартом были внесены изменения, которые не проверялись:

```bash
nginx -t
# или для Apache
apachectl configtest
```

**3. Проверка занятых портов**
Возможно, порт занят другим процессом или дублирующей службой:

```bash
ss -tlpn | grep :80
```

**4. Проверка прав на файлы и логи**
Иногда после обновлений или манипуляций с пользователями сервер не может прочитать сертификаты или записать логи:

```bash
ls -l /etc/nginx/ssl/
ls -l /var/log/nginx/
```

**5. Проверка внешних зависимостей**
Если сервер использует сетевые диски для корня сайта или хранилища логов, они могли не примонтироваться автоматически (проверить `/etc/fstab` и `mount -a`).

**6. Проверка автозапуска**
Если процесс не запущен, но ошибок нет — возможно, он просто не добавлен в автозагрузку:

```bash
systemctl is-enabled nginx
# Если disabled, исправить:
systemctl enable nginx
```

## Дополнительная информация

### Типичные ошибки после перезагрузки

- **Слетевшие права на временные папки:** `/var/lib/nginx` и др.
- **Проблемы с DNS:** Если в конфиге указаны имена бэкендов, которые не резолвятся в момент старта сервера.
- **SELinux:** Может блокировать доступ к новым путям или портам после перезагрузки. Попробуйте `setenforce 0` для проверки.
- **Изменение IP-адреса:** Если сервер привязан к конкретному IP, который изменился после перезагрузки (DHCP).
