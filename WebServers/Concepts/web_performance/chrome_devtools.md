# Chrome DevTools для анализа производительности

**Открытие:** `F12` или `Ctrl+Shift+I`. Для мобильного тестирования рекомендуется выносить DevTools в отдельное окно (`Unlock to separate Window`), чтобы не влиять на viewport.

## Мобильная эмуляция (Device Toolbar)

* **Выбор устройства:** Эмуляция конкретных моделей или custom-режим с настройкой viewport и DPR (Device Pixel Ratio).
* **CPU Throttling:** Замедление процессора для эмуляции мобильных устройств. Перед использованием требуется калибровка (бенчмарк определяет коэффициент замедления).
* **Network Throttling:** Торможение сети через пресеты (Fast 4G, Slow 4G) или кастомные профили с настройкой потери пакетов (1-2% максимум), задержки и пропускной способности.
* **Режимы:** Responsive для ручного контроля, оффлайн-режим для тестирования PWA.

## Вкладка Network

### Базовые настройки

* **Disable Cache:** Обязательно для симуляции холодной загрузки.
* **Preserve Log:** Сохранение лога между перезагрузками страниц.
* **Запись сессий:** Возможность экспорта/импорта HAR-файлов для совместной работы.

### Фильтрация ресурсов

* **По типу:** Doc, CSS, JS, Img, Font, Fetch/XHR и другие.
* **По домену/пути:** Свободный поиск или фильтрация по домену.
* **По приоритету:** Сортировка по приоритету загрузки (Highest, High, Medium, Low).

### Настройка колонок

* **Protocol:** Отображение HTTP/2, HTTP/3.
* **Content Encoding:** Проверка сжатия (Brotli, Gzip, Zstd).
* **Waterfall:** Детализация по этапам (DNS, TCP, TLS, TTFB, Content Download).

### Анализ размеров

* **Transfer Size:** Размер данных по сети (сжатые).
* **Resource Size:** Распакованный размер ресурсов.

### Тайминги

* **Total Time:** Общее время выполнения запроса.
* **Response Time:** Время до начала ответа сервера.

### Блокировка ресурсов (Network Request Blocking)

* **Block Request URL/Domain:** Тестирование SPOF (Single Point of Failure) путём блокировки конкретных ресурсов или доменов.
* **Панель блокировки:** Доступна через More Tools → Network Request Blocking.

### Анализ документа (Doc)

Начните с анализа основного HTML-документа. Проверьте время ответа сервера (**TTFB - Time To First Byte**), заголовки кэширования и сжатия.

### Анализ ресурсов (CSS, JS, Fonts, Img)

* **Рендер-блокирующие ресурсы:** CSS и JS в `<head>` без `async`/`defer` блокируют отрисовку. Их следует минимизировать.
* **Приоритет загрузки:** Браузер назначает внутренние приоритеты ресурсам (High, Low) для оптимизации их загрузки.
* **Сторонние ресурсы:** Загрузка критически важных ресурсов с других доменов (например, jQuery с CDN) требует установки нового соединения (DNS, TCP, TLS), что добавляет минимум 3 RTT и замедляет процесс. Размещение блокирующего JS с другого домена в `<head>` — это **"EpicFail"** с точки зрения скорости. Для оценки RTT можно использовать `ping`.
* **Форматы:** Используйте современные форматы: **WOFF2** для шрифтов, **WebP/AVIF** для изображений.
* **Waterfall:** График для просмотра последовательности и длительности загрузки ресурсов.

### Скриншоты (Screenshots)

Покадровая фиксация процесса загрузки с привязкой к таймлинии.

### Статус внизу вкладки

Показывает общее количество запросов и объем данных (скачанный и распакованный). 5 МБ распакованного JS — это серьезная проблема.

## Вкладка Lighthouse

### Назначение

Автоматический аудит сайта для быстрой оценки производительности и выявления проблем.

### Категории аудита

Performance, Best Practices, SEO, Accessibility, PWA.

### Режимы тестирования

* **Navigation:** Загрузка страницы с нуля и анализ метрик (по умолчанию).
* **Timespan:** Запись активности браузера в течение произвольного промежутка времени (для интерактивных тестов).
* **Snapshot:** Мгновенный снимок текущего состояния страницы (для динамического контента).

### Режимы троттлинга

* **Simulated:** Эмуляция замедления путём пересчёта метрик (быстрее, менее точно).
* **DevTools:** Реальное ограничение ресурсов (CPU и сети) — медленнее, но точнее и стабильнее.

### Профили устройств

Mobile (с троттлингом CPU и сети) и Desktop (без троттлинга или с минимальным).

### Дополнительные настройки

* **Clear Storage:** Очистка хранилища перед тестом для чистой загрузки.
* **JS Sampling:** Включение семплирования JavaScript для детального анализа.

### Результаты

* **Оценка в баллах:** Калькулятор весов метрик (веса могут меняться).
* **Web Vitals:** FCP, LCP, CLS, TBT, TTI и другие.
* **Filmstrip:** Покадровая раскадровка процесса загрузки.
* **Opportunities:** Рекомендации по оптимизации с оценкой потенциального улучшения.
* **Диагностика:** Детальная информация по каждой метрике.

### Экспорт

Сохранение отчётов в JSON, HTML, печать, интеграция с CI/CD через консольную версию Lighthouse.

> **Важно:** Рекомендации Lighthouse нужно интерпретировать с осторожностью. Например, инлайнинг всего CSS, чтобы "убрать блокирующие ресурсы", может ухудшить кэширование и увеличить вес страниц. Lighthouse эмулирует сеть путем пересчета, а не реального ограничения скорости, что делает его эмуляцию менее точной, чем у WebPageTest.

## Вкладка Performance

### Режимы записи

* **Reload:** Автоматическая запись профиля загрузки страницы с нуля (холодная загрузка).
* **Record:** Ручная запись сессии для фиксации произвольных действий пользователя (клики, навигация, взаимодействие с формами). Полезно для Single Page Applications.

### Настройки окружения (Environment Settings)

* **Disable Cache:** Отключение кэша для чистой загрузки.
* **CPU Throttling:** Замедление процессора (например, 4x slowdown) для эмуляции мобильных устройств.
* **Network Throttling:** Торможение сети через пресеты или кастомные профили.

### Анализ профиля

* **Waterfall:** Временная шкала загрузки ресурсов (синхронизирована с другими метриками).
* **Flame Graph:** Визуализация активности основного потока браузера (Main Thread). Жёлтые блоки — выполнение JavaScript, фиолетовые — рендеринг (Layout, Paint), зелёные — работа композитора.
* **Call Tree:** Иерархическое дерево вызовов функций для поиска Long Tasks.
* **Event Log:** Последовательная запись событий с детализацией по времени.
* **Скриншоты:** Покадровая фиксация процесса рендеринга страницы.

### Метрики Web Vitals

* **LCP (Largest Contentful Paint):** breakdown с рекомендациями по оптимизации.
* **CLS (Cumulative Layout Shift):** Выявление элементов, вызывающих сдвиги макета.
* **FCP (First Contentful Paint), FID (First Input Delay), TTI (Time to Interactive).**

### Дополнительные возможности

* **Дерево критических ресурсов:** Визуализация зависимостей между ресурсами, блокирующими рендеринг.
* **Рекомендации:** Контекстные подсказки по оптимизации (улучшение подключения к доменам, оптимизация изображений, шрифтов).
* **Фильтрация контента:** Возможность отключения контента третьих лиц (счетчики, аналитика) для чистоты анализа.
* **Профилирование памяти:** Опциональное включение для анализа потребления оперативной памяти.
* **Экспорт/Импорт:** Сохранение профилей в формате JSON для совместной работы.
* **Связь с другими вкладками:** Клик по элементам профиля открывает соответствующие ресурсы во вкладке Elements или Sources.

## Вкладка Recorder

### Назначение

Создание и воспроизведение сценариев взаимодействия с сайтом для автоматизации тестирования производительности.

### Функционал

* **Запись сессии:** Фиксация кликов, навигации, ввода данных в формы.
* **Экспорт сценариев:** Сохранение в JSON для повторного использования или передачи команде.
* **Воспроизведение:** Запуск записанного сценария с возможностью масштабирования задержек.
* **Интеграция с Performance:** Экспорт записанного сценария прямо во вкладку Performance для детального анализа.

### Применение

Тестирование Single Page Applications, пользовательских сценариев (корзина, фильтры, чекаут).

## Панель Performance Monitor

### Назначение

Мониторинг метрик в реальном времени при взаимодействии с сайтом.

### Метрики

* **CPU Usage:** Потребление процессора (помогает выявлять тяжёлые анимации, утечки).
* **JS Heap Size:** Потребление оперативной памяти (выявление утечек памяти).
* **DOM Nodes:** Количество узлов DOM (рост может указывать на проблемы).
* **Layout Count & Recalc Style:** Частота пересчётов макета и стилей.
* **Event Listener:** Количество обработчиков событий.

### Применение

Выявление проблем при интерактивном использовании сайта (анимации, динамический контент).

## Другие инструменты (More Tools)

* **Network Request Blocking:** Панель для блокировки ресурсов по URL или домену (тестирование SPOF).
* **Elements:** Анализ вёрстки, адаптивных изображений, шрифтов (Computed Styles → Font Family).
* **Console:** Отслеживание ошибок JavaScript, проблем с загрузкой ресурсов, политик безопасности.
* **Application:** Управление хранилищами (LocalStorage, SessionStorage, IndexedDB), Service Workers, манифестом PWA.
* **Memory:** Профилирование памяти (Heap Snapshot, Allocation Timeline) для поиска утечек.
* **Security:** Проверка TLS-соединения (протокол, шифры, сертификат), выявление mixed content.
* **Application → Storage:** Очистка хранилищ, управление cookie.
