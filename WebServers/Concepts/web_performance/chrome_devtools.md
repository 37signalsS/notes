# Chrome DevTools для анализа производительности

## Definitions

**Chrome DevTools** — набор инструментов веб-разработчика, встроенных в браузер Chrome (и другие браузеры на движке Blink). Ключевой инструмент для анализа и отладки производительности веб-приложений.

**Открытие:** `F12` или `Ctrl+Shift+I`. Для мобильного тестирования рекомендуется выносить DevTools в отдельное окно (`Unlock to separate Window`), чтобы не влиять на viewport.

## Basic Concepts

### Мобильная эмуляция (Device Toolbar)

- **Выбор устройства:** Эмуляция конкретных моделей или custom-режим с настройкой viewport и DPR (Device Pixel Ratio).
- **CPU Throttling:** Замедление процессора для эмуляции мобильных устройств. Перед использованием требуется калибровка (бенчмарк определяет коэффициент замедления).
- **Network Throttling:** Торможение сети через пресеты (Fast 4G, Slow 4G) или кастомные профили с настройкой потери пакетов (1–2% максимум), задержки и пропускной способности.
- **Режимы:** Responsive для ручного контроля, оффлайн-режим для тестирования PWA.

### Вкладка Network — анализ загрузки ресурсов

#### Базовые настройки

- **Disable Cache:** Обязательно для симуляции холодной загрузки.
- **Preserve Log:** Сохранение лога между перезагрузками страниц.
- **Запись сессий:** Экспорт/импорт HAR-файлов для совместной работы.

#### Фильтрация и колонки

- **По типу:** Doc, CSS, JS, Img, Font, Fetch/XHR.
- **По домену/пути:** Свободный поиск или фильтрация по домену.
- **По приоритету:** Сортировка по приоритету загрузки (Highest, High, Medium, Low).
- **Protocol:** Отображение HTTP/2, HTTP/3.
- **Content Encoding:** Проверка сжатия (Brotli, Gzip, Zstd).
- **Waterfall:** Детализация по этапам (DNS, TCP, TLS, TTFB, Content Download).

#### Анализ размеров и таймингов

- **Transfer Size:** Размер данных по сети (сжатый).
- **Resource Size:** Распакованный размер ресурсов.
- **Total Time:** Общее время выполнения запроса.
- **Response Time:** Время до начала ответа сервера.

#### Блокировка ресурсов (Network Request Blocking)

- **Block Request URL/Domain:** Тестирование SPOF (Single Point of Failure) путём блокировки конкретных ресурсов или доменов.
- **Панель блокировки:** Доступна через More Tools → Network Request Blocking.

#### Анализ документа (Doc)

Начните с анализа основного HTML-документа. Проверьте время ответа сервера (**TTFB — Time To First Byte**), заголовки кэширования и сжатия.

#### Анализ ресурсов (CSS, JS, Fonts, Img)

- **Рендер-блокирующие ресурсы:** CSS и JS в `<head>` без `async`/`defer` блокируют отрисовку. Их следует минимизировать.
- **Приоритет загрузки:** Браузер назначает внутренние приоритеты ресурсам (High, Low) для оптимизации их загрузки.
- **Сторонние ресурсы:** Загрузка критически важных ресурсов с других доменов (например, jQuery с CDN) требует нового соединения (DNS, TCP, TLS), что добавляет минимум 3 RTT. Размещение блокирующего JS с другого домена в `<head>` — критическая ошибка. Для оценки RTT можно использовать `ping`.
- **Форматы:** Используйте современные форматы: **WOFF2** для шрифтов, **WebP/AVIF** для изображений.
- **Waterfall:** График для просмотра последовательности и длительности загрузки ресурсов.

#### Скриншоты и статус

- **Screenshots:** Покадровая фиксация процесса загрузки с привязкой к таймлинии.
- **Статус внизу вкладки:** Общее количество запросов и объём данных (скачанный и распакованный). 5 МБ распакованного JS — серьёзная проблема.

### Вкладка Lighthouse — автоматический аудит

#### Назначение и категории

Автоматический аудит сайта для быстрой оценки производительности и выявления проблем. Категории: Performance, Best Practices, SEO, Accessibility, PWA.

#### Режимы тестирования

- **Navigation:** Загрузка страницы с нуля и анализ метрик (по умолчанию).
- **Timespan:** Запись активности браузера в течение произвольного промежутка времени.
- **Snapshot:** Мгновенный снимок текущего состояния страницы.

#### Режимы троттлинга

- **Simulated:** Эмуляция замедления путём пересчёта метрик (быстрее, менее точно).
- **DevTools:** Реальное ограничение ресурсов (CPU и сети) — медленнее, но точнее.

#### Профили устройств и настройки

- Mobile (с троттлингом CPU и сети) и Desktop (без троттлинга или с минимальным).
- **Clear Storage:** Очистка хранилища перед тестом.
- **JS Sampling:** Включение семплирования JavaScript.

#### Результаты и экспорт

- **Оценка в баллах:** Калькулятор весов метрик (веса могут меняться).
- **Web Vitals:** FCP, LCP, CLS, TBT, TTI.
- **Filmstrip:** Покадровая раскадровка процесса загрузки.
- **Opportunities:** Рекомендации по оптимизации с оценкой потенциального улучшения.
- **Диагностика:** Детальная информация по каждой метрике.
- **Экспорт:** JSON, HTML, печать, интеграция с CI/CD через консольную версию Lighthouse.

> **Важно:** Рекомендации Lighthouse нужно интерпретировать с осторожностью. Инлайнинг всего CSS может ухудшить кэширование. Эмуляция сети менее точна, чем у WebPageTest.

### Вкладка Performance — профилирование загрузки

#### Режимы записи

- **Reload:** Автоматическая запись профиля загрузки страницы с нуля (холодная загрузка).
- **Record:** Ручная запись сессии для фиксации произвольных действий пользователя (клики, навигация, формы). Полезно для Single Page Applications.

#### Настройки окружения

- **Disable Cache:** Отключение кэша для чистой загрузки.
- **CPU Throttling:** Замедление процессора (например, 4x slowdown).
- **Network Throttling:** Торможение сети через пресеты или кастомные профили.

#### Анализ профиля

- **Waterfall:** Временная шкала загрузки ресурсов (синхронизирована с другими метриками).
- **Flame Graph:** Визуализация активности основного потока браузера. Жёлтые блоки — выполнение JavaScript, фиолетовые — рендеринг (Layout, Paint), зелёные — работа композитора.
- **Call Tree:** Иерархическое дерево вызовов функций для поиска Long Tasks.
- **Event Log:** Последовательная запись событий с детализацией по времени.
- **Скриншоты:** Покадровая фиксация процесса рендеринга страницы.

#### Метрики Web Vitals

- **LCP (Largest Contentful Paint):** Breakdown с рекомендациями по оптимизации.
- **CLS (Cumulative Layout Shift):** Выявление элементов, вызывающих сдвиги макета.
- **FCP (First Contentful Paint), INP (Interaction to Next Paint), TTI (Time to Interactive).**

#### Дополнительные возможности

- **Дерево критических ресурсов:** Визуализация зависимостей между ресурсами, блокирующими рендеринг.
- **Рекомендации:** Контекстные подсказки по оптимизации.
- **Фильтрация контента:** Отключение контента третьих лиц (счётчики, аналитика) для чистоты анализа.
- **Профилирование памяти:** Опциональное включение для анализа потребления оперативной памяти.
- **Экспорт/Импорт:** Сохранение профилей в формате JSON.
- **Связь с другими вкладками:** Клик по элементам профиля открывает соответствующие ресурсы во вкладке Elements или Sources.

## Practical Scenarios

### Сценарий: аудит производительности перед релизом

1. Откройте DevTools (`F12`), перейдите во вкладку Lighthouse.
2. Выберите режим Navigation, профиль Mobile, троттлинг DevTools.
3. Включите Clear Storage, запустите аудит.
4. Проанализируйте оценку Performance, метрики Web Vitals, секции Opportunities и Diagnostics.
5. Экспортируйте отчёт в HTML для команды.

### Сценарий: поиск причины медленной загрузки SPA

1. Перейдите во вкладку Performance, включите Disable Cache и CPU Throttling 4x.
2. Нажмите Record, выполните пользовательский сценарий (навигация, взаимодействие с формами).
3. Остановите запись, изучите Flame Graph: жёлтые блоки — Long Tasks в JavaScript.
4. Раскройте Call Tree, найдите функцию с наибольшим Self Time.
5. Кликните по функции — DevTools откроет исходный код во вкладке Sources.

### Сценарий: тестирование отказоустойчивости (SPOF)

1. Откройте More Tools → Network Request Blocking.
2. Добавьте домен CDN (`*.cdn.example.com`) или конкретный ресурс (`/static/app.js`).
3. Перезагрузите страницу, проверьте: сайт загружается без этого ресурса?
4. Если нет — выявлена критическая зависимость.

### Сценарий: анализ утечки памяти

1. Откройте Performance Monitor (More Tools → Performance Monitor).
2. Наблюдайте за метриками JS Heap Size и DOM Nodes при длительной работе с приложением.
3. Стабильный рост без возврата к базовому уровню указывает на утечку.
4. Перейдите во вкладку Memory, сделайте Heap Snapshot до и после сценария, сравните разницу.

### Сценарий: запись и воспроизведение пользовательского сценария

1. Откройте вкладку Recorder, создайте новую сессию.
2. Выполните сценарий (например, добавление товара в корзину и оформление заказа).
3. Экспортируйте сценарий в JSON.
4. Импортируйте сценарий во вкладку Performance для детального анализа производительности этого пути.

## Additional Information

### Другие инструменты (More Tools)

- **Elements:** Анализ вёрстки, адаптивных изображений, шрифтов (Computed Styles → Font Family).
- **Console:** Отслеживание ошибок JavaScript, проблем с загрузкой ресурсов, политик безопасности.
- **Application:** Управление хранилищами (LocalStorage, SessionStorage, IndexedDB), Service Workers, манифест PWA.
- **Memory:** Профилирование памяти (Heap Snapshot, Allocation Timeline) для поиска утечек.
- **Security:** Проверка TLS-соединения (протокол, шифры, сертификат), выявление mixed content.
- **Application → Storage:** Очистка хранилищ, управление cookie.
