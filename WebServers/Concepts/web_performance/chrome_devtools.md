# Chrome DevTools для анализа производительности

## Определения

**Chrome DevTools** — набор инструментов веб-разработчика, встроенных в браузер Chrome (и другие браузеры на движке Blink). Ключевой инструмент для анализа и отладки производительности веб-приложений.

**Открытие:** `F12` или `Ctrl+Shift+I`. Для мобильного тестирования рекомендуется выносить DevTools в отдельное окно (`Unlock to separate Window`), чтобы не влиять на область просмотра (viewport).

## Основные концепции

### Мобильная эмуляция (Device Toolbar)

- **Выбор устройства:** Эмуляция конкретных моделей или кастомный режим с настройкой области просмотра и DPR (Device Pixel Ratio — коэффициент пикселей устройства).
- **CPU Throttling:** Замедление центрального процессора для эмуляции мобильных устройств. Перед использованием требуется калибровка (бенчмарк определяет коэффициент замедления).
- **Network Throttling:** Ограничение пропускной способности сети через пресеты (Fast 4G, Slow 4G) или пользовательские профили с настройкой потери пакетов (максимум 1–2%), задержки и пропускной способности.
- **Режимы:** Responsive для ручного контроля, автономный режим (Offline) для тестирования PWA (Progressive Web App — прогрессивное веб-приложение).

### Вкладка Network — анализ загрузки ресурсов

#### Базовые настройки

- **Disable Cache:** Обязательно для симуляции холодной загрузки (без кэша).
- **Preserve Log:** Сохранение журнала запросов между перезагрузками страниц.
- **Запись сессий:** Экспорт и импорт файлов HAR (HTTP Archive — архив HTTP) для совместной работы.

#### Фильтрация и колонки

- **По типу:** Doc, CSS (Cascading Style Sheets — каскадные таблицы стилей), JS (JavaScript), Img, Font, Fetch/XHR (XMLHttpRequest).
- **По домену или пути:** Свободный поиск или фильтрация по конкретному домену.
- **По приоритету:** Сортировка по внутреннему приоритету загрузки браузера (Highest, High, Medium, Low).
- **Protocol:** Отображение версий протокола (HTTP/2, HTTP/3).
- **Content Encoding:** Проверка алгоритмов сжатия (Brotli, Gzip, Zstd).
- **Waterfall:** Детализация по этапам прохождения запроса: DNS (Domain Name System), TCP (Transmission Control Protocol), TLS (Transport Layer Security), TTFB (Time to First Byte — время до первого байта), Content Download.

#### Анализ размеров и таймингов

- **Transfer Size:** Размер данных, переданных по сети (в сжатом виде).
- **Resource Size:** Размер ресурсов после распаковки браузером.
- **Total Time:** Общее время выполнения сетевого запроса.
- **Response Time:** Время до начала получения ответа от сервера.

#### Блокировка ресурсов (Network Request Blocking)

- **Block Request URL/Domain:** Тестирование SPOF (Single Point of Failure — единая точка отказа) путём блокировки загрузки конкретных ресурсов или целых доменов.
- **Панель блокировки:** Доступна через меню More Tools → Network Request Blocking.

#### Анализ документа (Doc)

Анализ следует начинать с основного HTML-документа. Необходимо проверить время ответа сервера (TTFB), заголовки управления кэшированием и тип сжатия.

#### Анализ ресурсов (CSS, JS, Fonts, Img)

- **Рендер-блокирующие ресурсы:** CSS и JS в секции `<head>` без атрибутов `async` или `defer` блокируют отрисовку страницы. Их количество и объем следует минимизировать.
- **Приоритет загрузки:** Браузер назначает приоритеты ресурсам для оптимизации критического пути рендеринга.
- **Сторонние ресурсы:** Загрузка ресурсов с других доменов (например, внешние библиотеки с CDN) требует установки нового соединения (DNS, TCP, TLS), что добавляет минимум 3 RTT (Round Trip Time — время приема-передачи). Использование блокирующего JS с внешнего домена в `<head>` считается критической ошибкой.
- **Форматы:** Рекомендуется использовать современные форматы: WOFF2 для шрифтов, WebP или AVIF для изображений.
- **Waterfall:** Графическое представление последовательности и длительности загрузки всех ресурсов страницы.

#### Скриншоты и статус

- **Screenshots:** Покадровая фиксация процесса загрузки страницы с привязкой к временной шкале.
- **Статус внизу вкладки:** Общее количество запросов и суммарный объём данных. Большой объем распакованного JavaScript (например, более 5 МБ) является признаком проблем с производительностью.

### Вкладка Lighthouse — автоматический аудит

#### Назначение и категории

Инструмент для автоматизированного аудита сайта. Категории анализа: Performance (производительность), Best Practices (лучшие практики), SEO (Search Engine Optimization — поисковая оптимизация), Accessibility (доступность), PWA.

#### Режимы тестирования

- **Navigation:** Анализ загрузки страницы с нуля (режим по умолчанию).
- **Timespan:** Запись активности браузера в течение заданного интервала времени.
- **Snapshot:** Анализ текущего состояния страницы в конкретный момент.

#### Режимы ограничения ресурсов (Throttling)

- **Simulated:** Эмуляция замедления через математический пересчёт метрик (быстрее, но менее точно).
- **DevTools:** Реальное ограничение ресурсов центрального процессора и сети — обеспечивает максимальную точность.

#### Профили устройств и настройки

- Mobile (с ограничением ресурсов) и Desktop (без ограничений).
- **Clear Storage:** Принудительная очистка всех хранилищ браузера перед началом теста.
- **JS Sampling:** Включение профилирования выполнения JavaScript.

#### Результаты и экспорт

- **Оценка в баллах:** Обобщенный показатель, рассчитанный на основе весов различных метрик.
- **Web Vitals:** Основные метрики FCP, LCP, CLS, TBT, TTI.
- **Filmstrip:** Покадровая визуализация процесса загрузки.
- **Opportunities:** Список конкретных рекомендаций по оптимизации с оценкой потенциального выигрыша по времени.
- **Диагностика:** Техническая информация по каждой измеренной метрике.
- **Экспорт:** Поддержка форматов JSON (JavaScript Object Notation), HTML, печать отчета.

### Вкладка Performance — профилирование производительности

#### Режимы записи

- **Reload:** Автоматическая запись профиля при холодной загрузке страницы.
- **Record:** Ручная запись для анализа действий пользователя (клики, прокрутка, заполнение форм). Критично для SPA (Single Page Application — одностраничное приложение).

#### Настройки окружения

- **Disable Cache:** Отключение кэша для воспроизводимости результатов.
- **CPU Throttling:** Имитация менее производительных устройств (например, замедление в 4 или 6 раз).
- **Network Throttling:** Ограничение скорости сетевого соединения.

#### Анализ профиля

- **Waterfall:** Временная шкала загрузки ресурсов.
- **Flame Graph:** Визуализация активности основного потока браузера. Жёлтые блоки обозначают выполнение JavaScript, фиолетовые — этапы рендеринга (Layout, Paint), зелёные — работу композитора.
- **Call Tree:** Дерево вызовов функций для идентификации Long Tasks (длительных задач).
- **Event Log:** Журнал событий браузера с точностью до миллисекунд.
- **Скриншоты:** Визуальная история рендеринга.

#### Метрики Web Vitals

- **LCP (Largest Contentful Paint):** Детальный разбор элемента и рекомендации.
- **CLS (Cumulative Layout Shift):** Список элементов, вызывающих нестабильность макета.
- **FCP (First Contentful Paint), INP (Interaction to Next Paint), TTI (Time to Interactive).**

#### Дополнительные возможности

- **Дерево критических ресурсов:** Визуализация цепочек зависимостей, блокирующих отрисовку.
- **Фильтрация контента:** Возможность скрыть активность сторонних скриптов для чистоты анализа.
- **Профилирование памяти:** Анализ потребления оперативной памяти в динамике.
- **Экспорт/Импорт:** Сохранение и загрузка профилей в формате JSON.

## Практические сценарии

### Сценарий: аудит производительности перед релизом

1. Откройте Chrome DevTools (`F12`), перейдите во вкладку Lighthouse.
2. Выберите режим Navigation, профиль Mobile, тип ограничения DevTools.
3. Включите опцию Clear Storage и запустите выполнение аудита.
4. Изучите раздел Performance и метрики Web Vitals, обращая внимание на рекомендации в секциях Opportunities и Diagnostics.
5. Экспортируйте отчет для дальнейшего анализа командой разработки.

### Сценарий: поиск причин медленной работы интерфейса

1. Во вкладке Performance включите Disable Cache и установите CPU Throttling 4x.
2. Запустите запись (Record) и выполните действия, вызывающие задержки в интерфейсе.
3. После остановки изучите Flame Graph на предмет Long Tasks (выделены красным углом).
4. Используйте Call Tree для поиска функций с наибольшим временем выполнения (Self Time).

### Сценарий: диагностика единой точки отказа (SPOF)

1. Через меню More Tools откройте панель Network Request Blocking.
2. Добавьте паттерн для блокировки (например, домен CDN или конкретный критический скрипт).
3. Перезагрузите страницу и убедитесь, что основной контент остается доступным и функциональным при сбое внешней зависимости.

### Сценарий: анализ утечек памяти

1. Откройте Performance Monitor (через меню More Tools).
2. Следите за графиками JS Heap Size и DOM Nodes (Document Object Model — объектная модель документа) при активном использовании приложения.
3. Если количество узлов DOM или размер кучи постоянно растет без возврата к исходным значениям, это указывает на утечку памяти.
4. Используйте вкладку Memory для создания снимков кучи (Heap Snapshot) и их сравнения.

## Дополнительная информация

### Вспомогательные инструменты (More Tools)

- **Elements:** Глубокий анализ объектной модели документа (DOM), стилей и примененных шрифтов.
- **Console:** Журнал ошибок выполнения JavaScript, предупреждений безопасности и проблем загрузки ресурсов.
- **Application:** Управление локальными хранилищами (LocalStorage, IndexedDB), Service Workers и манифестом PWA.
- **Memory:** Инструментарий для профилирования использования памяти и поиска утечек.
- **Security:** Проверка параметров безопасного соединения (сертификаты, протоколы TLS), поиск смешанного контента (mixed content).
