# Лучшие практики оптимизации производительности

## Definitions

**Лучшие практики оптимизации производительности** — совокупность проверенных подходов к минимизации времени загрузки и повышения интерактивности веб-страниц. Сфокусированы на устранении блокирующих рендеринг ресурсов, оптимизации изображений, контроле сторонних скриптов и корректной настройке загрузки контента.

## Basic Concepts

### Ключевые принципы

* **Минимизация блокирующих ресурсов** — каждый CSS и синхронный JS в `<head>` откладывает начало отрисовки (FCP/LCP).
* **Контроль выполнения JavaScript** — длительный JS блокирует основной поток, снижая интерактивность (INP/TBT).
* **Оптимизация изображений** — современные форматы (WebP, AVIF) и сжатие критичны для объёма передаваемых данных.
* **Lazy Loading** — загрузка ресурсов за пределами видимой области по требованию (`loading="lazy"` для изображений и iframe).
* **Изоляция сторонних скриптов** — счётчики, аналитика, рекламные сети потребляют ресурсы основного потока.
* **Верификация инструментов** — маркетинговые заявления CDN и сервисов "ускорения в один клик" требуют независимого тестирования.

## Practical Scenarios

### Блокирующие ресурсы в `<head>`

Каждый `<link rel="stylesheet">` и `<script>` (без `async`/`defer`) блокирует рендеринг.

**Решение:** минимизировать CSS/JS в `<head>`, использовать `defer` для скриптов, инлайнить критический CSS (с осторожностью — см. [chrome_devtools.md](./chrome_devtools.md)).

### Большое количество или объём JS

Длительное выполнение JavaScript блокирует основной поток, делая страницу неинтерактивной.

**Решение:** code splitting, tree shaking, отложенная загрузка неблокирующих скриптов, анализ через Performance tab — [chrome_devtools.md](./chrome_devtools.md).

### Неоптимизированные изображения

Старые форматы (JPEG, PNG) и отсутствие сжатия увеличивают время загрузки.

**Решение:** WebP/AVIF, адаптивные размеры (`srcset`), сжатие, CDN для изображений.

### Динамические элементы (слайдеры, карусели)

Могут "обманывать" инструменты тестирования, завышая LCP, так как каждый новый слайд воспринимается как изменение контента.

**Решение:** фиксировать LCP-элемент, избегать автоматической смены слайдов до стабилизации метрик.

### Отсутствие Lazy Loading

Загрузка всех изображений, включая невидимые, замедляет первоначальную загрузку.

**Решение:** `loading="lazy"` для изображений ниже линии экрана, `loading="eager"` для LCP-элемента.

### Сторонние скрипты (счётчики, аналитика, реклама)

Значительно влияют на производительность. Код часто раздут и требует ресурсов основного потока. Google Tag Manager может критично влиять на интерактивность.

**Решение:** отложенная загрузка после `window.load`, использование Web Workers (где возможно), блокировка для тестирования чистого профиля — [chrome_devtools.md](./chrome_devtools.md).

### Осторожность с CDN и автоматическими сервисами

* Загрузка критичных ресурсов с медленных CDN или использование сервисов "ускорения в один клик" (включая некоторые функции Cloudflare) может замедлить сайт.
* Автоматические сервисы часто применяют общие, неоптимальные методики.
* **Никогда не доверяйте маркетинговым заявлениям.** Эффективность проверяется детальным тестированием (например, через [WebPageTest](./webpagetest.md)), сравнивая метрики "до" и "после".
