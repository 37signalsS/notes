# Лучшие практики оптимизации производительности веб-приложений

## Определения

**Лучшие практики оптимизации производительности** — совокупность проверенных архитектурных и технических подходов к минимизации времени загрузки и повышения интерактивности страниц. Основной фокус направлен на устранение ресурсов, блокирующих рендеринг, оптимизацию доставки медиаконтента, контроль сторонних зависимостей и приоритизацию критического пути загрузки.

**Критический путь рендеринга (Critical Rendering Path)** — последовательность шагов, которые проходит браузер для преобразования HTML (HyperText Markup Language), CSS (Cascading Style Sheets) и JavaScript в видимые пиксели на экране.

## Основные концепции

### Ключевые принципы оптимизации

* **Минимизация блокирующих ресурсов** — каждый файл стилей CSS и синхронный скрипт JavaScript в секции `<head>` откладывает начало отрисовки контента (метрики FCP (First Contentful Paint) и LCP (Largest Contentful Paint)).
* **Контроль выполнения JavaScript** — длительное выполнение скриптов блокирует основной поток (main thread), что негативно сказывается на интерактивности (метрики INP (Interaction to Next Paint) и TBT (Total Blocking Time)).
* **Оптимизация медиаконтента** — использование современных форматов изображений (WebP, AVIF) и эффективное сжатие позволяют значительно сократить объем передаваемого трафика.
* **Ленивая загрузка (Lazy Loading)** — отложенная загрузка ресурсов, находящихся за пределами видимой области экрана, до момента необходимости их отображения.
* **Изоляция сторонних скриптов** — внешние зависимости (счетчики аналитики, рекламные блоки, виджеты социальных сетей) потребляют ресурсы процессора и могут замедлять работу основного приложения.
* **Доказательный подход** — маркетинговые обещания сервисов "ускорения" (включая автоматические функции CDN (Content Delivery Network)) требуют обязательной верификации через независимые замеры.

### Оптимизация шрифтов

Шрифты часто становятся причиной задержки отображения текста или нежелательных сдвигов макета (CLS (Cumulative Layout Shift)).

* **Использование `font-display: swap`** — позволяет отображать системный шрифт до момента полной загрузки кастомного, предотвращая невидимость текста (FOIT — Flash of Invisible Text).
* **Предварительная загрузка (Preload)** — использование `<link rel="preload">` для критических шрифтов, чтобы браузер начал их загрузку максимально рано.
* **Формат WOFF2** — наиболее современный и компактный формат шрифтов с поддержкой сжатия.

## Практические сценарии

### Устранение блокирующих ресурсов в `<head>`

Каждый тег `<link rel="stylesheet">` и `<script>` без атрибутов асинхронности блокирует построение дерева рендеринга.

**Решение:**

1. Переместить второстепенные скрипты вниз страницы или использовать атрибут `defer`.
2. Выделить **критический CSS** (стили, необходимые для отрисовки первого экрана) и вставить его инлайново в HTML, а основной файл стилей загружать асинхронно. Подробнее об анализе в [chrome_devtools.md](./chrome_devtools.md).

### Оптимизация объема и выполнения JavaScript

Большие бандлы JavaScript долго загружаются и требуют значительного времени на парсинг и выполнение.

**Решение:**

* Применять разделение кода (code splitting) и удаление неиспользуемого кода (tree shaking).
* Использовать Web Workers для выноса тяжелых вычислений из основного потока.
* Контролировать Long Tasks (задачи длительностью более 50 мс) через вкладку Performance в [Chrome DevTools](./chrome_devtools.md).

### Работа с неоптимизированными изображениями

**Решение:**

* Использовать атрибут `srcset` для предоставления браузеру возможности выбора изображения под разрешение экрана.
* Устанавливать явные атрибуты `width` и `height` для предотвращения сдвигов макета (CLS).
* Для LCP-элемента (например, главного баннера) использовать `loading="eager"` и `fetchpriority="high"`, а для остальных — `loading="lazy"`.

### Контроль сторонних зависимостей

Сторонние скрипты (Google Tag Manager, аналитика, рекламные сети) часто являются основным источником проблем с INP.

**Решение:**

* Ограничить количество контейнеров и скриптов в Google Tag Manager.
* Загружать аналитику только после события `window.load` или при первом взаимодействии пользователя.
* Тестировать влияние стороннего кода, временно блокируя его в браузере (см. [chrome_devtools.md](./chrome_devtools.md)).

### Осторожность с CDN и автоматическими оптимизаторами

* **Никогда не доверяйте маркетинговым заявлениям.** Эффективность любой "магической" кнопки ускорения (включая функции Cloudflare Rocket Loader или Polish) должна проверяться детальным тестированием в [WebPageTest](./webpagetest.md) до и после включения.
* Загрузка критических ресурсов с медленных или перегруженных CDN может увеличить время установления соединения из-за лишних DNS-запросов и рукопожатий TLS (Transport Layer Security).
