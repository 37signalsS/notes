# WebPageTest — инструмент синтетического тестирования производительности

## Определения

**WebPageTest** — профессиональный инструмент для синтетического (лабораторного) тестирования производительности, обеспечивающий глубокую диагностику в контролируемой среде. С 2025 года полностью интегрирован в платформу **Catchpoint Internet Performance Monitoring (IPM)**, что позволяет объединять данные синтетических тестов с глобальным мониторингом инфраструктуры.

**SPOF (Single Point of Failure — единая точка отказа)** — ресурс или домен (обычно сторонний: CDN со шрифтами, аналитика, рекламный скрипт), недоступность или задержка которого полностью блокирует отрисовку основного контента или критическую функциональность страницы.

**No-Code Experiments** — функционал WebPageTest, позволяющий имитировать изменения на странице (удаление скриптов, оптимизация изображений, изменение приоритетов загрузки через `fetchpriority`) для мгновенной проверки их влияния на метрики Core Web Vitals без физического изменения исходного кода.

## Основные концепции

### Распределённая архитектура и реальные устройства

WebPageTest использует сеть реальных устройств (Android, iOS) и десктопных браузеров, расположенных в более чем 50 локациях по всему миру. Ключевое отличие от эмуляции в Chrome DevTools — работа через **реальные сетевые каналы**, что позволяет точно имитировать:
*   **Packet Loss (потери пакетов):** Критично для тестирования устойчивости HTTP/3 (QUIC) и механизмов переотправки TCP.
*   **Jitter (дрожание фазы):** Влияние нестабильности пинга на стриминг и загрузку ресурсов.

### Ключевые возможности

*   **Мультипротокольный анализ:** Полная визуализация **HTTP/3 (QUIC)** в водопадных диаграммах. Инструмент подсвечивает проблемы с рукопожатием 0-RTT, ошибки ALPN и эффективность Connection Migration.
*   **Waterfall (Водопадная диаграмма):** Детальный график загрузки каждого ресурса.
    *   *Цветовая кодикация:* DNS (темно-синий), Connect (оранжевый), SSL/TLS (фиолетовый), TTFB (светло-голубой), Content (синий).
*   **Filmstrip (Раскадровка):** Визуальный ряд загрузки (обычно с шагом 0.1с–0.5с). Позволяет точно сопоставить события в Waterfall с тем, что видит пользователь.
*   **Scripting (Сценарии):** Мощный язык для имитации действий пользователя.
    ```text
    // Пример сценария авторизации
    setEventName    Open_Home
    navigate        https://example.com
    
    setEventName    Login_Action
    setValue        id=username    my_user
    setValue        id=password    my_password
    submitForm      id=login-form
    ```
*   **Performance Budgets:** Настройка алертинга при превышении лимитов (например, LCP > 2.5с или вес JS > 500 КБ).

## Практические сценарии

### Сценарий: Глубокая диагностика Core Web Vitals

1.  **Локация и сеть:** Выберите локацию, ближайшую к целевой аудитории. Установите профиль сети **4G (9 Mbps / 170ms RTT)** для имитации среднего мобильного пользователя.
2.  **Прогоны:** Запустите тест с **9 прогонами**. Это золотой стандарт 2026 года для минимизации влияния случайных сетевых флуктуаций.
3.  **Анализ фаз LCP:** В отчете перейдите в **Web Vitals View**. WebPageTest разбивает LCP на:
    *   *TTFB:* Время ответа сервера.
    *   *Load Delay:* Время, пока LCP-ресурс ждал в очереди.
    *   *Load Duration:* Длительность скачивания.
    *   *Render Delay:* Время от скачивания до отрисовки (загрузка Main Thread).

### Сценарий: Тестирование единой точки отказа (SPOF)

1.  Перейдите в **Advanced Settings** → вкладка **Block**.
2.  Укажите домен (например, `fonts.googleapis.com`) или конкретный скрипт.
3.  Запустите сравнение **Side-by-Side**.
4.  **Анализ:** Если при блокировке домена время `Start Render` увеличивается в 2-3 раза, значит ресурс является блокирующим.
5.  **Решение:** Хостинг ресурсов на своем домене, использование `async`/`defer` или переход на альтернативные шрифты.

### Сценарий: Автоматизация в CI/CD

Интеграция с GitHub Actions позволяет блокировать PR, которые ухудшают производительность:
```yaml
- name: WebPageTest Audit
  uses: webpagetest/github-action@v2
  with:
    apiKey: ${{ secrets.WPT_API_KEY }}
    url: ${{ env.STAGING_URL }}
    budget: .wptrules.json # Файл с лимитами метрик
```

## Дополнительная информация

### AI-инсайты и диагностика Main Thread

В 2026 году WebPageTest использует обученные модели для автоматического поиска аномалий в Waterfall. Инструмент подсвечивает:
*   **Main Thread Contention:** Периоды, когда выполнение JS блокирует обработку ввода (влияние на **INP**).
*   **Late Discovery:** Ресурсы, которые браузер обнаружил слишком поздно (например, изображения, спрятанные в JS-бандлах).
