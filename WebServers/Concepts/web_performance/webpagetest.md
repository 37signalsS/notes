# WebPageTest

## Definitions

**WebPageTest** — профессиональный инструмент для синтетического тестирования производительности веб-сайтов с распределённой архитектурой, обеспечивающий полный контроль над средой тестирования и географической локацией.

## Basic Concepts

### Распределённая архитектура

WebPageTest позволяет тестировать сайт из множества географических точек с полным контролем над средой: выбор локации, браузера, скорости соединения. Уникальная возможность — **эмуляция потери пакетов**, недоступная в большинстве других инструментов.

### Ключевые возможности

**Контролируемая среда:** выбор локации, браузера, профиля сети (включая кастомные профили с эмуляцией потери пакетов).

**Стабильность результатов:** поддержка множественных прогонов (рекомендуется 3–5) для получения медианного значения, что исключает влияние случайных факторов.

**Детальный отчёт:**
- **Waterfall** — наглядный график загрузки с детализацией по этапам (DNS, TCP, TLS, TTFB, Content Download).
- **Filmstrip View** — покадровая раскадровка процесса рендеринга, синхронизированная с Waterfall; позволяет точно определить, какой ресурс задерживает отрисовку.
- **Video** — видеозапись процесса загрузки страницы.

**Автоматизация:** наличие API для интеграции в CI/CD-пайплайны.

**SPOF-тестирование:** возможность блокировки конкретных ресурсов или доменов для оценки влияния сторонних зависимостей на работоспособность сайта.

## Practical Scenarios

### Сценарий: глубокий анализ производительности

1. Выберите локацию, близкую к целевой аудитории.
2. Установите профиль сети (например, Fast 3G для эмуляции мобильных условий).
3. Настройте браузер и устройство (mobile/desktop).
4. Запустите 3–5 прогонов для получения медианного результата.
5. Проанализируйте Waterfall: найдите блокирующие ресурсы, долгие запросы, избыточные загрузки.
6. Изучите Filmstrip View: определите момент первого визуального отображения (FCP) и Largest Contentful Paint (LCP).

### Сценарий: SPOF-тестирование

1. Определите критические сторонние ресурсы (CDN, аналитика, рекламные скрипты).
2. Используйте функцию Script или блокировку домена для имитации отказа ресурса.
3. Запустите тест — сайт остаётся функциональным без данного ресурса?
4. Если нет — выявлена критическая зависимость, требующая fallback-механизма.

### Сценарий: интеграция в CI/CD

1. Используйте WebPageTest API для автоматизации тестирования.
2. Настройте пороговые значения для метрик (LCP, FCP, CLS).
3. При превышении порогов — блокируйте релиз или создавайте алерт.

## Additional Information

### Интерпретация результатов

Динамический контент (например, **слайдеры**, бесконечная прокрутка) может искажать метрики LCP и общее время загрузки: каждый новый слайд воспринимается инструментом как изменение контента. Для корректной оценки пользовательского опыта анализируйте Filmstrip View, а не только числовые значения.

### Сравнение с другими инструментами

В отличие от [Chrome DevTools](./chrome_devtools.md), WebPageTest предлагает множество локаций, эмуляцию потери пакетов и API для CI/CD, но требует более сложной настройки. В отличие от [PageSpeed Insights](./pagespeed_insights.md), WebPageTest предоставляет контролируемые лабораторные данные с повторяемостью, а не единичный запуск с серверов Google.

Подробнее о принципах воспроизводимого тестирования — в [принципах тестирования](./testing_principles.md).
