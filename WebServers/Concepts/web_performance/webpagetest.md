# WebPageTest — инструмент синтетического тестирования производительности

## Определения

**WebPageTest** — профессиональный инструмент для синтетического (лабораторного) тестирования производительности веб-сайтов с распределённой архитектурой. Он обеспечивает полный контроль над средой тестирования, включая географическую локацию, параметры браузера и сетевые условия.

## Основные концепции

### Распределённая архитектура

WebPageTest позволяет тестировать веб-ресурсы из множества географических точек с полным контролем над средой. Уникальной возможностью инструмента является **эмуляция потери пакетов**, что недоступно в большинстве других сервисов анализа производительности.

### Ключевые возможности

* **Контролируемая среда:** выбор локации, типа браузера и профиля сети (включая кастомные конфигурации с заданными параметрами задержек и потерь пакетов).
* **Стабильность результатов:** поддержка выполнения множественных итераций (рекомендуется от 3 до 5 прогонов) для вычисления медианного значения, что минимизирует влияние случайных сетевых флуктуаций.
* **Детальная отчетность:**
  * **Waterfall (водопадная диаграмма)** — наглядный график загрузки ресурсов с детализацией по этапам протоколов: DNS (Domain Name System), TCP (Transmission Control Protocol), TLS (Transport Layer Security), TTFB (Time to First Byte — время до первого байта) и Content Download.
  * **Filmstrip View (раскадровка)** — покадровая визуализация процесса рендеринга, синхронизированная с водопадной диаграммой. Позволяет точно определить, какой именно ресурс задерживает отрисовку.
  * **Видеозапись** — визуальная фиксация процесса загрузки страницы для оценки пользовательского опыта.
* **Автоматизация:** наличие API (Application Programming Interface) для интеграции в процессы CI/CD (Continuous Integration / Continuous Deployment — непрерывная интеграция и непрерывное развертывание).
* **SPOF-тестирование (Single Point of Failure — единая точка отказа):** возможность блокировки конкретных доменов или ресурсов для оценки отказоустойчивости сайта при недоступности сторонних зависимостей (например, рекламных скриптов или аналитики).

## Практические сценарии

### Сценарий: Глубокий анализ производительности

1. Выбрать локацию, максимально приближенную к целевой аудитории проекта.
2. Установить профиль сети, соответствующий типичным условиям пользователей (например, профиль "Fast 3G" для мобильной аудитории).
3. Настроить эмуляцию устройства (мобильное или настольное).
4. Запустить от 3 до 5 прогонов для получения достоверного медианного результата.
5. Проанализировать водопадную диаграмму: выявить блокирующие ресурсы, длительные запросы к серверу и избыточный объем передаваемых данных.
6. Использовать раскадровку для определения моментов FCP (First Contentful Paint — первая отрисовка контента) и LCP (Largest Contentful Paint — отрисовка самого крупного контента).

### Сценарий: Тестирование единой точки отказа (SPOF)

1. Идентифицировать критические сторонние зависимости (CDN — Content Delivery Network, системы аналитики).
2. Использовать функционал блокировки домена для имитации отказа стороннего сервиса.
3. Запустить тест и проверить, сохраняет ли сайт функциональность при недоступности данного ресурса.
4. Если отрисовка блокируется — выявлена критическая зависимость, требующая внедрения механизмов фолбэка (fallback).

### Сценарий: Интеграция в пайплайн автоматизации

1. Использовать программный интерфейс WebPageTest для запуска автоматических тестов.
2. Настроить контроль пороговых значений для ключевых метрик: LCP, FCP, CLS (Cumulative Layout Shift — совокупное смещение макета).
3. При превышении заданных лимитов настроить блокировку сборки в CI/CD или отправку уведомлений команде разработки.

## Дополнительная информация

### Особенности интерпретации результатов

Наличие динамического контента, такого как слайдеры или бесконечная прокрутка, может искажать метрику LCP и общее время загрузки, так как каждое изменение в области просмотра воспринимается инструментом как новый этап отрисовки. Для корректной оценки рекомендуется анализировать раскадровку (Filmstrip View), а не полагаться исключительно на агрегированные числовые значения.

### Сравнение с альтернативными инструментами

В отличие от [Chrome DevTools](./chrome_devtools.md), WebPageTest предоставляет доступ к реальным устройствам в разных точках мира и точную эмуляцию сетевых потерь, хотя и требует более сложной настройки. По сравнению с [PageSpeed Insights](./pagespeed_insights.md), данный инструмент дает контролируемые лабораторные данные с высокой степенью воспроизводимости, а не разовый замер из облачной инфраструктуры Google.

Методология проведения воспроизводимых тестов подробно описана в разделе [принципы тестирования](./testing_principles.md).
