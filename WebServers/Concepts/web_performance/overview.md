## Определения

**Производительность веб-приложений (Web Performance)** — комплексная дисциплина, направленная на минимизацию времени доставки ресурсов, ускорение рендеринга и обеспечение мгновенной реакции на действия пользователя. В 2026 году производительность рассматривается не только как технический параметр, но и как критический фактор бизнес-успеха и экологической устойчивости (Carbon Intensity).

**Core Web Vitals** — стандартизированные метрики Google для оценки качества пользовательского опыта:
*   **LCP (Largest Contentful Paint):** Скорость загрузки основного контента.
*   **INP (Interaction to Next Paint):** Отзывчивость интерфейса (заменила FID).
*   **CLS (Cumulative Layout Shift):** Визуальная стабильность.
*   *Подробнее:* [web_vitals.md](./web_vitals.md).

## Основные концепции

### Клиентская производительность

Сфокусирована на том, как браузер обрабатывает полученные данные.

| Компонент | Описание |
| :--- | :--- |
| **Критический путь рендеринга** | Построение DOM → Построение CSSOM → Render Tree → Layout → Paint. |
| **Исполнение JavaScript** | Основной потребитель ресурсов CPU. В 2026 году акцент смещен на минимизацию Long Tasks и использование Off-main-thread вычислений. |
| **Приоритизация ресурсов** | Управление очередью загрузки через `fetchpriority` и `loading="lazy"`. |

**Современные методы оптимизации (2026):**
*   **Speculation Rules API:** Программное управление предзагрузкой (Prefetch) и предрендерингом (Prerender) на основе вероятности перехода пользователя.
*   **Priority Hints:** Явное указание высокого приоритета (`fetchpriority="high"`) для LCP-ресурсов.
*   **Partytown / Workerize:** Вынос сторонних скриптов (аналитика) в Web Workers.

### Серверная производительность

Эффективность генерации и доставки ответа сервером (Nginx, Angie, Бэкенд).

*   **Протоколы:** Повсеместное использование **HTTP/3 (QUIC)** для устранения блокировок очереди (HOL Blocking) и **TLS 1.3** для минимизации задержек на хендшейк.
*   **Сжатие:** Переход на **Zstandard (ZSTD)** и **Brotli** как стандарты де-факто, обеспечивающие лучший баланс между степенью сжатия и нагрузкой на CPU.
*   **[Кэширование](./caching.md):** Использование `stale-while-revalidate` и агрессивного кэширования статики с Cache Busting.
*   **[Оптимизация TLS](./tls_optimization.md):** Session Resumption, OCSP Stapling и использование современных шифров.

### Сетевая производительность

Минимизация влияния физических ограничений среды передачи.

*   **Latency (RTT):** Главный враг производительности. Решается через **CDN (Content Delivery Network)** и размещение Edge-узлов максимально близко к пользователю.
*   **Early Hints (103):** Позволяет браузеру начать загрузку критических ресурсов (CSS, шрифты), пока сервер еще генерирует основной HTML-ответ.
*   **Пропускная способность:** Оптимизация размера ресурсов (изображения AVIF/WebP v2, минификация кода).

## Практические сценарии

### Методология анализа

1.  **Сбор полевых данных (RUM):** Анализ реального опыта пользователей через Chrome User Experience Report (CrUX).
2.  **Лабораторное тестирование:** Использование [Chrome DevTools](./chrome_devtools.md) и [WebPageTest](./webpagetest.md) для глубокой диагностики в контролируемой среде.
3.  **Автоматизированный аудит:** Интеграция Lighthouse CI и [PageSpeed Insights](./pagespeed_insights.md) в CI/CD пайплайн.

### Стратегия приоритизации (Impact vs Effort)

| Проблема | Метрика | Приоритет | Решение |
| :--- | :--- | :--- | :--- |
| Медленный TTFB | LCP, FCP | **Критический** | CDN, кэширование, оптимизация БД. |
| Блокирующий JS | INP, TBT | **Высокий** | Code splitting, `async/defer`, Speculation Rules. |
| Нестабильная верстка | CLS | **Высокий** | Резервирование места (aspect-ratio), оптимизация шрифтов. |
| Огромные изображения | LCP, Трафик | **Средний** | Современные форматы, адаптивные размеры. |

### Устойчивая производительность (Eco-performance)

В 2026 году оптимизация производительности напрямую связана с экологией. Быстрый код потребляет меньше циклов CPU, что снижает энергопотребление дата-центров и устройств пользователей. Цель — минимизировать "цифровой углеродный след" через эффективные алгоритмы и сжатие.
