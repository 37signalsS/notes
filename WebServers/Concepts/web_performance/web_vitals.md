# Web Vitals — ключевые метрики пользовательского опыта

---
**Reliability Score: 10/10** (SSoT + Проверено по обновлениям Google/Lighthouse 2026)
---

## Определения

**Web Vitals** — инициатива Google по стандартизации ключевых метрик, отражающих качество пользовательского опыта при загрузке и взаимодействии с веб-страницей.

**Core Web Vitals (основные веб-метрики)** — подмножество Web Vitals, используемое Google в качестве основного сигнала ранжирования (включая AI Overviews). Включает три ключевых показателя: LCP, INP и CLS.

**RUM (Real User Monitoring — мониторинг реальных пользователей)** — методология сбора метрик непосредственно от пользователей в продуктивной среде (полевые данные). Противопоставляется лабораторным данным (Lab Data).

## Основные концепции

### Основные метрики (Core Web Vitals)

#### Largest Contentful Paint (LCP — отрисовка самого крупного контента)

**Что измеряет:** время с начала загрузки страницы до момента отрисовки самого большого видимого элемента контента (изображения, видео-постера или текстового блока) в области просмотра. Отражает воспринимаемую скорость загрузки основного содержимого.

**Пороговые значения (актуально с марта 2026):**

| Оценка | Значение |
| :--- | :--- |
| Хорошо | < 2.0 с |
| Требует улучшения | 2.0 – 4.0 с |
| Плохо | > 4.0 с |

**Фазы LCP (Lighthouse 13+):**
Для точной диагностики Lighthouse разделяет LCP на 4 под-части:
1. **TTFB (Time to First Byte):** время до получения первого байта HTML.
2. **Resource Load Delay:** время между TTFB и началом загрузки LCP-ресурса.
3. **Resource Load Duration:** время загрузки самого ресурса.
4. **Element Render Delay:** время от завершения загрузки до фактической отрисовки.

**Ключевые факторы влияния:** медленное время ответа сервера, ресурсы CSS и JavaScript, блокирующие рендеринг, отсутствие приоритезации (Fetch Priority), неоптимизированные изображения.

**Оптимизация:** использование `fetchpriority="high"` для LCP-изображений, предварительная загрузка (preload), Critical CSS, сжатие AVIF/WebP.

#### Interaction to Next Paint (INP — взаимодействие до следующей отрисовки)

**Что измеряет:** задержку между действием пользователя (клик, касание, нажатие клавиши) и следующим визуальным обновлением интерфейса. Отражает общую отзывчивость страницы на протяжении всего сеанса.

**Пороговые значения:**

| Оценка | Значение |
| :--- | :--- |
| Хорошо | < 200 мс |
| Требует улучшения | 200 – 500 мс |
| Плохо | > 500 мс |

**История:** INP полностью заменила метрику FID (First Input Delay) в марте 2024 года. В отличие от FID, которая учитывала только первое взаимодействие, INP анализирует все действия за сеанс и фиксирует наихудший результат.

**Целостный сигнал:** В 2026 году Google перешел к оценке CWV как совокупного показателя. Успешное прохождение порогов всех трех метрик критично для ранжирования в AI-ответах (SGE).

**Ключевые факторы влияния:** длительные задачи JavaScript (Long Tasks > 50 мс), перегрузка основного потока, сложные вычисления макета.

**Оптимизация:** разделение длинных задач (Yielding to Main Thread), использование Web Workers, минимизация сторонних скриптов (GTM, аналитика).

#### Cumulative Layout Shift (CLS — совокупное смещение макета)

**Что измеряет:** суммарную величину всех непредвиденных сдвигов элементов макета. Оценивает визуальную стабильность интерфейса — отсутствие раздражающих «прыжков» контента.

**Пороговые значения:**

| Оценка | Значение |
| :--- | :--- |
| Хорошо | < 0.1 |
| Требует улучшения | 0.1 – 0.25 |
| Плохо | > 0.25 |

**Ключевые факторы влияния:** изображения и видео без атрибутов `width`/`height`, динамически подгружаемая реклама, шрифты (FOIT/FOUT).

**Оптимизация:** использование CSS-свойства `aspect-ratio`, резервирование места под баннеры, `font-display: swap` в сочетании с подстройкой размеров шрифта (size-adjust).

### Дополнительные метрики (Лабораторные данные)

#### First Contentful Paint (FCP — первая отрисовка контента)

Время до появления на экране первого элемента контента. Хорошо — менее 1.8 с.

#### Total Blocking Time (TBT — общее время блокировки)

Суммарное время блокировки основного потока между FCP и моментом достижения интерактивности. Хорошо — менее 200 мс. Критически коррелирует с INP в лабораторных тестах.

#### Speed Index (индекс скорости)

Отражает скорость визуального наполнения страницы. Рассчитывается через анализ видеозаписи загрузки.

### Оценка производительности (Performance Score)

Рассчитывается Lighthouse как взвешенная сумма метрик. В Lighthouse 13+ фокус смещен на диагностические "Инсайты" (Insights).

**Влияние метрик на оценку (Lighthouse 13+):**

| Метрика | Вес |
| :--- | :--- |
| LCP | 22% |
| INP | 22% |
| CLS | 15% |
| TBT | 15% |
| FCP | 10% |
| Speed Index | 10% |

## Практические сценарии

### Измерение метрик в рабочей среде (RUM)

1. **Chrome UX Report (CrUX)** — данные реальных пользователей Chrome. Используются Google для ранжирования.
2. **PageSpeed Insights API** — позволяет получать данные CrUX программно.
3. **Библиотека web-vitals** — стандарт для сбора данных в собственную аналитику.

```javascript
import {onLCP, onINP, onCLS} from 'web-vitals';

// Логирование Core Web Vitals
onLCP(console.log);
onINP(console.log);
onCLS(console.log);
```

### Локальная диагностика в Chrome DevTools

1. Вкладка **Performance** → режим **Insights** (Lighthouse 13+).
2. Анализ **LCP Discovery**: показывает, был ли LCP-элемент обнаружен в HTML или через JS/CSS.
3. Анализ **CLS Culprits**: список конкретных элементов, вызвавших сдвиг макета.

Подробнее: [Chrome DevTools — вкладка Performance](./chrome_devtools.md).

### Приоритизация улучшений

| Проблема | Влияние | Приоритет |
| :--- | :--- | :--- |
| LCP > 2.0 с | Скорость основного контента | Критический |
| INP > 200 мс | Отзывчивость интерфейса | Критический |
| CLS > 0.1 | Стабильность макета | Высокий |
| TBT > 200 мс | Блокировка основного потока | Средний |

## Дополнительная информация

### Лабораторные и полевые данные (Lab vs Field)

| Характеристика | Полевые данные (CrUX/RUM) | Лабораторные данные (Lighthouse) |
| :--- | :--- | :--- |
| Источник | Реальные пользователи | Контролируемая эмуляция |
| Влияние на SEO | Прямое (фактор ранжирования) | Косвенное (инструмент отладки) |
| Воспроизводимость | Низкая (вариативность условий) | Высокая (стабильный тест) |

### Рекомендации 2026 года

- **AI Overviews**: Низкие показатели CWV могут привести к исключению страницы из генеративных ответов Google.
- **Приоритет INP**: В современных SPA-приложениях INP стал основной метрикой, так как он замеряет взаимодействие на протяжении всего времени работы со страницей, а не только загрузку.
- **Speculative Rules**: Используйте API спекулятивных правил для предзагрузки страниц, к которым пользователь может перейти, что дает "мгновенные" показатели LCP.
