# Web Vitals — ключевые метрики пользовательского опыта

## Определения

**Web Vitals** — инициатива Google по стандартизации ключевых метрик, отражающих качество пользовательского опыта при загрузке и взаимодействии с веб-страницей.

**Core Web Vitals (основные веб-метрики)** — подмножество Web Vitals, используемое Google в качестве сигнала ранжирования в поисковой выдаче. Включает три ключевых показателя: LCP, INP и CLS.

**RUM (Real User Monitoring — мониторинг реальных пользователей)** — методология сбора метрик непосредственно от пользователей в продуктивной среде. Противопоставляется лабораторным данным (Lab Data).

## Основные концепции

### Основные метрики (Core Web Vitals)

#### Largest Contentful Paint (LCP — отрисовка самого крупного контента)

**Что измеряет:** время с начала загрузки страницы до момента отрисовки самого большого видимого элемента контента (изображения, видео-постера или текстового блока) в области просмотра. Этот показатель отражает воспринимаемую пользователем скорость загрузки основного содержимого.

**Пороговые значения:**

| Оценка | Значение |
| :--- | :--- |
| Хорошо | < 2.5 с |
| Требует улучшения | 2.5 – 4.0 с |
| Плохо | > 4.0 с |

**Ключевые факторы влияния:** медленное время ответа сервера (TTFB — Time to First Byte), ресурсы CSS (Cascading Style Sheets) и JavaScript, блокирующие рендеринг, неоптимизированные изображения, отсутствие кэширования LCP-элемента.

**Оптимизация:** предварительная загрузка (preload) критических ресурсов, рендеринг на стороне сервера (SSR), настройка HTTP-кэширования, устранение блокирующих ресурсов, оптимизация веб-шрифтов.

#### Interaction to Next Paint (INP — взаимодействие до следующей отрисовки)

**Что измеряет:** задержку между действием пользователя (клик, касание, нажатие клавиши) и следующим визуальным обновлением интерфейса. Отражает общую отзывчивость страницы на протяжении всего сеанса работы пользователя.

**Пороговые значения:**

| Оценка | Значение |
| :--- | :--- |
| Хорошо | < 200 мс |
| Требует улучшения | 200 – 500 мс |
| Плохо | > 500 мс |

**История:** INP заменила метрику FID (First Input Delay — задержка первого ввода) в марте 2024 года. В отличие от FID, которая учитывала только первое взаимодействие, INP анализирует все действия за сеанс и фиксирует наихудший результат.

**Порог восприятия:** задержка менее 100 мс воспринимается пользователем как мгновенная реакция системы.

**Ключевые факторы влияния:** длительные задачи JavaScript (Long Tasks > 50 мс), перегрузка основного потока (main thread), сложные вычисления макета (layout thrashing).

**Оптимизация:** разделение длинных задач на части, использование Web Workers для тяжелых вычислений, оптимизация обработчиков событий, минимизация принудительных пересчетов макета.

#### Cumulative Layout Shift (CLS — совокупное смещение макета)

**Что измеряет:** суммарную величину всех непредвиденных сдвигов элементов макета за все время жизни страницы. Оценивает визуальную стабильность интерфейса — отсутствие раздражающих «прыжков» контента при загрузке.

**Пороговые значения:**

| Оценка | Значение |
| :--- | :--- |
| Хорошо | < 0.1 |
| Требует улучшения | 0.1 – 0.25 |
| Плохо | > 0.25 |

**Расчет:** каждый сдвиг оценивается как произведение доли затронутой области экрана на расстояние сдвига. CLS является суммой всех таких оценок.

**Ключевые факторы влияния:** медиафайлы (изображения, видео) без указания размеров (width/height), динамически подгружаемый контент (реклама, виджеты), проблемы со шрифтами (FOIT — Flash of Invisible Text / FOUT — Flash of Unstyled Text), анимации, влияющие на геометрию блоков.

**Оптимизация:** явное указание размеров для медиа-элементов, резервирование места под динамический контент, использование `font-display: swap`, реализация анимаций через свойства `transform` и `opacity`.

### Дополнительные метрики (Лабораторные данные)

#### First Contentful Paint (FCP — первая отрисовка контента)

Время от начала загрузки до момента появления на экране первого элемента контента (текста, изображения или непустого холста). Отражает скорость первичного визуального отклика системы.

**Пороговые значения:** хорошо — менее 1.8 с, требует улучшения — 1.8–3.0 с, плохо — более 3.0 с.

#### Total Blocking Time (TBT — общее время блокировки)

Суммарное время, в течение которого основной поток браузера был заблокирован между FCP и моментом достижения интерактивности. Блокировкой считается выполнение любой задачи JavaScript дольше 50 мс.

**Пороговые значения:** хорошо — менее 200 мс, требует улучшения — 200–600 мс, плохо — более 600 мс.

#### Time to Interactive (TTI — время до интерактивности)

Время, необходимое странице для перехода в состояние полной интерактивности: когда контент отображен, обработчики событий зарегистрированы и страница стабильно отвечает на действия пользователя в течение 50 мс.

#### Speed Index (индекс скорости)

Интегральный показатель, отражающий скорость визуального наполнения видимой части страницы контентом. Рассчитывается на основе анализа видеозаписи процесса загрузки.

### Оценка производительности (Performance Score)

Обобщенная оценка от 0 до 100, рассчитываемая инструментом Lighthouse как взвешенная сумма различных метрик. Веса показателей могут меняться в разных версиях инструмента.

**Влияние метрик на оценку (Lighthouse 12+):**

| Метрика | Вес |
| :--- | :--- |
| LCP | 22% |
| INP | 22% |
| CLS | 15% |
| TBT | 15% |
| FCP | 10% |
| Speed Index | 10% |

## Практические сценарии

### Измерение метрик в рабочей среде (RUM)

1. **Chrome UX Report (CrUX)** — открытый набор данных о реальном опыте пользователей браузера Chrome. Доступен через BigQuery и [PageSpeed Insights API](./pagespeed_insights.md).
2. **Библиотека web-vitals** — позволяет собирать метрики и отправлять их в системы аналитики.

```javascript
import {onLCP, onINP, onCLS} from 'web-vitals';

onLCP(console.log);
onINP(console.log);
onCLS(console.log);
```

1. **Google Analytics 4** — поддерживает интеграцию с библиотекой web-vitals для создания кастомных отчетов по производительности.

### Локальная диагностика в Chrome DevTools

1. Откройте инструменты разработчика (F12) → вкладка **Performance**.
2. Установите параметры **Disable Cache** и ограничение процессора (**CPU Throttling 4x**) для имитации среднего устройства.
3. Запустите запись (**Record**), обновите страницу и выполните типичные действия пользователя.
4. После остановки записи проанализируйте метрики Web Vitals в верхней части профиля. При нажатии на метрику (например, LCP) браузер подсветит соответствующий элемент на странице.

Подробнее: [Chrome DevTools — вкладка Performance](./chrome_devtools.md).

### Приоритизация улучшений

| Проблема | Влияние | Приоритет |
| :--- | :--- | :--- |
| LCP > 2.5 с | Воспринимаемая скорость загрузки | Высокий |
| INP > 200 мс | Ощущение отзывчивости | Высокий |
| CLS > 0.1 | Визуальный комфорт | Высокий |
| TBT > 200 мс | Готовность к взаимодействию | Средний |
| FCP > 1.8 с | Начальный отклик | Средний |

## Дополнительная информация

### Лабораторные и полевые данные (Lab vs Field)

| Характеристика | Полевые данные (Field Data/RUM) | Лабораторные данные (Lab Data) |
| :--- | :--- | :--- |
| Источник | Реальные пользователи (разные сети и устройства) | Фиксированное окружение разработчика |
| Состав метрик | LCP, INP, CLS (Core Web Vitals) | Полный набор: LCP, INP, CLS, FCP, TBT, TTI, Speed Index |
| Воспроизводимость | Низкая (агрегированная статистика) | Высокая (стабильный повторяемый тест) |
| Влияние на SEO | Прямое (через данные CrUX) | Косвенное (помогает в диагностике) |
| Инструменты | CrUX, Search Console, RUM-системы | Lighthouse, DevTools, [WebPageTest](./webpagetest.md) |

### Рекомендации и лучшие практики

- **Приоритет полевым данным**: для оценки влияния на SEO (Search Engine Optimization) и понимания реального опыта пользователей всегда ориентируйтесь на данные RUM.
- **Синтетика для отладки**: используйте лабораторные тесты для быстрой проверки гипотез и контроля регрессий производительности перед деплоем.
- **Динамический контент**: учитывайте, что элементы вроде рекламных баннеров или бесконечной прокрутки могут значительно искажать показатели CLS и LCP.
