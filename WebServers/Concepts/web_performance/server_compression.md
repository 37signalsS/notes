# Компрессия контента на веб-сервере

## Определения

**Компрессия (сжатие) контента** — процесс уменьшения объёма текстовых данных (HTML, CSS, JS, SVG, JSON) перед передачей клиенту. Один из самых эффективных способов сокращения объёма передаваемых данных и ускорения загрузки веб-страниц.

Основные алгоритмы:

- **Gzip** — универсально поддерживаемый, используется как запасной вариант.
- **Brotli** — современный алгоритм от Google, обеспечивает лучшее сжатие.
- **ZSTD (Zstandard)** — алгоритм от Facebook, исключительно высокая скорость сжатия/распаковки.

## Базовые концепции

### Типы компрессии

| Тип | Описание | Когда применять |
| :--- | :--- | :--- |
| **Статическая** | Файлы сжимаются заранее (во время сборки) | Статические ресурсы (CSS, JS, шрифты) |
| **Динамическая** | Контент сжимается «на лету» при каждом запросе | Динамический контент (HTML, JSON API) |

### Content Negotiation

Браузер отправляет заголовок `Accept-Encoding: gzip, deflate, br, zstd`. Сервер выбирает наиболее предпочтительный алгоритм и отвечает с `Content-Encoding`.

→ **[Оптимизация сжатия в Nginx](../../Nginx/Performance/nginx_compression.md)** — SSoT по теме компрессии

**Краткие рекомендации:**

- **Статика:** Brotli (уровень 11) + gzip fallback (уровень 6). Не создавайте `.zst` для статики — Nginx отдаст ему приоритет перед `.br`, что хуже по сжатию.
- **Динамика:** ZSTD (уровень 4–5) + Brotli fallback (4–5) + gzip fallback (3–4).
- **Gzip** — запасной вариант для браузеров без поддержки Brotli/ZSTD.
