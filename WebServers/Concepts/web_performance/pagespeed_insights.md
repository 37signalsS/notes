# PageSpeed Insights (PSI)

## Определения

**PageSpeed Insights (PSI)** — бесплатный инструмент от Google для анализа производительности веб-страниц на мобильных и десктопных устройствах. PSI объединяет в себе данные о реальном опыте пользователей (Field Data) и результаты автоматизированного лабораторного аудита (Lab Data).

**CrUX (Chrome User Experience Report)** — открытый набор данных о реальном опыте пользователей браузера Chrome, который служит источником полевых данных для PSI.

**Lighthouse** — инструмент с открытым исходным кодом для автоматизированного аудита качества веб-страниц, обеспечивающий лабораторные данные в отчетах PSI.

## Основные концепции

### Полевые данные против Лабораторных (Field vs Lab)

PageSpeed Insights уникален тем, что предоставляет два дополняющих друг друга набора данных в одном отчете.

| Тип данных | Источник | Характеристики |
| :--- | :--- | :--- |
| **Полевые данные (Field Data / CrUX)** | Реальные пользователи за последние 28 дней | Отражают реальный опыт, влияют на SEO, обновляются медленно. |
| **Лабораторные данные (Lab Data / Lighthouse)** | Один синтетический запуск на серверах Google | Помогают в отладке, предоставляют список рекомендаций (Opportunities), обновляются мгновенно. |

Подробное сравнение методологий доступно в разделе: **[Лабораторные и полевые данные](../../../WebServers/Concepts/web_performance/web_vitals.md#лабораторные-и-полевые-данные-lab-vs-field)**.

### Уровни агрегации данных

PSI может показывать данные на двух уровнях:

1. **URL (Этот URL):** данные конкретной страницы. Если данных CrUX для страницы недостаточно, этот раздел будет пуст.
2. **Origin (Весь домен):** агрегированные данные по всем страницам домена. Позволяет оценить общую производительность сайта, даже если конкретная новая страница еще не попала в CrUX.

### Оценка Core Web Vitals (Core Web Vitals Assessment)

В верхней части отчета PSI выводится вердикт: **Passed (Пройдено)** или **Failed (Не пройдено)**.

- Оценка основывается на 75-м перцентиле полевых данных за последние 28 дней.
- Учитываются три основные метрики: LCP, INP и CLS.
- Описание и пороги метрик: **[Основные метрики Core Web Vitals](../../../WebServers/Concepts/web_performance/web_vitals.md#основные-метрики-core-web-vitals)**.

## Практические сценарии

### Сценарий 1: Быстрый аудит производительности

1. Введите URL страницы на сайте [PageSpeed Insights](https://pagespeed.web.dev/).
2. Проверьте раздел **Field Data** (если доступен), чтобы понять, проходят ли реальные пользователи пороги Core Web Vitals.
3. Изучите раздел **Lab Data** для поиска технических проблем. Особое внимание уделите блоку **Opportunities** (Возможности) — Google рассчитывает потенциальную экономию времени для каждой рекомендации.
4. Сравните результаты для Mobile и Desktop. Мобильные показатели обычно хуже из-за ограничений процессора и сети.

### Сценарий 2: Использование API для мониторинга

PageSpeed Insights API позволяет автоматизировать сбор метрик и интегрировать их в CI/CD (Continuous Integration / Continuous Deployment) или системы мониторинга.

**Пример запроса (curl):**

```bash
# Получение данных для мобильной версии с использованием API ключа
curl "https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=https://example.com&strategy=mobile&key=YOUR_API_KEY"
```

**Ключевые параметры API:**

- `strategy`: `mobile` или `desktop`.
- `category`: по умолчанию `performance`, можно добавить `seo`, `accessibility`, `best-practices`.
- `locale`: язык отчета.

### Сценарий 3: Интерпретация расхождений данных

Часто результаты Lighthouse (Lab) не совпадают с CrUX (Field).

- **Lighthouse лучше, чем CrUX:** возможно, ваши реальные пользователи используют старые устройства или медленную сеть, в то время как серверы Google имеют отличную связность.
- **CrUX лучше, чем Lighthouse:** вероятно, ваша страница хорошо оптимизирована для повторных визитов (кэширование), которые CrUX учитывает, а Lighthouse — нет (всегда имитирует холодную загрузку).
