# Настройка HTTPS с помощью Let's Encrypt и Certbot

## Определения

**Let's Encrypt** — некоммерческий центр сертификации, предоставляющий бесплатные SSL/TLS сертификаты. Для автоматизации выдачи используется протокол **ACME (Automated Certificate Management Environment)** (RFC 8555).

**ACME** — протокол автоматизированного управления сертификатами, позволяющий без участия человека получать, обновлять и отзывать TLS-сертификаты.

**Certbot** — инструмент для автоматического получения и обновления сертификатов Let's Encrypt. Поддерживает плагины для веб-серверов (Nginx, Apache) и метод webroot.

**Webroot** — метод авторизации ACME, при котором проверочный файл размещается в директории `.well-known/acme-challenge/` на веб-сервере.

### Типы ключей: ECDSA vs RSA

**ECDSA (Elliptic Curve Digital Signature Algorithm)** — тип ключа на основе эллиптических кривых.

- **Преимущества:** Выше производительность сервера (быстрое симметричное шифрование), меньший размер ключа
- **Недостатки:** Поддержка ниже на устаревших клиентах
- **Certbot 3.x:** ECDSA — тип ключа по умолчанию

**RSA (Rivest-Shamir-Adleman)** — классический тип ключа.

- **Преимущества:** Отличная совместимость со всеми клиентами, быстрее для клиента при рукопожатии
- **Недостатки:** Медленнее для сервера, больший размер ключа
- **Рекомендация:** Использовать параллельно с ECDSA для максимальной совместимости

> **Best Practice:** Развертывание двух пар сертификатов (ECDSA + RSA) позволяет серверу выбирать оптимальный вариант: ECDSA для современных клиентов, RSA для обратной совместимости.

### Рейтлимиты Let's Encrypt

**Важно:** Let's Encrypt применяет строгие ограничения на количество запросов.

| Лимит | Значение |
| :--- | :--- |
| Duplicate Certificate Limit | 50 сертификатов на домен в неделю |
| Registration Rate Limit | 5 регистраций аккаунта на IP в час |
| Verification Rate Limit | 30 проверок авторизации на домен в час |

**Рекомендация:** Перед получением боевого сертификата используйте **staging-окружение** или **dry-run** для тестирования конфигурации.

## Основные концепции

### Методы авторизации (Challenges)

**HTTP-01** — создание проверочного файла в `.well-known/acme-challenge/`.

- Требует открытый 80 порт
- Не поддерживает wildcard-сертификаты
- Подходит для обычных доменных сертификатов

**DNS-01** — создание TXT-записи `_acme-challenge.example.com` в DNS.

- Поддерживает wildcard-сертификаты (`*.example.com`)
- Не требует доступности сервера извне
- Требует API DNS-провайдера или ручной записи

### Webroot авторизация

При использовании метода webroot необходимо настроить веб-сервер для обработки запросов к `.well-known`:

```nginx
server {
    listen 80;
    server_name example.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        # Основная конфигурация сайта
    }
}
```

Certbot создаст проверочный файл в указанной директории, и CA проверит доступность по HTTP.

### Рейтлимитинг и диагностика ошибок

**Важно:** При работе с Let's Encrypt применяются **рейтлимиты** (ограничения на количество запросов). В отличие от локальной конфигурации веб-сервера, где можно бесконечно экспериментировать с настройками, некорректная конфигурация при запросе сертификатов может привести к временной блокировке.

**Основные лимиты Let's Encrypt:**

- **50 сертификатов на домен в неделю** (Duplicate Certificate Limit)
- **5 запросов на регистрацию аккаунта** на IP в час
- **30 запросов на проверку авторизации** на домен в час

**Рекомендация:** Перед получением боевого сертификата используйте **staging-окружение** или **dry-run** для тестирования конфигурации:

```bash
# Тестовый запуск (staging)
certbot --staging --nginx -d example.com

# Dry-run для проверки процесса обновления
certbot renew --dry-run

# После успешного тестирования — боевой запуск
certbot --nginx -d example.com
```

**Диагностика ошибок:**

- **DNS ошибка:** Дождитесь обновления DNS-записей (может занять несколько минут)
- **404 Not Found:** Проверьте конфигурацию Location для `.well-known`, убедитесь что конфиг перезапущен
- **Rate limit exceeded:** Прекратите попытки, устраните причину ошибки, дождитесь сброса лимита

> **Важно:** Не повторяйте команду получения сертификата при ошибке без устранения причины — это быстро приведёт к блокировке. Сначала диагностируйте проблему (DNS, конфиг, доступность портов).

## Практические Сценарии

### 2.1. Установка Certbot

* **Debian/Ubuntu (для Nginx):**

    ```bash
    apt install -y certbot python3-certbot-nginx
    ```

* **CentOS/RHEL (для Nginx):**

    ```bash
    # В современных дистрибутивах (CentOS 8+, RHEL 8+) используется dnf
    dnf install -y epel-release
    dnf install -y certbot-nginx
    ```

### 2.2. Предварительная настройка Nginx

Certbot должен найти правильный `server_name` в конфигурации Nginx, чтобы автоматически настроить SSL. Убедитесь, что в файле конфигурации вашего сайта (например, `/etc/nginx/sites-available/example.com.conf`) директива `server_name` указана корректно. Детали базовой настройки можно найти в заметке [Установка и базовая настройка Nginx](../Nginx/Core/nginx_setup.md).

```nginx
server_name example.com www.example.com;
```

После проверки синтаксиса (`nginx -t`) перезагрузите Nginx:

```bash
systemctl reload nginx
```

### 2.3. Получение SSL-сертификата

**Базовый сценарий (один сертификат):**

Запустите Certbot с плагином для Nginx:

```bash
certbot --nginx -d example.com -d www.example.com
```

* При первом запуске потребуется указать email и согласиться с условиями.
* Certbot проверит, что вы контролируете домен.
* Вам будет предложено выбрать, делать ли автоматический редирект с HTTP на HTTPS. Рекомендуется выбрать `Redirect` (вариант 2).

После успешного выполнения Certbot сохранит сертификаты (обычно в `/etc/letsencrypt/live/example.com/`) и автоматически обновит конфигурацию Nginx.

**Продвинутый сценарий (ECDSA + RSA параллельно):**

Для максимальной совместимости и производительности рекомендуется получить два типа сертификатов:

```bash
# ECDSA сертификат (по умолчанию в Certbot 3.x)
certbot certonly --webroot -w /var/www/certbot \
    --key-type ecdsa \
    -d example.com -d www.example.com

# RSA сертификат (для обратной совместимости)
certbot certonly --webroot -w /var/www/certbot \
    --key-type rsa --rsa-key-size 2048 \
    -d example.com -d www.example.com
```

**Настройка Nginx для двух сертификатов:**

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;

    # ECDSA сертификат (приоритетный)
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain-ecdsa.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey-ecdsa.pem;

    # RSA сертификат (резервный)
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain-rsa.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey-rsa.pem;

    # Nginx автоматически выберет подходящий сертификат
}
```

> **Примечание:** Certbot создаёт файлы с суффиксами `-ecdsa` и `-rsa` при использовании разных типов ключей. Символические ссылки в директории `live/` всегда указывают на актуальные версии.

### 2.4. Настройка автоматического обновления

Сертификаты Let's Encrypt действительны 45 дней. Certbot настраивает автоматическое продление.

* **Debian/Ubuntu:** Пакет `certbot` создает таймер `systemd` (`certbot.timer`), который запускается дважды в день и обновляет сертификаты, если до истечения срока их действия осталось менее 30 дней.
    Проверить статус таймера:

    ```bash
    systemctl status certbot.timer
    ```

* **CentOS:** Необходимо добавить задачу в `cron`.
    Откройте `crontab` для редактирования:

    ```bash
    crontab -e
    ```

    Добавьте строку для ежедневной проверки в 4:10 утра:

    ```
    10 4 * * * /usr/bin/certbot renew --quiet
    ```

## Дополнительная информация

### Wildcard-сертификаты

**Wildcard-сертификат** (`*.example.com`) защищает основной домен и все поддомены первого уровня.

**Ограничение:** Certbot поддерживает wildcard только через DNS-01 challenge, что требует:
- API DNS-провайдера (Cloudflare, AWS Route53, etc.)
- Или ручной установки TXT-записей (не автоматизируется)

Для wildcard-сертификатов рекомендуется использовать **[acme.sh](./acme_sh.md)** с поддержкой множества DNS API.

### Альтернативные инструменты

**acme.sh** — легковесная альтернатива Certbot с широкой поддержкой DNS API.

- Написан на shell (bash)
- Поддерживает 100+ DNS API провайдеров
- Автоматическая установка wildcard-сертификатов
- Встроенная поддержка ECDSA/RSA

Подробное руководство: **[Использование acme.sh](./acme_sh.md)**.

**Модуль ACME в Angie:** Встроенная поддержка ACME в веб-сервере Angie. См. **[ACME в Angie](../Angie/angie_acme_module.md)**.

### Проверка и диагностика

```bash
# Проверка процесса обновления (dry-run)
certbot renew --dry-run

# Статус таймера автоматического обновления
systemctl status certbot.timer

# Просмотр установленных сертификатов
certbot certificates

# Детальная информация о сертификате
openssl x509 -in /etc/letsencrypt/live/example.com/fullchain.pem -text -noout
```

> **Важно:** Certbot отвечает за *получение* сертификатов. За *оптимальное использование* этих сертификатов отвечает Nginx. Убедитесь, что конфигурация TLS/SSL вашего сервера соответствует лучшим практикам безопасности и производительности. Подробное руководство находится в заметке [Оптимальная настройка TLS/SSL в Nginx](../Nginx/Security/TLS_SSL/nginx_tls_ssl_overview.md).
