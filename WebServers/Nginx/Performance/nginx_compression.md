# Оптимизация сжатия в Nginx (Gzip, Brotli, Zstandard)

## Определения

**Сжатие данных** — процесс уменьшения объема передаваемых данных с использованием специализированных алгоритмов, что напрямую влияет на скорость загрузки веб-страниц (LCP, FCP), экономию трафика и снижение нагрузки на сетевую инфраструктуру. Это ключевой элемент [общего руководства по оптимизации производительности](../../Concepts/web_performance/overview.md).

Основные алгоритмы сжатия в экосистеме Nginx/Angie:

*   **Gzip (DEFLATE)** — универсальный стандарт с поддержкой 100% браузеров. Является обязательным fallback-вариантом.
*   **Brotli (`br`)** — алгоритм от Google с использованием статического словаря. Обеспечивает на 15–20% лучшее сжатие текстовых данных, чем Gzip, при схожей скорости декомпрессии.
*   **Zstandard (Zstd)** — высокопроизводительный алгоритм от Meta (Facebook). Лидер по скорости сжатия и декомпрессии, что делает его идеальным для динамического контента (API, SSR).

## Основные концепции

В Nginx и его форке Angie сжатие реализуется через систему фильтров, которые обрабатывают тело ответа перед отправкой клиенту.

### Типы реализации сжатия

1.  **Динамическое сжатие (on-the-fly):**
    *   **Принцип:** Сервер сжимает данные в момент поступления запроса.
    *   **Применение:** HTML-страницы, JSON API, персонализированный контент.
    *   **Нюанс:** Потребляет CPU на каждый запрос. Является блокирующей операцией для рабочего процесса (worker), что может увеличить Time to First Byte (TTFB).
2.  **Статическое сжатие (pre-compressed):**
    *   **Принцип:** Файлы сжимаются заранее (на этапе сборки или CI/CD) и сохраняются с расширениями `.gz`, `.br` или `.zst`. Nginx отдает их напрямую через системный вызов `sendfile`.
    *   **Применение:** Статические ресурсы (JS, CSS, шрифты, SVG).
    *   **Плюсы:** Минимальная нагрузка на CPU, возможность использования максимальных уровней сжатия (Brotli 11).

### Согласование контента (Content Negotiation)

Процесс выбора алгоритма основан на заголовке `Accept-Encoding`. При наличии нескольких вариантов Nginx выбирает наиболее эффективный в зависимости от весов (q-values) или порядка обработки модулей.

**Важно:** Для корректного кэширования ответов промежуточными прокси-серверами и CDN необходимо всегда включать заголовок `Vary: Accept-Encoding`. В Nginx это делается через директиву `*_vary on;`.

## Практические сценарии

### Настройка Gzip (Базовый уровень)

Gzip встроен в ядро Nginx. Рекомендуется как обязательный минимум.

```nginx
http {
    gzip on;
    # Уровни 3-4 — баланс между CPU и размером для динамики
    gzip_comp_level 4; 
    # Минимальный порог (1024 байта). Сжатие мелких файлов может увеличить их размер.
    gzip_min_length 1024; 
    # Типы данных для сжатия (text/html сжимается всегда)
    gzip_types 
        text/plain 
        text/css 
        application/javascript 
        application/json 
        application/xml
        image/svg+xml;
    # Необходим для работы с CDN/Proxy
    gzip_vary on;
    # Настройка для работы за прокси-серверами
    gzip_proxied any; 
    # Минимальная версия HTTP для сжатия (рекомендуется 1.1)
    gzip_http_version 1.1;
    # Буферы для сжатия (16 буферов по 8k)
    gzip_buffers 16 8k;
}
```

**Разбор `gzip_proxied`:**
*   `any` — сжимать все запросы от прокси.
*   `no-cache`, `no-store`, `private` — сжимать, только если есть соответствующие инструкции Cache-Control (защита конфиденциальных данных).

### Настройка Brotli (Максимальное сжатие статики)

В Angie доступен как нативный модуль. В Nginx требует сборки с `ngx_brotli`.

```nginx
# В Angie загрузка модуля:
load_module modules/ngx_http_brotli_filter_module.so;
load_module modules/ngx_http_brotli_static_module.so;

http {
    brotli on;
    # Уровень 4-5 для динамики, 11 для статики
    brotli_comp_level 5;
    # Использование предварительно сжатых .br файлов
    brotli_static on;
    brotli_types text/plain text/css application/javascript application/json image/svg+xml;
    brotli_vary on;
}
```

### Настройка Zstandard (Высокая производительность)

Zstd является стандартом для высоконагруженных API в 2026 году.

```nginx
load_module modules/ngx_http_zstd_filter_module.so;
load_module modules/ngx_http_zstd_static_module.so;

http {
    zstd on;
    # Уровень 3 — оптимален для динамики (быстрее Gzip при лучшем сжатии)
    zstd_comp_level 3;
    zstd_static on;
    zstd_types text/plain text/css application/javascript application/json image/svg+xml;
    zstd_min_length 256; 
    zstd_vary on;
}
```

## Дополнительная информация

### Сравнение стратегий 2026

| Параметр | Gzip | Brotli | Zstandard |
| :--- | :--- | :--- | :--- |
| **Степень сжатия** | Средняя | **Наивысшая** | Высокая |
| **Скорость сжатия** | Средняя | Низкая (на макс. уровне) | **Экстремальная** |
| **Скорость декомпрессии** | Высокая | Высокая | **Наивысшая** |
| **Основная роль** | Fallback | **Статика** (JS, CSS) | **Динамика** (HTML, API) |

**Рекомендуемая комбинация:**
1.  **Статика:** Предварительное сжатие Brotli 11 + Gzip 6.
2.  **Динамика:** Zstd 3 (при поддержке клиентом) → Gzip 4.

### Безопасность и сжатие

**Атака BREACH:**
Злоумышленник может извлечь секреты (CSRF-токены), анализируя размер сжатого HTTP-ответа.
*   **Защита:** Отключать сжатие (`gzip off;`) в специфических `location`, отдающих чувствительные данные, или использовать маскирование токенов на уровне приложения.

### Оптимизация буферов и I/O

*   **`gzip_buffers`**: Увеличение количества буферов предотвращает сброс промежуточных данных на диск, что критично для больших JSON-ответов.
*   **`tcp_nopush on;`**: В сочетании с `sendfile` позволяет отправлять заголовки ответа и начало сжатого файла в одном TCP-пакете, снижая накладные расходы.

### Проверка эффективности

*   **Заголовки:** `curl -I -H "Accept-Encoding: zstd, br" https://example.com`
*   **Детализация:** Используйте вкладку **Network** в DevTools. Разница между значениями "Size" (объем данных) и "Transferred" (передано по сети) показывает эффективность сжатия.
