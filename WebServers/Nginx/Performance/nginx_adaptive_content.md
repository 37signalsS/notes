# Адаптивная доставка изображений с помощью Nginx

## Определения

**Адаптивная (или условная) доставка изображений** — это техника из [общего руководства по оптимизации веб-производительности](../../Concepts/web_performance/overview.md), при которой сервер отдает различные версии одного и того же изображения в зависимости от возможностей браузера клиента.

Основная цель — отправка изображений в современных форматах, таких как **WebP (Web Picture)** или **AVIF (AV1 Image File Format)**, браузерам, которые их поддерживают, с автоматическим откатом к стандартным форматам (JPEG — Joint Photographic Experts Group, PNG — Portable Network Graphics) для остальных клиентов.

Это позволяет значительно уменьшить объем передаваемого трафика без потери качества, что является важной частью [тюнинга производительности Nginx](nginx_performance_tuning.md).

## Основные концепции

### Механизм работы

1. **Подготовка ресурсов:** На сервере заранее создаются версии изображений в форматах WebP и AVIF. Они размещаются рядом с оригинальными файлами (например, `photo.jpg`, `photo.jpg.webp`, `photo.jpg.avif`).
2. **Запрос клиента:** При запросе ресурса браузер отправляет заголовок `Accept`, в котором перечислены поддерживаемые им MIME-типы (Multipurpose Internet Mail Extensions — многоцелевые расширения почты Интернета).
3. **Логика выбора:** [Nginx](../Core/nginx_overview.md) анализирует заголовок `Accept`. Если браузер заявляет о поддержке `image/webp` или `image/avif`, сервер пытается найти и отдать соответствующий файл.

### Преимущества

* **Экономия трафика:** Современные алгоритмы сжатия обеспечивают на 30–50% меньший размер файла при сопоставимом качестве.
* **Ускорение загрузки:** Меньший объем данных напрямую снижает время до отрисовки страницы.
* **Совместимость:** Старые браузеры продолжают получать стандартные файлы, не испытывая проблем с отображением.

## Практические сценарии

### Шаг 1: Определение поддержки форматов (map)

В блоке `http` конфигурационного файла `nginx.conf` необходимо создать карты для определения поддержки современных форматов на основе заголовка `Accept`.

```nginx
http {
    # Карта для определения поддержки WebP
    map $http_accept $webp_suffix {
        default "";
        "~*webp" ".webp";
    }

    # Карта для определения поддержки AVIF
    map $http_accept $avif_suffix {
        default "";
        "~*avif" ".avif";
    }
}
```

Здесь переменные `$webp_suffix` и `$avif_suffix` принимают значение расширения файла, если соответствующая строка найдена в заголовке `Accept`.

### Шаг 2: Настройка выдачи файлов (try_files)

В блоке `server` используется директива `try_files` для проверки наличия оптимизированных версий в порядке приоритета.

```nginx
server {
    # Обработка стандартных форматов изображений
    location ~* \.(jpe?g|png|gif)$ {
        # Приоритет: 1. AVIF, 2. WebP, 3. Оригинал
        try_files $uri$avif_suffix $uri$webp_suffix $uri =404;

        # Добавление заголовка Vary для корректного кэширования
        add_header Vary "Accept";
        
        # Информационный заголовок для отладки (опционально)
        add_header X-Image-Format $avif_suffix$webp_suffix;
    }
}
```

**Пример обработки:**
При запросе URL (Uniform Resource Locator — единый указатель ресурса) `/images/cover.jpg` Nginx выполнит поиск в следующем порядке:

1. `/images/cover.jpg.avif` (если поддерживается браузером).
2. `/images/cover.jpg.webp` (если AVIF не найден или не поддерживается).
3. `/images/cover.jpg` (оригинальный файл).

Подробную информацию о работе с локациями можно найти в разделах [основы директивы location](../Core/Location/basics.md) и [правила rewrite и try_files](../Core/nginx_rewrite_rules_and_try_files.md).

## Дополнительная информация

### Критическая важность заголовка Vary

При использовании адаптивной доставки контента **обязательно** добавление заголовка `Vary: Accept`. Он сообщает промежуточным узлам, таким как CDN (Content Delivery Network — сеть доставки контента) и прокси-серверы, что содержимое ответа зависит от заголовка `Accept` в запросе.

Без этого заголовка возникает риск "отравления кэша":

1. Старый браузер запрашивает `image.jpg`, CDN сохраняет JPEG-версию.
2. Новый браузер запрашивает тот же URL, и CDN отдает ему JPEG из кэша, игнорируя поддержку WebP.

### Именование файлов

Существует два подхода к именованию:

1. **Суффиксный (`image.jpg.webp`):** Самый простой и универсальный. Не требует изменения URI (Uniform Resource Identifier — единый идентификатор ресурса) через регулярные выражения.
2. **Замещающий (`image.webp`):** Требует более сложной логики в `try_files` и регулярных выражениях для сопоставления имен.

Рекомендуется использовать суффиксный метод для минимизации ошибок конфигурации.
