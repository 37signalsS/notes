# Адаптивная доставка изображений в Nginx (AVIF, WebP, JPEG XL)

## Определения

**Адаптивная (условная) доставка изображений** — стратегия оптимизации [производительности веб-приложений](../../Concepts/web_performance/overview.md), при которой сервер автоматически выбирает и отдает наиболее эффективный формат изображения в зависимости от возможностей браузера клиента.

Основная цель — минимизация объема передаваемого трафика (Payload) без потери визуального качества за счет использования современных алгоритмов сжатия:

*   **AVIF (AV1 Image File Format)** — наиболее эффективный формат 2026 года. Обеспечивает сжатие на 30–50% лучше, чем WebP, при сохранении детализации. Поддерживается всеми современными браузерами (Chrome, Firefox, Safari, Edge).
*   **WebP** — универсальный стандарт, обеспечивающий отличный баланс совместимости и сжатия. Используется как основной fallback для браузеров, не поддерживающих AVIF.
*   **JPEG XL (JXL)** — формат для профессиональной графики с поддержкой прогрессивного декодирования и бездефектного сжатия (lossless). В 2026 году активно внедряется в экосистему Apple и экспериментально в Chromium.

## Основные концепции

В Nginx и Angie адаптивность реализуется через анализ заголовков запроса и выбор файла на диске. Это значительно производительнее динамической конвертации, которая может создавать высокую нагрузку на CPU (подробнее о динамике см. в [модуле image_filter Angie](../../Angie/High_Load/image_filter/overview.md)).

### Механизм согласования контента (Content Negotiation)

Процесс выбора формата происходит прозрачно для клиента по следующей схеме:
1.  **Запрос:** Браузер отправляет заголовок `Accept` со списком поддерживаемых типов (например, `image/avif,image/webp,*/*`).
2.  **Анализ:** Nginx сопоставляет содержимое заголовка с переменной, определяющей суффикс файла.
3.  **Поиск:** Директива `try_files` проверяет наличие файлов на диске в порядке приоритета: `JXL → AVIF → WebP → Оригинал`.

### Преимущества статического подхода

*   **Производительность:** Использование системного вызова `sendfile` позволяет отдавать файлы с минимальными задержками.
*   **Качество:** Возможность использования максимальных уровней сжатия при подготовке файлов в CI/CD (что было бы слишком долго для динамической обработки).
*   **Кэшируемость:** Готовые файлы легко кэшируются на уровне CDN и промежуточных прокси.

## Практические сценарии

### Настройка маппинга форматов

В основном блоке `http` необходимо определить правила сопоставления заголовка `Accept` с суффиксами расширений.

```nginx
http {
    # Сопоставление возможностей браузера с расширениями файлов
    map $http_accept $img_suffix {
        default       "";
        "~*image/jxl"  ".jxl";
        "~*image/avif" ".avif";
        "~*image/webp" ".webp";
    }
}
```

*Важно:* Регулярные выражения в `map` проверяются последовательно. Если браузер поддерживает и AVIF, и WebP, он получит более эффективный формат (AVIF), так как он указан выше в списке или имеет приоритет в логике `try_files`.

### Конфигурация location для выдачи изображений

Для всех запросов к изображениям (JPEG, PNG) настраивается попытка отдачи оптимизированных версий.

```nginx
server {
    location ~* \.(jpe?g|png)$ {
        # Поиск оптимизированного файла по пути: оригинальное_имя.расширение.суффикс
        # Пример: /img/logo.png -> /img/logo.png.avif
        try_files $uri$img_suffix $uri =404;

        # Обязательный заголовок для корректной работы CDN
        add_header Vary "Accept";
        
        # Настройки кэширования
        expires 30d;
        add_header Cache-Control "public, no-transform";
        
        # Оптимизация логирования
        access_log off;
    }
}
```

## Дополнительная информация

### Критическая важность заголовка Vary

Заголовок `Vary: Accept` сообщает промежуточным кэшам (CDN, Nginx Proxy), что ответ сервера зависит от возможностей клиента. 
*   **Без заголовка:** CDN может закэшировать AVIF-версию для первого запроса и отдать её браузеру, который поддерживает только JPEG, что приведет к ошибке отображения.
*   **С заголовком:** CDN создаст разные копии кэша для разных значений `Accept`.

### Кэширование и no-transform

Директива `no-transform` в заголовке `Cache-Control` запрещает мобильным операторам и прокси-серверам пересжимать ваши изображения. Это гарантирует сохранение высокого качества и целостность адаптивной логики.

### Инструменты подготовки ресурсов

Рекомендуется генерировать оптимизированные копии на этапе сборки проекта:
*   **Sharp (CLI/Node.js):** Идеален для автоматизации массовой конвертации.
*   **libavif / libwebp:** Нативные утилиты для максимального контроля над параметрами кодирования.
*   **Squoosh CLI:** Позволяет добиться наилучшего визуального качества при минимальном размере.

### Проверка конфигурации

Для проверки правильности отдачи форматов используйте `curl`:
```bash
# Имитация поддержки AVIF
curl -I -H "Accept: image/avif, */*" https://example.com/images/photo.jpg
# → Должен вернуться Content-Type: image/avif (или соответствующий файл)
```
