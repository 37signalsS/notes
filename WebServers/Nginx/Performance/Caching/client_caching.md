# Клиентское кэширование в Nginx

## Definitions

**Клиентское кэширование (Browser Caching)** — механизм, позволяющий браузеру сохранять локальные копии ресурсов (CSS, JS, изображения, шрифты) и не запрашивать их повторно при последующих визитах. Управление осуществляется через HTTP-заголовки `Cache-Control` и `Expires`, которые сервер отправляет вместе с ресурсом.

**Cache Busting (сброс кэша)** — техника принудительного обновления кэшированных ресурсов путём изменения их URL. Применяется при использовании «вечного» кэширования, когда ресурс не должен обновляться по истечении TTL.

**Immutable** — директива `Cache-Control`, указывающая браузеру, что ресурс не изменится в течение всего срока жизни кэша. Позволяет браузеру полностью пропустить проверку ресурса (без условных запросов `If-None-Match` / `If-Modified-Since`).

## Basic Concepts

### Заголовки клиентского кэширования

Nginx управляет кэшированием через две ключевые директивы:

| Директива Nginx | HTTP-заголовок | Назначение |
|:----------------|:---------------|:-----------|
| `expires` | `Expires`, `Cache-Control: max-age` | Устанавливает срок жизни кэша |
| `add_header Cache-Control` | `Cache-Control` | Добавляет дополнительные директивы (`public`, `immutable`, `no-cache`) |

#### Директива `expires`

```nginx
expires 1y;       # Кэш на 1 год → Cache-Control: max-age=31536000
expires 30d;      # Кэш на 30 дней → Cache-Control: max-age=2592000
expires max;      # Максимальный срок (10 лет) → Cache-Control: max-age=315360000
expires -1;       # Запрет кэширования → Cache-Control: no-cache
expires epoch;    # Немедленное устаревание → Expires: Thu, 01 Jan 1970 00:00:01 GMT
```

> `expires` автоматически устанавливает и заголовок `Expires` (дата), и `Cache-Control: max-age` (секунды).

#### Директива `add_header`

Используется для дополнения `Cache-Control` специфичными директивами:

```nginx
add_header Cache-Control "public, immutable";   # Публичный, неизменяемый ресурс
add_header Cache-Control "public, no-cache";    # Требует валидации перед каждым использованием
```

### Стратегии кэширования по типу контента

| Тип контента | Стратегия | Заголовки | Обоснование |
|:-------------|:----------|:----------|:------------|
| Статика с версионированием (CSS, JS, шрифты) | «Вечное» кэширование | `expires 1y;` + `Cache-Control: public, immutable` | Ресурс не изменится — хэш в имени файла гарантирует актуальность |
| Изображения, медиа | Длительное кэширование | `expires 30d;` + `Cache-Control: public` | Обновляются реже, но без версионирования |
| HTML-страницы | Валидационное кэширование | `Cache-Control: no-cache` | Всегда актуальная разметка со ссылками на кэшированную статику |
| API-ответы | Без кэширования (или короткий TTL) | `Cache-Control: private, no-store` | Персонализированные данные |

## Practical Scenarios

### Сценарий 1: «Вечное» кэширование статики с cache busting

**Проблема:** нужно кэшировать CSS/JS на длительный срок, но при деплое новой версии браузер должен загрузить свежий файл.

**Решение:** хэш содержимого в имени файла + `immutable`.

```nginx
# Location для статических файлов с «вечным» кэшированием
location ~* \.(?:css|js|jpe?g|gif|png|ico|svg|woff|woff2|ttf|eot)$ {
    # 1. Устанавливаем длительный срок жизни кэша
    expires 1y;

    # 2. Добавляем директиву immutable — браузер не будет отправлять условные запросы
    add_header Cache-Control "public, immutable";

    # 3. Отключаем логирование для снижения I/O нагрузки
    access_log off;
}
```

**Как работает cache busting:**

| Подход | Пример | Оценка |
|:-------|:-------|:-------|
| Хэш в имени файла | `style.a1b2c3d4.css` | **Предпочтительно** — CDN и браузеры кэшируют без ограничений |
| Query string | `style.css?v=1.2` | Работает, но некоторые CDN/прокси могут игнорировать query string |

Хэш в имени файла генерируется сборщиками (Webpack, Vite, esbuild) автоматически при изменении содержимого.

### Сценарий 2: Динамический контент (HTML)

HTML должен отдаваться с `no-cache`, чтобы браузер всегда проверял актуальность разметки:

```nginx
location / {
    # Динамический контент — без кэширования, но с валидацией
    add_header Cache-Control "no-cache";

    # ETag включён по умолчанию в Nginx для статических файлов
    # Для динамического контента ETag генерируется бэкендом
}
```

Браузер получит свежий HTML с новыми ссылками на кэшированную статику (`style.a1b2c3d4.css` → `style.d4e5f6.css`).

### Сценарий 3: Запрет кэширования для конфиденциальных данных

```nginx
location /api/ {
    add_header Cache-Control "private, no-store, must-revalidate";
    # private  — только браузер пользователя (без CDN)
    # no-store — полное запрещение сохранения копии
    # must-revalidate — обязательная проверка актуальности
}
```
