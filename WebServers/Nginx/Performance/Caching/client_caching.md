# Клиентское кэширование в Nginx и Angie

> **Надежность: 10** (SSoT + Документация Nginx 1.29+ / Angie 1.12+ + Web 2026)
> **Свежесть: Июль 2026** (Включает Stale-While-Revalidate и HTTP 103 Early Hints)

## Определения

**Клиентское кэширование (Browser Caching)** — механизм, при котором браузер сохраняет копии ресурсов локально, чтобы исключить или минимизировать сетевые запросы при повторных посещениях. Это критический фактор [Web Performance](../../Concepts/web_performance/overview.md).

**Cache-Control** — основной HTTP-заголовок (стандарт RFC 9111), управляющий жизненным циклом кэша через набор директив (`max-age`, `immutable`, `no-cache` и др.).

**Stale-While-Revalidate (SWR)** — директива, позволяющая браузеру мгновенно отображать устаревший контент из кэша, пока в фоновом режиме выполняется запрос на его обновление.

**Early Hints (HTTP 103)** — механизм предварительной загрузки ресурсов. Сервер отправляет список критических файлов (CSS, шрифты) до того, как будет полностью сформирован основной HTML-ответ.

**Cache Busting** — стратегия принудительного обновления кэша путем изменения имени файла (добавление хэша контента: `style.abc123.css`), что делает старый кэш невалидным.

## Основные концепции

В 2026 году стратегия кэширования делится на два фундаментальных подхода: **Версионированная статика** и **Динамический контент**.

### Ключевые директивы Nginx

| Директива | Заголовок | Описание |
| :--- | :--- | :--- |
| **`expires`** | `Expires`, `Cache-Control: max-age` | Устанавливает время жизни кэша (TTL). |
| **`add_header`** | `Cache-Control` | Позволяет задавать современные флаги (`immutable`, `stale-while-revalidate`). |
| **`early_hints`** | `Link: ...; rel=preload` | Активирует отправку HTTP 103 (Nginx 1.29+). |

### Валидация vs Кэширование

1.  **Кэширование (Hit):** Браузер вообще не делает запрос к серверу. Время загрузки = 0 мс (чтение из памяти/диска).
2.  **Валидация (Revalidate):** Браузер шлет запрос с `If-None-Match` (ETag) или `If-Modified-Since`. Если файл не изменился, сервер отвечает `304 Not Modified`. Экономится трафик, но тратится время на RTT (Round Trip Time).

## Практические сценарии

### Сценарий 1: «Вечное» кэширование (Immutable)

Используется для файлов, имена которых гарантированно меняются при обновлении (JS/CSS бандлы из Webpack/Vite).

```nginx
location ~* \.(?:css|js|woff2?|png|webp|avif)$ {
    # 1. Установка максимального срока (1 год)
    expires 1y;
    
    # 2. Флаг immutable исключает запросы на валидацию (ETag) при обновлении страницы
    add_header Cache-Control "public, max-age=31536000, immutable";
    
    # 3. Оптимизация логов (снижение I/O)
    access_log off;
}
```

### Сценарий 2: Нулевая задержка для HTML (SWR + Early Hints)

Этот сценарий идеален для главных страниц, где важна и свежесть контента, и скорость отрисовки. Требует Nginx 1.29+.

```nginx
# В блоке http: включение Early Hints для H2/H3
map $http2$http3 $early_hints_enabled {
    default "";
    "~."    "on";
}

server {
    early_hints $early_hints_enabled;

    location / {
        proxy_pass http://backend;

        # 1. Браузер ДОЛЖЕН проверить актуальность (no-cache)
        # 2. Но может показать старое, если сервер тормозит (stale-while-revalidate)
        # 3. Или если сервер упал (stale-if-error)
        add_header Cache-Control "no-cache, stale-while-revalidate=604800, stale-if-error=86400";
        
        # Ручная подсказка для предварительной загрузки критического CSS
        add_header Link "</css/main.hash123.css>; rel=preload; as=style" always;
    }
}
```

### Сценарий 3: Запрет кэширования чувствительных данных

Для API с персональными данными или страниц личного кабинета.

```nginx
location ~* /(?:api/private|profile|settings) {
    # Полный запрет сохранения на диске и в прокси-кэшах
    expires -1;
    add_header Cache-Control "no-store, no-cache, must-revalidate, proxy-revalidate, private, max-age=0";
}
```

## Дополнительная информация

### Влияние сжатия на ETag

При использовании динамического сжатия (Gzip/Brotli) Nginx по умолчанию делает ETag «слабым» (префикс `W/`). Это может привести к тому, что некоторые прокси-серверы будут игнорировать кэш.
*   **Решение:** Для критически важной статики используйте [предварительное сжатие](../nginx_compression.md#статическое-сжатие-pre-compressed), чтобы ETag оставался сильным.
