# Клиентское кэширование в Nginx

## Определения

**Клиентское кэширование (Browser Caching)** — механизм, позволяющий браузеру сохранять локальные копии ресурсов (CSS — каскадные таблицы стилей, JS — JavaScript, изображения, шрифты) и не запрашивать их повторно при последующих визитах. Это значительно ускоряет загрузку страниц для пользователя и снижает нагрузку на сервер.

**Cache Busting (сброс кэша)** — техника принудительного обновления ресурсов путем изменения их URL (Uniform Resource Locator — единый указатель ресурса). Обычно реализуется через добавление хэша содержимого в имя файла.

**Immutable (неизменяемый)** — директива заголовка `Cache-Control`, сообщающая браузеру, что ресурс никогда не изменится в течение срока действия кэша. Это позволяет полностью исключить проверочные запросы к серверу.

**ETag (Entity Tag — тег сущности)** — уникальный идентификатор версии ресурса (обычно хэш содержимого), используемый браузером для проверки актуальности локальной копии.

**Last-Modified (Последнее изменение)** — заголовок ответа, указывающий дату и время последнего изменения файла на сервере.

## Основные концепции

Управление клиентским кэшированием в Nginx осуществляется через HTTP (HyperText Transfer Protocol — протокол передачи гипертекста) заголовки ответа.

### Ключевые директивы Nginx

| Директива | Соответствующий заголовок | Назначение |
| :--- | :--- | :--- |
| **`expires`** | `Expires`, `Cache-Control: max-age` | Устанавливает время жизни кэша (TTL — Time To Live). |
| **`add_header`** | `Cache-Control` | Добавляет специфические инструкции (`public`, `immutable`, `no-store`). |

#### Использование `expires`

Директива `expires` является наиболее простым способом управления кэшированием:

* `expires 1y;` — кэшировать на 1 год.
* `expires 30d;` — кэшировать на 30 дней.
* `expires -1;` — запрет кэширования (устанавливает `no-cache`).
* `expires epoch;` — устанавливает дату в прошлом (1970 год).

#### Использование `add_header Cache-Control`

Позволяет более гибко настраивать политики для современных браузеров и CDN (Content Delivery Network — сеть доставки контента):

* `public` — разрешает кэширование на промежуточных прокси-серверах.
* `private` — разрешает кэширование только в браузере пользователя.
* `no-cache` — разрешает кэширование, но требует обязательной валидации на сервере перед использованием.
* `no-store` — полный запрет любого кэширования.

### Стратегии по типам контента

1. **Версионированная статика:** Для файлов с хэшем в имени (`app.abc123.js`) применяется максимально длительное кэширование с флагом `immutable`.
2. **Изображения и медиа:** Кэшируются на длительный срок (от 30 дней), если они не меняются часто.
3. **HTML-страницы:** Обычно не кэшируются или требуют валидации (`no-cache`), чтобы браузер всегда получал актуальную разметку со ссылками на кэшированную статику.

## Практические сценарии

### Сценарий 1: «Вечное» кэширование статики

Применяется для ресурсов, имена которых меняются при обновлении содержимого.

```nginx
location ~* \.(?:css|js|woff2?|ttf|eot|otf|svg|png|jpe?g|gif|ico)$ {
    # Установка TTL на 1 год
    expires 1y;
    
    # Добавление флага immutable для исключения повторных проверок
    add_header Cache-Control "public, immutable";
    
    # Отключение логирования для снижения нагрузки на I/O (Input/Output — ввод-вывод)
    access_log off;
}
```

### Сценарий 2: Кэширование с обязательной валидацией

Используется для ресурсов, которые могут измениться без смены имени (например, `index.html`).

```nginx
location / {
    # Разрешить кэширование, но требовать проверку ETag/Last-Modified
    add_header Cache-Control "no-cache";
}
```

Браузер сохранит файл, но при каждом обращении будет слать запрос `If-None-Match`. Если файл не менялся, Nginx ответит `304 Not Modified` без передачи тела файла.

### Сценарий 3: Защита чувствительных данных

Для личных кабинетов или API (Application Programming Interface — программный интерфейс приложения) с персональными данными.

```nginx
location /api/private/ {
    # Запрет сохранения копий где-либо
    add_header Cache-Control "no-store, private";
}
```
