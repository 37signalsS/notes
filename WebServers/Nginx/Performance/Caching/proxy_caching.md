# Серверное кэширование (Proxy Cache) в Nginx

## Определения

**Серверное кэширование (Proxy Cache)** — механизм, при котором Nginx сохраняет ответы от бэкенд-серверов на диске и в разделяемой памяти, чтобы отдавать их клиентам напрямую без повторного обращения к источнику. Это значительно снижает нагрузку на приложение и ускоряет время ответа.

**Кэш-зона (Cache Zone)** — именованная область в разделяемой памяти (`keys_zone`), хранящая ключи кэшированных объектов и их метаданные. Определяется директивой `proxy_cache_path` в контексте `http`.

**Ключ кэша (Cache Key)** — уникальная строка, формируемая из параметров запроса, по которой Nginx ищет сохраненный ответ в кэше.

**Статус кэша (Cache Status)** — индикатор результата обработки запроса относительно кэша:

| Статус | Значение |
| :--- | :--- |
| **HIT** | Ответ отдан напрямую из кэша. |
| **MISS** | Запрос не найден в кэше, ответ получен от бэкенда. |
| **EXPIRED** | Запись устарела (истек TTL), запрос ушел на бэкенд для обновления. |
| **STALE** | Отдан устаревший ответ из-за недоступности бэкенда. |
| **UPDATING** | Отдан устаревший ответ, пока кэш обновляется в фоновом режиме. |
| **BYPASS** | Кэш был намеренно обойден (например, через `proxy_cache_bypass`). |
| **REVALIDATED** | Nginx успешно подтвердил актуальность кэша у бэкенда (получен ответ `304 Not Modified`). |

Общий обзор всех стратегий доступен в [обзоре кэширования](./overview.md).

## Основные концепции

### Архитектура кэша

Кэш в Nginx состоит из двух уровней хранения:

1. **Разделяемая память (Shared Memory):** Зона `keys_zone` хранит ключи и метаданные объектов. Это обеспечивает мгновенную проверку наличия ресурса в кэше всеми рабочими процессами Nginx.
2. **Дисковое хранилище:** Файлы кэшированных ответов. Для предотвращения деградации производительности файловой системы используется иерархия директорий (параметр `levels`).

### Жизненный цикл и TTL

Время жизни ресурса (TTL — Time To Live) в кэше определяется директивой `proxy_cache_valid` или заголовками ответа бэкенда (например, `Cache-Control`). После истечения TTL объект помечается как `EXPIRED`.

### Защита от «стада бизонов» (Cache Stampede)

При одновременном сбросе кэша для популярного ресурса тысячи запросов могут одновременно устремиться к бэкенду. Директива `proxy_cache_lock` позволяет Nginx отправить на бэкенд только один запрос, заставляя остальные ждать формирования кэша.

### Отказоустойчивость

Механизм `proxy_cache_use_stale` позволяет Nginx отдавать устаревшие версии контента, если бэкенд вернул ошибку или недоступен по таймауту. Это критически важно для обеспечения доступности сервиса при сбоях.

## Практические сценарии

### Шаг 1: Определение зоны кэширования

Настройка выполняется в контексте `http` (обычно в файле `nginx.conf`).

```nginx
# Определение пути и параметров кэша
proxy_cache_path /var/cache/nginx/proxy_cache
                  levels=1:2
                  keys_zone=my_cache:10m
                  inactive=60m
                  max_size=1g;
```

* `levels=1:2`: создаёт двухуровневую структуру поддиректорий.
* `keys_zone=my_cache:10m`: выделяет 10 МБ оперативной памяти для ключей.
* `inactive=60m`: удаляет данные, к которым не было обращений в течение часа.
* `max_size=1g`: ограничивает объем кэша на диске до 1 ГБ.

### Шаг 2: Включение кэширования для приложения

```nginx
server {
    location / {
        proxy_pass http://backend_upstream;

        # Активация кэша
        proxy_cache my_cache;

        # Формирование ключа (схема + метод + хост + URI)
        proxy_cache_key "$scheme$request_method$host$request_uri";

        # Время жизни для разных кодов ответа
        proxy_cache_valid 200 302 10m;
        proxy_cache_valid 404 1m;

        # Кэшировать только после 3-го обращения (защита от разовых запросов)
        proxy_cache_min_uses 3;

        # Добавление заголовка для отладки
        add_header X-Cache-Status $upstream_cache_status;
    }
}
```

Здесь URI (Uniform Resource Identifier) — единый идентификатор ресурса.

### Кэширование API (Application Programming Interface)

Для кэширования API-ответов часто требуется игнорировать заголовки бэкенда, запрещающие кэширование (например, `Set-Cookie`).

```nginx
location /api/v1/ {
    proxy_cache my_cache;
    proxy_ignore_headers Cache-Control Expires Set-Cookie;
    proxy_cache_valid 200 5m;
    
    # Защита от перегрузки бэкенда
    proxy_cache_lock on;
    proxy_cache_lock_timeout 5s;
}
```

### Принудительная очистка кэша (Cache Purge)

В Angie (и Nginx Plus) модуль очистки встроен. В Nginx OSS (Open Source Software — программное обеспечение с открытым исходным кодом) требуется сторонний модуль.

```nginx
location ~ /purge(/.*) {
    # Ограничение доступа по IP
    allow 127.0.0.1;
    deny all;

    # Очистка по ключу
    proxy_cache_purge my_cache "$scheme$host$1";
}
```

Запрос `GET /purge/api/data` удалит кэшированный ответ для `/api/data`.
