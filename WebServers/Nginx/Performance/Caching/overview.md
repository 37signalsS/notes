# Кэширование в Nginx и Angie: Обзор и концепции

> **Надежность: 10** (SSoT + Официальная документация Nginx 1.27 / Angie 1.12 + RFC 9111)
> **Свежесть: Июль 2026** (Включает кэш-персистентность Angie и современные директивы Cache-Control)

## Определения

**Кэширование (Caching)** — это процесс временного хранения копий данных для ускорения последующих запросов, снижения времени ответа (TTFB) и уменьшения нагрузки на вычислительные ресурсы (CPU, БД). В контексте Nginx кэширование является фундаментом [оптимизации производительности](../nginx_performance_tuning.md).

**Клиентское кэширование (Browser Caching)** — механизм сохранения ресурсов в браузере пользователя. Управление осуществляется через HTTP-заголовки.

**Серверное кэширование (Proxy Cache)** — механизм сохранения ответов бэкенда на стороне Nginx. Позволяет отдавать контент без обращения к приложению.

**Кэш-индекс (Cache Index)** — база метаданных в оперативной памяти (`keys_zone`), содержащая ключи и информацию о расположении файлов кэша на диске.

**Согласование кэша (Cache Validation)** — процесс проверки актуальности копии данных на сервере с помощью условных запросов.

## Основные концепции

Эффективная стратегия строится на комбинации клиентских и серверных механизмов. Глубокое описание протокола доступно в [HTTP-кэшировании](../../../../Networking/Protocols/HTTP/http_caching.md).

### Клиентское кэширование

Браузер управляет своим хранилищем на основе инструкций от сервера:

*   **Cache-Control:** Основной заголовок. В 2026 году стандарт включает `immutable` (запрет проверок для хэшированных файлов) и `stale-while-revalidate` (фоновое обновление).
*   **Валидаторы:** `ETag` (хэш контента) и `Last-Modified` (дата изменения). Позволяют серверу ответить `304 Not Modified` вместо повторной передачи данных.
*   **Уровни приватности:** `public` (кэшируется всеми), `private` (только браузером), `no-store` (строгий запрет записи).

Подробная настройка — в файле [Клиентское кэширование в Nginx](./client_caching.md).

### Серверное кэширование (Proxy Cache)

Nginx выступает как разделяемый кэш для тысяч пользователей:

*   **Разделяемая память (Shared Memory):** Зона `keys_zone` хранит индекс. В Angie 1.9+ индекс можно сохранять в файл (`file=/path/to.zone`), что устраняет задержки при «холодном старте» после перезагрузки.
*   **Дисковое хранение:** Ответы сохраняются в иерархической структуре папок (`levels`).
*   **Управление логикой:** Директивы `proxy_cache_bypass` и `proxy_no_cache` позволяют исключать из кэша запросы (например, для авторизованных пользователей).

Детальная конфигурация — в файле [Серверное кэширование в Nginx](./proxy_caching.md).

### Мониторинг и эффективность

Ключевая метрика — **Cache Hit Ratio** (процент ответов из кэша).

*   **$upstream_cache_status:** Статусы `HIT` (попадание), `MISS` (промах), `EXPIRED` (устарело), `BYPASS` (обход).
*   **Status Zones (Angie):** В версии 1.12 Angie позволяет создавать именованные зоны со статистикой по ключам (например, мониторинг кэша отдельно по каждому домену).

Методы анализа и визуализации — в файле [Мониторинг кэширования](./monitoring.md).

## Практические сценарии

### Выбор стратегии

| Задача | Решение |
| :--- | :--- |
| Ускорение повторных визитов (статика) | `expires`, `Cache-Control: immutable` |
| Снижение нагрузки на API | `proxy_cache` + `proxy_cache_valid` |
| Защита от «стада бизонов» (Cache Stampede) | `proxy_cache_lock` |
| Адаптивная доставка изображений | `proxy_cache_key` + `$img_suffix` + `Vary: Accept` |
*Подробнее об адаптивности см. в [Адаптивной доставке изображений](../nginx_adaptive_content.md).*

### Защита от перегрузок (Proxy Cache Lock)

Если кэш популярного ресурса истекает, сотни запросов могут одновременно уйти на бэкенд. `proxy_cache_lock on;` заставляет Nginx отправить только один запрос, а остальные «припарковать» до получения результата.

### Фоновое обновление (Stale-While-Revalidate)

Директива `proxy_cache_use_stale updating;` позволяет отдавать клиенту старую версию контента, пока Nginx в фоне запрашивает обновление у бэкенда. Это полностью исключает задержки (Latency) для пользователя при обновлении кэша.

## Дополнительная информация

### Безопасность и целостность

**Отравление кэша (Cache Poisoning):** Происходит, если ключ кэша (`proxy_cache_key`) недостаточно специфичен. Например, если не учитывать заголовок `Accept`, клиент с поддержкой AVIF может «отравить» кэш для клиентов, поддерживающих только JPEG. Всегда используйте `Vary` заголовки при вариативном контенте.
