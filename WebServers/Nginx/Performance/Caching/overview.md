# Кэширование в Nginx: Обзор и концепции

## Определения

**Кэширование (Caching)** — процесс временного хранения копий данных для ускорения последующих запросов. Кэширование сокращает время ответа, уменьшает нагрузку на бэкенд и снижает потребление сетевого трафика. В контексте Nginx кэширование является критически важным инструментом [оптимизации производительности](../nginx_performance_tuning.md).

**Клиентское кэширование (Browser Caching)** — механизм, при котором браузер сохраняет локальные копии ресурсов. Управление осуществляется через HTTP-заголовки (HyperText Transfer Protocol — протокол передачи гипертекста).

**Серверное кэширование (Proxy Cache)** — механизм, при котором Nginx сохраняет ответы от бэкенд-серверов и отдаёт их клиентам напрямую без обращения к приложению.

**ETag (Entity Tag — тег сущности)** — уникальный идентификатор версии ресурса (обычно хэш содержимого), используемый для проверки актуальности кэша.

**Last-Modified (Последнее изменение)** — заголовок, указывающий дату и время последнего изменения файла на сервере.

**Expires (Истекает)** — заголовок, содержащий точную дату устаревания ресурса. Современным стандартом является использование `Cache-Control`.

**Cache-Control (Управление кэшем)** — основной HTTP-заголовок для управления поведением кэша с помощью директив, таких как `max-age` (максимальное время жизни), `no-cache` (требуется валидация) и `no-store` (запрет сохранения).

**TTL (Time To Live — время жизни)** — период времени, в течение которого запись в кэше считается актуальной.

## Основные концепции

Эффективная стратегия кэширования в [Nginx](../../Core/nginx_overview.md) строится на комбинировании клиентских и серверных механизмов. Теоретические основы и описание протокола доступны в разделе [HTTP-кэширование](../../../../Networking/Protocols/HTTP/http_caching.md).

### Клиентское кэширование (Browser Caching)

Nginx передает инструкции браузеру, как долго хранить файлы и когда проверять их обновление.

* **Валидация (условные запросы):** Использование `ETag` и `Last-Modified` позволяет серверу отвечать кодом `304 Not Modified`, если файл не изменился, экономя трафик.
* **Длительное хранение:** Для статических файлов (CSS — каскадные таблицы стилей, JS — JavaScript, изображения) часто применяется «вечное» кэширование с использованием хэш-версионирования в именах файлов.

Подробная конфигурация и примеры приведены в файле [Клиентское кэширование в Nginx](./client_caching.md).

### Серверное кэширование (Proxy Cache)

Nginx выступает в роли разделяемого кэша для множества клиентов, сохраняя ответы API (Application Programming Interface — программный интерфейс приложения) и динамический контент.

* **Разделяемая память:** Nginx использует `keys_zone` для хранения ключей кэша в оперативной памяти, что обеспечивает сверхбыстрый поиск.
* **Дисковое хранилище:** Сами данные хранятся на диске, но благодаря системному кэшу страниц ОС (Operating System — операционная система) часто читаемые файлы отдаются со скоростью оперативной памяти.

Детальное описание директив `proxy_cache_path` и `proxy_cache` находится в файле [Серверное кэширование в Nginx](./proxy_caching.md).

### Мониторинг и эффективность

Основным показателем эффективности является **Cache Hit Ratio (Коэффициент попаданий в кэш)** — отношение запросов, обработанных из кэша (`HIT`), к общему количеству запросов.

Для отслеживания статуса кэширования используется переменная `$upstream_cache_status` в логах доступа. Для визуализации метрик применяется VTS-модуль (Virtual Host Traffic Status — статус трафика виртуальных хостов).

Подробная информация о методах анализа — в файле [Мониторинг кэширования в Nginx](./monitoring.md).

## Практические сценарии

### Выбор стратегии кэширования

| Задача | Решение |
| :--- | :--- |
| Ускорить загрузку статики для повторных визитов | Клиентское кэширование (`expires`, `Cache-Control`) |
| Снизить нагрузку на базу данных при тяжелых API-запросах | Серверное кэширование (`proxy_cache`) |
| Защитить бэкенд от «стада бизонов» (Cache Stampede) | Использование `proxy_cache_lock` |
| Обеспечить доступность сайта при сбое бэкенда | Отдача устаревшего кэша через `proxy_cache_use_stale` |

### Обновление контента (Cache Busting)

При использовании длительного клиентского кэширования (`max-age=31536000`) обновление файлов требует изменения их имен. Сборщики (Webpack, Vite) добавляют хэш содержимого в имя файла: `style.abc123.css`. Это позволяет браузеру мгновенно распознать новый ресурс как другой файл и загрузить его, не дожидаясь истечения срока старого кэша.

### Защита бэкенда при промахах кэша

В сценарии «стада бизонов» (Cache Stampede), когда кэш истекает для популярного ресурса, сотни запросов могут одновременно уйти на бэкенд. Директива `proxy_cache_lock` позволяет Nginx отправить только один запрос на бэкенд, заставляя остальные ждать результата и получать данные из кэша сразу после его наполнения.
