# Мониторинг и производительность кэша Nginx

## Определения

**Коэффициент попаданий в кэш (Cache Hit Ratio)** — процентное отношение количества запросов, успешно обработанных из кэша (`HIT`), к общему числу поступивших запросов. Высокий показатель (более 90% для статического контента) свидетельствует об эффективной настройке кэширования.

**`$upstream_cache_status`** — встроенная переменная Nginx, фиксирующая результат обработки запроса относительно кэша.

| Статус | Описание |
| :--- | :--- |
| **HIT** | Ответ отдан напрямую из кэша. |
| **MISS** | Запрос не найден в кэше, данные получены от бэкенда. |
| **EXPIRED** | Запись в кэше устарела, Nginx запросил обновление у бэкенда. |
| **STALE** | Отдан устаревший ответ из-за временной недоступности бэкенда. |
| **UPDATING** | Отдан устаревший ответ, пока в фоновом режиме идет обновление кэша. |
| **BYPASS** | Кэш был намеренно обойден (например, через директиву `proxy_cache_bypass`). |
| **REVALIDATED** | Nginx подтвердил актуальность кэша у бэкенда (получен ответ `304 Not Modified`). |

**Кэш страниц (Page Cache)** — механизм ОС (Operating System — операционная система) Linux для прозрачного кэширования данных файлов в RAM (Random Access Memory — оперативная память).

## Основные концепции

Производительность дискового кэша Nginx во многом опирается на эффективную работу Page Cache. Часто запрашиваемые ("горячие") данные хранятся в оперативной памяти средствами ядра Linux, что обеспечивает скорость доступа, сопоставимую с in-memory хранилищами (такими как Redis или Memcached), без усложнения архитектуры приложения.

Комплексный мониторинг кэширования строится на трех уровнях:

1. **Анализ логов:** Получение детальной информации о каждом запросе через переменную `$upstream_cache_status`.
2. **Сбор метрик:** Агрегация числовых показателей (количество попаданий, промахов, текущий размер кэша) в системы мониторинга (например, Prometheus).
3. **Визуализация:** Построение графиков и дашбордов в Grafana для отслеживания динамики эффективности кэша.

## Практические сценарии

### Настройка логирования статуса кэша

Для отслеживания эффективности работы кэша необходимо включить переменную статуса в формат логов доступа в блоке `http`.

```nginx
# Определение формата лога с учетом статуса кэша
log_format cache_extended '$remote_addr - $remote_user [$time_local] '
                          '"$request" $status $body_bytes_sent '
                          'cache_status="$upstream_cache_status"';

# Применение формата к файлу лога
access_log /var/log/nginx/cache_access.log cache_extended;
```

Для оперативного анализа логов можно использовать стандартные утилиты Linux:

```bash
# Подсчет количества статусов за текущий период
awk -F'cache_status="' '{print $2}' /var/log/nginx/cache_access.log | tr -d '"' | sort | uniq -c | sort -rn
```

### Сбор метрик через VTS-модуль

Для получения агрегированных данных в реальном времени используется модуль VTS (Virtual Host Traffic Status — статус трафика виртуальных хостов).

1. **Активация сбора данных:** В блоке `http` добавьте `vhost_traffic_status_zone;`.
2. **Экспорт в Prometheus:** Создайте отдельный `location` для выдачи метрик.

```nginx
location /metrics {
    # Вывод статистики в формате Prometheus
    vhost_traffic_status_display;
    vhost_traffic_status_display_format prometheus;
}
```

Подробная инструкция по интеграции находится в разделе [Настройка мониторинга VTS в Nginx](../../Operations/nginx_vts_monitoring_setup.md).

### Мониторинг в Angie Console

При использовании [Angie](../../../Angie/angie_overview.md) (современный форк Nginx) мониторинг кэша доступен "из коробки" через встроенную веб-консоль, которая предоставляет визуализацию метрик в реальном времени без необходимости настройки внешней связки Prometheus + Grafana.

## Дополнительная информация

### Выбор между локальным и внешним кэшем

Использование внешних хранилищ (Redis/Memcached) целесообразно в следующих случаях:

* Необходим общий кэш для нескольких независимых серверов Nginx.
* Требуются сложные механизмы инвалидации (очистки) по тегам или шаблонам.
* Кэш должен сохраняться после полной очистки дискового пространства сервера или переустановки Nginx.

Для большинства сценариев одиночного сервера встроенный дисковый кэш Nginx является более производительным решением за счет исключения сетевых задержек и работы через Page Cache ядра.
