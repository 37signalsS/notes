# Конфигурация HTTP/2 и HTTP/3 в Nginx и Angie

> **Надежность: 10** (SSoT + Официальная документация Nginx 1.26+ / Angie 1.12+ + Web 2026)
> **Свежесть: Июль 2026** (Актуально для Nginx 1.27.x, OpenSSL 3.5+, Angie 1.12+)

## Определения

**HTTP/2 (Hypertext Transfer Protocol Version 2)** — вторая мажорная версия протокола HTTP, разработанная для повышения производительности за счет мультиплексирования запросов и сжатия заголовков (HPACK) поверх TCP. Подробнее об эволюции протокола см. в [истории версий HTTP](../../../Networking/Protocols/HTTP/http_versions.md).

**HTTP/3 (Hypertext Transfer Protocol Version 3)** — третья мажорная версия протокола, использующая транспортный протокол QUIC вместо TCP для устранения проблемы блокировки начала очереди (Head-of-Line blocking) на транспортном уровне.

**QUIC (Quick UDP Internet Connections)** — транспортный протокол на базе UDP, объединяющий мультиплексирование потоков, контроль перегрузок и встроенное TLS 1.3 шифрование.

## Основные концепции

Использование современных версий HTTP является стандартом де-факто в 2026 году, обеспечивая минимальный Time to First Byte (TTFB) и устойчивость к нестабильным сетевым соединениям.

### Решение проблемы Head-of-Line Blocking

*   **HTTP/1.1:** Запросы блокируются последовательно в рамках одного соединения.
*   **HTTP/2:** Позволяет отправлять множество ресурсов одновременно через одно TCP-соединение. Однако потеря одного TCP-пакета блокирует **все** потоки в этом соединении до его восстановления.
*   **HTTP/3 (QUIC):** Каждый поток независим. Потеря UDP-пакета влияет только на конкретный ресурс (например, одно изображение), не затрагивая остальные потоки в рамках сессии.

### Технические требования (2026)

Для полноценной работы протоколов необходимы:

1.  **HTTP/2:**
    *   **Nginx 1.25.1+** или любая версия **Angie**.
    *   **OpenSSL 1.1.1+** (рекомендуется 3.0+ для ALPN).
    *   **TLS 1.2/1.3:** Браузеры не поддерживают HTTP/2 без шифрования.
2.  **HTTP/3 (QUIC):**
    *   **Nginx 1.26+** (Mainline/Stable) или **Angie 1.4.0+**.
    *   **Библиотека с поддержкой QUIC:** OpenSSL 3.2+, BoringSSL или QuicTLS.
    *   **Инфраструктура:** Открытый порт **UDP 443**.
    *   **Ядро Linux 5.7+:** Необходимо для эффективной работы `quic_bpf` и `quic_gso`.

## Практические сценарии

### Настройка HTTP/2

В современных версиях Nginx и Angie поддержка HTTP/2 включается через отдельную директиву, что позволяет гибко управлять протоколом на уровне `server` или `location`.

```nginx
server {
    listen 443 ssl;
    listen [::]:443 ssl;

    # Активация HTTP/2
    http2 on;

    ssl_certificate /etc/nginx/ssl/site.crt;
    ssl_certificate_key /etc/nginx/ssl/site.key;

    # Рекомендуется отключить Server Push (устарело, заменено на 103 Early Hints)
    http2_push off;
}
```

### Настройка HTTP/3 (QUIC)

Настройка требует активации UDP-прослушивания и информирования браузера о доступности нового протокола.

```nginx
# Глобальные настройки (контекст http)
quic_bpf on;       # Маршрутизация пакетов eBPF (в Nginx 1.27 может вызывать ошибки при reload)
quic_gso on;       # Generic Segmentation Offload для снижения нагрузки на CPU

server {
    # 1. TCP для HTTP/1.1 и HTTP/2
    listen 443 ssl;
    
    # 2. UDP для HTTP/3 (reuseport обязателен для балансировки между воркерами)
    listen 443 quic reuseport;
    
    # 3. Активация модуля
    http3 on;

    # 4. Реклама HTTP/3 (через заголовок Alt-Svc)
    # ma=86400 (24 часа) — время, на которое браузер запомнит поддержку h3
    add_header Alt-Svc 'h3=":443"; ma=86400';

    # 5. Оптимизация безопасности QUIC
    quic_retry on;    # Защита от UDP amplification (DoS)

    # 6. Ускорение повторных соединений (0-RTT)
    ssl_early_data on;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
}
```

### Специфические возможности Angie (Upstream HTTP/3)

Angie позволяет проксировать запросы к бэкендам по протоколу HTTP/3, чего не умеет стандартный Nginx Open Source.

```nginx
location /high-speed/ {
    # Включение HTTP/3 для взаимодействия с бэкендом
    proxy_http_version 3;
    proxy_pass https://backend_servers;
}
```

## Дополнительная информация

### Контроль перегрузок (Congestion Control)

В Nginx 1.27+ по умолчанию используется алгоритм **CUBIC** для QUIC. Для систем с высокой потерей пакетов может потребоваться тюнинг или использование BBR на уровне ОС, однако встроенный стек QUIC в Nginx имеет собственные механизмы контроля, настраиваемые через `quic_congestion`.

### Диагностика и отладка

Для проверки работы протоколов используйте:

1.  **Проверка UDP порта:** `ss -ulpn | grep :443`
2.  **Curl с поддержкой h3:** `curl --http3 -I https://example.com`
3.  **Логирование:** В `log_format` можно добавить переменные `$http2` и `$http3` для анализа доли трафика по новым протоколам.

**Известная проблема (Reload Bug):** В Nginx 1.27 при включенном `quic_bpf on;` команда `nginx -s reload` может приводить к потере новых QUIC-соединений из-за задержки закрытия сокетов старыми воркерами. В Angie эта проблема решена через более тесную интеграцию с eBPF.

### Взаимодействие с другими оптимизациями

*   **Сжатие:** Мультиплексирование делает сжатие критичным. Подробнее см. в [Оптимизации сжатия в Nginx](nginx_compression.md).
*   **TLS 1.3:** HTTP/3 работает **только** поверх TLS 1.3. Попытки ограничить протоколы до TLS 1.2 отключат поддержку QUIC.
*   **eBPF:** Использование `quic_bpf` позволяет сохранять активные QUIC-сессии при перезагрузке Nginx (с учетом ограничений выше).
