# Конфигурация HTTP/2 и HTTP/3 в Nginx

## Определения

**HTTP/2 (Hypertext Transfer Protocol Version 2)** — вторая мажорная версия протокола передачи гипертекста, разработанная для повышения производительности веб-приложений за счет мультиплексирования запросов и сжатия заголовков. Подробнее об эволюции протокола см. в [истории версий HTTP](../../../Networking/Protocols/HTTP/http_versions.md).

**HTTP/3 (Hypertext Transfer Protocol Version 3)** — третья мажорная версия протокола HTTP, использующая транспортный протокол QUIC вместо TCP (Transmission Control Protocol — протокол управления передачей) для устранения проблемы блокировки начала очереди (Head-of-Line blocking) на транспортном уровне.

**QUIC (Quick UDP Internet Connections)** — транспортный протокол на базе UDP (User Datagram Protocol — протокол пользовательских датаграмм), обеспечивающий мультиплексирование потоков, надежность и встроенное шифрование.

## Основные концепции

Использование современных версий протокола HTTP значительно улучшает взаимодействие пользователя с сайтом, сокращая время до отрисовки страницы.

### Эволюция и решение проблем блокировки

* **HTTP/1.1:** Запросы обрабатываются последовательно. Один "тяжелый" ресурс может заблокировать загрузку всех последующих в рамках одного соединения (Head-of-Line blocking на уровне соединения).
* **HTTP/2:** Вводит мультиплексирование — передачу множества ресурсов в одном соединении одновременно. Однако потеря одного TCP-пакета все еще блокирует все потоки до момента его повторной передачи (Head-of-Line blocking на уровне TCP).
* **HTTP/3 (QUIC):** Решает проблему блокировки на уровне транспорта. Потеря UDP-пакета влияет только на тот поток (ресурс), к которому он принадлежал, не затрагивая остальные.

### Требования к серверу

Для корректной работы протоколов в Nginx необходимы следующие условия:

1. **HTTP/2:**
    * Nginx любой актуальной версии (поддержка стабильна много лет).
    * OpenSSL версии 1.0.2 или выше (для поддержки ALPN — Application-Layer Protocol Negotiation).
    * Настроенный протокол безопасности TLS (Transport Layer Security — безопасность транспортного уровня). Большинство браузеров не поддерживают HTTP/2 без шифрования.
2. **HTTP/3:**
    * Nginx версии 1.25.0 или выше (или форк Angie), собранный с модулем `ngx_http_v3_module`.
    * Библиотека с поддержкой QUIC (например, BoringSSL, quictls или OpenSSL 3.2+).
    * Открытый UDP-порт 443 на межсетевом экране (файрволе).
    * Ядро Linux версии 5.7+ (для оптимальной производительности через BPF).

### Влияние на ресурсы

Использование HTTP/2 и HTTP/3 увеличивает нагрузку на CPU (Central Processing Unit — центральный процессор) и RAM (Random Access Memory — оперативная память) сервера примерно на 20–30% из-за более сложной обработки потоков и шифрования. Это компенсируется значительным ускорением загрузки для конечного пользователя.

## Практические сценарии

### Настройка HTTP/2

В современных версиях Nginx (1.25.1+) поддержка HTTP/2 включается параметром в директиве `listen`.

```nginx
server {
    # Прослушивание порта 443 с использованием SSL и HTTP/2
    listen 443 ssl http2;
    listen [::]:443 ssl http2;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # Рекомендуется отключить устаревший HTTP/2 Push
    http2_push off;
}
```

*Примечание: Директива `http2 on;` использовалась в версии 1.25.0, но была признана устаревшей в 1.25.1.*

### Настройка HTTP/3 (QUIC)

Настройка HTTP/3 требует одновременного прослушивания TCP (для HTTP/1.1 и HTTP/2) и UDP (для HTTP/3).

```nginx
# Глобальные настройки (контекст http)
quic_bpf on;       # Распределение UDP-пакетов между воркерами через eBPF
quic_gso on;       # Оптимизация передачи через Generic Segmentation Offload

server {
    # 1. Прослушивание UDP-порта для HTTP/3. Параметр reuseport обязателен.
    listen 443 quic reuseport;
    listen [::]:443 quic reuseport;

    # 2. Прослушивание TCP-порта для обратной совместимости
    listen 443 ssl http2;
    listen [::]:443 ssl http2;

    # 3. Активация модуля HTTP/3
    http3 on;

    # 4. Сообщение браузеру о поддержке HTTP/3 через заголовок Alt-Svc
    add_header Alt-Svc 'h3=":443"; ma=86400';

    # 5. Настройка 0-RTT (Zero Round-Trip Time) для ускорения повторных соединений
    # Требует OpenSSL 3.0.1+ и защиты от атак повторного воспроизведения (Replay Attacks)
    ssl_early_data on;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
}
```

### Диагностика протоколов

Для проверки корректности настройки используйте следующие инструменты:

1. **Инструменты разработчика в браузере:** Вкладка "Сеть" (Network), колонка "Протокол" (Protocol). Обозначения: `h2` — HTTP/2, `h3` — HTTP/3.
2. **Утилита curl:**

    ```bash
    # Проверка поддержки HTTP/2
    curl -I --http2 https://example.com

    # Проверка поддержки HTTP/3 (требует curl, собранный с поддержкой QUIC)
    curl -I --http3 https://example.com
    ```

3. **Проверка портов:**

    ```bash
    # Проверка TCP-порта 443
    ss -tlnp | grep :443
    # Проверка UDP-порта 443
    ss -ulnp | grep :443
    ```

## Дополнительная информация

### Механизмы обнаружения HTTP/3

Клиент не может сразу знать, что сервер поддерживает QUIC, так как UDP-порт может быть заблокирован. Существует два способа уведомления:

1. **Заголовок Alt-Svc (Alternative Services):** Сервер сообщает в HTTP/2 ответе, что он доступен по адресу `h3=":443"`. Браузер кэширует это на время `ma` (max-age) и следующие запросы шлет по UDP.
2. **DNS-запись типа HTTPS:** Позволяет браузеру узнать о поддержке протоколов еще до первого HTTP-запроса. Это решает проблему "холодного старта".

### Взаимодействие с другими оптимизациями

* **Сжатие:** Мультиплексирование делает динамическое сжатие (Gzip/Brotli) критичным к производительности. Подробнее см. в разделе [оптимизация сжатия в Nginx](nginx_compression.md).
* **TLS 1.3:** HTTP/3 требует использования TLS 1.3. Совместное использование TLS 1.3 и 0-RTT позволяет устанавливать соединение за минимальное количество RTT (Round-Trip Time — время кругового обхода).
