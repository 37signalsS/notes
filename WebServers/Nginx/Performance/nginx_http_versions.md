# Конфигурация HTTP/2 и HTTP/3 в Nginx и Angie

## Определения

**HTTP/2 (Hypertext Transfer Protocol Version 2)** — вторая мажорная версия протокола HTTP, разработанная для повышения производительности за счет мультиплексирования запросов и сжатия заголовков (HPACK) поверх TCP. Подробнее об эволюции протокола см. в [Истории версий HTTP](../../../Networking/Protocols/HTTP/http_versions.md).

**HTTP/3 (Hypertext Transfer Protocol Version 3)** — третья мажорная версия протокола, использующая транспортный протокол QUIC вместо TCP для устранения проблемы блокировки начала очереди (Head-of-Line blocking) на транспортном уровне.

**QUIC (Quick UDP Internet Connections)** — транспортный протокол на базе UDP, объединяющий мультиплексирование потоков, контроль перегрузок и встроенное TLS 1.3 шифрование.

## Основные концепции

Использование современных версий HTTP является стандартом де-факто в 2026 году, обеспечивая минимальный Time to First Byte (TTFB) и устойчивость к нестабильным сетевым соединениям.

### Решение проблемы Head-of-Line Blocking

*   **HTTP/1.1:** Запросы блокируются последовательно в рамках одного соединения.
*   **HTTP/2:** Позволяет отправлять множество ресурсов одновременно через одно TCP-соединение. Однако потеря одного TCP-пакета блокирует **все** потоки в этом соединении до его восстановления (проблема TCP HoL).
*   **HTTP/3 (QUIC):** Каждый поток независим. Потеря UDP-пакета влияет только на конкретный ресурс (например, одно изображение), не затрагивая остальные потоки в рамках сессии.

### Технические требования (2026)

1.  **HTTP/2:**
    *   **Nginx 1.25.1+** или любая версия **Angie**.
    *   **OpenSSL 1.1.1+** (рекомендуется 3.0+ для ALPN).
    *   **TLS 1.2/1.3:** Браузеры не поддерживают HTTP/2 без шифрования (h2).
2.  **HTTP/3 (QUIC):**
    *   **Nginx 1.26+** или **Angie 1.4.0+**.
    *   **Библиотека с QUIC:** OpenSSL 3.2+, BoringSSL или QuicTLS.
    *   **UDP 443:** Порт должен быть открыт в Firewall (включая промежуточные облачные балансировщики).
    *   **Ядро Linux 5.7+:** Необходимо для корректной работы `quic_bpf` и оптимизаций `quic_gso`.

## Практические сценарии

### Настройка HTTP/2

В современных версиях Nginx и Angie поддержка HTTP/2 включается через директиву `http2`.

```nginx
server {
    listen 443 ssl;
    listen [::]:443 ssl;

    # Активация HTTP/2
    http2 on;

    ssl_certificate /etc/nginx/ssl/site.crt;
    ssl_certificate_key /etc/nginx/ssl/site.key;

    # Server Push (устарело). Рекомендуется использовать HTTP 103 Early Hints.
    http2_push off;
}
```

### Настройка HTTP/3 (QUIC)

Требует активации UDP-прослушивания и рекламы протокола браузеру.

```nginx
# Оптимизации на уровне http
quic_bpf on;       # Маршрутизация пакетов через eBPF (сохранение сессий при reload)
quic_gso on;       # Снижение нагрузки на CPU при передаче пакетов

server {
    # 1. TCP-слушатели (HTTP/1.1 и HTTP/2)
    listen 443 ssl;
    
    # 2. UDP-слушатель для HTTP/3 (reuseport обязателен для балансировки)
    listen 443 quic reuseport;
    
    # 3. Активация HTTP/3
    http3 on;

    # 4. Реклама протокола (Alt-Svc)
    # Браузер запомнит поддержку h3 на 24 часа (ma=86400)
    add_header Alt-Svc 'h3=":443"; ma=86400';

    # 5. Безопасность и DoS-защита
    quic_retry on;    # Защита от UDP-амплификации

    # 6. Ускорение повторных соединений (0-RTT)
    # ВНИМАНИЕ: ssl_early_data делает сервер уязвимым к replay-атакам.
    # Используйте только если приложение защищено на уровне логики (Idempotency).
    ssl_early_data on;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
}
```

### Работа с бэкендами (Upstream)

*   **gRPC через HTTP/2:** Стандартный Nginx поддерживает проксирование gRPC.
    ```nginx
    location /grpc.service {
        grpc_pass grpc://backend_grpc;
    }
    ```
*   **Upstream HTTP/3 (Angie):** Angie позволяет взаимодействовать с бэкендами по HTTP/3, обеспечивая минимальные задержки внутри инфраструктуры.
    ```nginx
    location /api/ {
        proxy_http_version 3;
        proxy_pass https://backend_cluster;
    }
    ```

## Дополнительная информация

### Проблемы MTU и фрагментации UDP

QUIC чувствителен к размеру MTU. Если пакеты превышают MTU промежуточных узлов, они могут быть отброшены.
*   Nginx использует встроенные механизмы (PMTUD) для подбора оптимального размера пакета.
*   Рекомендуется обеспечивать возможность прохождения UDP-пакетов размером не менее 1200 байт.

### Безопасность 0-RTT (Replay Attacks)

Директива `ssl_early_data on;` позволяет клиенту отправлять данные в первом же пакете, не дожидаясь завершения TLS-handshake. Это экономит один RTT, но создает риск: злоумышленник может перехватить этот пакет и отправить его повторно (например, запрос на оплату).
*   **Правило:** Включайте 0-RTT только для GET-запросов без побочных эффектов или если бэкенд проверяет уникальность запросов (Idempotency Key).

### Диагностика

1.  **Проверка сокетов:** `ss -ulpn | grep :443` (наличие UDP-прослушивания).
2.  **Тестирование:** `curl --http3 -I https://example.com` (требует curl с поддержкой h3).
3.  **Логирование:** Используйте `$http2` и `$http3` в формате логов для анализа распределения трафика.
