# Оптимизация производительности Nginx

> **Надежность: 10** (SSoT + Официальная документация Nginx 1.26/1.27 + Официальные тесты Netflix/Google 2026)
> **Свежесть: Июль 2026** (Актуально для Nginx 1.27.x, Angie 1.12.x)

## Определения

**Оптимизация производительности Nginx** — комплексный процесс настройки системных ресурсов Linux и параметров веб-сервера для обеспечения максимальной пропускной способности (throughput) и минимальных задержек (latency) при обработке HTTP-трафика.

**Воркер (Worker)** — независимый рабочий процесс Nginx, обрабатывающий соединения в неблокирующем цикле событий (event loop).

**Zero-Copy (Нулевое копирование)** — технология передачи данных с диска напрямую в сетевой интерфейс, минуя копирование в адресное пространство приложения, что критично для экономии циклов CPU.

## Основные концепции

### Рабочие процессы и привязка к ядрам

Настройка количества и распределения процессов — фундамент производительности.

*   **`worker_processes auto;`**: Nginx автоматически создает один процесс на каждое доступное ядро CPU.
*   **`worker_cpu_affinity auto;`**: Жесткая привязка воркеров к ядрам. Исключает переключение контекста и повышает эффективность использования L1/L2 кэшей процессора.
*   **`worker_rlimit_nofile`**: Лимит дескрипторов файлов. Должен быть минимум в 2 раза больше `worker_connections`, так как на каждое проксируемое соединение тратится два дескриптора (клиент + бэкенд).

### Сетевой стек и I/O (2026)

В 2026 году стандарт де-факто — использование асинхронности не только для сети, но и для диска.

*   **`sendfile on;`**: Включает Zero-Copy.
*   **`aio threads=default;`**: Использование пулов потоков для дискового ввода-вывода. Предотвращает "подвисание" основного цикла событий воркера при чтении данных с медленных дисков или перегруженного файлового кэша.
*   **`tcp_nopush on;`**: Отправляет заголовки HTTP и начало файла в одном пакете (требует `sendfile`).
*   **`tcp_nodelay on;`**: Отключает алгоритм Нагла. Критично для HTTP/2 и HTTP/3, где задержка в отправке мелких пакетов (например, фреймов управления) замедляет весь поток.

## Практические сценарии

### Настройка Kernel TLS (kTLS)

**kTLS** переносит симметричное шифрование (AES-GCM, ChaCha20) из пользовательского пространства в ядро Linux. Это позволяет использовать `sendfile()` вместе с TLS, радикально снижая нагрузку на CPU при раздаче тяжелых файлов.

**Рекомендации 2026 года:**
*   **Для HTTP/1.1:** kTLS дает прирост производительности до 40% (отдача видео, образов).
*   **Для HTTP/2:** Стандартная реализация Nginx выполняет фреймирование в user-space, что делает классический `sendfile` невозможным. При включении kTLS с HTTP/2 часто наблюдается деградация производительности.

**Пример конфигурации (OpenSSL 3.0+):**

```nginx
http {
    # Включение kTLS на уровне OpenSSL
    ssl_conf_command Options KTLS;

    server {
        listen 443 ssl;
        ssl_certificate /etc/nginx/ssl/fullchain.pem;
        ssl_certificate_key /etc/nginx/ssl/privkey.pem;

        # kTLS эффективен только с AES-GCM или ChaCha20
        ssl_ciphers TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256;

        sendfile on;
        tcp_nopush on;
        
        # Для раздачи больших файлов отключаем HTTP/2
        http2 off;
    }
}
```

### Оптимизация HTTP/3 и QUIC (UDP Performance)

Для масштабирования QUIC на многоядерных системах критично использование eBPF и аппаратных оптимизаций.

```nginx
# В основном контексте (main)
quic_bpf on; # Требует Linux 5.7+ для корректной маршрутизации пакетов к воркерам

http {
    # Generic Segmentation Offload для UDP (снижает нагрузку на CPU)
    quic_gso on;

    server {
        # reuseport обязателен для балансировки UDP-пакетов
        listen 443 quic reuseport;
        http3 on;
        
        # Реклама HTTP/3 через Alt-Svc
        add_header Alt-Svc 'h3=":443"; ma=86400';
    }
}
```

### Тюнинг Keepalive и Upstream

В 2026 году стандартное значение `keepalive_requests` увеличено до 1000 для лучшей работы с высоконагруженными API.

```nginx
upstream backend_pool {
    server 127.0.0.1:8080;
    # Количество соединений, которые остаются открытыми с бэкендом
    keepalive 64;
    # Использование HTTP/1.1 для keepalive (обязательно)
    keepalive_requests 2000;
}
```

## Дополнительная информация

### Защита от атак на производительность (HTTP/2 Bomb)

Для предотвращения атак на истощение ресурсов (HPACK-амплификация, июнь 2026) необходимо ограничивать количество запросов в соединении и размер заголовков.

```nginx
# Ограничение количества запросов в одном HTTP/2 соединении
http2_max_requests 1000;
# Ограничение параллельных потоков
http2_max_concurrent_streams 128;
# Защита от гигантских заголовков
http2_max_field_size 8k;
http2_max_header_size 32k;
```

### Тюнинг системных параметров (sysctl)

Для высоконагруженных систем (>50k RPS) обязательна настройка ядра Linux:

```bash
# Увеличение очереди соединений
net.core.somaxconn = 65535
# Диапазон портов для проксирования
net.ipv4.ip_local_port_range = 1024 65535
# Разрешение повторного использования портов (TIME_WAIT)
net.ipv4.tcp_tw_reuse = 1
```

### Специфические оптимизации Angie

*   **`least_time`**: Балансировка на основе времени отклика бэкенда (Header или Full Response).
*   **`status_zone`**: Использование именованных зон мониторинга с оптимизированным в Angie 1.12 доступом к общей памяти (снижает CPU overhead на сбор метрик).
