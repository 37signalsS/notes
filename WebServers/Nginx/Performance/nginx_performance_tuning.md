# Оптимизация производительности Nginx и Angie

## Определения

**Оптимизация производительности Nginx** — комплексный процесс настройки системных ресурсов Linux и параметров веб-сервера для обеспечения максимальной пропускной способности (throughput) и минимальных задержек (latency) при обработке трафика.

**Рабочий процесс (Worker)** — независимый процесс Nginx/Angie, обрабатывающий соединения в неблокирующем цикле событий (event loop).

**Нулевое копирование (Zero-Copy)** — технология передачи данных с диска напрямую в сетевой интерфейс через системный вызов `sendfile()`, минуя копирование в адресное пространство приложения.

## Основные концепции

### Процессы и привязка к ядрам (Affinity)

Фундамент производительности — исключение переключения контекста (context switching).

*   **`worker_processes auto;`**: Создает один процесс на каждое доступное ядро CPU.
*   **`worker_cpu_affinity auto;`**: Жесткая привязка воркеров к ядрам. Это критично для эффективного использования L1/L2 кэшей процессора.
*   **`worker_rlimit_nofile`**: Лимит дескрипторов файлов. Должен быть минимум в 2 раза больше `worker_connections`, так как на каждое проксируемое соединение тратится два дескриптора (клиент + бэкенд).
*   **`worker_shutdown_timeout`**: Время на корректное завершение воркера при перезагрузке конфигурации. Предотвращает «подвисание» старых процессов при долгих соединениях (например, gRPC или WebSocket).

### Сетевой стек и ввод-вывод (I/O)

В 2026 году стандарт — полная асинхронность дисковых и сетевых операций.

*   **`sendfile on;`**: Включает технологию Zero-Copy.
*   **`sendfile_max_chunk 512k;`**: Ограничивает объем данных за один вызов `sendfile()`. Это предотвращает блокировку воркера одним быстрым клиентом, скачивающим тяжелый файл, и обеспечивает честное распределение ресурсов между всеми соединениями.
*   **`aio threads=default;`**: Использование пулов потоков для дискового I/O. Предотвращает блокировку основного цикла событий при чтении данных, которых нет в системном Page Cache.
*   **`tcp_nopush on;`**: Отправляет заголовки HTTP и начало файла в одном пакете (эффективно только с `sendfile`).
*   **`tcp_nodelay on;`**: Отключает алгоритм Нагла. Критично для HTTP/2 и HTTP/3, где задержка в отправке мелких фреймов управления замедляет весь поток.

### Кэширование открытых файлов

**`open_file_cache`** радикально ускоряет отдачу мелкой статики, кэшируя дескрипторы, размеры и время модификации файлов.

```nginx
open_file_cache          max=10000 inactive=20s;
open_file_cache_valid    30s;
open_file_cache_min_uses 2;
open_file_cache_errors   on;
```

## Практические сценарии

### Использование Kernel TLS (kTLS)

**kTLS** переносит симметричное шифрование (AES-GCM, ChaCha20) в ядро Linux. Это позволяет использовать `sendfile()` вместе с TLS.

**Рекомендации:**
*   **Для HTTP/1.1:** kTLS дает прирост до 40% при раздаче видео и тяжелых архивов.
*   **Для HTTP/2:** В стандартном Nginx kTLS может конфликтовать с логикой фреймирования в user-space. Рекомендуется тщательное тестирование.

```nginx
http {
    # Включение kTLS на уровне OpenSSL 3.0+
    ssl_conf_command Options KTLS;

    server {
        listen 443 ssl;
        ssl_ciphers TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256;
        sendfile on;
        tcp_nopush on;
        # kTLS наиболее эффективен при отключении HTTP/2 для раздачи файлов
        http2 off;
    }
}
```

### Оптимизация UDP для HTTP/3 (QUIC)

Для масштабирования QUIC необходимо использовать eBPF и аппаратные оптимизации.

```nginx
# В контексте main
quic_bpf on; # Требует Linux 5.7+ для сохранения сессий при reload

http {
    quic_gso on; # Generic Segmentation Offload (разгрузка CPU)

    server {
        listen 443 quic reuseport;
        http3 on;
        add_header Alt-Svc 'h3=":443"; ma=86400';
    }
}
```

### Настройка Keepalive и буферов

В 2026 году стандартное значение `keepalive_requests` увеличено до 1000+ для современных SPA и API.

```nginx
http {
    keepalive_timeout 65;
    keepalive_requests 1000;
    
    # Сброс соединений по таймауту для освобождения памяти
    reset_timedout_connection on;

    # Оптимизация буферов проксирования
    proxy_buffering on;
    proxy_buffers 16 16k;
    proxy_buffer_size 32k;
    proxy_busy_buffers_size 64k;
}
```

## Дополнительная информация

### Защита производительности (DDoS/Flood)

Для предотвращения исчерпания ресурсов при атаках типа "HTTP/2 Bomb" или медленных запросах:

```nginx
# Ограничения HTTP/2
http2_max_requests 1000;
http2_max_concurrent_streams 128;

# Тайм-ауты чтения тела и заголовков
client_body_timeout 10s;
client_header_timeout 10s;
send_timeout 10s;
```

### Системный тюнинг (sysctl)

Для высоконагруженных инсталляций (>100k RPS) обязательна настройка ядра Linux:

```bash
# Очередь входящих соединений
net.core.somaxconn = 65535
# Диапазон портов для исходящих соединений
net.ipv4.ip_local_port_range = 1024 65535
# Повторное использование TIME_WAIT сокетов
net.ipv4.tcp_tw_reuse = 1
# Максимальное количество открытых файлов в системе
fs.file-max = 2097152
```

Подробности см. в:
* [Тюнинг sysctl в Linux](../../../Linux/Core/kernel/sysctl.md)
* [Оптимизация TCP-стека](../../../Linux/Networking/Concepts/tcp_tuning/tcp_tuning_overview.md)

### Особенности Angie

*   **`least_time`**: Алгоритм балансировки, выбирающий сервер с наименьшим временем ответа.
*   **`status_zone`**: Именованные зоны мониторинга. В Angie 1.12 оптимизирован доступ к общей памяти, что снижает нагрузку на CPU при интенсивном сборе метрик.
