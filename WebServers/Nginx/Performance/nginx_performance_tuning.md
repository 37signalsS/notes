# Оптимизация производительности Nginx

## Определения

**Оптимизация производительности Nginx** — это процесс настройки операционной системы и самого веб-сервера для обработки максимального количества запросов с минимальной задержкой при эффективном использовании ресурсов системы.

**Воркер (Worker)** — рабочий процесс Nginx, выполняющий основную работу по обработке соединений.

**Дескриптор файла (File Descriptor)** — абстрактный показатель, используемый ОС (Operating System — операционная система) для идентификации открытого файла или сетевого сокета.

## Основные концепции

### Рабочие процессы и соединения

Ключевые директивы настраиваются в основном файле конфигурации `nginx.conf`.

* **`worker_processes`**: Количество рабочих процессов. Рекомендуется значение `auto` для автоматического определения по количеству ядер CPU (Central Processing Unit — центральный процессор).
* **`worker_connections`**: Максимальное число одновременных соединений на один воркер. Общий лимит системы равен произведению количества процессов на количество соединений.
* **`worker_rlimit_nofile`**: Лимит на количество открытых файлов (дескрипторов) для одного процесса. Должен быть выше, чем `worker_connections`.
* **`worker_cpu_affinity`**: Привязка воркеров к конкретным ядрам процессора для минимизации переключений контекста и лучшего использования кэша L1/L2 (Level 1/Level 2).

### Сетевой стек и обработка событий

* **`use epoll`**: Использование наиболее эффективного метода обработки событий в Linux.
* **`sendfile`**: Системный вызов для прямой передачи данных с диска в сетевой сокет (Zero-Copy), значительно ускоряющий отдачу статики.
* **`tcp_nopush`**: Группировка данных для отправки полными пакетами TCP (Transmission Control Protocol — протокол управления передачей). Работает только при включенном `sendfile`.
* **`tcp_nodelay`**: Отключение алгоритма Нагла для минимизации задержек при отправке небольших пакетов.

### Таймауты и управление ресурсами

* **`keepalive_timeout`**: Время ожидания нового запроса в рамках одного соединения. Оптимально 60–75 секунд.
* **`client_header_timeout`** и **`client_body_timeout`**: Время на чтение заголовков и тела запроса. Защищают от медленных атак (Slowloris).
* **`reset_timedout_connection on`**: Немедленное освобождение ресурсов при разрыве соединения по таймауту.

## Практические сценарии

### Настройка Kernel TLS (kTLS)

**Kernel TLS** переносит операции шифрования TLS (Transport Layer Security — безопасность транспортного уровня) из пространства пользователя в ядро ОС.

**Результаты тестирования производительности (отдача файлов ~1.5 ГБ):**

| Конфигурация | Производительность | Примечание |
| :--- | :--- | :--- |
| HTTP/1.1 + TLS | 100% | Базовый уровень |
| **HTTP/1.1 + kTLS** | **~130%** | Прирост за счет `sendfile` |
| HTTP/2 + TLS | ~70% | Накладные расходы протокола |
| **HTTP/2 + kTLS** | **~25-40%** | **Критическая деградация** |

**Вывод:** kTLS несовместим с HTTP/2 (Hypertext Transfer Protocol Version 2) из-за особенностей буферизации данных. Используйте kTLS только для HTTP/1.1 при раздаче тяжелого контента.

```nginx
server {
    listen 443 ssl;
    # Настройка kTLS требует OpenSSL 3.0+ и ядра Linux 5.x+
    ssl_conf_command Options PrioritizeChaCha;
    ssl_conf_command Ciphersuites TLS_AES_128_GCM_SHA256;
    
    http2 off;
    sendfile on;
}
```

### Оптимизация буферов для обратного прокси

Правильная настройка буферов `proxy_buffers` позволяет избежать записи ответов бэкенда во временные файлы на диск.

```nginx
location /api/ {
    # Буфер для заголовков ответа
    proxy_buffer_size 4k;
    # 8 буферов по 16 КБ для тела ответа
    proxy_buffers 8 16k;
    # Максимальный объем данных для немедленной отправки клиенту
    proxy_busy_buffers_size 32k;
}
```

### Тюнинг сокетов (reuseport)

Директива `reuseport` позволяет ядру распределять входящие соединения между воркерами более эффективно, устраняя конкуренцию за один слушающий сокет.

```nginx
server {
    listen 443 ssl reuseport;
    # ...
}
```

## Дополнительная информация

### Системный тюнинг (sysctl)

Максимальная производительность Nginx недостижима без настройки параметров ядра Linux:

* Увеличение `net.core.somaxconn` (очередь прослушиваемых сокетов).
* Настройка `net.ipv4.ip_local_port_range` (диапазон локальных портов).
* Тюнинг TCP-буферов (`net.ipv4.tcp_rmem`, `net.ipv4.tcp_wmem`).
