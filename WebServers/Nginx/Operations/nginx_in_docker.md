# Запуск Nginx в Docker

Этот документ основан на материалах вебинара "DevOps by Rebrain: Запуск веб-сервера Nginx в Docker".

## Зачем запускать Nginx в Docker?

1.  **Управление версиями**: Docker позволяет использовать любую необходимую версию Nginx, независимо от того, какая версия доступна в репозиториях операционной системы хоста. Это решает проблему устаревших пакетов.
2.  **Консистентность окружения**: Контейнер включает в себя все необходимые зависимости (например, конкретную версию OpenSSL), что гарантирует одинаковą работу Nginx на любой машине, где установлен Docker.
3.  **Изоляция**: Docker обеспечивает изоляцию процессов и файловой системы, что повышает безопасность и предсказуемость.
4.  **Портативность и автоматизация**: Docker-образ, содержащий Nginx с нужной конфигурацией, можно легко переносить между средами (разработка, тестирование, продакшн) и использовать в CI/CD пайплайнах для автоматического развертывания.
5.  **Кастомные сборки**: С помощью `Dockerfile` можно легко создавать собственные образы Nginx с дополнительными модулями (например, Brotli, ModSecurity) или специфическими настройками, скомпилированными в сам образ.

## Базовый запуск

Команда `docker run` используется для создания и запуска контейнера из образа.

```bash
# docker run [OPTIONS] IMAGE[:TAG|@DIGEST] [COMMAND] [ARG...]
```

Пример запуска простого контейнера для проверки работоспособности Docker:

```bash
docker run hello-world
```

### Запуск контейнера Nginx

Для запуска Nginx используется официальный образ `nginx`.

```bash
# Запуск в интерактивном режиме (foreground)
docker run nginx

# Запуск в фоновом режиме (detached)
docker run -d --name my-nginx nginx
```

*   `-d` (`--detach`): Запускает контейнер в фоновом режиме.
*   `--name`: Задает имя контейнеру для удобства управления.

## Проброс портов (Port Mapping)

Чтобы сделать Nginx доступным извне контейнера, необходимо пробросить порты с хостовой машины на порты контейнера.

```bash
docker run -d --name nginx-test -p 8080:80 nginx
```

*   `-p <host_port>:<container_port>`: Связывает порт `8080` на хосте с портом `80` внутри контейнера.
*   Формат: `слева порт хоста, справа порт контейнера`.

Теперь Nginx будет доступен по адресу `http://<host_ip>:8080`.

## Управление конфигурацией и данными

По умолчанию, конфигурация и файлы сайта находятся внутри контейнера. Это неудобно для управления и приводит к потере данных при удалении контейнера. Правильный подход — использовать **volumes** для монтирования директорий с хоста внутрь контейнера.

### Монтирование директории с сайтом

```bash
docker run -d --name nginx-web \
  -p 80:80 \
  -v /path/to/your/html:/usr/share/nginx/html \
  nginx
```

*   `-v <host_path>:<container_path>`: Монтирует директорию `/path/to/your/html` с хоста в директорию `/usr/share/nginx/html` внутри контейнера, где Nginx по умолчанию ищет файлы сайта.

### Монтирование конфигурационных файлов

Аналогично можно пробросить и конфигурационные файлы.

```bash
docker run -d --name nginx-custom-config \
  -p 80:80 \
  -v /path/to/your/html:/usr/share/nginx/html \
  -v /path/to/your/nginx.conf:/etc/nginx/nginx.conf:ro \
  nginx
```

*   Рекомендуется монтировать конфигурационные файлы в режиме "только для чтения" (`:ro`), чтобы предотвратить их случайное изменение из контейнера.

## Сетевые режимы

Docker предлагает несколько сетевых драйверов. Наиболее часто используемые для Nginx:

### 1. Bridge (по умолчанию)

*   Создает изолированную сеть для контейнеров.
*   Для доступа извне требуется проброс портов (`-p`).
*   Контейнеры в одной bridge-сети могут общаться друг с другом по именам.
*   При использовании этого режима создается виртуальный интерфейс `docker0` и используются правила `iptables` для управления трафиком.

### 2. Host

*   Контейнер использует сетевой стек хостовой машины напрямую, без изоляции.
*   Проброс портов не требуется. Если Nginx слушает порт 80 в контейнере, он будет слушать порт 80 и на хосте.
*   **Преимущество**: Максимальная производительность сети, так как отсутствует дополнительный уровень NAT.
*   **Недостаток**: Отсутствие сетевой изоляции. Нельзя запустить несколько контейнеров, слушающих один и тот же порт.

Пример запуска в режиме `host`:

```bash
docker run -d --name nginx-host-net --network host nginx
```

## Управление контейнером и логи

*   **Просмотр запущенных контейнеров:**
    ```bash
    docker ps
    ```

*   **Просмотр логов Nginx:**
    Контейнеризированные приложения, следуя лучшим практикам, выводят логи в `stdout` и `stderr`.
    ```bash
    # Показать все логи
    docker logs my-nginx

    # Следить за логами в реальном времени
    docker logs -f my-nginx
    ```

*   **Перезагрузка конфигурации Nginx:**
    Для применения новых настроек без перезапуска контейнера используется команда `nginx -s reload`, выполненная внутри контейнера.
    ```bash
docker exec my-nginx nginx -s reload
    ```

*   **Остановка и удаление контейнера:**
    ```bash
    docker stop my-nginx
    docker rm my-nginx
    ```

## Жизненный цикл и обновления

Контейнеры считаются "неизменяемыми" (immutable). Для обновления версии Nginx или изменения его конфигурации (которая не вынесена в volumes) следует старому принципу: **удалить старый контейнер и создать новый** из обновленного образа или с новыми параметрами.

### Политики перезапуска

Чтобы Nginx запускался автоматически после перезагрузки сервера, используется флаг `--restart`.

```bash
docker run -d --name nginx-prod --restart always -p 80:80 nginx
```

*   `--restart always`: Всегда перезапускать контейнер, если он остановлен.
*   `--restart unless-stopped`: Перезапускать, кроме случаев, когда он был остановлен вручную (`docker stop`).
