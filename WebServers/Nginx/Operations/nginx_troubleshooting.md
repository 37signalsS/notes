# Поиск и устранение неисправностей Nginx

## Определения

Ключевые определения, связанные с Nginx, такие как "master process", "worker process", "server block" и "location", подробно описаны в основной заметке **[Обзор Nginx](../Core/nginx_overview.md)**.

## Основные концепции

Фундаментальные принципы работы Nginx, его архитектура и модель обработки соединений изложены в заметке **[Обзор Nginx](../Core/nginx_overview.md)**. Понимание этих концепций является основой для эффективной диагностики.

## Практические сценарии

### Локализация проблемы: У меня или у всех?

1. **Проверьте с другого устройства/сети:** Попробуйте зайти на сайт с телефона через мобильный интернет. Если там работает — проблема у вас (кэш, DNS, провайдер).
2. **Проверьте DNS:** Убедитесь, что доменное имя правильно преобразуется в IP-адрес сервера. Для этого можно использовать утилиту `dig`, подробно описанную в заметке [Диагностика DNS](../../../Linux/Diagnostics/Networking/dns/overview.md).

    ```bash
    dig your-domain.com
    ```

    В секции `ANSWER SECTION` должен быть правильный IP-адрес вашего сервера.

### Сетевой доступ к серверу

1. **Простой `ping`:**

    ```bash
    ping your-domain.com
    ```

    Если пинги не проходят, возможно, сервер выключен или блокирует ICMP-пакеты (это нормально). Если IP из `dig` пингуется, идем дальше.

2. **Проверка порта (самое важное на этом шаге):** Попробуйте подключиться к портам 80 (HTTP) и 443 (HTTPS).

    ```bash
    telnet your-domain.com 80
    telnet your-domain.com 443
    ```

    * **Правильный ответ:** `Connected to your-domain.com`.
    * **Плохой ответ:** `Connection timed out` или `Connection refused`.
        * `Connection timed out`: Скорее всего, **[файрвол](../../../Linux/Networking/Settings/Persistent_Network/systemd_networkd.md)** на сервере или у облачного провайдера блокирует ваш IP или порт. Проверяйте правила `ufw`, `iptables` или security groups в облаке.
        * `Connection refused`: Nginx **не запущен** или слушает другой порт/IP.

### Проверка состояния Nginx

1. **Проверьте статус службы:** Для управления службами в современных Linux-системах используется `systemd`. Подробнее читайте в заметке об [управлении службами systemd](../../../Linux/Core/systemd/service_management.md).

    ```bash
    sudo systemctl status nginx
    ```

    * **`active (running)`:** Отлично, процесс запущен.
    * **`inactive (dead)` или `failed`:** Nginx не работает. Попробуйте запустить его: `sudo systemctl start nginx`. Если он не запускается, переходите к следующему шагу.

2. **Посмотрите, есть ли процесс в системе:**

    ```bash
    [`ps aux | grep nginx`](../../../Linux/Diagnostics/Processes/ps.md)
    ```

    Должны быть видны `master` и несколько `worker` процессов.

### Корректность конфигурации Nginx

1. **Запустите встроенный тест конфигурации Nginx:**

    ```bash
    sudo nginx -t
    ```

    * **`syntax is ok` и `test is successful`:** Синтаксис в порядке.
    * **Ошибки:** Nginx укажет на конкретный файл и строку с проблемой. Чаще всего это опечатки, забытая `;` или неправильные директивы. **Nginx не запустится, пока `nginx -t` не будет успешным.**

2. **Проверьте ключевые директивы** в файле конфигурации вашего сайта (`/etc/nginx/sites-available/your-domain.com`):
    * `listen`: Правильно ли указаны порты? `listen 80;`, `listen 443 ssl;`.
    * `server_name`: Указано ли ваше доменное имя? `server_name your-domain.com www.your-domain.com;`.
    * `root`: Правильно ли указан путь к файлам сайта?
    * `location`: Корректны ли блоки `location`? См. [Директива location](../Core/Location/basics.md).

### Анализ логов Nginx

Подробно о механизмах логирования в Nginx и доступных переменных можно прочитать в заметке **[Логирование в Angie/Nginx](../../Angie/angie_logging.md)**.

* **Лог ошибок:** `/var/log/nginx/error.log`
* **Лог доступа:** `/var/log/nginx/access.log`

Смотрите последние записи в логе ошибок в реальном времени, пока обновляете страницу сайта:

```bash
tail -f /var/log/nginx/error.log
```

**Распространенные ошибки в `error.log` и их причины:**

* **`"Permission denied"` (ошибка 403 Forbidden):**
  * **Проблема:** У рабочего процесса Nginx (обычно пользователь `www-data`) нет прав на чтение файлов сайта или на вход в директории.
  * **Решение:**
        1. Установите правильного владельца: `sudo chown -R www-data:www-data /path/to/your/site`.
        2. Установите правильные права: `sudo chmod -R 755 /path/to/your/site`. На все директории по пути к файлам должны быть права на исполнение (`+x`).

* **`"No such file or directory"` (ошибка 404 Not Found):**
  * **Проблема:** Директива `root` в конфиге Nginx указывает на неправильный путь, либо запрашиваемого файла действительно нет.
  * **Решение:** Проверьте путь в `root` и убедитесь, что файлы сайта лежат именно там.

* **`"connect() failed (111: Connection refused) while connecting to upstream"` (ошибка 502 Bad Gateway):**
  * **Проблема:** Nginx работает в режиме прокси (`proxy_pass`), но не может подключиться к бэкенд-приложению (например, Node.js, Python, PHP-FPM). Бэкенд либо не запущен, либо слушает не тот порт/IP. Подробнее о `proxy_pass` см. в заметке о [балансировке нагрузки](../Proxy/Load_Balancing/overview_concepts.md).
  * **Решение:**
        1. Проверьте, что ваш бэкенд запущен: `systemctl status my-app`.
        2. Проверьте, что он слушает тот же порт, что указан в `proxy_pass` (например, `127.0.0.1:8000`). Сделайте это с сервера Nginx: `curl http://127.0.0.1:8000`.

### Проверка системных ресурсов

* **Закончилось место на диске:** `df -h`
* **Закончилась оперативная память:** `free -m` или [`htop`](../../../Linux/Diagnostics/Processes/htop.md)
* **Высокая нагрузка на CPU:** [`htop`](../../../Linux/Diagnostics/Processes/htop.md)

## Дополнительная информация

Для автоматического анализа логов в скриптах часто используются утилиты `tail`, `awk` и `sed`. Базовые принципы их работы описаны в заметке [Основы shell](../../../Linux/Shell/shell_intro.md).

### Отслеживание новых записей в логе

Чтобы не обрабатывать весь лог-файл каждый раз, можно отслеживать только новые строки. Это делается путем сохранения смещения (количества уже обработанных строк).

```bash
# Файл для хранения смещения
OFFSET_FILE="/tmp/nginx_log_offset"
# Читаем последнее смещение или устанавливаем 0, если файл не существует
OFFSET=$(cat "$OFFSET_FILE" 2>/dev/null || echo 0)

LOG_SRC="/var/log/nginx/access.log"

# Считаем общее количество строк в логе
TOTAL_LINES=$(wc -l < "$LOG_SRC")
# Вычисляем количество новых строк
NEW_LINES=$((TOTAL_LINES - OFFSET))

if [ "$NEW_LINES" -gt 0 ]; then
  # Извлекаем только новые строки во временный файл для обработки
  tail -n "$NEW_LINES" "$LOG_SRC" > /tmp/nginx_new.log
  
  # ... здесь код для обработки /tmp/nginx_new.log ...
fi

# Сохраняем новое смещение для следующего запуска
echo "$TOTAL_LINES" > "$OFFSET_FILE"
```

### Извлечение данных с помощью `awk`

`awk` — мощный инструмент для обработки текста, разделенного на колонки. Он идеально подходит для парсинга логов Nginx.

Чтобы извлечь HTTP-статус код (9-я колонка в стандартном формате лога):

```bash
# Пример строки: 127.0.0.1 - - [21/May/2025:12:00:00 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.68.0"
# awk '{print $9}' вернет "200"
CODE=$(echo "$line" | awk '{print $9}')
```

### Фильтрация строк с помощью `sed`

`sed` (stream editor) отлично подходит для поиска и замены текста с использованием регулярных выражений.

**Пример: найти все строки с 5xx ошибками:**

```bash
# sed -n: не выводить строки по умолчанию
# '/.../p': найти шаблон и напечатать строку
sed -n '/HTTP\/[0-9.]*" 5[0-9[0-9] /p' /var/log/nginx/access.log
```

* `HTTP\/[0-9.]*"`: Находит часть запроса, например `HTTP/1.1"`.
* ` 5[0-9[0-9] `: Находит код от 500 до 599, окруженный пробелами.

**Пример: найти все строки с 4xx ошибками и записать в отдельный файл:**

```bash
sed -n 's/.*" [ ]*\(4[0-9[0-9]\) .*/&/p' /tmp/nginx_new.log >> "$LOG_4XX"
```

* `s/шаблон/замена/p`: команда замены, но так как в качестве замены используется `&` (вся совпавшая строка), она работает как фильтр.
* `\(4[0-9[0-9]\)`: Находит и "захватывает" код от 400 до 499.

| **Характеристика** | `awk` | `sed` |
| :--- | :--- | :--- |
| **Основное назначение** | Разбор по колонкам, вычисления, анализ | Потоковое редактирование, поиск и замена |
| **Логика** | Работа с полями (`$1`, `$2`) | Работа со строками и шаблонами |
