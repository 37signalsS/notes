# Nginx: отдача статических файлов

> **Надежность: 10** (Подтверждено актуальной документацией Nginx на июль 2026)

## Определения

**Отдача статики** — процесс передачи неизменяемых ресурсов (HTML-страницы — HyperText Markup Language, изображения, стили, скрипты) клиенту напрямую веб-сервером Nginx без участия бэкенд-приложений (PHP, Node.js, Python).

**Директива `root`** — задаёт базовый каталог, в котором Nginx ищет файлы. Полный путь к файлу на диске формируется путём добавления всего URI (Uniform Resource Identifier — унифицированный идентификатор ресурса) запроса к значению, указанному в `root`.

**Директива `alias`** — определяет замену части URI, совпавшей с блоком `location`, на указанный путь в файловой системе. В отличие от `root`, `alias` отбрасывает часть URI, указанную в `location`.

## Базовые концепции

### Директива `root`

`root` является наиболее часто используемой директивой для отдачи статического контента. Она может быть определена в контекстах `http`, `server` или `location`.

**Синтаксис:** `root /path/to/directory;`

**Принцип формирования пути:**
`Путь на диске = значение root + полный URI запроса`

**Пример:**

```nginx
server {
    root /var/www/html;

    location /images/ {
        # Запрос /images/photo.jpg -> /var/www/html/images/photo.jpg
    }
}
```

### Директива `alias`

`alias` используется, когда URI запроса не соответствует иерархии папок на диске. Она может быть определена только внутри контекста `location`.

**Синтаксис:** `alias /path/to/directory/;`

**Принцип формирования пути:**
`Путь на диске = значение alias + (URI запроса - значение location)`

**Пример:**

```nginx
location /static-data/ {
    alias /opt/media/files/;
    # Запрос /static-data/doc.pdf -> /opt/media/files/doc.pdf
    # Префикс "/static-data/" заменяется на "/opt/media/files/"
}
```

> **Безопасность (Off-by-slash):** Если `location` заканчивается слэшем, путь в `alias` также **обязательно** должен заканчиваться слэшем. Если в `location` слэш есть, а в `alias` — нет, Nginx может позволить прочитать файлы выше по дереву каталогов (Directory Traversal).

### Сравнение root и alias

| Характеристика | `root` | `alias` |
| :--- | :--- | :--- |
| **Формирование пути** | Добавляет URI целиком к пути | Заменяет префикс `location` на путь |
| **Контекст использования** | `http`, `server`, `location` | Только `location` |
| **Наследование** | Наследуется дочерними блоками | Не наследуется |
| **Регулярные выражения** | Полная поддержка | Требует именованных захватов |

## Практические сценарии

### Сценарий 1: Стандартный веб-сайт

Использование `root` на уровне `server` позволяет задать единую директорию для всего сайта.

```nginx
server {
    server_name example.com;
    root /var/www/mysite;

    location / {
        index index.html;
    }

    location /assets/ {
        # Использует основной root: /var/www/mysite/assets/
        expires 30d;
    }
}
```

### Сценарий 2: Отдача предварительно сжатых файлов (`gzip_static`)

Для экономии ресурсов CPU (Central Processing Unit — центральный процессор) можно отдавать заранее сжатые файлы (например, `.gz` или `.br`).

```nginx
location /static/ {
    root /var/www/html;
    # Nginx ищет файл.gz перед тем как сжимать его на лету
    gzip_static on; 
}
```

### Сценарий 3: Проверка существования файлов (`try_files`)

Директива `try_files` часто используется вместе с `root` для организации fallback-механизмов, особенно в SPA (Single Page Application — одностраничное приложение).

```nginx
location / {
    root /var/www/html;
    try_files $uri $uri/ /index.html =404;
}
```

## Оптимизация и безопасность

### Кэширование дескрипторов файлов

Под высокой нагрузкой Nginx тратит много ресурсов на системные вызовы `stat()`. Директива `open_file_cache` позволяет кэшировать информацию о файлах (дескрипторы, размеры, время модификации).

```nginx
open_file_cache max=1000 inactive=20s;
open_file_cache_valid 30s;
open_file_cache_min_uses 2;
open_file_cache_errors on;
```

### Сетевая оптимизация

Для эффективной отдачи статических файлов рекомендуется настроить следующие директивы:

- **`sendfile on;`** — Zero-Copy передача данных с диска в сокет, минуя пространство пользователя.
- **`tcp_nopush on;`** — отправка заголовков HTTP (Hypertext Transfer Protocol — протокол передачи гипертекста) и начала файла в одном пакете.
- **`tcp_nodelay on;`** — отключение алгоритма Нагла для быстрой отправки небольших данных.

### Защита от обхода символических ссылок

Для предотвращения доступа к файлам вне разрешенного `root` через символические ссылки используйте `disable_symlinks`.

```nginx
# Разрешить ссылки только внутри root
disable_symlinks on from=$document_root;
```
