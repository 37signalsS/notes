# Nginx: отдача статических файлов

> **Надежность: 10** (Подтверждено актуальной документацией Nginx на август 2026)

## Определения

**Отдача статики** — процесс передачи неизменяемых ресурсов (HTML-страницы — HyperText Markup Language, изображения, стили, скрипты, шрифты, видео) клиенту напрямую веб-сервером Nginx без участия бэкенд-приложений (PHP, Node.js, Python). Для SRE это baseline-сценарий, на котором проверяется эффективность кэширования ядром и сетевого стека.

**Директива `root`** — задаёт базовый каталог, в котором Nginx ищет файлы. Полный путь к файлу на диске формируется путём добавления всего URI (Uniform Resource Identifier — унифицированный идентификатор ресурса) запроса к значению, указанному в `root`.

**Директива `alias`** — определяет замену части URI, совпавшей с блоком `location`, на указанный путь в файловой системе. В отличие от `root`, `alias` отбрасывает часть URI, указанную в `location`. Критична для sysadmin при организации разделения доменов на одном сервере.

**MIME-типы (Multipurpose Internet Mail Extensions)** — механизм уведомления браузера о типе передаваемого контента через заголовок `Content-Type`. Неверный MIME-тип приводит к выполнению файлов в браузере вместо отображения (XSS-вектор).

**Директива `index`** — определяет список файлов, которые Nginx будет искать при запросе каталога (заканчивающегося слэшем). Если ни один файл из списка не найден, возвращается `403 Forbidden` или формируется листинг (при `autoindex on`).

**Директива `autoindex`** — включает режим автоматического листинга содержимого каталога при отсутствии индексного файла. Используется для внутренних хранилищ и репозиториев, но должен быть отключен в публичных зонах без контроля доступа.

**Директива `try_files`** — последовательно проверяет наличие файлов или директорий на диске и выполняет fallback-действие (внутренний редирект, возврат кода или проксирование). Основа работы SPA (Single Page Application) и современных фреймворков.

**Внутренний редирект (X-Accel-Redirect)** — механизм, при котором бэкенд-приложение передаёт Nginx управление на внутренний `location` с префиксом `internal`. Позволяет объединять авторизацию приложения и высокопроизводительную отдачу файлов из защищённых путей.

**Документный корень (document root)** — корневой каталог, ассоциированный с виртуальным хостом. Определяется директивой `root` в контексте `server` и наследуется всеми `location`, если не переопределён.

## Базовые концепции

### Директива `root`

`root` является наиболее часто используемой директивой для отдачи статического контента. Она может быть определена в контекстах `http`, `server` или `location`.

**Синтаксис:** `root /path/to/directory;`

**Принцип формирования пути:**
`Путь на диске = значение root + полный URI запроса`

**Пример:**

```nginx
server {
    root /var/www/html;

    location /images/ {
        # Запрос /images/photo.jpg -> /var/www/html/images/photo.jpg
    }
}
```

**Особенности наследования:**
- Если `root` определён в `http`, он наследуется всеми `server`.
- Если `root` определён в `server`, он наследуется всеми `location` внутри этого `server`.
- Если `root` определён в `location`, он переопределяет значение родителя только для этого блока.

### Директива `alias`

`alias` используется, когда URI запроса не соответствует иерархии папок на диске. Она может быть определена только внутри контекста `location`.

**Синтаксис:** `alias /path/to/directory/;`

**Принцип формирования пути:**
`Путь на диске = значение alias + (URI запроса - значение location)`

**Пример:**

```nginx
location /static-data/ {
    alias /opt/media/files/;
    # Запрос /static-data/doc.pdf -> /opt/media/files/doc.pdf
    # Префикс "/static-data/" заменяется на "/opt/media/files/"
}
```

> **Безопасность (Off-by-slash):** Если `location` заканчивается слэшем, путь в `alias` также **обязательно** должен заканчиваться слэшем. Если в `location` слэш есть, а в `alias` — нет, Nginx может позволить прочитать файлы выше по дереву каталогов (Directory Traversal).

### Директива `index`

Определяет файлы, которые Nginx ищет при запросе каталога. Поиск выполняется в порядке перечисления.

**Синтаксис:** `index file1 file2 ...;`

**Пример:**

```nginx
server {
    root /var/www/site;

    location / {
        index index.html index.htm index.php;
    }
}
```

При запросе `/` или `/docs/` Nginx попытается открыть `/var/www/site/index.html`, затем `/var/www/site/index.htm` и так далее.

### Сравнение `root` и `alias`

| Характеристика | `root` | `alias` |
| :--- | :--- | :--- |
| **Формирование пути** | Добавляет URI целиком к пути | Заменяет префикс `location` на путь |
| **Контекст использования** | `http`, `server`, `location` | Только `location` |
| **Наследование** | Наследуется дочерними блоками | Не наследуется |
| **Регулярные выражения** | Полная поддержка | Требует именованных захватов (`?name`) |

### Директива `try_files` в контексте статики

Проверяет существование ресурсов относительно `root` или `alias` и выполняет fallback.

**Синтаксис:** `try_files file ... uri | =code | @name;`

**Пример для SPA:**

```nginx
location / {
    root /var/www/app;
    try_files $uri $uri/ /index.html =404;
}
```

**Параметры:**
- `$uri` — нормализованный путь к файлу.
- `$uri/` — проверка существования директории (для индексных файлов).
- `/index.html` — внутренний редирект на файл.
- `=404` — возврат кода 404, если ни один путь не найден.

### MIME-типы и кодировки

Для корректного отображения файлов браузером необходимо правильно передавать заголовок `Content-Type`.

```nginx
http {
    include       mime.types;
    default_type  application/octet-stream;
    charset       utf-8;
}
```

- **`include mime.types;`** — подключает файл сопоставления расширений и MIME-типов.
- **`default_type`** — тип по умолчанию, если расширение неизвестно.
- **`charset`** — добавляет кодировку в заголовок `Content-Type`.

## Практические сценарии

### Сценарий 1: Стандартный веб-сайт

```nginx
server {
    server_name example.com;
    root /var/www/mysite;

    location / {
        index index.html index.htm;
    }

    location /assets/ {
        # Использует основной root: /var/www/mysite/assets/
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
}
```

### Сценарий 2: Отдача предварительно сжатых файлов (`gzip_static`)

Nginx может отдавать файл `.gz` с диска вместо того, чтобы сжимать оригинал на лету. Это экономит CPU. Подробнее о настройке сжатия см. **[Оптимизация сжатия в Nginx](../Performance/nginx_compression.md)**.

```nginx
location /static/ {
    root /var/www/html;
    gzip_static on; # Требует наличия файла.css.gz рядом с файлом.css
}
```

### Сценарий 3: Режим листинга файлов (`autoindex`)

Если в каталоге нет индексного файла, Nginx может сформировать список файлов автоматически.

```nginx
location /downloads/ {
    root /var/www/data;
    autoindex on;
    autoindex_exact_size off; # Показывать размер в КБ/МБ, а не байтах
    autoindex_localtime on;   # Использовать локальное время сервера
}
```

> **Безопасность:** `autoindex on` должен использоваться только в контролируемых зонах (внутренние репозитории, отладочные окружения). В публичных зонах листинг каталогов раскрывает структуру файловой системы.

### Сценарий 4: SPA и fallback (`try_files`)

```nginx
location / {
    root /var/www/app;
    try_files $uri $uri/ /index.html =404;
}
```

### Сценарий 5: Внутренняя отдача через `X-Accel-Redirect`

Бэкенд проверяет права доступа, а Nginx отдаёт файл из защищённого каталога.

```nginx
# В блоке server:
location /protected/ {
    internal;
    alias /data/secure/;
}

# В бэкенде (PHP/Python/Go):
# Header("X-Accel-Redirect: /protected/document.pdf");
```

### Сценарий 6: Отдача файлов из нескольких корней

Используется для организации зеркал или разделения статики по дискам разного типа (SSD/HDD).

```nginx
location /videos/ {
    root /mnt/hdd;
}

location /images/ {
    root /mnt/ssd;
}
```

## Оптимизация и безопасность

### Zero-Copy и сетевые оптимизации

Для высокопроизводительной отдачи файлов используются механизмы ядра ОС. Детальная настройка параметров ядра и сетевого стека описана в **[Тюнинг производительности Nginx](../Performance/nginx_performance_tuning.md)**.

Ключевые директивы, влияющие на отдачу статики:

- **`sendfile on;`** — включает Zero-Copy передачу данных.
- **`tcp_nopush on;`** — отправляет заголовки HTTP и начало файла в одном TCP-пакете.
- **`tcp_nodelay on;`** — отключает алгоритм Нагла.

### Продвинутые механизмы (AIO и DirectIO)

Для работы с очень большими файлами или при высокой фрагментации кэша ФС используются альтернативные методы:

- **`aio on;`** — (Asynchronous I/O) позволяет рабочему процессу не блокироваться в ожидании чтения с диска. На Linux требует `directio`.
- **`directio 512;`** — отключает кэширование на уровне ОС для файлов больше указанного размера.
- **`sendfile_max_chunk 512k;`** — ограничивает объем данных, передаваемый за один вызов `sendfile()`.

### Кэширование дескрипторов файлов (`open_file_cache`)

Позволяет Nginx не открывать файл заново при каждом запросе, сохраняя информацию в памяти. Рекомендуемые значения для высоконагруженных сайтов:

```nginx
open_file_cache max=10000 inactive=20s;
open_file_cache_valid 30s;
open_file_cache_min_uses 2;
open_file_cache_errors on;
```

### Защита файловой системы

- **`disable_symlinks on from=$document_root;`** — запрещает переход по символическим ссылкам, ведущим за пределы корневой директории сайта.
- **`internal;`** — (внутри `location`) делает файлы доступными только для внутренних перенаправлений Nginx (например, `X-Accel-Redirect`).

## Операции и команды

### Управление конфигурацией

```bash
# Проверка синтаксиса перед применением
nginx -t
# → nginx: configuration file /etc/nginx/nginx.conf test is successful

# Грациозная перезагрузка без потери соединений
nginx -s reload
# → graceful reload executed

# Принудительная перезагрузка (разрывает активные соединения)
nginx -s stop

# Просмотр работающих процессов
ps aux | grep nginx
```

### Проверка отдачи статики

```bash
# Проверка заголовков и кода ответа
curl -I https://example.com/assets/style.css

# Проверка с принудительным отключением кэша
curl -H "Cache-Control: no-cache" https://example.com/index.html

# Проверка отдачи сжатого контента
curl -H "Accept-Encoding: br" -I https://example.com/static/app.js

# Проверка листинга каталога
curl https://example.com/downloads/
```

### Управление правами (sysadmin)

```bash
# Установка владельца для корневого каталога сайта
chown -R www-data:www-data /var/www/mysite

# Установка прав: владелец — чтение/запись, группа и остальные — только чтение
chmod -R 755 /var/www/mysite

# Удаление прав на запись для группы и остальных (рекомендуется для статики)
chmod -R go-w /var/www/mysite

# Для каталогов с загрузкой пользователей (upload)
chmod 733 /var/www/uploads
```

### Управление кэшем файловой системы

```bash
# Просмотр page cache (требует root)
echo 3 > /proc/sys/vm/drop_caches

# Проверка количества открытых дескрипторов
ls /proc/$(cat /var/run/nginx.pid)/fd | wc -l
```

### SELinux/AppArmor (security hardening)

```bash
# Проверка контекста SELinux для файлов
ls -Z /var/www/html/

# Установка контекста для веб-контента (SELinux)
chcon -R -t httpd_sys_content_t /var/www/html/

# Для записываемых каталогов (upload, cache)
chcon -R -t httpd_sys_rw_content_t /var/www/uploads/

# AppArmor: проверка профиля Nginx
aa-status | grep nginx
```

## Диагностика и устранение неполадок

### Типичные ошибки

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `403 Forbidden` на статический файл | Нет прав на чтение файла или каталога | `chmod o+r` или проверка `disable_symlinks` |
| `404 Not Found` при существующем файле | Неверный `root`/`alias` или off-by-slash | Проверить `$document_root` через `return` |
| `403 Forbidden` при отключенном `autoindex` | Запрошен каталог без индексного файла | Добавить `index` или включить `autoindex` |
| Файл открывается как текст вместо скачивания | Отсутствует MIME-тип | Добавить `include mime.types;` или `default_type` |
| `404` после включения `alias` | В `alias` нет завершающего слэша | Добавить слэш, если `location` им заканчивается |
| Старый контент отдается после деплоя | Клиентский кэш без `Cache-Control: no-cache` | Использовать cache busting (хэши в именах) |

### Диагностические команды

```bash
# Определить, какой location обработал запрос (SRE-подход)
# В конфигурации добавьте:
# location / {
#     add_header X-Matched-Location "root-location" always;
# }

# Проверить переменную document_root для отладки
# location /test/ {
#     default_type text/plain;
#     return 200 "document_root: $document_root\nuri: $uri\n";
# }

# Просмотр логов доступа для статики
tail -f /var/log/nginx/access.log | grep "\.\(css\|js\|png\|jpg\)"

# Проверка настроек Open File Cache
curl http://localhost/stub_status 2>/dev/null || curl -s http://localhost/nginx_status 2>/dev/null || echo "stub_status не настроен"

# Анализ ошибок доступа
grep "denied" /var/log/nginx/error.log
```

### Проверка работы кэширования

```bash
# ETag и If-None-Match
curl -I https://example.com/static/file.js
# Должен присутствовать заголовок ETag

# Повторный запрос с валидацией
curl -H "If-None-Match: <etag>" -I https://example.com/static/file.js
# Должен вернуть 304 Not Modified
```

### Распространённые проблемы с `try_files`

1. **Бесконечный редирект:** `try_files $uri $uri/ /index.html` внутри `location /` вызывает `/index.html`, который снова попадает в тот же `location` и снова вызывает `try_files`.
   - **Решение:** Добавьте `index index.html;` или используйте именованный `location`.

2. **Потеря параметров запроса:** `try_files` передаёт только URI, query string отбрасывается.
   - **Решение:** Используйте `$is_args$args` в fallback: `try_files $uri $uri/ @backend;` и в `location @backend { proxy_pass http://backend$request_uri; }`.

## Лучшие практики

### Производительность

1. **Используйте `^~` для статических директорий.** Это прекращает поиск после нахождения самого длинного префикса и исключает проверку регулярных выражений, что критично для latency.
2. **Включайте `pcre_jit on;`** в контексте `main` для ускорения обработки регулярных выражений.
3. **Разделяйте статику по типам носителей:** горячая статика (CSS/JS) — на SSD, холодная (видео/архивы) — на HDD или объектное хранилище.
4. **Настраивайте `open_file_cache`** для сайтов с большим количеством мелких файлов (>1000).
5. **Используйте именованные locations** для fallback-механизмов вместо дублирования конфигурации.

### Безопасность

1. **Никогда не используйте `autoindex on`** в публичных зонах без контроля доступа.
2. **Блокируйте скрытые файлы и системные пути** на уровне `server`:

   ```nginx
   location ~ /\.(?!well-known) {
       deny all;
       access_log off;
       log_not_found off;
   }
   ```

3. **Отключайте симлинки** для каталогов, где пользователи могут загружать файлы:

   ```nginx
   disable_symlinks on from=$document_root;
   ```

4. **Используйте `internal`** для защищённых путей, доступных только через `X-Accel-Redirect`.
5. **Устанавливайте `merge_slashes on;`** (по умолчанию) для предотвращения атак обхода ограничений через двойные слэши.

### Эксплуатация (SRE)

1. **Ведение логов:** Настройте раздельные логи для статики и динамики, чтобы быстро диагностировать проблемы:

   ```nginx
   log_format static '$remote_addr - $remote_user [$time_local] '
                     '"$request" $status $body_bytes_sent '
                     '"$http_referer" "$http_user_agent"';

   location ~* \.(css|js|png|jpg|gif|ico|svg|woff2?)$ {
       access_log /var/log/nginx/static.access.log static;
   }
   ```

2. **Мониторинг:** Используйте `stub_status` или **[nginx-vts-monitoring-setup](../Operations/nginx_vts_monitoring_setup.md)** для отслеживания активных соединений и количества отданных файлов.
3. **Резервное копирование:** Статику следует выносить за пределы бэкапов конфигураций Nginx. Настройте `rsync` или файловые снэпшоты для `/var/www/`.
4. **Разделение ответственности:** Отдачу статики с TLS-терминацией лучше оставить на Nginx, а загрузку пользовательских файлов — вынести в отдельный виртуальный хост или поддомен для изоляции политик безопасности.
5. **Версионирование:** Для артефактов сборки (JS, CSS) используйте хэши в именах файлов. Это позволяет устанавливать `Cache-Control: immutable` с TTL 1 год без риска устаревшего контента.
