# Nginx: отдача статических файлов

> **Надежность: 10** (Подтверждено актуальной документацией Nginx на август 2026)

## Определения

**Отдача статики** — процесс передачи неизменяемых ресурсов (HTML-страницы — HyperText Markup Language, изображения, стили, скрипты) клиенту напрямую веб-сервером Nginx без участия бэкенд-приложений (PHP, Node.js, Python).

**Директива `root`** — задаёт базовый каталог, в котором Nginx ищет файлы. Полный путь к файлу на диске формируется путём добавления всего URI (Uniform Resource Identifier — унифицированный идентификатор ресурса) запроса к значению, указанному в `root`.

**Директива `alias`** — определяет замену части URI, совпавшей с блоком `location`, на указанный путь в файловой системе. В отличие от `root`, `alias` отбрасывает часть URI, указанную в `location`.

**MIME-типы (Multipurpose Internet Mail Extensions)** — механизм уведомления браузера о типе передаваемого контента через заголовок `Content-Type`.

**Директива `index`** — определяет список файлов, которые Nginx будет искать при запросе каталога (заканчивающегося слэшем).

## Базовые концепции

### Директива `root`

`root` является наиболее часто используемой директивой для отдачи статического контента. Она может быть определена в контекстах `http`, `server` или `location`.

**Синтаксис:** `root /path/to/directory;`

**Принцип формирования пути:**
`Путь на диске = значение root + полный URI запроса`

**Пример:**

```nginx
server {
    root /var/www/html;

    location /images/ {
        # Запрос /images/photo.jpg -> /var/www/html/images/photo.jpg
    }
}
```

### Директива `alias`

`alias` используется, когда URI запроса не соответствует иерархии папок на диске. Она может быть определена только внутри контекста `location`.

**Синтаксис:** `alias /path/to/directory/;`

**Принцип формирования пути:**
`Путь на диске = значение alias + (URI запроса - значение location)`

**Пример:**

```nginx
location /static-data/ {
    alias /opt/media/files/;
    # Запрос /static-data/doc.pdf -> /opt/media/files/doc.pdf
    # Префикс "/static-data/" заменяется на "/opt/media/files/"
}
```

> **Безопасность (Off-by-slash):** Если `location` заканчивается слэшем, путь в `alias` также **обязательно** должен заканчиваться слэшем. Если в `location` слэш есть, а в `alias` — нет, Nginx может позволить прочитать файлы выше по дереву каталогов (Directory Traversal).

### Сравнение root и alias

| Характеристика | `root` | `alias` |
| :--- | :--- | :--- |
| **Формирование пути** | Добавляет URI целиком к пути | Заменяет префикс `location` на путь |
| **Контекст использования** | `http`, `server`, `location` | Только `location` |
| **Наследование** | Наследуется дочерними блоками | Не наследуется |
| **Регулярные выражения** | Полная поддержка | Требует именованных захватов |

### MIME-типы и кодировки

Для корректного отображения файлов браузером необходимо правильно передавать заголовок `Content-Type`.

```nginx
http {
    include       mime.types;
    default_type  application/octet-stream;
    charset       utf-8;
}
```

- **`include mime.types;`** — подключает файл сопоставления расширений и MIME-типов.
- **`default_type`** — тип по умолчанию, если расширение неизвестно.
- **`charset`** — добавляет кодировку в заголовок `Content-Type`.

## Оптимизация сетевого ввода-вывода

Для высокопроизводительной отдачи файлов используются механизмы ядра ОС.

### Sendfile и сопутствующие оптимизации

- **`sendfile on;`** — включает Zero-Copy передачу данных. Данные копируются напрямую из кэша файловой системы в сетевой буфер ядра, минуя пространство пользователя.
- **`tcp_nopush on;`** — (только вместе с `sendfile`) заставляет Nginx отправлять заголовки HTTP и начало файла в одном TCP-пакете, минимизируя количество пакетов.
- **`tcp_nodelay on;`** — отключает алгоритм Нагла. Полезно для быстрой отправки небольших данных в режиме реального времени.

### Продвинутые механизмы (AIO и DirectIO)

Для работы с очень большими файлами или при высокой фрагментации кэша ФС используются альтернативные методы:

- **`aio on;`** — (Asynchronous I/O) позволяет рабочему процессу не блокироваться в ожидании чтения с диска. На Linux требует `directio`.
- **`directio 512;`** — отключает кэширование на уровне ОС для файлов больше указанного размера. Полезно для файлов, которые не помещаются в RAM, чтобы не вытеснять полезные данные из page cache.
- **`sendfile_max_chunk 512k;`** — ограничивает объем данных, передаваемый за один вызов `sendfile()`, чтобы одно медленное соединение не блокировало рабочий процесс надолго.

## Практические сценарии

### Сценарий 1: Стандартный веб-сайт

```nginx
server {
    server_name example.com;
    root /var/www/mysite;

    location / {
        index index.html index.htm;
    }

    location /assets/ {
        # Использует основной root: /var/www/mysite/assets/
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
}
```

### Сценарий 2: Отдача предварительно сжатых файлов (`gzip_static`)

Nginx может отдавать файл `.gz` с диска вместо того, чтобы сжимать оригинал на лету. Это экономит CPU.

```nginx
location /static/ {
    root /var/www/html;
    gzip_static on; # Требует наличия файла.css.gz рядом с файлом.css
}
```

### Сценарий 3: Режим листинга файлов (`autoindex`)

Если в каталоге нет индексного файла, Nginx может сформировать список файлов автоматически.

```nginx
location /downloads/ {
    root /var/www/data;
    autoindex on;
    autoindex_exact_size off; # Показывать размер в КБ/МБ, а не байтах
    autoindex_localtime on;   # Использовать локальное время сервера
}
```

### Сценарий 4: SPA и fallback (`try_files`)

```nginx
location / {
    root /var/www/app;
    try_files $uri $uri/ /index.html =404;
}
```

## Оптимизация и безопасность

### Кэширование дескрипторов файлов (`open_file_cache`)

Позволяет Nginx не открывать файл заново при каждом запросе, сохраняя информацию в памяти.

```nginx
open_file_cache max=1000 inactive=20s;
open_file_cache_valid 30s;
open_file_cache_min_uses 2;
open_file_cache_errors on;
```

### Контроль целостности и кэширования

- **`etag on;`** — (Entity Tag) включает генерацию уникального идентификатора версии файла. Позволяет клиенту проверить, изменился ли файл, без полной загрузки (через заголовок `If-None-Match`).
- **`if_modified_since exact;`** — управляет проверкой времени модификации файла.

### Защита файловой системы

- **`disable_symlinks on from=$document_root;`** — запрещает переход по символическим ссылкам, ведущим за пределы корневой директории сайта.
- **`internal;`** — (внутри `location`) делает файлы доступными только для внутренних перенаправлений Nginx (например, `X-Accel-Redirect`).
