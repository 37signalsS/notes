# Перенаправления и перезапись URI в Nginx

> **Надежность: 10** (Подтверждено актуальной документацией и техническими сценариями на июль 2026)

## Определения

Манипуляция **URI (Uniform Resource Identifier — унифицированный идентификатор ресурса)** — ключевая задача при обработке входящих запросов. В [Nginx](./nginx_overview.md) для этого используются директивы `rewrite`, `return` и `try_files`.

- **Rewrite (перезапись):** внутреннее изменение URI запроса на стороне сервера. Браузер клиента не получает уведомления об этом изменении.
- **Redirect (редирект):** внешнее перенаправление. Сервер отправляет клиенту ответ с кодом `3xx`, указывающий на новый **URL (Uniform Resource Locator — унифицированный указатель ресурса)**, по которому браузер должен выполнить новый запрос.

Концепции и примеры также применимы к [Angie](../../Angie/angie_overview.md).

## Базовые концепции

### Директива `rewrite`

Изменяет URI на основе регулярных выражений **PCRE (Perl Compatible Regular Expressions — Perl-совместимые регулярные выражения)**.

**Синтаксис:** `rewrite regex replacement [flag];`

| Флаг | Описание поведения |
| :--- | :--- |
| `last` | Прекращает текущую обработку и начинает новый поиск `location` с измененным URI. |
| `break` | Прекращает обработку `rewrite` и остается в текущем `location`. |
| `redirect` | Возвращает временный редирект (`302 Found`). |
| `permanent` | Возвращает постоянный редирект (`301 Moved Permanently`). |

> **Важно:** Nginx ограничивает количество внутренних перенаправлений (циклов) до **10**. Превышение лимита (например, при зацикливании `last`) приведет к ошибке `500 Internal Server Error`.

#### Работа с аргументами (Query String)

По умолчанию Nginx добавляет исходные аргументы запроса к новому URI. Чтобы отбросить их, добавьте знак вопроса `?` в конец строки замены:
`rewrite ^/users/(.*)$ /profile/$1? permanent;`

### Директива `return`

Наиболее эффективный способ прервать обработку и отправить ответ. Рекомендуется для простых редиректов, так как работает на уровне **FSM (Finite State Machine — конечный автомат)** Nginx без использования CPU (Central Processing Unit — центральный процессор) на Regex (Regular Expressions — регулярные выражения).

**Синтаксис:**
- `return code URL;` (например, `return 301 https://example.com;`)
- `return code [text];` (например, `return 403 "Access Denied";`)

### Директива `try_files`

Проверяет существование файлов или директорий в указанном порядке. Используется для реализации **ЧПУ (Человекопонятный URL)**.

**Синтаксис:** `try_files file ... uri | =code;`

```nginx
location / {
    # 1. Ищем файл. 2. Ищем папку. 3. Передаем в index.php
    try_files $uri $uri/ /index.php?$args;
}
```

## Условная логика: map и if

### Директива `map`

Безопасная и производительная альтернатива `if`. Позволяет создавать новые переменные на основе значений существующих. Объявляется только в контексте `http`.

```nginx
map $http_user_agent $is_mobile {
    default       0;
    "~*iphone|android" 1;
}
```

### Предостережение об использовании if («If is Evil»)

Директива `if` в контексте `location` часто ведет к непредсказуемому поведению и проблемам с производительностью.
**Безопасные операции внутри `if`:**
- `return ...`
- `rewrite ... last` / `break`

## Практические сценарии

### Сценарий 1: Редирект на HTTPS и основной домен

Наиболее частая задача для обеспечения безопасности через **SSL/TLS (Secure Sockets Layer / Transport Layer Security — протокол защищенных сокетов / безопасность транспортного уровня)**.

```nginx
server {
    listen 80;
    server_name www.example.com example.com;
    return 301 https://example.com$request_uri;
}
```

### Сценарий 2: Массовый редирект через map

Если нужно перенаправить сотни старых URL на новые без загромождения конфигурации.

```nginx
http {
    map $uri $new_uri {
        /old-page-1  /new-page-1;
        /old-page-2  /new-page-2;
    }

    server {
        if ($new_uri) {
            return 301 $new_uri;
        }
    }
}
```

### Сценарий 3: А/Б-тестирование (A/B Testing)

Разделение трафика на основе куки (**Cookie**) без изменения URL в браузере.

```nginx
map $cookie_test_group $backend_variant {
    "v1"    /index-a.html;
    "v2"    /index-b.html;
    default /index-default.html;
}

location / {
    try_files $backend_variant =404;
}
```

## Дополнительная информация

### Отладка и логирование

Для анализа работы правил `rewrite` используйте `rewrite_log`. Это добавит детальную информацию в `error_log` на уровне `notice`.

```nginx
server {
    rewrite_log on;
    error_log /var/log/nginx/error.log notice;
}
```
