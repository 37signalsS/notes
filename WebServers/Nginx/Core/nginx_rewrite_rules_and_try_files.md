# Перенаправления и перезапись URI в Nginx

> **Надежность: 10** (Подтверждено технической документацией и практическими сценариями на июнь 2026)

## Определения

Манипуляция **URI (Uniform Resource Identifier — унифицированный идентификатор ресурса)** — ключевая задача при обработке входящих запросов. В [Nginx](./nginx_overview.md) для этого используются директивы `rewrite`, `return` и `try_files`.

- **Rewrite (перезапись):** внутреннее изменение URI запроса на стороне сервера. Браузер клиента не знает об этом изменении.
- **Redirect (редирект):** внешнее перенаправление. Сервер отправляет клиенту ответ (обычно с кодом `3xx`), указывающий на новый **URL (Uniform Resource Locator — унифицированный указатель ресурса)**, по которому браузер должен выполнить новый запрос.

Концепции и примеры, описанные в этом файле, в равной степени применимы к [Angie](../../Angie/angie_overview.md), являющемуся форком Nginx.

## Базовые концепции

### Директива `rewrite`

Используется для изменения URI запроса на основе регулярных выражений **PCRE (Perl Compatible Regular Expressions — Perl-совместимые регулярные выражения)**.

**Синтаксис:** `rewrite regex replacement [flag];`

| Параметр | Описание |
| :--- | :--- |
| `regex` | Регулярное выражение для сопоставления с URI (без GET-параметров) |
| `replacement` | URI, на который будет перезаписан запрос; захваченные группы доступны как `$1`, `$2` |
| `flag` | Определяет дальнейшее поведение: `last`, `break`, `redirect`, `permanent` |

**Флаги `rewrite`:**

| Флаг | Тип | Поведение |
| :--- | :--- | :--- |
| `last` | Внутренний | Прекращает обработку текущих rewrite-правил, начинает новый поиск `location` с изменённым URI |
| `break` | Внутренний | Прекращает обработку rewrite, остаётся в текущем `location` с изменённым URI |
| `redirect` | Внешний | Возвращает код `302 Found` (временный редирект) |
| `permanent` | Внешний | Возвращает код `301 Moved Permanently` (постоянный редирект) |

### Директива `return`

Более простой и быстрый способ завершить обработку и отправить ответ, включая редиректы. Предпочтительнее `rewrite` для простых перенаправлений, так как не задействует движок регулярных выражений.

**Синтаксис:**

- `return code URL;`
- `return code [text];`

### Директива `try_files`

Проверяет существование файлов или директорий в указанном порядке и использует первый найденный ресурс. Если ничего не найдено, выполняется последнее действие. Идеально подходит для реализации **ЧПУ (Человекопонятный URL)**.

**Синтаксис:**

- `try_files file ... uri;`
- `try_files file ... =code;`

### Условная логика: map и if

#### Директива `map`

Безопасная, производительная и рекомендуемая альтернатива `if` для создания условной логики. Позволяет создавать переменные на основе значений других переменных. Объявляется в блоке `http`.

#### Предостережение об использовании if («If is Evil»)

Использование `if` в Nginx крайне не рекомендуется. Это может приводить к непредсказуемому поведению и проблемам с производительностью. Почти всегда существует лучшая альтернатива: `try_files`, `map` или [директива location](./Location/basics.md).

> **Безопасное использование:** директивы `return` и `rewrite ... last` надежно работают внутри `if`.

## Практические сценарии

### Редирект на HTTPS и новый домен

Задача: перенаправить трафик с HTTP на HTTPS или со старого URL на новый. Тесно связано с настройкой [SSL/TLS (Secure Sockets Layer / Transport Layer Security)](../Security/TLS_SSL/nginx_tls_ssl_overview.md).

**Решение через `return` (рекомендуется):**

```nginx
# 301 — HTTP → HTTPS
server {
    listen 80;
    server_name your_domain.com;
    return 301 https://$host$request_uri;
}
```

> **Производительность:** `return 301` работает на уровне **FSM (Finite State Machine — конечный автомат)** Nginx без запуска движка регулярных выражений. При высоком **RPS (Requests Per Second — запросов в секунду)** разница с `rewrite` ощутима.

### Внутренняя перезапись URI

Задача: изменить URI «на лету» без уведомления браузера.

```nginx
location /old-path/ {
    rewrite ^/old-path/(.*)$ /new-path/$1 last;
}
```

Флаг `last` заставляет Nginx начать новый цикл поиска подходящего `location` с уже изменённым путём.

### Настройка ЧПУ для фреймворков

Задача: направить все запросы, не соответствующие статическим файлам, на единую точку входа (например, `index.php`).

```nginx
location / {
    try_files $uri $uri/ /index.php?$args;
}
```

Переменная `$args` содержит все параметры запроса после знака `?`.

### А/Б-тестирование с помощью map

Задача: показывать разным пользователям разные версии страницы на основе файлов **cookie**, не изменяя URL.

```nginx
http {
    map $cookie_version $ab_test_page {
        default /index-old.html;
        new     /index-new.html;
    }

    server {
        location / {
            try_files $ab_test_page =404;
        }
    }
}
```

## Дополнительная информация

### Отладка правил перезаписи

Для диагностики работы правил включите логирование в блоке `server`:

```nginx
rewrite_log on;
error_log /var/log/nginx/error.log notice;
```

После этого в логе ошибок появятся записи о процессе сопоставления и изменения URI.

### Рекомендации по выбору инструмента

| Задача | Инструмент |
| :--- | :--- |
| Постоянный или временный редирект | `return` |
| Сложный редирект с регулярными выражениями | `rewrite ... redirect/permanent` |
| Внутренняя маршрутизация (перезапись) | `rewrite ... last` |
| Обработка статики с fallback на приложение | `try_files` |
| Условная логика на основе заголовков/cookie | `map` |
