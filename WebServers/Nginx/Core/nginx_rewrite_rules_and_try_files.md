# Nginx: Правила Rewrite, Redirect и Директива try_files

## Определения

Манипуляция URI — ключевая задача при обработке входящих запросов. В [[./nginx_overview.md|Nginx]] для этого используются директивы `rewrite`, `return` и `try_files`.

- **Перезапись (Rewrite):** Внутреннее изменение URI запроса на стороне сервера. Браузер не знает об этом изменении.
- **Редирект (Redirect):** Внешнее перенаправление. Сервер отправляет клиенту ответ (обычно с кодом 3xx), указывающий на новый URL, по которому браузер должен сделать новый запрос.

---

## Базовые концепции

### Директива `rewrite`
Используется для изменения URI запроса на основе регулярных выражений (PCRE).

**Синтаксис:** `rewrite regex replacement [flag];`
*   `regex`: Регулярное выражение для сопоставления с URI.
*   `replacement`: URI, на который будет перезаписан запрос. Захваченные группы из `regex` доступны как `$1`, `$2`.
*   `flag`: Определяет дальнейшее поведение (`last`, `redirect`, `permanent`).

### Директива `return`
Более простой и быстрый способ завершить обработку и отправить ответ, включая редиректы. Предпочтительнее `rewrite` для простых перенаправлений.

**Синтаксис:**
*   `return code URL;`
*   `return code [text];`

### Директива `try_files`
Проверяет существование файлов или директорий в указанном порядке и использует первый найденный ресурс. Если ничего не найдено, выполняется последнее действие. Идеально для "красивых" URL (ЧПУ).

Помимо статичных путей, директива может работать с переменными, что открывает возможности для более сложной логики (см. сценарий A/B тестирования ниже).

**Синтаксис:**
*   `try_files file ... uri;`
*   `try_files file ... =code;`

### Условная логика: `map` vs. `if`

#### Директива `map`
`map` — это безопасная, производительная и рекомендуемая альтернатива `if` для создания условной логики. Она позволяет создавать переменные на основе значений других переменных. Объявляется в блоке `http`.

**Синтаксис:**
```nginx
map $source_variable $new_variable {
    default value;
    "string" value1;
    ~regex   value2;
}
```

#### "If is Evil": Предостережение об использовании `if`
Использование `if` в Nginx **крайне не рекомендуется** ("If is Evil"). Это может приводить к непредсказуемому поведению и проблемам с производительностью. Почти всегда есть лучшая альтернатива (`try_files`, `map` или [[./nginx_location_directive.md|директиву location]]).

**Пример (не рекомендуется):**
```nginx
location / {
    if (!-f $request_filename) {
        rewrite ^(.*)$ /index.php?$1 last;
    }
}
```
Данный пример легко и правильно заменяется на `try_files $uri /index.php?$args;`.

## Практические сценарии

### Перенаправление (Redirect)

**Задача:** Перенаправить старый URL на новый или весь трафик с HTTP на HTTPS. Эта задача тесно связана с настройкой [[../Security/nginx_tls_ssl_configuration.md|безопасного соединения (SSL/TLS)]].

**Решение (`return`):**
Это лучший способ для простых редиректов, так как он не задействует движок регулярных выражений.

```nginx
# Постоянный редирект (301) с HTTP на HTTPS
server {
    listen 80;
    server_name your_domain.com;
    return 301 https://$host$request_uri;
}

# Редирект со старого URL на новый
location = /old-contacts {
    return 301 /contacts;
}
```

**Решение (`rewrite`):**
Используется для более сложных редиректов на основе регулярных выражений.

```nginx
# Временный редирект (302)
rewrite ^/tmp/(.*)$ /final/$1 redirect;

# Постоянный редирект (301)
# Осторожно: Браузеры агрессивно кэшируют этот редирект. Используйте `redirect` (302) во время отладки.
rewrite ^/username/(.*)$ /users/$1 permanent;
```

### Внутренняя перезапись (Rewrite)

**Задача:** Изменить URI "на лету" без ведома браузера.

**Решение (`rewrite` с флагом `last`):**
Nginx прекращает обработку текущего набора правил и начинает новый поиск `location` для измененного URI.

```nginx
rewrite ^/old/(.*)$ /new/$1 last;
```

### "Красивые" URL для фреймворков (ЧПУ)

**Задача:** Все запросы, которые не соответствуют статическим файлам, направить на единую точку входа (например, `index.php`). Этот паттерн часто используется в связке с [[../Proxy/nginx_load_balancing.md|балансировкой нагрузки]] и [[../Performance/nginx_proxy_caching.md|кэшированием]].

**Решение (`try_files`):**
Это самый эффективный и правильный способ.

```nginx
location / {
    # Пытаемся найти файл ($uri), затем директорию ($uri/).
    # Если не нашли, передаем управление на /index.php, сохраняя аргументы запроса.
    try_files $uri $uri/ /index.php?$args;
}
```

**Разбор аргументов `try_files`:**

*   **`$uri`**: Попробует найти файл, соответствующий URI запроса.
    *   Пример: если пользователь запросил `/about.html`, Nginx сначала проверит, существует ли файл `/var/www/html/about.html`.

*   **`$uri/`**: Если первый вариант не найден, проверяет, существует ли каталог с этим именем.
    *   Пример: `/blog/` → ищется каталог `/var/www/html/blog/`.

*   **`/index.php?$args`**: Если ничего из вышеперечисленного не найдено, запрос перенаправляется на `index.php` с оригинальными GET-параметрами (`$args`).
    *   `$args` — это переменная Nginx, содержащая все параметры запроса после `?`.
    *   Пример: если пользователь зашёл на `/post/42?comments=1`, Nginx отдаст `/index.php?comments=1`.

### Выборочное логирование с помощью `map`

**Задача:** Логировать редиректы в отдельный файл, чтобы не засорять основной лог доступа.

**Решение (`map`):**
`map` идеально подходит для этой задачи.

**Пример [[./nginx_setup.md|конфигурации в `nginx.conf`]] (блок `http`):**
```nginx
http {
    # ...
    log_format redirect_log '$remote_addr [$time_local] "$request" -> "$sent_http_location"';

    map $status $is_redirect {
        ~^3   1;
        default 0;
    }

    server {
        # ...
        access_log /var/log/nginx/redirects.log redirect_log if=$is_redirect;
        access_log /var/log/nginx/access.log main if=!$is_redirect;
        # ...
    }
}
```
1.  **`map`** создает переменную `$is_redirect`, которая равна `1`, если статус ответа `3xx`.
2.  **`access_log ... if=$is_redirect`** записывает в `redirects.log` только те запросы, которые привели к редиректу.
3.  Второй `access_log` с `if=!$is_redirect` исключает редиректы из основного лога.


### A/B тестирование с помощью `map`

**Задача:** Показывать разным пользователям разные версии страницы на основе `cookie`, не изменяя URL.

**Решение (`map` и `try_files`):**
```nginx
http {
    # ...
    # 1. Создаем переменную $ab_test_page, значение которой зависит от cookie 'version'
    map $cookie_version $ab_test_page {
        default /index-old.html; # Версия по умолчанию
        new     /index-new.html; # Новая версия для тестирования
    }

    server {
        listen 80;
        server_name site1.local;
        root /var/www/html;
        # ...

        # 2. Используем переменную в location
        location / {
            # Nginx проверит существование файла, указанного в $ab_test_page.
            try_files $ab_test_page =404;
        }
    }
}
```

**Разбор логики:**
1.  **Директива `map`**: Находится в блоке `http` и выполняется один раз за запрос. Она читает `cookie` с именем `version` (переменная `$cookie_version`). Если значение `new`, то `$ab_test_page` будет `/index-new.html`. В противном случае — `/index-old.html`.
2.  **Директива `try_files`**: Внутри `location` она использует уже вычисленное значение переменной `$ab_test_page` для поиска и отдачи нужного файла (`/var/www/html/index-new.html` или `/var/www/html/index-old.html`). Это крайне эффективно, так как вся логика определения переменной вынесена за пределы `location`.
