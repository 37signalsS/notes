# Установка и базовая настройка Nginx

## 1. Определения

**Nginx** — это веб-сервер и обратный прокси-сервер, используемый для обслуживания веб-контента, **[[../Proxy/nginx_load_balancing.md|балансировки нагрузки]]**, кэширования и многого другого. Для тех, кто интересуется альтернативами, существует заметка о **[[../../Angie/migration_from_nginx.md|миграции с Nginx на Angie]]**, его отечественном форке.

**Виртуальный хост (Server Block)** — блок конфигурации, описывающий отдельный сайт (домен). Позволяет одному серверу Nginx обслуживать множество сайтов.

> Для более глубокого обзора архитектуры и ключевых концепций обратитесь к файлу **[[./nginx_overview.md|Обзор Nginx]]**.

---

## 2. Базовые концепции: Структура конфигурации

*   **Главный файл:** `/etc/nginx/nginx.conf`. Это точка входа, которая подключает остальные файлы. Содержит глобальные настройки, такие как `user` и `worker_processes`. Оптимизация этих и других параметров рассмотрена в заметке о **[[../Performance/nginx_performance_tuning.md|тюнинге производительности Nginx]]**.

*   **Конфигурация сайтов (Виртуальных хостов):**
    *   **Debian/Ubuntu:** Используется система `sites-available` / `sites-enabled`.
        *   `/etc/nginx/sites-available/`: Содержит файлы конфигурации для всех сайтов.
        *   `/etc/nginx/sites-enabled/`: Содержит символические ссылки на файлы в `sites-available`, которые вы хотите активировать. Nginx читает только эту директорию.
    *   **CentOS/RHEL:** Используется директория `conf.d`.
        *   `/etc/nginx/conf.d/*.conf`: Nginx автоматически подключает все `.conf` файлы из этой директории. Сюда помещаются конфигурации всех сайтов.

## 3. Практические сценарии

### 3.1. Установка

Nginx может быть установлен непосредственно в операционную систему, как показано ниже, или запущен в контейнере, что подробно описано в руководстве по **[[../Operations/nginx_in_docker.md|запуску Nginx в Docker]]**.

#### Debian / Ubuntu
```bash
sudo apt update
sudo apt install nginx
```

#### CentOS / RHEL
```bash
# CentOS 7
sudo yum install epel-release && sudo yum install nginx

# CentOS 8+ / RHEL 8+
sudo dnf install epel-release && sudo dnf install nginx
```
*Замечание: В CentOS/RHEL пакет Nginx находится в репозитории EPEL (Extra Packages for Enterprise Linux), который может потребоваться установить.*

### 3.2. Управление сервисом

После установки Nginx обычно не запускается автоматически (особенно в CentOS/RHEL). Управление сервисом осуществляется с помощью стандартных команд `systemctl`. Подробнее о них можно прочесть в руководстве по **[[../../../Linux/Core/systemd/service_management.md|управлению службами Systemd]]**.

*   **Проверить статус:** `sudo systemctl status nginx`
*   **Запустить сервис:** `sudo systemctl start nginx`
*   **Добавить в автозагрузку:** `sudo systemctl enable nginx`
*   **Остановить сервис:** `sudo systemctl stop nginx`
*   **Перезагрузить конфигурацию:** `sudo systemctl reload nginx`
*   **Перезапустить сервис:** `sudo systemctl restart nginx`

### 3.3. Пример базовой конфигурации сайта

1.  **Создайте файл конфигурации:**
    *   На Ubuntu: `sudo nano /etc/nginx/sites-available/example.com`
    *   На CentOS: `sudo nano /etc/nginx/conf.d/example.com.conf`

2.  **Добавьте содержимое:**
    Центральным элементом является блок `location`, который определяет, как обрабатывать запросы. Для детального изучения его возможностей обратитесь к руководству **[[./nginx_location_directive.md|Глубокое погружение в директиву location]]**.
    ```nginx
    server {
        listen 80;
        listen [::]:80;

        # Это базовая конфигурация для HTTP. Для включения HTTPS (TLS/SSL)
        # и повышения безопасности, обратитесь к руководствам
        # [[../Security/nginx_tls_ssl_configuration.md|Настройка TLS/SSL в Nginx]] и
        # [[../Scenarios/nginx_with_letsencrypt.md|Nginx с Let's Encrypt]].

        server_name example.com www.example.com;

        root /var/www/example.com;
        index index.html;

        location / {
            try_files $uri $uri/ =404;
        }
    }
    ```
    Директива `try_files` в этом примере пытается найти файл, соответствующий URI запроса. Это базовый способ маршрутизации, более сложные сценарии рассматриваются в заметке о **[[./nginx_rewrite_rules_and_try_files.md|правилах rewrite, redirect и директиве try_files]]**.

    #### Ключевые директивы базовой конфигурации

    *   `listen 80;`: Указывает Nginx прослушивать входящие соединения на порту 80, который является стандартным портом для HTTP. Директива `listen [::]:80;` делает то же самое для протокола IPv6.

    *   `root /var/www/example.com;`: Задает корневой каталог, в котором Nginx будет искать файлы для этого сайта. Когда приходит запрос на `/page.html`, Nginx ищет его по пути `/var/www/example.com/page.html`.

    *   `index index.html;`: Сообщает Nginx, какой файл следует отдавать, если пользователь запрашивает целую директорию. Например, при запросе `http://example.com/` будет отдан файл `index.html` из директории, указанной в `root`.

    *   `server_name example.com www.example.com;`: Определяет, что данный блок `server` должен обрабатывать запросы, которые приходят на домены `example.com` и `www.example.com`. Такая запись `server_name site2.com www.site2.com;` используется, когда вы хотите, чтобы один и тот же блок `server` отвечал на запросы, приходящие на несколько доменных имён (например, с префиксом `www` и без него).

3.  **Создайте корневую директорию и тестовый файл:**
    ```bash
    sudo mkdir -p /var/www/example.com
    echo "Hello from Nginx!" | sudo tee /var/www/example.com/index.html
    ```

4.  **Активируйте сайт (только для Debian/Ubuntu):**
    ```bash
    sudo ln -s /etc/nginx/sites-available/example.com /etc/nginx/sites-enabled/
    ```

5.  **Проверьте и перезагрузите Nginx (см. раздел "Продвинутые детали"):**
    ```bash
    sudo nginx -t
    sudo systemctl reload nginx
    ```

Теперь при обращении к `http://example.com` (если DNS настроен) вы должны увидеть "Hello from Nginx!".

## 4. Продвинутые детали: Применение изменений

Nginx считывает конфигурацию только при запуске. Чтобы изменения вступили в силу, необходимо дать ему сигнал перечитать файлы.

**Правильная процедура:**

1.  **Проверка синтаксиса (Обязательно!):**
    Всегда проверяйте конфигурацию на наличие ошибок перед ее применением. Это защитит работающий сервер от сбоев.
    ```bash
    sudo nginx -t
    ```
    Если все в порядке, вы увидите `syntax is ok` и `test is successful`. В случае ошибки Nginx укажет на проблемный файл и строку, что является первым шагом в **[[../Operations/nginx_troubleshooting.md|диагностике неисправностей]]**.

2.  **Грациозная перезагрузка (`reload`):**
    Эта команда плавно применяет новую конфигурацию, обеспечивая **нулевое время простоя (zero downtime)**. Мастер-процесс Nginx читает новую конфигурацию и запускает новые рабочие процессы, в то время как старые рабочие процессы завершают обслуживание текущих запросов и после этого gracefully завершаются. Механизм основан на отправке сигнала `SIGHUP` мастер-процессу (см. **[[../../../Linux/Core/processes/signals.md|Сигналы в Linux]]**).
    ```bash
    sudo systemctl reload nginx
    ```

3.  **Полный перезапуск (`restart`):**
    **Никогда не используйте `restart`** для простого применения изменений конфигурации. Эта команда полностью останавливает все процессы Nginx и запускает их заново, что приводит к кратковременному простою и обрыву всех текущих соединений. `restart` следует использовать только в крайних случаях, например, при обновлении версии Nginx или если `reload` не помогает.
