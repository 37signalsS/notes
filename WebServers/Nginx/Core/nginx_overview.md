# Обзор Nginx

> **Надежность: 10** (Подтверждено актуальной документацией Nginx на июль 2026)

## Определения

**Nginx** (произносится как "engine-x") — это высокопроизводительный веб-сервер, обратный прокси-сервер, кэширующий прокси и балансировщик нагрузки с открытым исходным кодом. Он известен своей высокой производительностью, стабильностью, богатым набором функций, простой конфигурацией и низким потреблением системных ресурсов.

Чаще всего Nginx используется в следующих ролях:

- **Веб-сервер** для быстрой отдачи статического контента.
- **Обратный прокси-сервер (Reverse Proxy)** для передачи запросов приложениям на PHP (Hypertext Preprocessor — препроцессор гипертекста), Python, Node.js и др.
- **Балансировщик нагрузки** для распределения входящего трафика между группой бэкенд-серверов.
- **Кэширующий HTTP (Hypertext Transfer Protocol — протокол передачи гипертекста) сервер** для ускорения ответов и снижения нагрузки на бэкенд.
- **TLS (Transport Layer Security — безопасность транспортного уровня) терминатор** для централизованной обработки зашифрованного трафика HTTPS (Hypertext Transfer Protocol Secure — защищенный протокол передачи гипертекста).

### Nginx и его форки

- **История и статус:** Nginx, созданный Игорем Сысоевым, является отраслевым стандартом. После ухода F5 из России в 2022 году, оригинальная команда разработчиков создала форк **Angie**.
- **Angie:** Предлагает полную совместимость с Nginx, но включает в свободную версию функции, которые в Nginx доступны только в платной версии Plus (например, расширенное API (Application Programming Interface — программный интерфейс приложения) мониторинга, динамические апстримы). Подробнее см. в **[обзоре Angie](../../Angie/angie_overview.md)**.

## Базовые концепции

### Архитектура: решение проблемы C10k

Эффективность Nginx основана на решении **"проблемы C10k"** — задачи обслуживания 10 000 одновременных соединений при минимальных затратах ресурсов. Подробности механизмов мультиплексирования описаны в разделе **[Мультиплексирование ввода-вывода](../../../Networking/Concepts/io_multiplexing.md)**.

#### Процессная модель: Master и Worker

Архитектура Nginx построена на разделении ролей:

1.  **Мастер-процесс (Master Process):** Работает от имени `root`. Отвечает за чтение конфигурации, открытие сетевых портов и управление рабочими процессами.
2.  **Рабочие процессы (Worker Processes):** Работают от имени непривилегированного пользователя (например, `www-data`). Обрабатывают сетевые соединения. Обычно количество воркеров равно количеству ядер CPU (Central Processing Unit — центральный процессор).
3.  **Разделяемая память (Shared Memory):** Используется для взаимодействия воркеров, хранения зон кэширования, лимитов запросов и статистики.

#### Событийно-ориентированная модель

В отличие от классических серверов (например, Apache `pre-fork`), создающих отдельный процесс или поток на каждое соединение, Nginx использует **асинхронную модель на базе событий (Event-driven)**.

- **Один процесс — тысячи соединений:** Worker не блокируется в ожидании данных от клиента, а переключается на другие задачи через системные вызовы `epoll` (Linux) или `kqueue` (BSD).
- **Zero-Copy (sendfile):** Nginx использует механизм `sendfile` для передачи данных с диска напрямую в сетевой сокет, минуя копирование в пространство пользователя.

### Модульность и расширяемость

Nginx имеет модульную структуру. Функциональность (Gzip, SSL, Proxy) реализована в виде модулей:

- **Статические модули:** Скомпилированы в бинарный файл.
- **Динамические модули:** Подключаются через директиву `load_module` в конфигурации.

Современные версии Nginx поддерживают современные протоколы, такие как **HTTP/3 (QUIC)**, и интеграцию с технологиями ядра Linux, такими как **eBPF** (Extended Berkeley Packet Filter) для оптимизации UDP-трафика.

## Практические сценарии

### Виртуальные хосты (Server Blocks)

Nginx позволяет обслуживать тысячи доменов на одном IP (Internet Protocol — интернет-протокол) адресе.

**Механизм выбора:**
Nginx анализирует HTTP-заголовок `Host` и сопоставляет его с директивой `server_name` в конфигурации. Если совпадений нет, используется `default_server`.

Примеры настройки и структуры файлов приведены в руководстве по **[установке и настройке Nginx](./nginx_setup.md)**.
