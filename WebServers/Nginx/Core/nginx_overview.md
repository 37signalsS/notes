# Обзор Nginx

## Определения

**Nginx** (произносится как "engine-x") — это высокопроизводительный веб-сервер, обратный прокси-сервер, кэширующий прокси и балансировщик нагрузки с открытым исходным кодом. Он известен своей высокой производительностью, стабильностью, богатым набором функций, простой конфигурацией и низким потреблением ресурсов.

Чаще всего Nginx используется в следующих ролях:

- **Веб-сервер** для отдачи статического контента.
- **Обратный прокси-сервер (Reverse Proxy)** для приложений на PHP (Hypertext Preprocessor), Python, Node.js и т.д.
- **Балансировщик нагрузки** для распределения трафика между несколькими бэкенд-серверами.
- **Кэширующий HTTP (HyperText Transfer Protocol) сервер** для ускорения ответов.
- **TLS (Transport Layer Security) / SSL (Secure Sockets Layer) терминатор** для централизованной обработки HTTPS (HyperText Transfer Protocol Secure).

### Nginx и его форки

- **История:** Nginx, созданный Игорем Сысоевым, является самым популярным веб-сервером в мире. После того как компания F5 (владелец Nginx) закрыла московский офис разработки в 2022 году, ключевая команда разработчиков создала форк проекта под названием **Angie**.
- **Экосистема:** Angie предлагает полную совместимость с Nginx, но включает в Open Source версию многие функции, которые в Nginx являются частью платного продукта Nginx Plus. Также Angie предоставляет готовые пакеты с популярными сторонними модулями, которые для Nginx часто требуют ручной компиляции. Подробнее см. в **[обзоре Angie](../../Angie/angie_overview.md)**.

## Базовые концепции

### Архитектура: Решение проблемы C10k

Понимание архитектуры Nginx объясняет, почему он так эффективно справляется с высокой нагрузкой. Основа этого отличия лежит в решении **"проблемы C10k"** — задачи обслуживания 10 000 одновременных соединений. Глубокое описание механизмов I/O мультиплексирования приведено в разделе **[Мультиплексирование ввода-вывода](../../../Networking/Concepts/io_multiplexing.md)**.

#### Классическая модель: Процесс на соединение (Apache `pre-fork`)

Классические веб-серверы, как Apache в режиме `mpm_prefork`, выделяли **отдельный рабочий процесс на каждое активное подключение**.

- **Высокое потребление памяти:** Каждый процесс потреблял значительное количество оперативной памяти (десятки мегабайт, особенно с `mod_php`), даже если просто ожидал данных от медленного клиента.
- **Результат:** При росте числа соединений сервер быстро исчерпывал оперативную память. Обслужить 10 000 соединений в такой модели было практически невозможно.

#### Модель Nginx: Асинхронность и управление событиями

Nginx был спроектирован с нуля на основе **асинхронной, событийно-ориентированной модели (event-driven)**.

- **Мастер-процесс и воркер-процессы:** Nginx запускает один мастер-процесс (выполняет привилегированные операции, такие как чтение конфигурации и открытие портов) и несколько воркер-процессов (обрабатывают запросы). Количество воркеров обычно равно числу ядер процессора.
- **Один рабочий процесс на тысячи соединений:** Рабочий процесс Nginx (worker) является однопоточным и использует неблокирующий ввод-вывод для обработки тысяч соединений одновременно.
- **Минимальное потребление ресурсов:** Вместо того чтобы "зависать" в ожидании данных, worker немедленно переключается на обработку событий от других соединений. Это позволяет обслуживать огромное количество подключений с минимальными и предсказуемыми затратами памяти и CPU (Central Processing Unit).

Nginx превосходно справляется с **управлением соединениями** для любого типа контента:

- **Статика:** Отдает статические файлы (HTML (HyperText Markup Language), CSS (Cascading Style Sheets), JS (JavaScript), изображения) напрямую и очень быстро.
- **Динамика:** Для динамических запросов Nginx проксирует запрос на специализированный бэкенд (например, PHP-FPM (PHP FastCGI Process Manager), Gunicorn, uWSGI), эффективно ожидая ответа и передавая его клиенту.

## Практические сценарии

### Виртуальные хосты (Server Blocks)

Виртуальные хосты позволяют одному серверу Nginx обслуживать множество сайтов (доменов) на одном IP (Internet Protocol) адресе. В терминологии Nginx они называются `server` блоками.

**Принцип работы:**
Nginx принимает запрос, смотрит на заголовок `Host` и ищет `server` блок, у которого директива `server_name` совпадает с этим заголовком.

Детальное описание работы `server_name` и примеры базовой конфигурации приведены в руководстве по **[установке и настройке Nginx](./nginx_setup.md#пример-базовой-конфигурации-сайта)**.
