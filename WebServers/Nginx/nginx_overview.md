# Nginx Overview

Nginx (произносится как "engine-x") — это высокопроизводительный веб-сервер, который также может использоваться как обратный прокси-сервер (reverse proxy), балансировщик нагрузки, кэширующий HTTP-сервер и почтовый прокси-сервер.

## Установка

В CentOS/RHEL Nginx устанавливается пакетом `nginx` с помощью пакетного менеджера `yum` или `dnf`:

```bash
sudo yum install nginx
# или
sudo dnf install nginx
```

## Управление службой

Управление службой Nginx осуществляется через `systemctl`:

```bash
sudo systemctl start nginx.service    # Запустить Nginx
sudo systemctl stop nginx.service     # Остановить Nginx
sudo systemctl restart nginx.service  # Перезапустить Nginx
sudo systemctl reload nginx.service   # Перечитать конфигурацию без полного перезапуска
sudo systemctl status nginx.service   # Проверить статус
```

**Разница между `reload` и `restart`:**
*   **`reload`**: "Вежливо" просит службу перечитать свой конфигурационный файл без прерывания работы. Существующие соединения не разрываются. Этот метод работает, только если служба его поддерживает.
*   **`restart`**: "Жестко" останавливает все процессы службы и запускает их заново. Это всегда работает, но приводит к кратковременному простою.

## Конфигурационные файлы

Основной конфигурационный файл Nginx — `nginx.conf`, который обычно находится в директории `/etc/nginx/`. Этот файл содержит глобальные настройки сервера и может включать другие конфигурационные файлы из директорий, таких как `/etc/nginx/conf.d/`.

**Ключевые секции конфигурации:**

*   **`http`**: Глобальные настройки HTTP-сервера.
*   **`server`**: Определяет виртуальный хост (сайт).
*   **`location`**: Определяет, как Nginx обрабатывает запросы для различных URL-путей.

## История

Изначально разработан Игорем Сысоевым в 2002 году для решения проблемы C10k (обслуживание 10 000 одновременных соединений) для веб-сервиса Rambler. Впоследствии Nginx был выпущен как open-source проект и быстро набрал популярность благодаря своей производительности, стабильности, богатому набору функций и низкому потреблению ресурсов.

## Архитектура и производительность

Nginx был разработан для эффективного решения проблемы C10k, которая заключалась в неэффективной обработке большого количества одновременных соединений традиционными веб-серверами (например, Apache в режиме Prefork). В отличие от Apache, который запускал отдельный процесс для каждого соединения, Nginx использует асинхронную, событийно-ориентированную архитектуру (event loop).

Ключевые особенности архитектуры Nginx:
*   **Мастер-процесс и воркер-процессы:** Nginx запускает один мастер-процесс, который управляет несколькими воркер-процессами.
*   **Однопоточные воркеры:** Каждый воркер-процесс является однопоточным и может эффективно обрабатывать тысячи одновременных соединений благодаря неблокирующему вводу/выводу. Количество воркеров обычно настраивается по числу ядер процессора для оптимального распределения нагрузки.
*   **Низкое потребление ресурсов:** Благодаря своей архитектуре Nginx является легковесным и очень эффективным веб-сервером, способным обслуживать большое количество запросов при минимальных затратах оперативной памяти.

В 2019 году компания Nginx, Inc. была приобретена компанией F5 Networks.

## Модели версий

Nginx имеет две основные ветки разработки:

*   **Stable (стабильная):** Рекомендуется для производственных сред. Включает в себя только исправления критических ошибок и обновлений безопасности. Новые функции в эту ветку не добавляются. Версии имеют четный второй номер (например, `1.22.x`).
*   **Mainline (основная):** Активно развивающаяся ветка, в которую добавляются новые функции и улучшения. Несмотря на то, что она считается "бета-версией", она достаточно стабильна для использования в production. Версии имеют нечетный второй номер (например, `1.23.x`).

## Ключевые возможности

*   **Обработка статического контента:** Эффективная отдача статических файлов.
*   **Reverse Proxy:** Проксирование запросов к бэкенд-серверам (например, к приложениям на Python, PHP, Node.js).
*   **Правила Rewrite и Redirect:** Гибкое изменение URI запросов и перенаправление клиентов.
*   **Балансировка нагрузки:** Распределение трафика между несколькими бэкенд-серверами, включая [L4 (TCP/UDP) балансировку и проксирование](./nginx_l4_proxying.md).
*   **Кэширование:** Кэширование ответов от бэкенд-серверов для ускорения повторных запросов.
*   **SSL/TLS Termination:** Централизованная обработка HTTPS-трафика.
*   **Модульная архитектура:** Функциональность может быть расширена с помощью модулей. Некоторые важные функции, такие как поддержка [Brotli](https://github.com/google/ngx_brotli) или HTTP/3, требуют подключения сторонних или экспериментальных модулей.
*   **Оптимизация веб-приложений:** Nginx играет ключевую роль в [оптимизации производительности веб-приложений](../Concepts/web_application_optimization_overview.md) за счет компрессии, кэширования, терминирования TLS и поддержки современных протоколов HTTP.

## Nginx Plus

Nginx Plus — это коммерческая версия Nginx с расширенными возможностями, такими как расширенный мониторинг, динамическая реконфигурация бэкендов, поддержка кластеризации и техническая поддержка от F5.

## Angie Web Server

Angie — это форк Nginx, созданный бывшими разработчиками Nginx из московского офиса после ухода F5 Networks из России. Angie является drop-in заменой для Nginx, полностью совместимой по конфигурации, но предлагающей дополнительные возможности, такие как расширенная статистика и динамическая конфигурация.

## Nginx vs. Apache

Основное архитектурное различие между Nginx и Apache заключается в подходе к обработке соединений, что напрямую влияет на их производительность под высокой нагрузкой.

*   **Apache (в режиме `prefork`):**
    *   **Архитектура:** Запускает один мастер-процесс, который создает несколько дочерних процессов (воркеров). Каждый воркер обрабатывает одно соединение.
    *   **Проблема C10k:** При большом количестве одновременных соединений (например, 10 000) это приводит к запуску 10 000 воркеров. Каждый такой процесс потребляет значительный объем оперативной памяти (даже если он простаивает), что ведет к высокому потреблению ресурсов и неэффективности. Это известно как **проблема C10k**.

*   **Nginx:**
    *   **Архитектура:** Использует асинхронную, событийно-ориентированную модель (event loop) и неблокирующий ввод-вывод.
    *   **Решение проблемы C10k:** Один однопоточный рабочий процесс (worker process) может эффективно обрабатывать тысячи соединений одновременно. Вместо того чтобы блокироваться в ожидании ответа от диска или сети, Nginx переключается на обработку других событий. Это позволяет ему обслуживать огромное количество соединений с минимальным потреблением памяти и процессорного времени.

Изначально Nginx был создан именно для решения проблемы C10k и эффективной работы в условиях высоких нагрузок, что и стало причиной его популярности.
