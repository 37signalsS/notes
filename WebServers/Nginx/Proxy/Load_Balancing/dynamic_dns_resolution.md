# Динамическое разрешение DNS в Upstream — Nginx

## Определения

- **Динамическое разрешение DNS** — механизм, при котором Nginx периодически перечитывает DNS-записи для серверов в блоке `upstream`, автоматически обновляя их IP-адреса без перезагрузки конфигурации.
- **`resolver`** — директива, указывающая Nginx DNS-сервер для разрешения имён и время кэширования ответов.
- **`resolve`** — параметр директивы `server` в блоке `upstream`, активирующий периодическое обновление DNS-записи.

## Основные концепции

По умолчанию Nginx разрешает [доменные имена](../../../../Networking/Protocols/DNS/dns.md) серверов в блоке `upstream` только один раз — при загрузке конфигурации. Если IP-адрес бэкенда изменится (облачная среда, Docker, Kubernetes), Nginx продолжит отправлять трафик на старый адрес до следующей перезагрузки.

Директива `resolver` решает эту проблему, заставляя Nginx периодически опрашивать указанный DNS-сервер и обновлять IP-адреса бэкендов.

> **Историческая справка:** эта функция долгое время была эксклюзивом Nginx Plus. Позднее она появилась в open-source версии Angie, а затем была перенесена и в Nginx Open Source.

## Практические сценарии

### Базовая конфигурация с динамическим DNS

```nginx
http {
    # Указываем DNS-сервер и время кэширования записи
    resolver 1.1.1.1 valid=10s;

    upstream backend {
        # Nginx будет периодически перечитывать DNS-запись для этого хоста
        server backend.example.com resolve;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://backend;
        }
    }
}
```

### Параметры директив

| Директива / параметр | Описание |
|:---------------------|:---------|
| `resolver <address> [valid=<time>]` | Определяет DNS-сервер для разрешения имён. Параметр `valid` задаёт время кэширования DNS-ответа (по умолчанию используется TTL из записи). |
| `server <hostname> resolve` | Указывает Nginx использовать `resolver` для периодического обновления IP-адреса. |

> **Важно:** директива `resolver` в контексте `http` обязательна при использовании `resolve`. Без неё Nginx выдаст ошибку конфигурации.

### Применение в контейнерных средах

Механизм критически важен при работе с динамическими окружениями:

- **Kubernetes** — IP-адреса подов меняются при рестарте или масштабировании
- **Docker Compose** — имена сервисов резолвятся во внутренние IP контейнеров
- **Облачные платформы** — DNS-имена могут указывать на меняющийся пул адресов за load balancer'ом
