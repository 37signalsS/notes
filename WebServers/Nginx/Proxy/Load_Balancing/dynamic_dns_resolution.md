# Динамическое разрешение DNS в Upstream — Nginx

## Определения

**Динамическое разрешение DNS** — механизм, при котором Nginx периодически перечитывает DNS-записи для серверов в блоке upstream, автоматически обновляя их IP-адреса без перезагрузки конфигурации.

**resolver** — директива Nginx, указывающая адрес DNS-сервера для разрешения имён и время кэширования ответов.

**resolve** — параметр директивы server в блоке upstream, активирующий периодическое обновление IP-адреса через DNS.

## Основные концепции

По умолчанию Nginx разрешает [доменные имена](../../../../Networking/Protocols/DNS/dns.md) серверов в блоке upstream только один раз — в момент загрузки или перезагрузки конфигурации. Если IP-адрес бэкенда изменится (например, в облачной среде, Docker или Kubernetes), Nginx продолжит отправлять трафик на старый адрес до следующего выполнения `reload`.

Директива `resolver` в сочетании с параметром `resolve` позволяет Nginx периодически опрашивать DNS-сервер и обновлять IP-адреса бэкендов в оперативной памяти без прерывания обработки запросов.

Данная функциональность изначально была доступна только в коммерческой версии Nginx Plus, однако позже она появилась в open-source версии форка Angie, а затем была реализована и в Nginx Open Source.

## Практические сценарии

### Базовая конфигурация с динамическим DNS

Для работы механизма необходимо определить DNS-сервер в контексте `http` и добавить параметр `resolve` к соответствующим серверам в блоке `upstream`.

```nginx
http {
    # Указываем DNS-сервер и время кэширования записи
    resolver 1.1.1.1 valid=10s;

    upstream backend {
        # Зона разделяемой памяти обязательна для работы resolve
        zone backend_zone 64k;

        # Nginx будет периодически перечитывать DNS-запись для этого хоста
        server backend.example.com resolve;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://backend;
        }
    }
}
```

### Параметры директив

| Директива / параметр | Описание |
| :--- | :--- |
| `resolver <address> [valid=<time>]` | Определяет DNS-сервер. Параметр `valid` задаёт время кэширования ответа (по умолчанию используется TTL записи). |
| `server <hostname> resolve` | Указывает Nginx использовать `resolver` для обновления IP-адреса. |
| `zone <name> <size>` | Выделяет область памяти для хранения состояния группы серверов, что необходимо для работы `resolve`. |

При использовании `resolve` наличие директивы `resolver` в контексте `http` является обязательным. В противном случае Nginx выдаст ошибку при проверке конфигурации.

### Применение в динамических средах

Механизм критически важен для обеспечения непрерывности работы в инфраструктурах, где IP-адреса узлов могут меняться:

- **Kubernetes** — адреса подов меняются при пересоздании или масштабировании.
- **Docker Compose** — имена сервисов резолвятся во внутренние IP-адреса контейнеров.
- **Облачные платформы** — DNS-имена (FQDN) могут указывать на динамически меняющийся пул адресов балансировщика нагрузки.
