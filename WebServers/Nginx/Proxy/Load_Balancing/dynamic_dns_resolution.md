# Динамическое разрешение DNS в Upstream — Nginx

## Определения

**Динамическое разрешение DNS (Dynamic DNS Resolution)** — механизм, позволяющий Nginx периодически обновлять IP-адреса бэкендов в блоке `upstream` на основе DNS-записей без перезагрузки конфигурации (`reload`).

**resolver** — директива, определяющая DNS-серверы, которые Nginx будет использовать для разрешения имён в рантайме. С версии Nginx 1.27.3 может располагаться непосредственно внутри блока `upstream`.

**resolve** — параметр директивы `server` в блоке `upstream`, указывающий Nginx периодически перечитывать DNS-запись для данного хоста.

**service** — параметр директивы `server` (Angie/Nginx Plus), позволяющий разрешать имена через DNS SRV-записи (автоматическое получение портов, весов и приоритетов).

## Основные концепции

### Проблема статического разрешения
По умолчанию Nginx разрешает доменные имена бэкендов **только один раз** в момент старта или `reload`. Если IP-адрес сервера изменится (типично для Kubernetes, Docker или облачных балансировщиков), Nginx продолжит отправлять трафик на старый IP, что приведет к ошибкам (502/504).

### Версионные ограничения и возможности
До версии 1.27.3 параметр `resolve` был доступен только в Nginx Plus и Angie. В ноябре 2024 года функционал был перенесен в Nginx OSS.

| Функция | Nginx OSS (< 1.27.3) | Nginx OSS (1.27.3+) | Angie (OSS) | Nginx Plus |
| :--- | :--- | :--- | :--- | :--- |
| **Параметр `resolve`** | Нет | **Да** | Да | Да |
| **Поддержка SRV (`service`)** | Нет | Нет | **Да** | Да |
| **`resolver` в `upstream`** | Нет | **Да** | Да | Да |
| **Авто-настройка из `resolv.conf`** | Нет | Нет | **Да (`resolver conf`)** | Нет |

## Практические сценарии

### 1. Нативная динамика (Nginx 1.27.3+ / Angie / Plus)
Наиболее эффективный метод. Поддерживает `keepalive` соединения и все алгоритмы балансировки.

```nginx
http {
    # Для Angie: можно использовать системные настройки DNS
    # resolver conf; 

    upstream app_servers {
        # Зона разделяемой памяти ОБЯЗАТЕЛЬНА для работы resolve
        zone backend_zone 128k;

        # Резолвер можно указать прямо в апстриме (Nginx 1.27.3+)
        resolver 127.0.0.11 valid=10s;
        resolver_timeout 5s;

        # Периодическое обновление IP
        server backend.example.com resolve;
        
        # Только для Angie/Plus: поддержка SRV-записей (Service Discovery)
        # server backend.local service=http resolve;
    }

    server {
        listen 80;
        location / {
            proxy_pass http://app_servers;
        }
    }
}
```

### 2. Обходной путь через переменные (Nginx OSS 1.26 и ниже)
Если обновление до 1.27.3 невозможно, используется трюк с переменной в `proxy_pass`.

```nginx
server {
    listen 80;
    resolver 8.8.8.8 valid=30s;
    
    # Переменная заставляет Nginx игнорировать статический кеш при старте
    set $backend_host "api.external-service.com";

    location / {
        proxy_pass http://$backend_host:8080;
    }
}
```
**Особенности метода:**
- **Плюсы:** Работает во всех версиях Nginx OSS.
- **Минусы:** Игнорируются настройки блока `upstream` (нельзя использовать `least_conn`, `sticky`, `keepalive`). При каждом запросе может происходить DNS-запрос, если TTL мал.

## Технические нюансы

### Устойчивость при старте
При использовании параметра `resolve` Nginx успешно запустится, даже если доменное имя в данный момент не разрешается. Он пометит сервер как `down` и будет пытаться разрешить его в фоне. Без `resolve` ошибка разрешения имени при старте является **критической** и Nginx не запустится.

### Зона разделяемой памяти (`zone`)
Директива `zone` определяет объем памяти, где хранится текущее состояние апстрима (список разрешенных IP, их статусы, веса). 
- Рекомендуемый размер: `64k`–`128k` достаточно для сотен бэкендов.
- Если память в зоне закончится, Nginx не сможет обновлять список серверов.

### Кэширование и TTL
1. **Параметр `valid`**: В директиве `resolver` переопределяет TTL от DNS-сервера. Если не указан, используется TTL из DNS-ответа.
2. ** resolver_timeout**: Время ожидания ответа от DNS-сервера (по умолчанию 30с, рекомендуется снижать до 2–5с).

### Поддержка IPv6 и Docker
- В Docker-сетях резолвер всегда `127.0.0.11`.
- Если нужно отключить IPv6 (например, если бэкенд имеет кривой AAAA-запись), используйте `resolver 8.8.8.8 ipv6=off;`.
