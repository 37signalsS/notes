# Практическая конфигурация балансировки нагрузки Nginx

## Определения

**Upstream-группа** — именованная коллекция бэкенд-серверов в конфигурации Nginx, между которыми распределяются запросы. Определяется директивой `upstream`.

**Проксирование** — механизм перенаправления запроса от клиента к бэкенд-серверу через Nginx с помощью директивы `proxy_pass`.

**Keep-alive соединения** — постоянные TCP-соединения между Nginx и бэкендами, переиспользуемые для нескольких запросов для снижения накладных расходов на установку соединений.

## Основные концепции

### Роль upstream-группы

Upstream-группа является центральным элементом балансировки нагрузки. Она объявляет пул бэкенд-серверов и определяет алгоритм распределения запросов. Имя группы используется в директиве `proxy_pass` для указания целевого пула. Детальное описание алгоритмов балансировки приведено в файле [Алгоритмы балансировки](./algorithms.md).

### Механизм проксирования

Директива `proxy_pass` указывает Nginx установить новое HTTP-соединение с одним из серверов upstream-группы и передать ему исходный запрос клиента. Nginx выступает в роли обратного прокси-сервера, скрывая от клиента реальную структуру бэкендов.

## Практические сценарии

### Определение Upstream-группы

Директива `upstream` объявляет именованную группу бэкенд-серверов. Блок должен располагаться в контексте `http`, вне блоков `server`.

```nginx
upstream apache_backend {
    # Зона разделяемой памяти для хранения состояния группы.
    # Необходима для работы least_conn, health_check, sticky и др.
    zone backend_zone 64k;

    server 127.0.0.1:8080;
    server 127.0.0.1:8081;
    server 127.0.0.1:8082;
}
```

Здесь `apache_backend` — произвольное имя группы, которое используется в `proxy_pass`.

### Настройка проксирования (`proxy_pass`)

Для перенаправления запросов на созданную группу используется блок `location` внутри `server`.

```nginx
location / {
    # Перенаправляем запрос на группу серверов
    proxy_pass http://apache_backend;

    # Рекомендуемые заголовки для передачи информации о клиенте бэкенду
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

### Настройка производительности и надежности

#### Использование Keep-alive

По умолчанию Nginx открывает новое TCP-соединение для каждого запроса к бэкенду. Включение `keepalive` позволяет поддерживать постоянный пул соединений.

```nginx
upstream backend_servers {
    server 127.0.0.1:8080;
    server 127.0.0.1:8081;

    # Количество keep-alive соединений на каждый рабочий процесс Nginx
    keepalive 32;
}

server {
    location / {
        proxy_pass http://backend_servers;

        # Для работы keepalive требуется HTTP/1.1 и сброс заголовка Connection
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
```

Это снижает задержки и нагрузку на CPU за счет отсутствия необходимости выполнять TCP/TLS handshake для каждого запроса.

#### Настройка таймаутов

Таймауты предотвращают зависание соединений при медленном ответе бэкенда.

```nginx
location / {
    proxy_pass http://backend_servers;

    # Таймаут на установку соединения с бэкендом
    proxy_connect_timeout 5s;

    # Таймаут на передачу запроса бэкенду
    proxy_send_timeout 10s;

    # Таймаут на чтение ответа от бэкенда
    proxy_read_timeout 15s;
}
```

- **proxy_connect_timeout**: рекомендуется снижать (например, до `1s`) для быстрого ввода резервных серверов в работу.
- **proxy_read_timeout**: время ожидания ответа после начала передачи данных бэкендом.

#### Буферизация ответов

Nginx по умолчанию полностью считывает ответ от бэкенда в буфер перед отправкой клиенту, что освобождает бэкенд быстрее.

```nginx
location / {
    proxy_pass http://backend_servers;

    # Количество и размер буферов
    proxy_buffers 8 16k;

    # Размер буфера для первой части ответа (заголовков)
    proxy_buffer_size 8k;
}
```

Отключение буферизации (`proxy_buffering off;`) оправдано для потоковой передачи данных (например, Server-Sent Events).
