# Алгоритмы балансировки нагрузки Nginx

**Надёжность:** 10 (SSoT + Официальная документация Nginx 1.26 / Angie 1.12)
**Свежесть:** Июль 2026 (Актуально для Nginx 1.26.0+, Angie 1.12.0+)

## Определения

**Алгоритм балансировки** — логика, по которой Nginx выбирает конкретный сервер из группы `upstream` для обработки каждого входящего запроса. Выбор метода зависит от характера нагрузки, типа приложения (stateful/stateless) и требований к отказоустойчивости.

**Upstream** — именованная группа бэкенд-серверов, между которыми распределяется нагрузка. Подробнее: [Обзор концепций балансировки](./overview_concepts.md).

## Основные концепции

Nginx поддерживает несколько уровней распределения запросов, от простейшего циклического перебора до динамического анализа времени ответа.

### Round Robin (Циклическое распределение)

Алгоритм по умолчанию. Запросы распределяются по серверам поочередно.

- **Weighted Round Robin**: Запросы распределяются пропорционально весу (`weight`) сервера. 
  - *Пример*: Если у Server A `weight=5`, а у Server B `weight=1`, то из 6 запросов 5 уйдут на Server A.
  - *Технический нюанс*: Nginx использует «плавное» взвешивание (Smooth Weighted Round Robin), чтобы избежать лавинообразной нагрузки на сервер с самым большим весом в начале цикла.

### Least Connections (`least_conn`)

Запрос отправляется на сервер с наименьшим количеством **активных** соединений.

- **Сценарий**: Эффективен для длинных сессий (WebSockets, БД) или запросов с непредсказуемым временем обработки.
- **Особенности**: Учитывает веса серверов. Если число соединений пропорционально весам одинаково, используется Round Robin.
- **Предостережение**: Если один из бэкендов неисправен, но быстро отдает пустые ответы (например, ошибку 500 или 200 OK без контента), он будет иметь минимум активных соединений и «притянет» основной трафик.

### IP Hash (`ip_hash`)

Привязка клиента к серверу на основе его IP-адреса.

- **IPv4**: Использует первые три октета адреса. Это позволяет всей подсети клиента попадать на один бэкенд.
- **IPv6**: Использует весь адрес целиком.
- **Сценарий**: Реализация «липких сессий» (sticky sessions) без использования Cookie, когда состояние хранится в локальной памяти бэкенда.
- **Недостатки**: 
  - Дисбаланс, если много клиентов за одним корпоративным NAT.
  - Несовместим с параметром `weight` (до Nginx 1.21).

```nginx
upstream backend {
    ip_hash;
    server 127.0.0.1:9000;
    server 127.0.0.1:9001;
}
```

### Hash (`hash`)

Распределяет запросы на основе хеша произвольной переменной (URI, заголовки, аргументы).

- **Консистентное хеширование (`consistent`)**: Параметр минимизирует перераспределение запросов при добавлении или удалении сервера из группы (используется алгоритм Ketama). Критично для кэширующих прокси.

```nginx
upstream backend {
    # Балансировка по URI с сохранением привязки при изменении upstream
    hash $request_uri consistent;
    server 127.0.0.1:9000;
    server 127.0.0.1:9001;
}
```

### Random (`random`)

Выбор сервера случайным образом.

- **random two least_conn**: Балансировщик выбирает два случайных сервера и направляет запрос на тот, у которого меньше активных соединений.
- **Сценарий**: Используется в распределенных средах, где несколько независимых балансировщиков работают с одной группой бэкендов.

```nginx
upstream backend {
    random two least_conn;
    server 127.0.0.1:9000;
    server 127.0.0.1:9001;
    server 127.0.0.1:9002;
}
```

## Расширенные алгоритмы (Angie / Nginx Plus)

Эти алгоритмы недоступны в бесплатной версии Nginx OSS, но являются ключевыми для Angie и Nginx Plus.

### Least Time (`least_time`)

Выбирает сервер с наименьшим средним временем ответа и минимальным количеством активных соединений.

- **header**: Время получения первого байта заголовков ответа.
- **last_byte**: Время получения полного ответа.
- **inflight** (Angie): Учитывает также запросы, находящиеся в обработке.

```nginx
upstream backend {
    # Выбор по минимальному времени получения заголовков (только Angie/Plus)
    least_time header;
    server 10.0.0.1;
    server 10.0.0.2;
}
```

### Feedback (`feedback`)

Эксклюзивный алгоритм **Angie** (v1.6.0+). Динамически изменяет веса серверов на основе обратной связи (например, загрузки CPU бэкенда или длины его внутренней очереди). Требует поддержки на стороне приложения или агента.

## Практические сценарии

### Управление очередью и лимитами (`max_conns`, `queue`)

Для защиты бэкендов от перегрузки используются параметры ограничения соединений.

- **`max_conns=N`**: Жесткий лимит одновременных соединений к серверу.
- **`queue`**: Если все серверы достигли `max_conns`, запросы встают в очередь (в OSS Nginx запрос сразу вернет ошибку, если нет `backup`).

```nginx
upstream backend {
    zone upstream_zone 64k;
    server 10.0.0.1:80 max_conns=100;
    server 10.0.0.2:80 max_conns=100;
    
    # Очередь на 20 запросов с таймаутом ожидания 30с (Angie/Plus)
    queue 20 timeout=30s;
}
```

### Параметры серверов в upstream

| Параметр | Описание | Доступность |
|:---------|:---------|:------------|
| `weight=N` | Относительный вес сервера в балансировке. | Все версии |
| `max_fails=N` | Число ошибок до временного исключения сервера. | Все версии |
| `fail_timeout=T` | Время «штрафа» после `max_fails`. | Все версии |
| `max_conns=N` | Лимит одновременных соединений. | Все версии |
| `slow_start=T` | Плавный ввод сервера после восстановления. | Angie / Plus |
| `drain` | Плавный вывод из эксплуатации (завершение старых сессий). | Angie / Plus |
| `backup` | Резервный сервер (активен, если основные лежат). | Все версии |
| `down` | Ручное исключение сервера из ротации. | Все версии |

### Пример сложной конфигурации

```nginx
upstream api_cluster {
    zone api_zone 128k; # Зона для разделяемой памяти (нужна для least_conn и метрик)
    
    # Основные серверы с разным весом и плавным стартом
    server 10.5.0.10:8080 weight=3 max_conns=500;
    server 10.5.0.11:8080 weight=1 max_conns=200 slow_start=60s;
    
    # Использование консистентного хеширования по ID пользователя
    hash $arg_user_id consistent;
    
    # Резервный узел
    server 10.5.0.20:8080 backup;
    
    # Настройка очереди для Angie/Plus
    queue 50 timeout=10s;
}
```

## Сравнение возможностей версий

| Функция | Nginx OSS (1.26) | Nginx Plus | Angie (1.12) |
| :--- | :--- | :--- | :--- |
| Round Robin / Least Conn / Hash | Да | Да | Да |
| Least Time | Нет | Да | **Да** |
| Dynamic Feedback | Нет | Нет | **Да** |
| Queue (Очередь запросов) | Нет | Да | **Да** |
| Sticky Sessions (Cookie) | Нет | Да | **Да** |
| API / Prometheus Metrics | Нет (только stub) | Да | **Да** |
