# Балансировка нагрузки в Nginx: Дополнительная информация и сравнения

**Надёжность:** 10 (SSoT + Сводный анализ технологий 2026)
**Свежесть:** Июль 2026 (Актуально для Nginx 1.26+, HAProxy 3.0+, Traefik 3.7+)

## Определения

**Обратный прокси (Reverse Proxy)** — сервер, принимающий запросы извне и перенаправляющий их на один или несколько внутренних узлов. Nginx является индустриальным стандартом в этой роли.

**Событийно-ориентированная архитектура (Event-driven)** — модель обработки запросов в Nginx, при которой один рабочий процесс (worker) обслуживает тысячи соединений асинхронно через системные вызовы `epoll` (Linux) или `kqueue` (BSD).

**Service Discovery (Обнаружение сервисов)** — автоматизация поиска сетевых адресов бэкендов в динамических средах (Kubernetes, Consul).

## Основные концепции

### Сравнение архитектур: Nginx vs Apache

Nginx создавался для решения «проблемы C10k» (10 000 одновременных соединений), с которой классический Apache справлялся плохо.

| Характеристика | Apache HTTP Server | Nginx |
| :--- | :--- | :--- |
| **Модель обработки** | Процессы или потоки (Thread-per-request). Каждый запрос требует выделенной памяти. | Событийный цикл (Event loop). Один процесс обрабатывает тысячи запросов. |
| **Конфигурация** | Распределенная (`.htaccess`). Сервер ищет файл в каждой папке пути при каждом запросе. | Централизованная. Конфигурация компилируется при старте и хранится в RAM. |
| **Производительность** | Деградирует при росте числа соединений (context switching). | Линейная масштабируемость и минимальное потребление RAM (~2MB на 10k соединений). |
| **Статика** | Средняя скорость. | Лучшая в индустрии (использование `sendfile` и асинхронного I/O). |

**Проблема `.htaccess`:** В Apache использование этих файлов заставляет ядро выполнять системные вызовы `stat()` для каждой директории в пути к файлу. Если путь `/var/www/html/site/index.html`, Apache проверит наличие `.htaccess` в 4 директориях. Nginx лишен этого оверхеда по дизайну.

### Сравнение с HAProxy

HAProxy — это «скальпель» балансировки, в то время как Nginx — «швейцарский нож».

- **HAProxy 3.0 (2026):** Специализируется исключительно на балансировке (L4/L7). Обладает самыми мощными алгоритмами (например, привязка по RDP-кукам или заголовкам на уровне ядра) и лучшей в классе скоростью обработки SSL (crt-store).
- **Nginx 1.26:** Универсален. Умеет отдавать статику, кэшировать ответы, выполнять сложные `rewrite` правила и терминировать SSL.
- **Angie (Форк):** Устраняет главный недостаток Nginx OSS перед HAProxy — отсутствие бесплатных активных проверок (Health Checks) и нативного API мониторинга.

## Практические сценарии

### Выбор решения в 2026 году

| Сценарий | Рекомендуемое решение | Почему? |
| :--- | :--- | :--- |
| **Классический веб-сайт** | **Nginx** | Статика + Кэш + Балансировка в одном флаконе. |
| **High-load API / gRPC** | **HAProxy** | Минимальные задержки (latency) и глубокий анализ L7. |
| **Микросервисы (K8s/Docker)**| **Traefik** | Нативный Service Discovery, автоматический SSL, YAML-конфиг. |
| **Service Mesh / Edge** | **Envoy** | Программируемость через API (xDS), стандарт для распределенных систем. |
| **AI-инфраструктура** | **Envoy / Traefik** | Нативная поддержка **AI Gateway** и балансировка запросов к LLM (OpenAI, Anthropic). |

### Роль Angie как моста между OSS и Enterprise

Для команд, которым не хватает функционала Nginx Open Source, но нет бюджета на Nginx Plus, **[Angie](../../../Angie/angie_overview.md)** предоставляет возможности NGINX Plus бесплатно:
- **Динамический DNS** в блоке `upstream`.
- **Активные Health Checks** (проверка доступности бэкендов в фоне).
- **JSON API** для мониторинга (уровень HAProxy).
- **Sticky Sessions** на основе Cookie.
