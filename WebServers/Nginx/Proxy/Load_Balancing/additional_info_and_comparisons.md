# Балансировка нагрузки в Nginx: Сравнение и дополнительные сведения

## Определения

**Обратный прокси (Reverse Proxy)** — сервер-посредник, принимающий запросы от внешних клиентов и распределяющий их между внутренними узлами (бэкендами). В отличие от прямого прокси, он защищает и абстрагирует внутреннюю инфраструктуру.

**Событийно-ориентированная архитектура (Event-driven)** — модель обработки запросов (используемая в Nginx), при которой один процесс обслуживает тысячи соединений асинхронно. Это исключает накладные расходы на создание потоков (threads) для каждого нового клиента.

**Проблема C10k** — историческая задача по одновременному обслуживанию 10 000 соединений одним сервером. Успешное решение этой проблемы стало фундаментом популярности Nginx.

## Основные концепции

### Архитектурное сравнение: Nginx против Apache

Apache HTTP Server (с модулем `prefork` или `worker`) долгое время был стандартом, но проигрывал Nginx в плотности соединений.

| Характеристика | Apache HTTP Server | Nginx |
| :--- | :--- | :--- |
| **Модель обработки** | Процессы/потоки (Thread-per-request). Высокое потребление RAM на каждое соединение. | Событийный цикл (Event loop). Минимальное потребление RAM (~2MB на 10k соединений). |
| **Работа со статикой** | Передает файлы через обработку в потоках, что медленнее при высокой нагрузке. | Использование системных вызовов `sendfile` и асинхронного I/O. Лучшая скорость в индустрии. |
| **Конфигурация** | Поддержка `.htaccess` (распределенная). Снижает скорость из-за постоянных проверок ФС. | Централизованная. Считывается и компилируется один раз при старте. |
| **Масштабируемость** | Деградирует при росте числа конкурентных соединений. | Линейная масштабируемость. |

### Балансировщики 2026 года: Nginx, HAProxy, Traefik, Envoy

В 2026 году выбор инструмента зависит от архитектурного контекста.

| Инструмент | Роль | Сильные стороны |
| :--- | :--- | :--- |
| **Nginx / Angie** | Универсальный комбайн | Статика, кэширование, балансировка, гибкий `rewrite`. Идеален для Edge. |
| **HAProxy (3.0+)** | Высокоточный скальпель | Экстремальная производительность L4/L7, продвинутые алгоритмы, нативный мониторинг. |
| **Traefik (3.x)** | Cloud-Native прокси | Автоматический Service Discovery (Docker/K8s), встроенный ACME (SSL), простота YAML. |
| **Envoy** | Программируемая шина | Основа для Service Mesh, поддержка xDS API, расширяемость через WASM. |

## Практические сценарии

### Выбор решения под задачу (2026)

1.  **Традиционный веб-проект (Monolith / CMS):**
    *   **Выбор:** **Nginx**.
    *   **Почему:** Требуется отдача статики, кэширование и простая балансировка в одном процессе.
2.  **Динамические микросервисы (Docker Compose / Swarm / K8s):**
    *   **Выбор:** **Traefik**.
    *   **Почему:** Автоматически подхватывает новые контейнеры через labels и выпускает сертификаты Let's Encrypt.
3.  **High-Load API / Финансовые системы:**
    *   **Выбор:** **HAProxy**.
    *   **Почему:** Минимальные задержки (low latency) и возможность балансировки на основе глубокого анализа пакетов.
4.  **AI-инфраструктура и управление LLM:**
    *   **Выбор:** **Envoy AI Gateway**.
    *   **Почему:** Специализированные фильтры для кэширования промптов и балансировки запросов к OpenAI/Anthropic на основе токенов (GA с июня 2026).

## Технические нюансы 2026 года

### Ускорение eBPF и QUIC/HTTP-3
*   **eBPF:** Современные балансировщики (особенно в K8s через Cilium или Envoy) используют eBPF для обхода сетевого стека ядра (Socket Map), что снижает CPU overhead на 20-30%.
*   **HTTP/3 (QUIC):** В 2026 году поддержка HTTP/3 является обязательной. Nginx (через модуль `ngx_http_v3_module`) и Angie обеспечивают нативную поддержку QUIC, что критично для мобильных клиентов с нестабильной связью.

### Angie как замена Nginx Plus
Для инфраструктур, требующих Enterprise-функций без покупки лицензий, **[Angie](../../../Angie/angie_overview.md)** стал SSoT-решением, предоставляя:
*   Активные проверки (Active Health Checks).
*   Динамический DNS в апстримах.
*   Нативный экспорт метрик в Prometheus.
