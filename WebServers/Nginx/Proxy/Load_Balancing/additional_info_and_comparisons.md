# Балансировка нагрузки в Nginx: Дополнительная информация и сравнения

## Определения

**htaccess** — распределённый конфигурационный файл Apache, позволяющий управлять настройками веб-сервера на уровне отдельных директорий. Nginx не поддерживает данный механизм, используя централизованную конфигурацию для повышения производительности. Подробное описание приведено в [Обзоре Apache](../../../Apache/apache_overview.md#файлы-htaccess).

**Reverse Proxy (обратный прокси)** — сервер, который принимает запросы от клиентов и перенаправляет их на один или несколько бэкенд-серверов. Nginx чаще всего используется именно в этой роли при балансировке нагрузки.

## Основные концепции

### Организация конфигурации Nginx

Для удобства управления и масштабирования конфигурацию балансировки рекомендуется разделять по следующим директориям:

- **/etc/nginx/conf.d/** — глобальные настройки, определения групп серверов (блоки `upstream`) и общие параметры. Файлы в этой директории должны иметь расширение `.conf`.
- **/etc/nginx/sites-enabled/** — конфигурации конкретных виртуальных хостов (блоки `server`). Обычно содержит символические ссылки на файлы из `/etc/nginx/sites-available/`.

### Сравнение подходов: Nginx vs Apache

Nginx был спроектирован как высокопроизводительная альтернатива Apache, что отразилось на подходе к конфигурации и обработке запросов.

| Параметр | Apache | Nginx |
| :--- | :--- | :--- |
| Конфигурация директорий | Поддерживается через `.htaccess` | Не поддерживается (только централизованно) |
| Производительность | Снижена из-за постоянного чтения диска для `.htaccess` | Максимальная (конфигурация в оперативной памяти) |
| Гибкость (Shared-hosting) | Высокая (пользователи сами меняют настройки) | Требует доступа администратора к серверу |
| Отказоустойчивость | Ошибка в `.htaccess` блокирует только один сайт | Ошибка в конфиге предотвращается проверкой `nginx -t` |

Отсутствие поддержки `.htaccess` в Nginx является осознанным архитектурным решением для исключения лишних системных вызовов `stat()` при каждом запросе.

## Практические сценарии

### Сравнение Nginx и HAProxy

Nginx — это универсальный веб-сервер с функциями проксирования, в то время как HAProxy является специализированным высокопроизводительным балансировщиком.

| Критерий | Nginx (Open Source) | HAProxy |
| :--- | :--- | :--- |
| Алгоритмы балансировки | Базовые (Round Robin, Least Connections, IP Hash) | Широкий набор (URL params, HTTP headers, RDP cookies) |
| Health checks | Пассивные (реакция на ошибки бэкенда) | Активные и пассивные (периодические пробы) |
| Привязка сессий | Через IP Hash или сторонние модули | Встроенная гибкая поддержка (Sticky Sessions) |
| Универсальность | Веб-сервер + Прокси + Балансировщик | Только Балансировщик / Прокси |
| Мониторинг | Базовая статистика | Глубокая аналитика трафика в реальном времени |

**Nginx Plus / Angie Pro** расширяют возможности бесплатной версии Nginx, добавляя активные Health Checks, динамическую реконфигурацию без перезагрузки и балансировку на основе времени ответа бэкенда. Подробнее о форке: [Обзор Angie](../../../Angie/angie_overview.md).

### Матрица выбора решения

| Сценарий использования | Рекомендуемое решение |
| :--- | :--- |
| Универсальный веб-сервер, отдача статики и проксирование | **Nginx** |
| Сложная балансировка на L4/L7 уровнях с глубоким мониторингом | **HAProxy** |
| Shared-hosting с необходимостью использования `.htaccess` | **Apache** (бэкенд) + **Nginx** (фронтенд) |
| Enterprise-решение с динамическим управлением и поддержкой | **Nginx Plus** или **Angie Pro** |
