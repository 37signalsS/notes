# Балансировка нагрузки Nginx: Sticky Sessions (Прилипание сессий)

## Определения

**Sticky Sessions (Прилипание сессий)** — механизм балансировщика нагрузки, обеспечивающий направление всех запросов от одного клиента на один и тот же бэкенд-сервер. Применяется для stateful-приложений, хранящих состояние сессии локально на сервере.

> **Примечание:** В Nginx Open Source описанная ниже функциональность (`sticky`) доступна через сторонний модуль [ngx_http_upstream_sticky_module](https://bitbucket.org/nginx-goodies/nginx-sticky-module-ng/src/master/). В форке Nginx [Angie](../../../Angie/angie_overview.md) и в коммерческой версии Nginx Plus этот функционал является встроенным.

## Базовые концепции

В некоторых случаях, особенно при использовании stateful-приложений, необходимо, чтобы запросы от одного клиента всегда попадали на один и тот же бэкенд-сервер. Для этой цели, помимо метода `ip_hash`, можно использовать более гибкие механизмы «прилипания».

Доступны два режима:

- **`cookie`** — привязка через HTTP-куки
- **`route`** — привязка через значение переменной в запросе

## Практические сценарии

### Режим `cookie`

Nginx устанавливает специальную куку в браузере клиента, которая содержит информацию о выбранном бэкенде.

```nginx
upstream backend {
    sticky cookie srv_id expires=1h path=/; # srv_id - имя куки, expires - время жизни
    server 127.0.0.1:9000;
    server 127.0.0.1:9001;
}
```

**Параметры директивы:**

- `sticky cookie <name> [expires=time] [domain=domain] [path=path] [secure] [httponly]` — включает прилипание на основе куки
- `sticky secret <string>` — добавляет «соль» к значению идентификатора сервера перед хешированием; защищает от атак, направленных на угадывание хеша и принудительную привязку к определённому бэкенду
- `sticky strict` — если привязанный сервер недоступен, Nginx немедленно вернёт ошибку (например, 502 Bad Gateway); без этой директивы запрос будет прозрачно для клиента перенаправлен на другой доступный сервер в группе `upstream`

### Режим `route`

Привязка происходит на основе значения переменной, которая передаётся в запросе.

```nginx
upstream backend {
    sticky route $arg_route; # Привязка на основе значения параметра 'route' из URL
    server 127.0.0.1:9000 route=green;
    server 127.0.0.1:9001 route=blue;
}
```

**Параметры директивы:**

- `sticky route <variable>` — указывает переменную, по которой будет определяться маршрут; например, `$arg_route` для параметра `route` в URL (`?route=green`)
- `server ... route=<string>` — определяет строковый идентификатор маршрута для конкретного сервера

**Пример использования и риски:**
Если клиент сделает запрос `http://example.com/?route=green`, он будет направлен на сервер `127.0.0.1:9000`. Однако этот метод может быть небезопасен, так как позволяет клиенту напрямую выбирать бэкенд, что может быть использовано для DoS-атаки на конкретный сервер. Для защиты от подобных атак следует использовать `sticky secret`.
