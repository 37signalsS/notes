# Балансировка нагрузки Nginx: Sticky Sessions (Прилипание сессий)

## Определения

**Sticky Sessions (Прилипание сессий)** — механизм балансировщика нагрузки, обеспечивающий направление всех запросов от одного конкретного клиента на один и тот же бэкенд-сервер. Применяется для stateful-приложений, хранящих состояние сессии локально на сервере.

> **Примечание:** в Nginx Open Source функциональность `sticky` доступна через сторонний модуль [ngx_http_upstream_sticky_module](https://bitbucket.org/nginx-goodies/nginx-sticky-module-ng/src/master/). В форке Nginx [Angie](../../../Angie/angie_overview.md) и в коммерческой версии Nginx Plus этот функционал является встроенным.

## Основные концепции

В случаях использования stateful-приложений необходимо, чтобы запросы от одного клиента всегда попадали на один и тот же бэкенд-сервер. Помимо метода `ip_hash`, можно использовать более гибкие механизмы прилипания.

Доступны два основных режима работы:

- **cookie** — привязка через HTTP-куки.
- **route** — привязка через значение переменной в запросе.

## Практические сценарии

### Режим cookie

Nginx устанавливает специальную куку в браузере клиента, которая содержит информацию о выбранном бэкенде. При последующих запросах Nginx считывает эту куку и направляет трафик на тот же сервер.

```nginx
upstream backend {
    # srv_id - имя куки, expires - время жизни
    sticky cookie srv_id expires=1h path=/; 
    server 127.0.0.1:9000;
    server 127.0.0.1:9001;
}
```

**Параметры директивы:**

- `sticky cookie <name> [expires=time] [domain=domain] [path=path] [secure] [httponly]` — включает прилипание на основе куки.
- `sticky secret <string>` — добавляет «соль» к значению идентификатора сервера перед хешированием; защищает от атак, направленных на угадывание хеша и принудительную привязку к определённому бэкенду.
- `sticky strict` — если привязанный сервер недоступен, Nginx немедленно вернёт ошибку (например, 502 Bad Gateway); без этой директивы запрос будет прозрачно для клиента перенаправлен на другой доступный сервер в группе upstream.

### Режим route

Привязка происходит на основе значения переменной, которая передаётся в запросе (например, в параметрах URL или заголовках).

```nginx
upstream backend {
    # Привязка на основе значения параметра 'route' из URL
    sticky route $arg_route; 
    server 127.0.0.1:9000 route=green;
    server 127.0.0.1:9001 route=blue;
}
```

**Параметры директивы:**

- `sticky route <variable>` — указывает переменную, по которой будет определяться маршрут; например, `$arg_route` для параметра `route` в URL (`?route=green`).
- `server ... route=<string>` — определяет строковый идентификатор маршрута для конкретного сервера.

**Безопасность и риски:**
Если клиент сделает запрос `http://example.com/?route=green`, он будет направлен на сервер `127.0.0.1:9000`. Данный метод может быть использован для DoS-атаки на конкретный сервер, так как позволяет клиенту напрямую выбирать бэкенд. Для защиты следует использовать параметр `sticky secret`.
