# Балансировка нагрузки L7 (HTTP/HTTPS) с помощью Nginx: Обзор и концепции

## Определения

- **Балансировка нагрузки** — способ распределения запросов к приложению (сетевого трафика) между несколькими бэкенд-серверами. Ключевой компонент для построения масштабируемых и отказоустойчивых систем.

- **Роли Nginx**:
  - Веб-сервер;
  - **Реверс-прокси и балансировщик нагрузки;**
  - Почтовый прокси-сервер;
  - Кэширующий прокси.

- **Upstream** — именованная группа бэкенд-серверов в конфигурации Nginx, между которыми распределяется нагрузка. Подробнее: [Алгоритмы балансировки](./algorithms.md).

## Базовые концепции

### Stateless-архитектура для масштабирования

Балансировка нагрузки — только часть решения. Чтобы система была масштабируемой и отказоустойчивой, бэкенд-серверы должны быть **stateless** (не хранящие состояние).

Любой запрос от одного клиента может быть обработан любым бэкенд-сервером без потери данных или сессии. Состояние приложения (сессии, кэш, загруженные файлы) выносится на отдельные, общие для всех бэкендов сервисы.

#### Ключевые компоненты stateless-архитектуры

1. **Балансировщик нагрузки (Nginx):**
   - Принимает трафик.
   - **Терминирует TLS (SSL):** расшифровка HTTPS-трафика происходит здесь, к бэкендам запросы идут по внутреннему HTTP, что снижает нагрузку на них.
   - **Выполняет Health Checks:** периодически опрашивает бэкенды. Если бэкенд не отвечает, балансировщик временно исключает его из ротации. Подробнее: [Health Checks и мониторинг](./health_checks_and_monitoring.md).
   - Проксирует запросы к работающим бэкендам.

2. **Бэкенд-серверы (веб-приложение):**
   - Не хранят данных локально (ни сессий, ни загруженных файлов).
   - Все экземпляры содержат идентичный код.
   - Могут быть легко добавлены или удалены для горизонтального масштабирования.

3. **База данных (например, PostgreSQL, MySQL):**
   - Хранит основные данные приложения. Все бэкенды подключаются к одной базе данных или кластеру.

4. **Кэш и сессии (например, Redis, Memcached):**
   - Хранит временные данные: кэш страниц, результаты тяжёлых запросов и **пользовательские сессии**. При логине на одном бэкенде информация о сессии сохраняется в Redis, и любой другой бэкенд может её прочитать.

5. **Файловое хранилище (например, S3, MinIO, GlusterFS):**
   - Загружаемые пользователями файлы (аватары, документы) сохраняются в общее сетевое хранилище, а не на локальный диск бэкенда.

### Типы балансировки

- **L4 (Transport Layer):** балансировка на транспортном уровне (TCP/UDP). Nginx не анализирует содержимое HTTP-запросов. Подробнее: [L4-проксирование](../nginx_l4_proxying.md).
- **L7 (Application Layer):** балансировка на уровне приложений (HTTP/HTTPS). Nginx принимает HTTP-запрос, анализирует его (URL, заголовки, cookies) и направляет на соответствующий бэкенд.

### Алгоритмы балансировки

Nginx поддерживает несколько алгоритмов распределения запросов в блоке `upstream`: Round Robin (по умолчанию), Least Connections, IP Hash, Hash, Random. Выбор алгоритма зависит от архитектуры приложения и требований к сессиям.

Подробнее: [Алгоритмы балансировки](./algorithms.md).
