# Балансировка нагрузки L7 (HTTP/HTTPS) в Nginx: Обзор и концепции

## Определения

**Балансировка нагрузки (Load Balancing)** — способ распределения входящего сетевого трафика между группой бэкенд-серверов. Является ключевым компонентом для построения масштабируемых и отказоустойчивых систем. Общие принципы описаны в разделе [Кластеризация и балансировка для HA](../../../Concepts/High_Availability/ha_clustering_and_load_balancing.md).

**Upstream** — именованная группа бэкенд-серверов в конфигурации Nginx, между которыми распределяется нагрузка. Подробное описание алгоритмов и параметров приведено в файле [Алгоритмы балансировки](./algorithms.md).

**Реверс-прокси (Reverse Proxy)** — роль Nginx, в которой он принимает запросы от клиентов и перенаправляет их на один или несколько бэкенд-серверов. Подробнее о ролях Nginx см. в [Обзоре Nginx](../Core/nginx_overview.md).

## Основные концепции

### Stateless-архитектура и роль Nginx

Для обеспечения эффективного горизонтального масштабирования и отказоустойчивости бэкенд-серверы должны быть **stateless** (не хранящие состояние). Это означает, что любой экземпляр приложения может обработать любой запрос от любого клиента. Подробный разбор концепции: [Stateful vs Stateless](../../../Concepts/stateful_vs_stateless.md).

В такой архитектуре Nginx выполняет следующие задачи:

1. **Прием и распределение трафика** — направление запросов на свободные или наименее нагруженные узлы.
2. **Терминация TLS (SSL)** — расшифровка HTTPS-трафика на уровне балансировщика, что позволяет бэкендам работать по HTTP и экономить вычислительные ресурсы.
3. **Health Checks** — периодическая проверка работоспособности бэкендов. Если сервер не отвечает, Nginx временно исключает его из ротации. Подробнее: [Health Checks и мониторинг](./health_checks_and_monitoring.md).
4. **Управление сессиями** — при необходимости сохранения привязки клиента к серверу используются механизмы [Sticky Sessions](./sticky_sessions.md). В идеальной stateless-системе данные сессий выносятся во внешние хранилища (Redis, Memcached).

### Уровни балансировки в Nginx

Nginx поддерживает два основных типа балансировки в зависимости от уровня модели OSI:

- **L4 (Transport Layer)** — балансировка на транспортном уровне (TCP/UDP). Nginx работает с потоками данных, не анализируя содержимое пакетов. Это обеспечивает высокую производительность при работе с базами данных, почтовыми серверами и другими не-HTTP протоколами. Подробнее: [L4-проксирование в Nginx](../nginx_l4_proxying.md).
- **L7 (Application Layer)** — балансировка на прикладном уровне (HTTP/HTTPS). Nginx анализирует содержимое запросов (URL, заголовки, Cookies, тело запроса) и принимает решение о маршрутизации на основе этих данных.

### Алгоритмы распределения нагрузки

Nginx предоставляет гибкий набор алгоритмов для выбора целевого сервера в блоке `upstream`:

- **Round Robin** (по умолчанию) — поочередное распределение.
- **Least Connections** — выбор сервера с минимальным числом активных соединений.
- **IP Hash** — привязка клиента по хешу IP-адреса.
- **Hash** — распределение на основе произвольной переменной (например, URI).
- **Random** — случайный выбор (с возможностью учета нагрузки).

Детальное описание работы алгоритмов: [Алгоритмы балансировки](./algorithms.md).

## Практические сценарии

### Типовая схема балансировки

Стандартный стек высокодоступного веб-приложения включает:

1. **Nginx** как единую точку входа и балансировщик.
2. **Группу бэкендов** (stateless), обрабатывающих бизнес-логику.
3. **Redis/Memcached** для хранения общих сессий и кэша.
4. **Кластер БД** (PostgreSQL, MySQL) для персистентного хранения данных.

Конкретные примеры конфигурации `upstream` и `proxy_pass` приведены в файле [Практическая конфигурация балансировки](./practical_configuration.md).
