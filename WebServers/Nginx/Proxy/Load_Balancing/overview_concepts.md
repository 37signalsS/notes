# Балансировка нагрузки L7 (HTTP/HTTPS) в Nginx: Обзор и концепции

**Надёжность:** 10 (SSoT + Официальная документация Nginx 1.26 / Angie 1.12)
**Свежесть:** Июль 2026 (Актуально для Nginx 1.26.0+, Angie 1.12.0+)

## Определения

**Балансировка нагрузки (Load Balancing)** — способ распределения входящего сетевого трафика между группой бэкенд-серверов. Является ключевым компонентом для построения масштабируемых и отказоустойчивых систем. Общие принципы описаны в разделе [Кластеризация и балансировка для HA](../../../Concepts/High_Availability/ha_clustering_and_load_balancing.md).

**Upstream** — именованная группа бэкенд-серверов в конфигурации Nginx, между которыми распределяется нагрузка. Подробное описание алгоритмов и параметров приведено в файле [Алгоритмы балансировки](./algorithms.md).

**Реверс-прокси (Reverse Proxy)** — роль Nginx, в которой он терминирует клиентские соединения и перенаправляет запросы на бэкенды. Подробнее о ролях Nginx см. в [Обзоре Nginx](../Core/nginx_overview.md).

## Основные концепции

### Событийно-ориентированная архитектура L7

Nginx использует асинхронную, событийно-ориентированную модель (Event-driven), что позволяет одному рабочему процессу (worker) обрабатывать тысячи одновременных L7-соединений. В отличие от традиционных серверов, Nginx не создает поток (thread) на каждый запрос, что минимизирует накладные расходы на переключение контекста и память при парсинге заголовков, Cookies и URI.

### Stateless-архитектура и роль Nginx

Для эффективного масштабирования бэкенд-серверы должны быть **stateless** (не хранящие состояние). Это позволяет любому экземпляру приложения обработать запрос от любого клиента. Подробный разбор: [Stateful vs Stateless](../../../Concepts/stateful_vs_stateless.md).

В этой архитектуре Nginx выполняет задачи:
1. **Терминация TLS (SSL)** — расшифровка трафика, снимающая вычислительную нагрузку с бэкендов.
2. **Health Checks** — пассивные (OSS) или активные (Angie/Plus) проверки работоспособности. Подробнее: [Health Checks и мониторинг](./health_checks_and_monitoring.md).
3. **Session Persistence** — при необходимости сохранения привязки клиента используются [Sticky Sessions](./sticky_sessions.md).

### Оптимизация соединений (Keepalive)

Без настройки `keepalive` Nginx открывает новый TCP-сокет для каждого запроса к бэкенду. Это приводит к:
- Высокому потреблению ресурсов CPU на установку TCP/TLS соединений.
- Исчерпанию диапазона эфемерных портов и накоплению соединений в состоянии `TIME_WAIT`.

**Решение:** Кэширование соединений в блоке `upstream` позволяет переиспользовать открытые сокеты для множества запросов, что критично для высоконагруженных систем.

### Управление потоком данных (Buffering)

Буферизация (`proxy_buffering`) защищает бэкенды от «медленных» клиентов.
- Nginx считывает ответ от бэкенда максимально быстро в свои буферы (память или диск) и немедленно освобождает бэкенд для следующего запроса.
- Медленная передача данных клиенту ложится на плечи Nginx, который спроектирован для эффективной обработки тысяч таких сессий.

### Динамический Upstream и DNS Resolution

В Nginx Open Source имена серверов в `upstream` разрешаются в IP-адреса **только один раз** при старте или перезагрузке (`reload`).
- **Проблема:** В динамических средах (Kubernetes, AWS) IP-адреса бэкендов могут меняться.
- **Решение:** Использование переменных в `proxy_pass` или переход на **[Angie](../../../Angie/angie_overview.md)**, который поддерживает нативное переразрешение DNS согласно TTL без перезагрузки.

## Сравнение уровней балансировки

| Уровень OSI | Название | Что анализирует Nginx | Применение |
| :--- | :--- | :--- | :--- |
| **L4** | Транспортный | IP, TCP/UDP порт | БД (MySQL, PG), DNS, Почта. [L4-проксирование](../nginx_l4_proxying.md) |
| **L7** | Прикладной | URI, Headers, Cookies, JSON | Веб-приложения, API, микросервисы. |

## Практические сценарии

### Типовая схема балансировки

1. **Балансировщик (Nginx/Angie)**: Терминация TLS, балансировка, кэширование статики.
2. **Пул приложений**: Stateless-серверы (Python, Node.js, Go).
3. **Хранилище сессий**: Redis/Memcached (внешнее состояние).
4. **База данных**: Реляционный кластер с собственным L4-балансировщиком.

Детальные примеры конфигурации: [Практическая конфигурация балансировки](./practical_configuration.md).

## Сравнение возможностей (Nginx vs Angie)

| Функция | Nginx OSS (1.26) | Angie (1.12) |
| :--- | :--- | :--- |
| Балансировка HTTP/HTTPS | Да | Да |
| Активные Health Checks | Нет (нужен Plus) | **Да** |
| Динамический DNS в Upstream | Нет (нужен Plus) | **Да** |
| Мониторинг (JSON API) | Нет (нужен Plus) | **Да** |
| Sticky Sessions (Cookie) | Нет (нужен Plus) | **Да** |
