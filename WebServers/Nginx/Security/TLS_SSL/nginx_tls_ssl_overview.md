# Обзор TLS/SSL в Nginx

## Определения

### TLS в Nginx

**TLS (Transport Layer Security)** в Nginx обеспечивает шифрование трафика между клиентом и веб-сервером. Nginx поддерживает современные протоколы TLS 1.2 и TLS 1.3, а также предоставляет механизмы оптимизации производительности и усиления безопасности.

Теоретические основы протокола, включая процесс **[TLS Handshake](../../../../Networking/Protocols/tls.md#процесс-рукопожатия-ssltls-handshake)** и механизмы **[гибридного шифрования](../../../../Networking/Protocols/tls.md#гибридное-шифрование)**, описаны в системном SSoT по сетевым протоколам.

### Цепочка сертификатов (Certificate Chain)

Для успешной проверки подлинности сервера клиент должен иметь возможность проверить всю цепочку доверия от серверного сертификата до корневого.

* **Серверный сертификат (Server Certificate):** Выдан для конкретного домена.
* **Промежуточный сертификат (Intermediate CA):** Сертификат, выданный корневым центром и используемый для подписи серверных сертификатов.
* **Корневой сертификат (Root CA):** Вершина цепочки доверия, предустановлен в ОС/браузере.

**Специфика Nginx:**
При настройке Nginx требуется файл «полной цепочки» (**fullchain**), где сертификаты идут в строгом порядке: сначала серверный, затем все промежуточные. Корневой сертификат обычно не включается.

```plaintext
-----BEGIN CERTIFICATE-----
(Ваш серверный сертификат)
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
(Промежуточный сертификат)
-----END CERTIFICATE-----
```

Для работы требуются два основных файла:

1. **Файл цепочки (`fullchain.pem`):** Сертификат домена + промежуточные сертификаты.
2. **Приватный ключ (`privkey.pem`):** Секретный ключ, соответствующий сертификату.

Конфигурация на уровне виртуального хоста: [Конфигурация виртуальных хостов TLS](./nginx_tls_virtual_host_config.md).

## Базовые понятия

### Perfect Forward Secrecy (PFS)

Механизм, гарантирующий, что компрометация приватного ключа сервера не позволит расшифровать трафик прошлых сессий. Обеспечивается использованием эфемерных ключей (ECDHE, DHE).

* **Теория:** **[PFS в протоколе TLS](../../../../Networking/Protocols/tls.md#perfect-forward-secrecy-pfs)**.
* **Настройка в Nginx:** [Глобальные параметры TLS](./nginx_tls_global_parameters.md#протоколы-и-шифры).

### Strict-Transport-Security (HSTS)

Заголовок HTTP-ответа, предписывающий браузеру взаимодействовать с сайтом исключительно по HTTPS. Это предотвращает атаки типа SSL Stripping (понижение версии протокола).

* **Настройка в Nginx:** [Виртуальный хост TLS](./nginx_tls_virtual_host_config.md#базовая-конфигурация-https).

### OCSP Stapling

Механизм оптимизации, при котором сервер сам запрашивает статус валидности своего сертификата у CA и «прикрепляет» подписанный ответ к TLS-рукопожатию. Это ускоряет установку соединения и повышает приватность клиента.

* **Настройка в Nginx:** [Глобальные параметры TLS](./nginx_tls_global_parameters.md#настройка-ocsp-stapling).

### HTTP/2 и HTTP/3 (QUIC)

Современные протоколы, работающие поверх TLS (HTTP/2) или интегрированные с ним (HTTP/3). Обеспечивают мультиплексирование и ускорение загрузки данных.

* **Настройка в Nginx:** [Включение HTTP/2 и HTTP/3](../../Performance/nginx_http_versions.md).

### Mutual TLS (mTLS)

Взаимная аутентификация, при которой сервер проверяет сертификат клиента. Широко используется в микросервисных архитектурах и [Service Mesh](../../../../Service_Mesh/service_mesh_concepts.md).

* **Подробное руководство:** [Настройка mTLS в Nginx](./nginx_mtls_configuration.md).

### Kernel TLS (kTLS)

Оптимизация производительности за счёт переноса операций шифрования TLS в ядро ОС Linux. Это позволяет эффективно использовать системный вызов `sendfile` при отдаче статических файлов по HTTPS.

* **Важно:** kTLS может конфликтовать с HTTP/2.
* **Подробности:** [Оптимизация производительности Nginx](../../Performance/nginx_performance_tuning.md#kernel-tls-ktls).
