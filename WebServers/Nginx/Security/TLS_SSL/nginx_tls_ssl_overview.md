# Обзор TLS/SSL в Nginx

**Надёжность:** 10 (SSoT + Официальная документация Nginx 1.26/1.27 + Спецификации OpenSSL 3.5)
**Свежесть:** Июль 2026 (Актуально для Nginx 1.26+, 1.27.x+)

## Определения

### TLS в Nginx

**TLS (Transport Layer Security)** в Nginx обеспечивает надежное шифрование данных и проверку подлинности сервера при взаимодействии с клиентами. Современный Nginx ориентирован на протоколы **TLS 1.2** и **TLS 1.3**, обеспечивая баланс между безопасностью и производительностью.

Теоретические основы (процесс рукопожатия, шифры, гибридное шифрование) описаны в системном документе: **[Протокол TLS — системный обзор](../../../../Networking/Protocols/tls.md)**.

### Цепочка сертификатов (Certificate Chain)

Для успешной валидации клиент должен иметь возможность проследить путь доверия от серверного сертификата до доверенного корневого центра (Root CA).

*   **Серверный сертификат**: Выдан для вашего домена (например, `example.com`).
*   **Промежуточные сертификаты (Intermediate CA)**: Используются центрами сертификации для подписи конечных сертификатов, обеспечивая дополнительный уровень безопасности.

**Специфика Nginx**:
Nginx требует передачи «полной цепочки» в одном файле. Порядок сертификатов в файле критически важен:
1.  Сертификат домена.
2.  Промежуточные сертификаты (один или несколько).
*Корневой сертификат (Root CA) обычно не включается, так как он уже есть в хранилище клиента.*

Подробнее о форматах и диагностике: **[Диагностика SSL/TLS сертификатов](../../../../Security/Tools/ssl_certificate_diagnostics.md)**.

## Современные концепции и технологии

### Encrypted Client Hello (ECH)

**ECH** — это расширение TLS 1.3, которое шифрует всё приветствие клиента (ClientHello), включая поле **SNI (Server Name Indication)**.
- **Проблема**: Без ECH провайдеры и злоумышленники могут видеть имя домена, который вы посещаете, даже внутри зашифрованного канала.
- **Статус**: Поддерживается в Nginx 1.29+ при использовании OpenSSL 4.0 или специальных патчей.

### Perfect Forward Secrecy (PFS)

Гарантирует, что сессионные ключи не могут быть скомпрометированы даже при краже приватного ключа сервера. В Nginx обеспечивается через алгоритмы ECDHE (на эллиптических кривых).
- **Настройка**: [Глобальные параметры TLS](./nginx_tls_global_parameters.md).

### OCSP Stapling

Механизм оптимизации, при котором Nginx сам запрашивает статус валидности сертификата и передает его клиенту в процессе рукопожатия. Это ускоряет загрузку и повышает приватность пользователя.

### Kernel TLS (kTLS)

Перенос симметричного шифрования в ядро Linux (Kernel 5.10+).
- **Преимущество**: Позволяет использовать `sendfile()` напрямую с TLS, исключая копирование данных между user-space и ядром. Прирост производительности при отдаче статики — до 40%.

### HTTP/2 и HTTP/3 (QUIC)

- **HTTP/2**: Мультиплексирование запросов внутри одного TCP-соединения.
- **HTTP/3 (QUIC)**: Работает через UDP, интегрирует TLS 1.3 непосредственно в транспортный протокол, устраняя проблему блокировки очереди (Head-of-line blocking).
- **Настройка**: **[Конфигурация HTTP/2 и HTTP/3 в Nginx](../../Performance/nginx_http_versions.md)**.
