# Обзор TLS/SSL в Nginx

## Определения

### TLS в Nginx

**TLS (Transport Layer Security)** в Nginx обеспечивает надежное шифрование данных и проверку подлинности сервера при взаимодействии с клиентами. В 2026 году стандартом является **TLS 1.3**, который минимизирует задержки рукопожатия (1-RTT) и исключает устаревшие небезопасные шифры. Поддержка TLS 1.2 сохраняется только для совместимости с устаревшими клиентами.

Теоретические основы (процесс рукопожатия, шифры, гибридное шифрование) описаны в системном документе: **[Протокол TLS — системный обзор](../../../../Networking/Protocols/tls.md)**.

### Цепочка сертификатов (Certificate Chain)

Для успешной валидации клиент должен иметь возможность проследить путь доверия от серверного сертификата до доверенного корневого центра (Root CA).

*   **Серверный сертификат**: Выдан для вашего домена (Leaf).
*   **Промежуточные сертификаты (Intermediate CA)**: Используются центрами сертификации для подписи конечных сертификатов.

**Специфика Nginx**:
Nginx требует передачи «полной цепочки» (Full Chain) в одном файле. Порядок сертификатов в файле критически важен:
1.  Сертификат домена.
2.  Промежуточные сертификаты (один или несколько).
*Корневой сертификат (Root CA) обычно не включается, так как он уже есть в доверенном хранилище клиента.*

Подробнее о форматах и диагностике: **[Диагностика SSL/TLS сертификатов](../../../../Security/Tools/ssl_certificate_diagnostics.md)**.

### ALPN (Application-Layer Protocol Negotiation)

Расширение TLS, которое позволяет клиенту и серверу согласовать используемый протокол прикладного уровня (например, HTTP/2 или HTTP/3) непосредственно в процессе TLS-рукопожатия, избегая дополнительных сетевых задержек.

## Основные концепции

### Encrypted Client Hello (ECH)

**ECH** — это расширение TLS 1.3, которое шифрует всё приветствие клиента (ClientHello), полностью скрывая поле **SNI (Server Name Indication)**.
- **Проблема**: Без ECH провайдеры и злоумышленники могут видеть имя домена, который вы посещаете, даже внутри зашифрованного канала.
- **Статус (2026)**: Нативная поддержка в **Nginx 1.30+** (Stable) при использовании **OpenSSL 4.0+**.
- **Настройка**: Требует наличия директивы `ssl_ech_file` (путь к конфигурации ECH) и соответствующих записей в DNS (HTTPS/SVCB).

### Постквантовая криптография (PQC)

Защита от атак «Harvest Now, Decrypt Later» с использованием будущих квантовых компьютеров. 
- **Реализация**: В 2026 году **OpenSSL 3.5 LTS+** и **OpenSSL 4.0** включают поддержку алгоритма **ML-KEM (Kyber)** по умолчанию.
- **Гибридный обмен**: Nginx автоматически использует гибридные схемы (например, `X25519MLKEM768`), сочетающие классическую эллиптическую криптографию и квантово-устойчивые алгоритмы для обеспечения максимальной безопасности без потери совместимости.

### TLS 1.3 0-RTT (Early Data)

Механизм восстановления сессии, позволяющий клиенту отправить данные первого запроса (например, GET) вместе с приветствием, устраняя задержку на рукопожатие.
- **Риск**: Уязвимость к атакам воспроизведения (Replay Attacks).
- **Безопасность**: В Nginx включается через `ssl_early_data on`. Рекомендуется использовать только для безопасных (Idempotent) методов.

### Perfect Forward Secrecy (PFS)

Гарантирует, что сессионные ключи не могут быть скомпрометированы даже при краже приватного ключа сервера. В Nginx обеспечивается через алгоритмы ECDHE. В 2026 году использование PFS является обязательным стандартом.
- **Настройка**: [Глобальные параметры TLS](./nginx_tls_global_parameters.md).

### OCSP Stapling

Механизм оптимизации, при котором Nginx сам запрашивает статус валидности сертификата и передает его клиенту в процессе рукопожатия. Это ускоряет загрузку и повышает приватность пользователя, исключая прямое обращение клиента к OCSP-резолверу CA.

### Kernel TLS (kTLS)

Перенос симметричного шифрования (AES-GCM, ChaCha20) в ядро Linux (Kernel 5.10+).
- **Преимущество**: Позволяет использовать `sendfile()` напрямую с TLS, исключая копирование данных между user-space и ядром (Zero-copy). Прирост производительности при отдаче статики — до 40%.
- **Нюанс 2026**: В OpenSSL 3.5/4.0 произошла реконструкция уровня записей (record layer), что требует актуализации параметров буферов для сохранения максимальной эффективности.

### Динамический размер записей TLS (Dynamic Record Size)

Оптимизация передачи данных: использование маленьких записей в начале соединения (для минимизации TTFB) и переход к большим записям при передаче потоковых данных (для снижения нагрузки на CPU и повышения пропускной способности).

### Двойные стеки сертификатов (RSA + ECDSA)

Возможность одновременного использования старых RSA-сертификатов (для совместимости) и современных ECDSA-сертификатов (для производительности и безопасности). Nginx автоматически выбирает лучший вариант в зависимости от возможностей клиента. В 2026 году ECDSA является предпочтительным стандартом.

### HTTP/2 и HTTP/3 (QUIC)

- **HTTP/2**: Мультиплексирование запросов внутри одного TCP-соединения.
- **HTTP/3 (QUIC)**: Работает через UDP, интегрирует TLS 1.3 непосредственно в транспортный протокол, полностью устраняя проблему блокировки очереди (Head-of-line blocking). В Nginx 1.30+ поддержка HTTP/3 является нативной и стабильной.
- **Настройка**: **[Конфигурация HTTP/2 и HTTP/3 в Nginx](../../Performance/nginx_http_versions.md)**.
