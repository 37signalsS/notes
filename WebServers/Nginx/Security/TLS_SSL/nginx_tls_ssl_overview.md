# Обзор TLS/SSL в Nginx

## Определения

### TLS Handshake — процесс установки соединения

1. **TCP Handshake:** Устанавливается стандартное TCP-соединение.
2. **[TLS Handshake](../../../../Networking/Protocols/tls.md#процесс-рукопожатия-tls-handshake):**
    * Сервер отправляет клиенту свой публичный сертификат.
    * Клиент проверяет валидность сертификата (срок действия, цепочку доверия).
    * Клиент и сервер согласовывают сессионный ключ (master key) с использованием **[асимметричного шифрования](../../../../Networking/Protocols/tls.md#гибридное-шифрование)**. Этот процесс вычислительно дорогой.
    * Дальнейший обмен данными происходит с использованием **[симметричного шифрования](../../../../Networking/Protocols/tls.md#гибридное-шифрование)**, которое значительно быстрее и эффективнее для больших объёмов трафика.

Подробнее о параметрах TLS-соединения см. [Глобальные параметры TLS в Nginx](./nginx_tls_global_parameters.md).

### Иерархия и цепочка сертификатов

Для успешной проверки подлинности сервера клиент должен иметь возможность проверить всю цепочку сертификатов.

* **Корневой сертификат (Root CA):** Предустановлен в ОС или браузере. Является вершиной цепочки доверия.
* **Промежуточный сертификат (Intermediate CA):** Сертификат, выданный корневым центром и используемый для подписи сертификатов конечных пользователей. Их может быть несколько.
* **Серверный сертификат (Server Certificate):** Сертификат, выданный для вашего домена.

При настройке Nginx необходимо предоставить файл, содержащий **цепочку сертификатов**: сначала серверный сертификат, затем все промежуточные. Корневой сертификат включать не нужно.

```plaintext
-----BEGIN CERTIFICATE-----
(Ваш серверный сертификат)
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
(Промежуточный сертификат)
-----END CERTIFICATE-----
```

Для установки требуются два файла:

1. **Файл цепочки сертификатов (`fullchain.pem`):** содержит серверный сертификат + все промежуточные.
2. **Приватный ключ (`privkey.pem`):** секретный ключ, сгенерированный вместе с запросом на сертификат (CSR).

Конфигурация сертификатов на уровне виртуального хоста описана в [Конфигурация виртуальных хостов TLS](./nginx_tls_virtual_host_config.md).

## Базовые понятия

### Perfect Forward Secrecy (PFS)

PFS обеспечивается эфемерными алгоритмами обмена ключами (ECDHE, DHE). Для каждой сессии создаётся уникальный временный ключ. Если приватный ключ сервера будет скомпрометирован, злоумышленник не сможет расшифровать ранее перехваченный трафик.

Настройка шифров с PFS: [Глобальные параметры TLS](./nginx_tls_global_parameters.md#протоколы-и-шифры).

### Strict-Transport-Security (HSTS)

HSTS — заголовок HTTP-ответа, указывающий браузеру взаимодействовать с сайтом только по HTTPS. Предотвращает атаки понижения версии протокола.

Конфигурация HSTS: [Виртуальный хост TLS](./nginx_tls_virtual_host_config.md#базовая-конфигурация-https).

### OCSP Stapling

OCSP Stapling — механизм, при котором сервер сам получает подписанный ответ от CA о статусе своего сертификата и «прикрепляет» его к TLS-рукопожатию. Избавляет клиента от отдельного запроса к OCSP-серверу CA, ускоряя установку соединения.

Настройка OCSP Stapling: [Глобальные параметры TLS](./nginx_tls_global_parameters.md#настройка-ocsp-stapling).

### HTTP/2 и HTTP/3 (QUIC)

Современные протоколы HTTP/2 и HTTP/3 (на базе QUIC) ускоряют загрузку сайтов благодаря мультиплексированию запросов, сжатию заголовков и приоритизации потоков. HTTP/3 использует UDP вместо TCP, снижая задержки.

Конфигурация: [HTTP/2 в Nginx](./nginx_tls_virtual_host_config.md#включение-http2) и [HTTP/3 в Nginx](./nginx_tls_virtual_host_config.md#включение-http3-quic).

### Mutual TLS (mTLS)

mTLS — механизм взаимной аутентификации, при котором сервер проверяет сертификат клиента. Ключевой компонент безопасной коммуникации в архитектуре [Service Mesh](../../../../Service_Mesh/service_mesh_concepts.md).

Полная документация: [Настройка mTLS в Nginx](./nginx_mtls_configuration.md).

### Kernel TLS (kTLS)

Kernel TLS — механизм переноса операций шифрования TLS из пользовательского пространства (OpenSSL) в ядро ОС. Позволяет использовать системный вызов `sendfile` для отдачи статических файлов по HTTPS.

**Основные положения:**

* **Прирост производительности:** ~30% для HTTP/1.1 при отдаче больших файлов
* **Несовместимость с HTTP/2:** использование kTLS с HTTP/2 приводит к деградации производительности в 2–4 раза
* **Требования:** ядро Linux 5.x+, OpenSSL 3.0+, модуль ядра `tls`

Полная документация: [Оптимизация производительности Nginx](../../Performance/nginx_performance_tuning.md#kernel-tls-ktls).
