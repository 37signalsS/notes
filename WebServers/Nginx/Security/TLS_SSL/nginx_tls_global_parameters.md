# Глобальные параметры TLS в Nginx

**Надёжность:** 10 (SSoT + Официальная документация Nginx 1.26/1.27 + Спецификации OpenSSL 3.5)
**Свежесть:** Июль 2026 (Актуально для Nginx 1.26+, 1.27.x+)

## Определения

**Глобальные параметры TLS** — настройки протокола безопасности, которые задаются в блоке `http` файла `nginx.conf` и применяются ко всем виртуальным хостам сервера. Централизованное управление этими параметрами обеспечивает единообразную политику безопасности, упрощает аудит и повышает производительность.

**Возобновление сессии (Session Resumption)** — механизмы, позволяющие клиенту и серверу повторно использовать ранее согласованные параметры безопасности, избегая ресурсоемкого полного процесса рукопожатия.
*   **[Механизмы возобновления сессии](../../../../Networking/Protocols/tls.md#возобновление-сессии-session-resumption)** (теория).

**OCSP Stapling** — технология оптимизации, при которой сервер самостоятельно запрашивает статус валидности своего сертификата у CA и «прикрепляет» ответ к TLS-рукопожатию, ускоряя проверку на стороне клиента.

## Основные концепции

### Требования к окружению (2026)

Для поддержки новейших функций (HTTP/3, ECH, Постквантовая криптография) Nginx должен быть собран с актуальными библиотеками:
*   **OpenSSL 3.0/3.1**: Базовый уровень, поддержка TLS 1.3 и kTLS.
*   **OpenSSL 3.5.1+**: Рекомендуется для нативного QUIC API и полноценной поддержки 0-RTT.
*   **OpenSSL 4.0**: Необходим для нативного ECH (Encrypted Client Hello).

Проверка версии: `nginx -V` (искать строку `built with OpenSSL`).

### Управление сессиями и кэширование

#### Кэширование на стороне сервера (`ssl_session_cache`)
Основной механизм для TLS 1.2. Создает разделяемую зону памяти между всеми рабочими процессами Nginx.
*   `shared:SSL:10m` — 10 МБ памяти вмещают около 40 000 сессий. Рекомендуется устанавливать таймаут `ssl_session_timeout 1d;` для баланса безопасности и удобства пользователей.

#### Билеты сессий (`ssl_session_tickets`)
Хранение состояния сессии на стороне клиента в зашифрованном виде.
*   **Рекомендация:** `off`. Использование билетов без автоматической ротации ключей может нарушить **[PFS (Perfect Forward Secrecy)](../../../../Networking/Protocols/tls.md#perfect-forward-secrecy-pfs)**. С версии Nginx 1.23.2+ поддерживается автоматическая ротация ключей билетов.

### Протоколы и шифрование

#### Директива `ssl_protocols`
Определяет разрешенные версии TLS.
*   **Безопасный стандарт 2026**: `TLSv1.2 TLSv1.3`. 
*   Протоколы TLS 1.0 и 1.1 должны быть полностью отключены (RFC 8996).

#### Директива `ssl_ciphers`
Список алгоритмов шифрования для TLS 1.2. В TLS 1.3 наборы шифров фиксированы и управляются библиотекой автоматически.
*   **Рекомендация**: Используйте только AEAD-шифры (GCM, ChaCha20).
*   Пример (Mozilla Modern): `'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305'`.

#### Директива `ssl_prefer_server_ciphers`
*   `off`: Рекомендуется для современных систем. Позволяет клиенту выбрать наиболее производительный алгоритм (например, ChaCha20 на мобильных устройствах без аппаратного ускорения AES).

### Продвинутые команды OpenSSL (`ssl_conf_command`)

Позволяет передавать низкоуровневые параметры напрямую в библиотеку OpenSSL (только для OpenSSL 1.1.1+).

```nginx
# Управление наборами шифров TLS 1.3 (если не устраивают дефолтные)
ssl_conf_command Ciphersuites TLS_AES_256_GCM_SHA384:TLS_AES_128_GCM_SHA256;

# Принудительная приоритизация ChaCha20
ssl_conf_command Options PrioritizeChaCha;

# Включение kTLS на уровне библиотеки
ssl_conf_command Options KTLS;
```

## Безопасность и оптимизация

### Постквантовая защита (Hybrid ML-KEM)
В 2026 году для защиты от перехвата трафика с целью последующей расшифровки квантовыми компьютерами («harvest now, decrypt later») рекомендуется использовать гибридные кривые.
```nginx
# Стандарт 2026 года при наличии OpenSSL 3.5+
ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1:secp384r1;
```

### Защита Default Server (`ssl_reject_handshake`)
Для блокировки запросов по IP-адресу или к неизвестным доменам без передачи сертификата (что предотвращает утечку имен доменов в сертификатах-заглушках).
```nginx
server {
    listen 443 ssl default_server;
    server_name _;
    ssl_reject_handshake on; # Обрывает TLS на стадии рукопожатия
}
```

### Ранние данные (`ssl_early_data` / 0-RTT)
Ускоряет загрузку в TLS 1.3, отправляя данные в первом пакете.
*   **Риск**: Уязвимость к Replay-атакам (повторное воспроизведение запроса злоумышленником).
*   **Best Practice**: Включать только при наличии защиты на уровне приложения (обработка заголовка `Early-Data`) и ограничивать размер буфера: `ssl_buffer_size 4k;`.

## Практические сценарии

### Эталонная глобальная конфигурация (nginx.conf)

```nginx
http {
    # Глобальные настройки TLS
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305';
    ssl_prefer_server_ciphers off;

    # Управление сессиями
    ssl_session_timeout 1d;
    ssl_session_cache shared:SSL:10m;
    ssl_session_tickets off;

    # Современный обмен ключами (включая PQC)
    ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1:secp384r1;

    # OCSP Stapling (ускорение проверки сертификатов)
    ssl_stapling on;
    ssl_stapling_verify on;
    resolver 1.1.1.1 8.8.8.8 valid=300s;
    resolver_timeout 5s;

    # Оптимизация TTFB
    ssl_buffer_size 4k;
    
    # Скрытие версии
    server_tokens off;
}
```

### Логирование параметров TLS
Для диагностики и подтверждения того, что клиенты используют современные шифры.
```nginx
log_format tls_audit '$remote_addr [$time_local] "$request" '
                     'ssl_cipher:$ssl_cipher ssl_protocol:$ssl_protocol '
                     'pqc_curve:$ssl_curves';

server {
    access_log /var/log/nginx/tls_audit.log tls_audit;
}
```
