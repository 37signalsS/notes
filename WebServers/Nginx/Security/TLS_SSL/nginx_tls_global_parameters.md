# Глобальные параметры TLS в Nginx

## Определения

**Глобальные параметры TLS** — настройки протокола безопасности, которые задаются в блоке `http` файла `nginx.conf` и применяются ко всем виртуальным хостам сервера. Централизованное управление этими параметрами обеспечивает единообразную политику безопасности, упрощает аудит и повышает производительность.

**Возобновление сессии (Session Resumption)** — механизмы, позволяющие клиенту и серверу повторно использовать ранее согласованные параметры безопасности, избегая ресурсоемкого полного процесса рукопожатия.
*   **[Механизмы возобновления сессии](../../../../Networking/Protocols/tls.md#возобновление-сессии-session-resumption)** (теория).

**OCSP Stapling** — технология оптимизации, при которой сервер самостоятельно запрашивает статус валидности своего сертификата у CA и «прикрепляет» ответ к TLS-рукопожатию, ускоряя проверку на стороне клиента и повышая уровень приватности.

## Основные концепции

### Требования к окружению (2026)

Для поддержки современных функций безопасности (HTTP/3, ECH, PQC) Nginx должен быть собран с актуальными библиотеками:
*   **OpenSSL 3.0/3.1**: Базовый уровень 2026 года, обеспечивающий поддержку TLS 1.3 и kTLS.
*   **OpenSSL 3.5.1+**: Рекомендуется для стабильной работы нативного QUIC API и полноценной поддержки 0-RTT. Включает **ML-KEM (Kyber)** по умолчанию.
*   **OpenSSL 4.0**: Необходим для нативной поддержки **ECH (Encrypted Client Hello)**.

Проверка версии: `nginx -V` (строка `built with OpenSSL`).

### Управление сессиями и кэширование

#### Кэширование на стороне сервера (`ssl_session_cache`)
Основной механизм для TLS 1.2. Создает разделяемую зону памяти между рабочими процессами Nginx.
*   **Расчет**: `shared:SSL:10m` — 10 МБ памяти вмещают около 40 000 сессий. 
*   **Таймаут**: Рекомендуется `ssl_session_timeout 1d;` (24 часа) для минимизации полных рукопожатий при повторных визитах.

#### Билеты сессий (`ssl_session_tickets`)
Хранение состояния сессии на стороне клиента в зашифрованном виде.
*   **Безопасность**: Рекомендуется значение `off`, так как использование билетов без автоматической ротации ключей может нарушить **[PFS (Perfect Forward Secrecy)](../../../../Networking/Protocols/tls.md#perfect-forward-secrecy-pfs)**. 
*   **Автоматизация**: С версии Nginx 1.23.2+ поддерживается автоматическая ротация ключей билетов внутри рабочих процессов.

### Протоколы и шифрование

#### Директива `ssl_protocols`
Определяет разрешенные версии TLS.
*   **Стандарт 2026**: `TLSv1.2 TLSv1.3`. 
*   **Запрещено**: Протоколы TLS 1.0 и 1.1 должны быть отключены согласно RFC 8996.

#### Директива `ssl_ciphers`
Список алгоритмов для TLS 1.2. В TLS 1.3 наборы шифров фиксированы и управляются библиотекой автоматически.
*   **Рекомендация**: Используйте только AEAD-шифры (GCM, ChaCha20).
*   **Пример (Mozilla Modern)**: `'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305'`.

#### Директива `ssl_prefer_server_ciphers`
*   **`off`**: Рекомендуется для современных систем 2026 года. Позволяет клиенту выбрать наиболее производительный алгоритм (например, ChaCha20 на мобильных устройствах без аппаратного ускорения AES), что снижает нагрузку на CPU клиента и экономит заряд батареи.

### Продвинутые команды OpenSSL (`ssl_conf_command`)

Позволяет передавать низкоуровневые параметры напрямую в библиотеку OpenSSL (требует OpenSSL 1.1.1+).

```nginx
# Управление наборами шифров TLS 1.3 (если не устраивают дефолтные библиотеки)
ssl_conf_command Ciphersuites TLS_AES_256_GCM_SHA384:TLS_AES_128_GCM_SHA256;

# Принудительная приоритизация ChaCha20 для всех клиентов
ssl_conf_command Options PrioritizeChaCha;

# Включение kTLS на уровне библиотеки (если не включено в сборке)
ssl_conf_command Options KTLS;
```

## Безопасность и оптимизация

### Постквантовая защита (Hybrid ML-KEM)
В 2026 году для защиты от атак «harvest now, decrypt later» (перехват сейчас — расшифровка потом квантовым компьютером) обязательно использование гибридных кривых.
```nginx
# Стандарт 2026 года при наличии OpenSSL 3.5+
# Объединяет X25519 и ML-KEM-768
ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1:secp384r1;
```

### Защита Default Server (`ssl_reject_handshake`)
Метод блокировки запросов по IP или к неизвестным доменам. Предотвращает утечку имен доменов в сертификатах и снижает нагрузку от сканеров.
```nginx
server {
    listen 443 ssl default_server;
    server_name _;
    # Обрывает TLS на стадии рукопожатия, не отправляя сертификат
    ssl_reject_handshake on; 
}
```

### Ранние данные (`ssl_early_data` / 0-RTT)
Позволяет клиенту отправить GET-запрос вместе с приветствием TLS 1.3.
*   **Риск**: Уязвимость к Replay-атакам (повтор транзакций).
*   **Защита**: Включать только при наличии обработки заголовка `Early-Data` на бэкенде.
*   **Тюнинг**: Рекомендуется ограничивать размер буфера: `ssl_buffer_size 4k;` для ускорения первого ответа.

## Практические сценарии

### Эталонная глобальная конфигурация (nginx.conf)

```nginx
http {
    # Глобальные настройки протоколов и шифров
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305';
    ssl_prefer_server_ciphers off;

    # Управление сессиями (24 часа кэша, тикеты выключены для PFS)
    ssl_session_timeout 1d;
    ssl_session_cache shared:SSL:10m;
    ssl_session_tickets off;

    # Современный обмен ключами (включая Hybrid PQC)
    ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1:secp384r1;

    # OCSP Stapling (обязательно с резолвером)
    ssl_stapling on;
    ssl_stapling_verify on;
    resolver 1.1.1.1 8.8.8.8 valid=300s;
    resolver_timeout 5s;

    # Оптимизация TTFB и kTLS
    ssl_buffer_size 4k;
    ssl_conf_command Options +KTLS;
    
    # Скрытие версии сервера
    server_tokens off;
}
```

### Логирование параметров TLS для аудита
Позволяет подтвердить использование PQC-алгоритмов и анализировать распределение версий TLS.
```nginx
log_format tls_audit '$remote_addr [$time_local] "$request" '
                     'ssl_cipher:$ssl_cipher ssl_protocol:$ssl_protocol '
                     'pqc_curve:$ssl_curves ech_status:$ssl_ech_status';

server {
    access_log /var/log/nginx/tls_audit.log tls_audit;
}
```
