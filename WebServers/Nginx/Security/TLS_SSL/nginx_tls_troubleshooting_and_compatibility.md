# Диагностика TLS/SSL в Nginx и совместимость клиентов

## Определения

### TLS Troubleshooting (Диагностика TLS)

Процесс выявления и устранения проблем с TLS-соединениями в Nginx. Включает проверку синтаксиса конфигурации, анализ TLS-рукопожатия и валидацию цепочки сертификатов. Основные методы диагностики SSL/TLS описаны в: [Диагностика SSL/TLS сертификатов](../../../../Security/Tools/ssl_certificate_diagnostics.md).

### Server Name Indication (SNI)

Расширение протокола TLS, позволяющее клиенту указывать имя хоста (домен) на этапе установления соединения. Это необходимо для корректной работы нескольких HTTPS-сайтов на одном IP-адресе. Подробное описание и принцип работы: [Протокол TLS — SNI](../../../../Networking/Protocols/tls.md#sni-server-name-indication).

### OCSP Stapling

Механизм оптимизации, при котором веб-сервер самостоятельно запрашивает статус валидности своего сертификата у центра сертификации (CA) и «прикрепляет» его к TLS-рукопожатию. Подробнее: [Глобальные параметры TLS в Nginx — OCSP Stapling](./nginx_tls_global_parameters.md#настройка-ocsp-stapling).

## Основные понятия

### Уровни диагностики в Nginx

Для эффективного поиска проблем рекомендуется проверять конфигурацию послойно:

1. **Синтаксический уровень:** Проверка корректности директив Nginx с помощью встроенных средств валидации.
2. **Сетевой уровень:** Проверка доступности портов 443 по протоколам TCP (для стандартного HTTPS) и UDP (для HTTP/3 QUIC).
3. **Уровень TLS-рукопожатия:** Проверка цепочки сертификатов, поддерживаемых версий протоколов и наборов шифров.
4. **Внешняя оценка:** Глубокий анализ безопасности и совместимости через сторонние сервисы (например, SSL Labs).

## Практические сценарии

### Проверка конфигурации Nginx

Перед перезапуском сервиса всегда проверяйте синтаксис файлов конфигурации. Ошибка в TLS-директивах может привести к остановке веб-сервера.

```bash
sudo nginx -t
```

Подробно об общей диагностике Nginx: [Устранение неполадок в Nginx](../../Operations/nginx_troubleshooting.md).

### Проверка сетевой доступности портов

Убедитесь, что Nginx слушает порты и они не заблокированы файрволом.

```bash
# Проверка TCP порта 443 (HTTPS)
ss -tlpn | grep :443

# Проверка UDP порта 443 (HTTP/3 / QUIC)
# При использовании reuseport может отображаться несколько записей (по одной на воркер)
ss -ulpn | grep :443
```

### Анализ TLS-рукопожатия через CLI

Используйте `openssl s_client` для детальной проверки. При использовании виртуальных хостов параметр `-servername` обязателен для передачи SNI.

```bash
openssl s_client -connect your_domain.com:443 -servername your_domain.com
```

**Ключевые элементы вывода:**

- `Protocol` — используемая версия TLS (рекомендуется TLSv1.2 или TLSv1.3).
- `Verify return code: 0 (ok)` — цепочка сертификатов успешно проверена.
- `OCSP response` — наличие подписанного статуса (если включен Stapling).

Полный список команд для диагностики сертификатов: [Диагностика SSL/TLS сертификатов](../../../../Security/Tools/ssl_certificate_diagnostics.md).

### Тестирование через SSL Labs

Сервис [SSL Labs](https://www.ssllabs.com/ssltest/) предоставляет комплексную оценку безопасности.

- **Handshake Simulation:** Эмуляция подключения различных клиентов (ОС и браузеров).
- **Chain issues:** Проверка полноты цепочки сертификатов (наличие промежуточных CA в `ssl_certificate`).
- **Protocol Support:** Проверка на использование устаревших и небезопасных протоколов (SSLv2, SSLv3, TLS 1.0, 1.1).

## Дополнительная информация

### Совместимость клиентов

Выбор протоколов и шифров напрямую влияет на то, какие устройства смогут подключиться к серверу.

#### Современная конфигурация (TLS 1.2, 1.3)

Рекомендуемый стандарт для большинства современных проектов. Обеспечивает поддержку актуальных ОС и браузеров.

| Клиент | Минимальная версия | Примечание |
| :--- | :--- | :--- |
| **Android** | 4.4.2 | TLS 1.2+. TLS 1.3 доступен с Android 8.1 |
| **Windows** | 7 SP1 / 10 | IE 11+, Chrome 30+, Firefox 27+ |
| **iOS / Safari** | iOS 9 / macOS 10.11 | Safari 9+ |
| **Java** | 8 | TLS 1.2 по умолчанию |
| **OpenSSL** | 1.0.1 | Поддержка TLS 1.2 |

#### Устаревшие клиенты (не поддерживаются)

Эти системы требуют включения устаревших протоколов или слабых шифров, что снижает общую безопасность сервера.

- **Windows XP / Vista:** Internet Explorer 6, 7, 8.
- **Android:** Версии 2.x - 4.3.
- **Java:** Версии 6, 7 (без дополнительных настроек).
- **OpenSSL:** Версии ниже 1.0.1 (например, 0.9.8).
- **Safari:** Версии ниже 9.
