# Диагностика TLS/SSL в Nginx и совместимость клиентов

## Определения

**TLS Troubleshooting (Диагностика TLS)** — процесс выявления причин сбоев при установке защищенного соединения (рукопожатия). Включает анализ системных логов, проверку цепочек доверия сертификатов и согласование наборов шифров между клиентом и сервером.

**Server Name Indication (SNI)** — расширение TLS, позволяющее клиенту передавать имя хоста до завершения рукопожатия. Это критично для корректного выбора виртуального хоста (`server`) на одном IP-адресе.

**Encrypted Client Hello (ECH)** — расширение TLS 1.3, шифрующее всё приветствие клиента. В 2026 году является ключевым механизмом защиты приватности, скрывающим SNI от сетевых посредников.

**OCSP Stapling** — механизм оптимизации, при котором сервер сам запрашивает статус валидности своего сертификата у CA и передает его клиенту в процессе рукопожатия, ускоряя проверку и повышая приватность.

## Уровни диагностики

### 1. Анализ системных логов (`error_log`)

Для эффективной диагностики TLS необходимо установить уровень логирования `info` в блоке `main` или `http`:
`error_log /var/log/nginx/error.log info;`

| Ошибка в логе | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `no shared cipher` | Нет пересечения в поддерживаемых шифрах. | Проверьте `ssl_ciphers`. В 2026 используйте ECDSA. |
| `alert handshake failure (40)` | Клиент не передал SNI или сервер требует mTLS сертификат. | Проверьте `ssl_verify_client` и наличие SNI у клиента. |
| `certificate verify failed` | Ошибка в `ssl_client_certificate`. | Убедитесь, что файл содержит всю цепочку до Root CA. |
| `0-RTT early data rejected` | Проблема совместимости или риск Replay-атаки. | Проверьте `ssl_early_data` и настройки на бэкенде. |
| `ECH decryption failed` | Неверные ключи ECH в `ssl_ech_file`. | Обновите конфигурацию ECH согласно записям в DNS. |

### 2. Проверка HTTP/3 и QUIC (UDP 443)

HTTP/3 работает через UDP, поэтому стандартные средства (telnet, nc -z) не подходят.

**Инструментарий для диагностики:**
- **Локальная проверка**: `ss -ulpn | grep :443` (nginx должен слушать UDP).
- **Проверка модуля**: `nginx -V 2>&1 | grep -o 'http_v3_module'`
- **Внешний тест**: `curl --http3 -v -I https://example.com`
- **Проверка анонса**: Убедитесь, что заголовок `Alt-Svc: h3=":443"; ma=86400` присутствует в ответах через HTTP/2.

### 3. Анализ рукопожатия через CLI

Используйте `openssl s_client` (требуется версия 3.0+) с обязательным указанием `-servername` для проверки SNI:
```bash
openssl s_client -connect domain.com:443 -servername domain.com -status
```

**Ключевые показатели:**
- `Verification: OK`: Цепочка сертификатов в порядке.
- `Cipher is ...`: Проверка согласованного алгоритма (например, AES128-GCM-SHA256).
- `OCSP response: provided`: Подтверждение работы OCSP Stapling.
- `Protocol: TLSv1.3`: Подтверждение использования актуальной версии протокола.

## Практические сценарии

### 1. Логирование параметров TLS для аудита

Для анализа совместимости реальных клиентов добавьте расширенный формат лога:

```nginx
log_format tls_audit '$remote_addr [$time_local] "$request" '
                     'proto:$ssl_protocol cipher:$ssl_cipher '
                     'curve:$ssl_curves ech:$ssl_ech_status';

access_log /var/log/nginx/tls_audit.log tls_audit;
```

### 2. Диагностика проблем с "Reload" в QUIC

В Nginx 1.27.x и 1.29.x при использовании `quic_bpf on;` команда `reload` может вызывать кратковременную потерю UDP-пакетов.
**Решение**: Если после релоада HTTP/3 перестал отвечать, временно отключите `quic_bpf` или используйте `quic_retry on;` для повышения надежности установки соединений.

### 3. Внешний аудит безопасности

Для публичных сервисов используйте **SSL Labs Server Test**. 
**На что смотреть (2026):**
- **Grade A+**: Требует наличия HSTS и отсутствия устаревших шифров.
- **Chain issues**: Ошибки «Extra download» указывают на отсутствие Intermediate CA в `ssl_certificate`.
- **PQC Support**: Проверка готовности к постквантовым атакам (Hybrid ML-KEM).

## Совместимость клиентов (Baseline 2026)

| Категория | Поддержка | Рекомендация |
| :--- | :--- | :--- |
| **Современные (Chrome 125+, FF 125+)** | TLS 1.3, HTTP/3, ECH, Hybrid PQC | Полная поддержка всех функций безопасности 2026 года. |
| **Apple (iOS 18+, macOS 15+)** | TLS 1.3, HTTP/3, Hybrid PQC | ECH поддерживается нативно при наличии DNS HTTPS записей. |
| **Legacy Android (8.0 - 11.0)** | TLS 1.2 / 1.3 | Требуют наличия ECDHE-AES-GCM шифров для работы. |
| **Инфраструктурные (Java 11, Go 1.22+)** | TLS 1.3 | Поддерживают современный TLS, но могут не поддерживать ECH. |

**Важное замечание**: TLS 1.0 и 1.1 полностью выведены из эксплуатации. В Nginx 1.30+ поддержка этих протоколов может быть удалена на уровне сборки.
