# Диагностика TLS/SSL в Nginx и совместимость клиентов

**Надёжность:** 10 (SSoT + Официальная документация Nginx 1.26/1.27 + Спецификации RFC 9114/9460)
**Свежесть:** Июль 2026 (Актуально для Nginx 1.26+, 1.27.x+)

## Определения

**TLS Troubleshooting (Диагностика TLS)** — процесс выявления причин сбоев при установке защищенного соединения (рукопожатия). Включает анализ логов, проверку цепочек сертификатов и соответствия наборов шифров.

**Server Name Indication (SNI)** — расширение TLS, позволяющее клиенту передавать имя хоста до начала шифрования. Критично для работы виртуальных хостов на одном IP.

**Encrypted Client Hello (ECH)** — (Стандарт 2026) расширение TLS 1.3, шифрующее всё приветствие клиента, включая SNI, что предотвращает утечку посещаемых доменов провайдерам.

**OCSP Stapling** — механизм, при котором сервер сам доставляет клиенту статус валидности сертификата, избавляя браузер от лишних запросов к CA.

## Уровни диагностики

### 1. Анализ системных логов (`error_log`)

Для диагностики TLS необходимо установить уровень логирования `info` (в контексте `main` или `http`):
`error_log /var/log/nginx/error.log info;`

| Ошибка в логе | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `no shared cipher` | Нет пересечения в поддерживаемых шифрах. | Проверьте `ssl_ciphers`. В 2026 используйте ECDSA. |
| `alert handshake failure (40)` | Клиент не передал SNI или сервер требует клиентский сертификат. | Проверьте `ssl_verify_client` и настройки SNI. |
| `certificate verify failed` | Ошибка в `ssl_client_certificate`. | Убедитесь, что в файле вся цепочка до Root CA. |
| `0-RTT early data rejected` | Проблема совместимости или риск Replay-атаки. | См. раздел по [0-RTT в глобальных параметрах](./nginx_tls_global_parameters.md). |

### 2. Проверка HTTP/3 и QUIC

Так как HTTP/3 работает через UDP 443, стандартные инструменты проверки TCP-портов неэффективны.

**Команды для проверки:**
- **Наличие модуля**: `nginx -V 2>&1 | grep -o 'http_v3_module'`
- **Проверка UDP**: `ss -ulpn | grep :443` (должны быть записи с процессом nginx).
- **Тест извне**: `curl --http3 -I https://example.com` (требует актуальной версии curl).

**Внимание**: Если HTTP/3 не работает, проверьте наличие заголовка `Alt-Svc` в ответе сервера (HTTP/2/1.1), так как браузеры узнают о QUIC только через него.

### 3. Анализ рукопожатия через CLI

Используйте `openssl s_client` с обязательным указанием `-servername` для SNI:
```bash
openssl s_client -connect your_domain.com:443 -servername your_domain.com
```

**На что смотреть:**
- `Verification: OK` — цепочка доверия в порядке.
- `New, TLSv1.3, Cipher is ...` — используется актуальный протокол и шифр.
- `OCSP response: provided` — OCSP Stapling работает корректно.

## Практические сценарии

### Сценарий 1: Логирование параметров TLS для аудита

Добавьте в `nginx.conf` расширенный формат лога, чтобы видеть, какие клиенты используют устаревшие системы.

```nginx
log_format tls_audit '$remote_addr [$time_local] "$request" '
                     'proto:$ssl_protocol cipher:$ssl_cipher '
                     'curve:$ssl_curves ech:$ssl_ech_status';

server {
    access_log /var/log/nginx/tls_audit.log tls_audit;
}
```

### Сценарий 2: Диагностика "Reload Bug" в QUIC

В версиях до 1.27.4 при включенном `quic_bpf on;` команда `nginx -s reload` может приводить к потере пакетов QUIC.
**Решение**: Если после релоада HTTP/3 перестал отвечать, временно установите `quic_bpf off;` и проверьте стабильность.

### Сценарий 3: Внешняя проверка через SSL Labs

Для публичных серверов [SSL Labs Server Test](https://www.ssllabs.com/ssltest/) является обязательным шагом:
- Проверка **Chain issues** (не забыли ли вы Intermediate сертификат).
- Проверка **HSTS Preload** статуса.
- Тестирование на уязвимости (Heartbleed, POODLE и т.д. — в 2026 актуально для legacy-сред).

## Совместимость клиентов (Baseline 2026)

| Категория | Поддержка | Рекомендация |
| :--- | :--- | :--- |
| **Современные (Chrome 120+, FF 120+)** | TLS 1.3, HTTP/3, ECH | Идеальная поддержка всех функций 2026 года. |
| **Apple (iOS 17+, macOS 14+)** | TLS 1.3, HTTP/3 | ECH поддерживается частично (может требовать DNS HTTPS RR). |
| **Legacy Android (7.0 - 10.0)** | TLS 1.2 / 1.3 | Требуют наличия ECDHE-шифров в `ssl_ciphers`. |
| **Инфраструктурные (Java 8, OpenSSL 1.0.2)**| TLS 1.2 (ограничено) | Не поддерживают современные PQC кривые и TLS 1.3. |

**Важное замечание**: Протоколы TLS 1.0 и 1.1 официально признаны небезопасными (RFC 8996) и должны быть отключены. В Nginx 1.27.3+ они отключены по умолчанию.
