# VXLAN (Virtual Extensible LAN)

## Определения

VXLAN — это протокол туннелирования, разработанный для создания оверлейных сетей (overlay networks) в крупных виртуализированных средах и облачных дата-центрах. Он позволяет расширять сегменты локальной сети (L2) через маршрутизируемую IP-сеть (L3), решая проблемы масштабируемости, присущие традиционным VLAN.

## Базовые концепции

### Принцип работы

VXLAN инкапсулирует Ethernet-кадры (L2) в UDP-пакеты. Это позволяет передавать L2-трафик через L3-инфраструктуру, используя стандартные IP-маршрутизаторы.

* **Инкапсуляция:** Ethernet-кадр + VXLAN-заголовок + UDP-заголовок + IP-заголовок (обычно IPv4).
* **UDP-порт:** По умолчанию используется UDP-порт `4789`. В Linux-ядре по умолчанию может использоваться нестандартный порт (например, `8472`), так как реализация появилась до стандартизации порта IANA.
* **VNI (Virtual Network Identifier):** 24-битный идентификатор, который позволяет создать до 16 миллионов уникальных виртуальных сетей. Это значительно больше, чем 4096 VLAN-ов, и решает проблему масштабирования в крупных мультиарендных средах.

### Преимущества VXLAN

* **Масштабируемость:** VNI в 16 миллионов сетей значительно превосходит ограничения VLAN.
* **Гибкость:** Позволяет создавать L2-оверлеи поверх L3-инфраструктуры, упрощая развертывание виртуальных машин и контейнеров.
* **Совместимость с NAT:** Поскольку VXLAN инкапсулируется в UDP, он хорошо работает через устройства NAT.

## Практические сценарии

### Режимы работы VXLAN

#### 1. Unicast (точка-точка)

В этом режиме VXLAN-туннель явно устанавливается между двумя конечными точками. Это похоже на [GRE](./gre.md) в режиме точка-точка, но с инкапсуляцией L2-кадров в UDP.

**Пример настройки в Linux:**

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip link add vxlan0 type vxlan id 100 remote 192.0.2.2 local 192.0.2.1 dev eth0
sudo ip link set vxlan0 up
sudo ip address add 10.8.0.1/24 dev vxlan0

# На стороне 2 (например, 192.0.2.2)
sudo ip link add vxlan0 type vxlan id 100 remote 192.0.2.1 local 192.0.2.2 dev eth0
sudo ip link set vxlan0 up
sudo ip address add 10.8.0.2/24 dev vxlan0
```

* `id 100`: Указывает VNI для этой виртуальной сети.
* `dev eth0`: Указывает физический интерфейс, через который будет идти VXLAN-трафик.

#### 2. Multicast (многоточечный)

Это более мощный режим, который позволяет множеству хостов динамически присоединяться к одной VXLAN-сети без необходимости вручную настраивать каждую пару "точка-точка". Для этого используется групповая многоадресная рассылка (multicast).

* **Динамическое обнаружение:** Хосты присоединяются к определенной multicast-группе. Когда хост отправляет трафик в VXLAN-сеть, он отправляется на multicast-адрес, и все участники группы получают его. Это позволяет динамически обнаруживать удаленные VTEP (VXLAN Tunnel Endpoints).
* **IGMP (Internet Group Management Protocol):** Используется для управления членством в multicast-группах.
* **Преимущества:** Упрощает управление в больших масштабах, так как не требует статической конфигурации для каждой пары VTEP.

**Пример настройки в Linux:**

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip link add vxlan0 type vxlan id 100 group 239.0.0.10 local 192.0.2.1 dev eth0
sudo ip link set vxlan0 up
sudo ip address add 10.8.0.1/24 dev vxlan0

# На стороне 2 (например, 192.0.2.2)
sudo ip link add vxlan0 type vxlan id 100 group 239.0.0.10 local 192.0.2.2 dev eth0
sudo ip link set vxlan0 up
sudo ip address add 10.8.0.2/24 dev vxlan0
```

* `group 239.0.0.10`: Указывает multicast-адрес, к которому присоединяется VXLAN-интерфейс. [Адреса `239.0.0.0/8` зарезервированы для частного использования](../Concepts/network_classification.md).

## Дополнительная информация

### Ограничения

* **Отсутствие шифрования:** VXLAN сам по себе не предоставляет механизмов шифрования. Для обеспечения безопасности трафика в публичных сетях его необходимо комбинировать с IPsec.
* **Multicast через Интернет:** Multicast-режим VXLAN обычно не работает через публичный Интернет, так как провайдеры редко поддерживают multicast-маршрутизацию. В таких случаях приходится использовать unicast-режим или другие решения.
* **Overhead:** Добавление заголовков VXLAN, UDP и IP увеличивает размер пакета, что может повлиять на MTU и производительность.
