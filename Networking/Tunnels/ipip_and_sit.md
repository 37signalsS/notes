# Туннели IPIP и SIT

## Определения

**IPIP (IP-in-IP)** — протокол туннелирования, инкапсулирующий пакеты IPv4 в пакеты IPv4 для передачи через промежуточную IPv4-сеть. Является одним из простейших методов создания L3-оверлея.

**SIT (Simple Internet Transition)** — также известный как **6in4**, протокол инкапсуляции пакетов IPv6 в пакеты IPv4 для транзита IPv6-трафика через инфраструктуру, поддерживающую только IPv4.

**Общие характеристики:**

| Параметр | IPIP | SIT (6in4) |
| :--- | :--- | :--- |
| **Протокол (номер IP)** | 4 | 41 |
| **Внутренний протокол** | IPv4 | IPv6 |
| **Внешний протокол** | IPv4 | IPv4 |
| **Топология** | Point-to-Point | Point-to-Point |
| **Шифрование** | Отсутствует | Отсутствует |
| **RFC** | [RFC 2003](https://datatracker.ietf.org/doc/html/rfc2003) | [RFC 4213](https://datatracker.ietf.org/doc/html/rfc4213) |

## Основные концепции

### Принцип инкапсуляции

Оба протокола добавляют внешний IPv4-заголовок (20 байт) к исходному пакету.

```
[Внешний IPv4 Header (20B)] [Исходный IP-пакет (IPv4 или IPv6)]
```

- **Overhead:** Фиксированный, 20 байт.
- **Протокол 4/41:** В отличие от GRE или VXLAN, здесь нет промежуточных заголовков (GRE, UDP). Внешний IP-заголовок сразу содержит полезную нагрузку другого сетевого уровня.

### Особенности IPIP

- **Копирование флагов:** По умолчанию Linux копирует бит DF (Don't Fragment) из внутреннего пакета во внешний. Это позволяет корректно работать механизму PMTUD.
- **Прозрачность:** Внутренний пакет не модифицируется (TTL уменьшается только при маршрутизации внутри туннеля).
- **Ограничение:** Поддерживает только инкапсуляцию IPv4.

### Особенности SIT

- **Механизм 6in4:** Основной способ подключения изолированных IPv6-сетей к IPv6-интернету через IPv4.
- **6to4 (Устарело):** Использование специального префикса `2002::/16` для автоматического построения туннелей. В 2026 году считается небезопасным и не рекомендуется ([RFC 7526](https://datatracker.ietf.org/doc/html/rfc7526)) из-за проблем с асимметричной маршрутизацией и низкой надежностью релеев.
- **MTU:** Минимальный MTU для IPv6 составляет 1280 байт. С учетом оверхеда SIT, физический линк должен поддерживать MTU не менее 1300 байт.

### Проблема NAT-T (NAT Traversal)

Туннели IPIP и SIT **крайне плохо работают через NAT**.
- У них отсутствуют заголовки L4 (порты TCP/UDP).
- Большинство домашних роутеров (SOHO) не умеют транслировать протоколы 4 и 41, если не включена функция "IPsec/PPTP Passthrough".
- Если оба конца туннеля находятся за NAT, соединение практически невозможно без инкапсуляции в UDP (например, через WireGuard или VXLAN).

## Практические сценарии в Linux

В современных системах рекомендуется использовать `ip link` вместо устаревшей команды `ip tunnel`.

### 1. Настройка IPIP-туннеля

```bash
# Сторона A (Внешний IP: 1.1.1.1)
ip link add name ipip0 type ipip local 1.1.1.1 remote 2.2.2.2
ip link set ipip0 up
ip addr add 10.0.0.1/30 dev ipip0

# Сторона B (Внешний IP: 2.2.2.2)
ip link add name ipip0 type ipip local 2.2.2.2 remote 1.1.1.1
ip link set ipip0 up
ip addr add 10.0.0.2/30 dev ipip0
```

### 2. Настройка SIT-туннеля (6in4)

```bash
# Сторона A (Внешний IP: 1.1.1.1)
ip link add name sit0 type sit local 1.1.1.1 remote 2.2.2.2
ip link set sit0 up
ip addr add 2001:db8:abc::1/64 dev sit0

# Сторона B (Внешний IP: 2.2.2.2)
ip link add name sit0 type sit local 2.2.2.2 remote 1.1.1.1
ip link set sit0 up
ip addr add 2001:db8:abc::2/64 dev sit0
```

### 3. Диагностика

```bash
# Просмотр параметров туннеля
ip -d link show ipip0

# Статистика пакетов (дропы, ошибки)
ip -s link show sit0

# Мониторинг прохождения трафика
tcpdump -ni any proto 4   # Для IPIP
tcpdump -ni any proto 41  # Для SIT
```

## Оптимизация MTU и MSS

Из-за 20-байтового оверхеда пакеты могут фрагментироваться или отбрасываться.

### Расчёт MTU
- Физический MTU (1500) - IPv4 Header (20) = **MTU 1480**.

### MSS Clamping (Критично для TCP)
Даже если MTU настроен правильно, некоторые узлы в интернете могут блокировать ICMP (PMTUD). Чтобы TCP-сессии (HTTP, SSH) не зависали, необходимо принудительно уменьшать MSS.

```bash
# Правило для iptables
iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -o ipip0 -j TCPMSS --set-mss 1440
```

## Сравнение с альтернативами

| Критерий | IPIP / SIT | GRE | WireGuard |
| :--- | :--- | :--- | :--- |
| **Overhead** | 20 B | 24+ B | ~60-80 B |
| **Шифрование** | Нет | Нет | Да (нативно) |
| **Сложность** | Минимальная | Средняя | Средняя |
| **Работа за NAT** | Очень плохо | Плохо | Отлично (UDP) |
| **Протоколы** | Один (IPv4 или IPv6) | Любые | Любые |
