# Туннели IPIP и SIT

Протоколы IPIP (IP-in-IP) и SIT (Simple Internet Transition, или IPv6-in-IP) являются простыми протоколами инкапсуляции, которые позволяют передавать IP-пакеты одного типа внутри IP-пакетов другого типа. Они относятся к классу "чистой инкапсуляции", то есть не предоставляют встроенных механизмов шифрования.

## IPIP (IP-in-IP)

IPIP — это протокол, который инкапсулирует IPv4-пакеты внутри других IPv4-пакетов. Это буквально "IPv4 внутри IPv4".

*   **Протокол:** Использует номер протокола `4` в заголовке внешнего IPv4-пакета.
*   **Назначение:** Передача IPv4-трафика через промежуточную IPv4-сеть.
*   **Особенности:**
    *   **Point-to-Point:** Всегда требует явного указания локального и удаленного адресов туннеля.
    *   **Копирование флагов:** По стандарту, IPIP копирует некоторые специфичные для IPv4 опции (например, бит "Don't Fragment" - DF) из внутреннего пакета во внешний. Это позволяет внешнему пакету использовать возможности IPv4-сети настолько полно, насколько это возможно.
    *   **Ограничения:** Не может передавать IPv6-трафик.

### Пример настройки IPIP-туннеля в Linux

Используется команда `ip tunnel` (или `ip link`):

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip tunnel add ipip1 mode ipip remote 192.0.2.2 local 192.0.2.1
sudo ip link set ipip1 up
sudo ip address add 10.0.0.1/30 dev ipip1

# На стороне 2 (например, 192.0.2.2)
sudo ip tunnel add ipip1 mode ipip remote 192.0.2.1 local 192.0.2.2
sudo ip link set ipip1 up
sudo ip address add 10.0.0.2/30 dev ipip1
```
*   `ipip1`: Произвольное имя интерфейса.
*   `mode ipip`: Указывает тип туннеля.
*   `remote`: IP-адрес удаленной точки туннеля.
*   `local`: IP-адрес локальной точки туннеля.

## SIT (Simple Internet Transition / IPv6-in-IP)

SIT — это протокол, который инкапсулирует IPv6-пакеты внутри IPv4-пакетов. Его основное назначение — передача IPv6-трафика через сети, которые изначально поддерживают только IPv4.

*   **Протокол:** Использует номер протокола `41` в заголовке внешнего IPv4-пакета.
*   **Назначение:** Транзит IPv6 через IPv4-инфраструктуру.
*   **Особенности:**
    *   **Point-to-Point:** Аналогично IPIP, требует указания локального и удаленного IPv4-адресов.
    *   **Ограничения:** Из-за несовпадения форматов внутреннего (IPv6) и внешнего (IPv4) протоколов, SIT не может обеспечить такую же глубокую интеграцию и копирование полей, как IPIP. Это делает его менее функциональным в плане использования возможностей внешнего протокола.

### Пример настройки SIT-туннеля в Linux

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip tunnel add sit1 mode sit remote 192.0.2.2 local 192.0.2.1
sudo ip link set sit1 up
sudo ip address add fc00::1/64 dev sit1

# На стороне 2 (например, 192.0.2.2)
sudo ip tunnel add sit1 mode sit remote 192.0.2.1 local 192.0.2.2
sudo ip link set sit1 up
sudo ip address add fc00::2/64 dev sit1
```
*   `sit1`: Произвольное имя интерфейса.
*   `mode sit`: Указывает тип туннеля.
*   `remote`: IPv4-адрес удаленной точки туннеля.
*   `local`: IPv4-адрес локальной точки туннеля.
*   `fc00::/64`: Пример [Unique Local Address (ULA)](../Concepts/private_and_special_use_ip_addresses.md) для IPv6.

## Общие недостатки IPIP и SIT

*   **Отсутствие шифрования:** Оба протокола не предоставляют механизмов шифрования, что делает их небезопасными для использования в публичных сетях без дополнительной защиты (например, IPsec).
*   **Ограниченная гибкость:** Каждый туннель предназначен для передачи только одного типа трафика (IPv4 для IPIP, IPv6 для SIT). Для передачи разных типов трафика или создания множества виртуальных сетей требуются более продвинутые протоколы, такие как [[GRE]] или [[VXLAN]].
