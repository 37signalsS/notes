# Туннели IPIP и SIT

### Определения

**IPIP (IP-in-IP)** — протокол туннелирования, который инкапсулирует (заворачивает) пакеты IPv4 в другие пакеты IPv4. Используется для передачи IPv4-трафика через промежуточную IPv4-сеть.

**SIT (Simple Internet Transition)** — протокол, также известный как **IPv6-in-IP**, который инкапсулирует пакеты IPv6 в пакеты IPv4. Его основная задача — обеспечить транзит IPv6-трафика через сети, поддерживающие только IPv4.

Оба протокола относятся к классу "чистой инкапсуляции", то есть не предоставляют встроенных механизмов шифрования.

### Основные концепции

- **Протоколы инкапсуляции:**
  - **IPIP** использует номер протокола `4` в заголовке внешнего IPv4-пакета.
  - **SIT** использует номер протокола `41` в заголовке внешнего IPv4-пакета.

- **Тип туннеля:** Оба протокола создают туннели типа **Point-to-Point**, что требует явного указания IP-адресов начальной и конечной точек туннеля.

- **Особенности и различия:**
  - **Копирование флагов в IPIP:** По стандарту, IPIP копирует некоторые опции из внутреннего IPv4-пакета во внешний (например, бит "Don't Fragment" - DF). Это позволяет более эффективно использовать возможности промежуточной сети.
  - **Ограничения SIT:** Из-за несовпадения форматов (IPv6 внутри IPv4), SIT не может выполнять такое же копирование полей, что делает его менее функциональным в этом аспекте по сравнению с IPIP.
  - **Ограничения по трафику:** IPIP не может передавать IPv6-трафик, а SIT предназначен только для IPv6.

### Практические сценарии

#### Настройка IPIP-туннеля в Linux

Для создания туннеля используется команда `ip tunnel` (или `ip link`).

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip tunnel add ipip1 mode ipip remote 192.0.2.2 local 192.0.2.1
sudo ip link set ipip1 up
sudo ip address add 10.0.0.1/30 dev ipip1

# На стороне 2 (например, 192.0.2.2)
sudo ip tunnel add ipip1 mode ipip remote 192.0.2.1 local 192.0.2.2
sudo ip link set ipip1 up
sudo ip address add 10.0.0.2/30 dev ipip1
```
- `ipip1`: Произвольное имя интерфейса.
- `mode ipip`: Указывает тип туннеля.
- `remote` / `local`: IP-адреса удаленной и локальной точек туннеля.

#### Настройка SIT-туннеля в Linux

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip tunnel add sit1 mode sit remote 192.0.2.2 local 192.0.2.1
sudo ip link set sit1 up
sudo ip address add fc00::1/64 dev sit1

# На стороне 2 (например, 192.0.2.2)
sudo ip tunnel add sit1 mode sit remote 192.0.2.1 local 192.0.2.2
sudo ip link set sit1 up
sudo ip address add fc00::2/64 dev sit1
```
- `sit1`: Произвольное имя интерфейса.
- `mode sit`: Указывает тип туннеля.
- `fc00::/64`: Пример [Unique Local Address (ULA)](../Concepts/private_and_special_use_ip_addresses.md) для IPv6.

### Дополнительная информация

**Общие недостатки:**

- **Отсутствие шифрования:** Оба протокола передают данные в открытом виде, что делает их небезопасными для использования в публичных сетях без дополнительной защиты (например, с помощью IPsec).
- **Ограниченная гибкость:** Каждый туннель может передавать только один тип трафика (IPv4 для IPIP, IPv6 для SIT). Для более сложных сценариев, требующих передачи разных протоколов или создания множества виртуальных сетей, лучше подходят [GRE](./gre.md) или [VXLAN](./vxlan.md).
