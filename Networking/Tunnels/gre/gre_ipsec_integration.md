# GRE с IPsec: защищённое туннелирование

## Определения

**GRE (Generic Routing Encapsulation) over IPsec (IP Security)** — комбинация протоколов, при которой GRE-туннель обеспечивает инкапсуляцию любых сетевых протоколов (L2/L3), а IPsec — шифрование и аутентификацию всего трафика. Это стандартное решение для организации защищённых каналов связи между площадками — **VPN (Virtual Private Network)** типа site-to-site.

**Ключевые характеристики:**

| Параметр | Значение |
|----------|----------|
| **Протокол GRE** | IP 47 |
| **Протокол IPsec** | **ESP (Encapsulating Security Payload)** — IP 50 |
| **Порт IKE (Internet Key Exchange)** | UDP 500 (фаза 1), UDP 4500 (**NAT-T — NAT Traversal**) |
| **Эффективный MTU (Maximum Transmission Unit)** | ~1400–1420 байт (GRE over IPsec) |
| **Рекомендуемый подход** | GRE over IPsec (не IPsec over GRE) |

---

## Базовые концепции

### Два подхода к комбинации протоколов

#### 1. GRE over IPsec (рекомендуется)

GRE-пакет инкапсулируется в IPsec ESP.

**Схема инкапсуляции:**
```
[IP-пакет] → [GRE] → [IPsec ESP] → [Внешний IP]
```

**Преимущества:**
- IPsec защищает весь GRE-трафик (протокол 47).
- Меньшие накладные расходы (overhead) по сравнению с IPsec over GRE.
- Стандартный подход для site-to-site VPN.
- IPsec в туннельном режиме шифрует весь внутренний пакет.

#### 2. IPsec over GRE

IPsec-пакет инкапсулируется в GRE-туннель.

**Схема инкапсуляции:**
```
[IP-пакет] → [IPsec ESP] → [GRE] → [Внешний IP]
```

**Недостатки:**
- Дополнительный GRE-заголовок увеличивает overhead.
- Уменьшает объём полезных данных в одном кадре.
- Менее эффективен с точки зрения производительности.
- Заголовок GRE не шифруется (он виден промежуточным узлам вместе с IPsec-заголовками).

**Применение:** специфические сценарии с устаревшим оборудованием. Не рекомендуется для новых внедрений.

### Сравнение подходов

| Параметр | GRE over IPsec | IPsec over GRE |
|----------|----------------|----------------|
| **Порядок инкапсуляции** | GRE → IPsec | IPsec → GRE |
| **Overhead** | ~24 (GRE) + ~56–73 (IPsec) | ~56–73 (IPsec) + ~24 (GRE) |
| **Эффективный MTU** | ~1400–1420 байт | ~1380–1400 байт |
| **Производительность** | Выше | Ниже |
| **Безопасность** | IPsec шифрует GRE полностью | Заголовок GRE виден |
| **Рекомендация** | **Да** (стандарт) | Нет (legacy) |

### Режимы IPsec для GRE

| Режим | Описание | Применение с GRE |
|-------|----------|------------------|
| **Туннельный** | Шифруется весь IP-пакет + добавляется новый внешний IP-заголовок | Site-to-site VPN (рекомендуется) |
| **Транспортный** | Шифруется только полезная нагрузка (Payload) исходного IP-пакета | GRE поверх IPsec |

**Туннельный режим с GRE:**
```
[Внешний IP][ESP][GRE][Внутренний IP][Данные][ESP Trailer][ESP Auth]
```

**Транспортный режим с GRE:**
```
[Внешний IP][ESP][GRE][IP][Данные][ESP Trailer][ESP Auth]
```

**Важно:** транспортный режим часто используется, когда GRE и IPsec терминируются на одних и тех же устройствах, чтобы минимизировать overhead. Однако туннельный режим является более универсальным и безопасным.

### MTU и фрагментация

| Компонент | Overhead (байт) |
|-----------|-----------------|
| GRE (базовый) | 24 |
| GRE (с полем Key) | 28 |
| IPsec ESP (туннельный режим) | 56–73 |
| **Итого GRE over IPsec** | **~80–100** |

**Эффективный MTU при базовом значении 1500:**
- GRE over IPsec (туннельный): ~1400–1420
- GRE over IPsec (транспортный): ~1420–1440

**Рекомендации:**
- Установить MTU на GRE-интерфейсе: `ip link set <gre_if> mtu 1400`.
- Включить Path MTU Discovery: `sysctl -w net.ipv4.ip_no_pmtu_disc=0`.
- Для TCP-трафика использовать MSS Clamping или `tcp_mtu_probing=1`.

### NAT-Traversal (NAT-T) — прохождение NAT

**Проблема:** протокол ESP (IP 50) не содержит портов, поэтому классический NAT (PAT) не может транслировать его для нескольких устройств за одним IP.

**Решение:** NAT-T инкапсулирует ESP-пакеты в UDP-порт 4500.

**Применение:** если между конечными точками туннеля есть устройство с NAT, использование NAT-T становится обязательным для работы IPsec.

## Практические сценарии

### Настройка GRE over IPsec с использованием strongSwan

1. **Создание GRE-туннеля:**
```bash
ip link add gre_sec type gre remote 203.0.113.2 local 198.51.100.1
ip link set gre_sec up
ip address add 10.0.0.1/30 dev gre_sec
```

2. **Настройка параметров IPsec (`/etc/ipsec.conf`):**
```bash
# Пример конфигурации strongSwan
conn gre-tunnel
  left=198.51.100.1
  right=203.0.113.2
  leftprotoport=47
  rightprotoport=47
  esp=aes256-sha256
  ikev2=always
  auto=start
```

### Настройка GRE over IPsec с использованием LibreSwan

Пример конфигурации в `/etc/ipsec.conf`:
```bash
conn gre-protected
    left=198.51.100.1
    leftsubnet=10.0.0.0/30
    right=203.0.113.2
    rightsubnet=10.0.0.0/30
    leftprotoport=47
    rightprotoport=47
    ike=aes256-sha256-modp2048
    esp=aes256-sha256
    keyingtries=%forever
    auto=start
```

## Дополнительная информация

### Диагностика и устранение неполадок

**Проверка GRE-туннеля:**
```bash
ip -d link show gre_sec           # Проверка параметров и статуса интерфейса
ping -I gre_sec 10.0.0.2          # Проверка связности внутри туннеля
tcpdump -i eth0 proto 50 -n       # Проверка наличия зашифрованного ESP-трафика
```

**Проверка состояний IPsec (Security Associations — SA):**
```bash
ip xfrm state                     # Просмотр активных SA в ядре Linux
ip xfrm policy                    # Просмотр политик безопасности (SP)
strongswan status                 # Краткий статус strongSwan
```

**Типовые проблемы и решения:**

| Проблема | Причина | Решение |
|----------|---------|---------|
| SA не устанавливается | Блокировка портов UDP 500/4500 | Разрешить порты в Firewall |
| Пакеты ESP отбрасываются | Блокировка протокола IP 50 | Разрешить протокол ESP в Firewall |
| Фрагментация пакетов | Слишком большой MTU | Уменьшить MTU на GRE-интерфейсе до 1400 |
| Трафик не шифруется | Ошибка в политиках (leftprotoport) | Убедиться, что указан протокол 47 (GRE) |

### Преимущества и недостатки

**Преимущества:**
- **Универсальность:** GRE позволяет передавать любой трафик (L2, L3, Multicast).
- **Безопасность:** IPsec обеспечивает надежное шифрование и проверку целостности.
- **Поддержка динамической маршрутизации:** работа протоколов OSPF/BGP через туннель.

**Недостатки:**
- **Сложность:** необходимость настройки и поддержки двух разных протоколов.
- **Overhead:** значительное уменьшение полезной нагрузки в пакете (до 100 байт).
- **Нагрузка на CPU:** шифрование требует вычислительных ресурсов.
