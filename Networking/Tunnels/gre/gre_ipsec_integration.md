# GRE с IPsec: защищённое туннелирование

## Определения

**GRE over IPsec** — комбинация протоколов, при которой GRE-туннель обеспечивает инкапсуляцию любых сетевых протоколов (L2/L3), а IPsec — шифрование и аутентификацию всего трафика. Стандартное решение для site-to-site VPN.

**Ключевые характеристики:**

| Параметр | Значение |
|----------|----------|
| **GRE протокол** | IP 47 |
| **IPsec протокол** | ESP (IP 50) |
| **IKE порт** | UDP 500 (фаза 1), UDP 4500 (NAT-T) |
| **Эффективный MTU** | ~1400–1420 байт (GRE over IPsec) |
| **Рекомендуемый подход** | GRE over IPsec (не IPsec over GRE) |

---

## Базовые концепции

### Два подхода к комбинации

#### 1. GRE over IPsec (рекомендуется)

GRE-пакет инкапсулируется в IPsec ESP.

**Схема инкапсуляции:**

```
[IP-пакет] → [GRE] → [IPsec ESP] → [Внешний IP]
```

**Преимущества:**

- IPsec защищает весь GRE-трафик (протокол 47)
- Меньший overhead по сравнению с IPsec over GRE
- Стандартный подход для site-to-site VPN
- IPsec в туннельном режиме шифрует весь внутренний пакет

#### 2. IPsec over GRE

IPsec-пакет инкапсулируется в GRE-туннель.

**Схема инкапсуляции:**

```
[IP-пакет] → [IPsec ESP] → [GRE] → [Внешний IP]
```

**Недостатки:**

- Дополнительный GRE-заголовок увеличивает overhead
- Уменьшает объём полезных данных в одном кадре
- Менее эффективен для производительности
- GRE не шифрует IPsec-заголовки (они видны промежуточным узлам)

**Применение:** Специфические сценарии с legacy-оборудованием. Не рекомендуется для новых развёртываний.

### Сравнение подходов

| Параметр | GRE over IPsec | IPsec over GRE |
|----------|----------------|----------------|
| **Порядок инкапсуляции** | GRE → IPsec | IPsec → GRE |
| **Overhead** | ~24 (GRE) + ~56–73 (IPsec) | ~56–73 (IPsec) + ~24 (GRE) |
| **Эффективный MTU** | ~1400–1420 байт | ~1380–1400 байт |
| **Производительность** | Выше | Ниже |
| **Безопасность** | IPsec шифрует GRE полностью | GRE заголовок виден |
| **Рекомендация** | **Да** (стандарт) | Нет (legacy) |

### Режимы IPsec для GRE

| Режим | Описание | Применение с GRE |
|-------|----------|------------------|
| **Туннельный** | Шифруется весь IP-пакет + внешний IP-заголовок | Site-to-site VPN (рекомендуется) |
| **Транспортный** | Шифруется только полезная нагрузка | GRE/L2TP/PPP поверх IPsec |

**Туннельный режим с GRE:**

```
[Внешний IP][ESP][GRE][Внутренний IP][Данные][ESP Trailer][ESP Auth]
```

**Транспортный режим с GRE:**

```
[Внешний IP][ESP][GRE][IP][ICMP/TCP/UDP][ESP Trailer][ESP Auth]
```

**Важно:** Транспортный режим добавляет GRE-заголовок поверх IPsec, что увеличивает overhead. В большинстве случаев рекомендуется туннельный режим.

### MTU и фрагментация

| Компонент | Overhead |
|-----------|----------|
| GRE (базовый) | 24 байта |
| GRE (с Key) | 28 байт |
| IPsec ESP (туннельный) | 56–73 байта |
| **Итого GRE over IPsec** | **~80–100 байт** |

**Эффективный MTU при базовом MTU 1500:**

| Конфигурация | Эффективный MTU |
|--------------|-----------------|
| GRE over IPsec (туннельный) | ~1400–1420 |
| GRE over IPsec (транспортный) | ~1420–1440 |

**Рекомендации:**

- Установить MTU GRE-интерфейса: `ip link set <gre_if> mtu 1400`
- Включить Path MTU Discovery: `sysctl -w net.ipv4.ip_no_pmtu_disc=0`
- Для TCP: `tcp_mtu_probing=1`
- При PPPoE (MTU 1380): установить MTU GRE ≤ 1280

### NAT-Traversal (NAT-T)

**Проблема:** ESP (протокол 50) не содержит TCP/UDP-заголовков, что делает невозможным PAT-трансляцию.

**Решение:** NAT-T инкапсулирует ESP в UDP 4500.

**Применение с GRE:** При наличии NAT между конечными точками GRE over IPsec требует NAT-T для корректной работы.

## Практические сценарии

### GRE over IPsec с strongSwan

```bash
# 1. Создание GRE-туннеля
ip link add gre_sec type gre remote 203.0.113.2 local 198.51.100.1
ip link set gre_sec up
ip address add 10.0.0.1/30 dev gre_sec

# 2. Настройка IPsec (/etc/ipsec.conf)
# conn gre-tunnel
#   left=198.51.100.1
#   right=203.0.113.2
#   leftprotoport=47
#   rightprotoport=47
#   esp=aes256-sha256
#   ikev2=always
#   auto=start
```

### GRE over IPsec с LibreSwan

```bash
# /etc/ipsec.conf
conn gre-protected
    left=198.51.100.1
    leftsubnet=10.0.0.0/30
    right=203.0.113.2
    rightsubnet=10.0.0.0/30
    leftprotoport=47
    rightprotoport=47
    ike=aes256-sha256-modp2048
    esp=aes256-sha256
    keyingtries=%forever
    auto=start
```

## Дополнительная информация

### Диагностика и Troubleshooting

**Проверка GRE-туннеля:**

```bash
ip -d link show gre_sec           # Статус GRE
ping -I gre_sec 10.0.0.2          # Проверка связности
tcpdump -i eth0 proto 50 -n       # Проверка ESP-трафика
```

**Проверка IPsec SA:**

```bash
ip xfrm state                       # Активные SA
ip xfrm policy                      # Политики безопасности
strongswan status                   # Статус strongSwan
ipsec status                        # Статус IPsec
```

**Типичные проблемы:**

| Проблема | Причина | Решение |
|----------|---------|---------|
| SA не устанавливается | Блокировка UDP 500/4500 | Открыть порты на фаерволе |
| ESP-пакеты дропаются | Блокировка протокола 50 | Разрешить IP protocol 50 |
| Фрагментация | MTU слишком большой | Уменьшить MTU GRE до 1400 |
| NAT-T не работает | Блокировка UDP 4500 | Открыть UDP 4500 |
| Трафик не идёт | Несоответствие SP/политик | Проверить leftprotoport=47 |

### Преимущества и недостатки

**Преимущества GRE over IPsec:**

- **Универсальность:** GRE инкапсуляет любые протоколы (L2/L3)
- **Безопасность:** IPsec обеспечивает шифрование и аутентификацию
- **Мультипротокольность:** Поддержка multicast, IPv6, NetBIOS через GRE
- **Стандартизация:** Поддержка всеми вендорами

**Недостатки:**

- **Сложность настройки:** Два протокола требуют согласованной конфигурации
- **Overhead:** ~80–100 байт на пакет
- **Производительность:** Шифрование/дешифрование нагружает CPU
- **NAT:** Требуется NAT-T при наличии NAT между точками
