# GRE: практические сценарии настройки

## Определения

**Point-to-Point GRE (Generic Routing Encapsulation)** — туннель между двумя статическими конечными точками с явным указанием внешних IP-адресов (`remote` и `local`). Является базовым режимом работы GRE.

**Multipoint GRE (mGRE)** — туннель без жесткой привязки к удаленному адресу (`remote`), позволяющий устанавливать соединения с множеством точек через один интерфейс. Служит основой для построения **DMVPN (Dynamic Multipoint VPN)** с использованием протокола **NHRP (Next Hop Resolution Protocol)**.

**GRETAP (GRE Tunneling and Bridging)** — режим GRE для инкапсуляции Ethernet-кадров, обеспечивающий **L2 (Layer 2 — канальный уровень)** туннелирование. Позволяет объединять удаленные сегменты локальной сети через **L3 (Layer 3 — сетевой уровень)** инфраструктуру.

**Сравнение практических режимов:**

| Параметр | Point-to-Point | mGRE | GRETAP |
|----------|---------------|------|--------|
| **Уровень OSI** | L3 | L3 | L2 |
| **Remote IP** | Обязательно | Не указывается | Обязательно |
| **Топология** | Точка-точка | Hub-and-Spoke / Mesh | Точка-точка |
| **Overhead** | ~24 байта | ~24 байта | ~42 байта |
| **Применение** | Простые VPN-каналы | DMVPN, облака | L2-оверлей, миграция VM |

## Базовые концепции

### Общие принципы настройки GRE в Linux

Для управления туннелями используется пакет инструментов `iproute2`.

**Синтаксис команды ip:**

```bash
ip link add <name> type gre \
    remote <remote_ip> local <local_ip> \
    key <tunnel_id> ttl <ttl_value>
ip link set <name> up
ip address add <tunnel_ip>/<prefix> dev <name>
```

**Основные параметры:**

| Параметр | Описание | Обязательный |
|----------|----------|--------------|
| `remote` | Внешний IP-адрес удалённой точки | Нет (для mGRE) |
| `local` | Внешний IP-адрес локальной точки | Да |
| `key` | 32-битный идентификатор туннеля | Нет (рекомендуется) |
| `ttl` | **TTL (Time-to-Live)** внешнего IP-пакета | Нет (64 по умолчанию) |
| `tos` | **TOS (Type of Service)** | Нет |
| `dev` | Физический интерфейс привязки | Нет |

**Важно:** Параметр `key` должен совпадать на обеих сторонах. Его использование критично при наличии нескольких туннелей между одними и теми же IP-адресами для корректной демультиплексации трафика.

### Маршрутизация через GRE

После поднятия интерфейса необходимо направить в него целевой трафик:

```bash
# Статический маршрут через интерфейс туннеля
ip route add 10.10.0.0/16 dev gre0

# Маршрут через IP-адрес шлюза внутри туннеля
ip route add 10.10.0.0/16 via 10.0.1.2
```

### Проверка конфигурации

```bash
ip -d link show <gre_if>        # Детальные параметры (remote, local, key)
ip address show <gre_if>        # Проверка IP-адресации внутри туннеля
ip route show dev <gre_if>      # Просмотр маршрутов через интерфейс
ping -I <gre_if> <remote_ip>    # Проверка доступности удаленной стороны
tcpdump -i <gre_if> -n          # Анализ трафика внутри туннеля
tcpdump -i eth0 proto 47 -n    # Анализ GRE-пакетов в физическом канале
```

## Практические сценарии

### 1. Point-to-Point GRE

Типовой сценарий объединения двух офисов через общедоступную сеть.

**Конфигурация:**

```bash
# Сторона 1 (Внешний IP: 192.0.2.1)
ip link add gre0 type gre remote 192.0.2.2 local 192.0.2.1 key 100 ttl 255
ip link set gre0 up
ip address add 10.0.1.1/30 dev gre0
ip route add 10.10.0.0/16 via 10.0.1.2

# Сторона 2 (Внешний IP: 192.0.2.2)
ip link add gre0 type gre remote 192.0.2.1 local 192.0.2.2 key 100 ttl 255
ip link set gre0 up
ip address add 10.0.1.2/30 dev gre0
ip route add 10.20.0.0/16 via 10.0.1.1
```

**MTU (Maximum Transmission Unit):** По умолчанию устанавливается 1476 байт (1500 - 24 байта заголовков GRE/IP).

### 2. Multipoint GRE (mGRE)

Используется для построения динамических сетей с архитектурой Hub-and-Spoke.

**Сценарий:** Центральный узел (Hub) принимает соединения от множества филиалов (Spoke) без статического описания каждого из них.

```bash
# Hub (Внешний IP: 192.0.2.1)
ip link add gre_mp type gre local 192.0.2.1 key 345 ttl 255
ip link set gre_mp up
ip address add 10.0.3.1/24 dev gre_mp

# Spoke 1 (Внешний IP: 192.0.2.2)
ip link add gre_mp type gre local 192.0.2.2 key 345 ttl 255
ip link set gre_mp up
ip address add 10.0.3.2/24 dev gre_mp
# Статическая запись соседа (без использования NHRP)
ip neighbour add 10.0.3.1 dev gre_mp lladdr 192.0.2.1
```

**Особенности:**
- Для полноценной работы DMVPN в Linux требуется установка демона NHRP (например, OpenNHRP).
- Позволяет экономить IP-адреса и упрощает конфигурацию центрального узла.

### 3. GRETAP (L2-туннелирование)

Позволяет объединить удаленные виртуальные машины или сегменты сети в один **L2 (Layer 2)** домен.

**Сценарий:** Растягивание **VLAN (Virtual Local Area Network)** между двумя площадками.

```bash
# Сторона 1 (Внешний IP: 192.0.2.1)
ip link add gretap0 type gretap remote 192.0.2.2 local 192.0.2.1 ttl 255
ip link set gretap0 up
ip link set gretap0 master br0  # Добавление в сетевой мост

# Сторона 2 (Внешний IP: 192.0.2.2)
ip link add gretap0 type gretap remote 192.0.2.1 local 192.0.2.2 ttl 255
ip link set gretap0 up
ip link set gretap0 master br0
```

**Накладные расходы:** Около 42 байт (Ethernet + GRE + IP).
**MTU:** Рекомендуется устанавливать 1458 байт.
**Важно:** GRETAP передает широковещательный трафик. Для предотвращения петель необходимо использовать протокол **STP (Spanning Tree Protocol)** на сетевых мостах.

### 4. GRE с IPsec

Для обеспечения безопасности трафика GRE-туннель защищается через IPsec. В такой связке GRE отвечает за инкапсуляцию и маршрутизацию (включая мультикаст), а IPsec — за шифрование.

**Пример (strongSwan):**

```bash
# Создание GRE-туннеля
ip link add gre_sec type gre remote 203.0.113.2 local 198.51.100.1 key 500
ip link set gre_sec up
ip address add 10.0.0.1/30 dev gre_sec

# IPsec настраивается отдельно (см. связанный документ)
```

Подробно: [GRE с IPsec](./gre_ipsec_integration.md)

## Дополнительная информация

### Диагностика и устранение неполадок

**Методы проверки:**

```bash
# Проверка ARP-таблицы и соседей в туннеле
ip neighbour show dev <gre_if>

# Проверка корректности MTU и отсутствия фрагментации
ping -M do -s 1472 <remote_tunnel_ip>

# Анализ инкапсуляции внешних пакетов
tcpdump -i eth0 proto 47 -n -vv
```

**Типичные проблемы:**

| Проблема | Причина | Решение |
|----------|---------|---------|
| Интерфейс UP, но пинга нет | Отсутствует маршрут до `remote` IP | Проверить физическую связность |
| Пакеты теряются при нагрузке | Завышенный MTU | Уменьшить MTU до 1476 (или 1458 для GRETAP) |
| Асимметрия трафика | Ошибки маршрутизации | Проверить таблицу маршрутов на обеих сторонах |
| Проблемы с TCP-сессиями | Фрагментация | Использовать **MSS (Maximum Segment Size)** Clamping |

### Сравнение с альтернативами

| Задача | GRE | Альтернатива | Когда выбрать альтернативу |
|--------|-----|-------------|---------------------------|
| Простой L3-туннель | GRE | IPIP | IPIP имеет меньше накладных расходов |
| L2-оверлей | GRETAP | VXLAN | VXLAN предпочтительнее для масштабируемых облаков |
| Защищенный VPN | GRE + IPsec | WireGuard | WireGuard проще в настройке и производительнее |
| DMVPN-сети | mGRE + NHRP | WireGuard Mesh | Если не требуется строгая совместимость с Cisco |
