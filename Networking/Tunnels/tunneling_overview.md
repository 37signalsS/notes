# Обзор сетевых туннелей и инкапсуляции

## Определения

**Сетевой туннель** — логическое соединение («канал»), созданное путем инкапсуляции пакетов одного протокола в пакеты другого для их передачи через промежуточную сетевую инфраструктуру.

**Инкапсуляция** — процесс упаковки «пассажирского» пакета (внутреннего) в поле полезной нагрузки «несущего» пакета (внешнего).

**Оверлейная сеть (Overlay)** — виртуальная логическая сеть, построенная поверх физической инфраструктуры (Underlay) с использованием туннелей.

**VTEP (VXLAN Tunnel End Point)** — логическая сущность, выполняющая функции инкапсуляции и декапсуляции трафика на границе оверлея.

## Основные концепции

### Механизм работы (Data Plane)

Процесс передачи данных через туннель включает следующие этапы:

1.  **Поступление:** Пакет (L2 Ethernet или L3 IP) попадает на туннельный интерфейс.
2.  **Инкапсуляция:** Стек ядра (или Userspace-приложение) добавляет туннельный заголовок (GRE, VXLAN) и внешний заголовок (IP/UDP).
3.  **Транспортировка:** Пакет передается через физическую сеть как обычный IP-трафик.
4.  **Декапсуляция:** Удаленная точка туннеля снимает внешние заголовки и восстанавливает исходный пакет.

### Уровни инкапсуляции (OSI)

-   **L2-туннели (Bridging):** Передают Ethernet-кадры. Позволяют объединить удаленные узлы в один широковещательный домен.
    -   *Примеры:* VXLAN, GRETAP, L2TPv3, `tap`-интерфейсы.
-   **L3-туннели (Routing):** Передают IP-пакеты. Используются для маршрутизации между удаленными подсетями.
    -   *Примеры:* GRE, IPIP, SIT, WireGuard, `tun`-интерфейсы.
-   **L2.5 (Labels):** [MPLS](./mpls.md) — занимает промежуточное положение, используя метки для коммутации.

### Плоскость управления (Control Plane)

Control Plane определяет, как узлы узнают о маршрутах и расположении удаленных точек (VTEP).

1.  **Статическая:** Ручное указание IP-адресов удаленных точек (IPIP, базовый GRE).
2.  **Динамическая (Multicast):** Использование мультикаст-рассылок для автоматического обнаружения соседей (VXLAN Flood-n-Learn).
3.  **SDN / BGP EVPN:** Использование внешнего контроллера или протоколов маршрутизации ([BGP EVPN](../Protocols/bgp.md)) для распространения информации о доступности MAC/IP.

## Технические нюансы и ограничения

### Проблема MTU и фрагментации

Инкапсуляция добавляет дополнительные заголовки, что уменьшает полезный объем данных (Payload) в пакете.

-   **Оверхед (Overhead):**
    -   IPIP/SIT: 20 байт
    -   GRE: 24+ байта
    -   VXLAN: 50 байт
    -   WireGuard: ~60-80 байт
-   **Последствия:** Если пакет превышает MTU физического интерфейса (обычно 1500), он либо фрагментируется (снижение производительности), либо отбрасывается (блокировка трафика).
-   **Решение:** Настройка MSS Clamping (уменьшение размера TCP-сегмента) или использование Jumbo Frames в Underlay-сети. Подробнее в **[MTU и диагностика](../OSI_TCP_IP_Model/Network_layer/mtu_and_vpn.md)**.

### Прохождение через NAT (NAT Traversal)

1.  **Протоколы без L4 (Proto 4, 41, 47):** IPIP, SIT и GRE часто блокируются домашними роутерами, так как у них нет портов (TCP/UDP).
2.  **UDP-инкапсуляция:** VXLAN, WireGuard и Geneve используют UDP в качестве транспорта. Это делает их «дружелюбными» к NAT и позволяет использовать механизмы балансировки (ECMP) на основе хеша портов.

## Сравнение популярных технологий

| Технология | Уровень | Шифрование | Транспорт | Сценарий |
| :--- | :--- | :--- | :--- | :--- |
| **IPIP / SIT** | L3 | Нет | IP (4/41) | Простейший транзит IPv4/IPv6. |
| **GRE** | L2/L3 | Нет | IP (47) | Универсальные туннели, DMVPN. |
| **VXLAN** | L2 | Нет | UDP (4789) | Стандарт для облаков и K8s. |
| **Geneve** | L2 | Нет | UDP (6081) | Гибкий оверлей (TLV), OVN. |
| **WireGuard** | L3 | Да | UDP (случ.) | Современные высокоскоростные VPN. |
| **IPsec** | L3 | Да | ESP (50) | Защищенные Site-to-Site каналы. |
| **MPLS** | L2.5 | Нет | Shim-метки | Магистрали сервис-провайдеров. |

## Управление в Linux

В современных системах настройка выполняется через `ip link` (объект `ip tunnel` считается частично устаревшим).

```bash
# Создание туннеля (пример GRE)
ip link add dev gre0 type gre local <local_ip> remote <remote_ip>
ip link set gre0 up

# Диагностика
ip -d link show <dev> # Детальные параметры
ip -s link show <dev> # Статистика (ошибки, дропы)
```

Подробности реализации интерфейсов — в статье **[`tun` vs `tap`](./tun_vs_tap.md)**.

## Выбор технологии (Дерево решений)

```
Требуется L2-связность (объединение в один коммутатор)?
├─ Да → Нужно масштабирование (облако)?
│  ├─ Да → VXLAN / Geneve
│  └─ Нет → GRETAP
└─ Нет (Routing L3) → Нужно шифрование?
   ├─ Да → WireGuard (производительность) или IPsec (стандарт)
   └─ Нет → GRE (универсально) или IPIP (минимальный оверхед)
```
