# Сетевые туннели

## Определения

**Сетевой туннель** — технология инкапсуляции пакетов одного сетевого протокола в пакеты другого протокола для создания виртуального канала «точка-в-точку» через промежуточную сеть.

**Инкапсуляция** — процесс добавления внешнего заголовка к исходному пакету для транспортировки через сеть, не поддерживающую внутренний протокол.

**Оверлейная сеть (Overlay Network)** — виртуальная сеть, построенная поверх физической инфраструктуры с использованием туннелей.

**VTEP (VXLAN Tunnel End Point)** — конечная точка туннеля, выполняющая инкапсуляцию и декапсуляцию трафика.

## Базовые концепции

### Принцип работы

Туннелирование инкапсулирует «пассажирский» пакет (внутренний протокол) в поле полезной нагрузки «несущего» пакета (внешний протокол).

**Процесс инкапсуляции:**

1. Исходный пакет (IPv4/IPv6/Ethernet) поступает на туннельный интерфейс
2. Добавляется заголовок туннельного протокола (GRE/VXLAN/IPIP)
3. Добавляется внешний IP-заголовок с адресами конечных точек туннеля
4. Инкапсулированный пакет передаётся через физическую сеть
5. На удалённой точке туннеля происходит декапсуляция

**Уровни OSI:**

- **L2-туннели** — инкапсулируют Ethernet-кадры (GRETAP, VXLAN, `tap`)
- **L3-туннели** — инкапсулируют IP-пакеты (GRE, IPIP, SIT, `tun`)

### Виртуальные интерфейсы в Linux

В Linux туннели реализуются через виртуальные интерфейсы:

- **`tun`** — L3-интерфейс для IP-пакетов (точка-точка)
- **`tap`** — L2-интерфейс для Ethernet-кадров (виртуальный NIC)

Подробнее: [`tun` vs `tap`](./tun_vs_tap.md)

### Управление туннелями в Linux

Основной инструмент — `iproute2`:

- [`ip tunnel`](../../Linux/Networking/Tools/iproute2/ip_tunnel.md) — устаревший синтаксис
- `ip link add type <type>` — современный синтаксис

```bash
# Современный синтаксис (рекомендуется)
ip link add <name> type <proto> remote <dst> local <src>

# Устаревший синтаксис
ip tunnel add <name> mode <proto> remote <dst> local <src>
```

## Практические сценарии

### 1. Связь сегментов частной сети через публичную сеть (VPN)

Два или более офиса с [частными IP-адресами](../Protocols/ip.md) взаимодействуют через Интернет.

**Технологии:**

- **С шифрованием:** [WireGuard](../../Vpn/wireguard.md), [IPSec](./ipsec/ipsec.md), OpenVPN
- **Без шифрования (доверенные сети):** [GRE](./gre/gre.md), [IPIP](./ipip_and_sit.md)

### 2. Передача неподдерживаемого протокола

Инкапсуляция протокола, не поддерживаемого промежуточной сетью.

**Примеры:**

- IPv6 через IPv4-сети ([SIT](./ipip_and_sit.md), 6to4)
- Multicast через сети без поддержки multicast

### 3. Оверлейные сети в дата-центрах

Виртуальные L2-сегменты поверх физической L3-инфраструктуры.

**Технологии:** [VXLAN](./vxlan.md), GRE, Geneve

**Применение:**

- Виртуальные машины в одном L2-сегменте на разных физических серверах
- Мультитенантные облачные платформы (IaaS)
- Kubernetes CNI (Calico, Flannel, Cilium)

### 4. Объединение двух приватных сетей

| Метод | Описание | Когда использовать |
|-------|----------|-------------------|
| **VPN-туннель** | L3-туннель с шифрованием (WireGuard, IPsec) | Через публичную сеть, требуется безопасность |
| **GRE-туннель** | L2/L3-туннель без шифрования | Доверенная сеть, нужна простота |
| **VXLAN** | L2-оверлей поверх L3 | Дата-центр, много виртуальных сетей |
| **Маршрутизация** | Статические маршруты + IP-форвардинг | Прямая связность между роутерами |

**Важно:** Настройка [`iptables`](../../Linux/Networking/Settings/tools/firewall_common.md) и маршрутов обязательна на всех узлах.

## Дополнительная информация

### Классификация туннельных протоколов

#### По уровню инкапсуляции

| Уровень | Протоколы | Единица данных | Примеры использования |
|---------|-----------|----------------|----------------------|
| **L2** | VXLAN, GRETAP, `tap` | Ethernet-кадр | Виртуализация, объединение VLAN |
| **L3** | GRE, IPIP, SIT, `tun` | IP-пакет | VPN, транзит протоколов |

#### По наличию шифрования

| Тип | Протоколы | Описание |
|-----|-----------|----------|
| **С шифрованием** | WireGuard, OpenVPN, [IPSec](./ipsec/ipsec.md) | Защита «из коробки» |
| **Без шифрования** | GRE, IPIP, SIT, VXLAN | Только инкапсуляция, шифрование опционально ([IPSec](./ipsec/ipsec.md)) |

#### По топологии

| Топология | Протоколы | Описание |
|-----------|-----------|----------|
| **Point-to-Point** | IPIP, SIT, GRE (базовый) | Две статические конечные точки |
| **Point-to-Multipoint** | GRE mGRE, VXLAN multicast | Одна точка → множество точек |
| **Mesh** | VXLAN, WireGuard (ручная настройка) | Полносвязная топология |

### Сравнение протоколов туннелирования

| Протокол | Уровень | Шифрование | MTU overhead | Масштабируемость | Сценарий |
|----------|---------|------------|--------------|------------------|----------|
| **IPIP** | L3 | Нет | ~20 байт | Низкая | IPv4 через IPv4 |
| **SIT** | L3 | Нет | ~20 байт | Низкая | IPv6 через IPv4 |
| **GRE** | L2/L3 | Нет | ~24 байта | Средняя | Универсальный туннель |
| **GRETAP** | L2 | Нет | ~42 байта | Средняя | L2-оверлей |
| **VXLAN** | L2 | Нет | ~50 байт | Высокая (16M VNI) | Дата-центры |
| **WireGuard** | L3 | Да (встроенное) | ~60 байт | Высокая | Современный VPN |
| **OpenVPN** | L2/L3 | Да (встроенное) | ~60-80 байт | Средняя | Корпоративный VPN |
| **[IPSec](./ipsec/ipsec.md)** | L3 | Да (ESP) | ~56-73 байта | Высокая | Site-to-site VPN, интеграция с партнёрами |
| **L2TP** | L2 | Нет (требует IPsec) | ~40 байт | Средняя | VPN с аутентификацией |
| **PPTP** | L2 | Слабое (устарел) | ~40 байт | Низкая | Устаревший VPN |

#### Детали протоколов

**IPIP (IP-in-IP, RFC 2003):**
- Самый простой тип туннеля
- Инкапсулирует только IPv4
- Нет аутентификации и шифрования
- Не работает через NAT
- Заголовок: 20 байт (дополнительный IP)

**GRE (Generic Routing Encapsulation, RFC 2784):**
- Универсальный протокол от Cisco
- Пробрасывает IPv4/IPv6, multicast и немаршрутизируемые протоколы (NetBIOS, IPX, AppleTalk)
- Заголовок: 4 байта (минимальный) + опционально Key/Sequence
- Без состояния (stateless)
- Нет шифрования, не работает через NAT без дополнительных настроек

**OpenVPN:**
- Работает через TCP/UDP (порт 1194)
- Проходит через NAT
- Режимы: **TUN** (L3) и **TAP** (L2/Ethernet)
- Поддерживает шифрование и сжатие данных
- Требует демон/сервис

**IPsec (IP Security):**
- Набор протоколов для защиты IP-трафика
- **ESP:** Шифрование и аутентификация данных
- **AH:** Проверка целостности и аутентификация источника (без шифрования)
- **IKE:** Согласование алгоритмов и обмен ключами
- Режимы: **Транспортный** (шифруются только данные) и **Туннельный** (шифруется весь пакет)
- Не создаёт явных туннельных интерфейсов (использует Security Associations)

**L2TP (Layer 2 Tunneling Protocol):**
- Использует UDP (порт 1701)
- Работает через NAT
- Часто применяется в связке **L2TP/IPsec** для высокого уровня безопасности
- Сам по себе не шифрует трафик

**PPTP (Point-to-Point Tunneling Protocol):**
- Устаревший протокол
- Использует TCP 1723 для управления и GRE для передачи данных
- Небезопасен (известные уязвимости)
- Не рекомендуется к использованию

### Выбор протокола

```
Требуется L2-оверлей?
├─ Да → VXLAN (масштабируемо) или GRETAP (просто)
└─ Нет → Требуется шифрование?
         ├─ Да → WireGuard (производительность), [IPSec](./ipsec/ipsec.md) (site-to-site) или OpenVPN (зрелость)
         └─ Нет → GRE (универсально) или IPIP/SIT (транзит протокола)
```
