# GRE (Generic Routing Encapsulation)

GRE (Generic Routing Encapsulation) — это протокол туннелирования, разработанный Cisco, который позволяет инкапсулировать широкий спектр сетевых протоколов (IPv4, IPv6, Ethernet и др.) внутри IP-пакетов. В отличие от [[IPIP и SIT]], GRE является более универсальным и гибким, так как не привязан к конкретному внутреннему протоколу.

## Принцип работы

GRE инкапсулирует "пассажирский" пакет (например, IPv4 или IPv6) в GRE-заголовок, который, в свою очередь, помещается в IP-заголовок "несущего" протокола (обычно IPv4).

*   **Протокол:** Использует номер протокола `47` в заголовке внешнего IP-пакета.
*   **Гибкость:** Позволяет передавать несколько протоколов одновременно внутри одного туннеля.
*   **Отсутствие шифрования:** GRE сам по себе не предоставляет механизмов шифрования. Для обеспечения безопасности трафика в публичных сетях его часто комбинируют с **IPsec**.

## Режимы работы GRE

### 1. Point-to-Point GRE

Это базовый режим, аналогичный IPIP, где туннель устанавливается между двумя явно указанными конечными точками.

**Пример настройки в Linux (с использованием `ip link`):**

```bash
# На стороне 1 (например, 192.0.2.1)
sudo ip link add gre0 type gre remote 192.0.2.2 local 192.0.2.1
sudo ip link set gre0 up
sudo ip address add 10.0.1.1/30 dev gre0

# На стороне 2 (например, 192.0.2.2)
sudo ip link add gre0 type gre remote 192.0.2.1 local 192.0.2.2
sudo ip link set gre0 up
sudo ip address add 10.0.1.2/30 dev gre0
```

### 2. GRE с ключом (Keyed GRE)

GRE-заголовок может включать поле `Key` (ключ), которое является простым идентификатором туннеля. Этот ключ **не имеет отношения к шифрованию**, а служит для различения множества туннелей между одними и теми же хостами. Это позволяет создавать несколько виртуальных сетей поверх одной физической связи.

**Пример настройки:**

```bash
# На стороне 1
sudo ip link add gre1 type gre remote 192.0.2.2 local 192.0.2.1 key 123
sudo ip link set gre1 up
sudo ip address add 10.0.2.1/30 dev gre1

# На стороне 2
sudo ip link add gre1 type gre remote 192.0.2.1 local 192.0.2.2 key 123
sudo ip link set gre1 up
sudo ip address add 10.0.2.2/30 dev gre1
```

### 3. Multipoint GRE (без указания `remote`)

В этом режиме можно создать GRE-туннель без явного указания удаленного адреса (`remote`). Удаленные точки определяются динамически с помощью внешних механизмов, таких как протокол NHRP (Next Hop Resolution Protocol), используемый в DMVPN (Dynamic Multipoint VPN).

В Linux можно вручную добавить записи в таблицу соседей (`ip neighbour`), чтобы указать, какой удаленный IP-адрес соответствует какому внутреннему IP-адресу туннеля.

**Пример настройки (без `remote`):**

```bash
# На стороне 1
sudo ip link add gre_mp type gre local 192.0.2.1 key 345
sudo ip link set gre_mp up
sudo ip address add 10.0.3.1/30 dev gre_mp

# На стороне 2
sudo ip link add gre_mp type gre local 192.0.2.2 key 345
sudo ip link set gre_mp up
sudo ip address add 10.0.3.2/30 dev gre_mp

# Добавление записи в таблицу соседей на стороне 1 для 10.0.3.2
sudo ip neighbour add 10.0.3.2 dev gre_mp lladdr 192.0.2.2
```
*   `lladdr`: Указывает IP-адрес внешнего интерфейса удаленной точки.

### 4. GRE Tap (GRETAP)

GRETAP — это вариант GRE, который позволяет инкапсулировать Ethernet-кадры (L2-трафик) вместо IP-пакетов (L3-трафик). Это делает его пригодным для создания "удлиненных" Ethernet-сетей (LAN Extension) через маршрутизируемую IP-сеть.

*   **Назначение:** Соединение двух сегментов канального уровня (L2) через IP-сеть. Полезно для приложений, требующих общей коммутируемой сети, или для соединения виртуальных машин на разных гипервизорах.
*   **Использование:** Интерфейс GRETAP можно объединить в мост (bridge) с физическим или виртуальным сетевым интерфейсом.

**Пример настройки GRETAP в Linux:**

```bash
# На стороне 1
sudo ip link add gretap0 type gretap remote 192.0.2.2 local 192.0.2.1
sudo ip link set gretap0 up
# Далее gretap0 можно добавить в bridge
```
*   `type gretap`: Указывает на инкапсуляцию Ethernet-кадров.

## Сравнение с другими протоколами

*   **vs IPIP/SIT:** GRE значительно гибче, так как может инкапсулировать различные протоколы (IPv4, IPv6, Ethernet) и поддерживать множественные туннели с помощью ключей.
*   **vs VXLAN:** Для создания множества виртуальных сетей между одними и теми же хостами GRE требует создания отдельных туннелей или использования ключей. [[VXLAN]] предлагает более масштабируемое решение для L2-оверлеев, особенно в многоточечных сценариях.
