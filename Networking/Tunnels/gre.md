# GRE (Generic Routing Encapsulation)

### Определения

**GRE (Generic Routing Encapsulation)** — это протокол туннелирования, разработанный Cisco. Он позволяет инкапсулировать широкий спектр сетевых протоколов (IPv4, IPv6, Ethernet и др.) внутри IP-пакетов. В отличие от [IPIP и SIT](./ipip_and_sit.md), GRE является более универсальным и гибким, так как не привязан к конкретному внутреннему протоколу.

---

### Базовые концепции

#### Принцип работы
GRE инкапсулирует "пассажирский" пакет (например, IPv4 или IPv6) в GRE-заголовок, который, в свою очередь, помещается в IP-заголовок "несущего" протокола (обычно IPv4).

*   **Протокол:** Использует номер протокола `47` в заголовке внешнего IP-пакета.
*   **Гибкость:** Позволяет передавать несколько протоколов одновременно внутри одного туннеля.
*   **Отсутствие шифрования:** GRE сам по себе не предоставляет механизмов шифрования. Для обеспечения безопасности трафика в публичных сетях его часто комбинируют с **IPsec**.

#### Использование ключа (Key)

GRE-заголовок может включать поле `Key` (ключ) — простой идентификатор туннеля. Ключ **не является элементом шифрования**, а служит для различения множества туннелей между одними и теми же хостами. Это позволяет создавать несколько виртуальных сетей поверх одной физической связи.

### Практические сценарии

#### 1. Point-to-Point GRE
Базовый режим, аналогичный IPIP, где туннель устанавливается между двумя статически заданными конечными точками.

**Пример настройки в Linux:**
```bash
# Сторона 1 (192.0.2.1)
sudo ip link add gre0 type gre remote 192.0.2.2 local 192.0.2.1 key 100
sudo ip link set gre0 up
sudo ip address add 10.0.1.1/30 dev gre0

# Сторона 2 (192.0.2.2)
sudo ip link add gre0 type gre remote 192.0.2.1 local 192.0.2.2 key 100
sudo ip link set gre0 up
sudo ip address add 10.0.1.2/30 dev gre0
```

#### 2. Multipoint GRE (mGRE)

В этом режиме `remote` адрес не указывается, что позволяет динамически устанавливать соединения с несколькими точками. Определение удаленных узлов происходит с помощью внешних механизмов, таких как **NHRP (Next Hop Resolution Protocol)** в **DMVPN (Dynamic Multipoint VPN)**.

В Linux можно вручную настроить статическую маршрутизацию для mGRE, добавив записи в таблицу соседей (`ip neighbour`).

**Пример настройки:**
```bash
# Сторона 1 (Hub)
sudo ip link add gre_mp type gre local 192.0.2.1 key 345
sudo ip link set gre_mp up
sudo ip address add 10.0.3.1/24 dev gre_mp

# Сторона 2 (Spoke)
sudo ip link add gre_mp type gre local 192.0.2.2 key 345
sudo ip link set gre_mp up
sudo ip address add 10.0.3.2/24 dev gre_mp

# Добавление соседа на стороне 2 для связи с 10.0.3.1 через Hub
sudo ip neighbour add 10.0.3.1 dev gre_mp lladdr 192.0.2.1
```
*   `lladdr`: IP-адрес внешнего интерфейса удаленной точки.

#### 3. GRE Tap (GRETAP) — L2 туннелирование
**GRETAP** — это вариант GRE для инкапсуляции Ethernet-кадров (L2), а не IP-пакетов (L3). Это позволяет "растягивать" Ethernet-сегменты (VLAN) между площадками через маршрутизируемую IP-сеть (L3).

*   **Назначение:** Соединение двух сегментов канального уровня (L2) через IP-сеть. Полезно для приложений, требующих общей коммутируемой сети, или для соединения виртуальных машин на разных гипервизорах.
*   **Использование:** Интерфейс GRETAP можно объединить в мост (bridge) с физическим или виртуальным сетевым интерфейсом.

**Пример настройки:**
```bash
# Сторона 1
sudo ip link add gretap0 type gretap remote 192.0.2.2 local 192.0.2.1
sudo ip link set gretap0 up

# Сторона 2
sudo ip link add gretap0 type gretap remote 192.0.2.1 local 192.0.2.2
sudo ip link set gretap0 up

# Далее gretap0 добавляется в bridge на обеих сторонах
# sudo ip link set gretap0 master br0
```

### Дополнительная информация

#### Сравнение с другими протоколами
*   **vs IPIP/SIT:** GRE значительно гибче, так как инкапсулирует любые протоколы (IPv4, IPv6, Ethernet) и поддерживает множественные туннели с помощью ключей.
*   **vs [VXLAN](./vxlan.md):** Для создания L2-оверлеев GRE уступает VXLAN в масштабируемости. VXLAN изначально разработан для дата-центров и лучше справляется с большим количеством виртуальных сетей (VNI) и многоточечными сценариями.
