# IPsec (Internet Protocol Security)

## Определения

**IPsec (Internet Protocol Security)** — набор протоколов и технологий для организации защищённого соединения на сетевом уровне (L3) путём аутентификации и шифрования IP-пакетов.

**Ключевое отличие от других туннельных технологий:** IPsec не создаёт явных туннельных интерфейсов (как GRE, PPP, L2TP). Вместо этого используется концепция **Security Associations (SA)** и **Security Policy (SP)**.

---

## Основные концепции

### Архитектура и протоколы

| Протокол | Назначение | Порт/Протокол |
|----------|------------|---------------|
| **ISAKMP** | Фреймворк для управления SA (термины SA, SP, SAD, SPD) | — |
| **IKE (IKEv1/IKEv2)** | Аутентификация и обмен ключами | UDP 500, 4500 (NAT-T) |
| **ESP** | Аутентификация + шифрование | IP-протокол 50 |
| **AH** | Только аутентификация | IP-протокол 51 |

### Двухфазная модель установления соединения

1. **Фаза 1: ISAKMP SA (вспомогательный туннель)**
   Стороны договариваются о параметрах шифрования и аутентифицируют друг друга.
   - **Main Mode:** поочередный обмен параметрами (6 сообщений). Для site-to-site.
   - **Aggressive Mode:** все параметры в одном сообщении (3 сообщения). Для remote access.
2. **Фаза 2: IPsec SA (туннель пользовательских данных)**
   По защищённому ISAKMP-туннелю стороны договариваются о параметрах шифрования трафика.

**Особенности:**

- **ISAKMP SA** — двунаправленный, действует постоянно.
- **IPsec SA** — однонаправленные туннели. Для двусторонней связи требуется два SA (src→dst и dst→src). Имеют время жизни (lifetime).

### Ассоциации безопасности (SA) и политики безопасности (SP)

**SA (Security Association)** — логический туннель от одного сетевого устройства к другому.

**Базы данных:**

- **SAD (Security Associations Database)** — хранит параметры активных SA (SPI, ключи, алгоритмы, время жизни).
- **SPD (Security Policy Database)** — политики безопасности, определяющие, какой трафик должен быть защищён (аналог ACL).

**Параметры SP:** адрес источника/назначения, протокол, направление (in, out, fwd), действие (protect, bypass, discard).

> **Важно:** Классическая маршрутизация здесь не работает. Трафик направляется в туннель на основе SP, а не таблицы маршрутизации.

### Режимы инкапсуляции

| Режим | Описание | Схема пакета | Применение |
|-------|----------|--------------|------------|
| **Транспортный** | Шифруется только полезная нагрузка | `[IP][ESP][Data]` | GRE/L2TP поверх IPsec; Host-to-Host |
| **Туннельный** | Шифруется весь исходный пакет | `[New IP][ESP][Old IP][Data]` | Site-to-Site VPN; Remote Access |

**Схемы инкапсуляции детально:**

- **Транспортный:** `[IP][ESP][TCP/UDP][Данные][ESP Trailer][ESP Auth]`
- **Туннельный:** `[Внешний IP][ESP][Внутренний IP][TCP/UDP][Данные][ESP Trailer][ESP Auth]`

### Прохождение NAT (NAT-T)

**Проблема:** ESP не содержит портов, что делает невозможным работу PAT (Port Address Translation).

**Решение:** Инкапсуляция ESP в UDP-пакет (порт **4500**). Стороны согласовывают NAT-T в Фазе 1.

### MTU и фрагментация

| Тип | Оверхед (Overhead) | Эффективный MTU (при 1500) |
|-----|--------------------|----------------------------|
| **IPsec ESP (туннельный)** | ~56-73 байта | ~1427-1440 байт |

**Последствия:** требуется настройка **Path MTU Discovery (PMTUD)** или принудительное уменьшение MSS (Maximum Segment Size).

## Практические сценарии

### Подключение к API партнёра через IPsec (Network-to-Network)

**Контекст:** Организация подключается к закрытому API партнёра. Требуется защищённый канал между сетями.

```
IPsec Gateway A: 10.0.1.1 (LAN: 192.168.1.0/24)
IPsec Gateway B: 10.0.255.1 (LAN: 192.168.255.0/24)
```

**Особенности:**

- Туннель поднимается между внешними IP (10.0.x.x).
- Трафик передаётся между внутренними подсетями (192.168.x.x).

### Реализации IPsec на Linux

- **strongSwan:** Современная реализация, поддержка IKEv2. **Рекомендуется.**
- **LibreSwan:** Фокус на безопасности, поддержка Red Hat.
- **iproute2 (XFRM):** Низкоуровневое управление SA/SP напрямую в ядре Linux.

### Настройка strongSwan (Debian/Ubuntu)

```bash
# Установка
apt-get install strongswan strongswan-pki

# Пример конфигурации (/etc/ipsec.conf)
conn partner-net
    left=10.0.1.1
    leftsubnet=192.168.1.0/24
    right=10.0.255.1
    rightsubnet=192.168.255.0/24
    authby=psk
    auto=start
    keyexchange=ikev2

# Секреты (/etc/ipsec.secrets)
10.0.1.1 10.0.255.1 : PSK "SUPERPASSWORD"
```

### Управление и диагностика

```bash
ipsec start          # Запуск
ipsec status         # Краткий статус
ipsec statusall      # Подробная информация о SA
ipsec reload         # Перезагрузка конфига
```

## Дополнительная информация

### Сравнение с другими VPN-технологиями

| Технология | Уровень | Шифрование | Интерфейс | Особенности |
|------------|---------|------------|-----------|-------------|
| **IPsec** | L3 | Да (ESP) | Нет (SA) | Сложная настройка, нативный для HW |
| **WireGuard** | L3 | Да | Да (wg0) | Высокая скорость, простота |
| **OpenVPN** | L2/L3 | Да | Да (tun/tap) | Гибкость, работа через TCP/UDP |
| **GRE** | L3 | Нет | Да (gre0) | Поддержка мультикаста и динамической маршрутизации |

### Диагностика и устранение неполадок

**Важно:** Туннель обычно поднимается только при наличии подходящего трафика!

```bash
# Тестовый пинг для активации SP
ping -I 192.168.1.1 192.168.255.1

# Проверка SA/SP в ядре (XFRM)
ip xfrm state
ip xfrm policy

# Захват ESP трафика
tcpdump -i eth1 host 10.0.255.1 and proto 50
```

### Типовые проблемы

| Проблема | Вероятная причина | Решение |
|----------|-------------------|---------|
| Туннель не поднимается | Нет интересного трафика | Отправить пинг через туннель |
| Ошибка Фазы 1 | Неверный PSK или ID | Проверить `/etc/ipsec.secrets` |
| Ошибка Фазы 2 | Несоответствие подсетей (TS) | Проверить `leftsubnet`/`rightsubnet` |
| Пакеты уходят, но нет ответа | Firewall дропает UDP 500/4500 или ESP | Разрешить порты и протокол 50 |
| `No route to host` | Проблема с ARP для /32 маски | Добавить статическую ARP-запись |
