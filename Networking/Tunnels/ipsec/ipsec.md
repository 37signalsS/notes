# IPsec (Internet Protocol Security)

## Определения

**IPsec (Internet Protocol Security)** — набор протоколов и технологий для организации защищённого соединения на сетевом уровне (L3) путём аутентификации и шифрования IP-пакетов.

**Ключевое отличие от других туннельных технологий:**
- **Классический IPsec (Policy-based):** Не создаёт явных туннельных интерфейсов (как GRE, PPP, L2TP). Вместо этого используется концепция **Security Associations (SA)** и **Security Policy (SP)**. Трафик перехватывается ядром на основе политик (SPD).
- **Современный IPsec (Route-based):** Использует виртуальные интерфейсы (**VTI** или **XFRM**). Это позволяет использовать стандартную таблицу маршрутизации и динамические протоколы (OSPF, BGP) поверх IPsec.

## Основные концепции

### Архитектура и протоколы

| Протокол | Назначение | Порт/Протокол |
|----------|------------|---------------|
| **ISAKMP** | Фреймворк для управления SA (термины SA, SP, SAD, SPD) | — |
| **IKE (v1/v2)** | Аутентификация и обмен ключами | UDP 500, 4500 (NAT-T) |
| **ESP** | Аутентификация + шифрование (основной протокол данных) | IP-протокол 50 |
| **AH** | Только аутентификация (не обеспечивает конфиденциальность) | IP-протокол 51 |

### Протоколы обмена ключами (IKE)

#### IKEv1 (Устаревший)
Использует двухфазную модель:
1. **Phase 1 (ISAKMP SA):** Установление защищённого канала управления.
   - **Main Mode:** 6 сообщений, скрывает ID сторон.
   - **Aggressive Mode:** 3 сообщения, быстрее, но передаёт ID в открытом виде (небезопасно).
2. **Phase 2 (IPsec SA):** Согласование параметров шифрования данных (Quick Mode).

#### IKEv2 (Современный)
**Рекомендуется к использованию.** Основные улучшения:
- **Меньше сообщений:** Установление соединения за 4 сообщения (IKE_SA_INIT и IKE_AUTH).
- **Нативная поддержка NAT-T:** Встроена в протокол.
- **Reliability:** Поддержка подтверждения получения пакетов.
- **EAP (Extensible Authentication Protocol):** Поддержка современных методов аутентификации (сертификаты, логин/пароль).
- **MOBIKE:** Позволяет менять IP-адрес клиента без разрыва туннеля (важно для мобильных устройств).

### Ассоциации безопасности (SA) и политики безопасности (SP)

**SA (Security Association)** — логический туннель от одного сетевого устройства к другому.

**Базы данных:**
- **SAD (Security Associations Database)** — хранит параметры активных SA (SPI, ключи, алгоритмы, время жизни).
- **SPD (Security Policy Database)** — политики безопасности, определяющие, какой трафик должен быть защищён (аналог ACL).

**Параметры SP:** адрес источника/назначения, протокол, направление (in, out, fwd), действие (protect, bypass, discard).

### Режимы инкапсуляции

| Режим | Описание | Схема пакета | Применение |
|-------|----------|--------------|------------|
| **Транспортный** | Шифруется только полезная нагрузка | `[IP][ESP][Data]` | GRE/L2TP поверх IPsec; Host-to-Host |
| **Туннельный** | Шифруется весь исходный пакет | `[New IP][ESP][Old IP][Data]` | Site-to-Site VPN; Remote Access |

### Безопасность и алгоритмы (Cipher Suites)

В 2026 году рекомендуется использовать следующие параметры:
- **Шифрование:** AES-GCM (встроенная проверка целостности, высокая скорость на современном HW) или AES-CBC (256 бит).
- **Целостность:** SHA256, SHA384, SHA512.
- **Обмен ключами (Diffie-Hellman):** Группы 14 (2048-bit), 19 (ECP 256), 20 (ECP 384), 21 (ECP 521). **Группы 2, 5 считаются небезопасными.**

## Практические сценарии

### Реализации IPsec на Linux

- **strongSwan:** Самый популярный проект, полная поддержка IKEv2 и современных механизмов.
- **LibreSwan:** Форк Openswan, упор на безопасность и соответствие стандартам (часто в RHEL/CentOS).
- **iproute2 (XFRM):** Низкоуровневое управление SA/SP напрямую через ядро Linux.

### Настройка strongSwan (swanctl.conf — современный метод)

Современный strongSwan рекомендует использовать плагин **vici** и конфигурационный файл `swanctl.conf` вместо устаревшего `ipsec.conf`.

```hcl
# /etc/swanctl/conf.d/partner.conf
connections {
    partner-vpn {
        remote_addrs = 10.0.255.1
        local_addrs = 10.0.1.1
        auth = psk
        children {
            net-to-net {
                local_ts = 192.168.1.0/24
                remote_ts = 192.168.255.0/24
                esp_proposals = aes256gcm128-modp2048
                start_action = trap
            }
        }
    }
}

secrets {
    ike-partner {
        secret = "SUPERPASSWORD"
    }
}
```

### Настройка Routed IPsec (XFRM интерфейс)

Позволяет создать интерфейс `xfrm0`, которому можно назначить маршруты.

```bash
# Создание интерфейса XFRM (ID должен совпадать с if_id в конфиге strongSwan)
ip link add xfrm0 type xfrm dev eth0 if_id 1
ip link set xfrm0 up
ip addr add 10.255.255.1/30 dev xfrm0

# Маршрутизация через интерфейс
ip route add 192.168.255.0/24 dev xfrm0
```

## Управление и диагностика

### Команды strongSwan (swanctl)

```bash
swanctl --load-all       # Загрузка конфигурации и секретов
swanctl --initiate --child net-to-net  # Поднять туннель вручную
swanctl --list-conns     # Список настроенных соединений
swanctl --list-sas       # Список активных туннелей (SA)
swanctl --log            # Просмотр логов в реальном времени
```

### Диагностика в ядре

```bash
# Проверка SA/SP в ядре (XFRM)
ip xfrm state            # Показывает ключи и параметры шифрования
ip xfrm policy           # Показывает правила перехвата трафика

# Проверка счетчиков (помогает понять, доходят ли пакеты)
ip -s xfrm state
```

### Типовые проблемы

| Проблема | Вероятная причина | Решение |
|----------|-------------------|---------|
| `NO_PROPOSAL_CHOSEN` | Несовпадение алгоритмов шифрования | Проверить `esp_proposals` и `ike_proposals` на обеих сторонах |
| `AUTHENTICATION_FAILED` | Неверный PSK или ID сертификата | Проверить секреты и `local_id`/`remote_id` |
| `TS_UNACCEPTABLE` | Несовпадение подсетей (Traffic Selectors) | Проверить `local_ts` и `remote_ts` |
| Туннель UP, трафик не идет | Firewall или проблема MTU | Разрешить ESP/UDP-4500, настроить MSS Clamping |

## Дополнительная информация

### Сравнение с другими технологиями

| Технология | Плюсы | Минусы |
|------------|-------|--------|
| **IPsec** | Нативная поддержка в железе, стандартизирован | Сложность настройки, высокий overhead |
| **WireGuard** | Скорость, простота, современная криптография | Менее распространен в корпоративном HW |
| **OpenVPN** | Гибкость (TCP/UDP, любые порты) | Низкая производительность (userspace) |
