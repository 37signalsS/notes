# IPsec: архитектура и детализация

## Definitions

**IPSec Architecture** — детальное описание внутренних механизмов IPsec: структуры пакетов, процедур IKE, баз данных SAD/SPD, режимов инкапсуляции.

---

## Basic Concepts

### Детализация IKE: Фаза 1

**Технические параметры:**

| Параметр | Значение |
|----------|----------|
| Протокол | UDP порт 500 |
| Туннель | Двунаправленный |
| Аутентификация | Pre-Shared Key (PSK) или сертификаты |
| Результат | ISAKMP SA (действует постоянно) |

**Режимы обмена:**

| Режим | Описание | Применение |
|-------|----------|------------|
| **Main** | Поочередный обмен параметрами согласования (6 сообщений) | Постоянные каналы (site-to-site) |
| **Aggressive** | Все параметры в одном сообщении (3 сообщения) | Временные сессии (remote access) |

### Детализ IKE: Фаза 2

**Особенности:**

- **SA-туннели однонаправленные** — для двусторонней связи требуется два туннеля (src→dst и dst→src)
- Результат: **IPsec SA** (ESP или AH туннель)
- Имеет время жизни (lifetime), по истечении которого пересоздаётся

### Структура SAD и SPD

**SAD (Security Associations Database)** — хранит параметры активных SA:

| Поле | Описание |
|------|----------|
| SPI (Security Parameter Index) | Уникальный идентификатор SA |
| Sequence Number | Счётчик для защиты от replay-атак |
| Sequence Counter Overflow | Флаг переполнения счётчика |
| Anti-Replay Window | Окно для проверки replay-атак |
| AH/ESP Protocol | Используемый протокол (AH или ESP) |
| Keys | Ключи для шифрования и аутентификации |
| Lifetime | Время жизни SA |

**SPD (Security Policy Database)** — упорядоченный список политик безопасности:

| Поле | Описание |
|------|----------|
| Source/Destination Address | Адреса источника и назначения |
| Protocol | Протокол (TCP, UDP, ICMP, any) |
| Direction | Направление (in, out, fwd) |
| Action | Действие (discard, bypass, protect) |
| IPSec Protocol | ESP или AH |
| Mode | Transport или Tunnel |

## Practical Scenarios

### Схемы инкапсуляции

**Транспортный режим:**

```
[IP][ESP][TCP/UDP][Данные][ESP Trailer][ESP Auth]
```

Оригинальный IP-заголовок остаётся без изменений. Шифруется только полезная нагрузка.

**Туннельный режим:**

```
[Внешний IP][ESP][Внутренний IP][TCP/UDP][Данные][ESP Trailer][ESP Auth]
```

Шифруется весь исходный IP-пакет + добавляется внешний IP-заголовок.

**GRE over IPsec (транспортный режим):**

```
[Внешний IP][ESP][GRE][IP][ICMP][ESP Trailer][ESP Auth]
```

> **Важно:** При использовании GRE с IPsec в транспортном режиме добавление GRE-заголовка увеличивает overhead и уменьшает объём полезных данных. В большинстве случаев рекомендуется **туннельный режим IPsec** или **GRE over IPsec**.

### Сценарий использования AH

**AH (Authentication Header)** — протокол IP 51, только аутентификация (без шифрования).

**Специальный сценарий:** Решение проблем с MTU на недоверенных участках без необходимости шифрования.

**Особенности:**

- AH не создаёт туннельных интерфейсов — трафик маршрутизируется классически
- Фрагментируется только по внешнему заголовку
- Защищает от подмены пакетов, но не обеспечивает конфиденциальность
- **Практически не используется** в современных развёртываниях

## Additional Information

### Сравнение режимов инкапсуляции

| Критерий | Transport Mode | Tunnel Mode |
|----------|---------------|-------------|
| Шифрование IP-заголовка | Нет | Да |
| Размер overhead | Меньше | Больше (внешний IP + ESP) |
| Совместимость с NAT | Проблемы (ESP без портов) | Решается через NAT-T (UDP 4500) |
| Типичное использование | Host-to-host | Site-to-site VPN |
