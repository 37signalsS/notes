# IPsec: архитектура и детализация

> **Основной документ:** [ipsec.md](./ipsec.md).

Данный файл содержит углублённый архитектурный материал по механизмам IPsec.

---

## Определения

**SAD (Security Associations Database)** — база данных, хранящая параметры всех активных ассоциаций безопасности (ключи, алгоритмы, SPI).

**SPD (Security Policy Database)** — база данных политик, определяющая правила обработки трафика (шифровать, пропустить или отбросить).

**SPI (Security Parameter Index)** — 32-битный идентификатор в заголовке AH/ESP, позволяющий получателю сопоставить пакет с конкретной SA в базе SAD.

**Anti-Replay Window** — механизм защиты от повторной передачи пакетов, использующий скользящее окно и порядковые номера (Sequence Numbers).

## Основные концепции

### Детализация IKE: Фаза 1

**Режимы обмена:**

| Режим | Описание | Применение |
|-------|----------|------------|
| **Main** | Поочередный обмен параметрами согласования (6 сообщений) | Постоянные каналы (site-to-site) |
| **Aggressive** | Все параметры в одном сообщении (3 сообщения) | Временные сессии (remote access) |

### Детализация IKE: Фаза 2

**Особенности:**

- Результат: **IPsec SA** (ESP или AH туннель).
- Имеет время жизни (lifetime), по истечении которого пересоздаётся (rekeying).

### Структура SAD и SPD (подробно)

**SAD (Security Associations Database)** — хранит параметры активных SA:

| Поле | Описание |
|------|----------|
| SPI (Security Parameter Index) | Уникальный идентификатор SA |
| Sequence Number | Счётчик для защиты от replay-атак |
| Sequence Counter Overflow | Флаг переполнения счётчика |
| Anti-Replay Window | Окно для проверки replay-атак |
| Keys | Ключи для шифрования и аутентификации |
| Lifetime | Время жизни SA |

**SPD (Security Policy Database)** — упорядоченный список политик безопасности:

| Поле | Описание |
|------|----------|
| Action | Действие (**discard** — дропнуть, **bypass** — пропустить без защиты, **protect** — защитить через IPsec) |
| IPsec Protocol | ESP или AH |
| Mode | Transport или Tunnel |

## Практические сценарии

### Сценарий использования AH

**AH (Authentication Header)** — протокол IP 51, только аутентификация (без шифрования).

**Особенности:**

- Защищает от подмены пакетов, но не обеспечивает конфиденциальность.
- Не совместим с NAT (из-за проверки целостности заголовка IP).
- **Практически не используется** в современных развёртываниях, вытеснен ESP в режиме аутентификации.
