# IPsec: настройка стека KAME/racoon на Linux

> **Основной документ:** [IPsec (основной документ)](./ipsec.md).

Данный файл содержит техническое руководство по эксплуатации устаревшей реализации IPsec через стек KAME и демон управления ключами racoon.

> **ВНИМАНИЕ — УСТАРЕВШАЯ ТЕХНОЛОГИЯ:** Стек KAME/racoon не поддерживается и не обновляется с начала 2010-х годов. Он содержит критические ограничения безопасности (отсутствие поддержки IKEv2, использование дискредитированных алгоритмов шифрования). Для новых инсталляций **ОБЯЗАТЕЛЬНО** используйте **[strongSwan](./ipsec.md)** или **LibreSwan**.

---

## Определения и компоненты

**KAME** — исторический проект по реализации стека IPv6 и IPsec для BSD, части которого были интегрированы в ядро Linux (подсистема XFRM является его идеологическим преемником).

**Утилиты управления:**
- **racoon:** Демон (IKEv1-демон) для динамического согласования Security Associations (SA) и управления ключами.
- **setkey:** Низкоуровневая утилита для прямого манипулирования базами данных политик (SPD) и состояний (SAD) в ядре.
- **ipsec-tools:** Пакет, объединяющий эти инструменты (в современных дистрибутивах может отсутствовать или находиться в репозиториях legacy-ПО).

## Основные концепции конфигурации

### Компоненты взаимодействия

| Компонент | Роль в системе |
|-----------|----------------|
| **racoon** | Обработка протокола ISAKMP (Фаза 1 и Фаза 2) в пользовательском пространстве. |
| **setkey** | Синхронизация политик безопасности с ядром через протокол PF_KEY. |
| **af_key** | Модуль ядра, необходимый для взаимодействия между `racoon` и сетевым стеком. |

### Конфигурационные файлы

| Путь | Назначение |
|------|------------|
| `/etc/racoon.conf` | Основной файл: параметры IKE, предложения алгоритмов, пути к ключам. |
| `/etc/racoon/psk.txt` | База секретов Pre-Shared Keys (формат: `IP-адрес Ключ`). |
| `/etc/ipsec-tools.conf` | Скрипт для `setkey`, содержащий правила перехвата трафика (SPD). |

## Практические сценарии настройки

### Конфигурация Site-to-Site (Туннельный режим)

**Параметры стенда:**
- **Локальный шлюз (Public IP):** `10.0.1.1` (защищаемая сеть `192.168.1.0/24`)
- **Удаленный шлюз (Public IP):** `10.0.255.1` (защищаемая сеть `192.168.255.0/24`)

#### 1. Подготовка окружения

Убедитесь, что необходимые модули ядра загружены:
```bash
modprobe af_key
modprobe esp4
```

Установка пакетов (если доступны):
```bash
apt-get install racoon ipsec-tools
```

#### 2. Настройка политик безопасности (`/etc/ipsec-tools.conf`)

Этот файл инициализирует SPD (Security Policy Database). Без этих правил ядро не будет знать, что трафик нужно шифровать.

```bash
#!/usr/sbin/setkey -f
# Очистка текущих записей перед применением
flush;
spdflush;

# Политика для ИСХОДЯЩЕГО трафика
spdadd 192.168.1.0/24 192.168.255.0/24 any -P out ipsec
    esp/tunnel/10.0.1.1-10.0.255.1/require;

# Политика для ВХОДЯЩЕГО трафика
spdadd 192.168.255.0/24 192.168.1.0/24 any -P in ipsec
    esp/tunnel/10.0.255.1-10.0.1.1/require;
```

#### 3. Настройка демона ключей (`/etc/racoon.conf`)

```bash
path pre_shared_key "/etc/racoon/psk.txt";
log notify; 

listen {
    isakmp 10.0.1.1 [500];
    strict_address;
}

# Фаза 1: Установление защищенного канала управления
remote 10.0.255.1 {
    exchange_mode main;
    proposal {
        encryption_algorithm 3des;   # ВНИМАНИЕ: Алгоритм признан слабым
        hash_algorithm sha1;        # ВНИМАНИЕ: Алгоритм признан слабым
        authentication_method pre_shared_key;
        dh_group 2;                 # MODP 1024
    }
}

# Фаза 2: Создание SA для пользовательских данных
sainfo address 192.168.1.0/24 any address 192.168.255.0/24 any {
    pfs_group 2;
    encryption_algorithm 3des;
    authentication_algorithm hmac_sha1;
    compression_algorithm deflate;
}
```

#### 4. Настройка секретов (`/etc/racoon/psk.txt`)

```text
10.0.255.1    MySuperSecretKey123
```
*Важно: Права доступа должны быть строго `600` (`chmod 600 /etc/racoon/psk.txt`), иначе демон откажется работать из соображений безопасности.*

## Управление и диагностика

### Основные команды управления

| Задача | Команда |
|--------|---------|
| Применение политик SPD | `setkey -f /etc/ipsec-tools.conf` |
| Просмотр активных политик (SPD) | `setkey -DP` |
| Просмотр активных ассоциаций (SAD) | `setkey -D` |
| Полная очистка состояний и политик | `setkey -F && setkey -FP` |
| Запуск демона в отладочном режиме | `racoon -F -d` |

### Типовые проблемы и решения

1.  **Несоответствие селекторов трафика (TS):** Если `sainfo` в `racoon.conf` не совпадает с `spdadd` в `setkey`, Фаза 2 не будет согласована.
2.  **Проблема NAT-Traversal:** Racoon требует явной поддержки NAT-T в ядре и включенной опции `nat_traversal on;` в конфигурации. Порт UDP 4500 должен быть открыт.
3.  **Ошибки фрагментации:** KAME не поддерживает автоматическую подстройку MSS. Рекомендуется ручная настройка:
    ```bash
    iptables -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
    ```
4.  **Слабая криптография:** Многие современные устройства Cisco или Juniper по умолчанию запрещают 3DES/SHA1. Если туннель не поднимается с ошибкой `NO_PROPOSAL_CHOSEN`, проверьте совместимость алгоритмов.

## Дополнительная информация

### Критические недостатки и риски

*   **IKEv1 Only:** Отсутствие поддержки IKEv2 делает невозможным использование современных функций, таких как MOBIKE и улучшенная аутентификация.
*   **Производительность:** Стек KAME работает менее эффективно на многоядерных системах по сравнению с современным XFRM.
*   **Безопасность:** Отсутствие поддержки алгоритмов типа AES-GCM (AEAD).
