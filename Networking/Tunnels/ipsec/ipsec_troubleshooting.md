# IPsec: диагностика и устранение неполадок KAME/racoon

> **Основной документ:** [ipsec.md](./ipsec.md).

Данный файл содержит историческую документацию по методам диагностики и отладки устаревшей реализации IPsec через стек KAME/racoon.

> **ВНИМАНИЕ:** Для диагностики современных систем (strongSwan, LibreSwan) используйте **[раздел диагностики в основном документе](./ipsec.md#диагностика-и-устранение-неполадок)**.

---

## Определения

**ISAKMP SA (Phase 1)** — состояние согласования защищенного канала управления. Если Фаза 1 не установлена, передача данных невозможна.

**IPsec SA (Phase 2 / Quick Mode)** — состояние согласования конкретного туннеля для передачи пользовательских данных (ESP/AH).

**SAD (Security Association Database)** — база данных в ядре Linux, содержащая ключи и параметры шифрования для активных туннелей.

**SPD (Security Policy Database)** — база данных политик, определяющая, какой трафик подлежит защите.

## Инструментарий диагностики

### Основные команды

| Команда | Описание |
|---------|----------|
| `racoonctl show-sa isakmp` | Статус Фазы 1 (ISAKMP) |
| `racoonctl show-sa esp` | Статус Фазы 2 (ESP) |
| `setkey -D` | Просмотр всех SA в ядре (SAD) |
| `setkey -DP` | Просмотр всех политик в ядре (SPD) |
| `tcpdump -i any proto 50` | Проверка прохождения зашифрованного ESP трафика |
| `tcpdump -i any port 500 or port 4500` | Анализ процесса согласования ключей (IKE) |

## Методика устранения неисправностей

### 1. Проверка сетевого уровня (L3)
Убедитесь, что внешние адреса шлюзов доступны.
```bash
ping <remote_gateway_ip>
```
*Если ping не проходит, туннель не будет инициирован.*

### 2. Анализ логов racoon
Это самый важный этап. Логи обычно находятся в `/var/log/syslog` или `/var/log/messages`.

| Сообщение в логе | Вероятная причина | Решение |
|------------------|-------------------|---------|
| `failed to get sainfo` | Ошибка в конфигурации `sainfo` в `racoon.conf` | Проверьте соответствие подсетей и алгоритмов в Фазе 2 |
| `no policy found` | Отсутствует политика в SPD | Проверьте `setkey -DP` и файл `ipsec-tools.conf` |
| `phase1 negotiation failed due to time up` | Блокировка UDP 500 или неверный IP партнера | Проверьте Firewall и маршрутизацию до шлюза |
| `invalid secret` | Неверный Pre-Shared Key | Проверьте `/etc/racoon/psk.txt` и права доступа (0600) |

### 3. Проверка состояний в ядре (XFRM/KAME)
Если `racoon` рапортует об успехе, но трафик не идет, проверьте ядро.

**Проверка SAD (Keys/SPI):**
```bash
setkey -D
```
*Вы должны увидеть пары SPI (incoming и outgoing). Если их нет — Фаза 2 не завершена.*

**Проверка SPD (Policies):**
```bash
setkey -DP
```
*Вы должны увидеть правила `spdadd`. Если список пуст — трафик не будет перехватываться для шифрования.*

## Анализ трафика (tcpdump)

Успешный процесс установления туннеля выглядит так:
1. **UDP 500:** Обмен предложениями (Proposals).
2. **UDP 500:** Обмен Diffie-Hellman и аутентификация.
3. **ESP (Proto 50):** Появление зашифрованных данных.

**Захват трафика для отладки:**
```bash
tcpdump -n -i eth0 host <remote_gateway>
```

## Типовые проблемы legacy-систем

### Проблема NAT-Traversal
Стек KAME/racoon часто имеет проблемы с NAT-T. Если один из шлюзов за NAT:
- Проверьте, включен ли `nat_traversal on;` в `racoon.conf`.
- Убедитесь, что порт UDP 4500 открыт.
- В логах ищите `NAT-T is detected`.

### Проблема "зависших" SA
Иногда в ядре остаются старые записи SAD, которые мешают новым.
**Решение:** Очистка баз и перезапуск.
```bash
setkey -F
setkey -FP
service racoon restart
```
