# IPsec: диагностика и устранение неполадок стека KAME/racoon

> **Основной документ:** [IPsec (основной документ)](./ipsec.md).

Данный файл содержит методику диагностики и отладки устаревшей реализации IPsec через стек KAME и демон управления ключами racoon.

> **ВНИМАНИЕ:** Для диагностики современных систем (strongSwan, LibreSwan) используйте **[раздел диагностики в основном документе](./ipsec.md#управление-и-диагностика)**.

---

## Определения и терминология

**ISAKMP SA (Phase 1)** — защищённый канал управления. Если Фаза 1 не установлена, согласование ключей для данных невозможно.

**IPsec SA (Phase 2 / Quick Mode)** — конкретный туннель для передачи пользовательского трафика (ESP/AH).

**SAD (Security Association Database)** — база данных в ядре Linux, хранящая ключи и параметры шифрования для активных туннелей.

**SPD (Security Policy Database)** — база данных политик, определяющая, какой именно трафик подлежит защите (перехвату ядром).

## Инструментарий диагностики

### Специализированные команды racoon

| Команда | Описание |
|---------|----------|
| `racoonctl show-sa isakmp` | Просмотр статуса Фазы 1. |
| `racoonctl show-sa esp` | Просмотр активных туннелей Фазы 2. |
| `racoonctl vpn-connect <IP>` | Ручной запуск процесса согласования для пира. |
| `racoonctl delete-sa isakmp` | Принудительное удаление канала управления. |
| `racoon -F -d` | Запуск демона на переднем плане с отладочным выводом. |

### Низкоуровневая диагностика (ядро Linux)

В современных дистрибутивах для работы с ядром можно использовать как legacy-утилиту `setkey`, так и современные команды `ip xfrm`.

| Задача | Legacy (`setkey`) | Современный (`ip xfrm`) |
|--------|-------------------|-------------------------|
| Просмотр SAD (ключи) | `setkey -D` | `ip xfrm state` |
| Просмотр SPD (политики) | `setkey -DP` | `ip xfrm policy` |
| Очистка SAD | `setkey -F` | `ip xfrm state flush` |
| Очистка SPD | `setkey -FP` | `ip xfrm policy flush` |

## Методика устранения неисправностей

### 1. Проверка сетевой связности и Firewall

IPsec требует открытия следующих портов и протоколов на внешних интерфейсах:
- **UDP 500:** Для согласования IKE (Internet Key Exchange).
- **UDP 4500:** Для работы NAT-Traversal (NAT-T).
- **IP Protocol 50 (ESP):** Для передачи зашифрованных данных.
- **IP Protocol 51 (AH):** Если используется аутентификация заголовков (редко).

### 2. Глубокий анализ логов racoon

Логи демона обычно направляются в `syslog` или `messages`.

| Сообщение в логе | Вероятная причина | Решение |
|------------------|-------------------|---------|
| `failed to get sainfo` | Несовпадение подсетей или алгоритмов в Фазе 2. | Проверьте секции `sainfo` в `racoon.conf` на обеих сторонах. |
| `no policy found` | Трафик не попадает под правила SPD. | Проверьте вызов `spdadd` в `ipsec-tools.conf`. |
| `invalid secret` | Ошибка аутентификации (PSK). | Проверьте `/etc/racoon/psk.txt` и права доступа к нему (`chmod 600`). |
| `phase1 negotiation failed` | Блокировка UDP 500 или неверный IP адрес партнера. | Проверьте Firewall и маршрутизацию между шлюзами. |
| `notify: no phase2 found` | Партнер запрашивает туннель для подсети, которая у вас не описана. | Синхронизируйте селекторы трафика (TS) на обеих сторонах. |
| `could not get psk` | Демон не может прочитать файл ключей. | Проверьте владельца файла (должен быть `root`) и права доступа. |

### 3. Проверка состояний в ядре

Если логи показывают успешное установление SA (`ISAKMP-SA established`), но трафик не проходит:

1.  **Проверьте наличие SPI:** `ip xfrm state` должен показывать две записи для каждого туннеля (входящий и исходящий).
2.  **Проверьте счетчики пакетов:**
    ```bash
    ip -s xfrm state
    ```
    Если счетчики `packets` растут на одной стороне, но не на другой — пакеты блокируются Firewall на стороне приемника или теряются в пути.

## Анализ трафика (tcpdump)

Для отладки процесса согласования и проверки прохождения данных используйте следующие фильтры:

```bash
# Просмотр процесса согласования (Фаза 1 и 2)
tcpdump -n -i any port 500 or port 4500

# Просмотр зашифрованного трафика (ESP)
tcpdump -n -i any proto 50

# Детальный захват для конкретного пира
tcpdump -n -i any host <remote_gateway_ip> -w ipsec_debug.pcap
```

## Типовые проблемы и ограничения

### Проблемы NAT-Traversal
Стек KAME часто требует явной настройки NAT-T:
- Убедитесь, что в `racoon.conf` в секции `remote` указано `nat_traversal on;`.
- Порт UDP 4500 должен быть проброшен через все промежуточные NAT-устройства.

### Фрагментация и MTU
IPsec ESP добавляет оверхед (до 73 байт). Если туннель «поднят», но большие пакеты не проходят:
- Установите MSS Clamping: `iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu`.
- Проверьте доступность через пинг с флагом `DF` (Don't Fragment):
  ```bash
  ping -M do -s 1400 <remote_internal_ip>
  ```
