#### IP-адрес

IP (Internet Protocol) — межсетевой протокол модели OSI, уникальный внутри подсети идентификатор устройства третьего (сетевого) уровня. Его главная задача — адресация узлов сети и маршрутизация пакетов до них. Ключевые сущности для межсетевого протокола: IP-адрес, маска подсети и маршрут. IP-адрес состоит из четырех октетов (4-байтовое или 32-битное число), последний из которых указывает номер хоста в сети. Точки в IP-адресе служат только для визуального разделения октетов человеком. Для машины это сплошное 32-битное двоичное число.

##### Маска подсети

Маска подсети (32-битное число) — служит для разделения сетевой части (адреса подсети) и части хоста IP-адреса.

**Основная задача:** Маска разделяет IP-адрес на две части:
1.  **Адрес сети (Network ID):** Идентифицирует всю локальную сеть. У всех устройств в одной сети эта часть одинакова.
2.  **Адрес хоста (Host ID):** Уникальный идентификатор устройства внутри этой сети.

Компьютер использует побитовую операцию «И» (AND) между IP-адресом и маской подсети, чтобы вычислить адрес сети.

**Пример:**
-   **IP-адрес:** `192.168.1.10`
-   **Маска подсети:** `255.255.255.0`

В двоичном виде:
```
11000000.10101000.00000001.00001010  (IP-адрес)
И
11111111.11111111.11111111.00000000  (Маска)
-----------------------------------
11000000.10101000.00000001.00000000  (Адрес сети: 192.168.1.0)
```
Единицы в маске "сохраняют" соответствующую часть IP-адреса (адрес сети), а нули "обнуляют" ее (адрес хоста).

**Форматы записи маски**

1.  **Десятичный (Dotted-Decimal):** `255.255.255.0`
    Это стандартная запись, но она может быть громоздкой.

2.  **CIDR (Classless Inter-Domain Routing):** `/24`
    Это современный и более короткий формат. Число после `/` означает количество единиц в двоичном представлении маски. `/24` — это 24 единицы подряд, что в точности соответствует маске `255.255.255.0`.

| CIDR | Десятичная маска | Количество хостов |
| :--- | :--- | :--- |
| `/8` | `255.0.0.0` | ~16.7 млн |
| `/16` | `255.255.0.0` | 65 534 |
| `/24` | `255.255.255.0` | 254 |
| `/29` | `255.255.255.248`| 6 |
| `/32` | `255.255.255.255`| 1 (конкретный хост) |

**Главная практическая задача**

Маска нужна, чтобы компьютер мог ответить на вопрос: **"Адресат находится в моей локальной сети или мне нужно отправить пакет на шлюз (роутер)?"**

-   **Сценарий 1:** Ваш компьютер `192.168.1.10/24` хочет связаться с `192.168.1.50`.
    1.  Он вычисляет адрес сети для себя: `192.168.1.0`.
    2.  Он вычисляет адрес сети для адресата: `192.168.1.0`.
    3.  Адреса сетей совпадают. Вывод: "Мы в одной сети". Компьютер отправит пакет напрямую (используя ARP для определения MAC-адреса).

-   **Сценарий 2:** Ваш компьютер `192.168.1.10/24` хочет связаться с `8.8.8.8`.
    1.  Адрес своей сети: `192.168.1.0`.
    2.  Адрес сети адресата: `8.8.8.0` (с той же маской).
    3.  Адреса сетей не совпадают. Вывод: "Адресат в другой сети". Компьютер отправит пакет на **шлюз по умолчанию** (роутер), чтобы тот переслал его дальше.

#### MAC-адрес

MAC-адрес – это уникальный 48-битный аппаратный номер компьютера, который встроен в сетевую карту на стадии производства. MAC-адрес также известен как физический адрес сетевого устройства. Считается, что MAC-адрес каждого устройства в мире уникален благодаря соглашениям между производителями. В стандарте IEEE 802, канальный уровень (второй уровень) разделен на два подуровня:

*   Подуровень управления логическим каналом (LLC)
*   Подуровень управления доступом к среде (MAC)

MAC-адрес используется подуровнем управления доступом к среде (MAC) канального (второго) уровня модели OSI.

#### Протокол ARP (Address Resolution Protocol)

На самом деле протокол ARP находится между канальным и сетевым уровнем. С помощью него 32-битные IP-адреса преобразуются в 48-битные MAC-адреса.

Когда хосту в локальной сети нужно отправить пакет другому хосту, зная его IP-адрес, он использует ARP, чтобы узнать его MAC-адрес. Для этого компьютер делает широковещательный запрос следующего содержания: "Устройство с IP-адресом X и MAC-адресом Y просит устройство с вот этим IP-адресом Z сообщить свой MAC-адрес". Напоминаем, что широковещательный запрос принимается всеми устройствами в сети. Устройство, которому этот запрос не предназначен, отбрасывает его, но может сохранить информацию об IP-адресе и MAC-адресе отправителя в своем кэше, чтобы не выполнять ARP-запрос, если ему когда-нибудь понадобится связаться с этим устройством. Устройство с IP-адресом Z, получив запрос, также помещает информацию в свой кэш и отправляет отправителю одноадресный ответ, сообщая свой MAC-адрес.

#### Порт

Это числовое значение (от 0 до 65535), которое используется для идентификации конкретного процесса или службы на устройстве. Когда компьютер обменивается данными по сети, он использует IP-адрес для определения устройства и номер порта для определения конкретной службы или приложения.

Порты делятся на три диапазона в соответствии с рекомендациями IANA (Internet Assigned Numbers Authority):

1.  **Системные (или общеизвестные) порты (Well-Known Ports): 0–1023**
    *   **Назначение:** Зарезервированы для стандартных, хорошо известных системных служб и протоколов.
    *   **Примеры:**
        *   `20/21`: FTP (File Transfer Protocol)
        *   `22`: SSH (Secure Shell)
        *   `25`: SMTP (Simple Mail Transfer Protocol)
        *   `53`: DNS (Domain Name System)
        *   `80`: HTTP (HyperText Transfer Protocol)
        *   `443`: [HTTPS (HTTP Secure)](./tls_protocol.md)
    *   **Особенность:** Для использования этих портов в большинстве операционных систем требуются права суперпользователя (root).

2.  **Зарегистрированные (или пользовательские) порты (Registered/User Ports): 1024–49151**
    *   **Назначение:** Предназначены для приложений и служб, которые устанавливаются пользователями или сторонним программным обеспечением. Компании могут официально зарегистрировать порт для своего приложения в IANA.
    *   **Примеры:**
        *   `1433`: Microsoft SQL Server
        *   `3306`: MySQL
        *   `5432`: PostgreSQL
        *   `8080`: Часто используется как альтернативный порт для веб-серверов.

3.  **Динамические (или частные) порты (Dynamic/Private/Ephemeral Ports): 49152–65535**
    *   **Назначение:** Используются для временных (эфемерных) соединений. Когда ваш компьютер (клиент) подключается к веб-серверу (например, на порт 443), он выбирает для себя случайный свободный порт из этого диапазона для исходящего соединения.
    *   **Особенность:** Эти порты не закрепляются за какой-либо службой на постоянной основе и свободны для использования любым приложением.

#### Специальные IP-адреса и Частные Сети (RFC 1918)

В сетях TCP/IP существуют зарезервированные адреса и диапазоны, которые выполняют специальные функции и не используются для идентификации уникальных хостов в глобальном интернете.

| Адрес / Диапазон | Название | Основное назначение и описание |
| :--- | :--- | :--- |
| **`127.0.0.1`** | **Loopback / localhost** | **"Адрес для себя"**. Это специальный адрес, который всегда указывает на ваш собственный компьютер. Трафик, отправленный на `127.0.0.1`, никогда не покидает пределы машины. Используется для тестирования и доступа к локально запущенным сервисам (веб-серверы, базы данных). |
| **`0.0.0.0`** | **Unspecified Address** | Это немаршрутизируемый мета-адрес, который используется для обозначения "любого" или "всех" IP-адресов на локальной машине. Когда серверное приложение "слушает" порт на `0.0.0.0`, это означает, что оно будет принимать входящие соединения с любого сетевого интерфейса (например, Wi-Fi, Ethernet) на этом компьютере. Это делает приложение доступным не только с `localhost`, но и из локальной сети или интернета (если нет файрвола). В таблице маршрутизации 0.0.0.0 означает "маршрут по умолчанию" — шлюз(gateway), куда отправляется трафик для всех сетей, не указанных в таблице явно. |
| **`10.0.0.0/8`** | **Частная сеть, Класс A** | Диапазон `10.0.0.0` – `10.255.255.255`. Зарезервирован для использования в крупных корпоративных локальных сетях. Не маршрутизируется в интернете. |
| **`172.16.0.0/12`** | **Частная сеть, Класс B** | Диапазон `172.16.0.0` – `172.31.255.255`. Используется в локальных сетях среднего размера. Не маршрутизируется в интернете. |
| **`192.168.0.0/16`**| **Частная сеть, Класс C** | Диапазон `192.168.0.0` – `192.168.255.255`. Самый распространенный диапазон для домашних и малых офисных сетей (SOHO). Не маршрутизируется в интернете. |
