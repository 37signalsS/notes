# Wireshark и TCPDump: Анализ Сетевого Трафика

## Введение

Этот документ содержит обзор использования Wireshark и TCPDump для анализа сетевого трафика, включая принципы работы, особенности в Linux, использование фильтров и интерпретацию дампов.

## Libpcap: Основа Захвата Пакетов

Захват пакетов в Linux и других Unix-подобных системах осуществляется через библиотеку `libpcap` (Packet Capture library). Эта библиотека была разработана и поддерживается авторами популярной утилиты `tcpdump`.

Многие сетевые инструменты, такие как `iftop` (для статистики трафика на интерфейсе) и `nmap` (сканер портов), используют `libpcap` для захвата и анализа пакетов.

### Как работает libpcap

`libpcap` работает по-разному на разных операционных системах. В Linux она использует семейство сокетов `AF_PACKET`, которое позволяет любому процессу получать доступ к пакетам в "сыром" виде, как они приходят на сетевой интерфейс, а также отправлять полностью сформированные вручную пакеты.

Для работы `libpcap` обычно требуются привилегии `root`. В Linux и BSD можно предоставить эти привилегии обычному пользователю через POSIX capabilities или настройки SELinux/AppArmor. Например, в Fedora Wireshark часто получает необходимые права через контекст SELinux.

### libpcap в Windows

В Windows нет встроенного механизма захвата трафика, как в Unix-подобных системах. Для Wireshark и других инструментов в Windows используется сторонняя библиотека `Npcap` (ранее `WinPcap`), которая является драйвером, работающим через интерфейс NDIS.

## Promiscuous Mode (Неразборчивый Режим)

По умолчанию сетевой интерфейс обрабатывает только пакеты, предназначенные ему (с его MAC-адресом или широковещательные/многоадресные). В Promiscuous Mode интерфейс начинает обрабатывать *все* пакеты, проходящие через него, независимо от их адреса назначения.

Это критически важно для анализа трафика, особенно на мостах или транзитных машинах, где нужно видеть трафик, предназначенный другим хостам.

### Включение Promiscuous Mode

Wireshark может включать Promiscuous Mode автоматически при захвате. Однако `tcpdump` и консольная утилита `tshark` по умолчанию этого не делают. В таких случаях Promiscuous Mode необходимо включать вручную:

```bash
sudo ip link set dev <interface_name> promisc on
```

Пример создания моста и включения Promiscuous Mode:

```bash
sudo ip link add name br0 type bridge
sudo ip link set dev br0 up
sudo ip link set dev br0 promisc on
```

## Инструменты Захвата и Анализа Трафика

### TCPDump

`tcpdump` — это консольная утилита для захвата и анализа сетевого трафика. Она умеет создавать дампы трафика и записывать их в файлы.

#### Установка

`tcpdump` обычно не предустановлен в большинстве дистрибутивов Linux, за исключением специализированных, таких как Kali Linux. Установка выполняется с помощью пакетного менеджера вашей системы:

*   **CentOS/RHEL:**
    ```bash
    sudo yum install tcpdump
    ```
*   **Ubuntu/Debian:**
    ```bash
    sudo apt-get install tcpdump
    ```
*   **Arch Linux:**
    ```bash
    sudo pacman -S tcpdump
    ```
*   **macOS:** `tcpdump` предустановлен.

#### Запуск и основные параметры

Поскольку `tcpdump` взаимодействует напрямую с ядром операционной системы для перехвата пакетов, для его работы требуются привилегии суперпользователя.

*   **Запуск с `sudo`:**
    ```bash
    sudo tcpdump -i <interface_name>
    ```
    Используйте `sudo`, если ваш пользователь имеет соответствующие права.
*   **Переключение на пользователя `root`:**
    ```bash
    sudo -i
    tcpdump -i <interface_name>
    ```
    Этот метод удобен для длительной работы, чтобы не вводить `sudo` постоянно.

*   **Захват и вывод на экран (базовый):**
    ```bash
    sudo tcpdump -i <interface_name>
    ```
    Эта команда будет выводить все проходящие пакеты через указанный интерфейс. Для остановки используйте `Ctrl+C`.

*   **Просмотр доступных сетевых интерфейсов:**
    ```bash
    sudo tcpdump -D
    ```
    Выведет список всех доступных для захвата интерфейсов, включая физические, виртуальные и псевдоинтерфейсы (например, `any` для всех интерфейсов).

*   **Указание конкретного интерфейса:**
    ```bash
    sudo tcpdump -i eth0 # Захват трафика на интерфейсе eth0
    sudo tcpdump -i any  # Захват трафика на всех доступных интерфейсах
    ```
    Используйте ключ `-i` для выбора сетевого интерфейса.

*   **Отключение разрешения имен (DNS):**
    По умолчанию `tcpdump` пытается разрешить IP-адреса в доменные имена и номера портов в названия служб (например, 80 в `http`). Это может замедлять вывод и быть нежелательным.
    *   **Не разрешать IP-адреса:**
        ```bash
        sudo tcpdump -n -i <interface_name>
        ```
        Ключ `-n` предотвращает разрешение IP-адресов в доменные имена.
    *   **Не разрешать IP-адреса и порты:**
        ```bash
        sudo tcpdump -nn -i <interface_name>
        ```
        Ключ `-nn` предотвращает разрешение как IP-адресов, так и номеров портов.

*   **Ограничение количества пакетов:**
    ```bash
    sudo tcpdump -i <interface_name> -c 10
    ```
    Опция `-c` указывает количество пакетов для захвата, после чего `tcpdump` автоматически завершит работу.

*   **Подробный вывод (verbosity):**
    *   **Один уровень подробности:**
        ```bash
        sudo tcpdump -v -i <interface_name>
        ```
        Ключ `-v` увеличивает детализацию вывода (например, TTL, ID, общая длина пакета).
    *   **Два уровня подробности:**
        ```bash
        sudo tcpdump -vv -i <interface_name>
        ```
        Ключ `-vv` предоставляет еще больше деталей (например, опции TCP).
    *   **Максимальный уровень подробности:**
        ```bash
        sudo tcpdump -vvv -i <interface_name>
        ```
        Ключ `-vvv` дает максимальную детализацию.

*   **Вывод содержимого пакета в ASCII и HEX:**
    ```bash
    sudo tcpdump -X -i <interface_name>
    ```
    Ключ `-X` выводит содержимое пакета в шестнадцатеричном (HEX) и ASCII форматах. Это полезно для анализа данных на прикладном уровне.

*   **Захват и сохранение в файл:**
    ```bash
    sudo tcpdump -i <interface_name> -w output.pcap
    ```
    Опция `-w` сохраняет дамп в файл в формате `pcap`. Этот файл содержит "сырые" данные пакетов и может быть открыт в Wireshark или прочитан `tcpdump` с ключом `-r`.

*   **Чтение пакетов из файла:**
    ```bash
    tcpdump -r output.pcap
    tcpdump -r output.pcap -Xnn
    ```
    Ключ `-r` позволяет читать ранее сохраненный файл дампа. Можно комбинировать с другими ключами для форматирования вывода.

#### Фильтрация трафика

`tcpdump` поддерживает мощные фильтры для выборочного захвата трафика. Фильтры могут быть основаны на протоколах, хостах, портах и других параметрах.

*   **Фильтрация по протоколу:**
    *   **ICMP (пинги):**
        ```bash
        sudo tcpdump -i <interface_name> icmp
        ```
        Покажет только ICMP-трафик (например, запросы и ответы `ping`).
    *   **UDP:**
        ```bash
        sudo tcpdump -i <interface_name> udp
        ```
        Покажет только UDP-трафик.
    *   **TCP:**
        ```bash
        sudo tcpdump -i <interface_name> tcp
        ```
        Покажет только TCP-трафик.

*   **Фильтрация по хосту:**
    ```bash
    sudo tcpdump -i <interface_name> host 192.168.1.1
    sudo tcpdump -i <interface_name> host example.com
    ```
    Захватывает трафик, где источником или получателем является указанный IP-адрес или доменное имя.

*   **Фильтрация по порту:**
    ```bash
    sudo tcpdump -i <interface_name> port 80
    sudo tcpdump -i <interface_name> port 53
    ```
    Захватывает трафик, идущий на или с указанного порта.

*   **Комбинирование фильтров (логические операторы):**
    Можно использовать логические операторы `and`, `or`, `not` для создания сложных фильтров. Скобки `()` используются для группировки условий, но их нужно экранировать в командной строке.

    *   **Трафик на определенный хост и порт:**
        ```bash
        sudo tcpdump -i <interface_name> host 192.168.1.1 and port 22
        ```
        Покажет SSH-трафик между вашим хостом и 192.168.1.1.
    *   **Трафик на хост по нескольким портам:**
        ```bash
        sudo tcpdump -i <interface_name> host 192.168.1.254 and \( port 80 or port 22 \)
        ```
        Покажет трафик на хост 192.168.1.254 по портам 80 или 22.
    *   **DNS-трафик (UDP порт 53):**
        ```bash
        sudo tcpdump -i <interface_name> udp and port 53
        ```

#### Анализ TCP-соединений и HTTP/HTTPS

`tcpdump` позволяет наблюдать за этапами установки и завершения TCP-соединений, а также за содержимым незашифрованного трафика.

*   **TCP Handshake (трехстороннее рукопожатие):**
    При установке TCP-соединения происходит обмен пакетами:
    1.  **SYN:** Клиент отправляет серверу пакет с флагом SYN (Synchronize Sequence Numbers).
    2.  **SYN/ACK:** Сервер отвечает пакетом с флагами SYN и ACK (Acknowledgement).
    3.  **ACK:** Клиент подтверждает получение пакета сервера пакетом с флагом ACK.
    `tcpdump` отображает эти флаги (например, `Flags [S]` для SYN, `Flags [S.]` для SYN/ACK, `Flags [.]` для ACK).

*   **Завершение соединения:**
    Соединение обычно завершается обменом пакетами с флагом FIN (Finish) или RST (Reset).

*   **Видимость HTTP-трафика:**
    При использовании `-X` для незашифрованного HTTP-трафика можно увидеть заголовки и даже часть содержимого HTTP-запросов и ответов в ASCII-формате. Например, `GET / HTTP/1.1` или `200 OK`.

*   **HTTPS-трафик:**
    Трафик по HTTPS (порт 443) зашифрован. `tcpdump` покажет обмен зашифрованными пакетами, но их содержимое (данные прикладного уровня) будет нечитаемым. Можно увидеть служебную информацию, такую как обмен сертификатами (Server Name Indication - SNI), но не сами данные.

*   **Пример анализа HTTP-соединения:**
    ```bash
    sudo tcpdump -nn -i <interface_name> -c 3 host <web_server_ip> and port 80
    ```
    Эта команда покажет первые 3 пакета TCP-соединения (SYN, SYN/ACK, ACK) к веб-серверу по порту 80, демонстрируя установку соединения.

*   **Пример анализа HTTP-трафика с содержимым:**
    ```bash
    sudo tcpdump -Xnn -i <interface_name> host <web_server_ip> and port 80
    ```
    Позволяет увидеть заголовки HTTP и данные в открытом виде.

*   **Пример анализа HTTPS-трафика:**
    ```bash
    sudo tcpdump -Xnn -i <interface_name> host <web_server_ip> and port 443
    ```
    Покажет зашифрованный трафик. Содержимое будет нечитаемым, но можно увидеть обмен сертификатами.

*   **Перенаправление вывода в файл (для анализа):**
    Для удобства анализа большого объема трафика можно перенаправить вывод `tcpdump` в текстовый файл:
    ```bash
    sudo tcpdump -nn -i <interface_name> > capture.txt
    ```
    Или использовать ключ `-w` для сохранения сырых пакетов, которые затем можно анализировать с помощью `tcpdump -r` или Wireshark.

*   **Отличие `-w` от перенаправления `>`:**
    *   `>`: Перенаправляет форматированный вывод `tcpdump` (текст, который вы видите на экране) в файл.
    *   `-w`: Записывает "сырые" данные пакетов в бинарный файл `.pcap`, который содержит полную информацию о пакетах и может быть использован другими инструментами анализа трафика (например, Wireshark). Запись через `-w` значительно быстрее и эффективнее для больших объемов данных.

*   **Отображение флагов TCP:**
    `tcpdump` использует сокращения для флагов TCP:
    *   `[S]` - SYN
    *   `[.]` - ACK
    *   `[P]` - PSH (Push)
    *   `[F]` - FIN
    *   `[R]` - RST (Reset)
    *   `[U]` - URG (Urgent)
    *   `[W]` - ECE (ECN-Echo)
    *   `[E]` - CWR (Congestion Window Reduced)

### TShark

`tshark` — это консольная версия Wireshark, которая предоставляет более широкие возможности по сравнению с `tcpdump`, включая более детальный анализ протоколов и сохранение в формате `pcapng`.

*   **Захват и вывод детальной информации:**
    ```bash
    sudo tshark -i <interface_name>
    ```
*   **Захват и сохранение в файл (pcapng):**
    ```bash
    sudo tshark -i <interface_name> -w output.pcapng
    ```

### Wireshark

Wireshark — это графический анализатор сетевого трафика, который умеет как захватывать трафик в реальном времени, так и читать файлы дампов, созданные `tcpdump`, `tshark` или самим Wireshark. Он поддерживает множество форматов дампов.

### Форматы Файлов Дампов

*   **pcap (Packet Capture):** Старый, но широко используемый формат.
*   **pcapng (Packet Capture Next Generation):** Более новый формат, который поддерживает дополнительные метаданные, такие как имя интерфейса, комментарии к пакетам и т.д. `tshark` по умолчанию сохраняет в `pcapng`.

## Фильтры Wireshark

В Wireshark существуют два основных типа фильтров:

1.  **Фильтры захвата (Capture Filters):** Применяются библиотекой `libpcap` *до* того, как пакеты будут записаны в дамп. Они очень полезны на высоконагруженных системах для уменьшения размера дампа. Синтаксис этих фильтров совпадает с синтаксисом `tcpdump`.
    *   Пример: `ip host 192.168.1.1` (захватывает пакеты, где источником или получателем является 192.168.1.1)
    *   Пример: `tcp port 80` (захватывает TCP-трафик на порт 80)

2.  **Фильтры отображения (Display Filters):** Применяются *после* захвата трафика и позволяют фильтровать уже записанные пакеты для удобства анализа. Они гораздо более гибкие и мощные, чем фильтры захвата, и имеют свой собственный синтаксис.
    *   Пример: `ip.addr == 192.168.1.1`
    *   Пример: `tcp.port == 80`
    *   Пример: `vlan.id == 20`
    *   Пример: `frame.comment` (для отображения пакетов с комментариями)

## Интерпретация Дампов в Wireshark

### Структура Пакета

Wireshark отображает пакеты в многоуровневом виде, соответствующем модели OSI:

*   **Frame:** Информация о физическом уровне (размер кадра, время захвата, интерфейс).
*   **Ethernet:** Заголовок канального уровня (MAC-адреса источника и назначения, EtherType).
*   **VLAN:** Если присутствует, информация о VLAN (VLAN ID).
*   **IP (IPv4/IPv6):** Заголовок сетевого уровня (IP-адреса источника и назначения, протокол следующего уровня).
*   **TCP/UDP:** Заголовок транспортного уровня (порты источника и назначения, флаги TCP, контрольные суммы).
*   **Application Layer Protocol:** Протокол прикладного уровня (HTTP, SSH, DNS и т.д.).

### Полезные Возможности Wireshark

*   **Name Resolution:** Разрешение MAC-адресов в имена производителей (OUI Lookup) и IP-адресов в DNS-имена. Разрешение физических адресов (MAC) работает оффлайн. Разрешение DNS требует сетевых запросов и может замедлять анализ.
*   **Follow TCP Stream:** Позволяет просмотреть весь диалог TCP-соединения в текстовом виде, что удобно для анализа протоколов прикладного уровня (HTTP, SSH).
*   **Packet Comments:** Возможность добавлять произвольные комментарии к отдельным пакетам в дампе (сохраняется в `pcapng`).
*   **Coloring Rules:** Настройка правил раскраски пакетов для визуального выделения определенных типов трафика или пакетов с комментариями.
*   **Расшифровка TLS/SSL трафика:** Wireshark может расшифровывать TLS-трафик, если предоставлен приватный ключ сервера. Это полезно для отладки и демонстраций.
    *   `Preferences -> Protocols -> TLS -> (Pre)-Master-Secret log filename` или `RSA keys list`.
*   **Генерация правил файрвола:** Wireshark имеет устаревший инструмент для генерации правил `iptables` или `pf` на основе захваченного трафика.
*   **Анализ туннельного трафика:** Wireshark может разбирать туннельные протоколы (например, GRE), показывая как внешний, так и вложенный трафик.

### Проблемные Пакеты

*   **Connection Refused (RST/ACK):** В TCP-соединении `RST/ACK` вместо `SYN/ACK` в ответ на `SYN` указывает на то, что соединение было отклонено (например, на порту никто не слушает).
*   **Битые контрольные суммы:** Могут указывать на реальные проблемы с пакетами или на то, что на сетевой карте включен оффлоад подсчета контрольных сумм.

## Пример анализа трафика в Wireshark

Хотя `tcpdump` и `tshark` мощные инструменты, графический интерфейс Wireshark делает анализ трафика более наглядным и интерактивным.

**Основной рабочий процесс:**

1.  **Запуск и выбор интерфейса:** После запуска Wireshark предлагает выбрать сетевой интерфейс для захвата трафика (например, `eth0`, `wlan0`). Сразу после выбора начинается захват пакетов в реальном времени.

2.  **Применение фильтров отображения:** Чтобы отсеять лишний "шум" и сфокусироваться на интересующем протоколе, используется строка фильтров в верхней части окна. Синтаксис отличается от фильтров `tcpdump`.
    *   `icmp`: Показывает только пакеты протокола ICMP, например, от утилиты `ping`.
    *   `ssh`: Отображает трафик, связанный с протоколом SSH (по умолчанию на порту 22).
    *   `tcp.port == 80`: Показывает HTTP трафик.
    *   `ip.addr == 1.1.1.1`: Показывает весь трафик, где источником или получателем является указанный IP-адрес.

3.  **Анализ пакетов:** Интерфейс разделен на три основные части:
    *   **Список пакетов (Packet List):** Верхняя панель, где отображается пронумерованный список захваченных пакетов с основной информацией (время, источник, получатель, протокол).
    *   **Детали пакета (Packet Details):** Средняя панель, где выбранный пакет представлен в виде иерархической структуры в соответствии с моделью OSI (Frame, Ethernet, IP, TCP, etc.). Здесь можно раскрыть каждый уровень и посмотреть значения всех полей заголовков (например, IP-адреса, TCP-порты, флаги).
    *   **Байты пакета (Packet Bytes):** Нижняя панель, где показано сырое содержимое пакета в HEX и ASCII форматах.

**Пример с ICMP (`ping`):**

Применив фильтр `icmp`, можно увидеть `Echo (ping) request` и `Echo (ping) reply`. Выбрав пакет `request`, в деталях можно увидеть его тип (Type: 8), контрольную сумму и IP-адреса. В ответном пакете `reply` тип будет (Type: 0), а IP-адреса источника и назначения поменяются местами. Это позволяет наглядно убедиться, что запросы и ответы проходят корректно.

Таким образом, Wireshark позволяет в интерактивном режиме "препарировать" сетевые взаимодействия, что крайне полезно для диагностики проблем и изучения работы протоколов.

## Заключение

Wireshark и TCPDump являются мощными инструментами для диагностики сетевых проблем, анализа протоколов и понимания работы сети на низком уровне. Эффективное использование фильтров и знание особенностей интерпретации дампов значительно повышают продуктивность при работе с сетевым трафиком.
