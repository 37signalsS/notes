# Альтернативы ping: диагностика доступности без ICMP

## Определения

**Пинг без ICMP (TCP-пинг)** — метод проверки доступности удалённого хоста без использования протокола **ICMP (Internet Control Message Protocol — протокол межсетевых управляющих сообщений)**. Вместо стандартных пакетов Echo Request/Reply, которые отправляет утилита `ping`, используются пакеты **TCP (Transmission Control Protocol — протокол управления передачей)** или **UDP (User Datagram Protocol — протокол пользовательских датаграмм)** на определённые порты.

Этот подход необходим, когда ICMP-трафик блокируется сетевыми устройствами (брандмауэры, маршрутизаторы), что делает невозможным использование традиционного `ping`. Подробности об ICMP и работе `ping` — в заметке **[ping](../../Linux/Diagnostics/Networking/ping.md)**.

## Основные концепции

### Принцип работы TCP-пинга

Принцип заключается в имитации установления соединения с сервисом на удальном хосте. Отправляется TCP-пакет (чаще всего с флагом SYN) на известный порт (например, 80 для **HTTP (HyperText Transfer Protocol)** или 22 для **SSH (Secure Shell)**).

### Возможные исходы

| Ответ хоста | Значение | Доступность |
| :--- | :--- | :--- |
| **SYN/ACK** | Порт открыт, сервис активен | Хост доступен |
| **RST (Reset)** | Порт закрыт, сервис не запущен | Хост доступен |
| **Нет ответа** | Хост выключен или порт заблокирован | Недоступен / Блокировка |

**Ключевой принцип:** любой ответ от хоста (включая `RST`) подтверждает его сетевую доступность. Отсутствие ответа — единственный индикатор недоступности или полной блокировки трафика.

### Когда использовать TCP-пинг

- **ICMP заблокирован** файрволом — типичная ситуация в production-средах и облаках.
- **Нужна проверка конкретного сервиса** — `ping` подтверждает лишь доступность хоста, но не работоспособность приложения.
- **Мониторинг извне** — проверки должны использовать те же протоколы, что и реальные пользователи.

## Практические сценарии

### 1. Встроенные возможности Bash (/dev/tcp)

Самый быстрый способ проверить доступность порта без установки дополнительных утилит. Работает во многих современных Linux-дистрибутивах (зависит от сборки Bash).

```bash
# Проверка доступности порта 80 на google.com
(timeout 2 bash -c "</dev/tcp/google.com/80") &>/dev/null && echo "Open" || echo "Closed/Timeout"
```

### 2. Проверка TCP-порта с помощью nc, nmap, telnet

Эти утилиты позволяют отправить запрос на TCP-порт, чтобы проверить, ответит ли хост.

**Использование `nc` (netcat):**
Флаг `-z` (zero I/O) в сочетании с `-v` (verbose) позволяет быстро проверить порт.

```bash
# Проверка доступности порта 22 (SSH)
nc -zv 192.168.0.1 22
# → Connection to 192.168.0.1 22 port [tcp/ssh] succeeded!
```
*Примечание: в современных дистрибутивах флаг `-z` может отсутствовать в версии `ncat` или OpenBSD `nc`, используйте `nmap` или `nping`.*

**Использование `nmap` и `nping`:**
`nping` (часть пакета `nmap`) — один из самых мощных инструментов для кастомных проверок.

```bash
# TCP-пинг на порт 443 с помощью nping
sudo nping --tcp -p 443 8.8.8.8
# → RCVD (0.0125s) ICMP [172.217.16.14 > 192.168.1.10 ... TCP SYN/ACK]

# Быстрая проверка порта через nmap
nmap -p 22 192.168.0.1
```

**Использование `telnet`:**
Пытается установить полноценную сессию. Для выхода нажмите `Ctrl+]` и введите `quit`.

```bash
# Проверка порта 80
telnet example.com 80
# → Connected to example.com.
```

### 3. Проверка веб-сервисов с помощью curl или wget

Если на хосте работает веб-сервис, можно проверить его через **HTTP/HTTPS (HyperText Transfer Protocol Secure)**.

**Использование `curl`:**
Получение заголовков подтверждает работоспособность веб-сервера. Подробнее см. **[curl](../../Linux/Diagnostics/Networking/curl_network_diagnostics.md)**.

```bash
# Запрос заголовков (-I) в тихом режиме (-s)
curl -Is http://example.com | head -n 1
# → HTTP/1.1 200 OK
```

### 4. Расширенная диагностика с помощью hping3 и mtr

**`hping3`** позволяет точно контролировать флаги и параметры пакетов, что полезно для обхода сложных правил фильтрации.

```bash
# Отправка TCP SYN пакетов на порт 80
hping3 -S -p 80 example.com
# → len=46 ip=93.184.216.34 flags=SA seq=0 ttl=56 id=0 win=64240 rtt=10.5 ms
```

**`mtr` (My Traceroute)** в режиме TCP:
Позволяет увидеть, на каком именно хопе блокируется TCP-трафик.

```bash
# Трассировка по TCP порту 443
mtr -T -P 443 8.8.8.8
```

### 5. Визуализация и мониторинг (gping)

**`gping`** строит графики RTT в реальном времени, что удобно для выявления кратковременных всплесков задержек.

```bash
# Визуальный TCP-пинг
gping --tcp -p 443 google.com
```

### 6. Специализированные утилиты TCP-пинга

**`tcping` / `tcpping`:**
Имитируют поведение `ping`, используя TCP-соединения для измерения **RTT (Round-Trip Time — время приёма-передачи)**.

```bash
# TCP-пинг на порт 80
tcping example.com 80
# → Connected to example.com:80, time=12.45ms
```

**`psping` (Sysinternals):**
Поддерживает TCP/HTTP-пинг и измерение задержек (популярно в Windows).

## Дополнительная информация

### Сравнительная таблица утилит

| Утилита | Протокол | Назначение | Особенности |
| :--- | :--- | :--- | :--- |
| `bash /dev/tcp` | TCP | Моментальная проверка | Не требует установки стороннего ПО. |
| `nc` | TCP/UDP | Универсальный «швейцарский нож» | Быстрая проверка одного порта. |
| `nping` | TCP/UDP/ICMP/ARP | Профессиональная диагностика | Часть nmap, поддерживает кастомные флаги. |
| `nmap` | TCP/UDP | Сканирование сетей | Глубокий анализ портов и сервисов. |
| `curl` | HTTP/HTTPS | Проверка веб-сервисов | Проверяет прикладной уровень (L7). |
| `hping3` | TCP/UDP/ICMP | Тестирование файрволов | Позволяет имитировать атаки и обходить правила. |
| `gping` | TCP/ICMP | Визуализация | TUI-графики задержек. |
| `mtr` | TCP/UDP/ICMP | Трассировка | Выявление проблем на конкретном узле маршрута. |

### Практические рекомендации

- **Минимализм:** Используйте `/dev/tcp` в скриптах, где нельзя гарантировать наличие `nc`.
- **Единичная проверка:** `nc -zv <host> <port>` — самый быстрый способ.
- **Мониторинг веб-сервиса:** `curl -Is http://<host>` — проверяет не только сеть, но и ответ приложения.
- **Измерение задержек (RTT):** `tcping` или `gping --tcp` — даёт статистику, аналогичную `ping`.
- **Обход файрвола и тесты:** `hping3` или `nping` — позволяют имитировать разные типы трафика.

### Безопасность

- `hping3`, `nping` и `nmap` могут быть расценены системами обнаружения вторжений (IDS/IPS) как попытка атаки или сканирования.
- Для продвинутого анализа и написания собственных инструментов диагностики рекомендуется использовать библиотеку **Scapy** (Python).
