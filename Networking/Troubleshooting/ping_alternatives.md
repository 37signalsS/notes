# Альтернативы ping: диагностика доступности без ICMP

## Определения

**Пинг без ICMP (TCP-пинг)** — метод проверки доступности удалённого хоста без использования ICMP-пакетов (Echo Request/Reply), которые стандартная утилита `ping` отправляет по умолчанию. Вместо этого отправляются TCP- или UDP-пакеты на определённые порты для получения ответа от хоста.

Этот подход необходим, когда ICMP-трафик блокируется сетевыми устройствами (брандмауэры, маршрутизаторы), что делает невозможным использование традиционного `ping`. Подробности об ICMP и работе `ping` — в **[ping](../../Linux/Diagnostics/Networking/ping.md)**.

## Основные концепции

### Принцип работы TCP-пинга

Принцип работы заключается в имитации установления TCP-соединения с сервисом на удалённом хосте. Отправляется TCP-пакет (чаще всего с флагом SYN) на известный порт (например, 80 для HTTP или 22 для SSH).

### Возможные исходы

| Ответ хоста | Значение | Доступность |
| :--- | :--- | :--- |
| **SYN/ACK** | Порт открыт, сервис активен | Хост доступен |
| **RST (Reset)** | Порт закрыт, сервис не запущен | Хост доступен |
| **Нет ответа** | Хост выключен, недоступен, или порт заблокирован | Недоступен / блокировка |

**Ключевой принцип:** любой ответ от хоста (включая `RST`) подтверждает его доступность. Отсутствие ответа — единственный индикатор недоступности или полной блокировки трафика.

### Когда использовать TCP-пинг

- **ICMP заблокирован** файрволом — типичная ситуация в production-средах и облаках
- **Нужна проверка конкретного сервиса** — ping подтверждает лишь доступность хоста, но не работоспособность приложения
- **Мониторинг извне** — внешние проверки доступности должны использовать те же протоколы, что и реальные пользователи

## Практические сценарии

### 1. Проверка TCP-порта с помощью `nc`, `nmap`, `telnet`

Эти утилиты позволяют отправить простой запрос на TCP-порт, чтобы проверить, ответит ли хост.

**Использование `nc` (netcat):**
Утилита `nc` — это гибкий инструмент для работы с TCP/UDP. Флаг `-z` (zero I/O) в сочетании с `-v` (verbose) позволяет быстро проверить порт.

```bash
# Проверка доступности порта 22 (SSH) на 192.168.0.1
nc -zv 192.168.0.1 22
# Connection to 192.168.0.1 22 port [tcp/ssh] succeeded!
```

**Использование `nmap`:**
`nmap` — мощный сканер сетей, который также можно использовать для простой проверки порта. Подробнее см. [**`nmap`**](../../Linux/Diagnostics/Networking/nmap.md).

```bash
# Быстрая проверка порта с помощью nmap
nmap -p 22 192.168.0.1
# PORT   STATE SERVICE
# 22/tcp open  ssh
```

**Использование `telnet`:**
`telnet` пытается установить полноценную сессию, что может быть полезно для диагностики.

```bash
# Проверка доступности порта 80 на example.com
# При успешном подключении появится пустой экран. Для выхода нажмите Ctrl+] и введите quit.
telnet example.com 80
```

> **Примечание:** `telnet` считается устаревшим и небезопасным протоколом. Для проверки портов предпочтительнее использовать `nc` или `nmap`.

### 2. Проверка веб-сервисов с помощью `curl` или `wget`

Если на хосте работает HTTP/HTTPS сервис, можно проверить его доступность, отправив HTTP-запрос.

**Использование `curl`:**
`curl` позволяет получить заголовки ответа, что подтверждает работоспособность веб-сервера.

```bash
# Запрос заголовков (-I) и статуса (-s) с выводом первой строки ответа
curl -Is http://example.com | head -n 1
# HTTP/1.1 200 OK
```

**Использование `wget`:**
Режим "паука" (`--spider`) в `wget` проверяет доступность URL без скачивания контента.

```bash
# Проверка доступности URL без сохранения файла
wget --spider http://example.com
```

### 3. Расширенная проверка с помощью `hping3`

`hping3` — это инструмент для сборки и отправки кастомных пакетов. Он позволяет точно контролировать флаги, порты и другие параметры, что полезно для сложной диагностики.

```bash
# Отправка TCP SYN пакета на порт 80 хоста example.com
hping3 -S -p 80 example.com
```

### 4. Массовая проверка с помощью `fping`

`fping` предназначен для быстрой параллельной проверки множества хостов. Хотя по умолчанию используется ICMP, некоторые версии поддерживают и TCP-пинг.

```bash
# Пример команды для fping с поддержкой TCP-пинга
# fping -p 80 -t 500 -a <хост1> <хост2> ...
# Примечание: функционал TCP-пинга зависит от версии и сборки fping.
```

### 5. Специализированные утилиты TCP-пинга

**`tcpping` / `tcping` (от iputils):**
Специализированная утилита, имитирующая поведение `ping`, но использующая TCP-соединения.

```bash
# Отправка TCP SYN на порт 80 с интервалом 1 секунду
tcpping -p 80 example.com
# Или альтернатива (утилита tcping из пакета tcping)
tcping example.com 80
```

**`psping` (от Sysinternals для Windows, есть Linux-версии):**
Поддерживает TCP-пинг, HTTP-пинг, измерение задержек.

```bash
# TCP-пинг с указанием количества запросов
psping -n 4 example.com:80
```

### Практические рекомендации по выбору

- **Единичная быстрая проверка:** `nc -zv <host> <port>`
- **Мониторинг доступности сервиса:** `curl -Is http://<host> | head -n 1` (HTTP-статус)
- **Диагностика с измерением RTT:** `tcpping -p <port> <host>`
- **Проверка при подозрении на блокировку файрволом:** `hping3` с разными флагами (`-S`, `-A`, `-F`)
- **Массовая проверка ICMP:** `fping -a <список_хостов>`

### Безопасность

- `telnet` считается устаревшим и небезопасным протоколом — для проверки портов предпочтительнее `nc` или `nmap`
- `hping3` и `nmap` могут быть расценены IDS/IPS как сканирование — используйте только в рамках своих полномочий
