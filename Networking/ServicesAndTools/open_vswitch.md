# Open vSwitch (OVS)

## Определения

**Open vSwitch (OVS)** — это многофункциональный программный коммутатор с открытым исходным кодом, предназначенный для использования в виртуализированных средах. В отличие от стандартного Linux Bridge, OVS спроектирован для работы в динамических средах с высокой степенью автоматизации и поддержкой программно-определяемых сетей (SDN).

Проект поддерживает стандартные интерфейсы управления и протоколы, такие как OpenFlow, NetFlow, sFlow, LACP и 802.1Q VLAN.

## Основные концепции

### Архитектура OVS

OVS состоит из трёх основных компонентов:

1.  **ovs-vswitchd**: Демон, работающий в пространстве пользователя (userspace). Он реализует логику коммутации, управляет таблицами потоков и взаимодействует с ядром и контроллерами OpenFlow.
2.  **ovsdb-server**: Легковесная база данных, хранящая конфигурацию коммутатора (мосты, порты, интерфейсы, настройки VLAN).
3.  **openvswitch.ko (Kernel Module)**: Модуль ядра (datapath), отвечающий за быструю пересылку пакетов. Если пакет соответствует известному правилу в кеше ядра, он пересылается немедленно. Если нет — пакет передаётся в `ovs-vswitchd` для принятия решения.

### Компоненты конфигурации

-   **Bridge (Мост)**: Виртуальный коммутатор L2.
-   **Port (Порт)**: Точка подключения к мосту. Может быть физическим интерфейсом, виртуальным (veth, tap) или туннелем (GRE, VXLAN).
-   **Interface (Интерфейс)**: Программный объект внутри порта. Обычно порт и интерфейс имеют соотношение 1:1.
-   **Flow (Поток)**: Правило в таблице коммутации, определяющее, что делать с пакетом на основе его заголовков (L2-L4).

## Практические сценарии

### Основные команды управления

Для управления конфигурацией используется утилита `ovs-vsctl`.

```bash
# Просмотр текущей конфигурации
ovs-vsctl show

# Создание моста
ovs-vsctl add-br br0

# Добавление физического интерфейса в мост
ovs-vsctl add-port br0 eth0

# Удаление порта
ovs-vsctl del-port br0 eth0
```

### Настройка VLAN

OVS позволяет гибко управлять тегированием на портах.

```bash
# Добавление порта с тегом (Access port)
ovs-vsctl add-port br0 vnet0 tag=10

# Настройка транкового порта (разрешить несколько VLAN)
ovs-vsctl set port eth0 trunks=10,20,30

# Превращение существующего порта в access
ovs-vsctl set port vnet1 tag=20
```

### Работа с потоками (OpenFlow)

Для низкоуровневого управления потоками используется `ovs-ofctl`.

```bash
# Просмотр установленных потоков
ovs-ofctl dump-flows br0

# Добавление правила: сбросить весь трафик с входящего порта 1
ovs-ofctl add-flow br0 "in_port=1, action=drop"

# Пересылка трафика с порта 1 на порт 2
ovs-ofctl add-flow br0 "priority=100, in_port=1, actions=output:2"
```

### Интеграция с DPDK

Для сред с высокой нагрузкой OVS может использовать DPDK для обработки трафика полностью в userspace, минуя ядро Linux.

```bash
# Инициализация OVS с поддержкой DPDK (пример)
ovs-vsctl --no-wait set Open_vSwitch . other_config:dpdk-init=true
ovs-vsctl add-br br-dpdk -- set bridge br-dpdk datapath_type=netdev
```
Подробности см. в **[Практические сценарии DPDK и SR-IOV](../Concepts/dpdk/scenarios.md)**.

## Дополнительная информация

### Сравнение с Linux Bridge

| Характеристика | Linux Bridge | Open vSwitch |
| :--- | :--- | :--- |
| **Сложность** | Низкая (часть ядра) | Выше (требует демонов) |
| **Управление** | `ip link`, `bridge` | `ovs-vsctl`, `ovsdb` |
| **Поддержка SDN** | Нет | Да (OpenFlow) |
| **Туннелирование** | Ограничено | Богатая поддержка (VXLAN, Geneve) |
| **Производительность** | Хорошая для простых задач | Высокая (особенно с DPDK) |
