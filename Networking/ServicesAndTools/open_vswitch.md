# Open vSwitch (OVS) и OVN — Флагманское руководство

**Open vSwitch (OVS)** — это высокопроизводительный многоуровневый программный коммутатор с открытым исходным кодом, оптимизированный для работы в виртуализированных и динамических средах. В отличие от стандартного Linux Bridge, OVS спроектирован для поддержки программно-определяемых сетей (SDN) и расширенных протоколов управления.

## 1. Архитектура и основные концепции

Система OVS разделена на три функциональных блока для обеспечения гибкости и производительности:

1.  **ovs-vswitchd**: Основной демон (userspace). Управляет пересылкой пакетов, обрабатывает логику OpenFlow, управляет таблицами потоков и взаимодействует с внешними контроллерами. Это «мозг» системы.
2.  **ovsdb-server**: База данных конфигурации (JSON-RPC). Хранит информацию о мостах, портах, очередях QoS и настройках туннелей. Обладает транзакционностью и сохраняет состояние после перезагрузки.
3.  **Forwarding Plane (Datapath)**:
    *   **Kernel Datapath (openvswitch.ko)**: Стандартный режим. Первые пакеты потока отправляются в userspace (`ovs-vswitchd`) для принятия решения, после чего в ядро устанавливается «быстрое» правило для последующих пакетов.
    *   **Userspace Datapath (OVS-DPDK)**: Использует библиотеку DPDK для обработки пакетов полностью в обход ядра, исключая накладные расходы на прерывания и копирование данных.

### Ключевые сущности
*   **Bridge (Мост)**: Виртуальный коммутатор. Один экземпляр OVS может поддерживать множество независимых мостов.
*   **Port (Порт)**: Точка входа/выхода трафика. Типы:
    *   `Physical`: Привязка к физическому NIC.
    *   `Internal`: Виртуальный интерфейс для связи с хостом (например, для назначения IP мосту).
    *   `Tunnel`: Инкапсуляция (VXLAN, GRE, Geneve).
    *   `Patch`: Сверхбыстрое соединение двух мостов внутри одного экземпляра OVS (patch ports).
*   **Flow (Поток)**: Набор правил в таблице OpenFlow. Состоит из условий сопоставления (L2-L4 заголовки) и действий (отправить в порт, изменить заголовок, отбросить).

## 2. OVN (Open Virtual Network): Сетевая виртуализация

OVN — это система управления сетевой виртуализацией, построенная на базе OVS. Она обеспечивает абстракцию логических сетей, отделяя логическую топологию от физической инфраструктуры.

### Архитектура OVN
- **Northbound DB (NB)**: Описывает логическую топологию (логические мосты, роутеры, ACL). Управляется через `ovn-nbctl`.
- **Southbound DB (SB)**: Связывает логические сущности с физическими хостами (шасси). Хранит логические потоки (`lflow`). Управляется через `ovn-sbctl`.
- **ovn-northd**: Транслирует логическую конфигурацию из NB в SB.
- **ovn-controller**: Агент на каждом гипервизоре, который транслирует логические правила SB в конкретные потоки OpenFlow для локального OVS.

### Практика: Управление в OVN
```bash
# Создание логического коммутатора sw0 (NB)
ovn-nbctl ls-add sw0

# Добавление логического порта lsp1 и привязка адреса
ovn-nbctl lsp-add sw0 lsp1
ovn-nbctl lsp-set-addresses lsp1 "00:00:00:00:00:01 192.168.1.10"

# Просмотр логических потоков (SB)
# Позволяет увидеть путь пакета до его трансляции в конкретный OpenFlow
ovn-sbctl lflow-list sw0
```

## 3. OVS-DPDK: Экстремальная производительность

OVS-DPDK используется в сценариях, где ядро Linux становится «бутылочным горлышком» (10G/25G/100G каналы).

### Ключевые механизмы
- **HugePages**: Использование страниц памяти по 2 МБ или 1 ГБ для минимизации промахов TLB.
- **PMD (Poll Mode Drivers)**: Выделенные ядра CPU постоянно опрашивают сетевую карту (Poling), исключая прерывания и контекстные переключения.
- **Zero-copy**: Прямое чтение из памяти NIC в буферы userspace.

### Настройка OVS-DPDK
```bash
# 1. Выделение HugePages (пример: 1024 страницы по 2МБ)
echo 1024 > /sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages

# 2. Инициализация DPDK в OVS
ovs-vsctl --no-wait set Open_vSwitch . other_config:dpdk-init=true
ovs-vsctl --no-wait set Open_vSwitch . other_config:dpdk-socket-mem="1024,1024"

# 3. Создание моста и порта DPDK
ovs-vsctl add-br br-dpdk -- set bridge br-dpdk datapath_type=netdev
ovs-vsctl add-port br-dpdk dpdk0 -- set Interface dpdk0 type=dpdk options:dpdk-devargs=0000:04:00.0
```

## 4. Практические сценарии управления

### Конфигурация мостов и портов (ovs-vsctl)
```bash
# Просмотр всей иерархии (мосты, порты, интерфейсы)
ovs-vsctl show

# Создание моста и добавление физического интерфейса
ovs-vsctl add-br br-int
ovs-vsctl add-port br-int eth0

# Настройка внутреннего интерфейса для управления хостом
ovs-vsctl add-port br-int mgmt0 -- set Interface mgmt0 type=internal
ip addr add 192.168.1.10/24 dev mgmt0
ip link set mgmt0 up
```

### Работа с VLAN (802.1Q)
```bash
# Порт в режиме Access (VLAN 10)
ovs-vsctl add-port br-int vnet0 tag=10

# Порт в режиме Trunk (разрешить VLAN 10, 20, 30)
ovs-vsctl set port eth0 trunks=10,20,30

# Динамическое изменение тега на лету
ovs-vsctl set port vnet0 tag=20
```

### Настройка туннелей (VXLAN)
```bash
# Создание VXLAN-порта к удаленному гипервизору (VTEP)
ovs-vsctl add-port br-int vxlan0 -- set interface vxlan0 type=vxlan options:remote_ip=172.16.1.5
```

## 5. Диагностика и отладка (Экспертный уровень)

### Глубокая трассировка: ofproto/trace
Команда эмулирует прохождение пакета через конвейер таблиц OpenFlow. Это критически важно для отладки OVN или Antrea.
```bash
ovs-appctl ofproto/trace br-int in_port=1,dl_src=52:54:00:11:22:33,dl_dst=52:54:00:44:55:66
```
**Вывод показывает:**
- **Flow/Rule**: Конкретное правило, сработавшее в каждой таблице OpenFlow.
- **OpenFlow actions**: Логические действия (resubmit в другую таблицу, изменение полей).
- **Datapath actions**: Итоговое действие, которое будет передано в ядро (например, `pop_vlan,output:3`).

### Анализ путей данных: dpif/show
Позволяет увидеть статистику на уровне взаимодействия демона с datapath (ядром или DPDK).
```bash
# Показать статистику интерфейсов и хитов кэша datapath
ovs-appctl dpif/show
```

### Другие полезные команды
```bash
# Просмотр таблицы MAC-адресов (FDB)
ovs-appctl fdb/show br-int

# Просмотр установленных правил OpenFlow
ovs-ofctl dump-flows br-int

# Просмотр реальных потоков в ядре (Datapath flows)
ovs-dpctl dump-flows
```

## 6. Полезные советы и хитрости

- **MTU и туннели**: При использовании VXLAN/Geneve (особенно в OVN) всегда уменьшайте MTU на виртуальных интерфейсах ВМ (до **1450**), чтобы избежать фрагментации из-за 50-байтового оверхеда.
- **Patch Ports**: Используйте `type=patch` для соединения двух мостов внутри одного OVS. Это работает быстрее, чем создание veth-пар.
- **Мониторинг БД**: Команда `ovsdb-client monitor Open_vSwitch Bridge` позволяет в реальном времени следить за изменениями в конфигурации коммутатора.

## Сравнение с Linux Bridge

| Характеристика | Linux Bridge | Open vSwitch |
| :--- | :--- | :--- |
| **Реализация** | Целиком в ядре Linux | Гибридная (Kernel + Userspace) |
| **Управление** | `ip link`, `bridge` | `ovs-vsctl`, `ovs-ofctl`, `ovs-appctl` |
| **Поддержка SDN** | Нет | Полная (OpenFlow, OVN) |
| **Туннелирование** | Через внешние устройства ОС | Встроенное в логику портов |
| **Производительность** | Высокая (kernel-only) | Экстремальная (с DPDK) |
| **Сложность** | Низкая | Высокая |
