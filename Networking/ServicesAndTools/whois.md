# whois — протокол и утилита

## Определения

**whois** — сетевой протокол прикладного уровня, базирующийся на протоколе TCP (порт **43**), и одноимённая утилита командной строки. Используется для получения регистрационных данных о владельцах доменных имён, IP-адресов и автономных систем (AS).

**RDAP (Registration Data Access Protocol)** — современный преемник WHOIS (RFC 7480-7485). В отличие от классического WHOIS, RDAP использует HTTP(S), возвращает структурированные данные в формате JSON и поддерживает механизмы аутентификации и контроля доступа.

## Основные концепции

### Типы информации в whois

Данные предоставляются региональными интернет-регистраторами (RIR) и аккредитованными регистраторами доменов.

| Поле | Описание |
| :--- | :--- |
| `Domain Name` | Полное доменное имя (FQDN) |
| `Registrar` | Организация-регистратор, через которую куплен домен |
| `Creation Date` | Дата первой регистрации домена |
| `Updated Date` | Дата последнего изменения записи |
| `Registry Expiry Date` | Дата окончания срока делегирования |
| `Name Server` | Список авторитативных DNS-серверов |
| `Status` | Текущий статус домена (например, `clientTransferProhibited`) |
| `DNSSEC` | Статус безопасности (подписана ли зона) |
| `Registrant` | Данные владельца (часто скрыты приватностью или GDPR) |

### Механизм работы (Рекурсия)

Утилита `whois` обычно работает по следующему алгоритму:
1. Опрашивается глобальный сервер (например, `whois.iana.org`).
2. Получается ссылка на авторитативный WHOIS-сервер конкретной зоны или регистратора.
3. Утилита автоматически перенаправляет запрос к нужному серверу (рекурсивный поиск).

### Ограничения и проблемы

- **WHOIS Privacy:** Скрытие данных владельца через посредников (Privacy Protection).
- **GDPR:** Регламент ЕС, значительно ограничивающий публикацию персональных данных физических лиц.
- **Rate Limiting:** Регистраторы жестко ограничивают количество запросов в минуту с одного IP.
- **Отсутствие стандарта:** Ответы WHOIS — это неструктурированный текст, формат которого зависит от регистратора. Для автоматизации рекомендуется использовать RDAP.

## Практические сценарии

### Базовая диагностика

```bash
# Получение информации о домене
whois example.com

# Получение информации об IP-адресе (определяет RIR)
whois 8.8.8.8

# Запрос к конкретному серверу (минуя автоопределение)
whois -h whois.ripe.net 1.1.1.1
```

### Проверка подозрительного домена

**Сценарий:** Анализ «свежего» домена на признаки фишинга.

```bash
whois vicsoftware.net
```

**Результат анализа:**
- `Creation Date: 2025-01-06` — домен создан недавно, что является признаком риска для финансовых сервисов.
- `Registrar WHOIS Server: whois.namesilo.com` — регистратор в офшорной зоне.
- `Registrant State: PA` — не соответствует заявленной локации сервиса.

### Использование RDAP (современный подход)

Если стандартный `whois` возвращает неполные данные или требуется JSON для скриптов:

```bash
# Запрос через curl к RDAP-серверу (пример для домена .com)
curl -s https://rdap.verisign.com/com/v1/domain/example.com | jq
```

### Утилита mkpasswd

В многих дистрибутивах Linux (например, Debian/Ubuntu) утилита `mkpasswd` (генератор хешей паролей) поставляется в составе пакета `whois`.

```bash
# Генерация хеша пароля yescrypt (современный стандарт Linux)
mkpasswd -m yescrypt "my_password"
# → $y$j9T$v9M...
```

## Дополнительная информация

### Региональные регистраторы (RIR)

При проверке IP-адресов запрос направляется в одну из пяти организаций:

| RIR | Регион | Сервер |
| :--- | :--- | :--- |
| **RIPE NCC** | Европа, Ближний Восток, Центральная Азия | `whois.ripe.net` |
| **ARIN** | Северная Америка | `whois.arin.net` |
| **APNIC** | Азиатско-Тихоокеанский регион | `whois.apnic.net` |
| **LACNIC** | Латинская Америка и Карибский бассейн | `whois.lacnic.net` |
| **AFRINIC** | Африка | `whois.afrinic.net` |
