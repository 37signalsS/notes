# Обзор HTTP-клиентов для Linux

HTTP-клиенты командной строки — это незаменимые инструменты для любого DevOps-инженера. Они используются для широкого круга задач: от простого скачивания файлов до сложного тестирования API и автоматизации в скриптах. Выбор клиента зависит от конкретной цели: передача файлов, просмотр сайтов или взаимодействие с API. Важно отметить, что большинство рассматриваемых инструментов кроссплатформенны, но в Linux их использование зачастую проще благодаря наличию в репозиториях.

Основные клиенты, используемые в Linux:

*   **Wget:** Классическая утилита для скачивания файлов и рекурсивной загрузки сайтов.
*   **cURL:** Универсальный "швейцарский нож" для передачи данных по множеству протоколов, чрезвычайно популярен в скриптах и для работы с API.
*   **HTTPie:** Современный, дружелюбный к пользователю клиент, созданный для удобной работы с API.

## Инструменты для тестирования

Перед тем как рассматривать клиенты, стоит упомянуть сервисы, которые очень полезны для отладки и тестирования HTTP-запросов:

*   **[badssl.com](https://badssl.com):** Предоставляет различные варианты "плохих" HTTPS-сайтов (с просроченными, самоподписанными сертификатами, устаревшими шифрами и т.д.). Идеально для тестирования того, как клиент обрабатывает ошибки сертификатов, без необходимости создавать собственный "кривой" сервер.
*   **[httpbin.org](https://httpbin.org):** Тестовый API-сервер, который позволяет делать целый ряд типичных запросов и тестировать ответы. Существуют публичные инстансы, а также возможность развернуть его самостоятельно (например, в Docker).
*   **Встроенный веб-сервер Python:** Вместо поднятия полноценных веб-серверов (Apache, Nginx) для простых тестов можно использовать встроенный модуль Python. По умолчанию слушает на порту 8000.
    ```bash
    # Для Python 3
    python3 -m http.server 8000
    ```



## Wget

**Wget** (GNU Wget) — это утилита, основное предназначение которой — надежное скачивание файлов и создание локальных зеркал веб-сайтов.

### Разновидности Wget

Существует несколько реализаций Wget, каждая со своими особенностями:

*   **Wget из BusyBox:**
    *   Минималистичный, но повсеместно распространенный. Часто встречается в ограниченных окружениях (Alpine Linux, `initramfs`).
    *   Имеет сильно урезанный набор опций и минималистичные сообщения об ошибках (например, "connection reset by peer" без подробностей).
    *   BusyBox использует нулевой аргумент для определения выполняемой команды, поэтому `wget` может быть вызван как `busybox wget` или через символическую ссылку.
    *   Пример: при запросе к сайту с "плохим" сертификатом может выдать неинформативное "connection reset by peer". Опция `--no-check-certificate` может помочь в таких случаях.

*   **GNU Wget (Wget 1.x vs Wget 2.x):**
    *   **Wget 1.x:** Исторически поддерживал протокол FTP, но имел ограничения в работе с современным HTTP. Не поддерживал HTTP/2, TCP Fast Open и многие возможности современного TLS. HTTP/1.x — это текстовый протокол, который открывает новое TCP-соединение для каждого запроса, что неэффективно при загрузке множества ресурсов.
    *   **Wget 2.x:** Полностью переписанная версия, поддерживающая HTTP/2 и HTTP/3. Эти версии HTTP являются двоичными протоколами, способные переиспользовать одно соединение для передачи множества запросов, что значительно ускоряет зеркалирование сайтов и скачивание множества мелких файлов. Во многих новых дистрибутивах `wget` уже является символической ссылкой на `wget2`.

### Ключевые особенности и опции GNU Wget

*   **Зеркалирование сайтов:**
    *   `wget` — очень полезный инструмент для создания локальных копий веб-сайтов.
    *   Опции:
        *   `-r`, `--recursive`: включить рекурсию.
        *   `-l <depth>`, `--level=<depth>`: глубина рекурсии (например, `inf` для бесконечной глубины).
        *   `-k`, `--convert-links`: преобразовать абсолютные ссылки в локальные (относительные) для офлайн-просмотра. Это позволяет перемещать зеркало на другой сервер без потери работоспособности ссылок.
        *   `-p`, `--page-requisites`: загрузить все ресурсы, необходимые для отображения страницы (CSS, JS, изображения).
        *   `--adjust-extension`: добавлять к файлам подходящие расширения (.html, .css).
    *   Пример:
        ```bash
        wget -r -l inf -k -p --adjust-extension http://localhost:8000
        ```
    *   Важно: если веб-сервер слушает только на IPv4, а `localhost` резолвится в IPv6, используйте `-4`.

*   **Обработка ошибок и коды возврата:**
    *   GNU Wget предоставляет более детальные сообщения об ошибках по сравнению с BusyBox-версией.
    *   Коды возврата (exit status) можно посмотреть в документации (`man wget` в разделе `EXIT STATUS`). Например, код `8` означает "Server issued an error response".
    *   В отличие от `curl` (по умолчанию), `wget` (особенно `wget2`) возвращает ненулевой код выхода при HTTP-ошибках (4xx, 5xx), что делает его безопасным для использования в скриптах с `set -e`.
    *   Опция `--debug` для получения максимально подробной информации о происходящем:
        ```bash
        wget --debug https://badssl.com/expired
        ```

*   **Загрузка файлов:**
    *   `-c`, `--continue`: продолжить оборванную загрузку с того места, где она прервалась. Это реализуется через заголовок HTTP `Range`.
        ```bash
        wget -c https://example.com/large-file.zip
        ```
    *   `-b`, `--background`: запустить `wget` в фоновом режиме.
    *   Поддержка цифровых подписей: `wget` может проверять цифровые подписи файлов, что полезно для загрузки дистрибутивов.
    *   Работа с Metalink: `wget` умеет извлекать адреса из Metalink-файлов и автоматически выбирать зеркала.

*   **Wget как API-клиент:**
    *   `--header='Header-Name: Header-Value'`: установка произвольных HTTP-заголовков.
    *   Передача данных формы: `wget` не имеет встроенной удобной опции для передачи параметров POST-запросов в виде формы (`application/x-www-form-urlencoded` или `multipart/form-data`), что делает его менее удобным для работы с некоторыми API по сравнению с `curl` или `HTTPie`. Данные приходится формировать вручную.
    *   Работа с куками:
        ```bash
        # Сохранить cookies, полученные от сервера
        wget --save-cookies cookies.txt http://example.com

        # Загрузить cookies из файла для отправки на сервер
        wget --load-cookies cookies.txt http://example.com
        ```
    *   Файл `.netrc`: для BASIC-аутентификации можно использовать файл `.netrc` в домашней директории пользователя. Однако он не поддерживает токены `Bearer`.

*   **Особые возможности:**
    *   Вывод в стандартный вывод: если в качестве файла вывода указать дефис (`-`), данные будут выведены на стандартный вывод.
    *   Скачивание файла с именем `-`: используйте `./-`.

## cURL

**cURL** (Client for URLs) — это чрезвычайно мощный и гибкий инструмент для передачи данных. Он поддерживает огромное количество протоколов (HTTP, HTTPS, FTP, SCP, LDAP, и т.д.) и является стандартом де-факто для взаимодействия с API из командной строки.

### Ключевые особенности и опции

*   **Безопасность в скриптах:** В отличие от `wget`, `curl` по умолчанию **не** завершается с ошибкой при HTTP-статусах 4xx или 5xx. Для надежной работы в скриптах **всегда** используйте опцию `--fail`.
    ```bash
    # --fail (-f): завершиться с ошибкой (код 22) при HTTP-ошибках сервера
    # --show-error (-S): показывать ошибку, даже если используется -s (silent)
    curl -fsS http://httpbin.org/status/404
    echo "Код возврата: $?" # Выведет 22
    ```

*   **Работа с API:** `curl` предоставляет полный контроль над HTTP-запросом.
    ```bash
    # -X, --request: указать метод запроса (GET, POST, PUT, DELETE)
    # -H, --header: добавить заголовок
    # -d, --data: отправить данные в теле запроса (формат application/x-www-form-urlencoded)
    curl -X POST -H "Content-Type: application/json" -d '{"key":"value"}' http://httpbin.org/post
    ```

*   **Отправка файлов и форм:**
    ```bash
    # -F, --form: отправить данные в формате multipart/form-data
    # @filename: прикрепить файл
    curl -F "user=John" -F "avatar=@/path/to/photo.jpg" http://httpbin.org/post

    # Отправка "сырых" бинарных данных
    # --data-binary @filename
    curl --data-binary @archive.zip http://httpbin.org/post
    ```

*   **Отладка:**
    ```bash
    # -v, --verbose: показать подробную информацию о соединении и заголовках (менее детально, чем --trace)
    curl -v https://example.com
    ```
    Для максимально детального дампа обмена данными, включая TLS-информацию, используйте опцию `--trace <file>`.
    ```bash
    # --trace <file>: записать полный дамп обмена данными (включая бинарные и TLS) в файл
    curl --trace trace.log https://example.com
    ```

*   **Аутентификация и Cookies:** Помимо опций `--cookie` и `--cookie-jar` для работы с куками, `curl` также поддерживает файл `.netrc` для базовой аутентификации.

*   **Подмена User-Agent:** Можно легко подменить заголовок `User-Agent` с помощью опции `-A` или `--user-agent`.
    ```bash
    curl -A "MyCustomAgent/1.0" https://example.com
    ```

## HTTPie

**HTTPie** — это современный HTTP-клиент с интуитивно понятным синтаксисом, форматированным и подсвеченным выводом, поддержкой JSON и сессий. Он создан, чтобы сделать взаимодействие с API из командной строки максимально простым и приятным.

Исполняемый файл обычно называется `http`.

### Ключевые особенности и синтаксис

*   **Интуитивный синтаксис:** Методы (`GET`, `POST`) указываются как подкоманды. Параметры запроса добавляются в виде пар `ключ==значение` для URL-параметров и `ключ=значение` для тела запроса. По умолчанию `HTTPie` отправляет данные тела запроса в формате JSON.
    ```bash
    # GET-запрос с URL-параметром
    # Эквивалентно curl "http://httpbin.org/get?name=John"
    http GET httpbin.org/get name==John

    # POST-запрос с JSON-телом (по умолчанию)
    # Эквивалентно curl -X POST -H "Content-Type: application/json" -d '{"name":"John"}' http://httpbin.org/post
    http POST httpbin.org/post name=John
    ```
    Для явного указания формата формы или multipart можно использовать опции `--form` или `--multipart`.

*   **Сессии:** `HTTPie` может автоматически сохранять и переиспользовать cookies, заголовки `Authorization` и другие данные между запросами в рамках одной сессии. Сессии могут быть именованными и сохраняться в домашней директории пользователя.
    ```bash
    # Создаем сессию с именем 'my_session' и логинимся
    http --session=my_session POST http://example.com/login user=test pass=123

    # Последующие запросы в той же сессии автоматически используют полученные cookies
    http --session=my_session GET http://example.com/profile
    ```

*   **Аутентификация:** Встроенная поддержка различных схем аутентификации, включая Basic, Digest и Bearer.
    ```bash
    # Basic аутентификация
    http -a user:password http://example.com/protected

    # Bearer токен
    http -A bearer -a YOUR_TOKEN_HERE http://example.com/api/resource
    ```

*   **Офлайн-режим:** Позволяет посмотреть, как будет выглядеть запрос, не отправляя его на сервер.
    ```bash
    # -o, --offline: не отправлять запрос, только показать его
    http --offline POST httpbin.org/post name=John
    ```

## Общие концепции аутентификации

Понимание различных методов аутентификации важно при работе с HTTP-клиентами и API.

*   **BASIC-аутентификация:** Передает имя пользователя и пароль в заголовке `Authorization` в кодировке Base64. Хотя сами данные не шифруются, при использовании HTTPS они защищены от перехвата.
*   **DIGEST-аутентификация:** Более сложный механизм, при котором клиент вычисляет хеш от пароля и "вызова" (challenge) от сервера. Это предотвращает передачу пароля в открытом виде, но стал менее актуальным с повсеместным распространением HTTPS.
*   **BEARER-аутентификация:** Наиболее распространенный метод в современных API. Клиент отправляет токен (например, JWT) в заголовке `Authorization: Bearer YOUR_TOKEN`. Токен выдается сервером после успешной авторизации и несет в себе информацию о правах доступа.
*   **Аутентификация на основе Cookies:** Используется в веб-приложениях. После успешного входа через форму, сервер устанавливает куки в браузере клиента. Эти куки затем автоматически отправляются с каждым последующим запросом, поддерживая сессию пользователя. HTTP-клиенты могут имитировать это поведение, сохраняя и загружая куки.

| Задача                               | Wget                               | cURL                                                    | HTTPie                               |
| ------------------------------------ | ---------------------------------- | ------------------------------------------------------- | ------------------------------------ |
| **Основное назначение**              | Скачивание файлов, зеркалирование  | Универсальная передача данных, API, скрипты             | Удобная работа с API, интерактивность |
| **Скачать файл**                     | `wget <url>`                       | `curl -O <url>`                                         | `http --download <url>`              |

| **Отправить форму**                  | `--post-data='a=1&b=2'`            | `curl -d 'a=1&b=2'` или `curl -F 'a=1'`                 | `http -f POST <url> a=1 b=2`         |

| **Дружелюбность вывода**             | Низкая (лог-файл)                  | Низкая (сырой вывод)                                    | Высокая (подсветка, форматирование)  |
