# Wireshark — практические сценарии

## Определения

**Следование за потоком (Follow Stream)** — функция Wireshark, позволяющая воссоздать полный диалог между клиентом и сервером из отдельных пакетов одного TCP, UDP или HTTP соединения в удобном для чтения текстовом виде.

**Диалоги (Conversations)** — сводная статистика всех сетевых взаимодействий в дампе, сгруппированная по парам адресов (L2, L3, L4) с указанием объема переданных данных и количества пакетов.

**Иерархия протоколов (Protocol Hierarchy)** — статистический отчет, показывающий распределение захваченного трафика по уровням модели OSI и конкретным протоколам.

**Экспорт объектов (Export Objects)** — механизм извлечения файлов (изображений, документов, скриптов), которые были переданы внутри прикладных протоколов (например, HTTP или SMB).

## Основные концепции

### Установка и настройка прав доступа

Для захвата пакетов без прав суперпользователя (root) в Linux необходимо настроить соответствующие привилегии:

| ОС | Команда установки | Настройка прав |
| :--- | :--- | :--- |
| **Debian / Ubuntu** | `sudo apt install wireshark` | `sudo usermod -aG wireshark $USER` |
| **Fedora / RHEL** | `sudo dnf install wireshark` | `sudo usermod -aG wireshark $USER` |

При установке на Debian-подобные системы на вопрос о разрешении захвата обычным пользователям следует ответить «Да». Это установит POSIX (Portable Operating System Interface — переносимый интерфейс операционных систем) возможности (`capabilities`) на утилиту `dumpcap`. После добавления пользователя в группу требуется перезапуск сессии (перелогин).

### Базовый рабочий процесс

1.  **Выбор интерфейса**: Запустите Wireshark и выберите активный сетевой адаптер (он помечен графиком активности).
2.  **Запуск захвата**: Используйте кнопку с синим плавником или сочетание `Ctrl + E`.
3.  **Фильтрация**: Введите display-фильтр (например, `dns` или `ip.addr == 10.0.0.1`) для поиска нужных пакетов.
4.  **Остановка и сохранение**: Остановите захват (`Ctrl + E`) и сохраните результат через `File → Save As` в формате `.pcapng`.

### Работа с временными метками

Настройка отображения времени (`View → Time Display Format`) критична для поиска задержек (RTT — Round-Trip Time, время кругового обхода).

| Режим | Применение |
| :--- | :--- |
| **Seconds since beginning of capture** | Время от начала текущего сеанса захвата. |
| **Seconds since previous displayed packet** | Измерение задержек между пакетами, прошедшими текущий фильтр. |
| **Date and Time of Day** | Сопоставление сетевых событий с системными логами серверов. |

## Практические сценарии

### Сценарий 1: Первичный анализ неизвестного дампа

Если вы получили файл захвата без описания проблемы, следуйте алгоритму:
1.  Откройте `Statistics → Protocol Hierarchy`, чтобы понять, какой трафик преобладает (например, 90% TCP/HTTPS).
2.  Перейдите в `Statistics → Conversations` и отсортируйте по столбцу `Bytes`. Это выявит «самых громких» участников сети.
3.  Проверьте `Statistics → Expert Information`. Wireshark подсветит явные аномалии: разрывы соединений (RST), повторные передачи (Retransmissions) или ошибки контрольных сумм.

### Сценарий 2: Реконструкция диалога (Follow Stream)

Для анализа того, что именно передавалось внутри соединения:
1. Выберите любой пакет, относящийся к интересующей сессии.
2. Нажмите правой кнопкой мыши → `Follow → TCP Stream`.
3. В открывшемся окне вы увидите данные в формате ASCII или HEX. 
4. Текст от клиента подсвечивается красным, от сервера — синим.
5. Вы можете сохранить содержимое потока в файл для дальнейшего изучения.

### Сценарий 3: Динамическое добавление столбцов

Для удобства анализа сотен пакетов можно вынести любое поле протокола в общую таблицу:
1. Найдите поле в панели «Packet Details» (например, `http.request.uri`).
2. Нажмите правой кнопкой мыши → `Apply as Column`.
3. Теперь URL каждого запроса будет виден сразу в общем списке пакетов.

### Сценарий 4: Извлечение переданных файлов

Если в трафике передавались файлы по незашифрованному протоколу HTTP:
1. Перейдите в `File → Export Objects → HTTP`.
2. Выберите нужные файлы из списка (по расширению или размеру) и сохраните их на диск.
3. Это позволяет восстановить изображения, скрипты или документы без ручного парсинга байтов.

### Сценарий 5: Анализ баз данных и брокеров сообщений

Wireshark поддерживает глубокую диссекцию протоколов ПО среднего слоя (middleware):

- **Kafka**: фильтры `kafka.topic` (имя топика) и `kafka.value` (содержимое) позволяют отлаживать цепочки передачи сообщений.
- **PostgreSQL**: фильтр `pgsql.query` показывает текст SQL-запросов, что полезно для оптимизации запросов и отладки ORM (Object-Relational Mapping — объектно-реляционное отображение).
- **MongoDB**: фильтры `mongodb.query` и `mongodb.document` позволяют видеть JSON-документы прямо в трафике.

### Сценарий 6: Диагностика производительности сети

Для быстрого поиска причин медленной работы:
- **Задержки сервера**: RTT в норме, но время между запросом и ответом (Delta Time) велико.
- **Потери пакетов**: в Expert Information много событий `Previous segment not captured` и `TCP Retransmission`.
- **Проблемы клиента**: события `TCP Window Full` или `Zero Window`, означающие переполнение буферов принимающей стороны.

Детальный разбор — в **[диагностике производительности TCP](tcp_performance/tcp_performance_diagnostics.md)**.
