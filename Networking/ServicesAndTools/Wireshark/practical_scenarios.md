# Wireshark: Практические Сценарии

## Практические сценарии

### Установка и настройка прав

* **Debian/Ubuntu**: `sudo apt install wireshark`. Во время установки выберите `Yes` на вопрос "Should non-superusers be able to capture packets?". Затем добавьте пользователя в группу: `sudo usermod -aG wireshark $USER` и перезайдите в систему.
* **Fedora/RHEL**: `sudo dnf install wireshark`. Добавьте пользователя: `sudo usermod -aG wireshark $USER`.

### Базовое использование Wireshark (GUI)

1. **Запустите Wireshark**. На стартовом экране отображается список сетевых интерфейсов. Активные интерфейсы визуально подсвечиваются графиками сетевой активности, что помогает выбрать нужный.
2. **Выберите интерфейс** с активностью и нажмите синюю кнопку в виде плавника акулы (или `Ctrl+E`), чтобы начать захват.
3. **Примените фильтр отображения**, например `dns` или `http`, чтобы увидеть только интересующий трафик.
4. **Остановите захват** (красная кнопка "Stop" или `Ctrl+E`).
5. **Сохраните данные**: `File -> Save As...` (формат `.pcapng`).

#### Дополнительные приемы базового анализа

* **Анализ диалогов (Conversations)**: Через меню `Statistics -> Conversations` можно увидеть список всех сетевых взаимодействий. Сортировка по столбцу `Bytes` позволяет быстро определить наиболее "разговорчивые" IP-адреса и оценить общий объем переданных данных.
* **Иерархия протоколов (Protocol Hierarchy)**: Меню `Statistics -> Protocol Hierarchy` показывает распределение трафика по протоколам, что помогает быстро сориентироваться, какие протоколы используются в дампе. Отсюда можно применить фильтры к выбранным протоколам.
* **Динамическое добавление столбцов**: Для удобства анализа можно добавлять новые столбцы с информацией из полей протоколов. Например, выделите в панели "Packet Details" нужное поле (например, `http.request.uri`, `tcp.port`), кликните правой кнопкой мыши и выберите `Apply as Column`.
* **Экспорт объектов HTTP**: Из меню `File -> Export Objects -> HTTP` можно извлечь все файлы (изображения, скрипты, исполняемые файлы), переданные по HTTP, что полезно для анализа содержимого веб-трафика.

### Анализ потоков данных (Follow Stream)

Это одна из самых полезных функций. Кликните правой кнопкой мыши по пакету (например, HTTP) и выберите `Follow -> TCP Stream`. Wireshark откроет новое окно, где покажет полный диалог между клиентом и сервером в виде текста, отфильтровав все остальные пакеты.

### Анализ специфичных протоколов

Wireshark умеет детально разбирать множество протоколов, предоставляя доступ к их содержимому и метаданным.

* **Kafka**:
  * **Идентификация**: Kafka обычно работает на порту `9092`. Запросы (`Request`) и ответы (`Response`) можно различить по портам источника и назначения.
  * **Поля для анализа**: В панели "Packet Details" можно найти поля, специфичные для Kafka, например: `kafka.topic` (имя топика), `kafka.value` (содержимое сообщения). Добавление этих полей в качестве столбцов значительно упрощает анализ.
  * **Пример использования**: Полезно для отладки конфигураций Producer/Consumer, когда кажется, что сообщения не доходят. Анализ может выявить, что Producer пишет в один топик (например, `my_topic_json`), а Consumer читает из другого (`my_topic_binary`), из-за неявных правил формирования имен топиков в приложении.
* **PostgreSQL (PGSQL Protocol)**:
  * **Идентификация**: Обычно работает на порту `5432`.
  * **Поля для анализа**: `pgsql.query` - отображает текст SQL-запроса. Его можно добавить в столбец для быстрого обзора всех запросов к базе данных.
  * **Пример использования**: Позволяет увидеть все SQL-операции (SELECT, INSERT, UPDATE, DELETE, CREATE, DROP), отправляемые клиентом, и ответы сервера, что полезно для отладки ORM-запросов или анализа взаимодействия приложения с БД.
* **MS SQL (TDS Protocol)**:
  * **Идентификация**: Использует порт `1433`.
  * **Поля для анализа**: В протоколе TDS можно найти вызовы хранимых процедур (`tds.procname`), их параметры (`tds.paramname`, `tds.paramvalue`), а также текст SQL-батчей (`tds.sql_batch`).
  * **Пример использования**: Аналогично PostgreSQL, помогает понять взаимодействие с SQL Server, отлаживать вызовы хранимых процедур и анализировать их параметры.
* **MongoDB (MongoDB Protocol)**:
  * **Идентификация**: Обычно работает на порту `27017`.
  * **Поля для анализа**: `mongodb.op_code` (тип операции, например `OP_QUERY`, `OP_INSERT`), `mongodb.query` (содержимое запроса в формате JSON), `mongodb.document` (содержимое документа).
  * **Пример использования**: Позволяет анализировать взаимодействие с MongoDB, видеть отправляемые запросы и вставляемые/извлекаемые документы, что критически важно для отладки NoSQL-приложений.

### Анализ распространенных протоколов

* **ICMP (Ping)**: Фильтр `icmp`. Позволяет увидеть пакеты `Echo (ping) request` и `Echo (ping) reply`, измерить задержку (RTT) и выявить потери.
* **DNS**: Фильтр `dns`. Помогает анализировать:
  * **Типы записей**: `A`, `AAAA`, `CNAME`, `MX`, `NS`.
  * **Флаги**: `Authoritative Answer (AA)` показывает, пришел ответ от авторитетного сервера или из кэша.
  * **Обратные запросы (PTR)**: Запросы для доменов `.in-addr.arpa` для определения имени по IP.
* **TCP**: Фильтр `tcp`. Позволяет детально изучить:
  * **Установку соединения (3-way handshake)**: `SYN`, `SYN, ACK`, `ACK`.
  * **Передачу данных**: Пакеты с флагом `PSH`.
  * **Завершение соединения (4-way handshake)**: Пакеты с флагом `FIN`.
* **HTTP**: Фильтр `http`. Wireshark разбирает запросы и ответы, позволяя анализировать методы (`GET`, `POST`), статусы (`200 OK`, `404 Not Found`), заголовки и тело сообщения.

### Работа со временем

Эффективный анализ сетевого трафика часто требует глубокой работы с временными метками.

* **Форматы отображения времени**: В меню `View -> Time Display Format` можно выбрать различные форматы:
  * `Seconds since beginning of capture`: По умолчанию, показывает время относительно начала захвата.
  * `Seconds since previous displayed packet`: Показывает время между текущим и предыдущим отображенным пакетом. Крайне полезно для измерения задержек.
  * `Date and Time of Day`: Отображает абсолютную дату и время. Полезно для сопоставления трафика с логами других систем.
  * `Time of Day`: Отображает только абсолютное время.
  * `Time Reference`: Позволяет установить произвольную точку отсчета.
* **Установка временной точки отсчета (`Set Time Reference`)**: Кликните правой кнопкой мыши по любому пакету и выберите `Set Time Reference`. Этот пакет будет считаться "нулевой" точкой отсчета, и время всех остальных пакетов будет отображаться относительно него. Можно установить несколько таких точек.
* **Столбец "Delta time from previous displayed packet"**: Добавление этого столбца (через `Apply as Column` для соответствующего поля в `Frame` -> `Time delta from previous displayed packet`) позволяет постоянно видеть временной интервал между соседними пакетами, что очень удобно для поиска задержек в ответах сервера.
