# Wireshark — практические сценарии

## Определения

**Следование за потоком (Follow Stream)** — функция Wireshark, позволяющая воссоздать полный диалог между клиентом и сервером из отдельных пакетов одного TCP, UDP или HTTP соединения в удобном для чтения текстовом виде.

**Диалоги (Conversations)** — сводная статистика всех сетевых взаимодействий в дампе, сгруппированная по парам адресов (L2, L3, L4) с указанием объема данных и количества пакетов.

**Иерархия протоколов (Protocol Hierarchy)** — статистический отчет, показывающий распределение захваченного трафика по уровням модели OSI и конкретным протоколам.

**Экспорт объектов (Export Objects)** — механизм извлечения файлов (изображений, скриптов), которые были переданы внутри прикладных протоколов (HTTP, SMB, TFTP).

## Основные концепции

### Базовый рабочий процесс

1. **Выбор интерфейса**: Запустите Wireshark и выберите активный сетевой адаптер (отмечен графиком активности).
2. **Запуск захвата**: Используйте кнопку с синим плавником или `Ctrl + E`.
3. **Фильтрация**: Введите display-фильтр (например, `dns` или `ip.addr == 10.0.0.1`) для поиска нужных пакетов.
4. **Остановка и сохранение**: Остановите захват (`Ctrl + E`) и сохраните результат через `File → Save As` в формате `.pcapng`.

### Работа с временными метками

Настройка отображения времени (`View → Time Display Format`) критична для поиска задержек:

| Режим | Применение |
| :--- | :--- |
| **Seconds since beginning of capture** | Время от начала текущего сеанса захвата. |
| **Seconds since previous displayed packet** | Измерение задержек между пакетами, прошедшими текущий фильтр. |
| **Date and Time of Day** | Сопоставление сетевых событий с системными логами серверов. |

## Практические сценарии

### Сценарий 1: Первичный анализ неизвестного дампа

Если вы получили файл захвата без описания проблемы:
1. Откройте `Statistics → Protocol Hierarchy`, чтобы понять структуру трафика (например, доминирование TCP/HTTPS).
2. Перейдите в `Statistics → Conversations` и отсортируйте по столбцу `Bytes`. Это выявит основных участников обмена.
3. Проверьте `Statistics → Expert Information`. Wireshark подсветит аномалии: разрывы (RST), повторные передачи (Retransmissions) или ошибки контрольных сумм.

### Сценарий 2: Захват трафика в Kubernetes (ksniff)

Для отладки подов без встроенных инструментов захвата:
1. Установите плагин через Krew: `kubectl krew install sniff`.
2. Запустите захват в реальном времени с выводом в локальный Wireshark:
   ```bash
   kubectl sniff <pod-name> -n <namespace>
   ```
3. Для «distroless» образов используйте флаг `-p` (запуск через привилегированный под-помощник).

### Сценарий 3: Расшифровка TLS-трафика (HTTPS/gRPC)

Для анализа зашифрованного содержимого:
1. Запустите браузер или приложение с экспортом ключей:
   ```bash
   export SSLKEYLOGFILE=~/tls-keys.log
   google-chrome
   ```
2. В Wireshark: `Edit → Preferences → Protocols → TLS` → `(Pre)-Master-Secret log filename` укажите путь к файлу.
3. Используйте фильтр `http2` или `grpc` для просмотра расшифрованных данных.

### Сценарий 4: Анализ баз данных и ORM

Для выявления неэффективных запросов:
- **PostgreSQL**: Используйте фильтр `pgsql.query`, чтобы увидеть текст SQL-запросов. Сопоставьте время выполнения запроса с временными метками пакетов.
- **Redis**: Фильтр `redis.command` позволяет отслеживать интенсивность обращений к кэшу.
- **MongoDB**: Фильтр `mongodb.query` отображает JSON-структуры запросов.

### Сценарий 5: Поиск микро-всплесков (Micro-bursts)

При жалобах на кратковременные потери данных:
1. Используйте **I/O Graphs** (`Statistics → I/O Graphs`).
2. Установите интервал времени (Tick interval) в **1 microsecond** (доступно в Wireshark 4.4+).
3. Ищите резкие пики (Spikes) трафика, которые могут приводить к переполнению буферов сетевых карт или коммутаторов.

### Сценарий 6: Использование профилей под задачу

Для быстрой смены контекста анализа:
1. Создайте профиль для K8s: `Configuration Profiles (внизу справа) → New`.
2. Настройте специфичные колонки: `Source Pod`, `Dest Pod` (через кастомные поля GeoIP или аннотации).
3. Включите **Automatic Profile Switching** (Wireshark 4.4+), привязав профиль к фильтру `ip.addr == 10.244.0.0/16`.
