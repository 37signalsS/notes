# Wireshark — обзор инструментов и определений

## Определения

**Wireshark** — графический анализатор сетевых протоколов (сниффер) с открытым исходным кодом. Предназначен для захвата, детального разбора и визуализации сетевого трафика в реальном времени или из сохраненных файлов (pcap/pcapng). Является стандартом индустрии для траблшутинга сетей и анализа безопасности.

**tcpdump** — классическая консольная утилита для захвата и базового анализа сетевого трафика. Работает на базе библиотеки `libpcap`. Оптимальна для работы на продакшен-серверах без графической оболочки. Подробнее: **[tcpdump](../../../Linux/Diagnostics/Networking/tcpdump.md)**.

**tshark** — консольная версия Wireshark. Позволяет использовать всю мощь диссекторов Wireshark в CLI, экспортировать данные в форматы CSV/JSON/XML и автоматизировать анализ через скрипты. См. **[Использование tshark](./tshark_usage.md)**.

**termshark** — интерактивный TUI-интерфейс (текстовый пользовательский интерфейс) для `tshark`. Предоставляет удобство Wireshark (дерево протоколов, фильтры) непосредственно в терминале, что критично для анализа на удаленных узлах по SSH. См. **[Сетевые инструменты CLI и TUI](../../../Linux/Diagnostics/Networking/network_cli_tools.md#termshark)**.

**dumpcap** — специализированная низкоуровневая утилита для непосредственного захвата пакетов с интерфейса. Именно её Wireshark и `tshark` используют для записи данных на диск. Работает с минимальными привилегиями (требует только `CAP_NET_RAW`).

**Вспомогательные утилиты Wireshark:**
*   **editcap:** Редактирование дампов (удаление дубликатов, вырезание фрагментов по времени, изменение формата, экстракция секретов через `--extract-secrets`).
*   **mergecap:** Объединение нескольких файлов захвата в один с сохранением хронологии.
*   **reordercap:** Восстановление хронологического порядка пакетов (актуально при захвате с нескольких интерфейсов).
*   **text2pcap:** Преобразование текстовых HEX-дампов в бинарный формат `.pcap`.

**Диссектор (Dissector)** — программный модуль (на C или Lua), обучающий Wireshark понимать структуру конкретного протокола. Содержит более 3000 встроенных диссекторов.

**Экспертная информация (Expert Info)** — система автоматического обнаружения сетевых проблем (TCP Retransmissions, Zero Window, ICMP errors), которая подсвечивает пакеты цветовыми индикаторами и дает рекомендации. Уровни важности: **Error** (критические ошибки протокола), **Warning** (потери, retransmissions), **Note** (информационные события, Keep-Alive), **Chat** (стандартные процессы, SYN/FIN). Подробнее: **[Продвинутые функции](./advanced_features.md)**.

**libpcap / Npcap** — библиотеки, предоставляющие API для захвата сетевых пакетов в Unix-подобных системах (`libpcap`) и Windows (`Npcap`).

**Фильтр захвата (Capture Filter)** — фильтр на уровне `libpcap`, применяемый до записи пакетов. Использует синтаксис BPF (Berkeley Packet Filter). Отброшенные данные невозможно восстановить. Пример: `host 1.1.1.1 and port 80`. Подробнее: **[Основные концепции](./core_concepts.md)**.

**Фильтр отображения (Display Filter)** — фильтр, применяемый к уже захваченным пакетам. Использует собственный синтаксис Wireshark с поддержкой L7-полей и логических операций. Пример: `ip.addr == 1.1.1.1 && tcp.port == 80`. Подробнее: **[Основные концепции](./core_concepts.md)**.

**Промискусный режим (Promiscuous Mode)** — режим адаптера, при котором отключается аппаратная фильтрация по MAC-адресу назначения. Адаптер принимает все кадры L2-домена, даже если они не адресованы данному хосту. Критичен для захвата трафика других узлов в сегменте.

**Срез пакета (Snaplen)** — ограничение сохраняемых байт на пакет. Например, 96 байт покрывают заголовки L2-L4 без полезной нагрузки, что экономит место и защищает PII. Полный захват: `-s 0` (по умолчанию).

**Потоковая реконструкция (Follow Stream)** — функция воссоздания полного диалога клиент-сервер из пакетов одного TCP/UDP/HTTP-соединения в текстовом виде. Доступ: правый клик на пакете -> Follow -> TCP Stream (или HTTP/TLS/UDP). Отображает данные без протокольных заголовков.

**Иерархия протоколов (Protocol Hierarchy)** — статистика `Statistics -> Protocol Hierarchy`, показывающая распределение трафика по уровням OSI и протоколам. Позволяет мгновенно определить доминирующую нагрузку (HTTP, DNS, шифрованный трафик).

**Время ответа сервиса (Service Response Time, SRT)** — метрика задержки «запрос-ответ» на прикладном уровне. Поддерживается для SMB, RPC, HTTP, DNS, LDAP, MySQL, PostgreSQL. Доступ: `Statistics -> Service Response Time -> <протокол>`.

**Геолокация (GeoIP)** — обогащение IP-адресов геоданными и ASN через базы MaxMind. Поля: `ip.geoip.src_city`, `ip.geoip.src_asname`. Настройка: `Edit -> Preferences -> Name Resolution -> MaxMind database directories`.

**Блок расшифровки секретов (DSB, Decryption Secrets Block)** — блок формата pcapng (с Wireshark 3.0) для встраивания TLS-ключей (SSLKEYLOGFILE) прямо в файл дампа. Позволяет передавать расшифрованный трафик вместе с ключами.

**Post-Quantum Cryptography (PQC) в TLS 1.3** — гибридные ключевые группы (например, X25519 + ML-KEM), обеспечивающие защиту от квантовых компьютеров. Wireshark 4.4+ поддерживает их обработку при наличии секретов в SSLKEYLOGFILE.

**Форматы файлов:**
*   **pcap (Packet Capture):** Классический бинарный формат. Не поддерживает метаданные (имена интерфейсов, комментарии).
*   **pcapng (Packet Capture Next Generation):** Современный формат по умолчанию. Поддерживает метаданные интерфейсов, комментарии к пакетам, несколько потоков захвата и внедрение ключей расшифровки (TLS Secrets). Поддерживает сжатие **LZ4** (Wireshark 4.4+).

## Базовые концепции

### Архитектура захвата

Wireshark разделяет захват и анализ для повышения безопасности:
1.  **Привилегированный уровень:** `dumpcap` работает с сетевым интерфейсом (требует `CAP_NET_RAW`). Это позволяет запускать графический интерфейс (GUI) от имени обычного пользователя.
2.  **Пользовательский уровень:** GUI Wireshark или `tshark` обрабатывают захваченные данные.
3.  **Механизмы захвата:** 
    *   **Стандартные:** Ethernet, Wi-Fi.
    *   **Высокопроизводительные (Linux):** `AF_PACKET`, `AF_XDP` (обработка миллионов пакетов в сек).
    *   **Внешние (extcap):** `sshdump` (удаленный захват через SSH), `ciscodump` (Cisco EPC), `androiddump` (ADB), `udpdump`.

### Поддерживаемые протоколы

Wireshark поддерживает детальную диссекцию тысяч протоколов, включая:
*   **Транспортные:** TCP, UDP, SCTP, QUIC (HTTP/3), TLS 1.3.
*   **Прикладные:** HTTP/1.x, HTTP/2, WebSocket, DNS, DHCP, gRPC.
*   **Базы данных:** PostgreSQL, MySQL, MongoDB, MS SQL (TDS).
*   **Брокеры сообщений:** Kafka, AMQP, MQTT, RabbitMQ.
*   **Observability:** OTLP (OpenTelemetry), Syslog.
*   **Файловые:** SMB, NFS, FTP, SFTP.

### Сравнение инструментов

| Инструмент | Интерфейс | Назначение | Захват | Анализ |
| :--- | :--- | :--- | :--- | :--- |
| **Wireshark** | GUI | Глубокий визуальный анализ | Через `dumpcap` | Полная диссекция протоколов |
| **tshark** | CLI | Автоматизация, скрипты | Напрямую | Экспорт полей, статистика |
| **termshark** | TUI | Анализ на серверах без GUI | Через `tshark` | Интерактивный разбор |
| **tcpdump** | CLI | Быстрый захват, фильтрация | Напрямую | Базовый текстовый вывод |
| **dumpcap** | CLI | Захват без анализа | Напрямую | Отсутствует |

### Фильтрация: Capture vs Display

| Характеристика | Фильтр захвата (BPF) | Фильтр отображения (Wireshark) |
| :--- | :--- | :--- |
| **Время применения** | До записи пакетов | После захвата |
| **Производительность** | Очень высокая (ядро) | Средняя (пользовательское ПО) |
| **Гибкость** | Ограничена L2-L4 полями | Неограниченна (L7 диссекторы) |
| **Синтаксис** | `host 1.1.1.1 and port 80` | `ip.addr == 1.1.1.1 && tcp.port == 80` |
| **Возможность отмены** | Нет (данные отброшены) | Да (скрытые данные остаются в файле) |

**Важно:** Capture Filter применяется один раз и необратимо отбрасывает трафик. Display Filter можно включать/выключать без потери данных. При высокой нагрузке (>1 Gbps) комбинация обоих фильтров критична для экономии ресурсов.

### Захват трафика в контейнерах и Kubernetes

Каждый Pod/контейнер имеет свой Network Namespace. Захват на физическом интерфейсе хоста не покажет трафик внутри виртуальных мостов или veth-пар.

**Методы захвата:**
*   **nsenter:** Вход в неймспейс процесса с хоста: `nsenter -t <PID> -n tcpdump -i eth0`.
*   **kubectl debug:** Запуск временного контейнера с инструментами: `kubectl debug -it <pod_name> --image=nicolaka/netshoot`.
*   **ksniff (kubectl krew):** Плагин для захвата трафика Pod'а через packet stream: `kubectl sniff <pod-name> -n <namespace>`. При mTLS (Istio/Linkerd) захват на интерфейсе `lo` внутри пода — данные до шифрования sidecar.
*   **Sidecar-инъекция:** Добавление контейнера с `tcpdump`/`tshark` в Pod (требует перезапуска).
*   **eBPF-инструменты:** `Inspektor Gadget`, `pwru` — захват на уровне ядра без изменения состояния контейнеров. `pwru` показывает функцию ядра (например, `nft_do_chain`), где пакет уничтожен.

### Удалённый захват

Для анализа трафика на удалённом сервере без GUI-компонентов:
```bash
ssh root@remote-server "dumpcap -P -i eth0 -w -" | wireshark -k -i -
```
Альтернатива через `tcpdump`:
```bash
ssh user@host "sudo tcpdump -s 0 -U -n -w - -i eth0 not port 22" | wireshark -k -i -
```
Флаг `-P` в `dumpcap` задействует формат pcapng, `-w -` выводит поток в stdout.

### Управление профилями и автоматизация (v4.4+)

*   **Конфигурационные профили:** Наборы настроек (фильтры, колонки, правила раскраски) для разных задач (например, «Troubleshooting HTTP» или «Analysis K8s»).
*   **Автоматическое переключение профилей:** Возможность привязать профиль к display-фильтру.
*   **Пользовательские колонки:** Поддержка арифметических операций и логических тестов прямо в именах колонок (например, расчет битрейта `frame.len * 8`).

## Практические сценарии

### Работа с большими дампами (>1 ГБ)

*   **Сжатие LZ4:** Формат `pcapng` (Wireshark 4.4+) обеспечивает высокую скорость чтения при малом объеме файла.
*   **zlib-ng:** Ускорение работы со сжатыми дампами за счет современных инструкций процессора.
*   **Предварительная фильтрация:** Использование `editcap` для вырезания диапазона времени или `tshark` для экспорта только необходимых полей перед открытием в GUI.
*   **Память:** Wireshark загружает дерево диссекции всех пакетов в ОЗУ. Для экономии используйте `tshark` для потоковой обработки.

### Выбор формата сохранения

| Задача | Формат | Обоснование |
| :--- | :--- | :--- |
| Совместимость со старым ПО | `pcap` | Универсальная поддержка |
| Передача дампов с комментариями | `pcapng` | Сохранение заметок к пакетам |
| Запись с нескольких интерфейсов | `pcapng` | Разделение трафика по интерфейсам |
| Анализ в SRE/Cloud | `pcapng` + LZ4 | Баланс между скоростью и размером |

### Анализ зашифрованного трафика (TLS/QUIC)

Для анализа трафика приложений (Slack, Discord, браузеры) используйте механизм **SSLKEYLOGFILE**:
1.  **Инструмент Browser (SSL Keylog):** В Wireshark 4.2+ (Statistics -> Browser Launch Tool).
2.  **Ручная настройка:**
    ```bash
    export SSLKEYLOGFILE=~/tls-keys.log
    google-chrome
    ```
3.  **Настройка Wireshark:** `Edit → Preferences → Protocols → TLS` → `(Pre)-Master-Secret log filename`.
4.  **Фильтрация расшифрованного трафика:** Используйте фильтры `http2`, `quic`, `tls.handshake` для поиска нужных соединений. После расшифровки данные доступны на вкладке Decrypted TLS в Packet Details.
5.  **Внедрение ключей в pcapng (DSB):** При использовании Wireshark 3.0+ ключи автоматически встраиваются в блок DSB, позволяя передавать расшифрованный дамп вместе с ключами.

### Быстрый поиск причин деградации через Expert Info

При жалобах на «тормоза» в сети:
1. Откройте `Analyze → Expert Information`.
2. Перейдите на вкладку `Warnings`.
3. Ищите большое количество `TCP Retransmission` и `Previous segment not captured`. Это явный признак потерь пакетов на физическом уровне или перегрузки буферов оборудования.
4. Используйте навигацию: `Ctrl + .` (следующий пакет с Expert Info) и `Ctrl + ,` (предыдущий).

### Расследование медленных запросов через SRT

1. Выберите `Statistics → Service Response Time → MySQL` (или PostgreSQL, HTTP, DNS).
2. Нажмите `Create Stat`.
3. В таблице будет время выполнения каждого типа запроса. Сортировка по `Max SRT` покажет самые медленные запросы.
4. Клик на строку таблицы открывает соответствующие пакеты для детального анализа.

### Настройка GeoIP для анализа атак

1. Скачайте базы MaxMind (GeoLite2-City, GeoLite2-AS).
2. Укажите путь к ним в `Edit → Preferences → Name Resolution → MaxMind database directories`.
3. Перезагрузите Wireshark. Теперь в полях `ip.geoip.src_city` и `ip.geoip.src_asname` будет информация о географии.
4. Построение карты: `Statistics → Endpoint → Map`.

### Анализ TCP-потенциала через I/O Graphs

1. `Statistics → I/O Graphs`.
2. Создайте кривую: `Filter` = `tcp`, `Style` = `Line`, `Units` = `Bits/Tick`.
3. В Wireshark 4.4+ доступен интервал **1 микросекунд** для поиска микро-всплесков (micro-bursts). Пик, превышающий пропускную способность канала, указывает на мгновенное переполнение буферов коммутатора (Output Drops).

## Дополнительная информация

### Особенности и ограничения анализа

*   **Hardware Offload:** Ошибки контрольных сумм (`Bad Checksum`) в дампе часто являются следствием **Hardware Checksum Offload**. Ядро передает сетевой карте пакет с незаполненным полем суммы, а Wireshark перехватывает его **до** аппаратного расчета. Проверка: `ethtool -k eth0 | grep checksumming`.
*   **Потеря пакетов (Drops):** При высокой нагрузке анализатор может не успевать считывать данные. Проверяйте статистику (`Capture -> Interfaces -> Statistics`).
*   **eBPF:** Современный метод захвата данных до шифрования в ядре Linux (например, через `pwru` или `cilium-dbg`). `pwru` показывает конкретную функцию ядра, где пакет был отброшен.
*   **Экстракция секретов:** Команда `editcap --extract-secrets` позволяет извлечь ключи, внедренные в `pcapng`.

### Ключевые TCP-метрики для анализа

*   **iRTT (Initial RTT):** RTT, измеренный при 3-way handshake (SYN → SYN-ACK). Базовая задержка канала без учёта очередей.
*   **Bytes in Flight:** Объём данных, отправленных, но не подтверждённых (ACK). Если равен Window Size — наступает Window Full.
*   **TCP Zero Window:** Получатель объявляет `rwnd = 0` — переполнение приёмного буфера (`SO_RCVBUF`), требование немедленно остановить передачу.
*   **TCP Window Full:** Отправитель заполнил всё анонсированное окно получателя и ждет ACK. Это «потолок» пропускной способности, а не ошибка приложения.
*   **Spurious Retransmission:** Повторная отправка уже подтвержденных данных. Часто из-за некорректного RSS, когда пакеты одного потока попадают на разные ядра CPU.

### Ограничения пропускной способности TCP

Три ограничителя скорости TCP:
1.  **RWND** — буферы приёмника (ограничение приложения).
2.  **CWND** — сеть, алгоритмы CUBIC/BBR (ограничение перегрузки).
3.  **SND_BUF** — буферы отправителя.

**Формула Матиса:** `Throughput ≤ (MSS / RTT) * (1 / sqrt(p))`, где `p` — вероятность потери. Даже 1% потерь при RTT 50 мс ограничивает скорость до нескольких мегабит.

**Long Fat Networks (LFN):** Без `wscale` максимальное окно 64 КБ. При RTT 100 мс максимум: `65535 / 0.1 = 5.2 Мбит/с` независимо от канала в 1 Гбит/с. Решение — Window Scaling (`wscale` опция TCP).

### Современные алгоритмы TCP

*   **RACK (Recent Acknowledgment):** Алгоритм, ориентирующийся на время, а не на количество DupACK. Заменяет подсчёт 3 DupACK анализом времени. Быстрее восстанавливается при переупорядочивании (ядра 5.x+).
*   **TLP (Tail Loss Probe):** Зондирование «хвоста» очереди против длительных таймаутов RTO при потере последних сегментов.

### Диагностика проблем TCP

*   **ICMP Black Hole:** Отсутствие ICMP Fragmentation Needed при замирании TCP после крупного сегмента. Решение — TCP MSS Clamping или увеличение MTU. Фильтр: `icmp.type == 3 and icmp.code == 4`.
*   **CFS Throttling (Kubernetes):** Жёсткий лимит CPU приостанавливает потоки внутри периода (обычно 100 мс). В Wireshark задержки кратностью 100 мс.
*   **Уровни потерь:** `<0.1%` — допустимо; `0.1%–1%` — ощутимое замедление, деградация VoIP/Video; `>1%` — критично, проверка L1/L2.

### Определение Shaping vs реальных потерь

Если графики `all packets (Bits/s)` и `tcp.analysis.retransmission` «зеркальны» — реальные потери. Если скорость ограничена ровной «полкой» без всплесков ошибок — это Shaper провайдера.
