# Wireshark: Определения и Области Применения

## Определения

**Wireshark** — графический анализатор сетевых протоколов с открытым исходным кодом. Захватывает и детально разбирает сетевой трафик в реальном времени или из файлов сохранения (pcap/pcapng).

**tcpdump** — консольная утилита для захвата и базового анализа сетевого трафика. Работает на базе библиотеки `libpcap`. Часто используется для сохранения трафика в файл на продакшен-серверах с последующим анализом в Wireshark. Подробнее: **[tcpdump](../../../Linux/Diagnostics/Networking/tcpdump.md)**.

**tshark** — консольная версия Wireshark. Поддерживает capture/display-фильтры, экспорт в CSV/JSON, статистику. См. **[Использование tshark](./tshark_usage.md)**.

**termshark** — TUI-интерфейс для `tshark`, предоставляющий возможности Wireshark GUI в терминале. Идеален для анализа на удалённых серверах. См. **[Сетевые инструменты CLI и TUI](../../../Linux/Diagnostics/Networking/network_cli_tools.md#1-termshark-tui--wireshark-в-терминале)**.

**dumpcap** — низкоуровневая утилита, которую Wireshark и `tshark` используют непосредственно для захвата пакетов с сетевого интерфейса.

**libpcap / Npcap** — библиотеки, предоставляющие API для захвата сетевых пакетов в Unix-подобных системах (`libpcap`) и Windows (`Npcap`).

**pcap (Packet Capture)** — классический бинарный формат сохранения захваченного трафика. Не поддерживает метаданные (имя интерфейса, комментарии). Совместим со всеми инструментами анализа.

**pcapng (Packet Capture Next Generation)** — современный формат, используемый Wireshark по умолчанию. Поддерживает:

- Имена и описания интерфейсов
- Комментарии к отдельным пакетам
- Несколько потоков захвата в одном файле
- Временные метки с наносекундной точностью

## Основные концепции

### Архитектура захвата

Wireshark не захватывает пакеты напрямую — он делегирует это `dumpcap`, который работает с `libpcap`/`Npcap`. Разделение позволяет:

- Запускать захват с минимальными привилегиями (`dumpcap` получает только `cap_net_raw`)
- Запускать GUI-часть от обычного пользователя
- Снижать риски безопасности, связанные с анализом трафика

### Сравнение инструментов

| Инструмент | Интерфейс | Назначение | Захват | Анализ |
|---|---|---|---|---|
| **Wireshark** | GUI | Глубокий визуальный анализ | Через `dumpcap` | Полная диссекция протоколов |
| **tshark** | CLI | Автоматизация, скрипты | Напрямую | Экспорт полей, статистика |
| **termshark** | TUI | Анализ на серверах без GUI | Через `tshark` | Интерактивный, как Wireshark |
| **tcpdump** | CLI | Быстрый захват, простая фильтрация | Напрямую (`libpcap`) | Базовый, текстовый вывод |
| **dumpcap** | CLI | Захват без анализа (минимальные права) | Напрямую | Нет |

### Поддерживаемые протоколы

Wireshark поддерживает детальную диссекцию сотен протоколов, включая:

- **Транспортные:** TCP, UDP, SCTP, DCCP, QUIC (HTTP/3)
- **Прикладные:** HTTP/1.x, HTTP/2, WebSocket, DNS, DHCP, TLS/SSL, SSH
- **Базы данных:** PostgreSQL, MySQL, MongoDB, MS SQL (TDS)
- **Message Broker:** Kafka, AMQP, MQTT, RabbitMQ
- **Observability:** OTLP (OpenTelemetry), gRPC, Syslog
- **Файловые:** SMB, NFS, FTP, SFTP

Полный список: `Statistics → Protocol Hierarchy` в Wireshark.

## Практические сценарии

### Сценарий 1: Выбор формата сохранения

| Задача | Формат | Обоснование |
|---|---|---|
| Совместимость со старыми инструментами | `pcap` | Универсальная поддержка |
| Передача коллегам с комментариями | `pcapng` | Сохранение пакетных комментариев |
| Запись с нескольких интерфейсов | `pcapng` | Метаданные интерфейсов |
| Долгосрочное хранение | `pcap` (сжатый gzip) | Меньший размер, совместимость |

### Сценарий 2: Выбор инструмента для задачи

| Ситуация | Инструмент |
|---|---|
| Продакшен-сервер без GUI, нужно захватить дамп | `tcpdump -w dump.pcap` |
| Анализ дампа на рабочей станции | Wireshark GUI |
| Автоматизация: извлечь IP-адреса в CSV | `tshark -r dump.pcap -T fields -e ip.src` |
| Срочный анализ на сервере через SSH | `termshark -r dump.pcap` |
| Непрерывный захват с ротацией файлов | `dumpcap -b filesize:100000 -w capture.pcap` |

### Сценарий 3: Анализ Electron-приложений

Приложения на базе Chromium (Slack, Discord, VS Code) используют тот же стек TLS, что и браузеры:

1. Запустите приложение с `SSLKEYLOGFILE`:

   ```bash
   SSLKEYLOGFILE=~/tls-keys.log slack
   ```

2. Настройте Wireshark: `Edit → Preferences → Protocols → TLS → (Pre)-Master-Secret log filename` → `~/tls-keys.log`
3. Захватите трафик — появится расшифрованный HTTP/2 и WebSocket

Подробные методы: **[Методы расшифровки TLS](./tls_decryption_methods.md)**.

## Дополнительная информация

### Проблемы анализа зашифрованного трафика

Анализ TLS-трафика без ключей невозможен — данные выглядят как случайные байты. Основные препятствия:

| Препятствие | Суть | Обход |
|---|---|---|
| **Шифрование транспортного уровня** | Данные зашифрованы до передачи | SSLKEYLOGFILE, приватный ключ сервера |
| **SSL Pinning** | Приложение проверяет сертификат | Frida, патчинг, Xposed |
| **Perfect Forward Secrecy** | Уникальные эфемерные ключи на сессию | Непрерывная запись SSLKEYLOGFILE |
| **TLS 1.3** | Упрощённый handshake, ключи «разбросаны» | SSLKEYLOGFILE с TLS 1.3 support |
| **Защита ключей в ОС** | lsass.exe (Windows), keyring (Linux) | Ядерная отладка, специализированные скрипты |

Полное руководство: **[Методы расшифровки TLS](./tls_decryption_methods.md)**.
