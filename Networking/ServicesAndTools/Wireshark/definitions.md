# Wireshark — определения и области применения

## Определения

**Wireshark** — графический анализатор сетевых протоколов с открытым исходным кодом. Предназначен для захвата и детального разбора сетевого трафика в реальном времени или из файлов сохранения (pcap/pcapng).

**tcpdump** — консольная утилита для захвата и базового анализа сетевого трафика. Работает на базе библиотеки `libpcap`. Часто используется для сохранения трафика в файл на продакшен-серверах с последующим глубоким анализом в Wireshark. Подробнее: **[tcpdump](../../../Linux/Diagnostics/Networking/tcpdump.md)**.

**tshark** — консольная версия Wireshark. Поддерживает фильтры захвата и отображения, экспорт данных в форматы CSV и JSON, а также сбор статистики. См. **[Использование tshark](./tshark_usage.md)**.

**termshark** — TUI (Text-based User Interface — текстовый пользовательский интерфейс) для `tshark`, предоставляющий возможности Wireshark в терминале. Идеален для анализа на удалённых серверах по SSH. См. **[Сетевые инструменты CLI и TUI](../../../Linux/Diagnostics/Networking/network_cli_tools.md#termshark)**.

**dumpcap** — низкоуровневая утилита, которую Wireshark и `tshark` используют непосредственно для захвата пакетов с сетевого интерфейса.

**Диссектор (Dissector)** — программный модуль (на C или Lua), отвечающий за разбор (диссекцию) конкретного протокола. Wireshark содержит более 3000 встроенных диссекторов.

**Экспертная информация (Expert Info)** — автоматическая система анализа, помечающая подозрительные пакеты (повторные передачи, ошибки контрольных сумм, нарушения протокола) цветовыми индикаторами и комментариями.

**libpcap / Npcap** — библиотеки, предоставляющие API (Application Programming Interface — программный интерфейс приложения) для захвата сетевых пакетов в Unix-подобных системах (`libpcap`) и Windows (`Npcap`).

**pcap (Packet Capture)** — классический бинарный формат сохранения захваченного трафика. Не поддерживает метаданные (имена интерфейсов, комментарии).

**pcapng (Packet Capture Next Generation)** — современный формат, используемый Wireshark по умолчанию. Поддерживает метаданные интерфейсов, комментарии к пакетам, несколько потоков захвата и внедрение ключей расшифровки (TLS Secrets).

## Основные концепции

### Архитектура захвата

Wireshark не захватывает пакеты напрямую — он делегирует эту задачу `dumpcap`, который взаимодействует с `libpcap`/`Npcap`. Такое разделение позволяет:

- Запускать захват с минимальными привилегиями (`dumpcap` получает только необходимые сетевые права `cap_net_raw`).
- Использовать графический интерфейс (GUI — Graphical User Interface) от имени обычного пользователя.
- Повысить общую безопасность системы при анализе потенциально опасного трафика.

### Управление профилями и автоматизация

Начиная с версии 4.4, Wireshark поддерживает глубокую автоматизацию через профили:

- **Конфигурационные профили:** Наборы настроек (фильтры, колонки, правила раскраски) для разных задач (например, «Troubleshooting HTTP» или «Analysis K8s»).
- **Автоматическое переключение профилей:** Возможность привязать профиль к display-фильтру. При открытии дампа, содержащего соответствующий трафик, Wireshark переключится на нужный профиль автоматически.
- **Пользовательские колонки:** Поддержка арифметических операций и логических тестов прямо в именах колонок (например, расчет битрейта `frame.len * 8`).

### Сравнение инструментов

| Инструмент | Интерфейс | Назначение | Захват | Анализ |
| :--- | :--- | :--- | :--- | :--- |
| **Wireshark** | GUI | Глубокий визуальный анализ | Через `dumpcap` | Полная диссекция протоколов |
| **tshark** | CLI | Автоматизация, скрипты | Напрямую | Экспорт полей, статистика |
| **termshark** | TUI | Анализ на серверах без GUI | Через `tshark` | Интерактивный разбор пакетов |
| **tcpdump** | CLI | Быстрый захват, фильтрация | Напрямую | Базовый текстовый вывод |
| **dumpcap** | CLI | Захват без анализа | Напрямую | Отсутствует |

### Поддерживаемые протоколы

Wireshark поддерживает детальную диссекцию тысяч протоколов, включая:

- **Транспортные:** TCP, UDP, SCTP, QUIC (HTTP/3), TLS 1.3.
- **Прикладные:** HTTP/1.x, HTTP/2, WebSocket, DNS, DHCP, gRPC.
- **Базы данных:** PostgreSQL, MySQL, MongoDB, MS SQL (TDS).
- **Брокеры сообщений:** Kafka, AMQP, MQTT, RabbitMQ.
- **Observability:** OTLP (OpenTelemetry), Syslog.
- **Файловые:** SMB, NFS, FTP, SFTP.

## Практические сценарии

### Работа с большими дампами

Анализ файлов размером >1 ГБ требует оптимизации ресурсов:

- **Использование LZ4:** Формат `pcapng` поддерживает сжатие LZ4 (Wireshark 4.4+), что обеспечивает высокую скорость чтения при малом объеме файла.
- **zlib-ng:** Ускорение работы со сжатыми дампами за счет современных инструкций процессора.
- **Предварительная фильтрация:** Использование `editcap` для вырезания нужного диапазона времени или `tshark` для экспорта только необходимых полей перед открытием в GUI.
- **Память:** Wireshark загружает дерево диссекции всех пакетов в ОЗУ. Для экономии памяти используйте `tshark` или разбивайте файлы на части.

### Выбор формата сохранения

| Задача | Формат | Обоснование |
| :--- | :--- | :--- |
| Совместимость со старым ПО | `pcap` | Универсальная поддержка |
| Передача дампов с комментариями | `pcapng` | Сохранение заметок к пакетам |
| Запись с нескольких интерфейсов | `pcapng` | Разделение трафика по интерфейсам |
| Анализ в SRE/Cloud | `pcapng` + LZ4 | Баланс между скоростью и размером |

### Анализ современных приложений

Для анализа трафика приложений (Slack, Discord, браузеры) используйте механизм **SSLKEYLOGFILE**:

1. **Инструмент Browser (SSL Keylog):** В Wireshark 4.2+ появился встроенный инструмент для запуска браузеров с автоматической настройкой экспорта ключей.
2. **Ручная настройка:**
   ```bash
   export SSLKEYLOGFILE=~/tls-keys.log
   google-chrome
   ```
3. **Настройка Wireshark:** `Edit → Preferences → Protocols → TLS` → `(Pre)-Master-Secret log filename`.

Подробные инструкции: **[Методы расшифровки TLS](./tls_decryption_methods.md)**.

## Дополнительная информация

### Проблемы анализа зашифрованного трафика

Современные протоколы (TLS 1.3, QUIC) делают пассивный анализ без ключей практически невозможным. Основные методы:

- **SSLKEYLOGFILE:** Экспорт сессионных ключей из клиентских приложений.
- **eBPF:** Захват данных до их шифрования в ядре Linux.
- **Экстракция секретов:** Использование `editcap --extract-secrets` для извлечения ключей, внедренных в `pcapng`.

Полное руководство: **[Методы расшифровки TLS](./tls_decryption_methods.md)**.
