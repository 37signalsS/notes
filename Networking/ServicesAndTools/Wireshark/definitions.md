# Wireshark — определения и области применения

## Определения

**Wireshark** — графический анализатор сетевых протоколов с открытым исходным кодом. Предназначен для захвата и детального разбора сетевого трафика в реальном времени или из файлов сохранения (pcap/pcapng).

**tcpdump** — консольная утилита для захвата и базового анализа сетевого трафика. Работает на базе библиотеки `libpcap`. Часто используется для сохранения трафика в файл на продакшен-серверах с последующим глубоким анализом в Wireshark. Подробнее: **[tcpdump](../../../Linux/Diagnostics/Networking/tcpdump.md)**.

**tshark** — консольная версия Wireshark. Поддерживает фильтры захвата и отображения, экспорт данных в форматы CSV и JSON, а также сбор статистики. См. **[Использование tshark](./tshark_usage.md)**.

**termshark** — TUI (Text-based User Interface — текстовый пользовательский интерфейс) для `tshark`, предоставляющий возможности Wireshark в терминале. Идеален для анализа на удалённых серверах по SSH. См. **[Сетевые инструменты CLI и TUI](../../../Linux/Diagnostics/Networking/network_cli_tools.md#1-termshark-tui--wireshark-в-терминале)**.

**dumpcap** — низкоуровневая утилита, которую Wireshark и `tshark` используют непосредственно для захвата пакетов с сетевого интерфейса.

**libpcap / Npcap** — библиотеки, предоставляющие API (Application Programming Interface — программный интерфейс приложения) для захвата сетевых пакетов в Unix-подобных системах (`libpcap`) и Windows (`Npcap`).

**pcap (Packet Capture)** — классический бинарный формат сохранения захваченного трафика. Не поддерживает метаданные (имена интерфейсов, комментарии). Совместим практически со всеми инструментами сетевого анализа.

**pcapng (Packet Capture Next Generation)** — современный формат, используемый Wireshark по умолчанию. Поддерживает метаданные интерфейсов, комментарии к пакетам и несколько потоков захвата в одном файле.

## Основные концепции

### Архитектура захвата

Wireshark не захватывает пакеты напрямую — он делегирует эту задачу `dumpcap`, который взаимодействует с `libpcap`/`Npcap`. Такое разделение позволяет:

- Запускать захват с минимальными привилегиями (`dumpcap` получает только необходимые сетевые права `cap_net_raw`)
- Использовать графический интерфейс (GUI — Graphical User Interface) от имени обычного пользователя
- Повысить общую безопасность системы при анализе потенциально опасного трафика

### Сравнение инструментов

| Инструмент | Интерфейс | Назначение | Захват | Анализ |
| :--- | :--- | :--- | :--- | :--- |
| **Wireshark** | GUI | Глубокий визуальный анализ | Через `dumpcap` | Полная диссекция протоколов |
| **tshark** | CLI (Command Line Interface) | Автоматизация, скрипты | Напрямую | Экспорт полей, статистика |
| **termshark** | TUI | Анализ на серверах без GUI | Через `tshark` | Интерактивный разбор пакетов |
| **tcpdump** | CLI | Быстрый захват, фильтрация | Напрямую (`libpcap`) | Базовый текстовый вывод |
| **dumpcap** | CLI | Захват без анализа | Напрямую | Отсутствует |

### Поддерживаемые протоколы

Wireshark поддерживает детальную диссекцию сотен протоколов, включая:

- **Транспортные:** TCP, UDP, SCTP, DCCP, QUIC (HTTP/3)
- **Прикладные:** HTTP/1.x, HTTP/2, WebSocket, DNS, DHCP, TLS/SSL, SSH
- **Базы данных:** PostgreSQL, MySQL, MongoDB, MS SQL (TDS)
- **Брокеры сообщений:** Kafka, AMQP, MQTT, RabbitMQ
- **Observability:** OTLP (OpenTelemetry), gRPC, Syslog
- **Файловые:** SMB, NFS, FTP, SFTP

## Практические сценарии

### Выбор формата сохранения

| Задача | Формат | Обоснование |
| :--- | :--- | :--- |
| Совместимость со старым ПО | `pcap` | Универсальная поддержка |
| Передача дампов с комментариями | `pcapng` | Сохранение заметок к пакетам |
| Запись с нескольких интерфейсов | `pcapng` | Разделение трафика по интерфейсам в файле |
| Долгосрочное хранение | `pcap` + gzip | Максимальное сжатие и совместимость |

### Выбор инструмента под задачу

| Ситуация | Рекомендуемый инструмент |
| :--- | :--- |
| Сервер без GUI, нужно сохранить дамп для анализа | `tcpdump -w dump.pcap` |
| Анализ готового дампа на рабочей станции | Wireshark GUI |
| Извлечение конкретных полей (например, IP) в CSV | `tshark -r dump.pcap -T fields -e ip.src` |
| Оперативный разбор трафика на сервере через SSH | `termshark -r dump.pcap` |
| Длительный захват с ротацией файлов по размеру | `dumpcap -b filesize:100000 -w capture.pcap` |

### Анализ Electron-приложений

Приложения на базе Chromium (Slack, Discord, VS Code) позволяют расшифровывать TLS-трафик:

1. Запустите приложение с переменной окружения `SSLKEYLOGFILE`:
   ```bash
   SSLKEYLOGFILE=~/tls-keys.log slack
   ```
2. В Wireshark перейдите в `Edit → Preferences → Protocols → TLS` и укажите путь к файлу в поле `(Pre)-Master-Secret log filename`.
3. После начала захвата Wireshark автоматически расшифрует HTTP/2 и WebSocket трафик.

Подробные инструкции: **[Методы расшифровки TLS](./tls_decryption_methods.md)**.

## Дополнительная информация

### Проблемы анализа зашифрованного трафика

Без доступа к ключам шифрования содержимое пакетов TLS выглядит как случайные данные. Основные методы обхода:

- **SSLKEYLOGFILE:** Использование переменной окружения для экспорта сессионных ключей браузерами и приложениями.
- **Приватные ключи:** Использование ключа сервера (только для RSA-обмена без Perfect Forward Secrecy).
- **MITM (Man-in-the-Middle):** Использование прокси-серверов с подменой сертификатов для перехвата данных.

Полное руководство: **[Методы расшифровки TLS](./tls_decryption_methods.md)**.
