# Wireshark: Дополнительные Возможности и Настройки

## Определения

**Coloring Rules** — правила цветовой маркировки пакетов в интерфейсе Wireshark для визуального выделения определённых типов трафика и аномалий.

**Flow Graph** — графическое представление последовательности пакетов в потоке (TCP, UDP), отображающее взаимодействие клиент-сервер.

**Packet Comment** — текстовый комментарий, прикреплённый к отдельному пакету в файле захвата.

## Основные концепции

### Цветовая маркировка (Coloring Rules)

Wireshark использует цвета для выделения трафика, что ускоряет обнаружение аномалий. Встроенные правила:

| Цвет | Тип трафика |
|---|---|
| Светло-голубой | TCP |
| Светло-зелёный | HTTP |
| Тёмно-синий | DNS |
| Чёрный | Пакеты с ошибками (неверная контрольная сумма) |
| Красный | Проблемный TCP (ретрансмиты, Out-of-Order) |

Настройка: `View → Coloring Rules...`.

> **Важно:** чёрные и красные пакеты не всегда означают реальные ошибки — это может быть следствием **checksum offloading**. Подробности: **[Диагностика offloading](tcp_performance/tcp_network_losses_and_offloading.md#влияние-offloading-на-анализ-в-wireshark)**.

Пользовательские правила создаются через `View → Coloring Rules → New`. Каждое правило содержит:
- **Display Filter** — условие применения (например, `tcp.flags.syn == 1 && tcp.flags.ack == 0`)
- **Foreground/Background Color** — цвета текста и фона

### Граф потоков (Flow Graph)

`Statistics → Flow Graph` строит визуальную диаграмму взаимодействия в выбранном потоке.

- **Применение:** анализ последовательности запросов/ответов, документирование протоколов, выявление аномальных паттернов
- **Типы:** TCP, UDP, HTTP, любой протокол с поддержкой stream-анализа
- **Экспорт:** PNG, ASCII, SVG

### Раскраска диалогов (Colorize Conversation)

Клик правой кнопкой по пакету → `Colorize Conversation` выделяет все пакеты конкретного диалога (по паре IP:port). Удобно для изоляции проблемного соединения без написания ручных фильтров.

### Комментарии к пакетам

Клик правой кнопкой → `Packet Comment → Add Packet Comment`. Комментарии сохраняются в формате `pcapng` и отображаются в отдельной колонке. Применяются для фиксации подозрительных пакетов при длительном анализе.

### Горячие клавиши Wireshark GUI

| Клавиша | Действие |
|---|---|
| `Ctrl+E` | Начать/остановить захват |
| `Ctrl+R` | Перезапустить захват |
| `Ctrl+O` | Открыть файл |
| `Ctrl+S` | Сохранить файл |
| `Ctrl+F` | Найти пакет |
| `/` | Перейти к фильтру отображения |
| `Ctrl+/` | Очистить фильтр |

Полный список: `Help → Keyboard Shortcuts`.

## Практические сценарии

### Сценарий 1: Создание пользовательского правила раскраски для ретрансмитов

1. `View → Coloring Rules`
2. Нажмите `New`
3. Задайте:
   - **Name:** `TCP Retransmission`
   - **Filter:** `tcp.analysis.retransmission`
   - **Foreground:** белый, **Background:** красный
4. Переместите правило выше стандартных правил TCP (порядок важен — первое совпадение применяется)

### Сценарий 2: Визуализация HTTP-диалога через Flow Graph

1. Отфильтруйте поток: `tcp.stream eq 0`
2. Клик правой кнопкой → `Follow → TCP Stream`
3. В окне stream: `Statistics → Flow Graph`
4. Выберите тип `TCP` → `Draw`

Результат — диаграмма с направлением пакетов, флагами и временными метками.

### Сценарий 3: Документирование анализа с комментариями

При анализе инцидента добавляйте комментарии к ключевым пакетам:

```
Packet Comment: SYN flood — 500 SYN без ACK от 10.0.0.5 за 2 сек
```

Сохраните файл в формате `pcapng` — комментарии будут доступны при повторном открытии и передаче коллегам.
