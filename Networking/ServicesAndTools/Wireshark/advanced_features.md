# Wireshark: Дополнительные Возможности и Настройки

## Дополнительная информация

### Справочник по фильтрам

Важно помнить, что синтаксис **фильтров захвата** и **фильтров отображения** отличается. Фильтры захвата (Capture Filters) используют синтаксис `tcpdump` (например, `host 192.168.1.1` или `port 80`), тогда как фильтры отображения (Display Filters) требуют использования оператора сравнения (`==`) для большинства полей (например, `ip.addr == 192.168.1.1` или `tcp.port == 80`).

#### Фильтры захвата (`-f "..."`)

*Синтаксис `tcpdump`. Применяются при запуске захвата.*

| Сценарий | Фильтр |
|---|---|
| Трафик от/к хосту | `host 192.168.1.1` |
| Трафик к хосту | `dst host 8.8.8.8` |
| Трафик с порта 443 | `port 443` |
| Только TCP или UDP | `tcp or udp` |
| DNS трафик (порт 53) | `udp port 53` |
| Трафик из подсети | `net 192.168.1.0/24` |
| Исключить SSH | `not port 22` |

#### Фильтры отображения (`-Y "..."` или в GUI)

*Более мощный и гибкий синтаксис. Применяются к уже захваченным данным.*

| Действие | Фильтр |
|---|---|
| По IP-адресу (источник или назначение) | `ip.addr == 10.10.42.1` |
| По исходному IP | `ip.src == 10.10.42.1` |
| По протоколу | `http or dns or icmp` |
| По TCP порту | `tcp.port == 25` |
| Флаг TCP SYN | `tcp.flags.syn == 1 && tcp.flags.ack == 0` |
| HTTP Host | `http.host == "example.com"` |
| Широковещательный трафик | `eth.dst == ff:ff:ff:ff:ff:ff` |

### Цветовая маркировка (Coloring Rules)

Wireshark использует цвета для выделения трафика, что помогает быстро находить проблемы.

* **Светло-голубой**: TCP трафик.
* **Светло-зеленый**: HTTP трафик.
* **Темно-синий**: DNS трафик.
* **Черный**: Пакеты с ошибками (например, неверная контрольная сумма TCP).
* **Красный**: Проблемный TCP-трафик (например, повторные передачи).
Правила настраиваются в меню `View -> Coloring Rules...`.

**Важно:** чёрные и красные пакеты не всегда означают реальные ошибки — это может быть следствием **offloading** (аппаратной разгрузки сетевой карты). Для проверки см. **[Диагностика производительности TCP](./tcp_performance_diagnostics.md#сценарий-5-offloading-аппаратная-разгрузка)**.

### Визуализация и комментарии

* **Граф потоков (Flow Graph)**: В меню `Statistics -> Flow Graph` Wireshark может построить графическое представление взаимодействия в выбранном потоке (например, TCP). Это очень удобно для визуального понимания последовательности запросов и ответов, а также для документирования. Графы могут быть экспортированы в различные форматы.
* **Раскраска диалогов (Colorize Conversation)**: Для выделения определенных взаимодействий можно раскрасить все пакеты, относящиеся к конкретному диалогу (например, между двумя IP-адресами). Кликните правой кнопкой мыши по любому пакету в диалоге, выберите `Colorize Conversation` и задайте правила. Правила раскраски настраиваются в `View -> Coloring Rules...`.
* **Добавление комментариев к пакетам**: Кликните правой кнопкой мыши по пакету, выберите `Packet Comment -> Add Packet Comment`. Это позволяет добавлять текстовые заметки к отдельным пакетам, что очень удобно для фиксации выводов или подозрительных моментов при долгом анализе. Комментарии можно отображать в отдельном столбце.

### Дешифрование TLS-трафика

Wireshark может дешифровать TLS-трафик, что критически важно для анализа HTTPS, WebSockets over TLS и других защищенных протоколов.

#### Методы дешифрования

1. **С помощью приватного ключа сервера**: Если у вас есть приватный ключ сервера, используемый для TLS-соединения, его можно указать в `Edit -> Preferences -> Protocols -> TLS`. Добавьте запись с IP-адресом сервера, портом и путем к файлу ключа. Этот метод эффективен для трафика, где вы контролируете серверную часть.
2. **С помощью `(Pre)-Master-Secret log filename` (рекомендуемый для клиентского трафика)**: Современные браузеры (Firefox, Chrome) и приложения, построенные на их движках (Electron-приложения, такие как Slack, Mattermost, клиенты ChatGPT), могут быть настроены на запись своих TLS-сессионных ключей в специальный файл. Wireshark может использовать этот файл для автоматического дешифрования трафика.
    * **Настройка Wireshark**: В `Edit -> Preferences -> Protocols -> TLS` укажите путь к файлу в поле `(Pre)-Master-Secret log filename`.
    * **Запуск браузера/приложения**: Используйте `Tools -> TLS Key Log File -> Launch` в Wireshark. Это запустит браузер со специальными переменными окружения, которые заставят его записывать ключи в указанный файл.
    * **Применимость**: Этот метод позволяет дешифровать трафик, инициированный вашим браузером или Electron-приложениями, включая WebSockets, что дает возможность увидеть сообщения, передаваемые по защищенному соединению.
3. **С помощью MITM-прокси**: Инструменты вроде **Mitmproxy** позволяют перехватывать и дешифровать трафик, выступая в роли промежуточного прокси-сервера.
    * **Настройка**: Запустите Mitmproxy с параметром `--listen-host 127.0.0.1` (порт по умолчанию 8080).
    * **Настройка клиента**: Настройте браузер/приложение на использование прокси `127.0.0.1:8080`.
    * **Установка сертификата**: Для HTTPS-трафика необходимо установить корневой сертификат Mitmproxy в доверенные на клиенте.
    * **Ограничение**: Метод не работает при использовании **SSL Pinning** (см. ниже).
    * **Интеграция с Wireshark**: Mitmproxy может записывать ключи в тот же формат `SSLKEYLOGFILE`, который используется Wireshark.

#### Проблемы расшифровки TLS

**1. SSL Pinning (Certificate Pinning)**

**SSL Pinning** — механизм безопасности, при котором приложение проверяет не только валидность сертификата, но и его соответствие заранее заданным значениям (хеш сертификата, открытый ключ, домен).

* **Проблема**: При попытке MITM-атаки (включая прокси для отладки) приложение обнаруживает подмену сертификата и разрывает соединение.
* **Обход**: Требует модификации приложения (патчинг), динамического перехвата вызовов функций (Frida, Xposed) или отладки на уровне ОС.
* **Где встречается**: Мобильные приложения, браузеры (Firefox, Chrome) для доменов Google и других критичных сервисов, десктопные приложения с повышенными требованиями к безопасности.

**2. Perfect Forward Secrecy (PFS)**

При использовании алгоритмов с PFS (например, ECDHE) для каждой сессии генерируются уникальные эфемерные ключи.

* **Проблема**: Ключи, полученные для одной сессии, бесполезны для расшифровки других сессий.
* **Решение**: Файл `SSLKEYLOGFILE` должен записываться **непрерывно** во время захвата трафика.
* **Важно**: Ключи действительны только для тех сессий, которые были установлены **после** начала записи ключей.

**3. Версионность TLS**

* **TLS 1.2**: Использует последовательную генерацию секретов (premaster secret → master secret → session keys). Перехват на ранних этапах handshake теоретически позволяет расшифровать сессию.
* **TLS 1.3**: Упрощённый handshake (1-RTT), ключи генерируются из множества промежуточных значений, разбросанных по разным сообщениям. Прямое извлечение ключей из памяти затруднено.
* **Влияние на анализ**: TLS 1.3 требует более сложных методов мониторинга (например, отладка процесса lsass.exe в Windows для доступа к SSPI/SChannel).

**4. Хранение ключей в ОС**

* **Windows**: Ключи хранятся в процессе **lsass.exe** (Local Security Authority Subsystem Service) с использованием подсистемы **SChannel** (Secure Channel) и интерфейса **SSPI** (Security Support Provider Interface).
* **Защита**: Процесс lsass.exe защищён от несанкционированного доступа, ключи могут быть зашифрованы дополнительными механизмами.
* **Методы доступа**: Ядерная отладка (kernel debugging) между двумя ВМ, использование специализированных скриптов для дампа ключей из SChannel.

**5. Прикладной уровень шифрования**

Даже после расшифровки TLS данные могут быть зашифрованы на прикладном уровне (например, зашифрованное тело HTTP-запроса, проприетарные протоколы).

> **Важно**: Ключи действительны только для конкретной сессии. После завершения соединения или перезапуска приложения файл `SSLKEYLOGFILE` становится бесполезным для новых сессий.

#### Практический пример: Расшифровка трафика Chromium

1. **Подготовка**:
   * Установите Chromium: `sudo apt install chromium` (Linux).
   * Откройте Wireshark, выберите активный интерфейс.
2. **Запуск с записью ключей**:

   ```bash
   export SSLKEYLOGFILE=~/keylog.txt
   chromium --ssl-key-log-file=~/keylog.txt
   ```

3. **Настройка Wireshark**:
   * `Edit -> Preferences -> Protocols -> TLS`
   * Укажите путь к `~/keylog.txt` в поле `(Pre)-Master-Secret log filename`.
4. **Анализ**:
   * После посещения HTTPS-сайтов в Wireshark появятся записи `Decrypted TLS`, `HTTP2`.
   * Используйте `Follow -> TCP Stream` для просмотра содержимого.

> **Примечание**: Метод работает только с отладочными/специальными сборками браузеров. Продакшен-версии Chrome/Firefox могут требовать дополнительных настроек или не поддерживать запись ключей.
