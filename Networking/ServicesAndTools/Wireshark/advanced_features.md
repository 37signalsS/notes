# Wireshark — продвинутые функции и настройки

## Определения

**Экспертная информация (Expert Info)** — встроенная система автоматического анализа трафика, которая выявляет сетевые аномалии и ошибки протоколов. Она классифицирует пакеты по уровням (Error, Warning, Note, Chat) и предоставляет рекомендации по траблшутингу.

**Правила раскраски (Coloring Rules)** — механизм визуальной разметки списка пакетов на основе фильтров отображения. Позволяет мгновенно выделять критические ошибки (красным), успешные HTTP-запросы (зеленым) или специфические типы трафика (например, сканирование портов).

**Конфигурационные профили (Profiles)** — изолированные наборы настроек Wireshark (фильтры, колонки, макросы, правила раскраски). Позволяют мгновенно переключать рабочую среду под конкретную задачу (например, «Анализ K8s», «Отладка VoIP», «Security Audit»).

**Граф потоков (Flow Graph)** — визуализация обмена данными между узлами в виде временной диаграммы (Sequence Diagram). Помогает отслеживать логику «запрос-ответ» и последовательность установки соединений (Handshakes).

**Статистика времени ответа (Service Response Time, SRT)** — метрика задержки между запросом и соответствующим ему ответом на уровне приложения. Поддерживается для многих протоколов (SMB, RPC, HTTP, DNS, LDAP).

**Геолокация (GeoIP)** — процесс обогащения данных об IP-адресах информацией об их географическом местоположении и принадлежности к автономным системам (ASN) с использованием внешних баз данных (например, MaxMind).

## Базовые концепции

### Экспертная информация (Expert Info)

Система работает «на лету» во время диссекции пакетов. Уровни важности:
*   **Error (Красный):** Серьезные проблемы (например, неверный формат пакета, критическая ошибка протокола).
*   **Warning (Желтый):** Подозрительное поведение (например, TCP Retransmissions, Dup ACK, Fast Retransmission).
*   **Note (Голубой):** Информационные события (например, TCP Keep-Alive, Window Update).
*   **Chat (Зеленый):** Стандартные рабочие процессы (например, GET-запросы, SYN-пакеты).

Доступ через меню: `Analyze → Expert Information`.

### Управление профилями и автоматизация (Wireshark 4.4+)

Профили хранятся в отдельных директориях и включают все настройки интерфейса.
*   **Автоматическое переключение:** Начиная с v4.4, профиль можно привязать к конкретному display-фильтру. При открытии дампа, содержащего соответствующий трафик, Wireshark сменит профиль автоматически.
*   **Синхронизация колонок:** Колонки в списке пакетов теперь могут содержать сложные выражения, включая арифметические операции (например, `frame.len * 8` для расчета бит).

### Система раскраски (Coloring Rules)

Правила обрабатываются сверху вниз. Первое совпавшее правило определяет цвет пакета.
*   **Default:** Wireshark поставляется с набором правил для TCP-ошибок, HTTP и широковещательного трафика.
*   **Custom:** Можно создавать временные правила раскраски («Colorize Conversation») для отслеживания конкретного потока данных во время сессии.

### Графики и статистика

1.  **I/O Graphs (`Statistics → I/O Graphs`):** Построение графиков интенсивности трафика. В версии 4.4+ доступен интервал в **1 микросекунду** для поиска микро-всплесков (micro-bursts).
2.  **TCP Stream Graphs:** Специализированные графики для анализа TCP (Sequence Numbers, Window Scaling, Throughput). Подробнее: **[Графики TCP-потока](tcp_performance/tcp_performance_analysis_tools.md)**.
3.  **Endpoint Statistics:** Списки всех узлов с указанием объема переданных данных, что полезно для поиска «болтливых» клиентов.

## Практические сценарии

### Сценарий 1: Быстрый поиск причин деградации через Expert Info

При жалобах на «тормоза» в сети:
1. Откройте `Analyze → Expert Information`.
2. Перейдите на вкладку `Warnings`.
3. Ищите большое количество `TCP Retransmission` и `Previous segment not captured`. Это явный признак потерь пакетов на физическом уровне или перегрузки буферов оборудования.

### Сценарий 2: Создание профиля для анализа Kubernetes трафика

Для удобства отладки в K8s:
1. Создайте новый профиль `Kubernetes` (внизу справа в GUI).
2. Добавьте кастомные колонки для отображения IP: `ip.src` и `ip.dst`.
3. Если используется `cilium` или другие CNI с поддержкой метаданных в трафике, добавьте соответствующие поля в колонки.
4. Сохраните фильтры отображения для быстрого поиска ошибок: `http.response.code >= 400`.

### Сценарий 3: Расследование медленных БД-запросов через SRT

1. Выберите `Statistics → Service Response Time → MySQL` (или PostgreSQL).
2. Нажмите `Create Stat`.
3. В таблице будет приведено время выполнения каждого типа запроса. Сортировка по `Max SRT` покажет самые медленные запросы, которые можно изучить детально, кликнув на строку.

### Сценарий 4: Настройка GeoIP для анализа атак

1. Скачайте базы MaxMind (GeoLite2-City, GeoLite2-AS).
2. Укажите путь к ним в `Edit → Preferences → Name Resolution → MaxMind database directories`.
3. Перезагрузите Wireshark. Теперь в полях `ip.geoip.src_city` и `ip.geoip.src_asname` будет доступна информация о географии. Можно построить карту: `Statistics → Endpoint → Map`.

## Дополнительная информация

### Горячие клавиши для продвинутых пользователей

| Сочетание | Действие |
| :--- | :--- |
| `Ctrl + Alt + Shift + P` | Быстрое меню переключения профилей |
| `Ctrl + Shift + O` | Показать только пакеты, соответствующие фильтру отображения (включая expert info) |
| `Ctrl + .` | Следующий пакет с экспертной информацией |
| `Ctrl + ,` | Предыдущий пакет с экспертной информацией |
