# Wireshark — продвинутые функции и настройки

## Определения

**Правила раскраски (Coloring Rules)** — настраиваемые правила цветовой маркировки пакетов в интерфейсе Wireshark, предназначенные для визуального выделения определенных типов трафика, протоколов или сетевых аномалий.

**Граф потоков (Flow Graph)** — инструмент визуализации, представляющий последовательность обмена пакетами между узлами (диалог) в виде временной диаграммы. Позволяет наглядно проследить логику работы протоколов.

**Комментарии к пакетам (Packet Comment)** — текстовые заметки, которые аналитик может прикрепить к конкретным пакетам внутри файла захвата (поддерживается только форматом `pcapng`).

**Раскраска диалогов (Colorize Conversation)** — функция быстрого выделения цветом всех пакетов, относящихся к одному сетевому соединению (на основе пары IP-адресов и портов).

## Основные концепции

### Система цветовой маркировки

Wireshark использует цвета для мгновенной идентификации состояния трафика. По умолчанию применяются следующие правила:

| Цвет фона | Тип трафика или состояние |
| :--- | :--- |
| Светло-голубой | Стандартный TCP-трафик |
| Светло-зелёный | HTTP-сообщения |
| Тёмно-синий | DNS-запросы и ответы |
| Чёрный | Ошибки (например, неверная контрольная сумма) |
| Красный | Аномалии TCP (повторные передачи, нарушение порядка пакетов) |

Настройка правил осуществляется через меню `View → Coloring Rules...`. 

> **Важно:** чёрная или красная маркировка не всегда свидетельствует о реальной проблеме в сети. Например, «ошибки» контрольных сумм часто являются следствием работы **Checksum Offloading** сетевой карты. Подробности — в **[диагностике offloading](tcp_performance/tcp_network_losses_and_offloading.md)**.

### Визуализация потоков (Flow Graph)

Инструмент `Statistics → Flow Graph` создает диаграмму взаимодействий. Это критически важно при анализе:
- Сложных handshake-последовательностей (TCP, TLS).
- Многошаговых транзакций (SIP, HTTP/2).
- Причин задержек между запросом и ответом.

Результат можно экспортировать в форматы PNG, SVG или PDF для включения в отчеты.

### Аналитические заметки

Использование комментариев (`Клик правой кнопкой → Packet Comment`) позволяет документировать процесс расследования инцидента непосредственно внутри дампа. Это упрощает совместную работу, так как при передаче файла в формате `pcapng` коллега увидит все пометки аналитика.

### Горячие клавиши (GUI)

Эффективная работа в графическом интерфейсе невозможна без использования быстрых клавиш:

| Сочетание | Действие |
| :--- | :--- |
| `Ctrl + E` | Начать или остановить захват пакетов |
| `Ctrl + R` | Перезапустить текущий захват |
| `Ctrl + F` | Поиск внутри пакетов (по строке, hex или полю) |
| `/` (слэш) | Быстрый переход к строке фильтра отображения |
| `Ctrl + /` | Очистить текущий фильтр отображения |

## Практические сценарии

### Сценарий 1: Создание правила для выделения подозрительного трафика

Для визуального мониторинга попыток сканирования портов или атак:
1. Откройте `View → Coloring Rules`.
2. Нажмите `+` (New) для создания нового правила.
3. В поле **Name** введите `TCP SYN Scan`.
4. В поле **Filter** введите `tcp.flags.syn == 1 && tcp.flags.ack == 0`.
5. Установите яркий цвет фона (например, оранжевый).
6. Переместите правило в самый верх списка.

### Сценарий 2: Анализ последовательности HTTP-вызовов

1. Выберите любой HTTP-пакет.
2. Используйте `Statistics → Flow Graph`.
3. В окне настроек выберите `Limit to display filter` (если применен фильтр).
4. Установите тип потока `TCP Flows` или `HTTP`.
5. Это позволит увидеть, как один HTTP-запрос порождает серию TCP-подтверждений.

### Сценарий 3: Быстрая изоляция диалога

В загруженном дампе с тысячами пакетов:
1. Найдите интересующий пакет.
2. Нажмите правой кнопкой мыши → `Colorize Conversation → TCP → Color 1`.
3. Все пакеты этого соединения будут окрашены в выбранный цвет, даже если вы прокручиваете список или меняете фильтры.
