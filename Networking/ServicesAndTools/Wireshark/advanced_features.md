# Wireshark — продвинутые функции и настройки

## Определения

**Правила раскраски (Coloring Rules)** — настраиваемые правила цветовой маркировки пакетов в интерфейсе Wireshark, предназначенные для визуального выделения определенных типов трафика, протоколов или сетевых аномалий.

**Граф потоков (Flow Graph)** — инструмент визуализации, представляющий последовательность обмена пакетами между узлами (диалог) в виде временной диаграммы. Позволяет наглядно проследить логику работы протоколов.

**Комментарии к пакетам (Packet Comment)** — текстовые заметки, которые аналитик может прикрепить к конкретным пакетам внутри файла захвата (поддерживается только форматом `pcapng`).

**Конфигурационные профили (Profiles)** — наборы настроек (фильтры, колонки, правила раскраски), позволяющие быстро переключаться между различными сценариями анализа (например, «Troubleshooting HTTP» vs «Security Audit»).

**Статистика времени ответа (Service Response Time, SRT)** — метрика, вычисляемая Wireshark для различных протоколов (SMB, RPC, HTTP), показывающая задержку между запросом и соответствующим ответом на уровне приложения.

## Основные концепции

### Система цветовой маркировки

Wireshark использует цвета для мгновенной идентификации состояния трафика. По умолчанию применяются следующие правила:

| Цвет фона | Тип трафика или состояние |
| :--- | :--- |
| Светло-голубой | Стандартный TCP-трафик |
| Светло-зелёный | HTTP-сообщения |
| Тёмно-синий | DNS-запросы и ответы |
| Чёрный | Ошибки (например, неверная контрольная сумма) |
| Красный | Аномалии TCP (повторные передачи, нарушение порядка пакетов) |

Настройка правил осуществляется через меню `View → Coloring Rules...`. Чёрная или красная маркировка может быть следствием работы **Checksum Offloading**. Подробности — в **[диагностике offloading](tcp_performance/tcp_network_losses_and_offloading.md)**.

### Графики ввода-вывода (I/O Graphs)

Инструмент `Statistics → I/O Graphs` позволяет визуализировать интенсивность трафика во времени.
- **Microsecond Precision:** В Wireshark 4.4+ поддерживаются интервалы до 1 микросекунды для анализа микро-всплесков.
- **Сравнение фильтров:** Можно построить несколько графиков одновременно (например, общий трафик vs трафик ошибок `tcp.analysis.retransmission`).

### Визуализация потоков (Flow Graph)

Инструмент `Statistics → Flow Graph` создает диаграмму взаимодействий. Это критически важно при анализе:
- Сложных handshake-последовательностей (TCP, TLS).
- Многошаговых транзакций (SIP, HTTP/2).
- Причин задержек между запросом и ответом.

### Управление профилями (Wireshark 4.4+)

Профили позволяют адаптировать интерфейс под конкретную задачу.
- **Автоматическое переключение профилей:** Возможность привязать профиль к display-фильтру. Wireshark автоматически сменит профиль при открытии соответствующего дампа.
- **Кастомные колонки:** В новых версиях поддерживаются арифметические операции прямо в именах колонок (например, расчет битрейта `frame.len * 8`).

### Геолокация (GeoIP)

Wireshark может сопоставлять IP-адреса с географическим положением, используя базы данных MaxMind.
- Настройка: `Edit → Preferences → Name Resolution → MaxMind database directories`.
- Позволяет фильтровать трафик по странам (`ip.geoip.country == "Germany"`) и визуализировать карту соединений.

## Практические сценарии

### Сценарий 1: Создание правила для выделения сканирования портов

Для визуального мониторинга попыток атак:
1. Откройте `View → Coloring Rules`.
2. Добавьте правило с фильтром: `tcp.flags.syn == 1 && tcp.flags.ack == 0`.
3. Установите оранжевый цвет фона и переместите правило в самый верх списка.

### Сценарий 2: Поиск «зависших» запросов через SRT

1. Перейдите в `Statistics → Service Response Time → HTTP`.
2. Wireshark выведет таблицу с минимальным, максимальным и средним временем ответа.
3. Это позволяет быстро найти конкретные пакеты, на которых приложение «задумалось» (задержка > 1-2 сек).

### Сценарий 3: Расследование всплесков трафика (I/O Graphs)

1. Откройте `Statistics → I/O Graphs`.
2. Создайте два графика:
   - График 1 (черный): `all packets`.
   - График 2 (красный): `tcp.analysis.retransmission`.
3. Если всплеск на красном графике совпадает с падением на черном — проблема в потерях на канале связи.

## Дополнительная информация

### Горячие клавиши (GUI)

| Сочетание | Действие |
| :--- | :--- |
| `Ctrl + E` | Начать или остановить захват пакетов |
| `Ctrl + R` | Перезапустить текущий захват |
| `Ctrl + F` | Поиск внутри пакетов (строка, hex или поле) |
| `/` (слэш) | Переход к строке фильтра отображения |
