# Диагностика проблем производительности клиента TCP

## Определения

**TCP Zero Window** — состояние, при котором получатель (клиент) объявляет размер окна равным нулю. Это сигнал отправителю о том, что буфер приема переполнен и прием новых данных невозможен до освобождения места.

**TCP Window Full** — событие в Wireshark, означающее, что отправитель заполнил всё доступное окно получателя и вынужден приостановить передачу в ожидании подтверждения (ACK).

**Bytes in Flight (Байты в полете)** — количество данных, которые были отправлены, но еще не подтверждены. Достижение этим значением предела `Window Size` указывает на полное заполнение буфера получателя.

## Основные концепции

### Механизм возникновения задержек на стороне клиента

Проблема «тормозит клиент» обычно связана с тем, что приложение медленнее считывает данные из сокета, чем сеть их доставляет. Процесс выглядит следующим образом:

1.  **Заполнение буфера приема**: Данные накапливаются в системном буфере `SO_RCVBUF`.
2.  **Снижение анонсированного окна (Advertised Window)**: Клиент в каждом ACK-пакете сообщает серверу о всё меньшем свободном месте (например, `64KB → 32KB → 16KB`).
3.  **Zero Window**: Окно достигает нуля, сервер прекращает передачу.
4.  **Window Probe**: Сервер периодически отправляет проверочные пакеты, чтобы узнать, не освободилось ли место.
5.  **Возобновление**: Приложение вычитывает данные, буфер освобождается, клиент отправляет `Window Update`, и передача продолжается.

### Основные причины переполнения буфера

-   **Медленная логика приложения**: Обработка данных (десериализация, запись в БД) занимает больше времени, чем их получение.
-   **Высокая загрузка CPU**: Нехватка ресурсов процессора на обработку сетевого стека и прерываний.
-   **Ограничения ОС**: Слишком малый размер системных буферов TCP по умолчанию.

## Практические сценарии

### Диагностика в Wireshark

При анализе дампа трафика со стороны клиента ищите следующие признаки:

#### 1. Анализ экспертной информации
Перейдите в `Analyze → Expert Information`. Наличие большого количества предупреждений `TCP Zero Window` или `TCP Window Full` — прямой признак того, что клиент является узким местом.

#### 2. Мониторинг размера окна
Добавьте столбец `Calculated Window Size`. Если вы видите постепенное уменьшение этого значения до нуля при сохранении стабильно низкого RTT (Round-Trip Time), значит, сеть работает быстро, а клиент не успевает.

#### 3. Визуализация через графики
Используйте `Statistics → TCP Stream Graphs → Window Scaling`. 
- Падение графика до нулевой отметки на длительные интервалы подтверждает проблему переполнения буфера.

### Методы решения проблемы

#### Настройка операционной системы (Linux)
Увеличьте максимальный размер буфера приема:
```bash
# Установка максимального размера буфера в 16 Мбайт
sudo sysctl -w net.core.rmem_max=16777216
sudo sysctl -w net.ipv4.tcp_rmem='4096 87380 16777216'
```
Подробности в **[оптимизации буферов TCP](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_buffer_tuning.md)**.

#### Оптимизация приложения
- Используйте асинхронный ввод-вывод (например, `io_uring` или библиотеки на базе `epoll`).
- Выносите тяжелую обработку данных в отдельные потоки, чтобы не блокировать поток чтения из сокета.
- Увеличьте приоритет процесса с помощью `nice`.
