# Диагностика потерь в сети и Offloading TCP

## Сценарий 3: Потери в сети

**Симптомы:**

- Много ретрансмитов и DupACK
- Скорость передачи падает до нуля периодически
- RTT нестабильный

### Диагностика

#### 1. Проверить Expert Information

```
Analyze → Expert Information
```

- Искать: `Retransmission`, `Fast Retransmission`, `Out-Of-Order`, `DupACK`
- Подсчитать процент ошибок:

  ```
  (Retransmits / Total Packets) × 100%
  ```

#### 2. IO Graph для визуализации потерь

```
Statistics → IO Graphs
```

- Добавить фильтр: `tcp.analysis.retransmission`
- Красная линия — ошибки
- Чёрная линия — все пакеты

#### 3. Настроить масштабирование

- Axis Factor: ×10 или ×100 для видимости малых значений
- Interval: 100ms для детализации

### Интерпретация

| Процент потерь | Статус |
| :--- | :--- |
| **< 0,1%** | Норма, случайные потери |
| **0,1–1%** | Допустимо, но стоит наблюдать |
| **> 1%** | Проблема сети |

### Пример диагностики

```
Всего пакетов: 10,000
Retransmissions: 1,300 (13%)
График IO Graph: регулярные провалы до 0
Вывод: серьёзные потери в сети
```

### Причины и решение

| Причина | Решение |
| :--- | :--- |
| **Плохой сигнал Wi-Fi** | Проверить уровень сигнала, переключиться на 5 ГГц |
| **Перегруженность канала** | Проверить загрузку канала, сменить частоту |
| **Повреждение кабеля** | Заменить кабель, проверить коннекторы |
| **Ошибки оборудования** | Проверить логи свитчей/роутеров |

## Сценарий 4: Ограничение скорости сети

**Симптомы:**

- Нет потерь (< 0,1%)
- Скорость стабильная но низкая
- RTT в норме

### Диагностика

#### 1. Сравнить трафик с двух сторон

- Захват на клиенте и сервере одновременно
- Сравнить Delta Time

#### 2. Анализ задержек

- Клиент видит задержку получения ответа: 136ms
- Сервер видит задержку отправки: 34ms
- Разница (102ms) — задержка в сети

#### 3. Throughput график

- Стабильная линия без провалов
- Скорость ограничена на постоянном уровне

### Причины

| Причина | Описание |
| :--- | :--- |
| **Ограничение провайдера** | Шейперы на стороне ISP |
| **Низкая пропускная способность** | Ограничение канала |
| **QoS политики** | Приоритизация трафика |

## Сценарий 5: Offloading (аппаратная разгрузка)

### Определение

**Offloading** — делегирование обработки TCP-пакетов сетевой карте или драйверу:

- **TSO (TCP Segmentation Offload)** — сегментация больших пакетов
- **LRO (Large Receive Offload)** — сборка маленьких пакетов
- **Checksum Offloading** — вычисление контрольных сумм

### Проблема для анализа

Wireshark видит «некорректные» пакеты до обработки offloading:

- Пакеты больше MSS (например, 64KB вместо 1460 байт)
- Ошибки контрольных сумм
- Ложные Retransmit и DupACK

### Диагностика

#### 1. Проверить размер сегментов

```
Добавить столбец: TCP Segment Len
```

- Если размер > MSS (1460 байт) → offloading включён

#### 2. Сравнить с Expert Information

- Много ошибок (Retransmit, DupACK)
- Но Throughput стабильный без провалов
- Вывод: ложные ошибки из-за offloading

#### 3. Проверить IO Graph

- Если скорость не падает до 0 при «ошибках» → offloading

### Как отключить для теста

```bash
# Проверка статуса
ethtool -k eth0 | grep offload

# Отключение
ethtool -K eth0 tso off gso off gro off
```

**Важно:** после тестов включить обратно!

### Настройка захвата

- Некоторые сетевые карты позволяют захватывать **после** offloading
- Выбрать интерфейс в режиме промискуитета
