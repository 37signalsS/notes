# Графики Wireshark для анализа TCP

## Определения

**Графики TCP-потока (TCP Stream Graphs)** — специализированный набор инструментов визуализации в Wireshark, позволяющий анализировать поведение конкретного сетевого соединения (последовательность сегментов, задержки, скорость и размер окна).

**Графики ввода-вывода (IO Graphs)** — универсальный инструмент для построения графиков интенсивности трафика по всему дампу или по конкретным фильтрам. Позволяет накладывать несколько метрик друг на друга для корреляционного анализа.

**tcptrace (Time-Sequence Graph)** — расширенный вид временной диаграммы, который отображает не только номера последовательности (Sequence Numbers), но и анонсированное окно получателя (Receive Window), а также SACK-блоки.

## Основные концепции

### Виды графиков TCP Stream Graphs

Доступны через меню: `Statistics → TCP Stream Graphs`. Для работы требуется предварительно выбрать любой пакет интересующего потока.

| График | Назначение | Особенности (Wireshark 4.x) |
| :--- | :--- | :--- |
| **Time-Sequence (tcptrace)** | Анализ Seq, ACK и Window. | Показывает «потолок» окна; идеален для поиска Window Full. |
| **Throughput** | Мгновенная пропускная способность. | Поддержка усреднения (MA) для сглаживания графиков. |
| **Round Trip Time (RTT)** | Задержка подтверждений. | Визуализация джиттера и скачков RTT при перегрузках. |
| **Window Scaling** | Динамика буфера получателя. | Помогает выявить медленное вычитывание данных приложением. |

### Продвинутые возможности IO Graphs

Инструмент `Statistics → IO Graphs` позволяет анализировать не только объем трафика, но и его качество.
- **Интервалы (Tick interval):** В Wireshark 4.4+ поддерживаются интервалы до **1 микросекунды**, что необходимо для выявления микро-всплесков (Micro-bursts), вызывающих дропы на коммутаторах.
- **Единицы измерения (Y-axis):** Можно переключаться между `Packets`, `Bytes` и `Bits` (для оценки утилизации канала в Мбит/с).
- **SMA (Simple Moving Average):** Позволяет сглаживать пики для понимания общего тренда.

## Практические сценарии

### Сценарий 1: Диагностика ограничения скоростью окна (Window Limited)

Если скорость низкая, а потерь нет:
1. Откройте `Statistics → TCP Stream Graphs → Time-Sequence (tcptrace)`.
2. Если линия Sequence Numbers (отправленные данные) постоянно упирается в верхнюю линию Advertised Window — отправитель ограничен буфером получателя.
3. Решение: Увеличение `tcp_rmem` или оптимизация приложения-клиента.

### Сценарий 2: Корреляция потерь и скорости через IO Graphs

Для доказательства того, что «сеть тормозит»:
1. Откройте `Statistics → IO Graphs`.
2. Настройте два графика:
   - График 1 (черный): `all packets`, Y-axis: `Bits/s`.
   - График 2 (красный): `tcp.analysis.retransmission`, Y-axis: `Packets`.
3. Если каждый всплеск красного графика сопровождается «ямой» на черном — причина падения скорости в потерях пакетов.

### Сценарий 3: Анализ микро-всплесков (Burst Analysis)

При «загадочных» потерях на высокоскоростных интерфейсах:
1. В IO Graphs установите `Tick interval` в `1 ms` или `100 us`.
2. Ищите резкие пики (Spikes), превышающие среднюю скорость в 5-10 раз.
3. Такие всплески мгновенно переполняют буферы сетевых карт, вызывая дропы, которые не видны при усреднении в 1 секунду.

## Дополнительная информация

### Настройка осей и легенды

- **Y-axis (Calculated):** Используйте `SUM(tcp.len)` для построения графика объема переданных данных.
- **Save Graphs:** Все графики можно экспортировать в PDF или PNG для отчетов (`File → Export` в окне графика).
