# Графики Wireshark для анализа TCP

## Определения

**Графики TCP-потока (TCP Stream Graphs)** — специализированный набор инструментов визуализации в Wireshark, позволяющий анализировать поведение конкретного сетевого соединения (последовательность сегментов, задержки, скорость и размер окна).

**Графики ввода-вывода (IO Graphs)** — универсальный инструмент для построения графиков интенсивности трафика по всему дампу или по конкретным фильтрам (например, визуализация только ошибок ретрансмиссии).

## Основные концепции

### Виды графиков TCP Stream Graphs

Доступны через меню: `Statistics → TCP Stream Graphs`. Для работы требуется предварительно выбрать любой пакет интересующего потока.

| График | Назначение |
| :--- | :--- |
| **Time-Sequence (Stevens)** | Визуализация последовательности передачи сегментов во времени. |
| **Throughput** | Фактическая пропускная способность (скорость передачи полезных данных). |
| **Round Trip Time (RTT)** | График задержек между отправкой данных и получением подтверждения (ACK). |
| **Window Scaling** | Динамика изменения размера окна приема на стороне получателя. |

### Особенности IO Graphs

Доступны через меню: `Statistics → IO Graphs`. Основное преимущество — возможность одновременного отображения нескольких метрик разными цветами.

**Ключевые фильтры для анализа ошибок:**
- `tcp.analysis.retransmission` — поиск потерянных сегментов.
- `tcp.analysis.zero_window` — отслеживание переполнения буферов.
- `tcp.analysis.duplicate_ack` — поиск признаков нарушения порядка пакетов.

## Практические сценарии

### Анализ последовательности пакетов (Stevens)

Используется для выявления пауз в передаче данных.
- **Интерпретация**: Прямая наклонная линия означает стабильную передачу. Горизонтальные участки (паузы) указывают на ожидание тайм-аута или внутренние задержки приложения.
- **Применение**: Поиск задержек на стороне сервера.

### Мониторинг пропускной способности (Throughput)

Позволяет увидеть влияние сетевых потерь на скорость.
- **Интерпретация**: Резкие провалы до нуля часто совпадают по времени с событиями `Retransmission` в Expert Information. Плавное снижение может указывать на работу алгоритмов управления перегрузкой.
- **Применение**: Проверка стабильности канала связи.

### Диагностика буферов через Window Scaling

Отслеживание того, как клиент справляется с нагрузкой.
- **Интерпретация**: Если линия графика падает до нуля — клиент отправил `Zero Window`, и передача данных будет приостановлена сервером до освобождения места в буфере.
- **Применение**: Отладка медленных клиентов или БД.

### Визуализация ошибок через IO Graphs

Для наглядного представления доли ошибок в общем трафике:
1.  Откройте `Statistics → IO Graphs`.
2.  Создайте новый график (кнопка `+`).
3.  В поле **Display Filter** введите `tcp.analysis.retransmission`.
4.  Установите тип **Style** на `FBar` и выберите яркий цвет (например, красный).
5.  Это позволит мгновенно увидеть периоды «сетевого шторма» на фоне нормальной работы.
