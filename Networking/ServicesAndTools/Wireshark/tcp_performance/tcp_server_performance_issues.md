# Диагностика проблем производительности сервера TCP

## Сценарий 1: Тормозит сервер

**Симптомы:**

- Большие задержки между пакетами **на стороне сервера**
- Клиент подтверждает быстро (RTT в микросекундах)
- Паузы в передаче данных без видимых причин

### Диагностика

#### 1. Построить график Time-Sequence (Stevens)

```
Statistics → TCP Stream Graphs → Time-Sequence (Stevens)
```

- Паузы видны как горизонтальные линии
- По одному графику неясно, на чьей стороне проблема

#### 2. Проверить RTT

```
Statistics → TCP Stream Graphs → Round Trip Time Graph
```

- Стабильный низкий RTT (микросекунды) → клиент работает быстро

#### 3. Отсортировать по Delta Time

- Сортировка по убыванию
- Если в топе пакеты с задержкой от сервера → проблема на сервере

#### 4. Проверить Throughput

```
Statistics → TCP Stream Graphs → Throughput
```

- «Пилообразный» график с паузами → троттлинг ресурсов (CPU, Docker limits)

### Причины

| Причина | Описание |
| :--- | :--- |
| **Ограничение CPU** | Docker container, cgroups ограничивают процессорное время |
| **Блокировка приложения** | I/O операции, блокировки (locks), сборка мусора (GC) |
| **Нехватка ресурсов** | Недостаточно CPU, памяти, дискового I/O |

### Пример диагностики

```
Сервер отправляет пакет → Пауза 82ms → Отправляет следующий
Клиент подтверждает через 125μs (быстро)
Вывод: сервер тормозит
```

### Решение

1. **Проверить использование CPU:**

   ```bash
   top -H -p <pid_приложения>
   ```

2. **Проверить ограничения Docker:**

   ```bash
   docker stats <container>
   docker inspect <container> | grep -i cpu
   ```

3. **Проверить I/O:**

   ```bash
   iostat -x 1
   iotop
   ```

4. **Проверить логи приложения** — поиск блокирующих операций
