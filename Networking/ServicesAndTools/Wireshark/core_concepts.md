# Wireshark — основные концепции

## Определения

**Фильтр захвата (Capture Filter)** — фильтр, применяемый на уровне библиотеки `libpcap` (Linux) или `Npcap` (Windows) непосредственно **до** записи пакетов в файл. Он отбрасывает лишний трафик на этапе получения данных. Использует синтаксис в стиле `tcpdump`.

**Фильтр отображения (Display Filter)** — фильтр, применяемый в интерфейсе Wireshark к уже захваченным и сохранённым пакетам. Он позволяет гибко скрывать или показывать данные на основе любых полей протоколов. Использует собственный синтаксис Wireshark.

**Промискусный режим (Promiscuous Mode)** — режим работы сетевого адаптера, при котором он принимает все пакеты в сегменте сети, включая те, что не адресованы данному хосту.

**Разрешение имён (Name Resolution)** — процесс преобразования числовых адресов в понятные человеку имена: MAC-адреса преобразуются в названия производителей (через OUI — Organizationally Unique Identifier), а IP-адреса — в доменные имена (через DNS).

**Вынос вычисления контрольных сумм (Checksum Offload)** — технология, при которой расчет контрольных сумм пакетов выполняется сетевой картой (NIC) аппаратно. Это часто приводит к ложным сообщениям о «плохих контрольных суммах» в Wireshark.

**Срез пакета (Packet Slicing / Snaplen)** — ограничение объема данных, сохраняемых для каждого пакета (например, сохранение только первых 64 или 96 байт заголовков). Позволяет экономить место при захвате без потери структуры L2-L4.

**Удалённый захват (Remote Capture / Pipes)** — метод передачи потока пакетов с удалённого узла на локальную машину с Wireshark через SSH-туннель или именованный канал (pipe).

## Основные концепции

### Механизмы захвата пакетов

В Linux захват осуществляется через сокеты семейства **`AF_PACKET`** или современный интерфейс **`AF_XDP`** (для высокопроизводительных систем). Для работы без прав `root` используется:

1. Добавление пользователя в группу `wireshark`.
2. Установка `POSIX capabilities` (`cap_net_raw` и `cap_net_admin`) на исполняемый файл `dumpcap`.

### Захват в контейнеризированных средах

В Docker и Kubernetes каждый под имеет собственный сетевой неймспейс (**Network Namespace**), поэтому стандартный захват на хосте не видит внутренний трафик контейнеров:

- **Ephemeral Containers:** Использование `kubectl debug` с образом `netshoot` для подключения к неймспейсу пода.
- **Sidecar-инъекция:** Добавление временного контейнера с инструментами захвата в Pod.
- **eBPF (Inspektor Gadget):** Захват трафика на уровне ядра без внедрения в контейнеры. Идеально для «distroless» образов.
- **nsenter:** Вход в неймспейс контейнера напрямую с хоста: `nsenter -t <PID> -n tcpdump`.

### Фильтрация трафика

#### Фильтры захвата (Capture Filters)

Используются для экономии ресурсов при высоком трафике. Если пакет не прошел этот фильтр, он не попадает в буфер и на диск.

Примеры:
- `host 192.168.1.1` — трафик конкретного узла.
- `net 10.0.0.0/8` — трафик всей подсети.
- `tcp and port 443` — только HTTPS.

#### Фильтры отображения (Display Filters)

Позволяют находить аномалии в уже захваченном дампе. Поддерживают арифметику и логику (Wireshark 4.x).

Примеры:
- `ip.addr == 192.168.1.1` — поиск по IP.
- `http.request.method == "POST"` — только POST-запросы.
- `frame.time_delta > 0.5` — поиск пакетов с задержкой более 500 мс.

### Инкапсуляция и иерархия

Wireshark представляет пакет как стек протоколов:
`L1 (Physical) → L2 (Data Link) → L3 (Network) → L4 (Transport) → L7 (Application)`.

Для SRE важно отслеживать **Microsecond Precision** — Wireshark позволяет видеть временные метки с точностью до микросекунд, что критично для отладки микро-всплесков (micro-bursts).

## Практические сценарии

### Диагностика Checksum Offloading

Если пакеты помечены `Bad Checksum`, но сервис работает:
1. Проверьте: `ethtool -k eth0 | grep checksum`.
2. Если `tx-checksumming` включен, Wireshark видит пакет **до** того, как сетевая карта запишет в него верную сумму. Это норма.

### Удаленный захват через SSH

Для анализа трафика на сервере в реальном времени в локальном GUI:
```bash
ssh user@remote "sudo dumpcap -P -i eth0 -w -" | wireshark -k -i -
```

### Выбор стратегии захвата

| Ситуация | Рекомендация |
| :--- | :--- |
| **Обычная отладка** | Захватывайте всё (полный дамп). |
| **Высокая нагрузка (>1 Гбит/с)** | Используйте Capture Filters и Packet Slicing (`-s 96`). |
| **Безопасность (PII/Secrets)** | Используйте фильтрацию по порту и ограничивайте snaplen. |
| **Контейнеры (K8s)** | Используйте `kubectl sniff` или eBPF. |

## Дополнительная информация

### TCP-флаги в анализе

| Флаг | Значение для SRE |
| :--- | :--- |
| **SYN** | Попытка соединения. Всплеск SYN может быть признаком DDoS или утечки сокетов. |
| **RST** | Аварийный разрыв. Часто означает отказ приложения или блокировку файрволом. |
| **FIN** | Корректное закрытие. Зависание в FIN_WAIT указывает на проблемы в коде приложения. |
