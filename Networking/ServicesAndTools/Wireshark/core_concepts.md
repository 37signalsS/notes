# Wireshark: Основные Концепты

## Определения

**Capture Filter** — фильтр, применяемый **до** записи пакетов на уровне библиотеки `libpcap`/`Npcap`. Отбрасывает нерелевантный трафик до сохранения в файл. Синтаксис: `tcpdump`-style.

**Display Filter** — фильтр, применяемый **после** захвата к уже записанным пакетам в интерфейсе Wireshark. Гибкий синтаксис с операторами сравнения (`==`, `!=`, `>`, `contains`).

**Promiscuous Mode** — режим сетевого интерфейса, при котором принимаются все пакеты в сегменте сети, а не только адресованные данному хосту.

**Name Resolution** — процесс преобразования адресов в человекочитаемые имена: MAC → производитель (OUI), IP → доменное имя (DNS).

**Checksum Offload** — аппаратное вычисление контрольных сумм сетевой картой (NIC). При включении Wireshark захватывает пакеты до вычисления checksum, что может отображаться как «bad checksum» без реальной ошибки.

## Основные концепции

### Механизм захвата пакетов

В Linux захват происходит через сокеты семейства **`AF_PACKET`** — «сырые» пакеты с сетевого интерфейса. Для работы `dumpcap`/`tcpdump` обычно требуются привилегии `root`. В современных дистрибутивах это решается:

- Добавлением пользователя в группу `wireshark`: `sudo usermod -aG wireshark $USER`
- Настройкой `POSIX capabilities` на бинарнике `dumpcap`

Инструменты и форматы файлов описаны в **[Определения Wireshark](./definitions.md)**.

### Промискусный режим

Включается автоматически при захвате на физических интерфейсах. На loopback (`lo`) не требуется — все пакеты и так доступны. Для беспроводных интерфейсов (`wlan0`) промискусный режим не эквивалентен **monitor mode** (захват 802.11-фреймов без ассоциации с точкой доступа).

### Фильтрация трафика

#### Capture Filters

Применяются библиотекой `libpcap` **до** записи. Уменьшают размер файла дампа, но не допускают анализа отброшенных пакетов.

```
host 192.168.1.1          # трафик от/к хосту
port 443                  # трафик порта 443
net 10.0.0.0/8            # трафик подсети
not port 22               # исключить SSH
tcp and port 80           # только TCP на порт 80
```

Синтаксис полностью идентичен **[tcpdump](../../../Linux/Diagnostics/Networking/tcpdump.md#фильтры-захвата)**.

#### Display Filters

Применяются **после** захвата к уже записанным пакетам. Поддерживают любые поля протоколов, логические операторы (`and`, `or`, `not`), сравнения строк и диапазонов.

```
ip.addr == 192.168.1.1           # трафик хоста (src или dst)
tcp.port == 443                  # TCP-порт
http.request.method == "GET"     # HTTP GET-запросы
tcp.flags.syn == 1 && tcp.flags.ack == 0  # только SYN (новые соединения)
dns.qry.name contains "example"  # DNS-запросы с подстрокой
```

> **Правило:** capture filter — для уменьшения объёма дампа, display filter — для анализа. При сомнениях захватывайте всё, фильтруйте потом.

### Инкапсуляция пакетов

Пакет в Wireshark — иерархия протоколов, каждый уровень вложен в предыдущий:

```
Frame (физический) → Ethernet (L2) → IP (L3) → TCP/UDP (L4) → Application Data (L7)
```

Интерфейс Wireshark подсвечивает байты каждого уровня в панели «Packet Bytes» при выборе поля в «Packet Details».

> **Важно:** если байты не подсвечиваются — поле является результатом анализа Wireshark (например, номер потока `tcp.stream`), а не реальными данными из сети. Это критично при поиске ошибок и отладке протоколов.

### Разрешение имён

- **MAC-Resolution:** `00:1A:2B:xx:xx:xx` → `Cisco`, `Apple` (база OUI)
- **IP-Resolution:** `142.250.185.78` → `google.com` (обратный DNS-запрос)
- **Port-Resolution:** `:443` → `https` (файл `/etc/services`)
- **Пользовательские имена:** ПКМ по IP → `Edit Resolved Name...` → произвольное имя. Отображается во всех фильтрах и столбцах вместо IP.

Настройка: `View → Name Resolution`.

### TCP-флаги

Краткая справка по флагам TCP-заголовка. Детальное описание — в **[Управление соединением TCP](../../Protocols/TCP/connection/tcp_connection_overview.md)**.

| Флаг | Назначение |
|---|---|
| **SYN** | Установка соединения (handshake) |
| **ACK** | Подтверждение получения |
| **FIN** | Штатное завершение соединения |
| **RST** | Аварийный обрыв (ошибка, отказ) |
| **PSH** | Передача данных приложению без буферизации |
| **URG** | Приоритетные данные (устаревший, не используется) |

## Практические сценарии

### Сценарий 1: Определение причины «bad checksum»

Если Wireshark показывает `bad checksum` но трафик передаётся нормально:

1. Проверьте, включён ли Checksum Offloading: `ethtool -k eth0 | grep checksum`
2. Если `on` — это ожидаемое поведение: NIC вычисляет checksum после захвата Wireshark
3. Отключите для диагностики (не рекомендуется для продакшена): `ethtool -K eth0 rx off tx off`

Подробности: **[Диагностика offloading](tcp_performance/tcp_network_losses_and_offloading.md#влияние-offloading-на-анализ-в-wireshark)**.

### Сценарий 2: Присвоение имён серверам для удобства анализа

При работе с дампом из продакшена с десятками IP:

1. Откройте дамп, найдите первый пакет от ключевого сервера
2. ПКМ по `ip.src` → `Edit Resolved Name...` → введите `api-server`
3. Теперь все фильтры и столбцы будут показывать `api-server` вместо `10.0.5.23`

Можно задать несколько имён для разных серверов. Сохраняется в настройках Wireshark (не в файле дампа).

### Сценарий 3: Переход с capture filter на display filter

Типичная ошибка — слишком агрессивный capture filter:

```bash
# Было (потеряли важный трафик):
tshark -i eth0 -f "port 80" -w capture.pcap

# Стало (захват всего, фильтрация потом):
tshark -i eth0 -w capture.pcap
# Затем в GUI: ip.addr == 10.0.0.5 && tcp.port == 80
```

Если capture filter уже применился — данные потеряны безвозвратно, перехват невозможен.
