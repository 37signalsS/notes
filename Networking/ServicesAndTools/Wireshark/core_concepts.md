# Wireshark: Основные Концепции

## Основные концепции

### Механизм захвата пакетов
В Linux захват пакетов происходит через сокеты семейства **`AF_PACKET`**, что позволяет получать "сырые" пакеты с сетевого интерфейса. Для работы инструментов захвата (`tcpdump`, `dumpcap`) обычно требуются привилегии `root`. В современных дистрибутивах это решается добавлением пользователя в специальную группу (`wireshark`) или настройкой `POSIX capabilities`.

### Режимы и фильтрация
*   **Промискусный режим (Promiscuous Mode)**: Режим сетевого интерфейса, при котором он принимает все пакеты в сегменте сети, а не только те, что адресованы ему. Это необходимо для полноценного анализа трафика.
*   **Фильтры захвата (`Capture Filters`)**: Применяются **до** записи пакетов в дамп на уровне библиотеки `libpcap`. Они уменьшают объем захватываемых данных, отбрасывая нерелевантный трафик. Синтаксис идентичен `tcpdump` (например, `host 192.168.1.1`, `port 80`).
*   **Фильтры отображения (`Display Filters`)**: Применяются **после** захвата для фильтрации уже записанных пакетов в интерфейсе Wireshark. Обладают более мощным и гибким синтаксисом для анализа по любым полям протоколов (например, `ip.addr == 192.168.1.1`, `http.request.method == "GET"`).

### Ключевые понятия
*   **Checksum Offload**: Аппаратное вычисление контрольных сумм сетевой картой. Если эта функция включена, в захваченном трафике контрольные суммы могут отображаться как некорректные, поскольку ОС передает их "как есть", не вычисляя на программном уровне. Это не является реальной ошибкой в пакете.
*   **Разрешение имен (Name Resolution)**: Процесс преобразования адресов в имена. Wireshark может разрешать MAC-адреса в имена производителей (OUI) и IP-адреса в доменные имена (DNS), что упрощает анализ.
    *   **Пользовательские имена для IP**: Для удобства анализа можно присваивать собственные имена IP-адресам. Для этого кликните правой кнопкой мыши по IP-адресу в Packet Details, выберите `Edit Resolved Name...` и введите желаемое имя. Эти имена будут отображаться в Wireshark вместо IP-адресов.
*   **Инкапсуляция**: Пакет в Wireshark представлен как иерархия протоколов, где каждый следующий уровень вложен в предыдущий (Frame → Ethernet → IP → TCP/UDP → Application Data). Интерфейс Wireshark наглядно демонстрирует это, подсвечивая байты каждого уровня в общем дампе пакета.
    *   **Различие между реальными данными и анализом**: При просмотре деталей пакета в панели "Packet Details" выбор поля слева подсвечивает соответствующие байты в панели "Packet Bytes" справа. Если байты не подсвечиваются, это означает, что данное поле является результатом анализа Wireshark (например, номер потока), а не реальными данными, переданными по сети. Это важно учитывать при глубоком анализе или поиске ошибок.
