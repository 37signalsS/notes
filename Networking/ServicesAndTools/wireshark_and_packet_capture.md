# Wireshark: Анализ сетевого трафика

Wireshark — это бесплатный анализатор сетевых протоколов с открытым исходным кодом. Он захватывает и отображает полный контент пакетов в реальном времени, что делает его незаменимым инструментом для диагностики, анализа и обеспечения безопасности сети.

# Определения (Definitions)

### Инструменты для захвата трафика
*   **`libpcap`/`Npcap`**: Основополагающие библиотеки, предоставляющие API для захвата сетевых пакетов. `Npcap` является аналогом для Windows и устанавливается вместе с Wireshark.
*   **`tcpdump`**: Консольная утилита для захвата и анализа сетевого трафика в реальном времени. Умеет сохранять дампы в файлы формата `.pcap`.
*   **`tshark`**: Консольная версия Wireshark, обладающая более широкими возможностями по сравнению с `tcpdump`, включая детальный анализ протоколов и поддержку формата `.pcapng`.
*   **Wireshark**: Графический инструмент, который может как захватывать трафик в реальном времени, так и читать файлы дампов, созданные `tcpdump` или `tshark`.
*   **`dumpcap`**: Вспомогательная программа, которую Wireshark использует непосредственно для захвата пакетов.
*   **`USBPcap`**: Драйвер для захвата USB-трафика в Windows, может быть установлен опционально с Wireshark.

### Форматы файлов дампов
*   **pcap (Packet Capture):** Старый, но широко используемый формат для сохранения захваченного трафика.
*   **pcapng (Packet Capture Next Generation):** Более новый формат, который поддерживает дополнительные метаданные, такие как имя интерфейса, комментарии к пакетам и более точные временные метки. `tshark` по умолчанию сохраняет в `pcapng`.

### Режимы работы и фильтрация
*   **Промискусный режим (Promiscuous Mode)**: Режим работы сетевого интерфейса, при котором он принимает все пакеты, проходящие через него, а не только те, которые адресованы непосредственно ему. Это необходимо для анализа всего трафика в сегменте сети.
*   **Фильтры захвата (`Capture Filters`)**: Применяются **до** записи пакетов в дамп на уровне библиотеки `libpcap`. Они отбрасывают неинтересный трафик, чтобы уменьшить размер файла дампа. Синтаксис совпадает с `tcpdump` (например, `host 192.168.1.1`, `port 80`).
*   **Фильтры отображения (`Display Filters`)**: Применяются **после** захвата для фильтрации уже записанных пакетов в интерфейсе Wireshark. Они более гибкие и мощные, позволяя фильтровать по любым полям протоколов (например, `ip.addr == 192.168.1.1`, `http.request.method == "GET"`).

### Ключевые понятия
*   **Checksum Offload**: Аппаратное вычисление контрольных сумм сетевой картой. Если эта функция включена, в захваченном трафике контрольные суммы могут отображаться как некорректные, поскольку ОС передает их "как есть", не вычисляя на программном уровне.
*   **Разрешение имен (Name Resolution)**: Процесс преобразования адресов в имена. Wireshark может разрешать MAC-адреса в имена производителей (OUI) и IP-адреса в доменные имена (DNS).

# Базовые концепции (Basic Concepts)

### Механизм захвата пакетов
В Linux захват пакетов происходит через семейство сокетов **`AF_PACKET`**. Это позволяет процессу получать доступ к пакетам в "сыром" виде, как они пришли на сетевой интерфейс.

Для работы `libpcap` обычно требуются привилегии `root`. Однако в современных дистрибутивах можно предоставить эти привилегии обычному пользователю через:
*   **POSIX capabilities**: Назначение специальных прав исполняемому файлу.
*   **SELinux/AppArmor**: Настройка политик безопасности, разрешающих захват трафика. Например, в Fedora пользователь добавляется в группу `wireshark`.

### Интерфейс Wireshark
*   **Верхняя панель** (Packet List Pane): Список захваченных пакетов с краткой информацией (номер, время, источник, назначение, протокол).
*   **Средняя панель** (Packet Details Pane): Древовидная структура с детальной расшифровкой выбранного пакета по уровням протоколов (Ethernet, IP, TCP/UDP и т.д.).
*   **Нижняя панель** (Packet Bytes Pane): Содержимое пакета в виде 16-ричного дампа и ASCII-представления. Подсветка байтов при выборе полей в средней панели наглядно демонстрирует инкапсуляцию.

### Структура и инкапсуляция пакета
Пакет в Wireshark представлен как иерархия протоколов, где каждый следующий уровень вложен в предыдущий:
1.  **Frame**: Информация о фрейме (размер, время захвата).
2.  **Ethernet**: Канальный уровень (MAC-адреса).
3.  **VLAN**: Если есть, тег виртуальной сети.
4.  **IP (IPv4/IPv6)**: Сетевой уровень (IP-адреса).
5.  **TCP/UDP**: Транспортный уровень (порты, флаги).
6.  **Application Layer**: Прикладной уровень (HTTP, DNS и т.д.).

Выбирая различные уровни в "Packet Details Pane", можно видеть, как Wireshark подсвечивает соответствующие байты в "Packet Bytes Pane", иллюстрируя процесс инкапсуляции.

### Цветовая маркировка (Coloring Rules)
Wireshark использует цвета для выделения разных типов трафика. Это помогает быстро выявлять ошибки, аномалии и нужные протоколы.
*   Светло-голубой: TCP трафик.
*   Светло-зеленый: HTTP трафик.
*   Темно-синий: DNS трафик.
*   Черный: Пакеты с ошибками (например, некорректная контрольная сумма).
*   Красный: Проблемы с TCP (например, повторные передачи).

Вы можете настроить правила в меню `View -> Coloring Rules...`.

### Анализ TCP
*   **Установка соединения (Three-way Handshake)**: `SYN` → `SYN, ACK` → `ACK`. Wireshark помогает анализировать опции, передаваемые в первых пакетах, такие как `MSS` (Maximum Segment Size), `Window Scale` и поддержка `SACK`.
*   **Передача данных**: Флаг `PSH` (Push) указывает на необходимость немедленно передать данные приложению. Wireshark автоматически выполняет **сборку сегментов (Reassembly)**, объединяя несколько TCP-сегментов в одно сообщение прикладного уровня (PDU).
*   **Завершение соединения (Four-way Handshake)**: `FIN, ACK` → `ACK` → `FIN, ACK` → `ACK`.
*   **Keep-Alive**: Пустые TCP-сегменты для поддержания неактивных соединений и сброса таймеров на сетевом оборудовании.

### Анализ UDP
*   **Структура**: Протокол без установки соединения, основной заголовок которого содержит порты источника и назначения, длину и контрольную сумму.
*   **Демультиплексирование**: Основная функция UDP — доставка данных нужному приложению на основе порта назначения (`Destination Port`). Wireshark позволяет отследить, как ОС назначает разные эфемерные порты источника для разных клиентских процессов.

### Анализ DNS
*   **Структура сообщения**: DNS-сообщения (обычно по UDP) содержат `Transaction ID` для сопоставления запросов и ответов, флаги и секции (`Queries`, `Answers`).
*   **Флаги**:
    *   `Authoritative Answer (AA)`: Ключевой флаг, показывающий, получен ответ от авторитетного сервера зоны (`1`) или из кэша резолвера (`0`).
    *   `Recursion Desired (RD)` и `Recursion Available (RA)`: Управляют рекурсивным поведением DNS-серверов.

### Анализ HTTP
*   **Запрос-ответ**: Текстовый протокол, где клиент отправляет запрос (`GET /path HTTP/1.1`, заголовки), а сервер отвечает статусом (`HTTP/1.1 200 OK`, заголовки) и телом сообщения.
*   **Кэширование**: Для экономии трафика используется **условный GET (Conditional GET)** с заголовками `If-None-Match` (содержит `ETag`) или `If-Modified-Since`. Если ресурс не изменился, сервер отвечает коротким `304 Not Modified` без тела сообщения.

# Практические сценарии (Practical Scenarios)

## Установка Wireshark

### Linux
**Настройка прав**:
    *   **Debian/Ubuntu**: Во время установки появится запрос "Should non-superusers be able to capture packets?". Выберите `Yes`. Затем добавьте пользователя в группу: `sudo usermod -aG wireshark $USER`.
    *   **Fedora/RHEL**: Добавьте пользователя в группу `sudo usermod -aG wireshark $USER` и настройте права для `dumpcap`: `sudo setcap cap_net_raw,cap_net_admin=eip $(which dumpcap)`.

## Использование Wireshark (GUI)
1.  **Запустите Wireshark**. Вы увидите список сетевых интерфейсов.
2.  **Выберите интерфейс**, на котором есть активность, и нажмите синюю кнопку в виде плавника акулы (или `Ctrl+E`), чтобы начать захват.
3.  **Просмотр трафика**: Пакеты будут появляться в реальном времени в верхней панели.
4.  **Остановка захвата**: Нажмите красную кнопку "Stop" (`Ctrl+E`).
5.  **Сохранение данных**: `File -> Save As...` чтобы сохранить сессию в формате `.pcapng`.

### Анализ ICMP (Ping)
1.  Начните захват трафика.
2.  В терминале выполните команду `ping 8.8.8.8`.
3.  В поле фильтра отображения Wireshark введите `icmp` и нажмите Enter.
4.  Вы увидите пакеты `Echo (ping) request` и `Echo (ping) reply`, что полезно для диагностики задержек и потерь пакетов.

### Включение/выключение Promiscuous Mode
Режим включен по умолчанию. Чтобы управлять им:
1.  Нажмите `Ctrl+K` или `Capture -> Options...`.
2.  В открывшемся окне для нужного интерфейса снимите или поставьте галочку в столбце "Promiscuous".

### Анализ потоков данных
*   **"Follow TCP/UDP/HTTP Stream"**: Функция (`Analyze` -> `Follow`), которая собирает все сегменты/дейтаграммы одного соединения и показывает только данные прикладного уровня в виде единого диалога. Крайне полезна для анализа текстовых протоколов, таких как HTTP.

### Анализ DNS-запросов
*   **Запрос разных типов записей** с помощью `nslookup` или `dig`:
    *   `A` и `AAAA`: IPv4 и IPv6 адреса.
    *   `CNAME` (Canonical Name): Псевдоним для другого доменного имени.
    *   `MX` (Mail Exchanger): Почтовые серверы домена с указанием приоритета.
    *   `NS` (Name Server): Авторитетные серверы имен для доменной зоны.
*   **Анализ ответа с несколькими IP**: Крупные домены, такие как `yandex.ru`, часто возвращают несколько `A`-записей для балансировки нагрузки. В Wireshark это видно как несколько записей в секции `Answers`.
*   **Анализ обратного DNS-запроса (`PTR`)**: Позволяет по IP-адресу узнать имя. Для IP `77.88.44.55` Wireshark покажет запрос `PTR`-записи для специального имени `55.44.88.77.in-addr.arpa`.

## Использование tshark (командная строка)
`tshark` — это мощный инструмент для автоматизации и работы в средах без GUI.

### Установка (если не установлен с Wireshark)
*   **Debian/Ubuntu**: `sudo apt install tshark -y`
*   **Fedora/RHEL**: `sudo dnf install wireshark-cli -y`

### Примеры команд
```bash
# Показать список доступных интерфейсов
tshark -D

# Захват 100 пакетов с интерфейса enp0s3 и сохранение в файл
sudo tshark -i enp0s3 -c 100 -w capture.pcapng

# Чтение из файла с применением фильтра отображения
tshark -r capture.pcapng -Y "ip.addr == 185.15.59.224"

# Захват трафика по HTTP (порт 80)
sudo tshark -i enp0s3 -f "tcp port 80"

# Экспорт определенных полей в CSV
tshark -r capture.pcapng -T fields -e ip.src -e ip.dst -e frame.len -E header=y -E separator=, > packets.csv
```

# Справочник: Фильтры и команды

## Фильтры захвата (Capture Filters)
*Синтаксис `tcpdump`.*
| Сценарий | Фильтр захвата |
|---|---|
| Трафик от/к хосту | `host 192.168.1.1` |
| Трафик к хосту | `dst host 8.8.8.8` |
| Трафик с порта 443 | `port 443` |
| Только TCP или UDP | `tcp or udp` |
| DNS трафик (порт 53) | `udp port 53` |
| Трафик из подсети | `net 192.168.1.0/24` |
| Исключить SSH | `not port 22` |

## Фильтры отображения (Display Filters)
*Более мощный и гибкий синтаксис.*
| Действие | Фильтр отображения |
|---|---|
| По IP-адресу | `ip.addr == 10.10.42.1` |
| По исходному IP | `ip.src == 10.10.42.1` |
| Диапазон IP | `ip.addr >= 10.10.42.1 and ip.addr <= 10.10.42.100` |
| По протоколу | `http or ftp or ssh or icmp` |
| По TCP порту | `tcp.port == 25` |
| Флаг TCP SYN | `tcp.flags.syn == 1 && tcp.flags.ack == 0` |
| HTTP Host | `http.host == "example.com"` |
| Широковещательный трафик | `eth.dst == ff:ff:ff:ff:ff:ff` |

## Операторы фильтров отображения
| Оператор | Описание | Пример |
|---|---|---|
| `==` или `eq` | Равно | `ip.addr == 192.168.1.1` |
| `!=` или `ne` | Не равно | `ip.addr != 192.168.1.1` |
| `>` или `gt` | Больше | `frame.len > 1000` |
| `<` или `lt` | Меньше | `frame.len < 512` |
| `and` или `&&`| Логическое И | `ip.addr == 10.1.1.1 and tcp.port == 80` |
| `or` или `||` | Логическое ИЛИ | `http or dns` |
| `not` или `!` | Логическое НЕ | `!icmp` |

## Горячие клавиши Wireshark GUI
| Горячая клавиша | Действие |
|---|---|
| `Ctrl+E` | Начать/Остановить захват. |
| `Ctrl+R` | Перезапустить текущий захват. |
| `Ctrl+O` | Открыть файл захвата. |
| `Ctrl+S` | Сохранить текущий файл захвата. |
| `Ctrl+F` | Найти пакет. |
| `↓` / `↑` | Перемещение к следующему/предыдущему пакету. |

# Дополнительная информация (Additional information)

### Дешифрование TLS-трафика
Wireshark способен дешифровать TLS-трафик, если у вас есть приватный ключ сервера.
*   **Настройка**: В `Preferences` -> `Protocols` -> `TLS` можно добавить приватный ключ, указав IP-адрес сервера, порт и путь к файлу ключа.
*   **Альтернатива**: При отладке собственного кода иногда проще временно отключить шифрование на сервере (`null cipher`), чем настраивать дешифрование.

### Инструменты анализа в Wireshark
*   **Комментарии к пакетам**: Можно добавлять произвольные комментарии к пакетам (`Packet Comments`), что удобно для документирования анализа. Для фильтрации используется `frame.comment`.
*   **Интерпретация проблемных пакетов**:
    *   **`Connection Refused`**: `SYN` пакет, на который приходит ответ `RST, ACK`, указывает, что порт на целевом хосте закрыт.
    *   **IP Spoofing**: Wireshark покажет пакеты с поддельными IP-адресами, но их интерпретация требует глубокого понимания контекста сети.

### Интеграция и прочее
*   **Анализ туннельного трафика**: Wireshark корректно разбирает туннельные протоколы, такие как [GRE](../../Tunnels/gre.md), показывая как внешний заголовок туннеля, так и вложенный трафик.
*   **Генерация правил файрвола**: Wireshark имеет устаревшую функцию для генерации правил `iptables`. Она не поддерживает современные `nftables` и может работать некорректно.
