# Wireshark: Анализ сетевого трафика

## Определения

*   **Wireshark**: Графический анализатор сетевых протоколов с открытым исходным кодом. Захватывает и детально разбирает сетевой трафик в реальном времени или из файлов.
*   **`tcpdump`**: Консольная утилита для захвата и базового анализа сетевого трафика. Часто используется для сохранения трафика в файл для последующего анализа в Wireshark. Подробнее см. **[[../../Linux/Diagnostics/Networking/tcpdump.md|tcpdump]]**.
*   **`tshark`**: Консольная версия Wireshark с мощными возможностями анализа и фильтрации.
*   **`libpcap`/`Npcap`**: Библиотеки, предоставляющие API для захвата сетевых пакетов в Unix-подобных системах и Windows соответственно.
*   **`dumpcap`**: Вспомогательная утилита, которую Wireshark и `tshark` используют непосредственно для захвата пакетов.
*   **`pcap` (Packet Capture):** Старый, но широко используемый формат для сохранения захваченного трафика.
*   **`pcapng` (Packet Capture Next Generation):** Более новый формат, который поддерживает дополнительные метаданные (имя интерфейса, комментарии к пакетам) и является форматом по умолчанию для Wireshark/`tshark`.

## Основные концепции

### Механизм захвата пакетов
В Linux захват пакетов происходит через сокеты семейства **`AF_PACKET`**, что позволяет получать "сырые" пакеты с сетевого интерфейса. Для работы инструментов захвата (`tcpdump`, `dumpcap`) обычно требуются привилегии `root`. В современных дистрибутивах это решается добавлением пользователя в специальную группу (`wireshark`) или настройкой `POSIX capabilities`.

### Режимы и фильтрация
*   **Промискусный режим (Promiscuous Mode)**: Режим сетевого интерфейса, при котором он принимает все пакеты в сегменте сети, а не только те, что адресованы ему. Это необходимо для полноценного анализа трафика.
*   **Фильтры захвата (`Capture Filters`)**: Применяются **до** записи пакетов в дамп на уровне библиотеки `libpcap`. Они уменьшают объем захватываемых данных, отбрасывая нерелевантный трафик. Синтаксис идентичен `tcpdump` (например, `host 192.168.1.1`, `port 80`).
*   **Фильтры отображения (`Display Filters`)**: Применяются **после** захвата для фильтрации уже записанных пакетов в интерфейсе Wireshark. Обладают более мощным и гибким синтаксисом для анализа по любым полям протоколов (например, `ip.addr == 192.168.1.1`, `http.request.method == "GET"`).

### Ключевые понятия
*   **Checksum Offload**: Аппаратное вычисление контрольных сумм сетевой картой. Если эта функция включена, в захваченном трафике контрольные суммы могут отображаться как некорректные, поскольку ОС передает их "как есть", не вычисляя на программном уровне. Это не является реальной ошибкой в пакете.
*   **Разрешение имен (Name Resolution)**: Процесс преобразования адресов в имена. Wireshark может разрешать MAC-адреса в имена производителей (OUI) и IP-адреса в доменные имена (DNS), что упрощает анализ.
*   **Инкапсуляция**: Пакет в Wireshark представлен как иерархия протоколов, где каждый следующий уровень вложен в предыдущий (Frame → Ethernet → IP → TCP/UDP → Application Data). Интерфейс Wireshark наглядно демонстрирует это, подсвечивая байты каждого уровня в общем дампе пакета.

## Практические сценарии

### Установка и настройка прав
*   **Debian/Ubuntu**: `sudo apt install wireshark`. Во время установки выберите `Yes` на вопрос "Should non-superusers be able to capture packets?". Затем добавьте пользователя в группу: `sudo usermod -aG wireshark $USER` и перезайдите в систему.
*   **Fedora/RHEL**: `sudo dnf install wireshark`. Добавьте пользователя: `sudo usermod -aG wireshark $USER`.

### Базовое использование Wireshark (GUI)
1.  **Запустите Wireshark**. Вы увидите список сетевых интерфейсов.
2.  **Выберите интерфейс** с активностью и нажмите синюю кнопку в виде плавника акулы (или `Ctrl+E`), чтобы начать захват.
3.  **Примените фильтр отображения**, например `dns` или `http`, чтобы увидеть только интересующий трафик.
4.  **Остановите захват** (красная кнопка "Stop" или `Ctrl+E`).
5.  **Сохраните данные**: `File -> Save As...` (формат `.pcapng`).

### Анализ потоков данных (Follow Stream)
Это одна из самых полезных функций. Кликните правой кнопкой мыши по пакету (например, HTTP) и выберите `Follow -> TCP Stream`. Wireshark откроет новое окно, где покажет полный диалог между клиентом и сервером в виде текста, отфильтровав все остальные пакеты.

### Анализ распространенных протоколов
*   **ICMP (Ping)**: Фильтр `icmp`. Позволяет увидеть пакеты `Echo (ping) request` и `Echo (ping) reply`, измерить задержку (RTT) и выявить потери.
*   **DNS**: Фильтр `dns`. Помогает анализировать:
    *   **Типы записей**: `A`, `AAAA`, `CNAME`, `MX`, `NS`.
    *   **Флаги**: `Authoritative Answer (AA)` показывает, пришел ответ от авторитетного сервера или из кэша.
    *   **Обратные запросы (PTR)**: Запросы для доменов `.in-addr.arpa` для определения имени по IP.
*   **TCP**: Фильтр `tcp`. Позволяет детально изучить:
    *   **Установку соединения (3-way handshake)**: `SYN`, `SYN, ACK`, `ACK`.
    *   **Передачу данных**: Пакеты с флагом `PSH`.
    *   **Завершение соединения (4-way handshake)**: Пакеты с флагом `FIN`.
*   **HTTP**: Фильтр `http`. Wireshark разбирает запросы и ответы, позволяя анализировать методы (`GET`, `POST`), статусы (`200 OK`, `404 Not Found`), заголовки и тело сообщения.

### Использование `tshark` (командная строка)
`tshark` идеально подходит для автоматизации и работы в средах без GUI.
*   **Установка (если не установлен с Wireshark)**: `sudo apt install tshark` (Debian/Ubuntu) или `sudo dnf install wireshark-cli` (Fedora/RHEL).

```bash
# Показать список доступных интерфейсов
tshark -D

# Захват 100 пакетов с интерфейса enp0s3 и сохранение в файл
sudo tshark -i enp0s3 -c 100 -w capture.pcapng

# Чтение из файла с применением фильтра отображения
tshark -r capture.pcapng -Y "ip.addr == 185.15.59.224"

# Захват трафика по HTTP (порт 80) с использованием фильтра захвата
sudo tshark -i enp0s3 -f "tcp port 80"

# Экспорт определенных полей в CSV
tshark -r capture.pcapng -T fields -e ip.src -e ip.dst -e frame.len -E header=y -E separator=, > packets.csv
```

## Дополнительная информация

### Справочник по фильтрам

#### Фильтры захвата (`-f "..."`)
*Синтаксис `tcpdump`. Применяются при запуске захвата.*
| Сценарий | Фильтр |
|---|---|
| Трафик от/к хосту | `host 192.168.1.1` |
| Трафик к хосту | `dst host 8.8.8.8` |
| Трафик с порта 443 | `port 443` |
| Только TCP или UDP | `tcp or udp` |
| DNS трафик (порт 53) | `udp port 53` |
| Трафик из подсети | `net 192.168.1.0/24` |
| Исключить SSH | `not port 22` |

#### Фильтры отображения (`-Y "..."` или в GUI)
*Более мощный и гибкий синтаксис. Применяются к уже захваченным данным.*
| Действие | Фильтр |
|---|---|
| По IP-адресу (источник или назначение) | `ip.addr == 10.10.42.1` |
| По исходному IP | `ip.src == 10.10.42.1` |
| По протоколу | `http or dns or icmp` |
| По TCP порту | `tcp.port == 25` |
| Флаг TCP SYN | `tcp.flags.syn == 1 && tcp.flags.ack == 0` |
| HTTP Host | `http.host == "example.com"` |
| Широковещательный трафик | `eth.dst == ff:ff:ff:ff:ff:ff` |

### Цветовая маркировка (Coloring Rules)
Wireshark использует цвета для выделения трафика, что помогает быстро находить проблемы.
*   **Светло-голубой**: TCP трафик.
*   **Светло-зеленый**: HTTP трафик.
*   **Темно-синий**: DNS трафик.
*   **Черный**: Пакеты с ошибками (например, неверная контрольная сумма TCP).
*   **Красный**: Проблемный TCP-трафик (например, повторные передачи).
Правила настраиваются в меню `View -> Coloring Rules...`.

### Горячие клавиши Wireshark GUI
| Клавиша | Действие |
|---|---|
| `Ctrl+E` | Начать/Остановить захват |
| `Ctrl+R` | Перезапустить захват |
| `Ctrl+O` | Открыть файл |
| `Ctrl+S` | Сохранить файл |
| `Ctrl+F` | Найти пакет |

### Дешифрование TLS-трафика
Wireshark может дешифровать TLS-трафик при наличии приватного ключа сервера. Это настраивается в `Preferences -> Protocols -> TLS` путем добавления ключа с указанием IP-адреса сервера и порта.
