# Мониторинг сетевых соединений: TCPView, netstat и ss

В этой заметке рассматриваются утилиты для мониторинга сетевых соединений TCP/IP, их состояний, а также процессов, использующих эти соединения.

## 1. Состояния TCP-соединений

Состояния TCP-соединений, описанные в RFC 793, являются ключевыми для понимания работы сети. Вот основные из них:

*   **LISTEN**: Сервер ожидает входящих подключений на определенном порту.
*   **SYN_SENT**: Клиент отправил пакет SYN и ожидает SYN-ACK от сервера.
*   **SYN_RECEIVED**: Сервер получил SYN от клиента, отправил SYN-ACK и ожидает ACK от клиента (часть [TCP-рукопожатия](../Protocols/tcp_connection_establishment.md)).
*   **ESTABLISHED**: Соединение установлено и готово к передаче данных.
*   **FIN_WAIT1**: Одна сторона инициировала закрытие соединения и отправила FIN-пакет.
*   **FIN_WAIT2**: Первая сторона получила ACK на свой FIN-пакет.
*   **CLOSE_WAIT**: Удаленная сторона инициировала закрытие, а локальная сторона получила FIN-пакет.
*   **CLOSING**: Обе стороны одновременно отправили FIN-пакеты.
*   **LAST_ACK**: Локальная сторона отправила FIN и ожидает ACK от удаленной стороны.
*   **TIME_WAIT**: Локальная сторона закрыла соединение и ожидает истечения таймера, чтобы убедиться, что все пакеты были получены и обработаны. Это состояние необходимо для предотвращения проблем с задержавшимися сегментами старых соединений.

## 2. Утилиты мониторинга

### TCPView (Windows)

TCPView — это бесплатная графическая утилита для Windows, которая отображает список всех TCP- и UDP-соединений на компьютере, а также процессов, которые их используют.

**Ключевая информация, отображаемая TCPView:**

*   **Process Name / PID**: Имя и идентификатор процесса.
*   **Protocol**: Протокол (TCP или UDP).
*   **Local Address / Local Port**: Локальный IP-адрес и порт, используемые соединением.
*   **Remote Address / Remote Port**: Удаленный IP-адрес и порт, к которому установлено соединение.
*   **State**: Текущее состояние TCP-соединения (например, ESTABLISHED, LISTEN, TIME_WAIT).
*   **Module Name**: Для системных процессов указываются модули, использующие сетевое подключение.

### netstat (Windows / Linux)

`netstat` (network statistics) — это консольная утилита, доступная как в Windows, так и в Linux, предназначенная для отображения сетевых подключений, таблиц маршрутизации, статистики интерфейсов и т.д.

#### Использование в Windows

Примеры команд:

*   **`netstat -a`**: Показывает все активные соединения и порты, находящиеся в состоянии LISTEN (ожидания).
*   **`netstat -n`**: Выводит IP-адреса и номера портов в числовом формате, без разрешения имен хостов. Это ускоряет вывод.
*   **`netstat -b`**: Показывает исполняемый файл, участвующий в создании каждого соединения или порта прослушивания.

Пример вывода:

```
Proto  Local Address          Foreign Address        State           PID
TCP    0.0.0.0:80             0.0.0.0:0              LISTEN          1234  (Process.exe)
TCP    192.168.1.100:49152    8.8.8.8:443            ESTABLISHED     5678  (Browser.exe)
```

#### Использование в Linux (устарело)

В Linux `netstat` также предоставляет аналогичную информацию. Однако эта утилита считается устаревшей и вместо нее рекомендуется использовать `ss`. Особенностью `netstat` в Linux является то, что она показывает не только сетевые соединения, но и соединения через Unix-сокеты.

### ss (Linux)

`ss` (socket statistics) — это современная консольная утилита в Linux, которая является более быстрой и мощной альтернативой `netstat`. Она используется для вывода информации о сокетах.

Основные опции:

*   **`ss -t`**: Показывает только TCP-сокеты.
*   **`ss -u`**: Показывает только UDP-сокеты.
*   **`ss -a`**: Показывает все сокеты (LISTENING и NOT LISTENING).
*   **`ss -l`**: Показывает только LISTENING сокеты.
*   **`ss -n`**: Не разрешает имена служб и хостов.
*   **`ss -p`**: Показывает процесс, который использует сокет.
*   **`ss -e`**: Показывает расширенную информацию.
*   **`ss -s`**: Выводит сводную статистику по сокетам.

Пример команды для просмотра всех TCP-соединений, не разрешая имена, с указанием процессов:

```bash
ss -tlnp
```

Пример вывода:

```
Netid State    Recv-Q Send-Q Local Address:Port  Peer Address:Port
tcp   LISTEN   0      128    0.0.0.0:80          0.0.0.0:*      users:(("apache2",pid=1234,fd=5))
tcp   ESTAB    0      0      192.168.1.10:80     192.168.1.1:54321 users:(("apache2",pid=1235,fd=6))
```

### Практический пример: Мониторинг веб-сервера

При подключении к веб-серверу (например, Apache на порту 80), можно наблюдать изменения в состояниях соединений с помощью `ss` (или `netstat`).

1.  Когда веб-сервер запущен, `ss -tln` покажет его в состоянии `LISTEN` на порту 80.
2.  При открытии веб-страницы в браузере и обновлении `ss -tnp`, можно увидеть новые записи:
    *   Соединения в состоянии `SYN_SENT` (от клиента) или `SYN_RECEIVED` (на сервере), затем `ESTABLISHED`.
    *   После завершения обмена данными и закрытия соединения появятся состояния вроде `FIN_WAIT1`, `FIN_WAIT2`, `CLOSE_WAIT`, `TIME_WAIT`, отражающие процесс корректного завершения TCP-сессии.

## Заключение

Эти утилиты являются незаменимыми инструментами для сетевых администраторов и разработчиков при диагностике проблем с сетевыми соединениями, понимании их состояний и выявлении процессов, взаимодействующих по сети.
