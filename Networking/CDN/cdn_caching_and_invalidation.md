# Политики кеширования и инвалидации в CDN

Эффективное управление жизненным циклом контента в CDN — ключ к балансу между производительностью, нагрузкой на origin-сервер и актуальностью данных. Это достигается через грамотные политики кеширования, настройку TTL и своевременную инвалидацию.

## Часть 1: Политики кеширования контента

### Ключевые понятия

-   **TTL (Time To Live)**: Время, в течение которого объект считается «свежим» и может отдаваться из кеша без запроса к origin.
-   **Freshness vs Validation**: Свежесть (`max-age`/`s-maxage`) позволяет отдавать объект без проверки, тогда как валидация (`ETag`/`Last-Modified`) требует условного запроса к origin для подтверждения актуальности.
-   **Cache key**: Уникальный идентификатор объекта в кеше. Обычно состоит из схемы, хоста, пути, нормализованных query-параметров и определённых заголовков (`Vary`).
-   **Stale**: Устаревшая копия объекта. Может быть отдана при определённых условиях (`stale-while-revalidate`, `stale-if-error`).
-   **Purge/Invalidate**: Принудительное удаление или объявление объекта устаревшим в кеше.

### Директивы HTTP для CDN

| Директива/заголовок          | Назначение                                     | Типичный случай                               |
| ---------------------------- | ---------------------------------------------- | --------------------------------------------- |
| `Cache-Control: s-maxage`    | TTL для общих кешей (CDN)                      | Разделение логики кеширования для CDN и браузера |
| `Cache-Control: max-age`     | TTL для частных кешей (браузер)                | Управление кешем на клиенте                   |
| `public`/`private`           | Разрешает/запрещает кеширование в общих кешах  | `public` для статики, `private` для персональных данных |
| `no-store`/`no-cache`        | Полный запрет кеширования / только с валидацией| Конфиденциальные или часто меняющиеся данные   |
| `stale-while-revalidate`     | Отдавать устаревшее и обновлять в фоне         | Снижение задержки при обновлении              |
| `stale-if-error`             | Отдавать устаревшее при ошибке origin          | Повышение отказоустойчивости                  |
| `ETag`/`Last-Modified`       | Валидаторы для условных запросов (304)         | Экономия трафика при неизменном контенте      |
| `Vary`                       | Создание разных версий кеша по заголовкам      | `Accept-Encoding`, `Accept-Language`          |
| `Surrogate-Control`          | Специфичные для CDN директивы                  | Прямое управление промежуточными кешами       |

### Формирование cache key

-   **Базовые компоненты**: `scheme` + `host` + `path`.
-   **Query-параметры**: Использовать только значимые, игнорируя `utm_` и другие трекеры.
-   **Заголовки**: Минимизировать `Vary`, обычно достаточно `Accept-Encoding`.
-   **Cookies**: Игнорировать по умолчанию; включать в ключ только те, что влияют на контент.

## Часть 2: Настройка TTL и Инвалидация

### Примеры конфигурации TTL

**Долгоживущая статика (с версионированием):**

```http
HTTP/1.1 200 OK
Content-Type: text/css
ETag: "a1b2c3"
Cache-Control: public, max-age=31536000, s-maxage=31536000, immutable
```

**Динамический HTML:**

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
ETag: "p123"
Cache-Control: public, s-maxage=60, max-age=0, stale-while-revalidate=30, stale-if-error=86400
```

### Механизмы инвалидации

-   **Версионирование URL**: Лучший способ. Изменение URL (`/app.v123.js`) гарантирует загрузку новой версии без необходимости очистки кеша.
-   **Purge по URL**: Точечная (`/product/42`) или массовая (`/static/*`) инвалидация.
-   **Purge по тегам (Surrogate-Key)**: Групповая инвалидация связанных объектов (например, всех материалов по тегу `product:42`).
-   **Soft purge**: Помечает объект как `stale`, что вызывает немедленную ревалидацию при следующем запросе, но не удаляет его.
-   **Hard purge**: Полное удаление из кеша.

**Пример API-запроса на инвалидацию:**

```bash
# Инвалидация по путям
POST https://cdn.example.com/api/invalidate
Authorization: Bearer <token>
Content-Type: application/json

{ "paths": ["/product/42", "/category/12/*"] }

# Инвалидация по тегам
POST https://cdn.example.com/api/purge-tags
Authorization: Bearer <token>
Content-Type: application/json

{ "tags": ["product:42", "category:12"] }
```

### Рекомендации

-   Используйте **долгий TTL** для статики с версионированием и **короткий TTL** для HTML и API.
-   Применяйте `stale-while-revalidate` и `stale-if-error` для динамического контента, чтобы повысить производительность и отказоустойчивость.
-   Разделяйте директивы для CDN (`s-maxage`, `Surrogate-Control`) и браузера (`max-age`).
-   Предпочитайте **версионирование** и **теговую инвалидацию** массовым `purge`, чтобы снизить пиковую нагрузку на origin.
-   Не используйте `must-revalidate` вместе с `stale-while-revalidate`.
-   Настройте **негативное кеширование** (короткий TTL для 4xx/5xx ошибок) для защиты от повторных запросов к несуществующим ресурсам.
-   Анализируйте заголовки `Age`, `Via`, `X-Cache` и метрики `hit ratio` для оценки эффективности кеширования.
