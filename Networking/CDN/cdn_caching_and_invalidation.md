# CDN — Политики кэширования и инвалидации

### Определения

- **Кэширование в CDN**: Процесс сохранения копий контента на географически распределенных серверах (PoP) для ускорения доставки и снижения нагрузки на источник (Origin).
- **Инвалидация кэша (Cache Invalidation/Purge)**: Механизм принудительного удаления или пометки контента как "устаревшего" в кэше CDN, что заставляет сеть запросить свежую версию с исходного сервера.
- **Cache-Status**: Стандартный заголовок (RFC 9211), предоставляющий детальную информацию о том, как запрос был обработан кэшем (HIT, MISS, EXPIRED, STALE).
- **CDN-Cache-Control**: Специализированный заголовок (RFC 9213), позволяющий задавать политики кэширования отдельно для CDN, не влияя на поведение браузеров.
- **Surrogate Keys (Cache Tags)**: Метод группировки объектов в кэше с помощью меток (тегов) для их массовой инвалидации одним запросом.
- **Cache Key (Ключ кэша)**: Уникальный идентификатор ресурса в системе кэширования, обычно формируемый из URL и некоторых заголовков запроса.
- **Origin Shielding**: Дополнительный слой кэширования между пограничными узлами и источником, минимизирующий количество запросов к Origin при пропуске кэша (Cache Miss).

### Основные концепции

#### Иерархия управления кэшем

Современные CDN следуют приоритетности заголовков (от высшего к низшему):
1. **Правила в панели управления CDN** (Edge Rules): Переопределяют любые заголовки сервера.
2. **`CDN-Cache-Control`**: Инструкции специально для CDN.
3. **`Cache-Control` (директива `s-maxage`)**: Инструкция для разделяемых (shared) кэшей.
4. **`Cache-Control` (директива `max-age`)**: Общая инструкция для всех кэшей.
5. **`Expires`**: Устаревший метод задания даты устаревания.

#### Формирование и нормализация ключа кэша (Cache Key)

Эффективность кэширования (Hit Ratio) напрямую зависит от того, как формируется ключ. 

**Рекомендации по нормализации (2026):**
- **Нормализация Query-параметров**: Сортировка параметров в алфавитном порядке и удаление маркетинговых меток (`utm_*`, `fbclid`, `gclid`).
- **Регистр букв**: Приведение URL к нижнему регистру, если файловая система на источнике нечувствительна к регистру.
- **Сжатие (Compression)**: Кэширование разных версий контента (Gzip, Brotli, Zstandard) на основе заголовка `Accept-Encoding`.
- **Заголовок Vary**: Используется для кэширования версий контента на основе метаданных (например, `Vary: Accept-Language`). *Осторожно:* избыточное использование `Vary` приводит к фрагментации кэша.

### Механизмы инвалидации

#### 1. Мгновенная очистка (Purge)
- **Single URL Purge**: Удаление конкретного файла. Занимает от нескольких миллисекунд до нескольких секунд во всей глобальной сети.
- **Wildcard Purge**: Очистка по маске (например, `/images/*.jpg`). *Ресурсоемкая операция, поддерживается не всеми провайдерами.*

#### 2. Теговая инвалидация (Surrogate Keys)
Самый эффективный способ для сложных приложений (E-commerce).
1. Исходный сервер добавляет заголовок `Surrogate-Key: product_123 category_45`.
2. CDN сохраняет эти связи.
3. При обновлении товара отправляется один API-запрос на очистку тега `product_123`. Все связанные страницы (карточки, списки, рекомендации) инвалидируются мгновенно.

#### 3. Фоновое обновление (Stale-While-Revalidate)
Метод, позволяющий отдавать пользователю устаревший контент из кэша, пока CDN в фоновом режиме запрашивает обновление у Origin.
- **Преимущество:** Нулевая задержка для пользователя (0-ms Latency) даже при истекшем TTL.
- **Настройка:** `Cache-Control: public, s-maxage=60, stale-while-revalidate=600`.

### Безопасность кэширования

#### Защита от Cache Poisoning (Отравление кэша)
Атака, при которой злоумышленник заставляет CDN сохранить вредоносный ответ в кэше для всех пользователей.

**Методы защиты:**
- **Игнорирование нерелевантных заголовков**: Настройка CDN так, чтобы она не включала в Cache Key заголовки, которые не влияют на контент (например, `X-Forwarded-Host`).
- **Строгая нормализация**: Очистка входных данных перед формированием ключа.
- **Использование HTTPS**: Шифрование трафика между CDN и Origin для предотвращения подмены ответов.

#### Безопасность Origin
- **Signed URLs**: Выдача временных ссылок с криптографической подписью для доступа к приватному контенту.
- **Geo-fencing**: Ограничение доступа к кэшированному контенту на основе страны или IP-репутации прямо на границе сети (Edge).

### Практические сценарии (Best Practices 2026)

| Тип контента | Стратегия кэширования | Рекомендуемые заголовки |
| :--- | :--- | :--- |
| **Статика (Immutable)** | Кэширование на 1 год | `Cache-Control: public, max-age=31536000, immutable` |
| **Динамический HTML** | Короткое кэширование + SWR | `CDN-Cache-Control: s-maxage=300, stale-while-revalidate=3600` |
| **API-ответы** | Теговое кэширование | `Cache-Control: no-cache`, `Surrogate-Key: user_data` |
| **Ошибки (4xx/5xx)** | Негативное кэширование | Кратковременное кэширование (10-30 сек) для защиты от DoS |

### Мониторинг и отладка

Для анализа работы кэша используйте заголовок `Cache-Status`:
```http
Cache-Status: Cloudflare-CDN; hit; ttl=345; key=abc...
```

**Ключевые метрики SRE:**
- **CHR (Cache Hit Ratio)**: Процент запросов, обслуженных из кэша. Цель для статики — >95%, для динамики — >50%.
- **Origin Offload**: На сколько процентов CDN снизила нагрузку (трафик) на исходные серверы.
- **Invalidation Latency**: Время от отправки команды Purge до реального удаления объекта во всех PoP.
