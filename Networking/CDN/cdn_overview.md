# Как работает CDN: геораспределённые серверы

CDN — это распределённая по миру сеть узлов доставки (PoP, Points of Presence), которые приближают контент к пользователю. Геораспределение сокращает сетевые задержки, разгружает исходный сервер (origin) и обеспечивает устойчивость при региональных сбоях. Ключ к работе CDN — выбор «ближайшего» узла и эффективное кэширование, сочетающее DNS/маршрутизацию уровня сети с политиками HTTP.

## Поток запроса и уровни принятия решения

1) **Резолвинг имени**: браузер запрашивает DNS для вашего домена. Часто используется CNAME на домен CDN.
2) **Глобальный балансировщик**: GSLB выбирает «лучший» PoP на основе задержки, геолокации, нагрузки и доступности.
3) **Доставка по Anycast**: клиент получает IP, а маршрутизация BGP приводит трафик к ближайшему по топологии PoP.
4) **Кэш-решение**: узел проверяет наличие объекта. При HIT контент отдаётся сразу; при MISS запрашивается origin, объект сохраняется и отдаётся пользователю.
5) **Валидация**: при истечении TTL узел может ревалидировать с `If-None-Match`/`If-Modified-Since`, что уменьшает трафик к origin.

## Методы привязки пользователя к PoP

| Метод              | Преимущества                                                    | Ограничения                                                              |
| ------------------ | --------------------------------------------------------------- | ------------------------------------------------------------------------ |
| GeoDNS             | Простота, контроль на уровне DNS ответов                        | Нет учёта реальной задержки; кеширование рекурсорами замедляет реакции    |
| Anycast BGP        | Быстрый путь «по сети», устойчивая изоляция региональных инцидентов | Требует глобальной сети и точной настройки анонсов                       |
| HTTP 302 Redirect  | Гибкость, логика на приложении                                  | Дополнительный RTT, усложнение клиентов и кэширования                  |

Практически все крупные CDN комбинируют GeoDNS и Anycast, дополняя телеметрией реальной задержки.

## Политики кэширования на границе

Кэш-контроль осуществляется заголовками. Origin должен явно указывать, что и как кэшировать, отделяя поведение браузера от поведения CDN.

Пример ответов origin для статики и API:

```yaml
# Статика: длительное кэширование на границе, бесконечное в браузере
Cache-Control: public, max-age=31536000, immutable
Surrogate-Control: max-age=31536000
ETag: "app.css-<hash>"

# API: короткий TTL на границе, запрет на браузерный кэш
Cache-Control: no-store
Surrogate-Control: max-age=30, stale-while-revalidate=60
Vary: Authorization, Accept-Encoding
```

Полезные заголовки CDN для диагностики:

```less
X-Cache: HIT/MISS
Age: 123
Via: 1.1 cdn-edge
```

## Управление консистентностью

- **Версионирование объектов**: включение хеша в имя файла (app-`<hash>`.css) делает кэш «вечным», а деплой — атомарным.
- **Инвалидация**: точечное PURGE/ban по пути или тегам при изменении ресурса.
- **TTL-стратегии**: короткий TTL для быстро меняющихся объектов, stale-while-revalidate для снижения латентности при обновлении.

Пример инвалидации через API часто сводится к вызову:

```nginx
curl -H "Authorization: Bearer <token>" 
  -X POST https://cdn.example.com/invalidate 
  -d '["/assets/app-*.css"]'
```

## Особенности геораспределения

- **Иерархия кэшей**: региональные edge узлы могут обращаться к «суперкэшу» (mid-tier), что снижает нагрузку на origin и межконтинентальный трафик.
- **Региональные ограничения**: контент может быть недоступен или подменяться по зонам в целях соответствия правилам.
- **Протоколы и транспорт**: TLS-терминация происходит на edge; сертификаты и ключи реплицируются безопасно, обновления распространяются заранее.
- **Отказоустойчивость**: при деградации PoP GSLB исключает его из ответа; Anycast перераспределяет трафик, сохраняя доступность.

## Наблюдаемость и эффективность

- **Hit Ratio** и **Byte Hit Ratio** отражают качество кэширования.
- **Региональный TTFB** показывает пользу гео-распределения.
- **Трафик к origin** и **egress-стоимость** — ключ к оптимизации бюджета.
- **Ошибки регионов** (5xx на edge и на origin) анализируются раздельно для ускоренной локализации проблем.
