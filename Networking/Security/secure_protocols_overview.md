# Обзор защищенных сетевых протоколов

Стандартные протоколы, такие как HTTP, DNS, TCP и UDP, передают данные по сети в **открытом виде**. Это создает три основные угрозы безопасности:

1.  **Перехват (Eavesdropping):** Злоумышленник может прочитать передаваемые данные, включая пароли, номера кредитных карт и другую конфиденциальную информацию.
2.  **Манипуляция (Tampering):** Злоумышленник может изменить данные в процессе передачи. Например, подменить номер счета в банковской транзакции.
3.  **Атака "человек посередине" (Man-in-the-Middle, MitM):** Злоумышленник встраивается в канал связи между клиентом и сервером, перехватывая, читая и изменяя все сообщения, при этом оставаясь незамеченным для обеих сторон.

Для решения этих проблем были разработаны защищенные сетевые протоколы.

## Три столпа сетевой безопасности

Защищенные протоколы обеспечивают три ключевые гарантии безопасности:

1.  **Приватность (Confidentiality):**
    -   **Задача:** Защитить данные от прочтения посторонними.
    -   **Решение:** **Шифрование**. Все данные, передаваемые по сети, шифруются, что делает их нечитаемыми без ключа.

2.  **Целостность (Integrity):**
    -   **Задача:** Гарантировать, что данные не были изменены в процессе передачи.
    -   **Решение:** **Криптографические хеш-функции**. Получатель может проверить, что полученные данные в точности соответствуют отправленным.

3.  **Аутентификация (Authentication):**
    -   **Задача:** Убедиться, что вы общаетесь именно с тем, за кого себя выдает собеседник (например, что вы подключились к настоящему сайту банка, а не к его подделке).
    -   **Решение:** **Цифровые подписи** и **инфраструктура открытых ключей (Public Key Infrastructure, PKI)**.

## Основные защищенные протоколы

### TLS (Transport Layer Security)

[Протокол TLS](../Protocols/tls_protocol.md) является основой для большинства современных защищенных протоколов. Он обеспечивает фундаментальные функции безопасности (приватность, целостность, аутентификацию).

-   **Положение в стеке TCP/IP:** TLS работает "поверх" TCP, но "под" протоколами прикладного уровня. Фактически, он создает защищенный туннель, внутри которого передаются данные прикладного протокола.
-   **Положение в модели OSI:** TLS охватывает функции сразу трех уровней:
    -   **Транспортный (L4):** Обеспечивает передачу данных между процессами.
    -   **Представления (L6):** Отвечает за шифрование (преобразование формата данных).
    -   **Сеансовый (L5):** Управляет сеансом связи, включая его восстановление (`session resumption`) для ускорения повторных подключений.

### HTTPS (HTTP Secure)

HTTPS — это не отдельный протокол, а комбинация протокола HTTP, работающего поверх защищенного канала, созданного с помощью **TLS**.
- `HTTP + TLS = HTTPS`

### Безопасные варианты DNS

Поскольку стандартный DNS работает по UDP в открытом виде, он уязвим для перехвата и подмены. Для решения этой проблемы существует несколько подходов:

1.  **DNS over TLS (DoT):** инкапсулирует DNS-запросы в защищенный TLS-туннель. Работает по стандартному порту 853.
2.  **DNS over HTTPS (DoH):** инкапсулирует DNS-запросы в HTTPS-трафик. Это маскирует DNS-трафик под обычный веб-трафик, затрудняя его блокировку.
3.  **DNSSEC (DNS Security Extensions):** использует цифровые подписи для подтверждения подлинности и целостности DNS-ответов, защищая от подмены данных (но не шифруя сами запросы).
