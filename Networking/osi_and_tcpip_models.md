#### Модель OSI

Сетевая модель OSI (Open Systems Interconnection) — это концептуальная модель, которая стандартизирует сетевые функции, разделяя их на семь уровней. Каждый уровень обслуживает вышестоящий уровень и использует функции нижестоящего. В процессе отправки данные проходят от 7-го уровня к 1-му, а при получении — в обратном порядке. Этот процесс называется **инкапсуляцией** (при отправке) и **декапсуляцией** (при получении).

На каждом уровне к данным добавляется заголовок (header), и этот блок данных называется **PDU (Protocol Data Unit)**. У каждого уровня PDU имеет своё название.

| Уровень (Layer) | PDU (Тип данных) | Основные функции | Примеры протоколов и стандартов | Оборудование |
| :--- | :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | **Данные (Data)** | Предоставление API для доступа к сетевым службам. | [HTTP](./application_layer.md#http-hypertext-transfer-protocol), FTP, SMTP, DNS, WebSocket, [gRPC](./grpc_overview.md) | Хосты, Шлюзы, L7-брандмауэры (WAF) |
| **6. Представления (Presentation)** | **Данные (Data)** | Преобразование формата данных, сжатие, шифрование. | [SSL/TLS](./tls_protocol.md), ASCII, JPEG, MPEG | Хосты, Шлюзы |
| **5. Сеансовый (Session)** | **Данные (Data)** | Установка, управление и завершение сеансов связи между приложениями. | NetBIOS, RPC, Sockets API | Хосты, Шлюзы |
| **4. Транспортный (Transport)** | **Сегменты** (TCP)<br>**Дейтаграммы** (UDP) | Надёжная (TCP) или быстрая (UDP) доставка данных, контроль потока, адресация по портам. | TCP, UDP, SCTP | Хосты, L4-брандмауэры |
| **3. Сетевой (Network)** | **Пакеты (Packets)** | Маршрутизация пакетов между сетями, логическая адресация (IP-адреса). | IPv4, IPv6, ICMP, IPSec, OSPF | **[Маршрутизатор](./network_devices.md#маршрутизатор-роутер)**, L3-коммутатор |
| **2. Канальный (Data Link)** | **Кадры (Frames)** | Физическая адресация (MAC-адреса), контроль ошибок передачи, управление доступом к среде. | Ethernet, Wi-Fi, PPP, ARP, VLAN | **[Коммутатор (Switch)](./network_devices.md#коммутатор-свитч)**, Мост, Сетевая карта (NIC) |
| **1. Физический (Physical)** | **Биты (Bits)** | Передача битового потока по физической среде (электрические, световые сигналы). | Ethernet (кабель), USB, Bluetooth, RJ-45, Оптоволокно | **Концентратор (Hub)**, Повторитель, Кабели, Трансиверы |

**Уровни:**

*   **Host layers**: 7–4 (Отвечают за представление данных и взаимодействие с приложениями)
*   **Media layers**: 1–3 (Отвечают за передачу данных по сети)

#### Процесс отправки (Инкапсуляция): Собираем "матрёшку"

Когда вы отправляете данные, они проходят сверху вниз по уровням OSI, и на каждом уровне "заворачиваются" в новый "конверт" (PDU).

-   **Уровень 7 (Прикладной): Данные**
    -   **Что происходит:** Ваше приложение (браузер, мессенджер) создаёт исходные данные.
    -   **Результат:** `[Данные: "Привет"]`

-   **Уровень 4 (Транспортный): Данные → Сегменты**
    -   **Что происходит:** Протокол TCP берёт ваши данные и упаковывает их в **сегмент**. На этот "конверт" он пишет **номера портов** (от кого и кому, например, порт 443 для HTTPS). Это нужно, чтобы ОС на той стороне знала, какому приложению отдать данные.
    -   **Результат:** `[Заголовок TCP (порты)] [Данные: "Привет"]`

-   **Уровень 3 (Сетевой): Сегменты → Пакеты**
    -   **Что происходит:** Сегмент упаковывается в следующий конверт — **пакет**. На него протокол IP пишет глобальные адреса — **IP-адреса** отправителя и получателя. Это нужно для маршрутизации по всему интернету.
    -   **Результат:** `[Заголовок IP (IP-адреса)] [Сегмент]`

-   **Уровень 2 (Канальный): Пакеты → Кадры**
    -   **Что происходит:** Пакет упаковывается в последний конверт — **кадр** (фрейм). На него протокол Ethernet пишет локальные, физические адреса — **MAC-адреса** вашего компьютера и вашего роутера. Это нужно для доставки в пределах одной локальной сети.
    -   **Результат:** `[Заголовок Ethernet (MAC-адреса)] [Пакет] [Концевик]`

-   **Уровень 1 (Физический): Кадры → Биты**
    -   **Что происходит:** Ваша сетевая карта преобразует весь кадр целиком в последовательность электрических или световых сигналов.
    -   **Результат:** `0101011101000101...`

#### Процесс получения (Декапсуляция): Разбираем "матрёшку"

-   **Уровень 1: Биты → Кадры**
    -   Сетевая карта получает сигналы и собирает из них **кадр**.

-   **Уровень 2: Кадры → Пакеты**
    -   Система проверяет MAC-адрес в кадре. Если он совпадает, заголовок кадра отбрасывается, и из него извлекается **пакет**.

-   **Уровень 3: Пакеты → Сегменты**
    -   Система проверяет IP-адрес в пакете. Если он совпадает, заголовок пакета отбрасывается, и из него извлекается **сегмент**.

-   **Уровень 4: Сегменты → Данные**
    -   Система смотрит на порт в сегменте, чтобы понять, какому приложению предназначены данные. Заголовок сегмента отбрасывается.

-   **Уровень 7: Обработка данных**
    -   Чистые **данные** передаются приложению (например, веб-серверу).

#### Модель TCP/IP

Модель TCP/IP (Transmission Control Protocol/Internet Protocol) — это практическая, а не теоретическая модель, которая легла в основу современного Интернета. В отличие от OSI, она более гибкая и обычно описывается с помощью четырёх уровней.

**Соответствие уровней OSI и TCP/IP:**

| Уровни OSI | Уровень TCP/IP | Основные функции | Примеры протоколов |
| :--- | :--- | :--- | :--- |
| 7. Прикладной<br>6. Представления<br>5. Сеансовый | **4. Прикладной (Application)** | Взаимодействие с приложениями, представление данных, управление сеансами. | HTTP, FTP, DNS, SMTP, SSH, TLS |
| 4. Транспортный | **3. Транспортный (Transport)** | Обеспечение надёжной (TCP) или быстрой (UDP) доставки, адресация по портам. | TCP, UDP |
| 3. Сетевой | **2. Сетевой (Internet)** | Маршрутизация пакетов между сетями, глобальная адресация (IP). | IP, ICMP, OSPF |
| 2. Канальный<br>1. Физический | **1. Канальный (Network Access)** | Передача данных в локальной сети, физическая адресация (MAC), работа с физической средой. | Ethernet, Wi-Fi, ARP, кабели, коннекторы |

**Ключевые отличия от OSI:**

*   **Прагматизм против теории:** TCP/IP — это набор реальных протоколов, на которых построен интернет. OSI — это эталонная, теоретическая модель, созданная для стандартизации, но её протоколы не получили широкого распространения.
*   **Объединение уровней:** TCP/IP объединяет несколько уровней OSI, что делает модель проще:
    *   Уровни OSI 5, 6, 7 → **Прикладной уровень** TCP/IP.
    *   Уровни OSI 1, 2 → **Канальный уровень** TCP/IP.
*   **Фокус на IP:** В TCP/IP межсетевой протокол (IP) является центральным элементом, вокруг которого строятся все остальные взаимодействия
