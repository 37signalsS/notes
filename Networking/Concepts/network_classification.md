# Классификация сетей

## Определения

* **Классификация сетей:** Систематизация сетевых технологий по ключевым архитектурным и эксплуатационным признакам. Позволяет инженерам выбирать оптимальные стеки технологий для конкретных задач — от подключения носимых устройств до построения глобальных облачных магистралей.
* **Сетевая технология (Network Technology):** Совокупность протоколов, оборудования и среды передачи, обеспечивающая доставку данных между узлами. Классификация оперирует не одним, а набором независимых признаков (осей), поэтому одна и та же реальная сеть одновременно попадает в несколько классов (например, корпоративная Wi-Fi-сеть — это LAN, Broadcast network, Wireless, Private, Connectionless на канальном уровне).
* **Ось классификации (Classification axis):** Независимый признак, по которому сети делятся на группы (коммутация, среда передачи, география, модель взаимодействия и т.д.). Оси ортогональны: выбор по одной из них не предопределяет выбор по другой.

---

## Основные концепции

Сетевые технологии классифицируются по нескольким фундаментальным осям. Ниже приведены восемь основных осей; каждая из них описывает сеть с независимой стороны.

### 1. По типу коммутации

Определяет способ передачи данных между отправителем и получателем — как именно строится путь и как ресурсы резервируются во время сеанса.

#### Коммутация каналов (Circuit Switching)
Перед передачей устанавливается выделенный физический или логический путь, который резервируется на всё время сессии.
- **Плюсы:** Гарантированная полоса пропускания, отсутствие джиттера (вариации задержки), предсказуемая задержка.
- **Минусы:** Неэффективное использование ресурсов (канал занят даже в тишине), долгое установление связи.
- **Примеры:** PSTN (телефония), ISDN, выделенные линии SDH/OTN.
- **Современный контекст:** В чистом виде в data-plane IP-сетей почти не встречается, но принцип «резервирование пути под соединение» живёт в *Circuit Style Policies* (RSVP-TE) и в жёстких гарантиях каналов в оптике (OTN).

#### Коммутация пакетов (Packet Switching)
Данные делятся на пакеты, которые передаются независимо через общую сеть.
- **Дейтаграммный способ:** Каждый пакет маршрутизируется отдельно (IP-сети). Максимальная отказоустойчивость и эффективность использования полосы.
    - **Connectionless:** Узлы не хранят состояние соединения; каждый пакет несёт полный адрес получателя. Примеры: IP, Ethernet, UDP.
- **Виртуальный канал:** Пакеты следуют по заранее проложенному логическому пути (MPLS, ATM). Сочетает гибкость пакетов с предсказуемостью каналов.
    - **Connection-oriented:** Перед передачей данных устанавливается логический путь, и на каждом узле создаётся запись о соединении. Примеры: TCP (сквозное соединение), MPLS LSP, Frame Relay PVC, X.25, ATM.

#### Коммутация сообщений (Message Switching)
Исторический предшественник пакетной коммутации. Узел целиком принимает сообщение, сохраняет его (store-and-forward) и только затем пересылает дальше.
- **Плюсы:** Нет необходимости резервировать сквозной канал; устойчивость к разрывам связи.
- **Минусы:** Огромная задержка и требования к буферу узлов; непригодно для интерактивного трафика.
- **Примеры и наследие:** Телеграф, ранние почтовые системы. Живое наследие — электронная почта (SMTP store-and-forward), SMS, очереди сообщений (Kafka, RabbitMQ), а также **DTN (Delay-Tolerant Networking)** для космоса и экстремальных сред, где связь эпизодична.

### 2. По технологии передачи данных

#### Широковещательные сети (Broadcast Networks)
Единый канал связи разделяется всеми узлами сегмента. Сообщение одного узла «слышат» все остальные.
- **Механизмы доступа:** CSMA/CD (Ethernet) или CSMA/CA (Wi-Fi) для предотвращения коллизий.
- **Особенности:** Требует сегментации через [VLAN](./vlan_l2_switching/definitions_and_concepts.md) для ограничения широковещательного шторма.
- **Важное ограничение IPv6:** В IPv6 широковещание (broadcast) **отсутствует** — вместо него используется multicast (например, `ff02::1` — all-nodes) и NDP вместо ARP. Поэтому «широковещательный домен» в IPv6-сетях вырождается в multicast-группы.

#### Сети точка-точка (Point-to-Point Networks)
Прямое соединение двух узлов.
- **Эффективность:** Использование маски `/31` ([RFC 3021](../Protocols/IP_addressing/special_masks.md), раздел «/31 — Point-to-Point линки») позволяет использовать оба доступных адреса для хостов, экономя пространство IPv4.
- **Примеры:** Магистральные линки маршрутизаторов, туннели (GRE, IPsec, WireGuard).

#### Многоточечные сети (Multipoint / NBMA)
Один интерфейс/канал физически или логически соединяет более двух узлов, но без широковещания (Non-Broadcast Multi-Access). Требуют явного указания соседей.
- **Примеры:** Frame Relay, ATM, классический MPLS (в режиме NBMA), DOCSIS (кабельный доступ), спутниковые каналы.
- **Особенности:** Протоколы маршрутизации (OSPF, EIGRP) здесь требуют ручного назначения DR/BDR или neighbour, так как нет broadcast-обнаружения.

### 3. По географическому масштабу

| Тип | Название | Охват | Примеры / Технологии |
| :--- | :--- | :--- | :--- |
| **BAN** | Body Area Network | < 1 м | Носимые датчики, медицинские импланты (Bluetooth Low Energy) |
| **PAN** | Personal Area Network | ~10 м | Bluetooth, Zigbee, NFC (связь смартфона с часами/наушниками) |
| **LAN** | Local Area Network | До 1-2 км | Офис, дом ([Ethernet](../Protocols/ethernet.md), Wi-Fi 6E/7) |
| **CAN** | Campus Area Network | До 5-10 км | Университет, завод, военная база (объединение нескольких LAN) |
| **MAN** | Metropolitan Area Network | Город | Metro Ethernet, оптические кольца DWDM провайдеров |
| **WAN** | Wide Area Network | Регион / Страна | Магистрали ISP, Интернет, MPLS-сети корпораций |
| **GAN** | Global Area Network | Весь мир | Глобальные спутниковые системы (Starlink), Интернет в целом |

- **Производные классы:** WLAN (Wireless LAN — Wi-Fi сегмент), WWAN (Wireless WAN — сотовая связь 4G/5G как транспорт WAN), HAN (Home Area Network — бытовая автоматика).
- **Границы условны:** Современные технологии стирают чёткие границы. Например, Starlink обеспечивает «WAN-связность» на глобальном (GAN) уровне из дома, а VXLAN-over-Internet превращает географически разнесённые площадки в единый L2-сегмент (эмуляция LAN через WAN).

### 4. По среде передачи (Transmission Medium)

Ось описывает физическую природу сигнала и кабеля — определяет пропускную способность, задержку, помехоустойчивость и стоимость.

#### Проводные (Wired)
- **Витая пара (Twisted Pair):** Cat5e (1 Гбит/с), Cat6/6A (10 Гбит/с), Cat7/8 (40 Гбит/с, защита от перекрёстных наводок). Дешевы, но ограничены длиной сегмента (~100 м).
- **Коаксиальный кабель:** Исторически Ethernet 10BASE5/10BASE2, сегодня — кабельное ТВ и DOCSIS, а также антенные фидеры.
- **Оптоволокно (Optical Fiber):** Многомодовое (MMF, OM3/OM4/OM5 — до 100 м/400 м) для ЦОД; одномодовое (SMF, OS2 — десятки км) для магистралей. Иммунитет к ЭМИ, огромная полоса (100/400/800 Гбит/с и выше).

#### Беспроводные (Wireless)
- **Радио (Radio):** Wi-Fi (IEEE 802.11), сотовые сети (LTE/5G NR), LPWAN (LoRaWAN, NB-IoT) для IoT с низким энергопотреблением.
- **Оптические (Optical Wireless):** Li-Fi (видимый свет, ИК) — для зон с ЭМИ-изоляцией.
- **Спутниковые (Satellite):** GEO (геостационар, высокая задержка ~600 мс RTT), MEO/LEO (Starlink, OneWeb — задержка 20–50 мс RTT).

#### Сравнение сред

| Среда | Типичная задержка (RTT) | Помехоустойчивость | Мобильность | Примечание |
| :--- | :--- | :--- | :--- | :--- |
| Витая пара | < 1 мс (локально) | Средняя | Нет | Дешевизна и массовость |
| Оптоволокно | < 1 мс (локально) | Высокая | Нет | Эталон по полосе и дальности |
| Wi-Fi | 1–5 мс | Низкая (конкуренция эфира) | Да | Полудуплекс, CSMA/CA |
| 5G | 10–30 мс | Средняя | Да | Зависит от загрузки соты |
| Спутник LEO | 20–50 мс | Высокая | Да | Дорого, глобальное покрытие |
| Спутник GEO | ~600 мс | Высокая | Да | Не для real-time интерактива |

### 5. По модели взаимодействия (Interaction Model)

Как распределяются роли между узлами при обмене данными.

- **Клиент-сервер (Client-Server):** Централизованная модель, сервер предоставляет ресурс, клиент потребляет. Доминирует в корпоративных и облачных сетях (HTTP, DNS, SQL, SMB).
- **Одноранговая (Peer-to-Peer, P2P):** Все узлы равноправны, могут быть и клиентом, и сервером. Используется в файлообменных сетях (BitTorrent), блокчейнах, распределённых хранилищах.
- **Гибридная (Hybrid):** Централизованный узел координирует, но данные идут напрямую между равноправными участниками. Примеры: CDN (оркестрация через DNS/Anycast, отдача с edge), Skype (сигнализация через сервер, медиа P2P).

### 6. По принадлежности и доступу (Ownership / Access)

- **Публичные (Public):** Открыты для любого пользователя, управляются провайдерами/государством. Пример: Интернет, публичные Wi-Fi.
- **Частные (Private):** Принадлежат организации, изолированы от публичных сетей (физически или логически через VPN/файрвол). Пример: корпоративная LAN, изолированная СХД.
- **Гибридные (Hybrid):** Комбинация публичных и частных ресурсов с контролируемым взаимодействием. Пример: Hybrid Cloud, SD-WAN поверх Интернета + приватного MPLS.

### 7. По способу установления соединения (Connection Model)

Ось пересекается с коммутацией, но фокусируется на наличии/отсутствии состояния сеанса.

- **Ориентированные на соединение (Connection-oriented):** Перед данными устанавливается соединение, гарантируется порядок и надёжность доставки. Примеры: TCP, MPLS LSP, ATM, Frame Relay, X.25.
- **Без установления соединения (Connectionless):** Каждый пакет самодостаточен, доставка не гарантируется и порядок не сохраняется. Примеры: IP, Ethernet, UDP, IPv6.

### 8. Специализированные и современные типы

#### SAN (Storage Area Network)
Высокоскоростная сеть для подключения систем хранения данных (СХД). Работает независимо от LAN для исключения конкуренции за полосу.
- **Протоколы:** Fibre Channel (FC), iSCSI, а также современный **NVMe over Fabrics (NVMe-oF)**, обеспечивающий минимальные задержки для Flash-массивов через RDMA (RoCE).
- **Изоляция:** Трафик СХД физически или логически (выделенные адаптеры, VLAN, Jumbo Frames) отделяется от пользовательского — см. практический сценарий 4.

#### SD-WAN (Software-Defined WAN)
Оверлейная технология управления WAN-соединениями, отделяющая плоскость управления (Control Plane) от плоскости данных (Data Plane).
- **Принцип:** Динамический выбор пути (Path Steering) на основе качества линка (Latency, Packet Loss) между MPLS, LTE/5G и обычным ШПД.
- **Глубокое описание, архитектура и примеры конфигураций:** [SD-WAN — обзор и практика](./sdn/sd_wan.md).

#### Overlay и Underlay
Современный стандарт построения сетей ЦОД и облаков.
- **Underlay:** Физическая инфраструктура (кабели, коммутаторы, маршрутизаторы), обеспечивающая базовую IP-связность. Обычно строится на базе протоколов BGP или IS-IS (топология Clos/Leaf-Spine).
- **Overlay:** Логическая сеть, построенная поверх Underlay с помощью инкапсуляции. Позволяет создавать изолированные L2/L3 сегменты для тысяч арендаторов (tenants).
    - **Технологии:** VXLAN (стандарт для ЦОД), GENEVE, **HBONE** (используется в Istio Ambient Mesh для инкапсуляции трафика в HTTP/2 CONNECT).
    - **Подробно про VXLAN/GENEVE и MTU:** [VXLAN и GENEVE](./sdn/vxlan_geneve.md); обзор туннелирования: [Tunneling overview](../Tunnels/tunneling_overview.md).

#### VPN (Virtual Private Network)
Логическая частная сеть поверх чужой (обычно публичной) физической инфраструктуры. По оси «коммутация» это packet switching (дейтаграммный/туннельный), по оси «принадлежность» — Private поверх Public.
- **Технологии:** IPsec, WireGuard, OpenVPN, GRE, MPLS L3VPN/L2VPN. Подробнее в разделе [Vpn](../../Vpn/).

#### CDN (Content Delivery Network)
Распределённая сеть edge-узлов для кэширования и отдачи контента ближе к пользователю. По оси взаимодействия — гибридная модель (оркестрация через DNS/Anycast, отдача с edge). Подробнее: [CDN overview](../CDN/cdn_overview.md).

## Практические сценарии

### Предварительные требования (Prerequisites)

Перед применением сценариев ниже убедитесь, что выполнены общие условия:
- **Доступ:** Привилегированный (root/sudo) доступ к узлам Linux или права на конфигурацию сетевого оборудования (Cisco/Juniper/Fortinet).
- **Инструменты:** на Linux установлены `iproute2` (`ip`), `bridge`, `tcpdump`; для диагностики L2 — `ethtool`.
- **Базовые знания:** понимание модели OSI/L2–L3, адресации IPv4/IPv6, принципов маршрутизации.
- **Тестовое окружение:** изменения в production вносить после проверки в staging; иметь план отката (см. «Лучшие практики»).

### Сценарий 1: Настройка point-to-point линка /31 между маршрутизаторами

Демонстрирует классы **Packet Switching (дейтаграммный)** и **Point-to-Point**. Экономит IPv4 по сравнению с `/30`.

**Linux (iproute2), два узла в Underlay:**

```bash
# На R1 (локальный адрес 10.0.0.0/31):
sudo ip addr add 10.0.0.0/31 dev eth1
sudo ip link set eth1 up

# На R2 (локальный адрес 10.0.0.1/31):
sudo ip addr add 10.0.0.1/31 dev eth1
sudo ip link set eth1 up
```

**Cisco-style (IOS-XE), эквивалент:**

```cisco
! R1
interface GigabitEthernet0/1
 ip address 10.0.0.0 255.255.255.254
 no shutdown

! R2
interface GigabitEthernet0/1
 ip address 10.0.0.1 255.255.255.254
 no shutdown
```

**Валидация (ожидаемый результат):**

```bash
# С R1 должен пинговаться сосед 10.0.0.1
ping -c 3 10.0.0.1
# → 64 bytes from 10.0.0.1: icmp_seq=1 ttl=64 time=0.4 ms ... 0% packet loss

# Проверка назначенной маски и связности L2
ip -br addr show eth1
# → eth1   UP   10.0.0.0/31 ...
```

**Граничные случаи:**
- Некоторое *устаревшее* оборудование и старые ОС отвергают `/31` как «invalid host address». В таком случае используйте `/30` (теряется 50% адресов) или переходите на IPv6 с `/127` (RFC 6164).
- В IPv6 для P2P-линков де-факто стандарт — `/127` или `/64`; широковещание отсутствует, поэтому `/127` безопасен.

### Сценарий 2: Сегментация broadcast-домена через VLAN (предотвращение шторма)

Демонстрирует класс **Broadcast Networks** и метод ограничения broadcast-домена.

**Linux (802.1q VLAN на bridge):**

```bash
# Создать VLAN 100 на физическом интерфейсе и поднять bridge
sudo ip link add link eth0 name eth0.100 type vlan id 100
sudo ip link add br100 type bridge
sudo ip link set eth0.100 master br100
sudo ip link set br100 up
sudo ip link set eth0.100 up

# Назначить IP шлюза для сегмента
sudo ip addr add 192.168.100.1/24 dev br100
```

**Коммутатор (Cisco-style), Classic/ Rapid PVST:**

```cisco
vlan 100
 name SERVERS
!
interface GigabitEthernet1/0/10
 switchport mode access
 switchport access vlan 100
!
spanning-tree mode rapid-pvst
! Защита от петель на access-порту
interface GigabitEthernet1/0/10
 spanning-tree portfast
 spanning-tree bpduguard enable
```

**Валидация:**

```bash
# Проверить, что VLAN виден и активен
ip -d link show eth0.100
# → eth0.100@eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> ... vlan protocol 802.1q id 100

# Проверить участников bridge
bridge link show
# → 3: eth0.100: <...> master br100 state forwarding
```

Подробнее о моделях и дизайне VLAN: [VLAN и сегментация L2](./vlan_l2_switching/definitions_and_concepts.md).

### Сценарий 3: Построение Overlay (VXLAN) поверх Underlay — минимальный пример

Демонстрирует класс **Overlay/Underlay** и **Packet Switching (виртуальный канал через метки VNI)**. Полноценный production-пример с BGP EVPN см. в [VXLAN и GENEVE](./sdn/vxlan_geneve.md).

```bash
# VTEP1 (10.0.0.1) и VTEP2 (10.0.0.2), Underlay обеспечивает IP-связность между ними.
# Создать VXLAN-интерфейс VNI=100, трафик инкапсулируется в UDP/4789
sudo ip link add vxlan100 type vxlan \
    id 100 \
    local 10.0.0.1 \
    remote 10.0.0.2 \
    dstport 4789 \
    dev eth0
sudo ip link set vxlan100 up

# Подключить к bridge и назначить IP тестового хоста в overlay-L2
sudo ip link add br100 type bridge
sudo ip link set vxlan100 master br100
sudo ip addr add 192.168.100.1/24 dev br100
sudo ip link set br100 up
```

**Валидация (ожидаемый результат):**

```bash
# Пингуем overlay-соседа 192.168.100.2
ping -c 3 192.168.100.2
# → 64 bytes from 192.168.100.2 ... 0% packet loss

# Перехват инкапсулированных пакетов на Underlay (должны увидеть UDP/4789)
sudo tcpdump -nn -i eth0 port 4789
# → IP 10.0.0.1.XXXX > 10.0.0.2.4789: VXLAN, flags [I] (0x08), vni 100
```

**Граничный случай (MTU):** VXLAN добавляет ~50 байт overhead. Если Underlay MTU=1500, overlay-интерфейс должен быть ≤1450, иначе большие пакеты дропаются или фрагментируются. Проверка: `ping -M do -s 1422 192.168.100.2` (1422+28=1450).

### Сценарий 4: Изоляция трафика СХД (SAN) — выделенный VLAN + Jumbo Frames

Демонстрирует класс **SAN** и изоляцию storage-трафика от пользовательского.

```bash
# Выделить VLAN 200 для iSCSI/NVMe-oF и включить Jumbo Frames (MTU 9000)
sudo ip link add link eth1 name eth1.200 type vlan id 200
sudo ip link set eth1.200 mtu 9000
sudo ip addr add 192.168.200.1/24 dev eth1.200
sudo ip link set eth1.200 up

# Включить Jumbo Frames на физическом порту и коммутаторе (согласованно!)
sudo ip link set eth1 mtu 9000
```

**Валидация сквозного MTU (обе стороны должны поддерживать 9000):**

```bash
ping -M do -s 8972 192.168.200.2
# → 8972 + 28 = 9000 байт проходит без фрагментации
```

**Лучшая практика:** В production СХД изолируется *физически* (отдельные адаптеры/коммутаторы) или *логически* (отдельный VLAN + MTU 9000 на всём пути). Несовпадение MTU на любом звене вызывает скрытые потери и деградацию производительности БД.

### Сценарий 5: Выбор типа коммутации для приложения

Практическая сводка для принятия решений (какую ось коммутации выбрать):

| Требование приложения | Рекомендуемая модель | Обоснование |
| :--- | :--- | :--- |
| Телефония / видео (low jitter) | Circuit Switching / RSVP-TE, либо QoS на packet | Гарантия полосы и минимум джиттера |
| Web / API (масштаб, отказоустойчивость) | Packet (datagram, connectionless L3) | Эффективность и живучесть IP |
| Гарантия доставки и порядка (БД-репликация) | Connection-oriented (TCP) поверх packet | Надёжность на транспорте |
| Предсказуемость пути в провайдере | Virtual circuit (MPLS LSP) | Фиксированный маршрут и SLA |
| Эпизодическая связь (космос/IoT) | Message switching / DTN (store-and-forward) | Устойчивость к разрывам |

## Диагностика и устранение неполадок

### Шторм в широковещательной сети (Broadcast Storm)

**Симптом:** Резкий рост нагрузки на CPU всех коммутаторов в сегменте LAN, массовые потери пакетов, «зависание» сети.
**Причина:** Отсутствие сегментации (слишком большой broadcast-домен) или петля в L2 (ошибка подключения / сбой STP).
**Диагностика:**

```bash
# На коммутаторе: растущий счётчик broadcast и процессор
show interfaces | include broadcast        # Cisco: рост broadcast packets
show processes cpu | include IP Input       # высокая загрузка CPU

# На Linux-мосте: отлов broadcast-шторма
sudo tcpdump -i br100 broadcast 2>/dev/null | head
# → множество ARP/LLDP/NetBIOS подряд

# Поиск MAC-flapping (петля): один MAC появляется на разных портах
bridge fdb show | sort
```

**Решение:**
1. Разделить сеть на мелкие [VLAN](./vlan_l2_switching/definitions_and_concepts.md).
2. Включить **Storm Control** (ограничение速率 broadcast/multicast/unicast):

```cisco
interface GigabitEthernet1/0/10
 storm-control broadcast level 10
 storm-control action shutdown
```

3. Использовать современные альтернативы STP: MC-LAG, или переход к L3 на доступе (routed access), или EVPN с BGP-Unnumbered (см. [Топологии сетей: Leaf-Spine](./network_topologies.md)).

### Недоступность P2P-линка /31

**Симптом:** `ping` между соседями не проходит, интерфейс `UP` но `protocol down`.
**Причины и решения:**
- Обрудование отвергает `/31` → перейти на `/30` или IPv6 `/127`.
- Несовпадение MTU/состояния L1 → `ethtool eth1 | grep -i speed` (должно быть `Link detected: yes`).
- Ошибка адресации (оба узла в разных подсетях) → проверить маску: `ip -br addr show eth1`.

### Overlay-туннель падает / MTU mismatch

**Симптом:** Мелкие пакеты ходят, большие (например, передача файлов) — таймауты и retransmit.
**Диагностика:** `ping -M do -s 1422 <overlay-ip>` падает при MTU 1450.
**Решение:** Выставить MTU overlay-интерфейса ≤ (Underlay MTU − overhead). Для VXLAN: 1500−50=1450. Включить Jumbo Frames (9000) в Underlay для high-perf. Подробнее: [VXLAN и GENEVE — MTU](./sdn/vxlan_geneve.md).

## Лучшие практики (Best Practices)

- **P2P-линки:** Всегда используйте `/31` (IPv4) или `/127` (IPv6) на PtP-соединениях — экономия адресного пространства без потери функциональности.
- **Broadcast-домены:** Держите их маленькими. Одна VLAN = один broadcast-домен; сегментируйте по назначению (servers / users / mgmt / storage).
- **Underlay/Overlay:** Стройте Underlay на BGP-Unnumbered (IPv6 Link-Local + eBGP), Overlay — на VXLAN с BGP EVPN как control plane; это масштабируется до десятков тысяч узлов без проблем STP.
- **SAN:** Физически или логически изолируйте storage-трафик, включайте Jumbo Frames (MTU 9000) **согласованно на всех узлах пути**.
- **Откат изменений (Cleanup):** Перед применения в production фиксируйте текущий конфиг (`show run | file flash:prechange.cfg` на Cisco; `ip addr save` / `ip route save` на Linux), чтобы при сбое быстро вернуть состояние.
- **Мониторинг:** Отслеживайте broadcast-процент, utilisation линков и SLA (latency/loss) — основа для обоснованного выбора класса сети и путей в SD-WAN.

## Граничные случаи (Edge Cases)

- **IPv6 не имеет broadcast:** вместо широковещания — multicast (`ff02::1`) и NDP; класс «Broadcast Networks» к IPv6 применим только косвенно (как multicast-домен).
- **`/31` не поддерживается legacy-оборудованием:** fallback на `/30`; в IPv6 — `/127` (RFC 6164) безопасен.
- **Беспроводная среда — полудуплекс:** Wi-Fi использует CSMA/CA, поэтому реальная пропускная способность канала делится между всеми активными клиентами одной BSS; изоляция через отдельные SSID/VLAN.
- **VXLAN Overlay и MTU:** overhead ~50 байт; несогласованный MTU вызывает «тихие» потери больших пакетов (симптом — работает SSH, но не копируются файлы).
- **SD-WAN зависит от Underlay:** ухудшение базовой связности (Internet/MPLS) напрямую бьёт по overlay-туннелям; диагностику начинайте с Underlay (ping/traceroute до VTEP/peer).
- **NBMA-среды:** отсутствие broadcast-обнаружения требует ручного назначения соседей (OSPF neighbour,Frame Relay map) — иначе маршрутизация не поднимется.
