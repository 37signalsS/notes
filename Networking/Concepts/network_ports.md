# Сетевые порты

## Определения

**Порт** — числовое значение (0–65535) на [транспортном уровне (L4)](../OSI_TCP_IP_Model/osi_model.md) для идентификации конкретного процесса или службы на устройстве.

Пара `IP-адрес:Порт` (сокет) однозначно идентифицирует конечную точку соединения. Подробнее: [Socket API](./socket_api.md).

### Файл /etc/services
В Linux текстовая база данных соответствий имен служб и их портов находится в файле **`/etc/services`**. 
- **Назначение:** Позволяет программам обращаться к портам по именам (например, `ssh` вместо `22`).
- **Формат:** `имя_службы  порт/протокол  [алиасы]`
- **Пример:**
  ```text
  ssh             22/tcp                          # SSH Remote Login Protocol
  http            80/tcp          www             # WorldWideWeb HTTP
  ```

## Основные концепции

IP-адрес определяет устройство-получателя, порт — приложение на этом устройстве.

IANA делит порты на три диапазона:

| Диапазон | Название | Назначение |
| :--- | :--- | :--- |
| 0–1023 | Well-Known Ports | Стандартные системные службы |
| 1024–49151 | Registered Ports | Прикладные приложения (регистрация в IANA) |
| 49152–65535 | Dynamic/Private Ports | Эфемерные порты для временных соединений |

### Привязка к интерфейсу (Bind Address)

Служба может прослушивать порт на конкретном интерфейсе:

- `0.0.0.0:8080` — все интерфейсы (доступно извне)
- `127.0.0.1:8080` — только loopback (локальный доступ)
- `192.168.1.10:8080` — конкретный интерфейс

### Конфликт портов

Два процесса не могут прослушивать одну и ту же пару `IP:Порт` на одном протоколе (TCP/UDP). Попытка приводит к ошибке `Address already in use`. Возможные причины:

- Служба уже запущена (диагностика: [`lsof -i :8080`](../../Linux/Diagnostics/Processes/lsof.md#поиск-процесса-по-порту) или `ss -tlnp | grep :8080`)
- Сокет в состоянии `TIME_WAIT` после перезапуска (решение: `SO_REUSEADDR` / `SO_REUSEPORT`)
- Конфликт контейнеров (Docker/Podman мапят один порт хоста)

## Практические сценарии

### Системные порты (0–1023)

Зарезервированы для стандартных служб. Прослушивание требует привилегий `root`.

| Порт | Служба | Протокол |
| :--- | :--- | :--- |
| 22 | SSH | TCP |
| 25 | SMTP | TCP |
| 53 | DNS | TCP/UDP |
| 80 | HTTP | TCP |
| 443 | HTTPS | TCP |

### Зарегистрированные порты (1024–49151)

Для прикладных служб. Примеры:

| Порт | Служба |
| :--- | :--- |
| 1433 | Microsoft SQL Server |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 8080, 8000 | Альтернативные HTTP-порты |

### Динамические (эфемерные) порты (49152–65535)

Используются автоматически для **исходящих** соединений. Клиент выбирает случайный свободный порт из диапазона.

**Linux:** диапазон управляется через `net.ipv4.ip_local_port_range` (по умолчанию часто `32768 60999`).

```bash
# Текущий диапазон
cat /proc/sys/net/ipv4/ip_local_port_range

# Расширить до максимума
sysctl -w net.ipv4.ip_local_port_range="1024 65535"
```

### Пример: Браузер -> Веб-сервер

При открытии сайта `https://google.com` в браузере создается сетевое соединение со следующими параметрами:

1.  **Порт назначения (Destination Port):** `443` (стандартный порт для HTTPS).
2.  **Порт источника (Source Port):** случайный свободный порт из динамического диапазона (например, `51234`), выбранный операционной системой.

Веб-сервер "слушает" (listen) входящие запросы на порту `443`, а браузер использует эфемерный порт для получения ответа от сервера.

Подробнее: [TCP tuning overview](../../Linux/Networking/Concepts/tcp_tuning/tcp_tuning_overview.md), [TIME_WAIT management](../../Linux/Networking/Concepts/tcp_tuning/tcp_time_wait_management.md).
