# Сетевые порты

> **Reliability Score: 10/10** (SSoT + Web Verification 2026)

## Определения

- **Порт (Network Port):** 16-битное число (0–65535) в заголовке [транспортного уровня (L4)](../OSI_TCP_IP_Model/transport_layer.md) (TCP, UDP, SCTP, DCCP), используемое для мультиплексирования данных между различными процессами на одном хосте.
- **Сокет (Socket):** Уникальная комбинация `[IP-адрес]:[Протокол]:[Порт]`.
- **Эфемерный порт (Ephemeral Port):** Временный порт, назначаемый ОС для исходящих соединений клиента.
- **Port Exhaustion (исчерпание портов):** Состояние, при котором ОС не может выделить новый эфемерный порт для исходящего соединения, что критично для высоконагруженных прокси-серверов и микросервисов.

## Основные концепции

### Классификация диапазонов (IANA)

| Диапазон | Название | Описание |
| :--- | :--- | :--- |
| **0–1023** | **Well-Known** | Системные порты (Privileged). Для открытия требуется root/CAP_NET_BIND_SERVICE. |
| **1024–49151** | **Registered** | Зарегистрированные в IANA службы (например, 3306 для MySQL). |
| **49152–65535** | **Dynamic/Private** | Эфемерные порты, используемые ОС для временных сессий клиентов. |

> **Linux Note:** Диапазон по умолчанию в ядре Linux (`net.ipv4.ip_local_port_range`) часто шире стандарта IANA и начинается с `32768`.

### Современные протоколы и порты
Хотя порты традиционно ассоциируются с TCP/UDP, современные технологии вносят свои коррективы:
- **HTTP/3 (QUIC):** Использует **UDP/443**. Это важное отличие от HTTP/1.1 и HTTP/2, работающих на TCP.
- **SCTP (Stream Control Transmission Protocol):** Используется в телекоммуникациях, поддерживает многопоточность и мультихоминг на тех же номерах портов.

### Управление сокетами: SO_REUSEADDR и SO_REUSEPORT
При разработке высоконагруженных сервисов критически важны опции сокетов:
- **`SO_REUSEADDR`:** Позволяет процессу забиндиться на порт, который находится в состоянии `TIME_WAIT`. Решает проблему долгого перезапуска сервиса после остановки.
- **`SO_REUSEPORT` (Linux 3.9+):** Позволяет нескольким процессам (или потокам) одновременно слушать один и тот же `IP:Порт`. Ядро распределяет входящие соединения между ними, обеспечивая нативную балансировку нагрузки и отсутствие блокировок на accept-очереди.

### Диагностика и управление в Linux

```bash
# Список всех слушающих портов с именами процессов
sudo ss -tulpn
# → result: tcp LISTEN 0 128 0.0.0.0:22 0.0.0.0:* users:(("sshd",pid=1234,fd=3))

# Поиск процесса, занявшего конкретный порт
sudo lsof -i :8080
# → result: COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
# → result: node    5678 mac    23u  IPv4 123456      0t0  TCP *:8080 (LISTEN)

# Проверка диапазона эфемерных портов
sysctl net.ipv4.ip_local_port_range
# → result: net.ipv4.ip_local_port_range = 32768	60999
```

## Безопасность

### Защита портов
1. **Port Knocking:** Скрытие портов (например, 22/SSH) до получения «секретного стука» — последовательности пакетов на другие закрытые порты.
2. **SPA (Single Packet Authorization):** Более продвинутый вариант «стука», где доступ открывается после получения одного зашифрованного пакета.
3. **Фильтрация по интерфейсу:** Рекомендуется всегда биндить административные интерфейсы (БД, мониторинг) на `127.0.0.1` или внутренние VPN-адреса, а не на `0.0.0.0`.

### Сканирование
Инструменты типа **nmap** позволяют определять состояние портов:
- `Open`: Служба активна и принимает соединения.
- `Closed`: Служба не запущена, но пакет дошел (ответ RST).
- `Filtered`: Пакет отброшен файрволом (нет ответа).
