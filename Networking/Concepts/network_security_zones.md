# Сетевые зоны безопасности

## Определения

- **Зона безопасности (Security Zone)** — это логическая группа из одной или нескольких подсетей или VLAN, объединенных общими требованиями безопасности. Деление на зоны основано на уровне доверия к системам и правилах доступа между ними, а не только на физической или сетевой топологии.

- **Демилитаризованная зона (DMZ)** — это изолированная зона, содержащая сервисы, которые должны быть доступны из недоверенной сети (например, из Интернета). Системы в DMZ (веб-серверы, jump-хосты, почтовые реле) имеют наименьший уровень доверия.

- **Сеть управления (Management Network)** — это выделенная, строго изолированная сеть, предназначенная исключительно для административного доступа к сетевому оборудованию, серверам и другим компонентам инфраструктуры.

## Основные концепции

### Принцип "предположения о взломе" (Assume Breach)

Современная информационная безопасность строится на допущении, что абсолютной защиты не существует и система уже может быть скомпрометирована. Основная задача — не только предотвратить взлом, но и минимизировать (mitigate) возможный ущерб, если он произойдет.

### Изоляция и сегментация

Ключевой метод минимизации ущерба — это изоляция. Если злоумышленник получил доступ к одному серверу, его возможности для дальнейшего продвижения по сети должны быть максимально ограничены. Разделение сети на зоны позволяет выстроить барьеры и контролировать трафик между различными сегментами.

- **Зоны vs. VLAN'ы/Подсети**: VLAN'ы и подсети обеспечивают разделение на канальном (L2) и сетевом (L3) уровнях. Зоны — это более высокий, логический уровень абстракции, который используется межсетевыми экранами для применения политик доступа. Одна зона может включать в себя несколько VLAN'ов и подсетей.

### Разделение трафика данных и управления

Управляющий трафик (SSH, RDP, веб-интерфейсы администрирования) должен быть отделен от основного (пользовательского, прикладного) трафика. Это достигается путем создания выделенной сети управления, доступ к которой имеют только администраторы. Это значительно снижает поверхность атаки на критически важные управляющие интерфейсы.

## Практические сценарии

### Архитектура с DMZ

Классическая и надежная архитектура включает как минимум два уровня межсетевых экранов (МСЭ):

1. **Внешний МСЭ (роутер)**: Подключен к интернету. Он фильтрует входящий трафик и перенаправляет его на разрешенные сервисы в DMZ (например, проброс порта 80 на веб-сервер).
2. **DMZ**: Находится "между" внешним и внутренним МСЭ. Серверы в этой зоне не имеют прямого доступа во внутреннюю сеть.
3. **Внутренний МСЭ (роутер)**: Защищает внутреннюю сеть (пользователи, серверы баз данных, системы бэкапа). Он строго контролирует любой трафик, инициированный из DMZ во внутреннюю сеть.

Правила доступа:

- **Из Интернета в DMZ**: Разрешено только на определенные порты (например, 80, 443).
- **Из DMZ во внутреннюю сеть**: По умолчанию **запрещено всё**. Разрешаются только строго необходимые соединения (например, с jump-хоста в DMZ на один управляющий сервер во внутренней сети).
- **Из внутренней сети в DMZ и Интернет**: Обычно разрешается, но может быть ограничено.

### Применение правил на Zone-Based Firewall

Межсетевые экраны, работающие с зонами (например, **firewalld**), по умолчанию блокируют любой трафик между разными зонами. Для разрешения трафика необходимо создавать явные правила или политики.

Например, чтобы разрешить SSH-подключение с jump-хоста в зоне `dmz` на сервер в зоне `servers`, необходимо создать политику, которая разрешает трафик по порту 22 с конкретного IP-адреса источника на конкретный IP-адрес назначения.

### Зоны в Firewalld

Firewalld — это классический пример zone-based файрвола. Он использует предопределенные зоны с различными уровнями доверия:

- **drop**: Самый строгий уровень. Блокирует все входящие пакеты без уведомления (аналог `DROP`).
- **block**: Блокирует входящие пакеты, но отправляет ICMP-ответ отправителю (аналог `REJECT`).
- **public**: Для использования в общественных сетях. Разрешает только выбранные входящие соединения.
- **external**: Для внешних сетей с включенным NAT (masquerading). Используется для роутеров.
- **dmz**: Изолированные сервисы, доступные извне.
- **work/home**: Для доверенных домашних/рабочих сетей.
- **trusted**: Разрешает весь трафик.

**Назначение интерфейсов зонам:**

В firewalld зона может быть привязана к:

1. **Интерфейсу** (например, `eth0` — внешняя сеть, `eth1` — внутренняя сеть).
2. **Source IP-адресу** (подсети или конкретному IP).

```bash
# Назначить интерфейс зоне
firewall-cmd --zone=trusted --change-interface=eth1

# Добавить подсеть в зону (source-based зонирование)
firewall-cmd --zone=trusted --add-source=192.168.1.0/24
```

Подробнее о настройке зон и политик в `firewalld` см. в заметке **[Настройка файрвола в Linux: firewalld](../../Linux/Networking/Settings/Persistent_Network/systemd_networkd.md**.

Подробнее о настройке политик в `firewalld` см. в заметке **[Настройка файрвола в Linux: firewalld](../../Linux/Networking/Settings/Persistent_Network/systemd_networkd.md)**.

### Настройка сети управления

Для изоляции управления на сервере или сетевом устройстве выполняются следующие шаги:

1. Выделяется отдельный физический или виртуальный сетевой интерфейс (`management port`).
2. Этому интерфейсу назначается IP-адрес из подсети управления.
3. Службы управления (например, `sshd`) настраиваются на прослушивание только IP-адреса этого интерфейса (`ListenAddress 10.0.5.101`).
4. На межсетевом экране создается зона `management`, в которую помещается этот интерфейс, и в ней разрешается доступ к нужным службам (например, `ssh`). Во всех остальных зонах доступ к этим службам запрещается.
