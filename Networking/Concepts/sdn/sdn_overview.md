## Определения

- **SDN (Software-Defined Networking)**: Архитектурный подход к построению сетей, при котором плоскость управления (control plane) отделяется от плоскости передачи данных (data plane) и централизуется в программном контроллере. Позволяет управлять всей сетью как единым логическим устройством.

---

## Основные концепции

#### Традиционная архитектура vs SDN

В традиционных сетях каждое устройство (маршрутизатор, коммутатор) имеет собственную плоскость управления, что усложняет автоматизацию и создает зависимость от производителя. SDN выносит логику управления на центральный SDN-контроллер, оставляя сетевым устройствам только задачу пересылки трафика по правилам от контроллера.

#### Три уровня архитектуры SDN

1. **Application Layer (слой приложений)**: Бизнес-логика и сетевые сервисы (файрвол, балансировщик, аналитика). Взаимодействуют с контроллером через Northbound API (интерфейс северного направления).
2. **Control Layer (слой управления)**: «Мозг» сети — SDN-контроллер. Поддерживает глобальное видение сети, рассчитывает маршруты, преобразует требования приложений в правила для устройств.
3. **Infrastructure Layer (слой инфраструктуры)**: Физические или виртуальные коммутаторы и маршрутизаторы (data plane). Управляются контроллером через Southbound API (интерфейс южного направления).

#### Southbound vs Northbound API

| API | Направление | Назначение | Примеры протоколов |
| :--- | :--- | :--- | :--- |
| **Southbound** | Контроллер → Устройства | Управление устройствами, установка правил пересылки. | [OpenFlow](./openflow.md), NETCONF, PCEP |
| **Northbound** | Приложения → Контроллер | Программирование сети, получение аналитики, определение политик. | REST API (Representational State Transfer Application Programming Interface), Java/Python API |

#### Роль протоколов

- **Протоколы управления (например, OpenFlow)**: Динамическое программирование плоскости данных контроллером.
- **Протоколы видимости (например, NetFlow)**: Предоставляют контроллеру и приложениям телеметрию о сетевом трафике для анализа и принятия решений. Не являются протоколами управления.

---

## Практические сценарии

- **Централизованное управление файрволом**: Политики безопасности задаются на контроллере и автоматически применяются ко всем коммутаторам, обеспечивая консистентную защиту.
- **Динамическая балансировка нагрузки**: Контроллер анализирует загрузку каналов (например, через данные [NetFlow](./netflow.md)) и в реальном времени перенаправляет трафик по менее загруженным маршрутам.
- **Изоляция трафика в дата-центрах**: Создание виртуальных сетей для разных клиентов (multi-tenancy) поверх общей физической инфраструктуры с гарантированной изоляцией.
