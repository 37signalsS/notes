## Определения

- **SDN (Software-Defined Networking — Программно-определяемые сети)**: Архитектурный подход к построению сетей, при котором плоскость управления (control plane) отделяется от плоскости передачи данных (data plane) и централизуется в программном контроллере. Это позволяет управлять всей сетевой инфраструктурой как единым логическим устройством через абстракцию программного обеспечения.
- **IBN (Intent-Based Networking — Сети на основе намерений)**: Развитие концепции SDN, при которой администратор определяет только высокоуровневые бизнес-цели (намерения), а система автоматизации самостоятельно переводит их в конфигурации устройств и непрерывно проверяет их соответствие заданному состоянию.

## Основные концепции

### Традиционная архитектура против SDN

В традиционных сетях каждое устройство (маршрутизатор, коммутатор) обладает собственной плоскостью управления, работающей на базе распределенных протоколов (OSPF, BGP, STP). Это усложняет автоматизацию и создает зависимость от конкретных производителей. SDN выносит логику принятия решений на центральный SDN-контроллер, оставляя сетевым устройствам роль «простых» исполнителей, пересылающих трафик по четким правилам.

### Уровни архитектуры SDN

Классическая модель SDN состоит из трех логических уровней:

1.  **Уровень приложений (Application Layer)**: Бизнес-логика и сетевые сервисы (файрволы, балансировщики нагрузки, системы мониторинга). Приложения взаимодействуют с контроллером через **Northbound API (Application Programming Interface — Программный интерфейс приложения)** северного направления.
2.  **Уровень управления (Control Layer)**: Центральное звено — SDN-контроллер. Он поддерживает глобальное видение топологии сети, рассчитывает маршруты и транслирует требования приложений в инструкции для оборудования.
3.  **Уровень инфраструктуры (Infrastructure Layer)**: Физические или виртуальные сетевые устройства (коммутаторы, маршрутизаторы), составляющие плоскость данных. Они управляются через **Southbound API** южного направления.

### Интерфейсы Southbound и Northbound

| Интерфейс | Направление | Назначение | Примеры протоколов и технологий |
| :--- | :--- | :--- | :--- |
| **Southbound** | Контроллер → Устройства | Передача правил пересылки, конфигурация портов, сбор статистики. | [OpenFlow](./openflow.md), gNMI, NETCONF, P4, BGP-LS |
| **Northbound** | Приложения → Контроллер | Программирование сетевых политик, получение аналитики о трафике. | REST API (Representational State Transfer), Java/Python SDK |

## Современный ландшафт (2025–2026)

К 2026 году технологии SDN эволюционировали от простой централизации управления к полной программируемости всей цепочки передачи данных и внедрению искусственного интеллекта.

### Программируемость данных: eBPF и P4

- **eBPF (Extended Berkeley Packet Filter)**: Стандарт де-факто для облачных сетей (Cloud Native). Позволяет запускать безопасные программы внутри ядра Linux без его перекомпиляции. eBPF используется в современных CNI (Container Network Interface), таких как Cilium, для обеспечения высокопроизводительной маршрутизации, безопасности и наблюдаемости.
- **P4 (Programming Protocol-independent Packet Processors)**: Язык программирования для описания того, как пакеты должны обрабатываться сетевым оборудованием (коммутаторами, SmartNIC). P4 обеспечивает аппаратную независимость, позволяя одному и тому же коду работать на разных чипах (ASIC — Application-Specific Integrated Circuit).

### Управление и телеметрия

- **gNMI (gRPC Network Management Interface)**: Заменяет устаревший протокол SNMP для управления конфигурациями и сбора телеметрии. Использует HTTP/2 и Protocol Buffers для передачи данных, поддерживая потоковую телеметрию (Streaming Telemetry) в реальном времени.
- **AIOps (Artificial Intelligence for IT Operations)**: Интеграция моделей машинного обучения в SDN-контроллеры для предиктивного обнаружения аномалий и автоматического устранения неисправностей.

### SD-WAN и SASE

- **SD-WAN (Software-Defined Wide Area Network)**: Применение принципов SDN к распределенным сетям. Позволяет объединять каналы (MPLS, Internet, 5G) в единую виртуальную сеть с динамическим выбором пути на основе качества связи.
- **SASE (Secure Access Service Edge)**: Конвергенция сетевых возможностей (SD-WAN) и функций безопасности (CASB, FWaaS, ZTNA), предоставляемая в виде единого облачного сервиса.

## Практические сценарии

- **Микросегментация в дата-центрах**: Динамическое применение политик безопасности на уровне каждого контейнера или виртуальной машины, предотвращающее горизонтальное перемещение злоумышленников (East-West traffic).
- **Сетевой слайсинг в 5G/6G**: Создание изолированных виртуальных слоев сети с гарантированными параметрами задержки и полосы пропускания для разных типов трафика (например, для беспилотного транспорта и потокового видео).
- **Наблюдаемость в реальном времени**: Использование eBPF для глубокого анализа сетевых задержек на уровне приложений без внесения накладных расходов на обработку трафика.
