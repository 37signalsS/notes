### Определения

- **SDN (Software-Defined Networking)**: Архитектурный подход к построению сетей, при котором плоскость управления (control plane) отделяется от плоскости передачи данных (data plane) и централизуется в программном контроллере. Это позволяет управлять всей сетью как единым логическим устройством.

---

### Основные концепции

#### Традиционная архитектура vs. SDN

В традиционных сетях каждое устройство (маршрутизатор, коммутатор) имеет собственную плоскость управления, что делает автоматизацию сложной и зависящей от производителя. SDN выносит логику управления на центральный **SDN-контроллер**, оставляя сетевым устройствам только задачу пересылки трафика в соответствии с правилами, полученными от контроллера.

#### Три уровня архитектуры SDN

1.  **Application Layer (Слой приложений)**: Бизнес-логика и сетевые сервисы (например, файрвол, балансировщик нагрузки, системы аналитики). Они взаимодействуют с контроллером через **Northbound API**.
2.  **Control Layer (Слой управления)**: "Мозг" сети, представленный SDN-контроллером. Он поддерживает глобальное видение сети, рассчитывает маршруты и преобразует требования приложений в конкретные правила для устройств.
3.  **Infrastructure Layer (Слой инфраструктуры)**: Физические или виртуальные коммутаторы и маршрутизаторы (data plane), которые пересылают трафик. Они управляются контроллером через **Southbound API**.

#### Southbound vs. Northbound APIs

| API | Направление | Назначение | Примеры протоколов |
| :--- | :--- | :--- | :--- |
| **Southbound** | Контроллер → Устройства | Управление физическими устройствами, установка правил пересылки. | [OpenFlow](./openflow.md), NETCONF, PCEP |
| **Northbound** | Приложения → Контроллер | Программирование сети, получение аналитики, определение политик. | REST API, Java/Python API |

#### Роль протоколов

- **Протоколы управления (например, OpenFlow)**: Используются для того, чтобы контроллер мог динамически программировать плоскость данных.
- **Протоколы видимости (например, NetFlow)**: Не являются протоколами управления, но предоставляют контроллеру и приложениям детальную телеметрию о сетевом трафике для анализа и принятия решений.

---

### Практические сценарии

- **Централизованное управление файрволом**: Политики безопасности задаются на контроллере и автоматически применяются ко всем коммутаторам в сети, обеспечивая консистентную защиту.
- **Динамическая балансировка нагрузки**: Контроллер анализирует загрузку каналов (например, через данные [NetFlow](./netflow.md)) и в реальном времени перенаправляет потоки трафика по менее загруженным маршрутам.
- **Изоляция трафика в дата-центрах**: Создание виртуальных сетей для разных клиентов (multi-tenancy) поверх общей физической инфраструктуры с гарантированной изоляцией.
