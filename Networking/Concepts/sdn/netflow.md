### Определения

- **NetFlow**: Сетевой протокол, разработанный Cisco для сбора и экспорта информации об IP-трафике. Он группирует пакеты в "потоки" (flows) и экспортирует агрегированную статистику на коллектор для анализа.
- **Flow (Поток)**: Однонаправленная последовательность пакетов с общими атрибутами: IP-адреса и порты источника/назначения, протокол, ToS.
- **IPFIX (IP Flow Information Export)**: Стандартизированная IETF версия NetFlow (v10), которая является более гибкой за счет использования шаблонов.

> NetFlow предоставляет данные для аналитики и мониторинга, которые могут использоваться приложениями в [архитектуре SDN](./sdn_overview.md) для принятия решений.

---

### Основные концепции

#### Принцип работы

1.  **Сбор данных**: Маршрутизатор или коммутатор анализирует проходящие через него пакеты.
2.  **Кеширование потоков**: Устройство создает запись о новом потоке в своем кеше (flow cache). Статистика (счетчики пакетов и байт) для существующих потоков обновляется.
3.  **Экспорт потоков**: Запись о потоке "закрывается" и экспортируется на коллектор при выполнении одного из условий:
    -   Истечение тайм-аута неактивности (`inactive timeout`).
    -   Истечение тайм-аута активности (`active timeout`).
    -   Обнаружение флагов TCP FIN или RST.
4.  **Анализ на коллекторе**: Коллектор (например, `nfdump`, `Elastiflow`) получает данные, сохраняет их и предоставляет инструменты для анализа и визуализации.

#### Структура записи (на примере NetFlow v5)

Классическая запись NetFlow v5 содержит ключевые поля, идентифицирующие поток, и его статистику:
- **Идентификаторы потока**: `src_ip`, `dst_ip`, `src_port`, `dst_port`, `prot`.
- **Статистика**: `dPkts` (пакеты), `dOctets` (байты).
- **Временные метки**: `First` (время первого пакета), `Last` (время последнего пакета).
- **Атрибуты маршрутизации**: `input`/`output` интерфейсы, `next_hop`, `src_as`/`dst_as` (BGP AS).

#### Версии

| Версия | Ключевая особенность | Статус |
| :--- | :--- | :--- |
| **v5** | Фиксированный формат, наиболее распространенный. | Широко используется |
| **v9** | Гибкий формат на основе шаблонов (template-based). | Стандарт de-facto |
| **IPFIX** | Официальный стандарт IETF, развитие v9. | Современный стандарт |

### Практические сценарии

#### Настройка экспортера NetFlow (Cisco IOS)

```cisco
! Включаем NetFlow на интерфейсах
interface GigabitEthernet0/1
 ip flow ingress
 ip flow egress

! Настраиваем экспорт на коллектор
ip flow-export version 9
ip flow-export destination 192.168.10.100 2055
ip flow-export source Loopback0

! Устанавливаем таймауты (в секундах)
ip flow-cache timeout active 60
ip flow-cache timeout inactive 15

! Проверка работы
show ip cache flow
```

#### Анализ данных с помощью коллектора `nfdump`

```bash
# Запуск коллектора для сбора данных на порту 2055
nfcapd -w -D -p 2055 -l /var/nfdump

# Пример: показать топ-10 IP-адресов по объему трафика
nfdump -r /var/nfdump/nfcapd.202401011200 -s srcip/bytes -n 10

# Пример: отфильтровать трафик к веб-серверу, который превысил 1 МБ
nfdump -r /var/nfdump/nfcapd.current 'dst ip 10.0.0.80 and proto tcp and dst port 80 and bytes > 1000000'
```

### Дополнительная информация

- **Sampling (Сэмплирование)**: На высоконагруженных устройствах для снижения нагрузки может применяться сэмплирование, когда анализируется только каждый N-ный пакет (например, 1 из 100). Это снижает точность, но сохраняет общую картину трафика.
- **NetFlow vs. sFlow**: sFlow (sampled Flow) — альтернативная технология, которая всегда работает на основе сэмплирования пакетов и отправляет на коллектор не агрегированные потоки, а заголовки пакетов.
