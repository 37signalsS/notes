## Определения

- **NetFlow (Сетевой поток)**: Протокол, разработанный компанией Cisco для сбора, учета и экспорта информации об IP-трафике (Internet Protocol). Он позволяет агрегировать пакеты в логические потоки и передавать статистику на центральный коллектор для анализа производительности и безопасности.
- **Flow (Поток)**: Однонаправленная последовательность пакетов, имеющих общие атрибуты (называемые 5-tuple): IP-адреса источника и назначения, порты источника и назначения (L4 — Layer 4), а также тип протокола.
- **IPFIX (IP Flow Information Export — Экспорт информации об IP-потоках)**: Стандарт IETF (Internet Engineering Task Force), основанный на NetFlow v9. Является более гибким и расширяемым протоколом (иногда называемым NetFlow v10), позволяющим передавать произвольные метаданные.
- **L4 (Layer 4 — Транспортный уровень)**: Четвертый уровень модели OSI (Open Systems Interconnection), обеспечивающий передачу данных между процессами (например, через TCP или UDP).

> NetFlow предоставляет данные для аналитики и мониторинга, которые используются приложениями в **[архитектуре SDN](./sdn_overview.md)** для принятия решений о маршрутизации и безопасности.

## Основные концепции

### Принцип работы

Процесс мониторинга потоков разделен на три этапа:

1.  **Экспорт (Exporter)**: Сетевое устройство (маршрутизатор, коммутатор или программный агент) анализирует проходящие пакеты.
    - **Кэширование**: Устройство создает запись в Flow Cache для каждого нового потока.
    - **Агрегация**: Счетчики пакетов и байтов обновляются для существующих записей.
    - **Снятие с учета (Expiration)**: Запись экспортируется, если поток завершен (флаги FIN/RST), истек таймаут неактивности (Inactive Timeout) или максимальное время жизни потока (Active Timeout).
2.  **Сбор (Collector)**: Специализированное ПО принимает данные от экспортеров, выполняет первичную фильтрацию и сохраняет их в базу данных.
3.  **Анализ (Analysis)**: Визуализация данных, обнаружение аномалий (DDoS-атаки), планирование емкости каналов и аудит сетевой активности.

### Сравнение версий протоколов

| Версия | Ключевая особенность | Применение в 2026 году |
| :--- | :--- | :--- |
| **v5** | Фиксированный формат полей. Не поддерживает IPv6 и MPLS. | Устаревший стандарт, встречается в legacy-системах. |
| **v9** | Гибкий формат на основе шаблонов (Templates). Поддержка IPv6. | Стандарт де-факто для оборудования Cisco. |
| **IPFIX** | Официальный стандарт (v10). Позволяет добавлять кастомные поля (Vendor-specific). | **Основной стандарт** для мультибрендовых сетей и Cloud Native. |

## Современный ландшафт (2025–2026)

К 2026 году классический NetFlow эволюционировал в сторону глубокой наблюдаемости (**Observability**) и интеграции с облачными средами.

### Облачные потоки (VPC Flow Logs)

В публичных облаках (AWS, GCP, Azure) мониторинг потоков реализован как нативный сервис **VPC Flow Logs (Virtual Private Cloud Flow Logs)**.
- **Особенности**: Не требует установки агентов, собирает данные на уровне виртуальных сетевых интерфейсов.
- **Метаданные**: Включает облачный контекст (ID инстанса, зона доступности, результат проверки сетевых политик).

### Экспорт через eBPF

Современные программные экспортеры (например, **GoFlow2**, **Akita**) используют технологию **eBPF (Extended Berkeley Packet Filter)** в ядре Linux.
- **Производительность**: Минимальные накладные расходы на CPU.
- **Видимость L7**: Позволяет извлекать информацию прикладного уровня (DNS-запросы, HTTP-заголовки) на уровне транспортных потоков.

### Хранение и анализ: ClickHouse и AIOps

- **ClickHouse**: Считается эталонной базой данных для хранения миллиардов записей потоков благодаря колоночному хранению и высокой скорости выполнения аналитических запросов.
- **AIOps (Artificial Intelligence for IT Operations)**: Интеграция моделей машинного обучения для автоматического выявления «скрытых» аномалий в потоках, которые невозможно обнаружить классическими правилами.

## Практические сценарии

### Настройка экспорта (Cisco IOS)

Пример конфигурации для экспорта NetFlow v9 на коллектор:

```cisco
! Настройка монитора потоков
flow record FLOW-REC
 match ipv4 protocol
 match ipv4 source address
 match ipv4 destination address
 match transport source-port
 match transport destination-port
 collect counter bytes long
 collect counter packets long

! Настройка экспортера (адрес коллектора)
flow exporter FLOW-EXP
 destination 192.168.10.100
 source GigabitEthernet1
 transport udp 2055
 export-protocol netflow-v9

! Применение к интерфейсу
interface GigabitEthernet1
 ip flow monitor FLOW-MON ingress
```

### Анализ через `nfdump` (CLI)

Утилита `nfdump` остается популярным инструментом для оперативного анализа дампов NetFlow.

```bash
# Просмотр статистики по топ-10 потребителям трафика
nfdump -r /var/log/netflow/nfcapd.current -s srcip/bytes -n 10

# Поиск подозрительной активности: трафик на порт 445 (SMB) извне
nfdump -r /var/log/netflow/nfcapd.current 'dst port 445 and net 10.0.0.0/8'
```

## Дополнительная информация

- **Sampling (Сэмплирование)**: На высоконагруженных каналах (100G+) анализируется не каждый пакет, а один из N (например, 1:1000). Это снижает нагрузку на процессор экспортера, но может «пропускать» короткие атаки.
- **sFlow (Sampled Flow)**: Альтернативная технология, которая не агрегирует потоки на устройстве, а сразу пересылает заголовки случайно выбранных пакетов. Более эффективна для коммутаторов (L2).
- **[Архитектура SDN](./sdn_overview.md)** — общие принципы управления сетью.
- **[Open vSwitch (OVS)](../../ServicesAndTools/open_vswitch.md)** — поддержка экспорта NetFlow/IPFIX в виртуальных средах.
