## Определения

- **OpenFlow**: Стандартизированный протокол связи между плоскостью управления (контроллер) и плоскостью данных (коммутатор) в SDN-сетях. Позволяет контроллеру удаленно программировать таблицы потоков (flow tables) на сетевых устройствах.
- **Flow Table**: Таблица на коммутаторе, содержащая набор правил (Flow Entries) для обработки трафика.
- **Flow Entry**: Правило, состоящее из полей сопоставления (match fields), инструкций (instructions) и счетчиков (counters).

> OpenFlow — ключевой southbound-протокол в [архитектуре SDN](./sdn_overview.md).

---

## Основные концепции

#### Принцип работы

Коммутатор OpenFlow сопоставляет входящие пакеты с правилами в таблице потоков. При совпадении применяются инструкции (отправить в порт, изменить заголовок, отбросить). При отсутствии совпадения пакет (или его заголовок) отправляется на SDN-контроллер через сообщение `Packet-In` для получения инструкций.

#### Структура Flow Entry

| Компонент | Описание |
| :--- | :--- |
| **Match Fields** | Поля сопоставления: порт входа, MAC- (Media Access Control) / IP-адреса, порты L4 (Layer 4), VLAN ID (Virtual Local Area Network Identifier). |
| **Priority** | Приоритет правила. Проверка начинается с правил с высшим приоритетом. |
| **Counters** | Статистика: количество пакетов и байт. |
| **Instructions** | Действия: `Apply-Actions`, `Goto-Table` (переход к следующей таблице). |
| **Timeouts** | `Idle Timeout` (удаление при бездействии), `Hard Timeout` (удаление по времени). |
| **Cookie** | 64-битное поле для идентификации и фильтрации правил контроллером. |

#### Ключевые сообщения

**Controller-to-Switch (от контроллера к коммутатору):**

- `Modify-State` (`Flow-Mod`): Добавление, изменение или удаление правил.
- `Send-Packet` (`Packet-Out`): Отправка пакета через указанный порт.
- `Read-State`: Запрос статистики.

**Asynchronous (от коммутатора к контроллеру):**

- `Packet-In`: Уведомление о пакете без правила в таблице потоков.
- `Flow-Removed`: Уведомление об удалении правила (например, по таймауту).
- `Port-Status`: Уведомление об изменении состояния порта (up/down).

## Практические сценарии

#### Обработка нового потока трафика

1. **Первый пакет**: Пакет от `Хоста А` к `Хосту Б` прибывает на коммутатор OpenFlow.
2. **Промах в таблице**: В flow table отсутствует правило для данного потока.
3. **Packet-In**: Коммутатор отправляет пакет (или метаданные) на SDN-контроллер.
4. **Решение контроллера**: Контроллер анализирует пакет, определяет маршрут и отправляет `Flow-Mod` с новым правилом (например, "трафик от А к Б → порт 2"). Исходный пакет может быть возвращен через `Packet-Out`.
5. **Последующие пакеты**: Обрабатываются аппаратно на коммутаторе согласно правилу, без участия контроллера.

## Дополнительная информация

- **Версии**: Наиболее распространена OpenFlow 1.3, добавившая поддержку нескольких таблиц потоков и групповых таблиц.
- **Аппаратная поддержка**: OpenFlow поддерживается многими производителями оборудования и программными коммутаторами (например, OVS — Open vSwitch).
