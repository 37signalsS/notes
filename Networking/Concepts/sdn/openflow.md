### Определения

- **OpenFlow**: Стандартизированный протокол, который обеспечивает связь между плоскостью управления (контроллер) и плоскостью данных (коммутатор) в SDN-сетях. Он позволяет контроллеру удаленно программировать таблицы потоков (flow tables) на сетевых устройствах.
- **Flow Table**: Таблица на коммутаторе, содержащая набор правил (Flow Entries) для обработки трафика.
- **Flow Entry**: Правило, состоящее из полей для сопоставления (match fields), инструкций (instructions) и счетчиков (counters).

> OpenFlow является ключевым southbound-протоколом в [архитектуре SDN](./sdn_overview.md).

---

### Основные концепции

#### Принцип работы

Коммутатор OpenFlow сопоставляет входящие пакеты с правилами в таблице потоков. Если совпадение найдено, к пакету применяются указанные инструкции (например, отправить в порт, изменить заголовок, отбросить). Если совпадение не найдено, пакет (или его заголовок) отправляется на SDN-контроллер через сообщение `Packet-In` для получения инструкций.

#### Структура Flow Entry

| Компонент | Описание |
| :--- | :--- |
| **Match Fields** | Поля для сопоставления пакета: порт входа, MAC/IP-адреса, порты L4, VLAN ID и т.д. |
| **Priority** | Приоритет правила. Пакеты проверяются по правилам с более высоким приоритетом в первую очередь. |
| **Counters** | Статистика по правилу: количество пакетов и байт, прошедших через него. |
| **Instructions** | Действия, которые нужно применить к пакету: `Apply-Actions`, `Goto-Table` (переход к следующей таблице). |
| **Timeouts** | `Idle Timeout` (правило удаляется, если не используется) и `Hard Timeout` (правило удаляется по истечении времени). |
| **Cookie** | 64-битное поле, используемое контроллером для идентификации и фильтрации правил. |

#### Ключевые сообщения

- **Controller-to-Switch (от контроллера к коммутатору)**:
  - `Modify-State` (`Flow-Mod`): Основное сообщение для добавления, изменения или удаления правил в таблице потоков.
  - `Send-Packet` (`Packet-Out`): Инструкция коммутатору отправить конкретный пакет через указанный порт.
  - `Read-State`: Запрос статистики.

- **Asynchronous (от коммутатора к контроллеру)**:
  - `Packet-In`: Уведомление о прибытии пакета, для которого нет правила в таблице потоков.
  - `Flow-Removed`: Уведомление об удалении правила (например, по таймауту).
  - `Port-Status`: Уведомление об изменении состояния порта (up/down).

### Практические сценарии

#### Обработка нового потока трафика

1. **Первый пакет**: Пакет от `Хоста А` к `Хосту Б` прибывает на коммутатор OpenFlow.
2. **Промах в таблице**: В таблице потоков нет правила для этого пакета.
3. **Packet-In**: Коммутатор отправляет пакет (или его метаданные) на SDN-контроллер.
4. **Решение контроллера**: Контроллер анализирует пакет, определяет маршрут и отправляет на коммутатор сообщение `Flow-Mod` с новым правилом (например, "весь трафик от А к Б отправлять в порт 2"). Он также может отправить исходный пакет обратно через `Packet-Out`.
5. **Последующие пакеты**: Все следующие пакеты этого потока обрабатываются аппаратно на коммутаторе согласно новому правилу, без участия контроллера.

### Дополнительная информация

- **Версии**: Наиболее распространенной версией является OpenFlow 1.3, которая ввела поддержку нескольких таблиц потоков и групповых таблиц.
- **Аппаратная поддержка**: OpenFlow поддерживается многими производителями сетевого оборудования, а также в программных коммутаторах, таких как Open vSwitch (OVS).
