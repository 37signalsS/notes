## Определения

- **OpenFlow**: Стандартизированный протокол связи между уровнем управления (**Control Plane** — SDN-контроллер) и уровнем инфраструктуры (**Data Plane** — сетевой коммутатор). Позволяет контроллеру удаленно программировать логику обработки пакетов на сетевых устройствах через абстракцию таблиц потоков.
- **Flow Table (Таблица потоков)**: Структура данных на коммутаторе, содержащая набор правил (Flow Entries). Современные устройства поддерживают многоуровневые таблицы (Pipeline Processing).
- **Flow Entry (Запись потока)**: Элементарное правило обработки трафика, состоящее из критериев сопоставления (**Match Fields**), приоритета, счетчиков и набора инструкций.
- **VLAN ID (Virtual Local Area Network Identifier)**: 12-битный идентификатор виртуальной локальной сети, используемый для сегментации трафика на уровне L2.
- **L4 (Layer 4 — Транспортный уровень)**: Уровень модели OSI (Open Systems Interconnection), на котором работают протоколы TCP (Transmission Control Protocol) и UDP (User Datagram Protocol).

> OpenFlow является ключевым southbound-протоколом (интерфейсом «южного направления») в **[архитектуре SDN](./sdn_overview.md)**.

## Основные концепции

### Конвейерная обработка (Pipeline Processing)

В отличие от ранних версий, современные спецификации OpenFlow (начиная с 1.1) используют многотабличную обработку. Пакет проходит через последовательность таблиц (от 0 до $N$).
- **Переход между таблицами**: Осуществляется с помощью инструкции `Goto-Table`.
- **Метаданные**: 64-битное поле, которое позволяет передавать контекст обработки пакета между таблицами внутри коммутатора.
- **Преимущество**: Снижение количества правил за счет комбинаторной логики (например, Таблица 0 проверяет VLAN, Таблица 1 — IP-адреса, Таблица 2 — политики безопасности).

### Структура записи потока (Flow Entry)

| Компонент | Описание |
| :--- | :--- |
| **Match Fields** | Поля для сравнения: входящий порт, MAC-адреса (Media Access Control), IP-адреса, порты L4, метки MPLS, VLAN ID. |
| **Priority** | Определяет порядок проверки. При совпадении с несколькими правилами выбирается запись с наивысшим приоритетом. |
| **Counters** | Накопительная статистика: количество обработанных пакетов и суммарный объем данных в байтах. |
| **Instructions** | Действия: `Apply-Actions` (немедленно), `Write-Actions` (добавление в набор действий), `Goto-Table` (переход далее по конвейеру). |
| **Timeouts** | `Idle Timeout` (удаление при отсутствии трафика) и `Hard Timeout` (удаление по истечении абсолютного времени). |
| **Cookie** | Непрозрачный идентификатор, используемый контроллером для группировки и управления наборами правил. |

### Групповые и метровые таблицы (Group & Meter Tables)

- **Group Table**: Позволяет описывать сложные методы пересылки, применяемые к набору портов.
  - **Select**: Балансировка нагрузки (ECMP).
  - **All**: Мультикаст или зеркалирование трафика.
  - **Fast Failover**: Автоматическое переключение на резервный канал при отказе основного без участия контроллера.
- **Meter Table**: Используется для реализации механизмов QoS (Quality of Service). Позволяет измерять скорость потока и применять действия (например, `Drop` или `DSCP Remark`) при превышении лимитов.

### Типы сообщений

1. **Controller-to-Switch (Контроллер → Коммутатор)**:
   - `Features-Request`: Запрос возможностей устройства при установке соединения.
   - `Flow-Mod` (`Modify-State`): Основная команда для управления таблицами (добавление/удаление правил).
   - `Packet-Out`: Прямая отправка пакета через коммутатор (используется для ARP-запросов или [LLDP](../../Protocols/lldp.md)).

2. **Asynchronous (Коммутатор → Контроллер)**:
   - `Packet-In`: Передача пакета на контроллер, если для него не найдено соответствие в таблицах или сработал флаг `Send to Controller`.
   - `Flow-Removed`: Уведомление об удалении правила по таймауту.
   - `Port-Status`: Сигнал об изменении состояния физического порта.

## Современный ландшафт (2025–2026)

В 2026 году OpenFlow остается фундаментом для многих зрелых SDN-решений, но его роль трансформируется под давлением новых технологий.

### OpenFlow 1.3 против 1.5.1

- **OpenFlow 1.3 (LTS)**: Остается индустриальным стандартом де-факто. Обладает максимальной поддержкой в аппаратных коммутаторах (ASIC).
- **OpenFlow 1.5.1**: Предлагает расширенные возможности, такие как **Egress Tables** (обработка на выходе), атомарные обновления (**Bundles**) и улучшенную статистику. Широко поддерживается программными коммутаторами (OVS), но реже — аппаратными.

### Место в Cloud Native (Antrea и OVN)

- **Antrea (CNI)**: Активно использует OpenFlow и **[Open vSwitch (OVS)](../../ServicesAndTools/open_vswitch.md)** для реализации сетевых политик Kubernetes. Использует механизмы `Bundles` для обеспечения атомарности изменений, предотвращая кратковременные нарушения безопасности при обновлении правил.
- **OVN (Open Virtual Network)**: Построена на базе OVS и использует OpenFlow для управления виртуальными сетями в OpenStack и Kubernetes.

### OpenFlow и P4

С появлением языка **P4** (Programming Protocol-independent Packet Processors) OpenFlow часто рассматривается как «фиксированный» протокол. P4 позволяет определять собственные заголовки и логику парсинга пакетов, в то время как OpenFlow ограничен предопределенным набором полей. В современных высокопроизводительных сетях наблюдается миграция в сторону **P4Runtime** для управления оборудованием, однако OpenFlow сохраняет доминирующее положение в виртуализированных средах общего назначения.

## Практические сценарии

### Обработка нового потока трафика (Reactive Flow)

1. **Первый пакет**: Пакет от `Хоста А` к `Хосту Б` поступает на коммутатор.
2. **Table Miss**: В Таблице 0 не найдено совпадений. Выполняется инструкция по умолчанию — отправить пакет контроллеру.
3. **Packet-In**: Пакет передается SDN-контроллеру по протоколу OpenFlow.
4. **Решение контроллера**: Контроллер вычисляет маршрут, проверяет политики безопасности и отправляет сообщение `Flow-Mod`.
5. **Flow-Mod**: Коммутатор записывает новое правило. Все последующие пакеты этого потока обрабатываются аппаратно (на скорости канала) без участия контроллера.
