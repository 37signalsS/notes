# Сетевая сегментация и микросегментация

## Определения

- **Сетевая сегментация** — разделение сети на изолированные подсети (сегменты) для повышения производительности и безопасности за счёт локализации трафика и ограничения поверхности атаки.
- **Микросегментация** — контроль доступа на уровне отдельных рабочих нагрузок (ВМ, контейнеры, поды). Политики основаны на идентичности и контексте приложения, а не на IP-адресах.

## Основные концепции

В архитектуре [Zero Trust](./zero_trust_overview.md) сегментация и микросегментация реализуют принцип минимальных привилегий и ограничивают боковое перемещение (east-west traffic).

### Уровни сегментации

1. **L2/L3 (VLAN, подсети, ACL):** Традиционный подход, отделяет крупные домены.
2. **Пограничные фильтры (фаерволы, NACL):** Регулируют north-south трафик и трафик между сегментами.
3. **Виртуальные сегменты (VPC, Security Groups):** Декларативные политики, привязанные к облачным ресурсам.
4. **Распределённые средства (DFW, eBPF, host-based firewall):** L3–L7 контроль непосредственно на хосте или гипервизоре.
5. **Уровень приложений (Service Mesh):** Политики на основе криптографической идентичности (mTLS), контроль на L7 (HTTP-методы, gRPC).

### Принципы микросегментации

- **Deny-by-default:** Весь трафик запрещён, разрешены только явно описанные взаимодействия.
- **Идентификационная привязка:** Политики на стабильных идентификаторах (метки, сервисные аккаунты), а не на эфемерных IP.
- **Контекст и среда:** Раздельные политики для окружений (dev/stage/prod), зон (DMZ, внутренняя), уровней (web/app/db).
- **Наблюдаемость:** Сбор данных о потоках, логирование решений, dry-run перед применением политик.

### Сравнение подходов

| Подход | Масштаб | Управление | Плюсы | Ограничения |
| :--- | :--- | :--- | :--- | :--- |
| [VLAN](../OSI_TCP_IP_Model/data_link_layer.md)/подсети | Крупные домены | Сетевое | Простота, прогнозируемость | Грубо, мало контекста |
| Security Groups/NACL | Подсети/инстансы | Облачное | Декларативность, интеграция | IP/порт-центрично |
| DFW/eBPF/host-firewall | Хост/ворклоад | Распределённое | Точная изоляция, L3–L7 | Сложность согласования |
| Service Mesh | Сервис/идентичность | Прикладное | L7-контроль, mTLS | Доп. сложность, оверхед |

## Практические сценарии

### Типовой паттерн трёхзвенной архитектуры

- **Ingress:** Интернет → web, порты 80/443.
- **Web → App:** Web → app, порт 8080.
- **App → DB:** App → db, порт 5432 (PostgreSQL).
- **Lateral Movement:** Запрет между однотипными экземплярами.
- **Egress:** Только разрешённые внешние эндпоинты (API, репозитории).

### Микросегментация в Kubernetes

`NetworkPolicy` с deny-by-default: трафик к подам `tier: db` разрешён только от `role: app` на порт 5432.

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: db-isolated
  namespace: payments
spec:
  podSelector:
    matchLabels:
      tier: db
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          role: app
    ports:
    - protocol: TCP
      port: 5432
```

Полное руководство: [NetworkPolicy](../../Kubernetes/Networking/Network/network_policy.md).
