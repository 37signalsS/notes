# NAT (Network Address Translation)

## Определения

**NAT (Network Address Translation)** — это технология, позволяющая преобразовывать IP-адреса при передаче трафика через маршрутизатор. Чаще всего она используется для того, чтобы позволить нескольким устройствам в локальной сети выходить в интернет, используя один "белый" (публичный) IP-адрес, выданный провайдером.

NAT работает на [сетевом уровне (L3)](../OSI_TCP_IP_Model/Network_layer/Concepts/network_layer_overview.md) и обычно реализуется на маршрутизаторах или файрволах.

## Основные понятия

### Серый и белый IP-адрес

**Серый IP-адрес** — частный (приватный) IP-адрес из специально выделенных диапазонов, которые не маршрутизируются в глобальной сети (Интернет). Эти адреса можно бесплатно использовать для внутренних локальных сетей.

**Частные диапазоны IPv4 (RFC 1918):**
- `10.0.0.0/8` (10.0.0.0 – 10.255.255.255) — ~16.7 млн адресов
- `172.16.0.0/12` (172.16.0.0 – 172.31.255.255) — ~1 млн адресов
- `192.168.0.0/16` (192.168.0.0 – 192.168.255.255) — ~65 тыс. адресов

**Белый IP-адрес** — публичный IP-адрес, который маршрутизируется в Интернете и уникален в глобальном масштабе.

**Как проверить свой IP:**
1. Откройте сайт https://2ip.ru/ или https://whatismyip.com/
2. Сайт покажет IP-адрес, с которого вы подключились
3. Если отображаемый IP совпадает с вашим локальным (например, `192.168.x.x`) — у вас белый IP
4. Если отображаемый IP отличается — вы за NAT (серый IP)

**Пример:**
```bash
# В Windows (cmd):
ipconfig
# IPv4-адрес . . . . . . . . . . . : 172.20.10.6  ← серый IP

# В браузере откройте 2ip.ru
# Ваш IP: 178.178.244.253  ← белый IP (маршрутизатора)
```

В примере выше хост имеет серый IP `172.20.10.6`, но в Интернет выходит с белого IP `178.178.244.253` благодаря NAT.

### Задачи NAT

1. **Экономия IP-адресов:** Основная причина появления NAT. Позволяет целой локальной сети с [частными IP-адресами](../Protocols/ip.md#частные-приватные-сети-rfc-1918) (например, `192.168.x.x`) использовать для выхода в интернет один публичный IP-адрес.
2. **Повышение безопасности:** Скрывает внутреннюю структуру локальной сети от внешнего мира. Устройства извне не могут напрямую инициировать соединение с компьютерами внутри локальной сети, так как их частные IP-адреса не маршрутизируются в интернете.

### Виды и механизмы NAT

* **PAT (Port Address Translation) или NAT Overload:** Это самый распространенный механизм, используемый в домашних и офисных роутерах. Он позволяет множеству устройств использовать один публичный IP-адрес.
* **Статический NAT (Static NAT):** Однозначное сопоставление "один к одному" между локальным и глобальным IP-адресом (`192.168.1.10` ↔ `203.0.113.10`). Используется для публикации внутренних серверов во внешней сети. Не экономит адреса.
* **Динамический NAT (Dynamic NAT):** Администратор выделяет пул глобальных IP-адресов. Когда внутреннее устройство выходит в интернет, ему динамически назначается свободный IP-адрес из пула. Если пул исчерпан, новые устройства не смогут выйти в сеть. Сегодня используется редко.

### Типы NAT по поведению при трансляции

Различные реализации NAT по-разному обрабатывают входящие соединения из внешней сети:

1. **Full-cone NAT (Статический NAT 1:1)**
   - Взаимная трансляция: одна пара `внутренний IP:порт` всегда привязана к одной паре `внешний IP:порт`
   - Устройство полностью доступно извне по внешнему IP/порту
   - Любой внешний хост может отправить пакет на внутренний хост, зная внешний IP:порт

2. **Address-restricted-cone NAT**
   - Как Full-cone, но с фильтрацией по IP
   - Извне пакет пройдет, только если внутренний хост ранее отправлял пакет на этот внешний IP
   - Ограничивает доступ только к тем хостам, с которыми уже было взаимодействие

3. **Port-restricted-cone NAT**
   - Добавляет фильтрацию по порту
   - Внешний хост должен отвечать только с того порта, на который пришел пакет от внутреннего устройства
   - Более строгая версия Address-restricted-cone

4. **Symmetric NAT (PAT / Port Address Translation)**
   - Самый строгий тип
   - Для каждого нового адреса назначения создается новая уникальная трансляция
   - Часто используется в корпоративных сетях для безопасности
   - Затрудняет работу P2P-приложений

5. **One-to-Many (NAPT / IP Masquerading)**
   - Самый распространенный вид (домашние роутеры)
   - Множество внутренних адресов транслируются в один внешний белый IP
   - Разделение потоков происходит за счет динамической подмены портов источника

**NAT traversal** — техники (STUN, TURN, ICE) для установки прямого соединения между хостами, находящимися за NAT.

### SNAT vs Masquerade (Linux iptables/nftables)

В Linux-маршрутизаторах существуют два основных подхода к реализации NAT:

| Характеристика | **SNAT (Source NAT)** | **Masquerade** |
| :--- | :--- | :--- |
| **Назначение** | Статический публичный IP | Динамический IP (DHCP, PPPoE) |
| **Производительность** | Выше (меньше накладных расходов) | Ниже (дополнительное преобразование) |
| **Конфигурация** | Требует указания `--to-source` | Автоматически определяет внешний IP |
| **Трекинг соединений** | Менее интенсивный | Более интенсивный (трекает все соединения) |
| **Когда использовать** | Серверы со статическим IP | Домашние роутеры, динамические IP |

**SNAT (Source NAT):**

```bash
# Конкретный хост → конкретный публичный IP
iptables -t nat -A POSTROUTING -s 192.168.1.100 -o eth0 -j SNAT --to-source 203.0.113.50

# Вся подсеть → публичный IP
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 203.0.113.50
```

**Masquerade:**

```bash
# Автоматически использует IP внешнего интерфейса
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

**Почему SNAT производительнее:**

* SNAT точно знает, какому хосту принадлежит трафик
* Masquerade должен проверять весь диапазон внутренних адресов
* В современных реалиях разница минимальна для домашних сетей (10-20 хостов)
* Для провайдеров с тысячами клиентов SNAT предпочтительнее

> **Практическая рекомендация:** Если у вас статический публичный IP — используйте SNAT. Если динамический (DHCP, PPPoE) — Masquerade.

## Практические сценарии

### Пример работы PAT (NAT Overload)

**Принцип работы:**

1. Устройство с локальным IP (например, `192.168.0.3`) хочет отправить запрос в интернет (например, на `google.com`). ОС назначает этому соединению временный (эфемерный) порт, например, `54321`.
2. Пакет приходит на роутер. Роутер видит, что пакет идет из внутренней сети наружу.
3. Роутер подменяет в заголовке пакета IP-адрес источника (`192.168.0.3`) на свой собственный публичный IP-адрес (`203.0.113.50`).
4. Чтобы различать ответы для разных устройств, роутер также подменяет порт источника (`54321`) на новый, уникальный для этого соединения порт (например, `33456`).
5. Роутер создает запись в своей **таблице трансляций**:
    `[192.168.0.3]:54321  <--->  [203.0.113.50]:33456`
6. Пакет уходит в интернет. Внешний сервер (`google.com`) видит запрос, пришедший от `203.0.113.50:33456`, и отправляет ответ на этот адрес.
7. Роутер получает ответ. Он смотрит в свою таблицу трансляций, находит соответствующую запись и выполняет обратную замену: IP-адрес и порт назначения меняются на `192.168.0.3:54321`.
8. Пакет доставляется исходному устройству в локальной сети.

### Настройка NAT в firewalld (Linux Router)

Для превращения Linux-хоста в NAT-роутер необходимо:

1. **Включить IP Forwarding** (разрешить пересылку пакетов между интерфейсами):

    ```bash
    # Временно (до перезагрузки)
    sudo sysctl -w net.ipv4.ip_forward=1

    # Постоянно (добавить в /etc/sysctl.conf)
    echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.d/99-router.conf
    sudo sysctl -p /etc/sysctl.d/99-router.conf
    ```

2. **Настроить NAT (Masquerading) в firewalld:**

    ```bash
    # Проверить текущую зону внешнего интерфейса (обычно external или public)
    firewall-cmd --get-active-zones

    # Перевести внешний интерфейс в зону external (где уже есть masquerading)
    firewall-cmd --zone=external --change-interface=<внешний_интерфейс> --permanent

    # Или добавить masquerading в текущую зону
    firewall-cmd --add-masquerade --permanent

    # Перезагрузить firewalld для применения изменений
    firewall-cmd --reload

    # Проверить применение
    firewall-cmd --query-masquerade
    ```

    Зона `external` в firewalld по умолчанию имеет `masquerade=yes`, что автоматически включает NAT для всех исходящих пакетов.

3. **Проверка работы NAT:**

    ```bash
    # С хоста во внутренней сети
    ping 8.8.8.8

    # На роутере посмотреть трансляции
    firewall-cmd --list-all
    ```

### Port Forwarding (DNAT)

**Port Forwarding (проброс портов)** — это частный случай NAT (Destination NAT), при котором трафик, приходящий на определенный порт публичного IP-адреса, перенаправляется на внутренний хост с другим IP-адресом и/или портом.

Это позволяет получить доступ к сервисам во внутренней сети (например, домашнему серверу) из интернета, даже если провайдер выдает "серый" IP.

**Пример настройки через firewalld:**

Допустим, у вас есть веб-сервер во внутренней сети `192.168.1.10`, и вы хотите, чтобы при обращении к порту 8080 вашего публичного IP, трафик перенаправлялся на 80-й порт веб-сервера.

```bash
# Разрешить перенаправление портов в зоне external
firewall-cmd --permanent --zone=external --add-forward-port=port=8080:proto=tcp:toport=80:toaddr=192.168.1.10

# Перезагрузить firewalld
firewall-cmd --reload
```

**Пример на iptables:**

```bash
# Разрешить перенаправление пакетов
iptables -A FORWARD -i eth0 -o eth1 -p tcp --dport 80 -d 192.168.1.10 -m state --state NEW,ESTABLISHED,RELATED -j ACCEPT

# DNAT правило
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.10:80
```

### Проброс SSH через iptables (альтернатива SSH ProxyJump)

**Сценарий:** Доступ к серверу B (серый IP, внутренняя сеть) через сервер A (белый IP, публичный). В отличие от [SSH ProxyJump](../../Linux/Security/ssh/ssh_client_config.md#настройка-подключения-через-jump-host-proxyjump), этот метод работает на сетевом уровне и не требует SSH на промежуточном узле.

**Схема подключения:**
```
[Клиент] --(SSH:2222)--> [Сервер A: белый IP] --(SSH:22)--> [Сервер B: серый IP]
```

**Настройка на сервере A:**

1. **DNAT — перенаправление порта 2222 на порт 22 сервера B:**
   ```bash
   iptables -t nat -A PREROUTING -p tcp --dport 2222 -j DNAT --to-destination <IP_сервера_B>:22
   ```

2. **MASQUERADE — подмена источника для ответных пакетов:**
   ```bash
   iptables -t nat -A POSTROUTING -d <IP_сервера_B> -o eth0 -j MASQUERADE
   ```
   Где `eth0` — интерфейс, через который сервер A связан с сервером B.

3. **FORWARD — разрешение трафика через сервер A:**
   ```bash
   # К серверу B на порт 22
   iptables -A FORWARD -p tcp -d <IP_сервера_B> --dport 22 -j ACCEPT
   
   # Ответный трафик от сервера B
   iptables -A FORWARD -p tcp -s <IP_сервера_B> -j ACCEPT
   ```

4. **Включить IP-форвардинг (если не включён):**
   ```bash
   sysctl -w net.ipv4.ip_forward=1
   ```

**Подключение клиента:**
```bash
ssh user@сервер_A -p 2222 -i my_private_key
```

**Сравнение с SSH ProxyJump:**

| Характеристика | **iptables DNAT** | **SSH ProxyJump** |
| :--- | :--- | :--- |
| **Уровень** | Сетевой (L3) | Прикладной (L7, SSH) |
| **Требования к серверу A** | Доступ к iptables (root) | SSH-доступ |
| **Безопасность** | Ниже (открытый порт) | Выше (шифрование, аутентификация) |
| **Производительность** | Выше (нет накладных расходов SSH) | Ниже (инкапсуляция в SSH) |
| **Гибкость** | Один порт → один сервис | Динамическое туннелирование |
| **Когда использовать** | Постоянный доступ, высокая нагрузка | Временный доступ, безопасность |

> **Рекомендация:** Для временного доступа и безопасности используйте [SSH ProxyJump](../../Linux/Security/ssh/ssh_client_config.md#настройка-подключения-через-jump-host-proxyjump). Для постоянного доступа с высокой нагрузкой — iptables DNAT.

**Схема работы DNAT:**

```
[Клиент из Интернета]
       |
       | Запрос на 203.0.113.50:8080
       v
[Linux Router (DNAT)]
       |  -> Переписывает dst: 203.0.113.50:8080 → 192.168.1.10:80
       v
[Внутренний сервер 192.168.1.10:80]
```

**Схема работы NAT:**

```
[Внутренняя сеть] → [Linux Router (NAT)] → [Интернет]
     10.0.1.x              203.0.113.50 (публичный IP)
                  |
                  +-- SNAT: 10.0.1.x → 203.0.113.50
                  +-- DNAT: 203.0.113.50 → 10.0.1.x (ответы)
```

**Двойной NAT:** Если домашний роутер также использует NAT (серый IP от провайдера), возникает двойная трансляция адресов. Для избежания этого можно на домашнем роутере прописать статический маршрут к внутренней сети Linux-роутера.

## Дополнительная информация

### Домашний маршрутизатор

Обычно домашние маршрутизаторы поставляются с уже включенной функцией NAT. Для этого у них есть специальный WAN-порт, куда подключается провод от провайдера. Все пакеты, выходящие через этот порт, автоматически проходят через NAT. Пользователю не требуется дополнительная настройка — маскарадинг активирован по умолчанию.

### NAT-цепочка (Double NAT и более)

Маршрутизаторы с функцией NAT могут располагаться в цепочку, и тогда IP-адрес отправителя изменяется несколько раз при прохождении пакета.

**Пример работы NAT-цепочки:**

1. Изначально пакет отправляется с хоста (IP-адрес отправителя `192.168.1.1`)
2. Проходя через маршрутизатор 1, IP-адрес меняется на `10.0.0.254` (работает NAT)
3. Проходя через маршрутизатор 2, IP-адрес меняется на `77.88.8.254`
4. Сервер получает ICMP-запрос с IP-адресом отправителя `77.88.8.254`

При обратном следовании пакета каждый NAT-маршрутизатор выполняет обратную подмену IP. Исходный хост получает ответ и не узнает, что на пути следования пакета его IP-адрес менялся — подмена производится прозрачно.

**Двойной NAT (Carrier-Grade NAT):** Возникает, когда провайдер также использует NAT, выдавая абоненту "серый" IP-адрес. Это может создавать проблемы для:
- Проброса портов (требуется настройка на обоих роутерах)
- P2P-приложений (торренты, VoIP, онлайн-игры)
- Удаленного доступа к домашним устройствам

**Решение:** Запросить у провайдера публичный IP-адрес или использовать технологии обхода NAT (VPN, туннели).

### Одинаковые IP-адреса за разными NAT

Благодаря NAT разные хосты могут иметь одинаковые IP-адреса в своих локальных сетях. Например:
- Хост 1 за маршрутизатором 1: `192.168.1.1`
- Хост 2 за маршрутизатором 2: `192.168.1.1`

При выходе в интернет каждый из них будет иметь разные публичные IP-адреса (IP-адреса их маршрутизаторов). Это позволяет повторно использовать частные IP-диапазоны в миллионах независимых локальных сетей по всему миру.

### Проблемы NAT

Несмотря на свои преимущества, NAT создает ряд проблем для некоторых приложений, особенно для peer-to-peer (P2P) протоколов (VoIP, торренты, онлайн-игры), так как усложняет установку прямых соединений между пользователями, находящимися за разными NAT. Для решения этих проблем используются специальные техники, такие как **STUN/TURN** и **UPnP**.
