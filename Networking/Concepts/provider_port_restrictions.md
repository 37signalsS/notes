# Ограничения хостинг-провайдеров на сетевые порты

## Определения

**Ограничение провайдера (Provider Port Restriction)** — принудительная блокировка определенных сетевых портов на уровне инфраструктуры хостинг-провайдера (VPS, выделенные серверы, облачные инстансы). Ограничения применяются на сетевом оборудовании провайдера (маршрутизаторах, экранах, балансировщиках) и недоступны для изменения пользователем изнутри инстанса.

**Default Block List** — набор портов, заблокированных провайдером по умолчанию для всех клиентов. Состав списка зависит от политики безопасности провайдера и evolves со временем по мере появления новых векторов атак.

**Amplification-атака** — вид DDoS-атаки, при которой небольшой запрос к открытому сервису (DNS, NTP, Memcached) вызывает ответ многократно большего объема. Злоумышленник подменяет IP-адрес получателя на адрес жертвы, в результате она получает объемный трафик от множества Reflector-серверов.

## Базовые концепции

### Почему провайдеры блокируют порты

Провайдеры применяют proactive-блокировку для:

1. **Борьбы с ботнетами и спамом** — блокировка порта 25/TCP (SMTP) предотвращает рассылку спама с компрометированных серверов клиентов. Этот порт блокируется подавляющим большинством провайдеров для исходящего трафика.
2. **Снижения риска Amplification-атак** — открытые UDP-сервисы (DNS, NTP, Memcached) на клиентских инстансах могут быть использованы как Reflectors. Блокировка входящего трафика на эти порты защищает как самого клиента, так и интернет-инфраструктуру в целом.
3. **Снижения surface area Windows-сервисов** — порты RPC, SMB и NetBIOS редко используются для легитимного входящего доступа из интернета, но активно эксплуатируются червями и эксплойтами. Блокировка на уровне провайдера защищает клиентов, которые по незнанию оставляют эти порты открытыми.
4. **Регуляторных требований** — в некоторых юрисдикциях (включая РФ) действуют требования по блокировке доступа к определенным ресурсам (ТСПУ, роскомнадзор). Ограничения реализуются на уровне провайдера и не зависят от конфигурации файрвола на стороне клиента.

### Категории блокировок

Блокировки делятся по направлению трафика и категории сервисов:

| Направление | Категория | Типичные порты |
| :--- | :--- | :--- |
| **Исходящий** | SMTP | 25, 465, 587 TCP |
| **Входящий** | Amplification-уязвимые | 53, 123, 389, 1900, 11211 UDP |
| **Входящий** | Windows-сервисы | 135, 137, 138, 139 UDP/TCP, 445 TCP |
| **Входящий** | Управление / конференции | 3389 (RDP), 5060 (SIP) |
| **Любое** | Регуляторные | Зависит от юрисдикции |

### Условия снятия блокировок

Некоторые провайдеры позволяют снять блокировку по заявке в техподдержку:

- **Бизнес-аккаунты** — чаще всего получают разблокировку порта 25/TCP после верификации.
- **Статический IP** — условие для запроса разблокировки у части провайдеров.
- **Дедicated servers** — как правило, имеют меньше ограничений, чем виртуальные серверы.

Порты, связанные с amplification-атаками и Windows-сервисами, обычно разблокировать невозможно, так как провайдер применяет к ним blanket-блокировку на всех клиентов.

## Справочник заблокированных портов

### SMTP (исходящий трафик)

Детали настройки SMTP, relay-решения и SPF/DKIM/DMARC описаны в **[SMTP — протокол и серверы](../Protocols/smtp.md)**.

| Порт | Протокол | Назначение | Статус блокировки |
| :--- | :--- | :--- | :--- |
| **25** | TCP | MTA-to-MTA (прямая передача почты) | Блокируется большинством провайдеров |
| **465** | TCP | SMTP over SSL (legacy) | Блокируется частью провайдеров |
| **587** | TCP | Message Submission (STARTTLS) | Редко блокируется |

### Amplification-уязвимые сервисы (входящий UDP)

Блокировка направлена на защиту от атак типа DNS/NTP/Memcached amplification. Детали механизмов amplification и способы защиты описаны в **[DDoS — обзор и защита](../../Security/ApplicationSecurity/ddos_overview.md)**.

| Порт | Сервис | Риск amplification |
| :--- | :--- | :--- |
| **53** | DNS | Высокий (DNS amplification — до 54x) |
| **123** | NTP | Высокий (NTP amplification — до 556x) |
| **389** | LDAP | Средний (LDAP amplification) |
| **1900** | SSDP (UPnP) | Высокий (SSDP amplification — до 30x) |
| **11211** | Memcached | Критический (до 51 000x) |

### Windows-сервисы (входящий трафик)

Блокировка связана с высокой частотой эксплуатации уязвимостей в этих сервисах через интернет. Детали настройки Samba и защита портов SMB описаны в **[Samba: Безопасность](../../Linux/Networking/Services/samba/samba_security.md)**.

| Порт | Протокол | Сервис | Комментарий |
| :--- | :--- | :--- | :--- |
| **135** | TCP | RPC Endpoint Mapper | Обязателен для RPC; блокируется, если нет белых списков |
| **137** | UDP | NetBIOS Name Service | Legacy; почти не используется в современных сетях |
| **138** | UDP | NetBIOS Datagram Service | Legacy |
| **139** | TCP/UDP | NetBIOS Session Service | Legacy; заменен SMB на 445 |
| **445** | TCP | SMB over TCP | Блокируется большинством провайдеров |

### Другие часто блокируемые порты

| Порт | Протокол | Сервис | Статус |
| :--- | :--- | :--- | :--- |
| **3389** | TCP | RDP (Windows Remote Desktop) | Блокируется частью провайдеров (Timeweb Cloud, Яндекс Облако) |
| **5060** | UDP/TCP | SIP (VoIP) | Блокируется частью провайдеров |

### SMB over QUIC

SMB over QUIC — современный протокол файлового обмена, инкапсулирующий SMB поверх QUIC (UDP 443). Позволяет обойти блокировку порта 445/TCP на уровне провайдера, так как трафик идет через стандартный HTTPS-порт.

**Требования:**
- Windows Server 2022 / Windows 11 21H2+
- Сертификат TLS для SMB-сервера
- Открытый UDP-порт 443 на файрволе

Конфигурация и ограничения описаны в документации Microsoft: [SMB over QUIC](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-over-quic).

## Примеры провайдеров

### Selectel

Selectel поддерживает один из самых детализированных списков заблокированных портов. В список входят как стандартные порты SMTP и amplification-сервисов, так и порты удаленного управления.

Ссылка: [Blocked Ports — Selectel](https://docs.selectel.ru/infrastructure/blocked-ports/)

### Timeweb Cloud

Timeweb Cloud дополнительно блокирует порты 3389 (RDP) и 5060 (SIP), которые остаются открытыми у части других провайдеров.

Ссылка: [Cloud Servers Limitations — Timeweb Cloud](https://timeweb.cloud/docs/cloud-servers/limitations)

### Яндекс Облако (Bare Metal)

Для выделенных серверов (Bare Metal) действуют стандартные сетевые ограничения, включая блокировку Windows-сервисов и amplification-портов.

Ссылка: [Network Restrictions — Yandex Cloud Bare Metal](https://yandex.cloud/ru-kz/docs/baremetal/concepts/network-restrictions)

## Практические сценарии

### Сценарий 1: Диагностика блокировки порта провайдером

**Симптомы:**
- Порт открыт в файрволе и служба слушает на `0.0.0.0`
- `nc -zv <external_ip> <port>` возвращает `Connection timed out`
- Логи файрвола не показывают отброшенные пакеты

**Диагностика:**
```bash
# Проверка, слушает ли служба на всех интерфейсах
sudo ss -tlnp | grep :<port>

# Проверка файрвола
sudo iptables -L INPUT -n | grep <port>
# или
sudo nft list ruleset | grep <port>

# Проверка с внешнего хоста
nc -zv <external_ip> <port>
# → Connection timed out (возможна блокировка провайдером)
```

**Решение:**
1. Проверьте список заблокированных портов провайдера в документации.
2. Если порт заблокирован по умолчанию — запросите разблокировку в техподдержке (если провайдер это позволяет).
3. Если разблокировка невозможна — используйте альтернативный порт или туннель (VPN/SSH tunnel).
4. Для SMB используйте SMB over QUIC на порту 443/UDP.

### Сценарий 2: Обход блокировки SMTP

Для отправки почты при заблокированном порту 25/TCP используйте:

- **Port 587/TCP (STARTTLS)** — стандартный для Message Submission, блокируется реже.
- **Port 465/TCP (Implicit TLS)** — legacy, но все еще поддерживается большинством провайдеров.
- **Smarthost / Relay** — отправка через промежуточный сервис (Amazon SES, SendGrid, Mailgun).
- **IPv6** — некоторые провайдеры блокируют только IPv4-трафик на порту 25.

Детальная настройка relay в Postfix описана в **[SMTP — протокол и серверы](../Protocols/smtp.md)**.

### Сценарий 3: Передача файлов при блокировке порта 445/TCP

Если провайдер блокирует SMB на порту 445/TCP:

1. **SMB over QUIC** — используйте порт 443/UDP с сертификатом TLS.
2. **VPN-туннель** — поднимите VPN (WireGuard/OpenVPN) между клиентами и пробросьте SMB через tun-интерфейс.
3. **SFTP/SCP** — передавайте файлы поверх SSH на порту 22/TCP.
4. **HTTP-upload** — разверните веб-интерфейс загрузки файлов (nginx + upload модуль).

### Сценарий 4: Проверка перед арендой сервера

Перед заказом VPS/дедика проверьте документацию провайдера:

1. Найдите раздел "Ограничения", "Blocked Ports" или "Network Restrictions".
2. Убедитесь, что требуемые порты не заблокированы по умолчанию.
3. Если порты заблокированы — уточните возможность разблокировки и процедуру запроса.
4. Для критичных сервисов (почта, VoIP) запросите письменное подтверждение разблокировки до оплаты.

## Дополнительная информация

### Регуляторные ограничения (ТСПУ)

В некоторых юрисдикциях действуют системы технических средств противодействия угрозам (ТСПУ), которые могут блокировать доступ к определенным подсетям и портам на уровне всей страны. Ограничения:

- **Не зависят от конфигурации файрвола на сервере** — применяются на уровне вышестоящих провайдеров.
- **Могут блокировать SSH** — иногда единственным решением становится заказ нового инстанса в другом регионе.
- **Динамичны** — список заблокированных ресурсов обновляется без предупреждения.
