# L2 Switching и VLAN: Определения и концепции

## Определения

**Коммутатор (Switch)** — интеллектуальное устройство канального уровня (L2), предназначенное для соединения узлов в пределах одной локальной сети (LAN). В отличие от хаба, коммутатор анализирует заголовки кадров и пересылает их только на целевой порт. Современные коммутаторы делятся на:
- **L2-коммутаторы:** работают только на основе MAC-адресов.
- **L3-коммутаторы (Multilayer Switch):** объединяют функции коммутации и маршрутизации, выполняя пересылку трафика между VLAN на аппаратном уровне (**ASIC**).

**VLAN (Virtual Local Area Network)** — технология логического разделения одной физической сетевой инфраструктуры на несколько изолированных широковещательных доменов. Каждой виртуальной сети назначается уникальный **VLAN ID** (от 1 до 4094).

**Коммутательный процесс (Bridge)** — устройство или программный модуль, выполняющий функцию "прозрачного моста": анализирует кадры на основе MAC-адресов и пересылает их между сегментами без участия сетевого уровня (L3). Аппаратные коммутаторы и Linux Bridge являются примерами мостов.

**MAC-адрес (Media Access Control Address)** — уникальный 48-битный (6 байт) аппаратный идентификатор сетевого интерфейса, записываемый в шестнадцатеричном виде (например, `00:1A:2B:3C:4D:5E`). Состоит из **OUI (Organizationally Unique Identifier)** — первых трёх байт, определяющих производителя, и трёх байт уникального идентификатора.

**CAM-таблица (Content Addressable Memory — таблица MAC-адресов)** — динамическая база данных в памяти коммутатора (Content Addressable Memory), сопоставляющая MAC-адреса устройств с физическими портами и номерами VLAN. Лимит CAM-таблицы определяет максимальное количество устройств, которые коммутатор может обслуживать без «затопления» сети.

**FDB (Forwarding Database)** — логическое название таблицы пересылки коммутатора или моста. В аппаратных коммутаторах функционально эквивалентна CAM-таблице, но в программных мостах (Linux Bridge) FDB часто реализуется в обычной ОЗУ с хеш-таблицами, а не в специализированной CAM-памяти.

**Access-порт (Порт доступа)** — порт, предназначенный для подключения конечных устройств (серверов, ПК). Принадлежит только одной VLAN и передаёт нетегированные кадры.

**Trunk-порт (Магистральный порт)** — порт для связи между сетевыми устройствами (коммутаторами, маршрутизаторами, гипервизорами). Передаёт трафик нескольких VLAN одновременно, используя тегирование по стандарту **IEEE 802.1Q**.

**PVID (Port VLAN ID)** — идентификатор VLAN по умолчанию для нетегированных кадров, поступающих на порт. На Access-порте PVID определяет, в какую VLAN попадает входящий безтеговый трафик. На Trunk-порту PVID совпадает со значением **Native VLAN**. Термин используется в оборудовании Huawei, HP (Aruba), Juniper, а также в сетевом стеке Linux.

**Native VLAN** — специальная VLAN на Trunk-порту, трафик которой передаётся без тега 802.1Q. По умолчанию — VLAN 1. В целях безопасности рекомендуется менять её на неиспользуемый ID.

**Hybrid-порт** — специфичен для некоторых вендоров (Huawei, HP). Может передавать как тегированный, так и нетегированный трафик для разных VLAN на одном порту, что выходит за рамки традиционного разделения Access/Trunk.

**Voice VLAN** — специальный режим access-порта (преимущественно Cisco), позволяющий порту работать как «мини-транк»: нетегированный трафик данных попадает в Data VLAN, а тегированный трафик IP-телефона — в отдельную Voice VLAN. Позволяет подключать IP-телефон и ПК через один порт.

**STP (Spanning Tree Protocol, IEEE 802.1D)** — протокол канального уровня, предназначенный для обнаружения и логического блокировки избыточных путей, предотвращая сетевые петли и широковещательные штормы. Строит логическое дерево с одним корневым мостом (Root Bridge).

**RVST / RSTP (Rapid Spanning Tree Protocol, IEEE 802.1w)** — улучшенная версия STP с быстрой сходимостью (1–10 секунд вместо 30–50). Сокращает количество состояний портов с 5 до 3 и добавляет дополнительные роли портов.

**PVST+ (Per-VLAN Spanning Tree Plus)** — проприетарный протокол Cisco, запускающий отдельный экземпляр STP для каждой VLAN. Позволяет выполнять балансировку нагрузки, но увеличивает нагрузку на CPU при большом количестве VLAN.

**MSTP (Multiple Spanning Tree Protocol, IEEE 802.1s)** — стандарт, объединяющий VLAN в группы (инстансы), каждая из которых имеет собственное дерево STP. Обеспечивает балансировку нагрузки с меньшей нагрузкой на CPU по сравнению с PVST+.

**Bridge ID** — 8-байтовый идентификатор коммутатора, используемый STP для выбора Root Bridge. Состоит из приоритета (2 байта, кратно 4096, по умолчанию 32768) и MAC-адреса (6 байт). В PVST+/MSTP к приоритету добавляется Extended System ID — номер VLAN.

**BPDU (Bridge Protocol Data Unit)** — служебные кадры, которые коммутаторы обмениваются для координации STP. Содержат Bridge ID, стоимость пути и флаги для обнаружения топологических изменений.

**DTP (Dynamic Trunking Protocol)** — проприетарный протокол Cisco для автоматического согласования режима порта (Access или Trunk) и протокола тегирования между соседями. Использует многоадресный MAC `01-00-0C-CC-CC-CC`. Основной вектор атаки при VLAN Hopping.

**Port Security** — механизм защиты L2, ограничивающий количество и конкретный перечень MAC-адресов, которым разрешён доступ к порту. Защищает от атак типа **MAC Flooding** и **CAM Table Overflow**.

**IGMP Snooping** — механизм оптимизации многадцастного (Multicast) трафика на коммутаторе путем анализа IGMP-сообщений. Позволяет пересылать Multicast-кадры только в те порты, где есть активные подписчики группы, вместо широковещательного затопления (flooding).

**LACP (Link Aggregation Control Protocol, IEEE 802.3ad)** — протокол агрегации каналов, объединяющий несколько физических линков в один логический (Port Channel / Bonding). Увеличивает пропускную способность и обеспечивает отказоустойчивость.

**ASIC (Application-Specific Integrated Circuit)** — специализированная микросхема, выполняющая коммутацию и маршрутизацию на аппаратном уровне. Обеспечивает высокую пропускную способность L3-коммутаторов для меж-VLAN маршрутизации без нагрузки на CPU.

## Базовые концепции

### Алгоритм работы коммутатора (Алгоритм прозрачного моста)

Коммутатор выполняет пять основных функций для управления трафиком:

1.  **Обучение (Learning):** Считывает MAC-адрес отправителя и привязывает его к порту в CAM-таблице.
2.  **Затопление (Flooding):** Копирует кадр во все порты того же VLAN, кроме входящего, в двух случаях:
    - **Broadcast/Multicast:** трафик для всех или группы.
    - **Unknown Unicast Flooding (UUF):** когда MAC-адрес получателя отсутствует в CAM-таблице.
3.  **Пересылка (Forwarding):** Отправляет кадр в конкретный порт, если MAC-адрес получателя известен.
4.  **Фильтрация (Filtering):** Не пересылает кадр обратно в тот же порт, откуда он пришёл (защита от лишнего трафика в сегментах с общими средами).
5.  **Старение (Aging):** Удаляет неактивные записи из CAM-таблицы (обычно через 300 секунд) для актуализации топологии.

**Жизненный цикл записи в CAM-таблице:**
1. **Ingress:** Коммутатор принимает кадр на порту и считывает Source MAC.
2. **Learning:** MAC-адрес источника записывается в CAM-таблицу с привязкой к порту и VLAN. Если запись существует, таймер обновляется.
3. **Lookup:** Для Destination MAC выполняется поиск в таблице.
4. **Decision:** Если адрес найден — Forwarding на конкретный порт. Если не найден — Flooding во все порты той же VLAN (кроме входного).
5. **Aging:** Если MAC-адрес не активен в течение **Aging Time** (по умолчанию 300 секунд на большинстве коммутаторов), запись удаляется.

**Ограничения CAM-таблицы:** Аппаратные коммутаторы имеют конечный размер CAM-таблицы (например, 16K, 32K записей). При превышении лимита коммутатор вынужден работать в «режиме хаба» — затапливать весь трафик на все порты, что создаёт серьёзную угрозу безопасности.

### Домены в сетях L2

| Тип домена | Описание | Граница разделения |
| :--- | :--- | :--- |
| **Домен коллизий** | Сегмент, где возможны столкновения сигналов. | Каждый порт коммутатора (в Full Duplex коллизии исключены). |
| **Широковещательный домен** | Область распространения Broadcast-кадров. | Ограничивается границами VLAN или интерфейсом маршрутизатора. |

**Важно:** Одна физическая инфраструктура может содержать несколько широковещательных доменов (один на каждую VLAN). Меж-VLAN взаимодействие возможно только через L3-устройство (см. **[Меж-VLAN маршрутизация](../../Protocols/VLAN/vlan_inter_vlan_routing.md)**).

### Методы коммутации (Switching Methods)

-   **Store-and-Forward:** Полный прием кадра, проверка контрольной суммы (FCS) перед отправкой. Максимальная надежность, высокая задержка.
-   **Cut-Through:** Пересылка начинается после считывания первых 6 байт (MAC получателя). Минимальная задержка, риск трансляции битых кадров.
-   **Fragment-Free:** Коммутатор ждёт первых 64 байт кадра (минимальный размер Ethernet), чтобы отсечь коллизионные фрагменты.
-   **Adaptive Switching:** Автоматическое переключение между Cut-Through и Store-and-Forward при обнаружении ошибок.

### Взаимодействие с STP и отказоустойчивость

В сетях с VLAN протокол STP работает в режиме **PVST+ (Per-VLAN Spanning Tree)** или **MSTP**, почитать подробнее в **[STP: Протокол связующего дерева](../../Protocols/stp.md)**. Это позволяет строить независимые логические топологии для каждой VLAN, что даёт возможность балансировать нагрузку между избыточными линками.

**Роли портов STP:**
- **Root Port:** единственный порт с минимальной стоимостью пути до Root Bridge (на каждом не-корневом коммутаторе).
- **Designated Port:** порт, ответственный за передачу трафика в сегменте (один на каждый сегмент).
- **Blocking/Discarding:** порт, заблокированный для разрыва петли (в резерве на случай отказа).
- **Alternate Port (RSTP):** резервный путь к Root Bridge — мгновенно заменяет Root Port при отказе.
- **Backup Port (RSTP):** резервный путь в тот же сегмент, дублирующий Designated Port.

**Выбор Root Bridge:** Root Bridge выбирается по наименьшему **Bridge ID**. Рекомендуется вручную назначать корневым наиболее мощный коммутатор: `spanning-tree vlan 1-4094 root primary`.

### LACP — агрегация каналов (Link Aggregation)

**LACP (Link Aggregation Control Protocol, IEEE 802.3ad)** объединяет несколько физических линков в один логический канал (Port Channel в Cisco, Bonding в Linux).

**Преимущества:**
- **Увеличение пропускной способности:** суммируются скорости всех участников агрегата.
- **Отказоустойчивость:** при потере одного линка трафик продолжает идти по оставшимся.
- **Балансировка нагрузки:** распределение трафика по линкам на основе хэша (по SRC/DESC MAC, IP, портам).

Подробнее: **[Агрегация каналов (Link Aggregation)](../../Concepts/link_aggregation.md)**.

### IGMP Snooping

По умолчанию коммутатор рассылает мультикаст-трафик на все порты VLAN (как широковещательный). **IGMP Snooping** позволяет анализировать IGMP-сообщения и пересылать multicast-кадры только в порты с активными подписчиками группы, экономя пропускную способность и снижая нагрузку на хосты.

### Безопасность и ограничения L2

- **CAM Table Overflow:** Атака, при которой злоумышленник забивает таблицу поддельными MAC-адресами, заставляя коммутатор работать как хаб (flooding всего трафика). Защита — **Port Security**.
- **VLAN Hopping:** Обход изоляции VLAN через манипуляции с тегами или DTP.
- **Broadcast Storm:** Зацикливание широковещательного трафика, приводящее к отказу сети. Защита — **Storm Control**.
- **DHCP Snooping:** Защита от подмены DHCP-серверов и исчерпания пула адресов. Строит таблицу привязки `[MAC + IP + Lease + VLAN + Port]`, которая является источником истины для DAI и IP Source Guard.
- **ARP Spoofing:** Подмена MAC-адреса шлюза. Защита — **Dynamic ARP Inspection (DAI)**.

Подробнее о механизмах защиты: **[Безопасность портов и VLAN Hopping](../../Protocols/VLAN/vlan_dtp_security.md)** и **[Жёсткая защита L2: DHCP Snooping, DAI, IPSG, BPDU Guard](../../Protocols/VLAN/vlan_security_hardening.md)**.
