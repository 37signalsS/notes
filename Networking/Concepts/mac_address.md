# MAC-адрес (Media Access Control)

## Определения

**MAC-адрес** — это уникальный идентификатор, который назначается сетевому интерфейсу (сетевой карте) для связи на канальном уровне ([Layer 2](../OSI_TCP_IP_Model/osi_model.md)) в сегменте сети. Он используется в таких технологиях, как [Ethernet](../Protocols/ethernet.md) и Wi-Fi, для доставки кадров (frames) конкретному устройству в локальной сети.

В стандарте IEEE 802, канальный уровень разделен на два подуровня:

* **LLC (Logical Link Control):** Отвечает за взаимодействие с сетевым уровнем.
* **MAC (Media Access Control):** Отвечает за управление доступом к среде и использует MAC-адреса для адресации.

MAC-адреса регламентированы стандартами IEEE 802.

## Основные концепции

### Структура и формат

* **Длина:** 6 байт (48 бит).
* **Формат записи:** Шесть групп по две шестнадцатеричные цифры, разделенные двоеточиями (`:`) или дефисами (`-`).
  * Пример: `00:1A:2B:3C:4D:5E` или `00-1A-2B-3C-4D-5E`.

### Типы MAC-адресов

1. **Индивидуальный (Unicast):**
    * Адрес, который идентифицирует один конкретный сетевой адаптер.
    * Кадр, отправленный на unicast-адрес, доставляется только одному устройству в сети.
    * Первый бит старшего байта равен `0`.
    * Такой адрес есть у каждой сетевой карты. Он либо прошивается на заводе производителя, либо устанавливается вместе с драйверами.

2. **Групповой (Multicast):**
    * Адрес, который используется для отправки данных группе устройств.
    * Кадр, отправленный на multicast-адрес, получают все устройства, которые подписаны на эту группу.
    * Первый бит старшего байта равен `1`.
    * Начинается с префикса `01:00:5E`.
    * Пример: `01:00:5E:00:00:01`.
    * Этот специальный адрес сетевая карта может себе присвоить в случае, когда ожидается рассылка пакетов сразу группе хостов.

3. **Широковещательный (Broadcast):**
    * Специальный адрес для отправки данных всем устройствам в одном сегменте сети.
    * Кадр, отправленный на broadcast-адрес, получают все устройства в сети.
    * Адрес состоит из всех битовых единиц.
    * Шестнадцатеричное представление: `FF:FF:FF:FF:FF:FF`.
    * Такой адрес в поле получателя означает, что пакет должен быть обработан всеми хостами, которые получили данный пакет.

### Отображение группового IP-адреса в MAC-адрес

При отправке пакета на групповой IP-адрес (multicast) не используются ARP-запросы. Пакет доставляется сразу нескольким хостам, поэтому MAC-адрес формируется автоматически на основании IP-адреса назначения.

**Формат группового MAC-адреса:**

1. Первые 3 байта (24 бита) всегда `01:00:5E`
2. Затем следует бит `0`
3. Оставшиеся 23 бита MAC-адреса устанавливаются в младшие 23 бита IP-адреса

**Проблема отображения:**

В сети класса D (`224.0.0.0` – `239.255.255.255`) у всех IP-адресов старшие 4 бита всегда одинаковые, а меняются только младшие 28 бит. В MAC-адрес отображается всего 23 бита, оставшиеся 5 бит «не влезают».

**Следствие:** существует **32 (2⁵) групповых IP-адреса**, которые дают **одинаковый MAC-адрес**.

**Пример:**

```
IP-адреса:  224.1.1.1, 224.129.1.1, 225.1.1.1
MAC-адрес:  01:00:5E:01:01:01 (одинаковый для всех)
```

Сетевой интерфейс настраивается на приём пакетов по этому MAC-адресу. Если пакет придёт для другого IP с таким же MAC, он будет принят сетевой картой, но отброшен выше по стеку (на уровне IP) из-за несовпадения IP-адресов.

**Подробнее:** [Групповые IP-адреса](../Protocols/ip.md#частные-приватные-сети-rfc-1918), [Multicast в UDP](../Protocols/udp.md#передача-группового-трафика-multicast)

### Уникальность и назначение адресов

**Важно:** MAC-адрес обязан быть уникальным только лишь внутри бродкастового домена, иными словами — в пределах одного маршрутизатора (или сегмента сети L2).

Крайне важно, чтобы MAC-адреса были уникальны в пределах одного сегмента сети. Если в сети появятся два устройства с одинаковыми MAC-адресами, возникнет конфликт.

**Конфликт MAC-адресов:**

Когда в сети присутствуют два хоста с одинаковыми MAC-адресами, коммутатор начинает периодически переписывать запись в MAC-таблице, связывая адрес то с одним, то с другим портом (по мере получения кадров от каждого хоста). В результате:
- Часть трафика, предназначенного для этого MAC-адреса, доставляется первому хосту
- Другая часть трафика доставляется второму хосту
- Оба хоста получают неполные данные, что приводит к сбоям связи

Детальное описание поведения коммутатора при дублировании MAC-адресов см. в **[Канальный уровень](../OSI_TCP_IP_Model/data_link_layer.md)**.

Существует два способа назначения MAC-адресов:

#### 1. Централизованное назначение (аппаратный адрес)

Это способ по умолчанию. MAC-адрес "прошивается" производителем оборудования в сетевой адаптер на заводе. Для обеспечения глобальной уникальности используется иерархическая схема:

* **Первые 3 байта (24 бита):** **OUI (Organizationally Unique Identifier)** — уникальный идентификатор организации, который выдается производителю комитетом IEEE. По OUI можно определить производителя устройства.
  * Примеры OUI: `00-1B-63` (Cisco), `00-0A-95` (IBM), `E8-03-9A` (Intel).
* **Последние 3 байта (24 бита):** Назначаются производителем по своему усмотрению. Производитель должен гарантировать, что он не выпустит два адаптера с одинаковым OUI и одинаковой второй частью адреса.

#### 2. Локальное назначение (программный адрес)

Сетевой администратор может вручную изменить MAC-адрес сетевого адаптера. В этом случае ответственность за обеспечение уникальности адресов в сети ложится на администратора.

**Как отличить централизованный адрес от локального?**

Для этого используется **второй бит** старшего байта MAC-адреса:

* `0`: Адрес назначен централизованно (аппаратный).
* `1`: Адрес назначен локально (программный).

## Практические сценарии

### Как посмотреть MAC-адрес

#### Windows

* **Командная строка:**

  ```cmd
  ipconfig /all
  ```

  Искать параметр **"Физический адрес"** в списке локальных сетевых устройств.
* **Графический интерфейс:** В свойствах сетевого подключения.

#### Linux

* **Команда `ip` (современный способ, пакет iproute2):**

  ```bash
  ip link show
  ```

  или

  ```bash
  ip a
  ```

  Искать `link/ether`.

  > **Примечание:** В современных Linux-дистрибутивах команда `ifconfig` считается устаревшей и часто отсутствует в стандартной поставке. Вместо неё рекомендуется использовать `ip address` из пакета `iproute2`.

* **Команда `ifconfig` (устаревший способ):**

  ```bash
  ifconfig
  ```

  Искать `ether` или `HWaddr`.

#### macOS

* **Командная строка:**

  ```bash
  ifconfig
  ```
