# MAC-адрес (Media Access Control)

> **Reliability Score: 10/10** (SSoT + Web Verification 2026)

## Определения

- **MAC-адрес (Media Access Control Address):** Уникальный 48-битный идентификатор, назначаемый сетевому интерфейсу для связи на канальном уровне ([Layer 2](../OSI_TCP_IP_Model/osi_model.md)). Является физическим адресом устройства в сегменте сети.
- **Стандарт IEEE 802:** Разделяет канальный уровень на два подуровня:
    - **LLC (Logical Link Control):** Отвечает за взаимодействие с сетевым уровнем.
    - **MAC (Media Access Control):** Отвечает за управление доступом к среде и использует MAC-адреса для адресации.
- **OUI (Organizationally Unique Identifier):** Первые 3 байта (24 бита) адреса, идентифицирующие производителя оборудования.
- **UAA (Universally Administered Address):** Аппаратный адрес, прошитый на заводе.
- **LAA (Locally Administered Address):** Программный адрес, назначенный администратором или ОС.

## Основные концепции

### Структура и формат
- **Длина:** 6 байт (48 бит).
- **Запись:** Шесть групп по две шестнадцатеричные цифры, разделенные двоеточиями (`:`) или дефисами (`-`).
- **Битовая структура:**
    - **1-й бит старшего байта:** Тип адреса (0 — Unicast, 1 — Multicast).
    - **2-й бит старшего байта:** Способ назначения (0 — Глобальный/OUI, 1 — Локальный/Административный).

### Типы MAC-адресов

1. **Индивидуальный (Unicast):**
   - Идентифицирует один конкретный сетевой адаптер.
   - Младший бит старшего байта равен `0`.
2. **Групповой (Multicast):**
   - Используется для отправки данных группе устройств.
   - Младший бит старшего байта равен `1`.
   - **Важно для Linux:** ОС считает групповым любой адрес, где этот бит равен 1 (например, `01:00:00:00:00:00`), хотя стандартный диапазон IPv4 Multicast начинается с `01:00:5E`.
3. **Широковещательный (Broadcast):**
   - Специальный адрес для всех устройств в сегменте L2.
   - Состоит из всех битовых единиц: `FF:FF:FF:FF:FF:FF`.

### Отображение группового IP-адреса в MAC-адрес
При Multicast-рассылке не используется ARP. MAC-адрес формируется автоматически из IP-адреса назначения:
1. Первые 24 бита всегда `01:00:5E`.
2. 25-й бит всегда `0`.
3. Оставшиеся 23 бита берутся из младших бит IP-адреса.

**Проблема 32 к 1:**
У IP-адресов Multicast (класс D) меняются младшие 28 бит. Поскольку в MAC-адрес копируется только 23 бита, возникает ситуация, когда **32 разных IP-адреса** отображаются в **один и тот же MAC-адрес**.
*Пример:* `224.1.1.1` и `224.129.1.1` будут иметь одинаковый MAC `01:00:5E:01:01:01`. Это означает, что сетевая карта примет пакет, а фильтрация произойдет выше — на сетевом уровне.

### Метод EUI-64 (IPv6)
В сетях IPv6 MAC-адрес используется для генерации Interface ID:
1. 48-битный MAC делится пополам.
2. В середину вставляется `FF:FE`.
3. Инвертируется 7-й бит первого байта (Universal/Local).
*Пример:* `00:11:22:33:44:55` → `02:11:22:FF:FE:33:44:55`.

### Уникальность и конфликты
MAC-адрес должен быть уникален в пределах одного **широковещательного домена (L2)**.

**Конфликт в одной сети:**
Если у двух устройств один MAC, коммутатор будет постоянно обновлять таблицу коммутации (MAC-таблицу), перенаправляя трафик то на один порт, то на другой. Это называется **MAC Flapping**. Результат — потеря пакетов и нестабильное соединение у обоих хостов.

**Одинаковые MAC за маршрутизатором:**
Если устройства находятся в разных сетях, разделенных маршрутизатором, конфликта не будет. Маршрутизатор не пропускает ARP-запросы между сетями и доставляет пакеты на основе IP-адресов. На каждом сегменте пути L2-кадры будут иметь свои локально значимые MAC-адреса.

## Современные технологии

### Рандомизация MAC-адресов
Для защиты от отслеживания в Wi-Fi сетях современные ОС (iOS, Android, Windows) используют динамические MAC-адреса.
- **Сканирование:** При поиске сетей всегда используется случайный MAC.
- **Подключение:** Для каждой Wi-Fi сети может генерироваться свой уникальный, но постоянный для этой сети «локальный» MAC-адрес.

### Виртуализация и облака
- **macvlan:** Драйвер, дающий контейнеру или ВМ собственный уникальный MAC-адрес, делая его полноценным узлом физической сети. Требует поддержки Promiscuous mode на физическом интерфейсе.
- **ipvlan:** Позволяет нескольким сущностям делить один MAC-адрес хоста, используя разные IP. Это критично для публичных облаков (AWS/GCP), где количество MAC на одном порту строго ограничено.

## Практические сценарии

### Просмотр и изменение в Linux

```bash
# Просмотр MAC-адреса (link/ether)
ip link show eth0
# → result: eth0: <BROADCAST,MULTICAST,UP> mtu 1500 link/ether 08:00:27:6c:f5:62

# Временная смена MAC (LAA)
sudo ip link set dev eth0 down
sudo ip link set dev eth0 address 02:00:00:00:00:01
sudo ip link set dev eth0 up

# Просмотр ARP-таблицы (сопоставление IP -> MAC)
ip neighbor show
```

### Диагностика на коммутаторе
Для обнаружения конфликтов и поиска портов:
```text
# Пример вывода таблицы коммутации
MAC Address       VLAN    Port      Type
----------------  ----    ----      ----
08:00:27:6c:f5:62  10     Gi0/1     Dynamic
```
