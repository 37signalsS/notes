# NAT (Network Address Translation)

## Определения

**NAT (Network Address Translation — трансляция сетевых адресов)** — технология преобразования IP-адресов в заголовках пакетов при их прохождении через маршрутизатор или межсетевой экран. Основное назначение — обеспечение доступа устройств из частных сетей в публичные сети (интернет) и повторное использование IPv4-адресного пространства.

NAT работает на [сетевом уровне (L3)](../../OSI_TCP_IP_Model/Network_layer/Concepts/network_layer_overview.md) модели OSI и является критически важным компонентом современной сетевой инфраструктуры, несмотря на развитие IPv6.

## Базовые концепции

### Частные и публичные IP-адреса

*   **Частный («серый») IP-адрес** — адрес из диапазонов [RFC 1918](../../Protocols/IP_addressing/special_addresses.md#частные-приватные-сети-rfc-1918), не маршрутизируемый в глобальной сети.
*   **Публичный («белый») IP-адрес** — глобально уникальный адрес, маршрутизируемый в интернете.

**Способ проверки NAT:**
Если IP-адрес на сетевом интерфейсе устройства (например, `192.168.x.x` или `10.x.x.x`) отличается от адреса, видимого внешним сервисам (например, через `curl ifconfig.me`), значит, устройство находится за NAT.

### Задачи и преимущества NAT

1.  **Экономия адресного пространства:** Позволяет тысячам устройств использовать один публичный IP-адрес.
2.  **Безопасность (Security by Obscurity):** Скрывает внутреннюю топологию сети. Внешние узлы не могут инициировать соединение с внутренним хостом без явно настроенного проброса (DNAT).
3.  **Гибкость маршрутизации:** Позволяет менять провайдера или внутреннюю адресацию без перенастройки всех узлов сети.

## Виды и механизмы трансляции

### Основные типы (Iptables/Nftables классификация)

*   **SNAT (Source NAT):** Изменение адреса источника. Используется для выхода из локальной сети в интернет. Применяется, когда у маршрутизатора есть статический публичный IP.
*   **Masquerading (Маскарадинг):** Динамический вариант SNAT. Автоматически использует текущий IP-адрес внешнего интерфейса. Идеально для DHCP/PPPoE соединений.
*   **DNAT (Destination NAT):** Изменение адреса назначения. Используется для «проброса портов» (Port Forwarding), чтобы сделать внутренний сервис доступным извне.

### Механизмы реализации

1.  **Static NAT (1:1):** Однозначное соответствие одного внутреннего IP одному внешнему. Не экономит адреса, используется для публикации серверов.
2.  **Dynamic NAT:** Использование пула публичных адресов. Внутренний хост получает временный адрес из пула.
3.  **PAT (Port Address Translation / NAT Overload):** Самый массовый вид. Тысячи хостов транслируются в один IP, а уникальность соединений обеспечивается подменой номеров портов TCP/UDP.

**Принцип работы PAT:**
1. Хост `10.0.0.5:54321` отправляет пакет на `8.8.8.8:443`.
2. Маршрутизатор заменяет `10.0.0.5` на свой публичный `203.0.113.1`, а порт `54321` на свободный порт, например `33456`.
3. Создается запись в **таблице трансляций**: `10.0.0.5:54321 <-> 203.0.113.1:33456`.
4. Ответ от `8.8.8.8` приходит на `203.0.113.1:33456`, роутер делает обратную подмену и доставляет пакет хосту.

## Типы NAT по поведению (NAT Taxonomy)

Для P2P-приложений (VoIP, игры) критично поведение NAT при фильтрации и маппинге:

| Тип | Описание | P2P-совместимость |
| :--- | :--- | :--- |
| **Full Cone** | Любой внешний хост может отправить пакет на открытый порт маппинга. | Отличная |
| **Restricted Cone** | Внешний хост может ответить, только если внутренний хост ранее отправлял ему пакет. | Хорошая |
| **Port Restricted** | Ограничение не только по IP, но и по порту внешнего хоста. | Средняя |
| **Symmetric NAT** | Для каждого нового адреса назначения создается новый маппинг порта. | Плохая (требует Relay) |

## Технологии перехода на IPv6

В современной SRE-практике (2026+) NAT используется не только для IPv4, но и для интеграции с IPv6:

*   **NAT64 / DNS64:** Позволяет IPv6-only узлам (например, подам в K8s) обращаться к IPv4-only ресурсам интернета. DNS64 синтезирует AAAA-записи, а NAT64 транслирует трафик.
*   **NPTv6 (Network Prefix Translation):** Безсостоятельная (stateless) трансляция префиксов IPv6. Используется для мультикастинга и обеспечения независимости от провайдера без использования NAT в его классическом (stateful) понимании. Сохраняет checksum-нейтральность.

## Прохождение NAT (NAT Traversal)

Для установления прямой связи между хостами за NAT используются специализированные протоколы:

*   **STUN (Session Traversal Utilities for NAT):** Позволяет хосту узнать свой публичный IP и тип NAT.
*   **TURN (Traversal Using Relays around NAT):** Релейный сервер. Используется, когда прямое соединение невозможно (например, при Symmetric NAT). Весь трафик идет через сервер (дорого и медленно).
*   **ICE (Interactive Connectivity Establishment):** Фреймворк, который пробует сначала STUN, и если не получается — переключается на TURN.

## Hairpin NAT (Loopback NAT)

**Проблема:** Внутренний клиент пытается обратиться к внутреннему серверу по его **публичному** IP-адресу. Пакет доходит до маршрутизатора, транслируется (DNAT) на сервер, но сервер отвечает клиенту напрямую по локальной сети. Клиент отбрасывает пакет, так как ждал ответа от публичного IP.

**Решение:** Hairpin NAT заставляет маршрутизатор выполнять SNAT для внутреннего клиента, чтобы сервер отвечал через маршрутизатор.

## Сложные сценарии

### Двойной NAT (Double NAT)
Ситуация, когда пакет проходит через два и более NAT-устройства (например, роутер провайдера + ваш роутер).
*   **Проблемы:** Трудности с пробросом портов, увеличенная задержка, проблемы с VPN-туннелями.
*   **Carrier-Grade NAT (CGNAT):** Провайдерский NAT (RFC 6598, диапазон `100.64.0.0/10`). Лишает пользователя возможности иметь белый IP без доплаты.

### NAT и фрагментация IP
NAT-устройства часто испытывают трудности с фрагментированными пакетами, так как информация о портах L4 содержится только в первом фрагменте. Рекомендуется использовать [Path MTU Discovery (PMTUD)](../../OSI_TCP_IP_Model/Network_layer/mtu_and_vpn.md#path-mtu-discovery-pmtud).

## Лучшие практики SRE

1.  **Мониторинг таблицы трансляций:** Отслеживание размера таблицы (conntrack table). Переполнение ведет к дропам новых соединений.
2.  **SLO для NAT-шлюзов:** Контроль задержки (latency) вносимой трансляцией и доступности порта (Port Exhaustion).
3.  **FinOps:** Облачные NAT-шлюзы (AWS NAT Gateway, Yandex NAT Gateway) стоят дорого. Выгоднее переводить трафик на нативный IPv6 или использовать VPC Peering/Endpoints.
4.  **Безопасность:** NAT — не замена файрволу. Используйте политики Zero Trust и mTLS.
