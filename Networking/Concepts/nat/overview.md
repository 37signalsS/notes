# NAT (Network Address Translation)

## Определения

**NAT (Network Address Translation)** — технология преобразования IP-адресов при передаче трафика через маршрутизатор. Позволяет нескольким устройствам в локальной сети выходить в интернет, используя один публичный IP-адрес провайдера.

NAT работает на [сетевом уровне (L3)](../../OSI_TCP_IP_Model/Network_layer/Concepts/network_layer_overview.md) и обычно реализуется на маршрутизаторах или файрволах.

## Базовые концепции

### Серый и белый IP-адрес

**Серый IP-адрес** — частный (приватный) IP-адрес из специально выделенных диапазонов, которые не маршрутизируются в глобальной сети. Подробнее: [Специальные IP-адреса](../../Protocols/IP_addressing/special_addresses.md#частные-приватные-сети-rfc-1918).

**Белый IP-адрес** — публичный IP-адрес, который маршрутизируется в интернете и уникален в глобальном масштабе.

**Как проверить свой IP:**

1. Открыть <https://2ip.ru/> или <https://whatismyip.com/>
2. Если отображаемый IP совпадает с локальным (например, `192.168.x.x`) — у вас белый IP
3. Если отличается — вы за NAT (серый IP)

**Пример:**

```bash
# В Windows (cmd):
ipconfig
# IPv4-адрес . . . . . . . . . . . : 172.20.10.6  ← серый IP

# В браузере откройте 2ip.ru
# Ваш IP: 178.178.244.253  ← белый IP (маршрутизатора)
```

В примере хост имеет серый IP `172.20.10.6`, но в интернет выходит с белого IP `178.178.244.253` благодаря NAT.

### Задачи NAT

1. **Экономия IP-адресов:** Позволяет локальной сети с частными IP-адресами использовать для выхода в интернет один публичный IP-адрес.
2. **Повышение безопасности:** Скрывает внутреннюю структуру локальной сети от внешнего мира. Устройства извне не могут напрямую инициировать соединение с компьютерами внутри локальной сети.

### Виды и механизмы NAT

* **PAT (Port Address Translation) / NAT Overload:** Самый распространённый механизм (домашние/офисные роутеры). Множество устройств используют один публичный IP-адрес с разными портами.
* **Статический NAT (Static NAT):** Однозначное сопоставление "один к одному" между локальным и глобальным IP-адресом (`192.168.1.10` ↔ `203.0.113.10`). Для публикации внутренних серверов. Не экономит адреса.
* **Динамический NAT (Dynamic NAT):** Пул глобальных IP-адресов, динамически назначаемых при выходе в интернет. При исчерпании пула новые устройства не смогут выйти в сеть. Используется редко.

**Принцип работы PAT (NAT Overload):**

1. Устройство (`192.168.0.3`) отправляет запрос в интернет (например, на `google.com`). ОС назначает эфемерный порт, например, `54321`.
2. Роутер подменяет IP-адрес источника (`192.168.0.3`) на свой публичный IP (`203.0.113.50`).
3. Роутер подменяет порт источника (`54321`) на уникальный порт соединения (например, `33456`).
4. Роутер создаёт запись в **таблице трансляций**:
   `[192.168.0.3]:54321  <--->  [203.0.113.50]:33456`
5. Внешний сервер отвечает на `203.0.113.50:33456`.
6. Роутер выполняет обратную замену по таблице трансляций и доставляет пакет на `192.168.0.3:54321`.

### Типы NAT по поведению при трансляции

1. **Full-cone NAT (Статический NAT 1:1)**
   * Одна пара `внутренний IP:порт` ↔ одна пара `внешний IP:порт`
   * Любой внешний хост может отправить пакет, зная внешний IP:порт

2. **Address-restricted-cone NAT**
   * Как Full-cone, но с фильтрацией по IP
   * Пакет пройдёт, только если внутренний хост ранее отправлял пакет на этот внешний IP

3. **Port-restricted-cone NAT**
   * Добавляет фильтрацию по порту
   * Внешний хост должен отвечать с того же порта, на который пришёл пакет

4. **Symmetric NAT (PAT / Port Address Translation)**
   * Для каждого нового адреса назначения — уникальная трансляция
   * Затрудняет работу P2P-приложений

5. **One-to-Many (NAPT / IP Masquerading)**
   * Множество внутренних адресов → один внешний белый IP
   * Разделение потоков за счёт динамической подмены портов

### NAT traversal

**NAT traversal** — техники (STUN, TURN, ICE) для установки прямого соединения между хостами за NAT.

## Практические сценарии

### SNAT vs Masquerade (Linux iptables/nftables)

| Характеристика | **SNAT (Source NAT)** | **Masquerade** |
| :--- | :--- | :--- |
| **Назначение** | Статический публичный IP | Динамический IP (DHCP, PPPoE) |
| **Производительность** | Выше | Ниже (дополнительное преобразование) |
| **Конфигурация** | Требует `--to-source` | Автоматически определяет внешний IP |
| **Трекинг соединений** | Менее интенсивный | Более интенсивный |
| **Когда использовать** | Серверы со статическим IP | Домашние роутеры, динамические IP |

**SNAT:**

```bash
# Конкретный хост → публичный IP
iptables -t nat -A POSTROUTING -s 192.168.1.100 -o eth0 -j SNAT --to-source 203.0.113.50

# Вся подсеть → публитный IP
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 203.0.113.50
```

**Masquerade:**

```bash
# Автоматически использует IP внешнего интерфейса
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

> **Рекомендация:** Статический публичный IP — SNAT. Динамический (DHCP, PPPoE) — Masquerade.

## Дополнительные концепции

### Домашний маршрутизатор

Домашние маршрутизаторы поставляются с включённым NAT. Все пакеты, выходящие через WAN-порт, автоматически проходят через NAT — маскарадинг активирован по умолчанию.

### NAT-цепочка (Double NAT)

Маршрутизаторы с NAT могут располагаться в цепочку — IP-адрес отправителя изменяется несколько раз:

1. Хост (`192.168.1.1`) → маршрутизатор 1 (`10.0.0.254`)
2. Маршрутизатор 1 → маршрутизатор 2 (`77.88.8.254`)
3. Сервер получает пакет от `77.88.8.254`

При обратном следовании каждый NAT выполняет обратную подмену прозрачно для хоста.

**Двойной NAT (Carrier-Grade NAT):** Возникает, когда провайдер также использует NAT. Создаёт проблемы для:

- Проброса портов (нужна настройка на обоих роутерах)
- P2P-приложений (торренты, VoIP, онлайн-игры)
- Удалённого доступа к домашним устройствам

**Решение:** Запросить у провайдера публичный IP или использовать VPN/туннели.

### Одинаковые IP-адреса за разными NAT

Разные хосты могут иметь одинаковые IP-адреса в своих локальных сетях:

- Хост 1: `192.168.1.1` за маршрутизатором 1
- Хост 2: `192.168.1.1` за маршрутизатором 2

При выходе в интернет каждый имеет разные публичные IP. Это позволяет повторно использовать частные диапазоны в миллионах локальных сетей.

### Проблемы NAT

NAT усложняет установку прямых соединений для P2P-протоколов (VoIP, торренты, онлайн-игры). Для решения используются **STUN/TURN** и **UPnP**.
