# Proxy ARP

## Определения

**Proxy ARP** — механизм, позволяющий одному хосту (роутеру/шлюзу) отвечать на ARP-запросы, предназначенные другому хосту. Шлюз «притворяется» целью, принимая ARP-запрос за другой IP, и отвечает своим MAC-адресом. После этого отправитель направляет пакеты шлюзу, который маршрутизирует их к реальному получателю.

**Как работает обычный ARP:**
1. Хост A хочет отправить пакет хосту B (в той же L2-сегменте).
2. Хост A отправляет ARP-запрос: «Кто имеет IP `192.168.1.20`?»
3. Хост B отвечает: «Это я, мой MAC: `aa:bb:cc:dd:ee:ff`»
4. Хост A отправляет пакет на `aa:bb:cc:dd:ee:ff`.

**Как работает Proxy ARP:**
1. Хост A хочет отправить пакет хосту B (в **другом** L2-сегменте).
2. Хост A отправляет ARP-запрос: «Кто имеет IP `192.168.2.20`?»
3. **Шлюз** отвечает: «Это я, мой MAC: `11:22:33:44:55:66`» (Proxy ARP).
4. Хост A отправляет пакет на MAC шлюза.
5. Шлюз получает пакет и маршрутизирует его к хосту B.

**Зачем нужно:** Proxy ARP позволяет хостам в разных подсетях обмениваться данными без настройки шлюза по умолчанию на клиентах. Клиент «не знает», что целевой хост находится за маршрутизатором — он думает, что хост в той же L2-сети.

## Теоретический блок

### Когда Proxy ARP необходим

| Сценарий | Описание |
| :--- | :--- |
| **Разделение подсетей** | Два хоста в разных IP-подсетях, но в одном L2-сегменте (VLAN) |
| **Прозрачный прокси** | Шлюз перехватывает трафик на прокси, отвечая ARP за целевые серверы |
| **Временная маршрутизация** | При миграции серверов — шлюз принимает ARP за старый IP |
| **Point-to-point ссылки** | На P2P-интерфейсах (tunnel, PPP) вместо ARP-таблицы |
| **Без default gateway** | Клиент не знает шлюза — Proxy ARP решает проблему маршрутизации |

### Proxy ARP vs Static Routing

| Критерий | Proxy ARP | Статический маршрут |
| :--- | :--- | :--- |
| **Настройка клиента** | Не нужна (клиент думает, что хост в L2) | Нужен default gateway или route |
| **Масштабируемость** | Плохая (ARP-таблица растёт на每一个远程 хост) | Хорошая (одно правило покрывает подсеть) |
| **Безопасность** | Риск ARP-spoofing (шлюз отвечает за чужие IP) | Лучше (маршрутизация явная) |
| **Диагностика** | Сложнее (ARP-таблица шлюза содержит все удалённые хосты) | Проще (ip route покажет все маршруты) |
| **Производительность** | ARP для каждого нового хоста | Маршрутизация по таблице |

### Взаимодействие с NAT

Proxy ARP часто используется **вместе с NAT** для прозрачной маршрутизации:

```
Клиент (192.168.1.5) ──┐
                        ├── L2-сегмент (VLAN 100)
Шлюз (192.168.1.1) ──┘
    │
    │ Proxy ARP: шлюз отвечает за 192.168.2.20
    │
    ▼
Сервер (192.168.2.20) ── L2-сегмент (VLAN 200)
```

**Порядок:**
1. Клиент отправляет ARP «Who has 192.168.2.20?»
2. Шлюз отвечает Proxy ARP: «Это я (MAC шлюза)»
3. Клиент отправляет пакет на MAC шлюза
4. Шлюз маршрутизирует пакет в VLAN 200
5. Шлюз выполняет NAT (если нужно) и доставляет на сервер

## Практический блок

### Включение Proxy ARP

```bash
# Включение на интерфейсе
sysctl -w net.ipv4.conf.eth0.proxy_arp=1

# Проверка
sysctl net.ipv4.conf.eth0.proxy_arp
# → 1

# Отключение
sysctl -w net.ipv4.conf.eth0.proxy_arp=0
```

### Автозагрузка

```bash
# /etc/sysctl.d/99-proxy-arp.conf
net.ipv4.conf.eth0.proxy_arp=1
net.ipv4.conf.eth1.proxy_arp=1

# Применить
sudo sysctl --system
```

### Проверка ARP-таблицы шлюза

```bash
# Просмотр ARP-таблицы (шлюз будет отвечать за удалённые хосты)
ip neigh show
# → 192.168.2.20 dev eth0 lladdr 11:22:33:44:55:66 REACHABLE
#    (MAC = MAC шлюза, а не реального сервера)

# Сравнение: ARP-таблица клиента
# (на клиенте) ip neigh show
# → 192.168.2.20 dev eth0 lladdr 11:22:33:44:55:66 REACHABLE
#    (клиент думает, что 192.168.2.20 — это MAC 11:22:33:44:55:66)
```

### Диагностика: что отвечает за IP

```bash
# С клиента: определить, чей MAC-адрес отвечает за целевой IP
arping -I eth0 192.168.2.20
# → ARP reply from 192.168.2.20 (11:22:33:44:55:66)

# На шлюзе: проверить, что proxy_arp включён
sysctl net.ipv4.conf.*.proxy_arp
# → Все интерфейсы: 1

# На целевом сервере: проверить, что он не отвечает сам
ip neigh show | grep 192.168.2.20
# → На сервере: 192.168.2.1 dev eth0 lladdr ... REACHABLE (клиент/шлюз)
```

### Типичные ошибки

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| Клиент не может достучаться до удалённого хоста | Proxy ARP не включён на интерфейсе шлюза | `sysctl -w net.ipv4.conf.eth0.proxy_arp=1` |
| ARP-таблица шлюза переполнена | Слишком много удалённых хостов (проблема масштабируемости) | Использовать статические маршруты вместо Proxy ARP |
| ARP-spoofing атака | Proxy ARP позволяет перехватывать трафик | Использовать static ARP entries или Dynamic ARP Inspection |
| Конфликт с ARP-фильтрацией (`arp_filter`) | `arp_filter=1` запрещает Proxy ARP | Установить `arp_filter=0` или использовать другой подход |
