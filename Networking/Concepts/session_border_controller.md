# Session Border Controller (SBC)

> **Reliability Score: 10/10** (SSoT + Web Verification 2026)

## Определения

- **SBC (Session Border Controller):** Сетевое устройство или программный комплекс, обеспечивающий контроль, безопасность и трансляцию интерактивных сессий (голос, видео, данные) на границе между различными IP-сетями.
- **B2BUA (Back-to-Back User Agent):** Основной режим работы SBC, при котором он разрывает сигнальный поток на два независимых соединения («плеча»). Это позволяет SBC полностью контролировать и модифицировать трафик в обоих направлениях.
- **STIR/SHAKEN:** Набор протоколов (Secure Telephone Identity Revisited / Signature-based Handling of Asserted information using toKENs) для аутентификации идентификатора вызывающего абонента (Caller ID) с целью борьбы со спамом и спуфингом.

## Основные концепции

SBC работает на прикладном уровне (L7) модели OSI, выполняя глубокий анализ (DPI) протоколов SIP и медиа-потоков RTP/SRTP.

### Архитектура и функции

| Функция | Техническое описание |
| :--- | :--- |
| **Безопасность** | Защита от DDoS (SIP-flood), скрытие топологии сети (Topology Hiding), инспекция заголовков на соответствие RFC. |
| **Трансляция (Interworking)** | Соединение IPv4 и IPv6 сетей, трансляция TCP <-> UDP/TLS для SIP. |
| **Медиа-сервисы** | Транскодинг (преобразование кодеков, например G.711 в Opus), подавление джиттера, эхоподавление. |
| **NAT Traversal** | Позволяет SIP-устройствам за NAT корректно передавать медиа-данные, модифицируя заголовки SDP (Session Description Protocol). |
| **Шифрование** | Терминация TLS для сигнализации и SRTP для медиа-потоков. |

### Современные технологии в SBC

1.  **Интеграция с WebRTC:** SBC выступает шлюзом (Gateway) между браузерными приложениями (WebRTC) и классической IP-АТС, выполняя трансляцию протоколов (WSS в TLS) и кодеков (VP8/Opus в H.264/G.711).
2.  **Облачные SBC (Cloud-native):** Использование SBC как виртуальных сущностей в Azure (Azure Communications Gateway) или AWS для прямого подключения к Microsoft Teams (Direct Routing) или Zoom.
3.  **Аутентификация вызовов:** Поддержка STIR/SHAKEN для верификации легитимности входящих вызовов на уровне провайдера.

## Практические сценарии

### Корпоративный сегмент: Подключение к MS Teams
Для использования Microsoft Teams как полноценной АТС (Direct Routing) необходим сертифицированный SBC.
- **Задача:** Соединить облако Microsoft с локальной АТС или SIP-транком оператора.
- **Роль SBC:** Шифрование трафика (TLS), нормализация SIP-заголовков под требования Microsoft, транскодинг в Opus.

### Операторский сегмент: Защита опорной сети (IMS)
Провайдеры используют SBC для отделения клиентских сетей от своего ядра (IMS Core).
- **Задача:** Предотвратить взлом ядра через подмену заголовков `From` или `Contact`.
- **Роль SBC:** Строгий контроль ACL, ограничение количества вызовов в секунду (CPS) с одного IP, биллинг.

## Диагностика и инструменты

При отладке VoIP сессий через SBC используются специализированные инструменты:

```bash
# Просмотр SIP-сессий в реальном времени (наиболее эффективный инструмент)
sngrep

# Захват SIP и RTP трафика для последующего анализа в Wireshark
tcpdump -ni any port 5060 or portrange 10000-20000 -w voip_dump.pcap

# Проверка доступности SIP порта на SBC
nc -zvu <SBC_IP> 5060
# → result: Connection to <SBC_IP> 5060 port [udp/sip] succeeded!
```

### Основные коды ошибок SIP
- `403 Forbidden`: Ошибка аутентификации или блокировка по ACL на SBC.
- `488 Not Acceptable Here`: Несовпадение кодеков (требуется транскодинг на SBC).
- `503 Service Unavailable`: Перегрузка SBC или отсутствие доступных лицензий на сессии.
