# Session Border Controller (SBC)

## Определения

- **SBC (Session Border Controller):** Специализированный сетевой элемент (физический или виртуальный), который управляет сигнальными потоками и медиа-трафиком на границах IP-сетей. В отличие от обычных файрволов, SBC глубоко понимает протоколы реального времени (VoIP, видео).
- **B2BUA (Back-to-Back User Agent):** Архитектурный принцип работы SBC. Устройство выступает одновременно и как SIP-клиент (UAC), и как SIP-сервер (UAS). SBC разрывает сессию на два независимых «плеча» (Call Legs), что позволяет полностью переписывать заголовки, менять порты и управлять медиа-параметрами независимо для каждой стороны.
- **STIR/SHAKEN:** Стандарт аутентификации вызовов (Secure Telephone Identity Revisited / Signature-based Handling of Asserted information using toKENs). Использует криптографические сертификаты для подтверждения того, что номер вызывающего абонента не был подделан (анти-спуфинг).
- **HMR (Header Manipulation Rules):** Наборы правил на SBC для модификации SIP-заголовков «на лету» (например, изменение формата номера с +7 на 8).

## Базовые концепции

SBC оперирует на сессионном и прикладном уровнях (L5–L7), обеспечивая стыковку разнородных сетей.

### Ключевые функции и механизмы

| Категория | Технические детали |
| :--- | :--- |
| **Безопасность (L7)** | Защита от DoS/DDoS (SIP-flood), динамические ACL (автоблокировка по неудачным попыткам регистрации),Topology Hiding (скрытие внутренних IP-адресов АТС). |
| **SIP Нормализация** | Исправление несовместимостей между вендорами (Interworking). Например, перевод `P-Asserted-Identity` в `Remote-Party-ID` или удаление нестандартных заголовков. |
| **Управление медиа** | **Media Anchoring** (SBC пропускает RTP через себя для контроля) или **Media Release** (SBC разрешает устройствам передавать трафик напрямую, исключая себя из пути данных для экономии ресурсов). |
| **Транскодинг** | Преобразование кодеков в реальном времени (например, G.711 <-> Opus / G.729). Требует значительных вычислительных мощностей или специализированных DSP-чипов. |
| **NAT Traversal** | Механизм **Hosted NAT Traversal (HNT)**. SBC заменяет приватные IP в заголовках `Contact` и в теле SDP на свои публичные адреса, гарантируя прохождение голоса через роутеры. |

### Сравнение: SBC vs Традиционный Файрвол (Stateful Firewall)

| Характеристика | Традиционный Firewall | Session Border Controller |
| :--- | :--- | :--- |
| **Глубина анализа** | L3–L4 (IP, Порт) | L7 (SIP Method, Headers, SDP, RTP) |
| **Состояние** | Состояние соединения (TCP/UDP) | Состояние сессии (Call State, Dialog) |
| **Модификация** | Только NAT (IP/Port) | Модификация любого заголовка и тела пакета |
| **Медиа** | Часто блокирует RTP из-за динамических портов | Открывает только нужные порты для конкретной сессии |

## Практические сценарии

### Корпоративный сегмент: Подключение к Microsoft Teams (Direct Routing)
SBC является обязательным звеном для интеграции Teams с PSTN или локальными АТС.
- **Задача:** Обеспечить безопасный стык между Azure и корпоративной сетью.
- **Технические требования:** 
  - Настройка TLS-транка с использованием публичного CA-сертификата.
  - Поддержка заголовка `X-MS-SBC` для идентификации.
  - Транскодинг в кодек Opus (стандарт Teams) для улучшения качества в нестабильных сетях.

### Операторский сегмент: Стык (Peering) между провайдерами
Операторы используют SBC (часто называемые Peering SBC) для обмена трафиком.
- **Задача:** Учет (Billing) и контроль качества (SLA).
- **Механизмы:**
  - **LCR (Least Cost Routing):** Автоматический выбор самого дешевого маршрута для вызова.
  - **Admission Control:** Ограничение количества одновременных вызовов (Call Concurrency) согласно контракту.

## Диагностика и инструменты

### Работа с трафиком

```bash
# Просмотр SIP-диалогов в интерактивном режиме
# Позволяет видеть Flow Diagram каждого вызова
sngrep -t

# Захват только сигнального трафика на интерфейсе eth0
tcpdump -i eth0 -n -s 0 port 5060 -vvv -w signaling.pcap

# Анализ качества медиа-потока (Jitter, Packet Loss) через командную строку (если есть rtpengine/rtpproxy)
# Обычно анализируется через RTCP-отчеты на самом SBC
```

### Коды ответов и отладка сессий
- `401 Unauthorized`: SBC запрашивает аутентификацию (норма для регистрации).
- `403 Forbidden`: Ошибка в логине/пароле или IP-адрес источника не внесен в белый список (Trust List).
- `480 Temporarily Unavailable`: Вызываемый абонент не в сети (не зарегистрирован на SBC/АТС).
- `488 Not Acceptable Here`: Устройства не договорились о кодеках в SDP (нужен транскодинг).
