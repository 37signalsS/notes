# Качество real-time трафика: 4 ключевых параметра

## Определения

**Real-time трафик** — сетевой трафик, чувствительный к задержкам и их вариациям. К этому типу относятся:

- Онлайн-игры (CS:GO, Dota 2, Valorant)
- Видеозвонки и видеоконференции (Zoom, Skype, Teams)
- VoIP-телефония
- Видеостриминг (Twitch, YouTube Live)
- Удалённый рабочий стол (RDP, VNC)

Для оценки качества real-time трафика используются **четыре ключевых параметра**: **Latency**, **Bandwidth**, **Jitter**, **Loss**.

## Базовые концепции

### 1. Latency (Задержка)

**Latency** — интервал времени между отправкой пакета с данными и получением этих данных получателем.

**Характеристики:**

- **Измерение:** Миллисекунды (мс, ms)
- **Нормальные значения:**
  - Локальная сеть: <1 мс
  - В пределах города: 5–20 мс
  - Между городами: 20–50 мс
  - Междугородная/международная: 50–150 мс
  - Спутниковая связь: 500–700 мс
- **Критично для:** Онлайн-игр, VoIP, видеозвонков

**RTT (Round-Trip Time):** Время, необходимое для прохождения пакета от отправителя к получателю и обратно. Измеряется утилитой `ping`.

**Влияние на приложения:**

| Приложение | Макс. комфортная задержка |
| :--- | :--- |
| **Онлайн-игры (FPS)** | <50 мс |
| **VoIP** | <150 мс |
| **Видеозвонки** | <200 мс |
| **Веб-сёрфинг** | <500 мс |

### 2. Bandwidth (Пропускная способность)

**Bandwidth** — количество данных, которое проходит через канал за единицу времени.

**Характеристики:**

- **Измерение:** Биты в секунду (бит/с, Kbps, Mbps, Gbps)
- **Важно:** Увеличение пропускной способности **не уменьшает** задержку. Канал становится "толще", но не "быстрее"

**Типичные требования:**

| Приложение | Мин. пропускная способность |
| :--- | :--- |
| **VoIP (один звонок)** | 64–128 Кбит/с |
| **Видеозвонок (HD)** | 1–3 Мбит/с |
| **Стриминг (1080p)** | 3–5 Мбит/с |
| **Онлайн-игры** | 0.5–1 Мбит/с |

**Пример:** Если у вас был канал 10 Мбит/с и стал 50 Мбит/с, это никак не повлияет на Latency. Канал стал толще, а не быстрее.

### 3. Jitter (Джиттер)

**Jitter** — колебание задержки между доставкой последовательных пакетов. Статистическая вариация Latency.

**Характеристики:**

- **Измерение:** Миллисекунды (мс)
- **Нормальные значения:** <10 мс (идеально), <30 мс (приемлемо)
- **Критично для:** VoIP, видеозвонков, онлайн-игр

**Визуализация:**

```
Идеальный канал (Jitter = 0):
Пакет 1 → [20мс] → Получатель
Пакет 2 → [20мс] → Получатель
Пакет 3 → [20мс] → Получатель

Канал с большим Jitter:
Пакет 1 → [10мс] → Получатель
Пакет 2 → [50мс] → Получатель
Пакет 3 → [15мс] → Получатель
```

**Влияние на приложения:**

- **VoIP/Видеозвонки:** Прерывания звука, "роботизированный" голос, выпадение кадров
- **Онлайн-игры:** Рывки, телепортация объектов, неотзывчивое управление
- **Стриминг:** Буферизация, изменение качества

**Причины высокого Jitter:**

1. Перегрузка канала (конгестия)
2. Неправильная настройка очередей на маршрутизаторах
3. Интерференция в Wi-Fi сетях
4. Bufferbloat (избыточная буферизация в сетевых устройствах)

### 4. Loss (Потеря пакетов)

**Loss** — процент пакетов, не дошедших до получателя.

**Характеристики:**

- **Измерение:** Проценты (%)
- **Нормальные значения:** 0% (идеально), <1% (приемлемо)
- **Критично для:** Всех приложений, особенно real-time

**Влияние на приложения:**

| Приложение | Допустимые потери | Симптомы при превышении |
| :--- | :--- | :--- |
| **VoIP** | <1% | Пропуски в аудио, щелчки |
| **Видеозвонки** | <2% | Зависания, артефакты |
| **Онлайн-игры** | <0.5% | Лаги, телепортация |
| **Веб-сёрфинг** | <5% | Медленная загрузка |

**Причины потерь:**

1. Перегрузка канала (очереди переполнены)
2. Помехи в беспроводных сетях
3. Ошибки оборудования (кабели, порты)
4. Намеренное отбрасывание пакетов (QoS policing)

## Практические сценарии

### Диагностика проблем real-time трафика

**Сценарий 1: Лаги в онлайн-играх при хорошем пинге**

**Симптомы:**

- Ping <10 мс
- Скорость соединения 100+ Мбит/с
- Игра подтормаживает, рывки, неотзывчивое управление

**Диагноз:** Высокий Jitter

**Решение:**

1. Проверить сетевую статистику в игре
2. Использовать проводное соединение вместо Wi-Fi
3. Отключить фоновые загрузки
4. Настроить QoS на роутере (приоритет игрового трафика)

**Сценарий 2: Прерывания в видеозвонке**

**Симптомы:**

- Звук прерывается
- Видео "квадратиками"
- Ping в норме (30–50 мс)

**Диагноз:** Высокий Jitter или Loss

**Решение:**

1. Проверить потерю пакетов: `ping -c 100 <сервер>`
2. Проверить джиттер: `mtr <сервер>` (графа StDev)
3. Снизить качество видео в настройках
4. Проверить загрузку канала другими приложениями

**Сценарий 3: Долгая загрузка файлов и лаги в играх**

**Симптомы:**

- Файлы загружаются медленно
- В игры невозможно играть из-за лагов

**Диагноз:** Недостаточная пропускная способность (Bandwidth)

**Решение:**

1. Проверить скорость: `speedtest-cli` или <https://speedtest.net>
2. Выключить фоновые загрузки (торренты, обновления)
3. Обновить тариф у провайдера

### Инструменты диагностики

| Инструмент | Измеряет | Команда |
| :--- | :--- | :--- |
| **ping** | Latency, Loss | `ping -c 100 example.com` |
| **mtr** | Latency, Jitter, Loss | `mtr example.com` |
| **iperf3** | Bandwidth, Jitter | `iperf3 -c server` |
| **speedtest-cli** | Bandwidth | `speedtest-cli` |
| **Wireshark** | Полный анализ | `wireshark` |

**Пример анализа ping:**

```bash
$ ping -c 10 8.8.8.8
rtt min/avg/max/mdev = 18.234/20.567/25.891/2.345 ms
```

- **min/avg/max:** Минимальная/средняя/максимальная задержка
- **mdev:** Среднеквадратичное отклонение (Jitter)

**Интерпретация:**

- `mdev <10 мс` — отличный канал
- `mdev 10–30 мс` — приемлемо
- `mdev >30 мс` — высокий джиттер, нужны меры

### Рекомендации по настройке

**Для онлайн-игр:**

1. Приоритет трафика игры в QoS
2. Отключить Nagle algorithm (TCP_NODELAY)
3. Использовать проводное соединение
4. Закрыть фоновые приложения

**Для VoIP/видеозвонков:**

1. Гарантированная полоса пропускания (1–3 Мбит/с)
2. Jitter buffer на стороне клиента
3. Приоритет UDP трафика
4. Избегать Wi-Fi при плохом сигнале

**Для стриминга:**

1. Стабильный upload 3–5 Мбит/с для 1080p
2. Минимальный Jitter (<20 мс)
3. Потери <0.5%
4. Резервный канал для надёжности
