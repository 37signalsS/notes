# Лучшие практики настройки межсетевых экранов

## Определения

**Default Deny (Запрет по умолчанию)** — базовая стратегия безопасности, при которой весь трафик, не разрешённый явным образом, блокируется. Это исключает возможность случайного открытия лишних портов.

**Принцип минимальных привилегий (POLP)** — предоставление сервису или пользователю только тех сетевых доступов, которые минимально необходимы для их работы.

**Микросегментация** — разделение сети на мелкие изолированные зоны (сегменты) для ограничения «бокового перемещения» (Lateral Movement) злоумышленника внутри периметра.

## Основные концепции

### Модель нулевого доверия (Zero Trust)

В современной инфраструктуре сетевой контроль строится на отказе от концепции «доверенного внутреннего периметра»:
*   **Верификация каждого запроса:** Местоположение в сети не является фактором доверия.
*   **Явное разрешение:** Каждое взаимодействие (даже внутри одного дата-центра) должно быть описано правилом.
*   **Атрибутивный доступ:** Правила могут основываться не только на IP, но и на идентификаторах сервисов (Spiffe/SPIRE), метках (Kubernetes Labels) или ролях пользователей.

## Практические сценарии

### Практики проектирования набора правил

1.  **Политика DROP по умолчанию:** Установите политику по умолчанию `DROP` для всех цепочек (`INPUT`, `FORWARD`, `OUTPUT`).
2.  **Порядок имеет значение:** Размещайте наиболее часто используемые и специфичные правила в начале списка для снижения нагрузки на CPU.
3.  **Использование комментариев:** Всегда добавляйте комментарии к правилам (с указанием задачи или номера тикета), чтобы упростить аудит через полгода.
4.  **Специфичность (Specificity):** Вместо правила «разрешить всё из подсети А в подсеть Б», указывайте конкретный протокол, порт и IP-адреса. Избегайте использования `any`.
5.  **Контроль исходящего трафика (Egress):** Большинство взломов используют исходящие соединения для загрузки вредоносов или связи с C2-сервером. Разрешайте только необходимые внешние эндпоинты (например, репозитории обновлений и конкретные API).
6.  **Защита интерфейсов управления:** Доступ к SSH/Web-панелям управления должен быть разрешен только из доверенных подсетей (Management Network) или через Jump-хосты/VPN.
7.  **Ограничение частоты (Rate Limiting):** Применяйте ограничения на количество новых соединений в секунду для публичных сервисов (защита от брутфорса и простых DoS-атак).

### Пример: Защищенный веб-сервер (iptables)

```bash
# Установка политики запрета по умолчанию
iptables -P INPUT   DROP
iptables -P FORWARD DROP
iptables -P OUTPUT  DROP

# 1. Разрешить loopback (внутренние процессы сервера)
iptables -A INPUT  -i lo -j ACCEPT -m comment --comment "Allow local loopback"
iptables -A OUTPUT -o lo -j ACCEPT -m comment --comment "Allow local loopback"

# 2. Разрешить установленные и связанные соединения (Stateful)
iptables -A INPUT  -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 3. Входящий трафик (Ingress)
# Разрешить SSH только из сети администраторов
iptables -A INPUT -p tcp --dport 22 -s 192.168.10.0/24 -j ACCEPT -m comment --comment "Admin SSH access"
# Разрешить HTTP/HTTPS для всех
iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT -m comment --comment "Public web traffic"

# 4. Исходящий трафик (Egress)
# Разрешить DNS запросы только к конкретным серверам
iptables -A OUTPUT -p udp --dport 53 -d 8.8.8.8 -j ACCEPT -m comment --comment "Allow DNS to Google"
# Разрешить HTTPS для обновлений ОС
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow HTTPS egress for updates"

# 5. Логирование отброшенных пакетов (перед финальным DROP)
iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables_INPUT_denied: " --log-level 4
```

### Пример: Сегментация в Kubernetes (NetworkPolicy)

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: api-server-security
spec:
  podSelector:
    matchLabels:
      app: api-server
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: ingress-controller
    ports:
    - protocol: TCP
      port: 8080
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: postgres-db
    ports:
    - protocol: TCP
      port: 5432
```

## Дополнительная информация

### Типичные ошибки (Anti-patterns)

*   **Any-Any правила:** Открытие доступа ко всей подсети по всем портам «на время отладки» и забвение этого правила.
*   **Игнорирование IPv6:** Настройка защиты только для IPv4, оставляя IPv6-стек полностью открытым.
*   **Отсутствие логирования:** Без логов отброшенных пакетов невозможно понять, блокирует ли файрвол легитимный трафик или идет активная атака.
*   **Ручное управление:** Настройка правил командами без использования средств IaC (Ansible, Terraform), что ведет к рассинхрону конфигураций между серверами.
