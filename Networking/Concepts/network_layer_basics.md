# Сетевой уровень (L3)

**Сетевой уровень** — это третий уровень модели OSI, главная задача которого — построение крупных **составных сетей (internetworks)** из множества разнородных сетей, каждая из которых может быть построена на своей технологии канального уровня (Ethernet, Wi-Fi, сотовые сети и т.д.). Именно сетевой уровень и его протоколы (в первую очередь, IP) делают возможным существование глобальной сети Интернет.

Идею отдельного сетевого уровня для объединения разнородных сетей предложили Винтон Серф и Роберт Кан в 1974 году, за что их по праву считают "отцами Интернета".

## Ограничения канального уровня (L2)

Технологии канального уровня, такие как Ethernet, отлично подходят для создания локальных сетей, но они имеют фундаментальные ограничения, которые не позволяют построить на их основе глобальную сеть:

1.  **Разнородность технологий:** Существует множество L2-технологий, которые отличаются адресацией (MAC-адреса, IMEL-адреса), максимальным размером кадра (MTU), поддержкой широковещания и уровнем сервиса. Сетевой уровень предоставляет механизмы для их "бесшовного" согласования.
2.  **Проблема масштабируемости:**
    *   **Размер таблиц коммутации:** Коммутаторы хранят MAC-адреса всех устройств в сети. В глобальной сети с миллиардами устройств такая таблица была бы невозможна для хранения и поиска.
    *   **Широковещательный шторм:** Если коммутатор не знает, куда отправить кадр, он рассылает его на все порты. В масштабах Интернета это привело бы к мгновенному коллапсу сети из-за лавины "мусорного" трафика.
3.  **Отсутствие множественных путей:** Технологии L2, такие как Ethernet, не допускают петель в топологии для избежания широковещательных штормов. Протокол STP, который борется с петлями, отключает резервные каналы, что в глобальной сети привело бы к неэффективному использованию каналов и неоптимальным маршрутам.

## Ключевые задачи и функции сетевого уровня

Сетевой уровень решает вышеописанные проблемы с помощью следующих механизмов:

1.  **Объединение сетей (Internetworking):** Предоставление единой системы для связи между сетями, построенными на разных технологиях.
2.  **Глобальная адресация:** Введение унифицированной системы логических **глобальных адресов** (IP-адресов), которые не зависят от физических (локальных) адресов канального уровня (MAC-адресов). Это позволяет однозначно идентифицировать любой узел в глобальной сети. Для сопоставления глобальных и локальных адресов используется, например, протокол ARP.
3.  **Маршрутизация (Routing):** Это процесс определения и выбора оптимального пути для доставки пакетов через транзитные узлы — **маршрутизаторы**. В отличие от L2, сетевой уровень позволяет иметь **несколько активных путей** между узлами, что повышает отказоустойчивость и эффективность сети. Если один путь выходит из строя, пакеты могут быть направлены по другому.
4.  **Агрегация адресов:** Сетевой уровень оперирует не отдельными адресами устройств, а целыми **блоками адресов (подсетями)**. Маршрутизаторы хранят в своих таблицах маршруты к подсетям, а не к каждому хосту, что кардинально решает проблему масштабируемости.
5.  **Фрагментация:** Если пакет данных слишком велик для передачи через сеть с меньшим значением MTU (Maximum Transmission Unit), маршрутизатор может разбить его на более мелкие части — **фрагменты**. Фрагменты передаются по отдельности и собираются воедино на конечном узле. Этот процесс прозрачен для отправителя и получателя.
6.  **Отбрасывание пакетов:** Пакеты, для которых путь доставки неизвестен, на сетевом уровне не рассылаются всем подряд (как на L2), а просто **отбрасываются**. Это защищает сеть от циркуляции "мусорных" пакетов.

## Ключевые протоколы сетевого уровня (в стеке TCP/IP)

*   **IP (Internet Protocol):** Основной протокол для передачи данных.
*   **ICMP (Internet Control Message Protocol):** Используется для обмена служебными и диагностическими сообщениями между устройствами (например, `ping`, `traceroute`).
*   **ARP (Address Resolution Protocol):** Используется для определения MAC-адреса (L2) по известному IP-адресу (L3) в пределах одной локальной сети.
*   **DHCP (Dynamic Host Configuration Protocol):** Используется для автоматического назначения IP-адресов и других сетевых настроек хостам.

### ICMP (Internet Control Message Protocol)

Когда сетевое устройство (например, маршрутизатор) сталкивается с проблемой при обработке пакета, оно генерирует ICMP-сообщение и отправляет его источнику пакета. 

Каждое ICMP-сообщение содержит:

*   **Тип сообщения:** Указывает на характер события (например, "узел назначения недоступен").
*   **Код:** Уточняет причину (например, "порт недоступен").
*   **Данные:** Часто включают заголовок и первые 64 бита IP-пакета, вызвавшего ошибку.

**Основные типы ICMP-сообщений:**

*   **Echo Request / Echo Reply:** Основа утилиты `ping`. Позволяет проверить доступность узла и измерить время задержки.
*   **Destination Unreachable:** Сообщает, что пакет не может быть доставлен (например, узел не существует или порт закрыт).
*   **Time Exceeded:** Отправляется, когда время жизни (TTL) пакета истекает до того, как он достигнет места назначения. Используется утилитой `traceroute` для определения маршрута.
*   **Redirect:** Уведомляет хост о наличии более короткого пути для отправки пакетов.

### Логика маршрутизации: локальная сеть vs. внешняя

Ключевая задача сетевого уровня — определить, как доставить пакет. Логика принятия решений хостом-отправителем выглядит следующим образом.

#### Сценарий 1: Обмен трафиком в одной подсети

Когда хост **А** (IP `192.168.1.10`) отправляет пакет хосту **Б** (IP `192.168.1.20`) с маской подсети `255.255.255.0`:

1.  **Определение местоположения:** Хост **А** применяет маску подсети к своему IP и к IP-адресу назначения. В обоих случаях получается один и тот же адрес сети: `192.168.1.0`. **Вывод: адресат находится в той же локальной сети.**

2.  **Поиск MAC-адреса (ARP):** Для отправки кадра (frame) на канальном уровне (L2) требуется MAC-адрес получателя.
    *   Хост **А** проверяет свою ARP-таблицу на наличие записи для `192.168.1.20`.
    *   Если записи нет, хост **А** отправляет широковещательный **ARP-запрос** в локальную сеть: "Кто имеет IP `192.168.1.20`?".
    *   Хост **Б** отвечает однонаправленным **ARP-ответом**, сообщая свой MAC-адрес.

3.  **Прямая отправка:** Хост **А** кэширует MAC-адрес хоста **Б** и отправляет IP-пакет, инкапсулированный в Ethernet-кадр, напрямую на MAC-адрес получателя.

**Важно:** Шлюз по умолчанию (default gateway) в этом процессе не участвует.

#### Сценарий 2: Отправка трафика во внешнюю сеть

Если хост **А** (`192.168.1.10`) отправляет пакет на сервер в интернете (например, `8.8.8.8`):

1.  **Определение местоположения:** Хост **А** применяет маску подсети к IP-адресу назначения и получает адрес сети `8.8.8.0`. Этот адрес не совпадает с его собственной сетью (`192.168.1.0`). **Вывод: адресат находится во внешней сети.**

2.  **Отправка на шлюз:** Весь трафик для внешних сетей должен быть направлен на **шлюз по умолчанию** (например, роутер с IP `192.168.1.1`).
    *   Хост **А** использует ARP, чтобы определить MAC-адрес шлюза (`192.168.1.1`), если он еще не известен.
    *   IP-пакет инкапсулируется в Ethernet-кадр, но в качестве MAC-адреса назначения указывается **MAC-адрес шлюза**, а не конечного получателя.

3.  **Дальнейшая маршрутизация:** Шлюз, получив кадр, "распаковывает" его, анализирует IP-адрес назначения (`8.8.8.8`) и, на основе своей таблицы маршрутизации, пересылает пакет дальше по цепочке маршрутизаторов в сторону конечной цели.

#### Вывод: роль шлюза

*   **Шлюз не нужен для коммуникации внутри одной подсети.** Его отсутствие не помешает локальному обмену данными.
*   **Шлюз абсолютно необходим для связи с любыми устройствами за пределами локальной подсети.** Без него хост будет "изолирован" от внешнего мира.
