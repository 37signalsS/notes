#### Модель OSI

Сетевая модель OSI (Open Systems Interconnection) — это концептуальная модель, которая стандартизирует сетевые функции, разделяя их на семь уровней. Каждый уровень обслуживает вышестоящий уровень и использует функции нижестоящего. В процессе отправки данные проходят от 7-го уровня к 1-му, а при получении — в обратном порядке. Этот процесс называется **инкапсуляцией** (при отправке) и **декапсуляцией** (при получении).

На каждом уровне к данным добавляется заголовок (header), и этот блок данных называется **PDU (Protocol Data Unit)**. У каждого уровня PDU имеет своё название.

| Уровень (Layer) | PDU (Тип данных) | Основные функции | Примеры протоколов и стандартов | Оборудование |
| :--- | :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | **Данные (Data)** | Предоставление API для доступа к сетевым службам. | [HTTP](../Protocols/application_layer.md#http-hypertext-transfer-protocol), FTP, SMTP, DNS, WebSocket, [gRPC](../ServicesAndTools/grpc_overview.md) | Хосты, Шлюзы, L7-брандмауэры (WAF) |
| **6. Представления (Presentation)** | **Данные (Data)** | Преобразование формата данных, сжатие, шифрование. | [SSL/TLS](../Protocols/tls_protocol.md), ASCII, JPEG, MPEG | Хосты, Шлюзы |
| **5. Сеансовый (Session)** | **Данные (Data)** | Установка, управление и завершение сеансов связи между приложениями. | NetBIOS, RPC, Sockets API | Хосты, Шлюзы |
| **4. Транспортный (Transport)** | **Сегменты** (TCP)<br>**Дейтаграммы** (UDP) | Надёжная (TCP) или быстрая (UDP) доставка данных, контроль потока, адресация по портам. | TCP, UDP, SCTP | Хосты, L4-брандмауэры |
| **3. Сетевой (Network)** | **Пакеты (Packets)** | Маршрутизация пакетов между сетями, логическая адресация (IP-адреса). | IPv4, IPv6, ICMP, IPSec, OSPF | **[Маршрутизатор](./network_devices.md#маршрутизатор-роутер)**, L3-коммутатор |
| **2. Канальный (Data Link)** | **Кадры (Frames)** | Физическая адресация (MAC-адреса), контроль ошибок передачи, управление доступом к среде. | Ethernet, Wi-Fi, PPP, ARP, VLAN | **[Коммутатор (Switch)](./network_devices.md#коммутатор-свитч)**, Мост, Сетевая карта (NIC) |
| **1. Физический (Physical)** | **Биты (Bits)** | Передача битового потока по физической среде (электрические, световые сигналы). | Ethernet (кабель), USB, Bluetooth, RJ-45, Оптоволокно | **Концентратор (Hub)**, Повторитель, Кабели, Трансиверы |

**Уровни:**

*   **Host layers**: 7–4 (Отвечают за представление данных и взаимодействие с приложениями)
*   **Media layers**: 1–3 (Отвечают за передачу данных по сети)

#### Процесс отправки (Инкапсуляция): Собираем "матрёшку"

Когда вы отправляете данные, они проходят сверху вниз по уровням OSI, и на каждом уровне "заворачиваются" в новый "конверт" (PDU).

-   **Уровень 7 (Прикладной): Данные**
    -   **Что происходит:** Ваше приложение (браузер, мессенджер) создаёт исходные данные.
    -   **Результат:** `[Данные: "Привет"]`

-   **Уровень 4 (Транспортный): Данные → Сегменты**
    -   **Что происходит:** Протокол TCP берёт ваши данные и упаковывает их в **сегмент**. На этот "конверт" он пишет **номера портов** (от кого и кому, например, порт 443 для HTTPS). Это нужно, чтобы ОС на той стороне знала, какому приложению отдать данные.
    -   **Результат:** `[Заголовок TCP (порты)] [Данные: "Привет"]`

-   **Уровень 3 (Сетевой): Сегменты → Пакеты**
    -   **Что происходит:** Сегмент упаковывается в следующий конверт — **пакет**. На него протокол IP пишет глобальные адреса — **IP-адреса** отправителя и получателя. Это нужно для маршрутизации по всему интернету.
    -   **Результат:** `[Заголовок IP (IP-адреса)] [Сегмент]`

-   **Уровень 2 (Канальный): Пакеты → Кадры**
    -   **Что происходит:** Пакет упаковывается в последний конверт — **кадр** (фрейм). На него протокол Ethernet пишет локальные, физические адреса — **MAC-адреса** вашего компьютера и вашего роутера. Это нужно для доставки в пределах одной локальной сети.
    -   **Результат:** `[Заголовок Ethernet (MAC-адреса)] [Пакет] [Концевик]`

-   **Уровень 1 (Физический): Кадры → Биты**
    -   **Что происходит:** Ваша сетевая карта преобразует весь кадр целиком в последовательность электрических или световых сигналов.
    -   **Результат:** `0101011101000101...`

#### Процесс получения (Декапсуляция): Разбираем "матрёшку"

-   **Уровень 1: Биты → Кадры**
    -   Сетевая карта получает сигналы и собирает из них **кадр**.

-   **Уровень 2: Кадры → Пакеты**
    -   Система проверяет MAC-адрес в кадре. Если он совпадает, заголовок кадра отбрасывается, и из него извлекается **пакет**.

-   **Уровень 3: Пакеты → Сегменты**
    -   Система проверяет IP-адрес в пакете. Если он совпадает, заголовок пакета отбрасывается, и из него извлекается **сегмент**.

-   **Уровень 4: Сегменты → Данные**
    -   Система смотрит на порт в сегменте, чтобы понять, какому приложению предназначены данные. Заголовок сегмента отбрасывается.

-   **Уровень 7: Обработка данных**
    -   Чистые **данные** передаются приложению (например, веб-серверу).

#### Модель TCP/IP

Модель TCP/IP (Transmission Control Protocol/Internet Protocol) — это практическая, а не теоретическая модель, которая легла в основу современного Интернета. В отличие от OSI, она более гибкая и обычно описывается с помощью четырёх уровней.

**Соответствие уровней OSI и TCP/IP:**

| Уровни OSI | Уровень TCP/IP | Основные функции | Примеры протоколов |
| :--- | :--- | :--- | :--- |
| 7. Прикладной<br>6. Представления<br>5. Сеансовый | **4. Прикладной (Application)** | Взаимодействие с приложениями, представление данных, управление сеансами. | HTTP, FTP, DNS, SMTP, SSH, TLS |
| 4. Транспортный | **3. Транспортный (Transport)** | Обеспечение надёжной (TCP) или быстрой (UDP) доставки, адресация по портам. | TCP, UDP |
| 3. Сетевой | **2. Сетевой (Internet)** | Маршрутизация пакетов между сетями, глобальная адресация (IP). | IP, ICMP, OSPF |
| 2. Канальный<br>1. Физический | **1. Канальный (Network Access)** | Передача данных в локальной сети, физическая адресация (MAC), работа с физической средой. | Ethernet, Wi-Fi, ARP, кабели, коннекторы |

### OSI против TCP/IP

-   **Модель OSI** чаще всего используется как **теоретическая, эталонная модель**. Её главное преимущество — детальное разделение на 7 уровней, что удобно для обучения и формального описания сетевых функций. В техническом жаргоне часто используются обозначения уровней OSI.

-   **Модель TCP/IP** — это **практическая модель**, которая легла в основу современного интернета. Она ближе к реальной реализации сетевых стеков в операционных системах. Когда говорят о "стеке TCP/IP", имеют в виду именно эту модель и **набор протоколов** (стек протоколов), обеспечивающих работу сети, а не только два протокола TCP и IP.

Таким образом, OSI — это "как должно быть в теории", а TCP/IP — это "как это работает на практике".



### Уровни модели TCP/IP

Модель TCP/IP состоит из четырех уровней, каждый из которых выполняет свои функции:

1.  **Канальный уровень (Network Access Layer)**:
    *   **Функция**: Отвечает за физическую доставку данных в пределах одной локальной сети.
    *   **Адресация**: Использует MAC-адреса для идентификации устройств в локальной сети.
    *   **Пример**: Для физической доставки данных в локальной сети (Ethernet или Wi-Fi) вашему компьютеру нужно знать MAC-адрес устройства-получателя. Он формирует Ethernet-кадр, помещает туда данные, указывает MAC-адрес получателя и отправляет его. MAC-адрес — это уникальный цифровой идентификатор сетевого устройства, состоящий из 6 октетов. Для определения MAC-адреса устройства в той же локальной сети по его IP-адресу используется протокол ARP. Также на этом уровне происходит широковещательная рассылка DHCP-запросов для получения IP-адреса. Например, устройство отправляет широковещательный запрос (MAC-адрес назначения состоит из одних единиц), который рассылается всем устройствам в пределах широковещательного домена (локальной сети). DHCP-сервер отвечает на этот запрос, присваивая IP-адрес. Подход с передачей данных только по MAC-адресам не масштабируется на большие и сложные сети, поэтому для маршрутизации между сетями используются IP-адреса. MAC-адрес — это уникальный идентификатор устройства, назначенный производителем, не зависящий от местоположения устройства.

2.  **Межсетевой уровень (Internet Layer)**:
    *   **Функция**: Отвечает за маршрутизацию данных между различными локальными сетями (в интернете).
    *   **Адресация**: Использует IP-адреса для логической адресации устройств в глобальной сети. IP-адрес — это логический, программно-назначаемый адрес, который содержит в себе часть информации о маршруте, а именно адрес подсети.
    *   **Пример**: На этом уровне данные заворачиваются в IP-пакеты и в каждом пакете указывается IP-адрес, на который он должен быть доставлен. Чтобы отправить IP-пакет получателю, который не находится в вашей локальной сети, вам нужно передать этот пакет по цепочке устройств. Поскольку физическая доставка данных осуществляется только на канальном уровне, вам нужно спуститься на канальный уровень и отправить данные на следующее устройство в этой цепочке, которая имеет доступ к другой локальной сети. Потом вам надо снова подняться на сетевой уровень и решить, на какое следующее устройство должен быть доставлен этот пакет. Затем вы опять спускаетесь на первый уровень, передаёте данные на следующее устройство и повторяете до тех пор, пока ваш пакет не пройдёт через все промежуточные локальные сети и не достигнет того устройства, для которого он предназначен. На каждом промежуточном устройстве принимается решение, с учётом IP-адреса, на какое следующее устройство должен быть доставлен пакет, с тем, чтобы выбрать более или менее быстрый маршрут. Для маршрутизации используются маршрутизаторы (роутеры). Маршрутизация осуществляется с помощью протоколов маршрутизации, которые распределенно хранят на маршрутизаторах информацию, как добраться до других подсетей, не связанных с маршрутизатором напрямую. Эту информацию надо периодически обновлять, хранить данные о резервных маршрутах и ранжировать маршруты по какой-то метрике, например, на основе bandwidth и delay.


3.  **Транспортный уровень (Transport Layer)**:
    *   **Функция**: Обеспечивает связь между приложениями на разных устройствах, а не между самими устройствами. Отвечает за надежную (TCP) или быструю (UDP) доставку данных.
    *   **Адресация**: Использует номера портов для идентификации конкретных приложений или служб на устройстве.
    *   **Пример**: На этом уровне работают транспортные протоколы, такие как TCP, UDP, TLS и QUIC. Они позволяют обмениваться данными не между устройствами, а между приложениями, а точнее между портами. Приложение просит операционную систему выделить для него порт (например, 80 для HTTP). Если ОС соглашается, то приложение получает возможность слушать этот порт. Если на это устройство приходит TCP-пакет, в котором указан номер порта 80, то ОС даёт приложению сигнал, что на данном порте появились новые данные, и приложение получает возможность прочитать эти данные. Если придёт UDP-пакет, в котором указан порт 80, то приложение ничего о нём не узнает, потому что у операционной системы есть отдельная таблица сокетов для UDP и отдельная для TCP. Работая с протоколом TCP, программисту вообще не нужно думать о разбиении данных на TCP-пакеты, IP-пакеты и интернет-кадры, и о том, что эти пакеты могут отправляться по разным физическим маршрутам и теряться по пути. Он просто устанавливает TCP-соединение между двумя приложениями на разных устройствах, загружает массив байтов в TCP-сокет на одном устройстве и получает точно такой же массив байтов из TCP-сокета на другом устройстве. IP-пакеты могут теряться из-за помех, переполнения буферов сетевых устройств, препятствий на пути радиоканала, повреждённых кабелей и так далее. И никакие протоколы сетевого и канального уровней никак не борются с этой проблемой, поскольку это не их зона ответственности. Повторная отправка потерянных пакетов, если это необходимо, происходит на транспортном уровне. Например, этим занимается протокол TCP, потому что TCP — это протокол для надёжной передачи данных. TCP также восстанавливает порядок данных, потому что IP-пакеты вполне могут быть отправлены в одном порядке, а получены в другом. UDP ничего не делает для решения этих проблем, но зато он более быстрый. Протокол TLS работает поверх протокола TCP, поэтому он тоже обеспечивает надёжную доставку данных, но вдобавок к этому он обеспечивает шифрование и позволяет установить защищенный канал связи. Раньше для этого использовался протокол SSL, но он безнадёжно устарел.

4.  **Прикладной уровень (Application Layer)**:
    *   **Функция**: Определяет, как данные должны быть структурированы и интерпретированы приложениями. Содержит протоколы, с которыми непосредственно взаимодействуют пользовательские приложения.
    *   **Пример**: На этом уровне существуют известные всем протоколы HTTP, HTTPS, FTP для передачи файлов, SMTP для электронной почты, DNS и прочие. Этот уровень вообще не про то, как доставлять данные, он про то, как их структурировать и распознавать. Очень удобно, что вы можете создать TCP-соединение, отправить по нему массив байтов и получить этот массив на другом устройстве без всяких потерь. Но как вы будете интерпретировать эти байты? Как вы вообще поймёте, где начинается и где заканчивается сообщение, записанное этими байтами? Для этого нужны соглашения о структуре передаваемых сообщений и о порядке обмена сообщениями. И если вы хотите обмениваться сообщениями с клиентами и серверами по всему миру, для которых вы не писали ПО, то вам нужно использовать международные стандарты структуризации этих сообщений.

**Ключевые отличия от OSI:**

*   **Прагматизм против теории:** TCP/IP — это набор реальных протоколов, на которых построен интернет. OSI — это эталонная, теоретическая модель, созданная для стандартизации, но её протоколы не получили широкого распространения.
*   **Объединение уровней:** TCP/IP объединяет несколько уровней OSI, что делает модель проще:
    *   Уровни OSI 5, 6, 7 → **Прикладной уровень** TCP/IP.
    *   Уровни OSI 1, 2 → **Канальный уровень** TCP/IP.
*   **Фокус на IP:** В TCP/IP межсетевой протокол (IP) является центральным элементом, вокруг которого строятся все остальные взаимодействия.
