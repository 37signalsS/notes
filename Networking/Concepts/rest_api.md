# REST (Representational State Transfer)

## Что это такое?

**REST (Representational State Transfer)** — это архитектурный стиль программного обеспечения, который применяется для создания распределённых систем, таких как веб-службы. Он определяет набор принципов и ограничений, которым должна соответствовать система для обеспечения масштабируемости, гибкости и надежности.

Этот подход предложил Рой Филдинг, один из разработчиков HTTP-протокола, в начале 2000-х, как способ описания архитектуры Всемирной паутины.

## Основные принципы REST

RESTFul-сервисы позволяют работать с ресурсами (данными) через унифицированный интерфейс, основываясь на простых и понятных HTTP-командах (методах):

*   **GET** – получение данных о ресурсе. Является идемпотентным (многократное выполнение не меняет состояние на сервере) и безопасным (не вызывает побочных эффектов).
*   **POST** – создание нового ресурса или отправка данных для обработки. Не является идеемпотентным.
*   **PUT** – полная замена существующего ресурса или создание ресурса, если его нет. Является идемпотентным.
*   **PATCH** – частичное обновление существующего ресурса.
*   **DELETE** – удаление ресурса. Является идемпотентным.

Каждая единица данных (ресурс) идентифицируется уникальным универсальным идентификатором ресурса (URL/URI).

**Примеры URL-адресов ресурсов:**
*   Книга в библиотеке: `/books/2`
*   Страница книги: `/books/2/pages/145`

## REST на практике

REST-сервисы исключают использование сложных бинарных протоколов и слоёв, таких как SOAP или XML-RPC, и передают данные в легко читаемых форматах, таких как JSON или XML. Это делает архитектуру более лёгкой и быстрой в разработке и использовании.

### Примеры типичных REST-запросов (с использованием HTTP-методов):

1.  **GET `/books/`** – возвращает список всех книг.
2.  **GET `/books/2`** – предоставляет информацию о книге с ID 2.
3.  **POST `/books/`** – добавляет новую книгу в коллекцию. Тело запроса содержит данные новой книги.
4.  **PUT `/books/2`** – полностью обновляет информацию о книге с ID 2. Тело запроса содержит новые данные для книги.
5.  **PATCH `/books/2`** – частично обновляет информацию о книге с ID 2 (например, меняет только заголовок).
6.  **DELETE `/books/2`** – удаляет книгу с ID 2.

## Почему выбирают REST?

*   **Простота:** Легко понять и использовать. Модель взаимодействия интуитивно понятна, так как основана на стандартных HTTP-методах.
*   **Лёгкость (Lightweight):** Отсутствие дополнительных протокольных слоёв и использование текстовых форматов данных (JSON, XML) упрощает обработку данных и снижает накладные расходы.
*   **Гибкость (Flexibility):** Работает с любыми клиентами (веб-браузеры, мобильные приложения, десктопные программы) и серверами, поддерживающими HTTP.
*   **Масштабируемость:** Отсутствие состояния на сервере (statelessness) упрощает горизонтальное масштабирование.
*   **Отсутствие состояния (Statelessness):** Каждый запрос от клиента к серверу должен содержать всю информацию, необходимую для понимания запроса. Сервер не должен хранить контекст клиента между запросами. Это повышает надежность и масштабируемость.
*   **Кэширование:** Клиенты могут кэшировать ответы, что сокращает задержку и нагрузку на сервер.

## Особенности и ограничения

*   **Отсутствие встроенной безопасности:** REST сам по себе не включает встроенных механизмов безопасности (аутентификация, авторизация, шифрование). Для безопасности данных необходимо использовать дополнительные механизмы, такие как HTTPS для шифрования, и различные схемы аутентификации (например, HTTP Basic Auth, OAuth 2.0, JWT).
*   **Отсутствие стандарта:** REST — это архитектурный стиль, а не строгий стандарт. Это может приводить к некоторым вариациям в реализации.
*   **Избыточность:** Для получения сложных данных иногда требуется несколько запросов, что может быть неоптимально. Для таких случаев могут использоваться альтернативы, такие как GraphQL.
*   **Не подходит для всех задач:** REST не всегда является лучшим выбором для приложений, требующих постоянного двунаправленного соединения или очень низких задержек (например, онлайн-игры, чаты), где могут быть более эффективны технологии вроде WebSockets.
