# Прокси-сервер

## Определения

**Прокси-сервер** — промежуточный узел между клиентом и целевым сервером, перенаправляющий трафик через себя. Основные функции: кэширование, контроль доступа, фильтрация контента, сокрытие внутренней архитектуры.

## Основные концепции

### Как работает прокси-сервер

Прокси-сервер выступает посредником, разрывая прямое соединение между клиентом и сервером:

1. **Запрос клиента:** Клиент отправляет запрос не напрямую целевому серверу, а на адрес прокси.
2. **Перехват и обработка:** Прокси-сервер получает запрос. На этом этапе он может:
   - Проверить права доступа клиента.
   - Проверить наличие ресурса в локальном кэше (если есть — вернуть сразу).
   - Изменить заголовки (например, подставить `X-Forwarded-For` или скрыть IP клиента).
3. **Запрос к цели:** Если ресурса нет в кэше, прокси устанавливает собственное соединение с целевым сервером и запрашивает данные от своего имени.
4. **Ответ сервера:** Целевой сервер отправляет ответ прокси-серверу.
5. **Возврат клиенту:** Прокси получает данные, при необходимости кэширует их и пересылает клиенту.

Прокси-серверы классифицируются по протоколам и функциональному назначению.

### По протоколам

| Тип | Уровень | Особенности |
| :--- | :--- | :--- |
| HTTP-прокси | L7 | Кэширование, обработка HTTP-запросов ([HTTP](../Protocols/HTTP/http_basics.md)) |
| HTTPS-прокси | L7 | Шифрование через [TLS](../Protocols/tls.md) |
| SOCKS-прокси | L5 | Универсальный (HTTP, FTP, P2P), без кэширования |
| TCP/UDP-прокси | L4 | Прозрачная переадресация без анализа протокола |

### По направлению трафика

| Тип | От имени | Направление | Что видит внешний мир |
| :--- | :--- | :--- | :--- |
| **Forward Proxy** | Клиента | Исходящий трафик из локальной сети в интернет | IP прокси, а не клиента |
| **Reverse Proxy** | Сервера | Входящий трафик из интернета на бэкенды | Только IP прокси |

### По уровню анонимности

| Тип | Скрывает IP клиента | Скрывает факт прокси |
| :--- | :--- | :--- |
| Прозрачный (Transparent) | Нет | Нет |
| Анонимный | Да | Нет |
| Элитный (Elite) | Да | Да |

### Proxy Protocol

[Proxy Protocol](../Protocols/proxy_protocol.md) позволяет передавать исходный IP-адрес клиента через цепочку прокси на бэкенд. Критичен для логирования, аналитики и geo-IP.

### Современные расширения

- **API Gateway:** Reverse proxy для микросервисов с функциями аутентификации, rate limiting, маршрутизации по контенту, агрегации ответов.
- **Service Mesh:** Распределённый прокси-слой (Envoy/Istio) в виде sidecar-контейнеров. Обеспечивает mTLS, наблюдаемость, политики доступа на L7. Подробнее: [Service Mesh Concepts](../../Service_Mesh/service_mesh_concepts.md).

## Практические сценарии

### Forward Proxy

- Обход геолокационных ограничений.
- Кэширование внешних ресурсов для ускорения доступа.
- Корпоративный контроль: фильтрация сайтов, учёт трафика.

### Reverse Proxy

- **Балансировка нагрузки** между бэкенд-серверами ([L7](../../WebServers/Nginx/Proxy/Load_Balancing/overview_concepts.md), [L4](../../WebServers/Nginx/Proxy/nginx_l4_proxying.md)).
- **SSL/TLS-терминирование** — снятие шифрования на прокси, разгрузка бэкендов ([TLS](../Protocols/tls.md)).
- **Кэширование** контента для снижения нагрузки ([Proxy Cache](../../WebServers/Nginx/Performance/Caching/proxy_caching.md)).
- **Сокрытие архитектуры** — внешний мир видит только IP прокси.
- **Защита от DDoS** — маскировка реального IP хоста, фильтрация трафика, rate limiting, geo-блокировка.

### Реализации

- **Nginx/Angie:** обратный прокси и балансировщик ([настройка Angie](../../WebServers/Angie/angie_reverse_proxy.md)).
- **HAProxy:** высокопроизводительный L4/L7 балансировщик ([HAProxy Overview](../../WebServers/haproxy_overview.md)).
- **Traefik:** динамический reverse proxy для контейнеров ([Traefik Overview](../../WebServers/Traefik/traefik_overview.md)).
