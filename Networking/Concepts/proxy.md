# Прокси-сервер

## Определения

**Прокси-сервер** (от англ. *proxy* — «посредник») — промежуточный программный или аппаратный узел между клиентом и целевым сервером, который принимает запросы, обрабатывает их и пересылает получателю от своего имени.

Прокси-серверы работают на разных уровнях модели OSI:
- **L7 (Прикладной):** Понимают протоколы (HTTP, FTP), могут кэшировать контент и изменять заголовки.
- **L4 (Транспортный):** Работают с TCP/UDP потоками без анализа содержимого.

## Принципы работы

### Как работает прокси-сервер

Прокси-сервер разрывает прямое соединение между клиентом и сервером:

1. **Запрос клиента:** Клиент отправляет запрос не напрямую целевому серверу, а на адрес прокси.
2. **Перехват и обработка:** Прокси-сервер получает запрос и может выполнить следующие действия:
   - Проверить права доступа клиента (авторизация).
   - Проверить наличие ресурса в локальном кэше (если есть — вернуть ответ мгновенно).
   - Изменить заголовки (например, подставить `X-Forwarded-For` или скрыть оригинальный IP).
3. **Запрос к цели:** Если ресурса нет в кэше, прокси устанавливает соединение с целевым сервером и запрашивает данные.
4. **Ответ сервера:** Целевой сервер отправляет данные прокси-серверу.
5. **Возврат клиенту:** Прокси получает данные, при необходимости кэширует их и пересылает клиенту.

### Прозрачное проксирование (Transparent Proxying)

При прозрачном проксировании клиент не знает о существовании прокси (в настройках приложения прокси не указан). Трафик перехватывается на сетевом уровне (например, через `iptables` REDIRECT или TPROXY).

- **Техническая реализация:** Использование `Policy Based Routing` или перенаправление порта 80/443 на порт прокси-сервера.
- **Особенности:** Позволяет принудительно фильтровать трафик в корпоративных сетях без настройки клиентских устройств.

### Проксирование HTTPS (Метод CONNECT)

Поскольку HTTPS-трафик зашифрован, обычный прокси-сервер не может прочитать его содержимое без терминации SSL. Для этого используется HTTP-метод **CONNECT**.

1. Клиент отправляет запрос `CONNECT example.com:443 HTTP/1.1`.
2. Прокси устанавливает TCP-соединение с целевым сервером.
3. Прокси возвращает клиенту `HTTP/1.1 200 Connection Established`.
4. Клиент и сервер устанавливают TLS-соединение внутри созданного TCP-туннеля. Прокси выступает в роли прозрачной «трубы».

## Классификация прокси-серверов

### По протоколам

| Тип | Уровень OSI | Особенности |
| :--- | :--- | :--- |
| **HTTP-прокси** | L7 | Кэширование, фильтрация URL, обработка заголовков ([HTTP](../Protocols/HTTP/http_basics.md)) |
| **HTTPS-прокси** | L7 | Туннелирование через метод CONNECT или SSL-терминация ([TLS](../Protocols/tls.md)) |
| **SOCKS-прокси** | L5 | Универсальный туннель. SOCKS5 поддерживает UDP и аутентификацию, в отличие от SOCKS4. |
| **TCP/UDP-прокси** | L4 | Прозрачная переадресация потоков данных без анализа протокола |

### По направлению трафика

| Тип | Чьи интересы представляет | Направление | Основная цель |
| :--- | :--- | :--- | :--- |
| **Прямой прокси (Forward Proxy)** | Клиента | Из локальной сети в интернет | Анонимность, обход блокировок, кэширование |
| **Обратный прокси (Reverse Proxy)** | Сервера | Из интернета к бэкендам | Балансировка, безопасность, SSL-терминация |

### По уровню анонимности

| Тип | Передает IP клиента | Сообщает, что он прокси (`Via`) |
| :--- | :--- | :--- |
| **Прозрачный (Transparent)** | Да | Да |
| **Анонимный** | Нет (скрывает IP) | Да |
| **Элитный (Elite / High Anonymity)** | Нет | Нет |

## Протокол Proxy Protocol

[Протокол Proxy Protocol](../Protocols/proxy_protocol.md) позволяет передавать исходный IP-адрес клиента и порт через цепочку прокси (L4) на бэкенд, когда использование заголовков HTTP (L7) невозможно.

- **V1:** Текстовый формат (`PROXY TCP4 1.2.3.4 ...`).
- **V2:** Бинарный формат (более производительный, используется в HAProxy, Nginx, AWS ELB).

## Современные технологии и расширения

### Service Mesh и eBPF

Современные инфраструктуры отходят от классических прокси в пользу более глубокой интеграции с ядром Linux.

- **Service Mesh:** Распределённый прокси-слой (например, Envoy/Istio) в виде sidecar-контейнеров. Обеспечивает mTLS, наблюдаемость и сложные политики маршрутизации. Подробнее: [Service Mesh Concepts](../../Service_Mesh/service_mesh_concepts.md).
- **eBPF (Cilium):** Позволяет выполнять проксирование прямо в ядре Linux, обходя оверхед пользовательского пространства. Это технология "sidecar-less" service mesh (Istio Ambient).

### Современные инструменты

- **Envoy:** Стандарт де-факто для облачных инфраструктур, написан на C++.
- **Pingora:** Современный прокси-фреймворк от Cloudflare, написанный на **Rust**. Обеспечивает безопасность памяти и высокую производительность при обработке HTTP/3.
- **Traefik:** Динамический reverse proxy для Docker и Kubernetes с автоматическим обнаружением сервисов. Подробнее: [Traefik Overview](../../WebServers/Traefik/traefik_overview.md).

### Проблемы и решения HTTP/3 (QUIC)

Переход на HTTP/3 (работает поверх UDP) создает сложности для традиционных TCP-прокси.
- **MASQUE:** Фреймворк для туннелирования UDP-трафика (включая QUIC) через HTTP/3 прокси.
- **Connection Migration:** Прокси должен отслеживать Connection ID, а не только IP, чтобы поддерживать соединение при смене сети клиентом.

## Практические сценарии

### Прямой прокси (Forward Proxy)

- **Обход геолокационных ограничений:** Маскировка реального местоположения.
- **Кэширование:** Экономия трафика в больших организациях.
- **Контроль доступа:** Фильтрация нежелательного контента на уровне компании.

### Обратный прокси (Reverse Proxy)

- **Балансировка нагрузки:** Распределение запросов между группой бэкендов ([L7](../../WebServers/Nginx/Proxy/Load_Balancing/overview_concepts.md), [L4](../../WebServers/Nginx/Proxy/nginx_l4_proxying.md)).
- **SSL/TLS-терминирование:** Снятие нагрузки по шифрованию с серверов приложений ([TLS](../Protocols/tls.md)).
- **Защита от DDoS:** Скрытие реальных IP серверов и ограничение частоты запросов (Rate Limiting).
- **Кэширование бэкенда:** Хранение тяжелых ответов на прокси ([Proxy Cache](../../WebServers/Nginx/Performance/Caching/proxy_caching.md)).
