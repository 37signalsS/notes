### NAT (network address translation)

NAT — это технология, позволяющая перенаправлять трафик между локальной и глобальной сетями. Благодаря ей несколько устройств в локальной сети могут выходить в интернет, используя один "белый" IP-адрес, выданный провайдером.

**Механизмы трансляции адресов**

NAT использует четыре основных механизма:

1.  **Статический NAT (Static NAT):** Однозначное сопоставление "один к одному" между локальным и глобальным IP-адресом, заданное администратором. Например, `192.168.1.10` всегда транслируется в `203.0.113.10`. Этот механизм не экономит IP-адреса и используется для публикации внутренних серверов во внешней сети.

2.  **Динамический NAT (Dynamic NAT):** Администратор выделяет пул глобальных IP-адресов. Когда внутреннее устройство выходит в интернет, ему динамически назначается свободный IP-адрес из этого пула. Если пул исчерпан, новые устройства не смогут выйти в сеть, пока один из адресов не освободится. Этот механизм сегодня используется редко.

3.  **Статический PAT (Static Port Address Translation):** Транслирует разные приватные адреса в один и тот же публичный адрес, но с разными номерами портов.

4.  **Динамический PAT (Dynamic Port Address Translation) или перегруженный NAT (NAT Overload):** Самый распространенный механизм. Все устройства в локальной сети используют один глобальный IP-адрес. Роутер динамически создает таблицу соответствия, связывая уникальные пары `[локальный IP-адрес]:[локальный порт]` с парами `[глобальный IP-адрес]:[новый порт]`. Это позволяет тысячам устройств одновременно выходить в интернет через один публичный IP-адрес.

**Принцип работы PAT:**
1.  Устройство с локальным IP (например, 192.168.0.3) отправляет запрос в интернет.
2.  Роутер с глобальным IP (например, 208.135.26.4) подменяет локальный IP на свой глобальный, запоминая в таблице, какому устройству и порту соответствует этот запрос.
3.  Внешний сервер отвечает на глобальный IP роутера.
4.  Роутер, получив ответ, смотрит в свою таблицу и перенаправляет трафик на исходное устройство в локальной сети.

### Proxy

Прокси выполняет роль промежуточного звена между пользователем и интернетом, перенаправляя трафик через себя. Прокси позволяют ускорять загрузку страниц за счет кэширования, контролировать трафик и фильтровать нежелательный контент.

**Как прокси защищают от DDoS-атак?**

Ключевым методом является маскировка подлинного IP-адреса хоста. Злоумышленники взаимодействуют с прокси, а не с реальным сервером, что исключает прямую атаку.

Дополнительно прокси могут:
*   Фильтровать вредоносный трафик.
*   Ограничивать число запросов с одного IP (rate limiting).
*   Балансировать нагрузку, распределяя трафик между несколькими серверами.
*   Кэшировать контент для снижения нагрузки на основной сервер.
*   Блокировать ботов и применять гео-блокировку.

**Протоколы и виды прокси**

Прокси-серверы классифицируются по протоколам и функциональному назначению.

**По протоколам:**
*   **HTTP-прокси:** Специализируются на обработке HTTP-запросов, могут кэшировать контент для ускорения загрузки.
*   **HTTPS-прокси:** Аналогичны HTTP, но используют шифрование для защиты передаваемых данных.
*   **SOCKS-прокси:** Универсальны, поддерживают различные типы трафика (HTTP, FTP, P2P, игры), но обычно не кэшируют данные.

**По функциональному назначению:**
*   **Forward Proxy (Прямой прокси):** Работает от имени **клиента**. Он перехватывает исходящий трафик от пользователей в локальной сети и направляет его в интернет. Внешний мир видит запросы, идущие от IP-адреса прокси-сервера, а не от конечных пользователей.
    *   **Сценарии использования:**
        *   Обход блокировок и геолокационных ограничений.
        *   Кэширование внешних ресурсов для ускорения доступа.
        *   Фильтрация и контроль доступа сотрудников к внешним сайтам.

*   **Reverse Proxy (Обратный прокси):** Работает от имени **сервера**. Он принимает входящие запросы из интернета и распределяет их на один или несколько бэкенд-серверов, находящихся в локальной сети. Клиент не знает, какой именно сервер обработал его запрос.
    *   **Сценарии использования:**
        *   Балансировка нагрузки (Load Balancing) между несколькими серверами.
        *   SSL/TLS-терминирование (снятие шифрования).
        *   Кэширование контента для снижения нагрузки на бэкенды.
        *   Защита и сокрытие внутренней архитектуры сети.

*   **Анонимные прокси:** Скрывают IP-адрес клиента для повышения приватности.
*   **Прозрачные прокси:** Не скрывают IP-адрес, используются для мониторинга и контроля трафика в корпоративных или образовательных сетях.

### QoS

QoS (Quality of Service, качество обслуживания) – функция маршрутизации, которая позволяет определять приоритеты полосы пропускания для определенных программ, клиентов или служб. QoS резервирует определенный объём пропускной способности для критичных приложений.

## Объединение сетевых интерфейсов (Bonding)

**Bonding** (также известное как `teaming` или `Link Aggregation`) — это технология, позволяющая объединить несколько физических сетевых интерфейсов в один логический. Это делается для достижения двух основных целей:

1.  **Отказоустойчивость (Fault Tolerance):** Если один из физических каналов выходит из строя, трафик автоматически перенаправляется через оставшиеся рабочие каналы, обеспечивая непрерывность соединения.
2.  **Агрегация пропускной способности (Link Aggregation):** Суммирование пропускной способности нескольких каналов для увеличения общей скорости передачи данных.

**Режимы работы Bonding**

Модуль `bonding` в ядре Linux поддерживает несколько режимов работы:

-   `mode=0` (**balance-rr**): Round-robin. Пакеты поочередно отправляются через каждый интерфейс. Обеспечивает балансировку нагрузки и отказоустойчивость.
-   `mode=1` (**active-backup**): Один интерфейс активен, остальные находятся в режиме ожидания. Если активный интерфейс падает, один из резервных занимает его место. Идеально для отказоустойчивости.
-   `mode=4` (**802.3ad**): Динамическая агрегация каналов (LACP). Требует поддержки со стороны сетевого коммутатора. Обеспечивает как балансировку, так и отказоустойчивость, являясь отраслевым стандартом.
-   `mode=6` (**balance-alb**): Адаптивная балансировка нагрузки. Не требует специальной настройки коммутатора.

Настройка `bonding` обычно выполняется через системные конфигурационные файлы сети (например, в `/etc/network/interfaces` для Debian/Ubuntu или через `nmcli`/`nmtui` для систем с NetworkManager).
