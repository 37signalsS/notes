# DPDK: Технические детали

Этот документ раскрывает ключевые механизмы, которые обеспечивают высокую производительность DPDK. Для общего понимания архитектуры см. [Обзор DPDK](dpdk_overview.md).

### Определения

- **Hugepages**: Страницы памяти большого размера (2 МБ или 1 ГБ вместо стандартных 4 КБ). DPDK использует их для уменьшения количества промахов в TLB.
- **TLB (Translation Lookaside Buffer)**: Специализированный кеш в CPU, который хранит недавние преобразования виртуальных адресов в физические. Промах TLB (TLB miss) — дорогостоящая операция.
- **Polling (Режим опроса)**: Процесс, при котором CPU в цикле постоянно проверяет состояние устройства (например, наличие новых пакетов на сетевой карте), вместо ожидания сигнала прерывания.

### Основные концепции

**Оптимизация работы с памятью: Hugepages**

DPDK требует предварительного выделения пула Hugepages системным администратором.

- **Причина**: Большое число маленьких страниц (4 КБ) быстро переполняет TLB. Обращение к странице, отсутствующей в TLB, требует медленного поиска в таблицах страниц в основной памяти.
- **Решение**: Одна Hugepage на 2 МБ заменяет 512 обычных страниц, снижая нагрузку на TLB в 512 раз. Критически важно для приложений, обрабатывающих миллионы пакетов в секунду.

**Режим опроса (Polling) вместо прерываний**

- **Проблема прерываний**: Каждое прерывание заставляет CPU остановить текущую задачу, сохранить контекст, перейти к обработчику прерывания, выполнить его и восстановить контекст. Для интенсивного сетевого трафика это становится узким местом.
- **Решение DPDK**: Poll Mode Drivers (PMD) работают в режиме непрерывного опроса. Выделенное ядро CPU на 100% занято циклом проверки новых пакетов.
  - **Преимущества**: Нулевые накладные расходы на прерывания, минимальная и предсказуемая задержка (latency).
  - **Недостаток**: Ядро CPU загружено на 100% даже при отсутствии трафика. DPDK-приложения требуют тщательного планирования ресурсов CPU.

### Практические сценарии

**Настройка Hugepages**

Настройка выполняется через параметры ядра:

```bash
# Выделить 1024 страницы по 2МБ (всего 2ГБ)
# Добавить в /etc/sysctl.conf:
vm.nr_hugepages = 1024

# Применить немедленно:
sysctl -p

# Проверить выделение:
cat /proc/meminfo | grep Huge
```

**Оценка производительности**

Влияние техник на производительность:

| Метрика | Ядро Linux | DPDK | Улучшение |
| :--- | :--- | :--- | :--- |
| **Пропускная способность** | ~1-2 Mpps | 10-140 Mpps (зависит от CPU) | **~50-100x** |
| **Задержка (Latency)** | Десятки микросекунд (µs) | Единицы микросекунд (µs) | **~10x** |
| **Джиттер (Jitter)** | Высокий и непредсказуемый | Низкий и предсказуемый | **Стабильность** |

*Mpps = миллионов пакетов в секунду.*
