# DPDK: Технические детали

### Определения

- **EAL (Environment Abstraction Layer)**: Слой абстракции окружения, который инициализирует ресурсы (память, ядра CPU, PCI-устройства) и скрывает детали реализации конкретной ОС и архитектуры.
- **Hugepages (Большие страницы)**: Страницы памяти размером 2 МБ или 1 ГБ (вместо 4 КБ). Используются для минимизации промахов в TLB-кеше процессора.
- **TLB (Translation Lookaside Buffer)**: Буфер в CPU для кеширования трансляции виртуальных адресов в физические. Промах TLB (TLB miss) приводит к дорогостоящему поиску в таблицах страниц в RAM.
- **PMD (Poll Mode Driver)**: Драйвер, работающий в режиме непрерывного опроса устройства. Исключает накладные расходы на обработку прерываний ядра.
- **lcore (Logical Core)**: Поток CPU (или ядро), выделенное DPDK для выполнения цикла обработки пакетов.

### Основные концепции

#### Оптимизация памяти: Hugepages и Mempool
DPDK минимизирует задержки доступа к памяти через следующие механизмы:
1.  **Hugepages**: Снижение количества записей в таблицах страниц. Использование страниц 1 ГБ в 2026 году является стандартом для систем 400G/800G, так как это практически исключает TLB-промахи при работе с большими буферами.
2.  **Mempool**: Пул объектов фиксированного размера. DPDK выделяет память заранее и использует собственные аллокаторы, чтобы избежать фрагментации и блокировок в стандартном `malloc`.
3.  **NUMA-awareness**: DPDK всегда старается выделять память на том же NUMA-узле (процессорном сокете), где работает поток обработки, чтобы избежать задержек на шине QPI/UPI.

#### Обработка пакетов: Polling и Run-to-Completion
В отличие от прерываний ядра Linux, DPDK использует:
- **Polling (Режим опроса)**: `lcore` постоянно проверяет дескрипторы сетевой карты. Это дает предсказуемую задержку (Latency) и исключает переключения контекста `Userspace ↔ Kernel`.
- **Run-to-Completion**: Пакет обрабатывается от начала до конца одним ядром без передачи между потоками, что сохраняет данные в L1/L2 кешах процессора.

#### Технологии ускорения 2026 (DPDK 25.11+)
Современные версии DPDK активно используют аппаратные ускорители:
- **Intel DSA (Data Streaming Accelerator)**: Разгружает CPU от операций копирования памяти (Zero-copy DMA).
- **PCIe Gen6**: Поддержка скоростей до 64 GT/s. DPDK оптимизирует работу с очередями, чтобы минимизировать MMIO-чтения через шину.
- **Post-Quantum Cryptography (PQC)**: Поддержка алгоритмов ML-KEM и ML-DSA на аппаратном уровне (через `cryptodev`).

### Практические сценарии

#### Настройка Hugepages (2026)
В современных системах рекомендуется выделение страниц 1 ГБ через параметры загрузки ядра в `/etc/default/grub`:
```bash
# Добавить в GRUB_CMDLINE_LINUX_DEFAULT:
default_hugepagesz=1G hugepagesz=1G hugepages=16
```
Проверка выделения в реальном времени:
```bash
# Просмотр статистики Hugepages
cat /proc/meminfo | grep -i huge
# → HugePages_Total:     16
# → Hugepagesize:   1048576 kB
```

#### Управление ядрами (CPU Pinning)
Для максимальной производительности ядра CPU должны быть изолированы от планировщика ОС:
```bash
# Изоляция ядер 2-15 в grub
isolcpus=2-15
```
Запуск DPDK-приложения с привязкой к ядрам (EAL-аргументы):
```bash
# Использовать ядра 2, 4 и 6 на 0-м NUMA-узле
./my_dpdk_app -l 2,4,6 --socket-mem 1024,0
```

#### Оценка производительности (Baseline 2026)
Сравнение сетевого стека ядра и DPDK 25.11 на современных CPU (Xeon 6 / EPYC 5th Gen):

| Метрика | Ядро Linux (Standard) | DPDK (25.11 LTS) | Эффект |
| :--- | :--- | :--- | :--- |
| **Пропускная способность** | ~2 Mpps | 100+ Mpps (на ядро) | **~50x рост** |
| **Задержка (Latency)** | 20–50 µs | < 2 µs | **Минимизация** |
| **Масштабируемость** | Ограничена блокировками | Линейная (Lockless) | **Высокая** |
