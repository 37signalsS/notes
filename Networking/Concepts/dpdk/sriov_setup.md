# Настройка и использование SR-IOV

Этот документ представляет собой практическое руководство по настройке SR-IOV. Для понимания базовых концепций (PF, VF, PCI Passthrough) обратитесь к [Обзору SR-IOV](sriov.md).

---

## Определения

Определения ключевых терминов (SR-IOV, PF, VF, PCI Passthrough) приведены в [Обзор SR-IOV](sriov.md#определения).

---

## Основные концепции: Подготовка

Перед началом настройки убедитесь, что выполнены следующие условия:

1. **Поддержка в BIOS/UEFI**: В настройках материнской платы должна быть включена поддержка виртуализации (например, `Intel VT-d` или `AMD-Vi`) и, если есть, опция `SR-IOV`.
2. **Поддержка ядром**: Ядро Linux должно быть скомпилировано с поддержкой `VFIO` и `IOMMU`. В большинстве современных дистрибутивов это включено по умолчанию.
3. **Поддержка сетевой картой**: Сетевая карта должна аппаратно поддерживать SR-IOV.

## Практические сценарии: Пошаговая настройка

### Шаг 1: Активация VF (Virtual Functions)

Сначала необходимо указать ядру, сколько виртуальных функций нужно создать для вашего физического устройства (PF).

```bash
# Найти имя вашего сетевого интерфейса (например, eth0 или enp4s0f0)
ip link show

# Указать количество VF для создания. В данном примере создается 4 VF.
# Замените `eth0` на имя вашего интерфейса.
echo 4 > /sys/class/net/eth0/device/sriov_numvfs

# Чтобы сделать настройку постоянной, используйте systemd-link или rc.local.
```

### Шаг 2: Проверка созданных VF

После выполнения предыдущей команды должны появиться новые виртуальные устройства.

```bash
# Проверить список PCI-устройств. Вы должны увидеть новые "Virtual Function".
lspci | grep -i "virtual function"
```

Новые VF также появятся в списке сетевых интерфейсов (`ip link show`), но без IP-адресов.

### Шаг 3: Привязка VF к драйверу VFIO

Чтобы "пробросить" VF в виртуальную машину или контейнер, его необходимо отвязать от хостового драйвера и привязать к `vfio-pci`. Этот драйвер позволяет userspace-приложениям (например, QEMU/KVM) управлять устройством напрямую.

```bash
# Загрузить модуль, если он еще не загружен
sudo modprobe vfio-pci

# Найти PCI-адрес нужного VF (например, 0000:04:10.0)
lspci | grep -i "virtual function"

# Использовать скрипт dpdk-devbind.py (из состава DPDK) для удобной привязки
# или выполнить это вручную через /sys/bus/pci/drivers/...
sudo dpdk-devbind.py --bind=vfio-pci 0000:04:10.0
```

### Шаг 4: Назначение VF виртуальной машине (Libvirt/KVM)

Теперь VF можно добавить в конфигурацию ВМ как PCI-устройство.

**Пример XML-конфигурации для Libvirt:**

```xml
<domain type='kvm'>
  ...
  <devices>
    ...
    <hostdev mode='subsystem' type='pci' managed='yes'>
      <source>
        <address domain='0x0000' bus='0x04' slot='0x10' function='0x0'/>
      </source>
    </hostdev>
    ...
  </devices>
  ...
</domain>
```

После запуска ВМ увидит новое сетевое устройство, с которым сможет работать напрямую, минуя гипервизор.
