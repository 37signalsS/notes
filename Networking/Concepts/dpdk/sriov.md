# Обзор SR-IOV

### Определения

- **SR-IOV (Single Root I/O Virtualization)**: Спецификация интерфейса PCIe, позволяющая одному физическому устройству (например, сетевому адаптеру) представляться системе как несколько независимых виртуальных устройств.
- **Physical Function (PF)**: Полнофункциональная функция PCIe, обладающая правами на настройку и управление ресурсами SR-IOV. PF видна гипервизору и используется для создания виртуальных функций.
- **Virtual Function (VF)**: «Облегченная» функция PCIe, предназначенная исключительно для передачи данных. VF напрямую пробрасывается (PCI Passthrough) в виртуальную машину (ВМ) или контейнер.
- **vDPA (vHost Data Path Acceleration)**: Гибридная технология, позволяющая использовать стандартные драйверы VirtIO в гостевой ОС, обеспечивая при этом производительность уровня SR-IOV через прямую передачу данных в оборудование.
- **PCIe Gen6**: Стандарт шины 2026 года со скоростью до 64 GT/s (PAM4), обеспечивающий пропускную способность, необходимую для ИИ-фабрик (AI Fabric) и 800G-сетей.

### Основные концепции

#### Проблема программной виртуализации
В классической схеме (без SR-IOV) каждый пакет проходит через стек гипервизора (vSwitch, мосты), что вызывает:
- **Высокую нагрузку на CPU**: Процессор тратит циклы на эмуляцию прерываний и копирование данных.
- **Нестабильную задержку (Jitter)**: Программная обработка зависит от текущей загрузки хоста.
- **Ограничение пропускной способности**: Сложно достичь скоростей 100G+ на стандартных драйверах без специализированной разгрузки.

#### Архитектура SR-IOV: Аппаратное разделение
SR-IOV переносит логику коммутации пакетов непосредственно в **контроллер сетевой карты (NIC)**. Встроенный в адаптер L2-коммутатор направляет пакеты в соответствующую VF на основе MAC-адреса или VLAN-тега.

```
┌────────────────────┐      ┌────────────────────┐
│   ВМ 1 (Guest OS)  │      │   ВМ 2 (Guest OS)  │
│   [Драйвер VF]     │      │   [Драйвер VF]     │
└─────────┬──────────┘      └──────────┬─────────┘
          │ (Direct DMA)               │ (Direct DMA)
┌─────────▼────────────────────────────▼─────────┐
│        Сетевой адаптер (NIC) с SR-IOV          │
│  ┌──────────────────────────────────────────┐  │
│  │         Аппаратный L2-коммутатор         │  │
│  ├────────┬────────┬────────┬────────┬──────┤  │
│  │   PF   │  VF 1  │  VF 2  │  VF 3  │ ...  │  │
│  └────────┴────────┴────────┴────────┴──────┘  │
└───────────────────────┬────────────────────────┘
                        │
                ┌───────▼───────┐
                │ Физическая сеть│
                └───────────────┘
```

### Живая миграция (Live Migration) в 2026 году

Долгое время использование SR-IOV блокировало живую миграцию ВМ. В 2026 году эта проблема решена через гибридные механизмы:

1.  **Net_Failover (Bonding)**: ВМ видит один логический интерфейс, состоящий из «быстрой» ноги (SR-IOV VF) и «мобильной» ноги (VirtIO). При миграции трафик прозрачно переключается на VirtIO, а после завершения переезда — обратно на новый VF.
2.  **vDPA**: Позволяет абстрагировать аппаратную часть. Состояние очередей данных унифицировано, что дает возможность переносить ВМ между хостами с картами разных вендоров (например, NVIDIA → Intel) без потери соединения.
3.  **Hardware Dirty Page Tracking**: Современные NIC аппаратно отслеживают изменения в памяти, внесенные через DMA, что позволяет мигрировать даже высоконагруженные ИИ-узлы с минимальным временем простоя (Downtime < 500ms).

### Практические сценарии

#### ИИ-инфраструктуры (AI Fabric)
В 2026 году SR-IOV является обязательным компонентом ИИ-кластеров:
- **GPUDirect RDMA**: Использование VF сетевой карты для прямой передачи данных между памятью разных GPU (минуя CPU) через PCIe Gen6.
- **Lossless Ethernet**: Настройка приоритетов (PFC) на уровне VF для обеспечения работы без потерь пакетов, что критично для обучения LLM.

#### Облачные вычисления (Public/Private Clouds)
- **Мультитенантность**: Изоляция трафика разных клиентов на аппаратном уровне (PCIe-изоляция).
- **Телеком (NFV/5G)**: Использование SR-IOV в сочетании с DPDK для работы виртуальных функций сети (UPF, vRAN).

### Сравнение DPDK и SR-IOV (Состояние на 2026)

| Критерий | DPDK | SR-IOV |
| :--- | :--- | :--- |
| **Уровень** | Программный (Userspace) | Аппаратный (PCIe) |
| **Основной плюс** | Максимальная гибкость логики | Минимальная нагрузка на CPU |
| **Живая миграция** | Поддерживается (через vhost-user) | Поддерживается (через vDPA/Failover) |
| **Требования** | Любая NIC (с поддержкой PMD) | NIC с поддержкой SR-IOV |
| **Сложность** | Требует разработки приложения | Требует настройки инфраструктуры |
