# Обзор SR-IOV (Single Root I/O Virtualization)

### Определения

- **SR-IOV (Single Root I/O Virtualization)**: Спецификация интерфейса PCIe, разработанная PCI-SIG, которая позволяет одному физическому устройству (Physical Function, PF) представляться системе как несколько независимых виртуальных устройств (Virtual Functions, VF).
- **Physical Function (PF)**: Полнофункциональная PCI-функция, которая поддерживает спецификацию SR-IOV. PF обладает полным доступом к ресурсам устройства и используется для настройки, управления и создания виртуальных функций.
- **Virtual Function (VF)**: «Облегченная» PCI-функция, предназначенная исключительно для передачи данных. VF имеет собственный набор ресурсов (очереди, BAR-регистры), но зависит от PF в плане глобальной конфигурации.
- **IOMMU (Input-Output Memory Management Unit)**: Аппаратный блок (VT-d у Intel, AMD-Vi у AMD), который транслирует адреса ввода-вывода (IOVA) в физические адреса памяти (HPA). Необходим для безопасной изоляции памяти VF.
- **vDPA (vHost Data Path Acceleration)**: Гибридная технология, которая сохраняет стандартную плоскость управления VirtIO (для совместимости с гостевыми ОС), но ускоряет плоскость передачи данных за счет прямого взаимодействия с оборудованием (SR-IOV NIC).
- **PCIe Gen6**: Стандарт шины 2026 года со скоростью до 64 GT/s на линию, использующий модуляцию PAM4. Обеспечивает пропускную способность, критически важную для 800G-сетей и ИИ-фабрик.

---

### Архитектура и основные принципы

#### Проблема программной виртуализации
В стандартных схемах виртуализации (например, с использованием мостов Linux или Open vSwitch в режиме ядра) каждый пакет проходит через стек гипервизора:
1. Пакет поступает на NIC.
2. Генерируется прерывание процессора.
3. Гипервизор копирует пакет из памяти NIC в память ВМ.
4. Выполняется переключение контекста.
Это приводит к высокой нагрузке на CPU, нестабильным задержкам (jitter) и ограничению пропускной способности.

#### Аппаратное разделение ресурсов
SR-IOV переносит логику коммутации пакетов непосредственно на чип сетевого адаптера.

1.  **Встроенный L2-коммутатор (NIC Switch)**: Выполняет аппаратную фильтрацию и классификацию пакетов по MAC-адресам или VLAN-тегам.
2.  **Прямой доступ к памяти (DMA)**: Каждая VF взаимодействует напрямую с памятью виртуальной машины, минуя процессор хоста.
3.  **Изоляция через BAR**: Каждая VF имеет свои регистры Base Address Register (BAR), что позволяет ОС/гипервизору назначать их конкретным ВМ как отдельные PCI-устройства.

### Безопасность и изоляция

Использование SR-IOV требует строгих мер контроля, так как VF делят общие физические ресурсы:

- **Изоляция памяти**: Обеспечивается через IOMMU. ВМ не может получить доступ к памяти хоста или других ВМ через свою VF.
- **Защита от MAC/VLAN Spoofing**: PF может принудительно устанавливать MAC-адреса и VLAN-теги для VF, запрещая гостевой ОС изменять их.
- **Rate Limiting (QoS)**: Аппаратное ограничение полосы пропускания (Egress/Ingress) на уровне каждой VF для предотвращения влияния шумных соседей (Noisy Neighbors).
- **PCIe Error Handling**: Механизм AER (Advanced Error Reporting) позволяет изолировать сбои в одной VF, не затрагивая работу PF и других VF.

---

### Живая миграция (Live Migration) в 2026 году

Современные механизмы позволяют мигрировать ВМ с проброшенными VF без разрыва соединений:

1.  **Net_Failover (Bonding)**: Использование «пары» из SR-IOV VF (основной) и VirtIO (резервный). Перед миграцией трафик переносится на VirtIO, а после — на новую VF на целевом хосте.
2.  **vDPA State Transfer**: Унификация состояния очередей данных позволяет переносить контекст выполнения сетевого адаптера между разными поколениями и вендорами оборудования.
3.  **Hardware Dirty Page Tracking**: Аппаратная поддержка отслеживания «грязных» страниц памяти при DMA-операциях сводит время простоя (Downtime) к значениям менее 500 мс даже для 800G-интерфейсов.

### Практические сценарии

- **ИИ-инфраструктуры (AI Fabric)**: Использование **GPUDirect RDMA** через VF для связи памяти GPU разных узлов, минуя CPU и системную память.
- **Телеком (NFV/5G/6G)**: База для работы виртуализированных функций сети (UPF, vCU/vDU), где требуется обработка трафика в реальном времени с минимальными задержками.
- **Публичные облака**: Предоставление Bare-metal производительности в виртуальной среде с обеспечением жесткой изоляции клиентов.

### Сравнение DPDK и SR-IOV (2026)

| Характеристика | DPDK | SR-IOV |
| :--- | :--- | :--- |
| **Реализация** | Программная (Userspace) | Аппаратная (PCIe) |
| **Гибкость** | Максимальная (любая логика на C/Rust) | Ограничена возможностями NIC |
| **Нагрузка на CPU** | Постоянная (Polling mode) | Минимальная (Direct DMA) |
| **Задержки** | Очень низкие (стабильные) | Минимально возможные (аппаратные) |
| **Совместимость** | Требует поддержки в приложении | Требует поддержки в ОС/Гипервизоре |

### Диагностика и устранение неисправностей

1.  **Проверка поддержки IOMMU**:
    ```bash
    dmesg | grep -e DMAR -e IOMMU
    # → "DMAR: IOMMU enabled"
    ```
2.  **Список виртуальных функций**:
    ```bash
    lspci | grep -i "Virtual Function"
    ```
3.  **Проверка состояния через sysfs**:
    ```bash
    cat /sys/class/net/<interface>/device/sriov_numvfs
    ```
4.  **Типичная проблема: Нехватка ресурсов PCIe BAR**: Если система не может инициализировать VF, проверьте параметр ядра `pci=realloc`.
