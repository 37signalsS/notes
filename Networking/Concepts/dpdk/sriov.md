# SR-IOV (Single Root I/O Virtualization)

## Проблема виртуализации сети

```
┌─────────────────────────────────────────────────────────────┐
│                    VM 1                                     │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                 virtio-net                          │    │
│  └─────────────────────┬───────────────────────────────┘    │
└────────────────────────┼────────────────────────────────────┘
                         │ Переключение контекста
┌────────────────────────┼────────────────────────────────────┐
│  HYPERVISOR (KVM)      │                                    │
│  ┌─────────────────────▼───────────────────────────────┐    │
│  │              vSwitch (OVS/linux bridge)             │    │
│  └─────────────────────┬───────────────────────────────┘    │
└────────────────────────┼────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│              ФИЗИЧЕСКИЙ NIC                                 │
└─────────────────────────────────────────────────────────────┘

Накладные расходы: 
- Переключение VM → Hypervisor
- Обработка в vSwitch
- Копирование данных
```

## SR-IOV Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                    VM 1                                     │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                 VF Driver                           │    │
│  └─────────────────────┬───────────────────────────────┘    │
└────────────────────────┼────────────────────────────────────┘
                         │ Прямой доступ к VF (PCI passthrough)
┌────────────────────────┼────────────────────────────────────┐
│  HYPERVISOR (KVM)      │                                    │
│                        │ VF - Virtual Function              │
└────────────────────────┼────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│              ФИЗИЧЕСКИЙ NIC с SR-IOV                         │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  PF (Physical Function) - управление                │    │
│  │  ┌─────┬─────┬─────┬─────┐                          │    │
│  │  │ VF0 │ VF1 │ VF2 │ VF3 │  Virtual Functions       │    │
│  │  └─────┴─────┴─────┴─────┘                          │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘

Результат: VM напрямую работает с виртуальным NIC!
```

## VF (Virtual Functions) и PF (Physical Function)

**Physical Function (PF):**
- Полнофункциональный PCIe-функция
- Доступен хосту (hypervisor)
- Управление конфигурацией SR-IOV
- Может создавать VF

**Virtual Function (VF):**
- "Облегченный" PCIe-функция
- Только для передачи данных
- Назначается ВМ напрямую (PCI passthrough)
- Каждая ВМ видит VF как отдельный NIC
