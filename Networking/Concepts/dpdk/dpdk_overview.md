# Обзор DPDK (Data Plane Development Kit)

### Определения

- **DPDK (Data Plane Development Kit)**: Набор библиотек и драйверов пространства пользователя (userspace) для высокопроизводительной обработки сетевых пакетов. Позволяет обходить сетевой стек ядра ОС (Kernel Bypass), предоставляя приложению прямой доступ к сетевому адаптеру (NIC).
- **Kernel Bypass (Обход ядра)**: Технология, позволяющая приложению обрабатывать данные напрямую из оборудования, исключая накладные расходы на системные вызовы, копирование данных между ядром и пользователем, а также обработку прерываний.
- **Poll Mode Driver (PMD)**: Драйвер, работающий в режиме непрерывного опроса сетевой карты на предмет новых пакетов. Устраняет задержки, связанные с механизмом прерываний.
- **HugePages (Большие страницы)**: Механизм управления памятью, использующий страницы размером 2 МБ или 1 ГБ (вместо стандартных 4 КБ) для минимизации промахов в TLB-кеше процессора.

### Основные концепции

#### Проблема стандартного сетевого стека
Традиционная обработка пакетов в ядре Linux (через сокеты) сталкивается с «бутылочным горлышком» на скоростях выше 10 Гбит/с:
- **Переключения контекста**: Каждый пакет инициирует прерывание и системный вызов, что нагружает CPU.
- **Копирование данных**: Пакеты копируются из памяти ядра в память приложения.
- **Блокировки (Locks)**: Сетевой стек ядра использует блокировки для синхронизации, что ограничивает масштабируемость на многоядерных системах.

#### Архитектура DPDK
DPDK переносит обработку пакетов полностью в **Userspace**, используя следующие механизмы:
1. **EAL (Environment Abstraction Layer)**: Инициализирует ресурсы (память, ядра CPU, PCI-устройства) и предоставляет единый API для различных архитектур.
2. **Нулевое копирование (Zero-copy)**: Пакеты передаются приложению через общую память (DMA) без промежуточного копирования.
3. **Lockless Queues**: Использование бесблокировочных очередей (Ring Buffers) для высокоскоростного обмена данными между ядрами.
4. **HugePages**: Снижает нагрузку на блок MMU процессора, что критично для обработки миллионов пакетов в секунду (Mpps).

#### Сравнение DPDK и XDP (eBPF) — Состояние на 2026 год
В современных архитектурах часто выбирают между DPDK и XDP:

| Критерий | DPDK (25.11 LTS) | XDP / AF_XDP |
| :--- | :--- | :--- |
| **Производительность** | Максимальная (до 800G и выше) | Высокая (~85-90% от DPDK) |
| **Задержка (Latency)** | Детерминированная (< 2-5 µs) | Низкая (~5-15 µs) |
| **Интеграция** | Приложение «владеет» NIC | Сосуществует с ядром Linux |
| **Сложность** | Высокая (требует спец. драйверов) | Средняя (стандартные инструменты) |
| **CPU** | 100% загрузка ядра (Polling) | Адаптивная (Interrupt/NAPI) |

*Выбор:* DPDK остается золотым стандартом для сверхвысоких нагрузок (800G+) и HFT, в то время как XDP предпочтителен для облачных сред и стандартных K8s-кластеров.

### Технические характеристики (Актуально для 2026)

- **Версия**: DPDK 25.11 LTS (поддержка до конца 2028 года).
- **Производительность**: До 40+ Mpps на одно ядро CPU; поддержка линков 400G/800G и PCIe Gen6.
- **Требования к оборудованию**:
    - **CPU**: Архитектуры x86_64 (Xeon 6, EPYC 5th Gen), ARM Neoverse (v3+), RISC-V.
    - **NIC**: Поддержка PMD (NVIDIA ConnectX-7/8, Intel E810, Broadcom Thor2).
    - **Память**: Рекомендуется выделение 1 ГБ HugePages для высокоскоростных интерфейсов.

### Практические сценарии

DPDK является фундаментом для высокопроизводительных решений:
1. **OVS-DPDK**: Ускорение виртуальных коммутаторов Open vSwitch для облачных платформ (OpenStack).
2. **VPP (Vector Packet Processing)**: Программный маршрутизатор со скоростью обработки терабитных потоков.
3. **5G Core (UPF)**: Реализация функций обработки трафика в мобильных сетях.
4. **HFT (High-Frequency Trading)**: Системы, где каждая микросекунда задержки имеет значение.
