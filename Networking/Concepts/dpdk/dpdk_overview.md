# Обзор DPDK (Data Plane Development Kit)

### Определения

- **DPDK (Data Plane Development Kit)**: Набор библиотек и драйверов пространства пользователя (userspace), предназначенный для высокопроизводительной обработки сетевых пакетов. Основная цель — обеспечить обход сетевого стека ядра (Kernel Bypass) для минимизации задержек и максимизации пропускной способности.
- **Kernel Bypass (Обход ядра)**: Архитектурный подход, при котором сетевой трафик передается напрямую из сетевого адаптера (NIC) в приложение в userspace, минуя обработку в ядре ОС.
- **Poll Mode Driver (PMD)**: Драйвер, работающий в режиме опроса (polling) вместо прерываний. Ядро CPU постоянно проверяет регистры NIC на наличие новых данных, что исключает накладные расходы на переключение контекста и обработку аппаратных прерываний.
- **EAL (Environment Abstraction Layer)**: Слой абстракции окружения, который инициализирует низкоуровневые ресурсы (память, ядра CPU, PCI-устройства) и предоставляет единый интерфейс для приложения.

---

### Архитектура и ключевые компоненты

В 2026 году DPDK 25.11 LTS является фундаментом для всех высокопроизводительных сетевых решений. Его архитектура строится на нескольких базовых библиотеках (`librte_*`):

1.  **Инфраструктурные библиотеки**:
    - **librte_eal**: Сердце DPDK. Управляет выделением огромных страниц памяти (HugePages), привязкой к ядрам (CPU pinning) и доступом к шине PCI.
    - **librte_mempool**: Высокопроизводительный аллокатор объектов (пакетов). Использует локальные кэши на каждом ядре для исключения блокировок (lockless).
    - **librte_mbuf**: Описание структуры пакета. Поддерживает метаданные для аппаратной разгрузки (offloading).
2.  **Коммуникационные библиотеки**:
    - **librte_ring**: Реализация бесблокировочных очередей «один-ко-многим» или «многие-ко-многим», обеспечивающая сверхбыструю передачу данных между потоками.
    - **librte_ethdev**: Унифицированный интерфейс для взаимодействия с различными физическими и виртуальными сетевыми картами.

#### Аппаратная разгрузка (Hardware Offloading)
DPDK активно использует возможности современных NIC (ConnectX-8, Intel E810) для снижения нагрузки на CPU:
- **RSS (Receive Side Scaling)**: Аппаратное распределение входящего трафика по разным очередям (и ядрам CPU) на основе хэша заголовков (L3/L4).
- **Flow Director / Generic Flow API (`rte_flow`)**: Возможность программировать правила фильтрации и классификации пакетов непосредственно в железе NIC.
- **Checksum Offload**: Вычисление контрольных сумм IP/TCP/UDP силами сетевого адаптера.

### Основные концепции обработки данных

#### Проблема стандартного стека Linux
Стандартный путь пакета через ядро (`net_dev → softirq → tcp/ip stack → socket`) не позволяет достичь скоростей 100G+ из-за:
- **Копирования данных**: Минимум два копирования между буферами NIC, ядра и пользователя.
- **Переключений контекста**: Системные вызовы и прерывания «съедают» циклы процессора.
- **Блокировок**: Глобальные блокировки в сетевом стеке ограничивают масштабируемость на многопроцессорных системах.

#### Решение через DPDK (Polling + Zero-copy)
DPDK устраняет эти проблемы:
1.  **Polling (Опрос)**: Вместо ожидания прерывания, CPU «владеет» очередью NIC и забирает пакеты максимально быстро.
2.  **Zero-copy (Нулевое копирование)**: Благодаря HugePages и DMA, сетевая карта пишет пакеты напрямую в память, к которой у приложения есть прямой доступ.
3.  **Lockless design**: Весь путь пакета внутри DPDK-приложения спроектирован без использования мьютексов и семафоров.

### Сравнение DPDK и XDP (2026)

| Характеристика | DPDK (25.11 LTS) | XDP (Express Data Path) |
| :--- | :--- | :--- |
| **Место выполнения** | Пространство пользователя | Драйвер ядра (eBPF) |
| **Управление NIC** | Монопольное (Kernel bypass) | Совместное с ОС |
| **Производительность** | Экстремальная (400G/800G) | Очень высокая (100G/200G) |
| **Загрузка CPU** | 100% (Polling mode) | Адаптивная (по прерываниям) |
| **Сложность разработки** | Высокая | Средняя |

### Практические сценарии

- **Телеком (5G Core / UPF)**: Обработка абонентского трафика на скоростях терабитного уровня.
- **Облачные виртуальные сети**: Ускорение [Open vSwitch (OVS-DPDK)](../../ServicesAndTools/open_vswitch.md).
- **Высокочастотный трейдинг (HFT)**: Минимизация задержек до уровня единиц микросекунд.
- **Кибербезопасность**: Сверхбыстрые IDS/IPS и файрволы, анализирующие трафик «на лету» без потерь.
