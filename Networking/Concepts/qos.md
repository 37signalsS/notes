# QoS (Quality of Service)

## Определения

**QoS (Quality of Service)** — набор технологий для управления сетевым трафиком, позволяющий предоставлять различным типам данных разные приоритеты и гарантии обслуживания.

Ключевые параметры, на которые влияет QoS:
- **Bandwidth (Пропускная способность):** объем данных, передаваемый в единицу времени.
- **Latency (Задержка):** время прохождения пакета от отправителя к получателю.
- **Jitter (Джиттер):** колебание задержки во времени.
- **Packet Loss (Потеря пакетов):** процент пакетов, не достигших цели.

## Модели и архитектуры QoS

Существует три основные модели реализации качества обслуживания в сетях:

1. **Best Effort (Максимальные усилия):** модель по умолчанию. Сеть обрабатывает все пакеты одинаково, не давая никаких гарантий.
2. **IntServ (Integrated Services):** резервирование ресурсов «сквозным» методом от отправителя до получателя для каждого потока данных. Использует протокол **RSVP** (Resource Reservation Protocol). Масштабируемость низкая, так как роутеры должны хранить состояние каждого потока.
3. **DiffServ (Differentiated Services):** современный стандарт. Трафик классифицируется на границе сети, маркируется, и промежуточные узлы обрабатывают его на основе меток (Per-Hop Behavior, PHB). Высокая масштабируемость.

## Основные механизмы

| Механизм | Описание |
| :--- | :--- |
| **Приоритизация** | Критичный трафик (VoIP, видео) получает высший приоритет в очередях |
| **Гарантия полосы** | Резервирование части канала для конкретных приложений или подсетей |
| **Классификация** | Процесс идентификации трафика по портам, IP или данным L7 |
| **Маркировка** | Установка меток в заголовки пакетов (DSCP на L3, PCP на L2) |
| **Управление очередями** | Алгоритмы планирования (Queuing) обработки пакетов (FIFO, WFQ, HTB) |
| **Congestion Avoidance** | Предотвращение перегрузок путем раннего отбрасывания пакетов (WRED) |

## Классификация и маркировка

Для того чтобы сетевые устройства понимали, как обрабатывать пакет, он должен быть промаркирован.

### Уровень L2 (Data Link)
Используется поле **PCP (Priority Code Point)** в теге 802.1Q (VLAN). Поле состоит из 3 бит (значения 0–7):
- **0 (Best Effort):** стандартный трафик.
- **5 (Voice):** рекомендуемый приоритет для голоса.
- **7 (Control):** критический сетевой трафик.

### Уровень L3 (Network)
Используется поле **DSCP (Differentiated Services Code Point)** в заголовке IPv4/IPv6 (6 бит). Основные классы:
- **BE (Best Effort / CS0):** значение 0.
- **EF (Expedited Forwarding):** значение 46. Используется для трафика, чувствительного к задержкам (VoIP). Минимальные очереди.
- **AF (Assured Forwarding):** классы AF1x, AF2x, AF3x, AF4x. Гарантируют доставку при соблюдении лимитов.
- **CS (Class Selector):** совместимость со старым стандартом IP Precedence.

## Управление скоростью: Policing и Shaping

| Характеристика | Policing (Ограничение) | Shaping (Сглаживание) |
| :--- | :--- | :--- |
| **Действие** | Мгновенно отбрасывает (drop) избыток | Задерживает в буфере (delay) |
| **Влияние на задержку** | Не вносит задержек | Увеличивает задержку (буферизация) |
| **Применение** | Входящий трафик (Ingress) | Исходящий трафик (Egress) |
| **Результат** | «Зубчатый» график скорости | «Плавный» график скорости |

## Борьба с Bufferbloat и современные алгоритмы

**Bufferbloat (Раздувание буферов)** — проблема, при которой избыточная буферизация на промежуточных узлах (например, модем провайдера) приводит к огромным задержкам при полной загрузке канала.

Для решения проблемы используются алгоритмы **SQM (Smart Queue Management)**:

- **fq_codel (Flow Queue CoDel):** «золотой стандарт» для Linux. Разделяет трафик на потоки и использует алгоритм CoDel для отбрасывания пакетов из «застоявшихся» очередей.
- **CAKE (Common Applications Kept Enhanced):** наиболее современный и комплексный алгоритм (MikroTik v7, OpenWrt). Включает в себя шейпинг, фильтрацию ACK-пакетов (ускоряет асимметричные каналы) и изоляцию по хостам.
- **L4S (Low Latency, Low Loss, Scalable):** новый стандарт (2024–2025), позволяющий приложениям и сети взаимодействовать через ECN для поддержания ультранизких задержек.

## Практические сценарии

### Реализация в Linux (tc)

Утилита `tc` (traffic control) управляет очередями через дисциплины **qdisc**.

```bash
# Установка алгоритма fq_codel на интерфейс eth0
sudo tc qdisc add dev eth0 root fq_codel
```

Подробнее: [tc — управление трафиком](../../Linux/Networking/Tools/iproute2/tc.md).

### Реализация в MikroTik (RouterOS)

#### Simple Queue (Простая очередь)
Используется для быстрого ограничения скорости конкретных IP или интерфейсов.

```bash
# Ограничение IP 192.168.88.50 до 10 Мбит/с
/queue simple add name="Limit-IP-50" target=192.168.88.50/32 max-limit=10M/10M
```

#### PCQ (Per Connection Queue)
Автоматическое «справедливое» распределение полосы между всеми пользователями подсети.

```bash
# Настройка PCQ для равномерного распределения
/queue type add name=PCQ_down kind=pcq pcq-classifier=dst-address pcq-rate=5M
/queue simple add name="Fair-Share" target=192.168.88.0/24 queue=PCQ_down
```
