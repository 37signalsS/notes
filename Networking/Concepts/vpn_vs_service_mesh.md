# Сравнение VPN и Service Mesh

## Определения

Для обеспечения безопасности и управляемости современных распределенных систем используются два фундаментально разных подхода к организации сетевого взаимодействия:

*   **VPN (Virtual Private Network — виртуальная частная сеть):** Технология создания защищенного зашифрованного туннеля на сетевом или транспортном уровнях (L3/L4) модели OSI (Open Systems Interconnection). Основная задача — безопасное объединение удаленных узлов или сетей через публичный интернет. Фокусируется на трафике **North-South** (входящий/исходящий трафик периметра).
*   **Service Mesh (Сетка сервисов):** Выделенный инфраструктурный слой на прикладном уровне (L7) для управления взаимодействием между микросервисами. Реализуется через распределенные прокси-серверы (Sidecars) или компоненты ядра (eBPF). Фокусируется на трафике **East-West** (взаимодействие внутри кластера или дата-центра).

Оба инструмента являются критическими компонентами архитектуры **[Zero Trust (Нулевое доверие)](./zero_trust_overview.md)**, но работают на разных уровнях абстракции.

## Основные концепции

### Сравнительный анализ характеристик

| Критерий | VPN | Service Mesh |
| :--- | :--- | :--- |
| **Уровень OSI** | L3 (Сетевой) / L4 (Транспортный) | L7 (Прикладной) |
| **Технологии** | [IPsec](../Tunnels/ipsec/ipsec.md), [WireGuard](../../Vpn/wireguard.md), OpenVPN | Envoy, Istio, Linkerd, Cilium (eBPF) |
| **Идентификация** | IP-адреса, сертификаты устройств | Идентичность сервиса (SPIFFE/SVID), Service Accounts |
| **Шифрование** | Весь трафик внутри туннеля | mTLS (mutual Transport Layer Security) между сервисами |
| **Политики доступа** | ACL (Access Control List) по IP и портам | Контекстные правила (HTTP методы, пути, заголовки) |
| **Наблюдаемость** | Базовая (объем трафика, статус порта) | Глубокая (трассировка запросов, RPS, ошибки L7) |
| **Масштабируемость** | Ограничена мощностью VPN-шлюза | Высокая (распределенная обработка) |

### North-South против East-West
*   **North-South (Север-Юг):** Трафик, пересекающий границу доверенной сети. VPN обеспечивает безопасный вход в периметр для удаленных сотрудников или интеграцию офисов (Site-to-Site).
*   **East-West (Восток-Запад):** Трафик между компонентами внутри периметра. Service Mesh управляет лавинообразным ростом внутренних связей в микросервисной архитектуре, обеспечивая их защиту и контроль без необходимости настройки сотен правил файрвола.

### Современные тренды: Ambient Mesh
Традиционный Service Mesh использует Sidecar-контейнеры (Envoy) рядом с каждым приложением. Современные реализации (например, **Istio Ambient Mesh**) разделяют функции:
1.  **Ztunnel (Zero Trust Tunnel):** Легковесный прокси на уровне узла для обеспечения mTLS (L4).
2.  **Waypoint Proxy:** Отдельный инстанс для сложной L7-обработки (маршрутизация, политики) только там, где это необходимо.
Это сближает производительность Service Mesh с VPN, сохраняя гибкость L7.

## Практические сценарии

### Гибридная архитектура
Типовой паттерн современной инфраструктуры:
1.  **VPN (WireGuard/IPsec):** Создает защищенный канал между локальным офисом (On-premise) и облачным провайдером.
2.  **API Gateway:** Обрабатывает входящие запросы от внешних пользователей, выполняя аутентификацию и ограничение скорости (Rate Limiting).
3.  **Service Mesh:** Принимает запрос внутри облачного кластера и управляет его прохождением между микросервисами, обеспечивая шифрование и наблюдаемость.

### Пример политики безопасности (Istio AuthorizationPolicy)
В отличие от VPN, где доступ разрешается к IP-адресу, здесь доступ разрешается конкретной идентичности сервиса:

```yaml
apiVersion: security.istio.io/v1beta1
kind: AuthorizationPolicy
metadata:
  name: payment-access
spec:
  selector:
    matchLabels:
      app: payment-service
  action: ALLOW
  rules:
  - from:
    - source:
        principals: ["cluster.local/ns/orders/sa/orders-backend"]
    to:
    - operation:
        methods: ["POST"]
        paths: ["/v1/charge"]
```
