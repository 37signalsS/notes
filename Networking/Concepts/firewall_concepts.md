# Концепции сетевых файрволов

### Определения

- **Файрвол (Межсетевой экран)**: Система сетевой безопасности, которая контролирует входящий и исходящий трафик на основе набора правил. Он действует как барьер между доверенной и недоверенной сетями.
- **Фильтрация пакетов**: Основной механизм, при котором анализируются заголовки пакетов (L3/L4) для принятия решения о их дальнейшей судьбе (пропустить, отбросить).
- **Netfilter**: Фреймворк в ядре Linux, который позволяет перехватывать и манипулировать сетевыми пакетами. Утилиты, такие как `iptables` и `nftables`, являются пользовательскими интерфейсами к Netfilter.

---

### Основные концепции

#### Таблицы и Цепочки Netfilter

Netfilter организует правила в **таблицы** (по назначению) и **цепочки** (по точке перехвата).

- **Ключевые таблицы**:
  - `filter`: Основная таблица для фильтрации (`ACCEPT`, `DROP`, `REJECT`).
  - `nat`: Для преобразования сетевых адресов (NAT).
  - `mangle`: Для модификации заголовков пакетов (например, QoS).

- **Основные цепочки в таблице `filter`**:
  - `INPUT`: Для пакетов, предназначенных для процессов на самом сервере. **Основная точка защиты сервера.**
  - `OUTPUT`: Для пакетов, сгенерированных локальными процессами.
  - `FORWARD`: Для пакетов, проходящих через сервер транзитом.

#### Stateless vs Stateful фильтрация

Это два фундаментально разных подхода к анализу трафика.

| Критерий | Stateless (Без отслеживания состояния) | Stateful (С отслеживанием состояния) |
| :--- | :--- | :--- |
| **Принцип** | Каждый пакет анализируется изолированно, без учета предыдущих. | Отслеживает состояние TCP-соединений в таблице (`conntrack`). |
| **Пример правила** | `Разрешить пакеты на порт 80` И `Разрешить пакеты с порта 80`. | `Разрешить новые соединения на порт 80` И `Разрешить уже установленный трафик`. |
| **Производительность** | Максимальная, низкое потребление памяти. | Немного ниже, требует память для таблицы состояний. |
| **Безопасность** | Ниже. Требует более сложных и менее надежных правил. | **Выше**. Автоматически обрабатывает ответный трафик и защищает от атак. |
| **Состояния** | - | `NEW`, `ESTABLISHED`, `RELATED`, `INVALID`. |

**Stateful-фильтрация** является стандартом для современных файрволов, так как она значительно надежнее и упрощает написание правил.

#### Уровни фильтрации

- **L3/L4 (Сетевой/Транспортный)**: Фильтрация по IP-адресам, портам (TCP/UDP) и протоколам (ICMP). Это базовая функция любого файрвола.
- **L7 (Прикладной)**: Анализ содержимого самих протоколов (например, HTTP, DNS, SQL). Такие файрволы называются **Next-Generation Firewalls (NGFW)** или **Web Application Firewalls (WAF)**. Они способны обнаруживать угрозы, которые не видны на уровне L3/L4.

### Практические сценарии

#### Инструменты управления файрволом в Linux

Ниже приведены примеры синтаксиса для различных утилит, реализующих одно и то же простое правило: разрешить входящий трафик на порт 22 (SSH).

- **iptables** (классический инструмент):

    ```bash
    iptables -A INPUT -p tcp --dport 22 -j ACCEPT
    ```

- **nftables** (современная замена iptables):

    ```bash
    nft add rule inet filter input tcp dport 22 accept
    ```

- **ufw** (упрощенный интерфейс для `iptables`):

    ```bash
    ufw allow 22/tcp
    ```

- **firewalld** (динамический файрвол с концепцией зон):

    ```bash
    firewall-cmd --zone=public --add-service=ssh --permanent
    firewall-cmd --reload
    ```
