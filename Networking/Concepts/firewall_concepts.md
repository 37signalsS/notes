# Межсетевые экраны (Firewalls): Концепции и механизмы

## Определение

**Межсетевой экран (Firewall, Файрвол)** — это программный или программно-аппаратный комплекс, контролирующий прохождение сетевого трафика между различными сегментами сети на основе заданных правил безопасности. Его основная задача — изоляция доверенной сети (например, внутренней сети компании) от недоверенной (интернет) и предотвращение несанкционированного доступа.

## Основные концепции

### Механизмы фильтрации

#### 1. Фильтрация пакетов (Packet Filtering)
Базовый механизм, работающий на уровнях L3 (сетевой) и L4 (транспортный) модели OSI.
*   **Принцип:** Анализ заголовков каждого пакета в отдельности. Проверяются IP-адреса, протоколы (TCP, UDP, ICMP) и порты.
*   **Действия (Actions):**
    *   `ACCEPT`: Пропустить пакет.
    *   `DROP`: Молча отбросить (клиент ждет по таймауту).
    *   `REJECT`: Отклонить с отправкой уведомления (ICMP Unreachable).
    *   `LOG`: Записать в журнал.

#### 2. Контроль состояния (Stateful Inspection)
В отличие от простой фильтрации, файрвол отслеживает состояние активных соединений.
*   **Как это работает:** Файрвол хранит таблицу состояний (Connection Tracking — `conntrack`). Он знает, является ли пакет частью уже установленного сеанса (`ESTABLISHED`) или ответом на запрос (`RELATED`).
*   **Преимущество:** Позволяет автоматически пропускать обратный трафик для разрешенных исходящих соединений, не создавая для него отдельных правил.

#### 3. Глубокая инспекция пакетов (DPI — Deep Packet Inspection)
Анализ не только заголовков, но и содержимого (Payload) пакетов на прикладном уровне (L7).
*   **Назначение:** Обнаружение вирусов, спама, попыток эксплуатации уязвимостей или блокировка конкретных функций приложений (например, запрет передачи файлов внутри мессенджера).

### Поколения межсетевых экранов

*   **Традиционные файрволы (L3/L4):** Ограничиваются фильтрацией по IP и портам.
*   **Next-Generation Firewalls (NGFW):** Интегрируют классический файрвол с функциями DPI, систем предотвращения вторжений (IPS) и контроля приложений. Они понимают контекст (кто пользователь, какое приложение используется) и обеспечивают защиту на уровне L7.
*   **Web Application Firewalls (WAF):** Специализированные экраны для защиты веб-приложений. См. подробнее: **[WAF: Web Application Firewall](../../Security/ApplicationSecurity/waf.md)**.

### Системы обнаружения и предотвращения вторжений (IDS/IPS)

Часто интегрируются в межсетевые экраны для усиления защиты:
*   **IDS (Intrusion Detection System):** Анализирует копию трафика и сигнализирует о подозрительной активности (пассивный режим).
*   **IPS (Intrusion Prevention System):** Находится непосредственно на пути трафика (inline) и может блокировать вредоносные пакеты в реальном времени.

## Современные технологии фильтрации

### Высокопроизводительная фильтрация: eBPF и XDP

В современных высоконагруженных системах (и облачных инфраструктурах) классические механизмы ядра могут стать «бутылочным горлышком».

*   **XDP (eXpress Data Path):** Позволяет запускать eBPF-программы фильтрации непосредственно в драйвере сетевой карты, до того как пакет попадет в стек ядра Linux. Это обеспечивает экстремально высокую скорость (десятки миллионов пакетов в секунду), что критично для защиты от DDoS-атак.
*   **eBPF (Extended Berkeley Packet Filter):** Позволяет динамически внедрять логику проверки трафика в ядро без его перекомпиляции. Широко используется в Kubernetes (например, в Cilium) для реализации сетевых политик.

## Реализация в Linux (Netfilter)

Ядро Linux использует фреймворк **Netfilter** для управления пакетами.

*   **Цепочки (Chains):**
    *   `INPUT`: Для входящего трафика к самому хосту.
    *   `OUTPUT`: Для исходящего трафика от хоста.
    *   `FORWARD`: Для трафика, проходящего через хост (маршрутизация).
*   **Таблицы:**
    *   `filter`: Для правил фильтрации.
    *   `nat`: Для трансляции адресов.
    *   `mangle`: Для модификации заголовков (QoS, TTL).
