# Основы работы межсетевых экранов

## Определения

**Файрвол (межсетевой экран)** — система сетевой безопасности, контролирующая входящий и исходящий трафик на основе набора правил. Выполняет роль барьера между доверенной и недоверенной сетями.

**Фильтрация пакетов** — базовый механизм сетевой безопасности, работающий на уровнях L3 (сетевой) и L4 (транспортный) модели OSI (Open Systems Interconnection).

**Как это работает:**

1. **Перехват**: Каждый пакет, проходящий через сетевой интерфейс, перехватывается ядром (в Linux — через Netfilter).
2. **Анализ заголовков**: Из пакета извлекаются метаданные: IP (Internet Protocol)-адреса отправителя и получателя, тип протокола (TCP (Transmission Control Protocol), UDP (User Datagram Protocol), ICMP (Internet Control Message Protocol)), порты источника и назначения. Содержимое данных (Payload) на этом этапе игнорируется.
3. **Сравнение с правилами**: Эти данные последовательно сравниваются с таблицей правил (Rule Base). Правила обычно проверяются сверху вниз до первого совпадения.
4. **Принятие решения (Action)**:

- `ACCEPT`: Пропустить пакет дальше.
- `DROP`: Молча отбросить пакет (отправитель не получит уведомления, соединение "зависнет" по таймауту).
- `REJECT`: Отклонить пакет и отправить уведомление об ошибке (например, ICMP Port Unreachable).
- `LOG`: Записать информацию о пакете в системный журнал и перейти к следующему правилу.

**Особенности**:

- **Скорость**: Это очень быстрый процесс, требующий минимальных ресурсов CPU (Central Processing Unit).
- **Отсутствие контекста (Stateless)**: В чистом виде фильтрация пакетов не знает о предыдущих пакетах — она не видит разницы между первым пакетом нового соединения и ответом на уже существующее. Для решения этой проблемы применяется *Stateful-фильтрация* (см. ниже).

**Netfilter** — фреймворк ядра Linux для перехвата и манипуляции сетевыми пакетами. Утилиты `iptables` и `nftables` — пользовательские интерфейсы к Netfilter.

## Основные концепции

### Netfilter: таблицы и цепочки

Netfilter организует правила в **таблицы** (по назначению) и **цепочки** (по точке перехвата).

- **Ключевые таблицы**:
  - `filter`: Основная таблица для фильтрации (`ACCEPT`, `DROP`, `REJECT`).
  - `nat`: Для преобразования сетевых адресов (NAT, Network Address Translation).
  - `mangle`: Для модификации заголовков пакетов (например, QoS, Quality of Service).

- **Основные цепочки в таблице `filter`**:
  - `INPUT`: Для пакетов, предназначенных для процессов на самом сервере. **Основная точка защиты сервера.**
  - `OUTPUT`: Для пакетов, сгенерированных локальными процессами.
  - `FORWARD`: Для пакетов, проходящих через сервер транзитом.

### Фильтрация с отслеживанием состояния (Stateful) и без (Stateless)

Это два фундаментально разных подхода к анализу трафика.

- **Stateless-фильтрация** анализирует каждый пакет изолированно, без учета контекста соединения. Это быстро, но менее безопасно.
- **Stateful-фильтрация** отслеживает состояние TCP-соединений (`NEW`, `ESTABLISHED`, `RELATED`). Это стандарт для современных файрволов, так как он значительно надежнее и позволяет создавать более простые и точные правила.

> Подробное сравнение подходов в различных доменах (сети, Kubernetes, HTTP) см. в основном файле: **[Stateful vs Stateless](../../Concepts/stateful_vs_stateless.md)**.

### Уровни фильтрации

- **L3/L4 (Сетевой/Транспортный)**: Фильтрация по IP-адресам, портам (TCP/UDP) и протоколам (ICMP). Это базовая функция любого файрвола.
- **L7 (Прикладной)**: Анализ содержимого самих протоколов (например, HTTP, DNS, SQL). Такие файрволы называются **Next-Generation Firewalls (NGFW)** или **Web Application Firewalls (WAF)**. Они способны обнаруживать угрозы, которые не видны на уровне L3/L4.

## Практические сценарии

### Инструменты управления файрволом в Linux

Ниже приведены примеры синтаксиса для различных утилит, реализующих одно и то же простое правило: разрешить входящий трафик на порт 22 (SSH, Secure Shell).

- **iptables** (классический инструмент):

    ```bash
    iptables -A INPUT -p tcp --dport 22 -j ACCEPT
    ```

- **nftables** (современная замена iptables):

    ```bash
    nft add rule inet filter input tcp dport 22 accept
    ```

    Подробнее: **[nftables: архитектура и основные концепции](../../Linux/Networking/Settings/tools/nftables/architecture_and_concepts.md)**.

- **ufw** (упрощенный интерфейс для `iptables`):

    ```bash
    ufw allow 22/tcp
    ```

- **firewalld** (динамический файрвол с концепцией зон):

    ```bash
    firewall-cmd --zone=public --add-service=ssh --permanent
    firewall-cmd --reload
    ```
