# Межсетевые экраны (Firewalls): Концепции и механизмы

## Определения

*   **Межсетевой экран (Firewall, Файрвол):** Программный или программно-аппаратный комплекс, контролирующий прохождение сетевого трафика между различными сегментами сети на основе заданных правил безопасности. Основная задача — изоляция доверенной сети от недоверенной и предотвращение несанкционированного доступа.
*   **Default Deny (Запрет по умолчанию):** Базовый принцип безопасности («Zero Trust»), при котором запрещен любой трафик, не разрешенный явно.
*   **Trust Boundary (Граница доверия):** Логическая точка в сети, где происходит проверка подлинности и фильтрация трафика.

## Основные концепции

### Механизмы фильтрации

#### 1. Фильтрация пакетов (Packet Filtering)
Работает на уровнях L3 (сетевой) и L4 (транспортный) модели OSI.
*   **Принцип:** Анализ заголовков каждого пакета независимо от контекста. Проверяются IP-адреса, протоколы (TCP, UDP, ICMP) и порты.
*   **Действия (Actions):**
    *   `ACCEPT`: Пропустить пакет.
    *   `DROP`: Молча отбросить пакет (отправитель ждет по таймауту). Рекомендуется для внешнего периметра (скрытность).
    *   `REJECT`: Отклонить с отправкой ICMP-сообщения об ошибке. Рекомендуется для внутренних сетей (быстрая отладка).

#### 2. Контроль состояния (Stateful Inspection)
В отличие от простой фильтрации, файрвол отслеживает состояние активных сессий через таблицу состояний (**Connection Tracking** или **conntrack**).
*   **Логика:** Файрвол понимает, является ли входящий пакет ответом на легитимный исходящий запрос (`ESTABLISHED`) или связанным с ним техническим трафиком (`RELATED`).
*   **Результат:** Позволяет динамически открывать порты для обратного трафика, значительно упрощая наборы правил.

#### 3. Шлюзы прикладного уровня (Application Layer Gateways / Proxy Firewalls)
Работают на уровне L7. Файрвол выступает посредником (Proxy), разрывая прямое соединение между клиентом и сервером.
*   **Преимущество:** Полная проверка протокола (например, запрет конкретных команд FTP) и скрытие топологии сети.
*   **Недостаток:** Высокая нагрузка на ресурсы (оверхед на проксирование).

#### 4. Глубокая инспекция пакетов (DPI — Deep Packet Inspection)
Анализ содержимого (Payload) пакетов для идентификации приложений, вирусов или утечек данных, даже если они используют стандартные порты (например, 443).

### Поколения и типы экранов

*   **Next-Generation Firewalls (NGFW):** Объединяют функции классического файрвола, IPS (системы предотвращения вторжений), DPI и контроля приложений. Понимают контекст (пользователь из AD, тип приложения — Zoom, BitTorrent).
*   **Unified Threat Management (UTM):** Многофункциональные устройства «все в одном» (антивирус, антиспам, VPN, контент-фильтр). Ориентированы на малый и средний бизнес.
*   **Web Application Firewalls (WAF):** Специализированные экраны для защиты HTTP-трафика. Защищают от SQL-инъекций, XSS и других атак из OWASP Top 10. [Подробнее о WAF](../../Security/ApplicationSecurity/waf.md).

### Облачные и распределенные экраны

В современных инфраструктурах (2025–2026) фильтрация становится распределенной:
*   **Security Groups (SG):** Микро-файрволы уровня хоста/инстанса в облаках (AWS, Yandex Cloud). Обычно работают по принципу Stateful и Default Deny.
*   **Network ACL (NACL):** Экраны уровня подсети (Subnet). Часто бывают Stateless (требуют явного разрешения обратного трафика).
*   **Kubernetes NetworkPolicies:** Декларативное описание разрешенных потоков трафика между подами. Реализуются через eBPF (Cilium) или iptables/nftables на каждой ноде.

## Современные технологии производительности

### XDP (eXpress Data Path)
Позволяет запускать eBPF-программы фильтрации непосредственно в драйвере сетевой карты, до того как пакет попадет в стек ядра Linux.
*   **Применение:** Защита от массированных DDoS-атак (Drop пакетов на скорости линии).
*   **Производительность:** Десятки миллионов пакетов в секунду на одном ядре.

### eBPF в сетевой безопасности
Позволяет динамически внедрять логику проверки трафика в ядро без его перекомпиляции. eBPF-файрволы (например, в Cilium) обеспечивают фильтрацию на уровне L7 (по именам сервисов, путям API) с минимальными задержками по сравнению с sidecar-прокси.

## Практические сценарии

### Настройка в Linux (Netfilter)
Ядро Linux использует фреймворк Netfilter. Современным стандартом является **nftables**.

```bash
# Пример базового правила nftables для разрешения SSH
nft add rule inet filter input tcp dport 22 ct state new accept
```

**Цепочки Netfilter:**
- `INPUT`: Трафик к локальному хосту.
- `OUTPUT`: Трафик от локального хоста.
- `FORWARD`: Трафик, проходящий через хост (маршрутизация).

### Использование FQDN-фильтрации
Современные файрволы позволяют разрешать доступ не к IP-адресам (которые часто меняются в облаках), а к доменным именам (например, `*.amazonaws.com`). Это требует интеграции файрвола с DNS-резолвером для динамического обновления списков IP.

### Исходящая фильтрация (Egress Filtering)
Критически важный аспект безопасности. Запрет несанкционированного исходящего трафика предотвращает:
1.  Утечку данных.
2.  Связь зараженных узлов с C&C-серверами (Command and Control).
3.  Использование вашей инфраструктуры для участия в DDoS-атаках.
