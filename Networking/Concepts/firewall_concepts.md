# Концепции сетевых файрволов

## Определения

*   **Файрвол (брандмауэр)** — это система сетевой безопасности, которая контролирует входящий и исходящий сетевой трафик на основе заранее установленных правил безопасности. Его роль — реализовать граничный контроль доступа, решая, какой трафик разрешить, а какой отклонить. Базовый принцип — минимально необходимые права: по умолчанию трафик запрещается (default deny), а разрешения выдаются точечно (whitelist).
*   **Фильтрация пакетов** — основной механизм работы файрволов, при котором анализируются заголовки сетевых пакетов (например, IP-адреса и порты) и на основе правил принимается решение: пропустить пакет или заблокировать.
*   **Stateful Firewall** — "умный" файрвол, который отслеживает состояние TCP-соединений. Он может, например, автоматически пропускать все ответные пакеты для уже установленного соединения, что значительно упрощает настройку правил.

### Отличие NAT от фильтрации

Важно различать функции NAT и фильтрации: NAT изменяет IP-адреса/порты пакетов, а файрволл принимает решения допустить/заблокировать пакеты на основе этих адресов и портов. В реальных конфигурациях они работают совместно.

## Основные концепции

В основе фильтрации трафика в современных операционных системах, таких как Linux, лежит идея перехвата пакетов в ключевых точках их обработки ядром. В Linux этот фреймворк называется **Netfilter**. Для понимания принципов работы файрволов полезно ознакомиться с [Моделью OSI](../OSI_TCP_IP_Model/osi_model.md) и [моделью TCP/IP](../OSI_TCP_IP_Model/tcp_ip_model.md), так как файрволы работают на различных уровнях этих моделей.

### Уровни работы файрволлов

Файрволлы работают на разных уровнях сетевой модели:
*   **L3/L4** — работают на сетевом (IP) и транспортном (TCP/UDP, ICMP) уровнях; быстрые, применяются для базового фильтра и сегментации.
*   **L7** — анализируют протоколы приложений (HTTP, DNS и т.д.), поддерживают контентные правила и могут выступать в качестве прокси.

### Цепочки (Chains)

Netfilter предоставляет "хуки" (hooks) в ядре, к которым привязываются **цепочки (chains)** правил. Пакет последовательно проходит через правила в цепочке, и как только одно из правил срабатывает, выполняется соответствующее действие (например, `ACCEPT` или `DROP`).

*   **`PREROUTING`**: Самый первый этап для входящего пакета. Здесь решается, предназначен ли пакет локальному процессу или его нужно направить дальше (маршрутизировать). Используется для изменения адреса назначения ([NAT](./nat.md)).
*   **`INPUT`**: Трафик, предназначенный для локальных приложений на самом сервере. **Это основная цепочка для защиты сервера.**
*   **`FORWARD`**: Трафик, проходящий через сервер транзитом из одной сети в другую (маршрутизация).
*   **`OUTPUT`**: Трафик, сгенерированный локальными приложениями на сервере.
*   **`POSTROUTING`**: Последний этап перед отправкой пакета в сеть. Используется для изменения адреса источника ([NAT](./nat.md)).

### Таблицы (Tables)

Правила сгруппированы в таблицы в зависимости от их назначения.

*   **`filter`**: Основная таблица для фильтрации (разрешить/запретить). Содержит цепочки `INPUT`, `FORWARD` и `OUTPUT`.
*   **`nat`**: Используется для преобразования сетевых адресов (Network Address Translation). Содержит цепочки `PREROUTING`, `POSTROUTING`, `OUTPUT`.
*   **`mangle`**: Для продвинутой модификации заголовков пакетов (например, маркировки трафика для QoS).
*   **`raw`**: Для работы с пакетами до того, как система начнёт отслеживать их состояние (connection tracking).

### Типы и режимы работы файрволлов

*   **Размещение:**
    *   **Сетевой:** Устанавливается на периметре сети или между сегментами.
    *   **Хостовый:** Работает локально на отдельном сервере, виртуальной машине или контейнере. Часто эти подходы комбинируются.
*   **Реализация:**
    *   **Аппаратный:** Специализированные устройства (например, Cisco ASA, FortiGate).
    *   **Программный:** Работает как программное обеспечение на стандартном оборудовани (например, `iptables`, `nftables`, Windows Firewall).
    *   **Виртуализированный:** Реализуется в облачных средах или гипервизорах.
*   **Трек соединений:**

| Критерий | Stateless (без сохранения состояния) | Stateful (с сохранением состояния) |
|---|---|---|
| Контекст | Судьба каждого пакета решается независимо от предыдущих. | Учитывает состояние соединений и контекст предыдущих пакетов. |
| Производительность | Выше, но ограниченная гибкость. | Чуть ниже, но безопаснее по умолчанию. |
| UDP/ICMP | Требует явных правил для обоих направлений (входящий и исходящий трафик). | Облегчает допуск ответного трафика для установленных соединений. |
| Типовые правила | Простые списки контроля доступа (ACL). | Использует состояния `ESTABLISHED`, `RELATED`, `INVALID`, `NEW` и таймауты. |

#### Детальное сравнение Stateless и Stateful файрволов

**Stateless Firewall (Без сохранения состояния):**

- **Принцип работы:** Каждый пакет анализируется изолированно на основе статических правил (IP-адрес источника/назначения, порты, протоколы)
- **Преимущества:**
  - Максимальная производительность и минимальная задержка
  - Низкое потребление памяти (не хранит таблицу соединений)
  - Простота реализации и отладки
- **Недостатки:**
  - Не понимает контекста TCP-соединений
  - Требует явных правил для входящего и исходящего трафика
  - Уязвим к спуфингу и некоторым видам атак
- **Примеры:** Базовые ACL на маршрутизаторах Cisco, простые правила iptables без conntrack

**Stateful Firewall (С сохранением состояния):**

- **Принцип работы:** Отслеживает состояние сетевых соединений в таблице состояний (connection tracking)
- **Механизм Conntrack:**
  - Отслеживает этапы TCP-handshake (SYN, SYN-ACK, ACK)
  - Хранит информацию о соединениях UDP и ICMP
  - Автоматически разрешает ответный трафик для установленных соединений
- **Состояния соединений:**
  - `NEW` — новое соединение
  - `ESTABLISHED` — установленное соединение
  - `RELATED` — связанное соединение (например, FTP data channel)
  - `INVALID` — пакет не соответствует ни одному известному соединению
- **Преимущества:**
  - Автоматическая фильтрация ответного трафика
  - Защита от незавершенных TCP-handshake атак
  - Возможность детектирования аномалий протоколов
- **Недостатки:**
  - Требует больше памяти для хранения таблицы соединений
  - Потенциальная уязвимость к исчерпанию таблицы состояний (DoS)
  - Немного выше задержка на обработку
- **Примеры:** iptables с модулем conntrack, nftables, Windows Firewall, большинство современных NGFW

## Практические сценарии

На основе описанных концепций файрволы могут быть применены в различных сценариях: от защиты отдельного сервера путем фильтрации входящего и исходящего трафика до обеспечения безопасности периметра корпоративной сети. Например, можно настроить файрвол для разрешения только HTTP/HTTPS трафика на веб-сервер, блокируя все остальные порты, или для создания DMZ.

### Принципы построения правил

*   Определите политику по умолчанию отдельно для входящего, исходящего и транзитного трафика (рекомендуется `DROP` или `REJECT` по умолчанию).
*   Дайте приоритет устойчивости к сбоям: сначала разрешайте `loopback` и `established`/`related` соединения, затем узконаправленные порты, в конце — явные отказные правила.
*   Привязывайте правила к сетевым интерфейсам и зонам (например, `public`, `internal`, `dmz`).
*   Используйте группы/сеты адресов и портов для читаемости и упрощения управления.
*   Логируйте отказанные пакеты точечно, чтобы не перегружать систему журналирования.

### Примеры конфигурации в Linux

*   **iptables (классическая подсистема):**
    ```bash
    iptables -P INPUT DROP
    iptables -P FORWARD DROP
    iptables -P OUTPUT ACCEPT

    iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
    iptables -A INPUT -i lo -j ACCEPT

    iptables -A INPUT -p tcp --dport 22 -s 203.0.113.0/24 -j ACCEPT
    iptables -A INPUT -p tcp --dport 80 -j ACCEPT
    ```
*   **nftables (современная замена):**
    ```bash
    nft add table inet filter
    nft add chain inet filter input { type filter hook input priority 0; policy drop; }
    nft add rule inet filter input ct state established,related accept
    nft add rule inet filter input iif lo accept
    nft add rule inet filter input tcp dport {22,80} accept
    ```
*   **Упрощённые фронтенды:**
    *   **ufw:**
        ```bash
        ufw default deny incoming
        ufw default allow outgoing
        ufw allow 22/tcp
        ufw allow 80/tcp
        ufw enable
        ```
    *   **firewalld:**
        ```bash
        firewall-cmd --permanent --zone=public --add-service=http
        firewall-cmd --permanent --zone=public --add-service=ssh
        firewall-cmd --reload
        ```

### Отладка и эксплуатация файрволлов

*   **Просмотр активных правил:** Используйте команды `iptables -S`, `nft list ruleset`, `ufw status verbose`, `firewall-cmd --list-all`.
*   **Счётчики трафика:** Помогают обнаружить «мертвые» или чрезмерно срабатывающие правила, а также оценить объем проходящего трафика.
*   **Логирование отказов:**
    ```bash
    iptables -A INPUT -p tcp --dport 22 -j LOG --log-prefix "iptables ssh denied: "
    ```
    Настраивайте логирование точечно, чтобы не перегружать систему журналирования.
*   **Особенности протоколов:** Учитывайте эфемерные порты для ответных соединений и особенности протоколов без состояния (UDP), которые могут требовать отдельных правил для входящего и исходящего трафика.
*   **Управление конфигурацией:** Встраивайте правила файрволла в системы управления конфигурацией (например, Ansible, Puppet, Chef), используйте атомарные обновления и гарантируйте сохранение правил после перезагрузки системы.
