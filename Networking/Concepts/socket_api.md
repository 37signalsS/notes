# Интерфейс сокетов (Socket API)

## Определения

*   **Сокет (Socket):** Программный интерфейс для обеспечения обмена данными между процессами. В контексте сетей сокет представляет собой конечную точку (endpoint) в сетевом соединении. Это абстракция, которая позволяет приложению отправлять и получать данные по сети, не вдаваясь в детали реализации транспортных протоколов, таких как [TCP](../Protocols/TCP/overview.md) или [UDP](../Protocols/udp.md).
    В Unix-подобных системах сокеты следуют философии «все есть файл» и представлены файловыми дескрипторами, что позволяет использовать для работы с ними системные вызовы `read()` и `write()`.

*   **Интерфейс сокетов Беркли (Berkeley Sockets):** Исторически наиболее влиятельная реализация Socket API, ставшая стандартом де-факто (стандарт POSIX) для сетевых API в большинстве операционных систем.

В повседневной практике сетевиков под сокетом часто понимают сочетание `IP:Port`. Однако для точной идентификации соединения на сетевом уровне используется «пятерка параметров» (5-tuple):
`{Протокол, IP источника, Порт источника, IP назначения, Порт назначения}`.

## Базовые концепции

### Модель «Клиент-Сервер»

*   **Сервер:** Запускается на известном IP-адресе и порту, переходит в пассивный режим ожидания (прослушивания) и ждет входящих подключений от клиентов.
*   **Клиент:** Зная IP-адрес и порт сервера, активно инициирует установку соединения. После установки соединения клиент и сервер могут обмениваться данными.

### Типы сокетов и семейства адресов

При создании сокета (`socket()`) необходимо указать две ключевые константы:

1.  **Семейство адресов (Address Family):** Определяет используемый протокол сетевого уровня.
    *   `AF_INET`: Для [IPv4](../Protocols/IP_addressing/ip_overview.md).
    *   `AF_INET6`: Для IPv6.
    *   `AF_UNIX` (или `AF_LOCAL`): Для локального взаимодействия на одной машине (Unix-сокеты).
2.  **Тип сокета:** Определяет протокол транспортного уровня и семантику обмена данными.
    *   `SOCK_STREAM` (потоковый сокет): Использует **TCP**. Обеспечивает надежную, двустороннюю передачу данных с установкой соединения и сохранением порядка байтов.
    *   `SOCK_DGRAM` (датаграммный сокет): Использует **UDP**. Обеспечивает передачу независимых сообщений (датаграмм) без гарантий доставки и сохранения порядка.
    *   `SOCK_RAW`: Позволяет приложению напрямую работать с IP-пакетами, самостоятельно формируя заголовки (требуется для инструментов типа `ping` или `tcpdump`).

### Основные операции (Berkeley Sockets API)

| Операция | Назначение | Используется |
| :--- | :--- | :--- |
| `socket()` | Создание нового сокета (конечной точки). | Сервер и Клиент |
| `bind()` | Связывание сокета с конкретным IP-адресом и портом. | Сервер |
| `listen()` | Перевод сокета в режим прослушивания входящих соединений. | Сервер |
| `accept()` | Принятие входящего запроса. Создает **новый сокет** для этого соединения. | Сервер |
| `connect()`| Установка соединения с сервером. | Клиент |
| `send()` / `recv()` | Отправка и получение данных через сокет. | Сервер и Клиент |
| `setsockopt()` | Настройка параметров сокета (тайм-ауты, опции ядра). | Сервер и Клиент |
| `close()` | Закрытие сокета и разрыв соединения. | Сервер и Клиент |

## Продвинутые механизмы и производительность

### Блокирующий и неблокирующий ввод-вывод

*   **Блокирующий режим (Blocking):** Системный вызов (например, `accept` или `recv`) «замораживает» поток выполнения до завершения операции. Это просто в реализации, но неэффективно для тысяч соединений.
*   **Неблокирующий режим (Non-blocking):** Если данных нет, вызов немедленно возвращает ошибку `EAGAIN` или `EWOULDBLOCK`. Приложение может выполнять другие задачи и вернуться к проверке позже.
*   **Мультиплексирование (select, poll, epoll):** Механизмы ядра, позволяющие одному потоку следить за готовностью тысяч сокетов. `epoll` (Linux) является основой производительности современных серверов (Nginx, Redis).
*   **Асинхронный ввод-вывод (io_uring):** Современный интерфейс Linux (5.1+), использующий разделяемые кольцевые буферы. Позволяет достичь экстремальной производительности за счет минимизации переключений контекста. Подробнее: [io_uring](../../Linux/Core/kernel/io_uring.md).

### Критически важные опции (setsockopt)

*   **`SO_REUSEADDR`:** Позволяет серверу мгновенно перезапуститься на том же порту, даже если предыдущие соединения еще находятся в состоянии `TIME_WAIT`.
*   **`SO_REUSEPORT` (Linux 3.9+):** Разрешает нескольким процессам или потокам биндиться на один и тот же порт. Ядро автоматически балансирует входящие соединения между ними.
*   **`TCP_NODELAY`:** Отключает алгоритм Нагла. Критично для микросервисов и интерактивных приложений, где важна минимальная задержка (latency) для небольших пакетов.

## Практические сценарии

### Процесс взаимодействия (TCP)

1.  **На стороне сервера:**
    1.  `socket()`: создается основной сокет.
    2.  `bind()`: сокет «привязывается» к IP-адресу и порту сервера.
    3.  `listen()`: сервер начинает слушать порт, создается очередь для входящих подключений.
    4.  `accept()`: сервер блокируется и ждет подключения клиента. Когда клиент подключается, `accept()` создает **новый сокет** для этого конкретного соединения, а основной сокет продолжает слушать порт для новых клиентов.

2.  **На стороне клиента:**
    1.  `socket()`: создается сокет.
    2.  `connect()`: клиент инициирует соединение. Вызов `bind()` для клиента обычно не требуется, так как ОС автоматически назначает ему свободный **[эфемерный порт](./network_ports.md)**.

### Пример: Эхо-сервер и клиент на Python

#### Код сервера (echo_server.py)

```python
import socket

# Определяем хост и порт
HOST = '127.0.0.1'  # Loopback-адрес
PORT = 8888         # Порт > 1023

# 1. Создаем сокет: AF_INET для IPv4, SOCK_STREAM для TCP
server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 2. Опция SO_REUSEADDR позволяет сразу перезапустить сервер на том же порту
server_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)

# 3. Связываем сокет с адресом и портом
server_socket.bind((HOST, PORT))

# 4. Начинаем прослушивание
server_socket.listen()
print(f"Сервер запущен на {HOST}:{PORT} и ожидает подключения...")

# 5. Принимаем подключение. accept() возвращает НОВЫЙ сокет для данных.
conn, addr = server_socket.accept()
print(f"Подключен клиент: {addr}")

# 6. Цикл приема-передачи данных
with conn:
    # Отключаем задержки Нагла для мгновенного отклика
    conn.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)
    while True:
        data = conn.recv(1024)
        if not data:
            break
        print(f"Получено от клиента: {data.decode()}")
        conn.sendall(data)

server_socket.close()
```

#### Код клиента (echo_client.py)

```python
import socket

HOST, PORT = '127.0.0.1', 8888

# Используем контекстный менеджер для автоматического закрытия
with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.connect((HOST, PORT))
    s.sendall(b"Hello, world")
    data = s.recv(1024)
    print(f"Ответ от сервера: {data.decode()}")
```

### Проверка состояния и анализ

1.  **Диагностика:** Используйте `ss` для проверки слушающих портов.
    ```bash
    ss -tlpn | grep 8888
    # → LISTEN 0 5 *:8888 *:* users:(("python",pid=123,fd=3))
    ```
2.  **Анализ трафика (Wireshark):**
    При захвате на `loopback` с фильтром `tcp.port == 8888` можно увидеть:
    *   **TCP Handshake:** Тройное рукопожатие (`SYN` → `SYN-ACK` → `ACK`).
    *   **Передача:** Пакеты с флагом `PSH` (Push), указывающим на наличие данных для приложения.
    *   **Порты:** Источник — случайный эфемерный порт (например, 54321), назначение — 8888.

## Дополнительная информация

### Unix-сокеты (AF_UNIX)

Используются для взаимодействия процессов на одной машине.
*   **Принцип:** Вместо порта используется файл в ФС (например, `/var/run/docker.sock`).
*   **Абстрактные сокеты (Linux):** Путь начинается с нулевого байта (`\0`). Они не создают файла на диске и автоматически исчезают при закрытии процесса.
*   **Преимущества:** В 2-3 раза быстрее TCP loopback, так как данные копируются напрямую в ядре без вычисления контрольных сумм и инкапсуляции в IP/TCP заголовки.

#### Пример: Docker Socket
Демон Docker (`dockerd`) создает сокет `/var/run/docker.sock`. Все команды CLI `docker` — это фактически HTTP-запросы в этот Unix-сокет.

### Безопасность и шифрование

Стандартные сокеты передают данные в открытом виде.
*   **TLS/SSL:** Слой шифрования, который «оборачивает» TCP-сокет.
*   **Kernel TLS (kTLS):** Современная оптимизация в Linux, позволяющая ядру шифровать данные «на лету» во время системного вызова `sendfile`, что значительно снижает нагрузку на CPU.

### Socket API vs. WebSocket

*   **Socket API:** Низкоуровневый системный интерфейс (L4).
*   **WebSocket:** Протокол прикладного уровня (L7), работающий поверх TCP. Он инициируется через HTTP Upgrade и затем переходит в режим полнодуплексного обмена, используя Socket API в качестве транспорта.
