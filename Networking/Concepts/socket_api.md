# Интерфейс сокетов (Socket API)

## Определения

*   **Сокет (Socket):** Программный интерфейс для обеспечения обмена данными между процессами. В контексте сетей сокет представляет собой конечную точку (endpoint) в сетевом соединении. Это абстракция, которая позволяет приложению взаимодействовать с сетевым стеком ОС через файловые дескрипторы, скрывая детали реализации транспортных протоколов ([TCP](../Protocols/TCP/overview.md), [UDP](../Protocols/udp.md)).
    В Unix-подобных системах сокеты следуют философии «все есть файл» и представлены файловыми дескрипторами, что позволяет использовать для работы с ними системные вызовы `read()` и `write()`.

*   **Интерфейс сокетов Беркли (Berkeley Sockets):** Исторически наиболее влиятельная реализация Socket API, ставшая стандартом де-факто (стандарт POSIX) для сетевых API в большинстве операционных систем.

*   **Пятерка параметров (5-tuple):** Уникальный идентификатор сетевого соединения на транспортном уровне:
    `{Протокол, IP источника, Порт источника, IP назначения, Порт назначения}`.

## Базовые концепции

### Модель «Клиент-Сервер»

*   **Сервер:** Запускается на известном IP-адресе и порту, переходит в пассивный режим ожидания (прослушивания) через `listen()` и ждет входящих подключений.
*   **Клиент:** Инициирует установку соединения через `connect()`, зная адрес сервера. ОС автоматически назначает клиенту свободный **[эфемерный порт](./network_ports.md)**.

### Типы сокетов и семейства адресов

При создании сокета (`socket()`) указываются ключевые параметры:

1.  **Семейство адресов (Address Family):**
    *   `AF_INET`: Для [IPv4](../Protocols/IP_addressing/ip_overview.md).
    *   `AF_INET6`: Для IPv6.
    *   `AF_UNIX` (или `AF_LOCAL`): Для локального взаимодействия процессов на одной машине (Unix-сокеты). Данные передаются через память ядра, минуя сетевой стек.
2.  **Тип сокета:**
    *   `SOCK_STREAM` (потоковый сокет): Использует **TCP**. Надежная, двусторонняя передача с сохранением порядка байтов.
    *   `SOCK_DGRAM` (датаграммный сокет): Использует **UDP**. Передача независимых сообщений без гарантий доставки.
    *   `SOCK_RAW`: Прямой доступ к IP-пакетам. Позволяет вручную формировать заголовки L3/L4 (используется в `ping`, `tcpdump`, инструментах безопасности).

### Основные операции (Berkeley Sockets API)

| Операция | Назначение | Участник |
| :--- | :--- | :--- |
| `socket()` | Создание конечной точки (файлового дескриптора). | Оба |
| `bind()` | Привязка сокета к IP и порту. | Сервер |
| `listen()` | Перевод в режим прослушивания и задание размера очереди `backlog`. | Сервер |
| `accept()` | Извлечение запроса из очереди и создание **нового сокета** для сессии. | Сервер |
| `connect()`| Активная установка соединения. | Клиент |
| `send()` / `recv()` | Передача и прием данных (обычно для TCP). | Оба |
| `sendto()` / `recvfrom()` | Передача/прием данных с указанием адреса (для UDP). | Оба |
| `setsockopt()` | Настройка параметров сокета (тайм-ауты, опции ядра). | Оба |
| `close()` | Закрытие дескриптора и инициирование завершения соединения. | Оба |

## Продвинутые механизмы и производительность

### Управление очередями: Backlog
В Linux вызов `listen(fd, backlog)` управляет двумя очередями:
1.  **SYN Queue (Неполные соединения):** Соединения в состоянии `SYN_RECV`. Размер: `net.ipv4.tcp_max_syn_backlog`.
2.  **Accept Queue (Завершенные соединения):** Прошли 3-way handshake, ждут вызова `accept()`. Размер: `min(backlog, net.core.somaxconn)`.

### Режимы ввода-вывода
*   **Блокирующий (Blocking):** Поток «замирает» на системном вызове до завершения операции.
*   **Неблокирующий (Non-blocking):** Вызов возвращает `EAGAIN`, если операция не может быть завершена немедленно. Требует циклической проверки (polling).
*   **Мультиплексирование (select, poll, epoll):** Позволяет одному потоку эффективно отслеживать готовность тысяч дескрипторов. `epoll` — стандарт для высоконагруженных систем (Nginx, Envoy).
*   **Асинхронный ввод-вывод (io_uring):** Современный интерфейс Linux (5.1+), использующий разделяемые кольцевые буферы для исключения накладных расходов на системные вызовы. Подробнее: [io_uring](../../Linux/Core/kernel/io_uring.md).

### Оптимизации передачи данных
*   **Zero-copy (`sendfile`, `splice`):** Передача данных напрямую из кэша страниц в сокет, минуя копирование в пользовательское пространство (User-space).
*   **kTLS (Kernel TLS):** Шифрование выполняется в ядре, что позволяет использовать `sendfile` для защищенных соединений.
*   **eBPF Socket Redirection:** Использование `sockmap` для перенаправления пакетов между сокетами на одном хосте (например, в Service Mesh) напрямую, обходя сетевой стек TCP/IP.

### Критически важные опции (setsockopt)
*   **`SO_REUSEADDR`:** Позволяет биндиться на порт в состоянии `TIME_WAIT`. Решает проблему задержки при рестарте сервера.
*   **`SO_REUSEPORT`:** Позволяет нескольким процессам слушать один порт. Ядро балансирует входящие пакеты между ними.
*   **`TCP_NODELAY`:** Отключение алгоритма Нагла. Критично для минимизации задержек (Latency) в интерактивных протоколах.
*   **`SO_KEEPALIVE`:** Включает проверку «живучести» соединения на уровне TCP.

## Практические сценарии

### Процесс взаимодействия (TCP)

1.  **Сервер:** `socket()` → `bind()` → `listen()` → `accept()` (блокировка до входящего SYN).
2.  **Клиент:** `socket()` → `connect()` (SYN → SYN-ACK → ACK).
3.  **Передача:** `send()` / `recv()`. Данные сегментируются на уровне TCP и инкапсулируются в IP.
4.  **Закрытие:** `close()`. Одна сторона отправляет FIN, переходит в `FIN_WAIT_1`.

### Пример: Эхо-сервер и клиент на Python

#### Код сервера (echo_server.py)

```python
import socket

HOST, PORT = '127.0.0.1', 8888

# Создаем сокет (IPv4, TCP)
with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    # Опция для быстрого перезапуска
    s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind((HOST, PORT))
    s.listen(128)
    print(f"Сервер слушает на {HOST}:{PORT}...")

    conn, addr = s.accept()
    with conn:
        print(f"Подключен клиент: {addr}")
        # Отключаем задержки для малых пакетов
        conn.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)
        while True:
            data = conn.recv(1024)
            if not data: break
            conn.sendall(data)
```

### Диагностика и анализ

1.  **Socket Statistics (`ss`):** Современная замена `netstat`.
    ```bash
    # Показать статистику TCP-сокета (RTT, окно, MSS)
    ss -ti sport = :8888
    ```
2.  **Wireshark / tcpdump:**
    При анализе на `loopback` видны флаги `SYN`, `ACK`, `PSH` (передача данных) и `FIN`.

## Дополнительная информация

### Unix-сокеты (AF_UNIX)
*   **Преимущества:** В 2-3 раза быстрее TCP loopback. Нет оверхеда на инкапсуляцию, расчет контрольных сумм и фрагментацию.
*   **Абстрактные сокеты (Linux):** Путь начинается с `\0`. Не создают файла в ФС, автоматически очищаются при закрытии процесса.

### Безопасность и Socket API
*   **TLS/SSL:** Обертка над стандартным сокетом. Работает в User-space (OpenSSL) или в Kernel-space (kTLS).
*   **Socket Activation (systemd):** Механизм, где `systemd` открывает сокет и передает его дескриптор запускаемому сервису. Позволяет обновлять сервис без разрыва соединений.
