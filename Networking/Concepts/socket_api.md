# Интерфейс сокетов (Socket API)

## Определения

* **Сокет**: Программный интерфейс для обеспечения обмена данными между процессами. В контексте сетей, сокет представляет собой конечную точку в сетевом соединении. Это абстракция, которая позволяет приложению отправлять и получать данные по сети, не вдаваясь в детали реализации транспортных протоколов, таких как [TCP](../Protocols/TCP/overview.md) или [UDP](../Protocols/udp.md).

В повседневной практике сетевиков под сокетом часто понимают сочетание `IP:Port` (без указания транспортного протокола). Строго говоря, полная тройка — транспортный протокол + IP + порт — включает все необходимые критерии.

* **Интерфейс сокетов Беркли (Berkeley Sockets)**: Исторически наиболее влиятельная реализация Socket API, ставшая стандартом де-факто для сетевых API в большинстве операционных систем.

## Базовые концепции

Сокеты можно представить как специальный вид **файлов**: все, что записывается в сокет на одном компьютере, может быть прочитано из связанного с ним сокета на другом компьютере. Эта абстракция скрывает от программиста сложность сетевой передачи.

### Модель "Клиент-Сервер"

* **Сервер:** Запускается на известном IP-адресе и порту, переходит в пассивный режим ожидания (прослушивания) и ждет входящих подключений от клиентов.
* **Клиент:** Зная IP-адрес и порт сервера, активно инициирует установку соединения. После установки соединения клиент и сервер могут обмениваться данными.

### Типы сокетов и семейства адресов

При создании сокета необходимо указать две ключевые константы:

1. **Семейство адресов (Address Family):** Определяет используемый протокол сетевого уровня.
    * `AF_INET`: Для [IPv4](../Protocols/IP_addressing/ip_overview.md).
    * `AF_INET6`: Для IPv6.
    * `AF_UNIX`: Для локального взаимодействия на одной машине (Unix-сокеты).

2. **Тип сокета:** Определяет протокол транспортного уровня и семантику обмена данными.
    * `SOCK_STREAM` (потоковый сокет): Использует **TCP**. Обеспечивает надежную, двустороннюю передачу данных с установкой соединения и сохранением порядка байтов.
    * `SOCK_DGRAM` (датаграммный сокет): Использует **UDP**. Обеспечивает быструю передачу независимых сообщений (датаграмм) без гарантий доставки и сохранения порядка.

### Основные операции (Berkeley Sockets API)

| Операция | Назначение | Используется |
| :--- | :--- | :--- |
| `socket()` | Создание нового сокета (конечной точки). | Сервер и Клиент |
| `bind()` | Связывание сокета с конкретным IP-адресом и портом. | Сервер |
| `listen()` | Перевод сокета в режим прослушивания входящих соединений. Создает очередь для запросов. | Сервер |
| `accept()` | Принятие входящего запроса на соединение. Блокирует выполнение до прихода запроса. | Сервер |
| `connect()`| Установка соединения с сервером по указанному IP-адресу и порту. | Клиент |
| `send()` / `sendall()` | Отправка данных через сокет. | Сервер и Клиент |
| `recv()` | Получение (чтение) данных из сокета. | Сервер и Клиент |
| `close()` | Закрытие сокета и разрыв соединения. | Сервер и Клиент |

## Практические сценарии

### Процесс взаимодействия (TCP)

1. **На стороне сервера:**
    1. `socket()`: создается основной сокет.
    2. `bind()`: сокет "привязывается" к IP-адресу и порту сервера.
    3. `listen()`: сервер начинает слушать порт, создается очередь для входящих подключений.
    4. `accept()`: сервер блокируется и ждет подключения клиента. Когда клиент подключается, `accept()` создает **новый сокет** для этого конкретного соединения, а основной сокет продолжает слушать порт для новых клиентов.

2. **На стороне клиента:**
    1. `socket()`: создается сокет.
    2. `connect()`: клиент инициирует соединение с IP-адресом и портом сервера. Вызов `bind()` для клиента обычно не требуется, так как ОС автоматически назначает ему свободный **[эфемерный порт](./network_ports.md#динамические-или-частные-порты-dynamicprivateephemeral-ports-49152–65535)**.

3. **Обмен данными:**
    * Клиент использует `sendall()` для отправки данных, а сервер использует `recv()` на **новом сокете** для их получения.
    * Обмен может идти в обе стороны.

4. **Завершение:**
    * Обе стороны вызывают `close()` для закрытия своих сокетов и разрыва соединения.

### Пример: Эхо-сервер и клиент на Python

Рассмотрим практический пример эхо-сервера и клиента на Python, их запуск и анализ сетевого взаимодействия.

#### Код сервера (echo_server.py)

В данном коде IP-адрес и порт вынесены в константы. Используется адрес `127.0.0.1` (loopback), который означает, что данные не покинут пределы компьютера. Сервер выводит диагностические сообщения о своем состоянии.

```python
import socket

# Определяем хост и порт, вынося их в константы
HOST = '127.0.0.1'  # Loopback-адрес, сервер будет доступен только на этом компьютере
PORT = 8888         # Порт > 1023

# 1. Создаем сокет: AF_INET для IPv4, SOCK_STREAM для TCP
server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 2. Связываем сокет с адресом и портом
server_socket.bind((HOST, PORT))

# 3. Начинаем прослушивание
server_socket.listen()
print(f"Сервер запущен на {HOST}:{PORT} и ожидает подключения...")

# 4. Принимаем подключение. Метод accept() блокирует выполнение и ждет клиента.
# Он возвращает новый объект сокета для обмена данными и адрес клиента.
conn, addr = server_socket.accept()
print(f"Подключен клиент: {addr}")

# 5. Цикл приема-передачи данных
with conn:
    while True:
        # Получаем данные от клиента (до 1024 байт)
        data = conn.recv(1024)
        if not data:
            # Если данных нет, клиент закрыл соединение
            break
        
        print(f"Получено от клиента: {data.decode()}")
        
        # Отправляем данные обратно клиенту (эхо-сервер)
        conn.sendall(data)
        print("Отправлено обратно клиенту.")

# 6. Соединение с клиентом закрывается автоматически благодаря `with`.
print("Соединение с клиентом закрыто.")
server_socket.close()
print("Сервер завершил работу.")

```

*Обратите внимание, что этот сервер обслуживает только одного клиента, а затем завершает свою работу. Реальные серверы обычно работают в бесконечном цикле и используют многопоточность или асинхронность для обработки множества клиентов.*

#### Код клиента (echo_client.py)

Клиент подключается к указанному адресу и порту, отправляет сообщение и получает ответ.

```python
import socket

# Определяем хост и порт сервера
HOST = '127.0.0.1'
PORT = 8888

# 1. Создаем сокет
with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as client_socket:
    # 2. Подключаемся к серверу
    client_socket.connect((HOST, PORT))
    
    # 3. Отправляем данные
    message = b"Hello, world"
    client_socket.sendall(message)
    print("Сообщение отправлено серверу.")
    
    # 4. Получаем ответ от сервера
    data = client_socket.recv(1024)
    print(f"Получен ответ от сервера: {data.decode()}")

# 5. Сокет закрывается автоматически
print("Клиент завершил работу.")

```

#### Порядок запуска и проверка состояния

1. **Запуск сервера:** Откройте терминал и выполните:

    ```bash
    python echo_server.py
    ```

    Сервер выведет сообщение "Сервер запущен... и ожидает подключения..." и "зависнет". Это ожидаемое поведение — он заблокирован на вызове `accept()`, ожидая клиента.

2. **Проверка состояния сервера:** Откройте второй терминал и воспользуйтесь утилитой [**`ss`**](../../Linux/Diagnostics/Networking/ss.md) или ее устаревшим аналогом [**`netstat`**](../../Linux/Diagnostics/Networking/netstat.md), чтобы убедиться, что сервер действительно работает.

    ```bash
    # Рекомендуемый способ (ss)
    ss -tlpn | grep 8888
    # → LISTEN 0 5 *:8888 *:* users:(("python",pid=1234,fd=3))

    # Устаревший способ (netstat)
    netstat -an | grep 8888
    # → tcp 0 0 0.0.0.0:8888 0.0.0.0:* LISTEN
    ```

    Вы должны увидеть строчку, показывающую, что процесс Python находится в состоянии `LISTEN` на порту `8888`.

3. **Запуск клиента:** В том же втором терминале выполните:

    ```bash
    python echo_client.py
    ```

    Клиент подключится к серверу, отправит сообщение, получит ответ и завершит работу. В это же время "разблокируется" сервер, обработает запрос и тоже завершится.

#### Анализ трафика в Wireshark

Если запустить Wireshark для захвата трафика на loopback-интерфейсе (`lo` в Linux) с фильтром `tcp.port == 8888`, можно наблюдать весь цикл взаимодействия:

1. **[Установка соединения (TCP Handshake, Тройное рукопожатие)](../Protocols/TCP/overview.md#установка-соединения-tcp-handshake-тройное-рукопожатие):**
    * Клиент → Сервер: `SYN` (запрос на синхронизацию)
    * Сервер → Клиент: `SYN, ACK` (подтверждение и встречный запрос)
    * Клиент → Сервер: `ACK` (финальное подтверждение)

2. **Передача данных:**
    * **Клиент → Сервер:** Пакет с флагом `PSH` (Push), содержащий в теле (`data`) строку `Hello, world`. Wireshark покажет, что порт источника — это случайный **[эфемерный порт](./network_ports.md#динамические-эфемерные-порты-49152–65535)** (например, `53435`), назначенный ОС, а порт назначения — `8888`.
    * **Сервер → Клиент:** Пакет `ACK` для подтверждения получения данных.
    * **Сервер → Клиент:** Пакет с флагом `PSH`, содержащий ту же строку `Hello, world`. Теперь порт источника — `8888`, а порт назначения — эфемерный порт клиента.
    * **Клиент → Сервер:** Пакет `ACK` для подтверждения получения ответа.

3. **Завершение соединения (4-way handshake):**
    * Стороны обмениваются пакетами с флагами `FIN` и `ACK`, корректно закрывая соединение.

## Дополнительная информация

### Unix-сокеты (AF_UNIX)

Помимо сетевых сокетов (`AF_INET`, `AF_INET6`), которые используются для коммуникации по сети, существует важный тип сокетов для взаимодействия процессов **на одной и той же машине** — Unix-сокеты.

* **Семейство адресов:** `AF_UNIX`
* **Принцип работы:** Они не используют сетевой стек (IP-адреса и порты). Вместо этого они создают специальный файл в файловой системе (например, `/var/run/docker.sock`), который служит точкой для обмена данными.
* **Преимущества:**
  * **Скорость:** Работают значительно быстрее сетевых сокетов, так как данные не проходят через весь сетевой стек TCP/IP, а копируются напрямую в ядре.
  * **Безопасность:** Доступ к сокету можно контролировать стандартными правами доступа файловой системы Unix (владелец, группа, права `rwx`).

#### Пример: Docker Socket (`/var/run/docker.sock`)

Классический пример использования Unix-сокета — это API демона Docker.

* Демон Docker (`dockerd`) создает Unix-сокет `/var/run/docker.sock` и слушает его.
* Клиент командной строки `docker` (и другие приложения, например, Portainer) по умолчанию подключается к этому файлу для отправки команд демону (например, `docker ps`, `docker run`).
* Поскольку доступ к файлу сокета управляется правами ФС, для работы с ним обычно требуются права `root` или членство в группе `docker`.
* **Важно:** Предоставление доступа на запись к файлу `/var/run/docker.sock` фактически равносильно предоставлению root-доступа к хост-системе, так как через Docker API можно смонтировать любой каталог хоста в контейнер и изменить его.

### Socket API vs. WebSocket

Часто возникает путаница между низкоуровневым **Socket API** и протоколом **WebSocket**.

* **Socket API (Berkeley Sockets):** Это **интерфейс программирования (API)**, предоставляемый операционной системой. Он дает программисту базовые блоки (`socket()`, `bind()`, `listen()`, ...) для установления сетевых соединений (в основном TCP и UDP). Это фундаментальный механизм, на котором строятся многие сетевые протоколы.
* **WebSocket:** Это **протокол прикладного уровня (Layer 7)**, работающий поверх TCP. Он спроектирован для обеспечения постоянного двунаправленного полнодуплексного соединения между клиентом (обычно браузером) и сервером. В отличие от Socket API, WebSocket определяет стандартный способ "рукопожатия" (handshake) для обновления HTTP-соединения до WebSocket, а также формат кадров (frames) для обмена сообщениями.

Итог: WebSocket — это высокоуровневый протокол, который *использует* Socket API "под капотом" для своей работы.

### Безопасность: SSL/TLS

Стандартные сокеты, созданные через `socket()`, не обеспечивают шифрования. Весь трафик, передаваемый через них, является открытым текстом и может быть перехвачен.

Для защиты данных поверх стандартного TCP-сокета применяется протокол **[TLS (Transport Layer Security)](../Protocols/tls.md)**, историческим предшественником которого был SSL (Secure Sockets Layer).

* **Принцип работы:** После установления стандартного TCP-соединения клиент и сервер выполняют "рукопожатие" TLS. В ходе этого процесса они договариваются о ключах шифрования и проверяют подлинность друг друга (обычно сервер предоставляет клиенту цифровой сертификат).
* **Результат:** Весь последующий обмен данными инкапсулируется в защищенный TLS-канал.
* **В программировании:** Для работы с TLS используются специализированные библиотеки (например, `ssl` в Python или OpenSSL), которые "оборачивают" стандартный сокет, добавляя слой шифрования. Примером протокола, использующего этот подход, является **HTTPS**.
