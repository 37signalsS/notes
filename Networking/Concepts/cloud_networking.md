# Облачные сети (Cloud Networking)

## Определение

**Облачная сеть (Cloud Networking)** — это инфраструктура, позволяющая объединять облачные ресурсы (ВМ, контейнеры, базы данных) в изолированные виртуальные сегменты. В основе лежит концепция **Software-Defined Networking (SDN)**, где управление сетью отделено от физического оборудования и осуществляется программно через API.

## Основные концепции

### Virtual Private Cloud (VPC)

**VPC (Виртуальное приватное облако)** — логически изолированная сеть внутри публичного облака.

*   **Изоляция:** Трафик внутри VPC полностью отделен от других клиентов на уровне инкапсуляции (VXLAN, Geneve).
*   **Подсети (Subnets):** Разделение VPC на сегменты по IP-диапазонам. Подсети могут быть публичными (имеют маршрут в интернет) и приватными (доступ только через VPN/NAT).
*   **Таблицы маршрутизации (Route Tables):** Правила, определяющие, куда направлять пакеты (на интернет-шлюз, в другую подсеть или через VPN).
*   **Шлюзы:**
    *   **Internet Gateway (IGW):** Позволяет ресурсам с публичными IP обмениваться трафиком с интернетом.
    *   **NAT Gateway:** Позволяет ресурсам в приватных подсетях выходить в интернет (для обновлений), но запрещает входящие соединения извне.

### Связность и гибридные сети

Облака предоставляют механизмы объединения сетей:

*   **VPC Peering:** Прямое соединение двух VPC (в одном или разных регионах). Трафик идет по внутренней сети провайдера.
*   **Transit Gateway / Cloud Router:** Центральный хаб для соединения множества VPC и On-premise сетей, заменяющий сложные цепочки пирингов.
*   **Site-to-Site VPN:** Защищенный туннель (IPsec) через публичный интернет между офисом и облаком.
*   **Direct Connect / Interconnect:** Выделенный физический канал связи между ЦОД клиента и облаком для обеспечения минимальных задержек и высокой пропускной способности.

### Управление трафиком и балансировка

*   **Load Balancer (Балансировщики):**
    *   **Network (L4):** Высокопроизводительная балансировка TCP/UDP на основе IP и портов.
    *   **Application (L7):** Умная маршрутизация на основе HTTP-заголовков, путей (URL) и куки.
*   **Anycast IP:** Использование одного IP-адреса, который анонсируется из разных географических точек, направляя пользователя к ближайшему дата-центру.
*   **CDN (Content Delivery Network):** Сеть кеширующих серверов (Edge Locations) для быстрой доставки статического контента пользователям по всему миру.

## Географическая структура

Для обеспечения отказоустойчивости облако делится на уровни:

1.  **Регион (Region):** Географическая область (например, `ru-central1`). Состоит из нескольких зон.
2.  **Зона доступности (Availability Zone / AZ):** Один или несколько дата-центров с независимым питанием и охлаждением. Сетевые задержки между AZ обычно составляют <2 мс.
3.  **Edge Locations:** Точки присутствия для сервисов CDN и DNS, расположенные ближе к пользователям, чем основные регионы.

## Типы облачных хранилищ

Облачные сети тесно связаны с системами хранения. Подробный разбор типов СХД представлен в основном документе: **[Системы хранения данных (СХД): Обзор](../../Concepts/Storage/data_storage_overview.md)**.

| Тип | Назначение | Пример использования |
| :--- | :--- | :--- |
| **Блочное (Block)** | Виртуальные диски для ВМ (NVMe, SSD, HDD). | Системные диски, БД. |
| **Объектное (Object)** | Хранение файлов по API (S3). | Бэкапы, статика, логи. |
| **Файловое (File)** | Сетевые папки (NFS/SMB). | Общие конфиги, медиа-архивы. |

## Экономика трафика (FinOps)

Сетевые расходы в облаке часто становятся скрытой статьей бюджета:

*   **Ingress (Входящий):** Обычно бесплатен из интернета.
*   **Egress (Исходящий):** Трафик из облака в интернет — самый дорогой.
*   **Межзональный (Inter-AZ):** Трафик между зонами доступности одного региона часто платный (хотя дешевле внешнего).
*   **Внутризонный (Intra-AZ):** Обычно бесплатен.
