# Облачные сети (Cloud Networking)

## Определение

**Облачная сеть (Cloud Networking)** — это виртуализированная сетевая инфраструктура, предоставляемая как сервис (Network-as-a-Service, NaaS). Она позволяет объединять облачные ресурсы (ВМ, контейнеры, бессерверные функции) в изолированные логические сегменты. В основе лежит технология **Software-Defined Networking (SDN)**, где плоскость управления (Control Plane) отделена от физического оборудования и доступна пользователю через API или GUI.

Современные облачные сети ориентированы на **Service-centric** подход, где сетевые политики привязываются не только к IP-адресам, но и к метаданным (тегам), ролям сервисов и идентификаторам безопасности.

## Основные концепции

### Virtual Private Cloud (VPC)

**VPC (Виртуальное приватное облако)** — логически изолированный раздел публичного облака.

*   **Изоляция:** Трафик внутри VPC инкапсулируется (VXLAN, Geneve) и полностью отделен от трафика других клиентов.
*   **Подсети (Subnets):** Сегментация VPC по CIDR-диапазонам. 
    *   **Публичные:** Имеют прямой маршрут к **Internet Gateway (IGW)**. Предназначены для ресурсов, требующих доступности извне (например, Load Balancers, Bastion hosts).
    *   **Приватные:** Не имеют прямого маршрута к IGW. Для исходящего доступа в интернет (например, для обновления ПО) используют **NAT Gateway**, который скрывает внутренние IP-адреса ресурсов.
*   **Route Tables (Таблицы маршрутизации):** Управляют направлением трафика на уровне подсетей. Содержат правила, определяющие, через какой шлюз (IGW, NAT GW, Peering) должен проходить пакет для конкретного диапазона назначений.
*   **Виртуальные интерфейсы (vNIC/ENI):** Логические сетевые карты, которые можно динамически привязывать к инстансам.

### Безопасность и фильтрация

Облачные сети используют многоуровневую модель защиты:

1.  **Security Groups (SG):** Виртуальные файрволы на уровне интерфейса (vNIC). 
    *   **Stateful:** Если входящий пакет разрешен, ответный исходящий разрешается автоматически.
    *   **Гранулярность:** Работают на уровне инстансов/сервисов.
2.  **Network ACL (NACL):** Дополнительный уровень защиты на уровне подсети.
    *   **Stateless:** Правила для входящего и исходящего трафика должны быть настроены независимо.
    *   **Приоритет:** Обрабатываются раньше, чем Security Groups.
3.  **Cloud Firewall:** Централизованный сервис для фильтрации трафика между VPC, регионами или On-premise сетями с поддержкой IPS/IDS и L7-фильтрации.

## Связность и гибридные архитектуры

Облака предоставляют гибкие механизмы объединения распределенных сетей:

*   **VPC Peering:** Соединение двух VPC. Трафик остается внутри магистральной сети провайдера. Обычно не поддерживает транзитивную маршрутизацию (А ↔ Б ↔ В не означает А ↔ В).
*   **Transit Gateway / Cloud Router:** Хаб для централизованного управления связностью сотен VPC и удаленных офисов. Поддерживает транзитивность.
*   **Private Link / VPC Endpoints:** Позволяют ресурсам VPC получать доступ к облачным сервисам (S3, БД) или партнерским API через внутреннюю сеть облака, не выходя в публичный интернет.
    *   **Gateway Endpoints:** Маршрутизация на уровне таблиц (традиционно для S3/DynamoDB).
    *   **Interface Endpoints:** Использование внутренних IP-адресов из подсети VPC.
*   **Site-to-Site VPN:** Защищенный туннель (IPsec) через интернет.
*   **Direct Connect / Dedicated Interconnect:** Выделенная физическая линия (L2/L3) от ЦОД клиента до точки присутствия облака.

## Управление трафиком и балансировка

*   **Load Balancing (L4/L7):**
    *   **Network (L4):** Балансировка TCP/UDP с минимальными задержками.
    *   **Application (L7):** Маршрутизация на основе HTTP-заголовков, путей и TLS-терминация.
*   **Global Load Balancing (GSLB):** Распределение трафика между регионами на основе географии пользователя или состояния ресурсов (Health Checks).
*   **Anycast и Global Accelerator:** Использование единого IP-адреса, анонсируемого из множества Edge-локаций, для оптимизации пути трафика до облачной инфраструктуры.
*   **CDN (Content Delivery Network):** Кеширование контента в точках присутствия (Edge) для снижения задержек.

## Наблюдаемость и мониторинг

Современные облачные сети предоставляют глубокую аналитику без установки агентов:

*   **VPC Flow Logs:** Запись информации о принятом и отклоненном IP-трафике. Используется для отладки политик безопасности и анализа сетевых аномалий.
*   **Traffic Mirroring:** Дублирование трафика с виртуальных интерфейсов на сторонние системы анализа (IDS, DPI).
*   **Сетевая топология (Network Topology):** Визуализация связей между всеми ресурсами и шлюзами в реальном времени.

## Географическая структура

1.  **Регион (Region):** Географически изолированная группа дата-центров (например, `europe-west1`).
2.  **Зона доступности (Availability Zone / AZ):** Один или несколько ЦОД с независимой инженерной инфраструктурой. Сетевая связность между AZ обеспечивает высокую доступность приложений.
3.  **Local Zones / Wavelength:** Вынос облачных ресурсов ближе к крупным городам или внутрь сетей 5G для приложений с ультранизкой задержкой.

## Сетевой доступ к хранилищам

Доступ к СХД в облаке определяется сетевыми политиками. Подробнее о типах данных: **[Системы хранения данных (СХД): Обзор](../../Concepts/Storage/data_storage_overview.md)**.

| Тип доступа | Особенности | Сценарий |
| :--- | :--- | :--- |
| **Публичный эндпоинт** | Доступ через Internet Gateway по SSL/TLS. | Публичные статические сайты, мобильные приложения. |
| **VPC Endpoint** | Доступ по внутренней сети без IGW. | Безопасный бэкап БД в S3, доступ из приватных подсетей. |
| **Монтирование (NFS/SMB)** | Прямое подключение к файловым системам по IP из VPC. | Shared storage для группы ВМ, CI/CD артефакты. |

## Экономика трафика (FinOps)

*   **Входящий (Ingress):** Обычно бесплатен.
*   **Исходящий (Egress):** Самый дорогой тип трафика (в интернет).
*   **Inter-AZ:** Трафик между зонами доступности одного региона часто тарифицируется.
*   **Inter-Region:** Передача данных между регионами дороже, чем внутри одного.
