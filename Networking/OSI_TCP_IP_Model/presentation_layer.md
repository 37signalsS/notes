# Уровень представления (L6)

## Определения

**Уровень представления (Presentation Layer, L6)** — шестой уровень эталонной модели **OSI (Open Systems Interconnection)**. Он отвечает за трансляцию данных между сетевым форматом и форматом, который ожидает приложение. Уровень L6 обеспечивает синтаксическую совместимость систем, имеющих разные внутренние способы представления данных.

На этом уровне данные рассматриваются с точки зрения их структуры и синтаксиса, а не просто как поток бит (L1) или сегменты (L4).

- **PDU (Protocol Data Unit):** Данные (Data).
- **Адресация:** Отсутствует. Использует механизмы нижестоящих уровней (L4/L5).

## Базовые концепции

### Основные функции

1.  **Кодирование и трансляция данных:** Преобразование между различными кодировками символов и порядком байтов (Endianness).
2.  **Сжатие (Compression):** Уменьшение объема передаваемой информации для оптимизации использования канала связи.
3.  **Шифрование (Encryption):** Обеспечение конфиденциальности и целостности данных на уровне их представления (например, TLS).
4.  **Сериализация (Serialization):** Преобразование сложных структур данных (объектов) в поток байтов для передачи и обратно (десериализация).

### Статус в современных сетях (TCP/IP)

В стеке **TCP/IP** уровень представления не выделен в отдельный протокольный слой. Его функции распределены:
- **Прикладной уровень (L7):** Большинство протоколов (HTTP/2, gRPC) самостоятельно занимаются сжатием и сериализацией.
- **Библиотеки и Middleware:** Шифрование (OpenSSL/BoringSSL) и сериализация (Protobuf, Jackson) реализуются программно внутри приложения.

## Технические детали реализации

### Представление данных и кодирование

| Параметр | Описание | Примеры |
| :--- | :--- | :--- |
| **Кодировка текста** | Сопоставление символов числовым кодам. | ASCII, UTF-8, UTF-16, EBCDIC |
| **Порядок байтов (Endianness)** | Порядок размещения байтов в многобайтовых числах. Сетевой стандарт — **Big-Endian**. | Big-Endian (Motorola), Little-Endian (Intel) |
| **ASN.1** | Абстрактная синтаксическая нотация. Классический пример L6 для описания структур данных. | Используется в сертификатах X.509 и протоколе SNMP |

### Сжатие данных

В современных высоконагруженных системах (2026+) используются алгоритмы с разным балансом скорости и степени сжатия:

- **Gzip (Deflate):** Стандарт для веб-трафика (совместимость).
- **Brotli:** Оптимизирован для статического контента в вебе (лучшее сжатие, чем Gzip).
- **Zstandard (Zstd):** Разработка Meta. Высочайшая скорость декомпрессии, стандарт для логов и передачи больших объемов данных.

### Сериализация объектов

| Формат | Тип | Особенности |
| :--- | :--- | :--- |
| **JSON** | Текстовый | Легко читается человеком, но избыточен по объему. Стандарт для REST API. |
| **Protocol Buffers (Protobuf)** | Бинарный | Разработка Google. Очень компактный и быстрый. Основа для gRPC. |
| **Apache Avro** | Бинарный | Хранит схему вместе с данными. Стандарт для Big Data (Hadoop, Kafka). |
| **MessagePack** | Бинарный | «JSON в бинарном виде». Совместим с типами JSON, но компактнее. |

## Практические сценарии

### Сценарий 1: Работа TLS 1.3 (Инспекция L6 функций)

Хотя TLS часто относят к уровню 4 или 7 в TCP/IP, функционально он выполняет задачи L6:
- **Согласование (Negotiation):** Выбор общего алгоритма шифрования и версии протокола.
- **ALPN (Application-Layer Protocol Negotiation):** Выбор прикладного протокола (например, переход с HTTP/1.1 на HTTP/2) внутри защищенного соединения.
- **Шифрование:** Преобразование открытого текста прикладного уровня в шифротекст.

### Сценарий 2: Передача медиаданных

Форматы **JPEG**, **MPEG** или **MP3** по своей сути являются спецификациями уровня представления. Они определяют, как дискретные отсчеты (звука или цвета) должны быть закодированы для минимизации потерь и обеспечения возможности воспроизведения на любом конечном устройстве, независимо от его архитектуры.

### Сценарий 3: gRPC и Protobuf

В микросервисной архитектуре уровень представления реализуется через кодогенерацию:
1. Описание структуры данных в `.proto` файле.
2. Генерация кода «переводчика» для конкретного языка (Go, Java, Python).
3. При передаче данные L7 (объект в памяти) проходят через этот слой и превращаются в компактный бинарный поток L6.
