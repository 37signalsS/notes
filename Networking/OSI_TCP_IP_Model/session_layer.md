# Сеансовый уровень (L5)

## Определения

**Сеансовый уровень (L5, Session Layer)** — пятый уровень эталонной [модели OSI](./osi_model.md), ответственный за организацию, управление и разрыв сеансов связи (диалогов) между прикладными процессами на разных узлах сети.

- **PDU (Protocol Data Unit):** Данные (Data)
- **Адресация:** Напрямую отсутствует (опирается на порты транспортного уровня или идентификаторы сессий прикладного уровня)

## Базовые концепции

### Основные функции

1.  **Управление диалогом:** Определение режима передачи (дуплекс — одновременно в обе стороны, полудуплекс — по очереди) и очередности передачи данных.
2.  **Синхронизация:** Установка контрольных точек (checkpoints) в потоке данных. В случае сбоя передача возобновляется с последней подтвержденной точки, а не с самого начала.
3.  **Разделение сеансов:** Обеспечение того, чтобы данные разных сессий не перемешивались (особенно важно при мультиплексировании нескольких логических сессий в одно соединение).
4.  **Управление маркерами:** Предотвращение одновременного выполнения критических операций несколькими сторонами.

### Статус в модели TCP/IP

В практической модели **TCP/IP** сеансовый уровень не выделен как отдельный слой. Его задачи решаются следующими способами:
- **Прикладным уровнем:** Протоколы (например, HTTP/2 или gRPC) сами управляют жизненным циклом сессий и потоков.
- **Транспортным уровнем:** Частично функции управления соединением выполняет TCP (Handshake/Keep-alive).
- **Библиотеками:** TLS (Transport Layer Security) обеспечивает возобновление сессий.

## Современные реализации и сценарии

### 1. QUIC: Идентификатор соединения (Connection ID)
Классические сессии TCP (L4) привязаны к 4-tuple (IP и порт отправителя/получателя). При смене сети (например, переключение с Wi-Fi на 4G) сессия разрывается.
Протокол **QUIC** (основа HTTP/3) реализует функции сеансового уровня через **Connection ID**. Это позволяет сохранять сессию активной даже при смене IP-адреса клиента («мобильность сессии»).

### 2. TLS 1.3: Возобновление сессии (Session Resumption)
Механизм **0-RTT (Zero Round Trip Time)** позволяет клиенту и серверу возобновить ранее установленную защищенную сессию без полного рукопожатия. Это реализуется через PSK (Pre-Shared Key) и тикеты сессий, что является классической задачей L5 по управлению состоянием диалога.

### 3. gRPC и HTTP/2 Streams
В рамках одного TCP-соединения (L4) может существовать множество независимых потоков (Streams). gRPC использует это для реализации сложных диалогов:
- Унарные запросы (один запрос — один ответ).
- Стриминг (клиентский, серверный или двунаправленный).
Управление этими потоками — это современная реализация функций сеансового уровня в стеке TCP/IP.

### 4. SSH (Secure Shell)
Протокол SSH — пример объединения функций нескольких уровней. Он реализует:
- **Сеансовый уровень:** Управление сессией терминала, аутентификация, мультиплексирование каналов.
- **Уровень представления:** Шифрование и сжатие.
- **Прикладной уровень:** Предоставление интерфейса командной строки.

## Сводка по модели OSI

| Характеристика | Описание |
| :--- | :--- |
| **Единица данных (PDU)** | Данные (Data) |
| **Ключевая задача** | Управление диалогом и синхронизация |
| **Оборудование** | Хосты (серверы, рабочие станции), сетевые шлюзы |
| **Протоколы и API** | RPC, gRPC, [Sockets API](../Concepts/socket_api.md), NetBIOS, PAP (Password Authentication Protocol) |
