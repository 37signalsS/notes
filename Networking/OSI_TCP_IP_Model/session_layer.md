# Сеансовый уровень (L5)

## Определения

**Сеансовый уровень (L5, Session Layer)** — пятый уровень эталонной [модели OSI](./osi_model.md), ответственный за организацию, поддержание, управление и разрыв сеансов связи (диалогов) между прикладными процессами на разных узлах сети.

- **PDU (Protocol Data Unit):** Данные (Data) — уникальная особенность L5: он не добавляет собственный заголовок, а управляет сессиями через внутренние механизмы протоколов верхних уровней.
- **Адресация:** Напрямую отсутствует. Опирается на порты транспортного уровня (L4) или идентификаторы сессий прикладного уровня (L7).

### Единицы данных и инкапсуляция

| Характеристика | Описание |
| :--- | :--- |
| **PDU** | Данные (Data) |
| **Заголовок L5** | Отсутствует (в отличие от L4/L3/L2). Функции сеансов реализуются протоколами верхних уровней |
| **Идентификаторы сессий** | Session ID (TLS), Stream ID (HTTP/2), Connection ID (QUIC) |
| **Размер overhead** | 0 байт (управление сессиями — логическая функция) |

**Примечание:** В реальных стеках протоколов L5 не добавляет отдельного заголовка. Вместо этого функции сеансового уровня реализуются через:
- **TLS:** Session ID / Session Ticket (32-256 байт в扩展ах)
- **HTTP/2:** Stream ID (4 байта в заголовке кадра)
- **QUIC:** Connection ID (0-20 байт)

## Базовые концепции

### Связь с соседними уровнями

```text
L7 (Прикладной)
    ↓ Запросы на создание/завершение сессий
L5 (Сеансовый) ←─── Управление диалогами, контрольные точки, токены
    ↓ Использование транспортных соединений
L4 (Транспортный)
    ↓ Доставка сегментов
L3 (Сетевой)
```

**Взаимодействие с L4 (Транспортный):**
- L5 использует одно транспортное соединение (TCP/UDP) для нескольких логических сессий
- Мультиплексирование: несколько сессий поверх одного TCP-соединения (HTTP/2 streams)
- Демультиплексирование: маршрутизация данных по идентификаторам сессий

**Взаимодействие с L7 (Прикладной):**
- L7 инициирует создание сессий (SIP INVITE, HTTP CONNECT)
- L5 управляет жизненным циклом: establecimiento → datos → terminación
- L7 определяет семантику сессии (аутентификация, бизнес-логика)

### Основные функции

1.  **Управление диалогом (Dialog Control):** Определение режима передачи данных между узлами:
    - **Симплекс (Simplex):** Односторонняя передача.
    - **Полудуплекс (Half-duplex):** Передача в обоих направлениях, но строго по очереди. Уровень L5 контролирует, чья очередь передавать данные (например, с помощью токенов или маркеров).
    - **Дуплекс (Full-duplex):** Одновременная передача в обоих направлениях.
2.  **Синхронизация и восстановление (Synchronization):** Установка контрольных точек (checkpoints) в потоке данных. Если во время длительной передачи (например, большого файла) происходит сбой сети, сеансовый уровень обеспечивает возобновление передачи с последней подтвержденной контрольной точки, избегая необходимости передавать все данные заново с самого начала.
3.  **Разделение сеансов (Session Separation):** Разграничение данных, относящихся к разным логическим сессиям, чтобы они не перемешивались. Это особенно важно, когда несколько независимых сессий мультиплексируются поверх одного транспортного соединения (например, в HTTP/2 или gRPC).
4.  **Управление маркерами (Token Management):** Механизм предотвращения коллизий, гарантирующий, что критичные операции (например, изменение общего состояния) не выполняются одновременно двумя сторонами.

### Статус в модели TCP/IP

В практической модели **TCP/IP** сеансовый уровень (как и уровень представления L6) не выделен как отдельный слой. Его задачи распределены:
- **Прикладной уровень:** Большинство протоколов (например, HTTP, SMTP, SIP, RPC) сами управляют жизненным циклом сессий, авторизацией и потоками данных.
- **Транспортный уровень:** Базовое управление соединением (Handshake/Keep-alive, разрыв связи) берет на себя TCP.
- **Связующее ПО (Middleware) и библиотеки:** Например, TLS обеспечивает защищенный сеанс и его возобновление.

### Сводка по модели OSI

| Характеристика | Описание |
| :--- | :--- |
| **Единица данных (PDU)** | Данные (Data) |
| **Ключевая задача** | Управление диалогом, синхронизация и контрольные точки |
| **Оборудование** | Хосты (серверы, рабочие станции), сетевые шлюзы, SBC (Session Border Controllers) |

### Классические и современные протоколы L5

| Протокол | Тип | Описание | Где используется |
| :--- | :--- | :--- | :--- |
| **RPC (Remote Procedure Call)** | Классический | Вызов процедур на удалённых хостах仿佛 локальных | Распределённые системы, микросервисы (gRPC) |
| **NetBIOS** | Классический | Интерфейс для обмена данными в ЛВС Windows | legacy-системы, SMB |

## Практические сценарии

### 1. QUIC и мобильность сессии
Классические сессии TCP (L4) привязаны к 4-tuple (IP и порт отправителя/получателя). При смене сети (например, переключение смартфона с Wi-Fi на 4G) транспортная сессия разрывается, и её нужно переустанавливать.
Протокол **QUIC** (основа HTTP/3) реализует функции сеансового уровня посредством **Connection ID** (идентификатора соединения). Это позволяет сохранять сессию активной и прозрачно переносить её на новый IP-адрес без переподключения («мобильность сессии»).

### 2. TLS 1.3: Возобновление сессии (Session Resumption)
Механизм **0-RTT (Zero Round Trip Time)** в TLS 1.3 позволяет клиенту и серверу возобновить ранее установленную защищенную сессию без затрат на полное криптографическое рукопожатие. Это реализуется через PSK (Pre-Shared Key) и сессионные тикеты, что является классическим примером управления состоянием диалога (L5) на уровне безопасности.

### 3. gRPC и мультиплексирование потоков (HTTP/2 Streams)
В рамках единственного TCP-соединения (L4) может существовать множество независимых потоков (Streams). **gRPC** активно использует это для реализации сложных коммуникационных диалогов:
- Унарные запросы (один запрос — один ответ).
- Стриминг (клиентский, серверный или двунаправленный).
Изоляция, контроль очередности и управление жизненным циклом этих потоков внутри одного транспортного канала — современная реализация функций сеансового уровня.

### 4. SSH (Secure Shell)
Протокол SSH является примером инкапсуляции функций нескольких уровней (от L5 до L7). На уровне, эквивалентном L5, он реализует:
- Управление сессией терминала.
- Аутентификацию пользователя.
- Мультиплексирование (проброс портов и создание нескольких каналов внутри одного зашифрованного соединения).

### 5. Session Border Controllers (SBC) в VoIP
В телефонии и видеосвязи (VoIP) протокол **SIP (Session Initiation Protocol)** используется для создания, изменения и завершения сеансов связи. Устройства **SBC** работают на уровнях L5-L7, управляя SIP-диалогами, обеспечивая безопасность, трансляцию адресов для сессий и контроль качества обслуживания (QoS) между различными сетями связи.

### 6. WebSocket: Двунаправленные сессии
Протокол **WebSocket** (RFC 6455) устанавливает долгоживущие двунаправленные сессии поверх HTTP:
- Начинается с HTTP-запроса (Handshake) на L7
- После Upgrade переключается на режим двустороннего обмена данными (L5)
- Управление ping/pong для поддержания активности сессии
- Используется в реалтайм-приложениях: чаты, биржевые терминалы, online-игры

## Инструментарий диагностики

Для мониторинга и отладки сеансового уровня (L5) используются инструменты, отображающие активные соединения и сессии:

| Инструмент | Назначение | Пример использования |
| :--- | :--- | :--- |
| **`ss`** | Просмотр активных TCP-соединений и сокетов | `ss -tnp` — все TCP-соединения с процессами |
| **`lsof`** | Открытие файлов и сетевых соединений процесса | `lsof -i -P` — сетевые соединения всех процессов |
| **`netstat`** | Статистика соединений (устаревший, заменён `ss`) | `netstat -tna` — все TCP-соединения |
| **`openssl s_client`** | Тестирование TLS-сессий | `openssl s_client -connect example.com:443` |
| **`tcpdump`** | Захват пакетов с фильтрацией по портам/хостам | `tcpdump -i eth0 port 443` |
| **`wireshark`/`tshark`** | Глубокий анализ протоколов и сессий | Анализ TLS-рукопожатий, HTTP/2 потоков |
| **`curl`** | Тестирование HTTP/HTTPS сессий | `curl -v https://example.com` — вывод TLS-сессии |
| **`grpcurl`** | Тестирование gRPC-сервисов | `grpcurl -plaintext localhost:50051 list` |

**Примеры диагностики:**

```bash
# Просмотр TLS-сессий и их статуса
ss -tnp | grep :443
# → ESTAB  0  0  192.168.1.100:49152  93.184.216.34:443  users:(("chrome",pid=1234,fd=123))

# Просмотр установленных TLS-сессий на сервере (Linux)
cat /proc/net/tls_stat
# → TlsDecryptError: 0, TlsRxDeviceError: 0

# Анализ TLS-рукопожатия
openssl s_client -connect example.com:443 -state -debug 2>&1 | grep "SSL-Session"
# → SSL-Session:
#     Protocol  : TLSv1.3
#     Cipher    : TLS_AES_256_GCM_SHA384

# Просмотр HTTP/2 потоков (требуется mod_http2 в Apache)
curl -v --http2 https://example.com 2>&1 | grep "Stream"
# → * Stream #1: type:HEADERS, weight:257, dep:0, excl:0

# Мониторинг SIP-сессий (VoIP)
tcpdump -i eth0 port 5060 -nn -A | grep "SIP/2.0"
# → SIP/2.0 200 OK

# Просмотр WebSocket соединений
ss -tnp | grep ws
# → ESTAB  0  0  192.168.1.100:8765  192.168.1.200:54321
```

## Дополнительная информация

### Безопасность сеансового уровня (L5)

| Угроза | Описание | Защита |
| :--- | :--- | :--- |
| **Session Hijacking** | Перехват или подмена идентификатора сессии | Использование криптографически стойких Session ID, привязка к IP/User-Agent |
| **Replay Attack** | Повторное использование перехваченных данных сессии | Nonce, таймстемпы, монотонные номера в протоколах |
| **Session Fixation** | Принудительная установка известного злоумышленнику ID сессии | Генерация новых Session ID после аутентификации |
| **TLS Downgrade** | Принуждение к использованию устаревших версий TLS | Поддержка только TLS 1.2+, отключение слабых шифров |
| **Man-in-the-Middle** | Перехват трафика между клиентом и сервером | Проверка сертификатов, Certificate Pinning |
| **DoS через сессии** | Исчерпание ресурсов за счёт массового создания сессий | Rate-limiting, таймауты неактивных сессий, лимиты на IP |

**Пример защиты от session fixation (PHP):**
```php
// Регенерация Session ID после аутентификации
session_regenerate_id(true);
```

**Пример мониторинга аномальных сессий:**
```bash
# Поиск множественных сессий с одного IP (возможная атака)
ss -tn | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head
# → 150 192.168.1.100  ← подозрительно много соединений
```

### Современные реализации L5

В современных стеках функции сеансового уровня реализуются распределённо:

| Технология | Реализация L5 | Ключевые особенности |
| :--- | :--- | :--- |
| **Service Mesh (Istio, Linkerd)** | Sidecar-прокси (Envoy) | Управление сессиями между микросервисами: circuit breaking, retry, observability |
| **eBPF (Cilium)** | Программы в ядре Linux | Отслеживание и управление TCP-сессиями на уровне ядра |
| **QUIC** | Connection ID в пользовательском пространстве | Мобильность сессий, 0-RTT, мультиплексирование без HOL blocking |
| **HTTP/2** | Stream ID в заголовках кадров | Мультиплексирование потоков, приоритизация, серверный push |
| **gRPC** | HTTP/2 Streams | Bidirectional streaming, deadline propagation, cancellation |
