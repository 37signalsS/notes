# Канальный уровень (Data Link Layer)

## Определения

**Канальный уровень (Data Link Layer, L2)** — второй уровень [модели OSI](./osi_model.md), обеспечивающий передачу данных между устройствами в пределах одного сетевого сегмента.

- **PDU (Protocol Data Unit — единица данных):** Кадр (Frame)
- **Адресация:** [MAC-адреса](../Concepts/mac_address.md) (Media Access Control — управление доступом к среде, физические адреса)

**Кадр (Frame)** — логическая единица данных канального уровня, состоящая из заголовка (адреса, служебная информация), полезной нагрузки (пакет сетевого уровня) и концевика (контрольная сумма).

**MAC-адрес** — уникальный 48-битный идентификатор сетевого интерфейса. Подробное описание структуры и типов адресов см. в разделе **[MAC-адрес](../Concepts/mac_address.md)**.

## Базовые концепции

### Подуровни канального уровня (IEEE 802)

Согласно стандартам IEEE 802, канальный уровень разделяется на два функциональных подуровня:

| Подуровень | Описание |
| :--- | :--- |
| **LLC (Logical Link Control)** | Управление логическим каналом. Отвечает за взаимодействие с сетевым уровнем, идентификацию протоколов верхнего уровня и контроль потока. |
| **MAC (Media Access Control)** | Управление доступом к среде. Отвечает за физическую адресацию, формирование кадров и регулирование доступа к разделяемой физической среде. |

### Ключевые функции

*   **Формирование кадров (Framing):** Инкапсуляция пакетов сетевого уровня (L3) в кадры с добавлением границ (преамбула, флаги).
*   **Физическая адресация:** Использование MAC-адресов для доставки данных конкретному узлу в локальной сети.
*   **Управление доступом к среде:** Предотвращение или обработка конфликтов при одновременной передаче данных несколькими устройствами (например, через **CSMA/CD** — Carrier Sense Multiple Access with Collision Detection, в [Ethernet](../Protocols/ethernet.md)).
*   **Контроль ошибок:** Обнаружение искажений данных при передаче с помощью циклического избыточного кода (**CRC** — Cyclic Redundancy Check), результат которого записывается в поле **FCS** (Frame Check Sequence).

### Домены в сетях L2 (Layer 2)

#### Домен коллизий (Collision Domain)
Область сети, в которой возможны столкновения сигналов (**коллизии**) при одновременной передаче.
*   **Хаб (концентратор):** Все порты находятся в одном домене коллизий.
*   **Коммутатор:** Каждый порт является отдельным доменом коллизий (в полнодуплексном режиме коллизии отсутствуют).

#### Широковещательный домен (Broadcast Domain)
Логический сегмент сети, в котором широковещательный кадр (адрес `FF:FF:FF:FF:FF:FF`) доставляется всем узлам.
*   **Коммутатор:** По умолчанию объединяет все порты в один широковещательный домен.
*   **VLAN** (Virtual Local Area Network): Разделяет один физический коммутатор на несколько логических широковещательных доменов.
*   **Маршрутизатор:** Разделяет широковещательные домены (не пропускает широковещательный трафик между интерфейсами).

## Практические сценарии

### Коммутатор (Switch)

Интеллектуальное устройство, соединяющее узлы в локальной сети (**LAN**) и принимающее решение о пересылке кадров на основе таблицы MAC-адресов.

**Принцип работы (алгоритм прозрачного моста):**
1.  **Обучение (Learning):** Считывает MAC-адрес отправителя из входящего кадра и заносит его в таблицу вместе с номером порта.
2.  **Пересылка (Forwarding):** Ищет MAC-адрес получателя в таблице. Если найден — отправляет кадр в конкретный порт.
3.  **Затопление (Flooding):** Если адрес получателя неизвестен или является широковещательным — отправляет кадр во все порты, кроме входящего.

Подробные примеры работы и описание конфликтов MAC-адресов см. в разделе **[L2 Switching и VLAN: Определения и концепции](../Concepts/vlan_l2_switching/definitions_and_concepts.md)**.

### Оборудование и виртуализация

*   **Сетевая карта (NIC — Network Interface Card):** Аппаратный компонент, реализующий функции L1 и L2.
*   **Мост (Bridge):** Устройство или программная сущность для объединения сегментов сети. Современный коммутатор — это многопортовый мост.
*   **Виртуальный коммутатор:** Программная реализация коммутатора в средах виртуализации (например, **Linux Bridge** или **Open vSwitch**).
