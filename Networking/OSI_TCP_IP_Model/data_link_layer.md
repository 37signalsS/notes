# Канальный уровень (Data Link Layer)

## Определения

**Канальный уровень** — второй уровень [модели OSI](./osi_model.md), отвечающий за доставку кадров (frame) между устройствами, подключенными к одному сетевому сегменту. Заголовок кадра содержит аппаратные адреса отправителя и получателя, что позволяет определить, какое устройство отправило кадр и какое устройство должно получить и обработать его.

**Кадр (Frame)** — единица данных канального уровня, в которую упаковываются пакеты сетевого уровня. Представьте это как конверт: на нем написан MAC-адрес отправителя и MAC-адрес получателя, а внутри лежат сами данные.

- **PDU (Protocol Data Unit):** Кадр (Frame)
- **Адресация:** [MAC-адреса](../Concepts/mac_address.md) (физические адреса, 48 бит)

### MAC-адрес (Media Access Control)

**MAC-адрес** состоит из 48 бит (6 байт), зашитых в сетевую карту на заводе. 
* Выглядит как шесть пар шестнадцатеричных цифр (например, `00:1A:2B:3C:4D:5E`).
* Каждый сетевой интерфейс в мире имеет уникальный MAC.
* **Важное ограничение:** MAC-адреса работают только в пределах **одной локальной сети**. Они не маршрутизируются, поэтому ваш домашний роутер не может отправить кадр напрямую по MAC-адресу на сервер Google.

## Базовые концепции

### Подуровни канального уровня (IEEE 802)

| Подуровень | Функции |
| :--- | :--- |
| **LLC (Logical Link Control)** | Взаимодействие с сетевым уровнем, мультиплексирование протоколов, контроль потока и ошибок (опционально) |
| **MAC (Media Access Control)** | Физическая адресация (MAC-адреса), управление доступом к общей среде, формирование кадров |

### Задачи канального уровня

| Задача | Описание |
| :--- | :--- |
| **Формирование кадров (Framing)** | Упаковка пакетов в кадры с заголовком и концевиком |
| **Адресация** | Использование MAC-адресов для идентификации в пределах сегмента |
| **Управление доступом к среде (MAC)** | Регулирование доступа к общей среде, предотвращение коллизий |
| **Обнаружение и коррекция ошибок** | Проверка целостности через CRC, исправление ошибок |

#### Коллизия и домен коллизий

**Коллизия** — это столкновение сигналов (пакетов) в сети. Происходит, когда два или более хоста одновременно отправляют данные в общую среду передачи.

**Условия возникновения коллизии:**

- Коллизия может происходить только при **полудуплексном (half-duplex)** подключении, когда для приёма и передачи используется один и тот же физический канал.
- При **полнодуплексном (full-duplex)** режиме (например, в коммутируемом Ethernet) коллизии невозможны, так как используются раздельные каналы для приёма и передачи.

**Домен коллизий (Collision Domain)** — это сегмент сети, в пределах которого может произойти коллизия. Все устройства в одном домене коллизий делят одну и ту же полосу пропускания и конкурируют за доступ к среде.

| Устройство | Домен коллизий |
| :--- | :--- |
| **Хаб (концентратор)** | Все порты в одном домене коллизий |
| **Коммутатор** | Каждый порт — отдельный домен коллизий |
| **Маршрутизатор** | Каждый интерфейс — отдельный домен коллизий |

| Категория | Примеры |

## Практические сценарии

### Коммутатор (Switch)

**Назначение:** Интеллектуальное устройство для соединения узлов в **локальной сети (LAN)**. Основа технологии **коммутируемого Ethernet**.

**Уровень OSI:** Канальный уровень (L2), оперирует [MAC-адресами](../Concepts/mac_address.md).

**Принцип работы (алгоритм прозрачного моста):**

| Шаг | Описание |
| :--- | :--- |
| **1. Таблица коммутации** | Внутри коммутатора — MAC-таблица: MAC-адрес → порт |
| **2. Обратное обучение** | Коммутатор считывает **MAC-адрес отправителя** и запоминает порт |
| **3. Пересылка** | По **MAC-адресу получателя** ищет в таблице и отправляет на нужный порт |
| **4. Flooding** | Если адрес не найден (или широковещательный `FF:FF:FF:FF:FF:FF`) — отправка на все порты, кроме входного |

**Преимущества:**

- **Высокая производительность:** Соединения "точка-точка" в полнодуплексном режиме устраняют коллизии
- **Высокая безопасность:** Кадры доставляются только целевому получателю

**Домен коллизии:**

Коммутатор ограничивает домен коллизий до одного хоста и порта, к которому тот подключён. В отличие от хаба (концентратора), где все порты находятся в одном домене коллизий, коммутатор:

- Имеет буферы памяти для временного хранения пакетов
- При одновременном поступлении пакетов на разные порты помещает их в оперативную память
- Последовательно обрабатывает и отправляет пакеты в целевые порты без возникновения коллизий

Каждый порт коммутатора представляет собой отдельный домен коллизии.

**Практический пример работы коммутатора:**

Рассмотрим сеть из трёх хостов, подключённых к коммутатору:

- `host_1` → порт 1, MAC: `00:00:00:00:00:01`
- `host_2` → порт 2, MAC: `00:00:00:00:00:02`
- `host_3` → порт 3, MAC: `00:00:00:00:00:03`

**Сценарий 1: host_1 отправляет пакет host_2 (таблица пуста)**

| Шаг | Действие | Таблица коммутации |
| :--- | :--- | :--- |
| 1 | Таблица коммутации пуста | — |
| 2 | Пакет от `host_1` поступает на порт 1 | `00:00:00:00:00:01` → порт 1 |
| 3 | Поиск MAC `00:00:00:00:00:02` в таблице | Не найден |
| 4 | **Flooding** — отправка на порты 2 и 3 | — |

**Сценарий 2: host_2 отвечает host_1 (таблица содержит одну запись)**

| Шаг | Действие | Таблица коммутации |
| :--- | :--- | :--- |
| 1 | Пакет от `host_2` поступает на порт 2 | `00:00:00:00:00:01` → порт 1<br>`00:00:00:00:00:02` → порт 2 |
| 2 | Поиск MAC `00:00:00:00:00:01` в таблице | Найден (порт 1) |
| 3 | **Unicast** — отправка только на порт 1 | — |

**Сценарий 3: host_1 отправляет пакет host_3**

- В таблице есть записи для `host_1` и `host_2`, но нет для `host_3`
- Коммутатор выполняет **flooding** на порты 2 и 3
- После ответа от `host_3` таблица дополнится записью: `00:00:00:00:00:03` → порт 3

**Важные особенности:**

| Ситуация | Поведение коммутатора |
| :--- | :--- |
| **MAC получателя отсутствует в таблице** | Flooding на все порты, кроме входного (как хаб) |
| **Широковещательный пакет** (`FF:FF:FF:FF:FF:FF`) | Всегда flooding на все порты |
| **Дублирование MAC на разных портах** | Старая запись удаляется, новая добавляется с текущим портом |
| **Пакет с неизвестным MAC в сети** | Постоянный flooding — коммутатор всегда отправляет на все порты |

**Конфликт MAC-адресов:**

Если в одном сегменте сети появятся два хоста с одинаковым MAC-адресом, коммутатор будет периодически переписывать запись в таблице коммутации, связывая адрес то с одним, то с другим портом. Это приведёт к тому, что трафик будет доставляться непредсказуемо — часть пакетов одному хосту, часть другому.

### Другие устройства L2

| Устройство | Описание |
| :--- | :--- |
| **Мост (Bridge)** | Соединяет 2+ сегмента сети на L2. Современные коммутаторы — многопортовые мосты |
| **Сетевая карта (NIC)** | Плата, реализующая функции канального уровня |
