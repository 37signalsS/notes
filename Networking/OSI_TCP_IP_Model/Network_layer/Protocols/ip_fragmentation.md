# Фрагментация IP-пакетов

## Определения

**Фрагментация** — процесс разделения IP-пакета на более мелкие части (фрагменты), когда его общий размер превышает **MTU (Maximum Transmission Unit)** следующего сетевого сегмента.

**MTU** — максимальный размер полезной нагрузки (включая IP-заголовок, но без канального заголовка), который может быть передан по данному каналу связи. Стандартный MTU для Ethernet — **1500 байт**.

## Базовые концепции

### Причины фрагментации

1. **Разные MTU в сетях:** Интернет состоит из разнородных сетей (Ethernet, Wi-Fi, PPP, VPN-туннели) с разным MTU.
2. **Большие объёмы данных:** Приложения генерируют данные, которые при инкапсуляции превышают MTU участка пути.

### Механизм фрагментации (IPv4)

1. **Маршрутизатор** (или отправитель) определяет, что размер пакета превышает MTU интерфейса.
2. Пакет разбивается на фрагменты, каждый получает собственный IP-заголовок.
3. Поля заголовка для управления фрагментацией:
   - **Identification:** все фрагменты одного пакета имеют одинаковый ID
   - **Flags (MF — More Fragments):** установлен во всех фрагментах, кроме последнего
   - **Fragment Offset:** позиция фрагмента относительно начала исходного пакета (в 8-байтных блоках)
4. **Сборка:** производится **только на конечном хосте-получателе**. Маршрутизаторы фрагменты не собирают.

### Недостатки фрагментации

- **Нагрузка на CPU:** фрагментация и сборка требуют ресурсов от маршрутизаторов и хостов
- **Снижение производительности:** потеря одного фрагмента требует повторной передачи всего пакета
- **Риск DoS-атак:** атаки типа "fragment overlap" эксплуатируют уязвимости сборки
- **Проблемы с файрволами/NAT:** трудности с обработкой фрагментов, когда заголовки L4 не в первом фрагменте

## Практические сценарии

### Фрагментация в IPv6

В IPv6 фрагментация реализована иначе:

| Критерий | IPv4 | IPv6 |
|----------|------|------|
| **Где фрагментируется** | Любой маршрутизатор на пути | Только отправитель (end-host) |
| **Заголовок фрагментации** | Встроен в основной заголовок | Отдельное расширение заголовка (Extension Header) |
| **Механизм обнаружения MTU** | Опциональный PMTUD | Обязательный Path MTU Discovery |
| **Минимальный MTU** | 68 байт | 1280 байт (обязательно) |
| **DF бит** | Есть (Don't Fragment) | Не нужен — фрагментация всегда end-to-end |

**Причины изменений в IPv6:**

1. **Производительность:** фрагментация на маршрутизаторах требует значительных ресурсов CPU
2. **Простота оборудования:** маршрутизаторы работают быстрее без фрагментации
3. **Безопасность:** упрощается защита от DoS-атак с использованием фрагментов

**Расширение заголовка Fragment (IPv6):**

```
| Next Header (8 бит) | Reserved (8 бит) | Fragment Offset (13 бит) | Res | M (1 бит) | Identification (32 бита) |
```

- **M (More Fragments):** 1 = есть ещё фрагменты, 0 = последний фрагмент
- **Identification:** 32-битный идентификатор (vs 16 бит в IPv4)

**Процесс фрагментации IPv6:**

1. Отправитель определяет MTU пути через Path MTU Discovery (PMTUD)
2. Если пакет превышает MTU, **только отправитель** фрагментирует пакет
3. Каждый фрагмент получает: копию основных заголовков IPv6 + расширение Fragment + часть данных
4. Маршрутизаторы просто пересылают фрагменты
5. Получатель собирает фрагменты по полю Identification

**Если пакет слишком большой:**

- Отправитель получает ICMPv6 Packet Too Big (Type 2)
- Уменьшает размер пакета и повторяет отправку

### Как избежать/минимизировать фрагментацию

1. **Path MTU Discovery (PMTUD):** механизм определения минимального MTU на пути следования пакета через ICMP-сообщения
2. **Увеличение MTU:** настройка большего MTU в локальных сетях (Jumbo Frames)
3. **TCP MSS Clamping:** ограничение максимального размера TCP-сегмента (MSS) в SYN-пакетах на маршрутизаторе
