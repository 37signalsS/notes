# Фрагментация IP-пакетов

## Определения

**Фрагментация IP** — процесс разделения одного IP-пакета на несколько частей (фрагментов) меньшего размера. Это необходимо, когда пакет должен пройти через сегмент сети с **MTU (Maximum Transmission Unit)**, который меньше текущего размера пакета.

**MTU (Maximum Transmission Unit)** — максимальный размер кадра канального уровня (L2), который может быть передан в данном сегменте. Для стандартного Ethernet это **1500 байт**.

## Базовые концепции

### Почему фрагментация нежелательна

В современных сетях (2026+) фрагментации стараются избегать по следующим причинам:
1.  **Нагрузка на CPU:** Процесс нарезки на маршрутизаторах и сборки на хостах требует вычислительных ресурсов.
2.  **Эффективность TCP:** При потере одного фрагмента TCP-стек вынужден переотправлять **весь исходный пакет**, а не только потерянную часть.
3.  **Безопасность:** Фрагментированные пакеты сложнее анализировать брандмауэрам и системам IDS/IPS.
4.  **Таймауты сборки:** Хост-получатель держит фрагменты в памяти до получения всех частей. Если один фрагмент задержится или потеряется, буфер может переполниться.

## Механизм фрагментации в IPv4

В IPv4 фрагментация может выполняться как самим отправителем, так и промежуточными маршрутизаторами (если не установлен флаг DF).

### Поля заголовка для управления фрагментацией

Для восстановления исходного пакета используются три поля в заголовке IPv4:

1.  **Identification (16 бит):** Уникальный ID исходного пакета. Все фрагменты одного пакета имеют одинаковый ID.
2.  **Flags (3 бита):**
    - **Reserved:** Не используется (всегда 0).
    - **DF (Don't Fragment):** Если 1 — фрагментация запрещена. Если пакет больше MTU, он будет отброшен с отправкой ICMP `Fragmentation Needed`.
    - **MF (More Fragments):** Если 1 — это не последний фрагмент. Если 0 — последний.
3.  **Fragment Offset (13 бит):** Смещение данных этого фрагмента относительно начала исходных данных.
    - **Важно:** Смещение измеряется в **8-байтовых блоках (октетах)**. Например, если смещение 185, то данные начинаются с `185 * 8 = 1480`-го байта.

### Алгоритм расчета (Пример)

Исходный пакет 4000 байт (20 байт заголовок + 3980 байт данные) должен пройти через сеть с MTU 1500.
Максимальный размер данных в фрагменте: `1500 - 20 = 1480`. 1480 кратно 8 (требование Offset).

| Фрагмент | Размер (общий) | Данные | MF | Offset | Диапазон данных |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **№1** | 1500 | 1480 | 1 | 0 | 0 – 1479 |
| **№2** | 1500 | 1480 | 1 | 185 | 1480 – 2959 |
| **№3** | 1040 | 1020 | 0 | 370 | 2960 – 3979 |

## Особенности фрагментации в IPv6

В IPv6 философия фрагментации кардинально изменена для повышения производительности ядра сети:
- **Маршрутизаторам запрещено фрагментировать пакеты.** Если пакет велик, он отбрасывается, и отправителю летит ICMPv6 `Packet Too Big`.
- **End-to-End:** Фрагментация выполняется **только отправителем**.
- **Минимальный MTU:** Любое звено в IPv6 сети обязано поддерживать MTU не менее **1280 байт**.
- **Fragment Header:** Информация о фрагментации вынесена в расширенный заголовок (Extension Header), чтобы не замедлять обработку обычных пакетов.

Подробнее: **[Фрагментация в IPv6](../../../Protocols/ipv6_overview.md#фрагментация-в-ipv6)**.

## Безопасность и уязвимости

Фрагментация является классическим вектором сетевых атак:

1.  **Tiny Fragment Attack:** Отправитель создает первый фрагмент настолько малым, что заголовок L4 (порты TCP/UDP) не помещается в него полностью, а переносится во второй фрагмент. Это позволяет обходить простые ACL, которые фильтруют только первый фрагмент.
2.  **Fragment Overlap:** Создание фрагментов с перекрывающимися смещениями. Разные ОС по-разному собирают такие пакеты (одни предпочитают первый пришедший байт, другие — последний), что позволяет «спрятать» вредоносный код от IDS.
3.  **Reassembly Timeout DoS:** Отправка множества неполных цепочек фрагментов для исчерпания памяти хоста, выделенной под буфер сборки.

## Взаимодействие с инфраструктурой

### Stateful Firewalls и NAT
Современные брандмауэры (nftables, iptables с `conntrack`) выполняют **виртуальную дефрагментацию**. Они собирают пакет в памяти, анализируют его целиком и только потом пропускают фрагменты дальше. Это защищает от атак на перекрытие, но требует ресурсов.

### Как избежать фрагментации
1.  **Path MTU Discovery (PMTUD):** Механизм определения минимального MTU на всем пути. Требует разрешения ICMP сообщений (Type 3 Code 4 в IPv4, Type 2 в IPv6).
2.  **TCP MSS Clamping:** Маршрутизатор перехватывает SYN-пакеты и уменьшает в них значение MSS, заставляя хосты сразу отправлять пакеты нужного размера.
    - Подробнее: **[MTU и диагностика в VPN](../mtu_and_vpn.md)**.
