# Фрагментация IP-пакетов

**Фрагментация** — это процесс разделения IP-пакета на более мелкие части (фрагменты), когда его общий размер превышает **MTU (Maximum Transmission Unit)** следующего сетевого сегмента. MTU — это максимальный размер полезной нагрузки (включая IP-заголовок, но без канального заголовка), который может быть передан по данному каналу связи.

## Почему происходит фрагментация?

1. **Разные MTU в сетях:** Интернет состоит из множества разнородных сетей (Ethernet, Wi-Fi, PPP, VPN-туннели), каждая из которых имеет свой MTU. Например, стандартный MTU для Ethernet — 1500 байт. Если пакет размером 1500 байт проходит через VPN-туннель, который добавляет свой заголовок, то эффективный MTU для IP-пакета внутри туннеля уменьшается, и исходный пакет может быть фрагментирован.
2. **Большие приложения данные:** Приложения могут генерировать большие объемы данных, которые при упаковке в IP-пакеты превышают MTU какого-либо участка пути.

## Как происходит фрагментация?

* **Маршрутизатор** (или отправитель) определяет, что размер IP-пакета превышает MTU исходящего интерфейса.
* Он разбивает пакет на части, каждая из которых получает собственный IP-заголовок.
* Поля **Identification**, **Flags** (MF) и **Fragment Offset** используются для управления фрагментацией и последующей сборкой:
  * **Identification:** Все фрагменты одного исходного пакета имеют одинаковый идентификатор.
  * **MF (More Fragments):** Устанавливается во всех фрагментах, кроме последнего.
  * **Fragment Offset:** Указывает позицию данного фрагмента относительно начала исходного пакета.
* **Сборка:** Все фрагменты собираются **только на конечном хосте-получателе**. Маршрутизаторы по пути следования пакеты не собирают.

## Недостатки фрагментации

* **Нагрузка на CPU:** Процессы фрагментации и сборки требуют дополнительных ресурсов CPU как от маршрутизаторов (фрагментация), так и от конечных хостов (сборка).
* **Ухудшение производительности:** Потеря одного фрагмента требует повторной передачи всего исходного IP-пакета, что снижает пропускную способность.
* **Риск DoS-атак:** Атаки с использованием фрагментированных пакетов (например, "fragment overlap") могут эксплуатировать уязвимости в механизмах сборки.
* **Проблемы с файрволами/NAT:** Файрволы и NAT могут иметь трудности с корректной обработкой фрагментированных пакетов, так как информация для фильтрации/трансляции может находиться не в первом фрагменте.

## Фрагментация в IPv6

В IPv6 фрагментация реализована принципиально иначе, чем в IPv4:

### Ключевые отличия

| Критерий | IPv4 | IPv6 |
|----------|------|------|
| **Где фрагментируется** | Любой маршрутизатор на пути | Только отправитель (end-host) |
| **Заголовок фрагментации** | Встроен в основной заголовок | Отдельное расширение заголовка (Extension Header) |
| **Механизм обнаружения MTU** | Опциональный PMTUD | Обязательный Path MTU Discovery |
| **Минимальный MTU** | 68 байт | 1280 байт (обязательно) |
| **DF бит** | Есть (Don't Fragment) | Не нужен — фрагментация всегда end-to-end |

### Почему убрали фрагментацию на маршрутизаторах?

1. **Производительность:** Фрагментация на маршрутизаторах требует значительных ресурсов CPU
2. **Простота оборудования:** Маршрутизаторы работают быстрее без необходимости фрагментировать
3. **Безопасность:** Упрощается защита от DoS-атак с использованием фрагментов

### Расширение заголовка Fragment (IPv6)

```
| Next Header (8 бит) | Reserved (8 бит) | Fragment Offset (13 бит) | Res | M (1 бит) | Identification (32 бита) |
```

* **M (More Fragments):** 1 = есть еще фрагменты, 0 = последний фрагмент
* **Identification:** 32-битный идентификатор (vs 16 бит в IPv4) — уникален для каждого источника

### Процесс фрагментации IPv6

1. **Отправитель** определяет MTU пути через Path MTU Discovery (PMTUD)
2. Если пакет превышает MTU, **только отправитель** фрагментирует пакет
3. Каждый фрагмент получает:
   * Копию основных заголовков IPv6
   * Расширение заголовка Fragment
   * Часть данных
4. **Маршрутизаторы** просто пересылают фрагменты
5. **Получатель** собирает фрагменты по полю Identification

**Если пакет слишком большой и отправитель не может фрагментировать:**

* Отправитель получает ICMPv6 Packet Too Big (Type 2)
* Уменьшает размер пакета и повторяет отправку

## Как избежать/минимизировать фрагментацию?

* **Path MTU Discovery (PMTUD):** Механизм, который позволяет отправителю определить минимальный MTU на всем пути следования пакета и соответствующим образом настроить размер своих исходящих пакетов. Использует ICMP-сообщения.
* **Увеличение MTU:** Настраивать больший MTU там, где это возможно, например, на локальных сетях (Jumbo Frames). Однако это не решает проблему на всем пути в Интернете.
* **TCP MSS Clamping:** На маршрутизаторах можно настроить ограничение максимального размера TCP-сегмента (MSS) в SYN-пакетах, чтобы избежать фрагментации на уровне IP.
