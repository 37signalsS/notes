# Фрагментация IP-пакетов

## Определения

**Фрагментация** — процесс разделения IP-пакета на более мелкие части (фрагменты), когда его общий размер превышает **MTU (Maximum Transmission Unit)** следующего сетевого сегмента.

**MTU (Maximum Transmission Unit)** — максимальный размер полезной нагрузки (включая IP-заголовок, но без канального заголовка), который может быть передан по данному каналу связи. Стандартный MTU для Ethernet — **1500 байт**.

## Базовые концепции

### Причины фрагментации

1. **Разные MTU в сетях:** Интернет состоит из разнородных сетей (Ethernet, Wi-Fi, PPP, VPN-туннели) с разным MTU.
2. **Большие объёмы данных:** Приложения генерируют данные, которые при инкапсуляции в IP-пакеты превышают MTU участка пути.
3. **Ограничение IP-пакета:** поле `Total Length` (16 бит) ограничивает максимальный размер IP-пакета значением **65 535 байт**.
4. **Ограничение канального уровня:** стандартный Ethernet-фрейм — **1514 байт** (1500 байт данных + 14 байт заголовка Ethernet).

### Механизм фрагментации в IPv4

#### Расчёт полезной нагрузки

Максимальный размер данных в одном нефрагментированном пакете для стандартной Ethernet-сети:

```text
MTU Ethernet = 1500 байт (данные канального уровня)
IP-заголовок = 20 байт (без опций)
Максимальная полезная нагрузка = 1500 - 20 = 1480 байт
```

Данные, превышающие 1480 байт, будут фрагментированы.

#### Ключевые поля заголовка

Для управления фрагментацией в заголовке IPv4 используются три ключевых поля:

- **Identification (16 бит):** Уникальный идентификатор, который присваивается всем фрагментам одного исходного пакета. Позволяет хосту-получателю понять, какие фрагменты нужно собрать вместе.
- **Flags (3 бита):**
  - **MF (More Fragments):** `1` означает, что это не последний фрагмент. `0` означает, что это последний фрагмент пакета.
  - **DF (Don't Fragment):** `1` запрещает фрагментацию. Если такой пакет превышает MTU, маршрутизатор отбросит его и отправит ICMP-сообщение `Fragmentation Needed`.
- **Fragment Offset (13 бит):** Смещение данных этого фрагмента от начала данных исходного пакета. **Измеряется в 8-байтных блоках (октетах)**.

> **Почему смещение измеряется в 8-байтных блоках?**
> Поле `Fragment Offset` имеет размер 13 бит (2^13 = 8192). Максимальный размер IP-пакета — 65 535 байт. Чтобы 13-битное поле могло адресовать весь диапазон, смещение кодируется в блоках по 8 байт: `8191 * 8 = 65 528` байт, что покрывает почти весь диапазон.

#### Алгоритм фрагментации и сборки

1. **Фрагментация (на маршрутизаторе или у отправителя):**
    - Устройство определяет, что размер пакета превышает MTU исходящего интерфейса.
    - Исходные данные нарезаются на части, каждая из которых (вместе с IP-заголовком) не превышает MTU.
    - Для каждой части создаётся свой IP-пакет с собственным заголовком, но с одинаковым полем `Identification`.
    - Устанавливаются флаги `MF` и `Fragment Offset`.
2. **Сборка (только на конечном хосте-получателе):**
    - Хост получает фрагменты (возможно, не по порядку).
    - С помощью `Identification` он группирует их.
    - С помощью `Fragment Offset` он расставляет их в правильном порядке и собирает исходный пакет.

#### Пример фрагментации

Передача данных объёмом 4000 байт через сеть с MTU=1500 байт (полезная нагрузка 1480 байт):

| Фрагмент | Размер данных | Identification | MF | Fragment Offset | Расчёт смещения |
| :--- | :--- | :--- | :-: | :--- | :--- |
| 1 | 1480 байт | 0x1234 | 1 | 0 | `0 * 8 = 0` |
| 2 | 1480 байт | 0x1234 | 1 | 185 | `185 * 8 = 1480` |
| 3 | 1040 байт | 0x1234 | 0 | 370 | `370 * 8 = 2960` |

### Недостатки фрагментации

- **Повышенная нагрузка на CPU:** Процессы фрагментации и сборки требуют вычислительных ресурсов.
- **Снижение надёжности:** Потеря одного фрагмента приводит к необходимости повторной передачи **всего исходного пакета** (на транспортном уровне, например, TCP).
- **Уязвимости безопасности:** Используются в DoS-атаках (например, "fragment overlap").
- **Проблемы для сетевых устройств:** Файрволы и NAT-устройства испытывают трудности с обработкой фрагментов, так как информация о портах (TCP/UDP) доступна только в первом фрагменте.

## Практические сценарии

### Фрагментация в IPv6

В протоколе IPv6 механизм фрагментации был кардинально изменен для повышения производительности: фрагментация на маршрутизаторах полностью запрещена и выполняется только конечным узлом-отправителем.

Подробное описание механизма, включая работу **PMTUD**, структуру **Fragment Header** и отличия от IPv4, приведено в основном разделе: **[Фрагментация в IPv6](../../../Protocols/ipv6_overview.md#фрагментация-в-ipv6)**.

### Как избежать/минимизировать фрагментацию

1. **Path MTU Discovery (PMTUD):** Основной механизм, позволяющий отправителю заранее узнать минимальный MTU на пути и отправлять пакеты нужного размера.
2. **TCP MSS Clamping:** Техника на маршрутизаторах (часто на границе сети), которая принудительно уменьшает значение **MSS (Maximum Segment Size)** в TCP SYN-пакетах, чтобы предотвратить отправку слишком больших TCP-сегментов, которые могли бы привести к IP-фрагментации.
3. **Использование Jumbo Frames:** В локальных сетях (LAN) можно увеличить MTU до 9000 байт, что почти полностью исключает необходимость фрагментации для большинства задач.
