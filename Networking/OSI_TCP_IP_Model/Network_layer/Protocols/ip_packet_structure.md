# Структура IP-пакета (IPv4)

## Определения

**IP-пакет (IP Datagram)** — базовая единица данных на сетевом уровне модели OSI. Пакет состоит из управляющей части — **заголовка (Header)** и полезной нагрузки — **данных (Payload)**.

- **Размер заголовка:** от 20 байт (без опций) до 60 байт (с опциями).
- **Общая длина пакета:** ограничена полем `Total Length` (16 бит) и составляет максимум 65 535 байт. На практике размер пакета обычно ограничен параметром **MTU** (стандартно 1500 байт для Ethernet).

## Базовые концепции

### Структура заголовка IPv4 (по битам)

Заголовок организован в виде 32-битных строк (слов). Сетевой порядок байтов — **Big-Endian** (наиболее значимый байт передается первым).

| Смещение (бит) | 0–3 | 4–7 | 8–15 | 16–31 |
| :--- | :--- | :--- | :--- | :--- |
| **0** | Version | IHL | DSCP / ECN (ToS) | Total Length |
| **32** | Identification | Flags | Fragment Offset | |
| **64** | Time to Live (TTL) | Protocol | Header Checksum | |
| **96** | Source IP Address | | | |
| **128** | Destination IP Address | | | |
| **160** | Options (если IHL > 5) | | | |
| **...** | Padding (до границы 32 бит) | | | |

### Детальное описание полей

#### 1. Version (4 бита)
Всегда содержит значение `4` для протокола IPv4. Используется приемником для определения формата заголовка перед разбором остальных полей.

#### 2. IHL (Internet Header Length, 4 бита)
Длина заголовка в 32-битных словах.
- Минимум: `5` (5 * 4 = 20 байт).
- Максимум: `15` (15 * 4 = 60 байт).

#### 3. DSCP и ECN (бывшее поле ToS, 8 бит)
- **DSCP (Differentiated Services Code Point, 6 бит):** Определяет приоритет обработки пакета (QoS). Примеры: `EF` (Expedited Forwarding) для VoIP, `AF` (Assured Forwarding) для критических данных. Подробнее: **[Качество обслуживания (QoS)](../../../Concepts/qos.md)**.
- **ECN (Explicit Congestion Notification, 2 бита):** Позволяет маршрутизаторам сигнализировать о перегрузке сети, устанавливая биты в заголовке вместо отбрасывания пакета.

#### 4. Total Length (16 бит)
Общая длина пакета (заголовок + полезная нагрузка) в байтах.

#### 5. Identification, Flags, Fragment Offset
Используются для управления фрагментацией.
- **Identification:** ID исходного пакета.
- **Flags:** `DF` (Don't Fragment) и `MF` (More Fragments).
- **Fragment Offset:** Позиция фрагмента в 8-байтовых блоках.
- Подробнее: **[Фрагментация IP-пакетов](./ip_fragmentation.md)**.

#### 6. Time to Live (TTL, 8 бит)
Счетчик «жизни» пакета. Каждый маршрутизатор уменьшает это значение на 1. При `TTL=0` пакет отбрасывается, и отправителю летит ICMP `Time Exceeded`. Это защищает сеть от «бесконечных петель».

#### 7. Protocol (8 бит)
Указывает, какой протокол инкапсулирован в полезную нагрузку:
- `1` — ICMP
- `6` — TCP
- `17` — UDP
- `47` — GRE
- `50` — ESP (IPsec)

#### 8. Header Checksum (16 бит)
Контрольная сумма **только заголовка**. Поскольку TTL меняется на каждом маршрутизаторе, чек-сумма обязана пересчитываться на каждом «хопе».

#### 9. Source и Destination IP (32 бита каждое)
IP-адреса отправителя и получателя. Подробнее: **[IP-адресация — Обзор](../../../Protocols/IP_addressing/ip_overview.md)**.

#### 10. Options (переменная длина)
Используются для диагностики или специфической маршрутизации (редко в публичном интернете из-за соображений безопасности):
- **Record Route:** Запись IP-адресов маршрутизаторов на пути.
- **Timestamp:** Отметки времени прохождения узлов.
- **Strict/Loose Source Routing:** Указание конкретного пути прохождения пакета.

## Практические сценарии

### Диагностика через TTL (Traceroute)
Утилита `traceroute` использует поле TTL для построения карты маршрута:
1. Отправляется пакет с `TTL=1`. Первый роутер сбрасывает его и возвращает ошибку.
2. Отправляется пакет с `TTL=2`, `TTL=3` и так далее, пока не будет достигнут целевой хост.

### Инспекция пакетов (Deep Packet Inspection)
Системы DPI и брандмауэры анализируют поля заголовка для принятия решений:
- Фильтрация по `Protocol` (например, запрет GRE-туннелей).
- Приоритезация по `DSCP`.
- Обнаружение атак на фрагментацию через анализ `Flags` и `Offset`.

## Сравнение с IPv6

В IPv6 заголовок был упрощен для повышения производительности:
- Фиксированный размер (40 байт).
- Удалена контрольная сумма (Header Checksum), так как она дублируется на уровнях L2/L4.
- Фрагментация вынесена в дополнительные заголовки (Extension Headers).

Подробнее: **[Сравнение IPv4 и IPv6](../../../Protocols/ipv6_overview.md#сравнение-ипа-и-ipv6)**.
