# Структура IP-пакета (IPv4)

## Определения

**IP-пакет (IP Datagram)** — базовая единица данных на сетевом уровне модели **OSI**, обеспечивающая независимую доставку информации между узлами сети. Пакет состоит из управляющей части — **заголовка (Header)** и полезной нагрузки — **данных (Payload)**.

- **Размер заголовка:** От 20 байт (базовый) до 60 байт (с учетом опций).
- **Максимальный размер (MTU):** Ограничен полем `Total Length` (16 бит) — до 65 535 байт. В реальных сетях Ethernet размер пакета обычно составляет **1500 байт**.

## Базовые концепции

### Структура заголовка IPv4 (по битам)

Заголовок организован в виде 32-битных слов. Сетевой порядок байтов — **Big-Endian**.

| Смещение (бит) | 0–3 | 4–7 | 8–15 | 16–31 |
| :--- | :--- | :--- | :--- | :--- |
| **0** | Version (4) | IHL (4) | DSCP (6) / ECN (2) | Total Length (16) |
| **32** | Identification (16) | Flags (3) | Fragment Offset (13) | |
| **64** | Time to Live (8) | Protocol (8) | Header Checksum (16) | |
| **96** | Source IP Address (32) | | | |
| **128** | Destination IP Address (32) | | | |
| **160** | Options (переменная длина, если IHL > 5) | | | |

### Детальное описание полей

#### 1. Version (Версия)
Всегда `4` для IPv4. Позволяет приемнику понять, по каким правилам разбирать заголовок.

#### 2. IHL (Internet Header Length)
Длина заголовка в 32-битных словах. Минимальное значение `5` (20 байт). Если используются опции, IHL увеличивается.

#### 3. DSCP и ECN (Качество обслуживания)
- **DSCP (Differentiated Services Code Point):** 6 бит для маркировки приоритета трафика (QoS).
- **ECN (Explicit Congestion Notification):** 2 бита. Позволяют маршрутизаторам уведомлять хосты о перегрузке без отбрасывания пакетов (требует поддержки на L4).

#### 4. Total Length (Общая длина)
Длина всего IP-пакета (заголовок + данные) в байтах.

#### 5. Фрагментация (Identification, Flags, Offset)
Поля, позволяющие разрезать большой пакет на части и собрать его обратно.
- **Flags:** `DF` (Don't Fragment — запрет фрагментации) и `MF` (More Fragments — признак продолжения).
- Подробнее: **[Фрагментация IP-пакетов](./ip_fragmentation.md)**.

#### 6. Time to Live (TTL)
Счетчик «жизни» пакета. Каждый маршрутизатор уменьшает TTL на 1. При достижении 0 пакет уничтожается, а отправителю летит **ICMP Time Exceeded**. Это защищает от петель маршрутизации.

#### 7. Protocol (Протокол)
Указывает тип данных в Payload (протокол следующего уровня):
- `1` — **ICMP** (служебный)
- `2` — **IGMP** (мультикаст)
- `6` — **TCP**
- `17` — **UDP**
- `47` — **GRE** (туннелирование)
- `50` / `51` — **ESP / AH** (IPsec)
- `89` — **OSPF** (динамическая маршрутизация)
- `112` — **VRRP** (отказоустойчивость шлюзов)

#### 8. Header Checksum (Контрольная сумма)
Проверяет целостность только заголовка. Пересчитывается на каждом маршрутизаторе из-за изменения TTL.

#### 9. Options (Опции)
Редко используются в современном интернете из-за рисков безопасности:
- **Source Routing:** Позволяет отправителю задать путь (маршрутизаторы обычно блокируют это для защиты от спуфинга).
- **Record Route:** Записывает пройденные IP-адреса.
- **Timestamp:** Время прохождения через узлы.

## Практические сценарии

### 1. Траблшутинг через TTL (Traceroute)
Утилита `traceroute` намеренно шлет пакеты с последовательно возрастающим TTL (1, 2, 3...), заставляя каждый маршрутизатор на пути выдавать ICMP-ответ об истечении времени. Так строится карта хопов.

### 2. Анализ трафика (tcpdump)
Инженер может смотреть поля IP-заголовка напрямую:
```bash
# Просмотр пакетов с установленным флагом DF (Don't Fragment)
tcpdump -v 'ip[6] & 64 != 0'

# Просмотр пакетов с конкретным TTL (например, меньше 10)
tcpdump -v 'ip[8] < 10'

# Фильтрация по протоколу OSPF
tcpdump 'ip proto 89'
```

### 3. MTU Black Hole
Если приложение шлет большие пакеты с флагом `DF=1`, а где-то на пути MTU меньше размера пакета, маршрутизатор его отбросит. Если при этом блокируется ICMP (Destination Unreachable), возникнет «черная дыра» — соединение виснет.
Подробнее: **[MTU и PMTUD](../mtu_and_vpn.md)**.

## Дополнительная информация

### Сравнение с IPv6
Заголовок IPv6 имеет фиксированный размер 40 байт и не содержит контрольную сумму, что ускоряет его обработку аппаратными маршрутизаторами. Все опции вынесены в **Extension Headers**.
