# Структура IP-пакета (IPv4)

## Определения

**IP-пакет (дейтаграмма)** — ключевая единица данных на сетевом уровне модели OSI. Состоит из **заголовка (Header)**, содержащего служебную информацию, и **полезной нагрузки (Payload)**, которая переносит данные вышестоящих уровней (например, TCP или UDP).

## Базовые концепции

### Общая схема пакета

Диаграмма ниже иллюстрирует базовую структуру IP-пакета.

```text
+------------------+------------------------------------------+
|    Заголовок     |            Полезная нагрузка             |
|  (20-60 байт)    | (до 65,515 байт, обычно ограничено MTU)  |
+------------------+------------------------------------------+
```

- **Минимальный размер заголовка:** 20 байт (без опций).
- **Максимальный размер заголовка:** 60 байт (с опциями).
- **Максимальный размер всего пакета:** 65 535 байт, определяется полем `Total Length`.

### Структура заголовка IPv4

#### Краткое описание полей

| Поле | Длина (бит) | Описание |
| :--- | :--- | :--- |
| **Version** | 4 | Версия протокола (`4` для IPv4). |
| **IHL** | 4 | Длина заголовка в 32-битных словах (минимум `5`). |
| **DSCP/ECN** | 8 | Управление качеством обслуживания (QoS) и уведомление о перегрузках. |
| **Total Length** | 16 | Общая длина пакета (заголовок + данные) в байтах. |
| **Identification** | 16 | Идентификатор для сборки фрагментированных пакетов. |
| **Flags** | 3 | Флаги, управляющие фрагментацией (`DF`, `MF`). |
| **Fragment Offset** | 13 | Смещение данных фрагмента от начала исходного пакета. |
| **TTL** | 8 | Время жизни пакета, измеряемое в хопах (переходах). |
| **Protocol** | 8 | Протокол транспортного уровня (`6`=TCP, `17`=UDP, `1`=ICMP). |
| **Header Checksum** | 16 | Контрольная сумма для проверки целостности заголовка. |
| **Source IP Address** | 32 | IP-адрес отправителя. |
| **Destination IP Address** | 32 | IP-адрес получателя. |
| **Options** | 0-320 | Дополнительные параметры (используются редко). |
| **Padding** | 0-24 | Выравнивание до границы 32 бит. |

#### Подробное описание ключевых полей

- **IHL (Internet Header Length):** Указывает размер заголовка в 32-битных словах. Минимальное значение — `5`, что соответствует `5 * 4 = 20` байтам (заголовок без опций). Максимальное значение — `15` (`15 * 4 = 60` байт).
- **DSCP/ECN (Differentiated Services Code Point / Explicit Congestion Notification):** Современная интерпретация поля `Type of Service (ToS)`.
  - **DSCP (6 бит):** Используется для классификации и приоритизации трафика (QoS).
  - **ECN (2 бита):** Механизм, позволяющий маршрутизаторам уведомлять хосты о начинающейся перегрузке сети без отбрасывания пакетов.
- **TTL (Time To Live):** Счетчик, который уменьшается на единицу каждым маршрутизатором на пути следования пакета. Когда TTL достигает нуля, пакет отбрасывается, а отправителю направляется ICMP-сообщение `Time Exceeded`. Это предотвращает вечную циркуляцию пакетов в сети.
- **Header Checksum:** Контрольная сумма, которая вычисляется **только для заголовка**. Поскольку значение TTL меняется на каждом хопе, маршрутизаторы обязаны пересчитывать чек-сумму при каждой пересылке пакета.

## Практические сценарии

### Анализ фрагментации

Для управления фрагментацией используются три поля:

- **Identification:** Все фрагменты одного исходного пакета имеют одинаковый ID.
- **Flags:** Флаг `MF` (More Fragments) установлен у всех фрагментов, кроме последнего. Флаг `DF` (Don't Fragment) запрещает фрагментацию.
- **Fragment Offset:** Указывает позицию данных фрагмента относительно начала исходного пакета.

Подробнее см. в документе [Фрагментация IP-пакетов](./ip_fragmentation.md).

### Диагностика с помощью TTL

Утилита `traceroute` использует TTL для исследования маршрута до цели. Она отправляет пакеты, последовательно увеличивая TTL (1, 2, 3...), и отслеживает ICMP-ответы `Time Exceeded` от каждого маршрутизатора.

```bash
# traceroute отправляет UDP-пакеты с возрастающим TTL
traceroute example.com
```

## Сравнение заголовков IPv4 и IPv6

Заголовок IPv6 был значительно упрощен и оптимизирован для ускорения обработки пакетов маршрутизаторами: исключена контрольная сумма заголовка, фрагментация вынесена в расширенные заголовки, а размер зафиксирован на 40 байтах.

Подробное сравнение характеристик и структур приведено в основном разделе: **[Сравнение IPv4 и IPv6](../../../Protocols/ipv6_overview.md#сравнение-ipv4-и-ipv6)**.
