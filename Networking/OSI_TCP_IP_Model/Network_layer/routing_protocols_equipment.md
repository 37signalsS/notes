# Протоколы и оборудование сетевого уровня

## Определения

**Маршрутизация** — процесс определения оптимального пути для передачи данных между сетями.

**Маршрутизатор** — устройство сетевого уровня, предназначенное для объединения нескольких сетей в единую составную сеть (internetwork).

## Базовые концепции

### Ключевые протоколы сетевого уровня

| Протокол | Назначение |
|----------|------------|
| **[IP (Internet Protocol)](../../Protocols/IP_addressing/ip_overview.md)** | Передача данных и глобальная адресация |
| **[ICMP (Internet Control Message Protocol)](../../Protocols/ICMP/icmp_overview.md)** | Служебные и диагностические сообщения |
| **[ARP (Address Resolution Protocol)](../../Protocols/arp.md)** | Сопоставление IP-адресов (L3) и MAC-адресов (L2) |
| **[DHCP (Dynamic Host Configuration Protocol)](../../Protocols/DHCP/dhcp_overview.md)** | Автоматическое назначение IP-адресов хостам |
| **Протоколы маршрутизации** | Обмен информацией о сетях и построение таблиц маршрутизации | См. ниже |

### Типы маршрутизации

| Тип | Описание | Применение |
|-----|----------|------------|
| **Статическая** | Маршруты конфигурируются администратором вручную | Малые сети, дефолтные маршруты, stub-сети |
| **Динамическая** | Автоматический выбор маршрута на основе изменяющихся условий | Крупные сети с избыточной топологией |

### Протоколы динамической маршрутизации

| Протокол | Тип | Алгоритм | Применение |
|----------|-----|----------|------------|
| **OSPF** | IGP (Interior Gateway Protocol) | Link State (состояние каналов) | Крупные корпоративные сети |
| **RIP** | IGP | Distance Vector (вектор расстояния) | Малые сети (устаревший) |
| **[BGP](../../Protocols/bgp.md)** | EGP (Exterior Gateway Protocol) | Path Vector | Интернет, крупные провайдеры |
| **EIGRP** | IGP | Advanced Distance Vector (Cisco) | Сети Cisco |

## Практические сценарии

### Оборудование сетевого уровня

#### Маршрутизатор (Роутер)

**Назначение:** объединение нескольких сетей в единую составную сеть.

**Принцип работы:**

1. Получает пакет на интерфейс
2. Анализирует IP-адрес назначения
3. Сверяется с **таблицей маршрутизации**
4. Отправляет пакет на соответствующий интерфейс

**Отличие от коммутатора:**

- Коммутатор соединяет узлы *внутри* одной сети (L2, MAC-адреса)
- Маршрутизатор связывает *разные* сети (L3, IP-адреса)

#### L3-коммутатор

**Гибридное устройство**, сочетающее:

- Функции коммутатора: быстрая коммутация на L2 в пределах VLAN
- Функции маршрутизатора: маршрутизация между VLAN/подсетями на L3

**Применение:**

- Маршрутизация между VLAN в кампусных сетях
- Высокая производительность за счёт аппаратной маршрутизации

### Default-Free Zone (DFZ)

**Default-Free Zone (DFZ)** — совокупность маршрутизаторов в интернете, которые вместе содержат маршруты до всех сетей и не используют маршрут по умолчанию для передачи трафика.

#### Проблема маршрута по умолчанию

Маршрут по умолчанию (`0.0.0.0/0`) упрощает конфигурацию, но перекладывает проблему маршрутизации на другие устройства. В сложной сети только маршрута по умолчанию недостаточно — должен существовать хотя бы один маршрутизатор, который знает конкретные маршруты до всех сетей.

#### Пример сети, где маршрут по умолчанию недостаточен

Рассмотрим сеть с 2 хостами и 3 маршрутизаторами:

- Хост 1 и маршрутизатор 1: сеть `10.0.0.0/24`
- Маршрутизатор 1 и маршрутизатор 2: сеть `192.168.1.0/24`
- Маршрутизатор 2 и маршрутизатор 3: сеть `172.16.12.0/24`
- Маршрутизатор 3 и хост 2: сеть `169.254.1.0/24`

Если настроить маршруты по умолчанию:
- Хост 1 → маршрутизатор 1
- Маршрутизатор 1 → маршрутизатор 2
- Хост 2 → маршрутизатор 3
- Маршрутизатор 3 → маршрутизатор 2

Возникает проблема:
- Если на маршрутизаторе 2 установить маршрут по умолчанию на маршрутизатор 3, пакет от хоста 1 до хоста 2 дойдёт, но обратно нет (маршрутизатор 2 не знает маршрут до `10.0.0.0/24`).
- Если установить маршрут по умолчанию на маршрутизатор 1, пакеты от хоста 2 до хоста 1 будут доходить, но не обратно (нет маршрута до `169.254.1.0/24`).

#### Решения для обеспечения полной связности

**Вариант 1: Полный набор маршрутов на одном маршрутизаторе**

Добавить на маршрутизатор 2 конкретные маршруты до обеих сетей:

| IP сеть назначения | IP адрес маршрутизатора | Комментарий |
| :--- | :--- | :--- |
| `192.168.1.0/24` | `192.168.1.102` | Локальная сеть (маршрутизатор 2) |
| `172.16.12.0/24` | `172.16.12.102` | Локальная сеть (маршрутизатор 2) |
| `10.0.0.0/24` | `192.168.1.101` | Через маршрутизатор 1 |
| `169.254.1.0/24` | `172.16.12.103` | Через маршрутизатор 3 |

В этом случае **DFZ состоит только из маршрутизатора 2** — он самостоятельно знает все маршруты.

**Вариант 2: Комбинация маршрута по умолчанию и конкретных маршрутов**

- На маршрутизаторе 2: маршрут по умолчанию → маршрутизатор 1 + конкретный маршрут до `169.254.1.0/24` → маршрутизатор 3.
- В этом случае **DFZ состоит из маршрутизаторов 1 и 2** — вместе они обеспечивают маршруты до всех сетей.

#### Значение DFZ

- В интернете роль DFZ выполняют магистральные маршрутизаторы крупных провайдеров (Tier-1), которые хранят полные таблицы маршрутизации BGP.
- Размер полной таблицы маршрутизации интернета превышает 900 000 префиксов (на 2024 год).
- Маршрутизаторы в DFZ не используют маршрут по умолчанию — они знают конкретные пути до всех анонсированных сетей.

Подробнее о BGP и обмене маршрутами см. [BGP](../../Protocols/bgp.md).
