# Сетевой уровень (L3) — Обзор

## Определения

**Сетевой уровень (Network Layer, L3)** — третий уровень эталонной модели [OSI](../../osi_model.md), отвечающий за объединение разнородных сетевых сегментов в единую **составную сеть (internetwork)**. Его главная задача — обеспечить сквозную доставку данных между любыми двумя узлами глобальной сети, независимо от их физического расположения и используемых технологий канального уровня.

- **PDU (Protocol Data Unit):** Пакет (Packet).
- **Адресация:** Логическая иерархическая адресация (IPv4 — 32 бита, IPv6 — 128 бит). Подробнее: **[IP-адресация — Обзор](../../../Protocols/IP_addressing/ip_overview.md)**.

**Ключевой принцип:** Сетевой уровень абстрагирует вышестоящие слои от физической топологии. Если L2 работает с «соседями по проводу», то L3 работает со всей сетью как с единым целым.

## Базовые концепции

### Зачем нужен Сетевой уровень (L3 vs L2)

[Канальный уровень (L2)](../../data_link_layer.md) ограничен пределами одного широковещательного домена. Для глобальных коммуникаций он непригоден по ряду причин:
1.  **Отсутствие иерархии:** MAC-адреса не содержат информации о местоположении. Маршрутизация на основе MAC потребовала бы хранения таблиц со всеми устройствами мира в каждом коммутаторе.
2.  **Широковещательные штормы:** L2-механизмы (ARP, Flooding) в гигантских сетях привели бы к моментальной перегрузке каналов служебным трафиком.
3.  **Несовместимость сред:** L3 позволяет передать данные из Ethernet в Wi-Fi или MPLS, выступая «универсальным переводчиком».
4.  **Единственность пути:** Протоколы L2 (например, [STP](../../../Protocols/stp.md)) блокируют избыточные связи для исключения петель. L3, напротив, эффективно использует все доступные маршруты (ECMP).

### Иерархическая структура IP

IP-адрес разделен на **адрес сети** и **номер хоста**. Это позволяет маршрутизаторам:
- Оперировать блоками адресов (агрегация маршрутов).
- Резко сокращать размер таблиц маршрутизации.
- Определять, является ли получатель локальным или внешним.

## Ключевые функции и механизмы

### 1. Маршрутизация (Routing)
Определение оптимального пути прохождения пакета. Выполняется **маршрутизаторами** на основе динамических протоколов (OSPF, IS-IS, [BGP](../../../Protocols/bgp.md)).
- Пакет IP остается неизменным на всем пути (кроме поля TTL), в то время как кадр L2 пересобирается на каждом «прыжке» (hop).

### 2. Фрагментация и сборка
Если размер пакета превышает [MTU](../mtu_and_vpn.md) следующего сегмента сети, маршрутизатор (в IPv4) или отправитель (в IPv6) разбивает его на фрагменты. Подробнее: **[Фрагментация IP-пакетов](../Protocols/ip_fragmentation.md)**.

### 3. Управление временем жизни (TTL / Hop Limit)
Поле в заголовке, предотвращающее вечное зацикливание пакетов при ошибках маршрутизации. Значение уменьшается на 1 при каждом прохождении через маршрутизатор.

### 4. Качество обслуживания (QoS)
Маркировка пакетов через поле **DSCP (Differentiated Services Code Point)** для приоритезации критичного трафика (например, VoIP над бэкапами) в узлах сети.

## Современные технологии сетевого уровня (2026+)

### SDN и NFV
**Программно-конфигурируемые сети (SDN)** отделяют уровень управления (Control Plane) от уровня передачи данных (Data Plane). Это позволяет централизованно управлять маршрутизацией через API, что является стандартом в облаках и K8s.

### VRF (Virtual Routing and Forwarding)
Технология, позволяющая одному физическому маршрутизатору иметь несколько независимых таблиц маршрутизации. Это обеспечивает изоляцию трафика на уровне L3 (аналог VLAN для сетевого слоя).
- Подробнее: **[Практические сценарии маршрутизации](./routing_scenarios.md)**.

### Segment Routing (SRv6)
Современная замена MPLS. Позволяет задавать путь пакета непосредственно в его заголовке IPv6, обеспечивая гибкое управление трафиком (Traffic Engineering) без сложного поддержания состояний в промежуточных узлах.

### Обработка пакетов через eBPF/XDP
В высокопроизводительных системах маршрутизация переносится из стандартного стека ядра Linux в драйвер сетевой карты. Это позволяет обрабатывать миллионы пакетов в секунду с минимальными задержками (используется в Cilium и современных балансировщиках).
