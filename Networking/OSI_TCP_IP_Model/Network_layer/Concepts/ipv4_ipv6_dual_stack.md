# Сосуществование IPv4 и IPv6 (Dual Stack)

**Dual Stack** — это подход, при котором устройства и сети одновременно поддерживают оба протокола: IPv4 и IPv6.

## Почему необходимо сосуществование?

1. **Постепенная миграция:** Невозможно переключить весь Интернет за один день
2. **Legacy-системы:** Множество устройств и приложений работают только с IPv4
3. **Различные возможности:** Некоторые сервисы доступны только по IPv4, другие — по IPv6

## Реализация Dual Stack

**На хостах:**

- Оба протокола настраиваются на сетевых интерфейсах
- Приложения выбирают, какой протокол использовать (обычно IPv6 предпочтительнее)
- DNS возвращает оба типа записей (A для IPv4, AAAA для IPv6)

**В сети:**

- Маршрутизаторы поддерживают оба протокола
- Отдельные таблицы маршрутизации для IPv4 и IPv6
- Может использоваться разное оборудование или VLAN

## Приоритет выбора протокола

Согласно RFC 8305 (Happy Eyeballs), современные системы:

1. Отправляют запросы DNS одновременно для A и AAAA
2. Пробуют подключиться по IPv6 первым (с небольшой задержкой)
3. Если IPv6 не работает — переключаются на IPv4
4. Используют тот протокол, который ответил быстрее

## Технологии перехода

| Технология | Описание | Применение |
|------------|----------|------------|
| **Dual Stack** | Полная поддержка обоих протоколов | Предпочтительный подход |
| **Tunneling** | Инкапсуляция одного протокола в другой | Связь IPv6-сетей через IPv4 |
| **Translation** | Преобразование пакетов между протоколами | Доступ IPv6-only к IPv4-only |
| **NAT64/DNS64** | Трансляция адресов IPv6↔IPv4 | Доступ к IPv4 из IPv6-only сетей |

## Проблемы сосуществования

- **Увеличение сложности:** Нужно управлять двумя стеками адресации
- **Безопасность:** Два протокола = два вектора атаки
- **Ресурсы:** Дополнительная нагрузка на сетевое оборудование
- **Troubleshooting:** Сложнее диагностировать проблемы
