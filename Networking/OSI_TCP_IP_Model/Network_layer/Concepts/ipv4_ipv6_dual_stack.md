# Сосуществование IPv4 и IPv6 (Dual Stack)

## Определения

**Dual Stack** — подход, при котором устройства и сети одновременно поддерживают оба протокола: IPv4 и IPv6.

## Базовые концепции

### Почему необходимо сосуществование

1. **Постепенная миграция:** Невозможно переключить весь Интернет за один день
2. **Legacy-системы:** Множество устройств и приложений работают только с IPv4
3. **Различные возможности:** Некоторые сервисы доступны только по IPv4, другие — по IPv6

### Реализация Dual Stack

**На хостах:**

- Оба протокола настраиваются на сетевых интерфейсах
- Приложения выбирают протокол (обычно IPv6 предпочтительнее)
- DNS возвращает оба типа записей: **A** (IPv4) и **AAAA** (IPv6)

**В сети:**

- Маршрутизаторы поддерживают оба протокола
- Отдельные таблицы маршрутизации для IPv4 и IPv6
- Может использоваться разное оборудование или VLAN

### Приоритет выбора протокола (Happy Eyeballs)

Согласно **RFC 8305** (Happy Eyeballs v2), современные системы:

1. Отправляют DNS-запросы одновременно для **A** и **AAAA**
2. Пробуют подключиться по **IPv6** первым (с задержкой ~150-300 мс)
3. Если IPv6 не работает — переключаются на IPv4
4. Используют протокол, который ответил быстрее

> **Примечание:** В 2025 году разрабатывается **Happy Eyeballs v3** (draft-ietf-happy-happyeyeballs-v3) для улучшения алгоритма.

## Практические сценарии

### Технологии перехода

| Технология | Описание | Применение |
|------------|----------|------------|
| **Dual Stack** | Полная поддержка обоих протоколов | Предпочтительный подход |
| **Tunneling** | Инкапсуляция одного протокола в другой | Связь IPv6-сетей через IPv4-инфраструктуру |
| **Translation** | Преобразование пакетов между протоколами | Доступ IPv6-only к IPv4-only сервисам |
| **NAT64/DNS64** | Трансляция адресов IPv6↔IPv4 | Доступ к IPv4 из IPv6-only сетей |

### Проблемы сосуществования

- **Увеличение сложности:** управление двумя стеками адресации
- **Безопасность:** два протокола = два вектора атаки
- **Ресурсы:** дополнительная нагрузка на сетевое оборудование
- **Troubleshooting:** сложнее диагностировать проблемы

## Дополнительная информация

### Статус Dual Stack (2025–2026)

- **Основная стратегия:** Dual Stack остаётся ключевым подходом к миграции на IPv6. Около 40% трафика Google уже проходит по IPv6.
- **Happy Eyeballs v3:** Новая версия алгоритма активно разрабатывается ([draft-ietf-happy-happyeyeballs-v3](https://datatracker.ietf.org/doc/draft-ietf-happy-happyeyeballs-v3/)), с последней версией -03 от марта 2026 г. Microsoft Edge уже внедрил поддержку политики `HappyEyeballsV3Enabled`.
