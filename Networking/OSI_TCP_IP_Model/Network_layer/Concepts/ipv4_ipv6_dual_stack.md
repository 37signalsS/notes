# Сосуществование IPv4 и IPv6 (Dual Stack)

## Определения

**Dual Stack (Двойной стек)** — сетевая архитектура, при которой узлы и сетевое оборудование одновременно поддерживают и используют оба стека протоколов: IPv4 и IPv6. Это основной и наиболее предпочтительный метод миграции на IPv6, обеспечивающий плавный переход без прерывания связи.

**IPv4-mapped IPv6 addresses** — механизм (описанный в RFC 4291), позволяющий представлять IPv4-адреса внутри адресного пространства IPv6 (префикс `::ffff:0:0/96`). Позволяет Dual-stack приложениям слушать один IPv6-сокет и принимать соединения обоих протоколов.

## Базовые концепции

### Почему необходим Dual Stack

1.  **Постепенная миграция:** Глобальный переход занимает десятилетия; Dual Stack позволяет узлам общаться с "обоими мирами".
2.  **Legacy-совместимость:** Огромное количество старого оборудования и ПО не поддерживает IPv6 и никогда не будет обновлено.
3.  **Гибкость:** Администраторы могут внедрять IPv6 в своих темпах, сохраняя IPv4 как резервный или основной канал.

### Реализация на разных уровнях

-   **На уровне ОС (Хосты):** Ядро поддерживает два независимых стека. Каждому интерфейсу назначаются адреса обоих типов.
-   **На уровне приложений:** Современные сетевые библиотеки (например, в Go, Rust, Python) абстрагируют выбор протокола, используя алгоритмы приоритезации.
-   **В сети (Маршрутизаторы):** Поддержка двух таблиц маршрутизации (RIB/FIB) и протоколов динамической маршрутизации для каждого семейства (OSPFv2/v3, BGP).

## Алгоритмы выбора протокола

### Happy Eyeballs v2 и v3

Проблема: Если IPv6 настроен некорректно (например, пакеты дропаются), пользователи могут ждать секундные таймауты перед переключением на IPv4.
**Happy Eyeballs** (RFC 8305) решает это путем параллельного инициирования соединений.

1.  **Параллельный резолвинг:** Одновременный запрос записей A (IPv4) и AAAA (IPv6).
2.  **Задержка старта (Resolution Delay):** Система отдает предпочтение IPv6, но запускает таймер (~150-250 мс). Если IPv6-соединение не установилось за это время, начинается попытка по IPv4.
3.  **Побеждает быстрейший:** Используется то соединение, которое установилось первым. Второе закрывается.

> **Статус 2026:** Внедряется **Happy Eyeballs v3** (draft-ietf-v3-03). Основное улучшение — учет характеристик канала (RTT, потери) в реальном времени и поддержка **HTTPS RR** (RFC 9460) для ускорения TLS/QUIC.

## Технологии перехода и интеграции

В ситуациях, когда чистый Dual Stack невозможен, используются механизмы трансляции и туннелирования.

| Технология | Механизм | Применение |
| :--- | :--- | :--- |
| **NAT64** | Трансляция IPv6 пакетов в IPv4 (и наоборот) на уровне шлюза. | Доступ из IPv6-only сетей к IPv4-интернету. |
| **DNS64** | Синтезирует AAAA-запись для домена, у которого есть только A-запись. | Работает в паре с NAT64. Использует префикс `64:ff9b::/96`. |
| **464XLAT** | Двойная трансляция (CLAT на устройстве + PLAT на шлюзе). | Позволяет IPv4-only приложениям работать в IPv6-only сети (стандарт в Android/iOS). |
| **Dual-Stack Lite** | Инкапсуляция IPv4 в IPv6 туннель для экономии публичных IPv4-адресов провайдером. | Провайдерские сети (ISP). |

## Особенности реализации в Linux

### Сокеты и привязка адресов
Параметр `net.ipv6.bindv6only` определяет поведение при прослушивании адреса `::` (всех адресов).

-   **`bindv6only = 0` (По умолчанию):** Сокет `[::]` принимает трафик как IPv6, так и IPv4 (через IPv4-mapped адреса). Удобно для простых Dual-stack сервисов.
-   **`bindv6only = 1`:** Сокет принимает только IPv6. Для поддержки IPv4 нужно создавать отдельный сокет на `0.0.0.0`. Это безопаснее и прозрачнее для логирования.

```bash
# Проверить текущую настройку
sysctl net.ipv6.bindv6only
```

### Приоритеты в /etc/gai.conf
Файл определяет, какой адрес вернет функция `getaddrinfo()` первым. Можно настроить систему так, чтобы она всегда предпочитала IPv4 (редко требуется) или конкретные диапазоны IPv6.

## Проблемы и риски

1.  **Удвоение поверхности атаки:** Нужно настраивать и мониторить два файрвола (или использовать `inet` таблицы в `nftables`).
2.  **Асимметрия пути:** Пакет по IPv4 может идти через одного провайдера, а по IPv6 — через другого, что усложняет диагностику задержек.
3.  **MTU Issues:** IPv6 требует минимум 1280 байт. Если IPv4 туннель или оборудование режет MTU ниже этого значения, IPv6 перестанет работать.
4.  **IP-репутация:** Спам-фильтры и WAF могут иметь разные базы репутации для IPv4 и IPv6 адресов одного и того же клиента.
