# Модель TCP/IP

## Определения

-   **Модель TCP/IP (Transmission Control Protocol/Internet Protocol)** — это практическая, многоуровневая модель сетевого взаимодействия, которая является стандартом де-факто для современного Интернета. В отличие от теоретической модели OSI, TCP/IP была разработана на основе реально существующих протоколов и ориентирована на обеспечение надежной связи в глобальных сетях.
-   **Стек протоколов TCP/IP** — иерархически организованный набор сетевых протоколов, реализующий модель TCP/IP. Название стека происходит от двух ключевых протоколов: TCP (Transmission Control Protocol) и IP (Internet Protocol).

## Основные концепции

### Уровни модели TCP/IP

Модель TCP/IP состоит из четырех уровней, каждый из которых выполняет свои функции:

1.  **Канальный уровень (Network Access Layer)**: Отвечает за физическую доставку данных в пределах одной локальной сети. На этом уровне используются MAC-адреса для идентификации устройств.
    -   **Протоколы**: Ethernet, Wi-Fi, [ARP](./arp_protocol.md).
2.  **Межсетевой уровень (Internet Layer)**: Отвечает за маршрутизацию данных между различными сетями (internetworking). На этом уровне используются IP-адреса для глобальной адресации.
    -   **Протоколы**: [IP](./ip_address.md), ICMP, OSPF.
3.  **Транспортный уровень (Transport Layer)**: Обеспечивает связь между приложениями на разных устройствах. Отвечает за надежную ([TCP](../Protocols/tcp.md)) или быструю ([UDP](../Protocols/udp_protocol.md)) доставку данных. Для идентификации приложений используются номера [портов](./network_ports.md).
4.  **Прикладной уровень (Application Layer)**: Содержит протоколы, с которыми непосредственно взаимодействуют пользовательские приложения, и определяет, как данные должны быть структурированы и интерпретированы.
    -   **Протоколы**: [HTTP](../Protocols/http.md), DNS, SMTP, FTP.

### Инкапсуляция и стек протоколов

При передаче данных, сообщение протокола вышестоящего уровня вкладывается (инкапсулируется) в сообщение нижестоящего. Этот процесс происходит последовательно на всех уровнях:

-   Данные **прикладного уровня** (например, HTTP-запрос)
-   помещаются в **транспортный** сегмент ([TCP](../Protocols/tcp.md) или [UDP](../Protocols/udp_protocol.md))
-   который инкапсулируется в **межсетевой** пакет ([IP](./ip_address.md))
-   и, наконец, заключается в **канальный** кадр (например, Ethernet).

На принимающей стороне происходит обратный процесс — **декапсуляция**.

## Практические сценарии

### Сценарий 1: Запрос веб-страницы

1.  **Прикладной уровень**: Браузер формирует HTTP GET-запрос для получения веб-страницы.
2.  **Транспортный уровень**: Операционная система создает TCP-сегмент. В него помещается HTTP-запрос. Заголовку TCP присваиваются порт отправителя (случайный) и порт назначения (80 для HTTP или 443 для HTTPS).
3.  **Межсетевой уровень**: Создается IP-пакет, в который вкладывается TCP-сегмент. В заголовке IP указываются IP-адрес отправителя и IP-адрес сервера.
4.  **Канальный уровень**: IP-пакет помещается в Ethernet-кадр. С помощью протокола [ARP](./arp_protocol.md) определяется MAC-адрес шлюза (роутера), и этот MAC-адрес указывается как адрес назначения. Кадр отправляется в локальную сеть.
5.  **Маршрутизация**: Роутеры по всему миру, основываясь на IP-адресе назначения, перенаправляют пакет до тех пор, пока он не достигнет сети назначения.
6.  **Доставка**: Когда пакет прибывает на сервер, процесс декапсуляции проходит в обратном порядке, и HTTP-запрос доставляется веб-серверу.

### Сценарий 2: Получение IP-адреса по DHCP

1.  **Канальный уровень**: Устройство, подключенное к сети, не имеет IP-адреса. Оно отправляет широковещательный [DHCP](../Protocols/dhcp.md)-запрос (DHCPDISCOVER). MAC-адрес назначения в Ethernet-кадре устанавливается как `FF:FF:FF:FF:FF:FF`, чтобы все устройства в локальной сети получили этот кадр.
2.  **Реакция сервера**: DHCP-сервер в этой сети получает запрос и отвечает на него сообщением DHCPOFFER, предлагая IP-адрес и другие сетевые настройки. Ответ может быть широковещательным или одноадресным.
3.  **Подтверждение**: Устройство принимает предложение, отправляя DHCPREQUEST, и сервер финализирует аренду адреса сообщением DHCPACK. Весь этот обмен происходит в пределах одного широковещательного домена (локальной сети).

## Дополнительная информация

### Сравнение с моделью OSI

| Уровни OSI | Уровень TCP/IP | Ключевые отличия |
| :--- | :--- | :--- |
| 7. Прикладной<br>6. Представления<br>5. Сеансовый | **4. Прикладной (Application)** | TCP/IP объединяет функции верхних трех уровней OSI. Задачи сеанса и представления данных (шифрование, кодирование) решаются на прикладном уровне, если это необходимо приложению (например, протокол [TLS](../Protocols/tls.md)). |
| 4. Транспортный | **3. Транспортный (Transport)** | Функциональность очень схожа. |
| 3. Сетевой | **2. Сетевой (Internet)** | Уровень IP в TCP/IP является центральным элементом, вокруг которого построена вся модель. |
| 2. Канальный<br>1. Физический | **1. Канальный (Network Access)** | TCP/IP не детализирует эти уровни, предполагая, что они реализуются существующими технологиями (Ethernet, Wi-Fi). |

-   **OSI** — это **теоретическая, эталонная модель**, удобная для обучения и формального описания. Ее протоколы не получили широкого распространения.
-   **TCP/IP** — это **практическая модель**, на которой построен реальный интернет. Она проще и гибче.

### Гибридная пятиуровневая модель

Некоторые авторы, например Эндрю Таненбаум, предлагают гибридную **пятиуровневую модель**, которая ближе к практической реализации и сочетает в себе достоинства обеих моделей:
1.  Физический
2.  Канальный
3.  Сетевой
4.  Транспортный
5.  Прикладной
