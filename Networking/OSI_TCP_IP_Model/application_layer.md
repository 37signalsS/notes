# Прикладной уровень (Application Layer, L7)

## Определения

**Прикладной уровень (Application Layer, L7)** — верхний уровень сетевых моделей [OSI](./osi_model.md) и [TCP/IP](./tcp_ip_model.md), обеспечивающий интерфейс взаимодействия между программным обеспечением (приложениями) и сетевыми службами.

Это единственный уровень, который напрямую взаимодействует с пользовательскими данными и приложениями, такими как веб-браузеры, почтовые клиенты или терминалы удаленного доступа.

- **PDU (Protocol Data Unit — единица данных):** Данные (Data)
- **Адресация:** [Порты](../Concepts/network_ports.md) (в сочетании с IP-адресом образуют сетевой сокет)

> **Важно:** Необходимо различать сетевое приложение (например, браузер Google Chrome) и прикладной протокол (например, **HTTP** — Hypertext Transfer Protocol). Приложение использует протокол для обмена данными с другими узлами сети.

## Базовые концепции

### Абстракция и независимость

Протоколы прикладного уровня полностью изолированы от деталей передачи данных на нижних уровнях. Они полагаются на надежность или скорость, предоставляемую транспортным уровнем, не «зная» о физической среде передачи (кабель, радиоволны) или маршрутах следования пакетов.

### Взаимодействие с транспортным уровнем

Выбор протокола транспортного уровня определяется требованиями прикладного протокола к надежности и скорости.

| Протокол L4 | Характеристики | Когда используется | Примеры L7-протоколов |
| :--- | :--- | :--- | :--- |
| **[TCP](../Protocols/TCP/overview.md)** | Надёжный, с установкой соединения, гарантирует порядок и целостность | Когда потеря данных недопустима | HTTP/HTTPS, FTP, SMTP, SSH, gRPC |
| **[UDP](../Protocols/udp.md)** | Быстрый, без установки соединения, не гарантирует доставку | Когда важна минимальная задержка | DNS, DHCP, VoIP, потоковое видео, игры |

## Практические сценарии

### Оборудование и сетевые службы

На прикладном уровне работают не только конечные устройства (хосты), но и специализированное сетевое оборудование:

| Устройство / Служба | Функция | Примеры решений |
| :--- | :--- | :--- |
| **L7-балансировщики** | Маршрутизация трафика на основе содержимого (URL, заголовки, cookies) | [NGINX](../../WebServers/Nginx/Core/nginx_overview.md), HAProxy, Envoy |
| **WAF (Web Application Firewall)** | Защита от атак прикладного уровня (SQL-инъекции, XSS, L7 DDoS) | Cloudflare, ModSecurity, AWS WAF |
| **API-шлюзы (API Gateways)** | Централизованное управление API, аутентификация и трансформация протоколов | Kong, Tyk, Apigee |

### Основные протоколы прикладного уровня

| Протокол | Назначение | Порты | Транспорт (L4) |
| :--- | :--- | :--- | :--- |
| **[HTTP/HTTPS](../Protocols/HTTP/http_basics.md)** | Передача гипертекста и данных веб-приложений | 80, 443 | TCP |
| **[DNS](../Protocols/DNS/dns.md)** | Система доменных имен (преобразование имен в IP) | 53 | UDP / TCP |
| **[gRPC](../ServicesAndTools/grpc_overview.md)** | Удаленный вызов процедур для микросервисов | Любой | TCP (HTTP/2) |
| **SMTP / IMAP / POP3** | Передача и получение электронной почты | 25, 143, 110 | TCP |
| **SSH** | Безопасный удаленный доступ и управление | 22 | TCP |
| **FTP** | Протокол передачи файлов (File Transfer Protocol). Использует TCP, два соединения: управляющее (21) и данных (20). Обеспечивает надёжность, аутентификацию, список директорий. | 21, 20 | TCP |
| **TFTP** | Упрощённый протокол передачи файлов (Trivial File Transfer Protocol). Использует UDP, без аутентификации и списка директорий. Применяется для загрузки конфигураций и PXE-загрузки. | 69 | UDP |
| **SFTP** | Безопасная передача файлов поверх SSH (SSH File Transfer Protocol). | 22 | TCP |
| **[DHCP](../Protocols/DHCP/dhcp_overview.md)** | Динамическая настройка узла (назначение IP-адресов) | 67, 68 | UDP |

**FTP vs TFTP:** FTP использует TCP (надёжность, аутентификация, управление), создаёт два соединения (управляющее + данных). TFTP использует UDP (простота, без аутентификации), подходит для загрузки прошивок и PXE, но не обеспечивает безопасности и надёжности.

### Жизненный цикл сетевого запроса

Взаимодействие на прикладном уровне является отправной точкой для сложного процесса инкапсуляции и передачи данных по всему сетевому стеку. Подробный разбор всех этапов — от ввода URL в браузере до получения ответа — представлен в разделе **[Жизненный цикл веб-запроса](../Concepts/web_request_lifecycle.md)**.

## Дополнительная информация

### Место в модели OSI

Прикладной уровень завершает иерархию модели OSI, используя службы нижестоящих уровней:

- [Уровень представления (L6)](./presentation_layer.md) — кодирование и шифрование (например, [TLS](../Protocols/tls.md)).
- [Сеансовый уровень (L5)](./session_layer.md) — управление сессиями связи.

Сравнение функциональности и оборудования уровней L4 и L7 приведено в статье **[Модель OSI: Балансировщики нагрузки L4 и L7](./osi_model.md#балансировщики-нагрузки-l4-и-l7)**.
