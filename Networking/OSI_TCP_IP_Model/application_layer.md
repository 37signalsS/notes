# Прикладной уровень (L7)

## Определения

Прикладной уровень — это верхний уровень в сетевых моделях [OSI](./osi_model.md) и [TCP/IP](./tcp_ip_model.md), на котором непосредственно работают **сетевые приложения** (например, браузер, почтовый клиент). Он предоставляет интерфейс для взаимодействия приложений друг с другом через сеть.

Важно не путать само приложение и прикладной протокол, который оно использует. Например, сетевое приложение "веб-браузер" использует протокол [HTTP](../Protocols/http.md) для получения данных от другого сетевого приложения — "веб-сервера".

## Базовые концепции

### Абстракция от нижних уровней

Ключевая особенность прикладного уровня заключается в его **изоляции** от деталей реализации передачи данных. Протоколы этого уровня ([HTTP](../Protocols/http_protocol.md), [DNS](../Protocols/dns_protocol.md), SMTP и др.) не "знают", как именно данные передаются по сети — через кабели, Wi-Fi или оптоволокно. Они оперируют на уровне абстракции, как будто данные из одного приложения напрямую поступают в другое.

Задачу фактической доставки данных берет на себя **[транспортный уровень (L4)](./transport_layer.md)**.

### Взаимодействие с транспортным уровнем: TCP vs UDP

Прикладной уровень для передачи своих данных всегда использует один из двух основных протоколов транспортного уровня, которые предоставляют разные типы сервисов:

1.  **[TCP (Transmission Control Protocol — Протокол управления передачей)](../Protocols/tcp_protocol.md):**
    *   **Сервис:** Обеспечивает **надёжную** передачу **потока байтов**.
    *   **Как работает:** Устанавливает соединение между отправителем и получателем. Гарантирует, что все данные дойдут до адресата в правильном порядке и без потерь, выполняя повторную отправку в случае необходимости.
    *   **Когда используется:** В протоколах, где критична целостность и полнота данных (например, **[HTTP](../Protocols/http_protocol.md)**, FTP, SMTP).
    *   **Недостаток:** Установка соединения требует времени (TCP handshake), что создает дополнительные накладные расходы.

2.  **[UDP (User Datagram Protocol — Протокол пользовательских датаграмм)](../Protocols/udp_protocol.md):**
    *   **Сервис:** Обеспечивает **ненадёжную** передачу коротких сообщений (**дейтаграмм**).
    *   **Как работает:** Отправляет данные без предварительной установки соединения. Нет никаких гарантий, что пакет дойдет, и в каком порядке.
    *   **Когда используется:** В протоколах, где скорость важнее надежности, или для коротких запросов/ответов, где накладные расходы на установку TCP-соединения избыточны (например, **[DNS](../Protocols/dns.md)**, VoIP, **[DHCP](../Protocols/dhcp.md)**, онлайн-игры).
    *   **Преимущество:** Очень быстрый, так как отсутствуют задержки на установку соединения.

Выбор между TCP и UDP является фундаментальным решением при проектировании прикладного протокола и определяет его ключевые характеристики.

## Практические сценарии

### Оборудование

*   **Хосты:** Конечные устройства (компьютеры, серверы, смартфоны), на которых выполняются сетевые приложения.
*   **Шлюзы (Gateways):** Устройства, которые преобразуют данные из одного протокола в другой.
*   **L7-брандмауэры (Web Application Firewalls - WAF):** Устройства безопасности, анализирующие трафик на прикладном уровне для защиты от атак, таких как SQL-инъекции и XSS.

### Примеры протоколов и их применение

*   **[HTTP/HTTPS](../Protocols/http_protocol.md):** Для доступа к веб-сайтам.
*   **[DNS](../Protocols/dns_protocol.md):** Для преобразования доменных имен в IP-адреса.
*   **FTP/SFTP:** Для передачи файлов.
*   **SMTP, POP3, IMAP:** Для электронной почты.
*   **WebSocket:** Для интерактивной двунаправленной связи.
*   **[gRPC](../ServicesAndTools/grpc_overview.md):** Для удаленного вызова процедур.
