# Прикладной уровень (L7)

## Определения

**Прикладной уровень (Application Layer, L7)** — верхний уровень сетевых моделей [OSI](./osi_model.md) и [TCP/IP](./tcp_ip_model.md), обеспечивающий прямой интерфейс взаимодействия между программным обеспечением (приложениями) и сетевыми службами. Это единственный уровень, который напрямую работает с семантикой данных приложения.

- **PDU (Protocol Data Unit):** Данные (Data) / Сообщение (Message).
- **Адресация:** Идентификаторы прикладного уровня (URL, FQDN, Email, API-эндпоинты). На транспортном уровне опирается на [порты](../Concepts/network_ports.md).

> **Критическое различие:** Сетевое приложение (браузер, почтовый клиент) — это программный интерфейс, в то время как **прикладной протокол** (HTTP, SMTP) — это набор правил обмена данными, которые использует это приложение.

## Базовые концепции

### Взаимодействие с нижними уровнями

Протоколы L7 абстрагированы от топологии сети и полагаются на транспортный уровень (L4) для доставки данных.

| Протокол L4 | Требование L7 | Примеры L7-протоколов |
| :--- | :--- | :--- |
| **[TCP](../Protocols/TCP/overview.md)** | Целостность и порядок | HTTP/1.1, HTTP/2, SSH, БД (PostgreSQL, MySQL), gRPC |
| **[UDP](../Protocols/udp.md)** | Минимальная задержка | DNS, DHCP, VoIP, QUIC (база для HTTP/3), SNMP |

### Современные парадигмы: gRPC и HTTP/3

В современной архитектуре (2026+) произошел сдвиг в сторону бинарных протоколов и оптимизации задержек:
1.  **HTTP/3 (QUIC):** Устраняет проблему блокировки начала очереди (HOL Blocking) на транспортном уровне. Использует 0-RTT для мгновенной установки соединения.
2.  **gRPC:** Использует Protocol Buffers (Protobuf) для сериализации и HTTP/2 или HTTP/3 для передачи. Обеспечивает строгую типизацию и высокую производительность в микросервисах. Подробнее: **[Обзор gRPC](../ServicesAndTools/grpc_overview.md)**.

## Наблюдаемость и безопасность L7

### Наблюдаемость (Observability)
На уровне L7 осуществляется сбор ключевых метрик (Golden Signals):
- **Latency:** Время обработки запроса.
- **Traffic:** Количество запросов в секунду (RPS).
- **Errors:** Количество ошибок (4xx, 5xx).
- **Saturation:** Степень загрузки ресурсов приложения.

Современные инструменты на базе **eBPF** позволяют отслеживать L7-трафик без модификации кода приложения и без существенных задержек.

### Безопасность
Защита на прикладном уровне требует анализа содержимого пакетов (Deep Packet Inspection, DPI):
- **Инспекция TLS:** Расшифровка трафика для анализа на наличие угроз.
- **Анализ поведения:** Обнаружение ботов и атак на бизнес-логику (например, перебор паролей).
- **Zero Trust:** Проверка идентичности (mTLS) для каждого запроса внутри сети.
