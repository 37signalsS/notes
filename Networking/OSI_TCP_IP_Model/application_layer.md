# Прикладной уровень (L7)

## Определения

**Прикладной уровень** — верхний уровень в сетевых моделях [OSI](./osi_model.md) и [TCP/IP](./tcp_ip_model.md), на котором непосредственно работают **сетевые приложения**. Предоставляет интерфейс для взаимодействия приложений через сеть.

> **Важно:** Не путать приложение и прикладной протокол. Например, "веб-браузер" (приложение) использует протокол [HTTP](../Protocols/http.md) для связи с "веб-сервером".

- **PDU (Protocol Data Unit):** Данные (Data)
- **Адресация:** [Порты](../Concepts/network_ports.md) (в сочетании с IP образуют сокет)

## Базовые концепции

### Абстракция от нижних уровней

Протоколы L7 ([HTTP](../Protocols/http.md), [DNS](../Protocols/DNS/dns.md), SMTP и др.) **изолированы** от деталей передачи данных. Они не "знают" о кабелях, Wi-Fi или маршрутизации. Задачу доставки берёт на себя **[транспортный уровень (L4)](./transport_layer.md)**.

### Взаимодействие с транспортным уровнем

| Протокол L4 | Тип сервиса | Гарантии | Когда используется | Примеры L7 |
| :--- | :--- | :--- | :--- | :--- |
| **[TCP](../Protocols/TCP/overview.md)** | Потоковый, надёжный | Доставка, порядок, повторная отправка | Целостность критична | HTTP, FTP, SMTP, SSH |
| **[UDP](../Protocols/udp.md)** | Дейтаграммный, ненадёжный | Нет гарантий, быстрее | Скорость важнее | DNS, VoIP, DHCP, игры |

**Выбор между TCP и UDP** — фундаментальное решение при проектировании прикладного протокола.

## Практические сценарии

### Оборудование

| Устройство | Функция | Примеры |
| :--- | :--- | :--- |
| **Хосты** | Выполнение сетевых приложений | Компьютеры, серверы, смартфоны |
| **Шлюзы (Gateways)** | Преобразование протоколов | Прокси-серверы, API-шлюзы |
| **L7-брандмауэры (WAF)** | Анализ трафика L7, защита от атак | ModSecurity, AWS WAF, F5 ASM |
| **L7-балансировщики** | Маршрутизация по URL, заголовкам, cookies | NGINX, HAProxy, Envoy |

### Протоколы и применение

| Протокол | Назначение | Порт(ы) | Транспорт |
| :--- | :--- | :--- | :--- |
| **[HTTP/HTTPS](../Protocols/http.md)** | Веб-сайты, API | 80/443 | TCP |
| **[DNS](../Protocols/DNS/dns.md)** | Разрешение имён в IP | 53 | UDP/TCP |
| **FTP/SFTP** | Передача файлов | 21/22 | TCP |
| **SMTP** | Отправка почты | 25, 587 | TCP |
| **POP3/IMAP** | Получение почты | 110/143 | TCP |
| **SSH** | Удалённый доступ | 22 | TCP |
| **WebSocket** | Двунаправленная связь | 80/443 | TCP |
| **[gRPC](../ServicesAndTools/grpc_overview.md)** | RPC, микросервисы | Любой | TCP |
| **DHCP** | Автоназначение IP | 67/68 | UDP |

### Сценарий: Запрос веб-страницы

1. Браузер формирует HTTP GET-запрос
2. DNS-запрос для разрешения домена в IP (UDP)
3. TCP handshake с сервером (порт 443)
4. TLS handshake (шифрование)
5. Отправка HTTP-запроса
6. Получение HTTP-ответа
7. Рендеринг страницы
