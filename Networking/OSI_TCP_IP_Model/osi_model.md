# Модель OSI

## Определения

**Модель OSI (Open Systems Interconnection Reference Model)** — концептуальная семиуровневая модель, разработанная ISO для стандартизации сетевых функций и обеспечения совместимости различных технологий.

Вся сетевая инженерия — это, по сути, **набор протоколов**, где каждый следующий уровень решает проблему, которую не решил предыдущий. Модель OSI служит универсальным «языком» для описания того, как данные проходят путь от приложения на одном компьютере до приложения на другом.

**Открытая система** — система (компьютер, сетевое устройство), соответствующая открытым стандартам и способная взаимодействовать с другими открытыми системами.

### История и стандарты

| Параметр | Значение |
| :--- | :--- |
| **Разработчик** | ISO совместно с IEC |
| **Стандарт** | ISO/IEC 7498-1:1994 |
| **Год принятия** | 1984 |
| **Текущий статус** | Теоретическая основа, вытеснена [моделью TCP/IP](./tcp_ip_model.md) |

## Базовые концепции

### Уровни модели OSI

Каждый уровень решает свою задачу и ничего не знает о том, что происходит выше или ниже (принцип инкапсуляции).

| Уровень (Layer) | PDU (Тип данных) | Основные функции | Примеры | Оборудование |
| :--- | :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | **Данные (Data)** | Интерфейс взаимодействия приложений с сетью. | HTTP, FTP, DNS, gRPC | Хосты, L7-WAF |
| **6. Представления (Presentation)** | **Данные (Data)** | Кодирование, сжатие, шифрование. | SSL/TLS, JPEG, ASCII | Хосты |
| **5. Сеансовый (Session)** | **Данные (Data)** | Управление сеансами (создание, поддержание, разрыв). | NetBIOS, RPC | Хосты |
| **4. Транспортный (Transport)** | **Сегменты/Дейтаграммы**| Доставка между процессами, контроль целостности. | TCP, UDP, SCTP | Хосты, L4-FW |
| **3. Сетевой (Network)** | **Пакеты (Packets)** | Логическая адресация и выбор пути (маршрутизация). | IPv4, IPv6, ICMP | Маршрутизатор, L3-Switch |
| **2. Канальный (Data Link)** | **Кадры (Frames)** | Физическая адресация, доставка в локальной сети. | Ethernet, Wi-Fi, ARP | Коммутатор (Switch), Bridge |
| **1. Физический (Physical)** | **Биты (Bits)** | Передача сигналов по физической среде. | Кабели, Радиоволны | Хаб, Репитер, SFP |

*   **Верхние уровни (Host layers): 7–4** — реализуются программно в ОС и приложениях. Фокус на данных.
*   **Нижние уровни (Media layers): 1–3** — реализуются аппаратно и программно. Фокус на передаче через среду.

### Процесс передачи данных

Передача данных основана на двух ключевых процессах: **инкапсуляции** (при отправке) и **декапсуляции** (при получении).

#### Схема инкапсуляции

```text
[ Прикладной ] ----> Данные (Data)
[ Представления] ----> [H6][ Данные ]
[ Сеансовый ] ----> [H5][ Данные ]
[ Транспортный ] ----> [H4 (Порты)][ Данные ] = СЕГМЕНТ
[ Сетевой ] ----> [H3 (IP)][ Сегмент ] = ПАКЕТ
[ Канальный ] ----> [H2 (MAC)][ Пакет ][T2 (CRC)] = КАДР
[ Физический ] ----> 0101010110... = БИТЫ
```

**Важное правило маршрутизации:**
*   **IP-адреса** (L3) остаются неизменными от отправителя до получателя.
*   **MAC-адреса** (L2) меняются на каждом узле (маршрутизаторе), так как они отвечают за доставку только до следующего «хопа».

### Траблшутинг по уровням OSI

Метод «разделяй и властвуй» в диагностике сетей:

1.  **L1 (Физический):** Горят ли лампочки на порту? Цел ли кабель? Есть ли питание?
2.  **L2 (Канальный):** Видит ли коммутатор MAC-адрес устройства? Нет ли ошибок в VLAN? Проходит ли ARP-запрос?
3.  **L3 (Сетевой):** Проходит ли `ping` до шлюза или удаленного хоста? Верна ли таблица маршрутизации?
4.  **L4 (Транспортный):** Открыт ли нужный порт? Проходит ли TCP-рукопожатие (Handshake)? Не блокирует ли трафик Firewall?
5.  **L7 (Прикладной):** Что в логах приложения? Корректен ли HTTP-запрос? Нет ли ошибок аутентификации?

## Практические сценарии

### Сравнение балансировщиков L4 и L7

| Параметр | L4-балансировщик | L7-балансировщик |
| :--- | :--- | :--- |
| **База принятия решений** | IP, TCP/UDP порт | URL, заголовки HTTP, Cookies |
| **Производительность** | Очень высокая (анализ только заголовков) | Ниже (анализ тела запроса) |
| **Безопасность** | Базовая фильтрация | Глубокий анализ (WAF), терминация SSL |
| **Примеры** | HAProxy (TCP mode), IPVS, AWS NLB | Nginx, Envoy, AWS ALB |

## Дополнительная информация

### Роль в современной практике

Хотя Интернет построен на базе стека TCP/IP, модель OSI остается незаменимой:
*   **Универсальный стандарт:** позволяет разным вендорам (Cisco, Juniper, Huawei) взаимодействовать друг с другом.
*   **Аналитический инструмент:** помогает декомпозировать сложные проблемы.
*   **Обучение:** дает четкое понимание иерархии ответственности протоколов.

### Сравнение моделей OSI и TCP/IP

| Характеристика | OSI | TCP/IP |
| :--- | :--- | :--- |
| **Подход** | Теоретический (ISO) | Практический (IETF) |
| **Уровни** | 7 уровней | 4 уровня (или 5) |
| **Прикладной уровень**| Разделен на 3 (L7, L6, L5) | Единый прикладной уровень |
| **Статус** | Эталонная модель | Стандарт Интернета |
