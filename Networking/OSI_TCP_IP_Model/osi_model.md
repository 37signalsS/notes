# Модель OSI (Open Systems Interconnection)

## Определения

**Модель OSI (Open Systems Interconnection Reference Model)** — концептуальная семиуровневая модель, разработанная ISO для стандартизации сетевых функций и обеспечения совместимости различных технологий.

**Открытая система** — система (компьютер, сетевое устройство), соответствующая открытым стандартам и способная взаимодействовать с другими открытыми системами.

### История и стандарты

| Параметр | Значение |
| :--- | :--- |
| **Разработчик** | ISO совместно с IEC |
| **Стандарт** | ISO/IEC 7498-1:1994 |
| **Год принятия** | 1984 |
| **Текущий статус** | Теоретическая основа, вытеснена [моделью TCP/IP](./tcp_ip_model.md) |

## Базовые концепции

### Уровни модели OSI

Каждый уровень обслуживает вышестоящий и использует функции нижестоящего. В процессе отправки данные проходят от 7-го уровня к 1-му (**инкапсуляция**), а при получении — в обратном порядке (**декапсуляция**). На каждом уровне к данным добавляется заголовок, и этот блок данных называется **PDU (Protocol Data Unit)**.

| Уровень (Layer) | PDU (Тип данных) | Основные функции | Примеры протоколов и стандартов | Оборудование |
| :--- | :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | **Данные (Data)** | См. [Прикладной уровень (L7)](./application_layer.md) | [HTTP](../Protocols/http.md), FTP, SMTP, DNS, [gRPC](../ServicesAndTools/grpc_overview.md) | Хосты, Шлюзы, L7-брандмауэры (WAF) |
| **6. Представления (Presentation)** | **Данные (Data)** | См. [Уровень представления (L6)](./presentation_layer.md) | [SSL/TLS](../Protocols/tls.md), ASCII, JPEG, MPEG | Хосты, Шлюзы |
| **5. Сеансовый (Session)** | **Данные (Data)** | См. [Сеансовый уровень (L5)](./session_layer.md) | NetBIOS, RPC, Sockets API | Хосты, Шлюзы |
| **4. Транспортный (Transport)** | **Сегменты/Дейтаграммы**| См. [Транспортный уровень (L4)](./transport_layer.md) | TCP, UDP, SCTP | Хосты, L4-брандмауэры |
| **3. Сетевой (Network)** | **Пакеты (Packets)** | См. [Сетевой уровень (L3)](./Network_layer/Concepts/network_layer_overview.md) | IPv4, IPv6, ICMP, [DHCP](../Protocols/dhcp.md) | Маршрутизатор, L3-коммутатор |
| **2. Канальный (Data Link)** | **Кадры (Frames)** | См. [Канальный уровень (L2)](./data_link_layer.md) | Ethernet, Wi-Fi, [ARP](../Protocols/arp.md), [VLAN](../Protocols/vlan.md) | Коммутатор, Мост, Сетевая карта (NIC) |
| **1. Физический (Physical)** | **Биты (Bits)** | См. [Физический уровень (L1)](./physical_layer.md) | Ethernet (кабель), USB, Bluetooth, Оптоволокно | Концентратор, Повторитель, Кабели |

* **Host layers (Уровни хоста): 7–4** — отвечают за представление данных и взаимодействие с приложениями. Реализуются в ОС конечных устройств.
* **Media layers (Уровни среды): 1–3** — отвечают за передачу данных по сети.

### Процесс передачи данных

#### Инкапсуляция (отправка)

1. **L7 (Данные):** Приложение формирует данные.
    * `[Данные: "Привет"]`
2. **L4 (Сегменты/Дейтаграммы):** Данные упаковываются в **сегмент** с указанием **[портов](../Concepts/network_ports.md)** отправителя и получателя.
    * `[Заголовок TCP/UDP (порты)] [Данные]`
3. **L3 (Пакеты):** Сегмент упаковывается в **пакет** с указанием **[IP-адресов](../Protocols/ip.md)** отправителя и получателя для глобальной маршрутизации.
    * `[Заголовок IP (IP-адреса)] [Сегмент]`
4. **L2 (Кадры):** Пакет упаковывается в **кадр** с **[MAC-адресами](../Concepts/mac_address.md)** для доставки в пределах локальной сети.
    * `[Заголовок Ethernet (MAC-адреса)] [Пакет] [Концевик]`
5. **L1 (Биты):** Кадр преобразуется в электрические или световые сигналы для передачи по физической среде.
    * `0101011101000101...`

#### Декапсуляция (получение, L1 → L7)

Процесс происходит в обратном порядке: на каждом уровне соответствующий заголовок считывается и отбрасывается, а данные передаются на вышестоящий уровень, пока не достигнут приложения-получателя.

### Сетевая адресация

| Тип | Уровень | Пример | Действие |
| :--- | :--- | :--- | :--- |
| **Локальные адреса** | L2 | [MAC-адреса](../Concepts/mac_address.md) | В пределах сегмента сети |
| **Глобальные адреса** | L3 | [IP-адреса](../Protocols/ip.md) | Маршрутизация в глобальных сетях |

### Мнемонические правила (L1 → L7)

* «**Ф**изики **К**анали **С**етевым **Т**ранспортом **С**еансы **П**редставляют **А**ппликациям»
* «**Ф**ундамент **К**репок — **С**еть **Т**очно **С**вяжет **П**ланеты **А**бсолютно»

## Практические сценарии

### Балансировщики нагрузки L4 и L7

**Подробное описание:** [transport_layer.md](./transport_layer.md#оборудование-и-по), [application_layer.md](./application_layer.md#оборудование)

| Параметр | L4-балансировщик | L7-балансировщик |
| :--- | :--- | :--- |
| **Уровень** | Транспортный (L4) | Прикладной (L7) |
| **Решения на основе** | IP, порты, протокол (TCP/UDP) | URL, заголовки HTTP, cookies |
| **Производительность** | Быстрее, меньше накладных расходов | Медленнее, анализ содержимого |
| **Возможности** | Базовая маршрутизация | Маршрутизация по контенту, SSL offloading, кэширование |
| **Примеры** | HAProxy (mode tcp), NGINX (stream) | HAProxy (mode http), NGINX, Envoy |

## Дополнительная информация

### Роль в современной практике

Модель OSI почти не используется на практике в чистом виде. Её вытеснила более простая **[модель TCP/IP](./tcp_ip_model.md)**.

**OSI — это:**

* **Теоретический инструмент** для обучения и анализа
* **Общий язык** сетевых инженеров
* **Эталонная основа** для описания взаимодействий

### Сравнение OSI и TCP/IP

| Характеристика | OSI | TCP/IP |
| :--- | :--- | :--- |
| **Разработчик** | ISO/IEC | IETF / DARPA |
| **Подход** | Теоретический, «сверху вниз» | Практический, «снизу вверх» |
| **Уровней** | 7 | 4 (или 5 в гибридной) |
| **Распространение** | Теоретическая основа | Стандарт Интернета |
| **Гибкость** | Жёсткая иерархия | Гибкая, адаптируемая |

### Гибридная пятиуровневая модель

Модель, сочетающая OSI и TCP/IP (Эндрю Таненбаум):

| Уровень | Соответствие OSI |
| :--- | :--- |
| **5. Прикладной** | L7 + L6 + L5 |
| **4. Транспортный** | L4 |
| **3. Сетевой** | L3 |
| **2. Канальный** | L2 |
| **1. Физический** | L1 |

Используется в учебной литературе для упрощения.
