# Модель OSI

## Определения

**Модель OSI (Open Systems Interconnection Reference Model)** — концептуальная семиуровневая модель, разработанная ISO для стандартизации сетевых функций и обеспечения совместимости различных технологий. Она описывает, как данные проходят путь от приложения на одном компьютере до приложения на другом.

Вся сетевая инженерия — это, по сути, **набор протоколов**, где каждый следующий уровень решает проблему, которую не решил предыдущий. Модель OSI служит универсальным «языком» для описания сетевых процессов.

**Открытая система** — система (компьютер, сетевое устройство), соответствующая открытым стандартам и способная взаимодействовать с другими открытыми системами независимо от производителя.

### История и стандарты

| Параметр | Значение |
| :--- | :--- |
| **Разработчик** | ISO совместно с IEC |
| **Стандарт** | ISO/IEC 7498-1:1994 |
| **Год принятия** | 1984 |
| **Текущий статус** | Теоретическая основа, вытеснена практической [моделью TCP/IP](./tcp_ip_model.md) |

## Базовые концепции

### Уровни модели OSI

Каждый уровень решает свою задачу и ничего не знает о том, что происходит выше или ниже (принцип инкапсуляции). Взаимодействие происходит только с соседними уровнями через интерфейсы и с аналогичным уровнем удаленной системы через протоколы.

| Уровень (Layer) | PDU (Тип данных) | Основные функции | Примеры | Оборудование |
| :--- | :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | **Данные (Data)** | Интерфейс взаимодействия приложений с сетью. | HTTP, FTP, DNS, gRPC, SMTP, SSH | Хосты, L7-WAF, Proxy |
| **6. Представления (Presentation)** | **Данные (Data)** | Кодирование, сжатие, шифрование, сериализация. | SSL/TLS, JSON, XML, JPEG, ASCII | Хосты |
| **5. Сеансовый (Session)** | **Данные (Data)** | Управление сеансами (создание, поддержание, разрыв, чекпоинты). | RPC, NetBIOS, Sockets API | Хосты |
| **4. Транспортный (Transport)** | **Сегменты / Дейтаграммы**| Доставка между процессами, контроль целостности и потока. | TCP, UDP, SCTP, QUIC | Хосты, L4-FW, Балансировщики (NLB) |
| **3. Сетевой (Network)** | **Пакеты (Packets)** | Логическая адресация и выбор пути (маршрутизация). | IPv4, IPv6, ICMP, IPsec, BGP | Маршрутизатор, L3-Switch |
| **2. Канальный (Data Link)** | **Кадры (Frames)** | Физическая адресация, доставка в локальной сети, контроль ошибок. | Ethernet, Wi-Fi, ARP, STP | Коммутатор (Switch), Bridge |
| **1. Физический (Physical)** | **Биты (Bits)** | Передача сигналов по физической среде. | Кабели (UTP, Fiber), Радиоволны, SFP | Хаб, Репитер, Медиаконвертер |

*   **Верхние уровни (Host layers): 7–4** — реализуются программно в ОС и приложениях. Фокус на данных и взаимодействии процессов.
*   **Нижние уровни (Media layers): 1–3** — реализуются аппаратно и программно. Фокус на передаче через среду.

### Процесс передачи данных

Передача данных основана на двух ключевых процессах: **инкапсуляции** (при отправке) и **декапсуляции** (при получении).

#### Схема инкапсуляции

```text
[ Прикладной ] ----> Данные (Data)
[ Представления] ----> [H6][ Данные ]
[ Сеансовый ] ----> [H5][ Данные ]
[ Транспортный ] ----> [H4 (Порты)][ Данные ] = СЕГМЕНТ
[ Сетевой ] ----> [H3 (IP)][ Сегмент ] = ПАКЕТ
[ Канальный ] ----> [H2 (MAC)][ Пакет ][T2 (CRC)] = КАДР
[ Физический ] ----> 0101010110... = БИТЫ
```

**Важное правило маршрутизации:**
*   **IP-адреса** (L3) остаются неизменными от отправителя до получателя (за исключением NAT).
*   **MAC-адреса** (L2) меняются на каждом узле (маршрутизаторе), так как они отвечают за доставку только до следующего «хопа» в локальном сегменте.

### Логическое взаимодействие (Peer-to-Peer)

Уровни одной системы взаимодействуют с соответствующими уровнями другой системы так, будто они соединены напрямую. Например, L4 на стороне отправителя добавляет порядковый номер TCP-сегмента, который проверяется L4 на стороне получателя, при этом промежуточные узлы (маршрутизаторы L3) этот номер не анализируют.

## Практические сценарии

### Траблшутинг по уровням OSI

Метод «разделяй и властвуй» в диагностике сетей (обычно снизу вверх):

1.  **L1 (Физический):** Горят ли лампочки на порту? Цел ли кабель? Есть ли питание? Не повреждены ли SFP-модули?
2.  **L2 (Канальный):** Видит ли коммутатор MAC-адрес устройства (`show mac address-table`)? Нет ли ошибок в VLAN? Проходит ли ARP-запрос? Не заблокирован ли порт протоколом STP?
3.  **L3 (Сетевой):** Проходит ли `ping` до шлюза или удаленного хоста? Верна ли таблица маршрутизации (`ip route`)? Нет ли проблем с MTU (фрагментация)?
4.  **L4 (Транспортный):** Открыт ли нужный порт (`nc -zv`, `telnet`)? Проходит ли TCP-рукопожатие (Handshake)? Не блокирует ли трафик Firewall или Security Group?
5.  **L5/L6 (Сеансовый/Представления):** Нет ли проблем с TLS-сертификатами (истекли, неверный CA)? Корректна ли кодировка данных? Совпадают ли версии протоколов сериализации (например, Protobuf)?
6.  **L7 (Прикладной):** Что в логах приложения? Корректен ли HTTP-запрос (заголовки, метод)? Нет ли ошибок аутентификации (401/403) или проблем на стороне бэкенда (5xx)?

### Сравнение балансировщиков трафика

| Параметр | L4-балансировщик (NLB) | L7-балансировщик (ALB/Ingress) |
| :--- | :--- | :--- |
| **База принятия решений** | IP, TCP/UDP порт | URL, заголовки HTTP, Cookies, SNI |
| **Производительность** | Экстремально высокая (анализ только L4-заголовков) | Ниже (требуется парсинг L7-данных) |
| **Безопасность** | Базовая фильтрация по IP/Port | Глубокий анализ (WAF), терминация SSL/TLS |
| **Возможности** | Прозрачная проксируемость | Sticky Sessions, Path-based routing, манипуляция заголовками |
| **Примеры** | IPVS, HAProxy (TCP mode), AWS NLB | Nginx, Envoy, Traefik, AWS ALB |

### Безопасность и DDoS-атаки

*   **L3/L4 атаки:** SYN-flood, UDP-flood. Цель — забить канал или исчерпать ресурсы сетевого стека. Защита: фильтрация на уровне провайдера, Anycast, увеличение очередей TCP.
*   **L7 атаки:** HTTP-flood, Slowloris. Цель — исчерпать ресурсы приложения (CPU, RAM, коннекты к БД). Защита: Rate-limiting, WAF, анализ поведения пользователей.

## Дополнительная информация

### Роль в современной практике

Хотя Интернет построен на базе стека TCP/IP, модель OSI остается незаменимой:
*   **Универсальный стандарт:** позволяет разным вендорам (Cisco, Juniper, Arista) взаимодействовать друг с другом.
*   **Аналитический инструмент:** помогает декомпозировать сложные архитектурные проблемы на понятные зоны ответственности.
*   **Обучение:** дает фундамент для понимания того, как работают инкапсуляция и абстракция в ИТ-системах.
