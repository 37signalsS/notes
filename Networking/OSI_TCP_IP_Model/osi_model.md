# Модель OSI

## 1. Определения

*   **Модель OSI (Open Systems Interconnection Reference Model)** — это концептуальная семиуровневая модель, разработанная Международной организацией по стандартизации (ISO), которая стандартизирует сетевые функции для обеспечения совместимости различных сетевых технологий.
*   **Открытая система** — любая система (компьютер, сетевое устройство), которая соответствует открытым стандартам и спецификациям, что позволяет ей взаимодействовать с другими открытыми системами. Например, ОС Windows является открытой системой с точки зрения сети, хотя ее исходный код закрыт.

## 2. Базовые концепции

### Уровни модели OSI

Каждый уровень обслуживает вышестоящий и использует функции нижестоящего. В процессе отправки данные проходят от 7-го уровня к 1-му (**инкапсуляция**), а при получении — в обратном порядке (**декапсуляция**). На каждом уровне к данным добавляется заголовок, и этот блок данных называется **PDU (Protocol Data Unit)**.

| Уровень (Layer) | PDU (Тип данных) | Основные функции | Примеры протоколов и стандартов | Оборудование |
| :--- | :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | **Данные (Data)** | См. [[application_layer|Прикладной уровень (L7)]] | [HTTP](../Protocols/http.md), FTP, SMTP, DNS, [gRPC](../ServicesAndTools/grpc_overview.md) | Хосты, Шлюзы, L7-брандмауэры (WAF) |
| **6. Представления (Presentation)** | **Данные (Data)** | См. [[presentation_layer|Уровень представления (L6)]] | [SSL/TLS](../Protocols/tls_protocol.md), ASCII, JPEG, MPEG | Хосты, Шлюзы |
| **5. Сеансовый (Session)** | **Данные (Data)** | См. [[session_layer|Сеансовый уровень (L5)]] | NetBIOS, RPC, Sockets API | Хосты, Шлюзы |
| **4. Транспортный (Transport)** | **Сегменты/Дейтаграммы**| См. [[transport_layer|Транспортный уровень (L4)]] | TCP, UDP, SCTP | Хосты, L4-брандмауэры |
| **3. Сетевой (Network)** | **Пакеты (Packets)** | См. [[network_layer|Сетевой уровень (L3)]] | IPv4, IPv6, ICMP, [DHCP](../Protocols/dhcp.md) | Маршрутизатор, L3-коммутатор |
| **2. Канальный (Data Link)** | **Кадры (Frames)** | См. [[data_link_layer|Канальный уровень (L2)]] | Ethernet, Wi-Fi, [ARP](./arp_protocol.md), [VLAN](./vlan.md) | Коммутатор, Мост, Сетевая карта (NIC) |
| **1. Физический (Physical)** | **Биты (Bits)** | См. [[physical_layer|Физический уровень (L1)]] | Ethernet (кабель), USB, Bluetooth, Оптоволокно | Концентратор, Повторитель, Кабели |

*   **Host layers (Уровни хоста): 7–4** — отвечают за представление данных и взаимодействие с приложениями. Реализуются в ОС конечных устройств.
*   **Media layers (Уровни среды): 1–3** — отвечают за передачу данных по сети.

### Процесс передачи данных

#### Инкапсуляция (отправка)

1.  **L7 (Данные):** Приложение формирует данные.
    *   `[Данные: "Привет"]`
2.  **L4 (Сегменты/Дейтаграммы):** Данные упаковываются в **сегмент** с указанием **[портов](./network_ports.md)** отправителя и получателя.
    *   `[Заголовок TCP/UDP (порты)] [Данные]`
3.  **L3 (Пакеты):** Сегмент упаковывается в **пакет** с указанием **[IP-адресов](./ip_address.md)** отправителя и получателя для глобальной маршрутизации.
    *   `[Заголовок IP (IP-адреса)] [Сегмент]`
4.  **L2 (Кадры):** Пакет упаковывается в **кадр** с **[MAC-адресами](./mac_address.md)** для доставки в пределах локальной сети.
    *   `[Заголовок Ethernet (MAC-адреса)] [Пакет] [Концевик]`
5.  **L1 (Биты):** Кадр преобразуется в электрические или световые сигналы для передачи по физической среде.
    *   `0101011101000101...`

#### Декапсуляция (получение)

Процесс происходит в обратном порядке: на каждом уровне соответствующий заголовок считывается и отбрасывается, а данные передаются на вышестоящий уровень, пока не достигнут приложения-получателя.

### Сетевая адресация

*   **Локальные адреса (L2):** Привязаны к технологии канального уровня (например, MAC-адреса в Ethernet). Действуют только в пределах одного сегмента сети.
*   **Глобальные адреса (L3):** Используются на сетевом уровне (например, IP-адреса) и не зависят от технологии nižлежащего уровня, что делает возможной маршрутизацию в глобальных сетях.

## 3. Практические сценарии

### Балансировщики нагрузки L4 и L7

Балансировщики нагрузки распределяют трафик между серверами, и их классифицируют по уровню OSI, на котором они работают.

#### Балансировщик L4 (Транспортный уровень)

*   **Работает на:** Транспортном уровне (Layer 4) модели OSI.
*   **Принимает решения на основе:** IP-адресов, портов и протоколов (TCP/UDP).
*   **Как работает:** Перенаправляет сетевые пакеты на основе IP-адреса и порта назначения, не анализируя содержимое самих пакетов. Устанавливает TCP-соединение между клиентом и выбранным сервером.
*   **Особенности:**
    *   **Быстрый и эффективный:** Меньше накладных расходов, так как не требуется глубокий анализ пакетов.
    *   **Простой:** Не требует сложной конфигурации для базовых задач.
    *   **Прозрачный:** Не вносит изменений в HTTP-заголовки, поэтому бэкенд-серверы видят оригинальный IP-адрес клиента (если нет NAT).
    *   **Недостатки:** Не может принимать решения на основе содержимого HTTP-запросов (URL, куки, заголовки и т.д.).

#### Балансировщик L7 (Прикладной уровень)

*   **Работает на:** Прикладном уровне (Layer 7) модели OSI.
*   **Принимает решения на основе:** Данных прикладного уровня, таких как:
    *   URL-пути (например, `/api/users`, `/images`)
    *   HTTP-заголовки (например, `User-Agent`, `Host`, `Accept-Language`)
    *   Куки (Cookies)
    *   Тип контента (`Content-Type`)
    *   HTTP-методы (GET, POST, PUT, DELETE и т.д.)
*   **Как работает:** Завершает TCP-соединение с клиентом, анализирует весь HTTP-запрос (или другой протокол L7), а затем открывает новое TCP-соединение с выбранным бэкенд-сервером. Это позволяет ему "видеть" и изменять содержимое запросов и ответов.
*   **Особенности:**
    *   **Интеллектуальный:** Позволяет реализовать сложные правила маршрутизации и распределения трафика.
    *   **Гибкий:** Поддерживает маршрутизацию на основе контента, A/B-тестирование, переписывание URL, SSL/TLS-терминацию.
    *   **Возможности:** Умеет выполнять SSL/TLS-разгрузку (offloading), вставлять HTTP-заголовки (например, `X-Forwarded-For`), сжимать данные, кэшировать ответы.
    *   **Недостатки:** Более медленный и ресурсоемкий из-за необходимости парсинга и анализа содержимого на прикладном уровне.

## 4. Дополнительная информация

### Роль в современной практике

Модель OSI, несмотря на свою проработанность, на практике в чистом виде почти не используется. Ее вытеснила более простая и гибкая **[модель TCP/IP](./tcp_ip_model.md)**.

Тем не менее, OSI остается незаменимым **теоретическим инструментом и общим языком** для сетевых инженеров. Она служит эталонной основой для описания сетевых взаимодействий, анализа проблем и сопоставления различных технологий.
