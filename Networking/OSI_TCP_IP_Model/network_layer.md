# Сетевой уровень (L3)

## Определения

**Сетевой уровень (L3)** — это третий уровень [модели OSI](./osi_model.md), главная задача которого — построение крупных **составных сетей (internetworks)** из множества разнородных сетей, каждая из которых может быть построена на своей технологии канального уровня (Ethernet, Wi-Fi, сотовые сети и т.д.). Именно сетевой уровень и его протоколы (в первую очередь, IP) делают возможным существование глобальной сети Интернет.

Тип данных (PDU), с которым оперирует сетевой уровень, — **пакет (Packet)**.

## Основные концепции

### Необходимость сетевого уровня: ограничения L2

Технологии канального уровня (L2), такие как [Ethernet](../Protocols/ethernet.md), отлично подходят для создания локальных сетей, но они имеют фундаментальные ограничения, которые не позволяют построить на их основе глобальную сеть:

1.  **Разнородность технологий:** Существует множество L2-технологий, которые отличаются адресацией (MAC-адреса), максимальным размером кадра (MTU) и принципами работы. Сетевой уровень предоставляет "надстройку" для их бесшовного объединения.
2.  **Проблема масштабируемости:**
    *   **Размер таблиц коммутации:** Коммутаторы хранят MAC-адреса всех устройств в сети. В глобальной сети с миллиардами устройств такая таблица была бы невозможна для хранения и поиска.
    *   **Широковещательный шторм:** Если коммутатор не знает MAC-адрес получателя, он рассылает кадр на все порты. В масштабах Интернета это привело бы к мгновенному коллапсу сети из-за лавины "мусорного" трафика.
3.  **Отсутствие множественных путей:** Технологии L2 не допускают петель в топологии. Протокол [STP](../Protocols/stp.md), который борется с петлями, отключает резервные каналы, что в глобальной сети привело бы к неэффективному использованию ресурсов.

### Ключевые функции

Сетевой уровень решает вышеописанные проблемы с помощью следующих механизмов:

1.  **Объединение сетей (Internetworking):** Предоставление единой системы для связи между сетями, построенными на разных технологиях.
2.  **Глобальная адресация:** Введение унифицированной системы логических **глобальных адресов** ([IP-адресов](../Protocols/ip.md)), которые не зависят от физических адресов канального уровня ([MAC-адресов](../Concepts/mac_address.md)). Это позволяет однозначно идентифицировать любой узел в глобальной сети.
3.  **Маршрутизация (Routing):** Процесс определения и выбора оптимального пути для доставки пакетов через транзитные узлы — **маршрутизаторы**. В отличие от L2, сетевой уровень позволяет иметь **несколько активных путей** между узлами. Маршрутизаторы постоянно обмениваются информацией о топологии сети (с помощью протоколов маршрутизации, таких как OSPF), что позволяет им адаптироваться к изменениям и выбирать наилучший путь.
    *   **Принцип работы:** Чтобы отправить пакет получателю в другой сети, узел передает его по цепочке маршрутизаторов. На каждом шаге происходит спуск на канальный уровень для физической доставки следующему маршрутизатору, а затем подъем обратно на сетевой для принятия решения о следующем шаге. Этот процесс повторяется, пока пакет не достигнет целевой сети.
4.  **Агрегация адресов:** Для решения проблемы масштабируемости маршрутизаторы оперируют не отдельными адресами устройств, а целыми **блоками адресов (подсетями)**. IP-адрес логически делится на две части: **номер подсети (Network ID)**, общий для всех устройств в сети, и **номер хоста (Host ID)**, уникальный внутри этой сети. Таблица маршрутизации содержит маршруты к подсетям, а не к каждому хосту, что кардинально уменьшает ее размер.
5.  **Фрагментация:** Если пакет данных слишком велик для передачи через сеть с меньшим MTU (Maximum Transmission Unit), он разбивается на **фрагменты**. Фрагменты собираются воедино на конечном узле.
6.  **Отбрасывание пакетов:** Пакеты, для которых путь доставки неизвестен, не рассылаются всем подряд (как на L2), а просто **отбрасываются**. Это защищает сеть от циркуляции "мусорных" пакетов.
7.  **Ограничение времени жизни пакетов (TTL):** Каждый пакет имеет поле **Time To Live (TTL)** — счётчик, который уменьшается на единицу при прохождении каждого маршрутизатора. Если TTL достигает нуля, пакет уничтожается. Это предотвращает бесконечное "блуждание" пакетов по сети в случае петель маршрутизации.

## Практические сценарии

### Логика маршрутизации хоста

Ключевая задача сетевого уровня на хосте — определить, как доставить пакет: напрямую получателю в локальной сети или на шлюз по умолчанию для отправки во внешнюю сеть.

#### Сценарий 1: Обмен трафиком в одной подсети

Когда хост **А** (`192.168.1.10`) отправляет пакет хосту **Б** (`192.168.1.20`) с маской подсети `255.255.255.0`:

1.  **Определение местоположения:** Хост **А** применяет маску подсети к своему IP и к IP-адресу назначения. В обоих случаях получается один и тот же адрес сети: `192.168.1.0`. **Вывод: адресат находится в той же локальной сети.**
2.  **Поиск MAC-адреса ([ARP](../Protocols/arp.md)):** Для отправки кадра на канальном уровне (L2) требуется MAC-адрес. Хост **А** отправляет **ARP-запрос**: "Кто имеет IP `192.168.1.20`?". Хост **Б** отвечает, сообщая свой MAC-адрес.
3.  **Прямая отправка:** Хост **А** отправляет IP-пакет, инкапсулированный в Ethernet-кадр, напрямую на MAC-адрес хоста **Б**.

В этом процессе **шлюз по умолчанию не участвует**.

#### Сценарий 2: Отправка трафика во внешнюю сеть

Если хост **А** (`192.168.1.10`) отправляет пакет на сервер в интернете (например, `8.8.8.8`):

1.  **Определение местоположения:** Хост **А** применяет маску подсети к IP-адресу назначения (`8.8.8.8`) и видит, что результат не совпадает с его собственной сетью (`192.168.1.0`). **Вывод: адресат находится во внешней сети.**
2.  **Отправка на шлюз:** Весь трафик для внешних сетей направляется на **шлюз по умолчанию** (роутер с IP `192.168.1.1`).
    *   IP-пакет инкапсулируется в Ethernet-кадр.
    *   В качестве MAC-адреса назначения указывается **MAC-адрес шлюза** (полученный через ARP), а не конечного сервера.
3.  **Дальнейшая маршрутизация:** Шлюз, получив кадр, "распаковывает" его, анализирует IP-адрес назначения (`8.8.8.8`) и, на основе своей таблицы маршрутизации, пересылает пакет дальше в сторону цели.

**Вывод:** Шлюз абсолютно необходим для связи с любыми устройствами за пределами локальной подсети.

## Дополнительная информация

### Протоколы и оборудование

#### Ключевые протоколы (в стеке TCP/IP)

*   **[IP (Internet Protocol)](../Protocols/ip.md):** Основной протокол для передачи данных и глобальной адресации.
*   **[ICMP (Internet Control Message Protocol)](../Protocols/icmp.md):** Используется для обмена служебными и диагностическими сообщениями.
*   **[ARP (Address Resolution Protocol)](../Protocols/arp.md):** Используется для сопоставления IP-адресов (L3) и MAC-адресов (L2) в пределах одной локальной сети.
*   **[DHCP (Dynamic Host Configuration Protocol)](../Protocols/dhcp.md):** Используется для автоматического назначения IP-адресов хостам.
*   **Маршрутизация**: Процесс определения оптимального пути для передачи данных между сетями. Существует два основных типа:
    *   **Статическая маршрутизация**: Маршруты конфигурируются администратором вручную и остаются неизменными до ручного изменения.
    *   **Динамическая маршрутизация**: Механизм автоматического выбора маршрута на основе изменяющихся сетевых условий. Маршрутизаторы используют **протоколы маршрутизации** для обмена информацией о доступных сетях и автоматически адаптируются к изменениям в топологии сети.
*   **Протоколы маршрутизации (например, OSPF, RIP, [[BGP (Border Gateway Protocol): Обзор|../Protocols/BGP_overview.md]]):** Используются маршрутизаторами для обмена информацией о доступных сетях и построения таблиц маршрутизации.

#### Оборудование

*   **Маршрутизатор (Роутер):**
    *   **Назначение**: Ключевое устройство сетевого уровня, предназначенное для **объединения нескольких сетей** в единую составную сеть (internetwork). В отличие от коммутатора, который соединяет узлы *внутри* одной сети, маршрутизатор связывает *разные* сети.
    *   **Принцип работы**: Оперирует **IP-адресами**. Получив пакет, анализирует IP-адрес назначения и, на основе своей **таблицы маршрутизации**, принимает решение, на какой из своих интерфейсов (и, соответственно, в какую следующую сеть) нужно отправить пакет.
*   **L3-коммутатор:** Гибридное устройство, сочетающее функции коммутатора (быстрая коммутация на L2 в пределах VLAN) и маршрутизатора (маршрутизация между разными VLAN'ами или подсетями на L3).
