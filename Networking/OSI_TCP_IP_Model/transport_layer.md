# Транспортный уровень (L4)

## Определения

**Транспортный уровень (Transport Layer, L4)** — первый сквозной (end-to-end) уровень модели **OSI (Open Systems Interconnection)**, обеспечивающий передачу данных непосредственно между **процессами** на конечных хостах. Он абстрагирует прикладной уровень от сложностей сетевой инфраструктуры, гарантируя нужные параметры доставки.

- **PDU (Protocol Data Unit):** Единица данных. **Сегмент** (в TCP) или **дейтаграмма** (в UDP).
- **Адресация:** [Сетевые порты](../Concepts/network_ports.md) (16-битное число, 0–65535).
- **Сокет (Socket):** Комбинация `[IP-адрес]:Порт`, однозначно идентифицирующая конечную точку соединения. Подробнее: **[Socket API](../Concepts/socket_api.md)**.

## Базовые концепции

### Ключевые функции и механизмы

| Функция | Описание |
| :--- | :--- |
| **Мультиплексирование** | Объединение данных от разных приложений (разных портов) в один поток пакетов L3. |
| **Демультиплексирование** | Распределение входящих пакетов по процессам на основе порта назначения. |
| **Управление потоком (Flow Control)** | Регулирование скорости передачи во избежание переполнения буфера получателя (механизм Window в TCP). |
| **Управление перегрузкой (Congestion Control)** | Снижение темпа отправки при обнаружении потерь или задержек в сети (алгоритмы CUBIC, BBR). |
| **Сегментация** | Разбиение больших блоков данных прикладного уровня на части, соответствующие размеру **MSS**. |

### Связь L3 и L4: MTU и MSS

- **MTU (Maximum Transmission Unit):** Максимальный размер IP-пакета (L3). По умолчанию для Ethernet — 1500 байт.
- **MSS (Maximum Segment Size):** Максимальный размер полезной нагрузки TCP-сегмента (L4).
- **Формула:** `MSS = MTU - (IP Header) - (TCP Header)`. Обычно 1460 байт (1500 - 20 - 20).
- Несоответствие MSS/MTU на пути следования приводит к фрагментации или потере пакетов (при установленном флаге DF). Подробнее: **[MTU и PMTUD](./Network_layer/mtu_and_vpn.md)**.

## Ключевые протоколы

| Протокол | Тип | Характеристики | Сфера применения |
| :--- | :--- | :--- | :--- |
| **[TCP](../Protocols/TCP/overview.md)** | Потоковый | Надежный, с установкой соединения (Handshake), гарантирует порядок. | HTTP/1.1-2, SSH, БД, FTP. |
| **[UDP](../Protocols/udp.md)** | Дейтаграммный | Быстрый, без гарантий доставки и порядка, низкий оверхед. | DNS, VoIP, видео, игры, QUIC. |
| **QUIC** | Гибридный | Работает поверх UDP, объединяет надежность TCP и безопасность TLS 1.3. | HTTP/3, gRPC. |
| **SCTP** | Потоковый | Поддержка многопоточности и многоадресности (Multi-homing). | Сигнальные сети телефонии. |
| **MPTCP** | Расширение | Multi-Path TCP: агрегация каналов (Wi-Fi + 4G) в одну сессию. | Мобильные ОС, балансировщики. |

### Современное управление перегрузкой

Современные сетевые стеки (Linux Kernel 5.x+) отходят от классических алгоритмов, основанных на потерях (CUBIC, Reno), к алгоритмам, основанным на задержке:
- **BBR (Bottleneck Bandwidth and RTT):** Разработан Google. Оценивает реальную пропускную способность канала и RTT. Позволяет достигать максимальной скорости на каналах с высоким уровнем случайных потерь (Wi-Fi, LTE).

## Высокопроизводительная сетевая обработка

В высоконагруженных системах (2026+) стандартный стек ядра может стать узким местом:
1.  **Zero-copy (Нулевое копирование):** Системные вызовы `sendfile` или `splice` позволяют передавать данные напрямую из файлового кэша в сетевой буфер, минуя копирование в пространство пользователя.
2.  **eBPF Socket Redirection:** Позволяет перенаправлять пакеты между сокетами внутри одного хоста (например, от прокси к приложению) напрямую, полностью пропуская сетевой стек TCP/IP.
3.  **Kernel TLS (kTLS):** Перенос шифрования на уровень ядра для повышения производительности (совместимо с Zero-copy).

## Практические сценарии

### Оборудование и инструменты диагностики

- **L4 Балансировщики:** Работают с сессиями (Connection-based). Инструменты: **IPVS (LVS)**, **HAProxy (mode tcp)**, **Nginx (stream)**.
- **Диагностика:**
  - `ss -ntlp` — просмотр активных TCP-сокетов.
  - `netstat -s` — статистика по ошибкам и переповторам (Retransmits).
  - `iperf3` / `xfr` — тестирование пропускной способности.
  - `nc -zv <host> <port>` — проверка доступности порта. Подробнее: **[Инструменты диагностики](../../Linux/Networking/network_diagnostics_tools.md)** и **[Альтернативы ping](../Troubleshooting/ping_alternatives.md)**.

### Выбор между TCP и UDP

| Требование | Рекомендация | Обоснование |
| :--- | :--- | :--- |
| Важна целостность | **TCP** | Если потерян 1 байт, данные станут невалидными (JSON, код). |
| Важен минимальный пинг | **UDP** | Ожидание подтверждения ACK в TCP создает неприемлемые задержки для RT-данных. |
| Смена IP (Roaming) | **QUIC** | Механизм Connection ID позволяет не разрывать соединение при смене сети. |
