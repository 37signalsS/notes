# Транспортный уровень (L4)

## Определения

* **Транспортный уровень (L4)** — первый сквозной (end-to-end) и сете-независимый уровень [модели OSI](./osi_model.md). Обеспечивает логическое соединение между **процессами** на конечных хостах, а не между самими хостами.
* **PDU (Protocol Data Unit):** Сегмент (TCP), Дейтаграмма (UDP)
* **Адресация:** [Порты](../Concepts/network_ports.md) (16-бит, 0–65535). Пара `[IP-адрес]:Порт` = сокет.

## Базовые концепции

### Назначение уровня

Транспортный уровень обеспечивает доставку данных от приложения к приложению. На отправителе данные упаковываются в сегменты/дейтаграммы с указанием портов, на получателе — извлекаются и направляются нужному процессу.

**Пример:** При одновременной работе мессенджера и браузера L4 определяет, какому приложению передать данные, используя номера портов.

**Ключевые механизмы:** управление потоком (flow control), управление перегрузкой (congestion control), гарантированная доставка (TCP).

### Ключевые функции

1. **Адресация процессов (мультиплексирование/демультиплексирование):**
   * Направление входящих данных конкретному приложению через **[порты](../Concepts/network_ports.md)**
   * Поддержка множественных одновременных соединений

2. **Надёжная доставка (TCP):**
   * **Установка соединения:** Знаменитое «трехстороннее рукопожатие» (3-way handshake).
     1. **SYN:** Клиент просит установить соединение.
     2. **SYN-ACK:** Сервер подтверждает готовность.
     3. **ACK:** Клиент финализирует установку канала. Только после этого начинается передача данных.
   * **Подтверждения (ACK):** На каждый кусок данных получатель присылает подтверждение. Если оно не пришло — данные шлются повторно.
   * **Гарантии:** TCP гарантирует доставку в правильном порядке и без дубликатов, сам режет файлы на сегменты и собирает их.
   * **Минус:** Накладные расходы на рукопожатия и подтверждения требуют времени и трафика.

3. **Ненадёжная доставка (UDP):**
   * **Дейтаграммная передача:** Нет рукопожатия, нет подтверждений, нет повторных отправок. Данные просто «кидаются» в сторону получателя.
   * **Плюс:** Максимальная скорость. Нет задержек на установку и ожидание подтверждений.
   * **Когда использовать:** В стриминге (аудио, видео, игры), где актуальность данных важнее их полноты (старый кадр видео уже не нужен, лучше показать следующий).

**Логика выбора:** TCP — про надёжность (HTTP, SSH, базы данных), UDP — про скорость (звонки, стриминг, DNS).

4. **Управление потоком (Flow Control):**
   * Предотвращение переполнения буфера получателя
   * Механизм скользящего окна (TCP)

5. **Управление перегрузкой (Congestion Control):**
   * Предотвращение коллапса сети при чрезмерном трафике
   * Алгоритмы: Slow Start, Congestion Avoidance, Fast Retransmit (TCP)

### Основные протоколы

| Протокол | Тип | Надёжность | Установка соединения | Примеры использования |
| :--- | :--- | :--- | :--- | :--- |
| **[TCP](../Protocols/TCP/overview.md)** | Потоковый | Да | Да (handshake) | HTTP, FTP, SMTP, SSH |
| **[UDP](../Protocols/udp.md)** | Дейтаграммный | Нет | Нет | DNS, VoIP, DHCP, онлайн-игры |
| **SCTP** | Потоковый/сообщений | Да | Да | Телефония (SIGTRAN), WebRTC |

### Интерфейс: Сокеты

Приложения взаимодействуют с транспортным уровнем через **[Socket API](../Concepts/socket_api.md)**:

* `socket()`, `bind()`, `listen()`, `accept()`, `connect()`
* Абстрагирует детали TCP/UDP

## Практические сценарии

### Оборудование и ПО

Функции L4 реализуются программно на **конечных хостах** (в ОС), а также на специализированном оборудовании:

| Устройство | Функция | Примеры |
| :--- | :--- | :--- |
| **L4-балансировщики** | Распределение трафика по IP:порт | HAProxy, NGINX, F5 BIG-IP |
| **L4-брандмауэры** | Фильтрация по портам/протоколам | iptables, Cisco ASA |
| **Хосты (ОС)** | Реализация стека TCP/UDP | Linux, Windows, BSD |

### Сценарии выбора протокола

| Сценарий | Протокол | Обоснование |
| :--- | :--- | :--- |
| Веб-сервер (HTTP/HTTPS) | TCP | Требуется надёжная доставка |
| DNS-запросы | UDP | Короткие запросы, скорость важнее |
| VoIP/видеоконференции | UDP | Допустимы потери, важна задержка |
| Файлообмен (FTP, SFTP) | TCP | Гарантия целостности файлов |
| Онлайн-игры | UDP | Критична минимальная задержка |
