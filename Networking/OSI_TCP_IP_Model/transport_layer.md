# Транспортный уровень (L4)

## Определения

*   **Транспортный уровень (L4)** — это четвертый уровень [модели OSI](./osi_model.md), который является первым сквозным (end-to-end) и сете-независимым уровнем. Он обеспечивает логическое соединение не между хостами, а напрямую между **процессами**, запущенными на этих хостах.
*   **PDU (Protocol Data Unit):** Сегмент (для TCP), Дейтаграмма (для UDP).

## Основные концепции

В отличие от нижних уровней, работающих на каждом промежуточном узле (коммутаторах, маршрутизаторах), транспортный уровень функционирует исключительно на конечных хостах. Его главная задача — обеспечить прозрачную передачу данных между процессами, скрывая сложности сетевой инфраструктуры.

### Ключевые функции

1.  **Адресация процессов (мультиплексирование):** Направляет входящие данные конкретному приложению на хосте с помощью **[портов](../Concepts/network_ports.md)**. Пара `[IP-адрес](../Concepts/ip.md):Порт` однозначно идентифицирует сетевой процесс в интернете.
2.  *   **Надежная доставка:** Гарантирует, что все данные будут доставлены в правильном порядке и без потерь. Это достигается за счет:
    *   **Подтверждений (Acknowledgements):** Получатель подтверждает получение данных.
    *   **Повторной передачи (Retransmission):** Если подтверждение не приходит за определенное время, отправитель отправляет данные заново.
    *   **Нумерации последовательности (Sequence Numbers):** Позволяет восстановить правильный порядок сообщений, если они пришли вразнобой.
*   **Ненадежная доставка:** Данные отправляются без каких-либо гарантий. Это быстрее, но часть данных может потеряться или прийти не по порядку.
3.  **Управление потоком (Flow Control):** Механизм, предотвращающий переполнение буфера получателя. Получатель сообщает, какой объем данных он готов принять.
4.  **Управление перегрузкой (Congestion Control):** Алгоритмы (например, в TCP) для предотвращения коллапса сети из-за чрезмерного трафика. Отправитель снижает скорость при обнаружении перегрузки.

### Основные протоколы

*   **[TCP (Transmission Control Protocol)](../Protocols/TCP/overview.md):** Надежный, с установлением соединения, ориентированный на поток байт. Используется для HTTP, FTP, SMTP, где важна целостность данных.
*   **[UDP (User Datagram Protocol)](../Protocols/udp.md):** Ненадежный, без установления соединения, работает с сообщениями (дейтаграммами). Применяется в DNS, VoIP, онлайн-играх, где скорость важнее надежности.
*   **SCTP (Stream Control Transmission Protocol):** Комбинирует черты TCP и UDP, обеспечивает надежную доставку сообщений и поддерживает несколько потоков в рамках одного соединения.

### Интерфейс: Сокеты

Приложения взаимодействуют с транспортным уровнем через программный интерфейс — **[сокеты (Socket API)](../Concepts/socket_api.md)**. Он абстрагирует детали реализации TCP/UDP, предоставляя удобные функции для отправки и получения данных.

## Практические сценарии

### Оборудование и ПО

Функции L4 реализуются программно на **конечных хостах** (в операционной системе), а также на специализированном сетевом оборудовании:

*   **L4-балансировщики нагрузки:** Распределяют трафик между серверами на основе IP-адресов и портов (TCP/UDP), анализируя заголовки транспортного уровня.
*   **L4-брандмауэры (Firewalls):** Фильтруют трафик по тем же параметрам, разрешая или блокируя соединения для определенных портов и приложений.
