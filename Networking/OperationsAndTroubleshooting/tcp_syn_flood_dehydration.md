# Диагностика переполнения очереди TCP SYN (TCP Dehydration)

«TCP-обезвоживание» — это разговорный термин для ситуации, когда у сервера переполняется очередь для полуоткрытых (half-open) TCP-соединений. Это соединения, которые получили `SYN` от клиента, отправили в ответ `SYN/ACK`, но так и не дождались финального `ACK` от клиента.

При большом количестве таких «зависших» соединений, очередь (`backlog`) переполняется, и сервер перестаёт принимать новые легитимные подключения. Чаще всего это является симптомом **SYN-флуд атаки**.

## 1. Быстрая проверка состояния

Чтобы получить быстрый снимок состояния TCP-соединений, используйте `ss`.

```bash
ss -s
```

Обратите внимание на строки `SYN-SENT` и `SYN-RECV`:

```
TCP: ...
    ...
    1323 SYN-SENT
    987 SYN-RECV
```

Резкий и постоянный рост значения **`SYN-RECV`** до сотен или тысяч является явным признаком того, что сервер близок к исчерпанию лимита очереди.

## 2. Проверка лимитов

Чтобы узнать максимальный размер очереди для SYN-запросов (backlog), проверьте следующий параметр ядра:

```bash
cat /proc/sys/net/ipv4/tcp_max_syn_backlog
```

Стандартные значения — от 128 до 1024 и выше. Если количество соединений в состоянии `SYN-RECV` приближается к этому лимиту, начинается «обезвоживание».

## 3. Дополнительная диагностика

### Просмотр реального Backlog сокета

Команда `ss` позволяет увидеть текущие размеры очередей на прослушиваемых (`LISTEN`) сокетах.

```bash
ss -lnt
```

Смотрите на столбцы `Recv-Q` и `Send-Q`. Если `Recv-Q` для нужного порта забит и равен значению из `Send-Q` (которое является максимальным размером очереди для этого сокета), это означает, что приложение физически не успевает вызывать `accept()` для завершения установки соединения.

### Поиск источника атаки

Для выявления DoS-подобной активности можно отслеживать IP-адреса, с которых приходит аномально много SYN-запросов.

**Наблюдение в реальном времени:**
```bash
watch -n1 "netstat -ant | grep SYN_RECV"
```

**Агрегация и сортировка IP-адресов:**

Эта команда покажет топ IP-адресов, находящихся в состоянии `SYN_RECV`:

```bash
netstat -ant | awk '/SYN_RECV/ {print $5}' | cut -d: -f1 | sort | uniq -c | sort -nr | head
```

Если десятки или сотни запросов идут с одного IP-адреса или подсети, это с высокой вероятностью является SYN-флуд атакой.
