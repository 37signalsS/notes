# Диагностика: проблема с DNS или с сетью?

Иногда сервер может выглядеть «мертвым»: SSH-сессии и `curl`-запросы зависают, а сервисы стартуют с большими задержками. При этом, `ping` по IP-адресам проходит без проблем. Это классический симптом того, что проблема не в сетевой связности как таковой, а в разрешении имен (DNS).

Когда DNS lookup (поиск) занимает слишком много времени, TCP-соединения, ожидающие разрешения имени хоста, кажутся зависшими.

## Простая диагностика

### 1. Проверка полного пути разрешения

Используйте `dig +trace`, чтобы увидеть, на каком этапе "тормозит" DNS-запрос.

```bash
dig +trace example.com
```

Если запрос зависает уже на этапе обращения к корневым (`.`) или TLD-серверам (`.com`), проблема, скорее всего, связана с внешним DNS-провайдером или сетевой связностью до него.

### 2. Тест через конкретный внешний резолвер

Чтобы исключить локальные проблемы, выполните запрос напрямую через известный быстрый DNS-сервер, например, Cloudflare (`1.1.1.1`) или Google (`8.8.8.8`).

```bash
dig @1.1.1.1 example.com
```

Если здесь ответ приходит мгновенно, а без указания резолвера — медленно, значит, проблема локальная. Чаще всего виновником является локальный кеширующий DNS-сервис, такой как `systemd-resolved`.

### 3. Диагностика `systemd-resolved`

Если вы используете систему с `systemd`, проверьте состояние локального резолвера.

- **Выполнить запрос через `resolvectl`:**
  ```bash
  resolvectl query example.com
  ```
- **Проверить статус сервиса:**
  ```bash
  resolvectl status
  ```
- **Посмотреть статистику:**
  ```bash
  systemd-resolve --statistics
  ```
  Обратите внимание на счетчик `Transactions in progress`. Если это число постоянно растет, а ответы не приходят, значит локальный DNS-сервис не справляется с нагрузкой или завис. Также стоит проверить размер кеша (`Current Cache Size`).

## Временное решение для проверки

Чтобы окончательно убедиться, что проблема в `systemd-resolved`, можно временно его отключить и напрямую прописать внешний DNS-сервер в `/etc/resolv.conf`.

1.  **Останавливаем `systemd-resolved`:**
    > **Внимание:** Это действие изменит конфигурацию DNS на сервере. Не забудьте вернуть все обратно после теста.
    ```bash
    sudo systemctl stop systemd-resolved
    ```

2.  **Прописываем новый `nameserver`:**
    ```bash
    echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf
    ```

3.  **Проверяем скорость разрешения:**
    ```bash
    dig example.com
    ```

Если после этих действий DNS-запросы стали выполняться мгновенно, виноват локальный кеширующий резолвер. В этом случае следует изучать его конфигурацию, логи или просто перезапустить его (`sudo systemctl restart systemd-resolved`).
