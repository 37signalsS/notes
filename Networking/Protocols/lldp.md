# LLDP — протокол обнаружения канального уровня

> **Reliability Score: 10** (SSoT + IEEE 802.1AB + Linux Networking Stack)

## Определения

**LLDP (Link Layer Discovery Protocol)** — открытый стандарт протокола канального уровня (L2), позволяющий сетевым устройствам анонсировать информацию о себе (имя, модель, возможности, порт подключения) своим соседям в локальном сегменте сети. Описан в стандарте **IEEE 802.1AB**.

**LLDP-ADU (LLDP Agent Data Unit)** — единица данных LLDP, состоящая из набора TLV-структур.

**TLV (Type-Length-Value)** — формат кодирования данных, где указывается тип параметра, его длина и значение.

> **Важно:** LLDP работает только между непосредственно подключенными устройствами (Point-to-Point) и не маршрутизируется. Он является вендоронезависимой альтернативой проприетарному протоколу **CDP (Cisco Discovery Protocol)**.

> **См. также:** [Модель OSI](../OSI_TCP_IP_Model/osi_model.md), [Ethernet](./ethernet.md), [VLAN](./vlan.md)

## Основные концепции

### Назначение LLDP

LLDP используется для автоматического построения топологии сети, инвентаризации и диагностики физических подключений. С его помощью администратор может узнать, к какому порту коммутатора подключен сервер, не заходя в серверную.

### Механизм работы

1. **Анонсирование:** устройство периодически (по умолчанию каждые 30 секунд) рассылает LLDP-кадры на мультикаст-адрес `01:80:c2:00:00:0e`.
2. **Сбор данных:** соседи принимают эти кадры и сохраняют информацию в свою MIB (Management Information Base).
3. **Хранение:** данные хранятся в течение времени **TTL (Time To Live)**, указанного в пакете (обычно 120 секунд). Если новые данные не приходят, запись удаляется.

### Структура TLV (Type-Length-Value)

LLDP-пакет (LLDPDU) представляет собой последовательность TLV-блоков. Формат заголовка TLV:
- **Type (7 бит):** определяет тип информации.
- **Length (9 бит):** длина поля Value в байтах.
- **Value (0–511 байт):** полезная нагрузка.

**Обязательные TLV (Mandatory):**
1. **Chassis ID (Type 1):** Уникальный ID отправителя (обычно MAC-адрес).
2. **Port ID (Type 2):** Идентификатор порта отправителя.
3. **Time To Live (Type 3):** Время актуальности информации у соседа.
4. **End of LLDPDU (Type 0):** Маркер конца пакета.

**Важные опциональные TLV:**
- **System Capabilities (Type 7):** Битовая маска функций (Bridge, Router, Station и т.д.).
- **Management Address (Type 8):** IP-адрес для удаленного управления.
- **Organizationally Specific TLVs (Type 127):** Позволяют вендорам добавлять свои данные (например, VLAN ID через IEEE 802.1 или настройки PoE через IEEE 802.3).

### Безопасность и риски

LLDP — это протокол, основанный на полном доверии.
1. **Сбор информации (Reconnaissance):** Злоумышленник, подключившись к порту, может мгновенно узнать имя коммутатора, модель ОС и структуру управления сетью.
2. **LLDP Poisoning:** Подделка LLDP-пакетов может привести к ошибкам в системах мониторинга топологии.
3. **Рекомендация:** Отключайте LLDP на портах, смотрящих в сторону публичных зон или небезопасных клиентов.

## Практические сценарии (Linux)

В Linux наиболее распространенной реализацией является демон **lldpd**.

### 1. Установка и запуск

По умолчанию `lldpd` не установлен в большинстве дистрибутивов.

```bash
# Установка (Debian/Ubuntu)
sudo apt update && sudo apt install lldpd -y

# Запуск и добавление в автозагрузку
sudo systemctl enable --now lldpd
```

### 2. Настройка через systemd-networkd

Современный способ включения LLDP на серверах без установки дополнительных демонов.

```ini
# /etc/systemd/network/20-eth0.network
[Match]
Name=eth0

[Network]
# Принимать LLDP от соседей
LLDP=yes
# Рассылать информацию о себе
EmitLLDP=yes
```

### 3. Работа с виртуальными интерфейсами (Bonding/Bridging)

- **Bonding:** LLDP обычно должен быть включен на **физических** интерфейсах (slave), а не на интерфейсе `bond0`. Это позволяет видеть, к каким портам коммутатора подключен каждый линк агрегации.
- **Bridging:** Если физический интерфейс является частью моста (`br0`), демон `lldpd` автоматически "слушает" на нем трафик. Однако, если на коммутаторе включен STP, мультикаст LLDP может блокироваться или обрабатываться нестандартно.

### 4. Просмотр соседей (lldpcli)

Для взаимодействия с демоном `lldpd` используется утилита `lldpcli`.

```bash
# Краткий список соседей
lldpcli show neighbors

# Подробная информация (включая возможности и порты)
lldpcli show neighbors details

# Мониторинг появления/исчезновения соседей в реальном времени
lldpcli watch
```

**Пример вывода:**
```text
Interface:    eth0, via: LLDP, RID: 1, Time: 0 day, 00:01:23
  Chassis:     
    ChassisID: mac 00:11:22:33:44:55
    SysName:   sw-core-01
    SysDescr:  Cisco IOS Software, C2960 Software, Version 15.0(2)SE7
    MgmtIP:    192.168.1.254
    Capability: Bridge, enabled
  Port:        
    PortID:    ifname GigabitEthernet0/1
    PortDescr: Uplink to Server-Rack-1
```

### 5. Диагностика без демона (tcpdump)

Если демон не установлен, можно перехватить LLDP-кадры напрямую (EtherType `0x88cc`).

```bash
# Захват LLDP-фреймов на интерфейсе eth0
sudo tcpdump -i eth0 -nn -v ether proto 0x88cc
```

### 6. Отладка проблем LLDP

Если соседи не видны:
1. **Проверьте состояние линка:** LLDP требует `UP` на интерфейсе.
2. **Native VLAN:** LLDP-кадры обычно не тегируются. Если на порту коммутатора Native VLAN настроен неверно, пакеты могут не доходить.
3. **Фильтрация L2 Multicast:** Некоторые фаерволы (например, `ebtables`) или настройки `bridge-nf-call-iptables` могут блокировать мультикаст.
4. **Настройка на коммутаторе:** Убедитесь, что LLDP включен глобально и на конкретном порту (`lldp run` / `lldp transmit` / `lldp receive`).

## Дополнительная информация

### Сравнение протоколов

| Характеристика | LLDP (802.1AB) | CDP (Cisco) |
| :--- | :--- | :--- |
| **Стандарт** | Открытый (IEEE) | Проприетарный (Cisco) |
| **Поддержка** | Все современные вендоры | Преимущественно Cisco |
| **Мультикаст MAC** | `01:80:c2:00:00:0e` | `01:00:0c:cc:cc:cc` |
| **Расширяемость** | Очень высокая (TLV 127) | Ограничена вендором |

### LLDP-MED (Media Endpoint Discovery)

**LLDP-MED (ANSI/TIA-1057)** — расширение для оконечных устройств (VoIP, камеры).
- **Network Policy:** Автоматическая передача номера Voice VLAN и приоритетов QoS (CoS/DSCP).
- **PoE Management:** Согласование потребляемой мощности.
- **Inventory:** Передача серийных номеров и версий прошивок телефонов в систему управления коммутаторами.
