# LLDP — протокол обнаружения канального уровня

> **Reliability Score: 10** (SSoT + IEEE 802.1AB + Linux Networking Stack)

## Определения

**LLDP (Link Layer Discovery Protocol)** — открытый стандарт протокола канального уровня (L2), позволяющий сетевым устройствам анонсировать информацию о себе (имя, модель, возможности, порт подключения) своим соседям в локальном сегменте сети. Описан в стандарте **IEEE 802.1AB**.

**LLDP-ADU (LLDP Agent Data Unit)** — единица данных LLDP, состоящая из набора TLV-структур.

**TLV (Type-Length-Value)** — формат кодирования данных, где указывается тип параметра, его длина и значение.

> **Важно:** LLDP работает только между непосредственно подключенными устройствами (Point-to-Point) и не маршрутизируется. Он является вендоронезависимой альтернативой проприетарному протоколу **CDP (Cisco Discovery Protocol)**.

> **См. также:** [Модель OSI](../OSI_TCP_IP_Model/osi_model.md), [Ethernet](./ethernet.md), [VLAN](./vlan.md)

## Основные концепции

### Назначение LLDP

LLDP используется для автоматического построения топологии сети, инвентаризации и диагностики физических подключений. С его помощью администратор может узнать, к какому порту коммутатора подключен сервер, не заходя в серверную.

### Механизм работы

1. **Анонсирование:** устройство периодически (по умолчанию каждые 30 секунд) рассылает LLDP-кадры на мультикаст-адрес `01:80:c2:00:00:0e`.
2. **Сбор данных:** соседи принимают эти кадры и сохраняют информацию в свою MIB (Management Information Base).
3. **Хранение:** данные хранятся в течение времени **TTL (Time To Live)**, указанного в пакете (обычно 120 секунд). Если новые данные не приходят, запись удаляется.

### Ключевые TLV (Type-Length-Value)

Каждый LLDP-пакет обязан содержать четыре обязательных TLV:

1. **Chassis ID:** уникальный идентификатор устройства (обычно MAC-адрес управления).
2. **Port ID:** идентификатор порта, с которого отправлен пакет (имя интерфейса или его MAC).
3. **Time To Live (TTL):** время актуальности данных.
4. **End of LLDPDU:** маркер завершения пакета.

**Дополнительные TLV (Optional):**
- **System Name:** имя хоста.
- **System Description:** версия ОС, модель оборудования.
- **System Capabilities:** функции устройства (Bridge, Router, WLAN AP и др.).
- **Management Address:** IP-адрес для управления.
- **Port Description:** описание порта (alias).

## Практические сценарии (Linux)

В Linux наиболее распространенной реализацией является демон **lldpd**.

### 1. Установка и запуск

По умолчанию `lldpd` не установлен в большинстве дистрибутивов.

```bash
# Установка (Debian/Ubuntu)
sudo apt update && sudo apt install lldpd -y

# Запуск и добавление в автозагрузку
sudo systemctl enable --now lldpd
```

### 2. Просмотр соседей (lldpcli)

Для взаимодействия с демоном используется утилита `lldpcli`.

```bash
# Краткий список соседей
lldpcli show neighbors

# Подробная информация (включая порты коммутатора и возможности)
lldpcli show neighbors details

# Вывод в формате JSON (удобно для скриптов)
lldpcli -f json show neighbors
```

**Пример вывода:**
```text
Interface:    eth0, via: LLDP, RID: 1, Time: 0 day, 00:01:23
  Chassis:     
    ChassisID: mac 00:11:22:33:44:55
    SysName:   sw-core-01
    SysDescr:  Cisco IOS Software, C2960 Software (C2960-LANBASEK9-M), Version 15.0(2)SE7
    MgmtIP:    192.168.1.254
    Capability: Bridge, enabled
  Port:        
    PortID:    ifname GigabitEthernet0/1
    PortDescr: Uplink to Server-Rack-1
```

### 3. Диагностика без демона (tcpdump)

Если вы не можете или не хотите устанавливать `lldpd`, вы можете перехватить LLDP-кадры напрямую. LLDP использует EtherType `0x88cc`.

```bash
# Захват LLDP-фреймов на интерфейсе eth0
sudo tcpdump -i eth0 -nn -v ether proto 0x88cc
```

**Что искать в дампе:**
- `Chassis ID` — поможет идентифицировать коммутатор.
- `Port ID` — покажет, в какой физический разъем вы воткнуты.
- `System Name` — имя устройства.

### 4. Отладка проблем LLDP

Если соседи не видны:
1. **Проверьте Link:** LLDP не работает, если интерфейс в состоянии `DOWN`.
2. **VLAN Native:** LLDP-кадры обычно ходят без тегов. Убедитесь, что Native VLAN на коммутаторе совпадает с настройками порта.
3. **Фильтрация:** некоторые фаерволы или промежуточные устройства (непрозрачные мосты) могут отбрасывать мультикаст L2.
4. **Настройка коммутатора:** убедитесь, что LLDP включен на порту коммутатора (`lldp run` на Cisco).

## Дополнительная информация

### Сравнение протоколов

| Характеристика | LLDP (802.1AB) | CDP (Cisco) |
| :--- | :--- | :--- |
| **Стандарт** | Открытый (IEEE) | Проприетарный (Cisco) |
| **Поддержка** | Почти все вендоры | Преимущественно Cisco |
| **Мультикаст MAC** | `01:80:c2:00:00:0e` | `01:00:0c:cc:cc:cc` |
| **Расширяемость** | Высокая (кастомные TLV) | Ограничена вендором |

### LLDP-MED

**LLDP-MED (Media Endpoint Discovery)** — расширение протокола для оконечных устройств (IP-телефоны, видеокамеры). Позволяет автоматически передавать настройки голосового VLAN (Voice VLAN), параметры PoE и политики QoS.
