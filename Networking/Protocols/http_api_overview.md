# Обзор HTTP API

## Что такое HTTP API?

Протокол [HTTP](./application_layer.md#http-hypertext-transfer-protocol) был первоначально создан для передачи веб-страниц в формате HTML. Однако его применение гораздо шире. Сегодня с помощью HTTP передаются изображения, видео, файлы стилей (CSS), скрипты (JavaScript) и многое другое.

Кроме того, HTTP часто применяется для реализации **API (Application Programming Interface)**. HTTP API позволяет программам взаимодействовать друг с другом, вызывая функции на удалённом сервере. Программа-клиент отправляет HTTP-запрос, сервер выполняет соответствующую логику и возвращает HTTP-ответ, чаще всего в формате **JSON**.

## Структура запроса к API

В отличие от URL для веб-страниц, URL в API имеет свою специфику. Он указывает, к какой программе (или ресурсу) мы обращаемся и какие параметры ей передаём.

### Пример: Geolocation API

Рассмотрим API, которое по IP-адресу или доменному имени определяет его географическое положение.

**URL запроса:**
```
http://ip-api.com/json/sazankin.ru?lang=ru&fields=status,country,regionName,city,org,query
```

Разберём его структуру:

1.  **Базовый путь (Endpoint):** `http://ip-api.com/json/`
    *   `http://`: Протокол.
    *   `ip-api.com`: Адрес сервера.
    *   `/json/`: Путь, указывающий, что мы хотим получить ответ в формате JSON.
    *   `sazankin.ru`: Параметр, переданный как часть пути. В данном случае — доменное имя, для которого нужно определить геолокацию.

2.  **Параметры запроса (Query Parameters):**
    *   Параметры начинаются после знака `?` и перечисляются в формате `ключ=значение`, разделяясь символом `&`.
    *   `lang=ru`: Указывает, что ответ должен быть на русском языке.
    *   `fields=...`: Запрашивает только определённые поля в ответе.

**Пример ответа (в формате JSON):**
```json
{
    "status": "success",
    "query": "81.177.141.139",
    "country": "Россия",
    "regionName": "Москва",
    "city": "Москва",
    "org": "Tilda Publishing"
}
```
Как видно, в ответ мы получили не веб-страницу, а структурированные данные. Сервис сначала определил IP-адрес для доменного имени `sazankin.ru` (поле `query`), а затем предоставил геолокацию для этого IP.

## Практический пример: ручной вызов API через `telnet`

Хотя для работы с API существуют удобные инструменты, понимание "сырого" протокола HTTP очень полезно. Продемонстрировать это можно, отправив HTTP-запрос вручную с помощью утилиты `telnet` (или `putty` в режиме Raw).

1.  **Подключение к серверу:**
    Устанавливаем TCP-соединение с сервером API на порт 80.

    ```bash
    telnet ip-api.com 80
    ```

2.  **Отправка HTTP-запроса:**
    После установки соединения сервер ожидает от нас запрос. Вводим его вручную: стартовую строку, заголовки и пустую строку в конце.

    ```http
    GET /json/sazankin.ru HTTP/1.1
    Host: ip-api.com
    ```
    *   `GET /json/sazankin.ru HTTP/1.1`: Метод `GET`, путь к ресурсу и версия протокола.
    *   `Host: ip-api.com`: Обязательный заголовок в HTTP/1.1, указывающий, к какому домену мы обращаемся.
    *   `(пустая строка)`: Двойное нажатие Enter сигнализирует об окончании заголовков.

3.  **Получение ответа:**
    Сервер присылает "сырой" HTTP-ответ:

    ```http
    HTTP/1.1 200 OK
    Content-Type: application/json; charset=utf-8
    ... (другие заголовки) ...

    {"status":"success","country":"Россия","regionName":"Москва","city":"Москва","query":"81.177.141.139","org":"Tilda Publishing"}
    ```
    Ответ содержит строку состояния, заголовки и тело в формате JSON. Этот пример наглядно показывает, что HTTP-взаимодействие — это просто обмен текстовыми сообщениями по TCP-соединению.

## HTTP-методы и операции CRUD

В HTTP API принято сопоставлять [HTTP-методы](./application_layer.md#методы-http) со стандартными операциями по управлению данными — **CRUD** (Create, Read, Update, Delete).

| Операция | Описание | HTTP-метод | Описание метода |
| :--- | :--- | :--- | :--- |
| **Create** | Создание нового ресурса | `POST` | Отправляет данные на сервер для создания новой сущности. |
| **Read** | Чтение/получение ресурса | `GET` | Запрашивает данные. Безопасный и идемпотентный метод. |
| **Update** | Обновление ресурса | `PUT` / `PATCH` | `PUT` полностью заменяет ресурс, `PATCH` применяет частичные изменения. |
| **Delete** | Удаление ресурса | `DELETE` | Удаляет указанный ресурс. |

**Важно:** Это сопоставление является **рекомендацией (best practice)**, а не строгим правилом. Технически ничто не мешает, например, использовать `GET`-запрос для удаления объекта, но это считается плохим дизайном API.

## Сложности и особенности реальных API

Разработка и использование HTTP API связаны с рядом сложностей:

1.  **Отсутствие единого стандарта:**
    *   Параметры могут передаваться как часть URL, в строке запроса (`query string`), в теле запроса (для `POST`/`PUT`) или в заголовках.
    *   Форматы ответов и структура ошибок могут сильно отличаться.

2.  **Авторизация:**
    *   Большинство API требуют аутентификации и авторизации. Для этого часто используются стандартные протоколы, такие как **OAuth 2.0**. Клиент должен получить токен доступа и передавать его с каждым запросом.

3.  **Версионирование:**
    *   API со временем меняются. Чтобы не "сломать" старые клиенты, вводят версионирование (например, `/api/v1/users`, `/api/v2/users`). Разные версии могут принимать разные параметры и возвращать данные в разном формате.

## Инструменты для работы с API

Для взаимодействия с HTTP API существуют специализированные инструменты:

*   **[Postman](../ServicesAndTools/postman_api_testing.md):** Мощный инструмент с графическим интерфейсом, идеально подходит для ручного тестирования и исследования API.
*   **[cURL](../ServicesAndTools/linux_http_clients.md#curl):** Стандартная утилита командной строки, незаменима для автоматизации и использования в скриптах.
*   **[HTTPie](../ServicesAndTools/linux_http_clients.md#httpie):** Современный и более дружелюбный к пользователю клиент командной строки.
