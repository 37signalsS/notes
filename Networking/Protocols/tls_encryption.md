# Протокол TLS: Шифрование

Протокол [TLS (Transport Layer Security)](./tls_protocol.md) обеспечивает три ключевые функции безопасности: **приватность**, **целостность** и **аутентификацию**. Эта заметка посвящена тому, как TLS обеспечивает приватность с помощью шифрования.

**Приватность** — это защита данных от прочтения посторонними. Если клиент передает данные на сервер, злоумышленник не должен иметь возможности их прочитать, даже если перехватит. В TLS это достигается за счет шифрования.

## Типы шифрования

В криптографии существует два основных подхода к шифрованию: симметричный и асимметричный.

### 1. Симметричное шифрование

*   **Принцип:** Для шифрования и расшифровки данных используется **один и тот же ключ**. Этот ключ должен быть известен и отправителю, и получателю.
*   **Преимущество:** Работает очень быстро.
*   **Недостаток:** **Проблема распределения ключей**. Ключ необходимо хранить в секрете, и его нельзя передавать по открытой сети, так как злоумышленник может его перехватить.
*   **Алгоритмы в TLS:** AES, ChaCha20.

### 2. Асимметричное шифрование

*   **Принцип:** Используется **пара ключей**:
    *   **Открытый ключ (Public Key):** Может свободно распространяться по сети. Используется для шифрования данных.
    *   **Закрытый ключ (Private Key):** Хранится в строжайшем секрете у владельца. Используется для расшифровки данных, зашифрованных открытым ключом.
*   **Преимущество:** Решает проблему распределения ключей. Клиент может безопасно отправить сообщение серверу, зашифровав его открытым ключом сервера.
*   **Недостаток:** Работает значительно медленнее симметричного шифрования.
*   **Алгоритмы в TLS:** RSA, алгоритмы на основе эллиптических кривых (ECDH).

## Гибридное шифрование в TLS

TLS использует **гибридную схему**, комбинируя преимущества обоих подходов:

1.  **Асимметричное шифрование** используется на этапе **установки соединения (handshake)** для безопасного обмена **сессионным ключом**.
2.  **Симметричное шифрование** используется для шифрования всех остальных данных в рамках сессии с помощью этого сессионного ключа.

## Алгоритмы обмена ключами

В процессе рукопожатия TLS клиент и сервер должны безопасно согласовать общий сессионный ключ.

### Обмен ключами на основе RSA (устарел)

Исторически для обмена ключами использовался алгоритм RSA:

1.  Сервер имеет пару ключей RSA (открытый и закрытый).
2.  Клиент запрашивает соединение.
3.  Сервер отправляет клиенту свой открытый ключ (в составе [сертификата](./tls_protocol.md)).
4.  Клиент генерирует случайный сессионный ключ, шифрует его открытым ключом сервера и отправляет обратно.
5.  Сервер расшифровывает полученное сообщение своим закрытым ключом и получает сессионный ключ.

**Недостатки RSA-обмена:**

*   **Отсутствие Perfect Forward Secrecy (PFS):** Если злоумышленник в будущем украдет закрытый ключ сервера, он сможет расшифровать **все прошлые сессии**, трафик которых он записал. Это критическая уязвимость.
*   **Другие уязвимости:** Алгоритм подвержен различным атакам (например, атака "миллиона сообщений" Блейхенбахера).

Из-за этих недостатков обмен ключами на основе RSA **запрещен в TLS 1.3**.

### Обмен ключами на основе Диффи-Хеллмана (DHE/ECDHE)

Современные версии TLS используют алгоритмы Диффи-Хеллмана, чаще всего его вариант на эллиптических кривых (**ECDHE** - Elliptic Curve Diffie-Hellman Ephemeral).

**Принцип работы (упрощенно):**

1.  Клиент и сервер договариваются об общих, открытых параметрах (числа `p` и `g`).
2.  Каждая сторона генерирует свое **секретное число** (`a` у клиента, `b` у сервера).
3.  Каждая сторона вычисляет **открытое число** на основе общих параметров и своего секрета (например, `A = g^a mod p`) и отправляет его другой стороне.
4.  Используя свое секретное число и полученное открытое число, обе стороны **независимо** вычисляют **один и тот же общий секрет** (сессионный ключ).

**Ключевое преимущество — Perfect Forward Secrecy (PFS):**

В "эфемерном" (Ephemeral) варианте (DHE/ECDHE) секретные числа и ключи генерируются **заново для каждой сессии** и уничтожаются после ее завершения. Это означает:

> Даже если злоумышленник перехватит весь трафик сессии и позже украдет долгосрочный закрытый ключ сервера, он **не сможет** расшифровать эту сессию, так как для этого требовались временные (эфемерные) ключи, которых больше не существует.

## Набор шифров (Cipher Suite)

Набор шифров — это комбинация алгоритмов, которую клиент и сервер согласовывают для использования в TLS-сессии. В процессе `ClientHello` и `ServerHello` они выбирают один общий набор из списков, которые поддерживают.

Типичный набор шифров для TLS 1.2 выглядит так:
`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`

Он определяет:
*   **`ECDHE`**: Алгоритм обмена ключами (Elliptic Curve Diffie-Hellman Ephemeral).
*   **`RSA`**: Алгоритм аутентификации сервера (проверки его сертификата).
*   **`AES_128_GCM`**: Алгоритм симметричного шифрования (AES с длиной ключа 128 бит в режиме GCM).
*   **`SHA256`**: Хеш-функция для проверки целостности ([MAC](./tls_data_integrity.md)).
