# Spanning Tree Protocol (STP)

В коммутируемых сетях [L2](../OSI_TCP_IP_Model/osi_tcp_ip_models.md), построенных на основе мостов (bridges) и коммутаторов (switches), одной из самых серьезных проблем является **сетевая петля (network loop)**. Она возникает, когда между двумя устройствами существует более одного активного пути.

## Что такое широковещательный шторм (Broadcast Storm)?

Сетевая петля сама по себе не является проблемой, пока по сети не начинает передаваться **широковещательный (broadcast)** или **multicast** трафик.

1.  **Источник:** Любое устройство в сети отправляет широковещательный кадр. Классический пример — **[ARP-запрос](./arp_protocol.md)**, когда хост пытается узнать MAC-адрес другого хоста по его IP-адресу.
2.  **Распространение:** Коммутатор, получив широковещательный кадр, по определению должен отправить его во **все порты**, кроме того, из которого кадр пришел.
3.  **Петля в действии:** Если в сети есть петля, коммутаторы начинают пересылать этот кадр друг другу по кругу. Каждый коммутатор, получив кадр от соседа, снова рассылает его во все порты.
4.  **Экспоненциальный рост:** Количество копий одного и того же кадра начинает расти в геометрической прогрессии. Этот процесс лавинообразно занимает всю доступную пропускную способность сети.

**Последствия широковещательного шторма:**

*   **Отказ сети:** Полезный трафик не может быть передан, так как вся полоса пропускания занята "мусорными" кадрами. Сеть фактически перестает работать.
*   **Деградация [MAC-таблиц](./mac_address.md):** Коммутаторы постоянно видят один и тот же MAC-адрес источника приходящим с разных портов, что вызывает постоянное обновление таблицы MAC-адресов и ее нестабильность.
*   **Высокая нагрузка на CPU:** Сетевое оборудование и конечные устройства тратят все свои ресурсы на обработку бесполезного трафика.

## Решение: Spanning Tree Protocol (STP)

Для борьбы с петлями был создан **протокол STP (Spanning Tree Protocol)** и его более современные версии (RSTP, MSTP).

**Принцип работы STP:**

1.  **Обнаружение петель:** Коммутаторы обмениваются специальными служебными кадрами (BPDU - Bridge Protocol Data Units).
2.  **Построение дерева:** На основе этой информации они строят логическую топологию сети в виде дерева без петель.
3.  **Блокировка портов:** Если STP обнаруживает избыточный (резервный) путь, который создает петлю, он переводит порт на одном из коммутаторов в состояние **блокировки (blocking)**.

Физически кабель остается подключен, но логически порт не передает данные, разрывая петлю. Если основной путь по какой-то причине выйдет из строя, STP автоматически выведет заблокированный порт из блокировки и восстановит связность сети, используя ранее избыточный путь.

В выводе утилиты `brctl` для сетевых мостов в Linux можно увидеть, включен ли STP.

```bash
$ brctl show
bridge name     bridge id               STP enabled     interfaces
docker0         8000.0242ac110002       no              veth...
```

В данном примере для моста `docker0` протокол STP отключен (`no`), так как Docker предполагает, что управление сетевой топологией происходит на более высоком уровне.
