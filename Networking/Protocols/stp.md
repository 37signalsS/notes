# Spanning Tree Protocol (STP)

## Определения

* **Сетевая петля (Network Loop)**: Возникает в коммутируемых сетях L2 (на основе мостов и коммутаторов), когда между двумя устройствами существует более одного активного пути, что может приводить к широковещательным штормам.
* **Широковещательный шторм (Broadcast Storm)**: Экспоненциальный рост количества широковещательных или мультикастовых кадров в сети, вызванный сетевыми петлями, приводящий к полной загрузке пропускной способности и отказу сети.
* **Spanning Tree Protocol (STP)**: Сетевой протокол, предназначенный для обнаружения и предотвращения сетевых петель в коммутируемых сетях L2 путем логической блокировки избыточных портов.

## Основные понятия

### Принцип возникновения широковещательного шторма

Сетевая петля сама по себе не является проблемой, пока по сети не начинает передаваться **широковещательный (broadcast)** или **multicast** трафик.

1. **Источник:** Любое устройство в сети отправляет широковещательный кадр. Классический пример — **[ARP-запрос](./arp.md)**, когда хост пытается узнать MAC-адрес другого хоста по его IP-адресу.
2. **Распространение:** Коммутатор, получив широковещательный кадр, по определению должен отправить его во **все порты**, кроме того, из которого кадр пришел.
3. **Петля в действии:** Если в сети есть петля, коммутаторы начинают пересылать этот кадр друг другу по кругу. Каждый коммутатор, получив кадр от соседа, снова рассылает его во все порты.
4. **Экспоненциальный рост:** Количество копий одного и того же кадра начинает расти в геометрической прогрессии. Этот процесс лавинообразно занимает всю доступную пропускную способность сети.

### Последствия широковещательного шторма

* **Отказ сети:** Полезный трафик не может быть передан, так как вся полоса пропускания занята "мусорными" кадрами. Сеть фактически перестает работать.
* **Деградация [MAC-таблиц](../Concepts/mac_address.md):** Коммутаторы постоянно видят один и тот же MAC-адрес источника приходящим с разных портов, что вызывает постоянное обновление таблицы MAC-адресов и ее нестабильность.
* **Высокая нагрузка на CPU:** Сетевое оборудование и конечные устройства тратят все свои ресурсы на обработку бесполезного трафика.

### Принцип работы STP

STP (и его современные версии, такие как RSTP, MSTP) борется с петлями следующим образом:

1. **Обнаружение петель**: Коммутаторы обмениваются служебными кадрами (BPDU - Bridge Protocol Data Units).
2. **Построение дерева**: На основе BPDU строится логическая топология сети без петель, напоминающая дерево.
3. **Блокировка портов**: Обнаружив избыточный путь, STP переводит один из портов коммутатора в состояние блокировки (blocking). Логически этот порт не передает данные, разрывая петлю, но физически кабель остается подключенным.

При выходе из строя основного пути, STP автоматически выводит заблокированный порт из состояния блокировки, восстанавливая связность сети через ранее избыточный путь.

## Практические сценарии

### Проверка статуса STP в Linux

Для проверки статуса STP на сетевых мостах в Linux можно использовать утилиту `brctl`:

```bash
$ brctl show
bridge name     bridge id               STP enabled     interfaces
docker0         8000.0242ac110002       no              veth...
```

В примере выше для моста `docker0` протокол STP отключен (`no`). Это объясняется тем, что Docker обычно предполагает управление сетевой топологией на более высоком уровне.
