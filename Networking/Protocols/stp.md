# Spanning Tree Protocol (STP)

## Definitions

**Сетевая петля (Network Loop)** — ситуация в коммутируемых сетях L2, когда между устройствами существует более одного активного физического пути, что приводит к широковещательным штормам и нестабильности MAC-таблиц.

**Широковещательный шторм (Broadcast Storm)** — экспоненциальный рост broadcast/multicast-трафика из-за петель, вызывающий полную загрузку пропускной способности и отказ сети.

**STP (Spanning Tree Protocol, IEEE 802.1D)** — протокол канального уровня (L2) для обнаружения и логической блокировки избыточных путей, предотвращающий петли при сохранении физической отказоустойчивости.

**Ключевая идея:** STP строит **логическое дерево** (spanning tree) с одним корневым коммутатором, блокируя избыточные порты и разрывая петли.

## Basic Concepts

### Почему возникают петли

**Сценарий:**

```
    [Switch A]
     /        \
    /          \
[Switch B]──[Switch C]
```

1. Хост отправляет **broadcast-кадр** (например, [ARP-запрос](./arp.md))
2. Коммутаторы рассылают broadcast во все порты, кроме входного (flooding)
3. Кадр циркулирует по кругу A→B→C→A→...
4. Каждый коммутатор копирует кадр → экспоненциальный рост → сеть перегружается

**Последствия:** отказ сети (вся полоса занята «мусорным» трафиком), нестабильность MAC-таблиц (один MAC виден с разных портов), высокая нагрузка на CPU коммутаторов и хостов.

### Принцип работы STP

**Алгоритм:**

1. **Выбор корневого коммутатора (Root Bridge)** — коммутатор с наименьшим **Bridge ID** (приоритет + MAC). Приоритет по умолчанию: 32768. Рекомендуется вручную назначать главный и резервный корневые коммутаторы.
2. **Выбор корневых портов (Root Ports)** — на каждом не-корневом коммутаторе выбирается один порт с лучшим путём к корню.
3. **Выбор назначенных портов (Designated Ports)** — на каждом сегменте выбирается один порт для передачи трафика.
4. **Блокировка избыточных портов (Blocked/Alternate)** — все остальные порты переводятся в состояние **blocking**.

**Состояния портов (802.1D):**

| Состояние | Передача данных | Обучение MAC | Время |
|-----------|----------------|--------------|-------|
| Blocking | Нет | Нет | 20 сек (Max Age) |
| Listening | Нет | Нет | 15 сек (Forward Delay) |
| Learning | Нет | Да | 15 сек (Forward Delay) |
| Forwarding | Да | Да | — |
| Disabled | Нет | Нет | — |

**Время конвергенции классического STP:** 30–50 секунд.

### Эволюция STP

| Протокол | Стандарт | Конвергенция | Особенности |
|----------|----------|-------------|-------------|
| STP | IEEE 802.1D | 30–50 сек | Классический, медленный |
| RSTP | IEEE 802.1w | 1–10 сек | Быстрая конвергенция, новые роли портов |
| MSTP | IEEE 802.1s | 1–10 сек | Несколько экземпляров STP для VLAN |
| PVST+ | Cisco proprietary | 1–10 сек | STP на каждый VLAN (требует CPU) |

**RSTP улучшения:** новые роли портов (Alternate, Backup), быстрый переход в forwarding на edge-портах (PortFast), активная отправка BPDU каждые 2 сек, механизм proposal/agreement для быстрой конвергенции.

**Рекомендация:** использовать **RSTP** или **MSTP** вместо классического STP.

## Practical Scenarios

### Проверка статуса STP в Linux

Для мостов в Linux:

```bash
brctl show
# bridge name     bridge id               STP enabled     interfaces
# br0             8000.0242ac110002       yes             eth0
#                                                         eth1
# docker0         8000.0242ac110003       no              veth12345
```

**Настройка:**

```bash
brctl stp br0 on          # Включить STP
brctl showstp br0         # Параметры STP
brctl setbridgeprio br0 4096  # Приоритет моста
```

Docker по умолчанию отключает STP на `docker0`, так как управление сетью осуществляется на более высоком уровне.

### Настройка на коммутаторе

**Сценарий:** отказоустойчивая сеть с двумя коммутаторами и сервером с двумя NIC.

```
    [Server with 2 NICs]
         /       \
        /         \
  [Switch A]──[Switch B]
       |          |
    [Uplink to Core/Router]
```

**План:** Root Bridge — Switch A (приоритет 4096), Backup Root — Switch B (8192), PortFast на портах серверов, BPDU Guard на пользовательских портах.

**Пример (Cisco IOS):**

```cisco
spanning-tree mode rapid-pvst
spanning-tree vlan 1 priority 4096
interface GigabitEthernet0/1
  spanning-tree portfast
  spanning-tree bpduguard enable
```

### Диагностика

**Симптомы проблем:** периодические потери связи (1–2 мин), высокая загрузка CPU на коммутаторах, частые изменения топологии (TCN).

**Диагностические команды:**

```bash
# Cisco
show spanning-tree summary
show spanning-tree detail
show logging | include STP|SPAN

# Juniper
show spanning-tree bridge
show spanning-tree interface
```

**Частые причины:** неправильный Root Bridge (корнем становится слабый коммутатор), односторонняя связь (unidirectional link — помогает UDLD), петля из-за misconfigured порта (BPDU Guard должен блокировать), медленная конвергенция (перейти на RSTP).

### Безопасность

**Атаки:** Root Bridge Attack (злоумышленник отправляет BPDU с лучшим приоритетом и перехватывает трафик), BPDU Spoofing.

**Защита:**

| Функция | Описание | Где включать |
|---------|----------|--------------|
| BPDU Guard | Блокирует порт при получении BPDU | Access-порты |
| Root Guard | Запрещает порту стать корневым | Uplink-порты |
| Loop Guard | Обнаруживает односторонние ссылки | Designated-порты |
| BPDU Filter | Игнорирует BPDU | Edge-порты (с осторожностью) |

## Additional Information

### STP и VLAN

Классический STP работает для всех VLAN одинаково — субоптимальное использование путей. **Решения:** PVST+ (отдельный экземпляр STP на каждый VLAN, Cisco), MSTP (группы VLAN привязываются к экземплярам STP, стандарт). MSTP позволяет балансировать трафик по разным физическим путям: Instance 1 (VLAN 10, 20 → Root: Switch A), Instance 2 (VLAN 30, 40 → Root: Switch B).
