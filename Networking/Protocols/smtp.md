# SMTP — протокол передачи почты

## Определения

**SMTP (Simple Mail Transfer Protocol — простой протокол передачи почты)** — протокол прикладного уровня, предназначенный для передачи сообщений электронной почты в сетях TCP/IP.

**Ключевые характеристики:**
- **Транспорт:** использует [TCP](../Protocols/TCP/overview.md) для обеспечения надежной доставки.
- **Тип протокола:** текстовый (командно-ориентированный).
- **Основные порты:**
  - **25** — обмен почтой между серверами (**MTA to MTA**). Часто блокируется провайдерами для предотвращения спама.
  - **587** — порт отправки (**Submission**), используется клиентами (MUA) для передачи почты серверу провайдера (MSA) с использованием STARTTLS.
  - **465** — **SMTPS** (SMTP over SSL), устаревший метод (неявный TLS), но всё ещё встречается в старых системах.

> **См. также:** [DNS (MX-записи)](./DNS/dns_records.md), [Модель OSI](../OSI_TCP_IP_Model/osi_model.md)

## Основные концепции

### Роли и компоненты системы доставки
Процесс передачи почты включает взаимодействие нескольких агентов:

1. **MUA (Mail User Agent):** почтовый клиент пользователя (Outlook, Thunderbird, мобильные приложения).
2. **MSA (Mail Submission Agent):** сервер, принимающий почту от MUA. Проверяет авторизацию и корректность письма.
3. **MTA (Mail Transfer Agent):** сервер, отвечающий за маршрутизацию и пересылку писем между доменами (например, Postfix, Exim).
4. **MDA (Mail Delivery Agent):** компонент, сохраняющий письмо в локальное хранилище (почтовый ящик) получателя.
5. **DNS:** используется MTA для поиска адреса целевого сервера через записи типа **MX (Mail Exchanger)**.

### Сценарий доставки письма
1. **MUA → MSA:** клиент подключается по порту 587, проходит аутентификацию и передает письмо.
2. **MSA → MTA:** сервер провайдера отправляет письмо в очередь на пересылку.
3. **MTA → MTA:** сервер отправителя находит MX-запись домена получателя и пересылает письмо по порту 25.
4. **MTA → MDA:** сервер получателя принимает письмо и передает его в локальное хранилище.
5. ** MDA → MUA:** получатель забирает почту по протоколам **POP3** или **IMAP** (SMTP для получения почты клиентом не используется).

## Практические сценарии

### Тестирование SMTP вручную через telnet или nc
Ручное тестирование позволяет проверить доступность сервера и корректность обработки команд.

```bash
# Подключение к серверу
telnet smtp.example.com 25

# 1. Приветствие (имя вашего хоста)
HELO client.example.com
# → 250 Hello

# 2. Указание отправителя
MAIL FROM:<sender@example.com>
# → 250 OK

# 3. Указание получателя
RCPT TO:<recipient@example.com>
# → 250 OK

# 4. Начало ввода данных
DATA
# → 354 End data with <CR><LF>.<CR><LF>

# 5. Тело письма (Заголовки + текст)
Subject: Test email
From: sender@example.com
To: recipient@example.com

Hello, this is a test message via telnet!
.
# (точка на отдельной строке завершает ввод)
# → 250 OK: queued as 12345

# 6. Завершение сессии
QUIT
# → 221 Bye
```

## Дополнительная информация

### Безопасность и аутентификация
Для борьбы со спамом и подделкой отправителя (spoofing) используются следующие механизмы:

- **STARTTLS:** команда для перевода открытого (plaintext) соединения в зашифрованный режим TLS.
- **SMTP AUTH:** механизм аутентификации пользователя (обычно через SASL) перед отправкой почты.
- **SPF (Sender Policy Framework):** DNS-запись со списком IP-адресов, которым разрешено отправлять почту от имени домена.
- **DKIM (DomainKeys Identified Mail):** цифровая подпись письма, подтверждающая, что оно отправлено именно владельцем домена и не было изменено.
- **DMARC (Domain-based Message Authentication):** политика, указывающая получателю, что делать с письмами, не прошедшими проверку SPF или DKIM (например, `reject` или `quarantine`).

Подробнее о настройке DNS для почты: **[Записи DNS для почтовых служб](./DNS/dns_records.md)**.
