# Протокол IPv6 (Internet Protocol version 6)

## Определения

**IPv6 (Internet Protocol version 6)** — сетевой протокол следующего поколения, разработанный IETF для замены IPv4. Описан в **RFC 8200** (Internet Standard). Протокол решает проблему исчерпания адресов и вносит ряд архитектурных улучшений для повышения эффективности маршрутизации и безопасности.

**Ключевые отличия от IPv4:**
- **Размер адреса:** 128 бит (против 32 бит).
- **Адресное пространство:** ~$3,4 \times 10^{38}$ адресов.
- **Формат заголовка:** фиксированный размер 40 байт, отсутствие контрольной суммы (обработка быстрее на аппаратном уровне).
- **Инкапсуляция:** опции вынесены в **Extension Headers** (расширенные заголовки).

> **См. также:** **[Сосуществование IPv4 и IPv6 (Dual Stack)](../OSI_TCP_IP_Model/Network_layer/Concepts/ipv4_ipv6_dual_stack.md)**, **[ICMPv6 и диагностика](./ICMP/icmp_diagnostics_security.md)**

## Базовые концепции

### Преимущества архитектуры

| Преимущество | Техническое описание |
| :--- | :--- |
| **Иерархичность** | Структура адресации способствует агрегации маршрутов, что снижает нагрузку на глобальные таблицы BGP. |
| **End-to-end связность** | Возврат к классической модели связи без NAT, упрощающий работу P2P, VoIP и VPN. |
| **Neighbor Discovery** | Набор механизмов на базе ICMPv6, заменяющий ARP и IGMP. |
| **SLAAC** | Автоматическая настройка адреса без необходимости в DHCP-сервере. |
| **Anycast нативно** | Поддержка Anycast без специальных конфигураций протоколов маршрутизации. |

### Формат адреса и запись (RFC 5952)

Адрес состоит из 8 хекстетов (групп по 16 бит), разделенных двоеточиями.
**Пример:** `2001:0db8:0000:0000:0008:0800:200c:417a`

**Правила сокращения:**
1. **Удаление ведущих нулей:** в каждом хекстете (`0db8` → `db8`).
2. **Сжатие нулей (`::`):** заменяет одну самую длинную последовательность нулевых хекстетов (применяется только один раз).
3. **Регистр:** только строчные буквы.
**Результат сокращения:** `2001:db8::8:800:200c:417a`.

### Типы адресов и Scoping

IPv6 использует концепцию областей видимости (Scopes).

| Тип адреса | Префикс | Область видимости | Назначение |
| :--- | :--- | :--- | :--- |
| **Link-Local (LLA)** | `fe80::/10` | L2-сегмент | Служебный трафик (NDP, DHCPv6). Требует **Zone Index** (например, `%eth0`). |
| **Unique Local (ULA)** | `fc00::/7` | Организация | Аналог частных адресов (RFC 1918). Маршрутизируются внутри AS. |
| **Global Unicast (GUA)** | `2000::/3` | Глобальная | Публичные маршрутизируемые адреса. |
| **Multicast** | `ff00::/8` | Зависит от флагов | Групповая рассылка. Заменяет Broadcast. |
| **Loopback** | `::1/128` | Хост | Локальный интерфейс (lo). |
| **Unspecified** | `::/128` | Хост | Используется в качестве исходного адреса до получения собственного. |
| **IPv4-Mapped** | `::ffff:0:0/96` | Системная | Представление IPv4 в Dual-stack приложениях. |

## Структура и механизмы

### Заголовок IPv6 (40 байт)

1. **Version (4 бита):** значение `6`.
2. **Traffic Class (8 бит):** управление QoS (поля DSCP и ECN).
3. **Flow Label (20 бит):** маркировка пакетов одного потока для ускоренной обработки.
4. **Payload Length (16 бит):** размер данных (без учета заголовка). Поддерживает **Jumbograms** (RFC 2675).
5. **Next Header (8 бит):** тип следующего заголовка (L4 или Extension Header).
6. **Hop Limit (8 бит):** аналог TTL в IPv4.

### Расширенные заголовки (Extension Headers)

Цепочка заголовков, следующих за основным. Порядок важен для аппаратного парсинга:
- **Hop-by-Hop Options (0):** параметры для каждого узла.
- **Routing (43):** задание пути (используется в SRv6).
- **Fragment (44):** данные для сборки фрагментированного пакета.
- **ESP/AH (50/51):** безопасность IPsec.
- **Destination Options (60):** параметры только для конечного узла.

### Протокол обнаружения соседей (NDP)

NDP (RFC 4861) — критическая часть IPv6, работающая через ICMPv6 (Multicast).
- **Router Discovery (RS/RA):** Обнаружение маршрутизаторов. RA содержат префиксы и флаги конфигурации.
- **Address Resolution (NS/NA):** Аналог ARP. Разрешение L3-адреса в MAC.
- **NUD (Neighbor Unreachability Detection):** Проверка доступности соседа.
- **DAD (Duplicate Address Detection):** Проверка на конфликты IP при включении интерфейса.

### Способы назначения адресов и флаги RA

1. **SLAAC (Stateless Address Autoconfiguration):** Хост генерирует адрес сам на основе префикса из RA.
2. **Stateful DHCPv6:** Адрес выдается сервером (аналог DHCPv4).
3. **Stateless DHCPv6:** SLAAC для адреса + DHCPv6 для опций (DNS, поиск домена).

**Флаги в Router Advertisement (RA):**
- **M (Managed Address Configuration):** если 1, использовать Stateful DHCPv6.
- **O (Other Configuration):** если 1, получить доп. параметры через DHCPv6.

### Генерация Interface ID (младшие 64 бита)

- **EUI-64:** На основе MAC-адреса. Уязвимость: позволяет отслеживать хост при смене сетей.
- **Privacy Extensions (RFC 4941):** Генерация временных случайных адресов для исходящих соединений.
- **Stable Privacy (RFC 7217):** Современный стандарт (замена EUI-64). Генерация стабильного, но случайного адреса для каждого интерфейса (предотвращает трекинг).

## Продвинутые технологии и безопасность

### Segment Routing (SRv6)

Архитектура «маршрутизации от источника» (Source Routing), использующая Extension Headers (Routing Header Type 4).
- **Суть:** Путь пакета задается списком SID (Segment Identifiers), которые по сути являются IPv6-адресами.
- **Применение:** Traffic Engineering, централизованное управление сетью (SDN), замена MPLS.

### Безопасность NDP

Поскольку NDP работает на L2, он уязвим к атакам (Spoofing).
1. **RA Guard (RFC 6105):** Функция коммутатора, блокирующая RA-сообщения на портах, где не должно быть маршрутизаторов.
2. **SEND (Secure Neighbor Discovery):** Использование криптографически генерируемых адресов (CGA) для подписи NDP-сообщений. Из-за сложности часто заменяется на **ND Inspection** на оборудовании.

### Фрагментация и MTU

- **Минимальный MTU:** 1280 байт.
- **Отсутствие транзитной фрагментации:** Маршрутизаторы **никогда** не дробят пакеты. Если пакет велик, узел шлет **ICMPv6 Type 2 (Packet Too Big)**.
- **PMTUD (Path MTU Discovery):** Обязателен для хостов. Блокировка ICMPv6 Type 2 ломает связность (проблема «черных дыр» MTU).

## Практические сценарии

### Диагностика в Linux

```bash
# Пинг Link-Local адреса (обязателен Zone Index)
ping -6 fe80::1%eth0

# Просмотр таблицы соседей
ip -6 neigh show

# Трассировка с обнаружением MTU на пути
tracepath6 -n google.com

# Просмотр параметров RA от маршрутизаторов
rdisc6 eth0
```

### Механизмы перехода (Кратко)

- **Happy Eyeballs (RFC 8305):** Алгоритм быстрой попытки соединения по обоим протоколам с приоритетом IPv6.
- **NAT64 / DNS64:** Доступ из IPv6-only сетей к ресурсам IPv4.
- **464XLAT:** Двойная трансляция (CLAT на устройстве, PLAT у провайдера) для работы IPv4-only приложений.
