# Протокол IPv6 (Internet Protocol version 6)

> **Reliability Score: 10** (SSoT + Verified RFCs + Industry Standard)

## Определения

**IPv6 (Internet Protocol version 6)** — протокол сетевого уровня, разработанный для полной замены IPv4 и радикального расширения глобального адресного пространства. Описан в **RFC 8200** (Internet Standard).

**Ключевые отличия от IPv4:**
- **Размер адреса:** увеличен с 32 бит до 128 бит (16 байт).
- **Количество адресов:** ~$3,4 \times 10^{38}$ (адреса хватит для каждого атома на поверхности Земли).
- **Формат заголовка:** упрощен, имеет фиксированный размер 40 байт и оптимизирован для аппаратной обработки.

## Базовые концепции

### Преимущества архитектуры IPv6

| Преимущество | Техническое описание |
| :--- | :--- |
| **Иерархичность** | Упрощает агрегацию маршрутов, уменьшая размер глобальных таблиц BGP. |
| **Упрощенный заголовок** | Отсутствие контрольной суммы заголовка (проверка на L2 и L4 достаточна). |
| **Extension Headers** | Опции вынесены в цепочку дополнительных заголовков, что ускоряет обработку базового пакета. |
| **End-to-end связность** | Возвращает классическую модель связи без необходимости в NAT, что критично для P2P и VoIP. |
| **Neighbor Discovery** | Заменяет ARP и IGMP на единый механизм на базе ICMPv6. |

### Формат адреса и запись

Адрес записывается как 8 групп (хекстетов) по 4 шестнадцатеричных цифры, разделенных двоеточиями.

**Правила сокращения (RFC 5952):**
1. **Удаление ведущих нулей:** в каждом хекстете (`0db8` → `db8`).
2. **Сжатие нулей (`::`):** одна последовательность из подряд идущих нулевых хекстетов заменяется на `::` (только один раз в адресе).
3. **Регистр:** рекомендуется использовать строчные буквы.

**Пример:** `2001:0db8:0000:0000:0008:0800:200c:417a` → `2001:db8::8:800:200c:417a`.

### Типы адресов

| Тип | Префикс | Описание |
| :--- | :--- | :--- |
| **Global Unicast (GUA)** | `2000::/3` | Глобально маршрутизируемые публичные адреса. |
| **Link-Local (LLA)** | `fe80::/10` | Действуют только в пределах одного L2-сегмента. Обязательны для работы NDP. |
| **Unique Local (ULA)** | `fc00::/7` | Аналог частных адресов IPv4 (RFC 1918) для внутренних сетей. |
| **Multicast** | `ff00::/8` | Групповая рассылка. Полностью заменяет Broadcast. |
| **Solicited-Node Multicast** | `ff02::1:ffxx:xxxx` | Используется в NDP для разрешения адресов (вместо ARP). |
| **IPv4-Mapped** | `::ffff:0:0/96` | Представление IPv4 в пространстве IPv6 для Dual-stack приложений. |

## Структура и механизмы

### Заголовок IPv6 (Фиксированный)

Заголовок имеет размер **40 байт**.
- **Version (4 бита):** всегда `6`.
- **Traffic Class (8 бит):** управление QoS (DSCP/ECN).
- **Flow Label (20 бит):** идентификация потоков для обработки в реальном времени.
- **Payload Length (16 бит):** размер данных (без учета 40 байт основного заголовка).
- **Next Header (8 бит):** тип следующего заголовка (TCP, UDP или Extension Header).
- **Hop Limit (8 бит):** замена TTL из IPv4.

### Расширенные заголовки (Extension Headers)

Следуют сразу за основным заголовком. Примеры:
- **Hop-by-Hop Options:** параметры для каждого узла на пути.
- **Fragment Header:** используется при фрагментации отправителем.
- **Routing Header:** принудительное задание пути.
- **ESP/AH:** заголовки безопасности IPsec.

> **Безопасность:** Многие корпоративные файрволы настроены на отбрасывание пакетов со сложной цепочкой Extension Headers для предотвращения атак обхода фильтрации.

### Протокол обнаружения соседей (NDP)

NDP (RFC 4861) работает через ICMPv6 и выполняет задачи:
1. **Router Discovery:** поиск шлюзов по умолчанию.
2. **Prefix Discovery:** получение информации о подсетях.
3. **Address Resolution:** аналог ARP (сообщения NS/NA).
4. **Neighbor Unreachability Detection (NUD):** проверка доступности соседей.
5. **DAD (Duplicate Address Detection):** предотвращение конфликтов IP.

### Способы назначения адресов

1. **SLAAC (Stateless Address Autoconfiguration):** Хост настраивается сам на основе RA-пакетов маршрутизатора.
2. **Stateful DHCPv6:** Аналог DHCP в IPv4, сервер ведет базу выданных адресов.
3. **Stateless DHCPv6:** SLAAC для адреса + DHCPv6 только для дополнительных параметров (DNS, домен).

**Флаги в Router Advertisement (RA):**
- **M (Managed):** если 1, использовать Stateful DHCPv6.
- **O (Other):** если 1, получить доп. параметры через Stateless DHCPv6.

### Генерация Interface ID (младшие 64 бита)

- **EUI-64:** на основе MAC-адреса (с инверсией 7-го бита). Делает устройство отслеживаемым.
- **Privacy Extensions (RFC 4941):** генерация временных случайных адресов для исходящего трафика.
- **Stable Privacy (RFC 7217):** генерация стабильного, но случайного адреса для каждого интерфейса (современный стандарт).

## Практические аспекты для SRE

### Фрагментация и MTU

- Маршрутизаторы IPv6 **никогда не фрагментируют** транзитные пакеты.
- Если пакет больше MTU, узел шлет **ICMPv6 Type 2 (Packet Too Big)**.
- **Минимальный MTU** для IPv6 — **1280 байт**. Если канал не может обеспечить этот минимум, IPv6 в нем не будет работать без туннелирования.
- Отправитель обязан использовать **PMTUD** (Path MTU Discovery).

### Диагностика

```bash
# Пинг всех узлов в сегменте (Link-local multicast)
ping -6 ff02::1%eth0

# Просмотр соседей (аналог arp -a)
ip -6 neigh show

# Трассировка с указанием MTU
tracepath6 google.com

# Просмотр параметров RA
rdisc6 eth0
```

### Совместимость и переход

- **Dual Stack:** оба протокола включены. Приложения используют алгоритм **Happy Eyeballs (RFC 8305)** для выбора быстрейшего протокола.
- **NAT64 + DNS64:** доступ из IPv6-only сети к IPv4 ресурсам.
- **464XLAT:** стандарт для мобильных сетей, обеспечивающий работу IPv4-only приложений в IPv6 сетях.
