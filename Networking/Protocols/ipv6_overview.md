# Протокол IPv6 (Internet Protocol version 6)

## Определения

**IPv6 (Internet Protocol version 6)** — протокол сетевого уровня, разработанный для замены IPv4 и решения проблемы исчерпания глобального адресного пространства.

**Ключевые отличия от IPv4:**

- **Размер адреса:** увеличен с 32 бит до 128 бит.
- **Количество адресов:** ~$3,4 \times 10^{38}$ (против $4,3 \times 10^9$ в IPv4).
- **Формат заголовка:** упрощен и имеет фиксированный размер 40 байт для ускорения обработки маршрутизаторами.

## Базовые концепции

### Предпосылки создания

К 2010-м годам свободные блоки IPv4-адресов были практически исчерпаны. Внедрение **NAT (Network Address Translation — трансляция сетевых адресов)** и **CIDR (Classless Inter-Domain Routing — бесклассовая междоменная маршрутизация)** лишь отсрочило дефицит.

Подробнее об IPv4: [IP-адресация — Обзор](./IP_addressing/ip_overview.md).

### Преимущества IPv6

| Преимущество | Описание |
| :--- | :--- |
| **Огромное пространство** | Снимает ограничения на количество устройств в сети |
| **Упрощенный заголовок** | Фиксированный размер, отсутствие контрольной суммы (чек-суммы) заголовка |
| **Отсутствие широковещания** | **Broadcast** заменен на эффективный **Multicast** (групповая рассылка) |
| **End-to-end связность** | Отсутствие необходимости в NAT восстанавливает прямую связность узлов |
| **Автоконфигурация** | Механизм **SLAAC (Stateless Address Autoconfiguration)** позволяет устройствам получать адрес без сервера DHCP |
| **Безопасность** | Поддержка **IPsec** заложена в стандарт |

### Формат адреса и сокращенная запись

Адрес IPv6 состоит из 128 бит, разделенных на 8 групп (хекстетов) по 16 бит. Записывается в шестнадцатеричном формате.

**Правила сокращения:**

1. **Удаление ведущих нулей:** в каждом хекстете начальные нули можно опустить (`0DB8` → `DB8`).
2. **Двойное двоеточие (`::`):** одна последовательность из одного или нескольких нулевых хекстетов может быть заменена на `::`. Используется строго один раз в адресе.

**Пример:**
`2001:0db8:0000:0000:0001:0000:0000:0001`
→ `2001:db8:0:0:1::1` (или `2001:db8::1:0:0:1`)

### Типы адресов IPv6

| Тип | Префикс | Описание |
| :--- | :--- | :--- |
| **Global Unicast** | `2000::/3` | Глобально уникальные публичные адреса |
| **Link-local** | `fe80::/10` | Действуют только в пределах одного L2-сегмента. Обязательны для каждого интерфейса |
| **Unique Local (ULA)** | `fc00::/7` | Аналог частных (серых) адресов IPv4 для внутренних сетей |
| **Multicast** | `ff00::/8` | Групповые адреса |
| **Loopback** | `::1/128` | Интерфейс обратной петли (аналог `127.0.0.1`) |
| **Unspecified** | `::/128` | Используется хостом до получения адреса (аналог `0.0.0.0`) |

## Практические сценарии

### Сравнение IPv4 и IPv6

| Характеристика | IPv4 | IPv6 |
| :--- | :--- | :--- |
| **Размер адреса** | 32 бита (4 байта) | 128 бит (16 байт) |
| **Размер заголовка** | 20–60 байт (переменный) | 40 байт (фиксированный) |
| **Контрольная сумма** | Проверяется на каждом маршрутизаторе | Отсутствует (перенесена на L2/L4) |
| **Фрагментация** | Выполняется маршрутизаторами и отправителем | Только отправителем (end-to-end) |
| **Опции** | Встроены в заголовок (поле Options) | Вынесены в расширенные заголовки (**Extension Headers**) |
| **ARP** | Используется для разрешения адресов | Заменен на **NDP (ICMPv6)** |
| **NAT** | Необходим из-за нехватки адресов | Не требуется (end-to-end связность) |

### Структура заголовка IPv6

Заголовок IPv6 имеет фиксированный размер **40 байт**, что упрощает его обработку аппаратными средствами.

| Поле | Размер (бит) | Описание |
| :--- | :--- | :--- |
| **Version** | 4 | Версия протокола (`6`) |
| **Traffic Class** | 8 | Приоритизация трафика (**QoS — Quality of Service**) |
| **Flow Label** | 20 | Метка потока для обработки специфических пакетов |
| **Payload Length** | 16 | Длина полезной нагрузки (данных) |
| **Next Header** | 8 | Тип следующего заголовка (TCP=6, UDP=17, ICMPv6=58 или Extension Header) |
| **Hop Limit** | 8 | Максимальное количество переходов (аналог **TTL — Time To Live**) |
| **Source/Dest** | 128/128 | Адреса отправителя и получателя |

**Extension Headers (Расширенные заголовки):** дополнительные функции (фрагментация, безопасность) вынесены в отдельные заголовки, следующие за основным.

### Фрагментация в IPv6

В отличие от IPv4, в IPv6 маршрутизаторы **никогда не фрагментируют пакеты**.

- **Где происходит:** только на конечном узле-отправителе.
- **Механизм:** отправитель использует **PMTUD (Path MTU Discovery — обнаружение MTU на пути)**.
- **Гарантии:** сеть обязана поддерживать **MTU (Maximum Transmission Unit)** не менее **1280 байт**.
- **Заголовок:** информация о фрагментах передается в специальном расширенном заголовке `Fragment Header` (идентификатор пакета увеличен до 32 бит).

### Протокол обнаружения соседей (NDP)

**NDP (Neighbor Discovery Protocol)** работает поверх **ICMPv6 (Internet Control Message Protocol for IPv6)** и заменяет ARP.

**Основные функции:**

- **Address Resolution:** разрешение IP в MAC-адрес (через сообщения NS/NA).
- **SLAAC:** автоматическая настройка адреса (через RS/RA).
- **DAD (Duplicate Address Detection):** проверка уникальности адреса перед использованием.
- **Router Discovery:** поиск шлюзов по умолчанию.

**Типы сообщений:**

- **RS (Router Solicitation):** запрос маршрутизатора.
- **RA (Router Advertisement):** объявление параметров сети маршрутизатором.
- **NS (Neighbor Solicitation):** запрос адреса соседа.
- **NA (Neighbor Advertisement):** ответ соседа.

### Автоконфигурация (SLAAC)

Механизм позволяет хосту настроить адрес самостоятельно:

1. Хост узнает префикс сети из сообщения **RA** от маршрутизатора.
2. Генерирует идентификатор интерфейса (например, на основе MAC-адреса через **EUI-64** или случайным образом).
3. Проверяет адрес на уникальность с помощью **DAD**.

## Дополнительная информация

### Совместимость с IPv4

- **Dual Stack:** одновременная работа двух протоколов на одном интерфейсе.
- **Tunneling:** инкапсуляция IPv6 в IPv4 (протоколы SIT, GRE).
- **NAT64:** трансляция для взаимодействия IPv6-only узлов с IPv4-интернетом.
