# Протокол ICMP (Internet Control Message Protocol)

**ICMP (Internet Control Message Protocol)** — это служебный протокол, который используется устройствами в IP-сети для отправки сообщений об ошибках и управляющих сообщений. Он является неотъемлемой частью стека TCP/IP и работает на [[сетевом уровне (L3)|../Concepts/network_layer.md]]. Протокол IP предоставляет сервис передачи данных без гарантии доставки, и ICMP восполняет этот пробел, предоставляя механизм обратной связи.

Когда сетевое устройство (например, маршрутизатор) сталкивается с проблемой при обработке пакета, оно генерирует ICMP-сообщение и отправляет его источнику пакета.

## 1. Функции ICMP

Основные функции ICMP:
*   **Оповещение об ошибках на сетевом уровне:** Уведомление отправителя о проблемах с доставкой пакетов (например, узел или сеть недоступны).
*   **Тестирование работоспособности сети:** Предоставление средств для диагностики сетевых проблем (например, утилита `ping`).

## 2. Структура ICMP-сообщения

Каждое ICMP-сообщение инкапсулируется в IP-пакет и содержит:

*   **Тип сообщения (Type):** 8-битное поле, которое говорит о том, что произошло в сети — какое действие пытается выполниться или какая ошибка возникла.
*   **Код (Code):** 8-битное поле, в котором подробнее описывается попытка, причина и диагностическое действие для данного типа сообщения.
*   **Контрольная сумма (Checksum):** 16-битное поле, используемое для проверки правильности доставки (целостности) ICMP-сообщения.
*   **Служебная информация (4 байта):** Содержимое этих 4 байт зависит от типа и кода сообщения.
*   **Поле данных ICMP (Variable Data Field):** Часто содержит IP-заголовок и первые 8 байт данных из пакета, при передаче которого произошла ошибка. Это помогает отправителю диагностировать проблему.

## 3. Основные типы ICMP-сообщений

ICMP-сообщения лежат в основе многих популярных сетевых утилит для диагностики.

В целом, в ICMP можно выделить два основных типа сообщений по их назначению:

1.  **Сообщения запроса/ответа для проверки доступности и быстродействия сети:**
    *   **Echo Request (Type 8) / Echo Reply (Type 0):**
        *   **Назначение:** Основа утилиты `ping`. Позволяет проверить доступность узла и измерить время задержки (RTT).
        *   **Принцип:** Устройство A отправляет Echo Request устройству Б. Если устройство Б доступно, оно отвечает сообщением Echo Reply.
    *   **Timestamp Request (Type 13) / Timestamp Reply (Type 14):**
        *   **Назначение:** Используются для проверки быстродействия сети, позволяя измерить время кругового обхода и синхронизировать часы устройств.

2.  **Сообщения об ошибках и управляющие сообщения:**
    *   **Destination Unreachable (Type 3):**
        *   **Назначение:** Сообщает, что пакет не может быть доставлен до узла назначения.
        *   **Коды:**
            *   `Code 0: Net Unreachable` - Сеть назначения недоступна.
            *   `Code 1: Host Unreachable` - Узел назначения недоступен.
            *   `Code 3: Port Unreachable` - Порт на узле назначения закрыт (часто указывает на отсутствие службы).
    *   **Redirect (Type 5):**
        *   **Назначение:** Используется маршрутизаторами для уведомления хоста о наличии более оптимального пути для отправки пакетов в определенную сеть.
    *   **Time Exceeded (Type 11):**
        *   **Назначение:** Отправляется, когда время жизни (TTL) IP-пакета истекает (становится равным нулю) до того, как он достигнет места назначения.
        *   **Использование:** Этот механизм используется утилитой `traceroute` для определения маршрута до цели.
    *   **Parameter Problem (Type 12):**
        *   **Назначение:** Указывает на ошибку в заголовке IP-пакета или ICMP-сообщения (например, некорректное значение поля).
    *   **Router Advertisement (Type 9) / Router Solicitation (Type 10):**
        *   **Назначение:** Используются для автоматического обнаружения маршрутизаторов в локальной сети.
