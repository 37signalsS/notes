# IP-адрес (Internet Protocol Address)

**IP-адрес** — это уникальный числовой идентификатор устройства в компьютерной сети, работающей по протоколу IP. Он используется на [сетевом уровне (L3)](./network_layer_basics.md) для маршрутизации пакетов между сетями и доставки их конечному узлу.

В отличие от [MAC-адресов](./mac_address.md), которые привязаны к физическому оборудованию, IP-адреса являются логическими и могут назначаться динамически.

## Ключевые концепции

### Time To Live (TTL)

**Time To Live (TTL)** — это метод, используемый для ограничения времени жизни данных в сети. В контексте IP-пакетов TTL представляет собой 8-битный счётчик в заголовке IP-пакета, который уменьшается на единицу при каждом прохождении пакета через узел (хоп) на маршруте.

Когда значение TTL становится равным нулю, пакет уничтожается и, как правило, генерируется ICMP-сообщение "Time Exceeded" (тип 11, код 0) отправителю. Это предотвращает "бесконечное" путешествие пакета по сети, если он застрял в петле маршрутизации.

**Почему был введён TTL?**

TTL был введён для решения проблемы, когда IP-пакеты могли бы бесконечно путешествовать по сети из-за ошибок маршрутизации (например, сетевых петель). Без TTL такие "застрявшие" пакеты могли бы перегружать сетевые устройства и каналы связи, что негативно сказывалось бы на стабильности и производительности всей сети.

### Версии IP-протокола

Существует две версии протокола IP:
*   **IPv4:** Длина адреса четыре байта (32 бита). Наиболее распространенная версия, но адресное пространство практически исчерпано.
*   **IPv6:** Длина адреса шестнадцать байт (128 бит). Создана для решения проблемы нехватки IPv4-адресов.

### Структура IPv4-адреса

Длина IPv4-адреса составляет 32 бита, или 4 байта. Для удобства работы с такими адресами их делят на четыре части по восемь бит. Каждая такая часть называется **октет**. Каждый октет записывается в десятичном формате. Форма записи IP-адреса: четыре октета, разделённых точкой (например, `192.168.1.10`).

### Номер подсети и номер хоста

Одной из задач сетевого уровня является масштабирование — построение сети, которая может работать в масштабах всего мира. Для этого сетевой уровень работает не с отдельными компьютерами, а с так называемыми **подсетями**, которые объединяют несколько компьютеров. Маршрутизаторы, устройства, передающие данные на сетевом уровне, работают с подсетями, а не с отдельными IP-адресами.

IP-адрес состоит из двух частей:
1.  **Номер подсети (Network ID):** Старшие биты IP-адреса, одинаковые для всех компьютеров в одной подсети.
2.  **Номер компьютера (Host ID):** Младшие биты IP-адреса, уникальные для каждого компьютера в подсети.

Адрес подсети записывается таким образом, что в части, предназначенной для адреса хоста, указываются нули.

## Маска подсети

Маска подсети (32-битное число) — служит для разделения сетевой части (адреса подсети) и части хоста IP-адреса. Она указывает, где в IP-адресе находится адрес сети, а где адрес хоста.

**Структура маски:**
*   Там, где в IP-адресе находится номер сети, маска содержит единицы.
*   Там, где указан номер хоста, маска содержит нули.

Для того чтобы по IP-адресу и маске вычислить адрес сети, используется операция **логическое И (AND)**.

**Пример:**
-   **IP-адрес:** `192.168.1.10`
-   **Маска подсети:** `255.255.255.0`

В двоичном виде:
```
11000000.10101000.00000001.00001010  (IP-адрес)
И
11111111.11111111.11111111.00000000  (Маска)
-----------------------------------
11000000.10101000.00000001.00000000  (Адрес сети: 192.168.1.0)
```
Единицы в маске "сохраняют" соответствующую часть IP-адреса (адрес сети), а нули "обнуляют" ее (адрес хоста).

### Форматы записи маски

1.  **Десятичный (Dotted-Decimal):** `255.255.255.0`
2.  **CIDR (Classless Inter-Domain Routing) или префиксная запись:** `/24`
    Современный и более короткий формат. Число после `/` означает количество первых бит в IP-адресе, которые относятся к адресу сети. `/24` означает, что первые 24 бита (три октета) относятся к адресу сети.

### Главная практическая задача маски

Маска нужна, чтобы компьютер мог ответить на вопрос: **"Адресат находится в моей локальной сети или мне нужно отправить пакет на шлюз (роутер)?"**

-   **Сценарий 1: Общение в одной сети:**
    1.  Ваш компьютер `192.168.1.10/24` хочет связаться с `192.168.1.50`.
    2.  Он вычисляет адрес сети для себя и для адресата: `192.168.1.0`.
    3.  Адреса сетей совпадают. Вывод: "Мы в одной сети". Компьютер отправит пакет напрямую (используя [ARP](./arp_protocol.md) для определения MAC-адреса).

-   **Сценарий 2: Общение с внешней сетью:**
    1.  Ваш компьютер `192.168.1.10/24` хочет связаться с `8.8.8.8`.
    2.  Адреса сетей не совпадают (`192.168.1.0` vs `8.8.8.0`). Вывод: "Адресат в другой сети".
    3.  Компьютер отправит пакет на **шлюз по умолчанию** (роутер), чтобы тот переслал его дальше.

## Специальные и частные IP-адреса

В сетях TCP/IP существуют зарезервированные адреса и диапазоны, которые выполняют специальные функции и не используются для идентификации уникальных хостов в глобальном интернете.

### Специальные адреса

| Адрес / Диапазон | Название | Основное назначение и описание |
| :--- | :--- | :--- |
| **`127.0.0.1`** | **Loopback / localhost** | **"Адрес для себя"**. Это специальный адрес, который всегда указывает на ваш собственный компьютер. Трафик, отправленный на `127.0.0.1`, никогда не покидает пределы машины. |
| **`0.0.0.0`** | **Unspecified Address** | Немаршрутизируемый мета-адрес для обозначения "любого" или "всех" IP-адресов на локальной машине. Когда сервер "слушает" порт на `0.0.0.0`, он принимает соединения с любого сетевого интерфейса. |

### Частные (приватные) сети (RFC 1918)

Эти диапазоны предназначены для использования в локальных сетях (LAN) и не маршрутизируются в интернете. Для выхода в интернет с таких адресов используется [NAT](./nat.md).

*   **`10.0.0.0/8`**: `10.0.0.0` - `10.255.255.255`
*   **`172.16.0.0/12`**: `172.16.0.0` - `172.31.255.255`
*   **`192.168.0.0/16`**: `192.168.0.0` - `192.168.255.255`

### Другие зарезервированные диапазоны

*   **Адреса для документации и примеров (RFC 5737):** `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`.
*   **Многоадресная рассылка (Multicast):** `224.0.0.0/4`.
*   **Carrier-Grade NAT (RFC 6598):** `100.64.0.0/10`.

## Исторический взгляд: Классы IP-адресов (устаревший подход)

Ранее для определения границ сети и хоста использовались **классы IP-адресов (A, B, C)**. Этот метод был негибким и приводил к неэффективному расходованию адресов. Он был заменен бесклассовой маршрутизацией (CIDR) и масками подсети переменной длины (VLSM).

| Класс | Начальные биты | Диапазон адресов | Сеть | Хост |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `0`... | `0.0.0.0` - `127.255.255.255` | 1 октет | 3 октета |
| **B** | `10`... | `128.0.0.0` - `191.255.255.255` | 2 октета | 2 октета |
| **C** | `110`... | `192.0.0.0` - `223.255.255.255` | 3 октета | 1 октет |
