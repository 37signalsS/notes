## Определения

**IP-адрес (Internet Protocol Address)** — это уникальный числовой идентификатор устройства в компьютерной сети, работающей по протоколу IP. Он используется на [сетевом уровне (L3)](../OSI_TCP_IP_Model/Network_layer/Concepts/network_layer_overview.md) для маршрутизации пакетов и их доставки конечному узлу. В отличие от [MAC-адресов](../Concepts/mac_address.md), которые жестко привязаны к физическому оборудованию, IP-адреса являются логическими и могут назначаться динамически.

В рамках одной подсети существуют три фундаментальных типа адресов:

* **Адрес сети (Network Address):** Идентификатор всей сети или подсети. Он используется маршрутизаторами для построения таблиц маршрутизации. Этот адрес является первым в диапазоне и имеет нулевые биты в хостовой части. **Его нельзя назначать устройствам.**
* **Адрес хоста (Host Address):** Уникальный IP-адрес, который назначается сетевому интерфейсу конкретного устройства (компьютера, сервера, принтера). Это рабочие адреса, используемые для обмена данными.
* **Широковещательный адрес (Broadcast Address):** Специальный адрес для отправки сообщения **всем** устройствам в пределах одной подсети. Это последний адрес в диапазоне, у которого все биты хостовой части установлены в единицу. **Его также нельзя назначать устройствам.**

## Основные концепции

### Версии протокола

* **IPv4:** Длина адреса — 4 байта (32 бита). Наиболее распространенная версия, но адресное пространство практически исчерпано.
* **IPv6:** Длина адреса — 16 байт (128 бит). Создана для решения проблемы нехватки IPv4-адресов.

### Структура IPv4-адреса

Длина IPv4-адреса составляет 32 бита, или 4 байта. Для удобства работы с такими адресами их делят на четыре части по восемь бит. Каждая такая часть называется **октет**. Каждый октет записывается в десятичном формате. Форма записи IP-адреса: четыре октета, разделённых точкой (например, `192.168.1.10`).

### Компоненты IP-адреса

IP-адрес логически делится на две части для обеспечения масштабируемости сетей:

1. **Номер подсети (Network ID):** Старшие биты, одинаковые для всех устройств в одной подсети. Маршрутизаторы оперируют именно этими адресами.
2. **Номер хоста (Host ID):** Младшие биты, уникальные для каждого устройства в пределах подсети.

### Маска подсети (Subnet Mask)

Маска подсети — это 32-битное число, которое используется для разделения IP-адреса на сетевую и хостовую части.

* **Структура:** Единицы в маске соответствуют сетевой части адреса, нули — хостовой.
* **Назначение:** Определить, какие биты в IP-адресе относятся к сети, а какие — к хосту.

#### Форматы записи маски

1. **Десятичный (Dotted-Decimal):** `255.255.255.0`
2. **Префиксный (CIDR):** `/24`. Число после слэша означает количество бит, отведенных под сетевую часть. Это современный и наиболее распространенный формат.

### Time To Live (TTL)

**Time To Live (TTL)** — это 8-битный счётчик в заголовке IP-пакета, который предотвращает бесконечное "блуждание" пакетов в сети из-за петель маршрутизации. Каждый маршрутизатор, обрабатывая пакет, уменьшает TTL на единицу. Когда TTL достигает нуля, пакет уничтожается, а отправителю, как правило, возвращается ICMP-сообщение "Time Exceeded".

## Практические сценарии

### Определение адреса сети

Чтобы вычислить адрес сети, необходимо применить побитовую операцию **логическое И (AND)** к IP-адресу и маске подсети.

**Пример:**

* **IP-адрес:** `192.168.1.10`
* **Маска подсети:** `255.255.255.0` (`/24`)

В двоичном виде:

```
11000000.10101000.00000001.00001010  (IP-адрес)
AND
11111111.11111111.11111111.00000000  (Маска)
-----------------------------------
11000000.10101000.00000001.00000000  (Адрес сети: 192.168.1.0)
```

Единицы в маске "сохраняют" сетевую часть IP-адреса, а нули "обнуляют" хостовую.

### Принятие решения о маршрутизации (Главная задача маски)

Маска позволяет компьютеру ответить на ключевой вопрос: **"Адресат находится в моей локальной сети или нужно отправить пакет на шлюз по умолчанию?"**

* **Сценарий 1: Общение в одной сети**
    1. Компьютер `192.168.1.10/24` хочет отправить пакет на `192.168.1.50`.
    2. Он вычисляет адрес сети для себя (`192.168.1.0`) и для адресата (`192.168.1.0`).
    3. Адреса сетей совпадают. Вывод: "Мы в одной сети". Пакет будет отправлен напрямую (с использованием [ARP](./arp.md) для нахождения MAC-адреса).

* **Сценарий 2: Общение с внешней сетью**
    1. Компьютер `192.168.1.10/24` хочет отправить пакет на `8.8.8.8`.
    2. Адреса сетей не совпадают (`192.168.1.0` vs `8.8.8.0`). Вывод: "Адресат в другой сети".
    3. Пакет будет отправлен на **шлюз по умолчанию** (роутер), который перенаправит его дальше.

## Дополнительная информация

### IANA (Internet Assigned Numbers Authority)

**IANA** — организация, отвечающая за распределение IP-адресов и поддержку стандартов IPv4/IPv6. IANA выделяет диапазоны адресов региональным регистратурам (RIR), а также резервирует специальные диапазоны для конкретных целей.

Все специальные диапазоны адресов документированы в **RFC** (Request for Comments) — стандартах интернета.

### Специальные и частные IP-адреса

| Адрес / Диапазон | Название | Описание и назначение |
| :--- | :--- | :--- |
| **`127.0.0.1`** | **Loopback / localhost** | Адрес "для себя", всегда указывающий на собственный компьютер. Трафик на `127.0.0.1` не покидает пределы машины. |
| **`0.0.0.0`** | **Unspecified Address** | Немаршрутизируемый мета-адрес для обозначения "любого" или "всех" IP-адресов. Используется серверами для приема соединений на всех сетевых интерфейсах. |
| **`0.0.0.0/8`** | **This network** | Используется только как адрес источника, когда устройство ещё не знает свой IP (например, при DHCP-запросе). |
| **`169.254.0.0/16`** | **Link-local (APIPA)** | Автоматическая конфигурация при отсутствии DHCP-сервера. Адреса назначаются случайно из этого диапазона. |

#### Частные (приватные) сети (RFC 1918)

Эти диапазоны предназначены для локальных сетей (LAN) и не маршрутизируются в интернете. Для доступа в интернет с таких адресов используется [NAT](../Concepts/nat.md).

* `10.0.0.0/8` (`10.0.0.0` - `10.255.255.255`)
* `172.16.0.0/12` (`172.16.0.0` - `172.31.255.255`)
* `192.168.0.0/16` (`192.168.0.0` - `192.168.255.255`)

#### Другие зарезервированные диапазоны

* **Адреса для документации и примеров (RFC 5737):** `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`.
* **Многоадресная рассылка (Multicast):** `224.0.0.0/4`.
* **Carrier-Grade NAT (RFC 6598):** `100.64.0.0/10`.

### Исторический взгляд: Классовая адресация (устаревший подход)

Ранее для определения границ сети и хоста использовались **классы IP-адресов (A, B, C)**. Этот метод был негибким, приводил к неэффективному расходованию адресов и был заменен бесклассовой маршрутизацией (CIDR).

| Класс | Начальные биты | Диапазон адресов | Сеть | Хост |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `0...` | `0.0.0.0` - `127.255.255.255` | 1 октет | 3 октета |
| **B** | `10...` | `128.0.0.0` - `191.255.255.255` | 2 октета | 2 октета |
| **C** | `110...` | `192.0.0.0` - `223.255.255.255` | 3 октета | 1 октет |
