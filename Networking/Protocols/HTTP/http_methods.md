# HTTP Методы

## Обзор методов HTTP

| Метод | Назначение | Идемпотентность | Кэширование | Безопасный |
|---|---|---|---|---|
| **GET** | Получение данных (Read) | Да | Да | Да |
| **POST** | Создание ресурса (Create) | Нет | Нет | Нет |
| **PUT** | Полное обновление (Update) | Да | Нет | Нет |
| **PATCH** | Частичное обновление | Нет | Нет | Нет |
| **DELETE** | Удаление ресурса (Delete) | Да | Нет | Нет |
| **HEAD** | Запрос без тела ответа | Да | Да | Да |
| **OPTIONS** | Проверка доступных методов | Да | Да | Да |
| **CONNECT** | Создание туннеля | Нет | Нет | Нет |
| **TRACE** | Диагностика пути запроса | Да | Нет | Да |

## Детальное описание методов

### GET — получение данных

Используется для запроса ресурсов: страниц, карточек товаров, списков пользователей. Метод не должен изменять данные на сервере.

**Характеристики:**
- Идемпотентен (многократное выполнение не меняет состояние)
- Может быть закэширован
- Остаётся в истории браузера, может быть закладкой
- Имеет ограниченную длину URL
- Не должен использоваться для передачи конфиденциальных данных

### POST — создание ресурса

Применяется для отправки данных на сервер: создание заявок, пользователей, заказов, комментариев.

**Характеристики:**
- Не идемпотентен (повтор может создать дубликаты)
- Не кэшируется
- Не остаётся в истории браузера
- Нет ограничений по длине запроса
- Вызывает изменение состояния на сервере

### PUT — полное обновление

Сервер получает новую полную версию объекта и заменяет ею текущую. Используется для обновления ресурса целиком.

**Характеристики:**
- Идемпотентен
- Заменяет весь ресурс
- Может создать ресурс, если он не существует

### PATCH — частичное обновление

Подходит для точечного обновления: изменение имени пользователя, статуса заказа, одного параметра настройки.

**Характеристики:**
- Не идемпотентен (зависит от реализации)
- Обновляет только указанные поля
- Эффективнее PUT при частичных изменениях

### DELETE — удаление ресурса

Клиент сообщает серверу, что объект нужно удалить: пользователь, запись, файл, товар из каталога.

**Характеристики:**
- Идемпотентен
- Удаляет указанный ресурс
- Может вернуть `200 OK`, `204 No Content` или `404 Not Found`

### HEAD — запрос без тела ответа

Работает как GET, но сервер возвращает только заголовки.

**Применение:**
- Проверка доступности ресурса
- Получение даты изменения
- Проверка размера файла без загрузки содержимого

### OPTIONS — проверка доступных действий

Позволяет узнать, какие методы поддерживаются для конкретного ресурса.

**Применение:**
- CORS предварительные запросы (preflight)
- Определение возможностей API

### CONNECT — создание туннеля

Используется для установки соединения через прокси-сервер.

**Применение:**
- HTTPS-трафик через HTTP-прокси
- SSL/TLS туннелирование

### TRACE — диагностический запрос

Возвращает запрос обратно клиенту для проверки пути через промежуточные узлы.

**Применение:**
- Отладка сетевых проблем
- Обнаружение модификаций запроса
- На практике используется редко из-за рисков безопасности
