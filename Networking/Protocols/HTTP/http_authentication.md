# HTTP Аутентификация

## Методы HTTP-аутентификации

### 1. Базовая аутентификация (Basic Authentication)

**Принцип работы:**

1. **Первоначальный запрос:**
    * Клиент делает запрос к защищенному ресурсу без учетных данных.
2. **Ответ сервера:**
    * Сервер отвечает статусом `401 Unauthorized`.
    * В ответ добавляется заголовок `WWW-Authenticate: Basic realm="<Имя области защиты>"`, где `realm` — это описание защищенной области, которое браузер показывает пользователю.
3. **Ответ клиента:**
    * Браузер отображает встроенную форму для ввода логина и пароля.
    * После ввода данных формируется новый запрос с заголовком `Authorization`.
    * Учетные данные кодируются в формате `base64(имя_пользователя:пароль)`, и значение заголовка выглядит так: `Authorization: Basic <закодированная_строка>`.

**Безопасность:** Данные передаются в закодированном, но **не в зашифрованном** виде, поэтому их легко перехватить и декодировать. Использовать базовую аутентификацию можно **только** в сочетании с HTTPS, который обеспечивает шифрование всего канала связи.

### 2. Дайджест-аутентификация (Digest Authentication)

* **Принцип:** Использует алгоритм MD5 для хеширования пароля, случайного значения (`nonce`) от сервера и других данных. Это позволяет доказать знание пароля, не передавая его по сети.

### 3. Аутентификация на основе форм (Form-based Authentication)

* **Принцип:** Пользователь вводит учетные данные в HTML-форму. Данные отправляются `POST`-запросом на сервер, который проверяет их и, в случае успеха, создает сессию (обычно с помощью Cookies).

### 4. Токены (Bearer Token)

* **Принцип:** После успешного входа сервер выдает временный **токен** (например, JWT). Клиент должен передавать этот токен с каждым последующим запросом в заголовке `Authorization: Bearer <токен>`.

### 5. Cookies

Сервер может использовать куки для хранения сессионной информации. Атрибут `HttpOnly` защищает куки от доступа через JavaScript, что повышает безопасность.

### 6. Single Sign-On (SSO)

Механизм, позволяющий пользователю проходить аутентификацию один раз для доступа ко множеству приложений. Подробнее см. [SSO (Single Sign-On)](../../Security/Concepts/authentication_vs_authorization.md#федеративная-идентификация-federated-identity-и-sso-single-sign-on).
