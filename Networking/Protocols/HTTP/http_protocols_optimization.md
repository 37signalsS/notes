# HTTP Performance Optimization

## Definitions

**HTTP-оптимизация** — выбор и настройка версий HTTP-протокола и сопутствующих технологий для минимизации задержек (latency) и ускорения доставки контента.

Подробное сравнение версий протокола — в [эволюции HTTP](./http_versions.md).

## Basic Concepts

### Head-of-Line (HOL) Blocking

Явление, при котором медленный или потерянный пакет задерживает все последующие данные в соединении.

- **Уровень приложения (HTTP/1.1):** один запрос за раз по TCP-соединению. Частично решается множественными TCP-соединениями.
- **Транспортный уровень (TCP):** [HTTP/2](./http_versions.md#http2-2015) решает проблему мультиплексированием, но потеря одного TCP-пакета блокирует все стримы до ретрансмиссии.
- **Решение в [HTTP/3](./http_versions.md#http3-2022):** [QUIC](./http_versions.md#http3-2022) на базе UDP — потеря пакета в одном стриме не влияет на остальные.

### Затраты на установку соединения

Каждое новое TCP-соединение требует времени (RTT — Round-Trip Time):

1. **TCP Handshake:** 1 RTT
2. **TLS Handshake:** 1–2 RTT (подробнее: [TLS](../tls.md))

**Решения:**

- **HTTP Keep-Alive & Connection Pooling:** переиспользование установленных TCP+TLS соединений для последовательных запросов.
- **QUIC (HTTP/3):** объединяет TCP-рукопожатие и TLS 1.3 в один процесс — 1 RTT или 0-RTT для повторных подключений.

## Practical Scenarios

### Сценарий 1: Публичный веб-сайт / API

**Цель:** быстрая загрузка для всех пользователей, включая мобильных.

**Рекомендации:**

1. **Включить HTTP/2 и HTTP/3.** Примеры настройки: [Конфигурация HTTP/2/HTTP/3 в Nginx](../../../WebServers/Nginx/Performance/nginx_http_versions.md).
2. **Активировать TLS 1.3** — быстрее и безопаснее, обязателен для HTTP/3.
3. **Использовать HTTP Keep-Alive** — настроить разумные таймауты (`keepalive_timeout` в Nginx).
4. **Настроить DNS-запись типа HTTPS** для решения проблемы «холодного старта» HTTP/3:

   ```dns
   example.com HTTPS 1 . alpn="h2,h3"
   ```

   Подробнее: [DNS-записи HTTPS/SVCB](../DNS/dns_records.md).

**Проблема «холодного старта» HTTP/3:**

- **Без HTTPS-записи:** первый запрос → HTTP/2, сервер отправляет `Alt-Svc: h3=":443"; ma=86400`, последующие → HTTP/3.
- **С HTTPS-записью:** DNS-запрос возвращает A + HTTPS записи, первый запрос → HTTP/3 (QUIC).
- **Фактическое поведение браузеров (2025):** даже при HTTPS-записи возможны первые 1–2 запроса по HTTP/2 из-за возможной блокировки QUIC провайдером.

### Сценарий 2: Микросервисы (внутри дата-центра)

**Цель:** минимизация задержек при интенсивном обмене в доверенной низколатентной сети.

**Рекомендации:**

1. **Connection Pooling** — постоянные соединения между сервисами для избежания затрат на рукопожатия.
2. **gRPC поверх HTTP/2** — эффективное использование мультиплексирования и потоковой передачи.
3. **Circuit Breaker** — быстрое обнаружение недоступных сервисов, предотвращение каскадных сбоев.

### Сценарий 3: Мобильные клиенты

**Цель:** стабильная работа при нестабильной сети (переключение Wi-Fi ↔ сотовая связь, потери пакетов).

**Рекомендации:**

1. **Предпочесть HTTP/3** — connection migration сохраняет сессию при смене IP без переустановки соединения.
2. **Агрессивный Keep-Alive** при недоступности HTTP/3 для поддержания активного соединения.
