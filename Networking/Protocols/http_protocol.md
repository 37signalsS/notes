# Протокол HTTP (Hypertext Transfer Protocol)

HTTP (Hypertext Transfer Protocol) — протокол передачи гипертекста, который является основой Всемирной паутины (World Wide Web). Он определяет правила, по которым веб-клиенты (например, браузеры) и веб-серверы взаимодействуют для обмена информацией.

## История и ключевые концепции

Концепция HTTP была предложена Тимом Бернерсом-Ли из ЦЕРН в 1989 году. Он также предложил четыре ключевых компонента, которые легли в основу Веба:
1.  **HTML (Hypertext Markup Language):** Язык гипертекстовой разметки страниц.
2.  **HTTP (Hypertext Transfer Protocol):** Протокол передачи гипертекстовых страниц.
3.  **Веб-сервер:** Программа, на которой размещаются страницы в формате HTML.
4.  **Текстовый веб-браузер:** Программа для подключения к веб-серверам и отображения страниц. Изначально браузеры показывали только текст, но со временем стали поддерживать изображения, видео, аудио и другие ресурсы.

### Гипертекст

**Гипертекст** — это текст, который содержит разметку, указывающую, как отображать или обрабатывать фрагменты текста, а также включающую гиперссылки. Гиперссылки позволяют легко переходить с одной страницы на другую, обеспечивая легкую связанность информации и способствуя популярности Веба.

### URL (Uniform Resource Locator)

**URL (единообразный определитель местонахождения ресурса)** играет важную роль в Вебе. Он определяет, где именно находится страница или другой ресурс. URL вставляются в гиперссылки для связи страниц.

URL состоит из нескольких основных частей:
1.  **Протокол:** Например, `http://` или `https://`.
2.  **Адрес сервера:** Может быть доменным именем (например, `example.com`) или IP-адресом.
3.  **Адрес страницы/ресурса:** Конкретный путь к запрашиваемой странице или файлу на сервере (например, `/path/to/page.html`).

Помимо HTML-страниц, URL может использоваться для текстовых файлов, изображений, видео и других типов файлов.

## Версии протокола HTTP

HTTP прошел несколько этапов развития:
*   **HTTP/0.9 (1991):** Экспериментальная версия, использовавшаяся внутри ЦЕРН.
*   **HTTP/1.0 (1996):** Первая официальная версия.
*   **HTTP/1.1 (1997):** Расширение HTTP/1.0, добавившее кэширование, постоянные соединения (Keep-Alive) и механизмы аутентификации. Эта версия до сих пор широко используется.
*   **HTTP/2 (2015):** Обновленная версия, направленная на повышение производительности и безопасности за счет мультиплексирования, сжатия заголовков и работы поверх TCP с обязательным использованием TLS.
*   **HTTP/3 (2022):** Современная версия, вышедшая в 2022 году. Решает проблемы HTTP/2, переходя на транспортный протокол QUIC, который работает поверх UDP. Обеспечивает еще большую производительность и устойчивость к потерям пакетов.

## Модель "Запрос-Ответ"

Протокол HTTP работает по модели "запрос-ответ":
*   **Клиент** (как правило, веб-браузер) отправляет запрос на сервер (например, запрос на веб-страницу).
*   **Сервер** обрабатывает запрос и отправляет ответ, который содержит запрошенную информацию.

HTTP использует протокол TCP на транспортном уровне, что гарантирует надежную доставку данных. Веб-серверы обычно используют порт **80** для HTTP-трафика (и 443 для HTTPS).

## Структура HTTP-запроса

HTTP-запрос, особенно в версиях HTTP/1.0 и HTTP/1.1, которые используют текстовый режим работы, состоит из трех основных частей:
1.  **Стартовая строка (Request Line):**
2.  **Заголовки (Headers):**
3.  **Тело сообщения (Body):** (Необязательная часть).

### Стартовая строка запроса

Состоит из трех элементов:
*   **Метод HTTP:** Указывает тип действия, которое клиент хочет выполнить над ресурсом (например, `GET`).
*   **URI (Uniform Resource Identifier):** Идентифицирует запрашиваемый ресурс (например, `/index.html` или `/`).
*   **Версия протокола:** Указывает версию используемого HTTP-протокола (например, `HTTP/1.1`).

Пример: `GET /courses HTTP/1.1`

### Заголовки запроса (Headers)

Передают дополнительную информацию о клиенте, типе контента, поддерживаемых кодировках и т.д. Формат: `Название-Заголовка: Значение`.

*   **Host:** Является **обязательным** заголовком в HTTP/1.1. Указывает доменное имя веб-сервера, к которому обращается клиент. Это необходимо, так как современные серверы на одном IP-адресе могут обслуживать несколько доменных имен (виртуальные хосты).
    Пример: `Host: example.com`
*   `User-Agent`: Информация о браузере клиента.
*   `Accept-Encoding`: Поддерживаемые методы сжатия.

### Тело запроса (Body)

Содержит данные, отправляемые клиентом на сервер. Используется, например, для `POST`-запросов при отправке форм или JSON-данных. Для `GET`-запросов тело, как правило, отсутствует.

### HTTP-методы

Веб-сервер выполняет разные действия в зависимости от полученного HTTP-метода:

| Метод | Описание |
|---|---|
| **GET** | Запрашивает ресурс с сервера. Используется для получения данных (например, веб-страницы, изображения). |
| **POST** | Отправляет данные на сервер. Часто используется для отправки форм или создания новых ресурсов. |
| **HEAD** | Запрашивает только заголовки ответа, аналогичные `GET`, но без тела сообщения. Полезно для проверки существования ресурса или его метаданных. |
| **PUT** | Используется для помещения (создания или полного обновления) ресурса на сервер по указанному URI. |
| **DELETE** | Удаляет указанный ресурс с сервера. |
| **OPTIONS** | Запрашивает информацию о методах HTTP, поддерживаемых сервером для указанного ресурса. |

На практике чаще всего используются `GET` и `POST`.

## Структура HTTP-ответа

HTTP-ответ сервера клиенту также состоит из трех частей:
1.  **Строка состояния (Status Line):**
2.  **Заголовки (Headers):**
3.  **Тело сообщения (Body):** (Необязательная часть).

### Строка состояния

Состоит из трех элементов:
*   **Версия протокола:** (например, `HTTP/1.1`).
*   **Код состояния:** Трехзначное число, указывающее результат выполнения запроса (например, `200`).
*   **Текстовое описание:** Краткое пояснение кода состояния (например, `OK`).

Пример: `HTTP/1.1 200 OK`

### Заголовки ответа (Headers)

Передают дополнительную информацию о сервере, типе возвращаемого контента, кэшировании и т.д.

*   `Server`: Информация о программном обеспечении веб-сервера.
*   `Content-Type`: MIME-тип содержимого тела ответа (например, `text/html; charset=utf-8`).
*   `Content-Length`: Размер тела ответа в байтах.

### Тело ответа (Body)

Содержит запрошенные данные (например, HTML-страницу, изображение, JSON-данные).

### Коды состояния HTTP

Коды состояния HTTP — это трехзначные числа, сгруппированные в пять классов по первой цифре:

| Код | Категория | Описание | Примеры |
|---|---|---|---|
| **1xx** | Информационные | Запрос принят, процесс продолжается. | `100 Continue`, `101 Switching Protocols` |
| **2xx** | Успешные | Запрос успешно получен, понят и обработан. | `200 OK` (успешный запрос), `201 Created` |
| **3xx** | Перенаправление | Для завершения запроса требуется дополнительное действие. | `301 Moved Permanently` (постоянное перенаправление), `302 Found` (временное перенаправление) |
| **4xx** | Ошибка клиента | Запрос содержит синтаксическую ошибку или не может быть выполнен. | `403 Forbidden` (доступ запрещен), `404 Not Found` (ресурс не найден) |
| **5xx** | Ошибка сервера | Сервер не смог выполнить запрос из-за своей ошибки. | `500 Internal Server Error` (внутренняя ошибка сервера), `501 Not Implemented` (метод не реализован) |

## Ручное взаимодействие с HTTP (текстовый режим)

Поскольку HTTP/1.1 и более ранние версии являются текстовыми протоколами, с ними можно взаимодействовать напрямую через терминал, используя утилиты вроде `telnet`. Это позволяет наглядно увидеть "сырой" обмен сообщениями.

**Пример запроса к `netcourse.ru` на порт 80:**

1.  **Подключение к серверу:**
    ```bash
    telnet netcourse.ru 80
    ```
2.  **Отправка HTTP-запроса (вводятся вручную, завершаются двойным Enter):**
    ```http
    GET / HTTP/1.1
    Host: netcourse.ru

    ```
    *   `GET / HTTP/1.1`: Запрос корневой страницы по HTTP/1.1.
    *   `Host: netcourse.ru`: Обязательный заголовок для HTTP/1.1.

3.  **Получение HTTP-ответа:**
    ```http
    HTTP/1.1 200 OK
    Server: GitHub.com
    Content-Type: text/html; charset=utf-8
    Content-Length: 236

    <!DOCTYPE html>
    <html>
    <head>
    <title>Netcourse</title>
    ... (HTML-содержимое страницы) ...
    </html>
    ```
    Сервер отвечает строкой состояния `HTTP/1.1 200 OK`, заголовками (`Server`, `Content-Type`, `Content-Length`) и телом сообщения (HTML-код страницы).

## От HTTP/1.1 к HTTP/2 и HTTP/3

Современный Веб стал значительно сложнее, чем тот, который был задуман Тимом Бернерсом-Ли. Веб-страницы содержат не только текст, но и множество других ресурсов: изображения, видео, таблицы стилей (CSS), JavaScript-коды. Чтобы показать одну страницу, браузеру часто приходится загружать десятки или сотни таких файлов. Кроме того, веб-серверы всё чаще используют программы для динамической генерации страниц.

Протокол HTTP/1.1, несмотря на свои улучшения, имеет ограничения, такие как блокировка начала очереди (Head-of-Line Blocking) на уровне TCP, из-за которой ресурсы загружаются последовательно в рамках одного TCP-соединения, что замедляет отображение сложных страниц.

Для решения этих проблем и обеспечения более эффективной работы с современными веб-приложениями были разработаны HTTP/2 и HTTP/3, которые перешли на бинарный режим работы и используют более продвинутые механизмы мультиплексирования и транспортировки данных.

HTTP также широко используется не только для передачи гипертекста, но и для взаимодействия программ через API (Application Programming Interface).
