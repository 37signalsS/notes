# IP-адресация

## Определения

**IP-адрес (Internet Protocol Address)** — уникальный числовой идентификатор устройства в компьютерной сети, работающей по протоколу IP. Используется на сетевом уровне (L3) для маршрутизации пакетов и идентификации узлов.

**Подсеть (Subnet)** — логическая группа IP-адресов в пределах одной сети, объединенная общей маской. Сегментация на подсети позволяет ограничить широковещательный трафик и повысить безопасность.

**Маска подсети (Subnet Mask)** — 32-битное (для IPv4) число, определяющее, какая часть IP-адреса относится к идентификатору сети, а какая — к идентификатору конкретного хоста.

**Шлюз по умолчанию (Default Gateway)** — сетевой узел (обычно роутер), на который отправляются пакеты, если адрес назначения находится за пределами текущей локальной подсети.

**Хост (Host)** — любое оконечное устройство в сети (компьютер, сервер, сетевой интерфейс), имеющее уникальный IP-адрес.

## Основные концепции

### Версии IP-протокола

| Характеристика | IPv4 | IPv6 |
| :--- | :--- | :--- |
| **Размер адреса** | 32 бита (4 байта) | 128 бит (16 байт) |
| **Количество адресов** | ~4,3 млрд ($2^{32}$) | ~$3,4 \times 10^{38}$ ($2^{128}$) |
| **Формат записи** | Десятичный (например, `192.168.1.1`) | Шестнадцатеричный (например, `2001:db8::1`) |
| **Статус** | Дефицит адресов, использование NAT | Современный стандарт, встроенный IPsec |

Подробнее: **[Обзор IP-адресации](./ip_overview.md)** и **[Протокол IPv6](../ipv6_overview.md)**.

### Методы передачи данных

1. **Unicast (Одноадресная рассылка):** Передача данных от одного отправителя одному получателю. Самый распространенный тип трафика.
2. **Broadcast (Широковещательная рассылка):** Отправка пакета всем узлам в пределах одной подсети (только для IPv4).
3. **Multicast (Многоадресная рассылка):** Передача группе узлов, подписанных на определенный адрес (в IPv6 заменяет Broadcast).
4. **Anycast (Anycast-рассылка):** Доставка пакета ближайшему (по метрикам маршрутизации) узлу из группы серверов с одинаковым IP. Используется в DNS и CDN.

### Публичные и приватные адреса

- **Публичные (белые):** Уникальны в глобальном интернете, маршрутизируются повсеместно.
- **Приватные (серые):** Используются во внутренних сетях, описаны в **RFC 1918**. Не маршрутизируются в интернете без [NAT](../../Concepts/nat/overview.md).

| Диапазон (RFC 1918) | Префикс | Количество адресов |
| :--- | :--- | :--- |
| `10.0.0.0` — `10.255.255.255` | `10.0.0.0/8` | 16,777,216 |
| `172.16.0.0` — `172.31.255.255` | `172.16.0.0/12` | 1,048,576 |
| `192.168.0.0` — `192.168.255.255` | `192.168.0.0/16` | 65,536 |

### Способы назначения IP-адресов

- **Статическое (Static):** Ручное прописывание параметров в ОС. Используется для серверов и сетевого оборудования.
- **Динамическое (DHCP):** Автоматическое получение адреса от сервера. Подробнее: **[Протокол DHCP](../DHCP/dhcp_overview.md)**.
- **Автоконфигурация (SLAAC):** Механизм IPv6, позволяющий хосту самостоятельно сгенерировать адрес на основе префикса сети и MAC-адреса.

### Структура адреса и CIDR

IP-адрес делится на две части: **Network ID** (сетевая часть) и **Host ID** (хостовая часть).
**CIDR (Classless Inter-Domain Routing)** — запись маски через количество бит (префикс). Например, `/24` соответствует маске `255.255.255.0`.

## Практические сценарии

### Расчет параметров подсети (Метод магического числа)

Для IP `192.168.1.130/26`:
1. **Маска:** `/26` → `255.255.255.192`.
2. **Шаг сети:** $256 - 192 = 64$.
3. **Адрес сети:** Ближайшее к 130 кратное 64 число, меньшее 130 — это **128** (`192.168.1.128`).
4. **Broadcast:** Адрес перед следующей сетью (`128 + 64 - 1`) — **191** (`192.168.1.191`).
5. **Диапазон хостов:** `.129` – `.190` (62 адреса).

Подробные методы расчета: **[Методы расчета подсетей](./subnetting_calculation.md)**.

### Сегментация сети (VLSM)

Использование масок переменной длины позволяет эффективно делить адресное пространство. Например, из сети `/24` можно выделить одну сеть `/25` для офиса и две сети `/26` для серверных, минимизируя потери адресов.

### Проверка связности L2

Хосты могут общаться напрямую, если они находятся в одной подсети. Для проверки вычислите адреса сети для обоих хостов: если они совпадают, трафик пойдет по L2 через коммутатор. Если нет — потребуется маршрутизация (L3).
