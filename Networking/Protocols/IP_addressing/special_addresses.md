# Специальные и частные IP-адреса

## Определения

**IANA (Internet Assigned Numbers Authority)** — организация, отвечающая за распределение IP-адресов и поддержку стандартов IPv4/IPv6. IANA выделяет диапазоны адресов региональным регистратурам (RIR) и резервирует специальные диапазоны для конкретных целей.

**RFC (Request for Comments)** — стандарты интернета, документирующие все специальные диапазоны IP-адресов.

**Частные (private) IP-адреса** — «серые» адреса, не маршрутизируемые в глобальной сети. Для IPv4 они описаны в **RFC 1918**, для IPv6 — в **RFC 4193** (ULA). Для доступа в интернет используется технология [NAT](../../Concepts/nat/overview.md).

## Основные концепции

### Loopback-адреса (Локальная петля)

Адреса «для себя», всегда указывающие на собственный компьютер. Трафик на эти адреса не покидает пределы машины.

| Версия | Адрес / Префикс | Описание |
| :--- | :--- | :--- |
| **IPv4** | `127.0.0.1` | Стандартный localhost. Резервируется вся сеть `127.0.0.0/8`. |
| **IPv6** | `::1/128` | Эквивалент в IPv6. |

Подробности: [Сетевые интерфейсы в Linux](../../../Linux/Networking/Concepts/linux_network_interfaces.md#2-виртуальные-интерфейсы).

### Unspecified Address (Неуказанный адрес)

Используется хостом до того, как он получит собственный IP-адрес, или серверами для прослушивания всех интерфейсов.

| Версия | Адрес / Префикс | Описание |
| :--- | :--- | :--- |
| **IPv4** | `0.0.0.0` | Означает «любой адрес» или «все интерфейсы». |
| **IPv6** | `::` | Эквивалент в IPv6. |

### This Network (Текущая сеть)

`0.0.0.0/8` — используется только как адрес источника, когда устройство ещё не знает свой IP (например, при [DHCP-запросе](../DHCP/dhcp_overview.md)).

### Default Route (Маршрут по умолчанию)

Маршрут, используемый для всех пакетов, для которых нет явного пути в таблице маршрутизации.

| Версия | Префикс | Описание |
| :--- | :--- | :--- |
| **IPv4** | `0.0.0.0/0` | Маршрут «в мир». |
| **IPv6** | `::/0` | Аналог в IPv6. |

Подробности: [Маршрутизация в Linux](../../../Linux/SystemAdministration/routing.md#4-маршрут-по-умолчанию-default-gateway).

### Link-Local Addresses

Адреса, действующие только в пределах одного L2-сегмента (подсети).

| Версия | Диапазон / Префикс | Описание |
| :--- | :--- | :--- |
| **IPv4 (APIPA)** | `169.254.0.0/16` | Назначается автоматически при отсутствии DHCP (**RFC 3927**). |
| **IPv6** | `fe80::/10` | **Обязательны** для каждого интерфейса; используются для NDP и служебного трафика. |

### Частные (приватные) сети

| Тип | Диапазон / Префикс | RFC | Количество хостов (IPv4) |
| :--- | :--- | :--- | :--- |
| **IPv4 Class A** | `10.0.0.0/8` | RFC 1918 | ~16,7 млн |
| **IPv4 Class B** | `172.16.0.0/12` | RFC 1918 | ~1 млн |
| **IPv4 Class C** | `192.168.0.0/16` | RFC 1918 | ~65 тыс. |
| **IPv6 ULA** | `fc00::/7` | RFC 4193 | ~$1,2 \times 10^{36}$ подсетей `/64` |

**Особенности:**
- Не маршрутизируются в интернете напрямую.
- При выходе во внешнюю сеть подменяются на публичный IP маршрутизатора (NAT).
- Один и тот же адрес (например, `192.168.1.1`) может использоваться миллионами устройств за разными NAT.

### Зарезервированные диапазоны

**Адреса для документации:** Используются в примерах и учебных материалах.

| Версия | Диапазон / Префикс | RFC |
| :--- | :--- | :--- |
| **IPv4** | `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` | RFC 5737 |
| **IPv6** | `2001:db8::/32` | RFC 3849 |

**Multicast (Групповая рассылка):**

- **IPv4:** `224.0.0.0/4` (от `224.0.0.0` до `239.255.255.255`).
- **IPv6:** `ff00::/8`.

Подробности: [MAC-адреса](../../Concepts/mac_address.md#2-групповой-multicast).

**Carrier-Grade NAT (Shared Address Space):**
- **IPv4:** `100.64.0.0/10` (**RFC 6598**). Используется провайдерами для организации NAT на уровне оператора (Double NAT). Это позволяет избежать конфликтов с частными сетями клиентов (RFC 1918).

## Практические сценарии

### Диагностика APIPA-адреса

Если команда `ip addr` показывает адрес из диапазона `169.254.x.x`, это означает, что:
1. Сетевой кабель подключен, но DHCP-сервер недоступен.
2. Пул адресов на DHCP-сервере исчерпан.
3. Проблемы с прохождением широковещательных запросов DHCP в L2-сегменте.

### Приоритет Loopback

Сервисы, настроенные на `127.0.0.1`, недоступны из внешней сети. Для предоставления доступа извне необходимо изменить `bind_address` на публичный IP или `0.0.0.0` (все интерфейсы).

### Использование CGNAT в провайдерских сетях

Когда провайдер выдает клиенту адрес из `100.64.0.0/10`, клиент находится за «двойным NAT». Это делает невозможным прямой проброс портов (Port Forwarding) без дополнительных технологий (UPnP, STUN или аренда статического публичного IP).
