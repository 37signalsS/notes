# Специальные и частные IP-адреса

## Definitions

**IANA (Internet Assigned Numbers Authority)** — организация, отвечающая за распределение IP-адресов и поддержку стандартов IPv4/IPv6. IANA выделяет диапазоны адресов региональным регистратурам (RIR) и резервирует специальные диапазоны для конкретных целей.

**RFC (Request for Comments)** — стандарты интернета, документирующие все специальные диапазоны IP-адресов.

**Частные (private) IP-адреса** — «серые» адреса из диапазонов [RFC 1918](#частные-приватные-сети-rfc-1918), не маршрутизируемые в глобальной сети. Для доступа в интернет используется [NAT](../../Concepts/nat/overview.md). В отличие от них, «белые» (публичные) IP-адреса маршрутизируются в интернете напрямую.

## Basic Concepts

### Loopback-адреса

**Loopback** (`127.0.0.1`, localhost) — адрес «для себя», всегда указывающий на собственный компьютер. Трафик на `127.0.0.1` не покидает пределы машины. Полная сеть loopback: `127.0.0.0/8`. Подробности: [Сетевые интерфейсы в Linux](../../../Linux/Networking/Concepts/linux_network_interfaces.md#2-виртуальные-интерфейсы).

### Unspecified Address

`0.0.0.0` — немаршрутизируемый мета-адрес для обозначения «любого» или «всех» IP-адресов. Серверы используют его для приёма соединений на всех сетевых интерфейсах одновременно.

### This Network

`0.0.0.0/8` — используется только как адрес источника, когда устройство ещё не знает свой IP (например, при [DHCP-запросе](../DHCP/dhcp_overview.md)).

### Default Route

`0.0.0.0/0` — маршрут по умолчанию, используемый для всех сетей, для которых нет явного маршрута. Подробности: [Маршрутизация в Linux](../../../Linux/SystemAdministration/routing.md#4-маршрут-по-умолчанию-default-gateway).

### Link-Local (APIPA)

**Диапазон:** `169.254.0.0/16` ([RFC 3927](#основные-rfc))

Автоматическая конфигурация при отсутствии DHCP-сервера. Адреса назначаются случайно из этого диапазона.

### Частные (приватные) сети (RFC 1918)

| Диапазон | Класс | Количество хостов |
|----------|-------|-------------------|
| `10.0.0.0/8` (`10.0.0.0` – `10.255.255.255`) | A | ~16,7 млн |
| `172.16.0.0/12` (`172.16.0.0` – `172.31.255.255`) | B | ~1 млн |
| `192.168.0.0/16` (`192.168.0.0` – `192.168.255.255`) | C | ~65 тыс. |

**Особенности:**

- IP-адреса из этих сетей не могут быть использованы в сети Интернет напрямую
- Свободно используются в локальных сетях: дома, в офисе, кафе, гостиницах
- Один и тот же частный IP (например, `192.168.1.1`) может одновременно использоваться миллионами устройств по всему миру за разными NAT
- При выходе в интернет частный IP подменяется на публичный IP маршрутизатора (NAT/masquerading)

### Зарезервированные диапазоны

**Адреса для документации (RFC 5737):** используются в документации, примерах конфигураций и тестировании:

- `192.0.2.0/24` (TEST-NET-1)
- `198.51.100.0/24` (TEST-NET-2)
- `203.0.113.0/24` (TEST-NET-3)

**Multicast:** диапазон `224.0.0.0/4` (`224.0.0.0` – `239.255.255.255`) — групповая рассылка пакетов нескольким получателям одновременно. Подробности: [MAC-адреса](../../Concepts/mac_address.md#2-групповой-multicast).

**Carrier-Grade NAT (RFC 6598):** диапазон `100.64.0.0/10` (`100.64.0.0` – `100.127.255.255`) — используется провайдерами для NAT на уровне оператора связи.

## Practical Scenarios

### Когда устройство получает APIPA-адрес

При недоступности DHCP-сервера устройство автоматически назначает себе адрес из `169.254.0.0/16`. Это сигнал о проблеме: DHCP-сервер недоступен или пул адресов исчерпан. Диагностика: `ipconfig` / `ip addr` покажет адрес `169.254.x.x`.

### Повторное использование частных IP

Миллионы локальных сетей по всему миру используют `192.168.1.1` как адрес шлюза. Конфликтов не возникает — NAT на границе каждой сети транслирует частный адрес в уникальный публичный.

### Документационные адреса

При написании руководств, примеров конфигураций или тестов следует использовать диапазоны TEST-NET (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`), а не реальные адреса — это гарантирует отсутствие конфликтов и недоразумений.
