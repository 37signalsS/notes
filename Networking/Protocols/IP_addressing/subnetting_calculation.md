# Расчет параметров подсети (Subnetting)

## Определения

**Адрес сети (Network Address)** — идентификатор всей подсети. Это первый адрес в диапазоне, у которого все биты хостовой части равны нулю. Используется маршрутизаторами для принятия решения о направлении трафика. Не назначается конечным устройствам (исключение: маска `/31`).

**Широковещательный адрес (Broadcast Address)** — специальный адрес, предназначенный для отправки пакета всем узлам в рамках одной подсети. Это последний адрес в диапазоне, у которого все биты хостовой части равны единице.

**Subnetting** — логическое разделение одной крупной IP-сети на несколько более мелких сегментов путем «заимствования» бит из хостовой части адреса в пользу сетевой.

**VLSM (Variable Length Subnet Masking)** — технология использования масок разной длины для разных подсетей в пределах одного адресного пространства, что позволяет минимизировать количество неиспользуемых IP-адресов.

## Основные концепции

### Двоичное представление и октеты

IPv4-адрес состоит из 32 бит, разделенных на 4 октета по 8 бит каждый. Каждый октет может принимать значения от 0 до 255.

**Пример:** IP-адрес `192.168.1.130` в двоичном виде:
```
Октет 1 (192): 11000000
Октет 2 (168): 10101000
Октет 3 (1):   00000001
Октет 4 (130): 10000010
Итог: 11000000.10101000.00000001.10000010
```

### Маска подсети и правило непрерывности

Маска подсети — это 32-битное число, которое определяет, какая часть IP-адреса относится к адресу сети (биты установлены в `1`), а какая — к адресу хоста (биты установлены в `0`).

**Критическое правило:** Единицы в маске всегда должны идти непрерывным блоком слева направо. Недопустимы маски с разрывами (например, `11110011...`).

**Пример маски /26:**
- Префиксная запись: `/26` (означает 26 единиц подряд).
- Двоичный вид: `11111111.11111111.11111111.11000000`.
- Десятичный вид: `255.255.255.192`.

## Технические алгоритмы расчета

### Шаг 1. Расчет количества доступных хостов

Количество доступных хостов зависит от количества «нулевых» бит в маске (хостовая часть).
Формула: $N = 2^h - 2$, где $h$ — количество нулевых бит.

| Маска | Нулевых бит | Расчет | Доступно хостов |
| :--- | :--- | :--- | :--- |
| `/24` | 8 | $2^8 - 2 = 256 - 2$ | 254 |
| `/26` | 6 | $2^6 - 2 = 64 - 2$ | 62 |
| `/30` | 2 | $2^2 - 2 = 4 - 2$ | 2 |
| **`/31`** | 1 | $2^1$ | **2** (RFC 3021, PtP линки) |
| **`/32`** | 0 | $2^0$ | **1** (Хост-маршрут) |

### Шаг 2. Расчет адреса сети (Network Address)

Адрес сети вычисляется путем выполнения побитовой операции **логическое И (AND)** между IP-адресом и маской.

**Логика AND:**
- $1 \text{ AND } 1 = 1$
- $1 \text{ AND } 0 = 0$
- $0 \text{ AND } 1 = 0$
- $0 \text{ AND } 0 = 0$

**Пример:** IP `192.168.1.130`, маска `/26` (`255.255.255.192`).
Работаем с 4-м октетом (где происходит разделение):
```
IP (130):      1 0 0 0 0 0 1 0
Mask (192):    1 1 0 0 0 0 0 0
------------------------------
AND Result:    1 0 0 0 0 0 0 0  => 128 в десятичной системе.
```
**Результат:** Адрес сети — `192.168.1.128`.

### Шаг 3. Расчет широковещательного адреса (Broadcast)

Чтобы получить broadcast, нужно взять адрес сети и заменить все биты хостовой части (соответствующие нулям в маске) на единицы.

**Пример для /26** (6 бит хоста):
1. Адрес сети: `192.168.1.128` (4-й октет: `10 000000`).
2. Заменяем последние 6 бит на `1`: `10 111111`.
3. Переводим в десятичную систему: $128 + 32 + 16 + 8 + 4 + 2 + 1 = 191$.
**Результат:** Broadcast — `192.168.1.191`.

### Шаг 4. Определение диапазона хостов

Диапазон начинается со следующего адреса после сети и заканчивается адресом перед broadcast.
- **Первый хост:** Адрес сети + 1 (`192.168.1.129`).
- **Последний хост:** Broadcast - 1 (`192.168.1.190`).

## Практические методы

### Метод «магического числа» (Magic Number)

Позволяет быстро считать в уме без перевода в двоичный код.

1. **Найти «интересный» октет маски** (тот, который не равен 0 или 255).
2. **Вычесть значение октета из 256.** Результат — «магическое число» (шаг сети).
3. **Найти ближайшее кратное шагу число**, которое меньше или равно соответствующему октету IP-адреса. Это и будет октет адреса сети.

**Пример:** IP `172.16.10.50`, маска `255.255.255.240` (/28).
1. Интересный октет: 4-й (значение 240).
2. Магическое число: $256 - 240 = 16$.
3. Шаги сетей: `0, 16, 32, 48, 64...`
4. Для IP `.50` ближайшее меньшее кратное 16 — это `48`.
5. **Адрес сети:** `172.16.10.48`.
6. **Следующая сеть:** `172.16.10.64`.
7. **Broadcast текущей сети:** `48 + 16 - 1 = 63`.

### Проектирование сетей через VLSM

При проектировании всегда начинайте расчет с самой большой подсети (с наибольшим количеством хостов).

**Пример:** Выделена сеть `192.168.1.0/24`. Нужно разделить для:
1. Отдел продаж: 100 хостов.
2. Технический отдел: 50 хостов.
3. Серверная: 10 хостов.

**Решение:**
- **Продажи (100):** Ближайшая степень двойки — 128. Нужна маска `/25` (126 хостов).
  - Сеть: `192.168.1.0/25`. Диапазон: `.1 – .126`. Broadcast: `.127`.
- **Техники (50):** Ближайшая степень двойки — 64. Нужна маска `/26` (62 хоста).
  - Сеть: `192.168.1.128/26`. Диапазон: `.129 – .190`. Broadcast: `.191`.
- **Серверная (10):** Ближайшая степень двойки — 16. Нужна маска `/28` (14 хостов).
  - Сеть: `192.168.1.192/28`. Диапазон: `.193 – .206`. Broadcast: `.207`.

## Практические сценарии

### Проверка связности L2

Два узла находятся в одном широковещательном домене (могут общаться напрямую без роутера), если после применения операции AND к их IP-адресам с использованием их масок результат совпадает.

**Внимание:** Если у двух хостов в одном сегменте настроены разные маски, может возникнуть «односторонняя» связность или ошибки маршрутизации.

### Использование network и broadcast как хостов

- **IPv4:** Назначение адреса сети или broadcast хосту обычно блокируется ОС или приводит к некорректной работе сети (flooding, игнорирование пакетов).
- **IPv6:** Понятие broadcast отсутствует. Вместо него используется **Multicast**. Стандартный размер подсети для SLAAC — всегда **`/64`**.
