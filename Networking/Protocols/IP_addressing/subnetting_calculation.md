# Расчет параметров подсети (Subnetting)

## Шаг 1: Двоичное представление IP-адреса

Компьютер обрабатывает IPv4-адрес как 32 бита (единицы и нули). Для удобства эти 32 бита разбиты на 4 группы по 8 бит (**октеты**), которые записываются в десятичном виде (0–255).

**Пример:** `192.168.1.130` в двоичном виде:
```
11000000 . 10101000 . 00000001 . 10000010
```

## Шаг 2: Назначение маски подсети

Маска подсети — это 32-битное число, которое показывает, где в IP-адресе находится **адрес сети**, а где — **адрес хоста**.

**Правило:**
- Биты `1` в маске → часть сети (network portion)
- Биты `0` в маске → часть хоста (host portion)

В маске единицы всегда идут сплошным блоком слева направо, за ними следуют только нули (не может быть `11001100`).

**Пример маски /26** (26 единиц, затем 6 нулей):
```
11111111 . 11111111 . 11111111 . 11000000 = 255.255.255.192
```

## Шаг 3: Расчет адреса сети (Network Address)

Для определения адреса сети выполняется побитовая операция **логическое И (AND)** между IP-адресом и маской.

**Логика "И":** `1 и 1 = 1`, все остальные комбинации = `0`.

**Пример:** IP `192.168.1.130`, маска `/26` (`255.255.255.192`).

Анализируется только тот октет, где маска "разрывается" (не 255 и не 0). В данном случае — 4-й октет: IP `130`, маска `192`.

1. Переводим 4-й октет в двоичный вид:
   ```
   IP (130):      10000010
   Маска (192):   11000000
   ```
2. Применяем операцию "И":
   ```
   10000010
   AND
   11000000
   --------
   10000000
   ```
3. Переводим результат в десятичный вид: `10000000 = 128`.

**Итог:** Адрес сети — `192.168.1.128`.

> **Важно:** Адрес сети — это идентификатор подсети ("название улицы"). Его **нельзя** назначать устройствам.

## Шаг 4: Расчет широковещательного адреса (Broadcast Address)

Широковещательный адрес используется для отправки данных **всем** устройствам в подсети.

**Правило:** Взять адрес сети и во всей хостовой части (где в маске нули) установить единицы.

1. Маска `/26` оставляет на хосты 6 бит: `32 - 26 = 6`.
2. 4-й октет адреса сети: `10000000` (это 128).
3. Заменяем последние 6 бит на единицы: `10111111`.
4. Переводим в десятичный вид: `10111111 = 191`.

**Итог:** Широковещательный адрес — `192.168.1.191`.

> **Важно:** Broadcast-адрес также **нельзя** назначать устройствам.

## Шаг 5: Диапазон доступных хостов и количество устройств

Доступные для назначения устройствам адреса находятся между адресом сети и broadcast-адресом:

- **Первый доступный IP:** `192.168.1.129` (адрес сети + 1)
- **Последний доступный IP:** `192.168.1.190` (broadcast - 1)

**Формула количества устройств:**
```
2^(количество нулей в маске) - 2
```

Для маски `/26`:
- Нулей: `32 - 26 = 6`
- Количество хостов: `2^6 - 2 = 64 - 2 = 62`

В подсеть `/26` помещается ровно **62 устройства**.

## Метод "магического числа" для быстрого расчета

Позволяет рассчитывать параметры сети без перевода в двоичный вид.

**Алгоритм:**
1. Вычесть "интересный" октет маски из 256.
2. Полученное значение — шаг сети.
3. Сети кратны этому шагу: `.0, .шаг, .2×шаг, .3×шаг...`

**Пример:** Маска `255.255.255.192`.
- `256 - 192 = 64` (шаг сети).
- Сети идут с шагом 64: `.0`, `.64`, `.128`, `.192`.
- IP `130` попадает в диапазон от `128` до `191` (следующая сеть — `192`).
- **Адрес сети:** `192.168.1.128`
- **Broadcast:** `192.168.1.191` (конец диапазона, перед следующей сетью).

## Проверка принадлежности к одной сети

Чтобы определить, находятся ли два IP-адреса в одной подсети:

1. Применить маску подсети к обоим адресам (операция "И").
2. Если результат (адрес сети) совпал — устройства в одной сети (могут общаться напрямую без маршрутизатора).
3. Если адреса сети разные — требуется маршрутизатор.

**Пример 1:**
- IP 1: `192.168.1.10/24` → сеть `192.168.1.0`
- IP 2: `192.168.1.200/24` → сеть `192.168.1.0`
- **Вывод:** Одна сеть, общение напрямую.

**Пример 2:**
- IP 1: `192.168.1.10/24` → сеть `192.168.1.0`
- IP 2: `192.168.2.10/24` → сеть `192.168.2.0`
- **Вывод:** Разные сети, нужен маршрутизатор.

**Подробнее:** [Практические сценарии маршрутизации](../../OSI_TCP_IP_Model/Network_layer/Concepts/routing_scenarios.md)

## Практическое использование адресов сети и broadcast

### Можно ли использовать первый адрес сети (network address)?

**Технически — да, но не рекомендуется.** Первый адрес сети (например, `192.168.1.0/24`) является нормальным адресом и может быть назначен хосту. ОС, как правило, позволяет это сделать.

**Однако:** Сложившаяся сетевая практика такова, что этот адрес стараются не использовать для удобства администрирования и избежания путаницы.

### Можно ли использовать широковещательный адрес (broadcast address)?

**Нет, не следует.** Широковещательный адрес (например, `192.168.1.255/24`) **нельзя** назначать хостам по следующим причинам:

1. **Конфликт на сетевом уровне:** Все хосты в сети будут принимать и обрабатывать пакеты, отправленные на этот адрес.
2. **Защита от flooding:** Протоколы реализованы таким образом, чтобы не генерировать ответы на пакеты с широковещательным адресом отправителя.

**Механизм защиты:**

Если хост отправит пакет (ARP, ICMP или другой IP-пакет) с широковещательным IP-адресом отправителя:
- Получатели **не будут отвечать** на такой пакет
- Это предотвращает лавинообразную рассылку ответов: если бы хосты отвечали на широковещательный адрес отправителя, ответ также был бы широковещательным (IP: `192.168.1.255`, MAC: `FF:FF:FF:FF:FF:FF`)
- Такой ответ получили бы все хосты в сети, что привело бы к flooding

### Различия в реализациях протоколов (Fingerprinting)

Разные реализации сетевых протоколов ведут себя по-разному в определённых ситуациях. Этой особенностью пользуются для определения типа ОС на удаленном хосте (**fingerprinting**).

**Пример: обработка ICMP-эхо запросов на широковещательный адрес**

| ОС / Устройство | Поведение |
| :--- | :--- |
| **Windows, Linux, macOS, iOS, Android** | Игнорируют ICMP-эхо запросы на broadcast |
| **Сетевые принтеры HP** | Отправляют ICMP-эхо ответ даже на broadcast-запросы |

**Дополнительно:**
- **ARP-запросы от broadcast IP:** Большинство ОС игнорируют ARP-запросы, если IP-адрес отправителя является широковещательным
- **Docker/эмуляторы:** Могут обрабатывать такие запросы иначе, чем физические ОС
