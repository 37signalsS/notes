# Специальные маски подсети и CIDR

## Определения

**CIDR (Classless Inter-Domain Routing)** — бесклассовая адресация, заменившая классовую модель в 1993 году ([RFC 4632](#основные-rfc)). Позволяет гибко задавать размер сети через маску переменной длины (VLSM), записываемую в префиксной нотации `/N`.

**Классовая адресация (Classful Addressing)** — устаревший метод разделения IP-пространства на фиксированные классы (A, B, C, D, E) с жестко заданными масками.

**VLSM (Variable Length Subnet Mask)** — механизм использования масок разной длины внутри одной сети для оптимизации адресного пространства и минимизации потерь IP-адресов.

**Longest Prefix Match (LPM)** — алгоритм выбора маршрута, при котором из нескольких совпадений в таблице маршрутизации выбирается запись с самой длинной маской (наиболее специфичный маршрут).

## Основные концепции

### Префиксная нотация CIDR

Маска подсети записывается как `/N`, где **N** — количество единичных бит в маске. Это позволяет уйти от фиксированных границ октетов.

| CIDR | Маска (десятичная) | Маска (двоичная) | Хостов (IPv4) | Применение |
| :--- | :--- | :--- | :--- | :--- |
| **`/0`** | `0.0.0.0` | `00000000.00000000.00000000.00000000` | $2^{32}$ | Маршрут по умолчанию |
| **`/8`** | `255.0.0.0` | `11111111.00000000.00000000.00000000` | 16 777 214 | Магистральные сети (Класс A) |
| **`/16`** | `255.255.0.0` | `11111111.11111111.00000000.00000000` | 65 534 | Крупные сети (Класс B) |
| **`/24`** | `255.255.255.0` | `11111111.11111111.11111111.00000000` | 254 | Стандартная LAN (Класс C) |
| **`/30`** | `255.255.255.252` | `11111111.11111111.11111111.11111100` | 2 | Устаревшие PtP линки |
| **`/31`** | `255.255.255.254` | `11111111.11111111.11111111.11111110` | 2 | Современный PtP (RFC 3021) |
| **`/32`** | `255.255.255.255` | `11111111.11111111.11111111.11111111` | 1 | Хост-маршрут, Loopback |

### Префиксы IPv6

В IPv6 адресация строится исключительно на префиксах (десятичная запись масок не используется).

- **`/128`**: Аналог `/32` в IPv4. Конкретный интерфейс.
- **`/64`**: Стандарт подсети для одного сегмента. Необходим для работы SLAAC (автоконфигурации).
- **`/56`**: Блок, выделяемый провайдером конечному пользователю.
- **`/48`**: Типичный блок для организации (позволяет создать 65 536 подсетей по `/64`).
- **`/32`**: Блок, выделяемый региональным регистраторам (LIR).

### Правило непрерывности маски

Маска должна содержать непрерывную последовательность единиц слева направо. Разрывы в маске недопустимы в современных сетях.

**Пример недопустимой маски:**
- `255.255.0.255` → `11111111.11111111.00000000.11111111` (разрыв `0...1`).
**Исторический контекст:** До CIDR некоторые реализации допускали "дырявые" маски, но это несовместимо с современными алгоритмами аппаратной обработки (TCAM).

### Специальные маски

#### /0 — Маршрут по умолчанию (Default Route)
Означает отсутствие фиксированных бит. Используется для направления трафика, для которого нет более точного совпадения в таблице маршрутизации.
- **IPv4:** `0.0.0.0/0`
- **IPv6:** `::/0`

#### /32 — Хост-маршрут
Указывает на конкретный IP-адрес.
- **Loopback:** Виртуальный адрес маршрутизатора, доступный через любой физический интерфейс.
- **Приоритет:** Благодаря LPM, маршруты `/32` имеют наивысший приоритет.

#### /31 — Point-to-Point линки (RFC 3021)
Используется для экономии адресов на соединениях между двумя узлами.
- **Особенности:** Нет адреса сети и широковещательного адреса. Оба адреса в диапазоне назначаются интерфейсам.
- **Экономия:** 50% адресов по сравнению с `/30`.

### Классовая адресация (Историческая справка)

До 1993 года IP-пространство делилось на фиксированные классы:

| Класс | Диапазон | Сеть | Хост | Применение |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `0.0.0.0` – `127.255.255.255` | 1 октет | 3 октета | Магистральные сети |
| **B** | `128.0.0.0` – `191.255.255.255` | 2 октета | 2 октета | Крупные компании |
| **C** | `192.0.0.0` – `223.255.255.255` | 3 октета | 1 октет | Небольшие LAN |
| **D** | `224.0.0.0` – `239.255.255.255` | — | — | Multicast |
| **E** | `240.0.0.0` – `255.255.255.255` | — | — | Резерв |

**Главная проблема:** Огромные потери адресов. Если компании требовалось 300 адресов, ей выделялся класс B (65 534 адреса), так как класса C (254 адреса) было недостаточно.

## Практические сценарии

### Выбор маршрута по Longest Prefix Match (LPM)

Алгоритм LPM гарантирует, что пакет уйдет по самому специфичному маршруту.

**Пример таблицы маршрутизации:**
1. `10.0.0.0/8` via `GW1`
2. `10.1.1.0/24` via `GW2`
3. `10.1.1.5/32` via `GW3`

**Результат:**
- Пакет для `10.1.1.5` совпадает со всеми тремя записями, но уйдет через **GW3** (префикс `/32` — самый длинный).
- Пакет для `10.1.1.20` совпадает с 1 и 2, уйдет через **GW2** (`/24` длиннее `/8`).

### Агрегация маршрутов (Summarization)

Позволяет уменьшить размер таблиц маршрутизации, объединяя мелкие префиксы в один крупный.
**Пример:** Сети `192.168.0.0/24` и `192.168.1.0/24`.
- `192.168.0.0`: `... 00000000`
- `192.168.1.0`: `... 00000001`
Общая часть — первые 23 бита. Агрегированный маршрут: `192.168.0.0/23`.

### Настройка PtP линка (/31) в Linux

Современные ядра Linux полностью поддерживают RFC 3021.
```bash
# Назначение адреса на интерфейс
ip addr add 172.16.0.1/31 dev eth1
```
В данном случае адрес `172.16.0.0` и `172.16.0.1` будут принадлежать двум разным концам линка.

### Аппаратная обработка (TCAM)

В высокопроизводительных коммутаторах и маршрутизаторах поиск по LPM выполняется в памяти **TCAM** (Ternary Content-Addressable Memory). В отличие от обычной RAM, TCAM позволяет проверять совпадение адреса со всеми строками таблицы одновременно за один такт, учитывая маски (биты "0", "1" и "don't care").
