# Специальные маски подсети и CIDR

## Definitions

**CIDR (Classless Inter-Domain Routing)** — бесклассовый метод адресации, заменивший классовую адресацию в 1993 году ([RFC 4632](#основные-rfc)). Позволяет гибко задавать размер сети через маску переменной длины (VLSM), записываемую в префиксной нотации `/N`.

**Классовая адресация (Classful Addressing)** — устаревший метод разделения IP-пространства на фиксированные классы (A, B, C, D, E). Заменён CIDR из-за неэффективного распределения адресов.

**VLSM (Variable Length Subnet Mask)** — механизм использования масок разной длины внутри одной сети для оптимизации адресного пространства.

## Basic Concepts

### Префиксная нотация CIDR

Маска подсети записывается как `/N`, где **N** — количество единичных бит в маске (длина префикса).

| Маска (десятичная) | Маска (двоичная) | CIDR | Хостов |
| :--- | :--- | :--- | :--- |
| `255.0.0.0` | `11111111.00000000.00000000.00000000` | `/8` | 16 777 214 |
| `255.255.0.0` | `11111111.11111111.00000000.00000000` | `/16` | 65 534 |
| `255.255.255.0` | `11111111.11111111.11111111.00000000` | `/24` | 254 |
| `255.255.255.128` | `11111111.11111111.11111111.10000000` | `/25` | 126 |
| `255.255.255.192` | `11111111.11111111.11111111.11000000` | `/26` | 62 |
| `255.255.255.254` | `11111111.11111111.11111111.11111110` | `/31` | 2 (point-to-point) |
| `255.255.255.255` | `11111111.11111111.11111111.11111111` | `/32` | 1 (хост-маршрут) |

**Примеры записи:**

- `10.0.0.0/8` вместо `10.0.0.0 255.0.0.0`
- `172.16.0.0/16` вместо `172.16.0.0 255.255.0.0`
- `192.168.1.0/24` вместо `192.168.1.0 255.255.255.0`

### Правило непрерывности маски

Современные стандарты требуют, чтобы маска содержала **непрерывную последовательность единиц**, за которой следуют только нули.

**Недопустимые маски:**

- `255.255.0.255` → `11111111.11111111.00000000.11111111` (разрыв `01`)
- `255.0.255.0` → `11111111.00000000.11111111.00000000` (разрыв `01`)

**Историческая справка:** Раньше допускались маски с «дырками» (например, `192.168.0.2/255.255.0.255`), включавшие адреса `192.168.0.2`, `192.168.1.2`, `192.168.2.2` и т. д. На практике это создавало сложности в маршрутизации, поэтому стандарт упрощён до непрерывных масок.

### Специальная маска /32 (хост-маршрут)

Маска `/32` означает, что все 32 бита IP-адреса фиксированы — адресация к **конкретному хосту**.

**Характеристики:**

- **Количество адресов:** 1 (только сам IP-адрес)
- **Применение:** маршрутизация к конкретному хосту, loopback-интерфейсы, политики безопасности
- **Пример:** `192.168.1.25/32` — маршрут только к адресу `192.168.1.25`

Маршруты `/32` имеют наивысший приоритет в таблице маршрутизации — просматриваются раньше всех остальных (перед `/31`, `/30`, …, `/0`).

### Специальная маска /31 (point-to-point линки)

Маска `/31` — специальная маска для соединений **точка-точка**, определённая в [RFC 3021](#основные-rfc).

**Характеристики:**

- **Количество адресов:** 2 (оба адреса доступны для назначения)
- **Маска в десятичном виде:** `255.255.255.254`
- **Пример:** `192.168.1.0/31` включает адреса `192.168.1.0` и `192.168.1.1`

**Исторический контекст:**

Традиционно первый адрес подсети резервировался как **адрес сети**, последний — как **широковещательный**. Для `/31` это означало бы 0 доступных адресов. RFC 3021 (2000) изменил правило: в `/31` оба адреса считаются хостовыми, адрес сети и broadcast **не резервируются**.

**Обоснование:** в соединении точка-точка присутствуют только два устройства. Широковещательные пакеты не имеют смысла — отправлять некому, кроме единственного соседа.

**Ограничения:**

- Применяется **только для point-to-point** соединений (ровно два устройства)
- Не подходит для сетей с тремя и более устройствами
- Не все устаревшие системы поддерживают `/31`

**Сравнение масок для point-to-point:**

| Маска | Всего адресов | Доступно хостов | Потеряно | Применение |
| :--- | :--- | :--- | :--- | :--- |
| `/30` | 4 | 2 | 2 (сеть + broadcast) | Традиционное |
| `/31` | 2 | 2 | 0 | RFC 3021, оптимально |
| `/32` | 1 | 1 | 0 | Хост-маршрут, loopback |

### Агрегация маршрутов (CIDR)

Благодаря CIDR таблица маршрутизации может агрегировать множество сетей в одну запись:

| IP назначения | Маска | Шлюз | Интерфейс |
| :--- | :--- | :--- | :--- |
| `10.0.0.0` | `/8` | — | eth0 (локально) |
| `172.16.0.0` | `/12` | `10.0.0.100` | eth0 |
| `0.0.0.0` | `/0` | `10.0.0.1` | eth0 (default) |

Даже при добавлении тысяч хостов в диапазоны `10.0.0.0/8` или `172.16.0.0/12` таблица маршрутизации не изменится — одна запись покрывает весь диапазон. Подробности: [Маршрутизация в Linux](../../../Linux/SystemAdministration/routing.md).

### Исторический взгляд: классовая адресация

Классовая адресация использовалась до внедрения CIDR (1993). Весь диапазон IPv4 делился на 5 фиксированных классов:

| Класс | Диапазон | Сеть | Хост | Макс. хостов | Количество сетей |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A** | `0.0.0.0` – `127.255.255.255` | 1 октет | 3 октета | 16 777 214 (2²⁴ − 2) | 128 |
| **B** | `128.0.0.0` – `191.255.255.255` | 2 октета | 2 октета | 65 534 (2¹⁶ − 2) | 16 384 |
| **C** | `192.0.0.0` – `223.255.255.255` | 3 октета | 1 октет | 254 (2⁸ − 2) | 2 097 152 |
| **D** | `224.0.0.0` – `239.255.255.255` | — | — | — | Multicast |
| **E** | `240.0.0.0` – `255.255.255.255` | — | — | — | Зарезервировано |

Классы D и E не делятся на сеть/хост. Класс D используется для multicast, класс E зарезервирован для экспериментов.

**Проблема негибкости:**

Для сети на 4 000 хостов: одна сеть класса B (65 534 хоста) теряет ~61 500 адресов; 16 сетей класса C (4 064 хоста) — сложны в управлении. Для 40 000 хостов: одна сеть класса B теряет ~25 500 адресов (>50% не используется).

Частные диапазоны [RFC 1918](./special_addresses.md#частные-приватные-сети-rfc-1918) исторически относились к классам A (`10.0.0.0/8`), B (`172.16.0.0/12`), C (`192.168.0.0/16`). Link-local APIPA (`169.254.0.0/16`) — класс B.

## Practical Scenarios

### Хост-маршрут /32 для loopback-интерфейса

Loopback-интерфейс всегда имеет маску `/32`, т. к. это виртуальный интерфейс, указывающий на само устройство. В таблицах маршрутизации Linux:

```bash
127.0.0.1 dev lo proto kernel scope link src 127.0.0.1
```

### Point-to-point линк между роутерами (/31)

Для соединения двух роутеров оптимален `/31` — оба адреса рабочие, потерь нет:

```bash
# Подсеть 172.16.12.0/31 для линка между двумя роутерами:
# Роутер A: 172.16.12.0/31
# Роутер B: 172.16.12.1/31
# Нет сети и broadcast — оба адреса рабочие
```

Типичная ошибка новичков — использование `/24` для point-to-point: сеть из 254 адресов при потребности в 2. Правильный выбор — `/31` (RFC 3021) или `/30` (традиционный).

### WireGuard и /32

В конфигурациях WireGuard для указания конкретных пиров используется `/32`:

```ini
[Peer]
AllowedIPs = 10.0.0.2/32
```

Это создаёт хост-маршрут — трафик направляется строго к одному пиру.

### Политики firewall с /32

В правилах iptables маска `/32` используется для точного указания источника или получателя:

```bash
iptables -A INPUT -s 192.168.1.25/32 -p tcp --dport 22 -j ACCEPT
```
