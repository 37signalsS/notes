# Специальные маски подсети и CIDR

## Определения

**CIDR (Classless Inter-Domain Routing)** — бесклассовый метод адресации, заменивший классовую адресацию в 1993 году ([RFC 4632](#основные-rfc)). Позволяет гибко задавать размер сети через маску переменной длины (VLSM), записываемую в префиксной нотации `/N`.

**Классовая адресация (Classful Addressing)** — устаревший метод разделения IP-пространства на фиксированные классы (A, B, C, D, E). Заменён CIDR из-за неэффективного распределения адресов.

**VLSM (Variable Length Subnet Mask)** — механизм использования масок разной длины внутри одной сети для оптимизации адресного пространства.

**Longest Prefix Match (LPM)** — алгоритм выбора маршрута, при котором из нескольких совпадений выбирается запись с самой длинной маской (наиболее специфичный маршрут).

## Основные концепции

### Префиксная нотация CIDR

Маска подсети записывается как `/N`, где **N** — количество единичных бит в маске (длина префикса).

| Маска (десятичная) | Маска (двоичная) | CIDR | Хостов (IPv4) | Применение |
| :--- | :--- | :--- | :--- | :--- |
| `255.0.0.0` | `11111111.00...` | `/8` | 16 777 214 | Крупные магистрали |
| `255.255.0.0` | `11111111.11...` | `/16` | 65 534 | Корпоративные сети |
| `255.255.255.0` | `11111111.11...` | `/24` | 254 | Стандартная LAN |
| `255.255.255.252` | `11111111.11...` | `/30` | 2 | Резервные PtP (устарело) |
| `255.255.255.254` | `11111111.11...` | `/31` | 2 | Современный PtP (RFC 3021) |
| `255.255.255.255` | `11111111.11...` | `/32` | 1 | Хост-маршрут, Loopback |

### Префиксы IPv6

В IPv6 не используется десятичная запись масок; адресация всегда строится на префиксах.

- **`/128`**: Аналог `/32` в IPv4. Указывает на конкретный интерфейс.
- **`/64`**: Стандартный размер подсети для одного сегмента (требуется для работы SLAAC).
- **`/56`**: Стандартный блок, выделяемый провайдером конечному пользователю.
- **`/48`**: Типичный блок для организации (позволяет создать 65 536 подсетей по `/64`).
- **`/32`**: Блок, выделяемый LIR (региональным регистраторам).

### Правило непрерывности маски

Современные стандарты требуют, чтобы маска содержала **непрерывную последовательность единиц**, за которой следуют только нули.

**Недопустимые маски:**
- `255.255.0.255` → `11111111.11111111.00000000.11111111` (разрыв `01`)

**Историческая справка:** Раньше (до появления CIDR) некоторые реализации допускали «дырявые» маски, но это создавало огромные сложности для аппаратной обработки трафика на высоких скоростях.

### Специальная маска /32 (хост-маршрут)

Маска `/32` означает, что все 32 бита IP-адреса фиксированы — адресация к **конкретному хосту**.

**Характеристики:**
- **Применение:** маршрутизация к конкретному хосту, Loopback-интерфейсы, политики безопасности.
- **Приоритет:** Согласно принципу LPM, маршруты `/32` просматриваются раньше всех остальных.

### Специальная маска /31 (Point-to-Point линки)

Определена в [RFC 3021](#основные-rfc) для экономии адресного пространства на линках между двумя устройствами.

**Характеристики:**
- **Количество адресов:** 2 (оба доступны для назначения).
- **Особенности:** В `/31` отсутствует адрес сети и широковещательный адрес. Широковещание не требуется, так как на линке всего два соседа.
- **Преимущество:** Экономия 50% адресов по сравнению с традиционной маской `/30`.

### Исторический взгляд: классовая адресация

До 1993 года IP-пространство делилось на фиксированные классы:

| Класс | Диапазон | Сеть | Хост | Применение |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `0.0.0.0` – `127.255.255.255` | 1 октет | 3 октета | Магистральные сети |
| **B** | `128.0.0.0` – `191.255.255.255` | 2 октета | 2 октета | Крупные компании |
| **C** | `192.0.0.0` – `223.255.255.255` | 3 октета | 1 октет | Небольшие LAN |
| **D** | `224.0.0.0` – `239.255.255.255` | — | — | Multicast |
| **E** | `240.0.0.0` – `255.255.255.255` | — | — | Экспериментальные |

**Проблема:** Негибкость. Если компании нужно было 300 адресов, ей приходилось брать класс B (65к адресов), что привело к быстрому исчерпанию IPv4.

## Практические сценарии

### Выбор маршрута по LPM

Если в таблице маршрутизации есть записи:
1. `10.0.0.0/8`
2. `10.1.1.0/24`
3. `10.1.1.5/32`

Пакет для `10.1.1.5` будет направлен через маршрут **№3**, так как он имеет самую длинную маску (наиболее точное совпадение).

### Агрегация маршрутов (Route Summarization)

Благодаря CIDR тысячи мелких сетей можно объединить в один анонс.
**Пример:** Сети `192.168.0.0/24`, `192.168.1.0/24`, `192.168.2.0/24` и `192.168.3.0/24` можно агрегировать в одну запись `192.168.0.0/22`.

### Настройка PtP линка (/31) в Linux

При настройке интерфейса на маршрутизаторе:
```bash
# Назначение адреса с маской /31
ip addr add 172.16.0.1/31 dev eth1
```
Оба адреса в сети (`172.16.0.0` и `172.16.0.1`) становятся хостовыми.
