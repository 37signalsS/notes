# UDP — протокол пользовательских датаграмм

> **Reliability Score: 10** (SSoT + RFC Verified + Linux Networking Stack)

## Определения

**UDP (User Datagram Protocol — протокол пользовательских датаграмм)** — простейший протокол транспортного уровня (L4) стека TCP/IP, определенный в **RFC 768**. Он обеспечивает передачу данных между приложениями с минимальными накладными расходами, без установления соединения, подтверждения доставки и контроля порядка пакетов.

**Ключевая особенность:** UDP работает по принципу «best-effort» (максимальное усилие). Он жертвует надежностью ради скорости и предсказуемости задержек, что критично для современных приложений реального времени и сетевых сервисов инфраструктурного уровня.

> **См. также:** [TCP vs UDP](./TCP/overview.md), [Модель OSI](../OSI_TCP_IP_Model/osi_model.md)

## Основные концепции

### Ключевые характеристики

| Характеристика | Описание | Следствие |
| :--- | :--- | :--- |
| **Без соединения** | Нет рукопожатия (handshake) и обмена состоянием сессии | Нулевая задержка (0-RTT) перед отправкой данных |
| **Нет гарантий** | Данные могут быть потеряны, продублированы или перепутаны | Ответственность за целостность лежит на прикладном уровне |
| **Границы сообщений** | Сохраняет структуру датаграмм (message-oriented) | Приложение получает ровно столько байт, сколько было отправлено в одном системном вызове |
| **Отсутствие контроля** | Нет механизмов Flow Control и Congestion Control | Риск перегрузки сети при бесконтрольной отправке (требуется реализация в приложении) |
| **Минимальный оверхед** | Фиксированный заголовок 8 байт | Максимальная полезная нагрузка (Payload) в пакете |

### Структура UDP-заголовка

Заголовок UDP крайне лаконичен и состоит из четырех полей по 16 бит:

| Поле | Размер | Описание |
| :--- | :--- | :--- |
| **Source Port** | 2 байта | Порт отправителя. Опционален в IPv4 (может быть 0), обязателен, если ожидается ответ. |
| **Destination Port** | 2 байта | Порт получателя, на который направлена датаграмма. |
| **Length** | 2 байта | Общая длина датаграммы (заголовок + данные). Минимум 8 байт. |
| **Checksum** | 2 байта | Контрольная сумма заголовка, данных и **псевдозаголовка**. |

#### UDP-псевдозаголовок и контрольная сумма

Для расчета контрольной суммы UDP использует **псевдозаголовок** (Pseudo-header). Это технический прием, позволяющий UDP убедиться, что пакет доставлен на нужный IP-адрес, хотя IP-адреса относятся к сетевому уровню (L3).

Псевдозаголовок включает:
- IP-адреса источника и назначения.
- Нулевой байт (Padding).
- Номер протокола (17 для UDP).
- Длину UDP-датаграммы.

**Важно:** Если контрольная сумма вычислена как `0x0000`, она записывается как `0xFFFF`. Значение `0x0000` в поле Checksum означает, что отправитель не вычислял контрольную сумму (допустимо только в IPv4). В IPv6 контрольная сумма **обязательна**.

### Диапазоны портов

UDP использует те же диапазоны портов, что и TCP:
- **0 – 1023 (Well-known):** Системные порты (DNS/53, DHCP/67, NTP/123).
- **1024 – 49151 (Registered):** Зарегистрированные порты (Jaeger/6831, StatsD/8125).
- **49152 – 65535 (Dynamic/Ephemeral):** Динамические порты, выделяемые ОС для клиентских соединений.

### Протокол UDP Lite (RFC 3828)

**UDP Lite** (номер протокола IP — 136) — модификация UDP для приложений, которые могут переносить повреждение части данных, но не хотят отбрасывания всей датаграммы.

- **Отличие:** Поле `Length` в заголовке UDP заменяется на `Checksum Coverage`.
- **Механизм:** Позволяет защищать контрольной суммой только критическую часть пакета (например, заголовок кодека), игнорируя ошибки в полезной нагрузке.
- **Применение:** Потоковое аудио/видео в сетях с высоким уровнем помех.

### MTU и фрагментация

В отличие от TCP, который использует MSS для сегментации, UDP передает блоки данных «как есть».

- **Фрагментация IP:** Если UDP-пакет > MTU (обычно 1500), ядро дробит его на фрагменты. Потеря одного фрагмента = потеря всей датаграммы.
- **Path MTU Discovery (PMTUD):** UDP не поддерживает PMTUD нативно. Приложения должны либо использовать безопасный размер (**1472 байта** для Ethernet), либо реализовывать механизмы проверки пути.

## Практические сценарии

### Области применения

1.  **Инфраструктурные сервисы:** DNS, DHCP, NTP, SNMP.
2.  **Стриминг и VoIP:** RTP (Real-time Transport Protocol), WebRTC, SIP.
3.  **Игровые движки:** Передача состояний мира (World State) с высокой частотой.
4.  **Современный Web:** QUIC (HTTP/3) реализует контроль потока и надежность поверх UDP.
5.  **Туннелирование:** VXLAN, WireGuard, Foo-Over-UDP (FOU).
6.  **Сбор метрик:** StatsD (отправка метрик не должна блокировать основное приложение).

### Тюнинг производительности в Linux

Для высоконагруженных UDP-приложений (сотни тысяч пакетов в секунду) стандартных настроек недостаточно:

1.  **SO_REUSEPORT:** Масштабирование обработки на несколько ядер CPU.
2.  **UDP GSO/GRO:** Снижение нагрузки на CPU за счет передачи больших блоков данных между ядром и приложением.
3.  **SO_BUSY_POLL:** Снижение задержек за счет исключения ожидания прерываний (CPU активно опрашивает сетевую карту).
4.  **msg_zerocopy:** (Linux 4.14+) Позволяет отправлять данные без копирования из пространства пользователя в пространство ядра (требует поддержки в сетевой карте).
5.  **XDP (eBPF):** Обработка UDP-пакетов на самом раннем этапе (в драйвере сетевой карты), минуя весь сетевой стек ядра.

### Диагностика UDP

**Основные инструменты:**
- `ss -unlp` — просмотр слушающих UDP-сокетов и очередей.
- `nc -zu <ip> <port>` — проверка доступности порта.
- `tcpdump -i any udp port <port>` — захват трафика.
- `iperf3 -u -b 1G` — тестирование пропускной способности UDP с заданным рейтом.
- `xfr` — (если установлен) современная замена iperf.

**Мониторинг ошибок:**
```bash
# Проверка счетчиков ошибок UDP в стеке
netstat -su | grep -E "errors|dropped"
# Или через nstat
nstat -az UdpInErrors UdpOutErrors
```

**Оптимизация буферов:**
Если `UdpInErrors` растет, увеличьте лимиты приема:
```bash
sysctl -w net.core.rmem_max=26214400
sysctl -w net.ipv4.udp_mem="262144 524288 1048576"
```

## Дополнительная информация

### Сравнение с TCP

| Параметр | TCP | UDP |
| :--- | :--- | :--- |
| **Соединение** | Устанавливается (3-way handshake) | Отсутствует |
| **Надежность** | Гарантированная доставка | Не гарантирована |
| **Скорость** | Ниже (из-за подтверждений и контроля) | Максимально возможная |
| **Заголовок** | 20–60 байт | 8 байт |
| **Режим** | Потоковый (Streaming) | Сообщения (Datagrams) |

### RFC и стандарты

- **RFC 768** — базовая спецификация UDP.
- **RFC 3828** — Lightweight User Datagram Protocol (UDP Lite).
- **RFC 9000** — QUIC (Транспорт на базе UDP).
- **RFC 2460 / 8200** — Особенности UDP в IPv6.
