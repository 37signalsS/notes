# UDP — протокол пользовательских датаграмм

> **Reliability Score: 10** (SSoT + RFC Verified + Linux Networking Stack)

## Определения

**UDP (User Datagram Protocol — протокол пользовательских датаграмм)** — протокол транспортного уровня (L4) стека TCP/IP, обеспечивающий передачу данных без установления соединения, гарантий доставки и сохранения порядка следования пакетов.

**Ключевая особенность:** UDP жертвует надёжностью ради минимальных задержек и низких накладных расходов. Это делает его основным выбором для приложений реального времени, где актуальность данных важнее их полной доставки.

> **См. также:** [TCP vs UDP](./TCP/overview.md), [Модель OSI](../OSI_TCP_IP_Model/osi_model.md)

## Основные концепции

### Ключевые характеристики

| Характеристика | Описание | Следствие |
| :--- | :--- | :--- |
| **Без соединения** | Отсутствует процедура рукопожатия (handshake) | Мгновенная отправка данных без задержек на установку связи |
| **Нет гарантий доставки** | Датаграммы могут быть потеряны в сети | Приложение должно самостоятельно обрабатывать потери |
| **Нет порядка** | Датаграммы могут приходить в произвольном порядке | Приложение должно заниматься переупорядочиванием |
| **Нет контроля потока** | Отправитель не знает о состоянии буферов получателя | Возможна перегрузка получателя и отбрасывание пакетов |
| **Минимальный заголовок** | Фиксированный размер — 8 байт | Низкие накладные расходы на передачу служебной информации |
| **Работа с сообщениями** | Каждая датаграмма — независимая единица (message-oriented) | Сохранение границ сообщений при передаче |

### MTU и фрагментация

В отличие от TCP, который сам разбивает поток данных на сегменты согласно MSS (Maximum Segment Size), UDP передает данные «как есть».

- **Фрагментация на уровне IP:** Если размер UDP-дейтаграммы превышает MTU (Maximum Transmission Unit) канала, она будет фрагментирована на сетевом уровне (L3).
- **Риски:** Потеря одного фрагмента ведет к отбрасыванию всей дейтаграммы. Многие файрволы блокируют фрагментированные пакеты.
- **Рекомендация:** Для предотвращения фрагментации размер полезных данных в UDP не должен превышать **1472 байта** (1500 байт MTU - 20 байт IP заголовок - 8 байт UDP заголовок).

### Структура UDP-заголовка

| Поле | Размер | Описание |
| :--- | :--- | :--- |
| **Source Port** | 16 бит | Порт отправителя (опционально, может быть заполнен нулями) |
| **Destination Port** | 16 бит | Порт получателя |
| **Length** | 16 бит | Длина заголовка вместе с данными (минимум 8 байт) |
| **Checksum** | 16 бит | Контрольная сумма. Обязательна в IPv6, опциональна в IPv4. |

### Обработка ошибок и ICMP

UDP не занимается исправлением ошибок:
- Если контрольная сумма не совпадает, датаграмма **отбрасывается**.
- **ICMP Port Unreachable:** Если пакет приходит на закрытый UDP-порт, ОС отправит источнику ICMP-сообщение об ошибке (Type 3, Code 3). Это используется утилитами типа `traceroute`.

## Практические сценарии

### Области применения

UDP используется там, где критична скорость или поддерживается групповая рассылка:

- **DNS (Domain Name System):** быстрые короткие запросы и ответы.
- **VoIP (Voice over IP) и видеоконференции (SIP, RTP):** задержка критичнее, чем потеря отдельных кадров или звуков.
- **Онлайн-игры:** минимальная латентность (пинг) важнее целостности каждого пакета состояния.
- **DHCP (Dynamic Host Configuration Protocol):** рассылка широковещательных запросов для получения IP-адреса.
- **SNMP (Simple Network Management Protocol):** мониторинг устройств, где допустимы пропуски отдельных метрик.
- **NTP (Network Time Protocol):** высокоточная синхронизация времени, где важен точный расчет задержек.
- **Multicast:** групповая рассылка данных (например, потоковое видео или обновление ПО на множестве хостов).

### Передача данных реального времени

Для приложений реального времени **свежесть данных** важнее **полноты доставки**.

- **В онлайн-играх:** если пакет потерян, TCP инициировал бы повторную передачу, вызывая «зависание» (freeze). UDP позволяет просто проигнорировать старые данные и дождаться следующего актуального пакета состояния.
- **В видеосвязи:** потеря пакета приведет к кратковременному искажению (артефакту), но поток останется синхронизированным. Использование TCP привело бы к накапливающемуся отставанию видео от реальности.

### Групповая рассылка (Multicast)

UDP — единственный стандартный протокол транспортного уровня, поддерживающий **multicast** (рассылку одной копии данных группе подписчиков). Это позволяет эффективно транслировать контент (например, IPTV) тысячам пользователей, не нагружая сеть дублирующими потоками.

### Тюнинг производительности в Linux

Для высоконагруженных UDP-сервисов (QUIC, VoIP, Игры) применяются специфические оптимизации:

1. **SO_REUSEPORT:** Позволяет нескольким процессам/потокам слушать один и тот же UDP-порт. Ядро Linux само балансирует входящие пакеты между ними, что критично для масштабирования на многоядерных CPU.
2. **UDP GSO (Generic Segmentation Offload):** Позволяет приложению передавать ядру одну большую порцию данных, которую сетевая карта сама разобьет на мелкие пакеты. Это радикально снижает количество переключений контекста.
3. **UDP GRO (Generic Receive Offload):** Обратный механизм — ядро собирает несколько входящих UDP-пакетов в один большой блок перед передачей приложению.

### Безопасность и UDP-амплификация

Из-за отсутствия состояния (stateless) и возможности подмены IP-адреса отправителя (spoofing), UDP часто используется в **атаках усиления (Amplification Attacks)**:
- Злоумышленник шлет короткий запрос серверу (DNS, NTP, Memcached) от имени жертвы.
- Сервер отвечает жертве огромным объемом данных.
- **Защита:** Ограничение скорости ответов (Rate Limiting), использование RRL (Response Rate Limiting) в DNS, закрытие публичного доступа к сервисам типа Memcached.

### Диагностика UDP

**Инструменты:**
- **ss:** Просмотр сокетов и буферов. `ss -unlp` (показать процессы и порты).
- **tcpdump:** Захват трафика. `tcpdump -i eth0 udp port 53`.
- **nc (netcat):** Проверка доступности. `nc -zu 1.1.1.1 53`.

**Оптимизация буферов через sysctl:**
Если в статистике (`ss -s`) растут счетчики `packet receive errors`, увеличьте лимиты:

```bash
# Максимальный размер буферов приема (rmem) и отправки (wmem)
sysctl -w net.core.rmem_max=26214400
sysctl -w net.core.wmem_max=26214400

# Глобальные лимиты памяти для всего UDP-стека
sysctl -w net.ipv4.udp_mem="262144 524288 1048576"
```
