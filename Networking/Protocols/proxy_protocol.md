# Proxy Protocol

## Определения

**Proxy Protocol** — сетевой протокол, предназначенный для передачи информации о первоначальном соединении (адреса **IP (Internet Protocol)** клиента и сервера, порты) в начале **TCP (Transmission Control Protocol)** соединения через прокси-серверы уровня **L4 (Layer 4 — транспортный уровень)**.

**Проблема:** при использовании балансировщиков нагрузки уровня L4 (HAProxy, Nginx stream, AWS ELB) бэкенд видит только IP-адрес прокси-сервера, а не реального клиента. Это нарушает работу логирования, ограничения скорости (rate limiting), геолокации, списков контроля доступа **ACL (Access Control List)** и правил сетевого экрана (firewall rules).

**Решение:** Proxy Protocol добавляет специальный заголовок в начало потока данных приложения, сохраняя метаданные исходного соединения без необходимости изменения вышестоящих протоколов (например, HTTP).

## Базовые концепции

### Версии протокола

#### Proxy Protocol v1 (текстовый)

Представляет собой человекочитаемую строку в начале соединения.

**Пример:**
```text
PROXY TCP4 192.168.0.1 192.168.0.11 56324 443\r\n
```

**Формат:** `PROXY <protocol> <client-IP> <server-IP> <client-port> <server-port>\r\n`

**Типы протоколов:**
- `TCP4`: TCP поверх IPv4.
- `TCP6`: TCP поверх IPv6.
- `UNKNOWN`: используется, если информация о соединении недоступна (для обратной совместимости).

**Преимущества:** простота отладки (заголовок виден в инструментах анализа трафика, таких как tcpdump) и легкая реализация.
**Недостатки:** фиксированный набор полей, максимальный размер до 108 байт, отсутствие возможности расширения.

#### Proxy Protocol v2 (бинарный)

Компактный бинарный формат с поддержкой расширений.

**Структура:**
1. **Signature (12 байт):** неизменяемая последовательность для идентификации протокола.
2. **Адресные данные:** бинарное представление IP и портов.
3. **TLV (Type-Length-Value):** блоки дополнительных данных.

**Преимущества:**
- Высокая скорость обработки и компактность (минимум 16 байт).
- Поддержка расширений **TLV (Type-Length-Value)** для передачи:
    - Информации о **SSL/TLS (Secure Sockets Layer / Transport Layer Security)** (шифр, версия, данные клиентского сертификата).
    - Данных авторизации (имя пользователя).
    - Идентификатора сетевого пространства имен **NetNS (Network Namespace) ID**.

### Сценарии использования

| Сценарий | Описание |
| :--- | :--- |
| **L4-балансировка** | Передача IP клиента через HAProxy или Nginx в режиме `stream`. |
| **Сохранение IP клиента** | Обеспечение видимости реального адреса для бэкендов в целях логирования и безопасности. |
| **Цепочки прокси** | Передача метаданных через несколько уровней инфраструктуры. |
| **Kubernetes Ingress** | Передача IP-адреса клиента от Ingress-контроллера к подам приложения. |

## Практические сценарии

### Настройка HAProxy → Nginx

**Конфигурация HAProxy (отправитель):**
```haproxy
frontend https
    bind *:443
    mode tcp
    server backend1 192.168.1.10:8443 send-proxy-v2
```

**Конфигурация Nginx (получатель):**
```nginx
stream {
    server {
        listen 8443 proxy_protocol;
        proxy_pass http://backend;
    }
}

http {
    server {
        listen 443 ssl proxy_protocol;

        # Доверяем балансировщику
        set_real_ip_from 192.168.1.0/24;
        real_ip_header proxy_protocol;

        location / {
            # Переменная $remote_addr будет содержать реальный IP клиента
            access_log /var/log/nginx/access.log;
        }
    }
}
```

### Диагностика

**Проверка v1 (текстовый):**
```bash
# Использование telnet для имитации заголовка
telnet backend.example.com 80
# Ввод вручную: PROXY TCP4 192.168.1.100 10.0.0.1 54321 80
```

**Анализ трафика (tcpdump):**
```bash
# Для v1 (текст)
tcpdump -i eth0 -A port 80

# Для v2 (бинарная подпись)
tcpdump -i eth0 -X port 80
# Ожидаемая подпись: 0D 0A 0D 0A 00 0D 0A 51 55 49 54 0A
```

### Безопасность

**Риски:**
- **IP Spoofing:** возможность подделки заголовка злоумышленником.
- **DoS (Denial of Service):** атаки типа «отказ в обслуживании» через некорректно сформированные заголовки.

**Меры защиты:**
- **Доверенная сеть:** включать поддержку протокола только на интерфейсах, смотрящих во внутреннюю сеть балансировщиков.
- **Ограничение источников:** использовать директивы (например, `set_real_ip_from` в Nginx) для принятия заголовков только от известных IP-адресов балансировщиков.

## Дополнительная информация

### Поддержка в программном обеспечении

- **Отправители:** HAProxy (v1, v2), Nginx (v2), Envoy (v2), облачные балансировщики (Yandex Cloud, AWS, GCP).
- **Получатели:** Nginx (v1, v2), HAProxy, Apache (через `mod_remoteip`), PostgreSQL, MySQL, Redis.
