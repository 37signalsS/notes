# Протокол TCP: скользящее окно

В протоколе TCP для гарантии доставки данных используются подтверждения. Если отправленное сообщение не подтверждено в течение определённого времени, оно отправляется заново.

В компьютерных сетях существуют два основных варианта подтверждения доставки, используемые на разных уровнях модели TCP/IP:
*   Вариант с **остановкой и ожиданием** (Stop-and-Wait), чаще используется на канальном уровне (например, Wi-Fi).
*   Вариант со **скользящим окном** (Sliding Window), применяется в TCP на транспортном уровне.

## Остановка и ожидание (Stop-and-Wait)

Принцип работы:
1.  Отправитель передаёт данные получателю.
2.  Отправитель останавливается и ждёт подтверждения от получателя.
3.  После получения подтверждения отправитель передаёт следующую порцию данных и снова ждёт подтверждения.

Этот метод прост, но неэффективен для сетей с ненулевым временем передачи, так как каждый раз приходится ждать подтверждения.

## Скользящее окно (Sliding Window)

В TCP выгодно подтверждать не каждый сегмент, а сразу несколько. Это связано с тем, что сообщения передаются по сети не мгновенно, а проходят через множество промежуточных узлов, что приводит к задержкам.

**Пример неэффективности Stop-and-Wait:**
*   Представим, что время кругового обхода (Round Trip Time, RTT) составляет 10 миллисекунд.
*   Это означает, что за 1 секунду можно передать и подтвердить только 100 сегментов.
*   При размере данных в одном TCP-сегменте в 1460 байт (подробнее о размере будет рассмотрено далее: 1500 байт на канальном уровне, минус 20 байт IP-заголовка и 20 байт TCP-заголовка), скорость передачи составит 1460 байт/сегмент * 100 сегментов/секунда = 146 КБ/с. Это очень мало для современных гигабитных сетей.

Чтобы повысить производительность, отправитель не останавливается после первого сегмента, а отправляет в сеть сразу несколько сегментов, не дожидаясь подтверждения для каждого. Для этого используется механизм **скользящего окна**.

**Что такое окно?**
Окно - это набор данных (байтов), которые были отправлены, но получение которых ещё не подтверждено.
*   **Размер окна** — это количество байтов данных, которые могут быть переданы в сеть без получения подтверждения.

**Почему окно "скользящее"?**
Оно перемещается (скользит) по потоку данных по мере того, как приходят подтверждения о получении предыдущих сообщений.

*   **Пример:** Если получатель подтвердил доставку ещё четырёх сегментов, скользящее окно сдвигается. Его начало теперь находится там, где данные уже подтверждены. Часть данных уже находится в сети, и новые сегменты, которые ещё не были переданы, но уже находятся в окне, могут быть отправлены.

## Типы подтверждений в TCP

В протоколе TCP используются два типа подтверждений:

1.  **Кумулятивное подтверждение (Cumulative Acknowledgment):**
    *   Это тип подтверждения используется по умолчанию.
    *   Оно говорит о том, что получены **все предыдущие байты** до указанного номера.
    *   TCP в подтверждении отправляет номер байта, который он ожидает получить следующим.
    *   Хорошо подходит для окон небольшого размера.

2.  **Выборочное подтверждение (Selective Acknowledgment, SACK):**
    *   Используется для окон большого размера, когда может быть потерян один сегмент посреди большой порции данных.
    *   При кумулятивном подтверждении в такой ситуации можно подтвердить только данные до потерянного сегмента.
    *   При выборочном подтверждении отправитель может явно указать диапазоны тех частей данных, которые получены. Отправителю останется передать только ту часть данных, которая была реально потеряна.
    *   SACK не используется по умолчанию. Отправитель и получатель должны явно договориться об его использовании в процессе установки соединения.

## Выводы

*   Для обеспечения надёжности в компьютерных сетях используются различные варианты подтверждения сообщений.
*   **Остановка и ожидание** лучше подходит для канального уровня (например, Wi-Fi).
*   **Скользящее окно** — основной механизм, применяемый в TCP на транспортном уровне для повышения производительности передачи данных по крупным составным сетям.
*   **Размер окна** определяет количество байтов данных, которые могут быть переданы в сеть без получения подтверждения.
*   TCP использует **кумулятивное подтверждение** по умолчанию.
*   При использовании окон большого размера можно договориться о применении **выборочного подтверждения (SACK)** для более эффективной обработки потерь пакетов.
