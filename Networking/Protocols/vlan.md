# VLAN (Virtual Local Area Network) и стандарт IEEE 802.1Q

## Определения

**VLAN (виртуальная локальная сеть)** — это технология [канального уровня (L2)](../OSI_TCP_IP_Model/osi_tcp_ip_models.md), которая позволяет логически разделить одну физическую сеть на несколько независимых широковещательных доменов. Эта технология реализуется на управляемых [коммутаторах](./osi_tcp_ip_models.md#уровень-2-коммутатор-свитч).

Компьютеры, находящиеся в разных VLAN, не могут взаимодействовать друг с другом напрямую, даже если они подключены к одному и тому же физическому коммутатору.

## Базовые концепции

### Зачем нужны VLAN?

1.  **Безопасность:** Изоляция сетей разных отделов, компаний или групп пользователей. Например, в бизнес-центре сеть каждого арендатора можно выделить в отдельный VLAN, чтобы их трафик не пересекался.
2.  **Оптимизация производительности:** Ограничение широковещательного трафика. Широковещательные кадры (например, [ARP-запросы](./arp_protocol.md)) распространяются только в пределах своего VLAN, а не по всей физической сети. Это снижает бесполезную нагрузку на конечные устройства и сетевое оборудование.
3.  **Гибкость:** VLAN позволяют группировать хосты по логическому признаку (отдел, проект), а не по физическому расположению. Администраторы могут легко перемещать устройства между VLAN без необходимости физического переключения кабелей.

### Реализация VLAN

### 1. VLAN на одном коммутаторе (Port-based VLAN)

Это самый простой способ реализации. Каждому порту коммутатора присваивается идентификатор VLAN (VLAN ID).

-   Коммутатор ведет таблицу коммутации, в которой для каждого MAC-адреса хранится не только номер порта, но и VLAN ID.
-   Передача кадров разрешена только между портами, принадлежащими одному и тому же VLAN.
-   Если кадр приходит с порта, принадлежащего `VLAN 10`, он может быть отправлен только на порты, которые также состоят в `VLAN 10`. Попытка отправить кадр на порт в `VLAN 20` будет заблокирована коммутатором.

**Пример:**
- Порты 1-8: `VLAN 10` (Бухгалтерия)
- Порты 9-16: `VLAN 20` (Разработка)
- Порты 17-24: `VLAN 30` (Гостевая сеть)

Устройства из бухгалтерии могут общаться только между собой.

### 2. VLAN на нескольких коммутаторах (Тегирование кадров, IEEE 802.1Q)

Когда сеть охватывает несколько коммутаторов, им необходимо обмениваться информацией о принадлежности трафика к тому или иному VLAN. Для этого используется **тегирование**.

**Протокол IEEE 802.1Q** определяет стандартный формат тегированного Ethernet-кадра.

**Как это работает?**

1.  Когда кадр от конечного устройства (например, компьютера) поступает на порт коммутатора, коммутатор добавляет в этот кадр специальный **тег (tag)**.
2.  Этот тег содержит **VLAN ID** (12 бит, что позволяет создавать до 4094 VLAN).
3.  Кадр передается на другой коммутатор.
4.  Принимающий коммутатор читает тег, определяет, к какому VLAN принадлежит кадр, и направляет его на соответствующий порт.
5.  Перед отправкой кадра конечному устройству (которое не "понимает" теги) коммутатор удаляет тег, возвращая кадр в стандартный формат Ethernet.

## Расширенные детали

### Формат кадра 802.1Q

Чтобы добавить тег, не нарушая совместимость, стандарт 802.1Q изменяет структуру Ethernet-кадра:

1.  В поле **`EtherType`** стандартного кадра вместо кода протокола верхнего уровня (например, `0x0800` для IPv4) вставляется специальное значение **`0x8100`**. Это значение указывает, что данный кадр является тегированным (tagged frame).
2.  Сразу после этого поля добавляется **4-байтовый тег**, который содержит:
    -   **TPID (Tag Protocol Identifier):** 2 байта, всегда `0x8100`.
    -   **TCI (Tag Control Information):** 2 байта, которые включают:
        -   **PCP (Priority Code Point):** 3 бита для приоритезации трафика ([QoS](./qos.md)).
        -   **DEI (Drop Eligible Indicator):** 1 бит, указывает, можно ли отбросить кадр при перегрузке сети.
        -   **VID (VLAN Identifier):** **12 бит**, сам идентификатор VLAN.
3.  После тега следует поле с настоящим `EtherType` исходного протокола (например, `0x0800` для IPv4), а затем уже данные.

Из-за добавления 4-байтового тега максимальный размер Ethernet-кадра был увеличен с 1518 до 1522 байт.

Современные сетевые адаптеры, как правило, поддерживают стандарт 802.1Q и могут сами добавлять/удалять теги, что полезно для серверов, подключенных к нескольким VLAN одновременно (например, в средах виртуализации).
