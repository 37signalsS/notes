# VLAN — виртуальные локальные сети

## Определения

**VLAN (Virtual Local Area Network — виртуальная локальная сеть)** — технология канального уровня (L2), позволяющая логически разделить одну физическую сетевую инфраструктуру на несколько независимых широковещательных доменов.

**Широковещательный домен (Broadcast Domain)** — сегмент сети, в котором широковещательный кадр (с MAC-адресом назначения `FF:FF:FF:FF:FF:FF`) доставляется всем устройствам. VLAN ограничивает распространение таких кадров рамками одного идентификатора (VLAN ID).

**IEEE 802.1Q** — основной промышленный стандарт тегирования трафика, который определяет добавление 4-байтового тега в Ethernet-кадр для идентификации принадлежности к конкретной VLAN.

> **См. также:** [Формат кадра 802.1Q](./VLAN/vlan_8021q_frame.md), [Модель OSI](../OSI_TCP_IP_Model/osi_model.md)

## Основные концепции

### Назначение и преимущества

Использование VLAN позволяет отойти от физической топологии и группировать устройства по логическому или функциональному признаку.

| Преимущество | Описание |
| :--- | :--- |
| **Изоляция трафика** | Устройства в разных VLAN изолированы на L2. Это предотвращает утечку данных и широковещательные штормы между сегментами. |
| **Повышение безопасности** | Критически важные сервисы (управление, БД) отделяются от общих сетей, что снижает поверхность атаки. |
| **Оптимизация** | Уменьшение размера широковещательного домена снижает нагрузку на CPU хостов и сетевое оборудование. |
| **Гибкость управления** | Перемещение пользователя в другой отдел требует лишь смены настроек порта на коммутаторе, а не перекладки кабеля. |

### Типы портов коммутатора

Для работы с VLAN порты коммутатора настраиваются в одном из режимов:

- **Access-порт (порт доступа):** принадлежит одной VLAN. Предназначен для подключения конечных устройств (ПК, серверы), которые не понимают тегирование. Весь входящий нетегированный трафик помечается VLAN ID порта. Исходящий трафик передаётся без тега.
- **Trunk-порт (магистральный порт):** передаёт трафик нескольких VLAN одновременно. Кадры на таких портах обязательно тегируются (согласно 802.1Q), чтобы принимающая сторона могла определить их принадлежность. Используется для связи коммутаторов или подключения к гипервизорам.
- **Hybrid-порт:** может передавать как тегированный, так и нетегированный трафик для разных VLAN (специфично для некоторых вендоров).

### Принцип работы коммутации с VLAN

1. **Приём кадра:** при поступлении кадра на access-порт коммутатор сопоставляет его с VLAN ID этого порта.
2. **Коммутация:** решение о пересылке принимается только в пределах портов, принадлежащих этой же VLAN.
3. **Передача через Trunk:** если получатель находится на другом коммутаторе, в кадр вставляется тег 802.1Q с номером VLAN.
4. **Выдача получателю:** перед передачей в access-порт на стороне получателя тег удаляется.

### Меж-VLAN маршрутизация

Поскольку VLAN изолированы на канальном уровне (L2), для связи между ними требуется устройство сетевого уровня (L3):
- **Router-on-a-Stick:** маршрутизатор подключается через trunk-порт, на котором создаются виртуальные сабинтерфейсы.
- **L3-коммутатор (Multilayer Switch):** выполняет маршрутизацию на аппаратном уровне через интерфейсы SVI (Switch Virtual Interface).

Подробнее: **[Меж-VLAN маршрутизация](./VLAN/vlan_inter_vlan_routing.md)**.

## Практические сценарии

### Сценарий 1: Изоляция арендаторов в бизнес-центре

**Задача:** два офиса подключены к одному коммутатору, но не должны «видеть» трафик друг друга.

- **Офис 1 (Разработка):** порты 1-10 назначены в **VLAN 10**.
- **Офис 2 (Бухгалтерия):** порты 11-20 назначены в **VLAN 20**.

**Результат:** ARP-запросы от разработчиков не доходят до бухгалтерии, трафик полностью изолирован на уровне L2.

### Сценарий 2: Связь двух коммутаторов

**Задача:** объединить VLAN 10 на двух этажах здания.

- Порт 24 на обоих коммутаторах настраивается как **Trunk**.
- Настраивается список разрешённых VLAN (allowed vlan 10).
- При передаче кадра из порта 1 (VLAN 10) первого коммутатора в порт 1 второго коммутатора, кадр проходит через магистраль с тегом 10.

### Сценарий 3: Настройка в Linux

В Linux VLAN реализуются через создание сабинтерфейсов над физическим сетевым адаптером.

```bash
# Создание интерфейса для VLAN 10 поверх eth0
sudo ip link add link eth0 name eth0.10 type vlan id 10
sudo ip link set eth0.10 up
sudo ip addr add 192.168.10.1/24 dev eth0.10
```
Подробнее: **[VLAN в Linux: настройка и диагностика](./VLAN/vlan_linux_diagnostics.md)**.

## Дополнительная информация

### Рекомендации по проектированию (Best Practices)

1. **Принцип «Один VLAN = Одна подсеть»:** упрощает маршрутизацию, диагностику и настройку правил фаервола.
2. **Безопасность портов:**
   - Неиспользуемые порты должны быть отключены (`shutdown`) и переведены в неиспользуемую «чёрную» VLAN (например, VLAN 999).
   - Ограничивайте количество разрешённых VLAN на trunk-портах (`switchport trunk allowed vlan`).
3. **Native VLAN:**
   - Изменяйте стандартную Native VLAN (обычно ID 1) на неиспользуемую для защиты от атак типа VLAN Hopping.
   - Обеспечивайте совпадение Native VLAN на обоих концах транка. См.: **[Trunk и Native VLAN](./VLAN/vlan_trunk_native.md)**.
4. **Управление:** выделяйте отдельную Management VLAN для доступа к интерфейсам управления сетевого оборудования.
