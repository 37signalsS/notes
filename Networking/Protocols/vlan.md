# VLAN (Virtual Local Area Network) и стандарт IEEE 802.1Q

## Определения

**VLAN (виртуальная локальная сеть)** — технология канального уровня (L2), позволяющая логически разделить одну физическую сеть на несколько независимых широковещательных доменов.

**Ключевая особенность:** Устройства в разных VLAN не могут взаимодействовать напрямую на L2, даже при подключении к одному физическому коммутатору. Для меж-VLAN маршрутизации требуется L3-устройство (маршрутизатор или L3-коммутатор).

**Стандарт:** IEEE 802.1Q — определяет формат тегирования кадров.

## Базовые концепции

### Назначение VLAN

| Преимущество | Описание |
|-------------|----------|
| **Безопасность** | Изоляция сетей разных отделов, компаний, групп пользователей |
| **Оптимизация** | Ограничение broadcast-трафика (ARP-запросы не выходят за пределы VLAN) |
| **Гибкость** | Группировка по логическому признаку, а не физическому расположению |

### Пример использования VLAN

**Сценарий:** Бизнес-центр с несколькими арендаторами.

```
                    [Один физический коммутатор]
                              |
        +---------------------+---------------------+
        |                                           |
   [Офис 1: Разработка]                     [Офис 2: Турагентство]
   Хост 1 (VLAN 10)                         Хост 3 (VLAN 20)
   Хост 2 (VLAN 10)                         Хост 4 (VLAN 20)
   192.168.10.0/24                          192.168.20.0/24
```

**Проблема:** Все хосты подключены к одному коммутатору, но требуется изоляция для безопасности.

**Решение:** VLAN с назначением по портам (Port-Based VLAN):
- **VLAN ID = 10** для портов с хостами 1 и 2
- **VLAN ID = 20** для портов с хостами 3 и 4

**Результат:**
- Широковещательные пакеты (MAC `FF:FF:FF:FF:FF:FF`) от хоста 1 достигают только хоста 2
- Хосты 3 и 4 не получают трафик из VLAN 10
- Меж-VLAN взаимодействие возможно только через L3-устройство (маршрутизатор)

**Альтернативное мышление:** При создании VLAN внутри физического коммутатора образуется виртуальный коммутатор с назначенными портами. Весь трафик коммутируется только внутри этого виртуального коммутатора.

> **Port-Based VLAN** — альтернативное название VLAN по портам (access VLAN).

### Типы портов VLAN

| Тип | Описание | Использование |
|-----|----------|---------------|
| **Access Port** | Принадлежит одному VLAN, трафик нетегированный | Подключение конечных устройств (ПК, серверы) |
| **Trunk Port** | Пропускает трафик нескольких VLAN с тегами 802.1Q | Соединение коммутаторов, подключение к маршрутизаторам/гипервизорам |
| **Hybrid Port** | Может передавать тегированный и нетегированный трафик для разных VLAN | Гибкая настройка (некоторые вендоры) |

### Access VLAN (по портам)

**Принцип работы:**

```
Коммутатор получает пакет на access-порт:
│
├─ 1. Определяет VLAN ID порта (например, VLAN 10)
│
├─ 2. Коммутирует пакет ТОЛЬКО в рамках VLAN 10:
│   ├─ Если destination MAC известен → отправка на конкретный порт VLAN 10
│   ├─ Если destination MAC неизвестен → flooding на все порты VLAN 10
│   └─ Если broadcast (FF:FF:FF:FF:FF:FF) → flooding на все порты VLAN 10
│
└─ 3. Пакеты из других VLAN (например, VLAN 20) игнорируются
```

**Пример с двумя коммутаторами:**

```
[Хост 1] ──(VLAN 10)── [Коммутатор 1] ════Trunk════ [Коммутатор 2] ──(VLAN 10)── [Хост 2]
[Хост 3] ──(VLAN 20)── [Коммутатор 1] ════Trunk════ [Коммутатор 2] ──(VLAN 20)── [Хост 4]
```

**Процесс передачи ping от хоста 1 к хосту 2:**

1. **Хост 1 отправляет ARP-запрос** (broadcast) для определения MAC-адреса хоста 2
2. **Коммутатор 1 получает пакет** на access-порт с VLAN ID = 10
3. **Коммутация внутри VLAN 10:** Пакет передаётся только на порты VLAN 10, включая trunk-порт
4. **Добавление тега:** На trunk-порту коммутатор 1 добавляет тег 802.1Q с VLAN ID = 10
5. **Коммутатор 2 получает тегированный пакет** на trunk-порт
6. **Чтение тега:** Коммутатор 2 определяет VLAN ID = 10 и коммутирует только в порты VLAN 10
7. **Терминация:** Перед отправкой хосту 2 тег удаляется (access-порт)
8. **Хост 2 получает ARP-запрос** и отправляет ARP-ответ аналогичным путём

**Результат:** Хосты 3 и 4 (VLAN 20) не получают широковещательные пакеты из VLAN 10, несмотря на подключение к тем же коммутаторам.

> **Tagging VLAN** (англ.) — альтернативное название VLAN по тегам. В русской литературе также встречается как «VLAN с метками».

### Native VLAN

**Native VLAN** — специальный VLAN на trunk-портах, используемый для передачи нетегированного трафика между коммутаторами.

**Назначение:**

| Проблема | Решение через Native VLAN |
|----------|---------------------------|
| **Служебные протоколы** (STP, CDP, LACP) не понимают теги 802.1Q | Пакеты отправляются без тега в Native VLAN |
| **Пакет без тега на trunk-порту** — что делать? | Автоматически относится к Native VLAN |
| **Обратная совместимость** со старыми устройствами | Нетегированный трафик проходит корректно |

**Принцип работы:**

```
Trunk порт отправляет кадр:
├─ Тегированный (VLAN 10, 20, 30...) → добавляется тег 802.1Q
└─ Native VLAN (по умолчанию VLAN 1) → тег НЕ добавляется

Trunk порт получает кадр:
├─ С тегом → обрабатывается согласно VLAN ID
└─ Без тега → относится к Native VLAN
```

**Конфигурация (Cisco):**

```cisco
! Изменить Native VLAN на trunk-порту
interface GigabitEthernet0/1
 switchport trunk native vlan 99
!
! VLAN 99 должен существовать и не должен содержать пользовательский трафик
```

**Best Practices:**

- **Изменять Native VLAN с VLAN 1** на отдельный служебный VLAN (например, 99 или 999)
- **Не передавать пользовательский трафик** в Native VLAN
- **Native VLAN должен совпадать** на обоих концах trunk-соединения (иначе возможна потеря пакетов)

### Формат кадра 802.1Q

Стандартный Ethernet-кадр модифицируется добавлением 4-байтового тега:

```
| Dest MAC (6) | Src MAC (6) | TPID 0x8100 (2) | TCI (2) | EtherType (2) | Data (46-1500) | FCS (4) |
```

**Поля тега:**

| Поле | Размер | Описание |
|------|--------|----------|
| **TPID (Tag Protocol Identifier)** | 2 байта | `0x8100` — указывает на тегированный кадр. Размещается на месте поля Тип/Длина стандартного Ethernet-кадра. Принимающая сторона сразу определяет, что имеет дело с заголовком 802.1Q. |
| **TCI (Tag Control Information)** | 2 байта | Управляющая информация: |
| &nbsp;&nbsp;— PCP (Priority Code Point) | 3 бита | Приоритет для [QoS](../Concepts/qos.md) (0-7). Используется стандартом IEEE 802.1p для задания приоритета передаваемого трафика (class of service). 0 — наименьший приоритет, 7 — наивысший. |
| &nbsp;&nbsp;— DEI (Drop Eligible Indicator) | 1 бит | Индикатор допустимости удаления. Может использоваться отдельно или совместно с PCP для указания кадров, которые могут быть отброшены при наличии перегрузки. |
| &nbsp;&nbsp;— VID (VLAN Identifier) | 12 бит | ID VLAN (1-4094, 0 и 4095 зарезервированы). Указывает, какому VLAN ID принадлежит кадр. |

**Ключевая особенность:** Именно поле **VLAN Identifier** позволяет прямо в пакете передать информацию о его принадлежности к конкретному VLAN ID.

**MTU:** Из-за тега максимальный размер кадра увеличивается с 1518 до 1522 байт.

### Принцип тегирования

1. **Вход кадра:** Кадр от конечного устройства поступает на access-порт коммутатора
2. **Добавление тега:** Коммутатор добавляет 4-байтовый тег с VLAN ID
3. **Передача по trunk:** Тегированный кадр передаётся другому коммутатору
4. **Чтение тега:** Принимающий коммутатор читает VLAN ID и направляет кадр
5. **Удаление тега (Терминация):** Перед отправкой конечному устройству тег удаляется

**Терминация** — процесс удаления VLAN-тега из пакета перед отправкой конечному устройству.

### Trunk VLAN (по тегам/меткам)

**Задача:** Передать трафик нескольких VLAN между коммутаторами по одному физическому соединению.

**Проблема избыточности:** Без тегирования потребовалось бы по одному физическому кабелю на каждый VLAN, что неэффективно (порты на коммутаторах ограничены).

**Решение:** Стандарт IEEE 802.1Q описывает процедуру тегирования трафика. 802.1Q помещает внутрь Ethernet-фрейма 4-байтовый тег с информацией о принадлежности к VLAN.

> **На английском:** Tagging VLAN. В русской литературе: «VLAN по тегам», «VLAN с метками», «тегированный VLAN».

#### Заголовок 802.1Q в Ethernet-фрейме

**Расположение тега:**
```
| Dest MAC (6) | Src MAC (6) | 802.1Q Tag (4) | EtherType/Length (2) | Data (46-1500) | FCS (4) |
                              ↑
                              Тег вставляется между Src MAC и EtherType
```

**Размер тега:** 4 байта

**Состав тега 802.1Q:**

| Поле | Размер | Описание |
|------|--------|----------|
| **TPID (Tag Protocol Identifier)** | 2 байта | `0x8100` — идентифицирует кадр как тегированный 802.1Q |
| **TCI (Tag Control Information)** | 2 байта | Управляющая информация: |
| &nbsp;&nbsp;— PCP (Priority Code Point) | 3 бита | Приоритет QoS (0-7) по IEEE 802.1p |
| &nbsp;&nbsp;— DEI (Drop Eligitable Indicator) | 1 бит | Индикатор допустимости отбрасывания при перегрузке |
| &nbsp;&nbsp;— VID (VLAN Identifier) | 12 бит | ID VLAN (1-4094, 0 и 4095 зарезервированы) |

### Пример передачи пакета через trunk-соединение

**Топология:**
```
[Хост 1] --(Access, VLAN 10)--> [Коммутатор 1] <==Trunk==> [Коммутатор 2] --(Access, VLAN 10)--> [Хост 2]
```

**Процесс передачи пакета от хоста 1 к хосту 2:**

1. **Коммутатор 1 получает пакет** от хоста 1, смотрит настройку порта (Access, VLAN ID = 10) и назначает пакет в VLAN 10
2. **Коммутация внутри VLAN 10:** Пакет разрешено коммутировать только между портами, которым разрешено работать в VLAN 10. На основе таблицы коммутации пакет отправляется в порт, подключенный к коммутатору 2
3. **Добавление тега:** Так как порт между коммутатором 1 и 2 сконфигурирован как Trunk, коммутатор 1 перед отправкой добавляет в пакет тег (Tag) с информацией о VLAN (VLAN ID = 10)
4. **Коммутатор 2 получает пакет** на Trunk-порт с VLAN ID = 10, значит пакет можно коммутировать только в порты, принадлежащие VLAN ID = 10
5. **Коммутация к хосту 2:** На основе таблицы коммутации пакет отправляется в порт, куда подключён хост 2
6. **Терминация:** Хост 2 подключён на Access-порт с VLAN ID = 10, значит перед отправкой пакета тег удаляется

**Настройка коммутатора (пример):**

```cisco
! Назначение портов в VLAN
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 10

! Настройка trunk-порта
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

## Практические сценарии

### Меж-VLAN маршрутизация (Router-on-a-Stick)

**Задача:** Обеспечить связь между устройствами в разных VLAN.

**Ключевая особенность:** Устройства в разных VLAN не могут взаимодействовать напрямую на L2. Требуется L3-устройство (маршрутизатор или L3-коммутатор).

**Зачем нужна маршрутизация между VLAN:**

VLAN позволяют разделить один большой широковещательный домен на несколько небольших. Например, в сети компании на 1000 хостов можно выделить:
- Отдел бухгалтерии
- Серверную
- Разработчиков
- Тестировщиков

**Без VLAN** был бы один большой широковещательный домен, что вызывало бы:
- Проблемы с широковещательными пакетами (ARP-запросы на все 1000 хостов)
- Проблемы с безопасностью (любой хост видит трафик других)

**С VLAN** требуется маршрутизация для взаимодействия между отделами (например, разработчики хотят иметь доступ к серверам).

#### Схема 1: Маршрутизация через отдельные физические интерфейсы

**Топология:**
```
[Хост 1: 192.168.1.0/24] --(VLAN 10)--> [Маршрутизатор] <--(VLAN 20)-- [Хост 2: 10.0.0.0/24]
                                    (192.168.1.1)    (10.0.0.1)
```

**Процесс передачи пакета:**

1. Пакет от хоста 1 приходит на порт коммутатора с VLAN 10 → коммутация только между портами VLAN 10
2. Коммутатор отправляет пакет на маршрутизатор через порт в VLAN 10
3. Маршрутизатор получает пакет на интерфейс 192.168.1.1:
   - Разбирает IP-заголовок
   - Определяет, что IP получателя (10.0.0.2) не его
   - На основе таблицы маршрутизации отправляет пакет в интерфейс 10.0.0.1
4. Пакет приходит на порт коммутатора с VLAN 20 → коммутация только между портами VLAN 20
5. Коммутатор отправляет пакет хосту 2

**Недостаток:** Занимает по одному физическому порту коммутатора на каждый VLAN.

#### Схема 2: Маршрутизация через сабинтерфейсы (ROAS)

**ROAS (Router-on-a-Stick)** — схема маршрутизации между VLAN через один физический интерфейс с использованием сабинтерфейсов.

**Сабинтерфейс (sub-interface)** — виртуальный интерфейс сетевого уровня, который умеет отправлять и получать пакеты с VLAN-тегом (IEEE 802.1Q).

**Топология:**
```
[Хост 1: 192.168.1.0/24] --(VLAN 10)--> [Коммутатор] <==Trunk==> [Маршрутизатор]
                                                          (1 физический порт)
                                                           ├─ subif 192.168.1.1/24 (VLAN 10)
                                                           └─ subif 10.0.0.1/24 (VLAN 20)
[Хост 2: 10.0.0.0/24] ----(VLAN 20)--> [Коммутатор]
```

**Конфигурация коммутатора:**
- Порт к маршрутизатору настраивается как **Trunk** — пропускает трафик нескольких VLAN с тегами 802.1Q
- Остальные порты — **Access** — принадлежат одному VLAN, трафик нетегированный

**Процесс передачи пакета:**

1. Пакет от хоста 1 приходит на access-порт коммутатора с VLAN 10
2. Коммутатор отправляет пакет на маршрутизатор через trunk-порт, добавляя VLAN-тег (VLAN Id = 10)
3. Маршрутизатор получает пакет с VLAN-тегом:
   - Обрабатывается сабинтерфейсом 192.168.1.1 (настроен на VLAN 10)
   - Разбирает IP-заголовок
   - Определяет, что IP получателя (10.0.0.2) не его
   - На основе таблицы маршрутизации отправляет пакет в сабинтерфейс 10.0.0.1
   - Добавляет VLAN-тег со значением VLAN Id = 20
4. Пакет с VLAN Id = 20 приходит на trunk-порт коммутатора → коммутация между портами VLAN 20
5. Коммутатор отправляет пакет хосту 2

**Преимущества ROAS:**
- Экономия портов коммутатора (один физический порт вместо двух и более)
- Гибкость — можно добавлять VLAN без дополнительных физических подключений
- Масштабируемость — до 4094 VLAN на один физический интерфейс

**Конфигурация (Cisco):**
```cisco
! Сабинтерфейс для VLAN 10
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.1.1 255.255.255.0

! Сабинтерфейс для VLAN 20
interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.0.0.1 255.255.255.0
```

**Настройка в Linux:**
```bash
# Включить IP forwarding
sysctl -w net.ipv4.ip_forward=1

# Создать VLAN-интерфейсы с IP
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20

ip addr add 192.168.1.1/24 dev eth0.10
ip addr add 10.0.0.1/24 dev eth0.20

ip link set eth0.10 up
ip link set eth0.20 up

# Настроить NAT (если нужен выход в интернет)
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

**Терминология:** Запись «VLAN 10» является сокращением от «VLAN Id = 10» и общепринята в документации.

### Настройка VLAN в Linux

**Создание VLAN-интерфейсов:**

```bash
# Создать VLAN 10 на eth0
ip link add link eth0 name eth0.10 type vlan id 10

# Создать VLAN 20 на eth0
ip link add link eth0 name eth0.20 type vlan id 20

# Назначить IP-адреса
ip addr add 192.168.10.1/24 dev eth0.10
ip addr add 192.168.20.1/24 dev eth0.20

# Активировать интерфейсы
ip link set eth0.10 up
ip link set eth0.20 up

# Проверка
ip -d link show
```

**Настройка через NetworkManager (nmtui/nmcli):**

```bash
nmcli connection add type vlan ifname enp0s3.20 dev enp0s3 id 20
nmcli connection modify enp0s3.20 ipv4.addresses 192.168.20.1/24
nmcli connection modify enp0s3.20 ipv4.method manual
nmcli connection up enp0s3.20
```

**Постоянная конфигурация (Netplan, Ubuntu):**

**Полная документация:** **[Настройка Netplan](../../Linux/Networking/Settings/Persistent_Network/index.md#3-ubuntu-1710-netplan)** — примеры bonding, VLAN, маршрутов и DNS.

```yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: no
  vlans:
    eth0.10:
      id: 10
      link: eth0
      addresses: [192.168.10.1/24]
    eth0.20:
      id: 20
      link: eth0
      addresses: [192.168.20.1/24]
```

### Диагностика VLAN

**Проверка конфигурации:**

```bash
# Показать VLAN-интерфейсы
ip -d link show | grep vlan

# Проверка статистики
ip -s link show eth0.10

# tcpdump для отладки тегов
tcpdump -i eth0 -e vlan
tcpdump -i eth0 'vlan[0:2] & 0x0fff = 10'  # Только VLAN 10
```

**Типичные проблемы:**

| Проблема | Симптомы | Решение |
|----------|----------|---------|
| **Native VLAN mismatch** | Потеря пакетов на trunk | Убедиться, что native VLAN совпадает на обоих концах |
| **VLAN не разрешён на trunk** | Трафик не проходит | Добавить VLAN в allowed list на trunk-порту |
| **Отсутствие L3-маршрутизации** | Нет связи между VLAN | Настроить inter-VLAN routing на маршрутизаторе/L3-коммутаторе |

## Дополнительная информация

### MTU и VLAN

**Вопрос:** Требуется ли изменять MTU при включении VLAN tagging?

**Ответ:** **Нет, не требуется.**

**Обоснование:**

Стандартный Ethernet-кадр:
- 14 байт — заголовок Ethernet
- до 1500 байт — данные
- 4 байта — CRC32 (контрольная сумма)
- **Итого:** 1518 байт

С тегом 802.1Q добавляется 4 байта → **1522 байта**.

**Почему не нужно менять MTU:**

- Современные коммутаторы и сетевые карты по умолчанию поддерживают **baby giant frames** (1522 байта)
- MTU относится к **IP-уровню** (L3) и не включает заголовок Ethernet (L2)
- VLAN тег добавляется на L2 и не влияет на расчёт MTU для IP-пакетов

**Когда может потребоваться настройка:**

- Старое оборудование (15+ лет) может не поддерживать кадры >1518 байт
- При использовании **Q-in-Q** (802.1ad, два тега VLAN) → размер кадра 1526 байт
- В специфических сценариях с jumbo frames требуется согласование MTU по всей цепочке

### Безопасность VLAN

**Атаки:**

- **VLAN Hopping:** Злоумышленник отправляет тегированные кадры с access-порта
- **Double Tagging:** Два тега 802.1Q для обхода изоляции
- **Switch Spoofing:** Эмуляция коммутатора для получения trunk-доступа

**Защита:**

- Отключить DTP (Dynamic Trunking Protocol) на пользовательских портах
- Настроить access-порты явно
- Использовать private VLAN для дополнительной изоляции
- Включить BPDU Guard на edge-портах
