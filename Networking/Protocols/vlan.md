# VLAN (Virtual Local Area Network) и стандарт IEEE 802.1Q

## Определения

**VLAN (виртуальная локальная сеть)** — это технология [канального уровня (L2)](../OSI_TCP_IP_Model/data_link_layer.md), которая позволяет логически разделить одну физическую сеть на несколько независимых широковещательных доменов. Эта технология реализуется на управляемых [коммутаторах](../../OSI_TCP_IP_Model/data_link_layer.md#коммутатор-switch).

Компьютеры, находящиеся в разных VLAN, не могут взаимодействовать друг с другом напрямую, даже если они подключены к одному и тому же физическому коммутатору.

## Базовые концепции

### Зачем нужны VLAN?

1. **Безопасность:** Изоляция сетей разных отделов, компаний или групп пользователей. Например, в бизнес-центре сеть каждого арендатора можно выделить в отдельный VLAN, чтобы их трафик не пересекался.
2. **Оптимизация производительности:** Ограничение широковещательного трафика. Широковещательные кадры (например, [ARP-запросы](./arp.md)) распространяются только в пределах своего VLAN, а не по всей физической сети. Это снижает бесполезную нагрузку на конечные устройства и сетевое оборудование.
3. **Гибкость:** VLAN позволяют группировать хосты по логическому признаку (отдел, проект), а не по физическому расположению. Администраторы могут легко перемещать устройства между VLAN без необходимости физического переключения кабелей.

## Практические сценарии

### Настройка VLAN с использованием `ip` и `bridge` в Linux

VLAN (Virtual Local Area Network) — это способ разделения одной физической сети на несколько логически изолированных сетей. Это полезно для управления трафиком, повышения безопасности и уменьшения широковещательной нагрузки.

**Пример задачи:**
Имеется интерфейс `eth0`, подключённый к коммутатору, поддерживающему VLAN. Мы хотим настроить две VLAN:

- VLAN 10: с IP-адресом `192.168.10.1/24`.
- VLAN 20: с IP-адресом `192.168.20.1/24`.

#### 1. Установка необходимых пакетов

В современных дистрибутивах Linux утилиты `ip` и `bridge` уже включены в состав пакета `iproute2`. Убедитесь, что он установлен:

```bash
sudo apt install iproute2  # Для Debian/Ubuntu
sudo yum install iproute   # Для CentOS/RHEL
```

#### 2. Настройка VLAN-интерфейсов

Создайте VLAN-интерфейсы. С помощью команды `ip link` создадим виртуальные интерфейсы для VLAN 10 и VLAN 20, привязанные к физическому интерфейсу `eth0`:

```bash
sudo ip link add link eth0 name eth0.10 type vlan id 10
sudo ip link add link eth0 name eth0.20 type vlan id 20
```

- `link eth0`: Указывает родительский физический интерфейс.
- `name eth0.10`: Задает имя нового виртуального интерфейса (конвенция: `interface.vlan_id`).
- `type vlan id 10`: Указывает, что мы создаем интерфейс типа VLAN с тегом `10`.

#### 3. Назначение IP-адресов и активация

Назначьте IP-адреса VLAN-интерфейсам и включите их:

```bash
sudo ip addr add 192.168.10.1/24 dev eth0.10
sudo ip addr add 192.168.20.1/24 dev eth0.20

sudo ip link set eth0.10 up
sudo ip link set eth0.20 up
```

#### 4. Проверка конфигурации

Проверьте, что интерфейсы созданы и включены:

```bash
ip -d link show
```

Вы должны увидеть интерфейсы `eth0.10@eth0` и `eth0.20@eth0`, связанные с `eth0`.

#### 5. (Опционально) Настройка VLAN-мостов

Если требуется подключить несколько VLAN к мосту (например, для виртуализации):
Создайте мост:

```bash
sudo ip link add name br-vlan type bridge
```

Добавьте VLAN к мосту:

```bash
sudo ip link set eth0.10 master br-vlan
sudo ip link set eth0.20 master br-vlan
```

Назначьте IP-адрес мосту (если требуется) и включите его:

```bash
sudo ip addr add 192.168.30.1/24 dev br-vlan
sudo ip link set br-vlan up
```

#### 6. Удаление VLAN

Чтобы удалить VLAN-интерфейс:

```bash
sudo ip link delete eth0.10
sudo ip link delete eth0.20
```

> **Важно:** Как и другие команды `iproute2`, эти настройки являются временными. Чтобы сделать их постоянными, используйте конфигурационные файлы вашей системы (например, `/etc/netplan/` в Ubuntu или `/etc/sysconfig/network-scripts/` в CentOS). Подробнее см. в заметке: [Постоянная настройка сети в Linux](../../Linux/Networking/Settings/persistent_network_configuration.md).

## Дополнительная информация

### Формат кадра 802.1Q

Чтобы добавить тег, не нарушая совместимость, стандарт 802.1Q изменяет структуру Ethernet-кадра:

1. В поле **`EtherType`** стандартного кадра вместо кода протокола верхнего уровня (например, `0x0800` для IPv4) вставляется специальное значение **`0x8100`**. Это значение указывает, что данный кадр является тегированным (tagged frame).
2. Сразу после этого поля добавляется **4-байтовый тег**, который содержит:
    - **TPID (Tag Protocol Identifier):** 2 байта, всегда `0x8100`.
    - **TCI (Tag Control Information):** 2 байта, которые включают:
        - **PCP (Priority Code Point):** 3 бита для приоритезации трафика ([QoS](../Concepts/qos.md)).
        - **DEI (Drop Eligible Indicator):** 1 бит, указывает, можно ли отбросить кадр при перегрузке сети.
        - **VID (VLAN Identifier):** **12 бит**, сам идентификатор VLAN.
3. После тега следует поле с настоящим `EtherType` исходного протокола (например, `0x0800` для IPv4), а затем уже данные.

Из-за добавления 4-байтового тега максимальный размер Ethernet-кадра был увеличен с 1518 до 1522 байт.

Современные сетевые адаптеры, как правило, поддерживают стандарт 802.1Q и могут сами добавлять/удалять теги, что полезно для серверов, подключенных к нескольким VLAN одновременно (например, в средах виртуализации).
