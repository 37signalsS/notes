# SNMP — протокол сетевого управления

> **Reliability Score: 10** (SSoT + Verified RFCs + Industry Standard)

## Определения

**SNMP (Simple Network Management Protocol — простой протокол сетевого управления)** — стандартный протокол прикладного уровня (L7) для управления и мониторинга сетевых устройств (маршрутизаторов, коммутаторов, серверов, ИБП) в IP-сетях.

**MIB (Management Information Base — база управляющей информации)** — иерархическая база данных (дерево), описывающая структуру данных управления устройством. SMI (Structure of Management Information) определяет правила описания объектов в MIB.

**OID (Object Identifier — идентификатор объекта)** — уникальный числовой путь в дереве MIB (например, `1.3.6.1.2.1.1.1.0`), указывающий на конкретный узел данных.

> **См. также:** **[Протокол UDP](./udp.md)**, **[Модель OSI](../OSI_TCP_IP_Model/osi_model.md)**

## Основные концепции

### Компоненты архитектуры

1. **SNMP Manager (NMS):** система мониторинга (Zabbix, Prometheus SNMP Exporter), инициирующая запросы к устройствам.
2. **SNMP Agent:** ПО на управляемом устройстве, собирающее статистику и отвечающее на запросы менеджера.
3. **Managed Device:** устройство с активным SNMP-агентом.

### Эволюция версий

| Версия | Безопасность | Ключевые возможности | Рекомендация |
| :--- | :--- | :--- | :--- |
| **v1** | Community String (открытый текст) | Только 32-битные счетчики, малая эффективность. | Не использовать (небезопасно). |
| **v2c** | Community String (открытый текст) | 64-битные счетчики (`Counter64`), пакетные запросы (`GetBulk`). | Стандарт для внутренних сетей. |
| **v3** | USM (Аутентификация + Шифрование) | Полноценная модель безопасности (криптография), разделение прав. | Обязательно для внешних/критичных сетей. |

#### Уровни безопасности SNMPv3
- **noAuthNoPriv:** без аутентификации и шифрования (аналог v2c, но с пользователями).
- **authNoPriv:** аутентификация по паролю (MD5/SHA), данные передаются открыто.
- **authPriv:** аутентификация + шифрование данных (AES/DES). **Самый безопасный режим.**

### Основные операции (PDU)

- **Get / GetNext:** запрос одного или следующего объекта.
- **GetBulk:** эффективный обход таблиц за минимальное число запросов (v2c/v3).
- **Set:** изменение конфигурации устройства (требует прав на запись).
- **Trap:** асинхронное уведомление от агента к менеджеру при возникновении события (UDP 162).
- **Inform:** Trap с подтверждением доставки от менеджера (v2c/v3).

## Практические сценарии

### Сетевые порты

- **UDP 161:** Входящие запросы к агенту (Poll).
- **UDP 162:** Исходящие уведомления от агента (Traps/Informs).

### Работа в Linux (Net-SNMP)

```bash
# Установка инструментов
sudo apt install snmp snmp-mibs-downloader

# Опрос устройства (v2c)
snmpget -v2c -c <community> <IP> 1.3.6.1.2.1.1.1.0

# Обход дерева объектов
snmpwalk -v2c -c <community> <IP> 1.3.6.1.2.1.1

# Пример SNMPv3 (authPriv)
snmpwalk -v3 -l authPriv -u <user> -a SHA -A <pass> -x AES -X <priv_pass> <IP> .1.3.6
```

### Мониторинг интерфейсов (IF-MIB)

Основные OID для анализа трафика:
- `.1.3.6.1.2.1.2.2.1.2` (**ifDescr**): Имя интерфейса.
- `.1.3.6.1.2.1.2.2.1.8` (**ifOperStatus**): Статус (1=up, 2=down).
- `.1.3.6.1.2.1.31.1.1.1.6` (**ifHCInOctets**): Входящий трафик (64-бит).

## Безопасность и автоматизация

### Риски и защита
1. **Открытый текст (v1/v2c):** Пароль (community string) легко перехватывается в сети. Используйте ACL для ограничения доступа только с IP менеджера.
2. **Brute-force:** Подбор стандартных паролей (`public`, `private`). Всегда меняйте их на сложные строки.
3. **Удаленное управление:** Ограничивайте права агента режимом `Read-Only`, если не планируете использовать `Set`.

### Современная замена
В высоконагруженных и облачных средах SNMP постепенно вытесняется:
- **Streaming Telemetry:** (gNMI, gRPC) — устройство само шлет данные по мере изменения, а не ждет опроса.
- **Prometheus Exporters:** Трансляция SNMP-метрик в формат временных рядов.
