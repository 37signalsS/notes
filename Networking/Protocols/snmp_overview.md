# SNMP — протокол сетевого управления

## Определения

**SNMP (Simple Network Management Protocol — простой протокол сетевого управления)** — стандартный протокол прикладного уровня для управления и мониторинга сетевых устройств (маршрутизаторов, коммутаторов, серверов, принтеров) в IP-сетях.

**MIB (Management Information Base — база управляющей информации)** — иерархическая база данных, описывающая структуру данных управления устройством. Каждому объекту в MIB соответствует уникальный идентификатор OID.

**OID (Object Identifier — идентификатор объекта)** — числовой путь в дереве MIB (например, `1.3.6.1.2.1.1.1.0`), указывающий на конкретный параметр (например, описание системы или состояние порта).

> **См. также:** [Протокол UDP](./udp.md), [Модель OSI](../OSI_TCP_IP_Model/osi_model.md)

## Основные концепции

### Компоненты SNMP

1. **SNMP Manager (NMS — Network Management System):** система мониторинга, которая опрашивает устройства и собирает данные (например, Zabbix, Prometheus с SNMP Exporter).
2. **SNMP Agent:** программное обеспечение на управляемом устройстве. Оно собирает локальную статистику и передает её менеджеру по запросу.
3. **Managed Device (Управляемое устройство):** сетевое оборудование или сервер, на котором запущен агент.

### Версии протокола

| Версия | Безопасность | Особенности |
| :--- | :--- | :--- |
| **v1** | Низкая (Community String) | Базовая версия, только 32-битные счетчики, отсутствие шифрования. |
| **v2c** | Низкая (Community String) | Наиболее распространена. Добавлены 64-битные счетчики и команда `GetBulk`. |
| **v3** | Высокая (User/Pass/Encryption) | Поддерживает аутентификацию и шифрование (MD5/SHA, DES/AES). Отраслевой стандарт безопасности. |

### Основные операции

- **Get:** запрос конкретного значения OID.
- **GetNext:** запрос следующего значения в дереве (обход таблиц).
- **GetBulk:** (v2/v3) запрос блока данных за один раз.
- **Set:** изменение параметра на устройстве (например, удаленное выключение интерфейса).
- **Trap:** неинициированное сообщение от агента менеджеру о событии (например, аварийное отключение питания).
- **Inform:** подтверждаемый Trap (менеджер должен подтвердить получение сообщения).

## Практические сценарии

### Используемые порты

- **UDP 161:** для входящих запросов к агенту (Manager → Agent).
- **UDP 162:** для получения уведомлений на стороне менеджера (Agent → Manager Trap).

### Утилиты командной строки в Linux

Для работы с SNMP в Linux используется пакет `net-snmp-utils`.

```bash
# Установка в Debian/Ubuntu
sudo apt update && sudo apt install snmp snmp-mibs-downloader

# Получение описания системы (v2c, community "public")
snmpget -v2c -c public <IP_ADDRESS> 1.3.6.1.2.1.1.1.0

# Обход всего дерева системной информации
snmpwalk -v2c -c public <IP_ADDRESS> 1.3.6.1.2.1.1
```

### Мониторинг сетевых интерфейсов

Для мониторинга трафика обычно используются OID из ветки `IF-MIB` (1.3.6.1.2.1.2):

- `ifDescr` (.1.3.6.1.2.1.2.2.1.2): описание интерфейса.
- `ifInOctets` (.1.3.6.1.2.1.2.2.1.10): входящий трафик (32-бит).
- `ifHCInOctets` (.1.3.6.1.2.1.2.2.1.6): входящий трафик (64-бит, требует v2c/v3).

## Дополнительная информация

### Сферы применения

1. **Мониторинг производительности:** сбор данных о загрузке CPU, использовании памяти и пропускной способности каналов.
2. **Инвентаризация:** автоматическое получение серийных номеров, версий ПО и конфигураций.
3. **Оповещение об инцидентах:** мгновенное получение Traps при изменении статуса порта или критических отказах оборудования.
