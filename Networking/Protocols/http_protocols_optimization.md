# Оптимизация HTTP-протоколов для снижения латентности

## HTTP/2

### Преимущества

* **Мультиплексирование** — несколько запросов/ответов через одно TCP-соединение
* **Сжатие заголовков (HPACK)** — уменьшает объём передаваемых метаданных
* **Server Push** — сервер может отправлять ресурсы до их запроса клиентом
* **Приоритизация потоков** — важные ресурсы получают больше bandwidth

### Проблема Head-of-Line Blocking

При потере пакетов в TCP, все потоки HTTP/2 внутри этого соединения блокируются до повторной передачи.

## HTTP/3 и QUIC

### Преимущества

* **Основан на QUIC (UDP)** — устраняет Head-of-Line Blocking на уровне транспорта
* **Встроенное шифрование (TLS 1.3)** — сокращает количество рукопожатий
* **Миграция соединений** — соединение сохраняется при смене IP-адреса
* **Улучшенная работа при потерях** — потеря пакета блокирует только один поток

### Снижение tail latency

HTTP/3/QUIC особенно эффективен при:
* Нестабильных каналах (мобильные сети)
* Высоком RTT
* Сетях с потерями

## Keepalive и пулинг соединений

### Проблема

Установка нового TCP/TLS-соединения требует:
* TCP handshake (1 RTT)
* TLS handshake (1-2 RTT)

### Решение

* **Keepalive** — поддержание "тёплых" соединений
* **Connection pooling** — повторное использование существующих соединений
* **Connection reuse** — использование того же TCP/TLS-контекста

### Настройка

```nginx
# Пример для Nginx
keepalive_timeout 65;
keepalive_requests 1000;

# Пул upstream-соединений
upstream backend {
    server 10.0.0.1:8080;
    keepalive 32;
}
```

## Балансировка нагрузки

### Оптимизации

* **Сокращение L4/L7-хопов** — минимизируйте количество прокси
* **Local connect-таргеты** — предпочитайте локальные соединения
* **Connection pinning** — привязывайте соединения к серверам для снижения latency

### Пример

```
Client -> Edge (L4) -> App Server

Вместо:
Client -> Edge (L4) -> Gateway (L7) -> App Server -> Backend
```

## Сравнение протоколов

| Характеристика | HTTP/1.1 | HTTP/2 | HTTP/3 |
|----------------|----------|--------|--------|
| Транспорт | TCP | TCP | QUIC (UDP) |
| Мультиплексирование | Нет | Да | Да |
| Head-of-Line Blocking | Да | Да (TCP) | Нет |
| Шифрование | Опционально | TLS 1.2+ | TLS 1.3 (обязательно) |
| Рукопожатия | 2-3 RTT | 2-3 RTT | 0-1 RTT |

## Практические рекомендации

### Для веб-серверов

1. **Включите HTTP/2** для современных клиентов
2. **Подготовьтесь к HTTP/3** — экспериментируйте с QUIC
3. **Используйте keepalive** — настройте разумные таймауты
4. **Оптимизируйте TLS** — используйте TLS 1.3, OCSP stapling

### Для микросервисов

1. **Пулы соединений** — постоянные соединения между сервисами
2. **Circuit breaking** — быстрое обнаружение недоступных сервисов
3. **Retry policies** — экспоненциальный backoff при ошибках

### Для мобильных клиентов

1. **Предпочитайте HTTP/3** — лучше работает в мобильных сетях
2. **Агрессивное keepalive** — поддерживайте соединения активными
3. **Connection migration** — HTTP/3 сохраняет соединения при роуминге
