# Транспортный уровень (L4)

**Транспортный уровень** — это четвертый уровень модели OSI, который является первым сквозным (end-to-end) и сете-независимым уровнем. В отличие от нижних уровней, которые работают на каждом промежуточном узле сети (коммутаторах, маршрутизаторах), транспортный уровень работает только на конечных хостах. Он обеспечивает логическое соединение не между хостами, а напрямую между **процессами**, запущенными на этих хостах.

## Ключевые задачи

1.  **Адресация процессов (мультиплексирование):** Направление данных, полученных из сети, конкретному приложению на хосте.
2.  **Обеспечение надежности:** Предоставление выбора между надежной и ненадежной доставкой данных.

### 1. Адресация с помощью портов

Для идентификации процесса-получателя транспортный уровень использует адреса, называемые **портами**. Порт — это просто число от 0 до 65535. Пара `IP-адрес:Порт` однозначно идентифицирует сетевой процесс в интернете.

**Диапазоны портов (рекомендации IANA):**

1.  **Системные (или общеизвестные) порты (Well-Known Ports): 0–1023**
    *   **Назначение:** Зарезервированы для стандартных, хорошо известных системных служб.
    *   **Примеры:** `22` (SSH), `53` (DNS), `80` (HTTP), `443` (HTTPS).
    *   **Особенность:** Для использования этих портов в большинстве ОС требуются права суперпользователя (root).

2.  **Зарегистрированные (или пользовательские) порты (Registered Ports): 1024–49151**
    *   **Назначение:** Предназначены для приложений и служб, которые устанавливаются пользователями или сторонним ПО. Компании могут официально зарегистрировать порт для своего приложения.
    *   **Примеры:** `3306` (MySQL), `5432` (PostgreSQL), `8080` (альтернативный HTTP).

3.  **Динамические (или частные) порты (Dynamic/Private/Ephemeral Ports): 49152–65535**
    *   **Назначение:** Используются для временных (эфемерных) соединений на стороне клиента. Когда ваш браузер подключается к веб-серверу на порт 443, ОС назначает браузеру случайный порт из этого диапазона для исходящего соединения.

**Пример работы:**
Когда на хост приходит IP-пакет, сетевой уровень передает его транспортному. Транспортный уровень смотрит на номер порта назначения в заголовке TCP или UDP и передает данные тому приложению, которое "слушает" этот порт.

### 2. Обеспечение надежности

Поскольку нижележащий IP-протокол не дает никаких гарантий, транспортный уровень предоставляет приложениям выбор уровня сервиса:

*   **Надежная доставка:** Гарантирует, что все данные будут доставлены в правильном порядке и без потерь. Это достигается за счет:
    *   **Подтверждений (Acknowledgements):** Получатель подтверждает получение данных.
    *   **Повторной передачи (Retransmission):** Если подтверждение не приходит за определенное время, отправитель отправляет данные заново.
    *   **Нумерации последовательности (Sequence Numbers):** Позволяет восстановить правильный порядок сообщений, если они пришли вразнобой.
*   **Ненадежная доставка:** Данные отправляются без каких-либо гарантий. Это быстрее, но часть данных может потеряться или прийти не по порядку.

Восстановление данных программно на хостах, а не на промежуточном сетевом оборудовании, является более эффективным подходом, так как ошибки в современных проводных сетях происходят редко, и делать дорогое оборудование еще дороже из-за встроенных механизмов исправления ошибок нецелесообразно.

## Протоколы транспортного уровня

В стеке TCP/IP на транспортном уровне доминируют два протокола:

1.  **[TCP (Transmission Control Protocol)](./tcp_protocol.md):**
    *   Обеспечивает **надежную** доставку **потока байт** с установкой соединения.
    *   Используется протоколами, где критична целостность данных (HTTP, FTP, SMTP).

2.  **[UDP (User Datagram Protocol)](./udp_protocol.md):**
    *   Обеспечивает **быструю, но ненадежную** доставку независимых сообщений (**дейтаграмм**) без установки соединения.
    *   Используется там, где скорость важнее надежности (DNS, VoIP, онлайн-игры).

## Интерфейс транспортного уровня: Сокеты

Прикладные программы не работают с протоколами TCP или UDP напрямую. Вместо этого они используют **программный интерфейс (API)**, предоставляемый операционной системой, который называется **[интерфейс сокетов (Socket API)](../Concepts/socket_api.md)**. Этот интерфейс позволяет приложениям легко отправлять и получать данные по сети, абстрагируясь от деталей реализации транспортных протоколов.
