# ICMP Time Exceeded (Превышение времени)

**Reliability Score: 10/10** (SSoT + Проверено по RFC 792/4443)

## Определения

**ICMP Time Exceeded (Тип 11 для IPv4, Тип 3 для IPv6)** — служебное сообщение протокола ICMP, уведомляющее отправителя о том, что пакет был отброшен из-за истечения лимита его пересылок через маршрутизаторы или из-за превышения времени ожидания сборки фрагментов на целевом узле.

**Основные параметры:**
- **IPv4:** Тип 11 (Time Exceeded).
- **IPv6:** Тип 3 (Time Exceeded).
- **Код:** 0 или 1 (уточняет причину ошибки).

| Код | Название | Описание |
| :--- | :--- | :--- |
| **0** | Time To Live / Hop Limit exceeded in transit | Пакет отброшен маршрутизатором, так как счетчик пересылок достиг нуля. |
| **1** | Fragment reassembly time exceeded | Целевой узел отбросил пакет, не дождавшись всех его фрагментов для сборки. |

## Основные концепции

### Счетчик пересылок: TTL vs Hop Limit

Для предотвращения бесконечного циркулирования пакетов в сети при возникновении петель маршрутизации используется специальный счетчик в IP-заголовке.

*   **IPv4 — TTL (Time To Live):** Поле размером 8 бит. Исторически измерялось в секундах, но в современной практике каждый маршрутизатор (hop) уменьшает это значение ровно на 1.
*   **IPv6 — Hop Limit:** Поле размером 8 бит. Название приведено в соответствие с фактической функцией — ограничение количества "прыжков" (хопов).

### Механизм генерации сообщения (Код 0)

1. Отправитель устанавливает начальное значение (например, 64 или 128).
2. Каждый транзитный маршрутизатор уменьшает счетчик на 1.
3. Если маршрутизатор получает пакет со значением `1`, он уменьшает его до `0`, отбрасывает пакет и отправляет отправителю сообщение **ICMP Time Exceeded (Code 0)**.
4. В полезную нагрузку ICMP-сообщения вкладывается заголовок и часть данных отброшенного пакета для идентификации.

### Превышение времени сборки фрагментов (Код 1)

Когда узел получает фрагментированный IP-пакет:
1. Он запускает таймер при поступлении первого фрагмента.
2. Если по истечении времени (обычно 15–60 секунд) не все части пакета получены, узел отбрасывает уже принятые фрагменты.
3. Отправителю отправляется ICMP Time Exceeded (Code 1).

**Примечание для IPv6:** В IPv6 фрагментация выполняется только отправителем, маршрутизаторы не имеют права фрагментировать пакеты. Тем не менее, Code 1 сохраняется для уведомления о проблемах сборки на стороне получателя.

## Практические сценарии

### Обнаружение петель маршрутизации

При ошибках в таблицах маршрутизации пакет может попасть в кольцо между двумя или более узлами. Благодаря ICMP Time Exceeded такой пакет не будет циркулировать вечно, перегружая каналы, а будет отброшен, уведомив администратора об ошибке.

### Принцип работы traceroute и mtr

Утилиты трассировки намеренно используют механизм "превышения времени" для составления карты маршрута:
1. Отправляется первый пакет с `TTL=1`. Первый роутер отвечает Time Exceeded. Мы узнаем IP первого хопа.
2. Отправляется второй пакет с `TTL=2`. Пакет проходит первый роутер (TTL становится 1) и отбрасывается вторым. Мы узнаем второй хоп.
3. Процесс продолжается до достижения цели или лимита (обычно 30 хопов).

### Проверка лимита хопов в Linux/Windows

Вы можете вручную ограничить дальность полета пакета для диагностики:

```bash
# Linux: ограничить TTL значением 5 (пакет не уйдет дальше 5-го хопа)
ping -t 5 8.8.8.8

# Windows: аналогичная проверка через ключ -i
ping -i 5 8.8.8.8
```
