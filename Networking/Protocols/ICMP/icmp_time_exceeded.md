# ICMP Time Exceeded (Type 11)

## Определения

**ICMP Time Exceeded (Type 11)** — ICMP-сообщение, уведомляющее об истечении времени жизни пакета (TTL) или времени сборки фрагментов.

**Параметры:**
- **Type:** 11
- **Code:** 0 или 1

| Code | Название | Описание |
|------|----------|----------|
| **0** | Time To Live exceeded in transit | TTL пакета достиг 0 на маршрутизаторе |
| **1** | Fragment reassembly time exceeded | Время ожидания всех фрагментов IP-пакета истекло |

**Важно:** ICMP Time Exceeded Code 0 — классический пример **постоянной ошибки** (в отличие от спонтанных). При циклической маршрутизации или слишком низком начальном TTL каждая повторная отправка приводит к той же ошибке. Требуется изменение конфигурации маршрутизации или увеличение TTL.

## Basic Concepts

### Time To Live (TTL)

Поле **TTL** в IP-заголовке размером 1 байт (8 бит). Каждый маршрутизатор уменьшает TTL на 1 при обработке пакета. При TTL=0 пакет отбрасывается.

**Назначение:**
- Защита от бесконечной пересылки пакетов (циклическая маршрутизация)
- Ограничение времени жизни пакета в сети

### Процесс генерации ICMP Time Exceeded (Code 0)

1. Отправитель создаёт пакет с TTL=N
2. Каждый маршрутизатор уменьшает TTL на 1
3. При получении пакета с TTL=1:
   - Маршрутизатор уменьшает TTL до 0
   - Отбрасывает пакет
   - Отправляет ICMP **Time Exceeded** (Type 11, Code 0) на IP-адрес отправителя

### Fragment Reassembly Time Exceeded (Code 1)

Возникает при фрагментации IP-пакетов ([подробнее о фрагментации IP](../../OSI_TCP_IP_Model/Network_layer/Protocols/ip_fragmentation.md)):

1. Пакет фрагментируется при превышении MTU пути
2. Фрагменты передаются независимо, могут идти разными маршрутами
3. При потере одного или нескольких фрагментов:
   - Получатель ждёт все фрагменты в течение таймаута (15-60 секунд)
   - По истечении времени отправляет **Fragment Reassembly Time Exceeded**

**Причины потери фрагментов:** перегрузка сети, ошибки маршрутизации, проблемы с оборудованием, фрагментация на участках с разным MTU.

**На практике:** встречается редко в современных сетях благодаря Path MTU Discovery (PMTUD), корректной настройке оборудования и TCP MSS Clamping ([MTU и Path MTU Discovery](../../OSI_TCP_IP_Model/Network_layer/mtu_and_vpn.md#path-mtu-discovery-pmtud)).

## Practical Scenarios

### Сценарий: циклическая маршрутизация

| Шаг | Компонент | TTL |
|-----|-----------|-----|
| 1 | Хост 1 → Маршрутизатор 1 | 5 → 4 |
| 2 | Маршрутизатор 1 → Маршрутизатор 2 | 4 → 3 |
| 3 | Маршрутизатор 2 → Маршрутизатор 3 | 3 → 2 |
| 4 | Маршрутизатор 3 → Маршрутизатор 1 (цикл) | 2 → 1 |
| 5 | Маршрутизатор 1 → Маршрутизатор 2 | 1 → 0 → **ICMP Time Exceeded** |

**Результат:** Маршрутизатор 2 отбрасывает пакет и отправляет ICMP Time Exceeded хосту 1. Без механизма TTL пакет циркулировал бы бесконечно.

### Практический пример: защита от зацикливания

**Топология:**

```
                    ┌─────────────────┐
                    │ Маршрутизатор 1 │
                    │  10.0.0.1/24    │
                    └────────┬────────┘
                             │ 169.254.1.0/24
                    ┌────────┴────────┐
                    │ Маршрутизатор 3 │
                    │ 192.168.1.1/24  │
                    └────────┬────────┘
                             │ 192.168.1.0/24
                    ┌────────┴────────┐
                    │ Маршрутизатор 2 │
                    │ 172.16.12.1/24  │
                    └────────┬────────┘
                             │ 172.16.12.0/24
                    ┌────────┴────────┐
                    │ Маршрутизатор 1 │
                    │  (возврат)      │
                    └─────────────────┘
```

**Конфигурация маршрутизации:**

| Компонент | Сеть | Шлюз по умолчанию |
|-----------|------|-------------------|
| Хост 1 | 10.0.0.0/24 | Маршрутизатор 1 (10.0.0.1) |
| Маршрутизатор 1 | 172.16.12.0/24 | Маршрутизатор 2 |
| Маршрутизатор 2 | 192.168.1.0/24 | Маршрутизатор 3 |
| Маршрутизатор 3 | 169.254.1.0/24 | Маршрутизатор 1 |

**Тест:**
```bash
# Linux/macOS
ping -c 1 -t 5 12.34.45.67

# Windows
ping -n 1 -i 5 12.34.45.67
```

**Вывод ping:**
```bash
ping: Warning: source address might be selected on device other than: eth0
PING 12.34.45.67 (12.34.45.67) 56(84) bytes of data.
From 172.16.12.2 icmp_seq=1 Time to live exceeded

--- 12.34.45.67 ping statistics ---
1 packets transmitted, 0 received, +1 errors, 100% packet loss
```

### Применение в traceroute

Утилита `traceroute` использует ICMP Time Exceeded для определения пути пакета: последовательно отправляет пакеты с TTL=1, TTL=2, TTL=3... и фиксирует ICMP Time Exceeded от каждого маршрутизатора на пути ([подробнее о traceroute и mtr](../../../Linux/Diagnostics/Networking/traceroute_mtr.md)).

**Определение количества хопов:**
```bash
# Постепенное увеличение TTL
ping -c 1 -t 1 example.com  # Первый хоп
ping -c 1 -t 2 example.com  # Второй хоп
ping -c 1 -t 3 example.com  # Третий хоп

# Или специализированная утилита
traceroute example.com
```
