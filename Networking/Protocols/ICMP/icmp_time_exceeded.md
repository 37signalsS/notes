# ICMP Time Exceeded (Тип 11)

## Определения

**ICMP Time Exceeded (Тип 11)** — служебное сообщение протокола ICMP, уведомляющее отправителя о том, что пакет был отброшен из-за истечения его времени жизни (TTL) или превышения времени ожидания сборки фрагментов.

**Основные параметры:**

- **Тип:** 11 (Time Exceeded)
- **Код:** 0 или 1 (уточняет причину ошибки)

| Код | Название | Описание |
|------|----------|----------|
| **0** | Time To Live exceeded in transit | TTL пакета достиг 0 при пересылке маршрутизатором |
| **1** | Fragment reassembly time exceeded | Истекло время ожидания всех фрагментов IP-пакета на хосте назначения |

## Основные концепции

### Время жизни пакета (Time To Live — TTL)

Поле **TTL** в IP-заголовке (размером 8 бит) ограничивает время пребывания пакета в сети. Каждый маршрутизатор при обработке пакета уменьшает значение TTL на 1. Если TTL становится равным 0, пакет уничтожается.

**Назначение TTL:**

- **Защита от зацикливания:** предотвращает бесконечное циркулирование пакетов при ошибках маршрутизации.
- **Ограничение охвата:** позволяет ограничить "дальность" распространения пакета.

### Механизм генерации сообщения (Код 0)

1. Отправитель формирует IP-пакет с определенным значением TTL.
2. Каждый транзитный маршрутизатор уменьшает TTL на 1.
3. Если маршрутизатор получает пакет с `TTL=1`, он уменьшает его до 0, отбрасывает пакет и отправляет отправителю сообщение **ICMP Time Exceeded (Type 11, Code 0)**.

### Превышение времени сборки фрагментов (Код 1)

Если IP-пакет был фрагментирован, принимающая сторона должна собрать все фрагменты воедино.

- Получатель запускает таймер при поступлении первого фрагмента (обычно 15–60 секунд).
- Если за это время не все фрагменты получены, пакет отбрасывается.
- Отправителю направляется сообщение **ICMP Time Exceeded (Type 11, Code 1)**.

## Практические сценарии

### Обнаружение циклов маршрутизации

При наличии петли (кольца) в маршрутах пакет будет ходить между маршрутизаторами, пока его TTL не обнулится. Без механизма ICMP Time Exceeded такая ошибка могла бы привести к перегрузке каналов бесполезным трафиком.

| Шаг | Событие | Изменение TTL |
|-----|-----------|-----|
| 1 | Хост → R1 | 5 → 4 |
| 2 | R1 → R2 | 4 → 3 |
| 3 | R2 → R3 | 3 → 2 |
| 4 | R3 → R1 (петля) | 2 → 1 |
| 5 | R1 отбрасывает пакет | 1 → 0 → **ICMP Time Exceeded** |

### Использование в диагностике (traceroute)

Утилита [`traceroute`](../../../Linux/Diagnostics/Networking/traceroute_mtr.md) намеренно использует механизм TTL для определения пути пакета:

1. Отправляется пакет с `TTL=1`. Первый маршрутизатор возвращает ICMP Time Exceeded.
2. Отправляется пакет с `TTL=2`. Второй маршрутизатор возвращает сообщение.
3. Процесс повторяется, пока не будет достигнут целевой хост или предел трассировки.

### Тестирование защиты от зацикливания

Для проверки поведения сети можно отправить пакет с малым TTL:

```bash
# Linux: отправить 1 пакет с TTL=5
ping -c 1 -t 5 8.8.8.8

# Windows: отправить 1 пакет с TTL=5
ping -n 1 -i 5 8.8.8.8
```

Если до цели более 5 хопов, вы получите ответ: `From <IP-адрес>: icmp_seq=1 Time to live exceeded`.
