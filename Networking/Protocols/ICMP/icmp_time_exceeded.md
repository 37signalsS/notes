# ICMP Time Exceeded (Превышение времени)

## Определения

**ICMP Time Exceeded (Тип 11 для IPv4, Тип 3 для IPv6)** — служебное сообщение протокола ICMP, уведомляющее отправителя о том, что пакет был отброшен из-за истечения лимита его пересылок через промежуточные узлы или из-за превышения времени ожидания сборки фрагментов на целевом хосте.

**Основные параметры:**
- **IPv4:** Тип 11 (Time Exceeded).
- **IPv6:** Тип 3 (Time Exceeded).
- **Код (Code):** Уточняет конкретную причину отбрасывания пакета.

| Код | Название | Описание |
| :--- | :--- | :--- |
| **0** | TTL / Hop Limit exceeded in transit | Пакет отброшен маршрутизатором, так как счетчик пересылок достиг нуля. |
| **1** | Fragment reassembly time exceeded | Целевой узел отбросил пакет, не дождавшись всех фрагментов для сборки. |

## Основные концепции

### Счетчик пересылок: TTL vs Hop Limit

Для предотвращения бесконечного циркулирования пакетов при возникновении петель маршрутизации используется защитный механизм на сетевом уровне:

*   **IPv4 — TTL (Time To Live):** Поле в 8 бит. Первоначально задумывалось как время в секундах, но де-факто стало счетчиком переходов (hops). Каждый L3-узел уменьшает его на 1.
*   **IPv6 — Hop Limit:** Поле в 8 бит. Название исправлено для точного отражения функции — ограничение количества узлов-ретрансляторов.

### Механизм генерации сообщения (Код 0)

1. Отправитель устанавливает начальное значение (64, 128 или 255).
2. Каждый транзитный маршрутизатор уменьшает значение поля на 1.
3. Если узел получает пакет с `TTL=1`, он уменьшает его до `0`, отбрасывает пакет и генерирует **ICMP Time Exceeded (Code 0)** в сторону отправителя.
4. Пакет ICMP содержит заголовок и первые 64 бита данных оригинального (отброшенного) пакета для сопоставления.

### RFC 4884: Расширения ICMP и MPLS

Современные магистральные сети часто используют MPLS. Благодаря расширениям ICMP (Multi-Part Messages), сообщение Time Exceeded может включать в себя:
*   **MPLS Label Stack:** Стек меток, с которыми пакет пришел на узел. Это позволяет `traceroute` отображать не только IP-путь, но и логику коммутации меток внутри провайдерской сети.

### Превышение времени сборки фрагментов (Код 1)

Если целевой узел получает первый фрагмент пакета, он запускает таймер сборки.
*   Если по истечении времени (по умолчанию 15–60 секунд) не все фрагменты прибыли, узел очищает буфер и отправляет отправителю **Time Exceeded (Code 1)**.
*   **В IPv6:** Хотя маршрутизаторы не фрагментируют пакеты, отправитель по-прежнему может отправлять фрагментированные данные (например, при использовании расширений заголовков). Code 1 остается актуальным для диагностики проблем на стороне получателя.

## Практические сценарии

### Принцип работы traceroute и mtr

Утилиты трассировки намеренно провоцируют ошибки Time Exceeded для картографирования сети:
1. Пакет 1: `TTL=1`. Первый роутер отвечает `Time Exceeded`. Мы фиксируем его IP и задержку.
2. Пакет 2: `TTL=2`. Пакет проходит первый узел и отбрасывается вторым. Мы узнаем второй хоп.
3. Процесс повторяется до получения `Echo Reply` от цели или достижения лимита (Max Hops).

### ICMP Rate Limiting и диагностика

Для защиты управляющего процессора (Control Plane) маршрутизаторы ограничивают скорость генерации ICMP-пакетов.
*   **Эффект:** В выводе `mtr` могут наблюдаться "звездочки" (`* * *`) или 100% потери на промежуточных узлах, при этом финальный узел отвечает стабильно. Это нормальное поведение оборудования, а не сетевая проблема.

### Диагностика из командной строки

Проверка лимита хопов позволяет выявлять петли маршрутизации вручную:

```bash
# Linux: ограничить дальность 5-ю хопами
ping -t 5 8.8.8.8

# Windows: аналогично через ключ -i
ping -i 5 8.8.8.8
```
