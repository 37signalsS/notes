# ICMP Destination Unreachable (Type 3)

## Определения

**Destination Unreachable (Type 3)** — ICMP-сообщение, уведомляющее отправителя о невозможности доставки пакета до цели.

**Параметры:**

- **Type:** 3 (Destination Unreachable)
- **Code:** 0–15 (детализация причины недостижимости)

## Основные концепции

### Назначение

Сообщения Type 3 информируют отправителя о проблемах доставки, позволяя:

- Прекратить бесперспективные повторные передачи (TCP, UDP)
- Скорректировать параметры пакета (MTU, маршрут)
- Диагностировать недоступность хостов/сетей

### Механизм генерации

| Кто генерирует | Коды |
|----------------|------|
| **Маршрутизатор** | 0 (Net Unreachable), 1 (Host Unreachable), 4 (Fragmentation Needed) |
| **Хост назначения** | 2 (Protocol Unreachable), 3 (Port Unreachable) |

### Таблица кодов

| Code | Название | Описание |
|------|----------|----------|
| **0** | Net Unreachable | Маршрутизатор не знает маршрута до сети назначения |
| **1** | Host Unreachable | Хост не отвечает (выключен, ARP не отвечает) |
| **2** | Protocol Unreachable | Хост не поддерживает протокол IP-пакета |
| **3** | Port Unreachable | UDP-порт закрыт (для TCP — RST, не ICMP) |
| **4** | Fragmentation Needed | Пакет > MTU, флаг DF запрещает фрагментацию |
| 5–15 | Reserved/Other | Зарезервированы (Source Route Failed, Admin Prohibited и др.) |

## Практические сценарии

### Net Unreachable (Type 3, Code 0)

**Назначение:** Маршрутизатор не знает маршрута до сети назначения.

**Механизм возникновения:**

1. **Исходные условия:**
   - Хост 1 (192.168.1.10/24) отправляет TCP SYN на 8.8.4.4:53
   - Адрес назначения — вне локальной сети, пакет идёт на шлюз по умолчанию

2. **Процесс:**
   - Маршрутизатор проверяет таблицу маршрутизации
   - Маршрут до сети 8.8.4.4 отсутствует

3. **Результат:**
   - Пакет отбрасывается
   - Генерируется ICMP **Destination Unreachable, Code 0**

4. **Реакция TCP:**
   - TCP **немедленно прекращает попытки** установки соединения
   - Без ICMP TCP продолжил бы бесконечные повторные отправки SYN

**Диагностика:**

```bash
tcpdump -i eth0 'icmp[0] = 3 and icmp[1] = 0'
```

---

### Host Unreachable (Type 3, Code 1)

**Назначение:** Маршрутизатор знает сеть назначения, но хост не отвечает.

**Механизм возникновения:**

1. **Исходные условия:**
   - Хост 1 (192.168.1.10/24) отправляет TCP на 172.16.12.22:5555
   - Маршрутизатор знает сеть 172.16.12.0/24

2. **Процесс:**
   - Маршрутизатор отправляет **ARP-запросы** для 172.16.12.22
   - После **3 попыток** ответа не получено

3. **Результат:**
   - Генерируется ICMP **Destination Unreachable, Code 1**

**Особенность:** Если за время ARP-поиска получено несколько пакетов для одного хоста, маршрутизатор отправит **несколько ICMP-сообщений** (по одному на пакет).

**Диагностика:**

```bash
tcpdump -i eth0 -nn 'arp or icmp'
# Видно: arp who-has 172.16.12.22 tell 192.168.1.1 (x3)
# Затем: ICMP 172.16.12.22 unreachable (core)
```

---

### Protocol Unreachable (Type 3, Code 2)

**Назначение:** Хост назначения не поддерживает протокол, указанный в поле Protocol IP-пакета.

**Механизм:** Хост получает пакет с неизвестным протоколом (GRE=47, ESP=50, SCTP=132) → генерирует ICMP Code 2.

**На практике:** Встречается редко — большинство ОС поддерживают основные протоколы (TCP, UDP, ICMP).

---

### Port Unreachable (Type 3, Code 3)

**Назначение:** Хост получил UDP-датаграмму на порт, который никто не слушает.

**Ключевая особенность:** Генерируется **только для UDP**. Для TCP несуществующий порт обрабатывается отправкой RST.

**Механизм возникновения:**

1. UDP-клиент отправляет датаграмму на порт 5555
2. На хосте нет приложения, слушающего порт 5555
3. Хост генерирует ICMP **Port Unreachable**

**Значение для UDP:**

- UDP не устанавливает соединение (нет handshake)
- Без ICMP Port Unreachable отправитель не узнает о недоставке
- ICMP приходит только при ошибке

**Использование в сканировании портов:**

- UDP-сканеры используют ICMP Port Unreachable для определения закрытых портов
- Отсутствие ответа: порт открыт ИЛИ пакет потерян ИЛИ ICMP заблокирован файрволом

**Диагностика:**

```bash
echo "test" | nc -u 192.168.1.2 5555
tcpdump -i eth0 -nn 'icmp[0] = 3 and icmp[1] = 3'
```

### Fragmentation Needed but DF set (Type 3, Code 4)

**Назначение:** Пакет не может быть доставлен без фрагментации, но установлен флаг **DF (Don't Fragment)**.

**Механизм возникновения:**

1. **Исходные условия:**
   - Хост 1 отправляет пакет 9000 байт (Jumbo Frame)
   - MTU следующего звена: 1500 байт
   - В IP-заголовке установлен флаг DF

2. **Процесс:**
   - Маршрутизатор обнаруживает несоответствие MTU
   - Флаг DF запрещает фрагментацию
   - Пакет отбрасывается, генерируется ICMP Code 4

**Path MTU Discovery (PMTUD):**

ICMP Code 4 — ключевой элемент механизма PMTUD:

1. Отправитель устанавливает флаг DF
2. При получении "Fragmentation Needed" уменьшает размер пакета
3. Повторяет до нахождения оптимального MTU пути

**Диагностика:**

```bash
# Linux
ping -s 1472 -M do 8.8.8.8   # 1500 байт (1472 + 28 заголовков) — OK
ping -s 1473 -M do 8.8.8.8   # Ошибка: требуется фрагментация

# Windows
ping -l 2000 -f 8.8.8.8
```

**Проблемы безопасности:**

- **PMTUD Black Hole:** Файрвол блокирует ICMP Type 3 Code 4 → PMTUD не работает
- **Решение:** Разрешить ICMP Type 3 Code 4 на файрволе

Подробнее: [Path MTU Discovery](../../OSI_TCP_IP_Model/Network_layer/mtu_and_vpn.md#path-mtu-discovery-pmtud), [Фрагментация IP](../../OSI_TCP_IP_Model/Network_layer/Protocols/ip_fragmentation.md).

## Диагностика и устранение

| Код | Причина | Решение |
|-----|---------|---------|
| 0 (Net Unreachable) | Нет маршрута | Проверить маршруты на шлюзе |
| 1 (Host Unreachable) | Хост выключен, ARP не отвечает | Проверить доступность хоста |
| 2 (Protocol Unreachable) | Протокол не поддерживается | Проверить поддержку протокола |
| 3 (Port Unreachable) | UDP-порт закрыт | Проверить службу на хосте |
| 4 (Fragmentation Needed) | Пакет > MTU, флаг DF | Включить PMTUD или уменьшить MTU |
