# ICMP Destination Unreachable (Тип 3)

## Определения

**Destination Unreachable (Тип 3)** — служебное сообщение протокола ICMP, уведомляющее отправителя о невозможности доставки IP-пакета до цели.

**Параметры:**
- **Тип:** 3 (Destination Unreachable)
- **Код:** 0–15 (детализация конкретной причины отказа в доставке)

## Основные концепции

### Назначение
Сообщения типа 3 критически важны для стабильности сетевых соединений:
- **Оптимизация ресурсов**: позволяют стеку протоколов (TCP/UDP) немедленно прекратить бесперспективные повторные передачи.
- **Автоматическая настройка**: используются для механизма PMTUD (Path MTU Discovery).
- **Диагностика**: помогают локализовать место разрыва связи или ошибку конфигурации.

### Механизм генерации
Сообщение генерируется устройством (маршрутизатором или хостом), которое обнаружило невозможность дальнейшей передачи пакета.

| Источник | Генерируемые коды |
| :--- | :--- |
| **Маршрутизатор** | 0 (Net Unreachable), 1 (Host Unreachable), 4 (Fragmentation Needed) |
| **Хост назначения** | 2 (Protocol Unreachable), 3 (Port Unreachable) |

### Таблица основных кодов

| Код | Название | Описание |
| :--- | :--- | :--- |
| **0** | Net Unreachable | Маршрутизатор не знает маршрута до сети назначения |
| **1** | Host Unreachable | Хост не отвечает на ARP-запросы (выключен или отсутствует в сегменте) |
| **2** | Protocol Unreachable | Хост назначения не поддерживает указанный транспортный протокол |
| **3** | Port Unreachable | UDP-порт закрыт (для TCP вместо ICMP используется флаг RST) |
| **4** | Fragmentation Needed | Пакет превышает MTU, но установлен флаг DF (Don't Fragment) |

## Практические сценарии

### Недоступность сети (Code 0)
**Сценарий**: Ошибка в таблице маршрутизации.
1. Хост отправляет пакет на адрес, находящийся вне локальной сети.
2. Маршрутизатор проверяет свою таблицу маршрутов и не находит совпадений (даже маршрута по умолчанию).
3. Пакет отбрасывается, а хост получает ICMP Type 3 Code 0.
4. **Реакция**: TCP немедленно разрывает соединение с ошибкой "No route to host".

### Недоступность хоста (Code 1)
**Сценарий**: Узел физически отключен.
1. Маршрутизатор знает маршрут до сети, где должен находиться хост.
2. Маршрутизатор отправляет ARP-запрос для определения MAC-адреса хоста.
3. После нескольких неудачных попыток маршрутизатор генерирует ICMP Type 3 Code 1.
4. **Диагностика**: `tcpdump -i eth0 -nn 'arp or icmp'`.

### Недоступность порта (Code 3)
**Сценарий**: Сканирование портов или ошибка приложения.
1. UDP-пакет приходит на сервер на порт 5555.
2. Ни одно приложение на сервере не слушает этот порт.
3. Ядро ОС отправляет ICMP Port Unreachable.
4. **Применение**: Используется UDP-сканерами для определения закрытых портов. Если ответа нет — порт может быть открыт или защищен файрволом.

### Требуется фрагментация (Code 4)
**Сценарий**: Проблемы MTU в VPN-туннелях или при использовании Jumbo Frames.
1. Хост отправляет пакет размером 1500 байт с флагом DF.
2. На пути встречается туннель с MTU 1400.
3. Маршрутизатор отбрасывает пакет и отправляет ICMP Code 4, указывая допустимый размер MTU (1400).
4. **Проблема**: Если файрвол блокирует ICMP Type 3 Code 4, возникает "Black Hole" (соединение устанавливается, но данные не передаются).

## Дополнительная информация

### Сводная таблица диагностики

| Код | Вероятная причина | Решение |
| :--- | :--- | :--- |
| **0** (Net Unreachable) | Нет маршрута | Настроить статический маршрут или шлюз по умолчанию |
| **1** (Host Unreachable) | Проблема L2 или хост выключен | Проверить физику, ARP-таблицу и питание узла |
| **3** (Port Unreachable) | Служба не запущена | Проверить статус приложения (systemctl status) |
| **4** (Fragmentation Needed) | Блокировка ICMP или разница MTU | Разрешить ICMP Type 3 на файрволе; настроить MSS Clamping |
