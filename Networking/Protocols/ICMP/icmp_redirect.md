# ICMP Redirect и Source Quench

## Определения

**ICMP Redirect (Type 5)** — сообщение, используемое маршрутизаторами для оптимизации маршрута доставки пакетов путём рекомендации хосту использовать более оптимальный шлюз.

**ICMP Source Quench (Type 4)** — устаревшее сообщение для контроля перегрузки (запрос на уменьшение скорости отправки).

---

## ICMP Redirect (Type 5)

### Назначение

Оптимизация маршрута доставки пакетов путём рекомендации хосту использовать более оптимальный шлюз.

**Параметры:**
- **Type:** 5
- **Code:** 0-3

### Коды ICMP Redirect

| Code | Описание |
|------|----------|
| **0** | Redirect Datagram for the Network (перенаправление для сети) |
| **1** | Redirect Datagram for the Host (перенаправление для хоста) |
| **2** | Redirect Datagram for the Type of Service and Network |
| **3** | Redirect Datagram for the Type of Service and Host |

### Механизм работы

Классический сценарий работы ICMP Redirect:

1. **Исходная конфигурация:**
   - Хост 1: `10.0.0.1/24`
   - Хост 2: `192.168.1.1/24`
   - Маршрутизатор имеет два интерфейса в одной физической сети:
     - `10.0.0.100/24`
     - `192.168.1.100/24`

2. **Процесс:**
   - Хост 1 отправляет ICMP-запрос (например, ping) для хоста 2
   - Так как хосты в разных IP-сетях, хост 1 отправляет пакет на шлюз по умолчанию (маршрутизатор)
   - Маршрутизатор, получив пакет, определяет, что хост 2 находится в той же физической сети, что и хост 1 (через второй интерфейс)
   - Маршрутизатор:
     - Пересылает пакет хосту 2
     - Отправляет хосту 1 сообщение **ICMP Redirect** (Type 5, Code 1 — «Redirect Datagram for Host»)
   - Хост 1 обновляет свою таблицу маршрутизации и начинает отправлять пакеты хосту 2 напрямую, минуя маршрутизатор

3. **Результат:** При повторных запросах пакеты доставляются напрямую между хостами, сокращая путь и разгружая маршрутизатор.

### Проблемы безопасности

ICMP Redirect по умолчанию обрабатывается многими ОС, что создаёт риски:

- **Атака перенаправления трафика:** Злоумышленник может отправлять ложные Redirect для перехвата трафика
- **MITM-атаки:** Перенаправление трафика через компрометированный узел

### Защита

**1. Блокировка на файрволе:**
```bash
iptables -A INPUT -p icmp --icmp-type redirect -j DROP
```

**2. Отключение обработки на уровне ОС (Linux):**
```bash
# Проверка текущих настроек
sysctl net.ipv4.conf.all.accept_redirects
sysctl net.ipv4.conf.default.accept_redirects
sysctl net.ipv4.conf.<interface>.accept_redirects

# Отключение приёма Redirect
sysctl -w net.ipv4.conf.all.accept_redirects=0
sysctl -w net.ipv4.conf.default.accept_redirects=0

# Постоянное применение (/etc/sysctl.conf)
net.ipv4.conf.all.accept_redirects=0
net.ipv4.conf.default.accept_redirects=0
```

**3. Windows:** Настройка в реестре

Путь: `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`

Параметр: `EnableICMPRedirect` (DWORD) = 0

## ICMP Source Quench (Type 4)

### Назначение

Уведомление отправителя о том, что получатель или маршрутизатор не успевает обрабатывать входящие пакеты (контроль перегрузки).

**Параметры:**
- **Type:** 4
- **Code:** 0

### Механизм работы

1. Маршрутизатор или хост получает пакеты быстрее, чем может их обработать
2. Отправитель получает ICMP Source Quench-сообщение
3. Отправитель должен уменьшить скорость передачи

### Статус: Устарел (deprecated)

**Причины:**
- Неэффективен в современных высокоскоростных сетях
- Может использоваться для DoS-атак (ложные Source Quench для замедления легитимного трафика)
- В современных сетях контроль перегрузки реализован на транспортном уровне (TCP congestion control)

**Рекомендация:** Игнорировать Source Quench на современных системах; использовать механизмы контроля перегрузки TCP.
