# ICMP Echo Request/Reply и утилита ping

## Определения

**Echo Request (Type=8, Code=0)** — ICMP-сообщение для запроса проверки доступности удалённого хоста.

**Echo Reply (Type=0, Code=0)** — ICMP-сообщение, отвечающее на Echo Request и подтверждающее доступность хоста.

Это единственный тип ICMP-сообщений, который не сообщает об ошибках, а служит исключительно для диагностики.

## Основные концепции

### Механизм работы

Получив Echo Request, хост **должен** ответить Echo Reply (если сообщение не блокируется файрволом). На основе этих сообщений работает утилита [`ping`](../../Linux/Diagnostics/Networking/ping.md), измеряющая RTT (Round-Trip Time) — время прохождения пакета туда и обратно.

### Формат сообщения

| Поле | Echo Request | Echo Reply |
|------|--------------|------------|
| Type | 8 | 0 |
| Code | 0 | 0 |
| Identifier | PID отправителя | PID отправителя |
| Sequence Number | Порядковый номер пакета | Порядковый номер пакета |
| Data | Произвольные данные | Копия данных из запроса |

**Identifier** и **Sequence Number** позволяют сопоставлять запросы с ответами при множестве одновременных ping-сессий.

## Практические сценарии

### Broadcast Echo Request

При отправке ICMP-эхо запроса на [широковещательный адрес](../ip.md#широковещательный-адрес-broadcast-address) (например, `192.168.1.255/24`):

- Все хосты в сети получают пакет
- **Большинство ОС** (Windows, Linux, macOS) **игнорируют** такие запросы в целях безопасности
- **Некоторые устройства** (сетевые принтеры, специализированное оборудование) **отвечают** на broadcast ICMP-эхо запросы
- Для отправки ping на broadcast в Linux требуется опция `-b`: `ping -c 1 -b 192.168.1.255`

### Broadcast source address

Если IP-адрес отправителя в пакете является широковещательным:

- Получатели **не отвечают** на такой запрос
- Это защита от flooding сети: ответ на broadcast-адрес отправителя вызвал бы лавину пакетов
- Хост, назначивший себе broadcast-адрес (например, `192.168.1.255/24`), не сможет нормально обмениваться данными

### OS Fingerprinting

Различия в обработке broadcast ICMP-запросов используются для определения типа ОС удалённого хоста. Если хост отвечает на broadcast ping — это может быть сетевое устройство (принтер, маршрутизатор, специализированное оборудование).

Значение TTL в ответе ping позволяет приблизительно определить ОС (подробнее в [`ping`](../../Linux/Diagnostics/Networking/ping.md#интерпретация-ttl)):

| Начальное TTL | ОС / Устройство |
|---------------|-----------------|
| 64 | Linux, Unix, macOS |
| 128 | Windows |
| 255 | Сетевое оборудование (маршрутизаторы) |

**Пример расчёта хопов:**
```bash
$ ping 8.8.8.8
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=12.3 ms
```
- Получено TTL = 117, начальное TTL = 128 (Windows)
- Количество хопов ≈ 128 - 117 = **11**

## Дополнительная информация

### Безопасность

- ICMP Echo может блокироваться файрволами для сокрытия наличия хоста
- Flood ICMP-запросами используется в DDoS-атаках (smurf attack через broadcast)
- Современные ОС по умолчанию ограничивают rate ICMP-ответов
