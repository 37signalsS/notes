### Определения

**DHCP (Dynamic Host Configuration Protocol)** — это протокол прикладного уровня, предназначенный для автоматической конфигурации сетевых параметров устройств в IP-сетях. Его основная задача — динамическое назначение IP-адресов и передача клиентам дополнительных данных, таких как маска подсети, адрес шлюза по умолчанию и адреса DNS-серверов.

Ключевые компоненты архитектуры DHCP:

* **Сервер DHCP:** Центральный узел, который управляет пулом IP-адресов и отвечает на запросы клиентов.
* **Клиент DHCP:** Любое устройство (компьютер, смартфон, принтер), которое запрашивает сетевые настройки у сервера.
* **Агент ретрансляции DHCP (DHCP Relay Agent):** Маршрутизатор или хост, который пересылает DHCP-сообщения между клиентами и серверами, находящимися в разных подсетях.

### Основные концепции

#### Способы назначения IP-адресов

DHCP поддерживает три основных способа выделения IP-адресов:

* **Статическое назначение (Static Allocation):** Администратор вручную создает на DHCP-сервере привязку конкретного IP-адреса к MAC-адресу устройства. Этот адрес выделяется устройству при каждом запросе. Используется для серверов, принтеров и других устройств, требующих постоянного адреса.
* **Динамическое назначение (Dynamic Allocation):** DHCP-сервер выдает клиенту свободный IP-адрес из заранее определенного пула (scope) на ограниченное время (срок аренды, lease time). Это самый распространенный способ.
* **Автоматическое назначение (Automatic Allocation):** Сервер назначает IP-адрес клиенту на неограниченный срок, запоминая выданный адрес. Похоже на динамическое назначение, но без ограничения времени аренды.

#### Принцип работы (процесс DORA)

Взаимодействие между клиентом и сервером описывается последовательностью из четырех шагов, известной как **DORA**:

1. **Discovery (DHCPDISCOVER)**: Клиент (еще без IP) отправляет широковещательное сообщение `DHCPDISCOVER` для поиска DHCP-сервера. Этот запрос отправляется на MAC-адрес, состоящий из одних единиц (широковещательный адрес), так как клиент еще не знает MAC-адресов других устройств в сети. Сообщение содержит MAC-адрес клиента и запрос на присвоение IP-адреса.
2. **Offer (Предложение):** Все DHCP-серверы, получившие запрос, отвечают сообщением `DHCPOFFER`, содержащим предлагаемый IP-адрес и другие сетевые параметры.
3. **Request (Запрос):** Клиент выбирает одно из предложений и отправляет широковещательное сообщение `DHCPREQUEST`, в котором указывает MAC-адрес сервера, чье предложение он принял. Это информирует все серверы о его выборе.
4. **Acknowledgement (Подтверждение):** Выбранный сервер финализирует процесс, отправляя клиенту сообщение `DHCPACK`. Оно содержит подтверждение выделенного IP-адреса, срок аренды и все остальные настройки. После этого клиент может использовать полученные параметры.

#### Другие типы сообщений

Помимо DORA, существуют и другие сообщения:

* `DHCPNAK`: Сервер отправляет отказ в ответ на `DHCPREQUEST`, если предложенный адрес уже занят или конфигурация неверна.
* `DHCPRELEASE`: Клиент информирует сервер о досрочном освобождении IP-адреса.
* `DHCPINFORM`: Клиент, у которого уже есть IP-адрес (например, настроенный вручную), запрашивает у сервера дополнительные сетевые параметры (например, адрес DNS).
* `DHCPDECLINE`: Клиент сообщает серверу, что предложенный IP-адрес уже используется другим устройством в сети (обнаружен конфликт IP-адресов).

### Практические сценарии

* **Безопасность DHCP: Защита от несанкционированных DHCP-серверов (Rogue DHCP Server)**

    Поскольку DHCP-запросы являются широковещательными, существует риск атак типа "Rogue DHCP server", когда злоумышленник (или случайно запущенный некорректный сервис) разворачивает в сети собственный DHCP-сервер. Такой сервер может выдавать некорректные IP-адреса, адреса шлюзов по умолчанию или DNS-серверов, что приводит к перенаправлению трафика, отказу в обслуживании (DoS) или атакам "человек посередине" (Man-in-the-Middle).

    **Признаки несанкционированного DHCP-сервера:**
    1. **Получение неожиданного IP-адреса:** Клиенты получают IP-адреса из другой подсети, не соответствующей ожидаемой конфигурации.
    2. **Проблемы с доступом к сети:** Клиенты не могут выйти в интернет, получить доступ к локальным ресурсам или работают с перебоями, несмотря на получение IP-адреса.
    3. **Неверные сетевые параметры:** Клиенты получают неверные адреса шлюза, DNS-серверов или других опций.
    4. **Двойные DHCP-предложения:** При анализе сетевого трафика (например, с помощью Wireshark) видно несколько `DHCPOFFER` сообщений от разных серверов на один `DHCPDISCOVER` от клиента.

    **Как найти и отключить несанкционированный DHCP-сервер:**
    1. **Использование сетевых анализаторов:**
        * **Wireshark/tcpdump:** Захват трафика на порту клиента или коммутатора. Идентификация IP-адресов и MAC-адресов всех DHCP-серверов, отвечающих на `DHCPDISCOVER`. Сравнение их с легитимными серверами.
        * **Инструменты для поиска Rogue DHCP:** Существуют специализированные утилиты (например, `dhcp-discover` в Linux, `Rogue Detector` в некоторых сетевых анализаторах), которые активно сканируют сеть на предмет несанкционированных DHCP-ответов.
    2. **Проверка коммутационного оборудования:**
        * **Журналы (логи) коммутаторов:** Некоторые управляемые коммутаторы могут логировать активность DHCP-серверов или оповещать о попытках запуска несанкционированных DHCP.
        * **Таблица MAC-адресов коммутатора:** После обнаружения IP и MAC-адреса несанкционированного сервера, можно найти, к какому порту коммутатора он подключен.
    3. **Физическое отключение/Блокировка:**
        * После идентификации порта на коммутаторе, к которому подключен несанкционированный сервер, можно физически отключить устройство или административно заблокировать порт на коммутаторе.
        * Если несанкционированный сервер является легитимным устройством, но некорректно настроен (например, роутер, который был включен пользователем в режим маршрутизатора вместо точки доступа), его следует правильно перенастроить.

    **Методы защиты от несанкционированных DHCP-серверов:**
    1. **DHCP Snooping:** Это функция безопасности, доступная на управляемых коммутаторах [канального уровня (L2)](../../OSI_TCP_IP_Model/data_link_layer.md).
        * **Принцип работы:** Коммутатор отслеживает DHCP-трафик и строит базу данных доверенных DHCP-серверов и их ответов. Порты коммутатора классифицируются как:
            * **Доверенные (Trusted):** Порты, к которым подключены легитимные DHCP-серверы или другие доверенные устройства (например, аплинки к другим коммутаторам). На этих портах разрешены все типы DHCP-сообщений.
            * **Недоверенные (Untrusted):** Порты, к которым подключены конечные пользователи. На этих портах блокируются входящие `DHCPOFFER`, `DHCPACK`, `DHCPNAK`, `DHCPACK` и `DHCPLEASE` сообщения (т.е. ответы от серверов). Разрешены только исходящие `DHCPDISCOVER` и `DHCPREQUEST` от клиентов.
        * **Эффект:** Любой `DHCPOFFER` или `DHCPACK` от несанкционированного DHCP-сервера, подключенного к недоверенному порту, будет заблокирован коммутатором, предотвращая получение клиентами некорректных конфигураций.
    2. **Port Security (Безопасность портов):** Настраивается на коммутаторах для ограничения количества MAC-адресов, которые могут быть изучены на одном порту. Это может предотвратить подключение несанкционированных устройств или ограничить их влияние.
    3. **Dynamic ARP Inspection (DAI):** Связанная с DHCP Snooping функция, которая проверяет достоверность ARP-сообщений на основе базы данных DHCP Snooping. Предотвращает ARP-спуфинг, который часто используется после получения клиентом IP-адреса от несанкционированного DHCP-сервера.
    4. **Физическая безопасность:** Ограничение физического доступа к сетевому оборудованию и розеткам для предотвращения подключения несанкционированных устройств.
    5. **802.1X (Network Access Control):** Более комплексное решение, требующее аутентификации устройств перед предоставлением им сетевого доступа, что также помогает предотвратить подключение несанкционированных DHCP-серверов.

* **Порты:** DHCP-сервер использует порт **67/UDP**, а клиент — порт **68/UDP**.

## DHCPv6 (Dynamic Host Configuration Protocol for IPv6)

DHCPv6 — это протокол для автоматической конфигурации IPv6-адресов и сетевых параметров в сетях IPv6.

### Отличия от DHCPv4

| Критерий | DHCPv4 | DHCPv6 |
|----------|--------|--------|
| **Транспорт** | UDP (сервер 67, клиент 68) | UDP (сервер 547, клиент 546) |
| **Широковещание** | Использует broadcast (255.255.255.255) | Использует multicast (ff02::1:2 для всех агентов) |
| **DORA процесс** | Четырехэтапный (Discover → Offer → Request → Ack) | Двухэтапный (Solicit → Advertise → Request → Reply) или четырехэтапный при использовании Relay |
| **Адресация** | Выдает IPv4-адреса с маской | Выдает IPv6-адреса с префиксами |
| **Резервирование** | Привязка по MAC-адресу (DUID в DHCPv6) | Использует DUID (DHCP Unique Identifier) + IAID |
| **Совместимость с SLAAC** | Нет | Может работать вместе со SLAAC (Stateless Address Autoconfiguration) |

### Режимы работы DHCPv6

1. **Stateful DHCPv6:**
   * DHCPv6-сервер полностью управляет выделением IPv6-адресов
   * Клиент получает адрес, префикс, DNS и другие параметры от сервера
   * Аналогичен DHCPv4

2. **Stateless DHCPv6:**
   * IPv6-адреса назначаются через SLAAC (Router Advertisement)
   * DHCPv6 предоставляет только дополнительные параметры (DNS, NTP, domain name)
   * Клиент отправляет `Information-Request`, сервер отвечает `Reply` с опциями

### Типы сообщений DHCPv6

* **Solicit (1):** Клиент ищет DHCPv6-серверы
* **Advertise (2):** Серверы предлагают свои услуги
* **Request (3):** Клиент запрашивает параметры у конкретного сервера
* **Confirm (4):** Клиент проверяет валидность своего адреса
* **Renew (5):** Обновление аренды адреса
* **Rebind (6):** Попытка обновления у других серверов
* **Reply (7):** Ответ сервера на запрос клиента
* **Release (8):** Освобождение адреса
* **Decline (9):** Отказ от адреса (конфликт)
* **Reconfigure (10):** Сервер требует обновления конфигурации
* **Information-Request (11):** Запрос только опций (для stateless режима)

### DUID (DHCP Unique Identifier)

Уникальный идентификатор клиента DHCPv6, который сохраняется при смене сетевого интерфейса:

* **DUID-LLT:** На основе MAC + времени создания
* **DUID-EN:** Enterprise Number + идентификатор производителя
* **DUID-LL:** Только на основе MAC-адреса
* **DUID-UUID:** На основе UUID системы

### Идентификаторы Identity Association (IA)

* **IAID (Identity Association Identifier):** Идентификатор, назначаемый клиентом для каждого интерфейса
* **IA_NA (Non-temporary Address):** Ассоциация для обычных IPv6-адресов
* **IA_TA (Temporary Address):** Ассоциация для временных адресов (privacy extensions)
* **IA_PD (Prefix Delegation):** Делегирование префикса для маршрутизаторов

### Практические сценарии DHCPv6

**Настройка Stateful DHCPv6 (Linux с ISC DHCP):**

```bash
# /etc/dhcp/dhcpd6.conf
default-lease-time 600;
max-lease-time 7200;

subnet6 2001:db8::/64 {
    # Диапазон для выдачи
    range6 2001:db8::100 2001:db8::200;
    
    # DNS серверы
    option dhcp6.name-servers 2001:4860:4860::8888, 2001:4860:4860::8844;
    
    # Домен
    option dhcp6.domain-search "example.com";
    
    # Резервирование по DUID
    host client1 {
        host-identifier option dhcp6.client-id 00:01:00:01:12:34:56:78:aa:bb:cc:dd:ee:ff;
        fixed-address6 2001:db8::50;
    }
}
```

**Настройка Stateless DHCPv6:**

```bash
# Только опции, без выдачи адресов
subnet6 2001:db8::/64 {
    # Адреса через SLAAC
    range6 2001:db8::100 2001:db8::200 temporary;
    
    # DNS и другие опции через DHCPv6
    option dhcp6.name-servers 2001:4860:4860::8888;
    option dhcp6.domain-search "example.com";
}
```
