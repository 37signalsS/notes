# Протокол DNS (Domain Name System)

## Определения

**DNS (Domain Name System — система доменных имён)** — иерархическая распределённая база данных для преобразования человекочитаемых доменных имён в IP-адреса и обратно.

*   **Резолвер (Resolver):** программный компонент, выполняющий процесс разрешения имени.
    *   **Stub Resolver (Заглушка):** минимальная библиотека на стороне клиента (например, в `glibc`), которая только передаёт запрос рекурсивному серверу.
    *   **Recursive Resolver (Рекурсивный резолвер):** сервер, который выполняет всю цепочку запросов от корня до авторитетного сервера за клиента.
*   **Ресурсная запись (Resource Record, RR):** базовая единица данных в DNS (A, MX, CNAME и др.).
*   **Авторитетный ответ (Authoritative Answer):** ответ от сервера, владеющего зоной (флаг `AA`).
*   **Неавторитетный ответ (Non-Authoritative Answer):** ответ, извлечённый из кэша промежуточного сервера.
*   **TTL (Time To Live):** время актуальности записи в кэше (в секундах).
*   **RCODE (Response Code):** код результата выполнения запроса (например, `NOERROR`, `NXDOMAIN`).

## Базовые концепции

### Роли серверов

*   **Авторитетный сервер (Authoritative DNS Server):** хранит оригинальные файлы зон и несёт ответственность за точность данных в них.
*   **Рекурсивный резолвер (Recursive DNS Resolver):** "интеллектуальный" посредник, который кэширует ответы для ускорения последующих запросов.

### Транспортные протоколы и порты

Традиционно DNS работает на порту **53 (UDP/TCP)**, но современные стандарты расширяют этот список:

*   **UDP/53:** основной транспорт для быстрых и коротких запросов.
*   **TCP/53:** используется при превышении лимита размера UDP-пакета (флаг `TC` — Truncated) и для трансфера зон (AXFR/IXFR).
*   **DoT (DNS over TLS) — Порт 853:** шифрование DNS-трафика поверх TCP.
*   **DoH (DNS over HTTPS) — Порт 443:** инкапсуляция DNS-запросов в HTTPS-трафик для обхода блокировок и повышения приватности.
*   **DoQ (DNS over QUIC) — Порт 853:** современный стандарт (RFC 9250), обеспечивающий шифрование и устраняющий проблему блокировки начала очереди (Head-of-Line blocking) благодаря UDP/QUIC.

### Расширения протокола (EDNS)

**EDNS0 (Extension Mechanisms for DNS, RFC 6891)** — механизм обратной совместимости для добавления новых полей и флагов в DNS-пакет.
*   Позволяет увеличить размер UDP-пакета свыше 512 байт (обычно до 1232 или 4096 байт).
*   Добавляет поддержку ECS (EDNS Client Subnet) для оптимизации Geo-DNS.

### Иерархия и структура

Система организована в виде перевёрнутого дерева:
1.  **Корень (`.`):** управляется 13 группами корневых серверов.
2.  **TLD (Top-Level Domain):** домены верхнего уровня (.com, .ru, .org).
3.  **SLD (Second-Level Domain):** домены второго уровня (google.com, yandex.ru).

Подробности и роль ICANN: [Основные концепции DNS](./dns_concepts.md).

### Процесс разрешения имён

Включает итеративные и рекурсивные обращения. Резолвер последовательно опрашивает Root → TLD → Authoritative сервера.
Детальный разбор процесса: [Процесс разрешения имён в DNS](./dns_resolution.md).

### Формат сообщения и типы записей

DNS-пакет состоит из заголовка (Header), секции запроса (Question) и секций ответов (Answer, Authority, Additional).
*   [Формат DNS-сообщения](./dns_message_format.md) — структура и флаги пакета.
*   [Типы DNS-записей](./dns_records.md) — обзор A, AAAA, MX, CNAME, SRV, а также современных записей **HTTPS/SVCB** (RFC 9460).

## Практические сценарии

### Коды ответов (RCODE)

Понимание кодов ответов критично для диагностики:
*   **NOERROR (0):** запрос успешно выполнен.
*   **FORMERR (1):** ошибка формата запроса.
*   **SERVFAIL (2):** сервер не смог обработать запрос из-за внутренней ошибки или проблем с вышестоящими серверами.
*   **NXDOMAIN (3):** запрашиваемое доменное имя не существует.
*   **REFUSED (5):** сервер отказался выполнять запрос (например, из-за настроек ACL).

### Настройка DNS-клиента в ОС

В Linux конфигурация управляется через `/etc/resolv.conf`, `/etc/hosts` и системные службы.
Подробности: [DNS-клиент в Linux](../../../Linux/Networking/Concepts/dns_client.md).

### Диагностика протокола

Основные инструменты для проверки и отладки:
*   `dig` — рекомендуемый инструмент для глубокого анализа ответов и флагов.
*   `resolvectl` — утилита для взаимодействия с `systemd-resolved` в современных дистрибутивах.
*   `nslookup` / `host` — простые утилиты для быстрой проверки разрешения имён.

Примеры использования: [Диагностика DNS](../../../Linux/Diagnostics/Networking/dns/overview.md).
