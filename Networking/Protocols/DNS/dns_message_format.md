# Формат DNS-сообщения

## Определения

**DNS-сообщение (DNS Message)** — атомарная единица обмена данными в протоколе DNS, имеющая фиксированную бинарную структуру для запросов и ответов. Сообщения передаются в сетевом порядке байтов (Big-Endian).

*   **Transaction ID (Идентификатор транзакции):** 16-битное число, генерируемое клиентом для сопоставления ответа с конкретным запросом. Служит первичной защитой от подмены ответов.
*   **Label (Метка):** часть доменного имени, ограниченная точками. В бинарном виде предваряется байтом длины.
*   **Name Compression (Сжатие имен):** метод уменьшения размера пакета путём замены повторяющихся частей имен 14-битными указателями (Pointers).
*   **EDNS0 (RFC 6891):** механизмы расширения, позволяющие передавать данные > 512 байт по UDP и новые управляющие флаги через псевдо-запись **OPT**.

## Базовые концепции

### Общая структура пакета

Сообщение DNS состоит из заголовка фиксированной длины (12 байт) и четырех секций переменной длины.

```text
+---------------------+
|      Header         | (Фиксировано: 12 байт)
+---------------------+
|      Question       | (Запрашиваемые имена и типы)
+---------------------+
|       Answer        | (Ресурсные записи ответов)
+---------------------+
|      Authority      | (Записи о серверах имен)
+---------------------+
|      Additional     | (Дополнительные данные, включая OPT RR)
+---------------------+
```

### Структура заголовка (Header)

| Поле | Размер | Назначение |
| :--- | :--- | :--- |
| **Transaction ID** | 16 бит | Идентификатор сессии. |
| **Flags** | 16 бит | Управляющие биты и код ответа. |
| **QDCOUNT** | 16 бит | Количество записей в секции Question. |
| **ANCOUNT** | 16 бит | Количество записей в секции Answer. |
| **NSCOUNT** | 16 бит | Количество записей в секции Authority. |
| **ARCOUNT** | 16 бит | Количество записей в секции Additional. |

#### Детализация флагов (16 бит)

| Бит(ы) | Имя | Описание |
| :--- | :--- | :--- |
| 0 | **QR** | Query/Response: `0` — запрос, `1` — ответ. |
| 1-4 | **Opcode** | Тип запроса: `0` (QUERY), `4` (NOTIFY), `5` (UPDATE). |
| 5 | **AA** | Authoritative Answer: ответ от владельца зоны (`1`). |
| 6 | **TC** | TrunCation: пакет обрезан из-за лимита UDP (`1`). |
| 7 | **RD** | Recursion Desired: просить сервер о рекурсии (`1`). |
| 8 | **RA** | Recursion Available: сервер поддерживает рекурсию (`1`). |
| 9 | **Z** | Reserved: зарезервировано, всегда `0`. |
| 10 | **AD** | Authentic Data: данные проверены через DNSSEC (`1`). |
| 11 | **CD** | Checking Disabled: отключить проверку DNSSEC (`1`). |
| 12-15 | **RCODE** | Response Code: код результата (0 — успех, 3 — NXDOMAIN). |

### Структура секции Question

Каждый вопрос состоит из трех полей:
1.  **QNAME:** доменное имя (переменная длина, последовательность меток).
2.  **QTYPE:** тип запрашиваемой записи (A, MX, ANY) — 16 бит.
3.  **QCLASS:** класс сети (обычно `IN` = 1) — 16 бит.

### Структура секций данных (Answer/Authority/Additional)

Все ресурсные записи (RR) имеют единый формат:
1.  **NAME:** доменное имя (с использованием сжатия).
2.  **TYPE:** тип записи (A, NS, SOA и др.) — 16 бит.
3.  **CLASS:** класс (обычно `IN`) — 16 бит.
4.  **TTL:** время жизни в кэше — 32 бита.
5.  **RDLENGTH:** длина поля RDATA в байтах — 16 бит.
6.  **RDATA:** данные записи (IP-адрес, имя хоста и т.д.) — переменная длина.

### Механизм сжатия имен (Pointers)

Для экономии места DNS использует указатели. Если имя или его часть (например, `.example.com`) уже встречались в пакете:
*   Первые два бита байта устанавливаются в `11` (значение `0xC0`).
*   Оставшиеся 14 бит указывают на **смещение (offset)** в байтах от начала пакета, где это имя описано впервые.
*   Пример: `0xC00C` — указатель на имя, начинающееся с 12-го байта пакета.

### Расширенный DNS (EDNS0, RFC 6891)

Так как заголовок DNS фиксирован, EDNS использует псевдо-запись типа **OPT** в секции `Additional`.
*   **OPT RR:** не является реальной записью, а служит контейнером для метаданных.
*   **UDP Payload Size:** (в поле CLASS) — размер буфера клиента (например, 1232 байта).
*   **Extended RCODE:** (в поле TTL) — дополнительные 8 бит для кода ответа (всего становится 12 бит).
*   **EDNS Flags:** (в поле TTL) — включает флаг **DO** (DNSSEC OK) для запроса подписей.

## Практические сценарии

### 1. Анализ сырого пакета через tshark/tcpdump

Чтобы увидеть бинарную структуру и Transaction ID без интерпретации утилит типа `dig`:

```bash
# Перехват DNS-запроса и вывод в HEX
sudo tcpdump -i eth0 udp port 53 -XX -vv
```

### 2. Проверка флага TC (Truncation)

Если ответ превышает лимит (обычно 512 байт без EDNS или 1232 с EDNS), сервер устанавливает бит `TC`.

```bash
# Запрос, провоцирующий большой ответ (например, DNSSEC для корневой зоны)
dig . NS +dnssec +bufsize=512
# Если в ответе есть флаг 'tc', клиент должен переключиться на TCP.
```

### 3. Интерпретация RCODE в логах

При анализе логов BIND или CoreDNS коды ошибок помогают быстро найти причину:
*   **NXDOMAIN (3):** опечатка в имени или домен не существует.
*   **SERVFAIL (2):** проблема с цепочкой доверия DNSSEC или таймаут вышестоящего сервера.
*   **REFUSED (5):** запрос заблокирован ACL или политикой RPZ.
