# Основные концепции DNS

## Определения

**DNS (Domain Name System — система доменных имён)** — иерархическая распределённая база данных, обеспечивающая преобразование человекочитаемых имен хостов в сетевые адреса и обратно.

*   **FQDN (Fully Qualified Domain Name):** полное доменное имя, однозначно определяющее узел в иерархии (например, `www.google.com.`). Финальная точка указывает на корень дерева.
*   **TLD (Top-Level Domain):** домен верхнего уровня, правая часть имени после последней точки (`.com`, `.ru`).
*   **IDN (Internationalized Domain Names):** доменные имена, содержащие символы национальных алфавитов (кириллица, иероглифы).
*   **Punycode:** алгоритм кодирования IDN-имен в последовательности ASCII-символов, начинающиеся с префикса `xn--` (например, `президент.рф` → `xn--d1abbgf6aiiy.xn--p1ai`).
*   **ICANN:** международная организация, координирующая управление адресным пространством интернета и корневой зоной DNS.
*   **RDAP (Registration Data Access Protocol):** современный протокол доступа к регистрационным данным (замена устаревшему WHOIS), обеспечивающий структурированный формат (JSON) и контроль доступа.

## Базовые концепции

### Иерархия доменного пространства

Система DNS построена в виде перевёрнутого дерева:

1.  **Корень (Root Zone):** обозначается точкой (`.`). Обслуживается 13 группами корневых серверов (A–M), которые распределены по миру с помощью Anycast.
2.  **Домены верхнего уровня (TLD):**
    *   **ccTLD (country code):** национальные домены (`.ru`, `.cn`, `.uk`).
    *   **gTLD (generic):** общие домены (`.com`, `.net`, `.org`).
    *   **new gTLD:** расширенные домены, появившиеся после 2012 года (`.dev`, `.cloud`, `.moscow`).
3.  **Домены второго уровня (SLD):** регистрируются организациями или частными лицами (`example.com`).
4.  **Поддомены (Subdomains):** создаются владельцем SLD для сегментации ресурсов (`blog.example.com`).

### История: от файла hosts к DNS

Первоначально (до 1983 г.) для разрешения имен использовался файл `hosts`.
*   **Проблема:** сложность синхронизации огромного текстового файла на всех узлах сети при её бурном росте.
*   **Современность:** файл `/etc/hosts` (Linux/macOS) или `C:\Windows\System32\drivers\etc\hosts` (Windows) сохраняет наивысший приоритет для локальной отладки и переопределения имен. Порядок опроса (файлы vs DNS) настраивается в `/etc/nsswitch.conf`.

### Регистрация и владение доменами

Управление данными о владельцах и сроках регистрации осуществляется через иерархию:
*   **Registry (Реестр):** организация, владеющая базой данных конкретного TLD (например, Verisign для `.com`).
*   **Registrar (Регистратор):** аккредитованная компания, предоставляющая услуги регистрации пользователям.
*   **Registrant (Регистрант):** конечный владелец доменного имени.

### Интернациональные имена (IDN)

Для поддержки национальных языков используется Punycode-преобразование. DNS-серверы и протоколы по-прежнему работают только с ASCII, а конвертация происходит на стороне клиентского приложения (браузера).

## Практические сценарии

### 1. Трассировка иерархии через dig

Флаг `+trace` позволяет увидеть пошаговый процесс разрешения имени от корня до авторитетного сервера.

```bash
# Просмотр делегирования от корневых серверов вниз
dig google.com +trace
```

### 2. Получение данных о регистрации через RDAP

В отличие от `whois`, утилиты RDAP возвращают структурированный JSON (при поддержке регистратором).

```bash
# Пример использования curl для запроса RDAP (если установлен jq)
curl -s https://rdap.verisign.com/com/v1/domain/example.com | jq .
```
Обычный `whois` также часто перенаправляет запросы к RDAP-серверам в фоне. См. [whois — утилита и протокол](../../ServicesAndTools/whois.md).

### 3. Конвертация IDN в Punycode

Для проверки соответствия кириллического домена его ASCII-представлению:

```bash
# Использование утилиты idn (пакет libidn)
idn президент.рф
# -> xn--d1abbgf6aiiy.xn--p1ai
```
