# Основные концепции DNS

## Определения

**DNS (Domain Name System)** — распределённая система преобразования доменных имён в IP-адреса и обратно. Является иерархической базой данных, обеспечивающей глобальную адресацию ресурсов в Интернете. Подробности: [Протокол DNS](./dns.md).

**FQDN (Fully Qualified Domain Name)** — полное доменное имя, включающее все уровни иерархии с завершающей точкой (например, `drive.google.com.`). Точка в конце указывает на корневой домен.

**TLD (Top-Level Domain)** — домен верхнего уровня, являющийся частью имени после последней точки (`.com`, `.ru`, `.org`).

**ICANN (Internet Corporation for Assigned Names and Numbers)** — международная некоммерческая организация, управляющая распределением TLD и корневой зоной DNS.

## Базовые концепции

### Преимущества DNS

| Преимущество | Описание |
| :--- | :--- |
| **Удобство** | Запоминаемые имена вместо цифровых IP-адресов |
| **Гибкость** | Возможность смены IP-адреса без изменения доменного имени |
| **Масштабируемость** | Распределённая нагрузка через несколько серверов |
| **Отказоустойчивость** | Отсутствие единой точки отказа благодаря кэшированию и иерархии |

### История: от файла hosts к DNS

До 1983 года разрешение имён выполнялось с помощью текстового файла `hosts`, который содержал таблицу соответствия IP и имён.

**Недостатки файла hosts:**
- **Масштабируемость:** Невозможно поддерживать актуальность единого файла при росте сети.
- **Коллизии:** Трудности с обеспечением уникальности имён в глобальном масштабе.

**Современное использование:**
Файл по-прежнему существует в ОС для локального переопределения имён. Порядок его проверки определяется в `/etc/nsswitch.conf` (обычно `files` имеет приоритет перед `dns`).
- **Пути:** `/etc/hosts` (Linux/macOS), `C:\Windows\System32\drivers\etc\hosts` (Windows).
- **Подробности:** [Настройка DNS-клиента в Linux](../../../Linux/Networking/Concepts/dns_client.md).

### Иерархия доменных имён

DNS-пространство организовано в виде перевёрнутого дерева:

```
Корневой домен (.)
└── TLD (.com, .ru, .org)
    └── SLD (example.com, yandex.ru)
        └── Поддомен (www.example.com, maps.yandex.ru)
```

1. **Корневой уровень (`.`):** Обслуживается 13 кластерами серверов (A-M), имеющими сотни физических узлов по всему миру.
2. **TLD (Top-Level Domain):** 
   - **gTLD (generic):** общие домены (`.com`, `.net`, `.info`). Всего существует 1500+ gTLD.
   - **ccTLD (country code):** национальные домены (`.ru`, `.uk`, `.de`).
3. **SLD (Second-Level Domain):** Домены, регистрируемые организациями или частными лицами (например, `google.com`).

**Чтение FQDN:** Происходит справа налево — от общего (корень) к частному (хост).

### Регистраторы и ICANN

**ICANN** координирует работу глобальной системы DNS, но не регистрирует домены напрямую. Эта роль возложена на **Регистраторов** — аккредитованные организации, обеспечивающие интерфейс для покупки и управления доменами.

**Регистры (Registries):** Организации, управляющие базами данных конкретных TLD (например, Verisign для `.com`).

## Практические сценарии

### Анализ иерархии через dig

Использование флага `+trace` позволяет увидеть путь разрешения имени от корневых серверов до авторитетного сервера.

```bash
# Просмотр пути делегирования
dig +trace example.com

# Определение серверов, отвечающих за TLD
dig ru NS
```

### Проверка авторитетных серверов

Для изменения записей домена необходимо знать, какие серверы (NS-записи) являются для него авторитетными.

```bash
# Поиск NS-записей домена
dig example.com NS
```

### Выбор регистратора

При выборе регистратора следует учитывать:
- Поддержку управления DNSSEC — [Безопасность DNS](./dns_security.md).
- Наличие API для автоматизации обновлений (например, для ACME/Let's Encrypt).
- Поддержку скрытия данных владельца (WHOIS Privacy).
