# Основные концепции DNS

## Определения

**DNS** — распределённая система преобразования доменных имён в IP-адреса и обратно. Подробности: [Протокол DNS](./dns.md).

**FQDN (Fully Qualified Domain Name)** — полное доменное имя, включающее все уровни иерархии с завершающей точкой (например, `drive.google.com.`).

**TLD (Top-Level Domain)** — домен верхнего уровня (`.com`, `.ru`, `.org`).

**ICANN (Internet Corporation for Assigned Names and Numbers)** — организация, управляющая корневым доменом и распределением TLD.

## Базовые концепции

### Преимущества DNS

| Преимущество | Описание |
|--------------|----------|
| **Удобство** | Доменные имена легче запоминать, чем IP-адреса |
| **Гибкость** | Можно менять IP без изменения доменного имени |
| **Масштабируемость** | Одно имя может обслуживаться несколькими серверами |
| **Отказоустойчивость** | Распределённая архитектура без единой точки отказа |

### История: от файла hosts к DNS

**Файл `/etc/hosts`** — исходный механизм разрешения имён (до 1983 г.).

**Недостатки централизованного подхода:**

- **Масштабируемость:** Рост Интернета сделал поддержку единого файла невозможной
- **Актуальность:** Частые изменения IP требовали постоянных обновлений
- **Конфликты:** Отсутствие механизма разрешения коллизий имён

**Порядок проверки:** Система проверяет `/etc/hosts` **перед** обращением к DNS (если `files` указан первым в `/etc/nsswitch.conf`). Подробнее о настройке DNS-клиента в Linux: [DNS-клиент](../../../Linux/Networking/Concepts/dns_client.md).

> **Вектор атаки:** Вредоносное ПО может добавлять записи в `/etc/hosts` для перенаправления трафика на фишинговые сайты.

### Иерархия доменных имён

```
Корневой домен (.)
└── TLD (.com, .ru, .org)
    └── SLD (example.com, yandex.ru)
        └── Поддомен (www.example.com, maps.yandex.ru)
```

**Уровни иерархии:**

| Уровень | Пример | Описание |
|---------|--------|----------|
| **Корневой** | `.` | Включает все домены (13 кластеров серверов) |
| **TLD** | `.com`, `.ru` | Общие (gTLD) и национальные (ccTLD) |
| **SLD** | `example.com` | Регистрируемые домены второго уровня |
| **Поддомен** | `www.example.com` | Домены третьего+ уровня |

**Чтение FQDN:** Справа налево (от общего к частному):

```
drive.google.com.
  ↑      ↑     ↑  ↑
  хост  домен  TLD корень
```

### Регистраторы и ICANN

**ICANN:**

- Управление корневым доменом
- Распределение TLD между регистраторами
- Координация глобальной DNS-политики

**Регистраторы доменов:**

- Аккредитованные ICANN организации
- Регистрация доменов для конечных пользователей
- Поддержка уникальности имён в зоне
- Примеры: GoDaddy, Namecheap, Reg.ru (для `.ru`/`.рф`)

**Координационный центр домена `.ru`:**

- Координация деятельности регистраторов в РФ
- Поддержка национальной доменной зоны

## Практические сценарии

### Проверка иерархии домена

```bash
# Трассировка делегирования от корневых серверов
dig +trace example.com

# Определение TLD-серверов
dig com NS
dig ru NS

# Проверка авторитетных серверов домена
dig example.com NS
```

### Выбор регистратора

**Критерии:**

- Поддержка нужных TLD (`.com`, `.ru`, `.org`)
- Цена продления (не только первичной регистрации)
- API для автоматизации (ACME для SSL, DNS API)
- Поддержка DNSSEC — [Безопасность DNS](./dns_security.md)
- Двухфакторная аутентификация

## Дополнительная информация

- Количество корневых серверов: 13 кластеров (A–M), сотни физических узлов
- Общее количество TLD: 1500+ (gTLD + ccTLD)
- Базовые спецификации: RFC 1034, 1035
- Файл hosts: `/etc/hosts` (Linux), `C:\Windows\System32\drivers\etc\hosts` (Windows)
