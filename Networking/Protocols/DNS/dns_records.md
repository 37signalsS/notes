# Типы записей DNS

## Определения

**Ресурсная запись (Resource Record, RR)** — базовая единица данных в DNS, содержащая информацию о домене.

**Класс записей** — категория данных (почти всегда `IN` для Internet).

**TTL** — время жизни записи в кэше резолвера. Подробности: [Протокол DNS](./dns.md#определения).

## Базовые концепции

### Основные типы записей

| Запись | Назначение | Пример |
|--------|------------|--------|
| **A** | IPv4-адрес домена | `example.com A 93.184.216.34` |
| **AAAA** | IPv6-адрес домена | `example.com AAAA 2001:db8::1` |
| **CNAME** | Псевдоним (alias) для другого домена | `www.example.com CNAME example.com` |
| **MX** | Почтовый сервер (с приоритетом) | `example.com MX 10 mail.example.com` |
| **NS** | Авторитетный DNS-сервер зоны | `example.com NS ns1.example.net` |
| **PTR** | Обратное разрешение (IP → имя) | `34.216.184.93.in-addr.arpa PTR example.com` |
| **SOA** | Начальная запись зоны (Start of Authority) | См. [Зоны DNS](./dns_zones.md) |
| **TXT** | Произвольный текст (SPF, DKIM, верификация) | `example.com TXT "v=spf1 include:_spf.google.com ~all"` |

### Детальный разбор основных записей

* **A (Address)** — сопоставляет доменное имя с **IPv4-адресом**. Это самая частая запись, «фундамент» DNS.
* **CNAME (Canonical Name)** — указывает, что домен является **псевдонимом** другого домена.
  * **Важно**: При запросе CNAME резолвер должен выполнить повторный поиск для целевого домена.
  * **Ограничение**: CNAME не может существовать для корневого домена (apex) вместе с другими записями (например, MX или NS).
* **MX (Mail Exchanger)** — определяет **почтовый сервер** для домена.
  * Имеет поле **приоритета** (чем ниже число, тем выше приоритет).
  * Целью MX-записи должен быть домен (хост), имеющий собственную **A** или **AAAA** запись, а не другой CNAME.
* **NS (Name Server)** — указывает на **авторитетные DNS-серверы**, которые хранят информацию об этой зоне.
  * Именно через NS-записи происходит делегирование поддоменов.
* **PTR (Pointer)** — используется для **обратного разрешения** (IP → Имя).
  * Эти записи живут в специальных зонах (например, `in-addr.arpa` для IPv4). Используются почтовыми серверами для борьбы со спамом и в диагностических утилитах типа `traceroute`.

| Запись | Назначение | Пример |
|--------|------------|--------|
| **CAA** | Разрешённые центры сертификации (SSL) | `example.com CAA 0 issue "letsencrypt.org"` |
| **DNSKEY** | Открытый ключ DNSSEC | Для верификации подписей |
| **DS** | Delegations Signer (цепочка доверия DNSSEC) | `example.com DS 12345 8 2 ...` |
| **TLSA** | Привязка TLS-сертификатов к домену (DANE) | `_443._tcp.example.com TLSA ...` |
| **SSHFP** | Отпечаток SSH-ключа | `example.com SSHFP 1 1 1234567890abcdef...` |
| **DMARC** | Политика защиты почты (через TXT) | `_dmarc.example.com TXT "v=DMARC1; p=reject"` |

### Записи для сервисов

| Запись | Назначение | Пример |
|--------|------------|--------|
| **SRV** | Расположение сервиса (хост + порт) | `_sip._tcp.example.com SRV 10 60 5060 sipserver.example.com` |
| **NAPTR** | Динамическое определение сервисов (VoIP) | Используется с SIP |
| **HTTPS** | Параметры подключения HTTPS (альтернатива SVCB) | `example.com HTTPS 1 . alpn="h3,h2"` |
| **SVCB** | Service Binding (универсальная запись) | `example.com SVCB 1 target.example.com alpn="h3"` |

> **Актуальность (2025):** Записи **HTTPS** и **SVCB** (RFC 9460) набирают поддержку. Позволяют указать предпочтительные протоколы (HTTP/3, DoH), ускоряя установку соединения. Браузер запрашивает HTTPS-запись автоматически при первом обращении к домену, что позволяет использовать HTTP/3 с первого запроса, минуя проблему «холодного старта» с заголовком `Alt-Svc`.

## Практические сценарии

### Проверка записей домена

```bash
# Все записи домена
dig example.com ANY

# Записи конкретного типа
dig example.com MX
dig example.com TXT
dig example.com HTTPS

# Обратный DNS (PTR)
dig -x 93.184.216.34

# Проверка CAA (SSL-сертификаты)
dig example.com CAA
```

### Настройка CAA для SSL

Разрешить выдачу SSL-сертификатов только Let's Encrypt:

```dns
example.com CAA 0 issue "letsencrypt.org"
example.com CAA 0 issuewild "letsencrypt.org"  # Для wildcard-сертификатов
```

### Настройка HTTPS-записи

Указание поддержки HTTP/3 и HTTP/2:

```dns
example.com HTTPS 1 . alpn="h3,h2"
```

Это позволяет клиенту узнать поддерживаемые протоколы до установки TLS-соединения.

**Формат записи:**

```
NAME HTTPS priority target alpn="..."
```

* **priority** — приоритет (как в MX-записях). `1` — стандартное значение.
* **target** — целевой хост. `.` (точка) означает «этот же домен».
* **alpn** — список протоколов через запятую: `h3` (HTTP/3), `h2` (HTTP/2).

**Ограничения:**

* **Несовместимость с CNAME:** Если для домена установлена запись типа `CNAME`, создать HTTPS-запись не получится. Требуется использовать `A` или `AAAA` запись.
* **Требование к DNS-провайдеру:** Не все DNS-провайдеры поддерживают тип `HTTPS`. Проверьте документацию вашего провайдера.

**Проверка записи:**

```bash
# Проверка HTTPS-записи
dig example.com HTTPS

# Проверка SVCB-записи
dig example.com SVCB
```

**Проблема «холодного старта» HTTP/3:**

Без HTTPS-записи браузер узнаёт о поддержке HTTP/3 только после получения заголовка `Alt-Svc` от сервера. Это приводит к следующей последовательности:

1. Первый запрос → TCP + TLS handshake → HTTP/2 (браузер ещё не знает о HTTP/3)
2. Получение заголовка `Alt-Svc: h3=":443"; ma=86400`
3. Последующие запросы → HTTP/3 (QUIC)

**С HTTPS-записью:**

1. DNS-запрос → получение A + HTTPS записи
2. Браузер сразу знает о поддержке HTTP/3
3. Первый запрос → QUIC handshake → HTTP/3

**Фактическое поведение браузеров (Chrome 2025):**

Даже при наличии HTTPS-записи браузеры могут использовать гибридный сценарий:

* Параллельно создаются TCP и QUIC соединения
* Первые 1-2 запроса могут пойти по TCP/HTTP/2 (резервный канал)
* После подтверждения работоспособности QUIC → переключение на HTTP/3

Это связано с тем, что QUIC может быть заблокирован на уровне провайдера или фаервола, поэтому браузеры перестраховываются.

**Тестирование:**

* **Чистая загрузка:** `Ctrl+Shift+R` (Hard Reload) с опцией «Disable cache» не отменяет кэширование `Alt-Svc`. Для полностью чистой загрузки используйте режим инкогнито или специализированные инструменты (например, `fad` тесты).
* **Анализ пакетов:** Wireshark покажет порядок установки соединений (TCP vs QUIC) и момент переключения на HTTP/3.
* **DevTools:** Вкладка Network → колонка Protocol покажет используемый протокол для каждого запроса (H2, H3).

## Дополнительная информация

* **Синтаксис записей:** `NAME TTL CLASS TYPE RDATA`
* **Классы:** `IN` (Internet), `CH` (Chaos), `HS` (Hesiod) — почти всегда `IN`
* **Базовая спецификация:** RFC 1035; HTTPS/SVCB: RFC 9460 (2023)
* **Обратный DNS:** используется зона `in-addr.arpa` — [Зоны DNS](./dns_zones.md)
* **DNSSEC-записи:** DNSKEY, DS, RRSIG — [Безопасность DNS](./dns_security.md)
* **SPF (Type 99) устарела:** с июля 2025 провайдеры прекращают поддержку. Используйте TXT: `"v=spf1 ..."`
