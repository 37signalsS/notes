# Типы записей DNS

## Определения

**Ресурсная запись (Resource Record, RR)** — базовая единица данных в DNS, содержащая информацию о домене.

**Класс записей** — категория данных (почти всегда `IN` для Internet).

**TTL (Time To Live)** — время жизни записи в кэше резолвера (в секундах).

## Основные концепции

### Основные типы записей

| Запись | Назначение | Пример |
|--------|------------|--------|
| **A** | IPv4-адрес домена | `example.com A 93.184.216.34` |
| **AAAA** | IPv6-адрес домена | `example.com AAAA 2001:db8::1` |
| **CNAME** | Псевдоним (alias) для другого домена | `www.example.com CNAME example.com` |
| **MX** | Почтовый сервер (с приоритетом) | `example.com MX 10 mail.example.com` |
| **NS** | Авторитетный DNS-сервер зоны | `example.com NS ns1.example.net` |
| **PTR** | Обратное разрешение (IP → имя) | `34.216.184.93.in-addr.arpa PTR example.com` |
| **SOA** | Начальная запись зоны (Start of Authority) | См. [Зоны DNS](./dns_zones.md) |
| **TXT** | Произвольный текст (SPF, DKIM, верификация) | `example.com TXT "v=spf1 include:_spf.google.com ~all"` |

### Записи для безопасности и сервисов

| Запись | Назначение | Пример |
|--------|------------|--------|
| **CAA** | Разрешённые центры сертификации (SSL) | `example.com CAA 0 issue "letsencrypt.org"` |
| **DNSKEY** | Открытый ключ DNSSEC | Для верификации подписей |
| **DS** | Delegations Signer (цепочка доверия DNSSEC) | `example.com DS 12345 8 2 ...` |
| **TLSA** | Привязка TLS-сертификатов к домену (DANE) | `_443._tcp.example.com TLSA ...` |
| **SSHFP** | Отпечаток SSH-ключа | `example.com SSHFP 1 1 1234567890abcdef...` |
| **DMARC** | Политика защиты почты (через TXT) | `_dmarc.example.com TXT "v=DMARC1; p=reject"` |

### Записи для сервисов

| Запись | Назначение | Пример |
|--------|------------|--------|
| **SRV** | Расположение сервиса (хост + порт) | `_sip._tcp.example.com SRV 10 60 5060 sipserver.example.com` |
| **NAPTR** | Динамическое определение сервисов (VoIP) | Используется с SIP |
| **HTTPS** | Параметры подключения HTTPS (альтернатива SVCB) | `example.com HTTPS 1 . alpn="h3,h2"` |
| **SVCB** | Service Binding (универсальная запись) | `example.com SVCB 1 target.example.com alpn="h3"` |

> **Актуальность (2025):** Записи **HTTPS** и **SVCB** (RFC 9460) набирают поддержку. Позволяют указать предпочтительные протоколы (HTTP/3, DoH), ускоряя установку соединения.

| **CNAME** | 1035 | Псевдоним | Повсеместно |
| **MX** | 1035 | Почтовый обменник | Повсеместно |
| **NS** | 1035 | Сервер имён | Повсеместно |
| **PTR** | 1035 | Обратный указатель | Повсеместно |
| **SOA** | 1035 | Начальная запись зоны | Повсеместно |
| **TXT** | 1035 | Текстовая запись | Повсеместно |
| **SRV** | 2782 | Расположение сервиса | Широко |

| **DS** | 4034 | Делегирование DNSSEC | Широко |
| **TLSA** | 6698 | Привязка TLS-сертификата | Специализированная |
| **SSHFP** | 4255 | Отпечаток SSH | Специализированная |

## Практические сценарии

### Проверка записей домена

```bash
# Все записи домена
dig example.com ANY

# Записи конкретного типа
dig example.com MX
dig example.com TXT
dig example.com HTTPS

# Обратный DNS (PTR)
dig -x 93.184.216.34

# Проверка CAA (SSL-сертификаты)
dig example.com CAA
```

### Настройка CAA для SSL

Разрешить выдачу SSL-сертификатов только Let's Encrypt:

```dns
example.com CAA 0 issue "letsencrypt.org"
example.com CAA 0 issuewild "letsencrypt.org"  # Для wildcard-сертификатов
```

### Настройка HTTPS-записи

Указание поддержки HTTP/3 и HTTP/2:

```dns
example.com HTTPS 1 . alpn="h3,h2"
```

Это позволяет клиенту узнать поддерживаемые протоколы до установки TLS-соединения.

## Дополнительная информация

- **Синтаксис записей:** `NAME TTL CLASS TYPE RDATA`
- **Классы:** `IN` (Internet), `CH` (Chaos), `HS` (Hesiod) — почти всегда `IN`
- **Спецификация:** RFC 1035 (базовая), RFC 9460 (HTTPS/SVCB, 2023)
- **Инструменты:** `dig`, `nslookup`, онлайн-проверки (MXToolbox, DNSViz)
