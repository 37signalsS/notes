# Типы записей DNS

## Определения

**Ресурсная запись (Resource Record, RR)** — базовая единица данных в DNS, содержащая информацию о домене или сервисе.

**Тип записи (Type)** — двухбайтовое поле, определяющее формат и назначение данных (A, MX, TXT и др.).

**TTL (Time To Live)** — время в секундах, в течение которого резолвер может хранить запись в кэше. Подробности: [Протокол DNS](./dns.md).

## Базовые концепции

### Основные типы записей

| Запись | Назначение | Пример значения |
| :--- | :--- | :--- |
| **A** | IPv4-адрес хоста | `93.184.216.34` |
| **AAAA** | IPv6-адрес хоста | `2001:db8::1` |
| **CNAME** | Каноническое имя (псевдоним) | `example.com.` |
| **MX** | Почтовый сервер (Mail Exchanger) | `10 mail.example.com.` |
| **NS** | Авторитетный сервер имён | `ns1.example.net.` |
| **PTR** | Обратное разрешение (IP → Имя) | `example.com.` |
| **SOA** | Начальная запись зоны | [Зоны DNS](./dns_zones.md) |
| **TXT** | Произвольные текстовые данные | `"v=spf1 ..."` |

### Детальный разбор записей

* **A (Address):** сопоставляет имя с IPv4-адресом. Самая распространённая запись.
* **CNAME (Canonical Name):** указывает, что домен является псевдонимом другого домена.
  * *Ограничение:* не может сосуществовать с другими типами записей для одного имени (кроме DNSSEC). Не рекомендуется использовать для apex-домена (корня зоны).
* **MX (Mail Exchanger):** определяет хост для приёма почты. Содержит числовой приоритет (чем ниже число, тем выше приоритет).
* **NS (Name Server):** указывает на серверы, ответственные за зону. Используется для делегирования.
* **PTR (Pointer):** используется в обратных зонах (`in-addr.arpa`) для получения имени по IP. Критична для почтовых серверов (проверка легитимности отправителя).
* **TXT (Text):** используется для верификации домена, настройки политик безопасности почты (SPF, DKIM, DMARC).

### Записи для безопасности

| Запись | Назначение |
| :--- | :--- |
| **CAA** | Ограничение выдачи SSL-сертификатов конкретными центрами (CA). |
| **DNSKEY** | Открытый ключ для проверки подписей DNSSEC. Подробности: [Безопасность DNS](./dns_security.md). |
| **DS** | Delegated Signer — хеш ключа DNSKEY для построения цепочки доверия. |
| **TLSA** | Привязка сертификата к домену (DANE), альтернатива CA. |

### Записи для сервисов и протоколов

| Запись | Назначение |
| :--- | :--- |
| **SRV** | Определение хоста и порта для службы (SIP, XMPP, LDAP). |
| **HTTPS / SVCB** | Параметры подключения к веб-сервисам (поддержка HTTP/3, ALPN). Позволяют ускорить установку соединения (RFC 9460). |

> **Заметка по SPF:** отдельный тип записи SPF (Type 99) является устаревшим (RFC 7208). Настройки SPF должны публиковаться через записи типа **TXT**.

## Практические сценарии

### 1. Проверка записей с помощью dig

```bash
# Получение MX-записей
dig example.com MX

# Проверка SPF-политики (через TXT)
dig example.com TXT

# Проверка HTTPS-записи (поддержка HTTP/3)
dig example.com HTTPS
```

### 2. Настройка CAA для защиты домена

Разрешить выпуск сертификатов только для Let's Encrypt:
```dns
example.com. IN CAA 0 issue "letsencrypt.org"
```

### 3. Настройка HTTPS-записи для HTTP/3

Информирование клиента о поддержке HTTP/3 до начала TLS-рукопожатия:
```dns
example.com. IN HTTPS 1 . alpn="h3,h2"
```
Это предотвращает «холодный старт» (первое соединение по HTTP/2) и позволяет сразу использовать QUIC.

## Дополнительная информация

* **Синтаксис:** `NAME TTL CLASS TYPE RDATA`.
* **Класс (Class):** почти всегда `IN` (Internet). Другие значения (`CH`, `HS`) являются историческими или специфичными.
* **RFC 1035:** базовая спецификация типов записей.
* **RFC 9460:** спецификация записей HTTPS и SVCB (2023).

* [Безопасность DNS](./dns_security.md) — подробнее о DNSSEC, DoH и DoT.
