# Зоны DNS и запись SOA

## Зоны DNS

**Зона DNS** — это управляемая часть пространства доменных имен, за которую несет ответственность конкретный DNS-сервер (или группа серверов). Зона может совпадать с доменом второго уровня (например, `example.com`) или быть его подмножеством (например, `sub.example.com`), делегированным через NS-записи на другие серверы.

Существует два основных типа зон:

*   **Прямая зона (Forward Zone):** Сопоставляет доменные имена с IP-адресами (A, AAAA записи).
*   **Обратная зона (Reverse Zone):** Сопоставляет IP-адреса с доменными именами (PTR записи).

## SOA-запись (Start of Authority)

**SOA-запись (Start of Authority)** — обязательная ресурсная запись, которая должна присутствовать в начале каждой зоны. Она определяет основные параметры зоны и правила синхронизации между серверами. Без SOA-записи зона считается некорректной.

### Структура SOA-записи (синтаксис BIND)

```dns
$TTL 86400
@   IN  SOA    <master-dns> <admin-email> (
    2020080302  ; Serial
    7200        ; Refresh
    3600        ; Retry
    1209600     ; Expire
    3600        ; Negative response caching TTL
)
```

### Поля SOA-записи

*   **master-dns**: Имя основного (Primary/Master) DNS-сервера зоны. Это авторитетный сервер, который управляет изменениями и уведомляет вторичные серверы об обновлениях. В некоторых случаях (например, при внутренней автоматизации) здесь может быть указан внутренний домен.
*   **admin-email**: Почтовый адрес администратора зоны. Символ `@` заменяется точкой (например, `admin.example.com` вместо `admin@example.com`).
*   **Serial (Серийный номер)**: Числовой идентификатор версии зоны. При любом изменении записей в зоне серийный номер должен увеличиваться, сигнализируя вторичным серверам о необходимости синхронизации. Часто используется формат `YYYYMMDDNN` (дата + номер изменения за день).
*   **Refresh**: Интервал времени (в секундах), через который вторичный сервер должен запрашивать у основного проверку серийного номера для определения необходимости обновления.
*   **Retry**: Время ожидания перед повторной попыткой запроса SOA-записи у мастера, если тот не ответил.
*   **Expire**: Максимальное время (в секундах), в течение которого вторичный сервер продолжает отвечать на запросы по зоне, если связь с основным сервером потеряна. По истечении этого срока сервер перестает обслуживать зону.
*   **Negative response caching TTL**: Время кэширования ответов с ошибками (например, `NXDOMAIN`). Определяет, как долго резолверы должны помнить, что запрашиваемого имени не существует.

### Роли серверов: Master и Secondary

*   **Master (Primary)**: Основной авторитетный сервер, на котором вносятся изменения в зону.
*   **Secondary (Slave)**: Вторичный сервер, который работает в режиме "только для чтения". Он регулярно синхронизируется с Master-сервером, клонируя актуальную информацию о зоне. Наличие нескольких Secondary-серверов повышает отказоустойчивость DNS.
