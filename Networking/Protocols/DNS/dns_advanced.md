# Продвинутые сценарии использования DNS

## Определения

**Anycast** — метод сетевой адресации, при котором один IP-адрес используется множеством серверов в разных точках мира. Запрос автоматически направляется к ближайшему серверу.

**Geo-DNS (географический DNS)** — технология, возвращающая разные IP-адреса в зависимости от географического местоположения клиента.

**CDN (Content Delivery Network)** — распределённая сеть серверов для доставки контента с минимальной задержкой.

## Базовые концепции

### Anycast

- **Принцип работы:** Один IP (например, `8.8.8.8`) анонсируется из множества точек присутствия (PoP)
- **Маршрутизация:** BGP направляет трафик к ближайшему узлу по метрике AS_PATH
- **Преимущества:**
  - Снижение задержки (меньше хопов)
  - Отказоустойчивость (при падении узла трафик идёт на следующий)
  - Масштабируемость (легко добавлять узлы)
- **Примеры:** Публичные DNS-резолверы (Google `8.8.8.8`, Cloudflare `1.1.1.1`)

### Geo-DNS

- **Принцип работы:** DNS-сервер определяет местоположение клиента по IP резолвера
- **Настройка:** Владелец сервиса настраивает правила у DNS-провайдера
- **Пример:**
  - Северная Америка → `192.0.2.1`
  - Европа → `198.51.100.1`
  - Азия → `203.0.113.1`
- **Использование:** Глобальные сервисы (AWS Route53, Cloudflare DNS)

### CNAME и CDN

Связка CNAME-записи (подробности: [Типы DNS-записей](./dns_records.md)) с CDN позволяет автоматически направлять пользователей к ближайшему узлу доставки контента.

**Сценарий CNAME + CDN:**

1. Владелец создаёт CNAME: `cdn.example.com → example.cdnprovider.net`
2. Пользователь запрашивает `cdn.example.com`
3. DNS возвращает IP ближайшего CDN-сервера
4. Контент загружается с географически близкого узла

**Преимущества:**

- Не нужно управлять IP-адресами CDN
- Автоматическое перенаправление при изменениях
- Простая миграция между CDN-провайдерами

## Практические сценарии

### Миграция сервиса с управлением TTL

**Цель:** Бесшовная миграция сервиса на новый IP с минимальным временем простоя.

**Пошаговый план:**

| Шаг | Действие | Время |
|-----|----------|-------|
| 1 | Понизить TTL до 60–300 сек | За 24–48 часов до миграции |
| 2 | Обновить A-запись на новый IP | В окно миграции |
| 3 | Мониторить трафик на старый/новый IP | 1–2 часа после |
| 4 | Вернуть TTL к нормальному значению | Через 24 часа после |

**Обоснование:** Низкий TTL заставляет резолверы чаще обновлять кэш, сокращая время распространения изменений.

### Диагностика и мониторинг

Проверка TTL записей:

```bash
dig +noall +answer +ttlid example.com
```

Подробнее о формате DNS-сообщений и флагах: [Формат DNS-сообщения](./dns_message_format.md).

## Дополнительная информация

- Anycast требует поддержки BGP и собственного AS — [BGP](../../Protocols/bgp.md)
- Точность Geo-DNS зависит от базы геолокации IP (макс. ~95%)
- Основные CDN-провайдеры: Cloudflare, Akamai, Fastly, AWS CloudFront
