# Продвинутые сценарии использования DNS

DNS позволяет реализовывать сложные сценарии для распределения нагрузки, повышения производительности и отказоустойчивости.

## Anycast

**Anycast** — это метод сетевой адресации, при котором один и тот же IP-адрес используется множеством серверов, расположенных в разных точках мира. Когда вы отправляете запрос на такой IP (например, публичный DNS-резолвер `8.8.8.8`), сеть автоматически направляет его к географически ближайшему к вам серверу. Это значительно сокращает сетевые задержки (ping).

## Geo-DNS

**Geo-DNS (географический DNS)** — технология, позволяющая DNS-серверу возвращать разные IP-адреса в зависимости от географического местоположения клиента.

Владелец сервиса настраивает DNS-провайдера так, чтобы для одного и того же доменного имени в каждом регионе возвращался свой IP-адрес. Например, для `example.com`:
*   Пользователи из Северной Америки получают IP `192.0.2.1`.
*   Пользователи из Европы — `198.51.100.1`.
*   Пользователи из Азии — `203.0.113.1`.

Это уменьшает время отклика, направляя трафик на ближайший к пользователю сервер.

## CNAME и CDN

**CNAME (Canonical Name Record)** служит для определения псевдонимов для доменных имен. Например, запись `www.example.com CNAME example.com` перенаправляет все запросы к `www.example.com` на `example.com`. Клиент сначала запрашивает IP-адрес для `www.example.com`, получает ответ, что нужно искать `example.com`, затем отправляет новый запрос для `example.com` и получает его IP-адрес. Это позволяет нескольким сайтам с разными доменными именами быть доступными по одному и тому же IP-адресу. При переезде серверов на другой IP-адрес достаточно изменить одну запись в DNS, не редактируя каждую запись для каждого сайта.

**CDN (Content Delivery Network)** активно использует CNAME-записи для направления пользователей к ближайшему к ним серверу сети доставки контента. Это позволяет пользователю получать контент с сервера, расположенного географически ближе, что уменьшает время отклика. CDN-провайдеры кэшируют контент и обслуживают CDN-серверы, избавляя компанию от необходимости поддерживать свои серверы в каждом регионе. Настройка CDN позволяет определить, какой контент должен кэшироваться и на какое время.

## Миграция сервиса с помощью TTL

**TTL (Time To Live)** — ключевой параметр для управления миграцией сервисов.

Перед плановой миграцией сервиса на новый IP-адрес TTL для соответствующей A-записи намеренно понижают до минимального значения (например, 60-300 секунд). Это делается за несколько часов или дней до миграции.

Такой подход гарантирует, что после обновления IP-адреса в A-записи кэширующие DNS-резолверы по всему миру быстро обновят свои кэши, и пользователи начнут обращаться на новый IP-адрес с минимальной задержкой.
