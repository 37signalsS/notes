# Ethernet

## Определения

**Ethernet** — технология для создания проводных локальных компьютерных сетей (LAN). Вместе с Wi-Fi составляет основу большинства современных сетей. В [модели OSI](../OSI_TCP_IP_Model/osi_model.md) Ethernet охватывает **Физический (L1)** и **Канальный (L2)** уровни.

**Кадр Ethernet (Frame)** — единица передачи на канальном уровне, содержащая MAC-адреса отправителя/получателя, данные и контрольную сумму.

**Пакет Ethernet** — полная единица передачи на физическом уровне, включающая преамбулу, SFD, кадр, данные и FCS.

## Основные концепции

### История и развитие

- **Создание (1973):** Роберт Меткалф в Xerox PARC, на основе сети Aloha Гавайского университета.
- **Стандартизация (1980-е):** Консорциум DIX (DEC, Intel, Xerox) → IEEE 802.3 (1983).
- **Доминирование (1990-е):** Вытеснил Token Ring, FDDI, стал основным стандартом для LAN.

### Стандарты IEEE 802.3

Семейство стандартов **IEEE 802.3** описывает проводную технологию Ethernet. Содержит более 50 спецификаций, многие устарели.

**Ключевые стандарты:**

| Стандарт | Технология | Среда | Макс. дальность |
| :--- | :--- | :--- | :--- |
| **802.3i** | 10BASE-T | Витая пара (Cat3) | 100 м |
| **802.3u** | Fast Ethernet (100BASE-TX) | Витая пара (Cat5) | 100 м |
| **802.3ab** | Gigabit Ethernet (1000BASE-T) | Витая пара (Cat5e) | 100 м |
| **802.3ae** | 10 Gigabit Ethernet | Оптоволокно | до 40 км |
| **802.3bz** | 2.5G/5GBASE-T | Витая пара (Cat5e) | 100 м |

### Два подуровня: LLC и MAC

Канальный уровень разделён на два подуровня:

1. **LLC (Logical Link Control)** — верхний подуровень, общий для разных технологий. Отвечает за взаимодействие с сетевым уровнем (L3), мультиплексирование протоколов.
2. **MAC (Media Access Control)** — нижний подуровень, специфичный для каждой технологии. Отвечает за **[MAC-адресацию](../Concepts/mac_address.md)** и **управление доступом** к физической среде.

### Управление доступом к среде: CSMA/CD

В классическом Ethernet с разделяемой средой используется метод **CSMA/CD (Carrier Sense Multiple Access with Collision Detection)**.

#### Принцип работы

1. **Carrier Sense (Контроль несущей):** Перед передачей устройство проверяет среду. Если линия занята — ожидает.
2. **Multiple Access (Множественный доступ):** Если линия свободна — начинает передачу.
3. **Collision Detection (Обнаружение коллизий):** Во время передачи устройство слушает среду. Если сигнал искажён (коллизия):
   - Генерируется **JAM-сигнал** для оповещения всех участников
   - Кадр отбрасывается
   - Устройство ожидает случайный интервал и повторяет попытку

**Важно:** Коллизии возможны только при **полудуплексном (half-duplex)** соединении. При **полнодуплексном (full-duplex)** — используются раздельные каналы для приёма/передачи, коллизии невозможны.

#### Алгоритм экспоненциальной отсрочки

После `n`-й коллизии выбирается случайное `k ∈ [0, 2^n - 1]`. Время ожидания: `k × 512` битовых интервалов. После 16 неудачных попыток — ошибка.

### Формирование кадров (Framing)

Для выделения кадров из потока бит используются:

- **Указатель длины:** Поле длины в заголовке. Неустойчив к ошибкам (искажение → рассинхронизация).
- **Вставка байтов (Byte Stuffing):** Маркеры `STX`/`ETX`, экранирование через `ESC`.
- **Вставка битов (Bit Stuffing):** Маркер `01111110`, после 5 единиц вставляется `0`.
- **Средства физического уровня:** Избыточное кодирование (например, 4B/5B в Fast Ethernet) создаёт специальные кодовые комбинации для границ кадра.

### Контроль ошибок

- **Обнаружение (Ethernet):** Контрольная сумма (FCS). Кадр с ошибкой отбрасывается, восстановление — на уровне протоколов выше (TCP).
- **Исправление (Wi-Fi и др.):** FEC (Forward Error Correction) или ARQ (Automatic Repeat ReQuest) — в средах с высоким уровнем помех.

### Формат кадра Ethernet

Наиболее распространённый формат — **Ethernet II (DIX Ethernet)**.

#### Структура кадра (канальный уровень)

| Поле | Размер | Описание |
| :--- | :--- | :--- |
| **Destination MAC** | 6 байт | MAC-адрес получателя |
| **Source MAC** | 6 байт | MAC-адрес отправителя |
| **EtherType** | 2 байта | Тип протокола L3: `0x0800` (IPv4), `0x0806` (ARP), `0x86DD` (IPv6) |
| **Payload** | 46–1500 байт | Полезная нагрузка (MTU) |
| **FCS** | 4 байта | Контрольная сумма (CRC32) |

**Минимальный размер payload (46 байт):** необходим для корректной работы CSMA/CD. При меньшем объёме данных добавляется padding.

**Jumbo Frames:** кадры до 9000 байт для высокоскоростных сетей (требуют поддержки всего оборудования).

#### Полная структура (физический уровень)

| Поле | Размер | Описание |
| :--- | :--- | :--- |
| **Preamble** | 7 байт | `10101010...` — синхронизация тактовой частоты |
| **SFD** | 1 байт | `10101011` — маркер начала кадра |
| **Header + Payload + FCS** | 64–1518 байт | Кадр канального уровня (см. выше) |

**Итого:** 72–1526 байт на физическом уровне.

#### Обработка кадра сетевой картой

- **Совпадение MAC:** кадр принимается и передаётся выше (собственный MAC, broadcast `FF:FF:FF:FF:FF:FF`, multicast-подписка).
- **Несовпадение:** кадр отбрасывается на физическом уровне.

## Практические сценарии

### Классический vs. Коммутируемый Ethernet

| Характеристика | Классический Ethernet | Коммутируемый Ethernet |
| :--- | :--- | :--- |
| **Среда** | Разделяемая (shared media) | Точка-точка (switch) |
| **Топология** | Общая шина (логически), физически — звезда через hub | Звезда через switch |
| **Коллизии** | Возможны, требуется CSMA/CD | Отсутствуют (full-duplex) |
| **Безопасность** | Низкая (promiscuous mode) | Высокая (изоляция портов) |
| **Применение** | 10 Mbps — 1 Gbps (исторически) | 100 Mbps — 400 Gbps (современные сети) |

### Недостатки классического Ethernet

1. **Низкая производительность при нагрузке:** время тратится на разрешение коллизий.
2. **Низкая безопасность:** любой узел может перехватить весь трафик.
3. **Непредсказуемая доставка:** невозможно гарантировать latency для real-time трафика.

### Эволюция скоростей

| Поколение | Скорость | Стандарт | Среда |
| :--- | :--- | :--- | :--- |
| **Ethernet** | 10 Mbps | 802.3i | Коаксиал, витая пара, оптика |
| **Fast Ethernet** | 100 Mbps | 802.3u | Витая пара, оптика |
| **Gigabit Ethernet** | 1 Gbps | 802.3ab | Витая пара (Cat5e+) |
| **NBASE-T** | 2.5/5 Gbps | 802.3bz | Витая пара (Cat5e+) |
| **10 GbE** | 10 Gbps | 802.3ae | Оптоволокно |
| **25/40/50/100/200/400 GbE** | 25–400 Gbps | Различные | Оптоволокно |

## Дополнительная информация

### Связь с другими протоколами

- **VLAN (802.1Q):** [тегирование кадров](./vlan.md) добавляет 4-байтовый тег между Src MAC и EtherType.
- **STP (802.1D):** [протокол связующего дерева](./stp.md) предотвращает петли в Ethernet-сетях.
- **Link Aggregation (802.3ad):** [агрегация каналов](../Concepts/link_aggregation.md) (LACP) объединяет физические интерфейсы в логический.
- **ARP:** [протокол разрешения адресов](./arp.md) инкапсулируется напрямую в Ethernet-кадры (EtherType `0x0806`).
