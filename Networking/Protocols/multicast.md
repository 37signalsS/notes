# Multicast и IGMP Snooping

## Определения

**Multicast (групповая рассылка)** — технология передачи данных от одного источника группе получателей. В отличие от **Unicast** (один к одному) и **Broadcast** (один ко всем), трафик доставляется только тем узлам, которые выразили заинтересованность в получении данных конкретной группы.

**IGMP (Internet Group Management Protocol)** — протокол сетевого уровня (L3), используемый хостами и соседними роутерами для управления членством в группах рассылки IPv4.

**IGMP Snooping** — механизм канального уровня (L2), позволяющий коммутатору «подслушивать» IGMP-сообщения между хостами и маршрутизатором для оптимизации передачи мультикаст-трафика.

## Основные концепции

### Проблема Multicast-флуда

Без механизма IGMP Snooping коммутатор не знает, на каких портах находятся заинтересованные получатели мультикаста. 

**Причина:**
- В обычном трафике коммутатор изучает MAC-адреса отправителей и строит таблицу коммутации (CAM-таблицу).
- **Multicast MAC** никогда не выступает в роли адреса отправителя (Source MAC), поэтому он не изучается через ARP или обычную коммутацию.
- По умолчанию коммутатор обрабатывает мультикаст-кадры так же, как широковещательные (broadcast): **флудит (тиражирует) их на все порты** в пределах VLAN.

В сетях с высокой нагрузкой (видеостриминг, IPTV) это приводит к деградации полосы пропускания на портах, где этот трафик не нужен.

### Механизм работы IGMP Snooping

Коммутатор пассивно анализирует (snooping) IGMP-пакеты:
1. **IGMP Join:** когда хост сообщает о желании вступить в группу, коммутатор добавляет этот порт в таблицу рассылки для данной группы.
2. **IGMP Leave:** когда хост покидает группу, порт удаляется из таблицы.
3. **Результат:** мультикаст-трафик направляется только на порты с активными подписчиками и на порты, ведущие к мультикаст-маршрутизаторам (mrouter ports).

## Практические сценарии (Cisco)

### Проверка состояния

```cisco
# Посмотреть таблицу групп и портов
show ip igmp snooping groups

# Общая информация о настройках snooping
show ip igmp snooping
```

### Решение проблем (Где ломается)

#### 1. Отсутствие IGMP Querier
IGMP Snooping требует периодических запросов (**IGMP Queries**), чтобы хосты подтверждали своё участие в группах. Обычно запросы рассылает маршрутизатор.
- **Проблема:** если в сегменте нет мультикаст-маршрутизатора или он не настроен на рассылку запросов, записи в таблице snooping устаревают и удаляются. Трафик снова начинает флудиться на все порты.
- **Решение:** включить функцию querier на коммутаторе:

```cisco
ip igmp snooping querier
ip igmp snooping querier address 192.168.1.1
```

#### 2. Неизвестный Multicast (Unknown Multicast)
Если коммутатор получает трафик группы, которой нет в таблице snooping, по умолчанию он флудит его во все порты VLAN.
- **Решение:** на критичных узлах можно запретить флуд неизвестного мультикаста:

```cisco
no ip igmp snooping flood-unknown-multicast
```

#### 3. Статическое членство
Некоторые приложения или старые устройства не умеют посылать IGMP Join сообщения. В этом случае коммутатор не узнает о получателе.
- **Решение:** добавить порт в группу вручную:

```cisco
ip igmp snooping vlan 10 static 239.1.1.1 interface Gi0/5
```

## Дополнительная информация

### RPF в Multicast
В мультикаст-маршрутизации (PIM) проверка RPF используется для предотвращения петель. Маршрутизатор принимает мультикаст-пакет только в том случае, если он пришел через интерфейс, который является кратчайшим путем к **источнику** (Source) рассылки. Подробнее см. **[RPF и uRPF](./rpf_urpf.md)**.
