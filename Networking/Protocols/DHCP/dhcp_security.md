# Безопасность DHCP: Атаки и защита

## Уязвимости протокола DHCP

Протокол DHCP уязвим для двух основных типов атак:
1. **DHCP Starvation** (истощение пула адресов)
2. **Rogue DHCP** (поддельный DHCP-сервер)

---

## DHCP Starvation (Истощение DHCP-сервера)

**DHCP Starvation** — это атака типа DoS, направленная на исчерпание пула доступных IP-адресов DHCP-сервера.

### Механизм атаки

1. DHCP-сервер резервирует IP-адрес при получении `DHCPDISCOVER` запроса
2. Для идентификации клиента сервер запоминает MAC-адрес
3. Злоумышленник отправляет множество `DHCPDISCOVER` запросов с поддельными MAC-адресами
4. Сервер резервирует адреса для каждого запроса, пока пул не будет исчерпан

### Последствия

- Легитимные клиенты не могут получить IP-адрес
- Отказ в обслуживании (DoS) для новых устройств в сети
- Нарушение доступности сетевых ресурсов

### Методы защиты

| Метод | Описание |
|-------|----------|
| **Port Security** | Ограничение количества MAC-адресов на одном порту коммутатора |
| **DHCP Snooping** | Блокировка некорректных DHCP-запросов на недоверенных портах |
| **Rate Limiting** | Ограничение количества DHCP-запросов с одного порта |
| **Monitoring** | Мониторинг скорости выдачи адресов и заполненности пула |

## Rogue DHCP Server (Поддельный DHCP-сервер)

**Rogue DHCP** (он же **DHCP Spoofing**) — атака, при которой злоумышленник разворачивает поддельный DHCP-сервер, выдающий клиентам неверные сетевые настройки.

### Механизм атаки

1. Клиент отправляет широковещательный `DHCPDISCOVER`
2. Все DHCP-серверы в сети отвечают `DHCPOFFER`
3. Клиент принимает **первый полученный** `DHCPOFFER`
4. Злоумышленник настраивает свой сервер для максимально быстрой отправки ответов

### Варианты атаки

| Тип | Описание |
|-----|----------|
| **DoS** | Выдача нерабочих сетевых параметров (неверный шлюз, DNS) |
| **Man-in-the-Middle** | Выдача параметров, где шлюз по умолчанию — сервер атакующего |
| **Перехват трафика** | Перенаправление DNS-запросов на подконтрольный DNS-сервер |

### Признаки атаки

1. **Получение неожиданного IP-адреса:** Клиенты получают IP-адреса из другой подсети, не соответствующей ожидаемой конфигурации.
2. **Проблемы с доступом к сети:** Клиенты не могут выйти в интернет, получить доступ к локальным ресурсам или работают с перебоями.
3. **Неверные сетевые параметры:** Клиенты получают неверные адреса шлюза, DNS-серверов или других опций.
4. **Двойные DHCP-предложения:** При анализе сетевого трафика видно несколько `DHCPOFFER` сообщений от разных серверов на один `DHCPDISCOVER` от клиента.

### Как найти и отключить несанкционированный DHCP-сервер

**1. Использование сетевых анализаторов:**

- **Wireshark/tcpdump:** Захват трафика на порту клиента или коммутатора. Идентификация IP-адресов и MAC-адресов всех DHCP-серверов, отвечающих на `DHCPDISCOVER`.
- **Специализированные утилиты:** `dhcp-discover` (Linux), `Rogue Detector` — активное сканирование сети на предмет несанкционированных DHCP-ответов.

**2. Проверка коммутационного оборудования:**

- **Журналы коммутаторов:** Некоторые управляемые коммутаторы могут логировать активность DHCP-серверов.
- **Таблица MAC-адресов:** После обнаружения IP и MAC-адреса несанкционированного сервера, можно найти, к какому порту коммутатора он подключен.

**3. Физическое отключение/Блокировка:**

- После идентификации порта на коммутаторе можно физически отключить устройство или административно заблокировать порт.
- Если устройство легитимно, но некорректно настроено (например, роутер пользователя в режиме маршрутизатора), его следует правильно перенастроить.

## Методы защиты от несанкционированных DHCP-серверов

### 1. DHCP Snooping

Функция безопасности на управляемых коммутаторах канального уровня (L2).

**Принцип работы:**

Коммутатор отслеживает DHCP-трафик и строит базу данных доверенных DHCP-серверов и их ответов. Порты классифицируются как:

| Тип порта | Описание |
|-----------|----------|
| **Доверенные (Trusted)** | Порты с легитимными DHCP-серверами или аплинками. Разрешены все типы DHCP-сообщений. |
| **Недоверенные (Untrusted)** | Порты конечных пользователей. Блокируются входящие `DHCPOFFER`, `DHCPACK`, `DHCPNAK`. |

**Эффект:** Любой `DHCPOFFER` или `DHCPACK` от несанкционированного DHCP-сервера, подключенного к недоверенному порту, будет заблокирован коммутатором.

### 2. Port Security (Безопасность портов)

Настройка на коммутаторах для ограничения количества MAC-адресов на одном порту.

**Пример (Cisco):**
```cisco
interface GigabitEthernet0/1
 switchport port-security
 switchport port-security maximum 2
 switchport port-security violation shutdown
```

### 3. Dynamic ARP Inspection (DAI)

Связанная с DHCP Snooping функция, которая проверяет достоверность ARP-сообщений на основе базы данных DHCP Snooping. Предотвращает ARP-спуфинг.

### 4. Физическая безопасность

Ограничение физического доступа к сетевому оборудованию и розеткам для предотвращения подключения несанкционированных устройств.

### 5. 802.1X (Network Access Control)

Комплексное решение, требующее аутентификации устройств перед предоставлением сетевого доступа.

## Рекомендации по безопасности

1. **Включить DHCP Snooping** на всех коммутаторах доступа
2. **Настроить доверенные порты** только там, где подключены легитимные DHCP-серверы
3. **Ограничить количество MAC-адресов** на пользовательских портах (Port Security)
4. **Мониторить логи DHCP-сервера** на предмет аномальной активности
5. **Использовать авторитативный сервер** в каждой подсети
6. **Блокировать DHCP-трафик** на файрволе между недоверенными сегментами

> **Важно:** Будьте особенно внимательны при использовании DHCP в публичных местах (кафе, аэропорты, отели). В таких сетях риск атак Rogue DHCP и Man-in-the-Middle значительно выше.
