# Безопасность DHCP — атаки и защита

> **Надёжность: 10/10** (SSoT + RFC Verification)
> **Актуальность: 2026-07** (Статус: Актуально, проверено)

## Определения

Протокол **DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла)** по умолчанию не имеет встроенных механизмов аутентификации, что делает его уязвимым для атак на канальном уровне (L2).

**Основные угрозы:**
- **DHCP Starvation (Истощение пула):** DoS-атака, направленная на исчерпание всех доступных IP-адресов сервера.
- **Rogue DHCP Server (Поддельный сервер):** Установка несанкционированного сервера для перехвата трафика (Man-in-the-Middle) или блокировки доступа.
- **IP/MAC Spoofing:** Использование чужих сетевых идентификаторов для обхода систем контроля доступа.

## Модель угроз: IPv4 и IPv6

### Атаки в сетях IPv4
1. **Starvation:** Атакующий генерирует тысячи запросов `DHCPDISCOVER` с поддельными MAC-адресами. Сервер резервирует под них весь пул, и легитимные клиенты не могут получить адрес.
2. **Rogue Server:** Поддельный сервер отвечает на запросы быстрее легитимного, назначая себя шлюзом по умолчанию (Default Gateway) или подменяя адреса DNS.

### Атаки в сетях IPv6
В IPv6 задача усложняется из-за наличия двух механизмов назначения адресов (SLAAC и DHCPv6).
1. **RA Spoofing:** Атакующий рассылает поддельные **Router Advertisements (RA)**, объявляя себя маршрутизатором. Это позволяет перехватить трафик даже без участия DHCPv6.
2. **DHCPv6 Starvation:** Хотя пул адресов IPv6 ($2^{64}$) исчерпать невозможно, атака направлена на **ресурсы сервера** (память, CPU, таблицы состояний), забивая их фиктивными записями о DUID (DHCP Unique Identifier).

## Механизмы защиты (First-Hop Security)

Для защиты сети используются функции коммутаторов доступа (L2), известные как **First-Hop Security (FHS)**.

### DHCP Snooping — фундамент безопасности
Коммутатор анализирует DHCP-трафик и разделяет порты на:
- **Trusted (Доверенные):** Порты, ведущие к легитимному серверу. Разрешены любые сообщения.
- **Untrusted (Недоверенные):** Клиентские порты. Сообщения от серверов (`DHCPOFFER`, `DHCPACK`, `ADVERTISE`) на них **блокируются**.

**Результат:** Коммутатор строит **Snooping Binding Database** — таблицу соответствия `[MAC + IP + Lease Time + VLAN + Port]`. Эта таблица является «источником истины» для других механизмов.

### IP Source Guard (IPSG)
Использует базу данных Snooping для предотвращения **IP Spoofing**.
- На порт устанавливается динамический ACL.
- Пропускаются только те пакеты, чей источник IP и MAC совпадает с записью в базе Snooping.
- Пакеты со статическими IP, не прописанными в базе, отбрасываются.

### Dynamic ARP Inspection (DAI)
Защита от **ARP-спуфинга**. Коммутатор проверяет ARP-ответы на соответствие базе Snooping. Если связка IP-MAC в ARP-пакете не совпадает с базой, пакет отбрасывается.

### IPv6 Specific: RA Guard и DHCPv6 Guard
- **RA Guard (RFC 6105):** Блокирует сообщения Router Advertisement на портах, к которым не подключены легитимные маршрутизаторы.
- **DHCPv6 Guard:** Аналог DHCP Snooping для IPv6. Блокирует ответы серверов на клиентских портах.

## Продвинутые концепции

### SAVI (Source Address Validation Improvement)
**SAVI (RFC 7039)** — это комплексный фреймворк, объединяющий проверку адресов для всех методов их получения (SLAAC, DHCPv6, статика). SAVI обеспечивает строгую привязку IP-адреса к «якорю» (порту коммутатора), предотвращая любые попытки подмены адреса в dual-stack сетях.

## Практическая настройка и диагностика

### Пример конфигурации (Cisco)
```cisco
# Включение DHCP Snooping
ip dhcp snooping
ip dhcp snooping vlan 10,20

# Настройка доверенного порта (аплинк к серверу)
interface GigabitEthernet0/1
 ip dhcp snooping trust

# Включение IP Source Guard на клиентском порту
interface GigabitEthernet0/2
 ip verify source
```

### Обнаружение Rogue DHCP в Linux
Для поиска несанкционированных серверов можно использовать утилиту `nmap` или специализированные скрипты:
```bash
# Поиск DHCP-серверов в сегменте через nmap
sudo nmap --script broadcast-dhcp-discover

# Использование tcpdump для мониторинга ответов
sudo tcpdump -i eth0 -n port 67 or port 68
```

## Рекомендации SRE/DevOps
1. **Hardening L2:** Всегда включайте DHCP Snooping и Port Security на портах доступа.
2. **Мониторинг:** Настройте алертинг на событие `DHCP Snooping Violation` (попытка ответа с недоверенного порта).
3. **Лимиты:** Используйте `ip dhcp snooping limit rate` для защиты самого коммутатора от флуда запросами.
4. **IPv6:** В сетях с IPv6 обязательно внедрение RA Guard для предотвращения перехвата трафика через механизмы автоконфигурации.
