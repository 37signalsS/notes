# Безопасность DHCP — атаки и защита

## Определения

Протокол **DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла)** уязвим для двух основных типов атак:

- **DHCP Starvation (истощение пула)** — атака типа **DoS (Denial of Service — отказ в обслуживании)**, направленная на исчерпание пула IP-адресов (Internet Protocol) сервера с помощью запросов с поддельными **MAC-адресами (Media Access Control)**.
- **Rogue DHCP (поддельный DHCP-сервер)** — развёртывание несанкционированного сервера для выдачи клиентам неверных сетевых параметров, таких как шлюз по умолчанию или адреса **DNS (Domain Name System — система доменных имен)**. Также называется DHCP Spoofing.

## Основные концепции

### DHCP Starvation — истощение пула

**Механизм:**

1. Сервер резервирует IP-адрес при получении сообщения `DHCPDISCOVER`, фиксируя MAC-адрес клиента.
2. Злоумышленник отправляет множество запросов `DHCPDISCOVER` с поддельными уникальными MAC-адресами.
3. Доступный пул адресов полностью исчерпывается, и легитимные клиенты не могут получить настройки.

**Последствия:** отказ в обслуживании для новых устройств в сегменте сети.

### Rogue DHCP Server — поддельный сервер

**Механизм:**

1. Клиент отправляет широковещательный запрос `DHCPDISCOVER`.
2. Все доступные в сегменте серверы отвечают сообщением `DHCPOFFER`.
3. Клиент обычно принимает первое полученное предложение.
4. Злоумышленник настраивает свой сервер на максимально быструю отправку ответов, чтобы опередить легитимный сервер.

**Варианты атаки:**

| Тип | Описание |
| :--- | :--- |
| **DoS** | Выдача нерабочих параметров (неверный шлюз или DNS), что блокирует доступ в сеть. |
| **Man-in-the-Middle (Человек посередине)** | Шлюзом по умолчанию назначается сервер атакующего, что позволяет перехватывать и анализировать трафик. |
| **Перехват DNS** | DNS-запросы направляются на подконтрольный сервер для перенаправления пользователя на фишинговые ресурсы. |

**Признаки атаки:**

- Клиенты получают IP-адреса из сторонней подсети.
- Невозможность выхода в интернет или доступа к локальным ресурсам.
- Наличие нескольких сообщений `DHCPOFFER` от разных серверов на один запрос клиента (можно обнаружить с помощью анализатора трафика Wireshark).

### Механизмы защиты на канальном уровне (L2 — Data Link Layer)

#### DHCP Snooping — отслеживание DHCP

Коммутатор анализирует проходящий DHCP-трафик и разделяет порты на две категории:

| Тип порта | Описание |
| :--- | :--- |
| **Trusted (Доверенный)** | Порты, к которым подключены легитимные DHCP-серверы или вышестоящие коммутаторы. Разрешены все типы сообщений. |
| **Untrusted (Недоверенный)** | Пользовательские порты. Сообщения от серверов (`DHCPOFFER`, `DHCPACK`) на этих портах блокируются. |

#### Port Security — безопасность порта

Ограничение количества MAC-адресов, которые могут быть изучены на одном физическом порту коммутатора. Предотвращает атаку DHCP Starvation.

```cisco
interface GigabitEthernet0/1
 switchport port-security
 switchport port-security maximum 2
 switchport port-security violation shutdown
```

#### Dynamic ARP Inspection (DAI)

Механизм проверки соответствия IP и MAC-адресов в сообщениях протокола **ARP (Address Resolution Protocol — протокол разрешения адресов)** на основе базы данных, созданной DHCP Snooping. Предотвращает ARP-спуфинг.

## Практические сценарии

### Обнаружение и нейтрализация Rogue DHCP-сервера

**1. Сетевой анализ:**

- Использование **Wireshark** или **tcpdump** для захвата трафика и идентификации IP/MAC всех серверов, отправляющих ответы.
- Применение специализированных утилит (например, `dhcp-discover` в Linux) для активного поиска несанкционированных серверов.

**2. Локализация источника:**

- Поиск порта в таблице MAC-адресов управляемого коммутатора по адресу выявленного сервера.
- Проверка системных журналов (логов) сетевого оборудования.

**3. Блокировка:**

- Административное отключение порта (shutdown) или физическое отключение устройства.
- Если устройство принадлежит пользователю (например, домашний роутер), проведение разъяснительной работы и перенастройка.

### Общие рекомендации по обеспечению безопасности

1. Обязательное включение **DHCP Snooping** во всех сегментах сети доступа.
2. Настройка **Trusted-портов** строго для портов легитимных серверов.
3. Ограничение количества MAC-адресов на портах пользователей через **Port Security**.
4. Постоянный мониторинг логов DHCP-сервера на предмет аномального количества запросов.
5. Использование протокола **802.1X** для аутентификации устройств перед предоставлением доступа к сетевой инфраструктуре.
