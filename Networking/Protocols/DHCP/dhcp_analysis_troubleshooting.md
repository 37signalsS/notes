# Диагностика и анализ трафика DHCP

## Определения

**Анализ трафика DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла)** — процесс захвата и декодирования пакетов DHCP сетевым анализатором (например, Wireshark) для диагностики проблем конфигурации клиентов.

**Диагностика (troubleshooting) DHCP** — систематический поиск и устранение проблем получения или обновления **IP-адресов (Internet Protocol)** и сетевых параметров.

**APIPA (Automatic Private IP Addressing)** — механизм автоматического назначения частных IP-адресов из диапазона `169.254.0.0/16` при недоступности DHCP-сервера.

## Основные концепции

### Авторитативный и неавторитативный DHCP-сервер

Опция `authoritative` в конфигурации DHCP-сервера определяет его поведение при обработке некорректных запросов от клиентов.

#### Авторитативный (Authoritative) сервер

Считается «главным» для данной подсети. Если такой сервер получает от клиента запрос `DHCPREQUEST` с IP-адресом, который не принадлежит его пулу или некорректен для данной сети, он отправит клиенту сообщение `DHCPNAK (Negative Acknowledgement)`. Это заставит клиента немедленно прекратить использование неверного адреса и заново запустить процесс **DORA (Discover, Offer, Request, Acknowledge)**.

**Пример:** сотрудник приносит рабочий ноутбук из дома в офис. Ноутбук пытается использовать свой домашний IP-адрес. Авторитативный сервер офиса немедленно отправит `DHCPNAK`, и ноутбук получит новый корректный IP.

#### Неавторитативный (Non-authoritative) сервер

Если сервер не является авторитативным, он просто проигнорирует некорректный `DHCPREQUEST`. Клиент будет продолжать использовать неверный адрес до истечения его срока аренды, и все это время связь в сети будет отсутствовать.

**Рекомендация:** в каждой подсети должен быть только один авторитативный DHCP-сервер. Подробное описание процесса DORA — в [обзоре DHCP](./dhcp_overview.md).

## Практические сценарии

### Анализ трафика DHCP в Wireshark

**Цель:** изучить взаимодействие клиента и сервера, выявить сбои в процессе DORA.

#### Шаг 1. Захват трафика

1. Запустите **Wireshark** от имени администратора.
2. Выберите основной сетевой интерфейс (`Ethernet` или `Wi-Fi`).
3. Начните захват пакетов.

#### Шаг 2. Генерация трафика DHCP

| Операционная система | Команды |
| :--- | :--- |
| **Windows** | 1. `ipconfig /release` — освободить текущий IP.<br>2. `ipconfig /renew` — получить новый IP. |
| **macOS** | 1. `sudo ipconfig set en0 none` — освободить IP.<br>2. `sudo ipconfig set en0 dhcp` — получить новый IP. |
| **Linux** | 1. `sudo dhclient -r eth0` — освободить IP.<br>2. `sudo dhclient eth0` — получить новый IP. |

#### Шаг 3. Анализ захваченных пакетов

1. Остановите захват в Wireshark.
2. Примените фильтр отображения: `dhcp` или `bootp`.
3. Изучите последовательность DORA (детали полей — в [обзоре DHCP](./dhcp_overview.md#основные-концепции)):

| Пакет | Поля для анализа |
| :--- | :--- |
| **DHCP Discover** | `op=1`, `chaddr` (**MAC — Media Access Control** клиента), `ciaddr=0.0.0.0`. |
| **DHCP Offer** | `yiaddr` (предлагаемый IP), `siaddr` (**TFTP — Trivial File Transfer Protocol** сервер). |
| **DHCP Request** | Requested IP Address, DHCP Server Identifier. |
| **DHCP Ack** | `yiaddr` (выданный IP), Subnet Mask, Router, **DNS (Domain Name System)**, Lease Time. |

#### Пример анализа пакетов

Ниже представлен типичный вывод полей в Wireshark для успешного процесса DORA:

```text
Frame 1: DHCP Discover
    Client Hardware Address: aa:bb:cc:dd:ee:ff (MAC клиента)
    Client IP Address: 0.0.0.0
    Option: Message Type (Discover)

Frame 2: DHCP Offer
    Your IP Address: 192.168.1.100 (предлагаемый адрес)
    Server IP Address: 192.168.1.1 (адрес сервера)
    Option: Subnet Mask (255.255.255.0)
    Option: Router (192.168.1.1)
    Option: Domain Name Server (8.8.8.8)

Frame 3: DHCP Request
    Requested IP Address: 192.168.1.100
    DHCP Server Identifier: 192.168.1.1
    Option: Message Type (Request)

Frame 4: DHCP Ack
    Your IP Address: 192.168.1.100
    Option: IP Address Lease Time (86400 seconds)
    Option: Renewal Time Value (43200 seconds)
```

**Когда применять диагностику:**

- При массовых жалобах пользователей на отсутствие интернета (проверка пула адресов).
- После изменения сетевой топологии или замены шлюза.
- При подозрении на наличие несанкционированных DHCP-серверов в сети (Rogue DHCP).
- При возникновении конфликтов IP-адресов.

### Типичные проблемы и решения

| Проблема | Симптомы | Решение |
| :--- | :--- | :--- |
| **Клиент не получает IP** | `ipconfig` показывает `169.254.x.x` (APIPA). | Проверить доступность сервера, наличие свободных адресов в пуле. |
| **Конфликт IP-адресов** | Ошибки подключения, сообщение `DHCPDECLINE`. | Включить проверку (ping check) на сервере, проверить статические назначения. |
| **Задержка получения IP** | Ожидание 10–30 секунд при подключении. | Проверить задержку сети, настроить [DHCP Relay](./dhcp_relay.md). |
| **Неверные параметры** | Ошибочный шлюз или DNS. | Проверить конфигурацию области (scope) на сервере. |
