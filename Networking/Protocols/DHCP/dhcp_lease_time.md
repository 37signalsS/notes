# DHCP — Время аренды и типы сообщений

> **Надёжность: 10/10** (SSoT + RFC Verification)
> **Актуальность: 2026-07** (Статус: Актуально, проверено)

## Определения

**Lease Time (Время аренды)** — интервал времени, в течение которого клиент может использовать выделенный ему IP-адрес. DHCP является протоколом, основанным на аренде, что позволяет эффективно переиспользовать ограниченный пул адресов.

### Типы назначения адресов
1. **Dynamic Allocation (Динамическое):** Адрес выдаётся из пула на определённый срок. По истечении срока адрес возвращается в пул, если не был продлён.
2. **Automatic Allocation (Автоматическое):** Сервер назначает клиенту постоянный IP-адрес из пула. В отличие от динамического, срок аренды не ограничен.
3. **Static Allocation (Резервирование):** Привязка конкретного IP к MAC-адресу (IPv4) или DUID (IPv6). Выполняется администратором вручную. Подробности — [Резервирование IP в ISC DHCP](../../../Linux/Networking/Services/DHCP/isc_dhcp_server_reservations.md).

## Основные концепции: Таймеры и Жизненный цикл

### DHCPv4: Таймеры аренды (RFC 2131)
Сервер передаёт клиенту три ключевых значения времени (в секундах):
- **Lease Time (Option 51):** Полный срок аренды.
- **T1 (Renewal Time, Option 58):** Время начала продления (50% от Lease Time). Клиент отправляет **unicast** запрос `DHCPREQUEST` серверу, выдавшему адрес.
- **T2 (Rebinding Time, Option 59):** Время начала повторного связывания (87.5% от Lease Time). Если исходный сервер не ответил, клиент отправляет **broadcast** запрос `DHCPREQUEST` любому доступному серверу.

### DHCPv6: Состояния адреса (RFC 8415)
В IPv6 концепция аренды расширена за счёт состояний адреса:
- **Preferred Lifetime:** Время, в течение которого адрес считается предпочтительным для новых соединений.
- **Valid Lifetime:** Время, в течение которого адрес считается валидным. По истечении этого срока пакеты с данным адресом источника отбрасываются.
- **T1/T2:** Аналогично IPv4, используются для управления процессом обновления параметров IA_NA (Identity Association for Non-temporary Addresses).

| Состояние | Описание |
| :--- | :--- |
| **Preferred** | Адрес активен, используется для новых и старых соединений. |
| **Deprecated** | Срок Preferred истёк. Новые соединения не должны использовать этот адрес, но старые продолжают работать до конца Valid Lifetime. |
| **Invalid** | Срок Valid истёк. Адрес удаляется из системы. |

## Типы сообщений DHCP

### Управляющие сообщения (IPv4)
- **DHCPACK (Acknowledgement):** Положительный ответ сервера. Подтверждает аренду и передаёт параметры.
- **DHCPNAK (Negative Ack):** Отрицательный ответ. Сервер сообщает клиенту, что запрашиваемый адрес недоступен (например, клиент переместился в другую подсеть).
  - *Логика:* Авторитативный (Authoritative) сервер обязан отправить `DHCPNAK`, если видит запрос на неверный адрес для данной сети.
- **DHCPDECLINE:** Сообщение от клиента серверу. Клиент обнаружил конфликт (адрес уже занят в сети через ARP-проверку).
- **DHCPRELEASE:** Клиент добровольно освобождает адрес до истечения срока.
- **DHCPINFORM:** Запрос параметров (DNS, NTP) без запроса IP-адреса. Используется, когда IP настроен статически.

### Эквиваленты в IPv6
- **Renew:** Прямой аналог запроса на продление.
- **Rebind:** Попытка продления через любой сервер.
- **Release:** Освобождение адреса.
- **Decline:** Сообщение о конфликте.
- **Information-Request:** Аналог `DHCPINFORM` для получения только опций (Stateless DHCPv6).

## Практические сценарии и оптимизация

### Выбор времени аренды (SRE Best Practices)

| Сценарий | Lease Time | Обоснование |
| :--- | :--- | :--- |
| **Публичный Wi-Fi** | 30–120 мин | Высокая ротация клиентов. Длительная аренда приведёт к быстрому исчерпанию пула (Pool Exhaustion). |
| **Офисная сеть** | 12–24 часа | Баланс между нагрузкой на сеть и актуальностью данных. |
| **Дата-центр / Серверы** | 7–30 дней | Максимальная стабильность. Адреса меняются крайне редко. |
| **Миграция подсети** | 15–30 мин | Перед плановыми работами Lease Time снижается заранее (за 24-48ч), чтобы клиенты быстрее получили новые настройки. |

### Влияние на производительность
- **Короткая аренда:** Увеличивает количество широковещательного трафика (broadcast) и нагрузку на CPU DHCP-сервера. Может вызвать проблемы в сегментах с тысячами хостов.
- **Длинная аренда:** Риск нехватки адресов при появлении новых устройств. Неактуальность данных в DNS, если используется Dynamic DNS.
