# Время аренды DHCP и типы назначения

## Определения

**Lease Time (время аренды)** — срок, на который DHCP-сервер выдаёт IP-адрес клиенту. По истечении адреса клиент обязан продлить аренду, иначе сервер вернёт адрес в пул.

**Типы назначения DHCP:**

- **Dynamic Allocation** — адрес выдаётся из пула на ограниченное время ( Lease Time)
- **Automatic Allocation** — адрес выдаётся на неограниченный срок, но выбирается из пула автоматически
- **Static Allocation (DHCP Reservation)** — администратор вручную привязывает IP к MAC-адресу устройства

## Основные концепции

### Механизм продления аренды

DHCP-сервер передаёт клиенту два параметра через опции:

- **IP Address Lease Time** — общее время аренды
- **Renewal Time Value (T1)** — время начала продления (обычно 50% от Lease Time)

**Процесс продления:**

1. По истечении T1 (50%) клиент отправляет `DHCPREQUEST` серверу для продления
2. При получении `DHCPACK` аренда продлевается без прерывания подключения
3. Если сервер недоступен, клиент пытается обновить аренду у любого сервера после T2 (87.5% от Lease Time)
4. По истечении полного Lease Time сервер освобождает IP и может выдать его другому хосту

**Пример:** При аренде 186 400 секунд (~52 часа) T1 = 93 200 секунд (~26 часов). После 26 часов клиент начинает попытки продления, текущий IP остаётся за ним.

Зачем это нужно: без ограничения аренды адреса быстро исчерпались бы в сетях с высокой текучестью (гостевые Wi-Fi). Механизм автоматически возвращает неиспользуемые адреса в пул.

### Дополнительные сообщения DHCP

Помимо процесса DORA (описан в [DHCP Overview](./dhcp_overview.md)), существуют другие сообщения:

#### DHCPNAK (Negative Acknowledgement)

Сервер отправляет отказ в ответ на `DHCPREQUEST`.

**Причины:**

- Клиент запрашивает некорректный или уже занятый IP
- Клиент переместился в другую подсеть, но пытается использовать старый адрес
- Клиент запрашивает адрес, отличный от предложенного в `DHCPOFFER`

**Реакция клиента:** Освободить текущий адрес и заново запустить процесс DORA. Подробный пример — в [Troubleshooting: Authoritative сервер](./dhcp_analysis_troubleshooting.md).

#### DHCPDECLINE

Клиент сообщает серверу, что предложенный IP уже используется другим устройством (обнаружен конфликт после gratuitous ARP-проверки).

**Реакция сервера:** Пометить адрес как конфликтный и не выдавать его другим клиентам.

#### DHCPRELEASE

Клиент информирует сервер о досрочном освобождении IP-адреса (например, при корректном выключении). Подтверждение не требуется.

#### DHCPINFORM

Клиент с уже имеющимся IP-адресом (настроенным вручную) запрашивает дополнительные параметры (DNS, NTP и т.д.).

## Практические сценарии

### Рекомендуемое время аренды

| Тип сети | Рекомендуемое Lease Time | Обоснование |
|----------|-------------------------|-------------|
| **Гостевые сети** | 1–8 часов | Быстрое освобождение адресов |
| **Публичные Wi-Fi** | 30 мин – 2 часа | Высокая текучесть клиентов |
| **Корпоративные сети** | Несколько дней – месяцев | Сохранение IP при перезагрузках |
| **Серверы (резервирование)** | Неделя – бессрочно | Стабильность адресации |

### Когда какой тип назначения использовать

| Тип | Когда применять |
|-----|-----------------|
| **Dynamic** | Клиентские устройства (ПК, смартфоны, планшеты) — наиболее распространённый вариант |
| **Automatic** | Сети, где устройства должны сохранять IP, но ручное резервирование не требуется |
| **Static (Reservation)** | Серверы, принтеры, сетевое оборудование — устройства, требующие постоянного адреса (подробнее — [ISC DHCP Reservations](../../../Linux/Networking/Services/DHCP/isc_dhcp_server_reservations.md)) |
