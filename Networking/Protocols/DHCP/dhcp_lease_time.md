# DHCP — время аренды и типы назначения

## Определения

**Lease Time (время аренды)** — срок, на который сервер **DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла)** выдаёт **IP-адрес (Internet Protocol)** клиенту. По истечении этого срока клиент обязан продлить аренду, в противном случае сервер вернёт адрес в пул для повторного использования.

**Типы назначения адресов DHCP:**

- **Dynamic Allocation (динамическое распределение)** — адрес выдаётся из пула на ограниченное время (Lease Time).
- **Automatic Allocation (автоматическое распределение)** — адрес выбирается из пула автоматически и выдаётся на неограниченный срок (до ручного освобождения).
- **Static Allocation / DHCP Reservation (статическое распределение / резервирование)** — администратор вручную привязывает конкретный IP-адрес к **MAC-адресу (Media Access Control)** устройства.

## Основные концепции

### Механизм продления аренды

Сервер DHCP передаёт клиенту параметры времени через специальные опции:

- **IP Address Lease Time** — общее время аренды.
- **Renewal Time Value (T1)** — время начала процесса продления (по умолчанию составляет 50% от Lease Time).
- **Rebinding Time Value (T2)** — время попытки обновления у любого доступного сервера (составляет 87.5% от Lease Time).

**Процесс продления:**

1. По истечении времени T1 клиент отправляет запрос `DHCPREQUEST` серверу, выдавшему адрес, для продления аренды.
2. При получении подтверждения `DHCPACK` аренда продлевается, подключение не прерывается.
3. Если основной сервер недоступен, клиент после наступления времени T2 пытается обновить аренду, отправляя широковещательный запрос любому доступному серверу.
4. Если аренда не была продлена до истечения полного Lease Time, клиент обязан прекратить использование IP-адреса.

**Пример:** при установленном времени аренды 24 часа (86 400 секунд), T1 составит 12 часов. Спустя 12 часов клиент начнёт попытки продления, сохраняя текущий адрес.

Ограничение времени аренды критически важно для сетей с высокой текучестью устройств (например, публичные Wi-Fi зоны), так как позволяет автоматически возвращать неиспользуемые адреса в пул.

### Дополнительные сообщения DHCP

Помимо стандартного процесса **DORA (Discover, Offer, Request, Acknowledge)**, описанного в [DHCP — обзор](./dhcp_overview.md), протокол поддерживает другие типы сообщений:

#### DHCPNAK (Negative Acknowledgement)

Отрицательный ответ сервера на запрос `DHCPREQUEST`.

**Основные причины отправки:**
- Клиент запрашивает некорректный или уже занятый IP-адрес.
- Клиент переместился в другую подсеть, но пытается использовать старый адрес.
- Клиент запрашивает адрес, отличный от того, что был предложен в `DHCPOFFER`.

**Реакция клиента:** немедленно прекратить использование адреса и заново запустить процесс DORA. Подробности — в [диагностике DHCP](./dhcp_analysis_troubleshooting.md).

#### DHCPDECLINE

Клиент сообщает серверу, что предложенный IP-адрес уже используется другим устройством. Конфликт обычно обнаруживается с помощью проверки через протокол **ARP (Address Resolution Protocol — протокол разрешения адресов)**.

**Реакция сервера:** пометить адрес как конфликтный и исключить его из выдачи до вмешательства администратора.

#### DHCPRELEASE

Клиент информирует сервер о досрочном освобождении IP-адреса (например, при корректном завершении работы ОС). Подтверждение от сервера не требуется.

#### DHCPINFORM

Клиент, уже имеющий IP-адрес (например, настроенный вручную), запрашивает дополнительные параметры конфигурации: адреса **DNS (Domain Name System)**, **NTP (Network Time Protocol)** и другие.

## Практические сценарии

### Рекомендуемое время аренды

| Тип сети | Lease Time | Обоснование |
| :--- | :--- | :--- |
| **Гостевые Wi-Fi зоны** | 30 мин – 2 часа | Высокая текучесть клиентов, необходимость быстрого возврата адресов в пул. |
| **Офисные сети** | 1–3 дня | Устройства стабильны, адреса сохраняются при перезагрузках в течение рабочего дня. |
| **Статическая инфраструктура** | От 7 дней | Для серверов и принтеров с резервированием адреса. |

### Выбор типа назначения

| Тип назначения | Сценарий применения |
| :--- | :--- |
| **Динамическое** | Основной вариант для клиентских устройств (ноутбуки, смартфоны). |
| **Автоматическое** | Сети, где важно сохранение адреса за устройством без ручной настройки. |
| **Резервирование (Static)** | Сетевое оборудование, серверы, принтеры (подробно: [резервирование IP в ISC DHCP](../../../Linux/Networking/Services/DHCP/isc_dhcp_server_reservations.md)). |
