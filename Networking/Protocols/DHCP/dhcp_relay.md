# DHCP Relay — Ретранслятор DHCP

> **Надёжность: 10/10** (SSoT + RFC Verification)
> **Актуальность: 2026-07** (Статус: Актуально)

## Определения

**DHCP Relay (Dynamic Host Configuration Protocol Relay)** — механизм, позволяющий DHCP-клиентам и серверам находиться в разных подсетях (разных широковещательных доменах). Ретранслятор (обычно маршрутизатор или L3-коммутатор) перехватывает широковещательные запросы клиентов и пересылает их серверу в виде направленного (unicast) трафика.

**Проблема:** Маршрутизаторы по умолчанию не передают broadcast-сообщения. Без ретранслятора DHCP-запросы клиента не покинут пределы локальной подсети, что потребовало бы наличия DHCP-сервера в каждом сегменте сети.

## Основные концепции

### DHCPv4 Relay: Механизм `giaddr`
В IPv4 ретранслятор модифицирует исходный пакет клиента перед пересылкой серверу.

1. **Перехват:** Ретранслятор принимает широковещательный `DHCPDISCOVER` на порту `67/UDP`.
2. **Маркировка подсети (`giaddr`):** Ретранслятор записывает IP-адрес своего интерфейса, на который пришёл запрос, в поле **`giaddr`** (Gateway IP Address). Это критически важное поле — по нему сервер определяет, из какого пула (subnet) нужно выделить адрес.
3. **Счётчик прыжков (`hops`):** Увеличивается значение в поле `hops` (защита от бесконечных петель, обычно лимит — 16).
4. **Unicast-пересылка:** Пакет отправляется напрямую на IP-адрес DHCP-сервера.
5. **Обратный путь:** Сервер отправляет `DHCPOFFER` на адрес `giaddr`. Ретранслятор получает его и рассылает (broadcast или unicast в зависимости от флагов) в локальную подсеть клиента.

### DHCPv6 Relay: Инкапсуляция
В отличие от v4, в IPv6 ретранслятор не меняет пакет клиента, а **инкапсулирует** его в специальные сообщения.

- **Relay-Forward (Type 12):** Ретранслятор упаковывает сообщение клиента (Solicit) внутрь опции **Relay Message (Option 9)**.
  - Поле `Link-Address`: Содержит глобальный адрес интерфейса ретранслятора (аналог `giaddr`).
  - Пакет отправляется на адрес `All_DHCP_Servers` (`ff05::1:3`) или unicast-адрес сервера.
- **Relay-Reply (Type 13):** Сервер отвечает ретранслятору, упаковывая ответ для клиента внутрь сообщения. Ретранслятор извлекает ответ и передаёт его клиенту на основе опции **Interface-ID (Option 18)**.

## Информационные опции (SRE & Security)

### Option 82 (IPv4) / Option 18 & 37 (IPv6)
Ретранслятор может добавлять в запрос метаданные о месте подключения клиента. Это используется для безопасности и точной настройки (например, выдачи IP в зависимости от номера порта коммутатора).

| Компонент | DHCPv4 (Opt 82) | DHCPv6 | Описание |
| :--- | :--- | :--- | :--- |
| **Circuit ID** | Sub-option 1 | Option 18 | Идентификатор порта/VLAN на коммутаторе доступа. |
| **Remote ID** | Sub-option 2 | Option 37 | Идентификатор самого устройства доступа (MAC, DUID). |

**Применение:**
- **Port-based IP:** Привязка IP к физическому порту в стойке.
- **Борьба с подменой:** Сервер игнорирует запросы, если `Circuit ID` не соответствует ожидаемому сегменту.

## Безопасность и отказоустойчивость

### Взаимодействие с DHCP Snooping
DHCP Relay работает в связке с механизмом **DHCP Snooping** на коммутаторах доступа:
1. Коммутатор помечает порты как **Trusted** (доверенные, ведут к серверу/relay) и **Untrusted** (клиентские).
2. На клиентских портах блокируются ответы от серверов (`DHCPOFFER`, `DHCPACK`).
3. При включении Option 82 коммутатор вставляет информацию о порте, а Relay Agent пересылает её серверу.

### Рекомендации по безопасности
- **Rate Limiting:** Ограничение количества DHCP-пакетов в секунду на интерфейсах ретранслятора для защиты от DHCP Starvation атак.
- **Trusted Relay:** На сервере рекомендуется принимать запросы только от доверенных IP-адресов ретрансляторов.
- **IPsec:** Для передачи DHCP-трафика через публичные сети (например, между офисами) следует использовать IPsec для защиты от перехвата и модификации полей опций.

## Практические примеры настройки

### Cisco IOS
```cisco
interface GigabitEthernet0/1
 ip address 192.168.10.1 255.255.255.0
 ip helper-address 10.0.0.100  # IP-адрес DHCP-сервера
```

### Linux (systemd-networkd)
Современный способ настройки ретранслятора в Linux (v255+):
```ini
# /etc/systemd/network/relay.network
[Match]
Name=eth1

[Network]
DHCPRelay=yes

[DHCPRelay]
ServerAddress=10.0.0.100
GatewayAddress=192.168.10.1
```

### Linux (ISC dhcrelay)
Классическая утилита (устарела, но часто встречается):
```bash
# dhcrelay -i <интерфейс_клиентов> -i <интерфейс_сервера> <IP_сервера>
dhcrelay -i eth0 -i eth1 10.0.0.100
```
Подробная настройка — [ISC DHCP Relay](../../../Linux/Networking/Services/DHCP/isc_dhcp_server_relay.md).
