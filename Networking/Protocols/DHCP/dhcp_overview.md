# DHCP (Dynamic Host Configuration Protocol) — Обзор

## Определения

**DHCP (Dynamic Host Configuration Protocol)** — протокол прикладного уровня (L7 OSI), предназначенный для автоматической конфигурации сетевых параметров устройств в IP-сетях. Описан в [RFC 2131](https://datatracker.ietf.org/doc/html/rfc2131).

Для работы хоста в сети необходимы:

- Собственный IP-адрес и маска подсети
- Адрес шлюза по умолчанию (gateway)
- Адреса DNS-серверов

**Архитектура:**

- **DHCP-сервер** — управляет пулом IP-адресов, отвечает на запросы клиентов (маршрутизатор или выделенный сервер)
- **DHCP-клиент** — ПО на устройстве (ПК, смартфон, принтер), запрашивающее сетевые настройки
- **DHCP Relay Agent** — маршрутизатор/хост, пересылающий DHCP-сообщения между подсетями (подробнее — [DHCP Relay](./dhcp_relay.md))

**Транспорт:** UDP

- Сервер: порт **67/UDP**
- Клиент: порт **68/UDP**

Разные порты предотвращают обработку клиентом пакетов, предназначенных для сервера.

## Основные концепции

### Процесс DORA

Взаимодействие клиента и сервера — последовательность из четырёх шагов: **D**iscover → **O**ffer → **R**equest → **A**cknowledge.

#### 1. Discovery (Обнаружение)

Клиент без IP отправляет широковещательное `DHCPDISCOVER` для поиска DHCP-серверов.

**Детали пакета:**

- L2: MAC `FF:FF:FF:FF:FF:FF`, L3: IP `255.255.255.255`
- Источник IP: `0.0.0.0`
- **`chaddr`** — MAC-адрес клиента (критично: сервер использует его для ответа)
- **`op`** = `1` (Boot Request)
- Опция Message Type: Discover

#### 2. Offer (Предложение)

Сервер отвечает `DHCPOFFER` — предлагает IP и параметры.

**Детали пакета:**

- **ICMP ping check:** перед отправкой сервер проверяет адрес ICMP Echo Request — если адрес свободен, включает в предложение
- **`yiaddr`** — предлагаемый IP-адрес
- **`siaddr`** — IP следующего сервера (например, TFTP для PXE)
- **Bootp flags:** Unicast (по умолчанию) или Broadcast (если клиент не принимает unicast без IP)
- Клиент может получить несколько предложений от разных серверов

#### 3. Request (Запрос)

Клиент выбирает предложение (обычно первое) и отправляет широковещательный `DHCPREQUEST`.

**Детали пакета:**

- Широковещание (`255.255.255.255`) — чтобы все серверы увидели выбор и освободили зарезервированные адреса
- **Gratuitous ARP:** перед отправкой клиент проверяет предложенный IP на конфликт через ARP
- Опции:
  - **DHCP Server Identifier** — выбранный сервер
  - **Requested IP Address** — IP из DHCPOFFER
  - **Client Identifier** — MAC клиента

#### 4. Acknowledgement (Подтверждение)

Сервер финализирует процесс `DHCPACK` — подтверждает выделение и передаёт параметры.

**Детали пакета:**

- **`yiaddr`** — выданный IP
- Опции: Subnet Mask, DNS, Router, Lease Time, Renewal Time (T1 = 50%), NTP, domain name
- После получения `DHCPACK` клиент применяет настройки
- Сервер помечает адрес как занятый

Детали механизма продления аренды (T1/T2) — в [DHCP Lease Time](./dhcp_lease_time.md). Дополнительные сообщения (DHCPNAK, DHCPDECLINE, DHCPRELEASE, DHCPINFORM) — там же.

## Практические сценарии

### Когда применять DHCP

| Сценарий | Рекомендация |
|----------|-------------|
| **Клиентские устройства** | Dynamic Allocation — стандартный подход (ПК, смартфоны) |
| **Серверы, принтеры** | Static Allocation (Reservation) — постоянный IP через привязку к MAC |
| **Высокая текучесть клиентов** | Короткий Lease Time (30 мин – 2 часа) — гостевые Wi-Fi |
| **Стабильная инфраструктура** | Длинный Lease Time (дни – месяцы) — корпоративные сети |
| **Клиент в другой подсети** | DHCP Relay Agent — ретрансляция между подсетями ([DHCP Relay](./dhcp_relay.md)) |
