# DHCP — Обзор протокола

## Определения

**DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла)** — протокол прикладного уровня (L7) модели OSI (Open Systems Interconnection), предназначенный для автоматической конфигурации сетевых параметров устройств в IP-сетях (Internet Protocol). Описан в RFC 2131 (Request for Comments 2131).

Для работы хоста в сети необходимы:

- Собственный IP-адрес и маска подсети
- Адрес шлюза по умолчанию (Default Gateway)
- Адреса DNS-серверов (Domain Name System)

**Архитектура:**

- **DHCP-сервер** — управляет пулом IP-адресов, отвечает на запросы клиентов (маршрутизатор или выделенный сервер).
- **DHCP-клиент** — программное обеспечение на устройстве (персональный компьютер, смартфон, принтер), запрашивающее сетевые настройки.
- **DHCP Relay Agent (Ретранслятор DHCP)** — маршрутизатор или хост, пересылающий DHCP-сообщения между подсетями. Подробности — [DHCP Relay](./dhcp_relay.md).

**Транспорт:** протокол UDP (User Datagram Protocol)

- Сервер: порт **67/UDP**
- Клиент: порт **68/UDP**

Разные порты предотвращают обработку клиентом пакетов, предназначенных для сервера.

## Основные концепции

### Процесс DORA

Взаимодействие клиента и сервера представляет собой последовательность из четырёх шагов: **D**iscover (Обнаружение) → **O**ffer (Предложение) → **R**equest (Запрос) → **A**cknowledge (Подтверждение).

#### 1. Discovery — Обнаружение

Клиент без IP-адреса отправляет широковещательное сообщение `DHCPDISCOVER` для поиска доступных DHCP-серверов.

**Детали пакета:**

- L2 (Data Link Layer): MAC-адрес (Media Access Control) `FF:FF:FF:FF:FF:FF`, L3 (Network Layer): IP `255.255.255.255`
- Источник IP: `0.0.0.0`
- **`chaddr` (Client Hardware Address)** — MAC-адрес клиента. Критически важно: сервер использует его для идентификации и ответа.
- **`op`** = `1` (Boot Request)
- Опция Message Type: Discover

#### 2. Offer — Предложение

Сервер отвечает сообщением `DHCPOFFER` — предлагает IP-адрес и сетевые параметры.

**Детали пакета:**

- **ICMP ping check:** перед отправкой предложения сервер может проверить доступность адреса через ICMP (Internet Control Message Protocol) Echo Request. Если адрес не отвечает, он включается в предложение.
- **`yiaddr` (Your IP Address)** — предлагаемый клиенту IP-адрес.
- **`siaddr` (Next Server IP Address)** — IP-адрес следующего сервера в цепочке загрузки (например, TFTP-сервер для загрузки по [PXE](../../../Linux/Networking/Concepts/pxe_boot.md)).
- **Bootp flags:** Unicast (по умолчанию) или Broadcast (если клиент не может принимать unicast без настроенного IP).
- Клиент может получить несколько предложений от разных серверов.

#### 3. Request — Запрос

Клиент выбирает одно из предложений (обычно первое поступившее) и отправляет широковещательный запрос `DHCPREQUEST`.

**Детали пакета:**

- Широковещание (`255.255.255.255`) необходимо для того, чтобы все остальные серверы увидели выбор клиента и освободили зарезервированные под него адреса.
- **Gratuitous ARP:** перед отправкой запроса клиент может проверить предложенный IP-адрес на конфликт в сети с помощью протокола ARP (Address Resolution Protocol).
- Опции:
  - **DHCP Server Identifier** — идентификатор выбранного сервера.
  - **Requested IP Address** — запрашиваемый IP-адрес из полученного `DHCPOFFER`.
  - **Client Identifier** — MAC-адрес клиента.

#### 4. Acknowledgement — Подтверждение

Сервер завершает процесс сообщением `DHCPACK` — подтверждает выделение адреса и передаёт финальные параметры.

**Детали пакета:**

- **`yiaddr`** — окончательно выданный IP-адрес.
- Опции: Subnet Mask (маска подсети), DNS, Router (шлюз), Lease Time (время аренды), Renewal Time (T1 = 50% времени аренды), NTP (Network Time Protocol), доменное имя.
- После получения `DHCPACK` клиент применяет настройки к сетевому интерфейсу.
- Сервер помечает адрес в своей базе как занятый.

Детали механизма продления аренды и дополнительные типы сообщений описаны в [DHCP Lease Time](./dhcp_lease_time.md).

## Практические сценарии

### Выбор стратегии распределения адресов

| Сценарий | Рекомендация |
| :--- | :--- |
| **Пользовательские устройства** | Динамическое распределение (Dynamic Allocation) — стандарт для ПК и смартфонов. |
| **Серверы и сетевые принтеры** | Статическое распределение (Static Allocation / Reservation) — привязка IP к MAC-адресу. |
| **Гостевые сети (Wi-Fi)** | Короткое время аренды (Lease Time: 30 минут – 2 часа) для быстрой очистки пула. |
| **Корпоративная инфраструктура** | Длительное время аренды (от нескольких дней) для стабильности. |
| **Клиент в другой подсети** | Использование [DHCP Relay](./dhcp_relay.md) для ретрансляции запросов. |

### Диагностика и безопасность

- **Анализ трафика:** методы поиска неисправностей описаны в [DHCP Analysis & Troubleshooting](./dhcp_analysis_troubleshooting.md).
- **Безопасность:** защита от атак (Rogue DHCP, Starvation) — в [DHCP Security](./dhcp_security.md).
