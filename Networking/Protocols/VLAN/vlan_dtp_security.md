# Безопасность портов: DTP и Port Security

## Определения

**DTP (Dynamic Trunking Protocol)** — проприетарный протокол Cisco, предназначенный для автоматического согласования режима работы порта (access или trunk) и протокола инкапсуляции (802.1Q или ISL) между двумя соседними коммутаторами.

**Cisco Port Security** — функция канального уровня (L2), позволяющая ограничивать входной трафик на порту коммутатора на основе MAC-адресов отправителей. Используется для защиты от MAC-флудинга и подключения несанкционированных устройств.

**VLAN Hopping (перебор VLAN)** — тип сетевой атаки, позволяющий злоумышленнику отправить трафик из одной VLAN в другую, минуя маршрутизатор или межсетевой экран.

**Reliability Score:** 10 (SSoT + Cisco documentation verified)

## Базовые концепции

### Протокол DTP и его риски

DTP автоматически переводит порт в режим магистрали (trunk), если обнаруживает на другом конце соответствующий запрос. В корпоративных сетях DTP является критической уязвимостью.

#### Типы атак через DTP

1.  **Switch Spoofing (подмена коммутатора):** Злоумышленник подключает компьютер с ПО, эмулирующим коммутатор (например, Yersinia), и отправляет DTP-кадры. Порт коммутатора переходит в режим trunk, предоставляя атакующему доступ ко всем VLAN, разрешенным на этой магистрали.
2.  **Непредсказуемость топологии:** Ошибки автосогласования могут привести к образованию L2-петель или внезапному отключению сегментов сети.

**Важно:** Протокол ISL (Inter-Switch Link) устарел и практически не используется. Стандартом де-факто является IEEE 802.1Q.

### Port Security (безопасность порта)

Позволяет жестко контролировать, какие устройства могут подключаться к конкретному порту доступа (access).

#### Основные механизмы

- **Максимальное количество MAC (Max MACs):** Ограничение числа устройств на одном порту (например, не более одного).
- **Sticky MAC (прилипающие адреса):** Коммутатор запоминает первый увиденный MAC-адрес и записывает его в конфигурацию (running-config). Это избавляет от ручного ввода адресов.
- **Режимы нарушения (Violation Modes):**
    - **Shutdown (по умолчанию):** Порт немедленно выключается (переходит в состояние error-disabled) при обнаружении чужого MAC. Требует ручного включения (`shutdown` / `no shutdown`).
    - **Restrict:** Порт остается активным, но трафик с несанкционированного MAC отбрасывается. Коммутатор генерирует лог и увеличивает счетчик нарушений.
    - **Protect:** Трафик отбрасывается без уведомлений и логов.

### VLAN Hopping: механизмы и защита

Атака направлена на обход изоляции VLAN.

1.  **Double Tagging (двойное тегирование):** Злоумышленник отправляет кадр с двумя тегами 802.1Q. Первый тег соответствует Native VLAN транка. Первый коммутатор удаляет внешний тег и отправляет кадр в транк. Второй коммутатор видит второй тег и направляет кадр в целевую VLAN.
    - **Защита:** Никогда не использовать Native VLAN (например, VLAN 1) для пользовательского трафика. Всегда явно тегировать Native VLAN (`vlan dot1q tag native`).
2.  **Атака через DTP:** Как описано выше (Switch Spoofing).
    - **Защита:** Отключить DTP на всех портах (`switchport nonegotiate`).

## Практические сценарии (Cisco IOS)

### Сценарий 1: Настройка защищенного Trunk-порта

Полное отключение автоматики и фиксация параметров.

```cisco
interface GigabitEthernet1/0/24
 description *** Trunk to Distribution-SW ***
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 # Отключение согласования (DTP)
 switchport nonegotiate
 # Безопасность Native VLAN
 switchport trunk native vlan 999
```

### Сценарий 2: Настройка Port Security на порту доступа

Ограничение доступа для конечного пользователя.

```cisco
interface GigabitEthernet1/0/5
 description *** User-PC-Dept_Finance ***
 switchport mode access
 switchport access vlan 10
 switchport nonegotiate
 
 # Включение Port Security
 switchport port-security
 # Ограничение: 1 MAC-адрес
 switchport port-security maximum 1
 # Автоматическое запоминание адреса
 switchport port-security mac-address sticky
 # Режим блокировки при нарушении
 switchport port-security violation shutdown
```

### Сценарий 3: Диагностика и мониторинг

```cisco
# Просмотр статуса DTP и режима порта
show interfaces Gi1/0/5 switchport

# Просмотр статистики Port Security
show port-security interface Gi1/0/5
show port-security address

# Проверка портов в состоянии error-disabled
show interfaces status err-disabled
```

## Дополнительная информация

### Рекомендации по безопасности (L2 Hardening)

- **Отключайте неиспользуемые порты:** Все порты, к которым ничего не подключено, должны быть в состоянии `shutdown`.
- **Black Hole VLAN:** Неиспользуемые порты должны быть назначены в специальную VLAN, которая никуда не маршрутизируется (например, VLAN 999).
- **BPDU Guard:** Используйте на портах доступа совместно с PortFast для защиты от петель, вызванных подключением сторонних коммутаторов.
- **DHCP Snooping:** Защита от подмены DHCP-сервера.
