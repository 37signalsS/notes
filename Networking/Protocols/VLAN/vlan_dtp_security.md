# DTP (Dynamic Trunking Protocol) и безопасность портов

## Определения

**DTP (Dynamic Trunking Protocol)** — проприетарный протокол Cisco, предназначенный для автоматического согласования режима работы порта (access или trunk) и протокола инкапсуляции (802.1Q или ISL) между двумя соседними коммутаторами.

**Switchport Nonegotiate** — параметр настройки порта Cisco, который отключает отправку DTP-кадров, фиксируя текущий режим работы и предотвращая автоматические изменения.

## Базовые концепции

### Зачем отключать DTP?

DTP полезен в малых сетях для упрощения настройки, однако в корпоративных средах он создает риски безопасности и стабильности.

1.  **Риски безопасности (VLAN Hopping):** Злоумышленник может отправить DTP-кадр со своего устройства, заставив порт коммутатора перейти в режим trunk. Это позволит злоумышленнику получить доступ к трафику всех разрешенных VLAN в этом транке.
2.  **Непредсказуемость:** Ошибки в конфигурации или копирование настроек могут привести к тому, что порт доступа (`access`) внезапно станет магистральным (`trunk`), вызывая утечку трафика или петли L2.
3.  **Избыточность:** В современных сетях конфигурация портов должна быть строго детерминированной. Явная настройка режима порта исключает «сюрпризы» от автоматики.

### Режимы DTP (Cisco)

| Режим | Описание |
| :--- | :--- |
| **Access** | Порт работает только в режиме доступа, DTP отключен. |
| **Trunk** | Порт работает в режиме магистрали и пытается договориться с соседом через DTP. |
| **Dynamic Desirable** | Активно пытается стать транком, отправляя DTP-кадры. Станет транком, если сосед в режиме desirable, auto или trunk. |
| **Dynamic Auto** | Пассивно ждет DTP-кадра. Станет транком, если сосед в режиме desirable или trunk. |
| **Nonegotiate** | DTP полностью отключен. Порт не отправляет и не обрабатывает DTP-кадры. |

## Практические сценарии

### Сценарий 1: Настройка Trunk с отключением DTP

Лучшая практика — жестко зафиксировать режим trunk и запретить любые согласования.

```cisco
interface GigabitEthernet1/0/24
 description *** Trunk to Core-SW ***
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 # Отключение DTP
 switchport nonegotiate
```

**Результат:** Порт всегда работает как trunk только для указанных VLAN. Никаких автоматических переключений.

### Сценарий 2: Настройка Access с защитой

Для портов доступа также рекомендуется отключать механизмы согласования.

```cisco
interface GigabitEthernet1/0/10
 description *** PC-User-Dept1 ***
 switchport mode access
 switchport access vlan 20
 # Даже если на другом конце включат trunk, порт не сменит режим
 switchport nonegotiate
```

### Сценарий 3: Диагностика состояния DTP

Проверка режима работы и статуса согласования порта.

```cisco
# Проверка режима порта и DTP
show interfaces Gi1/0/24 switchport

# Ожидаемый вывод (фрагмент):
# Administrative Mode: trunk
# Operational Mode: trunk
# Administrative Trunking Encapsulation: dot1q
# Operational Trunking Encapsulation: dot1q
# Negotiation of Trunking: Off   <-- DTP отключен
```

## Дополнительная информация

### Рекомендации (Best Practices)

- **Меньше автоматики — меньше проблем:** Явно указывайте `switchport mode access` или `switchport mode trunk`.
- **Используйте `switchport nonegotiate`:** Это стандарт де-факто для защищенных сетей Cisco.
- **Ограничивайте разрешенные VLAN:** Всегда используйте `switchport trunk allowed vlan` на транках.
- **VLAN Hopping:** Отключение DTP — первый шаг к защите от атак перебора VLAN. См. также: **[Безопасность VLAN](../../Security/Network_Security/vlan_security_best_practices.md)**.
