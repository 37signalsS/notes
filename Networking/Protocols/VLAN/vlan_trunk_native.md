# Trunk VLAN и Native VLAN

## Определения

**Trunk-порт** — порт коммутатора, передающий трафик нескольких VLAN с тегами 802.1Q по одному физическому соединению.

**Native VLAN** — специальный VLAN на trunk-портах, используемый для передачи нетегированного трафика между коммутаторами. По умолчанию — VLAN 1.

> **На английском:** Tagging VLAN. В русской литературе: «VLAN по тегам», «VLAN с метками», «тегированный VLAN».

## Базовые концепции

### Назначение Trunk VLAN

**Задача:** Передать трафик нескольких VLAN между коммутаторами по одному физическому соединению.

**Проблема без тегирования:** По одному кабелю на каждый VLAN — неэффективно (порты на коммутаторах ограничены).

**Решение:** Стандарт IEEE 802.1Q описывает процедуру тегирования. 802.1Q помещает внутрь Ethernet-фрейма 4-байтовый тег с информацией о принадлежности к VLAN.

**Расположение тега:**

```
| Dest MAC (6) | Src MAC (6) | 802.1Q Tag (4) | EtherType/Length (2) | Data (46-1500) | FCS (4) |
                              ↑
                              Тег вставляется между Src MAC и EtherType
```

**Размер тега:** 4 байта. Состав тега (TPID, TCI: PCP, DEI, VID) подробно описан в **[Формат кадра 802.1Q](./vlan_8021q_frame.md#структура-кадра-8021q)**.

### Назначение Native VLAN

| Проблема | Решение через Native VLAN |
|----------|---------------------------|
| **Служебные протоколы** (STP, CDP, LACP) не понимают теги 802.1Q | Пакеты отправляются без тега в Native VLAN |
| **Пакет без тега на trunk-порту** — что делать? | Автоматически относится к Native VLAN |
| **Обратная совместимость** со старыми устройствами | Нетегированный трафик проходит корректно |

### Принцип работы

```
Trunk-порт отправляет кадр:
├─ Тегированный (VLAN 10, 20, 30...) → добавляется тег 802.1Q
└─ Native VLAN (по умолчанию VLAN 1) → тег НЕ добавляется

Trunk-порт получает кадр:
├─ С тегом → обрабатывается согласно VLAN ID
└─ Без тега → относится к Native VLAN
```

## Практические сценарии

### Изменение Native VLAN (Cisco)

```cisco
interface GigabitEthernet0/1
 switchport trunk native vlan 99
!
! VLAN 99 должен существовать и не должен содержать пользовательский трафик
```

### Настройка trunk-порта (Cisco)

```cisco
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 switchport trunk native vlan 99
```

### Диагностика trunk-соединений

```bash
# Проверить разрешённые VLAN на trunk
show interfaces trunk
show running-config interface Gi0/24

# Проверить native VLAN
show interfaces Gi0/24 switchport

# Проверить получение тегов на Linux
tcpdump -i eth0 -e 'vlan[0:2] & 0x0fff = 10'
```

## Дополнительная информация

### Проблемы безопасности: Native VLAN mismatch

Если Native VLAN не совпадает на концах trunk-соединения, возможна утечка трафика между VLAN.

**Пример:**

- Коммутатор 1: Native VLAN = 1
- Коммутатор 2: Native VLAN = 99

Трафик VLAN 1 с коммутатора 1 попадёт в VLAN 99 на коммутаторе 2.

**Защита:**

- Явно настроить одинаковый Native VLAN на обоих концах
- Использовать отдельный служебный VLAN (не VLAN 1)
- Не передавать пользовательский трафик в Native VLAN

### Best Practices

- **Изменять Native VLAN с VLAN 1** на отдельный служебный VLAN (например, 99 или 999)
- **Не передавать пользовательский трафик** в Native VLAN
- **Native VLAN должен совпадать** на обоих концах trunk-соединения
- **Явно указывать разрешённые VLAN** на trunk-портах

**Стандарты:**

- **IEEE 802.1Q** — стандарт тегирования VLAN
- **IEEE 802.1p** — приоритизация трафика
