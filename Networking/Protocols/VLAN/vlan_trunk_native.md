# Магистральные порты (Trunk) и Native VLAN

## Определения

**Trunk-порт (Магистральный порт)** — порт сетевого устройства (коммутатора, маршрутизатора или сервера), который способен передавать трафик нескольких VLAN по одному физическому или логическому соединению. Для идентификации принадлежности кадров используется тегирование по стандарту **IEEE 802.1Q**.

**Native VLAN (Собственный VLAN)** — специальный идентификатор VLAN на trunk-порту, трафик которого передается без добавления 802.1Q тега. По умолчанию в оборудовании Cisco и многих других вендоров Native VLAN соответствует **VLAN 1**.

**PVID (Port VLAN ID)** — термин, используемый вендорами (Huawei, HP, TP-Link, D-Link) для обозначения VLAN, в который попадает нетегированный трафик на порту. Концептуально идентичен Native VLAN.

**Reliability Score:** 10 (SSoT + Industry standards verified)

## Базовые концепции

### Назначение Trunk-портов

Основная задача магистральных портов — масштабируемость и экономия ресурсов. Вместо выделения отдельного физического кабеля для каждого VLAN, технология 802.1Q позволяет мультиплексировать сотни и тысячи VLAN в одном канале.

**Механизм работы:**
При отправке кадра через trunk-порт коммутатор проверяет его VLAN ID. Если ID не совпадает с Native VLAN, в кадр вставляется 4-байтовая метка (тег). Подробнее о структуре метки см. в **[Формат кадра 802.1Q](./vlan_8021q_frame.md)**.

### Особенности Native VLAN

Native VLAN необходим для обеспечения обратной совместимости и работы служебных протоколов.

| Категория | Поведение |
| :--- | :--- |
| **Служебные протоколы** | Протоколы управления (STP, CDP, [LLDP](../lldp.md), VTP) часто обмениваются данными без тегов через Native VLAN. |
| **Нетегированные кадры** | Если на trunk-порт поступает кадр без тега, коммутатор относит его к настроенному Native VLAN. |
| **Старое оборудование** | Устройства, не поддерживающие 802.1Q, могут взаимодействовать с сетью через Native VLAN магистрального порта. |

### Управление списком разрешенных VLAN (VLAN Pruning)

По умолчанию trunk-порт пропускает все VLAN (1–4094). Однако хорошей практикой является ограничение этого списка (**VLAN Allow List**). Это предотвращает распространение широковещательного шторма и повышает безопасность, ограничивая доступ к сегментам сети.

## Практические сценарии (Cisco IOS)

### Базовая настройка Trunk

```cisco
interface GigabitEthernet0/24
 description *** Uplink to Core-Switch ***
 switchport mode trunk
 # Разрешаем только необходимые VLAN
 switchport trunk allowed vlan 10,20,30,99
 # Назначаем Native VLAN (рекомендуется отличный от VLAN 1)
 switchport trunk native vlan 99
```

### Принудительное тегирование Native VLAN

Для защиты от атак типа VLAN Hopping можно заставить коммутатор тегировать даже Native VLAN на всех магистральных портах.

```cisco
# Глобальная конфигурация
vlan dot1q tag native
```
*Примечание: Если данная команда включена, все кадры (включая Native VLAN) будут выходить из trunk-портов с тегами.*

### Диагностика и проверка

```bash
# Просмотр активных транков и разрешенных VLAN
show interfaces trunk

# Проверка настроек Native VLAN на конкретном порту
show interfaces Gi0/24 switchport | include Native

# Мониторинг нетегированного трафика в Linux (tcpdump)
# Позволяет увидеть трафик Native VLAN, приходящий на физический интерфейс
tcpdump -i eth0 -e -nn not vlan
```

## Безопасность и типичные проблемы

### Native VLAN Mismatch (Несовпадение)

Если на двух концах магистрального канала настроены разные Native VLAN, возникает ситуация «VLAN Leaking» (утечка трафика).

**Пример ошибки:**
- SW1: Native VLAN = 10
- SW2: Native VLAN = 20
- Результат: Трафик из VLAN 10 на SW1 попадет напрямую в VLAN 20 на SW2 без маршрутизации.

**Симптомы:**
- Сообщения в логах: `%CDP-4-NATIVE_VLAN_MISMATCH`.
- Проблемы с STP (несогласованность дерева).
- Непредсказуемое поведение сети и дыры в безопасности.

### VLAN Hopping через Native VLAN

Атака «двойного тегирования» (Double Tagging) возможна только в том случае, если атакующий находится в том же VLAN, который является Native для транка.

**Защита:**
1.  Никогда не использовать VLAN 1.
2.  Выделять для Native VLAN отдельный ID, в котором нет пользовательских портов (Dummy VLAN).
3.  Использовать `vlan dot1q tag native`.

## Дополнительная информация

### Резюме Best Practices

- **Уходите от VLAN 1:** Всегда меняйте Native VLAN на произвольный номер (например, 999), не используемый для данных.
- **Синхронность:** Обеспечивайте идентичность Native VLAN на обоих концах соединения.
- **Минимизация привилегий:** Ограничивайте список разрешенных VLAN (`allowed vlan`).
- **Явность:** Отключайте автоматическое согласование транков (DTP) с помощью `switchport nonegotiate`. Подробнее: **[Безопасность портов: DTP и Port Security](./vlan_dtp_security.md)**.
