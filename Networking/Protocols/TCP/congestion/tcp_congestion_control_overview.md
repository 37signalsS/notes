# Управление перегрузкой TCP — Обзор и базовые механизмы

## Определения

**Управление перегрузкой (Congestion Control)** — механизм транспортного уровня, предназначенный для предотвращения переполнения сетевых узлов (роутеров, коммутаторов) путём адаптации скорости передачи данных к текущей пропускной способности канала.

**Ключевое отличие от [управления потоком (Flow Control)](../Flow_Control/index.md):**

- **Congestion Control:** Защита **сети** от переполнения (отправитель → сеть). Основной параметр — `cwnd` (Congestion Window).
- **Flow Control:** Защита **получателя** от переполнения (отправитель → получатель). Основной параметр — `rwnd` (Receive Window).

**Итоговое окно отправки (Send Window):**
Определяется как минимальное из двух значений:
```text
Send Window = min(cwnd, rwnd)
```

## Основные концепции

### Зачем нужно управление перегрузкой?

Передача данных «один пакет за раз» (Stop-and-Wait) надёжна, но крайне медленна на каналах с высокой задержкой.

**Пример расчета (Владивосток — Калининград):**
- **Расстояние:** ~7 500 км (RTT ≈ 100 мс).
- **MSS:** 1460 байт.
- **Скорость без окна:** (1460 байт / 0.1 сек) = 14.6 КБ/сек.

Для использования всей полосы (например, 1 Гбит/с) необходимо отправлять данные непрерывно, заполняя «трубу» канала. Этот объем называется **BDP (Bandwidth-Delay Product)**.

### Окно перегрузки (Congestion Window, cwnd)

`cwnd` — это переменная состояния на стороне отправителя, которая ограничивает количество байт, находящихся «в полёте» (Inflight), то есть отправленных, но ещё не подтверждённых.

### Базовые фазы алгоритмов (RFC 5681)

#### 1. Медленный старт (Slow Start)

**Цель:** Быстро занять доступную полосу при открытии соединения.

- **Начало:** `initcwnd` (обычно 10 MSS).
- **Рост:** Экспоненциальный. На каждый полученный ACK окно `cwnd` увеличивается на 1 MSS. Фактически, окно удваивается каждый RTT.
- **Условие перехода:** Достижение порога `ssthresh` или потеря пакета.

#### 2. Избегание перегрузки (Congestion Avoidance)

**Механизм AIMD (Additive Increase Multiplicative Decrease):**
Используется, когда соединение близко к пределу пропускной способности.

- **Аддитивный рост (AI):** Окно увеличивается линейно (+1 MSS за один RTT).
- **Мультипликативное уменьшение (MD):** При обнаружении потери (через DupACK) окно уменьшается в два раза (`cwnd = cwnd / 2`).

#### 3. Быстрая ретрансмиссия и восстановление (Fast Retransmit / Fast Recovery)

Вместо ожидания долгого тайм-аута (RTO), TCP реагирует на **3 дубликата ACK** (Duplicate ACK).

- **Fast Retransmit:** Немедленная переотправка потерянного сегмента.
- **Fast Recovery:** Позволяет продолжать передачу новых данных после потери, не возвращаясь к фазе Slow Start.
- **PRR (Proportional Rate Reduction):** Современный алгоритм в Linux (RFC 6937), заменяющий классический Fast Recovery для более плавного восстановления скорости.

## Механизмы обратной связи

### Сигналы о перегрузке (2026)

1.  **Потеря пакетов (Loss-based):** Классический сигнал (Reno, CUBIC). Считается «жестким» сигналом, так как очередь уже переполнена.
2.  **Рост задержки (Delay-based):** Предупредительный сигнал (Vegas, BBR). Позволяет снизить скорость до того, как пакеты начнут отбрасываться.
3.  **Явное уведомление (ECN):** Сетевое оборудование выставляет флаг `CE` (Congestion Experienced) в заголовке IP, сообщая о росте очередей без потери пакетов.
4.  **Tail Loss Probe (TLP):** Механизм Linux для быстрой диагностики потерь в конце транзакции, когда нет возможности получить Duplicate ACKs.

## Практические сценарии

### Сценарий 1: Расчет необходимого окна (BDP)

Для утилизации канала 100 Мбит/с при задержке 20 мс:
1. **Bandwidth:** 100 000 000 бит/с.
2. **RTT:** 0.020 сек.
3. **BDP:** 100 000 000 × 0.020 = 2 000 000 бит (250 КБ).
4. **cwnd в MSS:** 250 000 / 1460 ≈ **172 MSS**.

Если `cwnd` меньше этого значения, канал будет простаивать.

### Сценарий 2: Реакция на разные типы потерь

| Событие | Реакция (CUBIC/Reno) | Состояние после |
| :--- | :--- | :--- |
| **3 Duplicate ACKs** | `cwnd = cwnd * 0.7` (CUBIC) | Congestion Avoidance |
| **Тайм-аут (RTO)** | `cwnd = 1 MSS` | Slow Start |
| **Сигнал ECN** | Снижение скорости как при потере | Congestion Avoidance |
