# Алгоритмы управления перегрузкой TCP

## Определения

**Алгоритм управления перегрузкой (Congestion Control Algorithm)** — программная реализация логики управления окном перегрузки (`cwnd`) в протоколе TCP. Он определяет, как отправитель должен изменять скорость передачи данных в ответ на сигналы о состоянии сети (потери пакетов, изменение задержки или явные уведомления о перегрузке).

**Ключевые подходы:**

- **Loss-based (Reno, CUBIC):** используют потерю пакетов как основной сигнал для уменьшения скорости.
- **Delay-based (Vegas):** используют рост задержки RTT для проактивного обнаружения перегрузки до возникновения потерь.
- **Model-based (BBR):** строят динамическую модель сети, измеряя максимальную пропускную способность и минимальную задержку.

**SSoT:** базовые механизмы Slow Start, AIMD и Fast Recovery описаны в [Обзоре управления перегрузкой](./tcp_congestion_control_overview.md).

## Основные концепции

### Эволюция алгоритмов

| Поколение | Алгоритмы | Сигнал перегрузки | Период доминирования |
| :--- | :--- | :--- | :--- |
| **1-е (классические)** | Tahoe, Reno, NewReno | Потеря пакетов (RTO / DupACK) | 1988–2003 |
| **2-е (гибридные)** | CUBIC, HTCP | Потеря + время с момента последней потери | 2004–2015 |
| **3-е (модельные)** | BBR, Vegas | Доступная пропускная способность + RTT | 2016 – наст. время |

### CUBIC

CUBIC является алгоритмом по умолчанию в современных ОС (Linux, FreeBSD 14+, Windows Vista+).

**Особенности:**
- Функция роста окна зависит от **времени с момента последней потери**, а не от RTT, что делает его более справедливым (fairness) для соединений с разными задержками.
- Агрессивно использует пропускную способность в сетях с высоким BDP (Bandwidth-Delay Product).

**Формула роста:**
```text
W(t) = C × (t - K)³ + W_max

где:
  t — время с момента последней потери;
  K — время, необходимое для достижения W_max в отсутствие потерь;
  W_max — размер окна перед последним событием перегрузки;
  C — константа масштабирования (обычно 0.4).
```

### BBR (Bottleneck Bandwidth and Round-trip time)

Разработан Google в 2016 году. В отличие от классических алгоритмов, BBR не считает потерю пакета обязательным признаком перегрузки.

**Принципы работы:**
- **Измерение параметров:** BBR постоянно зондирует сеть для определения максимальной пропускной способности (Max BW) и минимального времени задержки (Min RTT).
- **Целевое окно:** `Target cwnd = Max BW × Min RTT × Gain`.
- **Минимизация bufferbloat:** BBR старается не заполнять буферы промежуточного оборудования, удерживая объём данных в полёте на уровне BDP.

**Версии BBR:**
- **BBRv1 (2016):** базовая версия, встроенная в ядро Linux 4.9+.
- **BBRv2 (2020):** улучшенная совместимость с CUBIC (fairness) и поддержка ECN.
- **BBRv3 (2023):** дальнейшая оптимизация производительности и стабильности.

### Прочие алгоритмы

| Алгоритм | Описание | Применение |
| :--- | :--- | :--- |
| **Reno** | Классический AIMD. Очень чувствителен к потерям. | Устарел, эталон для сравнения. |
| **Westwood** | Оценка пропускной способности на основе ACK. | Мобильные и беспроводные сети. |
| **HTCP** | Hamilton TCP. Адаптирован для высокоскоростных каналов. | Высокопроизводительные вычисления. |
| **DCTCP** | Data Center TCP. Использует ECN для минимизации задержек. | Внутри ЦОД (Microsoft Azure, Facebook). |

## Практические сценарии

### Выбор алгоритма в зависимости от условий

| Сценарий | Рекомендуемый алгоритм | Обоснование |
| :--- | :--- | :--- |
| **Веб-сервер (публичный)** | `BBR` | Лучшая работа на нестабильных каналах и при наличии потерь. |
| **Высокоскоростная сеть (LAN/DC)** | `CUBIC` или `DCTCP` | Стабильность и предсказуемость в чистых каналах. |
| **Спутниковые/мобильные связи** | `BBR` или `Westwood` | Устойчивость к высокой задержке и случайным потерям. |
| **Универсальное применение** | `CUBIC` | Надёжный выбор по умолчанию для большинства систем. |

### Настройка в Linux

В Linux управление алгоритмами осуществляется через `sysctl`. Подробные инструкции по настройке и выбору дисциплины очередей (qdisc) приведены в разделе [Алгоритмы управления перегрузкой в Linux](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_congestion_algorithms.md).

**Основные команды для проверки:**
```bash
# Просмотр текущего алгоритма
sysctl net.ipv4.tcp_congestion_control

# Просмотр доступных в системе алгоритмов
sysctl net.ipv4.tcp_available_congestion_control
```
