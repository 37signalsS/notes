# Алгоритм Нагла (Nagle Algorithm)

## Определения

**Алгоритм Нагла (Nagle Algorithm)** — алгоритм в TCP, предназначенный для уменьшения количества маленьких пакетов в сети путём их объединения (buffering) перед отправкой.

**Автор:** Джон Нагл (John Nagle), описан в **RFC 896** (1984).

**Цель:** повышение эффективности TCP/IP за счёт снижения накладных расходов на передачу мелких пакетов.

## Базовые концепции

### Проблема малых пакетов

При передаче интерактивных данных (телнет, удалённый рабочий стол) приложение может отправлять данные по одному байту. Это приводит к огромным накладным расходам.

**Пример накладных расходов для 1 байта данных:**

| Заголовок | Размер |
| :--- | :--- |
| Ethernet | 14 байт |
| IP | 20 байт |
| TCP | 20 байт |
| **Полезные данные** | **1 байт** |
| **Итого** | **55 байт** |

**Накладные расходы:** 5400% (54 байта служебной информации на 1 байт данных).

### Принцип работы алгоритма

**Правило алгоритма Нагла:**

> Отправитель может отправить новый пакет, если выполняется **одно из условий**:
>
> 1. Размер данных ≥ MSS (Maximum Segment Size)
> 2. Все ранее отправленные данные получили подтверждение (ACK)
> 3. Установлен флаг `TCP_NODELAY`

**Алгоритм:**

```
if (размер_данных >= MSS) {
    отправить немедленно
} else if (все_подтверждены()) {
    отправить немедленно
} else {
    буферизовать данные до получения ACK
}
```

### Пример работы

#### Без алгоритма Нагла

```
Клиент                          Сервер
  |                                 |
  |  "H" (1 байт) ----------------> |  ACK
  |  <----------------------------- |
  |  "E" (1 байт) ----------------> |  ACK
  |  <----------------------------- |
  |  "L" (1 байт) ----------------> |  ACK
  |  <----------------------------- |
  |  "L" (1 байт) ----------------> |  ACK
  |  <----------------------------- |
  |  "O" (1 байт) ----------------> |  ACK
  |  <----------------------------- |
```

**Результат:** 5 пакетов для передачи 5 байт данных.

#### С алгоритмом Нагла

```
Клиент                          Сервер
  |                                 |
  |  "H" (1 байт) ----------------> |  ACK
  |  <----------------------------- |
  |  [буферизация "ELLO"]          |
  |  (ждёт ACK на "H")             |
  |  "ELLO" (4 байта) ------------> |  ACK
  |  <----------------------------- |
```

**Результат:** 2 пакета для передачи 5 байт данных.

## Практические сценарии

### Когда алгоритм Нагла полезен

| Сценарий | Эффект |
| :--- | :--- |
| **Передача файлов** | Объединение мелких сегментов в крупные |
| **Пакетная обработка** | Уменьшение количества пакетов |
| **Высокая загрузка сети** | Снижение перегрузки от мелких пакетов |

### Когда алгоритм Нагла вреден

| Сценарий | Проблема |
| :--- | :--- |
| **Интерактивные приложения** | Задержка отображения символов (телнет, SSH) |
| **Удалённый рабочий стол** | Задержка отрисовки элементов интерфейса |
| **Онлайн-игры** | Повышенная задержка (latency) |
| **Real-time приложения** | Недопустимые задержки |

**Пример проблемы:**

При подключении через SSH к удалённому серверу каждый введённый символ должен отображаться в терминале немедленно. С алгоритмом Нагла:

1. Пользователь вводит символ
2. Клиент отправляет 1 байт
3. Клиент буферизует следующие символы до получения ACK
4. Задержка увеличивается на RTT (Round-Trip Time)

**Результат:** «вязкий», неотзывчивый интерфейс.

### Отключение алгоритма Нагла

**Флаг `TCP_NODELAY`:**

Для отключения алгоритма Нагла используется опция сокета `TCP_NODELAY`.

**Пример на Python:**

```python
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
sock.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)
```

**Пример на C:**

```c
int flag = 1;
setsockopt(sockfd, IPPROTO_TCP, TCP_NODELAY, &flag, sizeof(flag));
```

**Проверка в Linux:**

```bash
# Просмотр параметров TCP соединения
ss -tno | grep nodeLAY
```

### Взаимодействие с Delayed ACK

**Проблема:** алгоритм Нагла может конфликтовать с механизмом **Delayed ACK**.

**Delayed ACK:**

- Получатель задерживает отправку ACK до 500 мс
- Или до получения 2 полных сегментов
- Или до отправки данных в обратном направлении

**Сценарий конфликта:**

```
1. Отправитель отправляет 1 байт
2. Отправитель буферизует данные (ждёт ACK)
3. Получатель задерживает ACK (Delayed ACK)
4. Отправитель не может отправить новые данные
5. Получатель ждёт данные для отправки ACK вместе с ними
6. Взаимная блокировка до таймаута (до 500 мс)
```

**Решение:**

- Отключить алгоритм Нагла (`TCP_NODELAY`)
- Или отключить Delayed ACK (не рекомендуется, зависит от ОС)

**Настройка Delayed ACK в Linux:**

```bash
# Просмотр
sysctl net.ipv4.tcp_ack_skipped

# Отключение (не рекомендуется)
sysctl -w net.ipv4.tcp_ack_delayed=0
```

## Дополнительная информация

### RFC и стандарты

| RFC | Описание |
| :--- | :--- |
| **RFC 896** | Оригинальное описание алгоритма Нагла |
| **RFC 1122** | Требования к хостам (раздел 4.2.3.2) |
| **RFC 3465** | Ограничения на отправку мелких пакетов |

### Рекомендации по использованию

| Приложение | Рекомендация |
| :--- | :--- |
| **Веб-сервер (HTTP/HTTPS)** | Оставить включённым |
| **Передача файлов (FTP, SFTP)** | Оставить включённым |
| **SSH, Telnet** | Отключить (`TCP_NODELAY=1`) |
| **Онлайн-игры** | Отключить |
| **VoIP, видеоконференции** | Отключить (если используется TCP) |
| **Базы данных** | Зависит от workload (тестировать) |

**Общее правило:**

- **Потоковая передача данных** → оставить включённым
- **Интерактивный трафик** → отключить
