# Алгоритм Нагла (Nagle Algorithm)

## Определения

**Алгоритм Нагла (Nagle Algorithm)** — механизм в протоколе TCP, предназначенный для повышения эффективности использования пропускной способности сети путем предотвращения «проблемы маленьких пакетов» (Small Packet Problem). Он объединяет множество мелких вызовов `write` от приложения в один сегмент перед отправкой.

**Цель:** Снижение накладных расходов (заголовков L2-L4) при передаче интерактивного или мелко-блочного трафика. Без этого алгоритма каждый байт данных мог бы генерировать пакет размером в 41 байт (20 IP + 20 TCP + 1 Data).

**Стандарты:** Описан в **RFC 896** (1984) и является обязательным к реализации согласно **RFC 1122**.

---

## Базовые концепции

### Механизм работы (Логика)

Алгоритм Нагла работает по принципу «одного пакета в полете». Отправитель может отправить данные только если выполняется **хотя бы одно** из условий:
1.  **Полный сегмент:** В буфере накопилось достаточно данных для формирования сегмента максимального размера (**MSS**).
2.  **ACK получен:** Все ранее отправленные сегменты уже подтверждены получателем (в очереди нет неподтвержденных данных).
3.  **Таймаут:** Сработал внутренний таймер (менее распространенный случай в современных реализациях).
4.  **Флаг NODELAY:** Алгоритм явно отключен для данного сокета.

### Конфликт с Delayed ACK (TCP Deadlock)

Наиболее критическая проблема алгоритма — взаимодействие с механизмом **Delayed ACK** (отложенное подтверждение) на стороне получателя.

**Сценарий «тупика»:**
1.  **Отправитель** посылает первую часть данных (меньше MSS) и ждет ACK, чтобы отправить вторую мелкую часть (согласно правилу Нагла).
2.  **Получатель** получает первую часть, но не отправляет ACK немедленно, надеясь «приклеить» его к ответным данным (**Piggybacking**).
3.  Если ответных данных нет, получатель ждет срабатывания таймера Delayed ACK (обычно **40–200 мс**).
**Итог:** Соединение замирает на время таймера, что катастрофично для интерактивных систем.

### Nagle vs TCP_CORK

В Linux существует более агрессивная опция — `TCP_CORK`.
- **Nagle:** Позволяет отправить неполный пакет, если сеть пуста (получен ACK).
- **TCP_CORK:** Полностью запрещает отправку любых сегментов меньше MSS, пока «пробка» (cork) не будет вытащена приложением. Используется для сборки сложных ответов из нескольких вызовов `sendfile` и `write`.

## Практические сценарии

### Диагностика состояния алгоритма в Linux

Используйте утилиту `ss` для проверки активных опций сокета:
```bash
ss -tin dst 1.2.3.4
# → ESTAB 0 0 10.0.0.1:443 1.2.3.4:54321
# → cubic rto:204 rtt:15.2/0.5 nagle
```
- **nagle:** Алгоритм активен (стандартное поведение).
- **nodelay:** Алгоритм отключен опцией `TCP_NODELAY`.

### Обнаружение конфликта через tcpdump

Если в дампе наблюдается задержка ровно ~200 мс (или 40 мс в современных дистрибутивах) перед ACK, это признак конфликта.
```bash
sudo tcpdump -ni eth0 'tcp port 80' -tt
# → 12:00:00.000 IP 1.1.1.1 > 2.2.2.2: Flags [P.], seq 1:10, ack 1
# → 12:00:00.040 IP 2.2.2.2 > 1.1.1.1: Flags [.], ack 10
# # → Результат: Задержка 40мс указывает на ожидание таймера Delayed ACK.
```

### Применение в современных протоколах (2026)

- **HTTP/2 и HTTP/3:** Нагла **обязательно отключается** (`TCP_NODELAY`), так как протоколы сами управляют мультиплексированием и мелкими фреймами управления.
- **WebSockets / gRPC:** Отключается для обеспечения мгновенной реакции в реальном времени.
- **Интерактивный SSH:** Отключается по умолчанию для исключения лагов при вводе текста.

## Рекомендации по настройке

### Когда отключать (TCP_NODELAY)
- Любые **Request-Response** протоколы с мелкими сообщениями.
- Игровые сервера и финансовые транзакции (Low Latency).
- Приложения, использующие TLS (заголовки TLS могут дробиться).

### Отключение в коде (Python)
```python
import socket
sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
# Отключение алгоритма Нагла (включение режима No Delay)
sock.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)
```
