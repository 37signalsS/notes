# Алгоритм Нагла (Nagle Algorithm)

## Определения

**Алгоритм Нагла (Nagle Algorithm)** — механизм в протоколе TCP, предназначенный для повышения эффективности использования пропускной способности сети путем предотвращения «проблемы маленьких пакетов» (Small Packet Problem). Алгоритм объединяет мелкие порции данных в один сегмент перед отправкой.

**Цель:** Снижение накладных расходов (заголовков L2-L4) при передаче интерактивного или мелко-блочного трафика.

**Статус:** Описан в **RFC 896** (1984) и уточнен в **RFC 1122**. По умолчанию включен в большинстве ОС.

---

## Основные концепции

### Проблема малых пакетов

При передаче данных по 1 байту (например, в SSH-сессии) каждый байт упаковывается в заголовки:
- **Ethernet:** 14-18 байт.
- **IP:** 20 байт.
- **TCP:** 20-32 байт.
**Итог:** 54+ байта служебной информации на 1 байт данных. Алгоритм Нагла «склеивает» такие вызовы в один сегмент.

### Правила работы алгоритма

Отправитель может отправить данные только в трех случаях:
1.  Если в буфере накопилось достаточно данных для формирования **полного сегмента (MSS)**.
2.  Если **все** ранее отправленные сегменты получили подтверждение (ACK).
3.  Если алгоритм отключен (опция сокета `TCP_NODELAY`).

**Логика «одного пакета в полете»:** Если данных мало, Нагла ждет подтверждения на предыдущий пакет, прежде чем отправить следующий мелкий блок.

### Конфликт с Delayed ACK (Deadlock)

Самая известная проблема Нагла — «тупик» при взаимодействии с механизмом **Delayed ACK** (отложенное подтверждение) на стороне получателя.

**Сценарий тупика:**
1.  Отправитель (Нагла) посылает мелкий запрос и ждет ACK для отправки второй части.
2.  Получатель (Delayed ACK) получил первую часть, но ждет вторую, чтобы отправить один кумулятивный ACK, либо ждет срабатывания таймера (**200 мс**).
**Результат:** Передача данных замирает ровно на 200 мс в каждом цикле запрос-ответ.

## Практическая диагностика

### Проверка состояния в Linux

Для анализа конкретного соединения используйте `ss`:
```bash
ss -tin dst 1.2.3.4
# → State      Recv-Q Send-Q Local Address:Port  Peer Address:Port
# → ESTAB      0      0      10.0.0.1:443        1.2.3.4:54321
# →   cubic ... nagle ...
```
- `nagle`: Алгоритм включен (по умолчанию).
- `nodelay`: Алгоритм отключен (установлена опция `TCP_NODELAY`).

### Диагностика через tcpdump
Если вы видите в дампе трафика стабильные задержки около 200мс между `PSH` и `ACK`, это признак конфликта Нагла + Delayed ACK.

```bash
sudo tcpdump -ni eth0 'tcp port 80' -tt
# → 12:00:00.000 IP 1.1.1.1.54321 > 2.2.2.2.80: Flags [P.], seq 1:10, ack 1
# → 12:00:00.200 IP 2.2.2.2.80 > 1.1.1.1.54321: Flags [.], ack 10
```

## Рекомендации по использованию

### Когда оставлять включенным?
- **Передача файлов (Bulk Transfer):** Максимальная утилизация канала за счет крупных пакетов.
- **Файловые серверы (NFS, SMB):** Снижение нагрузки на CPU за счет уменьшения количества прерываний.

### Когда отключать (TCP_NODELAY)?
- **Интерактивные сессии (SSH, RDP):** Для мгновенного отклика на нажатия клавиш.
- **Микросервисы (HTTP/2, gRPC, RPC):** Чтобы мелкие заголовки и запросы не ждали ACK.
- **Онлайн-игры:** Минимизация латентности (Input Lag).

### Как отключить (Python пример)
```python
import socket
sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
# Отключение алгоритма Нагла
sock.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)
```
