# Протокол TCP (Transmission Control Protocol): Обзор

## Определения

**TCP (Transmission Control Protocol)** — основной протокол транспортного уровня (L4) в стеке TCP/IP. Он обеспечивает надежную, упорядоченную и безошибочную доставку непрерывного потока байт между приложениями поверх ненадежной сетевой инфраструктуры (IP).

**Основные термины:**
- **Сегмент (Segment):** Единица данных TCP (PDU), инкапсулированная в IP-пакет.
- **Поток байт (Byte Stream):** Абстракция передачи: TCP не сохраняет границы прикладных сообщений. Данные передаются как единая лента байт.
- **ISN (Initial Sequence Number):** Начальный порядковый номер, криптографически выбираемый узлами при установке соединения.

## Основные концепции

### Ключевые характеристики
| Характеристика | Описание | Механизмы реализации |
| :--- | :--- | :--- |
| **Надежность** | Гарантия доставки данных в целостности. | Подтверждения (ACK), ретрансмиссии (RTO, Fast Retransmit), контрольные суммы. |
| **Упорядоченность** | Восстановление исходного порядка данных при их перемешивании в сети. | Порядковые номера (Sequence Numbers). |
| **Ориентация на соединение** | Требуется установка логической сессии перед передачей. | Трехэтапное рукопожатие (3-way Handshake: SYN, SYN-ACK, ACK). |
| **Управление потоком (Flow Control)** | Защита получателя от переполнения локального буфера. | Скользящее окно приема (Receiver Window, `rwnd`). |
| **Управление перегрузкой (Congestion Control)**| Защита сетевых узлов от заторов и отбрасывания пакетов. | Окно перегрузки (`cwnd`), алгоритмы AIMD, BBRv3, CUBIC. |

### Место в сетевой модели и эволюция (2026)

TCP работает на **транспортном уровне** и служит стандартом де-факто для подавляющего большинства критичных к надежности приложений.

```text
Прикладной уровень (HTTP/1.1, HTTP/2, SMTP, SSH, gRPC)
         ↓
Транспортный уровень (TCP) ← Обеспечивает сессионность и надежность
         ↓
Сетевой уровень (IPv4, IPv6)
```

**Сравнение с альтернативами:**
- **UDP:** Используется, когда задержка критичнее надежности (стриминг видео, VoIP, DNS). Не имеет механизмов рукопожатия и контроля перегрузок.
- **QUIC (HTTP/3):** Современный протокол, работающий поверх UDP. Реализует механизмы TCP (надежность, окна перегрузки) в пространстве пользователя (User Space), устраняя проблему "Head-of-line blocking", свойственную TCP, и сокращая время рукопожатия (интеграция с TLS 1.3).

## Практические сценарии

### Выбор протокола для архитектуры

1.  **TCP:** Транзакционные системы (БД), передача файлов, классические REST API. Необходима гарантия того, что клиент получит полный JSON или бинарный объект без потерь.
2.  **UDP:** Мониторинг (StatsD/Syslog), потоковое медиа, где потеря одного кадра/метрики менее критична, чем задержка на ретрансмиссию.
3.  **QUIC:** Современные микросервисы (RPC нового поколения) и публичные веб-приложения (CDN/Браузеры), требующие устойчивости к смене IP клиента и минимального TTFB.

### Базовая диагностика в Linux

Проверка текущего состояния TCP-соединений — первая линия диагностики SRE:

```bash
# Сводная статистика сокетов по состояниям
ss -s

# Детальный просмотр параметров (cwnd, RTT, потери) конкретного соединения
ss -ti dst 1.2.3.4

# Просмотр загруженного алгоритма управления перегрузкой
sysctl net.ipv4.tcp_congestion_control
```

### Стандарты (RFC)

- **RFC 9293:** Transmission Control Protocol (современный консолидированный стандарт 2022 года, заменяющий исторический RFC 793).
- **RFC 5681:** TCP Congestion Control (базовые алгоритмы AIMD/Slow Start).
- **RFC 7323:** TCP Extensions for High Performance (Window Scale, Timestamps).
