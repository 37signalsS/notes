# Протокол TCP (Transmission Control Protocol): Обзор

## Определения

**TCP (Transmission Control Protocol)** — это базовый протокол транспортного уровня (L4) в стеке TCP/IP, обеспечивающий надежную доставку данных в виде непрерывного потока байт между приложениями на хостах сети.

**Основные термины:**

- **Сегмент (Segment):** единица данных протокола (PDU) на транспортном уровне.
- **Поток байт (Byte Stream):** абстракция TCP, при которой данные передаются как последовательность байт без сохранения границ сообщений прикладного уровня.
- **Handshake (Рукопожатие):** процесс установления соединения для согласования параметров сессии.

---

## Основные концепции

### Ключевые характеристики

| Характеристика | Описание | Реализация |
| :--- | :--- | :--- |
| **Надежность** | Гарантирует доставку данных без искажений | ACK, Retransmission, Checksum |
| **Упорядоченность** | Восстановление исходного порядка байт | Sequence Numbers |
| **Ориентация на соединение** | Требуется установка сессии перед передачей | 3-way Handshake |
| **Управление потоком** | Защита получателя от переполнения буфера | Flow Control (Window Size) |
| **Управление перегрузкой** | Адаптация скорости к состоянию сети | Congestion Control (cwnd) |

### Место в стеке TCP/IP

TCP работает на **транспортном уровне** и обеспечивает связь между прикладным и сетевым уровнями:

```text
Прикладной уровень (HTTP, DNS, SMTP)
         ↓
Транспортный уровень (TCP / UDP) ← TCP здесь
         ↓
Сетевой уровень (IP)
         ↓
Канальный уровень (Ethernet, Wi-Fi)
```

### Структура заголовка TCP

Минимальный размер заголовка составляет 20 байт, максимальный (с опциями) — 60 байт.

| Поле | Размер | Назначение |
| :--- | :--- | :--- |
| **Source/Destination Port** | 16 бит | Идентификация процессов отправителя и получателя. |
| **Sequence Number** | 32 бита | Номер первого байта данных в текущем сегменте. |
| **Acknowledgment Number** | 32 бита | Номер следующего ожидаемого байта (при флаге ACK). |
| **Флаги** | 6-9 бит | Управление состоянием (SYN, ACK, FIN, RST, PSH, URG). |
| **Window Size** | 16 бит | Текущий размер окна приема получателя. |
| **Checksum** | 16 бит | Проверка целостности заголовка и данных. |

*Подробнее:* [Формат заголовка TCP](./Header_Format/index.md).

### Сравнение TCP и UDP

| Критерий | TCP | [UDP](../udp.md) |
| :--- | :--- | :--- |
| **Тип передачи** | Потоковый (Byte Stream) | Дейтаграммный (Datagram) |
| **Надежность** | Гарантированная | Best-effort (не гарантируется) |
| **Соединение** | Устанавливается (Stateful) | Не требуется (Stateless) |
| **Скорость** | Ниже (из-за подтверждений) | Выше (минимальные задержки) |

*Примечание:* Современный протокол **QUIC** (HTTP/3) работает поверх UDP, но реализует механизмы надежности на прикладном уровне, объединяя преимущества обоих протоколов.

## Практические сценарии

### Выбор TCP в зависимости от задачи

1. **Веб-трафик (HTTP/HTTPS):** критична целостность данных (HTML, скрипты, изображения).
2. **Передача файлов (FTP, SFTP):** потеря одного байта делает файл нечитаемым.
3. **Электронная почта (SMTP, IMAP):** гарантированная доставка текста и вложений.
4. **Базы данных:** строгая последовательность запросов и ответов.

### Выбор UDP вместо TCP

- **Стриминг и VoIP:** задержка из-за ретрансмиссии потерянного пакета в TCP критичнее, чем потеря одного кадра.
- **DNS:** быстрый запрос-ответ в один пакет экономит ресурсы.
- **Онлайн-игры:** минимальная латентность (пинг) важнее стопроцентной доставки всех данных о перемещении.
