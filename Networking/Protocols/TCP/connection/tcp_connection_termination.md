# Завершение TCP-соединения

## Определения

**Завершение TCP-соединения (TCP Connection Termination)** — это четырехэтапный процесс корректного разрыва соединения, обеспечивающий доставку всех оставшихся данных и освобождение ресурсов на обеих сторонах.

**Ключевое свойство:** TCP является полнодуплексным протоколом, поэтому каждое направление передачи закрывается независимо.

---

## Основные концепции

### Флаг FIN

- **FIN (Finish):** сигнал о завершении передачи данных в одном направлении.
- Сегмент с флагом FIN потребляет один порядковый номер (Sequence Number), аналогично сегменту SYN.
- После отправки FIN сторона больше не может отправлять новые данные, но продолжает принимать данные от удаленного узла до тех пор, пока тот не отправит свой FIN.

### Состояния при завершении

| Состояние | Роль | Описание |
| :--- | :--- | :--- |
| **FIN_WAIT_1** | Инициатор | Отправлен FIN, ожидание подтверждения (ACK) от партнера. |
| **FIN_WAIT_2** | Инициатор | Получен ACK, ожидание FIN от удаленной стороны. |
| **CLOSE_WAIT** | Получатель | Получен FIN, приложение еще не вызвало функцию закрытия сокета. |
| **LAST_ACK** | Получатель | Отправлен собственный FIN, ожидание финального ACK. |
| **TIME_WAIT** | Инициатор | Отправлен финальный ACK, ожидание периода 2×MSL. |
| **CLOSING** | Обе стороны | Одновременная отправка сегментов FIN обеими сторонами. |

*Подробная таблица всех состояний:* [Состояния TCP](./tcp_connection_states.md).

### TIME_WAIT

**Назначение:**
- Гарантия того, что последний подтверждающий сегмент (ACK) будет доставлен (если он потеряется, удаленная сторона повторно отправит FIN).
- Защита от «старых» дубликатов сегментов, которые могут задержаться в сети и быть ошибочно приняты в рамках нового соединения с теми же портами.

**Длительность:** по стандарту составляет `2 × MSL` (Maximum Segment Lifetime). В Linux по умолчанию это 60 секунд (настраивается параметром `tcp_fin_timeout`).

## Практические сценарии

### Сценарий 1: Стандартное завершение (четырехэтапное)

Процесс происходит в 4 шага:

```text
   Сторона A (инициатор)                 Сторона B
     |                                            |
     |  FIN (seq=u) --------------------------->  |  ESTABLISHED
     |      (FIN_WAIT_1)                          |      ↓
     |                                            |  CLOSE_WAIT
     |  <---------------------- ACK (ack=u+1) ----|
     |      (FIN_WAIT_2)                          |
     |                                            |
     |  <--- Данные от Б к А могут еще идти --->  |
     |                                            |
     |  <--------------------- FIN (seq=v) -------|
     |      (TIME_WAIT)                           |  LAST_ACK
     |                                            |
     |  ACK (ack=v+1) --------------------------> |  CLOSED
     |      (TIME_WAIT)                           |
     |                                            |
     |  [Ожидание 2×MSL]                          |
     |      ↓                                     |
     |  CLOSED                                    |
```

**Шаги:**
1. **A → FIN:** инициатор объявляет о закрытии своего потока.
2. **B → ACK:** подтверждение получения FIN. Соединение переходит в состояние полузакрытости (сторона B может продолжать передачу).
3. **B → FIN:** сторона B завершает свою передачу и закрывает поток.
4. **A → ACK:** финальное подтверждение. Инициатор входит в режим ожидания `TIME_WAIT`.

*Проблема CLOSE_WAIT:* если приложение не закрывает сокет программно, он навсегда остается в состоянии `CLOSE_WAIT`. Подробнее: [Анализ CLOSE_WAIT](./tcp_connection_states.md#1-close_wait-проблема-на-стороне-приложения).

---

### Сценарий 2: Одновременное закрытие (Simultaneous Close)

Редкая ситуация, когда оба узла решают закрыть соединение одновременно.

```text
Сторона A                               Сторона B
     |                                     |
     | FIN --------------------------------| FIN
     | FIN_WAIT_1                          | FIN_WAIT_1
     |                                     |
     | <---------------------------------  |
     | FIN                                 | FIN
     | CLOSING                             | CLOSING
     |                                     |
     | ACK ------------------------------->| ACK
     | TIME_WAIT                           | TIME_WAIT
```

В этом случае оба узла переходят через состояние `CLOSING` в `TIME_WAIT`.
