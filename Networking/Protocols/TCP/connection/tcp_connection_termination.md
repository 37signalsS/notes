# Завершение TCP-соединения

## Definitions

**Завершение TCP-соединения** — четырёхэтапный процесс корректного разрыва TCP-соединения, обеспечивающий доставку всех оставшихся данных и корректное освобождение ресурсов на обеих сторонах.

**Ключевое свойство:** TCP — полнодупсельный протокол, поэтому каждая сторона закрывается независимо (свой поток данных).

---

## Basic Concepts

### Флаг FIN

- **FIN (Finish)** — сигнал завершения передачи данных в одном направлении
- Потребляет 1 номер последовательности (как `SYN`)
- После отправки FIN сторона больше не передаёт данные, но может принимать

### Состояния при завершении

| Состояние | Кто | Описание |
| :--- | :--- | :--- |
| **FIN_WAIT_1** | Инициатор | Отправлен FIN, ожидание ACK |
| **FIN_WAIT_2** | Инициатор | Получен ACK, ожидание FIN от удалённой стороны |
| **CLOSE_WAIT** | Получатель | Получен FIN, приложение не вызвало `close()` |
| **LAST_ACK** | Получатель | Отправлен FIN, ожидание ACK |
| **TIME_WAIT** | Инициатор | Отправлен ACK, ожидание 2×MSL |
| **CLOSING** | Обе | Одновременная отправка FIN |

**Полная таблица:** [Состояния TCP](./tcp_connection_states.md)

### TIME_WAIT

**Назначение:**

- Гарантия доставки последнего ACK
- Защита от старых дубликатов сегментов

**Длительность:** `2 × MSL` (в Linux по умолчанию 60 сек, параметр `tcp_fin_timeout`)

## Practical Scenarios

### Сценарий 1: Стандартное четырёхэтапное завершение

```
   Сторона A (инициатор)                 Сторона B
     |                                            |
     |  FIN (seq=u) --------------------------->  |  ESTABLISHED
     |      (FIN_WAIT_1)                          |      ↓
     |                                            |  CLOSE_WAIT
     |  <---------------------- ACK (ack=u+1) ----|
     |      (FIN_WAIT_2)                          |
     |                                            |
     |  ◄════ Данные от Б к А ещё могут ════════► |
     |           передаваться                     |
     |                                            |
     |  <--------------------- FIN (seq=v) -------|
     |      (TIME_WAIT)                           |  LAST_ACK
     |                                            |
     |  ACK (ack=v+1) --------------------------> |  CLOSED
     |      (TIME_WAIT)                           |
     |                                            |
     |  [Ожидание 2×MSL]                          |
     |      ↓                                     |
     |  CLOSED                                    |
```

**Шаги:**

1. **Сторона A → FIN:** инициация закрытия, переход в `FIN_WAIT_1`
2. **Сторона B → ACK:** подтверждение, переход в `CLOSE_WAIT` (может ещё отправлять данные)
3. **Сторона B → FIN:** завершение передачи, переход в `LAST_ACK`
4. **Сторона A → ACK:** подтверждение, переход в `TIME_WAIT` (ожидание 2×MSL)

**Проблема CLOSE_WAIT:** если приложение на стороне B не вызывает `close()`, сокет зависает в `CLOSE_WAIT`. [Подробнее о диагностике CLOSE_WAIT](./tcp_connection_states.md#1-close_wait-проблема-на-стороне-сервера)

---

### Сценарий 2: Одновременное закрытие (Simultaneous Close)

**Условие:** обе стороны отправляют `FIN` одновременно.

```
Сторона A                               Сторона B
     | (app close)                         | (app close)
     | FIN --------------------------------| FIN
     | FIN_WAIT_1                          | FIN_WAIT_1
     |                                     |
     | <---------------------------------  |
     | FIN                                 | FIN
     | CLOSING                             | CLOSING
     |                                     |
     | ACK ------------------------------->| ACK
     | TIME_WAIT                           | TIME_WAIT
```

**Результат:** обе стороны переходят в `CLOSING`, затем в `TIME_WAIT`.
