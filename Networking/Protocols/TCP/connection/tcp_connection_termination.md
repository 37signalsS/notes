# Завершение TCP-соединения

## Четырёхэтапное завершение

**Особенность:** TCP — полнодуплексный протокол, каждая сторона закрывается независимо.

**Процесс:** 4 сегмента (four-way termination)

```
   Сторона A                                Сторона B
     |                                            |
     |  FIN (seq=u) --------------------------->  |  ESTABLISHED
     |      (Состояние: FIN_WAIT_1)               |      ↓
     |                                            |  CLOSE_WAIT
     |  <---------------------- ACK (ack=u+1) ----|
     |      (Состояние: FIN_WAIT_2)               |  (Состояние: CLOSE_WAIT)
     |                                            |
     |  ◄════ Данные от Б к А ещё могут ════════► |
     |           передаваться                     |
     |                                            |
     |  <--------------------- FIN (seq=v) -------|
     |      (Состояние: TIME_WAIT)                |  (Состояние: LAST_ACK)
     |                                            |
     |  ACK (ack=v+1) --------------------------> |
     |      (Состояние: TIME_WAIT)                |  (Состояние: CLOSED)
     |                                            |
     |  [Ожидание 2×MSL]                          |
     |      ↓                                     |
     |  CLOSED                                    |
```

---

## Детальный алгоритм

### Шаг 1: FIN от инициатора закрытия

| Параметр | Значение |
| :--- | :--- |
| **Флаги** | `FIN=1` |
| **Sequence Number** | `seq=u` (номер последнего байта + 1) |
| **Состояние** | `FIN_WAIT_1` |

**Важно:** `FIN` потребляет 1 номер последовательности (как SYN).

---

### Шаг 2: ACK от получателя FIN

| Параметр | Значение |
| :--- | :--- |
| **Флаги** | `ACK=1` |
| **Acknowledgment Number** | `ack=u+1` |
| **Состояние инициатора** | `FIN_WAIT_2` |
| **Состояние получателя** | `CLOSE_WAIT` |

**Состояние CLOSE_WAIT:**

- Получатель FIN может ещё отправлять данные
- Приложение должно вызвать `close()` для отправки своего FIN
- **Проблема:** если приложение не закрывает сокет → зависание в `CLOSE_WAIT`

---

### Шаг 3: FIN от получателя

| Параметр | Значение |
| :--- | :--- |
| **Флаги** | `FIN=1` |
| **Sequence Number** | `seq=v` |
| **Состояние** | `LAST_ACK` |

---

### Шаг 4: ACK от инициатора

| Параметр | Значение |
| :--- | :--- |
| **Флаги** | `ACK=1` |
| **Acknowledgment Number** | `ack=v+1` |
| **Состояние** | `TIME_WAIT` |

---

## Одновременное закрытие (Simultaneous Close)

**Сценарий:** обе стороны отправляют `FIN` одновременно

```
Сторона A                               Сторона B
     | (app close)                         | (app close)
     | FIN --------------------------------| FIN
     | FIN_WAIT_1                          | FIN_WAIT_1
     |                                     |
     | <---------------------------------  |
     | FIN                                 | FIN
     | CLOSING                             | CLOSING
     |                                     |
     | ACK ------------------------------->| ACK
     | TIME_WAIT                           | TIME_WAIT
     |                                     |
```

**Результат:** обе стороны переходят в `TIME_WAIT`.
