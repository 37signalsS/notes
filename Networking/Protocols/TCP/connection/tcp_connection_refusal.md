# Отказ в установке TCP-соединения

## Definitions

**Отказ в установке TCP-соединения** — ситуации, когда TCP-соединение не может быть установлено по одной из двух причин: удалённая сторона явно отвергла запрос (RST) или не ответила на SYN (тайм-аут).

**Типы отказа:**

| Тип | Механизм | Время ошибки | Причина |
| :--- | :--- | :--- | :--- |
| **RST (Reset)** | Мгновенный сброс | ~0 мс | Порт закрыт, приложение недоступно |
| **SYN timeout** | Нет ответа, ретрансмиссии | ~7 сек | Сервер выключен, фаервол DROP |

---

## Basic Concepts

### RST (Reset) — мгновенный сброс

Если на хосте нет приложения, слушающего указанный порт, TCP отправляет `RST` в ответ на `SYN`:

```
   Клиент                                     Сервер
     |                                            |
     |  SYN (seq=x) ----------------------------> |  Порт закрыт
     |      (Состояние: SYN_SENT)                 |
     |  <---------------------------- RST --------|  Немедленный сброс
     |                                            |
     |  Получен RST → соединение не установлено   |
```

**Назначение RST:**

- Немедленно уведомить клиента о недоступности сервиса
- Позволить приложению быстро обработать ошибку (без ожидания тайм-аута)
- Экономить ресурсы сети и хоста

### SYN timeout — отсутствие ответа

Если удалённая сторона не отвечает на SYN (сервер выключен, фаервол DROP, маршрут отсутствует), TCP использует экспоненциальный backoff:

```
   Клиент                                     Сервер
     |                                            |
     |  SYN #1 --------------------------------> |  (нет ответа)
     |      (ожидание 1 секунду)                  |
     |  SYN #2 --------------------------------> |  (нет ответа)
     |      (ожидание 2 секунды)                  |
     |  SYN #3 --------------------------------> |  (нет ответа)
     |      (ожидание 4 секунды)                  |
     |  SYN #4 --------------------------------> |  (нет ответа)
     |                                            |
     |  Тайм-аут → ошибка соединения              |
```

### Алгоритм экспоненциального backoff

| Попытка | Задержка перед следующей | Кумулятивное время |
| :--- | :--- | :--- |
| 1 | 1 сек | 0 сек |
| 2 | 2 сек | 1 сек |
| 3 | 4 сек | 3 сек |
| 4 | — | 7 сек |

**Параметры:**

- **Попыток:** 4 (по умолчанию в современных системах)
- **Общее время:** ~7 секунд
- **Настройка:** `net.ipv4.tcp_syn_retries`

### Почему приложение «зависает»

При отсутствии `SYN-ACK` или `RST` TCP считает пакет потерянным и повторяет SYN. Приложение блокируется на время всех попыток (~7 сек), что воспринимается как «зависание».

### RST vs DROP (фаервол)

| Реакция | Поведение | Время ошибки | Команда iptables |
| :--- | :--- | :--- | :--- |
| **REJECT** | Мгновенный RST | ~0 мс | `iptables -j REJECT` |
| **DROP** | Нет ответа | ~7 сек | `iptables -j DROP` |

## Practical Scenarios

### Сценарий 1: Закрытый порт (RST)

**Симптом:** мгновенный отказ при подключении к порту.

**Причины RST:**

| Причина | Симптом | Решение |
| :--- | :--- | :--- |
| **Порт не слушается** | RST на SYN | Запустить приложение |
| **Приложение упало** | RST на данные | Перезапустить сервис |
| **Фаервол (REJECT)** | RST сразу | Проверить правила firewall |

**Диагностика:**

```bash
# Проверка портов через nmap (закрытый порт ответит RST)
nmap -p 80,443,5555 target.host

# Перехват RST-пакетов
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-rst != 0'
```

**Подробнее о диагностике:** [RST-диагностика](./tcp_connection_diagnostics.md#сценарий-4-диагностика-rst-reset)

---

### Сценарий 2: Хост не отвечает (SYN timeout)

**Симптом:** ожидание ~7 секунд перед ошибкой соединения.

**Причины отсутствия ответа:**

| Причина | Симптом | Решение |
| :--- | :--- | :--- |
| **Сервер выключен** | Нет ответа на SYN | Включить сервер |
| **Фаервол (DROP)** | Нет ответа (игнор) | Изменить правило на REJECT |
| **Маршрут отсутствует** | Нет пути до хоста | Проверить routing table |
| **NAT не настроен** | Порт не проброшен | Настроить port forwarding |

**Диагностика:**

```bash
# Наблюдение SYN-ретрансмиссий
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0'

# Проверка параметра SYN-ретрансмиссий
sysctl net.ipv4.tcp_syn_retries

# Трассировка до хоста
traceroute -T -p 80 target.host
```

**Подробнее о диагностике:** [SYN timeout](./tcp_connection_diagnostics.md#сценарий-5-диагностика-тайм-аутов-syn)
