# Передача данных в TCP

## Определения

**Передача данных в TCP** — это процесс обмена информацией между двумя узлами после успешного установления соединения ([Handshake](./tcp_connection_overview.md)). В отличие от протоколов, ориентированных на сообщения, TCP предоставляет сервис **надежной передачи потока байт (reliable byte stream)**.

---

## Основные концепции

### Модель потока байт (Byte Stream)

TCP рассматривает данные не как набор отдельных пакетов или сообщений, а как непрерывную последовательность байт.

- **Абстракция:** приложение записывает байты в сокет отправителя, а приложение-получатель считывает их из своего сокета.
- **Сегментация:** TCP самостоятельно определяет, какой объем данных поместить в один сегмент, исходя из параметров [MSS](../Header_Format/index.md#mss-maximum-segment-size) и текущего окна перегрузки ([cwnd](../congestion/tcp_congestion_control_overview.md)).
- **Сохранение границ:** TCP **не сохраняет** границы сообщений прикладного уровня. Если приложение отправило два сообщения по 100 байт, получатель может считать их как одно сообщение в 200 байт или как четыре по 50 байт.

### Механизмы нумерации и подтверждения

Для обеспечения надежности в потоке байт используются два ключевых поля заголовка:

1. **Sequence Number (порядковый номер):** номер первого байта данных в данном сегменте в рамках общего потока. Позволяет получателю восстановить правильный порядок байт и обнаруживать дубликаты.
   - *Подробнее:* [Sequence Numbers в TCP](../reliability_mechanisms/sequence_numbers.md).
2. **Acknowledgment Number (номер подтверждения):** номер следующего байта, который отправитель ACK ожидает получить. Используется кумулятивная схема подтверждения.
   - *Подробнее:* [Acknowledgments (ACK) в TCP](../reliability_mechanisms/acknowledgments.md).

### Флаг PSH (Push)

Флаг **PSH** используется для управления буферизацией данных на стороне отправителя и получателя.

- **Назначение:** указывает стеку TCP на необходимость немедленной передачи накопленных в буфере данных приложению-получателю, не дожидаясь заполнения сегмента или буфера.
- **Без PSH:** стек TCP может буферизовать мелкие порции данных для повышения эффективности сети (отправка одного большого сегмента вместо множества мелких).
- **С PSH:** данные немедленно «выталкиваются» из буфера отправителя и по прибытии немедленно передаются приложению получателя.
- **Типичное использование:**
  - Интерактивный трафик (SSH, Telnet), где каждое нажатие клавиши должно передаваться мгновенно.
  - Конец HTTP-запроса или ответа, когда отправитель знает, что данных больше не будет и их нужно обработать сейчас.

## Практические сценарии

### Сценарий 1: Передача данных с подтверждением

Пример передачи 2800 байт данных тремя сегментами:

```text
Отправитель (Client)                 Получатель (Server)
     |                                    |
     |  Пакет 1: seq=1001, 1000 байт ---> |  Приняты байты 1001–2000
     |  <---------------- ACK=2001 -------|  Жду байт 2001
     |                                    |
     |  Пакет 2: seq=2001, 800 байт ----> |  Приняты байты 2001–2800
     |  <---------------- ACK=2801 -------|  Жду байт 2801
     |                                    |
     |  Пакет 3: seq=2801, 1000 байт ---> |  Приняты байты 2801–3800
     |  <---------------- ACK=3801 -------|  Все данные подтверждены
```

### Сценарий 2: Диагностика флага PSH через tcpdump

Для анализа того, как приложение использует буферизацию, можно отфильтровать пакеты с установленным флагом PSH:

```bash
# Перехват только пакетов с установленным флагом PSH
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-push != 0'
```

**Интерпретация результатов:**

- Большое количество мелких PSH-пакетов свидетельствует об интерактивном режиме работы приложения.
- Один PSH-пакет в конце длинной последовательности сегментов без PSH указывает на эффективную пакетную передачу большого объема данных.
