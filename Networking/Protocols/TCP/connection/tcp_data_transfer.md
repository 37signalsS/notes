# Передача данных в TCP

## Definitions

**Передача данных в TCP** — процесс обмена информацией между двумя узлами после установления соединения. TCP передаёт не отдельные сообщения, а **непрерывный поток байт (byte stream)**, гарантируя доставку, порядок и целостность.

---

## Basic Concepts

### Модель byte stream

TCP работает с потоком байт, а не с датаграммами:

- Отправитель записывает байты в сокет, получатель читает поток
- TCP самостоятельно решает, сколько данных поместить в один сегмент
- Получатель собирает байты в правильном порядке благодаря [Sequence Numbers](../reliability_mechanisms/sequence_numbers.md)

```
Приложение отправляет: "HELLO" (5 байт) + "WORLD" (5 байт)
TCP может отправить:
  Вариант 1: один сегмент 10 байт
  Вариант 2: два сегмента по 5 байт
  Вариант 3: пять сегментов по 2 байта
```

**Результат:** получатель всегда получит те же 10 байт в том же порядке.

### Sequence Number (32 бита)

- Номер **первого байта данных** в сегменте
- Позволяет получателю восстановить порядок байт
- Защищает от дубликатов и переставленных пакетов

### Acknowledgment Number (32 бита)

- Номер **следующего ожидаемого байта**
- Действует только при флаге `ACK=1`
- **Кумулятивное подтверждение:** подтверждает все байты до указанного номера

### Флаг PSH (Push)

- **Назначение:** указание получателю на немедленную доставку данных приложению
- **Без PSH:** данные могут буферизоваться до заполнения буфера
- **С PSH:** немедленная передача приложению без ожидания
- **Применение:** интерактивные данные (SSH, терминал), конец HTTP-запроса

## Practical Scenarios

### Сценарий 1: Передача 2800 байт с подтверждениями

```
Отправитель                         Получатель
     |                                    |
     |  Пакет 1: seq=0, 1000 байт ------> |  Байты 0–999
     |  <---------------- ACK=1000 -------|  Ожидается байт 1000
     |                                    |
     |  Пакет 2: seq=1000, 800 байт ----> |  Байты 1000–1799
     |  <---------------- ACK=1800 -------|  Ожидается байт 1800
     |                                    |
     |  Пакет 3: seq=1800, 1000 байт ---> |  Байты 1800–2799
     |  <---------------- ACK=2800 -------|  Все данные получены
```

**Механизм:** отправитель увеличивает `seq` на количество отправленных байт, получатель отвечает `ACK` с номером следующего ожидаемого байта.

**Подробнее:** [Sequence Numbers](../reliability_mechanisms/sequence_numbers.md), [Acknowledgments](../reliability_mechanisms/acknowledgments.md)

---

### Сценарий 2: Диагностика PSH через tcpdump

```bash
# Перехват PSH-пакетов
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-push != 0'
```

**Интерпретация:**

- Много PSH-пакетов с малыми данными → интерактивный трафик (SSH, telnet)
- PSH в конце HTTP-ответа → сервер завершил передачу ответа
- Отсутствие PSH при буферизации → нормальное поведение TCP
