# Передача данных в TCP

## Определения

**Передача данных в TCP** — это процесс обмена информацией между двумя узлами после успешного установления соединения ([Handshake](./tcp_connection_overview.md)). В отличие от протоколов, ориентированных на сообщения, TCP предоставляет сервис **надежной передачи потока байт (reliable byte stream)**.

---

## Основные концепции

### Модель потока байт (Byte Stream)

TCP рассматривает данные не как набор отдельных пакетов, а как непрерывную последовательность байт.

- **Абстракция:** Приложение записывает байты в сокет отправителя, а приложение-получатель считывает их из своего сокета.
- **Сегментация:** TCP самостоятельно определяет, какой объем данных поместить в один сегмент, исходя из параметров [MSS](../Header_Format/index.md) и текущего окна перегрузки ([cwnd](../congestion/tcp_congestion_control_overview.md)).
- **Сохранение границ:** TCP **не сохраняет** границы сообщений прикладного уровня (проблема «склеивания» пакетов). Приложение должно самостоятельно реализовывать протоколы разграничения (например, через длину сообщения или разделители).

### Механизмы нумерации и подтверждения

Для обеспечения надежности используются два ключевых поля:

1.  **Sequence Number (Порядковый номер):** Номер первого байта данных в сегменте. Позволяет восстановить порядок и обнаружить дубликаты.
    *   *Подробнее:* [Sequence Numbers в TCP](../reliability_mechanisms/sequence_numbers.md).
2.  **Acknowledgment Number (Номер подтверждения):** Номер следующего байта, который отправитель ACK ожидает получить.
    *   *Подробнее:* [Acknowledgments (ACK) в TCP](../reliability_mechanisms/acknowledgments.md).

### Ускорение передачи: Оффлоадинг (2026)

Для снижения нагрузки на CPU современные системы используют механизмы аппаратного ускорения (Offloading):

-   **TSO (TCP Segmentation Offload):** ОС передает сетевой карте (NIC) один большой блок данных, а NIC сама нарезает его на сегменты MSS.
-   **GRO (Generic Receive Offload):** NIC или драйвер «склеивает» входящие мелкие сегменты одного потока в один большой буфер перед передачей в стек ядра.
-   **Zero Copy (`sendfile`, `splice`):** Передача данных из файла напрямую в сетевой буфер без копирования в пространство пользователя.

## Управление задержками и эффективностью

### Алгоритм Нейгла (Nagle's Algorithm)

**Цель:** Предотвращение засорения сети мелкими пакетами («Small Packet Problem»).

-   **Логика:** Отправитель копит мелкие данные в буфере до тех пор, пока не наберется полный сегмент (MSS) или пока не придет ACK на все ранее отправленные данные.
-   **Проблема:** В сочетании с **Delayed ACK** на стороне получателя это может вызвать задержку до 200–500 мс.
-   **Решение:** Опция сокета `TCP_NODELAY` (отключает алгоритм для интерактивных приложений).

### Флаг PSH (Push)

-   **Назначение:** Указывает стеку на необходимость немедленной передачи данных приложению, не дожидаясь заполнения буферов.
-   **Применение:** Интерактивные сессии (SSH), завершение HTTP-ответов.

## Практические сценарии

### Сценарий 1: Передача данных с подтверждением

Пример передачи 2800 байт данных:

```text
Отправитель (Client)                 Получатель (Server)
     |                                    |
     |  Пакет 1: seq=1001, 1000 байт ---> |  Приняты байты 1001–2000
     |  <---------------- ACK=2001 -------|  Жду байт 2001
     |                                    |
     |  Пакет 2: seq=2001, 800 байт ----> |  Приняты байты 2001–2800
     |  <---------------- ACK=2801 -------|  Жду байт 2801
```

### Сценарий 2: Диагностика сегментации через tcpdump

Для анализа размера сегментов и флагов:

```bash
# Перехват пакетов с просмотром длины данных (length) и флага PSH
sudo tcpdump -i eth0 -nn 'tcp port 80'
# → 10:00:01 IP 1.1.1.1.443 > 2.2.2.2.54321: Flags [P.], seq 1001:2001, ack 1, win 501, length 1000
```

**Интерпретация:**
- `Flags [P.]`: Установлен флаг PSH (P) и ACK (.).
- `length 1000`: Размер полезной нагрузки в данном сегменте.
