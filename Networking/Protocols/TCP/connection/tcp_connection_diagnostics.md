# Диагностика TCP-соединений

## 1. Диагностика состояний через ss

```bash
# Все TCP-соединения с состояниями
ss -tan

# Состояния с процессами
ss -tanp

# Подсчёт по состояниям
ss -tan | awk 'NR>1 {print $1}' | sort | uniq -c

# Пример вывода:
#   1500 ESTAB
#     50 TIME-WAIT
#     10 CLOSE-WAIT
#      5 SYN-RECV
```

---

## 2. Анализ handshake через tcpdump

```bash
# Перехват TCP-handshake
tcpdump -i eth0 -nn 'tcp port 80' -v

# Пример вывода handshake:
# 10:15:30.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890
# 10:15:30.130000 IP 93.184.216.34.80 > 192.168.1.10.54321: Flags [S.], seq 987654321, ack 1234567891
# 10:15:30.135000 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [.], ack 987654322
```

**Обозначения флагов:**

- `[S]` — SYN
- `[S.]` — SYN-ACK
- `[.]` — ACK
- `[F.]` — FIN-ACK
- `[R]` — RST

## 3. TIME_WAIT на клиенте vs сервере

| Сценарий | Кто в TIME_WAIT | Почему |
| :--- | :--- | :--- |
| **Браузер загружает страницу** | Клиент | Клиент инициирует закрытие |
| **HTTP-сервер отдаёт файл** | Сервер (при active close) | Сервер закрывает после отдачи |
| **Keep-alive соединения** | Реже | Соединение переиспользуется |

**Оптимизация для клиентских соединений:**

```bash
# Для исходящих соединений (клиенты)
sysctl -w net.ipv4.tcp_tw_reuse=1
```

**Подробнее:** [Оптимизация TCP в Linux](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_congestion_algorithms.md).

## 4. Диагностика RST (Reset)

**Сценарий:** порт закрыт или соединение отклонено

```bash
# Перехват RST-пакетов
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-rst != 0'

# Пример вывода:
# 10:15:30.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [R], seq 1234567890
```

**Проверка закрытых портов:**

```bash
# nmap покажет закрытые порты (ответ RST)
nmap -p 80,443,5555 target.host

# Пример вывода:
# 80/tcp   open   http
# 443/tcp  open   https
# 5555/tcp closed unknown  (RST received)
```

**Причины RST:**

| Причина | Симптом | Решение |
| :--- | :--- | :--- |
| **Порт не слушается** | RST на SYN | Запустить приложение |
| **Приложение упало** | RST на данные | Перезапустить сервис |
| **Фаервол (REJECT)** | RST сразу | Проверить правила firewall |
| **Соединение устарело** | RST после простоя | Увеличить тайм-ауты |

## 5. Диагностика тайм-аутов SYN

**Сценарий:** сервер не отвечает (фаервол DROP, хост выключен)

```bash
# Перехват SYN-ретрансмиссий
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0' and not 'tcp[tcpflags] & tcp-ack != 0'

# Пример вывода (клиент отправляет SYN повторно):
# 10:15:30.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890
# 10:15:31.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890  (retry #1)
# 10:15:33.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890  (retry #2)
# 10:15:37.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890  (retry #3)
```

**Проверка параметров:**

```bash
# Текущее значение SYN-ретрансмиссий
sysctl net.ipv4.tcp_syn_retries

# Трассировка до хоста (проверка маршрута)
traceroute -T -p 80 target.host

# Проверка доступности порта (с тайм-аутом)
timeout 10 bash -c 'cat < /dev/null > /dev/tcp/target.host/80' 2>&1
```

**Время ожидания:**

- **Попыток:** 4 (по умолчанию)
- **Общее время:** ~7 секунд (1+2+4)
- **Настройка:** `net.ipv4.tcp_syn_retries`

**Причины тайм-аутов:**

| Причина | Симптом | Решение |
| :--- | :--- | :--- |
| **Сервер выключен** | Нет ответа на SYN | Включить сервер |
| **Фаервол (DROP)** | Нет ответа (игнор) | Изменить правило на REJECT |
| **Маршрут отсутствует** | Нет пути до хоста | Проверить routing table |
| **NAT не настроен** | Порт не проброшен | Настроить port forwarding |

**RST vs DROP (фаервол):**

| Реакция | Поведение | Время ошибки | Команда |
| :--- | :--- | :--- | :--- |
| **REJECT** | Мгновенный RST | ~0 мс | `iptables -j REJECT` |
| **DROP** | Нет ответа | ~7 сек | `iptables -j DROP` |
