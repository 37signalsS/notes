# Диагностика TCP-соединений

## Definitions

**Диагностика TCP-соединений** — набор методов анализа состояния TCP-сокетов и сетевого трафика для выявления проблем соединения, потери пакетов и ошибок конфигурации.

**Инструменты:**

- `ss` — анализ состояния сокетов (быстрая замена `netstat`)
- `tcpdump` — перехват и анализ TCP-трафика в реальном времени

---

## Basic Concepts

### TCP-флаги в tcpdump

| Флаг | Значение | Назначение |
| :--- | :--- | :--- |
| `[S]` | SYN | Инициация соединения |
| `[S.]` | SYN-ACK | Подтверждение соединения |
| `[.]` | ACK | Подтверждение данных |
| `[F.]` | FIN-ACK | Корректное завершение |
| `[R]` | RST | Сброс соединения (ошибка/закрытый порт) |
| `[P.]` | PSH-ACK | Принудительная отправка буфера |

### Состояния TCP для диагностики

Критичные состояния при диагностике:

- **ESTAB** — активное соединение
- **TIME-WAIT** — завершение соединения (ожидание 2×MSL)
- **CLOSE-WAIT** — приложение не закрыло сокет (потенциальная утечка)
- **SYN-RECV** — полуоткрытое соединение (возможна SYN-флуд атака)

**Полная таблица состояний:** [Состояния TCP](./tcp_connection_states.md)

## Practical Scenarios

### Сценарий 1: Анализ состояний через ss

```bash
# Все TCP-соединения с состояниями
ss -tan

# Состояния с процессами (владелец сокета)
ss -tanp

# Подсчёт по состояниям
ss -tan | awk 'NR>1 {print $1}' | sort | uniq -c

# Пример вывода:
#   1500 ESTAB
#     50 TIME-WAIT
#     10 CLOSE-WAIT
#      5 SYN-RECV
```

**Интерпретация:**

- Много `CLOSE-WAIT` → приложение не вызывает `close()` (утечка сокетов)
- Много `SYN-RECV` → возможна SYN-флуд атака
- Много `TIME-WAIT` на сервере → рассмотреть `tcp_tw_reuse=1`

**Подробнее о проблемах состояний:** [Состояния TCP — Критичные состояния](./tcp_connection_states.md#критичные-состояния-для-диагностики)

### Сценарий 2: Анализ handshake через tcpdump

```bash
# Перехват TCP-handshake на порту 80
tcpdump -i eth0 -nn 'tcp port 80' -v

# Пример вывода handshake:
# 10:15:30.123456 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890
# 10:15:30.130000 IP 93.184.216.34.80 > 192.168.1.10.54321: Flags [S.], seq 987654321, ack 1234567891
# 10:15:30.135000 IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [.], ack 987654322
```

**Анализ задержек:**

- `SYN → SYN-ACK`: RTT (round-trip time)
- `SYN-ACK → ACK`: время обработки клиентом
- Нет `SYN-ACK` → сервер недоступен или фаервол DROP

**Подробнее об установке соединения:** [Handshake](./tcp_connection_overview.md)

### Сценарий 3: TIME_WAIT на клиенте vs сервере

| Сценарий | Кто в TIME_WAIT | Почему |
| :--- | :--- | :--- |
| **Браузер загружает страницу** | Клиент | Клиент инициирует закрытие |
| **HTTP-сервер отдаёт файл** | Сервер (при active close) | Сервер закрывает после отдачи |
| **Keep-alive соединения** | Реже | Соединение переиспользуется |

**Оптимизация для клиентских соединений:**

```bash
# Разрешить reuse TIME_WAIT-сокетов (для исходящих соединений)
sysctl -w net.ipv4.tcp_tw_reuse=1
```

> **Важно:** `tcp_tw_recycle` удалён в ядре 4.12+ из-за проблем с NAT.

**Подробнее:** [TIME_WAIT в состояниях TCP](./tcp_connection_states.md#2-time_wait-нормальное-состояние)

### Сценарий 4: Диагностика RST (Reset)

RST означает немедленный сброс соединения. Причины: закрытый порт, падение приложения, правила фаервола.

**Перехват RST-пакетов:**

```bash
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-rst != 0'
```

**Проверка закрытых портов:**

```bash
# nmap покажет закрытые порты (ответ RST)
nmap -p 80,443,5555 target.host
```

**Таблица причин RST и решений:**

| Причина | Симптом | Решение |
| :--- | :--- | :--- |
| **Порт не слушается** | RST на SYN | Запустить приложение |
| **Приложение упало** | RST на данные | Перезапустить сервис |
| **Фаервол (REJECT)** | RST сразу | Проверить правила firewall |
| **Соединение устарело** | RST после простоя | Увеличить тайм-ауты |

**Подробнее:** [RST-переходы в состояниях TCP](./tcp_connection_states.md#4-переходы-при-rst-reset), [Отказ в соединении](./tcp_connection_refusal.md#1-закрытый-порт-ответ-rst)

### Сценарий 5: Диагностика тайм-аутов SYN

Ситуация: сервер не отвечает (фаервол DROP, хост выключен, маршрут отсутствует).

**Перехват SYN-ретрансмиссий:**

```bash
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0' and not 'tcp[tcpflags] & tcp-ack != 0'
```

**Проверка параметров:**

```bash
# Текущее значение SYN-ретрансмиссий
sysctl net.ipv4.tcp_syn_retries

# Трассировка до хоста (проверка маршрута)
traceroute -T -p 80 target.host

# Проверка доступности порта (с тайм-аутом)
timeout 10 bash -c 'cat < /dev/null > /dev/tcp/target.host/80' 2>&1
```

**Параметры SYN-ретрансмиссий:**

- **Попыток:** 4 (по умолчанию)
- **Общее время:** ~7 секунд (1+2+4)
- **Настройка:** `net.ipv4.tcp_syn_retries`

**RST vs DROP (фаервол):**

| Реакция | Поведение | Время ошибки | Команда |
| :--- | :--- | :--- | :--- |
| **REJECT** | Мгновенный RST | ~0 мс | `iptables -j REJECT` |
| **DROP** | Нет ответа | ~7 сек | `iptables -j DROP` |

**Таблица причин тайм-аутов:**

| Причина | Симптом | Решение |
| :--- | :--- | :--- |
| **Сервер выключен** | Нет ответа на SYN | Включить сервер |
| **Фаервол (DROP)** | Нет ответа (игнор) | Изменить правило на REJECT |
| **Маршрут отсутствует** | Нет пути до хоста | Проверить routing table |
| **NAT не настроен** | Порт не проброшен | Настроить port forwarding |

**Подробнее:** [Тайм-ауты SYN](./tcp_connection_refusal.md#2-хост-не-отвечает-тайм-ауты-syn)
