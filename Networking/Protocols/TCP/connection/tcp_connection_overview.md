# Управление TCP-соединением

## Определения

**Управление соединением (TCP Connection Management)** — это совокупность механизмов протокола TCP, обеспечивающих надежную установку, поддержание и корректное завершение сеанса связи между двумя узлами.

**Ключевые этапы жизненного цикла соединения:**

- **Handshake (Трехэтапное рукопожатие):** процесс инициализации и согласования параметров.
- **Data Transfer (Передача данных):** активная фаза обмена информацией.
- **Termination (Завершение):** процесс освобождения ресурсов и закрытия потоков данных.

---

## Основные концепции

### Установка соединения: TCP Handshake

Целью трехэтапного рукопожатия является подтверждение доступности обеих сторон, согласование начальных порядковых номеров (ISN) и параметров сессии (MSS, Window Scale).

**Алгоритм процесса:**

```text
   Клиент (Инициатор)                         Сервер (Слушатель)
     |                                            |
     |  SYN (seq=x) ----------------------------> |  LISTEN
     |      (Состояние: SYN_SENT)                 |      ↓
     |                                            |  SYN_RECV
     |  <---------------------------- SYN-ACK ----|
     |           (seq=y, ack=x+1)                 |
     |                                            |
     |  ACK (seq=x+1, ack=y+1) -----------------> |
     |      (Состояние: ESTABLISHED)              |  (Состояние: ESTABLISHED)
```

#### Детальные шаги Handshake

1. **SYN (Synchronize):** Клиент отправляет сегмент с установленным флагом SYN и случайным начальным номером `seq=x`. Состояние клиента переходит в `SYN_SENT`.
2. **SYN-ACK:** Сервер, получив SYN, отвечает сегментом с флагами SYN и ACK. Он подтверждает номер клиента (`ack=x+1`) и предлагает свой начальный номер `seq=y`. Состояние сервера — `SYN_RECV`.
3. **ACK (Acknowledgment):** Клиент подтверждает получение SYN-ACK от сервера, отправляя сегмент с флагом ACK и номером `ack=y+1`. После этого обе стороны переходят в состояние `ESTABLISHED`.

### Почему необходимо 3 этапа?

Использование именно трех шагов решает проблему надежности в ненадежной сети:

- Сервер должен быть уверен, что клиент получил его подтверждение (SYN-ACK).
- Если бы шагов было 2, сервер мог бы выделить ресурсы под соединение, подтверждение которого (SYN-ACK) потерялось, а клиент об этом не узнал бы.
- Третий шаг подтверждает, что канал связи работает в обоих направлениях.

## Практические сценарии

### Сценарий 1: Успешная установка соединения

Приложение вызывает системный вызов `connect()`, что инициирует отправку первого SYN. В случае успеха (прохождения всех 3-х этапов) сокет переходит в состояние `ESTABLISHED`, и приложение может начать передачу данных.

### Сценарий 2: Отказ в соединении

Если порт на сервере закрыт, стек TCP сервера ответит сегментом **RST** (Reset). Если сервер недоступен или пакеты блокируются файрволом с правилом DROP, клиент будет повторять попытки отправки SYN до истечения тайм-аута.
*Подробнее:* [Отказ в установке соединения](./tcp_connection_refusal.md).

### Сценарий 3: Завершение сессии

После обмена данными одна из сторон инициирует закрытие, отправляя сегмент с флагом **FIN**.
*Подробнее:* [Завершение TCP-соединения](./tcp_connection_termination.md).
