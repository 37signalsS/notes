# Установка TCP-соединения (Handshake)

## Определения

**Установка TCP-соединения (3-way Handshake)** — процесс согласования параметров между клиентом и сервером для создания надежного двустороннего канала передачи данных. В ходе этого процесса узлы обмениваются начальными порядковыми номерами (**ISN**) и сетевыми опциями (MSS, SACK, Window Scale).

---

## Основные концепции

### Трехэтапное рукопожатие (3-way Handshake)

```text
Клиент (Active Open)                  Сервер (Passive Open)
     |                                     |
     |  1. SYN (seq=X, Options) ----------> |  Сервер в LISTEN
     |                                     |  Переход в SYN_RECEIVED
     |  2. <---- SYN-ACK (seq=Y, ack=X+1) --|  
     |  Клиент в SYN_SENT                  |
     |                                     |
     |  3. ACK (seq=X+1, ack=Y+1) --------> |
     |  Клиент в ESTABLISHED               |  Сервер в ESTABLISHED
```

1.  **SYN (Synchronize):** Клиент выбирает случайный ISN (`X`) и отправляет запрос. Указываются поддерживаемые опции (MSS, SACK_OK, WS).
2.  **SYN-ACK:** Сервер подтверждает получение SYN (`ack=X+1`), выбирает свой ISN (`Y`) и подтверждает выбранные опции.
3.  **ACK (Acknowledge):** Клиент подтверждает получение SYN сервера (`ack=Y+1`). Соединение установлено.

### Согласование опций (Options Negotiation)

На этапе SYN узлы договариваются о расширенных возможностях протокола:
- **MSS (Maximum Segment Size):** Максимальный размер полезной нагрузки (без заголовков). По умолчанию 1460 для Ethernet.
- **SACK (Selective ACK):** Разрешение подтверждать пакеты выборочно (эффективно при потерях).
- **Window Scale (WS):** Множитель для поля Window Size, позволяющий использовать окна более 64 КБ (критично для сетей с высоким BDP).

### TCP Fast Open (TFO)

**TCP Fast Open (RFC 7413)** — расширение, позволяющее передавать данные прикладного уровня уже в первом пакете SYN (0-RTT), если клиент ранее уже подключался к этому серверу и получил специальный TFO-cookie.
*Подробнее:* [TCP Fast Open в Linux](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_fast_open.md).

## Практические сценарии

### Сценарий 1: Диагностика рукопожатия через tcpdump

Анализ пакетов позволяет увидеть, какие опции были согласованы и нет ли задержек на этапе SYN.

```bash
# Перехват SYN и SYN-ACK пакетов
sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & (tcp-syn) != 0'
# → 12:00:01 IP 1.1.1.1.54321 > 2.2.2.2.80: Flags [S], seq 1000, win 65535, options [mss 1460,sackOK,wscale 7]
# → 12:00:01 IP 2.2.2.2.80 > 1.1.1.1.54321: Flags [S.], seq 2000, ack 1001, win 28960, options [mss 1460,sackOK,wscale 7]
```

**На что смотреть:**
- `Flags [S]`: SYN пакет.
- `Flags [S.]`: SYN-ACK пакет.
- `wscale 7`: Согласован множитель окна $2^7 = 128$.

### Сценарий 2: Проблема с «зависшим» SYN (Backlog)

Если сервер не отвечает на SYN, возможно, переполнена очередь **SYN Backlog**.

```bash
# Проверка статистики сетевого стека на наличие отброшенных SYN
nstat -az TcpExtListenDrops
# → TcpExtListenDrops                50                 0.0
```
*Решение:* Увеличение `net.ipv4.tcp_max_syn_backlog` в `sysctl`.
