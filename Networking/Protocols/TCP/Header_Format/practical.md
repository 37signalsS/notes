# Практика анализа заголовка TCP

## Определения

**Практический анализ заголовка TCP** — процесс исследования полей сегмента в реальном времени или в дампах трафика для диагностики проблем производительности, проверки настроек стека ОС и выявления сетевых аномалий.

**Инструментарий:**
- **tcpdump / Wireshark:** Захват и визуализация каждого бита заголовка.
- **ss (Socket Statistics):** Просмотр параметров, согласованных ядром (RTT, cwnd, wscale).
- **eBPF (bcc-tools):** Мониторинг жизненного цикла соединений без захвата трафика.

---

## Основные концепции

### Обозначение флагов в tcpdump

В выводе `tcpdump` флаги отображаются сокращенно:
- `[S]` — SYN (Установка).
- `[P]` — PUSH (Передача данных).
- `[.]` — ACK (Подтверждение).
- `[F]` — FIN (Завершение).
- `[R]` — RST (Сброс).

### Интерпретация параметров в ss

Утилита `ss -ti` показывает состояние «с точки зрения ядра»:
- **wscale:7,7:** Согласован множитель окна $2^7$ (128).
- **mss:1448:** Эффективный размер данных (с учетом опций TS).
- **rcv_space:** Текущий размер окна приема, объявленный партнеру.

## Практические сценарии

### Сценарий 1: Исследование рукопожатия (3-way Handshake)

```bash
sudo tcpdump -i any -nn -v 'tcp[tcpflags] & tcp-syn != 0'
# → 12:00:01 IP 1.1.1.1.54321 > 2.2.2.2.80: Flags [S], seq 1000, win 65535, 
# →   options [mss 1460,sackOK,TS val 123 ecr 0,nop,wscale 7]
```
**Анализ:** Если в `options` отсутствует `wscale`, пропускная способность будет ограничена 64 КБ вне зависимости от скорости канала.

### Сценарий 2: Влияние Offloading (TSO/GRO) на захват

При захвате на локальном хосте сегменты могут выглядеть аномально большими (например, 15000 байт при MTU 1500).
- **Причина:** **TSO (TCP Segmentation Offload)**. Ядро передает сетевой карте один большой блок, и `tcpdump` видит его до нарезки на физические пакеты.
- **Решение для точной диагностики:** Временно отключить оффлоадинг.
```bash
sudo ethtool -K eth0 tso off gro off
```

### Сценарий 3: Диагностика сбросов (RST) в реальном времени

```bash
sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-rst != 0'
# → 12:05:00 IP 1.2.3.4.80 > 5.6.7.8.4321: Flags [R.], seq 0, ack 1001, win 0
```
- Если приходит сразу после SYN — порт закрыт или заблокирован (REJECT).
- Если посреди сессии — аварийное завершение процесса.

### Сценарий 4: Анализ через eBPF (2026)

Для анализа без накладных расходов на копирование пакетов (как в tcpdump):
```bash
# Отслеживание переходов состояний FSM
sudo tcpstates
# → SKADDR           C-PID LAT(ms) OLDSTATE    -> NEWSTATE
# → ffff9...         1234  0.12    SYN_SENT    -> ESTABLISHED
```
