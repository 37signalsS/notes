# Практика анализа заголовка TCP

## Определения

**Практический анализ заголовка TCP** — это процесс исследования полей и параметров сегмента TCP в реальном времени или в дампах трафика с целью диагностики сетевых проблем, проверки корректности настройки стека ОС и выявления аномалий в поведении приложений.

**Основные инструменты:**
- **tcpdump / Wireshark:** для захвата и визуализации полей каждого сегмента.
- **ss (Socket Statistics):** для просмотра согласованных параметров заголовка активных соединений.

---

## Основные концепции

### Обозначение флагов в tcpdump
При захвате трафика утилита `tcpdump` использует сокращенные обозначения флагов, находящихся в 14-м байте заголовка:

| Обозначение | Флаг TCP | Описание |
| :--- | :--- | :--- |
| **[S]** | SYN | Попытка установить соединение. |
| **[S.]** | SYN-ACK | Подтверждение SYN от другой стороны. |
| **[.]** | ACK | Подтверждение получения данных (порядкового номера). |
| **[P]** | PSH | Флаг немедленной передачи данных приложению. |
| **[F]** | FIN | Запрос на корректное завершение соединения. |
| **[R]** | RST | Сброс соединения (ошибка или закрытый порт). |

### Отображение параметров в ss
Утилита `ss` выводит данные из управляющих структур ядра, соответствующих заголовку TCP:
- **ts:** (timestamps) метки времени включены.
- **sack:** (selective ack) поддержка SACK согласована.
- **wscale:7,7:** (window scale) множители окна для обеих сторон.
- **mss:1460:** максимальный размер данных, согласованный при handshake.

## Практические сценарии

### Сценарий 1: Исследование SYN-пакета (Handshake)
Команда для захвата первого этапа соединения:
```bash
tcpdump -i any -nn -v 'tcp[tcpflags] & tcp-syn != 0'
```
**На что обратить внимание в выводе:**
- `options [mss 1460,sackOK,TS val 12345 ecr 0,nop,wscale 7]` — здесь видны все предложенные опции. Если `wscale` отсутствует, скорость на длинных дистанциях будет ограничена.
- `win 65535` — начальное значение окна до применения масштабирования.

### Сценарий 2: Диагностика сбросов соединения (RST)
Если соединение обрывается внезапно, ищите флаг RST:
```bash
tcpdump -i any -nn 'tcp[tcpflags] & tcp-rst != 0'
```
**Интерпретация:**
- Если RST приходит в ответ на SYN — порт на сервере закрыт.
- Если RST приходит посреди ESTABLISHED сессии — приложение на одной из сторон аварийно завершилось.

### Сценарий 3: Проверка Window Scaling в реальных условиях
Если вы подозреваете, что пропускная способность ограничена окном:
```bash
ss -tno state established
```
Найдите ваше соединение и проверьте значение `wscale`. Если оно равно `0` или отсутствует, это подтверждает теорию об ограничении пропускной способности размером стандартного окна 64 КБ.

### Примечания по Wireshark
Для глубокого анализа рекомендуется использовать графический анализатор Wireshark. Он автоматически вычисляет "Relative Sequence Numbers" (начиная с 0 для удобства) и подсвечивает ошибки в заголовках (например, Checksum Error).
