# Практика анализа заголовка TCP

## Определения

**Практический анализ заголовка TCP** — процесс исследования управляющих полей сегмента в реальном времени или в сохраненных дампах (pcap). Целью анализа является диагностика сетевых задержек, проверка корректности работы алгоритмов управления потоком и выявление аномалий (например, некорректных контрольных сумм или флагов).

**Инструментарий:**
- **tcpdump / tshark:** Захват и разбор трафика в CLI.
- **Wireshark:** Графический анализ с глубокой инспекцией и экспертной системой.
- **ss (Socket Statistics):** Доступ к внутренним счетчикам ядра (структура `tcp_info`).
- **eBPF (bcc-tools / bpftrace):** Низкоуровневая трассировка событий стека TCP без накладных расходов на копирование пакетов.

## Базовые концепции

### Интерпретация флагов в tcpdump

Утилита `tcpdump` использует сокращенную нотацию для отображения флагов заголовка:
- `[S]` — **SYN:** Установка соединения.
- `[.]` — **ACK:** Подтверждение получения.
- `[P]` — **PSH:** Запрос на передачу данных приложению.
- `[F]` — **FIN:** Завершение соединения.
- `[R]` — **RST:** Сброс соединения (Reset).
- `[E]` — **ECE:** Уведомление о перегрузке (ECN-Echo).
- `[W]` — **CWR:** Подтверждение уменьшения окна перегрузки.

### Ключевые метрики в ss -ti

Вывод `ss` предоставляет данные напрямую из сетевого стека ядра:
- **rtt:** Время кругового обхода в мс.
- **ato:** Тайм-аут подтверждения (Acknowledgment Timeout).
- **mss:** Согласованный максимальный размер сегмента.
- **wscale:** Множитель масштабирования окна (Window Scale).
- **retrans:** Количество текущих ретрансмиссий в сессии.

## Практические сценарии

### Сценарий 1: Анализ процесса установки соединения (Handshake)

Проверка согласования опций (MSS, SACK, WS) позволяет выявить причины низкой производительности.

```bash
sudo tcpdump -i any -nn -v 'tcp[tcpflags] & tcp-syn != 0'
# → 12:00:01 IP 1.1.1.1.54321 > 2.2.2.2.80: Flags [S], seq 1024, win 65535, options [mss 1460,sackOK,wscale 7]
# → 12:00:01 IP 2.2.2.2.80 > 1.1.1.1.54321: Flags [S.], seq 4096, ack 1025, win 28960, options [mss 1460,sackOK,wscale 7]
```
**Анализ:** Если одна из сторон не вернула `wscale`, максимальная скорость передачи будет ограничена ~5 Мбит/с при задержке 100 мс.

### Сценарий 2: Фильтрация по битовым маскам (ECN)

Для обнаружения сигналов перегрузки сети можно использовать фильтры по смещениям в байтах.

```bash
# Поиск пакетов с установленным флагом ECE (бит 6 в байте флагов)
sudo tcpdump -i eth0 'tcp[13] & 64 != 0'
# → 12:10:05 IP 8.8.8.8.443 > 192.168.1.10.54321: Flags [.E], ack 100, win 501
```
# → Результат: Флаг `E` указывает, что промежуточный маршрутизатор пометил пакет как Congestion Experienced (CE).

### Сценарий 3: Влияние Offloading (TSO/GRO)

На отправляющем хосте пакеты в дампе могут выглядеть больше 64 КБ, что невозможно в физической сети.

- **Причина:** **TSO (TCP Segmentation Offload)**. Ядро передает сетевой карте один большой блок данных, а нарезка на сегменты MSS происходит аппаратно.
- **Решение для диагностики:** Временно отключите оффлоадинг, чтобы увидеть реальные заголовки:
```bash
sudo ethtool -K eth0 tso off gro off
# → Actual changes: tso: off, gro: off
```

### Сценарий 4: Трассировка сбросов и потерь через eBPF

Инструменты eBPF позволяют увидеть *почему* ядро отбросило пакет или отправило RST.

```bash
# Отслеживание ретрансмиссий в реальном времени
sudo tcpretrans
# → TIME     LADDR:LPORT          RADDR:RPORT          STATE
# → 12:15:01 192.168.1.10:54321   8.8.8.8:443          ESTABLISHED

# Отслеживание пакетов, отброшенных ядром (например, из-за Checksum Error)
sudo tcpdrop
# → TIME     PID    COMM       IP SADDR:SPORT       > DADDR:DPORT   STATE
```

## Дополнительная информация

### Визуальный анализ в Wireshark

Для глубокого анализа заголовков в Wireshark рекомендуется:
1.  **Expert Information:** Меню `Analyze -> Expert Info`. Подсвечивает аномалии: `Out-of-Order`, `Previous segment not captured`, `Dup ACK`.
2.  **TCP Stream Graph:** Меню `Statistics -> TCP Stream Graphs -> Time-Sequence (Stevens)`. Позволяет визуализировать динамику порядковых номеров и окна перегрузки.
