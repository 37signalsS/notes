# Опции TCP и ECN

## Определения

**Опции TCP (TCP Options)** — это дополнительные поля переменной длины в заголовке сегмента, предназначенные для расширения базового функционала протокола. Они позволяют согласовывать параметры производительности, улучшать механизмы надежности и точно измерять задержки.

**ECN (Explicit Congestion Notification)** — механизм явного уведомления о перегрузке сетевых узлов без необходимости отбрасывания пакетов, реализуемый через флаги в заголовке TCP и поле в заголовке IP.

---

## Основные концепции

### Структура опции
Каждая опция состоит из трех полей (за исключением NOP и End of List):
1. **Kind (1 байт):** уникальный идентификатор типа опции.
2. **Length (1 байт):** общая длина опции в байтах (включая поля Kind и Length).
3. **Value (переменная длина):** данные опции.

### Распространенные опции TCP

#### Максимальный размер сегмента (MSS)
Указывает максимальный объем полезной нагрузки (payload), который узел готов принять в одном сегменте.
- **Kind:** 2 | **Длина:** 4 байта.
- **Особенности:** передается только в SYN-пакетах.
- *Подробнее:* [Оптимизация буферов TCP](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_buffer_tuning.md).

#### Масштабирование окна (Window Scale)
Позволяет увеличить размер окна приема свыше стандартных 64 КБ путем умножения значения в заголовке на $2^n$.
- **Kind:** 3 | **Длина:** 3 байта.
- **Диапазон:** $n$ от 0 до 14 (макс. окно ~1 ГБ).
- **Особенности:** согласуется только во время рукопожатия (3-way handshake).

#### Выборочное подтверждение (SACK)
Позволяет получателю подтверждать блоки данных, полученные "за дырами" в последовательности, минимизируя лишние ретрансмиссии.
- **SACK-Permitted (Kind 4):** отправляется в SYN для подтверждения поддержки.
- **SACK-Data (Kind 5):** содержит границы (Left/Right edge) полученных блоков.
- *Подробнее:* [Диагностика надежности TCP](../reliability_mechanisms/diagnostics.md).

#### Метки времени (Timestamps)
Используются для защиты от наложения номеров последовательностей в высокоскоростных сетях (PAWS) и точного измерения RTT.
- **Kind:** 8 | **Длина:** 10 байт.

### Современные и расширенные опции (2026)

#### TCP Fast Open (TFO)
Позволяет передавать данные прикладного уровня уже в первом пакете SYN, сокращая задержку на 1 RTT.
- **Kind:** 34 | **Длина:** переменная (содержит Cookie).
- *Подробнее:* [TCP Fast Open в Linux](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_fast_open.md).

#### Multipath TCP (MPTCP)
Позволяет одному логическому соединению использовать несколько сетевых путей (например, Wi-Fi и LTE одновременно).
- **Kind:** 30 | **Длина:** переменная.

#### User Timeout (Тайм-аут пользователя)
Указывает, как долго TCP должен пытаться передать данные при отсутствии подтверждений перед принудительным закрытием.
- **Kind:** 28 | **Длина:** 4 байта.

## Практические сценарии

### Сценарий 1: Расчет MSS для Ethernet
Стандартный расчет при MTU 1500 байт:
```text
MSS = MTU - IPv4 Header (20) - TCP Header (20) = 1460 байт.
```
Если используются Timestamps (-12 байт с учетом выравнивания), эффективный MSS составит **1448 байт**.

### Сценарий 2: Проверка Window Scale в Linux
Если пропускная способность "упирается" в потолок на каналах с высоким RTT:
```bash
ss -ti dst 1.2.3.4
# → cubic rto:204 rtt:150/0.5 cwnd:10 wscale:7,7
```
**Интерпретация:** `wscale:7,7` означает множитель 128 ($2^7$) для обеих сторон. Если поле отсутствует, скорость будет ограничена ~5-10 Мбит/с при RTT 150мс.

### Сценарий 3: Активация ECN
Для улучшения работы на нестабильных каналах (требует поддержки на маршрутизаторах):
```bash
# Включение ECN в Linux (1 - активно, 2 - только если запрошено)
sudo sysctl -w net.ipv4.tcp_ecn=1
# → net.ipv4.tcp_ecn = 1
```

## Механизм ECN и L4S

ECN (Explicit Congestion Notification) использует 2 бита в поле Traffic Class (IP) и флаги в TCP:

1. **ECT/CE (IP):** Маршрутизатор помечает пакет как "испытавший перегрузку" (Congestion Experienced).
2. **ECE (TCP Flag):** Получатель уведомляет отправителя о пометке CE.
3. **CWR (TCP Flag):** Отправитель подтверждает снижение окна перегрузки.

**L4S (Low Latency, Low Loss, Scalable):** современная эволюция ECN (RFC 9330), позволяющая поддерживать ультра-низкие задержки в очередях за счет более частого и точного уведомления о микро-перегрузках.
