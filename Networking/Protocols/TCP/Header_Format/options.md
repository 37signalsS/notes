# Опции TCP и ECN

## Определения

**Опции TCP (TCP Options)** — дополнительные поля переменной длины, расположенные в конце заголовка TCP (после поля Urgent Pointer). Они расширяют базовый протокол, позволяя согласовывать параметры производительности, улучшать надежность (SACK) и обеспечивать работу в современных высокоскоростных сетях.

**ECN (Explicit Congestion Notification)** — механизм явного уведомления о перегрузке, позволяющий промежуточным узлам (маршрутизаторам) сообщать конечным точкам о возникновении очередей без отбрасывания пакетов.

## Базовые концепции

### Структура и выравнивание
Заголовок TCP должен быть выровнен по 32-битной границе. Если опции не заполняют это пространство полностью, используется забивка (padding).

**Формат опции (TLV - Type-Length-Value):**
1. **Kind (1 байт):** Тип опции.
2. **Length (1 байт):** Общая длина в байтах (включая Kind и Length).
3. **Value (переменная длина):** Данные.

**Служебные опции (без Length и Value):**
- **EOL (End of Option List, Kind 0):** Указывает на конец списка опций.
- **NOP (No Operation, Kind 1):** Используется для выравнивания последующих опций по 32-битной границе.

### Основные опции TCP (RFC 9293)

#### Максимальный размер сегмента (MSS)
Указывает максимальный объем данных (payload), который хост готов принять в одном сегменте.
- **Kind:** 2 | **Длина:** 4 байта.
- **Применение:** Передается **только** в SYN-пакетах.
- *Подробнее:* [Связь MTU и MSS](../../../OSI_TCP_IP_Model/transport_layer.md).

#### Масштабирование окна (Window Scale / WSCALE)
Позволяет использовать окна приема более 64 КБ (до 1 ГБ).
- **Kind:** 3 | **Длина:** 3 байта.
- **Механизм:** Значение в заголовке TCP умножается на $2^{wscale}$. Согласуется только при установке соединения.

#### Выборочное подтверждение (SACK)
Позволяет подтверждать получение отдельных блоков данных при наличии потерь.
- **SACK Permitted (Kind 4):** Отправляется в SYN для подтверждения поддержки механизма.
- **SACK Data (Kind 5):** Содержит пары 32-битных чисел (Left Edge, Right Edge) для каждого подтвержденного блока.
- *Подробнее:* [Диагностика надежности TCP](../reliability_mechanisms/diagnostics.md).

#### Метки времени (Timestamps / TS)
- **Kind:** 8 | **Длина:** 10 байт.
- **Функции:** Точное измерение RTT и защита от наложения номеров последовательностей (**PAWS**).

### Современные расширения (2026)

#### TCP Fast Open (TFO)
Позволяет отправлять данные в первом SYN-пакете.
- **Kind:** 34 | **Длина:** Переменная (6–18 байт для Cookie).
- *Подробнее:* [TCP Fast Open в Linux](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_fast_open.md).

#### Multipath TCP (MPTCP)
Агрегация нескольких интерфейсов (Wi-Fi + 5G) в одно логическое соединение.
- **Kind:** 30 | **Длина:** Переменная.

## Механизм ECN и L4S

ECN требует поддержки на сетевом (IP) и транспортном (TCP) уровнях.

### Взаимодействие уровней (L3 ↔ L4)
1. **IP Header (Field: Traffic Class/DS):** Использует последние 2 бита:
   - `00`: Не поддерживает ECN (Non ECN-Capable).
   - `10` / `01`: Поддерживает ECN (ECT(0) / ECT(1)).
   - `11`: Обнаружена перегрузка (**CE** — Congestion Experienced).
2. **TCP Header (Flags):**
   - **ECE (ECN-Echo):** Получатель сегмента с IP-битами `11` устанавливает этот флаг в подтверждении, чтобы уведомить отправителя.
   - **CWR (Congestion Window Reduced):** Отправитель устанавливает этот флаг после уменьшения `cwnd`, подтверждая получение уведомления.

### L4S (Low Latency, Low Loss, Scalable)
Современный стандарт (**RFC 9330**), использующий кодирование ECT(1) для сигнализации о микро-перегрузках. Позволяет алгоритмам (например, BBRv3 или Prague) поддерживать сверхнизкие задержки без потери пропускной способности.

## Практические сценарии

### Сценарий 1: Расчет эффективного MSS
При стандартном MTU 1500 байт на Ethernet:
```text
Базовый MSS = 1500 (MTU) - 20 (IP) - 20 (TCP) = 1460 байт.
```
Если в заголовке присутствуют Timestamps (10 байт + 2 байта NOP для выравнивания):
```text
Эффективный MSS = 1460 - 12 = 1448 байт.
```

### Сценарий 2: Диагностика согласованных опций через ss
Проверка множителя окна и поддержки ECN в активной сессии:
```bash
ss -ti dst 8.8.8.8
# → cubic rto:204 rtt:15.2/0.5 cwnd:10 wscale:7,7 ecn
```
- **wscale:7,7:** Обе стороны используют множитель 128 ($2^7$).
- **ecn:** Соединение успешно согласовало использование Explicit Congestion Notification.

### Сценарий 3: Проверка TFO Cookie
Проверка, использует ли клиент технологию Fast Open:
```bash
sudo tcpdump -i eth0 -nn -v 'tcp[tcpflags] & tcp-syn != 0'
# → ... options [mss 1460,sackOK,TS val 123 ecr 0,nop,wscale 7,tfo cookie 0a1b2c3d]
# # → Наличие "tfo cookie" подтверждает поддержку TFO.
```
