# Опции TCP и ECN

## Определения

**Опции TCP (TCP Options)** — это дополнительные поля переменной длины в заголовке сегмента, предназначенные для расширения базового функционала протокола. Они позволяют согласовывать параметры производительности, улучшать механизмы надежности и точно измерять задержки.

**ECN (Explicit Congestion Notification)** — механизм явного уведомления о перегрузке сетевых узлов без необходимости отбрасывания пакетов, реализуемый через флаги в заголовке TCP и поле в заголовке IP.

---

## Основные концепции

### Основные опции TCP

Все опции выравниваются по 32-битной границе с использованием заполняющих (PAD) байтов.

#### Максимальный размер сегмента (MSS)
Указывает максимальный объем данных (в байтах), который узел готов принять в одном сегменте.
- **Kind:** 2 | **Длина:** 4 байта.
- **Особенности:** передается только в SYN-пакетах при установке соединения.
- *Подробнее:* [Оптимизация MSS](../../../../Linux/Networking/Concepts/tcp_tuning/tcp_buffer_tuning.md).

#### Масштабирование окна (Window Scale)
Позволяет увеличить размер окна приема свыше стандартных 64 КБ.
- **Kind:** 3 | **Длина:** 3 байта.
- **Диапазон:** множитель до 2^14.
- **Особенности:** согласовывается во время handshake. Требуется поддержка обеими сторонами.

#### Выборочное подтверждение (SACK)
Позволяет получателю подтверждать отдельные блоки данных, полученные не по порядку, вместо полной ретрансмиссии.
- **Kind (Permitted):** 4 | **Kind (SACK):** 5.
- **Преимущество:** критически важно для эффективной работы в сетях с потерями.

#### Метки времени (Timestamps)
Используются для точного расчета RTT и защиты от старых дубликатов сегментов (PAWS).
- **Kind:** 8 | **Длина:** 10 байт.
- **Поля:** TSval (значение отправителя), TSecr (эхо-ответ).

## Практические сценарии

### Сценарий 1: Расчет MSS для Ethernet
Стандартный расчет при MTU 1500 байт:
```text
MSS = MTU - IPv4 Header (20) - TCP Header (20)
MSS = 1500 - 40 = 1460 байт.
```
Если используются опции (например, Timestamps), фактический объем данных в сегменте уменьшается, так как размер заголовка TCP растет.

### Сценарий 2: Проверка работы SACK в Linux
Чтобы убедиться, что механизм выборочных подтверждений активен:
```bash
# Проверка настройки ядра
sysctl net.ipv4.tcp_sack

# Мониторинг использования SACK в текущих соединениях
ss -ti | grep sack
```

### Сценарий 3: Диагностика Window Scale
Если скорость загрузки не превышает ~5 Мбит/с при высоком RTT, возможно, не согласован Window Scale:
```bash
# Проверка wscale через ss
ss -ti
# Результат: wscale:7,7 ( множитель 128 )
```

## Дополнительная информация

### Механизм ECN
ECN позволяет промежуточным маршрутизаторам помечать пакеты при возникновении очереди вместо их удаления.
1.  **Маршрутизатор:** устанавливает биты CE (Congestion Experienced) в заголовке IP.
2.  **Получатель:** видит метку и отправляет ACK с флагом **ECE** (ECN-Echo).
3.  **Отправитель:** снижает скорость и подтверждает это флагом **CWR** (Congestion Window Reduced).
