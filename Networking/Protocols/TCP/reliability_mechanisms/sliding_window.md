# Скользящее окно в TCP (Sliding Window)

## Определения

**Скользящее окно (Sliding Window)** — фундаментальный механизм TCP, обеспечивающий управление потоком данных. Он позволяет отправителю передавать несколько сегментов подряд, не дожидаясь подтверждения (ACK) для каждого из них. Это критически важно для эффективного использования полосы пропускания, особенно на каналах с высокой задержкой.

**Bandwidth-Delay Product (BDP)** — произведение пропускной способности канала на время задержки (RTT). BDP определяет объем данных, который необходимо держать «в полете», чтобы полностью загрузить канал. Если размер скользящего окна меньше BDP, канал будет простаивать.

## Основные концепции

### Структура окна отправителя (Sender Window)
Окно представляет собой буфер байтов, разделенный на логические зоны динамическими указателями:

```text
               ◄────────────── Окно (Window) ──────────────►
               ┌───────────────────────┬───────────────────┐
 подтверждено  │      в полете         │  можно отправить  │  нельзя
 (отброшено)   │ (отправлено, без ACK) │ (в рамках лимита) │ (вне окна)
               └───────────────────────┴───────────────────┘
               ▲                       ▲                   ▲
               │                       │                   │
         LastByteAcked           LastByteSent        LastByteAcked + Win
```

- **Левая граница (Left Edge):** Сдвигается вправо при получении подтверждений (ACK).
- **Правая граница (Right Edge):** Определяет максимальный порядковый номер байта, который можно отправить.

### Взаимодействие cwnd и rwnd
Реальное количество данных, которое TCP разрешает отправить (**Effective Window**), определяется как минимум из двух ограничителей:
1. **rwnd (Receiver Window):** Свободное место в буфере получателя (**Flow Control**). Объявляется получателем в заголовке ACK.
2. **cwnd (Congestion Window):** Оценка пропускной способности сети отправителем (**Congestion Control**). Рассчитывается алгоритмами (CUBIC, BBR).

```text
Effective Window = min(cwnd, rwnd)
```

### Масштабирование окна (Window Scale)
Поле `Window Size` в классическом заголовке TCP ограничено 16 битами (макс. 64 КБ). Для современных гигабитных сетей этого недостаточно.
- **RFC 7323:** Вводит опцию **Window Scale (WSCALE)**, которая задает множитель (степень 2). Это позволяет расширить окно до 1 ГБ. Согласовывается только на этапе Handshake (SYN-пакеты).

## Проблема «глупого окна» (Silly Window Syndrome)

Ситуация, при которой данные передаются крайне мелкими порциями (например, по 1 байту), что делает накладные расходы на заголовки (40 байт TCP/IP) несоизмеримыми с полезной нагрузкой.

### Решение на стороне получателя (Алгоритм Кларка)
Получатель не должен объявлять увеличение окна (`rwnd`), пока свободное место в буфере не станет равно:
- Либо **MSS** (Maximum Segment Size).
- Либо половине общего размера буфера приема.
До этого момента получатель продолжает объявлять `rwnd = 0`.

### Решение на стороне отправителя (Алгоритм Нагла)
Отправитель объединяет мелкие порции данных от приложения в один сегмент. Он не отправляет новый пакет, пока:
- Либо не накопится полный сегмент размера **MSS**.
- Либо не придет ACK на все ранее отправленные данные.
*Примечание:* Для интерактивных приложений (SSH, игры) алгоритм Нагла часто отключают опцией `TCP_NODELAY`.

## Практические сценарии

### Сценарий 1: Нулевое окно (Zero Window) и Persist Timer
Если приложение не успевает забирать данные из сокета, `rwnd` падает до 0. Чтобы избежать взаимной блокировки (deadlock) при потере ACK об открытии окна:
1. Отправитель запускает **Persist Timer**.
2. По истечении таймера шлет **Zero Window Probe** (сегмент в 1 байт).
3. Получатель отвечает текущим значением окна.

### Сценарий 2: Анализ BDP и окна в Linux
Для канала 10 Гбит/с и RTT 20 мс:
`BDP = 10^10 * 0.02 / 8 ≈ 25 МБ`.
Если `rwnd` или `cwnd` ограничены 64 КБ, скорость будет всего ~25 Мбит/с.

Просмотр текущего окна через `ss`:
```bash
ss -ti dst 1.2.3.4
# → cubic wscale:7,7 rto:204 rtt:15.2/0.5 cwnd:1000 rcv_space:14600
```
- **wscale:7,7:** Масштабирование включено (2^7 = 128).
- **cwnd:1000:** В полет можно отправить 1000 * MSS данных.
- **rcv_space:** Текущее окно, которое этот узел анонсирует партнеру.
