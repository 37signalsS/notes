# Скользящее окно в TCP (Sliding Window)

## Определения

**Скользящее окно (Sliding Window)** — это фундаментальный механизм протокола TCP, позволяющий отправителю передавать несколько сегментов данных один за другим, не дожидаясь подтверждения (ACK) для каждого из них. Этот механизм обеспечивает как надежность доставки (через нумерацию байт), так и высокую производительность сети.

**Основные параметры окна:**

- **LastByteAcked:** порядковый номер последнего байта, подтвержденного получателем.
- **LastByteSent:** порядковый номер последнего байта, физически отправленного в сеть.
- **LastByteWritten:** порядковый номер последнего байта, записанного приложением в буфер сокета.

---

## Основные концепции

### Принцип «скольжения»

Окно представляет собой диапазон порядковых номеров, которые отправителю разрешено иметь «в полете» (in-flight).

**Структура окна отправителя:**

```text
               ◄─────────────── Окно (Window) ───────────────►
               ┌───────────────────────┬─────────────────────┐
 подтверждено  │      в полете         │   можно отправить   │  нельзя
 (отброшено)   │ (отправлено, без ACK) │ (в рамках лимита)   │ (вне окна)
               └───────────────────────┴─────────────────────┘
               ▲                       ▲                     ▲
               │                       │                     │
         LastByteAcked           LastByteSent        LastByteAcked + Window
```

**Механика движения:**

1. **Отправка данных:** при отправке новых данных указатель `LastByteSent` сдвигается вправо.
2. **Получение ACK:** когда приходит подтверждение для порции данных, левая граница (`LastByteAcked`) сдвигается вправо («скользит»). Это открывает возможность для отправки новых байт с правой стороны.

### Взаимодействие с Flow и Congestion Control

Реальный размер окна, который использует TCP, является динамическим и определяется двумя факторами:

1. **Receiver Window (rwnd):** сколько места осталось в буфере получателя. Защищает получателя от переполнения.
2. **Congestion Window (cwnd):** сколько данных может пропустить сеть без создания заторов. Защищает сеть.

**Формула эффективного окна:**

```text
Effective Window = min(cwnd, rwnd)
```

### Восстановление порядка (Reordering)

Скользящее окно на стороне получателя позволяет принимать сегменты, пришедшие не по порядку (out-of-order).

- Если пришел сегмент с номером выше ожидаемого, получатель буферизует его, но не подтверждает (ACK остается на номере отсутствующего сегмента).
- Как только «дыра» в последовательности заполняется, окно получателя сдвигается сразу на несколько сегментов.

## Практические сценарии

### Сценарий 1: Работа окна при задержке ACK

Если сеть имеет высокую пропускную способность, но большую задержку (LFN — Long Fat Networks), отправитель может успеть заполнить всё окно до того, как придет первый ACK.

- **Симптом:** Передача данных идет короткими всплесками (bursts).
- **Решение:** Увеличение размера окна через [Масштабирование окна (Window Scale)](../Header_Format/index.md#масштабирование-окна-window-scaling).

### Сценарий 2: Заполнение окна (Window Full)

Ситуация, когда разность `LastByteSent - LastByteAcked` достигла размера окна.

- **Действие:** Отправитель обязан прекратить передачу и ждать ACK.
- **Диагностика:** В Wireshark такие пакеты помечаются как `[TCP Window Full]`.

### Сценарий 3: Нулевое окно (Zero Window)

Если получатель не успевает обрабатывать данные, он объявляет `rwnd = 0`.

- **Механизм:** Отправитель периодически посылает **Zero-Window Probe** (1 байт данных) для проверки состояния буфера.
- *Подробнее:* [Управление потоком](../Flow_Control/index.md#зондаж-нулевого-окна-zero-window-probe).
