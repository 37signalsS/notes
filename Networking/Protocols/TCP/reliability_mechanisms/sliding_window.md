# Sliding Window (Скользящее окно) в TCP

## Определения

**Sliding Window** — механизм управления потоком данных, позволяющий отправителю передавать несколько сегментов без ожидания ACK.

## Параметры окна

```
LastByteAcked — последний подтвержденный байт
LastByteSent  — последний отправленный байт
LastByteWritten — последний записанный в сокет байт
```

**Размеры окон:**

```
Effective Window = LastByteAcked + Window - LastByteSent
```

**Ограничения:**

```
LastByteSent - LastByteAcked ≤ cwnd (congestion window)
LastByteSent - LastByteAcked ≤ rwnd (receiver window)
```

Где:

* **cwnd** — окно перегрузки (congestion control)
* **rwnd** — окно получателя (flow control)

## Принцип работы

### 1. Отправка данных

Отправитель может отправить данные в пределах окна:

```
     LastByteAcked          LastByteSent
          |                     |
          v                     v
[ подтверждено | можно отправить | нельзя ]
```

### 2. Получение ACK

При получении ACK левая граница сдвигается вправо:

```
До ACK:
[ подтверждено | можно отправить | нельзя ]
      ^
      LastByteAcked

После ACK:
[ подтверждено | можно отправить | нельзя ]
               ^
               LastByteAcked (сдвинулось)
```

### 3. «Скольжение» окна

```
Отправитель                         Получатель
     |                                    |
     |  [1-1000] [1001-2000] [2001-3000]  |  Окно = 3000 байт
     |  ------------------------------>   |
     |                                    |
     |  <---------------- ACK=2001 -------|  Подтверждено [1-2000]
     |                                    |
     |  [3001-4000] [4001-5000]           |  Окно сдвинулось
     |  ------------------>               |
```

## Flow Control vs Congestion Control

### Flow Control (rwnd)

**Назначение:** защита получателя от переполнения буфера.

**Механизм:**

* Получатель указывает размер окна (rwnd) в каждом ACK
* Отправитель не может отправить больше, чем rwnd

### Congestion Control (cwnd)

**Назначение:** защита сети от перегрузки.

**Механизм:**

* Отправитель динамически изменяет cwnd на основе потерь
* Алгоритмы: Slow Start, Congestion Avoidance, Fast Recovery

**Подробнее:** [Congestion Control](../congestion/tcp_congestion_control_overview.md)

## Zero Window

**Ситуация:** получатель объявляет окно размера 0 (rwnd=0).

**Действия отправителя:**

* Остановка передачи данных
* Запуск таймера Zero Window Probe
* Периодическая отправка 1 байта для проверки доступности окна

**Пример:**

```
Получатель: ACK=5001, window=0  (буфер полон)
Отправитель: остановка
... (через некоторое время)
Отправитель: [5001] (1 байт, probe)
Получатель: ACK=5002, window=8192  (буфер освобожден)
Отправитель: возобновление передачи
```

## Window Scale

**Проблема:** 16-битное поле окна ограничивает размер 65535 байт.

**Решение:** опция **Window Scale** (RFC 1323) позволяет масштабировать окно.

**Масштаб:** сдвиг влево на 0-14 бит (максимум 1 ГБ).

**Пример:**

```
Window field = 65535
Scale factor = 7 (сдвиг на 7 бит)
Реальное окно = 65535 × 2^7 = 8 388 480 байт (~8 МБ)
```

**Согласование:** опция Window Scale передается в SYN при handshake.
