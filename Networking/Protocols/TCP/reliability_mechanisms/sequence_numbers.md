# Порядковые номера в TCP (Sequence Numbers)

## Определения

**Порядковый номер (Sequence Number)** — это 32-битное значение в заголовке TCP-сегмента, которое идентифицирует положение первого байта данных этого сегмента в общем потоке байт. TCP нумерует каждый переданный байт, что позволяет восстанавливать исходный порядок данных на стороне получателя.

**Начальный порядковый номер (Initial Sequence Number, ISN)** — случайное значение, выбираемое каждой стороной при установке соединения ([Handshake](../connection/tcp_connection_overview.md)).

---

## Основные концепции

### Назначение порядковых номеров

Использование `Sequence Numbers` решает три критические задачи надежности:

1.  **Восстановление порядка (Reordering):** сегменты могут доставляться по разным маршрутам и прибывать не по порядку. Получатель использует порядковые номера для сборки потока байт в правильной последовательности.
2.  **Обнаружение дубликатов:** если из-за ошибок маршрутизации получатель получает один и тот же сегмент дважды, он отбрасывает дубликат на основе уже принятых номеров.
3.  **Подтверждение получения:** поле `Acknowledgment Number` в обратном направлении указывает отправителю, до какого именно байта данные были успешно приняты.

### Механизм ISN (Initial Sequence Number)

При установке соединения стороны обмениваются своими ISN (флаг SYN).
- **Безопасность:** современные реализации используют генератор случайных чисел для выбора ISN. Это защищает соединение от атак типа «подмена TCP-сегмента» (TCP-hijacking), так как злоумышленнику сложно угадать текущую последовательность.
- **Разделение сессий:** уникальные ISN гарантируют, что сегменты от старой, уже закрытой сессии с теми же IP и портами не будут ошибочно приняты в рамках новой сессии.

### Проблема «заворачивания» (Wrapping)

Так как поле порядкового номера ограничено 32 битами (макс. 4 294 967 296 байт), в высокоскоростных сетях (10 Гбит/с и выше) счетчик может «завернуться» (вернуться к 0) за считанные секунды.
- **Решение:** использование опции **Timestamps** (RFC 7323) для механизма **PAWS** (Protection Against Wrapped Sequence numbers), который позволяет отличить старые сегменты от новых по временным меткам.

## Практические сценарии

### Сценарий 1: Сборка потока при нарушении порядка

Предположим, отправлено три сегмента по 1000 байт (ISN=0):
1.  Сегмент 1: `seq=0`
2.  Сегмент 2: `seq=1000`
3.  Сегмент 3: `seq=2000`

Если сегмент 3 пришел раньше сегмента 2:
- Получатель принимает `seq=0` (байты 0–999) и передает приложению.
- Получатель принимает `seq=2000` (байты 2000–2999), помещает в буфер, но не подтверждает (ACK остается на 1000).
- При получении `seq=1000` получатель «закрывает дыру» и подтверждает весь блок сразу: `ACK=3000`.

### Сценарий 2: Анализ порядковых номеров в tcpdump

По умолчанию `tcpdump` и Wireshark могут показывать относительные номера (начиная с 0) для удобства чтения.

```bash
# Просмотр реальных (абсолютных) порядковых номеров
tcpdump -i eth0 -S -nn tcp
```

**Пример вывода:**
```text
IP 192.168.1.10.54321 > 93.184.216.34.80: Flags [S], seq 1234567890
IP 93.184.216.34.80 > 192.168.1.10.54321: Flags [S.], seq 987654321, ack 1234567891
```
