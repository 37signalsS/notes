# Порядковые номера в TCP (Sequence Numbers)

## Определения

**Порядковый номер (Sequence Number)** — 32-битное беззнаковое целое число в заголовке TCP, идентифицирующее позицию первого байта данных конкретного сегмента в общем потоке. TCP рассматривает данные как непрерывную ленту байтов, где каждому байту присвоен уникальный номер.

**Начальный номер (Initial Sequence Number, ISN)** — значение, выбираемое каждой стороной при установке связи (флаг SYN). Современные ОС генерируют ISN случайным образом, чтобы предотвратить атаки предсказания номеров.

---

## Основные концепции

### 1. Правила инкрементации номеров
Порядковый номер увеличивается на количество переданных байтов данных. Однако существуют «виртуальные байты» для управляющих флагов:
- **SYN:** Занимает 1 виртуальный байт. После получения SYN-пакета с `seq = X`, подтверждение (ACK) будет иметь номер `X + 1`.
- **FIN:** Также занимает 1 виртуальный байт. Это гарантирует, что сигнал о закрытии соединения будет подтвержден точно так же, как и данные.
- **Данные:** Если сегмент содержит 1000 байт данных и начинается с `seq = 1001`, то следующий сегмент начнется с `seq = 2001`.

### 2. Защита от наложения номеров (PAWS)
В сетях со скоростью 10 Гбит/с и выше 32-битный счетчик (макс. 4 ГБ) может совершить полный круг («завернуться») менее чем за 4 секунды. Это создает риск того, что старый пакет, задержавшийся в сети, будет принят как новый в рамках того же соединения.

**PAWS (Protection Against Wrapped Sequence numbers, RFC 7323):**
- Использует опцию **TCP Timestamps**.
- Каждый сегмент несет метку времени отправителя.
- Если номера Seq совпадают, но метка времени пришедшего пакета меньше, чем последняя успешно принятая метка для этого соединения, пакет отбрасывается как старый дубликат.

### 3. Безопасность и SYN Cookies
При атаках типа SYN-флуд сервер может использовать поле `Sequence Number` в пакете SYN-ACK для хранения зашифрованного состояния соединения (**SYN Cookies**).
- Сервер не выделяет память под запись в очереди, а вычисляет специальный хеш (включающий IP-адреса, порты и секретный ключ) и записывает его в качестве своего ISN.
- Если клиент отвечает корректным ACK (где `ack_seq = ISN + 1`), сервер восстанавливает параметры соединения из этого номера и открывает сессию.

## Практические сценарии

### Сценарий 1: Анализ «дыр» в последовательности через tshark
Для выявления потерь в автоматизированном режиме удобно использовать `tshark`:

```bash
# Поиск пакетов, порядковые номера которых не следуют за предыдущими
tshark -r capture.pcap -Y "tcp.analysis.lost_segment"
```

### Сценарий 2: Мониторинг отброшенных пакетов (PAWS) в Linux
Если в сети наблюдаются странные разрывы соединений при высокой нагрузке, проверьте счетчики PAWS:

```bash
nstat -az TcpExtPAWSEstab
# → TcpExtPAWSEstab                   142                0.0
# Рост этого счетчика означает, что PAWS успешно отфильтровал старые сегменты.
```

### Сценарий 3: Проверка абсолютных Seq в tcpdump
По умолчанию инструменты показывают относительные номера. Флаг `-S` включает отображение реальных 32-битных значений:

```bash
sudo tcpdump -i any -S -nn tcp port 80
# → IP 1.1.1.1.54321 > 2.2.2.2.80: Flags [S], seq 3845612348
# → IP 2.2.2.2.80 > 1.1.1.1.54321: Flags [S.], seq 1098234567, ack 3845612349
```
