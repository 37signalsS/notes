# Sequence Numbers в TCP

## Определения

**Sequence Numbers** — механизм нумерации байт в TCP для обеспечения упорядоченной доставки данных.

**Принцип:** TCP нумерует **байты**, а не сегменты.

## Initial Sequence Number (ISN)

**ISN (Initial Sequence Number)** — случайное 32-битное число, выбираемое при установке соединения.

**Назначение:**

* Защищает от старых дубликатов сегментов
* Усложняет предсказание последовательности (защита от spoofing и **TCP-hijacking**)
* Обменивается в [handshake](../connection/tcp_connection_management_overview.md)

**Важно:** начальное значение ISN не равно 0. Обе стороны устанавливают случайное значение при установке соединения, которое считается начальным отсчётом (0). Это сделано для безопасности и предотвращения атак TCP-hijacking.

**Пример установки соединения:**

```
Отправитель                         Получатель
     |                                    |
     |  SYN, seq=1000 ------------------> |  ISN клиента = 1000
     |  <---------------- SYN, seq=2000 --|  ISN сервера = 2000
     |  ACK, ack=2001 ------------------> |  Ожидается байт 2001
     |                                    |
```

## Назначение Sequence Numbers

### 1. Восстановление порядка (Reordering)

Пакеты могут приходить не по порядку из-за маршрутизации. Sequence Numbers позволяют получателю восстановить правильный порядок.

```
Отправлено: [1-1000] [1001-2000] [2001-3000]
Получено:   [1-1000] [2001-3000] [1001-2000]  (перепутаны)
Действие:   буферизация [2001-3000], ожидание [1001-2000]
Результат:  передача приложению в порядке [1-1000[1001-2000[2001-3000]
```

### 2. Обнаружение дубликатов

Если сегмент с теми же Sequence Numbers уже получен, дубликат отбрасывается.

```
Отправлено: [1-1000]
Получено:   [1-1000] (первый раз) → принят
Получено:   [1-1000] (второй раз) → отброшен (дубликат)
```

### 3. Точное подтверждение полученных данных

ACK указывает следующий ожидаемый байт, что позволяет точно подтвердить полученные данные.

**Роль Sequence Number и Acknowledgment Number:**

- **Sequence Number** — позволяет принимающей стороне правильно размещать полученные данные в буфере (восстанавливать порядок)
- **Acknowledgment Number** — помогает отправителю понять, успешно ли дошли данные до получателя или имеется потеря

```
Отправлено: [1001-2000] [2001-3000]
Получено:   [1001-2000] [2001-3000] (все)
ACK:        ack=3001 (ожидается байт 3001)
```

## Пример передачи данных

### Базовый пример

```
Отправитель                         Получатель
     |                                    |
     |  Данные [1001-2000], seq=1001 ---> |  Байты 1001-2000
     |  Данные [2001-3000], seq=2001 ---> |  Байты 2001-3000
     |  <---------------- ACK, ack=3001 --|  Ожидается байт 3001
```

### Детальный пример: передача 2800 байт в 3 пакетах

**Сценарий:** TCP отправляет 2800 байт данных в трёх пакетах:
- Пакет 1: 1000 байт
- Пакет 2: 800 байт
- Пакет 3: 1000 байт

**Расчет Sequence Numbers:**

| Пакет | Размер данных | Sequence Number | Диапазон байт |
| :--- | :--- | :--- | :--- |
| 1 | 1000 байт | 0 | 0–999 |
| 2 | 800 байт | 1000 | 1000–1799 |
| 3 | 1000 байт | 1800 | 1800–2799 |

**Обмен пакетами:**

```
Отправитель                         Получатель
     |                                    |
     |  Пакет 1: seq=0, 1000 байт ------> |  Байты 0–999
     |  Пакет 2: seq=1000, 800 байт ----> |  Байты 1000–1799
     |  Пакет 3: seq=1800, 1000 байт ---> |  Байты 1800–2799
     |  <---------------- ACK, ack=2800 --|  Все данные получены
```

## Практические сценарии

### Сценарий 1: Пакеты пришли в правильном порядке

```
Отправлено: Пакет 1 (seq=0) → Пакет 2 (seq=1000) → Пакет 3 (seq=1800)
Получено:   Пакет 1 → Пакет 2 → Пакет 3
Действие:   Данные размещаются в буфере последовательно
Результат:  Байты 0–2799 собраны, переданы приложению
```

### Сценарий 2: Пакеты перепутались при передаче

**Ситуация:** пакеты пришли в порядке: 3, 1, 2

```
Шаг 1: Получен Пакет 3 (seq=1800, 1000 байт)
       Действие: TCP размещает данные со смещением 1800 байт
       Буфер: [??????????????][байты 1800–2799]

Шаг 2: Получен Пакет 1 (seq=0, 1000 байт)
       Действие: TCP размещает данные в начале буфера
       Буфер: [байты 0–999][???][байты 1800–2799]

Шаг 3: Получен Пакет 2 (seq=1000, 800 байт)
       Действие: TCP размещает данные со смещением 1000 байт
       Буфер: [байты 0–999][байты 1000–1799][байты 1800–2799]

Результат: Все байты 0–2799 собраны в правильном порядке
```

**Вывод:** Sequence Numbers позволяют TCP размещать данные в буфере получателя в правильном порядке, даже если пакеты приходят перемешанными.

## Конфликт Sequence Numbers

**Проблема:** что делать, если пришедшие данные наложились друг на друга? Или если хост получает два TCP-пакета с одинаковым номером смещения, но разными данными?

**Статус в RFC:** RFC не регламентирует поведение при конфликте Sequence Numbers с разными данными.

**Поведение реализаций:** разные ОС ведут себя по-разному:

| Реализация | Поведение |
| :--- | :--- |
| **Некоторые ОС** | Сохраняют более старые данные (первый полученный пакет) |
| **Другие ОС** | Перезаписывают более новыми данными (последний полученный пакет) |

**Рекомендация:** такие ситуации указывают на ошибки в реализации TCP или атаку на соединение. В нормальной работе конфликтов Sequence Numbers возникать не должно.

## 32-битное пространство

**Размер:** 2^32 = 4 294 967 296 байт (~4 ГБ)

**Проблема:** при высокой пропускной способности Sequence Numbers могут «завернуться».

**Решение:** опция **Timestamps** (RFC 7323) для защиты от старых дубликатов.
