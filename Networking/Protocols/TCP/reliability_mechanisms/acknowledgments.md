# Acknowledgments (ACK) в TCP

## Определения

**Acknowledgments (ACK)** — механизм подтверждений получения данных в TCP.

**Принцип:** ACK указывает номер следующего ожидаемого байта (кумулятивное подтверждение).

## Типы подтверждений

### 1. Кумулятивное подтверждение (Cumulative ACK)

**Принцип:** ACK подтверждает **все байты до указанного номера**.

**Пример:**

```
Отправлено: [1-1000] [1001-2000] [2001-3000]
Получено:   [1-1000] [1001-2000] [2001-3000] (все)
ACK:        ack=3001 (ожидается байт 3001)
```

**Преимущества:**

* Простой механизм
* Меньше служебного трафика

**Недостатки:**

* При потере одного сегмента отправитель не знает о полученных после него
* Избыточная ретрансмиссия при потерях

**Проблемный сценарий:**

```
Отправлено: [1-1000] [1001-2000] [2001-3000] [3001-4000]
Потерян:            [1001-2000]
Получено:   [1-1000]             [2001-3000] [3001-4000]
ACK:        ack=1001 (кумулятивно)
Проблема: отправитель не знает о полученных [2001-4000]
Ретрансмиссия: [1001-2000] [2001-3000] [3001-4000] (избыточно!)
```

### 2. Выборочное подтверждение (Selective Acknowledgment, SACK)

**Принцип:** получатель явно указывает полученные блоки данных.

**Сценарий с SACK:**

```
Отправлено: [1-1000] [1001-2000] [2001-3000] [3001-4000]
Потерян:            [1001-2000]
Получено:   [1-1000]             [2001-3000] [3001-4000]
ACK:        ack=1001
SACK:       blocks=[2001-4000]
Ретрансмиссия: только [1001-2000] (точно!)
```

**Опция TCP:** [SACK в заголовке](../Header_Format/index.md)

**SACK block format:**

```
Kind=5, Length=N, Left Edge, Right Edge
```

**Пример:**

```
SACK: left=2001, right=3001  (получено [2001-3000])
SACK: left=3001, right=4001  (получено [3001-4000])
```

**Включение SACK:**

* Обе стороны должны поддержать опцию `SACK permitted` в handshake
* В Linux включено по умолчанию (`net.ipv4.tcp_sack=1`)

**Преимущества SACK:**

* Точная ретрансмиссия только потерянных сегментов
* Выше пропускная способность при потерях
* Меньше задержка восстановления

## Delayed ACK

**Принцип:** получатель может задержать ACK для объединения с данными (piggybacking).

**Стандарт (RFC 1122):**

* ACK отправляется в течение 500 мс
* Или при получении 2 полных сегментов
* Или при отправке данных в обратном направлении

**Настройка в Linux:**

```bash
# Просмотр
sysctl net.ipv4.tcp_ack_skipped

# Отключение (не рекомендуется)
sysctl -w net.ipv4.tcp_ack_delayed=0
```

## Duplicate ACK (DupACK)

**Определение:** ACK с тем же номером подтверждения, отправленный повторно.

**Причина:** получатель получил сегменты не по порядку.

**Значение:** 3 DupACK запускают **Fast Retransmit**.

**Пример:**

```
Отправлено: [1-1000] [1001-2000] [2001-3000]
Потерян:            [1001-2000]
Получено:   [1-1000]             [2001-3000]
ACK:        ack=1001             ack=1001 (DupACK #1)
                           ack=1001 (DupACK #2)
                           ack=1001 (DupACK #3) → Fast Retransmit!
```
