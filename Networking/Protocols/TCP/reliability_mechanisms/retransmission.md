# Повторная передача в TCP (Retransmission)

## Определения

**Повторная передача (Retransmission)** — это механизм протокола TCP, обеспечивающий надежность путем повторной отправки сегментов данных, получение которых не было подтверждено удаленной стороной в течение определенного времени или при обнаружении признаков потери.

**Retransmission Timeout (RTO)** — интервал времени, по истечении которого отправитель считает сегмент потерянным и инициирует его повторную отправку.

---

## Основные концепции

### 1. Тайм-аут повторной передачи (RTO)

Механизм RTO используется для обнаружения потерь, когда от получателя не поступает никаких подтверждений.

**Алгоритм работы:**

1. При отправке сегмента запускается таймер.
2. Если подтверждение (ACK) получено до истечения таймера — таймер останавливается.
3. Если таймер истекает до получения ACK — сегмент отправляется повторно.

**Расчет значения RTO (RFC 6298):**
TCP адаптирует RTO под текущее состояние сети, измеряя время круговой задержки (RTT).

- **SRTT (Smoothed RTT):** сглаженное значение RTT.
- **RTTVAR (RTT Variance):** вариация задержки (джиттер).
- **Формула:** `RTO = SRTT + max(G, K * RTTVAR)`, где `K=4`.

**Экспоненциальная выдержка (Exponential Backoff):**
Если после повторной отправки подтверждение снова не получено, значение RTO удваивается (`RTO = RTO * 2`). Это предотвращает перегрузку сети при серьезных сбоях. Лимит попыток обычно составляет 15.

### 2. Быстрая ретрансмиссия (Fast Retransmit)

Позволяет восстановить данные быстрее, не дожидаясь истечения таймера RTO.

**Триггер:** получение **3 дублирующих подтверждений (DupACK)** с одним и тем же номером `Acknowledgment Number`.

- Дубликаты ACK возникают, когда получатель получает сегменты, следующие за потерянным.
- Три повтора — это эмпирический порог, позволяющий отличить реальную потерю от простого изменения порядка пакетов (reordering).

**Преимущество:** минимизирует задержку восстановления и предотвращает сброс окна перегрузки до начального значения.

### 3. Взаимодействие с управлением перегрузкой

Способ обнаружения потери напрямую влияет на скорость передачи данных:

| Механизм | Сигнал для сети | Реакция окна (cwnd) | Алгоритм |
| :--- | :--- | :--- | :--- |
| **3 DupACK** | Умеренная нагрузка | `cwnd = cwnd / 2` | Fast Recovery |
| **Тайм-аут RTO** | Серьезный затор | `cwnd = 1 MSS` | Slow Start |

## Практические сценарии

### Сценарий 1: Настройка минимального RTO в Linux

В некоторых сетях (например, внутри ЦОД с очень низким RTT) стандартное минимальное значение RTO может быть слишком большим.

```bash
# Просмотр параметров через ip route
ip route show

# Установка минимального RTO (мс) для конкретного маршрута
sudo ip route change default via <GATEWAY> dev <DEVICE> rto_min 200
```

*Примечание: Системный параметр `net.ipv4.tcp_frto` управляет алгоритмом F-RTO для борьбы с ложными ретрансмиссиями.*

### Сценарий 2: Ограничение попыток установки соединения

При неудачном рукопожатии (Handshake) TCP также выполняет ретрансмиссии пакета SYN.

```bash
# Количество попыток повтора SYN (по умолчанию обычно 6)
sysctl net.ipv4.tcp_syn_retries

# Уменьшение до 3 для ускорения обработки отказов
sudo sysctl -w net.ipv4.tcp_syn_retries=3
```
