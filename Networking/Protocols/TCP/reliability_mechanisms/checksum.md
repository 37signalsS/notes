# Контрольная сумма в TCP (Checksum)

## Определения

**Контрольная сумма (Checksum)** — 16-битное поле в заголовке TCP, предназначенное для проверки целостности заголовка, данных и параметров сетевого уровня. Это фундаментальный механизм защиты от повреждения бит при передаче через ненадежные сетевые узлы.

**Псевдозаголовок (Pseudo-header):** Виртуальная структура, временно формируемая в оперативной памяти для включения критических полей IP-заголовка в расчет контрольной суммы. Она обеспечивает защиту от ошибок маршрутизации (доставки сегмента не тому хосту или порту).

---

## Базовые концепции

### Особенности реализации
- **Обязательность:** В отличие от UDP (в IPv4), в протоколе TCP контрольная сумма обязательна для каждого сегмента.
- **Silent Drop:** Если контрольная сумма не совпадает, стек TCP на стороне получателя отбрасывает сегмент **без отправки уведомления** (например, ICMP или RST). Отправитель узнает о потере только по отсутствию подтверждения (ACK) и последующему срабатыванию таймера **RTO**.
- **Область покрытия:** Расчет охватывает псевдозаголовок, заголовок TCP (с полем Checksum, установленным в 0) и всю полезную нагрузку.

### Псевдозаголовок (Pseudo-header)
Псевдозаголовок связывает сетевой (L3) и транспортный (L4) уровни, гарантируя, что сегмент доставлен именно тому адресату, которому он предназначался.

#### Структура для IPv4
| Поле | Размер | Значение |
| :--- | :--- | :--- |
| **Source IP** | 32 бита | IP-адрес отправителя. |
| **Dest IP** | 32 бита | IP-адрес получателя. |
| **Reserved** | 8 бит | Всегда заполнено нулями. |
| **Protocol** | 8 бит | Для TCP значение всегда `6`. |
| **TCP Length** | 16 бит | Длина заголовка TCP + длина данных. |

#### Структура для IPv6 (RFC 8200)
| Поле | Размер | Значение |
| :--- | :--- | :--- |
| **Source IP** | 128 бит | IPv6-адрес отправителя. |
| **Dest IP** | 128 бит | IPv6-адрес получателя. |
| **TCP Length** | 32 бита | Длина заголовка TCP + длина данных. |
| **Zero** | 24 бита | Зарезервировано (0). |
| **Next Header** | 8 бит | Для TCP значение всегда `6`. |

### Алгоритм вычисления (Internet Checksum)
Используется арифметика 16-битного обратного кода (**One's Complement**), которая эффективна для программной реализации и позволяет сетевым картам легко вычислять сумму аппаратно.

1.  Весь блок данных (псевдозаголовок + TCP) разбивается на 16-битные слова. Если данных нечетное количество байт, добавляется нулевой байт (padding).
2.  Все слова суммируются. Если при сложении возникает перенос за пределы 16 бит, этот бит переноса прибавляется к младшему разряду суммы.
3.  После завершения суммирования результат инвертируется (все 0 становятся 1, и наоборот).
4.  Полученное значение записывается в поле Checksum.

## Практические сценарии

### Сценарий 1: Диагностика системных счетчиков в Linux
Для обнаружения проблем с контрольными суммами на уровне ОС (например, из-за плохих кабелей или ошибок памяти) используйте `nstat`.

```bash
# Просмотр счетчиков ошибок контрольных сумм
nstat -az | grep -i csum
# → TcpInCsumErrors                  5                  0.0
```
# → Результат: Ненулевое значение `TcpInCsumErrors` указывает на отбрасывание входящих пакетов из-за повреждения данных.

### Сценарий 2: Ложные срабатывания (Checksum Offloading)
При анализе трафика через `tcpdump` на локальном хосте часто видны пометки `bad cksum`.

- **Причина:** **Hardware Checksum Offload**. Ядро Linux передает сетевой карте пакет с незаполненным полем контрольной суммы, полагаясь на то, что NIC вычислит её аппаратно в момент передачи в провод. `tcpdump` перехватывает пакет **до** этого момента.
- **Проверка статуса:**
```bash
sudo ethtool -k eth0 | grep checksum
# → rx-checksumming: on
# → tx-checksumming: on
```

### Сценарий 3: Влияние GRO/LRO на целостность (2026)
Современные механизмы **GRO (Generic Receive Offload)** объединяют несколько сегментов в один большой до 64 КБ.
- **Нюанс:** Проверка контрольной суммы выполняется сетевой картой для каждого входящего сегмента MSS отдельно. Если карта подтвердила целостность, она передает ядру «склеенный» пакет.
- **Решение:** Если вы подозреваете повреждение данных внутри GRO-пакета, временно отключите агрегацию для «чистого» захвата:
```bash
sudo ethtool -K eth0 gro off
```
