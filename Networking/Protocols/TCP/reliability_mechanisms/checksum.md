# Контрольная сумма в TCP (Checksum)

## Определения

**Контрольная сумма (Checksum)** — это 16-битное поле в заголовке TCP, используемое для проверки целостности данных и заголовка сегмента. Она позволяет принимающей стороне обнаружить повреждение бит, возникшее при передаче по сети.

**Псевдозаголовок (Pseudo-header)** — виртуальная структура данных, объединяющая поля IP-заголовка и TCP-сегмента, используемая исключительно для вычисления контрольной суммы. Она гарантирует, что сегмент доставлен правильному узлу и процессу.

---

## Основные концепции

### Особенности реализации

- **Обязательность:** в отличие от протокола UDP (где контрольная сумма в IPv4 опциональна), в TCP она является обязательной для каждого сегмента.
- **Область проверки:** включает в себя псевдозаголовок, заголовок TCP и все передаваемые данные прикладного уровня.
- **Действие при ошибке:** если вычисленная получателем сумма не совпадает со значением в заголовке, сегмент **отбрасывается** без уведомления отправителя (silent drop). Это приводит к отсутствию подтверждения (ACK) и последующей ретрансмиссии по тайм-ауту.

### Псевдозаголовок (Pseudo-header)

Псевдозаголовок не передается в сети, а формируется динамически в памяти стека TCP при расчете суммы. Он связывает уровни L3 и L4 для защиты от ошибок маршрутизации.

**Структура (IPv4):**

| Смещение (бит) | 0–15 | 16–31 |
| :--- | :--- | :--- |
| **0** | IP-адрес источника (Source IP) — часть 1 | IP-адрес источника (Source IP) — часть 2 |
| **32** | IP-адрес назначения (Dest IP) — часть 1 | IP-адрес назначения (Dest IP) — часть 2 |
| **64** | Зарезервировано (0) \| Протокол (6) | Длина сегмента TCP (Header + Data) |

### Алгоритм вычисления (Internet Checksum)

Алгоритм основан на арифметике обратного кода (one's complement sum):
1.  Поле Checksum в заголовке TCP обнуляется.
2.  Данные (включая псевдозаголовок) разбиваются на 16-битные слова.
3.  Если количество байт нечетное, в конец добавляется нулевой байт (padding).
4.  Все слова суммируются. Все биты переноса за пределы 16 бит прибавляются к младшему биту результата.
5.  Итоговый результат инвертируется (биты 0 становятся 1, и наоборот).

## Практические сценарии

### Сценарий 1: Диагностика ошибок через tcpdump

При анализе сетевого трафика можно обнаружить неверные контрольные суммы.

```bash
# Просмотр трафика с подробной информацией о заголовках
tcpdump -i eth0 -nn -v tcp
```

**Пример вывода ошибки:**
```text
IP ... cksum 0x1234 (incorrect -> 0x5678)
```
*Интерпретация:* Если ошибок много, это может указывать на неисправность сетевого оборудования (кабели, порты коммутаторов) или драйверов.

### Сценарий 2: Ложные ошибки (Hardware Offloading)

Современные сетевые карты (NIC) вычисляют контрольную сумму аппаратно (**Checksum Offloading**). В этом случае `tcpdump` перехватывает пакет до того, как NIC запишет в него верную сумму, что отображается как ошибка.

**Проверка статуса Offloading:**
```bash
ethtool -k eth0 | grep checksum
# rx-checksumming: on
# tx-checksumming: on
```

**Отключение для отладки:**
Если необходимо увидеть реальные суммы в дампе:
```bash
sudo ethtool -K eth0 tx-checksumming off rx-checksumming off
```
