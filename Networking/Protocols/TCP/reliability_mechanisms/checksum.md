# Контрольная сумма в TCP (Checksum)

## Определения

**Контрольная сумма (Checksum)** — 16-битное поле в заголовке TCP, предназначенное для проверки целостности заголовка, данных и параметров сетевого уровня. Это базовая защита от повреждения бит при передаче.

**Псевдозаголовок (Pseudo-header):** Виртуальная структура, включающая IP-адреса и длину сегмента. Она не передается в сети, но участвует в расчете суммы для защиты от ошибок маршрутизации.

---

## Основные концепции

### Особенности реализации
- **Обязательность:** В отличие от UDP (в IPv4), в TCP контрольная сумма обязательна для каждого сегмента.
- **Silent Drop:** Если сумма не совпадает, сегмент отбрасывается **без уведомления**. Отправитель узнает об этом только по отсутствию ACK (тайм-аут RTO).
- **Область покрытия:** Псевдозаголовок + заголовок TCP + полезная нагрузка.

### Псевдозаголовок (Pseudo-header)
Псевдозаголовок связывает сетевой (L3) и транспортный (L4) уровни. Он формируется только в памяти для расчета суммы.

#### Структура для IPv4
| Поле | Размер | Значение |
| :--- | :--- | :--- |
| **Source IP** | 32 бита | IP-адрес отправителя. |
| **Dest IP** | 32 бита | IP-адрес получателя. |
| **Reserved** | 8 бит | Всегда 0. |
| **Protocol** | 8 бит | Для TCP всегда 6. |
| **TCP Length** | 16 бит | Длина заголовка TCP + данные. |

#### Структура для IPv6 (RFC 8200)
| Поле | Размер | Значение |
| :--- | :--- | :--- |
| **Source IP** | 128 бит | IPv6-адрес отправителя. |
| **Dest IP** | 128 бит | IPv6-адрес получателя. |
| **TCP Length** | 32 бита | Длина заголовка TCP + данные. |
| **Zero** | 24 бита | Зарезервировано (0). |
| **Next Header** | 8 бит | Для TCP всегда 6. |

### Алгоритм вычисления (Internet Checksum)
Основан на 16-битной арифметике обратного кода (One's Complement).
1.  Данные разбиваются на 16-битные слова.
2.  Слова суммируются с учетом переноса (биты переноса прибавляются к младшему разряду).
3.  Результат инвертируется.

## Практические сценарии

### Сценарий 1: Ложные ошибки (Checksum Offloading)
При захвате трафика на локальном хосте через `tcpdump` часто видны сообщения `bad cksum`.
- **Причина:** **Hardware Offloading**. ОС передает пакет сетевой карте (NIC) с «пустой» суммой, и NIC вычисляет её на лету. `tcpdump` перехватывает пакет до этого момента.

```bash
# Проверка статуса аппаратного вычисления сумм
ethtool -k eth0 | grep checksum
# → rx-checksumming: on
# → tx-checksumming: on
```

### Сценарий 2: Влияние GRO/LRO на диагностику (2026)
В современных ядрах механизмы **GRO (Generic Receive Offload)** и **LRO** объединяют несколько входящих сегментов в один большой перед передачей в стек.
- **Нюанс:** Контрольная сумма проверяется NIC для каждого сегмента отдельно. Если `tcpdump` показывает огромный агрегированный пакет (например, 15000 байт), сумма в нем может отображаться как некорректная.
- **Решение:** Для точного анализа целостности временно отключите GRO:
```bash
sudo ethtool -K eth0 gro off
```
