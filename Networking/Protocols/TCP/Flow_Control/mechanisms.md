# Механизмы управления потоком TCP

## Определения

**Zero Window (нулевое окно)** — состояние, когда буфер получателя полностью заполнен, отправитель прекращает передачу данных.

**Zero-Window Probe** — механизм предотвращения deadlock при потере ACK с ненулевым окном; отправитель периодически отправляет probe-сегменты для проверки состояния буфера получателя.

**Скользящее окно (Sliding Window)** — концепция передачи нескольких сегментов без ожидания ACK, повышающая утилизацию канала.

---

## Basic Concepts

### Zero Window (нулевое окно)

**Сценарий:** буфер получателя полностью заполнен.

**Действия получателя:**

- Отправляет `ACK` с `Window = 0`
- Отправитель **прекращает** передачу данных

**Проблема:** если следующий ACK с ненулевым окном потерян, отправитель будет ждать вечно (deadlock).

---

## Практические сценарии

### Зондаж нулевого окна (Zero-Window Probe)

**Механизм предотвращения deadlock:**

1. Отправитель запускает **persist timer** при получении `Window = 0`
2. По истечении таймера отправляет **probe-сегмент** (1 байт данных)
3. Получатель обязан ответить `ACK` с актуальным размером окна
4. Если окно всё ещё 0 — таймер перезапускается (экспоненциальное увеличение)

```
Отправитель                          Получатель
     |                                    |
     |  <--- ACK, Window = 0 ------------ |
     |  [Persist Timer: 60 сек]           |
     |                                    |
     |  Probe (1 байт) -----------------> |  Буфер: 5000/5000
     |  <--- ACK, Window = 0 ------------ |  (всё ещё полно)
     |  [Persist Timer: 120 сек]          |
     |                                    |  [Приложение читает данные]
     |                                    |  Буфер: 3000/5000
     |  Probe (1 байт) -----------------> |
     |  <--- ACK, Window = 2000 --------- |
     |  [Возобновление передачи]          |
```

**Настройка в Linux:**

```bash
# Минимальный интервал probe (по умолчанию 1 сек)
net.ipv4.tcp_probe_interval

# Максимальный интервал (экспоненциальный backoff)
net.ipv4.tcp_probe_threshold
```

### Скользящее окно (Sliding Window)

**Концепция:** отправитель может передаять несколько сегментов без ожидания ACK.

**Параметры окна:**

```
                    Скользящее окно
         ◄─────────────────────────────►
         ┌─────────────────────────────┐
         │  Отправлено, не подтверждено│
         ├─────────────────────────────┤
         │  Можно отправить           │
         ├─────────────────────────────┤
         │  Нельзя (за границей окна) │
         └─────────────────────────────┘
Last ACK ◄───► Last Sent            ◄───► Last ACK + Window
```

**Пример:**

```
Поток байт:  0    1000   2000   3000   4000   5000   6000
             │------│------│------│------│------│------│
                    ▲                       ▲
                    │                       │
              Last ACK (1000)         Last Sent (5000)

Window = 4000 байт
Можно отправить: 5000 → 5000+4000 = 9000
```

**«Скольжение»:** при получении ACK левая граница сдвигается вправо.
