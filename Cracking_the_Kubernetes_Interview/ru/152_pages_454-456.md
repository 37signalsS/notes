К распространенным причинам, по которым модуль остается в состоянии ожидания, относятся следующие:
•
Недостаточно ресурсов: наиболее распространенная причина.Планировщик проверяет, есть ли какой-либо узел
имеет достаточно свободного процессора и памяти для удовлетворения требований spec.resources.requests модуля.Если нет
одного узла достаточно, модуль подождет.На мероприятии будет четко указано что-то вроде этого:
Доступно 0/3 узлов: 3 Недостаточно памяти.
•
Несоответствие селектора узла. Если ваша спецификация модуля содержит метку nodeSelector, планировщик
будут рассматриваться только узлы с этими точными метками.Если ни один из узлов не имеет требуемых меток,
событие скажет следующее:
Доступно 0/3 узлов: 3 узла(ов) не соответствуют селектору узлов.
•
Загрязнения и допуски. Заражения — это метки, размещаемые на узлах для отпугивания модулей.Модуль может только
быть запланировано на испорченном узле, если он имеет соответствующую метку допуска.Если модуль не
терпеть загрязнения на доступных узлах, оно останется в ожидании.
