Как детально настроить доступ к Kubernetes API
Это важная тема, поскольку интервьюеры регулярно задают по ней вопросы. Детально 
настройка доступа к API Kubernetes включает в себя реализацию детальных элементов управления для ограничения 
и управлять разрешениями пользователей на основе ролей, обязанностей и конкретных требований к ресурсам. 
Обычно это достигается с помощью RBAC, функции Kubernetes, которая позволяет администраторам определять
настройте пользовательские роли и привяжите их к учетным записям пользователей или служб. Вот как детально настроить 
доступ к API Kubernetes:
1.	
Определите настраиваемые роли. Начните с определения настраиваемых ролей, инкапсулирующих определенные разрешения.
необходимые для различных задач или операций внутри кластера. Роли могут быть ограничены 
на уровне кластера или пространства имен, в зависимости от желаемого уровня детализации. Каждый 
Дистрибутив Kubernetes поставляется с предопределенными ролями, которые вы можете использовать, но они охватывают 
только общие случаи. Точно определяйте разрешения ролей, гарантируя, что у пользователей есть только 
доступ к ресурсам, необходимым для выполнения своих задач, при этом предотвращая несанкционированный доступ 
к чувствительным ресурсам.
Вот пример:
apiVersion: rbac.authorization.k8s.io/v1
вид: Роль
метаданные:
 пространство имен: dev
  имя: pod-reader
правила:
- apiGroups: [""]
  ресурсы: ["pods"]
  глаголы: ["получить", "список", "смотреть"]
Эта роль позволяет читать информацию о поде (получить, просмотреть, просмотреть) в пространстве имен dev.
2.	
Создайте привязки ролей. После определения ролей привяжите их к конкретным объектам, используя 
RoleBinding (для доступа в пределах пространства имен) или ClusterRoleBinding (для доступа на уровне всего кластера). 
доступ). Сущности могут быть следующими:
•	
Пользователи (отдельные пользователи-люди)
•	
Группы (коллекции пользователей)

Учетные записи служб (идентификаторы приложений/модулей, работающих в кластере)
