Как Ingress находит подходящую услугу?
Обычно (как всегда в Kubernetes) это основано на метках, но можно ответить и подробнее. Итак, 
когда запрос поступает на внешний IP-адрес или имя хоста кластера, входной контроллер 
определяет соответствующую серверную службу для маршрутизации запроса. Контроллер Ingress полагается 
на ресурсе Kubernetes под названием Endpoints, чтобы указать сетевой адрес серверной службы.
В Kubernetes конечные точки представляют собой набор сетевых адресов (IP-адреса и номера портов).

и фактические модули, которые обслуживают трафик для этой службы.
Вот как это работает:
•	
Создание службы. Когда вы создаете службу Kubernetes, Kubernetes автоматически создает 
объект Endpoints, связанный с этой службой. Объект Endpoints изначально содержит 
IP-адреса и номера портов всех модулей, которые выбирает селектор меток службы.
•	
IP-адрес и порт модуля: каждый модуль в кластере имеет свой IP-адрес и прослушивает определенные 
порты для обслуживания трафика. Когда модуль создается, Kubernetes добавляет его IP-адрес и порт в 
объект Endpoints, связанный со всеми службами, нацеленными на этот модуль.
•	
Обнаружение службы: когда контроллер Ingress получает входящий запрос, он ищет 
желаемую серверную службу на сервере API Kubernetes. Определение сервиса содержит 
ссылка на соответствующий объект Endpoints.
•

с помощью целевой службы для получения списка IP-адресов и портов модулей, обслуживающих 
этот сервис.
