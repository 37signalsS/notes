Каково состояние Live в Argo CD?
Активное состояние относится к текущему состоянию вашего приложения в кластере Kubernetes. 
Сюда входят такие сведения, как количество запущенных модулей, используемые ими образы и 
текущая конфигурация сервисов и развертываний. Живое состояние динамично и меняется по мере 
приложение запускается, отражая данные в реальном времени об операционной среде ваших приложений.
Что означает целевое состояние в Argo CD?
Целевое состояние — это желаемое состояние вашего приложения, определенное в вашем репозитории Git. Это 
декларативное состояние определяет, как ваше приложение должно быть настроено и работать, включая 
точные версии образов, желаемое количество реплик и конкретные конфигурации для каждого 
ресурс. Когда вы вносите изменения в конфигурацию вашего приложения в репозитории Git, 
целевое состояние обновляется. Затем Argo CD согласовывает живое состояние с этим целевым состоянием посредством 
автоматизированные процессы синхронизации.

Совет по собеседованию
Вопрос: Расскажите, как Argo CD обнаруживает и применяет изменения после слияния Git.
Ответ: После слияния PR в кластер ничего не проталкивается. Argo CD либо получит 
веб-перехватчик Git или обнаруживает новый коммит в следующем опросе, а затем сервер API 
просит репо-сервер получить эту ссылку и отобразить манифесты (Helm/Kustomize/plain 
ЯМЛ). Наконец, контроллер приложения сравнивает желаемое состояние из Git с 
живое состояние в кластере. Если они различаются и включена автосинхронизация (и вы внутри 
любые разрешенные окна синхронизации), он применяет изменения по порядку, соблюдая волны синхронизации. 
и дополнительные перехватчики — сокращение удаленных ресурсов, если они настроены, и самовосстановление. 
Затем он наблюдает за проверками работоспособности, пока приложение не сообщит о синхронизации/работоспособности, и повторяет попытку с помощью 
отсрочка при сбоях и отображение статуса в пользовательском интерфейсе/CLI. Если автосинхронизация отключена, Argo CD 
останавливается на OutOfSync и ожидает ручной синхронизации. В целом примирение носит тянущий характер.
на основе — CI никогда не требует учетных данных кластера.
