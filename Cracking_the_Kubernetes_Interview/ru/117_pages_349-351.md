Когда файл YAML будет готов, примените его к своему кластеру Kubernetes с помощью kubectl apply -f. 
Команда <crd-файл>.yaml. Это регистрирует CRD на сервере API Kubernetes, делая 
доступен новый тип пользовательского ресурса.
После регистрации CRD вы можете создавать, читать, обновлять и удалять экземпляры вашего пользовательского re.
source с помощью стандартных команд Kubernetes. Например, чтобы создать новый экземпляр пользовательского 
ресурса, вы должны написать файл YAML для ресурса и применить его с помощью kubectl apply -f 
<файл-ресурса>.yaml.

Что такое оператор Kubernetes?
Оператор Kubernetes — это метод упаковки, развертывания и управления приложением Kubernetes.

программное обеспечение.

Критические компоненты оператора Kubernetes и его роли
Во-первых, оператор Kubernetes почти всегда включает CRD (как мы обсуждали) вместе с ap.
соответствующие пользовательские ресурсы (CR), которые он использует для управления ресурсами в кластере.
Он также включает в себя следующие компоненты:
•	
Контроллер: это основной компонент оператора Kubernetes. Он содержит логику, 
управлять жизненным циклом приложения и обеспечивать соответствие фактического состояния желаемому состоянию 
указано в ЧР. Контроллер постоянно отслеживает изменения в CR и принимает 
соответствующие действия по устранению разногласий. Этот процесс известен как примирение 
петля. Другими словами, он гарантирует правильное развертывание и настройку приложения. 
регулирует количество экземпляров на основе заданных критериев или требований рабочей нагрузки, управляет 
обновления приложений, обеспечивая при этом минимальное время простоя и сохраняя целостность данных, 
обнаруживает и устраняет сбои для поддержания доступности приложений, а также собирает метрики 
и медицинскую информацию для принятия обоснованных решений о состоянии приложения.
Цикл согласования на самом деле не является компонентом; это фундаментальный шаблон, используемый 
контроллер. Он работает непрерывно, проверяя желаемое состояние, указанное в CR, на соответствие 
фактическое состояние приложения. При обнаружении несоответствий контролер принимает меры по их выравниванию.

Обработчики событий: это механизмы внутри контроллера, которые реагируют на изменения в 
кластер Кубернетес. Они отслеживают такие события, как создание, изменение или удаление 
CR. Когда такое событие происходит, обработчик запускает цикл согласования для обработки 
соответствующим образом изменить и обновить состояние приложения.
•	
Клиентские библиотеки: они используются контроллером для взаимодействия с API Kubernetes. 
Примером может служить клиентская библиотека Kubernetes. Эти библиотеки предоставляют необходимые 
функции для просмотра, просмотра, создания, обновления и удаления ресурсов Kubernetes. Контроллер 
может выполнять операции, необходимые для управления приложением и его компонентами, 
использование клиентских библиотек.
•	
Operation Lifecycle Manager (OLM): это необязательный, но ценный компонент для 
управление жизненным циклом Операторов. OLM упрощает развертывание, управление и 
обновление операторов в кластере Kubernetes. Он обеспечивает стандартизированный способ упаковки
старение, развертывание и обслуживание операторов, обеспечивая их постоянное управление и обновление.
