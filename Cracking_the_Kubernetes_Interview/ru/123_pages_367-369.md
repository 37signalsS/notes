Стратегии обеспечения высокой доступности etcd
Чтобы добиться высокой доступности для etcd, вам необходимо сделать следующее:
1.
Развертывание etcd в виде кластера. Высокодоступный кластер etcd должен состоять как минимум из трех
узлы для обеспечения кворума и отказоустойчивости.Это позволяет etcd продолжать работу даже
если один узел выйдет из строя.
2.
Используйте внешний кластер etcd. Развернув etcd как внешний кластер отдельно от
Плоскость управления Kubernetes позволяет улучшить масштабируемость и отказоустойчивость.Эта установка
изолирует etcd от любых потенциальных сбоев в плоскости управления, гарантируя, что ваш кластер
состояние остается неизменным, даже если в компонентах плоскости управления возникают проблемы.
3.
Выполняйте регулярное резервное копирование: резервные копии имеют решающее значение для восстановления в случае сбоя etcd.Использование
etcdctl, вы можете автоматизировать создание снимков etcd.
Вот пример команды для резервного копирования etcd:
ETCDCTL_API=3 сохранение моментального снимка etcdctl /path/to/backup.db \
--endpoints=https://etcd1.example.com:2379, https://etcd2.example.
ком:2379,https://etcd3.example.com:2379 \
--cacert=/etc/etcd/pki/ca.pem \
--cert=/etc/etcd/pki/etcd.pem \
--key=/etc/etcd/pki/etcd-key.pem
Давайте посмотрим на объяснение этого:
•
ETCDCTL_API=3: указывает версию API etcd (версия 3 является последней).
•
etcdctl snapshot save /path/to/backup.db: Делает снимок и сохраняет его в
указанный путь (/path/to/backup.db).
•
--endpoints: указывает на URL-адрес сервера etcd.Здесь он работает локально
(https://127.0.0.1:2379).
•
--cacert, --cert, --key: эти флаги предоставляют необходимые сертификаты и ключи для
безопасно аутентифицироваться на сервере etcd.
Важное примечание
Хотя добавление большего количества узлов повышает отказоустойчивость, оно также приводит к увеличению
с точки зрения производительности и сетевого трафика.Обычно рекомендуется
начните с кластера etcd из трех узлов, если вам не нужна большая отказоустойчивость.
