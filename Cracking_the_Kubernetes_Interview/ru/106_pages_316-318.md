Как можно использовать внешние инструменты управления секретами?
Внешние инструменты управления секретами, такие как HashiCorp Vault, AWS Secrets Manager и Azure Key. 
Vault обеспечивает надежную безопасность и контроль доступа для управления секретами. Эти инструменты хранят секреты 
за пределами Git и предоставлять API для их безопасного получения во время выполнения. Интеграция этих инструментов с 
ваш рабочий процесс GitOps гарантирует, что конфиденциальная информация никогда не будет раскрыта в ваших репозиториях, что 
сохраняет конфиденциальность и целостность ваших секретов.
Для более близкого к Kubernetes подхода многие команды используют Внешний оператор секретов (ESO). 
Этот мощный оператор расширяет API Kubernetes с помощью специального ресурса под названием ExternalSecret. 
Вместо хранения зашифрованных данных в Git вы фиксируете простой манифест ExternalSecret. 
Этот манифест действует как указатель, определяя, какой секрет следует получить от внешнего поставщика, например 
как HashiCorp Vault, AWS Secrets Manager или Azure Key Vault, и как назвать полученный результат. 
родной секрет Kubernetes.
ESO работает внутри вашего кластера, отслеживает эти ресурсы ExternalSecret и автоматически 
выполняет следующий рабочий процесс:
•	
Он аутентифицируется с помощью внешнего инструмента управления секретами.
•	
Он безопасно извлекает указанные секретные данные.
•	
Он создает стандартный секрет Kubernetes в кластере с полученными данными.
Этот шаблон очень эффективен, поскольку ваш репозиторий Git — единственный источник достоверной информации — содержит 
никакой конфиденциальной информации, даже в зашифрованном виде. Затем ваши модули приложений смогут 
смонтировать синхронизированный собственный Kubernetes Secret, как обычно, совершенно не подозревая об этом. 
основного механизма. Это обеспечивает четкое разделение задач и согласуется с
