# GitOps: Образы контейнеров и их жизненный цикл

В GitOps образ контейнера является ключевым артефактом, который связывает процессы непрерывной интеграции (CI) и непрерывной доставки (CD). Правильное управление образами — основа предсказуемости и безопасности всей системы.

## Определения

- **Образ контейнера (Container Image)**: Неизменяемый (immutable) бинарный пакет, который включает в себя приложение и все его зависимости. В GitOps-конвейере это главный "доставляемый" артефакт.
- **Реестр образов (Image Registry)**: Сервис для хранения, версионирования и распространения образов контейнеров. Примеры: Docker Hub, Harbor, Amazon ECR (Elastic Container Registry), Google Artifact Registry.
- **Неизменяемый тег (Immutable Tag)**: Тег образа, который уникально и постоянно идентифицирует один и тот же слой образа. Это может быть хеш коммита (например, `githash-a4b5c6d`) или версия по SemVer (Semantic Versioning), например, `1.2.3`.
- **Digest**: SHA256 (Secure Hash Algorithm 256-bit) хеш образа, гарантирующий неизменность. Пример: `my-app@sha256:a1b2c3...`.

## Базовые концепции

### Разделение CI и CD

GitOps четко разделяет зоны ответственности между CI (Continuous Integration — непрерывная интеграция) и CD (Continuous Delivery — непрерывная доставка):

- **CI**: Процесс сборки кода в артефакт. CI-пайплайн отвечает за сборку, тестирование и публикацию образа в реестр с неизменяемым тегом.
- **CD**: Процесс доставки артефакта в окружение. GitOps-инструмент (ArgoCD, Flux) отвечает за то, чтобы версия образа, указанная в Git-репозитории, работала в кластере.

Git-репозиторий с манифестами Kubernetes (K8s) служит "мостом" между этими двумя процессами.

### Важность неизменяемых тегов

Использование изменяемых (mutable) тегов, таких как `latest` или `staging`, является анти-паттерном в GitOps по нескольким причинам:

- **Непредсказуемость**: Невозможно быть уверенным, какая именно версия кода скрывается за тегом `latest`.
- **Потеря источника истины**: Git перестает быть единственным источником правды, так как фактическое состояние может измениться без коммита (просто из-за перезаписи тега в реестре).
- **Невозможность отката**: Нельзя надежно откатиться на предыдущую рабочую версию, если тег был перезаписан.

**Правило**: Всегда используйте неизменяемые теги — SemVer (`1.2.3`) или digest (`@sha256:...`).

Стратегии тегирования подробно описаны в руководстве по [версионированию и тегированию образов](../../Docker/Docker_registries/image_versioning_and_tagging.md).

## Практические сценарии

### Сценарий 1: Полный CI/CD пайплайн для GitOps

1. **Коммит**: Разработчик отправляет код в репозиторий приложения.
2. **CI-пайплайн (GitHub Actions, Jenkins)**:
    - Запускается сборка.
    - Образ контейнера собирается и тегируется хешем коммита (например, `my-app:a4b5c6d`).
    - Образ отправляется в приватный реестр.
3. **Обновление манифеста (Автоматическое)**:
    - Инструмент автоматического обновления образов обнаруживает новый образ в реестре.
    - Он автоматически создает коммит в конфигурационный репозиторий, обновляя тег образа в `Deployment.yaml`.
4. **CD-пайплайн (ArgoCD/Flux)**:
    - GitOps-инструмент обнаруживает новый коммит в конфигурационном репозитории.
    - Он синхронизирует состояние кластера, запуская деплой новой версии приложения.

### Сценарий 2: Автоматическое обновление образов

Для автоматизации обновления тегов в Git используются специализированные инструменты:

- **ArgoCD Image Updater**: Отдельный компонент для ArgoCD. Настройка выполняется через аннотации в объекте `Application`.
- **Flux Image Automation**: Встроенный контроллер (`image-automation-controller`). Настройка через CRD (Custom Resource Definition): `ImageRepository`, `ImagePolicy`, `ImageUpdateAutomation`.

Пример проверки статуса автоматизации в Flux через CLI (Command Line Interface):

```bash
flux get image updates
# → result:
# NAME            LAST RUN                COMMIT          STATUS
# podinfo-update  2024-05-30T10:00:00Z    1a2b3c4d        reconciliation finished: no changes made
```

Оба инструмента поддерживают:

- Сканирование реестров на наличие новых тегов.
- Фильтрацию по SemVer, регулярным выражениям (regex), датам.
- Автоматическое создание PR (Pull Request) или прямых коммитов в Git-репозиторий.
- Обновление digest для максимальной безопасности.

Подробная настройка: [ArgoCD Image Updater](../ArgoCD/argocd_overview.md#argocd-image-updater), [Flux Image Automation](../flux.md).
