# Crossplane: сравнение с Terraform

## Определения

**Crossplane** — Kubernetes-native инструмент для управления инфраструктурой через **CRD (Custom Resource Definitions)** с непрерывной сверкой состояния.

**Terraform** — CLI-инструмент для **IaC (Infrastructure as Code)** с декларативным языком **HCL (HashiCorp Configuration Language)** и управлением состоянием через state-файлы.

## Базовые концепции

### Ключевые различия

| Характеристика | Crossplane | Terraform |
| :--- | :--- | :--- |
| **Среда выполнения** | Выполняется как контроллер внутри Kubernetes | Выполняется как CLI-инструмент с любого хоста |
| **Управление состоянием** | Состояние инфраструктуры хранится в etcd Kubernetes | Требует настройки внешнего хранилища (S3, Consul, GCS) для хранения state-файла |
| **Модель выполнения** | Непрерывная сверка (**reconciliation loop**) — постоянно мониторит и корректирует | Выполнение по запросу (`plan`, `apply`) — требует ручного или CI/CD запуска |
| **Безопасность** | Интегрирован с **RBAC (Role-Based Access Control)** и политиками Kubernetes (OPA, Kyverno) | Требует отдельных решений для управления доступом (Vault, Sentinel) |
| **Интеграция с GitOps** | Нативная (ArgoCD, Flux) — достаточно применить манифесты | Требует дополнительных инструментов (Atlantis, Terraform Cloud) |
| **Язык конфигурации** | YAML (Kubernetes CRD) | HCL |
| **Экосистема провайдеров** | Через Upbound Registry и community providers | Terraform Registry (наибольшая экосистема) |
| **Комьюнити** | **CNCF (Cloud Native Computing Foundation)** Graduated (ноябрь 2025) | HashiCorp, наиболее зрелая экосистема (с 2014) |

## Практические сценарии

### Выбор инструмента

**Выбирайте Crossplane, когда:**

- Уже используете Kubernetes и GitOps (ArgoCD, Flux).
- Нужна непрерывная сверка состояния без ручного запуска пайплайнов.
- Требуется единый API для приложений и инфраструктуры.
- Важны Kubernetes-native политики безопасности (RBAC, OPA).
- Строите внутреннюю платформу с абстракциями (**Composition API**).

**Выбирайте Terraform, когда:**

- Требуется управление инфраструктурой без привязки к Kubernetes.
- Необходима максимальная экосистема провайдеров (более 1000).
- Команда уже имеет глубокую экспертизу в HCL.
- Нужны сложные зависимости между ресурсами вне жизненного цикла подов.
- Требуется Terraform Cloud/Enterprise для совместной работы.

### Гибридный подход

Оптимальный паттерн для многих организаций:

1. **Terraform**: Для начальной настройки кластера Kubernetes и базовой сети (**VPC**, подсети).
2. **Crossplane**: Для управления сервисами внутри кластера и динамическими облачными ресурсами (БД, очереди), необходимыми приложениям.
