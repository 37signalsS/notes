# Crossplane: сравнение с Terraform и OpenTofu

## Определения

**Crossplane** — это Kubernetes-native решение для управления инфраструктурой, превращающее кластер в полноценную платформу управления (Control Plane). Использует кастомные ресурсы (CRD) и контроллеры для непрерывной сверки состояния.

**Terraform** — индустриальный стандарт **IaC (Infrastructure as Code)** от HashiCorp. Использует язык HCL и ориентирован на событийное выполнение (workflow-based) через CLI или CI/CD.

**OpenTofu** — открытый форк Terraform (под эгидой Linux Foundation), возникший как ответ на изменение лицензионной политики HashiCorp. Совместим с экосистемой Terraform, но развивает уникальные функции (например, нативное шифрование состояния).

## Базовые концепции

### Ключевые различия (актуально на 2026 год)

| Характеристика | Crossplane | Terraform (HCP/Ent) | OpenTofu |
| :--- | :--- | :--- | :--- |
| **Среда выполнения** | Kubernetes Control Plane | CLI / CI-пайплайны | CLI / CI-пайплайны |
| **Хранение состояния** | etcd кластера (как CRD) | Файл `.tfstate` (S3/GCS) | Файл `.tfstate` (S3/GCS) |
| **Сверка состояния** | **Непрерывная** (Reconciliation) | По запросу (`plan`/`apply`) | По запросу (`plan`/`apply`) |
| **Исправление дрейфа** | **Автоматическое** (Self-healing) | Ручное (требует запуска) | Ручное (требует запуска) |
| **Язык конфигурации** | YAML (Kubernetes native) | HCL | HCL |
| **Безопасность** | RBAC Kubernetes, OPA, Kyverno | Sentinel, Vault, OPA | OPA, шифрование state-файла |
| **Лицензия** | Apache 2.0 | BSL (Business Source License) | MPL 2.0 (Open Source) |

### Управление состоянием и дрейфом (Drift)

*   **Crossplane:** Не имеет отдельного state-файла. "Состояние" — это текущий статус ресурсов в etcd. Контроллер постоянно (каждые несколько секунд/минут) проверяет соответствие реального ресурса в облаке его описанию в YAML. Если ресурс изменен в консоли облака, Crossplane автоматически вернет его к желаемому виду.
*   **Terraform / OpenTofu:** Состояние хранится в виде снимка (snapshot) в state-файле. Обнаружение дрейфа происходит только в момент запуска команды `plan`. В 2026 году Terraform Cloud предлагает "Continuous Health Checks" (сканирование каждые несколько часов), но исправление все равно требует подтверждения или запуска пайплайна.

## Практические сценарии

### Выбор инструмента

**Выбирайте Crossplane, когда:**
- Вы строите **Internal Developer Platform (IDP)** и хотите дать разработчикам возможность самим создавать БД или очереди через абстрактные "Claims".
- Вам нужно автоматическое исправление дрейфа без участия человека.
- Инфраструктура тесно связана с жизненным циклом приложений в Kubernetes.
- Вы хотите использовать единый стек безопасности (RBAC K8s) для приложений и облака.

**Выбирайте Terraform / OpenTofu, когда:**
- Вам нужно управлять фундаментальной инфраструктурой (VPC, Peering, IAM) вне контекста Kubernetes.
- Требуется максимально широкая поддержка провайдеров (более 3000 в реестре).
- Сложные зависимости между ресурсами требуют четкого плана выполнения перед применением изменений.
- Команда предпочитает HCL за его выразительность по сравнению с многословным YAML.

### Гибридный подход

Наиболее эффективная стратегия в 2026 году:

1.  **Terraform / OpenTofu:** Используется для "фундамента" — создание кластеров Kubernetes, сетей, глобальных политик безопасности и базовых IAM-ролей.
2.  **Crossplane:** Устанавливается в готовый кластер и управляет "динамической" инфраструктурой, необходимой приложениям (БД, S3-бакеты, топики Kafka). Это позволяет разработчикам работать в одном интерфейсе (kubectl/GitOps) без необходимости изучать HCL.

Для автоматизации Terraform/OpenTofu в GitOps-стиле часто применяются **TACOS**-платформы (Spacelift, env0, Scalr) или Flux TF-controller.
