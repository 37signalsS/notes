# ArgoCD — синхронизация и политики

## Определения

**Синхронизация (Synchronization)** — процесс приведения фактического состояния ресурсов в Kubernetes-кластере в соответствие с конфигурацией, описанной в Git-репозитории.

**Желаемое состояние (Desired State)** — эталонная конфигурация ресурсов (YAML, Helm, Kustomize), хранящаяся в Git.

**Фактическое состояние (Live State)** — текущее состояние объектов, запущенных в кластере Kubernetes.

**Расхождение (OutOfSync)** — статус приложения, указывающий на наличие различий между `Live State` и `Desired State`.

**Статус синхронизации (Sync Status)** — индикатор соответствия кластера источнику: `Synced` (соответствует) или `OutOfSync` (есть расхождения).

**Статус здоровья (Health Status)** — оценка работоспособности ресурсов: `Healthy` (здоров), `Progressing` (в процессе), `Degraded` (деградирован), `Suspended` (приостановлен), `Missing` (отсутствует).

## Основные концепции

### Цикл сверки (Reconciliation Loop)

ArgoCD Application Controller непрерывно выполняет цикл сравнения состояний (по умолчанию каждые 3 минуты или мгновенно по Webhook):

1. **Извлечение:** клонирование Git-репозитория и получение текущего состояния кластера через API Kubernetes.
2. **Генерация:** рендеринг манифестов (выполнение Helm template, Kustomize build и т.д.).
3. **Сравнение:** выявление диффов между манифестами и ресурсами в кластере.
4. **Обновление статуса:** визуализация расхождений в UI/CLI.

### Двунаправленная синхронизация и Self-Heal

ArgoCD реализует концепцию "дрейфа конфигурации" (Configuration Drift):

1. **Git → Кластер:** применение новых изменений из репозитория.
2. **Кластер → Git:** обнаружение ручных правок в кластере (например, через `kubectl edit`).
3. **Автоматическое исправление (Self-Heal):** если опция включена, ArgoCD автоматически перезапишет ручные правки в кластере эталонными значениями из Git.

### Современные методы синхронизации (v3.x)

- **Server-Side Apply (SSA):** перенос логики слияния манифестов на сторону API-сервера Kubernetes. Решает проблему лимита аннотаций (262KB) и лучше обрабатывает конфликты полей (например, при совместном использовании с HPA).
- **Progressive Sync (RollingSync):** поэтапное развертывание изменений через ApplicationSets. Позволяет обновлять группы приложений последовательно, дожидаясь статуса `Healthy` перед переходом к следующему этапу.
- **Пауза сверки (Reconciliation Pause):** возможность полностью остановить синхронизацию для конкретного кластера через аннотацию в секрете кластера (`argocd.argoproj.io/reconciliation-pause: "true"`).

### Параметры синхронизации (Sync Options)

В манифесте `Application` можно настроить тонкое поведение:
- `Prune=true`: удаление ресурсов в кластере, которых больше нет в Git.
- `Replace=true`: использование `kubectl replace` вместо `kubectl apply` для ресурсов, не поддерживающих патчинг.
- `Retry`: настройка стратегии повторных попыток при неудачной синхронизации.
