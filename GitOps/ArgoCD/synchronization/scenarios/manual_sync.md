# ArgoCD — ручная синхронизация

## Определения

**Ручная синхронизация (Manual Sync)** — режим работы ArgoCD Application, при котором автоматическое применение изменений отключено. Контроллер отслеживает состояние ресурсов и сигнализирует о расхождениях (статус `OutOfSync`), но не вносит изменения в кластер до явного действия пользователя.

**Селективная синхронизация (Selective Sync)** — возможность ручного выбора подмножества ресурсов внутри одного Application для применения изменений, оставляя остальные ресурсы в текущем состоянии.

**Dry Run (Пробный запуск)** — режим синхронизации, при котором ArgoCD имитирует применение манифестов и возвращает результат (успех или ошибка), не изменяя фактическое состояние ресурсов в кластере.

## Базовые концепции

### Особенности ручного режима

Ручная синхронизация является режимом по умолчанию для ArgoCD. Если в манифесте `Application` не определена секция `syncPolicy.automated`, приложение требует ручного вмешательства для деплоя.

**Преимущества:**
- **Полный контроль:** Оператор может проверить каждое изменение перед его применением.
- **Безопасность:** Исключается риск автоматического удаления ресурсов (Pruning) или перезаписи критических данных без проверки.
- **Гибкость:** Возможность синхронизировать только определенные компоненты системы в случае аварии или частичного обновления.

### Методы проверки расхождений

Перед выполнением ручной синхронизации критически важно провести аудит изменений:
1.  **UI Diff:** Визуальное сравнение YAML-манифестов в веб-интерфейсе ArgoCD.
2.  **CLI Diff:** Команда `argocd app diff`, показывающая текстовое различие (аналог `kubectl diff`).
3.  **App Details:** Проверка статуса каждого ресурса (например, `Missing`, `OutOfSync`).

## Практические сценарии

### Сценарий 1: Базовая синхронизация через манифест

Если автоматизация не требуется, секция `syncPolicy` может быть пустой или содержать только общие опции.

```yaml
spec:
  syncPolicy:
    syncOptions:
    - CreateNamespace=true
    - Validate=true
```

### Сценарий 2: Селективная синхронизация через CLI

Иногда требуется обновить только один ресурс (например, `ConfigMap`), не затрагивая работающие `Deployment`.

```bash
# Синхронизация только конкретного ресурса
argocd app sync my-app --resource apps:Deployment:my-deploy
argocd app sync my-app --resource :ConfigMap:my-config

# Синхронизация по меткам (labels)
argocd app sync my-app --label app.kubernetes.io/instance=my-app
```

### Сценарий 3: Проверка изменений (Dry Run)

Рекомендуется выполнять перед применением изменений в Production-средах.

```bash
# Проверка возможности синхронизации без применения
argocd app sync my-app --dry-run
```

### Сценарий 4: Принудительное удаление (Pruning) при ручной синхронизации

По умолчанию ручная синхронизация не удаляет ресурсы, которые исчезли из Git. Для их удаления нужно явно указать флаг.

```bash
# Синхронизация с удалением устаревших ресурсов
argocd app sync my-app --prune
```

### Сценарий 5: Откат к предыдущей версии (Rollback)

Хотя ArgoCD ориентирован на Git как источник истины, ручной откат позволяет быстро вернуться к предыдущему успешному состоянию (Sync Result) в случае сбоя.

```bash
# Просмотр истории синхронизаций
argocd app history my-app

# Откат к ID версии 4
argocd app rollback my-app 4
```
