# ArgoCD — автоматическая синхронизация

## Определения

**Автоматическая синхронизация (Automated Sync)** — режим работы ArgoCD, при котором контроллер автоматически применяет изменения из Git к кластеру при обнаружении расхождений (`OutOfSync`). Это позволяет реализовать классический GitOps-цикл без ручного вмешательства.

**Self-Heal (Автоматическое исправление)** — механизм, который отслеживает ручные изменения в кластере (Manual Drift) и автоматически возвращает состояние ресурсов к эталонному виду, описанному в Git.

**Prune (Удаление лишнего)** — процесс автоматического удаления ресурсов из Kubernetes, если соответствующие манифесты были удалены из Git-репозитория.

**Sync Options (Опции синхронизации)** — набор флагов, уточняющих поведение ArgoCD при применении манифестов (например, использование Server-Side Apply или пропуск валидации).

## Базовые концепции

### Преимущества и сценарии использования

Автоматическая синхронизация критически важна для:
- **Скорости доставки (Time-to-Market):** исключает задержки на ручное подтверждение в Dev/Staging.
- **Устранения дрейфа конфигурации:** гарантирует, что кластер всегда соответствует репозиторию, предотвращая "партизанские" правки через `kubectl edit`.
- **Масштабируемости:** позволяет управлять сотнями микросервисов, не требуя ручного деплоя каждого.

### Механика работы контроллера

1.  **Reconciliation Loop:** ArgoCD периодически сравнивает `Live State` (кластер) и `Desired State` (Git).
2.  **Детекция изменений:** если обнаружен статус `OutOfSync`, контроллер проверяет наличие секции `automated`.
3.  **Применение (Apply):** ArgoCD инициирует процесс `Sync`, применяя обновленные манифесты с учетом заданных `syncOptions`.

## Практические сценарии

### Настройка эталонной политики для Production

Для стабильной работы в высоконагруженных или мульти-теннантных окружениях рекомендуется использовать расширенный набор опций.

```yaml
spec:
  syncPolicy:
    automated:
      prune: true             # Удалять ресурсы, удаленные из Git
      selfHeal: true          # Исправлять ручные правки в кластере
      allowEmpty: false       # Защита от удаления всего при пустом репозитории
    syncOptions:
    - CreateNamespace=true       # Создать Namespace, если он отсутствует
    - ServerSideApply=true       # Использовать SSA для управления сложными полями
    - FailOnSharedResource=true  # Ошибка, если ресурс уже управляется другим Application
    - RespectIgnoreDifferences=true # Не перезаписывать поля, указанные в ignoreDifferences
    - ApplyOutOfSyncOnly=true    # Синхронизировать только изменившиеся ресурсы (оптимизация)
    - PruneLast=true             # Удалять старые ресурсы только после успеха новых
    retry:
      limit: 5                   # Количество попыток при сбое
      backoff:
        duration: 5s             # Начальная задержка
        factor: 2                # Множитель задержки
        maxDuration: 3m          # Максимальная задержка
```

### Сценарий 1: Защита от конфликтов (FailOnSharedResource)

В больших организациях разные команды могут случайно использовать один и тот же `ConfigMap` или `Service`.
- **Проблема:** Команда А и Команда Б имеют приложения, управляющие одним и тем же ресурсом. Они начинают "перетягивать" состояние ресурса друг на друга.
- **Решение:** Опция `FailOnSharedResource=true`. ArgoCD выдаст ошибку, если обнаружит, что ресурс уже помечен (через аннотации/лейблы) как принадлежащий другому приложению.

### Сценарий 2: Оптимизация больших приложений (ApplyOutOfSyncOnly)

Если ваше приложение состоит из 500+ ресурсов (например, большой Helm-чарт).
- **Проблема:** При каждом изменении одного `Deployment` ArgoCD по умолчанию пытается применить (apply) все 500 ресурсов, что создает нагрузку на API K8s.
- **Решение:** Опция `ApplyOutOfSyncOnly=true`. ArgoCD отправит запросы только для тех объектов, чье состояние в кластере отличается от Git.

### Сценарий 3: Совместная работа с HPA

- **Проблема:** HPA меняет количество реплик. ArgoCD видит `OutOfSync` и при включенном `SelfHeal` пытается вернуть значение из Git.
- **Решение:** Использовать комбинацию настроек:
    1.  Включить `RespectIgnoreDifferences=true` в `syncOptions`.
    2.  Настроить [ignoreDifferences](../ignore_differences.md) для поля `spec.replicas`.

## Дополнительная информация

### Ограничения и риски

- **Каскадное удаление:** Будьте осторожны с `prune: true` при массовом рефакторинге (например, переименовании папок в Git). Это может привести к одновременному удалению множества ресурсов.
- **Зависимости:** Автосинхронизация не всегда учитывает сложные зависимости между ресурсами. В таких случаях используйте [Sync Waves и Hooks](./sync_waves_hooks.md).
