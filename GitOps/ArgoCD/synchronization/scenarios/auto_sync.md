# ArgoCD — автоматическая синхронизация

## Определения

**Auto-Sync (Automated Sync)** — режим работы ArgoCD, при котором контроллер автоматически применяет изменения из Git-репозитория к кластеру при обнаружении расхождений (OutOfSync).

**Self-Heal** — механизм автоматического исправления дрейфа конфигурации (Manual Drift), когда ArgoCD возвращает состояние ресурса в кластере к описанному в Git.

**Prune** — процесс автоматического удаления ресурсов в кластере, которые были удалены из Git-репозитория.

## Базовые концепции

Автоматическая синхронизация позволяет реализовать полноценный GitOps-цикл, где Git является основным источником достоверных данных, а изменения в инфраструктуре происходят без ручного вмешательства.

### Когда использовать

- **Dev/Staging-окружения:** для максимальной скорости доставки изменений.
- **Приложения с высокой частотой развёртываний:** где ручное подтверждение становится узким местом.
- **Инфраструктурные компоненты:** работающие по модели "установил и забыл".

### Механика работы

1. ArgoCD обнаруживает расхождение между Git и кластером.
2. Если включен `automated sync`, контроллер инициирует операцию `Sync`.
3. По умолчанию ArgoCD не удаляет ресурсы и не исправляет ручные изменения в кластере, если не включены соответствующие опции (`prune` и `selfHeal`).

## Практические сценарии

### Настройка автоматической синхронизации

Конфигурация задается в секции `syncPolicy` ресурса `Application`.

```yaml
spec:
  syncPolicy:
    automated:
      prune: true      # Удалять ресурсы, отсутствующие в Git
      selfHeal: true   # Исправлять ручные изменения в кластере
      allowEmpty: false # Запретить удаление всех ресурсов при пустом Git
    syncOptions:
    - CreateNamespace=true        # Создать namespace, если его нет
    - ServerSideApply=true        # Использовать Server-Side Apply
    - PrunePropagationPolicy=foreground # Политика удаления зависимых ресурсов
    - PruneLast=true              # Удалять ресурсы в конце цикла синхронизации
    - RespectIgnoreDifferences=true # Учитывать ignoreDifferences при синхронизации
```

### Ключевые параметры syncOptions

| Опция | Описание | Применение |
| :--- | :--- | :--- |
| `CreateNamespace=true` | Автоматически создает целевой Namespace перед деплоем. | Если Namespace не управляется отдельно. |
| `ServerSideApply=true` | Использует механизм K8s SSA вместо `kubectl apply`. | Для работы с большими объектами или конфликтами полей. |
| `PruneLast=true` | Удаление происходит после того, как новые ресурсы станут Healthy. | Для минимизации Downtime. |
| `Replace=true` | Использует `kubectl replace` вместо `apply`. | Для ресурсов, не поддерживающих частичное обновление. |
| `Validate=false` | Отключает валидацию манифестов перед применением. | Если манифесты содержат специфические для плагинов расширения. |

## Дополнительная информация

### Ограничения и особенности

- **Retry Logic:** При неудачной синхронизации ArgoCD делает несколько попыток с экспоненциальной задержкой. Настройку можно изменить через `automated.retry`.
- **Ignore Differences:** Чтобы автоматическая синхронизация не срабатывала на специфические поля (например, `replicas` у HPA), используйте настройки [ignoreDifferences](../ignore_differences.md).
