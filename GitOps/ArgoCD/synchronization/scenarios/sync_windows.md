# Argo CD — окна синхронизации

> **Актуальность (2026):** В версии Argo CD v3.x управление окнами синхронизации стало более гибким благодаря поддержке часовых поясов (IANA Time Zones) и расширенному сопоставлению ресурсов через `andOperator`. Механизм остается ключевым инструментом для обеспечения безопасности деплоя в критические периоды (праздники, ночные смены).

## Определения

**Окна синхронизации (Sync Windows)** — функционал Argo CD, позволяющий регламентировать время выполнения операций синхронизации (автоматических и ручных) на основе расписания. Политики окон настраиваются в объекте **AppProject**.

**Deny Window (Запрещающее окно)** — интервал времени, в течение которого любые попытки синхронизации будут заблокированы. Используется для "заморозки" инфраструктуры.

**Allow Window (Разрешающее окно)** — интервал времени, в течение которого деплой разрешен. Важно: если в проекте определено хотя бы одно окно `Allow`, синхронизация возможна **только** в периоды активности таких окон.

**Sync Overrun** — параметр, позволяющий синхронизации, начатой *внутри* разрешенного окна, успешно завершиться, даже если время окна истекло в процессе деплоя.

## Базовые концепции

### Иерархия и логика проверки (Precedence)

При проверке возможности деплоя Argo CD следует алгоритму:
1.  **Deny приоритетнее всего:** Если текущее время попадает в активное окно `kind: deny`, синхронизация запрещена безусловно.
2.  **Обязательность Allow:** Если в проекте есть хотя бы одно правило `kind: allow`, текущее время должно совпадать хотя бы с одним из них. Если правил `allow` нет, считается, что деплой разрешен всегда (при условии отсутствия `deny`).
3.  **Manual Sync:** Флаг `manualSync: true` позволяет операторам выполнять ручную синхронизацию в UI/CLI даже в запрещенные периоды (полезно для экстренных фиксов).

### Параметры конфигурации (AppProject)

| Параметр | Описание |
| :--- | :--- |
| `kind` | Тип окна: `allow` или `deny`. |
| `schedule` | Расписание в формате Cron (`0 22 * * 5-7`). |
| `duration` | Длительность окна (например, `2h`, `30m`). |
| `timeZone` | Часовой пояс (например, `Europe/Moscow`). По умолчанию используется время сервера Argo CD. |
| `applications` | Список приложений или масок (`prod-*`). |
| `namespaces` | Целевые пространства имен в Kubernetes. |
| `clusters` | Названия или URL целевых кластеров. |
| `andOperator` | Если `true`, окно применится только при совпадении всех условий (App AND Namespace AND Cluster). |

## Практические сценарии

### Сценарий 1: Глобальная заморозка (Code Freeze)

Блокировка всех изменений на время новогодних праздников для всех приложений проекта.

```yaml
apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: production-project
spec:
  syncWindows:
  - kind: deny
    schedule: '0 0 31 12 *' # 31 декабря
    duration: 168h        # 7 дней
    timeZone: "Europe/Moscow"
    applications: ["*"]
    manualSync: false     # Даже админы не смогут деплоить вручную
```

### Сценарий 2: Окна обслуживания (Maintenance Windows)

Разрешить деплой только в рабочие часы по будням.

```yaml
spec:
  syncWindows:
  - kind: allow
    schedule: '0 10 * * 1-5' # Пн-Пт с 10:00
    duration: 8h
    timeZone: "Europe/Prague"
    applications: ["*-api"]
    manualSync: true         # Ручной деплой разрешен вне окна для хотфиксов
```

### Сценарий 3: Защита от прерывания длинных деплоев

Если деплой занимает 15 минут, а до конца окна осталось 5 минут, параметр `syncOverrun` предотвратит прерывание процесса.

```yaml
spec:
  syncWindows:
  - kind: allow
    schedule: '30 23 * * *' # Ежедневно в 23:30
    duration: 1h
    syncOverrun: true      # Разрешить завершение после 00:30
```

## Технические нюансы и ограничения

### Визуальная индикация
В интерфейсе Argo CD активные окна отображаются индикаторами:
- **Красный баннер:** Синхронизация заблокирована (на странице приложения и в настройках проекта).
- **Зеленый баннер:** Синхронизация разрешена (только если есть окна `Allow`).

### Особенности часовых поясов
Всегда явно указывайте `timeZone`. В мульти-региональных командах это предотвращает путаницу, когда расписание Cron срабатывает в неожиданное время из-за настроек системного времени в поде `argocd-application-controller`.
