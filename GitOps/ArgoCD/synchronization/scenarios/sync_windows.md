# ArgoCD — окна синхронизации

## Определения

**Окна синхронизации (Sync Windows)** — механизм в ArgoCD, позволяющий ограничивать выполнение синхронизации (автоматической или ручной) на основе временного расписания. Настройки окон определяются на уровне `AppProject`.

**Deny Window (Запрещающее окно)** — временной интервал, в течение которого синхронизация ресурсов запрещена.

**Allow Window (Разрешающее окно)** — временной интервал, в течение которого синхронизация ресурсов разрешена. Если в проекте определены какие-либо `Allow` окна, то вне этих окон синхронизация будет заблокирована.

## Базовые концепции

### Иерархия и приоритеты (Precedence)

ArgoCD применяет логику "Deny-First" при оценке окон:
1.  **Deny приоритетнее Allow:** Если приложение попадает под активное окно `Deny`, синхронизация блокируется, даже если в это же время активно окно `Allow`.
2.  **Условие Allow:** Если в проекте создано хотя бы одно окно `Allow`, для выполнения синхронизации одно из таких окон обязательно должно быть активно. Если окон `Allow` нет вообще, синхронизация разрешена всегда (при отсутствии активных `Deny`).
3.  **Отсутствие окон:** Если приложение не попадает ни под одно из существующих окон, синхронизация разрешена.

### Параметры конфигурации

| Параметр | Описание |
| :--- | :--- |
| **kind** | Тип окна: `allow` или `deny`. |
| **schedule** | Расписание в формате Cron. |
| **duration** | Длительность действия (например, `1h`, `30m`). |
| **timeZone** | Часовой пояс (например, `Europe/Moscow`). Важно для корректного учета перехода на летнее/зимнее время. |
| **applications** | Список имен приложений или маски (например, `prod-*`). |
| **namespaces** | Список целевых пространств имен Kubernetes. |
| **clusters** | Список целевых кластеров. |
| **manualSync** | Если `true`, ручная синхронизация разрешена даже во время действия запрета. |

### Точечное сопоставление (andOperator)

В новых версиях (v2.11+) доступен параметр `andOperator`. Если он установлен в `true`, окно применится только в том случае, если приложение соответствует имени **И** пространству имен **И** кластеру одновременно. По умолчанию используется логика `OR` (соответствие любому из фильтров).

## Практические сценарии

### Сценарий 1: Режим "Заморозки кода" (Code Freeze)

Запрет любых изменений на праздничные дни (например, с 31 декабря по 8 января).

```yaml
spec:
  syncWindows:
  - kind: deny
    schedule: '0 0 31 12 *'
    duration: 216h # 9 дней
    timeZone: "Europe/Moscow"
    applications:
    - '*'
    manualSync: false # Полная блокировка, даже для администраторов
```

### Сценарий 2: Технологические окна обслуживания (Maintenance Windows)

Разрешить деплой только в будни в рабочее время.

```yaml
spec:
  syncWindows:
  - kind: allow
    schedule: '0 10 * * 1-5' # Пн-Пт с 10:00
    duration: 8h
    timeZone: "Europe/Moscow"
    applications:
    - '*-prod'
    manualSync: true # В экстренных случаях можно деплоить вручную вне окна
```

### Сценарий 3: Предотвращение прерывания начатой синхронизации (syncOverrun)

Чтобы синхронизация, начатая за минуту до закрытия окна `Allow`, не была прервана, в конфигурацию можно добавить параметр `syncOverrun: true` (доступно в манифестах AppProject).

## Дополнительная информация

### Визуализация в UI
Когда окно синхронизации активно, в интерфейсе ArgoCD на уровне приложения и проекта отображаются соответствующие индикаторы (красный/зеленый баннеры), поясняющие, почему синхронизация заблокирована.
