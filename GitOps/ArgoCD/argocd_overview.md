# ArgoCD — декларативный CI/CD для Kubernetes

> **Актуальная версия:** v3.3 (февраль 2026). Установка: `kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml`

См. также: [Сравнение с Flux](../argo_vs_flux_manifests.md), [Установка и настройка](./argocd_installation_and_setup.md), [Troubleshooting](./argocd_troubleshooting_and_monitoring.md)

## Определения

**ArgoCD** — это декларативный [GitOps-инструмент](../GitOps_overview.md) непрерывной доставки (CD) для Kubernetes. Он автоматизирует развертывание приложений и синхронизирует состояние кластера с Git-репозиторием, который выступает как авторитетный источник конфигурации.

## Базовые концепции

### Для чего нужен ArgoCD?

- **Автоматизация развертывания:** устраняет ручное управление развертыванием через `kubectl apply`.
- **Мониторинг расхождений:** постоянно следит за расхождением между состоянием Git и кластера и корректирует его при необходимости.
- **Мультикластерность:** работает с несколькими кластерами (по умолчанию видит кластер, на котором установлен, остальные нужно добавлять).
- **Контроль версий:** все изменения проходят через Git, обеспечивая полный аудит.
- **Поддержка форматов:** работает со стандартными Kubernetes-манифестами, Helm-чартами и Kustomize.

### Особенности ArgoCD

- **Веб-интерфейс:** позволяет визуально отслеживать состояние приложений, просматривать манифесты, логи подов и события.
- **CLI:** предоставляет расширенные возможности управления через командную строку.
- **Интеграция с RBAC:** возможность управления правами доступа пользователей к приложениям и кластерам.
- **ApplicationSet:** автоматическое создание приложений на основе шаблонов. Позволяет управлять группами приложений или развертывать одно приложение на нескольких кластерах. Генератор `git` с `directories` автоматически создаёт Application для каждой директории в репозитории (см. [Практические сценарии Helm](../../Kubernetes/ToolsUtilities/Helm/helm_chart_practical_scenarios.md)).
- **Интеграция с CI-инструментами:** ArgoCD выполняет роль CD, CI-инструменты (например, GitLab CI) — роль CI. CI-пайплайн меняет тег образа в Git, а ArgoCD синхронизирует изменения.
- **Система уведомлений:** отправка оповещений о событиях в Slack, Telegram, Email через компонент **[ArgoCD Notifications](./argocd_notifications.md)**.

### Ключевой принцип: Двунаправленная синхронизация

ArgoCD не только применяет изменения из Git в кластер, но и отслеживает состояние ресурсов в самом кластере. Это позволяет обнаруживать "дрейф конфигурации" и автоматически восстанавливать желаемое состояние. Подробности см. в разделе **[Синхронизация в ArgoCD](./synchronization.md)**.

### Ключевые компоненты

Архитектура ArgoCD состоит из нескольких ключевых сервисов:

- **ArgoCD Server (`argocd-server`):** предоставляет веб-интерфейс и API для управления системой.
- **ArgoCD Repo Server (`argocd-repo-server`):** отвечает за клонирование Git-репозиториев, кеширование манифестов и их обработку (например, рендеринг Helm-чартов).
- **ArgoCD Application Controller (`argocd-application-controller`):** основной компонент, который следит за состоянием приложений и выполняет синхронизацию.
- **ArgoCD Dex Server (`argocd-dex-server`):** встроенный компонент [Dex](https://dexidp.io/) для аутентификации через внешние IdP (LDAP, SAML, GitHub).
- **Redis (`argocd-redis`):** используется для кеширования состояния кластера и данных о приложениях.

### Манифест Application

ArgoCD Application — это Kubernetes-ресурс, который описывает источник конфигурации и целевой кластер.

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/argoproj/argocd-example-apps.git # URL Git-репозитория
    targetRevision: HEAD # Ветка, тег или коммит
    path: guestbook # Путь к манифестам в репозитории
  destination:
    server: https://kubernetes.default.svc # Целевой кластер
    namespace: guestbook # Целевой неймспейс
  syncPolicy:
    automated:
      prune: true # Удалять ресурсы, отсутствующие в Git
      selfHeal: true # Восстанавливать изменения, внесенные вне Git
    syncOptions:
    - CreateNamespace=true # Создать неймспейс, если он не существует
```

### Синхронизация в ArgoCD

ArgoCD поддерживает автоматический и ручной режимы синхронизации манифестов. Детальное описание политик доступно в документе **[ArgoCD: Синхронизация и её политики](./synchronization.md)**.

### Управление секретами

Для безопасного хранения секретов в Git требуются сторонние инструменты:

- **[Sealed Secrets](../../Kubernetes/Security/sealed_secrets_overview.md)**: шифрует секреты в Git, которые расшифровывает контроллер в кластере.
- **[HashiCorp Vault (AVP)](./argocd_vault_integration.md)**: интеграция через плагин `argo-vault-plugin`.
- **[SOPS](../../Security/Tools/sops_overview.md)**: шифрование значений в YAML/JSON файлах.

### ArgoCD Image Updater

Компонент для автоматического обновления образов контейнеров (v0.18.0).

**Принцип работы:**
1. Мониторит Docker Registry на наличие новых тегов.
2. Обновляет манифесты в Git при обнаружении новых версий.
3. ArgoCD синхронизирует изменения.

Подробнее об обновлении образов — [GitOps: Образы контейнеров](../Concepts/containerization_and_image_storage.md).

## Дополнительная информация

### Ключевые изменения в версии v3.x

- **PreDelete Hooks** (v3.3): запуск Jobs перед удалением приложения.
- **OIDC Refresh**: обновление сессий без таймаутов.
- **Granular RBAC**: детальный контроль доступа к ресурсам.
- **Progressive Sync**: постепенное развёртывание на несколько кластеров.
- **Server-Side Apply**: улучшенная обработка конфликтов.

### Стратегии развертывания

- **Canary Deployment:** постепенный переход трафика к новой версии.
- **Blue/Green Deployment:** мгновенное переключение трафика на новую версию.
