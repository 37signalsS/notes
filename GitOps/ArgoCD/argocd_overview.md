# ArgoCD: Декларативный CI/CD для Kubernetes

> **Актуальная версия:** v3.3 (февраль 2026). Установка: `kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml`

См. также: [Сравнение с Flux](../argo_vs_flux_manifests.md), [Установка и настройка](./argocd_installation_and_setup.md), [Troubleshooting](./argocd_troubleshooting_and_monitoring.md).

## Определения

**ArgoCD** — это декларативный [GitOps-инструмент](../GitOps_overview.md) непрерывной доставки (CD) для Kubernetes. Он автоматизирует развертывание приложений и синхронизирует состояние кластера с Git-репозиторием, который выступает как единственный источник истины (Single Source of Truth).

## Базовые концепции

### Для чего нужен ArgoCD?

- **Автоматизация Развертывания:** Устраняет ручное управление развертыванием через `kubectl apply`.
- **Мониторинг Расхождений:** Постоянно следит за расхождением между состоянием Git и кластера и корректирует его при необходимости.
- **Мультикластерность:** Работает с несколькими кластерами (по умолчанию видит кластер, на котором установлен, остальные нужно добавлять).
- **Контроль Версий:** Все изменения проходят через Git, обеспечивая полный контроль версий.
- **Поддержка Форматов:** Работает со стандартными Kubernetes-манифестами, Helm-чартами и Kustomize. Поддержка Helm и Kustomize особенно полезна для параметризации манифестов, Helm рекомендуется для больших проектов, Kustomize — для небольших.

### Особенности ArgoCD

- **Веб-интерфейс:** Позволяет визуально отслеживать состояние приложений, просматривать манифесты, логи подов и события, что очень удобно для мониторинга.
- **CLI:** Предоставляет расширенные возможности управления через командную строку.
- **Интеграция с RBAC:** Возможность управления правами доступа пользователей к приложениям и кластерам.
- **ApplicationSet (App of Apps):** Автоматическое создание приложений на основе шаблонов. Позволяет управлять группами приложений или развертывать одно приложение на нескольких кластерах из одного `ApplicationSet` манифеста, значительно повышая уровень абстракции.
- **Интеграция с CI-инструментами:** ArgoCD выполняет роль CD, CI-инструменты (например, GitLab CI) — роль CI (сборка, тестирование). CI-пайплайн может менять тег образа в манифестах в Git-репозитории, а ArgoCD автоматически подхватит это изменение и развернет новую версию.
- **Система уведомлений:** Возможность отправлять уведомления о событиях жизненного цикла приложений (успех/ошибка синхронизации, изменение статуса) в Slack, Telegram, Email и др. через компонент **[ArgoCD Notifications](./argocd_notifications.md)**.

### Ключевой принцип: Двунаправленная синхронизация

Основное отличие ArgoCD от многих других инструментов CI/CD — его способность к **двунаправленной синхронизации**.

1. **Git → Кластер:** Как и большинство CD-инструментов, ArgoCD отслеживает изменения в Git-репозитории и применяет их к кластеру.
2. **Кластер → Git:** Уникальная особенность ArgoCD заключается в том, что он также отслеживает состояние развернутых приложений **в самом кластере**. Если кто-то вносит изменения в кластер вручную (например, через `kubectl edit`), ArgoCD обнаруживает это расхождение (`OutOfSync`). В зависимости от настроек (`selfHeal`), он может автоматически **откатить** эти изменения, возвращая состояние приложения к тому, которое описано в Git.

Эта функция обеспечивает, что Git всегда остается единственным источником правды, и предотвращает неконтролируемые изменения в конфигурации.

### Ключевые компоненты

Архитектура ArgoCD состоит из нескольких ключевых сервисов, работающих как поды в Kubernetes:

- **ArgoCD Server (`argocd-server`):** Предоставляет веб-интерфейс и API для управления системой.
- **ArgoCD Repo Server (`argocd-repo-server`):** Отвечает за клонирование Git-репозиториев, кеширование манифестов и их обработку (например, рендеринг Helm-чартов).
- **ArgoCD Application Controller (`argocd-application-controller`):** Основной компонент, который следит за состоянием приложений, сравнивает его с манифестами из Git и выполняет синхронизацию.
- **ArgoCD Dex Server (`argocd-dex-server`):** Встроенный компонент [Dex](https://dexidp.io/), который используется для аутентификации через внешние IdP (LDAP, SAML, GitHub, и др.). ArgoCD также поддерживает собственных локальных пользователей.
- **Redis (`argocd-redis`):** Используется для кеширования состояния кластера и данных о приложениях, что ускоряет операции сравнения и предотвращает перегрузку Kubernetes API.

### Манифест `Application`

ArgoCD Application — это Kubernetes-ресурс, который описывает, откуда брать конфигурацию приложения (Git-репозиторий, путь, ветка/тег) и куда его развертывать (целевой кластер, неймспейс).

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/argoproj/argocd-example-apps.git # URL Git-репозитория
    targetRevision: HEAD # Ветка, тег или коммит. Для тестирования может быть указана конкретная ветка разработчика.
    path: guestbook # Путь к манифестам в репозитории
  destination:
    server: https://kubernetes.default.svc # Целевой кластер (kubernetes.default.svc для текущего)
    namespace: guestbook # Целевой неймспейс
  syncPolicy:
    automated:
      prune: true # Удалять ресурсы, отсутствующие в Git (при удалении Application - удаляет все его ресурсы)
      selfHeal: true # Восстанавливать изменения, внесенные вне Git (удаленные вручную объекты будут восстановлены)
    syncOptions:
    - CreateNamespace=true # Создавать неймспейс, если он не существует
```

### Синхронизация в ArgoCD

- **Автоматическая (`syncPolicy.automated: true`):** Изменения в Git немедленно применяются к кластеру. ArgoCD постоянно опрашивает Git-репозиторий на предмет изменений.
- **Ручная:** Пользователь подтверждает развертывание через веб-интерфейс или CLI.

### Управление секретами

По умолчанию ArgoCD не работает с зашифрованными секретами напрямую. Для безопасного хранения секретов в Git (Secrets-in-Git) требуются сторонние инструменты:

- **[Sealed Secrets](../../Kubernetes/Security/sealed_secrets_overview.md)**: Шифрует секреты в Git, которые может расшифровать только контроллер в кластере.
- **[HashiCorp Vault (AVP)](./argocd_vault_integration.md)**: Интеграция через плагины, например, `argo-vault-plugin`.
- **[SOPS (Secrets OPerationS)](../../Security/Tools/sops_overview.md)**: Позволяет шифровать значения в YAML/JSON файлах.

### ArgoCD Image Updater

**ArgoCD Image Updater** (текущая версия: v0.18.0, декабрь 2025) — дополнительный компонент для автоматического обновления образов контейнеров.

**Принцип работы:**

1. Мониторит Docker Registry на наличие новых тегов образов
2. Обновляет манифесты в Git-репозитории при обнаружении новых версий
3. ArgoCD автоматически синхронизирует изменения

**Пример аннотаций для Application:**

```yaml
metadata:
  annotations:
    argocd-image-updater.argoproj.io/image-list: my-app=my-registry/my-app
    argocd-image-updater.argoproj.io/my-app.update-strategy: semver
    argocd-image-updater.argoproj.io/my-app.allow-tags: regexp:^v[0-9]+\.[0-9]+\.[0-9]+$
```

**Стратегии обновления:**

- `semver`: Обновление по семантической версии
- `latest`: Последний тег (не рекомендуется для production)
- `digest`: Обновление по хешу образа
- `name`: Сортировка по имени тега

Подробнее об обновлении образов — [GitOps: Образы контейнеров и их жизненный цикл](../Concepts/containerization_and_image_storage.md).

## Дополнительная информация

### Ключевые изменения в v3.x

- **PreDelete Hooks** (v3.3): Запуск Jobs перед удалением приложения для безопасного завершения работы
- **OIDC Refresh**: Обновление сессий без таймаутов
- **Granular RBAC**: Whitelist имён ресурсов для детального контроля доступа
- **Hydrator**: Улучшенная работа с Helm-чартами и Kustomize
- **Progressive Sync**: Постепенное развёртывание на несколько кластеров с валидацией
- **Server-Side Apply**: Улучшенная обработка конфликтов при синхронизации

### Стратегии Развертывания

- **Canary Deployment:** Постепенный переход трафика от старой версии к новой, с возможностью мониторинга и отката.
- **Blue/Green Deployment:** Резкий переход трафика на новую версию с возможностью быстрого отката к предыдущей.
