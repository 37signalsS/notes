# GitOps: Обзор Методологии

## Что такое GitOps?

**GitOps** — это методология управления инфраструктурой и приложениями, где Git-репозиторий является единственным источником истины (Single Source of Truth) для всей конфигурации. Основная цель — развертывание приложений в Kubernetes, при этом GitOps охватывает аспекты непрерывного развертывания/доставки (Continuous Deployment/Delivery) из CI/CD. Все изменения (конфигурация, код, манифесты) фиксируются в Git.

### Модели Развертывания

*   **Push Model (Традиционный CI/CD):** Инструменты CI/CD (GitLab CI, GitHub Actions, Jenkins) инициируют сборку и развертывание.
*   **Pull Model (GitOps):** Оператор (например, ArgoCD) непрерывно мониторит Git-репозиторий, извлекает изменения и развертывает их в кластере. Синхронизация происходит периодически, что снижает прямое взаимодействие с кластером.

### Принципы GitOps

1.  **Декларативность:** Состояние системы описано в виде файлов (например, YAML-манифесты для Kubernetes), что реализует концепцию Infrastructure as Code.
2.  **Управление Версиями и Аудит:** Git обеспечивает полную историю изменений, контроль версий, возможность отката к любой предыдущей версии и код-ревью через Pull/Merge Requests, повышая прозрачность и ответственность.
3.  **Автоматическая Синхронизация:** Инструменты GitOps постоянно сравнивают желаемое состояние (в Git) с фактическим состоянием кластера. При обнаружении расхождений они автоматически применяют необходимые обновления.
4.  **Самовосстановление (Self-Healing):** Если фактическое состояние кластера отклоняется от желаемого (например, из-за несанкционированного удаления ресурса), GitOps-инструменты автоматически восстанавливают его в соответствии с конфигурацией в Git.

### Преимущества GitOps

*   **Надежность:** Кластер можно восстановить до рабочего состояния из Git-репозитория, что упрощает аварийное восстановление.
*   **Прозрачность:** Все изменения видны, доступны для код-ревью. Конфигурации хранятся в централизованном репозитории, обеспечивая единый источник истины.
*   **Безопасность:** Меньше прямого взаимодействия с кластером, что снижает риск случайных или злонамеренных изменений. Все изменения проходят через Git-репозиторий.
*   **Скорость:** Автоматизация сокращает ручные операции, ускоряя циклы развертывания.
*   **Мультикластерность:** Возможность развертывания приложений на нескольких кластерах (dev, staging, prod) из одного источника.

### Недостатки GitOps

*   **Управление Секретами:** ArgoCD по умолчанию не умеет работать с файлами секретов напрямую. Требуются сторонние инструменты (например, `Sealed Secrets` для шифрования секретов в Git) или интеграция с внешними хранилищами секретов (например, Vault с плагином `argo-vault`).
*   **Зависимость от Git:** Git является критически важным компонентом. В случае недоступности Git система не будет функционировать. Необходимы регулярные бэкапы Git-репозитория.
*   **Строгий Регламент:** Любые изменения в инфраструктуре должны проходить через Git. Прямое изменение состояния кластера будет откачено GitOps-инструментом.
*   **Ограниченная динамичность:** Добавление нового окружения может потребовать ручного редактирования Git-репозитория и добавления дополнительных веток/конфигураций.

### Инструменты GitOps

*   **ArgoCD** — разработан исключительно для Kubernetes. Подробнее в заметке [ArgoCD](./ArgoCD.md).
*   **Flux** — более гибкий инструмент, может быть интегрирован с другими системами оркестрации, но имеет менее дружелюбный UI "из коробки".
*   **Crossplane** — расширяет GitOps для управления облачной инфраструктурой (IaC) через Kubernetes API. Подробнее в заметке [Crossplane: Управление облачной инфраструктурой](./Crossplane.md).
