# Proxmox Backup Server (PBS)

## Определения

**Proxmox Backup Server (PBS)** — это специализированное корпоративное решение для резервного копирования и восстановления виртуальных машин, контейнеров и физических хостов. Поддерживает инкрементальные бэкапы с дедупликацией на стороне клиента, сжатие и надежное шифрование данных.

## Основные концепции

### Преимущества PBS перед классическими бэкапами (Vzdump)

- **Инкрементальные копии**: В классическом варианте Proxmox делает полные копии ВМ. PBS сохраняет только измененные блоки относительно предыдущего запуска, что в разы ускоряет процесс бэкапа и кардинально экономит место на диске.
- **Дедупликация**: На уровне хранилища (Data Store) одинаковые блоки (например, файлы базовой ОС в разных ВМ) сохраняются лишь единожды.
- **Шифрование**: Данные могут быть зашифрованы алгоритмом AES-256 на стороне клиента (Proxmox VE) до их передачи на PBS-сервер.
- **Live Restore**: Позволяет запустить ВМ практически мгновенно, считывая данные напрямую с PBS по сети, пока идет процесс полного восстановления диска в фоновом режиме.
- **File Restore**: PBS позволяет гранулярно восстанавливать отдельные файлы прямо из бэкапа ВМ или контейнера.

## Практические сценарии

### Подключение PBS к Proxmox VE

1. **На стороне PBS**:
   - Создать `Datastore` (директорию для хранения).
   - Создать пользователя и выдать права на Datastore.
   - Скопировать `Fingerprint` сертификата (`Dashboard -> Show Fingerprint`).
2. **На стороне PVE**:
   - Перейти в `Datacenter -> Storage -> Add -> Proxmox Backup Server`.
   - Ввести IP-адрес сервера, имя пользователя, пароль, Fingerprint и название Datastore.
3. **Настройка расписания**: Перейти в `Datacenter -> Backup`, создать новую задачу, выбрать хранилище PBS и настроить дни/время запуска.

### Обслуживание хранилища (Data Store)

Управление свободным местом и целостностью данных в PBS состоит из трех ключевых задач, которые рекомендуется планировать последовательно:

1. **Prune (Очистка устаревших бэкапов)**: Применяет политики хранения (Retention). Пример: хранить 7 последних ежедневных, 4 еженедельных и 3 ежемесячных копии. Prune удаляет из индексов ссылки на бэкапы, не подпадающие под политику хранения. Рекомендуется запускать на стороне сервера PBS.
2. **Garbage Collection (Сборка мусора)**: Физическое удаление "осиротевших" блоков данных из хранилища (чанки, на которые больше нет ссылок после работы Prune). Запускать следует по расписанию после завершения Prune (рекомендуется раз в сутки).
3. **Verify (Проверка)**: Процесс пересчета контрольных сумм всех чанков бэкапа для подтверждения их целостности и предотвращения скрытого повреждения данных (bit rot). Настраивается в `Verify Jobs` (например, проверка старых бэкапов каждые 30 дней) или включается автоматическая верификация для каждого нового снепшота (Verify New Snapshots).
