# Обновление систем Proxmox

## Определения

**Proxmox Virtual Environment (PVE)** — платформа виртуализации с открытым исходным кодом, основанная на Debian GNU/Linux.

**Proxmox Backup Server (PBS)** — специализированное решение для резервного копирования и восстановления виртуальных машин, контейнеров и физических хостов.

**In-place Upgrade (Обновление на месте)** — процесс мажорного обновления операционной системы без необходимости ее полной переустановки с сохранением всех пользовательских данных и конфигураций. В Proxmox VE и PBS этот процесс реализуется сменой репозиториев в менеджере пакетов `apt` и вызовом команды полной модернизации системы.

**GUI (Graphical User Interface)** — графический веб-интерфейс управления Proxmox.

## Основные концепции

### Типы репозиториев

В Proxmox доступно три основных типа репозиториев:

- **Enterprise Repository**: Платный репозиторий, наиболее стабильный и протестированный. Требует активной подписки. Используется по умолчанию в корпоративных средах.
- **No-Subscription Repository**: Рекомендуемый репозиторий для пользователей без платной подписки. Содержит те же пакеты, но с меньшим временем тестирования. Перед использованием необходимо вручную отключить Enterprise-репозиторий в GUI (`Node -> Repositories`).
- **Test Repository**: Содержит самые новые пакеты для тестирования. Категорически не рекомендуется для использования в продуктивной среде.

### Безопасное обновление (Best Practices)

- **Использование мультиплексоров терминала**: Перед мажорным апгрейдом (например, 7.x -> 8.x) запрещается использовать встроенный веб-терминал Proxmox, так как сервис веб-интерфейса (`pveproxy`) будет перезапущен в процессе. Необходимо использовать SSH совместно со `screen` или `tmux`.
- **Освобождение места**: Для безопасного мажорного обновления рекомендуется иметь не менее 10 ГБ свободного пространства на корневом разделе (`/`).
- **Последовательность в кластере**: В кластерах с общими хранилищами (Shared Storage) или Ceph ноды обновляются поочередно. С обновляемой ноды предварительно мигрируются все виртуальные машины. Если используется Ceph, он должен быть обновлен до целевого релиза до начала обновления самой PVE.
- **Команды обновления**: Для патчей внутри текущей мажорной версии в Command Line Interface (CLI) следует использовать `apt dist-upgrade` или `apt full-upgrade`.
  - **Важно**: Использование обычного `apt upgrade` запрещено, так как оно не умеет изменять зависимости пакетов (удалять старые и устанавливать новые), что критично для ядра Proxmox.

## Практические сценарии

### Ежедневное обновление через GUI

1. Перейти в `Node -> Updates`.
2. Нажать `Refresh` для получения списка доступных пакетов.
3. Нажать `Upgrade`. Откроется окно терминала xterm.js, где будет выполнен процесс обновления.

### Проверка готовности к обновлению (pve8to9)

Перед переходом на новую мажорную версию необходимо запустить встроенный скрипт диагностики:

```bash
pve8to9 --full
# → System health check passed: OK
```

### Обновление мажорной версии Proxmox VE (CLI)

1. Обновить текущую систему до последнего минорного релиза:

   ```bash
   apt update && apt dist-upgrade
   ```

2. Заменить кодовое имя Debian в источниках (например, с `bookworm` на `trixie` для PVE 9):

   ```bash
   sed -i 's/bookworm/trixie/g' /etc/apt/sources.list
   ```

3. Выполнить финальное обновление:

   ```bash
   apt update && apt full-upgrade
   ```

### Модернизация репозиториев PBS (apt modernize-sources)

В новых версиях Proxmox Backup Server (начиная с 4.x) формат хранения репозиториев изменился на Debian DEB822 (`.sources` файлы).

Для автоматической конвертации старых `.list` файлов:

```bash
proxmox-backup-manager apt modernize-sources
# → Successfully modernized APT sources
```
