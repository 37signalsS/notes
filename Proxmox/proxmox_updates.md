# Обновление систем Proxmox

## Определения

**In-place Upgrade** — процесс мажорного обновления операционной системы без необходимости ее полной переустановки с сохранением всех пользовательских данных и конфигураций. В Proxmox VE и PBS этот процесс реализуется сменой apt-репозиториев и вызовом `apt full-upgrade`.

## Основные концепции

### Типы репозиториев

В Proxmox доступно три основных типа репозиториев:

- **Enterprise Repository**: Платный репозиторий, наиболее стабильный и протестированный. Требует активной подписки. Используется по умолчанию.
- **No-Subscription Repository**: Рекомендуемый репозиторий для пользователей без платной подписки. Содержит те же пакеты, но с меньшим временем тестирования. Перед использованием необходимо отключить Enterprise-репозиторий в GUI (`Node -> Repositories`).
- **Test Repository**: Содержит самые новые пакеты для тестирования. Не рекомендуется для использования в продакшене.

### Безопасное обновление (Best Practices)

- **Использование мультиплексоров терминала**: Перед мажорным апгрейдом категорически запрещается использовать встроенный веб-терминал Proxmox, так как сервис GUI (`pveproxy`) будет перезапущен. Обязательно использование SSH совместно со `screen` или `tmux`, чтобы процесс обновления не прервался при дисконнекте сессии.
- **Освобождение места**: Для безопасного обновления (например, с версии 8 на 9) рекомендуется иметь не менее 10 ГБ свободного пространства на root-разделе (минимум 5 ГБ).
- **Последовательность в кластере**: В кластерах с Shared Storage или Ceph ноды обновляются поочередно. С обновляемой ноды предварительно мигрируются все ВМ. Если используется Ceph, он должен быть обновлен до целевого релиза до старта обновления самой PVE.
- **Команды обновления**: Для обычных обновлений внутри мажорной версии в CLI всегда следует использовать `apt dist-upgrade` или `apt full-upgrade`. Обычный `apt upgrade` запрещен, так как он не удаляет старые зависимости и не устанавливает новые, что критично для ядра Proxmox.

## Практические сценарии

### Ежедневное обновление через GUI

1. Перейти в `Node -> Updates`.
2. Нажать `Refresh` для получения списка доступных пакетов.
3. Нажать `Upgrade`. Откроется окно терминала xterm.js, где будет выполнен процесс обновления. Это безопасный способ для рядовых патчей.

### Обновление мажорной версии Proxmox VE (с 8 до 9)

Процесс In-place обновления описан в официальной документации и включает следующие ключевые шаги:

1. Выполнение скрипта предварительной проверки: `pve8to9 --full`.
2. Замена репозиториев Debian (с `bookworm` на `trixie`) в `/etc/apt/sources.list` с помощью команды `sed`.
3. Замена репозиториев Proxmox VE и Ceph в `/etc/apt/sources.list.d/`.
4. Обновление списков пакетов (`apt update`) и выполнение самого процесса обновления (`apt full-upgrade` / `apt dist-upgrade`).

### Модернизация репозиториев PBS (apt modernize-sources)

В новых версиях Proxmox Backup Server изменился формат хранения репозиториев (Debian DEB822 формат). После обновления системы с версии 3 на 4 можно перевести все старые `.list` файлы в новый `.sources` формат с помощью встроенной утилиты: `apt-get update && proxmox-backup-manager apt modernize-sources`.
