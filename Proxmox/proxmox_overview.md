# Proxmox VE — Обзор и базовые концепции

## Определения

**Proxmox Virtual Environment (PVE)** — это бесплатная open-source платформа виртуализации корпоративного уровня на базе ОС Debian Linux. Proxmox предоставляет единый интерфейс управления для KVM-виртуальных машин, LXC-контейнеров, программно-определяемых сетей (SDN) и хранилищ данных.

## Основные концепции

### Установка и разбиение диска
При автоматической установке Proxmox на файловую систему ext4/XFS применяется следующая логика распределения пространства (LVM):
- **root_size**: 1/4 от общего объема диска (обычно не более 100 ГБ).
- **swap_size**: 1/8 от объема диска (минимум 4 ГБ, максимум 8 ГБ).
- **minfree**: Зарезервированное свободное место в LVM (по умолчанию 16 ГБ, если диск > 128 ГБ).
- **data_size**: Все оставшееся пространство выделяется под `LVM-Thin` для хранения дисков ВМ и контейнеров.

### Виртуальные машины (KVM)
Виртуальные машины в Proxmox обеспечивают полную аппаратную изоляцию за счет гипервизора KVM и эмулятора QEMU.
- **VirtIO-драйверы**: Для достижения максимальной производительности в Windows-машинах необходимо подключать дополнительный ISO-образ с драйверами (`virtio-win.iso`) во время установки.
- **QEMU Guest Agent**: Позволяет гипервизору получать информацию об IP-адресах, корректно завершать работу ОС и выполнять заморозку ФС при бэкапах.
- **Windows 11**: Требует наличия эмулируемого модуля **TPM 2.0** и использования **UEFI** (OVMF) вместо BIOS.

### LXC-контейнеры
Proxmox использует системные контейнеры LXC для легковесной виртуализации Linux-систем.
- **Unprivileged Containers**: Повышают безопасность за счет маппинга UID/GID. Включены по умолчанию.
- **Nesting**: Опция необходима для запуска Docker или вложенных LXC внутри контейнера.
- **Сеть**: В отличие от Docker, LXC-контейнеры получают полноценный IP-адрес в сети хоста и ведут себя как отдельные серверы.

### Шаблоны (Templates) и клонирование
- **Full Clone**: Полная копия, независимая от оригинала.
- **Linked Clone**: Использует диск шаблона как базу (Read-Only), записывая только изменения в новый слой. Экономит место, но создает зависимость от шаблона.
- **LVM-Thin Exception**: При использовании LVM-Thin базовый том шаблона можно удалять или изменять, так как клоны используют свои блоки данных, пока на них есть ссылки.

### Cloud-Init
Технология для автоматизации первичной настройки ВМ (пользователи, SSH-ключи, сеть) без ручного вмешательства.

## Практические сценарии

### Установка Windows 11
1. **Создание ВМ**: Выбрать Machine Type `q35`, BIOS `OVMF (UEFI)`, добавить `TPM Storage` и `EFI Storage`.
2. **Драйверы**: Подключить второй CD/DVD привод с ISO-образом `virtio-win`.
3. **Этап установки**: При выборе диска нажать `Load Driver` и выбрать путь `D:\amd64\win11` (для диска) и `D:\NetKVM\win11\amd64` (для сети).
4. **Завершение**: После установки Windows установить `VirtIO Guest Tools` из того же образа.

### Доступ по SSH для root в LXC
По умолчанию в шаблонах Linux доступ по SSH для пользователя root по паролю закрыт.
1. В консоли Proxmox войти в контейнер: `pct enter <ID>`.
2. Отредактировать `/etc/ssh/sshd_config`: установить `PermitRootLogin yes`.
3. Перезапустить службу: `systemctl restart ssh`.

### Создание Cloud-Init шаблона через CLI
Для автоматизации рекомендуется использовать официальные "cloud-ready" образы (Ubuntu Cloud Images, Debian Generic Cloud).
```bash
# 1. Загрузка образа и создание оболочки ВМ
wget https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64.img
qm create 9000 --name ubuntu-template --memory 2048 --net0 virtio,bridge=vmbr0

# 2. Импорт диска в хранилище
qm importdisk 9000 jammy-server-cloudimg-amd64.img local-lvm

# 3. Настройка параметров диска и Cloud-Init
qm set 9000 --scsihw virtio-scsi-pci --scsi0 local-lvm:vm-9000-disk-0
qm set 9000 --ide2 local-lvm:cloudinit
qm set 9000 --boot c --bootdisk scsi0
qm set 9000 --serial0 socket --vga serial0

# 4. Конвертация в шаблон
qm template 9000
```
