# Proxmox Virtual Environment (PVE) — Обзор и базовые концепции

## Определения

**Proxmox Virtual Environment (PVE)** — это бесплатная платформа виртуализации с открытым исходным кодом корпоративного уровня на базе дистрибутива Debian GNU/Linux. PVE предоставляет единый веб-интерфейс управления для виртуальных машин на базе KVM, системных контейнеров LXC, программно-определяемых сетей (SDN) и различных систем хранения данных.

## Основные концепции

### Установка и разбиение диска

При автоматической установке Proxmox VE использует LVM (Logical Volume Manager — менеджер логических томов) для гибкого управления пространством. Диск разделяется на область для операционной системы (root), раздел подкачки (swap) и пул для данных виртуальных машин (LVM-Thin).

Подробная схема и параметры разбиения описаны в разделе **[Логика разбиения диска при установке](./proxmox_storage.md#логика-разбиения-диска-при-установке)**.

### Виртуальные машины (KVM)

Виртуальные машины в Proxmox обеспечивают полную аппаратную изоляцию за счет гипервизора KVM (Kernel-based Virtual Machine) и эмулятора QEMU.

- **VirtIO-драйверы**: Для достижения максимальной производительности в Windows-машинах необходимо подключать дополнительный ISO-образ (образ оптического диска) с драйверами (`virtio-win.iso`) во время установки.
- **QEMU Guest Agent**: Программное обеспечение, позволяющее гипервизору получать информацию об IP-адресах (Internet Protocol), корректно завершать работу гостевой операционной системы и выполнять заморозку файловой системы при создании резервных копий.
- **Windows 11**: Требует наличия эмулируемого модуля TPM 2.0 (Trusted Platform Module — доверенный платформенный модуль) и использования UEFI (Unified Extensible Firmware Interface) вместо классического BIOS (Basic Input/Output System).

### Системные контейнеры (LXC)

Proxmox использует системные контейнеры LXC (Linux Containers) для легковесной виртуализации Linux-систем.

- **Unprivileged Containers (Непривилегированные контейнеры)**: Повышают безопасность за счет маппинга UID/GID (User ID / Group ID — идентификаторы пользователя и группы) контейнера на непривилегированные ID хоста. Включены по умолчанию.
- **Nesting (Вложенность)**: Опция, необходимая для запуска Docker или вложенных LXC внутри контейнера.
- **Сеть**: В отличие от приложений в Docker, LXC-контейнеры получают полноценный IP-адрес в сети хоста и ведут себя как отдельные серверы.

### Шаблоны (Templates) и клонирование

- **Full Clone (Полный клон)**: Полная копия виртуальной машины, полностью независимая от оригинала.
- **Linked Clone (Связанный клон)**: Использует диск шаблона как базу (только для чтения), записывая только изменения в новый слой. Экономит место, но создает зависимость от родительского шаблона.
- **LVM-Thin Exception**: При использовании LVM-Thin базовый том шаблона можно удалять или изменять, так как клоны используют свои блоки данных, пока на них есть ссылки.

### Cloud-Init

Технология для автоматизации первичной настройки виртуальных машин (создание пользователей, установка SSH-ключей (Secure Shell), настройка сети) при первом запуске без ручного вмешательства.

## Практические сценарии

### Установка Windows 11

1. **Создание ВМ**: Выбрать тип машины `q35`, BIOS `OVMF (UEFI)`, добавить `TPM Storage` и `EFI Storage`.
2. **Драйверы**: Подключить второй виртуальный CD/DVD привод с ISO-образом `virtio-win`.
3. **Этап установки**: При выборе диска нажать `Load Driver` и выбрать путь `D:\amd64\win11` (для диска) и `D:\NetKVM\win11\amd64` (для сетевой карты).
4. **Завершение**: После установки Windows запустить `VirtIO Guest Tools` из того же образа.

### Доступ по SSH для root в LXC

По умолчанию в большинстве шаблонов Linux доступ по SSH (Secure Shell) для пользователя root по паролю закрыт.

1. В консоли Proxmox (CLI — Command Line Interface) войти в контейнер: `pct enter <ID>`.
2. Отредактировать файл `/etc/ssh/sshd_config`: установить параметр `PermitRootLogin yes`.
3. Перезапустить службу: `systemctl restart ssh`.

### Создание Cloud-Init шаблона через CLI

Для автоматизации рекомендуется использовать официальные "cloud-ready" образы (например, Ubuntu Cloud Images).

```bash
# 1. Загрузка образа и создание оболочки виртуальной машины
wget https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64.img
qm create 9000 --name ubuntu-template --memory 2048 --net0 virtio,bridge=vmbr0

# 2. Импорт диска в хранилище
qm importdisk 9000 jammy-server-cloudimg-amd64.img local-lvm

# 3. Настройка параметров диска и Cloud-Init
qm set 9000 --scsihw virtio-scsi-pci --scsi0 local-lvm:vm-9000-disk-0
qm set 9000 --ide2 local-lvm:cloudinit
qm set 9000 --boot c --bootdisk scsi0
qm set 9000 --serial0 socket --vga serial0

# 4. Конвертация в шаблон
qm template 9000
```
