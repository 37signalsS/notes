# Хранилища и Ceph в Proxmox

## Определения

**Storage (Хранилище)** в Proxmox Virtual Environment (PVE) — это абстрактный слой управления данными, который позволяет подключать различные типы физических и сетевых накопителей для хранения дисков виртуальных машин (VM — Virtual Machines), контейнеров (LXC — Linux Containers), образов ISO и резервных копий.

**Content Types (Типы контента)** — это фильтры, определяющие, какие данные могут храниться на конкретном хранилище:

- **Disk images**: Диски виртуальных машин (KVM).
- **ISO images**: Установочные образы операционных систем.
- **Container templates**: Шаблоны LXC-контейнеров.
- **Container**: Корневые файловые системы контейнеров.
- **VZDump backups**: Резервные копии, созданные встроенным инструментом `vzdump`.
- **Snippets**: Пользовательские скрипты (например, для Cloud-Init).

## Основные концепции

### Типы локальных хранилищ

Локальные хранилища размещаются на дисках, физически установленных в сервер Proxmox.

- **Directory**: Обычная папка на файловой системе (ext4/XFS). Универсальна, поддерживает все типы контента. Виртуальные диски хранятся в виде файлов `.qcow2` или `.raw`.
- **LVM (Logical Volume Manager)**: Менеджер логических томов. Быстрый доступ к блочным устройствам, но не поддерживает снапшоты (в базовой реализации Proxmox) и Thin Provisioning.
- **LVM-Thin**: Оптимизированная версия LVM с поддержкой динамического выделения места (Thin Provisioning) и мгновенных снимков (snapshots). **Не поддерживает** встроенную репликацию между нодами.
- **ZFS (Zettabyte File System)**: Файловая система и менеджер томов "все в одном". Поддерживает компрессию, дедупликацию и целостность данных. **Обязательна** для работы встроенной функции Storage Replication (репликация по расписанию через `zfs send/receive`).

### Сетевые и общие хранилища (Shared Storage)

Общие хранилища доступны всем нодам кластера одновременно, что позволяет выполнять живую миграцию (Live Migration) без копирования данных диска.

- **NFS (Network File System)**: Сетевая файловая система. Поддерживает все типы контента. Проста в настройке.
- **SMB/CIFS (Server Message Block)**: Протокол сетевого доступа, популярный в Windows-средах.
- **iSCSI (Internet Small Computer Systems Interface)**: Протокол передачи блочных данных по IP-сетям. Требует наличия LVM поверх для возможности запуска нескольких ВМ.
- **Proxmox Backup Server (PBS)**: Специализированное хранилище для инкрементальных дедуплицированных бэкапов.

### Логика разбиения диска при установке

При автоматической установке Proxmox VE на одиночный диск (ext4/XFS) система использует LVM и применяет следующую логику распределения пространства:

- **root_size**: Раздел для операционной системы (обычно 1/4 от объема диска, максимум 100 ГБ). Контент: ISO, шаблоны, бэкапы.
- **swap_size**: Раздел подкачки (обычно 1/8 от объема, от 4 до 8 ГБ).
- **minfree**: Резервное место в LVM-группе (по умолчанию 16 ГБ для дисков > 128 ГБ).
- **data_size**: Все оставшееся место выделяется в `LVM-Thin` пул для хранения дисков ВМ и контейнеров.

### Hyperconverged Ceph (Гиперконвергентный Ceph)

**Ceph** — это распределенная программно-определяемая система хранения данных (SDS), которая объединяет диски всех серверов кластера в единый отказоустойчивый пул.

- **MON (Monitors)**: Узлы, поддерживающие карту состояния кластера (требуется нечетное количество, минимум 3).
- **MGR (Managers)**: Обеспечивают мониторинг и управление.
- **OSD (Object Storage Daemon)**: Процесс, управляющий конкретным физическим диском. Данные реплицируются между OSD на разных хостах.
- **MDS (Metadata Server)**: Необходим для работы **CephFS** (файловой системы поверх Ceph) для хранения ISO и бэкапов.
- **RBD (RADOS Block Device)**: Основной тип хранилища Ceph в Proxmox для дисков ВМ.

## Практические сценарии

### Управление хранилищами через CLI (pvesm)

Инструмент `pvesm` (Proxmox VE Storage Manager) позволяет управлять конфигурацией из терминала.

**Просмотр статуса всех хранилищ:**

```bash
pvesm status
# → Name             Type     Status  Total (KB)   Used (KB)   Free (KB)   %
# → local            dir      active  102000000    5000000     97000000    4.90%
# → local-lvm        thinpool active  400000000    20000000    380000000   5.00%
```

**Сканирование доступных NFS-экспортов на сервере:**

```bash
pvesm scan nfs 192.168.1.50
# → /export/proxmox 192.168.1.50
```

**Добавление нового NFS-хранилища:**

```bash
pvesm add nfs my-nfs-storage --server 192.168.1.50 --export /export/proxmox --content images,iso
```

### Настройка и проверка Ceph через CLI (pveceph)

В Proxmox используется утилита `pveceph` для управления гиперконвергентным кластером.

**Проверка состояния кластера Ceph:**

```bash
pveceph status
# → health: HEALTH_OK
# → osds: 3 up, 3 in
```

**Просмотр дерева OSD и их состояния:**

```bash
pveceph osd tree
```

**Создание нового OSD на диске `/dev/sdb`:**

```bash
pveceph osd create /dev/sdb
```

### Миграция диска (Move Storage)

В Proxmox можно перенести диск запущенной ВМ на другое хранилище без остановки работы системы.

1. В GUI: `VM -> Hardware -> Disk -> Disk Action -> Move Storage`.
2. Выбрать целевое хранилище.
3. Система выполнит фоновое копирование данных и переключит IO (Input/Output) на новый диск.
