# Yandex Resource Manager: Обзор

## 1. Определения

**Resource Manager** — сервис управления иерархией ресурсов и доступом в Yandex Cloud. Определяет структуру организации инфраструктуры: облака, каталоги, метки и привязки прав.

**Cloud (Облако)** — верхний уровень изоляции ресурсов с единым биллингом, квотами и лимитами.

**Folder (Каталог)** — логическая единица развёртывания и управления ресурсами внутри облака. Обычно соответствует окружению (dev, stage, prod), отдельному продукту или команде.

**Service Account (Сервисный аккаунт)** — специальная учётная запись для аутентификации приложений, скриптов и сервисов при взаимодействии с API Yandex Cloud.

**Labels (Метки)** — пары ключ-значение, используемые для маркировки ресурсов с целью группировки, фильтрации затрат в биллинге и применения политик.

## 2. Базовые концепции

### Иерархия ресурсов

Иерархическая модель позволяет эффективно управлять правами и квотами:

```
┌─────────────────────────────────────────┐
│              Cloud (Облако)             │
│         Биллинг, квоты, лимиты          │
└─────────────────────────────────────────┘
                   │
    ┌──────────────┼──────────────┐
    │              │              │
┌───▼────┐   ┌────▼────┐   ┌────▼────┐
│ Folder │   │ Folder  │   │ Folder  │
│  (dev) │   │ (stage) │   │  (prod) │
└────────┘   └─────────┘   └─────────┘
```

### Ключевые сущности управления

| Сущность | Назначение | Уровень применения |
| :--- | :--- | :--- |
| **Cloud** | Изоляция ресурсов, управление бюджетом и лимитами | Организация / Проект |
| **Folder** | Группировка ресурсов, изоляция окружений | Окружение / Продукт |
| **Labels** | Маркировка для аллокации затрат и автоматизации | Любой ресурс |
| **Service Account** | Идентификация программных систем | Каталог / Облако |
| **Access Bindings** | Управление доступом (привязка ролей к субъектам) | Любой уровень |

### Управление доступом и правами

Управление доступом базируется на механизме IAM (Identity and Access Management). Подробный разбор ролей и методов назначения прав приведён в документе **[IAM Роли и права доступа](./iam_roles.md)**.

Основные принципы:

- **Принцип минимальных прав:** назначение только необходимых полномочий для выполнения конкретной задачи.
- **Наследование:** права, назначенные на уровне облака, наследуются всеми каталогами внутри него.
- **Изоляция:** использование отдельных каталогов для разных окружений минимизирует риски случайного влияния на production.

## 3. Практические сценарии

### Изоляция окружений и сервисов

Рекомендуется использовать схему «Один каталог — одно окружение» (например, `app-prod`, `app-dev`). Это позволяет:

- Разграничить права доступа для разработчиков и автоматики деплоя.
- Изолировать сетевые контуры в рамках отдельных VPC в каждом каталоге.
- Устанавливать специфичные квоты на ресурсы (CPU, RAM) для каждого окружения.

### Использование меток для финансового контроля

Для всех ресурсов обязательны метки, позволяющие идентифицировать владельца и назначение затрат:

- `env`: окружение (dev, stage, prod).
- `project`: название проекта или приложения.
- `owner`: ответственное лицо или команда.
- `cost-center`: идентификатор финансового подразделения.

### Автоматизация управления иерархией

Декларативное описание структуры ресурсов через **[Terraform](./terraform_automation.md)** позволяет:

- Версионировать структуру каталогов и прав доступа в Git.
- Быстро разворачивать идентичные окружения для новых сервисов.
- Проводить аудит инфраструктуры через историю коммитов.

## 4. Дополнительная информация

### Лимиты и квоты

- **Количество каталогов:** по умолчанию до 50 на одно облако.
- **Метки:** до 20 пар ключ-значение на один ресурс.
- **Федерация идентичностей:** поддержка протокола OIDC для интеграции с внешними провайдерами (Active Directory, Google).
