# Yandex Monitoring: Основные концепции

## 1. Определения

**Yandex Monitoring** — сервис Yandex Cloud для сбора, хранения и визуализации метрик производительности и доступности облачных ресурсов и пользовательских приложений. Автоматически собирает метрики всех сервисов YC.

**Метрика** — именованный временной ряд числовых данных, описывающих состояние системы (CPU, память, латентность, ошибки).

**Cloud Logging** — сервис централизованного сбора и анализа логов YC. Интегрируется с Monitoring для создания метрик на основе логов ([документация YC](https://yandex.cloud/ru/services/logging)).

**Дашборд** — визуальная панель с графиками, числами и таблицами для мониторинга состояния систем в реальном времени.

**Алерт** — правило оповещения, срабатывающее при превышении пороговых значений метрик.

## 2. Базовые концепции

### Модель данных

Метрика состоит из:

| Компонент | Описание | Пример |
| :--- | :--- | :--- |
| **Имя** | Уникальный идентификатор метрики | `yandex_compute_cpu_usage` |
| **Метки (labels)** | Пары ключ-значение для фильтрации и группировки | `service=checkout`, `env=prod` |
| **Точки (points)** | Пары `timestamp + value` | `2026-04-10T12:00:00Z: 75.3` |

### Типы метрик

| Тип | Поведение | Пример |
| :--- | :--- | :--- |
| **Gauge** | Снимок состояния, может расти и убывать | Температура, использование памяти |
| **Counter** | Монотонно растущий счётчик | Число запросов, ошибок |
| **Histogram** | Распределение значений по бакетам | Латентность запросов |
| **Summary** | Распределение с квантилями (клиентские) | p50, p95, p99 латентности |

> **См. также:** [Типы метрик Prometheus](../../Prometheus/concepts/metric_types/overview.md) — аналогичные концепции в другой системе.

### Агрегации

| Агрегация | Описание | Применение |
| :--- | :--- | :--- |
| `sum`, `avg`, `min`, `max` | Базовые статистические агрегации | Любые метрики |
| `rate`, `delta` | Изменение значения за интервал | Счётчики (Counter) |
| `percentile`, `quantile` | Оценка распределения значений | Латентность (p50, p95, p99) |

### Источники метрик

| Источник | Тип | Описание |
| :--- | :--- | :--- |
| **Yandex Cloud сервисы** | Автоматически | Compute, Databases, Kubernetes, Load Balancer, VPC |
| **Custom Metrics API** | Push | Пользовательские метрики через HTTP API `timeseries:write` |
| **Prometheus-compatible** | Push/Pull | Managed Service for Prometheus, скрейпинг через ServiceMonitor/PodMonitor |
| **Log-based metrics** | Derived | Агрегация метрик из логов через Cloud Logging и Cloud Functions |

### Monitoring vs Logging

| Аспект | Monitoring | Cloud Logging |
| :--- | :--- | :--- |
| **Данные** | Агрегированные метрики (числа) | Детальные события (текст/JSON) |
| **Назначение** | Тренды, алерты, дашборды | Расследование инцидентов, аудит |
| **Хранение** | Долгосрочное (до 13 месяцев) | Краткосрочное (дни/недели, настраиваемое) |
| **Запросы** | Агрегации, оконные функции | Полнотекстовый поиск, парсинг полей |

> **Рекомендация:** Используйте совместно — Monitoring для обнаружения аномалий, Logging для диагностики причин.

### Кардинальность меток

**Кардинальность** — количество уникальных комбинаций значений меток. Высокая кардинальность увеличивает объём данных и стоимость хранения.

**Рекомендации:**

- Фиксированный набор ключей: `service`, `env`, `host`
- Избегать высокой кардинальности: не использовать `user_id`, `request_id`, `session_id`
- Ограничение: < 1000 уникальных значений на метку

## 3. Практические сценарии

### Быстрый запрос метрики

```
metric("yandex_compute_cpu_usage")
| filter(cluster="prod", host=~"app-.*")
| avg(5m)
| max()
```

### Создание метрики из лога

1. Cloud Logging собирает логи в log group
2. Log Router направляет события в Cloud Function
3. Функция агрегирует данные и публикует метрику через API

> **Подробный пример:** [Логи → Метрики](./monitoring_practical_scenarios.md#32-логи--метрики-log-based-metrics)

### Отправка custom-метрики

```bash
TOKEN=$(yc iam create-token)
FOLDER_ID=<your_folder_id>
ENDPOINT=https://monitoring.api.cloud.yandex.net/monitoring/v2/timeseries:write

curl -sS -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -X POST "$ENDPOINT?folderId=$FOLDER_ID" \
  -d '{"timeseries": [{"name": "custom.my_metric", "points": [{"ts": "2026-04-10T12:00:00Z", "value": 42}]}]}'
```

> **Подробный пример:** [Отправка метрик через API](./monitoring_practical_scenarios.md#31-отправка-пользовательских-метрик-через-api)

## 4. Дополнительная информация

### Методологии мониторинга

| Методология | Область | Метрики |
| :--- | :--- | :--- |
| **RED** | Микросервисы | **R**ate, **E**rrors, **D**uration |
| **USE** | Инфраструктура | **U**tilization, **S**aturation, **E**rrors |

> **Подробности:** [Best Practices](./monitoring_advanced_topics.md#best-practices)

### Безопасность

- **IAM-аутентификация** — через сервисные аккаунты YC
- **Folder-level изоляция** — метрики доступны в пределах каталога
- **Audit logging** — операции записываются в Cloud Logging
- **Шифрование at rest** — через KMS

### Хранение метрик

| Параметр | Значение |
| :--- | :--- |
| **Стандартное хранение** | до 13 месяцев |
| **Агрегация** | автоматическая: детальные → часовые → дневные |
| **Retention** | настраиваемый через политики хранения |

### Актуальная информация (2025–2026)

- **Q4 2025:** Вкладка Alerts для Managed Service for Prometheus
- **Q4 2025:** Детальные метрики диска для Managed Databases
- **Все сервисы YC** публикуют метрики автоматически (мониторинг по умолчанию)
