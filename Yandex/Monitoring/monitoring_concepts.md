# Yandex Monitoring: Основные концепции

## 1. Определения

**Yandex Monitoring** — сервис Yandex Cloud для сбора, хранения и визуализации метрик производительности и доступности облачных ресурсов и пользовательских приложений. Автоматически собирает метрики всех сервисов YC.

**Метрика** — именованный временной ряд числовых данных, описывающих состояние системы (CPU, память, латентность, ошибки).

**Cloud Logging** — сервис централизованного сбора и анализа логов YC. Интегрируется с Monitoring для создания метрик на основе логов.

**Дашборд** — визуальная панель с графиками, числами и таблицами для мониторинга состояния систем в реальном времени.

**Алерт** — правило оповещения, срабатывающее при превышении пороговых значений метрик.

## 2. Базовые концепции

### Модель данных

Метрика в Yandex Monitoring состоит из:

| Компонент | Описание | Пример |
| :--- | :--- | :--- |
| **Имя** | Уникальный идентификатор метрики | `yandex_compute_cpu_usage` |
| **Метки (labels)** | Пары ключ-значение для фильтрации и группировки | `service=checkout`, `env=prod` |
| **Точки (points)** | Пары `timestamp + value` | `2026-06-03T12:00:00Z: 75.3` |

### Типы метрик и агрегации

Yandex Monitoring поддерживает стандартные типы метрик (Gauge, Counter, Histogram, Summary). Подробное описание типов метрик и их характеристик приведено в файле **[Метрики: детали](../../Concepts/Observability_and_Monitoring/metrics_deep_dive.md)**.

Для работы с метриками используются статистические агрегации:

- Базовые: `sum`, `avg`, `min`, `max`.
- Для счётчиков: `rate`, `delta`.
- Для распределений: `percentile`, `quantile`.

### Источники метрик

| Источник | Тип | Описание |
| :--- | :--- | :--- |
| **Сервисы Yandex Cloud** | Автоматически | Compute, Databases, Kubernetes, Load Balancer, VPC |
| **Custom Metrics API** | Push | Пользовательские метрики через HTTP API `timeseries:write` |
| **Managed Service for Prometheus** | Push/Pull | Скрейпинг через ServiceMonitor/PodMonitor |
| **Метрики на основе логов** | Производные | Агрегация данных из Cloud Logging через Cloud Functions |

### Сравнение Monitoring и Logging

| Аспект | Yandex Monitoring | Cloud Logging |
| :--- | :--- | :--- |
| **Данные** | Агрегированные метрики (числа) | Детальные события (текст/JSON) |
| **Назначение** | Тренды, алерты, дашборды | Расследование инцидентов, аудит |
| **Хранение** | Долгосрочное (до 13 месяцев) | Краткосрочное (настраиваемое) |
| **Запросы** | Агрегации, оконные функции | Полнотекстовый поиск, парсинг |

### Кардинальность меток

Количество уникальных комбинаций значений меток напрямую влияет на стоимость и производительность. Основные рекомендации по управлению кардинальностью и лейблами доступны в разделе **[Многомерность](../../Concepts/Observability_and_Monitoring/metrics_deep_dive.md#многомерность-векторы-и-лейблы)**.

**Ограничения Yandex Monitoring:**

- Рекомендуется не превышать 1000 уникальных значений на одну метку.
- Избегайте использования динамических данных (ID пользователей, запросов) в метках.

## 3. Практические сценарии

### Запрос метрик

Для анализа данных используется встроенный язык запросов. Пример получения среднего использования CPU для группы хостов:

```
metric("yandex_compute_cpu_usage")
| filter(cluster="prod", host=~"app-.*")
| avg(5m)
| max()
```

### Метрики из логов

1. Сбор логов сервиса в Cloud Logging.
2. Настройка Log Router для передачи событий в Cloud Function.
3. Агрегация данных внутри функции и отправка метрики в Monitoring через API.

Подробные примеры реализации доступны в файле **[Практические сценарии](./monitoring_practical_scenarios.md)**.

### Отправка пользовательских метрик

```bash
TOKEN=$(yc iam create-token)
FOLDER_ID=<folder_id>
ENDPOINT=https://monitoring.api.cloud.yandex.net/monitoring/v2/timeseries:write

curl -sS -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -X POST "$ENDPOINT?folderId=$FOLDER_ID" \
  -d '{"timeseries": [{"name": "custom.my_metric", "points": [{"ts": "2026-06-03T12:00:00Z", "value": 42}]}]}'
```

## 4. Дополнительная информация

### Методологии мониторинга

При проектировании системы мониторинга рекомендуется использовать стандартные методологии (RED, USE, Four Golden Signals). Подробное описание методологий и рекомендации по их выбору приведены в файле **[Методологии мониторинга](../../Concepts/Observability_and_Monitoring/monitoring_methodologies.md)**.

### Безопасность и хранение

- **Аутентификация:** через IAM и сервисные аккаунты Yandex Cloud.
- **Изоляция:** доступ разграничивается на уровне каталогов (Folders).
- **Срок хранения:** стандартно до 13 месяцев.
- **Агрегация:** автоматическое понижение детализации для долгосрочного хранения.

### Актуальная информация (2025–2026)

- Все сервисы YC интегрированы с мониторингом по умолчанию.
- Поддержка Alerts для Managed Service for Prometheus (Q4 2025).
- Расширенные метрики дисковой подсистемы для управляемых баз данных (Q4 2025).
