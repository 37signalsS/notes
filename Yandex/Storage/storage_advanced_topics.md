# Yandex Storage: Дополнительные темы

## 1. Определения

**SSE-S3 / SSE-KMS** — технологии шифрования на стороне сервера. SSE-S3 использует ключи Yandex Cloud, SSE-KMS — ключи сервиса [KMS](../Resource_Manager/overview.md), обеспечивая контроль и аудит.

**Security Groups** — группы безопасности для контроля сетевого доступа к файловым хранилищам на уровнях L3/L4.

---

## 2. Базовые концепции

### Безопасность и шифрование

| Метод | Область применения | Особенности |
| :--- | :--- | :--- |
| **SSE-S3** | Данные Object Storage | Автоматическое управление ключами облаком |
| **SSE-KMS** | Данные Object Storage | Свои ключи, аудит через KMS, ротация |
| **Security Groups** | Доступ к File Storage | Фильтрация по портам (например, 2049 для NFS) |
| **TLS/HTTPS** | Передача данных | Шифрование в транзите для всех типов хранилищ |

### Интеграция с сервисами

- **Kubernetes:** использование Block и File Storage в качестве Persistent Volumes.
- **Docker:** хранение образов в реестрах на базе Object Storage.
- **Terraform:** декларативное управление всеми типами хранилищ.

---

## 3. Практические сценарии

### Ограничение доступа к файловому хранилищу

Пример настройки Security Group для NFS:

```bash
# Разрешить NFS (порт 2049) только из доверенной подсети
yc vpc security-group create \
  --name nfs-sg \
  --rule "direction=ingress,port=2049,protocol=tcp,predefined=self_security_group"
```

### Рекомендации по эксплуатации

**Объектное хранилище:**

- Используйте **Жизненные циклы** для удаления старых версий (30–90 дней).
- Включайте **Версионирование** для критически важных данных (артефакты, бэкапы).

**Блочное хранилище:**

- Настраивайте расписание снимков (snapshots) для регулярных бэкапов.
- Используйте тип `network-ssd-readonly` для высоконагруженных реплик БД.
