# Yandex Storage: Основные концепции

## 1. Определения

**Объектное хранилище (Object Storage)** — S3-совместимое хранилище для неструктурированных данных: артефактов сборок, бэкапов, статики, логов и медиафайлов.

**Блочное хранилище (Block Storage)** — сетевые диски для виртуальных машин в [Compute Cloud](../Compute-Cloud.md). Предоставляют блочный доступ с низкой задержкой.

**Файловое хранилище (File Storage)** — управляемое NFS-хранилище для общего доступа к файлам из нескольких виртуальных машин (ВМ).

---

## 2. Базовые концепции

### Сравнение типов хранилищ

| Тип | Интерфейс | Характеристики | Сценарии |
| :--- | :--- | :--- | :--- |
| **Object Storage** | S3 API (HTTP/REST) | Версионирование, lifecycle-политики, высокая доступность | Артефакты CI/CD, бэкапы, статика, логи, медиа |
| **Block Storage** | Блочное устройство (`/dev/vdb`) | Низкая задержка (<1 мс), снимки, онлайн-расширение | Загрузочные диски, БД, `/var/lib/docker` |
| **File Storage** | POSIX/NFS v4 | Общий доступ многим ВМ, POSIX-семантика | Общие тома приложений, медиа-библиотеки |

### Объектное хранилище (Object Storage)

**Ключевые возможности:**

- **S3-совместимость** — работа через стандартные инструменты (aws-cli, boto3, s3cmd).
- **Версионирование** — хранение всех версий объектов для защиты от случайного удаления.
- **Жизненные циклы (Lifecycle-политики)** — автоматическое удаление или переход в холодное хранение.
- **Публичный доступ** — возможность хостинга статических сайтов и интеграции с CDN.
- **Шифрование** — поддержка шифрования на стороне сервера (SSE-S3, SSE-KMS); подробнее см. [Дополнительные темы](./storage_advanced_topics.md).

**Классы хранения:**

| Класс | Стоимость | Доступ | Сценарии |
| :--- | :--- | :--- | :--- |
| **Standard** | Базовая | Мгновенный | Активные данные, частый доступ |
| **Infrequent Access** | Ниже | Мгновенный | Редкий доступ, бэкапы |
| **Cold Storage** | Минимальная | Часы | Архивы, долгосрочное хранение |

**Лимиты:**

- Максимальный размер объекта: 5 ГБ (одним запросом), 5 ТБ (через multipart upload).
- Максимальное количество бакетов на каталог: 100.
- Максимальный размер бакета: не ограничен.

### Блочное хранилище (Block Storage — диски)

**Типы дисков:**

| Тип | IOPS | Пропускная способность | Задержка | Сценарии |
| :--- | :--- | :--- | :--- | :--- |
| **network-ssd** | До 10 000 | До 300 МБ/с | <1 мс | БД, системы реального времени |
| **network-ssd-nonreplicated** | До 50 000 | До 600 МБ/с | <0.5 мс | Критичные к задержкам БД |
| **network-hdd** | До 200 | До 100 МБ/с | ~10 мс | Файловые серверы, архивы |
| **network-ssd-readonly** | До 20 000 | До 400 МБ/с | <1 мс | Реплики БД, статические данные |

**Возможности:**

- **Снимки (snapshots)** — резервные копии дисков на определенный момент времени.
- **Онлайн-расширение** — увеличение размера диска без остановки ВМ.
- **Мульти-аттач** (для `network-ssd-readonly`) — подключение одного диска к нескольким ВМ.

**Лимиты:**

- Максимальный размер диска: 4 ТБ (`network-ssd`), 8 ТБ (`network-hdd`).
- Максимальное количество снимков: 100 на один диск.

### Файловое хранилище (File Storage)

**Характеристики:**

- Протокол: NFS v4.
- Пропускная способность: до 1 ГБ/с.
- IOPS: до 10 000.
- Максимальный размер: до 10 ТБ.

**Сценарии использования:** общие каталоги для микросервисов, медиа-библиотеки, общие данные пользователей, общее хранилище (shared storage) для CI/CD.
