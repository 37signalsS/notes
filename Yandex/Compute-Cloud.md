# Yandex Cloud DevOps - Compute Cloud

## Обзор сервисов Яндекс Облака: Compute

Яндекс Облако предоставляет базовые строительные блоки для DevOps-практик: вычислительные ресурсы (Compute), управляемые базы данных (Managed Databases) и несколько классов хранилищ (Object, Block, File). Понимание их возможностей и границ применимости позволяет проектировать надежные и экономичные среды для CI/CD, продакшена и аналитики.

## Compute Cloud: виртуальные машины и окружение

Compute Cloud — это виртуальные машины (VM) с различными типами CPU/памяти и дисков. Важные особенности для DevOps:

- Образы: публичные, кастомные (например, через Packer), семейства образов для обновляемых шаблонов.
- Диски: network-ssd и network-hdd; снимки для бэкапов и клонирования окружений.
- Сети: подсети, security groups, публичные IP для публичных сервисов и NAT для исходящих соединений.
- Автоматизация: cloud-init/metadata для начальной конфигурации, привязка сервисных аккаунтов для доступа к API и Object Storage.
- Экономия: прерываемые (preemptible) инстансы подходят для CI-агентов и batch-задач.

Пример создания VM с облачной инициализацией и сервисным аккаунтом:

```bash
yc compute instance create \
  --name app-vm \
  --zone ru-central1-b \
  --platform standard-v3 \
  --cores 2 --memory 4 \
  --create-boot-disk image-folder-id=standard-images,image-family=ubuntu-2204-lts,type=network-ssd,size=20 \
  --network-interface subnet-name=default-ru-central1-b,nat-ip-version=ipv4 \
  --service-account-name sa-app \
  --metadata-from-file user-data=cloud-init.yaml
```

## Запуск виртуальной машины: короткий сценарий

Короткий сценарий полезен, когда требуется быстро получить рабочую виртуальную машину (ВМ) в Yandex Cloud для тестов, временного стенда, выполнения CI‑джоба или отладки. В таком сценарии важны предсказуемость, повторяемость и минимальный набор шагов без углубления в расширенные опции.

### Минимальные сущности, которые понадобятся

- Каталог с включённым биллингом.
- Сеть VPC и подсеть в нужной зоне доступности.
- Публичный SSH‑ключ для доступа.
- Образ операционной системы и загрузочный диск.
- Параметры вычислительных ресурсов (vCPU, RAM).
- Публичный IP (опционально) и правила доступа по SSH.

Если VPC уже создана провайдером по умолчанию, можно использовать стандартную сеть и подсеть.

### Сценарий через веб‑консоль

1) Откройте каталог и перейдите в Compute Cloud → Создать ВМ.
2) Выберите зону (например, ru‑central1‑a) и платформу. Укажите 1–2 vCPU и 2–4 ГБ RAM для небольших задач.
3) В разделе Диски выберите образ из стандартных: Ubuntu LTS (ubuntu‑2204‑lts) обычно подходит для CI/DevOps‑инструментов. Размер диска 15–20 ГБ достаточен для базового набора пакетов.
4) В Сетевых настройках укажите подсеть. Включите публичный IP, если нужен прямой доступ по SSH, или оставьте без NAT для приватного размещения (доступ через bastion/VPN).
5) В Безопасности разрешите SSH‑доступ: настройте группу безопасности так, чтобы порт 22 был доступен только с доверенных адресов.
6) В Метаданных вставьте публичный SSH‑ключ или добавьте cloud‑init user‑data для автоматической настройки.
7) Проверьте параметры и создайте ВМ. Подключение: ssh ubuntu@<публичный_IP>.

### Быстрый запуск через yc CLI

Ниже — минимальная команда для воспроизводимого запуска. Предполагается существование подсети default-ru-central1-a и файла ключа ~/.ssh/id_rsa.pub.

```bash
yc compute instance create \
  --name demo-vm \
  --zone ru-central1-a \
  --hostname demo-vm \
  --cores 2 --memory 4 \
  --create-boot-disk image-folder-id=standard-images,image-family=ubuntu-2204-lts,size=15 \
  --network-interface subnet-name=default-ru-central1-a,nat-ip-version=ipv4 \
  --metadata serial-port-enable=1 \
  --ssh-key ~/.ssh/id_rsa.pub
```

Полезные варианты:

- Добавить предсозданный security group: security-group-ids= внутри параметра network-interface.
- Для экономии: --preemptible для прерываемой ВМ.
- Для автоматизации: --metadata-from-file user-data=cloud-init.yaml.

### Минимальный cloud-init для базовой подготовки

```yaml
#cloud-config
package_update: true
packages:
  - git
  - docker.io
runcmd:
  - [systemctl, enable, --now, docker]
  - [usermod, -aG, docker, ubuntu]
```

Такой шаблон обновляет пакеты, устанавливает Docker и добавляет пользователя ubuntu в группу docker.

### Выбор параметров: практические ориентиры

- Образ: LTS‑выпуски удобны длительной поддержкой и предсказуемостью репозиториев.
- Ресурсы: для агентов CI и легковесных сервисов достаточно 2 vCPU/4 ГБ; сборка контейнеров или Java‑сервисы потребуют больше RAM/CPU.
- Диск: SSD улучшит скорость сборки и I/O‑операций; HDD дешевле для общего назначения.
- Сеть: публичный IP ускоряет доступ, но повышает требования к защите; без NAT безопаснее, но потребует bastion/VPN.
- Метаданные: cloud‑init обеспечивает идемпотентность и воспроизводимость состояния машины.

### Очистка ресурсов

Для контроля затрат останавливайте или удаляйте неиспользуемые ВМ:

```bash
yc compute instance stop --name demo-vm
yc compute instance delete --name demo-vm
```

## Симуляция вывода "Yandex Cloud VM created" по ID

Напишите программу, которая имитирует создание виртуальной машины в Yandex Cloud. Программа должна принимать на вход ID виртуальной машины и выводить сообщение о её успешном создании.

### Входные данные

На вход подается строка, содержащая ID виртуальной машины (строка из букв, цифр и дефисов).

### Выходные данные

Программа должна вывести строку в формате: "Yandex Cloud VM created: [ID]", где [ID] - это переданный идентификатор виртуальной машины.

**Sample Input:**

```
vm-test-123
```

**Sample Output:**

```
Yandex Cloud VM created: vm-test-123
```
