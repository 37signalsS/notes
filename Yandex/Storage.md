# Yandex Cloud DevOps - Storage

## Storage: объекты, блоки и файлы

Разные типы хранилища решают разные задачи. Сравнение:

| Тип хранилища | Интерфейс | Характеристики | Типичные сценарии |
|---------------|-----------|----------------|-------------------|
| Object Storage | S3-совместимый | Версионирование, политики жизненного цикла, дешево за ГБ, высокая доступность | Артефакты сборок, бэкапы, статика, логи |
| Block Storage (диски VM) | Блочные устройства | Низкая задержка, пригодно для ФС/БД, снимки, расширение онлайн | Диски приложений, /var/lib/docker, базы данных |
| File Storage (NFS) | POSIX/NFS | Общий доступ многим VM, шаринг каталогов | Общие тома для приложений, медиа, профильные данные |

Криптография на стороне сервиса и интеграция с KMS помогают выполнить требования безопасности. Доступ регулируется IAM: сервисные аккаунты для VM/CI и статические ключи для S3-клиентов.

Пример создания бакета и загрузки артефакта через S3-совместимый инструмент:

```bash
aws s3api create-bucket \
  --bucket my-artifacts \
  --endpoint-url https://storage.yandexcloud.net \
  --create-bucket-configuration LocationConstraint=ru-central1

aws s3 cp build.tar.gz s3://my-artifacts/releases/ \
  --endpoint-url https://storage.yandexcloud.net
```

Практические паттерны: хранить бэкапы Managed DB в Object Storage по расписанию, использовать snapshots дисков перед релизами, выносить тяжелые артефакты CI в бакеты с правилами lifecycle, а временные вычислительные задачи запускать на прерываемых VM с доступом к Object Storage через сервисные аккаунты.

## Диски в Compute Cloud

В Compute Cloud доступны следующие типы дисков:

- **network-ssd** - сетевые SSD-диски с высокой производительностью
- **network-hdd** - сетевые HDD-диски для экономичного хранения
- Снимки (snapshots) для бэкапов и клонирования окружений

Диски используются для:
- Загрузочных дисков виртуальных машин
- Хранения данных приложений
- /var/lib/docker для контейнеров
- Баз данных
