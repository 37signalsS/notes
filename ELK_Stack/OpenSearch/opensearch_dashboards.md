# OpenSearch Dashboards: Визуализация и Управление

OpenSearch Dashboards — это веб-интерфейс с открытым исходным кодом для визуализации данных OpenSearch и управления кластером. Он позволяет выполнять поиск по логам, строить аналитические панели, управлять пользователями и мониторить состояние системы без необходимости прямого использования API.

## Определения

- **OpenSearch Dashboards**: Веб-интерфейс для анализа данных (форк Kibana 7.10.2).
- **Index Pattern (Шаблон индекса)**: Настройка, указывающая Dashboards, какие индексы OpenSearch следует использовать для поиска и визуализации.
- **Discover**: Инструмент для интерактивного исследования данных, фильтрации и поиска по логам.
- **Tenant (Тенант)**: Изолированное рабочее пространство для хранения визуализаций, дашбордов и других объектов Dashboards. Позволяет разграничивать доступ между командами.
- **Snapshot (Снапшот)**: Резервная копия индексов или всего кластера, хранимая во внешнем репозитории (например, S3).

## Базовые концепции

### Структура интерфейса
1. **Discover**: Поиск и фильтрация документов.
2. **Visualize**: Создание отдельных графиков (Pie charts, Line graphs, Maps).
3. **Dashboards**: Объединение нескольких визуализаций в единую панель мониторинга.
4. **Dev Tools**: Консоль для выполнения прямых запросов к OpenSearch API.
5. **Stack Management**: Управление индексами, пользователями и ролями.

### Управление доступом (Security)
Интегрированный плагин безопасности позволяет гибко настраивать права:
- **Internal Users**: Локальная база пользователей Dashboards.
- **Roles**: Наборы разрешений на уровне кластера (`cluster permissions`) и индексов (`index permissions`).
- **Mapping**: Связывание внутренних пользователей или внешних групп (LDAP/OIDC) с ролями Dashboards.

## Практические сценарии

### 1. Работа с данными и поиск
Для начала работы необходимо создать **Index Pattern** (например, `logs-*`).
- **Discover**: Позволяет искать данные с использованием KQL (Kibana Query Language) или Lucene.
- **Фильтрация**: `response: 200 AND geo.src: "RU"`.
- **Sample Data**: Dashboards предоставляет готовые наборы данных (eCommerce, Flights, Web Logs) для тестирования функционала «в один клик».

### 2. Управление пользователями и ролями
Пример создания аналитика с ограниченным доступом:
1. **Создание пользователя**: `Security -> Internal users -> Create internal user`.
2. **Создание роли**: `Security -> Roles -> Create role`. Укажите конкретные индексы в `Index permissions` (например, `opensearch_dashboards_sample_data_flights`).
3. **Маппинг**: `Security -> Roles -> [Role Name] -> Mapped users -> Map users`.

### 3. Построение визуализаций и дашбордов
Процесс создания аналитической панели:
1. **Visualize**: Выбор типа (например, **Pie** для кодов ответа или **Area** для интенсивности трафика).
2. **Buckets**: Настройка агрегации (например, **Terms** по полю `response.keyword` или **Date Histogram** по `@timestamp`).
3. **Dashboard**: Объединение созданных элементов. Все элементы дашборда интерактивны — клик по сектору диаграммы автоматически фильтрует остальные панели.

### 4. Мониторинг и Observability
- **Cluster Health**: Проверка через Dev Tools (`GET /_cluster/health`) или в разделе `Index Management`.
- **Observability Plugin**: Объединяет логи, метрики (OpenTelemetry) и трассировки в единые представления.
- **Alerting**: Настройка мониторов (`Alerting -> Monitors`), которые отправляют уведомления при срабатывании триггеров (например, CPU > 75% или рост ошибок 5xx).

### 5. Резервное копирование и восстановление
Управление через **Snapshot Management**:
1. **Snapshots**: Просмотр доступных копий.
2. **Restore**: Восстановление конкретных индексов.
   - **Важно**: При восстановлении в Managed-средах (например, Selectel) может потребоваться пропустить восстановление состояния кластера (`Restore cluster state: false`).
   - Можно использовать префиксы (например, `restored_`) для предотвращения конфликтов с существующими индексами.
