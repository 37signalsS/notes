# Обзор OpenSearch

## Определения

**OpenSearch** — это полностью открытый, распределенный поисковый и аналитический движок, являющийся ответвлением (форком) **Elasticsearch** и **Kibana**. Проект был инициирован компанией Amazon Web Services (AWS) в ответ на изменение лицензионной политики Elastic.

OpenSearch предлагает тот же функционал, что и Elasticsearch, включая полнотекстовый поиск, аналитику логов, мониторинг приложений и анализ безопасности, но под полностью свободной лицензией Apache 2.0.

## Основные концепции

### Причины появления OpenSearch

Основной причиной создания OpenSearch стало изменение лицензии Elasticsearch и Kibana компанией Elastic, начиная с версии 7.11. Новая лицензия (Elastic License v2 и SSPL) накладывает ограничения на использование продуктов в коммерческих решениях по модели «программное обеспечение как услуга» (Software as a Service, SaaS), что вызвало обеспокоенность в сообществе.

OpenSearch является полностью открытой альтернативой, поддерживаемой консорциумом технологических компаний, и сохраняет совместимость с интерфейсом программирования приложений (Application Programming Interface, API) Elasticsearch.

### Компоненты

* **OpenSearch**: ядро для хранения, поиска и анализа данных.
* **OpenSearch Dashboards**: веб-интерфейс пользователя (User Interface, UI) для визуализации и анализа данных.

## Практические сценарии

### Использование как хранилища для Jaeger

Помимо собственного плагина Observability, OpenSearch часто используется как простое и надежное хранилище для трассировок, собираемых системой **[Jaeger](../../Jaeger/jaeger_overview.md)**.

* **Принцип работы**: в этой конфигурации Jaeger (компонент `jaeger-collector`) настроен на использование OpenSearch как своего серверного хранилища (бэкенда). Он самостоятельно управляет жизненным циклом данных, создавая ежедневные индексы для спанов и сервисов (например, `jaeger-span-2023-10-27`).
* **Чтение данных**: запросы на получение трасс из интерфейса Jaeger UI обрабатываются компонентом `jaeger-query`, который обращается напрямую к этим индексам в OpenSearch.

**Важно**: трассировки, сохраненные Jaeger в своих собственных индексах, **несовместимы** с дашбордами плагина Observability. Для использования нативного интерфейса трассировки в OpenSearch требуется отправка данных в формате OpenTelemetry Protocol (OTLP) через компонент **Data Prepper**. Эти два подхода к хранению трасс являются взаимоисключающими с точки зрения их анализа в интерфейсе пользователя.

### Плагин Observability и Data Prepper

OpenSearch предоставляет встроенный плагин **Observability**, который позволяет анализировать трассировки, метрики и логи в едином интерфейсе. Это бесплатная альтернатива аналогичным платным функциям в стеке Elastic.

Для использования дашбордов трассировки в этом плагине требуется специальный компонент **Data Prepper**.

* **Data Prepper**: это отдельный сервис-коллектор, который получает телеметрические данные в формате OTLP, преобразует их в нужный для OpenSearch формат и сохраняет в соответствующие индексы (`trace-analytic-row`, `trace-analytic-service-map`).

Типичная архитектура для сбора трасс:
`Приложение -> OTLP Collector -> Data Prepper -> OpenSearch`
