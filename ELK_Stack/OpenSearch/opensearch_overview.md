# Обзор OpenSearch

## Определения

**OpenSearch** — это полностью открытый, распределенный поисковый и аналитический движок, являющийся форком (ответвлением) **Elasticsearch** и **Kibana**. Проект был инициирован Amazon Web Services (AWS) в ответ на изменение лицензионной политики Elastic.

OpenSearch предлагает тот же функционал, что и Elasticsearch, включая полнотекстовый поиск, аналитику логов, мониторинг приложений и анализ безопасности, но под полностью свободной лицензией Apache 2.0.

## Основные концепции

### Причины появления OpenSearch

Основной причиной создания OpenSearch стало изменение лицензии Elasticsearch и Kibana компанией Elastic, начиная с версии 7.11. Новая лицензия (Elastic License v2 и SSPL) накладывает ограничения на использование продуктов в коммерческих SaaS-решениях, что вызвало обеспокоенность в сообществе.

OpenSearch является полностью открытой альтернативой, поддерживаемой консорциумом технологических компаний, и сохраняет совместимость с API Elasticsearch.

### Компоненты

*   **OpenSearch**: Ядро, аналогичное Elasticsearch, для хранения, поиска и анализа данных.
*   **OpenSearch Dashboards**: Веб-интерфейс для визуализации и анализа данных, аналог Kibana.

## Практические сценарии

### Использование как хранилища для Jaeger

Помимо собственного плагина Observability, OpenSearch часто используется как простое и надежное хранилище для трейсов, собираемых системой **[Jaeger](../../Jaeger/jaeger_overview.md)**.

*   **Принцип работы:** В этой конфигурации Jaeger (компонент `jaeger-collector`) настроен на использование OpenSearch как своего бэкенда. Он самостоятельно управляет жизненным циклом данных, создавая ежедневные индексы для спанов и сервисов (например, `jaeger-span-2023-10-27`).
*   **Чтение данных:** Запросы на получение трейсов из Jaeger UI обрабатываются компонентом `jaeger-query`, который обращается напрямую к этим индексам в OpenSearch.

> **Важно:** Трейсы, сохраненные Jaeger в своих собственных индексах, **несовместимы** с дашбордами плагина `Observability`. Для использования нативного UI трейсинга в OpenSearch требуется отправка данных в формате OTLP через **Data Prepper**. Эти два подхода к хранению трейсов являются взаимоисключающими с точки зрения их анализа в UI.

### Плагин Observability и Data Prepper

OpenSearch предоставляет встроенный плагин **Observability**, который позволяет анализировать трейсы, метрики и логи в едином интерфейсе. Это бесплатная альтернатива аналогичным платным функциям в стеке Elastic.

Для использования дашбордов трейсинга в этом плагине требуется специальный компонент **Data Prepper**.

*   **Data Prepper**: Это отдельный сервис-коллектор, который получает телеметрические данные в формате **OTLP (OpenTelemetry Protocol)**, преобразует их в нужный для OpenSearch формат и сохраняет в соответствующие индексы (`trace-analytic-row`, `trace-analytic-service-map`).

Типичная архитектура для сбора трейсов выглядит следующим образом:
`Приложение -> OTLP Collector -> Data Prepper -> OpenSearch`
