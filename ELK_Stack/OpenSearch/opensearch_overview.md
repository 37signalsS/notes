# OpenSearch: Обзор

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения OpenSearch — полностью открытой альтернативы Elastic Stack.

## Определения

* **OpenSearch** — распределенный поисковый и аналитический движок с открытым исходным кодом (лицензия Apache 2.0). Проект создан как форк Elasticsearch 7.10.2 и развивается под эгидой OpenSearch Foundation (при поддержке AWS, Oracle, Red Hat и др.).
* **OpenSearch Dashboards** — веб-интерфейс для визуализации данных и управления кластером (форк Kibana).
* **Neural Search** — набор возможностей для реализации семантического поиска с использованием векторов (embeddings) и моделей машинного обучения.
* **Search Pipeline** — механизм модульной обработки поисковых запросов и ответов (переписывание запросов, фильтрация, нормализация) на стороне сервера.
* **Remote-Backed Storage** — архитектурное решение, позволяющее использовать объектные хранилища (S3, Azure Blob) как основной уровень хранения данных, обеспечивая высокую долговечность и разделение ресурсов вычисления и хранения.

## Основные концепции

### История и лицензирование

OpenSearch появился в 2021 году после изменения лицензионной политики Elastic. В отличие от Elasticsearch, OpenSearch остается под лицензией Apache 2.0, что позволяет использовать все функции (Security, Alerting, ML) бесплатно в коммерческих и SaaS-решениях. По состоянию на 2026 год OpenSearch значительно дивергировал от Elasticsearch, сфокусировавшись на открытости и интеграции с генеративным ИИ.

### Ключевые возможности (OpenSearch 2.15+)

* **Встроенная безопасность (Security Plugin)**: TLS, интеграция с AD/LDAP/SAML и тонкая настройка прав доступа (FGAC) включены в базовую версию.
* **Segment Replication**: Репликация на уровне файлов Lucene (вместо повторного выполнения запросов на репликах), что снижает нагрузку на CPU на 40-50%.
* **Disk-Optimized Vector Search**: Использование бинарного квантования (Binary Quantization) позволяет сократить потребление памяти для векторного поиска до 32 раз, сохраняя высокую точность.
* **Hybrid Search**: Возможность одновременного выполнения лексического (BM25) и векторного поиска с автоматическим ранжированием результатов.
* **Index State Management (ISM)**: Автоматизация жизненного цикла индексов через политики (ротация, перемещение на холодные узлы, удаление).

### OpenSearch как векторная база данных

OpenSearch является одним из лидеров среди векторных хранилищ благодаря плагину **k-NN**:
- **Движки**: Поддержка Faiss, NMSLIB и Lucene.
- **Масштабируемость**: Возможность поиска по миллиардам векторов в распределенном кластере.
- **Интеграция с ML**: Поддержка локальных моделей (на узлах кластера) и интеграция с внешними сервисами (Amazon Bedrock, OpenAI) для генерации эмбеддингов "на лету" через Ingest Pipelines.

### Сравнение с Elasticsearch (Актуально на 2026 год)

| Характеристика | OpenSearch | Elasticsearch |
| :--- | :--- | :--- |
| **Лицензия** | Apache 2.0 (Open Source) | ELv2 / SSPL (Проприетарная) |
| **Стоимость** | Все функции бесплатны | Платные Enterprise-функции |
| **AI/ML** | Гибкая интеграция любых моделей | Мощные встроенные модели (ELSER) |
| **Хранение** | Глубокая интеграция с S3 (Remote Storage) | Оптимизированные Searchable Snapshots |
| **Производительность** | Лидер в скорости индексации | Лидер в задержках сложного поиска |

## Практические сценарии

### Реализация RAG (Retrieval-Augmented Generation)

OpenSearch выступает в роли хранилища знаний для LLM:
1. **Ingest**: Данные поступают в OpenSearch, где Neural Search Pipeline автоматически превращает текст в векторы.
2. **Search**: Пользователь задает вопрос, выполняется Hybrid Search для поиска наиболее релевантных кусков текста.
3. **Response**: Результаты поиска передаются в LLM как контекст для генерации точного ответа.

### Интеграция с Jaeger для трассировки

OpenSearch — стандартный бэкенд для **[Jaeger](../../Jaeger/jaeger_overview.md)**:
- **Прямая запись**: Jaeger Collector пишет спаны напрямую в индексы OpenSearch.
- **Trace Analytics**: Использование плагина Observability в OpenSearch Dashboards для визуализации карт сервисов и поиска "узких мест" в распределенных транзакциях.

### Автоматизация логов через ISM

Настройка политик хранения без внешних инструментов:
- **Hot**: Логи активно пишутся на SSD-узлы (7 дней).
- **Warm**: Индексы переносятся на HDD или Remote Storage (23 дня).
- **Delete**: Автоматическое удаление через 30 дней.
