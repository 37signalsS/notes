# Практическое руководство по настройке ELK (Elastic Stack)

## 1. Зачем нужна централизация логов?

В небольших проектах с одним-двумя сервисами анализ логов не представляет сложности — достаточно подключиться к серверу и изучить локальные файлы. Однако с ростом проекта до отказоустойчивого кластера с множеством сервисов возникают проблемы:

1.  **Трудоемкий поиск:** Приходится "прыгать" по серверам и вручную агрегировать логи, что отнимает много времени при поиске причин сбоя.
2.  **Хранение логов:** Возрастающая нагрузка генерирует большой объем логов (например, от балансировщика), который требует значительного дискового пространства. Масштабировать диски на каждом сервере — неэффективное решение.
3.  **Доступ для аналитики:** Предоставлять аналитикам прямой доступ к логам на боевых серверах небезопасно и неудобно. Необходимы инструменты для безопасного доступа, визуализации и построения отчетов.

Эти проблемы решает централизованная система логирования, такая как Elastic Stack.

## 2. Компоненты Elastic Stack

-   **Elasticsearch:** Поисковый и аналитический движок, ядро стека. Хранит и индексирует данные для быстрого поиска.
-   **Logstash:** Серверный конвейер для сбора, преобразования (парсинга) и отправки данных в Elasticsearch.
-   **Kibana:** Веб-интерфейс для поиска, анализа и визуализации данных, хранящихся в Elasticsearch.
-   **Beats:** Легковесные агенты для сбора данных. Мы будем использовать **Filebeat** — он удобен, менее ресурсоемок по сравнению с Logstash и хорошо подходит для сбора логов из файлов и других источников.

## 3. Практическая настройка стека в Docker

Развернем тестовый стенд, состоящий из Elasticsearch, Kibana и Filebeat. Все компоненты должны иметь **одинаковую версию** (в нашем примере `8.7.0`), чтобы избежать проблем с совместимостью.

### Шаг 1: Подготовка окружения

1.  **Создаем Docker-сеть:**

    ```bash
    docker network create elk
    ```
2.  **Настраиваем системный параметр для Elasticsearch:**

    Elasticsearch требует увеличения лимита `vm.max_map_count`.

    ```bash
    sudo sysctl -w vm.max_map_count=262144
    ```

### Шаг 2: Запуск Elasticsearch

1.  **Запускаем контейнер:**

    ```bash
    docker run --name es01 --net elk -p 9200:9200 -it -m 1GB \
      docker.elastic.co/elasticsearch/elasticsearch:8.7.0
    ```

    *   `-m 1GB` — Ограничиваем память, что важно для локального запуска.

2.  **Сохраняем учетные данные:** После первого запуска Elasticsearch сгенерирует пароль для пользователя `elastic` и токен для подключения Kibana. **Обязательно сохраните их!**

### Шаг 3: Запуск Kibana

1.  **Запускаем контейнер:**

    ```bash
    docker run --name kib-01 --net elk -p 5601:5601 \
      docker.elastic.co/kibana/kibana:8.7.0
    ```

2.  **Подключаем к Elasticsearch:**

    -   Откройте Kibana в браузере (`http://localhost:5601`).
    -   Вставьте токен, который вы сохранили на предыдущем шаге.
    -   Авторизуйтесь, используя логин `elastic` и сгенерированный пароль.

### Шаг 4: Настройка и запуск Filebeat

1.  **Конфигурация (`filebeat.yml`):**

    Создадим конфигурационный файл для приема логов по HTTP.

    ```yaml
    filebeat.inputs:
    - type: http_endpoint
      listen_address: 0.0.0.0
      listen_port: 8080
      response_code: 200
      response_body: '{"status": "ok"}'

    output.elasticsearch:
      hosts: ["https://<IP_АДРЕС_КОНТЕЙНЕРА_ES>:9200"]
      username: "elastic"
      password: "<ВАШ_ПАРОЛЬ>"
      ssl:
        enabled: true
        ca_trusted_fingerprint: "<FINGERPRINT>" # или используйте сертификат
        # certificate_authorities: ["/usr/share/filebeat/certs/ca.crt"]
    ```

    *   IP-адрес контейнера Elasticsearch можно узнать командой `docker inspect es01`.
    *   Для подключения к Elasticsearch v8 требуется настроить SSL. Проще всего скопировать CA-сертификат из контейнера Elasticsearch.

2.  **Копируем сертификат:**

    ```bash
    docker cp es01:/usr/share/elasticsearch/config/certs/http_ca.crt .
    ```

3.  **Запускаем Filebeat:**

    Не забудьте смонтировать конфигурационный файл и сертификат в контейнер.

### Шаг 5: Отправка и просмотр логов

1.  **Отправляем лог через `curl`:**

    ```bash
    curl -X POST "http://localhost:8080" -H "Content-Type: application/json" -d'
    {
      "message": "User logged in successfully",
      "user_id": "testuser",
      "level": "info"
    }
    '
    ```

2.  **Просмотр в Kibana:**

    -   Перейдите в `Stack Management -> Index Management -> Data Streams`, чтобы убедиться, что данные пришли и был создан соответствующий индекс.
    -   Перейдите в `Discover` и создайте **Data View** (например, с паттерном `logs-*`), чтобы увидеть ваши логи.

## 4. Ключевые концепции Elasticsearch

### Индексы, шаблоны и компоненты

-   **Индекс (Index):** Место хранения документов. Аналог таблицы в реляционных базах данных.
-   **Шаблон индекса (Index Template):** Набор правил (настройки, маппинги), который применяется к новым индексам, соответствующим определенному паттерну (например, `logs-*`).
-   **Компонентный шаблон (Component Template):** Переиспользуемые блоки конфигурации (например, маппинги или настройки шард), которые можно включать в шаблоны индексов, следуя принципу DRY.

### Маппинг (Mapping)

Маппинг — это схема данных для индекса, определяющая типы полей (например, `text`, `keyword`, `date`, `integer`).

-   **Почему это важно?** Правильный маппинг позволяет Elasticsearch эффективно индексировать и искать данные. Поле, смапленное как `date`, можно сортировать по времени; поле `keyword` — использовать для точных совпадений и агрегаций.
-   **Динамический маппинг:** По умолчанию Elasticsearch пытается угадать тип поля. В продуктивных средах это **не рекомендуется**, так как может привести к неоптимальному использованию ресурсов и увеличению размера индекса. Лучше определять маппинг явно.

### Ingest Pipelines (Конвейеры обработки)

Пайплайны выполняют предварительную обработку документов **перед** их индексацией.

-   **Процессоры:** Пайплайн состоит из процессоров. Самый популярный — **`grok`**.
-   **Grok:** Позволяет парсить неструктурированные текстовые данные (например, логи Nginx или syslog) в структурированные поля с помощью регулярных выражений.

**Пример:** Строку лога Nginx можно разбить на поля `client.ip`, `http.status_code`, `url.path` и т.д., что делает возможным поиск и агрегацию по этим полям.

### Управление жиненным циклом (Index Lifecycle Management - ILM)

ILM автоматизирует управление индексами, перемещая их по фазам в зависимости от заданных правил.

-   **Фазы:** 
    1.  **Hot:** Индекс активно используется для записи и чтения (самые быстрые диски).
    2.  **Warm:** Запись прекращена, но данные все еще часто запрашиваются. Индекс можно переместить на более медленные диски.
    3.  **Cold:** Данные редко используются. Индекс можно сжать или сделать read-only.
    4.  **Delete:** Индекс удаляется.
-   **Rollover (Ротация):** Ключевая операция в ILM. Когда индекс достигает определенного размера, возраста или количества документов, ILM автоматически создает новый индекс для записи, а старый переводит в следующую фазу.

### Потоки данных (Data Streams)

Абстракция поверх индексов, предназначенная для работы с временными рядами (логи, метрики). Data Stream автоматически управляет ротацией и созданием новых индексов, упрощая конфигурацию агентов (им достаточно знать только имя потока, а не конкретного индекса).

## 5. Визуализация в Kibana

-   **Discover:** Основной инструмент для интерактивного поиска и фильтрации логов.
-   **Dashboards:** Позволяют объединять различные визуализации (графики, таблицы, карты) на одном экране для создания комплексных панелей мониторинга.
-   **KQL (Kibana Query Language):** Простой и мощный язык запросов, используемый в строке поиска в Discover для фильтрации данных.
