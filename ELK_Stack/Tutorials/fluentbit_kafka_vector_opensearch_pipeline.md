# Практическое руководство: Построение отказоустойчивого конвейера логов с Fluent Bit, Kafka, Vector и OpenSearch

> Руководство описывает архитектуру и практические шаги для создания масштабируемого конвейера сбора, обработки и хранения логов.
>
> **Базовые понятия:** [Fluent Bit](../../Kubernetes/MonitoringLogging/EFK/fluentbit/fluent_comparison.md), [Kafka](../../Kafka/kafka_overview.md), [Vector](../../Vector/vector_overview.md), [OpenSearch](../OpenSearch/opensearch_overview.md).

## Определения

* **Конвейер логов**: Последовательность компонентов для сбора, обработки и хранения логов. Схема: `Fluent Bit → Kafka → Vector → OpenSearch`.
* **Асинхронная буферизация**: Механизм защиты от потери данных через промежуточный персистентный буфер (Kafka).
* **Противодавление (Backpressure)**: Ситуация, когда хранилище не успевает обрабатывать входящий поток данных, что приводит к блокировке отправителя или потере данных.

## Основные концепции

### Проблема: Потеря логов в высоконагруженных системах

В архитектуре с прямой отправкой (`Fluent Bit → OpenSearch`) существуют риски:

* **Переполнение буфера агента**: Внутренний буфер Fluent Bit ограничен. При длительной недоступности хранилища буфер переполняется, новые логи отбрасываются.
* **Отсутствие гарантии доставки**: При сбоях хранилища данные теряются безвозвратно.

### Решение: Архитектура с Kafka как буфером

Промежуточный персистентный буфер на базе Apache Kafka решает проблему надежности.

**Схема конвейера:**

```
Fluent Bit → Kafka → Vector → OpenSearch
```

### Роли компонентов

| Компонент | Роль | Задача |
| :--- | :--- | :--- |
| **Fluent Bit** | Агент-сборщик | Сбор логов с хостов/контейнеров Kubernetes, минимальная обработка, отправка в Kafka |
| **Kafka** | Персистентный буфер | Прием всего потока логов, сглаживание пиковых нагрузок, надежное хранение на диске |
| **Vector** | Агрегатор/трансформер | Чтение из Kafka, трансформация (парсинг JSON, преобразование полей), отправка в OpenSearch |
| **OpenSearch** | Хранилище | Индексация логов, полнотекстовый поиск, агрегация, визуализация через Dashboards |

### Ключевые преимущества архитектуры

* **Надежность**: Гарантия доставки логов при сбоях компонентов.
* **Масштабируемость**: Независимое масштабирование каждого компонента (брокеры Kafka, партиции, экземпляры Vector).
* **Гибкость**: Централизованная обработка в Vector без изменения конфигурации агентов.
* **Производительность**: Минимальная нагрузка на хосты благодаря легковесному агенту.

## Практические сценарии

### Настройка Fluent Bit: Отправка в Kafka

Ключевая часть — настройка `[OUTPUT]` для отправки логов в разные топики Kafka по тегу.

Подробный пример: **[Буферизация и маршрутизация в Fluent Bit](../../Kubernetes/MonitoringLogging/EFK/fluentbit/buffering_routing.md)**.

### Настройка Vector: Трансформация данных из Kafka

Vector использует язык **VRL (Vector Remap Language)** для преобразований:

* Парсинг JSON-логов
* Преобразование имен полей (`kubernetes.labels` → `kubernetes_labels`)
* Удаление ненужных полей
* Обогащение метаданными

Подробное описание VRL и примеры: **[Обзор Vector](../../Vector/vector_overview.md)**.

## Дополнительная информация

* **Мониторинг конвейера**: Отслеживайте лаг консьюмеров Kafka (Vector), размер очередей, скорость обработки событий.
* **Оптимизация производительности**: Увеличивайте число партиций Kafka для параллелизма, масштабируйте Vector горизонтально.
* **Безопасность**: Настройте TLS для всех соединений, аутентификацию в Kafka (SASL/SCRAM), RBAC в OpenSearch.
* **Смежные темы**: [Использование Kafka для мониторинга](../../Kafka/kafka_for_monitoring.md).
