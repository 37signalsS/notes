# Руководство: Настройка кластера Elasticsearch 8

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и описывает пошаговую настройку мультин-одового кластера Elasticsearch на примере версии 8.x.

## Определения

* **Токен регистрации (Enrollment Token)**: В Elasticsearch 8, временный токен, используемый для безопасного присоединения новых узлов к кластеру, автоматически настраивающий TLS и параметры безопасности.

## Основные концепции

Для получения полного понимания основных концепций Elasticsearch, таких как роли узлов, индексы, шарды, реплики, а также статусы кластера и кворум, обратитесь к **[Обзору Elasticsearch](../../ELK_Stack/Elasticsearch/elasticsearch_overview.md)**.

### Конфигурация узла и кластера

Основные параметры для настройки поведения узла и его взаимодействия с кластером:

* **`cluster.name`**: Уникальное имя кластера. Должно быть идентичным на всех узлах для их корректного объединения.
* **`node.name`**: Уникальное имя для каждого узла в кластере.
* **`network.host`**: IP-адрес(а), на которых узел будет слушать входящие соединения. Для продакшн-систем рекомендуется указывать конкретный IP-адрес.
* **`http.port`**: Порт для HTTP-соединений (REST API), по умолчанию `9200`.
* **`transport.port`**: Порт для внутренних коммуникаций между узлами кластера, по умолчанию `9300`.
* **`discovery.seed_hosts`**: Список IP-адресов или доменных имен узлов, которые потенциально могут быть мастер-узлами. Используется для обнаружения других узлов при старте.
* **`cluster.initial_master_nodes`**: **Критически важный параметр** для первого запуска кластера. Содержит список `node.name` узлов, которые имеют право быть мастерами при первичном формировании кластера. **Используется только один раз.** После успешного формирования кластера этот параметр следует удалить или закомментировать.

### Безопасность

Начиная с версии 8.x, Elasticsearch по умолчанию обеспечивает безопасность с использованием TLS и встроенных механизмов аутентификации/авторизации.

* **TLS (Transport Layer Security)**: Шифрование трафика между узлами кластера и между клиентами и кластером.
* **Встроенные пользователи**: Elasticsearch включает предопределенных пользователей, таких как `elastic` (суперпользователь) для администрирования. Пароли для них генерируются при первом запуске.
* **Токен регистрации (`enrollment token`)**: Рекомендуемый способ безопасного присоединения новых узлов к существующему кластеру. Токен содержит всю информацию для автоматической настройки TLS на новом узле.

## Практические сценарии

### Шаг 1: Подготовка и установка

1. **Убедитесь, что на всех узлах установлена Java** (рекомендуется OpenJDK).
2. **Установите пакет Elasticsearch** на **каждый** узел будущего кластера. В Ubuntu/Debian:

    ```bash
    sudo apt update
    sudo apt install elasticsearch
    ```

### Шаг 2: Настройка первого узла (Bootstrap)

Первый узел запускается особенным образом, чтобы сформировать основу кластера.

1. **Отредактируйте файл конфигурации** `/etc/elasticsearch/elasticsearch.yml`:

    ```yaml
    # Уникальное имя кластера. Должно быть одинаковым на всех узлах.
    cluster.name: my-es-cluster
    # Уникальное имя для текущего узла.
    node.name: node-1
    # Слушать на всех IP-адресах (для простоты). В production используйте конкретный IP.
    network.host: 0.0.0.0
    http.port: 9200
    transport.port: 9300
    # IP-адреса ВСЕХ узлов кластера для обнаружения.
    discovery.seed_hosts: ["192.168.101.63", "192.168.101.64", "192.168.101.65"]
    # Имена узлов, которые могут стать мастерами при ПЕРВОМ запуске.
    cluster.initial_master_nodes: ["node-1", "node-2", "node-3"]
    ```

    * `discovery.seed_hosts`: Перечислите IP-адреса всех узлов, которые войдут в кластер.
    * `cluster.initial_master_nodes`: **Важно!** Этот параметр используется только при самом первом запуске кластера. После того как кластер сформирован, его можно удалить.

### Шаг 3: Запуск и установка пароля

1. **Запустите сервис Elasticsearch:**

    ```bash
    sudo systemctl start elasticsearch
    sudo systemctl enable elasticsearch
    ```

2. **Установите пароль для суперпользователя `elastic`**. После первого запуска Elasticsearch 8 генерирует пароли. Чтобы задать свой, выполните:

    ```bash
    sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic -i
    # Введите и подтвердите новый пароль.
    ```

    Сохраните этот пароль, он понадобится для доступа к кластеру.

### Шаг 4: Добавление новых узлов в кластер

1. **На первом (уже работающем) узле сгенерируйте токен для присоединения:**

    ```bash
    sudo /usr/share/elasticsearch/bin/elasticsearch-create-enrollment-token -s node
    # Скопируйте сгенерированный длинный токен. Он действует 30 минут.
    ```

2. **На новом узле (который нужно присоединить):**
    * Убедитесь, что Elasticsearch остановлен: `sudo systemctl stop elasticsearch`.
    * **Важно: Очистите данные**, если узел ранее запускался отдельно. Это необходимо, чтобы он мог получить конфигурацию безопасности от кластера.

        ```bash
        # Этот шаг удалит все данные и конфигурацию узла!
        sudo rm -rf /var/lib/elasticsearch/*
        ```

    * Отредактируйте `elasticsearch.yml` точно так же, как на первом узле, но с уникальным `node.name` (например, `node-2`). Параметры `cluster.name` и `discovery.seed_hosts` должны быть идентичными.
    * **Выполните команду присоединения к кластеру**, используя скопированный токен:

        ```bash
        sudo /usr/share/elasticsearch/bin/elasticsearch-reconfigure-node --enrollment-token <ВАШ_ТОКЕН>
        ```

        Эта команда автоматически настроит TLS-сертификаты и параметры безопасности.
    * **Запустите Elasticsearch на новом узле:**

        ```bash
        sudo systemctl start elasticsearch
        sudo systemctl enable elasticsearch
        ```

3. **Повторите шаги 1-2 для всех остальных узлов.**

### Шаг 5: Проверка состояния кластера

```bash
# Проверить список узлов в кластере
curl -k -u elastic:<пароль> "https://localhost:9200/_cat/nodes?v"

# Проверить общее "здоровье" кластера
curl -k -u elastic:<пароль> "https://localhost:9200/_cluster/health?pretty"
```

*Флаг `-k` используется для игнорирования проверки самоподписанного сертификата. В production следует настроить доверенные сертификаты.*

Вы должны увидеть все ваши узлы, а статус `health` должен быть `green` или `yellow`.

### Шаг 6: Управление индексами

#### Создание индекса

```bash
curl -k -u elastic:<пароль> -X PUT "https://localhost:9200/my_test_index?pretty" -H 'Content-Type: application/json' -d'
{
  "settings": {
    "index.number_of_shards": 3,
    "index.number_of_replicas": 1
  }
}
'
```

*Для кластера из 3-х узлов имеет смысл создать 3 шарда и 1 или 2 реплики.*

#### Изменение количества реплик

```bash
curl -k -u elastic:<пароль> -X PUT "https://localhost:9200/my_test_index/_settings?pretty" -H 'Content-Type: application/json' -d'
{
  "index.number_of_replicas": 2
}
'
```

#### Просмотр информации о шардах

```bash
curl -k -u elastic:<пароль> -X GET "https://localhost:9200/_cat/shards/my_test_index?v"
```

## Дополнительная информация

### Типичные проблемы и отладка

* **Узел не присоединяется к кластеру:**
  * Проверьте логи: `sudo journalctl -u elasticsearch -f`.
  * Убедитесь, что `cluster.name` совпадает на всех узлах.
  * Проверьте сетевую связность между узлами (`ping`, `nc`). Порты `9200` и `9300` должны быть доступны.
  * Убедитесь, что `discovery.seed_hosts` содержит правильные IP-адреса.
* **Кластер в статусе Yellow:** Обычно означает, что не все реплики распределены. Это нормально, если узлов меньше, чем `1 (primary) + N (replicas)`.
* **Кластер в статусе Red:** Потерян один или несколько **первичных** шардов. Это серьезная проблема, означающая потерю данных.
* **Проблемы с сертификатами (TLS):** Использование токена регистрации — самый надежный способ избежать проблем с ручной настройкой TLS.
* **Приложения не видят кластер:** Убедитесь, что клиент вашего приложения настроен на работу с несколькими узлами кластера и умеет обрабатывать отказ одного из них.

### Рекомендации

* **Используйте конкретные версии:** Избегайте использования тега `latest`. Всегда указывайте конкретную, проверенную версию (например, `8.11.1`).
* **Изучайте логи:** Логи Elasticsearch — ваш главный источник информации для диагностики.
* **Согласование с разработчиками:** Убедитесь, что приложения, работающие с Elasticsearch, спроектированы с учетом его кластерной природы.
