# Logstash: Обзор

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения Logstash.
>
> **Детальное описание архитектуры конвейеров, фильтров и оптимизации** — в заметке **[Logstash: Конвейеры, фильтры и производительность](./logstash_pipelines.md)**.

## Определения

* **Logstash** — серверный конвейер обработки данных (Dataflow Engine) с открытым исходным кодом. Он позволяет принимать данные из множества источников одновременно, преобразовывать их (парсинг, обогащение, фильтрация) и отправлять в выбранное хранилище (обычно Elasticsearch).
* **Pipeline (Конвейер)** — логическая единица обработки данных в Logstash, состоящая из стадий ввода, фильтрации и вывода.
* **Event (Событие)** — базовая единица данных, проходящая через конвейер, представляющая собой JSON-подобную структуру.

## Основные концепции

### Ключевые характеристики

- **Модульность:** Весь функционал реализован через плагины (более 200 типов: inputs, filters, outputs, codecs).
- **Масштабируемость и отказоустойчивость:**
    - **Persistent Queues (PQ):** Позволяют сохранять события на диск для защиты от потери данных при сбое процесса.
    - **Dead Letter Queues (DLQ):** Механизм для сбора событий, которые не удалось обработать (например, из-за ошибок маппинга в Elasticsearch).
- **Централизованное управление:** Возможность управления конфигурациями конвейеров через Kibana (Centralized Pipeline Management).

### Стадии обработки данных

Logstash работает по модели **Input → Filter → Output**:

1. **Input (Ввод):** Сбор данных из различных источников.
    - Популярные: `beats`, `kafka`, `syslog`, `http`, `snmp`, `jdbc`.
2. **Filter (Фильтрация):** Преобразование и обогащение данных.
    - Популярные: `grok` (регулярные выражения), `dissect` (разбиение по разделителям), `mutate` (переименование, удаление полей), `geoip` (определение местоположения), `ruby` (произвольный код).
3. **Output (Вывод):** Отправка обработанных данных в целевые системы.
    - Популярные: `elasticsearch`, `kafka`, `s3`, `http`, `zabbix`, `influxdb`.

## Практические сценарии

### Конфигурационные файлы

- **`logstash.yml`**: Глобальные настройки узла (API, мониторинг, количество воркеров, пути).
- **`pipelines.yml`**: Список активных конвейеров и пути к их файлам конфигурации. Позволяет запускать несколько независимых потоков на одном узле.
- **`jvm.options`**: Параметры виртуальной машины Java. Критически важны настройки `-Xms` и `-Xmx` (рекомендуется выделять не более 50-75% свободной памяти, но не более 31 ГБ).
- **`conf.d/*.conf`**: Описание логики конкретных конвейеров.

### Пример конфигурации: прием и парсинг логов

Пример конвейера, который принимает логи от Filebeat, парсит JSON-сообщения и отправляет их в Elasticsearch.

```conf
input {
  # Прием данных от агентов Filebeat/Metricbeat по протоколу Lumberjack
  beats {
    port => 5044
  }
}

filter {
  # Если сообщение является JSON, разбираем его
  if [message] =~ /^\{.*/ {
    json {
      source => "message"
      target => "doc" # Помещаем результат в отдельное поле для чистоты структуры
    }
  }

  # Обогащение данными о местоположении, если есть IP
  if [source][ip] {
    geoip {
      source => "[source][ip]"
    }
  }
}

output {
  elasticsearch {
    hosts => ["https://es-cluster.example.com:9200"]
    index => "logs-%{[agent][type]}-%{+YYYY.MM.dd}"
    user => "${ES_USER}" # Использование переменных окружения
    password => "${ES_PWD}"
    cacert => "/etc/logstash/certs/ca.crt"
  }
}
```

## Дополнительная информация

### Производительность и ограничения

- **Ресурсоемкость:** Logstash работает на JVM. Несмотря на перенос многих компонентов с JRuby на чистую Java, он остается требовательным к памяти и CPU по сравнению с легковесными агентами.
- **Backpressure:** Logstash автоматически замедляет чтение из источников (например, Beats), если Elasticsearch не успевает принимать данные.

### Сравнение Logstash и Vector

Подробное сравнение приведено в заметке **[Vector: Обзор](../../Vector/vector_overview.md#сравнение-с-аналогами)**.

| Характеристика | Logstash | Vector |
| :--- | :--- | :--- |
| **Язык разработки** | Java / JRuby | Rust |
| **Потребление ресурсов** | Высокое | Низкое |
| **Плагины** | Огромная экосистема (зрелость) | Быстрорастущая, но меньше |
| **Конфигурация** | Проприетарный DSL | TOML / YAML / JSON |

**Рекомендация:** Используйте Logstash, если вам нужна глубокая интеграция с Elastic Stack или специфические плагины. Используйте Vector для высоконагруженных систем, где критична экономия ресурсов.
