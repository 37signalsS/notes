# Logstash

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения Logstash.
>
> **Детальное описание архитектуры конвейеров, фильтров и оптимизации** — в заметке **[Logstash: Конвейеры, фильтры и производительность](./logstash_pipelines.md)**.

## Определения

**Logstash** — серверный конвейер обработки данных (Dataflow Engine), который позволяет принимать, обрабатывать и отправлять данные из множества источников в рамках Elastic Stack.

## Основные концепции

### Ключевые характеристики

- **Модульность:** Функциональность расширяется плагинами (вводы, фильтры, выводы, кодеки).
- **Масштабируемость и отказоустойчивость:** Работа в кластере, персистентная очередь на диске для защиты от потерь при сбоях.
- **Централизованная обработка:** Вынос тяжелых операций (парсинг, обогащение) с агентов на выделенный пул серверов.

### Архитектура конвейера (Pipeline)

Конвейер состоит из трех стадий: **Input → Filter → Output**. Подробное описание структуры, порядка фильтров и условной логики — в **[Logstash: Конвейеры, фильтры и производительность](./logstash_pipelines.md#структура-конвейера-pipeline)**.

**Популярные плагины:**

| Стадия | Плагины |
| :--- | :--- |
| **Input** | `beats` (агенты Elastic), `kafka`, `file`, `syslog`, `http`, `tcp`, `udp` |
| **Filter** | `grok` (парсинг), `dissect` (быстрый парсинг), `mutate` (преобразования), `json`, `geoip`, `anonymize` |
| **Output** | `elasticsearch`, `kafka`, `file`, `http`, `s3`, `zabbix` |

## Практические сценарии

### Конфигурация

- **`logstash.yml`**: Основной конфигурационный файл для настроек самого Logstash (API, воркеры, пути).
- **`pipelines.yml`**: Определяет, какие конвейеры запускать и где находятся их конфигурации.
- **`*.conf`**: Файлы с описанием логики конвейеров (`input`, `filter`, `output`).
- **`jvm.options`**: Настройки Java Virtual Machine (размер хипа `Xms`, `Xmx`).

### Пример конфигурации: парсинг JSON из логов Docker

Ниже представлен практический пример конфигурации Logstash. Он принимает логи от Filebeat (например, запущенного на Docker-хосте), проверяет, является ли сообщение валидным JSON, и если да, то парсит его.

```conf
input {
  beats {
    port => 5044
  }
}

filter {
  # Пытаемся распарсить поле 'message' как JSON.
  # Это частый сценарий для логов контейнеров (Docker, Kubernetes).
  json {
    source => "message"
    # Если парсинг удался, поля из JSON будут добавлены в корень события.
    # Если 'message' не является валидным JSON, по умолчанию Logstash добавит тег _jsonparsefailure.
  }
}

output {
  elasticsearch {
    hosts => ["http://elasticsearch.example.com:9200"]
    # Имя индекса формируется динамически.
    # %{[agent][name]} - имя хоста, с которого пришел лог.
    index => "filebeat-%{[agent][name]}-%{+YYYY.MM.dd}"
  }
}
```

### Использование для извлечения метрик из логов

С помощью фильтров (`grok`, `dissect`) Logstash может парсить текстовые логи, извлекать из них числовые значения (например, код ответа из лога Nginx) и преобразовывать их в метрики для дальнейшей агрегации и визуализации. Несмотря на гибкость, этот подход является **самым ресурсоемким** по сравнению с Push- и Pull-моделями сбора метрик.

> Подробное сравнение стратегий сбора метрик: **[Стратегии сбора метрик](../../Concepts/Observability_and_Monitoring/metrics_collection_strategies.md)**.

## Дополнительная информация

### Производительность и недостатки

- **Ресурсоемкость:** Написан на Java (JRuby), работает на JVM — требователен к CPU и RAM.
- **Сложность:** Конфигурация и отладка (особенно `grok`) могут быть трудоемкими.

Подробное описание оптимизации, настройки воркеров и очередей — в **[Logstash: Конвейеры, фильтры и производительность](./logstash_pipelines.md#производительность-и-надёжность)**.

### Сравнение Logstash и Vector

**[Vector](../../Vector/vector_overview.md)** — высокопроизводительный аналог на Rust для сбора, преобразования и маршрутизации логов и метрик.

| Характеристика | Logstash | Vector |
| :--- | :--- | :--- |
| **Язык** | JRuby (JVM) | Rust |
| **Производительность** | Низкая | Очень высокая |
| **Потребление ресурсов** | Высокое | Низкое |
| **Функциональность** | Огромное число плагинов | Хорошая, уступает Logstash |
| **Конфигурация** | Собственный формат | TOML, YAML, JSON |
| **Экосистема** | Зрелая (Elastic Stack) | Растущая |

**Когда выбирать:**

- **Logstash:** Глубокая интеграция в Elastic Stack, экзотические плагины, производительность не критична.
- **Vector:** Приоритет — производительность и низкое потребление ресурсов, стандартные сценарии, гибкая маршрутизация.
