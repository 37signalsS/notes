# Обзор стека ELK (Elastic Stack)

ELK, также известный как Elastic Stack, — это набор из трех мощных продуктов с открытым исходным кодом — Elasticsearch, Logstash и Kibana — от компании Elastic. Этот стек предназначен для сбора, обработки, хранения, поиска и визуализации больших объемов данных в реальном времени, чаще всего логов.

## Компоненты стека

1.  **[Elasticsearch](./Elasticsearch/elasticsearch_overview.md) (E)**: "Сердце" стека. Это распределенный поисковый и аналитический движок, основанный на Apache Lucene. Он отвечает за хранение данных и предоставляет мощный API для полнотекстового поиска и аналитики.
2.  **[Logstash](./Logstash/logstash_overview.md) (L)**: Серверный конвейер обработки данных. Logstash принимает данные из множества источников, трансформирует их (парсинг, обогащение, фильтрация) и отправляет в хранилище, которым чаще всего является Elasticsearch.
3.  **[Kibana](./Kibana/kibana_overview.md) (K)**: Веб-интерфейс для Elasticsearch. Kibana позволяет пользователям выполнять интерактивный поиск, анализировать и визуализировать данные с помощью графиков, дашбордов и карт.

В современной версии стека также важную роль играют **Beats** — семейство легковесных агентов, которые устанавливаются на конечные узлы для сбора различных типов данных (логи, метрики, сетевой трафик) и их отправки в Logstash или Elasticsearch.

## Схема работы

`Beats -> Logstash -> Elasticsearch -> Kibana`

1.  **Beats** собирают данные с машин.
2.  **Logstash** централизованно принимает данные, парсит неструктурированные логи в структурированные JSON-документы, обогащает их (например, добавляя геолокацию по IP) и фильтрует.
3.  **Elasticsearch** индексирует и сохраняет обработанные данные.
4.  **Kibana** подключается к Elasticsearch и предоставляет пользовательский интерфейс для работы с данными.

Для повышения надежности и отказоустойчивости между Beats и Logstash часто встраивают брокер сообщений, такой как **Kafka**, который выступает в роли буфера и предотвращает потерю данных при сбоях.
