# Обзор Elastic Stack (ELK)

## Определения

* **Elastic Stack (ранее ELK)** — это комплексное решение для централизованного сбора, поиска, анализа и визуализации данных (логов, метрик, трассировок) в реальном времени.
* **ELK** — аббревиатура по названиям трех классических компонентов: **E**lasticsearch, **L**ogstash, **K**ibana. В современной экосистеме к ним добавились **Beats** и **Elastic Agent**.
* **Fleet** — система централизованного управления парком агентов (Elastic Agent) через интерфейс Kibana.

## Основные концепции

### Компоненты стека

Современная архитектура Elastic Stack (версии 8.x и 9.x) предлагает два основных способа доставки данных:

#### 1. Современный подход (Agent-based)
**Elastic Agent + Fleet**: Единый агент для всех типов данных (логи, метрики, безопасность).
* **Elastic Agent**: Универсальный агент, который заменяет собой множество отдельных Beats.
* **Fleet Server**: Компонент, обеспечивающий связь между агентами и Kibana для централизованного обновления конфигураций и политик.
* **Интеграции (Integrations)**: Готовые наборы настроек, пайплайнов и дашбордов для популярных систем, устанавливаемые в один клик.

#### 2. Классический подход (Beats + Logstash)
Используется для сложных сценариев обработки данных и интеграции с устаревшими системами. В Kubernetes для сбора логов часто используются **Fluentd**, **Fluent Bit** или **Filebeat**.
* **[Beats](./filebeat_overview.md)**: Семейство легковесных агентов (Filebeat, Metricbeat, Packetbeat).
* **[Logstash](./Logstash/logstash_overview.md)**: Конвейер обработки данных на стороне сервера. Принимает логи из различных источников, обрабатывает (фильтрует, трансформирует) их и отправляет в Elasticsearch или OpenSearch.

#### 3. Ядро системы
* **[Elasticsearch](./Elasticsearch/elasticsearch_overview.md)**: Распределенная система поиска и аналитики. Хранит данные и предоставляет мощные возможности поиска и запросов.
* **[OpenSearch](./OpenSearch/opensearch_overview.md)**: Форк Elasticsearch от AWS. Полностью открытая альтернатива для хранения и поиска данных.
* **[Kibana](./Kibana/kibana_overview.md)**: Инструмент визуализации (для OpenSearch используется OpenSearch Dashboards). Обеспечивает интуитивно понятный интерфейс для изучения, анализа и визуализации данных логов.

### Архитектурные решения (Solutions)

Elastic Stack разделен на три ключевых направления (Solutions):
* **Search**: Полнотекстовый поиск, семантический поиск с использованием векторов и ИИ (Elastic Search AI).
* **Observability**: Мониторинг инфраструктуры, логов (Logging), метрик и производительности приложений (APM).
* **Security**: SIEM-система для обнаружения угроз, защита конечных точек (Endpoint Security) и облачных сред.

### Отказоустойчивость и буферизация

В высоконагруженных системах между агентами (Beats/Agent) и хранилищем (Elasticsearch) часто внедряется промежуточный слой:
* **Брокеры сообщений**: [Kafka](../../Kafka/kafka_overview.md) или Redis используются для защиты от потери данных при всплесках трафика (bursts).
* **Конвейер**: `Agent -> Kafka -> Vector (или Logstash) -> Elasticsearch`.

## Практические сценарии

* **Централизованное логирование**: Сбор системных и прикладных логов для быстрого поиска и отладки (Debugging).
* **Мониторинг инфраструктуры**: Отслеживание CPU, RAM, Disk и сетевой активности в реальном времени.
* **Детекция угроз**: Анализ событий безопасности для выявления атак и аномалий в поведении пользователей.
* **Бизнес-аналитика**: Визуализация KPI на основе данных из баз данных (через Logstash JDBC) или API.
