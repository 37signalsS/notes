# Kibana: Поиск, визуализация и управление

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и детально рассматривает инструменты Kibana для исследования данных, их визуализации и управления. Данные актуальны для версий **8.19 (LTS)** и **9.x**.

## Определения

* **KQL (Kibana Query Language)** — упрощенный язык запросов для быстрой фильтрации. Поддерживает интуитивный синтаксис и автодополнение полей.
* **Lucene Query Syntax** — классический и гибкий язык запросов, поддерживающий регулярные выражения (RegEx), нечеткий поиск и сложные логические группировки.
* **ES|QL (Elasticsearch Query Language)** — современный потоковый (piped) язык запросов. Позволяет фильтровать, агрегировать и трансформировать данные "на лету" прямо в процессе выполнения запроса.
* **Elastic AI Assistant** — ИИ-ассистент, интегрированный в интерфейс Kibana. Помогает преобразовывать естественный язык в запросы ES|QL, создавать визуализации и объяснять ошибки в логах.
* **Runtime Fields** — вычисляемые поля («схема при чтении»). Позволяют извлекать или модифицировать данные без переиндексации индекса.
* **Lens** — основной визуальный конструктор. Использует принцип drag-and-drop для быстрого создания диаграмм и автоматически подбирает их тип на основе структуры данных.

## Основные концепции

### Сравнение языков запросов

В современных версиях Kibana выбор языка зависит от сложности задачи:

| Характеристика | KQL | Lucene | ES|QL |
| :--- | :--- | :--- | :--- |
| **Стиль** | Фильтрация | Полнотекстовый поиск | Потоковая трансформация |
| **Синтаксис** | `field: value` | `field:"value" AND ...` | `FROM index | WHERE ... | STATS ...` |
| **Агрегации** | Через UI (Lens) | Через UI (Lens) | **Встроены в запрос** |
| **RegEx** | Нет | Да | Да |
| **Сложность** | Низкая | Средняя | Высокая (но мощная) |
| **Рекомендация** | Быстрый поиск в Discover | Глубокая отладка, RegEx | Аналитика, сложные отчеты |

### Модель представления данных

Kibana не изменяет исходные документы в Elasticsearch. `Data View` служит абстракцией, которая описывает структуру индексов. В версиях 9.x акцент смещен на **ES|QL**, который может работать напрямую с индексами или алиасами, минуя необходимость предварительного создания Data View для некоторых аналитических задач.

## Практические сценарии

### Анализ инцидента с помощью ES|QL

**Задача:** Выявить топ-10 IP-адресов, с которых поступает наибольшее количество запросов с ошибками 404, и рассчитать их средний объем трафика.

```esql
FROM logs-*
| WHERE http.response.status_code == 404
| STATS count = COUNT(*), avg_bytes = AVG(http.response.body.bytes) BY source.ip
| WHERE count > 100
| SORT count DESC
| LIMIT 10
```
*Этот запрос можно выполнить в **Discover** (вкладка ES|QL) и мгновенно превратить в визуализацию.*

### Использование AI Assistant для визуализации

1. Откройте **Dashboard** → **Create new**.
2. В строке AI Assistant введите: *"Создай дашборд для логов Nginx: график кодов ответа по времени и таблицу с топ-5 медленных URL"*.
3. Ассистент сгенерирует необходимые ES|QL запросы и предложит макет дашборда.
4. Вы можете уточнить запрос: *"Сделай график в виде Donut chart"*, и визуализация обновится автоматически.

### Создание интерактивных дашбордов (9.x)

В Kibana 9.x элементы управления стали более гибкими:
* **Draggable Controls**: Фильтры теперь являются панелями. Их можно размещать рядом с графиками, а не только в верхней строке.
* **Variable Controls**: Используйте ES|QL для динамического заполнения выпадающих списков. Например, показывать в фильтре только те `host.name`, которые были активны за последний час.
* **Scoping**: Фильтры можно применять не ко всему дашборду, а к конкретной группе панелей.

## Дополнительная информация

### Управление объектами (Saved Objects)

* **NDJSON и GitOps**: Все объекты (дашборды, визуализации) экспортируются в формате `.ndjson`. Это стандарт для версионирования настроек Kibana в Git и автоматизированного деплоя через API.
* **Tags**: Используйте теги для группировки объектов по проектам (например, `Project: Alpha`, `Tier: Frontend`), что упрощает поиск при наличии сотен дашбордов.

### Продвинутая аналитика

* **Vega и Vega-Lite**: Если возможностей Lens недостаточно, используйте Vega для создания полностью кастомных визуализаций на базе JSON-спецификаций.
* **Maps Layers**: Добавляйте слои на карту напрямую через ES|QL запросы для анализа гео-активности с предварительной фильтрацией на стороне Elasticsearch.
