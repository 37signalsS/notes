# Kibana: Поиск, визуализация и управление

> Эта заметка является частью обзора [ELK-стека](../elk_stack_overview.md) и детально рассматривает инструменты Kibana для исследования данных, их визуализации и управления.
>
> **Базовые определения** ([Data View](./kibana_overview.md#определения), [KQL](./kibana_overview.md#определения), [Saved Objects](./kibana_overview.md#определения), [Spaces](./kibana_overview.md#определения)) — в [общем обзоре Kibana](./kibana_overview.md).

## Определения

* **Lucene Query Syntax** — мощный и гибкий язык запросов, поддерживаемый в Kibana, который позволяет использовать регулярные выражения, поиск по диапазонам и нечеткий поиск.
* **Scripted Fields** — вычисляемые поля, создаваемые в Data View для динамического расчёта значений на лету без изменения исходных документов в Elasticsearch.
* **Lens** — интуитивно понятный визуальный конструктор в Kibana, позволяющий создавать визуализации путем перетаскивания полей (drag-and-drop).

## Основные концепции

### Модель представления данных

Kibana работает как слой представления поверх данных в Elasticsearch и не изменяет исходные документы. `Data View` является основой для работы. Поля в нем наследуют типы из маппинга и получают свойства `searchable` (доступно для поиска) и `aggregatable` (доступно для агрегаций), что является критически важным для построения визуализаций.

### Сравнение KQL и Lucene

| Характеристика | KQL (Kibana Query Language) | Lucene |
| :--- | :--- | :--- |
| **Синтаксис** | Простой и читаемый: `status: "error" and service.name: "auth"` | Более строгий: `status:"error" AND service.name:"auth"` |
| **Диапазоны** | `bytes > 1000` | `bytes:{1000 TO *]` |
| **RegEx** | Не поддерживается | Поддерживается через `/.../` |
| **Автодополнение** | Развитое, с контекстными подсказками | Ограниченное |
| **Рекомендация** | Основной выбор для большинства сценариев | Для сложных случаев (RegEx, нечеткий поиск) |

## Практические сценарии

### Анализ ошибок веб-сервера

Типичный рабочий процесс: от обнаружения проблемы до создания дашборда.

**Задача:** Найти все ошибки 5xx в логах Nginx, визуализировать их распределение по кодам ответа и создать дашборд для мониторинга.

1. **Исследование в Discover:**
    * Откройте приложение **Discover**.
    * В строке поиска введите KQL-запрос для фильтрации логов Nginx со статусом 5xx: `service.type: "nginx" and http.response.status_code >= 500`.
    * Используя временной фильтр, выберите интересующий диапазон (например, "Последние 24 часа").
    * Изучите найденные документы для понимания контекста ошибок.

2. **Создание визуализации в Lens:**
    * Нажмите **Create visualization** и выберите **Lens**.
    * Lens автоматически подхватит текущие фильтры из Discover.
    * В качестве типа диаграммы выберите **Donut (Кольцевая диаграмма)**.
    * В поле **Slice by** перетащите поле `http.response.status_code`.
    * Дайте визуализации понятное имя, например, "Распределение ошибок Nginx (5xx)", и сохраните ее.

3. **Сборка дашборда:**
    * Перейдите в **Dashboard** и создайте новую панель.
    * Нажмите **Add from library** и добавьте визуализацию "Распределение ошибок Nginx (5xx)".
    * Вернитесь в Discover, сохраните поисковый запрос (`service.type: "nginx" and http.response.status_code >= 500`) под именем "Логи ошибок Nginx (5xx)".
    * Вернитесь на дашборд и добавьте этот сохраненный поиск.
    * Сохраните дашборд под именем "Мониторинг ошибок Nginx".

## Дополнительная информация

### Управление объектами и доступом

* **Stack Management (Экспорт/Импорт)**: Все созданные сущности (Saved Objects) управляются через `Stack Management`. Их можно экспортировать в JSON для переноса между окружениями или резервного копирования.
* **Изоляция контента**: [Spaces](./kibana_overview.md#определения) позволяют разделять объекты между командами или проектами.
* **Управление доступом (RBAC)**: Безопасность настраивается через роли, ограничивающие доступ к приложениям Kibana (например, Dev Tools) и к данным на уровне индексов (Index Privileges).
* **Отчетность (Reporting)**: Возможность генерации PDF/PNG отчетов из дашбордов и их отправки по расписанию или через алерты.
