# Kibana: Поиск, визуализация и управление

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и детально рассматривает инструменты Kibana для исследования данных, их визуализации и управления сохраненными объектами.

## Определения

*   **Data View (ранее Index Pattern)**: Логическое представление одного или нескольких индексов Elasticsearch в Kibana. Определяет, какие поля доступны для анализа и какое из них является полем времени (`@timestamp`).
*   **KQL (Kibana Query Language)**: Простой и интуитивно понятный язык запросов с автодополнением, используемый в строке поиска Kibana по умолчанию.
*   **Lucene Query Syntax**: Более мощный и сложный язык запросов, который также поддерживается в Kibana и позволяет использовать регулярные выражения, поиск по диапазонам и другие низкоуровневые возможности.
*   **Saved Objects**: Любые сущности, созданные в Kibana (дашборды, визуализации, Data Views, отчеты), которые можно экспортировать, импортировать и версионировать.
*   **Spaces**: Изолированные рабочие области в Kibana, позволяющие разделить проекты, команды и контент.

## Основные концепции

### Модель представления данных

Kibana работает как слой представления поверх данных в Elasticsearch. Она не изменяет исходные документы.
*   **Data View** является основой для работы. При его создании поля наследуют типы из маппинга и получают свойства:
    *   `searchable`: можно ли искать по полю.
    *   `aggregatable`: можно ли использовать поле для агрегаций (ключевое свойство для визуализаций).
    *   `runtime`: поле, вычисляемое "на лету" при выполнении запроса.

### Discover: исследование данных

Интерфейс `Discover` — основной инструмент для интерактивного анализа "сырых" логов.
*   **Ключевые элементы**:
    *   **Timepicker**: Выбор временного диапазона.
    *   **Строка запроса**: Ввод запросов на KQL или Lucene.
    *   **Панель фильтров**: Добавление и управление фильтрами по полям.
*   **Сравнение KQL и Lucene**:
| Характеристика | KQL (Kibana Query Language) | Lucene |
| :--- | :--- | :--- |
| **Синтаксис** | Простой и читаемый: `status: "error" and service.name: "auth"` | Более строгий: `status:"error" AND service.name:"auth"` |
| **Операторы** | `and`, `or`, `not` | `AND`, `OR`, `NOT`, префикс `-` |
| **Диапазоны** | `bytes > 1000`, `bytes <= 5000` | `bytes:{1000 TO *]`, `bytes:[* TO 5000]` |
| **RegEx** | Нет | Да, с использованием `/.../` |
| **Автодополнение** | Развитое, с подсказками по полям и значениям | Ограниченное |
| **Рекомендация** | Основной выбор для большинства пользователей | Для сложных случаев, требующих RegEx или специфичных операторов |

## Практические сценарии

### Примеры запросов

*   **KQL**:
    ```
    # Ошибки в сервисе checkout
    status: "error" and service.name: "checkout"

    # Сообщения с таймаутом, исключая определенных пользователей
    message: "*timeout*" and not user.email: *@example.com

    # События за последние 15 минут с двух хостов
    @timestamp >= "now-15m" and host.name: ("api-1" or "api-2")
    ```

*   **Lucene**:
    ```
    # Эквивалент на Lucene
    status:"error" AND service.name:"checkout"
    message:*timeout* AND NOT user.email:*@example.com
    @timestamp:[now-15m TO now] AND host.name:(api-1 OR api-2)
    ```

### Визуализация логов

Kibana предлагает несколько инструментов для создания визуализаций:

*   **Lens**: Современный и простой конструктор "drag-and-drop". Автоматически подбирает тип графика и позволяет быстро строить визуализации (например, "Топ-5 сервисов по числу ошибок").
*   **TSVB (Time Series Visual Builder)**: Мощный инструмент для анализа временных рядов. Позволяет строить производные, скользящие средние и выполнять сложные pipeline-агрегации.
*   **Vega**: Для полностью кастомных визуализаций с помощью декларативного языка (на основе JSON). Используется, когда стандартных средств недостаточно.

#### Пример Vega для подсчета событий по уровню

```json
{
  "$schema": "https://vega.github.io/schema/vega-lite/v5.json",
  "data": { "name": "es" },
  "transform": [{
    "aggregate": [{"op": "count", "as": "count"}],
    "groupby": ["log.level"]
  }],
  "mark": "bar",
  "encoding": {
    "x": { "field": "log.level", "type": "nominal", "title": "Уровень" },
    "y": { "field": "count", "type": "quantitative", "title": "Количество событий" }
  }
}
```

### Дашборды и интерактивность

*   **Дашборды** объединяют визуализации, карты и сохраненные поиски в единое представление.
*   **Фильтры и Timepicker** на дашборде применяются ко всем его панелям.
*   **Drilldowns**: Позволяют настроить действия при клике на элемент визуализации, например, переход на другой дашборд с передачей текущих фильтров.

## Дополнительная информация

### Управление объектами и доступом

*   **Saved Objects**: Все созданные в Kibana сущности хранятся как "сохраненные объекты". Ими можно управлять через `Stack Management`: экспортировать для переноса между окружениями (dev/prod), импортировать, просматривать зависимости.
*   **Spaces**: Позволяют создавать изолированные рабочие области для разных команд. У каждой области свой набор `Saved Objects`.
*   **Роли и доступ**: Безопасность настраивается через роли, которые могут ограничивать доступ как к функциональности Kibana (например, запретить доступ к Dev Tools), так и к данным (на уровне индексов или документов).
*   **Отчеты (Reporting)**: Kibana позволяет генерировать PDF/PNG отчеты из дашбордов, которые можно отправлять по расписанию.
