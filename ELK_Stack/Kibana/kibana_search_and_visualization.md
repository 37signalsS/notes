# Kibana: Поиск, визуализация и управление

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и детально рассматривает инструменты Kibana для исследования данных, их визуализации и управления.
>
> **Базовые определения** ([Data View](./kibana_overview.md#определения), [KQL](./kibana_overview.md#определения), [Saved Objects](./kibana_overview.md#определения), [Spaces](./kibana_overview.md#определения)) — в [общем обзоре Kibana](./kibana_overview.md).

## Определения

* **Lucene Query Syntax** — мощный и гибкий язык запросов, поддерживаемый в Kibana, который позволяет использовать регулярные выражения, поиск по диапазонам и нечеткий поиск.
* **Runtime Fields** — современная замена Scripted Fields. Это поля, вычисляемые во время выполнения запроса с помощью скриптов Painless. Они не требуют переиндексации данных и могут быть определены как в маппинге индекса, так и внутри Data View.
* **Lens** — основной визуальный конструктор в Kibana. Позволяет создавать визуализации методом drag-and-drop, автоматически предлагая подходящие типы диаграмм на основе выбранных данных.

## Основные концепции

### Модель представления данных

Kibana работает как слой представления поверх данных в Elasticsearch и не изменяет исходные документы (за исключением использования Runtime Fields на уровне индекса). `Data View` является абстракцией, которая позволяет Kibana понимать структуру одного или нескольких индексов. Поля в нем наследуют типы из маппинга и получают свойства `searchable` (доступно для поиска) и `aggregatable` (доступно для агрегаций/визуализаций).

### Сравнение KQL и Lucene

| Характеристика | KQL (Kibana Query Language) | Lucene |
| :--- | :--- | :--- |
| **Синтаксис** | Простой: `status: "error" and service.name: "auth"` | Строгий: `status:"error" AND service.name:"auth"` |
| **Диапазоны** | `bytes > 1000` | `bytes:{1000 TO *]` |
| **RegEx** | Не поддерживается | Поддерживается через `/.../` |
| **Автодополнение** | Нативное, с подсказками по полям и значениям | Ограниченное |
| **Рекомендация** | Стандарт для Discover и простых фильтров | Для сложных случаев (RegEx, нечеткий поиск) |

## Практические сценарии

### Анализ ошибок веб-сервера

Типичный рабочий процесс: от обнаружения проблемы до создания дашборда.

**Задача:** Найти все ошибки 5xx в логах Nginx, визуализировать их распределение по кодам ответа и создать дашборд.

1. **Исследование в Discover:**
    * Откройте **Discover**.
    * Введите KQL-запрос: `service.type: "nginx" and http.response.status_code >= 500`.
    * Выберите временной диапазон (например, "Last 24 hours").
    * Добавьте нужные поля в таблицу (например, `message`, `client.ip`) для быстрого анализа.

2. **Создание визуализации в Lens:**
    * Нажмите **Visualize** прямо из Discover или перейдите в **Lens**.
    * Выберите тип диаграммы **Donut** или **Treemap**.
    * Перетащите поле `http.response.status_code` в область **Slice by**.
    * Настройте агрегацию (по умолчанию `Count`).
    * Сохраните визуализацию в библиотеку.

3. **Сборка дашборда:**
    * Перейдите в **Dashboard** → **Create new dashboard**.
    * Добавьте созданную визуализацию.
    * Добавьте "Saved Search" из Discover, чтобы видеть список последних ошибок под графиком.
    * Настройте фильтры и сохраните дашборд.

## Дополнительная информация

### Управление объектами

* **NDJSON формат**: Saved Objects (дашборды, Data Views) экспортируются и импортируются в формате `.ndjson`. Это позволяет версионировать конфигурации Kibana в Git.
* **Изоляция**: [Spaces](./kibana_overview.md#определения) обеспечивают логическую изоляцию объектов. Роли пользователей могут быть ограничены конкретными пространствами.

### Безопасность и доступ (RBAC)

* **Kibana Privileges**: Настраиваются в ролях (Stack Management → Roles). Позволяют давать доступ "только на чтение" (Read) или "полный доступ" (All) к конкретным приложениям (например, доступ к Maps, но запрет на Dev Tools).
* **Index Privileges**: Определяют, к каким данным в Elasticsearch имеет доступ пользователь Kibana.
* **API Keys**: В Kibana можно создавать ключи API для автоматизации (например, для программного создания алертов или экспорта отчетов).

### Отчетность и алертинг

* **Reporting**: Генерация PDF/PNG отчетов из дашбордов. Требует наличия соответствующих шрифтов в ОС, где запущена Kibana.
* **Alerting**: Интеграция с системой уведомлений Elasticsearch. Позволяет создавать правила на основе данных (например, всплеск 5xx ошибок) с отправкой уведомлений в Slack, Email или Webhook.
