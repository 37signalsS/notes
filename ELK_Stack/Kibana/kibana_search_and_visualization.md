# Kibana: Поиск, визуализация и управление

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и детально рассматривает инструменты Kibana для исследования данных, их визуализации и управления.
>
> **Базовые определения** ([Data View](./kibana_overview.md#определения), [KQL](./kibana_overview.md#определения), [Saved Objects](./kibana_overview.md#определения), [Spaces](./kibana_overview.md#определения)) — в [общем обзоре Kibana](./kibana_overview.md).

## Определения

* **Lucene Query Syntax**: Более мощный и сложный язык запросов, который также поддерживается в Kibana и позволяет использовать регулярные выражения и поиск по диапазонам.
* **Scripted Fields**: Вычисляемые поля, создаваемые в Data View для динамического расчёта значений на лету без изменения исходных документов.

## Основные концепции

### Модель представления данных

Kibana работает как слой представления поверх данных в Elasticsearch и не изменяет исходные документы. `Data View` является основой для работы. Поля в нем наследуют типы из маппинга и получают свойства `searchable` и `aggregatable` (ключ к построению визуализаций).

### Сравнение KQL и Lucene

| Характеристика | KQL (Kibana Query Language) | Lucene |
| :--- | :--- | :--- |
| **Синтаксис** | Простой и читаемый: `status: "error" and service.name: "auth"` | Более строгий: `status:"error" AND service.name:"auth"` |
| **Диапазоны** | `bytes > 1000` | `bytes:{1000 TO *]` |
| **RegEx** | Нет | Да, с использованием `/.../` |
| **Автодополнение** | Развитое, с подсказками | Ограниченное |
| **Рекомендация** | Основной выбор для большинства пользователей | Для сложных случаев |

## Практический сценарий: Анализ ошибок веб-сервера

Продемонстрируем типичный рабочий процесс: от обнаружения проблемы до создания дашборда.

**Задача:** Найти все ошибки 5xx в логах Nginx, визуализировать их распределение по кодам ответа и создать дашборд для мониторинга.

1. **Исследование в Discover:**
    * Откройте приложение **Discover**.
    * В строке поиска введите KQL-запрос для фильтрации логов Nginx со статусом 5xx: `service.type: "nginx" and http.response.status_code >= 500`.
    * Используя временной фильтр, выберите интересующий диапазон (например, "Последние 24 часа").
    * Изучите найденные документы, чтобы понять контекст ошибок.

2. **Создание визуализации в Lens:**
    * Нажмите **Create visualization** и выберите **Lens**.
    * Lens автоматически подхватит текущие фильтры из Discover.
    * В качестве типа диаграммы выберите **Donut (Кольцевая диаграмма)**.
    * В поле **Slice by** перетащите поле `http.response.status_code`.
    * Вы мгновенно увидите распределение кодов ошибок (500, 502, 503 и т.д.).
    * Дайте визуализации понятное имя, например, "Распределение ошибок Nginx (5xx)", и сохраните ее.

3. **Сборка дашборда:**
    * Перейдите в **Dashboard** и создайте новую панель.
    * Нажмите **Add from library** и добавьте только что созданную визуализацию "Распределение ошибок Nginx (5xx)".
    * Вернитесь в Discover, сохраните ваш поисковый запрос (`service.type: "nginx" and http.response.status_code >= 500`) под именем "Логи ошибок Nginx (5xx)".
    * Вернитесь на дашборд и добавьте этот сохраненный поиск.
    * Теперь у вас есть панель, где слева показаны сырые логи с ошибками, а справа — их процентное распределение. Сохраните дашборд под именем "Мониторинг ошибок Nginx".

## Дополнительная информация

### Управление объектами и доступом

* **Экспорт/импорт**: Все созданные сущности управляются через `Stack Management` — экспортируются для переноса между окружениями (dev/prod) и импортируются.
* **Изоляция по командам**: [Spaces](./kibana_overview.md#определения) позволяют создавать отдельные рабочие области с собственным набором объектов.
* **Роли и доступ**: Безопасность настраивается через роли, ограничивающие доступ к функциональности Kibana (например, Dev Tools) и к данным на уровне индексов или документов.
* **Отчеты (Reporting)**: Генерация PDF/PNG отчетов из дашбордов с отправкой по расписанию.
