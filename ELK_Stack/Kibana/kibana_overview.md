# Kibana: Обзор

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения Kibana.

## Определения

*   **Kibana** — это компонент визуализации в стеке ELK. Это мощный веб-интерфейс, который позволяет в реальном времени искать, анализировать и визуализировать данные, хранящиеся в [Elasticsearch](../Elasticsearch/elasticsearch_overview.md).
*   **Data View (ранее Index Pattern)**: Логическое представление одного или нескольких индексов Elasticsearch. Определяет, какие поля доступны для анализа. Создание Data View — первый шаг для работы с данными в Kibana.
*   **KQL (Kibana Query Language)**: Простой и интуитивно понятный язык для фильтрации данных прямо в строке поиска Kibana.

## Основные концепции

Kibana предоставляет набор инструментов для работы с данными:

*   **Discover**: Основной инструмент для интерактивного поиска и просмотра необработанных данных (логов) в реальном времени.
*   **Visualize Library**: Позволяет создавать разнообразные графики, диаграммы, таблицы и карты для представления данных.
*   **Dashboard**: Интерактивные панели, объединяющие несколько визуализаций для создания комплексного представления о состоянии системы.
*   **Dev Tools (Консоль разработчика)**: Встроенная консоль для отправки REST-запросов напрямую в Elasticsearch. Мощный инструмент для отладки и администрирования.

## Практические сценарии

### Пример запроса на KQL

KQL позволяет легко фильтровать данные в интерфейсе `Discover`.

*   **Фильтрация по значению поля:** `response: "200"`
*   **Использование операторов `and`, `or`, `not`:** `method: "POST" and response: >=400`
*   **Проверка существования поля:** `user.name: *`

> Для более глубокого изучения поиска, KQL и средств визуализации, обратитесь к заметке **[Kibana: Поиск, визуализация и управление](./kibana_search_and_visualization.md)**.

### Конфигурация и безопасность

Ключевые настройки производятся в файле `kibana.yml`:
*   **Подключение к Elasticsearch**: Можно указать несколько эндпоинтов Elasticsearch для отказоустойчивости.
*   **Безопасность**: Если кластер Elasticsearch защищен, соответствующие учетные данные необходимо указать в `kibana.yml`. Для production рекомендуется отключать консоль разработчика (`console.enabled: false`), чтобы ограничить доступ к сырым запросам.

## Дополнительная информация

### Kibana vs. Grafana

*   **Kibana**: Тесно интегрирована с Elasticsearch, предоставляет мощные возможности именно для **поиска и анализа текстовых данных и логов**.
*   **[Grafana](../../Grafana/grafana_overview.md)**: Более универсальный инструмент, который отлично работает с **временными рядами (time-series)** из различных источников данных.

Выбор между ними часто зависит от основного сценария использования: глубокий анализ логов (Kibana) или мониторинг метрик (Grafana).
