# Kibana: Обзор

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения Kibana. Данные актуальны для версий **8.19 (LTS)** и **9.x**.

## Определения

* **Kibana** — это центральный интерфейс управления и визуализации в Elastic Stack. Она служит "окном" в данные, хранящиеся в [Elasticsearch](../Elasticsearch/elasticsearch_overview.md), предоставляя инструменты для анализа логов, мониторинга инфраструктуры и обеспечения безопасности.
* **Data View (ранее Index Pattern)** — логическая абстракция над индексами Elasticsearch. Она определяет, какие поля доступны для поиска и визуализации, их типы и форматы.
* **KQL (Kibana Query Language)** — основной язык запросов для фильтрации данных в Discover и на дашбордах. Отличается простым синтаксисом и мощным автодополнением.
* **Saved Objects** — сущности, создаваемые в Kibana (дашборды, визуализации, Data Views, алерты). Хранятся в специальном системном индексе Elasticsearch и могут экспортироваться в формате NDJSON.
* **Spaces (Пространства)** — механизм логической изоляции объектов. Позволяет разделять дашборды и настройки между командами или проектами внутри одного инстанса Kibana.
* **Elastic AI Assistant** — интегрированный ИИ-помощник (на базе Gemini, GPT и др.), помогающий генерировать запросы ES|QL, создавать визуализации и анализировать инциденты безопасности.
* **ES|QL (Elasticsearch Query Language)** — новый потоковый язык запросов, позволяющий выполнять поиск, фильтрацию, агрегацию и трансформацию данных в одном запросе с высокой производительностью.

## Основные концепции

### Аналитика и визуализация
* **Discover** — инструмент для исследования необработанных данных. В версиях 9.x поддерживает **Document Explorer** для быстрой навигации по миллионам записей.
* **Dashboard** — интерактивные панели. В современных версиях элементы управления (фильтры) стали мобильными, их можно размещать в любом месте дашборда.
* **Lens** — основной визуальный конструктор с поддержкой drag-and-drop. Автоматически выбирает оптимальный тип графика на основе перетащенных полей.
* **Maps** — многослойные карты для анализа геоданных в реальном времени.

### Решения и ИИ
* **Observability** — унифицированный мониторинг логов, метрик и трассировок (APM). Активно использует **OpenTelemetry (OTel)** как стандарт доставки данных.
* **Security** — полноценная SIEM-система и инструменты защиты конечных точек (Endpoint Security).
* **AI & Machine Learning** — автоматическое обнаружение аномалий, прогнозирование и семантический поиск (векторный поиск).

### Управление и безопасность
* **Fleet и Elastic Agent** — централизованное управление сбором данных. Kibana выступает в роли панели управления (Control Plane) для тысяч агентов.
* **RBAC (Role-Based Access Control)** — гибкая настройка прав доступа. Можно ограничить пользователя конкретным Space или дать доступ "только на чтение" к определенным индексам.
* **Dev Tools (Console)** — интерактивная консоль для работы с Elasticsearch API и отладки ES|QL запросов.

## Практические сценарии

### Создание Data View

1. Перейдите в **Stack Management** → **Data Views**.
2. Нажмите **Create data view**.
3. Укажите шаблон (например, `logs-*` или `metrics-nginx-*`).
4. Выберите поле времени (обычно `@timestamp`) для построения временных рядов.

### Организация работы через Spaces

Для изоляции данных команд (например, Dev и Ops):
1. Перейдите в **Stack Management** → **Spaces**.
2. Создайте пространство `Development`.
3. Настройте **Role**, разрешив доступ только к этому пространству.
4. Теперь объекты (дашборды, запросы), созданные в `Development`, не будут видны в пространстве `Default`.

### Конфигурация сервера (kibana.yml)

В версии 9.x по умолчанию используется протокол HTTP/2 при включенном TLS.

```yaml
# kibana.yml

# Сетевые настройки
server.host: "0.0.0.0"
server.port: 5601
server.name: "kibana-production"
# Публичный URL для формирования ссылок в алертах
server.publicBaseUrl: "https://kibana.example.com"

# Подключение к Elasticsearch
elasticsearch.hosts: ["https://es-cluster:9200"]

# Безопасность (использование Service Token)
elasticsearch.serviceAccountToken: "AAEAAWVsYXN0aWMva2liYW5hL2Vucm9sbC10b2tlbi0..."

# SSL/TLS конфигурация
elasticsearch.ssl.certificateAuthorities: [ "/etc/kibana/certs/ca.crt" ]

# Настройки для 9.x (если прокси не поддерживает HTTP/2)
# server.protocol: http1

# Локализация интерфейса
i18n.locale: "ru-RU"
```

## Дополнительная информация

### Сравнение Kibana и Grafana

| Функция | Kibana | [Grafana](../../Grafana/grafana_overview.md) |
| :--- | :--- | :--- |
| **Сильные стороны** | Глубокий анализ логов, SIEM, APM, AI | Визуализация метрик из разных источников |
| **Источники данных** | Elasticsearch / OpenSearch | 100+ (Prometheus, Zabbix, SQL и др.) |
| **Языки запросов** | KQL, Lucene, ES|QL | PromQL, LogQL, SQL |
| **Интеграция** | Бесшовная с Elastic Stack | Универсальная, OTel-нативная |
