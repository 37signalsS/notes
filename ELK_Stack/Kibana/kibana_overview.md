# Kibana: Обзор

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения Kibana. Данные актуальны для версий **8.19 (LTS)** (поддержка до июля 2027) и **9.x** (текущая稳定ная 9.5.x).

## Определения

* **Kibana** — это центральный интерфейс управления и визуализации в Elastic Stack. Она служит "окном" в данные, хранящиеся в [Elasticsearch](../Elasticsearch/elasticsearch_overview.md), предоставляя инструменты для анализа логов, мониторинга инфраструктуры и обеспечения безопасности. В версии 9.x Kibana стала платформой для автоматизации рабочих процессов (Workflows) и управления AI-агентами (Agent Builder).
* **Data View (ранее Index Pattern)** — логическая абстракция над индексами Elasticsearch. Она определяет, какие поля доступны для поиска и визуализации, их типы и форматы. В 9.x рекомендуется использовать Data View вместо прямого обращения к индексам для обеспечения согласованности именования и поддержки полей.
* **KQL (Kibana Query Language)** — основной язык запросов для фильтрации данных в Discover и на дашбордах. Отличается простым синтаксисом и мощным автодополнением. Оптимален для быстрой фильтрации; для сложных аналитических задач используйте ES|QL.
* **Saved Objects** — сущности, создаваемые в Kibana (дашборды, визуализации, Data Views, алерты). Хранятся в специальном системном индексе Elasticsearch и могут экспортироваться в формате NDJSON для версионирования и GitOps.
* **Spaces (Пространства)** — механизм логической изоляции объектов. Позволяет разделять дашборды и настройки между командами или проектами внутри одного инстанса Kibana. Рекомендуется для мультитенантности и сегментации доступа.
* **Elastic AI Assistant** — интегрированный ИИ-помощник (на базе Gemini, GPT и др.), помогающий генерировать запросы ES|QL, создавать визуализации и анализировать инциденты безопасности. В 9.x поддерживает контекстуальные подсказки на основе текущего состояния дашборда.
* **ES|QL (Elasticsearch Query Language)** — новый потоковый язык запросов, позволяющий выполнять поиск, фильтрацию, агрегацию и трансформацию данных в одном запросе с высокой производительностью. В 9.x стал основным рекомендуемым языком для аналитики.
* **Workflows** — система автоматизации рутинных задач в Kibana (версия 9.x). Позволяет создавать цепочки действий для обработки инцидентов, управления алертами и интеграции с внешними системами.
* **Agent Builder** — инструмент для создания и управления AI-агентами в Kibana (версия 9.x). Агенты могут автоматически выполнять задачи по анализу данных, реагированию на инциденты и генерации отчетов.

## Основные концепции

### Аналитика и визуализация
* **Discover** — инструмент для исследования необработанных данных. В версиях 9.x поддерживает **Document Explorer** для быстрой навигации по миллионам записей. Поддерживает ES|QL запросы для аналитики без создания дашбордов.
* **Dashboard** — интерактивные панели. В современных версиях элементы управления (фильтры) стали мобильными, их можно размещать в любом месте дашборда. В 9.x появилась возможность отложенной загрузки панелей для ускорения открытия дашбордов.
* **Lens** — основной визуальный конструктор с поддержкой drag-and-drop. Автоматически выбирает оптимальный тип графика на основе перетащенных полей. Поддерживает ES|QL как источник данных.
* **Maps** — многослойные карты для анализа геоданных в реальном времени. Поддерживает добавление слоев через ES|QL запросы.
* **Vega и Vega-Lite** — создание полностью кастомных визуализаций на базе JSON-спецификаций для задач, которые невозможно решить стандартными инструментами.

### Решения и ИИ
* **Observability** — унифицированный мониторинг логов, метрик и трассировок (APM). Активно использует **OpenTelemetry (OTel)** как стандарт доставки данных. В 9.x增强了 интеграция с Prometheus через нативную поддержку PromQL.
* **Security** — полноценная SIEM-система и инструменты защиты конечных точек (Endpoint Security). В 9.x появилась автоматизация реагирования на инциденты через Workflows.
* **AI & Machine Learning** — автоматическое обнаружение аномалий, прогнозирование и семантический поиск (векторный поиск). В 9.x增强了 векторный поиск для RAG-сценариев.

### Управление и безопасность
* **Fleet и Elastic Agent** — централизованное управление сбором данных. Kibana выступает в роли панели управления (Control Plane) для тысяч агентов. В 9.x появился **Agent Builder** для создания пользовательских AI-агентов.
* **RBAC (Role-Based Access Control)** — гибкая настройка прав доступа. Можно ограничить пользователя конкретным Space или дать доступ "только на чтение" к определенным индексам. Рекомендуется最小权限 principle.
* **Dev Tools (Console)** — интерактивная консоль для работы с Elasticsearch API и отладки ES|QL запросов. В 9.x增强了 подсказки и документация по API.
* **Workflows** — система автоматизации рутинных задач (9.x). Позволяет создавать цепочки действий для обработки инцидентов, управления алертами и интеграции с внешними системами.

### Требования к ресурсам и производительности

**Минимальные требования (для разработки/тестирования):**
* RAM: 2 ГБ
* CPU: 2 ядра
* Диск: 10 ГБ SSD

**Рекомендуемые требования для продакшена:**
* RAM: 4-8 ГБ (в 9.x рекомендуется минимум 2 ГБ для стабильной работы с Platinum/Enterprise функциями)
* CPU: 4+ ядер
* Диск: 50+ ГБ SSD (с учётом индексов и логов)
* Сеть: стабильное соединение с Elasticsearch (задержка < 10 мс)

**Оптимизация производительности:**
* Используйте **node.roles** для выделения узлов Kibana (в кластерной конфигурации).
* Настройте **xpack.security.session.idleTimeout** для автоматического завершения сессий.
* Используйте кэширование Data View для ускорения загрузки дашбордов.

## Практические сценарии

### Создание Data View

1. Перейдите в **Stack Management** → **Data Views**.
2. Нажмите **Create data view**.
3. Укажите шаблон (например, `logs-*` или `metrics-nginx-*`).
4. Выберите поле времени (обычно `@timestamp`) для построения временных рядов.
5. **Важно:** Для production используйте конкретные шаблоны (например, `logs-app-2026.08.*`) вместо общих `logs-*` для оптимизации производительности.

### Организация работы через Spaces

Для изоляции данных команд (например, Dev и Ops):
1. Перейдите в **Stack Management** → **Spaces**.
2. Создайте пространство `Development`.
3. Настройте **Role**, разрешив доступ только к этому пространству.
4. Теперь объекты (дашборды, запросы), созданные в `Development`, не будут видны в пространстве `Default`.
5. **Best Practice:** Создайте отдельные Space для каждого проекта или сервиса, чтобы избежать пересечения данных.

### Конфигурация сервера (kibana.yml)

В версии 9.x по умолчанию используется протокол HTTP/2 при включенном TLS.

```yaml
# kibana.yml

# Сетевые настройки
server.host: "0.0.0.0"
server.port: 5601
server.name: "kibana-production"
# Публичный URL для формирования ссылок в алертах
server.publicBaseUrl: "https://kibana.example.com"

# Подключение к Elasticsearch
elasticsearch.hosts: ["https://es-cluster:9200"]

# Безопасность (использование Service Token)
elasticsearch.serviceAccountToken: "AAEAAWVsYXN0aWMva2liYW5hL2Vucm9sbC10b2tlbi0..."

# SSL/TLS конфигурация
elasticsearch.ssl.certificateAuthorities: [ "/etc/kibana/certs/ca.crt" ]

# Настройки для 9.x (если прокси не поддерживает HTTP/2)
# server.protocol: http1

# Локализация интерфейса
i18n.locale: "ru-RU"

# Настройки безопасности и производительности
xpack.security.session.idleTimeout: "30m"
xpack.security.session.lifespan: "24h"
xpack.encryptedSavedObjects.encryptionKey: "минимум 32 символа"
logging.root.level: "info"
```

### Настройка безопасности

**SSL/TLS для Elasticsearch:**
1. Сгенерируйте сертификаты с помощью `elasticsearch-certutil`.
2. Настройте Kibana на использование HTTPS для подключения к Elasticsearch.
3. Убедитесь, что CA-сертификат доступен Kibana (монтирование в контейнер или указание пути в конфиге).

**RBAC (Role-Based Access Control):**
1. Создайте роли в **Stack Management** → **Roles**.
2. Определите privileges для индексов (например, `read` для `logs-*`).
3. Привяжите роли к пользователям или группам.
4. Для мультитенантности используйте **Space-aware roles** с ограничением по пространствам.

**Audit Logs:**
1. Включите аудит в `kibana.yml`:
   ```yaml
   xpack.security.audit.enabled: true
   xpack.security.audit.logfile.events.include:
     - "login_attempt"
     - "saved_objects_delete"
     - "space_delete"
   ```
2. Настройте отправку аудит-логов в Elasticsearch для централизованного мониторинга.

### Мониторинг Kibana

Kibana предоставляет встроенные метрики для мониторинга:
* **Health Check:** `GET /api/status` — проверка состояния Kibana.
* **Metrics API:** `GET /api/stats` — метрики производительности (CPU, память, запросы).
* **Stats API:** `GET /api/stats?extended=true` — расширенные метрики (включая информацию о соединениях с Elasticsearch).

**Рекомендации по мониторингу:**
* Настройте алертинг на основе метрик Kibana через Elasticsearch.
* Мониторьте использование памяти и времени отклика API.
* Отслеживайте количество активных соединений с Elasticsearch.

## Дополнительная информация

### Сравнение Kibana и Grafana

| Функция | Kibana | [Grafana](../../Grafana/grafana_overview.md) |
| :--- | :--- | :--- |
| **Сильные стороны** | Глубокий анализ логов, SIEM, APM, AI, автоматизация (Workflows) | Визуализация метрик из разных источников |
| **Источники данных** | Elasticsearch / OpenSearch | 100+ (Prometheus, Zabbix, SQL и др.) |
| **Языки запросов** | KQL, Lucene, ES|QL | PromQL, LogQL, SQL |
| **Интеграция** | Бесшовная с Elastic Stack | Универсальная, OTel-нативная |
| **AI/ML возможности** | Встроенные (AI Assistant, ML аномалии) | Ограниченные (через плагины) |
| **Автоматизация** | Workflows (9.x), Alerting | Alerting, OnCall |

### Troubleshooting

**Типичные проблемы и решения:**

1. **Kibana не подключается к Elasticsearch:**
   * Проверьте доступность Elasticsearch: `curl -k https://es-cluster:9200/_cluster/health`.
   * Убедитесь, что Service Token или учётные данные корректны.
   * Проверьте сертификаты SSL/TLS (пути, сроки действия).

2. **Дашборды загружаются медленно:**
   * Оптимизируйте Data View: используйте конкретные шаблоны индексов вместо общих.
   * Уменьшите количество панелей на дашборде (рекомендуется < 20).
   * Включите кэширование Data View.

3. **Ошибки при экспорте/импорте Saved Objects:**
   * Убедитесь, что версии Kibana совпадают (особенно при импорте из более новой версии).
   * Проверьте, все ли зависимости (Data Views, индексы) доступны в целевой системе.

4. **Проблемы с пространствами (Spaces):**
   * Убедитесь, что у пользователя есть роль с доступом к нужному пространству.
   * Проверьте, что объекты не привязаны к другому пространству.

### Best Practices

**Для производственных сред:**
* Используйте **отдельные узлы Kibana** (не совмещайте с Elasticsearch).
* Настройте **балансировку нагрузки** для Kibana в кластерной конфигурации.
* Регулярно **экспортируйте Saved Objects** в NDJSON для резервного копирования.
* Используйте **Service Accounts** вместо паролей для автоматизации.

**Для безопасности:**
* Включите **RBAC** и настройте最小权限 principle.
* Используйте **SSL/TLS** для всех соединений (Kibana ↔ Elasticsearch, браузер ↔ Kibana).
* Включите **аудит-логи** для отслеживания действий пользователей.
* Регулярно обновляйте Kibana до последних патчей (особенно для версий 8.19.x и 9.x).

**Для производительности:**
* Ограничивайте время жизни сессий (`xpack.security.session.idleTimeout`).
* Используйте **ES|QL** вместо KQL для сложных аналитических запросов.
* Мониторьте метрики Kibana и настраивайте алертинг на аномалии.

**Для мультитенантности:**
* Используйте **Spaces** для изоляции данных между командами/проектами.
* Настройте **Role-Based Access Control** с ограничением по индексам и пространствам.
* Используйте **Document-Level Security (DLS)** для дополнительной изоляции данных.
