# Kibana: Обзор

> Эта заметка является частью обзора [ELK стека](../elk_stack_overview.md) и служит основной точкой входа для изучения Kibana.

## Определения

* **Kibana** — это компонент визуализации в стеке ELK. Это мощный веб-интерфейс, который позволяет в реальном времени искать, анализировать и визуализировать данные, хранящиеся в [Elasticsearch](../Elasticsearch/elasticsearch_overview.md).
* **Data View (ранее Index Pattern)**: Логическое представление одного или нескольких индексов Elasticsearch. Определяет, какие поля доступны для анализа. Создание Data View — первый шаг для работы с данными в Kibana.
* **KQL (Kibana Query Language)**: Простой и интуитивно понятный язык для фильтрации данных прямо в строке поиска Kibana.

## Основные концепции

Kibana предоставляет набор инструментов («приложений») для работы с данными:

* **Discover**: Основной инструмент для интерактивного поиска и просмотра необработанных данных (логов).
* **Visualize**: Позволяет создавать разнообразные графики, диаграммы, таблицы и карты для представления данных.
* **Dashboard**: Интерактивные панели, объединяющие несколько визуализаций для создания комплексного представления о состоянии системы.
* **Dev Tools (Консоль разработчика)**: Встроенная консоль для отправки REST-запросов напрямую в Elasticsearch.
* **Spaces**: Рабочие области для организации контента. Позволяют разделить дашборды, визуализации и другие объекты по проектам или командам.
* **Saved Objects**: Любые сущности, созданные в Kibana (дашборды, Data Views, визуализации), которые можно экспортировать и импортировать для миграции между окружениями.

## Практические сценарии

### Создание Data View (Index Pattern)

1. Откройте веб-интерфейс Kibana.
2. В боковом меню выберите **Stack Management** → **Data Views** (или **Index Patterns** в старых версиях).
3. Нажмите **Create data view**.
4. Введите шаблон индексов (например, `my-cluster-*`).
5. Выберите поле времени (обычно `@timestamp`) в качестве **Time field**.
6. Нажмите **Save data view to Kibana**.

### Язык запросов KQL

KQL — основной способ фильтрации данных в Kibana с простым синтаксисом: `<field>: <value>`. Примеры использования в интерфейсе `Discover`:

* **Фильтрация по значению:** `response: "200"`
* **Операторы `and`, `or`, `not`:** `method: "POST" and response: >=400`
* **Сравнения:** `status: 200`, диапазоны `bytes: [1000 to 2000]`, `>`, `<`, `>=`, `<=`
* **Проверка существования поля:** `user.name: *`
* **Точный поиск (поиск фразы):** `message: "payment failed"`

> Для более глубокого изучения поиска, KQL и средств визуализации, обратитесь к заметке **[Kibana: Поиск, визуализация и управление](./kibana_search_and_visualization.md)**.

### Конфигурация и безопасность

Ключевые настройки производятся в файле `kibana.yml`.

```yaml
# kibana.yml

# Хост, на котором будет доступен веб-интерфейс Kibana
server.host: "0.0.0.0"

# Имя сервера для отображения в интерфейсе
server.name: "my-kibana"

# Адреса узлов Elasticsearch для подключения
elasticsearch.hosts: ["https://es01:9200", "https://es02:9200"]

# Учетные данные для подключения к защищенному кластеру Elasticsearch
elasticsearch.username: "kibana_system"
elasticsearch.password: "your_password"

# Путь к CA сертификату кластера Elasticsearch для проверки подлинности
elasticsearch.ssl.certificateAuthorities: [ "/etc/kibana/certs/ca.crt" ]

# Для production рекомендуется отключать консоль разработчика,
# чтобы ограничить доступ к сырым запросам через UI.
# console.enabled: false
```

## Дополнительная информация

### Сравнение Kibana и Grafana

* **Kibana**: Тесно интегрирована с Elasticsearch, предоставляет мощные возможности именно для **поиска и анализа текстовых данных и логов**.
* **[Grafana](../../Grafana/grafana_overview.md)**: Более универсальный инструмент, который отлично работает с **временными рядами (time-series)** из различных источников данных.

Выбор между ними часто зависит от основного сценария использования: глубокий анализ логов (Kibana) или мониторинг метрик (Grafana).
