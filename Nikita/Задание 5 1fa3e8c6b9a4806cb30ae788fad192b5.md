```
OFFSET_FILE="/tmp/nginx_log_offset"
OFFSET=$(cat "$OFFSET_FILE" 2>/dev/null || echo 0)
```

переменные OFFSET_FILE и OFFSET используются для **отслеживания, с какой строки лога access.log читать новые записи**, чтобы не обрабатывать одни и те же строки несколько раз.

---

Когда скрипт работает в цикле, он должен знать:

- **Где он закончил в прошлый раз.**
- **С каких строк лога начинать в следующий раз.**

---

### **Как это работает:**

1. **Первый запуск:**
    - Если файл OFFSET_FILE не существует, считается, что OFFSET = 0.
    - Скрипт берёт все строки из access.log.
2. **Обработка логов:**
    - Скрипт считает общее количество строк в логе:

```
TOTAL_LINES=$(wc -l < "$LOG_SRC")
```

- Затем вычитает OFFSET, чтобы узнать сколько новых строк появилось:

```
NEW_LINES=$((TOTAL_LINES - OFFSET))
```

1. **Сохраняет новое значение OFFSET:**

```
OFFSET=$TOTAL_LINES
echo "$OFFSET" > "$OFFSET_FILE"
```

## **Что делает эта строка**

```
awk '{print $9}'
```

### **Это означает:**

- Возьми **девятое поле** из строки (разделённой пробелами).
- В контексте лога NGINX это — **HTTP-статус код**.

### **Пример строки из access.log:**

```
127.0.0.1 - - [21/May/2025:12:00:00 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.68.0"
                                                  ↑ это и есть 9-е поле
```

- Здесь awk '{print $9}' вернёт 200.

---

awk — это язык для обработки текста **построчно и по полям**.

- Он по умолчанию разбивает строки по пробелам/табуляции.
- Позволяет обращаться к полям через $1, $2, … $NF (NF — последняя колонка).
- Очень удобен для извлечения и анализа структурированных логов.

---

## **А что такое sed**

sed — **stream editor**, редактор потока текста, который работает с текстом построчно и применяет **замены, удаление, вставку** и т.д. через регулярные выражения.

---

## **Различия между awk и sed**

| **Характеристика** | awk | sed |
| --- | --- | --- |
| Подходит для | Разбора по колонкам, анализ строк | Манипуляций со строками |
| Синтаксис | Язык программирования | Набор правил (команд) |
| Логика | Позиции (колонки) | Поиск/замена |
| Сложность | Чуть сложнее, но мощнее | Простой, но ограниченный |
| Использование в скриптах | Подсчёты, фильтрация, агрегация | Удаление строк, замены, вставки |

---

## **Если использовать sed**

Чтобы отфильтровать только строки со статусом 500:

```
sed -n '/ 500 /p' /var/log/nginx/access.log
```

- n — не печатай всё подряд.
- / 500 /p — найди строки, где есть 500 (с пробелами, чтобы избежать 5000 и т.п.), и напечатай их.

---

Разберём выражение по частям:

```bash
sed -n 's/.*" [ ]*\(4[0-9][0-9]\) .*/&/p' /tmp/nginx_new.log >> "$LOG_4XX"

```

Эта команда **сохраняет в файл только те строки из лога, в которых есть HTTP-статус 4xx**, например `404`, `403`и т.д.

---

## 1. **`sed -n`**

- `n` означает: **"ничего не печатай, кроме явно запрошенного через `p`"**.
- Без `n` `sed` бы по умолчанию печатал **все строки**, а `p` дублировал бы совпавшие.

---

## 2. **`s/.../.../p`** — команда `sed` замены

Формат:

```
s/шаблон/замена/p

```

- `s` — означает "substitute" (заменить).
- `/.../` — разделитель шаблона и замены.
- `p` — означает "print" только если **замена произошла**.

---

## 3. **Шаблон поиска:**

```bash
.*" [ ]*\(4[0-9][0-9]\) .*

```

Разберём по кусочкам:

| Выражение | Значение |
| --- | --- |
| `.*"` | всё до последней кавычки (обычно заканчивается запрос: `"GET /..."`) |
| `[ ]*` | 0 или более пробелов |
| `\(4[0-9][0-9]\)` | статус 4xx: 400–499. Скобки нужны, чтобы **захватить** часть — в `sed` это "группа" |
| `.*` | всё остальное в строке |

Пример совпадающей строки:

```
"GET /notfound.html HTTP/1.1" 404 158 "-" "curl/7.68.0"

```

---

## 4. **Замена: `&`**

- `&` означает: **"оставить всю строку как есть"**.
- То есть, даже если мы "заменяем", мы по сути **ничего не меняем**, а просто фильтруем.

---

## 5. **`p` после `s///`**

- Напечатай строку, **только если она соответствовала шаблону** и замена была выполнена.
- В сочетании с `n` это означает: **печатай только строки с кодами 4xx**.

---

### ✅ Итого:

```bash
sed -n 's/.*" [ ]*\(4[0-9][0-9]\) .*/&/p'

```

- Находит строки, где статус код — 4xx.
- Ничего не меняет (`&`), но выводит только такие строки.
- Удобно как фильтр, если хочешь чуть более гибкий контроль, чем с `grep`.

Команда:

```
cat /proc/loadavg
```

выводит информацию о **загрузке системы** (load average) и связанных с ней показателях.

Пример вывода:

```
0.00 0.00 0.00 1/188 16854
```

---

## **Расшифровка по позициям:**

| **Поле** | **Значение** |
| --- | --- |
| 0.00 | Load average за последние **1 минуту** |
| 0.00 | Load average за **5 минут** |
| 0.00 | Load average за **15 минут** |
| 1/188 | **1** процесс в очереди к CPU из **188** всего |
| 16854 | PID последнего завершившегося процесса |

---

## **Что такое Load Average?**

- Это **среднее количество процессов**, ожидающих выполнения (включая выполняющиеся).
- Если у тебя 1 CPU, то:
    - 1.00 = полностью загружен.
    - >1.00 = перегружен.
    - <1.00 = простаивает.

Пример:

- 2.00 при 4 CPU — нормальная загрузка.
- 2.00 при 1 CPU — перегрузка.

---

## **Пример разбора:**

```
0.00 0.00 0.00 1/188 16854
```

- Нагрузка низкая (0.00) — система **почти простаивает**.
- В очереди — 1 активный процесс из 188.
- Последний завершённый процесс имел PID 16854.

```
tail -n "$NEW_LINES" "$LOG_SRC" > /tmp/nginx_new.log
```

---

## **Пошаговое объяснение:**

- Читает **последние** $NEW_LINES строк из файла "$LOG_SRC" (например, это может быть лог-файл NGINX).
- $NEW_LINES — переменная, которая говорит сколько новых строк появилось с момента последнего чтения.
- tail -n — классический способ получить “хвост” лога.

---

### **> /tmp/nginx_new.log**

- Результат записывается в **временный файл** /tmp/nginx_new.log.
- Старая версия файла перезаписывается каждый раз.

---

## **Зачем нужен временный файл /tmp/nginx_new.log**

Этот файл используется как **буфер**:

- Он содержит **только новые строки**, появившиеся с момента последней обработки.
- Вместо того чтобы парсить весь лог каждый раз, скрипт работает **только с этим новым фрагментом**.
- Это **ускоряет обработку** и **снижает нагрузку**.

---

## **Контекст (в типичном скрипте):**

- Сначала скрипт запоминает, сколько байт было в логе (OFFSET).
- Потом смотрит, сколько новых байт добавилось (NEW_LINES).
- Использует tail -n для извлечения этих новых строк.
- Обрабатывает временный файл по частям:
    - Ищет коды 4xx, 5xx (awk/sed)
    - Считает ошибки
    - Удаляет лог при превышении размера
    - и т.д.

### **sed '/HTTP\/[0-9.]*" 5[0-9][0-9] /p'**

Это **шаблон и команда**:

- /.../p — шаблон поиска и команда p (print) — вывести строки, **соответствующие шаблону**.
- Разберём шаблон: HTTP\/[0-9.]*" 5[0-9][0-9]
    - HTTP\/ — соответствует строке HTTP/. Слэш экранируется \.
    - [0-9.]* — соответствует версии протокола, например 1.1 или 2.0. Символы — цифры и точки.
    - " — закрывающая кавычка после версии.
    - 5[0-9][0-9] — соответствует статус-коду HTTP **5XX**:
        - Пробел, затем 5, затем любые две цифры ([0-9][0-9]), затем пробел.
        - Например: 500, 502 и т. д.
