Начнем с того, что нередко сервера могут смотреть

А не из интернета.

Политики Firewall (Policies)
Помимо зон, которые определяют правила для трафика, входящего на сам хост (INPUT), firewalld предоставляет более новый и мощный механизм — **политики (policies)**. Они предназначены для управления **проходящим (FORWARD)** трафиком, то есть пакетами, которые маршрутизируются с одного интерфейса (зоны) на другой. Это основной инструмент для настройки Linux-машины в качестве сетевого файрвола.

Политика действует как мост между двумя зонами: входящей (ingress) и исходящей (egress).

Рассмотрим пример: нужно разрешить SSH-подключение с jump-хоста (10.0.2.101) в зоне `dmz` на сервер (10.0.5.101) в зоне `management`.

1.  **Создаем новую политику:**
    Название должно быть осмысленным, чтобы было понятно ее назначение.
    ```bash
    firewall-cmd --permanent --new-policy dmz-to-mgmt
    ```

2.  **Задаем входящую и исходящую зоны для политики:**
    Трафик будет поступать из зоны `dmz` и направляться в зону `management`.
    ```bash
    # Входящая зона (откуда идет трафик)
    firewall-cmd --permanent --policy dmz-to-mgmt --add-ingress-zone=dmz
    # Исходящая зона (куда идет трафик)
    firewall-cmd --permanent --policy dmz-to-mgmt --add-egress-zone=management
    ```

3.  **Добавляем разрешающее правило:**
    Поскольку стандартные опции политики не позволяют указать IP-адреса источника и назначения, для точечного разрешения необходимо использовать `rich-rule`.
    ```bash
    firewall-cmd --permanent --policy dmz-to-mgmt --add-rich-rule='rule family="ipv4" source address="10.0.2.101" destination address="10.0.5.101" service name="ssh" accept'
    ```
    Это правило разрешает TCP-трафик на порт 22 от конкретного хоста в `dmz` к конкретному хосту в `management`. Без указания source/destination адресов, мы бы разрешили SSH со *всех* хостов в `dmz` ко *всем* хостам в `management`.

4.  **Перезагружаем firewalld, чтобы применить изменения:**
    ```bash
    firewall-cmd --reload
    ```

Таким образом, политики предоставляют структурированный способ определять правила для транзитного трафика, что является более правильным подходом для настройки межсетевого экрана, чем использование `rich-rules` внутри зон для управления FORWARD-трафиком.

Еще одна примечательная опция – masquerade.
Мы с вами обсуждали NAT.
Когда вы выходите в интернет, ваш роутер подменяет ваши
домашние IP-адреса на свой внешний, чтобы другая
сторона знала куда посылать ответ.
Так вот, такой тип NAT называется source NAT, так как заменяет
source-адрес, то есть адрес отправителя.
Это также позволяет скрывать реальные IP-адреса отправителей,
поэтому такой NAT часто называют masquerade.
И так как Linux можно настроить как роутер, на нем можно врубить
source NAT с помощью Firewall'a.
По умолчанию он врублен в зоне external, но по желанию
можно и в других зонах.
Чуть ниже masquerade есть forward ports – это тоже Pro NAT, но
уже Pro Destination NAT, когда заменяется адрес получателя.
К примеру, ваш домашний компьютер недоступен из
интернета, а ваш роутер доступен, и вы можете на роутере
выделить какой-то порт, к примеру, 5555, и когда на
роутер на этот адрес будут приходить запросы, он будет
их пересылать на ваш домашний компьютер.
Таким образом вы сможете из интернета подключаться
к домашнему компьютеру, в простонародье это называется
параброс портов.
