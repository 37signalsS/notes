# Redis

## Определения

**Redis (Remote Dictionary Server)** — это высокопроизводительное хранилище данных в оперативной памяти (In-memory data store). Redis используется как база данных, кэш, брокер сообщений и очередь задач. Благодаря работе в RAM, Redis может работать в **16-20 раз быстрее**, чем классические реляционные СУБД (PostgreSQL, MySQL).

**Текущая версия:** Redis 8.x (2026).

**Лицензионные изменения (2024):** Начиная с версии 7.4, Redis перешел с лицензии BSD на проприетарные лицензии (RSALv2 и SSPLv1). Это привело к появлению полностью открытых форков под эгидой Linux Foundation, таких как **Valkey** и **Redict**.

Отличительная черта Redis — поддержка разнообразных структур данных с атомарными операциями на стороне сервера.

## Основные концепции

### Модель данных

Redis — хранилище типа «ключ-значение» с богатым набором структур:

| Структура | Описание | Размер |
| :--- | :--- | :--- |
| **Strings** | Текстовые или бинарные данные | До 512 МБ |
| **Lists** | Упорядоченные коллекции по порядку вставки | N элементов |
| **Sets** | Неупорядоченные коллекции уникальных строк | N элементов |
| **Hashes** | Карты (map) для хранения полей и значений | N полей |
| **Sorted Sets** | Множества с числовым score для сортировки | N элементов |
| **Bitmaps** | Битовые массивы для работы с битами | 512 МБ |
| **HyperLogLog** | Подсчет уникальных элементов (приблизительно) | ~12 КБ |
| **Geospatial** | Пространственные данные (широта/долгота) | N элементов |
| **Streams** | Логи событий для очередей и журналов | N записей |

**Внутренние оптимизации памяти:**

- `listpack`/`ziplist` — компактное хранение небольших коллекций
- `intset` — оптимизация для множеств целых чисел
- `quicklist` — связный список из listpack для списков

Все операции над структурами данных атомарны.

### Управление памятью

Redis использует аллокатор `jemalloc` с объектными обертками:

- **Компактное хранение:** Небольшие коллекции упаковываются эффективно
- **Накладные расходы:** Метаданные для каждого ключа и элемента
- **Фрагментация:** Возможна; для борьбы доступна `active defrag`
- **Лимит памяти:** Настраивается через `maxmemory`

**Политики вытеснения (`maxmemory-policy`):**

| Политика | Описание |
| :--- | :--- |
| `noeviction` | Не вытеснять, возвращать ошибку при нехватке памяти |
| `allkeys-lru` | Вытеснять наименее давно использованные ключи |
| `allkeys-lfu` | Вытеснять наименее часто используемые ключи |
| `allkeys-random` | Вытеснять случайные ключи |
| `volatile-lru` | Вытеснять LRU только среди ключей с TTL |
| `volatile-lfu` | Вытеснять LFU только среди ключей с TTL |
| `volatile-random` | Вытеснять случайные ключи только с TTL |
| `volatile-ttl` | Вытеснять ключи с наименьшим оставшимся TTL |

Подробнее: **[Политики вытеснения кэша](../Concepts/Caching/caching_eviction_policies.md)**.

### TTL и старение данных

Redis хранит TTL для каждого ключа с миллисекундной точностью:

1. **Пассивное истечение:** При попытке доступа к ключу с истекшим TTL
2. **Активное истечение:** Фоновый процесс выборочно проверяет ключи

**Настройка активного истечения:**

- `hz` — частота проверки (по умолчанию 10, диапазон 1–500)
- `active-expire` — включение/выключение активного истечения

### Персистентность (Persistence)

Redis поддерживает два основных механизма сохранения данных на диск:

**RDB (Snapshotting):**
- Создание снапшотов всей базы данных через определённые интервалы.
- Компактные файлы, максимально быстрое восстановление.
- Возможна потеря данных между моментами создания снапшотов.

**AOF (Append-Only File):**
- Журналирование каждой операции записи.
- В версиях 7.0+ используется **Multi-part AOF**, где данные разделяются на базовый файл (base file) и инкрементальные обновления (inc files), что делает процесс перезаписи (rewrite) эффективнее.
- Три режима сброса на диск (fsync): `always`, `everysec`, `no`.

**Рекомендация:** Сочетание RDB и AOF обеспечивает оптимальный баланс между скоростью восстановления и сохранностью данных.

### Программируемость: Lua и Функции

1. **Lua-скрипты:** Позволяют выполнять группу команд атомарно. Скрипты загружаются динамически и кэшируются сервером.
2. **Redis Functions (v7+):** Эволюция Lua-скриптов. Функции являются частью базы данных (персистентны), поддерживают версионность и упрощают управление логикой на стороне сервера, избавляя от необходимости повторной загрузки скриптов клиентами.

### Масштабирование и высокая доступность

**Репликация:**

- Асинхронная master-slave репликация
- Один мастер принимает запись, реплики — только чтение
- Каскадная репликация (реплика реплики)

**Sentinel:**

- Мониторинг мастер-нод и реплик
- Автоматическое переключение при сбое (failover)
- Уведомления об изменениях топологии

**Redis Cluster:**

- Шардирование с распределением ключей по 16384 хэш-слотам
- Автоматическое переназначение партиций при сбое
- Горизонтальное масштабирование записи

Транзакции (`MULTI`/`EXEC`) и Lua-скрипты выполняются атомарно в пределах одного узла кластера.

### Архитектура выполнения (Threading Model)

**Эволюция потоковой модели:**
- **Версии до 6.0:** Строго однопоточное выполнение команд и I/O.
- **Версии 6.0 - 7.2:** Введение **Threaded I/O**. Основной поток по-прежнему выполняет команды, но чтение/запись в сетевые сокеты делегируется вспомогательным потокам.
- **Версии 8.0+:** Дальнейшая оптимизация многопоточности для управления памятью и фоновых задач (lazy free, active defrag), что позволяет достигать миллионов RPS на одном узле. Основное ядро выполнения команд остается атомарным.

### Очереди задач
Одной из ключевых задач Redis является построение очередей сообщений на базе структуры **List**:
*   **LPUSH / RPUSH:** Добавление элементов в начало или конец списка.
*   **LPOP / RPOP:** Извлечение элементов.
*   **BLPOP / BRPOP:** Блокирующие операции, которые позволяют клиенту ожидать появления новых данных в списке (идеально для асинхронной обработки).

### Практические сценарии

#### Кеширование
Снижение нагрузки на основные БД за счет хранения горячих данных в RAM. Redis — единственный нереляционный представитель в топ-10 популярных СУБД, используемый для этих целей.

#### Брокер сообщений
Выступает посредником для маршрутизации сообщений между сервисами, поддерживая различные протоколы и вызовы веб-сервисов.

#### Машинное обучение (ML)
Используется как скоростное хранилище для автоматизации экспериментов и обработки больших объемов данных без задержек.

#### Хранение сессий и временных данных
*   Корзины интернет-магазинов, маршруты в навигаторах.
*   Временные данные: лайки, промежуточные состояния форм.


### Счетчики и аналитика

Атомарные операции для подсчёта событий:

```bash
# Увеличение на 1
INCR page_views:article:123

# Увеличение на N
INCRBY page_views:article:123 10

# Уменьшение на 1
DECR stock:item:456

# Увеличение дробного числа
INCRBYFLOAT rating:product:789 0.5
```

### Сессии пользователей

Быстрое хранение данных сессий:

```bash
# Создание сессии с TTL 30 минут
SETEX session:abc123 1800 "{\"user_id\":123,\"role\":\"admin\"}"

# Проверка сессии
EXISTS session:abc123

# Продление сессии
EXPIRE session:abc123 1800
```

### Распределённые блокировки

Реализация блокировок через `SET NX`:

```bash
# Попытка захвата блокировки
SET lock:resource:123 "client_id" NX EX 30

# Если OK — блокировка захвачена на 30 секунд
# Освобождение блокировки (через Lua для атомарности)
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
```

### Pub/Sub

Брокер сообщений для обмена сообщениями между клиентами:

```bash
# Публикация сообщения
PUBLISH channel:news "Breaking news!"

# Подписка на канал
SUBSCRIBE channel:news

# Подписка по шаблону
PSUBSCRIBE channel:*
```

### Геоданные

Хранение и поиск пространственных данных:

```bash
# Добавление местоположений
GEOADD cities 13.4050 52.5200 "Berlin"
GEOADD cities 2.3522 48.8566 "Paris"

# Поиск в радиусе 500 км от Берлина
GEORADIUS cities 13.4050 52.5200 500 km

# Расстояние между городами
GEODIST cities "Berlin" "Paris" km
```

### Установка и запуск

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install redis-server

# Запуск сервиса
sudo systemctl start redis-server
sudo systemctl enable redis-server

# Проверка статуса
sudo systemctl status redis-server

# Подключение к Redis
redis-cli

# Проверка подключения
redis-cli ping
# PONG
```

**Базовая настройка (`/etc/redis/redis.conf`):**

```conf
# Привязка к интерфейсу
bind 127.0.0.1 ::1
# Для всех интерфейсов (IPv4 и IPv6):
# bind 0.0.0.0 ::

# Порт
port 6379

# Требовать пароль
requirepass secure_password

# Лимит памяти
maxmemory 2gb
maxmemory-policy allkeys-lru

# Персистентность
save 900 1
save 300 10
save 60 10000
```
