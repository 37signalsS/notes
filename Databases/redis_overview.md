# Redis

## Определения

**Redis (Remote Dictionary Server)** — это быстрое хранилище данных с открытым исходным кодом, работающее в оперативной памяти. Redis используется как база данных, кэш, брокер сообщений и очередь.

**Текущая версия:** Redis 8.6 (февраль 2026).

Отличительная черта Redis — поддержка разнообразных структур данных с атомарными операциями на сервере.

## Основные концепции

### Модель данных

Redis — хранилище типа «ключ-значение» с богатым набором структур:

| Структура | Описание | Размер |
| :--- | :--- | :--- |
| **Strings** | Текстовые или бинарные данные | До 512 МБ |
| **Lists** | Упорядоченные коллекции по порядку вставки | N элементов |
| **Sets** | Неупорядоченные коллекции уникальных строк | N элементов |
| **Hashes** | Карты (map) для хранения полей и значений | N полей |
| **Sorted Sets** | Множества с числовым score для сортировки | N элементов |
| **Bitmaps** | Битовые массивы для работы с битами | 512 МБ |
| **HyperLogLog** | Подсчет уникальных элементов (приблизительно) | ~12 КБ |
| **Geospatial** | Пространственные данные (широта/долгота) | N элементов |
| **Streams** | Логи событий для очередей и журналов | N записей |

**Внутренние оптимизации памяти:**

- `listpack`/`ziplist` — компактное хранение небольших коллекций
- `intset` — оптимизация для множеств целых чисел
- `quicklist` — связный список из listpack для списков

Все операции над структурами данных атомарны.

### Управление памятью

Redis использует аллокатор `jemalloc` с объектными обертками:

- **Компактное хранение:** Небольшие коллекции упаковываются эффективно
- **Накладные расходы:** Метаданные для каждого ключа и элемента
- **Фрагментация:** Возможна; для борьбы доступна `active defrag`
- **Лимит памяти:** Настраивается через `maxmemory`

**Политики вытеснения (`maxmemory-policy`):**

| Политика | Описание |
| :--- | :--- |
| `noeviction` | Не вытеснять, возвращать ошибку при нехватке памяти |
| `allkeys-lru` | Вытеснять наименее давно использованные ключи |
| `allkeys-lfu` | Вытеснять наименее часто используемые ключи |
| `allkeys-random` | Вытеснять случайные ключи |
| `volatile-lru` | Вытеснять LRU только среди ключей с TTL |
| `volatile-lfu` | Вытеснять LFU только среди ключей с TTL |
| `volatile-random` | Вытеснять случайные ключи только с TTL |
| `volatile-ttl` | Вытеснять ключи с наименьшим оставшимся TTL |

Подробнее: **[Политики вытеснения кэша](../Concepts/Caching/caching_eviction_policies.md)**.

### TTL и старение данных

Redis хранит TTL для каждого ключа с миллисекундной точностью:

1. **Пассивное истечение:** При попытке доступа к ключу с истекшим TTL
2. **Активное истечение:** Фоновый процесс выборочно проверяет ключи

**Настройка активного истечения:**

- `hz` — частота проверки (по умолчанию 10, диапазон 1–500)
- `active-expire` — включение/выключение активного истечения

### Персистентность

Redis поддерживает два механизма сохранения данных на диск:

**RDB (Snapshotting):**

- Создание снапшотов через определённые интервалы
- Компактные файлы, быстрое восстановление
- Возможна потеря данных между снапшотами

**AOF (Append-Only File):**

- Журналирование всех операций записи
- Три режима fsync: `always`, `everysec`, `no`
- Более надёжно, но файлы больше и восстановление медленнее

**Рекомендация:** Использовать оба механизма для баланса производительности и надёжности.

### Масштабирование и высокая доступность

**Репликация:**

- Асинхронная master-slave репликация
- Один мастер принимает запись, реплики — только чтение
- Каскадная репликация (реплика реплики)

**Sentinel:**

- Мониторинг мастер-нод и реплик
- Автоматическое переключение при сбое (failover)
- Уведомления об изменениях топологии

**Redis Cluster:**

- Шардирование с распределением ключей по 16384 хэш-слотам
- Автоматическое переназначение партиций при сбое
- Горизонтальное масштабирование записи

Транзакции (`MULTI`/`EXEC`) и Lua-скрипты выполняются атомарно в пределах одного узла кластера.

### Архитектура выполнения

**Однопоточная модель:**

- Один поток для выполнения команд
- Неблокирующий I/O (epoll/kqueue)
- Отсутствие блокировок и переключений контекста
- Высокая производительность на простых операциях

**Многопоточность (v6+):**

- Отдельные потоки для I/O операций
- Фоновые задачи (удаление ключей, defrag)
- Основное выполнение команд остаётся однопоточным

## Практические сценарии

### Кеширование

Хранение часто запрашиваемых данных для снижения нагрузки на основные БД.

```bash
# Сохранение с TTL 1 час
SET user:123 "{\"name\":\"Alex\",\"age\":30}" EX 3600

# Получение данных
GET user:123
```

### Очереди задач

Использование списков для реализации очередей:

```bash
# Добавление задачи в конец очереди
LPUSH tasks "task1" "task2" "task3"

# Получение задачи из начала очереди
RPOP tasks

# Блокирующее получение (ожидает до 5 секунд)
BRPOP tasks 5
```

### Счетчики и аналитика

Атомарные операции для подсчёта событий:

```bash
# Увеличение на 1
INCR page_views:article:123

# Увеличение на N
INCRBY page_views:article:123 10

# Уменьшение на 1
DECR stock:item:456

# Увеличение дробного числа
INCRBYFLOAT rating:product:789 0.5
```

### Сессии пользователей

Быстрое хранение данных сессий:

```bash
# Создание сессии с TTL 30 минут
SETEX session:abc123 1800 "{\"user_id\":123,\"role\":\"admin\"}"

# Проверка сессии
EXISTS session:abc123

# Продление сессии
EXPIRE session:abc123 1800
```

### Распределённые блокировки

Реализация блокировок через `SET NX`:

```bash
# Попытка захвата блокировки
SET lock:resource:123 "client_id" NX EX 30

# Если OK — блокировка захвачена на 30 секунд
# Освобождение блокировки (через Lua для атомарности)
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
```

### Pub/Sub

Брокер сообщений для обмена сообщениями между клиентами:

```bash
# Публикация сообщения
PUBLISH channel:news "Breaking news!"

# Подписка на канал
SUBSCRIBE channel:news

# Подписка по шаблону
PSUBSCRIBE channel:*
```

### Геоданные

Хранение и поиск пространственных данных:

```bash
# Добавление местоположений
GEOADD cities 13.4050 52.5200 "Berlin"
GEOADD cities 2.3522 48.8566 "Paris"

# Поиск в радиусе 500 км от Берлина
GEORADIUS cities 13.4050 52.5200 500 km

# Расстояние между городами
GEODIST cities "Berlin" "Paris" km
```

### Установка и запуск

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install redis-server

# Запуск сервиса
sudo systemctl start redis-server
sudo systemctl enable redis-server

# Проверка статуса
sudo systemctl status redis-server

# Подключение к Redis
redis-cli

# Проверка подключения
redis-cli ping
# PONG
```

**Базовая настройка (`/etc/redis/redis.conf`):**

```conf
# Привязка к интерфейсу
bind 127.0.0.1

# Порт
port 6379

# Требовать пароль
requirepass secure_password

# Лимит памяти
maxmemory 2gb
maxmemory-policy allkeys-lru

# Персистентность
save 900 1
save 300 10
save 60 10000
```
