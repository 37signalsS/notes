# Redis против Memcached: сравнение систем кеширования

## Определения

**Redis (Remote Dictionary Server)** и **Memcached** — это высокопроизводительные in-memory (работающие в оперативной памяти) системы кеширования. Они предназначены для снижения нагрузки на основные базы данных и ускорения работы приложений за счет хранения часто запрашиваемых данных в оперативной памяти.

**Текущие версии:**

- Redis 8.6 (февраль 2026).
- Memcached 1.6.41 (март 2026).

Несмотря на общую цель, системы основаны на разных архитектурных решениях, что делает их подходящими для различных сценариев использования.

## Основные концепции

### Сравнение технических характеристик

| Аспект | Redis | Memcached |
| :--- | :--- | :--- |
| **Модель данных** | Сложные структуры (хэши, списки, множества) с атомарными операциями. | Простые пары «ключ-значение», значение — непрозрачный массив байт (blob). |
| **Управление памятью** | Аллокатор `jemalloc`, гибкие политики вытеснения (LRU, LFU и др.). | `Slab allocator` с фиксированными классами размеров. Только LRU по slab-классам. |
| **Персистентность** | Поддерживается: RDB (снимки базы данных) и AOF (журнал операций). | Отсутствует. Данные теряются при перезагрузке сервера. |
| **Масштабирование** | Встроенная репликация, Sentinel (высокая доступность), Cluster (шардирование). | На стороне клиента через согласованное хеширование. Серверы независимы. |
| **Многопоточность** | Однопоточный цикл команд, мультиплексирование I/O (ввод-вывод). Потоки для фона (v6+). | Полностью многопоточный. Эффективно использует многоядерные CPU. |
| **Размер значения** | До 512 МБ. | До 1 МБ. |
| **Ключ** | До 512 МБ. | До 250 байт. |

### Архитектурные различия

**Redis:**

- Единый поток для выполнения команд обеспечивает естественную атомарность операций без блокировок.
- Поддержка сложных структур данных (например, возможность добавить элемент в середину списка на стороне сервера) уменьшает сетевой трафик.
- Наличие персистентности (сохранения на диск) позволяет использовать Redis не только как кеш, но и как легкую базу данных.

**Memcached:**

- Многопоточная архитектура обеспечивает лучшую производительность на многоядерных системах при простых операциях получения/записи.
- Простота внутренней логики минимизирует накладные расходы на управление данными.
- Отсутствие встроенных механизмов репликации упрощает эксплуатацию одиночных узлов, перекладывая логику распределения на клиента.

## Практические сценарии

### Когда выбирать Memcached

Система является оптимальным выбором для **простого и максимально быстрого кеширования**.

**Рекомендуемые задачи:**

- Кеширование готовых HTML-фрагментов страниц.
- Снижение нагрузки на БД (База данных) через хранение сериализованных результатов SQL-запросов.
- Системы с экстремально высокой нагрузкой на чтение/запись простых строк, где важна утилизация всех ядер процессора.

### Когда выбирать Redis

Решение подходит для **сложных сценариев**, требующих продвинутой логики обработки данных в памяти.

**Рекомендуемые задачи:**

- Реализация очередей задач и систем обмена сообщениями (Pub/Sub).
- Работа с геоданными и аналитика в реальном времени.
- Хранение игровых рейтингов (через Sorted Sets).
- Обеспечение надежного хранения сессий пользователей с гарантией сохранности при перезагрузке.
- Реализация распределенных блокировок.

### Пример: хранение профиля пользователя

В **Redis** профиль хранится как структура `Hash`. Обновление одного поля (например, счетчика постов) происходит атомарно на стороне сервера одной командой `HINCRBY`.

В **Memcached** профиль обычно хранится как JSON-строка. Для обновления поля необходимо:

1. Получить всю строку на клиента.
2. Десериализовать JSON.
3. Изменить значение в коде приложения.
4. Записать строку обратно, используя механизм CAS (Check-And-Set) для предотвращения состояния гонки (race condition).

### Матрица выбора решения

| Требование | Redis | Memcached |
| :--- | :--- | :--- |
| Простое кеширование строк | Поддерживается | Предпочтительно |
| Сложные структуры данных | Предпочтительно | Нет |
| Сохранение на диск (Persist) | Поддерживается | Нет |
| Очереди задач | Поддерживается | Нет |
| Pub/Sub | Поддерживается | Нет |
| Многопоточность I/O | Частично | Да |
| Простота эксплуатации | Высокая | Очень высокая |
| Распределённые блокировки | Поддерживается | Через CAS |

## Дополнительная информация

### Производительность и экосистема

Обе системы обеспечивают задержку менее одной миллисекунды. Memcached может показывать лучшие результаты в многопоточных средах на простых ключах, в то время как Redis выигрывает в сценариях, где сложные манипуляции с данными можно перенести с клиента на сервер.

Клиентские библиотеки для обоих решений доступны для всех популярных языков программирования (Python, Java, Node.js, Go, PHP).
