# Redis против Memcached: сравнение систем кеширования

## Определения

**Redis (Remote Dictionary Server)** и **Memcached** — это высокопроизводительные системы кеширования в оперативной памяти (In-memory). Они предназначены для снижения нагрузки на основные базы данных и ускорения работы приложений.

**Текущие версии:**
- Redis 8.x (2026).
- Memcached 1.6.x (2026).

**Лицензирование и экосистема:**
- **Redis:** С 2024 года (v7.4+) перешел на проприетарные лицензии (RSALv2/SSPLv1), что привело к появлению открытых форков, таких как **Valkey** (поддерживается Linux Foundation).
- **Memcached:** Остается полностью открытым (лицензия BSD), что делает его предпочтительным для сред, требующих строгого Open Source.

## Основные концепции

### Сравнение технических характеристик

| Аспект | Redis | Memcached |
| :--- | :--- | :--- |
| **Модель данных** | Сложные структуры (хэши, списки, множества, потоки) с атомарными операциями. | Простые пары «ключ-значение», значение — непрозрачный массив байт (blob). |
| **Протокол** | RESP (текстовый/бинарный), поддержка конвейеризации. | Text/Binary и новые **Meta-команды** (v1.6+), минимизирующие трафик. |
| **Управление памятью** | Аллокатор `jemalloc`, гибкие политики вытеснения. | `Slab allocator`. Только LRU. Поддержка SSD через **Extstore**. |
| **Персистентность** | Поддерживается: RDB и **Multi-part AOF** (v7.0+). | Традиционно отсутствует. Сброс холодного тела объекта на диск через Extstore. |
| **Масштабирование** | Sentinel (HA), Cluster (шардирование на сервере). | На стороне клиента или через **Proxy (mcp)** на базе Lua. |
| **Программируемость** | Lua-скрипты и **Redis Functions** (v7.0+). | Логика проксирования на Lua (mcp). |
| **Многопоточность** | Однопоточное ядро команд, Threaded I/O (v6+). | Полностью многопоточный сервер. |
| **Размер значения** | До 512 МБ. | До 1 МБ (настраивается). |

### Архитектурные различия

**Redis:**
- Единый поток выполнения команд гарантирует атомарность без блокировок.
- Богатый набор структур данных позволяет перенести часть бизнес-логики на сторону сервера (например, работа с множествами или упорядоченными списками).
- Наличие персистентности позволяет использовать его как первичную БД для некоторых задач.

**Memcached:**
- Многопоточность обеспечивает лучшую масштабируемость на многоядерных системах при простых операциях.
- **Extstore** позволяет эффективно использовать SSD для кеширования огромных объемов данных (терабайты) при минимальном RAM.
- **mcp (Proxy)** дает полный контроль над маршрутизацией запросов внутри кластера.

## Практические сценарии

### Когда выбирать Memcached
- **Простое кеширование:** Краткосрочное хранение строк и небольших объектов.
- **Экстремальные нагрузки:** Системы с сотнями тысяч RPS на чтение простых ключей.
- **SSD-кеш:** Когда объем данных слишком велик для оперативной памяти (Extstore).
- **Строгий Open Source:** Когда политика компании запрещает использование ПО с лицензиями RSAL/SSPL.

### Когда выбирать Redis
- **Сложные типы данных:** Когда нужно атомарно менять части объекта (поля в хэше, элементы списка).
- **Долговечность данных:** Когда критически важно сохранить кэш/сессии после перезагрузки.
- **Очереди и Pub/Sub:** Использование как брокера сообщений или очереди задач.
- **Аналитика в реальном времени:** Использование встроенных функций для расчета статистик.

### Матрица выбора решения

| Требование | Redis | Memcached |
| :--- | :--- | :--- |
| Простое кеширование строк | Да | **Предпочтительно** |
| Масштабирование на терабайты (SSD) | Сложно | **Да (Extstore)** |
| Сложные структуры данных | **Да** | Нет |
| Сохранение на диск (Persistence) | **Да** | Частично (Extstore) |
| Очереди задач / Streams | **Да** | Нет |
| Программируемость (логика на сервере) | **Да (Functions)** | Да (Proxy Lua) |
| Многопоточная утилизация CPU | Ограниченно | **Да** |

## Дополнительная информация

### Производительность и экосистема
Оба решения обеспечивают задержку менее 1 мс. Memcached традиционно выигрывает в "чистой" пропускной способности на простых ключах в многопоточной среде. Redis выигрывает в функциональности, позволяя выполнять сложные атомарные операции, экономя на сетевых пересылках данных.
