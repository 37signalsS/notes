# Redis против Memcached: сравнение систем кеширования

## Определения

**Redis (Remote Dictionary Server)** и **Memcached** — это ведущие высокопроизводительные системы кеширования в оперативной памяти (In-memory). Они предназначены для снижения нагрузки на основные базы данных, ускорения работы приложений и управления состоянием в распределенных системах.

**Текущие версии (актуально на 2026 год):**
- **Redis 8.x:** Эволюционировал в мультимодальную платформу данных (AI-кэш, JSON, Векторный поиск).
- **Memcached 1.6.x:** Сохраняет фокус на экстремальной производительности и простоте, внедряя продвинутые мета-команды и проксирование.

**Лицензирование и экосистема:**
- **Redis:** Использует тройную лицензию (**AGPLv3**, RSALv2, SSPLv1). В 2025 году возврат к AGPLv3 вернул Redis статус Open Source (OSI-approved), что упростило его использование в корпоративных средах по сравнению с периодом 2024 года.
- **Valkey:** Основной открытый форк Redis (лицензия BSD), поддерживаемый Linux Foundation и облачными гигантами (AWS, GCP).
- **Memcached:** Остается полностью открытым (**лицензия BSD**), являясь эталоном стабильности и отсутствия лицензионных рисков.

## Основные концепции

### Сравнение технических характеристик

| Аспект | Redis 8.x | Memcached 1.6+ |
| :--- | :--- | :--- |
| **Модель данных** | Сложные структуры (JSON, Векторы, Хэши, Стримы) с атомарными операциями. | Простые пары «ключ-значение», значение — непрозрачный массив байт (blob). |
| **Протокол** | RESP3 (текстовый/бинарный), поддержка конвейеризации. | Text/Binary и **Meta-команды**, минимизирующие трафик и задержки. |
| **Управление памятью** | Аллокатор `jemalloc`, аппроксимированный LRU/LFU, `active defrag`. | `Slab allocator`. **Segmented LRU (SLRU)** для защиты горячих данных. |
| **Персистентность** | Полноценная: RDB, **Multi-part AOF** и оптимизированный движок **Redis Flex**. | Традиционно отсутствует. Вынос "холодных" данных на SSD через **Extstore**. |
| **Масштабирование** | Sentinel (HA), Cluster (шардирование на стороне сервера). | На стороне клиента или через **Proxy (mcp)** на базе Lua. |
| **Многопоточность** | Threaded I/O (сеть) + фоновые потоки (Flex/Lazy Free). Команды атомарны. | **Полностью многопоточный сервер**, масштабирующийся по всем ядрам. |
| **Размер значения** | До 512 МБ. | До 1 МБ по умолчанию (настраивается до гигабайтов). |
| **Безопасность** | **ACL v2**, TLS 1.3, интеграция с LDAP/Entra ID. | TLS, SASL, Meta-auth. |

### Архитектурные различия

**Redis:**
- **Мультимодальность:** В версии 8.x нативная поддержка векторного поиска (Vector Search) и JSON делает его идеальным для AI-приложений и RAG-систем.
- **Атомарность:** Единый поток выполнения команд гарантирует отсутствие race conditions без использования блокировок.
- **Программируемость:** **Redis Functions** позволяют исполнять логику на стороне сервера, сохраняя ее между перезагрузками.
- **Redis Flex:** Минимизирует влияние фоновых задач (сохранение на диск) на время отклика (Tail Latency).

**Memcached:**
- **Вертикальное масштабирование:** Благодаря полной многопоточности Memcached способен утилизировать десятки ядер CPU на одном узле, превосходя Redis в пропускной способности при работе с простыми ключами.
- **Segmented LRU (SLRU):** Разделение памяти на сегменты HOT, WARM и COLD предотвращает вытеснение часто используемых данных случайными массовыми запросами.
- **Extstore:** Позволяет хранить терабайты данных на SSD/NVMe, используя RAM только для метаданных и горячих заголовков, что радикально дешевле чистого In-memory.
- **mcp (Memcached Proxy):** Позволяет писать логику маршрутизации и отказоустойчивости на Lua прямо внутри процесса прокси.

## Практические сценарии

### Когда выбирать Memcached
- **Экстремальные нагрузки на чтение:** Системы с миллионами RPS на простых ключах-значениях.
- **Огромные объемы кэша:** Когда данные измеряются терабайтами (использование Extstore на SSD).
- **Сверхнизкие задержки:** Где важна минимальная обработка на стороне сервера без накладных расходов на парсинг сложных структур.
- **Проксирование трафика:** Когда требуется сложная балансировка кэша на уровне инфраструктуры (mcp).

### Когда выбирать Redis
- **AI и векторный поиск:** Хранение эмбеддингов и поиск по сходству (Vector Database).
- **Сложная бизнес-логика:** Когда нужно атомарно манипулировать частями объекта (например, инкремент поля в JSON).
- **Очереди и стриминг:** Использование Streams для построения надежных шин сообщений.
- **Первичная БД:** Для задач, где допустима модель In-memory с периодическим сбросом на диск (сессии, корзины, игровые лидерборды).

### Матрица выбора решения

| Требование | Redis 8.x | Memcached 1.6+ |
| :--- | :--- | :--- |
| Простое кеширование строк | Да | **Предпочтительно (SLRU)** |
| Масштабирование на терабайты (SSD) | Сложно | **Да (Extstore)** |
| Векторный поиск / AI | **Да (Нативно)** | Нет |
| Документы JSON | **Да (Нативно)** | Нет |
| Сохранение на диск (Persistence) | **Да (Надежно)** | Частично (Extstore) |
| Очереди задач / Streams | **Да** | Нет |
| Многопоточная утилизация CPU | Высокая (I/O) | **Экстремальная** |

## Безопасность

**Redis:** Предлагает зрелую модель **ACL v2**, позволяющую ограничивать доступ к конкретным ключам и категориям команд. Поддерживает аутентификацию через внешние системы (LDAP, Active Directory).

**Memcached:** Традиционно ориентирован на доверенные внутренние сети. Поддерживает TLS для шифрования и SASL для базовой аутентификации. Рекомендуется использовать UDP только в защищенных контурах для исключения векторов усиления DDoS.

## Облачные форки и Valkey

В 2026 году значительную долю рынка занимает **Valkey** — форк Redis под эгидой Linux Foundation.
- **Совместимость:** 100% совместим с протоколом Redis.
- **Преимущество:** Полностью открытая лицензия BSD, отсутствие вендор-лока.
- **Облака:** Является стандартом де-факто для AWS ElastiCache и GCP Cloud Memorystore.

## Дополнительная информация

### Производительность и TCO
Хотя Redis 8.x значительно сократил разрыв в производительности за счет оптимизации I/O, Memcached остается более эффективным с точки зрения стоимости владения (TCO) при хранении гигантских объемов кэша благодаря **Extstore**. Redis, в свою очередь, экономит ресурсы на уровне приложения, позволяя выполнять сложные операции одной командой вместо нескольких циклов «запрос-ответ».
