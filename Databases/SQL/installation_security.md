# Безопасная установка SQL-сервера

### Определения

- **Безопасная установка (Hardening)**: Процесс начальной настройки SQL-сервера после его инсталляции, направленный на устранение уязвимостей, поставляемых по умолчанию, и усиление общей защищенности.
- **`mysql_secure_installation`**: Интерактивная утилита командной строки, поставляемая с MariaDB и MySQL, которая помогает автоматизировать основные шаги по обеспечению безопасности сервера.

### Базовые концепции

После первичной установки SQL-сервера (например, MariaDB или MySQL) критически важно выполнить базовую настройку безопасности. Это включает в себя удаление стандартных уязвимостей и повышение общей защищенности системы, таких как анонимные пользователи, тестовые базы данных и небезопасные пароли.

### Практические сценарии

Большинство SQL-серверов предоставляют встроенный инструмент для начальной настройки безопасности. Для MariaDB и MySQL таким инструментом является утилита `mysql_secure_installation`.

#### Использование `mysql_secure_installation`:

1. **Запуск утилиты**:

    ```bash
    sudo mysql_secure_installation
    ```

2. **Последовательность действий**:
    Утилита последовательно предложит настроить следующие параметры:

    - **Настройка проверки надежности паролей (VALIDATE PASSWORD COMPONENT):** Позволяет установить требования к сложности паролей для пользователей базы данных.
    - **Изменение пароля для пользователя `root`:** Установка надежного пароля для административного пользователя.
    - **Удаление анонимных пользователей:** Удаление учетных записей, которые могут быть использованы для доступа без явных учетных данных.
    - **Отключение удаленного доступа для `root`:** Запрет на удаленное подключение к базе данных от имени суперпользователя.
    - **Удаление тестовой базы данных и доступов к ней:** Удаление демонстрационной базы данных (`test`), которая по умолчанию доступна для всех.
    - **Перезагрузка таблиц привилегий:** Немедленное применение всех внесенных изменений в системе привилегий.

#### Дополнительные меры безопасности (PostgreSQL)

PostgreSQL использует другую модель безопасности. После установки:

```bash
# Подключение к PostgreSQL
sudo -u postgres psql

# Создание нового пользователя с правами суперпользователя
CREATE USER admin WITH PASSWORD 'secure_password';
ALTER USER admin WITH SUPERUSER;

# Удаление публичного доступа к схеме
REVOKE ALL ON SCHEMA public FROM PUBLIC;
```

### Дополнительная информация

- Всегда устанавливайте надежный и уникальный пароль для пользователя `root`.
- Отключайте анонимных пользователей для предотвращения неавторизованного доступа.
- Запрещайте удаленный доступ для `root`, если он не является абсолютно необходимым. Для удаленного администрирования создавайте отдельных пользователей с ограниченными привилегиями.
- Удаляйте тестовые базы данных на всех производственных и тестовых окружениях.
- Ограничьте сетевой доступ к порту СУБД с помощью файрвола.
- Регулярно обновляйте СУБД до последних версий для получения патчей безопасности.
