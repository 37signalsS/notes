# Citus

## Определения

**Citus** — это расширение (extension) для СУБД (Система управления базами данных) PostgreSQL, которое превращает ее в распределенную базу данных. Он позволяет горизонтально масштабировать PostgreSQL, распределяя данные и запросы по кластеру из нескольких серверов.

Ключевая цель — **масштабирование PostgreSQL «наружу» (scale-out)** для обработки больших объемов данных и высоких нагрузок, которые не может выдержать один сервер.

**Текущая версия:** Citus 14.x (2026) с поддержкой PostgreSQL 18.

## Основные концепции

### Архитектура

- **Координатор (Coordinator Host):** основной узел, точка входа для приложений. Хранит метаданные о расположении шардов и управляет планированием распределенных запросов.
- **Воркеры (Worker Hosts):** рабочие узлы, хранящие фактические данные (шарды) и выполняющие локальные фрагменты запросов.
- **Шарды (Shards):** фрагменты распределенной таблицы. Citus разбивает таблицу на множество шардов (обычно 32 или более), которые равномерно распределяются по воркерам.

### Типы таблиц

Citus расширяет стандартную модель данных PostgreSQL тремя типами таблиц:

1. **Распределенные таблицы (Distributed Tables):**
    - Большие таблицы, шардированные по **ключу дистрибуции (distribution column)**.
    - Создание: `SELECT create_distributed_table('table_name', 'distribution_column');`

2. **Таблицы-справочники (Reference Tables):**
    - Небольшие таблицы, которые **полностью реплицируются на каждый узел** кластера.
    - Позволяют выполнять `JOIN` с распределенными таблицами локально на воркерах.
    - Создание: `SELECT create_reference_table('table_name');`

3. **Локальные таблицы (Local Tables):**
    - Стандартные таблицы PostgreSQL, живущие только на координаторе. Часто используются для служебных целей или небольших данных, не требующих масштабирования.

### Колоночное хранение (Columnar Storage)

Начиная с версии 10, Citus поддерживает **колоночный формат хранения** для распределенных таблиц. Это позволяет значительно сжимать данные (до 3-10 раз) и ускорять аналитические запросы (OLAP), считывая только необходимые колонки.

```sql
-- Создание таблицы с колоночным хранением
CREATE TABLE events (
    device_id bigint,
    event_type text,
    event_time timestamptz
) USING columnar;
```

### Совместное размещение (Colocation)

**Colocation** — это механизм, при котором строки из разных распределенных таблиц с одинаковым значением ключа дистрибуции гарантированно попадают на один и тот же шард/узел. Это критически важно для производительности `JOIN` и обеспечения ссылочной целостности (`FOREIGN KEY`).

### Работа с индексами и ограничениями

- **Уникальные индексы:** должны включать ключ дистрибуции, чтобы проверка уникальности выполнялась локально в рамках одного шарда.
- **Внешние ключи (Foreign Keys):** поддерживаются между "со-размещенными" (colocated) таблицами или при связи со справочниками.
- **Распространение схем:** любые команды `ALTER TABLE`, `CREATE INDEX` на координаторе автоматически транслируются на все шарды воркеров.

## Практические сценарии

### Области применения

- **SaaS и мультитенантность:** изоляция данных клиентов по `tenant_id`. Позволяет легко перемещать крупных клиентов на отдельные узлы.
- **Аналитика в реальном времени:** высокопроизводительный инжест данных и мгновенная агрегация по миллиардам строк.
- **Хранилища данных (DWH):** использование PostgreSQL как основы для масштабируемого хранилища с поддержкой стандартного SQL.

### Ребалансировка данных

При добавлении новых воркеров в кластер Citus позволяет перераспределить существующие шарды без остановки обслуживания (online rebalancing):

```sql
-- Запуск фоновой ребалансировки
SELECT citus_rebalance_start();
```

## Дополнительная информация

### Сравнение аналитических решений

| Система | Тип архитектуры | Основное назначение | Ключевые особенности |
| :--- | :--- | :--- | :--- |
| **[PostgreSQL](./PostgreSQL/overview.md)** | Одиночный узел | OLTP, общие задачи | Максимальная надежность |
| **[Greenplum](./greenplum.md)** | MPP (Fork) | Тяжелый OLAP, Big Data | Оптимизирована под сложные JOIN'ы |
| **Citus** | Распределенный PG (Extension) | SaaS, Real-time OLAP | Гибкость, совместимость с PG |

### Ограничения

- **Кросс-шардовые транзакции:** хотя они поддерживаются, большое количество распределенных транзакций может создавать нагрузку на координатор.
- **Смена ключа дистрибуции:** требует пересоздания таблицы или сложной миграции.
