# MongoDB

**MongoDB** – это документо-ориентированная NoSQL база данных. В отличие от реляционных баз данных (таких как MySQL или PostgreSQL), которые хранят данные в таблицах и строках, MongoDB хранит данные в гибких, JSON-подобных документах. Эта модель данных позволяет легко и быстро разрабатывать приложения, адаптируясь к изменяющимся требованиям.

Ключевые характеристики:

-   **Высокая производительность:** Обеспечивается за счет встроенного кэширования и оптимизированного доступа к данным.
-   **Высокая доступность:** Поддерживается через наборы реплик ([replication](./Concepts/replication.md)).
-   **Горизонтальное масштабирование:** Достигается с помощью [шардинга](./Concepts/sharding.md), что позволяет распределять данные по нескольким серверам.
-   **Гибкая схема данных:** Нет необходимости заранее определять структуру документов.

Данные хранятся в формате **BSON** (Binary JSON), который является бинарным представлением JSON-документов и поддерживает больше типов данных.

## Установка MongoDB Community Edition на Ubuntu

MongoDB использует свой репозиторий, поэтому сначала необходимо добавить его ключ в систему.

```bash
# Устанавливаем зависимости, если их нет
sudo apt-get install gnupg curl

# Импортируем ключ MongoDB
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | \
   sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
```

Создайте файл `/etc/apt/sources.list.d/mongodb-org-7.0.list`, чтобы `apt` знал, откуда скачивать пакеты.

```bash
echo "deb [ arch=amd64,arm64 signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
```

Обновите список пакетов и установите мета-пакет `mongodb-org`, который включает в себя все необходимые компоненты (сервер, клиент, утилиты).
```bash
sudo apt-get update
sudo apt-get install -y mongodb-org
```

После установки служба `mongod` не запускается автоматически.

-   **Запустить службу:**
    ```bash
    sudo systemctl start mongod
    ```

-   **Подключиться к базе данных:**
    Используйте `mongosh` (новый shell, который устанавливается вместе с сервером).
    ```bash
    mongosh
    ```

## Кластеризация: Replica Set и Sharding

MongoDB обеспечивает высокую доступность и масштабируемость с помощью двух ключевых механизмов: наборов реплик и шардинга.

### Набор реплик (Replica Set)

Набор реплик — это группа процессов `mongod`, которые поддерживают один и тот же набор данных.
-   **Цель:** Обеспечение отказоустойчивости и высокой доступности.
-   **Как работает:** В наборе реплик есть один **первичный** (primary) узел, который принимает все операции записи. Остальные узлы — **вторичные** (secondary) — асинхронно копируют данные с первичного. Если первичный узел выходит из строя, один из вторичных автоматически избирается новым первичным.
-   Подробнее см. в [Основной заметке о репликации](./Concepts/replication.md).

### Шардинг (Sharding)

Шардинг — это метод горизонтального масштабирования, который позволяет распределять данные по нескольким серверам (шардам).
-   **Цель:** Работа с очень большими наборами данных и распределение нагрузки на запись.
-   **Как работает:** MongoDB разбивает коллекцию на "чанки" (куски) и распределяет их по разным шардам на основе **ключа шарда** (shard key).
-   Подробнее см. в [Основной заметке о шардинге](./Concepts/sharding.md).

Для настройки кластера MongoDB обычно сначала настраивают наборы реплик для каждого шарда, а также для серверов конфигурации, чтобы обеспечить отказоустойчивость всей системы.
