# Memcached

## Определения

**Memcached** — это высокопроизводительная распределённая система кеширования объектов в оперативной памяти. Она предназначена для ускорения динамических веб-приложений путём снижения нагрузки на базу данных.

**Текущая версия:** Memcached 1.6.41 (март 2026).

Memcached представляет собой простое хранилище типа «ключ-значение», оптимизированное для максимальной скорости операций чтения и записи.

## Основные концепции

### Модель данных

Memcached — хранилище типа «ключ-значение»:

- **Ключ:** Строка до 250 байт
- **Значение:** Непрозрачный массив байт (`blob`) размером до 1 МБ
- **Метаданные:** TTL, флаги (для клиентской сериализации), CAS-токен

Сервер не интерпретирует формат значений. Сложные структуры данных (JSON, объекты) требуют сериализации и десериализации на стороне клиента.

**Основные команды:**

- `get` — получение значения по ключу
- `set` — сохранение значения
- `delete` — удаление ключа
- `incr`/`decr` — атомарное увеличение/уменьшение числового значения
- `cas` — атомарная запись с проверкой версии (Check-And-Set)

### Управление памятью: Slab Allocator

Memcached использует **slab-аллокатор** для эффективного управления памятью:

1. **Слабы (Slabs):** Память предварительно разбивается на страницы по 1 МБ
2. **Чанки (Chunks):** Каждый slab нарезается на чанки фиксированных размеров
3. **Классы размеров:** Чанки группируются в классы (например, 64 Б, 128 Б, 256 Б, ..., 1 МБ)
4. **Распределение:** Каждый объект помещается в чанк подходящего размера

**Преимущества:**

- Снижение фрагментации памяти
- Быстрое выделение/освобождение памяти
- Предсказуемое использование памяти

**Недостатки:**

- Неэффективное использование пространства при плохом соответствии размеров объектов классам чанков
- Возможна ситуация, когда есть свободная память, но нет чанков подходящего размера

### TTL и старение данных

**TTL (Time-To-Live)** задаётся для каждого элемента при сохранении:

- **Ленивое истечение:** Ключи удаляются при попытке доступа к ним
- **Фоновый crawler:** Периодически обходит элементы и удаляет просроченные
- **Интерпретация TTL:** Значение >30 дней (2 592 000 секунд) трактуется как абсолютное Unix-время

### Политика вытеснения: LRU

При заполнении памяти Memcached вытесняет данные по алгоритму **LRU (Least Recently Used)**:

- Вытесняется элемент, к которому дольше всего не обращались
- LRU реализуется отдельно для каждого slab-класса
- Начиная с версии 1.4.8 доступен улучшенный **segmented LRU**:
  - `-o lru_maintainer` — отдельный поток для управления LRU
  - `-o lru_crawler` — фоновое удаление просроченных ключей
  - `-o lru_maintainer=lru_crawler` — комбинация обоих режимов

Подробнее о политиках вытеснения: **[Caching Eviction Policies](../Concepts/Caching/caching_eviction_policies.md)**.

### Персистентность

Memcached **не поддерживает персистентность**:

- После перезапуска сервер стартует с пустым кешем
- Спроектирован как временное энергозависимое хранилище
- Для сохранения данных требуется внешнее хранилище

### Масштабирование и консистентность

**Горизонтальное масштабирование:**

- Осуществляется через **шардирование на стороне клиента**
- Используется **согласованное хеширование (consistent hashing)**
- Добавление/удаление серверов минимально перестраивает кеш

**Архитектурные особенности:**

- Серверы независимы друг от друга
- Нет обмена данными между узлами
- Встроенная репликация отсутствует
- Клиент отвечает за выбор сервера для каждого ключа

### Многопоточность

Memcached многопоточен:

- Эффективно утилизирует многоядерные процессоры
- Параллельная обработка запросов `get`/`set`
- Низкая латентность благодаря минималистичной семантике операций

## Практические сценарии

### Когда использовать Memcached

**Идеальные сценарии:**

- **Кеширование HTML-страниц:** Сохранение отрендеренных фрагментов страниц
- **Кеширование запросов к БД:** Результаты тяжелых SQL-запросов
- **Кеширование API-ответов:** Ответы внешних сервисов
- **Хранение сессий:** Временные данные пользовательских сессий
- **Простые счетчики:** Атомарное увеличение/уменьшение значений

**Требования для выбора Memcached:**

- Максимальная производительность на простых операциях
- Эффективное использование многоядерных CPU
- Простота развертывания и эксплуатации
- Не требуется персистентность данных

### Когда НЕ использовать Memcached

- **Сложные структуры данных:** Требуется Redis с поддержкой хэшей, списков, множеств
- **Персистентность:** Нужна сохранность данных после перезапуска
- **Pub/Sub:** Требуется брокер сообщений
- **Очереди задач:** Нужна полноценная очередь с приоритетами
- **Геоданные:** Требуется пространственная индексация

### Пример: кеширование запроса к БД

```python
import memcache
import json

# Подключение к кластеру Memcached
mc = memcache.Client(['192.168.1.10:11211', '192.168.1.11:11211'])

def get_user_profile(user_id):
    cache_key = f"user_profile:{user_id}"
    
    # Попытка получить из кеша
    data = mc.get(cache_key)
    if data:
        return json.loads(data)
    
    # Запрос к БД (cache miss)
    user_data = db.query("SELECT * FROM users WHERE id = ?", user_id)
    
    # Сохранение в кеш на 1 час
    mc.set(cache_key, json.dumps(user_data), time=3600)
    
    return user_data
```

### Пример: атомарное увеличение счетчика

```bash
# Увеличение счетчика на 1
incr page_views:article:123 1

# Увеличение на 5
incr page_views:article:123 5

# Если ключ не существует, можно задать начальное значение
incr page_views:article:123 1 1 3600
```

### Пример: CAS для предотвращения гонок

```python
# Получение значения с CAS-токеном
value, cas_id = mc.gets("counter")

# Атомарное обновление с проверкой версии
new_value = int(value) + 1
mc.cas("counter", new_value, cas_id)
```

## Дополнительная информация

### Требования к оборудованию

| Ресурс | Рекомендация | Примечание |
| :--- | :--- | :--- |
| **RAM** | 2–128 ГБ | Основной ресурс для кеша |
| **CPU** | 4+ ядер | Многопоточность эффективно использует ядра |
| **Сеть** | 1–10 Гбит/с | Сетевая задержка критична для производительности |
| **Диск** | Минимальный | Только для ОС и логов |

### Сравнение с Redis

| Аспект | Memcached | Redis |
| :--- | :--- | :--- |
| **Модель данных** | Простые ключ-значение | Структуры данных (хэши, списки, множества) |
| **Управление памятью** | Slab allocator | Jemalloc, гибкие политики (LRU, LFU) |
| **Персистентность** | Отсутствует | RDB, AOF |
| **Масштабирование** | На клиенте | Встроенное (Cluster, Sentinel) |
| **Многопоточность** | Да | Частично (I/O потоки в v6+) |
| **Функциональность** | Базовые операции + CAS | Транзакции, Pub/Sub, Lua, потоки |
