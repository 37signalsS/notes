# Memcached — обзор

## Определения

**Memcached** — это высокопроизводительная распределённая система кеширования объектов в оперативной памяти. Она предназначена для ускорения динамических веб-приложений путём снижения нагрузки на базу данных.

**Текущая версия:** Memcached 1.6.x (актуально на 2026 год).

**Лицензия:** BSD (полностью открытый исходный код).

Memcached представляет собой простое хранилище типа «ключ-значение», оптимизированное для максимальной скорости операций чтения и записи за счет минимальных накладных расходов и полной многопоточности.

## Основные концепции

### Модель данных

Memcached — хранилище типа «ключ-значение»:

- **Ключ:** строка до 250 байт.
- **Значение:** непрозрачный массив байт (blob) размером до 1 МБ (настраивается).
- **Метаданные:** TTL (Time-To-Live), флаги, CAS-токен.

**Типы команд:**
1. **Традиционные (Text/Binary):** `get`, `set`, `delete`, `incr`, `decr`, `cas`.
2. **Meta-команды (v1.6+):** новый расширяемый протокол (`mg`, `ms`, `md`, `mn`), который эффективнее традиционных команд. Он позволяет атомарно возвращать метаданные, обновлять TTL и выполнять условные операции в одном пакете.

### Управление памятью: Slab Allocator

Memcached использует **Slab Allocator** для предотвращения фрагментации памяти:

1. **Слабы (Slabs):** Память разбивается на страницы по 1 МБ.
2. **Классы размеров (Slab Classes):** Страницы нарезаются на чанки фиксированных размеров (напр., 64Б, 128Б, 256Б).
3. **Распределение:** Объект попадает в чанк ближайшего подходящего размера. Это исключает внешнюю фрагментацию, но может приводить к внутренней (пустое место внутри чанка).

### Внешнее хранилище (Extstore)

Начиная с версии 1.5.0, Memcached поддерживает **Extstore** — механизм для выноса "холодных" данных из оперативной памяти на быстрые диски (SSD/NVMe).
- **RAM:** Хранит метаданные (заголовки) и часто используемые данные.
- **Disk:** Тела крупных или редко используемых объектов сбрасываются на диск.
- **Масштабируемость:** Позволяет кешировать терабайты данных, используя на порядок меньше RAM по сравнению с Redis.

### Прокси-слой (Memcached Proxy - mcp)

В версиях 1.6.x представлен встроенный прокси-движок на базе **Lua**.
- **Маршрутизация:** Перенаправление запросов на разные пулы серверов на основе ключа.
- **Shadow Production:** Копирование трафика на тестовый кластер для проверки новых версий или конфигураций без риска для продакшена.
- **Сложная логика:** Реализация Rate Limiting, фильтрации или кастомного кворума прямо внутри Memcached.

### Время жизни и старение данных

**TTL (Time-To-Live):**
- **Ленивое истечение:** Ключ удаляется при попытке обращения к нему.
- **LRU Crawler:** Фоновый поток, который сканирует память и удаляет записи с истекшим TTL, не дожидаясь обращения.
- **Особенность:** Если значение TTL > 30 дней (2592000 секунд), оно интерпретируется как Unix Timestamp (абсолютное время).

### Политика вытеснения: Segmented LRU

Memcached использует **Segmented LRU (SLRU)**, разделяющий память на четыре очереди:
*   **TEMP:** Для объектов с очень коротким TTL.
*   **HOT:** Для новых объектов.
*   **WARM:** Для объектов, к которым обратились более одного раза.
*   **COLD:** Для объектов, которые давно не использовались.
Это защищает «горячие» данные от вымывания массовыми разовыми запросами (защита от сканирования).

### Безопасность и Сеть

- **Многопоточность:** Каждый поток имеет свою очередь запросов, что позволяет линейно масштабироваться с ростом количества ядер.
- **TLS:** Поддержка шифрования трафика.
- **SASL:** Механизм аутентификации.
- **Meta-auth:** Возможность аутентификации через мета-протокол.

## Практические сценарии

### Использование Meta-команд

Meta-команды позволяют экономить трафик, не возвращая само значение, если нужны только метаданные.

```bash
# Получить значение (v) и CAS-токен (c) для ключа mykey
mg mykey v c
# → VA 5 c123\r\nvalue\r\n

# Обновить TTL до 600 секунд без получения значения
mg mykey t600
# → HD\r\n
```

### Настройка Extstore (SSD кэш)

Пример запуска Memcached с использованием SSD для хранения тел объектов:

```bash
memcached -m 1024 -o ext_path=/dev/nvme0n1:100G,ext_wbuf_size=4,ext_threads=4,ext_item_size=512,ext_item_age=3600
```
*   `-m 1024`: 1 ГБ RAM под метаданные.
*   `ext_path`: 100 ГБ на NVMe диске.
*   `ext_item_size`: Объекты крупнее 512 байт могут быть вынесены на диск.

### Пример на Python (Meta-протокол)

Для работы с мета-командами рекомендуется использовать современные библиотеки, поддерживающие этот протокол.
