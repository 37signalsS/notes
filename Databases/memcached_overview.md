# Memcached

## Определения

**Memcached** — это высокопроизводительная распределённая система кеширования объектов в оперативной памяти. Она предназначена для ускорения динамических веб-приложений путём снижения нагрузки на базу данных.

**Текущая версия:** Memcached 1.6.x (актуально на 2026 год).

Memcached представляет собой простое хранилище типа «ключ-значение», оптимизированное для максимальной скорости операций чтения и записи за счет минимальных накладных расходов.

## Основные концепции

### Модель данных

Memcached — хранилище типа «ключ-значение»:

- **Ключ:** строка до 250 байт.
- **Значение:** непрозрачный массив байт (blob) размером до 1 МБ (настраивается).
- **Метаданные:** TTL (Time-To-Live), флаги, CAS-токен.

**Типы команд:**
1. **Традиционные (Text/Binary):** `get`, `set`, `delete`, `incr`, `decr`, `cas`.
2. **Meta-команды (v1.6+):** новый расширяемый протокол (`mg`, `ms`, `md`, `mn`), который эффективнее традиционных команд и позволяет за один запрос выполнять сложные операции с метаданными.

### Управление памятью: Slab Allocator

Memcached использует **Slab Allocator** для предотвращения фрагментации памяти:

1. **Слабы (Slabs):** память разбивается на страницы по 1 МБ.
2. **Классы размеров:** страницы нарезаются на чанки фиксированных размеров (64Б, 128Б и т.д.).
3. **Распределение:** объект попадает в чанк ближайшего подходящего размера.

### Внешнее хранилище (Extstore)

Начиная с версии 1.5.0, Memcached поддерживает **Extstore** — механизм для выноса "холодных" данных из оперативной памяти на быстрые диски (SSD/NVMe).
- В RAM хранятся только метаданные и "горячие" данные.
- Тела крупных или редко используемых объектов сбрасываются на диск.
- Позволяет кешировать терабайты данных при умеренном потреблении RAM.

### Прокси-слой (Memcached Proxy - mcp)

В версиях 1.6.x представлен встроенный прокси-движок на базе **Lua**.
- **Маршрутизация:** перенаправление запросов на разные пулы серверов на основе ключа.
- **Отказоустойчивость:** автоматическое переключение на резервные узлы.
- **Rate Limiting:** ограничение количества запросов.
- **Shadow Production:** дублирование трафика на новый кластер для тестирования.

### Время жизни и старение данных

**TTL (Time-To-Live):**
- **Ленивое истечение:** ключ удаляется при попытке обращения.
- **LRU Crawler:** фоновый процесс, очищающий память от просроченных записей.
- **Интерпретация:** если значение TTL > 30 дней, оно считается как Unix Timestamp.

### Политика вытеснения: Segmented LRU

Memcached использует улучшенный **Segmented LRU**, разделяя данные на три очереди:
1. **HOT:** новые данные, к которым часто обращаются.
2. **WARM:** данные, "выжившие" в HOT.
3. **COLD:** редко используемые данные, первые кандидаты на вытеснение или сброс в Extstore.

### Безопасность и Сеть

- **TLS:** поддержка шифрования трафика между клиентом и сервером.
- **SASL:** аутентификация пользователей.
- **UDP/TCP:** поддержка обоих протоколов (UDP часто отключают для предотвращения усиления DDoS).

## Практические сценарии

### Когда использовать Memcached

- **Простое кеширование:** когда не нужны сложные структуры данных (списки, хэши).
- **Высокая нагрузка на чтение:** за счет многопоточности Memcached часто быстрее Redis на многоядерных системах.
- **Огромные объемы данных:** при использовании Extstore на SSD.

### Когда НЕ использовать Memcached

- **Сложные структуры данных:** если нужно манипулировать частями объекта (рекомендуется Redis).
- **Персистентность:** данные Memcached полностью исчезают при перезапуске.
- **Шардирование:** Memcached требует умного клиента для распределения данных, в то время как Redis Cluster делает это на стороне сервера.

### Пример: Использование Meta-команд (mg)

```bash
# Meta Get: получить значение и обновить TTL до 300 секунд
mg mykey v t300
```

### Пример: Кеширование в Python

```python
import pymemcache.client.base as memcache

client = memcache.Client(('localhost', 11211))
client.set('key', 'value', expire=3600)
result = client.get('key')
```
