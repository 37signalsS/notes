# Memcached — обзор

**Актуально для:** Memcached 1.6.x (latest stable 1.6.45, 2026-07-09); пакеты: Ubuntu 24.04 (noble) — 1.6.24, Debian unstable — 1.6.45

## Определения

**Memcached** — высокопроизводительная распределённая система кеширования объектов в оперативной памяти (in-memory object cache). Спроектирована для ускорения динамических веб-приложений путём снижения нагрузки на основные базы данных. Модель данных — простые пары «ключ-значение» (blob); все операции O(1) и атомарны.

**Лицензия:** BSD-3-Clause (полностью открытый исходный код, отсутствие лицензионных рисков).

**Ключевые ограничения (по дизайну):** нет персистентности (кроме Extstore на SSD), нет репликации и failover «из коробки» (масштабирование — client-side consistent hashing или встроенный прокси), нет сложных структур данных.

## Основные концепции

### Архитектура и потоки (SMP)

Memcached — полностью многопоточное приложение (SMP): каждый worker thread обрабатывает свои соединения, конкурируя за доступ к хеш-таблице через гранулярные блокировки. Это позволяет линейно масштабироваться с ростом числа ядер CPU на одном узле. Модель — «worker threads» (как у nginx), а не «thread/process per connection» (как у Apache): низких чисел потоков достаточно.

- `-t` (threads): по умолчанию **4**; обычно равно числу ядер. Значения 64+ не рекомендуются, 80+ заметно замедляют работу.
- `-c` (conn-limit): по умолчанию **1024** одновременных соединений. Накладные расходы на соединение малы (ещё меньше для idle), но при исчерпании лимита новые соединения «зависают» в ожидании слота — контроль через счётчик `listen_disabled_num`.
- `-R` (max-reqs-per-event): по умолчанию **20** — защита от starvation одного клиента.
- `-b` (listen-backlog): по умолчанию **1024**.

### Slab Allocator

Memcached использует **Slab Allocator** для исключения внешней фрагментации, характерной для стандартного `malloc`:

1. **Страницы (Pages):** память (`-m`) разбивается на страницы по **1 МБ** (по умолчанию). Страница, однажды назначенная slab-классу, больше не перемещается.
2. **Классы размеров (Slab Classes):** страницы нарезаются на чанки фиксированных размеров. Разница между размерами определяется фактором роста (`-f`, по умолчанию **1.25**); минимальный чанк — `-n` (по умолчанию **48** байт).
3. **Размещение:** объект сохраняется в чанк ближайшего подходящего размера.
   - *Проблема:* внутренняя фрагментация (объект 65 Б в чанке 128 Б оставляет 63 Б неиспользуемыми).
   - *Решение:* тюнинг `-f` и `-n` под профиль данных; автоматическая балансировка страниц — `-o slab_automove`.

Посмотреть классы: `memcached -vv` при старте или `memcached-tool <host:port> display`.

### Segmented LRU (SLRU)

Сегментированный LRU — **default с версии 1.5.0** (ранее требовал `-o modern`; сейчас `-o modern` — no-op, все «modern»-опции включены по умолчанию; `no_modern` возвращает defaults 1.4.x):

- **TEMP:** объекты с TTL ≤ `temporary_ttl` (по умолчанию **61 с**). Никогда не перемещаются в другие очереди, не «бump'ятся» и **не могут быть вытеснены** — не ставьте `temporary_ttl` слишком высоким, иначе память может исчерпаться.
- **HOT:** новые объекты; кап 32% памяти slab-класса (`hot_lru_pct`) + возрастной кап (`hot_max_factor` × возраст COLD).
- **WARM:** объекты с повторными обращениями («защищённая» зона); кап 32% (`warm_lru_pct`, `warm_max_factor`).
- **COLD:** кандидаты на вытеснение; без капа по умолчанию. Активный объект из COLD сразу перемещается в WARM.

Архитектура предотвращает «вымывание» полезного кэша массовыми разовыми запросами (например, при сканировании БД).

Живая настройка без перезапуска (команда `lru`): `lru mode flat|segmented`, `lru tune ...`, `lru temp_ttl N` (`-1` отключает TEMP). Рекомендуемая связка при старте: `-o lru_maintainer,lru_crawler` — фоновый crawler освобождает просроченные TTL.

### Протоколы: Text, Meta и deprecated Binary

- **Text protocol** — базовый набор команд (`get`, `set`, `delete`, `incr` и т.д.).
- **Meta protocol** — введён в 2019, вошёл в **1.6.0** (2020-03). **Не заменяет** Text — он с ним совместим (cross-compatible) и рекомендуется для всех новых клиентов. Команды: `mg` (get — заменяет `get`/`gets`/`gat`/`gats`/`touch`), `ms` (set — все команды записи, включая CAS-условия), `md` (delete — с поддержкой «stale»-меток для stale-while-revalidate), `ma` (arithmetic — заменяет `incr`/`decr`, с 1.6.0), `mn` (noop — sentinel для pipelining). За один сетевой раунд можно, например, получить значение вместе с TTL и CAS-токеном.
- **Binary protocol** — **deprecated**: больше не получает обновлений (проблемы безопасности, низкая эффективность, сложность реализации клиентов).

Ключевые ограничения протокола: ключ — до **250 байт**; значение — до **1 МБ** по умолчанию (`-I`, мин. 1k, макс. **1G**); TTL — `0` (не истекает) или 1..2592000 с (30 дней), значение **> 2592000 интерпретируется как Unix-timestamp** (типичная ловушка: «TTL 60 дней» = timestamp 1970 года = мгновенное истечение).

CAS (`gets`/`cas`) — оптимистичная блокировка: сервер возвращает уникальный токен версии, запись проходит только если токен совпадает. `incr`/`decr` — атомарные счётчики (decrement не уходит ниже 0). `append`/`prepend` — конкатенация к значению.

### Extstore (Flash Storage)

Механизм **Extstore** (скомпилирован по умолчанию с 1.6.0, но включается только при старте через `-o ext_path=...`) позволяет кешировать объёмы, значительно превышающие RAM, за счёт быстрых дисков (NVMe/SSD):

- **Метаданные (ключи, заголовки):** всегда в RAM.
- **Данные (тела объектов):** объекты крупнее `ext_item_size` сбрасываются на диск.
- **TCO:** терабайты кэша на порядок дешевле, чем чистая RAM.

Defaults (см. `memcached -h` или `stats settings`): `ext_page_size=64M`, `ext_wbuf_size=8M` (write-буфер на bucket; всего резервируется 32 МБ), `ext_threads=1` (не более 8), `ext_item_size=512` байт, `ext_recache_rate=2000`, `ext_compact_under` = 1/4 страниц. Компакция управляется `ext_max_frag` (переписывать страницы, которые пусты хотя бы на N) и `ext_drop_unread`. Часть параметров меняется на лету: `extstore item_size|item_age|low_ttl|recache_rate|compact_under|drop_under|max_frag|drop_unread [value]`.

Ограничение: `append`/`prepend` не работают для объектов на диске (ответ `NOT_STORED`).

### Встроенный прокси (mcp)

**Встроенный прокси** (memcached proxy, «mcp») — прокси-движок на **Lua 5.4** для управления кластерами memcached. Это не отдельный бинарник, но и не включён «из коробки»: требуется **memcached 1.6.23+** и сборка `./configure --enable-proxy`.

- Включение: `-o proxy_config=routelib,proxy_arg=config.lua` (routelib — встроенная библиотека маршрутов; совместимые/кастомные — в репозитории memcached-proxylibs).
- Конфигурация описывает `pools{...}` (backend-пулы) и `routes{...}` (маршрутизация, например `route_direct{child="pool"}`).
- Архитектура: отдельный поток компилирует конфиг; **каждый worker thread получает собственную Lua VM** (данные между VM не разделяются); Lua-корутины позволяют процедурный стиль.
- Возможности: маршрутизация по пулам с fallback, переопределение команд, «встроенный в прокси» memcached, pluggable-хеширование ключей, снижение числа соединений к backend, shadow-копирование трафика через хуки (`mcp.attach(mcp.CMD_GET, ...)`).
- **SIGHUP** — горячая перезагрузка конфига без прерывания активного трафика.
- Диагностика: `stats proxy` (счётчики `vm_gc_runs`, `vm_memory_kb`), `watch proxyreqs|proxyevents|proxyuser`.
- TLS для backend-пулов — experimental (с 1.6.28).

## Предварительные требования

- ОС: Linux (Ubuntu 24.04 / Debian / RHEL-подобные), BSD; сборка из исходников — `libevent-dev` (Debian/Ubuntu) или `libevent-devel` (RHEL).
- Права: root для установки пакета; сам демон работает от непривилегированного пользователя (`-u memcache`, только при запуске от root).
- Сеть: выделенный внутренний интерфейс или unix-сокет; memcached **не должен быть доступен из интернета или недоверенным пользователям** (официальная позиция проекта).
- Ресурсы: RAM под `-m` + запас на ОС. `-m` — не глобальный лимит памяти (memcached использует чуть больше: метаданные, соединения); значения < 64 МБ всё равно дают минимум 64 МБ.

## Практические сценарии

### Установка и базовая настройка (Ubuntu 24.04 / Debian)

```bash
sudo apt update && sudo apt install -y memcached

# /etc/memcached.conf (Debian/Ubuntu; на RHEL — /etc/sysconfig/memcached: PORT/USER/MAXCONN/CACHESIZE/OPTIONS)
-m 4096        # 4 ГБ под объекты (не глобальный лимит RSS)
-l 127.0.0.1   # только локальный интерфейс; для доступа по сети — внутренний IP
-U 0           # UDP выключен (default с 1.5.6; включать только если нужен)
-c 2048        # макс. соединений
-t 8           # потоки ≈ числу ядер

sudo systemctl restart memcached

# Проверить, что конфиг применился:
echo "stats settings" | nc 127.0.0.1 11211 | egrep "maxbytes|maxconns|num_threads|udpport"
# → STAT maxbytes 4294967296
# → STAT maxconns 2048
# → STAT num_threads 8
# → STAT udpport 0
```

Изменения без правки unit-файла: `sudo systemctl edit memcached` (drop-in). Перезапуск — `systemctl restart memcached`; кэш при этом теряется (персистентности нет).

### Тюнинг Slab-аллокатора

Много мелких объектов — уменьшите фактор роста для экономии памяти:
```bash
memcached -m 2048 -f 1.1 -n 48
```
- `-f 1.1`: чанки растут медленнее, размеры классов ближе друг к другу (меньше внутренней фрагментации, больше классов).
- `-n 48`: минимальный размер чанка 48 байт (ключ + значение + флаги).
- `-I 5m`: лимит размера значения 5 МБ (по умолчанию 1 МБ; макс. 1G).
- `-o slab_automove`: автоматическая балансировка страниц между классами (тюнинги: `slab_automove_ratio`, `slab_automove_window`).
- Ручное перемещение страницы на лету: `slabs reassign <src_slab> <dst_slab>`.

### Extstore (SSD-кэш)

```bash
memcached -m 2048 -o ext_path=/mnt/nvme/memc_store:500G,ext_wbuf_size=32,ext_threads=4,ext_item_size=1024
```
- `ext_path=<путь>:<размер>`: файл/устройство под хранилище (суффиксы K/M/G).
- `ext_item_size=1024`: объекты крупнее 1 КБ выносятся на диск (default 512).
- `ext_wbuf_size=32`: write-буфер 32 МБ (default 8M; не может превышать `ext_page_size`).
- `ext_threads=4`: потоки записи (default 1; держите низкими, ≤ 8).

### Встроенный прокси (mcp)

```bash
# Сборка (требуется 1.6.23+):
./configure --enable-proxy && make && sudo make install

# config.lua
cat > config.lua <<'EOF'
pools{
  quickstart_pool = { backends = { "127.0.0.1:11212" } },
  fallback        = { backends = { "127.0.0.1:11213" } },
}
routes{
  map = { quickstart = route_direct{ child = "quickstart_pool" } },
  default = route_direct{ child = "fallback" },
}
EOF

# Запуск прокси на 11211, бэкенды — на 11212/11213:
./memcached -l 127.0.0.1 -p 11211 -o proxy_config=routelib,proxy_arg=config.lua
```

### Мониторинг и диагностика

1. **memcached-tool** (Perl-скрипт из комплекта):
   ```bash
   memcached-tool localhost:11211 display   # slab-классы (режим по умолчанию)
   memcached-tool localhost:11211 stats     # общая статистика
   memcached-tool localhost:11211 settings  # применённые настройки
   memcached-tool localhost:11211 keys -u   # дамп ключей (-u: unescape)
   ```
   `sizes` и `dump` — development-команды: при миллионах ключей могут «залочить» инстанс на минуты — не используйте в production (можно отключить: `-X`).
2. **Прямой протокол:**
   ```bash
   echo "stats" | nc 127.0.0.1 11211        # общие счётчики
   echo "stats slabs" | nc 127.0.0.1 11211  # страницы/чанки по классам
   echo "stats items" | nc 127.0.0.1 11211  # вытеснения по классам
   ```
3. **Hit Rate:** `get_hits / cmd_get` — ключевой показатель эффективности кэша.
4. **Вытеснения:** `evictions` в `stats`; детализация — `evicted`, `evicted_nonzero`, `evicted_unfetched`, `evicted_active` в `stats items` (по slab-классам).
5. **Переполнение соединений:** `listen_disabled_num` в `stats` — должно быть 0 или близко к 0.
6. Для Prometheus — `memcached_exporter` (prometheus/memcached_exporter).

## Безопасность

1. **UDP:** выключен по умолчанию с **1.5.6** (CVE-2018-1000115 — amplification-атаки). Не включайте (`-U 11211`) без необходимости; UDP полезен только для маленьких объектов.
2. **Сетевая изоляция:** биндинг на внутренний интерфейс (`-l 10.0.5.20`) или unix-сокет (`-s /run/memcached.sock` — отключает TCP/UDP полностью; права через `-a` в octal). Дополнительно — `iptables`/`nftables` на уровне хоста.
3. **TLS** (с 1.5.13): сборка `./configure --enable-tls`, OpenSSL ≥ 1.1.1; параметры `-o ssl_chain_cert=/path/cert.pem,ssl_key=/path/key.pem` (обязательны), опционально `ssl_ca`, `ssl_verify`, `ssl_ciphers`. Перезагрузка сертификатов — командой `refresh_certs` или SIGHUP (без разрыва соединений). kTLS-оффлоад: OpenSSL 3.0+ с `enable-ktls`, ядро Linux 4.17+ с `CONFIG_TLS`.
4. **SASL:** `-S` включает аутентификацию (только если сборка с SASL-поддержкой, `--enable-sasl`). На Debian/Ubuntu: `apt install sasl2-bin`, `/etc/sasl2/memcached.conf` (`mech_list: plain`), пользователь — `saslpasswd2 -a memcached -c -f /etc/sasl2/memcached-sasldb2 <user>`, владелец БД — `memcache:memcache`. Нужен `cyrus-sasl-plain` (предоставляет `libplain.so`).
5. **Отключение опасных команд:** `-F` (запрет `flush_all`), `-X` (запрет `stats cachedump` и `lru_crawler metadump`), `shutdown` отключён по умолчанию (включается `-A`).
6. **Согласованное хеширование (consistent hashing, ketama):** на стороне клиента (libmemcached и др.) — минимизирует потерю кэша при добавлении/удалении узлов.

## Валидация конфигурации (сводная таблица)

| Что проверить | Команда | Ожидание |
|---|---|---|
| Применился ли `-m` | `echo "stats settings" \| nc ... \| grep limit_maxbytes` | `STAT limit_maxbytes <байты>` = `-m` × 1024² |
| Порт/UDP | `stats settings` → `tcpport`, `udpport` | `udpport 0` (UDP off) |
| Потоки/соединения | `stats settings` → `num_threads`, `maxconns` | совпадают с `-t`/`-c` |
| Версия | `echo "version" \| nc ...` | `VERSION 1.6.x` |
| Вытеснения | `echo "stats" \| nc ... \| grep evictions` | `evictions` не растёт |
| Переполнение коннектов | `stats` → `listen_disabled_num` | `0` |
| Slab-баланс | `stats slabs` (total_pages) vs `stats items` (evicted) | вытеснения не сконцентрированы в одном классе |

## Troubleshooting

1. **Slab calcification (дисбаланс классов):** память распределена не под тот профиль данных. Диагностика: `evicted`/`evicted_nonzero` по классам (`stats items`) не коррелируют с `total_pages` (`stats slabs`). Решение: `-o slab_automove`, `slabs reassign`, либо рестарт для перераспределения (кэш при этом сбрасывается).
2. **Низкий Hit Rate:** нехватка памяти (`evictions` растёт) или «вымывание» разовыми запросами. Решение: увеличить `-m`, включить Extstore, проверить TTL и SLRU-распределение (`stats items` → `number_hot/warm/cold`).
3. **Клиенты «зависают» на подключении:** исчерпан `-c`. Признак: `listen_disabled_num > 0`. Решение: поднять `-c`, проверить пулинг соединений в клиентах.
4. **Таймауты клиентов:** медленные бэкенды, сетевая деградация или latency Extstore (диск). Проверяйте `rusage_user`/`rusage_system` и `bytes_read/written`.
5. **Ключ мгновенно «протухает»:** TTL > 2592000 интерпретирован как Unix-timestamp в прошлом. Используйте секунды (≤ 30 дней) или корректный timestamp.
6. **`append`/`prepend` возвращает `NOT_STORED`:** объект вынесен на Extstore — операции конкатенации для таких объектов не поддерживаются.
7. **Инстанс «замирает» на минуты:** выполнили `sizes`/`stats cachedump`/`lru_crawler metadump` на большом кэше. Отключите их на проде: `-X`.

## Best Practices и откат изменений

1. **Не экспонировать наружу:** только внутренний интерфейс/unix-сокет + firewall; UDP держать выключенным.
2. **Разделение инстансов:** отдельный memcached для кэша (допустимо вытеснение) и для сессий/критичных данных (`-M` — отказ от вытеснения: при нехватке памяти записи возвращают ошибку вместо удаления старых).
3. **Тюнинг потоков:** `-t` ≈ числу ядер; 64+ не рекомендуются.
4. **Экономия памяти:** `-C` отключает CAS (экономия 8 байт на объект, если CAS не используется); `-o no_inline_ascii_resp` — 24 байта на объект (малый штраф в ASCII-протоколе).
5. **`-k` (lock memory)** — фиксирует страницы в RAM (mlock); с большими кэшами — опасно, читайте README.
6. **Откат:** вся конфигурация — command-line/файл конфига systemd-юнита. Откат = возврат `/etc/memcached.conf` (или drop-in `systemctl edit`) + `systemctl restart memcached`. Данные не сохраняются — после любого рестарта кэш холодный, приложение должно корректно обрабатывать промахи.

## Дополнительная информация

### Чек-лист безопасности (Production Readiness)

- [ ] UDP выключен (`-U 0` / default)
- [ ] Биндинг на внутренний IP или unix-сокет; нет доступа из интернета
- [ ] `-F` и `-X` включены на проде (запрет `flush_all` и дампов)
- [ ] TLS/SASL при доступе нескольких команд/тенантов
- [ ] `listen_disabled_num` = 0, `evictions` не растёт, hit rate в норме
- [ ] Мониторинг: hit rate, evictions, `listen_disabled_num`, latency
