# Memcached

## Определения

**Memcached** — это высокопроизводительная распределённая система кеширования объектов в оперативной памяти. Она предназначена для ускорения динамических веб-приложений путём снижения нагрузки на базу данных.

**Текущая версия:** Memcached 1.6.41 (март 2026).

Memcached представляет собой простое хранилище типа «ключ-значение», оптимизированное для максимальной скорости операций чтения и записи.

## Основные концепции

### Модель данных

Memcached — хранилище типа «ключ-значение»:

- **Ключ:** строка до 250 байт.
- **Значение:** непрозрачный массив байт (blob) размером до 1 МБ.
- **Метаданные:** TTL (Time-To-Live), флаги (для клиентской сериализации), CAS-токен.

Сервер не интерпретирует формат значений. Сложные структуры данных (JSON, объекты) требуют сериализации и десериализации на стороне клиента.

**Основные команды:**

- `get` — получение значения по ключу.
- `set` — сохранение значения.
- `delete` — удаление ключа.
- `incr`/`decr` — атомарное увеличение или уменьшение числового значения.
- `cas` (Check-And-Set) — атомарная запись с проверкой версии.

### Управление памятью: Slab Allocator

Memcached использует **Slab Allocator** (аллокатор слабов) для эффективного управления оперативной памятью:

1. **Слабы (Slabs):** память предварительно разбивается на страницы по 1 МБ.
2. **Чанки (Chunks):** каждый Slab нарезается на чанки фиксированных размеров.
3. **Классы размеров:** чанки группируются в классы (например, 64 байт, 128 байт, 256 байт и так далее до 1 МБ).
4. **Распределение:** каждый объект помещается в чанк наиболее подходящего размера.

**Преимущества:**

- Снижение фрагментации памяти.
- Быстрое выделение и освобождение памяти.
- Предсказуемое использование ресурсов.

**Недостатки:**

- Неэффективное использование пространства при плохом соответствии размеров объектов классам чанков.
- Возможна ситуация, когда есть свободная память, но нет чанков подходящего размера в конкретном классе.

### Время жизни и старение данных

**TTL (Time-To-Live)** задаётся для каждого элемента при сохранении:

- **Ленивое истечение:** ключи удаляются при попытке доступа к ним.
- **Фоновый crawler:** периодически обходит элементы и удаляет просроченные.
- **Интерпретация TTL:** значение более 30 дней (2 592 000 секунд) трактуется как абсолютное Unix-время (метка времени), меньшее значение — как относительное время в секундах от текущего момента.

### Политика вытеснения: LRU

При заполнении памяти Memcached вытесняет данные по алгоритму **LRU (Least Recently Used — наиболее давно использованный)**:

- Вытесняется элемент, к которому дольше всего не обращались.
- LRU реализуется отдельно для каждого slab-класса.
- Начиная с версии 1.4.8 доступен улучшенный **Segmented LRU**:
  - `lru_maintainer` — отдельный поток для управления LRU.
  - `lru_crawler` — фоновое удаление просроченных ключей.

Подробнее о политиках вытеснения: **[Политики вытеснения в кэше](../Concepts/Caching/caching_eviction_policies.md)**.

### Сохранность данных

Memcached **не поддерживает персистентность** (сохранение на диск):

- После перезапуска сервер стартует с пустым кешем.
- Спроектирован как временное энергозависимое хранилище.
- Для сохранения данных требуется внешнее постоянное хранилище (например, реляционная база данных).

### Масштабирование и консистентность

**Горизонтальное масштабирование:**

- Осуществляется через **шардирование на стороне клиента**.
- Используется **согласованное хеширование (consistent hashing)**.
- Добавление или удаление серверов минимально перестраивает кеш.

**Архитектурные особенности:**

- Серверы независимы друг от друга.
- Нет обмена данными между узлами кластера.
- Встроенная репликация отсутствует.
- Клиент отвечает за выбор сервера для каждого конкретного ключа.

### Многопоточность

Memcached является многопоточным приложением:

- Эффективно утилизирует многоядерные центральные процессоры (CPU).
- Обеспечивает параллельную обработку запросов.
- Имеет низкую латентность благодаря минималистичной семантике операций.

## Практические сценарии

### Когда использовать Memcached

**Идеальные сценарии:**

- **Кеширование HTML-страниц:** сохранение отрендеренных фрагментов страниц.
- **Кеширование запросов к базе данных:** результаты тяжелых SQL-запросов.
- **Кеширование ответов API:** ответы внешних сервисов.
- **Хранение сессий:** временные данные пользовательских сессий.
- **Простые счетчики:** атомарное увеличение или уменьшение значений (например, просмотры страниц).

**Требования для выбора Memcached:**

- Максимальная производительность на простых операциях ключ-значение.
- Эффективное использование многоядерных процессоров.
- Простота развертывания и эксплуатации.
- Не требуется сохранение данных после перезапуска.

### Когда НЕ использовать Memcached

- **Сложные структуры данных:** если требуется поддержка хэшей, списков или множеств (рекомендуется Redis).
- **Персистентность:** если нужна сохранность данных после перезагрузки сервера.
- **Pub/Sub (Publish/Subscribe):** если требуется механизм издатель-подписчик.
- **Очереди задач:** если нужна полноценная очередь с приоритетами.
- **Геоданные:** если требуется пространственная индексация.

### Пример: кеширование запроса к базе данных

```python
import memcache
import json

# Подключение к кластеру Memcached
mc = memcache.Client(['192.168.1.10:11211', '192.168.1.11:11211'])

def get_user_profile(user_id):
    cache_key = f"user_profile:{user_id}"
    
    # Попытка получить данные из кеша
    data = mc.get(cache_key)
    if data:
        return json.loads(data)
    
    # Запрос к БД (cache miss)
    user_data = db.query("SELECT * FROM users WHERE id = ?", user_id)
    
    # Сохранение в кеш на 1 час
    mc.set(cache_key, json.dumps(user_data), time=3600)
    
    return user_data
```

### Пример: атомарное увеличение счетчика

```bash
# Увеличение счетчика на 1
incr page_views:article:123 1

# Увеличение на 5
incr page_views:article:123 5

# Если ключ не существует, можно задать начальное значение (в некоторых клиентах)
```

### Пример: CAS для предотвращения состояния гонки

```python
# Получение значения вместе с CAS-токеном
value, cas_id = mc.gets("counter")

# Атомарное обновление с проверкой версии
new_value = int(value) + 1
mc.cas("counter", new_value, cas_id)
```
