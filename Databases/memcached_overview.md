# Memcached — обзор

## Определения

**Memcached** — это высокопроизводительная распределённая система кеширования объектов в оперативной памяти. Она спроектирована для ускорения динамических веб-приложений путём снижения нагрузки на основные базы данных.

**Текущее состояние (2026):** Memcached 1.6.x является стандартом для высоконагруженных систем, требующих минимальных задержек и максимальной пропускной способности. В отличие от Redis, Memcached ориентирован на простоту и экстремальную многопоточность.

**Лицензия:** BSD (полностью открытый исходный код, отсутствие лицензионных рисков).

## Основные концепции

### Архитектура и управление памятью: Slab Allocator

Memcached использует **Slab Allocator** для полного исключения фрагментации памяти, характерной для стандартного `malloc`.

1.  **Слабы (Slabs):** Вся выделенная память (`-m`) разбивается на страницы по 1 МБ.
2.  **Классы размеров (Slab Classes):** Страницы нарезаются на чанки фиксированных размеров. Разница между размерами чанков определяется фактором роста (`-f`, по умолчанию 1.25).
3.  **Размещение:** Объект сохраняется в чанк ближайшего подходящего размера.
    *   *Проблема:* Внутренняя фрагментация (объект 65Б в чанке 128Б оставляет 63Б неиспользуемыми).
    *   *Решение:* Тюнинг `-f` (factor) и `-n` (min chunk size) под конкретный профиль данных.

### Мета-протокол (Meta-protocol v2)

В версии 1.6+ представлен мета-протокол, который заменяет старые Text и Binary протоколы, предлагая более высокую эффективность и расширяемость.

**Ключевые команды:**
- `mg` (Meta Get): Получение данных с возможностью возврата CAS, TTL, флагов и атомарного обновления TTL.
- `ms` (Meta Set): Сохранение данных с поддержкой условной записи (CAS) и возвратом новых метаданных.
- `md` (Meta Delete): Удаление с поддержкой инвалидации по CAS.
- `mn` (Meta No-op): Проверка связи.

**Преимущества:** Позволяет выполнять сложные атомарные операции (например, "получить значение и обновить TTL") за один сетевой раунд, что критично для производительности.

### Внешнее хранилище (Extstore)

Механизм **Extstore** позволяет кешировать объемы данных, значительно превышающие доступную RAM, за счет использования быстрых дисков (NVMe/SSD).
- **Метаданные (ключи, заголовки):** Всегда остаются в RAM для мгновенного поиска.
- **Данные (тела объектов):** "Холодные" или крупные объекты сбрасываются на диск.
- **TCO:** Позволяет хранить терабайты кэша на порядок дешевле, чем при использовании чистой оперативной памяти.

### Прокси-слой (mcp - Memcached Proxy)

Встроенный прокси-движок на базе **Lua** позволяет реализовывать сложную логику на стороне сервера:
- **Шардирование:** Распределение ключей по пулам серверов.
- **Shadow Reads/Writes:** Копирование трафика на тестовые инстансы.
- **Pool Failover:** Автоматическое переключение на резервный пул при сбоях.

### Вытеснение данных: Segmented LRU

Memcached использует сегментированный LRU для защиты "горячих" данных:
- **TEMP:** Объекты с TTL < 61с. Никогда не перемещаются в другие очереди.
- **HOT:** Новые объекты. При заполнении вытесняются в WARM или COLD.
- **WARM:** Объекты, к которым обратились повторно. "Защищенная" зона.
- **COLD:** Кандидаты на удаление.

Эта архитектура предотвращает "вымывание" полезного кэша массовыми разовыми запросами (например, при сканировании БД).

## Практические сценарии

### Установка и базовая настройка (Ubuntu 24.04)

```bash
sudo apt update && sudo apt install -y memcached

# Настройка в /etc/memcached.conf
# -m 4096 (4 ГБ RAM)
# -l 127.0.0.1 (только локальный интерфейс для безопасности)
# -c 2048 (макс. количество соединений)
# -t 8 (количество потоков, обычно равно числу ядер)

sudo systemctl restart memcached
```

### Тюнинг Slab-аллокатора

Если вы храните много мелких объектов, уменьшите фактор роста для экономии памяти:
```bash
memcached -m 2048 -f 1.1 -n 48
```
- `-f 1.1`: Чанки растут медленнее, размеры классов ближе друг к другу.
- `-n 48`: Минимальный размер чанка 48 байт.

### Настройка Extstore (SSD кэш)

Использование NVMe диска для хранения 500 ГБ данных:
```bash
memcached -m 2048 -o ext_path=/mnt/nvme/memc_store:500G,ext_wbuf_size=16,ext_threads=8,ext_item_size=1024
```
- `ext_item_size=1024`: Объекты больше 1 КБ будут выноситься на диск.

### Мониторинг и диагностика

1.  **memcached-tool:** Утилита для быстрого осмотра состояния.
    ```bash
    memcached-tool localhost:11211 display  # Просмотр slab-классов
    memcached-tool localhost:11211 stats    # Общая статистика
    ```
2.  **Анализ попаданий (Hit Rate):**
    `get_hits / (get_hits + get_misses)` — ключевой показатель эффективности кэша.
3.  **Анализ вытеснений (Evictions):** Если `evictions > 0`, значит памяти недостаточно и старые данные удаляются принудительно.

## Безопасность и Best Practices 2026

1.  **UDP Amplification:** По умолчанию Memcached может слушать UDP порт 11211. Это вектор для разрушительных DDoS-атак.
    *   *Действие:* Всегда отключайте UDP (`-U 0`) в публичных сетях.
2.  **Сетевая изоляция:** Используйте частные сети (VPC) и `iptables` для ограничения доступа.
3.  **SASL:** Для сред с несколькими пользователями включайте аутентификацию `-S`.
4.  **Согласованное хеширование (Consistent Hashing):** На стороне клиента (например, в библиотеке `libmemcached` или `ketama`) всегда используйте согласованное хеширование. Это минимизирует потерю кэша при добавлении или удалении узлов в кластере.
