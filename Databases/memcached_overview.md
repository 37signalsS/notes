# Memcached

## Определения

**Memcached** — это высокопроизводительная распределённая система кеширования объектов в оперативной памяти. Она предназначена для ускорения динамических веб-приложений путём снижения нагрузки на базу данных. Memcached представляет собой простое хранилище типа «ключ-значение».

## Основные концепции

### Модель данных

Memcached — это простое хранилище типа «ключ-значение», где ключ — это строка, а значение — непрозрачный массив байт (`blob`) размером до 1 МБ. Сервер не интерпретирует формат значений; любые сложные структуры данных (например, JSON, объекты) требуют сериализации и десериализации на стороне клиента.

### Управление памятью

Memcached использует **slab-аллокатор**:

- Память предварительно разбивается на «слабы» (`slabs`) — страницы памяти (по 1 МБ), которые нарезаются на чанки (`chunks`) фиксированных размеров.
- Каждый объект помещается в чанк подходящего размера.
- Это снижает фрагментацию и делает выделение/освобождение памяти очень быстрым, но может приводить к неэффективному использованию пространства, если размер объекта плохо соответствует размеру чанка.
- Вытеснение происходит по алгоритму **LRU (Least Recently Used)** для каждого slab-класса.

### TTL (Time-To-Live) и старение данных

- TTL задается для каждого элемента при его сохранении.
- Истечение ключей происходит **лениво** (при попытке доступа к ним).
- Фоновый процесс (`crawler`) периодически обходит элементы и удаляет просроченные, освобождая память.
- Значение TTL, превышающее 30 дней (60*60*24*30), интерпретируется как абсолютное Unix-время истечения.

### Устойчивость (Персистентность)

Memcached **не поддерживает персистентность** по своей природе. После перезапуска сервер стартует с пустым кешем. Он спроектирован как временное, энергозависимое хранилище.

### Масштабирование и консистентность

- Масштабирование Memcached осуществляется горизонтально через **шардирование на стороне клиента**.
- Как правило, для этого используется **согласованное хеширование (consistent hashing)**, что позволяет добавлять и удалять серверы с минимальной перестройкой кеша.
- Серверы Memcached независимы друг от друга и не обмениваются данными. Встроенные механизмы репликации отсутствуют.

## Практические сценарии

- **Многопоточность:** Memcached является многопоточным, что позволяет эффективно утилизировать многоядерные процессоры для обработки параллельных запросов.
- **Низкая латентность:** Благодаря минималистичной семантике операций (`get`, `set`, `delete`) достигается крайне низкая задержка.
- **Атомарные операции:** Поддерживает операцию **CAS (Check-And-Set)** для предотвращения «состояния гонки» при конкурентной записи, что позволяет реализовать оптимистичные блокировки.

Основные сценарии использования:

- **Кеширование вывода HTML-страниц.**
- **Кеширование результатов запросов к базам данных и API.**
- **Хранение сессий.**

Memcached идеален для простых сценариев кеширования, где требуется максимальная скорость и минимальные накладные расходы.
