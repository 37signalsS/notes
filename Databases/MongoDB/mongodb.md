# Обзор MongoDB

## Определения

**MongoDB** — высокопроизводительная документо-ориентированная NoSQL СУБД с открытым исходным кодом. Относится к семейству **Document Stores**. В контексте теоремы CAP классифицируется как **CP** (Consistency/Partition Tolerance).

- **Версия:** Актуальная стабильная ветка в 2026 году — **8.0+**. Устаревшая оболочка `mongo` полностью удалена, основным инструментом администрирования является **`mongosh`**.
- **BSON (Binary JSON):** Бинарный формат хранения, расширяющий JSON поддержкой типов `ObjectId`, `Date`, `BinData`, `Decimal128`.
- **Документ:** Основная единица записи. Максимальный размер — **16 МБ**. Для работы с более крупными файлами (видео, образы) используется спецификация **GridFS**.
- **Коллекция:** Группировка документов. Не требует жесткой схемы (Dynamic Schema), что позволяет документам в одной коллекции иметь разный набор полей.

## Базовые концепции

### Модель данных

- **Вложенность (Embedding):** Хранение связанных данных внутри одного документа. Рекомендуется для связей «один-к-одному» и «один-ко-многим», если данные часто читаются вместе.
- **Ссылки (Referencing):** Хранение `_id` другого документа. Используется для предотвращения чрезмерного раздувания документов или для связей «многие-ко-многим».

### Механизмы хранения (WiredTiger)

Основной движок с версии 3.2.

- **WiredTiger Cache:** По умолчанию занимает **50% доступной RAM минус 1 ГБ**. Это критично для планирования ресурсов в контейнерах.
- **Параллелизм:** Блокировки на уровне документа (Document-level locking).
- **Сжатие:** Алгоритмы `snappy` (по умолчанию), `zlib` или `zstd` для данных и префиксное сжатие для индексов.
- **Журналирование (Journaling):** Запись операций в журнал перед фиксацией в файлах данных для обеспечения устойчивости (Durability).

### Индексы

Подробная теория: **[Индексы баз данных](../Concepts/indexes.md)**.

- **_id Index:** Уникальный индекс, создаваемый автоматически.
- **Compound Index:** Индекс по нескольким полям. Важен порядок полей (правило **ESR**: Equality, Sort, Range).
- **Multikey Index:** Индекс для индексации содержимого массивов.
- **TTL Index:** Автоматическое удаление документов по истечении времени.
- **Hashed Index:** Используется для равномерного распределения данных при шардировании.

### Агрегация (Aggregation Framework)

Мощный инструмент обработки данных, работающий по принципу конвейера (Pipeline). Данные проходят через последовательность стадий, каждая из которых преобразует набор документов.

**Основные стадии ($stages):**
- **`$match`:** Фильтрация документов (аналог `WHERE`). Должна идти первой для использования индексов.
- **`$project`:** Изменение формы документа, добавление или удаление полей.
- **`$group`:** Группировка документов по ключу и выполнение агрегатных функций (`$sum`, `$avg`, `$push`).
- **`$sort`:** Сортировка результатов.
- **`$limit` / `$skip`:** Пагинация.
- **`$lookup`:** Выполнение левого внешнего соединения (аналог `LEFT JOIN`) с другой коллекцией.
- **`$unwind`:** Развертывание массива в отдельные документы для последующей обработки.

### Репликация (Replica Set)

Обеспечивает высокую доступность. Подробная теория: **[Репликация](../Concepts/replication.md)**.

- **Primary:** Узел, принимающий записи.
- **Secondary:** Узлы, реплицирующие **oplog** (operations log).
- **Arbiter:** Узел для голосования, не хранящий данные.
- **Write Concern (`w`):** Гарантия записи (напр., `w: "majority"` требует подтверждения от большинства узлов).
- **Read Concern:** Уровень изоляции чтения (напр., `majority` гарантирует чтение только подтвержденных данных).

### Шардирование (Sharding)

Горизонтальное масштабирование. Подробная теория: **[Шардирование](../Concepts/sharding.md)**.

- **Shard Key:** Поле, по которому данные делятся на части (chunks).
- **`mongos`:** Маршрутизатор запросов.
- **Config Servers:** Хранение метаданных кластера.

### Транзакции (ACID)

Поддержка многодокументных транзакций в Replica Set (4.0+) и Sharded Cluster (4.2+).
- Гарантируют атомарность для набора операций в разных коллекциях или базах.
- Используют Snapshot Isolation.

### Безопасность

- **RBAC:** Ролевая модель (роли `read`, `readWrite`, `dbAdmin`, `root`).
- **Аутентификация:** SCRAM-SHA-256 (стандарт), x.509, LDAP.
- **TLS/SSL:** Обязательно для защиты трафика между узлами и клиентами.
- **Encryption at Rest:** Шифрование данных на диске (Enterprise).

## Практические сценарии

### Когда использовать MongoDB
- Гибкие структуры данных (каталоги, профили).
- Высокая нагрузка на запись.
- Необходимость легкого горизонтального масштабирования.
- Аналитика реального времени через Aggregation Pipeline.

### Антипаттерны и "Белые пятна"
- **Толстые документы (Fat Documents):** Хранение огромных массивов внутри одного документа приводит к деградации производительности при частичных обновлениях.
- **Глубокая вложенность:** Затрудняет написание запросов и использование индексов.
- **Отсутствие индексов:** Приводит к полному сканированию коллекции (**COLLSCAN**), что парализует БД при больших объемах данных.
- **Заупотребление транзакциями:** Транзакции в MongoDB имеют накладные расходы. Если вам нужны транзакции для каждого запроса — возможно, вам нужна реляционная БД.

### Эксплуатация и отладка
- **`db.currentOp()`:** Просмотр текущих операций.
- **`db.explain("executionStats")`:** Анализ плана выполнения запроса и эффективности индексов.
- **`mongosh`:** Использование JavaScript для автоматизации административных задач.
