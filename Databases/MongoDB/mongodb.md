# Обзор MongoDB

## Определения

**MongoDB** — высокопроизводительная документо-ориентированная NoSQL СУБД с открытым исходным кодом. Она относится к системам типа **CP** (Consistency/Partition Tolerance) по теореме CAP.

- **BSON (Binary JSON):** Формат хранения данных, расширяющий JSON поддержкой дополнительных типов данных (например, `Date`, `BinData`).
- **Документ:** Основная единица записи данных в формате BSON. Аналог строки в реляционных БД.
- **Коллекция:** Группировка документов, имеющих общую тематику, но не обязательно идентичную структуру. Аналог таблицы.

## Базовые концепции

### Модель данных

- **Гибкая схема (Dynamic Schema):** Документы в одной коллекции могут иметь разные наборы полей. Это упрощает итеративную разработку и миграции.
- **Вложенность (Embedding):** Возможность хранить связанные данные (массивы, подобъекты) внутри одного документа. Позволяет избегать ресурсоемких операций `JOIN`.
- **Ссылки (Referencing):** Хранение идентификаторов (`_id`) документов из других коллекций для моделирования связей «многие ко многим».

### Механизмы хранения (WiredTiger)

С версии 3.2 основным движком хранения является **WiredTiger**.

- **Уровень документов (Document-level Concurrency):** Поддержка параллельной записи на уровне отдельных документов.
- **Сжатие:** Использование алгоритмов Snappy или Zlib для уменьшения объема данных на диске.
- **Журналирование (Journaling):** Обеспечивает устойчивость данных (Durability) при сбоях, записывая операции в журнал перед фиксацией на диске.

### Индексы

Индексы в MongoDB критически важны для производительности запросов. Подробная теория: **[Индексы баз данных](../Concepts/indexes.md)**.

- **_id Index:** Уникальный индекс на поле `_id`, создается автоматически.
- **Single Field:** Индекс по одному полю.
- **Compound Index:** Индекс по нескольким полям (важен порядок полей).
- **Multikey Index:** Индекс по полям, содержащим массивы.
- **TTL Index:** Автоматическое удаление документов через определенное время (удобно для логов и кэшей).
- **Hashed Index:** Используется для равномерного распределения данных при шардировании.

### Агрегация (Aggregation Framework)

Мощный инструмент обработки данных, работающий по принципу конвейера (Pipeline).

- **Стадии ($stages):** Операции, через которые проходят данные (`$match` → `$group` → `$project` → `$sort` → `$limit`).
- **Вычислительная мощность:** Позволяет выполнять сложные преобразования и аналитику непосредственно на стороне сервера БД.

### Транзакции

С версии 4.0 MongoDB поддерживает многодокументные **ACID-транзакции**. Общая концепция: **[ACID](../Concepts/acid.md)**.

- **Scope:** Сначала появились для Replica Set (4.0), затем для Sharded Cluster (4.2).
- **Snapshot Isolation:** Гарантирует согласованное представление данных внутри транзакции.

### Репликация (Replica Set)

**Replica Set** — группа узлов, обеспечивающая высокую доступность и отказоустойчивость. Подробная теория: **[Репликация](../Concepts/replication.md)**.

- **Primary:** Единственный узел, принимающий все операции записи.
- **Secondary:** Узлы, реплицирующие **oplog** (operations log) с primary. Могут обслуживать запросы на чтение.
- **Arbiter:** Узел, участвующий только в выборах (Elections) и не хранящий данных.
- **Failover:** Автоматическое переключение на новый primary при недоступности текущего.

### Шардирование (Sharding)

Метод горизонтального масштабирования путем распределения данных по нескольким серверам. Подробная теория: **[Шардирование](../Concepts/sharding.md)**.

- **Shard:** Отдельный сервер или Replica Set, хранящий часть данных.
- **Config Servers:** Хранят метаданные о распределении данных.
- **`mongos` (Query Router):** Маршрутизатор, направляющий запросы приложений на нужные шарды.
- **Shard Key:** Поле, по которому данные разбиваются на сегменты (chunks). Правильный выбор ключа критичен для балансировки нагрузки.

### Безопасность

Общие принципы защиты и "закалки" сервера описаны в руководстве **[Безопасная установка СУБД](../installation_security.md)**.

- **RBAC (Role-Based Access Control):** Разграничение доступа на основе ролей (read, readWrite, dbAdmin и др.).
- **Аутентификация:** Поддержка SCRAM (по умолчанию), x.509, LDAP, Kerberos.
- **Шифрование:** TLS/SSL для трафика и шифрование данных «в покое» (Encryption at Rest) в Enterprise-версии.

## Эксплуатация

### Системные требования и мониторинг

- **RAM:** MongoDB активно использует оперативную память для хранения WiredTiger Cache (по умолчанию 50% доступной RAM минус 1 ГБ).
- **Диск:** Требуются быстрые SSD для обеспечения низкого latency на запись.
- **Мониторинг:** Рекомендуется использовать `mongodb_exporter` для интеграции с **[Prometheus](../../Prometheus/Exporters/other_exporters.md)**.

### Основные утилиты

- **`mongosh`:** Современная командная оболочка (заменила устаревший `mongo` shell).
- **`mongodump` / `mongorestore`:** Создание и восстановление бинарных бэкапов.
- **`mongoexport` / `mongoimport`:** Экспорт/импорт данных в форматах JSON/CSV.

## Практические сценарии

- **Быстрая разработка (Rapid Prototyping):** Идеально для проектов с часто меняющейся структурой данных.
- **Каталоги товаров:** Хранение товаров с произвольными наборами атрибутов.
- **Content Management Systems (CMS):** Обработка статей, блогов, комментариев и профилей пользователей.
- **Аналитика реального времени:** Сбор и агрегация метрик/логов через Aggregation Pipeline.
- **IoT и Big Data:** Хранение огромных массивов слабоструктурированных данных.
