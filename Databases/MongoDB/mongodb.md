# MongoDB

## Определения

**MongoDB** — документо-ориентированная NoSQL СУБД. Хранит данные в гибких JSON-подобных документах (BSON).

- **Документ:** Основная единица данных. BSON-структура (Binary JSON), аналог строки в реляционной БД.
- **Коллекция:** Группа документов без строгой схемы, аналог таблицы.

## Основные концепции

### Модель данных

- **Гибкая схема:** Документы в коллекции могут иметь разную структуру.
- **Вложенные документы и массивы:** Моделирование сложных иерархий в одном документе без `JOIN`.

### Репликация (Replica Set)

**Replica Set** — группа процессов `mongod` с идентичными данными для отказоустойчивости. Общая концепция: **[Репликация баз данных](../Concepts/replication.md)**.

- **Primary:** Единственный узел, принимающий запись.
- **Secondary:** Асинхронно реплицируют `oplog` с primary, обслуживают чтение.
- **Arbiter:** Голосует на выборах, не хранит данные.
- **Elections:** Автоматический выбор нового primary при недоступности текущего.

### Шардирование (Sharding)

**Sharding** — распределение данных по шардам для горизонтального масштабирования. Общая концепция: **[Шардирование](../Concepts/sharding.md)**.

- **Shard:** Независимый replica set с частью данных.
- **`mongos`:** Query router, направляет запросы на нужные шарды.
- **Config Servers:** Replica set с метаданными распределения.
- **Shard Key:** Поле, определяющее размещение документа на шарде. Критичен для производительности.

### Эксплуатация

- **Потребление ресурсов:** Активно использует RAM и дисковое пространство.
- **Администрирование:** Управление кластером сложнее, чем у PostgreSQL.

## Практические сценарии

- **Rapid Prototyping:** Гибкая схема для быстрой эволюции модели данных.
- **CMS:** Разнородный контент, профили пользователей, комментарии.
- **Big Data / IoT:** Обработка больших объёмов от множества источников.
- **Каталоги продуктов:** Товары с различными атрибутами.

## Дополнительная информация
