# MongoDB: Безопасность

## Определения

**Безопасность в MongoDB** строится по модели эшелонированной защиты (Defense in Depth) и включает контроль доступа, сетевую изоляцию и шифрование данных на всех этапах жизненного цикла.

*   **RBAC (Role-Based Access Control):** Система разграничения прав, где привилегии привязываются к ролям, а роли — к пользователям.
*   **SCRAM (Salted Challenge Response Authentication Mechanism):** Стандартный протокол аутентификации «пароль-ответ». Стандарт 2026 года — **SCRAM-SHA-256**.
*   **TLS 1.3:** Современный стандарт шифрования трафика. В MongoDB 8.0 поддержка TLS 1.3 является приоритетной для обеспечения минимальных задержек при рукопожатии.
*   **Queryable Encryption (FLE 2.0):** Революционная технология шифрования полей на стороне клиента, позволяющая выполнять поиск по зашифрованным данным без их дешифрации на сервере.

## Базовые концепции

### 1. Аутентификация
MongoDB поддерживает несколько механизмов проверки подлинности:
*   **Внешняя:** LDAP, Active Directory, Kerberos (Enterprise).
*   **Внутренняя (Intra-cluster):** Узлы кластера идентифицируют друг друга через `keyFile` (общий секрет) или сертификаты **x.509** (рекомендуется).
*   **Клиентская:** SCRAM или сертификаты x.509.

### 2. Авторизация (RBAC)
Права доступа ограничены базой данных, в которой создан пользователь.
*   **Встроенные роли:** `read`, `readWrite` (на уровне БД), `dbAdmin`, `clusterAdmin`, `root` (полный доступ).
*   **Принцип минимальных привилегий:** Приложение должно иметь роль `readWrite` только в своей рабочей БД и не иметь доступа к базе `admin` или `config`.

### 3. Сетевая безопасность
*   **IP Binding:** По умолчанию MongoDB слушает только `localhost`. В Production необходимо явно указывать внутренние IP-адреса.
*   **Firewall:** СУБД должна находиться в изолированном сегменте сети (VLAN/VPC), доступ к порту 27017 должен быть ограничен только серверами приложений.

### 4. Шифрование (Data at Rest)
*   **Enterprise:** Нативное шифрование движка WiredTiger.
*   **Community:** Рекомендуется использование системных средств (LUKS для Linux, dm-crypt) или шифрование на уровне приложения (FLE).

## Практические сценарии

### 1. Первоначальная настройка (Hardening)
После установки необходимо создать администратора и включить авторизацию в `mongod.conf`.

**Шаг 1: Создание суперпользователя (в mongosh без авторизации):**
```javascript
use admin
db.createUser({
  user: "security_admin",
  pwd: passwordPrompt(),
  roles: [ { role: "root", db: "admin" } ]
})
```

**Шаг 2: Включение защиты в `/etc/mongod.conf`:**
```yaml
security:
  authorization: enabled
  javascriptEnabled: false # Отключаем серверный JS (защита от инъекций)

net:
  port: 27017
  bindIp: 127.0.0.1,10.0.5.42 # Только локальный и внутренний IP
  tls:
    mode: requireTLS
    certificateKeyFile: /etc/ssl/mongodb.pem
    CAFile: /etc/ssl/ca.pem
```

### 2. Настройка роли для приложения
```javascript
use sales_db
db.createRole({
  role: "app_server_role",
  privileges: [
    { resource: { db: "sales_db", collection: "" }, actions: ["find", "insert", "update"] }
  ],
  roles: []
})

db.createUser({
  user: "app_user",
  pwd: passwordPrompt(),
  roles: [ { role: "app_server_role", db: "sales_db" } ]
})
```

## Устранение неполадок

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **`Authentication failed`** | Неверные учетные данные или база аутентификации. | Убедитесь, что пользователь создавался в базе `admin` и при входе указано `--authenticationDatabase admin`. |
| **`SSL peer certificate validation failed`** | Истек срок сертификата или неверный CA. | Проверить цепочку сертификатов через `openssl verify`. Убедиться, что время на серверах синхронизировано (NTP). |
| **`Unauthorized` при выполнении команды** | Недостаточно прав в роли. | Проверить привилегии текущего пользователя через `db.getUser(username)`. |
| **Зависание при подключении** | Блокировка портов Firewall или неверный `bindIp`. | Проверить доступность порта через `telnet` или `nc`. |

## Чек-лист аудита безопасности (2026)

1.  [ ] **Авторизация:** Параметр `security.authorization` установлен в `enabled`.
2.  [ ] **Сетевая изоляция:** База недоступна из публичного интернета.
3.  [ ] **Шифрование трафика:** Используется TLS 1.2/1.3 для всех соединений.
4.  [ ] **Версионность:** Установлены последние патчи безопасности v8.0.x.
5.  [ ] **Секреты:** Пароли не хранятся в открытом виде (используйте Vault или Kubernetes Secrets).
6.  [ ] **Логирование:** Включен аудит событий в `systemLog`.
