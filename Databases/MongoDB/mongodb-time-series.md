# MongoDB: Time-series коллекции

## Определения

**Time-series коллекции** — это специализированный тип коллекций в MongoDB, оптимизированный для высокоскоростной записи и эффективного хранения последовательностей данных во времени (метрики, логи, события IoT, финансовые котировки).

*   **Bucketing (Баккетизация):** Внутренний механизм MongoDB, который объединяет несколько документов в один "баккет" (структуру в WiredTiger) для снижения объема метаданных и ускорения I/O.
*   **Columnar Storage (Колоночное хранение):** Метод физического хранения данных, при котором значения одного поля хранятся рядом. В MongoDB 8.0 это реализовано через Direct Columnar Compression.
*   **Block Processing (Блочная обработка):** Режим выполнения агрегаций, при котором операции проводятся не над каждым документом по отдельности, а над целыми блоками данных одновременно (векторизация).

---

## Архитектура и параметры

### 1. Ключевые поля
*   **`timeField`:** Поле типа `Date`, содержащее временную метку. Обязательно.
*   **`metaField`:** Поле, содержащее метаданные, идентифицирующие источник (например, `{ sensorId: 123, location: "DC1" }`). По этому полю происходит группировка в баккеты.
*   **`granularity`:** Настройка, определяющая ожидаемую частоту записей для одного источника:
    *   `seconds`: (По умолчанию) для записей каждые несколько секунд.
    *   `minutes`: для записей раз в минуту.
    *   `hours`: для редких записей.
    *   *Примечание:* Правильный выбор критичен для размера баккета.

### 2. MongoDB 8.0: Технологический скачок
В версии 8.0 работа с временными рядами была полностью переосмыслена:
*   **Direct Columnar Compression:** Данные в баккетах теперь сжимаются колоночно. Это дает экономию места до **90%** по сравнению с обычными коллекциями и снижает нагрузку на WiredTiger Cache.
*   **Ускорение аналитики:** Благодаря Block Processing, агрегации (расчет среднего, максимума за период) работают до **40 раз быстрее**.

## Практические сценарии

### 1. Создание коллекции для IoT-сенсоров
```javascript
db.createCollection("sensor_data", {
   timeseries: {
      timeField: "ts",
      metaField: "metadata",
      granularity: "seconds"
   },
   expireAfterSeconds: 2592000 // Хранить данные 30 дней (TTL)
})
```

### 2. Аналитический запрос (Окно за 5 минут)
Использование оконных функций для расчета скользящего среднего:

```javascript
db.sensor_data.aggregate([
  {
    $setWindowFields: {
      partitionBy: "$metadata.sensorId",
      sortBy: { ts: 1 },
      output: {
        avgTemp: {
          $avg: "$temp",
          window: { range: [-5, "current"], unit: "minute" }
        }
      }
    }
  }
])
```

### 3. Шардирование временных рядов
В версии 8.0+ **строго рекомендуется** шардировать по `metaField`. Шардирование по `timeField` создает "горячие" шарды и не рекомендуется.

```javascript
sh.shardCollection("iot_db.sensor_data", { "metadata.sensorId": 1 })
```

## Ограничения и особенности

*   **Изменение метаданных:** Значения в `metaField` должны быть относительно стабильными. Частое обновление метаданных в существующих документах ограничено.
*   **Размер баккета:** MongoDB автоматически управляет размером баккета (максимум 1000 документов или 16 МБ).
*   **Индексы:** MongoDB автоматически создает индекс по `{ metaField: 1, timeField: 1 }`. Дополнительные индексы возможны, но они замедляют запись.
*   **Обновление и удаление:** Операции `update` и `delete` имеют ограничения (например, фильтр должен соответствовать `metaField`).

---

## Устранение неполадок

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Медленная запись** | Слишком много индексов или неверная `granularity`. | Проверить количество индексов. Скорректировать `granularity` через `collMod`. |
| **Раздувание объема (Storage Bloat)** | Не используется `metaField` или он имеет слишком высокую кардинальность. | Убедиться, что общие признаки вынесены в `metaField` для эффективного баккетирования. |
| **Данные не удаляются по TTL** | TTL-монитор не успевает за потоком данных. | Проверить загрузку CPU. Увеличить размер баккета или использовать шардирование для распределения нагрузки на TTL-потоки. |

---

## Лучшие практики

1.  **Всегда используйте `metaField`:** Без него баккетизация будет неэффективной, и вы получите обычную коллекцию в "обертке" TS.
2.  **Выбирайте `granularity` точно:** Если данные приходят раз в час, а стоит `seconds`, будет создано слишком много полупустых баккетов.
3.  **Аналитика в 8.0:** Для максимальной производительности используйте нативные стадии агрегации, поддерживающие Block Processing.
