# Greenplum

## Определения

**Greenplum** — это СУБД (Система управления базами данных) с массивно-параллельной архитектурой (MPP — Massively Parallel Processing), основанная на PostgreSQL. Она спроектирована как платформа для построения корпоративных хранилищ данных (DWH — Data Warehouse) и выполнения сложных аналитических запросов (OLAP — Online Analytical Processing).

**Текущая версия:** VMware Tanzu Greenplum 7.x (2025–2026).

Ключевая идея — **распараллеливание выполнения запросов** по десяткам и сотням серверов для обработки петабайтных объемов данных.

## Основные концепции

### Архитектура без разделяемых ресурсов (Shared-Nothing MPP)

Greenplum использует архитектуру **Shared-Nothing** («без разделяемых ресурсов»), где каждый узел в кластере имеет собственные CPU, оперативную память и дисковую подсистему. Это исключает конкуренцию за ресурсы и позволяет линейно масштабировать производительность.

**Компоненты архитектуры:**

- **Мастер-хост (Master Host):** точка входа для клиентов. Хранит метаданные (глобальный каталог), оптимизирует и координирует выполнение запросов. Пользовательские данные на мастере не хранятся.
- **Сегмент-хосты (Segment Hosts):** рабочие узлы, на которых хранятся и обрабатываются данные. На каждом хосте работает один или несколько **сегментов** (экземпляров PostgreSQL), каждый из которых владеет частью общих данных.
- **Interconnect:** специализированный сетевой слой для обмена данными между сегментами во время выполнения распределенных запросов.

### Распределение данных

Greenplum комбинирует два уровня распределения данных для обеспечения максимальной параллельности:

1. **Дистрибуция (Distribution):** строки таблиц распределяются (шардируются) по всем сегментам в кластере на основе **ключа дистрибуции**.

    **Стратегии распределения:**
    - `DISTRIBUTED BY (key)` — по хешу ключа. Эффективно для операций соединения (JOIN) по этому ключу.
    - `DISTRIBUTED RANDOMLY` — случайное равномерное распределение. Используется, когда нет явного ключа для дистрибуции.
    - `DISTRIBUTED REPLICATED` — полные копии таблицы на каждом сегменте. Идеально для небольших таблиц-справочников.

2. **Партиционирование (Partitioning):** внутри каждого сегмента таблицы могут быть дополнительно разделены на логические части (партиции), например, по датам. Это ускоряет выборку за счет исключения ненужных данных (Partition Pruning).

Подробное описание принципов MPP и сравнение с традиционной архитектурой приведено в статье **[Шардирование и MPP](./Concepts/sharding.md)**.

## Практические сценарии

### Области применения Greenplum

**Подходящие сценарии:**

- **Корпоративные хранилища данных (DWH):** централизованный сбор и анализ данных всей организации.
- **Бизнес-аналитика (BI — Business Intelligence) и отчетность:** построение витрин данных и выполнение тяжелых агрегирующих запросов.
- **Анализ больших данных (Big Data):** исследовательский анализ и машинное обучение внутри БД с помощью Apache MADlib.
- **Сложные процессы обработки (ETL — Extract, Transform, Load):** пакетная обработка и преобразование огромных массивов данных.

### Противопоказания (Anti-patterns)

- **Транзакционные нагрузки (OLTP — Online Transaction Processing):** частые короткие операции вставки, обновления или удаления (INSERT/UPDATE/DELETE).
- **Запросы с критически низкой задержкой:** MPP-системы оптимизированы для пропускной способности (throughput), а не для минимального времени отклика (latency) одиночного запроса.
- **Малые объемы данных:** при объемах данных менее 1 ТБ стандартный PostgreSQL обычно эффективнее и проще в эксплуатации.

### Пример создания таблицы

```sql
-- Распределённая таблица с партиционированием
CREATE TABLE sales (
    sale_id SERIAL,
    sale_date DATE,
    product_id INT,
    customer_id INT,
    amount NUMERIC(10,2)
)
DISTRIBUTED BY (sale_id)
PARTITION BY RANGE (sale_date)
(
    PARTITION p2023 START ('2023-01-01') END ('2024-01-01'),
    PARTITION p2024 START ('2024-01-01') END ('2025-01-01')
);

-- Таблица-справочник (реплицируется на все сегменты)
CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name TEXT
) DISTRIBUTED REPLICATED;
```

### Параллельная загрузка данных

```bash
# Использование gpfdist для параллельной загрузки данных с внешних серверов
gpfdist -d /data/load_files -p 8080 &

-- Вставка данных из внешнего источника через механизм External Tables
INSERT INTO sales
SELECT * FROM sales_external_source;
```

## Дополнительная информация

### Сравнение аналитических решений

| Система | Тип архитектуры | Основное назначение | Ключевые особенности |
| :--- | :--- | :--- | :--- |
| **[PostgreSQL](./PostgreSQL/overview.md)** | OLTP (строковая) | Транзакции, операционные данные | ACID, развитая экосистема |
| **[ClickHouse](./clickhouse.md)** | OLAP (колоночная) | Сверхбыстрая аналитика, логи | Высокая скорость, сжатие данных |
| **Greenplum** | OLAP (MPP на базе PostgreSQL) | Сложная аналитика, DWH | SQL-совместимость, MADlib, JOIN'ы |

**Greenplum против ClickHouse:**

- Greenplum лучше справляется со сложными соединениями (JOIN) множества таблиц.
- ClickHouse показывает более высокую производительность на простых агрегатах в «широких» таблицах.
- Greenplum требует более сложной инфраструктуры и квалификации для администрирования.

### Экосистема и инструменты

- **Apache MADlib:** библиотека для выполнения алгоритмов машинного обучения и статистики прямо внутри базы данных.
- **gpfdist:** высокопроизводительная утилита для параллельного чтения и записи данных сегментами Greenplum.
- **PXF (Platform Extension Framework):** фреймворк для доступа к внешним данным в Hadoop, S3, JDBC без их предварительной загрузки.
- **Greenplum Command Center:** графический интерфейс для мониторинга состояния кластера и управления нагрузкой.

### Требования к ресурсам

**Рекомендации для продуктивных кластеров:**

| Компонент | Минимальные требования | Рекомендуемые параметры |
| :--- | :--- | :--- |
| **Процессор (CPU)** | 8 ядер на сегмент | 16+ ядер на сегмент |
| **Память (RAM)** | 32 ГБ на сегмент | 64+ ГБ на сегмент |
| **Диски** | SSD | NVMe SSD |
| **Сеть** | 1 Гбит/с | 10+ Гбит/с (RoCE или InfiniBand) |

### Ограничения системы

- **Версия ядра PostgreSQL:** Greenplum базируется на определенной версии PostgreSQL и может отставать от актуальных релизов ядра.
- **Операции UPDATE/DELETE:** могут выполняться медленно из-за необходимости координации распределенных транзакций и возможного перераспределения данных.
- **Сложность:** требует тщательного планирования схемы данных (выбор ключа дистрибуции) для предотвращения перекосов (Data Skew).
