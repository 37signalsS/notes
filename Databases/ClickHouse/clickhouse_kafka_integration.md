# Интеграция ClickHouse и Apache Kafka

## Определения

**Интеграция с Apache Kafka** — механизм ClickHouse для потокового потребления данных из очередей сообщений в режиме реального времени. ClickHouse выступает в роли консьюмера (consumer), преобразуя поток событий в строки таблиц.

**Движок `Kafka`** — специализированный движок таблиц, который служит интерфейсом для чтения и (реже) записи данных в топики Kafka.

**ETL-конвейер (Extract, Transform, Load)** — в контексте ClickHouse это связка из движка `Kafka`, материализованного представления для трансформации и целевой таблицы `MergeTree` для хранения.

## Основные концепции

### Стандартный паттерн интеграции

Для надежной и производительной обработки данных используется связка из трех сущностей:

1.  **Таблица-очередь (`Kafka` engine):** виртуальная таблица, не хранящая данные на диске. Она отвечает за соединение с брокером и чтение сообщений.
2.  **Целевая таблица (`MergeTree`):** физическое хранилище, где данные лежат в оптимальном для аналитики виде.
3.  **Материализованное представление (MV):** фоновый процесс (триггер), который срабатывает при поступлении пачки сообщений в таблицу-очередь и перекладывает их в целевую таблицу.

### Управление смещениями (Offsets)

ClickHouse автоматически фиксирует смещения (commits) в Kafka только после успешной записи блока данных в целевую таблицу. Это обеспечивает гарантию доставки **At-least-once** (минимум один раз). В случае сбоя во время записи, данные будут прочитаны повторно.

### Обработка ошибок парсинга

Для предотвращения остановки конвейера при поступлении битых сообщений (например, некорректный JSON) используется настройка:
- **`kafka_handle_error_mode = 'stream'`**: при ошибке парсинга ClickHouse записывает пустые значения в столбцы данных и заполняет системные столбцы `_error` и `_raw_message`, позволяя обработать их позже.

## Практические сценарии

### Реализация ETL-конвейера

**1. Создание таблицы-очереди:**
Рекомендуется использовать **Named Collections** для хранения параметров подключения, чтобы не дублировать их в каждой таблице.

```sql
CREATE TABLE kafka_queue (
    timestamp DateTime64(3),
    level String,
    message String
) ENGINE = Kafka()
SETTINGS 
    kafka_broker_list = 'host1:9092,host2:9092',
    kafka_topic_list = 'app_logs',
    kafka_group_name = 'clickhouse_consumers',
    kafka_format = 'JSONEachRow',
    kafka_num_consumers = 2,
    kafka_handle_error_mode = 'stream';
```

**2. Создание целевой таблицы:**
```sql
CREATE TABLE logs (
    timestamp DateTime64(3),
    level String,
    message String,
    _error String,        -- Для отладки ошибок парсинга
    _raw_message String   -- Оригинал сообщения при ошибке
) ENGINE = MergeTree()
PARTITION BY toYYYYMMDD(timestamp)
ORDER BY (level, timestamp);
```

**3. Создание материализованного представления:**
```sql
CREATE MATERIALIZED VIEW logs_mv TO logs AS
SELECT 
    timestamp, level, message, 
    _error, _raw_message
FROM kafka_queue;
```

## Рекомендации по производительности

### Батчинг (Batching)
Kafka работает эффективно только при вставке данных большими пачками.
- **`kafka_max_block_size`**: размер блока сообщений перед записью в MergeTree (рекомендуется 65k+).
- **`kafka_flush_interval_ms`**: максимальное время ожидания перед записью блока, даже если он не заполнился.

### Параллелизм
Количество потребителей (`kafka_num_consumers`) должно быть не больше количества партиций в топике Kafka. Оптимально — соответствие 1:1.

### Форматы данных
- **`JSONEachRow`**: наиболее гибкий для логов.
- **`Protobuf / Avro`**: наиболее производительные и компактные форматы, требуют указания схемы (`format_schema`).

## Мониторинг и отладка

Системные таблицы для контроля состояния:
- **`system.kafka_consumers`**: показывает активные соединения, текущие оффсеты и отставание (lag) от конца топика.
- **`system.errors`**: общее количество ошибок в процессе работы.
- **`system.logs`**: логирование процесса вставки (при включенном уровне `trace` можно увидеть детальный лог коммитов Kafka).

**Прямой запрос (Direct Select):**
По умолчанию `SELECT` из таблицы `Kafka` потребляет данные. Для отладки без сброса оффсетов используйте:
`SET stream_like_engine_allow_direct_select = 1;`
