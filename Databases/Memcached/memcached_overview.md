# Обзор Memcached

## Модель данных
Memcached — это простое хранилище типа ключ-значение, где значение представляет собой непрозрачный массив байт. Сервер не интерпретирует формат значений; любые сложные структуры данных требуют сериализации и десериализации на стороне клиента.

## Управление памятью
Memcached использует **slab-аллокатор**:
*   Память предварительно разбивается на «слабы» (slabs) — классы с чанками фиксированных размеров.
*   Каждый объект помещается в чанк подходящего размера.
*   Это снижает фрагментацию и делает расход памяти предсказуемым, но может приводить к неэффективному использованию памяти, если размер объекта плохо соответствует размеру чанка.
*   Вытеснение происходит по алгоритму LRU для каждого slab-класса.
*   Возможна автоматическая перебалансировка памяти между классами.

Оценочно, накладные расходы на хранение в Memcached минимальны и стабильны.

## TTL и протокол «старения»
*   TTL задается для каждого элемента.
*   Истечение ключей происходит **лениво** (при доступе к ним).
*   Фоновый процесс (`crawler`) периодически подчищает протухшие записи.
*   Значение TTL, превышающее 30 дней, интерпретируется как абсолютное Unix-время истечения.

## Устойчивость и перезапуски
Memcached **не поддерживает персистентность** по своей природе. После перезапуска сервер стартует с пустым кешем. Основная ставка делается на быстрый «прогрев» кеша за счет запросов к основному хранилищу данных.

## Масштабирование и консистентность
*   Масштабирование Memcached осуществляется через **шардирование на стороне клиента**, обычно с использованием **согласованного хеширования (consistent hashing)**.
*   Серверы Memcached независимы друг от друга.
*   Миграция данных или изменение состава кластера требуют перенастройки хеш-кольца на клиентах.
*   Встроенные механизмы репликации отсутствуют.

## Профиль производительности
*   Memcached является **многопоточным**, что позволяет эффективно утилизировать многоядерные процессоры.
*   Благодаря минимальной семантике операций (get/set/delete) достигается крайне низкая латентность.
*   Поддерживает операцию **CAS (Check-And-Set)** для предотвращения «состояния гонки» при конкурентной записи.
