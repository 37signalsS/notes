# Установка и настройка MariaDB

## Определения

**MariaDB** — реляционная система управления базами данных (RDBMS) с открытым исходным кодом, развивающаяся как высокопроизводительный и функционально богатый форк MySQL.

**LTS (Long Term Support)** — версии с долгосрочной поддержкой (обычно 5 лет), которые являются приоритетными для использования в производственных (production) средах из-за их стабильности и гарантированных обновлений безопасности.

**Unix Socket (`unix_socket`)** — механизм аутентификации, позволяющий локальным пользователям ОС подключаться к базе данных без пароля, если их имя пользователя в ОС совпадает с именем в БД (актуально для `root` через `sudo`).

## Основные концепции

### Жизненный цикл версий (на август 2026)

Для обеспечения безопасности и доступа к современным функциям (таким как векторный поиск и оптимизация бинарных логов) рекомендуется использовать актуальные LTS-ветки:
- **12.3 LTS (May 2026):** Рекомендуемая версия для всех новых инсталляций. Поддержка до 2031 года.
- **11.4 LTS:** Стабильная версия, широко используемая в текущих проектах. Поддержка до 2029 года.
- **10.11 LTS:** Зрелая версия, поддерживаемая до 2028 года.

### Способы установки

1. **Официальный репозиторий MariaDB Foundation:** Предоставляет самые свежие LTS и Rolling релизы. Рекомендуется для production.
2. **Репозитории дистрибутива (OS Repos):** Пакеты адаптированы под ОС, но часто содержат устаревшие версии (например, 10.6 в Debian 12).
3. **Docker / Podman:** Идеально для изоляции и облачных окружений.

## Практические сценарии

### Установка в Debian и Ubuntu (12.3 LTS)

Для установки используется официальный скрипт `mariadb_repo_setup`, который автоматически импортирует GPG-ключи и настраивает источники пакетов.

```bash
# 1. Загрузка и запуск скрипта настройки репозитория
curl -LsS https://r.mariadb.com/downloads/mariadb_repo_setup | sudo bash -s -- --mariadb-server-version="mariadb-12.3"

# 2. Установка сервера и клиента
sudo apt update
sudo apt install -y mariadb-server mariadb-client

# 3. Верификация подписи пакета (опционально)
dpkg -l mariadb-server # → Проверка установленной версии
```

### Установка в RHEL, Rocky Linux, AlmaLinux

```bash
# Настройка репозитория
curl -LsS https://r.mariadb.com/downloads/mariadb_repo_setup | sudo bash -s -- --mariadb-server-version="mariadb-12.3"

# Установка
sudo dnf install -y MariaDB-server MariaDB-client
```

### Первоначальный запуск и проверка статуса

```bash
# Включение автозапуска и запуск сервиса
sudo systemctl enable --now mariadb

# Проверка работоспособности процесса
systemctl status mariadb --no-pager

# Проверка прослушивания порта (по умолчанию 3306 на 127.0.0.1)
ss -tlnp | grep 3306
```

### Глубокая настройка безопасности (mariadb-secure-installation)

Этот скрипт является ОБЯЗАТЕЛЬНЫМ (Mandatory) для любого production-сервера.

```bash
sudo mariadb-secure-installation
```

**Разбор ключевых этапов:**
1. **Switch to unix_socket authentication:** Рекомендуется `Y`. Позволяет `root` входить через `sudo` без пароля.
2. **Change the root password:** Если выбран `unix_socket`, пароль для локального root не обязателен, но рекомендуется установить его для совместимости с внешними инструментами.
3. **Remove anonymous users:** Всегда `Y`. Удаляет пользователей без имени, имеющих доступ по умолчанию.
4. **Disallow root login remotely:** Всегда `Y`. Root должен подключаться только локально. Для удаленного доступа создавайте отдельных пользователей.
5. **Remove test database:** Всегда `Y`. Удаляет небезопасную базу `test`, доступную всем.
6. **Reload privilege tables:** Всегда `Y`. Применяет изменения немедленно.

### Настройка брандмауэра

Если требуется удаленный доступ (после изменения `bind-address` в `my.cnf`), необходимо открыть порт.

```bash
# UFW (Ubuntu/Debian)
sudo ufw allow 3306/tcp

# Firewalld (RHEL/CentOS)
sudo firewall-cmd --permanent --add-port=3306/tcp
sudo firewall-cmd --reload
```

## Устранение неполадок (Troubleshooting)

### Ошибка подключения к сокету
`ERROR 2002 (HY000): Can't connect to local MySQL server through socket '/var/run/mysqld/mysqld.sock'`
- **Причина:** Сервер не запущен или путь к сокету в `my.cnf` не совпадает с реальным.
- **Решение:** Проверьте статус через `systemctl` и логи `journalctl -u mariadb`.

### Ошибка Access Denied для root
- **Причина:** Попытка входа без `sudo` при включенном `unix_socket`.
- **Решение:** Используйте `sudo mariadb` или проверьте права доступа к файлу сокета.

### Медленный запуск
- **Причина:** Проблемы с разрешением имен (DNS).
- **Решение:** Добавьте `skip-name-resolve` в секцию `[mariadb]` конфигурационного файла.

## Дополнительная информация

### Совместимость аутентификации
Начиная с 12.3 LTS, MariaDB нативно поддерживает `caching_sha2_password`. Если старые приложения не могут подключиться, убедитесь, что клиентская библиотека обновлена или временно используйте `mysql_native_password` для конкретного пользователя.
