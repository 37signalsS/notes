# MariaDB: Обзор

## Определения

**MariaDB** — это реляционная система управления базами данных (СУБД) с открытым исходным кодом, созданная как форк MySQL. Проект управляется независимым фондом **MariaDB Foundation**. MariaDB сохраняет высокую степень совместимости с MySQL (drop-in replacement), но развивается как самостоятельная экосистема с уникальными движками хранения, расширенным SQL-синтаксисом и современными возможностями для работы с ИИ, аналитикой и временными данными.

**MariaDB Shell (`mariadb-shell`)** — современный интерактивный клиент нового поколения (введен в 12.x), поддерживающий выполнение команд на SQL, JavaScript и Python, а также встроенные инструменты миграции и интеграции с AI-моделями.

**Galera Cluster** — технология синхронной multi-master репликации, интегрированная в MariaDB. Обеспечивает высокую доступность и отсутствие потери данных при сбое узла (RPO=0), позволяя выполнять запись на любой узел кластера.

**Стандартная репликация (Source-Replica)** — механизм асинхронного или полусинхронного копирования данных. В отличие от Galera, имеет четкое разделение на узел записи (Source) и узлы чтения (Replica), что упрощает масштабирование и снижает требования к сети.

**[MaxScale](./MaxScale/maxscale_overview.md)** — интеллектуальный прокси-сервер баз данных, который понимает протокол MariaDB. Используется для балансировки нагрузки (Read/Write Split), автоматического переключения (Failover), обеспечения безопасности (SQL-firewall) и маскирования данных.

## Основные концепции

### История и стратегия развития

MariaDB была основана в 2010 году Майклом "Монти" Видениусом после покупки MySQL корпорацией Oracle. Ключевое отличие стратегии MariaDB — открытость к инновациям от сообщества и быстрое внедрение современных технологий.
- **MariaDB 10.x:** Внедрение Galera Cluster как стандартного решения для HA, расширение поддержки JSON и новых движков (MyRocks).
- **MariaDB 11.x:** Глубокая переработка ядра, включая новый стоимостный оптимизатор (Cost-based Optimizer) и нативную поддержку векторного поиска (11.7+).
- **MariaDB 12.x:** Современный этап (LTS-версия 12.3 выпущена в мае 2026 года). Основной фокус на облачной нативности (S3 Engine), производительности (Thread Pool) и инструментах разработчика.

### Архитектура и движки хранения

MariaDB использует подключаемую архитектуру движков (Pluggable Storage Engine), что позволяет оптимизировать БД под конкретные нагрузки:
1.  **Aria:** Улучшенный движок, заменивший MyISAM для системных таблиц. В отличие от MyISAM, Aria устойчива к сбоям (crash-safe) и поддерживает эффективное кэширование.
2.  **InnoDB:** Основной транзакционный движок. MariaDB поддерживает собственные оптимизации InnoDB, включая улучшенную очистку (Purge) и адаптивный хеш-индекс.
3.  **ColumnStore:** Движок для распределенной аналитики (OLAP), использующий колоночное хранение. Позволяет обрабатывать петабайты данных с высокой скоростью.
4.  **S3 Storage Engine:** Позволяет хранить архивные таблицы в облачных хранилищах (AWS S3, Google Cloud Storage), сохраняя возможность выполнять по ним SQL-запросы.

### Ключевые возможности и инновации

1.  **Системно-версионируемые таблицы (System-Versioned Tables):**
    - Автоматическое хранение истории всех изменений строк.
    - Поддержка стандарта SQL:2011.
    - Использование: аудит, восстановление состояния данных на момент времени (`AS OF`), анализ изменений цен или статусов.

2.  **Векторный поиск и AI (Vector Search):**
    - Нативная поддержка типа `VECTOR` и индексов **mHNSW**.
    - Встроенные функции для вычисления расстояний (L2, Cosine).
    - Интеграция с MariaDB Shell для загрузки эмбеддингов напрямую из моделей (HuggingFace, OpenAI).

3.  **Thread Pool:**
    - Механизм управления потоками, позволяющий эффективно обрабатывать тысячи одновременных соединений.
    - Минимизирует накладные расходы на переключение контекста процессора под высокой нагрузкой.

4.  **Расширенная совместимость:**
    - Режим `sql_mode=ORACLE` позволяет запускать хранимые процедуры на языке PL/SQL.
    - Поддержка невидимых столбцов (Invisible Columns) и виртуальных столбцов (Generated Columns).

### Сравнение с MySQL 8.x/9.x

| Характеристика | MariaDB (12.3 LTS) | MySQL (8.4/9.0) |
| :--- | :--- | :--- |
| **Оптимизатор** | Cost-based, учет веса движков, фокус на JOIN | Oracle Optimizer, глубокая привязка к InnoDB |
| **Движки** | Aria, MyRocks, Spider, S3, ColumnStore | Преимущественно InnoDB |
| **Временные данные** | Нативная поддержка системного версионирования | Ограниченная поддержка через триггеры |
| **Кластеризация** | Встроенная Galera (Multi-Master) | InnoDB Cluster (Group Replication) |
| **Схема данных** | Поддержка динамических столбцов и JSON | JSON-типы и функции |
| **Лицензирование** | GPLv2 (MaxScale под BSL) | GPLv2 / Commercial (Oracle) |

**Критическое замечание:** Из-за различных реализаций GTID (Global Transaction ID) и бинарных логов прямая репликация между MySQL 8.x+ и MariaDB 11/12 невозможна. Рекомендуется использовать `mariadb-dump` для миграции.

## Практические сценарии

### Настройка системного версионирования

Используется для создания таблиц, которые автоматически отслеживают изменения без ручного создания таблиц аудита.

**Prerequisites:** MariaDB 10.3+.

```sql
-- Создание таблицы с версионированием
CREATE TABLE product_prices (
    id INT PRIMARY KEY AUTO_INCREMENT,
    product_name VARCHAR(100),
    price DECIMAL(10, 2)
) WITH SYSTEM VERSIONING;

-- Обновление цены
UPDATE product_prices SET price = 150.00 WHERE product_name = 'SSD 1TB';

-- Запрос данных на конкретный момент в прошлом
SELECT * FROM product_prices FOR SYSTEM_TIME AS OF '2026-08-15 10:00:00';

-- Запрос всей истории изменений строки
SELECT * FROM product_prices FOR SYSTEM_TIME ALL WHERE product_name = 'SSD 1TB';
```

### Использование векторного поиска для RAG-систем

Сценарий поиска похожих документов на основе эмбеддингов.

**Prerequisites:** MariaDB 11.7+ (рекомендуется 12.3 LTS).

```sql
-- 1. Создание таблицы с векторным полем (размерность эмбеддинга 384)
CREATE TABLE documentation_chunks (
    id INT PRIMARY KEY AUTO_INCREMENT,
    content TEXT,
    embedding VECTOR(384) NOT NULL,
    VECTOR INDEX (embedding) -- Создание индекса mHNSW
);

-- 2. Поиск 5 наиболее релевантных фрагментов по косинусному сходству
SELECT content, VEC_DISTANCE_COSINE(embedding, [0.12, -0.05, ...]) as dist
FROM documentation_chunks
ORDER BY dist ASC
LIMIT 5;
```

### Оптимизация соединений через Thread Pool

Рекомендуется для систем с количеством соединений > 500.

**Настройка в `my.cnf`:**
```ini
[mariadb]
thread_handling = pool-of-threads
thread_pool_size = 16  # Обычно равно количеству ядер CPU
thread_pool_max_threads = 1000
```

**Валидация:**
```sql
SHOW GLOBAL STATUS LIKE 'Threadpool_threads';
-- Если значение близко к thread_pool_max_threads, требуется увеличение лимита или оптимизация запросов.
```

## Диагностика и устранение неисправностей

### Диагностика Galera Cluster

При возникновении проблем с кластером (например, узел не принимает записи), проверьте статус синхронизации и Flow Control. Детальная диагностика очередей и метрик доступна в **[Мониторинге MariaDB](monitoring.md)**.

### Анализ медленных запросов

MariaDB поддерживает расширенный вывод `EXPLAIN`.

```sql
EXPLAIN FORMAT=JSON SELECT ...;
-- В 12.3 LTS вывод включает детальную информацию о стоимости каждой операции (cost), 
-- что позволяет понять, почему оптимизатор выбрал конкретный индекс.
```

## Особенности и ограничения

-   **MySQL 8.0 Compatibility:** MariaDB **не является** 100% совместимой с MySQL 8.0+. Некоторые типы данных (например, пространственные индексы) и форматы аутентификации различаются.
-   **Storage Engine Limits:** Движок MyRocks не поддерживает внешние ключи (Foreign Keys) и требует специальной настройки для эффективной работы с памятью.
-   **MaxScale Licensing:** Несмотря на открытый код MariaDB Server, прокси MaxScale использует Business Source License (BSL). Он бесплатен для использования на кластерах менее чем с 3 узлами базы данных.
