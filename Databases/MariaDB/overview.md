# MariaDB: Обзор

## Определения

**MariaDB** — это реляционная система управления базами данных (СУБД) с открытым исходным кодом, созданная как форк MySQL. Проект управляется независимым фондом **MariaDB Foundation**. MariaDB сохраняет высокую степень совместимости с MySQL (drop-in replacement), но развивается как самостоятельная экосистема с уникальными движками хранения, расширенным SQL-синтаксисом и современными возможностями для работы с ИИ, аналитикой и временными данными.

**MariaDB Shell (`mariadb-shell`)** — современный интерактивный клиент нового поколения (введен в 12.x), поддерживающий выполнение команд на SQL, JavaScript и Python, а также встроенные инструменты миграции и интеграции с AI-моделями.

## Основные концепции

### История и развитие

MariaDB была основана в 2010 году Майклом "Монти" Видениусом после покупки MySQL корпорацией Oracle. 
- **MariaDB 10.x:** Внедрение Galera Cluster, расширение поддержки JSON и новых движков (MyRocks).
- **MariaDB 11.x:** Глубокая переработка ядра, включая новый стоимостный оптимизатор (Cost-based Optimizer) и нативную поддержку векторного поиска (11.7+).
- **MariaDB 12.x:** Современный этап (LTS-версия 12.3 выпущена в мае 2026 года). Основной фокус на облачной нативности (S3 Engine), производительности (Thread Pool) и инструментах разработчика.

### Ключевые возможности и инновации

1. **Системно-версионируемые таблицы (System-Versioned Tables):**
   - Позволяют хранить историю всех изменений данных автоматически.
   - Запросы могут обращаться к состоянию данных на любой момент времени в прошлом (`SELECT ... AS OF SYSTEM TIME ...`).
   - Идеально для аудита и восстановления данных без использования бэкапов.

2. **Векторный поиск (Vector Search):**
   - Нативная поддержка типа `VECTOR` и индексов **mHNSW**.
   - Позволяет строить RAG-системы (Retrieval-Augmented Generation) напрямую в базе данных, обеспечивая высокую скорость поиска по эмбеддингам.

3. **Расширенные движки хранения:**
   - **ColumnStore:** Для распределенной аналитики (OLAP).
   - **MyRocks:** Для экономии места и минимизации износа SSD (LSM-дерево).
   - **Spider:** Для прозрачного шардирования данных.
   - Подробнее см. в **[Движки хранения MariaDB](storage_engines.md)**.

4. **MaxScale (Database Proxy):**
   - Интеллектуальный прокси-сервер, обеспечивающий балансировку нагрузки, автоматическое переключение при сбоях (failover), SQL-фаервол и маскирование данных.

5. **Производительность и масштабируемость:**
   - **Thread Pool:** Позволяет серверу эффективно обрабатывать тысячи одновременных соединений с минимальными накладными расходами на переключение контекста.
   - **Multi-Source Replication:** Возможность репликации данных из нескольких источников на один сервер.

6. **Безопасность:**
   - **MariaDB Audit Plugin:** Детальное логирование действий пользователей для комплаенса.
   - Поддержка современных методов аутентификации (ED25519, PAM, Kerberos).

### Сравнение с MySQL

| Характеристика | MariaDB (12.3 LTS) | MySQL (8.4/9.0) |
| :--- | :--- | :--- |
| **Оптимизатор** | Собственный (Cost-based), фокус на JOIN | Oracle Optimizer, фокус на InnoDB |
| **Движки** | Широкий выбор (Aria, MyRocks, Spider, S3) | Преимущественно InnoDB |
| **Временные данные** | Нативная поддержка системного версионирования | Ограниченная поддержка через триггеры |
| **Кластеризация** | Встроенная Galera (Multi-Master) | InnoDB Cluster (Group Replication) |
| **Совместимость** | Разрыв бинарной совместимости с MySQL 8+ | — |

**Критическое замечание:** Из-за различий в формате GTID (Global Transaction ID) и бинарных логов прямая репликация между MySQL 8.x и MariaDB 11/12 невозможна. Перенос данных рекомендуется выполнять через логический дамп (`mariadb-dump`).

## Практические сценарии

- **Развертывание и базовая настройка:** См. **[Установка и настройка MariaDB](installation_and_setup.md)**.
- **Работа с историческими данными:** Создание таблицы с версионированием:
  ```sql
  CREATE TABLE employees (
      id INT PRIMARY KEY,
      salary INT
  ) WITH SYSTEM VERSIONING;
  ```
- **Отказоустойчивость с MaxScale:** Настройка маршрутизации чтение/запись (Read/Write Split) для снижения нагрузки на мастер-узел.
- **Мониторинг:** Интеграция с Prometheus через `mysqld_exporter` (поддерживает MariaDB-специфичные метрики).
- **Резервное копирование:** Использование `mariabackup` для горячего физического бэкапа (включая Galera Cluster). См. **[Бэкап и восстановление MariaDB](backup_and_recovery.md)**.
