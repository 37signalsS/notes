# Движки хранения в MariaDB

## Определения

**Движок хранения (Storage Engine)** — это программный модуль СУБД, отвечающий за низкоуровневые операции с данными: физическое хранение на диске, индексацию, управление блокировками и обеспечение транзакционности.

В MariaDB архитектура позволяет выбирать наиболее подходящий движок для каждой таблицы индивидуально в рамках одной базы данных. Это позволяет эффективно сочетать транзакционную (OLTP), аналитическую (OLAP) и архивную нагрузки на одном сервере.

## Основные концепции

### Актуальное состояние (LTS 12.3)

Версия MariaDB 12.3 LTS (выпущена в 2026 году) является ключевым этапом в развитии производительности и функциональности СУБД. Основные изменения коснулись глубокой интеграции компонентов и поддержки современных рабочих нагрузок (AI, Big Data).

**Ключевые нововведения:**
1. **Интеграция Binary Log в InnoDB:** События бинарного лога теперь могут храниться непосредственно в структурах InnoDB. Это устраняет необходимость двойной записи и синхронизации файлов, обеспечивая прирост производительности записи до 4 раз.
2. **Нативная поддержка векторов (Vector Search):** Полноценная поддержка типа данных `VECTOR` и индексов **mHNSW** (Modified Hierarchical Navigable Small World) для эффективного поиска по сходству.
3. **Оптимизация Aria:** Введение сегментированного кеша ключей (`aria_pagecache_segments`), что значительно улучшает масштабируемость системных и временных таблиц на многоядерных процессорах.
4. **Удаление Change Buffer:** Полное удаление кода Change Buffer (начиная с 11.0) в пользу прямого ввода-вывода, что стало возможным благодаря повсеместному переходу на SSD.

### Основные движки

**InnoDB:** Универсальный транзакционный движок по умолчанию.
- **Особенности:** Полная поддержка ACID, MVCC (Multi-Version Concurrency Control), внешние ключи.
- **Производительность:** В 12.3 LTS по умолчанию включена опция `innodb_snapshot_isolation=ON` для повышения согласованности данных.
- **AI-функции:** Используется как основное хранилище для векторных эмбеддингов с поддержкой аппаратного ускорения SIMD (AVX512, ARM Neon).

**Aria:** Усовершенствованная альтернатива MyISAM.
- **Назначение:** Используется MariaDB для хранения системных таблиц и выполнения сложных временных операций (Internal temporary tables).
- **Сценарии:** Таблицы, требующие устойчивости к сбоям (Crash-safe) без накладных расходов на полную ACID-транзакционность.

**MyRocks:** Движок на базе LSM-дерева (RocksDB).
- **Преимущества:** Экстремальное сжатие данных и оптимизация под интенсивную запись. Минимизирует эффект Write Amplification, продлевая ресурс SSD.
- **Сценарии:** Огромные массивы исторических данных, системы логирования и метрик.

**ColumnStore:** Колоночный движок для аналитики (OLAP).
- **Принцип:** Хранит данные по столбцам, обеспечивая мгновенную агрегацию (`SUM`, `AVG`) по миллиардам строк.
- **Сценарии:** Построение хранилищ данных (DWH) и сложная бизнес-аналитика.

**Spider:** Движок для распределенного хранения (Sharding).
- **Функция:** Прозрачное распределение данных одной таблицы между несколькими удаленными узлами MariaDB.
- **Сценарии:** Горизонтальное масштабирование баз данных сверх ресурсов одного сервера.

### Вспомогательные и специализированные движки

**S3:** Движок для холодного хранения данных в облаке.
- **Функция:** Позволяет переносить архивные таблицы в S3-совместимые хранилища (AWS S3, MinIO, Cloudflare R2).
- **Особенности:** Таблицы доступны только для чтения, поддерживают сжатие zlib. Другие узлы MariaDB могут автоматически обнаруживать эти таблицы в общем бакете.

**Archive:** Максимальное сжатие для логов.
- **Особенности:** Поддерживает только `INSERT` и `SELECT`. Данные сжимаются «на лету» с использованием zlib. Индексы не поддерживаются.

**Memory:** Хранение данных в оперативной памяти.
- **Особенности:** Очень высокая скорость доступа, но данные теряются при перезагрузке сервера. Использует хэш-индексы.

**Sequence:** Генератор числовых последовательностей.
- **Сценарии:** Создание виртуальных таблиц с числами для сложных запросов или генерации отчетов без создания физических данных.

**Connect:** Интеграция с внешними источниками.
- **Функция:** Доступ к CSV, JSON, Excel, XML или другим СУБД (через JDBC/ODBC) как к локальным таблицам.

## Практические сценарии

### Мониторинг состояния движков

```sql
-- Проверка доступных движков и их статуса
SHOW ENGINES;

-- Анализ движков используемых в конкретной БД
SELECT engine, count(*) 
FROM information_schema.tables 
WHERE table_schema = 'my_database' 
GROUP BY engine;
```

### Настройка векторного индекса (MariaDB 11.7+)

```sql
CREATE TABLE ai_memory (
    id INT PRIMARY KEY,
    content TEXT,
    embedding VECTOR(1536) NOT NULL,
    -- Создание индекса mHNSW для быстрого поиска
    VECTOR INDEX (embedding) DISTANCE=cosine
) ENGINE=InnoDB;
```

### Архивация данных в облако S3

```sql
-- Перевод исторической таблицы на S3
ALTER TABLE historical_logs ENGINE=S3 COMPRESSION_ALGORITHM=zlib;

-- Проверка статуса (таблица станет доступна только для чтения)
SHOW TABLE STATUS LIKE 'historical_logs';
```

## Дополнительная информация

### Сравнение характеристик (12.3 LTS)

| Движок | ACID | Индексация | Основной фокус |
| :--- | :---: | :--- | :--- |
| **InnoDB** | Да | B+Tree, mHNSW | Транзакции, Универсальность, AI |
| **Aria** | Частично | B+Tree | Системные и временные задачи |
| **MyRocks** | Да | LSM-Tree | Сжатие, интенсивная запись |
| **ColumnStore** | Да | Columnar | Аналитика (OLAP), Big Data |
| **S3** | Нет | Aria-based cache | Архивное холодное хранение |
| **Memory** | Нет | Hash, B-Tree | Временные данные, сверхвысокая скорость |

*\* Aria обеспечивает Crash-safety через логи транзакций, но не гарантирует полную MVCC-изоляцию.*
