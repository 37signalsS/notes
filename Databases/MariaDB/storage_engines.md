# Движки хранения (Storage Engines) в MariaDB

## Определения

**Движок хранения (Storage Engine)** — это программный компонент реляционной системы управления базами данных (РСУБД), который отвечает за фактическое хранение, извлечение и управление данными в таблицах. Каждый движок имеет свои уникальные характеристики, оптимизированные для определенных типов рабочих нагрузок и требований к данным.

## Основные концепции

### Гибкость выбора

Одной из ключевых особенностей и преимуществ MariaDB является поддержка и активное развитие множества движков хранения, в то время как Oracle MySQL фокусируется почти исключительно на InnoDB. Это дает большую гибкость в выборе оптимального движка для конкретных задач, позволяя балансировать между производительностью, надежностью, целостностью данных и используемым дисковым пространством.

### Основные движки и их характеристики

#### 1. InnoDB (и XtraDB)

* **Описание:** Остается основным движком по умолчанию для большинства задач. MariaDB использует форк InnoDB под названием **XtraDB** от Percona, который предлагает улучшения производительности.
* **Характеристики:** Универсальный транзакционный движок, соответствующий требованиям **[ACID](../../Concepts/acid.md)**. Поддерживает внешние ключи, блокировки на уровне строк и MVCC (Multiversion Concurrency Control).
* **Сценарии использования:** OLTP-нагрузки (online transaction processing), требующие высокой надежности, целостности данных и частых операций чтения/записи с транзакциями (например, электронная коммерция, банковские системы).

#### 2. Aria

* **Описание:** Движок, позиционируемый как отказоустойчивая и более современная замена устаревшему MyISAM.
* **Характеристики:** Использует транзакционный лог для восстановления после сбоев, имеет продвинутое кэширование. В самой MariaDB используется для внутренних системных и временных таблиц, повышая стабильность сервера.
* **Сценарии использования:** Внутренние нужды MariaDB, а также приложения с высокой скоростью чтения, где не требуются транзакции на уровне приложения.

#### 3. MyRocks

* **Описание:** Движок, основанный на структуре данных **LSM-дерево (Log-Structured Merge-tree)**.
* **Характеристики:** Оптимизирован для нагрузок с интенсивной записью (`INSERT`, `UPDATE`, `DELETE`) и обеспечивает значительно лучшее сжатие данных по сравнению с InnoDB.
* **Сценарии использования:** Системы с большим объемом данных и частыми операциями записи: хранение логов, метрик, IoT-данных.

#### 4. ColumnStore

* **Описание:** Колоночный движок хранения, оптимизированный для аналитических запросов (OLAP).
* **Характеристики:** Хранит данные по столбцам, а не по строкам. Это на порядки ускоряет выполнение агрегирующих запросов (`SUM`, `GROUP BY`) и обеспечивает высокое сжатие.
* **Сценарии использования:** Хранилища данных (DWH), аналитические отчеты, BI-системы.

#### 5. Другие специализированные движки

* **S3 Storage Engine:** Позволяет хранить таблицы MariaDB в объектных хранилищах, совместимых с Amazon S3. Полезен для архивирования.
* **Spider:** Движок для реализации **шардинга** на уровне базы данных, позволяя распределять таблицы по нескольким серверам.
* **FederatedX:** Позволяет обращаться к таблицам на удаленном сервере MariaDB/MySQL как к локальным.

## Практические сценарии

### Просмотр доступных движков

Команда `SHOW ENGINES` выводит список всех установленных в системе движков хранения и их статус.

```sql
SHOW ENGINES;
```

> Позволяет увидеть, какой движок используется по умолчанию (`DEFAULT`), поддерживаются ли транзакции и другие возможности.

### Указание движка при создании таблицы

Движок для таблицы задается с помощью параметра `ENGINE` в команде `CREATE TABLE`.

```sql
-- Создание таблицы для логов с движком MyRocks для лучшего сжатия и скорости записи
CREATE TABLE application_logs (
    event_time TIMESTAMP,
    level VARCHAR(10),
    message TEXT
) ENGINE=MyRocks;
```

### Изменение движка существующей таблицы

Движок можно изменить для уже существующей таблицы с помощью `ALTER TABLE`.

```sql
-- Преобразование таблицы в колоночный формат для ускорения аналитики
ALTER TABLE sales_archive ENGINE=ColumnStore;
```

> **Внимание:** Эта операция может быть длительной и ресурсоемкой, так как требует полной перестройки таблицы.

### Установка движка по умолчанию для сессии

Можно изменить движок по умолчанию для текущего сеанса.

```sql
SET SESSION default_storage_engine = Aria;
```
