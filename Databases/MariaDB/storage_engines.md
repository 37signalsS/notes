# Движки хранения (Storage Engines) в MariaDB

## Определения

**Движок хранения (Storage Engine)** — это программный компонент реляционной системы управления базами данных (РСУБД), который отвечает за фактическое хранение, извлечение и управление данными в таблицах. Каждый движок имеет свои уникальные характеристики, оптимизированные для определенных типов рабочих нагрузок и требований к данным.

## Основные концепции

### Гибкость выбора

Одной из ключевых особенностей и преимуществ MariaDB является поддержка и активное развитие множества движков хранения, в то время как Oracle MySQL фокусируется почти исключительно на InnoDB.

### Основные движки и их характеристики

**InnoDB (и XtraDB):** Остается основным движком по умолчанию для большинства задач. MariaDB использует форк InnoDB под названием **XtraDB** от Percona, который предлагает улучшения производительности. Универсальный транзакционный движок, соответствующий требованиям **[ACID](../Concepts/acid.md)**. Поддерживает внешние ключи, блокировки на уровне строк и MVCC. Настройка InnoDB описана в разделе **[Конфигурация MariaDB](configuration.md)**. Сценарии использования: OLTP-нагрузки (online transaction processing), требующие высокой надежности, целостности данных и частых операций чтения/записи с транзакциями (например, электронная коммерция, банковские системы). Сравнение движков в разных форках MySQL — в **[MySQL: Обзор и сравнение форков](../MySQL/overview.md)**.

**Aria:** Движок, позиционируемый как отказоустойчивая и более современная замена устаревшему MyISAM. Использует транзакционный лог для восстановления после сбоев, имеет продвинутое кэширование. В самой MariaDB используется для внутренних системных и временных таблиц, повышая стабильность сервера. Сценарии использования: внутренние нужды MariaDB, а также приложения с высокой скоростью чтения, где не требуются транзакции на уровне приложения.

**MyRocks:** Движок, основанный на структуре данных **LSM-дерево (Log-Structured Merge-tree)**. Оптимизирован для нагрузок с интенсивной записью (`INSERT`, `UPDATE`, `DELETE`) и обеспечивает значительно лучшее сжатие данных по сравнению с InnoDB. Сценарии использования: системы с большим объемом данных и частыми операциями записи: хранение логов, метрик, IoT-данных.

**ColumnStore:** Колоночный движок хранения, оптимизированный для аналитических запросов (OLAP). Хранит данные по столбцам, а не по строкам. Это на порядки ускоряет выполнение агрегирующих запросов (`SUM`, `GROUP BY`) и обеспечивает высокое сжатие. Сценарии использования: хранилища данных (DWH), аналитические отчеты, BI-системы.

**Другие специализированные движки:** S3 Storage Engine позволяет хранить таблицы MariaDB в объектных хранилищах, совместимых с Amazon S3 (полезен для архивирования). Spider — движок для реализации **шардинга** на уровне базы данных, позволяя распределять таблицы по нескольким серверам. FederatedX позволяет обращаться к таблицам на удаленном сервере MariaDB/MySQL как к локальным.

## Практические сценарии

### Просмотр доступных движков

Команда `SHOW ENGINES` выводит список всех установленных в системе движков хранения и их статус.

```sql
SHOW ENGINES;
```

> Позволяет увидеть, какой движок используется по умолчанию (`DEFAULT`), поддерживаются ли транзакции и другие возможности.

### Указание движка при создании таблицы

Движок для таблицы задается с помощью параметра `ENGINE` в команде `CREATE TABLE`.

```sql
-- Создание таблицы для логов с движком MyRocks для лучшего сжатия и скорости записи
CREATE TABLE application_logs (
    event_time TIMESTAMP,
    level VARCHAR(10),
    message TEXT
) ENGINE=MyRocks;
```

### Изменение движка существующей таблицы

Движок можно изменить для уже существующей таблицы с помощью `ALTER TABLE`.

```sql
-- Преобразование таблицы в колоночный формат для ускорения аналитики
ALTER TABLE sales_archive ENGINE=ColumnStore;
```

> **Внимание:** Эта операция может быть длительной и ресурсоемкой, так как требует полной перестройки таблицы.

### Установка движка по умолчанию для сессии

Можно изменить движок по умолчанию для текущего сеанса.

```sql
SET SESSION default_storage_engine = Aria;
```

## Дополнительная информация

### Сравнительная таблица основных движков

| Движок | Транзакции | Блокировка | Назначение |
| :--- | :---: | :---: | :--- |
| **InnoDB/XtraDB** | Да | Строка | OLTP, универсальный |
| **Aria** | Частично | Таблица | Замена MyISAM, внутренние таблицы |
| **MyRocks** | Да | Строка | Высокая плотность записи, IoT/логи |
| **ColumnStore** | Да | Строка | OLAP, аналитика |
| **MyISAM** | Нет | Таблица | Устарел, только для совместимости |

Для получения наиболее полной и актуальной информации о движках хранения MariaDB обращайтесь к [официальной документации MariaDB](https://mariadb.com/kb/en/storage-engines/).
