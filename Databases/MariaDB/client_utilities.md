# Клиентские утилиты MariaDB

## Определения

**Клиентские утилиты MariaDB** — это набор консольных программ для взаимодействия с сервером MariaDB, его администрирования, выполнения операций с данными и управления современными рабочими нагрузками (включая AI и кластерные конфигурации).

**MariaDB Shell (`mariadb-shell`)** — современный интерактивный клиент (введен в 12.x), объединяющий возможности SQL, JavaScript и Python с глубокой интеграцией в экосистему AI.

## Основные концепции

### Ребрендинг и совместимость

MariaDB завершила переход на собственные имена утилит. Старые имена (с префиксом `mysql*`) сохраняются как символические ссылки для обратной совместимости, но в SRE-практике и новых скриптах следует использовать актуальные имена.

| Старое имя | Актуальное имя (12.3 LTS) | Назначение |
| :--- | :--- | :--- |
| `mysql` | `mariadb` | Основной SQL-клиент |
| `mysqldump` | `mariadb-dump` | Логическое резервное копирование |
| `mysqladmin` | `mariadb-admin` | Административные задачи (ping, kill, status) |
| `mysqlcheck` | `mariadb-check` | Проверка и оптимизация таблиц |
| `mysqlbinlog` | `mariadb-binlog` | Чтение и обработка бинарных логов (PITR) |
| `mysql_upgrade` | `mariadb-upgrade` | Обновление системных таблиц после смены версии |
| `mysql_install_db` | `mariadb-install-db` | Инициализация каталога данных |
| `mysqlimport` | `mariadb-import` | Массовая загрузка данных из текстовых файлов |

### Преимущества MariaDB Shell

MariaDB Shell является приоритетным инструментом для современных DevOps-задач благодаря:
- **Интеграции с AI:** Встроенная поддержка протокола **MCP** позволяет передавать контекст базы данных в LLM для автоматической генерации запросов или анализа схем.
- **Поддержке плагинов:** Возможность расширения функционала через пользовательские скрипты на Python/JS.
- **Форматированию:** Нативный вывод в JSON/Table/Vertical без дополнительных флагов.

## Практические сценарии

### Инициализация и обновление

```bash
# Инициализация базы данных в новом каталоге (SRE-сценарий)
sudo mariadb-install-db --user=mysql --datadir=/var/lib/mysql_custom

# Обновление системных таблиц после миграции с 11.4 на 12.3 LTS
# Выполняется один раз после запуска нового бинарного файла сервера
mariadb-upgrade -u root -p
```

### Работа с бинарными логами (mariadb-binlog)

Используется для восстановления данных на конкретный момент времени (Point-in-Time Recovery).

```bash
# Декодирование бинарного лога в читаемый SQL с фильтрацией по базе
mariadb-binlog --database=prod_db /var/lib/mysql/binlog.000001 > recovery.sql

# Извлечение событий по GTID (Global Transaction ID) - актуально для 12.3+
# Позволяет точно восстановить транзакции в кластерных средах
mariadb-binlog --start-gtid="0-1-100" --stop-gtid="0-1-200" binlog.000002 | mariadb -u root -p
```

### Массовая загрузка данных (mariadb-import)

```bash
# Импорт CSV-файла в таблицу 'users' базы данных 'app_db'
# Файл должен иметь имя 'users.csv' (согласно имени таблицы)
mariadb-import --user=admin --password --fields-terminated-by=',' --local app_db users.csv
```

### Продвинутые сценарии MariaDB Shell

Интеграция с AI (концептуальный пример использования MCP):

```bash
# Запуск shell с активацией AI-помощника
mariadb-shell --ai-assist

# Внутри shell (AI mode):
# > "Найди все таблицы без первичных ключей и предложи команды для их добавления"
# AI анализирует information_schema и выдает готовый SQL.
```

Автоматизация на Python:

```python
# Запуск: mariadb-shell --py
# Скрипт для проверки статуса всех узлов Galera Cluster
import mariadb_shell
session = mariadb_shell.get_default_session()
result = session.run_sql("SHOW STATUS LIKE 'wsrep_cluster_size'")
print(f"Cluster size: {result.fetch_one()[1]}")
```

## Дополнительная информация

### Диагностика производительности (mariadb-slap)

Инструмент для стресс-тестирования сервера перед деплоем в production.

```bash
# Эмуляция нагрузки: 50 конкурентных клиентов, каждый выполняет 100 запросов
mariadb-slap --concurrency=50 --iterations=100 --query="SELECT * FROM my_db.test_table" --create-schema=my_db
```

### Переменные окружения и конфигурация

Для 12.3 LTS критически важны следующие переменные:
- `MARIADB_GROUP_SUFFIX`: Позволяет утилитам считывать специфические секции в `my.cnf` (например, `[client.production]`).
- `MARIADB_HISTFILE`: Путь к истории команд; рекомендуется выносить на зашифрованные разделы для повышения безопасности.
