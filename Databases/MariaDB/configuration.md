# Конфигурация MariaDB

## Определения

**Конфигурационный файл (`my.cnf`):** Основной файл, который MariaDB и клиентские утилиты читают при запуске для определения своих настроек. Традиционно называется `my.cnf`, в современных системах используются и другие имена, например `mariadb.cnf`.

**Директива `!includedir`:** Специальная директива в конфигурационных файлах, которая позволяет подключать все файлы из указанного каталога, обеспечивая модульность и упрощая управление конфигурацией.

## Базовые концепции

### Иерархия и порядок загрузки

Для сохранения совместимости с экосистемой MySQL, MariaDB использует модульную структуру конфигурации, которая загружается в определенном порядке:

1. **/etc/mysql/my.cnf:** Глобальный конфигурационный файл. Часто он не содержит прямых настроек, а лишь указывает на каталог с модульными файлами.
2. **/etc/mysql/mariadb.conf.d/:** Основной каталог, где хранятся файлы с настройками сервера и клиента. Файлы из этого каталога загружаются в алфавитном порядке, поэтому их имена обычно начинаются с чисел (`50-client.cnf`, `50-server.cnf`) для контроля порядка применения настроек.

### Основные конфигурационные файлы

`50-client.cnf` содержит настройки для клиентских приложений, таких как `mariadb`, `mariadb-dump`. Позволяет задать порт по умолчанию, сокет для подключения или учетные данные. `50-server.cnf` — ключевой файл для настройки сервера. В нем определяются параметры производительности (буферы, кэши), логирования, репликации и безопасности. `60-galera.cnf` — специализированный файл для настройки Galera Cluster, если он используется.

### Секции конфигурации

`[client]` — настройки для всех клиентских утилит. `[mysql]`, `[mariadb]` — настройки для консольного клиента `mariadb`. `[mysqld]`, `[server]`, `[mariadb-server]` — синонимичные секции для настроек серверного процесса. Рекомендуется использовать `[mariadb]` для новых конфигураций.

## Практические сценарии

### Пример настройки сервера (`50-server.cnf`)

```ini
[mariadb]
# -- Общие настройки --
# IP-адрес для приема подключений. 127.0.0.1 - только локальные. 0.0.0.0 - все интерфейсы.
bind-address = 127.0.0.1
# Максимальное количество одновременных подключений.
max_connections = 100

# -- Настройки производительности (движок InnoDB) --
# Основной параметр: размер буферного пула для данных и индексов.
# Рекомендуется устанавливать до 70-80% от доступной оперативной памяти на выделенном сервере.
# Подробнее о движках — в Движки хранения в MariaDB (storage_engines.md).
innodb_buffer_pool_size = 128M

# -- Логирование --
# Включение лога медленных запросов.
slow_query_log = 1
# Файл для лога.
slow_query_log_file = /var/log/mysql/mariadb-slow.log
# Время в секундах, после которого запрос считается медленным.
long_query_time = 1
# Записывать в лог explain-план для медленных запросов. Очень полезно для анализа.
log_slow_extra = 1

# -- Бинарный лог (для репликации и восстановления на точку времени) --
# Активирует бинлог. Укажите базовое имя файла.
# log_bin = /var/log/mysql/mysql-bin.log
# Уникальный ID сервера в топологии репликации (обязателен, если log_bin включен).
# server_id = 1
```

Для более сложных сценариев, таких как Multi-Source репликация, см. **[Multi-Source репликация в MySQL](../MySQL/multi-source-replication.md)** (концепции применимы, несмотря на то что документ находится в разделе MySQL).

### Пример безопасной настройки клиента

Вместо редактирования глобального `50-client.cnf`, более безопасным методом является создание файла `~/.my.cnf` в домашнем каталоге конкретного пользователя. Это позволяет избежать хранения учетных данных в общедоступных файлах.

**1. Создайте файл `~/.my.cnf`:**

```ini
[client]
host = localhost
port = 3306
user = app_user
password = "your_secret_password"
default-character-set = utf8mb4
```

**2. Установите строгие права доступа:**

Чтобы защитить учетные данные, файл `~/.my.cnf` должен быть доступен только его владельцу.

```bash
chmod 600 ~/.my.cnf
```

> **Внимание:** Хранение паролей в открытом виде даже в `~/.my.cnf` не является идеальным решением, но это компромисс между удобством и безопасностью для сред разработки и администрирования. В производственных средах приложения должны получать учетные данные из защищенных источников (например, Vault или переменные окружения). MariaDB не включает аналог `mysql_config_editor` для шифрования учетных данных.

## Дополнительная информация

### Расположение файлов данных и логов

**Директория с данными (`datadir`):** `/var/lib/mysql/`. Здесь хранятся подкаталоги для каждой базы данных, файлы логов InnoDB (`ib_logfile*`, `ibdata1`) и Aria (`aria_log*`).

**Лог ошибок:** `/var/log/mysql/error.log` или `/var/log/mariadb/mariadb.log`.

**Прочие логи:** Бинарные логи и логи медленных запросов обычно также находятся в `/var/log/mysql/`.

### Оптимизация производительности

Для выделенного сервера с большой нагрузкой рекомендуется настроить следующие параметры:

```ini
[mariadb]
# Размер буферного пула — до 70-80% ОЗУ
innodb_buffer_pool_size = 4G

# Параллельные потоки для записи (улучшает Write IO)
innodb_write_io_threads = 8
innodb_read_io_threads = 8

# Размер лог-файлов InnoDB (суммарно — около 1/4 от buffer_pool)
innodb_log_file_size = 512M

# С_flush для надежности (влияет на производительность)
innodb_flush_log_at_trx_commit = 1

# Максимальное количество соединений
max_connections = 200
```

Подробнее о выборе движка для конкретной нагрузки — в **[Движки хранения](storage_engines.md)**.

### Совместимость и отличия от MySQL

**Движки хранения:** MariaDB поддерживает и активно развивает большее количество **[движков хранения](storage_engines.md)**, чем MySQL.

**Структура таблиц:** В отличие от MySQL 8, где файлы структуры таблиц (`.frm`) были упразднены, в MariaDB они все еще используются для не-InnoDB таблиц, что архитектурно напоминает MySQL 5.7.
