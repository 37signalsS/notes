# Обслуживание MariaDB

## Определения

**mariadb-check** — основная утилита командной строки для проверки, восстановления, анализа и оптимизации таблиц. Является заменой устаревшей утилиты `mysqlcheck`.

**S3 Storage Engine** — движок хранения, позволяющий перемещать архивные партиции или таблицы в облачное хранилище AWS S3 (или совместимое), сохраняя возможность выполнения SQL-запросов к ним.

**System-Versioned Partitioning** — уникальная возможность MariaDB автоматически разделять данные на "текущие" и "исторические" на уровне партиций.

## Практические сценарии

### 1. Дефрагментация и анализ таблиц

MariaDB более агрессивно использует `mariadb-check` для обслуживания.

```bash
# Оптимизация (дефрагментация) всех таблиц во всех базах данных
sudo mariadb-check --all-databases --optimize

# Анализ статистики (рекомендуется после массовой вставки данных)
sudo mariadb-check --all-databases --analyze
```

**Примечание для InnoDB:** Как и в MySQL, `OPTIMIZE` для InnoDB выполняет `ALTER TABLE ... FORCE`, что пересоздает таблицу для освобождения места.

---

### 2. Секционирование (Partitioning) в MariaDB

MariaDB поддерживает стандартные типы (RANGE, LIST, HASH), но имеет уникальные интеграции.

#### Секционирование по системному времени (System Versioning):
Позволяет автоматически отделять архивные данные от актуальных.

```sql
CREATE TABLE employees (
    id INT,
    name TEXT
) WITH SYSTEM VERSIONING
PARTITION BY SYSTEM_TIME (
    PARTITION p_history HISTORY,
    PARTITION p_current CURRENT
);
```

#### Управление партициями на S3:
MariaDB позволяет выносить отдельные партиции на дешевое хранилище.

```sql
-- Пример перевода таблицы на S3 (требует настроенного s3 плагина)
ALTER TABLE archive_logs ENGINE=S3;
```

---

### 3. Мажорные обновления (Major Upgrade)

Процедуры обновления MariaDB (например, 10.11 -> 11.4 LTS) описаны в специализированных руководствах:

1.  **[Zero-Downtime Upgrade](./Operations/zero_downtime_upgrade.md)** — стратегия обновления кластеров Galera и репликационных топологий без остановки сервиса.
2.  **mariadb-upgrade:** В отличие от современного MySQL, в MariaDB запуск утилиты `mariadb-upgrade` остается **обязательным** шагом после установки новых бинарных файлов для обновления системных таблиц и словарей.

```bash
# Типовой запуск после обновления пакетов
sudo mariadb-upgrade --user=root --password
```
