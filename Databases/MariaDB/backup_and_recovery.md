# Резервное копирование и восстановление в MariaDB

В этом разделе описаны специфичные для MariaDB инструменты и подходы. Общие теоретические основы описаны в основной заметке: **[Стратегии резервного копирования баз данных](../../Concepts/backups.md)**.

## Определения

-   **Логическое резервное копирование** — процесс создания копии базы данных в виде текстового файла с SQL-командами (`CREATE TABLE`, `INSERT`), которые необходимы для её воссоздания. Этот метод обеспечивает гибкость и независимость от версий СУБД.
-   **Физическое резервное копирование** — процесс прямого копирования файлов базы данных с дисковой системы. Этот метод обеспечивает максимальную скорость, но привязан к конкретной версии и конфигурации СУБД.

## Базовые концепции

### Логический бэкап

-   **Плюсы:**
    -   **Гибкость:** Легко переносится между разными версиями MariaDB, а также на другие СУБД (например, PostgreSQL) с минимальными доработками.
    -   **Простота:** Дамп представляет собой текстовый файл, который можно открыть, проанализировать и даже изменить перед восстановлением.
    -   **Гранулярность:** Позволяет легко восстанавливать отдельные таблицы или данные.
-   **Минусы:**
    -   **Производительность:** Процессы создания дампа и особенно его восстановления могут быть очень медленными для баз данных большого объема.

### Физический бэкап

-   **Плюсы:**
    -   **Скорость:** Процессы бэкапа и восстановления ограничены только скоростью дисковой подсистемы, что делает их на порядок быстрее логических.
-   **Минусы:**
    -   **Низкая гибкость:** Бэкап жестко привязан к версии MariaDB, архитектуре и конфигурации.
    -   **Сложность:** Требует более аккуратного подхода к настройке и выполнению процедур восстановления.

## Практические сценарии

### Сценарий 1: Стандартный логический бэкап (`mariadb-dump`)

`mariadb-dump` (аналог `mysqldump`) — это стандартная утилита для создания логических бэкапов. Подходит для большинства повседневных задач с базами данных малого и среднего размера.

-   **Создание дампа одной базы данных:**
    ```bash
    mariadb-dump -u <user> -p <database_name> > backup.sql
    ```
-   **Создание дампа всех баз данных:**
    ```bash
    mariadb-dump -u <user> -p --all-databases > all_databases_backup.sql
    ```
-   **Восстановление из дампа:**
    ```bash
    mariadb -u <user> -p <database_name> < backup.sql
    ```

### Сценарий 2: Высокопроизводительный логический бэкап (`mydumper` и `myloader`)

`mydumper` и `myloader` — это комплект утилит для параллельного выполнения логического резервного копирования и восстановления. `mydumper` разбивает таблицы на части (чанки) и выгружает их в несколько потоков, а `myloader` аналогичным образом загружает их. Это решение значительно превосходит `mariadb-dump` по скорости на больших базах данных.

-   **Создание дампа:**
    ```bash
    # Указывается каталог, куда будут сохранены файлы дампа
    mydumper --database=<db_name> --outputdir=/path/to/dump/ -u <user> -p --threads=4
    ```
-   **Восстановление:**
    ```bash
    myloader --directory=/path/to/dump/ -u <user> -p --threads=4
    ```

### Сценарий 3: "Горячий" физический бэкап (`mariabackup`)

`mariabackup` — это форк утилиты Percona XtraBackup, адаптированный для MariaDB. Он позволяет создавать полные бинарные копии базы данных без остановки работы сервера, обеспечивая минимальное влияние на производительность.

Процесс состоит из трех шагов: создание копии, её подготовка и восстановление.

1.  **Создание "сырой" копии (`--backup`):**
    На этом этапе `mariabackup` копирует файлы данных, одновременно отслеживая изменения, которые происходят в базе во время копирования, и записывая их в свой лог.
    ```bash
    mariabackup --backup \
      --target-dir=/path/to/backup/ \
      --user=<user> --password=<password>
    ```

2.  **Подготовка бэкапа (`--prepare`):**
    После создания копии `mariabackup` применяет к ней изменения из своего лога, приводя файлы данных в консистентное состояние на момент окончания бэкапа.
    ```bash
    mariabackup --prepare --target-dir=/path/to/backup/
    ```

3.  **Восстановление (`--copy-back`):**
    Процедура восстановления требует остановки сервера MariaDB и полной очистки директории с данными (`datadir`).
    ```bash
    # 1. Остановить сервис MariaDB
    systemctl stop mariadb

    # 2. (Опционально, но рекомендуется) Сделать копию старых данных
    mv /var/lib/mysql /var/lib/mysql_old

    # 3. Создать пустую директорию данных
    mkdir /var/lib/mysql

    # 4. Скопировать подготовленный бэкап в директорию данных
    mariabackup --copy-back --target-dir=/path/to/backup/

    # 5. Установить правильные права на файлы
    chown -R mysql:mysql /var/lib/mysql

    # 6. Запустить сервис MariaDB
    systemctl start mariadb
    ```

## Дополнительная информация

-   **Совместимость `mariabackup`**: Современные версии `Percona XtraBackup` (для MySQL) несовместимы с MariaDB из-за различий в форматах данных. Для резервного копирования MariaDB необходимо использовать именно утилиту `mariabackup`, которая поставляется вместе с ней.
-   **Установка `mydumper`**: `mydumper` обычно не входит в стандартную поставку MariaDB и устанавливается как отдельный пакет из репозиториев вашего дистрибутива.
