# Резервное копирование и восстановление в MariaDB

Специфичные для MariaDB инструменты и подходы. Общие теоретические основы (логические/физические, горячие/холодные бэкапы) — в **[Стратегии резервного копирования баз данных](../Concepts/backups.md)**.

## Определения

**`mariadb-dump`** (аналог `mysqldump`) — стандартная утилита для создания **логических** бэкапов. Подходит для большинства повседневных задач с базами данных малого и среднего размера.

**`mydumper` и `myloader`** — комплект утилит для высокопроизводительного **логического** резервного копирования и восстановления. `mydumper` выполняет выгрузку в несколько потоков, `myloader` — параллельную загрузку, что значительно превосходит `mariadb-dump` по скорости на больших БД.

**`mariabackup`** — форк Percona XtraBackup, адаптированный для MariaDB. Утилита для создания "горячих" **физических** бэкапов без остановки работы сервера и с минимальным влиянием на производительность.

## Основные концепции

**Логический и физический бэкап:** `mariadb-dump` и `mydumper` создают логические бэкапы (набор SQL-команд), которые являются гибкими, но медленными для восстановления. `mariabackup` создает физическую копию файлов данных, что обеспечивает очень быстрое восстановление.

**Совместимость `mariabackup`:** Современные версии `Percona XtraBackup` (для MySQL) несовместимы с MariaDB из-за различий в форматах данных. Для резервного копирования MariaDB необходимо использовать именно утилиту `mariabackup`, которая поставляется вместе с ней.

## Практические сценарии

### Сценарий 1: Стандартный логический бэкап (`mariadb-dump`)

- **Создание дампа одной базы данных:**

    ```bash
    mariadb-dump -u <user> -p <database_name> > backup.sql
    ```

- **Создание дампа всех баз данных:**

    ```bash
    mariadb-dump -u <user> -p --all-databases > all_databases_backup.sql
    ```

- **Восстановление из дампа:**

    ```bash
    mariadb -u <user> -p <database_name> < backup.sql
    ```

### Сценарий 2: Высокопроизводительный логический бэкап (`mydumper` и `myloader`)

- **Создание дампа:**

    ```bash
    # Указывается каталог, куда будут сохранены файлы дампа
    mydumper --database=<db_name> --outputdir=/path/to/dump/ -u <user> -p --threads=4
    ```

- **Восстановление:**

    ```bash
    myloader --directory=/path/to/dump/ -u <user> -p --threads=4
    ```

### Сценарий 3: "Горячий" физический бэкап (`mariabackup`)

Процесс состоит из трех шагов: создание копии, её подготовка и восстановление.

1. **Создание "сырой" копии (`--backup`):**
    На этом этапе `mariabackup` копирует файлы данных, отслеживая изменения в лог.

    ```bash
    mariabackup --backup \
      --target-dir=/path/to/backup/ \
      --user=<user> --password=<password>
    ```

2. **Подготовка бэкапа (`--prepare`):**
    Применение изменений из лога для приведения файлов в консистентное состояние.

    ```bash
    mariabackup --prepare --target-dir=/path/to/backup/
    ```

3. **Восстановление (`--copy-back`):**
    Процедура требует остановки сервера и очистки директории с данными (`datadir`).

    ```bash
    # 1. Остановить сервис MariaDB
    systemctl stop mariadb

    # 2. (Опционально) Сделать копию старых данных
    mv /var/lib/mysql /var/lib/mysql_old

    # 3. Создать пустую директорию данных
    mkdir /var/lib/mysql

    # 4. Скопировать подготовленный бэкап
    mariabackup --copy-back --target-dir=/path/to/backup/

    # 5. Установить правильные права
    chown -R mysql:mysql /var/lib/mysql

    # 6. Запустить сервис MariaDB
    systemctl start mariadb
    ```

## Дополнительная информация

**Установка `mydumper`:** `mydumper` обычно не входит в стандартную поставку MariaDB и устанавливается как отдельный пакет из репозиториев вашего дистрибутива.

**Настройка клиента:** Параметры подключения (хост, порт, пользователь) по умолчанию можно задать в конфигурационном файле — подробности в **[Конфигурация MariaDB](configuration.md)**.
