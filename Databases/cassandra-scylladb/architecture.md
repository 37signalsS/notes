# Архитектура: Cassandra vs ScyllaDB

## Сравнительная характеристика (2026)

| Характеристика | Apache Cassandra 5.x/6.x | ScyllaDB 6.x |
| :--- | :--- | :--- |
| **Язык** | Java (JVM) | C++ (Seastar) |
| **Потоки** | Thread-per-request (Sync) | Shard-per-core (Async) |
| **Память** | JVM Heap (GC pauses) | Direct DMA, изолированная память ядер |
| **Масштабирование** | vNodes (медленно) | Tablets (динамично, мгновенно) |
| **Тюнинг** | Ручной (GC, Heap) | Автоматический (I/O Schedulers) |

---

## Архитектура Seastar (ScyllaDB)

Seastar — это фреймворк для высокопроизводительных приложений на C++, использующий модель **share-nothing**. Каждое ядро процессора работает как независимый узел:

- **Изолированная память:** Каждое ядро имеет собственный пул памяти, что исключает конкуренцию за ресурсы и кэши.
- **Асинхронный I/O:** Вместо блокирующих операций используется неблокирующий I/O через `io_uring` (Linux 5.11+). Это позволяет обрабатывать тысячи параллельных запросов без создания потоков.
- **Shard-per-core:** Данные разделены между ядрами. Каждый запрос маршрутизируется на то ядро, которое владеет соответствующим Partition Token. Отсутствие блокировок между ядрами.

---

## Архитектура Cassandra (JVM)

- **Thread-per-request:** Каждый входящий запрос занимает поток из пула. При большом количестве запросов возникает конкуренция за потоки.
- **GC Pauses:** Сборщик мусора Java (G1GC/ZGC) периодически останавливает обработку запросов для очистки памяти. При больших heap размерах (>32 GB) паузы могут достигать сотен миллисекунд.
- **vNodes:** Виртуальные узлы (по умолчанию 256 на физический узел) для более равномерного распределения данных. Перебалансировка при добавлении узлов медленная.

---

## Когда выбирать ScyllaDB vs Cassandra

**ScyllaDB предпочтительнее когда:**
- Критична низкая задержка (P99 < 5мс)
- Высокая пропускная способность (>100K ops/sec на узел)
- Ограничен бюджет на инфраструктуру (меньше узлов для той же нагрузки)
- Есть команда, готовая к управлению C++ конфигурацией

**Cassandra предпочтительнее когда:**
- Нужна максимальная совместимость с существующим кодом
- Команда экспертируется в JVM и Java-экосистеме
- Требуется работа с устаревшими версиями драйверов
