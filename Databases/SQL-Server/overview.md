# SQL Server (MS SQL): Обзор и SRE-перспектива

## Определения

**SQL Server** — реляционная СУБД от компании Microsoft. Начиная с версии 2017, полноценно поддерживает работу в среде Linux (через уровень абстракции PAL), что позволило использовать её в Docker и Kubernetes.

**PAL (Platform Abstraction Layer)** — программная прослойка, которая переводит системные вызовы Windows в вызовы Linux, обеспечивая работу движка SQL Server без потери производительности.

**SQL Server 2025 (v17.x)** — актуальная версия (2026 г.), ориентированная на "cloud-native" эксплуатацию, нативную поддержку cgroup v2 и улучшенную интеграцию с Linux-стеком.

---

## Архитектура и компоненты

1.  **Database Engine:** Основная служба обработки данных, управления памятью и выполнения запросов.
2.  **SQL Server Agent:** Планировщик задач (Job), используемый для автоматизации бэкапов и обслуживания.
3.  **mssql-conf:** Утилита командной строки для конфигурации параметров сервера в Linux (аналог реестра/sp_configure).

## Специфика лицензирования (SRE-контекст 2026)

Лицензирование Microsoft остается одним из самых сложных аспект при проектировании инфраструктуры.

### 1. Модели лицензирования
*   **Per Core (Поядерная):** Основная модель для SRE. Требует лицензирования всех ядер, на которых запущен SQL Server. 
    *   *Минимум:* 4 ядра на инстанс (VM или контейнер).
    *   *Преимущество:* Неограниченное количество пользователей/устройств.
*   **Server + CAL:** Лицензия на инстанс + клиентские лицензии (CAL) на каждого пользователя. Подходит только для малых внутренних систем (Standard Edition).

### 2. Software Assurance (SA) и контейнеризация
В 2026 году наличие **Software Assurance (SA)** является обязательным требованием для:
*   **Лицензирования отдельных контейнеров/VM:** Без SA вы обязаны лицензировать все физические ядра хоста.
*   **License Mobility:** Право перемещать контейнеры между узлами Kubernetes без покупки новых лицензий.
*   **Failover Rights:** SA дает право на бесплатную лицензию для пассивной реплики в группе Always On (при условии совпадения количества ядер с основной).

### 3. Нюансы в Kubernetes
Для соблюдения комплаенса в K8s SRE должен:
1.  Использовать `nodeSelector` или `Taints`, чтобы ограничить запуск SQL Server на конкретных лицензированных узлах.
2.  Настраивать `limits.cpu` в соответствии с купленными лицензиями (кратно 2, минимум 4).

## Практические сценарии выбора версии

| Редакция | Ограничения | Ключевые SRE-функции |
| :--- | :--- | :--- |
| **Enterprise** | Без лимитов | Always On AG (multi-node), Online Index Rebuild, In-Memory OLTP. |
| **Standard** | 24 ядра, 128 ГБ RAM | Basic Availability Groups (2 узла, 1 БД). |
| **Developer** | Только для разработки | Полный функционал Enterprise. Бесплатна. |
