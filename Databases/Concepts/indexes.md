# Индексы

## 1. Определения

**Индекс** — это специальная структура данных, связанная с таблицей базы данных, предназначенная для ускорения операций поиска и извлечения данных. Индексы работают по принципу предметного указателя в книге или каталога в библиотеке.

## 2. Основные концепции

Индекс содержит упорядоченный набор значений из одного или нескольких столбцов таблицы и указатели на физическое расположение соответствующих строк данных. Это позволяет СУБД быстро находить нужные строки без полного сканирования всей таблицы.

*   **Как это работает:** Вместо того чтобы просматривать каждую запись в таблице, СУБД обращается к индексу, который быстро указывает на точное местоположение искомых данных.
*   **Аналогия:** Библиотечный каталог, где каждой книге соответствует карточка с указанием, на какой полке она находится. Чтобы найти книгу, вы используете каталог (индекс), а не просматриваете все книги подряд.

## 3. Практические сценарии

Индексы наиболее эффективны в следующих случаях:

*   **Ускорение запросов `SELECT`**: Значительно сокращают время выполнения запросов с фильтрацией (`WHERE`), сортировкой (`ORDER BY`) и соединениями (`JOIN`) по индексированным столбцам.
*   **Обеспечение уникальности данных**: Уникальный индекс (например, для email-адресов) гарантирует отсутствие дубликатов.
*   **Поддержка целостности данных**: Используются для реализации первичных (`PRIMARY KEY`) и внешних (`FOREIGN KEY`) ключей.

**Пример создания индекса (SQL):**
```sql
CREATE INDEX idx_users_lastname ON users (last_name);
```

## 4. Продвинутые детали: Проблемы избыточного индексирования

Несмотря на очевидную пользу, наличие большого количества индексов может привести к серьезным проблемам с производительностью.

*   **Накладные расходы при записи (`INSERT`, `UPDATE`, `DELETE`):** Каждая операция записи в таблицу требует обновления *всех* связанных с ней индексов. Это кратно увеличивает объем дисковых операций и время блокировки.
*   **Накладные расходы на обслуживание:** При интенсивной записи структура индексов может деградировать (фрагментироваться), что требует периодической перестройки (`REINDEX`), ресурсоемкой операции.
*   **Увеличение размера базы данных:** Индексы занимают значительное дисковое пространство, иногда превышающее объем самих данных.
*   **Затраты на поддержку статистики:** Оптимизатор запросов полагается на статистику по данным. При частых изменениях статистика устаревает, и ее обновление требует дополнительных ресурсов. Неактуальная статистика может привести к выбору неэффективного плана запроса.

**Важно**: Индексы — это мощный инструмент для ускорения чтения, но **неиспользуемые индексы приносят только вред**, создавая накладные расходы без какой-либо пользы. Их необходимо регулярно находить и удалять.
