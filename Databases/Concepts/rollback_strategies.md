# Стратегии отката в базах данных

## Определения

**Откат (Rollback)** — это операция возврата базы данных или её части в предыдущее стабильное состояние при обнаружении ошибок, сбоев или неудачных изменений.

**Точка отката (Rollback Point / Restore Point)** — заранее подготовленный ориентир (метка, транзакция или снимок), к которому можно безопасно вернуться. Использование точек отката позволяет минимизировать время восстановления и предотвратить потерю данных при проведении рискованных операций (например, релизов или миграций).

## Основные концепции

Откат может выполняться на различных уровнях инфраструктуры. Выбор уровня зависит от критичности изменений и требуемой скорости восстановления.

### Уровни и механизмы отката

| Уровень | Механизм | Область действия | Особенности |
| :--- | :--- | :--- | :--- |
| **Транзакция** | `SAVEPOINT`, `ROLLBACK` | Текущая сессия пользователя | Самый быстрый способ; не работает после завершения транзакции (`COMMIT`). |
| **База данных** | **PITR (Point-in-Time Recovery)** | Вся база данных | Восстановление на произвольный момент времени через журналы (**WAL** или **Binlog**). |
| **Хранилище** | Снапшоты (**LVM**, **ZFS**, облачные снимки) | Дисковый том / файловая система | Мгновенный откат состояния всех файлов; может потребовать остановки СУБД для консистентности. |
| **Приложение** | **Down-миграции**, Feature Flags | Логика и схема данных | Позволяет откатить структурные изменения или функционал без восстановления всей БД. |

### Транзакционный откат

Обеспечивает атомарность изменений в рамках одной сессии. Если часть логики внутри транзакции завершилась ошибкой, можно откатить изменения либо полностью, либо до промежуточной точки (**SAVEPOINT**), не разрывая соединение. Подробнее о свойствах транзакций: **[ACID](./acid.md)**.

## Практические сценарии

### 1. Использование транзакционных точек (SAVEPOINT)

Применяется при батч-обработке данных, когда ошибка в одном пакете не должна прерывать работу всего процесса.

```sql
BEGIN;

-- Шаг 1: Основные изменения
UPDATE accounts SET balance = balance - 100 WHERE id = 1;

-- Создаем точку сохранения
SAVEPOINT before_bulk_update;

-- Шаг 2: Массовое обновление (рискованное)
UPDATE accounts SET balance = balance + 100 WHERE category = 'temporary';

-- Если обнаружили ошибку в Шаге 2:
ROLLBACK TO SAVEPOINT before_bulk_update;

-- Продолжаем работу с Шага 1
COMMIT;
```

### 2. Именованные точки восстановления (PostgreSQL)

Перед выполнением потенциально опасной операции (например, ручного исправления данных) можно создать именованную метку в журнале транзакций.

```sql
-- На мастере создаем метку
SELECT pg_create_restore_point('pre_data_fix_2025_03_25');

-- Если данные повреждены, можно восстановиться до этой метки через PITR.
```
