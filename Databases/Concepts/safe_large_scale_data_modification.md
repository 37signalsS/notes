# Как безопасно удалить или изменить миллион строк в базе данных?

Прямое выполнение операции `DELETE` для удаления или изменения большого количества строк (например, миллиона) может привести к серьезным проблемам с производительностью и доступностью базы данных. Основные риски:

-   **Блокировки таблицы:** `DELETE` может наложить длительные блокировки на таблицу, делая ее недоступной для других операций.
-   **Повышенная нагрузка:** Операция создает высокую нагрузку на процессор, ввод-вывод и лог транзакций, что замедляет общую производительность всей базы данных.
-   **Раздувание лога транзакций:** Удаление большого количества строк за одну транзакцию может привести к переполнению лога.

## Стратегии безопасного выполнения

### 1. Порционное удаление/изменение (Batching)

Это самый распространенный и рекомендуемый подход.

-   **Суть:** Операция разбивается на небольшие части (пакеты или "порции"), которые выполняются последовательно. Например, удалять по 1000-5000 записей за раз.
-   **Реализация:**
    -   Используйте цикл (`WHILE` или в коде приложения), который удаляет ограниченное количество строк (`LIMIT`) в каждой итерации.
    -   Каждую порцию выполняйте в отдельной транзакции.
    -   Чтобы снизить пиковую нагрузку, можно добавить небольшую задержку между транзакциями (например, 1 секунду).

```sql
-- Пример для PostgreSQL
DO $$
BEGIN
  WHILE EXISTS (SELECT 1 FROM your_table WHERE condition LIMIT 1) LOOP
    DELETE FROM your_table WHERE ctid IN (
      SELECT ctid FROM your_table WHERE condition LIMIT 1000
    );
    COMMIT; -- Фиксируем транзакцию после каждой пачки
    PERFORM pg_sleep(1); -- Небольшая пауза
  END LOOP;
END $$;
```

### 2. Создание новой таблицы (Create, Copy, Rename, Drop)

В некоторых случаях этот метод может быть значительно быстрее, особенно если нужно удалить большую часть таблицы.

-   **Суть:** Вместо удаления ненужных данных, вы копируете нужные данные в новую таблицу.
-   **Шаги:**
    1.  **Создать временную таблицу** с той же структурой, что и у исходной (`CREATE TABLE new_table AS SELECT * FROM old_table WHERE 1=0;`).
    2.  **Скопировать нужные данные** из старой таблицы в новую (`INSERT INTO new_table SELECT * FROM old_table WHERE <условие_для_сохранения_данных>;`).
    3.  **Переименовать таблицы:** Атомарно поменять местами старую и новую таблицы (`ALTER TABLE old_table RENAME TO old_table_to_drop; ALTER TABLE new_table RENAME TO old_table;`). Это минимизирует время простоя.
    4.  **Удалить старую таблицу** (`DROP TABLE old_table_to_drop;`).

### 3. Планирование и подготовка

-   **Резервная копия:** **Всегда** создавайте резервную копию перед выполнением массовых операций с данными.
-   **Окно обслуживания:** Найдите время, когда нагрузка на базу данных минимальна (как правило, ночное время), чтобы минимизировать влияние на пользователей.
-   **Мониторинг:** Внимательно следите за метриками производительности базы данных во время выполнения операции.
