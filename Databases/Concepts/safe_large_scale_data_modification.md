# Безопасные массовые операции с данными

## Определения

**Массовые операции с данными** — это запросы `UPDATE` (обновление) или `DELETE` (удаление), затрагивающие очень большое количество строк (тысячи, миллионы и более) в рамках одной транзакции. Их безопасное выполнение критически важно для поддержания производительности и доступности базы данных.

Перед выполнением любых массовых операций необходимо создать **[резервную копию](./backups.md)** базы данных.

## Основные концепции

Прямое выполнение массовых операций в одной транзакции почти всегда приводит к деградации производительности СУБД (Системы Управления Базами Данных).

**Основные риски:**

- **Длительные блокировки:** Операция может заблокировать таблицу на длительное время, делая её недоступной для других запросов.
- **Высокая нагрузка:** Создается пиковая нагрузка на **CPU (Central Processing Unit)** и дисковый **I/O (Input/Output)**, что замедляет работу всей системы.
- **Раздувание журнала предзаписи:** Запись миллионов изменений в **WAL (Write-Ahead Log)** или **Binlog** за одну транзакцию может привести к переполнению диска и сбоям репликации.
- **Потребление памяти:** Большие транзакции требуют значительных ресурсов оперативной памяти для хранения промежуточных состояний.

## Практические сценарии: Стратегии безопасного выполнения

### 1. Порционное выполнение (Batching)

Это наиболее рекомендуемый подход для большинства систем. Операция разбивается на небольшие пакеты (батчи), которые выполняются последовательно в отдельных транзакциях.

- **Суть:** Обработка по 1000–10000 строк за итерацию.
- **Преимущества:** Минимизация блокировок и распределение нагрузки во времени.
- **Реализация:** Использование циклов в приложении или хранимых процедурах с обязательным `COMMIT` (фиксацией) после каждого пакета.

```sql
-- Пример порционного удаления для PostgreSQL
DO $$
BEGIN
  LOOP
    -- Выполняем операцию над небольшой пачкой строк
    DELETE FROM your_table WHERE ctid IN (
      SELECT ctid FROM your_table WHERE status = 'old' LIMIT 5000
    );

    -- Если ни одна строка не была затронута, выходим из цикла
    EXIT WHEN NOT FOUND;

    COMMIT; -- Фиксируем транзакцию после каждой пачки
    PERFORM pg_sleep(1); -- Пауза между батчами для снижения нагрузки на I/O
  END LOOP;
END $$;
```

### 2. Пересоздание таблицы (Swap Table)

Метод эффективен, когда нужно изменить или удалить более 50–70% данных в таблице.

- **Суть:** Вместо удаления ненужного, вы копируете *нужные* данные в новую таблицу, а затем меняете их местами.
- **Шаги:**
    1. Создание новой таблицы со структурой старой (`CREATE TABLE new_table (LIKE old_table INCLUDING ALL)`).
    2. Копирование данных (`INSERT INTO new_table SELECT * FROM old_table WHERE <условие_сохранения>`).
    3. Атомарное переименование таблиц в одной транзакции (`ALTER TABLE old_table RENAME TO old_table_backup; ALTER TABLE new_table RENAME TO old_table;`).
    4. Удаление старой таблицы (`DROP TABLE old_table_backup`).

## Дополнительная информация

При планировании массовых операций учитывайте:

- **Окно обслуживания:** Время минимальной активности пользователей.
- **Мониторинг:** Наблюдение за лагом репликации и размером WAL во время выполнения.
- **Тестирование:** Обязательная проверка скрипта на копии данных аналогичного объема.
