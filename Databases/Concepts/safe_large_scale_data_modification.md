# Безопасные массовые операции с данными

## 1. Основные концепции: Риски

Прямое выполнение `DELETE` или `UPDATE` для большого количества строк (например, миллионов) в одной транзакции почти всегда приводит к серьезным проблемам с производительностью и доступностью базы данных.

**Основные риски:**
-   **Длительные блокировки:** Массовая операция может заблокировать таблицу на долгое время, делая ее недоступной для других запросов.
-   **Высокая нагрузка:** Создается пиковая нагрузка на CPU, дисковый I/O и лог транзакций, что замедляет работу всей СУБД.
-   **Раздувание лога транзакций:** Запись миллионов изменений в лог за одну транзакцию может привести к его переполнению и сбоям.

## 2. Практические сценарии: Стратегии безопасного выполнения

### Стратегия 1: Порционное выполнение (Batching)

Это самый распространенный и рекомендуемый подход.

-   **Суть:** Операция разбивается на небольшие части (пакеты по 1000-10000 строк), которые выполняются последовательно в отдельных коротких транзакциях.
-   **Реализация:**
    -   Используется цикл (`WHILE` в хранимой процедуре или в коде приложения), который изменяет/удаляет ограниченное количество строк (`LIMIT`) в каждой итерации.
    -   Между транзакциями можно добавить небольшую задержку (например, 1 секунду), чтобы снизить пиковую нагрузку.

```sql
-- Пример порционного удаления для PostgreSQL
DO $$
BEGIN
  LOOP
    -- Выполняем операцию над небольшой пачкой строк
    DELETE FROM your_table WHERE ctid IN (
      SELECT ctid FROM your_table WHERE <condition> LIMIT 1000
    );

    -- Если ни одна строка не была затронута, выходим из цикла
    EXIT WHEN NOT FOUND;

    COMMIT; -- Фиксируем транзакцию после каждой пачки
    PERFORM pg_sleep(1); -- Делаем паузу, чтобы не перегружать систему
  END LOOP;
END $$;
```

### Стратегия 2: Пересоздание таблицы

Этот метод может быть значительно быстрее, особенно если нужно удалить большую часть таблицы, а не изменить.

-   **Суть:** Вместо удаления ненужных данных, вы копируете *нужные* данные в новую таблицу.
-   **Шаги:**
    1.  **Создать новую таблицу** с той же структурой, что и у исходной (`CREATE TABLE new_table (LIKE old_table INCLUDING ALL);`).
    2.  **Скопировать нужные данные** из старой таблицы в новую (`INSERT INTO new_table SELECT * FROM old_table WHERE <условие_для_сохранения_данных>;`).
    3.  **Атомарно переименовать таблицы:** В рамках одной транзакции поменять местами старую и новую таблицы, что минимизирует время простоя.
    4.  **Удалить старую таблицу** (`DROP TABLE old_table_to_drop;`).

## 3. Продвинутые детали: Планирование

-   **Резервная копия:** **Всегда** создавайте резервную копию перед выполнением массовых операций с данными.
-   **Окно обслуживания:** Найдите время, когда нагрузка на базу данных минимальна, чтобы снизить влияние на пользователей.
-   **Мониторинг:** Внимательно следите за ключевыми метриками СУБД (нагрузка на CPU, I/O, состояние блокировок) во время выполнения операции.
