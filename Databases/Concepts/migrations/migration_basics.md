# Миграции баз данных: Основы

## Определения

**Миграция базы данных** — это управляемый процесс внесения изменений в схему базы данных (добавление, изменение или удаление таблиц, индексов, ограничений) с сохранением существующих данных и обеспечением целостности системы.

**Откат (Rollback)** — процесс возврата схемы и данных базы данных к предыдущему состоянию при обнаружении ошибок в примененной миграции.

## Основные концепции

### Зачем нужны миграции

Миграции решают проблему синхронизации структуры БД между различными окружениями (development, staging, production) и разными участниками команды разработки.

**Проблемы без миграций:**

- **Несогласованность схем:** на production может отсутствовать колонка, добавленная локально.
- **Потеря данных:** при ручном выполнении `ALTER TABLE` высок риск человеческой ошибки.
- **Невоспроизводимость:** невозможно быстро развернуть чистую базу данных актуальной структуры.
- **Сложность совместной работы:** конфликты при одновременном изменении одной таблицы разными разработчиками.

### Типы миграций

1. **Схемные миграции (Schema Migrations):** изменяют структуру. Используют операции **DDL (Data Definition Language)**. Примеры: `CREATE TABLE`, `ALTER TABLE`, `DROP INDEX`.
2. **Миграции данных (Data Migrations):** изменяют содержимое таблиц. Используют операции **DML (Data Manipulation Language)**. Примеры: трансформация форматов строк, заполнение новых полей на основе старых.
3. **Начальные данные (Seed Migrations):** заполнение справочников или создание административных учетных записей.

Подробнее о различиях операций: **[DDL vs DML](../Concepts/DDL_vs_DML.md)**.

### Инструменты миграций

Выбор инструмента зависит от используемого языка программирования и требований к управлению схемой.

| Инструмент | Язык | Особенности |
| :--- | :--- | :--- |
| **Flyway** | Java / CLI | SQL-first подход, строгая версионируемость. |
| **Liquibase** | Java / CLI | Поддержка XML, YAML, JSON и SQL; абстракция от диалекта СУБД. |
| **Alembic** | Python | Интеграция с SQLAlchemy, возможность автогенерации миграций. |
| **Django Migrations** | Python | Встроены в Django ORM, декларативный подход. |
| **Prisma Migrate** | TypeScript | Декларативное описание схемы, автоматическая генерация SQL. |
| **golang-migrate** | Go | Легковесный инструмент, поддержка множества драйверов БД. |
| **Atlas** | Go / CLI | Современный инструмент с поддержкой Schema-as-Code и GitOps. |

## Практические сценарии

### Примеры схемных миграций

```sql
-- Создание таблицы пользователей
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Добавление новой колонки
ALTER TABLE users ADD COLUMN phone VARCHAR(20);

-- Создание индекса для ускорения поиска
CREATE INDEX idx_users_email ON users(email);
```

### Примеры миграций данных

```sql
-- Объединение имени и фамилии в одно поле
UPDATE users 
SET full_name = first_name || ' ' || last_name
WHERE full_name IS NULL;

-- Первичное наполнение таблицы статистики
INSERT INTO user_stats (user_id, order_count)
SELECT user_id, COUNT(*) 
FROM orders 
GROUP BY user_id;
```

### Примеры начальных данных (Seed)

```sql
-- Заполнение справочника стран
INSERT INTO countries (code, name) VALUES 
('US', 'United States'),
('UK', 'United Kingdom'),
('RU', 'Russian Federation');
```

## Дополнительная информация

### Рекомендации

- **Версионирование:** всегда используйте строгую нумерацию или временные метки (timestamp) в именах файлов.
- **Транзакции:** оборачивайте миграции в транзакции, если СУБД это поддерживает (например, PostgreSQL).
- **Идемпотентность:** миграции должны быть написаны так, чтобы повторный запуск не приводил к ошибкам (например, `CREATE TABLE IF NOT EXISTS`).
