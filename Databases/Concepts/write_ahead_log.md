# Журнал предзаписи (Write-Ahead Log, WAL)

## Определения

**Журнал предзаписи (Write-Ahead Log, WAL)** — это стандартный механизм обеспечения целостности и долговечности данных, являющийся основой принципа **Durability** в **[ACID (Atomicity, Consistency, Isolation, Durability)](./acid.md)**.

**Чекпоинт (Checkpoint)** — это фоновый процесс, в ходе которого измененные ("грязные") страницы данных из оперативной памяти записываются в основные файлы базы данных на диске.

## Основные концепции

Основной принцип WAL заключается в том, что **изменения в данных должны быть записаны в специальный журнал *перед* тем, как они будут записаны в основные файлы базы данных.** Этот принцип "сначала запиши в журнал" позволяет существенно повысить производительность и надежность системы.

Это позволяет отделить быструю операцию фиксации транзакции (последовательная запись в конец лога) от медленной операции записи изменений в множество разных мест на диске (случайная запись).

### Решаемые проблемы

* **Производительность:** Запись в случайные места на диске — медленная операция. WAL заменяет множество случайных записей одной быстрой последовательной записью в файл журнала.
* **Надежность (восстановление после сбоев):** Если во время записи произошел сбой (отключение питания), СУБД после перезапуска читает WAL, находит зафиксированные транзакции, которые не успели попасть в файлы данных, и "накатывает" (replays) их.
* **Основа для репликации:** Поток событий WAL является источником данных для **[репликации](./replication.md)**. Master-сервер отправляет содержимое WAL на реплики, которые "проигрывают" эти события, поддерживая актуальное состояние данных.

## Практический сценарий: Жизненный цикл транзакции

1. **Запрос на изменение:** Клиент отправляет команду (`UPDATE`, `INSERT` или `DELETE`).
2. **Запись в журнал:** СУБД сначала добавляет запись об изменении в конец файла WAL. Это быстрая последовательная операция.
3. **Изменение в памяти:** После записи в WAL СУБД обновляет данные в оперативной памяти.
4. **Подтверждение:** Только после фиксации записи в журнале на диске СУБД сообщает клиенту об успешном выполнении.
5. **Чекпоинт:** Измененные страницы из памяти сбрасываются в основные файлы данных позже, во время очередного чекпоинта.

## Дополнительная информация

### Особенности WAL в PostgreSQL

* **Архивирование:** Для **PITR (Point-In-Time Recovery)** — восстановления на точку во времени — необходимо настроить архивирование WAL-сегментов. См. **[Резервное копирование и восстановление](../PostgreSQL/Concepts/backup_and_recovery.md)**.
* **Настройка:** Параметры `wal_buffers`, `checkpoint_timeout`, `max_wal_size` напрямую влияют на производительность записи. См. **[Performance Tuning](../PostgreSQL/Operations/performance_tuning.md)**.
* **Слоты репликации:** Механизм `replication slot` предотвращает удаление старых WAL, пока они не будут получены всеми репликами. См. **[Репликация в PostgreSQL](../PostgreSQL/Concepts/replication.md)**.
