# Обзор Redis

## Модель данных
Redis — это хранилище данных типа ключ-значение, поддерживающее богатый набор структур: строки, хэши, списки, множества, отсортированные множества, битовые поля, HyperLogLog, геоиндексы и потоки. 

Для экономии памяти применяются внутренние кодеки (listpack/ziplist, intset, quicklist). Все операции над структурами данных атомарны.

## Управление памятью
Redis опирается на аллокатор `jemalloc` и использует объектные обертки. Небольшие коллекции упаковываются компактно, но накладные расходы на метаданные выше для каждого ключа и элемента. Возможна фрагментация памяти; для борьбы с ней доступны `active defrag` и настройка `maxmemory`. 

Поддерживаются следующие политики высвобождения памяти: `noeviction`, `allkeys-lru`, `allkeys-lfu`, `allkeys-random`, `volatile-lru`, `volatile-lfu`, `volatile-random`, `volatile-ttl`.

## TTL и протокол «старения»
Redis хранит TTL для каждого ключа с миллисекундной точностью. Истечение ключей происходит двумя способами:
1.  **Пассивно:** при попытке доступа к ключу с истекшим TTL.
2.  **Активно:** в фоновом режиме Redis выборочно проверяет ключи; долю CPU для этого процесса можно настраивать.

## Устойчивость и перезапуски
Redis поддерживает два механизма персистентности:
1.  **RDB (snapshotting):** создание снапшотов базы данных через определённые интервалы.
2.  **AOF (Append-only file):** журналирование всех операций записи.

Возможно их сочетание. Это позволяет восстанавливать состояние кеша после перезапуска, используя его как «источник правды» или для ускорения холодного старта. Недостатки: потребление дискового пространства, влияние на память (механизм copy-on-write) и нагрузка на I/O (fsync).

## Масштабирование и консистентность
*   **Репликация:** поддержка master-slave репликации.
*   **Sentinel:** обеспечивает высокую доступность и автоматический failover.
*   **Redis Cluster:** обеспечивает шардирование с распределением ключей по хэш-слотам и автоматическим переназначением партиций.
Транзакции и Lua-скрипты выполняются атомарно в пределах одного узла кластера.

## Профиль производительности
Redis использует однопоточную модель для выполнения команд с неблокирующим вводом-выводом и поддержкой пайплайнинга. Это обеспечивает высокую производительность в сценариях, где требуются атомарные операции над сложными структурами данных и минимизация сетевого трафика между приложением и кешем.
