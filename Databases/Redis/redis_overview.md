# Redis

### Определения

**Redis (Remote Dictionary Server)** — это быстрое хранилище данных с открытым исходным кодом, работающее в оперативной памяти. Redis используется как база данных, кэш, брокер сообщений и очередь. Отличительной чертой является поддержка разнообразных структур данных.

---

### Основные концепции

#### Модель данных

Redis — это хранилище данных типа «ключ-значение», поддерживающее богатый набор структур:

- **Строки (Strings):** Текстовые или бинарные данные размером до 512 МБ.
- **Списки (Lists):** Коллекции строковых элементов, упорядоченные по порядку вставки.
- **Множества (Sets):** Неупорядоченные коллекции уникальных строк.
- **Хэши (Hashes):** Карты (map) для хранения полей и их значений.
- **Сортированные множества (Sorted Sets):** Множества, где каждый элемент ассоциирован с числовым значением (score) для сортировки.
- **Битовые поля (Bitmaps) и HyperLogLog:** Структуры для работы с битовыми операциями и подсчета уникальных элементов с минимальным использованием памяти.
- **Геоиндексы (Geospatial indexes):** Для работы с пространственными данными.
- **Потоки (Streams):** Структура для управления логами или очередями событий.

Для экономии памяти применяются внутренние кодеки (listpack/ziplist, intset, quicklist). Все операции над структурами данных атомарны.

#### Управление памятью

Redis опирается на аллокатор `jemalloc` и использует объектные обертки. Небольшие коллекции упаковываются компактно, но накладные расходы на метаданные выше для каждого ключа и элемента. Возможна фрагментация памяти; для борьбы с ней доступны `active defrag` и настройка `maxmemory`.

Поддерживаются следующие политики вытеснения ключей (`maxmemory-policy`): `noeviction`, `allkeys-lru`, `allkeys-lfu`, `allkeys-random`, `volatile-lru`, `volatile-lfu`, `volatile-random`, `volatile-ttl`.

#### TTL (Time-To-Live) и старение данных

Redis хранит TTL для каждого ключа с миллисекундной точностью. Истечение ключей происходит двумя способами:

1. **Пассивно:** при попытке доступа к ключу с истекшим TTL.
2. **Активно:** в фоновом режиме Redis выборочно проверяет ключи; долю CPU для этого процесса можно настраивать.

#### Устойчивость (Персистентность)

Redis поддерживает два механизма сохранения данных на диск:

1. **RDB (Snapshotting):** Создание снапшотов базы данных через определённые интервалы.
2. **AOF (Append-Only File):** Журналирование всех операций записи.

Возможно их сочетание для баланса между производительностью и надежностью. Это позволяет восстанавливать состояние после перезапуска.

#### Масштабирование и высокая доступность

- **Репликация:** Асинхронная master-slave репликация.
- **Sentinel:** Обеспечивает высокую доступность и автоматическое переключение на реплику (failover).
- **Redis Cluster:** Обеспечивает шардирование с распределением ключей по хэш-слотам и автоматическим переназначением партиций.

Транзакции (`MULTI`/`EXEC`) и Lua-скрипты выполняются атомарно в пределах одного узла кластера.

### Практические сценарии

Redis использует однопоточную модель для выполнения команд с неблокирующим вводом-выводом, что обеспечивает высокую производительность.

Основные сценарии использования:

- **Кеширование:** Хранение часто запрашиваемых данных для снижения нагрузки на основные БД.
- **Очереди задач:** Использование списков (команды `LPUSH`/`RPOP`) для реализации простых очередей.
- **Счетчики и аналитика в реальном времени:** Атомарные операции (`INCR`) для подсчета событий.
- **Сессии пользователей:** Быстрое хранение и доступ к данным сессий.
- **Реализация блокировок (Distributed Locks):** Создание распределенных блокировок.
- **Pub/Sub:** Использование в качестве брокера сообщений.
