# SQLite: Обзор и применение в SRE и Edge-вычислениях

## Определения

**SQLite** — компактная, встраиваемая, полнофункциональная реляционная СУБД. В отличие от клиент-серверных СУБД (PostgreSQL, MySQL), SQLite не является отдельным процессом; это библиотека, которая работает внутри приложения и хранит всю базу данных в одном кроссплатформенном файле на диске.

*   **Zero-Configuration:** Не требует установки, настройки сервера или управления пользователями.
*   **Serverless:** Приложение напрямую читает и пишет файлы базы данных.
*   **Single-file format:** Вся БД (схемы, индексы, данные) упакована в один файл.

## Базовые концепции

### Место SQLite в современной инфраструктуре (2026)

Несмотря на простоту, SQLite стал критически важным инструментом для SRE и Platform-инженеров в следующих областях:

1.  **Edge-вычисления и IoT:** Идеален для устройств с ограниченными ресурсами, где запуск тяжелого сервера БД невозможен.
2.  **Configuration Storage:** Используется как надежное хранилище настроек (Grafana, K3s через Kine, Podman).
3.  **Local-First приложения:** Обеспечивает работу приложения без интернета с последующей синхронизацией.
4.  **Эфемерные среды:** Идеален для CI/CD тестов, где нужно мгновенно создать и уничтожить БД.

### Архитектура и надежность

*   **Транзакционность (ACID):** SQLite полностью поддерживает ACID-транзакции даже при сбоях питания или системы.
*   **Manifest Typing:** Динамическая типизация (тип привязан к значению, а не к колонке), что упрощает работу с гибкими схемами данных.
*   **VFS (Virtual File System):** Абстрактный слой для работы с хранилищем, позволяющий SQLite работать поверх облачных хранилищ или зашифрованных разделов.

## Преимущества и ограничения

| Преимущество | Ограничение |
| :--- | :--- |
| **Нулевой оверхед** на сеть и управление. | **Ограниченная конкуренция:** По умолчанию один писатель блокирует всех читателей. |
| **Высокая скорость чтения** (часто быстрее клиент-серверных БД). | **Отсутствие RBAC:** Права доступа управляются на уровне ФС. |
| **Простота бэкапа:** Копирование одного файла. | **Не для Big Data:** Не рекомендуется для баз > 1 ТБ. |

## Практические сценарии

### 1. Проверка целостности файла (SRE-чекап)
Если файл БД кажется поврежденным (например, после OOM в приложении):
```bash
sqlite3 mydata.db "PRAGMA integrity_check;"
# → ok (если всё в порядке)
```

### 2. Экспорт данных в SQL
Для миграции на PostgreSQL или отладки:
```bash
sqlite3 mydata.db .dump > backup.sql
```
