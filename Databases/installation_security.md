# Безопасная установка СУБД

## Определения

**Безопасная установка (Hardening)** — процесс начальной настройки SQL-сервера после инсталляции, направленный на устранение уязвимостей по умолчанию и усиление защищенности системы.

**`mysql_secure_installation`** — интерактивная утилита командной строки, поставляемая с MariaDB и MySQL, которая автоматизирует основные шаги по обеспечению безопасности сервера.

## Основные концепции

После первичной установки SQL-сервера критически важно выполнить базовую настройку безопасности. Это включает устранение стандартных уязвимостей:

- Анонимные пользователи
- Тестовые базы данных
- Небезопасные пароли по умолчанию
- Разрешение удалённого доступа для root

Большинство SQL-серверов предоставляют встроенные инструменты для начальной настройки безопасности.

## Практические сценарии

### MySQL / MariaDB: Использование `mysql_secure_installation`

**Запуск утилиты:**

```bash
sudo mysql_secure_installation
# -> Securing the MySQL server deployment.
# -> Enter current password for root (enter for none):
```

**Последовательность действий:**

| Шаг | Описание | Рекомендация |
| :--- | :--- | :--- |
| **VALIDATE PASSWORD COMPONENT** | Настройка проверки сложности паролей | Включить для production |
| **Смена пароля root** | Установка надежного пароля для администратора | Обязательно |
| **Удаление анонимных пользователей** | Удаление учётных записей без пароля | Обязательно |
| **Запрет удалённого доступа root** | Блокировка подключения root извне | Обязательно |
| **Удаление тестовой БД** | Удаление БД `test`, доступной всем | Обязательно |
| **Перезагрузка привилегий** | Применение изменений | Обязательно |

Подробнее: **[Установка MySQL](./MySQL/installation.md)**, **[Установка MariaDB](./MariaDB/installation_and_setup.md)**.

### PostgreSQL: Ручная настройка безопасности

PostgreSQL использует другую модель безопасности. После установки:

```bash
# Подключение к PostgreSQL
sudo -u postgres psql
# -> psql (14.x)
# -> Type "help" for help.
```

```sql
-- Создание нового пользователя с правами суперпользователя
CREATE USER admin WITH PASSWORD 'secure_password';
-- -> CREATE ROLE

ALTER USER admin WITH SUPERUSER;
-- -> ALTER ROLE

-- Удаление публичного доступа к схеме
REVOKE ALL ON SCHEMA public FROM PUBLIC;
-- -> REVOKE
```

**Настройка `pg_hba.conf`:**

```conf
# Локальное подключение через peer-аутентификацию
local   all   postgres   peer

# Требовать пароль для сетевых подключений
host    all   all   127.0.0.1/32   scram-sha-256
host    all   all   ::1/128        scram-sha-256
```

**Настройка `postgresql.conf`:**

```conf
# Запретить подключение root-подобных пользователей
# Требовать SSL для удалённых подключений
ssl = on
password_encryption = scram-sha-256
```

Подробнее: **[Установка PostgreSQL](./PostgreSQL/overview.md)**.

## Дополнительная информация

### Общие рекомендации

- **Надежные пароли:** Всегда устанавливайте уникальный сложный пароль для административных пользователей.
- **Минимальные привилегии:** Не используйте root для приложений. Создавайте отдельных пользователей с ограниченными правами.
- **Сетевая безопасность:** Ограничьте доступ к порту СУБД через файрвол. Разрешайте только доверенным IP.
- **Регулярные обновления:** Обновляйте СУБД до последних версий для получения патчей безопасности.
- **Аудит и логирование:** Включите логирование подключений и изменений привилегий.

### Дополнительные меры защиты

| Мера | Описание | Приоритет |
| :--- | :--- | :--- |
| **SSL/TLS** | Шифрование соединений между клиентом и сервером | Высокий |
| **Аудит** | Логирование всех подключений и изменений | Высокий |
| **Сегментация сети** | Размещение БД в отдельной подсети | Средний |
| **Secrets Management** | Хранение паролей в Vault/AWS Secrets Manager | Средний |
| **Регулярный аудит привилегий** | Проверка и отзыв избыточных прав | Средний |
