# Neo4j: Мультитенантность и composite databases

**Актуально для:** Neo4j 2026.09.x / 5.26.x LTS

## Определения

| Термин | Значение |
| :--- | :--- |
| **Тенант (tenant)** | Независимый клиент или подразделение, чьи данные должны быть отделены от остальных. |
| **Изоляция данных** | Невозможность запросить или изменить данные другого тенанта. |
| **Изоляция запросов** | Один тяжёлый запрос одного тенанта не деградирует обслуживание остальных. |
| **Multi-database** | Несколько баз данных в одном DBMS, у каждой свои пользователи и права — механизм Neo4j для изоляции. |
| **Composite database** | Специальный тип базы, дающий доступ к разделённым данным одним запросом Cypher. Хранит данные только через алиасы. |
| **Constituent (составляющая)** | База, на которую указывает алиас в composite database: локальная или удалённая. |
| **Алиас базы** | Имя, под которым база известна внутри composite database. |
| **Data federation** | Два непересекающихся графа с разными метками и типами связей, которые читаются вместе. |
| **Data sharding** | Два графа с одинаковой моделью, но разными данными. |
| **Proxy node** | Узел-прослойка во втором графе с единственным свойством `<node>ID`, связывающий данные между графами. |
| **DEFAULT LANGUAGE** | Настройка версии Cypher по умолчанию для composite database (с 2025.06). |
| **graph.propertiesByName()** | Встроенная функция, возвращает `MAP` свойств, заданных на алисе. Доступна только в composite databases. |
| **SHOW ALIASES FOR DATABASE** | Команда просмотра всех алиасов — локальных, удалённых и входящих в composite database. |
| **Default database** | База по умолчанию для composite database (с 2025.04). |
| **Alias properties** | Свойства алиаса, задаваемые через `PROPERTIES {…}` при создании или изменении алиса. |

## Базовые понятия: четыре стратегии и их цена

Мультитенантность в графовой базе — это не одна настройка, а выбор между четырьмя стратегиями. Различие проходит по четырём осям: изоляция данных, изоляция запросов, эксплуатационная стоимость и предел масштабирования.

| Стратегия | Изоляция данных | Изоляция запросов | Эксплуатация | Предел |
| :--- | :--- | :--- | :--- | :--- |
| **Отдельная база на тенанта** (multi-database) | Высокая: отдельное пространство, отдельные права | Высокая: свой page cache и своя транзакция | Одна инфраструктура, больше баз в бэкапах и наблюдаемости | `dbms.max_databases`, по умолчанию **100** (Enterprise, минимум 2) |
| **Общий граф с меткой тенанта** | Низкая на уровне модели: обеспечивается фильтром в каждом запросе и sub-graph доступом | Низкая: один тяжёлый запрос мешает всем | Проще всего, один набор индексов | Рост индекса и стоимость фильтра `tenantId` в каждом запросе |
| **Composite databases** | Средняя: изоляция на уровне графа, но один запрос видит несколько | Средняя: запрос к конкретному алиасу изолирован, federated-запрос — нет | Требует Enterprise и дисциплины в именах | Ограничения самого механизма, перечислены ниже |
| **Отдельный DBMS или кластер на группу тенантов** | Максимальная | Максимальная | Дорого: отдельный бэкап, обновление, мониторинг | Нет технического предела, есть цена |

Практическое правило выбора: если один клиент способен завалить базу тяжёлым запросом — изоляция на уровне базы. Если клиенты доверенные и запросы предсказуемые — общий граф с меткой тенанта дешевле и проще.

### Multi-database как базовая изоляция

Neo4j поддерживает несколько баз в одном DBMS. Каждая база имеет собственное пространство пользователей и прав, собственную конфигурацию доступа, собственные индексы и собственный backup-контекст. Ограничение задаётся настройкой:

```properties
# neo4j.conf — Enterprise Edition
dbms.max_databases=100
```

Значение по умолчанию — **100**, минимально допустимое — 2. Всё, что связано с созданием баз, топологией и их размещением по серверам кластера, разобрано в [кластеризации](./clustering.md).

### Общий граф с меткой тенанта

Модель проще всего, но переносит ответственность на запросы: любая выборка по `:Customer` без фильтра по тенанту протекает. Что обязательно:

```cypher
// Метка тенанта и составной индекс — фильтр по тенанту должен быть индексируемым
CREATE INDEX customer_tenant_name IF NOT EXISTS
FOR (c:Customer) ON (c.tenantId, c.name);
```

```cypher
// Параметризация обязательна: tenantId приходит из сессии, а не из тела запроса
MATCH (c:Customer {tenantId: $tenantId, name: $name})
RETURN c.id;
```

Дополнительные меры, которые даёт сама платформа, разобраны в [безопасности](./security.md): sub-graph и property-based access control позволяют ограничить видимость по узлам и свойствам, а не по тексту запроса.

### Composite databases

Composite database — Enterprise-возможность (недоступна в Aura). Это база, которая **не хранит данные самостоятельно**: она содержит алиасы, указывающие на другие базы — локальные (в том же DBMS) или удалённые (в другом DBMS). Доступ к разделённым данным получается одним запросом.

Два сценария применения:

- **Data federation** — данные лежат в двух непересекающихся графах с разными метками и типами связей: например, данные о пользователях с их местоположением отдельно от постов пользователей на форумах, и нужно читать их вместе.
- **Data sharding** — два графа с одинаковой моделью (те же метки и типы связей), но разными данными: шарды на разных серверах, чтобы разделить нагрузку по ресурсам и хранилищу, либо в разных локациях. Существующую базу можно разшардировать командой `neo4j-admin database copy`.

Связи **не могут пересекать границы графов**. Чтобы соединять данные, применяют proxy node modeling: узлы с определённой меткой присутствуют в обоих федерируемых доменах; в одном графе эти узлы несут все данные, в другом — тот же узел существует как proxy и содержит только свойство `<node>ID`, связывающее записи между графами.

Ограничения механизма, которые важно знать до проектирования:

| Ограничение | Следствие |
| :--- | :--- |
| Не поддерживает команды управления привилегиями, индексами и ограничениями | Всё это задаётся на целевой базе-составляющей в её DBMS |
| Допускает только транзакции, которые читают из нескольких графов, либо читают из нескольких и пишут в один | Запись сразу в два графа невозможна — нет распределённой транзакции |
| Не поддерживает embedded-режим Neo4j в Java-приложениях | Только клиент/серверный режим через Bolt или HTTP |
| Не гарантирует совместимость между составляющими разных версий Neo4j | Набор доступных функций ограничивается пересечением возможностей DBMS и всех составляющих |
| Имена с точками нежелательны | Точка в имени базы неоднозначна: часть имени или разделитель алиаса |

### Дополнительные ограничения (с 2025.06)

| Ограничение | Следствие |
| :--- | :--- |
| Алиасы не могут указывать на composite database | Попытка создать алиас на composite database отклоняется с кодом `42NA6` |
| Параметры в именах алиасов | Первая точка в значении параметра всегда трактуется как разделитель composite/alias; без обрамления в кавычки — неоднозначность |
| Composite database не управляет доступом | `access` и `topology` унаследуются от составляющих; изменить их на уровне composite database нельзя |
| Aliases в composite database не получают `DEFAULT LANGUAGE` | Версия Cypher для составной базы задаётся на самой composite database, а не на алисах |

Имена составных баз подчиняются тем же правилам, что и имена обычных баз. Отличие в Cypher 5: синтаксис с точками без обрамления в обратные кавычки недоступен — и точки, и дефисы необходимо заключать в обратные кавычки.

## Практические сценарии

### База на тенанта

```cypher
CREATE DATABASE tenant_acme TOPOLOGY 1 PRIMARIES 0 SECONDARIES;
```

Полный порядок — в [кластеризации](./clustering.md#создание-базы-с-заданной-топологией). Роль приложения ограничивается своей базой: драйвер подключается с указанием базы, а привилегии выдаются на уровне этой базы.

### Проверка лимита баз

```cypher
SHOW DATABASES YIELD name, type, currentStatus, access;
```

Если тенантов больше, чем позволяет `dbms.max_databases`, стратегия «база на тенанта» упрётся в лимит — это повод пересмотреть стратегию, а не увеличивать лимит до бесконечности.

### Composite database поверх локальных баз

```cypher
CREATE DATABASE `movies-latest`;
CREATE COMPOSITE DATABASE cineasts;
CREATE ALIAS `cineasts.latest` FOR DATABASE `movies-latest`;
```

После создания составная база появляется в выводе `SHOW DATABASES` с типом `composite` и списком составляющих:

```plain
+-----------------------------------------------------------------+
| name             | type      | aliases           | constituents      |
+-----------------------------------------------------------------+
| "cineasts"       | "composite"| ["cineasts.latest"] | ["movies-latest"] |
| "movies-latest"  | "standard" | []                 | []                |
| "neo4j"          | "standard" | []                 | []                |
| "system"         | "system"   | []                 | []                |
+-----------------------------------------------------------------+
```

### Составная база поверх удалённых баз

Удалённый алиас указывает на базу другого DBMS; используются учётные данные, заданные в самом алиасе:

```cypher
CREATE ALIAS `cineasts.upcoming`
  FOR DATABASE upcoming
  AT 'neo4j+s://location:7687'
  USER neo4j
  PASSWORD 'password'
```

Схема `neo4j+s://` — маршрутизирующая: клиент получает routing table и обращается к актуальному лидеру.

### DEFAULT LANGUAGE для composite database (с 2025.06)

Каждой composite database можно задать версию Cypher по умолчанию — это влияет на все запросы, запускаемые против неё:

```cypher
CREATE COMPOSITE DATABASE inventory DEFAULT LANGUAGE CYPHER 5
```

```cypher
ALTER DATABASE inventory SET DEFAULT LANGUAGE CYPHER 25
```

Просмотр:

```cypher
SHOW DATABASES YIELD name, defaultLanguage
```

| name | defaultLanguage |
| :--- | :--- |
| `"neo4j"` | `"CYPHER 25"` |
| `"library"` | `"CYPHER 5"` |
| `"inventory"` | `"CYPHER 5"` |

Значение `CYPHER 5` фиксирует семантику на момент релиза Neo4j 2025.06: изменения в более поздних версиях не повлияют на запросы. Значение `CYPHER 25` — текущая версия языка, включая все изменения после 2025.06. Переключить версию можно и в запросе: префикс `CYPHER 25` перекрывает настройку базы.

### Алиасы composite database: свойства и default database (с 2025.04–2025.06)

Алиасы в составной базе могут не только указывать на целевую базу, но и нести произвольные свойства:

```cypher
CREATE ALIAS composite.first FOR DATABASE dba
  PROPERTIES {number: 1, tags: ['A', 'B']};
```

Эти свойства читаются встроенной функцией `graph.propertiesByName()`:

```cypher
UNWIND graph.names() AS name
RETURN name, graph.propertiesByName(name) AS props
```

| name | props |
| :--- | :--- |
| `"composite.first"` | `{number: 1, tags: ["A", "B"]}` |
| `"composite.second"` | `{number: 0, tags: ["A"]}` |

Функция доступна **только в composite databases** и возвращает свойства только по тем алиасам, у которых пользователь есть доступ. Это позволяет фильтровать графы по метаданным: например, читать узлы только из графов с тегом `"A"`.

С 2025.04 для composite database можно задать **default database** — алиас, к которому разворачивается подключение по умолчанию:

```cypher
ALTER DATABASE cineasts SET DEFAULT DATABASE cineasts.latest
```

Просмотр всех алиасов (включая composite):

```cypher
SHOW ALIASES FOR DATABASE
```

| name | composite | database | location | url | user |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `"library.romance"` | `"library"` | `"romance-books"` | `"remote"` | `"neo4j+s://location:7687"` | `"alice"` |
| `"library.sci-fi"` | `"library"` | `"sci-fi-books"` | `"local"` | `NULL` | `NULL` |

Колонка `composite` показывает, к какой составной базе относится алиас (или `null`, если алиас локальный). Отфильтровать можно по условию `WHERE composite = 'garden'`.

### Запросы к составной базе

Выбор одного графа на весь запрос:

```cypher
USE cineasts.latest
MATCH (movie:Movie)
RETURN movie.title AS title;
```

Чтение из двух графов через `UNION`:

```cypher
USE cineasts.latest
MATCH (movie:Movie)
RETURN movie.title AS title
UNION
USE cineasts.upcoming
MATCH (movie:Movie)
RETURN movie.title AS title;
```

Динамический выбор графа — форма `USE graph.byName(graphName)`. Имена всех составляющих возвращает встроенная функция `graph.names()`:

```cypher
// Читать из всех составляющих
UNWIND graph.names() AS graphName
CALL {
  USE graph.byName(graphName)
  MATCH (movie:Movie)
  RETURN movie
}
RETURN movie.title AS title;
```

```plain
+---------------------+
| graphName           |
+---------------------+
| "cineasts.latest"   |
| "cineasts.upcoming" |
+---------------------+
```

Полный перечень операций — `CREATE COMPOSITE DATABASE`, `ALTER`, `START`, `STOP`, `DELETE`, список, а также управление алиасами — в документации по composite databases; команды создания поддерживают `IF NOT EXISTS` и `OR REPLACE`.

### Composite database с алиасами, несущими свойства

Свойства алиасов позволяют помечать графы метаданными и фильтровать их в запросах:

```cypher
CREATE COMPOSITE DATABASE inventory;
CREATE ALIAS inventory.east FOR DATABASE east_db
  PROPERTIES {region: 'us-east-1', tier: 'hot'};
CREATE ALIAS inventory.west FOR DATABASE west_db
  PROPERTIES {region: 'us-west-2', tier: 'cold'};
```

Чтение метаданных и выбор нужных графов одним запросом:

```cypher
UNWIND graph.names() AS name
WITH name, graph.propertiesByName(name) AS props
WHERE props.tier = 'hot'
CALL () {
  USE graph.byName(name)
  MATCH (p:Product)
  RETURN p
}
RETURN p.name;
```

Запрос возвращает товары только из «горячих» графов, не зная заранее, какие алиасы существуют.

### Ограничение на источник репликации между кластерами

При настройке кросс-кластерной репликации баз (с 2026.08) **источником может быть только standard database**. Composite databases и sharded property databases (SPD) как источник не поддерживаются — см. [кластеризацию](./clustering.md).

## Устранение неполадок

| Проблема | Симптом | Причина | Решение |
| :--- | :--- | :--- | :--- |
| `CREATE DATABASE` отклонён | Ошибка лимита | Тенантов больше, чем `dbms.max_databases` | Сменить стратегию изоляции либо обсудить увеличение лимита осознанно |
| Запрос к составной базе не находит алиас | `Database not found` | Алиас не создан или имя указано без обратных кавычек | Проверить `SHOW DATABASES` (колонка `aliases`) и заключить имя с точкой в кавычки |
| Ошибка привилегий на составной базе | Отказано в операции | Привилегии не управляются на уровне composite database | Выдать права на целевой базе-составляющей в её DBMS |
| Попытка писать в два графа | Транзакция отклонена | Запись сразу в несколько графов не поддержана | Читать из нескольких, писать в один; согласовать схему записи |
| Транзакция с federated-запросом отклонена | Ошибка выполнения | Неверный тип транзакции | Перечитать ограничения composite databases: только чтение или чтение с записью в один граф |
| Запрос тенанта видит чужие данные | Утечка в общем графе | Фильтр по `tenantId` не задан в запросе | Обязательный индексируемый составной индекс и параметризация; sub-graph доступ |
| Cross-database replication не стартует | Ошибка настройки | Источник — composite database или SPD | Использовать standard database как источник |
| `graph.names()` пуст | Нет строк результата | У составной базы нет алиасов | Создать алиасы; проверить, что подключение идёт к composite database |
| `graph.propertiesByName()` возвращает `null` | Запрос к несуществующему алису | Имя графа не входит в `graph.names()` | Проверить, что алиас создан и пользователь имеет доступ к целевой базе |
| `ALTER DATABASE … SET DEFAULT LANGUAGE` отклонён | Ошибка синтаксиса | Версия Neo4j старше 2025.06 | DEFAULT LANGUAGE доступен с 2025.06; для более ранних версий — без этой настройки |
| `SHOW ALIASES FOR DATABASE` не показывает composite | Пустая таблица | У пользователя нет привилегии `SHOW ALIAS ON DBMS` | Выдать привилегию на составную базу |
| Ошибка `42NA6` при создании алиаса | Алиас указывает на composite database | Алиасы не могут быть направлены на составную базу | Указать на standard database или sharded property database |

## Лучшие практики

- **Выбирайте стратегию по изоляции запросов, а не по изоляции данных.** Один шумный тенант, деградирующий общий кэш, дороже любой экономии на инфраструктуре.
- **Общий граф требует дисциплины:** `tenantId` в составном индексе, параметризация, отказ от «быстрых» запросов без фильтра.
- **Планируйте `dbms.max_databases` заранее** — это лимит Enterprise, а не настройка приложения.
- **Composite databases — не изоляция, а федерация.** Не используйте их как замену базе на тенанта, если требование — изоляция запросов.
- **Не давайте именам composite database точки:** неоднозначность между именем и разделителем алиаса.
- **Привилегии выдавайте на составляющих базах**, а не на составной — механизм управления привилегиями там отсутствует.
- **Proxy node — осознанное решение:** держите метку proxy в обоих доменах и синхронизируйте свойство `<node>ID>`, иначе федеративные запросы будут молча терять связи.
- **Документируйте, где проходит граница tenant'а:** в общем графе это выражается только соглашением, которое легко нарушить.
- **DEFAULT LANGUAGE для composite database** задаётся при создании или через `ALTER DATABASE`. Используйте `CYPHER 5`, если нужна стабильность семантики; `CYPHER 25` — если нужна последняя версия языка.
- **Свойства алиасов (`PROPERTIES`)** — лёгкий механизм метаданных. Используйте их вместо внешней таблицы соответствий: `graph.propertiesByName()` читает их без дополнительных запросов.
- **Default database для composite database** упрощает подключение: клиенту не нужно указывать алиас вручную.
- **Проверяйте составляющие через `SHOW ALIASES FOR DATABASE`** — колонка `composite` отличает алиасы составной базы от локальных.
