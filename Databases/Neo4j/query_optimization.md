# Neo4j: Оптимизация запросов

Эффективность графовых запросов зависит от того, насколько точно описан шаблон и как ограничено пространство поиска.

## Анализ запросов: EXPLAIN и PROFILE

1.  **`EXPLAIN`:** Показывает план выполнения без запуска запроса. Используется для проверки структуры плана.
2.  **`PROFILE`:** Запускает запрос и показывает реальную нагрузку (DbHits — обращения к движку). **Основная метрика оптимизации.**

```cypher
// Пример анализа
PROFILE MATCH (p:Person {name: 'Alice'})-[:FRIENDS_WITH]->(friend)
RETURN friend.name;
// → DbHits: 3 (или меньше с индексом)
```

## Стратегии индексирования

Индексы в Neo4j используются для поиска *начальных точек* (Anchor points) обхода, а не для самого обхода.

```cypher
// Range Index — для точного поиска и диапазонов
CREATE INDEX FOR (p:Person) ON (p.email);

// Составной индекс — для комбинации свойств
CREATE INDEX FOR (p:Person) ON (p.lastName, p.firstName);

// Full-text Index — для нечёткого поиска по строкам (Lucene)
CREATE FULLTEXT INDEX personSearch FOR (p:Person) ON EACH [p.name, p.bio];

// Point Index — для пространственных данных
CREATE POINT INDEX FOR (n:Location) ON (n.coordinates);

// Token Index — для быстрого поиска по меткам
CREATE RANGE INDEX FOR (n:Person) ON (n.age);

// Просмотр индексов
SHOW INDEXES;

// Удаление индекса
DROP INDEX index_name;
```

**Best Practice:** Всегда создавайте индексы на свойства, по которым выполняется первичный поиск (`MATCH (n:User {email: '...'})`).

## Правила написания эффективных запросов

1.  **Используйте метки (Labels):** Запрос `MATCH (n) RETURN n` просканирует все узлы. `MATCH (n:User) RETURN n` ограничит поиск.
2.  **Указывайте направление связи:** Если направление известно, всегда пишите `(a)-[:FOLLOWS]->(b)` вместо `(a)-[:FOLLOWS]-(b)`. Это сокращает пространство поиска вдвое.
3.  **Параметризация:** Всегда используйте параметры (`$id`) вместо констант в строке запроса для переиспользования планов выполнения.
4.  **Сначала фильтрация, потом обход:** Используйте `WITH` для ограничения набора данных перед выполнением тяжелых `MATCH`.
5.  **Избегайте `OPTIONAL MATCH` в циклах:** Каждый `OPTIONAL MATCH` может умножить количество строк.
6.  **Используйте `LIMIT` и `SKIP`:** Всегда ограничивайте результат в промежуточных шагах.

```cypher
// Правильно: параметризованный запрос с индексным поиск
MATCH (p:Person {email: $email})-[:WORKS_AT]->(c:Company)
RETURN p.name, c.name;

// Неправильно: хардкод значений (.plan не переиспользуется)
MATCH (p:Person {email: 'alice@example.com'})-[:WORKS_AT]->(c:Company)
RETURN p.name, c.name;
```
