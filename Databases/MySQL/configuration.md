# Конфигурация MySQL (`my.cnf`)

## Определения

**Конфигурационный файл (`my.cnf`)** — основной файл для настройки сервера MySQL и клиентских утилит. Сервер `mysqld` читает его при запуске для определения рабочих параметров, таких как пути к данным, настройки производительности, логирования и репликации.

## Базовые концепции

### Расположение и структура

Файл конфигурации обычно находится в одном из следующих мест:

- `/etc/my.cnf`
- `/etc/mysql/my.cnf`
- `/etc/mysql/mysql.conf.d/mysqld.cnf` (в современных системах)

Настройки группируются по секциям. Основная секция для настройки сервера — `[mysqld]`.

### Ключевые группы параметров

#### 1. Общие настройки

- `user`: Пользователь, от имени которого запускается процесс mysqld.
- `datadir`: Каталог для хранения файлов баз данных.
- `port`: TCP-порт для приема подключений.
- `bind-address`: IP-адрес, на котором сервер слушает подключения. `127.0.0.1` — только локальные, `0.0.0.0` — все доступные интерфейсы.
- `socket`: Файл сокета для локальных подключений.

#### 2. Настройки производительности

- `max_connections`: Максимальное количество одновременных подключений.
- `max_allowed_packet`: Максимальный размер одного пакета, отправляемого серверу.
- `table_open_cache`: Количество кэшируемых открытых таблиц.
- `key_buffer_size`: Размер буфера для индексов таблиц MyISAM. Для систем, использующих преимущественно InnoDB, этот параметр менее важен.
- `innodb_buffer_pool_size`: **Ключевой параметр производительности для InnoDB.** Размер буферного пула для кэширования данных и индексов. Рекомендуется устанавливать в 50-70% от доступной ОЗУ на выделенном сервере.

#### 3. Логирование

- `log_error`: Путь к файлу лога ошибок.
- `slow_query_log`: Включает (1) или выключает (0) логирование медленных запросов.
- `slow_query_log_file`: Файл для записи медленных запросов.
- `long_query_time`: Время в секундах, по истечении которого запрос считается медленным.
- `log-queries-not-using-indexes`: Логировать запросы, которые не используют индексы, что помогает в оптимизации.

#### 4. Репликация

- `server-id`: Уникальный идентификатор сервера в топологии репликации.
- `log_bin`: Включает ведение бинарного лога, указывая путь к файлам. **Обязательно для master-сервера.**
- `expire_logs_days`: Автоматическое удаление файлов бинарного лога через указанное количество дней.
- `max_binlog_size`: Максимальный размер одного файла бинарного лога.

## Практические сценарии

### Пример подробной конфигурации `my.cnf`

```ini
[mysqld]

# -- 1. Базовые настройки --
user                    = mysql
pid-file                = /var/run/mysqld/mysqld.pid
socket                  = /var/run/mysqld/mysqld.sock
port                    = 3306
datadir                 = /var/lib/mysql
bind-address            = 0.0.0.0

# -- 2. Настройки производительности --
# Увеличивайте эти значения в зависимости от нагрузки и доступных ресурсов.
max_connections         = 151
max_allowed_packet      = 64M
table_open_cache        = 4000
# Для MyISAM. Если используете InnoDB, важнее innodb_buffer_pool_size.
key_buffer_size         = 16M 

# -- 3. Логирование --
log_error               = /var/log/mysql/error.log

# Включение и настройка лога медленных запросов
slow_query_log          = 1
slow_query_log_file     = /var/log/mysql/mysql-slow.log
long_query_time         = 2
log-queries-not-using-indexes

# -- 4. Репликация --
# server-id должен быть уникальным для каждого сервера в кластере.
server-id               = 1
log_bin                 = /var/log/mysql/mysql-bin.log
expire_logs_days        = 30
max_binlog_size         = 100M

# -- Фильтрация репликации (используйте осторожно) --
# Реплицировать только указанную базу данных.
# binlog_do_db          = database_name
# Игнорировать указанную базу данных при репликации.
# binlog_ignore_db      = database_name
```

## Дополнительная информация

- **Клиентский файл `.my.cnf`**: Не путайте серверный `my.cnf` с клиентским файлом `~/.my.cnf`. Последний используется для задания параметров подключения по умолчанию (хост, пользователь, пароль) для утилит `mysql`, `mysqldump` и др. Пример его настройки можно найти в [документе по мониторингу](./monitoring.md).
- **Подробная настройка репликации**: Детальное описание шагов по настройке репликации, включая создание пользователя и инициализацию реплики, находится в [документе о репликации в MySQL](./replication.md).
- **Официальная документация**: Полный список и описание всех серверных переменных доступны на [официальном сайте MySQL](https://dev.mysql.com/doc/refman/8.0/en/server-system-variables.html).
