# Конфигурация MySQL (my.cnf)

## Определения

**Конфигурационный файл (my.cnf)** — основной файл для настройки параметров работы Системы Управления Базами Данных (СУБД) MySQL и её клиентских утилит. Серверный процесс `mysqld` считывает этот файл при запуске для определения путей к данным, параметров производительности, настроек логирования и топологии репликации.

**Секция конфигурации** — блок параметров в файле, ограниченный квадратными скобками (например, `[mysqld]`), который определяет, к какому компоненту (серверу, клиенту или конкретной утилите) относятся настройки.

## Основные концепции

### Расположение и структура

В современных Linux-системах (Ubuntu, Rocky Linux) конфигурационные файлы MySQL располагаются по следующим путям:

- `/etc/my.cnf` — глобальный файл (часто содержит инклюды).
- `/etc/mysql/my.cnf` — основной путь в Debian/Ubuntu.
- `/etc/mysql/mysql.conf.d/mysqld.cnf` — специфичные настройки сервера в Ubuntu.

Файл имеет INI-подобную структуру. Основные секции: `[mysqld]` (сервер), `[client]` (все клиенты), `[mysql]` (консольный клиент).

### Ключевые группы параметров MySQL 8.4 LTS

#### 1. Автоматическая настройка и база

- **`innodb_dedicated_server`**: При установке в `ON` сервер автоматически рассчитывает `innodb_buffer_pool_size` и `innodb_redo_log_capacity` на основе доступной ОЗУ и ядер CPU. Идеально для Docker и выделенных ВМ.
- `bind-address`: IP-адрес для прослушивания. `::` разрешает все IPv4 и IPv6 подключения.
- `port`: TCP-порт (по умолчанию 3306).

#### 2. Производительность InnoDB

- **`innodb_buffer_pool_size`**: Размер кэша данных и индексов в ОЗУ. Если не используется `innodb_dedicated_server`, рекомендуется 50–75% от общего объёма ОЗУ.
- **`innodb_redo_log_capacity`**: **Новый стандарт в 8.4.** Заменяет устаревшие `innodb_log_file_size`. Определяет общий объем дискового пространства для журналов транзакций (Redo Log). Можно менять динамически.
- **`innodb_flush_method`**: В версии 8.4 для SSD/NVMe рекомендуется явно устанавливать `O_DIRECT`, так как автоматика `innodb_dedicated_server` больше не управляет этим параметром.
- `max_connections`: Максимальное количество одновременных подключений.

#### 3. Логирование и диагностика

- `log_error`: Путь к логу ошибок.
- `slow_query_log`: Включение записи медленных запросов (0/1).
- `long_query_time`: Время (в секундах), после которого запрос считается медленным.
- `binlog_expire_logs_seconds`: Время хранения бинарных логов. Заменило старый параметр в днях.

## Практические сценарии

### Пример современной конфигурации для SSD (MySQL 8.4+)

```ini
[mysqld]
# -- Базовые настройки --
user                    = mysql
datadir                 = /var/lib/mysql
socket                  = /var/run/mysqld/mysqld.sock
bind-address            = ::

# -- Автоматическая настройка (Auto-tuning) --
# MySQL сам рассчитает buffer pool и redo log на основе ресурсов системы
innodb_dedicated_server = ON

# -- Оптимизация для современных SSD --
# В 8.4 это нужно задавать вручную даже при включенном dedicated_server
innodb_flush_method     = O_DIRECT
innodb_io_capacity      = 10000
innodb_io_capacity_max  = 20000

# -- Безопасность и лимиты --
max_connections         = 500
max_allowed_packet      = 128M

# -- Логирование --
slow_query_log          = 1
long_query_time         = 1
log_error               = /var/log/mysql/error.log

# -- Репликация --
server-id               = 1
log_bin                 = /var/log/mysql/mysql-bin.log
# Хранить логи 7 дней
binlog_expire_logs_seconds = 604800
```

## Дополнительная информация

### Проверка текущих значений

Многие параметры в MySQL 8.4 являются динамическими. Проверить их можно без перезагрузки:
```sql
SHOW VARIABLES LIKE 'innodb_redo_log_capacity';
SHOW GLOBAL STATUS LIKE 'Innodb_buffer_pool_pages_data';
```
