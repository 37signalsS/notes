# Конфигурация MySQL (my.cnf)

## Определения

**Конфигурационный файл (my.cnf)** — основной файл для настройки параметров работы Системы Управления Базами Данных (СУБД) MySQL и её клиентских утилит. Серверный процесс `mysqld` считывает этот файл при запуске для определения путей к данным, параметров производительности, настроек логирования и топологии репликации.

**Секция конфигурации** — блок параметров в файле, ограниченный квадратными скобками (например, `[mysqld]`), который определяет, к какому компоненту (серверу, клиенту или конкретной утилите) относятся данные настройки.

## Основные концепции

### Расположение и структура

В современных Linux-системах конфигурационные файлы MySQL обычно располагаются по следующим путям:

- `/etc/my.cnf` — глобальный файл конфигурации.
- `/etc/mysql/my.cnf` — альтернативный путь в Debian/Ubuntu.
- `/etc/mysql/mysql.conf.d/mysqld.cnf` — специфичный для сервера файл в новых версиях дистрибутивов.

Файл имеет INI-подобную структуру. Основная секция для настройки серверной части — `[mysqld]`. Также существуют секции `[client]` (настройки для всех клиентов) и `[mysql]` (настройки конкретно для консольного клиента).

### Ключевые группы параметров

#### 1. Общие настройки

- `user`: Системный пользователь, от имени которого запускается процесс `mysqld`.
- `datadir`: Путь к директории, где хранятся файлы баз данных.
- `port`: TCP-порт для сетевых подключений (по умолчанию 3306).
- `bind-address`: IP-адрес для прослушивания. `127.0.0.1` разрешает только локальные подключения, `0.0.0.0` — со всех интерфейсов IPv4, `::` — со всех интерфейсов IPv4 и IPv6.
- `socket`: Путь к файлу Unix-сокета для локальных подключений.

#### 2. Настройки производительности

- `max_connections`: Максимальное количество одновременных клиентских подключений.
- `innodb_buffer_pool_size`: **Важнейший параметр для движка InnoDB.** Определяет размер Оперативной Памяти (ОЗУ), выделяемой под кэширование данных и индексов таблиц. Рекомендуется устанавливать в пределах 50–70% от общего объёма ОЗУ на выделенном сервере БД.
- `max_allowed_packet`: Максимальный размер пакета данных, который может быть передан за один запрос.
- `table_open_cache`: Количество открытых таблиц, которые сервер может хранить в кэше.

#### 3. Логирование

- `log_error`: Путь к файлу лога ошибок.
- `slow_query_log`: Включает (1) или выключает (0) запись медленных запросов.
- `slow_query_log_file`: Путь к файлу лога медленных запросов.
- `long_query_time`: Время выполнения запроса в секундах, после которого он считается медленным.
- `log_queries_not_using_indexes`: Логирование запросов, которые не используют индексы (полезно для оптимизации).

#### 4. Репликация

- `server-id`: Уникальный числовой идентификатор сервера в топологии репликации.
- `log_bin`: Включает ведение бинарного лога (Binary Log), необходимого для репликации и восстановления данных.
- `binlog_expire_logs_seconds`: (заменил устаревший `expire_logs_days`) Время автоматического удаления старых бинарных логов в секундах.
- `max_binlog_size`: Максимальный размер одного файла бинарного лога.

## Практические сценарии

### Пример конфигурации my.cnf для сервера средней нагрузки

```ini
[mysqld]
# -- Базовые настройки --
user                    = mysql
pid-file                = /var/run/mysqld/mysqld.pid
socket                  = /var/run/mysqld/mysqld.sock
port                    = 3306
datadir                 = /var/lib/mysql
bind-address            = ::

# -- Производительность (на примере 8 ГБ ОЗУ) --
max_connections         = 200
# ~70% от ОЗУ
innodb_buffer_pool_size = 5G
max_allowed_packet      = 64M
table_open_cache        = 4000

# -- Логирование --
log_error               = /var/log/mysql/error.log
slow_query_log          = 1
slow_query_log_file     = /var/log/mysql/mysql-slow.log
long_query_time         = 2
log_queries_not_using_indexes = 1

# -- Репликация (Master-режим) --
server-id               = 1
log_bin                 = /var/log/mysql/mysql-bin.log
# Хранить логи 7 дней (7 * 24 * 3600)
binlog_expire_logs_seconds = 604800
max_binlog_size         = 100M
```
