# MySQL Operator для Kubernetes

## Определения

**MySQL Operator** — это расширение Kubernetes, которое автоматизирует развертывание, управление и эксплуатацию кластеров MySQL (преимущественно MySQL InnoDB Cluster) в контейнеризированной среде. Он обеспечивает высокую доступность и упрощает сложные операции с базами данных, превращая их в нативные задачи Kubernetes.

*   **Репозиторий:** [github.com/mysql/mysql-operator](https://github.com/mysql/mysql-operator)
*   **Назначение:** Обеспечение надежности и масштабируемости MySQL в кластере Kubernetes.

## Основные возможности

Оператор берет на себя рутинные задачи администратора БД:

*   **Автоматизация кластеризации:** Создание и управление MySQL InnoDB Cluster (Group Replication).
*   **Высокая доступность (HA):**
    *   Автоматическое обнаружение сбоев узлов.
    *   Выполнение переключения на резервную копию (Failover) и восстановление (Recovery) без вмешательства человека.
*   **Масштабирование:** Простое изменение количества инстансов MySQL в кластере.
*   **Управление секретами:** Глубокая интеграция с [Kubernetes Secrets](../Kubernetes/Base/secrets/secrets_overview.md) для безопасного управления паролями и сертификатами.
*   **Резервное копирование:** Автоматизированное создание бэкапов и восстановление из них.
*   **Маршрутизация трафика:** Интеграция с **MySQL Router** для обеспечения прозрачного подключения приложений к текущему Primary-узлу.

## Архитектура и компоненты

### Ключевые ресурсы

| Ресурс | Описание |
| :--- | :--- |
| **InnoDBCluster** | Основной ресурс, описывающий топологию кластера MySQL, количество реплик и параметры хранилища. |
| **MySQLRouter** | Конфигурация прокси-слоя, который распределяет запросы между мастером и репликами. |
| **MySQLBackup** | Определение заданий на резервное копирование. |

### Принцип работы

Оператор постоянно отслеживает состояние подов MySQL. При выходе из строя Primary-узла, Group Replication инициирует выборы нового лидера, а MySQL Router автоматически обновляет свои маршруты, чтобы приложения продолжали работать с новым мастером. Оператор, в свою очередь, перезапускает упавший под и возвращает его в кластер в качестве реплики.

## Практические сценарии

### Пример описания InnoDB Cluster

```yaml
apiVersion: mysql.oracle.com/v2
kind: InnoDBCluster
metadata:
  name: my-cluster
spec:
  instances: 3
  router:
    instances: 2
  secretName: my-db-secrets
  edition: community
  storage:
    persistentVolumeClaim:
      resources:
        requests:
          storage: 50Gi
```
