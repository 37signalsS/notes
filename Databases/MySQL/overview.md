# MySQL: Обзор и сравнение форков

## Определения

**MySQL** — реляционная система управления базами данных (СУБД), изначально разработанная компанией MySQL AB. После поглощения Sun Microsystems корпорацией Oracle в 2010 году MySQL перешла под контроль Oracle и развивается в нескольких направлениях.

**Форк (Fork)** — ответвление исходного кода проекта, создающее независимую версию продукта. В экосистеме MySQL существуют три основных форка, каждый из которых имеет свою философию развития и набор особенностей.

## Основные концепции

### Механизмы репликации
Репликация в MySQL включает три этапа:
1.  **Master** записывает изменения в двоичный журнал (**binary log**).
2.  **Slave** копирует эти события в свой журнал ретрансляции (**relay log**).
3.  **Slave** воспроизводит изменения из relay log на своих данных.

**Подходы к репликации:**
*   **Покомандная (Statement-based):** В журнал записываются SQL-запросы (INSERT, UPDATE).
*   **Построчная (Row-based):** В журнал записываются фактические изменения строк (дефолт в MySQL 8+).

**Типы синхронизации:**
*   **Синхронная (MySQL sync):** Транзакция завершается на мастере только после подтверждения записи на репликах. Обеспечивает строгую консистентность, но чувствительна к сетевым задержкам.
*   **Полусинхронная (Semi-sync):** Мастер ждет подтверждения от одной реплики о получении данных (записи в relay log), прежде чем подтвердить транзакцию клиенту.

### Безопасность и эксплуатация
*   **Access Control Lists (ACL):** Система безопасности на основе списков контроля доступа для всех соединений и операций.
*   **Утилита `mysqlcheck`:** Основной инструмент для проверки, восстановления и оптимизации таблиц «на лету».
*   **JSON в MySQL:** Использование типа JSON предпочтительнее текстовых полей благодаря автоматической валидации и бинарному формату хранения, позволяющему пропускать (skip) части документа при поиске.

### Oracle MySQL Community Edition — оригинальная версия

Оригинальная версия MySQL, разрабатываемая Oracle Corporation.

- **Модель разработки:**
  - **LTS (Long Term Support)** — стабильные версии с длительной поддержкой (например, 8.4).
  - **Innovation** — версии с новыми функциями, не рекомендуемые для production (например, 9.x).
- **Движок InnoDB:** Основной фокус на развитии InnoDB. Устаревшие движки (MyISAM, Memory) постепенно выводятся из эксплуатации.
- **Транзакционный DDL (Data Definition Language):** Начиная с версии 8.0, операции изменения структуры таблиц стали транзакционными.
- **MySQL Document Store:** Возможность работы с JSON-документами без схемы (NoSQL) через X Plugin и MySQL Shell.
- **MySQL Shell:** Клиент с поддержкой JavaScript, Python и SQL для продвинутого управления.
- **Ограничения:**
  - Query Cache полностью удалён в версии 8.0.
  - `mysql_native_password` помечен как устаревший в 8.4 LTS и удалён в 9.0+.

### Percona Server for MySQL — оптимизированный форк

Форк Oracle MySQL, представляющий собой набор оптимизаций и патчей поверх оригинальной кодовой базы.

- **Полная совместимость:** Версии синхронизированы с Oracle MySQL.
- **Движок XtraDB:** Улучшенный форк InnoDB с расширенными возможностями мониторинга.
- **Движок MyRocks:** Поддержка LSM (Log-Structured Merge-tree — дерево слияния с журнальной структурой) для эффективного сжатия данных и оптимизации записи.
- **Улучшенный мониторинг:** Детальное логирование медленных запросов и интеграция с PMM (Percona Monitoring and Management).
- **Кластеризация:** Поддержка Galera Cluster для обеспечения синхронной репликации.

---

### MariaDB — независимое развитие

Независимый форк, созданный оригинальными разработчиками MySQL из-за опасений относительно политики Oracle.

- **Открытая разработка:** Управление через независимый фонд MariaDB Foundation.
- **Несовместимость с MySQL 8+:** Начиная с версии 8.0, бинарная совместимость была нарушена — прямая миграция без дампа невозможна.
- **Множество движков хранения:** Активно развиваются специализированные движки:
  - **ColumnStore** — колоночное хранение для OLAP (Online Analytical Processing — аналитическая обработка в реальном времени).
  - **Spider** — шардинг на уровне СУБД.
  - **Aria** — безопасная альтернатива MyISAM.
- **SQL-расширения:** Поддержка новых типов данных (`UUID`, `INET6`) и расширенного синтаксиса.
- **Векторный поиск:** Начиная с версии 12.3 LTS, встроена поддержка векторного поиска для задач ИИ (RAG — Retrieval-Augmented Generation).
- **Query Cache:** Функция сохранена и продолжает поддерживаться.

См. также: **[Обзор MariaDB](../MariaDB/overview.md)**.

## Практические сценарии

### Сравнение производительности (бенчмарк 2026)

Тестирование проводилось с использованием OLTP (Online Transaction Processing — обработка транзакций в реальном времени) тестов sysbench.

| Тест | MySQL 8.4.10 | Percona 8.4.10-10 | MariaDB 12.3.1 |
| :--- | :--- | :--- | :--- |
| **Read-Write (32 GB, 512 threads)** | ~13 325 TPS | **~13 385 TPS** | ~9 500 TPS |
| **Read-Only (32 GB, 128 threads)** | ~23 500 TPS | ~23 800 TPS | **~28 500 TPS** |

**Основные выводы:**

1. **Percona и Oracle MySQL** лидируют в сценариях с высокой конкурентностью записи (500+ потоков).
2. **MariaDB** демонстрирует преимущество в нагрузках, ориентированных на чтение.
3. Увеличение Buffer Pool с 2 GB до 32 GB дает прирост производительности в 10–20 раз.
4. **TPS (Transactions Per Second)** — количество транзакций в секунду.

### Критерии выбора форка

- **Максимальная совместимость с экосистемой Oracle:** Oracle MySQL.
- **Требования к глубокому мониторингу и MyRocks:** Percona Server.
- **Аналитические задачи и векторный поиск:** MariaDB.

### Миграция между форками

- **MySQL ↔ Percona:** Возможна прямая миграция через копирование файлов данных (бинарная совместимость).
- **MySQL 8+ → MariaDB:** Требуется логический дамп и восстановление (`mysqldump` / `mariadb-dump`). GTID (Global Transaction Identifier) несовместимы.

## Дополнительная информация

### Утилиты и инструменты

- **Резервное копирование:** В MySQL используется `mysqldump`, в MariaDB — `mariadb-dump`. Для физического бэкапа рекомендуются `XtraBackup` (Percona) или `MariaBackup` (MariaDB).
- **Кластерные решения:** MySQL InnoDB Cluster (Oracle), Percona XtraDB Cluster (Galera), MariaDB Galera Cluster.
