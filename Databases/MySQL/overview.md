# MySQL: Обзор и сравнение форков

## Определения

**MySQL** — реляционная система управления базами данных (СУБД), изначально разработанная компанией MySQL AB. На текущий момент экосистема MySQL разделена на три основных направления: оригинальная версия от Oracle, оптимизированная Percona Server и независимая MariaDB.

**Форк (Fork)** — ответвление исходного кода, создающее независимый продукт. Форки MySQL сохраняют высокую степень совместимости на уровне протоколов и SQL-синтаксиса, но значительно различаются во внутренних механизмах и наборе дополнительных функций.

**Релизные модели (Oracle/Percona):**
- **LTS (Long Term Support):** Стабильные версии (например, **8.4 LTS**). Фокус на надежности, поддержка до 8 лет.
- **Innovation:** Версии с частыми обновлениями (например, **9.x**). Содержат новейшие функции (например, векторные типы данных), но имеют короткий цикл поддержки.

## Базовые концепции

### Архитектура InnoDB и внутренние механизмы
**InnoDB** — основной транзакционный движок хранения (Storage Engine) в MySQL и Percona. В MariaDB используется его форк (ранее XtraDB).

Ключевые механизмы InnoDB:
*   **Redo Log:** Журнал опережающей записи (WAL). Гарантирует надежность (Durability): при сбое системы изменения восстанавливаются из этого лога. В MySQL 8.4 управляется параметром `innodb_redo_log_capacity`.
*   **Undo Log:** Хранит данные для отката транзакций и обеспечивает многоверсионность (MVCC). Позволяет читать согласованные данные, даже если они изменяются параллельно.
*   **Doublewrite Buffer:** Защищает от "разорванных страниц" (torn pages) при сбоях питания. Данные сначала пишутся в этот буфер, а затем в основной файл данных.
*   **Change Buffer:** Кэширует изменения вторичных индексов, когда страницы данных не находятся в Buffer Pool. В MariaDB 11.0+ этот механизм **удален**, так как он неэффективен на современных SSD.
*   **Adaptive Hash Index:** Автоматически создает хэш-индексы для часто запрашиваемых страниц InnoDB Buffer Pool для ускорения поиска.

### Репликация и консистентность
В современной документации используется терминология **Источник (Source)** и **Реплика (Replica)** вместо Master/Slave.

**Механизмы репликации:**
1.  **Binary Log (Binlog):** Источник записывает изменения. Типы: **Statement-based** (SQL-запросы), **Row-based** (изменения строк, дефолт в MySQL 8+), **Mixed**.
2.  **Relay Log:** Реплика копирует binlog источника в свой локальный журнал перед выполнением.
3.  **GTID (Global Transaction Identifier):** Уникальный ID каждой транзакции. Позволяет легко переключать реплики между источниками и гарантирует отсутствие дублей при восстановлении.

**Типы синхронизации:**
*   **Асинхронная:** Источник не ждет подтверждения от реплик. Максимальная скорость, риск потери данных.
*   **Полусинхронная (Semi-sync):** Источник ждет подтверждения получения данных (записи в relay log) хотя бы от одной реплики.
*   **Синхронная (Galera Cluster):** Транзакция подтверждается только после успешной записи на все узлы кластера.

### Транзакции и безопасность
*   **XA Транзакции:** Распределенные транзакции, позволяющие согласованно изменять данные в нескольких разных ресурсах (например, в двух разных БД). Используют протокол двухфазной фиксации (2PC).
*   **Транзакционный DDL:** Начиная с MySQL 8.0, операции `ALTER TABLE`, `DROP TABLE` и др. стали атомарными (либо выполняются полностью, либо не выполняются вовсе).
*   **Access Control Lists (ACL):** Система разграничения прав доступа на основе хоста, пользователя и конкретных объектов (БД, таблицы, колонки).
*   **Аутентификация:** В MySQL 9.0+ удален `mysql_native_password`. Стандарт — `caching_sha2_password`.

### Работа с данными и NoSQL
*   **JSON в MySQL:** Бинарный формат хранения позволяет пропускать части документа при поиске. Включает автоматическую валидацию.
*   **MySQL Document Store:** Возможность использовать MySQL как NoSQL-хранилище (через X Plugin). Позволяет работать с JSON-коллекциями без схем, используя CRUD-операции вместо SQL.
*   **Векторный поиск:** Доступен в MariaDB (начиная с 12.3 LTS) и MySQL Innovation (9.x) для задач ИИ (RAG) и поиска по сходству.

## Основные ветки (Форки)

### Oracle MySQL Community Edition
Официальная версия, развиваемая Oracle.
- **Преимущества:** Эталонная реализация InnoDB, поддержка MySQL Document Store, продвинутый **MySQL Shell** (поддержка SQL, JS, Python).
- **Особенности:** **Query Cache** полностью удален в версии 8.0.

### Percona Server for MySQL
Оптимизированный форк, нацеленный на высокую нагрузку и прозрачность.
- **Thread Pool:** Позволяет эффективно обрабатывать тысячи соединений (в Oracle MySQL доступно только в платной Enterprise-версии).
- **Улучшенная диагностика:** Расширенное логирование медленных запросов и полная интеграция с Percona Monitoring and Management (PMM).
- **Движок MyRocks:** Оптимизированное хранение на основе LSM-деревьев для экономии места и ресурса SSD.

### MariaDB
Полностью независимый форк с собственной философией.
- **Движки хранения:** Огромный выбор специализированных движков: **Aria** (безопасная замена MyISAM), **ColumnStore** (аналитика), **Spider** (шардинг).
- **Инновации:** Системное версионирование таблиц (`AS OF SYSTEM TIME`), сохранена поддержка **Query Cache**.
- **Совместимость:** Бинарная совместимость с MySQL 8.0+ нарушена — миграция возможна только через логический дамп.

## Практические сценарии

### Сравнение производительности (бенчмарк 2026)

| Тест | MySQL 8.4 LTS | Percona 8.4 LTS | MariaDB 12.3 LTS |
| :--- | :---: | :---: | :---: |
| **OLTP Write (высокая нагрузка)** | Хорошо | **Отлично (Thread Pool)** | Удовлетворительно |
| **Аналитика (OLAP / Big Data)** | Средне | Средне | **Отлично (ColumnStore)** |
| **Сжатие (Space Saving)** | Средне | **Отлично (MyRocks)** | **Отлично (MyRocks)** |

### Критерии выбора форка
- **Oracle MySQL:** Если нужна максимальная предсказуемость, стандартная экосистема и поддержка NoSQL (Document Store).
- **Percona Server:** Если требуется Thread Pool "бесплатно", глубокий мониторинг (PMM) или нужно экономить место на диске (MyRocks).
- **MariaDB:** Если нужны исторические таблицы (версионирование), аналитические функции или векторный поиск в рамках LTS-релиза.

## Дополнительная информация

### Утилиты и инструменты
- **Обслуживание:** Утилита `mysqlcheck` (в MariaDB — `mariadb-check`) для проверки и оптимизации таблиц.
- **Резервное копирование:** 
  - Логическое: `mysqldump` / `mariadb-dump`.
  - Физическое (горячее): `Percona XtraBackup` или `MariaBackup`.
- **Прокси и балансировка:** 
  - **MaxScale (MariaDB):** Интеллектуальный прокси с поддержкой Read/Write Split и автоматического Failover.
  - **ProxySQL:** Универсальный прокси с гибкой маршрутизацией запросов.
- **Администрирование:** **Percona Toolkit** — набор скриптов для проверки консистентности репликации (`pt-table-checksum`) и онлайн-смены схем (`pt-online-schema-change`).
