# MySQL: Обзор и сравнение форков

## Definitions

**MySQL** — реляционная система управления базами данных (СУБД), изначально разработанная компанией MySQL AB. После поглощения Sun Microsystems корпорацией Oracle в 2010 году, MySQL перешла под контроль Oracle и с тех пор развивается в нескольких направлениях.

**Форк (Fork)** — ответвление исходного кода проекта, создающее независимую версию продукта. В экосистеме MySQL существуют три основных форка, каждый со своей философией развития и набором особенностей.

## Basic Concepts

### Три основных форка MySQL

На март 2026 года существуют три основные версии MySQL, каждая из которых имеет свои особенности:

| Форк | Разработчик | Текущая версия | Движок по умолчанию |
| :--- | :--- | :--- | :--- |
| **Oracle MySQL** | Oracle Corporation | 8.4.8 (LTS) / 9.6.0 (Innovation) | InnoDB |
| **Percona Server** | Percona Corporation | 8.4.7-7 (LTS) / 8.0.45-36 | XtraDB (форк InnoDB) |
| **MariaDB** | MariaDB Foundation | 11.4.10 (LTS) / 10.11.16 (LTS) | InnoDB/XtraDB |

### 1. Oracle MySQL Community Edition

**Оригинальная версия MySQL**, разрабатываемая Oracle Corporation.

**Ключевые особенности:**

- **Модель разработки:**
  - **LTS (Long Term Support)** — стабильные версии с длительной поддержкой (например, 8.4)
  - **Innovation** — версии с новыми функциями, не рекомендуемые для production (например, 9.0)
  
- **Движок InnoDB:** Основной акцент на развитии InnoDB, остальные движки (MyISAM, Memory) постепенно выводятся из употребления или не развиваются.

- **Транзакционный DDL:** Начиная с версии 8.0, операции DDL (CREATE, ALTER, DROP) стали транзакционными для InnoDB.

- **MySQL Shell:** Продвинутый клиент с поддержкой JavaScript, Python и SQL для управления сервером.

- **Оптимизация для высокой конкурентности:** Улучшения в управлении блокировками и доступом для многопоточных систем с интенсивной записью.

- **Изменения в совместимости:** В минорных релизах версии 8.x формат данных мог меняться, что требовало осторожности при обновлении.

**Ограничения:**

- Query Cache полностью удалён в версии 8.0 из-за проблем с производительностью в высококонкурентных средах.
- Закрытая модель разработки новых функций (не все изменения обсуждаются с сообществом).

**Документация:** [dev.mysql.com](https://dev.mysql.com/doc/)

---

### 2. Percona Server for MySQL

**Форк Oracle MySQL**, представляющий собой набор патчей поверх оригинальной кодовой базы.

**Ключевые особенности:**

- **Полная совместимость:** Версии синхронизированы с Oracle MySQL (например, Percona Server 8.0 соответствует MySQL 8.0).

- **Движок XtraDB:** Форк InnoDB с дополнительными улучшениями производительности и мониторинга.

- **Движок MyRocks:** Поддержка LSM-деревьев для сжатия данных и оптимизации операций записи.

- **Улучшенный мониторинг:**
  - Более детальное логирование медленных запросов
  - Расширенные метрики производительности
  - Audit-фильтры для безопасности

- **Перконовские патчи:** Оптимизации для специфических сценариев использования (адаптивные сетевые буферы, улучшенное управление транзакциями).

- **Percona Monitoring and Management (PMM):** Собственная система мониторинга с готовыми дашбордами.

- **Кластеризация:** Поддержка Galera Cluster для синхронной репликации.

**Сценарии использования:**

- Высоконагруженные production-системы, требующие расширенного мониторинга
- Системы с интенсивной записью (MyRocks)
- Требования к аудиту и безопасности

**Документация:** [percona.com/doc](https://www.percona.com/doc/percona-server/LATEST/index.html)

### 3. MariaDB

**Независимый форк**, созданный оригинальными разработчиками MySQL (включая Монти Видениуса) из-за несогласия с политикой Oracle.

**Ключевые особенности:**

- **Открытая разработка:** Управление через независимый фонд MariaDB Foundation, все изменения обсуждаются сообществом.

- **Несовместимость с MySQL 8+:** Начиная с версии MySQL 8.0, пути развития разошлись настолько, что прямая бинарная миграция невозможна. Требуется логический дамп.

- **Множество движков хранения:** В отличие от фокуса на InnoDB в MySQL, MariaDB активно развивает специализированные движки:
  - **Aria** — улучшенный MyISAM с восстановлением после сбоев
  - **ColumnStore** — колоночное хранение для аналитики (OLAP)
  - **MyRocks** — поддержка LSM-деревьев
  - **S3 Storage Engine** — хранение данных в Amazon S3
  - **Spider** — шардинг на уровне СУБД

- **Query Cache:** Сохранён (в отличие от MySQL 8.0), но может быть отключён из-за проблем с блокировками.

- **Расширенные типы данных:** `UUID`, `INET4`, `INET6` для нативного хранения соответствующих значений.

- **SQL-совместимость:** Поддержка `CREATE OR REPLACE TABLE`, `DELETE ... RETURNING`, последовательностей (`CREATE SEQUENCE`).

- **Регулярные выражения:** На базе PCRE (в Oracle MySQL — только POSIX).

- **MaxScale:** Прокси-балансировщик нагрузки (вышел из open-source в проприетарную лицензию).

**Ограничения:**

- Отсутствие поддержки операторов для JSON (в старых версиях)
- Нет ролей в ранних версиях
- GTID несовместимы с MySQL

**Документация:** [mariadb.com/kb](https://mariadb.com/kb/)

**Подробнее:** [MariaDB: Обзор](../MariaDB/overview.md)

## Practical Scenarios

### Сравнение производительности (бенчмарк 2026 — Percona)

Тестирование проводилось на идентичных конфигурациях с использованием sysbench OLTP-тестов.

**Участники тестирования:**

- MySQL 5.7.44, 8.0.45, 8.4.8, 9.6.0 (Oracle)
- Percona Server 5.7.44-48, 8.0.45-36, 8.4.7-7
- MariaDB 10.11.16, 11.4.10, 12.1.2

**Результаты (TPS — transactions per second):**

| Тест | MySQL 8.4.8 | Percona 8.4.7-7 | MariaDB 10.11.16 | MariaDB 11.4.10 |
| :--- | :--- | :--- | :--- | :--- |
| **Read-Write (32 GB, 512 threads)** | ~13 325 | **~13 385** | ~9 800 (peak @128) | ~9 500 (peak @128) |
| **Read-Only (32 GB, 128 threads)** | ~23 500 | ~23 800 | **~32 392** | ~23 500 |
| **Read-Write (2 GB, 512 threads)** | ~530 | ~450 (worst) | ~600 | **~813** (Percona 5.7) |
| **Read-Write (10 Gb/s, 512 threads)** | ~12 781 | **~13 076** | ~11 200 | ~10 800 |

**Выводы:**

1. **Read-Write (высокая конкуренция):** Percona 8.4 и MySQL 8.4 лидируют с результатом ~13 300 TPS при 512 потоках. MariaDB показывает пик на 128 потоках, затем деградация производительности.

2. **Read-Only:** MariaDB 10.11 демонстрирует преимущество (~32 000 TPS), на 38% выше следующих результатов.

3. **Ограниченная память (2 GB):** Percona 5.7 показывает лучший результат (813 TPS), современные версии 8.4 plateau на ~530 TPS.

4. **Сетевая нагрузка:** Сеть добавляет 2–10% оверхеда. Percona 8.4 и MySQL 8.4 минимально подвержены влиянию.

5. **Эволюция версий:**
   - **MariaDB:** Версии 11.4 и 12.1 показывают регресс относительно 10.11 (до -27% в Read-Only).
   - **MySQL:** Версии 8.4/9.6 превосходят 5.7 на 300%+ при высокой конкуренции (512 потоков).
   - **Percona vs MySQL:** Разница между MySQL 8.0 и Percona 8.0 менее 3% (патчи Percona не оказывают значимого влияния на OLTP).

> **Важно:** Увеличение Buffer Pool с 2 GB до 32 GB даёт прирост производительности в 10–26 раз. Результаты могут варьироваться в зависимости от конкретной нагрузки, настроек и аппаратной конфигурации. Рекомендуется проводить собственное тестирование перед выбором форка.

### Критерии выбора форка

| Критерий | Рекомендация |
| :--- | :--- |
| **Максимальная совместимость** | Oracle MySQL или Percona Server |
| **Расширенный мониторинг** | Percona Server (PMM, детальное логирование) |
| **Высокая конкурентность записи** | MariaDB (по результатам бенчмарков) |
| **Аналитика (OLAP)** | MariaDB (ColumnStore) |
| **Шардинг** | MariaDB (Spider) |
| **Query Cache** | MariaDB (единственный с поддержкой) |
| **Открытость разработки** | MariaDB |
| **Enterprise-поддержка** | Oracle MySQL или Percona |

### Миграция между форками

**MySQL 5.7 → MariaDB:**
- Прямая миграция возможна (совместимый формат данных)
- Достаточно скопировать файлы данных или использовать репликацию

**MySQL 8.x → MariaDB:**
- Прямая миграция **невозможна** (несовместимый формат данных)
- Требуется логический дамп (`mysqldump` / `mariadb-dump`)
- GTID несовместимы — репликация между форками невозможна

**Oracle MySQL ↔ Percona Server:**
- Полная совместимость (Percona — набор патчей поверх MySQL)
- Возможна прямая миграция копированием файлов
- Репликация работает без ограничений

## Additional Information

### Исполняемые файлы

MariaDB проводит ребрендинг исполняемых файлов:
- `mysql` → `mariadb` (клиент)
- `mysqldump` → `mariadb-dump`
- Старые имена сохранены как символические ссылки для совместимости

### Резервное копирование

- **Oracle MySQL / Percona:** `mysqldump`, `mysqlbackup` (Enterprise), `xtrabackup` (Percona)
- **MariaDB:** `mariadb-dump`, `mariabackup` (форк xtrabackup)

### Кластерные решения

- **Oracle MySQL:** MySQL InnoDB Cluster (на базе MySQL Shell и Group Replication)
- **Percona:** Percona XtraDB Cluster (на базе Galera)
- **MariaDB:** MariaDB Galera Cluster (встроенная поддержка)
