# Установка и начало работы с MySQL

## Определения

**MySQL Server (`mysqld`)** — основной процесс СУБД, отвечающий за управление данными, обработку SQL-запросов, управление памятью и обеспечение транзакционности (ACID).

**MySQL Client (`mysql`)** — консольная утилита для выполнения SQL-запросов и администрирования. В современных версиях (8.4+) рекомендуется использовать **MySQL Shell (`mysqlsh`)** для продвинутых задач, включая работу с JSON и управление кластерами.

**mysqld_safe** — скрипт-обертка, который запускает сервер `mysqld`, отслеживает его состояние и автоматически перезапускает при аварийном завершении, записывая ошибки в лог.

**Systemd Unit** — файл конфигурации службы (обычно `mysql.service` или `mysqld.service`), управляющий жизненным циклом процесса через `systemctl`.

**Модели релизов (с 2024 года):**
- **LTS (Long Term Support):** Стабильные версии (например, **8.4 LTS**). Предназначены для критических Production-систем. Поддержка — до 8 лет.
- **Innovation:** Версии для быстрого внедрения новых функций (например, **9.0**). Каждая версия поддерживается только до выхода следующей (раз в 3 месяца).

## Базовые концепции

### Архитектура и уровни обработки
MySQL имеет многоуровневую архитектуру, что важно понимать для правильной установки и отладки:
1.  **Уровень соединений:** Обработка подключений, аутентификация и проверка безопасности.
2.  **Ядро СУБД:** Парсинг запросов, анализ, оптимизация (выбор индексов) и кэширование.
3.  **Уровень хранилищ (Storage Engines):** Модульная архитектура, позволяющая использовать разные движки (InnoDB — стандарт, MyISAM, Memory). Установка MySQL по умолчанию настраивает InnoDB как основной движок.

### Требования и подготовка (Prerequisites)
Перед установкой необходимо убедиться в выполнении следующих условий:
- **Ресурсы:** Минимум 1 ГБ RAM (для стабильной работы InnoDB с минимальным `buffer_pool_size`).
- **Пользователи:** СУБД должна запускаться от имени системного пользователя `mysql`. В современных дистрибутивах пакетный менеджер создает его автоматически.
- **Сеть:** Порт `3306/tcp` должен быть открыт в Firewall, если планируется удаленный доступ.
- **Файловая система:** Рекомендуется выделять отдельный логический том (LVM) или диск для `/var/lib/mysql`, чтобы избежать переполнения корневого раздела логами или данными.

### Репозитории Oracle vs Стандартные репозитории ОС
Стандартные репозитории дистрибутивов (Ubuntu 24.04, RHEL 9) часто содержат ветку 8.0, которая близится к EOL (октябрь 2026). Для получения актуальных **8.4 LTS** или **9.x Innovation** необходимо подключать официальные репозитории Oracle через пакеты конфигурации (`mysql-apt-config` или `mysql84-community-release`).

### Безопасность и аутентификация
- **Методы входа:** По умолчанию в 8.4+ используется плагин `caching_sha2_password`. Если старое приложение требует `mysql_native_password`, его нужно включить явно в конфигурации, так как в будущих версиях (9.0+) он удален.
- **Закалка (Hardening):** Скрипт `mysql_secure_installation` обязателен. Он отключает небезопасные настройки по умолчанию (анонимные пользователи, удаленный root).

## Практические сценарии

### 1. Установка на Debian / Ubuntu (24.04+)

На Ubuntu выбор версии осуществляется через интерактивный конфигуратор.

```bash
# 1. Загрузка конфигуратора репозитория
wget https://dev.mysql.com/get/mysql-apt-config_0.8.39-1_all.deb

# 2. Установка конфигуратора
sudo dpkg -i mysql-apt-config_0.8.39-1_all.deb
# -> Выберите "MySQL Server & Cluster" -> "mysql-8.4-lts" -> "Ok"

# 3. Установка сервера
sudo apt update
sudo apt install -y mysql-server

# 4. Проверка и запуск
sudo systemctl enable --now mysql
```

### 2. Установка на Rocky Linux / RHEL / AlmaLinux (9.x)

```bash
# 1. Добавление репозитория
sudo dnf install -y https://dev.mysql.com/get/mysql84-community-release-el9-1.noarch.rpm

# 2. Установка сервера (пакет community-server содержит все зависимости)
sudo dnf install -y mysql-community-server

# 3. Запуск службы
sudo systemctl enable --now mysqld
```

### 3. Начальная настройка и валидация

**Шаг 1: Получение временного пароля (только для RHEL-систем)**
```bash
sudo grep 'temporary password' /var/log/mysqld.log
```

**Шаг 2: Запуск закалки безопасности**
```bash
sudo mysql_secure_installation
```

**Шаг 3: Проверка состояния установки**
```bash
# Проверка версии и подключения
mysqladmin -u root -p version

# Проверка статуса движков
sudo mysql -e "SHOW ENGINES;"
```

### 4. Создание базы данных и пользователя

```sql
-- Создание БД с поддержкой эмодзи и правильной сортировкой
CREATE DATABASE app_production 
CHARACTER SET utf8mb4 
COLLATE utf8mb4_0900_ai_ci;

-- Создание пользователя с ограничением по сети
CREATE USER 'web_app'@'192.168.1.%' IDENTIFIED BY 'Complex_Password_2026!';

-- Принцип минимальных привилегий (вместо ALL PRIVILEGES)
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP ON app_production.* TO 'web_app'@'192.168.1.%';

FLUSH PRIVILEGES;
```

### 5. Обновление MySQL

При переходе между минорными версиями (например, 8.4.1 -> 8.4.2) процесс автоматизирован:
1.  **Бэкап:** `mysqldump --all-databases > full_backup.sql`.
2.  **Обновление пакетов:** `sudo apt update && sudo apt upgrade mysql-server`.
3.  **Перезапуск:** `sudo systemctl restart mysql`.
4.  **Проверка:** MySQL 8.0.16+ выполняет `mysql_upgrade` автоматически при старте.

### 6. Поиск и устранение неисправностей (Troubleshooting)

- **Ошибка: "Can't connect to local MySQL server through socket"**
  - *Причина:* Сервер не запущен или путь к сокету в `my.cnf` не совпадает с клиентом.
  - *Решение:* Проверьте `systemctl status mysql` и лог `/var/log/mysql/error.log`.
- **Ошибка: "InnoDB: Upgrade after a crash is not supported"**
  - *Причина:* Попытка обновиться на "грязных" данных после сбоя.
  - *Решение:* Вернитесь на старую версию, выполните чистую остановку (`SET GLOBAL innodb_fast_shutdown = 0`), затем обновляйтесь.
- **Занятый порт 3306:**
  - *Диагностика:* `sudo ss -tulpn | grep 3306`.
  - *Решение:* Остановите конфликтующий процесс (например, MariaDB).

## Дополнительная информация

### Рекомендации (Best Practices)
1.  **Лимиты ресурсов:** Всегда настраивайте `innodb_buffer_pool_size` (рекомендуется 50-75% от общего объема RAM на выделенном сервере).
2.  **Логирование:** Включите `slow_query_log` для идентификации проблемных запросов на ранних этапах.
3.  **Изоляция:** Используйте `AppArmor` (Ubuntu) или `SELinux` (RHEL) для ограничения доступа процесса к файловой системе.

### Краевые случаи (Edge Cases)
- **Установка из исходников:** Требуется только если нужны специфические флаги компиляции (например, для очень старых CPU без поддержки специфических инструкций). В 99% случаев используйте бинарные репозитории.
- **Большие пакеты:** Если планируется загрузка крупных файлов/дампов, увеличьте `max_allowed_packet` до 64M или выше сразу после установки.
