# MySQL в Docker

### Определения

**MySQL в Docker** — это подход, при котором сервер базы данных MySQL запускается внутри изолированного контейнера Docker. Это обеспечивает переносимость, консистентность окружения и упрощает развертывание и масштабирование.

### Базовые концепции

#### 1. Персистентность данных: Volumes

**Категорически запрещено** хранить данные базы данных внутри файловой системы контейнера, так как они будут утеряны при его удалении. Для обеспечения сохранности данных используются **именованные тома (named volumes)**.

-   **Принцип:** Том (`mysql-data`) монтируется в директорию, где MySQL хранит свои файлы (`/var/lib/mysql`). Все данные, записанные в эту директорию, физически сохраняются в управляемой Docker области на хост-машине.
-   **Преимущество:** Тома существуют независимо от контейнеров. Вы можете удалить, обновить и запустить новый контейнер MySQL, подключив к нему ранее созданный том, и все данные останутся нетронутыми.

#### 2. Конфигурация

Для применения кастомных настроек MySQL используется монтирование файла конфигурации (`my.cnf`) из хост-системы в контейнер.

#### 3. Инициализация

Официальные образы MySQL поддерживают механизм автоматической инициализации базы данных при первом запуске на пустом томе. Скрипты (`.sh`, `.sql`, `.sql.gz`), помещенные в директорию `/docker-entrypoint-initdb.d/` внутри контейнера, будут выполнены в алфавитном порядке.

#### 4. Производительность: Host vs Docker

Производительность MySQL в Docker напрямую зависит от двух факторов: **дискового I/O** и **сетевого режима**.

-   **Дисковый I/O:** При использовании `docker volume` накладные расходы минимальны, так как операции ввода-вывода транслируются напрямую в файловую систему хоста. Узким местом, как и при нативной установке, остается производительность дисковой подсистемы хоста.

-   **Сетевой режим (`bridge` vs `host`):** Это ключевой фактор, влияющий на производительность.
    -   **Режим `bridge` (по умолчанию):** Трафик проходит через userspace-прокси `docker-proxy`, что создает значительные накладные расходы на CPU при большом количестве мелких и быстрых запросов. Падение производительности на read-only нагрузках может достигать **50% и более** по сравнению с нативной установкой.
    -   **Режим `host` (`--network host`):** Контейнер использует сетевой стек хоста напрямую, исключая `docker-proxy`. Этот режим обеспечивает максимальную сетевую производительность, сравнимую с нативной, и является **рекомендованным для production-окружений**. Недостатки — снижение уровня сетевой изоляции и риск конфликта портов.

### Практические сценарии

#### 1. Базовый запуск с именованным томом

```bash
# 1. Создаем именованный том для данных
docker volume create mysql-data

# 2. Запускаем контейнер MySQL, монтируя том
docker run -d --name mysql-db \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=my-secret-pw \
  -v mysql-data:/var/lib/mysql \
  mysql:8.4
```

#### 2. Запуск с кастомной конфигурацией

```bash
# Пробрасываем свой my.cnf в контейнер
docker run -d --name mysql-db-custom-config \
  -p 3307:3306 \
  -e MYSQL_ROOT_PASSWORD=my-secret-pw \
  -v mysql-data:/var/lib/mysql \
  -v ./my.cnf:/etc/mysql/conf.d/custom.cnf \
  mysql:8.4
```

#### 3. Запуск со скриптами инициализации

```bash
# Монтируем директорию со скриптами для первоначальной настройки
docker run -d --name mysql-db-initialized \
  -p 3308:3306 \
  -e MYSQL_ROOT_PASSWORD=my-secret-pw \
  -v mysql-data:/var/lib/mysql \
  -v ./init-scripts:/docker-entrypoint-initdb.d \
  mysql:8.4
```

#### 4. Запуск для максимальной производительности

```bash
# Используем сетевой режим 'host' для минимизации задержек
docker run -d --name mysql-db-high-perf \
  --network host \
  -e MYSQL_ROOT_PASSWORD=my-secret-pw \
  -v mysql-data:/var/lib/mysql \
  mysql:8.4
```
> **Примечание:** В режиме `--network host` проброс портов (`-p`) не требуется и не работает. MySQL будет доступен напрямую по порту 3306 на IP-адресе хоста.
