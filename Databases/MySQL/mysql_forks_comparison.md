## Сравнение форков MySQL: Oracle vs Percona vs MariaDB

На рынке существует три основных, активно развивающихся форка MySQL, каждый из которых обладает своими особенностями. Выбор между ними зависит от конкретных требований к производительности, функциональности и экосистеме.

| Характеристика | Oracle MySQL Community | Percona Server for MySQL | MariaDB |
| :--- | :--- | :--- | :--- |
| **Основа** | Оригинальный MySQL от Oracle | Fork Oracle MySQL | Fork оригинального MySQL (до Oracle) |
| **Совместимость** | Эталон | **Полная drop-in замена** для Oracle MySQL | Высокая, но с растущими различиями после v5.7 |
| **Основной движок** | InnoDB | XtraDB (улучшенный InnoDB) | InnoDB, **Aria**, **MyRocks**, **ColumnStore** |
| **Системные таблицы**| InnoDB | InnoDB | **Aria** |
| **Query Cache** | **Удален** в v8.0 | **Удален** в v8.0 | **Сохранен и поддерживается** |
| **Кластеризация** | NDB Cluster (отдельный продукт) | Percona XtraDB Cluster (на базе Galera) | MariaDB Galera Cluster (встроен) |
| **Ключевые фокусы** | Развитие InnoDB, MySQL Shell, JSON | Производительность, мониторинг, enterprise-фичи в open-source | Открытость, разнообразие движков, новые SQL-фичи |
| **Экосистема** | Официальные инструменты Oracle | Percona Monitoring and Management (PMM), Percona XtraBackup | MariaDB MaxScale (BSL), MariaDB Backup |

---

### Oracle MySQL Community Edition

- **Разработчик:** Oracle Corporation.
- **Философия:** Основной упор делается на развитие движка InnoDB. Вся СУБД, включая системные таблицы, переведена на InnoDB.
- **Особенности:**
    - **MySQL Shell:** Продвинутый клиент для работы с базой.
    - **Удаление старых фич:** `query_cache` был полностью удален в версии 8.0, так как считался неэффективным и источником блокировок при высоких нагрузках.
    - **JSON:** Улучшенная поддержка функций и операторов для работы с JSON.
    - **X-Protocol:** Новый протокол для доступа к данным, используемый MySQL Shell.

---

### Percona Server for MySQL

- **Разработчик:** Percona.
- **Философия:** Взять лучшее от Oracle MySQL и добавить enterprise-уровня фичи, связанные с производительностью, диагностикой и мониторингом, оставаясь при этом в рамках open-source. Является **полностью совместимой заменой** (drop-in replacement) для Oracle MySQL.
- **Особенности:**
    - **XtraDB:** Собственный форк InnoDB с патчами для улучшения производительности и масштабируемости.
    - **Расширенный мониторинг:** Дополнительные метрики и таблицы для глубокого анализа производительности (например, **User Statistics**, **Thread Pool** для управления потоками).
    - **Percona XtraBackup:** Де-факто стандарт индустрии для горячего физического резервного копирования InnoDB/XtraDB.
    - **Интеграция с PMM:** Глубокая интеграция с Percona Monitoring and Management для всестороннего мониторинга.
    - **MyRocks:** Поддержка движка хранения MyRocks.

---

### MariaDB

> Для получения более подробной информации см. основной документ: **[Обзор MariaDB](../MariaDB/overview.md)**


- **Разработчик:** MariaDB Corporation Ab и сообщество (основан оригинальными разработчиками MySQL).
- **Философия:** Создание по-настоящему открытого и управляемого сообществом форка MySQL с сохранением духа поддержки множества движков хранения и активного внедрения новых возможностей.
- **Особенности:**
    - **Разнообразие движков:** Помимо InnoDB, активно развиваются и поддерживаются другие движки: **[Aria](../MariaDB/mariadb_storage_engines.md)** (транзакционная замена MyISAM), **[ColumnStore](../MariaDB/mariadb_storage_engines.md)** (колоночное хранилище), **[MyRocks](../MariaDB/mariadb_storage_engines.md)**, **S3 Engine**.
    - **Сохранение `query_cache`:** В отличие от Oracle, `query_cache` не был удален и продолжает поддерживаться, что может быть полезно для определенных типов нагрузок (преобладание чтения).
    - **Новые SQL-фичи:** Добавляются новые типы данных (`UUID`, `INET6`), функции (полноценные регулярные выражения PCRE), синтаксический сахар (`CREATE OR REPLACE TABLE`).
    - **Оптимизатор запросов:** Активная работа над улучшением оптимизатора запросов.
    - **MariaDB Backup:** Собственный форк Percona XtraBackup для обеспечения совместимости с новыми версиями MariaDB.

### Несовместимость и миграция

- **Percona Server:** Миграция с Oracle MySQL и обратно обычно проходит безболезненно, так как форматы данных полностью совместимы в рамках одной мажорной версии.
- **MariaDB:**
    - Начиная с версий после 5.7 (MySQL) и 10.1 (MariaDB), форматы данных и функциональность начали значительно расходиться.
    - Прямой бинарный апгрейд с MySQL 8.x на MariaDB 10.x/11.x **невозможен**. Миграция требует **логического дампа (`mysqldump`)** и восстановления.
    - Ключевые различия, требующие внимания при миграции:
        - Разная реализация **GTID**.
        - Отличия в хранении и функциях для работы с **JSON**.
        - Различия в реализации ролей и аутентификации.
        - Разные системные таблицы (InnoDB в MySQL vs Aria в MariaDB).
    - **Лицензирование:** Некоторые компоненты экосистемы, например, прокси **`MaxScale`**, распространяются по **Business Source License (BSL)**, что накладывает ограничения на бесплатное коммерческое использование (более 2 серверов).
