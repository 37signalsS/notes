# Репликация MySQL: Обзор

## Определения

**Репликация MySQL** — это процесс создания и поддержания идентичных копий (реплик) базы данных на нескольких серверах. Данные копируются с основного сервера, называемого **Master**, на один или несколько подчиненных серверов, называемых **Slave**.

## Ключевые компоненты

- **Master Server (Ведущий)**: Источник данных, на котором происходят все операции записи. Изменения фиксируются в специальном журнале.

- **Slave Server (Ведомый)**: Копия Master-сервера, которая получает изменения от Master и применяет их к своей копии данных. Обычно используется для распределения нагрузки на чтение, резервного копирования или как "горячий" резерв.

- **Бинарный лог (Binary Log)**: Файл на Master-сервере, в который записываются все события, изменяющие данные (DML) или структуру базы данных (DDL). Является основой для репликации.

- **Журнал ретрансляции (Relay Log)**: Файл на Slave-сервере, в который I/O-поток записывает события, полученные из бинарного лога Master-сервера. SQL-поток читает события из этого журнала и выполняет их.
