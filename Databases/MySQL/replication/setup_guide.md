# Пошаговая настройка репликации MySQL

## Определения

**Репликация MySQL** — процесс синхронизации данных между несколькими серверами, обеспечивающий отказоустойчивость и масштабируемость.

**Источник (Source)** — основной сервер, генерирующий события бинарного лога.
**Реплика (Replica)** — подчиненный сервер, применяющий события из бинарного лога источника.

**GTID (Global Transaction Identifier)** — уникальный идентификатор каждой транзакции. Рекомендуемый стандарт для современных инсталляций, позволяющий автоматически находить позицию в логах.

**Classic Replication** — метод репликации с использованием явных координат бинарного лога (имя файла и позиция).

## Основные концепции

### Предварительные требования и надежность

Для промышленной эксплуатации (Production) на всех узлах должны быть установлены следующие параметры:

| Группа | Параметр | Значение | Описание |
| :--- | :--- | :--- | :--- |
| **Сетевая** | Порт | 3306 | Должен быть открыт между Source и Replica. |
| **Идентификация** | `server_id` | Уникальный | Целое число (1-4294967295), разное для всех узлов. |
| **Бинарный лог** | `binlog_format` | `ROW` | Обеспечивает максимальную консистентность данных. |
| **Надежность** | `sync_binlog` | `1` | Сброс binlog на диск после каждой транзакции. |
| **Надежность** | `innodb_flush_log_at_trx_commit` | `1` | Сброс логов InnoDB (Redo Log) на диск после каждой транзакции. |

### Методы инициализации реплики

1.  **MySQL Clone Plugin:**
    *   **Для кого:** Новые реплики в MySQL 8.0.17+.
    *   **Плюсы:** Не требует места под дамп, очень быстрый (физическое копирование).
2.  **MySQL Shell (`util.dumpInstance`):**
    *   **Для кого:** Крупные БД (> 50 ГБ), миграция в облака.
    *   **Плюсы:** Параллельная выгрузка и загрузка, поддержка S3.
3.  **mysqldump:**
    *   **Для кого:** Небольшие БД, устаревшие версии.
    *   **Плюсы:** Текстовый формат, универсальность.
4.  **Percona XtraBackup:**
    *   **Для кого:** Крупные БД с высокими требованиями к аптайму (Hot Backup).
    *   **Плюсы:** Не блокирует источник, физическое копирование.

## Практические сценарии

### 1. Подготовка Источника (Source)

**Создание пользователя с правами репликации:**
```sql
CREATE USER 'repl_user'@'%' IDENTIFIED BY 'StrongPassword123!';
GRANT REPLICATION SLAVE ON *.* TO 'repl_user'@'%';

-- Дополнительно для Clone Plugin
GRANT BACKUP_ADMIN ON *.* TO 'repl_user'@'%';
```

**Конфигурация `my.cnf`:**
```ini
[mysqld]
server_id = 101
gtid_mode = ON
enforce_gtid_consistency = ON
log_bin = /var/log/mysql/mysql-bin.log
binlog_format = ROW

# Надежность и очистка
sync_binlog = 1
innodb_flush_log_at_trx_commit = 1
binlog_expire_logs_seconds = 604800 # 7 дней
```

### 2. Настройка Реплики через Clone Plugin

Самый современный способ развертывания реплики.

**На обоих серверах:**
```sql
INSTALL PLUGIN clone SONAME 'mysql_clone.so';
```

**На Реплике:**
```sql
-- Указываем список доверенных доноров
SET GLOBAL clone_valid_donor_list = '192.168.1.10:3306';

-- Запуск клонирования (сервер перезагрузится автоматически)
CLONE INSTANCE FROM 'repl_user'@'192.168.1.10':3306 IDENTIFIED BY 'StrongPassword123!';
```

### 3. Настройка GTID-репликации (ручная)

Если данные уже перенесены (например, через дамп):

**На Реплике:**
```sql
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='192.168.1.10',
  SOURCE_USER='repl_user',
  SOURCE_PASSWORD='StrongPassword123!',
  SOURCE_AUTO_POSITION = 1;

START REPLICA;
```

### 4. Настройка классической репликации (без GTID)

Используется только в специфических случаях или на старых версиях.

1. **На Источнике:** Получить позицию после снятия бэкапа.
   `SHOW MASTER STATUS;` → `mysql-bin.000001`, `154`
2. **На Реплике:**
```sql
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='192.168.1.10',
  SOURCE_USER='repl_user',
  SOURCE_PASSWORD='StrongPassword123!',
  SOURCE_LOG_FILE='mysql-bin.000001',
  SOURCE_LOG_POS=154;
```

### 5. Использование фильтров (Специфика)

Для исключения баз данных или таблиц настраивайте фильтры на **Реплике**. Рекомендуется использовать `wildcard` фильтры для корректной работы с транзакциями.

```ini
[mysqld]
# Реплицировать только конкретные таблицы (wildcard надежнее)
replicate-wild-do-table = production_db.%
# Игнорировать временные базы
replicate-ignore-db = tmp_test_db
```

## Дополнительная информация

### Безопасность и стабильность

*   **SSL/TLS:** Всегда используйте шифрование при репликации через незащищенные сети.
    `CHANGE REPLICATION SOURCE TO ..., SOURCE_SSL = 1;`
*   **Crash-Safe Replication:** В MySQL 8.0 репозитории метаданных (`master_info_repository`, `relay_log_info_repository`) по умолчанию находятся в таблицах InnoDB. Это гарантирует атомарность обновления позиции и данных.
*   **Primary Keys:** Установите `sql_generate_invisible_primary_key = ON` (8.0.30+) или контролируйте наличие ПК. Репликация таблиц без PK крайне медленна.

### Мониторинг

```sql
-- Проверка статуса
SHOW REPLICA STATUS\G

-- Проверка через системные представления (MySQL 8.0)

SELECT * FROM performance_schema.replication_applier_status_by_worker;
```
