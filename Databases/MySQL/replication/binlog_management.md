# Управление бинарными логами в MySQL

## Определения

**Бинарный лог (Binary Log)** — журнал всех событий, изменяющих данные (DML) или структуру базы данных (DDL). Является основой для репликации и восстановления данных на определенный момент времени (**Point-in-Time Recovery — PITR**).

**Управление логами** — процесс настройки ротации, очистки и защиты журналов для обеспечения баланса между доступностью данных для восстановления и свободным местом на диске.

## Основные концепции

### Параметры жизненного цикла логов

MySQL 8.0+ предоставляет гибкие инструменты для автоматического управления объемом логов:

- **binlog_expire_logs_seconds:** Основной параметр для настройки времени хранения (заменил устаревший `expire_logs_days`). Определяет, через какое время после создания файл будет автоматически удален.
- **max_binlog_size:** Размер одного файла, при достижении которого происходит ротация (создание нового файла). Обычно устанавливается в пределах 100MB – 1GB.
- **binlog_space_limit:** (MySQL 8.0.x+) Позволяет задать жесткий лимит на суммарный объем всех бинарных логов на диске. При достижении лимита сервер автоматически удаляет самые старые логи.

### Безопасность и сжатие

Для защиты и оптимизации логов используются следующие технологии:
- **binlog_encryption:** (MySQL 8.0.14+) Шифрование содержимого логов на диске с помощью Keyring-плагина. Защищает данные от чтения при краже физических носителей.
- **binlog_transaction_compression:** (MySQL 8.0.20+) Сжатие событий транзакций с использованием алгоритма ZSTD. Позволяет сократить занимаемое место на 60–90%.
- **sync_binlog:** Определяет частоту сброса лога на диск. Значение `1` гарантирует максимальную сохранность данных при сбоях (Crash-Safety).

### Point-in-Time Recovery (PITR)

Процесс восстановления, позволяющий "проиграть" транзакции из бинарного лога поверх последнего полного бэкапа до определенной секунды или идентификатора транзакции. Это единственный способ минимизировать потери данных (RPO → 0) при авариях.

## Практические сценарии

### Мониторинг занимаемого места

Информацию о логах можно получить как из SQL-интерфейса, так и через системные таблицы:

```sql
-- Просмотр списка файлов и их размеров
SHOW BINARY LOGS;

-- Анализ эффективности сжатия транзакций
SELECT * FROM performance_schema.binary_log_transaction_compression_stats\G
```

### Настройка автоматической очистки

Пример конфигурации в `my.cnf` для хранения логов в течение 10 дней с лимитом на общий объем:

```ini
[mysqld]
# Хранение 10 дней (10 * 24 * 3600)
binlog_expire_logs_seconds = 864000
# Лимит на общий объем логов (например, 50 ГБ)
binlog_space_limit = 53687091200
# Максимальный размер одного файла
max_binlog_size = 512M
```

### Ручная очистка и ротация

Иногда требуется немедленно освободить место или начать новый файл лога вручную.

```sql
-- Принудительная ротация (закрытие текущего файла и создание нового)
FLUSH BINARY LOGS;

-- Удаление всех логов до конкретного файла
PURGE BINARY LOGS TO 'mysql-bin.000123';

-- Удаление логов старше конкретной даты
PURGE BINARY LOGS BEFORE '2024-05-01 00:00:00';
```

### Процедура Point-in-Time Recovery

Пример восстановления данных с помощью утилиты `mysqlbinlog`:

```bash
# Восстановление транзакций до указанного времени
mysqlbinlog --stop-datetime="2024-05-20 10:00:00" \
    /var/lib/mysql/binlog.000001 /var/lib/mysql/binlog.000002 | mysql -u root -p

# Восстановление по GTID (рекомендуется для MySQL 8.0)
mysqlbinlog --include-gtids="uuid:1-100" /var/lib/mysql/binlog.000001 | mysql -u root -p
```

## Дополнительная информация

### Рекомендации по безопасности

1.  **Шифрование:** Включайте `binlog_encryption = ON`, если в базе хранятся персональные данные (PII).
2.  **Синхронизация:** В высоконагруженных системах `sync_binlog = 1` может создавать нагрузку на диск. Если допустима потеря последних транзакций, можно увеличить значение, но это нарушает принцип Crash-Safety.
3.  **Изоляция:** Храните бинарные логи на отдельном физическом диске или разделе. Это предотвратит остановку сервера (из-за переполнения диска с данными) при резком росте объема логов.
