# Управление бинарными логами (binlog)

## Размер бинарных логов

В системах с высокой нагрузкой на запись binlog могут занимать значительно больше места, чем сама база данных.

> **Практический пример:** При объёме БД 40 ГБ и нагрузке ~1000 записей/сек, binlog за неделю могут занять 2–3 ТБ. Рекомендуется выделять под binlog минимум в 50–100 раз больше места относительно размера БД при активной записи.

## Мониторинг размера binlog

```sql
-- Показать все binlog файлы и их размеры
SHOW BINARY LOGS;

-- Проверить текущий размер используемого binlog
SHOW MASTER STATUS;
```

## Очистка binlog

```sql
-- Удалить все binlog до указанного файла
PURGE BINARY LOGS TO 'mysql-bin.000010';

-- Удалить binlog старше указанного времени
PURGE BINARY LOGS BEFORE DATE_SUB(NOW(), INTERVAL 7 DAY);
```

> **Важно:** Перед очисткой убедитесь, что все slave-серверы уже применили эти binlog. В противном случае репликация будет нарушена.

## Рекомендации

- Устанавливайте `expire_logs_days` или `binlog_expire_logs_seconds` для автоматической ротации.
- Мониторьте свободное место на диске — при заполнении диска master перестанет принимать запись.
- Для экономии места можно использовать сжатие binlog (`binlog_checksum` и внешние утилиты).
