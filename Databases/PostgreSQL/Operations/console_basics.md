# Работа с PostgreSQL через консоль (psql)

## Определения

**psql** — интерактивный терминальный клиент для PostgreSQL, основной инструмент администратора и разработчика для выполнения SQL-запросов и управления сервером из командной строки.

## Основные концепции

### Режимы работы

- **Интерактивный режим:** работа в консоли с получением немедленного ответа. Основной режим для отладки и администрирования.
- **Пакетный режим:** выполнение заранее подготовленных скриптов.
  ```bash
  psql -f script.sql -d mydb
  # Или через конвейер (stdin)
  cat script.sql | psql -d mydb
  ```
- **Синтаксис:**
  - **SQL-команды:** заканчиваются точкой с запятой `;`. Отправляются на сервер для выполнения.
  - **Мета-команды (Backslash commands):** начинаются с `\`. Выполняются самим клиентом `psql` немедленно, не требуют `;` в конце.

### Подключение к серверу

Существует два основных способа указания параметров подключения:

1. **Классические ключи CLI:**
   ```bash
   psql -h <хост> -p <порт> -U <пользователь> -d <база_данных>
   ```
2. **Строка подключения (Connection URI):** (Рекомендуется для 2026 года, так как поддерживает параметры в одном месте)
   ```bash
   psql "postgresql://user:password@host:port/dbname?sslmode=require"
   ```

### Аутентификация

Способы входа без ручного ввода пароля (в порядке убывания безопасности):

1. **Peer-аутентификация:** (Для локальных подключений в Linux) `psql` использует имя текущего системного пользователя. 
   ```bash
   # Вход под системным суперпользователем
   sudo -u postgres psql
   ```
2. **Файл `.pgpass`:** (Рекомендуется для удаленных подключений) файл в домашней директории (`~/.pgpass`) с правами `0600`.
   - Формат: `hostname:port:database:username:password`
3. **Переменная окружения `PGPASSWORD`:** (Менее безопасно) пароль передается в открытом виде, может быть виден в списке процессов (`ps aux`).

## Практические сценарии

### Полезные мета-команды psql

#### Инспекция и навигация
- `\l` — список всех баз данных.
- `\c <db_name>` — переключение на другую базу данных.
- `\dt+` — список таблиц с описанием и размером на диске.
- `\d <object>` — подробное описание таблицы, индекса или представления.
- `\du` — список ролей (пользователей).
- `\conninfo` — параметры текущего соединения.
- `\dn+` — список схем с указанием владельцев.

#### Работа с кодом (Functions & Views)
- `\df+ <pattern>` — список функций с исходным кодом.
- `\sf <function_name>` — вывести только исходный код функции (Show Function).
- `\sv <view_name>` — вывести исходный код представления (Show View).
- `\ef <function_name>` — открыть код функции во внешнем редакторе для изменения.
- `\ev <view_name>` — открыть код представления во внешнем редакторе.

#### Управление выводом и форматом
- `\x` — переключение в вертикальный режим (удобно для широких строк).
- `\timing` — включение замера времени выполнения каждого запроса.
- `\pset pager off` — отключить постраничный вывод (весь результат в консоль сразу).
- `\o <file_path>` — перенаправить результат следующего запроса в файл (Output).
- `\pset format csv` — переключить формат вывода на CSV (удобно для отчетов).
- `\watch <seconds>` — циклическое выполнение запроса (мини-мониторинг).

#### Взаимодействие с системой
- `\i <file>` — выполнить SQL-команды из внешнего файла (Input).
- `\copy ...` — импорт/экспорт CSV **со стороны клиента** (не требует прав суперпользователя).
- `\! <command>` — выполнить команду оболочки (shell) без выхода из `psql`.
- `\e` — открыть текущий буфер запроса в редакторе (Vim/Nano).
- `\gexec` — выполнить результат предыдущего запроса как набор SQL-команд.
- `\errverbose` — вывести детализированное сообщение о последней ошибке.


### Управление доступом и ролями

Создание и настройка прав подробно описаны в разделе **[Управление ролями и правами доступа](./role_management.md)**. 

Основные команды инспекции в `psql`:
- `\du` — список всех ролей.
- `\drds` — список настроек, специфичных для конкретных ролей и баз данных.

### Диагностические запросы

Использование системных представлений для быстрого анализа состояния БД.

**Размер объектов:**
```sql
-- Топ-10 таблиц по размеру (включая индексы)
SELECT relname AS "Table", 
       pg_size_pretty(pg_total_relation_size(relid)) AS "Size"
FROM pg_catalog.pg_statio_user_tables 
ORDER BY pg_total_relation_size(relid) DESC 
LIMIT 10;
-- → результат: orders | 15 GB
```

**Активность и блокировки:**
```sql
-- Активные запросы (не в простое)
SELECT pid, usename, state, query, wait_event_type, wait_event 
FROM pg_stat_activity 
WHERE state != 'idle';

-- Принудительное завершение "зависшего" процесса
-- SELECT pg_terminate_backend(<pid>);
```
Больше запросов для анализа производительности — в разделе **[Наблюдаемость PostgreSQL](./observability.md)**.

### Типовые ошибки и Troubleshooting

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `psql: error: connection... failed: Connection refused` | База не запущена или порт 5432 закрыт. | Проверить статус через `systemctl status postgresql` и `netstat -ntlp`. |
| `FATAL: password authentication failed` | Неверный пароль или пользователь. | Проверить `.pgpass` или `PGPASSWORD`. |
| `FATAL: no pg_hba.conf entry` | Доступ с этого IP или для этого пользователя запрещен. | Настроить **[pg_hba.conf](../../installation_security.md#postgresql-безопасность-на-уровне-хоста-и-ролей)**. |
| `psql: error: FATAL: remaining connection slots are reserved` | Исчерпан лимит `max_connections`. | Завершить лишние сессии (`pg_terminate_backend`) или использовать **PGBouncer**. |

## Дополнительная информация

### Продвинутая настройка .psqlrc

Файл `~/.psqlrc` позволяет автоматизировать рутинные действия и улучшить визуализацию.

```sql
-- 1. Визуальное оформление
\set PROMPT1 '%n@%m:%>%p/%/ %R%# '  -- Подробное приглашение (user@host:port/db)
\pset null '[NULL]'                -- Четкое отображение пустых значений
\pset linestyle unicode            -- Использовать красивые рамки для таблиц
\pset border 2                     -- Двойные рамки
\timing on                         -- Включить замер времени по умолчанию

-- 2. Полезные сокращения (Variables)
-- Быстрый поиск блокировок через :locks
\set locks 'SELECT pid, mode, granted FROM pg_locks WHERE NOT granted;'

-- 3. Цветовое выделение (через внешние переменные)
-- PostgreSQL 2026 поддерживает кастомизацию через терминальные escape-последовательности
```

### Переменные окружения

| Переменная | Описание |
| :--- | :--- |
| `PGHOST` | Хост сервера по умолчанию |
| `PGPORT` | Порт сервера (обычно 5432) |
| `PGUSER` | Имя пользователя для подключения |
| `PGDATABASE` | База данных по умолчанию |
| `EDITOR` | Редактор для команды `\e` (например, `vim` или `nano`) |
