# PostgreSQL: Обзор

## Определения

**PostgreSQL** — свободная объектно-реляционная система управления базами данных (СУБД). Является одной из самых продвинутых open-source баз данных, строго следующей стандартам SQL и обеспечивающей надежное хранение данных с поддержкой транзакций [ACID](../Concepts/acid.md).

*   **OLTP (Online Transactional Processing):** Основной профиль использования PostgreSQL — обработка большого количества коротких транзакций в реальном времени.
*   **Расширяемость:** Возможность добавления собственных типов данных, индексов и языков программирования (PL/pgSQL, PL/Python, PL/v8).
*   **Реляционная модель:** Хранение данных в таблицах со строгой схемой и связями, при этом поддерживается работа с неструктурированными данными (JSONB).

## Основные концепции

### Архитектура и надежность
PostgreSQL использует модель «процесс на соединение» (process-per-connection). Основной процесс (postmaster) управляет разделяемой памятью (Shared Buffers) и порождает дочерние процессы для обслуживания клиентских запросов.
*   **Однопоточность выполнения:** Один SQL-запрос выполняется в рамках одного процесса и использует **только одно ядро CPU**. Масштабирование производительности происходит за счет параллельного выполнения множества *разных* запросов, а не ускорения одного.
*   **Выбор оборудования:** Для нагрузок, критичных к задержкам (latency) одиночных запросов, эффективнее использовать процессоры с высокой тактовой частотой (High Frequency), чем большое количество медленных ядер.
*   **WAL (Write-Ahead Logging):** Все изменения сначала записываются в журнал транзакций, а затем в файлы данных. В случае сбоя WAL позволяет восстановить целостность.
*   **Типы потоковой репликации:**
    *   **Асинхронная:** Подтверждение транзакции происходит сразу после записи на мастере, WAL отправляется на реплики позже. Обеспечивает максимальную производительность.
    *   **Синхронная:** Транзакция фиксируется на мастере только после подтверждения записи в WAL хотя бы одной реплики. Обеспечивает высокую надежность.
*   **Логическая репликация:** Работает на уровне отдельных записей и таблиц. Позволяет выборочно подписываться на изменения (например, копировать только часть таблиц на разные реплики).
*   **MVCC (Multi-Version Concurrency Control):** Читающие процессы не блокируют пишущие, предоставляя каждому снимок данных на момент начала транзакции.
*   **Наследование:** Концепция ООП, позволяющая таблицам наследовать данные и структуру других таблиц, что способствует переиспользованию компонентов.
*Подробнее: [Архитектура](./Concepts/architecture.md) и [MVCC](./Concepts/concurrency_and_locking.md)*.

### Универсальность и расширяемость
PostgreSQL адаптируется под разные задачи за счет модулей и плагинов:
*   **Поддерживаемые языки (Процедурные языки):**
    *   Встроенные: `PL/pgSQL` (аналог PL/SQL в Oracle).
    *   Скриптовые: `PL/Python`, `PL/Perl`, `PL/v8` (JS), `PL/Lua`, `PL/Ruby`, `PL/PHP`.
    *   Классические: `C`, `C++`, `Java` (через PL/Java).
    *   Статистические: `R` (через PL/R).
*   **Типы индексов:** B-дерево, хеш, GiST, GIN, BRIN, Bloom.
*   **Расширения:**
    *   `PostGIS`: Работа с геоданными и пространственная индексация.
    *   `pgcrypto`: Криптографические функции.
    *   `hstore`: Хранение пар key-value (квази-NoSQL).
*   **Пользовательские типы данных:** Позволяют создавать типы с жесткими ограничениями (например, диапазон чисел 1-5) для предотвращения записи некорректных данных на уровне схемы.

## Практические сценарии

### PostgreSQL как универсальная платформа
Благодаря расширениям, PostgreSQL может успешно заменять специализированные инструменты:

| Задача | Решение в PostgreSQL | Преимущество |
| :--- | :--- | :--- |
| **Документная БД** | Тип **[JSONB](./Concepts/json_support.md)** | Валидация JSON-схемы и транзакции ACID |
| **Временные ряды** | Расширение **[TimescaleDB](../timescaledb.md)** | Производительность в 10+ раз выше для IoT |
| **Уникальные ID** | Расширение **[uuid-ossp](./Concepts/extensions_utility.md)** | Исключение конфликтов в распределенных БД |
| **Безопасность** | Расширение **[pgcrypto](./Concepts/pgcrypto.md)** | Шифрование полей (AES/PGP) и хеширование паролей |
| **Полнотекстовый поиск** | Встроенный **[FTS](./Concepts/full_text_search.md)** | Поиск с триграммами (**[pg_trgm](./Concepts/full_text_search.md)**) |
| **Векторный поиск (AI)** | Расширение **[pgvector](./pgvector.md)** | Хранение эмбеддингов рядом с метаданными |


### Выбор между PostgreSQL и альтернативами
Используйте PostgreSQL для всех задач по умолчанию, кроме случаев, требующих узкой специализации:
*   **Аналитика больших данных:** При объемах >1 ТБ и сложных агрегациях рассмотрите [ClickHouse](../ClickHouse/clickhouse.md) или [Greenplum](../greenplum.md).
*   **Экстремальное масштабирование записи:** Для распределенной записи используйте [Citus](../citus.md).
*   **Низкая задержка (In-memory):** Для кэширования с микросекундным доступом рассмотрите [Redis](../redis_overview.md).
