# PostgreSQL: Обзор

## Определения

**PostgreSQL** — свободная объектно-реляционная система управления базами данных (СУБД). Является одной из самых продвинутых open-source баз данных, строго следующей стандартам SQL и обеспечивающей надежное хранение данных с поддержкой транзакций [ACID](../Concepts/acid.md).

*   **OLTP (Online Transactional Processing):** Основной профиль использования PostgreSQL — обработка большого количества коротких транзакций в реальном времени.
*   **Расширяемость:** Возможность добавления собственных типов данных, индексов и языков программирования (PL/pgSQL, PL/Python, PL/v8).
*   **Реляционная модель:** Хранение данных в таблицах со строгой схемой и связями, при этом поддерживается работа с неструктурированными данными (JSONB).
*   **Надежность (SRE-контекст):** СУБД ориентирована на достижение минимальных показателей **RPO (Recovery Point Objective)** и **RTO (Recovery Time Objective)** через механизмы WAL, репликации и инкрементальных бэкапов.

## Базовые концепции

### Архитектура и надежность
PostgreSQL использует модель «процесс на соединение» (process-per-connection). Основной процесс (postmaster) управляет разделяемой памятью (Shared Buffers) и порождает дочерние процессы для обслуживания клиентских запросов.

*   **Процессная модель:** Каждый SQL-запрос выполняется в рамках одного процесса и использует **только одно ядро CPU**. Для эффективного управления большим количеством соединений (>500) критически важно использование пулеров соединений, таких как **[PgBouncer](./Operations/pgbouncer_setup.md)**.
*   **Выбор оборудования:** Из-за однопоточности выполнения запроса эффективнее использовать процессоры с высокой тактовой частотой (High Frequency), чем большое количество медленных ядер.
*   **WAL (Write-Ahead Logging):** Все изменения сначала записываются в журнал транзакций, а затем в файлы данных. В **PostgreSQL 17** введена нативная поддержка **инкрементальных бэкапов** на основе WAL-суммирования (`pg_basebackup --incremental`).
*   **MVCC (Multi-Version Concurrency Control):** Читающие процессы не блокируют пишущие. Изменения (`UPDATE`/`DELETE`) создают новые версии строк, что требует регулярной очистки через **VACUUM**.
    - **Оптимизация VACUUM (PG 17):** Новый механизм использует структуру **TidStore**, которая потребляет до 20 раз меньше памяти (RAM), значительно ускоряя очистку на огромных таблицах.
*   **Streaming I/O (PG 17):** Улучшенная производительность последовательного чтения данных и работы `ANALYZE` за счет асинхронного предсказательного ввода-вывода.
*Подробнее: [Архитектура](./Concepts/architecture.md) и [MVCC](./Concepts/concurrency_and_locking.md)*.

### Репликация и доступность
*   **Потоковая репликация (Физическая):** Передача WAL-записей в реальном времени.
    *   **Асинхронная:** Максимальная производительность, риск потери данных при сбое.
    *   **Синхронная:** Гарантия сохранности данных на реплике до подтверждения клиенту.
*   **Логическая репликация:** Работает на уровне отдельных записей. В современных версиях (PG 16+) поддерживается репликация со Standby-серверов.
    - **pg_createsubscriber (PG 17):** Новая утилита для быстрого конвертирования физической реплики в логическую, что упрощает миграции между мажорными версиями без простоя.
*   **High Availability (HA):** Построение кластеров с автоматическим переключением (Failover) с помощью **Patroni** и распределенного хранилища конфигураций (DCS: etcd, Consul).
*Подробнее: [Репликация](./Concepts/replication.md) и [High Availability](./Concepts/high_availability.md)*.

### Безопасность и управление
PostgreSQL предоставляет многоуровневую систему защиты:
*   **RBAC (Role-Based Access Control):** Управление правами через роли и привилегии.
    - **Роль MAINTAIN (PG 17):** Позволяет выполнять задачи по обслуживанию (VACUUM, REINDEX, ANALYZE) без прав суперпользователя, следуя принципу наименьших привилегий.
*   **RLS (Row-Level Security):** Ограничение доступа к конкретным строкам таблицы на основе атрибутов пользователя (например, пользователь видит только свои заказы).
*   **Шифрование:** Поддержка TLS для соединений и расширение `pgcrypto` для шифрования данных внутри БД.
*Подробнее: [Управление ролями](./Operations/role_management.md)*.

### Универсальность и расширяемость
*   **Процедурные языки:** `PL/pgSQL` (встроенный), `PL/Python`, `PL/v8` (JS), `PL/R`.
*   **Типы индексов:** B-дерево, хеш, GiST (геоданные), GIN (полнотекстовый поиск, JSONB), BRIN (огромные таблицы), Bloom.
*   **EXPLAIN (GENERIC_PLAN) (PG 16):** Возможность увидеть план выполнения запроса с параметрами без их фактического подставления, что полезно для отладки производительности Prepared Statements.
*   **Расширения:**
    *   `PostGIS`: Геопространственный анализ.
    *   `pg_stat_statements`: Детальная статистика по запросам (в PG 17 добавлено отслеживание вложенных вызовов).
    *   `pgvector`: Векторный поиск для AI-приложений.

## Практические сценарии

### PostgreSQL как универсальная платформа
Благодаря расширениям, PostgreSQL может успешно заменять специализированные инструменты:

| Задача | Решение в PostgreSQL | Преимущество |
| :--- | :--- | :--- |
| **Документная БД** | Тип **[JSONB](./Concepts/json_support.md)** | Валидация JSON-схемы и транзакции ACID |
| **Временные ряды** | Расширение **[TimescaleDB](../timescaledb.md)** | Автоматическое партиционирование и сжатие |
| **Уникальные ID** | Тип **UUID** / **uuid-ossp** | Исключение конфликтов в распределенных БД |
| **Безопасность** | Расширение **[pgcrypto](./Concepts/pgcrypto.md)** | Шифрование полей (AES/PGP) на уровне БД |
| **Полнотекстовый поиск** | Встроенный **[FTS](./Concepts/full_text_search.md)** | Поиск с триграммами (**[pg_trgm](./Concepts/full_text_search.md)**) |
| **Векторный поиск (AI)** | Расширение **[pgvector](./pgvector.md)** | Хранение эмбеддингов рядом с метаданными |

### Выбор между PostgreSQL и альтернативами
Используйте PostgreSQL для всех задач по умолчанию, кроме случаев, требующих узкой специализации:
*   **Аналитика больших данных (OLAP):** При объемах >1 ТБ и тяжелых агрегациях — [ClickHouse](../ClickHouse/clickhouse.md) или [Greenplum](../greenplum.md).
*   **Горизонтальное масштабирование записи:** Для распределенной записи на множество узлов — [Citus](../citus.md).
*   **In-memory кэширование:** Для микросекундного доступа к простым ключам — [Redis](../redis_overview.md).
