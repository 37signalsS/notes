# PostgreSQL: Обзор

## Определения

**PostgreSQL** — свободная объектно-реляционная система управления базами данных (СУБД). Является одной из самых продвинутых open-source баз данных, строго следующей стандартам SQL и обеспечивающей надежное хранение данных с поддержкой транзакций [ACID](../Concepts/acid.md).

*   **OLTP (Online Transactional Processing):** Основной профиль использования PostgreSQL — обработка большого количества коротких транзакций в реальном времени.
*   **Расширяемость:** Возможность добавления собственных типов данных, индексов и языков программирования (PL/pgSQL, PL/Python, PL/v8).
*   **Реляционная модель:** Хранение данных в таблицах со строгой схемой и связями, при этом поддерживается работа с неструктурированными данными (JSONB).

## Основные концепции

### Архитектура и надежность
PostgreSQL использует модель «процесс на соединение» (process-per-connection). Основной процесс (postmaster) управляет разделяемой памятью (Shared Buffers) и порождает дочерние процессы для обслуживания клиентских запросов.
*   **WAL (Write-Ahead Logging):** Механизм, при котором все изменения сначала записываются в журнал, а затем в файлы данных. Это основа для транзакций ACID и [репликации](./Concepts/replication.md).
*   **MVCC (Multi-Version Concurrency Control):** Позволяет читающим процессам не блокировать пишущие, предоставляя каждому снимок данных на момент начала транзакции.
*Подробнее: [Архитектура](./Concepts/architecture.md) и [MVCC](./Concepts/concurrency_and_locking.md)*.

### Управление доступом и конфигурация
*   **Роли:** Универсальная сущность для управления доступом. В PostgreSQL нет разделения на пользователей и группы — все является ролями.
*   **Конфигурация:** Основные файлы — `postgresql.conf` (настройки сервера) и `pg_hba.conf` (управление клиентским доступом).

### Новые возможности (версии 15-17)
Современные версии PostgreSQL принесли значительные улучшения:
*   **PG 15:** Добавлена команда `MERGE`, расширена поддержка JSON функций стандарта SQL.
*   **PG 16:** Улучшена логическая репликация со standby-серверов, добавлена статистика `pg_stat_io`.
*   **PG 17:** Поддержка `JSON_TABLE`, ускорение параллельного `VACUUM`.

## Практические сценарии

### PostgreSQL как универсальная платформа
Благодаря расширениям, PostgreSQL может успешно заменять специализированные инструменты, упрощая инфраструктуру:

| Задача | Решение в PostgreSQL | Преимущество |
| :--- | :--- | :--- |
| **Документная БД** | Тип **[JSONB](./Concepts/json_support.md)** + GIN-индексы | Транзакции ACID для документов |
| **Полнотекстовый поиск** | Встроенный **[FTS](./Concepts/full_text_search.md)** | Не нужна синхронизация с Elastic |
| **Векторный поиск (AI)** | Расширение **[pgvector](./pgvector.md)** | Хранение эмбеддингов рядом с данными |
| **Очереди задач** | `SELECT FOR UPDATE SKIP LOCKED` | Гарантия транзакционности очереди |
| **Геоданные** | Расширение **PostGIS** | Стандарт индустрии для ГИС-данных |

### Выбор между PostgreSQL и альтернативами
Используйте PostgreSQL для всех задач по умолчанию, кроме случаев, требующих узкой специализации:
*   **Аналитика больших данных:** При объемах >1 ТБ и сложных агрегациях рассмотрите [ClickHouse](../ClickHouse/clickhouse.md) или [Greenplum](../greenplum.md).
*   **Экстремальное масштабирование записи:** Для распределенной записи используйте [Citus](../citus.md).
*   **Низкая задержка (In-memory):** Для кэширования с микросекундным доступом рассмотрите [Redis](../redis_overview.md).
