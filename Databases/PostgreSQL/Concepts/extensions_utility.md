# Вспомогательные расширения PostgreSQL

## Определения

- **Расширение (Extension)** — программный модуль, который добавляет в PostgreSQL новые типы данных, функции, операторы, индексы или системные представления.
- **Trusted Extension** — расширение, которое обычный пользователь (не суперпользователь) может устанавливать самостоятельно (при наличии прав `CREATE` в базе).
- **Shared Preload Libraries** — библиотеки, которые должны быть загружены при старте сервера (`shared_preload_libraries` в `postgresql.conf`).

## Основные расширения

### Мониторинг и диагностика

#### pg_stat_statements (Золотой стандарт)
Собирает статистику выполнения всех SQL-запросов (время, кол-во строк, I/O).
- **Зачем:** Поиск медленных запросов и анализ нагрузки на систему.
- **Особенности:** Требует перезагрузки сервера (`shared_preload_libraries = 'pg_stat_statements'`).
Подробнее: **[Оптимизация производительности](../Operations/performance_tuning.md)**.

#### amcheck
Проверка целостности индексов (прежде всего B-Tree).
- **Зачем:** Выявление повреждений данных (corruption) на уровне индексов после сбоев оборудования или багов.
- **Применение:** `SELECT bt_index_check('my_index');`.

#### pageinspect
Низкоуровневый анализ содержимого страниц данных.
- **Зачем:** Позволяет увидеть внутреннюю структуру таблиц и индексов на диске (RAW-данные). Полезно для DBA при отладке Bloat и изучении MVCC.

### Типы данных и идентификаторы

#### uuid-ossp и gen_random_uuid
Генерация UUID (Universally Unique Identifiers).
- **uuid-ossp**: Требуется для генерации UUID версий 1, 3, 5.
- **PostgreSQL 13+**: Функция `gen_random_uuid()` (v4) встроена в ядро и **не требует расширений**. Используйте её по умолчанию для идентификаторов.

#### citext
Регистронезависимый текстовый тип данных.
- **Зачем:** Упрощает работу с email, логинами и другими полями, где `A == a`. Избавляет от необходимости писать `LOWER(column)`.

#### hstore
Хранение данных в формате «ключ-значение».
- **Зачем:** Простая реализация NoSQL внутри реляционной базы. 
- **Примечание:** В современных проектах чаще заменяется типом **JSONB**, который поддерживает вложенность и более сложные типы данных.

### Индексация и поиск

#### btree_gist и btree_gin
Позволяет использовать стандартные B-Tree операторы (`=`, `<`, `>`) в GiST и GIN индексах.
- **Зачем:** Создание составных индексов, объединяющих сложные типы (геоданные, полнотекст) и обычные (ID, даты). Критично для использования **Exclusion Constraints** (исключающих ограничений).

#### pg_trgm (Триграммы)
Разбиение текста на последовательности из трех символов.
- **Зачем:** Поиск с опечатками, нечеткое сравнение строк и ускорение `LIKE`.
Подробнее: **[Полнотекстовый поиск](./full_text_search.md)**.

#### unaccent
Удаление диакритических знаков (ударения, ё -> е). Полезно для нормализации поиска в европейских и славянских языках.

### Безопасность

#### pgcrypto
Криптографические функции (AES, PGP, BCrypt).
Подробнее: **[Руководство по pgcrypto](./pgcrypto.md)**.

## Практические сценарии

### Настройка Exclusion Constraints (btree_gist)
Предотвращение пересечения интервалов времени (например, бронирование переговорной).

```sql
CREATE EXTENSION btree_gist;

CREATE TABLE bookings (
    room_id INT,
    reservation_period TSRANGE,
    EXCLUDE USING gist (room_id WITH =, reservation_period WITH &&)
);
```

### Диагностика медленных запросов
После включения `pg_stat_statements` можно найти топ-5 самых «тяжелых» запросов:

```sql
SELECT query, calls, total_exec_time, mean_exec_time
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 5;
```

## Дополнительная информация

### Рекомендации
- **Меньше — лучше:** Не устанавливайте расширения «на всякий случай». Каждое расширение — это дополнительный код, который может влиять на стабильность и безопасность.
- **Обновление:** При обновлении версии PostgreSQL не забывайте выполнять `ALTER EXTENSION ... UPDATE;`.
- **Схема:** Устанавливайте расширения в системную схему (например, `extensions`) или `public`, чтобы избежать конфликтов имен.
