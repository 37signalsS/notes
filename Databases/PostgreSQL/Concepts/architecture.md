# Архитектура PostgreSQL

### Определения

* **Экземпляр (Instance):** Совокупность процессов PostgreSQL (`postmaster` и дочерние), управляющих кластером баз данных. Принимает клиентские подключения (по умолчанию порт `5432/TCP`).
* **Кластер баз данных (Database Cluster):** Набор баз данных, управляемый одним экземпляром PostgreSQL. Физически представляет собой каталог с данными (`PGDATA`).
* **База данных (Database):** Изолированный набор объектов SQL (таблиц, индексов) внутри кластера.
* **Журнал предзаписи (WAL):** Фундаментальный механизм обеспечения долговечности (Durability) и целостности. Все изменения сначала последовательно записываются в WAL и только затем применяются к файлам данных. Является основой для транзакционности, репликации и восстановления. Подробно концепция описана в документе **[Журнал предзаписи (WAL)](../../Concepts/write_ahead_log.md)**.
* **Индекс (Index):** Вспомогательная структура данных для ускорения поиска и сортировки строк таблицы.

### Основные концепции

#### Процессная модель

PostgreSQL использует многопроцессную архитектуру:

* **Postmaster:** Главный управляющий процесс. Отвечает за запуск и остановку экземпляра, восстановление после сбоев, прослушивание соединений и создание дочерних процессов.
* **Backend Process (`postgres`):** Дочерний процесс, создаваемый `postmaster` для каждого клиентского подключения. Обслуживает все запросы одного клиента, обеспечивая изоляцию сессий.
* **Фоновые процессы (Background Workers):** Специализированные процессы для служебных задач:
  * **`Checkpointer`:** Периодически записывает измененные ("грязные") данные из общей памяти на диск (создает "чекпоинт").
  * **`Background Writer (bgwriter)`:** Помогает `Checkpointer`, асинхронно сбрасывая часть "грязных" страниц на диск для сглаживания пиковой нагрузки на I/O.
  * **`Autovacuum Launcher`:** Запускает рабочие процессы для очистки таблиц от "мертвых" строк (MVCC).
  * **`WAL Writer`:** Сбрасывает записи WAL из буферов в памяти на диск.

#### Хранение данных и кэширование

* **Страница (Page):** Минимальная единица дискового ввода-вывода, блок фиксированного размера (обычно 8 КБ), на которые разделены файлы данных.
* **Общая память (Shared Memory):** Область RAM, используемая всеми процессами PostgreSQL. Ключевой компонент — **буферный кэш (Shared Buffers)** для кэширования страниц данных и индексов.
* **Кэш ОС:** Операционная система также кэширует дисковые операции, создавая второй уровень кэширования.

#### Пул соединений (Connection Pool)

Поскольку создание `backend` процесса для каждого подключения ресурсоемко, в производственных средах используется внешний **пул соединений** (например, `PgBouncer`). Он управляет очередью клиентов и переиспользует уже установленные соединения с базой данных, снижая накладные расходы.

### Практические сценарии

#### Жизненный цикл запроса

1. **Парсинг (Parsing):** Проверка синтаксиса и преобразование текстового SQL-запроса в дерево разбора.
2. **Анализ и переписывание (Analysis & Rewriting):** Проверка семантики (существование объектов, права доступа) и раскрытие представлений (`VIEW`).
3. **Планирование (Planning):** Оптимизатор (Query Planner) на основе статистики данных генерирует и выбирает наиболее эффективный план выполнения запроса (порядок соединения таблиц, использование индексов).
4. **Выполнение (Execution):** Исполнитель (Executor) выполняет план и возвращает результат.

### Дополнительная информация

* **Репликация:** Механизмы тиражирования данных основаны на передаче WAL. См. **[Репликация в PostgreSQL](./replication.md)**.
* **Резервное копирование и восстановление:** Процессы создания бэкапов и восстановления на точку времени (PITR) тесно связаны с WAL. См. **[Резервное копирование и восстановление](./backup_and_recovery.md)**.
* **Производительность:** Настройка компонентов архитектуры (память, фоновые процессы) — основа для оптимизации производительности PostgreSQL.
