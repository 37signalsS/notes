# Полнотекстовый поиск (FTS) в PostgreSQL

## Определения

- **FTS (Full Text Search)** — встроенный механизм PostgreSQL для поиска документов на естественном языке. Позволяет находить слова с учетом морфологии (склонения, спряжения).
- **tsvector** — специальный тип данных, представляющий документ в виде оптимизированного списка лексем (нормализованных слов).
- **tsquery** — тип данных для поискового запроса, поддерживающий логические операторы (`&` — И, `|` — ИЛИ, `!` — НЕ, `<->` — фразовый поиск).
- **Лексема (Lexeme)** — нормализованная форма слова (например, «бежать», «бежит», «бежал» → «беж»).
- **Стемминг (Stemming)** — процесс приведения слова к его корню/основе.

## Базовые концепции

### Как работает FTS

1.  **Токенизация**: Разбиение текста на отдельные слова (токены).
2.  **Лингвистическая обработка**: Удаление стоп-слов (предлоги, союзы) и приведение слов к лексемам через словари (например, `russian`, `english`).
3.  **Создание вектора**: Преобразование текста в `tsvector`.
4.  **Сопоставление**: Проверка вхождения `tsquery` в `tsvector` с помощью оператора `@@`.

### Индексация

Для быстрого поиска по большим объемам текста необходимо использовать **GIN (Generalized Inverted Index)**. Без индекса поиск будет выполнять полный скан таблицы (`Seq Scan`).

```sql
-- Создание индекса на колонку 'body' с использованием русского словаря
CREATE INDEX idx_articles_fts ON articles 
USING gin (to_tsvector('russian', body));
```

### Сравнение с Elasticsearch

PostgreSQL может успешно заменять Elasticsearch для многих задач, пока объем данных не требует сложного распределенного поиска.

| Характеристика | PostgreSQL (FTS) | Elasticsearch |
| :--- | :--- | :--- |
| **Сложность** | Низкая (часть БД) | Высокая (отдельный кластер) |
| **Согласованность** | Мгновенная (ACID) | Near real-time (задержка индексации) |
| **Морфология** | Встроенные словари | Продвинутые плагины и анализаторы |
| **Масштабирование** | До ~10 млн документов на ноду | Миллиарды документов (горизонтально) |
| **Функции** | Ранжирование, подсветка | Продвинутый релеванс, синонимы, нечеткий поиск |

## Практические сценарии

### Простой поиск

```sql
-- Поиск статей, содержащих слова "поиск" и "индекс"
SELECT title 
FROM articles 
WHERE to_tsvector('russian', body) @@ to_tsquery('russian', 'поиск & индекс');
```

### Ранжирование результатов

Используется функция `ts_rank` для сортировки по релевантности:

```sql
SELECT title, ts_rank(to_tsvector('russian', body), query) AS rank
FROM articles, to_tsquery('russian', 'база & данных') query
WHERE to_tsvector('russian', body) @@ query
ORDER BY rank DESC;
```

## Когда использовать FTS в PostgreSQL

- **MVP и небольшие проекты**: Когда не хочется усложнять стек внедрением Elasticsearch.
- **Требование ACID**: Если результаты поиска должны быть доступны мгновенно после вставки.
- **Гибридные запросы**: Когда нужно одновременно фильтровать по обычным колонкам и искать по тексту.
- **Объем данных**: До 10 миллионов документов на один сервер.

## Когда переходить на специализированные решения (Elasticsearch)

- **Миллиарды документов**: Когда требуется горизонтальное масштабирование поиска.
- **Сложная аналитика поиска**: Синонимы, обработка опечаток (fuzzy search), сложные кастомные анализаторы.
- **Высокая нагрузка**: Если поиск создает слишком большую нагрузку на основную транзакционную БД.
