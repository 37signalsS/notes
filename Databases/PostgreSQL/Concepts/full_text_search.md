# Полнотекстовый поиск (FTS) в PostgreSQL

## Определения

- **FTS (Full Text Search)** — встроенный механизм PostgreSQL для поиска документов на естественном языке. Позволяет находить слова с учетом морфологии (склонения, спряжения).
- **tsvector** — специальный тип данных, представляющий документ в виде оптимизированного списка лексем (нормализованных слов) с позиционной информацией.
- **tsquery** — тип данных для поискового запроса, поддерживающий логические операторы, фразовый поиск и веса.
- **Лексема (Lexeme)** — нормализованная форма слова (например, «бежать», «бежит» → «беж»).
- **Стемминг (Stemming)** — процесс приведения слова к его основе путем отсечения окончаний и суффиксов.
- **Словарь (Dictionary)** — компонент, отвечающий за нормализацию токенов в лексемы и удаление стоп-слов.
- **Парсер (Parser)** — компонент, разбивающий сырой текст на токены различных типов (слова, цифры, email и т.д.).
- **GIN (Generalized Inverted Index)** — основной тип индекса для FTS, хранящий список документов для каждой лексемы.

## Базовые концепции

### Архитектура поиска
Процесс преобразования текста в поисковый вектор включает три этапа:
1.  **Токенизация**: Разбиение строки на составляющие с помощью парсера.
2.  **Обработка словарями**: Удаление стоп-слов и нормализация оставшихся токенов.
3.  **Формирование вектора**: Сборка лексем в объект `tsvector`.

### Типы индексов для FTS

| Тип индекса | Особенности | Когда использовать |
| :--- | :--- | :--- |
| **GIN** | Высокая скорость поиска, но медленное обновление. Поддерживает `fastupdate` для ускорения вставок. | Стандарт для большинства задач FTS. |
| **GiST** | Компактный, быстрее обновляется, но поиск медленнее и может быть «нечетким» (lossy). Поддерживает KNN-поиск. | Когда важна скорость вставки и экономия места. |
| **RUM** | Стороннее расширение (contrib). Хранит позиции лексем и дополнительные метаданные (например, метки времени). | Когда нужно быстрое ранжирование по релевантности и фразовый поиск на огромных данных. |

### Конфигурации поиска
PostgreSQL использует конфигурации (например, `russian`, `english`) для связи парсеров и словарей.
- Просмотр доступных: `\dF` в psql.
- Конфигурация по умолчанию: параметр `default_text_search_config`.

## Практические сценарии

### Отладка и анализ (ts_debug)
Функция `ts_debug` позволяет увидеть, как именно текст разбивается на токены и какие словари их обрабатывают.

```sql
SELECT * FROM ts_debug('russian', 'Базы данных — это круто!');
-- Выведет: тип токена, описание, слово, словари, лексему.
```

### Создание векторов с весами (Weights)
Для повышения релевантности можно назначать веса разным частям документа: `A` (самый высокий), `B`, `C`, `D` (по умолчанию).

```sql
SELECT setweight(to_tsvector('russian', title), 'A') || 
       setweight(to_tsvector('russian', body), 'B') 
AS doc_vector
FROM articles;
```

### Хранимые колонки и триггеры
Для производительности вектор должен быть индексирован.

**Вариант 1: GENERATED колонки (PostgreSQL 12+)**
```sql
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    title TEXT,
    body TEXT,
    fts_vector tsvector GENERATED ALWAYS AS (
        setweight(to_tsvector('russian', coalesce(title, '')), 'A') || 
        setweight(to_tsvector('russian', coalesce(body, '')), 'B')
    ) STORED
);
CREATE INDEX idx_articles_fts ON articles USING gin(fts_vector);
```

**Вариант 2: Триггеры (для сложных правил или старых версий)**
```sql
CREATE FUNCTION articles_fts_trigger() RETURNS trigger AS $$
begin
  new.fts_vector := 
     setweight(to_tsvector('russian', coalesce(new.title,'')), 'A') ||
     setweight(to_tsvector('russian', coalesce(new.body,'')), 'B');
  return new;
end
$$ LANGUAGE plpgsql;

CREATE TRIGGER tsvectorupdate BEFORE INSERT OR UPDATE
ON articles FOR EACH ROW EXECUTE FUNCTION articles_fts_trigger();
```

### Расширенный поиск (websearch_to_tsquery)
Функция `websearch_to_tsquery` (PG 11+) поддерживает синтаксис Google-поиска.

```sql
-- "фраза" (в кавычках), -исключение (минус)
SELECT title 
FROM articles 
WHERE fts_vector @@ websearch_to_tsquery('russian', '"база данных" -oracle');
```

### Фразовый поиск и расстояние
Оператор `<->` означает, что слова должны идти друг за другом. `<N>` задает расстояние.

```sql
-- "база" сразу перед "данных"
SELECT to_tsquery('russian', 'база <-> данных');

-- "база" в пределах 2 слов от "данных"
SELECT to_tsquery('russian', 'база <2> данных');
```

### Поиск без акцентов и ё/е (unaccent)
Расширение `unaccent` позволяет игнорировать диакритические знаки и специфичные буквы.

```sql
CREATE EXTENSION unaccent;
-- Создание кастомной конфигурации на базе russian
CREATE TEXT SEARCH CONFIGURATION russian_unaccent (COPY = russian);
ALTER TEXT SEARCH CONFIGURATION russian_unaccent 
    ALTER MAPPING FOR hword, hword_asciipart, hword_part, word 
    WITH unaccent, russian_stem;
```

### Работа со словарями
1.  **Simple**: Удаляет стоп-слова, не нормализует (полезно для ID, кодов).
2.  **Ispell/Hunspell**: Качественная морфология на основе словарей (требует файлы `.aff` и `.dict`).
3.  **Synonym**: Заменяет слова синонимами (например, "postgres" -> "postgresql").
4.  **Thesaurus**: Заменяет фразы на одну лексему (например, "база данных" -> "бд").

### Поиск по триграммам (pg_trgm)
Эффективен для поиска с опечатками или нечеткого совпадения строк.
- **GIN/GiST индекс**: Ускоряет `LIKE`, `ILIKE` и `~`.
- **Пример**: `WHERE name % 'опечатка'` (оператор сходства).

### Ранжирование и подсветка
- **ts_rank**: Частота лексем (плотность).
- **ts_rank_cd**: Ранжирование с учетом близости слов (Cover Density).
- **ts_headline**: Генерация сниппета.

```sql
SELECT 
    title, 
    ts_headline('russian', body, query, 'StartSel=<b>, StopSel=</b>') as snippet
FROM articles, websearch_to_tsquery('russian', 'индексы') query
WHERE fts_vector @@ query
ORDER BY ts_rank_cd(fts_vector, query) DESC;
```

### Поиск внутри JSONB
PostgreSQL позволяет индексировать значения JSONB.
```sql
-- Индексация всех текстовых значений в JSON
CREATE INDEX idx_json_fts ON articles USING gin(to_tsvector('russian', data));
```
Расширение **`jsquery`** предоставляет более гибкий DSL для поиска во вложенных структурам.

## Дополнительная информация

### PostgreSQL FTS vs Elasticsearch
| Характеристика | PostgreSQL (FTS) | Elasticsearch |
| :--- | :--- | :--- |
| **Сложность** | Низкая (часть БД) | Высокая (отдельный кластер) |
| **Согласованность** | ACID (мгновенно) | Eventual Consistency (задержка) |
| **Масштабирование** | Вертикальное (до ~20 млн док) | Горизонтальное (миллиарды док) |
| **Функционал** | Базовый поиск | Fuzzy, аналитика, автодополнение |

### Оптимизация производительности
- **GIN fastupdate**: Включено по умолчанию. Ускоряет вставку, группируя изменения в памяти, но требует периодической очистки.
- **work_mem**: Влияет на скорость построения индексов и сортировки лексем.
- **Подгрузка словарей**: На больших нагрузках словари кэшируются в памяти процесса.

### Рекомендации
- Используйте **Stored-колонки** для стабильной производительности.
- Для мультиязычного поиска создайте несколько колонок `tsvector` или объединяйте их через `coalesce`.
- Для семантического поиска (по смыслу) используйте **[pgvector](../pgvector.md)**.
