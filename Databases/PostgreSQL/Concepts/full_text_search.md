# Полнотекстовый поиск (FTS) в PostgreSQL

## Определения

- **FTS (Full Text Search)** — встроенный механизм PostgreSQL для поиска документов на естественном языке. Позволяет находить слова с учетом морфологии (склонения, спряжения).
- **tsvector** — специальный тип данных, представляющий документ в виде оптимизированного списка лексем (нормализованных слов) с позиционной информацией.
- **tsquery** — тип данных для поискового запроса, поддерживающий логические операторы и фразовый поиск.
- **Лексема (Lexeme)** — нормализованная форма слова (например, «бежать», «бежит» → «беж»).
- **Стемминг (Stemming)** — процесс приведения слова к его основе путем отсечения окончаний и суффиксов.
- **GIN (Generalized Inverted Index)** — основной тип индекса для FTS, хранящий список документов для каждой лексемы.

## Базовые концепции

### Архитектура поиска
Процесс преобразования текста в поисковый вектор включает три этапа:
1.  **Токенизация**: Разбиение строки на составляющие (слова, числа, email и т.д.) с помощью парсера.
2.  **Обработка словарями**: Удаление стоп-слов и нормализация оставшихся токенов в лексемы.
3.  **Формирование вектора**: Сборка лексем в объект `tsvector`.

### Типы индексов для FTS

| Тип индекса | Особенности | Когда использовать |
| :--- | :--- | :--- |
| **GIN** | Высокая скорость поиска, но медленное обновление и большой размер. | Стандарт для большинства задач FTS. |
| **GiST** | Компактный, быстрее обновляется, но поиск медленнее и может быть «нечетким» (lossy). | Когда важна скорость вставки и экономия места. |
| **RUM** | Расширение (contrib), хранит позиции и веса. Очень быстрое ранжирование. | Профессиональный поиск с сортировкой по релевантности. |

### Конфигурации поиска
PostgreSQL использует конфигурации (например, `russian`, `english`) для определения правил токенизации и набора словарей. Текущая конфигурация по умолчанию задается параметром `default_text_search_config`.

## Практические сценарии

### Создание векторов с весами (Weights)
Для повышения релевантности можно назначать разные веса разным частям документа (A, B, C, D).

```sql
SELECT setweight(to_tsvector('russian', title), 'A') || 
       setweight(to_tsvector('russian', body), 'B') 
AS doc_vector
FROM articles;
```

### Оптимизация: Хранимые (Stored) колонки
Для исключения вычислений `to_tsvector` при каждом запросе рекомендуется использовать генерируемые колонки (доступно с PostgreSQL 12+).

```sql
-- Создание таблицы с предвычисленным вектором
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    title TEXT,
    body TEXT,
    fts_vector tsvector GENERATED ALWAYS AS (
        setweight(to_tsvector('russian', coalesce(title, '')), 'A') || 
        setweight(to_tsvector('russian', coalesce(body, '')), 'B')
    ) STORED
);

-- Индексация предвычисленной колонки
CREATE INDEX idx_articles_fts ON articles USING gin(fts_vector);
```

### Удобный поиск (websearch_to_tsquery)
Функция `websearch_to_tsquery` (PostgreSQL 11+) позволяет использовать синтаксис поисковых систем (кавычки для фраз, минус для исключения).

```sql
-- Поиск фразы "база данных" без слова "oracle"
SELECT title 
FROM articles 
WHERE fts_vector @@ websearch_to_tsquery('russian', '"база данных" -oracle');
```

### Поиск по триграммам (pg_trgm)
Расширение `pg_trgm` позволяет искать текст на основе триграмм (последовательностей из трех символов).
- **Преимущества:** Поиск нечувствителен к опечаткам и ошибкам в написании. Позволяет эффективно искать похожие строки.
- **Оптимизация:** Ускоряет выполнение запросов `LIKE`, `ILIKE` и регулярных выражений при использовании GIN или GiST индексов.
- **Применение:** Поиск по именам, фамилиям или названиям товаров, где пользователь может допустить ошибку.

### Ранжирование и подсветка
- **ts_rank**: Базовое ранжирование на основе частоты лексем.
- **ts_headline**: Генерация сниппета с подсветкой найденных слов.

```sql
SELECT 
    title, 
    ts_headline('russian', body, query) as snippet
FROM articles, websearch_to_tsquery('russian', 'индексы') query
WHERE fts_vector @@ query
ORDER BY ts_rank(fts_vector, query) DESC;
```

### Поиск по JSONB
PostgreSQL поддерживает полнотекстовый поиск внутри JSON-документов. Расширение **`jsquery`** значительно расширяет эти возможности, предоставляя эффективную индексацию и гибкий поиск по вложенным структурам и массивам.

## Дополнительная информация

### PostgreSQL FTS vs Elasticsearch
| Характеристика | PostgreSQL (FTS) | Elasticsearch |
| :--- | :--- | :--- |
| **Сложность** | Низкая (часть БД) | Высокая (отдельный кластер) |
| **Согласованность** | ACID (мгновенно) | Eventual Consistency (задержка ~1с) |
| **Масштабирование** | Вертикальное (до ~10-20 млн док) | Горизонтальное (миллиарды док) |
| **Функционал** | Базовый поиск | Нечеткий поиск (fuzzy), синонимы, аналитика |

### Рекомендации
- Используйте **GIN-индексы** для большинства задач.
- Всегда выносите `tsvector` в **Stored-колонку** для производительности на больших данных.
- Для семантического поиска (по смыслу, а не по словам) и реализации AI-функционала (RAG) используйте расширение **[pgvector](../pgvector.md)**.
