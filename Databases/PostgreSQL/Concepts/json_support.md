# JSON в PostgreSQL

## Определения

**JSON (JavaScript Object Notation)** — текстовый формат обмена данными, основанный на JavaScript. В PostgreSQL представлен двумя типами данных: `json` и `jsonb`.

**json (Plain JSON)** — хранит точную копию входного текста. При каждом обращении требуется повторный парсинг. Сохраняет форматирование, пробелы и порядок ключей.

**jsonb (Binary JSON)** — хранит данные в декомпозированном бинарном формате. Парсинг происходит один раз при вставке. Не сохраняет пробелы, порядок ключей и дубликаты (остается последнее значение). Поддерживает эффективную индексацию.

**TOAST (The Oversized Attribute Storage Technique)** — механизм PostgreSQL для хранения больших атрибутов (блобов). Если размер JSON превышает порог (обычно 2 КБ), он выносится в отдельные страницы хранения (TOAST-таблицы).

## Основные концепции

### Сравнение json и jsonb

| Характеристика | `json` | `jsonb` |
| :--- | :--- | :--- |
| **Хранение** | Текст "как есть" | Бинарное дерево |
| **Вставка** | Быстрая (без парсинга) | Медленнее (требуется парсинг) |
| **Чтение** | Медленное (нужен парсинг) | Быстрое (готовая структура) |
| **Индексация** | Нет (только полнотекстовый поиск) | **GIN**, GiST, B-Tree (выражения) |
| **Числа** | Строки | Тип `numeric` |

### Хранение и производительность (TOAST)

JSONB-объекты хранятся как иерархические структуры с указателями. Это позволяет быстро перемещаться к нужным узлам без полного чтения объекта.
Однако при обновлении поля (`jsonb_set`) PostgreSQL копирует **весь** документ, создает новую версию строки (MVCC) и записывает её (в том числе в TOAST). Это приводит к:
- Раздуванию таблиц (Bloat).
- Повышенной нагрузке на I/O.
- Нагрузке на `autovacuum`.

**Рекомендация:** Часто меняющиеся поля (статусы, счетчики) следует выносить в обычные колонки таблицы.

### Индексация

#### 1. GIN (Generalized Inverted Index)
Основной тип индекса для `jsonb`. Позволяет эффективно проверять наличие ключей и вхождение объектов.

- **`jsonb_ops` (по умолчанию):** индексирует каждый ключ и значение. Поддерживает все операторы (`@>`, `?`, `?&`, `?|`).
- **`jsonb_path_ops`:** индексирует только пути. Индекс компактнее и быстрее, но поддерживает только оператор вхождения `@>`.

#### 2. B-Tree (Functional/Expression Index)
Если поиск всегда идет по конкретному полю (например, `ID` или `status`), эффективнее создать обычный B-Tree индекс на результат выражения:
```sql
CREATE INDEX idx_orders_status ON orders ((data->>'status'));
```
Такой индекс меньше весит, быстрее работает и может быть покрывающим (Index Only Scan).

## Практические сценарии

### Основные операторы

| Оператор | Описание | Пример |
| :--- | :--- | :--- |
| `->` | Получить объект/элемент массива по ключу/индексу | `data->'user'` |
| `->>` | Получить значение как текст | `data->>'name'` |
| `#>` | Получить объект по заданному пути | `data#>'{a,b}'` |
| `@>` | Проверка вхождения (содержит ли левый JSON правый) | `data @> '{"id": 1}'` |
| `?` | Проверка наличия ключа | `data ? 'status'` |

### Сравнение с MongoDB

| Функция | PostgreSQL (jsonb) | MongoDB |
| :--- | :--- | :--- |
| **Транзакции** | Полная поддержка ACID | Ограниченная (на уровне документа/сессии) |
| **Джоины** | Нативные SQL Joins | `lookup` (менее эффективно) |
| **Обновления** | Копирование всего документа (медленно) | In-place updates (быстро) |
| **Схема** | Гибридная (Relation + JSON) | Только документы |

### Когда использовать JSON в Postgres
- **Слабоструктурированные данные:** Характеристики товаров в интернет-магазинах (разные наборы атрибутов для разных категорий).
- **Конфигурации и флаги:** Настройки пользователя, AB-тесты.
- **Логи и аудит:** Хранение метаданных событий, структура которых может меняться.

## Дополнительная информация

- **Ограничение размера:** Один JSONB-объект не может превышать 1 ГБ (технический лимит PostgreSQL), но на практике проблемы начинаются гораздо раньше (>1-2 МБ) из-за накладных расходов на MVCC.
- **Валидация:** PostgreSQL проверяет валидность JSON при вставке, но не проверяет схему (если не используются сторонние расширения или `CHECK` констрейнты с `jsonb_matches_schema`).
