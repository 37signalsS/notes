# Поддержка JSON в PostgreSQL

## Определения

- **JSON (JavaScript Object Notation)**: Легкий текстовый формат обмена данными. В PostgreSQL представлен двумя основными типами: `json` и `jsonb`.
- **json (Plain JSON)**: Текстовый тип данных, хранящий точную копию входного текста. Сохраняет форматирование, пробелы и порядок ключей. Требует парсинга при каждом обращении к элементам.
- **jsonb (Binary JSON)**: Бинарный тип данных, хранящий декомпозированную структуру. Парсинг происходит один раз при вставке. Не сохраняет пробелы и порядок ключей, но поддерживает эффективную индексацию.
- **TOAST (The Oversized Attribute Storage Technique)**: Механизм PostgreSQL для хранения больших атрибутов. Документы размером более ~2 КБ автоматически сжимаются и выносятся во внетабличное хранилище.
- **SQL/JSON**: Набор стандартных функций и операторов (SQL:2016), внедренных в PostgreSQL (особенно в версиях 16–17) для унифицированной работы с JSON.

## Базовые концепции

### Сравнение типов json и jsonb

| Характеристика | `json` | `jsonb` |
| :--- | :--- | :--- |
| **Хранение** | Текст "как есть" | Бинарная иерархия |
| **Вставка** | Быстрая | Медленнее (валидация + бинаризация) |
| **Чтение** | Медленное (парсинг на лету) | Быстрое (прямой доступ) |
| **Индексация** | Нет | **GIN**, B-Tree (на выражения) |
| **Обновление** | Полная перезапись | Полная перезапись (MVCC) |

**hstore (расширение)**: Полезно для плоских структур ключ-значение, где все значения являются строками. В современном дизайне чаще заменяется на `jsonb`.

### Хранение и производительность (MVCC и TOAST)

PostgreSQL использует модель **MVCC**. При любом обновлении поля внутри `jsonb`-документа СУБД создает **полную копию** всей строки таблицы. 

**Важные нюансы:**
- **Bloat (Раздувание)**: Частые микро-обновления больших документов (`jsonb_set`) ведут к быстрому раздуванию таблиц и индексов.
- **TOAST Overhead**: Если документ вынесен в TOAST, чтение даже одного ключа потребует извлечения всех чанков документа из TOAST-таблицы, их декомпрессии и парсинга.
- **Рекомендация**: Часто меняющиеся атрибуты (счетчики, статусы) следует хранить в обычных колонках таблицы, а не внутри JSON.

## Индексация

1. **GIN (Generalized Inverted Index)**:
   - `jsonb_ops` (по умолчанию): Индексирует все ключи и значения. Позволяет использовать операторы `@>` (вхождение) и `?` (наличие ключа).
   - `jsonb_path_ops`: Индексирует только хеши полных путей. Работает быстрее и занимает меньше места, но поддерживает только оператор `@>`.

2. **B-Tree (функциональные индексы)**:
   Идеально для поиска по конкретному полю верхнего уровня.
   ```sql
   CREATE INDEX idx_user_id ON orders ((data->>'user_id'));
   ```

## Практические сценарии

### Основные операторы и сабскриптинг

| Оператор | Описание | Пример |
| :--- | :--- | :--- |
| `->` | Получить элемент как JSON | `data->'profile'` |
| `->>` | Получить элемент как текст | `data->>'email'` |
| `[]` | Сабскриптинг (PG 14+) | `data['profile']['name']` |
| `@>` | Проверка вхождения | `data @> '{"role": "admin"}'` |

### Модификация данных

- **`jsonb_set(target, path, new_value, create_if_missing)`**: Изменение или добавление значения по пути.
- **`jsonb_insert(target, path, new_value, [insert_after])`**: Вставка значения в массив.
- **Оператор `-`**: Удаление ключа или элемента массива по индексу.
  ```sql
  UPDATE users SET data = data - 'old_key';
  ```

### SQL/JSON Пути (JsonPath)

Позволяет использовать сложные выражения (PG 12+).
```sql
-- Поиск товаров дороже 1000
SELECT * FROM products 
WHERE jsonb_path_exists(attributes, '$.price ? (@ > 1000)');
```

### Новое в PostgreSQL 16 и 17

1. **JSON_TABLE (PG 17)**: Превращение JSON в реляционную таблицу прямо в запросе.
   ```sql
   SELECT jt.*
   FROM orders,
        JSON_TABLE(data, '$.items[*]'
          COLUMNS (
            product_name text PATH '$.name',
            price numeric PATH '$.price'
          )
        ) AS jt;
   ```
2. **Конструкторы и предикаты (PG 16)**:
   - `JSON_OBJECT()` / `JSON_ARRAY()`: Стандартные способы создания JSON.
   - `IS JSON`: Проверка валидности (например, `val IS JSON OBJECT`).
3. **JSON_VALUE (PG 17)**: Извлечение скалярного значения с приведением типа.
   ```sql
   SELECT JSON_VALUE(data, '$.customer.id' RETURNING int) FROM orders;
   ```

### Валидация через JSON Schema
В ядре PostgreSQL нативной поддержки JSON Schema пока нет. 
- **Решение**: Использовать расширение **`pg_jsonschema`** или выполнять валидацию на стороне приложения перед вставкой.

## Дополнительная информация

### Сравнение с MongoDB

| Характеристика | PostgreSQL (`jsonb`) | MongoDB |
| :--- | :--- | :--- |
| **Гарантии** | Полный **ACID** | На уровне документа |
| **Связи** | Нативные JOIN | Ограниченно (`$lookup`) |
| **Обновления** | Перезапись всей строки | Частичное обновление |

### Когда использовать JSON

- **Слабоструктурированные данные**: Характеристики разных типов товаров.
- **Интеграция**: Хранение "сырых" ответов внешних API.
- **Прототипирование**: Когда схема данных еще не устоялась.
