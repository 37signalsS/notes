# MariaDB

## 1. Обзор

MariaDB — это реляционная СУБД, созданная оригинальными разработчиками MySQL как полностью открытый и управляемый сообществом форк. Она стремится сохранять высокую совместимость с MySQL, но при этом активно внедряет новые возможности и поддерживает разнообразие движков хранения.

### 1.1. История и философия

Изначально MySQL, разработанный компанией MySQL AB, стал де-факто стандартом для веб-приложений в начале 2000-х. В 2008 году MySQL AB была поглощена Sun Microsystems, а в 2010 году Sun, в свою очередь, была поглощена Oracle Corporation.

Опасаясь за будущее MySQL как открытого проекта под управлением Oracle, ключевые разработчики во главе с Майклом "Монти" Видениусом форкнули кодовую базу (на тот момент версии 5.5) и основали MariaDB.

Философия MariaDB заключается в следующем:
- **Открытость:** Разработка ведется полностью открыто и управляется сообществом через MariaDB Foundation.
- **Разнообразие движков:** В отличие от Oracle, который фокусируется почти исключительно на InnoDB, MariaDB активно поддерживает и развивает множество движков хранения.
- **Внедрение новых фич:** Активное добавление нового SQL-синтаксиса, функций и улучшений оптимизатора.

### 1.3. Ключевые отличия от MySQL 8

Начиная с версии MySQL 8.0, различия между продуктами стали существенными, что делает прямую миграцию без логического дампа невозможной. 

- **Движки хранения:** MariaDB предлагает гораздо более широкий выбор специализированных движков.
- **Query Cache:** В отличие от MySQL 8, где кэш запросов был полностью удален, в MariaDB он сохранен. Он может быть эффективен для нагрузок с преобладанием чтения (много `SELECT`) и редкой записью.
- **Оптимизатор запросов:** Команда MariaDB активно работает над улучшением собственного оптимизатора, добавляя новые возможности и улучшая производительность.
- **SQL-функциональность:**
    - **Типы данных:** Добавлены `UUID`, `INET4`, `INET6` для удобного хранения соответствующих типов данных.
    - **Операторы:** `CREATE OR REPLACE TABLE`, `DELETE ... RETURNING`.
    - **Анализ запросов:** `EXPLAIN` можно записывать в slow query log для анализа планов выполнения медленных запросов.
    - **Регулярные выражения:** Используется PCRE (Perl Compatible Regular Expressions), более мощный и привычный синтаксис по сравнению с POSIX-синтаксисом в MySQL.
- **Процессы:** `PROCESSLIST` показывает прогресс выполнения длительных запросов (например, для `ALTER TABLE`).
- **Кластеризация:** Встроенная поддержка Galera Cluster для создания синхронного мульти-мастер кластера.
- **Системные таблицы:** В MariaDB системные таблицы используют движок Aria, в то время как в MySQL 8 все переведено на InnoDB.

## 2. Движки хранения (Storage Engines)

Одной из ключевых особенностей и преимуществ MariaDB является поддержка и активное развитие множества движков хранения (storage engines), в то время как Oracle MySQL фокусируется почти исключительно на InnoDB.

### 2.1. InnoDB

InnoDB (в MariaDB используется его форк XtraDB от Percona) остается основным движком по умолчанию для большинства задач. Это универсальный транзакционный движок, соответствующий требованиям **[ACID](../Concepts/acid.md)**, который хорошо подходит для OLTP-нагрузок.

### 2.2. Aria

Aria — это движок, который позиционируется как отказоустойчивая и более современная замена MyISAM.

- **История:** Изначально MyISAM был основным движком в MySQL, известным своей скоростью на простых операциях, но и печально известным своей ненадежностью (повреждение таблиц при сбоях) и отсутствием поддержки транзакций.
- **Преимущества Aria:**
    - **Отказоустойчивость:** Aria использует транзакционный лог, что гарантирует восстановление данных после сбоя сервера. Проблема повреждения данных, свойственная MyISAM, решена.
    - **Кэширование:** Имеет более продвинутую систему кэширования данных и индексов, схожую с InnoDB.
    - **Использование:** В MariaDB движок Aria используется для внутренних системных и временных таблиц, что повышает общую стабильность сервера.
- **Будущее:** В планах разработчиков (Aria 2.0) — сделать его полностью транзакционным движком, который сможет составить конкуренцию InnoDB.

### 2.3. MyRocks

MyRocks — это движок хранения, разработанный в Facebook и основанный на структуре данных LSM-дерево (Log-Structured Merge-tree). Он также доступен в Percona Server.

- **Особенности:**
    - **Оптимизация под запись:** LSM-деревья идеально подходят для нагрузок с очень большим количеством операций записи (`INSERT`, `UPDATE`, `DELETE`).
    - **Сжатие данных:** Обеспечивает значительно лучшее сжатие данных по сравнению с InnoDB, что позволяет экономить дисковое пространство.
- **Сценарии использования:** Системы, где идет постоянный поток данных: логи, метрики, IoT.

### 2.4. ColumnStore

ColumnStore — это колоночный движок хранения, предназначенный для аналитических запросов (OLAP).

- **Принцип работы:** В отличие от традиционных строковых движков (InnoDB, Aria), которые хранят все поля одной записи рядом, ColumnStore хранит значения каждого столбца вместе.
- **Преимущества:**
    - **Скорость аналитики:** Запросы, которые агрегируют данные по нескольким столбцам (например, `SUM(price) GROUP BY category`), выполняются на порядки быстрее, так как движку нужно читать только данные из столбцов `price` и `category`, а не все данные таблицы.
    - **Высокое сжатие:** Данные в одном столбце обычно однотипны и хорошо сжимаются.
- **Сценарии использования:** Хранилища данных (Data Warehouses), аналитические отчеты.

### 2.5. Другие движки

- **S3 Storage Engine:** Позволяет хранить таблицы MariaDB в объектных хранилищах, совместимых с Amazon S3. Это может быть полезно для архивирования или для работы с очень большими объемами редко используемых данных.
- **Spider:** Движок для реализации шардинга (горизонтального масштабирования) на уровне самой базы данных.
- **FederatedX:** Позволяет обращаться к таблицам на удаленном сервере MariaDB/MySQL как к локальным.

## 3. Практические сценарии

### 3.1. Установка MariaDB в разных ОС и базовая настройка безопасности

#### 3.1.1. Установка

*   **Ubuntu и Debian:**
    ```bash
    apt -y install mariadb-server mariadb-client
    ```
*   **CentOS:**
    ```bash
    yum -y install mariadb mariadb-server
    ```

```bash
systemctl status mariadb
```

#### 3.1.2. Начальная настройка безопасности

После установки рекомендуется запустить встроенный инструмент для настройки безопасности:

```bash
mysql_secure_installation
```

C его помощью вы сможете отключить небезопасные опции. Рекомендуется подтвердить все параметры:

*   Новый пароль `root` для сервера баз данных.
*   Удаление анонимных пользователей.
*   Отключение удалённого доступа для пользователя `root`.
*   Удаление тестовой базы данных и доступов к ней.
*   Перезагрузка таблиц для применения новых параметров.

### 3.2. Установка в Ubuntu

Хотя MariaDB может находиться в стандартных репозиториях Ubuntu, для получения конкретной или последней версии рекомендуется использовать официальный репозиторий MariaDB.

1.  **Установка вспомогательных пакетов:**
    ```bash
    sudo apt update
    sudo apt install -y apt-transport-https curl
    ```

2.  **Добавление GPG ключа:**
    Ключ необходим для проверки подлинности пакетов.
    ```bash
    sudo mkdir -p /etc/apt/keyrings
    sudo curl -o /etc/apt/keyrings/mariadb-keyring.pgp 'https://mariadb.org/mariadb_release_signing_key.pgp'
    ```

3.  **Добавление репозитория:**
    Создайте файл `/etc/apt/sources.list.d/mariadb.sources`. Его содержимое определяет версию и дистрибутив.

    **Пример для MariaDB 11.3 и Ubuntu 22.04 (Jammy):**
    ```
    # MariaDB 11.3 repository list
    # https://mariadb.org/download/
    X-Repolib-Name: MariaDB
    Types: deb
    URIs: https://deb.mariadb.org/11.3/ubuntu
    Suites: jammy
    Components: main main/debug
    Signed-By: /etc/apt/keyrings/mariadb-keyring.pgp
    ```
    > **Примечание:** `jammy` соответствует Ubuntu 22.04. Для других версий Ubuntu (например, 20.04 `focal`) измените значение `Suites`. Версию MariaDB можно изменить, поменяв ее в `URIs` (например, на `10.11`).

4.  **Установка сервера:**
    После добавления репозитория обновите список пакетов и установите `mariadb-server`.
    ```bash
    sudo apt update
    sudo apt install -y mariadb-server
    ```

После установки сервис должен запуститься автоматически.

- **Проверить статус сервиса:**
  ```bash
  systemctl status mariadb
  ```

- **Подключиться к серверу:**
  Изначально для пользователя `root` пароль не требуется (используется аутентификация через unix-сокет).
  ```bash
  sudo mariadb
  ```
  Или, как псевдоним, можно использовать `mysql`.
  ```bash
  sudo mysql
  ```
  Внутри консоли вы увидите приветствие `Welcome to the MariaDB monitor`.

### 3.2. Конфигурация

Для сохранения совместимости с экосистемой MySQL, MariaDB использует схожую структуру и расположение конфигурационных файлов.

- **Основной каталог:** `/etc/mysql/`
- **Главный файл:** `/etc/mysql/my.cnf` или `/etc/mysql/mariadb.conf`. Обычно он содержит только ссылки (`!includedir`) на другие каталоги.
- **Каталог с настройками:** `/etc/mysql/mariadb.conf.d/`. Основная конфигурация сервера и клиента производится именно здесь. Файлы в этом каталоге загружаются в алфавитном порядке (поэтому их имена начинаются с чисел, например, `50-server.cnf`).

#### Основные файлы в `mariadb.conf.d`

-   `50-client.cnf`: Настройки для клиентских приложений (например, `mariadb`, `mariadb-dump`). Здесь можно задать порт по умолчанию, сокет или пароль.
-   `50-server.cnf`: **Основной файл для настройки сервера.** Здесь задаются параметры, влияющие на производительность, логирование, репликацию и безопасность.
-   `60-galera.cnf`: Конфигурация для Galera Cluster, если он используется.

#### Основные параметры в `50-server.cnf`

Конфигурация разделена на секции, например `[mysqld]`, `[server]`, `[mariadb]`.

```ini
[mariadb]
# -- Общие настройки --
# IP-адрес для приема подключений. 127.0.0.1 - только локальные. 0.0.0.0 - все интерфейсы.
bind-address = 127.0.0.1
# Максимальное количество одновременных подключений.
max_connections = 100

# -- Настройки движков --
# Размер буфера для ключей MyISAM/Aria.
key_buffer_size = 16M
# Основной параметр для InnoDB: размер буферного пула для данных и индексов.
# Рекомендуется устанавливать до 70-80% от доступной оперативной памяти на выделенном сервере.
innodb_buffer_pool_size = 128M

# -- Логирование --
# Включение лога медленных запросов.
slow_query_log = 1
# Файл для лога.
slow_query_log_file = /var/log/mysql/mariadb-slow.log
# Время в секундах, после которого запрос считается медленным.
long_query_time = 1
# Записывать в лог explain-план для медленных запросов. Очень полезно для анализа.
log_slow_extra = 1

# -- Бинарный лог (для репликации и восстановления на точку времени) --
# Активирует бинлог. Укажите базовое имя файла.
# log_bin = /var/log/mysql/mysql-bin.log
# Уникальный ID сервера в топологии репликации.
# server_id = 1
```

#### Расположение данных и логов

-   **Директория с данными (datadir):** `/var/lib/mysql/`
    -   Здесь хранятся подкаталоги для каждой базы данных, а также файлы логов InnoDB (`ib_logfile*`, `ibdata1`) и Aria (`aria_log*`).
    -   В отличие от MySQL 8, где файлы структуры таблиц (`.frm`) были упразднены, в MariaDB они все еще используются, что напоминает архитектуру MySQL 5.7.
-   **Лог ошибок:** `/var/log/mysql/error.log` или `/var/log/mariadb/mariadb.log`.
-   **Бинарные логи и логи медленных запросов:** Обычно также в `/var/log/mysql/`.

#### Клиентские утилиты

MariaDB постепенно переименовывает утилиты с `mysql*` на `mariadb*` для устранения путаницы. Однако для обратной совместимости старые имена работают как символические ссылки или псевдонимы.

| Старое имя | Новое имя | Назначение |
| --- | --- | --- |
| `mysql` | `mariadb` | CLI-клиент для подключения к серверу. |
| `mysqldump` | `mariadb-dump` | Создание логического дампа базы данных. |
| `mysqladmin` | `mariadb-admin` | Утилита для административных задач. |
| `mysqlcheck` | `mariadb-check` | Проверка и восстановление таблиц. |

### 3.3. Резервное копирование и восстановление

В этом разделе описаны специфичные для MariaDB инструменты. Общие теоретические подходы и стратегии описаны в основной заметке: **[Стратегии резервного копирования](../Concepts/backups.md)**.

#### Логическое резервное копирование

Логический бэкап представляет собой текстовый файл с SQL-командами (`CREATE TABLE`, `INSERT`), необходимыми для воссоздания базы данных.

-   **Плюсы:**
    -   Гибкость: легко переносится между разными версиями СУБД и даже разными СУБД (с доработками).
    -   Простота: дамп можно открыть и прочитать.
    -   Возможность частичного восстановления.
-   **Минусы:**
    -   Медленно: создание и особенно восстановление больших баз данных занимает много времени.

##### Утилита `mariadb-dump`

`mariadb-dump` (аналог `mysqldump`) — стандартная утилита для создания логических бэкапов.

-   **Создание дампа одной базы данных:**
    ```bash
    mariadb-dump -u <user> -p <database_name> > backup.sql
    ```
-   **Создание дампа всех баз данных:**
    ```bash
    mariadb-dump -u <user> -p --all-databases > all_databases_backup.sql
    ```
-   **Восстановление из дампа:**
    ```bash
    mariadb -u <user> -p <database_name> < backup.sql
    ```

##### Утилиты `mydumper` и `myloader`

`mydumper` — это высокопроизводительная утилита для создания многопоточных логических бэкапов. Он разбивает таблицы на части (чанки) и выгружает их параллельно в несколько файлов. `myloader` выполняет обратную операцию, также в несколько потоков.

Это решение значительно быстрее `mariadb-dump` на больших базах данных.

-   **Установка:**
    `mydumper` обычно доступен в виде отдельного пакета.
-   **Создание дампа:**
    ```bash
    # Указывается каталог, куда будут сохранены файлы дампа
    mydumper --database=<db_name> --outputdir=/path/to/dump/ -u <user> -p --threads=4
    ```
-   **Восстановление:**
    ```bash
    myloader --directory=/path/to/dump/ -u <user> -p --threads=4
    ```

#### Физическое резервное копирование

Физический бэкап — это прямое копирование файлов базы данных с диска.

-   **Плюсы:**
    -   Очень быстро: скорость ограничена только производительностью дисковой подсистемы.
-   **Минусы:**
    -   Менее гибкий: привязан к конкретной версии MariaDB.
    -   Сложнее в настройке и восстановлении.

##### Утилита `mariabackup`

`mariabackup` — это форк популярной утилиты Percona XtraBackup, адаптированный для MariaDB. Он позволяет создавать "горячие" бинарные копии базы данных без остановки работы сервера.

> **Важно:** Современный Percona XtraBackup несовместим с MariaDB из-за различий в форматах данных. Необходимо использовать именно `mariabackup`.

Процесс состоит из двух основных этапов: создание "сырой" копии и её подготовка.

1.  **Создание "сырой" копии (`--backup`):**
    На этом этапе `mariabackup` копирует файлы данных InnoDB/XtraDB и одновременно отслеживает изменения, которые происходят в базе во время копирования, записывая их в свой лог.
    ```bash
    mariabackup --backup \
      --target-dir=/path/to/backup/ \
      --user=<user> --password=<password>
    ```

2.  **Подготовка бэкапа (`--prepare`):**
    После создания копии её нужно "подготовить". На этом этапе `mariabackup` применяет к скопированным файлам данных изменения из своего лога, приводя их в консистентное состояние на момент окончания бэкапа.
    ```bash
    mariabackup --prepare --target-dir=/path/to/backup/
    ```

3.  **Восстановление (`--copy-back`):**
    Восстановление требует остановки сервера и полной очистки директории с данными.
    ```bash
    # 1. Остановить сервис MariaDB
    systemctl stop mariadb

    # 2. (Рекомендуется) Сделать копию старых данных, а не удалять сразу
    mv /var/lib/mysql /var/lib/mysql_old

    # 3. Создать пустую директорию
    mkdir /var/lib/mysql

    # 4. Скопировать подготовленный бэкап в директорию данных
    mariabackup --copy-back --target-dir=/path/to/backup/

    # 5. Вернуть права на файлы пользователю mysql
    chown -R mysql:mysql /var/lib/mysql

    # 6. Запустить сервис
    systemctl start mariadb
    ```
