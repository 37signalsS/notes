# Оркестрация и методы автоматизации

## Определения

- **Оркестрация (Orchestration)**: Скоординированное выполнение набора действий на разных узлах в определенном порядке с учетом зависимостей. В отличие от [highstate](Highstate_and_Execution_Order.md), который фокусируется на состоянии *одного* узла, оркестрация управляет *процессом* в масштабе всей инфраструктуры.
- **Runner**: Модуль, который исполняется на Salt Master, а не на Minion. Раннеры используются для централизованных задач: оркестрация (`state.orchestrate`), управление облачными ресурсами (`salt-cloud`), вызов команд по расписанию.
- **Beacon (Маяк)**: Модуль на Minion, отслеживающий системные события (изменение файла, загрузка CPU, появление лога) и отправляющий их на шину событий Salt ([архитектура](Architecture.md)).
- **Reactor (Реактор)**: Система на Master, слушающая события от Beacon и других источников и запускающая ответные действия (вызов Runner'а или применение состояния).

---

## Основные концепции

**Модели автоматизации в Salt**

| Модель | Описание | Инструменты Salt |
|---|---|---|
| **Push (проталкивание)** | Master инициирует выполнение команд и состояний на Minion'ах. | `salt`, `state.apply`, `state.highstate` |
| **Pull (вытягивание)** | Minion самостоятельно по расписанию запрашивает и применяет состояния. | `schedule` |
| **Событийная (Event-Driven)** | Действия запускаются в ответ на события в системе. | `beacons`, `reactor` |

**Инструменты для оркестрации**

- **`state.orchestrate`**: Основной инструмент для оркестрации. Это Runner, который выполняет SLS-файл на Master. Внутри этого файла можно вызывать состояния (`salt.state`) или функции (`salt.function`) на разных группах Minion'ов, выстраивая зависимости между ними.
- **Reactor + Beacons**: Мощная связка для создания реактивной инфраструктуры, которая автоматически реагирует на изменения.
- **`salt-api`**: REST API для интеграции Salt с внешними системами (CI/CD, чат-боты, панели управления), позволяя запускать оркестрацию по внешнему триггеру.
- **Schedule**: Планировщик для выполнения рутинных задач (например, резервное копирование) на Minion'ах по расписанию.

## Практические сценарии

**1. Оркестрация развертывания приложения**

Этот SLS-файл, запущенный через `state.orchestrate`, описывает процесс развертывания: сначала настраивается база данных, затем выполняются миграции, и только после этого развертывается приложение.

```yaml
# /srv/salt/orch/deploy_app.sls

# Шаг 1: Настроить и запустить БД
provision_db:
  salt.state:
    - tgt: 'role:db'
    - tgt_type: grain
    - sls:
      - postgres.install

# Шаг 2: Выполнить миграции на узлах приложения
migrate_db:
  salt.function:
    - name: cmd.run
    - tgt: 'role:app'
    - tgt_type: grain
    - arg:
      - 'python manage.py migrate'
    - require: # Зависит от шага 1
      - salt: provision_db

# Шаг 3: Развернуть приложение
deploy_app:
  salt.state:
    - tgt: 'role:app'
    - tgt_type: grain
    - sls:
      - app.deploy
    - require: # Зависит от шага 2
      - salt: migrate_db
```

Запуск оркестрации:

```bash
salt-run state.orchestrate orch.deploy_app
```

**2. Автоматический перезапуск сервиса при изменении конфига (Beacon + Reactor)**

**Minion (Beacon):** Отслеживает изменения в файле `.env`.

```yaml
# /etc/salt/minion.d/beacons.conf
beacons:
  inotify:
    /etc/myapp/.env:
      mask: [modify]
```

**Master (Reactor):** При получении события вызывает SLS для перезапуска.

```yaml
# /srv/salt/reactor/restart_app.sls
{% set minion_id = data['id'] %}

restart_service:
  local.cmd:
    - tgt: {{ minion_id }}
    - fun: service.restart
    - arg:
      - myapp
```

**3. Интеграция с CI/CD через `salt-api`**

Команда для запуска оркестрации из Jenkins, GitLab CI или другого инструмента.

```bash
curl -sSk https://salt-master:8000/run \
  -H "X-Auth-Token: $SALT_API_TOKEN" \
  -d client='runner' \
  -d fun='state.orchestrate' \
  -d mods='orch.deploy_app'
```

## Дополнительная информация

- **Идемпотентность**: Проектируйте оркестрации так, чтобы их можно было безопасно запускать повторно.
- **Параллельное выполнение**: Для управления одновременным выполнением на большом количестве узлов используйте параметры `batch` и `serial` в `salt.state`.
- **Архитектурная основа**: Все инструменты оркестрации работают поверх [шины событий](Architecture.md), ядра Salt.
- **Отладка**: `test=True` для безопасной проверки логики оркестрации.

**Сравнение с другими инструментами**

Salt Orchestration обеспечивает полную оркестрацию с поддержкой Push и Pull ([сравнение моделей](../Concepts/configuration_management_push_vs_pull.md)) и идемпотентность, в отличие от GitLab CI, где идемпотентность зависит от скриптов. Ansible Playbooks также обеспечивают полную оркестрацию, но работают только в Push-режиме.

**Современные возможности (3006+)**

Salt Cloud для управления облачными ресурсами (AWS, Azure, GCP, vSphere), интеграция с Kubernetes, расширенная поддержка реактивных сценариев (Event-Driven Automation).

**Best Practices**

Разделяйте [highstate](Highstate_and_Execution_Order.md) (состояние узлов) и оркестрацию (координация); используйте `batch` для предотвращения перегрузки сети; логируйте все запуски для аудита; тестируйте в изоляции перед применением в продакшене. Интеграция с внешними CI/CD-системами описана в [обзоре CI/CD](../CI-CD/ci_cd_overview.md).
