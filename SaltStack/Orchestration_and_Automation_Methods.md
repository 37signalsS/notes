# Способы оркестрации и автоматизации

Оркестрация в контексте SaltStack — это согласованное выполнение действий на множестве узлов с учетом зависимостей, событий и целевых критериев. Автоматизация решает отдельные задачи (установка пакета, перезапуск сервиса), а оркестрация связывает их в управляемые цепочки: подготовка инфраструктуры, деплой приложения, миграции, проверки здоровья. В Salt это достигается сочетанием декларативных состояний, событийной шины и специализированных механизмов запуска.

## Модели выполнения

*   Push-ориентация: мастер инициирует выполнение на минионах, обеспечивая быстрый и централизованный контроль.
*   Pull-ориентация по расписанию: задачи запускаются локально на минионах через планировщик, снижается нагрузка на мастер.
*   Событийно-ориентированная автоматизация: маяки (beacons) генерируют события, реактор (reactor) сопоставляет их с действиями.
*   Императивное vs декларативное: модули выполнения выполняют команды «здесь и сейчас», состояния обеспечивают идемпотентность и желаемое состояние, а оркестрация связывает несколько состояний/команд в единый процесс.

## Инструменты Salt для оркестрации

| Подход | Когда использовать | Особенности |
|---|---|---|
| state.apply | Применение состояний на целевых узлах | Декларативность, идемпотентность |
| state.orchestrate (runner) | Сквозные сценарии на уровне мастера | Управление зависимостями между группами узлов |
| salt-ssh | Без демона на целевых узлах | Удобно для изолированных/малых сред |
| Reactor + Beacons | Реакция на события (файлы, процессы, системные метрики) | Полностью event-driven |
| Schedule | Регулярные задачи на минионах | Локальные cron-подобные задания |
| salt-cloud | Жизненный цикл инфраструктуры | Создание/удаление VM перед конфигурированием |
| Syndic | Многоуровневые топологии | Масштабирование на крупные ландшафты |
| salt-api | Интеграция с внешними системами | Триггеры из CI/CD, чат-ботов, порталов |

## Таргетинг и порядок выполнения

Таргетинг позволяет точно выбирать узлы: по маске, зернам (grains), выражениям compound и nodegroups. Порядок и зависимости задаются через require, watch, onchanges, а масштабирование и безопасность — через batch/serial и ограничения параллельности.

Пример orchestration SLS, запускающий установку БД, миграции и деплой приложения:

```yaml
# /srv/salt/orch/deploy.sls
provision_db:
  salt.state:
    - tgt: 'role:db'
    - tgt_type: grain
    - sls:
      - postgres.install
      - postgres.config

migrate:
  salt.function:
    - name: cmd.run
    - tgt: 'G@role:app and E@^prod-'
    - expr_form: compound
    - arg:
      - 'alembic upgrade head'
    - require:
      - salt: provision_db

deploy_app:
  salt.state:
    - tgt: 'G@role:app and E@^prod-'
    - expr_form: compound
    - sls: app.deploy
    - require:
      - salt: migrate
```

Запуск:

```applescript
salt-run state.orchestrate orch.deploy pillar='{"version":"1.2.3"}'
```

## Событийно-ориентированная автоматизация (beacons + reactor)

Маяк на минионе отслеживает изменения файла конфигурации:

```yaml
# /etc/salt/minion.d/beacons.conf
beacons:
  inotify:
    /etc/myapp/.env:
      - mask:
        - modify
```

Правило реактора на мастере:

```markdown
# /etc/salt/master.d/reactor.conf
reactor:
  - 'salt/beacon/*/inotify/*':
    - /srv/salt/reactor/restart-app.sls
```

Действие реактора:

```yaml
# /srv/salt/reactor/restart-app.sls
restart_app:
  local.service.restart:
    - tgt: 'G@role:app and E@^prod-'
    - expr_form: compound
    - arg:
      - 'myapp'
```

## Интеграция с CI/CD через salt-api

Внешняя система может триггерить оркестрацию после сборки артефакта:

```kotlin
curl -sSk https://salt-master:8000/run 
  -H "X-Auth-Token: $TOKEN" 
  -d client=runner 
  -d fun=state.orchestrate 
  -d mods=orch.deploy 
  -d pillar='{"version":"1.2.3","env":"prod"}'
```

## Практические рекомендации

*   Проектируйте оркестрации идемпотентными и реэнтерабельными.
*   Отлаживайте с test=true и подробными returners.
*   Разносите инфраструктурные и прикладные шаги на разные таргеты.
*   Используйте nodegroups для стабильного таргетинга и compound-выражения для точности.
*   Ограничивайте параллельность batch-параметрами для чувствительных сервисов.
*   Закладывайте обработку неуспехов: onfail, retry-паттерны, временные таймауты.
