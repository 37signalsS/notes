# Подходы к безопасности

## Определения

- **Модель доверия (Trust Model)**: В Salt основное доверие выстраивается между Master и Minion. Master является центром управления и источником правды, а Minion'ы доверяют его командам после установления защищенного канала.
- **PKI (Public Key Infrastructure)**: Основа аутентификации в Salt. Каждый Minion имеет криптографическую пару ключей. Публичный ключ отправляется на Master для подписи, после чего устанавливается зашифрованное соединение.
- **`client_acl` (External Authentication)**: Механизм внешних прав доступа, который позволяет ограничивать, какие пользователи или группы могут выполнять какие команды на каких Minion'ах. Используется в связке с `external_auth`.
- **SDB (Salt Data Backend)**: Интерфейс для получения данных (включая секреты) из внешних систем, таких как HashiCorp Vault, Consul или etcd.

## Основные концепции

**1. Аутентификация и управление ключами**

Безопасность Salt начинается с контроля над ключами Minion'ов.

- **Принятие ключей**: Ключи должны приниматься вручную (`salt-key -A <minion_id>`). Глобальный `auto_accept: True` крайне не рекомендуется. Допустимо использовать `autosign_grains_dir` для автоматического принятия ключей только для Minion'ов с определенными Grains.
- **Проверка ключа мастера**: Чтобы защититься от MitM-атак, Minion должен проверять подпись публичного ключа мастера. Это включается директивами `master_sign_pubkey: True` на мастере и `verify_master_pubkey_sign: True` на Minion.
- **Ротация ключей**: Ключи следует периодически менять для снижения рисков компрометации.

**2. Авторизация и ограничение прав (ACL)**

После аутентификации необходимо ограничить права пользователей и систем.

- **External Authentication (`external_auth`)**: Позволяет пользователям аутентифицироваться в Salt через системные механизмы (PAM, LDAP).
- **Client ACL (`client_acl`)**: Определяет, что именно аутентифицированный пользователь может делать. Права выдаются на конкретные модули и функции с возможностью таргетинга.

**3. Управление секретами**

Никогда не храните секреты в открытом виде, особенно в состояниях (`file_roots`), которые доступны многим Minion'ам.

- **Pillar**: Основной механизм для передачи секретов. Pillar-данные рендерятся на мастере и доставляются только тем Minion'ам, для которых они предназначены.
- **Шифрование в Pillar**: Salt поддерживает рендереры GPG и KMS для шифрования данных прямо внутри Pillar-файлов.
- **Salt Vault (SDB)**: Наиболее безопасный подход. Секреты хранятся во внешнем, защищенном хранилище (например, HashiCorp Vault), а Salt получает их "на лету" по мере необходимости через SDB-интерфейс.

## Практические сценарии

**1. Пример Client ACL для команды Ops**

В конфигурации мастера (`/etc/salt/master`) даем пользователям группы `ops` право выполнять `test.ping` и применять состояния (`state.apply`) только на серверах с ролью `app` в продакшене.

```yaml
external_auth:
  pam:
    ops: # Имя системной группы
      - .* # Доступ ко всем Minion'ам
      - '@wheel' # Доступ к wheel-функциям
      - '@runner' # Доступ к runner-функциям

client_acl:
  ops: # Группа, определенная в external_auth
    - 'G@role:app and E@prod-.*': # Таргетинг
      - test.ping
      - state.apply
```

**2. Шифрование секрета с помощью GPG-рендерера**

**Master**: Настраивает рендерер.

```yaml
# /etc/salt/master
renderer: jinja | yaml | gpg
```

**Pillar**: Пароль зашифрован.

```yaml
# /srv/pillar/db.sls
db_password: |
  -----BEGIN PGP MESSAGE-----
  ... (зашифрованный текст) ...
  -----END PGP MESSAGE-----
```

При рендеринге Pillar для Minion'а Salt расшифрует это значение своим GPG-ключом.

**3. Отключение опасных модулей на Minion**

Если на серверах не должно быть возможности выполнять произвольные команды, можно отключить модуль `cmd`.

```yaml
# /etc/salt/minion
disable_modules:
  - cmd
```

## Дополнительная информация

- **Сетевая безопасность**: Ограничьте доступ к портам мастера (4505, 4506) только из доверенных сетей. `salt-api` следует "прятать" за обратным прокси (reverse proxy).
- **Аудит**: Включайте логирование действий и регулярно анализируйте их. Храните ограниченное количество истории выполненных заданий (`keep_jobs`).
- **Изоляция окружений**: Используйте окружения Salt (`saltenv`) для разделения состояний и Pillar-данных между средами (dev, stage, prod).

**Современные возможности (3006+)**

- **Secrets Management**: Интеграция с HashiCorp Vault, AWS Secrets Manager, Azure Key Vault
- **Compliance**: Модули для проверки соответствия стандартам (CIS, PCI-DSS, HIPAA)
- **Enhanced PKI**: Улучшенная поддержка ротации ключей и отзыва сертификатов

**Best Practices**

- **Минимальные привилегии**: Давайте пользователям и системам только необходимые права
- **Регулярная ротация ключей**: Меняйте ключи Minion и мастер-ключи по расписанию
- **Шифрование Pillar**: Всегда шифруйте чувствительные данные в Pillar
- **Мониторинг событий**: Отслеживайте подозрительную активность через шину событий
- **Сегментация сети**: Изолируйте Salt-трафик в отдельной сети VLAN
