# Безопасность и управление секретами в SaltStack

## Определения

- **Модель доверия (Trust Model)**: Иерархическая модель, где Master является доверенным источником конфигураций, а Minion'ы проходят аутентификацию через PKI перед выполнением команд.
- **PKI (Public Key Infrastructure)**: Система на базе RSA-ключей для аутентификации миньонов и AES-шифрования трафика.
- **eAuth (External Authentication)**: Система делегирования аутентификации внешним провайдерам (LDAP, Active Directory, PAM) для доступа к Salt-API или CLI.
- **Publisher ACL**: Механизм разграничения прав доступа локальных пользователей ОС к командам Salt без прав root.
- **SDB (Salt Data Backend)**: Универсальный интерфейс для динамического получения данных из защищенных хранилищ (Vault, AWS Secrets Manager) в реальном времени.

## Основные концепции

### 1. Жизненный цикл ключей и PKI

Безопасность начинается с контроля доступа к мастеру.
- **Аутентификация миньонов**: Только принятые ключи (`salt-key -a`) имеют доступ к шине. Глобальный `auto_accept: True` запрещен.
- **Защита от MitM**: Использование `master_sign_pubkey` гарантирует, что миньон подключается к подлинному мастеру.
- **Ротация и отзыв**: При компрометации узла ключ должен быть немедленно удален (`salt-key -d <minion_id>`). В крупных средах рекомендуется автоматизировать ротацию ключей раз в 90 дней.

### 2. Авторизация и контроль доступа (ACL)

SaltStack предлагает три уровня контроля:
1.  **`publisher_acl`**: Для пользователей, имеющих локальный доступ к терминалу мастера.
2.  **`external_auth` (eAuth)**: Для доступа через `salt-api` или сторонние системы. Позволяет использовать корпоративные учетные записи.
3.  **`peer_acl`**: Позволяет миньонам отправлять команды другим миньонам (использовать с крайней осторожностью).

### 3. Управление секретами (Secret Management)

Секреты никогда не должны находиться в открытом виде в Git или SLS-файлах.

**Методы шифрования Pillar:**
- **GPG-рендерер**: Классический метод. Данные шифруются на мастере и расшифровываются только для целевого миньона.
- **Fernet**: Современная альтернатива GPG, использующая симметричное шифрование. Проще в настройке и быстрее работает.

**Интеграция с внешними хранилищами (Vault):**
- **Pillar-интеграция**: Секреты подтягиваются из Vault в момент рендеринга Pillar на мастере.
- **SDB-запросы**: Миньон запрашивает секрет напрямую из Vault через мастера, не сохраняя его в своей конфигурации.

## Практические сценарии

### 1. Настройка eAuth с интеграцией PAM
Позволяет пользователю `devops_admin` выполнять команды через Salt-API, аутентифицируясь по системному паролю.

```yaml
# /etc/salt/master.d/eauth.conf
external_auth:
  pam:
    devops_admin:
      - 'web-*':
        - test.ping
        - state.apply
      - '@runner':
        - jobs.lookup_jid
```

### 2. Использование шифрования Fernet в Pillar
1. Генерируем ключ на мастере и кладем в `/etc/salt/fernet.key`.
2. Шифруем строку: `salt-call fernet.encrypt "super-secret"`.
3. Вставляем в Pillar:
```yaml
# /srv/pillar/secrets.sls
api_key: |
  -----BEGIN FERNET MESSAGE-----
  ... (base64) ...
  -----END FERNET MESSAGE-----
```

### 3. Харденинг (Укрепление) системы
- **Минимальные привилегии**: Запуск Master и Minion от непривилегированных пользователей (где возможно).
- **Отключение модулей**: Блокировка потенциально опасных функций на миньонах.
```yaml
# /etc/salt/minion.d/hardening.conf
disable_modules:
  - cmd
  - shell
  - disk.wipe
```

## Дополнительная информация

### Безопасность Salt-API
- **TLS**: Использование HTTPS обязательно. Рекомендуется размещать `salt-api` за обратным прокси (Angie/Nginx) с настроенным HSTS и современными шифрами.
- **CORS**: Ограничение источников запросов (`/etc/salt/master` → `rest_cherrypy: cors_origin`).

### Аудит и комплаенс
- **Журналирование**: Все события на шине (`salt/job/*/new`, `salt/job/*/ret`) должны логироваться.
- **Salt Returners**: Отправка результатов выполнения команд напрямую в защищенную БД или SIEM (Splunk, ELK) для последующего аудита.
- **Compliance**: Модули `hubblestack` или встроенные проверки на соответствие стандартам CIS.

### Свежесть и актуальность (2026)
- **Salt 3008 LTS**: Поддержка последних стандартов шифрования и Python 3.12+.
- **FIPS Mode**: Поддержка работы в режиме соответствия федеральным стандартам обработки информации.
