### Определения

- **Архитектура SaltStack**: Модель управления конфигурацией, построенная на взаимодействии центрального узла **Master** и агентов **Minion** через асинхронную шину сообщений.
- **Master**: Сервер, который отправляет команды и состояния, хранит Pillar-данные и является точкой входа для управления.
- **Minion**: Агент, работающий на управляемых узлах. Он слушает команды мастера, выполняет их и сообщает о результатах.
- **Grains**: Статическая информация о Minion (ОС, версия ядра, архитектура CPU), которая собирается при старте агента. Используется для таргетинга.
- **Pillar**: Конфиденциальные и целевые данные (пароли, ключи, переменные), которые Master безопасно передает конкретным Minion.
- **Event Bus**: Шина событий (по умолчанию на основе ZeroMQ), через которую происходит все взаимодействие в Salt.

### Основные концепции

**Коммуникационная модель**

Взаимодействие между Master и Minion происходит по двум основным портам:
- **4505 (Publisher)**: Master публикует задания. Minion'ы подписываются и получают их.
- **4506 (Retriever)**: Minion'ы возвращают результаты выполнения заданий и файлы.

Коммуникации защищены с помощью PKI-инфраструктуры. При первом запуске Minion генерирует ключевую пару и отправляет публичный ключ на Master. После принятия ключа администратором (`salt-key -A`) весь трафик между ними шифруется.

**Таргетинг (Targeting)**

Таргетинг — это механизм выбора Minion'ов, к которым будет применена команда или состояние. Salt поддерживает гибкие методы выбора:
- Глоббинг (например, `web-*`).
- Регулярные выражения (например, `E@^(web|db)\\.prod`).
- По Grains (например, `G@os:Ubuntu`).
- По Pillar (например, `P@role:database`).
- Составные выражения (Compound), объединяющие несколько методов.

**Разделение команд и состояний**

Salt разделяет два подхода к управлению:
1.  **Императивный (Execution Modules)**: Выполнение конкретных команд «здесь и сейчас». Пример: `salt '*' pkg.install nginx`.
2.  **Декларативный (State Modules)**: Описание *желаемого* состояния системы в SLS-файлах. Salt сам определяет, какие действия нужно предпринять для его достижения. Подробнее см. в **[Highstate и порядок выполнения](Highstate_and_Execution_Order.md)**.

### Практические сценарии

**1. Минимальная конфигурация**

```yaml
# /etc/salt/master
interface: 0.0.0.0
file_roots:
  base:
    - /srv/salt
pillar_roots:
  base:
    - /srv/pillar
```

```yaml
# /etc/salt/minion
id: web-01.example.com
master: <ip_or_dns_of_master>
```

**2. Пример таргетинга**

Выполнить команду `test.ping` на всех машинах с ОС Debian, которые также являются веб-серверами или кэш-серверами:
```bash
salt -C 'G@os:Debian and (web* or cache*)' test.ping
```

### Дополнительная информация

**Топологии развертывания**

- **Один мастер**: Стандартная и наиболее распространенная топология.
- **Мультимастер (Multi-Master)**: Minion настроен на работу с несколькими мастерами для обеспечения отказоустойчивости.
- **Иерархия с Syndic**: Создание "мастера мастеров" для управления крупными или географически распределенными инфраструктурами.
- **Masterless (Без мастера)**: `salt-call --local` позволяет применять состояния локально без необходимости подключения к мастеру, что полезно для создания образов (Packer) или в изолированных средах.
