# Архитектура SaltStack

## Определения

- **Архитектура SaltStack**: Модель управления конфигурацией, построенная на взаимодействии центрального узла **Master** и агентов **Minion** через асинхронную шину сообщений.
- **Master**: Центральный сервер управления, который отправляет команды, хранит Pillar-данные и управляет ключами.
- **Minion**: Агент на управляемом узле, исполняющий команды и сообщающий о результатах.
- **Grains**: Статические данные о миньоне (ОС, CPU, RAM), собираемые локально. Используются для таргетинга.
- **Pillar**: Динамические конфиденциальные данные (секреты, переменные), назначаемые мастером конкретным миньонам.
- **Event Bus**: Шина событий (ZeroMQ или TCP), обеспечивающая мгновенную связь между компонентами.
- **Runners**: Модули, исполняемые на Master для управления инфраструктурой Salt (работа с ключами, очередями заданий).
- **Beacons**: Механизм мониторинга на Minion, отправляющий события в шину при изменении состояния (например, падение процесса).
- **Reactors**: Логика на Master, которая реагирует на события Beacons для автоматического исправления дрейфа или сбоев.
- **Proxy Minion**: Прокси-агент для управления устройствами без поддержки Python (коммутаторы, API-сервисы).

## Основные концепции

### Коммуникационная модель

Взаимодействие Master и Minion строится по схеме «издатель-подписчик» (Pub/Sub):

1.  **Порт 4505 (Publisher)**: Мастер публикует сообщения. Все миньоны слушают этот порт.
2.  **Порт 4506 (Retriever)**: Миньоны возвращают данные (результаты выполнения, запросы файлов или Pillar) на мастер.

**Транспортные протоколы:**
- **ZeroMQ (по умолчанию)**: Высокая производительность, асинхронность. Требует установки библиотек в ОС.
- **TCP**: Альтернатива без зависимостей от ZeroMQ, полезная в сетях с жесткими правилами фильтрации трафика.

Безопасность обеспечивается PKI-инфраструктурой на базе AES-256 и RSA ([подробнее о безопасности](Security_Approaches.md)).

### Таргетинг (Targeting)

Таргетинг позволяет выбирать целевые узлы для команд:
- **Глоббинг**: `salt 'web-*' test.ping`
- **Grains**: `salt -G 'os:Ubuntu' test.ping`
- **Pillar**: `salt -I 'role:cache' test.ping`
- **Составные (Compound)**: `salt -C 'G@os:Debian and not web-01*' test.ping`

### Декларативный и императивный подходы

1.  **Императивный (Execution Modules)**: Прямые команды. `salt '*' pkg.install vim`.
2.  **Декларативный (State Modules)**: Описание состояния в SLS-файлах (YAML + Jinja). Salt сам вычисляет необходимые изменения ([модели управления конфигурацией](../Concepts/configuration_management_models.md)).
    *   Процесс применения состояний: [Highstate и порядок выполнения](Highstate_and_Execution_Order.md).

## Практические сценарии

### 1. Базовая настройка
Файлы конфигурации по умолчанию:
- `/etc/salt/master`: Настройка корней файлов (`file_roots`) и данных (`pillar_roots`).
- `/etc/salt/minion`: Указание `master: <IP>` и `id: <hostname>`.

### 2. Пример декларативного состояния (SLS)
Файл `/srv/salt/webserver.sls`:
```yaml
install_nginx:
  pkg.installed:
    - name: nginx

nginx_service:
  service.running:
    - name: nginx
    - enable: True
    - watch:
      - pkg: install_nginx
```
Применение: `salt 'web-*' state.apply webserver`.

## Дополнительная информация

### Топологии и масштабирование

- **Иерархия (Syndic)**: Узел-посредник (Syndic), который передает команды от «Мастера Мастеров» локальным мастерам. Позволяет масштабироваться на десятки тысяч узлов.
- **Multi-Master**: Подключение миньона к нескольким мастерам для отказоустойчивости.
- **Salt-SSH**: Агентский режим (Agentless). Управление через SSH без установки миньона. Идеально для начальной настройки или закрытых сегментов.
- **Masterless**: Использование `salt-call --local` для применения состояний без мастера (например, при сборке образов Packer).

### Экосистема и свежесть (2026)

- **Salt 3008 LTS**: Актуальная ветка с мая 2026 года. Включает улучшенную поддержку Python 3.12+ и оптимизацию ZeroMQ.
- **Salt-API**: REST-интерфейс для интеграции Salt с внешними системами (CI/CD, порталы самообслуживания).
- **Salt Cloud**: Инструмент для автоматического развертывания виртуальных машин в облаках (AWS, Azure, GCP, OpenStack) с последующей установкой миньона.
- **Tiamat / Onedir**: Современный метод распространения Salt в виде единого бинарного файла со всеми зависимостями (упрощает установку в изолированных ОС).
- **Event-Driven Automation**: Использование связки [Beacon + Reactor](Orchestration_and_Automation_Methods.md) для создания самовосстанавливающейся инфраструктуры.
