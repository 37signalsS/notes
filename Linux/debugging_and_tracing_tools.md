# Инструменты отладки и трассировки в Linux

В Linux существует множество мощных инструментов для "black box" отладки и анализа поведения работающих процессов, даже без доступа к их исходному коду. Эти утилиты позволяют заглянуть "внутрь" приложения, отслеживая его взаимодействие с ядром и другими библиотеками.

## Основные инструменты

### strace: Трассировка системных вызовов и сигналов

`strace` — это мощная утилита для диагностики и отладки в Linux, которая перехватывает и записывает **системные вызовы (system calls)**, которые процесс выполняет, и сигналы, которые он получает.

#### Пример использования (диагностика ошибки)

Если вы выполните команду `strace ls /non_existent_directory`, вы увидите много вывода, но в конце будет ключевая строка:
```
openat(AT_FDCWD, "/non_existent_directory", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY) = -1 ENOENT (No such file or directory)
```
Это лог системного вызова `openat`, который завершился с ошибкой `ENOENT` — "Нет такого файла или каталога". `strace` наглядно показал, что именно пошло не так.

Другой пример с `cat`:
```bash
$ sudo strace -f cat ./blah
execve("/usr/bin/cat", ["cat", "./blah"], 0x7ffce4de2098 /* 16 vars */) = 0
...
openat(AT_FDCWD, "./blah", O_RDONLY)    = -1 ENOENT (No such file or directory)
write(2, "cat: ./blah: No such file or directory\n", 40) = 40
...
exit_group(1)                           = ?
+++ exited with 1 +++
```
Здесь также видно, что `openat` завершился неудачей, после чего программа вывела сообщение об ошибке и завершилась с кодом 1.

#### Основные команды

*   **Присоединиться к работающему процессу по PID:**
    ```bash
    sudo strace -p <PID>
    ```

*   **Запустить команду и отследить её, сохранив вывод в файл:**
    ```bash
    strace -o trace.log <команда>
    ```

*   **Расширенный пример для комплексной отладки:**
    ```bash
    # -f: отслеживать дочерние процессы (forks)
    # -tt: добавить микросекунды к временным меткам
    # -T: показать время, затраченное на каждый системный вызов
    # -s 200: увеличить лимит на длину выводимой строки до 200 символов
    # -e trace=...: отслеживать только определённые вызовы (например, сетевые и связанные с открытием файлов)
    sudo strace -f -ttT -s 200 -e trace=network,open -o trace.log <команда>
    ```

#### Проблемы с правами (`Operation not permitted`)

Если `strace` не работает и выдает ошибку `Operation not permitted`, возможно, система безопасности ограничивает использование системного вызова `ptrace`. Это можно проверить в файле `/proc/sys/kernel/yama/ptrace_scope`. Подробнее об этом можно прочитать в `man 2 ptrace`.

### ltrace
*   **Назначение:** Трассировка вызовов **библиотечных функций (library calls)**.
*   **Когда использовать:** Когда нужно отследить, какие функции из динамических библиотек (`.so`) вызывает приложение. Это полезно для понимания логики работы программы, когда системных вызовов недостаточно. Например, можно увидеть, какие строки приложение сравнивает с помощью `strcmp` или какие данные шифрует через OpenSSL.

### GDB (GNU Debugger)
*   **Назначение:** Полноценный интерактивный **отладчик**.
*   **Когда использовать:** Для глубокого анализа и отладки, когда нужно не просто наблюдать, а активно вмешиваться в работу процесса. GDB позволяет:
    *   Устанавливать точки останова (breakpoints).
    *   Пошагово выполнять код.
    *   Просматривать и изменять значения переменных и состояние памяти.
    *   Анализировать дампы памяти (coredumps) после сбоя приложения.

### eBPF (extended Berkeley Packet Filter)
*   **Назначение:** Динамическая трассировка и программируемый мониторинг **на уровне ядра**.
*   **Когда использовать:** Для сложных задач, требующих высокой производительности и минимального влияния на систему. `eBPF` — это не просто утилита, а целая подсистема ядра, которая позволяет безопасно выполнять пользовательский код в ядре для сбора детальной информации о системных событиях, сетевом трафике, производительности и многом другом.
*   **Подробнее:** [См. ebpf.md](./ebpf.md)
