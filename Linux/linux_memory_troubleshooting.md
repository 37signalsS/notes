# Linux: Диагностика потребления памяти процессами (`/proc/<PID>/smaps_rollup`)

Когда необходимо быстро понять, почему контейнер или сервис потребляет много памяти, не стоит полностью полагаться на утилиты вроде `top` или `htop`. Они часто показывают *виртуальную* память, что может ввести в заблуждение относительно реального потребления ресурсов.

Для более точной информации о реальном потреблении памяти процессом используйте:

```bash
cat /proc/<PID>/smaps_rollup
```

Замените `<PID>` на идентификатор процесса, который вас интересует.

### Что показывает `smaps_rollup`?

Эта команда предоставляет агрегированную информацию о памяти процесса, включая:

*   **RSS (Resident Set Size):** Реальный объем физической памяти, используемой процессом.
*   **Приватные страницы (Private):** Память, которая принадлежит только этому процессу и не используется другими. Рост этого показателя может указывать на утечки памяти в приложении.
*   **Анонимные страницы (Anonymous):** Память, которая не привязана к файлам на диске (например, куча, стек процесса).
*   **Shared страницы (Shared):** Память, которая может быть разделена между несколькими процессами (например, общие библиотеки).

### Почему это полезно?

*   **Точная диагностика:** Позволяет мгновенно увидеть, растет ли именно *приватная* память процесса. Это ключевой индикатор для выявления утечек памяти.
*   **Различение реального потребления:** Помогает понять, действительно ли процесс удерживает большой объем памяти единолично, или же значительная часть приходится на *shared*-страницы, которые распределены между несколькими процессами и не являются эксклюзивной нагрузкой.
*   **Глубокий анализ без сложных инструментов:** Предоставляет важные детали без необходимости запускать сложные инструменты профилирования.
