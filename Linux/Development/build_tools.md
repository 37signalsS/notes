# Инструменты сборки в Linux

## Кэширование компиляции с `ccache`

### Определения

`ccache` — это инструмент, который кэширует результаты компиляции исходного кода для ускорения повторных сборок.

### Основные концепции

`ccache` функционирует как "обертка" для компилятора (например, `gcc` или `clang`). При вызове он хэширует исходный файл и параметры компиляции. Если для полученного хэша в кэше уже существует скомпилированный объектный файл, `ccache` возвращает его. В противном случае вызывается реальный компилятор, и результат его работы сохраняется в кэш для будущих сборок.

### Практические сценарии

*   **Установка:**
    ```bash
    # Debian/Ubuntu
    sudo apt install ccache
    # RHEL/CentOS
    sudo dnf install ccache
    ```
*   **Интеграция и использование:**
    Для интеграции `ccache` с системой сборки (например, `make` или `cmake`), можно экспортировать переменные окружения, указывающие на `ccache` как на компилятор по умолчанию:
    ```bash
    export CC="ccache gcc"
    export CXX="ccache g++"
    ```
*   **Управление кэшем:**
    *   **Изменение директории кэша:**
        По умолчанию кэш находится в `~/.ccache`. Это можно изменить с помощью переменной окружения:
        ```bash
        export CCACHE_DIR=/path/to/cache
        ```
    *   **Просмотр статистики:**
        Для анализа эффективности кэширования (количество попаданий и промахов) используется команда:
        ```bash
        ccache -s
        ```

## Динамическая компоновка

### Определения

**Динамическая компоновка (Dynamic Linking)** — это механизм, при котором связывание программы с общими библиотеками (`.so` файлы) происходит во время ее выполнения, а не на этапе компиляции.

**Отложенная привязка (Lazy Binding)** — это техника, используемая динамическим компоновщиком (`ld.so`) для ускорения запуска программ. Разрешение адреса внешней функции откладывается до момента ее первого вызова, вместо того чтобы разрешать все символы сразу при старте.

### Основные концепции

Механизм отложенной привязки основан на двух структурах:

1.  **PLT (Procedure Linkage Table / Таблица связывания процедур):** Содержит короткие заглушки для каждой внешней функции. Первый вызов функции ведет к заглушке в PLT.
2.  **GOT (Global Offset Table / Глобальная таблица смещений):** Хранит реальные адреса символов (функций, переменных). Изначально записи для функций в GOT указывают обратно на PLT.

**Процесс работы отложенной привязки:**

1.  **Первый вызов функции:**
    1.  Программа обращается к заглушке в **PLT**.
    2.  Заглушка передает управление динамическому компоновщику (`ld.so`).
    3.  Компоновщик находит реальный адрес функции в общей библиотеке.
    4.  Найденный адрес записывается в **GOT**.
    5.  Выполняется переход на реальный адрес функции.
2.  **Последующие вызовы:**
    При повторных вызовах заглушка в PLT сразу передает управление на реальный адрес функции, который уже сохранен в GOT, что значительно быстрее.

### Дополнительная информация

*   Переменная окружения `LD_BIND_NOW=1` отключает отложенную привязку. Если она установлена, динамический компоновщик разрешит адреса всех символов при запуске программы. Это может замедлить запуск, но полезно для отладки или для приложений, где задержки во время выполнения недопустимы.
