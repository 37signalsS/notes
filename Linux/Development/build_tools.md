# Инструменты сборки в Linux

## Определения

* **GCC (GNU Compiler Collection)** — стандартный набор компиляторов в Linux для языков C, C++, Fortran и других.
* **LLVM/Clang** — современная инфраструктура компилятора и фронтенд для C-подобных языков, обеспечивающая быструю компиляцию и глубокую диагностику.
* **Make** — классическая утилита автоматизации сборки, выполняющая команды на основе графа зависимостей, описанных в `Makefile`.
* **CMake** — кроссплатформенная система генерации файлов сборки (мета-сборщик), создающая конфигурации для Make, Ninja или IDE.
* **Ninja** — небольшая и максимально быстрая система сборки, оптимизированная для инкрементальных сборок и параллельного выполнения.
* **ccache** — инструмент кэширования результатов компиляции, значительно ускоряющий повторные сборки за счет переиспользования объектных файлов.
* **Динамическая компоновка (Dynamic Linking)** — механизм связывания программы с разделяемыми библиотеками (`.so` файлы) в момент её запуска или выполнения.
* **Отложенная привязка (Lazy Binding)** — техника оптимизации, при которой реальный адрес внешней функции разрешается динамическим линковщиком только при её первом вызове.

## Основные концепции

### Этапы создания бинарного файла
1. **Препроцессинг:** Обработка макросов, включение заголовочных файлов (`#include`).
2. **Компиляция:** Перевод исходного кода в ассемблерный код.
3. **Ассемблирование:** Создание объектных файлов (`.o`), содержащих машинный код, но еще не связанных между собой.
4. **Компоновка (Линковка):** Объединение объектных файлов и библиотек в единый исполняемый файл или библиотеку.

### Иерархия систем сборки
* **Низкий уровень (Ninja):** Фокусируется только на максимально быстром выполнении команд компиляции.
* **Средний уровень (Make):** Позволяет описывать зависимости и логику сборки вручную.
* **Высокий уровень (CMake):** Позволяет описывать проект декларативно, автоматически генерируя файлы для Make или Ninja в зависимости от платформы.

### Принцип работы ccache
`ccache` перехватывает вызовы компилятора и создает уникальный хэш на основе:
* Содержимого исходного файла.
* Всех включенных заголовочных файлов.
* Флагов компиляции и версии самого компилятора.
При совпадении хэша `ccache` мгновенно подставляет готовый результат из своего хранилища, минуя стадию компиляции.

### Механизм PLT и GOT
Для реализации динамической линковки используются две таблицы:
* **PLT (Procedure Linkage Table):** Содержит короткие инструкции (заглушки) для вызова внешних функций. При первом вызове заглушка передает управление динамическому линковщику (`ld.so`).
* **GOT (Global Offset Table):** Хранит абсолютные адреса символов в памяти. После первого разрешения адреса линковщик записывает его в GOT, и последующие вызовы через PLT происходят мгновенно.

## Практические сценарии

### Настройка ccache
**Установка:**
```bash
# Debian/Ubuntu
sudo apt install ccache
# RHEL/CentOS
sudo dnf install ccache
```

**Использование с CMake:**
Рекомендуемый способ интеграции в современные проекты:
```bash
cmake -DCMAKE_C_COMPILER_LAUNCHER=ccache -DCMAKE_CXX_COMPILER_LAUNCHER=ccache ..
```

**Статистика использования:**
```bash
ccache -s
# → выводит попадания (cache hit) и промахи (cache miss)
```

### Инструменты анализа бинарников
**Просмотр зависимостей от библиотек:**
```bash
ldd /usr/bin/ls
# → список .so файлов и путей к ним в системе
```

**Анализ таблицы символов:**
```bash
nm -D /usr/lib/x86_64-linux-gnu/libssl.so.3 | grep SSL_connect
# → 00000000000456a0 T SSL_connect
```

**Проверка ELF-заголовков:**
```bash
readelf -h my_app
# → тип архитектуры, точка входа и тип бинарника (EXEC или DYN)
```

### Отладка линковки через LD_DEBUG
Переменная окружения `LD_DEBUG` заставляет динамический линковщик выводить подробные логи работы:
```bash
# Посмотреть, какие библиотеки и откуда загружаются
LD_DEBUG=libs ls

# Посмотреть процесс разрешения каждого символа (binding)
LD_DEBUG=symbols ./my_application
```

**Отключение Lazy Binding:**
Полезно для проверки наличия всех символов сразу при старте (например, в CI) или для уменьшения задержек первого вызова:
```bash
export LD_BIND_NOW=1
./my_application
```

### Пример простого Makefile
```makefile
CC = gcc
CFLAGS = -Wall -Wextra -O2
TARGET = my_app
SRCS = main.c utils.c
OBJS = $(SRCS:.c=.o)

all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(OBJS) -o $(TARGET)

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) $(TARGET)
```
