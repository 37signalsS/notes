# Инструменты сборки в Linux

## Определения

* **ccache** — инструмент, кэширующий результаты компиляции исходного кода для ускорения повторных сборок.
* **Динамическая компоновка (Dynamic Linking)** — механизм, при котором связывание программы с общими библиотеками (`.so` файлы) происходит во время ее выполнения, а не на этапе компиляции.
* **Отложенная привязка (Lazy Binding)** — техника, используемая динамическим компоновщиком (`ld.so`) для ускорения запуска программ. Разрешение адреса внешней функции откладывается до момента ее первого вызова.

## Основные концепции

### Кэширование компиляции с `ccache`

`ccache` функционирует как "обертка" для компилятора (например, `gcc` или `clang`). При вызове он хэширует исходный файл и параметры компиляции. Если для полученного хэша в кэше уже существует скомпилированный объектный файл, `ccache` возвращает его. В противном случае вызывается реальный компилятор, и результат его работы сохраняется в кэш для будущих сборок.

### Механизм динамической компоновки (PLT/GOT)

Механизм отложенной привязки основан на двух структурах:

1. **PLT (Procedure Linkage Table / Таблица связывания процедур):** Содержит короткие заглушки для каждой внешней функции. Первый вызов функции ведет к заглушке в PLT.
2. **GOT (Global Offset Table / Глобальная таблица смещений):** Хранит реальные адреса символов (функций, переменных). Изначально записи для функций в GOT указывают обратно на PLT.

**Процесс работы отложенной привязки:**

1. **Первый вызов функции:**
   1. Программа обращается к заглушке в **PLT**.
   2. Заглушка передает управление динамическому компоновщику (`ld.so`).
   3. Компоновщик находит реальный адрес функции в общей библиотеке.
   4. Найденный адрес записывается в **GOT**.
   5. Выполняется переход на реальный адрес функции.
2. **Последующие вызовы:**
   При повторных вызовах заглушка в PLT сразу передает управление на реальный адрес функции, который уже сохранен в GOT, что значительно быстрее.

## Практические сценарии

### Использование `ccache`

**Установка:**

```bash
# Debian/Ubuntu
sudo apt install ccache
# RHEL/CentOS
sudo dnf install ccache
```

**Интеграция с системами сборки (make, cmake):**
Для использования `ccache` как компилятора по умолчанию необходимо экспортировать переменные окружения:

```bash
export CC="ccache gcc"
export CXX="ccache g++"
```

**Управление кэшем:**
По умолчанию кэш находится в `~/.ccache`. Изменение директории:

```bash
export CCACHE_DIR=/path/to/cache
```

Просмотр статистики эффективности кэширования:

```bash
ccache -s
# → выводит статистику попаданий и промахов (hits/misses), размер кэша
```

### Управление динамической компоновкой

**Отключение отложенной привязки:**
Установка переменной окружения `LD_BIND_NOW` заставляет динамический компоновщик разрешить адреса всех символов при запуске программы:

```bash
export LD_BIND_NOW=1
./my_program
```

## Дополнительная информация

Отключение отложенной привязки (`LD_BIND_NOW=1`) может замедлить запуск приложения, но это полезно для отладки или для программ, где непредвиденные задержки во время выполнения недопустимы (например, в системах реального времени).
