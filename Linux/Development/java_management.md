# Управление и тюнинг Java (JVM)

## Определения

- **JVM (Java Virtual Machine):** Виртуальная машина, исполняющая Java-байт-код. Управляет памятью и ресурсами для Java-приложений.
- **Куча (Heap):** Основная область памяти, используемая JVM для хранения объектов.
- **cgroups (Control Groups):** Функция ядра Linux, используемая контейнеризаторами (например, Docker) для ограничения ресурсов (ЦП, память) контейнера.

## Базовые концепции

### Управление памятью JVM

По умолчанию JVM может попытаться занять столько памяти и CPU, сколько посчитает нужным, основываясь на ресурсах хост-системы. Если не ограничивать ресурсы явно, это может привести к нехватке памяти на сервере и аварийным завершениям (OOM).

Основные флаги для управления кучей:

- `-Xms` — определяет, сколько памяти JVM должна выделить сразу при старте.
- `-Xmx` — определяет максимум памяти, выше которого куча не вырастет. Всегда рекомендуется устанавливать этот параметр в production-средах.

Память, потребляемая JVM, состоит не только из кучи (`-Xmx`). Она также включает Metaspace, память под стеки потоков и собственную (native) память.

### Осведомленность о ресурсах контейнера

В средах контейнеризации (Docker/Kubernetes) JVM по умолчанию может видеть все ядра и всю память хоста, а не лимиты контейнера. Без дополнительных настроек она создаст лишние потоки (например, для Garbage Collector или компилятора) и будет конфликтовать за ресурсы.

Начиная с Java 11+, JVM умеет автоматически читать cgroup-лимиты контейнера.

## Практические сценарии

### Настройка лимитов для Production

Минимальный набор параметров для запуска Java-приложения в production (в том числе в контейнерах):

```bash
# -Xms: начальная память
# -Xmx: максимальная память
# -XX:ActiveProcessorCount: ограничение потоков GC и компилятора
# -XX:+UseContainerSupport: явное включение поддержки cgroups
java -Xms256m -Xmx1g -XX:ActiveProcessorCount=2 -XX:+UseContainerSupport -jar app.jar
```

### Использование переменных окружения

Для удобного управления параметрами JVM без пересборки приложения или контейнера, рекомендуется передавать их через переменные окружения, например, `JAVA_OPTS`:

```bash
export JAVA_OPTS="-Xms256m -Xmx1g -XX:ActiveProcessorCount=2 -XX:+UseContainerSupport"
java $JAVA_OPTS -jar app.jar
```
