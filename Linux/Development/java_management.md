# Управление и тюнинг Java (JVM)

## Определения

* **JVM (Java Virtual Machine):** Виртуальная машина, исполняющая Java-байт-код. Управляет памятью и ресурсами для Java-приложений.
* **JRE (Java Runtime Environment):** Среда выполнения Java, включающая JVM и стандартные библиотеки.
* **Куча (Heap):** Основная область оперативной памяти, используемая JVM для хранения объектов, создаваемых приложением. Размер задается флагами `-Xms` (начальный) и `-Xmx` (максимальный) или `-XX:MaxRAMPercentage`.
* **cgroups (Control Groups):** Функция ядра Linux, используемая системами контейнеризации (Docker, Kubernetes) для ограничения ресурсов (ЦП, память) контейнера.

## Основные концепции

### Управление памятью JVM

По умолчанию JVM может попытаться занять столько памяти и ресурсов процессора, сколько посчитает нужным, основываясь на ресурсах хост-системы. Если не ограничивать ресурсы явно, это может привести к нехватке памяти на сервере и аварийным завершениям (OOM).

Общий объем памяти, потребляемый JVM, превышает размер кучи. Он также включает:

* **Metaspace:** область для метаданных классов.
* **Стеки потоков:** память, выделяемая под каждый поток выполнения.
* **Собственная (native) память:** используется для внутренних нужд виртуальной машины.

Поэтому лимит памяти контейнера всегда должен быть больше, чем максимальный размер кучи. Рекомендуется выделять контейнеру на 25–50% больше памяти, чем настроено для кучи приложения.

### Осведомленность о ресурсах контейнера

В средах контейнеризации JVM по умолчанию может видеть все ядра и всю память хоста, а не лимиты контейнера, что приводит к созданию лишних потоков (например, для Garbage Collector или компилятора) и выделению избыточного объема памяти, вызывая OOM Killed контейнера.

* **Старые версии (до JDK 8u191 и JDK 10):** Не учитывали лимиты `cgroups`. Требуют явного указания ресурсов.
* **Современные версии (JDK 8u191+, JDK 10+):** Корректно определяют лимиты контейнера и адаптируются к ним благодаря встроенному механизму `UseContainerSupport` (включен по умолчанию в современных версиях).

## Практические сценарии

### Настройка лимитов для Production

Минимальный набор параметров для запуска Java-приложения в production (в том числе в контейнерах) для современных версий (JDK 10+):

```bash
# -XX:MaxRAMPercentage: выделение процента от доступной памяти (или лимита контейнера) под кучу
# -XX:ActiveProcessorCount: ограничение потоков GC и компилятора (полезно при отсутствии автоопределения лимитов CPU)
# -XX:+UseContainerSupport: явное включение поддержки cgroups (обычно включено по умолчанию)
java -XX:MaxRAMPercentage=75.0 -XX:ActiveProcessorCount=2 -XX:+UseContainerSupport -jar app.jar
# → Запуск приложения с кучей размером 75% от лимита памяти
```

Для старых версий (до JDK 8u191) требуется явное указание кучи в мегабайтах/гигабайтах:

```bash
# Лимит контейнера должен быть минимум 384 MB для выделенных 256 MB
java -Xms256m -Xmx256m -jar app.jar
```

### Использование переменных окружения

Для удобного управления параметрами JVM без пересборки приложения или контейнера рекомендуется передавать их через переменные окружения, например, `JAVA_OPTS` или `JAVA_TOOL_OPTIONS`:

```bash
export JAVA_OPTS="-XX:MaxRAMPercentage=75.0 -XX:ActiveProcessorCount=2 -XX:+UseContainerSupport"
java $JAVA_OPTS -jar app.jar
# → Приложение использует переданные параметры JVM
```
