# Установка и базовая настройка Nginx

Nginx — это высокопроизводительный веб-сервер, который часто используется также в качестве обратного прокси-сервера (reverse proxy), балансировщика нагрузки и HTTP-кэша.

## Установка

Установка Nginx в CentOS производится с помощью пакетного менеджера `yum` или `dnf`.

```bash
# Для CentOS 7
sudo yum install nginx

# Для CentOS 8+ и других современных RHEL-дистрибутивов
sudo dnf install nginx
```

## Управление службой и портами

После установки служба `nginx` не запускается автоматически.

1.  **Запуск службы:**
    ```bash
    sudo systemctl start nginx
    ```

2.  **Обработка конфликтов портов:**
    Если на сервере уже работает другой веб-сервер (например, Apache) на 80-м порту, Nginx не сможет запуститься. В логах (`journalctl -u nginx`) или статусе (`systemctl status nginx`) появится ошибка "Address already in use".
    
    Для решения проблемы необходимо либо остановить другой сервис, либо изменить порт для одного из них.
    ```bash
    # Остановить Apache, чтобы освободить порт для Nginx
    sudo systemctl stop httpd
    sudo systemctl start nginx
    ```

## Структура конфигурации

-   **Основной файл:** `/etc/nginx/nginx.conf`.
-   **Дополнительные конфиги:** `/etc/nginx/conf.d/*.conf`. Nginx автоматически подключает все `.conf` файлы из этой директории. Это стандартное место для размещения конфигураций виртуальных хостов (серверных блоков).

### Основные блоки в `nginx.conf`

-   **`http { ... }`**: Основной блок, определяющий параметры для HTTP-сервера.
-   **`server { ... }`**: Определяет виртуальный сервер (аналог `<VirtualHost>` в Apache).
    -   `listen 80;`: Порт, на котором слушает сервер.
    -   `server_name example.com www.example.com;`: Имена хостов, на которые будет откликаться этот серверный блок.
    -   `root /var/www/html;`: Корневой каталог для файлов сайта.
-   **`location / { ... }`**: Определяет, как обрабатывать запросы для определенного URI. `/` означает обработку всех запросов.

## Nginx как Reverse Proxy и балансировщик нагрузки

Одна из самых популярных ролей Nginx — работа в качестве обратного прокси-сервера, который принимает запросы из интернета и перенаправляет их на один или несколько внутренних серверов (бэкендов).

**Преимущества:**
-   **Балансировка нагрузки:** Распределение запросов между несколькими бэкенд-серверами для повышения производительности и отказоустойчивости.
-   **Безопасность:** Бэкенд-серверы скрыты от прямого доступа из интернета.
-   **Гибкость:** Позволяет использовать разные бэкенды для разных задач (например, Apache для PHP, Node.js для API).

### Пример: Настройка балансировки на 3 Apache-сервера

**Задача:** Настроить Nginx так, чтобы он принимал запросы на 80-м порту и поочередно перенаправлял их на три бэкенд-сервера Apache, работающих на портах 8080, 8081 и 8082.

#### 1. Определение группы бэкенд-серверов (`upstream`)

В файле `nginx.conf` (или в `conf.d/`) внутри блока `http` создается блок `upstream`, который описывает группу серверов для балансировки.

```nginx
# /etc/nginx/conf.d/default.conf

# Определяем группу бэкенд-серверов
upstream apache_backend {
    server 127.0.0.1:8080;
    server 127.0.0.1:8081;
    server 127.0.0.1:8082;
}

server {
    listen 80;

    location / {
        # Перенаправляем все запросы на нашу группу бэкендов
        proxy_pass http://apache_backend;
    }
}
```

-   **`upstream apache_backend`**: Создает именованную группу серверов.
-   **`server ...`**: Перечисляет адреса и порты бэкенд-серверов.

#### 2. Настройка проксирования (`proxy_pass`)

В блоке `location` используется директива `proxy_pass`, которая указывает Nginx перенаправить запрос на указанный `upstream`.

-   **`proxy_pass http://apache_backend;`**: Nginx возьмет запрос и отправит его на один из серверов в группе `apache_backend`.

### Метод балансировки

По умолчанию Nginx использует метод **Round Robin** (циклический перебор). Каждый новый запрос отправляется на следующий сервер в списке по очереди. Это простой, но эффективный способ равномерного распределения нагрузки.

### Обработка сбоев бэкендов

Nginx автоматически отслеживает состояние бэкенд-серверов. Если один из серверов перестает отвечать, Nginx временно исключает его из пула балансировки и перестает отправлять на него запросы. Это обеспечивает отказоустойчивость: пока работает хотя бы один бэкенд, сервис остается доступным.
