# Установка и базовая настройка Apache (httpd) в CentOS

Apache (пакет `httpd` в дистрибутивах на базе Red Hat) — это один из самых старых и проверенных веб-серверов в мире. Этот документ описывает базовую установку, поиск конфигурационных файлов и запуск сервиса.

## Установка

Установка Apache в CentOS производится с помощью пакетного менеджера `yum` или `dnf`.

```bash
# Для CentOS 7
sudo yum install httpd

# Для CentOS 8+ и других современных RHEL-дистрибутивов
sudo dnf install httpd
```
YUM/DNF автоматически разрешит все зависимости, скачает и установит пакет.

## Управление службой

После установки служба `httpd` не запускается автоматически. Для управления ею используется `systemctl`.

1.  **Проверить статус службы:**
    ```bash
    sudo systemctl status httpd
    # ● httpd.service - The Apache HTTP Server
    #    Loaded: loaded (/usr/lib/systemd/system/httpd.service; disabled; vendor preset: disabled)
    #    Active: inactive (dead)
    ```
    Статус `inactive (dead)` означает, что служба установлена, но не запущена.

2.  **Запустить службу:**
    ```bash
    sudo systemctl start httpd
    ```

3.  **Проверить, что служба слушает 80-й порт:**
    ```bash
    sudo ss -tlpn | grep httpd
    # LISTEN    0      128          *:80                   *:*      users:(("httpd",pid=...))
    ```

4.  **Включить автозапуск при загрузке системы:**
    ```bash
    sudo systemctl enable httpd
    ```

## Поиск и анализ конфигурационных файлов

Один из первых шагов после установки любого сервиса — найти его конфигурационные файлы.

1.  **Поиск процесса:**
    Можно найти запущенный процесс и посмотреть, с какими параметрами он был запущен.
    ```bash
    ps aux | grep httpd
    ```
    Однако в выводе не всегда явно указан путь к конфигурационному файлу.

2.  **Использование `man`:**
    Страницы руководства (`man`) часто содержат информацию о расположении файлов.
    ```bash
    man httpd
    ```
    В документации можно найти упоминание флага `-f`, который задает путь к конфигурационному файлу, и путь по умолчанию.

3.  **Использование `find`:**
    Зная стандартное имя файла (`httpd.conf`), можно найти его по всей системе.
    ```bash
    sudo find / -name "httpd.conf"
    ```
    Скорее всего, основной файл будет находиться в `/etc/httpd/conf/httpd.conf`.

### Структура конфигурации

-   **/etc/httpd/conf/httpd.conf**: Основной файл конфигурации.
-   **/etc/httpd/conf.d/**: Директория для дополнительных конфигурационных файлов (`.conf`). Apache автоматически подгружает все файлы из этой директории. Это стандартная практика для разделения конфигурации на логические части (например, для каждого сайта).

### Основные директивы в `httpd.conf`

-   `ServerRoot "/etc/httpd"`: Корневой каталог для конфигурации Apache.
-   `Listen 80`: Указывает, на каком порту веб-сервер должен принимать входящие соединения.
-   `User apache`, `Group apache`: Пользователь и группа, от имени которых будут работать дочерние процессы Apache.
-   `DocumentRoot "/var/www/html"`: Директория по умолчанию, из которой будут отдаваться файлы сайта.
-   `IncludeOptional conf.d/*.conf`: Директива, которая подключает все `.conf` файлы из директории `conf.d`.

### Виртуальные хосты

Для размещения нескольких сайтов на одном сервере используются **виртуальные хосты**. Конфигурация для каждого сайта обычно выносится в отдельный файл в `/etc/httpd/conf.d/`.

**Пример файла `/etc/httpd/conf.d/site1.conf`:**
```apacheconf
<VirtualHost *:8080>
    ServerName site1.example.com
    DocumentRoot /var/www/site1
</VirtualHost>
```
Чтобы Apache начал слушать дополнительный порт, необходимо также добавить директиву `Listen 8080` в основной `httpd.conf`.

### Файлы `.htaccess`

Apache позволяет делегировать часть конфигурации владельцам сайтов с помощью файлов `.htaccess`. Эти файлы размещаются в директориях сайта и могут содержать директивы, которые переопределяют или дополняют основную конфигурацию сервера для данной директории.

**Преимущество:** Разработчики могут управлять настройками (например, `mod_rewrite` для ЧПУ) без доступа к основным конфигурационным файлам сервера.
**Недостаток:** Обработка `.htaccess` на каждый запрос снижает производительность.

В отличие от Apache, Nginx не поддерживает аналог `.htaccess`. Вся конфигурация для Nginx должна быть явно прописана в основных файлах конфигурации, что делает его более производительным, но менее гибким для хостинг-сред.
