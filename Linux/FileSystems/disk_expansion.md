# Расширение дискового пространства в Linux

## Определения

**Расширение (Expansion)** — процесс увеличения емкости запоминающего устройства, который в Linux всегда состоит из двух обязательных этапов:

1. **Увеличение раздела (Partition)** — изменение границ логической области на физическом диске.
2. **Расширение файловой системы (Filesystem)** — адаптация структуры ФС под новый размер раздела.

**growpart** — утилита (часть пакета `cloud-guest-utils` или `cloud-utils-growpart`), позволяющая расширить раздел диска "на горячую" без его размонтирования.

## Основные концепции

### Порядок действий

Порядок операций критичен: **сначала раздел, потом файловая система**. Попытка расширить ФС до расширения раздела не даст результата.

### Подготовка и проверка

Перед манипуляциями крайне рекомендуется сделать резервную копию данных (snapshot, backup).

**Команды для проверки текущего состояния:**

- `lsblk` — древовидная структура (диск → раздел → PV → LV → ФС).
- `df -h` — информация о свободном месте и точках монтирования.
- `sudo fdisk -l` или `sudo parted -l` — детальная информация о таблицах разделов.
- `cat /proc/partitions` — показывает, какие разделы и какого размера **видит ядро** в данный момент. Сравнение этого вывода с `lsblk` или `fdisk` позволяет понять, применились ли изменения таблицы разделов.
- `sudo lsblk -f` — отображение типов файловых систем.

### Обновление информации о диске (Rescan)

Если диск был увеличен на уровне гипервизора (VMware, Cloud) "на горячую", ядро Linux может не сразу увидеть новый размер. Для принудительного обновления выполните:

```bash
# Для диска sda
echo 1 > /sys/class/block/sda/device/rescan
---

## Практические сценарии

### Сценарий 0: Нюанс GPT — перемещение Backup Header

При расширении физического/виртуального диска с разметкой **GPT**, резервная копия таблицы разделов (Backup Header) остается в "старом" конце диска. Утилиты разметки могут не увидеть новое пространство или выдать ошибку, так как Backup Header мешает расширению.

**Решение через `gdisk`:**
1. Запустить экспертный режим: `sudo gdisk /dev/sda`.
2. Команда `x` — expert mode.
3. Команда `e` — переместить Backup Header в новый конец диска (Relocate backup data structures to the end of the disk).
4. Команда `m` — возврат в основное меню.
5. Команда `w` — сохранение изменений.

---

### Сценарий 1: Расширение с помощью growpart (рекомендуемый)

Это самый удобный и безопасный способ расширения "на лету".

**1. Установка утилиты:**

- **Debian/Ubuntu:** `sudo apt update && sudo apt install cloud-guest-utils -y`
- **RHEL/CentOS:** `sudo yum install cloud-utils-growpart -y`

**2. Расширение раздела:**

```bash
# growpart <устройство> <номер_раздела>
sudo growpart /dev/sda 1
```

**3. Расширение файловой системы:**

- **ext4:** `sudo resize2fs /dev/sda1`
- **XFS:** `sudo xfs_growfs /` (указывается точка монтирования)

**Команда "в одну строку" (для sda1 на ext4):**

```bash
echo 1 > /sys/class/block/sda/device/rescan && growpart /dev/sda 1 && resize2fs -p /dev/sda1
```

---

### Сценарий 2: Расширение LVM-дисков

Если используется LVM, добавляется промежуточный этап обновления физического тома (PV).

1. **Расширение раздела:** `sudo growpart /dev/sda 3`
2. **Обновление PV:** `sudo pvresize /dev/sda3`
3. **Расширение LV и ФС одновременно:**

   ```bash
   sudo lvextend -l +100%FREE -r /dev/mapper/ubuntu--vg-ubuntu--lv
   ```

   *Примечание: флаг `-r` автоматически вызывает нужную утилиту для расширения ФС.*

Подробное описание операций LVM см. в [lvm_resize.md](./LVM/operations/lvm_resize.md).

---

### Сценарий 3: Расширение через fdisk (ручной способ)

Используется, если невозможно установить `growpart`. Самый рискованный способ, требует осторожности.

1. Запустить: `fdisk /dev/sda`
2. Команда `p` — запомнить **начальный сектор** (Start sector) нужного раздела.
3. Команда `d` — удалить раздел.
4. Команда `n` — создать раздел заново.
   - Выбрать тот же номер раздела.
   - **Указать тот же начальный сектор!**
   - Конечный сектор — по умолчанию (до конца диска).
5. При вопросе "Remove signature?" ответить **N** (No), чтобы не потерять данные.
6. Команда `w` — сохранить изменения.
7. Обновить таблицу разделов: `sudo partprobe /dev/sda` (принуждает ядро перечитать таблицу без перезагрузки).
8. Проверить результат: `cat /proc/partitions`.
9. Расширить ФС: `resize2fs /dev/sda2`.

---

### Сценарий 4: Расширение через parted

Альтернатива для GPT-дисков и разделов более 2 ТБ.

1. Запустить: `parted /dev/sda`
2. Просмотр: `print`
3. Расширение: `resizepart <номер_раздела>`
   - Указать конечную точку (End), например `100%`.
4. Выход: `quit`
5. Обновление: `partprobe`
6. Расширение ФС: `resize2fs /dev/sda2` или `xfs_growfs /`.
