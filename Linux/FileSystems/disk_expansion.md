# Расширение дискового пространства в Linux

## Определения

- **Расширение (Expansion):** Комплексный процесс увеличения доступной емкости запоминающего устройства, затрагивающий несколько уровней абстракции ОС.
- **growpart:** Утилита из пакета `cloud-guest-utils`, предназначенная для безопасного расширения раздела диска до границ физического носителя в режиме онлайн.
- **Rescan:** Операция принудительного уведомления ядра Linux об изменении размера блочного устройства (актуально для виртуальных дисков и облачных хранилищ).
- **Файловая система (FileSystem, ФС):** Финальный слой расширения, позволяющий ОС использовать новое пространство внутри контейнера (раздела или тома).

## Основные концепции

### Иерархия уровней расширения

Процесс всегда выполняется строго «снизу вверх». Пропуск любого этапа приведет к тому, что операционная система не увидит новый объем.

1.  **Физический/Виртуальный уровень:** Увеличение диска в гипервизоре или замена физического накопителя.
2.  **Уровень ядра (Device Scanning):** Обнаружение нового размера ядром через `rescan`.
3.  **Уровень разделов (Partitioning):** Изменение границ раздела в таблице MBR или GPT.
4.  **Уровень LVM (опционально):** Адаптация Physical Volume (PV), Volume Group (VG) и Logical Volume (LV).
5.  **Уровень ФС:** Расширение структур метаданных файловой системы.

### Приоритет безопасности

- **Резервное копирование:** Перед изменением таблицы разделов или ФС обязателен снапшот или бэкап.
- **Онлайн-операции:** Большинство современных инструментов (`growpart`, `resize2fs`, `xfs_growfs`) поддерживают работу на смонтированных ФС.
- **Верификация:** Используйте `lsblk -f` для контроля изменений на каждом этапе.

## Практические сценарии

### 1. Пересканирование диска (Rescan)

Если размер диска был изменен «на горячую», ядро может не обновить данные автоматически.

```bash
# Обновление информации для диска sda
echo 1 | sudo tee /sys/class/block/sda/device/rescan

# Для всех SCSI-устройств (требует пакета sg3_utils)
sudo rescan-scsi-bus.sh
```

### 2. Исправление GPT Backup Header

При расширении диска с разметкой GPT вторичная (резервная) таблица остается в середине диска, что блокирует расширение последнего раздела.

```bash
# Использование gdisk для перемещения структур в новый конец диска
sudo gdisk /dev/sda
# Последовательность: x (expert) -> e (relocate backup structures) -> w (write)
```

### 3. Расширение раздела и ФС через growpart

Самый универсальный и безопасный метод.

```bash
# 1. Расширить раздел 2 на диске sdb
sudo growpart /dev/sdb 2

# 2. Адаптация конкретной ФС:
# Для ext4 (указывается устройство):
sudo resize2fs /dev/sdb2

# Для XFS (указывается точка монтирования):
sudo xfs_growfs /mnt/data

# Для Btrfs (указывается путь):
sudo btrfs filesystem resize max /mnt/btrfs
```

### 4. Расширение раздела подкачки (Swap)

Если Swap представлен разделом, его расширение требует временного отключения.

```bash
sudo swapoff /dev/sdXN
sudo growpart /dev/sdX 1
sudo mkswap /dev/sdXN
sudo swapon /dev/sdXN
```

### 5. Особенности расширения в LVM

LVM абстрагирует ФС от физических разделов, что упрощает процесс.

```bash
# 1. Обновить размер PV после расширения раздела
sudo pvresize /dev/sda3

# 2. Расширить LV на всё доступное место в VG с автоматическим расширением ФС
sudo lvextend -l +100%FREE -r /dev/mapper/vg0-lv_root
```
*Примечание: Флаг `-r` автоматически вызывает `resize2fs` или `xfs_growfs`.*

### 6. Ручное расширение через fdisk (Risky)

Применяется в критических случаях, если `growpart` недоступен.
1. Запустить `fdisk`.
2. Запомнить **Start Sector** раздела.
3. Удалить раздел (`d`).
4. Создать новый (`n`) с тем же номером и тем же **Start Sector**.
5. На вопрос «Remove signature?» ответить **N** (No).
6. Сохранить (`w`) и выполнить `sudo partprobe`.

## Верификация и диагностика

- **`lsblk -f`:** Показывает иерархию, типы ФС и использование места (FSSUSE%).
- **`xfs_info /mnt/path`:** Детальная информация о блоках XFS.
- **`df -hT`:** Итоговая проверка доступного места в ОС.
