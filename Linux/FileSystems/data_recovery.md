# Логическое восстановление данных

## Определения

- **Логическое восстановление данных:** Процесс извлечения и восстановления файлов или ФС (Файловых Систем), потерянных из-за программных ошибок, случайного удаления, форматирования или логического повреждения структур данных, при условии физической исправности носителя.
- **Carving (Карвинг):** Метод восстановления данных, основанный на поиске известных сигнатур (заголовков и футеров) файлов в «сыром» потоке байтов, полностью игнорируя метаданные файловой системы.
- **TRIM (Discard):** Команда интерфейса ATA, позволяющая ОС информировать SSD о том, какие блоки данных больше не содержат полезной информации (например, после удаления файла). После выполнения TRIM данные физически обнуляются контроллером SSD, что делает восстановление невозможным.
- **Дескриптор файла (File Descriptor):** Абстрактный указатель (целое число), используемый процессом для доступа к открытому файлу. Если файл удалён с диска, но дескриптор открыт, данные остаются доступными через `/proc`.

## Основные концепции

### Золотые правила восстановления

1.  **Стоп-запись:** Немедленно прекратите любую запись на носитель. Любая операция записи (включая автоматические логи системы) может перезаписать блоки, помеченные как свободные.
2.  **Режим Read-Only:** Всегда монтируйте повреждённый раздел в режиме «только чтение» или работайте с размонтированным устройством:
    ```bash
    mount -o remount,ro /dev/sdb1
    ```
3.  **Принцип образа:** Никогда не проводите эксперименты на оригинальном носителе. Создайте посекторную копию (образ) и работайте с ней.
4.  **Восстановление «вовне»:** Всегда сохраняйте восстановленные данные на **другой** физический накопитель.

### Влияние типа носителя и ФС

- **SSD против HDD:** На современных SSD с включенным TRIM восстановление удалённых файлов практически невозможно, так как контроллер очищает ячейки памяти в фоновом режиме сразу после команды `unlink`.
- **RAID-массивы:** Восстановление данных с RAID требует предварительной сборки массива (через `mdadm` или программные эмуляторы) и только после этого — применения инструментов логического восстановления.
- **Тип ФС:**
  - **Ext3/Ext4:** Хорошо поддаются восстановлению через анализ журнала.
  - **XFS:** Сложна в восстановлении из-за разреженной структуры и динамического выделения Inode.
  - **Btrfs:** Имеет встроенные инструменты для «отката» и восстановления из неповрежденных деревьев.

## Практические сценарии

### 1. Восстановление файла, открытого процессом

Если файл был удалён из ФС (например, случайным `rm`), но процесс (база данных, логгер, веб-сервер) всё ещё удерживает его дескриптор.

**Шаги восстановления:**
1.  **Поиск PID и FD:**
    ```bash
    # Поиск процесса по имени файла или через lsof
    lsof +L1 | grep "deleted"
    # → nginx  1234  root  4r  REG  8,1  1024  45678 /var/log/nginx/access.log (deleted)
    ```
    Здесь `1234` — PID, `4` — номер дескриптора (FD).
2.  **Извлечение данных из /proc:**
    ```bash
    cp /proc/1234/fd/4 /mnt/recovery/access.log.restored
    ```

### 2. Восстановление разделов через TestDisk

**TestDisk** — стандарт для восстановления таблиц разделов (MBR/GPT) и исправления загрузочных секторов.

1.  Запуск: `sudo testdisk /dev/sdb`.
2.  Выбор `Analyse` → `Quick Search`.
3.  Если разделы найдены, используйте `P` для просмотра файлов и `C` для их копирования на другой диск перед записью новой таблицы разделов.

### 3. Файлоспецифичные инструменты

#### Ext4 (extundelete и debugfs)
`extundelete` автоматически анализирует журнал и пытается восстановить дерево каталогов.
```bash
# Восстановление всей директории
extundelete /dev/sdb1 --restore-directory /home/user/docs
```
`debugfs` позволяет вручную исследовать Inode:
```bash
debugfs -R "lsdel" /dev/sdb1  # Список недавно удаленных Inode
```

#### Btrfs (btrfs restore)
Позволяет копировать файлы с поврежденной ФС, которая не монтируется.
```bash
btrfs restore /dev/sdb1 /mnt/external_recovery
```

#### XFS (xfs_db)
В XFS нет надежного способа «отменить удаление» (undelete), но можно попытаться найти фрагменты данных через `xfs_db` в экспертном режиме.

### 4. Data Carving (PhotoRec, Foremost, Scalpel)

Если метаданные ФС полностью уничтожены (после форматирования), используются карверы.

- **PhotoRec:** Интерактивный и мощный, поддерживает сотни типов файлов.
  ```bash
  photorec /dev/sdb1
  ```
- **Foremost:** Консольная утилита от спецслужб США (OSI). Работает по конфигу сигнатур.
  ```bash
  foremost -i /dev/sdb1 -o /mnt/recovery/foremost
  ```
- **Scalpel:** Более производительный форк Foremost, оптимизированный для больших дисков.

### 5. Создание образов (dd и ddrescue)

Для работы с «умирающими» дисками (битые сектора) обычный `dd` не подходит, так как он зависает на ошибках.

- **GNU ddrescue:** Лучший инструмент для спасения данных. Он копирует сначала целые блоки, а затем пытается многократно вычитать поврежденные.
  ```bash
  # mapfile нужен для возобновления работы при прерывании
  ddrescue -d -r3 /dev/sdb /mnt/recovery/disk.img /mnt/recovery/rescue.log
  ```
