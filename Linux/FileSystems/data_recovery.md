# Логическое восстановление данных

## Определения

- **Логическое восстановление данных:** Процесс извлечения и восстановления файлов или ФС (Файловых Систем), потерянных из-за программных ошибок, случайного удаления, форматирования или логического повреждения структур данных, при условии физической исправности носителя.
- **Carving (Карвинг):** Метод восстановления данных, основанный на поиске известных сигнатур (заголовков) файлов в сыром потоке байтов, игнорируя метаданные файловой системы.
- **Дескриптор файла (File Descriptor):** Абстрактный указатель, используемый процессом для доступа к открытому файлу.

## Основные концепции

- **Первое правило:** Немедленно прекратить запись на раздел, где находились удалённые данные. Любая операция записи может перезаписать блоки данных, которые помечены как свободные, но всё ещё содержат полезную информацию.
- **Приоритет действий при инциденте:**
  - На работающей системе: остановить сервисы, активно пишущие на диск (базы данных, логи).
  - Размонтировать ФС (`umount`) или перевести её в режим "только чтение":

    ```bash
    mount -o remount,ro /dev/sdb1
    ```

- **Работа с образом:** Всегда восстанавливайте данные на **другой** физический носитель. Рекомендуется сначала создать посекторную копию (образ) повреждённого раздела с помощью [утилиты `dd`](./dd.md) и проводить восстановление, работая с этим образом.

## Практические сценарии

### 1. Восстановление файла, открытого процессом

Если файл был удалён из ФС (например, случайным `rm`), но процесс (например, Nginx) всё ещё удерживает его дескриптор, данные фактически остаются на диске, пока процесс не закроет файл или не завершится.

**Пример: Восстановление `nginx.conf`**

1. Найти PID (Process Identifier, идентификатор процесса) и номер FD (File Descriptor, дескриптор файла):

   ```bash
   # Ищем процесс nginx и удаленные файлы, которые он удерживает
   lsof -n | grep nginx | grep deleted
   
   # → nginx  1234  root  4r  REG  8,1  1024  45678 /etc/nginx/nginx.conf (deleted)
   ```

2. Скопировать содержимое файла из виртуальной ФС `/proc`:

   ```bash
   # Где 1234 — PID процесса, а 4 — номер дескриптора (из столбца FD в lsof)
   sudo cp /proc/1234/fd/4 /etc/nginx/nginx.conf
   ```

3. Проверить восстановленный файл и перезагрузить конфигурацию:

   ```bash
   nginx -t && systemctl reload nginx
   ```

### 2. Восстановление разделов и файлов через TestDisk

**TestDisk** — мощный интерактивный инструмент для восстановления потерянных разделов и исправления таблиц разделов.

1. Запуск: `sudo testdisk /dev/sdb` (укажите устройство целиком).
2. Выбор типа таблицы разделов (обычно Intel или EFI GPT).
3. Навигация: `Analyse` → `Quick Search`.
4. Для восстановления файлов: после сканирования можно нажать `P` для просмотра списка файлов (удалённые файлы часто выделены красным) и `C` для их копирования на другой диск.

### 3. Восстановление через extundelete (для ext3/ext4)

Специализированная утилита для восстановления данных на ФС семейства ext, использующая информацию из журнала.

```bash
# Восстановить конкретный файл по его пути внутри ФС
extundelete /dev/sdb1 --restore-file /path/to/deleted/file

# Восстановить все удалённые файлы в указанной директории
extundelete /dev/sdb1 --restore-directory /path/to/dir
```

### 4. Создание образа раздела

Если прямое восстановление затруднено, необходимо снять образ для безопасных экспериментов.

```bash
# Использование dd для создания образа (подробнее см. dd.md)
dd if=/dev/sdb1 of=/mnt/backup/disk.img bs=4M status=progress
```

### 5. Поиск по сигнатурам через PhotoRec

**PhotoRec** входит в состав TestDisk и специализируется на восстановлении файлов (медиа, документы, архивы) по их внутренним сигнатурам. Инструмент игнорирует метаданные ФС, поэтому эффективен даже после форматирования.

1. Запуск: `sudo photorec /dev/sdb1`.
2. Выбор типа ФС (для Linux — `ext2/ext3/ext4`).
3. Выбор области поиска (`Free` — только свободное место, `Whole` — весь раздел).

## Дополнительная информация

- **Btrfs:** Инструмент `btrfs restore` позволяет копировать файлы с ФС, которую невозможно смонтировать обычным способом.
- **XFS:** Утилита `xfs_repair` в основном исправляет структуру ФС, возможности восстановления именно удалённых файлов в XFS крайне ограничены.
