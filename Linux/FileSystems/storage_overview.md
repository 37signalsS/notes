# Управление хранилищами в Linux: Обзор

## Определения

- **Блочное устройство (Block Device):** Низкоуровневая абстракция накопителя в ядре Linux, оперирующая данными в виде блоков фиксированного размера и поддерживающая произвольный доступ. Примеры: HDD (`sda`), SSD (`sdb`), NVMe (`nvme0n1`), LVM-тома. Подробнее см. в **[Типы устройств: блочные и символьные](./device_types.md)**.
- **Слой Device Mapper:** Фреймворк ядра, позволяющий создавать виртуальные блочные устройства поверх физических (LVM, LUKS, Multipath).
- **Файловая система (FileSystem):** Логическая структура (`ext4`, `XFS`, `Btrfs`), определяющая способ хранения и организации файлов на блочном устройстве. Подробнее см. в **[Внутреннее устройство ФС](./fs_internals.md)**.
- **Монтирование (Mounting):** Процесс связывания файловой системы с точкой в иерархии каталогов VFS. Подробнее см. в **[Основы монтирования](./mounting/index.md)**.
- **Раздел (Partition):** Логически выделенная область на физическом диске, воспринимаемая ОС как отдельное блочное устройство. Границы описываются в таблице разделов (MBR или GPT).
- **RAID (Redundant Array of Independent Disks):** Технология объединения нескольких физических дисков в логический массив для повышения производительности или отказоустойчивости. Реализуется через `mdadm` (программный) или аппаратные контроллеры.
- **LUN (Logical Unit Number):** Логический номер блочного устройства в сетевых хранилищах (SAN, iSCSI). Для операционной системы выглядит как обычный диск.
- **LBA (Logical Block Addressing):** Метод адресации секторов на диске, при котором каждому сектору присваивается уникальный порядковый номер.
- **Сектор (Sector):** Минимальная физическая единица хранения на диске. Традиционно 512 байт, современные диски используют 4 КБ (Advanced Format).
- **Блок (Block):** Логическая единица данных, которой оперирует файловая система (обычно 4 КБ).
- **Выравнивание (Alignment):** Требование, чтобы границы раздела совпадали с границами физических секторов диска. Неправильное выравнивание вызывает Read-Modify-Write и снижает производительность.
- **Барьер записи (Write Barrier):** Гарантия ядра, что данные и метаданные фиксированы на диске в правильном порядке. Критичен для журналируемых ФС при отсутствии BBU.
- **Журналирование (Journaling):** Механизм обеспечения атомарности операций ФС. Изменения сначала записываются в журнал (WAL), а затем применяются к основным структурам.
- **Тонкое провизионирование (Thin Provisioning):** Технология выделения пространства из пула по мере записи данных, а не сразу при создании тома. Риск: переполнение пула (OOS).
- **Снапшот (Snapshot):** Точка во времени состояния тома или ФС, основанная на Copy-on-Write (CoW).
- **Глубина очереди (Queue Depth):** Количество запросов I/O, которые устройство или драйвер могут обрабатывать одновременно. NVMe поддерживает десятки тысяч очередей.
- **IOPS (Input/Output Operations Per Second):** Количество операций ввода-вывода в секунду. Ключевая метрика для транзакционных нагрузок.
- **Пропускная способность (Throughput):** Объем данных, передаваемый в единицу времени (MB/s, GB/s).
- **Задержка (Latency):** Время выполнения одной операции I/O (от отправки запроса до подтверждения).

## Архитектура хранения

Управление данными в Linux строится по принципу многоуровневой абстракции, где каждый слой добавляет функциональность или упрощает управление.

### Уровни абстракции (Storage Stack)

1. **Физический уровень (Hardware):** Контроллеры (SATA, SAS, NVMe) и накопители.
2. **Драйверы устройств:** Уровень ядра, обеспечивающий связь с оборудованием (`sd`, `nvme`).
3. **Блочный слой ядра (Block Layer):**
   - **I/O Schedulers:** Планировщики (`mq-deadline`, `kyber`, `none`), оптимизирующие порядок выполнения запросов к диску.
   - **Buffer Cache:** Кэширование блоков данных в RAM.
4. **Уровень виртуализации (опционально):**
   - **MD RAID:** Программные массивы.
   - **DM (Device Mapper):** LVM, LUKS (шифрование), Thin Provisioning.
5. **Файловая система:** Организация файлов и метаданных.
6. **VFS (Virtual File System):** Единый интерфейс доступа к файлам для приложений.

### Поток данных I/O

Запись данных от приложения к диску проходит через все уровни стека:

```
Приложение (write())
    ↓
VFS (sys_write → file_operations)
    ↓
Драйвер ФС (ext4_file_write, xfs_file_write)
    ↓
Page Cache (кэширование страниц)
    ↓
Writeback (kworker/flusher → сброс dirty pages)
    ↓
Block Layer (bio → request queue → I/O scheduler)
    ↓
Драйвер блочного устройства (sd, nvme, dm-X)
    ↓
Контроллер диска (SATA/SAS/NVMe)
    ↓
Физический носитель (NAND/пластина)
```

На чтении данных при Cache Miss происходит обратный путь, но с обращением к Page Cache на стороне чтения.

### Идентификация устройств

Использование имен вроде `/dev/sda` ненадежно, так как они могут измениться при перезагрузке или смене порта. В SRE-практике используются постоянные идентификаторы:
- **UUID:** Уникальный идентификатор файловой системы (хранится в её метаданных).
- **PARTUUID:** Идентификатор раздела (хранится в таблице разделов GPT).
- **WWN (World Wide Name):** Уникальный заводской номер физического накопителя.
- **LABELS:** Человекочитаемые метки (например, `DATA_DRIVE`).

Подробное объяснение разницы между UUID и PARTUUID, их изменение при пересоздании ФС и влияние на загрузку — в [Разделы и файловые системы](./partitions_and_filesystems.md#UUID-vs-PARTUUID-ключевое-различие).

## Типы носителей и их архитектура

### Сравнение: HDD / SSD / NVMe

| Критерий | HDD (CMR) | SATA SSD | NVMe SSD |
| :--- | :--- | :--- | :--- |
| **Скорость чтения** | 80–160 MB/s | 500–560 MB/s | 3,500–7,500 MB/s |
| **Случайное чтение 4K (IOPS)** | 80–120 | 50k–100k | 200k–700k |
| **Задержка (latency)** | 5–10 мс | 50–100 мкс | 10–50 мкс |
| **Ресурс (P/E-циклы)** | N/A (механический) | 1k–10k (TLC) | 1k–10k (TLC) |
| **Максимальный TBW (1 ТБ)** | N/A | 600–3,000 TBW | 600–5,000 TBW |
| **Чувствительность к вибрации** | Высокая | Средняя | Низкая |
| **Потребление энергии** | 6–9 Вт (работа) | 2–4 Вт | 5–10 Вт (пик) |
| **Стоимость за 1 ГБ** | Низкая | Средняя | Высокая |
| **Рекомендуемое применение** | Архивы, логи, cold storage | Базы данных, виртуализация | Высоконагруженные БД, кэши, аналитика |

### Архитектурные особенности NVMe

В отличие от SATA (одна очередь на 32 запроса), NVMe использует архитектуру **blk-mq** с множественными парами очередей (Queue Pairs), привязанными к ядрам CPU. Это обеспечивает параллелизм до 64K очередей и минимальную задержку.

### Write Amplification и износ SSD

**Усиление записи (WA)** — отношение физических операций записи на NAND к логическим от хоста. Факторы:
- **Garbage Collection** (GC): перемещение валидных страниц при очистке блока.
- **SLC-кэш**: эмуляция SLC-режима для burst-производительности, после заполнения которой происходит падение до steady state.
- **Фрагментация**: CoW-ФС (Btrfs, ZFS) увеличивают WA из-за копирования блоков при изменении.

Для SRE важно: WA напрямую сокращает ресурс SSD (TBW) и может вызывать всплески задержки.

## Логическая организация хранилища

### Слои абстракции

```
┌──────────────────────────────────────────────────────┐
│  Приложение / Файловая система (ext4, XFS, Btrfs)   │
├──────────────────────────────────────────────────────┤
│  Уровень виртуализации (опционально)                  │
│  ├── LVM (LV → VG → PV)                              │
│  ├── LUKS (шифрование)                                │
│  ├── Stratis (pool → filesystem)                      │
│  └── MD RAID (mdadm)                                  │
├──────────────────────────────────────────────────────┤
│  Блочный слой ядра (Block Layer + Scheduler)          │
├──────────────────────────────────────────────────────┤
│  Драйвер устройства (sd, nvme, dm-X)                  │
├──────────────────────────────────────────────────────┤
│  Контроллер и физический носитель                     │
└──────────────────────────────────────────────────────┘
```

### Ключевые технологии

- **Partitioning:** Разделение диска на логические области (MBR/GPT). См. [Разделы и файловые системы](./partitions_and_filesystems.md).
- **RAID (mdadm):** Объединение дисков в массивы для отказоустойчивости или производительности. См. [Обзор RAID и mdadm](./RAID/overview.md).
- **LVM:** Гибкое управление томами с онлайн-расширением и снапшотами. См. [LVM — Обзор и основные концепции](./LVM/overview_concepts.md).
- **Stratis:** Высокоуровневый менеджер хранилищ на основе XFS и Device Mapper. См. [Stratis](./stratis.md).
- **LUKS:** Шифрование дисков на уровне блоков через Device Mapper.

## Производительность и тюнинг

### Выравнивание разделов

Современные диски используют физические сектора 4 КБ (Advanced Format). Если раздел начинается не с границы 4 КБ, операция записи ФС (4 КБ) затрагивает два физических сектора, вызывая Read-Modify-Write. 

**Решение:** Начинать разделы с сектора 2048 (1 МиБ), что кратно любому размеру блока.

### Планировщики I/O

| Тип диска | Рекомендуемый планировщик | Обоснование |
| :--- | :--- | :--- |
| NVMe | `none` (noop) | Аппаратная многопоточность, минимизация задержек ядра |
| SATA SSD / SAS SSD | `mq-deadline` | Баланс между latency и throughput |
| HDD (интерактивная) | `bfq` | Справедливое распределение между процессами |
| HDD (сервер / bulk) | `mq-deadline` | Предсказуемость и группировка запросов |

### Бенчмаркинг

Для измерения производительности используется `fio` (Flexible I/O Tester). Ключевые метрики:
- **IOPS:** количество операций в секунду (критично для СУБД).
- **Throughput:** пропускная способность (MB/s).
- **Latency:** задержка операций (p50, p95, p99).

Для мониторинга в реальном времени используется `iostat` из пакета `sysstat`. Подробнее см.:
- [fio — бенчмаркинг хранилища](../Diagnostics/Filesystem/fio.md)
- [iostat — статистика ввода-вывода](../Diagnostics/Filesystem/iostat.md)

## Мониторинг здоровья

### S.M.A.R.T. и накопители

`smartctl` — основной инструмент для диагностики здоровья дисков. Мониторинг включает:
- **Состояние здоровья:** `smartctl -H` (PASSED/FAILED).
- **Процент износа:** `Percentage Used` (NVMe) или `Media_Wearout_Indicator` (SATA).
- **Температура:** алерты при >70°C для SSD.
- **Переназначенные сектора:** рост `Reallocated_Sector_Ct` (ID 5) означает деградацию.

Для автоматического мониторинга используется `smartd`. Подробнее см. [Диагностика дисков (smartctl)](../Diagnostics/Hardware/smartctl/index.md).

### Мониторинг LVM и RAID

- **LVM:** `pvs`, `vgs`, `lvs` для проверки свободного места; `lvm2-monitor` (`dmeventd`) для автоматических реакций.
- **RAID:** `cat /proc/mdstat` и `mdadm --detail` для проверки статуса массива; `mdadm --monitor` для уведомлений.

## Диагностика и устранение неполадок

### Иерархия диагностики (Сверху вниз)

1. **Общая оценка:** Влияет ли I/O на отзывчивость системы? (`iostat -xz 1`, `vmstat 1`).
2. **Уровень устройств:** Какой диск перегружен? (`iostat`, `lsblk`).
3. **Уровень ФС:** Проблема в файловой системе? (`df -hT`, `df -i`, `dmesg | grep -i ext4`).
4. **Уровень приложения:** Какой процесс генерирует нагрузку? (`iotop -o`, `pidstat -d 1`).

### Типичные проблемы

| Симптом | Возможная причина | Диагностика | Решение |
| :--- | :--- | :--- | :--- |
| Высокий `await` на диске | Перегрузка диска или очередь запросов | `iostat -xz 1` | Добавить диски, сменить scheduler, проверить `aqu-sz` |
| `df` показывает 100%, `du` показывает 50% | Удаленные, но открытые файлы | `sudo lsof +L1` | Перезапуск процесса или truncate через `/proc/PID/fd/FD` |
| ФС в режиме `read-only` | Аппаратная ошибка I/O или aborted journal | `dmesg`, `blockdev --getro` | Замена кабеля/диска, `mount -o remount,rw` |
| Высокий `Dirty` без записи | Writeback stalled | `iostat`, `vm.dirty_ratio` | Уменьшить `vm.dirty_ratio`, проверить `iostat` |
| Исчерпание inodes | Мелкие файлы (кэши, очереди) | `df -i` | Удаление мелких файлов или пересоздание ФС |

### Проверка перед операциями

Перед любым изменением конфигурации хранилища выполните:
```bash
# 1. Проверка смонтированных ФС и опций
findmnt -D

# 2. Проверка свободного места и inodes
df -hT
df -i

# 3. Проверка состояния дисков
sudo smartctl -H /dev/sdX

# 4. Проверка ошибок ядра
sudo dmesg -T | grep -Ei 'error|fail|I/O'
```

## Практические сценарии

### 1. Подготовка нового диска к работе

Классический цикл подготовки нового накопителя в системе:

```bash
# 1. Поиск устройства (допустим, нашли /dev/sdb)
lsblk

# 2. Удаление старых метаданных (если диск не новый)
# ОСТОРОЖНО: Это уничтожит данные о ФС!
sudo wipefs -a /dev/sdb

# 3. Разметка диска (GPT)
# Создаем один раздел на весь диск с выравниванием 1 MiB
sudo parted /dev/sdb mklabel gpt mkpart primary ext4 0% 100%

# 4. Создание файловой системы (XFS — стандарт для RHEL/CentOS)
sudo mkfs.xfs -L DATA_DRIVE /dev/sdb1

# 5. Получение UUID для fstab
blkid /dev/sdb1

# 6. Настройка fstab (используйте UUID или stable path)
# UUID=... /mnt/data xfs defaults,noatime 0 2
```

### 2. Работа с современными NVMe-накопителями

NVMe используют другой стек и именование (`/dev/nvme0n1`). Для управления используется утилита `nvme-cli`.

```bash
# Просмотр списка NVMe устройств
sudo nvme list

# Получение SMART-логов (температура, ресурс)
sudo nvme smart-log /dev/nvme0

# Проверка температур и износа
sudo nvme smart-log /dev/nvme0 | grep -E 'temperature|percentage_used|available_spare'
```

### 3. Шифрование LUKS (Device Mapper)

Шифрование данных «в покое» (Data at Rest) с использованием LUKS.

```bash
# Инициализация шифрования
sudo cryptsetup luksFormat /dev/sdb1

# Открытие контейнера (создает /dev/mapper/secure_data)
sudo cryptsetup luksOpen /dev/sdb1 secure_data

# Создание ФС внутри защищенного слоя
sudo mkfs.ext4 /dev/mapper/secure_data
```

### 4. Бенчмаркинг производительности

Для оценки производительности хранилища используется `fio`:

```bash
# Последовательная запись (throughput)
fio --name=seq_write --rw=write --bs=1M --size=10G --filename=/dev/sdb \
    --ioengine=io_uring --direct=1 --group_reporting

# Случайное чтение 4K (IOPS)
fio --name=rand_read --rw=randread --bs=4k --size=4G --filename=./testfile \
    --ioengine=io_uring --direct=1 --iodepth=64 --numjobs=4 --runtime=60 --time_based
```

### 5. Комплексная проверка здоровья хранилища

Для SRE важно регулярно проверять состояние всех компонентов:

```bash
# 1. Топология устройств
lsblk -f -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,MODEL,SERIAL,ROTA

# 2. Состояние SMART для всех дисков
sudo smartctl --scan | while read -r dev; do
    echo "=== $dev ==="
    sudo smartctl -H "$dev"
done

# 3. Производительность дисков
iostat -xz 1 3

# 4. Ошибки ядра
sudo dmesg -T | grep -Ei 'EXT4|XFS|I/O error|Buffer I/O|read-only|abort'
```

### 6. Замена диска в RAID-массиве

Общий алгоритм замены вышедшего из строя диска:

```bash
# 1. Определить сбойный диск
cat /proc/mdstat
# → [_U] означает деградацию

# 2. Пометка failed и удаление
sudo mdadm /dev/md0 --fail /dev/sdb1
sudo mdadm /dev/md0 --remove /dev/sdb1

# 3. Установка нового диска и добавление в массив
sudo mdadm /dev/md0 --add /dev/sdc1

# 4. Мониторинг восстановления
watch cat /proc/mdstat
```

### 7. Безопасное уничтожение данных

Для HDD: полная затирка через `dd` или `shred`.
Для SSD/NVMe: `blkdiscard` (TRIM всего устройства) или `nvme format`.

```bash
# SSD/NVMe: безопасный discard
sudo blkdiscard /dev/nvme0n1

# HDD: затирка нулями
sudo dd if=/dev/zero of=/dev/sdX bs=4M status=progress conv=fdatasync
```
