# Управление хранилищами в Linux: Обзор

## Определения

- **Блочное устройство (Block Device):** Низкоуровневая абстракция накопителя в ядре Linux, оперирующая данными в виде блоков фиксированного размера и поддерживающая произвольный доступ. Примеры: HDD (`sda`), SSD (`sdb`), NVMe (`nvme0n1`), LVM-тома. Подробнее см. в **[Типы устройств: блочные и символьные](./device_types.md)**.
- **Слой Device Mapper:** Фреймворк ядра, позволяющий создавать виртуальные блочные устройства поверх физических (LVM, LUKS, Multipath).
- **Файловая система (FileSystem):** Логическая структура (`ext4`, `XFS`, `Btrfs`), определяющая способ хранения и организации файлов на блочном устройстве. Подробнее см. в **[Внутреннее устройство ФС](./fs_internals.md)**.
- **Монтирование (Mounting):** Процесс связывания файловой системы с точкой в иерархии каталогов VFS. Подробнее см. в **[Основы монтирования](./mounting/index.md)**.

## Архитектура хранения

Управление данными в Linux строится по принципу многоуровневой абстракции, где каждый слой добавляет функциональность или упрощает управление.

### Уровни абстракции (Storage Stack)

1.  **Физический уровень (Hardware):** Контроллеры (SATA, SAS, NVMe) и накопители.
2.  **Драйверы устройств:** Уровень ядра, обеспечивающий связь с оборудованием (`sd`, `nvme`).
3.  **Блочный слой ядра (Block Layer):**
    - **I/O Schedulers:** Планировщики (`mq-deadline`, `kyber`, `none`), оптимизирующие порядок выполнения запросов к диску.
    - **Buffer Cache:** Кэширование блоков данных в RAM.
4.  **Уровень виртуализации (опционально):**
    - **MD RAID:** Программные массивы.
    - **DM (Device Mapper):** LVM, LUKS (шифрование), Thin Provisioning.
5.  **Файловая система:** Организация файлов и метаданных.
6.  **VFS (Virtual File System):** Единый интерфейс доступа к файлам для приложений.

### Идентификация устройств

Использование имен вроде `/dev/sda` ненадежно, так как они могут измениться при перезагрузке или смене порта. В SRE-практике используются постоянные идентификаторы:
- **UUID:** Уникальный идентификатор файловой системы (хранится в ее метаданных).
- **PARTUUID:** Идентификатор раздела (хранится в таблице разделов GPT).
- **WWN (World Wide Name):** Уникальный заводской номер физического накопителя.
- **LABELS:** Человекочитаемые метки (например, `DATA_DRIVE`).

## Инструментарий администратора

| Команда | Назначение |
| :--- | :--- |
| `lsblk -f` | Вывод дерева устройств с типами ФС и UUID. Самый удобный инструмент для первичного осмотра. |
| `blkid` | Низкоуровневый просмотр атрибутов блочных устройств (UUID, TYPE, PARTUUID). |
| `wipefs` | Просмотр и удаление сигнатур ФС или таблиц разделов (важно перед переиспользованием диска). |
| `findmnt` | Анализ текущих точек монтирования и их параметров. |
| `lsblk -t` | Информация о топологии диска (размер сектора, выравнивание). |
| `smartctl` | Диагностика здоровья дисков (S.M.A.R.T.). |

## Практические сценарии

### 1. Подготовка нового диска к работе

Классический цикл подготовки нового накопителя в системе:

```bash
# 1. Поиск устройства (допустим, нашли /dev/sdb)
lsblk

# 2. Удаление старых метаданных (если диск не новый)
# ОСТОРОЖНО: Это уничтожит данные о ФС!
sudo wipefs -a /dev/sdb

# 3. Разметка диска (GPT)
# Создаем один раздел на весь диск
sudo parted /dev/sdb mklabel gpt mkpart primary ext4 0% 100%

# 4. Создание файловой системы (XFS — стандарт для RHEL/CentOS)
sudo mkfs.xfs -L DATA_DRIVE /dev/sdb1

# 5. Получение UUID для fstab
blkid /dev/sdb1

# 6. Настройка fstab
# UUID=... /mnt/data xfs defaults 0 2
```

### 2. Работа с современными NVMe-накопителями

NVMe используют другой стек и именование (`/dev/nvme0n1`). Для управления используется утилита `nvme-cli`.

```bash
# Просмотр списка NVMe устройств
sudo nvme list

# Получение SMART-логов (температура, ресурс)
sudo nvme smart-log /dev/nvme0
```

### 3. Шифрование LUKS (Device Mapper)

Шифрование данных «в покое» (Data at Rest) с использованием LUKS.

```bash
# Инициализация шифрования
sudo cryptsetup luksFormat /dev/sdb1

# Открытие контейнера (создает /dev/mapper/secure_data)
sudo cryptsetup luksOpen /dev/sdb1 secure_data

# Создание ФС внутри защищенного слоя
sudo mkfs.ext4 /dev/mapper/secure_data
```
