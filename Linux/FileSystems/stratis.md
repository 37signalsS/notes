# Stratis: Управление многоуровневым хранилищем

## Определения

- **Stratis:** Гибридное решение для управления локальным хранилищем в Linux (преимущественно RHEL/Fedora), объединяющее функции менеджера томов и файловой системы. Работает как демон `stratisd`, который абстрагирует сложность настройки Device Mapper (LVM) и XFS.
- **Пул (Pool):** Логическое объединение одного или нескольких блочных устройств, из которого выделяется пространство для файловых систем.
- **Тонкое выделение (Thin Provisioning):** Механизм, позволяющий создавать файловые системы с виртуальным размером, превышающим физическую емкость пула. Пространство выделяется только при записи данных.
- **Тиринг (Tiering) / Кэширование:** Использование быстрых устройств (например, NVMe SSD) в качестве кэша для более медленных накопителей внутри одного пула.

## Основные концепции

### Архитектура и стек технологий

Stratis не является новой файловой системой «с нуля». Он представляет собой слой автоматизации поверх проверенных технологий ядра Linux:
- **XFS:** Используется в качестве единственной поддерживаемой файловой системы для презентации данных.
- **Device Mapper:** Используется для реализации тонкого выделения (`dm-thin`) и кэширования (`dm-cache`).
- **LUKS:** Используется для прозрачного шифрования данных в пуле.
- **VDO (Virtual Data Optimizer):** Может быть интегрирован в стек Stratis для обеспечения дедупликации и сжатия.

### Ключевые особенности

- **Автоматическое расширение:** В отличие от классического LVM, где нужно расширять сначала LV, а затем ФС, Stratis делает это автоматически. ФС XFS всегда видит большой объем (например, 1 ТБ), но реально занимает минимум места.
- **Отсутствие встроенного RAID:** Stratis не реализует избыточность (зеркалирование или четность) на своем уровне. Если требуется отказоустойчивость, Stratis должен работать поверх аппаратного RAID или программного `mdadm`.
- **Снапшоты на базе CoW:** Позволяют мгновенно создавать копии файловых систем внутри пула.

## Практические сценарии

### Установка и подготовка

```bash
# Установка демона и CLI-утилиты (RHEL/CentOS/Fedora)
sudo dnf install stratisd stratis-cli

# Активация сервиса
sudo systemctl enable --now stratisd
```

### Создание и управление пулами

**ВАЖНО:** Блочные устройства, добавляемые в Stratis, должны быть чистыми (без таблиц разделов и метаданных других ФС).

```bash
# Создание базового пула
sudo stratis pool create storage_pool /dev/sdb

# Создание зашифрованного пула (требует ввода пароля в сессии)
sudo stratis pool create --key-desc my_key encrypted_pool /dev/sdc

# Добавление кэширующего SSD-устройства
sudo stratis pool init-cache storage_pool /dev/nvme0n1
```

### Управление файловыми системами

```bash
# Создание ФС внутри пула
sudo stratis filesystem create storage_pool data_files

# Просмотр списка ФС и их UUID (необходим для монтирования)
sudo stratis filesystem list

# Создание снапшота
sudo stratis filesystem snapshot storage_pool data_files data_files_backup
```

### Настройка автоматического монтирования

Поскольку `stratisd` инициализирует устройства после загрузки ядра, использование стандартных записей в `fstab` без специальных опций может привести к сбою загрузки.

**Пример записи в `/etc/fstab`:**
```ini
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /mnt/stratis xfs defaults,x-systemd.requires=stratisd.service 0 0
```

### Шифрование и интеграция с Clevis

Для автоматической разблокировки зашифрованных пулов при загрузке рекомендуется использовать Clevis (например, через TPM2 или сетевой сервер Tang).

```bash
# Привязка пула к TPM2 (если поддерживается оборудованием)
sudo stratis pool bind tpm2 encrypted_pool --key-desc my_key
```

## Производительность и ограничения

- **Метаданные:** Stratis резервирует около 1 ГБ пространства в пуле под собственные нужды и метаданные Device Mapper.
- **Только XFS:** Невозможно использовать ext4 или btrfs внутри Stratis.
- **Уменьшение пула:** На данный момент Stratis не поддерживает удаление дисков данных из пула без его полного пересоздания.
