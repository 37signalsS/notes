# Stratis: Управление многоуровневым хранилищем

## Определения

- **Stratis:** Гибридное решение для управления локальным хранилищем в Linux (преимущественно RHEL/Fedora), объединяющее функции менеджера томов и файловой системы. Работает через демон `stratisd`, который абстрагирует настройку Device Mapper и XFS.
- **Пул (Pool):** Группа блочных устройств, объединенных в единый ресурс для создания файловых систем.
- **Тонкое выделение (Thin Provisioning):** Технология, позволяющая создавать файловые системы с виртуальным размером, превышающим физическую емкость. Реальное пространство на диске занимается только по мере записи данных.
- **Снапшот (Snapshot):** Точечная копия файловой системы, использующая механизм Copy-on-Write (CoW).
- **Кэш-устройство (Cache Device):** Быстрый накопитель (SSD/NVMe), добавляемый в пул для ускорения доступа к данным на медленных дисках (HDD).
- **D-Bus API:** Межпроцессный интерфейс, через который `stratisd` предоставляет управление пулами и файловыми системами. CLI-утилита `stratis` является клиентом этого API.

## Основные концепции

### Архитектура и стек технологий

Stratis является надстройкой над проверенными компонентами ядра Linux, предоставляя высокоуровневый API (D-Bus) для управления ими.

- **XFS:** Единственная поддерживаемая файловая система. Stratis автоматически управляет её расширением.
- **Device Mapper:** Используется для реализации тонкого провизионирования (`dm-thin`) и кэширования (`dm-cache`).
- **LUKS2:** Обеспечивает шифрование на уровне пула.
- **Статус (RHEL 9/10):** В RHEL 9 Stratis всё ещё находится в статусе **Technology Preview**. В RHEL 10 он становится полноценным компонентом с расширенной поддержкой в Web Console (Cockpit).

#### D-Bus и stratisd

`stratisd` работает как системный сервис, предоставляющий интерфейс через D-Bus. Это позволяет:

- Отделять управление хранилищем от конкретной сессии пользователя.
- Интегрироваться с systemd и Cockpit.
- Обеспечивать атомарность операций через демона.

CLI-утилита `stratis` посылает запросы к `stratisd` по D-Bus. При сбое демона все операции CLI зависают или возвращают ошибку связи.

#### Device Mapper targets в Stratis

| Target | Назначение |
| :--- | :--- |
| `dm-thin` | Реализация тонкого провизионирования. Обеспечивает виртуальные размеры файловых систем. |
| `dm-cache` | Прозрачное кэширование данных с быстрых устройств (SSD/NVMe) на медленные (HDD). |
| `dm-crypt` | Шифрование на уровне блоков (интеграция с LUKS2). |

### Ключевые особенности

- **Автоматизация:** Stratis самостоятельно увеличивает размер файловой системы XFS по мере роста объема данных в пуле.
- **Отсутствие встроенного RAID:** Stratis **не обеспечивает** избыточность. Для защиты данных он должен располагаться поверх аппаратного RAID или программного `mdadm`.
- **Тиринг (Caching):** Возможность добавления быстрых устройств (SSD/NVMe) в качестве кэша для медленных накопителей (HDD) в одном пуле.
- **Лимиты (RHEL 10+):** Появилась возможность устанавливать предельные размеры для отдельных файловых систем, чтобы одна ФС не могла исчерпать весь физический объем пула.

#### Thin Provisioning в Stratis

В отличие от LVM Thin Pool, Stratis управляет тонким провизионированием через `dm-thin` напрямую, без отдельного управления VG/LV. Это упрощает администрирование, но снижает гибкость по сравнению с LVM.

- **Аллокация по требованию:** Физические блоки выделяются только при первой записи.
- **Overcommit:** Возможность создавать ФС суммарным размером, превышающим физический объем пула.
- **Риск переполнения:** При исчерпании физического пространства пул переходит в режим `Out Of Space` (OOS), и запись становится невозможной.

#### Снапшоты в Stratis

Снапшоты Stratis реализованы через механизм Copy-on-Write на уровне `dm-thin`:

- **Мгновенное создание:** Снапшот создается за секунды, так как копируются только метаданные.
- **Чтение:** Снапшоты доступны только для чтения (read-only). Это предотвращает случайное изменение.
- **Зависимость:** Снапшот зависит от исходной файловой системы. Удаление исходной ФС делает снапшот нечитаемым.
- **Рекурсия:** Поддерживаются цепочки снапшотов (снапшот снапшота) с общим ancestry.

#### Кэширование (Tiering)

Stratis поддерживает двухуровневое хранение в одном пуле:

- **Data devices:** Медленные, большие устройства (HDD, SATA SSD).
- **Cache device:** Быстрое устройство (NVMe, Intel Optane) для хранения часто используемых блоков.

Кэш работает через `dm-cache` в режиме `smq` (Stochastic Multiqueue) по умолчанию — оптимален для смешанных нагрузок.

### Сравнение: Stratis vs LVM

| Критерий | Stratis | LVM |
| :--- | :--- | :--- |
| **Уровень абстракции** | Высокий (pool → filesystem) | Средний (PV → VG → LV) |
| **Файловые системы** | Только XFS | Любая (ext4, XFS, Btrfs) |
| **Тонкое провизионирование** | Встроено (`dm-thin`) | Требует отдельного Thin Pool |
| **Кэширование** | Встроено (`dm-cache`) | Требует `lvmcache` |
| **Шифрование** | LUKS2 на уровне пула | LUKS на уровне LV или PV |
| **RAID** | Нет (требует внешний mdadm) | Нет (требует внешний mdadm) |
| **Снапшоты** | Встроенные (read-only) | Встроенные (read-write возможен) |
| **Мониторинг** | `stratis pool list` | `lvs`, `pvs`, `vgs` |
| **Сложность** | Низкая | Средняя/Высокая |
| **Гибкость** | Ограниченная | Высокая |

### inode и dentry в контексте Stratis

Stratis управляет файловыми системами XFS, поэтому фундаментальные структуры (inode, dentry, superblock) остаются ответственностью XFS. Stratis не изменяет внутреннее устройство ФС, только абстрагирует размещение на блочных устройствах.

## Практические сценарии

### Установка и запуск

```bash
# Установка компонентов
sudo dnf install stratisd stratis-cli

# Запуск и включение автозагрузки
sudo systemctl enable --now stratisd
```

### Управление пулами

**Важно:** Перед добавлением устройства в пул необходимо очистить его метаданные (например, старые метки LVM или разделов).

```bash
# Очистка подписей на диске
sudo wipefs -a /dev/sdb

# Создание пула из одного или нескольких дисков
sudo stratis pool create storage_pool /dev/sdb /dev/sdc

# Добавление кэширующего устройства (SSD) в пул
sudo stratis pool init-cache storage_pool /dev/nvme0n1

# Расширение пула (добавление новых дисков с данными)
sudo stratis pool add-data storage_pool /dev/sdd
```

### Управление файловыми системами и снапшотами

```bash
# Создание новой ФС
sudo stratis filesystem create storage_pool data_files

# Просмотр списка ФС и их UUID
sudo stratis filesystem list

# Создание мгновенного снимка (снапшота)
sudo stratis filesystem snapshot storage_pool data_files backup_snap
```

### Мониторинг состояния пулов и ФС

Для SRE критически важно отслеживать использование пространства и здоровье пулов:

```bash
# Общий статус всех пулов (имя, размер, использование)
sudo stratis pool list
# → Pool Name     Total Physical Size   Total Physical Used
# → storage_pool  1.8 TiB               450 GiB (24%)

# Детализация по файловым системам в пуле
sudo stratis filesystem list
# → Pool Name     FS Name       Created     Used
# → storage_pool  data_files    2024-01-01  120 GiB

# Проверка состояния устройств в пуле
sudo stratis pool list --details
# → Devs: 3 (2 data, 1 cache)
```

#### Мониторинг через journalctl

```bash
# Логи stratisd (операции, ошибки)
sudo journalctl -u stratisd -f

# Поиск ошибок за последний час
sudo journalctl -u stratisd --since "1 hour ago" | grep -i error

# Критические события
sudo journalctl -u stratisd -p err
```

#### Интеграция с Prometheus (через node_exporter)

`stratisd` экспортирует метрики через D-Bus. Для сбора в Prometheus используйте `stratis_exporter` или парсинг вывода `stratis pool list` через textfile collector:

```bash
# Пример для node_exporter textfile collector
stratis pool list | awk 'NR>1 {print "stratis_pool_total_bytes{pool=\"" $1 "\"} " $2 * 1024^3}'
stratis pool list | awk 'NR>1 {print "stratis_pool_used_bytes{pool=\"" $1 "\"} " $3 * 1024^3}'
```

### Настройка автоматического монтирования

Поскольку инициализация пулов Stratis происходит во время работы демона `stratisd`, обычная запись в `fstab` может привести к ошибке загрузки (диск еще не готов).

**Запись в `/etc/fstab`:**
```ini
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /mnt/data xfs defaults,x-systemd.requires=stratisd.service 0 0
```

#### systemd unit для гарантированного порядка

```ini
# /etc/systemd/system/stratisd.service.d/override.conf
[Unit]
After=local-fs.target
Before=remote-fs.target
```

### Автоматизация через Ansible

Для управления Stratis рекомендуется использовать системную роль `storage` (входит в пакет `rhel-system-roles`).

```yaml
- name: Настройка Stratis через системную роль
  include_role:
    name: redhat.rhel_system_roles.storage
  vars:
    storage_pools:
      - name: my_pool
        type: stratis
        disks: [/dev/sdb]
        volumes:
          - name: data_vol
            mount_point: /mnt/stratis_data
```

### Добавление и управление кэш-устройством

```bash
# Добавление SSD в качестве кэша (одиночное действие, необратимо без удаления пула)
sudo stratis pool init-cache storage_pool /dev/nvme0n1

# Проверка статуса кэша
sudo stratis pool list --details
# → Cache: /dev/nvme0n1 (512 GB)
```

**Важно:** Кэширующее устройство очищается при инициализации. Убедитесь, что на нем нет данных.

### Работа с снапшотами для бэкапов

```bash
# Создание снапшота
sudo stratis filesystem snapshot storage_pool data_files daily_backup_$(date +%Y%m%d)

# Монтирование снапшота для чтения (только read-only)
sudo mount -o ro /dev/stratis/storage_pool/daily_backup_20240101 /mnt/backup_verify

# Копирование на внешний носитель
sudo rsync -aAXv /mnt/backup_verify/ /mnt/external_drive/backup/

# Удаление устаревшего снапшота
sudo stratis filesystem destroy storage_pool daily_backup_20231231
```

### Управление размером файловых систем

Stratis автоматически расширяет XFS при заполнении, но при необходимости можно задать лимит:

```bash
# Просмотр текущего и виртуального размера
sudo stratis filesystem list
# → data_files  120 GiB / 500 GiB (virtual)

# Установка лимита (RHEL 10+)
sudo stratis filesystem set-size-limit storage_pool data_files 1T
```

### Интеграция с LUKS2

Stratis поддерживает шифрование на уровне пула через LUKS2:

```bash
# Шифрование устройства перед созданием пула
sudo cryptsetup luksFormat /dev/sdb
sudo cryptsetup open --type luks /dev/sdb crypt_pool

# Создание пула на зашифрованном устройстве
sudo stratis pool create secure_pool /dev/mapper/crypt_pool
```

Для автоматического открытия LUKS при загрузке используйте Clevis/Tang (если настроены) или TPM2.

## Эксплуатация и ограничения

- **Метаданные:** Под нужды Stratis и Device Mapper резервируется около 1 ГБ пространства в каждом пуле.
- **Удаление устройств:** На текущий момент **невозможно** удалить диск из пула без полной пересборки пула.
- **Шифрование:** Поддерживается интеграция с **Clevis/Tang** (сетевая разблокировка) и **TPM2** (аппаратная привязка).
- **Зависимость от XFS:** Возможность работать только с XFS ограничивает переносимость данных между другими ФС без переформатирования.
- **Режим OOS:** При исчерпании физического пространства пул переходит в режим Read-Only. Для восстановления нужно добавить устройства или удалить данные/снапшоты.

## Диагностика и устранение неполадок

### Проверка статуса демона

```bash
# Если команды stratis зависают или возвращают ошибки связи
sudo systemctl status stratisd

# Перезапуск демона (сбрасывает D-Bus соединения)
sudo systemctl restart stratisd
```

### Логи и трассировка

```bash
# Детальная информация об операциях
sudo journalctl -u stratisd -f

# Фильтрация по уровню ошибки
sudo journalctl -u stratisd -p err --since "2 hours ago"

# Проверка статуса Device Mapper устройств
sudo dmsetup ls --tree

# Проверка состояния dm-thin пулов
sudo dmsetup status
```

### Ошибки создания и добавления устройств

```bash
# Если диск не добавляется, убедитесь в отсутствии разделов/меток
sudo wipefs -a /dev/sdX

# Проверка, что устройство не используется другими PV/LVM
sudo pvs
sudo vgs

# Проверка поддержки dm-thin в ядре
sudo dmsetup targets | grep thin
# → thin-pool           v1.19.0
```

### Ограничения и ограничения Stratis

- **Нет встроенного RAID:** Для защиты от сбоя дисков Stratis требует внешний RAID-массив (см. [Обзор RAID и mdadm](./RAID/overview.md)).
- **Один пул на набор устройств:** Невозможно создать несколько пулов на пересекающихся наборах дисков.
- **Миграция:** Перенос пула на другой сервер требует переноса всех устройств ( offline операция).

### Восстановление после сбоя устройства

```bash
# 1. Определить вышедшее устройство
sudo stratis pool list --details
# → Devs: 3 (2 data, 1 cache) — проверьте физические устройства

# 2. Пометка устройства как failed (если поддерживается)
# Stratis не поддерживает горячую замену — требуется остановка сервисов

# 3. Замена диска и добавление в пул (если пул на RAID)
sudo stratis pool add-data storage_pool /dev/sdd

# 4. Если пул на hardware RAID, замена происходит на уровне контроллера
```
