# Stratis: Управление многоуровневым хранилищем

## Определения

* **Stratis:** Новый инструмент управления хранилищем от Red Hat, напоминающий упрощенную комбинацию LVM и файловых систем. Находится в разработке и **не рекомендуется для production-среды**.
* **Thin Provisioning (Тонкий провизионинг):** Технология, при которой файловая система создается с номинальным размером (например, 1 ТБ), но реальное место занимается только под фактические данные.
* **Tiering (Тиринг):** Технология использования быстрых дисков (SSD) в качестве кэша для медленных дисков (HDD) для ускорения операций записи.
* **Pool (Пул):** Группа физических дисков, объединенных в Stratis для создания файловых систем.

## Базовые концепции

Stratis упрощает работу с хранилищем по сравнению с традиционным стеком (RAID + LVM + XFS):

1.  **Диски объединяются в Pools (пулы):** В пулах создаются файловые системы.
2.  **Автоматическое управление:** Нет необходимости вручную указывать размеры логических томов и файловых систем. Stratis автоматически выделяет место.
3.  **XFS only:** Stratis на данный момент поддерживает только файловую систему XFS. Это означает, что уменьшение файловой системы невозможно.
4.  **Метаданные:** Для метаданных (структура файловой системы, inodes) выделяется около 500 МБ независимо от реального использования.

### Особенности

* **Нет встроенного RAID:** Stratis не обеспечивает отказоустойчивость. Для защиты данных необходимо использовать RAID на уровне дисков.
* **Снапшоты:** Являются полной копией файловой системы с другим UID, а не инкрементным изменением (как в LVM).
* **Шифрование:** Поддержка создания зашифрованных пулов.
* **Кэширование (Tiering):** Позволяет использовать SSD-диски в качестве кэша для записи данных на HDD.

## Практические сценарии

### 1. Установка и запуск

```bash
# Установка (например, в RHEL)
sudo dnf install stratis-cli stratisd

# Проверка статуса сервиса
sudo systemctl status stratisd

# Запуск и включение автозапуска
sudo systemctl enable --now stratisd
```

### 2. Создание пула

```bash
# Создание пула из одного или нескольких дисков
# ВАЖНО: Диски должны быть пустыми (удалить разделы, FS, LVM)
sudo stratis pool create myPool /dev/sdd

# Просмотр списка пулов
sudo stratis pool list

# Просмотр детальной информации о пуле (включая наличие кэша и шифрования)
sudo stratis pool list-properties myPool
```

### 3. Управление дисками в пуле

* **Добавление диска данных (расширение пула):**

    ```bash
    sudo stratis pool add-data myPool /dev/sde
    ```

* **Добавление SSD-диска в качестве кэша (Tiering):**

    ```bash
    # Инициализация кэша (если еще нет)
    sudo stratis pool init-cache myPool /dev/sdf
    
    # Просмотр устройств в пуле
    sudo stratis blockdev list
    ```

### 4. Управление файловыми системами

* **Создание файловой системы:**

    ```bash
    # Создание ФС в указанном пуле
    sudo stratis filesystem create myPool myFS1
    
    # Просмотр списка ФС
    sudo stratis filesystem list
    ```

* **Создание снапшота:**

    ```bash
    # Создание копии текущей ФС
    # ВАЖНО: Снапшот не должен создаваться на смонтированной ФС, либо нужно убедиться, что запись не ведется
    sudo stratis filesystem snapshot myPool myFS1 myFS1_snap
    ```

* **Восстановление из снапшота:**
    1.  Удалить старую ФС: `sudo stratis filesystem destroy myPool myFS1`
    2.  Переименовать снапшот: `sudo stratis filesystem rename myPool myFS1_snap myFS1`

### 5. Монтирование

* **Ручное монтирование:**

    ```bash
    # Получение UUID
    sudo stratis filesystem list
    
    # Монтирование по UUID
    mount -U <UUID> /mnt/stratis
    ```

* **Автоматическое монтирование (fstab):**

    В `fstab` необходимо указать:
    * UUID файловой системы
    * Тип ФС: `xfs`
    * Опции монтирования: `x-systemd.requires=stratisd` (критически важно!)

    Пример строки в `/etc/fstab`:

    ```
    UUID=<uuid_файловой_системы> /mnt/stratis xfs defaults,x-systemd.requires=stratisd 0 0
    ```
