# Монтирование директории на отдельный диск

Чтобы содержимое определённой директории (например, `/var/log` или `/home/user/data`) физически хранилось на отдельном диске, необходимо выполнить следующие шаги:

1.  **Подготовить диск**: Убедитесь, что на диске есть раздел и на нём создана файловая система (например, ext4 или xfs).
    -   Посмотреть диски и разделы: `lsblk`
    -   Создать файловую систему (если нужно): `sudo mkfs.ext4 /dev/sdb1`

2.  **Создать точку монтирования**: Это пустая директория, к которой будет "привязан" диск.
    ```sh
    sudo mkdir -p /path/to/directory
    ```

3.  **Временно смонтировать диск**: Это позволит проверить, что всё работает правильно.
    ```sh
    sudo mount /dev/sdb1 /path/to/directory
    ```
    После этого все файлы, созданные в `/path/to/directory`, будут физически записываться на диск `/dev/sdb1`.

4.  **Настроить автоматическое монтирование при загрузке**: Чтобы диск монтировался каждый раз при старте системы, нужно добавить запись в файл `/etc/fstab`.
    -   **Узнать UUID диска**: Это более надёжный способ идентификации, чем имя устройства (`/dev/sdb1`), которое может измениться.
        ```sh
        sudo blkid /dev/sdb1
        ```
    -   **Добавить запись в `/etc/fstab`**:
        ```
        # <file system> <mount point>   <type>  <options>       <dump>  <pass>
        UUID=...      /path/to/directory ext4    defaults        0       2
        ```

5.  **Перенести существующие данные (если необходимо)**:
    Если в директории уже были данные, их нужно перенести на новый диск. Это делается *до* настройки постоянного монтирования в `fstab`.
    ```sh
    # 1. Смонтировать новый диск во временную точку
    sudo mount /dev/sdb1 /mnt

    # 2. Скопировать данные со сохранением прав
    sudo rsync -av /path/to/directory/ /mnt/

    # 3. Переименовать старую директорию (для бэкапа)
    sudo mv /path/to/directory /path/to/directory.bak

    # 4. Создать пустую точку монтирования
    sudo mkdir /path/to/directory

    # 5. Размонтировать диск и смонтировать его в нужную точку
    sudo umount /mnt
    sudo mount /dev/sdb1 /path/to/directory

    # 6. Проверить, что данные на месте, и добавить запись в fstab
    ```

# Файл /etc/fstab

Файл `/etc/fstab` (file systems table) — это один из ключевых конфигурационных файлов в Linux, который содержит информацию о различных файловых системах и точках их монтирования. Система использует этот файл при загрузке для автоматического монтирования дисков, разделов и сетевых файловых систем.

Каждая строка в `/etc/fstab` представляет одну файловую систему и состоит из шести полей, разделенных пробелами или табами.

```text
<file system> <mount point>   <type>  <options>       <dump>  <pass>
```

1.  **`<file system>`**: Устройство или ресурс, который нужно смонтировать.
    *   **Рекомендуемый способ:** `UUID=<uuid>` (например, `UUID=abc-123...`). Это самый надёжный метод, так как UUID уникален и не меняется. Узнать UUID можно командой `sudo blkid`.
    *   **Альтернатива:** Путь к устройству, например, `/dev/sda1`. Менее надёжно, так как имя может измениться после перезагрузки.
    *   Для сетевых ФС здесь указывается `user@host:/path`.

2.  **`<mount point>`**: Директория в файловой системе, к которой будет "привязан" ресурс (например, `/home`, `/var/log`). Директория должна существовать.

3.  **`<type>`**: Тип файловой системы.
    *   Для дисков: `ext4`, `xfs`, `btrfs`, `vfat`.
    *   Для сетевых ФС: `nfs`, `cifs`.
    *   Для swap: `swap`.
    *   `auto`: Позволяет системе автоматически определить тип ФС.

4.  **`<options>`**: Опции монтирования, перечисляются через запятую.
    *   `defaults`: Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
    *   `rw` / `ro`: Монтировать в режиме чтение/запись или только чтение.
    *   `noatime`: Не обновлять `atime` (время последнего доступа) для файлов. Это может повысить производительность диска, так как сокращает количество операций записи.
    *   `nofail`: Не останавливать загрузку системы, если устройство не может быть смонтировано. Критически важно для съёмных дисков или сетевых ресурсов.
    *   `user`: Разрешить обычному пользователю монтировать файловую систему.

5.  **`<dump>`**: Используется утилитой `dump` для определения, нужно ли создавать резервную копию файловой системы.
    *   `0`: Не делать дамп.
    *   `1`: Делать дамп.
    *   На практике почти всегда установлено в `0`.

6.  **`<pass>`**: Определяет порядок проверки файловых систем утилитой `fsck` при загрузке.

    *   `0`: Не проверять.
    *   `1`: Устанавливается для корневой файловой системы (`/`). Она проверяется первой.
    *   `2`: Устанавливается для остальных файловых систем. Они проверяются после корневой.

После редактирования `/etc/fstab` можно проверить корректность монтирования всех записей командой:
```bash
sudo mount -a
```
Если команда выполнилась без ошибок, значит, синтаксис в файле корректен.

### Альтернативные способы монтирования

Хотя `/etc/fstab` является стандартом (и на современных системах обрабатывается `systemd`), существуют и другие методы для автоматического монтирования, каждый со своими преимуществами.

#### Autofs (Монтирование по требованию)

`autofs` — это сервис, который автоматически монтирует файловую систему, как только к ней происходит обращение, и отмонтирует ее после периода бездействия. Это идеальный вариант для съёмных дисков или сетевых папок, чтобы не держать их подключенными постоянно.

1.  **Установите `autofs`**:
    ```bash
    sudo apt install autofs  # Debian/Ubuntu
    sudo dnf install autofs  # Fedora/CentOS
    ```

2.  **Настройте главный файл `/etc/auto.master`**. Добавьте строку, которая указывает на вашу карту монтирования. Например, для прямых монтирований (где путь абсолютный):
    ```
    # <точка монтирования> <файл карты>   <опции>
    /-                      /etc/auto.direct --timeout=60
    ```
    Здесь `/-` означает, что пути в карте будут абсолютными, а `--timeout=60` — отмонтировать диск после 60 секунд бездействия.

3.  **Создайте и настройте файл карты `/etc/auto.direct`**. Добавьте в него строку для вашего диска:
    ```
    # <полный путь>  <опции монтирования>  <источник>
    /mnt/data         -fstype=ext4,rw       :/dev/disk/by-uuid/1234-ABCD-5678-EFGH
    ```
    Обратите внимание на синтаксис: опции идут до источника, а перед источником ставится двоеточие `:`.

4.  **Перезапустите сервис**:
    ```bash
    sudo systemctl restart autofs
    ```
    Теперь, как только вы или программа попытаетесь получить доступ к `/mnt/data`, `autofs` автоматически смонтирует диск.

#### Правила Udev (Продвинутый, на основе событий)

`udev` — это подсистема ядра, которая управляет устройствами в `/dev`. Можно создать правило, которое будет выполнять команду `mount` каждый раз, когда ядро обнаруживает подключение конкретного диска. Этот метод очень гибкий, но сложнее в настройке.

1.  **Найдите уникальные атрибуты диска.** Например, серийный номер.
    ```bash
    udevadm info -a -n /dev/sdb1 | grep 'serial'
    ```
    Вы получите что-то вроде `ATTRS{serial}=="123456789"`.

2.  **Создайте файл правила** в `/etc/udev/rules.d/`, например, `99-mydisk.rules`.
    ```
    ACTION=="add", KERNEL=="sd*", ATTRS{serial}=="123456789", RUN+="/bin/mount /dev/%k /mnt/data"
    ```
    Это правило говорит: "когда добавляется (`add`) устройство, имя которого начинается на `sd*` и у которого серийный номер `123456789`, выполнить команду монтирования". `%k` подставит имя устройства (например, `sdb1`).

3.  **Перезагрузите правила `udev`**:
    ```bash
    sudo udevadm control --reload-rules && sudo udevadm trigger
    ```

#### Systemd .mount и .automount 

Для автоматического монтирования сетевых ресурсов при старте системы, а также монтирования по требованию, можно использовать systemd-юниты `.mount` и `.automount`. Это современный подход, который предлагает больше гибкости и лучшую интеграцию с системой инициализации.

**1. Юнит `.mount` для постоянного монтирования**

Юнит `.mount` определяет параметры монтирования и точку монтирования. Его имя строится по пути к точке монтирования, где `/` заменяется на `-`. Например, для точки монтирования `/mnt/share` файл будет называться `mnt-share.mount`.

Пример содержимого файла `mnt-share.mount` (например, `/etc/systemd/system/mnt-share.mount`):

```ini
[Unit]
Description=Mount network share
After=network-online.target  # Убедиться, что сеть доступна

[Mount]
What=//192.168.0.10/share
Where=/mnt/share
Type=cifs
Options=credentials=/etc/smb.cred,_netdev,vers=3.0

[Install]
WantedBy=multi-user.target
```

**Пояснения к секциям:**

*   **`[Unit]`**: Общие метаданные для юнита. `Description` — описание, `After=network-online.target` — указывает, что юнит должен запускаться только после того, как будет доступна сеть (важно для сетевых ресурсов).
*   **`[Mount]`**: Определяет параметры монтирования.
    *   `What` — ресурс для монтирования (например, сетевая папка, как в примере `//192.168.0.10/share`).
    *   `Where` — точка монтирования в локальной файловой системе (`/mnt/share`).
    *   `Type` — тип файловой системы (`cifs` для SMB/CIFS, `nfs` для NFS, `ext4` для локальных дисков и т.д.).
    *   `Options` — опции монтирования, аналогичные опциям в `/etc/fstab`. `_netdev` указывает, что это сетевой ресурс.
*   **`[Install]`**: Определяет, как юнит будет интегрирован в систему при включении (`enable`). `WantedBy=multi-user.target` означает, что юнит будет запускаться при переходе в многопользовательский режим (стандартный режим работы сервера).

После создания файла юнита необходимо:

1.  Создать точку монтирования: `sudo mkdir -p /mnt/share`
2.  Перезагрузить systemd: `sudo systemctl daemon-reload`
3.  Включить юнит для автоматического запуска при загрузке: `sudo systemctl enable mnt-share.mount`
4.  Запустить юнит сейчас: `sudo systemctl start mnt-share.mount`
5.  Проверить статус: `sudo systemctl status mnt-share.mount`

**2. Юнит `.automount` для монтирования по требованию**

Юнит `.automount` позволяет монтировать ресурс только при первом обращении к нему. Это ускоряет загрузку системы, если сетевые ресурсы не нужны сразу, или если сеть еще не поднята. Он работает в паре с соответствующим `.mount` юнитом.

Пример содержимого файла `mnt-share.automount` (например, `/etc/systemd/system/mnt-share.automount`):

```ini
[Unit]
Description=Automount network share

[Automount]
Where=/mnt/share
TimeoutIdleSec=600  # Отмонтировать через 10 минут бездействия

[Install]
WantedBy=multi-user.target
```

**Пояснения к секциям:**

*   **`[Unit]`**: Общие метаданные.
*   **`[Automount]`**: Определяет параметры авто монтирования.
    *   `Where` — точка монтирования.
    *   `TimeoutIdleSec` — время в секундах, после которого ресурс будет автоматически отмонтирован при отсутствии активности.
*   **`[Install]`**: Как юнит будет интегрирован.

После создания файла `.automount` юнита необходимо:

1.  Создать точку монтирования (если не создана): `sudo mkdir -p /mnt/share`
2.  Перезагрузить systemd: `sudo systemctl daemon-reload`
3.  Включить **только `.automount` юнит** для автоматического запуска при загрузке (он "поднимет" `.mount` юнит при необходимости): `sudo systemctl enable mnt-share.automount`
4.  Запустить `.automount` юнит сейчас: `sudo systemctl start mnt-share.automount`
5.  Проверить статус: `sudo systemctl status mnt-share.automount`

При первой попытке доступа к `/mnt/share` (например, `ls /mnt/share`) systemd автоматически активирует `mnt-share.mount`.
