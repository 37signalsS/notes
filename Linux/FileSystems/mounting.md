# Управление монтированием файловых систем в Linux

## Определения

### Монтирование (Mounting)

**Монтирование** — это процесс, при котором операционная система делает файловую систему, находящуюся на каком-либо устройстве хранения (например, на разделе жесткого диска, USB-накопителе или сетевом ресурсе), доступной в определённой точке общего дерева каталогов. Эта точка называется **точкой монтирования (mount point)**.

### Способы автоматического монтирования

1. **`/etc/fstab`**: Файл `/etc/fstab` (file systems table) — это один из ключевых конфигурационных файлов в Linux, который содержит информацию о различных файловых системах и точках их монтирования. Система использует этот файл при загрузке для автоматического монтирования дисков, разделов и сетевых файловых систем. Это традиционный способ для статического монтирования.

2. **Systemd `.mount` и `.automount`**: Для автоматического монтирования сетевых ресурсов при старте системы, а также монтирования по требованию, можно использовать systemd-юниты `.mount` и `.automount`. Это современный подход, который предлагает больше гибкости и лучшую интеграцию с системой инициализации.
    * **`.mount`**: Определяет, как и что монтировать. Аналог записи в `fstab`.
    * **`.automount`**: Определяет точку монтирования, которая будет обслуживаться `systemd` для монтирования по требованию.

3. **Autofs (Монтирование по требованию)**: `autofs` — это сервис, который автоматически монтирует файловую систему, как только к ней происходит обращение, и отмонтирует ее после периода бездействия. Это идеальный вариант для съёмных дисков или сетевых папок, чтобы не держать их подключенными постоянно.

4. **Правила Udev (Монтирование на основе событий)**: `udev` — это подсистема ядра, которая управляет устройствами в `/dev`. Можно создать правило, которое будет выполнять команду `mount` каждый раз, когда ядро обнаруживает подключение конкретного диска. Этот метод очень гибкий, но сложнее в настройке. Подробнее о работе с `udev` см. в [Udev: подсистема динамического управления устройствами](../Core/udev.md).

## Основные концепции

### Команда mount

Команда `mount` подключает файловую систему с устройства к каталогу — точке монтирования. В Linux и Unix-подобных системах файловые системы необходимо примонтировать, чтобы они стали доступны в общей иерархии каталогов.

```bash
# Базовый синтаксис
sudo mount /dev/sdb1 /mnt/data

# Монтирование по UUID (рекомендуется)
sudo mount UUID=a1b2c3d4-e5f6-7890 /mnt/data
```

### Структура и синтаксис файла /etc/fstab

Файл `/etc/fstab` (file systems table) — сердце автоматизации монтирования. Init-система запускает `mount -a` при загрузке, автоматически монтируя все необходимые файловые системы: корневую, `/home`, `/var`, сетевые шары.

Каждая строка в `/etc/fstab` описывает одну файловую систему и состоит из шести полей:

```text
<file system>    <mount point>    <type>    <options>    <dump>    <pass>
```

| Поле | Описание | Примеры |
|------|----------|---------|
| **1. Устройство** | Путь, UUID или метка | `/dev/sdb1`, `UUID=xxx`, `LABEL=data` |
| **2. Точка монтирования** | Каталог назначения | `/mnt/data`, `/home` |
| **3. Тип ФС** | Формат файловой системы | `ext4`, `xfs`, `ntfs`, `nfs`, `cifs` |
| **4. Опции** | Параметры монтирования | `defaults`, `rw`, `ro`, `noauto`, `nofail` |
| **5. Dump** | Резервное копирование (`dump`) | `0` — отключено, `1` — включено |
| **6. Pass** | Порядок проверки `fsck` | `0` — не проверять, `1` — корневая ФС, `2` — остальные |

**Пример записи:**
```
UUID=a1b2c3d4-e5f6-7890    /mnt/backup    ext4    defaults,nofail    0    2
```

#### Расширенное описание полей

**1. `<file system>`**: Устройство или ресурс для монтирования.
* **Рекомендуемый способ:** `UUID=<uuid>` — самый надёжный метод, так как UUID уникален и не меняется. Узнать UUID: `sudo blkid`.
* **Альтернатива:** Путь к устройству (`/dev/sda1`) — менее надёжно, имя может измениться после перезагрузки.
* Для сетевых ФС: `user@host:/path`.

2. **`<mount point>`**: Директория в файловой системе, к которой будет "привязан" ресурс (например, `/home`, `/var/log`). Директория должна существовать.

3. **`<type>`**: Тип файловой системы.
    * Для дисков: `ext4`, `xfs`, `btrfs`, `vfat`.
    * Для сетевых ФС: `nfs`, `cifs`.
    * Для swap: `swap`.
    * `auto`: Позволяет системе автоматически определить тип ФС.

4. **`<options>`**: Опции монтирования, перечисляются через запятую.
    * `defaults`: Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
    * `rw` / `ro`: Монтировать в режиме чтение/запись или только чтение.
    * `noatime`: Не обновлять `atime` (время последнего доступа) для файлов. Это может повысить производительность диска, так как сокращает количество операций записи.
    * `nofail`: Не останавливать загрузку системы, если устройство не может быть смонтировано. Критически важно для съёмных дисков или сетевых ресурсов.
    * `user`: Разрешить обычному пользователю монтировать файловую систему.

5. **`<dump>`**: Используется утилитой `dump` для определения, нужно ли создавать резервную копию файловой системы.
    * `0`: Не делать дамп.
    * `1`: Делать дамп.
    * На практике почти всегда установлено в `0`.

**6. `<pass>`**: пределяет порядок проверки файловых систем утилитой `fsck` при загрузке.
    * `0`: Не проверять.
    * `1`: Устанавливается для корневой файловой системы (`/`). Она проверяется первой.
    * `2`: Устанавливается для остальных файловых систем. Они проверяются после корневой.

### Команда mount -a

`mount -a` (mount all) монтирует все файловые системы из `/etc/fstab`, которые:
* Имеют опцию `auto` (или не имеют `noauto`)
* Ещё не смонтированы

```bash
# Применить все изменения из /etc/fstab без перезагрузки
sudo mount -a
```

Записи с опцией `noauto` пропускаются — они монтируются только вручную.

После правки `/etc/fstab` не нужно перезагружаться или монтировать всё вручную — достаточно одной команды `mount -a`.

## Практические сценарии

### Сценарий 1: Быстрое добавление нового раздела

Полный рабочий процесс добавления нового диска:

```bash
# 1. Создаём точку монтирования
sudo mkdir /data

# 2. Определяем UUID раздела
sudo blkid /dev/sdc1

# 3. Добавляем в /etc/fstab
# UUID=xxx /data ext4 defaults 0 2
echo 'UUID=xxx /data ext4 defaults 0 2' | sudo tee -a /etc/fstab

# 4. Применяем изменения
sudo mount -a

# 5. Проверяем
sudo df -h /data
```

### Сценарий 2: Монтирование директории на отдельный диск через fstab

Чтобы содержимое определённой директории (например, `/var/log` или `/home/user/data`) физически хранилось на отдельном диске, необходимо выполнить следующие шаги:

1. **Подготовить диск**: Убедитесь, что на диске есть раздел и на нём создана файловая система.
    * Посмотреть диски и разделы: `lsblk`
    * Создать файловую систему (если нужно): `sudo mkfs.ext4 /dev/sdb1`

2. **Перенести существующие данные (если необходимо)**: Если в директории уже были данные, их нужно перенести на новый диск *до* настройки постоянного монтирования в `fstab`.

    ```sh
    # 1. Смонтировать новый диск во временную точку
    sudo mount /dev/sdb1 /mnt

    # 2. Скопировать данные со сохранением прав
    sudo rsync -av /path/to/directory/ /mnt/

    # 3. Переименовать старую директорию (для бэкапа)
    sudo mv /path/to/directory /path/to/directory.bak

    # 4. Создать пустую точку монтирования
    sudo mkdir /path/to/directory

    # 5. Размонтировать диск и смонтировать его в нужную точку
    sudo umount /mnt
    sudo mount /dev/sdb1 /path/to/directory
    ```

3. **Настроить автоматическое монтирование при загрузке**:
    * **Узнать UUID диска**: `sudo blkid /dev/sdb1`
    * **Добавить запись в `/etc/fstab`**:

        ```
        # <file system> <mount point>   <type>  <options>       <dump>  <pass>
        UUID=...      /path/to/directory ext4    defaults        0       2
        ```

    > **Важно:** Всегда используйте `UUID` устройства вместо его имени (`/dev/sdb1`). Имена устройств могут меняться после перезагрузки или подключения новых дисков, что приведет к ошибкам монтирования. `UUID` остается постоянным и гарантирует корректное монтирование.

4. **Проверить**: `sudo mount -a`. Если ошибок нет, можно удалить бэкап-директорию.

### Сценарий 3: Монтирование по требованию с помощью Systemd

**1. Юнит `.mount` для постоянного монтирования**

Юнит `.mount` определяет параметры монтирования. Его имя строится по пути к точке монтирования, где `/` заменяется на `-`. Например, для `/mnt/share` файл будет называться `mnt-share.mount`.

Пример `/etc/systemd/system/mnt-share.mount`:

```ini
[Unit]
Description=Mount network share
After=network-online.target  # Убедиться, что сеть доступна

[Mount]
What=//192.168.0.10/share
Where=/mnt/share
Type=cifs
Options=credentials=/etc/smb.cred,_netdev,vers=3.0

[Install]
WantedBy=multi-user.target
```

**Пояснения к секциям:**

* **`[Unit]`**: Общие метаданные для юнита. `Description` — описание, `After=network-online.target` — указывает, что юнит должен запускаться только после того, как будет доступна сеть (важно для сетевых ресурсов).
* **`[Mount]`**: Определяет параметры монтирования.
  * `What` — ресурс для монтирования (например, сетевая папка, как в примере `//192.168.0.10/share`).
  * `Where` — точка монтирования в локальной файловой системе (`/mnt/share`).
  * `Type` — тип файловой системы (`cifs` для SMB/CIFS, `nfs` для NFS, `ext4` для локальных дисков и т.д.).
  * `Options` — опции монтирования, аналогичные опциям в `/etc/fstab`. `_netdev` указывает, что это сетевой ресурс.
* **`[Install]`**: Определяет, как юнит будет интегрирован в систему при включении (`enable`). `WantedBy=multi-user.target` означает, что юнит будет запускаться при переходе в многопользовательский режим (стандартный режим работы сервера).

После создания файла юнита необходимо:

1. Создать точку монтирования: `sudo mkdir -p /mnt/share`
2. Перезагрузить systemd: `sudo systemctl daemon-reload`
3. Включить юнит для автоматического запуска при загрузке: `sudo systemctl enable mnt-share.mount`
4. Запустить юнит сейчас: `sudo systemctl start mnt-share.mount`
5. Проверить статус: `sudo systemctl status mnt-share.mount`

**2. Юнит `.automount` для монтирования по требованию**

Юнит `.automount` позволяет монтировать ресурс только при первом обращении к нему. Это ускоряет загрузку системы, если сетевые ресурсы не нужны сразу, или если сеть еще не поднята. Он работает в паре с соответствующим `.mount` юнитом.

Пример содержимого файла `mnt-share.automount` (например, `/etc/systemd/system/mnt-share.automount`):

```ini
[Unit]
Description=Automount network share

[Automount]
Where=/mnt/share
TimeoutIdleSec=600  # Отмонтировать через 10 минут бездействия

[Install]
WantedBy=multi-user.target
```

**Активация монтирования по требованию:**

```sh
sudo mkdir -p /mnt/share
sudo systemctl daemon-reload
# Включаем и запускаем только .automount юнит
sudo systemctl enable --now mnt-share.automount
sudo systemctl status mnt-share.automount
```

При первой попытке доступа к `/mnt/share` systemd автоматически активирует `mnt-share.mount`.

### Сценарий 4: Монтирование по требованию с помощью Autofs

1. **Установите `autofs`**: `sudo apt install autofs`
2. **Настройте главный файл `/etc/auto.master`**. Добавьте строку:

    ```
    # <точка монтирования> <файл карты>   <опции>
    /-                      /etc/auto.direct --timeout=60
    ```

    `/-` означает, что пути в карте будут абсолютными, а `--timeout=60` — отмонтировать после 60 секунд бездействия.
3. **Создайте и настройте файл карты `/etc/auto.direct`**:

    ```
    # <полный путь>  <опции монтирования>  <источник>
    /mnt/data         -fstype=ext4,rw       :/dev/disk/by-uuid/1234-ABCD-5678-EFGH
    ```

    Обратите внимание на синтаксис: опции идут до источника, а перед источником ставится двоеточие `:`.
4. **Перезапустите сервис**: `sudo systemctl restart autofs`.

### Сценарий 5: Монтирование по событию с помощью правил Udev

1. **Найдите уникальные атрибуты диска**, например, серийный номер.

    ```bash
    udevadm info -a -n /dev/sdb1 | grep 'serial'
    # Вывод: ATTRS{serial}=="123456789"
    ```

2. **Создайте файл правила** `/etc/udev/rules.d/99-mydisk.rules`.

    ```
    ACTION=="add", KERNEL=="sd*", ATTRS{serial}=="123456789", RUN+="/bin/mount /dev/%k /mnt/data"
    ```

    Это правило говорит: "когда добавляется (`add`) устройство, имя которого начинается на `sd*` и у которого серийный номер `123456789`, выполнить команду монтирования". `%k` подставит имя устройства (например, `sdb1`).
3. **Перезагрузите правила `udev`**:
    Более подробно об управлении правилами `udev` см. в разделе [Управление правилами `udev`](../Core/udev.md#Управление-правилами-udev).

## Дополнительная информация

### Проверка конфигурации fstab

После редактирования `/etc/fstab` всегда проверяйте корректность командой:

```bash
sudo mount -a
```

Если команда выполнилась без ошибок — синтаксис корректен. **Важно:** всегда выполняйте эту проверку перед перезагрузкой системы, чтобы избежать ситуации, когда система не может загрузиться из-за ошибки в fstab.

### Полезные команды для работы с монтированием

```bash
# Просмотр смонтированных файловых систем
mount | grep /data
df -hT

# Получение UUID устройства
sudo blkid /dev/sdb1
lsblk -f

# Размонтирование
sudo umount /mnt/data

# Принудительное размонтирование (если ресурс занят)
sudo umount -l /mnt/data  # "lazy" отмонтирование
sudo umount -f /mnt/data  # "force" (для недоступных NFS)
```
