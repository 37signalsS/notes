# Восстановление таблиц разделов: MBR и GPT

## Определения

- **MBR (Master Boot Record):** Устаревший стандарт таблицы разделов, занимающий первые 512 байт диска. Содержит загрузчик (446 байт) и таблицу из 4 основных разделов (4×16 байт).
- **GPT (GUID Partition Table):** Современный стандарт таблицы разделов. Поддерживает диски >2 ТБ, до 128 разделов по умолчанию. Ключевая особенность — дублирование таблицы в конце диска (Secondary/Backup GPT).
- **Primary GPT:** Основная таблица разделов в начале диска.
- **Secondary (Backup) GPT:** Резервная копия таблицы разделов в конце диска.

## Основные концепции

### Сравнение MBR и GPT

| Характеристика | MBR | GPT |
| :--- | :--- | :--- |
| **Макс. размер диска** | 2 ТБ | Практически не ограничен |
| **Макс. разделов** | 4 основных (или 3 + расширенный) | 128 по умолчанию |
| **Надёжность** | Таблица в одном месте | Дублируется в начале и конце диска |
| **Статус** | Устаревший | Современный стандарт |

### Критичность восстановления

- **MBR:** Повреждение MBR блокирует загрузку ОС и доступ к разделам. Данные в разделах остаются нетронутыми.
- **GPT:** Повреждение Primary GPT восстанавливается из Secondary GPT. При повреждении обеих таблиц — сканирование диска по сигнатурам ФС.

### Приоритет сохранения данных

**Перед любыми операциями:**

1. **Отмонтировать диск** или смонтировать в режиме «только чтение»: `mount -o remount,ro /dev/sdX`
2. **Создать резервную копию** таблицы разделов
3. **Использовать отдельный носитель** для хранения бэкапов и восстановленных данных

## Практические сценарии

### Резервное копирование таблиц разделов

**MBR:**

```bash
# Бэкап первых 512 байт (MBR)
dd if=/dev/sda of=mbr_backup.img bs=512 count=1

# Восстановление (полная перезапись MBR)
dd if=mbr_backup.img of=/dev/sda bs=512 count=1
```

**GPT:**

```bash
# Бэкап заголовка и таблицы разделов (34 сектора = 17 КБ)
dd if=/dev/sda of=gpt_backup.img bs=512 count=34

# Восстановление
dd if=gpt_backup.img of=/dev/sda bs=512 count=34
```

### Восстановление с помощью gdisk (GPT)

`gdisk` автоматически обнаруживает несоответствие Primary/Secondary GPT и предлагает восстановление.

**Сценарий:** Primary GPT повреждена, Secondary GPT в порядке.

```bash
gdisk /dev/sda
```

Ручное восстановление:

1. `r` — recovery & transformation options
2. `c` — load backup partition table
3. `w` — сохранить изменения

**Сценарий: Конфликт GPT и программного RAID (MDADM)**
Если на диске ранее была разметка GPT, а затем он был добавлен в RAID-массив без полной очистки, может возникнуть конфликт. Суперблок RAID записывается в начало диска (затирая Primary GPT), но **Secondary GPT в конце диска сохраняется**.

- **Проблема:** При загрузке система может обнаружить валидную Secondary GPT и автоматически «восстановить» старую таблицу разделов поверх данных RAID, что приведет к развалу массива.
- **Решение (полная очистка всех структур GPT):**
  - **Через `gdisk`:** `x` (expert mode) → `z` (zap) → подтвердить удаление GPT и MBR.
  - **Через `sgdisk`:** `sudo sgdisk --zap-all /dev/sdX`.

При расширении виртуального диска Secondary GPT не смещается автоматически:

1. `gdisk /dev/sda`
2. Изменить/создать раздел для использования нового пространства
3. При `w` `gdisk` автоматически переместит Secondary GPT

> **Важно:** `gdisk` не позволит изменить раздел за пределы Secondary GPT без её пересоздания.

### Восстановление разделов через fdisk (MBR)

**Сценарий:** Разделы случайно удалены из таблицы MBR.

1. `fdisk /dev/sda`
2. `p` — просмотреть текущую таблицу, записать начальные секторы
3. `d` — удалить раздел, `n` — создать заново с **тем же начальным сектором**
4. `w` — сохранить
5. `partprobe /dev/sda` — обновить таблицу разделов ядра (или перезагрузить)

> **Важно:** Удаление раздела не стирает данные — таблица разделов содержит только метаданные.

### Расширенные и логические разделы (MBR)

MBR ограничивает число основных разделов до 4. **Расширенный раздел** — контейнер для **логических разделов**.

**Порядок восстановления:**

1. Восстановить расширенный раздел
2. Восстановить логические разделы внутри него

### Сканирование диска с TestDisk

Если положение разделов неизвестно — `testdisk` сканирует диск по сигнатурам файловых систем:

```bash
sudo testdisk /dev/sda
```
