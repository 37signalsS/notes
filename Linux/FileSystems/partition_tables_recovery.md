# Восстановление таблиц разделов: MBR и GPT

## Определения

- **MBR (Master Boot Record):** Устаревший стандарт таблицы разделов, занимающий первые 512 байт диска. Содержит загрузчик (446 байт) и таблицу из 4 основных разделов (4×16 байт).
- **GPT (GUID Partition Table):** Современный стандарт таблицы разделов. Поддерживает диски >2 ТБ, до 128 разделов по умолчанию. Ключевая особенность — дублирование таблицы в конце диска (Secondary/Backup GPT).
- **Primary GPT:** Основная таблица разделов в начале диска.
- **Secondary (Backup) GPT:** Резервная копия таблицы разделов в конце диска.

## Основные концепции

### Сравнение MBR и GPT

| Характеристика | MBR | GPT |
| :--- | :--- | :--- |
| **Макс. размер диска** | 2 ТБ | Практически не ограничен |
| **Макс. разделов** | 4 основных (или 3 основных + расширенный) | 128 по умолчанию |
| **Надёжность** | Таблица хранится в одном месте | Дублируется в начале и конце диска |
| **Статус** | Устаревший | Современный стандарт |

### Критичность восстановления

- **MBR:** Повреждение делает невозможной загрузку ОС и доступ к разделам. Данные в разделах остаются нетронутыми.
- **GPT:** Повреждение Primary GPT может быть восстановлено из Secondary GPT. При повреждении обеих таблиц требуется сканирование диска.

### Приоритет сохранения данных

**Перед любыми операциями:**

1. **Отмонтировать диск** или смонтировать в режиме "только чтение":
   ```bash
   sudo mount -o remount,ro /dev/sdX
   ```
2. **Создать резервную копию** таблицы разделов (см. ниже).
3. **Использовать другой носитель** для сохранения восстановленных данных.

## Практические сценарии

### 1. Резервное копирование таблиц разделов

#### MBR — резервное копирование

```bash
# Копирование первых 512 байт (MBR)
dd if=/dev/sda of=mbr_backup.img bs=512 count=1

# Восстановление из резервной копии
# ВНИМАНИЕ: Полностью перезапишет текущую MBR
dd if=mbr_backup.img of=/dev/sda bs=512 count=1
```

#### GPT — резервное копирование

```bash
# Копирование заголовка и таблицы разделов (34 сектора = 17 КБ)
dd if=/dev/sda of=gpt_backup.img bs=512 count=34

# Восстановление
dd if=gpt_backup.img of=/dev/sda bs=512 count=34
```

### 2. Восстановление с помощью gdisk (GPT)

`gdisk` — стандартная утилита для работы с GPT. Автоматически обнаруживает повреждения и предлагает восстановить из Secondary GPT.

**Сценарий:** Primary GPT повреждена, Secondary GPT в порядке.

```bash
gdisk /dev/sda
```

`gdisk` обнаружит несоответствие и предложит использовать резервную копию. Для ручного восстановления:

1. Команда `r` (recovery & transformation options)
2. Команда `c` (load backup partition table)
3. Команда `w` (сохранить изменения)

**Увеличение размера диска (ВМ):**

При увеличении размера виртуального диска Secondary GPT не смещается автоматически:

1. `gdisk /dev/sda`
2. Изменить/создать раздел для использования нового пространства
3. При сохранении (`w`) `gdisk` автоматически переместит Secondary GPT

> **Важно:** `gdisk` не позволит изменить раздел за пределы Secondary GPT без её пересоздания.

### 3. Восстановление разделов с помощью fdisk (MBR)

**Сценарий:** Разделы случайно удалены из таблицы MBR.

1. Запустить `fdisk`:
   ```bash
   fdisk /dev/sda
   ```

2. Записать текущую таблицу (`p`) — записать начальные секторы.

3. Удалить раздел (`d`) и создать заново (`n`) с **тем же начальным сектором**.

4. Сохранить (`w`).

5. Обновить таблицу разделов ядра:
   ```bash
   partprobe /dev/sda
   ```
   Или перезагрузить систему.

> **Важно:** Данные не стираются при удалении раздела — таблица разделов это только метаданные.

### 4. Расширенные и логические разделы (MBR)

В MBR существует ограничение: максимум 4 основных раздела. Для обхода используется **расширенный раздел** — "контейнер" для **логических разделов**.

**При восстановлении:**

1. Сначала восстановить расширенный раздел.
2. Затем логические разделы внутри него.

> **Примечание:** В GPT таких ограничений нет.

### 5. Автоматическое сканирование с TestDisk

Если точное положение разделов неизвестно, используйте `testdisk` для сканирования диска.

```bash
sudo testdisk /dev/sda
```

`testdisk` найдет удалённые разделы по сигнатурам файловых систем и позволит восстановить таблицу.

См. также [Логическое восстановление данных](./data_recovery.md) для подробной информации.

## Дополнительная информация

### Поле pass в /etc/fstab

Порядок проверки файловых систем при загрузке определяется полем `<pass>` в `/etc/fstab`. См. [Управление монтированием файловых систем](./mounting/fstab.md).

### Фрагментация и выравнивание

- **Выравнивание разделов:** Современные утилиты (`parted`, `fdisk`) автоматически выравнивают разделы по границам мегабайта.
- **Фрагментация:** Для Ext3/Ext4 менее критична благодаря extent-based allocation. См. [partitions_and_filesystems.md](./partitions_and_filesystems.md#Фрагментация-ext3-и-ext4).
