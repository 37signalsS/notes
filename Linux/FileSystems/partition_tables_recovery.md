# Восстановление таблиц разделов: MBR и GPT

## Определения

- **MBR (Master Boot Record):** Первый сектор диска (LBA 0), содержащий первичный загрузчик (446 байт), таблицу из 4 разделов (64 байта) и сигнатуру `0x55AA`. Ограничен дисками до 2.2 ТБ.
- **GPT (GUID Partition Table):** Современный стандарт разметки (часть UEFI), использующий LBA-адресацию и GUID для идентификации. Данные защищены контрольными суммами CRC32.
- **Protective MBR:** Слой совместимости в первом секторе диска GPT. Предотвращает перезапись диска старыми утилитами, помечая весь диск как один раздел типа `0xEE`.
- **Primary GPT Header:** Основной заголовок и таблица разделов (LBA 1 и далее).
- **Secondary GPT (Backup Header):** Копия таблицы разделов, хранящаяся в последних 33 секторах диска. Позволяет восстановить разметку при повреждении начала диска.

## Основные концепции

### Сравнение стандартов разметки

| Характеристика | MBR (Legacy) | GPT (Modern) |
| :--- | :--- | :--- |
| **Макс. объем диска** | 2.2 ТБ | 9.4 ЗБ (при секторах 512Б) |
| **Лимит разделов** | 4 основных (или 3 + Extended) | 128 (по умолчанию в Linux) |
| **Избыточность** | Нет (одна копия в LBA 0) | Да (Primary и Secondary копии) |
| **Целостность** | Не проверяется | Контрольные суммы CRC32 |
| **Адресация** | 32-bit (LBA) | 64-bit (LBA) |

### Механика повреждений

- **Повреждение MBR:** Уничтожение первого сектора (например, `dd if=/dev/zero ... count=1`) делает диск неразмеченным для ОС. Данные внутри разделов сохраняются, но их границы теряются.
- **Повреждение GPT:** Если поврежден Primary Header (LBA 1), ядро автоматически пытается использовать Secondary Header из конца диска. Если повреждены оба, требуется низкоуровневое сканирование.

### Правила безопасности при восстановлении

1.  **Запрет записи:** Не создавайте новые разделы и не форматируйте диск до завершения восстановления.
2.  **Режим Read-Only:** Используйте `mount -o remount,ro` или работайте с отмонтированным устройством.
3.  **Бэкап метаданных:** Перед любым исправлением сделайте дамп текущего состояния таблицы (даже если оно кажется поврежденным).
4.  **Смена носителя:** Сохраняйте дампы и восстановленные файлы на **другой** физический диск.

## Практические сценарии

### 1. Резервное копирование и экспорт разметки

**Метод А: Текстовый дамп (sfdisk — рекомендуется)**
Позволяет восстановить разметку на диск другого объема (если он больше исходного).
```bash
# Экспорт в файл
sudo sfdisk -d /dev/sda > partitions_backup.txt

# Импорт (восстановление)
sudo sfdisk /dev/sda < partitions_backup.txt
```

**Метод Б: Бинарный бэкап GPT (sgdisk)**
Копирует заголовок и таблицу разделов в бинарный файл.
```bash
sudo sgdisk --backup=sda_gpt.bak /dev/sda
# Восстановление:
sudo sgdisk --load-backup=sda_gpt.bak /dev/sda
```

### 2. Восстановление GPT из резервной копии (gdisk)

Утилита `gdisk` — основной инструмент для работы с "битыми" GPT.

1.  Запуск: `sudo gdisk /dev/sda`.
2.  При обнаружении ошибок GPT предложит выбрать, какую копию использовать.
3.  Для ручного восстановления из Backup Header:
    -   Нажать `r` (Recovery/transformation).
    -   Нажать `d` (Use backup GPT header) или `c` (Load backup partition table).
    -   Проверить структуру: `p`.
    -   Записать на диск: `w`.

### 3. Конфликт GPT и сигнатур RAID/LVM

**Проблема:** При добавлении диска в RAID без очистки GPT, Secondary GPT в конце диска сохраняется. После удаления RAID ОС может увидеть старую разметку GPT и проигнорировать новые данные.

**Решение (полная очистка всех структур):**
```bash
# Удаление GPT и MBR структур без удаления данных в центре диска
sudo sgdisk --zap-all /dev/sdX

# Проверка и удаление оставшихся сигнатур ФС/RAID
sudo wipefs -a /dev/sdX
```

### 4. Исправление GPT после расширения диска (VM)

В виртуальных средах после увеличения диска Secondary GPT оказывается "в середине" объема.

**Метод А: Интерактивный (gdisk)**
1.  `sudo gdisk /dev/sda` → Вход в экспертный режим: `x`.
2.  Переместить структуры в конец: `e`.
3.  Сохранить: `w`.

**Метод Б: CLI (sgdisk)**
```bash
sudo sgdisk -e /dev/sda
```

### 5. Ручное восстановление разделов по границам (fdisk)

Если таблица удалена, но вы знаете точные начальные секторы разделов (например, из старых логов), их можно восстановить "вслепую".

1.  Запуск: `fdisk /dev/sda`.
2.  Создать новый раздел (`n`). Указать **тот же начальный сектор**.
3.  Если утилита обнаружит старую сигнатуру ФС, **откажитесь от её удаления** (Answer: `N`).
4.  Записать таблицу: `w`.

### 6. Использование TestDisk для автоматического поиска

Если границы разделов полностью потеряны, используйте поиск по сигнатурам ФС.

1.  `sudo testdisk /dev/sdX`.
2.  Выберите тип таблицы (**EFI GPT** или **Intel** для MBR).
3.  `Analyse` → `Quick Search`.
4.  Если разделы найдены корректно (можно проверить содержимое через `P`), выберите их и нажмите `Write`.
