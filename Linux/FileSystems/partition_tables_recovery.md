# Восстановление таблиц разделов: MBR и GPT

## Определения

- **MBR (Master Boot Record — главная загрузочная запись):** Устаревший стандарт структуры разделов, располагающийся в первом секторе диска (512 байт). Содержит код загрузчика (446 байт), таблицу разделов (64 байта) и сигнатуру (`0x55AA`).
- **GPT (GUID Partition Table — таблица разделов на базе GUID):** Современный стандарт разметки диска, являющийся частью инициативы **UEFI (Unified Extensible Firmware Interface — унифицированный расширяемый интерфейс прошивки)**. Использует глобально уникальные идентификаторы (**GUID**, Globally Unique Identifier) для разделов.
- **Primary GPT (Основная GPT):** Таблица разделов, расположенная в начале диска (LBA 1).
- **Secondary GPT (Резервная GPT):** Точная копия основной таблицы, хранящаяся в последних секторах диска. Обеспечивает возможность восстановления при повреждении основной структуры.

## Основные концепции

### Сравнение MBR и GPT

| Характеристика | MBR | GPT |
| :--- | :--- | :--- |
| **Максимальный размер диска** | 2.2 ТБ (Terabyte) | До 9.4 ЗБ (Zettabyte) |
| **Количество разделов** | 4 основных (или 3 + расширенный) | До 128 (по умолчанию в Linux) |
| **Надежность** | Таблица в одном месте | Дублирование в начале и конце диска |
| **Статус** | Устаревший | Современный стандарт |

### Критичность повреждений

- **MBR:** Повреждение первого сектора делает диск "пустым" для ОС и блокирует загрузку. Сами данные в разделах при этом остаются нетронутыми.
- **GPT:** Благодаря дублированию, повреждение основной таблицы обычно исправляется автоматически или вручную из резервной копии.

### Правила безопасности при восстановлении

**Перед любыми операциями:**

1. **Исключить запись:** Немедленно прекратить любые операции записи на диск.
2. **Только чтение:** По возможности смонтировать ФС в режиме read-only: `mount -o remount,ro /dev/sdX`.
3. **Бэкап метаданных:** Создать копию текущей таблицы разделов перед попытками исправления.
4. **Внешний носитель:** Всегда сохраняйте восстановленные данные и бэкапы на отдельное физическое устройство.

## Практические сценарии

### 1. Резервное копирование таблиц разделов (утилита dd)

**Бэкап MBR:**

```bash
# Копирование первых 512 байт
dd if=/dev/sda of=mbr_backup.img bs=512 count=1
```

**Бэкап GPT:**

```bash
# Копирование заголовка и таблицы (34 сектора)
dd if=/dev/sda of=gpt_backup.img bs=512 count=34
```

### 2. Восстановление GPT через gdisk

Утилита `gdisk` автоматически обнаруживает повреждение **Primary GPT** и предлагает использовать **Secondary GPT**.

**Сценарий:** Заголовок поврежден, но резервная копия цела.

1. Запуск: `sudo gdisk /dev/sda`.
2. Вход в режим восстановления: нажать `r` (**recovery & transformation options**).
3. Загрузка резервной таблицы: нажать `c` (**load backup partition table from disk**).
4. Проверка: нажать `p` для просмотра списка разделов.
5. Запись изменений: нажать `w`.

### 3. Конфликт GPT и программного RAID (mdadm)

Если диск с GPT был добавлен в **RAID (Redundant Array of Independent Disks)** без очистки, метаданные RAID затирают Primary GPT, но **Secondary GPT в конце диска сохраняется**. При загрузке ОС может обнаружить старую разметку и попытаться "восстановить" её поверх данных RAID.

**Решение (полная очистка структур GPT):**

```bash
# Полное удаление всех структур разметки
sudo sgdisk --zap-all /dev/sdX
```

### 4. Расширение виртуального диска (GPT)

При увеличении размера диска в виртуальной машине **Secondary GPT** оказывается не в конце диска, а в середине, что блокирует расширение последнего раздела.

**Исправление через gdisk:**

1. `sudo gdisk /dev/sda`.
2. Перейти в экспертный режим: `x`.
3. Переместить структуры в конец: `e` (**relocate backup data structures to the end of the disk**).
4. Сохранить: `w`.

### 5. Ручное восстановление MBR через fdisk

Если таблица разделов MBR удалена, её можно восстановить, создав разделы заново с **абсолютно теми же начальными секторами**.

1. `sudo fdisk /dev/sda`.
2. Посмотреть текущее состояние: `p`.
3. Создать новый раздел: `n`.
4. Указать тот же номер и **Start sector**.
5. На вопрос **"Remove signature?"** обязательно ответить **N** (No).
6. Применить изменения: `w` и `partprobe /dev/sda`.

### 6. Глубокое сканирование через TestDisk

Если границы разделов неизвестны, **TestDisk** сканирует диск по сигнатурам файловых систем.

1. Запуск: `sudo testdisk /dev/sda`.
2. Выбор типа разметки (**Intel** для MBR или **EFI GPT**).
3. Команда: `Analyse` → `Quick Search`.
4. Если разделы найдены, нажать `Write` для записи таблицы на диск.
