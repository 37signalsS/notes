# Виртуальные и псевдофайловые системы Linux

## Определения

- **VFS (Virtual File System — виртуальная файловая система):** Слой абстракции в ядре Linux, предоставляющий унифицированный интерфейс (системные вызовы `open`, `read`, `write`) для взаимодействия с различными типами файловых систем. Благодаря VFS приложения работают с файлами одинаково, независимо от того, хранятся ли они на диске, в памяти или на удаленном сервере.
- **Псевдофайловая система (Pseudo-filesystem):** Тип файловой системы, которая не управляет данными на физических накопителях. Содержимое таких ФС генерируется ядром "на лету" и обычно хранится в оперативной памяти.
- **Tmpfs (Temporary File System — временная файловая система):** Псевдофайловая система, предназначенная для хранения временных данных в виртуальной памяти (**RAM** + **Swap**).
- **Ramfs (RAM File System):** Устаревший аналог `tmpfs`, работающий исключительно в оперативной памяти без возможности сброса данных в раздел подкачки (**Swap**).

## Основные концепции

### Роль VFS в архитектуре ядра

VFS выступает посредником между пространством пользователя и конкретными драйверами ФС. Она преобразует абстрактные операции в специфичные для каждой системы действия.

- **Преимущество:** Обеспечивает прозрачность доступа к данным.
- **Кэширование:** На уровне VFS реализуются механизмы **Page Cache** (кэширование данных файлов) и **Dentry Cache** (кэширование путей для ускорения поиска).

### Характеристики Tmpfs

`tmpfs` является наиболее часто используемой псевдо-ФС для временных данных:

- **Динамическое выделение:** Память потребляется только по мере записи данных (в отличие от RAM-дисков, резервирующих весь объем сразу).
- **Использование Swap:** При нехватке физической **RAM** неиспользуемые страницы `tmpfs` могут быть вытеснены в раздел подкачки.
- **Энергозависимость:** Все данные уничтожаются при перезагрузке системы или размонтировании.

### Другие псевдофайловые системы

В Linux существует несколько специализированных интерфейсов к ядру:

- **procfs (`/proc`):** Информация о процессах и системных переменных. Подробнее: **[Виртуальная файловая система /proc](./virtual_fs_proc.md)**.
- **sysfs (`/sys`):** Топология устройств и управление атрибутами оборудования. Подробнее: **[Виртуальная файловая система /sys](./virtual_fs_sys.md)**.
- **devtmpfs (`/dev`):** Динамическое управление узлами устройств. Подробнее: **[Виртуальная файловая система /dev](./virtual_fs_dev.md)**.
- **cgroupfs (`/sys/fs/cgroup`):** Интерфейс для управления контрольными группами ресурсов. Подробнее: **[Cgroups (Контрольные группы)](../Core/cgroups.md)**.

## Практические сценарии

### Использование Tmpfs в системе

| Точка монтирования | Назначение |
| :--- | :--- |
| `/run` | Состояние запущенных демонов (PID-файлы, сокеты). |
| `/dev/shm` | Разделяемая память для межпроцессного взаимодействия (**IPC**, Inter-Process Communication). |
| `/tmp` | Временные файлы пользователей и приложений (в большинстве дистрибутивов). |

### Монтирование Tmpfs вручную

Создание временного хранилища с ограничением по размеру:

```bash
# Создать точку монтирования и смонтировать 512 МБ памяти
sudo mkdir -p /mnt/tmp_ram
sudo mount -t tmpfs -o size=512M tmpfs /mnt/tmp_ram
```

Настройка автоматического монтирования в `/etc/fstab`:

```text
tmpfs /mnt/tmp_ram tmpfs defaults,size=1G 0 0
```

### Сравнение Ramfs и Tmpfs

| Характеристика | Ramfs | Tmpfs |
| :--- | :--- | :--- |
| **Носитель** | Только **RAM** | **RAM** + **Swap** |
| **Лимит размера** | Нет (может вызвать **OOM**, Out of Memory) | Настраиваемый (флаг `size`) |
| **Гибкость** | Низкая | Высокая |
