# Виртуальные и псевдофайловые системы Linux

## Определения

- **VFS (Virtual File System):** Высокоуровневый слой абстракции в ядре Linux, предоставляющий унифицированный программный интерфейс (POSIX) для взаимодействия с разнородными файловыми системами. Благодаря VFS приложения работают с файлами одинаково, независимо от того, хранятся ли они на диске, в памяти или в сетевом облаке.
- **Псевдофайловая система (Pseudo-filesystem):** Специализированная файловая система, содержимое которой не хранится на физических носителях. Данные генерируются ядром «на лету» или хранятся исключительно в оперативной памяти.
- **Интерфейс «Ядро — Пространство пользователя»:** Основная роль большинства псевдо-ФС в качестве канала экспорта системной статистики и управления параметрами ядра без использования специфических системных вызовов.

## Основные концепции

### Архитектура: VFS и псевдо-ФС

VFS преобразует абстрактные вызовы (например, `read()`) в вызовы конкретных функций драйвера ФС. В случае псевдо-ФС эти функции обращаются напрямую к структурам данных в памяти ядра.

| Тип системы | Назначение | Примеры |
| :--- | :--- | :--- |
| **Общего назначения** | Хранение временных данных в RAM | `tmpfs`, `ramfs` |
| **Информационные** | Экспорт статистики и состояния | `procfs`, `sysfs` |
| **Конфигурационные** | Тонкая настройка объектов ядра | `configfs`, `cgroupfs` |
| **Отладочные** | Глубокий анализ и трассировка | `debugfs`, `tracefs` |
| **Специфические** | Безопасность и спец-объекты | `securityfs`, `bpffs`, `efivarfs` |

### Временные файловые системы (Tmpfs)

`tmpfs` — наиболее востребованная псевдо-ФС для повседневных задач администрирования.
- **Динамичность:** Память потребляется только под реальный объем записанных данных.
- **Использование Swap:** При нехватке оперативной памяти данные могут вытесняться в область подкачки.
- **Энергозависимость:** Все данные теряются при размонтировании или перезагрузке.

## Обзор ключевых псевдофайловых систем

| Система | Точка монтирования | Описание |
| :--- | :--- | :--- |
| **`procfs`** | `/proc` | Информация о процессах и системных лимитах. Подробнее: [Виртуальная ФС /proc](./virtual_fs_proc.md). |
| **`sysfs`** | `/sys` | Объектная модель устройств и драйверов. Подробнее: [Виртуальная ФС /sys](./virtual_fs_sys.md). |
| **`devtmpfs`** | `/dev` | Динамическое управление узлами устройств. Подробнее: [Виртуальная ФС /dev](./virtual_fs_dev.md). |
| **`cgroupfs`** | `/sys/fs/cgroup` | Управление контрольными группами ресурсов. Подробнее: [Cgroups](../Core/cgroups.md). |
| **`configfs`** | `/sys/kernel/config` | Альтернатива `sysctl` для динамического создания объектов (например, iSCSI таргеты). |
| **`debugfs`** | `/sys/kernel/debug` | Низкоуровневая отладка, не предназначенная для постоянного использования. |
| **`tracefs`** | `/sys/kernel/tracing` | Интерфейс для механизмов трассировки ядра (ftrace). |
| **`bpffs`** | `/sys/fs/bpf` | Хранение закрепленных (pinned) объектов eBPF. |

## Практические сценарии

### 1. Оптимизация производительности через Tmpfs

Монтирование каталога компиляции или кэша приложения в RAM значительно сокращает задержки.

```bash
# Создание точки монтирования
sudo mkdir -p /mnt/app_cache

# Монтирование с ограничением 2 ГБ и запретом исполнения файлов (security hardening)
sudo mount -t tmpfs -o size=2G,noexec,nosuid,nodev tmpfs /mnt/app_cache
```

### 2. Управление системными конфигурациями (Configfs)

Использование `configfs` для настройки iSCSI или USB-гаджетов требует создания каталогов, которые ядро интерпретирует как команды на создание объектов.

```bash
# Пример: ядро автоматически создаст структуру подкаталогов при mkdir в configfs
sudo mkdir /sys/kernel/config/target/iscsi/iqn.2026-07.com.example:storage
```
