# Дисковые квоты

## Определения

- **Дисковая квота (Disk Quota):** Системный механизм ограничения потребления ресурсов файловой системы. Позволяет лимитировать объем данных или количество создаваемых объектов (inodes) для конкретных пользователей, групп или проектов.
- **Мягкий лимит (Soft Limit):** Порог, при достижении которого пользователю высылается предупреждение. Запись данных разрешена до истечения **льготного периода**.
- **Жесткий лимит (Hard Limit):** Абсолютный предел. Любая попытка записи, превышающая этот порог, блокируется немедленно с ошибкой `Disk quota exceeded`.
- **Льготный период (Grace Period):** Время (по умолчанию 7 дней), в течение которого разрешено превышение мягкого лимита. Если лимит не будет снижен до истечения периода, мягкий лимит блокирует запись аналогично жесткому.
- **Проектные квоты (Project Quotas):** Механизм ограничения места для конкретного каталога (дерева каталогов), независимо от того, какие пользователи в нем пишут. Широко применяется в контейнеризации и общих папках.

## Основные концепции

### Типы ресурсов для ограничения

1.  **Блочные квоты (Block Quotas):** Ограничивают суммарный объем данных (в КБ/МБ/ГБ).
2.  **Квоты Inode (Inode Quotas):** Ограничивают количество файлов, каталогов и ссылок. Предотвращают исчерпание таблицы дескрипторов ФС (атаки «миллион пустых файлов»).

### Реализация в разных ФС

- **Ext4:** Требует создания файлов `aquota.user` / `aquota.group` в корне раздела. Метаданные квот хранятся в скрытых системных файлах.
- **XFS:** Квоты являются нативной частью метаданных ФС. Не требуют дополнительных файлов и работают значительно быстрее. Поддерживают проектные квоты (`prjquota`).

## Практические сценарии

### 1. Настройка традиционных квот (ext4)

**Шаг 1: Настройка монтирования**
В файле `/etc/fstab` добавьте опции `usrquota` и `grpquota`:
```text
UUID=... /home ext4 defaults,usrquota,grpquota 0 2
```

**Шаг 2: Инициализация и включение**
```bash
# Перемонтирование
sudo mount -o remount /home

# Создание файлов индексов (БД квот)
sudo quotacheck -ugcm /home

# Включение системы квот
sudo quotaon -v /home
```

### 2. Настройка современных квот (XFS)

XFS не требует инициализации через `quotacheck`.

**Шаг 1: Монтирование с поддержкой квот**
```text
# В /etc/fstab: uquota - пользователи, gquota - группы, pquota - проекты
UUID=... /data xfs defaults,uquota,pquota 0 0
```

**Шаг 2: Управление через xfs_quota**
Утилита `xfs_quota` предоставляет интерактивную оболочку или принимает команды через `-c`.
```bash
# Установка лимита пользователю (Мягкий: 10ГБ, Жесткий: 11ГБ)
sudo xfs_quota -x -c 'limit bsoft=10g bhard=11g user1' /home

# Просмотр сводного отчета
sudo xfs_quota -x -c 'report -h' /home
```

### 3. Проектные квоты (Ограничение папки)

Позволяет ограничить размер конкретной директории, например, под логи.

```bash
# 1. Присвоить ID проекта каталогу (в файле /etc/projects)
echo "10:/var/log/app" >> /etc/projects
echo "log_project:10" >> /etc/projid

# 2. Инициализация проекта
sudo xfs_quota -x -c 'project -s log_project' /var/log/app

# 3. Установка лимита на папку
sudo xfs_quota -x -c 'limit -p bhard=5g log_project' /var/log/app
```

## Диагностика и мониторинг

- **Проверка квот для текущего пользователя:**
  ```bash
  quota -s
  ```
- **Сводный отчет по всем пользователям (ext4):**
  ```bash
  sudo repquota -as
  ```
- **Изменение льготного периода:**
  ```bash
  sudo edquota -t
  ```
