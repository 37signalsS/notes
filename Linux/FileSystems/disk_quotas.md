# Дисковые квоты

## Определения

- **Дисковая квота (Disk Quota):** Системный механизм ограничения потребления ресурсов файловой системы. Позволяет лимитировать объем данных или количество создаваемых объектов (inodes) для конкретных пользователей, групп или проектов.
- **Мягкий лимит (Soft Limit):** Порог, при достижении которого пользователю высылается предупреждение. Запись данных разрешена до истечения **льготного периода**.
- **Жесткий лимит (Hard Limit):** Абсолютный предел. Любая попытка записи, превышающая этот порог, блокируется немедленно с ошибкой `Disk quota exceeded`.
- **Льготный период (Grace Period):** Время (по умолчанию 7 дней), в течение которого разрешено превышение мягкого лимита. После истечения периода мягкий лимит блокирует запись аналогично жесткому до тех пор, пока использование ресурса не упадет ниже порога.
- **Проектные квоты (Project Quotas):** Механизм ограничения места для конкретной иерархии каталогов (дерева), независимо от владельцев файлов. Широко применяется в контейнеризации и многопользовательских shared-директориях.
- **dquot (Disk Quota Structure):** Структура данных в оперативной памяти ядра Linux, содержащая запись о квоте для одной пары (субъект, файловая система). Хранит текущее использование по блокам и inode, мягкие/жесткие лимиты, таймер льготного периода и флаги состояния.
- **quotaon / quotaoff:** Команды для включения и выключения принудительной проверки квот в работающей системе. При включении ядро начинает активировать проверку лимитов для каждой операции записи.
- **quotacheck:** Утилита для сканирования файловой системы и построения текущей базы использования квот. Для классических квот ext4 создает/обновляет файлы `aquota.user` и `aquota.group` в корне раздела. Должна запускаться при несмонтированной ФС для гарантии целостности.
- **repquota:** Утилита для генерации отчета о текущем состоянии всех квот на файловой системе. Читает файлы `aquota.*` (ext4) или метаданные dquots (XFS).
- **edquota:** Утилита для редактирования лимитов конкретного пользователя (`-u`) или группы (`-g`) через текстовый редактор. Ключ `-p` копирует лимиты с шаблонного субъекта на список пользователей/групп, `-t` редактирует льготный период (grace period) для всех файловых систем с квотами.
- **setquota:** Команда для пакетной установки лимитов без интерактивного редактора. Используется в скриптах автоматизации и массовых операциях.
- **xfs_quota:** Утилита для управления квотами в XFS. Поддерживает пользовательские, групповые и проектные квоты.
- **rpc.rquotad (rpc.rquota):** Сетевой демон, предоставляющий информацию о квотах по протоколу NFS. Позволяет клиентам видеть квоты сервера при монтировании по NFS.
- **quota (пользовательская команда):** Утилита, с помощью которой пользователь может проверить собственное использование квот на смонтированных файловых системах.

## Основные концепции

### Типы ресурсов для ограничения

1.  **Блочные квоты (Block Quotas):** Ограничивают суммарный объем данных (в КБ/МБ/ГБ).
2.  **Квоты Inode (Inode Quotas):** Ограничивают количество файлов, каталогов и ссылок. Это критично для предотвращения атак типа «отказ в обслуживании» через создание миллионов пустых файлов, что может исчерпать таблицу Inode при наличии свободного места на диске.

### Внутреннее устройство квот в ядре Linux

Квоты реализованы на уровне VFS (Virtual File System) и прозрачны для конкретной файловой системы, если та поддерживает механизм через `struct dquot`.

**Структура dquot:**
Для каждой тройки (UID/GID/PROJECTID, ФС) ядро хранит структуру `struct dquot`, содержащую:
- Текущее использование блоков и inode.
- Мягкие и жесткие лимиты.
- Время истечения льготного периода (`dqb_itime` для inode, `dqb_btime` для блоков).
- Флаги состояния (активна, превышен лимит, истекает grace period).

**Механизм проверки при записи:**
При каждой операции, потенциально изменяющей использование (например, `open(O_CREAT)`, `write`, `truncate`, `link`), VFS вызывает `dquot_alloc_block()` или `dquot_alloc_inode()`. Эти функции:
1. Находят соответствующую структуру `dquot` по UID/GID/PROJECTID.
2. Проверяют, не превысит ли операция жесткий лимит.
3. Если операция превышает мягкий лимит — проверяют, не истек ли льготный период.
4. При превышении возвращают `-EDQUOT`, который преобразуется в ошибку `Disk quota exceeded`.

**In-memory кэширование:**
При монтировании ФС с поддержкой квот ядро загружает все активные записи квот в оперативную память (hash-таблица по `dquot`). Это позволяет проверять лимиты без обращения к диску на каждую операцию. Изменения сбрасываются на диск периодически или при `quotaoff`/`umount`.

### Реализация в файловых системах

| Характеристика | Ext4 (Традиционные) | Ext4 (Внутренние) | XFS (Нативные) |
| :--- | :--- | :--- | :--- |
| **Хранение** | Файлы `aquota.*` в корне | Скрытые системные Inode | Метаданные (dquots) |
| **Целостность** | Риск рассинхрона при сбое | Журналируемые (атомарные) | Журналируемые |
| **Утилиты** | `quotacheck`, `quotaon` | Не требует `quotacheck` | `xfs_quota` |
| **Проектные квоты**| Нет | С ядра 4.4 (`prjquota`) | Да (полная поддержка) |

**Механизм In-memory:** При монтировании ФС с квотами ядро загружает структуры квот в оперативную память. При каждой операции записи ядро проверяет текущее использование против лимитов в структурах `dquot`.

### Классические (традиционные) квоты vs внутренние (journaled)

**Классические (user/group quotas):**
- Хранятся в файлах `aquota.user` и `aquota.group` в корне ФС.
- Требуют периодического запуска `quotacheck` для синхронизации с реальным использованием (особенно после некорректного отключения питания).
- Файлы видимы пользователям с root-доступом.
- При сбое питания база квот может рассинхронизироваться с реальным состоянием ФС.

**Внутренние (journaled) квоты:**
- Хранятся в специальных служебных inode внутри ФС (аналогично журналу).
- Изменения квот проходят через журнал ФС, обеспечивая атомарность.
- Не требуют `quotacheck` после сбоя — ядро восстанавливает состояние из журнала.
- Файлы `aquota.*` в корне не создаются.
- Начиная с ext4 с ядром 4.4+ являются рекомендуемым методом.

### Проектные квоты (Project Quotas)

Проектные квоты позволяют ограничивать место для иерархии каталогов (дерева) независимо от владельцев файлов. Используют специальный идентификатор проекта (project ID), хранящийся в inode файлов.

**Особенности:**
- В Ext4 поддерживаются с ядра 4.4 (нужна опция `prjquota` при монтировании).
- В XFS являются нативной возможностью с момента создания ФС.
- Применяются в контейнеризации (ограничение RW-слоя overlay2), веб-хостинге (ограничение места на сайт), системах резервного копирования.

## Практические сценарии

### 1. Настройка современных квот в Ext4 (Internal Quotas)

Это рекомендуемый метод для современных дистрибутивов, так как он не требует видимых файлов в корне и устойчив к сбоям.

```bash
# 1. Включение признака квот в метаданных ФС (выполняется на отмонтированном разделе)
sudo tune2fs -O quota /dev/sdb1

# 2. Настройка монтирования в /etc/fstab
# Опции usrquota и grpquota достаточны для внутреннего механизма
UUID=... /data ext4 defaults,usrquota,grpquota 0 2

# 3. Перемонтирование
sudo mount -o remount /data

# 4. Установка лимита (1ГБ мягкий, 1.1ГБ жесткий)
sudo setquota -u user1 1048576 1153434 0 0 /data

# 5. Проверка
sudo quota -u user1 /data
# → Disk quotas for user user1 (uid 1001):
# →  Filesystem  blocks       soft       hard     inods     soft     hard
# →  /dev/sdb1    850000   1048576   1153434        50        0        0
```

### 2. Настройка квот в XFS

В XFS квоты являются частью дизайна и включаются только на этапе монтирования.

```bash
# 1. Монтирование с поддержкой квот пользователей и проектов
# В /etc/fstab: uquota, pquota
UUID=... /mnt/xfs xfs defaults,uquota,gquota,pquota 0 2
sudo mount -o remount /mnt/xfs

# Альтернативно: монтирование через опции (не сохраняется после перезагрузки)
sudo mount -o uquota,pquota /dev/sdc1 /mnt/xfs

# 2. Установка лимитов через xfs_quota
# -x: экспертный режим, -c: команда
sudo xfs_quota -x -c 'limit bsoft=500m bhard=600m user1' /mnt/xfs

# 3. Просмотр отчета
sudo xfs_quota -x -c 'report -h' /mnt/xfs
# → User            Quota ID
# → Blocks
# → user1          Bsoft:  500.0MB  Bhard:  600.0MB  Isoft:        0  Ihard:        0
```

**Установка утилит:** пакет `quota` (`quota`, `repquota`, `edquota`, `setquota`, `quotacheck`, `quotaon`) и пакет `xfsprogs` (`xfs_quota`, `xfs_info`); в RHEL/CentOS: `sudo yum install -y quota xfsprogs`.

**Эквивалентные написания опций.** XFS принимает оба написания (они идентичны): `uquota` = `usrquota` = `quota` (пользовательские), `gquota` = `grpquota` (групповые), `pquota` = `prjquota` (проектные). Опция `noquota` принудительно отключает весь учёт и принудительное ограничение квот в ФС.

**Режим отчётов без ограничения (`noenforce`).** Каждую опцию можно задать в варианте `*noenforce` (`uqnoenforce`, `gqnoenforce`, `pqnoenforce`): учёт и отчёты работают, но запись не блокируется. Полезно для мониторинга реального использования перед включением принудительных лимитов.

**Квоты на корневом разделе (`/`).** Для корневой файловой системы флаги квот передаются через параметр загрузчика `rootflags=`:

```bash
# 1. В /etc/default/grub добавить к строке GRUB_CMDLINE_LINUX:
#    rootflags=uquota,gquota

# 2. Перегенерировать конфигурацию загрузчика:
sudo grub2-mkconfig -o /boot/grub2/grub.cfg   # RHEL/CentOS/Fedora
sudo update-grub                                # Debian/Ubuntu

# 3. Перезагрузиться и проверить:
mount | grep ' on / '
# → /dev/sda2 on / type xfs (rw,relatime,uquota,gquota)
```

### 3. Проектные квоты для изоляции директорий (XFS)

Идеально для ограничения размера логов или домашних папок без привязки к UID.

```bash
# 1. Описание проектов в системных файлах
echo "100:/var/www/html" | sudo tee -a /etc/projects
echo "www_site:100" | sudo tee -a /etc/projid

# 2. Инициализация проекта (проход по дереву и установка ID проекта в Inode)
sudo xfs_quota -x -c 'project -s www_site' /mnt/xfs

# 3. Установка лимита
sudo xfs_quota -x -c 'limit -p bhard=2g www_site' /mnt/xfs

# 4. Проверка
sudo xfs_quota -x -c 'report -h -p' /mnt/xfs
```

### 4. Квоты в Docker (Storage Options)

При использовании `overlay2` поверх XFS с поддержкой `pquota` можно ограничивать размер RW-слоя контейнера:

```bash
docker run -it --storage-opt size=10G ubuntu bash
```

Для контроля квот на уровне хоста при работе с Docker:
```bash
# Проверить размер слоев overlay2
sudo du -sh /var/lib/docker/overlay2/* | sort -rh | head -10

# Проверить, что overlay2 смонтирован с поддержкой pquota
findmnt -o TARGET,FSTYPE,OPTIONS | grep overlay
# → /var/lib/docker/overlay2 overlay overlay rw,relatime,lowerdir=...,workdir=...,upperdir=...
```

### 5. Мониторинг использования и оповещения о приближении к лимитам

Для оперативного реагирования на приближение пользователей или групп к лимитам настройте регулярный мониторинг.

**Автоматизированный скрипт проверки (bash):**

```bash
#!/bin/bash
# Файл: /usr/local/bin/check_quotas.sh
# Проверка использования квот и оповещение при превышении 80% мягкого лимита
FS=/data
THRESHOLD=80
LOG=/var/log/quota_alerts.log

sudo repquota -u $FS 2>/dev/null | awk -v t=$THRESHOLD '
NR>2 && $4 ~ /[0-9]/ {
    usage=$3; soft=$4; percent=(usage/soft)*100;
    if (percent > t && soft > 0) {
        printf "ALERT: User %s used %d%% of block quota (%d/%d blocks) on %s\n", $1, percent, usage, soft, "'$FS'"
    }
}' >> $LOG
```

**Интеграция с cron:**

```bash
# Добавить в crontab (каждый час)
0 * * * * /usr/local/bin/check_quotas.sh
```

**Интеграция с мониторингом (Prometheus + node_exporter):**

`node_exporter` собирает метрики квот через текстовый файл с коллектором:

```bash
# Создание метрик в формате Prometheus (скрипт /usr/local/bin/quota_metrics.sh)
cat << 'EOF' > /var/lib/node_exporter/quota.prom
# HELP node_quota_usage_percent Использование квоты пользователя в процентах
# TYPE node_quota_usage_percent gauge
node_quota_usage_percent{user="user1",mount="/data"} 85.4
EOF
```

### 6. Массовое управление квотами (edquota, rpc.rquotad)

**Копирование лимитов между пользователями:**

```bash
# Создать шаблонного пользователя с нужными лимитами
sudo edquota -u template_user

# Применить те же лимиты к списку пользователей
for user in user2 user3 user4; do
    sudo edquota -p template_user $user
done
```

**Редактирование льготного периода (grace period):**

```bash
# Открывает редактор с настройкой грейс-периода для всех ФС с квотами
# (единицы: seconds, minutes, hours, days; 0 = значение по умолчанию)
sudo edquota -t
# → Grace period before enforcing soft limits for users:
# → Filesystem     Block grace period     Inode grace period
# → /dev/sdb1            7days                  7days
```

**Сетевые квоты через NFS (rpc.rquotad):**

Для предоставления информации о квотах клиентам NFS на сервере должен быть запущен демон `rpc.rquotad`:

```bash
# На сервере NFS (Debian/Ubuntu)
sudo apt install nfs-kernel-server
sudo systemctl enable --now rpc-rquotad.service

# На клиенте при монтировании NFS квоты видны автоматически
mount -t nfs server:/export /mnt/nfs
quota -u $USER /mnt/nfs
```

### 7. Квоты для баз данных и приложений

**PostgreSQL / MySQL data directory:**

Для предотвращения исчерпания диска базой данных настройте квоту на каталог с данными:

```bash
# 1. Создать группу для СУБД
sudo groupadd dbadmin

# 2. Для XFS (project quota):
echo "200:/var/lib/postgresql" | sudo tee -a /etc/projects
echo "db_site:200" | sudo tee -a /etc/projid
sudo xfs_quota -x -c 'project -s db_site' /mnt/xfs
sudo xfs_quota -x -c 'limit -p bhard=500g db_site' /mnt/xfs

# 3. Для ext4 (group quota):
sudo setquota -g dbadmin 0 524288000 0 0 /var/lib/postgresql

# 4. Убедиться, что пользователь postgres входит в группу dbadmin
sudo usermod -aG dbadmin postgres
```

**Примечание:** При достижении лимита база данных получит ошибку записи. Настройте мониторинг, чтобы вовремя реагировать на `Disk quota exceeded` в логах PostgreSQL/MySQL.

### 8. Миграция с классических квот на внутренние (Ext4)

Если ФС ранее использовала классические квоты с файлами `aquota.*`, перейдите на внутренние для повышения надежности:

```bash
# 1. Отмонтировать ФС
sudo umount /data

# 2. Отключить классические квоты
sudo tune2fs -O ^quota /dev/sdXN

# 3. Включить внутренние квоты
sudo tune2fs -O quota /dev/sdXN

# 4. Перемонтировать
sudo mount /data

# 5. Удалить старые файлы (они больше не используются)
sudo rm -f /data/aquota.*

# 6. Проверить, что квоты активны
sudo mount | grep /data
# → /dev/sdXN on /data type ext4 (rw,usrquota,grpquota)
```

## Диагностика и устранение неполадок

### Анализ использования квот

**Ext4 — `repquota`:**

```bash
sudo repquota -aus /data
# → User quotas for user user1 (uid 1001):
# →  Filesystem  blocks       soft       hard     inods     soft     hard
# →  /dev/sdb1    850000   1048576   1153434        50        0        0
```

В выводе `repquota`:
- **blocks**: текущее использование по объему.
- **soft/hard**: мягкий и жесткий лимиты по объему.
- **inods**: текущее использование по Inode.
- **Grace**: если в колонке стоит время (например, `6days`), значит мягкий лимит превышен и идет отсчет до блокировки.

**XFS — `xfs_quota report`:**

```bash
sudo xfs_quota -x -c 'report -h' /mnt/xfs
# → User            Quota ID
# → Blocks
# → user1          Bsoft:  500.0MB  Bhard:  600.0MB  Isoft:        0  Ihard:        0
```

### Чек-лист диагностики

1. **Квоты не применяются:**
   - Проверьте опции монтирования: `mount | grep /data` — должны быть `usrquota`/`grpquota` (ext4) или `uquota`/`gquota`/`pquota` (XFS).
   - Проверьте, включен ли признак квот в суперблоке ext4: `sudo tune2fs -l /dev/sdXN | grep -i quota`.
   - Для XFS убедитесь, что квоты были включены при форматировании (`mkfs.xfs -q`) или при монтировании.

2. **Квоты не работают после перезагрузки:**
   - Проверьте `/etc/fstab` — опции квот должны быть указаны там.
   - Убедитесь, что `quotaon` запускается в скриптах инициализации (systemd unit `quotaon.service` или `quotad`).

3. **"Disk quota exceeded" при наличии свободного места:**
   - Проверьте обе колонки (блоки и Inode) через `repquota` или `df -i`.
   - Возможно, исчерпаны Inode (`df -i` показывает 0%).
   - Проверьте, не принадлежат ли файлы другому UID (например, через ACL или SUID-бинарники).

4. **Использование "зависло" после удаления файлов:**
   - Запустите `sudo quotacheck -uv /data` для пересчета.
   - Проверьте, не держит ли процесс удаленные файлы открытыми: `sudo lsof +L1`.

5. **Проектные квоты XFS не применяются:**
   - Проверьте, что в `/etc/fstab` указана опция `pquota`.
   - После изменения `/etc/projects` или `/etc/projid` выполните инициализацию: `sudo xfs_quota -x -c 'project -s имя_проекта' /mount`.
   - Проверьте project ID файлов: `sudo xfs_quota -x -c 'state -p' /mnt/xfs`.

### Распространенные ошибки

- **Disk quota exceeded:** Ошибка возникает даже если на диске есть свободное место. Проверьте обе колонки (блоки и Inode).
- **Квоты для root:** По умолчанию лимиты квот не применяются к пользователю `root`. Это сделано для предотвращения ситуации, когда системные службы (например, syslog) не могут писать логи, парализуя систему.
- **Копирование квот:** Чтобы быстро применить лимиты одного пользователя к другим, используйте `edquota -p user_template user_target`.
- **Несоответствие использования после сбоя питания (ext4 классические квоты):** Файлы `aquota.*` могут содержать устаревшие данные. Решение: `sudo quotacheck -uv /data` на отмонтированной ФС.
- **Квоты не применяются к SUID/SGID процессам:** Процессы, запущенные от root или с SUID-битом, игнорируют квоты. Проверяйте квоты от имени реального пользователя.
- **Grace period не сбрасывается:** Мягкий лимит блокирует запись после истечения grace period, даже если пользователь удалил данные. Нужно явно сбросить таймер: `sudo repquota` покажет `none` или время в колонке Grace, когда пользователь снова сможет писать (когда использование упадет ниже мягкого лимита).
- **Запись обрывается на границе жёсткого лимита:** При превышении жёсткого лимита в процессе записи файл дописывается только до остатка лимита, после чего операция завершается ошибкой `Disk quota exceeded` (при попытке записать 1.5 МБ при остатке в 512 КБ будет записано только 512 КБ). Приложения должны обрабатывать частичную запись и проверять итоговый размер файла.

## Лучшие практики

1. **Используйте внутренние квоты (Ext4 journaled) или XFS нативные:** Они надежнее классических, так как не требуют `quotacheck` после сбоев и не хранят видимые файлы в корне ФС.
2. **Настраивайте опции монтирования в `/etc/fstab`:** Никогда не применяйте параметры квот только через `mount` без записи в `fstab` — настройки потеряются после перезагрузки.
3. **Мониторьте использование через 80% мягкого лимита:** Настройте оповещения до достижения жесткого лимита, чтобы пользователи успели очистить место.
4. **Используйте проективные квоты для shared-директорий:** Вместо управления квотами на каждого пользователя в `/home` или `/var/www`, используйте проектные квоты на уровне каталога.
5. **Регулярно проверяйте Inode квоты:** Для систем с миллионами мелких файлов (логи, кэши) Inode-квоты часто срабатывают раньше блочных.
6. **Документируйте лимиты:** Ведите реестр квот (пользователи, группы, проекты, лимиты, ответственные) в конфигурационном менеджменте.
7. **Тестируйте откат:** Убедитесь, что сервисы корректно обрабатывают `Disk quota exceeded` (например, PostgreSQL падает с понятной ошибкой, а не повреждает WAL).
8. **Для XFS с внешним логом:** Если используете внешний лог XFS, квоты хранятся на основном устройстве и не влияют на производительность лога.
