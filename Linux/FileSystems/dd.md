# Утилита dd

## Определения

- **`dd` (Dataset Definition / Data Description):** Одна из старейших и наиболее мощных низкоуровневых утилит Unix-подобных систем, предназначенная для копирования и преобразования данных поблочно. В отличие от высокоуровневых инструментов (типа `cp`), `dd` оперирует потоками байтов и секторов, игнорируя границы файлов и типы файловых систем.
- **«Disk Destroyer»:** Ироничное название утилиты, подчеркивающее её деструктивный потенциал: при ошибке в параметре `of` (например, указание системного диска вместо флешки) данные уничтожаются мгновенно и без подтверждения.
- **Поблочное копирование:** Метод передачи данных фиксированными порциями (блоками). Размер блока напрямую влияет на нагрузку на CPU и скорость обмена данными с контроллером накопителя.
- **Образ диска (Image):** Точная побитовая копия носителя или его части, содержащая не только данные файлов, но и загрузчики, таблицы разделов и пустые сектора.
- **Сектор (Sector):** Минимальная адресуемая единица хранения на блочном устройстве. Классический размер — 512 байт; современные диски используют 4 КБ (4Kn — native 4K) или 512e (эмуляция 512 байт поверх 4 КБ физических секторов). Размер сектора критически важен при работе с `dd`: несоответствие `bs` физическому размеру сектора приводит к невыравниванному I/O и падению производительности.
- **Прямой ввод-вывод (O_DIRECT):** Режим передачи данных напрямую между пользовательским буфером и устройством, минуя системный кэш страниц (page cache). Важен для тестирования «чистой» скорости накопителя и для предотвращения вытеснения полезных данных из оперативной памяти.
- **Разреженный файл (Sparse File):** Файл, в котором последовательности нулевых байтов не занимают физического места на диске (создаются «дыры»). Создается флагом `conv=sparse` или системными вызовами `fallocate` с опцией `FALLOC_FL_PUNCH_HOLE`.
- **Порядок байтов (Endianness):** Способ хранения многобайтовых чисел. Little-endian (x86, ARM) — младший байт хранится по младшему адресу. Big-endian — старший байт хранится по старшему адресу. Флаг `conv=swab` меняет местами байты в парах, что полезно при обмене данными между системами с разным порядком байтов.
- **Short Read (Короткое чтение):** Ситуация, когда системный вызов `read()` возвращает меньше байт, чем запрошено. Это нормально для пайпов, сокетов и некоторых устройств. Флаг `iflag=fullblock` заставляет `dd` ждать заполнения всего буфера.
- **Logical Block Addressing (LBA):** Метод адресации секторов на диске, где каждый сектор имеет линейный номер. `dd` оперирует в терминах блоков размером `ibs`, а не физических секторов, что может приводить к невыравниванному I/O, если `bs` не кратен размеру физического сектора.

## Основные концепции

`dd` рассматривает любой входной (`if`) и выходной (`of`) объект как последовательный массив байтов. Утилита читает `ibs` байт за раз, при необходимости преобразует их и записывает `obs` байт в место назначения. Ключевое архитектурное отличие от `cp` — полное отсутствие семантики файловых систем: `dd` не проверяет и не соблюдает границы файлов, имена inode или атрибуты. Это делает её универсальным инструментом для работы с raw-устройствами, но и опасным при невнимательном использовании.

### Ключевые параметры

| Параметр | Описание | Примечание |
| :--- | :--- | :--- |
| **`if=<путь>`** | Input File — источник данных. | Файл, раздел (`/dev/sdb1`), диск (`/dev/sdb`), `stdin` или `/dev/zero`, `/dev/urandom`. |
| **`of=<путь>`** | Output File — место назначения. | Файл, устройство, `stdout`. Без указания `of` вывод идет в `stdout`. |
| **`bs=<размер>`** | Block Size — размер блока (одновременно для чтения и записи). | Ускоряет I/O за счет уменьшения количества системных вызовов. Примеры: `4M`, `1G`, `64K`. |
| **`ibs=<размер>`** | Input Block Size — размер блока чтения. | Используется для тонкой настройки, если `bs` не подходит. |
| **`obs=<размер>`** | Output Block Size — размер блока записи. | Используется для тонкой настройки, если `bs` не подходит. |
| **`count=<n>`** | Количество блоков для копирования. | По умолчанию — до конца файла. Часто используется для создания файлов фиксированного размера. |
| **`count_bytes=<n>`** | Количество байт для копирования (GNU extension). | Полезно для точного ограничения объема данных при работе с пайпами. |
| **`skip=<n>`** | Пропустить `n` блоков во входном файле. | Аналог смещения (offset) при чтении. |
| **`skip_bytes=<n>`** | Пропустить `n` байт во входном файле (GNU extension). | Позволяет задавать точное смещение в байтах. |
| **`seek=<n>`** | Пропустить `n` блоков в выходном файле. | Позволяет записывать данные в середину файла/диска. |
| **`seek_bytes=<n>`** | Пропустить `n` байт в выходном файле (GNU extension). | Позволяет задавать точное смещение назначения в байтах. |
| **`status=progress`** | Вывод индикатора прогресса. | Добавлено в Coreutils 8.24. Показывает скорость, объем и ETA в реальном времени. |
| **`oflag=append`** | Режим добавления (O_APPEND). | Данные записываются в конец файла. |

**Варианты суффиксов размера:** `c` (1), `w` (2), `b` (512), `K` (1024), `M` (1024^2), `G` (1024^3), `T` (1024^4).

### Флаги преобразования (conv)

Параметры `conv` определяют, как данные модифицируются «на лету»:

- **`noerror`:** Игнорировать ошибки чтения. Без этого флага `dd` остановится на первом же «битом» секторе.
- **`sync`:** Дополнять каждый входной блок нулями до размера `ibs`, если чтение вернуло меньше данных.
  - **Критическая связка `conv=noerror,sync`:** При восстановлении данных с поврежденного диска `noerror` позволяет пропустить битые сектора, а `sync` гарантирует, что на их место в образе будут записаны нули. Без `sync` данные «сдвинутся», что сделает структуру файловой системы в образе нечитаемой.
- **`notrunc`:** Не обрезать выходной файл. Если `of` уже существует и больше записываемых данных, остаток файла сохранится.
- **`sparse`:** При записи блоков, полностью состоящих из нулей, не записывать их физически, а создавать «дыру» в файле. Это создает **разреженные файлы**, экономя место.
- **`fdatasync` / `fsync`:** Форсировать сброс кэша записи на диск перед завершением работы. `fdatasync` сбрасывает только данные файла, а `fsync` — также и метаданные (inode, время модификации, размер). Использование `fsync` увеличивает время завершения, но повышает надежность.
- **`swab`:** Менять местами каждые два байта (Swap Bytes). Полезно для работы с данными, созданными в системах с другим порядком байтов (Endianness).
- **`lcase`, `ucase`:** Преобразование регистра (нижний/верхний) для символов ASCII.
- **`block` / `unblock`:** Преобразование фиксированных/переменных блоков с учетом пробелов. Используется редко, в основном для совместимости со старыми магнитными лентами.
- **`ascii` / `ebcdic`:** Конвертация между кодировками ASCII и EBCDIC. Историческое наследие работы с мейнфреймами.

### Расширенные флаги (iflag/oflag)

- **`direct`:** Прямой ввод-вывод (O_DIRECT). Данные передаются напрямую между диском и буфером `dd`, минуя системный кэш страниц (page cache). Эффективно для тестирования «чистой» скорости диска и для больших файлов, чтобы не вытеснять полезные данные из RAM.
- **`fullblock`:** Настаивать на заполнении всего буфера при чтении. Если `read()` вернул меньше байт, чем `ibs` (что часто бывает с пайпами), `dd` будет ждать остаток данных. Предотвращает преждевременное завершение блоков и потерю данных при чтении из пайпов или сетевых устройств.
- **`nocache`:** Дать ядру совет (posix_fadvise) не кэшировать данные. Полезно для очень больших файлов, чтобы не вытеснять полезные данные из оперативной памяти.
- **`dsync`:** Использовать синхронный ввод-вывод для данных. Гарантирует, что каждая запись завершена перед следующей, но без гарантии синхронизации метаданных (в отличие от `conv=fsync`).
- **`sync` (oflag):** Использовать синхронный ввод-вывод для данных и метаданных (эквивалент O_SYNC). Замедляет операцию, но обеспечивает максимальную надежность.
- **`nonblock`:** Неблокирующий ввод-вывод. Полезно при работе с устройствами, которые могут возвращать `EAGAIN` (например, NAND через MTD).

## Безопасность и подготовка к работе

`dd` не запрашивает подтверждения и не имеет механизма отката. Последовательность действий перед запуском критически важна.

### Проверка устройств и путей

Перед любой операцией с блочными устройствами выполните:

```bash
# Список всех блокирующих устройств с размерами и точками монтирования
lsblk -f
# → NAME   FSTYPE LABEL  SIZE MOUNTPOINT
# → sda           931.5G
# → ├─sda1 ext4        500G /
# → └─sda2 swap       431.5G [SWAP]
# → sdb           931.5G

# Идентификация файловых систем и UUID
blkid /dev/sdb1
# → /dev/sdb1: UUID="abc123..." TYPE="ext4" PARTUUID="..."

# Проверка типа устройства (блочное vs символьное)
file -s /dev/sda
# → /dev/sda: block special (8/0)

# Получение канонического пути (разрешение symlinks)
readlink -f /dev/sdb
# → /dev/sdb (или /dev/disk/by-id/ata-...)

# Размер устройства в байтах
blockdev --getsize64 /dev/sdb
# → 1000204886016
```

### Паттерн dry-run

Перед выполнением деструктивной команды замените `of` на `stdout` и перенаправьте в `wc -c` или `hexdump` для проверки объема и формата данных:

```bash
# Проверка: какой объем данных будет скопирован
sudo dd if=/dev/sda bs=4M count=10 | wc -c
# → 41943040 (10 блоков по 4 МБ)

# Проверка: корректность первого сектора
sudo dd if=/dev/sda bs=512 count=1 | hexdump -C | head
```

### Запрет записи на смонтированные устройства

```bash
# Проверка точек монтирования
findmnt -rn /dev/sdb1
# → если вывод пустой — устройство не смонтировано

# Принудительный перевод в read-only (для разделов)
sudo mount -o remount,ro /dev/sdb1 /mnt/data
```

## Практические сценарии

### 1. Создание и клонирование образов дисков

#### Создание сжатого образа диска

```bash
sudo dd if=/dev/sda bs=4M status=progress | gzip -c > sda_backup.img.gz
# → 500107862016 bytes (500 GB) copied, 120.5 s, 4.2 MB/s
```

Для многопоточной компрессии используйте `pigz` (parallel gzip):

```bash
sudo dd if=/dev/sda bs=4M status=progress | pigz -c > sda_backup.img.gz
# → на многоядерных CPU скорость сжатия растет линейно с количеством ядер
```

Для максимального сжатия без потерь используйте `zstd`:

```bash
sudo dd if=/dev/sda bs=4M status=progress | zstd -c > sda_backup.img.zst
```

#### Клонирование диска на диск

```bash
# ВНИМАНИЕ: Проверьте устройства через lsblk перед запуском!
sudo dd if=/dev/sda of=/dev/sdb bs=4M status=progress conv=fdatasync
# → 500107862016 bytes (500 GB) copied, 125.3 s, 4.0 MB/s
```

Для клонирования на диск большего размера после завершения копирования расширьте раздел и файловую систему:

```bash
# Расширение раздела (в примере — последний раздел на sdb)
sudo growpart /dev/sdb 3
# Расширение файловой системы
sudo resize2fs /dev/sdb3  # для ext4
# или
sudo xfs_growfs /mnt/data  # для XFS (требует монтирования)
```

#### Клонирование с пропуском областей

Если нужно скопировать только начальную часть диска (например, для переноса данных на меньший носитель):

```bash
# Копирование первых 100 ГБ
sudo dd if=/dev/sda of=/dev/sdb bs=4M count=25600 status=progress
# 25600 блоков × 4 МБ = 100 ГБ
```

### 2. Резервное копирование критических структур

#### Бэкап Master Boot Record

```bash
# MBR = первый сектор (512 байт): загрузчик (446) + таблица разделов (64) + сигнатура (2)
sudo dd if=/dev/sda of=mbr_backup.bin bs=512 count=1
# → 512 bytes copied, 0.001 s, 512 kB/s
```

Для восстановления:

```bash
sudo dd if=mbr_backup.bin of=/dev/sda bs=512 count=1
```

#### Бэкап и восстановление таблицы разделов GPT

GPT хранит заголовок и таблицу в начале и в конце диска. Для полного бэкапа требуется 67 секторов (34 в начале + 33 в конце):

```bash
# Определение размера диска в секторах
SECTORS=$(blockdev --getsz /dev/sda)

# Бэкап Primary GPT (LBA 1–34, 34 сектора × 512 байт = 17408 байт)
sudo dd if=/dev/sda of=gpt_header.bin bs=512 skip=1 count=34

# Бэкап Secondary GPT (последние 33 сектора)
sudo dd if=/dev/sda of=gpt_backup.bin bs=512 skip=$((SECTORS - 33)) count=33
```

Восстановление Primary GPT из бэкапа:

```bash
sudo dd if=gpt_header.bin of=/dev/sda bs=512 seek=1 count=34 conv=notrunc
```

#### Восстановление только таблицы разделов MBR

Восстановление только таблицы разделов (последние 66 байт MBR), не трогая загрузчик:

```bash
sudo dd if=mbr.bin of=/dev/sda bs=1 skip=446 seek=446 count=66
```

### 3. Работа с разреженными файлами (Sparse)

Создание образа, который занимает место только по мере наполнения:

```bash
sudo dd if=/dev/sdb of=sparse_image.img bs=4M conv=sparse status=progress
```

Проверка размера файла vs виртуального размера:

```bash
# Физический размер на диске
du -h sparse_image.img
# → 2.1G

# Виртуальный размер
ls -lh sparse_image.img
# → -rw-r--r-- 1 root root 100G sparse_image.img
```

Полезно для виртуальных машин и контейнеров, где пустые пространства внутри диска не должны занимать место в хранилище.

### 4. Подготовка носителей и безопасное уничтожение данных

#### Быстрая затирка нулями

```bash
sudo dd if=/dev/zero of=/dev/sdX bs=4M status=progress
```

#### Затирка случайными данными

```bash
sudo dd if=/dev/urandom of=/dev/sdX bs=4M status=progress
```

Медленнее, но заполняет носитель недетерминированными данными. Для SSD избыточно: контроллер wear-leveling не гарантирует запись на каждый физический блок.

#### Безопасное уничтожение данных: NIST SP 800-88

Стандарт NIST SP 800-88 Revision 1 (2014) определяет, что для магнитных дисков (HDD) достаточно одного прохода нулями или случайными данными. Для SSD/Flash/составных накопителей рекомендуется использование встроенной команды Secure Erase (`hdparm` или `nvme format`), так как `dd` не учитывает wear-leveling и может не дойти до некоторых физических ячеек.

```bash
# Проверка поддержки Secure Erase
sudo hdparm -I /dev/sda | grep -i "secure erase"
# →    Security: supported
# →    Security: enabled
# →    Security: frozen

# Если накопитель frozen — разблокировка через suspend/resume
sudo systemctl suspend
# (проснуться и быстро запустить)
sudo hdparm --user-master u --security-set-pass PASS /dev/sda
sudo hdparm --user-master u --security-erase PASS /dev/sda
```

Для NVMe:

```bash
# Форматирование с стиранием всех данных (опасно!)
sudo nvme format /dev/nvme0n1 --ses=1
```

#### Проверка результатов wiping

```bash
# Поиск нестиранных секторов (ищем не-нули)
sudo dd if=/dev/sdX bs=1M | hexdump -C | grep -v ' 00 '
# → если вывод пустой — все нули
```

### 5. Бенчмаркинг и тестирование скорости накопителей

#### Тестирование последовательной записи

```bash
# Обход кэша: прямой ввод-вывод
dd if=/dev/zero of=testfile bs=1G count=1 oflag=direct
# → результат в МБ/с покажет реальную пропускную способность шины/диска
```

Для гарантии сброса данных на диск добавьте `conv=fdatasync`:

```bash
# Обход кэша + финализация записи на диск
dd if=/dev/zero of=testfile bs=1G count=1 oflag=direct conv=fdatasync
# → 1073741824 bytes (1.1 GB) copied, 2.345 s, 458 MB/s
```

Для более точного тестирования используйте несколько итераций и разный размер блоков:

```bash
# Тест с блоком 4K (имитация БД/ВМ)
for bs in 4k 64k 1M; do
  echo "=== bs=$bs ==="
  dd if=/dev/zero of=testfile bs=$bs count=10000 oflag=direct conv=fdatasync
  rm -f testfile
done
```

#### Тестирование чтения

```bash
# Очистка кэша перед тестом (требует root)
echo 3 | sudo tee /proc/sys/vm/drop_caches

# Тест чтения
dd if=testfile of=/dev/null bs=1M iflag=direct
# → 1073741824 bytes (1.1 GB) copied, 0.8 s, 1.3 GB/s
```

#### Тестирование накопителя, смонтированного в точке

```bash
# Запись на смонтированный раздел
sudo dd if=/dev/zero of=/mnt/data/testfile bs=1G count=1 oflag=dsync
# → результат показывает реальную скорость с учетом journaling и ФС
```

#### Важно о тестировании

- `dd` измеряет пропускную способность между буфером пользователя и устройством. Он не учитывает overhead ФС, кэширование метаданных и поведение при конкурентной нагрузке.
- Для комплексного тестирования используйте `fio`, который моделирует случайный I/O, задает глубину очереди и поддерживает `libaio`.

### 6. Создание файлов подкачки (swap)

#### Создание swap-файла

```bash
# Создание файла размером ровно 2 ГБ (базовый пример)
dd if=/dev/zero of=/swapfile bs=1M count=2048
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
```

Для больших объемов используйте соответствующий `count`:

```bash
# Создание файла размером ровно 16 ГБ
sudo dd if=/dev/zero of=/swapfile bs=1M count=16384 status=progress
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Проверка
swapon --show
# → /swapfile  partition  16G  0B  8%  0/0

# Постоянное включение: добавьте в /etc/fstab
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

#### Swap для hibernation

Для использования hibernation (suspend-to-disk) размер swap должен быть не менее объема RAM:

```bash
# Проверка объема RAM
grep MemTotal /proc/meminfo
# → MemTotal:       16431680 kB

# Создание swap достаточного размера для hibernation
sudo dd if=/dev/zero of=/hiberfile bs=1M count=20000 status=progress
sudo mkswap /hiberfile
```

```bash
# Создание полного образа

# Просмотр таблицы разделов в образе
```

### 9. Восстановление данных с помощью ddrescue

Обычный `dd` не предназначен для работы с failing-дисками: при ошибках чтения он завершается или зависает. **GNU ddrescue** — инструмент, оптимизированный для rescue-сценариев: он копирует сначала целые блоки, а затем многократно пытается прочитать битые области, сохраняя лог для возобновления.

#### Установка

```bash
# Debian/Ubuntu
sudo apt install gddrescue

# RHEL/CentOS/Fedora
sudo dnf install ddrescue

# Arch
sudo pacman -S ddrescue
```

#### Базовое использование

```bash
# Создание mapfile для возобновления при прерывании
sudo ddrescue -d -r3 /dev/sdb /mnt/recovery/disk.img /mnt/recovery/rescue.log
# → -d  : прямой доступ к устройству (O_DIRECT), минуя кэш
# → -r3 : 3 попытки чтения битых блоков
```

#### Стратегии rescue

```bash
# Этап 1: Быстрое копирование целых блоков (skip-режим)
sudo ddrescue -d -n /dev/sdb /mnt/recovery/disk.img /mnt/recovery/stage1.log

# Этап 2: Многопроходное чтение поврежденных блоков
sudo ddrescue -d -r3 /dev/sdb /mnt/recovery/disk.img /mnt/recovery/stage1.log

# Этап 3: Чтение оставшихся нулевых блоков (если нужно полное заполнение)
sudo ddrescue -d -r3 --fill-mode=+ /dev/sdb /mnt/recovery/disk.img /mnt/recovery/stage1.log
```

#### Копирование с ограничением скорости

```bash
# Ограничение до 10 МБ/с, чтобы не перегружать failing-диск
sudo ddrescue --max-read-rate=10M /dev/sdb /mnt/recovery/disk.img rescue.log
```

#### Сравнение с обычным dd

| Характеристика | dd | ddrescue |
| :--- | :--- | :--- |
| Обработка ошибок | Останавливается или пропускает | Запоминает позицию, возвращается |
| Возобновление | Нет | Через mapfile |
| Скорость на здоровых дисках | Высокая | Немного ниже |
| Скорость на failing-дисках | Падает на ошибках | Оптимизирована |
| Целевое назначение | Здоровые носители | Восстановление данных |

### 12. Миграция данных между дисками разного размера

#### Копирование на меньший диск

Если новый диск меньше исходного, ограничьте объем копирования:


## Тонкая настройка и производительность

### Выбор Block Size (`bs`)

Значение по умолчанию (512 байт) крайне неэффективно: на копирование 1 ГБ потребуется ~2 млн системных вызовов. Оптимальный диапазон зависит от типа накопителя:

| Тип накопителя | Рекомендуемый `bs` | Примечание |
| :--- | :--- | :--- |
| HDD (7200 RPM) | `1M` – `4M` | Оптимально для последовательного I/O |
| SATA SSD | `4M` – `8M` | Выше 8M обычно не дает прироста |
| NVMe SSD | `8M` – `16M` | Высокая параллельность позволяет большие блоки |
| USB 3.0 флешка | `1M` – `4M` | Зависит от контроллера флешки |
| Сетевые устройства | `64K` – `1M` | Большие блоки вызывают латентность |

Больше 16M обычно не дает прироста и может вызвать проблемы с фрагментацией памяти в некоторых условиях.

### Мониторинг прогресса

```bash
# Если Coreutils >= 8.24 (современные дистрибутивы)
sudo dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# Если Coreutils < 8.24 — отправка USR1 процессу
sudo kill -USR1 $(pgrep ^dd)
# Утилита выведет текущий статус в стандартный поток ошибств.

# Для многострочного вывода статуса (несколько сигналов)
watch -n 1 "sudo kill -USR1 $(pgrep ^dd) 2>&1"
```

### Использование `pv` (Pipe Viewer)

Для более наглядного прогресса (процент, время до конца, скорость):

```bash
sudo dd if=/dev/sda bs=4M | pv -s 500G | dd of=/dev/sdb bs=4M
# → 4.32GB 0:12:34 [6.12MB/s] [==>                    ] 0%
```

### Параметры производительности ядра

Для операций `dd` с большими объемами можно временно изменить параметры ядра:

```bash
# Увеличение буфера dirty writeback (для быстрого завершения dd)
echo 600 | sudo tee /proc/sys/vm/dirty_writeback_centisecs

# Отключение swappiness для операций с большими файлами
echo 10 | sudo tee /proc/sys/vm/swappiness

# Возврат к значениям по умолчанию после завершения
echo 500 | sudo tee /proc/sys/vm/dirty_writeback_centisecs
echo 60 | sudo tee /proc/sys/vm/swappiness
```

### Приоритизация процессов

```bash
# Низкий приоритет CPU (nice=19, наименьший)
sudo nice -n 19 dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# Минимальный приоритет I/O (class 3 = idle)
sudo ionice -c 3 dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# Привязка к конкретным ядрам CPU (для NUMA-систем)
sudo taskset -c 4-7 dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# Комбинация
sudo nice -n 19 ionice -c 3 dd if=/dev/sda of=/dev/sdb bs=4M status=progress
```

### Использование многопоточного сжатия

```bash
# pigz — параллельный gzip (использует все ядра)
sudo dd if=/dev/sda bs=4M status=progress | pigz -c > sda.img.gz

# pbzip2 — параллельный bzip2
sudo dd if=/dev/sda bs=4M status=progress | pbzip2 -c > sda.img.bz2

# pixz — параллельный XZ с поддержкой seek (можно декомпрессировать часть)
sudo dd if=/dev/sda bs=4M status=progress | pixz > sda.img.xz

# zstd — параллельный с хорошим балансом скорость/сжатие
sudo dd if=/dev/sda bs=4M status=progress | zstd -c > sda.img.zst
```

## Обработка ошибок и автоматизация

### Коды возврата

`dd` возвращает 0 при успехе, ненулевое значение при ошибке. Типичные сценарии:

```bash
# Успешное завершение
dd if=/dev/zero of=/tmp/test bs=1M count=10
echo $?
# → 0

# Ошибка чтения (битый сектор)
dd if=/dev/sda of=/tmp/test bs=4M count=1 conv=noerror
echo $?
# → 1 (или другой ненулевой код)
```

### Скриптовая обертка с обработкой ошибок

```bash
#!/bin/bash
set -euo pipefail

SRC="/dev/sda"
DST="/dev/sdb"
BS="4M"
LOG="/var/log/dd_clone_$(date +%Y%m%d_%H%M%S).log"

echo "[INFO] Начало клонирования: $(date)" | tee -a "$LOG"

# Проверка устройств
if [[ ! -b "$SRC" ]]; then
  echo "[ERROR] Источник $SRC не является блочным устройством" | tee -a "$LOG"
  exit 1
fi

if [[ ! -b "$DST" ]]; then
  echo "[ERROR] Назначение $DST не является блочным устройством" | tee -a "$LOG"
  exit 1
fi

# Проверка смонтированных разделов
if findmnt -rn "$SRC" &>/dev/null; then
  echo "[ERROR] $SRC смонтирован! Отмонтируйте перед клонированием." | tee -a "$LOG"
  exit 1
fi

# Выполнение
sudo dd if="$SRC" of="$DST" bs="$BS" status=progress conv=fdatasync 2>&1 | tee -a "$LOG"
DD_EXIT=${PIPESTATUS[0]}

if [[ $DD_EXIT -eq 0 ]]; then
  echo "[SUCCESS] Клонирование завершено: $(date)" | tee -a "$LOG"
else
  echo "[ERROR] dd завершился с кодом $DD_EXIT" | tee -a "$LOG"
  exit $DD_EXIT
fi
```

### Логирование и сохранение вывода

```bash
# Полное логирование с временными метками
LOG="/var/log/dd_$(date +%Y%m%d_%H%M%S).log"
{
  echo "=== Запуск dd ==="
  date
  sudo dd if=/dev/sda of=/dev/sdb bs=4M status=progress
  echo "=== Завершено ==="
  date
} | tee "$LOG"
```

### Возобновление прерванной операции

Если `dd` был прерван (Ctrl+C, сбой питания), можно возобновить с помощью `seek` и `skip`:

```bash
# Определение уже скопированных блоков
COPIED_BLOCKS=$(blockdev --getsize64 /dev/sdb)
BLOCK_SIZE=4194304  # 4M

# Возобновление с позиции
sudo dd if=/dev/sda of=/dev/sdb bs=4M \
  skip=$((COPIED_BLOCKS / BLOCK_SIZE)) \
  seek=$((COPIED_BLOCKS / BLOCK_SIZE)) \
  status=progress conv=fdatasync
```

## Меры предосторожности (Pitfalls)

1. **Порядок `if` и `of`:** Самая частая ошибка — перепутать источник и назначение. Последствия необратимы. Всегда проверяйте команду перед нажатием Enter.
2. **Размер устройства:** При восстановлении образа на диск, который меньше оригинального, файловая система будет повреждена. Используйте `count` для ограничения объема.
3. **Кэширование записи:** Если не использовать `conv=fdatasync` или `fsync`, команда может завершиться мгновенно (данные ушли в RAM), но при извлечении носителя данные могут быть потеряны. Всегда используйте `conv=fdatasync` для деструктивных операций.
4. **Короткие чтения (Short Reads):** При чтении из сети или пайпов без `iflag=fullblock` размер блока может оказаться меньше `ibs`, что в сочетании с `count` приведет к недочитыванию данных.
5. **Смонтированные файловые системы:** `dd` на смонтированном устройстве может привести к неконсистентным данным. Всегда отмонтируйте раздел перед клонированием или используйте `snapshot` (LVM, Btrfs).
6. **Размер блока и выравнивание:** Использование `bs`, не кратного физическому размеру сектора (512e или 4Kn), приводит к невыравниванному I/O и падению производительности до 30–50%.
7. **Ограничение `count`:** При явном указании `count` убедитесь, что `count × bs` не превышает размер целевого устройства. Иначе `dd` перезапишет соседние устройства.
8. **Файлы вместо устройств:** Запись образа диска в обычный файл на той же ФС создает двойное потребление места (файл + кэш). Используйте `conv=sparse` или пишите напрямую на устройство.

## Сравнение с альтернативами

| Инструмент | Основное назначение | Скорость на HDD | Скорость на SSD | Восстановление ошибок | Форматы |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **dd** | Универсальное побайтовое копирование | Средняя | Высокая | Нет | Любой |
| **ddrescue** | Восстановление данных с failing-дисков | Низкая → Высокая | Высокая | Да (mapfile, многопроходность) | Любой |
| **dc3dd** | Forensic-копирование (forensic dd) | Средняя | Средняя | Нет | Любой + хеши |
| **partclone** | Клонирование с awareness ФС | Высокая | Высокая | Нет | ext2/3/4, xfs, btrfs, ntfs |
| **partimage** | Клонирование ФС (legacy) | Средняя | Средняя | Нет | ext2/3/4, ReiserFS, FAT |
| **cat** | Простое копирование файлов | Высокая | Высокая | Нет | Любой |
| **pv** | Пайплайн с прогресс-баром | Высокая | Высокая | Нет | Потоковый |
| **Clonezilla** | Массовое развертывание (live CD) | — | — | — | Любой (через partclone/dd) |

### Выбор инструмента

- **Здоровые диски, побайтовое копирование:** `dd` или `cat` (если нет нужды в блоках/смещениях).
- **Failing-диск, сохранение данных:** `ddrescue` — однозначно.
- **Forensic-копирование:** `dc3dd` (добавляет хеши MD5/SHA1 в заголовок образа).
- **Клонирование с awareness ФС:** `partclone` (быстрее `dd`, пропускает пустые блоки, но требует поддержки конкретной ФС).
- **Массовое развертывание:** Clonezilla или Redo Rescue.

### dd vs cat

```bash
# dd с небольшим блоком
dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# cat (часто быстрее на здоровых дисках из-за больших внутренних буферов)
cat /dev/sda > /dev/sdb
# → но нет контроля блоков, смещений и conv-флагов
```

## Дополнительная информация

### Альтернативы

- **`ddrescue` (GNU):** Рекомендуется для поврежденных дисков. Умеет читать данные частями, возвращаться к битым секторам позже, вести лог работы (mapfile) для возобновления операции. Подробности — в разделе [Восстановление данных с помощью ddrescue](#9-восстановление-данных-с-помощью-ddrescue).
- **`dc3dd`:** Forensic-версия `dd` с встроенным хешированием (MD5, SHA-1, SHA-256), хранением хешей в заголовке образа и поддержкой форензик-логирования. Используется в инцидентах для обеспечения цепочки custody.
- **`partclone`:** Интеллектуальное клонирование с awareness файловой системы. Пропускает пустые блоки, работает быстрее `dd` для разделов с низким заполнением. Поддерживает ext2/3/4, xfs, btrfs, ntfs, fat.
- **`shred`:** Специализированный инструмент для гарантированного уничтожения данных (несколько проходов, разные паттерны). Для SSD используйте `hdparm` Secure Erase.
- **`cat`:** Иногда быстрее для простого копирования, но не имеет настроек блоков и смещений.
- **`pv`:** Пайплайн-утилита с прогресс-баром, скоростью и ETA. Часто используется в паре с `dd` для визуализации долгих операций.
- **`qemu-img`:** Для работы с образами виртуальных машин (qcow2, raw, vmdk, vdi). Поддерживает конвертацию, сжатие, resize и snapshot.
