# Утилита dd

## Определения

- **`dd` (Dataset Definition):** Низкоуровневая утилита командной строки для Unix-подобных систем, предназначенная для копирования и преобразования данных поблочно. Благодаря прямому доступу к устройствам позволяет выполнять операции, недоступные обычным средствам копирования файлов. Из-за высокого риска необратимой потери данных при ошибках в параметрах её часто называют «Disk Destroyer».
- **Поблочное копирование:** Метод передачи данных, при котором информация считывается и записывается фиксированными порциями (блоками) определённого размера.
- **Образ диска (Image):** Файл, содержащий полную копию структуры и данных носителя (сектор за сектором).

## Основные концепции

Утилита `dd` работает с потоками данных, последовательно считывая их из источника и записывая в место назначения.

### Ключевые параметры

- **`if=<source>` (Input File):** Путь к источнику данных. Это может быть обычный файл или файл устройства (например, `/dev/sda`). По умолчанию используется `stdin`.
- **`of=<destination>` (Output File):** Путь к месту назначения. Если файл не существует, он будет создан; если существует — перезаписан. По умолчанию используется `stdout`.
- **`bs=<size>` (Block Size):** Размер блока для чтения и записи. Рекомендуется использовать значения кратные степени двойки (например, `bs=4M` для 4 мегабайт) для повышения производительности **I/O (Input/Output)**. Можно задавать отдельно `ibs` (входной) и `obs` (выходной).
- **`count=<n>`:** Количество блоков, которые необходимо скопировать.
- **`seek=<n>`:** Пропустить `n` блоков в выходном файле перед началом записи.
- **`skip=<n>`:** Пропустить `n` блоков во входном файле перед началом чтения.
- **`status=progress`:** Включает отображение индикатора выполнения и скорости копирования в реальном времени.

### Флаги преобразования (conv)

Параметр `conv` позволяет модифицировать данные в процессе копирования:
- **`noerror`:** Продолжать работу при возникновении ошибок чтения (критично для восстановления данных).
- **`sync`:** Дополнять блоки нулями до размера `bs`, если чтение вернуло меньше данных. Обычно используется вместе с `noerror`.
- **`notrunc`:** Не обрезать выходной файл при записи.
- **`sparse`:** Создавать «дыры» в выходном файле вместо записи блоков из нулей. Это создает **разреженные файлы**, которые занимают меньше места на диске.
- **`fdatasync`:** Форсировать физическую запись данных на диск перед завершением работы команды.

### Расширенные флаги (iflag/oflag)

- **`direct`:** Использовать прямой ввод-вывод в обход кэша операционной системы.
- **`fullblock`:** Настаивать на заполнении всего блока при чтении (важно при работе с пайпами и сокетами).
- **`dsync`:** Использовать синхронный ввод-вывод для данных.

## Практические сценарии

### 1. Создание и восстановление образов

Создание полной копии диска или раздела:

```bash
# Создать образ диска /dev/sda в файл sda.img
sudo dd if=/dev/sda of=/path/to/sda.img bs=4M status=progress conv=fdatasync
```

Восстановление данных из образа:

```bash
# Записать содержимое образа обратно на физическое устройство
sudo dd if=/path/to/sda.img of=/dev/sdb bs=4M status=progress
```

### 2. Создание загрузочного USB-носителя

Запись ISO-образа операционной системы на флеш-накопитель:

```bash
# Запись образа на устройство /dev/sdX
sudo dd if=linux-distro.iso of=/dev/sdX bs=4M status=progress conv=fdatasync
```

### 3. Работа с разреженными файлами

Создание компактного образа, который не занимает место под пустые блоки:

```bash
# Копирование диска в разреженный файл
sudo dd if=/dev/sdb of=disk_sparse.img bs=4M conv=sparse status=progress
```

### 4. Безопасное удаление данных

Заполнение диска нулями или случайными данными для предотвращения восстановления:

```bash
# Затирка диска нулями
sudo dd if=/dev/zero of=/dev/sda bs=4M status=progress

# Затирка случайными данными (более надежно)
sudo dd if=/dev/urandom of=/dev/sda bs=4M status=progress
```

### 5. Тестирование производительности

Измерение скорости работы дисковой подсистемы:

```bash
# Тест скорости записи файла объемом 1 ГБ в обход кэша ОС
dd if=/dev/zero of=testfile bs=1G count=1 oflag=direct

# Тест скорости чтения созданного файла
dd if=testfile of=/dev/null bs=1G
```

### 6. Создание файлов подкачки и контейнеров

Применяется для создания файлов подкачки (**Swap**) или контейнеров для **LVM**:

```bash
# Создать пустой файл размером 2 ГБ
dd if=/dev/zero of=storage.img bs=1G count=2
```

## Меры предосторожности (Pitfalls)

1. **Ошибки в именах устройств:** Команда `of=/dev/sda` вместо `of=/dev/sdb` мгновенно уничтожит системный диск. Всегда проверяйте целевое устройство через `lsblk` или `fdisk -l`.
2. **Отсутствие fdatasync:** Без этого флага данные могут остаться в кэше записи, и извлечение флешки сразу после завершения команды приведет к повреждению данных.
3. **Пайпы и блоки:** При получении данных через пайп (например, `gzip -dc image.gz | dd ...`) всегда добавляйте `iflag=fullblock`, иначе `dd` может считать неполный блок и образ будет поврежден.

## Дополнительная информация

- **Безопасность:** Для гарантированного уничтожения данных рекомендуется использовать утилиту `shred`.
- **Альтернативы:**
  - `ddrescue` — для восстановления данных с поврежденных носителей (умное управление повторными попытками).
  - `pv` — для мониторинга прогресса в сложных пайпах (`cat img | pv | dd ...`).
