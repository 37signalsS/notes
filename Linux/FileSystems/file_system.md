# Стандарт POSIX и его роль в Linux

**POSIX (Portable Operating System Interface)** — это набор стандартов, разработанный IEEE, который определяет, как операционные системы должны выглядеть и вести себя с точки зрения программиста. Его главная цель — обеспечить **совместимость исходного кода** между различными Unix-подобными операционными системами.

**Ключевые аспекты, которые определяет POSIX:**

1.  **Интерфейс командной строки (Shell):** Стандартизирует команды (`ls`, `cp`, `grep`), синтаксис и переменные окружения.
2.  **Системные вызовы (API):** Определяет стандартный набор функций на языке C для взаимодействия с ядром (например, `open()`, `read()`, `write()`, `fork()`).
3.  **Файловая система:** Описывает базовую структуру каталогов, права доступа к файлам (rwx) и концепцию "всё есть файл".
4.  **Процессы и потоки:** Стандартизирует управление процессами, сигналами и потоками (pthreads).

**Почему это важно для Linux?**

Хотя Linux не является сертифицированной POSIX-системой "из коробки" (сертификация стоит дорого), он **в значительной степени совместим с POSIX**. Это означает, что программы, написанные с соблюдением стандартов POSIX, могут быть легко скомпилированы и запущены на Linux, macOS, BSD и других Unix-системах с минимальными изменениями или без них.

**Linux Standard Base (LSB) и Filesystem Hierarchy Standard (FHS)**

-   **LSB (Linux Standard Base):** Это более специфичный стандарт, который расширяет POSIX и направлен на обеспечение бинарной совместимости между различными дистрибутивами Linux. Он определяет такие вещи, как структура файловой системы, основные библиотеки и команды.
-   **FHS (Filesystem Hierarchy Standard):** Является частью LSB и подробно описывает, в каких каталогах должны располагаться те или иные типы файлов (например, `/bin` для исполняемых файлов, `/etc` для конфигураций). Это обеспечивает предсказуемость и порядок в системе.

### Стандартная иерархия каталогов (FHS)

-   `/bin`: Основные утилиты командной строки, необходимые для работы системы.
-   `/boot`: Файлы, необходимые для загрузки, включая ядро Linux и конфигурацию загрузчика.
-   `/dev`: Файлы устройств, представляющие аппаратные компоненты.
-   `/etc`: Файлы конфигурации системы и приложений.
-   `/home`: Домашние каталоги пользователей.
-   `/lib`: Библиотеки, необходимые утилитам из `/bin` и `/sbin`.
-   `/media`: Точки монтирования для съёмных носителей (CD, USB).
-   `/mnt`: Точка для временного монтирования файловых систем.
-   `/opt`: Пакеты стороннего программного обеспечения.
-   `/proc`: Виртуальная файловая система с информацией о процессах и ядре.
-   `/root`: Домашний каталог пользователя `root`. В любой файловой системе должен быть один главный каталог — это корневой каталог (`/`), от которого строится всё дерево.
-   `/sbin`: Системные исполняемые файлы, используемые для администрирования.
-   `/sys`: Виртуальная файловая система, предоставляющая интерфейс к драйверам ядра.
-   `/tmp`: Временные файлы.
-   `/usr`: Пользовательские утилиты, библиотеки и данные.
-   `/var`: Переменные данные, такие как логи, почта и базы данных.

## Псевдофайловые системы

Это виртуальные файловые системы, которые не хранят данные на диске, а предоставляют доступ к структурам ядра и системной информации в виде файлов.

-   **procfs (`/proc`)**: Информация о процессах (`/proc/<PID>`), процессоре (`/proc/cpuinfo`), памяти (`/proc/meminfo`) и настройках ядра (`/proc/sys`).
-   **sysfs (`/sys`)**: Информация об устройствах, драйверах и их иерархии. Позволяет управлять питанием (`/sys/power`).
-   **tmpfs (`/dev/shm`, `/run`)**: Хранит файлы в оперативной памяти для сверхбыстрого доступа. Используется для разделяемой памяти и временных файлов служб.
-   **cgroupfs (`/sys/fs/cgroup`)**: Управление ресурсами (CPU, память, I/O) для групп процессов. Основа для контейнеризации (Docker, Kubernetes).

## Основы хранения данных

### Эволюция носителей информации

-   **Магнитные ленты**: Один из ранних форматов, используется до сих пор для долгосрочного хранения и бэкапов (например, формат LTO). Данные хранятся последовательно.
-   **HDD (Hard Disk Drive)**: Жесткие диски с вращающимися магнитными пластинами и считывающей головкой. Данные также организованы в виде дорожек и секторов, но доступ к ним быстрее, чем у лент.
-   **SSD (Solid-State Drive)**: Твердотельные накопители на основе флеш-памяти. Не имеют движущихся частей, что обеспечивает произвольный доступ к любой ячейке памяти и очень высокую скорость чтения. Однако у ячеек есть ограниченный ресурс циклов перезаписи.

### Организация данных на диске: Блоки

Независимо от типа носителя, для операционной системы все дисковое пространство представляется в виде единой непрерывной "ленты", разбитой на **блоки** фиксированного размера (например, 4096 байт). Блок — это минимальная единица данных, которой оперирует файловая система при чтении или записи. Даже если файл занимает всего 10 байт, на диске под него будет выделен целый блок.

### Фрагментация и дефрагментация

-   **Фрагментация**: Когда файл изменяется и его новые части записываются в разные, несмежные блоки на диске, он становится фрагментированным. Для его чтения считывающей головке HDD приходится перемещаться по всему диску, что замедляет доступ. На SSD этот эффект менее выражен, но все же присутствует.
-   **Дефрагментация**: Процесс перемещения фрагментов файла в последовательные блоки для ускорения доступа.
    -   **Для HDD**: Критически важна для поддержания производительности.
    -   **Для SSD**: Спорная операция. С одной стороны, она может немного ускорить чтение больших файлов, но с другой — интенсивно расходует ресурс ячеек памяти из-за большого количества операций перезаписи. В большинстве случаев для SSD дефрагментация не рекомендуется.

### Низкоуровневая организация диска: Секторы, Цилиндры, Головки

На самом низком уровне, до появления файловых систем, диск представляется как набор физических компонентов. Понимание этой структуры помогает разобраться в ограничениях и принципах работы дисковых подсистем.

-   **Сектор (Sector)**: Минимальная адресуемая единица хранения данных на диске. Исторически размер сектора составлял **512 байт**. Даже если нужно записать один байт, будет занят целый сектор.
-   **Дорожка (Track)**: Концентрическая окружность на поверхности магнитной пластины диска, на которой располагаются секторы.
-   **Головка (Head)**: Устройство, которое считывает и записывает информацию с определенной поверхности магнитной пластины.
-   **Цилиндр (Cylinder)**: Совокупность всех дорожек с одним и тем же номером на всех поверхностях пластин.

#### Адресация: от CHS к LBA

1.  **CHS (Cylinder-Head-Sector)**: Исторически первая система адресации. Чтобы найти нужный сектор, необходимо было указать три координаты: номер цилиндра, номер головки и номер сектора. Эта система имела жесткие ограничения (например, максимальный объем диска около 500 МБ) и была неудобной.

2.  **LBA (Logical Block Addressing)**: Современная система адресации. В ней каждый сектор на диске имеет уникальный последовательный номер (от 0 до N). Операционной системе больше не нужно знать о физической геометрии диска (цилиндрах и головках). Она просто запрашивает "блок номер 12345", а контроллер диска сам преобразует этот логический адрес в физические координаты. Это основной метод адресации сегодня.

#### Современные размеры секторов: 512e и 4K Native (4Kn)

Современные диски (как HDD, так и SSD) физически используют секторы размером **4096 байт (4 КБ)** для повышения эффективности хранения и коррекции ошибок. Однако для обратной совместимости со старыми системами они могут "притворяться", что у них секторы по 512 байт.

-   **512n (Native)**: Классический формат, где и логический, и физический размер сектора равны 512 байт. Встречается на старых дисках.
-   **512e (Emulation)**: Диск с физическими секторами 4 КБ, который эмулирует для системы логические секторы по 512 байт. Это самый распространенный сегодня формат.
-   **4Kn (4K Native)**: Диск, у которого и логический, и физический размер сектора равны 4 КБ. Обеспечивает лучшую производительность, но требует поддержки со стороны ОС и BIOS/UEFI.

Проблема с 512e может возникать при **выравнивании разделов (partition alignment)**. Если раздел начинается с адреса, не кратного 4 КБ, одна логическая операция файловой системы может потребовать чтения и записи двух физических блоков вместо одного, что снижает производительность. Современные утилиты разметки диска (например, `parted`) автоматически выравнивают разделы правильно.

## Разделы и файловые системы

### Что такое файловая система?

**Файловая система (ФС)** — это структура и набор правил, которые определяют, как файлы хранятся на диске и как осуществляется доступ к ним. Без файловой системы диск был бы просто набором неструктурированных блоков.

Ключевые функции файловой системы:

1.  **Таблица файлов (Содержание)**: Каждая ФС имеет аналог "содержания книги" — специальную таблицу (например, **inode table** в Ext4), где хранится информация о каждом файле:
    -   Имя файла.
    -   Атрибуты (права доступа, владелец, временные метки).
    -   Физическое расположение на диске (номера блоков, в которых хранится файл).
    -   Размер файла.

    Благодаря этой таблице системе не нужно сканировать весь диск для поиска файла. Она обращается к таблице, находит нужную "страницу" (блок) и сразу переходит к ней.

2.  **Журналирование**: Современные файловые системы (Ext4, XFS, NTFS) являются **журналируемыми**. Перед выполнением любой операции (например, перемещение файла), система сначала записывает намерение в специальный журнал. Если в процессе операции произойдет сбой (например, отключение питания), после перезагрузки система прочитает журнал, увидит незавершенную транзакцию и либо завершит ее, либо отменит, гарантируя целостность данных.

3.  **Управление пространством**: ФС отслеживает свободные и занятые блоки, решает, куда записать новый файл или его фрагмент.

### Таблицы разделов: MBR vs. GPT

Чтобы использовать диск, его нужно разбить на **разделы (partitions)**. Информация об этих разделах хранится в специальной таблице в самом начале диска.

1.  **MBR (Master Boot Record)**:
 
    -   **Надежность**: Таблица разделов хранится только в одном месте. При ее повреждении восстановить данные сложно.
    -   **Статус**: Устаревший стандарт.

2.  **GPT (GUID Partition Table)**:
    -   **Ограничения**:
        -   Поддерживает до **128 разделов** по умолчанию.
        -   Максимальный размер раздела практически не ограничен (зеттабайты).
    -   **Надежность**: Таблица разделов дублируется в начале и в конце диска, что повышает шансы на восстановление.
    -   **Статус**: Современный стандарт, используется во всех новых системах.

### Практика: работа с разделами с помощью `parted`

`parted` — мощная утилита для управления разделами диска.

**Пример рабочего процесса:**

1.  **Запуск `parted` для конкретного диска:**
    ```bash
    sudo parted /dev/sdb
    ```

2.  **Создание таблицы разделов (если диск новый):**
    ```bash
    # (parted)
    mklabel gpt
    ```

3.  **Создание раздела:**
    ```bash
    # (parted) mkpart [имя_раздела] [тип_фс] [начало] [конец]
    mkpart primary ext4 0% 100%
    ```
    Эта команда создаст один раздел `ext4`, занимающий весь диск.

4.  **Установка флагов раздела:**
    Флаги указывают на специальное назначение раздела.
    -   **Для LVM:**
        ```bash
        (parted) set 1 lvm on
        ```
    -   **Для RAID:**
        ```bash
        (parted) set 1 raid on
        ```

5.  **Просмотр разделов и выход:**
    ```bash
    # (parted)
    print
    # (parted)
    quit
    ```

6.  **Форматирование раздела:**
    После создания раздела его необходимо отформатировать в нужную файловую систему.
    ```bash
    sudo mkfs.ext4 /dev/sdb1
    ```

### Просмотр блочных устройств (`lsblk`)

Утилита `lsblk` позволяет просмотреть список всех блочных устройств в системе, их размеры, точки монтирования и взаимосвязи (например, разделы, LVM, RAID).

```bash
lsblk
```

Пример вывода `lsblk`:
```
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda           8:0    0     8G  0 disk 
├─sda1        8:1    0   1.8G  0 part /boot
├─sda2        8:2    0     1K  0 part 
└─sda3        8:3    0   6.2G  0 part 
  └─ubuntu--vg-ubuntu--lv 253:0    0   6.2G  0 lvm  /
sdb           8:16   0     1G  0 disk 
└─sdb1        8:17   0   500M  0 part 
```

-   **`NAME`**: Имя устройства.
-   **`TYPE`**: Тип устройства (disk, part, lvm, raid).
-   **`MOUNTPOINTS`**: Точки монтирования.

### Уникальные идентификаторы устройств (UUID)

Для надежного монтирования дисков, особенно в `/etc/fstab`, рекомендуется использовать UUID (Universally Unique Identifier) вместо имен устройств (`/dev/sdb1`). Имена устройств могут меняться при перезагрузке, тогда как UUID остается постоянным.

Утилита `blkid` позволяет просмотреть UUID и другие атрибуты блочных устройств:

```bash
sudo blkid
```

Пример вывода `blkid`:
```
/dev/sda1: UUID="a1b2c3d4-e5f6-7890-1234-567890abcdef" TYPE="ext4" PARTUUID="..."
/dev/sdb1: UUID="b2c3d4e5-f6a7-8901-2345-67890abcdef0" TYPE="ext4" PARTUUID="..."
/dev/mapper/ubuntu--vg-ubuntu--lv: UUID="c3d4e5f6-a7b8-9012-3456-7890abcdef01" TYPE="ext4"
```

## FUSE (Filesystem in Userspace)

**FUSE (Filesystem in Userspace)** — это интерфейс ядра Linux, который позволяет создавать файловые системы, работающие в пространстве пользователя, без необходимости писать код для ядра. Это значительно упрощает разработку и повышает безопасность.

**Как это работает:**
Модуль ядра FUSE действует как "мост". Он перенаправляет запросы к виртуальной файловой системе от ядра к пользовательской программе-демону, которая и реализует всю логику (чтение, запись, создание директорий).

### Преимущества FUSE

-   **Изоляция и безопасность:** Поскольку код файловой системы работает в пространстве пользователя, ошибка в нем не приведет к падению всей системы (Kernel Panic), в отличие от ошибки в нативном драйвере ядра.
-   **Гибкость и простота:** Разрабатывать файловую систему на любом языке программирования в userspace гораздо проще, чем писать модуль ядра на C.
-   **Разнообразие применений:** FUSE позволяет реализовать файловые системы поверх чего угодно:
    -   **Сетевые протоколы:** `sshfs` монтирует удаленную директорию через SSH.
    -   **Облачные хранилища:** `rclone` может монтировать Google Drive, Dropbox, S3 и десятки других облачных сервисов как локальную папку.
    -   **Архивы:** Монтирование `zip` или `tar` архива как файловой системы без его полной распаковки.
    -   **Базы данных и API:** Представление данных из базы данных или веб-API в виде файлов и директорий.
    -   **Шифрование:** `EncFS` или `gocryptfs` создают зашифрованную файловую систему поверх существующей директории.

### Примеры использования

-   **`sshfs`:** Монтирование удаленной файловой системы.
    ```bash
    # Установить sshfs
    sudo apt install sshfs
    # Смонтировать домашнюю директорию удаленного пользователя
    mkdir ~/remote_server
    sshfs user@remote-host:/home/user ~/remote_server
    ```

-   **`rclone`:** Монтирование облачного хранилища.
    ```bash
    # После настройки rclone (`rclone config`)
    mkdir ~/gdrive
    rclone mount "MyGoogleDrive:" ~/gdrive --daemon
    ```

## Файловые дескрипторы

Файловый дескриптор — это целое неотрицательное число, которое ядро использует для идентификации открытого файла или другого ресурса ввода-вывода (сокет, канал).

-   `0` – `stdin` (стандартный ввод)
-   `1` – `stdout` (стандартный вывод)
-   `2` – `stderr` (стандартный вывод ошибок)

### Просмотр количества открытых файловых дескрипторов

-   **`lsof` (List Open Files):** Показывает все файлы, открытые процессами.
    ```bash
    # Показать все открытые файлы для процесса с указанным PID
    sudo lsof -p <PID>
    # Посчитать количество открытых файлов для процесса
    sudo lsof -p <PID> | wc -l
    ```

-   **`ulimit`:** Позволяет просматривать и устанавливать лимиты ресурсов для текущей сессии пользователя, включая максимальное количество открытых файловых дескрипторов.
    ```bash
    # Показать текущий лимит на количество открытых файловых дескрипторов для текущего пользователя
    ulimit -n
    ```

-   **`cat /proc/sys/fs/file-nr`:** Показывает системную информацию о файловых дескрипторах.
    ```bash
    # Вывод содержит три значения:
    # 1. Количество выделенных файловых дескрипторов
    # 2. Количество неиспользуемых файловых дескрипторов
    # 3. Максимальное количество файловых дескрипторов, которое может быть выделено ядром
    cat /proc/sys/fs/file-nr
    ```

### Отслеживание утечек файловых дескрипторов

Утечка файловых дескрипторов происходит, когда процесс открывает файлы, но не закрывает их, со временем исчерпывая доступный лимит. Это может привести к ошибке "Too many open files".

-   **`lsof` (List Open Files):** Показывает все файлы, открытые процессом.
    ```bash
    # Показать все открытые файлы для процесса с указанным PID
    sudo lsof -p <PID>
    ```

-   **Просмотр через `/proc`:** Директория `/proc/<PID>/fd/` содержит символические ссылки на все файлы, открытые процессом. Подсчитав их количество, можно оценить потребление дескрипторов.
    ```bash
    # Посчитать количество открытых дескрипторов для процесса
    ls -l /proc/<PID>/fd/ | wc -l
    ```

-   **`fuser`:** Показывает, какие процессы используют указанный файл или файловую систему.

## Анализ дискового пространства

### Свободное место (`df`)

`df` (disk free) — это утилита, предназначенная для отображения информации о свободном и занятом дисковом пространстве на смонтированных файловых системах. Она работает очень быстро, поскольку не сканирует файловую систему, а считывает уже готовую информацию из **суперблока** файловой системы. Суперблок содержит метаданные о состоянии ФС, включая количество занятых и свободных блоков.

По умолчанию `df` выводит информацию в блоках (обычно 1КБ). Для более удобного чтения используются следующие опции:

```sh
# Показать свободное место в человекочитаемом формате
df -h

# Показать использование inode (индексных дескрипторов)
df -i
```
Если `inode` используется на 100%, вы не сможете создавать новые файлы, даже если на диске есть свободное место.

### Увеличение количества inodes (Ext2/3/4)

**Проблема:** В файловых системах семейства `Ext` (Ext2, Ext3, Ext4) количество inodes (индексных дескрипторов) **фиксируется в момент форматирования раздела**. Изменить это значение на уже существующей файловой системе без её пересоздания **невозможно**. Если у вас закончились inodes, вы не сможете создавать новые файлы, даже если на диске много свободного места.

**Решение:** Единственный способ — это создать резервную копию данных, переформатировать раздел с новыми параметрами и восстановить данные.

**Резервное копирование (Критически важно!)**

Перед любыми действиями создайте полную резервную копию всех данных с нужного раздела.

```sh
# Пример копирования данных с помощью rsync
sudo rsync -avh /path/to/your/mountpoint/ /path/to/backup/
```

**Отмонтирование раздела**

```sh
sudo umount /path/to/your/mountpoint
```

**Переформатирование с нужным количеством inodes**

Используйте команду `mkfs.ext4` с одним из флагов:

*   `-i bytes-per-inode`: Задаёт соотношение байт на один inode. Чем меньше значение, тем больше будет создано inodes.
    *   Значение по умолчанию обычно `16384` (1 inode на 16 КБ).
    *   Для систем с огромным количеством мелких файлов (почта, кэш) можно поставить `4096` (1 inode на 4 КБ).
*   `-N number-of-inodes`: Прямо указывает, сколько inodes нужно создать.

**Пример (рекомендуемый способ):**

```sh
# Замените /dev/sdXN на ваш раздел
sudo mkfs.ext4 -i 4096 /dev/sdXN
```

**Монтирование и восстановление данных**

```sh
# Монтируем свежеотформатированный раздел
sudo mount /dev/sdXN /path/to/your/mountpoint

# Восстанавливаем данные из резервной копии
sudo rsync -avh /path/to/backup/ /path/to/your/mountpoint/
```
**Альтернатива:** Файловые системы, такие как **XFS** или **Btrfs**, выделяют inodes динамически, поэтому у них нет проблемы с исчерпанием их запаса. Миграция на одну из этих ФС может быть долгосрочным решением.

### Занятое место (`du`)

Команда `du` (disk usage) рекурсивно подсчитывает, сколько места на диске занимают файлы и директории. В отличие от `df`, `du` реально проходит по файловой системе, считывая размеры каждого файла и каталога. Это делает её более медленной, но она показывает фактический объем данных, занимаемый файлами.

-   `-h` (`--human-readable`): Выводить размеры в удобном для человека формате (K, M, G).
-   `-s` (`--summarize`): Показать только итоговую сумму для указанной директории, не показывая размеры вложенных файлов и папок.
-   `-d <N>` или `--max-depth=<N>`: Установить глубину рекурсии. Например, `--max-depth=1` покажет размеры всех файлов и директорий на первом уровне вложенности.
-   `-c` (`--total`): Показать итоговую сумму в конце списка.

```sh
# Узнать общий (суммарный) размер текущей директории
du -sh .

# Узнать, сколько места занимает конкретная директория, например /var/log
sudo du -sh /var/log

# Показать размеры всех директорий внутри /var на один уровень вглубь и отсортировать их по размеру, чтобы найти самые большие
sudo du -h --max-depth=1 /var | sort -rh
```

**Разница между `df` и `du`**:
-   `df` (disk free) показывает использование диска с точки зрения файловой системы, считывая информацию из **суперблока**. Он мгновенно предоставляет данные о том, сколько всего блоков занято и свободно на разделе. `df` не пересчитывает занятое место, а получает уже готовую информацию. Это делает его очень быстрым и подходящим для мониторинга общего состояния дискового пространства.
-   `du` (disk usage) рекурсивно подсчитывает суммарный размер конкретных файлов и директорий, проходя по файловой системе. Это более медленная операция, так как она реально пересчитывает объемы данных, но она показывает фактический объем данных, занимаемый файлами. `du` полезен для определения, какие каталоги или файлы занимают больше всего места.

Ни одна из утилит не является "лучше" другой; они служат разным целям. `df` дает быстрый обзор состояния файловой системы, а `du` — детальную информацию о занятом пространстве конкретными файлами и каталогами.

Расхождения между `df` и `du` могут возникнуть по нескольким причинам:
1.  **Удаленные, но открытые файлы:** Если файл был удалён, но всё ещё используется каким-либо процессом (дескриптор файла открыт), `du` не будет учитывать этот файл, а `df` будет, так как место на диске еще не освобождено до тех пор, пока процесс не закроет файл.
2.  **Блочное выделение:** `df` считает выделенные блоки, а `du` — фактический размер данных. Если у вас много мелких файлов, которые не полностью заполняют свои блоки, `df` может показать больший объем, чем `du`, поскольку файловая система выделяет место блоками фиксированного размера.
3.  **Точки монтирования:** `df` показывает информацию только для смонтированных файловых систем, тогда как `du` может подсчитывать размер файлов в директориях, которые могут быть точками монтирования для других файловых систем.

### Место на диске не освободилось после удаления файлов

Иногда после удаления больших файлов (`rm file.log`) команда `df -h` показывает, что свободное место не увеличилось.

Это происходит, когда какой-либо запущенный процесс всё ещё использует этот "удалённый" файл. В файловых системах Linux удаление файла командой `rm` лишь убирает его имя (ссылку) из директории. Сами данные на диске (inode и блоки данных) остаются нетронутыми до тех пор, пока хотя бы один процесс держит этот файл открытым (имеет открытый файловый дескриптор).

Чтобы найти процесс, который удерживает удалённый файл, можно использовать `lsof` (list open files) и отфильтровать вывод по слову "deleted":

- **Способ 1:**
  ```sh
  sudo lsof | grep deleted
  ```
  Эта команда покажет список процессов и файлы, которые они держат открытыми, несмотря на удаление.

- **Способ 2:**
  ```sh
  sudo lsof +L1
  ```
  Эта команда использует встроенную функцию `lsof` для поиска файлов, у которых количество ссылок (link count) меньше 1, то есть удалённых файлов.

**Решение:**
Чтобы освободить место, нужно заставить процесс "отпустить" файл. Есть несколько способов:

1.  **Перезапустить сервис/процесс (рекомендуемый способ):**
    Если файл удерживается системной службой (например, `nginx` или `rsyslog`), самым безопасным способом будет её перезапуск.
    ```sh
    sudo systemctl restart <имя_сервиса>
    ```
    Это заставит процесс корректно завершиться и освободить все файловые дескрипторы.

2.  **Завершить процесс:**
    Если это не критичный сервис, можно просто завершить процесс, используя его PID из вывода `lsof`.
    ```sh
    kill <PID>
    ```

3.  **"Очистить" файл без перезапуска (рискованный способ):**
    В некоторых случаях, когда перезапуск сервиса нежелателен, можно очистить содержимое файла, не удаляя его. Это можно сделать, перенаправив в него пустой вывод.
    ```sh
    # > /path/to/original/file/that/was/deleted
    # Пример для лог-файла nginx, который был удалён, но удерживается процессом с PID 1234
    # Путь к файлу можно найти в выводе lsof
    sudo truncate -s 0 /proc/1234/fd/5 
    ```
    - `truncate -s 0` обрезает файл до нулевого размера, что немедленно освобождает дисковое пространство.
    - `/proc/<PID>/fd/<номер_дескриптора>` — это специальный путь, который позволяет получить доступ к файлу через открытый дескриптор процесса.

## Мониторинг дисков

### Мониторинг нагрузки

-   **`iostat`**: Статистика по вводу/выводу для устройств.
-   **`iotop`**: Показывает использование диска процессами в реальном времени (аналог `top` для I/O).
    ```sh
    sudo iotop -oP
    ```
    - `-o`: Показывать только активные процессы.
    - `-P`: Не разделять нагрузку по потокам.
-   **`pidstat`**: Отчёт по использованию ресурсов процессами, включая I/O.
    ```sh
    pidstat -dl 1
    ```

### Проверка состояния дисков с помощью `smartctl`

**S.M.A.R.T. (Self-Monitoring, Analysis, and Reporting Technology)** — это технология самодиагностики, встроенная в большинство современных жёстких дисков (HDD) и твердотельных накопителей (SSD). Утилита `smartctl` из пакета `smartmontools` позволяет считывать эти данные для оценки состояния диска и прогнозирования возможных сбоев.

#### Использование `smartctl`

1.  **Установка:**
    ```bash
    sudo apt-get install smartmontools # Debian/Ubuntu
    sudo yum install smartmontools     # CentOS/RHEL
    ```

2.  **Просмотр общей информации о здоровье диска:**
    ```bash
    # Замените /dev/sda на ваш диск
    sudo smartctl -H /dev/sda
    ```
    В выводе ищите строку `SMART overall-health self-assessment test result`. Значение `PASSED` говорит о том, что диск считает себя исправным.

3.  **Просмотр всех S.M.A.R.T. атрибутов:**
    ```bash
    sudo smartctl -a /dev/sda
    ```
    Эта команда выводит подробную таблицу с атрибутами, такими как:
    -   `Reallocated_Sector_Ct`: Количество переназначенных секторов. Рост этого значения — плохой знак.
    -   `Temperature_Celsius`: Текущая температура диска.
    -   `Power_On_Hours`: Количество часов, которые диск был включён.
    -   `UDMA_CRC_Error_Count`: Ошибки передачи данных по интерфейсу. Могут указывать на проблемы с кабелем.

## Кэширование файловой системы (Page Cache)

Поскольку **устройства ввода-вывода являются слабым местом** любой системы, Linux использует агрессивное кэширование для ускорения доступа к данным.

**Page Cache (кэш страниц)** — это основной механизм дискового кэша. Когда процесс читает файл, его страницы (куски данных) копируются с диска в оперативную память (в Page Cache). **Единожды открытый файл загружается в кэш и не удаляется оттуда, пока системе не потребуется память** для других, более важных задач. При повторном чтении данные отдаются мгновенно из памяти, минуя медленный диск.

То же самое происходит и при записи: данные сначала записываются в кэш, а ядро позже, в фоновом режиме, сбрасывает их на диск. Это объясняет, почему в выводе утилиты `free -m` колонка `buff/cache` почти всегда занята — Linux использует всю доступную память для ускорения работы.

### Суперблок (Superblock)

**Суперблок** — это структура, которая содержит метаданные о самой файловой системе. Он критически важен для её работы, поэтому в системе хранится несколько его резервных копий.

**Содержимое суперблока:**
-   Размер файловой системы и размер блока.
-   Количество свободных и занятых блоков и inode'ов.
-   Расположение таблицы inode'ов.
-   Точка монтирования и статус файловой системы.

Посмотреть информацию о суперблоке для файловой системы Ext2/3/4:
```sh
sudo dumpe2fs /dev/sda1 | grep -i superblock
```

## Монтирование директории на отдельный диск

Чтобы содержимое определённой директории (например, `/var/log` или `/home/user/data`) физически хранилось на отдельном диске, необходимо выполнить следующие шаги:

1.  **Подготовить диск**: Убедитесь, что на диске есть раздел и на нём создана файловая система (например, ext4 или xfs).
    -   Посмотреть диски и разделы: `lsblk`
    -   Создать файловую систему (если нужно): `sudo mkfs.ext4 /dev/sdb1`

2.  **Создать точку монтирования**: Это пустая директория, к которой будет "привязан" диск.
    ```sh
    sudo mkdir -p /path/to/directory
    ```

3.  **Временно смонтировать диск**: Это позволит проверить, что всё работает правильно.
    ```sh
    sudo mount /dev/sdb1 /path/to/directory
    ```
    После этого все файлы, созданные в `/path/to/directory`, будут физически записываться на диск `/dev/sdb1`.

4.  **Настроить автоматическое монтирование при загрузке**: Чтобы диск монтировался каждый раз при старте системы, нужно добавить запись в файл `/etc/fstab`.
    -   **Узнать UUID диска**: Это более надёжный способ идентификации, чем имя устройства (`/dev/sdb1`), которое может измениться.
        ```sh
        sudo blkid /dev/sdb1
        ```
    -   **Добавить запись в `/etc/fstab`**:
        ```
        # <file system> <mount point>   <type>  <options>       <dump>  <pass>
        UUID=...      /path/to/directory ext4    defaults        0       2
        ```

5.  **Перенести существующие данные (если необходимо)**:
    Если в директории уже были данные, их нужно перенести на новый диск. Это делается *до* настройки постоянного монтирования в `fstab`.
    ```sh
    # 1. Смонтировать новый диск во временную точку
    sudo mount /dev/sdb1 /mnt

    # 2. Скопировать данные со сохранением прав
    sudo rsync -av /path/to/directory/ /mnt/

    # 3. Переименовать старую директорию (для бэкапа)
    sudo mv /path/to/directory /path/to/directory.bak

    # 4. Создать пустую точку монтирования
    sudo mkdir /path/to/directory

    # 5. Размонтировать диск и смонтировать его в нужную точку
    sudo umount /mnt
    sudo mount /dev/sdb1 /path/to/directory

    # 6. Проверить, что данные на месте, и добавить запись в fstab
    ```

## Файл /etc/fstab

Файл `/etc/fstab` (file systems table) — это один из ключевых конфигурационных файлов в Linux, который содержит информацию о различных файловых системах и точках их монтирования. Система использует этот файл при загрузке для автоматического монтирования дисков, разделов и сетевых файловых систем.

Каждая строка в `/etc/fstab` представляет одну файловую систему и состоит из шести полей, разделенных пробелами или табами.

```text
<file system> <mount point>   <type>  <options>       <dump>  <pass>
```

1.  **`<file system>`**: Устройство или ресурс, который нужно смонтировать.
    *   **Рекомендуемый способ:** `UUID=<uuid>` (например, `UUID=abc-123...`). Это самый надёжный метод, так как UUID уникален и не меняется. Узнать UUID можно командой `sudo blkid`.
    *   **Альтернатива:** Путь к устройству, например, `/dev/sda1`. Менее надёжно, так как имя может измениться после перезагрузки.
    *   Для сетевых ФС здесь указывается `user@host:/path`.

2.  **`<mount point>`**: Директория в файловой системе, к которой будет "привязан" ресурс (например, `/home`, `/var/log`). Директория должна существовать.

3.  **`<type>`**: Тип файловой системы.
    *   Для дисков: `ext4`, `xfs`, `btrfs`, `vfat`.
    *   Для сетевых ФС: `nfs`, `cifs`.
    *   Для swap: `swap`.
    *   `auto`: Позволяет системе автоматически определить тип ФС.

4.  **`<options>`**: Опции монтирования, перечисляются через запятую.
    *   `defaults`: Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
    *   `rw` / `ro`: Монтировать в режиме чтение/запись или только чтение.
    *   `noatime`: Не обновлять `atime` (время последнего доступа) для файлов. Это может повысить производительность диска, так как сокращает количество операций записи.
    *   `nofail`: Не останавливать загрузку системы, если устройство не может быть смонтировано. Критически важно для съёмных дисков или сетевых ресурсов.
    *   `user`: Разрешить обычному пользователю монтировать файловую систему.

5.  **`<dump>`**: Используется утилитой `dump` для определения, нужно ли создавать резервную копию файловой системы.
    *   `0`: Не делать дамп.
    *   `1`: Делать дамп.
    *   На практике почти всегда установлено в `0`.

6.  **`<pass>`**: Определяет порядок проверки файловых систем утилитой `fsck` при загрузке.

    *   `0`: Не проверять.
    *   `1`: Устанавливается для корневой файловой системы (`/`). Она проверяется первой.
    *   `2`: Устанавливается для остальных файловых систем. Они проверяются после корневой.

После редактирования `/etc/fstab` можно проверить корректность монтирования всех записей командой:
```bash
sudo mount -a
```
Если команда выполнилась без ошибок, значит, синтаксис в файле корректен.

### Альтернативные способы монтирования

Хотя `/etc/fstab` является стандартом (и на современных системах обрабатывается `systemd`), существуют и другие методы для автоматического монтирования, каждый со своими преимуществами.

#### Autofs (Монтирование по требованию)

`autofs` — это сервис, который автоматически монтирует файловую систему, как только к ней происходит обращение, и отмонтирует ее после периода бездействия. Это идеальный вариант для съёмных дисков или сетевых папок, чтобы не держать их подключенными постоянно.

1.  **Установите `autofs`**:
    ```bash
    sudo apt install autofs  # Debian/Ubuntu
    sudo dnf install autofs  # Fedora/CentOS
    ```

2.  **Настройте главный файл `/etc/auto.master`**. Добавьте строку, которая указывает на вашу карту монтирования. Например, для прямых монтирований (где путь абсолютный):
    ```
    # <точка монтирования> <файл карты>   <опции>
    /-                      /etc/auto.direct --timeout=60
    ```
    Здесь `/-` означает, что пути в карте будут абсолютными, а `--timeout=60` — отмонтировать диск после 60 секунд бездействия.

3.  **Создайте и настройте файл карты `/etc/auto.direct`**. Добавьте в него строку для вашего диска:
    ```
    # <полный путь>  <опции монтирования>  <источник>
    /mnt/data         -fstype=ext4,rw       :/dev/disk/by-uuid/1234-ABCD-5678-EFGH
    ```
    Обратите внимание на синтаксис: опции идут до источника, а перед источником ставится двоеточие `:`.

4.  **Перезапустите сервис**:
    ```bash
    sudo systemctl restart autofs
    ```
    Теперь, как только вы или программа попытаетесь получить доступ к `/mnt/data`, `autofs` автоматически смонтирует диск.

#### Правила Udev (Продвинутый, на основе событий)

`udev` — это подсистема ядра, которая управляет устройствами в `/dev`. Можно создать правило, которое будет выполнять команду `mount` каждый раз, когда ядро обнаруживает подключение конкретного диска. Этот метод очень гибкий, но сложнее в настройке.

1.  **Найдите уникальные атрибуты диска.** Например, серийный номер.
    ```bash
    udevadm info -a -n /dev/sdb1 | grep 'serial'
    ```
    Вы получите что-то вроде `ATTRS{serial}=="123456789"`.

2.  **Создайте файл правила** в `/etc/udev/rules.d/`, например, `99-mydisk.rules`.
    ```
    ACTION=="add", KERNEL=="sd*", ATTRS{serial}=="123456789", RUN+="/bin/mount /dev/%k /mnt/data"
    ```
    Это правило говорит: "когда добавляется (`add`) устройство, имя которого начинается на `sd*` и у которого серийный номер `123456789`, выполнить команду монтирования". `%k` подставит имя устройства (например, `sdb1`).

3.  **Перезагрузите правила `udev`**:
    ```bash
    sudo udevadm control --reload-rules && sudo udevadm trigger
    ```

## Логическое восстановление данных

**Важно:** При потере данных первое, что нужно сделать, — это отмонтировать файловую систему (`umount`) или смонтировать её в режиме "только чтение" (`mount -o remount,ro`), чтобы предотвратить перезапись удалённых данных.

### Инструменты для восстановления

-   **`TestDisk`**: Мощная утилита для восстановления потерянных разделов и исправления загрузочных секторов.
-   **`PhotoRec`**: Идёт в комплекте с `TestDisk`. Восстанавливает файлы по их сигнатурам, игнорируя файловую систему. Эффективен для восстановления фотографий, документов и архивов с отформатированных носителей.

-   **Для Ext3/Ext4:**
    -   `extundelete`: Ищет удалённые файлы в журнале файловой системы.
    -   `ext4magic`: Более продвинутый инструмент для восстановления.

-   **Для XFS:**
    -   `xfs_repair`: В первую очередь, это инструмент для проверки и исправления метаданных. Возможности восстановления удалённых файлов ограничены.

-   **Для Btrfs:**
    -   `btrfs restore`: Специализированная утилита для извлечения файлов с повреждённой или немонтируемой файловой системы Btrfs.

## Проверка и восстановление целостности ФС (`fsck`)

`fsck` (File System Check) — это стандартная утилита для проверки и исправления ошибок в файловых системах Linux.

**Ключевые моменты:**
-   **Запуск на размонтированном разделе:** `fsck` всегда должна запускаться на **размонтированной** файловой системе, чтобы избежать повреждения данных.
-   **Автоматическая проверка:** Система обычно автоматически запускает `fsck` при загрузке, если файловая система была помечена как "грязная" (например, после некорректного выключения).

**Использование:**
```bash
# Принудительно проверить файловую систему на разделе /dev/sdXN
sudo fsck -f /dev/sdXN
```

**Особенности для XFS:**
Файловая система XFS имеет собственную утилиту для восстановления — `xfs_repair`. Стандартный `fsck.xfs` является лишь оберткой и не выполняет реального исправления ошибок.
```bash
# Для проверки и восстановления XFS
sudo xfs_repair /dev/sdXN
```

## Мониторинг событий ФС (`inotify`)

`inotify` — это подсистема ядра Linux, которая позволяет приложениям отслеживать события в файловой системе в реальном времени (например, создание, удаление, изменение файлов).

**Утилиты для работы с `inotify`:**
-   **`inotifywait`**: Ожидает определённого события и завершает работу. Удобно для использования в скриптах.
    ```bash
    # Ждать любого события в директории /tmp и выйти
    inotifywait /tmp
    ```
-   **`inotifywatch`**: Собирает статистику о событиях в файловой системе.

**Пример с `inotifywait`:**
```bash
# Мониторить директорию /var/www в реальном времени (-m) и рекурсивно (-r)
inotifywait -m -r /var/www
```

**Лимиты `inotify`:**
Существует ограничение на количество "наблюдателей" (watches), которое может создать один пользователь. Если вы видите ошибку "Too many open files" при использовании `inotify`, возможно, нужно увеличить этот лимит:
```bash
# Посмотреть текущий лимит
sysctl fs.inotify.max_user_watches

# Установить новый лимит
sudo sysctl -w fs.inotify.max_user_watches=524288
```
