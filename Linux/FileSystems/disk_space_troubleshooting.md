# Устранение нехватки места на диске

## Определения

- **Зарезервированное пространство ext:** Часть дискового пространства в файловых системах ext2/3/4 (по умолчанию 5%), доступная только пользователю `root`. Предназначена для обеспечения стабильности системы при полном заполнении диска обычными пользователями.

## Основные концепции

- **Причины нехватки места:** Лог-файлы, кэши, временные файлы, старые ядра, базы данных, контейнеры Docker с accumulated логами.
- **Диагностика:** Определение типа нехватки —_BLOCKS_ (`df -h`) или inodes (`df -i`) — критично для выбора стратегии устранения.
- **Зарезервированное пространство ext:** Файловые системы ext2/3/4 резервируют 5% блоков для `root`, чтобы критически важные системные процессы (запись логов, вход администратора) могли работать даже при полном заполнении диска.

## Практические сценарии

### 1. Аварийное освобождение места (ext)

**Ситуация:** Диск заполнен на 100%, базовые команды не работают (не могут создать временные файлы).

**Решение:** Временно обнулить резерв для получения немедленного доступа к пространству.

```bash
sudo tune2fs -m 0 /dev/sdX
```

**Важно:** После очистки диска **обязательно верните резерв на 5%**:

```bash
sudo tune2fs -m 5 /dev/sdX
```

Отсутствие резерва повышает риск фрагментации и может помешать `root` исправить проблемы с диском.

### 2. Диагностика и поиск крупных файлов

**Определение занятого пространства по директориям:**

```bash
du -sh /* 2>/dev/null | sort -rh | head -20
```

**Интерактивный анализ:** `ncdu` — удобная утилита для навигации по директориям и выявления крупнейших потребителей пространства.

### 3. Очистка часто заполняемых ресурсов

- **Логи:** Ротация через `logrotate`, очистка старых файлов в `/var/log/`.
- **Docker:** Удаление stopped контейнеров, unused образов и томов (`docker system prune`).
- **Пакетный менеджер:** Очистка кэша (`apt clean`, `yum clean all`).
- **Журнал systemd:** `journalctl --vacuum-size=100M`.
