# Virtual Data Optimizer (VDO)

## Определения

- **VDO (Virtual Data Optimizer):** Технология оптимизации дискового пространства в ядре Linux (модули `kvdo` и `uds`), обеспечивающая дедупликацию, сжатие и тонкое выделение ресурсов (**Thin Provisioning**) на уровне блочного устройства.
- **Дедупликация (Deduplication):** Процесс устранения дублирующихся блоков данных. VDO хранит только одну уникальную копию блока, заменяя повторы ссылками. Выполняется с помощью сервиса **UDS**.
- **Сжатие (Compression):** Уменьшение размера уникальных блоков данных с использованием алгоритма **LZ4**. Выполняется после дедупликации; сжатые блоки упаковываются в физические блоки по 4 КБ.
- **UDS (Universal Deduplication Service):** Индекс метаданных, используемый для быстрого поиска идентичных блоков по их хеш-суммам.

## Основные концепции

### Архитектура и место в стеке

VDO работает как промежуточный слой Device Mapper. В современных системах (RHEL 9+) VDO полностью интегрирован в LVM как тип логического тома.

```text
+---------------------------------------------------+
|      Файловая система (XFS, Ext4)                 |
+---------------------------------------------------+
|      VDO LV (Логический объем, e.g., 100G)        |
+---------------------------------------------------+
|      VDO Pool (Физический слой: Сжатие/Дедуп)     |
+---------------------------------------------------+
|      Физическое устройство (PV / RAID / LUKS)     |
+---------------------------------------------------+
```

### Типы индекса UDS

Тип индекса выбирается при создании и не может быть изменен позже:
- **Dense (Плотный):** Режим по умолчанию. Обеспечивает максимальную эффективность дедупликации. Требует ~1 ГБ ОЗУ на 1 ТБ окна дедупликации.
- **Sparse (Разреженный):** Требует в 10 раз меньше памяти (~1 ГБ ОЗУ на 10 ТБ окна), но полагается на временную локальность данных (повторы должны приходить группами). Использует в 10 раз больше места на диске для метаданных.

### Размер Slab

**Slab** — базовая единица распределения физического пространства (по умолчанию 2 ГБ).
- VDO ограничен **8192 слабами**.
- С дефолтным размером 2 ГБ максимальный физический объем VDO составляет **16 ТБ**.
- Для поддержки до **256 ТБ** физического пространства необходимо использовать Slab размером 32 ГБ при создании.

### Порядок обработки записей

VDO обрабатывает каждую запись последовательно:
1. **Дедупликация:** Блок вычисляется по хешу, выполняется поиск в UDS. Если найден дубликат — используется существующая запись.
2. **Сжатие:** Уникальные блоки сжимаются алгоритмом LZ4. Если сжатый блок умещается в меньший размер, экономится место.
3. **Упаковка (Packing):** Сжатые блоки упаковываются в физические страницы по 4 КБ, что позволяет размещать несколько логических блоков в одном физическом.

### Block Map

**Block Map** — структура, отображающая логические сектора на физические. Кэшируется в ОЗУ для минимизации задержек. Размер кэша влияет на производительность при случайном доступе.

### Write Policy

Политика записи определяет гарантии сохранности данных при отказе питания:
- **`sync`:** Каждая запись финализируется на диск через `fdatasync`. Безопасно для любых дисков.
- **`async`:** Данные принимаются в кэш ядра. Требует NVRAM, ИБП или Supercaps на дисках.
- **`auto`:** Автовыбор на основе возможностей устройства (рекомендуется).

### Поддерживаемые файловые системы

- **XFS:** Рекомендуется. Поддерживает большие разреженные файлы и discard.
- **Ext4:** Поддерживается. Требует аккуратной работы с discard для освобождения блоков.

## Практические сценарии

### Требования и подготовка

**Минимальные требования:**
- **ОС:** RHEL 9+, CentOS Stream 9+, Rocky Linux 9+, AlmaLinux 9+, Oracle Linux 9+
- **Ядро:** 5.14+ (проверка: `uname -r`)
- **Пакеты:** `kmod-kvdo`, `lvm2-vdo`
- **Модуль ядра:** `kvdo` загружается автоматически при установке пакета

```bash
# Проверка поддержки VDO в ядре
sudo modprobe kvdo
lsmod | grep kvdo
# → kvdo                  45056  0

# Установка (RHEL 9+)
sudo dnf install lvm2-vdo kmod-kvdo
```

### Установка (RHEL 9+)

```bash
# Установка LVM-интеграции и модулей ядра
sudo dnf install lvm2-vdo kmod-kvdo
```

### Создание VDO-тома через LVM

```bash
# Создание VDO-тома: 10ГБ физики, 100ГБ логики (10:1)
# --type vdo: включает дедупликацию и сжатие
sudo lvcreate --type vdo --name my_vdo_lv --size 10G --virtualsize 100G my_vg

# Создание с разреженным (Sparse) индексом и увеличенным Slab
sudo lvcreate --type vdo --name big_vdo_lv --size 20T --virtualsize 100T \
  --vdosettings 'vdo_slab_size_mb=32768 vdo_use_sparse_index=enabled' my_vg
```

### Создание VDO напрямую через vdosetup

VDO можно создать поверх блочного устройства без LVM. Используется для специализированных сценариев или когда LVM не требуется.

```bash
# Очистка целевого устройства (все данные будут потеряны)
sudo wipefs -a /dev/sdb1

# Создание VDO-устройства
sudo vdosetup create --name=vdo1 \
  --device=/dev/sdb1 \
  --vdoLogicalSize=100G \
  --vdoPhysicalSize=10G \
  --writePolicy=auto \
  --compression=enabled \
  --deduplication=enabled

# Форматирование и монтирование
sudo mkfs.xfs /dev/mapper/vdo1
sudo mkdir -p /mnt/vdo_direct
sudo mount -o discard /dev/mapper/vdo1 /mnt/vdo_direct
```

**Параметры `vdosetup`:**
| Параметр | Описание |
| :--- | :--- |
| `--vdoLogicalSize` | Виртуальный (логический) размер VDO |
| `--vdoPhysicalSize` | Физический размер backing device |
| `--writePolicy` | `auto`, `sync`, `async` |
| `--compression` | `enabled` / `disabled` |
| `--deduplication` | `enabled` / `disabled` |
| `--slabSize` | Размер slab в MB (2048, 4096, 8192, 16384, 32768) |
| `--sparseIndex` | Включить sparse-индекс |

### Изменение размеров (Resize)

**Увеличение физического объема (Pool):**
```bash
# 1. Расширить VG (если нужно)
# 2. Расширить VDO Pool
sudo lvextend -L +50G my_vg/vdo_pool_my_vdo_lv
```

**Увеличение логического объема (Virtual Size):**
```bash
# 1. Расширить логический том
sudo lvextend -L +200G my_vg/my_vdo_lv
# 2. Расширить файловую систему
sudo xfs_growfs /mnt/vdo_data
```

Подробнее о resize см. в [LVM — Изменение размеров](./LVM/operations/lvm_resize.md).

### Мониторинг и диагностика

```bash
# Статистика экономии (уровень LVM)
sudo lvs -o+vdo_compression,vdo_deduplication,vdo_usage_percent

# Детальная статистика (vdostats)
sudo vdostats --human-readable

# Низкоуровневая диагностика через sysfs
ls /sys/kvdo/my_vdo_lv/statistics/
```

**Ключевые метрики `vdostats`:**
- `physical size` — общий физический объем
- `physical used` — занято физически
- `virtual size` — виртуальный размер
- `virtual used` — занято виртуально
- `saving factor` — коэффициент экономии

### Удаление и отключение VDO

```bash
# Отмонтировать ФС
sudo umount /mnt/vdo_data

# Удалить VDO LV (через LVM)
sudo lvremove my_vg/my_vdo_lv
# → Это удалит VDO Pool LV (vdo_pool_my_vdo_lv) и сам my_vdo_lv

# Или удалить напрямую через vdostatus + vdostop
sudo vdostatus --mode summary
# → /dev/mapper/vdo1      2.0 GB physical   17 GB logical
sudo vdostop /dev/mapper/vdo1
```

**Важно:** Удаление VDO необратимо. Все сжатые и дедуплицированные данные будут потеряны. Рекомендуется сделать бэкап критичных данных перед удалением.

## Эксплуатация и восстановление

### Режимы записи (Write Policy)

- **`sync`:** Гарантирует запись на диск. Безопасно для дисков без защиты от потери питания.
- **`async`:** Высокая производительность. Требует наличия NVRAM/ИБП/Supercaps на дисках.
- **`auto`:** Попытка автоопределения (рекомендуется).

### Исчерпание физического пространства

Если VDO Pool заполнен на 100%, устройство переходит в режим **Read-Only**.
**Действия для восстановления:**
1.  **Увеличение Pool:** Добавить физическое пространство через `lvextend`.
2.  **Очистка данных:** Если расширение невозможно, удалите файлы и выполните `fstrim -v /mnt/vdo_data`. VDO освободит блоки только после получения команд `discard`.
3.  **Мониторинг:** Рекомендуется настроить алерты на 80% заполнения физического пула.

### Бэкап и восстановление

VDO не предоставляет встроенных механизмов бэкапа метаданных. Для восстановления после сбоя:
1. Восстановите файловую систему с помощью `xfs_repair` или `fsck`.
2. Если LV удален, восстановите из резервной копии LVM (`/etc/lvm/backup/`).
3. Данные на физическом уровне могут быть восстановлены только если структура UDS не повреждена.

## Производительность и требования

### Потребление памяти (RAM)

| Компонент | Требование |
| :--- | :--- |
| **VDO Module** | 38 МБ + 268 МБ на 1 ТБ физики + 1.6 МБ на 1 ТБ логики |
| **UDS Index (Dense)** | 1 ГБ на 1 ТБ окна дедупликации |
| **UDS Index (Sparse)** | 1 ГБ на 10 ТБ окна дедупликации |
| **Block Map Cache** | Минимум 150 МБ (по умолчанию 128 МБ кэша) |

### Выбор Write Policy

| Сценарий | Рекомендация |
| :--- | :--- |
| Диски без NVRAM, ИБП | `sync` |
| Enterprise-диски с NVRAM/Supercaps | `async` |
| Неизвестная конфигурация | `auto` |

### Особенности размещения

- **Шифрование (LUKS):** Должно быть **ПОД** VDO (`LUKS -> VDO -> XFS`). Шифрование поверх VDO сделает дедупликацию невозможной из-за высокой энтропии.
- **RAID:** VDO должен располагаться поверх аппаратного или программного RAID. VDO сам не обеспечивает избыточность.

### Троублшутинг

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| `VDO pool is full` | VDO Pool исчерпан | `lvextend -L +SIZE VG/pool` или `fstrim -v /mountpoint` |
| Высокое потребление ОЗУ | Слишком маленький slab | Увеличить `vdo_slab_size_mb` при пересоздании |
| Низкий коэффициент сжатия | Несжимаемые данные (медиа, зашифрованные) | Ожидаемо; для медиа VDO не подходит |
| Высокая латентность | Низкий Block Map Cache | Увеличить кэш через `vdo_slab_size_mb` |
| `kvdo module not found` | Модуль не установлен | `dnf install kmod-kvdo` |

## Сценарии использования

| Сценарий | Эффективность | Причина |
| :--- | :--- | :--- |
| **VDI / VM Images** | Максимальная | Огромное количество дубликатов системных файлов. |
| **Бэкапы (нешифрованные)** | Высокая | Повторы данных в инкрементальных копиях. |
| **Файловые помойки** | Средняя | Зависит от типов файлов (документы — ок, медиа — нет). |
| **Базы данных** | Низкая | Высокие накладные расходы на задержки (latency) I/O. |

### Сравнение VDO с Thin Provisioning

| Критерий | VDO | Thin Provisioning (LVM) |
| :--- | :--- | :--- |
| Дедупликация | Да (на уровне блоков) | Нет |
| Сжатие | Да (LZ4) | Нет |
| Overcommit | Да (виртуальный размер > физики) | Да |
| Экономия ОЗУ | Высокая (зависит от индекса) | Минимальная |
| Производительность | Средняя (накладные на dedup/compress) | Высокая |
| Подходит для | Медленно меняющиеся данные, бэкапы | Быстро меняющиеся данные, базы |
| Гибкость размера | Жесткий slab (нельзя изменить после создания) | Динамический |
