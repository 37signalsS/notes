# VDO (Virtual Data Optimizer)

## Определения

* **VDO (Virtual Data Optimizer)** — технология от Red Hat для снижения потребления дискового пространства. Работает на уровне блочного устройства.
* **Дедупликация (Deduplication)** — процесс замены дублирующихся блоков данных ссылками на один уникальный блок. Особенно эффективна для однотипных данных (например, множество ВМ с одинаковой ОС).
* **Сжатие (Compression)** — алгоритм сжатия данных (используется LZ4).
* **Thin Provisioning (Тонкое выделение)** — виртуальное выделение места. Диску выделяется больше места, чем физически доступно (например, физический диск 50 ГБ, а виртуальный — 500 ГБ).

## Основные концепции

### Как работает VDO

VDO располагается **поверх блочного устройства** и **ниже файловой системы**.

```
Файловая система (XFS, ext4)
        ↓
    VDO (сжатие + дедупликация + thin provisioning)
        ↓
Блочное устройство (HDD, SSD, RAID, LUKS)
```

* **Дедупликация:** Одинаковые блоки данных сохраняются один раз. Эффективно для ВМ с идентичными ОС.
* **Сжатие:** Каждый блок сжимается алгоритмом LZ4.
* **Thin Provisioning:** Файловая система видит больший объем, чем физически доступно. Позволяет "overcommit" дискового пространства.

### Режимы записи

* **synchronous (sync):** VDO ожидает подтверждения записи от диска. Гарантирует целостность данных, но медленнее.
* **asynchronous (async):** VDO не ждет подтверждения. Быстрее, но есть риск потери данных при сбое питания.
* **auto:** VDO сам выбирает режим в зависимости от накопителя (по умолчанию).

### Производительность

VDO потребляет ресурсы CPU и RAM, что снижает производительность:

* При синхронной записи падение скорости может достигать 50-60%.
* Требуется ~700 МБ ОЗУ на 1 ТБ физического диска.

## Практические сценарии

### Установка

```bash
# Установка VDO и утилит (RHEL/CentOS)
sudo dnf install vdo kmod-kvdo
```

### Создание VDO-тома

```bash
# Создание VDO
# name=vdo_name -- имя тома
# device=/dev/sdX -- блочное устройство
# vdoLogicalSize=XXG -- логический размер (thin provisioning)
sudo vdo create --name=vdo_name --device=/dev/sdX --vdoLogicalSize=50G

# Проверка статуса
sudo vdo status --name=vdo_name
```

### Создание файловой системы и монтирование

```bash
# Создание файловой системы поверх VDO
sudo mkfs.xfs -K /dev/mapper/vdo_name

# Монтирование (временное)
sudo mkdir /mnt/vdo
sudo mount /dev/mapper/vdo_name /mnt/vdo

# Монтирование (постоянное через /etc/fstab)
# Опция x-systemd.requires=vdo.service гарантирует запуск после VDO
echo "/dev/mapper/vdo_name /mnt/vdo xfs defaults,x-systemd.requires=vdo.service 0 0" | sudo tee -a /etc/fstab
```

### Мониторинг

```bash
# Просмотр статистики VDO ( space-saving, compression ratio )
sudo vdostats --human-readable

# Подробная информация
sudo vdo status --name=vdo_name
```

### Управление

```bash
# Остановка/запуск VDO
sudo systemctl stop vdo.service
sudo systemctl start vdo.service

# Включение/отключение сжатия
sudo vdo enableCompression --name=vdo_name
sudo vdo disableCompression --name=vdo_name

# Включение/отключения дедупликации
sudo vdo enableDeduplication --name=vdo_name
sudo vdo disableDeduplication --name=vdo_name
```

## Дополнительная информация

### Требования

* **Оперативная память:** ~700 МБ на 1 ТБ физического диска.
* **Место на диске:** Минимум ~5 ГБ физического диска.
* **Размер Slab:** Влияет на максимальный объем. Для >16 ТБ нужно указать `--vdoSlabSize=32G`.

### Когда использовать

* **Да:** Хранилища бэкапов, ВМ с идентичными ОС, файловые хранилища с высокой избыточностью.
* **Нет:** Базы данных (низкая эффективность сжатия), высоконагруженные системы (падение производительности), небольшие объемы данных.

### Безопасность

* VDO не работает поверх зашифрованных томов (LUKS), если шифрование не поддерживает сквозную запись (passthrough).
* Рекомендуется использовать RAID под VDO для отказоустойчивости.
