# Мониторинг RAID-массивов

## Определения

**Мониторинг RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — непрерывное отслеживание состояния массива, дисков-участников и процессов восстановления (rebuild/reshape) для предотвращения потери данных.

**S.M.A.R.T. (Self-Monitoring, Analysis and Reporting Technology)** — встроенная в накопители система самодиагностики для оценки физического состояния дисков (износ, ошибки чтения, перегрев).

## Основные концепции

### Источники информации и инструменты

| Источник | Команда / Метод | Назначение |
| :--- | :--- | :--- |
| **Ядро (sysfs)** | `cat /proc/mdstat` | Быстрый статус всех активных массивов. |
| **Утилита mdadm** | `mdadm --detail /dev/mdX` | Исчерпывающие данные о конкретном массиве. |
| **Суперблок** | `mdadm --examine /dev/sdX` | Проверка метаданных на уровне отдельного диска/раздела. |
| **SMART** | `smartctl -a /dev/sdX` | Анализ «здоровья» физического оборудования. |
| **Экспортеры** | `node_exporter` | Сбор метрик для Prometheus/Grafana. |

## Практические сценарии

### Оперативная проверка через терминал

Для наблюдения за процессом восстановления в реальном времени используется:
```bash
watch -n 1 cat /proc/mdstat
```

**Интерпретация вывода:**
*   `[UU]` — все диски в зеркале/массиве исправны.
*   `[_U]` — первый диск в RAID 1 вышел из строя (degraded).
*   `[>..........]` — процесс синхронизации (resync) или восстановления (recovery).
*   `speed=15420K/sec` — текущая скорость операций ввода-вывода при восстановлении.

### Глубокий анализ через mdadm

Команда `sudo mdadm --detail /dev/md0` предоставляет расширенные статусы:

| Состояние (State) | Описание |
| :--- | :--- |
| **active, clean** | Массив исправен, данные согласованы. |
| **active, degraded** | Массив работает, но отсутствует один или несколько дисков. Требуется вмешательство. |
| **active, checking** | Выполняется плановая проверка целостности (scrubbing). |
| **recovering** | Идёт перенос данных на новый диск (после замены). |
| **resyncing** | Начальная синхронизация данных после создания массива. |

### Анализ метаданных и предотвращение Split-Brain

При возникновении проблем со сборкой массива после сбоя, необходимо сравнить поле **Events** через `mdadm --examine`:
```bash
sudo mdadm --examine /dev/sda1 /dev/sdb1
```
*   **Events:** Если значения счетчика событий на дисках различаются, это означает, что один из дисков перестал получать обновления раньше другого (stale disk).
*   **Решение:** Автоматическая сборка может не произойти. Требуется ручная сборка с указанием наиболее актуального диска.

## Продвинутый мониторинг и управление

### Параметры sysfs для тонкой настройки

Интерфейс ядра `/sys/block/mdX/md/` позволяет управлять процессом мониторинга и восстановления.

1.  **Контроль ошибок (mismatch_cnt):**
    После выполнения проверки (`check`), значение в этом файле должно быть **0**.
    ```bash
    cat /sys/block/md0/md/mismatch_cnt
    ```
    Если значение > 0, это указывает на расхождения данных в RAID 1/10 или ошибки чётности в RAID 5/6.

2.  **Лимиты скорости восстановления:**
    Чтобы восстановление RAID не парализовало работу приложений, можно ограничить скорость (в КБ/сек):
    ```bash
    # Минимальная скорость (по умолчанию 1000)
    echo 50000 | sudo tee /sys/block/md0/md/sync_speed_min
    # Максимальная скорость (по умолчанию 200000)
    echo 100000 | sudo tee /sys/block/md0/md/sync_speed_max
    ```

### Автоматизация через Prometheus Node Exporter

В современных инфраструктурах используется `node_exporter` с включенным коллектором `mdadm` (активен по умолчанию).

**Ключевые метрики:**
*   `node_md_state` — текущее состояние массива (active, inactive и т.д.).
*   `node_md_disks_required` vs `node_md_disks` — разница указывает на деградацию.
*   `node_md_is_composite` — общее состояние здоровья.

### Настройка уведомлений в mdadm.conf

Для получения алертов на почту или выполнения внешних скриптов:
1.  Отредактируйте `/etc/mdadm/mdadm.conf`:
    ```text
    MAILADDR admin@example.com
    PROGRAM /usr/local/bin/raid-event-handler.sh
    ```
2.  Перезапустите службу:
    ```bash
    sudo systemctl restart mdadm
    ```

## Диагностика и обслуживание

### Проверка целостности (Scrubbing)

Рекомендуется выполнять раз в месяц для выявления «тихих» ошибок (bit rot).

```bash
# Запуск фоновой проверки
echo check | sudo tee /sys/block/md0/md/sync_action

# Мониторинг прогресса
cat /sys/block/md0/md/sync_completed
```

### Проверка физического состояния (SMART)

Для программного RAID диски доступны напрямую:
```bash
# Проверка здоровья через smartctl
sudo smartctl -H /dev/sda
# Просмотр атрибутов (Reallocated_Sector_Ct, Current_Pending_Sector)
sudo smartctl -A /dev/sda
```
Подробнее: [Проверка дисков в RAID](../../Diagnostics/Hardware/smartctl/index.md#проверка-дисков-в-raid-массивах).
