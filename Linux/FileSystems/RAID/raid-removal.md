# Удаление RAID-массива: полное руководство

## Определения

**Удаление RAID (Redundant Array of Independent Disks)** — процесс деактивации виртуального блочного устройства и полной очистки физических накопителей от метаданных. Операция является деструктивной и необратимой.

**Очистка суперблока (Metadata Clearing)** — удаление служебных заголовков RAID (`md` metadata) с физических дисков или разделов. Без выполнения этого шага ядро Linux может попытаться автоматически собрать массив при следующей загрузке (через `initramfs` или `udev`), даже если устройство было остановлено.

**Безопасное стирание данных (Secure Erase)** — многократная перезапись области данных с целью невозможного восстановления. Критично при утилизации или передаче дисков третьим лицам.

## Основные концепции

### Инструментарий для демонтажа

| Команда | Назначение | Особенности |
| :--- | :--- | :--- |
| **`mdadm --stop`** | Деактивация массива | Переводит массив в неактивное состояние. Устройство `/dev/mdX` исчезает из системы. |
| **`mdadm --zero-superblock`** | Стирание метаданных | Записывает нули в область суперблока. Критично для предотвращения автосборки. |
| **`wipefs --all`** | Очистка всех подписей | Самый надежный метод. Удаляет подписи RAID, LVM, файловых систем и GPT/MBR. |
| **`cryptsetup close`** | Закрытие LUKS | Необходимо, если RAID использовался как нижележащий слой для шифрования. |
| **`dmsetup remove`** | Удаление DM-устройств | Используется для принудительного удаления остаточных записей в Device Mapper. |
| **`blkid`** | Просмотр метаданных | Показывает текущие подписи на устройстве — полезно для проверки очистки. |
| **`lsblk -f`** | Информация о ФС и RAID | Отображает иерархию устройств, файловые системы и RAID-состояние. |

### Подготовка перед удалением

> **Критически важно:** Перед удалением RAID-массива убедитесь, что все данные перенесены или заархивированы. Удаление необратимо.

**Чек-лист подготовки:**

```bash
# 1. Проверка текущего состояния
cat /proc/mdstat
sudo mdadm --detail /dev/md0

# 2. Проверка использованных разделов
df -h | grep md
mount | grep md

# 3. Проверка LVM поверх RAID
sudo pvs | grep md
sudo lvs

# 4. Проверка шифрования
sudo cryptsetup status /dev/mapper/*

# 5. Проверка swap на RAID
swapon -s | grep md
```

**Если данные на RAID критичны:**
1. Создайте полный бэкап на внешний носитель или облако
2. Верифицируйте бэкап (проверьте целостность архива)
3. Только после подтверждения целостности — приступайте к удалению

## Практические сценарии

### Полный демонтаж массива (Стек «Сверху Вниз»)

Для безопасного удаления без зависаний системы процедура должна выполняться строго в порядке, обратном созданию (L7 → L1).

#### Шаг 1: Подготовка и размонтирование

1.  **Остановка сервисов:** Завершите работу всех БД и приложений, использующих данные на RAID.
    ```bash
    # Проверка открытых файлов на RAID
    sudo lsof /dev/md0
    sudo fuser -v /dev/md0
    ```
2.  **Остановка swap (если используется на RAID):**
    ```bash
    sudo swapoff /dev/md1  # Если swap-раздел на RAID
    ```
3.  **Размонтирование ФС:**
    ```bash
    sudo umount /mnt/raid_data
    ```
4.  **Удаление из fstab:**
    Отредактируйте `/etc/fstab` и удалите (или закомментируйте) строку монтирования этого массива.
    ```bash
    # Найдите строку с RAID
    grep -n "md" /etc/fstab
    # Закомментируйте или удалите
    sudo nano /etc/fstab
    ```

#### Шаг 2: Удаление вышележащих слоев (LVM/LUKS)

Если RAID является базой для других технологий:

*   **LUKS (Шифрование):**
    ```bash
    # Проверка статуса
    sudo cryptsetup status my_encrypted_raid
    
    # Закрытие
    sudo cryptsetup close my_encrypted_raid
    ```
*   **LVM:**
    ```bash
    # Проверка PV
    sudo pvs | grep md
    
    # Удаление LV (если есть)
    sudo lvremove /dev/vg_name/lv_name
    
    # Удаление VG
    sudo vgremove vg_name
    
    # Удаление PV
    sudo pvremove /dev/md0
    ```
    *Примечание: Если PV входит в активную VG, сначала удалите LV и VG.*

#### Шаг 3: Остановка массива mdadm

Проверьте статус:
```bash
cat /proc/mdstat
# → md0 : active raid1 sdc1[1] sdb1[0]
#       1953513472 blocks super 1.2 [2/2] [UU]
```

Остановите массив:
```bash
sudo mdadm --stop /dev/md0
# → mdadm: stopped /dev/md0
```

**Если устройство занято (Device or resource busy):**
1. Найдите блокирующий процесс: `sudo lsof /dev/md0` или `sudo fuser -v /dev/md0`.
2. Проверьте наличие остаточных DM-слоев: `ls /dev/mapper`. Удалите их через `dmsetup remove`.
3. Проверьте屍open сокеты: `sudo ss -tlnp | grep :2049` (NFS) или другие сервисы.

#### Шаг 4: Уничтожение метаданных на физических дисках

После остановки `/dev/md0` необходимо очистить каждый физический диск или раздел, входивший в него (например, `/dev/sdb1` и `/dev/sdc1`).

```bash
# Метод 1: Только суперблок RAID
sudo mdadm --zero-superblock /dev/sdb1 /dev/sdc1

# Метод 2: Полная очистка (Рекомендуется)
sudo wipefs --all /dev/sdb1
sudo wipefs --all /dev/sdc1

# Метод 3: Проверка результата
sudo blkid /dev/sdb1
# → (пустой вывод означает успешную очистку)
```

> **Важно:** Для метаданных версии 1.2 (стандарт) суперблок находится в начале диска, для 0.90 — в конце. `wipefs` корректно обрабатывает все версии.

**Безопасное стирание данных (Secure Erase):**
Если диск передаётся третьим лицам или утилизируется:
```bash
# Быстрое стирание (только заголовки)
sudo wipefs --all --force /dev/sdb

# Полное стирание (весь диск, долго)
sudo dd if=/dev/zero of=/dev/sdb bs=1M status=progress
# Или для SSD (используйте vendor-утилиту или hdparm)
sudo hdparm --user-master u --security-set-pass p /dev/sdb
sudo hdparm --user-master u --security-erase p /dev/sdb
```

#### Шаг 5: Очистка конфигурации ОС

1.  **mdadm.conf:** Удалите строку `ARRAY` для данного UUID из файла `/etc/mdadm/mdadm.conf`.
    ```bash
    # Найти строку
    grep -n "md0" /etc/mdadm/mdadm.conf
    
    # Удалить (замените номер строки)
    sudo sed -i '/ARRAY \/dev\/md0/d' /etc/mdadm/mdadm.conf
    ```
2.  **Initramfs:** Если массив использовался для корня или был прописан в конфигах загрузки, обновите образ:
    ```bash
    sudo update-initramfs -u
    ```
3.  **GRUB (если RAID использовался для /boot):**
    ```bash
    # Обновление конфига GRUB
    sudo update-grub
    
    # Проверка
    grep -i "md" /boot/grub/grub.cfg
    ```

#### Шаг 6: Верификация очистки

```bash
# Проверка что RAID не собирается
cat /proc/mdstat
# → Пустой вывод или только другие массивы

# Проверка что диски чисты
sudo blkid | grep -E "sd[b-c]"
# → Пустой вывод

# Проверка что нет ссылок в конфигах
grep -r "md0" /etc/mdadm/ /etc/fstab/ /etc/default/grub 2>/dev/null
# → Пустой вывод
```

### Удаление накопителя из активного массива

Применяется при замене диска или уменьшении количества устройств (Grow/Shrink).

1.  **Пометка «Failed»:**
    ```bash
    sudo mdadm /dev/md0 --fail /dev/sdb1
    # → mdadm: set /dev/sdb1 faulty in /dev/md0
    ```

2.  **Физическое извлечение (Remove):**
    ```bash
    sudo mdadm /dev/md0 --remove /dev/sdb1
    # → mdadm: hot removed /dev/sdb1 from /dev/md0
    ```

3.  **Проверка состояния после удаления:**
    ```bash
    cat /proc/mdstat
    # → md0 : active raid1 sdc1[1]
    #       1953513472 blocks super 1.2 [1/1] [_U]
    ```

4.  **Очистка извлеченного диска:**
    Если диск будет использоваться в другом месте, обязательно выполните `sudo mdadm --zero-superblock /dev/sdb1`.

### Конвертация уровня RAID (Level Migration)

Иногда необходимо не удалять массив полностью, а изменить его уровень (например, RAID 5 → RAID 6 для повышения надежности). Это операция «на лету» без потери данных.

**Поддерживаемые миграции:**
| Из | В | Условия |
| :--- | :--- | :--- |
| RAID 1 | RAID 5 | Добавление 1+ дисков |
| RAID 5 | RAID 6 | Добавление 1 диска |
| RAID 5 | RAID 0 | Потеря отказоустойчивости (опасно!) |
| RAID 1 | RAID 0 | Потеря отказоустойчивости (опасно!) |

**Пример: RAID 5 → RAID 6:**
```bash
# 1. Добавить новый диск
sudo mdadm /dev/md0 --add /dev/sdf1

# 2. Изменить уровень
sudo mdadm --grow /dev/md0 --level=6 --raid-devices=4

# 3. Мониторинг процесса
watch cat /proc/mdstat
# → md0 : active raid6 sdf1[3] sde1[2] sdd1[1] sdc1[0]
#       resync=DONE algorithm=2 [4/4] [UUUU]
```

**Важно:** Конвертация — длительный процесс (часы-сутки). Массив работает в degraded state до завершения.

---

### Удаление RAID при восстановлении системы

Если массив поврежден и восстановление невозможно, может потребоваться удаление для создания нового массива.

**Экстренное удаление (когда массив не останавливается):**
```bash
# Принудительная остановка
sudo mdadm --stop --force /dev/md0

# Если не помогает — загрузитесь с Live USB и выполните:
sudo mdadm --zero-superblock /dev/sdb1 /dev/sdc1
sudo wipefs --all /dev/sdb1 /dev/sdb1
```

**Восстановление после ошибочного удаления:**
Если массив был удален по ошибке:
1. Не записывайте новые данные на диски!
2. Попробуйте восстановить суперблок:
   ```bash
   # Если есть бэкап суперблока
   sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 \
       --assume-clean /dev/sdb1 /dev/sdc1
   ```
3. Используйте утилиты восстановления: `testdisk`, `photorec`, или профессиональные сервисы.

## Диагностика и решение проблем

### Массив собирается сам после перезагрузки

*   **Причина:** Не очищены метаданные на одном из дисков или информация осталась в `initramfs`.
*   **Решение:** Повторно выполните Шаг 4 (очистка дисков) и Шаг 5 (обновление initramfs).

**Диагностика:**
```bash
# Проверка что диски все еще содержат RAID метаданные
sudo mdadm --examine /dev/sdb1
# → Если看到 superblock = 1.2 — очистка не завершена

# Проверка initramfs
lsinitramfs /boot/initrd.img-$(uname -r) | grep mdadm
```

### Ошибка «Device or resource busy» при остановке

*   **Причина:** Открытые файловые дескрипторы или активные слои Device Mapper.
*   **Действие:** Проверьте `mount`, `swapon -s`, `pvs`, `cryptsetup status`. Все, что использует `/dev/mdX`, должно быть закрыто.

**Диагностика:**
```bash
# Найти открытые файлы
sudo lsof /dev/md0
sudo fuser -v /dev/md0

# Проверить все mount points
mount | grep md

# Проверить DM-устройства
ls /dev/mapper/
sudo dmsetup ls

# Проверить LVM
sudo pvs | grep md
sudo lvs
```

### Массив не останавливается (kdamped state)

*   **Причина:** Ядро заблокировало массив из-за ошибок ввода-вывода или повреждения метаданных.
*   **Решение:**
    ```bash
    # Принудительная остановка
    sudo mdadm --stop --force /dev/md0
    
    # Если не помогает — перезагрузка
    sudo reboot
    
    # После перезагрузки — очистка дисков
    sudo mdadm --zero-superblock /dev/sdb1 /dev/sdc1
    ```

### Невозможно очистить суперблок («Device or resource busy»)

*   **Причина:** Устройство используется системой (swap, LVM,mnt).
*   **Решение:**
    ```bash
    # Проверить все использования
    blkid /dev/sdb1
    sudo lsof /dev/sdb1
    sudo fuser -v /dev/sdb1
    
    # Если swap
    sudo swapoff /dev/sdb1
    
    # Если LVM
    sudo vgchange -an vg_name
    sudo pvremove /dev/sdb1
    ```

### Ошибка при update-initramfs

*   **Причина:** Конфликт версий или отсутствие необходимых пакетов.
*   **Решение:**
    ```bash
    # Переустановка mdadm
    sudo apt reinstall mdadm  # Debian/Ubuntu
    sudo dnf reinstall mdadm  # RHEL/CentOS
    
    # Принудительное обновление
    sudo update-initramfs -u -k all
    ```

### RAID массив не удаляется из fstab

*   **Причина:** Неверный формат записи или опечатка.
*   **Решение:**
    ```bash
    # Найти точную строку
    grep -n "md" /etc/fstab
    
    # Удалить по номеру строки (замените 5 на реальный номер)
    sudo sed -i '5d' /etc/fstab
    
    # Или закомментировать
    sudo sed -i 's|^UUID=.*md.*|# &|' /etc/fstab
    ```

## Безопасность и лучшие практики

### Безопасное стирание данных

При утилизации дисков или передаче их третьим лицам необходимо гарантировать невозможность восстановления данных.

**Методы стирания:**

| Метод | Скорость | Надежность | Применение |
| :--- | :--- | :--- | :--- |
| `wipefs --all` | Быстро | Средняя | Удаление метаданных (не данных) |
| `dd if=/dev/zero` | Средняя | Высокая | Полное перезаписывание |
| `shred` | Медленно | Очень высокая | Многократная перезапись |
| Vendor-утилиты | Зависит от NVMe/SATA | Очень высокая | SSD/HDD |

**Пример безопасного стирания:**
```bash
# Быстрое стирание (для повторного использования)
sudo wipefs --all --force /dev/sdb

# Полное стирание (для утилизации)
sudo dd if=/dev/zero of=/dev/sdb bs=1M status=progress

# Многократное стирание (для высокой безопасности)
sudo shred -vfz -n 3 /dev/sdb
```

### Чек-лист перед утилизацией дисков

```bash
# 1. Убедитесь что RAID остановлен
cat /proc/mdstat | grep md

# 2. Очистите метаданные
sudo mdadm --zero-superblock /dev/sd[b-e]
sudo wipefs --all /dev/sd[b-e]

# 3. Проверьте очистку
sudo blkid /dev/sd[b-e]
# → Должен вернуть пустой вывод

# 4. Для SSD: выполните Secure Erase
sudo hdparm -I /dev/sdb | grep "Security"
# → Если supported, выполните security erase
```
