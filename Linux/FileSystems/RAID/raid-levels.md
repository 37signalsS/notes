# Уровни RAID: технические характеристики и рекомендации 2026

## Определения

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология виртуализации данных, объединяющая несколько физических накопителей в один логический блок для повышения производительности, отказоустойчивости или обоих показателей одновременно.

**Ключевые технические параметры:**
*   **Stripe (Полоса):** Совокупность блоков данных, распределенных по всем дискам массива.
*   **Chunk Size (Размер блока):** Объем данных, записываемый на один диск перед переходом на следующий (обычно от 64 КБ до 1 МБ).
*   **Parity (Чётность):** Результат логической операции (XOR), позволяющий восстановить данные при потере одного из слагаемых.
*   **URE (Unrecoverable Read Error):** Вероятность возникновения нечитаемого сектора. Для современных дисков (2026 год, 30ТБ+) этот показатель критичен при выборе уровня избыточности.

---

## Основные уровни RAID

### RAID 0 — Чередование (Striping)

**Принцип:** Данные делятся на блоки и записываются поочерёдно на все диски массива. Нет избыточности.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | 0 дисков (отказ любого диска уничтожает массив) |
| Чтение | Высокая (линейно растёт с кол-вом дисков) |
| Запись | Высокая (линейно растёт с кол-вом дисков) |
| Полезная ёмкость | 100% |

**Применение:** Временные файлы, кэши, своп-разделы, рабочие пространства для обработки видео или обучения ИИ, где скорость критична, а данные легко восстановимы из бэкапа.

---

### RAID 1 — Зеркалирование (Mirroring)

**Принцип:** Полное дублирование данных на два или более диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | N-1 дисков |
| Чтение | Высокая (возможно параллельное чтение разных блоков) |
| Запись | Средняя (ограничена скоростью самого медленного диска) |
| Полезная ёмкость | 1/N (обычно 50% при двух дисках) |

**Применение:** Системные разделы (OS Boot), базы данных с высокой нагрузкой на чтение при малом объёме данных.

**Особенности реализации в Linux (mdadm):**
```bash
# Создание RAID 1 с bitmap для ускорения rebuild
sudo mdadm --create /dev/md0 --level=1 --bitmap=internal \
    --raid-devices=2 /dev/sdb1 /dev/sdc1

# Проверка состояния зеркал
cat /proc/mdstat
# → md0 : active raid1 sdc1[1] sdb1[0]
#       1953513472 blocks super 1.2 [2/2] [UU]
```

> **Важно:** В RAID 1 배열 `UU` означает, что оба диска работоспособны. Метка `_U` или `U_` указывает на деградацию.

---

### RAID 4 — Чередование с выделенной чётностью

**Принцип:** Аналог RAID 5, но чётность хранится на фиксированном диске (parity disk). Выдерживает отказ одного диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 3 |
| Отказоустойчивость | 1 диск |
| Чтение | Высокая (параллельное со всех дисков кроме parity) |
| Запись | Средняя (бутылочное горлышко на parity-диске) |
| Полезная ёмкость | (N-1)/N |

> **Почему RAID 4 устарел:** Фиксированный parity-диск становится узким местом при записи — все операции записи затрагивают его, что ограничивает общую пропускную способность. RAID 5 с распределённой чётностью лишен этого недостатка.

**Применение:** Историческая справка; в современных системах практически не используется (заменён RAID 5/6).

---

### RAID 5 — Чередование с распределённой чётностью

**Принцип:** Данные и контрольные суммы (XOR) распределяются по всем дискам. Выдерживает отказ одного диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 3 |
| Отказоустойчивость | 1 диск |
| Чтение | Высокая |
| Запись | Низкая (Write Penalty = 4) |
| Полезная ёмкость | (N-1)/N |

> **Критическое предупреждение 2026:** Категорически не рекомендуется для дисков >10 ТБ. При использовании современных дисков 30 ТБ вероятность ошибки URE ($10^{-14}$) при ребилде массива стремится к 100%. RAID 5 сегодня — это "отложенная потеря данных".

---

### RAID 6 — Чередование с двойной чётностью

**Принцип:** Использует две независимые схемы чётности. Выдерживает одновременный отказ двух любых дисков.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 |
| Отказоустойчивость | 2 диска |
| Чтение | Высокая |
| Запись | Очень низкая (Write Penalty = 6) |
| Полезная ёмкость | (N-2)/N |

**Применение:** Стандарт для средних файловых хранилищ и архивов на дисках высокой плотности до 12–16 штук в группе.

> **Подробнее:** [Управление RAID 6](./raid6-management.md) — создание, замена дисков, восстановление, LVM поверх RAID 6.

---

### RAID 10 (1+0) — Зеркало страйпов

**Принцип:** Комбинация RAID 1 и RAID 0. Диски объединяются в зеркальные пары, которые затем чередуются.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 (кратное 2) |
| Отказоустойчивость | Минимум 1 диск (до 1 в каждой зеркальной паре) |
| Чтение/Запись | Максимальная производительность для случайного I/O |
| Полезная ёмкость | 50% |

**Применение:** Высоконагруженные базы данных (OLTP), системы виртуализации.

> **Подробнее:** [Управление RAID 10](./raid10-management.md) — создание, замена дисков, миграция RAID 1 -> RAID 10.

---

## Современные и специализированные уровни (Актуальность 2026)

### RAID-TP (Triple Parity)
**Принцип:** Три независимых слоя чётности (горизонтальная, диагональная, анти-диагональная).
*   **Отказоустойчивость:** Выдерживает отказ **3-х дисков**.
*   **Контекст:** Стал стандартом для массивов на базе HDD 20ТБ+, где время ребилда может превышать 48 часов.

### RAID-Z (ZFS)
Интегрированная реализация RAID в файловой системе ZFS.
*   **RAID-Z1 / Z2 / Z3:** Аналоги RAID 5, 6 и TP соответственно.
*   **Self-healing:** Использование контрольных сумм для каждого блока позволяет ФС автоматически обнаруживать и исправлять «тихую порчу данных» (Bit rot) при чтении.
*   **Отсутствие Write Hole:** Благодаря архитектуре Copy-on-Write данные никогда не перезаписываются на месте.

---

## Вложенные уровни RAID (Nested)

Используются для объединения преимуществ разных уровней в больших массивах.

### RAID 50 (5+0)
Объединяет несколько групп RAID 5 в общий RAID 0.
*   **Преимущества:** Быстрее ребилд (восстанавливается только одна подгруппа), выше производительность записи, чем у чистого RAID 5.
*   **Отказоустойчивость:** Выдерживает отказ одного диска в *каждой* подгруппе.

### RAID 60 (6+0)
Объединяет несколько групп RAID 6 в общий RAID 0.
*   **Применение:** Сверхбольшие массивы (24+ дисков), где требуется высокая плотность хранения при сохранении шансов на выживание при множественных отказах.

## Горячая замена (Hot Spare)

**Hot Spare** — резервный диск, не участвующий в正常工作 массива, но готовый к автоматической замене вышедшего из строя диска.

### Типы Hot Spare

| Тип | Описание | Использование |
| :--- | :--- | :--- |
| **Global Hot Spare** | Доступен для *любого* массива в системе | Рекомендуется для серверов с несколькими RAID-массивами |
| **Dedicated Hot Spare** | Закреплён за конкретным массивом | Когда нужна гарантированная замена для критичного массива |

### Настройка Hot Spare в mdadm

```bash
# Добавление глобального Hot Spare
sudo mdadm /dev/md0 --add /dev/sde1

# Создание массива с Hot Spare
sudo mdadm --create /dev/md0 --level=5 --raid-devices=3 \
    --spare-devices=1 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1

# Проверка наличия spare
cat /proc/mdstat
# → md0 : active raid5 sde1[3](S) sdd1[2] sdc1[1] sdb1[0]
#       2930270208 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/3] [UUU]
```

**Статусы дисков в /proc/mdstat:**
*   `[UU]` — все диски работоспособны
*   `[_U]` или `[U_]` — один диск недоступен (degraded)
*   `(S)` — spare (горячий резерв)
*   `(F)` — failed (сбойный)

### Поведение при отказе диска

1. **Автоматическое переключение:** При выходе из строя активного диска spare автоматически начинает rebuild.
2. **Время восстановления:** Зависит от размера массива и нагрузки (от нескольких минут до суток).
3. **Рекомендация:** Используйте Hot Spare для критичных массивов — это сокращает время degraded state.

## Технические нюансы и проблемы

### Проблема «Write Hole»
При внезапном отключении питания в RAID 5/6 может возникнуть рассинхронизация: данные записаны, а чётность нет.
*   **Решение mdadm:** Использование PPL (Partial Parity Log) или выделенного NVMe-диска под журнал записи.
*   **Решение ZFS:** Использование ZIL (ZFS Intent Log) и CoW-структуры.

### Chunk Size и выравнивание (Alignment)
*   **Малый Chunk (4K-64K):** Оптимален для случайного I/O малого размера (базы данных). Увеличивает вероятность того, что один запрос будет обработан одним диском.
*   **Большой Chunk (256K-1M):** Оптимален для последовательных операций (видео, бэкапы). Позволяет эффективно использовать пропускную способность нескольких дисков для одного файла.
*   **Stripe Width:** Общий размер данных в одной "строке" массива. Файловая система должна быть выровнена по Stripe Width для исключения операций Read-Modify-Write.

### RAID на SSD и NVMe
Специфика 2026 года (накопители QLC/PLC 100ТБ+):
1.  **TRIM/Discard:** Обязательная поддержка на уровне RAID-контроллера (программного или аппаратного) для предотвращения деградации производительности.
2.  **Wear Leveling (Износ):** В RAID 1/10 диски изнашиваются одинаково. Рекомендуется использовать накопители разных брендов или партий.
3.  **IOPS Penalty:** Высокая производительность SSD делает Write Penalty менее заметным для латентности, но критичным для общего ресурса записи (TBW).

## Производительность и расчеты

### Write Penalty (Штраф на запись)
Количество физических операций ввода-вывода на одну логическую запись ОС.

| Уровень RAID | Write Penalty |
| :--- | :--- |
| RAID 0 | 1 |
| RAID 1 / 10 | 2 |
| RAID 5 / Z1 | 4 |
| RAID 6 / Z2 | 6 |
| RAID-TP / Z3 | 8 |

### Формула эффективного IOPS
Для оценки производительности массива под нагрузкой:

$$Effective IOPS = \frac{Raw IOPS \times N}{Read\% + (Write\% \times Penalty)}$$

*Пример:* 10 HDD (100 IOPS каждый) в RAID 6 при нагрузке 70% чтение / 30% запись:
$1000 / (0.7 + (0.3 \times 6)) = 1000 / 2.5 = 400$ IOPS.

### Пропускная способность (Throughput)

| Уровень RAID | Чтение (N дисков) | Запись (N дисков) | Ограничение |
| :--- | :--- | :--- | :--- |
| RAID 0 | N × S | N × S | Нет |
| RAID 1 | N × S (при параллельном чтении) | S | Запись = скорость самого медленного |
| RAID 5 | (N-1) × S | (N-1) × S / Penalty | Write Penalty |
| RAID 6 | (N-2) × S | (N-2) × S / Penalty | Write Penalty × 1.5 |
| RAID 10 | N × S | (N/2) × S | Запись = 50% от RAID 0 |

*Где S — пропускная способность одного диска.*

### Надежность и URE

**URE (Unrecoverable Read Error)** — вероятность ошибки чтения, которая не может быть исправлена средствами ECC диска.

**Формула вероятности потери данных при ребилде:**

$$P_{data\_loss} = 1 - (1 - P_{URE})^{N-1}$$

*Где N — количество дисков в массиве.*

**Примеры расчета (URE = 10^{-14} для enterprise HDD):**

| Дисков в RAID 5 | Вероятность потери данных при ребилде |
| :--- | :--- |
| 3 | ~0.0003% |
| 6 | ~0.0006% |
| 12 | ~0.0012% |
| 24 | ~0.0024% |

**Вывод:** При использовании дисков >10 ТБ RAID 5 становится ненадежным. Рекомендуется RAID 6/TP для массивов 12+ дисков.

### Время ребилда (Rebuild Time)

Время восстановления массива после отказа диска:

| Фактор | Влияние |
| :--- | :--- |
| Объём массива | Пропорционально (чем больше, тем дольше) |
| Нагрузка на массив | Ребилд замедляется при параллельной работе |
| Пропускная способность диска | От 100 МБ/с (HDD) до 3500 МБ/с (NVMe) |
| Bitmap | Ускоряет на 50-90% (синхронизация только изменённых блоков) |

**Оценка времени ребилда (упрощённая):**

$$T_{rebuild} = \frac{Объём\_массива}{Скорость\_диска \times (1 + 0.3 \times Нагрузка)}$$

*Пример:* Массив RAID 5 на 3 HDD по 10 ТБ (100 МБ/с), без нагрузки:
$30 ТБ / (100 МБ/с) ≈ 83 часа (3.5 суток)$

## Практические примеры и рекомендации

### Сценарий 1: Сервер базы данных (OLTP)

**Требования:** Высокие IOPS на запись, минимальные задержки, высокая доступность.

**Решение:** RAID 10 на SSD.

```bash
# Создание RAID 10 из 6 SSD (3 зеркальных пары)
sudo mdadm --create /dev/md0 --level=10 --raid-devices=6 \
    /dev/nvme0n1 /dev/nvme1n1 /dev/nvme2n1 \
    /dev/nvme3n1 /dev/nvme4n1 /dev/nvme5n1

# Проверка
cat /proc/mdstat
# → md0 : active raid10 nvme5n1[5] nvme4n1[4] nvme3n1[3] nvme2n1[2] nvme1n1[1] nvme0n1[0]
#       2930270208 blocks super 1.2 near-copies [6/6] [UUUUUU]
```

**Результат:** ~100K IOPS на чтение, ~50K IOPS на запись (с учётом Write Penalty).

### Сценарий 2: Файловый сервер для архива

**Требования:** Максимальная ёмкость, защита от потери данных, умеренная стоимость.

**Решение:** RAID 6 на HDD.

```bash
# Создание RAID 6 из 8 HDD по 16 ТБ
sudo mdadm --create /dev/md0 --level=6 --raid-devices=8 \
    --chunk=512 /dev/sd{a,b,c,d,e,f,g,h}1

# Настройка Hot Spare
sudo mdadm /dev/md0 --add /dev/sdi1

# Проверка
cat /proc/mdstat
# → md0 : active raid6 sdi1[8](S) sdh1[7] sdg1[6] ... sda1[0]
#       1125899906842624 blocks super 1.2 level 6, 512k chunk, algorithm 2 [8/8] [UUUUUUUU]
```

**Результат:** ~112 ТБ полезного пространства, защита от 2 отказов, Hot Spare для быстрого восстановления.

### Сценарий 3: Временные данные (render farm / AI cache)

**Требования:** Максимальная скорость чтения/записи, данные восстановимы из бэкапа.

**Решение:** RAID 0.

```bash
# Создание RAID 0 из 4 NVMe
sudo mdadm --create /dev/md0 --level=0 --raid-devices=4 \
    --chunk=256 /dev/nvme{0,1,2,3}n1

# Результат: ~28 ТБ, скорость ~14000 МБ/с (reading)
```

### Сценарий 4: Критичный системный раздел

**Требования:** Отказоустойчивость, возможность загрузки, простота восстановления.

**Решение:** RAID 1.

```bash
# Создание RAID 1 для /boot
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 \
    --metadata=1.0 /dev/sdb1 /dev/sdc1

# Форматирование и монтирование
sudo mkfs.ext4 /dev/md0
sudo mount /dev/md0 /boot

# Обновление mdadm.conf
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
```

**Результат:** Два идентичных раздела, загрузка с любого диска, автоматическое восстановление.
