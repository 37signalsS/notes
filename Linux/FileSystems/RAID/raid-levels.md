# Уровни RAID и рекомендации

## Определения

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология виртуализации данных, которая объединяет несколько физических дисков в один логический элемент для повышения производительности и отказоустойчивости.

**Уровень RAID** — конкретный метод распределения данных по дискам массива, определяющий баланс между производительностью, надежностью и полезной ёмкостью.

## Основные концепции

### RAID 0 — Чередование (Striping)

**Принцип:** Данные разделяются на блоки (страйпы), записываемые поочерёдно на все диски.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | Нет |
| Чтение | Высокая |
| Запись | Высокая |
| Полезная ёмкость | 100% |

**Преимущества:**

* Максимальная производительность чтения и записи.
* Полное использование ёмкости всех накопителей.
* Простота настройки.

**Недостатки:**

* Отсутствие отказоустойчивости: выход из строя одного диска приводит к потере всех данных в массиве.
* Суммарная надежность ниже, чем у одиночного диска.

**Применение:**

* Временные файлы, файлы подкачки, кэш.
* Обработка видео (если исходные материалы сохранены отдельно).

---

### RAID 1 — Зеркалирование (Mirroring)

**Принцип:** Данные записываются одновременно на два или более диска в идентичном виде.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | 1 диск |
| Чтение | Высокая (параллельное чтение) |
| Запись | Средняя (запись на все диски) |
| Полезная ёмкость | 50% |

**Преимущества:**

* Высокая надежность и простота восстановления.
* Высокая скорость чтения при обращении к разным блокам данных.

**Недостатки:**

* Высокая стоимость хранения (50% ёмкости тратится на избыточность).

**Применение:**

* Загрузочные разделы операционной системы.
* Критически важные данные небольшого объема.

---

### RAID 5 — Чередование с распределённой чётностью

**Предупреждение:** Не рекомендуется для современных систем с дисками объемом более 1 ТБ.
**Причина:** Высокий риск возникновения **URE (Unrecoverable Read Error / Некорректируемая ошибка чтения)** во время восстановления (rebuild). Для современных накопителей большой емкости вероятность отказа второго диска или ошибки чтения при пересчете данных критически высока.

**Принцип:** Блоки данных и контрольные суммы распределяются по всем дискам массива.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 3 |
| Отказоустойчивость | 1 диск |
| Чтение | Высокая |
| Запись | Средняя (штраф на запись — 4 операции) |
| Полезная ёмкость | (N-1)/N |

**Преимущества:**

* Эффективное использование дискового пространства.

**Недостатки:**

* Низкая скорость записи из-за необходимости пересчета четности.
* Длительное время восстановления, в течение которого массив не защищен.

---

### RAID 6 — Чередование с двойной чётностью

**Принцип:** Аналогичен RAID 5, но вычисляются и записываются две независимые контрольные суммы на разные диски.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 |
| Отказоустойчивость | 2 диска |
| Чтение | Высокая |
| Запись | Низкая (штраф на запись — 6 операций) |
| Полезная ёмкость | (N-2)/N |

**Преимущества:**

* Высокая отказоустойчивость: массив сохраняет работоспособность при одновременном выходе из строя двух дисков.

**Недостатки:**

* Высокий штраф на запись.
* Требуется более мощный контроллер для вычисления четности.

**Применение:**

* Объемные хранилища данных, архивы.

---

### RAID 10 (1+0) — Зеркалирование + чередование

**Принцип:** Комбинация RAID 1 и RAID 0. Диски объединяются в зеркальные пары, которые затем собираются в массив с чередованием.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 (кратное 2) |
| Отказоустойчивость | Минимум 1 диск (до 1 в каждой паре) |
| Чтение | Максимальная |
| Запись | Максимальная (нет штрафа за расчет четности) |
| Полезная ёмкость | 50% |

**Преимущества:**

* Оптимальное сочетание производительности и надежности.
* Быстрое восстановление без нагрузки на вычислительные ресурсы.

**Недостатки:**

* Низкая эффективность использования пространства.

**Применение:**

* Промышленный стандарт для систем управления базами данных.
* Инфраструктура виртуальных рабочих столов (**VDI (Virtual Desktop Infrastructure)**).

## Практические сценарии

### Выбор конфигурации для баз данных

**OLTP (Online Transaction Processing / Обработка транзакций в реальном времени):**

* Требует высокой скорости записи и минимальных задержек.
* **Рекомендуется:** RAID 10.
* **Не рекомендуется:** RAID 5/6 (из-за штрафа на запись).

**OLAP (Online Analytical Processing / Аналитическая обработка в реальном времени):**

* Требует высокой скорости последовательного чтения.
* **Рекомендуется:** RAID 10 или RAID 6 (для больших архивов).

**Журналы транзакций (WAL (Write-Ahead Logging / Журналирование с опережающей записью)):**

* **Рекомендуется:** RAID 10 или RAID 1 (для небольших систем).

### Рекомендации по применению

| Задача | Уровень RAID | Примечание |
| :--- | :--- | :--- |
| ОС и системные разделы | RAID 1 | Простота и надежность загрузки |
| Высоконагруженные СУБД | RAID 10 | Максимальная производительность I/O |
| Файловые архивы | RAID 6 | Баланс объема и защиты от двух сбоев |
| Среды виртуализации | RAID 10 | Работа с множеством **VM (Virtual Machine / Виртуальная машина)** |
| Временные данные (кэш) | RAID 0 | Когда скорость важнее сохранности |
