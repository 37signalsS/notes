# Уровни RAID и рекомендации

## Определения

**Уровень RAID** — конкретный метод распределения данных по дискам массива, определяющий баланс между производительностью, отказоустойчивостью и полезной ёмкостью.

## Основные концепции

### RAID 0 — Чередование (Striping)

**Принцип:** Данные разделяются на блоки (страйпы), записываемые поочерёдно на все диски.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | ❌ Нет |
| Чтение | ★★★★★ |
| Запись | ★★★★★ |
| Полезная ёмкость | 100% |

**Преимущества:**

* Максимальная производительность чтения/записи
* Полное использование ёмкости всех дисков
* Простота реализации

**Недостатки:**

* **Нет отказоустойчивости** — сбой одного диска = потеря **всех** данных
* Риск потери выше, чем на одиночном диске (вероятность отказа растёт с числом дисков)

**Применение:**

* Временные файлы, кэш
* Видеомонтаж (исходники не критичны)
* Игровые системы (не серверы)

> **Запрещено для:** Баз данных, критичных данных, систем с высокими требованиями к доступности.

---

### RAID 1 — Зеркалирование (Mirroring)

**Принцип:** Данные записываются одновременно на два (или более) диска в идентичной форме.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | ✅ 1 диск |
| Чтение | ★★★★☆ (распараллеливается) |
| Запись | ★★★☆☆ (пишется на оба диска) |
| Полезная ёмкость | 50% |

**Преимущества:**

* Высокая отказоустойчивость
* Отличная скорость чтения
* Быстрое восстановление (просто копирование)
* Простота управления

**Недостатки:**

* 50% потерь ёмкости
* При программной реализации — нет горячей замены без перезагрузки (зависит от системы)

**Применение:**

* Загрузочные диски (`/boot`, `/`)
* Критичные системы (учётные системы, небольшие СУБД)
* Серверы с 2 дисками

---

### RAID 5 — Чередование с распределённой чётностью

> ⚠️ **УСТАРЕЛ (с 2009 г.)** — не рекомендуется для новых систем с дисками >1ТБ.
>
> **Причина:** Риск **URE (Unrecoverable Read Error)** при rebuild достигает 40% для дисков 2ТБ+. Время rebuild для 8ТБ диска = 12-24 часа, в течение которых массив уязвим к сбою второго диска.

**Принцип:** Блоки данных и контрольные суммы чётности распределяются по всем дискам. Требуется минимум 3 диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 3 |
| Отказоустойчивость | ✅ 1 диск |
| Чтение | ★★★★☆ |
| Запись | ★★★☆☆ (штраф 4 операции) |
| Полезная ёмкость | (N-1)/N ≈ 67-94% |

**Преимущества:**

* Хорошая производительность чтения
* Высокая полезная ёмкость
* Отказоустойчивость к 1 диску

**Недостатки:**

* **Штраф на запись (Write Penalty):** 4 операции на запись (чтение данных + чтение чётности + запись данных + запись чётности)
* Длительный rebuild (окно уязвимости)
* Риск потери при сбое второго диска во время rebuild

**Применение:**

* ⚠️ Только для дисков <1ТБ
* Файловые серверы с небольшой нагрузкой на запись
* **Не рекомендуется для новых систем**

---

### RAID 6 — Чередование с двойной чётностью

> ✅ **Рекомендуется** для массивов из 4+ дисков вместо RAID 5.

**Принцип:** Аналогичен RAID 5, но записываются **две** контрольные суммы. Требуется минимум 4 диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 |
| Отказоустойчивость | ✅ 2 диска |
| Чтение | ★★★★☆ |
| Запись | ★★☆☆☆ (штраф 6 операций) |
| Полезная ёмкость | (N-2)/N |

**Преимущества:**

* Высокая отказоустойчивость (2 диска)
* Хорошая производительность чтения
* Безопасен при rebuild после сбоя одного диска

**Недостатки:**

* Ещё больший штраф на запись (6 операций)
* Длительный rebuild
* Потеря ёмкости 2 дисков

**Применение:**

* Файловые серверы с большим числом дисков (6+)
* Архивное хранение
* Системы с высокими требованиями к доступности

---

### RAID 10 (1+0) — Зеркалирование + чередование

**Принцип:** Данные чередуются (RAID 0), затем каждый набор зеркалируется (RAID 1). Требуется минимум 4 диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 (чётное число) |
| Отказоустойчивость | ✅ 1 диск на зеркальную пару |
| Чтение | ★★★★★ |
| Запись | ★★★★★ (нет штрафа на чётность) |
| Полезная ёмкость | 50% |

**Преимущества:**

* Максимальная производительность чтения **и** записи
* Высокая отказоустойчивость
* **Быстрое восстановление** (копирование с зеркала, не пересчёт)
* Нет штрафа на запись

**Недостатки:**

* 50% потерь ёмкости
* Требуется чётное число дисков (минимум 4)

**Применение:**

* ✅ **Промышленный стандарт для СУБД** (PostgreSQL, MySQL, Oracle)
* Транзакционные системы с высокой нагрузкой на запись
* Виртуализация (VDI, гипервизоры)

## Практические сценарии

### Выбор RAID для баз данных

**OLTP-системы (высокая нагрузка на запись):**

| Уровень | Подходит? | Обоснование |
| :--- | :--- | :--- |
| **RAID 10** | ✅ **Рекомендуется** | Нет штрафа на запись, быстрое восстановление |
| RAID 6 | ⚠️ С осторожностью | Штраф 6 операций на запись, медленно для write-intensive |
| RAID 5 | ❌ **Запрещено** | Штраф 4 операции + риск при rebuild |
| RAID 0 | ❌ **Запрещено** | Нет отказоустойчивости |

**OLAP-системы (чтение, аналитика):**

| Уровень | Подходит? | Обоснование |
| :--- | :--- | :--- |
| RAID 10 | ✅ Отлично | Максимальная производительность |
| RAID 6 | ✅ Хорошо | Высокая ёмкость, чтение не страдает |
| RAID 5 | ⚠️ Только для тестовых | Риск URE при rebuild |

**Журналы транзакций (WAL, binlog, redo log):**

> **Требование:** Максимальная скорость записи, минимальная задержка.

| Уровень | Подходит? |
| :--- | :--- |
| **RAID 10** | ✅ **Единственный правильный выбор** |
| RAID 1 | ✅ Допустимо для небольших систем |
| RAID 5/6 | ❌ **Запрещено** (штраф на запись критичен) |

---

### Рекомендации по выбору для различных сценариев

| Сценарий | Рекомендуемый уровень | Альтернатива |
| :--- | :--- | :--- |
| Загрузочный диск (`/boot`, `/`) | RAID 1 | — |
| Домашний сервер (2 диска) | RAID 1 | — |
| Файловый сервер (4-6 дисков) | RAID 6 | RAID 10 (если важна запись) |
| СУБД (OLTP, write-intensive) | **RAID 10** | — |
| СУБД (OLAP, read-intensive) | RAID 10 | RAID 6 |
| Веб-сервер (статика) | RAID 1 | RAID 5 (только для <1ТБ дисков) |
| Бэкапы (write-once, read-rarely) | RAID 6 | RAID 5 (только для <1ТБ) |
| Видеомонтаж (исходники) | RAID 0 | — |
| Гипервизор (VM storage) | RAID 10 | — |

---

### Альтернативы классическому RAID

| Технология | Описание | Когда предпочесть |
| :--- | :--- | :--- |
| **ZFS RAID-Z2** | Аналог RAID 6 с защитой от silent corruption | Файловые серверы, где важна целостность данных |
| **ZFS RAID-Z1** | Аналог RAID 5 с защитой от URE | Замена RAID 5 на ZFS |
| **LVM RAID** | RAID через LVM + mdadm | Нужна гибкость LVM (snapshots, resize) |
| **Ceph** | Распределённое СХД | Кластеры от 3 узлов, нужна масштабируемость |
