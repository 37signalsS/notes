# Уровни RAID и технические рекомендации

## Определения

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология виртуализации данных, объединяющая несколько физических накопителей в один логический блок для повышения производительности, отказоустойчивости или обоих показателей одновременно.

**Уровень RAID** — метод распределения данных (striping) и избыточности (mirroring/parity) между дисками, определяющий баланс между скоростью, надёжностью и стоимостью хранения.

## Основные уровни RAID

### RAID 0 — Чередование (Striping)

**Принцип:** Данные делятся на блоки и записываются поочерёдно на все диски массива.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | 0 дисков |
| Чтение | Высокая (линейно растёт с кол-вом дисков) |
| Запись | Высокая (линейно растёт с кол-вом дисков) |
| Полезная ёмкость | 100% |

**Применение:** Временные файлы, кэши, своп-разделы — там, где скорость критична, а потеря данных не является катастрофой.

---

### RAID 1 — Зеркалирование (Mirroring)

**Принцип:** Полное дублирование данных на два или более диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | N-1 дисков |
| Чтение | Высокая (возможно параллельное чтение) |
| Запись | Средняя (ограничена скоростью самого медленного диска) |
| Полезная ёмкость | 1/N (обычно 50%) |

**Применение:** Системные разделы (OS Boot), базы данных с высокой нагрузкой на чтение при малом объёме.

---

### RAID 5 — Чередование с распределённой чётностью

**Принцип:** Данные и контрольные суммы (XOR) распределяются по всем дискам. При выходе из строя одного диска данные восстанавливаются «на лету» путём вычислений.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 3 |
| Отказоустойчивость | 1 диск |
| Чтение | Высокая |
| Запись | Низкая (требуется 4 операции I/O на одну запись — "Write Penalty") |
| Полезная ёмкость | (N-1)/N |

> **Внимание:** Не рекомендуется для дисков >2 ТБ. Вероятность неисправимой ошибки чтения (URE) при восстановлении массива (rebuild) критически высока.

---

### RAID 6 — Чередование с двойной чётностью

**Принцип:** Аналог RAID 5, но с использованием двух независимых схем чётности. Выдерживает одновременный отказ двух любых дисков.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 |
| Отказоустойчивость | 2 диска |
| Чтение | Высокая |
| Запись | Очень низкая (Write Penalty = 6 операций I/O) |
| Полезная ёмкость | (N-2)/N |

**Применение:** Большие файловые хранилища, архивы на дисках высокой плотности.

---

### RAID 10 (1+0) — Зеркало страйпов

**Принцип:** Комбинация RAID 1 и RAID 0. Диски объединяются в зеркальные пары, которые затем чередуются.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 (кратное 2) |
| Отказоустойчивость | Минимум 1 диск (до 1 в каждой зеркальной паре) |
| Чтение/Запись | Максимальная производительность |
| Полезная ёмкость | 50% |

**Применение:** Базы данных (OLTP), высоконагруженные системы виртуализации.

## Вложенные уровни RAID (Nested)

Для сверхбольших массивов используются вложенные уровни, объединяющие отказоустойчивость RAID 5/6 с производительностью RAID 0.

### RAID 50 (5+0)
Объединяет несколько групп RAID 5 в общий RAID 0.
*   **Преимущества:** Выше скорость восстановления, чем у одиночного RAID 5.
*   **Отказоустойчивость:** Выдерживает отказ одного диска в *каждой* подгруппе RAID 5.

### RAID 60 (6+0)
Объединяет несколько групп RAID 6 в общий RAID 0.
*   **Применение:** Массивы из 16+ дисков, где требуется экстремальная надёжность при большом объёме.

## Технические нюансы и проблемы

### Проблема «Write Hole»
В RAID 5/6/50/60 при внезапном отключении питания в момент записи может возникнуть ситуация, когда блок данных записан, а соответствующий ему блок чётности — нет (или наоборот). Это приводит к незаметному повреждению данных (silent corruption).
*   **Решение mdadm:** Использование внешнего журнала (PPL — Partial Parity Log) или Write-intent bitmap.
*   **Решение ZFS/Btrfs:** Использование Copy-on-Write (CoW), где Write Hole невозможен архитектурно.

### Chunk Size и выравнивание (Alignment)
**Chunk Size** (размер блока чередования) определяет, какой объём данных записывается на один диск перед переходом на следующий.
*   **Малый Chunk (4K-64K):** Хорош для случайного I/O малого размера (базы данных).
*   **Большой Chunk (256K-1M):** Оптимален для последовательного чтения/записи больших файлов (видео, бэкапы).
*   **Stripe Width:** Общий размер данных в одной строке массива (без чётности). Файловая система должна быть выровнена по границе Stripe Width для предотвращения деградации производительности (Read-Modify-Write).

### RAID на SSD накопителях
При использовании SSD в массиве возникают специфические требования:
1.  **TRIM/Discard:** Программный RAID в Linux (`mdadm`) поддерживает передачу команд TRIM на нижележащие диски. Это необходимо для поддержания производительности SSD.
2.  **Over-provisioning:** Рекомендуется оставлять 10-20% ёмкости неразмеченной для эффективной работы контроллера SSD (Garbage Collection).
3.  **Износ:** В зеркальных массивах (RAID 1/10) диски изнашиваются синхронно. Рекомендуется использовать диски из разных партий или производителей для предотвращения одновременного отказа.

## Сводная таблица выбора уровня

| Задача | Рекомендуемый RAID | Почему? |
| :--- | :--- | :--- |
| **Системный раздел** | RAID 1 | Простота, надёжность, возможность загрузки. |
| **База данных (OLTP)** | RAID 10 | Минимум задержек на запись, быстрая работа. |
| **Файловый архив** | RAID 6 | Баланс между ценой за ГБ и надёжностью. |
| **Video Editing** | RAID 0 / RAID 10 | Требуется максимальная пропускная способность. |
| **Бэкап-сервер** | RAID 60 | Безопасность при огромных объёмах данных. |
