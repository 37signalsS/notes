# Уровни RAID: технические характеристики и рекомендации 2026

## Определения

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология виртуализации данных, объединяющая несколько физических накопителей в один логический блок для повышения производительности, отказоустойчивости или обоих показателей одновременно.

**Ключевые технические параметры:**
*   **Stripe (Полоса):** Совокупность блоков данных, распределенных по всем дискам массива.
*   **Chunk Size (Размер блока):** Объем данных, записываемый на один диск перед переходом на следующий (обычно от 64 КБ до 1 МБ).
*   **Parity (Чётность):** Результат логической операции (XOR), позволяющий восстановить данные при потере одного из слагаемых.
*   **URE (Unrecoverable Read Error):** Вероятность возникновения нечитаемого сектора. Для современных дисков (2026 год, 30ТБ+) этот показатель критичен при выборе уровня избыточности.

## Основные уровни RAID

### RAID 0 — Чередование (Striping)

**Принцип:** Данные делятся на блоки и записываются поочерёдно на все диски массива. Нет избыточности.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | 0 дисков (отказ любого диска уничтожает массив) |
| Чтение | Высокая (линейно растёт с кол-вом дисков) |
| Запись | Высокая (линейно растёт с кол-вом дисков) |
| Полезная ёмкость | 100% |

**Применение:** Временные файлы, кэши, своп-разделы, рабочие пространства для обработки видео или обучения ИИ, где скорость критична, а данные легко восстановимы из бэкапа.

---

### RAID 1 — Зеркалирование (Mirroring)

**Принцип:** Полное дублирование данных на два или более диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 2 |
| Отказоустойчивость | N-1 дисков |
| Чтение | Высокая (возможно параллельное чтение разных блоков) |
| Запись | Средняя (ограничена скоростью самого медленного диска) |
| Полезная ёмкость | 1/N (обычно 50% при двух дисках) |

**Применение:** Системные разделы (OS Boot), базы данных с высокой нагрузкой на чтение при малом объёме данных.

---

### RAID 5 — Чередование с распределённой чётностью

**Принцип:** Данные и контрольные суммы (XOR) распределяются по всем дискам. Выдерживает отказ одного диска.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 3 |
| Отказоустойчивость | 1 диск |
| Чтение | Высокая |
| Запись | Низкая (Write Penalty = 4) |
| Полезная ёмкость | (N-1)/N |

> **Критическое предупреждение 2026:** Категорически не рекомендуется для дисков >10 ТБ. При использовании современных дисков 30 ТБ вероятность ошибки URE ($10^{-14}$) при ребилде массива стремится к 100%. RAID 5 сегодня — это "отложенная потеря данных".

---

### RAID 6 — Чередование с двойной чётностью

**Принцип:** Использует две независимые схемы чётности. Выдерживает одновременный отказ двух любых дисков.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 |
| Отказоустойчивость | 2 диска |
| Чтение | Высокая |
| Запись | Очень низкая (Write Penalty = 6) |
| Полезная ёмкость | (N-2)/N |

**Применение:** Стандарт для средних файловых хранилищ и архивов на дисках высокой плотности до 12–16 штук в группе.

---

### RAID 10 (1+0) — Зеркало страйпов

**Принцип:** Комбинация RAID 1 и RAID 0. Диски объединяются в зеркальные пары, которые затем чередуются.

| Параметр | Значение |
| :--- | :--- |
| Мин. дисков | 4 (кратное 2) |
| Отказоустойчивость | Минимум 1 диск (до 1 в каждой зеркальной паре) |
| Чтение/Запись | Максимальная производительность для случайного I/O |
| Полезная ёмкость | 50% |

**Применение:** Высоконагруженные базы данных (OLTP), системы виртуализации.

---

## Современные и специализированные уровни (Актуальность 2026)

### RAID-TP (Triple Parity)
**Принцип:** Три независимых слоя чётности (горизонтальная, диагональная, анти-диагональная).
*   **Отказоустойчивость:** Выдерживает отказ **3-х дисков**.
*   **Контекст:** Стал стандартом для массивов на базе HDD 20ТБ+, где время ребилда может превышать 48 часов.

### RAID-Z (ZFS)
Интегрированная реализация RAID в файловой системе ZFS.
*   **RAID-Z1 / Z2 / Z3:** Аналоги RAID 5, 6 и TP соответственно.
*   **Self-healing:** Использование контрольных сумм для каждого блока позволяет ФС автоматически обнаруживать и исправлять «тихую порчу данных» (Bit rot) при чтении.
*   **Отсутствие Write Hole:** Благодаря архитектуре Copy-on-Write данные никогда не перезаписываются на месте.

## Вложенные уровни RAID (Nested)

Используются для объединения преимуществ разных уровней в больших массивах.

### RAID 50 (5+0)
Объединяет несколько групп RAID 5 в общий RAID 0.
*   **Преимущества:** Быстрее ребилд (восстанавливается только одна подгруппа), выше производительность записи, чем у чистого RAID 5.
*   **Отказоустойчивость:** Выдерживает отказ одного диска в *каждой* подгруппе.

### RAID 60 (6+0)
Объединяет несколько групп RAID 6 в общий RAID 0.
*   **Применение:** Сверхбольшие массивы (24+ дисков), где требуется высокая плотность хранения при сохранении шансов на выживание при множественных отказах.

## Технические нюансы и проблемы

### Проблема «Write Hole»
При внезапном отключении питания в RAID 5/6 может возникнуть рассинхронизация: данные записаны, а чётность нет.
*   **Решение mdadm:** Использование PPL (Partial Parity Log) или выделенного NVMe-диска под журнал записи.
*   **Решение ZFS:** Использование ZIL (ZFS Intent Log) и CoW-структуры.

### Chunk Size и выравнивание (Alignment)
*   **Малый Chunk (4K-64K):** Оптимален для случайного I/O малого размера (базы данных). Увеличивает вероятность того, что один запрос будет обработан одним диском.
*   **Большой Chunk (256K-1M):** Оптимален для последовательных операций (видео, бэкапы). Позволяет эффективно использовать пропускную способность нескольких дисков для одного файла.
*   **Stripe Width:** Общий размер данных в одной "строке" массива. Файловая система должна быть выровнена по Stripe Width для исключения операций Read-Modify-Write.

### RAID на SSD и NVMe
Специфика 2026 года (накопители QLC/PLC 100ТБ+):
1.  **TRIM/Discard:** Обязательная поддержка на уровне RAID-контроллера (программного или аппаратного) для предотвращения деградации производительности.
2.  **Wear Leveling (Износ):** В RAID 1/10 диски изнашиваются одинаково. Рекомендуется использовать накопители разных брендов или партий.
3.  **IOPS Penalty:** Высокая производительность SSD делает Write Penalty менее заметным для латентности, но критичным для общего ресурса записи (TBW).

## Производительность и расчеты

### Write Penalty (Штраф на запись)
Количество физических операций ввода-вывода на одну логическую запись ОС.

| Уровень RAID | Write Penalty |
| :--- | :--- |
| RAID 0 | 1 |
| RAID 1 / 10 | 2 |
| RAID 5 / Z1 | 4 |
| RAID 6 / Z2 | 6 |
| RAID-TP / Z3 | 8 |

### Формула эффективного IOPS
Для оценки производительности массива под нагрузкой:

$$Effective IOPS = \frac{Raw IOPS \times N}{Read\% + (Write\% \times Penalty)}$$

*Пример:* 10 HDD (100 IOPS каждый) в RAID 6 при нагрузке 70% чтение / 30% запись:
$1000 / (0.7 + (0.3 \times 6)) = 1000 / 2.5 = 400$ IOPS.

## Сводная таблица выбора (2026)

| Задача | Рекомендуемый RAID | Почему? |
| :--- | :--- | :--- |
| **Системный раздел** | RAID 1 | Простота, загрузка с любого диска. |
| **БД (OLTP, High Load)** | RAID 10 | Минимум задержек на запись, быстрый ребилд. |
| **Хранилище (HDD 20ТБ+)** | RAID-TP / Z3 | Единственный безопасный вариант при огромном времени ребилда. |
| **Файловый сервер (SSD)** | RAID 6 / Z2 | Баланс между ценой за ТБ и надежностью. |
| **Video Editing / AI Cache** | RAID 0 | Максимальная скорость для временных данных. |
