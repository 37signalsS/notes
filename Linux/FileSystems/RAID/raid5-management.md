# Управление RAID 5

## Определения

**RAID 5 (Redundant Array of Independent Disks Level 5)** — уровень массива с чередованием данных и распределённой чётностью (parity). Обеспечивает баланс между объёмом и отказоустойчивостью, позволяя пережить отказ одного любого накопителя.

**Write Hole** — проблема рассинхронизации данных и блоков чётности при аварийном выключении питания во время записи. Может приводить к незаметной порче данных (silent corruption).

## Основные концепции

### Особенности и ограничения

| Параметр | Значение |
| :--- | :--- |
| **Мин. дисков** | 3 |
| **Отказоустойчивость** | 1 диск |
| **Штраф на запись** | 4 операции I/O (Read Data, Read Parity, Write Data, Write Parity) |
| **Chunk Size** | По умолчанию 512 КБ (в mdadm). Влияет на IOPS и пропускную способность. |

> **Критическое предупреждение:** Для дисков объемом более 2 ТБ использование RAID 5 сопряжено с высоким риском. Во время длительного процесса восстановления (rebuild) вероятность возникновения некорректируемой ошибки чтения (URE) на оставшихся дисках может превышать 50%, что приведет к полной потере массива. Рекомендуется переход на RAID 6 или RAID 10.

### Защита от Write Hole

Для минимизации рисков при сбое питания в Linux используются следующие механизмы:
1.  **Write-intent Bitmap:** Отслеживает «грязные» блоки. Ускоряет ресинхронизацию, но не гарантирует полную атомарность записи.
2.  **PPL (Partial Parity Log):** Журнал частичной чётности. Обеспечивает защиту от Write Hole без использования внешних журнальных устройств. Поддерживается в новых версиях `mdadm` для RAID 5.
3.  **Внешний журнал (Journal Device):** Использование выделенного NVMe SSD в качестве журнала записи.

## Практические сценарии

### Создание массива

```bash
# Создание с использованием PPL для защиты от Write Hole
sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 \
    --consistency-policy=ppl /dev/sdb1 /dev/sdc1 /dev/sdd1
```

**Особенности для SSD:**
При использовании SSD убедитесь, что включена поддержка TRIM (через настройку `discard` в параметрах монтирования или `fstrim`). Программный RAID 5 в Linux поддерживает передачу команд TRIM на базовые устройства.

### Обслуживание и мониторинг

#### Проверка целостности (Scrubbing)
Рекомендуется выполнять ежемесячно.
```bash
echo check | sudo tee /sys/block/md0/md/sync_action
```
После завершения проверьте файл `mismatch_cnt`. Если значение > 0, требуется запуск `repair`.

#### Лимиты скорости восстановления
Чтобы rebuild не блокировал работу системы:
```bash
# Установка минимальной и максимальной скорости (КБ/с)
echo 50000 | sudo tee /proc/sys/dev/raid/speed_limit_min
echo 200000 | sudo tee /proc/sys/dev/raid/speed_limit_max
```

### Изменение конфигурации (Reshape)

#### Добавление диска
```bash
# 1. Добавление диска как Spare
sudo mdadm /dev/md0 --add /dev/sde1
# 2. Запуск процесса расширения
sudo mdadm --grow /dev/md0 --raid-devices=4
```
**Важно:** Процесс Reshape может занять много времени и нагружать CPU. Прерывание процесса (например, при сбое питания) крайне опасно без наличия бэкапа.

#### Изменение Chunk Size
```bash
sudo mdadm --grow /dev/md0 --chunk=128
```

#### Миграция в RAID 6
Если количество дисков растет, безопасность RAID 5 становится недостаточной.
```bash
# Требуется наличие хотя бы одного Spare диска
sudo mdadm --grow /dev/md0 --level=6 --raid-devices=5
```
