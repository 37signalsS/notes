# Управление RAID 5

## Определения

**RAID 5 (Redundant Array of Independent Disks Level 5)** — уровень дискового массива, использующий чередование данных (Striping) и распределённую чётность (Parity). Обеспечивает баланс между производительностью чтения, полезной ёмкостью и отказоустойчивостью.

**Чётность (Parity)** — результат логической операции XOR, вычисляемый для блоков данных в одной строке массива (stripe). Позволяет восстановить недостающий блок данных при потере одного любого накопителя.

**Write Hole** — проблема рассинхронизации данных и блоков чётности при аварийном выключении питания в момент записи. Это может привести к повреждению файловой системы или незаметной порче данных (Silent Corruption).

**Write Penalty = 4** — при каждой операции записи выполняются 4 физические операции ввода-вывода: чтение данных, чтение чётности, запись данных, запись чётности. Это ключевое ограничение RAID 5, снижающее производительность записи.

**Rebuild (Ресинхронизация)** — процесс восстановления данных на новом диске после замены вышедшего из строя накопителя. В RAID 5 данные восстанавливаются вычислением XOR по оставшимся блокам в каждой stripe.

## Основные концепции

### Технические характеристики

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| **Мин. дисков** | 3 | Минимум для реализации схемы (N-1) + Parity. |
| **Отказоустойчивость** | 1 диск | Выход из строя второго диска приводит к потере всего массива. |
| **Штраф на запись** | 4 операции I/O | Read Data, Read Parity, Write Data, Write Parity. |
| **Полезная ёмкость** | (N-1) / N | Например, в массиве из 4-х дисков по 10 ТБ доступно 30 ТБ. |
| **Chunk Size** | 512 КБ | По умолчанию в `mdadm`. Влияет на распределение мелких и крупных файлов. |
| **Метаданные** | 1.2 (по умолчанию) | Суперблок в начале диска (4 КБ от начала). |

### Критические риски URE (Контекст 2026)

> **Внимание:** Для современных HDD объемом более 10 ТБ (и тем более 30 ТБ) использование RAID 5 сопряжено с экстремальным риском.

*   **Проблема:** При ребилде массива объемом 30 ТБ вероятность возникновения неисправимой ошибки чтения (URE, $10^{-14}$) на оставшихся дисках математически стремится к 100%.
*   **Рекомендация:** Используйте RAID 5 только для SSD-массивов или небольших HDD-групп. Для хранения важных данных на дисках высокой плотности переходите на **RAID 6** или **RAID-Z3**.

**Формула вероятности потери данных при ребилде:**

$$P_{data\_loss} = 1 - (1 - P_{URE})^{N-1}$$

*Где N — количество дисков в массиве.*

| Дисков в RAID 5 | Вероятность потери данных при ребилде |
| :--- | :--- |
| 3 | ~0.0003% |
| 6 | ~0.0006% |
| 12 | ~0.0012% |
| 24 | ~0.0024% |

> **Вывод:** При использовании дисков >10 ТБ RAID 5 становится ненадежным. Рекомендуется RAID 6/TP для массивов 12+ дисков.

### Защита от Write Hole

В Linux `mdadm` предлагает три способа решения этой проблемы:

1.  **PPL (Partial Parity Log):** Внутренний журнал частичной чётности. Хранится в метаданных массива. Рекомендуется как стандарт для HDD. Работает для 배열ей размером до 64 дисков, не требует дополнительного оборудования.
2.  **Journal Device:** Выделенное быстрое устройство (NVMe SSD) для логирования всех записей. Максимальная надежность и производительность, но требует доп. оборудования. Подходит для критичных систем.
3.  **Write-intent Bitmap:** Ускоряет ресинхронизацию, но не является полной защитой от Write Hole. Рекомендуется как дополнение к PPL.

### Производительность: чтение и запись

#### Write Penalty (Штраф на запись)

Каждая операция записи в RAID 5 выполняет 4 физических операции ввода-вывода:

| Операция | Описание |
| :--- | :--- |
| Read Data | Чтение старого блока данных (для вычисления новой чётности) |
| Read Parity | Чтение старого блока чётности |
| Write Data | Запись нового блока данных |
| Write Parity | Запись нового блока чётности |

**Формула эффективных IOPS:**

$$Effective IOPS = \frac{Raw IOPS \times N}{Read\% + (Write\% \times Penalty)}$$

*Пример:* 6 HDD (150 IOPS каждый) при нагрузке 70% чтение / 30% запись:
$900 / (0.7 + (0.3 \times 4)) = 900 / 1.9 = 474$ IOPS.

**Вывод:** RAID 5 хорош для нагрузок с преобладанием чтения (>80%). При смешанной нагрузке или высокой доле записи производительность резко падает.

#### Пропускная способность

| Уровень RAID | Чтение (N дисков) | Запись (N дисков) |
| :--- | :--- | :--- |
| RAID 5 | (N-1) × S | (N-1) × S / 4 |

*Где S — пропускная способность одного диска.*

**Пример:** RAID 5 из 4 SATA HDD (200 МБ/с):
- Чтение: 3 × 200 = 600 МБ/с (теоретически)
- Запись: 3 × 200 / 4 = 150 МБ/с (теоретически)

### Поведение в деградированном состоянии

При отказе одного диска RAID 5 продолжает работать, но с существенными ограничениями:

1. **Производительность чтения:** Каждый запрос чтения требует вычисления XOR по (N-1) оставшимся блокам вместо прямого чтения. Это создаёт нагрузку на CPU и дисковую подсистему.
2. **Производительность записи:** Write Penalty сохраняется, но чётность вычисляется на основе (N-1) блоков.
3. **Отсутствие избыточности:** Любая следующая ошибка диска — полная потеря данных.
4. **Нагрузка при восстановлении:** Во время rebuild оставшиеся диски испытывают 100% нагрузку на чтение, что может замедлить работу приложений.

**Оценка времени ребилда RAID 5:**

```
T_rebuild ≈ Размер_массива / Скорость_чтения_оставшихся_дисков × N
Пример: RAID 5 из 4 HDD по 10 ТБ (200 МБ/с), без нагрузки
30 ТБ / (200 МБ/с × 3) ≈ 50 000 секунд ≈ 14 часов
```

> **Важно:** Время ребилда пропорционально размеру массива. Для массивов 100+ ТБ процесс может занимать сутки. Использование Write-intent Bitmap сокращает время на 50–90% при сбоях питания (синхронизируются только изменённые блоки).

### Совместимость дисков

В отличие от RAID 1, RAID 5 **не допускает** использование дисков разного объёма:

*   **Ограничение:** Фактический размер массива определяется самым маленьким диском. При этом оставшееся пространство на более крупных дисках не используется.
*   **Рекомендация:** Используйте диски одинакового объёма, модели и производителя. Это упрощает обслуживание и исключает путаницу при мониторинге.
*   **Замена дисков:** При замене диска на меньший объём массив автоматически уменьшится. Для расширения необходимо выполнить `mdadm --grow --size=max` после замены всех дисков на одинаковые.

## Практические сценарии

### Предварительные требования

**Оборудование:**
- Минимум 3 диска (или раздела) одинакового объёма
- Для загрузочного RAID 5: оба диска должны быть доступны BIOS/UEFI при старте
- Рекомендуется резервный диск (Hot Spare) для автоматического восстановления
- Дополнительный NVMe SSD для Journal Device (опционально, но рекомендуется)

**Программное обеспечение:**
```bash
# Установка mdadm (Debian/Ubuntu)
sudo apt update && sudo apt install mdadm

# Установка mdadm (RHEL/CentOS/Fedora)
sudo dnf install mdadm

# Проверка версии
mdadm --version
# → mdadm - v4.2 - 2023-...
```

**Начальное состояние:**
```bash
# Проверка что диски доступны
lsblk
# → NAME   SIZE TYPE MOUNTPOINTS
#   sdb    500G disk
#   sdc    500G disk
#   sdd    500G disk

# Проверка что на дисках нет активных файловых систем
sudo blkid /dev/sdb /dev/sdc /dev/sdd
```

### Создание массива

#### 1. Подготовка накопителей
Рекомендуется использовать GPT-разделы с небольшим отступом в конце диска (100–500 МБ) для компенсации разницы в объеме дисков разных вендоров.

```bash
# Создание GPT-разметки
sudo parted /dev/sdb mklabel gpt
sudo parted /dev/sdc mklabel gpt
sudo parted /dev/sdd mklabel gpt

# Создание разделов типа 'Linux raid'
sudo parted /dev/sdb mkpart primary 1M 100%
sudo parted /dev/sdb set 1 raid on

sudo parted /dev/sdc mkpart primary 1M 100%
sudo parted /dev/sdc set 1 raid on

sudo parted /dev/sdd mkpart primary 1M 100%
sudo parted /dev/sdd set 1 raid on

# Проверка
sudo parted /dev/sdb print
# → Number  Start   End     Size    Type     Flags
#   1       1049kB  500GB   500GB   primary  raid
```

#### 2. Очистка и проверка
```bash
# Удаление старых подписей (ФС, LVM, RAID)
sudo wipefs --all /dev/sdb1 /dev/sdc1 /dev/sdd1

# Очистка суперблока RAID (если был ранее)
sudo mdadm --zero-superblock /dev/sdb1 /dev/sdc1 /dev/sdd1

# Проверка что диски чисты
sudo blkid /dev/sdb1 /dev/sdc1 /dev/sdd1
# → (пустой вывод)
```

#### 3. Создание массива

```bash
# Создание RAID 5 с PPL (Partial Parity Log) — рекомендуется для HDD
sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 \
    --consistency-policy=ppl /dev/sdb1 /dev/sdc1 /dev/sdd1

# Создание RAID 5 с Write-intent Bitmap (для ускорения rebuild после сбоя питания)
sudo mdadm --create --verbose /dev/md0 --level=5 --bitmap=internal \
    --raid-devices=3 /dev/sdb1 /dev/sdc1 /dev/sdd1

# Проверка
cat /proc/mdstat
# → md0 : active raid5 sdd1[2] sdc1[1] sdb1[0]
#       1048575360 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/3] [UUU]
#       [>..........]  recovery = 3.2% finish=10.5min speed=412480K/sec
```

> **Примечание:** `--consistency-policy=ppl` и `--bitmap=internal` не рекомендуется использовать одновременно — PPL уже обеспечивает защиту от Write Hole.

#### 4. Форматирование и монтирование
```bash
# Создание файловой системы (ext4)
sudo mkfs.ext4 -L "raid5_data" /dev/md0

# Создание файловой системы (XFS)
sudo mkfs.xfs -L "raid5_data" /dev/md0

# Монтирование
sudo mkdir -p /mnt/raid5
sudo mount /dev/md0 /mnt/raid5

# Добавление в fstab для автозагрузки
echo '/dev/md0 /mnt/raid5 ext4 defaults,noatime 0 2' | sudo tee -a /etc/fstab
```

#### 5. Финализация конфигурации
```bash
# Добавление в mdadm.conf
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf

# Обновление initramfs
sudo update-initramfs -u

# Проверка что массив определится при следующей загрузке
sudo mdadm --detail --scan
# → ARRAY /dev/md0 level=5 num-devices=3 metadata=1.2 UUID=...
```

### Работа с файловой системой

#### Выравнивание (Alignment)
Для оптимальной производительности файловая система должна быть выровнена по границе Stripe Width:

*   **Stripe Width** = `Chunk Size` × `(N - 1)`.
*   Пример: 3 диска, Chunk 512K. Stripe Width = 512K × 2 = 1024K.

```bash
# Пример создания ext4 с выравниванием
sudo mkfs.ext4 -b 4096 -E stride=128,stripe-width=256 /dev/md0
# stride = Chunk / Block size = 512/4 = 128
# stripe-width = stride * (N-1) = 128 * 2 = 256

# Проверка выравнивания после создания
sudo dumpe2fs -h /dev/md0 | grep -i "stride\|stripe"
```

#### Scrubbing (Проверка целостности)
Необходимо запускать ежемесячно для выявления «тихой порчи» данных.

```bash
# Запуск проверки
echo check | sudo tee /sys/block/md0/md/sync_action

# Просмотр прогресса
watch cat /proc/mdstat

# Проверка ошибок (если mismatch_cnt > 0, данные на дисках расходятся)
cat /sys/block/md0/md/mismatch_cnt
# → 0 (массив консистентен)

# Исправление (автоматическая перезапись чётности на основе данных)
echo repair | sudo tee /sys/block/md0/md/sync_action
```

> **Внимание:** Команда `repair` может перезаписать верные данные неверными, если причина в ошибке чтения. Используйте её только после анализа результатов `check` и убедитесь, что физические диски исправны (SMART-тест пройден).

#### Настройка скорости восстановления
```bash
# Установка лимитов (КБ/с)
echo 100000 | sudo tee /proc/sys/dev/raid/speed_limit_min
echo 500000 | sudo tee /proc/sys/dev/raid/speed_limit_max

# Проверка текущих значений
cat /proc/sys/dev/raid/speed_limit_min
cat /proc/sys/dev/raid/speed_limit_max
```

### Добавление Hot Spare (Горячий резерв)
Резервный диск, который автоматически заменит вышедший из строя.

```bash
# Добавление горячего резерва
sudo mdadm /dev/md0 --add /dev/sde1

# Проверка
cat /proc/mdstat
# → md0 : active raid5 sde1[3](S) sdd1[2] sdc1[1] sdb1[0]
#       1048575360 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/3] [UUU]
```

**Поведение при отказе диска:**
1. Сбойный диск автоматически помечается как failed
2. Spare начинает rebuild без вмешательства администратора
3. Время восстановления — от нескольких минут до часов

**Создание массива с Hot Spare:**
```bash
sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 \
    --spare-devices=1 --consistency-policy=ppl \
    /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
```

---

### Изменение конфигурации (Reshape)

#### Добавление диска и расширение
1. Добавьте диск как Spare: `sudo mdadm /dev/md0 --add /dev/sf1`.
2. Расширьте массив: `sudo mdadm --grow /dev/md0 --raid-devices=4`.
3. После завершения ребилда расширьте ФС: `sudo resize2fs /dev/md0`.

```bash
# Мониторинг прогресса
watch cat /proc/mdstat
```

#### Миграция в RAID 6
Если безопасность одного диска стала недостаточной:
```bash
# Требуется наличие Spare диска
sudo mdadm --grow /dev/md0 --level=6 --raid-devices=5
```

> **Важно:** Конвертация RAID 5 → RAID 6 — длительный процесс (часы-сутки). Массив работает в degraded state до завершения. Перед миграцией убедитесь в наличии актуального бэкапа.

### LVM поверх RAID 5

Для гибкого управления томами можно разместить LVM поверх RAID 5:

```bash
# 1. Создание RAID 5
sudo mdadm --create /dev/md0 --level=5 --consistency-policy=ppl \
    --raid-devices=3 /dev/sdb1 /dev/sdc1 /dev/sdd1

# 2. Создание Physical Volume (PV)
sudo pvcreate /dev/md0
# → Physical volume "/dev/md0" successfully created.

# 3. Создание Volume Group (VG)
sudo vgcreate vg_raid5 /dev/md0
# → Volume group "vg_raid5" successfully created

# 4. Создание Logical Volume (LV)
sudo lvcreate -n lv_data -L 200G vg_raid5
# → Logical volume "lv_data" created.

# 5. Форматирование и монтирование
sudo mkfs.ext4 /dev/vg_raid5/lv_data
sudo mkdir -p /mnt/data
sudo mount /dev/vg_raid5/lv_data /mnt/data

# 6. Проверка
sudo lvs
# → LV     VG       Attr       LSize   Pool Origin Data%  Meta%
#   lv_data vg_raid5 -wi-a----- 200.00g
```

**Преимущества LVM поверх RAID 5:**
- Онлайн-расширение томов без остановки сервисов
- Снапшоты для бэкапов и отката
- Тонкое выделение (Thin Provisioning) при необходимости
- Гибкое управление несколькими томами на одном массиве

## Обработка сбоев и восстановление

### Стандартная замена диска

При отказе диска (`cat /proc/mdstat` покажет `[UU_]`) массив переходит в режим `degraded`.

1.  **Удаление сбойного диска:**
    ```bash
    sudo mdadm /dev/md0 --fail /dev/sdb1
    sudo mdadm /dev/md0 --remove /dev/sdb1
    ```
2.  **Добавление нового диска:**
    ```bash
    sudo mdadm /dev/md0 --add /dev/sde1
    ```
3.  **Мониторинг восстановления:**
    ```bash
    watch -n 1 cat /proc/mdstat
    ```
    Во время восстановления (Rebuild) производительность системы снизится. Не выключайте питание до завершения процесса.

### Производительность в деградированном состоянии

При потере одного диска RAID 5 начинает работать значительно медленнее. В отличие от RAID 1, где данные берутся напрямую с зеркала, в RAID 5 при каждом чтении недостающий блок данных необходимо восстанавливать на лету: вычисляется XOR по оставшимся блокам в stripe. Это создаёт дополнительную нагрузку на CPU и дисковую подсистему, особенно заметную при последовательных операциях чтения.

### Выбор дисков и риски группового отказа

При проектировании массива критически важно избегать дисков одной партии, модели и производителя. Время наработки на отказ у дисков одной партии близко, и при выходе из строя одного накопителя высока вероятность, что остальные находятся на грани срока службы. Рекомендации:
- Используйте диски минимум от двух разных производителей.
- Покупайте диски в разных местах в разное время, чтобы сместить сроки замены.
- При апгрейде заменяйте диски по одному, не меняя весь массив одновременно.

### Аварийное восстановление при критической деградации

#### Ограничения

Если в RAID 5 вышло из строя **два и более дисков** и данные с них невозможно считать, массив считается потерянным. В этом случае единственный путь — обращение в сервисный центр для аппаратного снятия дампа с дисков.

Если же с дисков можно считать хотя бы часть данных, работа ведётся **не с физическими дисками, а с их образами**.

#### Обязательный этап — дампирование дисков

Перед любой работой с failing-накопителями создайте их образы. Используйте `ddrescue` вместо `dd`: он работает деликатнее, не создаёт пиковой нагрузки на диск и сохраняет лог (`mapfile`) для возобновления операции.

```bash
# Создание образа с логированием прогресса
ddrescue -d -r3 /dev/sdb /mnt/recovery/disk1.img /mnt/recovery/disk1.log
```

После создания образов все эксперименты проводите на них. Для удобства можно использовать LVM-снапшот или отдельный том для хранения образов и создания разностных копий перед рискованными операциями.

#### Сборка деградированного массива из оставшихся дисков

Когда количество доступных дисков меньше минимального для массива (3 для RAID 5), стандартная команда `mdadm --create` не подходит. Используйте `mdadm --assemble` с ключевым словом `missing` для указания отсутствующих устройств.

**Важно:** Порядок дисков в команде должен соответствовать их оригинальным номерам в массиве (`Active device`). Определить порядок можно через `mdadm --examine <disk>`:

```bash
# Определение порядка дисков
sudo mdadm --examine /dev/sdb
# Active device 0
sudo mdadm --examine /dev/sdc
# Active device 1
sudo mdadm --examine /dev/sdd
# Active device 3
```

Сборка деградированного массива (отсутствует диск №2):

```bash
# Остановите возможный автособранный массив
sudo mdadm --stop /dev/md127

# Соберите массив в деградированном состоянии
sudo mdadm --create --verbose /dev/md127 --level=5 --raid-devices=4 \
    /dev/sdb /dev/sdc missing /dev/sdd
```

При успешной сборке массив перейдёт в состояние `active degraded`, а файловая система на нём должна появиться автоматически.

#### Работа с несовместимыми метаданными (data-offset)

При сборке массива, созданного старой версией `mdadm`, может возникнуть ошибка монтирования из-за разницы в `data-offset` (смещении данных относительно начала суперблока). Например, старые версии использовали offset 2048 секторов, а современные — 496.

Определите актуальный offset через `mdadm --examine` (поле `Data Offset`) на оставшемся диске и укажите его при создании массива:

```bash
# Offset указывается в килобайтах
# 2048 секторов × 512 байт / 1024 = 1024 КБ
sudo mdadm --create --verbose /dev/md127 --level=5 --raid-devices=4 \
    --data-offset=1024K /dev/sdb /dev/sdc missing /dev/sdd
```

Правильный offset позволяет файловой системе собраться без ошибок `Wrong file system type, option or superblock missing`.

#### Ограничения

- **Невозможно уменьшить количество дисков** в существующем массиве без его полного пересоздания. Если после сбоя у вас осталось меньше дисков, чем было в оригинальном массиве, создать меньший RAID 5 из них напрямую не получится.
- Если файловая система на массиве не монтируется, не пересоздавайте её. Данные ФС хранятся на дисках и должны появиться после корректной сборки массива.
- Мелкие файлы, умещающиеся в один chunk, могут сохраниться даже после удаления, так как их блоки не перезаписываются. На это рассчитывать не стоит.

## Диагностика и решение проблем

### Массив не собирается автоматически при загрузке

**Причина:** Отсутствует запись в `mdadm.conf` или `initramfs` не содержит информацию о массиве.

```bash
# Проверка mdadm.conf
cat /etc/mdadm/mdadm.conf | grep md0

# Если отсутствует — добавить
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf

# Обновить initramfs
sudo update-initramfs -u

# Проверка что массив определяется
sudo mdadm --assemble --scan
```

### Массив получил другое имя (md127 вместо md0)

**Причина:** Отсутствует `mdadm.conf` или UUID не совпадают.

```bash
# Найти массив
cat /proc/mdstat

# Собрать по UUID
sudo mdadm --assemble /dev/md0 --uuid=<UUID_массива>

# Или собрать по компонентам
sudo mdadm --assemble /dev/md0 /dev/sdb1 /dev/sdc1 /dev/sdd1

# Сохранить конфигурацию
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
```

### Reshape завершился с ошибкой

**Причина:** Недостаточно места, сбой питания или аппаратная ошибка.

```bash
# Проверка текущего состояния reshape
cat /proc/mdstat

# Если reshape прерван — возобновление
sudo mdadm --grow /dev/md0 --raid-devices=4

# Если reshape невозможен — восстановление из метаданных
sudo mdadm --examine /dev/sdb1 | grep "Array State"
```

### Массив деградирован, но работает нормально

Это штатное состояние. RAID 5 продолжает обслуживать запросы через оставшиеся диски.

```bash
# Проверка что массив доступен
df -h /mnt/raid5
# → /dev/md0  500G  120G  360G  25% /mnt/raid5

# Проверка что нет ошибок в логах
dmesg | grep -i "md0\|error\|fault"
```

**Рекомендация:** Запланируйте замену диска в ближайшее время. Массив работает без избыточности — любая следующая ошибка диска приведёт к потере данных.

### mismatch_cnt > 0 после scrubbing

**Причина:** Расхождения между данными и чётностью. Возможные причины:
- Аппаратная ошибка чтения (坏道, перегрев)
- Write Hole после аварийного выключения питания
- Повреждение метаданных

```bash
# Проверка SMART для всех дисков
for disk in /dev/sd{b,c,d}; do
    echo "=== $disk ==="
    sudo smartctl -H $disk
    sudo smartctl -A $disk | grep -E "Reallocated|Current_Pending|Offline_Uncorrectable"
done

# Если SMART в порядке — запуск repair
echo repair | sudo tee /sys/block/md0/md/sync_action
```

## Лучшие практики

### Выбор дисков
*   Используйте диски одинакового объёма, модели и производителя
*   Избегайте дисков из одной партии — время наработки на отказ у них близко
*   Для критичных систем — диски разных производителей, купленных в разное время
*   Enterprise-grade SSD/HDD для серверных нагрузок

### Конфигурация
*   Используйте `--consistency-policy=ppl` для защиты от Write Hole
*   Включайте `--bitmap=internal` для ускорения rebuild после сбоев питания
*   Не используйте оба механизма одновременно — PPL уже обеспечивает защиту
*   Сохраняйте `mdadm.conf` и обновляйте `initramfs` после каждого изменения

### Chunk Size
*   **Малый Chunk (4K-64K):** Оптимален для случайного I/O малого размера (базы данных)
*   **Большой Chunk (256K-1M):** Оптимален для последовательных операций (видео, бэкапы)
*   **По умолчанию (512K):** Баланс для смешанных нагрузок

### Мониторинг
*   Регулярный scrubbing (не реже 1 раза в месяц)
*   Мониторинг SMART для каждого диска в массиве
*   Настраивайте уведомления через `mdmonitor` или внешние системы
*   Контролируйте `mismatch_cnt` после scrubbing

### Безопасность
*   Не используйте RAID 5 как замену бэкапу — он не защищает от логических ошибок
*   Регулярно тестируйте восстановление из бэкапа
*   Храните копии критичных данных на независимых носителях

## Edge Cases

### Диски разного объёма
RAID 5 автоматически использует размер самого маленького диска. Оставшееся пространство на более крупных дисках не используется. Для расширения:
1. Замените все диски на одинаковые большего объёма
2. Выполните `sudo mdadm --grow /dev/md0 --size=max`
3. Расширьте ФС: `sudo resize2fs /dev/md0`

### Сбой двух дисков одновременно
Крайне редкая, но возможная ситуация (одинаковое время наработки, одинаковые условия эксплуатации). RAID 5 не защищает от этого — требуется бэкап. Если данные критичны, используйте RAID 6.

### Массив на SSD
*   Включите TRIM: `echo 'options md_mod start_ro=0' | sudo tee /etc/modprobe.d/md.conf`
*   Мониторьте износ через SMART: `smartctl -a /dev/sdX | grep "Percentage_Used"`
*   Write Penalty на SSD менее заметна для латентности, но критична для ресурса записи (TBW)
*   Рассмотрите RAID 10 для SSD — он обеспечивает лучшую производительность записи

### Несколько RAID-массивов на одних дисках
Допускается создание нескольких RAID-массивов на разных разделах одного диска, но это:
- Снижает надежность (сбой диска влияет на оба массива)
- Увеличивает фрагментацию
- Рекомендуется только для временных данных

### RAID 50 (5+0)
Объединяет несколько групп RAID 5 в общий RAID 0:
- Быстрее ребилд (восстанавливается только одна подгруппа)
- Выше производительность записи, чем у чистого RAID 5
- Отказоустойчивость: отказ одного диска в каждой подгруппе

```bash
# Пример: два RAID 5 по 3 диска, объединённых в RAID 0
sudo mdadm --create /dev/md0 --level=5 --raid-devices=3 /dev/sdb1 /dev/sdc1 /dev/sdd1
sudo mdadm --create /dev/md1 --level=5 --raid-devices=3 /dev/sde1 /dev/sdf1 /dev/sdg1
sudo mdadm --create /dev/md10 --level=0 --raid-devices=2 /dev/md0 /dev/md1
```
