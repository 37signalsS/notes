# Управление RAID 5

## Определения

**RAID 5 (Redundant Array of Independent Disks Level 5)** — уровень дискового массива, использующий чередование данных (Striping) и распределённую чётность (Parity). Обеспечивает баланс между производительностью чтения, полезной ёмкостью и отказоустойчивостью.

**Чётность (Parity)** — результат логической операции XOR, вычисляемый для блоков данных в одной строке массива (stripe). Позволяет восстановить недостающий блок данных при потере одного любого накопителя.

**Write Hole** — проблема рассинхронизации данных и блоков чётности при аварийном выключении питания в момент записи. Это может привести к повреждению файловой системы или незаметной порче данных (Silent Corruption).

---

## Основные концепции

### Технические характеристики

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| **Мин. дисков** | 3 | Минимум для реализации схемы (N-1) + Parity. |
| **Отказоустойчивость** | 1 диск | Выход из строя второго диска приводит к потере всего массива. |
| **Штраф на запись** | 4 операции I/O | Read Data, Read Parity, Write Data, Write Parity. |
| **Полезная ёмкость** | (N-1) / N | Например, в массиве из 4-х дисков по 10 ТБ доступно 30 ТБ. |
| **Chunk Size** | 512 КБ | По умолчанию в `mdadm`. Влияет на распределение мелких и крупных файлов. |

### Критические риски URE (Контекст 2026)
> **Внимание:** Для современных HDD объемом более 10 ТБ (и тем более 30 ТБ) использование RAID 5 сопряжено с экстремальным риском.
*   **Проблема:** При ребилде массива объемом 30 ТБ вероятность возникновения неисправимой ошибки чтения (URE, $10^{-14}$) на оставшихся дисках математически стремится к 100%.
*   **Рекомендация:** Используйте RAID 5 только для SSD-массивов или небольших HDD-групп. Для хранения важных данных на дисках высокой плотности переходите на **RAID 6** или **RAID-Z3**.

### Защита от Write Hole
В Linux `mdadm` предлагает три способа решения этой проблемы:
1.  **PPL (Partial Parity Log):** Внутренний журнал частичной чётности. Хранится в метаданных массива. Рекомендуется как стандарт для HDD.
2.  **Journal Device:** Выделенное быстрое устройство (NVMe SSD) для логирования всех записей. Максимальная надежность и производительность, но требует доп. оборудования.
3.  **Write-intent Bitmap:** Ускоряет ресинхронизацию, но не является полной защитой от Write Hole.

## Практические сценарии

### Создание массива

```bash
# Создание RAID 5 с использованием PPL
sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 \
    --consistency-policy=ppl /dev/sdb1 /dev/sdc1 /dev/sdd1
```

**Выравнивание ФС (Stripe Width):**
Для оптимальной производительности файловая система должна быть выровнена по границе Stripe Width.
*   **Stripe Width** = `Chunk Size` × `(N - 1)`.
*   Пример: 3 диска, Chunk 512K. Stripe Width = 512K × 2 = 1024K.
```bash
# Пример создания ext4 с выравниванием
sudo mkfs.ext4 -b 4096 -E stride=128,stripe-width=256 /dev/md0
# stride = Chunk / Block size = 512/4 = 128
# stripe-width = stride * (N-1) = 128 * 2 = 256
```

### Обслуживание и мониторинг

#### Проверка и исправление (Scrubbing)
Необходимо запускать ежемесячно для выявления "тихой порчи" данных.
```bash
# Запуск проверки
echo check | sudo tee /sys/block/md0/md/sync_action

# Просмотр прогресса
watch cat /proc/mdstat

# Проверка ошибок (если mismatch_cnt > 0, данные на дисках расходятся)
cat /sys/block/md0/md/mismatch_cnt

# Исправление (автоматическая перезапись чётности на основе данных)
echo repair | sudo tee /sys/block/md0/md/sync_action
```

#### Настройка скорости восстановления
```bash
# Установка лимитов (КБ/с)
echo 100000 | sudo tee /proc/sys/dev/raid/speed_limit_min
echo 500000 | sudo tee /proc/sys/dev/raid/speed_limit_max
```

### Изменение конфигурации (Reshape)

#### Добавление диска и расширение
1. Добавьте диск как Spare: `sudo mdadm /dev/md0 --add /dev/sde1`.
2. Расширьте массив: `sudo mdadm --grow /dev/md0 --raid-devices=4`.
3. После завершения ребилда расширьте ФС: `sudo resize2fs /dev/md0`.

#### Миграция в RAID 6
Если безопасность одного диска стала недостаточной:
```bash
# Требуется наличие Spare диска
sudo mdadm --grow /dev/md0 --level=6 --raid-devices=5
```

## Обработка сбоев и восстановление

При отказе диска (`cat /proc/mdstat` покажет `[UU_]`) массив переходит в режим `degraded`.

1.  **Удаление сбойного диска:**
    ```bash
    sudo mdadm /dev/md0 --fail /dev/sdb1
    sudo mdadm /dev/md0 --remove /dev/sdb1
    ```
2.  **Добавление нового диска:**
    ```bash
    sudo mdadm /dev/md0 --add /dev/sde1
    ```
3.  **Мониторинг восстановления:**
    Во время восстановления (Rebuild) производительность системы снизится. Не выключайте питание до завершения процесса.
