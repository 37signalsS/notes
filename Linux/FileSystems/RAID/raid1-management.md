# Управление RAID 1 (зеркалирование)

## Определения

**RAID 1 (Redundant Array of Independent Disks Level 1 / Избыточный массив независимых дисков уровня 1)** — технология объединения накопителей, при которой данные идентично записываются на два или более диска (зеркалирование). Обеспечивает высокую отказоустойчивость: массив остается работоспособным до тех пор, пока исправен хотя бы один диск из зеркальной пары.

## Основные концепции

### Подходы к созданию массива

| Подход | Описание | Когда использовать |
| :--- | :--- | :--- |
| **Разделы диска** | Массив создаётся на разделах с типом `Linux RAID` | Гибкость, возможность использования диска под другие задачи |
| **Целые диски** | Массив создаётся на физических устройствах `/dev/sdX` | Максимальная простота настройки |

Для загрузочных массивов рекомендуется использовать разделы с таблицей разделов **GPT (GUID Partition Table / Таблица разделов GUID)**. Для выделенных файловых хранилищ оптимально использовать диски целиком.

## Практические сценарии

### Создание RAID 1

#### 1. Подготовка дисков

**Вариант 1: Использование разделов (рекомендуется)**

```bash
# Создание таблицы разделов GPT на /dev/sdb
sudo parted /dev/sdb mklabel gpt
sudo parted /dev/sdb mkpart primary 0% 100%
sudo parted /dev/sdb set 1 raid on

# Повторить аналогичные действия для /dev/sdc
```

#### 2. Очистка старых метаданных

Перед сборкой необходимо убедиться в отсутствии остатков старых конфигураций.

```bash
# Проверка наличия метаданных
sudo mdadm --examine /dev/sdb1

# Удаление сигнатур файловых систем и LVM (Logical Volume Manager)
sudo wipefs --all /dev/sdb1

# Удаление суперблока RAID
sudo mdadm --zero-superblock /dev/sdb1
```

#### 3. Создание массива

```bash
# Сборка массива md0 из двух разделов
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

При создании массива для раздела `/boot` рекомендуется использовать версию метаданных `1.0` для лучшей совместимости с загрузчиками: `--metadata=1.0`.

#### 4. Сохранение конфигурации и обновление загрузки

```bash
# Фиксация структуры массива в конфигурационном файле
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf

# Обновление образа initramfs (временной файловой системы ядра)
sudo update-initramfs -u
```

#### 5. Подготовка файловой системы и монтирование

```bash
# Создание ФС (Файловой системы) ext4
sudo mkfs.ext4 /dev/md0

# Определение UUID (Universally Unique Identifier / Универсальный уникальный идентификатор)
UUID=$(sudo blkid -s UUID -o value /dev/md0)

# Добавление записи в /etc/fstab для автоматического монтирования
echo "UUID=$UUID /mnt/raid1 ext4 defaults 0 0" | sudo tee -a /etc/fstab
```

---

### Обслуживание и управление сбоями

#### Определение неисправного накопителя

При переходе массива в состояние `degraded` (деградирован) необходимо выявить сбойное устройство. Подробная диагностика описана в разделе **[Мониторинг RAID-массивов](./monitoring.md)**.

```bash
# Поиск устройств со статусом failed
sudo mdadm --detail /dev/md0 | grep "failed"
```

#### Замена диска (Hot Swap)

```bash
# 1. Пометка диска как сбойного
sudo mdadm /dev/md0 --fail /dev/sdb1

# 2. Исключение диска из состава массива
sudo mdadm /dev/md0 --remove /dev/sdb1

# 3. Подключение нового диска и его добавление в массив
sudo mdadm /dev/md0 --add /dev/sdd1
```

Процесс синхронизации данных (rebuild) можно отслеживать через `/proc/mdstat`.

Процедура демонтажа массива должна выполняться последовательно для предотвращения ошибок в системе. Подробная инструкция приведена в документе **[Удаление RAID-массива](./raid-removal.md)**.
