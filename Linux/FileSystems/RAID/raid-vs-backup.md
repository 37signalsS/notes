# RAID и резервное копирование

## Определения

> **Ключевое правило:** **RAID ≠ резервное копирование**

RAID обеспечивает отказоустойчивость к сбою дисков, но **не защищает** от других угроз потери данных.

## Основные концепции

### Что защищает RAID

| Угроза | Защищает RAID? |
| :--- | :--- |
| Сбой одного диска (RAID 1/5/6/10) | ✅ Да |
| Сбой двух дисков (RAID 6/10) | ✅ Да (RAID 6/10) |
| Сбой одного диска (RAID 0) | ❌ Нет |
| Ошибка пользователя (rm -rf, DROP TABLE) | ❌ Нет |
| Логическое повреждение данных | ❌ Нет |
| Вирусы / шифровальщики | ❌ Нет |
| Пожар, потоп, кража | ❌ Нет |
| Повреждение ФС | ❌ Нет |

### Почему RAID не заменяет бэкап

#### 1. Множественный сбой

* RAID 5: сбой 2 дисков = **полная потеря данных**
* RAID 6: сбой 3 дисков = **полная потеря данных**
* Общий отказ: скачок напряжения, пожар, потоп уничтожат весь массив

#### 2. Ошибка пользователя

```bash
# Случайное удаление данных
rm -rf /mnt/raid/data/

# DROP DATABASE в СУБД
```

RAID мгновенно синхронизирует удаление на все зеркала — данные исчезают везде.

#### 3. Логическое повреждение

* Повреждение ФС (ext4, XFS) реплицируется на все диски
* Ошибка приложения (некорректная запись) тиражируется
* Вирус-шифровальщик зашифрует данные на всём массиве

#### 4. Физические угрозы

* Пожар, потоп, землетрясение
* Кража сервера
* Умышленное уничтожение

Только **внешняя резервная копия** в другом физическом месте защищает от этих угроз.

## Практические сценарии

### Правило 3-2-1

**Рекомендация для критичных данных:**

| Число | Требование |
| :--- | :--- |
| **3** | Минимум 3 копии данных (основная + 2 бэкапа) |
| **2** | Хранение на 2 разных типах носителей |
| **1** | 1 копия вне площадки (offsite) |

**Пример для сервера с RAID:**

1. **Основная:** RAID 10 на сервере
2. **Локальный бэкап:** Ежедневные инкрементальные бэкапы на NAS
3. **Внешний бэкап:** Еженедельные полные бэкапы в облако (S3, Backblaze)

---

### Стратегия бэкапа для RAID-массивов

| Тип данных | Частота | Хранение |
| :--- | :--- | :--- |
| Базы данных (OLTP) | Непрерывная репликация + hourly binlog | Локально + offsite |
| Файловый сервер | Ежедневно инкрементально, еженедельно полно | Локально + offsite |
| Конфигурации | При изменении (git) | Git-репозиторий offsite |
| Виртуальные машины | Ежедневно snapshot + export | Локально + offsite |

---

### Инструменты резервного копирования

| Инструмент | Тип | Когда использовать |
| :--- | :--- | :--- |
| **rsync** | Синхронизация файлов | Простые сценарии, зеркалирование |
| **borgbackup** | Инкрементальный с дедупликацией | Локальные и удалённые бэкапы |
| **restic** | Инкрементальный с шифрованием | Облачные бэкапы |
| **pg_basebackup** | PostgreSQL | Бэкап СУБД |
| **mysqldump / xtrabackup** | MySQL/MariaDB | Бэкап СУБД |
| **Veeam / Proxmox Backup** | Виртуальные машины | Гипервизоры |
