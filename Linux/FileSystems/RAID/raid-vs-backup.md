# Отличие RAID от резервного копирования

## Определения

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология объединения физических дисков в одну логическую единицу для обеспечения **высокой доступности (High Availability)** и производительности. RAID защищает систему от простоя при отказе оборудования.

**Резервное копирование (Backup)** — создание копии данных на независимом носителе для обеспечения **сохранности данных (Data Integrity)**. Бэкап позволяет восстановить информацию после её удаления, повреждения или катастрофической потери.

> **Фундаментальное правило:** RAID — это не бэкап. RAID обеспечивает непрерывность бизнес-процессов, а бэкап — выживание данных.

## Сравнение концепций

### Цели и сценарии защиты

| Параметр | RAID (Отказоустойчивость) | Резервное копирование |
| :--- | :--- | :--- |
| **Основная цель** | Непрерывность работы (Uptime) | Восстановление после катастроф |
| **Объект защиты** | Физический носитель (диск) | Информация (логические данные) |
| **Логическая ошибка** | Реплицируется мгновенно | Позволяет откатиться к состоянию до ошибки |
| **Удаление данных** | Удаляются со всего массива сразу | Доступны в предыдущих копиях |
| **Bit rot** | Может распространить ошибку | Позволяет восстановить неповрежденный блок |

### Матрица угроз и эффективности

| Тип угрозы | Защита через RAID | Защита через Backup | Комментарий |
| :--- | :--- | :--- | :--- |
| **Отказ 1 диска** | Да (кроме RAID 0) | Да | RAID позволяет продолжить работу без паузы. |
| **Множественный отказ** | Нет (зависит от уровня) | Да | Выход 3 дисков в RAID 6 фатален для массива. |
| **Ошибка пользователя** | Нет | Да | `rm -rf` или `DROP TABLE` требуют бэкапа. |
| **Вирус-шифровальщик** | Нет | Да (offline/immutable) | RAID зашифрует все зеркала одновременно. |
| **Bit rot (тихая порча)** | Частично | Да | RAID без проверки контрольных сумм может не заметить порчу. |
| **Кража/Пожар** | Нет | Да (off-site) | Уничтожение сервера убивает массив. |

## Технические нюансы

### Проблема "Bit rot" (Тихое повреждение данных)
Bit rot — это постепенная деградация носителя, приводящая к изменению отдельных бит данных без явного отказа диска.
*   **RAID:** Большинство стандартных уровней RAID (0, 1, 5, 10) не имеют встроенных механизмов проверки контрольных сумм данных. При чтении поврежденного блока RAID может вернуть неверные данные или перезаписать "зеркало" ошибочным значением.
*   **Решение:** Современные ФС (ZFS, Btrfs) интегрируют RAID и контрольные суммы, выявляя Bit rot «на лету». Однако бэкап остается единственным способом восстановления, если повреждение затронуло все избыточные копии.

### Снимки (Snapshots) против Резервных копий
Многие путают снимки ФС или LVM с бэкапами.
*   **Снимки:** Хранятся на том же физическом носителе/массиве. Позволяют мгновенно откатиться к версии файла, но бесполезны при физическом выходе массива из строя.
*   **Резервные копии:** Хранятся на независимом оборудовании. Требуют времени на копирование, но обеспечивают выживаемость данных при смерти основного хранилища.

### Штраф за восстановление (Rebuild)
Восстановление RAID (особенно RAID 5/6) создает огромную нагрузку на оставшиеся диски.
*   Если во время пересборки (rebuild) возникнет ошибка на другом диске, массив будет потерян.
*   Наличие свежего бэкапа перед началом rebuild — критическая мера предосторожности для системного администратора.

## Практические стратегии

### Правило «3-2-1-1-0»
Современный стандарт защиты данных:
1.  **3 копии:** Основные данные + 2 резервные.
2.  **2 типа носителей:** Например, массив дисков сервера и облачное хранилище/лента.
3.  **1 копия вне площадки (Off-site):** Облако или удаленный дата-центр.
4.  **1 копия offline/immutable:** Неизменяемое хранилище (S3 Object Lock) для защиты от Ransomware.
5.  **0 ошибок:** Регулярная автоматизированная проверка восстановления.

### Комплексный подход (Tiered Storage)
1.  **Слой 0 (Hot):** RAID 10 на NVMe SSD для максимального IOPS и доступности.
2.  **Слой 1 (Snapshots):** Часовые снимки ФС для быстрой защиты от случайных удалений.
3.  **Слой 2 (Local Backup):** Ночные бэкапы на локальный NAS (BorgBackup, Restic).
4.  **Слой 3 (Cloud):** Еженедельные зашифрованные архивы в S3.
