# Отличие RAID от резервного копирования

## Определения

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология объединения нескольких физических дисков в один логический элемент для повышения отказоустойчивости к сбоям оборудования и увеличения производительности.

**Резервное копирование (Backup)** — процесс создания копии данных на независимом носителе для восстановления информации в случае её повреждения, случайного удаления или физической потери.

> **Фундаментальное правило:** RAID обеспечивает доступность данных при сбое аппаратного обеспечения, но не является средством их сохранения при логических ошибках или внешних угрозах.

## Основные концепции

### Возможности и ограничения RAID

| Тип угрозы | Защита через RAID | Комментарий |
| :--- | :--- | :--- |
| Выход из строя одного диска | Да (кроме RAID 0) | Массив продолжает работу в режиме деградации |
| Выход из строя двух дисков | Да (RAID 6, RAID 10) | Зависит от конкретной конфигурации и уровня |
| Случайное удаление (rm -rf) | Нет | Удаление мгновенно реплицируется на все диски |
| Ошибка ПО или вирус | Нет | Поврежденные данные записываются на все носители сразу |
| Кража или пожар | Нет | Физическое уничтожение сервера ведет к потере всего массива |
| Повреждение файловой системы | Нет | Логические ошибки ФС (Файловой системы) затрагивают весь массив |

### Критические риски при отсутствии бэкапа

1. **Множественный сбой:** При выходе из строя дисков сверх лимита отказоустойчивости (например, два диска в RAID 5) данные теряются безвозвратно. Реконструкция массива в таких случаях крайне сложна или невозможна.
2. **Человеческий фактор:** Ошибочные команды, такие как `DROP DATABASE` или `rm -rf`, немедленно исполняются на всех зеркалах массива.
3. **Логическое повреждение:** Ошибки в работе приложений или действие вирусов-шифровальщиков портят данные на уровне логики, что RAID не способен предотвратить, так как его задача — обеспечивать идентичность данных на физическом уровне.

## Практические сценарии

### Применение правила "3-2-1"

Для обеспечения надежного хранения данных рекомендуется следовать классической схеме:

* **3 копии данных:** Оригинальные данные на рабочем массиве + две резервные копии.
* **2 разных носителя:** Например, основной массив сервера и внешнее сетевое хранилище **NAS (Network Attached Storage)**.
* **1 копия вне площадки:** Облачное хранилище (например, **S3 (Simple Storage Service)**) или удаленный сервер в другом дата-центре.

**Пример комплексной стратегии для RAID-системы:**

1. Основные данные хранятся на сервере в массиве RAID 10 (высокая доступность).
2. Ежечасно создаются инкрементальные снимки данных на локальный NAS.
3. Еженедельно полная копия данных отправляется в удаленное облако для защиты от катастрофических сбоев площадки.

### Инструменты резервного копирования

| Инструмент | Сфера применения | Особенности |
| :--- | :--- | :--- |
| **rsync** | Синхронизация файлов | Простота в использовании, работа через SSH |
| **BorgBackup** | Инкрементальный бэкап | Поддержка дедупликации, сжатия и шифрования |
| **Restic** | Облачные бэкапы | Нативная поддержка S3, Azure и других провайдеров |
| **pg_basebackup** | Базы данных PostgreSQL | Создание полных физических копий работающей БД |
