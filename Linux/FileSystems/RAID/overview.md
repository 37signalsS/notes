# Обзор RAID и mdadm

## Определения

### RAID

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология виртуализации данных, объединяющая несколько физических дисков в одну логическую сущность (массив). Основные цели:

1.  **Производительность** — увеличение скорости чтения и записи за счёт параллелизации операций ввода-вывода (I/O).
2.  **Отказоустойчивость** — защита от потери данных при выходе из строя одного или нескольких накопителей.

### Типы реализации RAID

| Тип | Описание | Преимущества | Недостатки |
| :--- | :--- | :--- | :--- |
| **Программный** | Управляется ядром ОС (`mdadm` в Linux) | Гибкость, переносимость, отсутствие привязки к оборудованию (vendor lock-in). | Нагрузка на CPU, зависимость от стабильности ОС. |
| **Аппаратный** | Специализированный контроллер (HBA) с собственным процессором и RAM. | Разгрузка хоста, аппаратный кэш с защитой (BBU/Flash). | Высокая стоимость, сложность восстановления при поломке контроллера. |
| **Интегрированный (FakeRAID)** | Программная логика, встроенная в чипсет материнской платы. | Низкая стоимость. | Низкая надежность, проприетарные драйверы, ограниченный функционал. |

> **Рекомендация:** В современных Linux-системах программный RAID на базе `mdadm` является стандартом де-факто. Он превосходит FakeRAID по стабильности и часто не уступает аппаратным контроллерам начального уровня по производительности. Многие аппаратные RAID-контроллеры начального уровня используют `mdadm` под капотом, а в экстренных ситуациях диски из такого массива можно извлечь и собрать на обычном сервере через `mdadm`, что невозможно с проприетарными решениями.

### Утилита mdadm

**`mdadm` (Multiple Devices Admin)** — стандартный инструмент в Linux для создания, управления и мониторинга программных RAID-массивов. Она взаимодействует с модулем ядра **MD (Multiple Devices)**.

*   **MD драйвер:** Работает на уровне блочных устройств, создавая виртуальное устройство (например, `/dev/md0`) из физических дисков или разделов.
*   **Слой в стеке:** Находится выше физических дисков, но ниже файловых систем, LVM или слоев шифрования (LUKS).
*   **Пакет:** Входит в стандартную поставку всех основных дистрибутивов Linux. Установка: `sudo apt install mdadm` (Debian/Ubuntu) или `sudo dnf install mdadm` (RHEL/CentOS/Fedora).

### Сравнение реализаций RAID

| Критерий | Программный (mdadm) | Аппаратный (HBA/RAID-контроллер) | FakeRAID (BIOS) |
| :--- | :--- | :--- | :--- |
| **Стоимость** | Нулевая (встроен в ядро) | Высокая (от $200 до $2000+) | Нулевая |
| **Производительность** | Зависит от CPU (1-3% при нагрузке) | Высокая (свой процессор + кэш) | Низкая |
| **Отказоустойчивость контроллера** | Нет привязки (переносимость между серверами) | Потеря контроллера = потеря массива | Привязка к чипсету |
| **Функционал** | Полный (RAID 0/1/4/5/6/10, reshape, bitmap) | Зависит от модели | Ограниченный |
| **Восстановление** | `mdadm --assemble` на любом Linux | Только на совместимом контроллере | Требует того же BIOS |
| **Кэш** | Ядро ОС (page cache) | Аппаратный кэш + BBU/Flash | Нет |
| **Простота управления** | CLI + sysfs | Зависит от.vendor (MegaCLI, hpssacli) | BIOS setup |

> **Подробнее:** [Аппаратные RAID-контроллеры](./hardware-raid.md) — storcli, ssacli, MegaCLI, BBU, мониторинг.

> **Практическая рекомендация:** Для серверов начального и среднего уровня программный RAID на базе `mdadm` — оптимальный выбор. Он обеспечивает достаточную производительность для большинства задач, полную переносимость между серверами и отсутствие vendor lock-in. Аппаратные контроллеры оправданы только при высоконагруженных базах данных (100K+ IOPS) или необходимости аппаратного кэша с защитой от потерь (BBU).

## Основные концепции

### Архитектура и метаданные

Программный RAID хранит структуру массива в **суперблоке** (метаданных) на каждом диске-участнике. Это позволяет ОС автоматически идентифицировать и собирать массив при загрузке.

**Версии метаданных:**

| Версия | Расположение | Особенности |
| :--- | :--- | :--- |
| **0.90** | Конец устройства | Устарела. Ограничение: 28 дисков, 2 ТБ на устройство. |
| **1.0** | Конец устройства | Позволяет читать данные напрямую как с обычного раздела (удобно для `/boot`). |
| **1.1** | Начало устройства | Редко используется. |
| **1.2** | 4 КБ от начала | **Стандарт по умолчанию.** Оптимальна для современных систем. |

### Уровни RAID

Детальный разбор уровней и их характеристик представлен в [raid-levels.md](./raid-levels.md).

| Уровень | Мин. дисков | Отказоустойчивость | Штраф на запись | Полезная ёмкость |
| :--- | :--- | :--- | :--- | :--- |
| **RAID 0** | 2 | Нет | Нет | 100% |
| **RAID 1** | 2 | 1 диск | Нет | 50% |
| **RAID 5** | 3 | 1 диск | Высокий | (N-1)/N |
| **RAID 6** | 4 | 2 диска | Очень высокий | (N-2)/N |
| **RAID 10** | 4 | 1 диск в паре | Нет | 50% |

### Планирование и надежность

*   **Разделы против целых дисков:** Рекомендуется использовать разделы (тип `Linux raid autodetect`, код `FD00` в GPT). Это позволяет оставить небольшое неразмеченное место в конце диска (100–500 МБ) для компенсации разницы в объёме дисков разных производителей при замене.
*   **Выбор дисков:** Избегайте дисков одной партии, модели и производителя. Время наработки на отказ у дисков одной партии близко, и при выходе из строя одного накопителя остальные часто оказываются на грани срока службы. Используйте диски минимум от двух производителей, купленных в разное время и в разных местах. При апгрейде заменяйте диски по одному, смещая сроки их отказа.
*   **Write-intent Bitmap:** Механизм отслеживания «грязных» блоков. Значительно ускоряет восстановление массива после сбоя питания, так как синхронизируются только измененные данные.
### Проверка целостности (Scrubbing)

Регулярное фоновое чтение всех блоков для выявления скрытых ошибок чётности или битых секторов. Рекомендуется запускать не реже одного раза в месяц.

```bash
# Запуск проверки
echo check | sudo tee /sys/block/md0/md/sync_action

# Просмотр прогресса
watch cat /proc/mdstat

# Проверка ошибок (mismatch_cnt > 0 означает расхождения)
cat /sys/block/md0/md/mismatch_cnt

# Исправление обнаруженных ошибок (перезапись на основе чётности)
echo repair | sudo tee /sys/block/md0/md/sync_action
```

> **Внимание:** Команда `repair` может перезаписать верные данные неверными, если причина в ошибке чтения. Используйте её только после анализа результатов `check`.

### Управление скоростью фоновых операций

При активном мониторинге процесс `resync` или `check` может замедлять работу приложений. Скорость можно ограничить или увеличить:

```bash
# Минимальная скорость (КБ/с, по умолчанию 1000)
echo 50000 | sudo tee /proc/sys/dev/raid/speed_limit_min

# Максимальная скорость (КБ/с, по умолчанию 200000)
echo 500000 | sudo tee /proc/sys/dev/raid/speed_limit_max
```

### Управление плохими блоками (Bad Blocks)

Современные версии `mdadm` (метаданные 1.2+) ведут список плохих блоков на уровне массива:

```bash
# Просмотр списка плохих блоков для конкретного диска
sudo mdadm --examine-badblocks /dev/sdb1

# Если количество плохих блоков растет — это признак необходимости замены диска
```

**Ручное сканирование поверхности диска** (если массив ещё не создан или для нового диска):
```bash
# Проверка на bad blocks (4 КБ блоки, 8 потоков, лог в файл)
sudo badblocks -v -b 4096 -c 32768 -t random /dev/sdb 2>&1 | tee badblocks_sdb.log
```

> **Внимание:** Еслиbad blocks обнаружены до создания массива — не используйте этот диск. Еслиbad blocks появились во время эксплуатации — запланируйте замену диска и мониторьте через `smartctl`.

### Горячая замена дисков (Hot Spare)

**Hot Spare** — резервный диск, который автоматически заменяет вышедший из строя накопитель и инициирует процесс восстановления (rebuild).

```bash
# Добавление горячего резерва
sudo mdadm /dev/md0 --add /dev/sdd1

# Просмотр горячего резерва в массиве
cat /proc/mdstat
# → диск с меткой (S) является spare
```

**Типы горячего резерва:**
- **Дедикация:** Резервный диск назначен только для конкретного массива.
- **Общий пул:** Несколько дисков в пуле, доступных для любых массивов (настраивается через `mdadm.conf`).

При выходе из строя активного диска процесс rebuild запускается автоматически, если есть Hot Spare. Восстановление занимает время пропорционально размеру массива.

### Продвинутые механизмы

*   **PPL (Partial Parity Log):** Используется в RAID 5/6 для решения проблемы «Write Hole» (повреждение данных при сбое питания во время записи). PPL хранит лог операций записи, обеспечивая консистентность без использования внешнего журнала.
*   **Reshape и Grow:** `mdadm` позволяет изменять конфигурацию массива «на лету»: добавлять диски, менять уровень RAID (например, из RAID 1 в RAID 5) или увеличивать размер массива. См. раздел [Практические сценарии](#изменение-конфигурации-массива-reshape).
*   **TRIM/Discard для SSD:** Важно включить поддержку TRIM на уровне RAID-массива для предотвращения деградации производительности SSD. В `mdadm` TRIM работает нативно (ядро 3.7+). Проверка: `cat /sys/block/md0/md/devfs` или `dmesg | grep md0 | grep trim`.

### RAID на SSD: особенности

При использовании SSD в RAID-массивах необходимо учитывать специфические факторы:

1.  **TRIM/Discard:** Обязательно включите `discard` в fstab или запускайте `fstrim` по расписанию. Без этого SSD теряют производительность при длительной эксплуатации из-за неэффективного управления блоками.
2.  **Write amplification:** В RAID 5/6 штраф на запись (Write Penalty) увеличивает количество физических операций, что ускоряет износ SSD (снижение TBW).
3.  **Выравнивание:** Убедитесь, что границы разделов выровнены по 1 МБ для оптимальной работы SSD.
4.  **Температура:** SSD в RAID могут нагреваться плотной компоновкой. Мониторьте через `smartctl -a /dev/sdX | grep Temperature`.

### Выбор дисков для RAID

*   **Избегайте дисков одной партии:** Время наработки на отказ у дисков из одной партии близко — при выходе из строя одного накопителя остальные часто оказываются на грани срока службы.
*   **Разные производители:** Используйте диски минимум от двух производителей, купленных в разное время и в разных местах.
*   **При агрессивной эксплуатации:** Заменяйте диски по одному, смещая сроки их отказа.
*   **Для критичных данных:** Используйте диски с повышенным ресурсом (enterprise-grade SSD или helium-filled HDD).

## Практические сценарии

### Создание и автоматизация сборки

При создании массива метаданные записываются сразу, но для сохранения конфигурации между перезагрузками требуются дополнительные шаги.

1.  **Создание массива (пример RAID 1):**
    ```bash
    sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
    ```

2.  **Обновление mdadm.conf:**
    Без этого шага массив может получить другое имя (например, `/dev/md127`) после перезагрузки.
    ```bash
    # Добавление информации о массиве в конфиг
    mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

3.  **Обновление initramfs:**
    Если ОС загружается с RAID, необходимо обновить образ начальной загрузки:
    ```bash
    sudo update-initramfs -u
    ```

### Мониторинг и уведомления

1.  **Проверка статуса в реальном времени:**
    ```bash
    cat /proc/mdstat
    ```
    Метки `[UU]` означают исправность дисков, `[_U]` — деградацию.

2.  **Детальный просмотр массива:**
    ```bash
    sudo mdadm --detail /dev/md0
    ```
    Поля `State`, `Working Devices`, `Failed Devices` и `Rebuild Status` показывают текущее состояние.

3.  **Проверка суперблока на физическом диске:**
    ```bash
    sudo mdadm --examine /dev/sdb1
    ```
    Полезно для диагностики, если массив не собирается автоматически.

4.  **Демон mdmonitor:**
    `mdadm` работает в режиме демона для отслеживания событий. Настройка уведомлений по почте производится в `/etc/mdadm/mdadm.conf`:
    ```conf
    MAILADDR admin@example.com
    ```
    Проверка работы демона: `systemctl status mdadm`

5.  **Автоматический тест уведомлений:**
    ```bash
    sudo mdadm --monitor --scan --test --oneshot
    ```

### Проверка SMART для дисков в RAID

Для проверки состояния физических дисков, входящих в RAID-массив, используйте `smartctl`:

```bash
# Проверка здоровья диска
sudo smartctl -H /dev/sdb

# Полный вывод атрибутов
sudo smartctl -a /dev/sdb

# Запуск короткого теста
sudo smartctl -t short /dev/sdb

# Просмотр результатов теста
sudo smartctl -l selftest /dev/sdb
```

Для дисков за аппаратными RAID-контроллерами используйте флаги инкапсуляции:
```bash
# LSI MegaRAID
sudo smartctl -d megaraid,0 -a /dev/sda

# HP Smart Array
sudo smartctl -d cciss,0 -a /dev/sda
```

Подробнее см. в разделе [Диагностика дисков (smartctl)](../../Diagnostics/Hardware/smartctl/index.md).

### Восстановление массива после сбоя

Общий алгоритм восстановления деградированного RAID-массива:

1.  **Диагностика:** Определите сбойный диск через `cat /proc/mdstat` (метки `[_U]` или `[U_]`).
2.  **Пометка «Failed»:**
    ```bash
    sudo mdadm /dev/md0 --fail /dev/sdb1
    ```
3.  **Удаление из массива:**
    ```bash
    sudo mdadm /dev/md0 --remove /dev/sdb1
    ```
4.  **Установка нового диска** и его добавление:
    ```bash
    sudo mdadm /dev/md0 --add /dev/sdc1
    ```
5.  **Мониторинг восстановления:**
    ```bash
    watch -n 1 cat /proc/mdstat
    ```
    Процесс может занять от нескольких минут до нескольких часов в зависимости от размера массива и нагрузки на систему.

Детальные инструкции по каждому уровню RAID см. в соответствующих файлах:
- [Управление RAID 1](./raid1-management.md)
- [Управление RAID 5](./raid5-management.md)

### Изменение конфигурации массива (Reshape)

`mdadm` позволяет изменять параметры массива без потери данных:

| Операция | Команда | Примечание |
| :--- | :--- | :--- |
| **Добавление диска** | `mdadm /dev/md0 --add /dev/sde1` | Диск должен быть не.partitioned или с очищенным суперблоком |
| **Увеличение числа устройств** | `mdadm --grow /dev/md0 --raid-devices=6` | Требуется предварительное добавление дисков |
| **Смена уровня RAID** | `mdadm --grow /dev/md0 --level=6 --raid-devices=5` | Конвертация RAID 5 → RAID 6 «на лету» |
| **Увеличение размера** | `mdadm --grow /dev/md0 --size=max` | После замены всех дисков на более емкие |
| **Смена chunk size** | `mdadm --grow /dev/md0 --chunk=1024` | Для оптимизации под типичную нагрузку |

> **Важно:** После `--grow` необходимо расширить файловую систему:
> - ext4: `sudo resize2fs /dev/md0`
> - XFS: `sudo xfs_growfs /mnt/raid`

После любой операции изменения конфигурации рекомендуется проверить целостность данных через scrubbing.
