# Обзор RAID и mdadm

## Определения

### RAID

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология виртуализации данных, объединяющая несколько физических дисков в одну логическую сущность (массив). Основные цели:

1.  **Производительность** — увеличение скорости чтения и записи за счёт параллелизации операций ввода-вывода (I/O).
2.  **Отказоустойчивость** — защита от потери данных при выходе из строя одного или нескольких накопителей.

### Типы реализации RAID

| Тип | Описание | Преимущества | Недостатки |
| :--- | :--- | :--- | :--- |
| **Программный** | Управляется ядром ОС (`mdadm` в Linux) | Гибкость, переносимость, отсутствие привязки к оборудованию (vendor lock-in). | Нагрузка на CPU, зависимость от стабильности ОС. |
| **Аппаратный** | Специализированный контроллер (HBA) с собственным процессором и RAM. | Разгрузка хоста, аппаратный кэш с защитой (BBU/Flash). | Высокая стоимость, сложность восстановления при поломке контроллера. |
| **Интегрированный (FakeRAID)** | Программная логика, встроенная в чипсет материнской платы. | Низкая стоимость. | Низкая надежность, проприетарные драйверы, ограниченный функционал. |

> **Рекомендация:** В современных Linux-системах программный RAID на базе `mdadm` является стандартом де-факто. Он превосходит FakeRAID по стабильности и часто не уступает аппаратным контроллерам начального уровня по производительности. Многие аппаратные RAID-контроллеры начального уровня используют `mdadm` под капотом, а в экстренных ситуациях диски из такого массива можно извлечь и собрать на обычном сервере через `mdadm`, что невозможно с проприетарными решениями.

### Утилита mdadm

**`mdadm` (Multiple Devices Admin)** — стандартный инструмент в Linux для создания, управления и мониторинга программных RAID-массивов. Она взаимодействует с модулем ядра **MD (Multiple Devices)**.

*   **MD драйвер:** Работает на уровне блочных устройств, создавая виртуальное устройство (например, `/dev/md0`) из физических дисков или разделов.
*   **Слой в стеке:** Находится выше физических дисков, но ниже файловых систем, LVM или слоев шифрования (LUKS).

## Основные концепции

### Архитектура и метаданные

Программный RAID хранит структуру массива в **суперблоке** (метаданных) на каждом диске-участнике. Это позволяет ОС автоматически идентифицировать и собирать массив при загрузке.

**Версии метаданных:**

| Версия | Расположение | Особенности |
| :--- | :--- | :--- |
| **0.90** | Конец устройства | Устарела. Ограничение: 28 дисков, 2 ТБ на устройство. |
| **1.0** | Конец устройства | Позволяет читать данные напрямую как с обычного раздела (удобно для `/boot`). |
| **1.1** | Начало устройства | Редко используется. |
| **1.2** | 4 КБ от начала | **Стандарт по умолчанию.** Оптимальна для современных систем. |

### Уровни RAID

Детальный разбор уровней и их характеристик представлен в [raid-levels.md](./raid-levels.md).

| Уровень | Мин. дисков | Отказоустойчивость | Штраф на запись | Полезная ёмкость |
| :--- | :--- | :--- | :--- | :--- |
| **RAID 0** | 2 | Нет | Нет | 100% |
| **RAID 1** | 2 | 1 диск | Нет | 50% |
| **RAID 5** | 3 | 1 диск | Высокий | (N-1)/N |
| **RAID 6** | 4 | 2 диска | Очень высокий | (N-2)/N |
| **RAID 10** | 4 | 1 диск в паре | Нет | 50% |

### Планирование и надежность

*   **Разделы против целых дисков:** Рекомендуется использовать разделы (тип `Linux raid autodetect`, код `FD00` в GPT). Это позволяет оставить небольшое неразмеченное место в конце диска (100–500 МБ) для компенсации разницы в объёме дисков разных производителей при замене.
*   **Выбор дисков:** Избегайте дисков одной партии, модели и производителя. Время наработки на отказ у дисков одной партии близко, и при выходе из строя одного накопителя остальные часто оказываются на грани срока службы. Используйте диски минимум от двух производителей, купленных в разное время и в разных местах. При апгрейде заменяйте диски по одному, смещая сроки их отказа.
*   **Write-intent Bitmap:** Механизм отслеживания «грязных» блоков. Значительно ускоряет восстановление массива после сбоя питания, так как синхронизируются только измененные данные.
*   **Scrubbing (Проверка целостности):** Регулярное фоновое чтение всех блоков для выявления скрытых ошибок чётности или битых секторов.
*   **Hot Spare:** Резервный диск, который автоматически заменяет вышедший из строя накопитель и инициирует процесс восстановления (rebuild).

### Продвинутые механизмы

*   **PPL (Partial Parity Log):** Используется в RAID 5/6 для решения проблемы «Write Hole» (повреждение данных при сбое питания во время записи). PPL хранит лог операций записи, обеспечивая консистентность без использования внешнего журнала.
*   **Reshape и Grow:** `mdadm` позволяет изменять конфигурацию массива «на лету»: добавлять диски, менять уровень RAID (например, из RAID 1 в RAID 5) или увеличивать размер массива.

## Практические сценарии

### Создание и автоматизация сборки

При создании массива метаданные записываются сразу, но для сохранения конфигурации между перезагрузками требуются дополнительные шаги.

1.  **Создание массива (пример RAID 1):**
    ```bash
    sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
    ```

2.  **Обновление mdadm.conf:**
    Без этого шага массив может получить другое имя (например, `/dev/md127`) после перезагрузки.
    ```bash
    # Добавление информации о массиве в конфиг
    mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

3.  **Обновление initramfs:**
    Если ОС загружается с RAID, необходимо обновить образ начальной загрузки:
    ```bash
    sudo update-initramfs -u
    ```

### Мониторинг и уведомления

1.  **Проверка статуса в реальном времени:**
    ```bash
    cat /proc/mdstat
    ```
    Метки `[UU]` означают исправность дисков, `[_U]` — деградацию.

2.  **Демон mdmonitor:**
    `mdadm` работает в режиме демона для отслеживания событий. Настройка уведомлений по почте производится в `/etc/mdadm/mdadm.conf`:
    ```conf
    MAILADDR admin@example.com
    ```
    Проверка работы демона: `systemctl status mdadm`
