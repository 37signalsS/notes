# Обзор RAID и mdadm

## Определения

### RAID

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — технология объединения нескольких физических дисков в одну логическую сущность (массив) для решения двух задач:

1. **Производительность** — увеличение скорости чтения и записи данных.
2. **Отказоустойчивость** — защита от потери данных при выходе из строя одного или нескольких накопителей.

### Типы реализации RAID

| Тип | Описание | Преимущества | Недостатки |
| :--- | :--- | :--- | :--- |
| **Программный** | Создаётся ОС (Операционной системой) средствами утилит (`mdadm` в Linux) | Гибкость, низкая стоимость, отсутствие привязки к оборудованию | Нагрузка на CPU (Центральный процессор), зависимость от стабильности ОС |
| **Аппаратный** | Отдельный контроллер с собственным процессором и кэшем | Максимальная производительность, независимость от ресурсов ОС | Высокая стоимость, риск потери доступа к данным при поломке контроллера (vendor lock-in) |
| **Интегрированный (FakeRAID)** | Контроллер встроен в чипсет материнской платы | Дешевле аппаратного решения | Зависимость от драйверов, надёжность ниже программного RAID |

> **Рекомендация:** Для систем на базе Linux предпочтительнее использовать **программный RAID** на базе `mdadm` — это надёжнее и гибче, чем FakeRAID, и дешевле аппаратных решений.

### mdadm

**`mdadm` (Multiple Devices Admin)** — стандартная утилита в Linux для управления программными RAID-массивами. Работает через модуль ядра **MD (Multiple Devices)**.

> **LVM и MD:** LVM (Logical Volume Manager) может создавать RAID-тома самостоятельно, используя механизмы MD, однако прямое использование `mdadm` предоставляет более тонкий контроль над массивом. Распространённая комбинация — LVM поверх mdadm.

## Основные концепции

### Архитектура программного RAID

Программный RAID в Linux функционирует на уровне блочных устройств через модуль ядра `md`. Массивы представлены в системе как устройства `/dev/mdX`. Текущее состояние всех активных массивов можно просмотреть в виртуальном файле `/proc/mdstat`.

### Метаданные (суперблок)

Утилита `mdadm` записывает служебную информацию (метаданные) на каждый диск массива. Это позволяет системе идентифицировать диски и автоматически собирать массив при загрузке.

**Версии метаданных:**

| Версия | Расположение | Особенности применения |
| :--- | :--- | :--- |
| `0.90` | Конец устройства | Устаревший формат. Использовался для загрузочных разделов (`/boot`) на старых системах |
| `1.0` | Конец устройства | Позволяет получить доступ к данным до сборки массива. Применяется для загрузчиков |
| `1.1` | Начало устройства | Современный формат. Редко используется как стандарт по умолчанию |
| `1.2` | 4К от начала | Формат по умолчанию для современных версий `mdadm`. Оптимален для большинства задач |

### Уровни RAID

Краткое сравнение основных уровней RAID приведено ниже. Подробный разбор — в [raid-levels.md](./raid-levels.md).

| Уровень | Мин. дисков | Отказоустойчивость | Производительность | Полезная ёмкость |
| :--- | :--- | :--- | :--- | :--- |
| **RAID 0** | 2 | Нет | Чтение/запись: Высокая | 100% |
| **RAID 1** | 2 | 1 диск | Чтение: Высокая, Запись: Средняя | 50% |
| **RAID 5** | 3 | 1 диск | Чтение: Высокая, Запись: Средняя | (N-1)/N |
| **RAID 6** | 4 | 2 диска | Чтение: Высокая, Запись: Низкая | (N-2)/N |
| **RAID 10** | 4 | 1 диск на пару | Чтение/запись: Максимальная | 50% |

> **Важно:** RAID 5 считается **устаревшим** для современных дисков объёмом более 1 ТБ из-за высокого риска возникновения URE (Unrecoverable Read Error / Некорректируемая ошибка чтения) во время восстановления (rebuild). Рекомендуется использовать RAID 6 или RAID 10.

## Практические сценарии

### Конфигурация и загрузка

После создания или изменения состава RAID-массива необходимо выполнить два обязательных шага для обеспечения автоматической сборки после перезагрузки:

1. **Обновление конфигурационного файла:** Сохраните текущую структуру массивов в `/etc/mdadm/mdadm.conf`.

    ```bash
    sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

2. **Обновление initramfs:** Обновите образ временной файловой системы, чтобы ядро могло собрать RAID на раннем этапе загрузки.

    ```bash
    sudo update-initramfs -u
    ```
