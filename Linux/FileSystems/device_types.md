# Типы устройств в Linux: блочные и символьные

## Определения

- **Блочное устройство (Block Device):** Объект в `/dev`, представляющий оборудование, которое оперирует данными в виде блоков фиксированного размера (секторов/кластеров) и поддерживает произвольный доступ (**Random Access**). Позволяет считывать или записывать любой блок независимо от последовательности.
- **Символьное устройство (Character Device):** Объект в `/dev`, представляющий оборудование, которое передает данные как последовательный поток байтов. Обычно не поддерживает произвольный доступ и работает в режиме реального времени (**Stream-based**).
- **Старший номер устройства (Major Number):** Числовой идентификатор, связывающий файл устройства с конкретным драйвером в ядре Linux.
- **Младший номер устройства (Minor Number):** Числовой идентификатор, используемый драйвером для различения конкретных физических экземпляров оборудования или логических разделов одного типа.

## Основные концепции

### Архитектурные различия

| Характеристика | Блочное устройство | Символьное устройство |
| :--- | :--- | :--- |
| **Доступ** | Произвольный (адресация по LBA) | Последовательный (потоковый) |
| **Буферизация** | Использует системный **Buffer Cache** | Обычно без кэша ядра (прямая передача) |
| **I/O Scheduler** | Применяется для оптимизации очереди | Не используется |
| **Интерфейс** | `ls -l` помечает символом `b` | `ls -l` помечает символом `c` |
| **Примеры** | HDD, SSD, NVMe, LVM, RAID | TTY, клавиатура, `/dev/null`, `/dev/urandom` |

### Роль Buffer Cache для блочных устройств

Ядро Linux не записывает данные на блочное устройство мгновенно. Вместо этого оно использует слой абстракции, который объединяет мелкие запросы записи в крупные блоки для снижения износа накопителей и повышения производительности. Это делает операции с блочными устройствами асинхронными, если не указаны флаги синхронизации (`O_DIRECT`, `O_SYNC`).

### Псевдоустройства (Pseudo-devices)

Многие файлы в `/dev` не привязаны к физическому железу, но реализуют логику символьных устройств:
- **`/dev/null`:** Поглощает любые данные («черная дыра»).
- **`/dev/zero`:** Источник бесконечного потока нулевых байтов.
- **`/dev/urandom`:** Интерфейс к криптографически стойкому генератору случайных чисел.
- **`/dev/full`:** Всегда возвращает ошибку «диск переполнен» при записи.

## Практические сценарии

### 1. Глубокая диагностика через `stat`

Команда `stat` позволяет увидеть Major и Minor номера, а также тип устройства (Device type):

```bash
stat /dev/sda
# → Device type: 8,0 (Major 8, Minor 0)
# → Inode: 429 (Block special file)

stat /dev/ttyS0
# → Device type: 4,40 (Major 4, Minor 64)
# → Inode: 452 (Character special file)
```

### 2. Просмотр активных драйверов

Список зарегистрированных в текущий момент Major-номеров и соответствующих им драйверов:

```bash
cat /proc/devices
# Вывод разделен на Character devices и Block devices
```

### 3. Ручное создание узлов устройств

В современных системах файлы в `/dev` создаются демоном `udev`. Однако в изолированных средах (chroot, контейнеры без привилегий) может потребоваться ручное создание:

```bash
# Создание символьного устройства tty с правами 666
sudo mknod -m 666 /tmp/my_tty c 5 0
```

### 4. Определение Major/Minor для NVMe

NVMe накопители используют другую схему нумерации по сравнению со SCSI/SATA:

```bash
ls -l /dev/nvme0n1
# brw-rw---- 1 root disk 259, 0 ... /dev/nvme0n1
```
Здесь Major 259 зарезервирован для блочных устройств с динамической аллокацией номеров.
