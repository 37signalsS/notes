# Типы устройств в Linux: блочные и символьные

## Определения

- **Блочное устройство (Block Device):** Объект в `/dev`, представляющий оборудование, которое оперирует данными в виде блоков фиксированного размера (секторов/кластеров) и поддерживает произвольный доступ (**Random Access**). Позволяет считывать или записывать любой блок независимо от последовательности.
- **Символьное устройство (Character Device):** Объект в `/dev`, представляющий оборудование, которое передает данные как последовательный поток байтов. Обычно не поддерживает произвольный доступ и работает в режиме потока (**Stream-based**).
- **Старший номер устройства (Major Number):** Числовой идентификатор (0–4095), связывающий файл устройства с конкретным драйвером в ядре Linux. Major-номера могут быть статическими (зарезервированными) или динамическими.
- **Младший номер устройства (Minor Number):** Числовой идентификатор (0–1048575), используемый драйвером для различения конкретных физических экземпляров оборудования (например, разных дисков) или логических разделов одного типа.
- **Регистрация драйвера (Device Registration):** Процесс, при котором драйвер ядра сообщает подсистеме устройств о поддерживаемом типе оборудования, резервируя Major Number и предоставляя таблицу операций (`file_operations`).
- **Узел устройства (Device Node):** Специальный файл в файловой системе (типа `b` или `c`), который служит точкой входа из пользовательского пространства к драйверу ядра. Содержит Major и Minor номера вместо данных.
- **Буфер кэша ядра (Buffer Cache / Page Cache):** Слой кэширования в оперативной памяти, через который проходят все операции чтения/записи с блочными устройствами. Позволяет объединять мелкие запросы, ускоряя повторные обращения и снижая нагрузку на накопитель.
- **Прямой ввод-вывод (Direct I/O, O_DIRECT):** Режим, при котором данные передаются между буфером пользователя и устройством напрямую, минуя Page Cache. Используется СУБД и системами хранения для управления кэшированием на уровне приложения.
- **devtmpfs:** Виртуальная файловая система, монтируемая ядром в `/dev`. Автоматически создает узлы устройств по мере регистрации драйверов, обеспечивая доступность устройств на ранних этапах загрузки (Early Boot) без участия userspace-демонов.
- **sysfs:** Виртуальная файловая система, монтируемая в `/sys`, предоставляющая структурированное представление устройств, драйверов и их атрибутов в виде файлов. Источник данных для udev и административных инструментов.
- **udev:** Демон пользовательского пространства (`systemd-udevd`), который обрабатывает события ядра (uevents), создает симлинки в `/dev/disk/`, устанавливает права доступа и запускает связанные сервисы.

## Основные концепции

### Архитектурные различия

| Характеристика | Блочное устройство | Символьное устройство |
| :--- | :--- | :--- |
| **Доступ** | Произвольный (адресация по LBA) | Последовательный (потоковый) |
| **Буферизация** | Использует системный **Buffer Cache** (Page Cache) | Обычно без кэша ядра (прямая передача) |
| **I/O Scheduler** | Применяется для оптимизации очереди запросов | Не используется |
| **Интерфейс** | В `ls -l` помечается символом `b` | В `ls -l` помечается символом `c` |
| **Примеры** | HDD, SSD, NVMe, LVM, RAID, Loop-устройства | TTY, клавиатура, `/dev/null`, `/dev/urandom`, звуковые карты |
| **Ядерный слой** | `struct block_device` + BIO + request queue | `struct cdev` + `file_operations` |
| **Максимальный размер** | Ограничен адресным пространством LBA (например, 512e → 2 TB на 512-байтовые сектора) | Потоковый, не имеет фиксированного размера |

### Модель драйверов устройств в ядре

Ядро Linux использует два независимых регистрационных механизма для подключения драйверов к пространству пользователя:

1.  **Блочные устройства (`register_blkdev`):** Драйвер регистрирует Major Number и предоставляет таблицу операций `struct block_device_operations`. Ядро создает структуру `request_queue` и связывает её с планировщиком I/O (`mq-deadline`, `bfq`, `none`).
2.  **Символьные устройства (`register_chrdev` или `cdev`):** Драйвер регистрирует Major Number и связывает таблицу `struct file_operations`, содержащую указатели на функции `open`, `read`, `write`, `ioctl`, `release`. Вызовы передаются драйверу напрямую, без буферизации и планировщика.

**Динамическая аллокация Major-номеров:**
В старых ядрах Major-номера присваивались статически. Современные драйверы используют динамическую аллокацию через `alloc_chrdev_region()` или `register_blkdev()` с нулевым Major, запрашивая любой свободный номер из диапазона 234–254 или 259+.

### Механизмы ввода-вывода

1.  **Buffer Cache (Page Cache):** Ядро Linux по умолчанию кэширует операции с блочными устройствами. Это позволяет объединять мелкие запросы записи в крупные блоки, снижая нагрузку на накопитель. Операции являются асинхронными.
2.  **Direct I/O (O_DIRECT):** Системный вызов `open` с флагом `O_DIRECT` позволяет приложению (например, СУБД) обходить кэш ядра и писать напрямую на устройство. Это требует строгого выравнивания данных по размеру блока устройства (обычно 512 или 4096 байт) и используется для управления кэшированием на уровне приложения.
3.  **devtmpfs:** Современная виртуальная файловая система, монтируемая ядром в `/dev`. Она автоматически создает узлы устройств по мере того, как драйверы регистрируют оборудование в ядре, избавляя от необходимости ручного создания файлов через `mknod`.

### Представление устройств в sysfs

Современные ядра экспортируют информацию об устройствах через иерархию `/sys`:

| Путь | Уровень | Описание |
| :--- | :--- | :--- |
| `/sys/block/` | Блочные устройства | Диски, разделы, loop-устройства, dm-* |
| `/sys/class/block/` | Symlinks | Канонические имена → `/sys/block/sda` |
| `/sys/class/mem/` | Символьные | Устройства памяти (`/dev/mem`, `/dev/kmem`) |
| `/sys/class/tty/` | Символьные | Терминалы и последовательные порты |
| `/sys/class/net/` | Символьные | Сетевые интерфейсы |
| `/sys/devices/` | Полная иерархия | Дерево устройств с учетом шин (PCI, USB, SATA) |

**Пример структуры диска в sysfs:**
```
/sys/block/sda/
├── device/          → атрибуты контроллера (SATA/SCSI/NVMe)
├── queue/           → параметры очереди (scheduler, read_ahead_kb, optimal_io_size)
├── sda1/            → раздел как отдельный блок-устройство
│   ├── size
│   └── start
└── stat             → счётчики I/O (чтение/запись, время)
```

### Псевдоустройства (Pseudo-devices)

Файлы в `/dev`, реализующие логику драйвера без привязки к физическому железу:
- **`/dev/null`:** Поглощает любые данные, при чтении всегда возвращает EOF.
- **`/dev/zero`:** Источник бесконечного потока нулевых байтов (`0x00`).
- **`/dev/full`:** Имитирует переполненный диск — любая запись возвращает ошибку `ENOSPC`.
- **`/dev/random` и `/dev/urandom`:** Интерфейсы к генератору случайных чисел ядра. Начиная с ядра **5.6**, поведение обоих устройств унифицировано: они используют один и тот же CSPRNG-пул и не блокируются (кроме момента начальной инициализации энтропии при загрузке).
- **`/dev/loop-control`:** Управляющее устройство для динамического создания и удаления loop-устройств через ioctl. Заменяет старый параметр `max_loop`.
- **`/dev/watchdog`:** Символьное устройство, интерфейс к watchdog-таймеру ядра. Используется для автоматической перезагрузки системы при зависании.
- **`/dev/net/tun`:** Символьное устройство для создания TUN/TAP интерфейсов (виртуальные сетевые карты для VPN, контейнеров).

### Устройства Device Mapper

Фреймворк Device Mapper предоставляет абстракцию для создания виртуальных блочных устройств с переопределяемой логикой отображения:

| Устройство | Назначение | Пример |
| :--- | :--- | :--- |
| **dm-0, dm-1...** | Узлы Device Mapper | `/dev/mapper/vg0-lv0` → `/dev/dm-0` |
| **dm-crypt** | Шифрование на уровне блоков (LUKS) | Зашифрованный раздел |
| **dm-thin** | Тонкое провизионирование | Thin Pool для LVM или Stratis |
| **dm-cache** | Кэширование SSD → HDD | Ускорение медленного массива |
| **dm-raid** | Программный RAID через DM | RAID1/5/6/10 |
| **dm-multipath** | Многопутевой доступ к SAN | MPIO для FC/iSCSI |

Device Mapper является фундаментом для LVM, cryptsetup и некоторых реализаций RAID. Драйвер `dm-mod` регистрируется как блок-устройство с динамическими Major-номерами.

### Классификация по типу доступа

Помимо классического деления на block/character, устройства можно классифицировать по поведению:

| Тип | Поведение | Примеры |
| :--- | :--- | :--- |
| **Серийные (Serial)** | Данные передаются строго последовательно, без позиционирования | TTY, `/dev/random`, аудио-карты |
| **Пакетные (Packet-oriented)** | Обмен дискретными пакетами/блоками с адресацией | Блочные устройства, `/dev/tun` |
| **Умные (Smart)** | Имеют внутренний процессор и буфер, поддерживают команды управления | SATA/SAS диски (TCQ, NCQ), NVMe |
| **Простые (Dumb)** | Передают данные без промежуточной обработки | Параллельные порты, простые GPIO |

## Практические сценарии

### 1. Глубокая диагностика через `stat` и `file`

Команды для определения типа устройства и его параметров:

```bash
# stat: Major/Minor номера, тип файла
stat /dev/sda
# → Device type: 8,0 (Major 8, Minor 0)
# → Inode: 429 (Block special file)

stat /dev/ttyS0
# → Device type: 4,40 (Major 4, Minor 64)
# → Inode: 452 (Character special file)

# file: текстовое описание типа устройства
file -s /dev/sda
# → /dev/sda: block special (8/0)

file -s /dev/ttyS0
# → /dev/ttyS0: character special (4/64)

# file: loop-устройство
file -s /dev/loop0
# → /dev/loop0: block special (7/0)
```

*Примечание: Major 8 зарезервирован для SCSI/SATA дисков, Major 4 — для TTY/Serial консолей, Major 259 — для NVMe.*

### 2. Просмотр зарегистрированных драйверов и устройств

Список Major-номеров и иерархия устройств:

```bash
# Активные Major-номера в текущей сессии ядра
cat /proc/devices
# Вывод разделен на Character devices и Block devices

# Полный список блок-устройств с размерами и точками монтирования
lsblk -f
# → NAME   FSTYPE LABEL  SIZE MOUNTPOINT
# → sda           931.5G
# → ├─sda1 ext4        500G /
# → └─sda2 swap       431.5G [SWAP]
# → nvme0n1       931.5G

# Иерархия в sysfs
ls -l /sys/block/
# → sda  sdb  nvme0n1  loop0  dm-0  dm-1

# Символьные устройства
ls -l /sys/class/tty/
# → console  tty  ttyS0  ttyS1
```

### 3. Ручное создание узлов устройств

В изолированных средах (chroot, bare containers) может потребоваться ручное создание узла, если `devtmpfs` недоступна:

```bash
# Создание символьного устройства null (Major 1, Minor 3)
sudo mknod -m 666 /tmp/my_null c 1 3

# Создание блочного устройства loop (Major 7, Minor 0)
sudo mknod -m 660 /dev/loop0 b 7 0

# Проверка
ls -l /dev/loop0
# → brw-rw---- 1 root disk 7, 0 ... /dev/loop0
```

### 4. Нумерация в современных подсистемах (NVMe и LVM)

Современные драйверы часто используют динамическую аллокацию Major-номеров из диапазона 234–254 или 259+.

```bash
# NVMe накопители (Major 259)
ls -l /dev/nvme0n1
# brw-rw---- 1 root disk 259, 0 ... /dev/nvme0n1

# LVM логические тома (Major 253 или 252)
ls -l /dev/mapper/data_vg-lv_root
# brw-rw---- 1 root disk 253, 0 ... /dev/mapper/data_vg-lv_root

# Device Mapper (dm-*) — динамические Major
ls -l /dev/dm-0
# brw-rw---- 1 root disk 254, 0 ... /dev/dm-0
```

### 5. Мониторинг и производительность блочных устройств

#### 5.1 Основные утилиты мониторинга

```bash
# Список устройств с размерами, типами ФС и точками монтирования
lsblk -f -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,MODEL,SERIAL
# → NAME    SIZE TYPE FSTYPE MOUNTPOINT MODEL    SERIAL
# → sda    931.5G disk        /         Samsung  S3Z2NX0M
# → ├─sda1   500G part ext4   /                      
# → └─sda2 431.5G part swap   [SWAP]                 

# Идентификация ФС и UUID
blkid /dev/sdb1
# → /dev/sdb1: UUID="abc123..." TYPE="ext4" PARTUUID="..."

# Статистика I/O в реальном времени
iostat -xz 1 5
# → device      r/s  w/s  rMB/s  wMB/s  aqu-sz  await  %util
# → sda        10.5  5.2   0.80   0.40   0.15   2.30   12.4
# → nvme0n1    45.0 20.0   3.20   1.50   0.05   0.80   25.6

# Трассировка блочных устройств
blktrace -d /dev/sda -o - | blkparse -i -
```

#### 5.2 Тонкая настройка параметров устройства

```bash
# Read-ahead: количество предзагружаемых секторов (по умолчанию 256)
blockdev --getra /dev/sda
# → 256

# Установка read-ahead в 2 MB (4096 секторов × 512 байт)
sudo blockdev --setra 4096 /dev/sda

# Оптимальный размер I/O для устройства
blockdev --getioopt /dev/sda
# → 4096 (байт)

# Размер сектора (физический)
blockdev --getss /dev/sda
# → 512

# Размер блока ФС (для сравнения)
tune2fs -l /dev/sda1 | grep "Block size"
# → Block size:               4096

# Очередь запросов: глубина
cat /sys/block/sda/queue/nr_requests
# → 128

# Максимальный размер сектора (для выравнивания)
cat /sys/block/sda/queue/logical_block_size
cat /sys/block/sda/queue/physical_block_size
```

#### 5.3 Scheduler I/O и политики

```bash
# Текущий планировщик
cat /sys/block/sda/queue/scheduler
# → [mq-deadline] kyber bfq none

# Установка планировщика (временно, до перезагрузки)
echo "mq-deadline" | sudo tee /sys/block/sda/queue/scheduler

# Постоянная настройка через udev (сохраняется после reboot)
cat > /etc/udev/rules.d/60-iosched.rules << 'EOF'
# HDD: BFQ для интерактивности
ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/rotational}=="1", ATTR{queue/scheduler}="bfq"
# SATA SSD: mq-deadline
ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/rotational}=="0", ATTR{queue/scheduler}="mq-deadline"
# NVMe: без планировщика (none)
ACTION=="add|change", KERNEL=="nvme*", ATTR{queue/scheduler}="none"
EOF
sudo udevadm control --reload-rules
sudo udevadm trigger --type=devices --action=add
```

### 6. Идентификация и безопасное манипулирование устройствами

```bash
# Канонический путь (разрешение всех symlinks)
readlink -f /dev/sdb
# → /dev/sdb
# или для stable naming:
# → /dev/disk/by-id/ata-Samsung_SSD_860_S3Z2NX0M123456

# Определение размера устройства в байтах
blockdev --getsize64 /dev/sdb
# → 1000204886016

# Проверка, смонтировано ли устройство
findmnt -rn /dev/sdb1
# → /mnt/data ext4 rw,relatime
# или пустой вывод = не смонтировано

# Безопасное уничтожение данных (SSD: blkdiscard вместо dd)
sudo blkdiscard /dev/nvme0n1    # TRIM всего устройства
sudo blkdiscard /dev/sdb1       # TRIM раздела

# Для HDD: безопасная затирка через dd
sudo dd if=/dev/zero of=/dev/sdX bs=4M status=progress conv=fdatasync

# Быстрая проверка на "не нули" после wiping
sudo dd if=/dev/sdX bs=1M | hexdump -C | grep -v ' 00 ' | head
```

### 7. Контейнеры и доступ к устройствам (cgroup device controller)

Контейнеры имеют ограниченный доступ к устройствам через cgroup device controller:

```bash
# Просмотр разрешенных устройств для контейнера (cgroup v2)
cat /sys/fs/cgroup/devices/devices.list
# → c 1:3 rwm    (null)
# → c 1:8 rwm    (random)
# → c 5:0 rwm    (tty)
# → c 5:1 rwm    (console)

# Разрешение доступа к устройству через cgroup
echo 'c 8:0 rwm' | sudo tee -a /sys/fs/cgroup/devices/devices.allow

# Docker: проброс конкретного устройства
docker run --device=/dev/sda:/dev/sda --device-read-only=/dev/sda \
  -it ubuntu bash

# Docker: все устройства (privileged)
docker run --privileged -it ubuntu bash

# Docker: ограничение доступа только к /dev/null
docker run --device=/dev/null -it ubuntu bash
```

### 8. Hotplug и горячее подключение устройств

Сценарии для серверов с горячей заменой дисков:

```bash
# Мониторинг событий подключения/отключения в реальном времени
udevadm monitor --kernel --udev --subsystem-match=block
# → KERNEL[12345.678901] add      /devices/.../nvme1n1   (block)
# → UDEV   [12345.681234] add      /devices/.../nvme1n1p1 (block)

# Проверка, видит ли ядро новое устройство
cat /proc/partitions
# → major minor  #blocks  name
# →   259       0 976762584 nvme1n1
# →   259       1   1048576 nvme1n1p1

# Принудительный вызов событий udev
sudo udevadm trigger --subsystem-match=block --action=add

# Проверка готовности устройства
sudo udevadm settle --timeout=30

# Логи udev для диагностики
journalctl -u systemd-udevd --since "5 minutes ago" -p info
```

### 9. Резервное копирование с учетом типов устройств

Разные типы устройств требуют разных стратегий:

```bash
# tar: по умолчанию создает sparse-файлы для устройств (не копирует данные)
tar -cvpf backup.tar /dev/sdb
# → /dev/sdb: character special (11, 0) — sparse-запись, не данные диска

# Для корректного копирования блочных устройств используйте dd
sudo dd if=/dev/sda of=/backup/sda.img bs=4M status=progress conv=fdatasync

# Символьные устройства: копирование потока (например, /dev/zero)
sudo dd if=/dev/zero of=/tmp/testfile bs=1M count=100

# Проверка, является ли файл устройством (не обычным файлом)
file /backup/sda.img
# → /backup/sda.img: data (ранее block special)
```

## Типичные ошибки и диагностика

| Проблема | Причина и решение |
| :--- | :--- |
| **Недостаточные права на устройство** | Проверьте права доступа: `ls -l /dev/sda`. Для LVM/RAID добавьте пользователя в группу `disk`. Для контейнеров используйте `--device` или `--privileged`. |
| **Устройство не появляется в `/dev`** | Проверьте, загружен ли драйвер: `lsmod | grep sdax`. Проверьте `dmesg | tail` на наличие ошибок обнаружения. Для USB — проверьте `lsusb`. |
| **Неверный Major/Minor при ручном создании** | Используйте `./scripts/setlocalversion` или проверьте `/proc/devices` и документацию драйвера. Ошибка в Major → ядро вызовет не тот драйвер. |
| **Ошибка "Device or resource busy"** | Устройство смонтировано (`findmnt /dev/sda1`), используется LVM или часть активного массива RAID. Отмонтируйте или деактивируйте перед операцией. |
| **Блочное устройство определяетcя как символьное** | Возможно, использован неверный Major при `mknod` или поврежден inode. Проверьте через `stat` и пересоздайте узел. |
| **Stale device node после отключения** | При hot-unplug узел может остаться в `/dev`. Очистите: `sudo udevadm trigger --subsystem-match=block --action=remove`. |
| **Ошибка "No such device" при mount** | Проверьте `lsblk` — устройство существует? Проверьте `dmesg` — драйвер загружен? Проверьте `cat /proc/partitions` — раздел существует? |
| **"Wrong fs type" при монтировании** | Устройство существует, но содержит не ФС. Проверьте: `file -s /dev/sda1`. Возможно, это раздел swap или LVM PV. |

## Лучшие практики

### 1. Идентификация устройств

- **Используйте stable naming** (`/dev/disk/by-uuid/`, `/dev/disk/by-id/`) в скриптах и `/etc/fstab` вместо `/dev/sdX`.
- **Проверяйте тип устройства** через `file -s` перед операциями, особенно при автоматизации.
- **Используйте `lsblk`** как основную утилиту для инвентаризации: она показывает иерархию, размеры, типы и точки монтирования.

### 2. Безопасность

- **Никогда не полагайтесь на имена `/dev/sdX`** в production-скриптах — они меняются при добавлении/удалении дисков.
- **Проверяйте, что устройство не смонтировано** перед операциями записи (`findmnt`, `lsblk`).
- **Используйте `conv=fdatasync`** с `dd` для критичных операций, чтобы гарантировать запись на диск.
- **Для SSD используйте `blkdiscard`** вместо `dd if=/dev/zero` — быстрее и безопаснее для wear-leveling.

### 3. Производительность

- **Выбирайте `bs` кратно размеру сектора** (512e → 4096, 4Kn → 4096) для выровненного I/O.
- **Настраивайте read-ahead** (`blockdev --setra`) под нагрузку: большие значения для последовательного чтения, маленькие для случайного.
- **Выбирайте scheduler по типу диска:** `none` для NVMe, `mq-deadline` для SSD, `bfq` для HDD с интерактивной нагрузкой.

### 4. Мониторинг и observability

- **Мониторьте `iostat`** для detecting degraded RAID или failing-дисков (рост await, %util).
- **Следите за `dmesg`** на предмет ошибок SATA/SCSI/NVMe (`kernel: sd 0:0:0:0: [sda] FAILED`).
- **Логируйте события udev** при изменении правил: `journalctl -u systemd-udevd -f`.

### 5. Восстановление и откат

- **Сохраняйте таблицу разделов** перед операциями: `sudo dd if=/dev/sda of=mbr_backup.bin bs=512 count=1`.
- **Тестируйте на виртуальных машинах** перед работой с физическими дисками.
- **Используйте `ddrescue`** для failing-дисков вместо обычного `dd`.

### 6. Управление устройствами в контейнерах

- **Используйте `--device`** вместо `--privileged` для минимальных привилегий.
- **Пробрасывайте только нужные устройства:** `--device=/dev/sdb` вместо доступа ко всей системе.
- **Для сетевых устройств (TUN/TAP)** используйте `--cap-add NET_ADMIN` и `--device /dev/net/tun`.
