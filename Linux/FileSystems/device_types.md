# Типы устройств в Linux: блочные и символьные

## Определения

- **Блочное устройство (Block Device):** Объект в `/dev`, представляющий оборудование, которое оперирует данными в виде блоков фиксированного размера (секторов/кластеров) и поддерживает произвольный доступ (**Random Access**). Позволяет считывать или записывать любой блок независимо от последовательности.
- **Символьное устройство (Character Device):** Объект в `/dev`, представляющий оборудование, которое передает данные как последовательный поток байтов. Обычно не поддерживает произвольный доступ и работает в режиме потока (**Stream-based**).
- **Старший номер устройства (Major Number):** Числовой идентификатор (0–4095), связывающий файл устройства с конкретным драйвером в ядре Linux. Major-номера могут быть статическими (зарезервированными) или динамическими.
- **Младший номер устройства (Minor Number):** Числовой идентификатор (0–1048575), используемый драйвером для различения конкретных физических экземпляров оборудования (например, разных дисков) или логических разделов одного типа.

## Основные концепции

### Архитектурные различия

| Характеристика | Блочное устройство | Символьное устройство |
| :--- | :--- | :--- |
| **Доступ** | Произвольный (адресация по LBA) | Последовательный (потоковый) |
| **Буферизация** | Использует системный **Buffer Cache** (Page Cache) | Обычно без кэша ядра (прямая передача) |
| **I/O Scheduler** | Применяется для оптимизации очереди запросов | Не используется |
| **Интерфейс** | В `ls -l` помечается символом `b` | В `ls -l` помечается символом `c` |
| **Примеры** | HDD, SSD, NVMe, LVM, RAID, Loop-устройства | TTY, клавиатура, `/dev/null`, `/dev/urandom`, звуковые карты |

### Механизмы ввода-вывода

1. **Buffer Cache (Page Cache):** Ядро Linux по умолчанию кэширует операции с блочными устройствами. Это позволяет объединять мелкие запросы записи в крупные блоки, снижая нагрузку на накопитель. Операции являются асинхронными.
2. **Direct I/O (O_DIRECT):** Системный вызов `open` с флагом `O_DIRECT` позволяет приложению (например, СУБД) обходить кэш ядра и писать напрямую на устройство. Это требует строгого выравнивания данных по размеру блока устройства (обычно 512 или 4096 байт) и используется для управления кэшированием на уровне приложения.
3. **devtmpfs:** Современная виртуальная файловая система, монтируемая ядром в `/dev`. Она автоматически создает узлы устройств по мере того, как драйверы регистрируют оборудование в ядре, избавляя от необходимости ручного создания файлов через `mknod`.

### Псевдоустройства (Pseudo-devices)

Файлы в `/dev`, реализующие логику драйвера без привязки к физическому железу:
- **`/dev/null`:** Поглощает любые данные, при чтении всегда возвращает EOF.
- **`/dev/zero`:** Источник бесконечного потока нулевых байтов (`0x00`).
- **`/dev/full`:** Имитирует переполненный диск — любая запись возвращает ошибку `ENOSPC`.
- **`/dev/random` и `/dev/urandom`:** Интерфейсы к генератору случайных чисел ядра. Начиная с ядра **5.6**, поведение обоих устройств унифицировано: они используют один и тот же CSPRNG-пул и не блокируются (кроме момента начальной инициализации энтропии при загрузке).

## Практические сценарии

### 1. Глубокая диагностика через `stat`

Команда `stat` показывает Major и Minor номера в поле «Device type»:

```bash
stat /dev/sda
# → Device type: 8,0 (Major 8, Minor 0)
# → Inode: 429 (Block special file)

stat /dev/ttyS0
# → Device type: 4,40 (Major 4, Minor 64)
# → Inode: 452 (Character special file)
```
*Примечание: Major 8 зарезервирован для SCSI/SATA дисков, Major 4 — для TTY/Serial консолей.*

### 2. Просмотр зарегистрированных драйверов

Список Major-номеров, активных в текущей сессии ядра:

```bash
cat /proc/devices
# Вывод разделен на Character devices и Block devices
```

### 3. Ручное создание узлов устройств

В изолированных средах (chroot, bare containers) может потребоваться ручное создание узла, если `devtmpfs` недоступна:

```bash
# Создание символьного устройства null (Major 1, Minor 3)
sudo mknod -m 666 /tmp/my_null c 1 3
```

### 4. Нумерация в современных подсистемах (NVMe и LVM)

Современные драйверы часто используют динамическую аллокацию Major-номеров из диапазона 234–254 или 259+.

```bash
# NVMe накопители (Major 259)
ls -l /dev/nvme0n1
# brw-rw---- 1 root disk 259, 0 ... /dev/nvme0n1

# LVM логические тома (Major 253 или 252)
ls -l /dev/mapper/data_vg-lv_root
# brw-rw---- 1 root disk 253, 0 ... /dev/mapper/data_vg-lv_root
```
