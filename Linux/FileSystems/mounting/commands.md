# Определения

**Команды монтирования** — набор системных утилит командной строки, предназначенных для управления подключением (монтированием) и отключением (размонтированием) файловых систем в иерархию каталогов Linux. 

Основными инструментами являются `mount` (подключение), `umount` (отключение) и `findmnt` (инспекция).

# Основные концепции

## mount — подключение файловых систем

Команда `mount` связывает файловую систему на устройстве или сетевом ресурсе с определенным каталогом (**точкой монтирования**).

*   **Синтаксис**: `mount [опции] <источник> <точка_монтирования>`
*   **Идентификация источника**: 
    *   **UUID**: Универсальный идентификатор ФС. Рекомендуется для стабильности (не зависит от порядка инициализации дисков).
    *   **PARTUUID**: Идентификатор раздела (GPT). Полезен, если ФС не создана.
    *   **LABEL**: Метка тома.
    *   **Путь устройства**: `/dev/sdX` (нестабильно после перезагрузки).
*   **Автоопределение**: Ядро обычно автоматически определяет тип ФС, обращаясь к `libblkid`.

### Специальные режимы монтирования

1.  **Bind Mount (`--bind`)**: Примонтировать часть иерархии в другое место. Полезно для `chroot` или контейнеров.
    ```bash
    mount --bind /source/dir /target/dir
    ```
2.  **Move (`--move`)**: Переместить уже смонтированную ФС в другую точку монтирования атомарно.
    ```bash
    mount --move /old/point /new/point
    ```
3.  **Propagation (Распространение)**: Управление тем, как события монтирования передаются между пространствами имен (shared, private, slave, unbindable). Подробнее: [Mount Namespaces](../../Virtualization/mount_namespaces.md).

## umount — отключение файловых систем

Команда `umount` безопасно завершает работу с ФС, сбрасывая буферы записи на диск.

*   **Синтаксис**: `umount [опции] <точка_монтирования | устройство>`

### Решение проблем занятости (target is busy)

Если ФС нельзя размонтировать, используйте диагностику:

1.  **`lsof`**: Поиск открытых файлов и процессов.
    ```bash
    sudo lsof +D /mnt/data
    ```
2.  **`fuser`**: Проверка использования ресурсов (интегрирована во многие системы).
    ```bash
    sudo fuser -vm /mnt/data
    ```

**Варианты принудительного отключения:**
*   **Lazy (`-l`)**: Немедленно удаляет точку из дерева ФС. Ядро фактически отключит устройство только после закрытия всех дескрипторов.
*   **Force (`-f`)**: Применяется для "повисших" сетевых ФС (NFS/CIFS).
*   **Recursive (`-R`)**: Размонтировать дерево вместе со всеми вложенными точками.

## findmnt — современная инспекция

Утилита `findmnt` является основным инструментом для анализа состояния монтирования в современных системах.

*   **Дерево монтирования**: `findmnt --tree` (наглядно показывает зависимости слоев).
*   **Фильтрация**: `findmnt -t ext4` (показать только конкретный тип ФС).
*   **Верификация**: `findmnt --verify` (проверка `/etc/fstab` на наличие ошибок, дубликатов и битых путей).

# Практические сценарии

```bash
# 1. Просмотр всех точек монтирования в удобном виде
findmnt --real  # Исключает виртуальные ФС (proc, sys, dev)

# 2. Монтирование по UUID (предпочтительно)
sudo mount UUID="a1b2c3d4-e5f6-7890" /mnt/backup

# 3. Монтирование ISO-образа (петлевое устройство)
sudo mount -o loop /path/to/image.iso /mnt/iso

# 4. Перемонтирование в режим только для чтения (защита данных)
# Подробнее в [remount.md](./remount.md)
sudo mount -o remount,ro /mnt/data

# 5. Применение изменений из fstab
# ВАЖНО: В системах с systemd рекомендуется сначала выполнить daemon-reload
sudo systemctl daemon-reload
sudo mount -a

# 6. Проверка fstab на ошибки перед перезагрузкой
findmnt --verify --verbose

# 7. Размонтирование с принудительным завершением процессов (осторожно!)
sudo fuser -vkm /mnt/data && sudo umount /mnt/data
```
