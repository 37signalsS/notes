# Определения

**Монтирование (Mounting)** — процесс логического подключения файловой системы (раздела диска, сетевого ресурса, образа или виртуальной ФС) к определенной директории в едином дереве каталогов Linux. 

Эта директория называется **точкой монтирования (mount point)**. После завершения операции содержимое целевого устройства становится доступным для чтения и записи по указанному пути, скрывая исходное содержимое каталога (если оно было).

С точки зрения ядра, монтирование — это связывание структуры данных конкретной файловой системы с объектом в **VFS (Virtual File System)**.

# Основные концепции

## Методы монтирования

В современной экосистеме Linux выбор метода зависит от требуемой стабильности, скорости загрузки и динамичности окружения.

| Метод | Механизм | Сценарий использования | Сложность | Рекомендация |
| :--- | :--- | :--- | :--- | :--- |
| **Ручное** | Команда `mount` | Временное подключение, отладка | Низкая | Для разовых задач |
| **Статическое** | `/etc/fstab` | Постоянные диски, разделы ОС | Низкая | Стандарт для локальных ФС |
| **Systemd mount** | Юниты `.mount` | Сетевые диски, сложные зависимости | Средняя | Современная замена fstab |
| **Systemd automount** | Юниты `.automount` | Ленивое монтирование (по запросу) | Средняя | Альтернатива Autofs |
| **Autofs** | Демон `autofs` | Корпоративные NFS/SMB шары | Высокая | Масштабируемые среды |
| **Udev** | Правила `udev` | Внешние USB/Thunderbolt носители | Высокая | Специфичное оборудование |

## Описание подходов

1. **Традиционный (`/etc/fstab`)**: Самый распространенный способ. При загрузке `systemd-fstab-generator` динамически создает временные `.mount` юниты из содержимого этого файла. Подробнее: [fstab.md](./fstab.md).

2. **Декларативный (`systemd`)**: Позволяет задавать зависимости (например, монтировать только после старта `network-online.target`). Рекомендуется для NFS, CIFS и дисков, необходимых для работы конкретных сервисов. Подробнее: [scenarios/systemd_mount.md](./scenarios/systemd_mount.md).

3. **Динамический (`autofs`)**: Монтирование происходит в момент обращения процесса к директории и размонтируется по таймауту. Это предотвращает зависание всей системы при недоступности сетевого ресурса. Подробнее: [scenarios/autofs_mount.md](./scenarios/autofs_mount.md).

4. **Событийный (`udev`)**: Используется для автоматизации монтирования при физическом появлении устройства (hot-plug). Часто применяется для шифрованных USB-токенов или внешних дисков. Подробнее: [scenarios/udev_mount.md](./scenarios/udev_mount.md).

# Специальные типы монтирования

Linux поддерживает продвинутые механизмы управления деревом ФС:

### 1. Bind Mount (Монтирование привязкой)
Создает зеркало уже существующей директории или файла в другом месте.
*   **Применение:** Проброс данных в `chroot`, контейнеры или изоляция путей.
*   **Команда:** `mount --bind /source /target`.

### 2. Loop Mount (Петлевое монтирование)
Позволяет монтировать файлы как блочные устройства (через `/dev/loopX`).
*   **Применение:** Работа с ISO-образами, дисками виртуальных машин или зашифрованными файлами-контейнерами.
*   **Команда:** `mount -o loop image.iso /mnt`.

### 3. OverlayFS (Наложенная ФС)
Объединяет несколько директорий в одну виртуальную точку. Использует слои: `lowerdir` (RO) и `upperdir` (RW).
*   **Применение:** Базовая технология для слоев в Docker и Live-дистрибутивах.

# Распространение монтирования (Mount Propagation)

В системах с пространствами имен (Namespaces), например в контейнерах, важно контролировать, как события монтирования передаются между родителем и потомком:

*   **Shared:** События передаются в обе стороны. Монтирование в родителе появится в потомке и наоборот.
*   **Slave:** События передаются только от родителя к потомку.
*   **Private:** Полная изоляция. События не передаются.
*   **Unbindable:** Запрещает делать Bind Mount данного ресурса (защита от рекурсии).

# Управление и диагностика

### Основные инструменты
*   **`mount` / `umount`**: Базовые команды. 
    *   `umount -l` (Lazy): Размонтировать ФС немедленно, даже если она занята (очистка произойдет после закрытия всех дескрипторов).
    *   `umount -f` (Force): Принудительное отключение (в основном для NFS/CIFS при потере связи).
*   **`findmnt`**: Рекомендуемый инструмент для анализа. Позволяет видеть дерево зависимостей и параметры VFS.
*   **`remount`**: Изменение опций «на лету» (например, `ro` -> `rw`). Подробнее: [remount.md](./remount.md).

### Проверка перед перезагрузкой
Всегда проверяйте корректность статических записей:
```bash
# Проверка синтаксиса /etc/fstab
findmnt --verify
# → Success: no errors or warnings detected
```
