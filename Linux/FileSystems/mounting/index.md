# Определения

**Монтирование (Mounting)** — процесс логического подключения файловой системы (раздела диска, сетевого ресурса, образа или виртуальной ФС) к определенной директории в едином дереве каталогов Linux. 

Эта директория называется **точкой монтирования (mount point)**. После завершения операции содержимое целевого устройства становится доступным для чтения и записи по указанному пути, скрывая исходное содержимое каталога (если оно было).

# Основные концепции

## Методы монтирования

В современной экосистеме Linux выбор метода зависит от требуемой стабильности, скорости загрузки и динамичности окружения.

| Метод | Механизм | Сценарий использования | Сложность | Рекомендация |
| :--- | :--- | :--- | :--- | :--- |
| **Ручное** | Команда `mount` | Временное подключение, отладка | Низкая | Для разовых задач |
| **Статическое** | `/etc/fstab` | Постоянные диски, разделы ОС | Низкая | Стандарт для локальных ФС |
| **Systemd mount** | Юниты `.mount` | Сетевые диски, сложные зависимости | Средняя | Современная замена fstab |
| **Systemd automount** | Юниты `.automount` | Ленивое монтирование (по запросу) | Средняя | Альтернатива Autofs |
| **Autofs** | Демон `autofs` | Корпоративные NFS/SMB шары | Высокая | Масштабируемые среды |
| **Udev** | Правила `udev` | Внешние USB/Thunderbolt носители | Высокая | Специфичное оборудование |

## Описание подходов

1. **Традиционный (`/etc/fstab`)**: Самый распространенный способ. На современных системах с systemd файл `fstab` парсится утилитой `systemctl-fstab-generator`, которая на лету создает временные `.mount` юниты при загрузке. Подробнее: [fstab.md](./fstab.md).

2. **Декларативный (`systemd`)**: Позволяет задавать зависимости (например, монтировать только после старта `network-online.target`). Рекомендуется для NFS, CIFS и дисков, необходимых для работы конкретных сервисов. Подробнее: [scenarios/systemd_mount.md](./scenarios/systemd_mount.md).

3. **Динамический (`autofs`)**: Позволяет не держать соединение открытым постоянно. Монтирование происходит в момент перехода в директорию и размонтируется по таймауту. Подробнее: [scenarios/autofs_mount.md](./scenarios/autofs_mount.md).

4. **Событийный (`udev`)**: Используется для автоматизации монтирования при физическом появлении устройства. Часто применяется в защищенных средах для специфической обработки носителей. Подробнее: [scenarios/udev_mount.md](./scenarios/udev_mount.md).

# Специальные типы монтирования

Помимо стандартного подключения разделов, Linux поддерживает продвинутые механизмы:

### 1. Bind Mount (Монтирование привязкой)
Позволяет примонтировать уже смонтированную директорию в другое место дерева каталогов. Создает «зеркало» папки.
*   **Применение:** Изоляция сервисов, создание `chroot` окружений, проброс папок в контейнеры.
*   **Команда:** `mount --bind /source /target`.

### 2. Loop Mount (Петлевое монтирование)
Позволяет монтировать файлы (образы дисков, ISO) так, как если бы они были блочными устройствами.
*   **Применение:** Установка ОС с образов, работа с зашифрованными контейнерами.
*   **Команда:** `mount -o loop image.iso /mnt`.

### 3. OverlayFS (Наложенная ФС)
Объединяет несколько директорий в одну виртуальную ФС, где один слой (верхний) обычно доступен для записи, а другой (нижний) — только для чтения.
*   **Применение:** Технология слоев в Docker, LiveCD системы.

# Управление и диагностика

Основные инструменты для работы с точками монтирования:

*   **`mount` / `umount`**: Базовые команды подключения и отключения.
*   **`findmnt`**: (Рекомендуется) Современная утилита для отображения дерева монтирования и поиска зависимостей.
*   **`remount`**: Изменение опций ФС (например, переход из `ro` в `rw`) без остановки работы. Подробнее: [remount.md](./remount.md).
