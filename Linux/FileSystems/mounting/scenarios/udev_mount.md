# Автоматическое монтирование через udev

## Определения

**Udev** — подсистема Linux для динамического управления устройствами в директории `/dev`. Она позволяет выполнять действия (скрипты, команды) при появлении или удалении аппаратных интерфейсов.

Теоретические основы, синтаксис правил и методы инспекции атрибутов описаны в основном материале: [Udev — динамическое управление устройствами](../../../Core/udev.md).

## Основные концепции

Использование udev для монтирования основано на обработке событий `add` (подключение) и `remove` (отключение). 

> **Важное архитектурное предупреждение:** В современных системах с `systemd` прямое выполнение `/bin/mount` через ключ `RUN` в правилах udev считается антипаттерном. `udev` завершает процессы в `RUN` по таймауту, что может привести к повреждению файловой системы или некорректному состоянию юнитов монтирования. 

**Рекомендуемые современные подходы:**
1.  **`systemd-mount`**: Утилита, специально разработанная для вызова из udev; она передает задачу монтирования демону systemd.
2.  **Systemd-юниты**: Активация готового `.mount` юнита через переменную окружения `ENV{SYSTEMD_WANTS}`.

## Практический сценарий: Монтирование USB-диска по серийному номеру

### 1. Подготовка точки монтирования

```bash
sudo mkdir -p /mnt/secure-storage
```

### 2. Сбор атрибутов устройства

Найдите серийный номер вашего устройства (подставьте свое имя устройства, например `sdb1`):
```bash
udevadm info -a -n /dev/sdb1 | grep 'serial'
# → ATTRS{serial}=="ABC123456789"
```

### 3. Настройка правил udev

Создайте файл `/etc/udev/rules.d/99-usb-mount.rules`. 

#### Вариант А: Использование systemd-mount (Рекомендуемый)

Этот метод наиболее надежен, так как systemd берет на себя управление жизненным циклом монтирования и корректно обрабатывает зависимости.

```ini
# /etc/udev/rules.d/99-usb-mount.rules

# При подключении: монтируем раздел sdb1 (или аналогичный) по серийному номеру родительского устройства
ACTION=="add", SUBSYSTEM=="block", ENV{ID_SERIAL_SHORT}=="ABC123456789", RUN+="/usr/bin/systemd-mount --no-block --collect /dev/%k /mnt/secure-storage"

# При отключении: systemd-mount автоматически обработает размонтирование (clean up)
```

#### Вариант Б: Вызов через системный скрипт (Для сложных условий)

Если перед монтированием требуется сложная логика (например, проверка на вирусы или дешифрация), используйте скрипт, но вызывайте его как сервис или через `systemd-run`.

**Правило udev:**
```ini
ACTION=="add", SUBSYSTEM=="block", ENV{ID_SERIAL_SHORT}=="ABC123456789", RUN+="/usr/bin/systemd-run --unit=usb-mount@%k /usr/local/bin/usb-handler.sh %k"
```

### 4. Применение конфигурации

После редактирования правил необходимо заставить `udev` перечитать их:
```bash
sudo udevadm control --reload-rules
# Опционально: принудительно вызвать выполнение правил для уже подключенных устройств
sudo udevadm trigger
```

### 5. Мониторинг и отладка

Если монтирование не происходит, проверьте поток событий и лог выполнения:
```bash
# Мониторинг событий в реальном времени
udevadm monitor --udev --property

# Просмотр логов systemd, если использовался systemd-mount
journalctl -u systemd-mount -f
```
