# Определения

Этот сценарий описывает процесс переноса содержимого существующего системного каталога (например, `/var/log`, `/home`) на отдельный физический диск с последующим монтированием этого диска в исходное расположение. Это частая практика для высвобождения места на корневом разделе или для изоляции дискового ввода-вывода.

# Основные концепции

Ключевая задача — скопировать все данные без потерь и с сохранением прав доступа, при этом минимизировав риск повреждения данных.

*   **Предотвращение записи**: Перед копированием необходимо остановить все службы, которые могут записывать данные в переносимый каталог. Для критичных системных каталогов (как `/var`) эту операцию рекомендуется проводить в **однопользовательском режиме** (`systemctl rescue`).
*   **Копирование данных**: Для переноса используется утилита `rsync` с флагом `-a` (архивный режим), который рекурсивно копирует файлы, сохраняя все права, владельцев, временные метки и символические ссылки.
*   **Безопасность**: Старые данные не удаляются сразу, а переименовываются в бэкап. Это позволяет откатить изменения, если что-то пойдет не так.

# Практический сценарий: Перенос `/var/log` на новый диск

### 1. Подготовка

1.  **Подготовьте новый диск**: Убедитесь, что на диске (`/dev/sdb1` в нашем примере) создан раздел и файловая система. См. [сценарий добавления нового диска](./basic_partition.md).
2.  **Остановите службы**: Остановите сервисы, которые активно пишут в логи, чтобы избежать потери данных при копировании.
    ```bash
    sudo systemctl stop rsyslog.service
    ```

### 2. Копирование данных

1.  **Смонтируйте новый диск** во временную точку монтирования.
    ```bash
    sudo mount /dev/sdb1 /mnt
    ```
2.  **Скопируйте данные** с помощью `rsync`. Слеш в конце исходного пути (`/var/log/`) важен — он означает "скопировать содержимое каталога", а не сам каталог.
    ```bash
    sudo rsync -av /var/log/ /mnt/
    ```

### 3. Настройка новой точки монтирования

1.  **Переименуйте старый каталог** (создайте бэкап).
    ```bash
    sudo mv /var/log /var/log.bak
    ```
2.  **Создайте пустой каталог**, который станет новой точкой монтирования.
    ```bash
    sudo mkdir /var/log
    ```
3.  **Размонтируйте диск** из временной точки.
    ```bash
    sudo umount /mnt
    ```

### 4. Настройка автоматического монтирования

1.  **Узнайте UUID** нового раздела.
    ```bash
    sudo blkid /dev/sdb1
    ```
2.  **Добавьте запись в `/etc/fstab`**.
    ```text
    # Вставьте реальный UUID
    UUID=...    /var/log    ext4    defaults,nofail    0    2
    ```
3.  **Смонтируйте новый раздел** и проверьте.
    ```bash
    sudo mount -a
    df -hT /var/log
    ```
    Убедитесь, что раздел примонтирован и его содержимое соответствует тому, что было в `/var/log.bak`.

### 5. Завершение

1.  **Запустите остановленные службы**.
    ```bash
    sudo systemctl start rsyslog.service
    ```
2.  **Удалите бэкап** после того, как убедились, что все работает корректно в течение некоторого времени.
    ```bash
    sudo rm -rf /var/log.bak
    ```
