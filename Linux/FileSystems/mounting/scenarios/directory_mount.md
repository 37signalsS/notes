# Определения

**Сценарий переноса каталога (Directory migration scenario)** — процесс перемещения содержимого существующего системного каталога (например, `/var/log`, `/home`) на отдельный физический диск или раздел с последующим монтированием этого ресурса в исходное расположение. Применяется для высвобождения места на корневом разделе или оптимизации производительности дискового ввода-вывода (I/O).

# Основные концепции

Ключевая задача — скопировать все данные без потерь и с сохранением прав доступа POSIX (Portable Operating System Interface), минимизируя риски при выполнении операции.

* **Предотвращение записи**: Перед копированием необходимо остановить все службы, которые могут записывать данные в переносимый каталог. Для критических системных каталогов (например, `/var`) операцию рекомендуется проводить в однопользовательском режиме (`systemctl rescue`).
* **Копирование данных**: Для переноса используется утилита `rsync` в архивном режиме. Это гарантирует рекурсивное копирование файлов с сохранением прав, владельцев, временных меток и символических ссылок. Подробнее: [rsync — синхронизация файлов](../../../SystemAdministration/rsync.md).
* **Безопасность**: Исходные данные не удаляются сразу, а переименовываются в резервную копию (backup). Это позволяет быстро откатить изменения в случае ошибки.

## Опции rsync для миграции

| Опция | Назначение |
| :--- | :--- |
| `-a` | Архивный режим (сохраняет права, владельца, ссылки) |
| `-v` | Подробный вывод (verbose) |
| `-x` | Не пересекать границы файловых систем |
| `-H` | Сохранять жёсткие ссылки |
| `-A` | Сохранять ACL (Access Control List) |
| `-X` | Сохранять расширенные атрибуты |

**Рекомендуемая комбинация:** `rsync -avxHAX`

# Практические сценарии

## Сценарий: Перенос `/var/log` на новый диск

### 1. Подготовка

1. **Подготовьте новый диск**: Создайте раздел и файловую систему (например, на `/dev/sdb1`). См. **[Сценарий базовой разметки](./basic_partition.md)**.
2. **Остановите службы**: Отключите сервисы, активно записывающие логи (например, `rsyslog`).

    ```bash
    sudo systemctl stop rsyslog.service
    ```

### 2. Копирование данных

**Вариант A: Использование rsync (рекомендуется)**

1. **Смонтируйте новый диск** во временную точку монтирования.

    ```bash
    sudo mount /dev/sdb1 /mnt
    ```

2. **Выполните копирование**. Слэш в конце пути источника (`/var/log/`) указывает на копирование содержимого, а не самой директории.

    ```bash
    sudo rsync -avxHAX /var/log/ /mnt/
    ```

**Вариант B: Использование tar (альтернатива)**

```bash
sudo tar -C /var -cf - log | (cd /mnt && tar -xf -)
```

### 3. Настройка новой точки монтирования

1. **Переименуйте старый каталог** для создания резервной копии.

    ```bash
    sudo mv /var/log /var/log.bak
    ```

2. **Создайте пустую директорию** для новой точки монтирования.

    ```bash
    sudo mkdir /var/log
    ```

3. **Размонтируйте диск** из временного расположения.

    ```bash
    sudo umount /mnt
    ```

### 4. Настройка автоматического монтирования

1. **Узнайте UUID** (Universally Unique Identifier) раздела.

    ```bash
    sudo blkid /dev/sdb1
    ```

2. **Добавьте запись в `/etc/fstab`** (file systems table).

    ```text
    # /etc/fstab
    UUID=ЗНАЧЕНИЕ_UUID    /var/log    ext4    defaults,nofail    0    2
    ```

3. **Выполните монтирование** и проверку.

    ```bash
    sudo mount -a
    findmnt /var/log
    ```

### 5. Завершение

1. **Запустите службы**.

    ```bash
    sudo systemctl start rsyslog.service
    ```

2. **Проверьте логи** и работу системы в течение нескольких дней. После подтверждения стабильности удалите бэкап:

    ```bash
    sudo rm -rf /var/log.bak
    ```

## Откат изменений

Если при проверке обнаружены ошибки, верните систему в исходное состояние:

```bash
# 1. Остановка служб
sudo systemctl stop rsyslog.service

# 2. Размонтирование и очистка
sudo umount /var/log
sudo rmdir /var/log

# 3. Восстановление данных
sudo mv /var/log.bak /var/log

# 4. Запуск служб
sudo systemctl start rsyslog.service
```
