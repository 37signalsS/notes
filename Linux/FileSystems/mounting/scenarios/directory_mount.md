# Определения

**Сценарий переноса каталога (Directory migration scenario)** — комплексная процедура перемещения содержимого существующей системной директории (например, `/var/log`, `/var/lib/docker`, `/home`) на выделенный физический или виртуальный диск. 

Основная цель операции — предотвращение переполнения корневого раздела (`/`), изоляция данных для повышения отказоустойчивости или оптимизация производительности дисковой подсистемы.

# Основные концепции

Для безопасного переноса данных без их повреждения или потери прав доступа необходимо соблюдать следующие принципы:

1.  **Консистентность данных**: Перед копированием все процессы, пишущие в целевой каталог, должны быть остановлены.
2.  **Сохранение метаданных**: Использование инструментов, поддерживающих расширенные атрибуты (ACL, SELinux contexts, hard links).
3.  **Атомарность переключения**: Использование временных точек монтирования для проверки данных перед финальной правкой конфигурации.

# Практические сценарии

## Сценарий: Перенос /var/log на новый диск

### 1. Подготовка нового диска
Сначала необходимо разметить и отформатировать новый диск. 
*Подробные инструкции см. в разделе: **[Сценарий базовой разметки](./basic_partition.md)**.*
Предположим, новый раздел доступен как `/dev/sdb1`.

### 2. Остановка зависимых сервисов
Это критически важный шаг. Если сервисы продолжат запись во время копирования, данные будут повреждены или неполны.
```bash
# Пример для системного журнала
sudo systemctl stop rsyslog.service
sudo systemctl stop systemd-journald.service
```

### 3. Миграция данных
Смонтируйте новый диск во временную папку и выполните копирование с сохранением всех атрибутов.

```bash
# 1. Временное монтирование
sudo mount /dev/sdb1 /mnt

# 2. Копирование (флаг -aAX сохраняет права, ACL и атрибуты)
# Слэш в конце /var/log/ обязателен — копируется содержимое
sudo rsync -aAXv /var/log/ /mnt/
```

### 4. Настройка постоянного монтирования

#### Шаг 1: Получение UUID
```bash
lsblk -f /dev/sdb1
```

#### Шаг 2: Резервное копирование и подготовка
```bash
# Переименуйте старый каталог (для возможности отката)
sudo mv /var/log /var/log.bak

# Создайте пустую точку монтирования с теми же правами
sudo mkdir /var/log
sudo chmod 755 /var/log
```

#### Шаг 3: Конфигурация /etc/fstab
```bash
# Добавьте запись (замените UUID на ваш)
echo 'UUID=ваш-uuid-тут /var/log ext4 defaults,noatime 0 2' | sudo tee -a /etc/fstab
```

### 5. Применение и запуск
```bash
# 1. Обновление systemd (обязательно!)
sudo systemctl daemon-reload

# 2. Монтирование
sudo mount /var/log

# 3. Запуск сервисов
sudo systemctl start systemd-journald.service
sudo systemctl start rsyslog.service
```

### 6. Очистка (Safety Check)
Убедитесь, что все данные на месте и сервисы работают корректно. Только после этого удаляйте старую копию:
```bash
sudo rm -rf /var/log.bak
```
