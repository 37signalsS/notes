# Определения

**Autofs** — системная служба Linux для автоматического монтирования файловых систем по требованию. 

В отличие от статического монтирования через `/etc/fstab`, Autofs подключает ресурс только в момент обращения процесса к соответствующей директории и автоматически размонтирует его после заданного периода неактивности. Это критически важно для экономии сетевых ресурсов и предотвращения зависаний системы при недоступности удаленных серверов.

> **Текущий статус:** Autofs версии 5.x является стандартом индустрии. Несмотря на наличие альтернативы в лице `systemd automount`, Autofs остается предпочтительным выбором для сложных корпоративных сред с использованием NIS, LDAP или сотен сетевых шаров.

# Основные концепции

## Архитектура и конфигурация

Работа Autofs базируется на иерархии конфигурационных файлов:

1.  **Главный файл (`/etc/auto.master`)**: Определяет базовые точки монтирования и связывает их с файлами карт.
2.  **Файлы карт (Maps)**: Содержат списки поддиректорий, опции монтирования и источники данных.
3.  **Исполняемые карты (Executable Maps)**: Скрипты, которые динамически генерируют параметры монтирования (полезно для интеграции с БД или облачными API).

## Режимы отображения директорий

*   **Non-browsable (по умолчанию)**: Вложенные точки монтирования не видны в выводе `ls`, пока к ним не обратятся по точному имени. Это предотвращает массовое сканирование сетевых ресурсов.
*   **Browsable (`--ghost`)**: Создает пустые директории-плейсхолдеры, которые видны пользователю всегда. Это упрощает навигацию, но может замедлить работу при огромном количестве точек.

## Сравнение: Autofs и Systemd Automount

| Критерий | Autofs | Systemd Automount |
| :--- | :--- | :--- |
| **Сложность** | Выше (специфичный синтаксис) | Ниже (нативные юниты) |
| **Масштабируемость** | Сотни и тысячи точек (wildcards) | Десятки точек |
| **Интеграция** | Отличная (SSSD, LDAP, NIS) | Ограниченная |
| **Изоляция** | Работает в пространстве пользователя | Часть системы инициализации |

# Практические сценарии

## Сценарий 1: Динамические домашние директории (NFS)

Стандартное решение для кластеров и офисных сетей, где данные пользователя должны «следовать» за ним на любой сервер.

### 1. Настройка auto.master
Указываем, что корень `/home` управляется картой `auto.home`.
```text
# /etc/auto.master
/home  /etc/auto.home  --timeout=600 --ghost
```

### 2. Создание карты auto.home
Используем подстановочные знаки: `*` (ключ обращения) и `&` (значение ключа).
```text
# /etc/auto.home
*  -rw,soft,intr,nosuid  nfsserver.local:/export/home/&
```
*При обращении к `/home/user1` будет автоматически смонтирован путь `nfsserver.local:/export/home/user1`.*

## Сценарий 2: Прямое монтирование (Absolute Paths)

Используется для подключения конкретных ресурсов в произвольные точки дерева ФС.

### 1. Настройка auto.master
Специальный ключ `/-` позволяет использовать абсолютные пути внутри файла карты.
```text
# /etc/auto.master
/-  /etc/auto.direct  --timeout=60
```

### 2. Создание карты auto.direct
```text
# /etc/auto.direct
/mnt/backup  -fstype=nfs4,ro,soft  backup-srv.local:/volumes/bkp
/mnt/data    -fstype=ext4,rw       :/dev/disk/by-uuid/a1b2c3d4...
```

## Сценарий 3: Интеграция с SSSD и LDAP

В крупных инфраструктурах карты Autofs хранятся централизованно в каталоге LDAP. SSSD (System Security Services Daemon) кэширует их и предоставляет службе Autofs.

**Настройка в `/etc/sssd/sssd.conf`:**
```ini
[sssd]
services = nss, pam, autofs

[autofs]
# Настройки кэширования карт
```

**Настройка в `/etc/nsswitch.conf`:**
```text
automount: files sss
```

# Диагностика и отладка

Autofs может быть сложен в отладке из-за "невидимости" процессов монтирования.

```bash
# 1. Запуск в интерактивном режиме с выводом отладочной информации
sudo systemctl stop autofs
sudo automount -f -v

# 2. Проверка статуса и последних событий
systemctl status autofs

# 3. Мониторинг через системный журнал
journalctl -u autofs -f

# 4. Просмотр активных точек монтирования
findmnt -t autofs
```

# Ограничения и риски

| Риск | Описание | Решение |
| :--- | :--- | :--- |
| **Stale Mounts** | Сервер упал, точка монтирования зависла | Использовать опции `soft,retrans=2,timeo=50` |
| **Race Conditions** | Конфликт при одновременном обращении | Настройка `negative_timeout` для кэширования ошибок |
| **Security** | Проброс SUID через сетевые шары | Всегда использовать `nosuid` в опциях карт |
