# Определения

**Systemd mount units** — современный декларативный механизм управления файловыми системами в Linux. В отличие от традиционного `/etc/fstab`, юниты монтирования являются полноправными объектами системы инициализации, что позволяет использовать весь арсенал функций `systemd`: зависимости, мониторинг, логирование и автоматизацию.

Основные типы юнитов:
*   **.mount** — описывает параметры статического монтирования.
*   **.automount** — обеспечивает монтирование по требованию (при первом обращении).

# Основные концепции

## Преимущества перед /etc/fstab

*   **Управление зависимостями**: Возможность привязать монтирование к состоянию сети (`network-online.target`), конкретному устройству или запуску базы данных.
*   **Параллелизм**: Асинхронная обработка запросов на монтирование ускоряет общую загрузку системы.
*   **Инспекция и логирование**: Стандартный интерфейс `systemctl status` и сбор подробных логов в `journald`.
*   **Динамическое управление**: Возможность создавать временные (transient) монтирования «на лету» без редактирования конфигурационных файлов.

## Генератор systemd-fstab-generator

Важно понимать, что в современных дистрибутивах `/etc/fstab` не игнорируется. При загрузке специальный инструмент `systemd-fstab-generator` парсит `fstab` и динамически создает `.mount` юниты в директории `/run/systemd/generator/`. 
> Поэтому после ручного изменения `/etc/fstab` обязательна команда `sudo systemctl daemon-reload`.

## Правила именования

Имя файла юнита **должно строго соответствовать** пути точки монтирования:
1.  Удаляется ведущий слеш.
2.  Все остальные слеши заменяются дефисами (`-`).
3.  Символы, которые уже являются дефисами, и спецсимволы экранируются (через `systemd-escape`).

| Точка монтирования | Имя юнита |
| :--- | :--- |
| `/` | `-.mount` |
| `/mnt/storage` | `mnt-storage.mount` |
| `/var/lib/docker` | `var-lib-docker.mount` |

# Структура юнит-файла

### Секция [Unit]
*   **`After=` / `Before=`**: Порядок запуска относительно других служб.
*   **`Requires=` / `Wants=`**: Логические зависимости.
*   **`BindsTo=`**: Если указанный юнит (например, сетевой интерфейс или диск) исчезает, это монтирование также останавливается.

### Секция [Mount]
*   **`What=`**: Источник (путь к устройству, `UUID=...`, `LABEL=...` или сетевой адрес).
*   **`Where=`**: Абсолютный путь точки монтирования (должен совпадать с именем файла).
*   **`Type=`**: Тип ФС (ext4, xfs, nfs4, cifs и т.д.).
*   **`Options=`**: Список опций через запятую (аналогично 4-му полю fstab).
*   **`DirectoryMode=`**: Права доступа к создаваемой точке монтирования (например, `0755`).

### Секция [Install]
*   **`WantedBy=`**: Обычно `multi-user.target` для загрузки в штатном режиме.

# Практические сценарии

## Сценарий 1: Сетевая папка (NFS) с контролем сети

Этот метод надежнее `fstab`, так как исключает попытки монтирования до того, как сеть станет доступна.

**Файл `/etc/systemd/system/mnt-backup.mount`**:
```ini
[Unit]
Description=Корпоративное хранилище бэкапов (NFS)
After=network-online.target
Wants=network-online.target

[Mount]
What=backup-server.local:/volumes/safe
Where=/mnt/backup
Type=nfs
Options=rw,soft,timeo=50
TimeoutSec=30

[Install]
WantedBy=multi-user.target
```

## Сценарий 2: Автомонтирование по требованию (.automount)

Идеально для ресурсов, которые используются редко, или для ускорения загрузки критических сервисов.

**Файл `/etc/systemd/system/mnt-backup.automount`**:
```ini
[Unit]
Description=Автомонтирование бэкапов по запросу

[Automount]
Where=/mnt/backup
TimeoutIdleSec=300
DirectoryMode=0755

[Install]
WantedBy=multi-user.target
```
*Примечание: При использовании `.automount` соответствующий `.mount` файл должен существовать, но его не нужно включать через `enable`.*

## Сценарий 3: Временное монтирование (systemd-mount)

Используется для разовых задач без создания файлов на диске. Юнит создается в памяти.
```bash
# Создать временное монтирование
sudo systemd-mount /dev/sdb1 /mnt/tmp-disk

# Посмотреть созданный юнит
systemctl status mnt-tmp--disk.mount
```

# Диагностика

```bash
# Проверка состояния
systemctl status mnt-storage.mount

# Просмотр логов монтирования
journalctl -u mnt-storage.mount

# Список всех активных юнитов монтирования
systemctl list-units --type=mount

# Проверка иерархии и опций
findmnt /mnt/storage
```
