# Определения

**Сценарий базовой разметки (Basic partition scenario)** — структурированная последовательность действий по подготовке и вводу в эксплуатацию нового физического или виртуального накопителя. 

Процесс включает в себя инициализацию таблицы разделов, создание файловой системы и настройку отказоустойчивого автоматического монтирования через системные конфигурационные файлы.

# Основные концепции

Подготовка диска выполняется в строго определенном порядке для обеспечения целостности данных и стабильности системы:

1.  **Идентификация**: Определение целевого устройства и проверка отсутствия на нем важных данных.
2.  **Очистка (опционально)**: Удаление старых сигнатур ФС или RAID с помощью `wipefs`.
3.  **Разметка (Partitioning)**: Создание логических областей (разделов) с использованием стандартов MBR или GPT.
4.  **Форматирование (Formatting)**: Создание структур файловой системы на разделе.
5.  **Настройка монтирования**: Регистрация раздела в системе для автоматического подключения при загрузке.

## Сравнение инструментов разметки

| Инструмент | Стандарт | Особенности |
| :--- | :--- | :--- |
| **`fdisk`** | MBR/GPT | Интерактивный, классический, поддержка GPT в современных версиях. |
| **`parted`** | GPT/MBR | Поддержка скриптов, работа с дисками > 2 ТБ, выравнивание по умолчанию. |
| **`gdisk`** | GPT | Специализированный инструмент для работы с GPT-разметкой. |

# Практические сценарии

## Сценарий: Подготовка нового диска данных

### 1. Идентификация и безопасность

Найдите имя нового диска в системе:
```bash
lsblk
```
*Убедитесь, что устройство (например, `/dev/sdb`) не примонтировано и не содержит данных. Если диск использовался ранее, удалите старые метаданные:*
```bash
# ПРЕДУПРЕЖДЕНИЕ: Эта команда уничтожает данные о ФС на диске!
sudo wipefs -a /dev/sdb
```

### 2. Создание таблицы разделов и разделов

#### Вариант А: Использование parted (Рекомендуется для автоматизации)
```bash
# Создание таблицы GPT
sudo parted /dev/sdb mklabel gpt

# Создание одного раздела на весь объем с выравниванием
sudo parted -a optimal /dev/sdb mkpart primary ext4 0% 100%
```

#### Вариант Б: Использование fdisk (Интерактивный режим)
```bash
sudo fdisk /dev/sdb
```
Последовательность команд внутри fdisk:
1.  `g` — создать новую пустую таблицу разделов GPT.
2.  `n` — добавить новый раздел (примите значения по умолчанию для номера, первого и последнего секторов).
3.  `w` — записать таблицу на диск и выйти.

### 3. Создание файловой системы (Форматирование)

После разметки появится новое блочное устройство `/dev/sdb1`.

```bash
# Для ext4 (универсальный выбор)
sudo mkfs.ext4 -L DATA_DRIVE /dev/sdb1

# Для XFS (оптимально для больших файлов)
sudo mkfs.xfs -L DATA_DRIVE /dev/sdb1
```

### 4. Настройка автоматического монтирования

#### Шаг 1: Получение UUID
Использование UUID (Universally Unique Identifier) вместо имен устройств (`/dev/sdb1`) предотвращает ошибки монтирования при изменении порядка дисков в системе.
```bash
lsblk -f /dev/sdb1
# → Скопируйте значение UUID (например: a1b2c3d4-e5f6...)
```

#### Шаг 2: Редактирование /etc/fstab
Создайте точку монтирования и добавьте запись:
```bash
sudo mkdir -p /mnt/data

# Рекомендуемая строка для ext4
echo 'UUID=ваш-uuid-тут /mnt/data ext4 defaults,noatime,nofail 0 2' | sudo tee -a /etc/fstab
```

#### Шаг 3: Применение изменений (Критично для systemd)
В современных дистрибутивах необходимо заставить systemd перечитать конфигурацию:
```bash
# 1. Обновление юнитов монтирования
sudo systemctl daemon-reload

# 2. Пробное монтирование всех ресурсов из fstab
sudo mount -a

# 3. Верификация корректности fstab
findmnt --verify --verbose
```
