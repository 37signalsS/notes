# Определения

**Перемонтирование (Remount)** — операция изменения параметров уже смонтированной файловой системы без её предварительного размонтирования (`umount`). 

Этот механизм позволяет ядру перенастроить драйвер файловой системы «на лету», сохраняя доступ к данным для запущенных процессов и открытых файловых дескрипторов.

# Основные концепции

## Назначение и преимущества

Главное преимущество перемонтирования — **непрерывность работы**. В отличие от цикла `umount` + `mount`, при `remount`:
- Процессы не получают ошибок `EBUSY`.
- Не требуется закрывать открытые файлы или останавливать сервисы.
- Сохраняется состояние кэша страниц (page cache) в оперативной памяти.

Это делает операцию единственным способом изменения параметров для **корневой файловой системы (`/`)** и других разделов, которые нельзя размонтировать в работающей системе.

## Синтаксис и правила использования

```bash
# Общий синтаксис
sudo mount -o remount,<новые_опции> <точка_монтирования | устройство>

# Пример для корневой ФС (переход в режим записи)
sudo mount -o remount,rw /
```

**Критическое правило:** При выполнении `remount` вы должны указывать **только те опции, которые хотите изменить**. Остальные параметры будут наследованы из текущего состояния монтирования (или из `/etc/fstab`, если точка монтирования там описана).

## Механика на уровне ядра

1.  **VFS Layer**: Ядро идентифицирует суперблок смонтированной ФС.
2.  **Safety Checks**: Проверяется возможность применения новых опций. Например, нельзя перейти в `ro`, если на ФС есть незакрытые файлы, открытые на запись (в некоторых случаях ядро может это заблокировать).
3.  **Driver Callback**: Вызывается специфичная для ФС функция (например, `ext4_remount`), которая обновляет внутренние структуры драйвера.

# Практические сценарии

## 1. Изменение режима доступа (ro/rw)

Самый частый сценарий при восстановлении системы или защите данных.

| Задача | Команда | Контекст |
| :--- | :--- | :--- |
| **Аварийный доступ** | `mount -o remount,rw /` | Редактирование конфигов в режиме восстановления |
| **Защита данных** | `sync && mount -o remount,ro /data` | Защита от записи перед работами с оборудованием |
| **Проверка ФС** | `mount -o remount,ro /home` | Перевод в `ro` для запуска `fsck` на живой системе |

> **Важно:** Всегда выполняйте команду `sync` перед перемонтированием в `ro`, чтобы гарантировать сброс всех буферов записи на диск.

## 2. Перемонтирование Bind Mounts

Для изменения прав доступа к "зеркальным" директориям требуется двухэтапный процесс или специфичный синтаксис.

```bash
# Создание bind mount (наследует права источника)
sudo mount --bind /source /target

# Изменение прав только для точки назначения (например, сделать ее RO)
sudo mount -o remount,bind,ro /target
```

## 3. Управление производительностью и SSD

Изменение параметров работы с накопителем без перезагрузки.

*   **TRIM (Discard):**
    ```bash
    # Включить онлайн-очистку (Continuous TRIM)
    sudo mount -o remount,discard /
    ```
*   **Время доступа (atime):**
    ```bash
    # Отключить обновление времени доступа для ускорения IO
    sudo mount -o remount,noatime /var/lib/mysql
    ```

## 4. Специфичные опции файловых систем

*   **ext4 (Журналирование):** Изменение интервала фиксации транзакций.
    ```bash
    sudo mount -o remount,commit=60 /data
    ```
*   **Btrfs (Сжатие):** Включение или изменение алгоритма сжатия на лету.
    ```bash
    sudo mount -o remount,compress=zstd:3 /mnt/btrfs
    ```

# Управление и диагностика

## Применение изменений из fstab

Если вы изменили опции в `/etc/fstab`, вы можете применить их без размонтирования:
```bash
sudo mount -o remount /точка/монтирования
```
Ядро перечитает строку из `fstab` для этой точки и применит изменения.

## Проверка результата

Для верификации примененных опций используйте `findmnt` (более надежно, чем `cat /proc/mounts`):
```bash
# Показать только опции для конкретной точки
findmnt -no OPTIONS /data

# Сравнить состояние до и после
mount | grep /data
```

# Ограничения

| Тип ограничения | Описание |
| :--- | :--- |
| **Структурные изменения** | Опции, меняющие формат данных (например, `block_size` или некоторые режимы `data=journal`), нельзя изменить через remount. |
| **Занятые ресурсы** | Переход `rw` -> `ro` может завершиться ошибкой `EBUSY`, если процессы удерживают дескрипторы на запись или есть неудаленные файлы (`deleted`). |
| **Сетевые задержки** | При перемонтировании NFS/CIFS возможны кратковременные подвисания процессов (I/O wait), пока ядро согласует параметры с сервером. |
