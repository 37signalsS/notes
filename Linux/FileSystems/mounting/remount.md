# Перемонтирование файловой системы (Remount)

## Определения

**Remount (перемонтирование)** — операция изменения параметров уже смонтированной файловой системы **без её размонтирования** (`umount`) и повторного монтирования. Выполняется командой `mount -o remount,<опции> <точка_монтирования>`.

## Основные концепции

### Зачем нужен remount

Ключевое преимущество remount — **не требует закрытия открытых файлов и завершения процессов**, работающих с файловой системой. Это критично для:

- **Корневой ФС (`/`)** — невозможно размонтировать, но можно перемонтировать.
- **Разделов с активными процессами** — БД, веб-серверы, логи.
- **Сетевых ФС (NFS/CIFS)** — без обрыва активных соединений.

### Синтаксис

```bash
# Общая форма
sudo mount -o remount,<опции> <точка_монтирования | устройство>

# Для корневой ФС
sudo mount -o remount,rw /
```

**Важно:** При remount указываются **только изменяемые опции**. Все неупомянутые опции сохраняют текущие значения.

### Как работает remount внутри ядра

1. Пользователь вызывает `mount -o remount,<options>`.
2. Ядро находит уже смонтированную ФС по точке монтирования или устройству.
3. Вызывается `reconfigure` супер-операции ФС (vfs-level).
4. Драйвер конкретной ФС применяет новые опции к уже работающему экземпляру.
5. Если опция не может быть применена «на лету» — ядро возвращает ошибку (`EINVAL` или `EBUSY`).

**Не все опции поддерживают remount.** Например, изменение `data=journal` на `data=ordered` для ext4 требует полного размонтирования.

## Практические сценарии

### 1. Переключение ro ↔ rw (самый частый сценарий)

**Режим только для чтения:**

```bash
# Перемонтировать в ro (безопасно при подозрении на повреждение ФС)
sudo mount -o remount,ro /mnt/data
```

**Режим чтения-записи:**

```bash
# Перемонтировать в rw
sudo mount -o remount,rw /mnt/data
```

**Когда применяется:**

| Сценарий | Команда |
| :--- | :--- |
| **Восстановление пароля** (single-user mode) | `mount -o remount,rw /` |
| **Защита от повреждения ФС** | `mount -o remount,ro /dev/sda1` |
| **Ремонт ФС (fsck)** | `mount -o remount,ro /` → `fsck` → `mount -o remount,rw /` |
| **Безопасность: блокировка записи в `/usr`** | `mount -o remount,ro /usr` |

### 2. Изменение режима журналирования

```bash
# ext4: переключение на writeback (максимальная производительность)
sudo mount -o remount,data=writeback /mnt/data

# ext4: возврат к ordered (по умолчанию)
sudo mount -o remount,data=ordered /mnt/data
```

> **Внимание:** Переключение между режимами journaling на лету возможно не для всех ФС. Проверьте `dmesg` после команды.

### 3. Включение/отключение discard (SSD/TRIM)

```bash
# Включить онлайн-TRIM (не рекомендуется для production — см. fstrim)
sudo mount -o remount,discard /

# Отключить online discard (рекомендуется)
sudo mount -o remount,nodiscard /
```

> **Рекомендация:** Используйте `nodiscard` + периодический `fstrim` (по крону или таймеру systemd). Подробности — в [Обслуживание SSD (fstrim)](../../SystemAdministration/fstrim_ssd_maintenance.md).

### 4. Включение ACL (Access Control Lists)

```bash
# Включить поддержку ACL без размонтирования
sudo mount -o remount,acl /home

# Проверить
mount | grep acl
```

### 5. Изменение commit-интервала (ext4)

```bash
# Увеличить интервал записи в журнал с 5 до 30 секунд
sudo mount -o remount,commit=30 /mnt/data
```

### 6. Экстренное перемонтирование всех ФС в ro

При подготовке к перезагрузке или при критической ошибке:

```bash
# Перемонтировать все ФС в режим только для чтения
sudo mount -o remount,ro -a
```

### 7. Перемонтирование после изменения fstab

После редактирования `/etc/fstab` новые опции не применяются автоматически. Нужно перемонтировать:

```bash
# Применить изменения из fstab для конкретной точки
sudo mount -o remount /mnt/data

# Или для всех записей fstab
sudo mount -a
```

### 8. NFS и CIFS: переподключение после обрыва сети

```bash
# NFS: принудительное переподключение
sudo mount -o remount,intr,timeo=600 /mnt/nfs

# CIFS: перемонтирование после восстановления сети
sudo mount -o remount /mnt/cifs
```

## Ограничения и подводные камни

| Ограничение | Описание | Решение |
| :--- | :--- | :--- |
| **Не все опции применимы** | `data=journal`, `block_size` требуют полного remount | Размонтировать → смонтировать заново |
| **Активные записи могут потеряться** | При переключении `ro` данные в Page Cache не сброшены | Сначала `sync`, затем `remount,ro` |
| **Конфликт с fstab** | Remount не меняет fstab — после перезагрузки вернутся старые опции | Обновите `/etc/fstab` одновременно |
| **Overlay/Union ФС** | Remount нижнего слоя не влияет на смонтированный overlay | Пересобрать overlay |
| **Контейнеры** | Remount в хосте может не отразиться в контейнере | Перезапустить контейнер или перемонтировать внутри |

## Диагностика

```bash
# Проверить текущие опции монтирования
mount | grep <точка>
findmnt -no OPTIONS <точка>

# Проверить, поддерживает ли ФС remount для конкретной опции
dmesg | tail -5   # после remount — ищите ошибки

# Посмотреть, какие опции изменились
findmnt -o TARGET,OPTIONS --target /mnt/data
```
