# Определения

**Remount (перемонтирование)** — операция изменения параметров уже смонтированной файловой системы **без её размонтирования** (`umount`) и повторного монтирования. Выполняется командой `mount -o remount,<опции> <точка_монтирования>`.

# Основные концепции

## Назначение remount

Ключевое преимущество remount — **не требует закрытия открытых файлов и завершения процессов**, работающих с файловой системой. Это критично для:

- **Корневой ФС (`/`)** — невозможно размонтировать в работающей системе, но можно перемонтировать.
- **Разделов с активными процессами** — базы данных, веб-серверы, системные логи.
- **Сетевых ФС (NFS/CIFS)** — позволяет изменить параметры без обрыва активных соединений.

## Синтаксис

```bash
# Общая форма
sudo mount -o remount,<опции> <точка_монтирования | устройство>

# Для корневой ФС
sudo mount -o remount,rw /
```

**Важно:** При remount указываются **только изменяемые опции**. Все неупомянутые опции сохраняют текущие значения.

## Механизм работы в ядре

1. Пользователь вызывает `mount -o remount,<options>`.
2. Ядро находит уже смонтированную ФС по точке монтирования или устройству.
3. Вызывается функция переконфигурации на уровне VFS (Virtual File System).
4. Драйвер конкретной ФС применяет новые опции к уже работающему экземпляру.
5. Если опция не может быть применена «на лету» — ядро возвращает ошибку (`EINVAL` или `EBUSY`).

Не все опции поддерживают remount. Например, изменение `data=journal` на `data=ordered` для ext4 требует полного размонтирования.

# Практические сценарии

## Переключение режимов ro и rw

**Режим только для чтения:**

```bash
sudo mount -o remount,ro /mnt/data
```

**Режим чтения-записи:**

```bash
sudo mount -o remount,rw /mnt/data
```

| Сценарий | Команда |
| :--- | :--- |
| **Восстановление пароля** (single-user mode) | `mount -o remount,rw /` |
| **Защита от повреждения ФС** | `mount -o remount,ro /dev/sda1` |
| **Ремонт ФС (fsck)** | `mount -o remount,ro /` → `fsck` → `mount -o remount,rw /` |
| **Безопасность: блокировка записи в `/usr`** | `mount -o remount,ro /usr` |

## Изменение режима журналирования

```bash
# ext4: переключение на writeback (максимальная производительность)
sudo mount -o remount,data=writeback /mnt/data

# ext4: возврат к ordered (по умолчанию)
sudo mount -o remount,data=ordered /mnt/data
```

> **Внимание:** Переключение между режимами journaling на лету возможно не для всех файловых систем. Проверьте вывод `dmesg` после выполнения команды.

## Управление TRIM (SSD)

```bash
# Включить онлайн-TRIM (не рекомендуется для высоконагруженных систем)
sudo mount -o remount,discard /

# Отключить online discard (рекомендуемый подход)
sudo mount -o remount,nodiscard /
```

Рекомендуется использовать `nodiscard` в сочетании с периодическим запуском `fstrim` (подробнее в [fstrim](../../SystemAdministration/fstrim_ssd_maintenance.md)).

## Включение ACL (Access Control Lists)

```bash
sudo mount -o remount,acl /home
mount | grep acl
```

## Изменение интервала фиксации данных (ext4)

```bash
sudo mount -o remount,commit=30 /mnt/data
```

## Экстренное перемонтирование всех ФС в режим ro

```bash
sudo mount -o remount,ro -a
```

## Применение изменений из fstab

```bash
# Применить изменения из fstab для конкретной точки
sudo mount -o remount /mnt/data

# Или для всех записей fstab
sudo mount -a
```

## Сетевые ФС: переподключение

```bash
# NFS: принудительное переподключение с изменением таймаута
sudo mount -o remount,intr,timeo=600 /mnt/nfs

# CIFS: перемонтирование после восстановления сетевого соединения
sudo mount -o remount /mnt/cifs
```

# Дополнительная информация

## Ограничения и особенности

| Ограничение | Описание | Решение |
| :--- | :--- | :--- |
| **Неприменимые опции** | Некоторые параметры (`block_size`, режимы журналирования) требуют полного пересоздания структуры в памяти | Размонтировать и смонтировать заново |
| **Риск потери данных** | При переключении в `ro` данные в Page Cache могут быть не сброшены | Сначала выполнить `sync`, затем `remount,ro` |
| **Синхронизация с fstab** | Remount не меняет файл конфигурации — после перезагрузки вернутся старые значения | Обновить `/etc/fstab` параллельно с выполнением команды |
| **Overlay/Union ФС** | Перемонтирование нижнего слоя не влияет на уже смонтированный overlay | Пересобрать структуру overlay |
| **Контейнеризация** | Изменения на хосте могут не отразиться внутри запущенного контейнера | Перезапустить контейнер или выполнить remount внутри него |

## Диагностика

```bash
# Проверить текущие опции монтирования
mount | grep <точка>
findmnt -no OPTIONS <точка>

# Проверить поддержку опции драйвером ФС
dmesg | tail -5

# Просмотр изменившихся параметров
findmnt -o TARGET,OPTIONS --target /mnt/data
```
