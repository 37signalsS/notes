# Определения

**`/etc/fstab`** (file systems table) — ключевой конфигурационный файл Linux, содержащий статический список файловых систем, монтируемых при загрузке. Процесс инициализации выполняет команду [`mount -a`](./commands.md#mount--a-монтирование-по-fstab) для подключения всех ресурсов из этого файла.

# Основные концепции

## Структура файла

Каждая строка в `/etc/fstab` описывает один ресурс и состоит из шести полей, разделенных пробелами или табами.

```text
<file system>    <mount point>    <type>    <options>    <dump>    <pass>
```

| Поле | Описание | Примеры |
|------|----------|---------|
| **1. Устройство (`<file system>`)** | Идентификатор устройства или ресурса. Рекомендуется использовать `UUID` для надежности. | `UUID=...`, `LABEL=...`, `/dev/sdb1` |
| **2. Точка монтирования (`<mount point>`)** | Существующий каталог, к которому подключается ресурс. | `/mnt/data`, `/home`, `/var/log` |
| **3. Тип ФС (`<type>`)** | Тип файловой системы. | `ext4`, `xfs`, `nfs`, `cifs`, `swap` |
| **4. Опции (`<options>`)** | Параметры монтирования, перечисленные через запятую. | `defaults`, `ro`, `noatime`, `nofail` |
| **5. Дамп (`<dump>`)** | Флаг для утилиты `dump` (резервное копирование). На практике почти всегда `0`. | `0` (отключено), `1` (включено) |
| **6. Проверка (`<pass>`)** | Порядок проверки файловой системы утилитой `fsck` при загрузке. | `0` (не проверять), `1` (корень), `2` (прочие) |

## Ключевые опции монтирования (`<options>`)

* `defaults`: Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
* `rw` / `ro`: Разрешить чтение и запись (`read-write`) или только чтение (`read-only`).
* `noatime`: Отключить обновление времени последнего доступа к файлам, что снижает количество операций записи и может повысить производительность.
* `nofail`: Не прерывать загрузку системы, если устройство недоступно. Критически важная опция для внешних дисков или сетевых ресурсов.
* `noauto`: Не монтировать файловую систему автоматически при выполнении `mount -a`.
* `user`: Разрешить обычным (не root) пользователям монтировать файловую систему.
* `nodev`: Запретить интерпретацию файлов устройств (character or block special devices).
* `nosuid`: Запретить выполнение SUID/SGID битов. Это важная мера безопасности, предотвращающая повышение привилегий через исполняемые файлы.
* `noexec`: Запретить прямой запуск исполняемых файлов на данной файловой системе.

### Опции systemd (x-systemd.*)

Помимо стандартных опций монтирования, в `/etc/fstab` можно использовать опции, интерпретируемые systemd:

* `x-systemd.automount`: Включает автомонтирование по требованию (аналог `.automount` юнита). Ресурс монтируется только при первом обращении к точке монтирования.
* `x-systemd.idle-timeout=<время>`: Время бездействия, после которого ресурс автоматически размонтируется. Формат: `30`, `1min`, `1h`.
* `x-systemd.device-timeout=<секунды>`: Время ожидания появления устройства. Важно: по умолчанию 90 сек. Для внешних дисков ставьте `5-10` сек.
* `x-systemd.mount-timeout=<секунды>`: Таймаут ожидания монтирования. `0` = бесконечное ожидание (для зашифрованных разделов).
* `x-systemd.requires=<юнит>`: Указывает зависимость от другого юнита (например, `x-systemd.requires=vdo.service` для VDO).
* `_netdev`: Указывает, что это сетевое устройство. Монтирование не начнется, пока не будет запущена сеть.

#### Рекомендации по комбинации опций

| Сценарий | Опции |
| :--- | :--- |
| **Внешний диск** | `nofail,x-systemd.device-timeout=5` |
| **NFS/CIFS шары** | `_netdev,x-systemd.automount,x-systemd.mount-timeout=30` |
| **Зашифрованный раздел** | `nofail,x-systemd.device-timeout=0` |
| **Ленивое монтирование** | `x-systemd.automount,x-systemd.idle-timeout=1min` |

### Применение опций для повышения безопасности

Разделение каталогов, таких как `/home`, `/var`, `/tmp`, на отдельные файловые системы с применением специальных опций монтирования является одной из базовых практик по укреплению безопасности системы.

* **Защита `/home`**:
  Если вынести `/home` на отдельный раздел, можно примонтировать его с опцией `noexec`. Это запретит прямой запуск любых исполняемых файлов из домашних директорий пользователей.

  ```
  UUID=...    /home    ext4    defaults,noexec,nosuid,nodev    0    2
  ```

* **Защита `/tmp` и `/var/tmp`**:
  Эти каталоги часто используются для хранения временных файлов, и их можно использовать для атак. Монтирование их с опциями `noexec,nosuid,nodev` значительно снижает риски.

* **Защита `/var/log`**:
  Рекомендуется выносить директорию `/var/log` на отдельную файловую систему. Это предотвращает ситуацию, когда заполнение логами приведет к исчерпанию места на корневой файловой системе.

* **Защита `/usr`**:
  После установки всего необходимого ПО раздел `/usr` можно временно перемонтировать в режим "только для чтения" (`ro`). Это усложнит злоумышленнику возможность модифицировать системные бинарные файлы.

# Практические сценарии

### 1. Поиск UUID устройства

Перед добавлением записи в `fstab` необходимо узнать `UUID` устройства:

```bash
# Показать UUID для всех блочных устройств
sudo blkid

# Или использовать lsblk
lsblk -f
```

### 2. Добавление записи в fstab

Откройте `/etc/fstab` с правами суперпользователя и добавьте новую строку в конец файла.

**Пример записи для дополнительного диска:**

```
UUID=a1b2c3d4-e5f6-7890    /mnt/backup    ext4    defaults,nofail    0    2
```

### 3. Проверка синтаксиса fstab (Безопасность)

Критически важно! После редактирования `/etc/fstab` и перед перезагрузкой всегда выполняйте проверку:

```bash
# Команда смонтирует все новые (еще не смонтированные) записи в fstab
sudo mount -a
```

Если команда завершилась без ошибок, синтаксис корректен.

### 4. Современная проверка с findmnt

```bash
# Подробная проверка с верификацией
findmnt --verify --verbose

# Показать все смонтированные ФС в дереве
findmnt --tree

# Проверить конкретную точку монтирования
findmnt /mnt/data
```

### 5. Рекомендации по идентификации устройств

| Метод | Рекомендация | Пример |
| :--- | :--- | :--- |
| **UUID=** | Предпочтительно для ФС | `UUID=a1b2c3d4-...` |
| **PARTUUID=** | Предпочтительно для GPT-разделов | `PARTUUID=12345678-01` |
| **LABEL=** | Допустимо, но менее надёжно | `LABEL=Data` |
| **/dev/sdX** | Не рекомендуется (неперсистентно) | `/dev/sdb1` |

### 6. Опции atime для производительности

| Опция | Поведение | Рекомендация |
| :--- | :--- | :--- |
| `relatime` | Обновление при изменении mtime/ctime или >24ч | По умолчанию (в `defaults`) |
| `noatime` | Полное отключение записи atime | Для серверов |
| `lazytime` | Запись в память, синк на диск реже | Kernel 4.0+ (комбинируется с `relatime`) |
| `strictatime` | Запись при каждом чтении | Только для специфичных случаев |

**Пример:**

```
UUID=...    /home    ext4    defaults,noatime    0    2
```

# Дополнительная информация

Поле `<pass>` напрямую влияет на работу утилиты `fsck` при загрузке системы.

Для более гибких сценариев монтирования (например, по требованию или на основе событий) рассмотрите использование [Systemd mount units](./scenarios/systemd_mount.md) или [Autofs](./scenarios/autofs_mount.md).

Общая информация о монтировании и доступных методах находится в [главном файле раздела](./index.md).
