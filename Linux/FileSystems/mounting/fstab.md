# Определения

**`/etc/fstab`** (file systems table) — ключевой конфигурационный файл Linux, содержащий статический список файловых систем, монтируемых при загрузке. Процесс инициализации выполняет команду [`mount -a`](./commands.md#mount--a-—-монтирование-по-fstab) для подключения всех ресурсов из этого файла.

> **Важно:** В современных системах с `systemd` записи в `fstab` преобразуются в нативные юниты монтирования с помощью `systemd-fstab-generator`. После каждого ручного редактирования `fstab` необходимо выполнять команду `sudo systemctl daemon-reload` для обновления конфигурации планировщика.

# Основные концепции

## Структура файла

Каждая строка в `/etc/fstab` описывает один ресурс и состоит из шести полей, разделенных пробелами или символами табуляции.

```text
<file system>    <mount point>    <type>    <options>    <dump>    <pass>
```

| Поле | Описание | Примеры |
| :--- | :--- | :--- |
| **1. Устройство (`<file system>`)** | Идентификатор устройства или ресурса. | `UUID=...`, `LABEL=...`, `/dev/sdb1`, `tmpfs` |
| **2. Точка монтирования (`<mount point>`)** | Каталог, к которому подключается ресурс. | `/mnt/data`, `/home`, `none` (для swap) |
| **3. Тип ФС (`<type>`)** | Тип файловой системы. | `ext4`, `xfs`, `btrfs`, `tmpfs`, `swap`, `nfs`, `cifs` |
| **4. Опции (`<options>`)** | Параметры монтирования через запятую. | `defaults`, `ro`, `noatime`, `nofail`, `_netdev` |
| **5. Дамп (`<dump>`)** | Флаг для утилиты `dump` (бэкап). Почти всегда `0`. | `0` (отключено), `1` (включено) |
| **6. Проверка (`<pass>`)** | Порядок проверки `fsck` при загрузке. | `0` (не проверять), `1` (корень), `2` (прочие) |

## Ключевые опции монтирования

* `defaults`: Стандартный набор (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
* `rw` / `ro`: Режим чтения-записи или "только чтение".
* `noatime`: Отключение обновления времени последнего доступа. Повышает производительность и снижает износ SSD.
* `nofail`: Система продолжит загрузку, даже если устройство недоступно (важно для внешних и сетевых дисков).
* `noauto`: Не монтировать автоматически при загрузке или по команде `mount -a`.
* `user`: Позволяет обычным пользователям монтировать ФС (автоматически включает `noexec`, `nosuid`, `nodev`).
* `nodev`: Запрет на использование файлов специальных устройств.
* `nosuid`: Запрет на работу SUID/SGID битов (защита от повышения привилегий).
* `noexec`: Запрет на запуск исполняемых файлов.

### Опции systemd (x-systemd.*)

Systemd расширяет возможности `fstab` специфичными параметрами:

* `x-systemd.automount`: Автомонтирование при первом обращении к директории.
* `x-systemd.idle-timeout=<время>`: Автоматическое размонтирование после периода бездействия (например, `5min`).
* `x-systemd.device-timeout=<секунды>`: Время ожидания появления устройства в системе (по умолчанию 90с).
* `x-systemd.mount-timeout=<секунды>`: Таймаут на саму операцию монтирования.
* `_netdev`: Критически важная опция для сетевых ФС; откладывает монтирование до инициализации сети.

#### Рекомендации по комбинации опций

| Сценарий | Опции |
| :--- | :--- |
| **Внешний USB-диск** | `defaults,nofail,x-systemd.device-timeout=5` |
| **Сетевые ресурсы (NFS/SMB)** | `_netdev,x-systemd.automount,x-systemd.mount-timeout=30` |
| **Временная папка в RAM** | `tmpfs /tmp tmpfs defaults,size=2G,mode=1777 0 0` |
| **Оптимизация SSD** | `defaults,noatime,discard` (или использование `fstrim.timer`) |

### Безопасное разделение ресурсов

Рекомендуется выносить критические пути на отдельные разделы с ограничивающими опциями:

* **`/home`**: `defaults,nosuid,nodev` — защита от создания устройств и SUID-файлов пользователями.
* **`/tmp` и `/var/tmp`**: `defaults,nosuid,nodev,noexec` — полная изоляция временных файлов.
* **`/var/log`**: Отдельный раздел предотвращает отказ системы при переполнении диска логами.
* **`/boot`**: Можно монтировать в `ro` после загрузки для защиты ядра.

# Практические сценарии

### 1. Получение идентификаторов (UUID)

```bash
# Рекомендуемый способ (показывает UUID и тип ФС)
lsblk -f

# Альтернатива для всех блочных устройств
sudo blkid
```

### 2. Добавление новой записи

1. Создайте резервную копию: `sudo cp /etc/fstab /etc/fstab.bak`
2. Добавьте запись (пример для раздела под бэкапы):
```text
UUID=a1b2c3d4-e5f6-7890    /mnt/backup    ext4    defaults,nofail    0    2
```

### 3. Применение и проверка (Алгоритм)

**Никогда не перезагружайтесь сразу после редактирования fstab!**

1. Перечитайте конфигурацию systemd:
   ```bash
   sudo systemctl daemon-reload
   ```
2. Проверьте синтаксис и попробуйте смонтировать:
   ```bash
   sudo mount -a
   ```
3. Проверьте наличие ошибок:
   ```bash
   findmnt --verify --verbose
   ```

### 4. Рекомендации по выбору идентификатора

| Тип | Надежность | Применение |
| :--- | :--- | :--- |
| **UUID** | Высокая | Основной метод для всех ФС |
| **PARTUUID** | Высокая | Для GPT-разделов без файловой системы |
| **LABEL** | Средняя | Удобно для переносных накопителей |
| **/dev/sdX** | Низкая | Только для временных тестов (пути могут меняться) |

### 5. Управление временем доступа (atime)

| Параметр | Описание | Приоритет |
| :--- | :--- | :--- |
| `relatime` | Обновление только при изменении файла или раз в сутки | По умолчанию (оптимально) |
| `noatime` | Полное отключение обновлений времени доступа | Для БД и высоконагруженных серверов |
| `lazytime` | Запись изменений на диск с задержкой | Для современных ядер (экономия IO) |

# Дополнительная информация

* **Поле `<pass>`**: Корень (`/`) всегда `1`, остальные локальные диски — `2`, сетевые ресурсы и swap — `0`.
* **Systemd Mount Units**: Для сложных графов зависимостей (например, монтирование только после запуска БД) используйте [нативные юниты монтирования](./scenarios/systemd_mount.md).
* **Диагностика**: Если система загрузилась в `Emergency Mode` из-за ошибки в fstab, используйте `mount -o remount,rw /` для исправления файла.

Подробный разбор команд монтирования доступен в [соседнем разделе](./commands.md).
