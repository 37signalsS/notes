# Определения

**`/etc/fstab`** (file systems table) — это ключевой конфигурационный файл в Linux, который содержит статический список файловых систем, монтируемых операционной системой при загрузке. Процесс инициализации системы выполняет команду [`mount -a`](./commands.md#mount--a-монтирование-по-fstab), чтобы подключить все перечисленные в этом файле ресурсы.

# Основные концепции

## Структура файла

Каждая строка в `/etc/fstab` описывает один ресурс и состоит из шести полей, разделенных пробелами или табами.

```text
<file system>    <mount point>    <type>    <options>    <dump>    <pass>
```

| Поле | Описание | Примеры |
|------|----------|---------|
| **1. Устройство (`<file system>`)** | Идентификатор устройства или ресурса. **Рекомендуется использовать `UUID`** для надежности. | `UUID=...`, `LABEL=...`, `/dev/sdb1` |
| **2. Точка монтирования (`<mount point>`)** | Существующий каталог, к которому подключается ресурс. | `/mnt/data`, `/home`, `/var/log` |
| **3. Тип ФС (`<type>`)** | Тип файловой системы. | `ext4`, `xfs`, `nfs`, `cifs`, `swap` |
| **4. Опции (`<options>`)** | Параметры монтирования, перечисленные через запятую. | `defaults`, `ro`, `noatime`, `nofail` |
| **5. Дамп (`<dump>`)** | Флаг для утилиты `dump` (резервное копирование). На практике почти всегда `0`. | `0` (отключено), `1` (включено) |
| **6. Проверка (`<pass>`)** | Порядок проверки файловой системы утилитой `fsck` при загрузке. | `0` (не проверять), `1` (корень), `2` (прочие) |

## Ключевые опции монтирования (`<options>`)

* `defaults`: Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
* `rw` / `ro`: Разрешить чтение и запись (`read-write`) или только чтение (`read-only`).
* `noatime`: Отключить обновление времени последнего доступа к файлам, что снижает количество операций записи и может повысить производительность.
* `nofail`: Не прерывать загрузку системы, если устройство недоступно. Критически важная опция для внешних дисков или сетевых ресурсов.
* `noauto`: Не монтировать файловую систему автоматически при выполнении `mount -a`.
* `user`: Разрешить обычным (не root) пользователям монтировать файловую систему.
* `nodev`: Запретить интерпретацию файлов устройств (character or block special devices).
* `nosuid`: Запретить выполнение SUID/SGID битов. Это важная мера безопасности, предотвращающая повышение привилегий через исполняемые файлы.
* `noexec`: Запретить прямой запуск исполняемых файлов на данной файловой системе.

### Применение опций для повышения безопасности

Разделение каталогов, таких как `/home`, `/var`, `/tmp`, на отдельные файловые системы с применением специальных опций монтирования является одной из базовых практик по укреплению безопасности системы.

* **Защита `/home`**:
  Если вынести `/home` на отдельный раздел, можно примонтировать его с опцией `noexec`. Это запретит прямой запуск любых исполняемых файлов из домашних директорий пользователей. Если злоумышленник или вредоносная программа загрузит скрипт или бинарный файл в `/home/user`, запустить его напрямую не получится.
  ```
  UUID=...    /home    ext4    defaults,noexec,nosuid,nodev    0    2
  ```

* **Защита `/tmp` и `/var/tmp`**:
  Эти каталоги часто используются для хранения временных файлов, и их можно использовать для атак. Монтирование их с опциями `noexec,nosuid,nodev` значительно снижает риски.

* **Защита `/usr`**:
  После установки всего необходимого ПО, раздел `/usr`, где хранятся исполняемые файлы программ, можно временно перемонтировать в режим "только для чтения" (`ro`). Это усложнит злоумышленнику возможность модифицировать системные бинарные файлы для внедрения вредоносного кода. Перед обновлением системы права возвращаются на `rw`.


# Практические сценарии

### 1. Поиск UUID устройства

Перед добавлением записи в `fstab` необходимо узнать `UUID` устройства. Это можно сделать несколькими способами:

```bash
# Показать UUID для всех блочных устройств
sudo blkid

# Или использовать lsblk
lsblk -f
```

### 2. Добавление записи в fstab

Откройте `/etc/fstab` с правами суперпользователя и добавьте новую строку в конец файла.

**Пример записи для дополнительного диска:**

```
UUID=a1b2c3d4-e5f6-7890    /mnt/backup    ext4    defaults,nofail    0    2
```

### 3. Проверка синтаксиса fstab (Безопасность)

**Критически важно!** После редактирования `/etc/fstab` и перед перезагрузкой всегда выполняйте проверку. Это поможет избежать ситуации, когда система не сможет загрузиться из-за синтаксической ошибки.

```bash
# Команда смонтирует все новые (еще не смонтированные) записи в fstab
sudo mount -a
```

Если команда завершилась без ошибок, синтаксис корректен.
