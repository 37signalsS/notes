# Определения

**`/etc/fstab`** (file systems table) — основной конфигурационный файл в Linux-системах, содержащий информацию о файловых системах и устройствах хранения, которые должны монтироваться автоматически при загрузке системы или по команде.

Процесс инициализации использует этот файл для определения того, какие разделы диска, сетевые ресурсы или виртуальные файловые системы должны быть подключены и с какими параметрами.

> **Важно:** В системах с `systemd` содержимое `/etc/fstab` обрабатывается утилитой `systemd-fstab-generator`, которая динамически создает нативные юниты монтирования (`.mount`) в директории `/run/systemd/generator/`. После любого изменения файла необходимо выполнить команду `sudo systemctl daemon-reload`.

# Основные концепции

## Роль fstab в процессе загрузки

При загрузке системы `systemd` использует `systemd-fstab-generator` для чтения `/etc/fstab` и динамического создания временных `.mount` юнитов в директории `/run/systemd/generator/`. Эти юниты обрабатываются как обычные systemd-юниты с зависимостями и приоритетами.

**Порядок чтения fstab:**
1. **initramfs (ранняя загрузка):** В ранней стадии загрузки `initramfs` читает fstab для монтирования корневой ФС и необходимых разделов.
2. **systemd-fstab-generator:** После перехода на основную ФС генератор создает `.mount` юниты.
3. **systemd:** Юниты обрабатываются с учетом зависимостей (например, `network-online.target` для сетевых ФС).

**Важно:** Изменения в fstab применяются только после `systemctl daemon-reload`, который перезапускает генератор.

## Структура файла

Каждая строка в `/etc/fstab` описывает одну файловую систему и состоит из шести полей, разделенных пробелами или табуляцией.

```text
<file system>    <mount point>    <type>    <options>    <dump>    <pass>
```

| Поле | Описание | Примеры |
| :--- | :--- | :--- |
| **1. Устройство (`<file system>`)** | Идентификатор ресурса (UUID, LABEL, путь к устройству). | `UUID=550e8400-e29b...`, `/dev/mapper/vg0-root`, `server:/share` |
| **2. Точка монтирования (`<mount point>`)** | Каталог, в который будет смонтирована ФС. | `/`, `/home`, `/mnt/data`, `none` (для swap) |
| **3. Тип ФС (`<type>`)** | Тип файловой системы. | `ext4`, `xfs`, `btrfs`, `nfs4`, `cifs`, `swap`, `tmpfs` |
| **4. Опции (`<options>`)** | Параметры монтирования через запятую. | `defaults`, `noatime`, `ro`, `nofail`, `_netdev` |
| **5. Дамп (`<dump>`)** | Используется утилитой `dump` для бэкапа. | `0` (игнорировать), `1` (создавать дамп) |
| **6. Проверка (`<pass>`)** | Порядок проверки `fsck` при загрузке. | `0` (не проверять), `1` (корень), `2` (остальные) |

## Синтаксические особенности

**Комментарии:** Строки, начинающиеся с `#`, игнорируются. Используйте комментарии для документирования изменений и временного отключения записей.

**Пустые строки:** Игнорируются. Можно использовать для визуального разделения групп записей.

**Пробелы и табуляции:** Поля разделяются любым количеством пробелов или табуляций. Начальные и конечные пробелы в полях игнорируются.

**Специальные значения:**
- `none` — используется для `swap` и `tmpfs`, когда точное имя устройства не критично.
- `default` / `defaults` — набор стандартных опций (аналог `rw,suid,dev,exec,auto,nouser,async`).

**Экранирование:** Пробелы в путях (например, точки монтирования) не поддерживаются напрямую. Используйте обратный слэш или избегайте пробелов в именах каталогов.

## Приоритет опций

При конфликте опций применяется следующий порядок:
1. **Опции из командной строки** (`mount -o`) — наивысший приоритет.
2. **Опции из `/etc/fstab`** — применяются, если не указаны в командной строке.
3. **Опции по умолчанию** — используются при отсутствии явных указаний.

Для `remount` указывайте **только изменяемые опции**. Остальные наследуются из текущего состояния монтирования или fstab.

## Файл /etc/mtab

На современных системах `/etc/mtab` является символической ссылкой на `/proc/mounts` или `/proc/self/mountinfo`. Это означает, что текущее состояние монтирования отражает ядро, а не fstab.

**Различия:**
- **fstab** — статическая конфигурация для автозагрузки.
- **mtab / proc/mounts** — динамическое состояние текущих монтирований (включая временные).

## fstab и initramfs

В ранней стадии загрузки (до перехода на основную ФС) `initramfs` использует fstab для:
1. Монтирования корневой ФС (обычно через `root=` в cmdline).
2. Монтирования разделов, необходимых для доступа к корню (например, `/boot` на отдельном разделе).
3. Инициализации LVM, RAID или LUKS перед монтированием корня.

Если fstab поврежден, система может не перейти в основную ФС, что приведет к Emergency Mode.

## Идентификация устройств

Использование имен устройств (например, `/dev/sda1`) считается плохой практикой, так как они могут измениться при смене конфигурации оборудования.

1.  **UUID (Universally Unique Identifier):** Самый надежный метод. Привязан к файловой системе.
    *   Пример: `UUID=b312a45c-e23f-4e56-9d31-64d728a45c12`
2.  **LABEL:** Удобно для переносимых дисков.
    *   Пример: `LABEL=BackupDrive`
3.  **PARTUUID/PARTLABEL:** Идентификаторы разделов GPT (не зависят от содержимого ФС).
     *   Пример: `PARTUUID=e29b-4e56-9d31`
     *   **Важно:** PARTUUID привязан к записи раздела в таблице разделов, а не к ФС. Подробнее — в [UUID vs PARTUUID](../partitions_and_filesystems.md#UUID-vs-PARTUUID-ключевое-различие).
4.  **LVM Path:** Для логических томов.
    *   Пример: `/dev/mapper/vg_system-lv_root`

## Ключевые опции монтирования

### Общие опции
* `defaults`: Эквивалент набора `rw, suid, dev, exec, auto, nouser, async`.
* `rw` / `ro`: Доступ на чтение-запись или только чтение.
* `noatime` / `relatime`: Отключение или ограничение обновления времени последнего доступа (atime). `noatime` существенно снижает нагрузку на I/O, особенно на SSD.
* `nofail`: Система не прерывает загрузку и не уходит в Emergency Mode, если устройство отсутствует.
* `noexec`: Запрет выполнения бинарных файлов на разделе (полезно для `/tmp` или `/home`).
* `nosuid`: Игнорирование битов SUID/SGID (повышение безопасности).
* `_netdev`: Указывает, что ФС требует наличия сети. Предотвращает попытки монтирования сетевых ресурсов до инициализации сетевых интерфейсов.

### Опции для конкретных ФС
* **Btrfs:** `subvol=@home` (монтирование конкретного подтома), `compress=zstd` (сжатие на лету), `compress-force=zstd` (принудительное сжатие), `nodatacow` (отключение COW для данных).
* **XFS:** `nobarrier` (отключение барьеров для производительности, опасно при сбоях питания), `logbufs=8` (увеличение буферов логов), `allocsize=64k` (размер выделяемых блоков).
* **ext4:** `data=ordered` (порядок записи данных), `data=writeback` (отслеживание только метаданных), `commit=60` (интервал синхронизации), `barrier=0` (отключение барьеров).
* **NFS:** `hard`/`soft` (поведение при обрыве связи), `timeo=600` (таймаут в десятых долях секунды), `retrans=3` (количество повторов), `nconnect=8` (параллельные TCP-соединения), `vers=4.2` (версия протокола), `sec=krb5` (аутентификация Kerberos).
* **CIFS (Samba):** `credentials=/path/to/file` (путь к файлу с логином/паролем), `uid=1000,gid=1000` (назначение владельца всех файлов), `vers=3.0` (версия протокола), `sec=ntlmssp` (механизм аутентификации), `noperm` (отключение проверки прав Linux).
* **Tmpfs:** `size=2G` (ограничение размера в RAM), `nr_nodes=1000` (ограничение количества inode).
* **NFS v4:** `nordirplus` (отключение предзагрузки директорий), `noacl` (отключение ACL).
* **iSCSI:** `_netdev` (требует сети), `nofail` (не прерывать загрузку), `nodefs.iscsi` (монтирование iSCSI-устройства).

### Опции systemd (x-systemd.*)
Systemd добавляет расширенные функции управления монтированием. Эти опции позволяют создавать нативные `.mount` и `.automount` юниты непосредственно из fstab через `systemd-fstab-generator`.

| Опция | Назначение | Рекомендация |
| :--- | :--- | :--- |
| `x-systemd.automount` | Ленивое монтирование — ФС подключается при первом обращении к каталогу | Используйте для сетевых ресурсов (NFS/CIFS) вместо `autofs` в простых сценариях |
| `x-systemd.idle-timeout=N` | Автоматическое размонтирование через N секунд неактивности | `300`–`600` для домашних каталогов; `60`–`120` для временных шаров |
| `x-systemd.device-timeout=N` | Время ожидания появления устройства (секунды) | `10s`–`30s` для внешних дисков; не использовать для критичных разделов — приведёт к зависанию загрузки |
| `x-systemd.requires=service.service` | Монтирование только после запуска указанного сервиса | Используйте для ресурсов, зависящих от сети (`NetworkManager-wait-online.service`) или LUKS (`systemd-cryptsetup@*.service`) |
| `x-systemd.after=service.service` | Гарантия порядка запуска (аналог `After=` в юнитах) | Обязательно для NFS/CIFS: `x-systemd.after=network-online.target` |
| `x-systemd.wants=service.service` | Мягкая зависимость — запускает сервис, но не прерывает загрузку при его отсутствии | `x-systemd.wants=network-online.target` для сетевых ФС |
| `x-systemd.mount-timeout=N` | Таймаут самой операции монтирования (секунды) | `60` для медленных NFS/CIFS; по умолчанию 90 |
| `x-systemd.make-mount目录` | Автоматическое создание точки монтирования | Полезно для динамических путей |

**Важно:** Опции `x-systemd.requires` и `x-systemd.after` задают **жёсткие зависимости**. Если указанный сервис не запустится, монтирование не произойдёт, и система может перейти в Emergency Mode. Используйте `x-systemd.wants` для мягких зависимостей.

### Опции производительности и целостности данных

Эти опции критичны для production-серверов и являются частым предметом собеседований.

| Опция | Эффект | Рекомендация |
| :--- | :--- | :--- |
| `noatime` | Полностью отключает обновление времени последнего доступа (atime). Снижает количество записей на 30–50% | **Обязательно** для SSD, баз данных и интенсивных I/O-нагрузок |
| `relatime` | Обновляет atime только если текущее время больше времени модификации (mtime) или изменения (ctime). Стандарт по умолчанию с ядра 2.6.30 | Безопасная альтернатива `noatime` для систем с зависимостью от atime |
| `lazytime` | Откладывает запись atime/ctime/mtime в память и сбрасывает при других метаданных обновлениях (ядро 4.0+) | Хороший баланс между производительностью и совместимостью |
| `commit=N` | Интервал синхронизации журнала ext4 (по умолчанию 5 секунд). Увеличение снижает I/O | `commit=30`–`60` для логов и временных данных; **не** для критичных БД |
| `data=ordered` | В журнал пишутся метаданные, данные сбрасываются до фиксации (по умолчанию ext4) | Стандарт для большинства сценариев |
| `data=writeback` | Журналируются только метаданные, порядок записи данных не гарантируется | **Опасно** при сбоях питания; допустимо для временных данных или БД с WAL |
| `barrier=1` | Включает write barriers — гарантирует сброс кэша диска перед фиксацией транзакции | **Включено по умолчанию**. Отключайте только при наличии BBU (Battery Backup Unit) |
| `nobarrier` | Отключает write barriers | **Опасно** без BBU — возможна потеря данных при аварийном отключении питания |
| `discard` | Онлайн-TRIM — немедленное информирование SSD о неиспользуемых блоках | Рекомендуется для SSD с низким использованием; для высоконагруженных — `fstrim` |
| `discard=async` | Асинхронный TRIM (ядро 5.6+, Btrfs) | Снижает латентность записи по сравнению с синхронным `discard` |

# Практические сценарии

### 1. Подготовка и добавление нового диска

Перед редактированием всегда определяйте UUID:
```bash
lsblk -f /dev/sdb1
# → NAME FSTYPE LABEL UUID                                 MOUNTPOINTS
# → sdb1 ext4   Data  a1b2c3d4-e5f6-7890-abcd-ef1234567890 
```

Добавление записи в `/etc/fstab`:
```text
UUID=a1b2c3d4-e5f6-7890-abcd-ef1234567890    /mnt/data    ext4    defaults,noatime,nofail    0    2
```

### 2. Монтирование сетевого ресурса NFS

С использованием автоматизации systemd для надежности:
```text
192.168.1.10:/srv/nfs    /mnt/nfs    nfs4    _netdev,x-systemd.automount,x-systemd.idle-timeout=5min,nofail    0    0
```

### 3. Настройка Swap-файла

Если используется файл вместо раздела подкачки:
```text
/swapfile    none    swap    defaults    0    0
```

Для SSD рекомендуется добавить `discard` для автоматического TRIM:
```text
/swapfile    none    swap    sw,discard    0    0
```

### 4. Монтирование Btrfs с подтомами и сжатием

```text
UUID=...    /          btrfs    defaults,subvol=@root,compress=zstd    0    0
UUID=...    /home      btrfs    defaults,subvol=@home,compress=zstd    0    0
```

### 5. Создание Bind Mount (проброс директории)

Позволяет сделать одну директорию доступной по другому пути:
```text
/var/www/html    /home/user/website    none    bind    0    0
```

### 6. Монтирование XFS с оптимизацией

```text
UUID=...    /data    xfs    defaults,noatime,nobarrier,logbufs=8    0    2
```

### 7. Монтирование LVM-тома

```text
/dev/mapper/vg_data-lv_db    /mnt/db    ext4    defaults,noatime    0    2
```

### 8. Монтирование зашифрованного раздела (LUKS)

```text
UUID=...    /mnt/encrypted    ext4    defaults,noatime    0    2
```
Примечание:LUKS-разделы требуют ввода пароля при монтировании. Для автоматизации используйте keyfile.

### 9. Монтирование iSCSI-диска

```text
UUID=...    /mnt/iscsi    ext4    defaults,_netdev,nofail    0    2
```

### 10. Монтирование multipath-диска

```text
/dev/mapper/mpatha1    /mnt/data    ext4    defaults,_netdev,nofail    0    2
```

### 11. Монтирование NFS с Kerberos

```text
192.168.1.10:/srv/nfs    /mnt/nfs    nfs4    _netdev,sec=krb5,x-systemd.automount    0    0
```

### 12. Монтирование CIFS с файлом учетных данных

```text
//server/share    /mnt/smb    cifs    credentials=/etc/samba/creds,uid=1000,gid=1000,vers=3.0    0    0
```

### 13. Монтирование tmpfs с ограничениями

```text
tmpfs    /tmp    tmpfs    defaults,size=2G,noexec,nosuid,nodev    0    0
```

### 14. Монтирование DevPTS

```text
devpts    /dev/pts    devpts    defaults,gid=5,mode=620    0    0
```

### 15. Комплексный fstab для production-сервера

Типичный `/etc/fstab` production-сервера с LVM, шифрованием, сетевыми ресурсами и tmpfs для временных данных:

```text
# === КОРНЕВОЙ РАЗДЕЛ (LVM + LUKS) ===
# Шифрованный корень: Disk → LUKS → PV → VG → LV → ext4
UUID=c3d4e5f6-...    /    ext4    defaults,noatime,errors=remount-ro    0    1

# === ОБЯЗАТЕЛЬНЫЕ СИСТЕМНЫЕ РАЗДЕЛЫ ===
# /boot — отдельный раздел (BIOS/UEFI)
UUID=a1b2c3d4-...    /boot    ext4    defaults,noatime    0    2

# /boot/efi — EFI System Partition (UEFI)
UUID=B1C2-D3E4    /boot/efi    vfat    defaults,noatime    0    2

# === LVM-ТОМЫ ДАННЫХ ===
/dev/mapper/vg_system-lv_var        /var        xfs    defaults,noatime,nosuid,nodev    0    2
/dev/mapper/vg_system-lv_home       /home       ext4   defaults,noatime,nosuid,nodev    0    2
/dev/mapper/vg_data-lv_database     /var/lib/postgresql  xfs  defaults,noatime,nobarrier  0    2
/dev/mapper/vg_data-lv_docker       /var/lib/docker      xfs  defaults,noatime            0    2

# === ВРЕМЕННЫЕ ФС ===
tmpfs    /tmp        tmpfs    defaults,size=2G,noexec,nosuid,nodev    0    0
tmpfs    /dev/shm    tmpfs    defaults,size=4G,noexec,nosuid,nodev    0    0
tmpfs    /run        tmpfs    defaults,size=1G,noexec,nosuid,nodev    0    0

# === SWAP ===
/dev/mapper/vg_system-lv_swap    none    swap    sw,discard    0    0

# === СЕТЕВЫЕ РЕСУРСЫ (NFS) ===
# Ленивое монтирование с таймаутом и зависимостью от сети
nas01:/exports/logs          /mnt/nfs_logs    nfs4    _netdev,soft,timeo=50,retrans=3,nconnect=8,x-systemd.automount,x-systemd.idle-timeout=300,x-systemd.after=network-online.target,x-systemd.device-timeout=30s    0    0

# === СЕТЕВЫЕ РЕСУРСЫ (CIFS/SMB) ===
//fileserver/backups    /mnt/smb_backups    cifs    credentials=/etc/samba/creds,uid=1000,gid=1000,vers=3.1.1,sec=ntlmssp,_netdev,nofail    0    0

# === MULTIPATH (SAN/iSCSI) ===
/dev/mapper/mpatha1    /mnt/san_data    ext4    defaults,_netdev,nofail,nosuid,nodev    0    2

# === BIND MOUNT ===
/data/nginx/html    /var/www/html    none    bind,ro    0    0
```

**Пояснения к критичным опциям:**
- `errors=remount-ro` — корневой раздел переходит в read-only при ошибках ФС (защита от порчи данных)
- `nobarrier` для PostgreSQL — безопасно только при наличии BBU на RAID-контроллере; ускоряет запись
- `nconnect=8` для NFS — параллельные TCP-соединения для балансировки нагрузки (требует ядро 5.3+)
- `x-systemd.device-timeout=30s` — не даёт системе зависнуть при недоступности NFS-сервера при загрузке
- `vers=3.1.1` для CIFS — текущий безопасный стандарт (ACES-256-GCM шифрование)

### 16. fstab для production-сервера с высокой доступностью (HA)

```text
# === КОРНЕВОЙ РАЗДЕЛ (RAID1 + LVM) ===
/dev/mapper/vg_root-lv_root    /    ext4    defaults,noatime,errors=remount-ro    0    1

# === NFS через Keepalived (VIP) ===
# Монтирование на VIP — при failover Keepalived переключает VIP и монтирует ресурс
nfs-vip.internal:/data    /mnt/nfs_data    nfs4    _netdev,hard,timeo=600,retrans=2,nconnect=4,actimeo=60    0    0
# Не используем automount для критичных данных — монтируем всегда
# Не используем soft — данные важнее Availability

# === CIFS через CTDB (кластер Samba) ===
//ctdb-vip/shared    /mnt/smb_shared    cifs    credentials=/etc/samba/creds,vers=3.1.1,sec=krb5,multiuser,nofail    0    0
# multiuser — позволяет другим пользователям обращаться к смонтированной шаре
```

**Отличия HA-конфигурации:**
- `hard` вместо `soft` для NFS — процессы блокируются вместо потери данных
- `actimeo=60` — кэш атрибутов обновляется раз в минуту (баланс между нагрузкой на сервер и актуальностью)
- `sec=krb5` для CIFS — Kerberos-аутентификация вместо NTLMv2
- `multiuser` — поддержка нескольких UID при монтировании CIFS

## Безопасная проверка конфигурации

**Никогда не перезагружайтесь сразу после внесения изменений!** Ошибка в `fstab` может привести к сбою загрузки (Emergency Mode).

### Проверка через `mount -a`

Команда `mount -a` (строго строчный флаг `-a`) заставляет утилиту прочитать `/etc/fstab` сверху вниз и попытаться примонтировать все диски, которые там описаны, но ещё не подключены к системе.

**Важно:** Для чтения и монтирования всей таблицы дисков из fstab служит только короткий одиночный флаг `-a` в нижнем регистре. Длинная форма `--all` не используется для этой операции.

Если в файле есть хоть одна опечатка UUID, неверный тип ФС или синтаксическая ошибка, команда `mount -a` немедленно выведет предупреждение. Если команда отработала в полной тишине, значит конфиг чист и сервер можно перезапускать без страха.

После успешного `mount -a` современный systemd может выдать подсказку с просьбой обновить конфигурацию. В этом случае выполните:

```bash
sudo systemctl daemon-reload
```

### Алгоритм проверки

1.  **Синтаксическая проверка:**
    ```bash
    findmnt --verify
    # → Success: no errors or warnings detected
    ```
2.  **Применение конфигурации:**
    ```bash
    sudo systemctl daemon-reload
    sudo mount -a
    ```
    Если команда `mount -a` не вывела ошибок, значит записи корректны.
3.  **Проверка результата:**
    ```bash
    df -hT /mnt/data
    ```

## Диагностика и восстановление

*   **Emergency Mode:** Если система не загружается, введите пароль root и перемонтируйте корень в режим записи:
    ```bash
    mount -o remount,rw /
    ```
    После этого исправьте `/etc/fstab` с помощью `vi` или `nano`.
*   **Просмотр текущих монтирований:**
    ```bash
    findmnt
    # → Отображает дерево всех смонтированных систем и их параметры из fstab/mtab.
    ```
*   **Диагностика загрузки:**
    ```bash
    systemd-analyze plot > boot.svg
    # → Визуализация временной шкалы загрузки с указанием зависимостей mount-юнитов
    ```
*   **Проверка юнитов fstab:**
    ```bash
    systemctl list-units --type=mount
    # → Показывает все смонтированные точки, включая созданные из fstab
    ```

## Типичные ошибки и решения

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| **`mount: can't find in /etc/fstab`** | Неверный UUID, LABEL или путь | Проверьте `blkid` или `lsblk -f` |
| **`mount: wrong fs type, bad option`** | Неверный тип ФС или несовместимые опции | Установите необходимый пакет (nfs-utils, cifs-utils) |
| **`Mount denied: CIFS`** | Неверные учетные данные или версия протокола | Проверьте файл credentials и версию SMB |
| **System boots to emergency mode** | Ошибка в fstab (неверный UUID, отсутствует раздел) | Войдите в root, исправьте fstab, выполните `mount -a` |
| **NFS mount hangs** | Проблемы с сетью или сервер недоступен | Используйте `soft,timeo=50,retrans=3` вместо `hard` |
| **`No such device` при загрузке** | Устройство недоступно в ранней стадии загрузки | Добавьте `nofail` или `x-systemd.device-timeout=10s` |

## Безопасность и опции монтирования

Для повышения безопасности используйте следующие опции:
- **`nosuid`** — игнорирует SUID/SGID биты на разделе (предотвращает повышение привилегий).
- **`noexec`** — запрещает выполнение бинарных файлов на разделе (для `/tmp`, `/var`, `/home`).
- **`nodev`** — запрещает интерпретацию блочных/символьных устройств на разделе.

Пример безопасной конфигурации для `/tmp`:
```text
tmpfs    /tmp    tmpfs    defaults,size=2G,noexec,nosuid,nodev    0    0
```

## Автоматизация через Ansible

Для управления fstab в Ansible используйте модуль `ansible.builtin.mount`:
```yaml
- name: Mount NFS share
  ansible.builtin.mount:
    path: /mnt/nfs
    src: 192.168.1.10:/srv/nfs
    fstype: nfs4
    opts: _netdev,x-systemd.automount
    state: mounted
```

## Мониторинг точек монтирования

Для мониторинга использования дискового пространства на основе fstab:
```bash
# Проверка использования всех разделов из fstab
df -h | grep -vE '^/dev/sd[a-z][0-9]|^tmpfs|^udev'

# Алертинг на основе node_exporter (Prometheus)
node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"} * 100 < 15
```
