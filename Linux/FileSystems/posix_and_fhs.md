# POSIX и FHS — стандарты файловой системы

## Определения

- **POSIX (Portable Operating System Interface):** Семейство стандартов IEEE, определяющих интерфейсы взаимодействия между операционной системой и приложениями. В контексте ФС стандарт определяет семантику системных вызовов, права доступа и обязательные атрибуты объектов.
- **FHS (Filesystem Hierarchy Standard):** Стандарт, регламентирующий структуру каталогов и размещение файлов в Unix-подобных системах. Его цель — обеспечить предсказуемость расположения системных ресурсов для разработчиков ПО и системных администраторов.
- **UsrMerge:** Современная архитектурная инициатива по объединению разделенных ранее каталогов (`/bin`, `/sbin`, `/lib`) в соответствующие подкаталоги внутри `/usr`. Это упрощает управление снимками системы и разделение пользовательских данных и системных файлов.

## Основные концепции

### POSIX-совместимость объектов

Согласно POSIX, каждый объект файловой системы (файл, каталог, ссылка) обязан обладать набором метаданных, хранящихся в Inode:
1.  **UID (User ID):** Идентификатор владельца.
2.  **GID (Group ID):** Идентификатор группы владельца.
3.  **Permissions (Mode):** Битовая маска прав доступа (rwx) для владельца, группы и остальных.
4.  **Timestamps:** Время последнего доступа (atime), модификации данных (mtime) и изменения метаданных (ctime).

### Принцип «Всё есть файл»

Фундаментальная концепция Unix/Linux: унифицированный доступ к разнородным ресурсам через интерфейс файловой системы. Это позволяет использовать стандартные инструменты (например, `grep` или `cat`) для работы с устройствами, каналами связи и параметрами ядра.

## Иерархия каталогов (FHS 3.0+)

| Путь | Назначение | Особенности |
| :--- | :--- | :--- |
| `/` | **Root** | Вершина иерархии. Единственная точка, не имеющая родителя. |
| `/bin` | **Essential Binaries** | Критичные утилиты (`ls`, `cat`). В современных системах — симлинк на `/usr/bin`. |
| `/boot` | **Static Boot Files** | Ядро (vmlinuz), initramfs, конфигурация GRUB. |
| `/dev` | **Device Files** | Интерфейс к оборудованию. Обычно это `devtmpfs`. |
| `/etc` | **Configuration** | Локальные конфигурационные файлы. Не должны содержать бинарных данных. |
| `/home` | **User Home** | Персональные данные пользователей. |
| `/root` | **Root Home** | Домашний каталог суперпользователя. Расположен отдельно от `/home` на случай его отсутствия. |
| `/run` | **Runtime Data** | Динамические данные времени выполнения (PID-файлы, сокеты). Хранится в `tmpfs`. |
| `/srv` | **Service Data** | Данные для сервисов (например, `/srv/www`, `/srv/ftp`). |
| `/tmp` | **Temporary Files** | Временные файлы, часто очищаемые при загрузке. |
| `/usr` | **User Hierarchy** | Основное место хранения установленного ПО, библиотек и документации. |
| `/var` | **Variable Files** | Данные, размер которых часто меняется (логи, базы данных, очереди). |

### Различие /tmp и /var/tmp

- **`/tmp`:** Предназначен для краткосрочных данных. В современных дистрибутивах монтируется как `tmpfs` (оперативная память) и полностью очищается при перезагрузке.
- **`/var/tmp`:** Предназначен для временных данных большого объема или требующих сохранения между перезагрузками. Хранится на физическом диске.

## Практические сценарии

### 1. Проверка структуры UsrMerge

В современных системах (Debian 12+, RHEL 9+) классические пути являются символическими ссылками.

```bash
ls -ld /bin /sbin /lib /lib64
# → lrwxrwxrwx 1 root root 7 ... /bin -> usr/bin
# → lrwxrwxrwx 1 root root 8 ... /sbin -> usr/sbin
```

### 2. Поиск конфигураций вне /etc

Согласно FHS, конфигурации должны быть в `/etc`. Проверка наличия нестандартных конфигов:
```bash
# Поиск файлов .conf вне /etc и /usr/share
sudo find / -name "*.conf" -not -path "/etc/*" -not -path "/usr/share/*"
```

### 3. Идентификация Runtime-сокетов

Данные в `/run` позволяют диагностировать активные сервисы без обращения к таблице процессов:
```bash
ls -F /run | grep "@" # Поиск Unix-сокетов
```
