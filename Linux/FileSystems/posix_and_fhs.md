# POSIX и FHS: Стандарты файловой системы Linux

## Определения

- **POSIX (Portable Operating System Interface)** — это набор стандартов, который описывает, как Unix-подобные операционные системы должны функционировать. Его главная цель — обеспечить **совместимость исходного кода** программ между различными системами (Linux, macOS, BSD). Стандарт затрагивает системные вызовы (API), интерфейс командной строки, права доступа и базовую структуру файловой системы. Хотя Linux не сертифицирован как POSIX-совместимый, он следует этим стандартам в значительной степени.

- **FHS (Filesystem Hierarchy Standard)** — это стандарт, который определяет структуру каталогов в Linux и других Unix-подобных системах. Он предписывает, какие файлы и каталоги где должны располагаться, что обеспечивает предсказуемость и порядок. Например, `/bin` для основных команд, `/etc` для конфигураций.

- **LSB (Linux Standard Base)** — это более широкий стандарт для дистрибутивов Linux, направленный на обеспечение **бинарной совместимости** (не только на уровне исходного кода). FHS является важной частью LSB.

## Основные концепции

- **Принцип "Всё есть файл"**: В Unix-подобных системах большинство объектов, включая оборудование (диски `/dev/sda`, терминалы `/dev/tty1`), сетевые сокеты и системную информацию ([`/proc`](./virtual_fs_proc.md)), представлены в виде файлов. Это позволяет использовать для взаимодействия с ними стандартные утилиты, такие как `read`, `write`, `cat`, `echo`.

- **Единое корневое дерево**: Ключевое архитектурное отличие от Windows, где каждому диску или разделу присваивается своя буква (`C:`, `D:`), и каждый представляет собой отдельное, изолированное дерево каталогов. В Linux и других Unix-подобных системах вся файловая система организована в виде единой иерархической структуры, начинающейся с корневого каталога (`/`). Любые дополнительные диски, разделы или сетевые ресурсы не создают новых "корней", а "монтируются" в существующие каталоги внутри этого единого дерева, становясь его неотъемлемой частью. Например, отдельный диск для пользовательских данных может быть примонтирован к каталогу `/home`, и его содержимое будет доступно по этому пути, а не через новую букву диска.

## Практические сценарии: Навигация по стандартной иерархии (стандарт FHS)

- `/`: **Корень (Root)**. Вершина всей иерархии файловой системы.
- `/bin`: **Основные команды (Binaries)**. Критически важные утилиты, доступные всем пользователям, необходимые для загрузки и восстановления системы (`ls`, `cp`, `mv`). В современных системах часто является символической ссылкой на `/usr/bin`.
- `/sbin`: **Системные команды (System Binaries)**. Утилиты для администрирования (`fdisk`, `mkfs`, `ifconfig`), обычно требующие прав `root`. Часто является ссылкой на `/usr/sbin`.
- `/boot`: **Загрузочные файлы**. Ядро Linux (`vmlinuz`), образ `initramfs` и конфигурация загрузчика (GRUB).
- `/dev`: **[Файлы устройств (Devices)](./virtual_fs_dev.md)**. Представление аппаратных и виртуальных устройств в виде файлов. Управляется динамически ядром.
- `/etc`: **Конфигурации (Editable Text Configuration)**. Системные и программные конфигурационные файлы.
- `/home`: **Домашние каталоги**. Личные каталоги пользователей (`/home/username`), где хранятся их файлы и настройки.
- `/root`: **Домашний каталог `root`**. Отделен от `/home` для обеспечения доступа суперпользователя, даже если раздел `/home` недоступен.
- `/lib`, `/lib64`: **Основные библиотеки (Libraries)**. Общие библиотеки, необходимые для работы программ из `/bin` и `/sbin`.
- `/opt`: **Опциональное ПО (Optional)**. Для установки сторонних программных пакетов, которые не входят в дистрибутив.
- `/srv`: **Данные сервисов (Service data)**. Данные для сервисов, предоставляемых системой (например, файлы для веб-сайта).
- `/tmp`: **Временные файлы (Temporary)**. Для хранения временных данных. Файлы обычно удаляются при перезагрузке.
- `/usr`: **Пользовательские ресурсы (Unix System Resources)**. "Вторая система", содержит большинство пользовательских программ, библиотек и документации.
  - `/usr/bin`: Основные пользовательские команды.
  - `/usr/sbin`: Не критичные для системы команды администрирования.
  - `/usr/lib`: Библиотеки для программ из `/usr/bin`.
  - `/usr/local`: Для программ, установленных вручную администратором, чтобы отделить их от пакетного менеджера.
- `/var`: **Переменные данные (Variable)**. Данные, изменяющиеся во время работы системы.
  - `/var/log`: Файлы журналов (логи).
  - `/var/lib`: Данные состояния для приложений (например, базы данных).
  - `/var/cache`: Кэш приложений.
  - `/var/spool`: Очереди для печати, почты и т.д.
- `/proc`: **[Виртуальная файловая система (procfs)](./virtual_fs_proc.md)**. Предоставляет интерфейс к информации о ядре и процессах в реальном времени. Ее содержимое генерируется "на лету" и хранится в памяти.
- `/sys`: **[Виртуальная файловая система (sysfs)](./virtual_fs_sys.md)**. Предоставляет структурированный доступ к информации об устройствах и драйверах с точки зрения ядра. Ее содержимое генерируется "на лету" и хранится в памяти.
- `/mnt`, `/media`: **Точки монтирования**. `/mnt` для временных ручных монтирований, `/media` для автоматического монтирования съемных носителей (USB, CD/DVD).
- `/lost+found`: **Восстановленные файлы**. Используется утилитой `fsck` для сохранения поврежденных фрагментов файлов после сбоя системы.

## Дополнительная информация

- **Объединение `/bin` и `/usr/bin` (UsrMerge)**: В современных дистрибутивах Linux каталоги `/bin`, `/sbin`, `/lib`, `/lib64` являются символическими ссылками на соответствующие каталоги внутри `/usr` (например, `/bin` → `/usr/bin`). Это изменение упрощает структуру и устраняет историческое различие между "критически важными для загрузки" и "обычными" программами, так как `initramfs` теперь содержит все необходимое для монтирования раздела `/usr`.
- **Динамические файловые системы `tmpfs`**: Каталоги [`/dev`](./virtual_fs_dev.md), [`/proc`](./virtual_fs_proc.md), [`/sys`](./virtual_fs_sys.md) и часто [`/tmp`](./virtual_filesystems.md) монтируются как `tmpfs`. Это означает, что их содержимое хранится в оперативной памяти, а не на диске. Это обеспечивает высокую скорость работы и автоматическую очистку при перезагрузке.
