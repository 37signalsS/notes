# Оптимизация производительности файловых систем

## Определения

Производительность файловой системы определяется совокупностью параметров: режимы журналирования, mount-опции, планировщик I/O, размеры блоков и настройки ядра.

## Основные концепции

### Журналирование

Журналирование — ключевой фактор надёжности и производительности. Подробное описание механизмов, режимов и влияния на I/O см. в **[Журналирование файловых систем](./journaling.md)**.

Краткая сводка:

| Режим ext4 | Надёжность | Производительность |
| :--- | :--- | :--- |
| `data=journal` | Максимальная | Минимальная (двойная запись) |
| `data=ordered` (по умолчанию) | Высокая | Хорошая |
| `data=writeback` | Низкая | Максимальная |

**Вынос журнала на SSD** ускоряет метаданные-операции в 2–5× на HDD. Подробности — в [Журналирование: Вынос журнала](./journaling.md#вынос-журнала-на-отдельный-носитель).

### Mount-опции для производительности

* **`noatime`** — не обновлять время доступа при каждом чтении. Устраняет лишние записи метаданных.
* **`nodiratime`** — то же, но только для директорий (atime файлов обновляется).
* **`relatime`** (по умолчанию) — обновлять atime только если он старше mtime/ctime.
* **`commit=N`** — интервал между commit-ами в журнал (по умолчанию 5 сек). Увеличение до 15–30 сек снижает число записей, но повышает риск потери данных.
* **`barrier=1`** (по умолчанию) — гарантия порядка записи. Отключение (`barrier=0`) опасно при наличии write-back кэша на диске.

```bash
# /etc/fstab — пример оптимизированного монтирования
UUID=xxx /mnt/data ext4 defaults,noatime,commit=15 0 2
```

### Размер блока (Block Size)

* **4 КБ** (по умолчанию) — баланс для mixed workload.
* **1 КБ** — эффективнее для тысяч мелких файлов (почта, логи).
* **8 КБ** — лучше для больших файлов (видео, бэкапы).

Задаётся при создании ФС и не меняется после:

```bash
mkfs.ext4 -b 4096 /dev/sda1
```

### I/O Scheduler (Планировщик ввода-вывода)

Ядро Linux использует планировщик для упорядочивания запросов к диску. Доступные планировщики:

```bash
cat /sys/block/sda/queue/scheduler
# [mq-deadline] kyber bfq none
```

| Планировщик | Когда использовать |
| :--- | :--- |
| **`mq-deadline`** (по умолчанию для SSD/NVMe) | General-purpose, базы данных |
| **`kyber`** | Высокопроизводительные NVMe, автоматическая настройка |
| **`bfq`** | Интерактивные рабочие нагрузки, ротационные диски |
| **`none`** | Виртуализация (планировщик гипервизора) |

```bash
# Временно изменить
echo kyber | sudo tee /sys/block/sda/queue/scheduler

# Постоянно через udev: /etc/udev/rules.d/60-io-scheduler.rules
ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/scheduler}="kyber"
```

### Read-Ahead (Опережающее чтение)

Ядро предварительно читает данные, которые могут понадобиться процессу.

```bash
# Текущее значение (в 512-байтовых секторах)
blockdev --getra /dev/sda
# 256 (т.е. 128 КБ)

# Увеличить для последовательного чтения (бэкапы, медиа)
blockdev --setra 2048 /dev/sda  # 1 МБ

# Уменьшить для случайного чтения (базы данных)
blockdev --setra 64 /dev/sda    # 32 КБ
```

### Barriers и кэш диска

**Write barrier** гарантирует, что данные, записанные в журнал, физически окажутся на диске до применения изменений.

* **`barrier=1`** (по умолчанию) — безопасно.
* **`barrier=0`** — опасно при write-back кэше на диске, допустимо только при наличии BBU (Battery Backup Unit) на RAID-контроллере.

```bash
# Проверить статус write-cache диска
hdparm -W /dev/sda
# Write caching = on

# Отключить (безопаснее, но медленнее)
hdparm -W 0 /dev/sda
```

## Практические сценарии

### Тюнинг для базы данных (PostgreSQL)

```bash
# /etc/fstab
UUID=xxx /var/lib/postgresql ext4 defaults,noatime,barrier=1,data=ordered 0 2

# I/O scheduler
echo mq-deadline | tee /sys/block/sda/queue/scheduler

# Read-ahead — меньше для случайного чтения
blockdev --setra 256 /dev/sda

# vm.dirty_* — меньше задержки записи
sysctl -w vm.dirty_background_ratio=5
sysctl -w vm.dirty_ratio=10
```

### Тюнинг для файлового хранилища (NFS/Samba)

```bash
# /etc/fstab
UUID=xxx /mnt/storage ext4 defaults,noatime,commit=30 0 2

# Read-ahead — больше для последовательного чтения
blockdev --setra 4096 /dev/sda

# I/O scheduler
echo kyber | tee /sys/block/sda/queue/scheduler
```

### Тюнинг для логов и мониторинга

```bash
# /etc/fstab
UUID=xxx /var/log ext4 defaults,noatime,data=writeback 0 2

# data=writeback приемлем для логов — потеря последних строк при сбое допустима
```
