# Оптимизация производительности файловых систем

## Определения

### Оптимизация производительности файловых систем

**Оптимизация производительности файловой системы** — это совокупная настройка параметров на уровнях файловой системы (ФС), ядра операционной системы и оборудования для достижения требуемого баланса между скоростью записи/чтения, надёжностью данных и потреблением ресурсов. Ключевые параметры: режимы журналирования, опции монтирования, планировщик ввода-вывода (I/O — Input/Output), размеры блоков, настройки ядра (`vm.dirty_*`).

## Основные концепции

### Журналирование

Журналирование — ключевой фактор надёжности и производительности. Подробное описание механизмов, режимов и влияния на операции ввода-вывода см. в **[Журналирование файловых систем](./journaling.md)**.

Краткая сводка:

| Режим ext4 | Надёжность | Производительность |
| :--- | :--- | :--- |
| `data=journal` | Максимальная | Минимальная (двойная запись) |
| `data=ordered` (по умолчанию) | Высокая | Хорошая |
| `data=writeback` | Низкая | Максимальная |

**Вынос журнала на SSD** (Solid State Drive — твердотельный накопитель) ускоряет операции с метаданными в 2–5 раз на HDD (Hard Disk Drive — жесткий диск). Подробности — в [Журналирование: Вынос журнала](./journaling.md#вынос-журнала-на-отдельный-носитель).

### Опции монтирования для производительности

* **`noatime`** — не обновлять время доступа при каждом чтении. Устраняет лишние записи метаданных.
* **`nodiratime`** — то же, но только для директорий (atime файлов обновляется).
* **`relatime`** (по умолчанию) — обновлять atime только если он старше mtime/ctime.
* **`commit=N`** — интервал между фиксациями (commit) в журнал (по умолчанию 5 секунд). Увеличение до 15–30 секунд снижает число записей, но повышает риск потери данных.
* **`barrier=1`** (по умолчанию) — гарантия порядка записи. Отключение (`barrier=0`) опасно при наличии кэша с обратной записью (write-back) на диске.

```bash
# /etc/fstab — пример оптимизированного монтирования
UUID=xxx /mnt/data ext4 defaults,noatime,commit=15 0 2
```

### Размер блока

* **4 КБ** (по умолчанию) — баланс для смешанных нагрузок.
* **1 КБ** — эффективнее для тысяч мелких файлов (почта, логи).
* **8 КБ** — лучше для больших файлов (видео, резервные копии).

Задаётся при создании ФС и не меняется после:

```bash
mkfs.ext4 -b 4096 /dev/sda1
```

### Планировщик ввода-вывода

Подробное описание планировщиков, их эволюции и настроек см. в **[I/O Scheduler](../../Core/kernel/io_schedulers.md)**.

Краткая сводка для выбора:

| Планировщик | Когда использовать |
| :--- | :--- |
| **`mq-deadline`** (по умолчанию для SSD/NVMe) | Общее назначение, базы данных |
| **`kyber`** | Высокопроизводительные накопители NVMe (Non-Volatile Memory Express), автоматическая настройка |
| **`bfq`** | Интерактивные рабочие нагрузки, классические жесткие диски (HDD) |
| **`none`** | Виртуализация (используется планировщик гипервизора) |

```bash
# Проверить текущий планировщик
cat /sys/block/sda/queue/scheduler

# Временно изменить
echo kyber | sudo tee /sys/block/sda/queue/scheduler
```

### Опережающее чтение

Ядро предварительно читает данные, которые могут понадобиться процессу.

```bash
# Текущее значение (в 512-байтовых секторах)
blockdev --getra /dev/sda
# 256 (т.е. 128 КБ)

# Увеличить для последовательного чтения (резервные копии, медиафайлы)
blockdev --setra 2048 /dev/sda  # 1 МБ

# Уменьшить для случайного чтения (базы данных)
blockdev --setra 64 /dev/sda    # 32 КБ
```

### Барьеры записи и дисковый кэш

Барьер записи (Write barrier) гарантирует, что данные, записанные в журнал, физически окажутся на диске до применения изменений.

* **`barrier=1`** (по умолчанию) — безопасно.
* **`barrier=0`** — опасно при включенном кэше обратной записи на диске, допустимо только при наличии BBU (Battery Backup Unit — блок резервного питания от батареи) на RAID-контроллере.

```bash
# Проверить статус кэша записи диска
hdparm -W /dev/sda
# Write caching = on

# Отключить (безопаснее, но медленнее)
hdparm -W 0 /dev/sda
```

## Практические сценарии

### Тюнинг для базы данных (PostgreSQL)

```bash
# /etc/fstab
UUID=xxx /var/lib/postgresql ext4 defaults,noatime,barrier=1,data=ordered 0 2

# Планировщик ввода-вывода
echo mq-deadline | tee /sys/block/sda/queue/scheduler

# Read-ahead — меньше для случайного чтения
blockdev --setra 256 /dev/sda

# Настройки ядра — уменьшение задержек записи
sysctl -w vm.dirty_background_ratio=5
sysctl -w vm.dirty_ratio=10
```

### Тюнинг для файлового хранилища (NFS/Samba)

```bash
# /etc/fstab
UUID=xxx /mnt/storage ext4 defaults,noatime,commit=30 0 2

# Read-ahead — больше для последовательного чтения
blockdev --setra 4096 /dev/sda

# Планировщик ввода-вывода
echo kyber | tee /sys/block/sda/queue/scheduler
```

### Тюнинг для логов и мониторинга

```bash
# /etc/fstab
UUID=xxx /var/log ext4 defaults,noatime,data=writeback 0 2

# data=writeback приемлем для логов — потеря последних строк при сбое допустима
```
