# Виртуальная файловая система /sys (sysfs)

## Определения

- **sysfs:** Виртуальная файловая система в ядре Linux, монтируемая в каталог `/sys`. Она служит интерфейсом для экспорта объектной модели ядра (**Kernel Object Model**) в пространство пользователя. Позволяет просматривать и изменять параметры оборудования, драйверов и модулей ядра.
- **Kobject (Kernel Object):** Базовая структура данных в ядре, представляющая отдельный элемент иерархии (диск, шина, драйвер). Каждый каталог в `/sys` соответствует определенному **kobject**.
- **Uevent:** Сообщение, генерируемое ядром при изменении состояния **kobject** (например, подключение устройства). Эти сообщения считываются демоном `udev` для автоматизации настройки системы.

## Основные концепции

### Структура и топология

В отличие от `/proc`, которая является во многом неструктурированным набором статистики, `sysfs` имеет строгую иерархическую структуру. Один файл в `sysfs` (атрибут) обычно содержит ровно одно текстовое значение.

#### Ключевые каталоги

- **`/sys/devices/`:** Главное дерево всех объектов. Отражает реальную физическую топологию системы (цепочки подключения устройств к шинам).
- **`/sys/bus/`:** Устройства, сгруппированные по типу шины (PCI, USB, I2C). Содержит подкаталоги `devices` (ссылки на `/sys/devices/`) и `drivers`.
- **`/sys/class/`:** Логическая группировка устройств по функциональности (сетевые карты `net`, блочные устройства `block`, подсистема питания `power_supply`).
- **`/sys/module/`:** Параметры и состояние всех загруженных модулей ядра.
- **`/sys/fs/`:** Настройки и статистика смонтированных файловых систем (например, `/sys/fs/ext4/`).
- **`/sys/kernel/`:** Глобальные параметры ядра, не привязанные к конкретным устройствам (IRQ, параметры безопасности, отладочная информация).

### Взаимодействие с атрибутами

Атрибуты в `sysfs` могут иметь права только на чтение (`RO`) или на чтение и запись (`RW`). Изменение параметров через `echo` (от имени `root`) применяется мгновенно и не требует перезагрузки, но сбрасывается после неё.

## Практические сценарии

### 1. Управление жизненным циклом PCI-устройств

`sysfs` позволяет программно отключать и подключать устройства к драйверам без перезагрузки системы.

```bash
# Принудительное отключение драйвера от видеокарты (например, для проброса в ВМ)
echo "0000:01:00.0" | sudo tee /sys/bus/pci/devices/0000:01:00.0/driver/unbind

# Инициирование пересканирования шины PCI для поиска новых устройств
echo 1 | sudo tee /sys/bus/pci/rescan
```

### 2. Сбор статистики сетевых интерфейсов

Вместо парсинга вывода `ifconfig` или `ip`, в скриптах эффективнее обращаться к `sysfs` напрямую.

```bash
# Получить количество принятых байт на интерфейсе eth0
cat /sys/class/net/eth0/statistics/rx_bytes

# Проверить статус линка (up/down)
cat /sys/class/net/eth0/operstate
```

### 3. Настройка планировщика ввода-вывода (I/O Scheduler)

Для оптимизации работы дисков под конкретную нагрузку:

```bash
# Просмотр доступных и активного планировщика (активный в скобках)
cat /sys/block/sda/queue/scheduler
# → [mq-deadline] kyber none

# Установка планировщика none (рекомендуется для NVMe)
echo none | sudo tee /sys/block/sda/queue/scheduler
```

### 4. Диагностика и отладка (debugfs)

Каталог `/sys/kernel/debug/` часто служит точкой монтирования для **debugfs**, предоставляющей доступ к глубоким структурам ядра.

```bash
# Просмотр статистики прерываний (IRQ)
sudo cat /sys/kernel/debug/irq/irqs/1
```
*Примечание: Если каталог пуст, его нужно смонтировать: `mount -t debugfs none /sys/kernel/debug`.*
