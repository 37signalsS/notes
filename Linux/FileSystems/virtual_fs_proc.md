# Виртуальная файловая система /proc (procfs)

## Определения

- **procfs:** Специальная виртуальная файловая система в Linux, предоставляющая интерфейс к внутренним структурам данных ядра. Она служит основным механизмом экспорта системной статистики и информации о процессах в пространство пользователя.
- **PID (Process Identifier):** Уникальный числовой идентификатор, присваиваемый ядром каждой активной задаче (процессу или потоку).
- **Control Plane ядра:** Роль `/proc` в качестве интерфейса для управления параметрами ядра «на лету» через подкаталог `/proc/sys/`.

## Основные концепции

### Механизм динамической генерации

Файлы в `/proc` не существуют на физических носителях. При выполнении системного вызова `read()` к такому файлу ядро вызывает соответствующую функцию-обработчик, которая собирает данные из оперативной памяти и форматирует их в текст. Это гарантирует абсолютную точность данных в момент обращения.

### Иерархия и структура

1.  **Каталоги процессов (`/proc/[PID]/`):** Динамически создаются при старте процесса и удаляются при его завершении.
2.  **Специальные ссылки:**
    - **`/proc/self/`:** Символическая ссылка на каталог текущего процесса, обращающегося к ФС. Удобно для использования в скриптах.
    - **`/proc/thread-self/`:** Ссылка на данные текущего потока.
3.  **Системная статистика:** Файлы в корне `/proc`, описывающие состояние памяти, CPU, прерываний и дисков.

### Детальная информация о процессе (/proc/[PID]/)

| Файл | Описание контента |
| :--- | :--- |
| `cmdline` | Полные аргументы запуска (разделены нулевым байтом). |
| `environ` | Переменные окружения процесса. |
| `fd/` | Список открытых дескрипторов (файлы, сокеты, пайпы). |
| `maps` / `smaps` | Карта виртуальной памяти. `smaps` дает детальную статистику по PSS/RSS для каждого сегмента. |
| `status` | Человекочитаемая сводка: лимиты, права (UID/GID), состояние сигналов. |
| `ns/` | Ссылки на пространства имен (**Namespaces**), в которых изолирован процесс. |
| `stack` | Текущий стек вызовов процесса в пространстве ядра (помогает найти причину «зависания» в D-состоянии). |

## Безопасность и ограничения

### Параметр hidepid

Для предотвращения утечки информации в многопользовательских средах или контейнерах монтирование `/proc` поддерживает опцию `hidepid`:
- `hidepid=1`: Пользователи не видят каталоги PID других пользователей (но видят их в `ps`).
- `hidepid=2`: Полная невидимость процессов других пользователей.

### Атомарность

Чтение файлов `/proc` не является атомарным. Если файл большой (например, `smaps`), состояние процесса может измениться в процессе чтения, что приведет к небольшим несоответствиям в данных.

## Практические сценарии

### 1. Восстановление «удаленного» файла

Если лог-файл был удален (`rm`), но приложение продолжает в него писать, данные физически остаются на диске до закрытия дескриптора.

```bash
# Поиск дескриптора (помечен как (deleted))
ls -l /proc/<PID>/fd/ | grep filename

# Копирование данных обратно
cp /proc/<PID>/fd/<FD_NUMBER> /tmp/restored_file
```

### 2. Анализ причин высокой нагрузки (Load Average)

Файл `/proc/loadavg` является первоисточником для всех утилит мониторинга.

```bash
cat /proc/loadavg
# → 0.45 0.52 0.61 1/840 23456
# (1/5/15 мин | активные/всего задач | PID последнего созданного процесса)
```

### 3. Диагностика нехватки памяти (OOM)

Файл `/proc/meminfo` содержит более 50 полей. Ключевые для SRE:
- **`MemAvailable`:** Реальное количество памяти, доступное для запуска новых приложений (с учетом кэшей).
- **`Dirty`:** Объем памяти, ожидающий записи на диск.
