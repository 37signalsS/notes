# Виртуальная файловая система /proc (procfs)

## Определения

**`procfs`** — это виртуальная файловая система в Linux, которая монтируется в каталог `/proc`. Она предоставляет динамический интерфейс к структурам данных ядра, позволяя в реальном времени получать информацию о системе и запущенных процессах, а также изменять некоторые параметры ядра. Ее содержимое хранится в оперативной памяти и генерируется "на лету" при обращении.

## Основные концепции

### Интерфейс к ядру

`/proc` служит "окном" в ядро Linux. Вместо того чтобы использовать сложные системные вызовы для получения системной информации, программы и пользователи могут просто "читать" или "писать" в файлы, расположенные в `/proc`, как если бы это были обычные текстовые файлы.

### Две основные категории информации

В `/proc` можно выделить два основных типа данных:

1.  **Информация о процессах**: Для каждого запущенного процесса создается каталог с числовым именем, соответствующим его PID (`/proc/[PID]`). В этих каталогах содержится детальная информация о состоянии, памяти, открытых файлах и других атрибутах процесса.
2.  **Системная информация**: Файлы, расположенные непосредственно в `/proc` или в его подкаталогах (например, `/proc/sys/`), предоставляют общую информацию о системе (CPU, память, версии ядра) и позволяют управлять поведением ядра.

### Динамичность и хранение в памяти

Содержимое `/proc` не записывается на диск. Оно динамически генерируется ядром при каждом обращении. Это означает, что информация всегда актуальна, но также подразумевает, что изменения в `/proc` (например, через `/proc/sys/`) не сохраняются после перезагрузки системы, если они не были внесены в постоянные конфигурационные файлы.

## Практические сценарии

### Получение информации о процессах

Для каждого запущенного процесса в `/proc` создается каталог `/proc/[PID]/`. Наиболее полезные файлы и каталоги внутри:

-   `exe`: Символическая ссылка на исполняемый файл процесса.
-   `cwd`: Ссылка на текущую рабочую директорию процесса.
-   `cmdline`: Командная строка, с которой был запущен процесс.
-   `environ`: Переменные окружения процесса.
-   `status`: Подробная информация о процессе (PID, PPID, UID, GID, потребление памяти: `VmSize`, `VmRSS` и т.д.).
-   `stat`: Информация о процессе в виде одной строки для программного парсинга (например, утилитой `ps`). Значения памяти здесь указаны в страницах.
-   `fd/`: Каталог с символическими ссылками на все открытые файловые дескрипторы процесса. Полезен для восстановления удаленных файлов.
-   `maps`: Карта памяти процесса. Показывает, какие области памяти отображены в адресное пространство процесса.
-   `oom_score`, `oom_score_adj`: Параметры, влияющие на поведение OOM (Out-of-Memory) Killer.

### Просмотр и изменение системных параметров ядра

Каталог `/proc/sys/` предоставляет доступ к параметрам ядра, которые можно просматривать и изменять в реальном времени.

-   Например, команда `echo 1 > /proc/sys/net/ipv4/ip_forward` включит пересылку IP-пакетов.
-   Утилита `sysctl` предоставляет более удобный интерфейс для работы с этими параметрами.
    -   **См. подробнее:** [Настройка параметров ядра (sysctl)](../../Core/kernel/sysctl.md)

### Использование для диагностики и восстановления

`procfs` широко используется диагностическими утилитами и может быть полезна в сценариях восстановления.

-   **Как работает `lsof`**: Утилита `lsof` (List Open Files) не использует специальные системные вызовы. Вместо этого она сканирует каталоги `/proc/[PID]/fd/` и `/proc/[PID]/maps` для агрегации информации обо всех открытых файлах и сокетах.
-   **Восстановление удаленного файла**: Если файл был удален, но все еще открыт каким-либо процессом, его можно восстановить. Ядро продолжает удерживать его содержимое на диске, а ссылка на него доступна через `/proc/[PID]/fd/`.
    ```bash
    # Пример: восстановление удаленного файла, открытого процессом с PID 12345 и дескриптором 4
    cp /proc/12345/fd/4 restored_file.txt
    ```

## Дополнительная информация

### Ключевые системные информационные файлы

Некоторые важные файлы непосредственно в `/proc`, предоставляющие общую информацию о системе:

-   `/proc/cpuinfo`: Детальная информация о процессоре. Подробнее см. в [cpu_info.md](../../Diagnostics/Hardware/cpu_info.md).
-   `/proc/meminfo`: Подробная статистика по использованию оперативной памяти. Подробнее см. в [proc_meminfo.md](../../Diagnostics/Memory/proc_meminfo.md).
-   `/proc/devices`: Список зарегистрированных в ядре символьных и блочных устройств.
    -   **См. подробнее о major/minor номерах:** [Виртуальная файловая система /dev](./virtual_fs_dev.md)
-   `/proc/interrupts`: Статистика по каждому вектору прерывания для каждого CPU. Подробнее см. в [interrupts.md](../../Core/kernel/interrupts.md).
-   `/proc/pressure/`: Метрики давления ресурсов (CPU, память, I/O). Подробнее см. в [psi.md](../../Core/kernel/psi.md).
-   `/proc/mounts`: Список всех примонтированных файловых систем. Подробнее см. в [mounting.md](../../FileSystems/mounting.md).
-   `/proc/version`: Версия ядра Linux.
-   `/proc/uptime`: Время работы системы с момента загрузки.
-   `/proc/kcore`: Виртуальный файл, представляющий всю физическую память системы (требует прав root).
