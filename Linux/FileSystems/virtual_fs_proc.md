# Виртуальная файловая система /proc

`procfs` — это виртуальная файловая система в Linux, которая предоставляет интерфейс к структурам данных ядра. Она монтируется в каталог `/proc` и позволяет в реальном времени получать информацию о системе и процессах, а также изменять некоторые параметры ядра "на лету". Утилиты вроде `ps`, `top`, `lsof`, `free`, `sysctl` получают свои данные именно из `/proc`.

### Информация о процессах

Основная часть `/proc` — это каталоги, имена которых являются числовыми идентификаторами процессов (PID).

-   `/proc/[PID]/`: Каталог, содержащий полную информацию о процессе с соответствующим PID.
-   `/proc/self`: Символическая ссылка на `/proc/[PID]` текущего процесса, который осуществляет доступ к `/proc`.

#### Ключевые файлы и каталоги внутри `/proc/[PID]/`:

-   `exe`: Символическая ссылка на исполняемый файл процесса.
-   `cwd`: Ссылка на текущую рабочую директорию процесса.
-   `cmdline`: Командная строка, с которой был запущен процесс (аргументы разделены нулевыми символами `\0`).
-   `environ`: Переменные окружения процесса.
-   `status`: Подробная информация о процессе в удобочитаемом формате (PID, PPID, UID, GID, потребление памяти `VmSize`, `VmRSS` и т.д.). Удобен для ручного анализа.
-   `stat`: Информация о процессе в виде одной строки с полями, разделенными пробелами. Этот формат предназначен для программного парсинга (например, утилитой `ps`). Значения, такие как `rss` (Resident Set Size), здесь указаны в количестве страниц памяти, а не в байтах. Для получения реального размера в байтах это значение нужно умножить на размер страницы (обычно 4096 байт).
-   `fd/`: Каталог, содержащий символические ссылки для каждого открытого файлового дескриптора.
    -   `0` — стандартный ввод (stdin)
    -   `1` — стандартный вывод (stdout)
    -   `2` — стандартный вывод ошибок (stderr)
    -   Остальные числа соответствуют открытым файлам, сокетам и другим ресурсам. Это позволяет, например, восстановить удаленный файл, если он все еще открыт каким-либо процессом.
-   `maps`: Карта памяти процесса. Показывает, какие области памяти (включая файлы библиотек `.so`) отображены в адресное пространство процесса. `lsof` использует `fd/` и `maps` для своей работы.
-   `oom_score`: "Очки", набранные процессом для OOM (Out-of-Memory) Killer. Чем выше значение, тем больше вероятность, что процесс будет "убит" при нехватке памяти.
-   `oom_score_adj`: Значение для корректировки `oom_score`. Установка в `-1000` может защитить процесс от OOM Killer.

### Системная информация и параметры ядра

-   `/proc/sys/`: Иерархия файлов для просмотра и изменения параметров ядра в реальном времени. Это тот же интерфейс, который использует утилита `sysctl`. Например, команда `sysctl -w net.ipv4.ip_forward=1` эквивалентна `echo 1 > /proc/sys/net/ipv4/ip_forward`. Изменения, сделанные здесь, сбрасываются при перезагрузке.
-   `/proc/cpuinfo`: Информация о процессоре (модель, частота, флаги, количество ядер).
-   `/proc/meminfo`: Подробная статистика по использованию оперативной памяти (общее количество, свободная, кэш, буферы, swap и т.д.).
-   `/proc/devices`: Список зарегистрированных в ядре символьных и блочных устройств и их major-номера.
-   `/proc/mounts`: Список всех примонтированных в системе файловых систем.
-   `/proc/version`: Версия ядра Linux.
-   `/proc/uptime`: Время работы системы с момента загрузки.
-   `/proc/kcore`: Виртуальный файл, представляющий всю физическую память (RAM) системы в формате ELF core. Его размер соответствует максимально адресуемому объему памяти для данной архитектуры, а не реальному объему RAM. Доступ к нему требует прав суперпользователя и специальных инструментов.

### Практические примеры

#### Как работает lsof

Утилита `lsof` (List Open Files) является ярким примером использования `/proc`. Для получения информации обо всех открытых файлах она не использует никаких специальных системных вызовов. Вместо этого она:

1.  Сканирует все числовые каталоги в `/proc` (т.е. для каждого PID).
2.  Для каждого процесса просматривает содержимое каталога `fd/`, чтобы найти все открытые файловые дескрипторы.
3.  Анализирует файл `maps`, чтобы найти файлы библиотек и другие файлы, отображенные в память.

Таким образом, `lsof` просто агрегирует и представляет в удобном виде информацию, уже доступную в `/proc`.

#### Восстановление удаленного файла

Если файл был удален, но все еще используется каким-либо процессом, его можно восстановить. Процесс продолжает удерживать файловый дескриптор, и ядро не освобождает занимаемое файлом место на диске до тех пор, пока последний процесс не закроет его.

**Сценарий:**

1.  Открываем большой текстовый файл с помощью `less`:
    ```bash
    less large_file.txt
    ```
2.  В другом терминале находим PID процесса `less` и удаляем файл:
    ```bash
    ps aux | grep less
    # Находим PID, например, 12345
    rm large_file.txt
    ```
3.  Файл исчез из каталога, но `less` все еще его отображает. В каталоге `/proc` для этого процесса файл будет помечен как `(deleted)`:
    ```bash
    ls -l /proc/12345/fd/
    # lr-x------ 1 user user 64 ноя  9 11:20 4 -> /path/to/large_file.txt (deleted)
    ```
4.  Восстанавливаем файл, копируя его по ссылке из `fd`:
    ```bash
    cp /proc/12345/fd/4 restored_file.txt
    ```
Таким образом, данные файла были успешно восстановлены, так как процесс `less` удерживал их в памяти, а ядро предоставляло к ним доступ через `/proc`.
