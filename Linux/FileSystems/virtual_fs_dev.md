# Виртуальная файловая система /dev

## Определения

- **Файловая система `/dev` (devtmpfs):** Специализированная виртуальная файловая система (псевдо-ФС), монтируемая в оперативной памяти и предназначенная для хранения файлов устройств (узлов). Она позволяет ядру автоматически создавать и удалять узлы устройств по мере регистрации драйверов, обеспечивая доступность оборудования на самых ранних этапах загрузки (Early Boot).
- **Файл устройства (Device Node):** Специальный объект в иерархии ФС (тип `b` для блочных или `c` для символьных), который служит интерфейсом взаимодействия между пользовательским пространством и драйвером ядра.
- **Persistent Naming (Стабильное именование):** Механизм создания неизменных путей к устройствам (через символические ссылки) на основе уникальных атрибутов оборудования (UUID, серийный номер), что предотвращает ошибки при изменении порядка подключения дисков (например, смена `/dev/sda` на `/dev/sdb`).
- **systemd-tmpfiles:** Механизм systemd для декларативного создания, удаления и управления объектами ФС (файлами, каталогами, узлами устройств). Используется для создания статических узлов устройств, которые не генерируются автоматически через devtmpfs/udev (например, кастомные символьные устройства или файлы в `/dev/` для старых драйверов).
- **initramfs (Initial RAM Filesystem):** Временный корневой ФС, монтируемый ядром на этапе загрузки до монтирования реального корня. Содержит минимальный набор утилит и драйверов, необходимых для обнаружения корневого устройства и переключения на него. На этапе initramfs `/dev` управляется через `devtmpfs`, что позволяет работать с дисками и шинами.

## Основные концепции

### Архитектура devtmpfs и Udev

Современный механизм управления устройствами в Linux является гибридным и состоит из двух уровней:

1.  **Уровень ядра (devtmpfs):** Как только ядро обнаруживает новое устройство, драйвер регистрирует его. Ядро мгновенно создает базовый узел в `/dev` (например, `/dev/sdb`). Это гарантирует, что критические устройства доступны до запуска системных служб.
2.  **Уровень пользователя (Udev):** Демон `systemd-udevd` получает уведомление от ядра (**uevent**). Он анализирует атрибуты устройства в `/sys`, применяет правила (udev rules), создает дополнительные символические ссылки (например, в `/dev/disk/by-uuid/`), устанавливает права доступа (ACL) и владельцев.

### Процесс загрузки и инициализация /dev

На этапе загрузки система проходит следующую последовательность инициализации `/dev`:

1.  **Ядро:** При старте ядро монтирует `devtmpfs` в `/dev` (если указана опция `devtmpfs=mount` или используется systemd). Если `devtmpfs` не смонтирована, ядро создает только статические узлы (`/dev/null`, `/dev/console` и др.).
2.  **initramfs:** Внутри initramfs `udev` запускается в userspace для обработки оборудования, необходимого для монтирования корневого ФС (например, SATA/NVMe контроллеры, SCSI-хосты). Здесь `/dev` заполняется узлами для дисков, разделов и шин.
3.  **Переключение на реальный root:** После монтирования реального корневого раздела (по `root=UUID=...` или `root=PARTUUID=...`) и переключения корня (`pivot_root` или `switch_root`), `devtmpfs` из initramfs сливается с `/dev` целевой системы.
4.  **systemd-udevd:** После перехода на реальный root `systemd-udevd` продолжает работать, дополняя `/dev` симлинками, правами и запуская сервисы для новых устройств.

**Важно для SRE:** Если `devtmpfs` не смонтирована или повреждена в initramfs, система может не увидеть корневой диск. Для диагностики на этапе initramfs используйте:
```bash
# В консоли initramfs:
ls /dev/sd* /dev/nvme*
ls /dev/disk/by-uuid/
cat /proc/partitions
```

### Структура и ключевые компоненты

| Путь | Описание | Особенности |
| :--- | :--- | :--- |
| `/dev/disk/` | Иерархия стабильных имен дисков. | Содержит подкаталоги `by-id`, `by-path`, `by-uuid`, `by-partuuid`, `by-label`. |
| `/dev/pts/` | Виртуальные терминалы (Pseudo-Terminals). | Используется `devpts`. Файлы `/dev/pts/N` создаются динамически для каждой сессии SSH или эмулятора терминала. |
| `/dev/mapper/` | Узлы Device Mapper. | Точки доступа для томов LVM, зашифрованных дисков LUKS и Multipath-устройств. |
| `/dev/shm/` | Разделяемая память (Shared Memory). | Прямой интерфейс к `tmpfs` для быстрого межпроцессного взаимодействия (IPC). |
| `/dev/fd/` | Дескрипторы файлов текущего процесса. | Ссылка на `/proc/self/fd`. Также здесь находятся `stdin` (0), `stdout` (1), `stderr` (2). |

### Идентификация: Major и Minor

Каждый узел устройства привязан к драйверу через два числа:
- **Major (Старший номер):** Определяет драйвер устройства (например, 8 для SCSI/SATA дисков).
- **Minor (Младший номер):** Определяет конкретный экземпляр или раздел диска (например, 0 для `/dev/sda`, 1 для `/dev/sda1`).
*Подробный список и классификация номеров приведены в [Типах устройств](./device_types.md).*

### Опции монтирования и безопасность

Поскольку `/dev` содержит интерфейсы к оборудованию, его монтирование требует строгих опций безопасности:

```bash
# /etc/fstab: стандартная запись для devtmpfs
devtmpfs  /dev    devtmpfs  nosuid,noexec,nodev,size=2G,mode=0755  0  0
```

| Опция | Назначение | Примечания |
| :--- | :--- | :--- |
| `nosuid` | Запрещает выполнение программ с установленным SUID-битом | Защита от повышения привилегий через устройства. |
| `noexec` | Запрещает прямой запуск исполняемых файлов с устройства | Критично для `/dev/shm`; для корневого `/dev` обычно включен по умолчанию в systemd. |
| `nodev` | Запрещает интерпретацию специальных файлов как устройств | Предотвращает создание суицидных устройств внутри `/dev` в контейнерах. |
| `size=` | Ограничение объема `devtmpfs`/`tmpfs` в RAM | По умолчанию 50% RAM. Для `/dev` обычно достаточно `size=2G`; для `/dev/shm` значение зависит от нагрузки (см. практические сценарии). |
| `mode=` | Права доступа на корневой каталог ФС | `mode=0755` гарантирует, что только root может создавать узлы; `mode=1777` требуется для `/dev/pts` и `/dev/shm`. |
| `nr_inodes=` | Максимальное количество inodes | Полезно на системах с тысячами устройств (high-density NVMe). |

**Динамическое ограничение /dev/shm:** В системах с большим количеством процессов (СУБД, in-memory кэши) ограничьте `/dev/shm` через `mount` или `/etc/fstab`, чтобы предотвратить исчерпание памяти:
```bash
# Ограничение /dev/shm до 4 ГБ
mount -t tmpfs -o size=4G,noexec,nosuid,nodev tmpfs /dev/shm
```

### Параметры runtime и ограничения

- **`/proc/sys/kernel/pty/max`:** Максимальное количество псевдо-терминалов (PTY). По умолчанию 4096. На шлюзах или серверах с большим количеством SSH-сессий может потребоваться увеличение:
```bash
# Проверить текущее значение
cat /proc/sys/kernel/pty/max
# → 4096

# Временно увеличить до 8192
echo 8192 | sudo tee /proc/sys/kernel/pty/max

# Перманентно через sysctl.d
echo 'kernel.pty.max = 8192' | sudo tee /etc/sysctl.d/99-pty.conf
sudo sysctl -p /etc/sysctl.d/99-pty.conf
```

- **`/dev/shm` и POSIX разделяемая память:** В Linux `tmpfs`, смонтированный в `/dev/shm`, используется для POSIX разделяемой памяти (`shm_open`) и отображений (`mmap` с `MAP_SHARED`). Размер по умолчанию равен половине RAM. Для СУБД и кэширующих серверов (Redis, KeyDB) это может быть узким местом.

### Пространства имен и /dev

Каждый mount namespace имеет собственную виртуальную иерархию `/dev`. При создании нового namespace через `unshare` или контейнеризацию:

- **Пространство имен монтирования:** Умолчанию наследует текущую таблицу монтирования, но можно выполнить перемонтирование (`mount --bind`) или создать изолированный `devtmpfs`.
- **Контейнеры:** Минимальный `/dev` в контейнере обычно содержит только узлы, проброшенные через `--device` или `--privileged`. Если `devtmpfs` не проброшена явно, контейнер работает с усеченным набором устройств.
- **PID и UTS namespace:** Не влияют напрямую на `/dev`, но через `udev` и `systemd` могут влиять на правила (например, `ENV{ID_PATH}` зависит от топологии шин, которая видна глобально).

### Взаимодействие с systemd-tmpfiles

`systemd-tmpfiles` отвечает за создание файлов и директорий, которые не генерируются динамически через `udev`. Для устройств это применяется в случаях:

- Статические узлы для драйверов, которые не регистрируются через `devtmpfs`.
- Создание каталогов в `/dev` с определенными правами (например, `/dev/cgroup` в старых системах).
- Удаление устаревших узлов при отключении оборудования (правила с возрастом `d` или `D`).

Пример конфигурации `/etc/tmpfiles.d/static-devices.conf`:
```ini
# Создание статического символьного устройства
c! /dev/my-custom-dev 600 0 0 - 240 0

# Создание каталога с правами
d /dev/gpio 0755 root root
```

Применение правил:
```bash
sudo systemd-tmpfiles --create --prefix /dev
```

## Практические сценарии

### 1. Поиск диска по стабильному имени

В файле `/etc/fstab` и конфигурациях загрузчика всегда следует использовать пути из `/dev/disk/by-*`, чтобы избежать проблем при перестановке дисков.

```bash
# Найти UUID для конкретного раздела
ls -l /dev/disk/by-uuid | grep sdb1

# Или через универсальную утилиту
blkid /dev/sdb1
```

### 2. Создание узла вручную (mknod)

В chroot-окружениях или «тонких» контейнерах, где `devtmpfs` не проброшена, может потребоваться ручное создание базовых узлов:

```bash
# Создание /dev/null (Символьное устройство, Major 1, Minor 3)
sudo mknod -m 666 /dev/null c 1 3
```

### 3. Диагностика и «принудительное» обновление

Если устройство подключено, но узел в `/dev` не появился (или не создались симлинки udev):

```bash
# Повторный вызов событий udev для всех блочных устройств
sudo udevadm trigger --subsystem-match=block

# Проверка, видит ли ядро устройство в принципе
cat /proc/partitions
```

### 4. Использование системных генераторов и заглушек

- **/dev/urandom:** Основной источник энтропии для криптографии. Не блокируется при исчерпании пула (в отличие от устаревшего `/dev/random`).
- **/dev/zero:** Используется для создания пустых файлов заданного размера или обнуления дисков.
- **/dev/full:** Полезен для тестирования поведения приложений при ошибке записи «Диск переполнен».

```bash
# Тест: как приложение реагирует на нехватку места
myapp > /dev/full
```

### 5. Настройка persistent device nodes через systemd-tmpfiles

Если udev не создает узел (например, для кастомного символьного устройства или legacy оборудования), используйте `systemd-tmpfiles`:

```bash
# /etc/tmpfiles.d/my-custom-dev.conf
c! /dev/my-custom-dev 660 root operator 240 0

# Применение
sudo systemd-tmpfiles --create --prefix /dev
```

**Валидация:**
```bash
ls -l /dev/my-custom-dev
# → crw-rw---- 1 root operator 240, 0 ... /dev/my-custom-dev
```

### 6. Boot parameters и стабильная корневая ФС

Для стабильной загрузки используйте UUID или PARTUUID вместо путей `/dev/sdX`. Это предотвращает сбои при изменении порядка дисков.

**GRUB (Bios/GPT):**
```bash
# /etc/default/grub
GRUB_CMDLINE_LINUX="root=UUID=91c2... ro quiet splash"
```
```bash
# Применение
sudo update-grub
```

**Для NVMe:** Используйте `PARTUUID` или `UUID`, так как `/dev/nvmeXnYpZ` может измениться при добавлении других NVMe-дисков:
```bash
# Просмотр PARTUUID
sudo blkid /dev/nvme0n1p2
# → /dev/nvme0n1p2: PARTUUID="8e21..." TYPE="ext4"

# В GRUB:
linux   /boot/vmlinuz-6.5.0 root=PARTUUID=8e21... ro
```

### 7. Tuning /dev/shm для локальных нагрузок

Для СУБД (PostgreSQL, MySQL) и in-memory кэшей (Redis) размер `/dev/shm` по умолчанию (50% RAM) может быть недостаточным или избыточным.

```bash
# Проверить текущий размер
df -h /dev/shm
# → tmpfs           8.0G  1.2G  6.8G  16% /dev/shm

# Перемонтирование с новым размером (без перезагрузки)
sudo mount -o remount,size=16G /dev/shm

# Перманентно в /etc/fstab
tmpfs   /dev/shm    tmpfs    defaults,size=16G,noexec,nosuid,nodev    0  0
```

### 8. Troubleshooting udev и device nodes в контейнерах/chroot

**Проблема:** В Docker/Podman/LXC контейнере отсутствует `/dev/null` или другие критические узлы.

```bash
# Внутри контейнера:
ls -l /dev/null
# → ls: cannot access '/dev/null': No such file or directory

# Решение 1: Пробросить devtmpfs при запуске (Docker/Podman)
docker run --device /dev/null --device /dev/zero ...

# Решение 2: Создать вручную в Dockerfile
mknod -m 666 /dev/null c 1 3
mknod -m 666 /dev/zero c 1 5
```

**Проблема:** Udev-события не обрабатываются в chroot (нет systemd-udevd).

```bash
# Принудительный запуск udev в chroot (если systemd не запущен)
sudo udevadm trigger --type=devices --action=add
sudo udevadm settle --timeout=30

# Проверка очереди событий
sudo udevadm monitor --kernel --udev --subsystem-match=block
```

### 9. Мониторинг и аудит событий устройств

Для SRE важно отслеживать изменения топологии оборудования в production.

```bash
# Мониторинг событий в реальном времени
sudo udevadm monitor --kernel --udev --property

# Фильтрация по блочным устройствам
sudo udevadm monitor --udev --subsystem-match=block --property | grep -E 'ACTION=add|DEVNAME'

# Просмотр истории событий через journald
sudo journalctl -u systemd-udevd --since "1 hour ago" -p info

# Поиск ошибок за последние 24 часа
sudo journalctl -u systemd-udevd --since "24 hours ago" | grep -i 'fail\|error\|timeout'
```

### 10. Управление PTY/TTY и сессиями

На серверах с большим количеством SSH-подключений может потребоваться настройка лимитов:

```bash
# Проверить текущее количество активных PTY
ls /dev/pts/ | wc -l
# → 42

# Проверить максимальный лимит
cat /proc/sys/kernel/pty/max
# → 4096

# Настройка лимита в systemd (если используется systemd-logind)
# /etc/systemd/logind.conf
[Login]
NAutoVTs=6
ReserveVT=6
KillUserProcesses=yes
```

### 11. Hotplug и Multipath в production

При замене дисков в SAN или Hot-Plug NVMe важно принудительно обновить udev:

```bash
# После физической замены диска в SAN (Fibre Channel / iSCSI)
sudo multipath -r
sudo udevadm trigger --subsystem-match=block --action=add
sudo udevadm settle --timeout=30

# Проверка новых путей
ls /dev/mapper/mpath*
multipath -ll

# Для NVMe (NVMe over Fabrics или локальный hotplug)
sudo nvme list
sudo udevadm trigger --subsystem-match=nvme --action=add
```
