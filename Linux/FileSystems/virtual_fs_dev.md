# Виртуальная файловая система /dev

## Определения

- **Файловая система `/dev`**: Специальная виртуальная файловая система в Linux, которая предоставляет программам и пользователям унифицированный интерфейс для взаимодействия с аппаратными и виртуальными устройствами через файлы. Ее содержимое не хранится на диске, а генерируется динамически ядром и `udev`.

- **Файл устройства (Device File)**: Специальный тип файла, расположенный в `/dev`, который служит интерфейсом к конкретному устройству. В отличие от обычных файлов, чтение или запись в файл устройства напрямую взаимодействует с драйвером соответствующего оборудования. Файлы устройств идентифицируются по **major** и **minor** номерам.

## Основные концепции

### "Всё есть файл" в /dev

Концепция "всё есть файл" в Linux ярко проявляется в `/dev`. Каждое устройство в системе, будь то жесткий диск, терминал, USB-флешка или даже генератор случайных чисел, представлено как файл. Это позволяет использовать стандартные системные вызовы и утилиты командной строки (такие как `cat`, `echo`, `dd`) для работы с устройствами.

### Динамическое управление с помощью udev

В современных системах Linux содержимое каталога `/dev` не статично. Оно создается и управляется демоном `udev`, который взаимодействует с ядром. Когда устройство подключается к системе или отключается, `udev` автоматически создает или удаляет соответствующие файлы устройств в `/dev`. Это обеспечивает гибкость и актуальность содержимого каталога. Более подробную информацию о `udev` можно найти здесь: [Udev: подсистема динамического управления устройствами](../Core/udev.md).

### Major и Minor номера устройств

Каждый файл блочного или символьного устройства в `/dev` имеет два идентификатора:

- **Major number (старший номер)**: Идентифицирует драйвер устройства в ядре. Устройства, использующие один и тот же драйвер (например, все SATA-диски), будут иметь одинаковый major number.
- **Minor number (младший номер)**: Идентифицирует конкретное устройство, управляемое этим драйвером. Например, `/dev/sda` и `/dev/sdb` будут иметь одинаковый major number, но разные minor numbers.

Список зарегистрированных в ядре устройств и их major-номеров можно посмотреть в файле `/proc/devices`.

### Типы файлов устройств

Файлы в `/dev` бывают двух основных типов, различающихся способом обмена данными:

- **Блочные устройства (`b`)**: Оперируют данными фиксированными блоками (например, 512 байт). Используются для устройств, требующих произвольного доступа и высокой производительности, таких как жесткие диски (`/dev/sda`).
- **Символьные устройства (`c`)**: Оперируют данными последовательно, побайтно. Используются для устройств, работающих с потоками данных, таких как терминалы (`/dev/tty1`), последовательные порты.

**Подробности о различиях:** [Типы устройств в Linux: блочные и символьные](./device_types.md)

## Практические сценарии

### Специальные псевдо-устройства

В `/dev` существует ряд псевдо-устройств, не связанных напрямую с физическим оборудованием, но предоставляющих полезные функции:

- **/dev/null**: "Черная дыра", поглощает все записываемые в нее данные. При чтении всегда возвращает EOF. Используется для подавления вывода команд.
- **/dev/zero**: Источник нулевых байтов. При чтении возвращает бесконечную последовательность нулей. Полезно для создания файлов заданного размера, заполненных нулями.
- **/dev/random** и **/dev/urandom**: Источники криптографически стойких случайных (или псевдослучайных) данных.
    > **Примечание:** В виртуализированных средах недостаток энтропии для `/dev/random` может приводить к "зависанию" приложений. Подробнее о диагностике и решении этой проблемы см. в заметке [**Диагностика и решение проблем с низкой энтропией в Linux**](../Diagnostics/Troubleshooting/linux_entropy_troubleshooting.md).
- **/dev/full**: Имитирует переполненный диск. Любая попытка записи в него завершается ошибкой "No space left on device".
- **/dev/tty**: Ссылка на управляющий терминал текущего процесса.
- **/dev/pts/***: Псевдо-терминалы для эмуляторов терминала, SSH-сессий и других программ.

### Использование псевдо-устройств в командной строке

- **Подавление вывода команды:**

    ```bash
    # Стандартный вывод и ошибки команды будут перенаправлены в /dev/null
    command > /dev/null 2>&1
    ```

- **Создание файла заданного размера, заполненного нулями:**

    ```bash
    # Создаст файл large_file.img размером 1 ГБ (1024 блока по 1 МБ), заполненный нулями
    dd if=/dev/zero of=large_file.img bs=1M count=1024
    ```

- **Тестирование обработки ошибок нехватки места:**

    ```bash
    # Попытка записи в /dev/full всегда возвращает ошибку
    echo "Тестовая строка" > /dev/full
    # Вывод: bash: echo: write error: No space left on device
    ```

## Дополнительная информация

### Исторический контекст и mknod

В ранних версиях Linux каталог `/dev` был статическим и содержал огромное количество предварительно созданных файлов устройств. Это было негибко и избыточно. Современный подход с `udev` значительно улучшил управление устройствами.

Тем не менее, команда `mknod` для ручного создания файла устройства сохраняется. Она может быть полезна в специфических сценариях, например, при отладке драйверов или восстановлении системы, если `udev` по какой-либо причине не функционирует.

```bash
# Пример создания символьного устройства вручную
# mknod [имя_файла] c [major_number] [minor_number]
mknod /tmp/my_char_device c 100 1
# Эта команда создаст в /tmp файл символьного устройства с major-номером 100 и minor-номером 1.
```
