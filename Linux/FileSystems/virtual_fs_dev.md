# Виртуальная файловая система /dev

## Определения

- **Файловая система `/dev` (devtmpfs):** Специализированная виртуальная файловая система в оперативной памяти, предназначенная для хранения файлов устройств (узлов). Является эволюцией `tmpfs`, позволяющей ядру автоматически создавать узлы устройств на ранних этапах загрузки, до запуска менеджера устройств в пространстве пользователя.
- **Файл устройства (Device Node):** Интерфейс в иерархии ФС, связывающий приложения с драйверами ядра через системные вызовы работы с файлами.
- **Псевдоустройство (Pseudo-device):** Виртуальный объект в `/dev`, реализующий программную логику драйвера без привязки к физическому оборудованию (например, `/dev/null`).

## Основные концепции

### Архитектура devtmpfs

В отличие от устаревшего статического `/dev`, современная `devtmpfs` работает совместно с ядром:
1.  **Ядро:** При обнаружении оборудования создает запись в `devtmpfs`.
2.  **Udev:** Демон в пространстве пользователя перехватывает событие (uevent), меняет права доступа, создает символические ссылки (например, по ID диска) и выполняет дополнительные сценарии.
3.  **Доступность:** Узлы устройств доступны сразу после монтирования `devtmpfs`, что критично для загрузки (например, для доступа к `/dev/root`).

### Стандартная структура каталогов в /dev

| Подкаталог | Назначение |
| :--- | :--- |
| `/dev/disk/` | Символические ссылки на блочные устройства, сгруппированные по UUID (`by-uuid`), меткам (`by-label`), ID оборудования (`by-id`) и пути на шине (`by-path`). |
| `/dev/pts/` | Виртуальные терминалы (Pseudo-Terminals), создаваемые для SSH и эмуляторов консоли. Реализовано через `devpts`. |
| `/dev/mapper/` | Логические устройства, созданные через Device Mapper (LVM, LUKS, Multipath). |
| `/dev/shm/` | Разделяемая память (Shared Memory), монтируемая как `tmpfs`. |
| `/dev/input/` | Устройства ввода (мыши, клавиатуры, джойстики). |

### Идентификация через Major/Minor

Каждое устройство однозначно определяется парой чисел:
- **Major Number:** Идентифицирует драйвер.
- **Minor Number:** Идентифицирует конкретный экземпляр или раздел диска.
*Примечание: Список активных номеров можно просмотреть в `/proc/devices`.*

## Практические сценарии

### 1. Диагностика устройства через udevadm

Для получения полной информации о цепочке драйверов и атрибутах устройства (например, флешки `/dev/sdb`):

```bash
# Просмотр всех атрибутов устройства в базе udev
udevadm info --query=all --name=/dev/sdb

# Мониторинг событий создания/удаления узлов в реальном времени
udevadm monitor --environment --udev
```

### 2. Использование системных «заглушек»

- **/dev/null:** Поглощает ввод, возвращает EOF при чтении.
- **/dev/zero:** Источник бесконечных нулей (`0x00`).
- **/dev/full:** Имитирует переполненный диск (любая запись возвращает ошибку).
- **/dev/random / /dev/urandom:** Генераторы случайных чисел.
  *Современный стандарт: Использовать `/dev/urandom` для большинства задач, так как он не блокируется.*

```bash
# Очистка начала диска (стирание таблицы разделов)
sudo dd if=/dev/zero of=/dev/sdX bs=512 count=1
```

### 3. Работа в контейнерах и chroot

В изолированных средах `/dev` часто монтируется с ограниченным набором узлов из соображений безопасности.
- В Docker по умолчанию доступны только базовые устройства (`null`, `zero`, `random`, `tty`, `console`).
- Для доступа к физическому диску внутри контейнера используется флаг `--device`.
