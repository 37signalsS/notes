# Виртуальная файловая система /dev

## Определения

- **Файловая система `/dev` (devtmpfs):** Специальная виртуальная файловая система в Linux, предоставляющая унифицированный интерфейс для взаимодействия с аппаратными и виртуальными устройствами через файлы. Содержимое `/dev` не хранится на диске, а генерируется ядром и менеджером устройств в оперативной памяти.
- **Файл устройства (Device File):** Специальный объект в файловой системе, выступающий посредником между пользовательским пространством и драйвером устройства в ядре.
- **Псевдо-устройство (Pseudo-device):** Виртуальный объект в `/dev`, который ведет себя как файл устройства, но не привязан к реальному физическому оборудованию (например, генератор случайных чисел).

## Основные концепции

### Концепция «Всё есть файл»

В Linux доступ к оборудованию унифицирован. Чтение данных с диска или отправка текста на принтер выполняется с помощью тех же системных вызовов (`read`, `write`), что и работа с обычными текстовыми файлами. Это позволяет использовать стандартные утилиты Shell (например, `cat`, `echo`, `dd`) для прямого взаимодействия с «железом».

### Идентификация устройств: Major и Minor

Ядро идентифицирует файлы устройств не по именам, а по паре чисел:

- **Старший номер (Major Number):** Указывает на драйвер, который управляет данным устройством (например, `8` для **SCSI (Small Computer System Interface)** и **SATA (Serial AT Attachment)** дисков).
- **Младший номер (Minor Number):** Позволяет драйверу различать конкретные экземпляры оборудования или разделы (например, для `/dev/sda` minor равен `0`, для `/dev/sda1` — `1`).

Просмотр зарегистрированных драйверов и их номеров:

```bash
cat /proc/devices
```

### Динамическое управление (udev)

В современных дистрибутивах за наполнение каталога `/dev` отвечает подсистема **udev**. Она отслеживает события ядра (подключение/отключение оборудования) и динамически создает или удаляет соответствующие файлы, а также назначает им права доступа и символические ссылки на основе правил. Подробнее: **[Udev — динамическое управление устройствами](../Core/udev.md)**.

## Практические сценарии

### Использование специальных псевдо-устройств

В `/dev` находится ряд критически важных виртуальных инструментов:

- **/dev/null:** «Черная дыра». Любые записанные в нее данные исчезают бесследно. При чтении всегда возвращает **EOF** (End of File).

  ```bash
  # Подавление вывода команды
  command > /dev/null 2>&1
  ```

- **/dev/zero:** Источник бесконечных нулевых байтов (`\0`).

  ```bash
  # Создание файла размером 100 МБ (Megabyte), заполненного нулями
  dd if=/dev/zero of=test_file bs=1M count=100
  ```

- **/dev/full:** Имитирует переполненный носитель. Любая запись завершается ошибкой `No space left on device`. Полезно для тестирования поведения ПО при нехватке места.
- **/dev/random и /dev/urandom:** Генераторы случайных чисел. `/dev/random` может блокироваться в ожидании накопления системной энтропии, тогда как `/dev/urandom` (unblocked) выдает данные непрерывно.

  ```bash
  # Генерация случайного пароля из 16 символов
  head -c 16 /dev/urandom | base64
  ```

### Работа с терминалами

- **/dev/tty:** Псевдоним для управляющего терминала текущего процесса. Запись в него выведет текст на экран текущей сессии независимо от перенаправлений.
- **/dev/pts/X:** Виртуальные терминалы (Pseudo Terminal Slave), используемые для SSH-сессий и эмуляторов терминала в графическом интерфейсе.

### Ручное создание файлов устройств (mknod)

Если автоматическое создание через udev невозможно (например, в среде **chroot**), используется утилита `mknod`:

```bash
# Создание блочного устройства (b) с Major 8 и Minor 0
sudo mknod /dev/sdb_manual b 8 0
```
