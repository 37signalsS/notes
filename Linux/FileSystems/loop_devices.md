# Петлевые устройства (Loop Devices)

## Определения

- **Loop Device (Петлевое устройство):** Псевдоустройство в ядре Linux (модуль `loop`), которое позволяет представить обычный файл как блочное устройство. Это позволяет монтировать образы дисков, работать с ISO-файлами или создавать зашифрованные контейнеры без выделения физического накопителя.
- **losetup:** Системная утилита для управления связями между файлами и петлевыми устройствами (`/dev/loopX`).
- **loop-control:** Управляющее устройство (`/dev/loop-control`), позволяющее динамически создавать и удалять узлы `/dev/loopN` через системные вызовы (ioctl).

## Основные концепции

### Принцип работы

Драйвер петлевого устройства выступает в роли транслятора: он перехватывает блочные запросы ввода-вывода (I/O) к устройству `/dev/loopX` и преобразует их в операции чтения/записи конкретных смещений внутри ассоциированного файла.

**I/O Path через loop-устройство:**
1. Приложение отправляет блочный запрос на `/dev/loopX` (например, через `read()`).
2. Драйвер `loop` перехватывает запрос и вычисляет смещение внутри файла-образа: `file_offset = block_device_offset + loop_offset`.
3. Если включен `Direct I/O`, запрос передается напрямую в page cache файла-образа.
4. Если `Direct I/O` выключен (по умолчанию), данные проходят через page cache хоста, что приводит к двойному кэшированию.
5. ФС, смонтированная на loop-устройстве, работает как с обычным блочным устройством.

### Жизненный цикл устройства

1. **Создание:** При `losetup -f` ядро через `/dev/loop-control` (ioctl `LOOP_CTL_ADD`) выделяет свободный номер `/dev/loopN`.
2. **Привязка:** Устанавливается связь между `/dev/loopN` и файлом-образом. Устанавливаются флаги (`AUTOCLEAR`, `Direct I/O`, `Read-only`).
3. **Использование:** Устройство доступно для форматирования (`mkfs`), монтирования (`mount`) или использования в LVM/cryptsetup.
4. **Разрыв:** При `losetup -d` или `umount` (с `AUTOCLEAR`) связь разрывается, номер возвращается в пул.

### Ключевые механизмы и флаги

- **AUTOCLEAR (`LO_FLAGS_AUTOCLEAR`):** Флаг, указывающий ядру автоматически разорвать связь с файлом и уничтожить устройство сразу после того, как последний процесс закроет дескриптор устройства (обычно после `umount`). Этот флаг включен по умолчанию при использовании `mount -o loop`.
- **Direct I/O:** По умолчанию операции проходят через системный **Page Cache** хоста. Это может привести к «двойному кэшированию» (внутри образа и на хосте). Флаг `--direct-io[=on|off]` позволяет петлевому устройству обращаться к файлу напрямую, снижая нагрузку на CPU и память.
- **Выравнивание и размер сектора:** Для современных накопителей (4K Native) рекомендуется устанавливать логический размер сектора петлевого устройства через `--sector-size=4096`, чтобы избежать штрафа производительности **Read-Modify-Write (RMW)**.
- **Partscan (`-P`):** Флаг, instructing the loop driver to scan the associated file for partition tables and create `/dev/loopNp1`, `/dev/loopNp2`, etc.
- **Offset (`-o`):** Позволяет начать привязку не с начала файла, а с указанного смещения. Используется для доступа к конкретным разделам внутри образа без `-P`.
- **Read-only (`-r`):** Создает устройство только для чтения. Запросы записи возвращают `EROFS`.

### Сравнение методов монтирования

| Функция | `mount -o loop` | Manual `losetup` + `mount` |
| :--- | :--- | :--- |
| **Автоматизация** | Полная (создание, привязка, монтирование) | Ручная |
| **Autoclear** | **Включен** (устройство удалится после umount) | **Выключен** (требует `losetup -d`) |
| **Разделы** | Не поддерживает таблицы разделов напрямую | Поддерживает через `-P` (Partscan) |
| **Контроль** | Ограничен опциями монтирования | Полный (offset, sizelimit, sector-size) |

### Разреженные файлы (Sparse Files)

Разреженный файл содержит "дыры" (holes) — диапазоны байтов, которые не занимают место на диске до первой записи. Для loop-устройств это означает:
- Файл выглядит как диск заданного размера (`truncate -s 10G`), но реальное потребление места начинается с нуля.
- При записи ФС выделяет блоки внутри файла, файл растет.
- Особенно полезно для виртуальных машин и контейнеров, где зарезервировано, но не использовано, много места.

**Важно:** Нельзя создавать разреженные файлы на уже заполненной ФС, если вы планируете записать в них максимальное количество данных — может произойти внезапное исчерпание места.

## Практические сценарии

### 1. Создание и монтирование разреженного диска с Direct I/O

Использование разреженных файлов (Sparse Files) позволяет резервировать место только по мере записи.

```bash
# 1. Создать "пустой" файл на 10 ГБ (реально занимает 0 байт)
truncate -s 10G my_disk.img

# 2. Привязать с Direct I/O и 4K-сектором
# --show выведет имя созданного устройства
DEV=$(sudo losetup --direct-io=on --sector-size=4096 -f --show my_disk.img)

# 3. Форматирование и монтирование
sudo mkfs.xfs "$DEV"
sudo mount "$DEV" /mnt/test
```

### 2. Изменение размера «на лету» (Hot-resize)

Если размер файла-образа увеличился, нужно уведомить ядро об изменении емкости блочного устройства.

```bash
# 1. Увеличить файл
truncate -s +2G my_disk.img

# 2. Обновить емкость устройства в ядре
sudo losetup -c /dev/loop0

# 3. Расширить файловую систему (пример для ext4)
sudo resize2fs /dev/loop0
```

### 3. Работа с образами, содержащими разделы

Если файл является дампом целого диска с таблицей разделов (GPT/MBR), используйте флаг `-P`.

```bash
# Привязать и просканировать таблицу разделов
sudo losetup -P -f --show full_system.img
# -> Выведет: /dev/loop0

# Разделы появятся как отдельные устройства
ls /dev/loop0p*
# -> /dev/loop0p1, /dev/loop0p2
```

### 4. Диагностика и управление

```bash
# Список всех активных устройств в формате JSON (удобно для jq)
losetup -a --json

# Поиск первого свободного устройства
losetup -f

# Принудительная очистка всех неиспользуемых loop-устройств
sudo losetup -D
```

### 5. Монтирование ISO-образа для установки ОС

Loop-устройства часто используются для монтирования ISO-образов дистрибутивов при установке или в PXE-средах.

```bash
# Создать точку монтирования
sudo mkdir -p /mnt/iso

# Монтировать ISO (autoclear включен)
sudo mount -o loop /var/lib/libvirt/iso/ubuntu-22.04.iso /mnt/iso

# Проверить содержимое
ls /mnt/iso
# -> autorun.inf  boot  dists  doc  install  md5sum.txt  pool  preseed

# После использования umount — устройство автоматически удалится
sudo umount /mnt/iso
```

### 6. Swap на файле через loop-устройство

В некоторых средах (контейнеры, ограниченные VPS) требуется создать swap на файле. Loop-устройство обеспечивает правильную выравненность.

```bash
# 1. Создать swap-файл (выравнивание по 4K для производительности)
sudo fallocate -l 4G /swapfile.img
sudo chmod 600 /swapfile.img

# 2. Привязать через losetup с выравниванием
DEV=$(sudo losetup --direct-io=on --sector-size=4096 -f --show /swapfile.img)

# 3. Создать swap
sudo mkswap "$DEV"
sudo swapon "$DEV"

# 4. Добавить в /etc/fstab для постоянства
echo "$DEV none swap sw 0 0" | sudo tee -a /etc/fstab
```

### 7. Тестирование производительности диска (fio на loop)

Loop-устройства позволяют протестировать ФС без выделенного блочного устройства.

```bash
# 1. Создать тестовый образ
truncate -s 2G /tmp/fio_test.img
DEV=$(sudo losetup --direct-io=on --sector-size=4096 -f --show /tmp/fio_test.img)

# 2. Форматировать
sudo mkfs.ext4 -F "$DEV"

# 3. Запустить fio
sudo fio --name=test --filename="$DEV" --ioengine=libaio --direct=1 --rw=randread --bs=4k --numjobs=4 --time_based --runtime=30 --size=1G

# 4. Очистка
sudo losetup -d "$DEV"
```

### 8. Отладка зависших loop-устройств

Иногда после сбоя или некорректного `umount` устройство остается в системе. `losetup -a` показывает его, но файл удален.

```bash
# 1. Найти зависшие устройства
losetup -a
# -> /dev/loop0: [0801]:123456 (/deleted/path/my_disk.img)

# 2. Проверить, используется ли устройство
sudo fuser -v /dev/loop0
# -> USER PID ACCESS COMMAND
# -> root 12345 F... mount

# 3. Освободить устройство
sudo losetup -d /dev/loop0
```

### 9. Автоматизация через systemd

Создание и монтирование loop-устройства можно автоматизировать через systemd-юнит.

```ini
# /etc/systemd/system/mount-loop-data.service
[Unit]
Description=Mount loop device for data
After=local-fs.target

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/usr/bin/losetup --direct-io=on --sector-size=4096 -f --show /var/data/disk.img
ExecStop=/usr/bin/losetup -d /dev/loop0

[Install]
WantedBy=multi-user.target
```

```bash
# Активация
sudo systemctl enable --now mount-loop-data.service

# Проверка
systemctl status mount-loop-data.service
# -> Active: active (running) since ...
```

### 10. Восстановление данных из поврежденного образа

Loop-устройства используются в forensic для монтирования образов дисков без записи.

```bash
# 1. Привязать образ в режиме только чтение
sudo losetup -r -f --show /forensics/sda.img
# -> /dev/loop0

# 2. Если есть разделы, использовать -P
sudo losetup -r -P -f --show /forensics/sda.img
# -> /dev/loop0
ls /dev/loop0p*
# -> /dev/loop0p1

# 3. Монтировать раздел только для чтения
sudo mount -o ro,noload /dev/loop0p1 /mnt/forensics

# 4. Проверить ФС без записи
sudo fsck -n /dev/loop0p1
```

## Безопасность и ограничения

- **Только чтение:** Для защиты эталонных образов используйте `losetup -r` (read-only).
- **Лимиты:** В старых системах количество устройств ограничено параметром `max_loop`. В современных ядрах управляющее устройство `/dev/loop-control` создает узлы динамически.
- **Целостность:** При прямом удалении файла-образа (`rm`) без предварительного `losetup -d` устройство останется в системе в «подвешенном» состоянии, а дескриптор файла будет удерживаться ядром до перезагрузки или ручного удаления устройства.
- **Двойное кэширование:** При отсутствии `Direct I/O` данные кэшируются дважды: в page cache хоста и внутри ФС, смонтированной на loop. Это удваивает потребление RAM. Для больших образов (>10 ГБ) всегда используйте `--direct-io=on`.
- **Root-требования:** Создание loop-устройств требует привилегий root. В контейнерах может потребоваться `--privileged` или `SYS_ADMIN` capability.

## Типичные ошибки и диагностика

| Проблема | Причина и решение |
| :--- | :--- |
| **"No space left on device" при монтировании** | Разреженный файл исчерпал место на хостовой ФС. Проверьте `df -h .` в директории с образом. Увеличьте файл через `truncate` или переместите его на диск с большим свободным местом. |
| **Высокое потребление RAM при работе с образами** | Двойное кэширование (page cache хоста + внутренний кэш ФС). Используйте `--direct-io=on` и/или `mount -o sync,dirsync`. |
| **"Device is busy" при losetup -d** | Устройство смонтировано или используется процессом. Найдите процесс: `sudo fuser -v /dev/loop0` или `lsof /dev/loop0`. Сначала размонтируйте (`umount`), затем удалите устройство. |
| **Ошибка "loop: I/O error" в dmesg** | Файл-образ удален или поврежден. Проверьте `ls -l /proc/$(pgrep -f loop)/fd` для поиска дескриптора. Если файл удален — восстановите из бэкапа или удалите устройство. |
| **Низкая производительность на NVMe хосте** | Отсутствует `--direct-io` или `--sector-size=4096`. Включите оба параметра. Также проверьте, что планировщик I/O на loop-устройстве не `mq-deadline` — для NVMe используйте `none`. |
| **Loop-устройства не создаются (нет /dev/loop-control)** | Модуль `loop` не загружен: `sudo modprobe loop`. В очень старых системах может потребоваться `modprobe max_loop=64`. |
| **Sparse файл внезапно занял много места** | ФС внутри образа записала данные в ранее "дырявые" блоки. Разреженные файлы скрывают реальное потребление места. Используйте `du --apparent-size` для логического размера и `du` для реального. |

## Лучшие практики

### 1. Производительность

- **Всегда используйте `--direct-io=on`** для production-образов объемом >1 ГБ. Это устраняет двойное кэширование.
- **Устанавливайте `--sector-size=4096`** на всех современных дисках (4K Native) и виртуальных машинах. На хостах с 512e дисками можно оставить значение по умолчанию.
- **Для I/O-интенсивных задач** (базы данных, компиляция) используйте `mount -o sync,dirsync` или `O_DIRECT` через `fio`, чтобы обойти page cache хоста полностью.
- **Не монтируйте** образы, к которым нужен только случайный доступ, через `mount -o loop`. Используйте `fuseiso` или монтируйте через `losetup` с отдельным управлением.

### 2. Надежность

- **Используйте `losetup -r`** для всех эталонных/распространяемых образов, чтобы предотвратить случайное изменение.
- **Проверяйте образ перед использованием:** `fsck -n` или `virt-cat`/`guestfish` для виртуальных машин.
- **Делайте бэкапы суперблока** перед изменениями: `sudo dd if=/dev/sda1 of=superblock_backup.bin bs=1M count=1`.
- **Не удаляйте файл-образа**, пока устройство привязано. `AUTOCLEAR` защищает только при `mount -o loop`, но не при ручном `losetup`.

### 3. Мониторинг

- **Отслеживайте привязки:** Добавьте `losetup -a` в мониторинг (Prometheus node exporter, Zabbix) для обнаружения утечек устройств.
- **Логируйте dmesg** на предмет ошибок `loop:`. В production это может указывать на повреждение образа или нехватку места.
- **Следите за `/proc/meminfo`** — если `Dirty` растет без записи на диск при работе с loop-образами, проверьте, не отключен ли writeback.

### 4. Безопасность

- **Ограничивайте права доступа** к файлам-образам: `chmod 600 disk.img`. Это предотвращает чтение данных другими пользователями.
- **Используйте `ro`** для неизменяемых артефактов (ISO, эталонные образы).
- **При работе с конфиденциальными данными** используйте LUKS поверх loop: `cryptsetup luksFormat /dev/loop0`, затем монтируйте расшифрованный mapper-устройство.
- **В контейнерах** запросите только необходимые capabilities (`SYS_ADMIN`, `BLOCK_DEVICE`). Не используйте `--privileged` без необходимости.
