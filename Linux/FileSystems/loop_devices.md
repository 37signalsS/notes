# Петлевые устройства (Loop Devices)

## Определения

- **Loop Device (Петлевое устройство):** Псевдоустройство в ядре Linux (модуль `loop`), которое позволяет представить обычный файл как блочное устройство. Это позволяет монтировать образы дисков, работать с ISO-файлами или создавать зашифрованные контейнеры без выделения физического накопителя.
- **losetup:** Системная утилита для управления связями между файлами и петлевыми устройствами (`/dev/loopX`).
- **loop-control:** Управляющее устройство (`/dev/loop-control`), позволяющее динамически создавать и удалять узлы `/dev/loopN` через системные вызовы (ioctl).

## Основные концепции

### Принцип работы

Драйвер петлевого устройства выступает в роли транслятора: он перехватывает блочные запросы ввода-вывода (I/O) к устройству `/dev/loopX` и преобразует их в операции чтения/записи конкретных смещений внутри ассоциированного файла.

### Ключевые механизмы и флаги

- **AUTOCLEAR (`LO_FLAGS_AUTOCLEAR`):** Флаг, указывающий ядру автоматически разорвать связь с файлом и уничтожить устройство сразу после того, как последний процесс закроет дескриптор устройства (обычно после `umount`). Этот флаг включен по умолчанию при использовании `mount -o loop`.
- **Direct I/O:** По умолчанию операции проходят через системный **Page Cache** хоста. Это может привести к «двойному кэшированию» (внутри образа и на хосте). Флаг `--direct-io[=on|off]` позволяет петлевому устройству обращаться к файлу напрямую, снижая нагрузку на CPU и память.
- **Выравнивание и размер сектора:** Для современных накопителей (4K Native) рекомендуется устанавливать логический размер сектора петлевого устройства через `--sector-size=4096`, чтобы избежать штрафа производительности **Read-Modify-Write (RMW)**.

### Сравнение методов монтирования

| Функция | `mount -o loop` | Manual `losetup` + `mount` |
| :--- | :--- | :--- |
| **Автоматизация** | Полная (создание, привязка, монтирование) | Ручная |
| **Autoclear** | **Включен** (устройство удалится после umount) | **Выключен** (требует `losetup -d`) |
| **Разделы** | Не поддерживает таблицы разделов напрямую | Поддерживает через `-P` (Partscan) |
| **Контроль** | Ограничен опциями монтирования | Полный (offset, sizelimit, sector-size) |

## Практические сценарии

### 1. Создание и монтирование разреженного диска с Direct I/O

Использование разреженных файлов (Sparse Files) позволяет резервировать место только по мере записи.

```bash
# 1. Создать "пустой" файл на 10 ГБ (реально занимает 0 байт)
truncate -s 10G my_disk.img

# 2. Привязать с Direct I/O и 4K-сектором
# --show выведет имя созданного устройства
DEV=$(sudo losetup --direct-io=on --sector-size=4096 -f --show my_disk.img)

# 3. Форматирование и монтирование
sudo mkfs.xfs "$DEV"
sudo mount "$DEV" /mnt/test
```

### 2. Изменение размера «на лету» (Hot-resize)

Если размер файла-образа увеличился, нужно уведомить ядро об изменении емкости блочного устройства.

```bash
# 1. Увеличить файл
truncate -s +2G my_disk.img

# 2. Обновить емкость устройства в ядре
sudo losetup -c /dev/loop0

# 3. Расширить файловую систему (пример для ext4)
sudo resize2fs /dev/loop0
```

### 3. Работа с образами, содержащими разделы

Если файл является дампом целого диска с таблицей разделов (GPT/MBR), используйте флаг `-P`.

```bash
# Привязать и просканировать таблицу разделов
sudo losetup -P -f --show full_system.img
# -> Выведет: /dev/loop0

# Разделы появятся как отдельные устройства
ls /dev/loop0p*
# -> /dev/loop0p1, /dev/loop0p2
```

### 4. Диагностика и управление

```bash
# Список всех активных устройств в формате JSON (удобно для jq)
losetup -a --json

# Поиск первого свободного устройства
losetup -f

# Принудительная очистка всех неиспользуемых loop-устройств
sudo losetup -D
```

## Безопасность и ограничения

- **Только чтение:** Для защиты эталонных образов используйте `losetup -r` (read-only).
- **Лимиты:** В старых системах количество устройств ограничено параметром `max_loop`. В современных ядрах управляющее устройство `/dev/loop-control` создает узлы динамически.
- **Целостность:** При прямом удалении файла-образа (`rm`) без предварительного `losetup -d` устройство останется в системе в «подвешенном» состоянии, а дескриптор файла будет удерживаться ядром до перезагрузки или ручного удаления устройства.
