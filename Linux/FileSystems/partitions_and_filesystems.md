# Разделы и файловые системы

### Что такое файловая система?

**Файловая система (ФС)** — это структура и набор правил, которые определяют, как файлы хранятся на диске и как осуществляется доступ к ним. Без файловой системы диск был бы просто набором неструктурированных блоков.

Ключевые функции файловой системы:

1.  **Таблица файлов (Содержание)**: Каждая ФС имеет аналог "содержания книги" — специальную таблицу (например, **inode table** в Ext4), где хранится информация о каждом файле:
    -   Имя файла.
    -   Атрибуты (права доступа, владелец, временные метки).
    -   Физическое расположение на диске (номера блоков, в которых хранится файл).
    -   Размер файла.

    Благодаря этой таблице системе не нужно сканировать весь диск для поиска файла. Она обращается к таблице, находит нужную "страницу" (блок) и сразу переходит к ней.

2.  **Журналирование**: Современные файловые системы (Ext4, XFS, NTFS) являются **журналируемыми**. Перед выполнением любой операции (например, перемещение файла), система сначала записывает намерение в специальный журнал. Если в процессе операции произойдет сбой (например, отключение питания), после перезагрузки система прочитает журнал, увидит незавершенную транзакцию и либо завершит ее, либо отменит, гарантируя целостность данных.

3.  **Управление пространством**: ФС отслеживает свободные и занятые блоки, решает, куда записать новый файл или его фрагмент.

### Таблицы разделов: MBR vs. GPT

Чтобы использовать диск, его нужно разбить на **разделы (partitions)**. Информация об этих разделах хранится в специальной таблице в самом начале диска.

1.  **MBR (Master Boot Record)**:
 
    -   **Надежность**: Таблица разделов хранится только в одном месте. При ее повреждении восстановить данные сложно.
    -   **Статус**: Устаревший стандарт.

2.  **GPT (GUID Partition Table)**:

    -   **Ограничения**:
        -   Поддерживает до **128 разделов** по умолчанию.
        -   Максимальный размер раздела практически не ограничен (зеттабайты).
    -   **Надежность**: Таблица разделов дублируется в начале и в конце диска, что повышает шансы на восстановление.
    -   **Статус**: Современный стандарт, используется во всех новых системах.

### Практика: работа с разделами с помощью `parted`

`parted` — мощная утилита для управления разделами диска.

**Пример рабочего процесса:**

1.  **Запуск `parted` для конкретного диска:**
    ```bash
    sudo parted /dev/sdb
    ```

2.  **Создание таблицы разделов (если диск новый):**
    ```bash
    # (parted)
    mklabel gpt
    ```

3.  **Создание раздела:**
    ```bash
    # (parted) mkpart [имя_раздела] [тип_фс] [начало] [конец]
    mkpart primary ext4 0% 100%
    ```
    Эта команда создаст один раздел `ext4`, занимающий весь диск.

4.  **Установка флагов раздела:**
    Флаги указывают на специальное назначение раздела.
    -   **Для LVM:**
        ```bash
        (parted) set 1 lvm on
        ```
    -   **Для RAID:**
        ```bash
        (parted) set 1 raid on
        ```

5.  **Просмотр разделов и выход:**
    ```bash
    # (parted)
    print
    # (parted)
    quit
    ```

6.  **Форматирование раздела:**
    После создания раздела его необходимо отформатировать в нужную файловую систему.
    ```bash
    sudo mkfs.ext4 /dev/sdb1
    ```

### Создание файловой системы (`mkfs`)

Создание файловой системы на блочном устройстве (форматирование) выполняется с помощью утилиты `mkfs` (make file system). Эта команда является оберткой для утилит, специфичных для каждой файловой системы (например, `mkfs.ext4`, `mkfs.xfs`).

**Общий синтаксис:**
```bash
# -t указывает тип файловой системы
mkfs -t [тип_фс] [устройство]

# Прямой вызов утилиты для конкретной ФС
mkfs.[тип_фс] [устройство]
```

**Пример для `ext4`:**
```bash
sudo mkfs -t ext4 /dev/sdb1

# или эквивалентно
sudo mkfs.ext4 /dev/sdb1
```

**Основные параметры (`mkfs.ext4`):**

При создании файловой системы можно задать множество параметров, которые влияют на ее производительность и характеристики.

-   `-L label`: Задает текстовую **метку** для файловой системы. Это удобнее, чем запоминать имя устройства.
    ```bash
    sudo mkfs.ext4 -L DATA_DISK /dev/sdb1
    ```
-   `-m reserved-blocks-percentage`: Устанавливает **процент блоков, зарезервированных для суперпользователя (`root`)**. По умолчанию это `5%`. Резерв нужен, чтобы root мог войти в систему для исправления проблем, даже если диск заполнен на 100%. Для дисков с данными (не системных) это значение часто уменьшают до `0` или `1`.
    ```bash
    sudo mkfs.ext4 -m 1 /dev/sdb1
    ```
-   `-b block-size`: Задает **размер блока** в байтах (например, 1024, 2048, 4096). Больший размер блока эффективнее для хранения больших файлов, меньший — для множества мелких. По умолчанию — 4096 байт (4K), что является оптимальным для большинства сценариев.
-   `-N number-of-inodes`: Устанавливает точное **количество индексных дескрипторов (inode)**. Каждый файл или каталог в файловой системе требует одного inode. Если на диске планируется хранить огромное количество мелких файлов, может потребоваться увеличить это значение.
-   `-E extended-options`: Задает **расширенные параметры**, специфичные для `ext4`. Например, для RAID-массивов важны `stride` и `stripe-width`, чтобы выровнять файловую систему относительно геометрии RAID.
    ```bash
    # Пример для RAID5 из 4 дисков с чанком 64K
    # Stride = 64K / 4K = 16
    # Stripe-width = 16 * (4 диска - 1 диск четности) = 48
    sudo mkfs.ext4 -E stride=16,stripe-width=48 /dev/md0
    ```

> **Важно:** Для разных файловых систем (XFS, Btrfs и др.) команды и ключи могут отличаться. Всегда обращайтесь к документации (`man mkfs.xfs`) для конкретной ФС.

### Просмотр блочных устройств (`lsblk`)

Утилита `lsblk` позволяет просмотреть список всех блочных устройств в системе, их размеры, точки монтирования и взаимосвязи (например, разделы, LVM, RAID).

```bash
lsblk
```

Пример вывода `lsblk`:
```
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda           8:0    0     8G  0 disk 
├─sda1        8:1    0   1.8G  0 part /boot
├─sda2        8:2    0     1K  0 part 
└─sda3        8:3    0   6.2G  0 part 
  └─ubuntu--vg-ubuntu--lv 253:0    0   6.2G  0 lvm  /
sdb           8:16   0     1G  0 disk 
└─sdb1        8:17   0   500M  0 part 
```

-   **`NAME`**: Имя устройства.
-   **`TYPE`**: Тип устройства (disk, part, lvm, raid).
-   **`MOUNTPOINTS`**: Точки монтирования.

### Уникальные идентификаторы устройств (UUID)

Для надежного монтирования дисков, особенно в `/etc/fstab`, рекомендуется использовать UUID (Universally Unique Identifier) вместо имен устройств (`/dev/sdb1`). Имена устройств могут меняться при перезагрузке, тогда как UUID остается постоянным.

Утилита `blkid` позволяет просмотреть UUID и другие атрибуты блочных устройств:

```bash
sudo blkid
```

Пример вывода `blkid`:
```
/dev/sda1: UUID="a1b2c3d4-e5f6-7890-1234-567890abcdef" TYPE="ext4" PARTUUID="..."
/dev/sdb1: UUID="b2c3d4e5-f6a7-8901-2345-67890abcdef0" TYPE="ext4" PARTUUID="..."
/dev/mapper/ubuntu--vg-ubuntu--lv: UUID="c3d4e5f6-a7b8-9012-3456-7890abcdef01" TYPE="ext4"
```

### Монтирование файловых систем

**Монтирование** — это процесс, который делает файловую систему на устройстве (например, разделе диска или USB-накопителе) доступной по определённому пути в общей иерархии каталогов.

#### Просмотр примонтированных ФС

Существует несколько способов увидеть, какие файловые системы уже смонтированы.

-   **Способ 1: `mount`**
    Классическая команда. Вывод может быть довольно объемным.
    ```bash
    # Показать все файловые системы
    mount
    
    # Отфильтровать вывод по типу ФС
    mount -t ext4
    ```

-   **Способ 2: `findmnt`**
    Современная утилита, которая выводит информацию в более читаемом древовидном формате.
    ```bash
    findmnt
    ```

-   **Способ 3: `df -hT`**
    Основное назначение — показать свободное место, но также наглядно отображает смонтированные устройства и их типы.
    ```bash
    df -hT
    ```

#### Ручное монтирование

Процесс состоит из двух шагов: создание точки монтирования и непосредственно монтирование.

```bash
# 1. Создание точки монтирования (пустой директории)
sudo mkdir -p /media/usb

# 2. Монтирование устройства
# mount [устройство] [точка_монтирования]
sudo mount /dev/sdd1 /media/usb
```

#### Автоматическое монтирование (`/etc/fstab`)

Для автоматического монтирования при загрузке системы используется файл `/etc/fstab`. В него добавляется строка, описывающая устройство, точку монтирования и параметры.

**Структура записи:**
`<устройство> <точка_монтирования> <тип_фс> <опции> <dump> <pass>`

**Пример:**
```
# Для монтирования по UUID (рекомендуется)
UUID="b2c3d4e5-f6a7-8901-2345-67890abcdef0" /mnt/data ext4 defaults 0 2
```
-   После редактирования `/etc/fstab` можно примонтировать все файловые системы из него командой `sudo mount -a`.
