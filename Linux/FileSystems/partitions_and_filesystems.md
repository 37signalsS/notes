# Разделы и файловые системы в Linux

## Определения

### Файловая система (ФС)

**Файловая система (ФС)** — это [логическая структура и набор правил](fs_internals.md), определяющих способ организации, хранения и именования данных на физических носителях. ФС преобразует набор [неструктурированных блоков](disk_storage_fundamentals.md) в иерархию файлов и директорий.

### Раздел (Partition)

**Раздел** — это логически выделенная область на физическом диске, которая воспринимается ОС как отдельное [блочное устройство](storage_overview.md#Определения). Информация о границах разделов хранится в таблице разделов.

### Таблица разделов (Partition Table)

**Таблица разделов** — структура данных, описывающая разделение диска. Основные стандарты:
- **MBR (Master Boot Record):** Устаревший стандарт (макс. 2 ТБ, 4 основных раздела).
- **GPT (GUID Partition Table):** Современный стандарт (поддержка дисков > 2 ТБ, дублирование таблицы).
Подробное сравнение — в [partition_tables_recovery.md](./partition_tables_recovery.md#Сравнение-стандартов-разметки).

### Монтирование

**Монтирование** — процесс подключения файловой системы к директории (точке монтирования) в общем дереве каталогов. Подробнее см. в [Управление монтированием файловых систем в Linux](./mounting/index.md).

## Основные концепции

### Виртуальная файловая система (VFS)

**Virtual File System (VFS)** — уровень абстракции в ядре Linux, позволяющий работать с различными ФС через единый интерфейс системных вызовов.
- **Преимущество:** ОС скрывает детали реализации конкретной ФС за единым деревом каталогов, начинающимся от корня `/`. Подробнее — в [virtual_filesystems.md](virtual_filesystems.md).

### Структура таблиц разделов (Технические детали)

#### MBR (Master Boot Record)
Располагается в первом секторе диска (512 байт):
- **Код загрузчика (446 байт):** Бинарный код, передающий управление.
- **Таблица разделов (64 байта):** 4 записи по 16 байт каждая.
- **Сигнатура (2 байта):** Всегда `55 AA` (hex), признак загрузочного диска.

#### GPT (GUID Partition Table)
- **Дублирование:** Хранит основную таблицу в начале и **резервную копию в конце диска**, что позволяет восстановить разметку при повреждении.
- **LBA (Logical Block Addressing):** Использует 64-битную адресацию блоков.

### Именование устройств и идентификаторы

#### Имена устройств (нестабильные)
- `/dev/sd[a-z]` — SATA/SCSI/USB-диски. Разделы: `/dev/sdb1`.
- `/dev/nvme[0-N]n[1-M]` — NVMe-накопители. Разделы: `/dev/nvme0n1p1`.
- **Проблема:** Имена (`sda`, `sdb`) зависят от порядка обнаружения ядром и могут меняться при перезагрузке.

#### Постоянные идентификаторы (рекомендуемые)

- **UUID (Universally Unique Identifier):** Уникальный ID **файловой системы**, генерируемый утилитой `mkfs` при форматировании и намертво вшитый в метаданные самой ФС. Вероятность случайного совпадения UUID в мире равна нулю. В отличие от имён `/dev/sdX`, он не привязан к порту материнской платы и не меняется при переименовании дисков или перезагрузке сервера, что критично для стабильности `/etc/fstab` и резервного копирования. Существует в двух форматах: короткий (4 байта HEX, используется BIOS/GPT загрузка) и длинный (8-4-4-4-12, используется ядром и fstab).
- **LABEL:** Текстовая метка (например, `DATA_DISK`).
- **Пути в `/dev/disk/`:**
    - `/dev/disk/by-uuid/` — ссылка по UUID ФС.
    - `/dev/disk/by-id/` — по серийному номеру оборудования.
    - `/dev/disk/by-partuuid/` — ссылка по ID раздела (PARTUUID).
    - `/dev/disk/by-label/` — ссылка по метке (LABEL).

##### UUID vs PARTUUID: ключевое различие

UUID и PARTUUID часто путают, но они относятся к **разным уровням** и **не взаимозаменимы**:

- **UUID** привязан к **файловой системе** — он хранится в её суперблоке.
- **PARTUUID** привязан к **записи раздела в таблице разделов** (GPT или MBR) — он хранится в самой таблице разделов, а не в ФС.

Это значит, что UUID и PARTUUID могут относиться к **разным объектам**: самому диску, его разделу и файловой системе внутри.

**Просмотр обоих идентификаторов вместе:**

```bash
lsblk -o NAME,SIZE,FSTYPE,UUID,PARTUUID,MOUNTPOINTS
```

Пример вывода:

```
NAME      SIZE  FSTYPE  UUID           PARTUUID    MOUNTPOINTS
nvme0n1   500G
├─nvme0n1p1 512M vfat   7A3C-91F2   4f8a...     /boot/efi
└─nvme0n1p2 499G ext4   91c2...       8e21...     /
```

То же самое можно получить через `blkid`:

```bash
blkid /dev/nvme0n1p2
# → /dev/nvme0n1p2: UUID="91c2..." PARTUUID="8e21..." TYPE="ext4"

# Полный вывод атрибутов всех блочных устройств
sudo blkid
# → /dev/sda1: UUID="..." TYPE="ext4" PARTUUID="..."
# → /dev/sdb1: UUID="..." TYPE="xfs" PARTUUID="..."
```
Аббревиатура `blkid` расшифровывается как **block device attributes** (атрибуты блочного устройства). Утилита считывает сигнатуры файловых систем и выводит их UUID, типы и PARTUUID.

**Частые ошибки при выборе инструмента для чтения UUID:**
- `id` — выводит идентификаторы пользователей и групп (UID/GID), а не дисков.
- `uuidgen` — генерирует случайный UUID, но не считывает его с уже существующего блочного устройства.
- Команды вида `fs` для чтения атрибутов дисков в стандартном наборе Linux отсутствуют.
Для получения UUID существующего блочного устройства используйте `blkid`.

**Когда каждый идентификатор меняется:**

- **UUID меняется** при создании новой файловой системы (`mkfs.ext4 /dev/nvme0n1p2`). Раздел остаётся тем же, но его ФС получает новый UUID. После этого запись в `/etc/fstab` с `UUID=...` потеряет ссылку.
- **PARTUUID меняется** при удалении и повторном создании раздела в таблице разделов (новая запись получает новый PARTUUID). Если ФС внутри пересоздать (`mkfs`), PARTUUID обычно сохраняется.

**Влияние на загрузку (Kernel Command Line):**

В параметрах ядра можно указывать корневую ФС двумя способами:

- `root=UUID=91c2...` — ядро и initramfs ищут **файловую систему** с заданным UUID.
- `root=PARTUUID=8e21...` — ядро ищет **конкретный раздел** по его PARTUUID.

Разница важна при **клонировании дисков**: если диск полностью клонируется, структура разделов и их PARTUUID копируются, а UUID файловых систем также совпадают. В результате система может обнаружить не тот экземпляр ФС. Использование `UUID` привязывает загрузку к содержимому ФС, тогда как `PARTUUID` — к физическому разделу.

**Практическое правило:**

- **UUID** отвечает на вопрос «**какую файловую систему найти**» — используется в `/etc/fstab`, `root=UUID=...` и `/dev/disk/by-uuid/`.
- **PARTUUID** отвечает на вопрос «**кой раздел найти**» — используется в `root=PARTUUID=...` и `/dev/disk/by-partuuid/`.

При диагностике загрузки, клонировании дисков и проблемах с `/etc/fstab` всегда уточняйте, какой именно идентификатор задействован и к какому уровню устройства он относится.

### Структуры данных (Inodes)

Каждая ФС (Ext4, XFS) имеет "содержание" — таблицу **[inode (индексных дескрипторов)](links_inodes_dentries.md#Индексный-дескриптор-(Inode))**.
- **Метаданные:** Права, владелец, временные метки, размер, ссылки на блоки данных.
- **Имена:** Имена файлов хранятся не в inode, а в структурах директорий (`dentry`), связывая имя с номером inode.
- **Лимиты:** Исчерпание свободных inode (особенно в Ext4) не позволит создавать файлы даже при наличии свободного места.

### Журналирование

**Журналирование** обеспечивает целостность данных при сбоях. Перед выполнением операции ФС записывает намерение в журнал.
- **Режимы (на примере Ext4):**
    - `data=ordered` (по умолчанию): В журнал пишутся только метаданные, но данные сбрасываются на диск *до* фиксации метаданных.
    - `data=journal`: Полное журналирование данных и метаданных (медленно, максимально надежно).
    - `data=writeback`: Пишутся только метаданные, порядок записи данных не гарантируется (быстро).
Подробнее — в **[Журналирование файловых систем](./journaling.md)**.

### Выравнивание разделов (Alignment)

Современные диски используют физические секторы 4K. Если раздел начинается не с границы физического сектора, производительность записи падает (Read-Modify-Write).
- Современные утилиты (`parted`, `fdisk`) по умолчанию выравнивают разделы по границе 1 МиБ (2048 секторов по 512 байт).

## Практические сценарии

### Анализ и диагностика

```bash
# Список всех блочных устройств и точек монтирования
lsblk -f

# Вывод lsblk (пример):
# NAME   FSTYPE LABEL  UUID                                 MOUNTPOINT
# sda
# ├─sda1 vfat          C321-1234                            /boot/efi
# └─sda2 ext4   ROOT   a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6 /

# Просмотр UUID и типов ФС
sudo blkid

# Анализ свободного места и типов примонтированных ФС
df -hT
```

### Работа с разделами

#### Использование `parted`
```bash
# Запуск для конкретного диска
sudo parted /dev/sdb

# Создание таблицы (LABEL)
(parted) mklabel gpt

# Создание раздела (mkpart [имя] [тип_фс] [начало] [конец])
(parted) mkpart database ext4 1MiB 100%
# 1MiB обеспечивает выравнивание (Alignment)
```

#### Использование `fdisk`
Классическая интерактивная утилита для работы с MBR и GPT. Запускается с указанием диска и переключает сессию в свой собственный командный режим (приглашение `Command m for help`), где управление осуществляется одиночными строчными буквами:

```bash
sudo fdisk /dev/sdb
```

**Главные горячие клавиши меню:**

| Клавиша | Действие | Описание |
| :--- | :--- | :--- |
| `p` | Print | Выводит текущую таблицу разделов на экран. |
| `n` | New | Запускает пошаговый мастер создания нового раздела. |
| `t` | Type | Позволяет изменить системный ID раздела (например, с `83` на `1` для загрузочного). |
| `d` | Delete | Удаляет выбранную запись раздела из таблицы. |
| `w` | Write | Записывает все накопленные изменения на физический диск и завершает работу. |
| `q` | Quit | Выход из утилиты **без сохранения** изменений. |

**Важно:** Все манипуляции до нажатия `w` выполняются исключительно в оперативной памяти, их можно безопасно отменить командой `q`. Только `w` фиксирует таблицу разделов в первом секторе диска.

**Пример создания первого раздела:**
```bash
sudo fdisk /dev/sdc
# Ввод: p (посмотреть текущую таблицу — пусто)
# Ввод: n (новый раздел)
# Ввод: n (первичный), Enter (номер 1), Enter (начальный сектор — по умолчанию), Enter (конечный сектор — по умолчанию)
# Ввод: p (проверить — появился раздел /dev/sdc1)
# Ввод: w (записать изменения на диск)
```

#### Использование `gdisk` (GPT Fdisk)
Современный аналог `fdisk`, предназначенный исключительно для работы со стандартом GPT. Поддерживает диски объемом более 2 ТБ и сохраняет все привычные горячие клавиши семейства fdisk:

```bash
sudo gdisk /dev/sdb
```

**Клавиши, общие с `fdisk`:** `p` (print), `n` (new), `w` (write), `q` (quit без сохранения).

**Дополнительные клавиши:**
- `d` (delete) — удаление раздела. Критически важна при работе с дисками, где старый раздел перекрывает область резервной копии GPT (Secondary Header) в конце диска.
- `r` (recovery/transformation) — вход в экспертный режим восстановления GPT.

**Особенности работы с GPT:**
При запуске на диске, где старая разметка перекрывает резервную таблицу GPT (расположенную в последних 33 секторах), утилита выдаст предупреждение и не даст записать таблицу. Типичный сценарий исправления:

```bash
sudo gdisk /dev/sdc
# Ввод: d (удалить конфликтный раздел)
# Ввод: n (создать новый раздел, значения по умолчанию)
# Ввод: w (записать)
# Подтверждение: Y (заглавная) + Enter
```

После очистки конфликтного раздела `gdisk` автоматически рассчитывает корректные отступы и оставляет законные 33 сектора в конце диска под зеркальную копию таблицы.

### Создание файловой системы (`mkfs`)

Универсальная команда `mkfs` — сокращение от **Make File System**. Она создаёт файловую систему на уже размеченном разделе. Без этого шага раздел остаётся «голым куском железа», и записать на него данные нельзя.

Синтаксис:
```bash
mkfs.<тип> <устройство>
```
Например:
```bash
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.xfs /dev/sdb1
```

#### EXT4 — универсальный стандарт

**Ext4** — классический выбор по умолчанию для дистрибутивов **Ubuntu** и **Debian**. Она стабильная, проверенная временем и отлично работает на домашних ПК и небольших серверах.

```bash
# Создание с меткой (-L) и резервом для root 1% (-m)
sudo mkfs.ext4 -L DATA_DISK -m 1 /dev/sdb1
```

**Ключевые параметры `mkfs.ext4`:**
- `-b block-size`: Размер блока (1024, 2048, 4096).
- `-N number-of-inodes`: Точное количество inode.
- `-E extended-options`: Расширенные параметры (например, для RAID).
    ```bash
    # Пример для RAID5 (4 диска, чанк 64K): Stride=16, Stripe-width=48
    sudo mkfs.ext4 -E stride=16,stripe-width=48 /dev/md0
    ```

#### XFS — высокопроизводительный стандарт

**XFS** — высокопроизводительная файловая система, которая по умолчанию ставится в **Red Hat**, **CentOS** и **Rocky Linux**. Она создавалась специально для огромных серверных хранилищ, массивов данных и умеет обрабатывать файлы на высокой скорости.

```bash
# Принудительное форматирование (-f) — стирает предыдущую ФС на устройстве
sudo mkfs.xfs -f /dev/sdb1

# Создание с меткой
sudo mkfs.xfs -L DATA_XFS /dev/sdb1
```

**Типичные ошибки при выборе команды форматирования:**
- `make fs` — такой команды в Linux нет. Это вариант-ловушка для новичков.
- `fs` — команды `fs` для форматирования в стандартном наборе Linux отсутствуют.
- `format` — в Linux нет команды `format` для дисков; это утилита из DOS/Windows.
Для форматирования разделов используйте `mkfs.<тип>` в нижнем регистре.

### Тюнинг и обслуживание (tune2fs)

Утилита `tune2fs` позволяет изменять параметры существующих ФС Ext2/3/4 без потери данных.
```bash
# Просмотр параметров ФС
sudo tune2fs -l /dev/sdb1

# Изменение метки
sudo tune2fs -L NEW_LABEL /dev/sdb1

# Отключение резервирования для root (для дисков с данными)
sudo tune2fs -m 0 /dev/sdb1
```

### Проверка файловой системы (fsck)
**ВНИМАНИЕ:** Проверка выполняется только на **отмонтированной** ФС.
```bash
sudo umount /dev/sdb1
sudo fsck.ext4 -f /dev/sdb1
```
Подробнее — в [fsck.md](./fsck.md).

## Дополнительная информация

### Резервированное пространство для root (Root Reserved Space)
В Ext-системах по умолчанию резервируется 5%.
- **Зачем:** Предотвращение полной остановки системы (логи, работа демонов) при заполнении диска пользователями.
- **Для данных:** На терабайтных дисках 5% — это десятки гигабайт. Рекомендуется снижать до `0` или `1` через `tune2fs -m`.

### Фрагментация
`ext4` использует extent-based allocation и multi-block allocation, что значительно снижает фрагментацию. Однако при заполнении диска >90% фрагментация может расти.

### Кросс-платформенная совместимость
- **Linux → Windows:** NTFS/FAT32/exFAT поддерживаются через `ntfs-3g` ([FUSE](./fuse.md)). Корневая ФС Linux на NTFS невозможна (нет POSIX-прав).
- **Windows → Linux:** Ext4/XFS нативно не поддерживаются. Доступ через WSL2 или сторонние драйверы.
