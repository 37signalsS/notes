# Разделы и файловые системы в Linux

## Определения

### Файловая система (ФС)

**Файловая система (ФС)** — это [структура и набор правил](fs_internals.md), которые определяют, как файлы хранятся на диске и как осуществляется доступ к ним. Без файловой системы диск был бы просто набором [неструктурированных блоков](disk_storage_fundamentals.md).

### Разделы и таблицы разделов

Диск разбивается на **разделы (partitions)**. Информация о разделах хранится в таблице разделов. Два стандарта: [MBR](./partition_tables_recovery.md) и [GPT](./partition_tables_recovery.md). Сравнение — в [partition_tables_recovery.md](./partition_tables_recovery.md#сравнение-mbr-и-gpt).

### Монтирование

**Монтирование** — это процесс, который делает файловую систему на устройстве (например, разделе диска или USB-накопителе) доступной по определённому пути в общей иерархии каталогов. Подробное описание концепции и практических сценариев монтирования файловых систем см. в [Управление монтированием файловых систем в Linux](./mounting/index.md).

## Основные концепции

### Ключевые функции файловой системы

1. **Таблица файлов (Содержание)**: Каждая ФС имеет аналог "содержания книги" — специальную таблицу (например, **[inode table](links_inodes_dentries.md#Inode-Индексный-дескриптор)** в Ext4), где хранится информация о каждом файле:
    - Имя файла.
    - Атрибуты (права доступа, владелец, временные метки).
    - Физическое расположение на диске (номера блоков, в которых хранится файл).
    - Размер файла.

    Благодаря этой таблице системе не нужно сканировать весь диск для поиска файла. Она обращается к таблице, находит нужную "страницу" (блок) и сразу переходит к ней.

2. **Журналирование**: Современные файловые системы (Ext4, XFS, NTFS) являются **журналируемыми**. Перед выполнением любой операции (например, перемещение файла), система сначала записывает намерение в специальный журнал. Если в процессе операции произойдет сбой (например, отключение питания), после перезагрузки система прочитает журнал, увидит незавершенную транзакцию и либо завершит ее, либо отменит, гарантируя целостность данных.

    Подробнее о механизме журналирования, режимах работы и влиянии на производительность см. в **[Журналирование файловых систем](./journaling.md)**.

3. **Управление пространством**: ФС отслеживает свободные и занятые блоки, решает, куда записать новый файл или его фрагмент.

### Зарезервированное пространство для root (Root Reserved Space)

#### Зачем файловые системы ext* резервируют 5% места?

**Зарезервированное пространство для root** — это часть дискового пространства в файловых системах Ext (ext2, ext3, ext4), которая по умолчанию (обычно 5%) выделяется для использования исключительно пользователем `root`.

- **Цель:** Обеспечить стабильность и работоспособность системы в условиях, когда диск полностью заполнен обычными пользователями. Это позволяет `root`-процессам (например, системному журналированию, работе демонов, критическим обновлениям) продолжать функционировать, предотвращая полный отказ системы.
- **Конфигурация:** Параметр `-m` утилиты `mkfs.ext4` или `tune2fs` на существующей ФС. Подробнее — в [Создание файловой системы (`mkfs`)](#создание-файловой-системы-mkfs).

## Практические сценарии

### Работа с разделами

#### Конфигурация mkfs по умолчанию: `mke2fs.conf`

Утилиты `mkfs.ext4` и другие используют файл конфигурации `/etc/mke2fs.conf` для установки параметров по умолчанию (размер блока, количество inodes и т.д.).

#### Создание разделов с помощью `parted`

1. **Запуск `parted` для конкретного диска:**

    ```bash
    sudo parted /dev/sdb
    ```

2. **Создание таблицы разделов (если диск новый):**

    ```bash
    # (parted)
    mklabel gpt
    ```

3. **Создание раздела:**

    ```bash
    # (parted) mkpart [имя_раздела] [тип_фс] [начало] [конец]
    mkpart database ext4 0% 100%
    # Пример: создание раздела с именем "database" для ext4, занимающего весь диск.
    # Можно также указать конкретный размер, например: mkpart primary ext4 1MiB 10.7GB
    ```

    Эта команда создаст раздел `ext4`.

#### Создание файловой системы (`mkfs`)

**Пример для `ext4`:**

```bash
sudo mkfs.ext4 /dev/sdb1
```

> **Примечание:** Файловая система `ext4` часто рекомендуется для хранения баз данных (например, PostgreSQL) благодаря своей стабильности, производительности и хорошей поддержке в Linux.

**Основные параметры (`mkfs.ext4`):**

- `-L label`: Задает текстовую **метку** для файловой системы. Это удобнее, чем запоминать имя устройства.

    ```bash
    sudo mkfs.ext4 -L DATA_DISK /dev/sdb1
    ```

- `-m reserved-blocks-percentage`: Устанавливает **процент блоков, зарезервированных для `root`**. По умолчанию `5%`. Это пространство предназначено для того, чтобы критически важные системные процессы (например, запись логов) могли продолжать функционировать даже при полном заполнении диска обычными данными. Пользователь `root` может использовать это зарезервированное пространство. Для дисков с данными (не системных) это значение часто уменьшают до `0` или `1` для увеличения доступного места.

    ```bash
    sudo mkfs.ext4 -m 1 /dev/sdb1
    ```

- `-b block-size`: Задает **размер блока** в байтах (например, 1024, 4096). Больший размер эффективнее для больших файлов, меньший — для множества мелких.
- `-N number-of-inodes`: Устанавливает точное **количество [inode](links_inodes_dentries.md#Inode-Индексный-дескриптор)**. Если планируется хранить огромное количество мелких файлов, может потребоваться увеличить это значение.
- `-E extended-options`: Задает **расширенные параметры**. Например, для RAID-массивов важны `stride` и `stripe-width`.

    ```bash
    # Пример для RAID5 из 4 дисков с чанком 64K (Stride = 16, Stripe-width = 48)
    sudo mkfs.ext4 -E stride=16,stripe-width=48 /dev/md0
    ```

### Просмотр информации о дисках и файловых системах

#### Просмотр блочных устройств (`lsblk`)

Утилита `lsblk` позволяет просмотреть список всех блочных устройств, их размеры, точки монтирования и взаимосвязи. Она особенно полезна для быстрого выявления новых, еще не размеченных физических дисков, которые могли быть добавлены в систему.

```bash
lsblk
```

Пример вывода:

```
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda           8:0    0     8G  0 disk
├─sda1        8:1    0   1.8G  0 part /boot
└─sda3        8:3    0   6.2G  0 part
  └─ubuntu--vg-ubuntu--lv 253:0    0   6.2G  0 lvm  /
sdb           8:16   0     1G  0 disk
└─sdb1        8:17   0   500M  0 part
```

- **`NAME`**: Имя устройства.
- **`TYPE`**: Тип устройства (disk, part, lvm, raid).
- **`MOUNTPOINTS`**: Точки монтирования.

### Именование устройств и постоянные идентификаторы

#### Проблема нестабильных имен устройств

В Linux устройства хранения именуются по алфавиту (`sda`, `sdb`, `sdc` и т.д.) в зависимости от порядка их обнаружения ядром. **Эти имена непостоянны** — при перезагрузке, переподключении дисков или изменении конфигурации оборудования одно и то же физическое устройство может получить другое имя (например, `sdb` может стать `sdc`). Это может привести к потере данных при неправильном монтировании.

Для решения этой проблемы используются постоянные идентификаторы:

- **UUID (Universally Unique Identifier)**: Уникальный 128-битный идентификатор, присваиваемый файловой системе или разделу при создании.
- **LABEL**: Текстовая метка, которую можно задать при создании файловой системы.
- **ID устройства из `/dev/disk/by-id`**: Постоянные символические ссылки на основе идентификаторов оборудования.
- **Путь к устройству `/dev/disk/by-path`**: Постоянные ссылки на основе физического пути к устройству.

Просмотр идентификаторов:

```bash
# Просмотр UUID и LABEL
sudo blkid

# Просмотр ссылок в /dev/disk
ls -la /dev/disk/by-uuid/
ls -la /dev/disk/by-id/
```

Рекомендуется использовать `UUID` в файлах `/etc/fstab` для надежного монтирования разделов.

#### Просмотр примонтированных ФС и свободного места

- **`mount`**: Классическая команда, показывает все файловые системы.

    ```bash
    mount | column -t
    ```

- **`findmnt`**: Современная утилита с древовидным выводом.

    ```bash
    findmnt
    ```

- **`df -hT`**: Показывает свободное место, точки монтирования и типы ФС. Подробнее об утилите `df` см. в [Диагностика файловой системы и дискового пространства](../Diagnostics/Filesystem/filesystem_and_disk_space_diagnostics.md#df-анализ-свободного-пространства).

    ```bash
    df -hT
    ```

Для получения подробной информации о монтировании — [mounting/index.md](./mounting/index.md).

### Расширение разделов и файловых систем

Процесс увеличения емкости диска включает в себя расширение самого раздела и последующую адаптацию файловой системы. Подробные инструкции для различных сценариев (growpart, LVM, fdisk, parted) см. в разделе **[Расширение дискового пространства в Linux](./disk_expansion.md)**.

### Уменьшение файловых систем (ext2/3/4)

### Фрагментация ext3 и ext4

`ext4` использует extent-based allocation (выделение непрерывных экстентов) и multi-block allocation, что снижает фрагментацию по сравнению с FAT32/NTFS. Полностью избежать её невозможно при интенсивной записи/удалении.

### Кросс-платформенная совместимость

- **Linux → Windows ФС:** NTFS/FAT32/exFAT читаются и записываются через `ntfs-3g` ([FUSE](./fuse.md)). Установить корневую ФС Linux на NTFS невозможно — нет поддержки POSIX-прав.
- **Windows → Linux ФС:** Ext4/XFS не поддерживаются Windows нативно. Доступ через WSL2 или сторонние драйверы.
