# VFS и Псевдофайловые системы

## 1. Определения

-   **VFS (Virtual File System)**: Слой абстракции в ядре Linux, который предоставляет единый интерфейс (API) для взаимодействия с различными типами файловых систем. Благодаря VFS, приложения используют стандартные системные вызовы (`open`, `read`, `write`) для работы с файлами, не задумываясь о том, какая ФС используется — `ext4`, `NFS` или псевдо-ФС.

-   **Псевдофайловая система**: Тип файловой системы, которая взаимодействует с VFS, но не управляет данными на физическом устройстве хранения. Ее содержимое генерируется ядром "на лету" и хранится в оперативной памяти, предоставляя доступ к системной информации и параметрам ядра.

## 2. Основные концепции

Ключевая идея псевдофайловых систем — предоставление доступа к внутренним данным и функциям ядра через привычный файловый интерфейс. Это позволяет пользователям и программам просматривать и изменять системные параметры с помощью стандартных утилит (`cat`, `echo`, `ls`).

Когда происходит чтение файла из такой системы (например, `cat /proc/meminfo`), ядро не обращается к диску. Вместо этого оно перехватывает запрос, собирает необходимую информацию из своих внутренних структур данных и возвращает ее в виде содержимого файла.

## 3. Практические примеры

Ниже перечислены ключевые псевдофайловые системы в Linux.

-   **`procfs`** (монтируется в `/proc`): Предоставляет детальную информацию о процессах и состоянии системы.
    -   **См. подробнее:** [Виртуальная файловая система /proc (procfs)](./virtual_fs_proc.md)

-   **`sysfs`** (монтируется в `/sys`): Отображает иерархию устройств и драйверов, позволяя просматривать их состояние и изменять параметры.
    -   **См. подробнее:** [Виртуальная файловая система /sys (sysfs)](./virtual_fs_sys.md)

-   **`devtmpfs`** (монтируется в `/dev`): Динамически создает файлы устройств (например, `/dev/sda`, `/dev/tty1`), обеспечивая интерфейс для взаимодействия с аппаратным обеспечением.

-   **`tmpfs`**: Файловая система, полностью находящаяся в оперативной памяти. Используется для каталогов `/tmp`, `/run`, а также для реализации разделяемой памяти (`/dev/shm`).
    -   **См. подробнее:** [Другие виртуальные ФС](./other_virtual_fs.md)
