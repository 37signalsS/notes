# Внутреннее устройство файловых систем

## Определения

- **Файловая система (FileSystem, ФС):** Набор алгоритмов и структур данных, определяющих способ организации, хранения и именования данных на блочных устройствах.
- **VFS (Virtual File System):** Слой программной абстракции в ядре Linux, предоставляющий приложениям унифицированный интерфейс (POSIX) для работы с разнородными файловыми системами.
- **Объект ФС (FS Object):** Структурная единица VFS (например, `inode` или `dentry`), представляющая конкретный элемент файловой иерархии в памяти ядра.

## Архитектура VFS

VFS позволяет ядру поддерживать сотни типов ФС (дисковые, сетевые, виртуальные), скрывая детали реализации за стандартными объектами.

### Четыре фундаментальных объекта VFS

| Объект | Структура в ядре | Описание |
| :--- | :--- | :--- |
| **Superblock** | `struct super_block` | Описывает состояние всей смонтированной ФС (тип, размер, флаги). |
| **Inode** | `struct inode` | Описывает конкретный файл (права, метаданные, физическое расположение). |
| **Dentry** | `struct dentry` | Описывает компонент пути и связывает имя файла с его Inode (кэширует иерархию). |
| **File** | `struct file` | Описывает открытый процессом файл (позиция чтения/записи, режим доступа). |

### Путь запроса ввода-вывода (I/O Path)

1.  **Userspace:** Приложение вызывает `read(fd, buf, len)`.
2.  **VFS:** Находит `struct file` по дескриптору `fd`, обращается к связанному `inode`.
3.  **Page Cache:** Проверяет наличие данных в оперативной памяти. Если данных нет — инициирует чтение.
4.  **FS Driver:** Преобразует логическое смещение в файле в адреса физических блоков (LBA) на диске.
5.  **Block Layer:** Формирует структуру `bio` (Block I/O) и передает её планировщику (I/O Scheduler) и драйверу устройства.

## Основные компоненты

### Суперблок и его резервирование

Суперблок — критическая точка отказа. Для защиты от повреждений файловые системы (особенно ext4) дублируют его в начале каждой группы блоков.
- Содержит: `magic number` (для идентификации типа ФС), количество свободных блоков/inode, размер блока.

### Кэширование: Page Cache vs Buffer Cache

В современных ядрах Linux (2.4+) эти кэши объединены.
- **Page Cache:** Кэширует целые страницы памяти с данными файлов.
- **Buffer Cache:** Работает на уровне блоков диска. Используется VFS для кэширования метаданных (суперблоков, индексов), которые не вписываются в концепцию страниц файлов.

## Практические сценарии

### 1. Анализ смонтированных ФС через findmnt

Утилита `findmnt` предоставляет более детальную информацию о VFS-параметрах, чем классический `mount`.

```bash
# Показать дерево монтирования с типами ФС и опциями
findmnt -t ext4,xfs

# Проверить флаги монтирования конкретного раздела
findmnt -no SOURCE,TARGET,OPTIONS /
```

### 2. Глубокое исследование ext4 через debugfs

Для анализа повреждений или поиска удаленных файлов на ext2/3/4 используется `debugfs`.

```bash
# Открыть ФС в режиме только для чтения
sudo debugfs -R "stats" /dev/sda1 | grep "Filesystem features"

# Просмотр содержимого конкретного inode
sudo debugfs -R "stat <2>" /dev/sda1
```

### 3. Восстановление суперблока XFS

В XFS используется `xfs_db` для инспекции и `xfs_repair` для восстановления.

```bash
# Просмотр первичного суперблока
sudo xfs_db -c "sb 0" -c "p" /dev/sda1

# Если первичный суперблок поврежден, XFS автоматически ищет копии при xfs_repair
sudo xfs_repair /dev/sda1
```
