# Внутреннее устройство файловых систем

## Определения

- **Файловая система (с точки зрения ОС):** На уровне операционной системы файловая система реализуется как **драйвер** или **модуль ядра**. Этот модуль предоставляет стандартизированный API (например, системные вызовы `open`, `read`, `write`), через который пользовательские программы могут взаимодействовать с файлами, не вникая в детали их физического хранения на устройстве.

- **Page Cache (Кэш страниц):** Область в оперативной памяти (RAM), хранящая копии данных с диска (страницы файлов) для ускорения доступа.

- **Суперблок (Superblock):** Ключевая структура метаданных, описывающая состояние файловой системы (размер, количество блоков, расположение inode'ов).

## Основные концепции

### Page Cache

Ядро Linux использует Page Cache для кэширования дисковых операций, минимизируя обращения к медленным дисковым устройствам.

- **Чтение:** Данные файла при первом чтении копируются с диска в Page Cache. Последующие чтения происходят напрямую из RAM.
- **Запись:** Данные сначала записываются в Page Cache, затем ядро в фоновом режиме асинхронно сбрасывает их на диск.
- **Управление:** Page Cache не удаляется из памяти, пока она не потребуется для других задач. Он динамически регулируется ядром.

### Суперблок

Суперблок критически важен для монтирования и корректной работы файловой системы. Он содержит:

- Тип и размер файловой системы.
- Размер блока.
- Количество свободных и занятых [блоков](disk_storage_fundamentals.md) и [inode'ов](links_inodes_dentries.md#inode-индексный-дескриптор).
- Точку монтирования и статус ("чистая" или "грязная").

Из-за его важности файловая система хранит несколько резервных копий суперблока.

## Практические сценарии

### Наблюдение за Page Cache

- Использование утилиты `free` для просмотра объема памяти, выделенного под Page Cache:

    ```bash
    free -m
    ```

    Значение в колонке `buff/cache` показывает этот объем.

### Просмотр информации о суперблоке

- Для файловых систем Ext2/3/4 информацию из суперблока можно прочитать с помощью `dumpe2fs`:

    ```sh
    sudo dumpe2fs /dev/sda1 | grep -i superblock
    ```

    Эта команда покажет расположение основного суперблока и его резервных копий.

## Дополнительная информация

Фундаментальные структуры файловой системы, такие как [Inode и Dentry](links_inodes_dentries.md), тесно связаны с внутренним устройством ФС. Управление памятью для ядерных объектов осуществляется через [Slab Allocator](../Core/memory/slab_allocator.md). Обзор различных файловых систем и их функций представлен в [Разделах и файловых системах в Linux](partitions_and_filesystems.md), а детальное сравнение типов ФС (ext4, XFS, Btrfs, ZFS, F2FS) — в [Сравнительном обзоре типов ФС](./filesystem_types_comparison.md).

Механизм [Page Cache](../Core/memory/caching_and_reclaiming.md) реализуется на уровне виртуальной файловой системы [VFS](./virtual_filesystems.md). Настройка [writeback кэша](../Diagnostics/Performance/DiskIO/writeback_tuning.md) влияет на скорость сброса dirty pages на диск.
