# Внутреннее устройство файловых систем

## Определения

- **Файловая система (FileSystem, ФС):** На уровне операционной системы реализуется как драйвер или модуль ядра. Предоставляет стандартизированный **API (Application Programming Interface)** через системные вызовы (например, `open`, `read`, `write`), абстрагируя детали физического хранения данных на накопителе.
- **VFS (Virtual File System — виртуальная файловая система):** Слой абстракции в ядре Linux, обеспечивающий единый интерфейс для работы с различными типами ФС. Подробнее: [Виртуальные файловые системы](./virtual_filesystems.md).
- **Суперблок (Superblock):** Ключевая структура метаданных, описывающая состояние и параметры всей файловой системы (размер, количество блоков, расположение таблиц метаданных).

## Основные концепции

### Взаимодействие ядра с файловой системой

Процесс обращения к данным проходит через несколько уровней абстракции:

1. **VFS:** Унифицирует системные вызовы, преобразуя их в операции над объектами ФС (inode, dentry).
2. **Page Cache:** Кэширует данные файлов в оперативной памяти для ускорения повторного доступа. Подробнее: [Кэширование и освобождение памяти](../Core/memory/caching_and_reclaiming.md).
3. **Драйвер конкретной ФС (Ext4, XFS, Btrfs):** Реализует логику размещения данных на блочном устройстве согласно своей спецификации.

### Суперблок

Суперблок — это "паспорт" файловой системы, необходимый для её монтирования. Он содержит критическую информацию:

- Тип файловой системы и её общий размер.
- Размер логического блока.
- Статус ФС (чистая, грязная, с ошибками).
- Количественные показатели: свободные и занятые [блоки данных](./disk_storage_fundamentals.md), а также [индексные дескрипторы (Inode)](./links_inodes_dentries.md).
- Параметры монтирования по умолчанию.

Файловые системы обычно хранят несколько резервных копий суперблока в разных частях раздела для возможности восстановления при повреждении основного.

## Практические сценарии

### Просмотр метаданных суперблока

#### Для файловых систем Ext2/Ext3/Ext4

Утилита `dumpe2fs` позволяет прочитать информацию из суперблока и найти его резервные копии:

```bash
# Просмотр расположения основного и резервных суперблоков
sudo dumpe2fs /dev/sda1 | grep -i superblock
```

#### Для файловой системы XFS

Используется интерактивная утилита `xfs_db` в режиме "только чтение" (`-r`):

```bash
sudo xfs_db -r /dev/sda1
xfs_db> sb 0    # Перейти к суперблоку 0
xfs_db> p       # Вывести (print) содержимое
```

### Взаимосвязь структур

Внутреннее устройство ФС опирается на иерархию структур метаданных:

- **[Индексные дескрипторы (Inode) и записи каталогов (Dentry)](./links_inodes_dentries.md):** Описывают отдельные файлы и связи между ними.
- **[Журналирование ФС](./journaling.md):** Обеспечивает целостность метаданных при сбоях.
- **[Сравнение типов ФС](./filesystem_types_comparison.md):** Различия в реализации внутренних структур у Ext4, XFS и Btrfs.

Настройка параметров ядра для управления кэшированием (writeback) и "грязными" страницами описана в материале [Настройка writeback кэша](../Diagnostics/Performance/DiskIO/writeback_tuning.md).
