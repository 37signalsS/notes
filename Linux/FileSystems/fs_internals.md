# Внутреннее устройство файловых систем

## Определения

- **Файловая система (FileSystem, ФС):** Набор алгоритмов и структур данных, определяющих способ организации, иерархического хранения и именования данных на блочных устройствах.
- **VFS (Virtual File System):** Высокоуровневый слой абстракции в ядре Linux, предоставляющий приложениям унифицированный интерфейс (POSIX API) для взаимодействия с разнородными ФС (ext4, XFS, NFS, procfs).
- **Объект VFS:** Абстрактная структура данных в памяти ядра, представляющая элемент ФС. Основные объекты: Superblock, Inode, Dentry, File.
- **Экстент (Extent):** Непрерывный диапазон физических блоков на диске, описываемый парой «начальный блок + длина». Современная альтернатива поблочному маппингу, снижающая фрагментацию и размер метаданных.

## Архитектура VFS

VFS преобразует абстрактные системные вызовы (например, `read()`) в вызовы конкретных функций драйвера ФС через таблицы указателей на функции.

### Фундаментальные объекты VFS

| Объект | Структура в ядре | Описание | Основные операции (`_ops`) |
| :--- | :--- | :--- | :--- |
| **Superblock** | `struct super_block` | Описывает состояние смонтированной ФС. | `write_super`, `put_super`, `statfs`. |
| **Inode** | `struct inode` | Метаданные конкретного файла (права, размер, время). | `create`, `lookup`, `mkdir`, `setattr`. |
| **Dentry** | `struct dentry` | Связующее звено между именем файла и его Inode. | `d_compare`, `d_delete`, `d_release`. |
| **File** | `struct file` | Состояние открытого файла процессом (курсор, флаги). | `read`, `write`, `mmap`, `fsync`. |

Пример таблицы операций (`struct file_operations`) позволяет ядру вызывать `ext4_file_read` или `xfs_file_read` прозрачно для приложения.

### Путь запроса ввода-вывода (I/O Path)

1.  **Userspace:** Приложение вызывает `read(fd, buf, len)`.
2.  **VFS:** Находит `struct file` по дескриптору `fd`, проверяет права и обращается к связанному `inode`.
3.  **Page Cache:** Ядро ищет данные в оперативной памяти (Pages). Если данные найдены (Cache Hit), они копируются в буфер приложения.
4.  **FS Driver:** При промахе (Cache Miss) драйвер ФС преобразует логическое смещение в файле в адреса физических блоков (LBA) с помощью **экстентов** или карт блоков.
5.  **Block Layer:** Формирует структуру `bio` (Block I/O), которая передается планировщику (I/O Scheduler) и затем драйверу блочного устройства.

## Основные компоненты

### Физическая организация: Группы и области

Файловые системы делят диск на крупные логические области для локализации данных и метаданных, что снижает перемещение головок HDD.

- **Block Groups (ext4):** Диск делится на группы фиксированного размера. Каждая группа содержит копию суперблока (опционально), битовые карты блоков/инод и таблицу инод. Это позволяет хранить метаданные рядом с данными файла.
- **Allocation Groups (XFS):** Аналог групп блоков, но с поддержкой параллельного доступа. Каждая AG имеет собственные структуры управления свободным пространством (B+ деревья), что позволяет XFS эффективно масштабироваться на многоядерных системах.

### Кэширование и целостность

В современных ядрах (2.4+) Page Cache и Buffer Cache интегрированы.
- **Page Cache:** Кэширует данные файлов страницами (обычно 4 КБ).
- **Buffer Cache:** Используется для кэширования метаданных (структур управления ФС), которые не кратны размеру страницы или относятся к сырому блочному устройству.
- **Writeback:** Механизм отложенной записи «грязных» страниц из RAM на диск. Параметры тюнинга описаны в [настройке Page Cache](../Diagnostics/Performance/DiskIO/writeback_tuning.md).

## Практические сценарии

### 1. Анализ топологии ФС через `findmnt`

Утилита позволяет увидеть иерархию монтирования и специфические VFS-флаги.

```bash
# Показать дерево монтирования с источниками и опциями
findmnt -D

# Проверить статус "readonly" и параметры журналирования
findmnt -no TARGET,OPTIONS /
```

### 2. Глубокое исследование метаданных (debugfs)

Для ext4 можно просмотреть структуру конкретного инода и его экстентов.

```bash
# Просмотр карты экстентов файла
sudo debugfs -R "extents /etc/passwd" /dev/sda1
# → Level 0: 1 1 542456 -- показывает диапазон блоков
```

### 3. Диагностика суперблоков (XFS)

XFS хранит суперблок в начале каждой Allocation Group.

```bash
# Инспекция геометрии ФС
sudo xfs_info /mnt/data

# Проверка состояния свободных блоков в AG
sudo xfs_db -c "freesp" /dev/sda1
```
