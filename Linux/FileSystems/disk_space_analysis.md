# Анализ дискового пространства

### Свободное место (`df`)



### Увеличение количества inodes (Ext2/3/4)

**Проблема:** В файловых системах семейства `Ext` (Ext2, Ext3, Ext4) количество inodes (индексных дескрипторов) **фиксируется в момент форматирования раздела**. Изменить это значение на уже существующей файловой системе без её пересоздания **невозможно**. Если у вас закончились inodes, вы не сможете создавать новые файлы, даже если на диске много свободного места.

**Решение:** Единственный способ — это создать резервную копию данных, переформатировать раздел с новыми параметрами и восстановить данные.

**Резервное копирование (Критически важно!)**

Перед любыми действиями создайте полную резервную копию всех данных с нужного раздела.

```sh
# Пример копирования данных с помощью rsync
sudo rsync -avh /path/to/your/mountpoint/ /path/to/backup/
```

**Отмонтирование раздела**

```sh
sudo umount /path/to/your/mountpoint
```

**Переформатирование с нужным количеством inodes**

Используйте команду `mkfs.ext4` с одним из флагов:

*   `-i bytes-per-inode`: Задаёт соотношение байт на один inode. Чем меньше значение, тем больше будет создано inodes.
    *   Значение по умолчанию обычно `16384` (1 inode на 16 КБ).
    *   Для систем с огромным количеством мелких файлов (почта, кэш) можно поставить `4096` (1 inode на 4 КБ).
*   `-N number-of-inodes`: Прямо указывает, сколько inodes нужно создать.

**Пример (рекомендуемый способ):**

```sh
# Замените /dev/sdXN на ваш раздел
sudo mkfs.ext4 -i 4096 /dev/sdXN
```

**Монтирование и восстановление данных**

```sh
# Монтируем свежеотформатированный раздел
sudo mount /dev/sdXN /path/to/your/mountpoint

# Восстанавливаем данные из резервной копии
sudo rsync -avh /path/to/backup/ /path/to/your/mountpoint/
```
**Альтернатива:** Файловые системы, такие как **XFS** или **Btrfs**, выделяют inodes динамически, поэтому у них нет проблемы с исчерпанием их запаса. Миграция на одну из этих ФС может быть долгосрочным решением.

### Занятое место (`du`)


**Разница между `df` и `du`**:
-   `df` (disk free) показывает использование диска с точки зрения файловой системы, считывая информацию из **суперблока**. Он мгновенно предоставляет данные о том, сколько всего блоков занято и свободно на разделе. `df` не пересчитывает занятое место, а получает уже готовую информацию. Это делает его очень быстрым и подходящим для мониторинга общего состояния дискового пространства.
-   `du` (disk usage) рекурсивно подсчитывает суммарный размер конкретных файлов и директорий, проходя по файловой системе. Это более медленная операция, так как она реально пересчитывает объемы данных, но она показывает фактический объем данных, занимаемый файлами. `du` полезен для определения, какие каталоги или файлы занимают больше всего места.

Ни одна из утилит не является "лучше" другой; они служат разным целям. `df` дает быстрый обзор состояния файловой системы, а `du` — детальную информацию о занятом пространстве конкретными файлами и каталогами.

Расхождения между `df` и `du` могут возникнуть по нескольким причинам:
1.  **Удаленные, но открытые файлы:** Если файл был удалён, но всё ещё используется каким-либо процессом (дескриптор файла открыт), `du` не будет учитывать этот файл, а `df` будет, так как место на диске еще не освобождено до тех пор, пока процесс не закроет файл.
2.  **Блочное выделение:** `df` считает выделенные блоки, а `du` — фактический размер данных. Если у вас много мелких файлов, которые не полностью заполняют свои блоки, `df` может показать больший объем, чем `du`, поскольку файловая система выделяет место блоками фиксированного размера.
3.  **Точки монтирования:** `df` показывает информацию только для смонтированных файловых систем, тогда как `du` может подсчитывать размер файлов в директориях, которые могут быть точками монтирования для других файловых систем.

### Место на диске не освободилось после удаления файлов

Иногда после удаления больших файлов (`rm file.log`) команда `df -h` показывает, что свободное место не увеличилось.

Это происходит, когда какой-либо запущенный процесс всё ещё использует этот "удалённый" файл. В файловых системах Linux удаление файла командой `rm` лишь убирает его имя (ссылку) из директории. Сами данные на диске (inode и блоки данных) остаются нетронутыми до тех пор, пока хотя бы один процесс держит этот файл открытым (имеет открытый файловый дескриптор).

Чтобы найти процесс, который удерживает удалённый файл, можно использовать `lsof` (list open files) и отфильтровать вывод по слову "deleted":

- **Способ 1:**
  ```sh
  sudo lsof | grep deleted
  ```
  Эта команда покажет список процессов и файлы, которые они держат открытыми, несмотря на удаление.

- **Способ 2:**
  ```sh
  sudo lsof +L1
  ```
  Эта команда использует встроенную функцию `lsof` для поиска файлов, у которых количество ссылок (link count) меньше 1, то есть удалённых файлов.

**Решение:**
Чтобы освободить место, нужно заставить процесс "отпустить" файл. Есть несколько способов:

1.  **Перезапустить сервис/процесс (рекомендуемый способ):**
    Если файл удерживается системной службой (например, `nginx` или `rsyslog`), самым безопасным способом будет её перезапуск.
    ```sh
    sudo systemctl restart <имя_сервиса>
    ```
    Это заставит процесс корректно завершиться и освободить все файловые дескрипторы.

2.  **Завершить процесс:**
    Если это не критичный сервис, можно просто завершить процесс, используя его PID из вывода `lsof`.
    ```sh
    kill <PID>
    ```

3.  **"Очистить" файл без перезапуска (рискованный способ):**
    В некоторых случаях, когда перезапуск сервиса нежелателен, можно очистить содержимое файла, не удаляя его. Это можно сделать, перенаправив в него пустой вывод.
    ```sh
    # > /path/to/original/file/that/was/deleted
    # Пример для лог-файла nginx, который был удалён, но удерживается процессом с PID 1234
    # Путь к файлу можно найти в выводе lsof
    sudo truncate -s 0 /proc/1234/fd/5 
    ```
    - `truncate -s 0` обрезает файл до нулевого размера, что немедленно освобождает дисковое пространство.
    - `/proc/<PID>/fd/<номер_дескриптора>` — это специальный путь, который позволяет получить доступ к файлу через открытый дескриптор процесса.
