# Файловая система /dev

Файловая система `/dev` (от англ. devices — устройства) — это специальная виртуальная файловая система в Linux, которая предоставляет доступ к устройствам системы через файлы. Концепция "всё есть файл" здесь реализуется в полной мере: с оборудованием (дисками, терминалами, принтерами) можно взаимодействовать как с обычными файлами.

## Типы файлов устройств

В каталоге `/dev` можно встретить файлы нескольких типов, основными из которых являются:

-   `b` — **Блочные устройства (block devices)**: Устройства, которые обмениваются данными блоками информации. Классический пример — жесткие диски (`/dev/sda`), SSD, флеш-накопители.
-   `c` — **Символьные устройства (character devices)**: Устройства, которые обмениваются данными посимвольно. Примеры включают терминалы (`/dev/tty1`, `/dev/pts/0`), порты (`/dev/ttyS0`) и специальные устройства, такие как `/dev/null`.
-   `l` — **Символические ссылки (symbolic links)**: Ссылки, используемые для создания более удобных или стандартизированных имен для устройств. Например, `/dev/cdrom` может быть ссылкой на `/dev/sr0`.

## Major и Minor номера

При просмотре содержимого `/dev` с помощью `ls -l` вместо размера файла для блочных и символьных устройств отображаются два числа, разделенные запятой. Это **major** и **minor** номера.

```bash
$ ls -l /dev/sda
brw-rw---- 1 root disk 8, 0 ноя  9 10:37 /dev/sda
```

-   **Major number (старший номер)**: Первое число (в примере `8`). Оно идентифицирует драйвер устройства в ядре. Несколько устройств, управляемых одним и тем же драйвером, будут иметь одинаковый major number.
-   **Minor number (младший номер)**: Второе число (в примере `0`). Оно используется драйвером для идентификации конкретного физического устройства. Если к системе подключено несколько однотипных дисков, у них будет одинаковый major number, но разные minor numbers.

Список зарегистрированных в ядре устройств и их major-номеров можно посмотреть в файле `/proc/devices`.

## Динамическое создание

В современных дистрибутивах Linux содержимое каталога `/dev` генерируется динамически с помощью демона `udev`. При загрузке системы или при подключении нового устройства `udev` автоматически создает соответствующий файл устройства в `/dev`. В прошлом этот каталог содержал статический набор всех возможных файлов устройств, что было менее гибко.

## Специальные устройства

В `/dev` существует ряд псевдо-устройств, которые предоставляют полезные функции:

-   `/dev/null`: "Черная дыра". Все данные, записанные в этот файл, исчезают. При чтении из него немедленно возвращается конец файла (EOF). Используется для подавления вывода команд.
-   `/dev/zero`: Источник нулевых байтов. При чтении из этого файла возвращается бесконечная последовательность символов `\0`.
-   `/dev/random` и `/dev/urandom`: Источники случайных (или псевдослучайных) данных.
-   `/dev/full`: Устройство, имитирующее переполненный диск. При попытке записи в него всегда возвращается ошибка "No space left on device".
-   `/dev/tty`: Ссылка на управляющий терминал текущего процесса.
-   `/dev/pts/*`: Псевдо-терминалы, используемые для SSH-сессий, эмуляторов терминала в GUI и т.д.

## Практические примеры

### Взаимодействие с терминалами

Поскольку терминалы представлены файлами, можно отправлять сообщения из одного терминала в другой, просто записывая в соответствующий файл устройства.

Предположим, у нас открыты два терминала: `/dev/pts/0` и `/dev/pts/1`.

```bash
# Из терминала /dev/pts/0 отправить сообщение в /dev/pts/1
echo "Привет из pts/0" > /dev/pts/1
```

Это сообщение появится в окне второго терминала. Это демонстрирует, что ядро обрабатывает запись в файл устройства как ввод данных для соответствующего терминала.

### Использование псевдо-устройств

-   **Подавление вывода:**
    ```bash
    # Весь стандартный вывод и ошибки команды будут проигнорированы
    command > /dev/null 2>&1
    ```

-   **Создание файла, заполненного нулями:**
    ```bash
    # Создаст файл размером 1 ГБ, заполненный нулевыми байтами
    dd if=/dev/zero of=large_file.img bs=1M count=1024
    ```

-   **Тестирование нехватки места на диске:**
    ```bash
    # Попытка записи в /dev/full всегда завершается ошибкой нехватки места
    echo "test" > /dev/full
    # Вывод: bash: echo: write error: No space left on device
    ```

## Исторический контекст и mknod

В ранних версиях Linux каталог `/dev` был статическим. Он содержал огромное количество файлов для всех возможных устройств, которые теоретически могли быть подключены к системе. Это было неэффективно и неудобно. Современный подход с `udev` решает эту проблему, создавая файлы устройств только для реально существующего и подключенного оборудования.

Несмотря на автоматизацию, возможность ручного создания файла устройства сохраняется с помощью команды `mknod`. Это может быть полезно в специфических или отладочных сценариях.

```bash
# Пример создания символьного устройства
# mknod [имя_файла] c [major_number] [minor_number]
mknod /tmp/my_char_device c 100 1
```
Эта команда создаст в `/tmp` файл символьного устройства `my_char_device` с major-номером 100 и minor-номером 1.
