# Проверка и восстановление целостности файловой системы (fsck)

## Определения

- **`fsck` (File System Check):** Стандартная утилита в Unix-подобных системах для проверки целостности файловой системы и исправления обнаруженных в ней ошибок.

## Основные концепции

- **Безопасность запуска:** `fsck` всегда должна запускаться на **размонтированной** файловой системе. Попытка запустить проверку на смонтированном разделе может привести к необратимому повреждению данных.
- **Автоматическая проверка:** Система автоматически запускает `fsck` при загрузке, если файловая система помечена как "грязная" (например, после аварийного завершения работы ОС). Порядок проверки файловых систем при загрузке определяется полем `<pass>` в файле `/etc/fstab`.

## Практические сценарии

### Стандартное использование `fsck`

Для принудительной проверки файловой системы (например, ext2/3/4) на разделе `/dev/sdXN`:

```bash
# Ключ -f (force) заставляет fsck проверить файловую систему, даже если она помечена как "чистая".
sudo fsck -f /dev/sdXN
```

### Проверка и восстановление XFS с помощью `xfs_repair`

Стандартная утилита `fsck` не работает для файловой системы XFS. Вместо нее используется специализированная команда `xfs_repair`.

```bash
# Для проверки и восстановления целостности XFS
sudo xfs_repair /dev/sdXN
```

> **Примечание:** `fsck.xfs` существует, но является лишь оберткой для `xfs_repair` и не выполняет реального исправления. Возможности `xfs_repair` по логическому [восстановлению удалённых файлов](data_recovery.md) крайне ограничены.

- Подробнее о влиянии поля `<pass>` в `/etc/fstab` см. в [Управление монтированием файловых систем в Linux](mounting/fstab.md).

- Для восстановления таблиц разделов (MBR/GPT) см. [Восстановление таблиц разделов](partition_tables_recovery.md).
- Для мониторинга состояния дисков используйте [`smartctl`](../Diagnostics/Hardware/smartctl/index.md).
