# Проверка и восстановление целостности файловой системы (fsck)

## Определения

- **`fsck` (File System Check):** Стандартная утилита в Unix-подобных системах для проверки целостности файловой системы и исправления обнаруженных в ней ошибок. Является фронтендом (обёрткой), который вызывает специализированную утилиту для конкретной ФС (например, `fsck.ext4`, `fsck.xfs`).

- **Коды возврата `fsck`:** Утилита возвращает битовую маску, где каждый бит означает определённый результат: `0` — ошибок нет, `1` — ошибки исправлены, `2` — требуется перезагрузка, `4` — ошибки не исправлены, `8` — операционная ошибка, `16` — синтаксическая ошибка, `32` — проверка отменена пользователем, `128` — ошибка разделяемой библиотеки.

## Основные концепции

### Безопасность запуска

`fsck` всегда должна запускаться на **размонтированной** файловой системе. Попытка запустить проверку на смонтированном в режиме записи разделе может привести к необратимому повреждению данных. Исключение — режим `read-only` (`-n`), который выполняет только диагностику без внесения изменений.

### Автоматическая проверка при загрузке

Система автоматически запускает `fsck` при загрузке, если файловая система помечена как "грязная" (например, после аварийного завершения работы ОС). Порядок проверки определяется полем `<pass>` в файле [fstab](mounting/fstab.md):

- `0` — не проверять.
- `1` — проверять первой (только для корневой ФС `/`).
- `2` — проверять после корневой ФС.

Для журналируемых ФС (ext4, XFS) проверка обычно ограничивается replay журнала и занимает секунды. Для non-journaling ФС (ext2) требуется полное сканирование, которое на больших дисках может занимать часы.

### Режимы работы

- **Автоматическое исправление (`-a` или `-p`):** Автоматически исправляет все обнаруженные ошибки без запроса пользователя. `-p` (preen) — более консервативный режим, исправляет только безопасные ошибки.
- **Интерактивный режим (`-r`):** Запрашивает подтверждение для каждого исправления.
- **Только чтение (`-n`):** Открывает ФС в режиме read-only, не записывает изменений. Используется для диагностики.
- **Принудительная проверка (`-f`):** Проверяет ФС, даже если она помечена как "чистая".

## Практические сценарии

### Принудительный запуск проверки при следующей загрузке

Если файловую систему (особенно корневую `/`) невозможно размонтировать, можно запланировать её проверку при перезагрузке системы.

**1. Параметр ядра (рекомендуемый способ для современных систем):**
Добавьте `fsck.mode=force` в строку загрузки ядра (через GRUB). Это заставит `systemd-fsck` выполнить проверку всех файловых систем, помеченных для проверки в `fstab`.
- Чтобы также автоматически исправлять ошибки: `fsck.mode=force fsck.repair=yes`.

**2. Использование `tune2fs` (для ext2/3/4):**
Можно обмануть систему, установив счётчик монтирований выше лимита:
```bash
# Установить текущее число монтирований в 50 (при лимите, например, 30)
sudo tune2fs -C 50 /dev/sdXN

# Или заставить проверять через каждые N дней
sudo tune2fs -i 1d /dev/sdXN
```

**3. Флаг-файл (устаревший способ):**
В старых дистрибутивах (до перехода на systemd) работал метод создания пустого файла в корне:
```bash
sudo touch /forcefsck
```
*Примечание: В современных системах на базе systemd этот файл игнорируется.*

**4. Использование `shutdown`:**
Некоторые системы поддерживают флаг `-F`:
```bash
sudo shutdown -rF now
```

### Проверка и восстановление XFS (`xfs_repair`)

Для XFS стандартная `fsck` не выполняет реального исправления — `fsck.xfs` является лишь обёрткой, которая вызывает `xfs_repair`. Основной инструмент:

```bash
# Проверка и восстановление целостности XFS
sudo xfs_repair /dev/sdXN

# Режим only-check (только диагностика, без исправлений)
sudo xfs_repair -n /dev/sdXN
```

Если журнал XFS повреждён, может потребоваться его сброс (с риском потери данных):

```bash
sudo xfs_repair -L /dev/sdXN  # Обнулить журнал (последнее средство)
```

### Проверка и восстановление Btrfs

Для Btrfs используется встроенная утилита `btrfs check`:

```bash
# Только проверка (без исправлений)
sudo btrfs check /dev/sdXN

# Проверка с исправлением (требует размонтирования)
sudo btrfs check --repair /dev/sdXN
```

> **Важно:** Режим `--repair` для Btrfs считается опасным и может привести к дополнительной потере данных. Рекомендуется сначала создать [образ диска](dd.md) и работать с его копией.

### Диагностика без внесения изменений

Для безопасной диагностики используйте флаг `-n` (no-change), который открывает ФС в режиме read-only:

```bash
sudo fsck -n /dev/sdXN
```
