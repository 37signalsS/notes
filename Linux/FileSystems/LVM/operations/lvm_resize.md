# Изменение размеров LVM

## Определения

**PV (Physical Volume — физический том)** — нижний уровень иерархии LVM; физический диск или раздел (например, `/dev/sdb1`), инициализированный для использования в LVM.

**VG (Volume Group — группа томов)** — пул дискового пространства, объединяющий один или несколько PV.

**LV (Logical Volume — логический том)** — виртуальный раздел, создаваемый из пространства VG, на котором размещается файловая система.

**PE (Physical Extent — физический экстент)** — минимальный блок данных в VG (по умолчанию 4 МБ). Все операции изменения размера кратны размеру PE.

**LE (Logical Extent — логический экстент)** — единица измерения размера LV, соответствующая одному PE в данной VG.

## Базовые концепции

Изменение размеров в LVM выполняется по принципу «снизу вверх» при расширении и «сверху вниз» при уменьшении.

### Способы указания размера

При использовании команд `lvextend` и `lvreduce` можно указывать размер двумя способами:
- **Флаг `-L` (Size):** абсолютное или относительное значение в единицах объема (например, `-L 10G`, `-L +2G`).
- **Флаг `-l` (Extents):** размер в логических экстентах (например, `-l 100`, `-l +100%FREE`). Использование `%FREE` позволяет задействовать всё оставшееся пространство без ошибок округления.

### Поддержка файловыми системами

Изменение размера LVM-тома должно сопровождаться изменением размера файловой системы (ФС).

| Файловая система | Расширение (Extend) | Уменьшение (Reduce) | Инструментарий |
| :--- | :--- | :--- | :--- |
| **ext2/ext3/ext4** | Онлайн (без отмонтирования) | Офлайн (требуется `umount`) | `resize2fs`, `e2fsck` |
| **XFS** | Онлайн | **Не поддерживается** | `xfs_growfs` |

### Точность расчетов

Утилиты LVM и ФС могут использовать разные базы (1000 vs 1024).
**Рекомендация:** При уменьшении тома всегда сжимайте ФС до размера на 100–200 МБ меньше целевого LV, чтобы избежать ошибок округления и потери данных. После успешного уменьшения LV расширьте ФС до границ тома командой `resize2fs` без указания размера.

## Практические сценарии

### Сценарий 1: Онлайн-расширение логического тома и ФС

Самый частый сценарий. Использование флага `-r` (`--resizefs`) позволяет выполнить обе операции одной командой.

**Шаг 1: Проверка свободного места в VG**
```bash
sudo vgs
# → VG      #PV #LV #SN Attr   VSize   VFree
# → data_vg   1   1   0 wz--n- <20.00g <5.00g
```

**Шаг 2: Расширение LV и ФС**
```bash
# Добавить 2 ГБ
sudo lvextend -L +2G -r /dev/data_vg/my_lv
# → Logical volume data_vg/my_lv successfully resized.
# → resize2fs 1.46.5 (30-Dec-2021)
# → Filesystem at /dev/mapper/data_vg-my_lv is mounted on /mnt/data; on-line resizing required

# Использовать всё свободное место в группе
sudo lvextend -l +100%FREE -r /dev/data_vg/my_lv
```

### Сценарий 2: Офлайн-уменьшение (ext4)

**Внимание:** Операция невозможна для XFS. Обязательно создайте резервную копию перед началом.

**Шаг 1: Размонтирование и проверка**
```bash
sudo umount /mnt/data
sudo e2fsck -f /dev/data_vg/my_lv
```

**Шаг 2: Сжатие файловой системы**
Уменьшаем ФС до 8 ГБ (с запасом, если целевой LV — 9 ГБ).
```bash
sudo resize2fs /dev/data_vg/my_lv 8G
```

**Шаг 3: Уменьшение LV**
```bash
sudo lvreduce -L 9G /dev/data_vg/my_lv
# → WARNING: Reducing active logical volume to 9.00 GiB.
# → THIS MAY DESTROY YOUR DATA (filesystem etc.)
# → Do you really want to reduce data_vg/my_lv? [y/n]: y
```

**Шаг 4: Растягивание ФС до границ LV**
```bash
sudo resize2fs /dev/data_vg/my_lv
sudo mount /dev/data_vg/my_lv /mnt/data
```

### Сценарий 3: Расширение после увеличения физического диска (VM/Cloud)

Применим, когда объем виртуального диска (LUN) был увеличен на стороне гипервизора или облака.

**Шаг 1: Обнаружение изменений**
```bash
# Пересканирование диска (например, sdb)
echo 1 | sudo tee /sys/class/block/sdb/device/rescan
```

**Шаг 2: Расширение раздела (если LVM на разделе)**
```bash
sudo growpart /dev/sdb 1 # Расширение первого раздела на sdb
```

**Шаг 3: Обновление размера PV**
```bash
sudo pvresize /dev/sdb1
# → Physical volume "/dev/sdb1" changed
```

**Шаг 4: Расширение LV**
Выполняется согласно **Сценарию 1**.

### Сценарий 4: Изменение размера зашифрованного тома (LUKS + LVM)

Типовая схема: `Disk → LUKS Container → LVM PV → VG → LV`.

**Расширение:**
1. Расширьте физический носитель (см. Сценарий 3).
2. Расширьте LUKS-контейнер:
   ```bash
   sudo cryptsetup resize crypt_disk
   ```
3. Обновите размер PV:
   ```bash
   sudo pvresize /dev/mapper/crypt_disk
   ```
4. Расширьте LV согласно Сценарию 1.

### Сценарий 5: Изменение размера в Тонких пулах (Thin Provisioning)

Для тонких томов расширение виртуального размера не требует свободного места в VG сразу, но требует контроля заполнения пула.

```bash
# Расширение виртуального размера тонкого тома (LV)
sudo lvextend -V 2T /dev/my_vg/thin_lv

# Расширение физического пространства самого пула (требует VFree в VG)
sudo lvextend -L +100G /dev/my_vg/thin_pool
```
*Подробнее см. в [LVM — Тонкое провизионирование](../thin-provisioning.md).*
