# Изменение размеров LVM

## Определения

**Расширение (Extend)** — увеличение размера логического тома (LV) и файловой системы без остановки работы системы (online).

**Уменьшение (Reduce)** — уменьшение размера LV и ФС. Рискованная операция, требующая размонтирования тома (offline) для файловых систем семейства ext.

**pvresize** — утилита для обновления размера физического тома (PV) после изменения размера раздела диска или виртуального диска.

## Базовые концепции

### Общие принципы

- **Расширение** — безопасная операция, выполняется "на лету" для большинства современных файловых систем.
- **Уменьшение** — опасная операция, требующая обязательного создания резервных копий.
- Флаг `-r` (`--resizefs`) в командах `lvextend` и `lvreduce` автоматически вызывает соответствующую утилиту изменения размера ФС.
- Размер файловой системы не может превышать размер логического тома: ФС ≤ LV.

### Поддержка файловыми системами

| Файловая система | Расширение | Уменьшение | Инструментарий |
| :--- | :--- | :--- | :--- |
| **ext2/ext3/ext4** | Онлайн | Офлайн | `resize2fs`, `e2fsck` |
| **XFS** | Онлайн | **Не поддерживается** | `xfs_growfs` |

## Практические сценарии

### Сценарий 1: Расширение LV и файловой системы

**Шаг 1: Проверка свободного места в VG**

```bash
sudo vgs  # Проверка значения в столбце VFree
```

**Шаг 2: Расширение VG (если в группе нет места)**

Добавьте новый физический том (PV) в группу:

```bash
sudo pvcreate /dev/sdd1
sudo vgextend my_vg /dev/sdd1
```

**Шаг 3: Расширение LV и ФС одной командой**

Рекомендуемый способ (использование флага `-r`):

```bash
# Добавить 5 ГБ
sudo lvextend -L +5G -r /dev/my_vg/my_lv

# Использовать всё доступное пространство в VG
sudo lvextend -l +100%FREE -r /dev/my_vg/my_lv
```

**Шаг 4: Ручное расширение ФС (если LV уже расширен без -r)**

```bash
# Для ext2/3/4
sudo resize2fs /dev/my_vg/my_lv

# Для XFS (требуется точка монтирования)
sudo xfs_growfs /mnt/data
```

### Сценарий 2: Уменьшение LV (только для ext2/3/4)

**Внимание:** Для файловой системы XFS операция уменьшения невозможна.

**Шаг 1: Размонтирование тома**

```bash
sudo umount /mnt/data
```

**Шаг 2: Проверка целостности ФС**

```bash
sudo e2fsck -f /dev/my_vg/my_lv
```

**Шаг 3: Уменьшение ФС**

Рекомендуется уменьшать ФС до размера чуть меньше целевого размера LV, чтобы избежать ошибок округления.

```bash
# Уменьшить ФС до 14 ГБ (целевой LV будет 15 ГБ)
sudo resize2fs /dev/my_vg/my_lv 14G
```

**Шаг 4: Уменьшение LV**

```bash
sudo lvreduce -L 15G /dev/my_vg/my_lv
```

**Шаг 5: Адаптация ФС под полный размер LV**

```bash
sudo resize2fs /dev/my_vg/my_lv
```

**Шаг 6: Монтирование тома**

```bash
sudo mount /dev/my_vg/my_lv /mnt/data
```

### Сценарий 3: Расширение LVM после увеличения диска (Rescan)

Применим для виртуальных машин или облачных сред при увеличении диска "на горячую".

**Шаг 1: Принудительное сканирование диска**

```bash
# Обновление информации о диске sda
echo 1 | sudo tee /sys/class/block/sda/device/rescan
```

**Шаг 2: Расширение раздела диска**

Используйте `growpart` (утилита из пакета `cloud-utils-growpart` или `cloud-guest-utils`):

```bash
sudo growpart /dev/sda 2  # Расширение раздела 2 на диске sda
```

**Шаг 3: Расширение PV**

```bash
sudo pvresize /dev/sda2
```

**Шаг 4: Расширение LV и ФС**

```bash
sudo lvextend -l +100%FREE -r /dev/my_vg/my_lv
```
