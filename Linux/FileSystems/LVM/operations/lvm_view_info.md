# Просмотр информации LVM

## Определения

**Команды краткого вывода (Reporting commands)** — утилиты `pvs`, `vgs`, `lvs`, выводящие информацию в компактном табличном виде (одна строка на объект). Оптимальны для оперативного мониторинга и автоматизации.

**Команды подробного вывода (Display commands)** — утилиты `pvdisplay`, `vgdisplay`, `lvdisplay`, предоставляющие детальный многострочный отчет о каждом объекте, включая UUID, метаданные и внутренние параметры сегментов.

**Команды сканирования (Scanning commands)** — утилиты `pvscan`, `vgscan`, `lvscan`, предназначенные для поиска LVM-объектов на всех доступных блочных устройствах и обновления системного кэша.

## Базовые концепции

### Иерархия инструментов мониторинга

Инструментарий LVM разделен на уровни, соответствующие архитектуре PV → VG → LV.

| Объект | Краткий отчет | Подробный отчет | Область анализа |
| :--- | :--- | :--- | :--- |
| **Physical Volume (PV)** | `sudo pvs` | `sudo pvdisplay` | Физические диски, разделы, свободные экстенты |
| **Volume Group (VG)** | `sudo vgs` | `sudo vgdisplay` | Группы томов, размер PE, суммарные ресурсы |
| **Logical Volume (LV)** | `sudo lvs` | `sudo lvdisplay` | Логические разделы, точки монтирования, атрибуты |

### Атрибуты в выводе (Attr)

В кратком выводе (`lvs`, `vgs`, `pvs`) присутствует столбец `Attr`. Основные флаги для LV:
1. **w/r/-:** Бит записи (write/read-only).
2. **a/-:** Состояние активации (active/inactive).
3. **o/-:** Открыт ли том (open — примонтирован или используется).
4. **C/m/s/t:** Тип тома (Contiguous, Mirrored, Snapshot, Thin).

## Практические сценарии

### Сценарий 1: Общая диагностика блочных устройств

Первым шагом всегда рекомендуется использовать системную утилиту `lsblk` для понимания физической топологии.

```bash
lsblk
# → sdb           8:16   0   20G  0 disk
# → └─data_vg-lv_data 253:0    0   10G  0 lvm  /mnt/data
```

### Сценарий 2: Анализ распределения места в группах томов

Используется для принятия решения о расширении LV.

```bash
sudo vgs
# → VG      #PV #LV #SN Attr   VSize   VFree
# → data_vg   1   2   0 wz--n- <20.00g <5.00g
```
*   `VFree` — критический показатель: сколько места можно выделить новым или существующим LV.

### Сценарий 3: Проверка физических носителей (PV)

```bash
sudo pvs
# → PV         VG      Fmt  Attr PSize   PFree
# → /dev/sdb   data_vg lvm2 a--  <20.00g <5.00g
```

### Сценарий 4: Мониторинг тонких пулов (Thin Provisioning)

Для тонких томов важно следить за реальным потреблением физического места в пуле.

```bash
sudo lvs
# → LV          VG      Attr       LSize   Pool       Origin Data%  Meta%
# → thin_lv     data_vg Vwi-a-tz-- 100.00g thin_pool        15.40
# → thin_pool   data_vg twi-aotz--  20.00g                77.00  12.50
```
*   `Data%` — если значение приближается к 100%, тонкий пул переполнен, и запись на все зависимые LV будет заблокирована.

### Сценарий 5: Кастомизация вывода (Выбор полей и сортировка)

Reporting-команды позволяют гибко настраивать формат для скриптов или глубокого анализа.

```bash
# Вывод только имени и UUID группы томов
sudo vgs -o vg_name,vg_uuid
# → VG      VG UUID
# → data_vg 6R8j31-3G9a-L1m2-S3n4...

# Сортировка LV по размеру (от большего к меньшему)
sudo lvs --sort -lv_size

# Показать все доступные поля для LV
sudo lvs -o help
```

### Сценарий 6: Сканирование и активация

Используется после подключения новых дисков или при восстановлении системы.

```bash
sudo vgscan
# → Reading all physical volumes.  This may take a while...
# → Found volume group "data_vg" using metadata type lvm2

sudo lvscan
# → ACTIVE            '/dev/data_vg/lv_data' [10.00 GiB] inherit
# → INACTIVE          '/dev/data_vg/lv_backup' [5.00 GiB] inherit
```
*   Если статус `INACTIVE`, том нужно активировать: `sudo vgchange -ay data_vg`.
