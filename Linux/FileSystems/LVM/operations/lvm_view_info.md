# Просмотр информации LVM

## Определения

**Команды краткого вывода (Reporting commands)** — утилиты `pvs`, `vgs`, `lvs`, которые выводят информацию в компактном табличном виде (одна строка на объект). Оптимальны для повседневного мониторинга и использования в скриптах.

**Команды подробного вывода (Display commands)** — утилиты `pvdisplay`, `vgdisplay`, `lvdisplay`, предоставляющие детальный многострочный отчет о каждом объекте, включая метаданные и внутренние параметры.

**Команды сканирования (Scanning commands)** — утилиты `pvscan`, `vgscan`, `lvscan`, предназначенные для поиска LVM-объектов на дисках и обновления кэша системы.

## Базовые концепции

### Иерархия инструментов просмотра

Инструментарий LVM разделен на уровни в соответствии с архитектурой системы (PV → VG → LV).

| Объект | Краткий отчет | Подробный отчет | Область анализа |
| :--- | :--- | :--- | :--- |
| **Physical Volume (PV)** | `sudo pvs` | `sudo pvdisplay` | Физические диски и разделы |
| **Volume Group (VG)** | `sudo vgs` | `sudo vgdisplay` | Группы томов (пулы ресурсов) |
| **Logical Volume (LV)** | `sudo lvs` | `sudo lvdisplay` | Логические тома (разделы ФС) |

### Методика диагностики структуры

Для получения полной картины состояния дисковой подсистемы рекомендуется выполнять проверку в следующем порядке:

1. **Блочные устройства:** `lsblk` — показывает общую иерархию от физического диска до точки монтирования.
2. **Физический уровень:** `sudo pvs` — проверка доступности дисков и свободного места на них.
3. **Уровень пулов:** `sudo vgs` — анализ распределения места в группах томов.
4. **Логический уровень:** `sudo lvs` — проверка состояния конкретных томов, их размеров и атрибутов.

## Практические сценарии

### Сценарий 1: Проверка свободного места в VG

Самая частая операция перед расширением томов.

```bash
sudo vgs
```

**Ключевые поля вывода:**

- `VSize` — общий объем группы томов.
- `VFree` — доступное пространство, которое можно распределить между LV.

### Сценарий 2: Анализ использования физических носителей

Позволяет понять, на каких дисках физически расположены данные.

```bash
sudo pvs
```

**Ключевые поля вывода:**

- `PSize` — физический размер диска/раздела.
- `PFree` — нераспределенное пространство внутри PV.

### Сценарий 3: Мониторинг логических томов

```bash
sudo lvs
```

**Ключевые поля вывода:**

- `LSize` — размер тома.
- `Data%` — заполнение данными (актуально для Thin Provisioning).
- `Snap%` — заполнение снимка (Snapshot) данными об изменениях.

### Сценарий 4: Кастомизация вывода (Выбор столбцов)

Reporting-команды поддерживают флаг `-o` для вывода специфических полей.

```bash
# Просмотр LV с указанием родительского пула и процента использования
sudo lvs -o lv_name,vg_name,lv_size,data_percent

# Просмотр PV с информацией о размере метаданных
sudo pvs -o pv_name,pv_size,pv_mda_size

# Просмотр VG с размером экстента (Physical Extent)
sudo vgs -o vg_name,vg_extent_size
```

### Сценарий 5: Глубокая диагностика объекта

Используется при возникновении ошибок или необходимости узнать точные параметры (например, UUID).

```bash
# Детальный отчет по конкретному логическому тому
sudo lvdisplay /dev/my_vg/my_lv
```

### Сценарий 6: Сканирование системы на наличие LVM

Необходимо после подключения новых дисков (например, SAN или перенесенных с другой системы).

```bash
sudo vgscan   # Находит все VG и восстанавливает /etc/lvm/cache/.cache
sudo lvscan   # Показывает статус активации всех томов (ACTIVE/INACTIVE)
```
