# Создание PV, VG и LV

## Определения

**Physical Volume (PV — физический том)** — диск, раздел диска или другое блочное устройство, инициализированное для использования в LVM. Является базовым уровнем хранения.

**Volume Group (VG — группа томов)** — виртуальный пул хранения, объединяющий один или несколько физических томов (PV). Группа томов представляет собой единое адресное пространство для создания логических разделов.

**Logical Volume (LV — логический том)** — виртуальный раздел, создаваемый внутри группы томов. На логических томах создаются файловые системы.

## Базовые концепции

### Иерархия уровней LVM

Процесс абстракции дискового пространства проходит через следующие этапы:
`Физический носитель → Physical Volume (PV) → Volume Group (VG) → Logical Volume (LV) → Файловая система`

### Ключевые принципы инициализации

- **Очистка метаданных:** Перед созданием PV крайне рекомендуется выполнить очистку диска утилитой `wipefs`, чтобы избежать конфликтов со старыми таблицами разделов или подписями ФС.
- **Гибкость VG:** Группа томов может объединять диски разных типов и размеров (например, SSD и HDD), обеспечивая единый объем.
- **Адресация LV:** Доступ к логическим томам осуществляется через символические ссылки в `/dev/<VG_NAME>/<LV_NAME>` или `/dev/mapper/<VG_NAME>-<LV_NAME>`.

### Основные утилиты

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| **Инициализация PV** | `sudo pvcreate /dev/sdb1` | Подготовка устройства к работе в LVM. |
| **Создание VG** | `sudo vgcreate data_vg /dev/sdb1` | Создание пула из одного или нескольких PV. |
| **Создание LV (размер)** | `sudo lvcreate -L 10G -n my_lv data_vg` | Выделение тома фиксированного размера. |
| **Создание LV (процент)** | `sudo lvcreate -l 100%FREE -n my_lv data_vg` | Выделение всего свободного места. |

## Практические сценарии

### Сценарий 1: Подготовка нового диска с разделением на LV

**Шаг 1: Идентификация диска**

```bash
lsblk
```

*Убедитесь, что устройство (например, `/dev/sdb`) не содержит важных данных.*

**Шаг 2: Создание разделов (опционально)**

Хотя LVM может работать с целым диском, использование разделов (тип `8e00` в `gdisk` или `8e` в `fdisk`) является классическим подходом.

```bash
sudo fdisk /dev/sdb
# Рекомендуемый порядок в fdisk: n (новый), p (основной), t (тип), 8e (LVM), w (записать)
```

**Шаг 3: Инициализация физических томов (PV)**

```bash
# Удаление старых подписей
sudo wipefs --all /dev/sdb1

# Инициализация
sudo pvcreate /dev/sdb1
```

**Шаг 4: Создание группы томов (VG)**

```bash
sudo vgcreate vg_data /dev/sdb1
```

**Шаг 5: Создание логических томов (LV)**

```bash
# Создание тома для логов (5 ГБ)
sudo lvcreate -n lv_logs -L 5G vg_data

# Создание тома для данных (все оставшееся место)
sudo lvcreate -n lv_storage -l 100%FREE vg_data
```

**Шаг 6: Создание файловой системы и монтирование**

```bash
sudo mkfs.ext4 /dev/vg_data/lv_storage
sudo mkdir -p /mnt/storage
sudo mount /dev/vg_data/lv_storage /mnt/storage
```

**Шаг 7: Настройка автозапуска через /etc/fstab**

Используйте UUID для стабильности (получить через `sudo blkid`):

```text
UUID=ваш-uuid-тома  /mnt/storage  ext4  defaults  0  2
```

### Сценарий 2: Создание LVM на базе целого диска (без разделов)

Подход удобен для виртуальных сред, где диск выделяется под конкретную задачу целиком.

```bash
sudo wipefs --all /dev/sdc
sudo pvcreate /dev/sdc
sudo vgcreate vg_backup /dev/sdc
sudo lvcreate -l 100%FREE -n lv_backup vg_backup
```
