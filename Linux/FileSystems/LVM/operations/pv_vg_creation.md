# Создание PV, VG и LV

## Определения

**PV (Physical Volume — физический том)** — диск, раздел или блочное устройство (например, LUKS-контейнер), инициализированное для работы в LVM. Содержит метаданные и метку LVM.

**VG (Volume Group — группа томов)** — виртуальный пул хранения, объединяющий один или несколько PV. Группа томов представляет собой единое адресное пространство для нарезки логических томов.

**LV (Logical Volume — логический том)** — виртуальный блочный раздел, создаваемый внутри VG. Для операционной системы LV выглядит как обычный диск.

**PE (Physical Extent — физический экстент)** — минимальный «кирпичик» данных в LVM (по умолчанию **4 МиБ**). Размер LV всегда кратен размеру PE.

## Базовые концепции

### Иерархия уровней LVM

Процесс абстракции дискового пространства проходит через этапы:
`Физический носитель → Physical Volume (PV) → Volume Group (VG) → Logical Volume (LV) → Файловая система`

### Ключевые принципы инициализации

- **Очистка метаданных:** Перед созданием PV рекомендуется выполнить `wipefs --all`, чтобы удалить старые сигнатуры RAID или файловых систем.
- **Размер метаданных (`--metadatasize`):** По умолчанию 1 МиБ. Для групп с сотнями LV или сложной структурой рекомендуется увеличивать до 2–4 МиБ при создании PV.
- **Выравнивание (`--dataalignment`):** LVM автоматически выравнивает данные по границам экстентов. На SSD и RAID рекомендуется проверять соответствие размера PE физическому блоку/страйпу.
- **Размер Physical Extent (PE):** Задается при создании VG (параметр `-s`). Для очень больших массивов (10+ ТБ) выгодно увеличивать до 32–128 МиБ для ускорения работы инструментов управления.

### Основные типы логических томов

| Тип | Флаг / Параметр | Описание |
| :--- | :--- | :--- |
| **Linear** | По умолчанию | Последовательное заполнение PV. |
| **Striped** | `-i <кол-во>` | RAID 0 (чередование) для повышения скорости. |
| **RAID 1** | `--type raid1` | Зеркалирование. Рекомендуемый тип в 2026 году. |
| **Thin** | `--thin` | Тонкое провизионирование (выделение по требованию). |

## Практические сценарии

### Сценарий 1: Подготовка нового диска с разделением на LV

**Шаг 1: Идентификация диска**
```bash
lsblk
# → sdb           8:16   0   20G  0 disk
```

**Шаг 2: Инициализация физического тома (PV)**
Рекомендуется использовать весь диск без создания `fdisk`-разделов для упрощения расширения.
```bash
sudo wipefs --all /dev/sdb
sudo pvcreate --metadatasize 2M /dev/sdb
# → Physical volume "/dev/sdb" successfully created.
```

**Шаг 3: Создание группы томов (VG)**
```bash
sudo vgcreate vg_data /dev/sdb
# → Volume group "vg_data" successfully created
```

**Шаг 4: Создание логических томов (LV)**
```bash
# Создание тома для БД (10 ГБ)
sudo lvcreate -n lv_db -L 10G vg_data
# → Logical volume "lv_db" created.

# Создание зеркального тома (RAID 1) на двух дисках (требует 2 PV)
sudo lvcreate --type raid1 -m 1 -L 5G -n lv_critical vg_data
```

**Шаг 5: Создание файловой системы**
```bash
sudo mkfs.ext4 /dev/vg_data/lv_db
sudo mount /dev/vg_data/lv_db /mnt/db
```

### Сценарий 2: Создание LV с чередованием (Performance)

Требуется как минимум два физических носителя.
```bash
# Использование двух дисков в одной VG
sudo vgcreate vg_perf /dev/sdc /dev/sdd

# Создание Striped LV по 2 дискам (-i 2) с чанком 64k
sudo lvcreate -i 2 -I 64k -L 40G -n lv_high_perf vg_perf
# → Logical volume "lv_high_perf" created.
```

### Сценарий 3: Создание тома без зануления (Зануление)

По умолчанию LVM зануляет первый КиБ данных нового LV для безопасности. Флаг `-Z n` отключает это поведение (используется для специфических задач восстановления или миграции).
```bash
sudo lvcreate -Z n -L 1G -n lv_raw vg_data
```
