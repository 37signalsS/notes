# Жизненный цикл LVM

## Определения

**Жизненный цикл LVM (LVM Lifecycle)** — полный цикл существования системы логических томов, охватывающий этапы от подготовки физических носителей до окончательного удаления всех структур данных и метаданных.

## Базовые концепции

Процесс управления LVM строится на иерархическом принципе, где каждый этап зависит от успешного завершения предыдущего.

### Этапы жизненного цикла

1. **Инициализация (Physical Volume)** — подготовка диска или раздела, запись метаданных LVM.
2. **Агрегация (Volume Group)** — объединение одного или нескольких PV в единый пул дискового пространства.
3. **Выделение (Logical Volume)** — создание логических разделов нужного размера из пула VG.
4. **Эксплуатация** — создание файловой системы, монтирование, изменение размеров, создание снимков или миграция данных.
5. **Утилизация** — плановое удаление структур в порядке, обратном созданию (unmount → LV → VG → PV).

### Ключевые правила

- **Порядок удаления:** всегда строго обратный порядку создания. Невозможно удалить VG, пока в ней есть активные LV.
- **Безопасность данных:** перед удалением LV или уменьшением тома необходимо размонтировать файловую систему и убедиться в наличии резервных копий.
- **Идентификация:** для стабильности системы (например, в `/etc/fstab`) рекомендуется использовать UUID томов, а не их имена.

## Практические сценарии

### Сценарий 1: Полный цикл — от создания до удаления

**Шаг 1: Подготовка носителя и создание PV**

```bash
# Инициализация диска /dev/sdc
sudo pvcreate /dev/sdc
```

**Шаг 2: Создание группы томов (VG)**

```bash
sudo vgcreate my_vg /dev/sdc
```

**Шаг 3: Создание логического тома (LV)**

```bash
sudo lvcreate -L 2G -n my_app_lv my_vg
```

**Шаг 4: Подготовка к работе (ФС и Монтирование)**

```bash
sudo mkfs.ext4 /dev/my_vg/my_app_lv
sudo mkdir -p /mnt/my_app
sudo mount /dev/my_vg/my_app_lv /mnt/my_app
```

> Для настройки автозапуска см. **[Монтирование через fstab](../../mounting/fstab.md)**.

**Шаг 5: Обслуживание (Расширение)**

При необходимости добавьте место "на лету":

```bash
# Добавление нового диска в группу и расширение тома с ФС
sudo vgextend my_vg /dev/sdd
sudo lvextend -l +100%FREE -r /dev/my_vg/my_app_lv
```

**Шаг 6: Полное удаление структуры**

```bash
sudo umount /mnt/my_app                # 1. Размонтирование
sudo lvremove /dev/my_vg/my_app_lv     # 2. Удаление LV
sudo vgremove my_vg                    # 3. Удаление VG
sudo pvremove /dev/sdc /dev/sdd        # 4. Очистка LVM-меток с дисков
```

### Сценарий 2: Миграция данных (Замена диска)

Используется для вывода старого диска из эксплуатации без остановки сервисов.

```bash
sudo vgextend my_vg /dev/sde1    # 1. Добавить новый диск в VG
sudo pvmove /dev/sdc             # 2. Переместить данные со старого диска
sudo vgreduce my_vg /dev/sdc     # 3. Исключить старый диск из VG
sudo pvremove /dev/sdc           # 4. Удалить метаданные LVM
```
