# Жизненный цикл LVM

## Определения

**Жизненный цикл LVM (LVM Lifecycle)** — совокупность этапов существования системы логических томов: от инициализации физических носителей и агрегации ресурсов до эксплуатации, миграции и окончательной утилизации.

**Активация (Activation)** — процесс перевода группы томов (VG) или логического тома (LV) в состояние готовности к использованию ядром Linux. Деактивированные тома недоступны для ввода-вывода.

**Экспорт/Импорт (Export/Import)** — механизм подготовки группы томов для физического переноса между разными операционными системами или аппаратными узлами.

**Метаданные LVM** — служебная информация (хранится в начале PV и в `/etc/lvm/backup/`), описывающая структуру VG, PE-карту и параметры томов.

## Базовые концепции

Управление LVM — это иерархический процесс. Ошибки на нижних уровнях (PV) каскадно влияют на работоспособность всей системы.

### Этапы жизненного цикла

1.  **Инициализация (PV Layer):** Запись LVM-меток и резервирование места под метаданные на диске.
2.  **Агрегация (VG Layer):** Создание пула ресурсов. На этом этапе определяется размер Physical Extent (PE).
3.  **Выделение (LV Layer):** Нарезка виртуальных блочных устройств.
4.  **Эксплуатация:** Работа с файловыми системами, создание снимков, расширение.
5.  **Миграция и Перенос:** Перемещение данных между дисками (`pvmove`) или системный экспорт (`vgexport`).
6.  **Утилизация:** Демонтаж структур в порядке, строго обратном созданию.

### Управление состоянием и безопасность

-   **Автоматизация:** Современные дистрибутивы активируют LVM автоматически при загрузке через `udev` и `systemd-udev-settle`.
-   **Резервное копирование:** LVM автоматически сохраняет копии метаданных в `/etc/lvm/backup/` при каждом изменении. Это позволяет восстановить структуру даже после случайного удаления `vgremove`.
-   **Целостность:** Нельзя удалять PV из VG (`vgreduce`), если на нем остались занятые экстенты. Сначала требуется `pvmove`.

## Практические сценарии

### Сценарий 1: Полный цикл — от создания до удаления

Пример создания тома для базы данных и его последующей утилизации.

**Шаг 1: Инициализация физического диска**
```bash
sudo pvcreate /dev/sdc
# → Physical volume "/dev/sdc" successfully created.
```

**Шаг 2: Создание группы томов**
```bash
sudo vgcreate vg_data /dev/sdc
# → Volume group "vg_data" successfully created
```

**Шаг 3: Создание логического тома**
```bash
sudo lvcreate -L 5G -n lv_db vg_data
# → Logical volume "lv_db" created.
```

**Шаг 4: Утилизация (Удаление)**
```bash
sudo umount /mnt/db
sudo lvremove /dev/vg_data/lv_db  # Удаление LV
sudo vgremove vg_data             # Удаление VG
sudo pvremove /dev/sdc            # Очистка диска
# → Labels on physical volume "/dev/sdc" successfully wiped.
```

### Сценарий 2: Перенос группы томов на другую систему

Используется при физической перестановке дисков между серверами.

**На исходном сервере:**
1. Размонтируйте ФС.
2. Деактивируйте и экспортируйте VG:
```bash
sudo vgchange -an vg_data         # Деактивация
sudo vgexport vg_data             # Экспорт (пометка VG как готовой к переносу)
# → Volume group "vg_data" successfully exported
```

**На целевом сервере:**
1. После подключения диска просканируйте устройства:
```bash
sudo pvscan
sudo vgimport vg_data             # Импорт
sudo vgchange -ay vg_data         # Активация
# → 1 logical volume(s) in volume group "vg_data" now active
```

### Сценарий 3: Восстановление после случайного удаления (Disaster Recovery)

Если группа томов была удалена командой `vgremove`, её можно восстановить из бэкапа метаданных.

**Шаг 1: Поиск последнего бэкапа**
```bash
ls /etc/lvm/backup/
# → vg_data
```

**Шаг 2: Тестовое восстановление**
```bash
sudo vgcfgrestore --test -f /etc/lvm/backup/vg_data vg_data
```

**Шаг 3: Применение восстановления**
```bash
sudo vgcfgrestore -f /etc/lvm/backup/vg_data vg_data
# → Restored volume group vg_data
```
