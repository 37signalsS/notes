# Жизненный цикл LVM

## Определения

**Жизненный цикл LVM (LVM Lifecycle)** — совокупность этапов существования системы логических томов: от инициализации физических носителей и агрегации ресурсов до эксплуатации, миграции и окончательной утилизации.

**Активация (Activation)** — процесс перевода группы томов (VG) или логического тома (LV) в состояние готовности к использованию ядром Linux. Деактивированные тома недоступны для ввода-вывода.

**Экспорт/Импорт (Export/Import)** — механизм подготовки группы томов для физического переноса между разными операционными системами или аппаратными узлами.

**Метаданные LVM** — служебная информация, описывающая структуру VG, PE-карту и параметры томов. Хранится в начале PV (Metadata Area) и дублируется в текстовом виде в `/etc/lvm/`.

## Базовые концепции

Управление LVM — это иерархический процесс. Ошибки на нижних уровнях (PV) каскадно влияют на работоспособность всей системы.

### Этапы жизненного цикла

1.  **Инициализация (PV Layer):** Запись LVM-меток и резервирование места под метаданные на диске.
2.  **Агрегация (VG Layer):** Создание пула ресурсов. Здесь определяется размер Physical Extent (PE).
3.  **Выделение (LV Layer):** Нарезка виртуальных блочных устройств.
4.  **Эксплуатация:** Работа с ФС, создание снимков, расширение томов.
5.  **Миграция и Перенос:** Перемещение данных между дисками (`pvmove`) или системный экспорт (`vgexport`).
6.  **Утилизация:** Демонтаж структур в порядке, строго обратном созданию.

### Управление состоянием и безопасность

-   **Автоматизация:** Современные дистрибутивы активируют LVM автоматически при загрузке через `udev`.
-   **Частичная активация:** Если один из PV в группе отсутствует, VG не активируется. Команда `vgchange -ay --partial` позволяет принудительно активировать уцелевшие LV (риск повреждения ФС, рекомендуется режим RO).
-   **Резервное копирование метаданных:**
    -   **/etc/lvm/backup/** — актуальная копия структуры VG.
    -   **/etc/lvm/archive/** — история изменений (автоматический бэкап **до** выполнения команды).
-   **Целостность:** Нельзя удалять PV из VG (`vgreduce`), если на нем остались занятые экстенты. Сначала требуется `pvmove`.

## Практические сценарии

### Сценарий 1: Полный цикл — от создания до удаления

**Шаг 1: Подготовка носителей**
```bash
sudo pvcreate /dev/sdc
# → Physical volume "/dev/sdc" successfully created.
```

**Шаг 2: Создание и нарезка пула**
```bash
sudo vgcreate vg_data /dev/sdc
sudo lvcreate -L 10G -n lv_app vg_data
# → Logical volume "lv_app" created.
```

**Шаг 3: Демонтаж (Удаление)**
Удаление выполняется строго в обратном порядке.
```bash
sudo umount /mnt/app
sudo lvremove /dev/vg_data/lv_app
sudo vgremove vg_data
sudo pvremove /dev/sdc
# → Labels on physical volume "/dev/sdc" successfully wiped.
```

### Сценарий 2: Перенос и клонирование групп томов

**Стандартный перенос диска на другой сервер:**
```bash
# Исходный сервер:
sudo vgchange -an vg_data
sudo vgexport vg_data
# → Volume group "vg_data" successfully exported

# Целевой сервер:
sudo pvscan
sudo vgimport vg_data
sudo vgchange -ay vg_data
# → 1 logical volume(s) in volume group "vg_data" now active
```

**Импорт клонированного диска (Duplicate UUID):**
Если диск был клонирован на уровне СХД, возникнет конфликт UUID.
```bash
sudo vgimportclone --basevgname vg_data_clone /dev/sdd
# → Volume group "vg_data" successfully cloned to "vg_data_clone"
```

### Сценарий 3: Восстановление метаданных (Disaster Recovery)

Если вы ошиблись с размером или случайно удалили логический том, LVM позволяет откатить состояние всей группы томов (VG) к предыдущему чекпоинту.

**Шаг 1: Поиск нужной точки отката**
```bash
sudo vgcfgrestore --list vg_data
# → File: /etc/lvm/archive/vg_data_00042-12345.vg
```

**Шаг 2: Применение восстановления**
```bash
sudo vgcfgrestore -f /etc/lvm/archive/vg_data_00042-12345.vg vg_data
```
