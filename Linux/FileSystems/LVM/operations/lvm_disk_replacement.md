# Замена физического диска в LVM

## Определения

**pvmove** — утилита LVM, предназначенная для перемещения физических экстентов (PE) с одного физического тома (PV) на другой (или другие) в пределах одной группы томов (VG) без остановки работы системы.

**Миграция данных (Migration)** — процесс переноса содержимого физического тома на новые носители для вывода старого оборудования из эксплуатации или балансировки нагрузки.

**Экстент (Extent)** — минимальный блок дискового пространства в LVM (обычно **4 МиБ**).

## Базовые концепции

Замена физического диска в LVM выполняется в режиме онлайн благодаря механизму Device Mapper. Данные перемещаются поблочно, при этом логический том остается доступным для чтения и записи.

### Ключевые принципы

-   **Область действия:** Миграция возможна только внутри одной Volume Group (VG). Напрямую между разными VG данные переместить нельзя.
-   **Доступное пространство:** В целевой VG должно быть достаточно свободных PE для размещения всех данных мигрируемого PV.
-   **Транзакционность:** Процесс перемещения каждого экстента атомарен. Если процесс прервется (сбой питания), он автоматически возобновится с последнего чекпоинта при повторном запуске `pvmove` без аргументов.
-   **Механизм работы:** LVM временно создает зеркальный LV для перемещаемых данных, что обеспечивает непрерывность доступа.

### Производительность и тюнинг

-   **Фоновый режим (`-b` / `--background`):** Рекомендуется для больших объемов (сотни ГиБ), чтобы не блокировать терминал.
-   **Интервал опроса (`-i` / `--interval`):** Задает частоту (в сек) проверки завершения копирования сегмента. Низкий интервал ускоряет миграцию, но создает нагрузку на запись метаданных VG.
-   **Приоритет I/O (`ionice`):** Чтобы миграция не мешала работе приложений, используйте минимальный приоритет:
    ```bash
    sudo ionice -c 3 pvmove -b /dev/sdb
    ```

## Практические сценарии

### Сценарий 1: Плановая замена диска

**Шаг 1: Подготовка нового диска**
```bash
sudo pvcreate /dev/sdd
# → Physical volume "/dev/sdd" successfully created.
```

**Шаг 2: Расширение группы томов**
```bash
sudo vgextend my_vg /dev/sdd
# → Volume group "my_vg" successfully extended
```

**Шаг 3: Запуск миграции данных**
```bash
# Запуск с контролем прогресса каждые 10 секунд
sudo pvmove -i 10 /dev/sdc
# → /dev/sdc: Moved: 0.52%
# → /dev/sdc: Moved: 100.00%
```
*Статус можно отслеживать через:* `sudo pvmove --status` или `sudo lvs -o+move_pv,move_pe`.

**Шаг 4: Вывод старого диска из группы**
```bash
sudo vgreduce my_vg /dev/sdc
# → Removed "/dev/sdc" from volume group "my_vg"
```

**Шаг 5: Очистка LVM-меток**
```bash
sudo pvremove /dev/sdc
# → Labels on physical volume "/dev/sdc" successfully wiped.
```

### Сценарий 2: Аварийная остановка и диагностика

Если процесс миграции завис или вызывает критическую нагрузку.

**Шаг 1: Принудительная остановка**
```bash
sudo pvmove --abort
# → Cancellation of pvmove in progress
```
*Уже перемещенные данные останутся на новом месте, LV продолжит работу.*

**Шаг 2: Анализ проблем**
Проверьте наличие ошибок ввода-вывода (I/O errors):
```bash
dmesg | grep -i "error"
```

**Шаг 3: Возобновление**
Для продолжения просто введите:
```bash
sudo pvmove
```

### Сценарий 3: Замена диска в RAID-массиве LVM

Для томов типа `raid1/5/6/10` вместо `pvmove` эффективнее использовать встроенный механизм MD-подсистемы.
```bash
# Прямая замена старого PV на новый в RAID-томе
sudo lvconvert --replace /dev/old_pv /dev/new_pv my_vg/raid_lv
```
*Это инициирует штатное перестроение (rebuild) массива на новом диске.*

### Сценарий 4: Аварийный вывод «мертвого» диска (Missing PV)

Если диск физически вышел из строя и его данные потеряны.
1. **Диагностика:** `vgs` покажет атрибут `p` (partial), `pvs` покажет `unknown device`.
2. **Удаление:**
   ```bash
   sudo vgreduce --removemissing --force my_vg
   ```
   **Внимание:** Все логические тома, которые находились на этом диске (даже частично), будут безвозвратно удалены.

### Сценарий 5: Миграция конкретного логического тома

Если нужно освободить место на диске только для одного LV.
```bash
sudo pvmove -n lv_data /dev/sdc /dev/sdd
```

## Дополнительная информация

### Нюансы для Тонких томов (Thin Pools)
-   **Метаданные:** Тонкий пул имеет том метаданных (`tmeta`). Его перемещение может вызвать кратковременные блокировки (stalls) записи во всем пуле.
-   **Риск переполнения:** Перед началом `pvmove` убедитесь, что пул не заполнен на 100%, иначе операция миграции может прерваться с ошибкой.
