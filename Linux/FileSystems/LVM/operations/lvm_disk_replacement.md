# Замена физического диска в LVM

## Определения

**pvmove** — утилита LVM, предназначенная для перемещения физических экстентов (PE) с одного физического тома (PV) на другой (или другие) в пределах одной группы томов (VG) без остановки работы системы.

**Миграция данных (Migration)** — процесс переноса содержимого физического тома на новые носители с целью вывода старого оборудования из эксплуатации или балансировки нагрузки.

## Базовые концепции

Замена физического диска в LVM выполняется в режиме онлайн благодаря механизму Device Mapper. Данные перемещаются поблочно, при этом логический том остается доступным для чтения и записи.

### Ключевые принципы

- **Область действия:** Миграция возможна только в пределах одной группы томов (Volume Group).
- **Доступное пространство:** В целевой VG должно быть достаточно свободных физических экстентов для размещения всех данных мигрируемого PV.
- **Фоновый режим:** Процесс `pvmove` выполняется в фоновом режиме. При больших объемах данных операция может занять значительное время.
- **Отказоустойчивость:** Если процесс прервется (например, из-за сбоя питания), он может быть возобновлен с того же места при повторном запуске команды.
- **Мониторинг:** Состояние процесса можно отслеживать через `pvmove --status` или просматривать атрибуты LV.

## Практические сценарии

### Сценарий 1: Плановая замена диска (Добавление нового + Удаление старого)

Типовой сценарий при замене старого HDD на новый или миграции на более емкий диск.

**Шаг 1: Подготовка нового диска**

Инициализируйте новый диск как физический том LVM.

```bash
sudo pvcreate /dev/sdd1
```

**Шаг 2: Расширение группы томов**

Добавьте новый диск в ту же группу томов, где находится заменяемый диск.

```bash
sudo vgextend my_vg /dev/sdd1
```

**Шаг 3: Запуск миграции данных**

Переместите данные со старого диска (например, `/dev/sdc1`).

```bash
# Запуск перемещения всех данных
sudo pvmove /dev/sdc1

# Мониторинг процесса (в другом терминале)
sudo pvmove --status
# или через атрибуты томов
sudo lvs -o+move_pv,move_pe
```

**Шаг 4: Извлечение старого диска из группы**

После завершения миграции (когда `pvs` покажет, что старый PV пуст), удалите его из VG.

```bash
sudo vgreduce my_vg /dev/sdc1
```

**Шаг 5: Очистка LVM-меток**

Удалите метаданные LVM с физического диска перед его физическим отключением.

```bash
sudo pvremove /dev/sdc1
```

### Сценарий 2: Аварийное обслуживание (Зависание процесса)

Если процесс миграции перестал прогрессировать:

1. **Проверка статуса:** `sudo pvmove --status`
2. **Анализ логов:** Проверьте `dmesg` на наличие ошибок ввода-вывода (I/O errors) на дисках.
3. **Возобновление:** Если система была перезагружена, просто запустите `sudo pvmove` без параметров — процесс продолжится автоматически.
