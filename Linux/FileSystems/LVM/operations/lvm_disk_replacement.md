# Замена физического диска в LVM

## Определения

**pvmove** — утилита LVM, предназначенная для перемещения физических экстентов (PE) с одного физического тома (PV) на другой (или другие) в пределах одной группы томов (VG) без остановки работы системы.

**Миграция данных (Migration)** — процесс переноса содержимого физического тома на новые носители с целью вывода старого оборудования из эксплуатации или балансировки нагрузки.

**Экстент (Extent)** — минимальный блок дискового пространства, которым оперирует LVM (обычно 4 МБ).

## Базовые концепции

Замена физического диска в LVM выполняется в режиме онлайн благодаря механизму Device Mapper. Данные перемещаются поблочно, при этом логический том остается доступным для чтения и записи.

### Ключевые принципы

- **Область действия:** Миграция возможна только в пределах одной группы томов (Volume Group). Нельзя переместить данные между разными VG напрямую.
- **Доступное пространство:** В целевой VG должно быть достаточно свободных физических экстентов для размещения всех данных мигрируемого PV.
- **Фоновый режим:** Процесс `pvmove` выполняется в фоновом режиме. При больших объемах данных операция может занять значительное время и создать нагрузку на I/O.
- **Транзакционность:** Процесс перемещения каждого экстента атомарен. Если процесс прервется (например, из-за сбоя питания), он может быть возобновлен с того же места при повторном запуске команды `pvmove` без аргументов.
- **Мониторинг:** Состояние процесса можно отслеживать через `pvmove --status` или атрибуты LV.

## Практические сценарии

### Сценарий 1: Плановая замена диска (Добавление нового + Удаление старого)

Типовой сценарий при замене старого накопителя на новый или миграции на более емкий диск.

**Шаг 1: Подготовка нового диска**
Инициализируйте новый диск (например, `/dev/sdd1`) как физический том LVM.
```bash
sudo pvcreate /dev/sdd1
# → Physical volume "/dev/sdd1" successfully created.
```

**Шаг 2: Расширение группы томов**
Добавьте новый диск в ту же группу томов, где находится заменяемый диск.
```bash
sudo vgextend my_vg /dev/sdd1
# → Volume group "my_vg" successfully extended
```

**Шаг 3: Запуск миграции данных**
Переместите данные со старого диска (например, `/dev/sdc1`).
```bash
# Запуск перемещения всех данных
sudo pvmove /dev/sdc1
# → /dev/sdc1: Moved: 0.52%
# → /dev/sdc1: Moved: 100.00%
```

**Мониторинг процесса:**
```bash
# Просмотр статуса
sudo pvmove --status
# → Task /dev/sdc1 is 45.2% complete

# Через атрибуты томов
sudo lvs -o+move_pv,move_pe
```

**Шаг 4: Извлечение старого диска из группы**
После завершения миграции удалите пустой PV из VG.
```bash
sudo vgreduce my_vg /dev/sdc1
# → Removed "/dev/sdc1" from volume group "my_vg"
```

**Шаг 5: Очистка LVM-меток**
Удалите метаданные LVM с физического диска.
```bash
sudo pvremove /dev/sdc1
# → Labels on physical volume "/dev/sdc1" successfully wiped.
```

### Сценарий 2: Аварийная остановка или сбой миграции

Если процесс миграции необходимо прервать или он перестал прогрессировать.

**Шаг 1: Принудительная остановка**
```bash
sudo pvmove --abort
# → Cancellation of pvmove in progress
```
*Примечание: Уже перемещенные данные останутся на новом месте, процесс остановится на границе текущего экстента.*

**Шаг 2: Анализ проблем**
Проверьте системный лог на наличие ошибок ввода-вывода (I/O errors):
```bash
dmesg | grep -i "error"
```

**Шаг 3: Возобновление**
Если система была перезагружена, просто запустите команду без параметров для продолжения:
```bash
sudo pvmove
```

### Сценарий 3: Миграция конкретного логического тома

Если нужно освободить место на диске только для одного критичного LV.

```bash
sudo pvmove -n my_lv /dev/sdc1 /dev/sdd1
```
*Здесь данные тома `my_lv` перемещаются с `/dev/sdc1` строго на `/dev/sdd1`.*
