# LVM: Снимки (Snapshots)

### Снимки (Snapshots)

Снимок — это "мгновенная" копия логического тома (LV), использующая механизм **copy-on-write**. Он занимает место только для данных, изменившихся с момента его создания. Идеально подходит для выполнения резервного копирования без остановки сервисов, так как основной том продолжает работать без прерываний.

#### Принцип работы: Copy-on-Write (COW)

LVM использует технологию **Copy-on-Write** (копирование при записи):

1. При создании снимка выделяется определенное место на диске (буфер).
2. Когда данные на исходном томе изменяются, **старые** данные копируются в область снимка **перед** записью новых данных.
3. Снимок хранит только те блоки, которые были изменены на исходном томе после создания снимка.

> **Размер снимка:** Снимок не обязан быть равен размеру исходного тома. Он должен вмещать только те данные, которые предположительно изменятся за время жизни снимка. Однако, если снимок переполнится, он станет недоступным.

Для создания снимка LVM-тома используется команда `lvcreate` с опциями `-L` (указать размер снимка), `-s` (указать, что это снимок) и `-n` (указать имя снимка).

**Пример команды:**

```bash
lvcreate -L 1G -s -n my_lv_snapshot /dev/my_vg/my_lv
```

* `-L 1G`: задает размер снимка в 1 Гигабайт (это буфер для хранения изменений, происходящих на оригинальном томе после создания снимка).
* `-s`: указывает, что создается моментальный снимок (snapshot).
* `-n my_lv_snapshot`: задает имя для нового снимка.
* `/dev/my_vg/my_lv`: полный путь к оригинальному логическому тому, для которого создается снимок.

После создания снимка, вы можете смонтировать его как обычный том, выполнить резервное копирование данных, а затем удалить снимок. Это позволяет получить консистентную копию данных без простоя приложения.

**Использование снимка:**

Смонтируйте снимок как обычный том для доступа к данным:

```bash
mkdir /mnt/snapshot
mount /dev/my_vg/my_lv_snapshot /mnt/snapshot
# ... выполнить резервное копирование данных с /mnt/snapshot ...
```

**Удаление снимка:**

После завершения резервного копирования снимок следует удалить, чтобы освободить занимаемое им пространство:

```bash
umount /mnt/snapshot
lvremove /dev/my_vg/my_lv_snapshot
```

### Восстановление из снимка (lvconvert --merge)

Снимок можно "слить" обратно в исходный том. При этом изменения, накопленные в снимке, будут применены к исходному тому, а сам снимок будет удален.

> **Важно:** Для восстановления **оба тома должны быть отмонтированы**. Если это корневая ФС, потребуется загрузка в режиме восстановления (recovery mode) или использование LiveCD.

```bash
# Отмонтировать исходный том и снимок
umount /dev/my_vg/my_lv
umount /dev/my_vg/my_lv_snapshot

# Слить снимок с исходным томом
lvconvert --merge /dev/my_vg/my_lv_snapshot

# Примонтировать восстановленный том
mount /dev/my_vg/my_lv /mnt/data
```

### Производительность

Снимки увеличивают количество операций записи на диск, так как при каждом изменении данных на исходном томе происходит:
1. Чтение старых данных
2. Запись старых данных в снимок
3. Запись новых данных на исходный том

Поэтому на активно используемых томах снимки могут **снижать производительность**, особенно если снимков несколько. Рекомендуется создавать снимки перед рискованными операциями (обновлениями) и удалять их сразу после завершения задачи.
