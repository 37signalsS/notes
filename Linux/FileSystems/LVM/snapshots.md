# LVM: Снимки (Snapshots)

---

## Определения

**Снимок (Snapshot)** — "мгновенная" копия логического тома (LV), использующая механизм **copy-on-write (COW)**. Занимает место только для данных, изменившихся с момента создания.

**Основное применение:** Резервное копирование без остановки сервисов.

---

## Основные концепции

### Принцип работы: Copy-on-Write (COW)

LVM использует технологию **Copy-on-Write**:

1. При создании снимка выделяется буфер определённого размера.
2. При изменении данных на исходном томе **старые** данные копируются в область снимка **перед** записью новых.
3. Снимок хранит только блоки, изменённые после его создания.

```
Исходный том (LV)          Снимок (Snapshot)
┌─────────────────┐        ┌─────────────────┐
│ Блок A: данные1 │ ─────→ │ Блок A: данные1 │ (скопировано при записи)
│ Блок B: данные2 │        │                 │
│ Блок C: данные3 │ ─────→ │ Блок C: данные3 │ (скопировано при записи)
│ Блок D: данные4 │        │                 │
└─────────────────┘        └─────────────────┘
     Изменён: A, C              Занято: 2 блока
```

#### Размер снимка

**Снимок не обязан быть равен размеру исходного тома!**

- Должен вмещать только данные, которые изменятся за время жизни снимка
- **Риск:** При переполнении снимок становится недоступным
- **Рекомендация:** 10–20% от размера LV для краткосрочных снимков

## Практические сценарии

### Сценарий 1: Создание снимка для резервного копирования

```bash
# Создать снимок размером 1 ГБ
lvcreate -L 1G -s -n my_lv_snapshot /dev/my_vg/my_lv
```

| Параметр | Описание |
| :--- | :--- |
| `-L 1G` | Размер буфера снимка (1 ГБ) |
| `-s` | Режим снимка (snapshot) |
| `-n my_lv_snapshot` | Имя снимка |
| `/dev/my_vg/my_lv` | Исходный логический том |

#### Использование снимка

```bash
# Смонтировать снимок
mkdir /mnt/snapshot
mount /dev/my_vg/my_lv_snapshot /mnt/snapshot

# Выполнить резервное копирование
tar -czf /backup/data.tar.gz /mnt/snapshot/

# Размонтировать и удалить снимок
umount /mnt/snapshot
lvremove /dev/my_vg/my_lv_snapshot
```

---

### Сценарий 2: Восстановление из снимка (lvconvert --merge)

Снимок можно "слить" обратно в исходный том. Накопленные изменения будут применены, снимок удалён.

> **Важно:** Оба тома должны быть **отмонтированы**. Для корневой ФС требуется загрузка в recovery mode или LiveCD.

```bash
# Отмонтировать исходный том и снимок
umount /dev/my_vg/my_lv
umount /dev/my_vg/my_lv_snapshot

# Слить снимок с исходным томом
lvconvert --merge /dev/my_vg/my_lv_snapshot

# Примонтировать восстановленный том
mount /dev/my_vg/my_lv /mnt/data
```

---

### Сценарий 3: Мониторинг снимков

```bash
# Проверка использования снимка
lvs -o+snap_percent my_vg

# Вывод:
#   LV              VG    Attr       LSize   Snap%
#   my_lv           my_vg owi-a-----  10.00g
#   my_lv_snapshot  my_vg swi-a-----   1.00g  15.23
```

| Значение Snap% | Действие |
| :--- | :--- |
| < 50% | Норма |
| 50–80% | Планировать удаление/расширение |
| > 80% | **Критично!** Удалить или расширить немедленно |
| 100% | Снимок недоступен, требует удаления |

---

### Сценарий 4: Расширение снимка

Если снимок переполняется, его можно расширить:

```bash
# Расширить снимок на 500 МБ
lvextend -L +500M /dev/my_vg/my_lv_snapshot
```

## Производительность

Снимки увеличивают количество операций записи:

1. Чтение старых данных
2. Запись старых данных в снимок
3. Запись новых данных на исходный том

**Влияние:**

- На активно используемых томах — **снижение производительности**
- Несколько снимков — кумулятивный эффект

**Рекомендации:**

- Создавать снимки перед рискованными операциями (обновления, миграции)
- Удалять сразу после завершения задачи
- Не использовать для долгосрочного хранения

## Тонкие снимки (Thin Snapshots)

При использовании тонкого провизионирования ([thin-provisioning.md](./thin-provisioning.md)) снимки создаются без выделения фиксированного размера:

```bash
# Создать тонкий снимок (не требует указания размера)
lvcreate -s -n thin_snapshot /dev/my_vg/thin_lv
```

**Преимущества:**

- Не требует предварительного выделения места
- Использует пространство пула динамически

**Недостатки:**

- Зависит от свободного места в пуле
- Требует мониторинга пула

## Диагностика и troubleshooting

### Частые проблемы

| Проблема | Команда проверки | Решение |
| :--- | :--- | :--- |
| Снимок переполнен | `lvs -o+snap_percent` | Удалить снимок (`lvremove`) |
| Невозможно создать снимок | `vgs` (нет места) | Освободить место в VG |
| Снимок не активируется | `lvchange -ay <snapshot>` | Проверить зависимости LV |

### Команды управления

```bash
# Создание
lvcreate -L 1G -s -n <имя> <исходный_LV>

# Просмотр
lvs -o+snap_percent

# Расширение
lvextend -L +500M <снимок>

# Удаление
lvremove <снимок>

# Восстановление
lvconvert --merge <снимок>
```
