# LVM — снимки

## Определения

**Снимок (Snapshot)** — виртуальная копия логического тома (LV), зафиксированная на определенный момент времени. Использует механизм **Copy-on-Write (COW)**, что позволяет создавать снимки мгновенно, независимо от объема данных.

**COW (Copy-on-Write — копирование при записи)** — стратегия оптимизации, при которой новые данные записываются в новое место, а старые данные из исходного тома копируются в область снимка только в момент их первого изменения.

**Thin Snapshot (Тонкий снимок)** — снимок, созданный внутри **Thin Pool**. Не требует фиксированного объема заранее и динамически потребляет пространство пула.

## Базовые концепции

### Принцип работы COW

При создании обычного (толстого) снимка выделяется специальная область — COW-буфер.
1.  **Запрос на запись:** Приходит на блок `A` исходного тома.
2.  **Сохранение оригинала:** LVM считывает блок `A` и записывает его в COW-буфер снимка.
3.  **Обновление данных:** Новые данные записываются в блок `A` исходного тома.

*Результат:* Снимок содержит «старое» состояние блока, исходный том — «новое».

### Влияние на производительность

Использование снимков создает дополнительную нагрузку на дисковую подсистему:
-   **Задержка при записи (Latency):** Каждая первая запись в блок требует чтения и записи (3 операции ввода-вывода вместо 1).
-   **Множественные снимки:** Если у одного LV есть 5 снимков, одна запись в исходный том может породить до 5 операций копирования (по одной в каждый снимок).
-   **Рекомендация:** Используйте снимки для краткосрочных задач (бэкап, обновление ОС) и удаляйте их сразу после завершения работ.

### Атрибуты и мониторинг состояния

В выводе команды `lvs` состояние снимка отображается в колонке `Attr`.

| Позиция | Символ | Описание |
| :--- | :--- | :--- |
| 1 (Тип) | `s` | Обычный исправный снимок (Snapshot). |
| 1 (Тип) | `S` | Невалидный снимок (Invalid Snapshot) — переполнен. |
| 5 (Статус) | `I` | Снимок стал невалидным из-за нехватки места. |
| 5 (Статус) | `s` / `S` | Снимок приостановлен (Suspended). |
| 10 (Акт.) | `k` | Активация пропущена (Activation Skip). |

*Пример невалидного снимка:*
```bash
lvs
# → LV            VG      Attr       LSize   Origin  Snap%
# → lv_data_snap  vg_data Swi-I-p---  2.00g  lv_data 100.00
```
*Такой снимок нельзя смонтировать, его необходимо удалить.*

### Автоматическое расширение

LVM поддерживает автоматическое расширение снимков при достижении порога заполнения. Настраивается в `/etc/lvm/lvm.conf` в секции `activation`.

```conf
# /etc/lvm/lvm.conf
activation {
    snapshot_autoextend_threshold = 70
    snapshot_autoextend_percent = 20
}
```
*Логика:* При заполнении на 70% снимок будет расширен на 20% от текущего размера. 
**Требование:** В системе должен быть запущен демон `dmeventd`, а в VG должно быть свободное место.

## Практические сценарии

### Сценарий 1: Создание снимка

**Базовое создание:**
```bash
sudo lvcreate -L 2G -s -n lv_root_snap /dev/vg_system/lv_root
# → Logical volume "lv_root_snap" created.
```

**Создание с пропуском активации (Activation Skip):**
Полезно для бэкапов, чтобы устройство не появлялось в `/dev/mapper` сразу.
```bash
sudo lvcreate -L 5G -s -n lv_backup_snap -ky /dev/vg_data/lv_data
```
*Для активации такого снимка вручную:*
```bash
sudo lvchange -ay -K /dev/vg_data/lv_backup_snap
```

### Сценарий 2: Восстановление данных (Слияние)

Используется утилита `lvconvert --merge` для возврата состояния тома.

**Внимание:** Для корневой ФС потребуется перезагрузка. Для обычных томов — размонтирование.

```bash
# 1. Размонтирование (если возможно)
sudo umount /mnt/data

# 2. Запуск слияния
sudo lvconvert --merge /dev/vg_data/lv_data_snap
# → Merging of volume vg_data/lv_data_snap started.

# 3. Активация тома (если слияние выполняется в фоне)
sudo lvchange -ay /dev/vg_data/lv_data
```

### Сценарий 3: Мониторинг и ручное расширение

Критически важно для предотвращения выхода снимка из строя (`Snap%` не должен достигать 100%).

```bash
sudo lvs -o lv_name,vg_name,lv_size,snap_percent
# → LV            VG      LSize   Snap%
# → lv_root       vg_sys  20.00g
# → lv_root_snap  vg_sys   2.00g  45.12
```

**Ручное расширение:**
```bash
sudo lvextend -L +1G /dev/vg_system/lv_root_snap
# → Logical volume vg_system/lv_root_snap successfully resized.
```

### Сценарий 4: Традиционные (Thick) vs Тонкие (Thin) снимки

| Характеристика | Традиционные (Thick) | Тонкие (Thin) |
| :--- | :--- | :--- |
| **Рекурсия** | Нет (нельзя сделать снимок со снимка) | **Да** (любая глубина вложенности) |
| **Выделение места** | Сразу (фиксированный размер) | Динамически из Thin Pool |
| **Производительность** | Падает с числом снимков | Почти не зависит от количества |
| **Переполнение** | Умирает конкретный снимок | Может заблокировать весь Thin Pool |

**Пример рекурсивного тонкого снимка:**
```bash
# Снимок со снимка
sudo lvcreate -s -n thin_snap_v2 /dev/vg_data/thin_snap_v1
```
