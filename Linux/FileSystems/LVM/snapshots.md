# LVM — снимки

---

## Определения

**Снимок (Snapshot)** — «мгновенная» копия логического тома (LV), использующая механизм **Copy-on-Write (COW)**. Занимает место только для данных, изменившихся с момента создания снимка.

**Основное применение:** Резервное копирование без остановки сервисов и создание точек отката перед рискованными операциями.

---

## Основные концепции

### Принцип работы — Copy-on-Write (COW)

LVM использует технологию **Copy-on-Write**:

1. При создании снимка выделяется буфер определенного размера (cow-область).
2. При изменении данных на исходном томе **старые** данные копируются в область снимка **перед** записью новых.
3. Снимок хранит только блоки, измененные после его создания.

```
Исходный том (LV)          Снимок (Snapshot)
┌─────────────────┐        ┌─────────────────┐
│ Блок A: данные1 │ ─────→ │ Блок A: данные1 │ (скопировано при записи)
│ Блок B: данные2 │        │                 │
│ Блок C: данные3 │ ─────→ │ Блок C: данные3 │ (скопировано при записи)
│ Блок D: данные4 │        │                 │
└─────────────────┘        └─────────────────┘
     Изменен: A, C              Занято: 2 блока
```

### Размер снимка

**Снимок не обязан быть равен размеру исходного тома.**

- Должен вмещать только данные, которые изменятся за время жизни снимка.
- **Риск:** При переполнении снимка (100% COW-области) он становится недоступным и невалидным.
- **Рекомендация:** 10–20% от размера LV для краткосрочных снимков.

### Производительность

Снимки увеличивают количество операций записи (I/O overhead):

1. Чтение старых данных из исходного тома.
2. Запись старых данных в снимок.
3. Запись новых данных на исходный том.

**Влияние:**

- На активно используемых томах — снижение производительности.
- Наличие нескольких снимков одного тома создает кумулятивный эффект (каждая запись дублируется во все снимки).

## Практические сценарии

### Создание снимка для резервного копирования

```bash
# Создать снимок размером 1 ГБ
lvcreate -L 1G -s -n my_lv_snapshot /dev/my_vg/my_lv
```

| Параметр | Описание |
| :--- | :--- |
| `-L 1G` | Размер буфера снимка (1 ГБ) |
| `-s` | Режим снимка (snapshot) |
| `-n my_lv_snapshot` | Имя снимка |
| `/dev/my_vg/my_lv` | Исходный логический том |

#### Использование снимка

```bash
# Смонтировать снимок
mkdir /mnt/snapshot
mount /dev/my_vg/my_lv_snapshot /mnt/snapshot

# Выполнить резервное копирование
tar -czf /backup/data.tar.gz /mnt/snapshot/

# Размонтировать и удалить снимок
umount /mnt/snapshot
lvremove /dev/my_vg/my_lv_snapshot
```

### Восстановление из снимка — lvconvert --merge

Снимок можно «слить» обратно в исходный том. Накопленные изменения будут применены, а снимок удален.

> **Важно:** Для слияния оба тома должны быть **отмонтированы**. Для корневой ФС потребуется перезагрузка (слияние произойдет при активации тома ядром).

```bash
# Отмонтировать исходный том и снимок
umount /dev/my_vg/my_lv
umount /dev/my_vg/my_lv_snapshot

# Слить снимок с исходным томом
lvconvert --merge /dev/my_vg/my_lv_snapshot

# Примонтировать восстановленный том
mount /dev/my_vg/my_lv /mnt/data
```

### Мониторинг и расширение снимков

```bash
# Проверка использования снимка
lvs -o+snap_percent my_vg

# Вывод:
#   LV              VG    Attr       LSize   Snap%
#   my_lv           my_vg owi-a-----  10.00g
#   my_lv_snapshot  my_vg swi-a-----   1.00g  15.23
```

| Значение Snap% | Состояние | Действие |
| :--- | :--- | :--- |
| < 50% | Норма | Нет |
| 50–80% | Внимание | Планировать удаление или расширение |
| > 80% | Критично | Расширить немедленно |
| 100% | Снимок сломан | Только удаление (`lvremove`) |

Если снимок близок к заполнению, его можно расширить (при наличии свободного места в VG):

```bash
# Расширить снимок на 500 МБ
lvextend -L +500M /dev/my_vg/my_lv_snapshot
```

### Тонкие снимки — Thin Snapshots

При использовании **Thin Provisioning** снимки создаются без предварительного выделения фиксированного размера COW-области.

```bash
# Создать тонкий снимок
lvcreate -s -n thin_snapshot /dev/my_vg/thin_lv
```

**Особенности:**

- Не требует указания размера при создании.
- Использует общее пространство **Thin Pool** динамически.
- Поддерживает рекурсивные снимки (снимок со снимка).

Подробности работы с пулами описаны в [Thin Provisioning](./thin-provisioning.md).

## Дополнительная информация

### Диагностика и устранение неисправностей

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Снимок переполнен (Snap% = 100) | Слишком много изменений в исходном LV | Удалить снимок. В следующий раз выделить больше места. |
| Ошибка при `lvconvert --merge` | Том занят (mounted) | Отмонтировать LV или перезагрузиться. |
| Низкая скорость записи на LV | Влияние COW-механизма | Удалить ненужные снимки. |

### Команды управления

```bash
# Создание
lvcreate -L 1G -s -n <имя> <исходный_LV>

# Просмотр статуса
lvs -o+snap_percent

# Расширение (только для обычных снимков)
lvextend -L +500M <снимок>

# Удаление
lvremove <снимок>

# Откат к состоянию снимка
lvconvert --merge <снимок>
```
