# LVM — Операции управления

## Определения

**Операции управления LVM** — совокупность административных задач по поддержке, мониторингу и изменению конфигурации системы логических томов на протяжении всего их жизненного цикла.

**LVM CLI Toolkit** — набор утилит пользовательского пространства (pvs, vgs, lvs и др.), взаимодействующих с Device Mapper в ядре для управления блочными устройствами.

**Фильтры LVM** — параметры конфигурации в `/etc/lvm/lvm.conf`, ограничивающие список блочных устройств, которые система должна сканировать при поиске метаданных LVM.

## Базовые концепции

### Иерархия инструментов управления

Инструментарий LVM разделен по функциональному назначению:
1.  **Reporting (Отчеты):** `pvs`, `vgs`, `lvs`. Компактный табличный вывод, идеально подходит для мониторинга.
2.  **Display (Детализация):** `pvdisplay`, `vgdisplay`, `lvdisplay`. Подробная многострочная информация об объектах.
3.  **Action (Действие):** `pvcreate`, `vgextend`, `lvextend`, `lvremove`. Команды, вносящие изменения в структуру.
4.  **Maintenance (Обслуживание):** `pvscan`, `vgscan`, `vgck`, `pvck`. Сканирование и проверка целостности.

## Практические сценарии

### Сценарий 1: Оперативная проверка здоровья (SRE Cheat Sheet)

Быстрая диагностика всех уровней абстракции:
```bash
# 1. Проверка физических дисков на ошибки метаданных
sudo pvs
# → PV         VG      Fmt  Attr PSize   PFree
# → /dev/sdb1  data_vg lvm2 a--  <20.00g <5.00g

# 2. Проверка свободного места для расширения
sudo vgs
# → VG      #PV #LV #SN Attr   VSize   VFree
# → data_vg   1   2   0 wz--n- <20.00g <5.00g

# 3. Поиск "зависших" снимков или переполненных тонких томов
sudo lvs -o lv_name,data_percent,snap_percent
```

### Сценарий 2: Аварийное обслуживание (Scan & Repair)

Используется, когда тома не видны в системе после перезагрузки или подключения нового SAN-хранилища.

```bash
# Обновление кэша фильтров и поиск VG
sudo vgscan
# → Found volume group "data_vg" using metadata type lvm2

# Принудительная активация всех найденных томов
sudo vgchange -ay
# → 2 logical volume(s) in volume group "data_vg" now active
```

### Сценарий 3: Управление фильтрами устройств

Настройка LVM на игнорирование определенных дисков (например, локальных дисков при наличии Multipath).

**Правка `/etc/lvm/lvm.conf`:**
```ini
devices {
    # Разрешить только multipath-устройства и запретить всё остальное
    filter = [ "a|/dev/mapper/mpath.*|", "r|.*|" ]
}
```

## Дополнительная информация

### Диагностика и устранение неисправностей

| Проблема | Признак | Решение |
| :--- | :--- | :--- |
| **VG Not Found** | Система не грузится или VG не видна | Проверить фильтры в `lvm.conf` и выполнить `vgscan`. |
| **I/O Error (Thin Pool)** | ФС перешла в Read-Only | Пул переполнен (`Data% = 100`). Расширить пул командой `lvextend`. |
| **Metadata Corruption** | Команда `vgck` выдает ошибки | Восстановить из `/etc/lvm/backup/` (см. [Advanced Topics](./advanced_topics/practical_scenarios.md)). |
