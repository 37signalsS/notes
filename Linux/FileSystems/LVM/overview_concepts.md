# LVM — Обзор и основные концепции

## Определения

**LVM (Logical Volume Manager — менеджер логических томов)** — система управления дисковым пространством в Linux, предоставляющая слой абстракции между физическими накопителями и файловыми системами.

**Device Mapper** — фреймворк ядра Linux, обеспечивающий отображение (mapping) одного блочного устройства на другое. Является архитектурной основой для LVM, программных RAID (dm-raid) и шифрования (dm-crypt).

**Physical Volume (PV — физический том)** — базовый уровень хранения в LVM. Это может быть целый диск (`/dev/sdb`), раздел (`/dev/sdc1`) или даже файл-образ.

**Volume Group (VG — группа томов)** — виртуальный пул, объединяющий ресурсы одного или нескольких PV. VG представляет собой единое адресное пространство.

**Logical Volume (LV — логический том)** — виртуальный раздел, нарезаемый из пространства VG. Для операционной системы LV выглядит как обычное блочное устройство.

## Базовые концепции

### Иерархическая структура

Архитектура LVM строится по принципу снизу вверх:
1.  **PV Layer:** Инициализация физических носителей. В начале каждого PV резервируется место под метаданные.
2.  **VG Layer:** Агрегация PV в общий пул. Здесь определяется размер **Physical Extent (PE)** — минимального кванта данных.
3.  **LV Layer:** Выделение виртуальных устройств. Размер LV всегда кратен размеру PE.

### Механизм отображения (Mapping)

LVM оперирует логическими экстентами (**LE**), которые сопоставляются с физическими экстентами (**PE**).
-   В **линейных томах (Linear LV)** экстенты выделяются последовательно.
-   В **чередующихся томах (Striped LV)** данные распределяются между несколькими PV для повышения производительности (аналог RAID 0).
-   В **зеркальных томах (Mirrored LV)** экстенты дублируются на разных PV (аналог RAID 1).

### Преимущества абстракции

-   **Гибкость:** Возможность расширения ФС «на лету» без размонтирования (для XFS и ext4).
-   **Объединение:** Создание тома размером больше, чем любой из физических дисков в системе.
-   **Снапшоты:** Мгновенная фиксация состояния данных для бэкапа (механизм COW).
-   **Миграция:** Перемещение данных между дисками (`pvmove`) без остановки работы сервисов.

## Практические сценарии

### Создание базовой структуры хранения

Типовой процесс подготовки диска для приложения:

**Шаг 1: Инициализация физического устройства**
```bash
sudo pvcreate /dev/sdb
# → Physical volume "/dev/sdb" successfully created.
```

**Шаг 2: Создание группы томов**
```bash
sudo vgcreate vg_data /dev/sdb
# → Volume group "vg_data" successfully created
```

**Шаг 3: Выделение логического тома**
```bash
sudo lvcreate -L 10G -n lv_app vg_data
# → Logical volume "lv_app" created.
```

**Шаг 4: Подготовка файловой системы**
```bash
sudo mkfs.xfs /dev/vg_data/lv_app
sudo mount /dev/vg_data/lv_app /mnt/app
```
*Подробные параметры команд см. в [Создание PV, VG и LV](./operations/pv_vg_creation.md).*

## Дополнительная информация

### Особенности эксплуатации

-   **initramfs:** Если корень (`/`) находится на LVM, образ `initramfs` должен содержать хук `lvm2` для активации VG до монтирования ФС.
-   **Размещение /boot:** Крайне рекомендуется выносить `/boot` на отдельный физический раздел (Standard Partition), чтобы обеспечить доступ загрузчика к ядру даже при повреждении метаданных LVM.
-   **Метаданные:** LVM хранит текстовые копии конфигурации в `/etc/lvm/backup/`. Всегда делайте бэкап этой директории.
