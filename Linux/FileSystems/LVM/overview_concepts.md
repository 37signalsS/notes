# LVM — Обзор и основные концепции

---

## Определения

**LVM (Logical Volume Manager — менеджер логических томов)** — система управления дисковым пространством в Linux, которая предоставляет уровень абстракции между физическими дисками и файловыми системами.

**Основное назначение:** Гибкое управление дисковыми ресурсами, позволяющее объединять несколько физических устройств в единые пулы и изменять размеры разделов без остановки системы.

---

## Основные концепции

### LVM и Device Mapper

LVM не является изолированным модулем ядра. Это набор утилит пользовательского пространства, работающих поверх фреймворка **Device Mapper**.

**Device Mapper** — инфраструктура в ядре Linux, предназначенная для создания виртуальных блочных устройств и отображения (mapping) их секторов на другие блочные устройства. На Device Mapper также основаны:

- **dm-crypt/LUKS** — шифрование дисков.
- **mdadm** — программные RAID-массивы.

### Иерархия LVM (PV, VG, LV)

Структура LVM строится по трехуровневой схеме:

1. **PV (Physical Volume — физический том)**:
    - Нижний уровень: физический диск (например, `/dev/sdb`) или раздел (`/dev/sdb1`).
    - Инициализируется командой `pvcreate`.
    - Содержит метаданные LVM.

2. **VG (Volume Group — группа томов)**:
    - Средний уровень: объединение одного или нескольких PV в единый пул дискового пространства.
    - Инициализируется командой `vgcreate`.
    - Представляет собой виртуальный «диск», из которого нарезаются логические разделы.

3. **LV (Logical Volume — логический том)**:
    - Верхний уровень: виртуальный раздел, создаваемый внутри VG.
    - Инициализируется командой `lvcreate`.
    - Форматируется в файловую систему (ext4, xfs) и монтируется как обычное блочное устройство (путь: `/dev/mapper/VG-LV` или `/dev/VG/LV`).

### Базовые единицы — экстенты (PE и LE)

Все пространство внутри LVM делится на блоки фиксированного размера — экстенты.

- **PE (Physical Extent — физический экстент)**: Минимальная единица дискового пространства в VG. По умолчанию размер PE составляет **4 МБ**.
- **LE (Logical Extent — логический экстент)**: Единица, из которой состоит LV. Размер LE всегда равен размеру PE в данной VG.

**Механизм работы:** LVM создает карту сопоставления LE → PE. Это позволяет LV быть «фрагментированным» на физическом уровне (находиться на разных дисках), оставаясь непрерывным логическим устройством для операционной системы.

## Практические сценарии

### Создание базовой структуры LVM

Типовой процесс подготовки нового хранилища:

```bash
# 1. Подготовка физического устройства
pvcreate /dev/sdb1

# 2. Создание группы томов
vgcreate data_vg /dev/sdb1

# 3. Создание логического тома на 10 ГБ
lvcreate -L 10G -n data_lv data_vg

# 4. Создание файловой системы и монтирование
mkfs.ext4 /dev/data_vg/data_lv
mount /dev/data_vg/data_lv /mnt/data
```

Подробные инструкции приведены в разделе **[Создание PV, VG и LV](./operations/pv_vg_creation.md)**.

## Дополнительная информация

### Взаимодействие с процессом загрузки

Если корневая файловая система (`/`) расположена на LVM, процесс загрузки имеет особенности:

1. **initramfs (Initial RAM File System)**: Должна содержать драйверы Device Mapper и утилиты LVM для активации томов перед монтированием корня.
2. **Ограничение /boot**: Рекомендуется выносить каталог `/boot` на отдельный стандартный раздел (не LVM). Это гарантирует, что загрузчик (GRUB) сможет прочитать ядро и `initramfs` до того, как будет активирован LVM.

### Рекомендации по планированию

- **Не выделяйте все место сразу**: Оставляйте 10–20% пространства в Volume Group свободным. Это необходимо для создания **[снимков](./snapshots.md)**, расширения томов или временных операций при замене дисков.
- **Названия**: Используйте осмысленные имена для VG и LV (например, `vg_system`, `lv_docker`), чтобы избежать путаницы при большом количестве дисков.
