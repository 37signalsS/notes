# LVM (Logical Volume Manager): Обзор и Основные Концепции

## Определения

**LVM (Logical Volume Manager)** — система управления логическими томами в Linux, абстрагирующая физическое дисковое пространство для гибкого управления без остановки системы.

**Ключевое преимущество:** LVM решает ограничения традиционного разбиения дисков:
- Невозможность легко изменять размеры разделов
- Отсутствие возможности объединять пространство с разных физических дисков

---

## Основные концепции

### LVM и Device Mapper

Важно понимать, что LVM не является самостоятельным модулем ядра. Вместо этого, LVM — это набор пользовательских утилит (`pvcreate`, `vgcreate`, `lvcreate` и др.), которые работают поверх фреймворка **Device Mapper** в ядре Linux.

**Device Mapper** — универсальный слой ядра, предоставляющий инфраструктуру для создания виртуальных блочных устройств и отображения (mapping) их секторов на другие блочные устройства.

| Компонент | Уровень | Назначение |
| :--- | :--- | :--- |
| **Device Mapper** | Ядро Linux | Низкоуровневый механизм создания "логических" устройств |
| **LVM** | Пользовательское пространство | Высокоуровневые инструменты и политика управления (PV, VG, LV) |

**Проще говоря:** **LVM — это удобный интерфейс к Device Mapper**. Помимо LVM, Device Mapper также является основой для:
- Шифрования дисков (`dm-crypt`/LUKS)
- Программного RAID (`mdadm`)

---

### Ключевые абстракции: PV, VG, LV

#### Иерархия LVM

```
Физический диск (PV)
       ↓
Группа томов (VG) — пул пространства
       ↓
Логический том (LV) — "виртуальный раздел"
       ↓
Файловая система (ext4, xfs)
       ↓
Точка монтирования (/mnt/data)
```

#### 1. Physical Volume (PV) — Физический том

Базовый строительный блок LVM:
- Физический диск (`/dev/sdb`) или раздел (`/dev/sdb1`)
- Инициализируется командой `pvcreate`
- Содержит метаданные LVM в начале устройства

#### 2. Volume Group (VG) — Группа томов

Объединённый пул дискового пространства:
- Создаётся из одного или нескольких PV командой `vgcreate`
- Представляет единое адресное пространство
- Имеет фиксированный размер PE (Physical Extent)

#### 3. Logical Volume (LV) — Логический том

Аналог обычного раздела диска:
- "Нарезается" из пространства VG командой `lvcreate`
- Форматируется в файловую систему (ext4, xfs)
- Монтируется в каталог как обычное блочное устройство
- Путь: `/dev/<VG>/<LV>` или `/dev/mapper/<VG>-<LV>`

---

### Базовые единицы: Экстенты (PE и LE)

В основе LVM лежат экстенты — минимальные непрерывные блоки данных.

| Тип | Расшифровка | Описание |
| :--- | :--- | :--- |
| **PE** | Physical Extent | Физический экстент. VG делится на PE одинакового размера. **По умолчанию 4 МБ** |
| **LE** | Logical Extent | Логический экстент. LV состоит из LE. Размер LE = размеру PE |

**Принцип работы:** LVM создаёт карту сопоставления LE → PE. При изменении размера тома обновляется только карта, а не физические данные.

**Пример:**
```
LV (10 ГБ) = 2560 LE × 4 МБ
     ↓
Карта: LE[0] → PE[100], LE[1] → PE[101], ...
     ↓
PV1: PE[100-500], PV2: PE[501-1500], PV3: PE[1501-2560]
```

### Преимущества и философия использования

| Преимущество | Описание |
| :--- | :--- |
| **Гибкость** | Объединение дисков, изменение размеров "на лету" |
| **Абстракция** | LV не привязаны к физическому расположению на дисках |
| **Продвинутые функции** | [Снимки](./snapshots.md), [Тонкое провизионирование](./thin_provisioning.md) |
| **Простота управления** | Нет жесткого планирования разделов |

#### Рекомендации по свободному пространству

**Не выделяйте всё свободное пространство VG под LV!**

Оставшееся место полезно для:
- Расширения существующих томов
- Создания снимков (snapshots)
- Операций `pvmove` при замене дисков

**Рекомендация:** Оставляйте 10–20% VG свободным.

## Практические сценарии

### Типовая последовательность операций

```bash
# 1. Инициализация PV
pvcreate /dev/sdb1

# 2. Создание VG
vgcreate data_vg /dev/sdb1

# 3. Создание LV
lvcreate -L 10G -n data_lv data_vg

# 4. Форматирование и монтирование
mkfs.ext4 /dev/data_vg/data_lv
mount /dev/data_vg/data_lv /mnt/data
```

Подробнее: [Создание PV, VG и LV](./operations/pv_vg_creation.md)

## Дополнительная информация

### Загрузка системы и LVM

Если корневая ФС (`/`) на LVM-томе, для загрузки используется `initramfs`:
- `initramfs` содержит утилиты LVM
- Активирует VG и LV до монтирования корневой ФС
- Ядро продолжает загрузку после активации

**Важно:** `/boot` **не должен** находиться на LVM:
- GRUB должен прочитать ядро и `initramfs` до активации LVM
- Разместите `/boot` на обычном разделе (ext4/xfs)

Подробнее: [Расширенные темы](./advanced_topics.md#lvm-и-процесс-загрузки-linux)
