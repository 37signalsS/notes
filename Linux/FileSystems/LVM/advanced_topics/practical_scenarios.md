# LVM: Практические сценарии восстановления и оптимизации

## Определения

**Восстановление метаданных (Metadata Recovery)** — процесс реанимации структуры групп томов и логических томов из резервных копий конфигурации или дампов метаданных физических томов.

**Миграция Swap (Swap Migration)** — перенос области подкачки с логического тома LVM в файл или на другой носитель для упрощения управления дисковым пространством.

**Межгрупповая миграция (Cross-VG Transfer)** — процесс передачи дискового пространства между независимыми группами томов.

## Базовые концепции

### Механизмы защиты метаданных

LVM автоматически сохраняет резервные копии конфигурации VG при каждом изменении в каталоге `/etc/lvm/backup/`. Также в начале каждого PV (первый мегабайт) хранится дескриптор метаданных, который можно считать вручную при повреждении файловой системы.

### Особенности Swap в LVM

Использование LV для swap дает преимущество в производительности при высокой нагрузке (за счет отсутствия фрагментации ФС), но swap-файл на обычном разделе значительно проще расширять или переносить без изменения структуры LVM.

### Ограничения переноса между VG

В LVM нет прямой команды "перенести 10ГБ из VG1 в VG2". Перенос возможен только через физическое перемещение всего PV или через создание промежуточного LV, который инициализируется как PV для другой группы.

## Практические сценарии

### Сценарий 1: Восстановление LVM после повреждения метаданных

Используется, если PV перестал распознаваться системой как часть VG.

**Шаг 1: Поиск резервной копии конфигурации**

```bash
sudo ls /etc/lvm/backup/
# Выберите файл, соответствующий имени вашей VG (например, my_vg)
```

**Шаг 2: Получение UUID физического тома**
Если PV поврежден, UUID можно найти в тексте файла бэкапа.

```bash
sudo grep -A 10 "physical_volumes" /etc/lvm/backup/my_vg
```

**Шаг 3: Восстановление PV и дескриптора метаданных**

```bash
# Восстановление PV с сохранением старого UUID
sudo pvcreate --uuid "XYZ-123-..." --restorefile /etc/lvm/backup/my_vg /dev/sdb1
```

**Шаг 4: Восстановление структуры VG**

```bash
sudo vgcfgrestore -f /etc/lvm/backup/my_vg my_vg
sudo vgchange -ay my_vg
```

---

### Сценарий 2: Замена swap-раздела на swap-файл

Освобождение места в LVM для более гибкого использования.

**Шаг 1: Создание и подготовка файла**

```bash
# Создание файла на 4 ГБ
sudo dd if=/dev/zero of=/swapfile bs=1M count=4096 status=progress
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

**Шаг 2: Обновление конфигурации монтирования**
В `/etc/fstab` замените путь к LV на `/swapfile`.

```text
/swapfile none swap sw 0 0
```

**Шаг 3: Удаление старого тома**

```bash
sudo swapoff /dev/my_vg/lv_swap
sudo lvremove /dev/my_vg/lv_swap
```

---

### Сценарий 3: Передача пространства между VG (Обходной путь)

Сценарий: передать 10 ГБ из `vg_system` в `vg_data`.

**Шаг 1: Создание транспортного LV в источнике**

```bash
sudo lvcreate -L 10G -n lv_transfer vg_system
```

**Шаг 2: Инициализация LV как PV для другой группы**

```bash
sudo pvcreate /dev/vg_system/lv_transfer
sudo vgextend vg_data /dev/vg_system/lv_transfer
```

**Шаг 3: Использование пространства в vg_data**
Теперь вы можете расширять тома в `vg_data`, используя емкость из `vg_system`.
