# LVM: Расширенные темы

## Определения

**Расширенные темы LVM** — комплексные вопросы эксплуатации системы логических томов, включающие взаимодействие с процессом загрузки ОС, интеграцию с файловыми системами и глубокую диагностику метаданных.

**initramfs (Initial RAM Filesystem)** — временная файловая система, используемая ядром при загрузке для активации драйверов и утилит (включая LVM), необходимых для монтирования корневого раздела.

## Базовые концепции

### Взаимодействие с процессом загрузки

Для успешной загрузки системы с корнем на LVM необходимо соблюдение двух условий: наличие утилит LVM в `initramfs` и правильное размещение каталога `/boot`.

#### Загрузка и initramfs

1. **Загрузчик (GRUB)** передает управление ядру и загружает образ `initramfs`.
2. **Программы в initramfs** выполняют сканирование дисков (`pvscan`, `vgscan`) и активацию групп томов (`vgchange -ay`).
3. **Ядро** монтирует логический том как корневую файловую систему (`/`).

#### Ограничение размещения /boot

Рекомендуется выносить каталог `/boot` на отдельный стандартный раздел (не LVM).

- **Причина:** Большинство загрузчиков требуют прямой доступ к ядру и конфигам до активации стека LVM.
- **Рекомендуемая схема:**
  - `/dev/sda1` (512 МБ – 1 ГБ, ext4/XFS) — точка монтирования `/boot`.
  - `/dev/sda2` (LVM PV) — все остальные разделы (`/`, `/home`, `swap`).

### Взаимодействие с файловыми системами

LVM работает на блочном уровне, но изменения размеров должны быть синхронизированы с уровнем ФС.

#### Точность единиц измерения

LVM и утилиты ФС могут использовать разные базы для расчетов:

- **LVM:** Предпочтительно использует десятичные `GB` (10^9) или двоичные `GiB` (2^30).
- **Рекомендация:** При уменьшении тома всегда сжимайте ФС до размера на 100–200 МБ меньше целевого LV, чтобы избежать ошибок округления, после чего расширяйте ФС до границ LV.

#### Перечитывание таблицы разделов (partprobe)

Если LVM создан на базе разделов диска (`/dev/sda1`), после изменения таблицы разделов ядро может "видеть" старые границы.

```bash
# Принудительное обновление таблицы разделов в ядре
sudo partprobe /dev/sda
```

## Практические сценарии

### Сценарий 1: Диагностика и устранение неисправностей

| Проблема | Инструмент проверки | Решение |
| :--- | :--- | :--- |
| **VG не активируется** | `sudo vgscan`, `sudo vgs` | Проверить наличие всех PV через `sudo pvs`. |
| **LV не монтируется** | `sudo lvdisplay`, `dmesg` | Проверить целостность ФС: `sudo fsck -y /dev/vg/lv`. |
| **Метаданные повреждены** | `sudo pvck`, `sudo vgck` | Восстановить из бэкапа (см. [Сценарии восстановления](./practical_scenarios.md)). |

### Сценарий 2: Восстановление загрузки (Rebuild initramfs)

Если после обновления или изменения конфигурации дисков система выдает ошибку `Volume group not found`, необходимо пересобрать образ `initramfs` с включенными модулями LVM.

#### Для Debian / Ubuntu

```bash
# Добавление модуля в конфигурацию
echo "lvm2" | sudo tee -a /etc/initramfs-tools/modules

# Пересборка образа для текущего ядра
sudo update-initramfs -u -k $(uname -r)
sudo update-grub
```

#### Для RHEL / CentOS / Rocky

```bash
# Проверка наличия модуля в dracut
dracut --list-modules | grep lvm

# Принудительное включение модуля
echo 'add_dracutmodules+=" lvm "' | sudo tee /etc/dracut.conf.d/lvm.conf

# Полная пересборка
sudo dracut --force --regenerate-all
```

#### Для Arch Linux

```bash
# Проверка HOOKS в /etc/mkinitcpio.conf
# Должно быть: HOOKS=(... block lvm2 filesystems ...)

# Пересборка всех пресетов
sudo mkinitcpio -P
```
