# LVM: Дополнительная Информация

## Дополнительная информация

### LVM и процесс загрузки Linux

Если корневая файловая система (`/`) находится на LVM-томе, для загрузки системы используется `initramfs` (initial RAM file system). `initramfs` содержит утилиты LVM, которые активируют Volume Groups и Logical Volumes, после чего ядро монтирует корневую ФС и продолжает загрузку.

**Важно:** Загрузочный каталог `/boot` не должен находиться на LVM, так как загрузчик (GRUB) должен прочитать ядро и `initramfs` до активации LVM.

### LVM и файловые системы

* LVM управляет блочными устройствами, но не отменяет ограничений файловых систем.
* **Точность размеров:** Утилиты LVM и ФС могут по-разному интерпретировать `GB` (10^9) и `GiB` (2^30). Чтобы избежать ошибок при уменьшении, всегда сначала сжимайте файловую систему до размера *меньшего*, чем целевой размер LV.
* **`partprobe`:** После изменения таблицы разделов диска (например, в `fdisk` или `parted`), используйте `partprobe`, чтобы ядро перечитало ее без перезагрузки.

### Передача пространства между Volume Groups (обходной путь)

**Внимание: Этот метод не является стандартной практицией. Используйте с осторожностью.**

Прямого механизма переноса пространства между VG нет. Но можно временно "одолжить" пространство, создав LV в одной VG, отформатировав его как PV и добавив в другую VG.

**Сценарий:** Передать 500 МБ из `VG_SOURCE` в `VG_DEST`.

1. В `VG_SOURCE` создаем временный LV:

    ```bash
    lvcreate -L 500M -n temp_transport_lv VG_SOURCE
    ```

2. Инициализируем этот LV как PV:

    ```bash
    pvcreate /dev/VG_SOURCE/temp_transport_lv
    ```

3. Добавляем этот "виртуальный" PV в `VG_DEST`:

    ```bash
    vgextend VG_DEST /dev/VG_SOURCE/temp_transport_lv
    ```

4. Теперь в `VG_DEST` появилось 500 МБ свободного места, которое можно использовать для расширения ее томов.

5. **Очистка (после использования):** Проведите операции в обратном порядке (`vgreduce`, `pvremove`, `lvremove`).

### Восстановление LVM после потери метаданных

Если метаданные LVM на физическом томе (PV) были удалены или повреждены, но сам физический том остался нетронутым, их можно восстановить. Это особенно актуально, когда потеряна информация о Volume Group (VG) и Logical Volumes (LV).

**Сценарий:** Утеряны метаданные VG и LV на PV, который был единственным в VG (например, `pvremove` и `vgremove`).

1. **Создайте дамп метаданных физического тома (PV):** Метаданные LVM хранятся в начале физического тома (обычно в первом мегабайте). Необходимо сделать дамп этой части диска.

    ```bash
    dd if=/dev/vdb of=pv_metadata_backup.img bs=1M count=1
    ```

    > **Примечание:** `/dev/vdb` - это пример блочного устройства, которое было Physical Volume. Замените на ваше устройство.

2. **Очистите файл дампа от нерелевантной информации:** Файл дампа `pv_metadata_backup.img` будет содержать не только текстовые метаданные LVM, но и бинарные данные. Необходимо удалить бинарный "мусор" и оставить только секции, относящиеся к LVM (например, начинающиеся с `pv`, `vg`, `lv`). Это можно сделать вручную в текстовом редакторе.

    ```bash
    # Откройте файл для редактирования (пример с `vi`)
    vi pv_metadata_backup.img
    ```

    > **Задача:** Удалить все нетекстовые и не относящиеся к LVM данные. В частности, в начале файла будут нечитаемые символы. Найдите начало секции LVM (например, `pv_name = "..."`, `vg_name = "..."`) и удалите все до неё. Убедитесь, что сохранены секции `pv`, `vg` и `lv`.

3. **Восстановите физический том (PV):** Используйте очищенный файл дампа для восстановления PV, указав его UUID. UUID можно найти в очищенном файле (строка `uuid = "..."`).

    ```bash
    pvcreate --uuid "<UUID_из_файла>" --restorefile pv_metadata_backup.img /dev/vdb
    ```

    > **Пример:** `pvcreate --uuid "XYZabc-1234-..." --restorefile pv_metadata_backup.img /dev/vdb`

4. **Восстановите группу томов (VG):** Используйте очищенный файл дампа для восстановления конфигурации VG. Имя VG также можно найти в файле (строка `vg_name = "..."`).

    ```bash
    vgcfgrestore -f pv_metadata_backup.img <имя_VG>
    ```

    > **Пример:** `vgcfgrestore -f pv_metadata_backup.img my_vg`

5. **Активируйте группу томов:**

    ```bash
    vgchange -ay <имя_VG>
    ```

6. **Проверьте наличие логических томов (LV) и монтирование:**

    ```bash
    lvs
    mount /dev/<имя_VG>/<имя_LV> /mnt/data
    ```

    Если все шаги выполнены корректно, логические тома и данные на них станут доступны.
