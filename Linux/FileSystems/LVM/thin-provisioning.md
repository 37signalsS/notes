# LVM — Тонкое провизионирование (Thin Provisioning)

---

## Определения

| Термин | Описание |
| :--- | :--- |
| **Thin Provisioning (Тонкое выделение)** | Метод создания логических томов (LV) с виртуальным размером, превышающим доступное физическое пространство. Место выделяется динамически по мере записи данных. |
| **Thin Pool (Тонкий пул)** | Специальный LV-контейнер, объединяющий реальное дисковое пространство для обслуживания тонких томов. |
| **Thin Volume (Тонкий том)** | Логический том с виртуальным размером внутри тонкого пула. При создании не занимает физического места. |
| **Thin Snapshot (Тонкий снимок)** | Снимок тонкого тома, не требующий предварительного выделения размера. Использует пространство пула только для измененных блоков. |

---

## Базовые концепции

### Отличия от традиционных томов

| Характеристика | Традиционный LV | Thin Volume |
| :--- | :--- | :--- |
| Размер при создании | Фиксированный | Виртуальный (может превышать физический) |
| Выделение места | Сразу при создании | По требованию (при записи данных) |
| Overcommit | Невозможен | Возможен (виртуальный > физический) |
| Зависимость | Независимый | Требует Thin Pool |

### Архитектура

```
Volume Group (VG)
    └── Thin Pool (реальное пространство, например 100 ГБ)
        ├── Thin Volume 1 (виртуальный размер 1 ТБ)
        ├── Thin Volume 2 (виртуальный размер 500 ГБ)
        └── Thin Volume 3 (виртуальный размер 2 ТБ)

Итого виртуально: 3.5 ТБ
Физически в пуле: 100 ГБ
Коэффициент overcommit: 35×
```

### Преимущества

- **Эффективность:** физическое место не резервируется заранее и не простаивает.
- **Overcommit:** возможность выделить приложениям больше места, чем доступно физически, в расчете на постепенный рост.
- **Упрощение планирования:** не требуется точный прогноз потребностей на этапе создания тома.
- **Быстрые снимки:** тонкие снимки создаются мгновенно и более эффективно расходуют место.

### Риски и митигация

| Риск | Описание | Митигация |
| :--- | :--- | :--- |
| **Переполнение пула** | При заполнении 100% пула запись прекращается на всех томах. | Мониторинг, алерты, авто-расширение пула. |
| **Переполнение метаданных** | Метаданные пула заполняются независимо от данных. | Контроль `Meta%`, расширение метаданных. |
| **Снижение производительности** | Возможны задержки при интенсивной записи (аллокация блоков). | Использование SSD для пула, мониторинг задержек. |
| **Неожиданное потребление** | Один том может внезапно занять весь пул. | Квоты на уровне файловых систем, мониторинг. |

## Практические сценарии

### Создание тонкого пула

Для создания тонкого пула необходимо указать размер реального дискового пространства в группе томов (VG).

```bash
# Создать пул my_thin_pool размером 100 ГБ в группе томов my_vg
lvcreate -L 100G --thinpool my_thin_pool my_vg
```

### Создание тонкого тома

Тонкий том создается внутри существующего пула. Указывается виртуальный размер (может быть очень большим).

```bash
# Создать том с виртуальным размером 1 ТБ
lvcreate -V 1T --thin -n my_thin_lv my_vg/my_thin_pool
```

### Мониторинг состояния

Критически важно следить за заполнением данных и метаданных. При достижении 100% запись на все тома пула будет заблокирована.

```bash
# Просмотр состояния пула и томов
lvs -o+thin_pool,thin_count,data_percent,metadata_percent

# Пример вывода:
#   LV            VG    Attr       LSize   Data%  Meta%
#   my_thin_pool  my_vg twi-a-t--- 100.00g 45.23   12.50
#   my_thin_lv    my_vg Vwi-a-t---   1.00t  10.00
```

| Параметр | Описание | Warning | Critical |
| :--- | :--- | :--- | :--- |
| **Data%** | Заполнение пула данными | > 70% | > 85% |
| **Meta%** | Заполнение метаданных | > 60% | > 75% |

### Расширение ресурсов

Если пул или метаданные близки к заполнению, их можно расширить на лету (при наличии свободного места в VG).

```bash
# Расширить пул на 50 ГБ
lvextend -L +50G my_vg/my_thin_pool

# Расширить метаданные пула
lvextend --poolmetadatasize +1G my_vg/my_thin_pool
```

### Автоматическое расширение

LVM поддерживает автоматическое расширение пула при достижении пороговых значений через сервис `dmeventd`.

Настройка в `/etc/lvm/lvm.conf`:

```ini
activation {
    # Расширять при заполнении на 80%
    thin_pool_autoextend_threshold = 80
    # Расширять на 20% от текущего размера
    thin_pool_autoextend_percent = 20
}
```

### Тонкие снимки (Thin Snapshots)

Тонкие снимки не требуют указания размера, так как используют пространство пула.

```bash
# Создать снимок тонкого тома
lvcreate -s -n my_snapshot my_vg/my_thin_lv
```

Подробнее о механизме снимков: **[LVM — снимки](./snapshots.md)**.

### Диагностика и устранение неисправностей

| Проблема | Команда проверки | Решение |
| :--- | :--- | :--- |
| Пул переполнен (Data% = 100) | `lvs` | Расширить пул (`lvextend`) или удалить лишние данные/снимки. |
| Ошибка записи на диск | `dmesg`, `journalctl` | Проверить заполнение метаданных и пула. |
| Низкая производительность | `iostat` | Проверить фрагментацию пула и тип носителя. |

## Дополнительная информация

### Рекомендации по эксплуатации

1. **Планирование Overcommit:**
   - Для стабильных систем рекомендуется коэффициент не более 2–3×.
   - В тестовых средах допустимо 5–10× при строгом мониторинге.
2. **Резерв в Volume Group:** всегда оставляйте 20–30% свободного места в VG для возможности расширения тонкого пула в экстренных ситуациях.
3. **Метаданные:** не экономьте на размере метаданных при создании пула. Если томов и снимков планируется много, выделите сразу 1–2 ГБ.

### Справочник основных команд

```bash
# Создание пула и тома
lvcreate -L 100G --thinpool <pool_name> <vg_name>
lvcreate -V 1T --thin -n <lv_name> <vg_name>/<pool_name>

# Мониторинг
lvs -o+data_percent,metadata_percent

# Расширение
lvextend -L +size <vg_name>/<pool_name>
lvextend --poolmetadatasize +size <vg_name>/<pool_name>
```
