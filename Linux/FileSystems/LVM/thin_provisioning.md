# LVM: Тонкие тома (Thin Provisioning)

---

## Определения

| Термин | Описание |
| :--- | :--- |
| **Тонкое провизионирование (Thin Provisioning)** | Метод создания LV с "виртуальным" размером, превышающим доступное физическое пространство. Место выделяется динамически по мере записи. |
| **Тонкий пул (Thin Pool)** | Специальный LV-контейнер с реальным дисковым пространством. |
| **Тонкий том (Thin Volume)** | LV с виртуальным размером внутри пула. При создании не занимает места. |

---

## Основные концепции

### Отличия от традиционных томов

| Характеристика | Традиционный LV | Тонкий том |
| :--- | :--- | :--- |
| Размер при создании | Фиксированный | Виртуальный (может превышать физический) |
| Выделение места | Сразу при создании | По требованию (при записи данных) |
| Переподписка (overcommit) | Невозможна | Возможна (виртуальный > физический) |
| Зависимость | Независимый | Требует тонкий пул |

### Архитектура

```
Volume Group (VG)
    └── Thin Pool (реальное пространство, например 100 ГБ)
        ├── Thin Volume 1 (виртуальный размер 1 ТБ)
        ├── Thin Volume 2 (виртуальный размер 500 ГБ)
        └── Thin Volume 3 (виртуальный размер 2 ТБ)
        
Итого виртуально: 3.5 ТБ
Физически в пуле: 100 ГБ
Коэффициент переподписки: 35×
```

## Преимущества и недостатки

### Преимущества

| Преимущество | Описание |
| :--- | :--- |
| **Эффективность** | Место не резервируется заранее |
| **Переподписка** | Возможность выделить больше, чем есть физически |
| **Упрощение планирования** | Не нужно точно прогнозировать потребности |
| **Быстрое создание** | Тонкие тома создаются мгновенно |

### Недостатки и риски

| Риск | Описание | Митигация |
| :--- | :--- | :--- |
| **Переполнение пула** | Запись прекращается на всех томах | Мониторинг, алерты, авто-расширение |
| **Сложность мониторинга** | Нужно следить за пулом и томами | Автоматизация, дашборды |
| **Снижение производительности** | При интенсивной записи | SSD для пула, мониторинг IOPS |
| **Неожиданное потребление** | Тома заполняются быстрее плана | Квоты, лимиты, алерты |

## Практический сценарий: Создание и управление

### Создание тонкого пула

```bash
# Создать пул my_thin_pool размером 100 ГБ
lvcreate -L 100G --thinpool my_thin_pool my_vg
```

**Важные параметры:**

- `--thinpool` — имя создаваемого пула
- Пул занимает реальное место в VG

### Создание тонкого тома

```bash
# Создать том с виртуальным размером 1 ТБ
lvcreate -V 1T --thin -n my_thin_lv my_vg/my_thin_pool
```

**Важные параметры:**

- `-V` (или `--virtualsize`) — виртуальный размер тома
- `--thin` — указание создать тонкий том
- Том не занимает место до первой записи

### Мониторинг

**Критически важно следить за заполнением пула!** При переполнении запись прекращается на всех тонких томах.

```bash
# Просмотр состояния пула и томов
lvs -o+thin_pool,thin_count,thin_provisioned,data_percent,metadata_percent

# Пример вывода:
#   LV            VG    Attr       LSize   Data%  Meta%
#   my_thin_pool  my_vg twi-a-t--- 100.00g 45.23   12.50
#   my_thin_lv    my_vg Vwi-a-t---   1.00t  10.00
```

| Параметр | Описание | Критический порог |
| :--- | :--- | :--- |
| `Data%` | Заполнение данными | > 80% |
| `Meta%` | Заполнение метаданных | > 75% |

### Расширение пула

```bash
# Расширить пул на 50 ГБ
lvextend -L +50G my_vg/my_thin_pool

# Расширить пул на всё свободное место в VG
lvextend -l 100%FREE my_vg/my_thin_pool
```

### Расширение метаданных пула

Метаданные пула могут переполниться независимо от данных:

```bash
# Проверить размер метаданных
lvs -o+lv_attr,chunk_size my_vg/my_thin_pool

# Расширить метаданные (если Meta% > 75%)
lvextend --poolmetadatasize +1G my_vg/my_thin_pool
```

## Автоматическое расширение

LVM поддерживает автоматическое расширение пула через `dmeventd`:

### Настройка dmeventd

```bash
# Включить мониторинг для пула
lvchange --monitor y my_vg/my_thin_pool

# Проверить статус мониторинга
lvs -o+lv_attr my_vg/my_thin_pool
# Атрибут 'm' указывает на активный мониторинг
```

### Конфигурация автоматического расширения

Файл `/etc/lvm/lvm.conf`:

```ini
activation {
    thin_pool_autoextend_threshold = 80  # Расширять при 80% заполнении
    thin_pool_autoextend_percent = 20    # Расширять на 20%
}
```

**Параметры:**

- `thin_pool_autoextend_threshold` — порог срабатывания (%)
- `thin_pool_autoextend_percent` — на сколько расширять (%)

> **Важно:** Автоматическое расширение требует свободного места в VG!

## Тонкие снимки (Thin Snapshots)

Тонкие пулы поддерживают снимки без предварительного выделения размера:

```bash
# Создать тонкий снимок
lvcreate -s -n my_snapshot my_vg/my_thin_lv

# Проверить
lvs -o+lv_role my_vg
```

**Преимущества перед обычными снимками:**

- Не требует указания размера
- Использует пространство пула динамически
- Можно создавать множественные снимки

**Недостатки:**

- Зависит от свободного места в пуле
- Требует мониторинга пула

Подробнее: [snapshots.md](./snapshots.md#тонкие-снимки-thin-snapshots)

## Диагностика и troubleshooting

### Частые проблемы

| Проблема | Команда проверки | Решение |
| :--- | :--- | :--- |
| Пул переполнен (Data% = 100%) | `lvs -o+data_percent` | Расширить пул (`lvextend`) |
| Метаданные переполнены | `lvs -o+metadata_percent` | Расширить метаданные |
| Том не записывает данные | `dmesg`, `journalctl` | Проверить заполнение пула |
| Невозможно создать том | `vgs`, `lvs` | Проверить место в VG и пуле |

### Команды управления

```bash
# Создание пула
lvcreate -L 100G --thinpool my_pool my_vg

# Создание тонкого тома
lvcreate -V 1T --thin -n my_lv my_vg/my_pool

# Мониторинг
lvs -o+thin_pool,data_percent,metadata_percent

# Расширение пула
lvextend -L +50G my_vg/my_pool

# Расширение метаданных
lvextend --poolmetadatasize +1G my_vg/my_pool

# Включение мониторинга
lvchange --monitor y my_vg/my_pool
```

## Рекомендации по эксплуатации

### Планирование ёмкости

1. **Определите коэффициент переподписки:**
   - Для тестовых сред: 5–10×
   - Для production: 2–5×
   - Критичные системы: без переподписки

2. **Оставьте резерв в VG:**
   - Минимум 20% для расширения пула
   - Учитывайте рост данных

3. **Выберите размер пула:**
   - Исходя из ожидаемого потребления на 6–12 месяцев
   - Учитывайте сезонность

### Мониторинг

**Обязательные метрики:**

- `Data%` — заполнение данными
- `Metadata%` — заполнение метаданных
- IOPS и задержки пула

**Алерты:**

- Warning: Data% > 70%
- Critical: Data% > 85%
- Critical: Metadata% > 75%

### Производительность

**Рекомендации:**

- Размещайте пул на SSD для рабочих нагрузок
- Избегайте переподписки > 5× для production
- Мониторьте IOPS и задержки
