# Ссылки, Inode и Dentry

## Определения

### Жёсткая ссылка

Жёсткая ссылка — второе имя для тех же данных на диске. Напрямую указывает на тот же индексный дескриптор (Inode), что и оригинальный файл. Имя файла в Unix-подобных операционных системах (Operating System (OS)) — это запись в каталоге, сопоставляющая текстовое имя с номером Inode.

* **Синтаксис:**

    ```bash
    ln [TARGET_FILE] [LINK_NAME]
    ```

  * `TARGET_FILE` — существующий файл.
  * `LINK_NAME` — новое имя для этого файла.

### Символическая ссылка

Символическая ссылка (Symlink) — специальный файл-указатель, содержащий текстовый путь к другому объекту. Имеет собственный уникальный Inode. При обращении операционная система (Operating System (OS)) считывает путь из ссылки и перенаправляет запрос к целевому файлу.

* **Синтаксис:**

    ```bash
    ln -s [TARGET] [LINK_NAME]
    ```

  * `-s` — создание символической ссылки.
  * `-f` (`--force`) — принудительная замена существующей ссылки или файла.

### Индексный дескриптор (Inode)

**Inode (index node)** — фундаментальная структура данных в файловых системах (ФС), хранящая метаинформацию о файле или каталоге (права, владелец, размер, временные метки), за исключением его имени. Каждый объект имеет уникальный номер Inode в пределах своего раздела.

**Размер и структура в ext4:** в файловой системе ext4 один Inode занимает 256 байт. В них хранятся: владелец, группа, права доступа, размер, временные метки с точностью до наносекунд (`atime`, `mtime`, `ctime`), счётчик жёстких ссылок и указатели на блоки данных.

### Запись каталога (Dentry)

**Dentry (directory entry)** — структура в памяти ядра, связывающая имя файла с его Inode. Используется виртуальной файловой системой (Virtual File System (VFS)) для кэширования путей и ускорения доступа. Подробнее об управлении такими структурами см. в статье о [Slab Allocator](../Core/memory/slab_allocator.md).

### Структура каталога

Каталог — это специальный файл, содержащий таблицу записей вида **"имя -> номер Inode"**. Когда пользователь обращается к файлу по имени, ядро находит соответствующую строку в каталоге, извлекает номер Inode и получает доступ к метаданным и блокам данных.

## Основные концепции

### Особенности жёстких ссылок

* **Равноправие:** все жёсткие ссылки на один Inode абсолютно идентичны. Понятия "оригинал" не существует, пока жива хотя бы одна ссылка.
* **Счётчик ссылок:** поле `i_nlink` в Inode хранит количество имён, указывающих на него. Команда `rm` (системный вызов `unlink()`) удаляет запись из каталога и уменьшает этот счётчик.
* **Удаление данных:** данные физически удаляются с диска, только если счётчик ссылок стал равен нулю **и** ни один процесс не держит файл открытым. См. [устранение нехватки места на диске](./disk_space_troubleshooting.md).
* **Ограничения:**
  * Нельзя создавать для директорий (для предотвращения зацикливания, исключение — `.` и `..`).
  * Работают только в пределах одного раздела (одной ФС).

### Особенности символических ссылок

* **Гибкость:** могут указывать на директории и объекты в других файловых системах.
* **Механизм:** Symlink содержит строку с путём. Если путь короткий (до ~60 байт), он хранится прямо в Inode (**fast symlink**).
* **Разрешение путей:** ядро проходит по цепочке ссылок (лимит — 40 переходов). Если целевой файл удалён, ссылка становится "битой" (dangling).
* **Права:** права самой ссылки обычно игнорируются; доступ определяется правами целевого файла.

### Метаданные в Inode

* **Тип и права доступа (Mode):** обычный файл, каталог, ссылка, права `rwx`.
* **Владелец (UID) и Группа (GID):** идентификаторы пользователя (User ID (UID)) и группы (Group ID (GID)).
* **Размер:** в байтах.
* **Временные метки:**
  * `atime`: время последнего доступа (access time).
  * `mtime`: время последней модификации содержимого (modification time).
  * `ctime`: время изменения метаданных или статуса Inode (change time).
* **Счётчик жёстких ссылок:** сколько имён ссылается на этот Inode.
* **Указатели на блоки данных:** информация о физическом расположении данных на накопителе.

### Особенности и ограничения Inode

* **Статическое выделение (ext4):** количество Inode фиксируется при создании файловой системы. Большое количество мелких файлов может привести к исчерпанию Inode раньше, чем закончится дисковое пространство. Диагностика: `df -i`. Подробнее: [Диагностика файловых систем](../Diagnostics/Filesystem/filesystem_and_disk_space_diagnostics.md).
* **Динамическое выделение (XFS, Btrfs):** Inode создаются по мере необходимости, что исключает проблему их преждевременного исчерпания.

### Права на удаление и родительский каталог

Удаление файла — это модификация **родительского каталога** (удаление записи из таблицы). Поэтому для удаления файла требуются права на запись (`w`) и выполнение (`x`) в родительской директории, а не права на сам файл.

### Удаление файла как операция над каталогом

Архитектура Unix разделяет имя и данные. Процесс `rm`:

1. Находит номер Inode по имени в каталоге.
2. Уменьшает счётчик ссылок в Inode.
3. Удаляет запись "имя -> Inode" из каталога.
4. Если ссылок больше нет, помечает Inode и блоки данных как свободные.

| Особенности | Причина / Следствие |
| :--- | :--- |
| **Переименование** | Быстрое в пределах одной ФС (меняется только запись в каталоге) |
| **Открытые файлы** | Данные не удалятся, пока процесс удерживает файловый дескриптор (File Descriptor (FD)) |

## Практические сценарии

### Применение ссылок

* **Инкрементальные бэкапы:** `rsync --link-dest` использует жёсткие ссылки на неизменённые файлы для экономии места.
* **Управление версиями:** символическая ссылка `/usr/bin/python` может указывать на конкретную версию (например, `python3.11`).
* **Конфигурации:** использование `sites-enabled` в Nginx, где файлы в каталоге являются ссылками на реальные конфиги в `sites-available`.

### Сравнение команд mv и cp: роль Inode

* **`cp` (копирование):** создаёт новый Inode и полностью копирует блоки данных.
* **`mv` (перемещение):**
  * В пределах одной ФС: просто меняет запись в каталоге. Inode и данные остаются прежними. Операция выполняется мгновенно.
  * Между разными ФС: работает как `cp` с последующим `rm` оригинала.

## Дополнительная информация

### Защита от небезопасных ссылок

Ядро предоставляет параметры `fs.protected_symlinks` и `fs.protected_hardlinks` для защиты от атак в общедоступных каталогах (например, `/tmp`). Подробнее: [Защита ссылок](../Security/Fstec/kernel_runtime_protection.md#защита-от-небезопасных-ссылок-symlinks-и-hardlinks).

### Последствия удаления ссылок

* **Удаление жёсткой ссылки:** уменьшает счётчик `i_nlink`. Файл остаётся доступен под другими именами.
* **Удаление символической ссылки:** удаляется только файл-указатель. Оригинал не затрагивается.
* **Удаление цели:** делает символическую ссылку нерабочей, но не влияет на жёсткие ссылки.
