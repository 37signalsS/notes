# Мониторинг событий ФС (inotify)

### Определения

**`inotify`** — это подсистема ядра Linux, предоставляющая API для отслеживания событий файловой системы в реальном времени, таких как создание, удаление, изменение и перемещение файлов и директорий.

### Основные концепции

Для работы с `inotify` из командной строки используется пакет **`inotify-tools`**, который включает две основные утилиты:

-   **`inotifywait`**: Блокирующая утилита, которая ожидает указанного события и завершает работу. Идеальна для использования в скриптах.
-   **`inotifywatch`**: Собирает и выводит статистику о событиях файловой системы за определённый период.

### Практические сценарии

#### Ожидание одного события в скрипте

`inotifywait` можно использовать для запуска действий после изменения в директории.
```bash
# Ожидать любого события в директории /tmp, затем завершить работу
inotifywait /tmp
echo "Событие в /tmp зафиксировано."
```

#### Непрерывный мониторинг директории

Ключ `-m` (`--monitor`) заставляет `inotifywait` работать непрерывно, а `-r` (`--recursive`) включает рекурсивное отслеживание вложенных директорий.
```bash
# Мониторить директорию /var/www и все её поддиректории в реальном времени
inotifywait -m -r /var/www
```

### Дополнительная информация

#### Управление лимитами `inotify`

Для предотвращения исчерпания ресурсов ядро ограничивает количество "наблюдателей" (`watches`), которое может создать один пользователь. Приложения, активно использующие `inotify` (например, VS Code, файловые синхронизаторы), могут столкнуться с ошибкой при достижении этого лимита.

**1. Просмотр текущего лимита:**
```bash
sysctl fs.inotify.max_user_watches
```

**2. Временное изменение лимита (до перезагрузки):**
```bash
sudo sysctl -w fs.inotify.max_user_watches=524288
```

**3. Постоянное изменение лимита:**

Добавьте следующую строку в файл `/etc/sysctl.conf` и выполните `sudo sysctl -p`:
```ini
fs.inotify.max_user_watches=524288
```
