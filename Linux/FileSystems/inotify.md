# Мониторинг событий файловой системы — inotify

## Определения

- **inotify (inode notify):** Подсистема ядра Linux, предоставляющая программный интерфейс (API) для отслеживания событий файловой системы в реальном времени. Позволяет приложениям подписываться на уведомления об изменениях в конкретных файлах или директориях.
- **fanotify:** Более современный интерфейс мониторинга ФС, предназначенный для сканеров вирусов и систем иерархического хранения (HSM). В отличие от inotify, поддерживает перехват событий для всей точки монтирования и позволяет блокировать операции до подтверждения (permission events).
- **Событие (Event):** Дискретное действие над объектом ФС (открытие, чтение, запись, удаление, перемещение).

## Основные концепции

### Механизм работы

inotify работает на уровне VFS (Virtual File System). Приложение создает экземпляр inotify и добавляет в него «дескрипторы наблюдения» (**watch descriptors**) для интересующих объектов.

### Системные лимиты (sysctl)

Для предотвращения исчерпания ресурсов ядро накладывает три ключевых ограничения на пользователя:

| Параметр | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| **`fs.inotify.max_user_watches`** | Максимальное количество директорий/файлов, которые может отслеживать один пользователь. | ~8192–65536 |
| **`fs.inotify.max_user_instances`** | Максимальное количество очередей inotify, которые может создать один пользователь. | 128 |
| **`fs.inotify.max_queued_events`** | Максимальное количество событий в одной очереди. Если события приходят быстрее, чем приложение их читает, очередь переполняется. | 16384 |

**Просмотр и изменение:**

```bash
# Текущие значения
sysctl fs.inotify

# Временное увеличение (для высоконагруженных сред разработки или IDE)
sudo sysctl -w fs.inotify.max_user_watches=524288

# Постоянное применение в /etc/sysctl.d/99-inotify.conf
# fs.inotify.max_user_watches=524288
```

### Сравнение: inotify vs fanotify

| Критерий | inotify | fanotify |
| :--- | :--- | :--- |
| **Область действия** | Конкретные файлы/папки. | Вся точка монтирования / вся ФС. |
| **Рекурсия** | Требует явного добавления каждой подпапки. | Поддерживается нативно для всей ФС. |
| **Права (Permission)** | Только уведомление (постфактум). | Поддержка блокирующих запросов (Allow/Deny). |
| **Сложность** | Простой, доступен без root. | Сложный, требует привилегий `CAP_SYS_ADMIN`. |

## Инструментарий

Пакет **inotify-tools** предоставляет CLI-интерфейс к API:

- **`inotifywait`:** Ожидает наступления событий. Идеально подходит для скриптов.
- **`inotifywatch`:** Собирает статистику обращений к файлам за период времени.

## Практические сценарии

### 1. Автоматическая очистка кэша при изменении конфига

```bash
#!/bin/bash
# Скрипт отслеживает сохранение файла и перезапускает сервис
TARGET="/etc/nginx/nginx.conf"

while true; do
    # -e close_write: событие закрытия файла после записи
    inotifywait -e close_write "$TARGET"
    nginx -t && systemctl reload nginx
done
```

### 2. Рекурсивный мониторинг директории с логами

Для обработки событий в конвейере (pipeline) используйте флаг `--monitor` (`-m`).

```bash
# Отслеживание новых файлов в /var/log/app рекурсивно
inotifywait -m -r -e create --format '%w%f' /var/log/app | while read NEW_FILE
do
    echo "Обнаружен новый лог-файл: $NEW_FILE"
    # Здесь может быть команда для загрузки файла в S3 или архивации
done
```

### 3. Форматированный аудит активности

```bash
# Вывод: [Время] [Событие] [Путь]
inotifywait -m -r --timefmt '%H:%M:%S' --format '[%T] %e %w%f' /home/user/data
```

## Устранение неполадок

- **Ошибка `No space left on device`:** Несмотря на название, это часто означает, что исчерпан лимит `max_user_watches`.
- **Пропущенные события:** Если события происходят слишком часто, увеличьте `max_queued_events`.
- **Событие `IN_IGNORED`:** Возникает, когда файл удален или ФС размонтирована. inotify автоматически удаляет такой watch descriptor.
