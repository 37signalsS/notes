# FUSE (Filesystem in Userspace)

## Определения

- **FUSE (Filesystem in Userspace):** Программный интерфейс и фреймворк ядра Linux, позволяющий реализовывать полноценные файловые системы в пространстве пользователя (userspace). Это исключает необходимость написания кода на уровне ядра, что повышает безопасность и скорость разработки.
- **libfuse / fuse3:** Библиотеки (C/C++), реализующие протокол взаимодействия с модулем ядра. `fuse3` — текущий стандарт, поддерживающий многопоточность и расширенные возможности ядра Linux 4.x–6.x.
- **Демон ФС (Userspace Daemon):** Процесс, содержащий логику ФС. Он обрабатывает системные вызовы (open, read, write), перенаправленные ядром.
- **FUSE Passthrough:** (Ядро 6.9+) Механизм, позволяющий ядру напрямую обращаться к физическому файлу (backing file) после его открытия демоном, минуя пересылку данных через userspace.

## Основные концепции

### Архитектура и путь запроса

FUSE выступает мостом между виртуальной файловой системой (VFS) и пользовательским процессом.

```text
+---------------------------------------------------+
|   Приложение (ls, cp, cat)                        |
+---------------------------------------------------+
|               Ядро (VFS)                          |
+-------------------+-------------------------------+
                    | (Запрос VFS)
                    v
+-------------------+-------------------------------+
|               Модуль ядра FUSE                    |
+-------------------+-------------------------------+
                    | (Передача через /dev/fuse)
                    v
+-------------------+-------------------------------+
|   Демон ФС (SSHFS, Rclone, gocryptfs)             |
+---------------------------------------------------+
```

1.  Приложение выполняет системный вызов (например, `read()`).
2.  VFS передает запрос модулю ядра `fuse.ko`.
3.  Ядро ставит запрос в очередь и передает его демону через дескриптор `/dev/fuse`.
4.  Демон обрабатывает запрос и возвращает результат обратно в `/dev/fuse`.
5.  Ядро завершает системный вызов для приложения.

### Преимущества и недостатки

**Преимущества:**
- **Изоляция:** Сбой демона не приводит к Kernel Panic.
- **Гибкость:** Поддержка любых языков (C, Go, Rust, Python) и источников данных (S3, API, БД, архивы).
- **User-friendly:** Монтирование без прав root (с помощью `fusermount3`).

**Недостатки:**
- **Overhead:** Двойное переключение контекста и копирование данных между ядром и пользователем.
- **Зависимость:** Смерть процесса-демона приводит к зависанию точки монтирования (состояние `D` или ошибки `Transport endpoint is not connected`).

## Конфигурация и тюнинг производительности

### Файл /etc/fuse.conf

- **`user_allow_other`:** Разрешает пользователям использовать опцию монтирования `allow_other`. Без неё ФС видна только владельцу процесса монтирования.

### Опции монтирования для оптимизации

| Опция | Описание | Когда использовать |
| :--- | :--- | :--- |
| **`direct_io`** | Обход кэша страниц ядра. | Сильно динамические данные, экономия ОЗУ. Несовместимо с `mmap`. |
| **`kernel_cache`** | Использовать кэш страниц ядра для чтения. | Высокая скорость повторного чтения. Риск неактуальных данных. |
| **`writeback_cache`** | Буферизация записи в ядре. | Резкое повышение скорости последовательной записи. |
| **`max_readahead`** | Размер упреждающего чтения. | Оптимизация чтения больших файлов (стандарт 128K). |
| **`readdirplus`** | Запрос атрибутов файлов при листинге. | Ускорение `ls -l` на удаленных ФС (NFS, S3). |

## Практические сценарии

### 1. Облачные и удаленные хранилища (Rclone)

Rclone вытеснил SSHFS и специализированные драйверы (s3fs).

```bash
# Монтирование S3 с кэшированием записи и чтением
rclone mount remote_s3:bucket /mnt/s3 \
    --vfs-cache-mode full \
    --vfs-cache-max-age 24h \
    --allow-other
```

### 2. Контейнеризация (fuse-overlayfs)

Критический компонент для **Rootless Podman**.
- Обычный `overlay` в ядре требует прав root.
- `fuse-overlayfs` позволяет пользователю объединять слои образов без привилегий.

### 3. Шифрование «на лету» (Gocryptfs)

Современная альтернатива EncFS, исправляющая проблемы безопасности.
```bash
# Инициализация и монтирование
gocryptfs -init /data/cipher
gocryptfs /data/cipher /mnt/plain
```

### 4. Поддержка NTFS (ntfs-3g)

Хотя в ядре 5.15+ есть нативный драйвер `ntfs3` от Paragon, `ntfs-3g` (FUSE) остается самым стабильным и переносимым способом работы с разделами Windows.

## Диагностика и решение проблем

### Типичные ошибки
- **`Transport endpoint is not connected`:** Демон ФС упал или был убит.
  *   *Решение:* Принудительное размонтирование: `fusermount3 -uz /mnt/path`.
- **Зависание `ls` (D-state):** Демон завис или ждет ответа от сети.
  *   *Решение:* Использование опции `-o reconnect` (для sshfs/rclone) или увеличение таймаутов.

### Поиск проблем (Deadlocks)
FUSE чувствителен к нехватке памяти (Memory Pressure). Если ядро пытается сбросить страницы FUSE для освобождения памяти, а демону FUSE нужна память для обработки этого сброса — возникает deadlock.
- **Избегайте** использования FUSE для разделов подкачки (swap) или критических системных путей.
