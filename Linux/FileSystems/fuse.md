# FUSE (Filesystem in Userspace)

## Определения

- **FUSE (Filesystem in Userspace):** Программный интерфейс и фреймворк ядра Linux, позволяющий реализовывать полноценные файловые системы в пространстве пользователя (userspace). Это исключает необходимость написания кода на уровне ядра, что повышает безопасность и скорость разработки. FUSE был создан для решения проблемы нехватки универсальных драйверов ФС в ядре и для упрощения создания специализированных ФС под конкретные задачи.
- **libfuse / fuse3:** Библиотеки (C/C++), реализующие протокол взаимодействия с модулем ядра. `fuse3` (libfuse 3.x) — текущий стандарт, поддерживающий многопоточность, неблокирующий ввод-вывод и расширенные возможности ядра Linux 4.x–6.x. `libfuse2` (fuse 2.9.x) устарел и не получает исправлений безопасности с 2022 года.
- **Демон ФС (Userspace Daemon):** Процесс, содержащий логику ФС. Он обрабатывает системные вызовы (open, read, write, flush, release), перенаправленные ядром. Демон работает от имени обычного пользователя или через setuid-root (если требуется монтирование в системные каталоги).
- **FUSE Passthrough:** (Ядро 6.9+) Механизм, позволяющий ядру напрямую обращаться к физическому файлу (backing file) после его открытия демоном, минуя пересылку данных через userspace. Это снижает латентность для последовательного чтения на 30–50% за счет устранения копирования данных между пространствами.
- **fusermount3 / fusermount:** Утилита для монтирования FUSE-ФС от имени пользователя без прав root. `fusermount3` — интерфейс к FUSE 3.x. Поддерживает опцию `-o allow_other` при включенном `user_allow_other` в `/etc/fuse.conf`.
- **mount.fuse3:** Вспомогательная утилита для монтирования через `/bin/mount`. Используется, когда требуется стандартный синтаксис `mount -t fuse.<тип> ...`.

## Основные концепции

### Архитектура и путь запроса

FUSE выступает мостом между виртуальной файловой системой (VFS) и пользовательским процессом. Запрос проходит через несколько слоев абстракции, что добавляет накладные расходы, но обеспечивает безопасность и гибкость.

```text
+---------------------------------------------------+
|   Приложение (ls, cp, cat, systemd)               |
+---------------------------------------------------+
|               Ядро (VFS)                          |
+-------------------+-------------------------------+
                     | (Запрос VFS)
                     v
+-------------------+-------------------------------+
|               Модуль ядра FUSE                    |
|              (fuse.ko)                            |
+-------------------+-------------------------------+
                     | (Передача через /dev/fuse)
                     |      и设备映射 (char device)
                     v
+-------------------+-------------------------------+
|   Демон ФС (SSHFS, gocryptfs, fuse-overlayfs)     |
|   Процесс userspace, pid=N, UID/GID владельца     |
+---------------------------------------------------+
```

1.  Приложение выполняет системный вызов (например, `read()`).
2.  VFS определяет точку монтирования и передает запрос модулю ядра `fuse.ko`.
3.  Ядро ставит запрос в очередь (request queue) и передает его демону через дескриптор `/dev/fuse`.
4.  Демон обрабатывает запрос (выполняет сетевой вызов, читает encrypted данные, собирает слой overlay) и возвращает результат обратно в `/dev/fuse`.
5.  Ядро завершает системный вызов для приложения.

**Почему двойное копирование:** Ядро работает в защищенном режиме (ring 0), а демон — в пользовательском режиме (ring 3). Любой переход между режимами требует переключения контекста (context switch), а данные копируются через разделяемую память или page cache.

### libfuse2 vs fuse3: миграция

| Характеристика | libfuse 2.9.x (fuse2) | libfuse 3.x (fuse3) |
| :--- | :--- | :--- |
| **Пакет в Debian/Ubuntu** | `libfuse2` | `libfuse3` |
| **Многопоточность** | Один обработчик на устройство | Многопоточный обработчик по умолчанию |
| **Версия ядра** | Linux 2.6+ | Linux 4.4+ (рекомендуется 5.x+) |
| **Статус поддержки** | EOL, безопасные исправления не выпускаются | Активная разработка |
| **Опция `direct_io`** | Работает | Работает, но есть нюансы с `writeback_cache` |
| **Рекомендация** | Только для legacy-сценариев | Использовать для всех новых развертываний |

**Миграция:** Замените пакет `libfuse2` на `libfuse3`, обновите зависимости демона (например, `rclone` ≥ 1.58, `gocryptfs` ≥ 2.0). Проверьте поддержку fuse3 у сторонних демонов перед обновлением production-систем.

### Модель безопасности

- **`user_allow_other` в `/etc/fuse.conf`:** Разрешает пользователям использовать опцию монтирования `allow_other`. Без неё ФС видна только владельцу процесса монтирования.
- **Опасность `allow_other`:** При включении `allow_other` все пользователи системы получают доступ к точке монтирования. Это нарушает принцип наименьших привилегий, если каталог монтирования доступен для записи группе или others.
- **Рекомендация:** Используйте `allow_other` только в сочетании с:
  - Жесткими правами на точку монтирования (`chmod 700` для владельца).
  - SELinux/AppArmor политиками, ограничивающими доступ демона.
  - Демонами, не принимающими данных от ненадежных источников (например, `gocryptfs` безопаснее, чем `sshfs` с открытым ключом без парольной фразы).

### Преимущества и недостатки

**Преимущества:**
- **Изоляция:** Сбой демона не приводит к Kernel Panic. Ошибка обрабатывается в userspace.
- **Гибкость:** Поддержка любых языков (C, Go, Rust, Python) и источников данных (локальные каталоги, SSH, API, базы данных, архивы).
- **User-friendly:** Монтирование без прав root (с помощью `fusermount3`) для несистемных точек.
- **Быстрая разработка:** Возможность прототипировать ФС без перезагрузки ядра и модулей.

**Недостатки:**
- **Overhead:** Двойное переключение контекста и копирование данных между ядром и пользователем. Для последовательного чтения производительность может быть на 20–40% ниже нативной ФС.
- **Зависимость:** Смерть процесса-демона приводит к зависанию точки монтирования (состояние `D` или ошибки `Transport endpoint is not connected`).
- **Потенциальные deadlocks:** При критической нехватке памяти ядро и демон могут заблокировать друг друга (см. раздел «Поиск проблем»).
- **Ограничение POSIX-семантики:** Не все FUSE-демоны корректно реализуют `fcntl`-блокировки, `mmap` или `fallocate`. Это нарушает работу приложений, ожидающих строгую POSIX-совместимость (например, СУБД).

## Конфигурация и тюнинг производительности

### Файл /etc/fuse.conf

Полный набор параметров:

```text
# /etc/fuse.conf — глобальная конфигурация FUSE
# Пустые строки и строки, начинающиеся с #, игнорируются.

# Разрешить пользователям монтировать с опцией allow_other.
# Требуется для совместного доступа к ФС несколькими пользователями.
user_allow_other

# Максимальное количество FUSE-устройств, создаваемых ядром.
# По умолчанию: 0 (без ограничения). Установите лимит на shared-хостах.
# max_devices = 1024

# Разрешить монтирование с опцией default_permissions.
# Ядро будет проверять стандартные права доступа (ugo/rwx).
# Улучшает безопасность, но добавляет накладные расходы.
# default_permissions
```

### Опции монтирования для оптимизации

| Опция | Описание | Когда использовать |
| :--- | :--- | :--- |
| **`direct_io`** | Обход кэша страниц ядра. Данные передаются напрямую между демоном и приложением. | Сильно динамические данные, экономия ОЗУ. Несовместимо с `mmap` и `writeback_cache`. |
| **`kernel_cache`** | Использовать кэш страниц ядра для чтения. Демон уведомляется только об изменении файла (invalidate). | Высокая скорость повторного чтения неизменяемых файлов. Риск неактуальных данных при изменении через другой инстанс демона. |
| **`writeback_cache`** | Буферизация записи в ядре. Увеличивает скорость последовательной записи, но увеличивает риск потери данных при падении демона. | Резкое повышение скорости последовательной записи при приемлемом риске потери последних данных. |
| **`max_readahead`** | Размер упреждающего чтения в байтах. Стандартное значение: 128 КБ. | Оптимизация чтения больших файлов (медиа, образы). Уменьшите для смешанной нагрузки (много мелких файлов). |
| **`readdirplus`** | Запрос атрибутов файлов (size, mtime) при листинге каталога. | Ускорение `ls -l`, `stat` на ФС с высокой задержкой. Увеличивает количество запросов к демону. |
| **`reconnect`** | Повторно подключаться к демону, если соединение разорвано. | Критично для sshfs и rclone при нестабильной сети. |
| **`allow_other`** | Разрешить доступ к ФС другим пользователям системы. | Требует `user_allow_other` в `/etc/fuse.conf`. Используйте с осторожностью. |
| **`default_permissions`** | Ядро проверяет стандартные права POSIX. | Рекомендуется для shared-доступа, когда демон не реализует проверку прав самостоятельно. |

### Системные лимиты и параметры ядра

```bash
# Проверить текущие лимиты
cat /proc/sys/fs/fuse/max_user_namespaces
cat /proc/sys/fs/fuse/max_user_consoles
cat /proc/sys/fs/inotify/max_user_instances

# Временное увеличение лимита (до перезагрузки)
sudo sysctl fs.fuse.max_user_namespaces=65536

# Постоянное изменение — /etc/sysctl.d/99-fuse.conf
cat <<'EOF' | sudo tee /etc/sysctl.d/99-fuse.conf
fs.fuse.max_user_namespaces = 65536
fs.inotify.max_user_instances = 1024
EOF
sudo sysctl --system
```

## Практические сценарии

### 1. Контейнеризация (fuse-overlayfs)

**Предпосылки:** Rootless Podman/Docker, ограниченные права на хосте, необходимость объединения слоев контейнера без нативного overlay.

**Пошаговая инструкция:**

```bash
# 1. Установка
sudo apt install fuse-overlayfs  # Debian/Ubuntu
sudo dnf install fuse-overlayfs  # RHEL/Fedora

# 2. Проверка поддержки в ядре
grep overlay /proc/filesystems
# → nodev    overlay

# 3. Настройка containerd/storage.conf для Podman/Docker
# Добавить в [storage.options] или в containers.conf:
#   mount_program = "/usr/bin/fuse-overlayfs"
#   mountopt = "fuse-overlayfs,lowerdir=..."

# 4. Запуск rootless-контейнера
podman run --rm -it alpine sh
```

**Валидация:**
```bash
# Проверить тип ФС внутри контейнера
podman inspect <container> --format '{{.GraphDriver.Name}}'
# → fuse-overlayfs

# Проверить отсутствие ошибок в логах
journalctl --user -u podman --since "10 minutes ago" | grep -i fuse
```

**Очистка:**
```bash
podman system prune --all --force
# Удаление неиспользуемых образов и слоев
```

**Ограничения:** `fuse-overlayfs` медленнее нативного overlay (на 10–20% при массовой записи). Не поддерживает все возможности overlay, например, `metacopy` в старых версиях ядра.

### 2. Шифрование «на лету» (Gocryptfs)

**Предпосылки:** Хранение чувствительных данных на общем хранилище (NFS, SMB, внешние диски), требование шифрования на уровне ФС без предварительного создания контейнеров (LUKS).

**Пошаговая инструкция:**

```bash
# 1. Установка
sudo apt install gocryptfs  # Debian/Ubuntu
sudo dnf install gocryptfs  # RHEL/Fedora (from COPR)

# 2. Инициализация зашифрованного хранилища
gocryptfs -init /data/cipher
# → Выберите парольную фразу (максимум 512 бит энтропии)
# → Генерируется master.key и конфиг gocryptfs.conf

# 3. Монтирование
mkdir -p /mnt/plain
gocryptfs /data/cipher /mnt/plain
# → Ввод парольной фразы

# 4. Работа с данными (прозрачно для приложений)
cp /etc/fstab /mnt/plain/backup-fstab
ls -la /mnt/plain/backup-fstab

# 5. Размонтирование
fusermount3 -u /mnt/plain
```

**Валидация:**
```bash
# Проверить, что файлы на диске зашифрованы
file /data/cipher/*.gocryptfs.*
# → data: gocryptfs ciphertext

# Проверить точку монтирования
mount | grep gocryptfs
# → gocryptfs on /mnt/plain type fuse.gocryptfs
```

**Очистка/деинсталляция:**
```bash
# Если требуется удалить зашифрованные данные безвозвратно
shred -vfz -n 3 /data/cipher/*
rm -rf /data/cipher /mnt/plain
```

**Ограничения и edge cases:**
- Производительность на запись ниже нативной ФС на 15–25% из-за шифрования (AES-NI ускоряет до 10% потерь).
- Имена файлов могут быть зашифрованы (режим `-plaintextnames` отключает, но снижает безопасность).
- Максимальный размер файла: 2^64−1 байт, но для файлов >16 ГБ эффективность шифрования снижается из-за размера блока (16 КБ).
- Резервное копирование: `/data/cipher` можно бэкапить как обычные файлы, но для восстановления требуется `gocryptfs.conf` и `master.key`.

### 3. Удаленный доступ к файлам (SSHFS)

**Предпосылки:** Централизованное хранилище на удаленном сервере, необходимость прозрачного доступа без NFS/SMB (ограничения файрвола, отсутствие прав root).

**Пошаговая инструкция:**

```bash
# 1. Установка
sudo apt install sshfs  # Debian/Ubuntu
sudo dnf install fuse-sshfs  # RHEL/Fedora

# 2. Создание точки монтирования и монтирование
mkdir -p /mnt/remote
sshfs -o reconnect,allow_other,default_permissions,ServerAliveInterval=15,ServerAliveCountMax=3 \
  admin@192.168.1.10:/export/data /mnt/remote

# 3. Автоматическое монтирование через systemd (см. ниже)

# 4. Размонтирование
fusermount3 -u /mnt/remote
```

**Валидация:**
```bash
# Проверить подключение
mount | grep sshfs
# → admin@192.168.1.10:/export/data on /mnt/remote type fuse.sshfs

# Проверить задержку
time ls -la /mnt/remote/ | head -20
```

**Очистка:**
```bash
fusermount3 -u /mnt/remote
rmdir /mnt/remote
# Удалить строку из /etc/fstab или юнит systemd, если больше не требуется
```

**Ограничения:**
- Производительность чувствительна к RTT. При задержке >50 мс скорость последовательного чтения может падать в 3–5 раз.
- Не подходит для интенсивной записи множеством мелких файлов (каждый вызов `open/write/close` = отдельный SSH-запрос).
- SSH-ключ без парольной фразы снижает безопасность; используйте `ssh-agent` с ограниченным временем жизни.

### 4. Поддержка NTFS и других Foreign ФС (ntfs-3g)

**Предпосылки:** Обмен данными с Windows-системами, загрузочные флешки, внешние диски.

**Пошаговая инструкция:**

```bash
# 1. Установка
sudo apt install ntfs-3g  # Debian/Ubuntu
sudo dnf install ntfs-3g  # RHEL/Fedora

# 2. Монтирование раздела
sudo mkdir -p /mnt/windows
sudo mount -t ntfs-3g -o permissions,defaults /dev/sdb1 /mnt/windows

# 3. Проверка
ls -la /mnt/windows/Users/
# → NTFS-права маппятся на UID/GID текущего пользователя

# 4. Размонтирование
sudo umount /mnt/windows
```

**Валидация:**
```bash
# Проверить тип ФС
df -T /mnt/windows
# → /dev/sdb1   ntfs-3g

# Проверить поддержку прав
sudo ntfs-3g.probe -v /dev/sdb1
# → NTFS signature is present.
```

**Ограничения:**
- Производительность ниже нативного `ntfs3` (ядро 5.15+) на 10–15% при последовательной записи, но `ntfs-3g` стабильнее в edge cases (поврежденные разделы, Windows 11 с шифрованием BitLocker).
- `ntfs-3g` не поддерживает transparent compression (NTFS compression) при монтировании.
- Для внешних дисков используйте опцию `windows_names`, запрещающую создание файлов с именами, недопустимыми в Windows.

### 5. Монтирование архивов и образов (archivemount, avfs)

**Предпосылки:** Работа с ISO, ZIP, TAR.GZ как с обычными каталогами без распаковки. Полезно для CI/CD артефактов, бэкапов.

**Пошаговая инструкция (archivemount):**

```bash
# 1. Установка
sudo apt install archivemount  # Debian/Ubuntu
sudo dnf install archivemount  # RHEL/Fedaro

# 2. Монтирование образа ISO
mkdir -p /mnt/iso
archivemount /data/images/ubuntu-22.04.iso /mnt/iso

# 3. Чтение содержимого
ls -la /mnt/iso/
cat /mnt/iso/.disk/info

# 4. Размонтирование
fusermount3 -u /mnt/iso
```

**Пошаговая инструкция (AVFS — виртуальная ФС для архивов):**

```bash
# 1. Установка
sudo apt install avfs  # Debian/Ubuntu

# 2. Монтирование AVFS (создает # директорию для доступа к любому архиву)
mount -t fuse.avfs avfs /mnt/avfs -o allow_other

# 3. Доступ к архиву через # директорию
ls /mnt/avfs/
# → Содержимое домашней директории + # директория

ls /mnt/avfs#/home/user/backup.tar.gz
# → Просмотр содержимого архива без распаковки

# 4. Размонтирование
fusermount3 -u /mnt/avfs
```

**Валидация:**
```bash
# Проверить точку монтирования
mount | grep -E "archivemount|avfs"
```

**Ограничения:**
- Запись в архив через archivemount не поддерживается (read-only).
- AVFS требует переиндексации при добавлении новых архивов (avfsd отслеживает изменения).
- Производительность пропорциональна размеру архива; для ZIP >4 ГБ используйте `zipfs` из p7zip-full.

### 6. Создание пользовательских ФС для мониторинга и метрик (sysadmin)

**Предпосылки:** Агрегация метрик из разнородных источников (логи, статусы сервисов, температуру) в единое дерево файлов для совместимости с утилитами `top`, `df`, `free`.

**Альтернативы без FUSE:** Для сбора метрик используйте Prometheus Node Exporter,Textfile Collector или `collectd`. FUSE здесь применяется только для legacy-интеграции или специфических задач.

**Пример (Go + libfuse3):**

```go
// Пример минимального демона, экспортирующего метрику "load" в /mnt/metrics/load
// Для production используйте github.com/hanwen/go-fuse/v2/fuse

package main

import (
    "syscall"
    "github.com/hanwen/go-fuse/v2/fs"
    "github.com/hanwen/go-fuse/v2/fuse"
    "os"
    "time"
)

type MetricNode struct {
    fs.Inode
}

func (n *MetricNode) Getattr(ctx *fuse.Context, out *fuse.AttrOut) syscall.Errno {
    out.Size = 4
    out.Mode = 0444
    out.Mtime = uint32(time.Now().Unix())
    return 0
}

func (n *MetricNode) Read(ctx *fuse.Context, dest []byte, off int64, fh fs.FileHandle) (fuse.ReadResult, syscall.Errno) {
    load, _ := os.ReadFile("/proc/loadavg")
    return fuse.ReadResultData(load), 0
}

func main() {
    root := &MetricNode{}
    server, err := fs.Mount("/mnt/metrics", root, &fs.Options{})
    if err != nil {
        panic(err)
    }
    server.Wait()
}
```

**Пошаговая инструкция (Python + llfuse):**

```bash
# 1. Установка
pip install llfuse

# 2. Запуск демона
python3 my_metric_fs.py /mnt/metrics

# 3. Проверка
cat /mnt/metrics/cpu_usage
# → "0.42"

# 4. Интеграция с системными утилитами
watch -n 1 'cat /mnt/metrics/load'
df -h /mnt/metrics  # если ФС экспортирует объемы
```

**Валидация:**
```bash
# Проверить, что демон запущен
ps aux | grep my_metric_fs
mount | grep my_metric_fs

# Проверить экспортируемые файлы
find /mnt/metrics -type f -executable
```

**Ограничения:**
- Производительность Python-реализаций на 30–40% ниже Go/Rust из-за GIL и накладных расходов интерпретатора.
- Для production метрик используйте специализированные ФС только если требуется совместимость с утилитами, не умеющими читать Prometheus/statsd.

## Диагностика и решение проблем

### Типичные ошибки

- **`Transport endpoint is not connected`:**
  - **Причина:** Демон ФС упал или был убит (OOM Killer, `kill -9`, паника в userspace).
  - **Диагностика:**
    ```bash
    # Проверить, жив ли демон
    pgrep -af sshfs|gocryptfs|rclone
    # Проверить системный лог
    journalctl --since "10 minutes ago" | grep -iE "fuse|killed|oom"
    dmesg | grep -iE "fuse|transport endpoint"
    ```
  - **Решение:** Принудительное размонтирование:
    ```bash
    fusermount3 -uz /mnt/path
    # или
    umount -l /mnt/path  # ленивое размонтирование (async)
    ```

- **Зависание `ls` (D-state):**
  - **Причина:** Демон завис или ждет ответа от неответившего удаленного сервиса (сеть, SSH, API).
  - **Диагностика:**
    ```bash
    # Найти процессы в uninterruptible sleep (D-state)
    ps aux | awk '$8 ~ /D/ {print}'
    # Проверить, какой процесс удерживает ФС
    sudo lsof +D /mnt/path
    sudo fuser -vm /mnt/path
    ```
  - **Решение:** Использование опций `reconnect`, увеличение таймаутов или принудительное размонтирование.

### Логи и события ядра

```bash
# Все события FUSE за последний час
journalctl --since "1 hour ago" | grep -E "fuse|FUSE"

# События ядра, связанные с FUSE
dmesg | grep -E "fuse|FUSE"

# Логи конкретного демона (пример для gocryptfs)
journalctl --user -u gocryptfs --since "30 minutes ago"

# Мониторинг создания/уничтожения FUSE-устройств в реальном времени
sudo udevadm monitor --kernel --property | grep FUSE
```

### Производительность и мониторинг

```bash
# Задержка системных вызовов для FUSE-процесса
sudo perf stat -e syscalls:sys_enter_* -p $(pgrep -f sshfs)

# Ввод-вывод демона FUSE
sudo pidstat -d -p $(pgrep -f sshfs) 1

# Использование памяти демоном FUSE
ps -p $(pgrep -f sshfs) -o pid,rss,vsz,comm

# Количество запросов в очереди FUSE (ядро 5.4+)
cat /sys/fs/fuse/connections/*/waiting
# → Количество запросов, ожидающих обработки демоном

# Мониторинг deadlock-риска (очереди FUSE)
watch -n 5 'cat /sys/fs/fuse/connections/*/waiting'
# Если значение постоянно растет — демон не успевает обрабатывать запросы
```

### Поиск проблем (Deadlocks)

FUSE чувствителен к нехватке памяти (Memory Pressure). Если ядро пытается сбросить страницы FUSE для освобождения памяти, а демону FUSE нужна память для обработки этого сброса — возникает deadlock.

- **Избегайте** использования FUSE для разделов подкачки (swap) или критических системных путей.
- **Мониторинг:** Настройте алерты на рост очереди FUSE (`/sys/fs/fuse/connections/*/waiting`) и увеличение латентности `stat()` на точках монтирования.
- **Решение:** При deadlock требуется перезагрузка или `echo 3 > /proc/sys/vm/drop_caches` (с осторожностью, сбрасывает весь page cache).

### Аварийное размонтирование и восстановление

```bash
# Ленивое размонтирование (async) — немедленно возвращает управление
sudo umount -l /mnt/path

# Принудительное размонтирование через fusermount3
fusermount3 -uz /mnt/path

# Если точка монтирования "зависла" и fsck не помогает
sudo mount -o remount /  # перемонтирование корня
sudo rm -rf /mnt/path     # удаление "мертвой" точки
mkdir -p /mnt/path        # повторное создание
```

## Безопасность

### Принципы безопасного развертывания

1. **Принцип наименьших привилегий:** Монтируйте ФС от имени отдельного сервисного пользователя, а не root, если это возможно. Используйте `fusermount3` вместо прямого вызова `mount`.
2. **Ограничение `allow_other`:** Включайте `allow_other` только при необходимости. Если ФС монтируется для одного пользователя — не включайте эту опцию.
3. **Права на точку монтирования:** Устанавливайте `chmod 700` на каталог монтирования, если ФС используется одним пользователем. Для shared-доступа — `chmod 750` с соответствующей группой.
4. **SELinux / AppArmor:** Применяйте политики Mandatory Access Control к демонам FUSE.
   ```bash
   # Пример для AppArmor (Ubuntu)
   sudo aa-complain /usr/bin/gocryptfs
   # Пример для SELinux (RHEL)
   sudo semanage fcontext -a -t bin_t "/usr/bin/gocryptfs"
   ```
5. **Сетевые демоны (sshfs, rclone):** Ограничьте сетевой доступ демона через файрвол (например, только внутренняя сеть 10.0.0.0/8). Используйте SSH-ключи с парольной фразой и `ssh-agent`.

### Векторы атак

- **Privilege escalation через setuid:** Старые версии libfuse2 использовали setuid-root бинарники (fusermount). В libfuse3 и современных дистрибутивах fusermount3 работает через `cap_sys_admin` в пользовательском namespace или через polkit.
- **Эксплуатация vulnerabilities в демоне:** Демон FUSE работает от имени пользователя, но имеет доступ к ФС. Уязвимость в демоне (например, buffer overflow в gocryptfs) может привести к утечке данных. Регулярно обновляйте демоны.
- **Доступ к другим точкам монтирования:** Если `allow_other` включен глобально, злоумышленник с доступом к ФС может попытаться перемонтировать её и получить доступ к данным. Используйте `default_permissions` для принудительной проверки прав.
