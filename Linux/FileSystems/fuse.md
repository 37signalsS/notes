# FUSE (Filesystem in Userspace)

## Определения

- **FUSE (Filesystem in Userspace):** Программный интерфейс в Unix-подобных операционных системах, позволяющий непривилегированным пользователям создавать собственные файловые системы без изменения кода ядра. Логика файловой системы реализуется в пользовательском пространстве (userspace).
- **libfuse / fuse3:** Библиотека и эталонная реализация интерфейса FUSE. Версия `fuse3` является актуальным стандартом, заменяющим устаревшую `fuse` (2.x).
- **Демон ФС (FS Daemon):** Процесс в пространстве пользователя, который обрабатывает запросы ввода-вывода, перенаправленные ядром через модуль FUSE.

## Основные концепции

### Архитектура и принцип работы

Инфраструктура FUSE состоит из трех компонентов: модуля ядра (`fuse.ko`), пользовательской библиотеки (`libfuse` / `fuse3`) и утилиты монтирования (`fusermount` / `fusermount3`).

```text
+---------------------------------------------------+
|   Приложение (например, ls, cp, cat)              |
+---------------------------------------------------+
|               Ядро (VFS)                          |
+-------------------+-------------------------------+
                    | (Запрос VFS)
                    v
+-------------------+-------------------------------+
|               Модуль ядра FUSE                    |
+-------------------+-------------------------------+
                    | (Передача через /dev/fuse)
                    v
+-------------------+-------------------------------+
|   Демон ФС (Userspace Process / SSHFS / Rclone)   |
+---------------------------------------------------+
```

1.  Приложение вызывает системный вызов (например, `read()`).
2.  VFS передает запрос модулю ядра FUSE.
3.  Модуль FUSE ставит запрос в очередь и уведомляет демона ФС через файл устройства `/dev/fuse`.
4.  Демон считывает запрос, выполняет необходимую логику и возвращает результат в `/dev/fuse`.
5.  Ядро завершает системный вызов для исходного приложения.

### Преимущества и недостатки

**Преимущества:**
- **Безопасность и стабильность:** Ошибки в коде ФС не вызывают панику ядра (Kernel Panic). Весь код выполняется с правами обычного пользователя.
- **Скорость разработки:** Возможность реализации ФС на высокоуровневых языках (Python, Go, Rust, Java).
- **Монтирование без root:** Обычные пользователи могут монтировать ресурсы в свои домашние директории.

**Недостатки:**
- **Производительность (Overhead):** Многократное переключение контекста между Userspace и Kernelspace для каждой операции приводит к значительным задержкам. Не рекомендуется для высоконагруженных систем (High-IOPS).

## Конфигурация и безопасность

### Файл /etc/fuse.conf

Поведение FUSE регулируется глобальным конфигурационным файлом.
- **`user_allow_other`:** Критически важный параметр. По умолчанию FUSE-ФС видна только пользователю, который её смонтировал. Эта опция позволяет использовать флаг `-o allow_other` для предоставления доступа другим пользователям (включая `root`).

### Безопасность монтирования

Утилита `fusermount` имеет SUID-бит, что позволяет ей выполнять монтирование от имени обычного пользователя. Однако ядро применяет строгие ограничения: другие пользователи (даже `root`) не могут войти в смонтированную директорию, если не указана опция `allow_other`.

## Практические сценарии

### 1. Монтирование через Rclone (Рекомендуемый метод)

Rclone является современным стандартом для работы с облачными и удаленными хранилищами (S3, SFTP, WebDAV).

```bash
# Монтирование S3-бакета с кэшированием для повышения производительности
rclone mount remote_s3:my-bucket /mnt/s3 \
    --vfs-cache-mode full \
    --allow-other \
    --daemon
```

### 2. Использование SSHFS (Устаревающий метод)

SSHFS позволяет монтировать удаленную директорию через SSH. Проект считается находящимся на этапе поддержки (maintenance mode), для новых задач рекомендуется Rclone.

```bash
# Монтирование
sshfs user@remote-host:/data ~/mnt/remote -o reconnect,allow_other

# Размонтирование (используйте версию 3, если установлена)
fusermount3 -u ~/mnt/remote
```

### 3. Контейнеризация: fuse-overlayfs

В rootless-контейнерах (Podman) обычный пользователь не может использовать нативный `overlay` драйвер ядра.
- **Роль:** `fuse-overlayfs` реализует объединение слоев образа в пространстве пользователя.
- **Настройка:** В Podman выбирается автоматически, если обнаружен соответствующий бинарный файл.

### 4. NTFS-3G

Обеспечивает полноценную поддержку записи для разделов NTFS в Linux. Несмотря на появление в ядре 5.15 драйвера `ntfs3` от Paragon, `ntfs-3g` остается стандартом совместимости в многих дистрибутивах.
