# Файловые дескрипторы

## Определения

- **Файловый дескриптор (File Descriptor, FD):** Целое неотрицательное число, которое ядро Linux использует для идентификации открытого файла или другого ресурса ввода-вывода (сокета, канала, устройства).

## Основные концепции

### Стандартные потоки

Каждый процесс в Linux при запуске автоматически получает три стандартных файловых дескриптора:

- `0` – `stdin` (стандартный ввод): Источник данных для процесса (по умолчанию — клавиатура).
- `1` – `stdout` (стандартный вывод): Место вывода основного результата процесса (по умолчанию — экран терминала).
- `2` – `stderr` (стандартный вывод ошибок): Место вывода сообщений об ошибках процесса (по умолчанию — экран терминала).

Подробнее о стандартных потоках и их перенаправлении см. в [Перенаправление ввода-вывода в Bash](../Shell/io_redirection.md) и [Операторы и конвейеры в Bash](../Shell/operators_and_pipelines.md).

### Как устроены дескрипторы внутри ядра

У каждого процесса есть **таблица файловых дескрипторов** — по сути, массив, где индекс — это номер дескриптора, а значение — указатель на внутреннюю структуру ядра (`struct file`). В этой структуре ядро хранит всё про данное открытие: текущую позицию чтения/записи, флаги доступа (O_RDONLY, O_WRONLY, O_RDWR), счётчик ссылок. Эта структура, в свою очередь, ссылается на inode файла (что такое inode — см. [Ссылки, Inode и Dentry](./links_inodes_dentries.md)).

Когда процесс вызывает `open()`, ядро создаёт запись в этой таблице и возвращает процессу наименьший свободный номер. Далее процесс работает только с этим числом: `read(3)`, `write(3)`, `close(3)`.

### Всё есть файл

В Linux «всё есть файл». Каждый открытый ресурс — это файловый дескриптор:

| Ресурс | Пример |
| :--- | :--- |
| Обычные файлы | `/var/log/syslog` |
| Сокеты (TCP/UDP) | Каждое TCP-соединение = один FD |
| Именованные каналы (pipes) | `pipe()` между процессами |
| Unix-сокеты | IPC через доменные сокеты |
| Устройства (`/dev/`) | `/dev/sda`, `/dev/null` |
| epoll/inotify | Асинхронный I/O, мониторинг событий |

Если не ограничивать количество дескрипторов, один процесс может исчерпать все ресурсы ядра. Поэтому существуют лимиты.

### Лимиты файловых дескрипторов

| Тип лимита | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| **Soft limit** (на процесс) | Мягкий лимит. Процесс может поднять его сам, но не выше hard limit | 1024 |
| **Hard limit** (на процесс) | Жёсткий потолок. Только `root` или admin может повысить | 4096 (иногда 524288) |
| **Системный лимит** (`fs.file-max`) | Максимум дескрипторов для всех процессов суммарно | Зависит от RAM (обычно миллионы) |

**Практическая проблема:** дефолтный soft limit 1024 — частая причина сбоев. Каждое TCP-соединение — это файловый дескриптор. Запустили высоконагруженный сервер (nginx, Kafka), пошла нагрузка, уперлись в лимит — и приложение отбивает новые подключения с ошибкой `Too many open files`.

**Проверка:**

```bash
# Soft limit текущей сессии
ulimit -Sn

# Hard limit
ulimit -Hn

# Системный максимум
cat /proc/sys/fs/file-max

# Сколько дескрипторов использует процесс
ls /proc/<PID>/fd/ | wc -l

# Сколько дескрипторов выделено системой
cat /proc/sys/fs/file-nr
# Вывод: <выделено> <свободно_выделенных> <системный_максимум>
```

### Утечки файловых дескрипторов

Утечка файловых дескрипторов возникает, когда процесс открывает файлы или сокеты, но не закрывает их, постепенно исчерпывая системные или установленные для процесса лимиты. Это приводит к ошибкам `Too many open files` и может вызвать отказ приложения.

Подробнее о диагностике утечек: [Локализация утечек файловых дескрипторов](../Diagnostics/Troubleshooting/troubleshooting_file_descriptor_leaks.md).

## Практические сценарии

### Освобождение файловых дескрипторов

Если процесс удерживает файловые дескрипторы и необходимо их освободить, доступны следующие методы.

**Завершение процесса:**

```bash
# Корректное завершение (SIGTERM)
kill <PID>

# Принудительное завершение (крайняя мера)
kill -9 <PID>
```

Подробнее о сигналах: [Process Signals](../Core/processes/signals.md).

**Перезапуск сервиса:**

Если файлы удерживаются службой (Nginx, Apache, MySQL):

```bash
systemctl restart <service>
# Или
service <service> restart
```

**Поиск процессов, удерживающих файл:**

```bash
lsof <имя_файла>
fuser <имя_файла>
```

**Закрытие дескриптора без завершения процесса:**

1. Найти открытые дескрипторы процесса:

   ```bash
   ls -l /proc/<PID>/fd/
   ```

2. Закрыть конкретный дескриптор через `gdb` (если процесс нельзя перезапустить):

   ```bash
   gdb -p <PID>
   (gdb) call close(<FD>)
   (gdb) detach
   (gdb) quit
   ```

   > **Важно:** Использование `gdb` требует осторожности — принудительное закрытие дескриптора может нарушить логику процесса.

**Перемонтирование файловой системы:**

Если файл удалён, но удерживается процессом, можно перемонтировать файловую систему:

```bash
mount -o remount /
```

Поиск удалённых, но удерживаемых файлов:

```bash
lsof | grep deleted
```

Подробнее о диагностике удалённых файлов: [`lsof`](../Diagnostics/Processes/lsof.md).

### Просмотр и мониторинг файловых дескрипторов

- **`lsof` (List Open Files):** Основной инструмент для отображения всех файлов и ресурсов ввода-вывода, открытых процессами.

    ```bash
    # Показать все открытые файлы для процесса по PID
    sudo lsof -p <PID>
    # Посчитать количество открытых дескрипторов для процесса
    sudo lsof -p <PID> | wc -l
    ```

    Подробнее об использовании `lsof` см. в [lsof — Список открытых файлов](../Diagnostics/Processes/lsof.md).

- **Просмотр через `/proc`:** Директория `/proc/<PID>/fd/` содержит символические ссылки на все открытые файловые дескрипторы процесса.

    ```bash
    # Посчитать количество открытых дескрипторов для процесса
    ls -l /proc/<PID>/fd/ | wc -l
    ```

- **`ulimit`:** Просмотр и установка лимитов ресурсов (включая лимит на количество открытых файловых дескрипторов) для текущей сессии или процесса.

    ```bash
    # Показать текущий лимит на FD
    ulimit -n
    # Установить новый лимит (для текущей сессии)
    ulimit -n 4096
    ```

    Подробнее о лимитах ресурсов см. в [Лимиты ресурсов в Linux: ulimit](../Core/processes/limits_hierarchy.md).

- **`cat /proc/sys/fs/file-nr`:** Общесистемная информация о файловых дескрипторах.

    ```bash
    # Вывод: <выделено_FD> <свободно_выделенных_FD> <макс_FD_в_системе>
    cat /proc/sys/fs/file-nr
    ```

- **`fuser`:** Показывает, какие процессы используют указанный файл или файловую систему.

    ```bash
    # Найти процесс, использующий файл
    fuser -v /path/to/your/file
    ```
