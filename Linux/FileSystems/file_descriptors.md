# Файловые дескрипторы

## Определения

- **Файловый дескриптор (File Descriptor, FD):** Неотрицательное целое число, которое ядро Linux использует в качестве абстрактного указателя для идентификации открытого файла или ресурса ввода-вывода (I/O — Input/Output). К ресурсам относятся обычные файлы, каталоги, сокеты, каналы и устройства.
- **Стандартные потоки (Standard Streams):** Три предопределенных дескриптора (`0`, `1`, `2`), которые автоматически открываются ядром для каждого нового процесса.

## Основные концепции

### Стандартные потоки ввода-вывода

При запуске процесса ядро резервирует первые три записи в его таблице дескрипторов:

| FD | Название | Системный макрос | Описание |
| :--- | :--- | :--- | :--- |
| **0** | **stdin** | `STDIN_FILENO` | Стандартный ввод (по умолчанию — клавиатура). |
| **1** | **stdout** | `STDOUT_FILENO` | Стандартный вывод (по умолчанию — экран терминала). |
| **2** | **stderr** | `STDERR_FILENO` | Стандартный вывод ошибок (по умолчанию — экран терминала). |

Подробнее о работе с потоками в командной оболочке см. в разделе **[Перенаправление ввода-вывода в Bash](../Shell/io_redirection.md)**.

### Механизм работы в ядре

В Linux реализована многоуровневая структура управления файлами:

1. **Таблица дескрипторов процесса:** Локальный массив процесса, где индекс — это число FD. Каждая запись указывает на структуру в общесистемной таблице открытых файлов.
2. **Таблица открытых файлов (System-wide Open File Table):** Хранит состояние каждого открытия: текущую позицию (offset), флаги доступа (чтение/запись), статус блокировок и счетчик ссылок.
3. **Таблица Inode:** Хранит метаданные самого файла на диске. Несколько дескрипторов могут указывать на один и тот же Inode (например, при дублировании дескрипторов или открытии одного файла разными процессами).

Подробнее о структуре метаданных см. в материале **[Ссылки, Inode и Dentry](./links_inodes_dentries.md)**.

### Концепция «Всё есть файл»

Благодаря абстракции FD, ядро предоставляет унифицированный интерфейс (`read`, `write`, `close`) для работы с разнородными ресурсами. «Открытым файлом» в терминах Linux считается:

- Обычный файл на диске
- TCP- или UDP-сокет
- Unix-сокет
- Канал (pipe)
- `eventfd`, `signalfd`, `timerfd`
- Экземпляр epoll
- Каталог, открытый через `opendir`
- Дескриптор устройства (`/dev/null`, `/dev/random` и т. д.)

Типичный HTTP-сервис на Go держит: 1 FD для сокета прослушивания, 1 FD на каждое принятое соединение, 1 FD на каждое исходящее соединение (часто через пул), несколько FD для логов, stdin/stdout/stderr и экземпляров epoll. Сервис с 10 000 одновременных соединений легко выходит на 12 000+ FD.

### Лимиты дескрипторов

Для предотвращения исчерпания ресурсов ядра (памяти под структуры `struct file`) и защиты от некорректно работающих приложений (утечек) установлены ограничения:

- **Soft Limit (Мягкий лимит):** Текущее ограничение процесса. Процесс может сам увеличить его до значения Hard Limit.
- **Hard Limit (Жесткий лимит):** Максимально допустимый потолок. Повысить его может только пользователь с привилегиями `root`.
- **System-wide Limit (`fs.file-max`):** Общий лимит открытых файлов для всей операционной системы.

Превышение лимита приводит к ошибке `Too many open files` (EMFILE или ENFILE).

## Практические сценарии

### Диагностика использования дескрипторов

Проверка лимитов текущей сессии:

```bash
# Мягкий лимит
ulimit -Sn
# Жесткий лимит
ulimit -Hn
```

Анализ использования дескрипторов конкретным процессом:

```bash
# Список открытых файлов процесса (через PID)
ls -l /proc/<PID>/fd/

# Подсчет количества открытых дескрипторов
ls /proc/<PID>/fd/ | wc -l
```

Просмотр общесистемной статистики:

```bash
# Вывод: <используется> <свободно_выделено> <максимум>
cat /proc/sys/fs/file-nr
```

### Поиск процессов по открытым файлам

Использование утилиты `lsof` (List Open Files) для идентификации «владельца» ресурса:

```bash
# Найти, кто открыл конкретный файл
lsof /path/to/file

# Показать все сетевые дескрипторы процесса
lsof -i -p <PID>
```

Подробнее об использовании утилиты см. в справочнике **[lsof — Список открытых файлов](../Diagnostics/Processes/lsof.md)**.

### Решение проблем с удерживаемыми файлами

Если файл удален (`rm`), но место на диске не освободилось, это означает, что процесс удерживает его FD.

1. Найти такие файлы: `lsof +L1` или `lsof | grep deleted`.
2. Освободить место: завершить процесс или обнулить файл через дескриптор в `/proc`:

   ```bash
   # Обнуление удаленного, но открытого файла (FD=7)
   : > /proc/<PID>/fd/7
   ```

Подробнее о диагностике нехватки места см. в **[Устранение нехватки места на диске](./disk_space_troubleshooting.md)**.
