# Файловые дескрипторы

## Определения

- **Файловый дескриптор (File Descriptor, FD):** Неотрицательное целое число, которое ядро Linux использует в качестве абстрактного указателя для идентификации открытого файла или ресурса ввода-вывода (I/O). С точки зрения программиста — это индекс в массиве открытых ресурсов процесса.
- **Описание открытого файла (Open File Description):** Системная структура данных (внутри ядра), на которую ссылается дескриптор. Она содержит состояние: текущее смещение (offset), флаги состояния (status flags) и счетчик ссылок.
- **Стандартные потоки (Standard Streams):** Три предопределенных дескриптора (`0`, `1`, `2`), которые автоматически открываются ядром для каждого нового процесса.

## Основные концепции

### Стандартные потоки ввода-вывода

При запуске процесса ядро резервирует первые три записи в его таблице дескрипторов:

| FD | Название | Системный макрос | Описание |
| :--- | :--- | :--- | :--- |
| **0** | **stdin** | `STDIN_FILENO` | Стандартный ввод (по умолчанию — клавиатура). |
| **1** | **stdout** | `STDOUT_FILENO` | Стандартный вывод (по умолчанию — экран терминала). |
| **2** | **stderr** | `STDERR_FILENO` | Стандартный вывод ошибок (по умолчанию — экран терминала). |

Подробнее о работе с потоками в командной оболочке см. в разделе **[Перенаправление ввода-вывода в Bash](../Shell/io_redirection.md)**.

### Трехуровневая архитектура ядра

В Linux реализована многослойная абстракция для управления ресурсами, что позволяет разным дескрипторам разделять состояние файла:

1.  **Таблица дескрипторов процесса (Process Descriptor Table):**
    - Локальна для каждого процесса.
    - Содержит записи, указывающие на записи в общесистемной таблице открытых файлов.
    - Флаг `FD_CLOEXEC` хранится именно здесь (на уровне дескриптора).
2.  **Общесистемная таблица открытых файлов (Open File Table):**
    - Содержит «Описания открытых файлов» (Open File Descriptions).
    - Хранит **текущую позицию (offset)**, флаги доступа (чтение/запись, `O_APPEND`, `O_NONBLOCK`) и счетчик ссылок.
    - При вызове `fork()` или `dup()` создаются новые дескрипторы, указывающие на **ту же самую** запись в этой таблице. Это причина, по которой родитель и потомок разделяют общее смещение в файле.
3.  **Таблица Inode (Inode Table):**
    - Хранит метаданные самого файла на диске (права, размер, физические блоки).
    - Разные записи в Open File Table (созданные через независимые вызовы `open()`) могут указывать на один и тот же Inode, но иметь разные смещения.

Подробнее о структуре метаданных см. в материале **[Ссылки, Inode и Dentry](./links_inodes_dentries.md)**.

### Наследование и флаги дескрипторов

Поведение дескрипторов при системных вызовах критично для безопасности и производительности:

-   **fork():** Потомок получает полную копию таблицы дескрипторов родителя. Дескрипторы указывают на те же Open File Descriptions.
-   **exec():** По умолчанию дескрипторы остаются открытыми в новой программе. Это может привести к утечке данных (например, если дочерний процесс получит доступ к открытому файлу паролей).
-   **O_CLOEXEC (Close-on-exec):** Флаг, указывающий ядру автоматически закрыть дескриптор при выполнении `exec()`. Рекомендуется использовать по умолчанию для всех открываемых файлов в многопоточных приложениях.
-   **O_NONBLOCK:** Переводит работу с дескриптором в неблокирующий режим. Если данных нет, `read()` вернет ошибку `EAGAIN` вместо ожидания.

### Концепция «Всё есть файл»

Благодаря абстракции FD, ядро предоставляет унифицированный интерфейс (`read`, `write`, `close`, `select/poll/epoll`) для работы с разнородными ресурсами:

-   **Обычные файлы и каталоги.**
-   **Сетевые сокеты:** TCP, UDP, Unix Domain Sockets.
-   **Каналы (Pipes):** Анонимные и именованные (`fifo`).
-   **Специальные дескрипторы уведомлений:**
    -   `eventfd`: Легковесный счетчик для межпроцессного взаимодействия.
    -   `signalfd`: Чтение сигналов как данных из файла.
    -   `timerfd`: Таймеры, интегрируемые в событийные циклы.
-   **Дескрипторы управления:** `epoll` инстансы, **[io_uring](../Core/kernel/io_uring.md)**.
-   **Анонимная память:** `memfd_create` (файл в RAM, не привязанный к ФС).
-   **Управление процессами:** `pidfd` (стабильный идентификатор процесса, исключающий риск переиспользования PID).

### Лимиты дескрипторов

Для защиты системы от «прожорливых» или некорректных приложений установлены ограничения:

1.  **Soft Limit (Мягкий лимит):** Текущее ограничение процесса. Процесс может сам увеличить его до Hard Limit через `setrlimit()`.
2.  **Hard Limit (Жесткий лимит):** Потолок, который может повысить только `root`.
3.  **System-wide Limit (`fs.file-max`):** Общий лимит открытых файлов для всего ядра.
4.  **fs.nr_open:** Максимальное значение, которое может принять `ulimit -n`.

Превышение лимита приводит к ошибке `Too many open files` (`EMFILE` — лимит процесса, `ENFILE` — лимит системы).

## Практические сценарии

### Диагностика использования дескрипторов

Проверка лимитов текущей сессии:

```bash
# Мягкий / Жесткий лимиты
ulimit -Sn
ulimit -Hn
```

Просмотр лимитов **уже запущенного** процесса:

```bash
cat /proc/<PID>/limits | grep "Max open files"
```

Изменение лимитов на лету (требует прав или того же пользователя):

```bash
# Установить новые лимиты для работающего процесса
prlimit --pid <PID> --nofile=4096:8192
```

### Глубокий анализ через procfs (fd и fdinfo)

Директория `/proc/<PID>/fd/` содержит символические ссылки на все открытые ресурсы.

```bash
# Список открытых файлов
ls -l /proc/<PID>/fd/

# Подсчет количества открытых дескрипторов
ls /proc/<PID>/fd/ | wc -l
```

Файлы в `/proc/<PID>/fdinfo/<FD>` предоставляют метаданные открытого дескриптора:

```bash
cat /proc/self/fdinfo/0
# → pos:    0          (текущее смещение)
# → flags:  02100002   (флаги доступа в восьмеричном виде)
# → mnt_id: 21         (ID монтирования)
```
*Для сокетов или epoll в fdinfo может содержаться дополнительная специфическая информация.*

### Поиск владельцев ресурсов (lsof и ss)

Утилита `lsof` (List Open Files) — основной инструмент инспекции:

```bash
# Кто открыл конкретный файл
lsof /var/log/nginx/access.log

# Все сетевые дескрипторы процесса
lsof -i -p <PID>

# Альтернатива для сокетов (быстрее на нагруженных системах)
ss -tp -p
```

Подробнее см. в справочнике **[lsof — Список открытых файлов](../Diagnostics/Processes/lsof.md)**.

### Решение проблем с удерживаемыми файлами (Deleted files)

Если файл удален (`rm`), но его FD открыт, ядро не освобождает место на диске.

1.  **Найти такие файлы:**
    ```bash
    lsof +L1
    # ИЛИ
    lsof | grep deleted
    ```
2.  **Освободить место:**
    -   Перезапустить сервис (лучший вариант).
    -   Обнулить файл через дескриптор, если нельзя остановить процесс:
        ```bash
        : > /proc/<PID>/fd/<FD_NUMBER>
        ```

Подробнее см. в **[Устранение нехватки места на диске](./disk_space_troubleshooting.md)**.
