# Управление программным RAID с помощью mdadm

## Определения

### Что такое RAID?

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** — это технология, которая позволяет объединить несколько независимых физических дисков в одну логическую сущность (массив).

В работе с дисками традиционно существуют две основные проблемы, которые решает технология RAID:
*   Низкая скорость чтения/записи.
*   Выход дисков из строя и, как следствие, потеря данных.

### Типы RAID

*   **Программные массивы** создаются уже после установки операционной системы средствами программных продуктов и утилит (например, `mdadm` в Linux). Главным их недостатком является зависимость от ОС и использование ресурсов центрального процессора для управления массивом. Однако это наиболее гибкий и дешевый вариант.
*   **Аппаратные RAID-контроллеры** создают дисковый массив до установки операционной системы и не зависят от неё. Они представляют собой отдельную плату со своим процессором и кэш-памятью, что обеспечивает максимальную производительность. Это более дорогостоящее решение.
*   **Интегрированный RAID** — гибридное решение, где функции контроллера встроены в чипсет материнской платы.

### Что такое mdadm?

`mdadm` (multiple devices administration) — это стандартная утилита в Linux для создания и управления программными RAID-массивами.

## Основные концепции

### Уровни RAID

Существуют следующие основные уровни спецификации RAID: 0, 1, 5, 6, 10. Кроме того, существуют более сложные или комбинированные конфигурации.

#### RAID 0 - Чередование (Striping)
В системе RAID 0 данные разделяются на блоки (страйпы), которые записываются на все диски в массиве поочередно. При одновременном использовании нескольких дисков (минимум 2) это обеспечивает превосходную производительность ввода-вывода.

*   **Преимущества**:
    *   Очень высокая производительность как в операциях чтения, так и записи.
    *   Используется весь доступный объем памяти дисков.
    *   Простота в реализации.
*   **Недостатки**:
    *   **Не отказоустойчив**. Сбой одного диска ведет к потере **всех** данных в массиве.
    *   Не должен использоваться для критически важных систем.
*   **Применение**: Некритичное хранение данных, которые должны считываться/записываться с высокой скоростью (например, видеомонтаж, временные файлы).

#### RAID 1 - Зеркалирование (Mirroring)
Данные хранятся дважды: записываются как на основной диск, так и на зеркальный. В случае сбоя диска контроллер использует оставшийся рабочий диск.

*   **Преимущества**:
    *   Отличная скорость чтения и приемлемая скорость записи.
    *   Высокая отказоустойчивость: при сбое данные не нужно перестраивать, их просто копируют на новый диск.
    *   Простая и надежная технология.
*   **Недостатки**:
    *   Эффективная ёмкость составляет только половину от общей ёмкости дисков.
    *   Программные RAID 1 не всегда поддерживают "горячую" замену диска.
*   **Применение**: Критически важные хранилища (ОС, учетные системы), где требуется высокая отказоустойчивость.

#### RAID 5 - Чередование с четностью (Striping with Distributed Parity)
Требуется минимум 3 диска. Блоки данных распределяются по дискам, и на одном из дисков (распределенно) записывается контрольная сумма четности (parity). Эта сумма позволяет восстановить данные одного вышедшего из строя диска.

*   **Преимущества**:
    *   Быстрое чтение, запись несколько медленнее из-за расчета четности.
    *   Отказоустойчивость к сбою одного диска.
    *   Высокий коэффициент использования дискового пространства (N-1).
*   **Недостатки**:
    *   Длительное время восстановления (rebuild), во время которого массив уязвим ("окно уязвимости").
    *   Выход из строя второго диска во время восстановления приведет к полной потере данных.
*   **Применение**: Универсальная система для файловых серверов и серверов приложений, сочетающая ёмкость, производительность и безопасность.

#### RAID 6 - Чередование с двойной четностью (Striping with Dual Parity)
Похож на RAID 5, но данные о четности записываются на два отдельных диска. Требуется минимум 4 диска и выдерживает отказ двух дисков одновременно.

*   **Преимущества**:
    *   Очень высокая отказоустойчивость.
    *   Быстрое чтение.
*   **Недостатки**:
    *   Скорость записи ниже, чем у RAID 5, из-за расчета двойной четности.
    *   Потеря ёмкости составляет 2 диска.
    *   Длительное время восстановления.
*   **Применение**: Файловые серверы с большим количеством дисков, где требуется максимальная доступность.

#### RAID 10 (1+0) - Совмещение зеркалирования и чередования
Гибридная конфигурация: сначала данные чередуются (RAID 0), а затем полученные наборы зеркалируются (RAID 1). Требуется минимум 4 диска.

*   **Преимущества**:
    *   Очень высокая производительность чтения и записи.
    *   Высокая отказоустойчивость.
    *   Очень быстрое время восстановления.
*   **Недостатки**:
    *   Половина ёмкости хранения теряется на зеркалирование, что делает его дорогим.
*   **Применение**: Высоконагруженные базы данных, транзакционные системы, где требуется максимальная скорость и отказоустойчивость.

### RAID не заменит резервную копию!

Все уровни RAID, кроме RAID 0, обеспечивают защиту от сбоя одного или двух дисков. Однако это не отменяет необходимости в резервном копировании.

Почему RAID — это не бэкап:
*   **Множественный сбой**: RAID не спасет от скачка напряжения, пожара или наводнения.
*   **Ошибка пользователя**: Если кто-то случайно удалит данные, RAID исправно синхронизирует это удаление на всех дисках. Только бэкап позволит восстановить файлы.
*   **Логические повреждения**: RAID защищает от физического отказа диска, но не от логического повреждения данных (вирус, ошибка приложения). Поврежденные данные будут реплицированы на все диски массива.
*   **Защита от кражи**: Резервные копии можно хранить в другом физическом месте.

## Практические сценарии

### Полный практический цикл управления RAID 1 (зеркало)

Рассмотрим на примере создания, управления сбоями и удаления массива `/dev/md0` из двух дисков: `/dev/sdb` и `/dev/sdc`.

Существует два основных подхода к созданию массива: использование разделов диска или целых дисков.

#### Способ 1: Использование разделов диска (рекомендуется)

Этот метод более гибкий, так как позволяет использовать диски не полностью под RAID, оставляя место для других разделов (например, системного загрузчика).

**1. Подготовка дисков**

Для каждого диска, который будет участвовать в массиве, нужно создать раздел и пометить его для использования в RAID.

```bash
# Запускаем parted для первого диска
sudo parted /dev/sdb

# (parted) Создаем таблицу разделов GPT
mklabel gpt

# (parted) Создаем раздел на весь диск
mkpart primary 0% 100%

# (parted) Включаем флаг 'raid' для этого раздела. Это меняет тип раздела на 'fd00' (Linux RAID).
set 1 raid on

# (parted) Выходим
quit
```
Повторите те же действия для `/dev/sdc`. Убедитесь, что на разделах нет старых метаданных RAID. Если суперблок найден, его нужно затереть:
```bash
# Проверяем наличие метаданных
sudo mdadm --examine /dev/sdb1

# Если найдено, затираем
sudo mdadm --zero-superblock /dev/sdb1
```

**2. Создание массива**
```bash
# /dev/md0 — имя будущего массива
# --level=1 — уровень RAID (зеркало)
# --raid-devices=2 — количество устройств в массиве
# /dev/sdb1 и /dev/sdc1 — разделы-участники
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

#### Способ 2: Использование целых дисков (проще)

Этот метод проще, если вы выделяете диски целиком под массив. Нет необходимости создавать разделы.

**1. Подготовка дисков**

Убедитесь, что на дисках нет важных данных и старых метаданных RAID.
```bash
# Проверяем наличие метаданных на диске /dev/sdb
sudo mdadm --examine /dev/sdb

# Если найдено, затираем (ВНИМАНИЕ: это сотрет данные!)
sudo mdadm --zero-superblock /dev/sdb
```
Повторите для `/dev/sdc`.

**2. Создание массива**
```bash
# Команда аналогична, но мы указываем имена целых дисков
sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc
```
Утилита запросит подтверждение, так как использование целых дисков является менее стандартной практикой, чем использование разделов.
```
mdadm: Note: this array has metadata at the start and
    may not be suitable for a boot device.  If you have
    a separate boot partition, then this is likely safe.  If you
    are not sure, then you should probably create differing
    partitions on the drives and use them for a boot device.
Continue creating array? y
```
Введите `y` и нажмите Enter. Опция `--verbose` предоставит дополнительную информацию о процессе создания.

После выполнения команды начнется процесс синхронизации (resync), за которым можно следить через `watch cat /proc/mdstat`.

#### 3. Сохранение конфигурации и обновление ядра

Чтобы массив автоматически собирался при загрузке, его конфигурацию нужно сохранить. Этот шаг **критически важен**.

```bash
# Сканируем существующие массивы и добавляем их в файл конфигурации
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf

# Обновляем initramfs, чтобы ядро знало о конфигурации массива при загрузке
sudo update-initramfs -u
```

#### 4. Создание ФС и постоянное монтирование

**1. Создание файловой системы**
```bash
# Создаем файловую систему ext4 на нашем новом массиве
sudo mkfs.ext4 /dev/md0
```

**2. Монтирование и добавление в /etc/fstab**

Чтобы массив автоматически монтировался при каждой загрузке системы, его нужно добавить в файл [`/etc/fstab`](../mounting.md#структура-и-синтаксис-файла-etcfstab).

1.  Создайте директорию для монтирования: `sudo mkdir /mnt/raid1`
2.  Определите [UUID массива](../mounting.md#структура-и-синтаксис-файла-etcfstab) (например, `blkid | grep 'md0'`).
3.  Добавьте соответствующую запись в `/etc/fstab`. Пример: `UUID=ваш_uuid /mnt/raid1 ext4 defaults 0 0`
4.  Обновите конфигурацию systemd и [проверьте монтирование](../mounting.md#дополнительная-информация):
    ```bash
    sudo systemctl daemon-reload
    sudo mount -a
    ```
Теперь массив будет монтироваться в `/mnt/raid1` автоматически.

**Дополнительный трюк:** если устройство прописано в `/etc/fstab`, его можно монтировать, указывая только имя устройства или точку монтирования.
```bash
sudo umount /dev/md0
# Эта команда сработает, так как система знает из fstab, куда его монтировать
sudo mount /dev/md0
```

#### 5. Мониторинг и управление сбоями

*   **"Горячий" сбой и восстановление**:
    1.  **Определение сбойного диска**:
        *   Проверить статус массива: `cat /proc/mdstat` (искать `_` вместо `U`)
        *   Детальный статус: `sudo mdadm --detail /dev/md0` (искать `faulty` или `failed` в состоянии устройства).
    2.  **Пометка диска как сбойного**: Если диск не помечен автоматически, сделайте это вручную.
        ```bash
        sudo mdadm /dev/md0 --fail /dev/sdb1 # Замените /dev/sdb1 на имя сбойного диска
        ```
        Массив перейдет в деградированный режим (`degraded mode`), но останется доступным.
    3.  **Удаление сбойного диска**:
        ```bash
        sudo mdadm /dev/md0 --remove /dev/sdb1 # Замените /dev/sdb1 на имя сбойного диска
        ```
    4.  **Добавление нового диска**:
        *   Подключите новый физический диск или раздел.
        *   Убедитесь, что на новом диске нет старых метаданных RAID: `sudo mdadm --examine /dev/sdd1` (если найдены, затрите: `sudo mdadm --zero-superblock /dev/sdd1`).
        ```bash
        sudo mdadm /dev/md0 --add /dev/sdd1 # Замените /dev/sdd1 на имя нового диска
        ```
        Начнется процесс восстановления (rebuild). Отслеживать прогресс можно с помощью `watch cat /proc/mdstat`.

*   **"Холодный" сбой и восстановление**:
    Если система загрузилась в режим обслуживания (`maintenance mode`) с неактивным массивом:
    1.  **Остановка массива**: `mdadm --stop /dev/md0`.
    2.  **Принудительная сборка**: `mdadm --assemble --run /dev/md0 /dev/sdc1` (указываем живой диск).
    3.  **Перезагрузка**: Убедитесь, что массив активен, и перезагрузите систему. Затем замените диск в штатном режиме.


### Полный практический цикл управления RAID 5

Рассмотрим на примере создания, расширения и управления массивом `/dev/md0` из дисков `/dev/vdb`, `/dev/vdc`, `/dev/vdd`.

#### 1. Создание массива
Предполагается, что диски уже подготовлены.
```bash
sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 /dev/vdb /dev/vdc /dev/vdd
```
Далее сохраняем конфигурацию и обновляем `initramfs`, как в примере с RAID 1.

#### 2. Управление сбоями
1.  **Имитация сбоя**: `sudo mdadm /dev/md0 --fail /dev/vdb`.
2.  **Удаление сбойного диска**: `sudo mdadm /dev/md0 --remove /dev/vdb`.
3.  **Добавление нового диска** (например, `/dev/vde`): `sudo mdadm /dev/md0 --add /dev/vde`. Начнется `rebuild`.

#### 3. Расширение массива (Grow)
`mdadm` позволяет добавлять диски в существующий RAID 5 "на лету".
1.  **Добавление нового диска в массив**: Диск сначала будет добавлен как запасной (`spare`).
    ```bash
    sudo mdadm /dev/md0 --add /dev/vdb
    ```
2.  **Запуск процесса расширения**: Увеличиваем количество рабочих дисков в массиве.
    ```bash
    # --grow — команда для изменения размера
    # --raid-devices=4 — новое количество дисков
    sudo mdadm --grow /dev/md0 --raid-devices=4
    ```
    Начнется длительный процесс `reshape` (перераспределение данных).
3.  **Изменение размера файловой системы**: После `reshape` нужно расширить саму ФС.
    ```bash
    sudo resize2fs /dev/md0
    ```
4.  **Обновление конфигурации**: Снова сохраните конфигурацию и обновите `initramfs`.
    ```bash
    sudo mdadm --detail --scan | sudo tee /etc/mdadm/mdadm.conf
    sudo update-initramfs -u
    ```

### Полное удаление RAID-массива

1.  **Отмонтировать файловую систему**: `sudo umount /dev/md0` и удалить запись из `/etc/fstab`.
2.  **Остановить массив**: `sudo mdadm --stop /dev/md0`.
3.  **Затереть суперблоки**: **Важнейший шаг**, удаляющий метаданные RAID с дисков.
    ```bash
    sudo mdadm --zero-superblock /dev/sdb1
    sudo mdadm --zero-superblock /dev/sdc1
    # ... и так далее для всех дисков
    ```
4.  **Удалить конфигурацию**: Удалите строку из `/etc/mdadm/mdadm.conf` и обновите `initramfs`.

## Дополнительная информация

Для мониторинга состояния RAID-массивов в реальном времени удобно использовать:
```bash
watch cat /proc/mdstat
```
В выводе для здорового RAID 1 вы увидите `[UU]`, для RAID 5 с тремя дисками — `[UUU]`. Символ `_` (например, `[_U]`) означает сбойный диск.

Для получения детальной информации о конкретном массиве:
```bash
sudo mdadm --detail /dev/md0
```
Здесь виден статус массива (`State : active`, `clean`, `degraded`), его участников и процесс восстановления.
