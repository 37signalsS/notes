# Управление программным RAID с помощью mdadm

`mdadm` (multiple devices administration) — это стандартная утилита в Linux для создания и управления программными RAID-массивами.

## Что такое RAID?

**RAID (Redundant Array of Independent Disks / Избыточный массив независимых дисков)** - это технология, которая позволяет объединить несколько независимых физических дисков в одну логическую сущность (массив).

В работе с дисками традиционно существуют две основные проблемы, которые решает технология RAID:
*   Низкая скорость чтения/записи.
*   Выход дисков из строя и, как следствие, потеря данных.

Существуют аппаратные и программные RAID-массивы:
*   **Программные массивы** создаются уже после установки операционной системы средствами программных продуктов и утилит (например, `mdadm` в Linux). Главным их недостатком является зависимость от ОС и использование ресурсов центрального процессора для управления массивом. Однако это наиболее гибкий и дешевый вариант.
*   **Аппаратные RAID-контроллеры** создают дисковый массив до установки операционной системы и не зависят от неё. Они представляют собой отдельную плату со своим процессором и кэш-памятью, что обеспечивает максимальную производительность. Это более дорогостоящее решение.
*   **Интегрированный RAID** — гибридное решение, где функции контроллера встроены в чипсет материнской платы.

## Уровни RAID

Существуют следующие основные уровни спецификации RAID: 0, 1, 5, 6, 10. Кроме того, существуют более сложные или комбинированные конфигурации, такие как RAID 01, 10, 50, 05, 60, 06, а также менее распространенные уровни 2, 3, 4 и 7.

### RAID 0 - Чередование (Striping)

В системе RAID 0 данные разделяются на блоки (страйпы), которые записываются на все диски в массиве поочередно. При одновременном использовании нескольких дисков (минимум 2) это обеспечивает превосходную производительность ввода-вывода. Скорость записи и чтения может вырасти кратно числу дисков, поскольку данные передаются контроллерам дисков одновременно.

**Преимущества:**
*   RAID 0 обеспечивает очень высокую производительность как в операциях чтения, так и записи, так как нет накладных расходов, связанных с контролем четности.
*   Используется весь доступный объем памяти дисков, накладных расходов на избыточность нет.
*   Технология проста в реализации.

**Недостатки:**
*   RAID 0 **не отказоустойчив**.
*   В случае сбоя всего одного диска все данные в массиве RAID 0 будут потеряны.
*   Не должен использоваться для критически важных систем.
*   Минимальное количество дисков: 2.

**Идеальное применение:**
RAID 0 идеально подходит для некритического хранения данных, которые должны считываться/записываться с высокой скоростью, например, для ретуши изображений, видеомонтажа или временных файлов больших объемов.

### RAID 1 - Зеркалирование (Mirroring)

Данные хранятся дважды: записываются как на основной диск (или набор дисков), так и на зеркальный диск (или набор дисков). В случае сбоя диска контроллер использует оставшийся рабочий диск для продолжения работы и восстановления данных.

**Преимущества:**
*   RAID 1 предлагает отличную скорость чтения (может быть выше, чем у одного диска, за счет чтения с обоих зеркал) и скорость записи, сопоставимую с одиночным диском.
*   В случае сбоя диска данные не нужно перестраивать; их просто нужно скопировать на новый диск при замене.
*   RAID 1 - очень простая и надежная технология.
*   Минимальное количество дисков: 2.

**Недостатки:**
*   Основным недостатком является то, что эффективная емкость хранилища составляет только половину от общей емкости дисков, поскольку все данные записываются дважды.
*   Программные решения RAID 1 не всегда допускают горячую замену неисправного диска. Это означает, что неисправный диск можно заменить только после выключения компьютера, что может быть неприемлемо для серверов. Аппаратные контроллеры обычно поддерживают горячую замену.

**Идеальное применение:**
RAID 1 идеально подходит для критически важных хранилищ, например, для учетных систем, операционных систем или небольших серверов, где будут использоваться только два диска с данными, но требуется высокая отказоустойчивость.

### RAID 5 - Чередование с четностью (Striping with Distributed Parity)

RAID 5 является одним из наиболее распространенных безопасных уровней RAID. Требуется минимум 3 диска (до 16). Блоки данных распределяются по дискам, и на одном из дисков (распределенно, а не фиксировано) записывается контрольная сумма четности (parity) всех данных блока. Используя данные контроля четности, массив может пересчитать данные одного вышедшего из строя диска.

**Преимущества:**
*   Транзакции чтения данных очень быстрые, в то время как транзакции записи данных несколько медленнее (из-за необходимости расчета и записи четности).
*   В случае сбоя одного диска у вас по-прежнему есть доступ ко всем данным. Массив работает в деградированном режиме, пока неисправный диск заменяется, а контроллер восстанавливает данные на новом диске.
*   Высокий коэффициент использования дискового пространства: N-1 дисков для данных, 1 диск для четности.
*   Минимальное количество дисков: 3.

**Недостатки:**
*   Отказы дисков влияют на производительность, хотя это все еще допустимо.
*   Это сложная технология. Время восстановления (rebuild) после сбоя диска может быть очень долгим (день и более для больших дисков), в зависимости от нагрузки на массив и скорости контроллера.
*   Если другой диск выйдет из строя в процессе восстановления, данные будут потеряны навсегда (т.н. "окно уязвимости"). При этом нагрузка на каждый из оставшихся дисков возрастает, что потенциально может привести к лавинообразному выходу из строя последующих дисков.

**Идеальное применение:**
RAID 5 — это хорошая универсальная система, которая сочетает в себе эффективное хранилище с превосходной безопасностью (отказ одного диска) и достойной производительностью. Он идеально подходит для файловых серверов и серверов приложений с ограниченным количеством дисков с данными.

### RAID 6 - Чередование с двойной четностью (Striping with Dual Parity)

RAID 6 похож на RAID 5, но данные о четности записываются на два отдельных диска. Это означает, что для него требуется минимум 4 диска, и он может выдержать отказ двух дисков одновременно без потери данных. Это значительно повышает надежность по сравнению с RAID 5, особенно при использовании больших дисков, где время восстановления очень велико.

**Преимущества:**
*   Как и в RAID 5, операции чтения данных выполняются очень быстро.
*   Высокая отказоустойчивость: если два диска выйдут из строя, у вас все равно будет доступ ко всем данным, даже если вышедшие из строя диски заменяются. Таким образом, RAID 6 значительно более безопасен, чем RAID 5.
*   Минимальное количество дисков: 4.

**Недостатки:**
*   Операции записи данных выполняются медленнее RAID 5 из-за дополнительных данных о четности, которые необходимо рассчитать и записать (производительность записи может быть на 20% ниже).
*   Отказы дисков влияют на пропускную способность, хотя это все еще допустимо.
*   Это более сложная технология. Восстановление массива, в котором вышел из строя один диск, может занять много времени.
*   Потеря ёмкости составляет 2 диска (вместо одного, как в RAID 5).

**Идеальное применение:**
RAID 6 — это очень надежная универсальная система, которая сочетает в себе эффективное хранилище с превосходной безопасностью (отказ до двух дисков) и достойной производительностью. Это предпочтительнее, чем RAID 5, на файловых серверах и серверах приложений, которые используют много больших дисков для хранения данных, или где требуется максимальная доступность.

### RAID 10 (1+0) - Совмещение зеркалирования и чередования (Mirror of Stripes)

RAID 10 представляет собой вложенную (гибридную) конфигурацию, которая объединяет преимущества (и недостатки) RAID 0 и RAID 1. Сначала данные чередуются между группами дисков (по принципу RAID 0), а затем каждая такая группа зеркалируется (по принципу RAID 1).

**Преимущества:**
*   Очень высокая производительность чтения/записи (за счет чередования).
*   Высокая отказоустойчивость (за счет зеркалирования). Массив может пережить отказ одного диска в каждой зеркальной паре.
*   Если что-то идет не так с одним из дисков, время восстановления очень быстрое, поскольку все, что нужно, — это скопировать все данные с выжившего зеркала на новый диск (может занять всего 30 минут для дисков емкостью 1 ТБ).
*   Минимальное количество дисков: 4 (должно быть четным).

**Недостатки:**
*   Половина емкости хранения уходит на зеркалирование (как в RAID 1), что делает его дорогим способом обеспечения избыточности по сравнению с RAID 5 или RAID 6.
*   Менее эффективное использование пространства.

**Идеальное применение:**
RAID 10 идеально подходит для высоконагруженных баз данных, транзакционных систем и серверов, где требуется как максимальная скорость, так и очень высокая отказоустойчивость, а стоимость хранения не является основным ограничивающим фактором.

## RAID не заменит резервную копию!

Все уровни RAID, кроме RAID 0, обеспечивают защиту от сбоя одного или двух дисков. Система RAID 6 продолжит работу даже при выходе из строя одновременно 2 дисков. Однако для полной безопасности вам все равно необходимо выполнять регулярное резервное копирование данных из системы RAID.

Почему RAID — это не бэкап:
*   **Множественный сбой:** Резервная копия пригодится, если все диски выйдут из строя одновременно из-за скачка напряжения, пожара, наводнения или другого масштабного системного сбоя.
*   **Защита от кражи:** Резервные копии могут храниться вне серверной комнаты или ЦОД, в другом физическом месте, обеспечивая защиту от кражи всей системы хранения.
*   **Ошибка пользователя:** Наиболее важной причиной резервного копирования данных нескольких поколений является ошибка пользователя. Если кто-то случайно удаляет важные данные, и это остается незамеченным в течение нескольких часов, дней или недель, хороший набор резервных копий гарантирует, что вы все равно сможете восстановить эти файлы.
*   **Логические повреждения:** RAID защищает от физического отказа диска, но не от логического повреждения данных (например, из-за вируса или ошибки приложения). Поврежденные данные будут реплицированы или записаны на все диски массива. Резервная копия позволяет откатиться к состоянию до повреждения.



## Полный практический цикл управления RAID 1 (зеркало)

Рассмотрим на примере создания, управления сбоями и удаления массива `/dev/md0` из двух дисков: `/dev/sdb` и `/dev/sdc`.

### 1. Подготовка дисков

Для каждого диска, который будет участвовать в массиве, нужно создать раздел и пометить его для использования в RAID.

```bash
# Запускаем parted для первого диска
sudo parted /dev/sdb

# (parted) Создаем таблицу разделов GPT
mklabel gpt

# (parted) Создаем раздел на весь диск
mkpart primary 0% 100%

# (parted) Включаем флаг 'raid' для этого раздела
set 1 raid on

# (parted) Выходим
quit
```
Повторите те же действия для второго диска (`/dev/sdc`). Убедитесь, что на разделах нет старых метаданных RAID: `sudo mdadm --examine /dev/sdb1`. Если суперблок найден, его нужно затереть: `sudo mdadm --zero-superblock /dev/sdb1`.

### 2. Создание массива

1.  **Мониторинг в реальном времени (в отдельном терминале):**
    ```bash
    watch cat /proc/mdstat
    ```
    Это позволит наблюдать за состоянием RAID-массивов вживую.

2.  **Создание массива:**
    ```bash
    # /dev/md0 — имя будущего массива
    # --level=1 — уровень RAID (зеркало)
    # --raid-devices=2 — количество устройств в массиве
    # /dev/sdb1 и /dev/sdc1 — разделы-участники
    sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
    ```
    После выполнения команды в окне с `watch` начнется процесс синхронизации (resync).

### 3. Сохранение конфигурации и обновление ядра

1.  **Сохранение конфигурации массива:**
    Чтобы массив автоматически собирался при загрузке, его конфигурацию нужно сохранить в файл `/etc/mdadm/mdadm.conf`.
    ```bash
    # Эта команда просканирует существующие массивы и добавит их в файл конфигурации
    sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

2.  **Обновление initramfs:**
    Поскольку RAID-массив может быть необходим на ранних этапах загрузки, нужно обновить `initramfs`, чтобы ядро знало о конфигурации массива.
    ```bash
    sudo update-initramfs -u
    ```

### 4. Создание ФС и монтирование

1.  **Создание файловой системы** на массиве:
    ```bash
    sudo mkfs.ext4 /dev/md0
    ```

2.  **Монтирование и добавление в `/etc/fstab`** для автозагрузки:
    ```bash
    sudo mkdir /mnt/raid1
    sudo mount /dev/md0 /mnt/raid1
    # ...затем редактируем /etc/fstab, используя UUID массива (sudo blkid /dev/md0)
    ```

### 5. Мониторинг и управление сбоями

-   **Детальная информация:**
    ```bash
    sudo mdadm --detail /dev/md0
    ```
    Здесь виден статус массива (`State : active`), его участников (`active sync`) и процесс восстановления.

-   **Краткая информация в реальном времени:**
    ```bash
    watch cat /proc/mdstat
    ```
    В выводе `mdstat` для здорового RAID 1 вы увидите `[UU]`, где `U` означает, что диск активен (Up).

#### Сценарий 1: "Горячий" сбой и восстановление

1.  **Имитация сбоя**: Физически отключаем один из дисков или помечаем его как сбойный.
    ```bash
    sudo mdadm /dev/md0 --fail /dev/sdb1
    ```
    `cat /proc/mdstat` покажет статус `[_U]` или `[U_]`. Массив работает в **деградировавшем режиме (degraded mode)**. Данные по-прежнему доступны.

2.  **Удаление сбойного диска** из массива:
    ```bash
    sudo mdadm /dev/md0 --remove /dev/sdb1
    ```

3.  **Добавление нового/исправленного диска**:
    После подключения нового диска и его подготовки (шаг 1), добавляем его в массив.
    ```bash
    sudo mdadm /dev/md0 --add /dev/sdb1
    ```
    Начнется процесс восстановления (rebuild), за которым можно следить через `cat /proc/mdstat`.

#### Сценарий 2: "Холодный" сбой и восстановление из Maintenance Mode

Если система была выключена, один из дисков изъят, а потом система включена, `mdadm` может не собрать массив автоматически, и система загрузится в **режим обслуживания (maintenance mode)**.

1.  **Остановка массива**: В режиме обслуживания остановите неактивный массив.
    ```bash
    mdadm --stop /dev/md0
    ```

2.  **Принудительная сборка (Force Assemble)**: Соберите массив из оставшихся "живых" дисков.
    ```bash
    # --run заставляет массив запуститься, даже если не все диски на месте
    mdadm --assemble --run /dev/md0 /dev/sdc1
    ```

3.  **Проверка и перезагрузка**: Убедитесь, что массив активен (`cat /proc/mdstat`), смонтируйте его вручную, если нужно, и перезагрузите систему (`reboot`). После этого можно в штатном режиме заменить сбойный диск, как в Сценарии 1.

## Полный практический цикл управления RAID 5

Рассмотрим на примере создания, управления сбоями и расширения массива `/dev/md0`, собранного из трех дисков: `/dev/vdb`, `/dev/vdc`, `/dev/vdd`. Диск `/dev/vde` будет использоваться как запасной для имитации замены.

### 1. Создание массива

Предполагается, что диски уже подготовлены (созданы разделы с типом `linux_raid_autodetect`).

1.  **Создание массива RAID 5:**
    ```bash
    # --create /dev/md0 — имя будущего массива
    # --verbose — подробный вывод
    # --level=5 — уровень RAID
    # --raid-devices=3 — количество устройств в массиве
    sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 /dev/vdb /dev/vdc /dev/vdd
    ```

2.  **Мониторинг процесса создания:**
    Сразу после создания начнется процесс синхронизации (rebuild). За ним можно наблюдать в реальном времени.
    ```bash
    watch cat /proc/mdstat
    ```
    Вывод будет выглядеть примерно так, с указанием прогресса:
    ```
    md0 : active raid5 vdd[2] vdc[1] vdb[0]
          10475520 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/3] [UUU]
          [=>...................]  resync =  5.0% (524288/10475520) finish=1.5min speed=104857K/sec
    ```

### 2. Сохранение конфигурации, создание ФС и монтирование

1.  **Сохранение конфигурации массива:**
    Чтобы массив автоматически собирался при загрузке, его конфигурацию нужно сохранить в `/etc/mdadm/mdadm.conf`.
    ```bash
    # Сканируем массив и добавляем его в файл конфигурации
    sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

2.  **Обновление initramfs:**
    Это необходимо, чтобы ядро знало о конфигурации массива на ранних этапах загрузки.
    ```bash
    sudo update-initramfs -u
    ```

3.  **Создание файловой системы:**
    ```bash
    sudo mkfs.ext4 /dev/md0
    ```

4.  **Монтирование и добавление в `/etc/fstab`:**
    ```bash
    sudo mkdir /mnt/raid5
    sudo mount /dev/md0 /mnt/raid5
    
    # Получаем UUID для добавления в fstab
    sudo blkid /dev/md0
    
    # Добавляем строку в /etc/fstab:
    # UUID=<...uuid_from_blkid...> /mnt/raid5 ext4 defaults 0 2
    ```

### 3. Мониторинг и управление сбоями

-   **Детальная информация:**
    ```bash
    sudo mdadm --detail /dev/md0
    ```
    Вывод покажет состояние (`State : clean`), количество активных и рабочих дисков.

-   **Имитация сбоя диска:**
    Пометим один из дисков как сбойный.
    ```bash
    sudo mdadm /dev/md0 --fail /dev/vdb
    ```
    `cat /proc/mdstat` покажет массив в деградировавшем состоянии, например `[U_U]`. Массив продолжит работать. `mdadm --detail` покажет статус диска `faulty`.

-   **Удаление сбойного диска:**
    ```bash
    sudo mdadm /dev/md0 --remove /dev/vdb
    ```

-   **Добавление нового диска:**
    Добавляем новый (или "отремонтированный") диск в массив. В нашем случае это `/dev/vde`.
    ```bash
    sudo mdadm /dev/md0 --add /dev/vde
    ```
    Сразу после добавления начнется процесс восстановления (rebuild), за которым можно следить через `cat /proc/mdstat`. По завершении массив вернется в состояние `clean`.

### 4. Расширение массива (Grow)

`mdadm` позволяет добавлять диски в существующий RAID 5 массив "на лету".

1.  **Добавление нового диска в массив:**
    Допустим, мы хотим добавить диск `/dev/vdb` (который ранее был "сбойным", а теперь "исправлен") в массив, чтобы увеличить его объем.
    ```bash
    sudo mdadm /dev/md0 --add /dev/vdb
    ```
    Сначала диск будет добавлен как запасной (`spare`).

2.  **Запуск процесса расширения:**
    Указываем `mdadm`, что нужно изменить количество дисков в массиве с 3 до 4.
    ```bash
    # --grow — команда для изменения размера
    # --raid-devices=4 — новое количество дисков
    sudo mdadm --grow /dev/md0 --raid-devices=4
    ```
    Начнется длительный процесс `reshape`, во время которого данные будут перераспределены по всем четырем дискам. За прогрессом можно следить через `cat /proc/mdstat`.

3.  **Изменение размера файловой системы:**
    После завершения `reshape` сам массив станет больше, но файловая система на нем останется прежнего размера. Ее нужно расширить.
    ```bash
    # Для файловых систем ext2/3/4
    sudo resize2fs /dev/md0
    ```
    Теперь команда `df -h` покажет новый, увеличенный размер файловой системы.

4.  **Обновление конфигурации:**
    Не забудьте обновить конфигурационный файл после изменения состава массива.
    ```bash
    sudo mdadm --detail --scan | sudo tee /etc/mdadm/mdadm.conf
    sudo update-initramfs -u
    ```

## Полное удаление RAID-массива

1.  **Отмонтировать файловую систему**:
    ```bash
    sudo umount /dev/md0
    ```

2.  **Удалить запись из `/etc/fstab`**.

3.  **Остановить массив**:
    ```bash
    sudo mdadm --stop /dev/md0
    ```

4.  **Затереть суперблоки**: Это самый важный шаг. Он удаляет метаданные RAID с дисков-участников, после чего `mdadm` перестает их видеть как часть массива.
    ```bash
    # Замените на реальные диски вашего массива
    sudo mdadm --zero-superblock /dev/sdb1
    sudo mdadm --zero-superblock /dev/sdc1
    # ... и так далее для всех дисков
    ```

5.  **Удалить конфигурацию**: Удалите соответствующую строку из `/etc/mdadm/mdadm.conf`.

6.  **Обновить `initramfs`**:
    ```bash
    sudo update-initramfs -u
    ```
Теперь бывшие диски-участники свободны и могут использоваться для других целей.
