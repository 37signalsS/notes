# LVM (Logical Volume Manager)

LVM (Logical Volume Manager) — это система управления логическими томами в Linux, которая позволяет гибко управлять дисковым пространством. Она абстрагируется от физических дисков, позволяя объединять их в единое пространство, а затем создавать, изменять размер и удалять логические разделы без остановки системы. LVM решает ограничения традиционного разбиения дисков, такие как невозможность легко изменять размеры разделов или объединять пространство с разных физических дисков в единый логический том.

## 1. Определения и основные концепции

### LVM и Device Mapper

Важно понимать, что LVM не является самостоятельным модулем ядра. Вместо этого, LVM — это набор пользовательских утилит (`pvcreate`, `vgcreate`, `lvcreate` и др.), которые работают поверх фреймворка **Device Mapper** в ядре Linux.

**Device Mapper** — это универсальный слой ядра, который предоставляет обобщенную инфраструктуру для создания виртуальных блочных устройств и отображения (mapping) их секторов на другие блочные устройства.

-   **Device Mapper (ядро):** Предоставляет низкоуровневый механизм для создания "логических" устройств.
-   **LVM (пользовательское пространство):** Предоставляет высокоуровневые инструменты и политику для удобного управления дисковым пространством (PV, VG, LV).

Проще говоря, **LVM — это удобный интерфейс к Device Mapper**. Помимо LVM, Device Mapper также является основой для других технологий, таких как шифрование дисков (`dm-crypt`/LUKS) и программный RAID (`mdadm`).

### Ключевые абстракции: PV, VG, LV
LVM вводит три уровня абстракции:

1.  **Physical Volume (PV) — Физический том**
    -   Это физический диск (`/dev/sdb`) или его раздел (`/dev/sdb1`), инициализированный для использования в LVM. Это базовый строительный блок.

2.  **Volume Group (VG) — Группа томов**
    -   Это "пул" дискового пространства, который объединяет один или несколько физических томов (PV) в единое целое.

3.  **Logical Volume (LV) — Логический том**
    -   Это аналог обычного раздела диска, который "нарезается" из пространства группы томов (VG). Именно логический том форматируется в файловую систему (ext4, xfs) и монтируется в каталог.

### Базовые единицы: Экстенты (PE и LE)
В основе LVM лежат экстенты — минимальные непрерывные блоки данных, которыми оперирует LVM.

-   **PE (Physical Extent) — Физический экстент:** Каждая группа томов (VG) делится на физические экстенты одинакового размера. По умолчанию размер PE составляет **4 МБ**. Это самые маленькие "кирпичики" дискового пространства в VG.
-   **LE (Logical Extent) — Логический экстент:** Логические тома (LV) состоят из логических экстентов. Размер LE обычно совпадает с размером PE. LVM создает карту, которая сопоставляет логические экстенты с физическими.

Когда вы создаете логический том, LVM выделяет для него набор LE, которые, в свою очередь, указывают на конкретные PE на физических дисках. Эта абстракция позволяет легко перемещать данные и изменять размеры томов, просто обновляя карту сопоставления LE и PE.

### Преимущества и философия использования

-   **Гибкость:** Объединение дисков, динамическое изменение размера томов "на лету".
-   **Абстракция:** Логические тома не привязаны к физическому расположению на дисках.
-   **Продвинутые функции:** Снимки (Snapshots), тонкое выделение ресурсов (Thin Provisioning).
-   **Простота управления:** Вместо жесткого планирования разделов, можно выделить минимум пространства и расширять его по мере необходимости.

## 2. Практические сценарии

### 2.1. Просмотр информации

| Команда | Описание |
| :--- | :--- |
| `pvs` или `pvdisplay` | Показывает информацию о физических томах (PV). |
| `vgs` или `vgdisplay` | Показывает информацию о группах томов (VG). |
| `lvs` или `lvdisplay` | Показывает информацию о логических томах (LV). |

### 2.2. Создание и настройка

**Последовательность действий:**

1.  **Создание физического тома (PV):** Помечаем диск или раздел как готовый для LVM.
    ```bash
    pvcreate /dev/sdb1
    ```

2.  **Создание группы томов (VG):** Объединяем один или несколько PV в единый пул.
    ```bash
    # Из одного диска
    vgcreate my_vg /dev/sdb1

    # Из нескольких дисков
    vgcreate my_vg /dev/sdb1 /dev/sdc1
    ```

3.  **Создание логического тома (LV):** "Нарезаем" том из пространства VG.
    ```bash
    # Создать LV размером 10 ГБ
    lvcreate -L 10G -n my_lv my_vg

    # Создать LV, используя весь оставшийся объем VG
    lvcreate -l 100%FREE -n my_lv my_vg
    ```

4.  **Форматирование и монтирование LV:**
    Путь к тому: `/dev/<имя_VG>/<имя_LV>` или `/dev/mapper/<имя_VG>-<имя_LV>`.
    ```bash
    mkfs.ext4 /dev/my_vg/my_lv
    mkdir /data
    mount /dev/my_vg/my_lv /data
    ```

### 2.3. Изменение размеров

#### Расширение логического тома (LV)

Это безопасная операция, которую можно выполнять "на лету".

1.  **Расширение группы томов (VG):** Если в VG закончилось место, ее можно расширить, добавив новый PV.
    ```bash
    # 1. Инициализировать новый диск как PV
    pvcreate /dev/sdd1
    # 2. Добавить PV в существующую VG
    vgextend my_vg /dev/sdd1
    ```

2.  **Расширение логического тома (LV):**
    ```bash
    # Добавить 5 ГБ к существующему LV
    lvextend -L +5G /dev/my_vg/my_lv
    ```

3.  **Расширение файловой системы:** Файловая система должна "увидеть" новое пространство.
    -   Для **ext2/3/4**: `resize2fs /dev/my_vg/my_lv`
    -   Для **XFS**: `xfs_growfs /path/to/mountpoint`

    **Удобный способ:** Использовать флаг `-r`, чтобы расширить LV и ФС одной командой.
    ```bash
    lvextend -L +5G -r /dev/my_vg/my_lv
    ```

#### Уменьшение логического тома (LV)

**Внимание: Это рискованная операция. Всегда делайте резервные копии!**

-   **Ограничения ФС:**
    -   **XFS:** Не поддерживает уменьшение.
    -   **ext2/3/4:** Поддерживает, но **только в офлайн-режиме** (том должен быть отмонтирован).

-   **Безопасный подход для ext2/3/4:**
    1.  `umount /data` — **Отмонтировать том.**
    2.  `e2fsck -f /dev/my_vg/my_lv` — **Проверить ФС.**
    3.  `resize2fs /dev/my_vg/my_lv 14G` — **Уменьшить ФС** до размера *чуть меньше* целевого размера LV.
    4.  `lvreduce -L 15G /dev/my_vg/my_lv` — **Уменьшить LV.**
    5.  `resize2fs /dev/my_vg/my_lv` — **Расширить ФС**, чтобы занять все доступное место на LV.
    6.  `mount /dev/my_vg/my_lv /data` — **Смонтировать обратно.**

### 2.4. Замена физического диска в VG (pvmove)

`pvmove` позволяет заменять физический диск в группе томов без остановки работы системы.

**Процесс замены:**

1.  **Подготовьте новый диск:** Подключите, создайте раздел и инициализируйте его как PV (`pvcreate /dev/sdd1`).
2.  **Добавьте новый диск в VG:** Добавьте новый PV в ту же группу томов (`vgextend my_vg /dev/sdd1`).
3.  **Переместите данные:** Команда `pvmove` мигрирует все данные со старого диска на другие свободные диски в той же VG.
    ```bash
    # Переместить все данные с /dev/sdc1
    pvmove /dev/sdc1
    ```
    Этот процесс может занять длительное время.
4.  **Удалите старый диск из VG:**
    ```bash
    vgreduce my_vg /dev/sdc1
    ```
5.  **Очистите LVM-метки:**
    ```bash
    pvremove /dev/sdc1
    ```
    Теперь старый диск можно физически извлекать.

### 2.5. Полный жизненный цикл LVM: Комплексный пример

Этот сценарий объединяет создание, расширение и удаление LVM-структур.

1.  **Подготовка диска и создание PV:**
    -   Добавьте новый диск (`/dev/sdc`).
    -   Создайте на нем раздел (`/dev/sdc1`) и пометьте его для LVM (`parted`, `set 1 lvm on`).
    -   Инициализируйте PV:
        ```bash
        sudo pvcreate /dev/sdc1
        ```

2.  **Создание VG и LV:**
    ```bash
    sudo vgcreate my_vg /dev/sdc1
    sudo lvcreate -L 1G -n my_test_lv my_vg
    ```

3.  **Форматирование и монтирование:**
    ```bash
    sudo mkfs.ext4 /dev/my_vg/my_test_lv
    sudo mkdir /mnt/test
    sudo mount /dev/my_vg/my_test_lv /mnt/test
    ```
    *(Не забудьте про `/etc/fstab` для постоянного монтирования)*.

4.  **Расширение "на лету":**
    -   Добавьте еще один диск/раздел (`/dev/sdd1`) в VG: `pvcreate /dev/sdd1`, `vgextend my_vg /dev/sdd1`.
    -   Расширьте LV и файловую систему одной командой:
        ```bash
        sudo lvextend -L +500M -r /dev/my_vg/my_test_lv
        ```

5.  **Полное удаление (в обратном порядке):**
    ```bash
    sudo umount /mnt/test
    sudo lvremove /dev/my_vg/my_test_lv
    sudo vgreduce my_vg /dev/sdc1
    sudo vgreduce my_vg /dev/sdd1
    sudo pvremove /dev/sdc1 /dev/sdd1
    ```

## 3. Продвинутые возможности

### 3.1. Снимки (Snapshots)

Снимок — это "мгновенная" копия LV, использующая механизм **copy-on-write**. Он занимает место только для данных, изменившихся с момента его создания. Идеально для консистентных бэкапов без остановки сервисов.

-   **Создание:**
    ```bash
    # Создать снимок my_lv_snapshot для тома my_lv с буфером 1 ГБ
    lvcreate -L 1G -s -n my_lv_snapshot /dev/my_vg/my_lv
    ```
-   **Использование:** Смонтируйте снимок как обычный том для доступа к данным.
    ```bash
    mkdir /mnt/snapshot
    mount /dev/my_vg/my_lv_snapshot /mnt/snapshot
    # ... сделать бэкап с /mnt/snapshot ...
    ```
-   **Удаление:**
    ```bash
    umount /mnt/snapshot
    lvremove /dev/my_vg/my_lv_snapshot
    ```

### 3.2. Тонкие тома (Thin Provisioning)

Эта функция позволяет создавать тома с "виртуальным" размером, превышающим доступное физическое пространство. Место выделяется динамически, по мере записи данных.

-   **Компоненты:**
    1.  **Тонкий пул (Thin Pool):** Специальный LV, который служит контейнером с реальным дисковым пространством.
    2.  **Тонкий том (Thin Volume):** LV с виртуальным размером, созданный внутри пула. Не занимает места при создании.

-   **Создание:**
    1.  Создайте тонкий пул:
        ```bash
        # Создать пул my_thin_pool размером 100 ГБ
        lvcreate -L 100G --thinpool my_thin_pool my_vg
        ```
    2.  Создайте тонкий том внутри пула:
        ```bash
        # Создать том my_thin_lv с виртуальным размером 1 ТБ
        lvcreate -V 1T --thin -n my_thin_lv my_vg/my_thin_pool
        ```

-   **Мониторинг и расширение:**
    Важно следить за заполнением пула, иначе запись во все тонкие тома прекратится.
    ```bash
    # Просмотр состояния
    lvs -o+thin_pool,thin_count,thin_provisioned

    # Расширение пула
    lvextend -L +50G my_vg/my_thin_pool
    ```

### 3.3. Передача пространства между Volume Groups (обходной путь)

**Внимание: Этот метод не является стандартной практикой. Используйте с осторожностью.**

Прямого механизма переноса пространства между VG нет. Но можно временно "одолжить" пространство, создав LV в одной VG, отформатировав его как PV и добавив в другую VG.

**Сценарий:** Передать 500 МБ из `VG_SOURCE` в `VG_DEST`.

1.  В `VG_SOURCE` создаем временный LV:
    ```bash
    lvcreate -L 500M -n temp_transport_lv VG_SOURCE
    ```
2.  Инициализируем этот LV как PV:
    ```bash
    pvcreate /dev/VG_SOURCE/temp_transport_lv
    ```
3.  Добавляем этот "виртуальный" PV в `VG_DEST`:
    ```bash
    vgextend VG_DEST /dev/VG_SOURCE/temp_transport_lv
    ```
4.  Теперь в `VG_DEST` появилось 500 МБ свободного места, которое можно использовать для расширения ее томов.
5.  **Очистка (после использования):** Проведите операции в обратном порядке (`vgreduce`, `pvremove`, `lvremove`).

## 4. Системные аспекты

### 4.1. LVM и процесс загрузки Linux

Если корневая файловая система (`/`) находится на LVM-томе, для загрузки системы используется `initramfs` (initial RAM file system). `initramfs` содержит утилиты LVM, которые активируют Volume Groups и Logical Volumes, после чего ядро монтирует корневую ФС и продолжает загрузку.

**Важно:** Загрузочный каталог `/boot` не должен находиться на LVM, так как загрузчик (GRUB) должен прочитать ядро и `initramfs` до активации LVM.

### 4.2. LVM и файловые системы

-   LVM управляет блочными устройствами, но не отменяет ограничений файловых систем.
-   **Точность размеров:** Утилиты LVM и ФС могут по-разному интерпретировать `GB` (10^9) и `GiB` (2^30). Чтобы избежать ошибок при уменьшении, всегда сначала сжимайте файловую систему до размера *меньшего*, чем целевой размер LV.
-   **`partprobe`:** После изменения таблицы разделов диска (например, в `fdisk` или `parted`), используйте `partprobe`, чтобы ядро перечитало ее без перезагрузки.
