# Типы файлов в Linux

## Определения

- **Тип файла:** Свойство объекта в файловой системе, определяющее его назначение и способ взаимодействия с ним со стороны ядра и пользовательских приложений.
- **Всё есть файл:** Фундаментальная концепция Unix-подобных систем, согласно которой доступ к аппаратным устройствам, каналам связи и системным данным унифицирован через интерфейс файловой системы.

## Основные концепции

В Linux тип файла можно определить по первому символу в выводе команды `ls -l`. Каждый тип имеет свои особенности адресации и использования.

### Таблица типов файлов

| Символ | Тип файла | Английское название | Описание |
| :---: | :--- | :--- | :--- |
| **`-`** | **Обычный файл** | Regular File | Текстовые данные, бинарные исполняемые файлы, изображения и т.д. |
| **`d`** | **Каталог** | Directory | Файл, содержащий список имен других файлов и соответствующие им номера **Inode**. |
| **`l`** | **Символическая ссылка** | Symbolic Link | Указатель на другой файл или каталог по его пути. Подробнее: [Inode и ссылки](./links_inodes_dentries.md). |
| **`b`** | **Блочное устройство** | Block Device | Файл интерфейса к оборудованию, передающему данные блоками (диски). Подробнее: [Типы устройств](./device_types.md). |
| **`c`** | **Символьное устройство** | Character Device | Файл интерфейса к оборудованию с побайтовой передачей (терминалы). Подробнее: [Типы устройств](./device_types.md). |
| **`p`** | **Именованный канал** | Named Pipe (FIFO) | Канал для однонаправленной передачи данных между процессами. |
| **`s`** | **Сокет** | Socket | Интерфейс для двунаправленного межпроцессного взаимодействия (**IPC**, Inter-Process Communication). |

### Особенности специальных файлов

- **Каталоги (`d`):** Технически являются файлами, которые сопоставляют человекочитаемые имена с номерами индексных дескрипторов (Inode).
- **FIFO (`p`):** Работает по принципу **First-In, First-Out** (первым пришел — первым ушел). Данные передаются через память, не сохраняясь на диске.
- **Сокеты (`s`):** Позволяют процессам обмениваться данными локально (Unix Domain Sockets) или через сеть.

## Практические сценарии

### Определение типа файла через `ls`

Первый символ строки прав доступа указывает на тип файла:

```bash
# ls -l /bin/sh /dev/sda /etc/passwd /tmp/.X11-unix/X0
-rw-r--r-- 1 root root  # Обычный файл (-)
brw-rw---- 1 root disk  # Блочное устройство (b)
lrwxrwxrwx 1 root root  # Символическая ссылка (l)
srwxrwxrwx 1 root root  # Сокет (s)
```

### Использование утилиты `file`

Утилита `file` анализирует содержимое или метаданные файла для более точной идентификации, независимо от расширения:

```bash
file /bin/bash
# → /bin/bash: ELF 64-bit LSB pie executable, x86-64 ...

file /dev/sda
# → /dev/sda: block special (8/0)
```

### Создание специальных файлов

Обычные пользователи редко создают устройства, но могут создавать каналы:

```bash
# Создание именованного канала (FIFO)
mkfifo my_pipe
ls -l my_pipe
# prw-r--r-- 1 user group 0 ... my_pipe
```
