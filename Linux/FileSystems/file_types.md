# Типы файлов в Linux

## Определения

- **Тип файла:** Свойство объекта в файловой системе, определяющее его внутреннюю структуру, назначение и набор допустимых системных вызовов для работы с ним.
- **Всё есть файл (Everything is a file):** Фундаментальная концепция архитектуры Unix/Linux, при которой доступ к аппаратным ресурсам (диски, клавиатуры), потокам данных (pipe) и системным интерфейсам (сокеты) осуществляется через унифицированный интерфейс файловых дескрипторов и стандартные системные вызовы (`open`, `read`, `write`, `close`).
- **st_mode:** Поле в структуре `stat` (и в Inode), которое содержит информацию о типе файла и правах доступа в виде битовой маски.

## Основные концепции

В Linux существует 7 стандартных типов файлов, определенных стандартом POSIX. Тип файла является статическим свойством и записывается в Inode в момент создания объекта.

### Классификация типов файлов

| Символ | Тип файла | Системная константа | Описание |
| :---: | :--- | :--- | :--- |
| **`-`** | **Обычный файл** | `S_IFREG` | Последовательность байтов. Данные хранятся в блоках данных ФС. Сюда относятся тексты, бинарные файлы (ELF), архивы. |
| **`d`** | **Каталог** | `S_IFDIR` | Список имен файлов и соответствующих им номеров Inode. В современных ФС (ext4, XFS) реализован как B-дерево или хеш-таблица. |
| **`l`** | **Символическая ссылка** | `S_IFLNK` | Содержит путь к другому объекту. Может указывать на файл, каталог или даже на несуществующий объект. |
| **`b`** | **Блочное устройство** | `S_IFBLK` | Интерфейс к оборудованию с произвольным доступом (диски). Данные передаются блоками фиксированного размера через Buffer Cache. |
| **`c`** | **Символьное устройство** | `S_IFCHR` | Интерфейс к оборудованию с последовательным доступом (терминалы, `/dev/null`). Данные передаются байт за байтом. |
| **`p`** | **Именованный канал (FIFO)** | `S_IFIFO` | Очередь для межпроцессного взаимодействия (IPC). Данные передаются через буфер в памяти ядра, не записываясь на диск. |
| **`s`** | **Сокет** | `S_IFSOCK` | Конечная точка для двунаправленной передачи данных между процессами (локально или по сети). |

### Низкоуровневая реализация (st_mode)

Тип файла кодируется в старших 4 битах (12-15) 16-битного поля `st_mode`. Для извлечения типа используется битовая маска `S_IFMT` (0170000 в восьмеричной системе).

| Константа (C) | Восьмеричное значение | Описание |
| :--- | :--- | :--- |
| `S_IFREG` | `0100000` | Обычный файл |
| `S_IFDIR` | `0040000` | Каталог |
| `S_IFLNK` | `0120000` | Символическая ссылка |
| `S_IFBLK` | `0060000` | Блочное устройство |
| `S_IFCHR` | `0020000` | Символьное устройство |
| `S_IFIFO` | `0010000` | FIFO (Named Pipe) |
| `S_IFSOCK` | `0140000` | Сокет |

Для проверки типа в программировании на C используются макросы, например `S_ISREG(m)`, которые выполняют операцию `(m & S_IFMT) == S_IFREG`.

### Взаимодействие с Inode и структурой данных

1.  **Обычные файлы:** Inode содержит указатели на блоки данных на диске. В современных ФС (ext4) используются экстенты (extents) для оптимизации хранения больших файлов.
2.  **Каталоги:** Это файлы со специальным флагом. Ядро интерпретирует их содержимое как список структур `dirent` (имя файла + номер Inode).
3.  **Символические ссылки:**
    *   **Fast Symlinks:** Если путь короткий (обычно < 60 байт), он хранится прямо в Inode (в поле, где обычно хранятся указатели на блоки), что экономит дисковые операции.
    *   **Slow Symlinks:** Если путь длинный, он записывается в отдельный блок данных.
4.  **Устройства (b, c):** Inode не содержит указателей на блоки данных. Вместо этого в полях `i_rdev` хранятся **Major** (идентификатор драйвера) и **Minor** (номер конкретного устройства) номера.
5.  **FIFO и Сокеты:** Inode служит лишь точкой входа (anchor) в файловой системе. Реальные данные передаются через структуры в оперативной памяти ядра.

## Практические сценарии

### Идентификация и диагностика

1.  **Команда `ls -l`**: Первый символ строки разрешений (например, `drwxr-xr-x` → каталог).
2.  **Команда `stat`**: Показывает тип в текстовом виде и восьмеричный код `st_mode`.
    ```bash
    stat /dev/sda
    # → Device type: 8,0 (Major 8, Minor 0)
    # → Inode: 429 (Block special file)
    ```
3.  **Команда `file`**: Анализирует содержимое файла (Magic Numbers), что позволяет отличить JPEG от ELF внутри типа «Обычный файл».

### Поиск файлов по типу

Утилита `find` использует флаг `-type`:

```bash
# Найти все символические ссылки в /etc
sudo find /etc -type l

# Найти все сокеты в системе
sudo find / -type s 2>/dev/null

# Найти все блочные устройства (диски)
find /dev -type b
```

### Создание объектов различных типов

| Тип | Команда | Пример |
| :--- | :--- | :--- |
| **Обычный файл** | `touch`, `truncate` | `touch file.txt` |
| **Каталог** | `mkdir` | `mkdir my_dir` |
| **Символическая ссылка** | `ln -s` | `ln -s /etc/passwd link_to_pass` |
| **Жесткая ссылка** | `ln` | `ln existing_file hard_link` (Тип остается тем же) |
| **FIFO** | `mkfifo` | `mkfifo /tmp/my_pipe` |
| **Устройство** | `mknod` | `sudo mknod /dev/my_device c 10 200` (Требует root) |

## Устранение неполадок

-   **«Битые» ссылки (Dangling Links):** Символическая ссылка указывает на путь, которого не существует. Команда `ls` часто подсвечивает их красным. Проверка: `test -e link_name || echo "Broken"`.
-   **Ошибки типов в Docker:** Контейнеры по умолчанию не имеют доступа к блочным устройствам хоста. Для работы с ними (например, для мониторинга SMART) требуется флаг `--privileged` или явный проброс через `--device`.
-   **Лимит Inode:** Если в системе много мелких файлов (особенно типов `s` или `p`), могут закончиться Inode, даже если на диске есть свободное место. Проверка: `df -i`.
