# Стандарт POSIX и его роль в Linux

**POSIX (Portable Operating System Interface)** — это набор стандартов, разработанный IEEE, который определяет, как операционные системы должны выглядеть и вести себя с точки зрения программиста. Его главная цель — обеспечить **совместимость исходного кода** между различными Unix-подобными операционными системами.

**Ключевые аспекты, которые определяет POSIX:**

1.  **Интерфейс командной строки (Shell):** Стандартизирует команды (`ls`, `cp`, `grep`), синтаксис и переменные окружения.
2.  **Системные вызовы (API):** Определяет стандартный набор функций на языке C для взаимодействия с ядром (например, `open()`, `read()`, `write()`, `fork()`).
3.  **Файловая система:** Описывает базовую структуру каталогов, права доступа к файлам (rwx) и концепцию "всё есть файл".
4.  **Процессы и потоки:** Стандартизирует управление процессами, сигналами и потоками (pthreads).

**Почему это важно для Linux?**

Хотя Linux не является сертифицированной POSIX-системой "из коробки" (сертификация стоит дорого), он **в значительной степени совместим с POSIX**. Это означает, что программы, написанные с соблюдением стандартов POSIX, могут быть легко скомпилированы и запущены на Linux, macOS, BSD и других Unix-системах с минимальными изменениями или без них.

**Linux Standard Base (LSB) и Filesystem Hierarchy Standard (FHS)**

-   **LSB (Linux Standard Base):** Это более специфичный стандарт, который расширяет POSIX и направлен на обеспечение бинарной совместимости между различными дистрибутивами Linux. Он определяет такие вещи, как структура файловой системы, основные библиотеки и команды.
-   **FHS (Filesystem Hierarchy Standard):** Является частью LSB и подробно описывает, в каких каталогах должны располагаться те или иные типы файлов (например, `/bin` для исполняемых файлов, `/etc` для конфигураций). Это обеспечивает предсказуемость и порядок в системе.

### Стандартная иерархия каталогов (FHS)

-   `/bin`: Основные утилиты командной строки, необходимые для работы системы.
-   `/boot`: Файлы, необходимые для загрузки, включая ядро Linux и конфигурацию загрузчика.
-   `/dev`: Файлы устройств, представляющие аппаратные компоненты.
-   `/etc`: Файлы конфигурации системы и приложений.
-   `/home`: Домашние каталоги пользователей.
-   `/lib`: Библиотеки, необходимые утилитам из `/bin` и `/sbin`.
-   `/media`: Точки монтирования для съёмных носителей (CD, USB).
-   `/mnt`: Точка для временного монтирования файловых систем.
-   `/opt`: Пакеты стороннего программного обеспечения.
-   `/proc`: Виртуальная файловая система с информацией о процессах и ядре.
-   `/root`: Домашний каталог пользователя `root`.
-   `/sbin`: Системные исполняемые файлы, используемые для администрирования.
-   `/sys`: Виртуальная файловая система, предоставляющая интерфейс к драйверам ядра.
-   `/tmp`: Временные файлы.
-   `/usr`: Пользовательские утилиты, библиотеки и данные.
-   `/var`: Переменные данные, такие как логи, почта и базы данных.

## Определение дистрибутива Linux

Чтобы узнать, какой дистрибутив Linux используется, можно посмотреть содержимое специальных файлов в директории `/etc`.

-   **Основной способ (для современных систем):**
    ```sh
    cat /etc/os-release
    ```
    Этот файл содержит детальную информацию в формате `ключ=значение`, включая `NAME` (имя дистрибутива) и `VERSION` (версия).

-   **Альтернативные способы:**
    -   `cat /etc/lsb-release`: Используется в дистрибутивах, следующих стандарту LSB (Linux Standard Base), например, в Ubuntu.
    -   `cat /etc/redhat-release`: Для дистрибутивов на базе Red Hat (CentOS, Fedora).
    -   `cat /etc/debian_version`: Для Debian и его производных.

## Псевдофайловые системы

Это виртуальные файловые системы, которые не хранят данные на диске, а предоставляют доступ к структурам ядра и системной информации в виде файлов.

-   **procfs (`/proc`)**: Информация о процессах (`/proc/<PID>`), процессоре (`/proc/cpuinfo`), памяти (`/proc/meminfo`) и настройках ядра (`/proc/sys`).
-   **sysfs (`/sys`)**: Информация об устройствах, драйверах и их иерархии. Позволяет управлять питанием (`/sys/power`).
-   **tmpfs (`/dev/shm`, `/run`)**: Хранит файлы в оперативной памяти для сверхбыстрого доступа. Используется для разделяемой памяти и временных файлов служб.
-   **cgroupfs (`/sys/fs/cgroup`)**: Управление ресурсами (CPU, память, I/O) для групп процессов. Основа для контейнеризации (Docker, Kubernetes).

## Файловые дескрипторы

Файловый дескриптор — это целое неотрицательное число, которое ядро использует для идентификации открытого файла или другого ресурса ввода-вывода (сокет, канал).

-   `0` – `stdin` (стандартный ввод)
-   `1` – `stdout` (стандартный вывод)
-   `2` – `stderr` (стандартный вывод ошибок)

### Отслеживание утечек файловых дескрипторов

Утечка файловых дескрипторов происходит, когда процесс открывает файлы, но не закрывает их, со временем исчерпывая доступный лимит. Это может привести к ошибке "Too many open files".

-   **`lsof` (List Open Files):** Показывает все файлы, открытые процессом.
    ```bash
    # Показать все открытые файлы для процесса с указанным PID
    sudo lsof -p <PID>
    ```

-   **Просмотр через `/proc`:** Директория `/proc/<PID>/fd/` содержит символические ссылки на все файлы, открытые процессом. Подсчитав их количество, можно оценить потребление дескрипторов.
    ```bash
    # Посчитать количество открытых дескрипторов для процесса
    ls -l /proc/<PID>/fd/ | wc -l
    ```

-   **`fuser`:** Показывает, какие процессы используют указанный файл или файловую систему.

## Анализ дискового пространства

### Свободное место (`df`)

```sh
# Показать свободное место в человекочитаемом формате
df -h

# Показать использование inode (индексных дескрипторов)
df -i
```
Если `inode` используется на 100%, вы не сможете создавать новые файлы, даже если на диске есть свободное место.

### Увеличение количества inodes (Ext2/3/4)

**Проблема:** В файловых системах семейства `Ext` (Ext2, Ext3, Ext4) количество inodes (индексных дескрипторов) **фиксируется в момент форматирования раздела**. Изменить это значение на уже существующей файловой системе без её пересоздания **невозможно**. Если у вас закончились inodes, вы не сможете создавать новые файлы, даже если на диске много свободного места.

**Решение:** Единственный способ — это создать резервную копию данных, переформатировать раздел с новыми параметрами и восстановить данные.

**Резервное копирование (Критически важно!)**

Перед любыми действиями создайте полную резервную копию всех данных с нужного раздела.

```sh
# Пример копирования данных с помощью rsync
sudo rsync -avh /path/to/your/mountpoint/ /path/to/backup/
```

**Отмонтирование раздела**

```sh
sudo umount /path/to/your/mountpoint
```

**Переформатирование с нужным количеством inodes**

Используйте команду `mkfs.ext4` с одним из флагов:

*   `-i bytes-per-inode`: Задаёт соотношение байт на один inode. Чем меньше значение, тем больше будет создано inodes.
    *   Значение по умолчанию обычно `16384` (1 inode на 16 КБ).
    *   Для систем с огромным количеством мелких файлов (почта, кэш) можно поставить `4096` (1 inode на 4 КБ).
*   `-N number-of-inodes`: Прямо указывает, сколько inodes нужно создать.

**Пример (рекомендуемый способ):**

```sh
# Замените /dev/sdXN на ваш раздел
sudo mkfs.ext4 -i 4096 /dev/sdXN
```

**Монтирование и восстановление данных**

```sh
# Монтируем свежеотформатированный раздел
sudo mount /dev/sdXN /path/to/your/mountpoint

# Восстанавливаем данные из резервной копии
sudo rsync -avh /path/to/backup/ /path/to/your/mountpoint/
```
**Альтернатива:** Файловые системы, такие как **XFS** или **Btrfs**, выделяют inodes динамически, поэтому у них нет проблемы с исчерпанием их запаса. Миграция на одну из этих ФС может быть долгосрочным решением.

### Занятое место (`du`)

Команда `du` (disk usage) рекурсивно подсчитывает, сколько места на диске занимают файлы и директории.

-   `-h` (`--human-readable`): Выводить размеры в удобном для человека формате (K, M, G).
-   `-s` (`--summarize`): Показать только итоговую сумму для указанной директории, не показывая размеры вложенных файлов и папок.
-   `-d <N>` или `--max-depth=<N>`: Установить глубину рекурсии. Например, `--max-depth=1` покажет размеры всех файлов и директорий на первом уровне вложенности.
-   `-c` (`--total`): Показать итоговую сумму в конце списка.

```sh
# Узнать общий (суммарный) размер текущей директории
du -sh .

# Узнать, сколько места занимает конкретная директория, например /var/log
sudo du -sh /var/log

# Показать размеры всех директорий внутри /var на один уровень вглубь и отсортировать их по размеру, чтобы найти самые большие
sudo du -h --max-depth=1 /var | sort -rh
```

**Разница между `df` и `du`**: `df` показывает использование диска с точки зрения файловой системы (сколько всего занято на разделе), а `du` — суммарный размер конкретных файлов и директорий. Расхождения могут возникнуть, если файл был удалён, но всё ещё используется каким-либо процессом (дескриптор файла открыт). В этом случае `du` не будет учитывать этот файл, а `df` будет, так как место на диске еще не освобождено. 

### Место на диске не освободилось после удаления файлов

Иногда после удаления больших файлов (`rm file.log`) команда `df -h` показывает, что свободное место не увеличилось.

Это происходит, когда какой-либо запущенный процесс всё ещё использует этот "удалённый" файл. В файловых системах Linux удаление файла командой `rm` лишь убирает его имя (ссылку) из директории. Сами данные на диске (inode и блоки данных) остаются нетронутыми до тех пор, пока хотя бы один процесс держит этот файл открытым (имеет открытый файловый дескриптор).

Чтобы найти процесс, который удерживает удалённый файл, можно использовать `lsof` (list open files) и отфильтровать вывод по слову "deleted":

- **Способ 1:**
  ```sh
  sudo lsof | grep deleted
  ```
  Эта команда покажет список процессов и файлы, которые они держат открытыми, несмотря на удаление.

- **Способ 2:**
  ```sh
  sudo lsof +L1
  ```
  Эта команда использует встроенную функцию `lsof` для поиска файлов, у которых количество ссылок (link count) меньше 1, то есть удалённых файлов.

**Решение:**
Чтобы освободить место, нужно заставить процесс "отпустить" файл. Есть несколько способов:

1.  **Перезапустить сервис/процесс (рекомендуемый способ):**
    Если файл удерживается системной службой (например, `nginx` или `rsyslog`), самым безопасным способом будет её перезапуск.
    ```sh
    sudo systemctl restart <имя_сервиса>
    ```
    Это заставит процесс корректно завершиться и освободить все файловые дескрипторы.

2.  **Завершить процесс:**
    Если это не критичный сервис, можно просто завершить процесс, используя его PID из вывода `lsof`.
    ```sh
    kill <PID>
    ```

3.  **"Очистить" файл без перезапуска (рискованный способ):**
    В некоторых случаях, когда перезапуск сервиса нежелателен, можно очистить содержимое файла, не удаляя его. Это можно сделать, перенаправив в него пустой вывод.
    ```sh
    # > /path/to/original/file/that/was/deleted
    # Пример для лог-файла nginx, который был удалён, но удерживается процессом с PID 1234
    # Путь к файлу можно найти в выводе lsof
    sudo truncate -s 0 /proc/1234/fd/5 
    ```
    - `truncate -s 0` обрезает файл до нулевого размера, что немедленно освобождает дисковое пространство.
    - `/proc/<PID>/fd/<номер_дескриптора>` — это специальный путь, который позволяет получить доступ к файлу через открытый дескриптор процесса.

## Мониторинг нагрузки на диски

-   **`iostat`**: Статистика по вводу/выводу для устройств.
-   **`iotop`**: Показывает использование диска процессами в реальном времени (аналог `top` для I/O).
    ```sh
    sudo iotop -oP
    ```
    - `-o`: Показывать только активные процессы.
    - `-P`: Не разделять нагрузку по потокам.
-   **`pidstat`**: Отчёт по использованию ресурсов процессами, включая I/O.
    ```sh
    pidstat -dl 1
    ```

### Жёсткая ссылка (Hard Link)

Жёсткая ссылка — это не отдельный файл, а **второе имя для тех же данных на диске**. Она напрямую указывает на тот же **inode** (индексный дескриптор), что и оригинальный файл.

```bash
ln [TARGET_FILE] [LINK_NAME]
```
*   `TARGET_FILE` — существующий файл.
*   `LINK_NAME` — новое имя (ссылка) для этого файла.

Каждый файл в системе представлен inode, который хранит метаданные (права, владелец, размер) и указатели на блоки данных. Имя файла — это лишь запись в директории, которая сопоставляет имя с номером inode.
Когда вы создаете жёсткую ссылку, вы просто добавляете еще одну запись в директорию, которая указывает на тот же самый inode.

**Ключевые особенности:**
*   **Равноправие:** Все жёсткие ссылки на один inode абсолютно равноправны. Не существует "оригинала" и "ссылки".
*   **Удаление:** Файл физически удаляется с диска только тогда, когда удаляется **последняя** жёсткая ссылка на него. Это происходит потому, что в inode есть счётчик ссылок, и данные освобождаются только когда он достигает нуля.
*   **Ограничения:**
    *   **Нельзя создать для директорий:** Это сделано для предотвращения зацикливания файловой системы (например, `dir1/link_to_dir1`), что могло бы сломать многие утилиты (`find`, `ls -R`).
    *   **Только в пределах одной файловой системы:** Inode уникален только в рамках своего раздела (файловой системы). Нельзя создать жёсткую ссылку на файл, находящийся на другом диске или разделе.
*   **Проверка:** Команда `ls -li` покажет одинаковый номер inode для всех жёстких ссылок.

### Символическая ссылка (Symbolic Link / Symlink)

Символическая ссылка (или симлинк) — это **специальный файл-указатель**, который содержит **текстовый путь** к другому файлу или директории. Аналог "ярлыка" в Windows.

```bash
ln -s [TARGET] [LINK_NAME]
```
*   `-s` — обязательный флаг, указывающий, что нужно создать символическую ссылку.
*   `TARGET` — путь, на который будет указывать ссылка (файл или директория).
*   `LINK_NAME` — имя самой ссылки.
*   `-f` - (--force): "Принудительно". Если по пути уже существует какой-то файл или другая ссылка, эта опция удалит его перед созданием новой ссылки.

Симлинк имеет свой собственный, уникальный inode. Когда вы обращаетесь к нему, операционная система читает путь, записанный внутри, и перенаправляет вас к целевому файлу или директории.

**Ключевые особенности:**
*   **Указатель:** Это не копия данных, а лишь путь.
*   **"Битые" ссылки:** Если оригинальный файл или директорию удалить или переместить, символическая ссылка останется, но станет "битой" (dangling) — она будет указывать в никуда.
*   **Гибкость:**
    *   Можно создавать ссылки на **директории**.
    *   Можно создавать ссылки на файлы **в других файловых системах** (на других дисках, разделах, смонтированных сетевых папках).
    *   Путь к цели может быть **относительным** или **абсолютным**.
*   **Проверка:** `ls -l` показывает, куда указывает ссылка.

### Практическое применение

*   **Жёсткие ссылки:**
    *   **Резервное копирование:** Некоторые утилиты (например, `rsync --link-dest`) используют жёсткие ссылки для создания инкрементальных бэкапов, экономя дисковое пространство. Неизменившиеся файлы представляются жёсткими ссылками на файлы из предыдущего бэкапа.
    *   **Безопасное обновление файлов:** Можно создать новый файл, а затем атомарно заменить старый, переименовав новый файл поверх старого.

*   **Символические ссылки:**
    *   **Управление версиями ПО:** Часто используется для переключения между разными версиями программ. Например, `/usr/bin/python` может быть симлинком на `/usr/bin/python3.11`.
    *   **Удобство доступа:** Создание "ярлыков" в домашних директориях для доступа к файлам, лежащим глубоко в файловой системе.
    *   **Конфигурационные файлы:** Размещение реальных конфигов в одном месте (например, в системе контроля версий) и создание симлинков на них в тех местах, где их ожидают программы (`/etc/nginx/sites-enabled/`, `~/.config/`).

### Inode (Индексный дескриптор)

**Inode** — это ключевая структура в Unix-подобных файловых системах, которая хранит метаданные о файле или директории. Каждый файл и каталог имеет свой уникальный inode.

**Содержимое inode:**
-   **Номер inode**: Уникальный идентификатор в рамках файловой системы.
-   **UID и GID**: ID пользователя и группы-владельца.
-   **Режим**: Права доступа (rwx) и тип файла (обычный файл, директория, символическая ссылка и т.д.).
-   **Количество жёстких ссылок**: Счётчик, показывающий, сколько имён ссылается на этот inode.
-   **Размер файла**: В байтах.
-   **Временные метки**:
    -   `atime`: Время последнего доступа.
    -   `mtime`: Время последней модификации содержимого.
    -   `ctime`: Время последнего изменения метаданных (прав, владельца).
-   **Указатели на блоки данных**: Адреса блоков на диске, где хранится содержимое файла. Могут быть прямыми (указывают на блок с данными) и косвенными (указывают на блок, содержащий список других блоков).

**Важные моменты:**
-   **Имя файла не хранится в inode.** Оно находится в файле директории, в которой лежит файл.
-   **Удаление файла**: Системный вызов `unlink()` удаляет запись о файле из директории и уменьшает счётчик жёстких ссылок в inode. Данные на диске физически не затираются, а лишь помечаются как свободные, пока не будут перезаписаны.
-   **Выделение inode'ов**:
    -   В файловых системах типа **Ext4** количество inode'ов создаётся при форматировании. Если они закончатся, новые файлы создать будет нельзя, даже при наличии свободного места на диске. Проблема актуальна при наличии большого количества мелких файлов.
    -   В **XFS** и **Btrfs** используется **динамическое выделение inode'ов**. Это означает, что inode'ы создаются по мере необходимости, а не резервируются заранее. 

### Dentry (Directory Entry)

**Dentry** — это структура в памяти ядра, которая связывает имя файла с его inode. Dentry кэшируются для ускорения доступа к файлам.

### Кэширование файловой системы (Page Cache)

Поскольку **устройства ввода-вывода являются слабым местом** любой системы, Linux использует агрессивное кэширование для ускорения доступа к данным.

**Page Cache (кэш страниц)** — это основной механизм дискового кэша. Когда процесс читает файл, его страницы (куски данных) копируются с диска в оперативную память (в Page Cache). **Единожды открытый файл загружается в кэш и не удаляется оттуда, пока системе не потребуется память** для других, более важных задач. При повторном чтении данные отдаются мгновенно из памяти, минуя медленный диск.

То же самое происходит и при записи: данные сначала записываются в кэш, а ядро позже, в фоновом режиме, сбрасывает их на диск. Это объясняет, почему в выводе утилиты `free -m` колонка `buff/cache` почти всегда занята — Linux использует всю доступную память для ускорения работы.

### Суперблок (Superblock)

**Суперблок** — это структура, которая содержит метаданные о самой файловой системе. Он критически важен для её работы, поэтому в системе хранится несколько его резервных копий.

**Содержимое суперблока:**
-   Размер файловой системы и размер блока.
-   Количество свободных и занятых блоков и inode'ов.
-   Расположение таблицы inode'ов.
-   Точка монтирования и статус файловой системы.

Посмотреть информацию о суперблоке для файловой системы Ext2/3/4:
```sh
sudo dumpe2fs /dev/sda1 | grep -i superblock
```

## Монтирование директории на отдельный диск

Чтобы содержимое определённой директории (например, `/var/log` или `/home/user/data`) физически хранилось на отдельном диске, необходимо выполнить следующие шаги:

1.  **Подготовить диск**: Убедитесь, что на диске есть раздел и на нём создана файловая система (например, ext4 или xfs).
    -   Посмотреть диски и разделы: `lsblk`
    -   Создать файловую систему (если нужно): `sudo mkfs.ext4 /dev/sdb1`

2.  **Создать точку монтирования**: Это пустая директория, к которой будет "привязан" диск.
    ```sh
    sudo mkdir -p /path/to/directory
    ```

3.  **Временно смонтировать диск**: Это позволит проверить, что всё работает правильно.
    ```sh
    sudo mount /dev/sdb1 /path/to/directory
    ```
    После этого все файлы, созданные в `/path/to/directory`, будут физически записываться на диск `/dev/sdb1`.

4.  **Настроить автоматическое монтирование при загрузке**: Чтобы диск монтировался каждый раз при старте системы, нужно добавить запись в файл `/etc/fstab`.
    -   **Узнать UUID диска**: Это более надёжный способ идентификации, чем имя устройства (`/dev/sdb1`), которое может измениться.
        ```sh
        sudo blkid /dev/sdb1
        ```
    -   **Добавить запись в `/etc/fstab`**:
        ```
        # <file system> <mount point>   <type>  <options>       <dump>  <pass>
        UUID=...      /path/to/directory ext4    defaults        0       2
        ```

5.  **Перенести существующие данные (если необходимо)**:
    Если в директории уже были данные, их нужно перенести на новый диск. Это делается *до* настройки постоянного монтирования в `fstab`.
    ```sh
    # 1. Смонтировать новый диск во временную точку
    sudo mount /dev/sdb1 /mnt

    # 2. Скопировать данные со сохранением прав
    sudo rsync -av /path/to/directory/ /mnt/

    # 3. Переименовать старую директорию (для бэкапа)
    sudo mv /path/to/directory /path/to/directory.bak

    # 4. Создать пустую точку монтирования
    sudo mkdir /path/to/directory

    # 5. Размонтировать диск и смонтировать его в нужную точку
    sudo umount /mnt
    sudo mount /dev/sdb1 /path/to/directory

    # 6. Проверить, что данные на месте, и добавить запись в fstab
    ```

## Файл /etc/fstab

Файл `/etc/fstab` (file systems table) — это один из ключевых конфигурационных файлов в Linux, который содержит информацию о различных файловых системах и точках их монтирования. Система использует этот файл при загрузке для автоматического монтирования дисков, разделов и сетевых файловых систем.

Каждая строка в `/etc/fstab` представляет одну файловую систему и состоит из шести полей, разделенных пробелами или табами.

```text
<file system> <mount point>   <type>  <options>       <dump>  <pass>
```

1.  **`<file system>`**: Устройство или ресурс, который нужно смонтировать.
    *   **Рекомендуемый способ:** `UUID=<uuid>` (например, `UUID=abc-123...`). Это самый надёжный метод, так как UUID уникален и не меняется. Узнать UUID можно командой `sudo blkid`.
    *   **Альтернатива:** Путь к устройству, например, `/dev/sda1`. Менее надёжно, так как имя может измениться после перезагрузки.
    *   Для сетевых ФС здесь указывается `user@host:/path`.

2.  **`<mount point>`**: Директория в файловой системе, к которой будет "привязан" ресурс (например, `/home`, `/var/log`). Директория должна существовать.

3.  **`<type>`**: Тип файловой системы.
    *   Для дисков: `ext4`, `xfs`, `btrfs`, `vfat`.
    *   Для сетевых ФС: `nfs`, `cifs`.
    *   Для swap: `swap`.
    *   `auto`: Позволяет системе автоматически определить тип ФС.

4.  **`<options>`**: Опции монтирования, перечисляются через запятую.
    *   `defaults`: Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
    *   `rw` / `ro`: Монтировать в режиме чтение/запись или только чтение.
    *   `noatime`: Не обновлять `atime` (время последнего доступа) для файлов. Это может повысить производительность диска, так как сокращает количество операций записи.
    *   `nofail`: Не останавливать загрузку системы, если устройство не может быть смонтировано. Критически важно для съёмных дисков или сетевых ресурсов.
    *   `user`: Разрешить обычному пользователю монтировать файловую систему.

5.  **`<dump>`**: Используется утилитой `dump` для определения, нужно ли создавать резервную копию файловой системы.
    *   `0`: Не делать дамп.
    *   `1`: Делать дамп.
    *   На практике почти всегда установлено в `0`.

6.  **`<pass>`**: Определяет порядок проверки файловых систем утилитой `fsck` при загрузке.
    *   `0`: Не проверять.
    *   `1`: Устанавливается для корневой файловой системы (`/`). Она проверяется первой.
    *   `2`: Устанавливается для остальных файловых систем. Они проверяются после корневой.

После редактирования `/etc/fstab` можно проверить корректность монтирования всех записей командой:
```bash
sudo mount -a
```
Если команда выполнилась без ошибок, значит, синтаксис в файле корректен.

## Логическое восстановление данных

**Важно:** При потере данных первое, что нужно сделать, — это отмонтировать файловую систему (`umount`) или смонтировать её в режиме "только чтение" (`mount -o remount,ro`), чтобы предотвратить перезапись удалённых данных.

### Инструменты для восстановления

-   **`TestDisk`**: Мощная утилита для восстановления потерянных разделов и исправления загрузочных секторов.
-   **`PhotoRec`**: Идёт в комплекте с `TestDisk`. Восстанавливает файлы по их сигнатурам, игнорируя файловую систему. Эффективен для восстановления фотографий, документов и архивов с отформатированных носителей.

-   **Для Ext3/Ext4:**
    -   `extundelete`: Ищет удалённые файлы в журнале файловой системы.
    -   `ext4magic`: Более продвинутый инструмент для восстановления.

-   **Для XFS:**
    -   `xfs_repair`: В первую очередь, это инструмент для проверки и исправления метаданных. Возможности восстановления удалённых файлов ограничены.

-   **Для Btrfs:**
    -   `btrfs restore`: Специализированная утилита для извлечения файлов с повреждённой или немонтируемой файловой системы Btrfs.

## Проверка и восстановление целостности ФС (`fsck`)

`fsck` (File System Check) — это стандартная утилита для проверки и исправления ошибок в файловых системах Linux.

**Ключевые моменты:**
-   **Запуск на размонтированном разделе:** `fsck` всегда должна запускаться на **размонтированной** файловой системе, чтобы избежать повреждения данных.
-   **Автоматическая проверка:** Система обычно автоматически запускает `fsck` при загрузке, если файловая система была помечена как "грязная" (например, после некорректного выключения).

**Использование:**
```bash
# Принудительно проверить файловую систему на разделе /dev/sdXN
sudo fsck -f /dev/sdXN
```

**Особенности для XFS:**
Файловая система XFS имеет собственную утилиту для восстановления — `xfs_repair`. Стандартный `fsck.xfs` является лишь оберткой и не выполняет реального исправления ошибок.
```bash
# Для проверки и восстановления XFS
sudo xfs_repair /dev/sdXN
```

## Мониторинг событий ФС (`inotify`)

`inotify` — это подсистема ядра Linux, которая позволяет приложениям отслеживать события в файловой системе в реальном времени (например, создание, удаление, изменение файлов).

**Утилиты для работы с `inotify`:**
-   **`inotifywait`**: Ожидает определённого события и завершает работу. Удобно для использования в скриптах.
    ```bash
    # Ждать любого события в директории /tmp и выйти
    inotifywait /tmp
    ```
-   **`inotifywatch`**: Собирает статистику о событиях в файловой системе.

**Пример с `inotifywait`:**
```bash
# Мониторить директорию /var/www в реальном времени (-m) и рекурсивно (-r)
inotifywait -m -r /var/www
```

**Лимиты `inotify`:**
Существует ограничение на количество "наблюдателей" (watches), которое может создать один пользователь. Если вы видите ошибку "Too many open files" при использовании `inotify`, возможно, нужно увеличить этот лимит:
```bash
# Посмотреть текущий лимит
sysctl fs.inotify.max_user_watches

# Установить новый лимит
sudo sysctl -w fs.inotify.max_user_watches=524288
```
