## Про память в Linux

Когда вы смотрите на показатели памяти (например, в top, free или через `cat /proc/meminfo`), важно понимать, что именно подразумевается под «used», «free», «buff/cache» и т. д. На первый взгляд может казаться, что система «съедает» всю память, но зачастую это лишь особенности кэширования и работы ядра.

1. Total — Общий объём оперативной памяти (RAM), который распознаёт ядро Linux.
    
2. Used — Количество памяти, занимаемой процессами вместе буферами и кэшами.
    
3. Free — Память, которая прямо сейчас не задействована ни под процессы, ни под кэш.
    
4. Buff/Cache
    - Buffers — память, зарезервированная под буферизацию операций ввода-вывода (I/O). Пример: при копировании большого файла cp bigfile /backup/bigfile часть данных попадает в буферы, прежде чем окончательно записаться на диск. Это помогает оптимизировать операции записи. По окончании записи ядро освобождает или переиспользует буферы.
    - Cache — память, используемая для кэширования файловых данных. Пример: когда вы повторно открываете один и тот же лог-файл, чтение во второй раз будет быстрее, так как ядро может брать данные из кэша (без повторных обращений к диску). Если приложению понадобится память, ядро автоматически «отдаст» часть кэша, так что buff/cache не означает «пропавшую» память.

5. Available — Показывает объём памяти, который ядро может отдать под новые процессы без использования swap. При необходимости кэш и буфер освобождаются автоматически.
    
6. Swap — Когда системе не хватает физической памяти (или при определённой настройке swappiness), неиспользуемые страницы памяти могут выгружаться в swap-раздел (или файл). Если swap активно используется, это может указывать на нехватку RAM, но иногда ядро использует swap и при наличии свободной памяти, если считает, что выгрузка «простаивающих» страниц — более эффективный вариант.

## Оперативная память (ОЗУ)

```sh
free -h
```

| Поле       | Значение | Что означает                                                                 |
|------------|----------|-----------------------------------------------------------------------------|
| **total**  | 7.7G     | Вся оперативная память в системе.                                           |
| **used**   | 3.2G     | Память, занятая процессами (но не вся реально используется, total - free - buff/cache).      |
| **free**   | 843M     | Полностью свободная память (не используется ни для чего).                   |
| **shared** | 123M     | Память, разделяемая между процессами (например, shared libraries, IPC).     |
| **buff/cache** | 3.7G | Память, занятая кэшем и буферами (может быть освобождена при необходимости).|
| **available** | 2.9G | Реальная физическая память, которую система может выделить новым процессам без запуска механизма подкачки (swapping). Это наиболее точный показатель свободной памяти для приложений.(≈ free + часть buff/cache).  |

Файл `/proc/meminfo` предоставляет исчерпывающую статистику об использовании оперативной и swap-памяти. Рассмотрим ключевые параметры:

**Общая память:**
-   `MemTotal`: Общий объем физической RAM.
-   `MemFree`: Количество полностью свободной, неиспользуемой памяти. Это "сырой" показатель, который часто бывает низким, так как Linux стремится использовать свободную память для кэширования.
-   `MemAvailable`: **Наиболее важный показатель для оценки свободной памяти.** Это оценка того, сколько памяти доступно для запуска новых приложений без необходимости выгрузки данных в swap. Включает `MemFree` и часть кэша, которую можно безболезненно освободить.

**Кэш и буферы:**
-   `Buffers`: Память, используемая для временного хранения "сырых" дисковых блоков. Это кэш метаданных файловой системы.
-   `Cached`: Память, используемая для кэширования данных, прочитанных с диска (page cache). При повторном чтении файла данные будут взяты отсюда, а не с медленного диска.
-   `SwapCached`: Память, которая была выгружена в swap, а затем снова загружена в RAM, но все еще остается в swap-файле. Если понадобится, ее можно будет быстро выгрузить обратно, не записывая на диск заново.

**Активная и неактивная память:**
-   `Active`: Память, которая активно используется в данный момент.
-   `Inactive`: Память, которая использовалась, но сейчас неактивна. Является основным кандидатом на вытеснение (reclaiming) при нехватке памяти.
-   `Active(anon)` / `Inactive(anon)`: Анонимная память (не связанная с файлами), которая активно/неактивно используется. Это, как правило, память процессов (стек, куча).
-   `Active(file)` / `Inactive(file)`: Память, используемая для кэширования файлов, которая активно/неактивно используется.
-   `Unevictable`: Страницы памяти, которые нельзя выгрузить в swap (например, заблокированные с помощью `mlock()`).
-   `Mlocked`: Память, заблокированная процессом с помощью системного вызова `mlock()`. Гарантированно не будет выгружена в swap.

**Swap-пространство:**
-   `SwapTotal`: Общий размер раздела или файла подкачки.
-   `SwapFree`: Количество свободного места в swap.

**Страницы памяти:**
-   `Dirty`: Память, которая была изменена, но еще не записана на диск. Если система внезапно выключится, эти данные будут потеряны.
-   `Writeback`: Память, которая в данный момент записывается на диск.
-   `AnonPages`: Анонимные (нефайловые) страницы памяти, используемые процессами.
-   `Mapped`: Память, которая отображена в адресное пространство процессов (например, файлы или библиотеки).
-   `Shmem`: Объем разделяемой памяти (включая `tmpfs`).

**Память ядра:**
-   `Slab`: Память, используемая ядром для кэширования собственных структур данных (inodes, dentries и т.д.).
-   `SReclaimable`: Часть `Slab`, которую можно освободить при нехватке памяти.
-   `SUnreclaim`: Часть `Slab`, которую освободить нельзя.
-   `KernelStack`: Память, выделенная для стеков потоков ядра.
-   `PageTables`: Память, занимаемая таблицами страниц, которые используются для трансляции виртуальных адресов в физические.

**Управление памятью:**
-   `CommitLimit`: Общий объем виртуальной памяти, который система может выделить. Рассчитывается как `SwapTotal + (MemTotal * vm.overcommit_ratio / 100)`.
-   `Committed_AS`: Объем виртуальной памяти, который уже был выделен (запрошен) процессами. Если это значение приближается к `CommitLimit`, система близка к нехватке памяти.

**Огромные страницы (Huge Pages):**
-   `HugePages_Total` / `HugePages_Free` / `Hugepagesize`: Информация о количестве и размере "огромных страниц". Они используются для уменьшения накладных расходов на управление памятью для приложений, работающих с большими объемами данных (например, базы данных).

## Физическая и виртуальная память

В Linux, как и в большинстве современных ОС, процессы не могут обращаться к физической оперативной памяти (RAM) напрямую. Вместо этого система предоставляет каждому процессу **виртуальную память** — абстракцию, которая решает несколько ключевых задач:

1.  **Изоляция:** Виртуальная память, выделенная одному процессу, полностью изолирована и недоступна для других. Это фундаментальный механизм безопасности, который не позволяет одному приложению "покуситься" на память другого.
2.  **Сопоставление с реальной памятью:** Когда процесс хочет записать или прочитать данные, происходит сопоставление (mapping) виртуальных адресов с физическими. Этим управляет ядро ОС в **пространстве ядра (kernelspace)**.

| Характеристика | Физическая память (RAM) | Виртуальная память |
| :--- | :--- | :--- |
| **Что это?** | Реальные аппаратные чипы на материнской плате. | Абстракция, создаваемая операционной системой. |
| **Скорость** | Очень высокая. | Значительно медленнее, особенно при доступе к данным на диске. |
| **Размер** | Ограничен объемом установленных модулей ОЗУ. | Ограничен размером жесткого диска и архитектурой процессора. |
| **Доступ** | Процессор может выполнять код только из физической памяти. | Процессы работают с виртуальными адресами, которые ОС и аппаратура "переводят" в физические. |

**Как это работает: Механизм страниц**

И физическая, и виртуальная память делятся на небольшие блоки фиксированного размера, называемые **страницами** (обычно 4 КБ).

1.  **Таблицы страниц:** Для каждого процесса ядро Linux ведет специальную карту — **таблицу страниц**. В этой таблице для каждой виртуальной страницы процесса записано, где она находится на самом деле:
    *   В какой-то физической странице в ОЗУ.
    *   На жестком диске в специальном разделе или файле (swap).
    *   Нигде (если память была запрошена, но еще не использовалась).

2.  **MMU (Memory Management Unit):** Это специальный аппаратный блок в процессоре. Когда программа обращается к адресу в своей виртуальной памяти, MMU на лету заглядывает в таблицу страниц и мгновенно преобразует виртуальный адрес в физический.

**Преимущества и принципы работы виртуальной памяти:**
*   **Изоляция процессов:** Каждый процесс работает в своем собственном "пузыре" виртуальной памяти и не может испортить память другого процесса. Виртуальная память, выделенная одному процессу, полностью изолирована и недоступна для других.
*   **Использование памяти, превышающей ОЗУ (Overcommit):** Программы могут запрашивать больше памяти, чем физически установлено. Неактивные страницы памяти выгружаются в **пространство подкачки (swap)** на диске. Linux часто использует механизм **"чрезмерного выделения" (overcommit)**, когда система *обещает* процессу больше виртуальной памяти, чем есть в RAM. Например, процессу дадут запрошенные 6 ГБ виртуальной памяти при наличии всего 4 ГБ физической. Процесс будет работать, пока его реальное потребление не превысит доступный объем в 4 ГБ. Как только это произойдет, и если swap будет исчерпан, возникнет ошибка выделения, которая может спровоцировать **OOM Killer**.
*   **Эффективное использование ОЗУ:** Общие библиотеки загружаются в физическую память только один раз, а не для каждого процесса.

### Vmstat: мониторинг активности swap

Утилита `vmstat` предоставляет информацию о процессах, памяти, подкачке, вводе-выводе, системных прерываниях и активности процессора. В контексте swap особенно важны два поля в её выводе:

-   **si (swap-in):** Объем памяти, загруженный из swap-раздела в RAM (в килобайтах в секунду). Постоянно высокое значение `si` свидетельствует о том, что системе не хватает оперативной памяти, и она вынуждена постоянно считывать данные с медленного диска.
-   **so (swap-out):** Объем памяти, выгруженный из RAM в swap-раздел (в килобайтах в секунду). Высокое значение `so` говорит о том, что система активно освобождает RAM, перемещая неактивные страницы в swap.

### Управление Swap (файлом подкачки)

**Swap** (или файл подкачки) — это пространство на диске, которое операционная система использует, когда ей не хватает оперативной памяти (RAM). Если память заполнена, ядро Linux перемещает неактивные страницы памяти (данные) из RAM в swap-пространство, освобождая RAM для более важных задач. Это предотвращает сбои системы из-за нехватки памяти.

Существует два основных способа организации swap:
1.  **Swap-раздел (swap partition)**: Отдельный раздел на диске, предназначенный исключительно для подкачки.
2.  **Swap-файл (swap file)**: Специальный файл, расположенный внутри существующей файловой системы (например, `/swapfile`). Является более гибким решением.

#### Swap-раздел vs Swap-файл

| Характеристика      | Swap-раздел                                       | Swap-файл                                           |
| ------------------- | ------------------------------------------------- | --------------------------------------------------- |
| **Производительность** | Традиционно считался быстрее, но на современных SSD разница незначительна. | Практически не уступает разделу по скорости.        |
| **Гибкость**        | **Низкая**. Размер сложно изменить без утилит для работы с разделами. | **Высокая**. Легко создать, удалить или изменить размер на лету. |
| **Использование**     | Классический подход, обязателен для старых систем. | Современный и рекомендуемый подход в большинстве случаев. |
| **Гибернация**      | Необходим для режима гибернации (сохранения состояния RAM на диск). | С современными ядрами Linux гибернация в swap-файл также возможна, но требует более сложной настройки. |

### Рекомендации по использованию для разных сценариев

| Сценарий | Использовать Swap? | Рекомендуемый размер | Swappiness (`vm.swappiness`) | Тип (Файл/Раздел) | Примечания |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Рабочая станция / Ноутбук** | Да, настоятельно | >= RAM (для гибернации), иначе 4-8 ГБ для систем > 8ГБ RAM. | 60 (стандарт) | Файл (гибкость) | Полезно для запуска множества приложений и необходимо для режима гибернации (suspend-to-disk). |
| **Сервер баз данных (MySQL, PostgreSQL)** | С большой осторожностью | 1–4 ГБ (как "подушка безопасности") | 1–10 | Раздел (производительность) | Активный свопинг критически снижает производительность БД. Swap здесь нужен только для предотвращения OOM killer. |
| **Сервер приложений (Web, Microservices)** | Да | 0.5x RAM или 4–8 ГБ | 10–30 | Файл (гибкость) | Предотвращает падение приложений при утечках памяти или неожиданных пиках нагрузки. |
| **Системы с малым объемом RAM (< 2ГБ)** | Обязательно | 1x – 2x RAM | 60 (стандарт) | Файл | Жизненно необходимо для работы системы. На устройствах с SD-картами (Raspberry Pi) интенсивный swap может ускорить износ карты. |
| **Системы с очень большим объемом RAM (> 64ГБ)** | Да, небольшой | 4–16 ГБ | 10 | Файл или Раздел | Даже при большом объеме RAM небольшой swap полезен для выгрузки редко используемых страниц памяти и как защита от OOM. |

#### Создание и активация Swap-файла

Процесс создания swap-файла состоит из нескольких команд:

```bash
# 1. Выделить место для файла (например, 4 ГБ)
sudo fallocate -l 4G /swapfile

# 2. Установить правильные права доступа (только root должен иметь доступ)
sudo chmod 600 /swapfile

# 3. Отформатировать файл как swap-пространство
sudo mkswap /swapfile

# 4. Активировать swap-файл
sudo swapon /swapfile

# 5. Добавить запись в /etc/fstab для автоматического подключения при загрузке
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

#### Проверка состояния

```sh
# Показать активные swap-области
swapon --show

# Показать использование памяти и swap
free -h
```

## Тюнинг параметров Swap

`vm.swappiness` — это параметр ядра Linux, который контролирует, насколько агрессивно система будет использовать swap. Значение варьируется от 0 до 100.

-   **`100`**: Максимально агрессивное использование swap. Ядро будет выгружать данные в swap очень активно.
-   **`60`**: Значение по умолчанию для большинства дистрибутивов.
-   **`10`**: Рекомендуемое значение для серверов и десктопов. Ядро будет неохотно использовать swap, предпочитая сначала очищать файловый кэш.
-   **`0 или 1`**: Ядро будет избегать swap любой ценой и прибегнет к нему только чтобы предотвратить OOM-ошибку.

**Как проверить текущее значение:**
```sh
cat /proc/sys/vm/swappiness
```

**Как временно изменить значение:**
```sh
sudo sysctl vm.swappiness=10
```

**Как изменить значение навсегда:**
Откройте файл `/etc/sysctl.conf` и добавьте или измените строку:
```
vm.swappiness=10
```
Затем примените изменения: `sudo sysctl -p`.


## Управление выделением памяти (Memory Overcommit)

**Memory Overcommit** — это механизм ядра, который позволяет процессам запрашивать больше виртуальной памяти, чем физически доступно в системе. Это возможно, потому что программы часто резервируют память, но не используют её всю сразу.

Поведение этого механизма регулируется параметром `vm.overcommit_memory`:

-   `0` (Heuristic overcommit handling, по умолчанию): Ядро использует эвристику для оценки, достаточно ли памяти. Запросы, которые очевидно ведут к переполнению, отклоняются.
-   `1` (Always overcommit): Ядро всегда разрешает выделение памяти, каким бы большим ни был запрос. Этот режим может быть опасен, так как повышает риск вызова OOM Killer.
-   `2` (Don't overcommit): Ядро строго ограничивает выделение виртуальной памяти. Процесс не может запросить больше, чем `SwapTotal + (RAM * overcommit_ratio)`. `overcommit_ratio` — это процент RAM, который можно выделить сверх swap (по умолчанию 50%).

Настройка производится через `sysctl`:
```bash
sudo sysctl -w vm.overcommit_memory=1
```

## Оптимизация памяти: Kernel Samepage Merging (KSM)

**KSM (Kernel Samepage Merging)** — это фоновый процесс в ядре, который сканирует память и ищет идентичные страницы. Если он находит две или более одинаковые страницы, он объединяет их в одну, помечая её как "copy-on-write" (CoW).

**Как это работает:**
1.  KSM объединяет одинаковые страницы в одну физическую страницу.
2.  Если какой-либо процесс пытается изменить эту страницу, ядро автоматически создает для него копию, и только после этого процесс вносит изменения.

**Преимущества:**
-   **Экономия RAM:** KSM значительно сокращает потребление памяти, особенно в средах с высокой степенью дублирования данных, например, при запуске множества однотипных виртуальных машин на одном хосте.

KSM управляется через файлы в `/sys/kernel/mm/ksm/`.

## Оптимизация для архитектуры NUMA

**NUMA (Non-Uniform Memory Access)** — это архитектура построения памяти, используемая в многопроцессорных системах. В ней память физически разделена на "узлы" (nodes), и каждый процессор (или группа ядер) имеет быстрый локальный доступ к своему узлу памяти, но более медленный доступ к памяти других узлов.

**Проблема:** Если процесс, выполняющийся на одном процессоре, постоянно обращается к памяти, расположенной на другом узле, возникают задержки, снижающие производительность.

**Оптимизация:**
Основная стратегия — обеспечить **локальность NUMA**, то есть сделать так, чтобы процесс и память, с которой он работает, находились на одном и том же узле.

-   **`numactl`**: Это основная утилита для управления политиками NUMA. Она позволяет принудительно запускать процесс на определённом узле и выделять ему память только из этого узла.
    ```bash
    # Запустить процесс my_app на узле 0 и выделять ему память только оттуда
    numactl --cpunodebind=0 --membind=0 my_app
    ```

## Использование HugePages

**HugePages** — это страницы памяти большого размера (обычно 2 МБ или 1 ГБ вместо стандартных 4 КБ). Их использование позволяет сократить накладные расходы на управление памятью.

**Преимущества:**
-   **Снижение нагрузки на TLB (Translation Lookaside Buffer):** TLB — это кэш процессора для трансляции виртуальных адресов в физические. Использование меньшего количества больших страниц вместо огромного количества маленьких снижает вероятность промахов в TLB, ускоряя доступ к памяти.
-   **Уменьшение размера таблиц страниц:** Требуется меньше записей для отображения того же объёма памяти.

**Применение:**
HugePages особенно полезны для приложений, работающих с большими объёмами непрерывной памяти, таких как базы данных (Oracle, PostgreSQL) и системы виртуализации (KVM).

**Активация:**
Количество HugePages настраивается через параметр ядра:
```bash
# Выделить 1024 страницы по 2 МБ (всего 2 ГБ)
sudo sysctl -w vm.nr_hugepages=1024
```
### Параметр ядра `vfs_cache_pressure`

Этот параметр контролирует, насколько агрессивно ядро будет освобождать память, используемую для кэширования **dentry** (записи каталогов) и **inode** (метаданные файлов).

-   **Значение по умолчанию: `100`**. Ядро быстро освобождает кэш inode/dentry.
-   **Низкое значение (например, `50`):** Ядро будет дольше хранить этот кэш в памяти. Это может ускорить доступ к файлам на системах с большим количеством файлов, но увеличит риск нехватки памяти для процессов.
-   **Высокое значение (более `100`):** Ядро будет очень агрессивно очищать кэш метаданных.

Настройка производится аналогично `swappiness` через `sysctl`:
```bash
sudo sysctl -w vm.vfs_cache_pressure=50
```
