# TCP Wrappers (libwrap) в Linux

> **Статус технологии (Legacy):** TCP Wrappers считается устаревшим (deprecated) механизмом безопасности. Начиная с **RHEL 8/9**, технология полностью удалена из дистрибутива. В **Ubuntu 24.04** поддержка сохраняется для некоторых служб (например, OpenSSH), но стратегически рекомендуется миграция на фильтрацию уровня ядра (Netfilter) или встроенные средства приложений.

## Определения

* **TCP Wrappers** — это программный слой управления доступом к сетевым службам на уровне прикладных протоколов (L7). Он позволяет ограничивать подключения на основе IP-адресов, имен хостов или сетевых сегментов.
* **libwrap** — разделяемая библиотека, предоставляющая API для проверки прав доступа. Служба должна быть динамически или статически скомпилирована с поддержкой этой библиотеки для работы TCP Wrappers.
* **tcpd** — классическая утилита-демон, которая выступала в роли «обертки» для служб, запускаемых через суперсерверы `inetd` или `xinetd`. В современных системах практически не используется, так как службы вызывают `libwrap` напрямую.

## Основные концепции

### Порядок обработки правил

Когда приложение получает запрос на подключение, библиотека `libwrap` последовательно проверяет два конфигурационных файла. Как только найдено первое совпадение, проверка прекращается.

1.  **`/etc/hosts.allow`** — Белый список. Если клиент соответствует правилу здесь, доступ разрешается немедленно.
2.  **`/etc/hosts.deny`** — Черный список. Если клиент не попал в белый список, но соответствует правилу здесь, доступ блокируется.
3.  **Разрешение по умолчанию** — Если совпадений не найдено ни в одном файле, доступ разрешается.

### Синтаксис правил

Общий формат записи:
```text
daemon_list : client_list [: option : option ...]
```

* **daemon_list**: Имя исполняемого файла службы (например, `sshd`) или ключевое слово `ALL`.
* **client_list**: Список IP-адресов, подсетей (`192.168.1.`), имен хостов или доменов (`.example.com`).
* **Ключевые слова**:
    * `ALL` — совпадение со всем.
    * `LOCAL` — хосты без точки в имени (локальная сеть).
    * `UNKNOWN` — хосты, чьи данные не удалось разрешить (DNS/User).
    * `PARANOID` — хосты, у которых IP не совпадает с Reverse DNS записью.

## Практические сценарии

### 1. Настройка базового ограничения для SSH

Наиболее безопасная конфигурация строится по принципу «запрещено всё, что не разрешено».

**Файл `/etc/hosts.allow`:**
```ini
# Разрешить доступ администратору и доверенной подсети
sshd : 203.0.113.42, 192.168.1.0/255.255.255.0
```

**Файл `/etc/hosts.deny`:**
```ini
# Запретить всем остальным
sshd : ALL
```

### 2. Расширенный синтаксис (EXCEPT и SHELL команды)

TCP Wrappers поддерживает сложную логику исключений и выполнение действий при срабатывании правила.

**Использование EXCEPT:**
```ini
# Разрешить доступ ко всем службам для всей сети, кроме подозрительного хоста
ALL : 192.168.1. EXCEPT 192.168.1.66
```

**Использование SPAWN (Активное реагирование):**
```ini
# При попытке входа с запрещенного IP — записать лог и отправить уведомление
sshd : .malicious.com : spawn (echo "Access denied to %u@%h" | mail -s "Alert" admin@example.com) & : deny
```
*Где `%u` — имя пользователя (через identd), `%h` — имя хоста.*

### 3. Диагностика поддержки и правил

**Проверка поддержки библиотекой службой:**
```bash
# Проверяем, слинкован ли бинарник с libwrap
ldd $(which sshd) | grep libwrap
# → libwrap.so.0 => /lib/x86_64-linux-gnu/libwrap.so.0 (0x...)
```

**Тестирование конфигурации без реальных подключений:**
```bash
# tcpdmatch <служба> <IP_клиента>
tcpdmatch sshd 192.168.1.10
# → client:   address  192.168.1.10
# → server:   process  sshd
# → access:   granted
```

### 4. Современная альтернатива: systemd IPAddressAllow

В системах с **systemd** (RHEL 9+, Ubuntu 22.04+) можно ограничивать доступ на уровне unit-файла, что работает эффективнее и не требует `libwrap`.

Отредактируйте сервис (`systemctl edit ssh.service`):
```ini
[Service]
# Разрешить только конкретные IP
IPAddressAllow=192.168.1.0/24 203.0.113.42
# Запретить всё остальное
IPAddressDeny=any
```

## Дополнительная информация

### Сравнение с современными методами защиты

| Механизм | Уровень OSI | Плюсы | Минусы |
| :--- | :--- | :--- | :--- |
| **TCP Wrappers** | L7 (Прикладной) | Простой синтаксис, привязка к именам доменов. | Устарел, работает не для всех служб, User-space. |
| **nftables / ufw** | L3-L4 (Сетевой) | Высокая скорость (Kernel-space), универсальность. | Сложнее синтаксис (для nftables). |
| **systemd** | L3-L4 | Настройка в контексте службы, нет зависимости от библиотек. | Требует systemd. |
| **Fail2Ban** | L7 (Логи) | Автоматизация блокировок при атаках. | Задержка между атакой и блокировкой. |

### Рекомендации по миграции

1.  **Проверьте актуальность:** Если вы используете RHEL 9+, TCP Wrappers уже не работают. Перейдите на `firewalld` (Rich Rules).
2.  **Для SSH:** Отдавайте приоритет директиве `AllowUsers` в `sshd_config` или `IPAddressAllow` в `sshd.service`.
3.  **Изоляция:** Для критических служб используйте сетевые пространства имен (Network Namespaces) или VRF.
