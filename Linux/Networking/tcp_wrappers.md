# TCP Wrappers: Ограничение доступа к сетевым службам

> **Устаревшая технология**: TCP Wrappers считается устаревшим механизмом безопасности. Современные дистрибутивы (RHEL 8+, Debian 11+) не включают `libwrap` по умолчанию. Для новых проектов рекомендуется использовать файрволы (`nftables`, `iptables`, `firewalld`) и встроенные механизмы контроля доступа служб.

## Определения

**TCP Wrappers** — это программный набор, предоставляющий механизм контроля доступа к сетевым службам в системах Linux/Unix на уровне приложений. Использует файлы `/etc/hosts.allow` и `/etc/hosts.deny` для фильтрации входящих запросов на основе IP-адресов клиентов, доменных имён или имён хостов.

**libwrap** — библиотека, предоставляющая функции TCP Wrappers. Демон должен быть скомпилирован с поддержкой `libwrap` для работы с TCP Wrappers.

## Основные концепции

Когда клиент пытается подключиться к службе, настроенной с использованием TCP Wrappers (например, `sshd`, [vsftpd](./Services/ftp/vsftpd_setup.md)), демон службы сначала обращается к библиотеке `libwrap`.
 Эта библиотека проверяет конфигурационные файлы:

1. **`/etc/hosts.allow`**: Проверяется первым. Если найдено соответствующее правило, доступ разрешается, и дальнейшая проверка не производится.
2. **`/etc/hosts.deny`**: Если правило не найдено в `hosts.allow`, проверяется `hosts.deny`. Если найдено соответствующее правило, доступ запрещается.
3. **Нет правил**: Если правила не найдены ни в одном из файлов, доступ по умолчанию разрешается.

## Практические сценарии

### Сценарий 1: Настройка правил доступа

Конфигурационные файлы `hosts.allow` и `hosts.deny` имеют простой формат:

```
<daemon_list>: <client_list>
```

* `<daemon_list>`: Список демонов (имен служб), к которым применяется правило (например, `sshd`, `ALL`).
* `<client_list>`: Список клиентов, к которым применяется правило. Может быть IP-адресом, маской подсети (`192.168.1.0/24`), именем хоста, доменным именем (`.example.com`) или `ALL`.

### Примеры настройки

#### Разрешить доступ только с определенных IP-адресов для SSH

Добавьте в `/etc/hosts.allow`:

```ini
sshd: 192.168.1.100 192.168.1.101
```

Затем добавьте в `/etc/hosts.deny`:

```ini
sshd: ALL
```

Эти правила разрешат подключение по SSH только с IP-адресов `192.168.1.100` и `192.168.1.101`, а всем остальным SSH-доступ будет запрещен.

#### Разрешить все для HTTP, запретить Telnet для конкретной сети

```ini
# /etc/hosts.allow
httpd: ALL
ALL: LOCAL # Разрешить всем локальным хостам доступ ко всем службам

# /etc/hosts.deny
in.telnetd: 192.168.1.0/24
```

### Важные замечания

* После изменения файлов `hosts.allow` или `hosts.deny` **не требуется перезапускать службу**. Изменения применяются немедленно.
* Всегда тщательно проверяйте правила, чтобы не заблокировать себе доступ к системе.
* TCP Wrappers являются базовым механизмом контроля доступа и **не заменяют полноценный файрвол** (например, `iptables`, `nftables`, `ufw`). Они работают на уровне приложений, а не на сетевом уровне.
* В случае конфликта (например, правило разрешает в `hosts.allow`, но запрещает в `hosts.deny`), правило из `hosts.allow` имеет приоритет.
* Не все службы поддерживают TCP Wrappers. Демон должен быть скомпилирован с поддержкой `libwrap`.

### Сценарий 2: Диагностика и проверка

#### Проверка поддержки libwrap в демоне

Перед настройкой убедитесь, что служба поддерживает TCP Wrappers:

```bash
# Проверка зависимости от libwrap через ldd
ldd /usr/sbin/sshd | grep libwrap

# Пример вывода для службы с поддержкой:
#   libwrap.so.0 => /lib/x86_64-linux-gnu/libwrap.so.0 (0x00007f...)
```

Если вывод пустой — служба не поддерживает TCP Wrappers.

#### Тестирование правил с tcpdmatch

Утилита `tcpdmatch` позволяет проверить, какое правило будет применено к конкретному клиенту:

```bash
# Синтаксис: tcpdmatch <демон> <клиент>
tcpdmatch sshd 192.168.1.100
tcpdmatch sshd 10.0.0.50
tcpdmatch vsftpd .example.com
```

**Пример вывода:**

```
client: 192.168.1.100
server: sshd
access: granted
rule: /etc/hosts.allow line 1
```

#### Просмотр логов

TCP Wrappers может логировать запросы через syslog. Проверьте логи:

```bash
# Журнал подключений (зависит от конфигурации syslog)
grep -i "tcpd\|libwrap" /var/log/syslog
journalctl -u ssh | grep -i "wrap"
```

## Дополнительная информация

### Сравнение механизмов контроля доступа

| Механизм | Уровень | Преимущества | Недостатки |
| :--- | :--- | :--- | :--- |
| **TCP Wrappers** | Прикладной (L7) | Простая настройка, гибкие правила по доменам | Устарел, не все службы поддерживают |
| **[iptables](./Settings/tools/iptables_basics.md) / [nftables](./Settings/tools/nftables/architecture_and_concepts.md)** | Сетевой (L3-L4) | Универсальность, производительность, stateful-фильтрация | Сложнее в настройке |
| **firewalld/ufw** | Сетевой (L3-L4) | Удобный интерфейс, динамическое управление | Надстройка над iptables/nftables |
| **SSH AllowUsers/AllowGroups** | Прикладной (L7) | Встроенный механизм SSH | Только для SSH |

### Рекомендации по миграции

Для современных систем рекомендуется:

1. **Для SSH**: Используйте директивы `AllowUsers`, `AllowGroups`, `DenyUsers`, `DenyGroups` в `/etc/ssh/sshd_config`
2. **Для других служб**: Настройте правила в [nftables](./Settings/tools/nftables/architecture_and_concepts.md) или [iptables](./Settings/tools/iptables_basics.md)
3. **Для динамического управления**: Используйте `firewalld` или `ufw`

**Пример миграции SSH с TCP Wrappers на sshd_config:**

```bash
# Было в /etc/hosts.allow:
# sshd: 192.168.1.100 192.168.1.101

# Стало в /etc/ssh/sshd_config:
AllowUsers user1@192.168.1.100 user2@192.168.1.101

# Или по группе:
AllowGroups sshusers
```

После изменения `sshd_config` требуется перезапуск службы: `systemctl restart sshd`.
