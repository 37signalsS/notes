# Policy-Based Routing (PBR) в Linux

## Определения

**Policy-Based Routing (PBR)** — это механизм в ядре Linux, который позволяет выбирать таблицу маршрутизации на основе набора правил (политик). В отличие от традиционной маршрутизации, где решение принимается только на основе IP-адреса назначения, PBR позволяет учитывать другие параметры: IP-адрес источника, порт, протокол или даже метки пакетов (`fwmark`).

## Базовые концепции

### Принцип работы

Стандартная маршрутизация в Linux использует одну главную таблицу (`main`) для всех решений. PBR расширяет эту модель, позволяя создавать несколько независимых таблиц маршрутизации и определять, какую из них использовать для конкретного пакета.

Процесс состоит из трех ключевых компонентов:

1. **Несколько таблиц маршрутизации**: Вы создаете кастомные таблицы, каждая со своим набором маршрутов (например, со своим шлюзом по умолчанию).
2. **Селекторы (Правила)**: С помощью команды `ip rule` вы создаете правила, которые определяют, по какому критерию выбирать таблицу. Правила проверяются по порядку (приоритету).
3. **Маркировка пакетов**: Часто для выбора нужных пакетов используется их маркировка с помощью `iptables` (таблица `mangle`, действие `MARK`). Правило `ip rule` затем ссылается на эту метку (`fwmark`).

### Сферы применения

* **Разделение трафика по разным каналам:** Например, направлять HTTP/S-трафик через один канал (VPN), а весь остальной трафик — напрямую.
* **Балансировка нагрузки:** Распределять трафик между несколькими интернет-провайдерами.
* **Изоляция сервисов:** Запрещать контейнерам доступ в интернет, но разрешать обмен данными в локальной сети.

Для управления правилами и маршрутами используется утилита **[iproute2](../Tools/iproute2/overview.md)**, а для маркировки пакетов — **[iptables](../Settings/linux_firewall_management.md)**.

## Практические сценарии

Рассмотрим пример, где нужно направить трафик от веб-браузера через VPN, а SSH-трафик — напрямую.

Предположим, система имеет два сетевых интерфейса:

* `eth0` – основной канал в интернет (шлюз `192.168.1.1`).
* `tun0` – VPN-интерфейс (шлюз `10.8.0.1`).

### 1. Создание дополнительных таблиц маршрутов

По умолчанию в Linux используется основная таблица `main`. Для PBR необходимо создать дополнительные. Имена таблиц и их числовые идентификаторы добавляются в файл `/etc/iproute2/rt_tables`.

```bash
# Добавляем таблицы, если они еще не существуют
sudo grep -qxF '100 vpn_table' /etc/iproute2/rt_tables || echo "100 vpn_table" | sudo tee -a /etc/iproute2/rt_tables
sudo grep -qxF '200 direct_table' /etc/iproute2/rt_tables || echo "200 direct_table" | sudo tee -a /etc/iproute2/rt_tables
```

### 2. Добавление маршрутов в новые таблицы

Добавим маршруты по умолчанию для каждой таблицы, указывая соответствующий шлюз.

```bash
# Маршрут для прямого подключения через eth0
sudo ip route add default via 192.168.1.1 dev eth0 table direct_table

# Маршрут для подключения через VPN
sudo ip route add default via 10.8.0.1 dev tun0 table vpn_table
```

### 3. Маркировка пакетов с помощью `iptables`

```bash
# Маркируем пакеты от пользователя 'browseruser' (под которым запущен браузер) меткой '1'
sudo iptables -t mangle -A OUTPUT -m owner --uid-owner browseruser -j MARK --set-mark 1

# Маркируем исходящий SSH-трафик (порт 22) меткой '2'
sudo iptables -t mangle -A OUTPUT -p tcp --dport 22 -j MARK --set-mark 2
```

### 4. Создание правил маршрутизации

```bash
# Пакеты с меткой 1 направлять в таблицу 'vpn_table'
sudo ip rule add fwmark 1 table vpn_table

# Пакеты с меткой 2 направлять в таблицу 'direct_table'
sudo ip rule add fwmark 2 table direct_table
```

Теперь весь трафик от пользователя `browseruser` пойдет через VPN, а SSH-трафик — напрямую. Остальной трафик будет использовать стандартную таблицу `main`.

## Дополнительная информация

### Проверка конфигурации PBR

```bash
# Показать все созданные правила и их приоритет
ip rule show

# Показать маршруты в таблице vpn_table
ip route show table vpn_table

# Показать маршруты в таблице direct_table
ip route show table direct_table
```

### Порядок обработки

Ядро обрабатывает правила `ip rule` в порядке их **приоритета** (самое низкое число — самый высокий приоритет). По умолчанию правила добавляются с приоритетами, начиная с `32766` и ниже. Можно явно указать приоритет с помощью `priority <число>`.

Стандартный набор правил выглядит так:

```
0:      from all lookup local
32766:  from all lookup main
32767:  from all lookup default
```

Ваши правила будут вставлены между `local` и `main`, обеспечивая их проверку до стандартной маршрутизации.
