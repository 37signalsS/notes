# Инструменты диагностики сети

## Определения

**Сетевая диагностика** — это процесс выявления и устранения проблем в компьютерных сетях. Он включает в себя измерение производительности, анализ трафика и проверку конфигураций для обеспечения стабильной и быстрой работы сети.

## Основные концепции

Диагностика сети оперирует тремя ключевыми метриками:

1.  **Пропускная способность (Bandwidth):** Максимальное количество данных, которое может быть передано по каналу за единицу времени. Измеряется утилитами вроде `iperf3`.
2.  **Задержка (Latency/RTT):** Время, необходимое для прохождения пакета от отправителя к получателю и обратно. Измеряется `ping` и `mtr`.
3.  **Потери пакетов (Packet Loss):** Процент пакетов, которые не достигли пункта назначения. Выявляется с помощью `ping` и `mtr`.

Инструменты делятся на несколько категорий:
*   **Анализаторы сокетов:** Показывают текущие соединения и слушающие порты (`ss`).
*   **Измерители производительности:** Тестируют реальную пропускную способность (`iperf3`).
*   **Инструменты трассировки:** Отслеживают маршрут пакетов и задержки на каждом узле (`mtr`, `traceroute`).
*   **Анализаторы трафика:** Перехватывают и декодируют сетевые пакеты для глубокого анализа (`tcpdump`, `wireshark`).

## Практические сценарии

### Сценарий 1: Проверка доступности порта и сервиса

**Задача:** Убедиться, что порт на удаленном хосте открыт и сервис на нем отвечает.
**Инструмент:** `nc` (netcat).

```bash
# Проверить доступность TCP-порта 443 на хосте example.com
nc -zv example.com 443

# Проверить доступность UDP-порта 53 на DNS-сервере
nc -zvu 8.8.8.8 53
```
*   `Connection succeeded`: Порт открыт.
*   `Connection refused`: Порт закрыт, сервис не запущен.
*   `Connection timed out`: Пакеты блокируются (например, firewall).

### Сценарий 2: Измерение реальной пропускной способности канала

**Задача:** Измерить максимальную скорость между двумя серверами.
**Инструмент:** `iperf3`.

```bash
# На сервере (принимающей стороне)
iperf3 -s

# На клиенте (отправляющей стороне)
iperf3 -c <IP-адрес сервера>

# Для проверки обратного канала (сервер -> клиент)
iperf3 -c <IP-адрес сервера> -R
```
Асимметрия скорости в прямом и обратном канале — частая проблема.

### Сценарий 3: Поиск узкого места в сети (потери и задержки)

**Задача:** Определить, на каком участке сети происходят потери пакетов или возникает высокая задержка.
**Инструмент:** `mtr`.

```bash
# Запустить трассировку до хоста с отправкой 100 пакетов
mtr -rwzc 100 example.com
```
Анализ колонок `Loss%` (потери) и `Avg` (средняя задержка) для каждого хопа (строки) помогает локализовать проблемный узел.

### Сценарий 4: Анализ текущих соединений и производительности TCP

**Задача:** Посмотреть, какие процессы держат порты, и проверить состояние TCP-сессий.
**Инструмент:** `ss`.

Подробное руководство по использованию `ss`, включая анализ `retransmits` и `RTT`, находится в специальной заметке: **[Анализ сокетов с помощью ss](../Diagnostics/Networking/ss.md)**.

### Сценарий 5: Комплексный порядок диагностики

1.  **Проверка DNS:** Убедитесь, что доменное имя правильно разрешается в IP-адрес.
    *   См. руководство: **[Диагностика DNS](../Diagnostics/Networking/dns_diagnostics.md)**.
2.  **Проверка базовой связности и маршрута:** `ping` и `mtr`.
3.  **Проверка открытых портов:** `nc`.
4.  **Анализ активных соединений:** `ss`.
5.  **Измерение пропускной способности:** `iperf3`.
6.  **Глубокий анализ трафика (при необходимости):** `tcpdump`.

## Дополнительная информация

Для более глубокого анализа сетевого стека и управления им используются утилиты из пакета `iproute2`, такие как:
*   `tc`: Управление трафиком (QoS). См. [заметку о tc](./Tools/iproute2/tc.md).
*   `ethtool`: Просмотр и настройка параметров сетевых драйверов. См. [заметку о ethtool](./Tools/ethtool.md).
