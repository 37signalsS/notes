# TCP Tuning для высокой нагрузки

В больших сервисах стандартные сетевые настройки ядра Linux иногда становятся узким местом. Например, при сотнях тысяч одновременных соединений сервер может «терять» пакеты SYN, а TCP-сессии застревать в TIME_WAIT. Чтобы этого избежать, настраивают несколько параметров через `sysctl`.

## Основные параметры

### 1. `net.core.somaxconn`

Определяет максимальное количество ожидающих соединений в очереди `listen()`. Это очередь запросов на соединение, которые были приняты ядром, но еще не обработаны приложением.

**Проверка текущего значения:**
```bash
sysctl net.core.somaxconn
```

**Увеличение значения (пример до 65535):**
```bash
sudo sysctl -w net.core.somaxconn=65535
```

### 2. `net.ipv4.tcp_max_syn_backlog`

Размер очереди незавершённых TCP-соединений (SYN_RECV). Важно при пиковых нагрузках, чтобы предотвратить потерю SYN-пакетов при высокой частоте запросов на соединение.

**Увеличение значения (пример до 4096):**
```bash
sudo sysctl -w net.ipv4.tcp_max_syn_backlog=4096
```

### 3. `net.ipv4.tcp_fin_timeout`

Время удержания соединений в состоянии `FIN_WAIT2`. Сокращение этого таймаута может помочь быстрее освобождать ресурсы, но слишком низкое значение может привести к проблемам с корректным завершением соединений.

**Сокращение значения (пример до 15 секунд):**
```bash
sudo sysctl -w net.ipv4.tcp_fin_timeout=15
```

### 4. `net.ipv4.tcp_tw_reuse` и `net.ipv4.tcp_tw_recycle`

Эти параметры влияют на обработку соединений в состоянии `TIME_WAIT`.

*   **`net.ipv4.tcp_tw_reuse` (рекомендуется)**
    Позволяет повторно использовать сокеты в состоянии `TIME_WAIT` для новых исходящих соединений, если временная метка (timestamp) соединения больше, чем timestamp предыдущего соединения. Это значительно сокращает количество сокетов в `TIME_WAIT`.

    **Включение:**
    ```bash
    sudo sysctl -w net.ipv4.tcp_tw_reuse=1
    ```

*   **`net.ipv4.tcp_tw_recycle` (ВНИМАНИЕ: устарел и опасен для NAT)**
    Параметр `tcp_tw_recycle` также ускоряет переработку сокетов в `TIME_WAIT`. Однако он использует временные метки таким образом, что может нарушить работу клиентов, находящихся за NAT-устройствами (например, балансировщиками нагрузки), поскольку у всех клиентов за NAT будет один и тот же IP-адрес, но разные временные метки. Это может привести к тому, что запросы от разных клиентов за NAT будут игнорироваться. Поэтому использование `tcp_tw_recycle` КАТЕГОРИЧЕСКИ НЕ РЕКОМЕНДУЕТСЯ.

## Проверка эффекта

После применения настроек можно проверить их влияние на систему:

*   **Посмотреть количество TIME_WAIT-соединений:**
    ```bash
    ss -s | grep timewait
    ```
    Ожидается уменьшение их количества при активном использовании `tcp_tw_reuse`.

*   **Нагрузить сервер** с помощью утилит `ab` (ApacheBench) или `wrk` и сравнить, сколько одновременных соединений сервер держит без потерь или с меньшими задержками.

## Автоматизация

Чтобы настройки сохранялись после перезагрузки системы, добавьте их в файл `/etc/sysctl.conf` или в новый файл с расширением `.conf` в директории `/etc/sysctl.d/` (например, `/etc/sysctl.d/99-tcp-tuning.conf`):

```ini
net.core.somaxconn = 65535
net.ipv4.tcp_max_syn_backlog = 4096
net.ipv4.tcp_fin_timeout = 15
net.ipv4.tcp_tw_reuse = 1
```

**Примените изменения после добавления в файл:**
```bash
sudo sysctl -p
```

Эта команда загрузит настройки из `/etc/sysctl.conf` и всех файлов в `/etc/sysctl.d/`.

### Оптимизация для пропускной способности и RTT

Если основная цель — не только обработка большого числа соединений, но и достижение максимальной скорости передачи данных с минимальной задержкой (RTT), следует обратить внимание на следующие параметры.

#### 1. Увеличение размеров буферов

Слишком маленькие буферы ограничивают скорость, а слишком большие могут приводить к задержкам. Настройки ниже позволяют использовать больше памяти для TCP-соединений, снижая потери пакетов при высоких скоростях.

```bash
# Максимальный размер буфера приёма
sysctl -w net.core.rmem_max=67108864
# Максимальный размер буфера отправки
sysctl -w net.core.wmem_max=67108864
# Буферы TCP для чтения (min, default, max)
sysctl -w net.ipv4.tcp_rmem="4096 87380 33554432"
# Буферы TCP для записи (min, default, max)
sysctl -w net.ipv4.tcp_wmem="4096 65536 33554432"
```

#### 2. Алгоритмы контроля перегрузок

Некоторые алгоритмы более агрессивны и лучше подходят для быстрых сетей.

```bash
# Установка алгоритма BBR (Bottleneck Bandwidth and RTT)
sysctl -w net.ipv4.tcp_congestion_control=bbr
```
BBR — современный алгоритм от Google, который может значительно ускорить TCP-соединения и минимизировать RTT, особенно в нестабильных сетях.

#### 3. Оптимизация обработки ACK

Частота отправки подтверждений (ACK) влияет на задержку.

```bash
# Минимальная задержка перед отправкой ACK (в мс)
sysctl -w net.ipv4.tcp_delack_min=10
# Улучшение работы с масштабированием окна TCP
sysctl -w net.ipv4.tcp_adv_win_scale=2
```
Эти параметры могут уменьшить задержки на медленных соединениях, но требуют тестирования для конкретной сети.

#### 4. Ускорение установки и закрытия соединений

Оптимизация обработки SYN-запросов и состояния `TIME_WAIT` напрямую влияет на скорость установки новых соединений.

```bash
# Включение защиты от SYN-флуда
sysctl -w net.ipv4.tcp_syncookies=1
# Уменьшение числа повторных SYN-запросов
sysctl -w net.ipv4.tcp_syn_retries=2
# Более быстрое закрытие неактивных соединений (уменьшение времени в FIN_WAIT_2)
sysctl -w net.ipv4.tcp_fin_timeout=10
```
Эти настройки, как и предыдущие, стоит добавлять в `/etc/sysctl.conf` для сохранения после перезагрузки.
