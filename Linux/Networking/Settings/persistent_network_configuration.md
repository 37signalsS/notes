# Постоянная настройка сети в Linux

## Определения

*   **Постоянная настройка сети** — это конфигурация сетевых параметров (таких как IP-адреса, маски подсети, шлюзы, DNS-серверы), которая сохраняется после перезагрузки операционной системы. В отличие от временных настроек, применяемых утилитой [[iproute2|../../Linux/Networking/Tools/iproute2.md]], постоянная конфигурация достигается редактированием системных файлов или использованием специализированных инструментов.

## Базовые концепции

Настройки, сделанные с помощью команды `ip`, являются временными и сбрасываются после перезагрузки. Для постоянной конфигурации сети в Linux необходимо редактировать системные файлы. Подходы различаются в зависимости от дистрибутива и используемой системы управления сетью. Концепции работы DNS-клиента, включая роль файла `/etc/resolv.conf`, подробно описаны в заметке [[Настройка и диагностика DNS-клиента в Linux|../Concepts/dns_client.md]].

## Практические сценарии

### 1. Debian/Ubuntu (классический способ)

В старых версиях Debian и Ubuntu, а также в системах, где не используется `NetworkManager` или `netplan`, сеть настраивается через файл `/etc/network/interfaces`.

**Пример статической конфигурации:**
```ini
# /etc/network/interfaces

# The loopback network interface
auto lo
iface lo inet loopback

# Основной сетевой интерфейс
auto eth0
iface eth0 inet static
    address 10.10.10.10       # Основной IPv4-адрес
    netmask 255.255.255.0     # Маска подсети
    gateway 10.10.10.1        # Шлюз по умолчанию
    dns-nameservers 8.8.8.8 1.1.1.1 # DNS-серверы
```

- **Добавление дополнительных IP-адресов (алиасов):**
  ```ini
  auto eth0:1
  iface eth0:1 inet static
      address 10.10.10.11
      netmask 255.255.255.255
  ```

- **Применение изменений:**
  ```bash
  sudo systemctl restart networking
  ```

### 2. CentOS/RHEL (NetworkManager)

В дистрибутивах на базе RHEL (CentOS, AlmaLinux) управлением сетью по умолчанию занимается **NetworkManager**. Хотя можно редактировать файлы `ifcfg-*` вручную, предпочтительным способом является использование утилиты `nmcli`.

#### Использование `nmcli`

-   **Посмотреть устройства и соединения:**
    ```bash
    nmcli device status
    nmcli connection show
    ```

-   **Изменить существующее соединение на статическое:**
    Предположим, есть соединение `System eth0`, работающее по DHCP.
    ```bash
    # Устанавливаем статический IP, маску и шлюз
    sudo nmcli connection modify 'System eth0' ipv4.method manual ipv4.addresses 10.10.10.10/24 gw4 10.10.10.1

    # Добавляем DNS-серверы
    sudo nmcli connection modify 'System eth0' ipv4.dns "8.8.8.8 1.1.1.1"

    # Применяем изменения
    sudo nmcli connection up 'System eth0'
    ```

#### Редактирование `ifcfg` файлов (традиционный способ)

Конфигурационные файлы для каждого интерфейса находятся в `/etc/sysconfig/network-scripts/`. Например, для `eth0` это будет `ifcfg-eth0`.

**Пример статической конфигурации:**
```ini
# /etc/sysconfig/network-scripts/ifcfg-eth0
DEVICE="eth0"
BOOTPROTO="none"       # Отключаем DHCP, используем статическую конфигурацию
ONBOOT="yes"           # Запускать при старте системы
IPADDR="10.10.10.10"
PREFIX="24"            # Маска подсети
GATEWAY="10.10.10.1"
DNS1="8.8.8.8"
DNS2="1.1.1.1"
```

-   **Применение изменений:**
    ```bash
    sudo systemctl restart NetworkManager
    ```

### 3. Ubuntu 17.10+ (Netplan)

В современных версиях Ubuntu для управления сетью используется `netplan`. Это утилита, которая использует декларативные YAML-файлы, а затем генерирует на их основе настройки для `systemd-networkd` (на серверах) или `NetworkManager` (на десктопах).

Конфигурационные файлы находятся в `/etc/netplan/`.

**Пример статической конфигурации:**
```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: no
      addresses:
        - 10.10.10.10/24
      routes:
        - to: default
          via: 10.10.10.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
```

-   **`renderer: networkd`**: Указывает, что `netplan` должен генерировать конфигурацию для `systemd-networkd`.
-   **`enp0s3`**: Имя вашего интерфейса. Узнать можно командой `ip a`.

**Применение конфигурации:**
```bash
# 1. Проверить синтаксис
sudo netplan generate
# 2. Применить конфигурацию
sudo netplan apply
```

## Расширенные детали

### 1. Фиксация имен сетевых интерфейсов

Иногда после перезагрузки или обновления ядро может переименовать сетевые интерфейсы (например, `eth0` в `enp0s3`). Это может нарушить работу файрвола и скриптов. Чтобы зафиксировать имя интерфейса, можно использовать правило `udev` или [[systemd|../../Linux/Core/systemd.md]].

#### Использование `systemd.link`

Это современный и предпочтительный способ.

1.  **Узнайте MAC-адрес нужного интерфейса:**
    ```bash
    ip link show eth0
    # Вывод будет содержать что-то вроде link/ether 52:54:00:ab:cd:ef
    ```
    Подробнее о MAC-адресах.

2.  **Создайте файл правила `.link`:**
    Создайте файл `/etc/systemd/network/10-persistent-net.link`.
    ```ini
    # /etc/systemd/network/10-persistent-net.link
    [Match]
    MACAddress=52:54:00:ab:cd:ef

    [Link]
    Name=net0
    ```
    - `[Match]`: Условие, по которому `systemd` найдет устройство. `MACAddress` — самый надежный способ.
    - `[Link]`: Действие. `Name=net0` задает новое, постоянное имя `net0`.

3.  **Перезагрузите систему** или выполните `sudo udevadm trigger`, чтобы применить изменения.

Теперь ваш сетевой интерфейс всегда будет называться `net0`.
