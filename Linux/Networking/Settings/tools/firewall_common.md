## Основные концепции

### Сохранение правил между перезагрузками

Правила, примененные через CLI, хранятся в памяти ядра и сбрасываются при перезагрузке. Обеспечение персистентности зависит от используемого инструмента и дистрибутива.

| Дистрибутив | Сценарий | Инструмент сохранения | Метод / Команда |
| :--- | :--- | :--- | :--- |
| **Ubuntu 24.04/26.04** | **ufw** (Default) | `ufw.service` | Автоматически (`/etc/ufw/*.rules`) |
| **Debian 12+ / Ubuntu** | **nftables** (Native) | `nftables.service` | `nft list ruleset > /etc/nftables.conf` |
| **RHEL 9+ / Alma / Rocky** | **firewalld** (Default) | `firewalld.service` | Использование флага `--permanent` |
| **Любой (Legacy)** | **iptables** | `iptables-persistent` | `netfilter-persistent save` |

#### Использование nftables (Рекомендуемый метод)
В современных системах рекомендуется использовать нативный сервис `nftables`, который атомарно загружает правила из одного файла.

```bash
# Проверка статуса сервиса
sudo systemctl status nftables

# Сохранение текущего набора правил (атомарно)
sudo nft list ruleset | sudo tee /etc/nftables.conf

# Включение автозагрузки
sudo systemctl enable nftables
```

## Практические сценарии

### Выбор действия: DROP vs REJECT

| Параметр | **DROP** | **REJECT** |
| :--- | :--- | :--- |
| **Поведение** | Пакет молча отбрасывается. | Пакет отклоняется с отправкой **ICMP Unreachable**. |
| **Скрытность** | Максимальная ("Stealth mode"). | Минимальная (хост виден). |
| **Отладка** | Сложная (таймауты на клиенте). | Простая (немедленная ошибка). |
| **Рекомендация** | **Внешние (WAN) интерфейсы.** | **Внутренние (LAN) интерфейсы.** |

### Взаимодействие Docker и межсетевого экрана

Docker динамически управляет правилами Netfilter, что часто приводит к конфликтам с `ufw` и `firewalld`.

**Ключевые особенности (Docker v28+):**
1. **Обход фильтров:** Правила Docker (цепочка `DOCKER`) обрабатываются раньше цепочек `INPUT` большинства высокоуровневых инструментов. Это означает, что опубликованный порт (`-p 80:80`) будет открыт, даже если в `ufw` он запрещен.
2. **Secure by Default:** В новых версиях Docker ограничивает доступ к IP контейнеров из локальной сети, если порты не опубликованы.
3. **Цепочка DOCKER-USER:** Это единственное место, где пользователь может надежно добавлять свои правила, которые **не будут** перезаписаны демоном Docker.

```bash
# Пример: Запретить доступ к портам контейнеров со всех адресов, кроме доверенного
sudo iptables -I DOCKER-USER -i eth0 ! -s 192.168.1.100 -j DROP
```

### Диагностика и отладка

Для отслеживания того, какие правила блокируют трафик, используйте логирование:

```bash
# Для nftables (добавить в цепочку)
nft add rule inet filter input counter log prefix "NFT_DROP: " drop

# Просмотр логов в реальном времени
sudo journalctl -kf | grep "DROP"
```

Для анализа состояний соединений используйте утилиту `conntrack`:
```bash
# Список активных трансляций (NAT) и соединений
sudo conntrack -L
```
