# iptables: основы и практические сценарии

## Определения

**Netfilter** — это встроенный в ядро Linux фреймворк для перехвата и манипуляции сетевыми пакетами. Он обеспечивает фильтрацию, трансляцию адресов (NAT) и модификацию пакетов.

**iptables** — классическая утилита командной строки для управления правилами Netfilter. В современных дистрибутивах (Debian 11+, Ubuntu 22.04+, RHEL 8+) она часто заменена на **nftables**, но продолжает использоваться как через слой совместимости (`iptables-nft`), так и в устаревших системах (`iptables-legacy`).

**Stateful Firewall (межсетевой экран с отслеживанием состояния)** — технология фильтрации, которая учитывает контекст соединения (например, пакет является частью уже установленного TCP (Transmission Control Protocol)-сеанса).

## Основные концепции

### Структура: Таблицы и цепочки

iptables организует правила в **таблицы** (по назначению) и **цепочки** (по этапу прохождения пакета).

**Основные таблицы:**

- `filter` — основная таблица для принятия решений о допуске пакета (`ACCEPT`, `DROP`, `REJECT`).
- `nat` — используется для **NAT (Network Address Translation)** (преобразование IP-адресов или портов).
- `mangle` — для специализированной модификации заголовков пакетов (например, изменение TTL).

**Стандартные цепочки таблицы `filter`:**

- `INPUT` — для пакетов, входящих на сам хост.
- `OUTPUT` — для пакетов, созданных локальными процессами.
- `FORWARD` — для пакетов, проходящих через хост транзитом (актуально для роутеров и Docker-хостов).

### Анатомия правила

Каждое правило состоит из **критериев** (match) и **цели** (target). Пакет проверяется правилами цепочки сверху вниз до первого совпадения.

**Основные цели (Targets):**

- `ACCEPT` — пропустить пакет.
- `DROP` — молча отбросить пакет (клиент не получает ответа).
- `REJECT` — отклонить пакет с отправкой уведомления об ошибке (**ICMP (Internet Control Message Protocol)** ответ).
- `LOG` — записать информацию о пакете в системный журнал и продолжить проверку следующих правил.

## Практические сценарии

### 1. Построение базового набора правил

Ниже приведен пример настройки безопасного файрвола для сервера, использующего механизм **Conntrack** для отслеживания состояний.

```bash
# 1. Разрешить уже установленные и связанные соединения (Stateful)
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 2. Разрешить трафик на локальном интерфейсе (loopback)
sudo iptables -A INPUT -i lo -j ACCEPT

# 3. Разрешить входящий SSH (Secure Shell) (порт 22)
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT

# 4. Разрешить веб-трафик (HTTP/HTTPS)
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -m conntrack --ctstate NEW -j ACCEPT

# 5. Разрешить входящий ping (ICMP echo-request)
sudo iptables -A INPUT -p icmp --icmp-type 8 -j ACCEPT

# 6. Установить политики по умолчанию (сначала разрешите SSH, чтобы не потерять доступ!)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
```

### 2. Безопасное применение правил (iptables-apply)

Для предотвращения случайной самоблокировки при настройке удаленного сервера через SSH рекомендуется использовать утилиту `iptables-apply`. Она применит правила и будет ждать подтверждения от пользователя; если подтверждение не получено (например, из-за потери связи), правила будут автоматически откачены.

```bash
# Применить правила из файла с запросом подтверждения
sudo iptables-apply /path/to/rules.txt
```

### 3. Инспекция и отладка

```bash
# Просмотр правил с номерами строк и счетчиками трафика
sudo iptables -nvL --line-numbers

# Удаление конкретного правила по его номеру в цепочке INPUT
sudo iptables -D INPUT 5

# Вставка правила в начало цепочки (позиция 1)
sudo iptables -I INPUT 1 -s 192.168.1.100 -j DROP

# Сброс всех правил (Flush) — ОСТОРОЖНО, может привести к блокировке при политике DROP
sudo iptables -F
```

## Дополнительная информация

### Сохранение конфигурации

По умолчанию правила iptables сбрасываются после перезагрузки. Инструкции по обеспечению персистентности для различных дистрибутивов доступны в разделе **[Сохранение правил между перезагрузками](./firewall_common.md#сохранение-правил-между-перезагрузками)**.

### Взаимодействие с Docker

Docker создает собственные цепочки (например, `DOCKER`, `DOCKER-USER`) и активно манипулирует таблицей `nat`. При ручной настройке `iptables` важно не затирать правила Docker.

Подробнее см. в разделе **[Интеграция Docker с iptables](../../../../Docker/Docker_network/troubleshooting/iptables_integration.md)**.

### Альтернативные инструменты

- **[nftables](./nftables/practical_scenarios.md)** — современная замена iptables (рекомендуется).
- **[UFW — Uncomplicated Firewall](./ufw.md)** — упрощенный интерфейс для Ubuntu/Debian.
- **[Firewalld: динамический межсетевой экран](./firewalld.md)** — управление на основе зон в RHEL-based системах.
