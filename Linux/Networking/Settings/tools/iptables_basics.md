# iptables: основы и практические сценарии

## Определения

**Netfilter** — фреймворк в ядре Linux для фильтрации трафика.

**iptables** — классическая утилита управления правилами Netfilter. В современных системах часто является слоем совместимости над `nftables` (`iptables-nft`).

**Важно:** В Debian 11+ и современных дистрибутивах по умолчанию используется `nftables`. Утилита `iptables` может быть слоем совместимости (`iptables-nft`) или устаревшим режимом (`iptables-legacy`). Для новых проектов рекомендуется использовать `nftables` напрямую.

**Основные концепции:**

- **Stateful Firewall** — фильтрация с отслеживанием состояния соединений
- **Таблицы** — `filter` (фильтрация), `nat` (NAT), `mangle` (модификация заголовков)
- **Цепочки (Chains)** — предопределённые точки применения правил к пакетам

### Цепочки iptables

| Цепочка | Направление | Описание |
| :--- | :--- | :--- |
| **PREROUTING** | Вход | Применяется ко всем входящим пакетам до маршрутизации |
| **INPUT** | Вход | Применяется к пакетам, предназначенным локальному хосту |
| **FORWARD** | Транзит | Применяется к пакетам, проходящим через хост (роутинг) |
| **OUTPUT** | Выход | Применяется к пакетам, созданным локальным хостом |
| **POSTROUTING** | Выход | Применяется ко всем исходящим пакетам после маршрутизации |

## Basic Concepts

### Архитектура iptables

**Правила (Rules):** Состоят из критериев и действия. Пакет сравнивается с правилами по порядку до первого совпадения.

**Действия (Targets):**

| Действие | Описание |
| :--- | :--- |
| `ACCEPT` | Разрешить пакет |
| `DROP` | Молча отбросить (отправитель не получает ответа) |
| `REJECT` | Отклонить с ICMP-сообщением (`connection refused`) |
| `LOG` | Записать в системный лог, обработка продолжается |

**Политика по умолчанию (Default Policy):** Применяется, если пакет не совпал ни с одним правилом. Рекомендуется `DROP` для безопасности.

### DROP vs REJECT

| Параметр | `DROP` | `REJECT` |
| :--- | :--- | :--- |
| **Поведение** | Пакеты молча отбрасываются | Отправляется ICMP-сообщение |
| **Использование** | Внешние сети, интернет | Внутренние доверенные сети |
| **Безопасность** | Скрывает хост, замедляет сканирование | Раскрывает информацию |
| **Отладка** | Затруднена | Упрощена |

**Рекомендация:** `DROP` для внешних интерфейсов, `REJECT` для внутренних сетей.

## Practical Scenarios

### 1. Настройка для веб-сервера

**Золотое правило:** Сначала разрешающие правила, потом политика `DROP`.

```bash
# 1. Разрешить установленные соединения (Stateful)
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 2. Разрешить loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# 3. Разрешить новые соединения (SSH первым!)
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -m conntrack --ctstate NEW -j ACCEPT

# 4. Разрешить ICMP (ping)
sudo iptables -A INPUT -p icmp --icmp-type 8 -j ACCEPT

# 5. Установить политику DROP
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT  # Обычно оставляют ACCEPT
```

### 2. Безопасное применение (iptables-apply)

При настройке удалённого сервера через SSH используйте `iptables-apply` — она автоматически откатывает правила при потере соединения:

```bash
# Применить правила из файла с подтверждением
sudo iptables-apply rules.txt

# Тестовый режим с автооткатом
sudo iptables-apply --test
```

### 3. Полезные команды

```bash
# Просмотр правил с номерами и счётчиками
sudo iptables -nvL --line-numbers

# Вставить правило на позицию 1 в INPUT
sudo iptables -I INPUT 1 -s 1.2.3.4 -j DROP

# Удалить правило по номеру
sudo iptables -D INPUT 1

# Сброс всех правил и счётчиков (ОПАСНО!)
sudo iptables -F
sudo iptables -X
```

## Additional Information

### Сохранение правил

Правила не сохраняются после перезагрузки. См. **[Общие вопросы: сохранение правил](./firewall_common.md#сохранение-правил-между-перезагрузками)**.

### Docker и iptables

Docker добавляет свои правила в цепочки `DOCKER` и `FORWARD`. Для безопасной настройки используйте цепочку `DOCKER-USER`.

См. **[Взаимодействие Docker и файрвола](./firewall_common.md#взаимодействие-docker-и-файрвола)**.

- **[ufw](#)** — упрощённый интерфейс для Ubuntu
- **[firewalld](./firewalld.md)** — динамический менеджер для RHEL/CentOS
