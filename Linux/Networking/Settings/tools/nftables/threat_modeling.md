# nftables — моделирование угроз и схемы защиты

## Определения

**Моделирование угроз** — процесс выявления потенциальных атак и разработки мер защиты для конкретной системы или сети.

**DoS (Denial of Service — отказ в обслуживании)** — атака, целью которой является доведение информационной системы до состояния, при котором она не может обрабатывать запросы легитимных пользователей.

**IP-спуфинг (Internet Protocol spoofing — подмена IP-адреса)** — вид атаки, заключающийся в использовании чужого IP-адреса с целью обмана системы безопасности.

## Основные концепции

### Алгоритм моделирования угроз

Для настройки межсетевого экрана nftables рекомендуется следующий алгоритм:

1. **Формулирование модели угроз** — выявление актуальных рисков для конкретного узла.
2. **Анализ и разработка схемы разграничения** — определение перечня разрешенного и запрещенного трафика.
3. **Реализация правил** — трансляция выбранной схемы в синтаксис nftables.

### Источники данных об угрозах

- [MITRE ATT&CK Matrix](https://attack.mitre.org/)
- [Банк данных угроз ФСТЭК России](https://bdu.fstec.ru/)

### Типовые угрозы для серверов и рабочих станций

| Угроза | Описание | Меры нейтрализации в nftables |
| :--- | :--- | :--- |
| **Эксплуатация уязвимостей** | Атаки на сетевые сервисы через программные ошибки | Ограничение входящего трафика по портам и доверенным IP-адресам |
| **DoS через перегрузку** | Исчерпание ресурсов системы огромным количеством запросов | Использование `rate limiting` (ограничение частоты) и динамических списков |
| **IP-спуфинг (127.0.0.0/8)** | Подделка обратного адреса для доступа к локальным сервисам | Отбрасывание пакетов с адресами loopback-сети, приходящих не с loopback-интерфейса |
| **Брутфорс аутентификации** | Автоматизированный подбор паролей к сервисам (например, SSH) | Ограничение попыток подключения через `meter` или интеграция с Fail2ban |
| **Вредоносный исходящий трафик** | Активность троянов, майнеров или утечка данных | Настройка строгих правил для исходящего (Egress) трафика |
| **Несанкционированные порты** | Работа вредоносного ПО на нестандартных портах | Политика `DROP` по умолчанию для всех входящих соединений |

## Практические сценарии

### Схемы разграничения трафика

#### №1. Минимальная защита рабочей станции

- **Описание**: Разрешен любой исходящий трафик. Входящий трафик разрешен только для уже установленных соединений (`established`, `related`).
- **Защита**: Эффективна против большинства внешних сканирований и попыток прямого подключения к системе. Не защищает от утечек данных.

#### №2. Минимальная защита сервера

- **Описание**: Как в схеме №1, но с дополнительным разрешением портов конкретных сервисов (HTTP/HTTPS, SSH) и обязательной защитой от IP-спуфинга.
- **Защита**: Базовый уровень для публично доступных серверов.

#### №3. Стандартная защита сервера

- **Описание**: Как в схеме №2, но с ограничением исходящего трафика. Разрешены только необходимые соединения (например, к репозиториям обновлений или DNS-серверам).
- **Защита**: Предотвращает несанкционированную передачу данных вовне при компрометации сервера.

#### №4. Усиленная защита сервера

- **Описание**: Включает в себя схему №3, дополненную механизмами `rate limiting`, белыми списками IP-адресов администраторов и защитой от перебора паролей.
- **Защита**: Максимальный уровень безопасности для критически важных систем.
