# nftables — тестирование правил файрвола

## Определения

**Тестирование файрвола** — процесс верификации настроенных правил фильтрации для подтверждения того, что разрешен только необходимый трафик, а все остальные порты и протоколы корректно заблокированы.

**Белый ящик (White Box)** — тестирование изнутри системы, включающее проверку слушающих сокетов и локальных таблиц правил.

**Черный ящик (Black Box)** — тестирование системы извне (из другой сети) с целью обнаружения открытых портов и уязвимых сервисов.

## Основные концепции

### Методология проверки

Для качественной проверки nftables рекомендуется сочетать локальный аудит и удаленное сканирование:

1. **Локальный аудит**: Проверка, какие порты реально слушают приложения на всех интерфейсах (`0.0.0.0`) или конкретных IP.
2. **Эмуляция сервисов**: Открытие временных портов в тех диапазонах, которые должны быть заблокированы, для проверки реакции файрвола.
3. **Удаленное сканирование**: Попытка подключения к портам с другого узла.

### Реакция на пакеты (DROP vs REJECT)

При тестировании важно обращать внимание на состояние портов в выводе сканеров:

- **Filtered (DROP)**: Файрвол молча отбрасывает пакет. Сканер долго ждет ответа (таймаут). Это стандарт для публичных интерфейсов.
- **Closed (REJECT)**: Файрвол возвращает ICMP-ответ об ошибке. Сканер мгновенно определяет, что порт закрыт. Обычно используется во внутренних сетях.

## Практические сценарии

### Шаг 1. Локальная проверка слушающих портов

Используйте современную утилиту `ss` для просмотра всех ожидающих соединение сокетов.

```bash
# Просмотр всех слушающих TCP (-t) и UDP (-u) портов с именами процессов (-p)
sudo ss -tulpn
```

*Подробнее см.: **[Анализ сокетов с помощью ss](../../../../Diagnostics/Networking/ss.md)***

### Шаг 2. Эмуляция сервисов на закрытых портах

Для проверки того, что файрвол реально блокирует трафик на портах, где нет живых сервисов, их можно временно «открыть» с помощью `nc` (netcat).

```bash
# Эмуляция UDP-сервиса на порту 100
echo "UDP Test" | nc -lu 100

# Эмуляция TCP-сервиса на порту 300
echo "TCP Test" | nc -lt 300
```

*Примечание: без ключа `-k` утилита `nc` завершится после получения первого пакета/соединения.*

### Шаг 3. Удаленное сканирование портов

Выполните сканирование с другого сервера в той же сети.

```bash
# TCP-сканирование конкретного порта
nmap -p 300 <IP-адрес_сервера>

# UDP-сканирование конкретного порта (требует прав root)
sudo nmap -sU -p 100 <IP-адрес_сервера>
```

*Подробнее см.: **[nmap (Network Mapper)](../../../../Diagnostics/Networking/nmap.md)***

### Автоматизация: Скрипт массового открытия портов

Если нужно проверить блокировку целого диапазона портов, используйте скрипт `openport.sh`.

```bash
#!/bin/bash
# Использование: ./openport.sh <UDP|TCP> <start_port> <end_port>

PROTOCOL=$1
START_PORT=$2
END_PORT=$3

if [[ $# != 3 ]]; then
    echo "Usage: $0 <UDP|TCP> <start_port> <end_port>"
    exit 1
fi

for (( x=$START_PORT; x<=$END_PORT; x++ )); do
    if [ "$PROTOCOL" == "UDP" ]; then
        nc -lu $x &
    elif [ "$PROTOCOL" == "TCP" ]; then
        nc -lt $x &
    else
        echo "Error: invalid protocol. Use TCP or UDP."
        exit 1
    fi
    echo "Opened $PROTOCOL port: $x"
done
```

**Пример использования:**

```bash
# Открыть диапазон TCP 1-50 для теста
chmod +x openport.sh
./openport.sh TCP 1 50

# После теста завершите процессы nc
pkill nc
```
