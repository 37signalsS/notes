# nftables — тестирование и верификация правил

## Определения

**Тестирование межсетевого экрана** — комплекс мероприятий по проверке корректности работы правил фильтрации, направленный на подтверждение доступности разрешённых ресурсов и блокировку запрещённых векторов трафика.

**Позитивное тестирование** — проверка того, что разрешённый трафик (например, на порт 80 или 443) беспрепятственно проходит через фильтры.

**Негативное тестирование** — проверка того, что несанкционированный трафик (на закрытые порты или от запрещённых источников) корректно отбрасывается файрволом.

**Синтаксическая валидация** — проверка корректности структуры и параметров правил без их фактического применения в ядре.

## Основные концепции

### Методология верификации

Эффективная проверка конфигурации nftables строится на трёх уровнях:

1.  **Уровень конфигурации (Static):** Проверка синтаксиса и логики до загрузки правил.
2.  **Уровень локальной системы (Host-side):** Проверка состояния сокетов и интерфейсов.
3.  **Уровень сетевого взаимодействия (Network-side):** Имитация действий пользователя и злоумышленника с внешних узлов.

### Типы ответов при тестировании

При сканировании портов (например, с помощью `nmap`) крайне важно интерпретировать состояние порта:

| Состояние | Действие файрвола | Технический смысл |
| :--- | :--- | :--- |
| **Open** | `accept` | Пакет принят, приложение ответило. |
| **Filtered** | `drop` | Пакет отброшен "молча". Сканер ожидает таймаута. |
| **Closed** | `reject` | Файрвол ответил ICMP-сообщением об ошибке (Port Unreachable). |

## Практические сценарии

### 1. Проверка синтаксиса без применения правил

Прежде чем применить изменения, которые могут заблокировать доступ (особенно по SSH), необходимо выполнить проверку файла конфигурации.

```bash
# Проверка файла на наличие ошибок синтаксиса
sudo nft --check --file /etc/nftables.conf
# → (если вывода нет, ошибок не обнаружено)
```

### 2. Локальный аудит активных сервисов

Перед тестированием файрвола нужно понимать, какие порты реально слушают приложения.

```bash
# Вывод всех слушающих TCP и UDP сокетов с числовыми значениями портов
sudo ss -tunlp
```

*Дополнительно:* если порт слушает только на `127.0.0.1`, он не будет доступен извне независимо от настроек nftables.

### 3. Эмуляция сервисов для проверки блокировки

Если на сервере нет запущенного приложения, но нужно проверить правило `DROP`, можно использовать `netcat`.

```bash
# Запуск временного TCP-сервера на порту 8888
nc -l -p 8888

# Запуск временного UDP-сервера на порту 9999
nc -l -u -p 9999
```

### 4. Внешнее сканирование (Черный ящик)

Выполняется с удалённого узла.

```bash
# Быстрое сканирование основных TCP-портов
nmap -F <Target_IP>

# Проверка конкретного порта и определение версии службы
nmap -p 22 -sV <Target_IP>

# Сканирование UDP-портов (требует прав root, выполняется долго)
sudo nmap -sU -p 53,123,161 <Target_IP>
```

### 5. Мониторинг срабатывания правил в реальном времени

Если в правилах nftables используется действие `log`, вы можете отслеживать отброшенные пакеты.

```bash
# Просмотр логов файрвола через journalctl
sudo journalctl -f -k | grep "nftables"

# Альтернативно через dmesg
sudo dmesg -w | grep "IN="
```

### Автоматизация: Скрипт массовой проверки портов

Скрипт для автоматизированного открытия портов на стороне сервера для проведения тестов.

```bash
#!/bin/bash
# Использование: ./firewall-tester.sh <TCP|UDP> <start_port> <end_port>

TYPE=$1
START=$2
END=$3

case $TYPE in
    TCP) CMD="nc -lk -p" ;;
    UDP) CMD="nc -luk -p" ;;
    *) echo "Используйте TCP или UDP"; exit 1 ;;
esac

echo "Запуск эмуляции $TYPE на портах $START-$END..."

for port in $(seq $START $END); do
    $CMD $port > /dev/null 2>&1 &
done

echo "Для остановки выполните: pkill nc"
```

## Дополнительная информация

### Важные замечания

- **Таймауты в UDP:** Тестирование UDP сложнее, так как протокол не гарантирует доставку. nmap может пометить порт как `open|filtered`, если не получил ответа ICMP.
- **Connection Tracking:** Помните, что nftables отслеживает состояния. Если ваше соединение уже установлено (`established`), изменение правил может не повлиять на него до разрыва сессии.
