# nftables — архитектура и основные концепции

## Определения

**nftables** — современная подсистема ядра Linux для фильтрации и классификации сетевых пакетов, пришедшая на смену классическому набору `iptables`, `ip6tables`, `ebtables` и `arptables`.

**Netfilter** — фреймворк внутри ядра Linux, предоставляющий хуки (hooks) для перехвата и манипуляции сетевыми пакетами. nftables является основным пользовательским интерфейсом для взаимодействия с Netfilter в современных дистрибутивах.

**IPv4 (Internet Protocol version 4)** — четвёртая версия сетевого протокола IP.

**IPv6 (Internet Protocol version 6)** — новая версия протокола IP с расширенным адресным пространством.

**ARP (Address Resolution Protocol)** — протокол определения MAC-адреса по IP-адресу.

**ICMP (Internet Control Message Protocol)** — протокол межсетевых управляющих сообщений.

## Основные концепции

### Ключевые особенности nftables

- **Единая утилита**: `nft` заменяет все специализированные утилиты семейства iptables.
- **Единый стек протоколов**: Семейство `inet` позволяет обрабатывать IPv4 и IPv6 в рамках одной таблицы и цепочки.
- **Производительность**: Более эффективная обработка правил за счет использования виртуальной машины (VM) в ядре, которая исполняет байт-код правил.
- **Гибкая структура**: В nftables отсутствуют предопределённые таблицы. Пользователь сам создает необходимую иерархию.
- **Встроенные объекты**: Нативная поддержка сетов (наборов), словарей (maps), квот и лимитов.

### Архитектурные компоненты

| Компонент | Описание |
| :--- | :--- |
| **Таблицы (tables)** | Контейнеры верхнего уровня для цепочек. Привязаны к конкретному семейству протоколов. |
| **Цепочки (chains)** | Группы правил. Бывают **базовые** (привязаны к хуку Netfilter) и **обычные** (используются для логической организации). |
| **Правила (rules)** | Конкретные инструкции, состоящие из критериев соответствия и действий. |
| **Сеты (sets)** | Коллекции элементов (IP-адреса, порты) для быстрого поиска в одном правиле. |
| **Мапы (maps)** | Словари "ключ-значение" (например, IP-адрес -> действие). |
| **Хэндлы (handles)** | Уникальные числовые идентификаторы объектов, необходимые для точечного изменения или удаления. |

### Семейства таблиц

| Семейство | Описание |
| :--- | :--- |
| `inet` | Объединенная обработка IPv4 и IPv6 (рекомендуется для большинства задач). |
| `ip` | Только IPv4-трафик. |
| `ip6` | Только IPv6-трафик. |
| `arp` | Фильтрация ARP-пакетов. |
| `bridge` | Обработка трафика на уровне сетевого моста (L2). |
| `netdev` | Фильтрация на самом раннем этапе (ingress) сразу после получения пакета сетевым интерфейсом. |

### Хуки (hooks) и приоритеты

Базовые цепочки перехватывают пакеты на определенных этапах прохождения через сетевой стек.

| Хук (Hook) | Описание | Приоритеты (стандартные значения) |
| :--- | :--- | :--- |
| `prerouting` | Пакет только что поступил (до принятия решения о маршрутизации). | `raw` (-300), `dstnat` (-100) |
| `input` | Пакет предназначен для локального хоста. | `filter` (0) |
| `forward` | Пакет проходит через хост транзитом. | `filter` (0) |
| `output` | Пакет создан локальным процессом. | `filter` (0), `srcnat` (100) |
| `postrouting` | Пакет готов к отправке (после маршрутизации). | `srcnat` (100) |

### Основные действия (Verdicts)

| Действие | Описание |
| :--- | :--- |
| `accept` | Разрешить прохождение пакета. Прекращает обработку в текущей таблице. |
| `drop` | Молча отбросить пакет. |
| `reject` | Отклонить пакет с отправкой уведомления (ICMP-сообщения). |
| `log` | Записать информацию о пакете в системный журнал. |
| `jump <chain>` | Перейти в указанную цепочку и вернуться после её обработки. |
| `goto <chain>` | Перейти в указанную цепочку без возврата. |

## Практические сценарии

### Синтаксис командной строки nft

Основной формат команды:
`nft <команда> <объект> <семейство> <таблица> <цепочка> <параметры>`

**Основные команды:**

- `add` — добавить новый объект.
- `delete` — удалить объект (часто по хэндлу).
- `list` — вывести текущую конфигурацию.
- `flush` — очистить содержимое (таблицы или набора правил).

### Примеры использования

```bash
# Просмотр всех правил с выводом хэндлов
nft -a list ruleset

# Добавление правила в цепочку input семейства inet (разрешить SSH на 22 порту)
nft add rule inet my_table my_input tcp dport 22 accept

# Удаление правила по его хэндлу
nft delete rule inet my_table my_input handle 5

# Использование интервалов в правилах
nft add rule inet my_table my_input ip saddr { 192.168.1.0-192.168.1.50 } drop
```

## Дополнительная информация

### Важные замечания по эксплуатации

1. **Отсутствие предопределенных таблиц**: В отличие от iptables, команды `nft` завершатся ошибкой, если вы попытаетесь добавить правило в таблицу, которая еще не создана. Сначала необходимо создать таблицу и базовую цепочку.
2. **Порядок обработки**: В nftables пакет проходит через ВСЕ базовые цепочки с одинаковым хуком, даже если в одной из них он был принят (`accept`). Пакет отбрасывается немедленно при первом совпадении с действием `drop`.
3. **Миграция**: Для автоматического перевода правил с iptables используйте утилиту `iptables-translate`.
