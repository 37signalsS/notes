# nftables: архитектура и основные концепции

## Определения

**nftables** — современная подсистема Linux для фильтрации сетевого трафика, заменяющая `iptables`, `ip6tables`, `ebtables` и `arptables`. Использует фреймворк **Netfilter** и предоставляет более производительный и гибкий синтаксис.

**Важно:** В Debian 11+ и современных дистрибутивах `iptables` по умолчанию отсутствует — используется `nftables`. Для миграции существуют утилиты `iptables-translate`, `iptables-restore-translate` (пакет `iptables`).

**Ключевые особенности:**

- Единая утилита `nft` заменяет четыре прежних (`iptables`/`ip6tables`/`ebtables`/`arptables`)
- Единый синтаксис для IPv4/IPv6 (семейство `inet`)
- Более производительная обработка правил
- Иерархическая структура: таблицы → цепочки → правила
- Встроенные сеты (наборы), мапы, квоты, лимиты
- Динамические сеты с таймаутами для защиты от брутфорса

**Предупреждение:** Правила, сконвертированные через `iptables-translate`, могут не работать без создания необходимых таблиц и цепочек — в nftables нет предопределённых таблиц, их нужно создавать явно.

## Архитектура nftables

| Компонент | Описание |
| :--- | :--- |
| **Таблицы (tables)** | Контейнеры для цепочек (например, `inet filter`, `ip nat`). **Нет предопределённых таблиц** — создаются пользователем |
| **Цепочки (chains)** | Контейнеры для правил с указанием hook и priority. Бывают **базовые** (получают пакеты из хука) и **обычные** (для группировки правил) |
| **Правила (rules)** | Условия и действия для пакетов. Добавляются через `add rule`, удаляются по `handle` |
| **Сеты (sets)** | Наборы значений (IP, порты) для эффективного сопоставления. Бывают **именованные** (изменяемые) и **анонимные** (в строке правила) |
| **Мапы (maps)** | Сопоставление значений (например, IP → действие). Бывают **verdict maps** (ключ → действие) |
| **Хэндлы (handle)** | Уникальные идентификаторы правил в таблице. Используются для удаления/изменения правил |

### Семейства таблиц

| Семейство | Описание |
| :--- | :--- |
| `inet` | IPv4 + IPv6 (универсальное) |
| `ip` | Только IPv4 |
| `ip6` | Только IPv6 |
| `arp` | ARP-пакеты |
| `bridge` | Мосты (bridge) |
| `netdev` | Фильтрация на уровне устройства (raw data) |

### Хуки (hooks) и приоритеты

Цепочки получают пакеты из хуков. Порядок обработки определяется **приоритетом** (чем ниже число, тем раньше обработка).

| Хук | Направление | Приоритеты (зарезервированные слова) |
| :--- | :--- | :--- |
| `prerouting` | Вход (до маршрутизации) | `dstnat` (-100) |
| `input` | Вход (локальный хост) | `filter` (0) |
| `forward` | Транзит | `filter` (0) |
| `output` | Выход (локальный хост) | `filter` (0), `srcnat` (100) |
| `postrouting` | Выход (после маршрутизации) | `srcnat` (100) |

**Типы базовых цепочек:**

- `filter` — стандартный тип для любого хука
- `nat` — для NAT (обрабатывается только первый пакет соединения)
- `route` — для маркировки пакетов (хук `output`)

### Основные действия

| Действие | Описание |
| :--- | :--- |
| `accept` | Разрешить пакет |
| `drop` | Молча отбросить |
| `reject` | Отклонить с ICMP-сообщением |
| `log` | Записать в лог |
| `limit rate X/minute` | Ограничить частоту |
| `jump <chain>` | Переход на обычную цепочку (возврат к следующему правилу) |
| `goto <chain>` | Переход на обычную цепочку (возврат к policy по умолчанию) |
| `return` | Досрочный выход из цепочки |
| `continue` | Продолжить обработку в текущей цепочке |

## Синтаксис командной строки

```
nft <команда> <объект> <путь> <параметры>
```

**Команды:** `add`, `create`, `delete`, `list`, `flush`, `insert`, `replace`, `rename`

**Объекты:** `table`, `chain`, `rule`, `set`, `map`, `quota`, `limit`, `counter`, `ruleset`

**Примеры:**

```bash
# Добавить правило
nft add rule inet filter input iif eth0 tcp dport 22 accept

# Просмотр правил с хэндлами
nft -a list chain inet filter input

# Удалить правило по хэндлу
nft delete rule inet filter input handle 4

# Вставить правило по индексу (перед 3-м правилом)
nft insert rule inet filter output index 3 tcp dport 2300-2400 drop comment "Block games ports"
```

**Интервалы:** Работают в правилах, сетах, словарях

```bash
# Порты
tcp dport { 22, 80, 443 }
tcp dport 2300-2400

# IP-адреса
ip saddr { 192.168.1.1-192.168.1.50, 10.0.0.0/8 }
```
