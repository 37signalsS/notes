# nftables — паттерн OneButtonFirewall (прозрачный мост)

## Определения

**OneButtonFirewall (OBF)** — паттерн конфигурации межсетевого экрана, минимизирующий ручную настройку за счет использования топологической изоляции и принципа "диода". Основная идея заключается в создании барьера, который прозрачен для исходящего трафика и блокирует любой неинициированный входящий трафик.

**IP-диод (IP Diode)** — архитектурный принцип сетевой безопасности, при котором трафик может безусловно проходить только в одном направлении (из защищаемого сегмента во внешний), а в обратном направлении разрешаются только пакеты, принадлежащие уже установленным (ESTABLISHED) или связанным (RELATED) соединениям.

**Прозрачный мост (Transparent Bridge)** — режим работы сетевого устройства, при котором оно пересылает кадры на уровне L2 (Ethernet), не имея собственного IP-адреса в сегменте и не требуя изменения настроек маршрутизации (Default Gateway) на защищаемых узлах.

## Основные концепции

### Принцип работы OBF

Паттерн реализуется на уровне L2 в семействе `bridge`. Межсетевой экран физически помещается в разрыв сети между защищаемыми узлами и остальной инфраструктурой.

1.  **Зонирование интерфейсов:** Порты моста делятся на `internal` (доверенные) и `external` (недоверенные).
2.  **Stateful-фильтрация на L2:** Используется механизм отслеживания состояний (`conntrack`) для автоматического разрешения ответов из внешней сети на запросы из внутренней.
3.  **Обработка служебного трафика:**
    *   **ARP:** Безусловное разрешение для работы разрешения MAC-адресов.
    *   **DHCP:** Разрешение для автоматического получения IP-адресов.
    *   **IPv6 NDP:** Разрешение Multicast-сообщений (Neighbor Discovery) для работы IPv6.
4.  **Broadcast/Multicast:** Ограниченное разрешение для обеспечения работы сетевого окружения.

### Системные требования

Для корректной работы Stateful-фильтрации в режиме моста на старых ядрах (или в специфичных дистрибутивах) может потребоваться модуль `br_netfilter` и соответствующие настройки `sysctl`, однако современные версии `nftables` поддерживают conntrack в семействе bridge нативно.

```bash
# Загрузка модуля (если conntrack в bridge не срабатывает)
sudo modprobe br_netfilter

# Включение передачи трафика моста в netfilter
sudo sysctl -w net.bridge.bridge-nf-call-iptables=1
sudo sysctl -w net.bridge.bridge-nf-call-ip6tables=1
```

## Практические сценарии

### 1. Эталонная конфигурация nftables (L2 Bridge)

Данный набор правил создает "невидимый" барьер. Предполагается, что интерфейс `external` смотрит во внешнюю сеть, а остальные порты моста — во внутреннюю.

```bash
#!/usr/sbin/nft -f

flush ruleset

table bridge firewall {
    chain fw_forward {
        type filter hook forward priority filter; policy drop;

        # 1. Разрешить ARP (Address Resolution Protocol)
        ether type arp accept

        # 2. Разрешить весь трафик из внутренней сети наружу (IP-диод)
        iifname != "external" accept

        # 3. Разрешить ответы на установленные соединения (Stateful)
        # Обрабатывает IPv4 и IPv6
        ct state established,related accept

        # 4. Разрешить IPv6 Neighbor Discovery (NDP)
        # Критично для работы IPv6 в прозрачном режиме
        ip6 nexthdr icmpv6 icmpv6 type { nd-neighbor-solicit, nd-neighbor-advert, nd-router-solicit, nd-router-advert } accept

        # 5. Разрешить DHCP (IPv4)
        udp dport 67-68 accept

        # 6. Разрешить широковещательный трафик (Broadcast IPv4)
        # Для работы NetBIOS и сетевого обнаружения Windows
        pkttype broadcast ip daddr 255.255.255.255 accept
    }
}
```

### 2. Настройка сетевого моста (Netplan — Ubuntu/Debian)

Современный способ настройки интерфейсов для работы OBF.

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0: { dhcp4: no } # External
    enp2s0: { dhcp4: no } # Internal 1
    enp3s0: { dhcp4: no } # Internal 2
  bridges:
    br0:
      interfaces: [enp1s0, enp2s0, enp3s0]
      parameters:
        stp: false # Отключить STP для минимизации задержек в простых топологиях
      dhcp4: no
      accept-ra: no
```

### 3. Настройка сетевого моста (Legacy interfaces)

Для старых версий Debian или систем без Netplan.

```bash
# /etc/network/interfaces
auto br0
iface br0 inet manual
    bridge_ports enp1s0 enp2s0 enp3s0
    bridge_stp off
    up ip link set $IFACE up
```

## Дополнительная информация

### Преимущества паттерна

*   **Нулевая конфигурация узлов:** Не нужно менять IP-адреса, маски или шлюзы на защищаемых серверах.
*   **Скрытность (Stealth):** Устройство защиты не имеет IP-адреса, его невозможно просканировать или атаковать напрямую по сети.
*   **Универсальность:** Работает с любыми ОС (Windows, Linux, IoT-устройства).

### Ограничения и риски

*   **Отсутствие L3-изоляции:** Все узлы внутри моста находятся в одном L2-домене. OBF не защищает от атак "узел-узел" внутри доверенного сегмента.
*   **Сложность отладки:** Поскольку устройство прозрачно, при ошибках в правилах пакеты просто пропадают без видимых причин в логах шлюзов.
*   **IPv6 SLAAC:** В прозрачном режиме автоконфигурация IPv6 может работать некорректно без явного разрешения всех типов ICMPv6, необходимых для обнаружения маршрутизаторов.
