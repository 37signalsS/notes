# nftables — паттерн OneButtonFirewall

## Определения

**OneButtonFirewall (OBF)** — паттерн настройки межсетевого экрана, минимизирующий необходимость ручного конфигурирования правил за счет использования топологической изоляции.

**IP-диод (Internet Protocol Diode)** — архитектурный принцип сетевой безопасности, при котором трафик может безусловно проходить только в одном направлении (из защищаемого сегмента во внешний), а в обратном направлении разрешаются только пакеты, принадлежащие уже установленным соединениям.

## Основные концепции

Паттерн OneButtonFirewall реализуется на уровне L2 (канальный уровень) в режиме моста (bridge). Это позволяет внедрять защиту в существующую сеть без изменения IP-адресации узлов.

### Принцип работы

1. **Сегментация портов**: Интерфейсы межсетевого экрана жестко делятся на "внутренние" (защищаемый сегмент) и "внешние" (недоверенный сегмент).
2. **Направленная фильтрация**:
    - Трафик из внутреннего сегмента во внешний разрешен полностью.
    - Трафик из внешнего сегмента во внутренний разрешен только для состояний `ESTABLISHED` (установлено) и `RELATED` (связано).
3. **Обработка широковещательного трафика**: Разрешается широковещательный трафик (Broadcast) для обеспечения работы базовых сетевых протоколов в Windows-средах.
4. **Служебные исключения**: Явное разрешение для протокола DHCP (Dynamic Host Configuration Protocol) для корректного получения сетевых настроек узлами.

## Практические сценарии

### Конфигурация nftables (L2 Bridge)

Данная конфигурация создает "невидимый" барьер, работающий по принципу диода.

```bash
#!/usr/sbin/nft -f

# Очистка текущих правил
flush ruleset

table bridge firewall {
    chain fw_forward {
        # Политика по умолчанию — отбрасывать пакеты
        type filter hook forward priority filter; policy drop;

        # 1. Разрешить весь трафик между внутренними портами
        # и трафик от внутренних портов к внешнему
        iifname != "external" accept

        # 2. Разрешить IPv4-трафик по уже установленным соединениям (обратный путь)
        ether type ip ct state established,related accept

        # 3. Разрешить весь IPv4-трафик с широковещательными MAC-адресами
        # (MAC — Media Access Control)
        ether type ip ether daddr ff:ff:ff:ff:ff:ff accept

        # 4. Исключение для DHCP (UDP 68)
        # Нужно для получения адреса Linux-клиентами во внутреннем сегменте
        # (UDP — User Datagram Protocol)
        udp dport 68 accept
    }
}
```

### Настройка сетевых интерфейсов (Debian/Ubuntu)

Для работы nftables в режиме моста необходимо объединить физические интерфейсы в программный мост `br0`.

```bash
# /etc/network/interfaces

auto lo
iface lo inet loopback

# Физические интерфейсы переводим в ручной режим
iface external inet manual
iface ens36 inet manual
iface ens37 inet manual
iface ens38 inet manual

# Создание моста
auto br0
iface br0 inet manual
    bridge_ports external ens36 ens37 ens38
```

## Дополнительная информация

### Преимущества

- **Zero Configuration**: Не требует написания детальных списков контроля доступа (ACL).
- **Топологическая гибкость**: Автоматически адаптируется при изменении количества узлов во внутреннем сегменте.
- **Скрытность (Stealth)**: Межсетевой экран не имеет собственного IP-адреса в защищаемом сегменте, что затрудняет его обнаружение и атаку.

### Недостатки

- **Отсутствие гранулярности**: Невозможно ограничить трафик между узлами внутри одного сегмента.
- **Риск широковещательного шторма**: Неограниченный Broadcast-трафик может быть использован для DoS-атак на канальном уровне.
- **Неселективность**: Не подходит для сред, где требуется строгая микросегментация.
