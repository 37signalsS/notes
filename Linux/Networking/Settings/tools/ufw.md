# UFW — Uncomplicated Firewall

## Определения

**UFW (Uncomplicated Firewall)** — это высокоуровневый интерфейс для управления правилами межсетевого экрана, разработанный для упрощения настройки `iptables` и `nftables`. Является стандартом по умолчанию в дистрибутиве Ubuntu и широко используется в Debian.

Основная цель UFW — предоставить интуитивно понятный синтаксис для базовых задач фильтрации трафика, не требуя глубоких знаний синтаксиса Netfilter.

## Основные концепции

### Принципы работы

1.  **Default Deny Incoming:** по умолчанию весь входящий трафик блокируется.
2.  **Default Allow Outgoing:** исходящий трафик разрешен для обеспечения работы обновлений и внешних запросов.
3.  **Stateful Inspection:** UFW отслеживает состояние соединений (ESTABLISHED, RELATED), автоматически разрешая ответный трафик.
4.  **Application Profiles:** поддержка профилей приложений (хранятся в `/etc/ufw/applications.d/`), которые позволяют открывать порты по имени сервиса (например, `Nginx Full`).

### Архитектура и бэкенд

В современных дистрибутивах (Ubuntu 22.04+, Debian 11+) UFW использует **nftables** в качестве бэкенда через уровень совместимости `iptables-nft`. Это обеспечивает лучшую производительность и корректную обработку IPv4 и IPv6 в рамках единого набора правил.

### Базовое управление

```bash
sudo ufw status                # Проверка статуса
# → Status: active (или inactive)

sudo ufw enable                # Включение файрвола (загрузка правил)
# → Firewall is active and enabled on system startup

sudo ufw disable               # Выключение файрвола
# → Firewall stopped and disabled on system startup

sudo ufw reload                # Перезагрузка правил без разрыва соединений
```

## Практические сценарии

### 1. Начальная настройка ("Безопасный старт")

**Задача:** настроить базовые политики и обеспечить доступ по SSH перед включением файрвола, чтобы не потерять доступ к удаленному серверу.

```bash
# 1. Установка политик по умолчанию
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 2. Разрешение SSH с защитой от брутфорса
# limit ограничивает количество попыток подключения (6 попыток за 30 секунд)
sudo ufw limit ssh
# → Rule added

# 3. Включение файрвола
sudo ufw enable

# 4. Проверка расширенного статуса
sudo ufw status verbose
# → Status: active
# → Logging: on (low)
# → Default: deny (incoming), allow (outgoing), disabled (routed)
```

### 2. Работа с портами и протоколами

```bash
# Разрешить входящий TCP трафик на порт 80 (HTTP)
sudo ufw allow 80/tcp

# Разрешить диапазон портов для пассивного FTP
sudo ufw allow 40000:40100/tcp

# Добавление комментария к правилу для аудита
sudo ufw allow 8080/tcp comment 'Custom API Service'
```

### 3. Ограничение доступа по IP и интерфейсам

```bash
# Разрешить доступ к БД PostgreSQL только с конкретного IP
sudo ufw allow from 192.168.1.50 to any port 5432

# Разрешить трафик только на конкретном сетевом интерфейсе (например, локальная сеть)
sudo ufw allow in on eth1 to any port 3306

# Разрешить доступ ко всей подсети
sudo ufw allow from 10.0.0.0/24
```

### 4. Профили приложений

```bash
# Список доступных профилей
sudo ufw app list

# Просмотр деталей профиля
sudo ufw app info "Nginx Full"

# Разрешение профиля
sudo ufw allow "Nginx Full"
```

### 5. Удаление и модификация правил

```bash
# Просмотр правил с номерами (удобно для удаления)
sudo ufw status numbered
# → [ 1] 22/tcp                     LIMIT IN    Anywhere

# Удаление правила по номеру
sudo ufw delete 1

# Сброс всех правил к заводским настройкам (отключение и удаление правил)
sudo ufw reset

# Тестовый прогон (dry-run) — просмотр изменений без их применения
sudo ufw --dry-run allow 9000
```

## Дополнительная информация

### Взаимодействие с Docker (Проблема Bypass)

**Критическая особенность:** Docker по умолчанию манипулирует цепочками `iptables` (в частности `PREROUTING`) напрямую, что позволяет трафику попадать в контейнеры в обход правил `INPUT` в UFW. Если вы опубликовали порт (`-p 80:80`), он будет доступен извне, даже если UFW говорит `deny`.

**Рекомендации:**
- Используйте пакет **[ufw-docker](https://github.com/chaifeng/ufw-docker)** для автоматической синхронизации правил.
- Привязывайте порты к `127.0.0.1` (`-p 127.0.0.1:80:80`) и используйте Reverse Proxy (Nginx/Angie).
- Подробнее см. в разделе **[Docker — сеть](../../../../Docker/Docker_network/docker_network.md)**.

### Логирование

UFW поддерживает несколько уровней логирования: `low` (по умолчанию), `medium`, `high`, `full`.

```bash
sudo ufw logging medium
```
Логи обычно записываются в `/var/log/ufw.log` и системный журнал `journald`.

### IPv6

UFW автоматически управляет правилами IPv6, если в файле `/etc/default/ufw` установлено `IPV6=yes`. Большинство команд (например, `allow 80`) создают правила сразу для обоих протоколов.

### Влияние на сканирование (Nmap)

При политике `deny` (которая использует действие `DROP`), сканирование портов замедляется, так как `nmap` не получает ответов и ожидает таймаута. Порты отображаются как `filtered`.
