## Определения

**IPv6-поддержка в сервисах** — способность приложения прослушивать сокеты IPv6 и корректно обрабатывать трафик с адресов длиной 128 бит.

**Режимы прослушивания:**
- **Dual Stack (::)**: сервис слушает на адресе `::`, что в Linux (при `net.ipv6.bindv6only=0`) позволяет принимать соединения как по IPv6, так и по IPv4 (через механизм IPv4-mapped addresses).
- **Separate Sockets**: явное указание прослушивания конкретных адресов для каждого протокола.

## Основные концепции

Для работы сервиса по IPv6 необходимо:
1.  Наличие IPv6-адреса на интерфейсе хоста (SSoT: **[Настройка адресов](./address_configuration.md)**).
2.  Разрешающие правила в межсетевом экране (SSoT: **[Firewall для IPv6](./firewall.md)**).
3.  Корректная директива прослушивания в конфигурации самого приложения.

## Практические сценарии

### 1. Веб-серверы и прокси

| Сервис | Директива прослушивания | Пример |
| :--- | :--- | :--- |
| **Nginx** | `listen [::]:<port>` | `listen [::]:443 ssl;` |
| **Apache** | `Listen [::]:<port>` | `Listen [::]:80` |
| **HAProxy** | `bind :::<port>` | `bind :::80` |

### 2. Системные и инфраструктурные сервисы

- **SSH (sshd)**: по умолчанию обычно слушает все адреса. Для явной привязки в `/etc/ssh/sshd_config`:
  ```ssh
  ListenAddress ::
  ```
- **Chrony (NTP)**: настройка доступа и прослушивания в `chrony.conf`:
  ```ini
  bindaddress ::
  allow fc00::/64
  ```
- **Docker (v27+)**: включение IPv6 для всей инфраструктуры (SSoT: **[Docker: Обзор сетей](../../../../Docker/Docker_network/docker_network.md)**).
  ```bash
  # Создание сети с нативным IPv6
  docker network create --ipv6 --subnet fd00::/64 my-net
  ```

### 3. Базы данных

- **PostgreSQL**: в файле `postgresql.conf` укажите:
  ```ini
  listen_addresses = '::'
  ```
  *Примечание: также необходимо обновить `pg_hba.conf` для разрешения доступа с IPv6-сетей.*
- **Redis**: в файле `redis.conf`:
  ```ini
  bind 127.0.0.1 ::1
  # Для всех интерфейсов:
  # bind * -::*
  ```
- **MySQL / MariaDB**: в секции `[mysqld]`:
  ```ini
  bind-address = ::
  ```

## Диагностика и проверка

### Проверка прослушиваемых портов

Используйте утилиту `ss` (Socket Statistics) для анализа состояния сокетов.

```bash
# Показать все TCP-порты IPv6 в состоянии прослушивания
ss -6 -lnt

# Показать соответствие процесса и порта
sudo ss -6 -lntp

# Просмотр UDP-сервисов
ss -6 -lunp
```

**Интерпретация вывода:**
- `[::]:80` — сервис слушает на всех IPv6-адресах (Dual Stack).
- `fe80::...%eth0:123` — сервис привязан к конкретному Link-Local адресу.

### Тестирование подключения

```bash
# Проверка через netcat
nc -6 -zv ::1 22

# Проверка HTTP через curl
curl -6 -I http://[::1]/
```

## Дополнительная информация

### Типичные ошибки

- **Синтаксис адреса**: IPv6-адреса в URL и некоторых конфигах (Nginx, Apache) **обязательно** заключать в квадратные скобки: `[2001:db8::1]`.
- **Зависимость от DNS**: если сервис настроен на прослушивание имени хоста, убедитесь, что имя разрешается в IPv6-адрес (запись AAAA).
- **Разделение сокетов**: в некоторых системах при включении `net.ipv6.bindv6only=1` прослушивание `::` не будет включать IPv4. В этом случае необходимо указывать обе директивы (например, `listen 80; listen [::]:80;` в Nginx).
