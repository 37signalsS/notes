# Debian/Ubuntu: /etc/network/interfaces

**Reliability Score: 10 (SSoT + Web)**

**Файл /etc/network/interfaces** — конфигурационный файл для управления сетевыми интерфейсами в дистрибутивах семейства Debian. Он используется пакетом **ifupdown** (классический) или **ifupdown2** (современный). Это императивный подход к настройке сети, при котором параметры каждого интерфейса описываются в виде строф (stanzas).

## Определения

- **ifupdown / ifupdown2** — набор утилит (`ifup`, `ifdown`, `ifquery`, `ifreload`) для управления сетевыми интерфейсами на основе конфигурации.
- **ifupdown2** — современная реализация на Python, поддерживающая применение настроек без перезагрузки интерфейсов и понимающая зависимости (мосты поверх бондов и т.д.). Стандарт для **Proxmox VE**.
- **Stanza (Строфа)** — логический блок конфигурации, начинающийся с ключевого слова (например, `iface`, `auto`, `allow-hotplug`).
- **Bonding (Агрегация каналов)** — объединение нескольких физических интерфейсов в один логический для повышения пропускной способности или отказоустойчивости.
- **Bridge (Мост)** — программный коммутатор, объединяющий интерфейсы в одну L2-сеть. См. **[Linux Bridge](../../Concepts/linux_bridge.md)**.
- **VLAN (Virtual LAN)** — технология создания виртуальных сетей внутри одного физического канала (стандарт 802.1Q).

## Базовые концепции

### Структура файла и подключение конфигов

Современный стандарт подразумевает использование раздельных файлов для разных интерфейсов.

```ini
# /etc/network/interfaces

# Подключение всех файлов из директории (рекомендуется)
source /etc/network/interfaces.d/*

# Обязательная настройка петли
auto lo
iface lo inet loopback
```

### Основные директивы управления

| Директива | Описание |
| :--- | :--- |
| **`auto`** | Поднимает интерфейс при загрузке системы (`ifup -a`). |
| **`allow-hotplug`** | Поднимает интерфейс при обнаружении события от ядра/udev (подключение кабеля). |
| **`iface`** | Основная строфа: `iface <имя> <семейство> <метод>`. |

- **Семейства:** `inet` (IPv4), `inet6` (IPv6).
- **Методы:** `static`, `dhcp`, `manual` (для интерфейсов без IP, входящих в мост), `loopback`.

## Практические сценарии

### 1. Статическая настройка IPv4 и IPv6

```ini
auto eth0
iface eth0 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1
    # DNS-серверы (требует пакет resolvconf)
    dns-nameservers 8.8.8.8 1.1.1.1
    dns-search corp.internal

iface eth0 inet6 static
    address 2001:db8::10/64
    gateway 2001:db8::1
```

### 2. Создание сетевого моста (Bridge)

Критически важно для виртуализации (KVM, Proxmox).

```ini
auto vmbr0
iface vmbr0 inet static
    address 10.0.0.10/24
    gateway 10.0.0.1
    bridge-ports eth0
    bridge-stp off
    bridge-fd 0
    # Поддержка VLAN на мосту (vlan-aware)
    bridge-vlan-aware yes
    bridge-vids 2-4094
```

### 3. Агрегация каналов (Bonding)

```ini
auto bond0
iface bond0 inet manual
    bond-slaves eth0 eth1
    bond-mode 802.3ad
    bond-miimon 100
    bond-lacp-rate 1
    bond-xmit-hash-policy layer2+3
```

### 4. Настройка VLAN (802.1Q)

Интерфейс создается с использованием суффикса `.<VLAN_ID>`. Требует установленного пакета `vlan`.

```ini
auto eth0.100
iface eth0.100 inet static
    address 172.16.100.10/24
```

### 5. Использование хуков (Hook Scripts)

Хуки позволяют выполнять команды на разных стадиями жизни интерфейса. В командах доступны переменные окружения, такие как `$IFACE`.

```ini
iface eth0 inet static
    address 192.168.50.10/24
    # Выполнить после поднятия: добавить маршрут
    post-up ip route add 10.100.0.0/16 via 192.168.50.1
    # Выполнить перед опусканием: очистить правила
    pre-down iptables -F
```

## Дополнительная информация

### Управление и диагностика

| Задача | ifupdown (Классический) | ifupdown2 (Современный) |
| :--- | :--- | :--- |
| Применить изменения | `systemctl restart networking` | `ifreload -a` |
| Проверить синтаксис | `ifquery --list` | `ifreload -dn` (Dry-run) |
| Поднять/Опустить | `ifup` / `ifdown` | `ifup` / `ifdown` |
| Статус интерфейса | `ifquery <iface>` | `ifquery <iface>` |

### ifupdown vs ifupdown2

| Особенность | ifupdown | ifupdown2 |
| :--- | :--- | :--- |
| **Язык** | C + Shell | Python |
| **Зависимости** | Низкие | Требует Python |
| **Контроль зависимостей** | Ограничен | Полный (авто-порядок Bond -> Bridge) |
| **Применение на лету** | Нет (перезапуск интерфейса) | Да (`ifreload`) |
| **Проверка синтаксиса** | Почти нет | Встроенная |

### Часто задаваемые вопросы (FAQ)

- **Проблема:** После редактирования `/etc/network/interfaces` настройки не применяются через `ifup`.
  - **Решение:** `ifup` сверяет текущее состояние с файлом `/run/network/ifstate`. Если интерфейс уже помечен как «up», команда ничего не сделает. Используйте `ifdown --force <iface> && ifup <iface>`.
- **Проблема:** Конфликт с NetworkManager.
  - **Решение:** Если интерфейс описан в `interfaces`, NetworkManager по умолчанию игнорирует его (параметр `managed=false` в `NetworkManager.conf`).
