# Постоянная настройка сети

**Постоянная настройка сети** (Persistent Network Configuration) — это процесс конфигурации параметров сетевых интерфейсов (IP-адреса, маршруты, DNS, параметры L2), которые сохраняются в энергонезависимой памяти системы и автоматически применяются при загрузке ОС или перезапуске сетевых служб. В отличие от временных настроек, выполняемых через стек [iproute2](../../Tools/iproute2/overview.md), персистентность обеспечивается специализированными системными менеджерами.

## Определения

- **Сетевой менеджер (Network Manager)** — системный демон, управляющий жизненным циклом сетевых соединений, отслеживающий состояние линков и применяющий конфигурационные профили.
- **Императивный подход** — метод настройки, при котором администратор описывает последовательность действий или использует жестко заданные параметры в конфигурационных файлах (например, `/etc/network/interfaces`).
- **Декларативный подход** — метод настройки, при котором описывается желаемое конечное состояние сети (часто в формате YAML), а конкретную реализацию берет на себя абстрактный слой (например, Netplan).
- **Renderer (Бэкенд)** — низкоуровневая служба (systemd-networkd или NetworkManager), которая исполняет конфигурацию, подготовленную высокоуровневой утилитой.

## Базовые концепции

Выбор инструмента для постоянной настройки зависит от семейства дистрибутива, версии ОС и роли узла (сервер или рабочая станция).

### Сводная таблица сетевых менеджеров

| Инструмент | Дистрибутивы | Тип конфигурации | Основные утилиты |
| :--- | :--- | :--- | :--- |
| **`ifupdown` / `ifupdown2`** | Debian, Proxmox, старые Ubuntu | Императивная | `ifup`, `ifdown`, `ifreload` |
| **NetworkManager** | RHEL 8/9, CentOS, AlmaLinux, Rocky Linux, Fedora, Ubuntu Desktop | Императивная / Декларативная (keyfile) | `nmcli`, `nmtui` |
| **Netplan** | Ubuntu 17.10+, Debian 12 (опционально) | Декларативная (YAML) | `netplan` |
| **`systemd-networkd`** | Arch Linux, Ubuntu Server, Debian 12, контейнеры | Декларативная (INI-like) | `networkctl` |

### Рекомендации по выбору

1. **Серверные системы**:
   - В экосистеме Ubuntu/Debian предпочтителен **Netplan** с бэкендом **systemd-networkd**. Это обеспечивает минимальное потребление ресурсов и быструю загрузку.
   - В семействе RHEL 9 стандартным и единственным поддерживаемым инструментом является **NetworkManager**.
2. **Облачные окружения**: Часто используется `cloud-init`, который генерирует конфигурацию для `systemd-networkd` или `netplan`.
3. **Рабочие станции**: **NetworkManager** является безусловным стандартом из-за развитой поддержки Wi-Fi, VPN-плагинов и интеграции с графическими оболочками.

> **Важно (RHEL 9 / AlmaLinux 9 / Rocky Linux 9):** Поддержка классических скриптов `network-scripts` (файлы `ifcfg-ethX`) полностью прекращена. Рекомендуется использовать нативный формат `keyfile` в NetworkManager.

## Дополнительная информация

### Конфликты сетевых менеджеров

Одной из частых проблем является одновременная работа нескольких менеджеров (например, `systemd-networkd` и `NetworkManager`), пытающихся управлять одним интерфейсом. Это приводит к "миганию" настроек, дублированию IP-адресов и проблемам с маршрутизацией. 
**Решение:** Оставляйте активным только один менеджер, явно отключая остальные через `systemctl disable --now`.

### Фиксация имен интерфейсов

Механизм **Predictable Network Interface Names** (например, `enp0s3`) иногда требует ручного переопределения (например, для лицензионного ПО, привязанного к `eth0`). Это реализуется через `systemd.link`.

**Пример конфигурации (`/etc/systemd/network/10-eth0.link`):**

```ini
[Match]
MACAddress=52:54:00:ab:cd:ef

[Link]
Name=eth0
```

### Диагностика состояния

| Команда | Контекст | Описание |
| :--- | :--- | :--- |
| `networkctl status` | systemd-networkd | Состояние линков и примененные настройки |
| `nmcli device status` | NetworkManager | Список устройств и активных профилей |
| `netplan status` | Netplan | Текущее состояние конфигурации (в новых версиях) |
| `journalctl -u systemd-networkd` | systemd | Анализ логов загрузки сети |
