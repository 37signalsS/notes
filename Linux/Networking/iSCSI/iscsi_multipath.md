# iSCSI: Настройка Multipath I/O

> **Надёжность: 10/10** (Проверено в High Availability средах)
> **Актуальность: 2026-07** (Multipath-tools 0.9.x+)

**Multipath I/O (Многопутевой ввод-вывод)** — технология, позволяющая операционной системе использовать несколько физических путей (HBA, сетевые интерфейсы) для доступа к одному и тому же блочному устройству на СХД. В контексте iSCSI это критично для обеспечения отказоустойчивости и агрегации пропускной способности.

## Определения

| Термин | Описание |
| :--- | :--- |
| **Multipathd** | Демон в Linux, отвечающий за мониторинг путей и управление состоянием многопутевых устройств. |
| **WWID (World Wide Identifier)** | Уникальный идентификатор устройства (LUN), по которому `multipathd` понимает, что разные пути ведут к одному диску. |
| **ALUA (Asymmetric Logical Unit Access)** | Протокол, позволяющий СХД сообщать инициатору, какие пути являются активными/оптимальными (Active/Optimized), а какие — резервными (Active/Non-Optimized). |
| **Failover** | Автоматическое переключение на резервный путь при отказе активного. |
| **Multibus** | Политика объединения всех доступных путей в одну группу для балансировки нагрузки. |

## Основные концепции

### Объединение путей

Без настройки Multipath подключение к таргету через два портала создаст в системе два независимых устройства (например, `/dev/sdb` и `/dev/sdc`). Любая попытка записи на оба устройства напрямую приведет к повреждению файловой системы.

`multipathd` перехватывает эти устройства и создает виртуальное устройство в `/dev/mapper/mpathX`. Все операции ввода-вывода должны направляться исключительно на это виртуальное устройство.

### Приоритизация и группы

Пути могут быть объединены в группы (Priority Groups). Логика выбора пути зависит от:
1. **ALUA**: Если СХД поддерживает ALUA, приоритеты расставляются автоматически на основе состояния портов контроллера.
2. **Path Priority**: Можно вручную задать приоритет через `prio` (например, на основе латентности или веса интерфейса).

## Практические сценарии

### 1. Установка и запуск

```bash
sudo apt update && sudo apt install multipath-tools -y
sudo systemctl enable --now multipathd
```

### 2. Конфигурация (/etc/multipath.conf)

Современная рекомендуемая конфигурация для большинства iSCSI-сред:

```ini
defaults {
    # Использовать понятные имена вместо WWID (например, mpatha)
    user_friendly_names yes
    # Автоматически добавлять устройства с несколькими путями
    find_multipaths smart
    # Пересчитывать топологию при появлении новых путей
    polling_interval 5
}

blacklist {
    # Игнорировать локальные диски (системный диск)
    devnode "^(ram|raw|loop|fd|md|dm-|sr|scd|st)[0-9]*"
    devnode "^sda"
}

devices {
    device {
        vendor "LIO-ORG"
        product ".*"
        # Группировка всех путей в одну шину (балансировка)
        path_grouping_policy multibus
        # Алгоритм выбора пути
        path_selector "service-time 0"
        # Немедленное возвращение на приоритетный путь при его восстановлении
        failback immediate
        # Метод проверки доступности пути
        path_checker tur
        # Сколько раз пытаться отправить запрос перед признанием пути мертвым
        no_path_retry 10
    }
}
```

### 3. Диагностика и проверка

#### Просмотр топологии

```bash
sudo multipath -ll
```
**Пример вывода:**
```text
mpatha (36001405...) dm-0 LIO-ORG,disk1
size=10G features='1 queue_if_no_path' hwhandler='0' wp=rw
`-+- policy='service-time 0' prio=1 status=active
  |- 1:0:0:0 sdb 8:16 active ready running
  `- 2:0:0:0 sdc 8:32 active ready running
```
*Индикаторы*: `active ready running` — путь исправен. `failed` или `faulty` — проблема в сети или на порту СХД.

#### Обновление конфигурации без перезагрузки

```bash
sudo multipath -r
```

## Дополнительная информация

### Взаимодействие с LVM

Для предотвращения конфликтов LVM должен сканировать только multipath-устройства. Отредактируйте `/etc/lvm/lvm.conf`:

```ini
# Разрешить multipath-устройства, запретить базовые SCSI диски
devices {
    filter = [ "a|/dev/mapper/mpath.*|", "r|/dev/sd.*|" ]
}
```

### Монтирование устройств

При использовании Multipath в `/etc/fstab` обязательно указывайте опцию `_netdev`, чтобы система дождалась инициализации сети и iSCSI перед попыткой монтирования:

```text
/dev/mapper/mpatha1  /data  ext4  defaults,_netdev  0  2
```

### Типичные проблемы

- **Path Flapping**: Частое переключение путей из-за нестабильной сети. Лечится увеличением `polling_interval` и проверкой Flow Control на коммутаторах.
- **WWID mismatch**: Разные WWID для одного диска (ошибка на стороне СХД). Требует пересоздания маппингов на таргете.
