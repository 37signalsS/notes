# iSCSI: Основные концепции

**iSCSI (Internet Small Computer System Interface)** — протокол блочного доступа, позволяющий передавать команды SCSI через IP-сети (TCP/IP). Технология позволяет подключать удалённые блочные устройства по сети так, будто они являются локальными дисками.

## Определения

| Термин | Описание |
| :--- | :--- |
| **Target (Таргет)** | Сервер (хранилище), предоставляющий блочные устройства (LUN) по сети. |
| **Initiator (Инициатор)** | Клиент, который подключается к таргету и получает доступ к удаленным дискам. |
| **LUN (Logical Unit Number)** | Логический том или физический диск, «презентованный» таргетом инициатору. |
| **IQN (iSCSI Qualified Name)** | Уникальный идентификатор устройства в iSCSI-сети. Формат: `iqn.YYYY-MM.reverse.domain:optional.id`. |
| **Portal (Портал)** | Пара IP-адрес:Порт (обычно 3260), по которой доступен таргет. |
| **SAN (Storage Area Network)** | Выделенная сеть для передачи данных от серверов к устройствам хранения (iSCSI — один из протоколов SAN). |
| **CHAP (Challenge-Handshake Authentication Protocol)** | Метод аутентификации, использующий общий секрет для подтверждения прав доступа. |

## Основные концепции

### Архитектурная модель

Протокол работает по модели «клиент-сервер», инкапсулируя команды SCSI в TCP-пакеты.

```
┌─────────────────────────┐      IP-сеть (TCP:3260)      ┌─────────────────────────┐
│       Initiator         │◄────────────────────────────►│         Target          │
│       (Клиент)          │                              │        (Сервер)         │
│ Реализация: open-iscsi  │                              │ Реализация: tgt / LIO   │
└────────────┬────────────┘                              └────────────┬────────────┘
             │                                                        │
             ▼                                                        ▼
      /dev/sdb (Блок)                                          /dev/sdb (Физический)
    (Виртуальный диск)                                         (Или файл-образ/LVM)
```

### Адресация (IQN)

Каждый узел (таргет или инициатор) должен иметь уникальное имя. Стандарт IQN состоит из:

1. Литерала `iqn.`
2. Даты регистрации домена (`YYYY-MM`)
3. Имени домена в обратном порядке (`com.example`)
4. Произвольного идентификатора после двоеточия (`:storage.lun1`)

Пример: `iqn.2026-06.com.example:target01`

### Реализации в Linux

| Компонент | Реализация | Статус | Примечание |
| :--- | :--- | :--- | :--- |
| **Target** | `tgt` (scsi-target-utils) | Стабильно | Работает в user-space, прост в настройке, хорошая производительность. |
| **Target** | `LIO` (targetcli) | Стабильно | Работает в kernel-space, стандарт для современных ядер Linux. |
| **Initiator** | `open-iscsi` | Стандарт | Универсальный клиент для всех дистрибутивов. |

## Практические сценарии

Развертывание iSCSI-инфраструктуры делится на два основных этапа:

## Дополнительная информация

### Сравнение с NFS

В отличие от NFS (файловый доступ), iSCSI предоставляет **блочный доступ**. Это означает, что инициатор сам создает файловую систему на удаленном устройстве. Это критично для:

- Баз данных (требуют прямого контроля над I/O).
- Виртуализации (Proxmox, VMware требуют блочных устройств для LVM или VMFS).
- Кластерных систем.

### Ограничения и задержки

- **Сетевая задержка**: iSCSI крайне чувствителен к задержкам в сети. Не рекомендуется использовать для latency-sensitive приложений (например, **etcd**) через нестабильные каналы.
- **MTU**: Для повышения производительности рекомендуется использовать **Jumbo Frames (MTU 9000)** в выделенной сети хранения.
- **Безопасность**: Трафик iSCSI передается в открытом виде. Для защиты данных необходимо использовать CHAP для аутентификации и IPsec или физическую изоляцию сети для защиты трафика.
