# iSCSI: Основные концепции

> **Надёжность: 10/10** (Концептуальный фундамент)
> **Актуальность: 2026-07**

**iSCSI (Internet Small Computer System Interface)** — протокол блочного доступа, позволяющий инкапсулировать команды SCSI в IP-пакеты (TCP/IP). Технология позволяет превратить стандартную Ethernet-сеть в сеть хранения данных (SAN), где удалённые дисковые ресурсы подключаются к системе и работают как локальные блочные устройства.

## Определения

| Термин | Описание |
| :--- | :--- |
| **Target (Таргет)** | Сервер или система хранения (Storage Array), предоставляющая блочные устройства (LUN) по сети. |
| **Initiator (Инициатор)** | Клиент (хост), который инициирует запросы к таргету для получения доступа к дискам. |
| **LUN (Logical Unit Number)** | Логическая единица адресации, представляющая собой конкретный объем дискового пространства, выделенный таргетом. |
| **IQN (iSCSI Qualified Name)** | Уникальный идентификатор узла в сети iSCSI. Формат: `iqn.YYYY-MM.reverse.domain:optional.id`. |
| **Portal (Портал)** | Комбинация IP-адреса и TCP-порта (по умолчанию 3260), через которую доступен таргет. |
| **TPG (Target Portal Group)** | Группа порталов и настроек доступа внутри одного таргета. |
| **Multipath I/O (MPIO)** | Технология объединения нескольких физических путей к одному LUN для повышения отказоустойчивости и балансировки нагрузки. |
| **iSER (iSCSI Extensions for RDMA)** | Расширение протокола, использующее RDMA (InfiniBand, RoCE, iWARP) для снижения нагрузки на CPU и минимизации задержек. |

## Основные концепции

### Архитектурная модель

iSCSI работает на прикладном уровне модели OSI, используя TCP/IP для транспортировки.

```text
┌─────────────────────────┐      IP-сеть (TCP:3260)      ┌─────────────────────────┐
│       Initiator         │◄────────────────────────────►│         Target          │
│       (Клиент)          │                              │        (Сервер)         │
│ Программный: open-iscsi │       Трафик: SCSI over TCP  │ Реализация: LIO / tgt   │
│ Аппаратный: iSCSI HBA   │                              │ Хранилище: Диск/LVM/Файл│
└────────────┬────────────┘                              └────────────┬────────────┘
             │                                                        │
             ▼                                                        ▼
      /dev/sdb (Блок)                                          /dev/sdb (Физический)
    (Виртуальный диск)                                         (Или файл-образ/LVM)
```

### Адресация (IQN)

Каждый инициатор и таргет должен обладать уникальным именем. Стандарт **IQN** является наиболее распространенным (существует также EUI, но он используется редко).

Структура IQN:
1. `iqn.` — префикс.
2. `YYYY-MM` — дата регистрации домена владельца.
3. `com.example` — доменное имя в обратном порядке.
4. `:storage.target01` — произвольный уникальный идентификатор (String).

Пример: `iqn.2026-07.com.example.srv:node01.initiator`

### Реализации в Linux

| Компонент | Реализация | Статус | Характеристика |
| :--- | :--- | :--- | :--- |
| **Target** | **LIO (linux-iscsi.org)** | **Стандарт** | Реализация в пространстве ядра (Kernel-space). Поддерживает iSCSI, FC, FCoE, vhost. Управляется через `targetcli`. |
| **Target** | **tgt (scsi-target-utils)** | **Legacy** | User-space реализация. Проста в настройке, но уступает LIO по производительности и функциональности. |
| **Initiator**| **open-iscsi** | **Стандарт** | Основной стек инициатора (iscsid, iscsiadm). Поддерживается всеми дистрибутивами. |

## Дополнительная информация

### Сетевая инфраструктура и Jumbo Frames

Для стабильной работы iSCSI рекомендуется:
- **Выделенная сеть (SAN)**: Физическая или логическая (VLAN) изоляция трафика хранения от общего трафика.
- **Jumbo Frames (MTU 9000)**: Увеличение размера кадра снижает количество прерываний и нагрузку на CPU, что критично для 10GbE+ сетей.
- **Flow Control**: Должен быть включен на коммутаторах для предотвращения потерь пакетов при перегрузках.

### Безопасность

1. **CHAP**: Односторонняя или взаимная аутентификация по логину и паролю. Защищает от несанкционированного подключения, но не шифрует данные.
2. **Network Isolation**: Основной метод защиты. Доступ к порталу должен быть ограничен на уровне Firewall и VLAN.
3. **iSCSI over TLS**: Современный стандарт шифрования трафика (поддерживается в новейших реализациях LIO), защищающий данные от перехвата.

### Сравнение с NVMe-oF

**NVMe over Fabrics (NVMe-oF)** — современный преемник iSCSI для высокопроизводительных систем (All-Flash).
- **iSCSI**: Высокая совместимость, работает на любой Ethernet-инфраструктуре, выше задержки из-за накладных расходов SCSI и TCP.
- **NVMe-oF**: Экстремально низкие задержки, требует поддержки RDMA или TCP с оптимизацией, использует протокол NVMe вместо SCSI.
