# iSCSI: Основные концепции

**iSCSI (Internet Small Computer System Interface)** — сетевой протокол блочного доступа, позволяющий инкапсулировать команды SCSI в IP-пакеты (TCP/IP). Технология позволяет объединять удалённые дисковые ресурсы в распределённую сеть хранения данных (SAN), где удалённые накопители (LUN) подключаются к хостам и функционируют как локальные блочные устройства.

## Определения и сокращения

| Термин | Описание |
| :--- | :--- |
| **Target (Таргет)** | Сервер или система хранения (Storage Array), предоставляющая блочные устройства по сети. |
| **Initiator (Инициатор)** | Клиент (хост), который инициирует запросы к таргету для получения доступа к дискам. |
| **LUN (Logical Unit Number)** | Логическая единица адресации, представляющая собой конкретный объем дискового пространства на таргете. |
| **IQN (iSCSI Qualified Name)** | Уникальный идентификатор узла в сети iSCSI. Формат: `iqn.YYYY-MM.reverse.domain:optional.id`. |
| **Portal (Портал)** | Комбинация IP-адреса и TCP-порта (по умолчанию 3260), через которую доступен таргет. |
| **TPG (Target Portal Group)** | Группа порталов и настроек доступа (ACL, CHAP) внутри одного таргета. |
| **PDU (Protocol Data Unit)** | Единица обмена данными в iSCSI, содержащая заголовок и полезную нагрузку. |
| **ERL (Error Recovery Level)** | Уровень восстановления ошибок, определяющий возможности протокола по обработке сбоев. |
| **Multipath I/O (MPIO)** | Технология объединения нескольких физических путей к одному LUN для отказоустойчивости. |
| **iSER (iSCSI Extensions for RDMA)** | Расширение протокола, использующее RDMA для минимизации задержек и нагрузки на CPU. |

## Основные концепции

### Архитектурная модель

iSCSI работает на прикладном уровне модели OSI, используя TCP/IP для транспортировки SCSI-команд.

```text
┌─────────────────────────┐      IP-сеть (TCP:3260)      ┌─────────────────────────┐
│       Initiator         │◄────────────────────────────►│         Target          │
│       (Клиент)          │                              │        (Сервер)         │
│ Программный: open-iscsi │       Трафик: SCSI over TCP  │ Реализация: LIO / tgt   │
│ Аппаратный: iSCSI HBA   │                              │ Хранилище: Диск/LVM/Файл│
└────────────┬────────────┘                              └────────────┬────────────┘
             │                                                        │
             ▼                                                        ▼
      /dev/sdb (Блок)                                          /dev/sdb (Физический)
    (Виртуальный диск)                                         (Или файл-образ/LVM)
```

### Структура PDU (Protocol Data Unit)

Обмен данными между инициатором и таргетом происходит через пакеты PDU. Структура типичного PDU:

1.  **BHS (Basic Header Segment)**: Обязательный 48-байтовый заголовок (код операции, флаги, длина).
2.  **AHS (Additional Header Segment)**: Опциональные дополнительные заголовки (редко используются).
3.  **Header Digest**: Контрольная сумма заголовка (CRC32C) для защиты от искажений.
4.  **Data Segment**: Полезная нагрузка (команды SCSI, параметры или данные диска).
5.  **Data Digest**: Контрольная сумма данных (CRC32C) для проверки целостности.

### Фазы работы протокола

Сессия iSCSI проходит через строго определенные этапы:

1.  **Discovery Phase (Фаза обнаружения)**: Инициатор запрашивает список доступных таргетов (SendTargets). Используется специальная сессия "Discovery".
2.  **Login Phase (Фаза входа)**:
    *   *Security Negotiation*: Аутентификация (например, CHAP).
    *   *Operational Parameter Negotiation*: Согласование MTU, размеров PDU, использования Digest и т.д.
3.  **Full Feature Phase (Рабочая фаза)**: Штатный обмен командами ввода-вывода (Read/Write).

### Уровни восстановления ошибок (Error Recovery Levels)

Протокол iSCSI поддерживает три уровня восстановления (**ERL**):

-   **ERL 0 (Session Recovery)**: При любом сбое в соединении сессия закрывается и создается заново. Простейший уровень, поддерживаемый всеми.
-   **ERL 1 (PDU Recovery)**: Возможность повторной передачи потерянных PDU без разрыва сессии.
-   **ERL 2 (Connection Recovery)**: Позволяет переключать активные операции с одного соединения на другое внутри одной сессии (требует Multiple Connections per Session, MCS).

### Адресация (IQN)

Каждый узел должен обладать уникальным именем. Стандарт **IQN** является основным.

Структура IQN:
1. `iqn.` — префикс.
2. `YYYY-MM` — дата регистрации домена владельца.
3. `com.example` — доменное имя в обратном порядке.
4. `:storage.target01` — произвольный идентификатор.

Пример: `iqn.2026-07.com.example.srv:node01.initiator`

### Реализации в Linux

| Компонент | Реализация | Статус | Характеристика |
| :--- | :--- | :--- | :--- |
| **Target** | **LIO (linux-iscsi.org)** | **Стандарт** | Ядерная реализация. Максимальная производительность. Управление: `targetcli`. |
| **Target** | **tgt (scsi-target-utils)** | **Legacy** | Пользовательское пространство. Проще в отладке, медленнее. |
| **Initiator**| **open-iscsi** | **Стандарт** | Стек инициатора (`iscsid`, `iscsiadm`). Стандарт де-факто. |

## Дополнительная информация

### Целостность данных (Digest)

В отличие от стандартного TCP, iSCSI может использовать дополнительные контрольные суммы (Digest) на уровне протокола. Это критично для блочного трафика, так как стандартных контрольных сумм Ethernet/TCP недостаточно для предотвращения повреждения данных при прохождении через сетевое оборудование (Silent Data Corruption).

### Сравнение с NVMe-oF

**NVMe over Fabrics (NVMe-oF)** — эволюция сетевого хранения.
- **iSCSI**: Высокая совместимость, работает везде, но имеет накладные расходы на стек SCSI и TCP.
- **NVMe-oF**: Экстремальная производительность, оптимизирован под Flash/NVMe, требует современной инфраструктуры (RoCE/TCP с разгрузкой).
