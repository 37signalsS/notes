# iSCSI: Оптимизация производительности

> **Надёжность: 10/10** (Рекомендации вендоров корпоративных СХД)
> **Актуальность: 2026-07** (Ядро Linux 6.x+, 25/40/100GbE)

**Оптимизация iSCSI** — комплекс мер по настройке сетевого стека, параметров протокола и дисковой подсистемы для минимизации задержек (Latency) и максимизации пропускной способности (Throughput). Основная задача — снизить накладные расходы на инкапсуляцию SCSI в TCP/IP и уменьшить нагрузку на CPU.

## Определения

| Термин | Описание |
| :--- | :--- |
| **MTU (Maximum Transmission Unit)** | Максимальный размер полезного блока данных в одном Ethernet-кадре. |
| **Interrupt Coalescing** | Механизм задержки генерации прерываний сетевой картой для их объединения и снижения нагрузки на CPU. |
| **Offloading** | Перенос вычислений (например, расчет контрольных сумм или сегментация TCP) с центрального процессора на сетевую карту. |
| **Queue Depth** | Количество команд ввода-вывода, которые могут быть отправлены устройству одновременно без ожидания завершения предыдущих. |
| **Delayed ACK** | Механизм TCP, задерживающий отправку подтверждения получения пакета. В iSCSI часто вреден, так как увеличивает латентность. |

## Основные концепции

### Влияние сети на блочный трафик

iSCSI крайне чувствителен к потерям пакетов и джиттеру. В отличие от HTTP-трафика, потеря одного iSCSI-пакета может привести к блокировке всей очереди ввода-вывода ОС.

Ключевые зоны оптимизации:
1.  **Снижение количества прерываний**: Использование Jumbo Frames и Interrupt Coalescing.
2.  **Эффективное использование CPU**: Привязка прерываний (IRQ Affinity) к ядрам, на которых работают процессы инициатора/таргета.
3.  **Минимизация задержек TCP**: Тюнинг алгоритмов подтверждения (Nagle, Delayed ACK) и буферов.

## Практические сценарии

### 1. Сетевое ускорение (Offloading)

Используйте `ethtool` для управления аппаратными функциями разгрузки. Для iSCSI рекомендуется включить:
- **TSO (TCP Segmentation Offload)**: Разгрузка сегментации.
- **GRO (Generic Receive Offload)**: Склеивание входящих пакетов.

```bash
# Проверка текущих настроек
sudo ethtool -k eth1

# Включение основных функций
sudo ethtool -K eth1 tso on gro on lro off
```
*Примечание*: **LRO (Large Receive Offload)** часто рекомендуется отключать на маршрутизаторах, но на конечных узлах iSCSI его влияние следует тестировать индивидуально.

### 2. Настройка Jumbo Frames (MTU 9000)

Увеличение MTU до 9000 снижает нагрузку на CPU на 20-30% при высоких скоростях.

```bash
# Установка MTU
sudo ip link set dev eth1 mtu 9000
```
**Важно**: Все узлы в сегменте (включая коммутатор) должны иметь одинаковый MTU. [Подробнее о MTU и фрагментации](../../../Networking/OSI_TCP_IP_Model/Network_layer/mtu_and_vpn.md).

### 3. Управление прерываниями (IRQ Affinity)

Для исключения переключений контекста между ядрами CPU привяжите прерывания сетевой карты к конкретным ядрам.

```bash
# Поиск номера прерывания сетевой карты
cat /proc/interrupts | grep eth1

# Привязка к первому ядру (маска 1)
echo 1 | sudo tee /proc/irq/<IRQ_NUM>/smp_affinity
```
Подробнее см. в разделе **[Прерывания в ядре Linux](../../Core/kernel/interrupts.md)**.

### 4. Тюнинг iSCSI сессии (`iscsid.conf`)

Оптимизация параметров в `/etc/iscsi/iscsid.conf`:

```ini
# Глубина очереди для устройства (рекомендуется 32-64 для HDD, до 256 для NVMe)
node.session.queue_depth = 64

# Отключение Nagle и Delayed ACK (через параметры TCP в последних версиях ядра или напрямую в коде инициатора)
node.conn[0].tcp.nodelay = 1

# Размеры буферов передачи данных
node.session.iscsi.FirstBurstLength = 262144
node.session.iscsi.MaxBurstLength = 16776192
```

### 5. Выбор планировщика I/O

Для iSCSI на современных ядрах (6.x+) лучшим выбором является:
- **`none`**: Для NVMe-основанных таргетов или All-Flash СХД.
- **`mq-deadline`**: Универсальный выбор для большинства сред.

```bash
echo none | sudo tee /sys/block/sdb/queue/scheduler
```

## Дополнительная информация

### Изоляция и QoS

- **Выделенные адаптеры**: Рекомендуется использовать отдельные NIC для SAN-трафика.
- **Flow Control**: На коммутаторах должен быть включен IEEE 802.3x Flow Control для предотвращения переполнения буферов.
- **iSER (iSCSI Extensions for RDMA)**: Для экстремальной производительности используйте iSER, который полностью исключает копирование данных в TCP-стеке.
