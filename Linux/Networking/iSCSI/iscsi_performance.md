# iSCSI: Оптимизация производительности

**Оптимизация iSCSI** — комплекс мер по настройке сетевого стека, параметров протокола и дисковой подсистемы для минимизации задержек (Latency) и максимизации пропускной способности (Throughput). Основная задача — снизить накладные расходы на инкапсуляцию SCSI в TCP/IP и уменьшить нагрузку на CPU.

## Определения и сокращения

| Термин | Описание |
| :--- | :--- |
| **MTU (Maximum Transmission Unit)** | Максимальный размер кадра. Для iSCSI стандарт — 9000 (Jumbo Frames). |
| **BDP (Bandwidth-Delay Product)** | Объем данных "в пути", необходимый для заполнения канала. Определяет размер буферов TCP. |
| **PFC (Priority-based Flow Control)** | Механизм управления потоком (802.1Qbb), предотвращающий потери пакетов в сетях RoCE/iSCSI. |
| **IRQ Affinity** | Привязка обработки прерываний сетевой карты к конкретным ядрам CPU. |
| **NUMA (Non-Uniform Memory Access)** | Архитектура памяти, где задержка доступа зависит от расположения памяти относительно процессора. |
| **Offloading** | Аппаратная разгрузка CPU (расчет контрольных сумм, сегментация) на сетевой адаптер. |

## Основные концепции

### Влияние сети на блочный трафик

iSCSI крайне чувствителен к потерям пакетов. Потеря одного сегмента приводит к срабатыванию механизмов TCP Retransmission, что вызывает всплеск задержек (Latency Spikes) и блокировку очереди ввода-вывода (Head-of-Line Blocking).

Ключевые зоны оптимизации:
1.  **Минимизация прерываний**: Использование Jumbo Frames (уменьшение количества пакетов) и Interrupt Coalescing.
2.  **Эффективность CPU**: Привязка IRQ к ядрам того же NUMA-узла, на котором находится сетевая карта.
3.  **Тюнинг TCP**: Использование алгоритмов (CUBIC/BBR) и размеров буферов, соответствующих BDP.

## Практические сценарии

### 1. Сетевое ускорение (Offloading)

Используйте `ethtool` для управления аппаратными функциями разгрузки.

```bash
# Проверка текущих настроек
sudo ethtool -k eth1
# → tcp-segmentation-offload: on
# → generic-receive-offload: on

# Оптимальная конфигурация для iSCSI
sudo ethtool -K eth1 tso on gro on lro off
```
*Примечание*: **LRO (Large Receive Offload)** рекомендуется отключать, так как он может конфликтовать с iSCSI-пакетами, вызывая ошибки CRC на уровне инициатора.

### 2. Настройка Jumbo Frames (MTU 9000)

Снижает нагрузку на CPU на 20-30% за счет уменьшения количества обрабатываемых заголовков.

```bash
# Установка MTU
sudo ip link set dev eth1 mtu 9000

# Верификация (проверка прохождения кадра без фрагментации)
ping -M do -s 8972 <TARGET_IP>
# → 8980 bytes from <TARGET_IP>: icmp_seq=1 ttl=64 time=0.123 ms
```

### 3. Тюнинг сетевого стека (sysctl)

Для высокоскоростных SAN (10GbE+) необходимо увеличить лимиты буферов. Расчет BDP: `Bandwidth * RTT`.

```bash
# /etc/sysctl.d/99-iscsi-performance.conf
# Максимальные размеры буферов (128MB для 40/100G)
net.core.rmem_max = 134217728
net.core.wmem_max = 134217728

# Автотюнинг TCP (min, default, max)
net.ipv4.tcp_rmem = 4096 87380 134217728
net.ipv4.tcp_wmem = 4096 65536 134217728

# Отключение Delayed ACK (ускоряет подтверждение мелких блоков)
net.ipv4.tcp_low_latency = 1
# Дисциплина очереди для iSER/RoCE
net.core.default_qdisc = fq
```

### 4. Тюнинг сессии iSCSI (`iscsid.conf`)

Параметры, определяющие размер iSCSI PDU и глубину очередей.

```ini
# Размер сегмента данных (должен быть кратен MTU и размеру страницы 4KB)
# Оптимально 256KB для современных систем
node.session.iscsi.MaxRecvDataSegmentLength = 262144
node.session.iscsi.MaxXmitDataSegmentLength = 262144

# Глубина очереди инициатора (Queue Depth)
# 32-64 для HDD, 128-256 для SSD/NVMe
node.session.queue_depth = 128

# Отключение Nagle (минимизация латентности)
node.conn[0].tcp.nodelay = 1
```

### 5. Управление прерываниями и NUMA

Для минимизации задержек памяти (Memory Latency) привяжите прерывания к "родному" CPU-сокету.

```bash
# 1. Определяем NUMA-узел сетевой карты
cat /sys/class/net/eth1/device/numa_node
# → 0 (означает первый сокет)

# 2. Определяем список ядер этого узла
lscpu | grep "NUMA node0"
# → NUMA node0 CPU(s): 0-15,32-47

# 3. Привязываем прерывание к маске (например, ядро 0)
echo 1 | sudo tee /proc/irq/<IRQ_NUM>/smp_affinity
```

### 6. iSER (iSCSI Extensions for RDMA)

iSER полностью исключает TCP-стек и копирование данных в памяти (Zero-Copy).

**Преимущества:**
- Снижение Latency в 3-5 раз.
- Практически нулевая загрузка CPU при передаче данных.

**Настройка инициатора:**
```bash
# Загрузка модулей
sudo modprobe ib_iser
# Подключение через iSER
sudo iscsiadm -m discovery -t sendtargets -p <IP_TARGET>
sudo iscsiadm -m node -T <IQN> -p <IP> -o update -n node.conn[0].iscsi.HeaderDigest -v None
sudo iscsiadm -m node -T <IQN> -p <IP> --login
```

## Дополнительная информация

### Управление потоком (Flow Control)

1.  **IEEE 802.3x (Global Flow Control)**: При переполнении буфера коммутатор посылает PAUSE-кадр, останавливая весь трафик на порту. Может вызвать "разлив" заторов (Congestion Spreading).
2.  **IEEE 802.1Qbb (PFC)**: Позволяет останавливать только трафик определенного приоритета (Class of Service). **Рекомендуется** для совмещенных сетей (LAN + iSCSI) и RoCE.

### Выбор планировщика I/O

Для сетевых блочных устройств на современных ядрах (6.x+):
- **`none`**: Идеально для быстрых таргетов (NVMe-о-F, SSD SAN). Исключает лишнюю логику переупорядочивания в ядре.
- **`mq-deadline`**: Для HDD-массивов, где важна приоритизация чтения перед записью.
