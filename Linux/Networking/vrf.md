# VRF (Virtual Routing and Forwarding) в Linux

## Определения

* **VRF (Virtual Routing and Forwarding)** — технология сетевой изоляции на уровне L3 (сетевой уровень OSI), позволяющая создавать несколько независимых таблиц маршрутизации внутри одного экземпляра операционной системы.
* **VRF-интерфейс (L3 Master Device)** — виртуальное устройство в Linux, выступающее в роли «контейнера» для других сетевых интерфейсов. Он агрегирует таблицу маршрутизации и управляет правилами обработки трафика для привязанных к нему устройств.
* **Slave-интерфейс** — физический или виртуальный сетевой интерфейс, привязанный к VRF-интерфейсу. Весь трафик такого устройства обрабатывается исключительно в контексте таблицы маршрутизации VRF.

## Основные концепции

### Механизм работы

В Linux VRF реализован через инфраструктуру **L3 Master Device**. Когда интерфейс назначается мастером (master) для других интерфейсов, ядро перехватывает процесс выбора маршрута (FIB lookup) для пакетов, входящих и выходящих через эти устройства, и направляет его в таблицу маршрутизации, ассоциированную с VRF.

### Сравнение VRF и Network Namespaces (NetNS)

| Характеристика | VRF | Network Namespaces (NetNS) |
| :--- | :--- | :--- |
| **Уровень изоляции** | Только L3 (маршрутизация). | Полный стек (L2-L4, порты, Netfilter). |
| **Управление** | Видны все интерфейсы в одном контексте. | Каждый NetNS имеет свой набор интерфейсов. |
| **Производительность** | Минимальные накладные расходы. | Выше расходы на переключение контекста. |
| **Сложность** | Проще в настройке для маршрутизации. | Сложнее, требует veth-пары для связи. |
| **Общие ресурсы** | Легко делить сокеты и память. | Строгая изоляция ресурсов. |

### Параметры ядра (sysctl)

Для корректной работы сервисов в мульти-VRF среде критически важны следующие параметры:

* **`net.ipv4.tcp_l3mdev_accept = 1`** — позволяет сервисам, слушающим на `0.0.0.0` (например, SSH), принимать соединения из любого VRF.
* **`net.ipv4.udp_l3mdev_accept = 1`** — аналогично для UDP (DNS, SNMP).
* **`net.ipv4.raw_l3mdev_accept = 1`** — разрешает работу ICMP (ping) в контексте VRF.
* **`net.ipv6.conf.all.keep_addr_on_down = 1`** — предотвращает удаление IPv6 адресов при кратковременном выключении интерфейса в момент привязки к VRF.

## Практические сценарии

### Создание и настройка VRF

```bash
# 1. Создать VRF-интерфейс, привязанный к таблице маршрутизации 100
sudo ip link add vrf-mgmt type vrf table 100

# 2. Активировать интерфейс
sudo ip link set vrf-mgmt up

# 3. Привязать физический интерфейс к VRF
# Внимание: при этом интерфейс eth1 временно перейдет в состояние DOWN
sudo ip link set eth1 master vrf-mgmt
sudo ip link set eth1 up

# 4. Проверить конфигурацию
ip vrf show
# → Name              Table
# → -----------------------
# → vrf-mgmt            100
```

### Управление маршрутизацией

При использовании VRF таблицы маршрутизации разделены.

```bash
# Добавить маршрут по умолчанию в таблицу VRF
sudo ip route add default via 192.168.1.1 dev eth1 table 100

# Рекомендация: добавить unreachable маршрут для предотвращения утечки трафика в таблицу main
sudo ip route add unreachable default table 100 metric 8192

# Просмотр таблицы маршрутизации
ip route show table 100
# или
ip route show vrf vrf-mgmt
```

### Запуск приложений в контексте VRF

Если приложение не поддерживает VRF нативно (VRF-aware), его нужно запускать через `cgroups` с помощью `ip vrf exec`.

```bash
# Выполнить ping через конкретный VRF
ip vrf exec vrf-mgmt ping -c 3 8.8.8.8

# Запустить SSH-сервер в контексте VRF (если l3mdev_accept = 0)
sudo ip vrf exec vrf-mgmt /usr/sbin/sshd -D
```

### Использование VRF-aware приложений

Современное ПО (FRR, Bird, Strongswan) умеет привязываться к VRF через `setsockopt(SO_BINDTODEVICE)`. В этом случае `ip vrf exec` не требуется, достаточно указать имя VRF-интерфейса в конфигурации приложения.

## Диагностика

```bash
# Список всех VRF
ip vrf show

# Просмотр интерфейсов-сателлитов
ip link show master vrf-mgmt

# Проверка принадлежности сокета к VRF
ss -ntlp
# → Local Address:Port ... Device
# → 0.0.0.0:22            ... vrf-mgmt
```
