# nscd (Name Service Cache Daemon)

## Определения

**`nscd` (Name Service Cache Daemon)** — устаревший (Legacy) системный демон в Linux, предназначенный для кэширования запросов к службам имен через Name Service Switch (NSS). В 2024–2026 годах считается **устаревшим** и заменен на более современные инструменты (SSSD, systemd-resolved).

**Кэшируемые базы данных:**
- `passwd` — учетные записи пользователей.
- `group` — группы пользователей.
- `hosts` — разрешение имен (DNS).
- `services` — информация о сетевых службах.
- `netgroup` — сетевые группы.

**Статус на 2025 год:**
- **RHEL 10 / Fedora 36+:** Удален из репозиториев.
- **Современные дистрибутивы:** Заменен на `sssd` (для пользователей/групп) и `systemd-resolved` (для DNS).

## Основные концепции

### Механизм работы
`nscd` перехватывает вызовы библиотечных функций `libc` (таких как `gethostbyname`, `getpwnam`), которые обычно обращаются к файлам (`/etc/hosts`, `/etc/passwd`) или внешним сервисам (DNS, LDAP). Демон хранит результаты в оперативной памяти или на диске, обеспечивая мгновенный ответ при повторных запросах.

### Проблемы актуальности данных и TTL
Основной недостаток `nscd` при кэшировании DNS — игнорирование значения TTL (Time To Live), установленного в DNS-записи. `nscd` использует собственные настройки времени жизни кэша, что часто приводит к:
- **Устаревшим ответам (Stale data):** Возврат старого IP, когда DNS-сервер уже обновил запись.
- **Негативному кэшированию (Negative Caching):** Сохранение ошибки `NXDOMAIN` на длительный срок, блокируя доступ к недавно созданным доменам.

## Практические сценарии

### Установка и управление сервисом
Несмотря на статус legacy, `nscd` может потребоваться для поддержки старых систем или специфических сценариев.

```bash
# Установка (Debian/Ubuntu)
sudo apt update && sudo apt install nscd

# Установка (RHEL/CentOS/Rocky)
sudo dnf install nscd

# Управление сервисом
sudo systemctl enable --now nscd
sudo systemctl status nscd
```

### Диагностика и статистика кэша
Команда для анализа эффективности кэширования:

```bash
nscd -g
```
Ключевые показатели:
- **positive hits / misses**: соотношение успешных нахождений к промахам.
- **negative hits / misses**: статистика по «отрицательным» ответам (например, хост не найден).
- **check-files**: статус мониторинга изменений в локальных файлах (например, `/etc/hosts`).

### Принудительная очистка (Invalidation)
Если система отдает неверные данные, необходимо сбросить кэш конкретной базы:

```bash
# Сброс кэша DNS (хостов)
sudo nscd -i hosts

# Сброс кэша пользователей
sudo nscd -i passwd

# Сброс кэша групп
sudo nscd -i group
```

### Миграция на современные аналоги
В современной инфраструктуре рекомендуется заменить `nscd` следующими службами:
1. **[systemd-resolved](../../Diagnostics/Networking/dns/dns_resolution_performance.md#сценарий-4-анализ-эффективности-кэширования-systemd-resolved)** — для кэширования DNS с поддержкой TTL и Split DNS.
2. **SSSD (System Security Services Daemon)** — для кэширования данных пользователей и групп, особенно при интеграции с LDAP/AD.

> **Внимание:** Одновременный запуск `nscd` и `sssd` категорически не рекомендуется, так как это приводит к «двойному кэшированию», конфликтам и непредсказуемому поведению системы.

## Конфигурация

Основной файл настроек: `/etc/nscd.conf`.

### Глобальные параметры
```conf
logfile             /var/log/nscd.log  # Путь к файлу логов
threads             4                  # Количество рабочих потоков
debug-level         0                  # Уровень отладки (0-10)
paranoia            no                 # Перезапуск при обнаружении повреждения кэша
restart-interval    3600               # Интервал автоперезапуска (сек)
```

### Настройка базы данных hosts
```conf
enable-cache        hosts   yes     # Включить кэширование DNS
positive-time-to-live hosts  3600    # Время хранения успешных ответов (1 час)
negative-time-to-live hosts  20      # Время хранения NXDOMAIN (20 сек)
suggested-size      hosts   211     # Начальный размер хеш-таблицы
check-files         hosts   yes     # Следить за изменениями в /etc/hosts
shared              hosts   yes     # Разрешить клиентам читать кэш напрямую из памяти
```
