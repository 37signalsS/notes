# NFS: Диагностика и устранение неполадок

---

## Определения

**NFS-диагностика** — системный процесс выявления причин сбоев при монтировании, доступе к данным или деградации производительности в сетевой файловой системе NFS.

**Stale File Handle (ESTALE)** — состояние, при котором клиент обращается к файлу по дескриптору (file handle), который на сервере уже недействителен (файл удален, перемещен на другую ФС или ФС была пересоздана).

**RPC Timeouts** — задержки или отсутствие ответов от удаленных процедур, часто приводящие к зависанию процессов в состоянии `D` (uninterruptible sleep).

---

## Основные концепции

### Инструменты диагностики

| Утилита | Область применения | Техническое назначение |
| :--- | :--- | :--- |
| **`nfsstat`** | Статистика RPC | Анализ количества повторов (`retrans`) и типов вызовов. |
| **`rpcinfo`** | Регистрация RPC | Проверка, зарегистрированы ли службы `nfs`, `mountd`, `nlockmgr` в portmapper. |
| **`nfsiostat`** | Анализ задержек | Посекундный мониторинг Latency для каждой точки монтирования. |
| **`showmount -e`** | Проверка экспортов | Дистанционный просмотр доступных директорий на сервере. |
| **`mountstats`** | Глубокий анализ | Чтение статистики из `/proc/self/mountstats` (RTT, очереди). |
| **`tcpdump`** | Анализ пакетов | Проверка прохождения трафика через порт 2049 (NFS) и 111 (RPC). |

### Важные системные файлы

- **`/proc/fs/nfsd/threads`** — текущее количество работающих потоков на сервере.
- **`/proc/net/rpc/nfsd`** — детальная статистика сервера (кэш ответов, ошибки дескрипторов).
- **`/etc/idmapd.conf`** — конфигурация маппинга имен для NFSv4.

## Практические сценарии

### Проблема: Ошибки при монтировании (Mount Failures)

1.  **"RPC: Program not registered":**
    - *Причина:* Служба NFS не запущена на сервере или `rpcbind` не работает.
    - *Действие:* `sudo systemctl restart nfs-server` на сервере. Проверьте через `rpcinfo -p <server_ip>`.
2.  **"Permission denied" (MNT3ERR_ACCES):**
    - *Причина:* IP клиента не входит в список разрешенных в `/etc/exports` или используются неверные параметры Squash.
    - *Действие:* Проверьте `/etc/exports` и выполните `sudo exportfs -ra` на сервере.
3.  **"Protocol not supported":**
    - *Причина:* Несоответствие версий (например, клиент требует v4.2, а сервер поддерживает только v3).
    - *Действие:* Укажите версию явно: `-o nfsvers=4.1`.

### Проблема: Пользователи отображаются как `nobody`
Характерно для NFSv4 при несовпадении доменов или сбоях маппинга.

**Алгоритм решения:**
1. Проверьте параметр `Domain` в `/etc/idmapd.conf` на обоих концах. Они **должны совпадать**.
2. Проверьте статус демона: `sudo systemctl status nfs-idmapd`.
3. Сбросьте кэш идентификаторов:
   ```bash
   sudo nfsidmap -c
   # → success
   ```

### Проблема: `Stale File Handle` (ESTALE)
Файл или директория были удалены или пересозданы на сервере, но клиент сохранил старый дескриптор.

**Решение:**
1. Найдите процессы, удерживающие дескриптор: `lsof | grep /mnt/nfs`.
2. Если обычный `umount` не помогает (девайс занят), используйте "ленивое" размонтирование:
   ```bash
   sudo umount -l /mnt/nfs
   sudo mount -a
   # → success
   ```
*Примечание:* В NFSv4 эта проблема встречается реже благодаря встроенным механизмам делегирования и проверки состояния.

### Проблема: Проблемы с блокировками (Locking Issues)
Часто в NFSv3, где за блокировки отвечают отдельные службы `lockd` и `statd`.

**Диагностика:**
- Проверьте, что порт `statd` (NSM) открыт в файрволе.
- В NFSv4 блокировки интегрированы в основной протокол (порт 2049), поэтому проблемы с ними обычно означают разрыв TCP-сессии или истечение Lease-таймаута.

### Проблема: Зависание ввода-вывода (IO Hangs)
Процессы замирают при чтении/записи на сетевой диск.

**Действия:**
1.  **Проверка сети:** Проверьте MTU. Несоответствие (например, 9000 на сервере и 1500 на клиенте) ведет к потере фрагментированных пакетов.
    ```bash
    ping -M do -s 8972 <server_ip>  # Проверка Jumbo Frames
    ```
2.  **Проверка RPC:** Посмотрите статистику повторов: `nfsstat -c`. Если `retrans` растет, значит пакеты теряются или сервер перегружен.
3.  **Анализ очередей:** Используйте `nfsiostat 1`. Если `avg exe` (время исполнения) значительно выше `avg RTT` (время сети), значит задержка на стороне дисков сервера.

## Дополнительная информация

### Сетевая отладка через `rpcinfo`

Позволяет проверить доступность конкретных версий протокола:
```bash
# Проверка TCP-соединения с NFS v4 на сервере
rpcinfo -t 10.0.0.5 nfs 4
# → program 100003 version 4 ready and waiting
```

### Контрольный список (Checklist) при сбоях

- [ ] Выполнена ли команда `exportfs -ra` на сервере после изменений?
- [ ] Разрешен ли порт 2049/tcp в `iptables`/`nftables`/`firewalld`?
- [ ] Одинаковы ли значения UID/GID для критически важных пользователей (если не используется Kerberos)?
- [ ] Нет ли ошибок в `/var/log/syslog` или `dmesg` на сервере, связанных с `nfsd` (например, нехватка потоков)?
