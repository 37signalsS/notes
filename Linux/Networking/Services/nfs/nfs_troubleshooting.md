# NFS: Диагностика и устранение неполадок

| Метаданные | Значение |
| :--- | :--- |
| **Оценка надёжности** | 10 (Централизованный материал + проверенные кейсы) |
| **Актуальность** | Июль 2024 (NFSv4.2) |

---

## Определения

**NFS-диагностика** — системный процесс выявления причин сбоев при монтировании, доступе к данным или деградации производительности в сетевой файловой системе NFS.

**Stale File Handle** — состояние, при котором клиент обращается к файлу по дескриптору (inode), который на сервере уже не существует или был заменён (например, после удаления и повторного создания файла).

---

## Основные концепции

### Инструменты диагностики

| Утилита | Область применения | Ключевой флаг |
| :--- | :--- | :--- |
| **`nfsstat`** | Статистика вызовов и ошибок RPC | `-c` (клиент), `-s` (сервер) |
| **`nfsiostat`** | Анализ задержек (Latency) операций | `nfsiostat 1` |
| **`showmount`** | Проверка списка экспортов | `-e <server_ip>` |
| **`rpcinfo`** | Проверка регистрации RPC-служб | `-p <server_ip>` |
| **`mountstats`** | Детальная статистика точки монтирования | `mountstats /mnt/nfs` |
| **`tcpdump`** | Анализ трафика на уровне пакетов | `-i any port 2049` |

### Журналы и системная информация

```bash
# Просмотр ошибок в реальном времени (клиент и сервер)
journalctl -k | grep -i nfs

# Проверка состояния idmapd (маппинг пользователей NFSv4)
sudo systemctl status nfs-idmapd

# Информация об активных клиентах (на сервере)
cat /proc/fs/nfsd/clients/*/info
```

## Практические сценарии

### Проблема: Пользователи отображаются как `nobody` или `4294967294`
Типично для NFSv4 при несовпадении доменов идентификации.

**Решение:**
1. Проверьте параметр `Domain` в файле `/etc/idmapd.conf` на сервере и всех клиентах. Значения должны быть идентичны.
2. Проверьте, запущен ли демон `nfs-idmapd`.
3. Очистите кэш idmap:
   ```bash
   nfsidmap -c
   # → success
   ```

### Проблема: Ошибка `Stale File Handle`
Возникает, когда файл был изменён или удалён на сервере вне контекста текущей сессии клиента.

**Решение:**
1. Попробуйте найти процессы, использующие старую дескриптор: `lsof +D /mnt/nfs`.
2. Если `umount` не срабатывает, используйте "ленивое" размонтирование:
   ```bash
   sudo umount -l /mnt/nfs
   sudo mount -a
   # → success
   ```

### Проблема: Зависание (Hang) при операциях ввода-вывода
Чаще всего связано с использованием опции `hard` при обрыве сетевого соединения.

**Алгоритм действий:**
1. Проверьте сетевую связность и задержки: `ping -s 1472 server_ip` (проверка MTU).
2. Проверьте количество повторных попыток RPC: `nfsstat -c` (поле `retrans`).
3. Если сервер недоступен навсегда, используйте `umount -f -l /mnt/nfs`.

### Проблема: Ошибки доступа (Permission Denied)

| Уровень проверки | Действие |
| :--- | :--- |
| **Экспорт** | Проверьте `/etc/exports` на сервере: разрешён ли IP клиента? |
| **Squash** | Проверьте `root_squash`. Если включено, `root` клиента маппится в `nobody`. |
| **Права ФС** | Проверьте локальные права (POSIX) на директорию на сервере. |
| **MAC (SELinux)** | Проверьте лог `/var/log/audit/audit.log` на предмет блокировок `nfsd`. |

### Проблема: Деградация производительности (Низкий Throughput)
Если сеть 10GbE+, а скорость как у 1GbE.

**Диагностика:**
1. Проверьте параметр `nconnect` в `mount` (должен быть > 1 для распараллеливания TCP-потоков).
2. Проверьте MTU. Несоответствие MTU (например, 9000 на сервере и 1500 на коммутаторе) приводит к массовой фрагментации и потере пакетов.
3. Используйте `nfsiostat` для поиска "медленных" RPC-вызовов (высокий `avg RTT`).

## Дополнительная информация

### Контрольный список при сбоях (Checklist)

1.  **Сетевой уровень:** Доступен ли порт 2049/tcp? (Используйте `nc -zv`).
2.  **Службы:** Запущены ли `nfs-server` (на сервере) и `rpc-statd` (на клиенте)?
3.  **Конфигурация:** Выполнялась ли команда `exportfs -ra` после правок `/etc/exports`?
4.  **Версии:** Не пытаетесь ли вы монтировать NFSv4 по протоколу UDP? (NFSv4 поддерживает только TCP).
