# NFS (Network File System) — устранение неполадок

## Определения

**NFS-диагностика** — процесс выявления и устранения проблем подключения, монтирования, производительности и безопасности в **NFS (Network File System)**. Ключевые симптомы включают зависания системы, ошибки доступа (**Stale file handle**, **Permission denied**), таймауты и сбои аутентификации Kerberos.

## Основные концепции

### Инструменты диагностики

| Утилита | Назначение | Пример использования |
| :--- | :--- | :--- |
| `exportfs -v` | Проверка экспортированных директорий на сервере | `exportfs -v` |
| `showmount -e` | Просмотр доступных ресурсов сервера с клиента | `showmount -e <IP_сервера>` |
| `nfsstat -c` | Статистика **NFS** на стороне клиента | `nfsstat -c` |
| `nfsstat -s` | Статистика **NFS** на стороне сервера | `nfsstat -s` |
| `rpcinfo` | Проверка служб удалённого вызова процедур (**RPC**) | `rpcinfo -p <IP_сервера>` |
| `nc` | Проверка доступности сетевых портов | `nc -zv <IP> 2049` |

### Журналы регистрации (логи)

```bash
# Журнал NFS на сервере (Debian/Ubuntu)
journalctl -u nfs-kernel-server -f
# → -- Groups of logs --

# Журнал NFS на стороне клиента
journalctl -u nfs-client.target -f

# Просмотр системных сообщений ядра
dmesg | grep -i nfs
# → [  12.345678] NFS: Registering the id_resolver key type

# Детальная информация о клиентах на сервере
cat /proc/fs/nfsd/clients/*/info 2>/dev/null
```

## Практические сценарии

### Алгоритм диагностики подключения

```bash
# 1. Проверка состояния службы на сервере
systemctl status nfs-kernel-server
# → Active: active (running)

# 2. Проверка активных экспортов на сервере
exportfs -v
# → /srv/nfs/shared 10.0.0.0/24(rw,wdelay,root_squash,...)

# 3. Проверка доступных ресурсов на клиенте
showmount -e 10.0.0.5
# → Export list for 10.0.0.5:
# → /srv/nfs/shared 10.0.0.0/24

# 4. Проверка доступности сетевого порта 2049 (NFSv4)
nc -zv 10.0.0.5 2049
# → Connection to 10.0.0.5 2049 port [tcp/nfs] succeeded!
```

### Монтирование «зависает» или `df` не отвечает

**Причина:** Недоступность **NFS**-сервера при использовании опции `hard` на клиенте.

**Решение:**

1. Проверьте сетевое соединение с помощью `ping`.
2. Если сервер недоступен, выполните «ленивое» размонтирование:

   ```bash
   sudo umount -l /mnt/nfs
   ```

3. После восстановления доступности сервера выполните повторное монтирование: `sudo mount -a`.

### Ошибка `Stale file handle`

**Причина:** Файл или директория на сервере были удалены или переименованы, но клиент продолжает использовать устаревший идентификатор (inode).

**Решение:**

```bash
# Принудительное размонтирование проблемного пути
sudo umount -f /mnt/nfs/path 2>/dev/null || sudo umount -l /mnt/nfs/path

# Повторное монтирование всех ресурсов из /etc/fstab
sudo mount -a
```

### Ошибка `Permission denied`

**Основные причины:**

| Причина | Диагностика | Решение |
| :--- | :--- | :--- |
| Клиент не указан в `/etc/exports` | `cat /etc/exports` | Добавить **IP (Internet Protocol)** или подсеть клиента |
| Блокировка межсетевым экраном | `sudo ufw status` | Открыть порт **2049/tcp** |
| Несовпадение **UID/GID** | `id` на клиенте и сервере | Синхронизация **UID (User ID)** и **GID (Group ID)** |
| Механизм `root_squash` | `exportfs -v` | Работать от имени обычного пользователя или использовать `no_root_squash` |
| Неверный параметр `sec=` | `mount | grep nfs` | Указать корректный метод аутентификации (sys/krb5) |

### Ошибка `mount.nfs: Connection timed out`

**Решение:**

1. Проверьте сетевую связность до сервера.
2. Убедитесь, что порт **2049** открыт на сервере.
3. Для **NFSv3** проверьте доступность портов **RPC** (порт 111 — `rpcbind`, а также порты `mountd`, `statd`).

### Ошибки Kerberos (`Authentication failed`)

**Причины:** Истечение срока действия билета **TGT (Ticket-Granting Ticket)**, расхождение системного времени или неверный **Principal**.

**Решение:**

```bash
# Проверка наличия и срока действия билета
klist
# → Default principal: user@EXAMPLE.COM

# Получение нового билета Kerberos
kinit user@REALM

# Проверка синхронизации времени (допустимое расхождение < 5 мин)
timedatectl status
# → System clock synchronized: yes
```

### Проблема: низкая производительность

**Решение:** Проверьте параметры монтирования (`rsize`, `wsize`, `noatime`), настройки выделенной сети и **MTU (Maximum Transmission Unit)**. Подробные рекомендации см. в [nfs_performance.md](./nfs_performance.md).
