# NFS (Network File System) — производительность и оптимизация

## Определения

**NFS-производительность** — совокупность параметров и практик, направленных на максимизацию пропускной способности (**throughput**, МБ/с) и минимизацию задержек (**latency**, мс) при работе с сетевыми монтированиями. Ключевые метрики включают количество операций ввода-вывода в секунду (**IOPS — Input/Output Operations Per Second**), пропускную способность и время отклика.

## Основные концепции

### Параметры rsize/wsize

Размер блока данных для операций чтения (`rsize`) и записи (`wsize`). Эти параметры определяют объём данных, передаваемых за одну операцию удалённого вызова процедур (**RPC — Remote Procedure Call**).

| Опция | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `rsize` | Размер блока чтения | 1048576 (1 МБ) |
| `wsize` | Размер блока записи | 1048576 (1 МБ) |
| `timeo` | Таймаут в десятых долях секунды | 600 (60 сек) |
| `retrans` | Количество повторных попыток | 3 |
| `noatime` | Отключить обновление времени доступа | Выключено |
| `nodiratime` | Отключить обновление времени доступа для директорий | Выключено |

### Настройка потоков на сервере

На современных системах (ядро Linux 5.x и выше) параметр `RPCNFSDCOUNT` часто игнорируется, так как ядро может автоматически масштабировать количество потоков `nfsd`. Для ручной настройки в **NFSv4** рекомендуется использовать файл `/etc/nfs.conf`.

**Просмотр и настройка потоков:**

```bash
# Проверить текущее количество активных потоков
cat /proc/fs/nfsd/threads
# → 8

# Временное изменение количества потоков (до перезагрузки)
echo 16 | sudo tee /proc/fs/nfsd/threads
# → 16

# Постоянная настройка через /etc/nfs.conf
# [nfsd]
# threads=16
```

## Практические сценарии

### Монтирование с оптимизированными параметрами

```bash
sudo mount -t nfs4 -o rsize=1048576,wsize=1048576,timeo=600,retrans=3,noatime 10.0.0.5:/srv/nfs/shared /mnt/nfs/shared
```

### Диагностика производительности

```bash
# Статистика NFS на стороне клиента
nfsstat -c
# → Client nfs v4:
# → calls      retrans    authrefrsh
# → 1250       0          1250

# Мониторинг ввода-вывода (I/O) в реальном времени
iostat -x 1
# → avg-cpu:  %user   %nice %system %iowait  %steal   %idle
# →            0.50    0.00    1.20    5.00    0.00   93.30

# Проверка сетевых задержек до сервера
ping -c 4 10.0.0.5
# → 4 packets transmitted, 4 received, 0% packet loss, time 3004ms
# → rtt min/avg/max/mdev = 0.120/0.150/0.180/0.020 ms
```

### Рекомендации по оптимизации

1. **Версия протокола:** Используйте **NFSv4.2** для поддержки копирования на стороне сервера (server-side copy) и разреженных файлов (sparse files).
2. **Параллельный NFS (pNFS — Parallel NFS):** Для кластерных решений используйте pNFS для распределения нагрузки.
3. **Метаданные:** Включайте опцию `noatime` для снижения количества операций записи при чтении файлов.
4. **Режим записи:** Используйте `sync` для критически важных данных и `async` для временных файлов или кэшируемых данных (повышает скорость, но снижает надёжность при сбое).
5. **Размер блоков (rsize/wsize) под нагрузку:**
   - Большие файлы (видео, бэкапы): `1048576` (1 МБ).
   - Множество мелких файлов: `32768` (32 КБ) или `65536` (64 КБ).
6. **Сетевая инфраструктура:**
   - Выделенная сеть или **VLAN (Virtual Local Area Network)** для трафика хранения.
   - Использование **Jumbo Frames** с **MTU (Maximum Transmission Unit)** 9000 в изолированных сетях.
