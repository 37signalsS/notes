# NFS: Производительность и оптимизация

---

## Определения

**NFS-производительность** — совокупная мера эффективности сетевой файловой системы, оцениваемая по пропускной способности (**Throughput**), задержкам (**Latency**) и количеству операций ввода-вывода в секунду (**IOPS**).

**RPC (Remote Procedure Call) Slots** — внутренние структуры данных ядра, определяющие количество одновременных запросов, которые клиент может отправить серверу по одному соединению.

**pNFS (Parallel NFS)** — расширение протокола NFSv4.1+, позволяющее клиентам получать доступ к данным напрямую с нескольких серверов хранения (Data Servers), минуя основной сервер метаданных.

---

## Основные концепции

### Клиентские механизмы ускорения

1.  **Размер блоков (`rsize`/`wsize`):** Максимальный объём данных в одном RPC-пакете. Современный стандарт — `1048576` (1 МБ). При использовании Jumbo Frames (MTU 9000) большие блоки значительно снижают накладные расходы на обработку прерываний.
2.  **Множественные соединения (`nconnect`):** Параметр (ядро 5.3+), позволяющий открывать до 16 TCP-соединений для одной точки монтирования.
    - *Преимущество:* Параллелизация трафика, обход ограничений одного потока TCP.
    - *Ограничение:* При использовании Kerberos (`sec=krb5*`) эффективность может зависеть от версии ядра и реализации GSS-API.
3.  **Кэширование атрибутов (`actimeo`):** Устанавливает время жизни (в секундах) для кэша атрибутов файлов и директорий.
    - `actimeo=60` значительно снижает количество запросов `GETATTR` в средах с множеством мелких файлов, но может приводить к временной рассинхронизации состояния файлов между клиентами.
4.  **Локальное кэширование (FS-Cache):** Использование локального диска клиента для кэширования данных NFS (через `cachefilesd`). Включается опцией монтирования `fsc`.

### Серверная оптимизация

1.  **Потоки `nfsd`:** Количество процессов в ядре для обработки запросов.
    - Рекомендуемое значение: от 2 до 4 потоков на каждое ядро процессора сервера.
    - Мониторинг очередей: если `/proc/net/rpc/nfsd` показывает большое количество `th_usage` на высоких процентах, количество потоков нужно увеличить.
2.  **Задержки дисковой подсистемы:** NFS крайне чувствителен к задержкам. Использование SSD/NVMe и RAID с кэшем на запись (с защитой по питанию) критично при монтировании с опцией `sync`.

### Сетевые параметры

- **Jumbo Frames (MTU 9000):** Рекомендуется для выделенных сетей хранения данных (SAN/NAS). Снижает накладные расходы на инкапсуляцию.
- **RPC Slot Table:** Ограничивает количество "in-flight" запросов.
    - По умолчанию — 65.
    - Для высокопроизводительных 10/40/100GbE сетей рекомендуется увеличивать до 128 или 256.

## Практические сценарии

### Настройка монтирования для высокоскоростных сетей

Сценарий оптимизации для клиента в 10GbE+ сети, работающего с тяжелыми данными.

```bash
# Монтирование с параллелизацией, кэшированием и FS-Cache
sudo mount -t nfs -o nfsvers=4.2,nconnect=8,rsize=1048576,wsize=1048576,noatime,fsc 10.0.0.5:/data /mnt/data
# → success
```

**Разбор опций:**
- `nconnect=8`: 8 TCP-каналов для передачи данных.
- `noatime`: Отключение обновления времени доступа (снижает нагрузку на метаданные при чтении).
- `fsc`: Использование локального кэша диска (требует работающего `cachefilesd`).

### Тюнинг RPC-слотов и TCP (sysctl)

Для устранения узких мест в сетевом стеке примените следующие настройки на клиенте:

```bash
# Увеличение таблицы слотов RPC
sudo sysctl -w sunrpc.tcp_slot_table_entries=128
sudo sysctl -w sunrpc.tcp_max_slot_table_entries=128

# Оптимизация буферов TCP для 10GbE
sudo sysctl -w net.core.rmem_max=16777216
sudo sysctl -w net.core.wmem_max=16777216
# → success
```

### Настройка количества потоков на сервере

Отредактируйте `/etc/nfs.conf` (или `/etc/default/nfs-kernel-server` в старых системах):

```ini
[nfsd]
threads=128
```

Перезапустите сервис и проверьте результат:
```bash
sudo systemctl restart nfs-server
cat /proc/fs/nfsd/threads
# → 128
```

## Дополнительная информация

### Продвинутые механизмы

- **NFSv4.2 Server-Side Copy (SSC):** Позволяет клиенту отправить команду серверу скопировать файл из одной директории в другую без перекачивания данных по сети.
- **pNFS (Parallel NFS):** Позволяет масштабировать пропускную способность за счет прямого доступа к нескольким узлам хранения. Требует сложной настройки и поддержки на стороне СХД (Data Servers).
- **Диагностика через `nfsiostat`:**
  ```bash
  nfsiostat 5 /mnt/data
  # → Показывает: avg RTT (мс), avg exe (мс), пропускную способность (MB/s).
  ```

### Резюме по опциям `sync` vs `async`

| Режим | Безопасность | Производительность | Резюме |
| :--- | :--- | :--- | :--- |
| **`sync`** | Максимальная | Низкая (особенно на запись) | Обязательно для БД и критичных данных. |
| **`async`** | Низкая (риск потери данных) | Экстремальная | Подходит для временных файлов, логов или сред с ИБП. |
