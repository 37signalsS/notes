# NFS: Производительность и оптимизация

| Метаданные | Значение |
| :--- | :--- |
| **Оценка надёжности** | 10 (Централизованный материал + RFC + Практика) |
| **Актуальность** | Июль 2024 (Kernel 5.3+, NFSv4.2) |

---

## Определения

**NFS-производительность** — совокупная мера эффективности сетевой файловой системы, оцениваемая по пропускной способности (**Throughput**), задержкам (**Latency**) и количеству операций ввода-вывода в секунду (**IOPS**).

**RPC (Remote Procedure Call) Slots** — внутренние структуры данных ядра, определяющие количество одновременных запросов, которые клиент может отправить серверу по одному соединению.

---

## Основные концепции

### Клиентские механизмы ускорения

1.  **Размер блоков (`rsize`/`wsize`):** Максимальный объём данных в одном RPC-пакете. Современный стандарт — 1048576 (1 МБ). Большие блоки уменьшают накладные расходы на заголовки при передаче крупных файлов.
2.  **Множественные соединения (`nconnect`):** Параметр (доступен с ядра 5.3), позволяющий открывать несколько TCP-соединений (до 16) для одной точки монтирования. Это позволяет обойти ограничения пропускной способности одного потока и эффективнее использовать многоядерные процессоры и широкие каналы связи.
3.  **Кэширование атрибутов (`actimeo`):** Время жизни кэша метаданных (права, размер, время модификации). Увеличение `actimeo` снижает количество проверочных запросов `GETATTR` к серверу, что критично при работе с тысячами мелких файлов.

### Серверные ресурсы

1.  **Потоки `nfsd`:** Количество процессов в ядре, обрабатывающих входящие запросы. Недостаток потоков приводит к постановке RPC-запросов в очередь и росту задержек.
2.  **Задержки дисковой подсистемы:** NFS крайне чувствителен к времени отклика дисков сервера, особенно при использовании опции `sync`.

### Сетевые параметры

- **Jumbo Frames (MTU 9000):** Снижает количество прерываний процессора при обработке трафика. Рекомендуется только в изолированных сетях хранения.
- **TCP Slot Table:** Ограничивает количество "летящих" (in-flight) RPC-запросов. Для 10GbE+ сетей значения по умолчанию (обычно 65) могут быть недостаточны.

## Практические сценарии

### Настройка высокопроизводительного монтирования

Сценарий для клиента в 10GbE сети, работающего с большими объёмами данных.

```bash
# Монтирование с использованием 8 TCP-соединений и оптимизированным кэшированием
sudo mount -t nfs4 -o nconnect=8,rsize=1048576,wsize=1048576,noatime,actimeo=60 10.0.0.5:/data /mnt/data
# → success
```

**Разбор опций:**
- `nconnect=8`: Параллелизация трафика по 8 соединениям.
- `noatime`: Отключение записи времени последнего доступа (снижает нагрузку на запись).
- `actimeo=60`: Кэширование атрибутов файлов на 60 секунд.

### Тюнинг сервера (Debian/Ubuntu)

1.  **Увеличение количества потоков:**
    Отредактируйте `/etc/nfs.conf`:
    ```ini
    [nfsd]
    threads=64
    ```
    Примените изменения:
    ```bash
    sudo systemctl restart nfs-server
    sudo cat /proc/fs/nfsd/threads
    # → 64
    ```

2.  **Тюнинг RPC-слотов (на клиенте):**
    Для очень быстрых сетей увеличьте лимиты через `sysctl`:
    ```bash
    sudo sysctl -w sunrpc.tcp_slot_table_entries=128
    ```

### Инструменты диагностики

1.  **`nfsiostat`:** Аналог `iostat` специально для NFS. Показывает задержки RPC и пропускную способность.
    ```bash
    nfsiostat 1 /mnt/data
    # → op/s      rpc bklog
    # → 1500.00   0.00
    ```
2.  **`nfsstat`:** Статистика по версиям протокола и типам вызовов.
    ```bash
    nfsstat -c  # Статистика на клиенте
    nfsstat -s  # Статистика на сервере
    ```
3.  **`mountstats`:** Детальная статистика по конкретной точке монтирования, включая среднее время RTT (Round Trip Time).

## Дополнительная информация

### Рекомендации по оптимизации

- **NFSv4.2 Server-Side Copy:** Позволяет копировать файлы внутри одной шары без перекачивания данных через клиента.
- **pNFS (Parallel NFS):** Позволяет клиентам напрямую обращаться к нескольким узлам хранения. Требует поддержки на стороне СХД.
- **Async vs Sync:** Использование `async` в `/etc/exports` на сервере радикально повышает скорость записи, но делает данные уязвимыми при сбое питания сервера. Рекомендуется использовать только с ИБП или для некритичных данных.
