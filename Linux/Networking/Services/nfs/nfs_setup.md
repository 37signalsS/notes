# NFS: Настройка сервера и клиента

## Настройка NFS-сервера

### Установка

```bash
# Для Debian/Ubuntu
sudo apt-get update
sudo apt-get install -y nfs-kernel-server

# Для CentOS/RHEL
sudo yum install -y nfs-utils
```

### Создание экспортируемой директории

```bash
sudo mkdir -p /srv/nfs/shared
sudo chown nobody:nogroup /srv/nfs/shared
sudo chmod 0755 /srv/nfs/shared
```

### Конфигурация экспорта (`/etc/exports`)

Файл `/etc/exports` определяет экспортируемые директории и права доступа к ним.

**Формат:** `<директория> <клиент>(<опции>)`

**Пример:**

```ini
# Доступ для клиента 10.0.0.10
/srv/nfs/shared 10.0.0.10(rw,sync,no_subtree_check)

# Доступ для подсети 10.0.0.0/24
/srv/nfs/data 10.0.0.0/24(rw,sync,no_subtree_check)

# Только для чтения
/srv/nfs/readonly 10.0.0.0/24(ro,sync,no_subtree_check,root_squash)
```

**Основные опции:**

| Опция             | Описание                                                                                             |
| :---------------- | :--------------------------------------------------------------------------------------------------- |
| `ro` / `rw`       | Доступ только для чтения / чтения и записи.                                                          |
| `sync`            | Сервер подтверждает запись только после сохранения на диск. Обеспечивает надежность.                 |
| `async`           | Сервер подтверждает запись до сохранения на диск. Увеличивает скорость, но не гарантирует целостность данных при сбое. |
| `root_squash`     | Запросы от `root` клиента выполняются от имени `nobody`. Рекомендуется для безопасности.             |
| `no_root_squash`  | **(ОПАСНО)** Разрешает `root` клиенту иметь полные `root`-права на сервере в экспортируемой папке.   |
| `all_squash`      | Все запросы выполняются от имени `nobody:nogroup`. Полезно для публичных ресурсов. |
| `anonuid=<UID>`   | Указывает UID для `all_squash`. Позволяет задать конкретного пользователя. |
| `anongid=<GID>`   | Указывает GID для `all_squash`. |
| `no_subtree_check`| Отключает проверку поддиректорий, повышая производительность. Рекомендуется.                        |

Подробнее о security-опциях (`sec=krb5*`) см. [Безопасность NFS](./nfs_security.md).

### Применение конфигурации

```bash
sudo exportfs -a                 # Применить изменения в /etc/exports
sudo systemctl restart nfs-kernel-server # Перезапустить службу NFS
```

## Настройка NFS-клиента

### Установка

```bash
# Для Debian/Ubuntu
sudo apt-get update
sudo apt-get install -y nfs-common

# Для CentOS/RHEL
sudo yum install -y nfs-utils
```

### Просмотр доступных ресурсов

```bash
showmount -e <IP_адрес_сервера>
```

### Монтирование

1. **Создание точки монтирования:**

    ```bash
    sudo mkdir -p /mnt/nfs/shared
    ```

2. **Временное монтирование (для проверки):**

    ```bash
    # NFSv4 (рекомендуется)
    sudo mount -t nfs4 10.0.0.5:/srv/nfs/shared /mnt/nfs/shared
    ```

3. **Автоматическое монтирование через `/etc/fstab`:**

    ```ini
    # <сервер>:<путь>             <точка_монтирования>  <тип>  <опции>                      <dump> <pass>
    10.0.0.5:/srv/nfs/shared    /mnt/nfs/shared       nfs4   hard,nofail,noatime,_netdev    0      0
    ```

    **Ключевые опции для `fstab`:**

    | Опция     | Описание                                                                                                   |
    | :-------- | :--------------------------------------------------------------------------------------------------------- |
    | `hard`    | Процесс "зависнет" при недоступности сервера до восстановления связи. Рекомендуется для предотвращения потери данных. |
    | `soft`    | Процесс получит ошибку ввода-вывода при недоступности сервера. Может привести к повреждению данных. Не рекомендуется. |
    | `nofail`  | Система не прекратит загрузку, если NFS-сервер недоступен.                                                  |
    | `noatime` | Отключает обновление времени доступа к файлам, повышая производительность.                                 |
    | `_netdev` | Указывает системе монтировать ресурс только после поднятия сети.                                           |

### Автоматическое монтирование через AutoFS

Для динамического монтирования NFS-ресурсов (например, домашних директорий пользователей) рекомендуется использовать **AutoFS** вместо статического монтирования в fstab.

Подробная настройка AutoFS для NFS описана в разделе [Монтирование по требованию с помощью Autofs](../../../FileSystems/mounting/scenarios/autofs_mount.md).
