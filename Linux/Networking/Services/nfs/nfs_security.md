# NFS: Безопасность и аутентификация

---

## Определения

**NFS-безопасность** — комплекс мер по защите сетевой файловой системы, включающий проверку подлинности (аутентификацию), разграничение прав доступа (авторизацию), контроль целостности данных и сетевую изоляцию.

**RPCSEC_GSS** — протокол безопасности, позволяющий NFS использовать механизмы GSS-API (Generic Security Services Application Program Interface), такие как Kerberos, для обеспечения надежной аутентификации и шифрования.

**Labeled NFS** — расширение протокола (NFSv4.2), позволяющее передавать метки безопасности (Security Attributes) между клиентом и сервером для поддержки систем принудительного контроля доступа (MAC), таких как SELinux.

---

## Основные концепции

### Методы аутентификации (`sec=`)

Параметр `sec` в `/etc/exports` или опциях монтирования определяет уровень защиты.

| Метод | Уровень защиты | Техническое описание |
| :--- | :--- | :--- |
| **`sys`** | Минимальный | Использует стандартные UID/GID. Сервер доверяет идентификаторам, присланным клиентом. Уязвим для подмены IP и идентификаторов. |
| **`krb5`** | Средний | Аутентификация на базе билетов Kerberos. Проверяет подлинность пользователя, но трафик передается в открытом виде. |
| **`krb5i`** | Высокий | Kerberos + контроль целостности (Integrity). Каждый пакет подписывается криптографически, защищая от модификации (MitM). |
| **`krb5p`** | Максимальный | Kerberos + шифрование (Privacy). Полное шифрование данных и метаданных трафика. Рекомендуется для недоверенных сетей. |

### Механизмы маппинга (Squash)

Управление тем, как сервер интерпретирует запросы от пользователей клиента.

- **`root_squash` (По умолчанию):** Запросы от `root` (UID 0) преобразуются в анонимного пользователя (`nobody`). Это критически важно для защиты сервера от скомпрометированных клиентов.
- **`no_root_squash`:** `root` на клиенте обладает правами `root` на сервере. Разрешено только для специфических задач (например, бездисковая загрузка), где доверие между узлами абсолютно.
- **`all_squash`:** Все пользователи маппятся в анонимного (`anonuid`/`anongid`). Идеально для публичных хранилищ "только для чтения".

### Безопасность поддеревьев (Subtree Check)

- **`subtree_check`:** Сервер проверяет, находится ли запрашиваемый файл в разрешенном поддереве. Это безопаснее, если экспортируется не весь раздел диска, но может вызывать проблемы с открытыми файлами при переименовании директорий.
- **`no_subtree_check`:** Отключает проверку. Повышает производительность и стабильность, рекомендуется, если экспортируется вся файловая система (весь раздел).

## Практические сценарии

### Закаленная конфигурация экспорта (`/etc/exports`)

Пример настройки с максимальной изоляцией и шифрованием:

```ini
# Экспорт для критических данных (только конкретный IP, Kerberos с шифрованием)
/srv/nfs/secure 10.0.0.42(rw,sync,sec=krb5p,root_squash,no_subtree_check)

# Резервные копии (только чтение, маппинг всех в nobody)
/srv/nfs/backups 10.0.0.0/24(ro,all_squash,anonuid=65534,anongid=65534)
```

### Настройка Labeled NFS (SELinux)

Для передачи контекстов SELinux убедитесь, что используется NFSv4.2.

**На сервере и клиенте:**
```bash
# Проверка поддержки в ядре (должно быть Y)
grep CONFIG_NFS_V4_2 /boot/config-$(uname -r)
# → CONFIG_NFS_V4_2=y
```

**Монтирование на клиенте:**
```bash
sudo mount -t nfs -o nfsvers=4.2 10.0.0.5:/data /mnt/data
# Проверка меток
ls -Z /mnt/data
# → system_u:object_r:nfs_t:s0 file.txt
```

### Харденинг RPC и Сетевого экрана

NFSv4 требует только порт **2049/TCP**. Все остальные службы (portmapper, mountd) можно ограничить или отключить.

**Firewalld (RHEL/CentOS):**
```bash
# Разрешить NFS только из доверенной зоны
sudo firewall-cmd --permanent --zone=internal --add-service=nfs
sudo firewall-cmd --permanent --zone=public --remove-service=nfs
sudo firewall-cmd --reload
# → success
```

**UFW (Ubuntu):**
```bash
sudo ufw allow from 10.0.0.0/24 to any port 2049 proto tcp
# → Rule added
```

### Интеграция с Kerberos (краткий алгоритм)

1.  **Настройка KDC:** Добавьте принципалы службы `nfs/hostname.domain`.
2.  **Keytab:** Экспортируйте ключи в `/etc/krb5.keytab` на сервере и клиенте.
3.  **Запуск служб:** Включите `rpc-gssd` на клиенте и `rpc-svcgssd` на сервере.
4.  **Монтирование:** Используйте `-o sec=krb5p`.

## Дополнительная информация

### Шифрование без Kerberos

Если внедрение инфраструктуры Kerberos избыточно, используйте туннелирование для защиты трафика:
- **WireGuard / IPsec:** Создание зашифрованного канала между узлами и монтирование NFS через внутренние IP туннеля.
- **SSH Tunnel:** (Для разовых задач) Переброс порта 2049, однако это может вызвать проблемы с производительностью.

### Контрольный список (Checklist)

- [ ] Использовать только NFSv4.2 (отключить NFSv3 в настройках `/etc/default/nfs-kernel-server` или `/etc/nfs.conf`).
- [ ] Применять `root_squash` для всех общих ресурсов.
- [ ] Ограничивать экспорт конкретными IP-адресами (избегать имен хостов, которые можно подменить через DNS-спуфинг).
- [ ] Регулярно проверять лог `/var/log/audit/audit.log` на предмет отказов в доступе (особенно при использовании SELinux).
