# NFS: Безопасность и аутентификация

| Метаданные | Значение |
| :--- | :--- |
| **Оценка надёжности** | 10 (Централизованный материал + RFC) |
| **Актуальность** | Июль 2024 (NFSv4.2+) |

---

## Определения

**NFS-безопасность** — комплекс мер по защите сетевой файловой системы, включающий проверку подлинности (аутентификацию), разграничение прав доступа (авторизацию), шифрование трафика и сетевую изоляцию.

**RPC (Remote Procedure Call)** — протокол, на котором базируется NFS. Его безопасность критически важна, так как уязвимости в RPC-службах (например, `rpcbind`) могут привести к компрометации сервера.

---

## Основные концепции

### Методы аутентификации (`sec=`)

Параметр `sec` определяет уровень защиты соединения между клиентом и сервером.

| Метод | Уровень защиты | Описание |
| :--- | :--- | :--- |
| **`sys`** | Низкий | Использует UID/GID пользователя. Доверяет клиенту "на слово". Легко компрометируется подменой IP или идентификатора. |
| **`krb5`** | Средний | Аутентификация через Kerberos. Проверяет подлинность пользователя и сервера, но не шифрует данные. |
| **`krb5i`** | Высокий | Kerberos + контроль целостности. Защищает от атак типа "Man-in-the-Middle" (изменение данных в пути). |
| **`krb5p`** | Максимальный | Kerberos + шифрование. Полная конфиденциальность трафика. Существенно нагружает CPU. |

### Механизмы Squash (маппинг root)

По умолчанию NFS-сервер не доверяет `root`-пользователю удалённой машины.

- **`root_squash` (рекомендуется):** Запросы от `root` (UID 0) преобразуются в анонимного пользователя `nobody`. Это предотвращает ситуацию, когда взломанный клиент получает полный контроль над файлами сервера.
- **`no_root_squash` (опасно):** `root` на клиенте имеет права `root` на сервере. Допустимо только для бездисковых станций или узкоспециализированных кластеров в изолированных сетях.
- **`all_squash`:** Все пользователи (включая обычных) маппятся в анонимного. Полезно для публичных файловых архивов.

### Безопасность в NFSv4.2

Современная версия протокола поддерживает **Labeled NFS** (метки безопасности). Это позволяет передавать контексты **SELinux** или **AppArmor** между клиентом и сервером, обеспечивая гранулярный контроль доступа на уровне Mandatory Access Control (MAC).

## Практические сценарии

### Настройка безопасного экспорта (`/etc/exports`)

Пример конфигурации с ограничением по сети и использованием Kerberos:

```ini
# Безопасный экспорт для доверенной подсети
/srv/nfs/secure 10.0.0.0/24(rw,sync,sec=krb5p,root_squash,no_subtree_check)

# Публичный архив только для чтения
/srv/nfs/public 192.168.1.0/24(ro,all_squash,anonuid=65534,anongid=65534)
```

### Настройка Firewall

**Для NFSv4 (используется только порт 2049):**

```bash
# ufw
sudo ufw allow from 10.0.0.0/24 to any port 2049 proto tcp
# → Rule added

# firewalld
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="10.0.0.0/24" service name="nfs" accept'
sudo firewall-cmd --reload
# → success
```

**Для NFSv3 (не рекомендуется):** Требуется открытие портов `rpcbind` (111), `mountd`, `statd`. Рекомендуется фиксировать эти порты в конфигурации `/etc/default/nfs-kernel-server` для упрощения правил файрвола.

### Интеграция с Kerberos

1. **На сервере:** Создайте системный principal и добавьте его в keytab.
   ```bash
   kadmin -q "addprinc -randkey nfs/server.example.com"
   kadmin -q "ktadd /etc/krb5.keytab nfs/server.example.com"
   ```
2. **На клиенте:** Выполните аналогичные действия и смонтируйте ресурс.
   ```bash
   sudo mount -t nfs4 -o sec=krb5p server.example.com:/data /mnt/data
   # → success
   ```

## Дополнительная информация

### Контрольный список (Checklist) безопасности

1.  **Изоляция сети:** Всегда выделяйте NFS-трафик в отдельный VLAN или приватную сеть.
2.  **Минимальные привилегии:** Никогда не используйте `*` в `/etc/exports`, указывайте конкретные IP или подсети.
3.  **Защита idmapd:** В NFSv4 убедитесь, что параметр `Domain` в `/etc/idmapd.conf` совпадает на всех узлах. Это предотвращает маппинг всех файлов в `nobody` из-за несовпадения доменов.
4.  **Мониторинг:** Используйте `nfsstat` и анализ логов `/var/log/syslog` для обнаружения попыток несанкционированного доступа.
