# NFS — сетевая файловая система

---

## Определения

**NFS (Network File System)** — протокол распределённой файловой системы, позволяющий монтировать удалённые директории и работать с ними как с локальными. Протокол обеспечивает прозрачный доступ к файлам по сети, инкапсулируя сетевые вызовы в стандартные операции VFS (Virtual File System).

**NAS (Network Attached Storage)** — класс устройств или сервисов, предоставляющих файловое хранилище по сети. NFS является одним из основных протоколов для взаимодействия с NAS в Unix/Linux-средах.

**VFS (Virtual File System)** — абстрактный слой ядра Linux, предоставляющий унифицированный интерфейс для различных файловых систем. NFS регистрируется в VFS как сетевой тип файловой системы.

**RPC (Remote Procedure Call)** — механизм, используемый NFS для выполнения команд на удалённом сервере. В версиях до NFSv3 включительно RPC требовал динамического распределения портов через `rpcbind`. Начиная с NFSv4, протокол работает через фиксированный порт **2049/TCP**.

**Экспорт (Export)** — директория на сервере, объявленная доступной для монтирования удалёнными клиентами. Конфигурируется в `/etc/exports`.

**Монтирование (Mount)** — процесс подключения экспортированной директории к файловому пространству клиента.

**File Handle** — уникальный opaque-идентификатор файла или директории, присваиваемый сервером. Клиент использует его в последующих операциях вместо имени пути.

**Делегирование (Delegation)** — механизм NFSv4, при котором сервер временно передаёт клиенту права на управление кэшированием файла, уменьшая количество обращений к серверу.

**Лиза (Lease)** — временной интервал, в течение которого сервер гарантирует клиенту сохранность состояний (например, блокировок). Клиент должен подтверждать активность до истечения лиза.

## Основные концепции

### Архитектура и версии

NFS реализует клиент-серверную модель. Современный стандарт NFSv4 значительно отличается от предыдущих версий тем, что он является **Stateful** (сохраняет состояние открытых файлов и блокировок) и требует только один открытый порт в сетевом экране.

| Версия | Состояние | Особенности |
| :--- | :--- | :--- |
| **NFSv3** | Устарела | Stateless, требует `rpcbind` (порт 111) и дополнительные порты для `mountd`, `lockd`. |
| **NFSv4.0** | Поддерживается | Stateful, один порт (2049/TCP), встроенная поддержка ACL (Access Control Lists). |
| **NFSv4.1** | Рекомендуется | Поддержка **pNFS (Parallel NFS)** для разделения данных и метаданных. Улучшенная сессионность. |
| **NFSv4.2** | Актуальная | **Server-Side Copy** (копирование внутри сервера), разреженные файлы (**Sparse Files**), резервирование места. |

### Компоненты системы

| Компонент | Назначение | Версия NFS |
| :--- | :--- | :--- |
| **nfsd** (nfs-kernel-server) | Основной демон сервера, обрабатывающий запросы ввода-вывода. | Все |
| **rpcbind** | Служба сопоставления портов RPC. Необходима для NFSv3; в чистых средах NFSv4 может быть отключена. | NFSv3, частично NFSv4 |
| **mountd** | Демон, обрабатывающий запросы на монтирование (`MOUNT`/`UMOUNT`). В NFSv4 функция интегрирована в `nfsd`. | NFSv3 |
| **rpc.idmapd** | Демон маппинга имен пользователей и групп для NFSv4. Обеспечивает согласованность прав, когда UID/GID на клиенте и сервере не совпадают. | NFSv4 |
| **rpc.statd** (NSM) | Network Status Monitor. Обрабатывает уведомления о перезагрузке сервера для корректной работы блокировок. | NFSv3 |
| **rpc.lockd** (NLM) | Network Lock Manager. Управляет блокировками файлов в NFSv3. | NFSv3 |

### Механизмы блокировок (Locking)

- **NFSv3:** Использует вспомогательные протоколы **NLM (Network Lock Manager)** и **NSM (Network Status Monitor)**. Это часто вызывает проблемы при работе через NAT или Firewall.
- **NFSv4:** Блокировки интегрированы непосредственно в протокол NFS. Сервер отслеживает состояние (Leases), и клиент должен периодически подтверждать свою активность.

### Безопасность и идентификация

1.  **Механизмы аутентификации (`sec=`):**
    - `sys` (по умолчанию): Доверие на основе UID/GID клиента. Небезопасно, так как заголовки легко подделать.
    - `krb5`: Аутентификация через Kerberos.
    - `krb5i`: Kerberos + проверка целостности данных (защита от атак Man-in-the-Middle).
    - `krb5p`: Kerberos + полное шифрование трафика (Privacy).

2.  **Маппинг пользователей (NFSv4):**
    NFSv4 использует строковые имена (`user@domain`) вместо числовых UID/GID.
    - **`rpc.idmapd`** — демон (или встроенный в ядро механизм), преобразующий имена пользователей.
    - **`root_squash`** — маппинг `root` клиента в анонимного пользователя (`nobody/nogroup`) на сервере для предотвращения захвата прав.

### Клиентское кэширование

NFS-клиент поддерживает два уровня кэша:

- **Атрибуты (Attribute Cache):** Кэширует метаданные (размер, время модификации, права). Управляется опцией `actimeo`. Слишком большое значение может привести к рассинхронизации между клиентами.
- **Данные (Data Cache):** Кэширует содержимое файлов. Управляется опциями `rsize`/`wsize` и демоном `cachefilesd` (FS-Cache).

### Требования к сетевому экрану

| Версия | Порты / Протокол | Примечание |
| :--- | :--- | :--- |
| **NFSv3** | 111/tcp (rpcbind), 2049/tcp (nfsd), 32767-32770/tcp (mountd, statd, lockd — динамические) | Сложное управление правилами из-за динамических портов. |
| **NFSv4** | 2049/tcp | Единственный обязательный порт. Остальные службы могут быть отключены. |

### Обзор параметров экспорта

| Категория | Опция | Эффект |
| :--- | :--- | :--- |
| **Доступ** | `rw` / `ro` | Запись или только чтение. |
| **Синхронизация** | `sync` / `async` | `sync` — запись подтверждается после физической записи; `async` — выше производительность, но риск потери данных. |
| **Безопасность** | `root_squash` / `no_root_squash` / `all_squash` | Управление маппингом UID 0 и анонимных пользователей. |
| **Производительность** | `no_subtree_check` | Отключает проверку поддерева. Рекомендуется для целых разделов. |
| **Сеть** | `secure` / `insecure` | Ограничение на источники запросов (привилегированные / непривилегированные порты). |

### Обзор параметров монтирования

| Категория | Опция | Эффект |
| :--- | :--- | :--- |
| **Надёжность** | `hard` / `soft` | `hard` — повтор при сбое (защита от повреждения данных); `soft` — возврат ошибки (риск для БД). |
| **Сеть** | `_netdev` | Монтирование после поднятия сетевого интерфейса (обязательно для fstab). |
| **Протокол** | `nfsvers=4.2` | Явное указание версии. |
| **Производительность** | `rsize` / `wsize` | Размер блока данных (обычно 1048576). |
| **Параллелизм** | `nconnect=N` | Количество параллельных TCP-соединений (ядро 5.3+, NFSv4.2+). |

## Практические сценарии

### Быстрый старт (Ubuntu/Debian)

Базовая настройка для обмена данными в доверенной подсети.

**Настройка сервера:**
```bash
sudo apt update && sudo apt install -y nfs-kernel-server
# Создание директории и установка прав
sudo mkdir -p /srv/nfs/shared
sudo chown nobody:nogroup /srv/nfs/shared
# Добавление записи в /etc/exports
echo "/srv/nfs/shared 10.0.0.0/24(rw,sync,no_subtree_check)" | sudo tee -a /etc/exports
# Применение конфигурации
sudo exportfs -ra
# → success
```

**Настройка клиента:**
```bash
sudo apt update && sudo apt install -y nfs-common
sudo mkdir -p /mnt/shared
# Монтирование с использованием NFSv4.2
sudo mount -t nfs -o nfsvers=4.2 10.0.0.5:/srv/nfs/shared /mnt/shared
# → success
```

### Быстрый старт (RHEL / CentOS / Rocky / AlmaLinux)

Аналогичная настройка для экосистемы RHEL.

**Настройка сервера:**
```bash
sudo dnf install -y nfs-utils
sudo systemctl enable --now nfs-server
# Создание директории
sudo mkdir -p /srv/nfs/shared
sudo chown nfsnobody:nfsnobody /srv/nfs/shared
# Добавление записи в /etc/exports
echo "/srv/nfs/shared 10.0.0.0/24(rw,sync,no_subtree_check,root_squash)" | sudo tee -a /etc/exports
sudo exportfs -ra
# → success
```

**Настройка клиента:**
```bash
sudo dnf install -y nfs-utils
sudo mkdir -p /mnt/shared
sudo mount -t nfs -o nfsvers=4.2,hard,timeo=600,_netdev 10.0.0.5:/srv/nfs/shared /mnt/shared
# → success
```

### Постоянное монтирование через fstab

Для автоматического подключения при загрузке системы добавьте запись в `/etc/fstab`:

```text
10.0.0.5:/srv/nfs/shared  /mnt/shared  nfs  nfsvers=4.2,hard,timeo=600,nconnect=4,_netdev  0 0
```

**Примечание:** Параметр `_netdev` критически важен — он откладывает монтирование до полной инициализации сети, предотвращая зависание загрузки при недоступном сервере.

### Мониторинг в производственной среде

Для контроля состояния NFS в инфраструктуре SRE/DevOps необходимо отслеживать:

- **Доступность экспорта:** `showmount -e <server>` из скриптов проверки работоспособности.
- **Задержки и повторы:** `nfsiostat 1` — при росте `retrans` выше 1-2% требуется анализ сети.
- **Очереди сервера:** `/proc/net/rpc/nfsd` — рост `th_usage` указывает на нехватку потоков.
- **Сетевые ошибки:** `nfsstat -c` — мониторинг количества `cached` vs `retrans`.

### Резервное копирование и восстановление

NFS-ресурсы следует монтировать с опцией `hard` для предотвращения повреждения данных при сбоях. При создании резервных копий:

1. Используйте `rsync` с опцией `--timeout` для долгих операций.
2. Для снапшотов LVM/ZFS на сервере предпочитайте `sync` запись.
3. После восстановления данных проверяйте `nfsstat -m` на клиентах — наличие `wsize`/`rsize` ниже ожидаемого может указывать на разрыв сессии.

### Высокая доступность NFS-сервера

Для критичных сред разворачивайте NFS в активном-пассивном режиме:

- **Синхронизация данных:** Общая дисковая подсистема (DRBD, Ceph, SAN) между узлами.
- **Виртуальный IP:** Keepalived или Pacemaker для переключения IP при падении активного узла.
- **STONITH:** Обязательно для предотвращения split-brain при использовании кластерных файловых систем.

### Сравнение технологий общего доступа

| Характеристика | **NFS** | **SMB/CIFS** | **iSCSI** |
| :--- | :--- | :--- | :--- |
| **Тип доступа** | Файловый (NAS) | Файловый (NAS) | Блочный (SAN) |
| **Кроссплатформенность** | Unix/Linux | Windows, macOS, Linux | Универсальный (с драйверами) |

| **Рекомендация** | Linux/Unix-инфраструктура, контейнеры | Гетерогенные среды, Windows | БД, кластеры |
