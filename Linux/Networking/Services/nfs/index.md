# NFS — сетевая файловая система

| Метаданные | Значение |
| :--- | :--- |
| **Оценка надёжности** | 10 (Централизованный материал + RFC) |
| **Актуальность** | Июль 2024 (NFSv4.2+) |

---

## Определения

**NFS (Network File System)** — протокол распределённой файловой системы, позволяющий монтировать удалённые директории и работать с ними как с локальными. Протокол обеспечивает прозрачный доступ к файлам по сети, инкапсулируя сетевые вызовы в стандартные операции VFS (Virtual File System).

**RPC (Remote Procedure Call)** — механизм, используемый NFS для выполнения команд на удалённом сервере. В современных версиях (NFSv4) используется преимущественно порт **2049/TCP**.

---

## Основные концепции

### Архитектура и версии

NFS реализует клиент-серверную модель, где сервер экспортирует файловые ресурсы, а клиент монтирует их.

| Версия | Состояние | Особенности |
| :--- | :--- | :--- |
| **NFSv3** | Устарела | Stateless (без сохранения состояния), требует `rpcbind` (порт 111), UDP/TCP. |
| **NFSv4.0** | Поддерживается | Stateful (сохранение состояния), один порт (2049/TCP), встроенная безопасность. |
| **NFSv4.1** | Рекомендуется | Поддержка **pNFS (Parallel NFS)** для распределения нагрузки на хранилища. |
| **NFSv4.2** | Актуальная | Поддержка **Server-Side Copy**, разреженных файлов (**Sparse Files**) и меток безопасности. |

### Безопасность и идентификация

1.  **Механизмы аутентификации (`sec=`):**
    - `sys` (по умолчанию): Доверие на основе UID/GID, передаваемых в пакете. Небезопасно (легко подделать).
    - `krb5`: Аутентификация через Kerberos.
    - `krb5i`: Kerberos + проверка целостности данных.
    - `krb5p`: Kerberos + полное шифрование трафика.

2.  **Маппинг пользователей (NFSv4):**
    В отличие от NFSv3, использующей числовые UID/GID, NFSv4 оперирует строковыми именами (`user@domain`).
    - **`rpc.idmapd`** — демон, отвечающий за преобразование имен пользователей между клиентом и сервером.
    - **`root_squash`** — критическая опция безопасности, маппирующая `root` клиента в анонимного пользователя (`nobody`) на сервере.

3.  **Интеграция с каталогами:**
    Для согласованности UID/GID в больших сетях рекомендуется использовать:
    - **[LDAP и SSSD](../../../SystemAdministration/Users/LDAP_SSSD/index.md)** — для централизации учетных записей.
    - **[Kerberos](../../../../Security/Concepts/kerberos.md)** — для защиты транспортного уровня.

## Практические сценарии

### Быстрый старт (Ubuntu/Debian)

Сценарий базовой настройки для доверенной сети.

**Настройка сервера:**
```bash
sudo apt update && sudo apt install -y nfs-kernel-server
# Создание директории и прав
sudo mkdir -p /srv/nfs/shared
sudo chown nobody:nogroup /srv/nfs/shared
# Экспорт (RW, синхронная запись, без проверки поддеревьев)
echo "/srv/nfs/shared 10.0.0.0/24(rw,sync,no_subtree_check)" | sudo tee -a /etc/exports
sudo exportfs -ra
# → success
```

**Настройка клиента:**
```bash
sudo apt update && sudo apt install -y nfs-common
sudo mkdir -p /mnt/shared
# Монтирование по протоколу NFSv4
sudo mount -t nfs4 10.0.0.5:/srv/nfs/shared /mnt/shared
# → success
```

### Применение в инфраструктуре

- **Kubernetes:** Использование **NFS CSI Driver** (`nfs.csi.k8s.io`) для динамического выделения томов с поддержкой снимков (snapshots) и расширения.
- **Облачные провайдеры:** Управляемые сервисы (например, **Yandex Cloud File Storage**) предоставляют отказоустойчивый NFS по модели SaaS.
- **Высокие нагрузки:** Оптимизация через `rsize`, `wsize` и использование `pNFS`.
