# Samba: Устранение неполадок

> **Надежность: 10** (Подтверждено диагностической практикой и документацией Samba 4.24+)

## Определения

**testparm** — утилита проверки синтаксиса конфигурационного файла `smb.conf`. Показывает ошибки конфигурации и итоговые параметры после обработки всех директив.

**smbstatus** — утилита просмотра активных сессий, подключённых пользователей, открытых файлов и установленных блокировок в реальном времени.

## Базовые концепции

### Диагностические утилиты

| Утилита | Назначение |
| :--- | :--- |
| **`testparm -v`** | Проверка конфигурации; `-v` — показывает все параметры, включая значения по умолчанию. |
| **`smbstatus -S`** | Статистика по сетевым ресурсам и активным подключениям. |
| **`pdbedit -L -v`** | Просмотр детальной информации о пользователях в базе Samba. |
| **`smbclient -L`** | Тестирование видимости сетевых ресурсов (шар) с сервера или клиента. |
| **`net ads testjoin`** | Проверка валидности членства сервера в домене Active Directory. |
| **`wbinfo -t`** | Проверка "доверительного отношения" (trust relationship) с доменом. |

### Файлы логов и системные журналы

В современных дистрибутивах (2026) основным источником диагностики является `journald`.

| Команда | Описание |
| :--- | :--- |
| **`journalctl -u smbd -f`** | Журнал файлового сервиса в реальном времени. |
| **`journalctl -u winbind -f`** | Журнал сервиса интеграции с доменом (маппинг ID). |
| **`/var/log/samba/log.smbd`** | Традиционный лог процесса (если настроен в `smb.conf`). |
| **`/var/log/samba/log.%m`** | Индивидуальный лог клиента (где `%m` — имя хоста клиента). |

## Практические сценарии

### Быстрая диагностика при отказе доступа

1.  **Проверка синтаксиса:** `testparm -s` (убедитесь, что нет ошибок в путях и параметрах).
2.  **Проверка служб:** `systemctl status smbd winbind` (сервис должен быть `active (running)`).
3.  **Проверка порта:** `ss -tlnp | grep :445` (порт должен прослушиваться процессом `smbd`).
4.  **Проверка прав:** `ls -ld /path/to/share` (пользователь, от которого работает Samba, или группа должны иметь доступ).
5.  **Проверка пользователя:** `smbpasswd -e username` (убедитесь, что учетная запись не заблокирована).

### Типовые ошибки 2026 и их решения

| Сообщение / Симптом | Возможная причина | Решение |
| :--- | :--- | :--- |
| `NT_STATUS_ACCESS_DENIED` | Несоответствие `ntlm auth` | Клиент пытается использовать NTLMv1. Включите NTLMv2 или Kerberos. |
| `NT_STATUS_CONNECTION_RESET` | Форсированное шифрование | Клиент не поддерживает SMB3 encryption. Обновите клиент или настройте `smb encrypt = auto`. |
| Медленная запись (IO Wait) | Отсутствие AIO | Включите асинхронный ввод-вывод: `aio read size = 1`, `aio write size = 1`. |
| Ошибка Kerberos (Time skew) | Рассинхронизация времени | Настройте `chrony` для синхронизации с контроллером домена. |
| macOS: Ошибки поиска/метаданных | Отсутствие модуля `fruit` | Добавьте `vfs objects = fruit streams_xattr` в настройки шары. |

### Расширенная отладка (Debug Level)

Если стандартные логи не помогают, увеличьте уровень детализации (не рекомендуется для продакшена из-за нагрузки на диск):

```bash
# Динамическое изменение уровня логирования без перезагрузки
smbcontrol smbd debug 10

# Проверка лога (в другом терминале)
tail -f /var/log/samba/log.smbd

# Возврат к стандартному уровню
smbcontrol smbd debug 2
```

### Диагностика маппинга идентификаторов (ID Map)

Если пользователи домена видны как `nobody` или имеют неверные UID:

```bash
# Очистка кеша маппинга (в крайнем случае)
sudo net cache flush

# Проверка конкретного пользователя
wbinfo -n "username"      # SID по имени
wbinfo -S "SID"           # UID по SID
```
