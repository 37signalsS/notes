# DHCP-сервер: Развертывание и настройка (ISC DHCP)

## Определения

**[DHCP (Dynamic Host Configuration Protocol)](../../../Networking/Protocols/dhcp.md)** — протокол для автоматической конфигурации сетевых параметров устройств в IP-сетях.

**ISC DHCP** — классическая и наиболее распространенная реализация DHCP-сервера для Linux, разработанная Internet Systems Consortium. Пакет может называться `isc-dhcp-server` (Debian/Ubuntu) или `dhcp-server` (RHEL/CentOS).

## Базовые концепции

*   **Назначение:** DHCP-сервер автоматически выдает клиентам IP-адреса из пула, а также маску подсети, шлюз по умолчанию, адреса DNS-серверов и другие дополнительные опции.
*   **Статический IP:** DHCP-сервер должен иметь статический IP-адрес для обеспечения доступности.
*   **Структура конфигурации:**
    *   `/etc/dhcp/dhcpd.conf`: Основной файл конфигурации. Имеет иерархическую структуру: глобальные параметры могут быть переопределены внутри блоков `subnet`.
    *   `/etc/dhcp/dhcpd6.conf`: Конфигурация для IPv6.
    *   `/etc/default/isc-dhcp-server` (Debian) или `/etc/sysconfig/dhcpd` (RHEL): Указание интерфейсов для прослушивания.
*   **Файл аренды:** Информация о выданных IP-адресах и сроках их аренды хранится в `/var/lib/dhcp/dhcpd.leases` (Debian) или `/var/lib/dhcpd/dhcpd.leases` (RHEL).

## Практические сценарии

### 1. Установка

-   **Debian/Ubuntu:**
    ```bash
    sudo apt update
    sudo apt install isc-dhcp-server
    ```
-   **RHEL/CentOS:**
    ```bash
    sudo dnf install dhcp-server
    ```

### 2. Настройка интерфейса прослушивания

Укажите, на каких сетевых интерфейсах DHCP-сервер должен принимать запросы.

-   **Debian/Ubuntu (`/etc/default/isc-dhcp-server`):**
    ```ini
    INTERFACESv4="eth0"
    ```
-   **RHEL/CentOS (`/etc/sysconfig/dhcpd`):**
    ```ini
    DHCPDARGS="eth0"
    ```

### 3. Основная конфигурация (`/etc/dhcp/dhcpd.conf`)

Файл состоит из глобальных параметров и секций `subnet` для каждой сети. Всегда делайте резервную копию перед редактированием.

#### Пример базового файла конфигурации

```ini
# ГЛОБАЛЬНЫЕ ПАРАМЕТРЫ (ДЕЙСТВУЮТ ДЛЯ ВСЕХ ПОДСЕТЕЙ)

# Если этот сервер является основным в сети, он должен быть авторитативным.
# Это позволяет ему отправлять DHCPNAK для принудительного обновления
# некорректных адресов у клиентов.
authoritative;

# Имя домена и DNS-серверы, передаваемые клиентам.
# Можно использовать публичные DNS или адреса внутренних серверов.
option domain-name "work.example.com";
option domain-name-servers 8.8.8.8, 1.1.1.1;

# Настройки времени аренды по умолчанию (в секундах).
# default: будет использоваться, если клиент не запросил иное.
# max: ограничивает максимальный срок, который может запросить клиент.
default-lease-time 86400;   # 1 день
max-lease-time 604800;      # 7 дней

# Настройка логирования через syslog. Local7 - стандартный facility.
log-facility local7;

# --- СЕКЦИИ ДЛЯ КАЖДОЙ ПОДСЕТИ ---

# Пример 1: Сеть для серверов (VLAN 10)
subnet 10.0.10.0 netmask 255.255.255.0 {
    # Диапазон выдаваемых IP-адресов
    range 10.0.10.100 10.0.10.200;

    # Шлюз для этой подсети
    option routers 10.0.10.1;

    # Переопределение времени аренды для этой конкретной сети
    # Серверы меняются редко, поэтому аренда может быть долгой.
    default-lease-time 2592000; # 30 дней
    max-lease-time 5184000;   # 60 дней
}

# Пример 2: Сеть для пользователей (VLAN 20)
subnet 10.0.20.0 netmask 255.255.255.0 {
    range 10.0.20.50 10.0.20.250;
    option routers 10.0.20.1;
    # Для пользовательской сети можно оставить аренду по умолчанию или сделать короче
}
```

### 4. Резервирование IP и передача маршрутов

#### Резервирование IP-адреса (Static Allocation)
Чтобы устройство (например, сервер или принтер) всегда получало один и тот же IP-адрес, используется резервирование по MAC-адресу.

```ini
# Резервирование IP-адреса для конкретного устройства
host fileserver {
    hardware ethernet 08:00:27:1A:2B:3C; # MAC-адрес устройства
    fixed-address 10.0.10.5;             # IP, который всегда будет выдаваться
}
```

#### Передача статических маршрутов
DHCP может передавать клиентам статические маршруты. Это полезно, если из одной подсети нужно обеспечить доступ в другую через специфический шлюз.

```ini
# Пример: DMZ с выдачей статичного маршрута (VLAN 30)
# Позволяет сообщить хостам, как добраться до внутренней сети 172.16.0.0/16
# через внутренний роутер 10.0.30.254
subnet 10.0.30.0 netmask 255.255.255.0 {
    range 10.0.30.10 10.0.30.20;
    option routers 10.0.30.1;
    
    # Опция для передачи статических маршрутов (classless static routes)
    # Формат: <маска-сети>.<IP-сети> <IP-шлюза>
    # 16.172.16 соответствует сети 172.16.0.0/16
    option rfc3442-classless-static-routes 16, 172, 16, 10, 0, 30, 254;
}
```

### 5. Расширенные сценарии

#### 5.1. Настройка отказоустойчивости (Failover)

Для обеспечения высокой доступности (High Availability) службы DHCP настраивают два сервера в режиме failover. Они синхронизируют между собой информацию о выданных адресах и могут подменять друг друга в случае сбоя.

**Принцип работы:**
1.  **Два сервера:** Один настраивается как `primary`, другой как `secondary`.
2.  **Синхронизация:** Серверы обмениваются информацией о выданных арендах по TCP-порту 647.
3.  **Разделение нагрузки:** Пул адресов делится между серверами (`split`), что позволяет распределять нагрузку.

**Шаг 1: Организация конфигурационных файлов**
Конфигурация для failover-пары почти идентична, за исключением нескольких параметров. Рекомендуется вынести общие части в отдельные файлы и подключать их через `include`.

Структура может быть такой:
- `/etc/dhcp/dhcpd.conf`: Содержит уникальные для каждого сервера failover-параметры.
- `/etc/dhcp/dhcpd.conf.d/subnets.conf`: Общие определения `subnet`.
- `/etc/dhcp/dhcpd.conf.d/reservations.conf`: Общие определения `host` (резервации).

**Шаг 2: Настройка `dhcpd.conf`**

**Конфигурация для `primary` сервера (например, 10.0.4.4):**
```ini
# /etc/dhcp/dhcpd.conf на PRIMARY сервере

# Определение failover-пары
failover peer "dhcp-failover" {
    primary; # Этот сервер - основной
    address 10.0.4.4; # Его собственный IP для обмена
    port 647;
    peer address 10.0.4.5; # IP второго сервера
    peer port 647;
    
    max-response-delay 60; # Ждать 60 сек, прежде чем считать партнера "упавшим"
    max-unacked-updates 10; # Кол-во обновлений без подтверждения
    
    # Обязательные параметры для primary
    mclt 3600; # Max Client Lead Time. Время, на которое один сервер может продлить аренду без ведома другого
    split 128; # Распределение адресов 50/50 (256 - все на primary, 0 - все на secondary)
    load balance max seconds 3;
}

# Подключение общих файлов конфигурации
include "/etc/dhcp/dhcpd.conf.d/subnets.conf";
include "/etc/dhcp/dhcpd.conf.d/reservations.conf";
```

**Конфигурация для `secondary` сервера (например, 10.0.4.5):**
```ini
# /etc/dhcp/dhcpd.conf на SECONDARY сервере

failover peer "dhcp-failover" {
    secondary; # Этот сервер - вторичный
    address 10.0.4.5; # Его собственный IP
    port 647;
    peer address 10.0.4.4; # IP первого сервера
    peer port 647;
    
    max-response-delay 60;
    max-unacked-updates 10;
    load balance max seconds 3;
}

# Подключение общих файлов конфигурации
include "/etc/dhcp/dhcpd.conf.d/subnets.conf";
include "/etc/dhcp/dhcpd.conf.d/reservations.conf";
```

**Шаг 3: Модификация `subnets.conf`**
В каждой подсети, которая должна быть отказоустойчивой, необходимо указать имя failover-пары. Диапазон адресов (`range`) заключается в блок `pool`.

```ini
# /etc/dhcp/dhcpd.conf.d/subnets.conf

subnet 10.0.10.0 netmask 255.255.255.0 {
    option routers 10.0.10.1;
    
    pool {
        failover peer "dhcp-failover"; # Указываем нашу failover-пару
        range 10.0.10.100 10.0.10.200;
    }
}
```

**Шаг 4: Настройка файрвола**
На обоих DHCP-серверах необходимо разрешить входящие подключения на порт **TCP/647** для обмена failover-сообщениями.

#### 5.2. Настройка DHCP Relay

DHCP-запросы являются широковещательными и по умолчанию не выходят за пределы своей подсети (VLAN). Если DHCP-сервер находится в другой подсети, клиенты не смогут его обнаружить. Эту проблему решает **DHCP Relay Agent**.

**Принцип работы:**
1.  Маршрутизатор (или другой L3-устройство), имеющий интерфейсы в нескольких подсетях, настраивается как DHCP Relay.
2.  Получив широковещательный `DHCPDISCOVER` от клиента, Relay "заворачивает" его в unicast-пакет и пересылает на указанный IP-адрес реального DHCP-сервера.
3.  DHCP-сервер отправляет ответ обратно Relay-агенту, который, в свою очередь, пересылает его клиенту.

**Установка и настройка (RHEL/CentOS):**

1.  **Установка пакета:**
    Пакет `dhcp-relay` является частью `dhcp-server`. Если `dhcp-server` уже установлен, relay доступен. В других системах может называться `isc-dhcp-relay`.
    ```bash
    sudo dnf install dhcp-server 
    ```

2.  **Настройка службы:**
    В systemd-юните службы `dhcrelay.service` нужно указать IP-адреса DHCP-серверов.
    ```bash
    sudo systemctl edit --full dhcrelay.service
    ```
    В секции `[Service]` найдите строку `ExecStart` и добавьте в конец IP-адреса ваших DHCP-серверов.
    
    Пример:
    ```ini
    [Service]
    ...
    ExecStart=/usr/sbin/dhcrelay -d --no-pid $DHCRELAY_ARGS 10.0.4.4 10.0.4.5
    ```
    Где `10.0.4.4` и `10.0.4.5` — адреса ваших отказоустойчивых DHCP-серверов.

3.  **Запуск службы:**
    ```bash
    sudo systemctl daemon-reload
    sudo systemctl start dhcrelay
    sudo systemctl enable dhcrelay
    ```
    После этого устройство начнет пересылать DHCP-запросы из всех подсетей, в которых у него есть активные интерфейсы.

### 6. Проверка и запуск службы

1.  **Проверка синтаксиса конфигурации:**
    ```bash
    sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
    ```
    *Если команда не найдена, может потребоваться `isc-dhcp-server -t`*

2.  **Запуск/перезапуск и добавление в автозагрузку:**
    ```bash
    # Для systemd (современные дистрибутивы)
    sudo systemctl restart isc-dhcp-server  # или dhcpd
    sudo systemctl enable isc-dhcp-server   # или dhcpd
    ```

### 7. Верификация и мониторинг

#### На сервере

-   **Проверка статуса службы:**
    ```bash
    systemctl status isc-dhcp-server  # или dhcpd
    ```

-   **Просмотр логов:**
    -   В логах failover-пары ищите сообщения `balanced` или `normal`, подтверждающие успешную синхронизацию.
    -   Через `journalctl`:
        ```bash
        sudo journalctl -u isc-dhcp-server -f
        ```
    -   Логи могут также писаться в `/var/log/syslog` или `/var/log/messages`, в зависимости от настроек `rsyslog` и `log-facility` в `dhcpd.conf`. Вы увидите 4 сообщения DORA для каждого клиента.

-   **Просмотр выданных аренд:**
    ```bash
    cat /var/lib/dhcpd/dhcpd.leases
    ```
    В файле будет информация о выданном IP, MAC-адресе клиента, времени начала и окончания аренды.

#### На клиенте (Linux)

1.  **Проверка полученного IP:**
    ```bash
    ip addr show eth0
    ```
    Найдите `inet` адрес и убедитесь, что он из правильного диапазона. Пометка `dynamic` подтверждает получение по DHCP.

2.  **Проверка шлюза и статичных маршрутов:**
    ```bash
    ip route
    ```
    Вы должны увидеть `default via <IP-шлюза>` и другие маршруты, если они были переданы сервером.

3.  **Проверка DNS-серверов:**
    ```bash
    cat /etc/resolv.conf
    ```
    Файл должен содержать адреса DNS-серверов, указанные в `dhcpd.conf`.

4.  **Просмотр деталей аренды (через NetworkManager):**
    ```bash
    nmcli device show eth0 | grep IP4
    ```

## Дополнительная информация

*   **Файрвол:**
    *   На DHCP-сервере должен быть открыт порт **UDP/67** для запросов клиентов.
    *   При использовании failover, должен быть открыт порт **TCP/647** для обмена между серверами.
*   **DHCP-клиент:** В современных Linux-системах за работу DHCP-клиента обычно отвечает **NetworkManager**, который вызывает `dhclient` или использует встроенные механизмы. Настройки для клиента (например, запрос специфичных опций) производятся через профили NetworkManager (`nmcli`).
