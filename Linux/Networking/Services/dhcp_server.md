# DHCP-сервер: Развертывание и настройка

## Определения

**DHCP (Dynamic Host Configuration Protocol)** — протокол сетевого управления, который используется на IP-сетях для автоматического назначения IP-адресов и связанных параметров настройки сети устройствам, подключенным к сети. DHCP позволяет системным администраторам избежать ручной настройки каждого устройства в сети.

**`isc-dhcp-server`** — популярное программное обеспечение для реализации DHCP-сервера в Linux-системах, особенно в Debian-подобных дистрибутивах.

## Основные концепции

*   **Назначение:** DHCP-сервер автоматически выдает клиентам IP-адреса из заранее определенного пула, а также другую сетевую информацию (маску подсети, шлюз по умолчанию, DNS-серверы).
*   **Статический IP для DHCP-сервера:** Сам DHCP-сервер должен иметь статический IP-адрес, чтобы клиенты всегда могли его найти.
*   **Файлы конфигурации:** Основные настройки `isc-dhcp-server` хранятся в `/etc/dhcp/dhcpd.conf` и `/etc/default/isc-dhcp-server`.
*   **Файл аренды IP-адресов:** Вся информация об арендованных IP-адресах хранится в файле `/var/lib/dhcp/dhcpd.leases`.

## Практические сценарии

### 1. Установка `isc-dhcp-server`

```bash
sudo apt update
sudo apt install isc-dhcp-server
```

### 2. Настройка статического IP-адреса для DHCP-сервера

DHCP-сервер должен иметь статический IP-адрес. Пример настройки в `/etc/network/interfaces` (для Debian/Ubuntu):

```ini
# /etc/network/interfaces
auto enp3s0
iface enp3s0 inet static
    address 192.168.0.100
    netmask 255.255.255.0
```
После изменения сетевых настроек перезапустите сетевую службу или систему.

### 3. Конфигурация интерфейса прослушивания

Укажите сетевой интерфейс, на котором DHCP-сервер будет прослушивать запросы клиентов.

1.  Откройте файл `/etc/default/isc-dhcp-server`:
    ```bash
    sudo vim /etc/default/isc-dhcp-server
    ```
2.  Найдите и отредактируйте строку `INTERFACESv4`, указав имя вашего сетевого интерфейса (например, `enp3s0`):
    ```ini
    INTERFACESv4="enp3s0"
    ```
    Также убедитесь, что `ISC_DHCP_SERVER_IPV4="yes"` (или аналогичная опция) раскомментирована.

### 4. Основная конфигурация DHCP-сервера (`/etc/dhcp/dhcpd.conf`)

Этот файл содержит определения подсетей, диапазонов IP-адресов и другие параметры, выдаваемые клиентам.

1.  Откройте файл `/etc/dhcp/dhcpd.conf`:
    ```bash
    sudo vim /etc/dhcp/dhcpd.conf
    ```
2.  Пример конфигурации для подсети `192.168.0.0/24`:
    ```ini
    # Файлы конфигурации могут содержать различные глобальные опции.
    # Например, DNS-серверы и доменное имя.
    option domain-name "example.com";
    option domain-name-servers 8.8.8.8, 8.8.4.4;

    # Объявление основной подсети
    subnet 192.168.0.0 netmask 255.255.255.0 {
        # Диапазон выдаваемых IP-адресов
        range 192.168.0.10 192.168.0.20;
        # IP-адрес шлюза по умолчанию
        option routers 192.168.0.1;
        # Указание, что этот DHCP-сервер является основным для данной подсети
        authoritative;
        # Время аренды IP-адреса (опционально, можно оставить по умолчанию)
        # default-lease-time 600;
        # max-lease-time 7200;
    }
    ```
3.  **Проверка синтаксиса:** После сохранения файла рекомендуется проверить его на ошибки.
    ```bash
    sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
    ```

### 5. Запуск и проверка статуса DHCP-сервера

1.  **Перезапустите службу DHCP-сервера:**
    ```bash
    sudo systemctl restart isc-dhcp-server
    ```
2.  **Проверьте статус службы:**
    ```bash
    systemctl status isc-dhcp-server
    ```
    Убедитесь, что служба активна (`active (running)`).

### 6. Проверка на клиентах

1.  На DHCP-клиенте убедитесь, что сетевой интерфейс настроен на получение IP по DHCP (например, `iface eth0 inet dhcp` в `/etc/network/interfaces` или через NetworkManager/Netplan).
2.  Перезапустите сетевую службу на клиенте или выполните `sudo dhclient -r` и `sudo dhclient` для обновления аренды.
3.  Проверьте полученный IP-адрес:
    ```bash
    ip a
    ```
    Клиент должен получить IP-адрес из настроенного диапазона.
4.  На сервере проверьте файл арендованных IP-адресов:
    ```bash
    cat /var/lib/dhcp/dhcpd.leases
    ```

## Дополнительная информация

*   **`dhcpd.pid`:** В некоторых случаях, особенно после некорректного завершения работы, файл `dhcpd.pid` в `/var/run/` может мешать запуску службы. Если служба не стартует, проверьте и удалите этот файл вручную (`sudo rm /var/run/dhcpd.pid`).
*   **Проблема с hostname:** Иногда DHCP-клиенты могут отправлять hostname с символами, которые DHCP-сервер обрабатывает некорректно (например, подчеркивания). Это может приводить к неожиданному отображению hostname в файле `dhcpd.leases`. Убедитесь, что hostname клиентов корректен.
*   **Файрвол:** Убедитесь, что файрвол на DHCP-сервере разрешает входящие UDP-пакеты на порт `67` (DHCP-сервер) и исходящие UDP-пакеты на порт `68` (DHCP-клиент).
*   **`dhcpd.leases` и `dhcpd.leases~`:** `dhcpd.leases` хранит текущие аренды, а `dhcpd.leases~` является его резервной копией. В случае проблем DHCP-сервер может обратиться к `dhcpd.leases~` для восстановления информации об аренде.
