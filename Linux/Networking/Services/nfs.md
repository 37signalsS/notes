# NFS (Network File System): Настройка и лучшие практики

## Определения

**NFS (Network File System)** — протокол распределенной файловой системы, позволяющий пользователям получать доступ к файлам и каталогам на удаленных компьютерах, управляя ими как локальными.

## Базовые концепции

### Ключевые концепции

* **Клиент-серверная модель**:
  * **NFS-сервер**: Экспортирует (предоставляет доступ) свои директории.
  * **NFS-клиент**: Монтирует экспортированные директории в свою файловую систему.
* **RPC (Remote Procedure Call)**: Механизм коммуникации NFS. Служба `rpcbind` информирует клиентов о портах служб NFS. Для NFSv4+ этот механизм менее критичен, так как протокол стремится использовать один порт (2049).
* **`root_squash`**: Важная функция безопасности, при которой запросы от `root` клиента выполняются сервером от имени пользователя `nobody:nogroup`. Это предотвращает получение `root`-прав клиента на файловой системе сервера.
* **Версии NFS**: Рекомендуется использовать **NFSv4** как более производительную и безопасную версию с улучшенной работой через файрволы. NFSv4 функционирует поверх TCP.
* **Маппинг UID/GID**: NFS использует числовые UID и GID для разделения привилегий. Для корректной работы в многохостовых средах требуется централизованная система идентификации (например, NIS, LDAP) для обеспечения согласованного маппинга UID/GID на клиентах и сервере. Подробнее см. [[Управление пользователями в Linux|../../SystemAdministration/users_management.md]].

## Практические сценарии

### Настройка NFS-сервера

Установка NFS-сервера:

```bash
# Для Debian/Ubuntu
sudo apt-get update
sudo apt-get install -y nfs-kernel-server
```

#### Создание экспортируемой директории

```bash
sudo mkdir -p /srv/nfs/shared
sudo chown nobody:nogroup /srv/nfs/shared
```

#### Конфигурация экспорта (`/etc/exports`)

Файл `/etc/exports` определяет экспортируемые директории и права доступа к ним.

**Формат:** `<директория> <клиент>(<опции>)`

**Пример:**

```ini
# Доступ для клиента 10.0.0.10
/srv/nfs/shared 10.0.0.10(rw,sync,no_subtree_check)

# Доступ для подсети 10.0.0.0/24
/srv/nfs/data 10.0.0.0/24(rw,sync,no_subtree_check)
```

**Основные опции:**

| Опция             | Описание                                                                                             |
| :---------------- | :--------------------------------------------------------------------------------------------------- |
| `ro` / `rw`       | Доступ только для чтения / чтения и записи.                                                          |
| `sync`            | Сервер подтверждает запись только после сохранения на диск. Обеспечивает надежность.                 |
| `async`           | Сервер подтверждает запись до сохранения на диск. Увеличивает скорость, но не гарантирует целостность данных при сбое. |
| `root_squash`     | Запросы от `root` клиента выполняются от имени `nobody`. Рекомендуется для безопасности.             |
| `no_root_squash`  | **(ОПАСНО)** Разрешает `root` клиенту иметь полные `root`-права на сервере в экспортируемой папке.   |
| `no_subtree_check`| Отключает проверку поддиректорий, повышая производительность. Рекомендуется.                        |

#### Настройка файрвола

Для обеспечения работы NFS необходимо разрешить доступ к соответствующим портам через файрвол. Подробности см. [[Настройка файрвола в Linux: iptables и nftables|../Settings/linux_firewall_management.md]].

```bash
# Пример для ufw
sudo ufw allow from 10.0.0.0/24 to any app NFS
```

#### Применение конфигурации

```bash
sudo exportfs -a                 # Применить изменения в /etc/exports
sudo systemctl restart nfs-kernel-server # Перезапустить службу NFS
```

### Настройка NFS-клиента

#### 1. Установка

```bash
# Для Debian/Ubuntu
sudo apt-get update
sudo apt-get install -y nfs-common

# Для CentOS/RHEL
sudo yum install -y nfs-utils
```

#### 2. Просмотр доступных ресурсов

```bash
showmount -e <IP_адрес_сервера>
```

#### 3. Монтирование

1. **Создание точки монтирования:**

    ```bash
    sudo mkdir -p /mnt/nfs/shared
    ```

2. **Временное монтирование (для проверки):**

    ```bash
    sudo mount -t nfs 10.0.0.5:/srv/nfs/shared /mnt/nfs/shared
    ```

3. **Автоматическое монтирование через `/etc/fstab`:**
    Добавьте следующую строку в `/etc/fstab`:

    ```ini
    # <сервер>:<путь>             <точка_монтирования>  <тип>  <опции>                      <dump> <pass>
    10.0.0.5:/srv/nfs/shared    /mnt/nfs/shared       nfs    hard,nofail,noatime,_netdev    0      0
    ```

    **Ключевые опции для `fstab`:**

    | Опция     | Описание                                                                                                   |
    | :-------- | :--------------------------------------------------------------------------------------------------------- |
    | `hard`    | Процесс "зависнет" при недоступности сервера до восстановления связи. Рекомендуется для предотвращения потери данных. |
    | `soft`    | Процесс получит ошибку ввода-вывода при недоступности сервера. Может привести к повреждению данных. Не рекомендуется. |
    | `nofail`  | Система не прекратит загрузку, если NFS-сервер недоступен.                                                  |
    | `noatime` | Отключает обновление времени доступа к файлам, повышая производительность.                                 |
    | `_netdev` | Указывает системе монтировать ресурс только после поднятия сети.                                           |

## Дополнительная информация

### Устранение неполадок

* **Монтирование "зависает" или `df` не отвечает:**
  * **Причина:** Недоступность NFS-сервера при использовании опции `hard` на клиенте.
  * **Решение:** Проверьте сетевое соединение и доступность сервера. Убедитесь, что служба `nfs-kernel-server` активна: `systemctl status nfs-kernel-server`.

* **Ошибка `Permission denied` при монтировании или доступе к файлам:**
  * **Причина №1 (Сервер):** Отсутствие IP-адреса клиента в `/etc/exports` или некорректные права доступа.
  * **Причина №2 (Файрвол):** Блокировка подключений файрволом на сервере. Проверьте правила `ufw` или `iptables`.

* **Ошибка `mount.nfs: Connection timed out`:**
  * **Причина:** Проблемы с сетью или файрволом, препятствующие доступу клиента к RPC-портам сервера.
  * **Решение:** Проверьте `ping` до сервера и убедитесь в правильности настройки файрвола на сервере.
