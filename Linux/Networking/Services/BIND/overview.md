# Настройка DNS-сервера BIND: Обзор

## Определения

**BIND (Berkeley Internet Name Domain)** — наиболее широко используемое программное обеспечение для реализации DNS-сервера с полной поддержкой спецификации протокола DNS.

**named (Name Daemon)** — системная служба (демон), реализующая функциональность BIND. В дистрибутивах на базе RHEL (Red Hat Enterprise Linux) служба называется `named`, в Debian/Ubuntu — `bind9`.

## Базовые концепции

### Роли BIND в инфраструктуре

| Роль | Назначение | Конфигурация |
|------|------------|--------------|
| **Авторитативный сервер** | Хранит официальные записи зоны, отвечает авторитетно | Зоны в `named.conf.local` |
| **Рекурсивный сервер** | Выполняет рекурсивные запросы от клиентов, кэширует ответы | `recursion yes;` |
| **Перенаправляющий (Forwarder)** | Перенаправляет запросы внешним DNS-серверам | `forward only;` + `forwarders {}` |
| **Master (Primary)** | Первичный источник данных зоны (файлы редактируются вручную) | `type master;` |
| **Slave (Secondary)** | Автоматически копирует зону с Master через трансфер (AXFR/IXFR) | `type slave;` + `masters {}` |

### Механизмы управления и безопасности

* **ACL (Access Control Lists):** именованные списки IP-адресов или сетей для ограничения доступа к рекурсии, трансферу зон или обновлению записей.
* **Views (Представления):** механизм разделения ответов в зависимости от источника запроса (Split-horizon DNS). Позволяет отдавать разные записи для внутренних и внешних клиентов.
* **rndc (Remote Name Daemon Control):** утилита командной строки для управления запущенным сервером `named` (перезагрузка зон, очистка кэша, просмотр статуса).

### Сценарии использования

**Корпоративная сеть:**

* Внутренний авторитативный сервер для локальных доменов (`corp.internal`).
* Рекурсивный кэширующий сервер для снижения нагрузки на канал и ускорения ответов.
* Использование Views для разделения прав доступа и видимости ресурсов.

**Публичный DNS-сервис:**

* Развёртывание Master/Slave архитектуры для обеспечения высокой доступности зон.
* DNSSEC (Domain Name System Security Extensions) — подпись зон для защиты от подмены ответов (Cache Poisoning).

## Практические сценарии

### Структура конфигурации BIND (Debian/Ubuntu)

| Файл | Назначение |
|------|------------|
| `/etc/bind/named.conf` | Главный файл конфигурации (подключает остальные) |
| `/etc/bind/named.conf.options` | Глобальные опции: рекурсия, форвардеры, ACL, порты |
| `/etc/bind/named.conf.local` | Объявление локальных зон (Master/Slave) |
| `/etc/bind/named.conf.default-zones` | Стандартные зоны (root-серверы, localhost) |
| `/etc/bind/zones/` | Рекомендуемая директория для файлов данных зон |
