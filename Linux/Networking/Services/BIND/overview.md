# Настройка DNS-сервера BIND: Обзор

## Определения

**BIND (Berkeley Internet Name Domain)** — наиболее широко используемое программное обеспечение для реализации DNS-сервера (**Domain Name System** — система доменных имён) с полной поддержкой спецификаций протокола DNS. Разрабатывается и поддерживается организацией **ISC (Internet Systems Consortium)**.

**named (Name Daemon)** — системная служба (демон), реализующая функциональность BIND. В дистрибутивах на базе **RHEL (Red Hat Enterprise Linux)** служба называется `named`, в **Debian/Ubuntu** — `bind9`.

**Актуальные версии (2025-2026):**
*   **BIND 9.18 (LTS — Long Term Support):** стабильная версия с долгосрочной поддержкой.
*   **BIND 9.20 (ESV — Extended Support Version):** версия с расширенным циклом обновлений, поддерживающая современные стандарты безопасности и производительности.

## Базовые концепции

### Роли BIND в инфраструктуре

| Роль | Назначение | Конфигурация |
|------|------------|--------------|
| **Авторитативный сервер** | Хранит официальные записи зоны, отвечает авторитетно | Зоны в `named.conf.local` |
| **Рекурсивный сервер** | Выполняет рекурсивные запросы от клиентов, кэширует ответы | `recursion yes;` |
| **Перенаправляющий (Forwarder)** | Перенаправляет запросы внешним DNS-серверам | `forward only;` + `forwarders {}` |
| **Master (Primary — первичный)** | Первичный источник данных зоны (файлы редактируются вручную) | `type master;` |
| **Slave (Secondary — вторичный)** | Автоматически копирует зону с Master через трансфер (**AXFR/IXFR**) | `type slave;` + `masters {}` |

### Механизмы управления и безопасности

*   **ACL (Access Control Lists — списки управления доступом):** именованные списки **IP (Internet Protocol)** адресов или сетей для ограничения доступа к рекурсии, трансферу зон или динамическому обновлению записей.
*   **Views (Представления):** механизм разделения ответов в зависимости от источника запроса (**Split-horizon DNS**). Позволяет отдавать разные записи (например, внутренние и публичные IP) для разных групп клиентов.
*   **rndc (Remote Name Daemon Control — удалённое управление демоном имён):** утилита командной строки для безопасного управления запущенным сервером `named` (перезагрузка зон, очистка кэша, просмотр статистики без перезапуска службы).
*   **RPZ (Response Policy Zones):** механизм фильтрации DNS-запросов ("DNS Firewall"), позволяющий блокировать доступ к вредоносным доменам или перенаправлять запросы на основе политик.

### Современные технологии и производительность

*   **QP-trie (Quaternary Prefix Trie):** современная структура данных, используемая в новых версиях BIND для ускорения поиска в кэше и снижения нагрузки на **CPU (Central Processing Unit)**.
*   **DoH/DoT (DNS over HTTPS / DNS over TLS):** поддержка шифрования DNS-трафика для обеспечения приватности и защиты от атак типа **Man-in-the-Middle**.
*   **DNSSEC (Domain Name System Security Extensions):** набор расширений для обеспечения целостности и аутентичности данных DNS с использованием цифровых подписей.

## Практические сценарии

### Структура конфигурации BIND (Debian/Ubuntu)

| Файл | Назначение |
|------|------------|
| `/etc/bind/named.conf` | Главный файл конфигурации (подключает остальные) |
| `/etc/bind/named.conf.options` | Глобальные опции: рекурсия, форвардеры, ACL, порты, параметры безопасности |
| `/etc/bind/named.conf.local` | Объявление локальных зон (Master/Slave) и Views |
| `/etc/bind/named.conf.default-zones` | Стандартные зоны (root-серверы, localhost, широковещательные адреса) |
| `/etc/bind/zones/` | Рекомендуемая директория для хранения файлов описания зон |
