# Настройка первичного DNS-сервера (Master) для локальной зоны

## Определения

**DNS (Domain Name System — система доменных имён)** — распределённая система для получения информации о доменах и сопоставления их с сетевыми адресами.

**Master-сервер (Primary — первичный)** — авторитативный DNS-сервер, на котором хранятся эталонные файлы зоны. Любые изменения в данных зоны вносятся администратором вручную именно на этом сервере.

**FQDN (Fully Qualified Domain Name — полностью определённое доменное имя)** — имя домена, указывающее его точное место в иерархии DNS, заканчивающееся точкой (например, `ns1.example.com.`). Точка в конце критически важна для BIND, так как она предотвращает автоматическое добавление суффикса зоны к имени.

## Базовые концепции

### Файлы конфигурации и структура

| Файл | Назначение |
|------|------------|
| `/etc/bind/named.conf.local` | Основной файл для объявления локальных зон. |
| `/etc/bind/zones/db.<zone>` | Файл текстовой базы данных зоны (zone file), содержащий ресурсные записи. |

### Запись SOA и серийный номер

**SOA (Start of Authority — начальная запись зоны)** содержит метаданные об управлении зоной. Ключевым параметром является **Serial** — целое число, которое **обязательно** должно увеличиваться при каждом изменении файла зоны. Это сигнал для вторичных (**Slave**) серверов о необходимости синхронизации.

**Рекомендуемый формат Serial:** `YYYYMMDDNN`, где `YYYYMMDD` — дата последнего изменения, а `NN` — номер правки за этот день (например, `2025072501`).

## Практические сценарии

### 1. Объявление зоны в `named.conf.local`

Для Master-сервера необходимо указать тип зоны и разрешить передачу данных (трансфер) на вторичные серверы.

```conf
// /etc/bind/named.conf.local

zone "corp.local" {
    type master;
    file "/etc/bind/zones/db.corp.local";
    allow-transfer { 192.168.10.20; }; // IP (Internet Protocol) адрес вторичного сервера
    notify yes;                        // Отправка уведомлений об изменениях Slave-серверам
};
```

### 2. Создание и наполнение файла зоны

**Шаг 1: Подготовка директории**

```bash
sudo mkdir -p /etc/bind/zones
sudo chown bind:bind /etc/bind/zones
```

**Шаг 2: Создание файла зоны**
Важно соблюдать синтаксис: если имя не заканчивается точкой, BIND автоматически добавит к нему имя текущей зоны.

```dns
; /etc/bind/zones/db.corp.local
$TTL    86400  ; TTL (Time To Live) — 1 день
@       IN      SOA     ns1.corp.local. admin.corp.local. (
                             2025072501     ; Serial (ГГГГММДДНН)
                             3600           ; Refresh (1 час)
                             600            ; Retry (10 минут)
                             1209600        ; Expire (2 недели)
                             3600 )         ; Negative Cache TTL (1 час)

; NS (Name Server) записи (указывают, кто обслуживает зону)
@       IN      NS      ns1.corp.local.
@       IN      NS      ns2.corp.local.

; A (Address) записи для серверов имен
ns1     IN      A       192.168.10.10
ns2     IN      A       192.168.10.20

; A-записи для инфраструктурных ресурсов
gateway IN      A       192.168.10.1
web     IN      A       192.168.10.50
db      IN      CNAME   web.corp.local.  ; Алиас (псевдоним)
```

### 3. Валидация и применение конфигурации

**Проверка синтаксиса:**
Утилиты не выводят сообщений при отсутствии ошибок.

```bash
# Проверка общей конфигурации
sudo named-checkconf

# Проверка конкретного файла зоны
sudo named-checkzone corp.local /etc/bind/zones/db.corp.local
# → zone corp.local/IN: loaded serial 2025072501
# → OK
```

**Применение изменений:**
Для подгрузки новых зон без остановки службы используйте `rndc`.

```bash
sudo rndc reload
# → server reload successful
```

### 4. Верификация разрешения имен

Проверьте, что сервер возвращает авторитативный ответ для созданной зоны.

```bash
dig @127.0.0.1 web.corp.local
```

**Анализ ключевых флагов в выводе:**
*   `status: NOERROR` — запрос успешно разрешён.
*   `flags: qr aa rd ra` — наличие флага **aa (Authoritative Answer)** подтверждает, что ответ получен от первичного сервера зоны.

## Дополнительная информация

Инструкции актуальны для **BIND (Berkeley Internet Name Domain)** версий 9.18+ **LTS (Long Term Support)** и 9.20+ **ESV (Extended Support Version)**.
