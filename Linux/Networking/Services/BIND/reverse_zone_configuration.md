# Настройка обратной зоны в BIND

## Определения

**Обратная зона (Reverse Zone)** — зона **DNS (Domain Name System — система доменных имён)**, предназначенная для преобразования **IP (Internet Protocol — межсетевой протокол)** адресов в доменные имена.

**PTR (Pointer — указатель) запись** — ресурсная запись DNS, которая сопоставляет IP-адрес с каноническим именем хоста (**FQDN**). Она является обратным аналогом записи типа **A**.

**in-addr.arpa / ip6.arpa** — специальные домены верхнего уровня, используемые для иерархического хранения обратных записей для IPv4 и IPv6 соответственно.

## Базовые концепции

### Форматы и иерархия обратных зон

В обратных зонах октеты IP-адреса записываются в обратном порядке, так как иерархия DNS растёт справа налево (от корня к хосту).

| Тип адреса | Формат зоны | Пример записи для хоста |
|------------|-------------|-------------------------|
| **IPv4 (/24)** | `C.B.A.in-addr.arpa` | `10.0.16.172.in-addr.arpa.` |
| **IPv4 (/16)** | `B.A.in-addr.arpa` | `10.3.16.172.in-addr.arpa.` |
| **IPv6** | `...ip6.arpa` | `b.a.9.8...ip6.arpa.` (ниббл-формат) |

### Особенности и применение PTR-записей

*   **Верификация почты:** многие почтовые серверы отклоняют письма, если для IP-адреса отправителя отсутствует корректная PTR-запись или она не совпадает с именем в **HELO/EHLO**.
*   **Безопасность:** используется в механизмах проверки **SPF (Sender Policy Framework)** и для антифрод-систем.
*   **Диагностика:** утилиты `traceroute` и `mtr` используют обратное разрешение для отображения имен промежуточных узлов.
*   **Делегирование:** обычно обратные зоны делегируются владельцем блока адресов (провайдером). Для подсетей меньше `/24` используется стандарт **RFC 2317** (бесклассовое делегирование).

## Практические сценарии

### 1. Объявление обратной зоны (Master)

**Конфигурация в `/etc/bind/named.conf.local`:**

```conf
zone "16.172.in-addr.arpa" {
    type master;
    file "/etc/bind/zones/db.172.16";
    allow-transfer { 172.16.0.6; }; // IP-адрес вторичного сервера
};
```

### 2. Создание файла данных обратной зоны

**Файл `/etc/bind/zones/db.172.16`:**

```dns
$TTL 86400
@   IN  SOA  ns1.example.com. admin.example.com. (
    2025072501  ; Serial (ГГГГММДДНН)
    3600        ; Refresh
    600         ; Retry
    1209600     ; Expire
    3600 )      ; Negative TTL

; NS-записи (имена серверов должны быть FQDN с точкой)
    IN  NS  ns1.example.com.
    IN  NS  ns2.example.com.

; PTR-записи (указывается только часть хоста относительно имени зоны)
5.0     IN  PTR  ns1.example.com.
6.0     IN  PTR  ns2.example.com.
10.3    IN  PTR  mail.example.com.
20.3    IN  PTR  app.example.com.
```

### 3. Бесклассовое делегирование (RFC 2317)

Если вам делегирована подсеть меньше `/24` (например, `172.16.0.64/26`), провайдер создает записи **CNAME**, указывающие на вашу зону.

**Ваша конфигурация:**
```conf
zone "64-127.0.16.172.in-addr.arpa" {
    type master;
    file "/etc/bind/zones/db.172.16.0.64_26";
};
```

### 4. Проверка и верификация

**Валидация зоны:**
```bash
sudo named-checkzone 16.172.in-addr.arpa /etc/bind/zones/db.172.16
# → OK
```

**Тестирование запросом:**
```bash
# Использование специального флага -x для обратного поиска
dig -x 172.16.0.5 +short
# → ns1.example.com.

# Прямой запрос PTR-записи
dig @localhost 10.3.16.172.in-addr.arpa PTR
```

## Дополнительная информация

*   **Версии:** инструкции актуальны для **BIND** 9.18+ (**LTS — Long Term Support**) и 9.20+ (**ESV — Extended Support Version**).
*   **IPv6:** для настройки обратных зон IPv6 используется полубайтовый (ниббл) формат, где каждый символ шестнадцатеричного адреса разделяется точкой.
*   **Спецификации:** 
    *   **RFC 1035:** базовое определение PTR.
    *   **RFC 2317:** Classless IN-ADDR.ARPA delegation.
