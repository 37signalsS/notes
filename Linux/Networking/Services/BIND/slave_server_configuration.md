# Настройка вторичного сервера

## Определения

**Вторичный сервер (Secondary / Slave)** — авторитативный DNS (Domain Name System — система доменных имён) сервер, который автоматически получает копию данных зоны с первичного сервера через механизм зонной передачи.

**Зонная передача (Zone Transfer)** — процесс синхронизации данных зоны между серверами с использованием протоколов AXFR (Authoritative Transfer — полная передача зоны) или IXFR (Incremental Zone Transfer — инкрементальная передача зоны).

## Базовые концепции

### Механизм синхронизации

Процесс обновления данных на вторичном сервере следует строгому алгоритму:

| Этап | Описание |
|------|----------|
| 1 | Вторичный сервер запрашивает запись SOA (Start of Authority — начальная запись зоны) у первичного сервера. |
| 2 | Сравнивает серийный номер (Serial) полученной записи с локальной версией. |
| 3 | Если Serial на первичном сервере больше → инициируется запрос на передачу зоны (AXFR или IXFR). |
| 4 | Полученные данные сохраняются в локальный файл зоны. |

### Преимущества архитектуры Master/Slave

- **Отказоустойчивость:** при недоступности первичного сервера вторичный продолжает обслуживать запросы клиентов.
- **Распределение нагрузки:** возможность распределения DNS-запросов между несколькими серверами.
- **Географическая доступность:** размещение вторичных серверов в разных сегментах сети или локациях сокращает задержки.

Теоретические основы зон и типов серверов подробно описаны в разделе **[Зоны DNS и SOA-запись](../../../../Networking/Protocols/DNS/dns_zones.md)**.

## Практические сценарии

### 1. Настройка вторичного сервера

**Установка программного обеспечения:**

Инструкции по развёртыванию приведены в разделе **[Установка BIND](./installation.md)**.

**Объявление зоны в `/etc/bind/named.conf.local`:**

```conf
zone "test.example.com" {
    type slave;
    file "/var/lib/bind/test.example.com.zone";  // Путь для хранения локальной копии
    masters { 172.16.0.5; };  // IP (Internet Protocol) адрес первичного сервера
};
```

**Подготовка файловой системы:**

BIND должен иметь права на запись в директорию, где хранятся файлы вторичных зон. В Debian/Ubuntu для этого используется `/var/lib/bind`.

```bash
sudo chown bind:bind /var/lib/bind
```

**Применение изменений:**

```bash
sudo named-checkconf
sudo systemctl restart bind9

# Просмотр журнала на наличие подтверждения трансфера
journalctl -u bind9 -f
```

### 2. Настройка первичного сервера для разрешения трансфера

Для успешной синхронизации первичный сервер должен разрешать передачу данных конкретному IP-адресу.

**В файле `/etc/bind/named.conf.local` на стороне Master:**

```conf
zone "test.example.com" {
    type master;
    file "/etc/bind/zones/db.test.example.com";
    allow-transfer { 172.16.0.6; };  // IP-адрес вторичного сервера
    also-notify { 172.16.0.6; };     // Уведомлять об изменениях немедленно
};
```

- `allow-transfer` — ограничение доступа к данным зоны (безопасность).
- `also-notify` — использование механизма NOTIFY (RFC — Request for Comments 1996) для ускорения синхронизации.

### 3. Проверка синхронизации

После настройки необходимо убедиться, что данные переданы корректно.

```bash
# Проверка SOA-записи (Serial должен совпадать с Master)
dig @localhost test.example.com SOA

# Проверка создания файла зоны (BIND 9.16+ может хранить их в бинарном формате)
ls -la /var/lib/bind/test.example.com.zone
```

### 4. Диагностика и устранение неполадок

**Трансфер не инициируется:**

1. **Сетевая доступность:** проверьте доступность порта TCP/53 на первичном сервере (AXFR использует TCP).
2. **Права доступа:** убедитесь, что на первичном сервере в `allow-transfer` указан верный IP.
3. **Права на запись:** проверьте, может ли демон `named` записывать файлы в `/var/lib/bind`.

**Ручная проверка AXFR:**

```bash
dig @172.16.0.5 test.example.com AXFR
```

## Дополнительная информация

**Протоколы:** BIND по умолчанию пытается использовать IXFR (RFC 1995) для экономии трафика, переключаясь на AXFR при необходимости.

**Безопасность:** для защиты трансферов в публичных сетях рекомендуется использовать TSIG-ключи (Transaction Signature).
