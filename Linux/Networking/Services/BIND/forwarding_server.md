# BIND — перенаправляющий сервер

## Определения

**Forwarding DNS-сервер (Domain Name System — система доменных имен)** — рекурсивный сервер, перенаправляющий запросы внешним DNS-серверам (форвардерам), а не выполняющий полную рекурсию самостоятельно.

**Форвардер (Forwarder)** — внешний DNS-сервер, которому перенаправляются запросы (например, `8.8.8.8`, `1.1.1.1`).

## Базовые концепции

### Режимы работы

| Режим | Описание | Конфигурация |
|-------|----------|--------------|
| **Forward only** | Все запросы перенаправляются, самостоятельная рекурсия не выполняется | `forward only;` |
| **Forward first** | Сначала попытка форвардинга, при неудаче — самостоятельная рекурсия | `forward first;` |

### Преимущества перенаправляющего сервера

- **Снижение нагрузки:** Не выполняется полная рекурсия с итерацией по серверам
- **Экономия трафика:** Один запрос к форвардеру вместо множества итераций
- **Кэширование:** Общие запросы обслуживаются из локального кэша
- **Контроль:** Централизованное управление внешними запросами

## Практические сценарии

### 1. Базовая конфигурация

**Файл `/etc/bind/named.conf.options`:**

```conf
// ACL (Access Control List — список управления доступом) для внутренних клиентов
acl "my_clients" {
    192.168.0.0/24;      // Внутренняя подсеть
    127.0.0.1;           // Локальный хост
    localnets;           // Все локальные сети хоста
};

options {
    directory "/var/cache/bind";

    // Форвардеры для внешних запросов
    forwarders {
        8.8.8.8;         // Google Public DNS
        1.1.1.1;         // Cloudflare DNS
    };
    forward only;        // Только перенаправление (без самостоятельной рекурсии)

    // Разрешение рекурсивных запросов от клиентов
    recursion yes;

    // IP-адреса (Internet Protocol) для прослушивания
    listen-on { 172.16.0.5; 127.0.0.1; };

    // Разрешение запросов только от доверенных клиентов
    allow-query { my_clients; };

    // DNSSEC-валидация
    dnssec-validation auto;

    listen-on-v6 { any; };
};
```

### 2. Параметры конфигурации

| Параметр | Описание | Значение |
|----------|----------|----------|
| `forwarders {}` | Список DNS-серверов для перенаправления | `8.8.8.8; 1.1.1.1;` |
| `forward only` | Только перенаправление (ошибка при недоступности форвардеров) | `only` / `first` |
| `recursion yes` | Разрешение рекурсивных запросов от клиентов | `yes` / `no` |
| `allow-query {}` | Разрешение запросов от указанных IP/ACL | `{ my_clients; }` |
| `listen-on {}` | IP-адреса для прослушивания | `{ 172.16.0.5; }` |

### 3. Проверка и применение

**Проверка синтаксиса:**

```bash
sudo named-checkconf
```

**Перезапуск службы:**

```bash
sudo systemctl restart bind9
systemctl status bind9
```

### 4. Верификация работы

**Тест с клиента:**

```bash
# Убедитесь, что клиент использует BIND-сервер
# (через DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла) или вручную в /etc/resolv.conf)

# Проверка разрешения имени
dig rambler.ru

# Проверка кэширования (повторный запрос должен быть быстрее)
dig rambler.ru
```

**Ожидаемый вывод:**

```
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 12345
;; flags: qr rd ra; QUERY: 1, ANSWER: 3, AUTHORITY: 0, ADDITIONAL: 1

;; ANSWER SECTION:
rambler.ru.     120  IN  A   81.19.73.18
```

**Флаги:**

- `AUTHORITY: 0` — ответ не от авторитетного сервера (кэширующий/перенаправляющий)
- `status: NOERROR` — успешное разрешение

### 5. Диагностика

**Проверка кэша и трассировка:**

```bash
# Включение отладочной трассировки
rndc trace

# Просмотр логов
tail -f /var/log/named/query.log

# Отключение трассировки
rndc notrace
```

**Проверка подключения к форвардерам:**

```bash
# Тест прямого запроса к форвардеру
dig @8.8.8.8 example.com

# Проверка доступности портов
ss -tlnp | grep :53
```

## Дополнительная информация

Актуально для BIND 9.18+ (LTS — Long Term Support, долгосрочная поддержка) и 9.20+ (ESV — Extended Support Version, версия с расширенной поддержкой). Публичные DNS-форвардеры: Google (`8.8.8.8`, `8.8.4.4`), Cloudflare (`1.1.1.1`, `1.0.0.1`), Quad9 (`9.9.9.9` — блокировка вредоносных доменов).
