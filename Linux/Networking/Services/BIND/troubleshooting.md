# Диагностика и устранение неисправностей BIND

## Определения

**named-checkconf** — специализированная утилита для проверки синтаксиса конфигурационных файлов **BIND (Berkeley Internet Name Domain)**. Она проверяет только структуру файлов, но не проверяет существование файлов зон или корректность записей в них.

**named-checkzone** — утилита для проверки синтаксиса файлов зонных данных. Она проверяет соответствие записей стандартам и наличие обязательных записей (**SOA**, **NS**).

**rndc (Remote Name Daemon Control — удалённое управление демоном имён)** — утилита командной строки для безопасного управления запущенным сервером BIND (перезагрузка конфигурации, очистка кэша, просмотр статистики) без остановки службы.

## Базовые концепции

### Уровни диагностики

Эффективный поиск неисправностей в **DNS (Domain Name System — система доменных имён)** требует последовательного анализа уровней:

| Уровень | Назначение | Инструменты |
| :--- | :--- | :--- |
| **Конфигурация** | Проверка синтаксиса файлов и зон | `named-checkconf`, `named-checkzone` |
| **Служба** | Состояние процесса и системные журналы | `systemctl status`, `journalctl` |
| **Сеть** | Доступность портов **UDP/TCP 53** | `ss`, `netstat`, `tcpdump` |
| **Разрешение** | Тестирование корректности ответов DNS | `dig`, `nslookup`, `host` |
| **Управление** | Взаимодействие с активным демоном | `rndc` |

### Коды ответов DNS (RCODE)

Код ответа (**RCODE — Response Code**) в заголовке сообщения указывает на результат выполнения запроса:

*   `NOERROR` — успешное выполнение запроса.
*   `NXDOMAIN` — запрашиваемое доменное имя не существует.
*   `SERVFAIL` — сервер не смог обработать запрос (ошибки в конфигурации зоны, недоступность вышестоящих серверов).
*   `REFUSED` — сервер отклонил запрос по политическим соображениям (ограничения в **ACL — Access Control List**).

Подробности см. в разделе: **[Формат сообщений и коды RCODE](../../../../Networking/Protocols/DNS/dns_message_format.md)**.

## Практические сценарии

### 1. Проверка конфигурации и строгость зон

Перед перезапуском службы всегда выполняйте синтаксический анализ.

```bash
# Проверка основного файла и всех включенных файлов (include)
sudo named-checkconf /etc/bind/named.conf

# Проверка зоны с повышенной строгостью (fail при любых ошибках)
sudo named-checkzone -k fail example.com /etc/bind/zones/db.example.com
```

### 2. Анализ системных журналов и службы

При сбоях запуска BIND часто выдаёт детализированные ошибки в системный лог.

```bash
# Просмотр логов в реальном времени с фильтрацией по службе
sudo journalctl -u bind9 -f

# Проверка статуса (особое внимание на строку 'Main PID' и последние ошибки)
systemctl status bind9
```

**Типичные ошибки:**
*   `permission denied`: служба не может прочитать файл зоны (проверьте права `chown bind:bind`).
*   `no TTL specified`: в файле зоны пропущена директива **$TTL (Time To Live — время жизни)**.
*   `semicolon expected`: пропущена точка с запятой в конце строки в `named.conf`.

### 3. Диагностика разрешения имён через dig

Утилита `dig` позволяет выполнять как прямые запросы, так и отслеживать весь путь итерации.

```bash
# Проверка ответа конкретного сервера (флаг +short для краткости)
dig @127.0.0.1 example.com A +short

# Итеративная трассировка запроса от корневых серверов (режим отладки пути)
dig @127.0.0.1 example.com +trace
```

**Ключевые флаги в выводе (Header):**
*   `aa` (**Authoritative Answer**) — ответ получен напрямую от владельца зоны.
*   `ra` (**Recursion Available**) — сервер подтверждает поддержку рекурсии.

### 4. Проверка трансфера зон (AXFR)

Проверка репликации между первичным (**Master**) и вторичным (**Slave**) серверами.

```bash
# Тестирование полного трансфера зоны (AXFR — Authoritative Zone Transfer)
# Трансфер всегда использует протокол TCP (Transmission Control Protocol)
dig @<IP_MASTER> example.com AXFR
```

Если трансфер запрещён, сервер вернёт `Transfer failed` или `REFUSED`. Проверьте директиву `allow-transfer` в конфигурации.

### 5. Анализ состояния через rndc

Утилита предоставляет глубокую информацию о внутренних метриках сервера.

```bash
# Текущий статус: количество запросов (QPS), состояние рекурсии и кэша
sudo rndc status

# Просмотр статистики (создает файл /var/cache/bind/named.stats)
sudo rndc stats
```

## Дополнительная информация

*   **Уязвимости и безопасность:** критическая уязвимость **CVE-2025-13878** (завершение процесса при обработке записей BRID/HHIT) требует обновления до версий 9.18.44+ или 9.20.18+.
*   **Производительность:** при высокой нагрузке на **CPU (Central Processing Unit — центральный процессор)** проверьте использование структуры **QP-trie** в конфигурации сборки.
