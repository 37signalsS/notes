# ISC DHCP: Резервирование IP и передача маршрутов

> **Надёжность: 10/10** (Соответствие стандартам RFC 2131 и RFC 3442)
> **Актуальность: 2026-07** (Статус: End of Life)

> **Важно:** ISC (Internet Systems Consortium) DHCP устарел. Для новых развёртываний используйте **[Kea DHCP](./isc_dhcp_server_overview.md#kea-dhcp-современная-альтернатива)**. Синтаксис резервирования в Kea реализован через **JSON (JavaScript Object Notation)**.

## Определения

**DHCP Reservation (Static Allocation / Статическое назначение)** — механизм привязки фиксированного **IP-адреса (Internet Protocol — межсетевой протокол)** к уникальному идентификатору клиента, обычно к его **MAC-адресу (Media Access Control — адрес управления доступом к среде)**.

**Classless Static Routes (RFC 3442)** — расширение протокола **DHCP (Dynamic Host Configuration Protocol — протокол динамической настройки узла)**, позволяющее передавать клиентам список маршрутов с произвольной маской подсети (**CIDR — Classless Inter-Domain Routing**).

**fixed-address** — директива в конфигурации `dhcpd`, указывающая конкретный IP, который должен быть выдан определенному хосту.

> **Теоретическая база:** [Типы назначения DHCP](../../../../Networking/Protocols/DHCP/dhcp_lease_time.md) — сравнение динамического, автоматического и статического распределения.

## Основные концепции

### Область видимости (Scope) объявлений host

В ISC DHCP блоки `host` могут располагаться в разных частях конфигурации, что влияет на их поведение:
1. **Глобально (вне subnet):** Хост будет сопоставляться во всех подсетях. Это удобно, если устройство может перемещаться между сегментами сети, но должно сохранять один и тот же IP (если подсети это позволяют).
2. **Внутри subnet:** Хост привязан к конкретному сегменту. Если устройство физически подключится к другому порту/VLAN, сервер может не выдать ему зарезервированный адрес, если он не принадлежит новой подсети.

### Нюансы RFC 3442 (Option 121)

Передача маршрутов через RFC 3442 имеет важную особенность: согласно стандарту, если клиент получает опцию 121, он **обязан игнорировать** стандартную опцию `routers` (шлюз по умолчанию). 

**Решение:** Для сохранения доступа в интернет необходимо передавать маршрут по умолчанию (`0.0.0.0/0`) внутри самого списка RFC 3442.

### Взаимодействие с базой аренды

Зарезервированные адреса (`fixed-address`) по умолчанию **не записываются** в файл аренды `dhcpd.leases`. Это означает, что сервер не отслеживает их "использование" так же строго, как динамические адреса. Администратор должен гарантировать, что зарезервированные адреса не входят в динамические пулы (`range`), чтобы избежать конфликтов.

## Практические сценарии

### Резервирование IP-адреса

Пример привязки адреса для сетевого принтера:

```ini
host office-printer {
    # Сопоставление по MAC-адресу
    hardware ethernet 00:11:22:33:44:55;
    # Назначаемый адрес (должен быть вне динамического range)
    fixed-address 10.0.10.20;
    # Можно задать специфичное имя хоста для клиента
    option host-name "printer-main";
}
```

### Передача статических маршрутов

Сценарий: Клиенты в подсети `10.0.30.0/24` должны обращаться к сети филиала `172.16.0.0/16` через локальный роутер `10.0.30.254`, сохраняя выход в интернет через основной шлюз `10.0.30.1`.

```ini
subnet 10.0.30.0 netmask 255.255.255.0 {
    range 10.0.30.100 10.0.30.200;
    
    # Стандартный шлюз (будет проигнорирован современными клиентами при наличии опции 121)
    option routers 10.0.30.1;

    # RFC 3442 (Option 121):
    # Формат: <маска>, <сеть>, <шлюз>
    # 1. Маршрут к филиалу: 16, 172, 16, 10, 0, 30, 254
    # 2. Маршрут по умолчанию (0.0.0.0/0): 0, 10, 0, 30, 1
    option rfc3442-classless-static-routes 
        16, 172, 16, 10, 0, 30, 254, 
        0, 10, 0, 30, 1;
}
```

## Решение проблем

### Ошибки применения на клиентах

* **Windows:** Поддерживает опцию 121 (RFC 3442) из коробки. Проверка: `route print`.
* **Linux (dhclient):** Обычно поддерживает, но требует наличия соответствующих скриптов в `/etc/dhcp/dhclient-exit-hooks.d/`.
* **Конфликты:** Если `fixed-address` находится внутри `range`, сервер может выдать этот адрес другому клиенту до того, как "законный" владелец подключится. 
  **Правило:** Всегда выносите `fixed-address` за пределы динамических диапазонов.

### Диагностика сервера

* **Просмотр пакетов:**
    ```bash
    # Проверка наличия опции 121 в DHCP Offer/Ack
    sudo tcpdump -i eth0 port 67 or port 68 -vv -n
    ```
* **Проверка синтаксиса:**
    ```bash
    sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
    ```
