# ISC DHCP — проверка, мониторинг и диагностика

> **Надёжность: 9/10** (Проверенные временем методы диагностики)
> **Актуальность: 2026-07** (Статус: End of Life)

> **Важно:** ISC (Internet Systems Consortium) DHCP устарел. Для новых развёртываний используйте **[Kea DHCP](./isc_dhcp_server_overview.md#kea-dhcp-современная-альтернатива)**. Мониторинг Kea осуществляется через **JSON (JavaScript Object Notation)** и специализированный агент управления.

## Определения

**Проверка конфигурации (dhcpd -t)** — процесс валидации синтаксиса основного файла конфигурации `dhcpd.conf` без фактического запуска демона. Предотвращает простои из-за опечаток.

**Файл аренды (dhcpd.leases)** — база данных в текстовом формате, где **DHCP-сервер (Dynamic Host Configuration Protocol — протокол динамической настройки узла)** фиксирует состояние выданных **IP-адресов (Internet Protocol — межсетевой протокол)**.

**omshell (Object Management Shell)** — интерактивная утилита для управления и инспекции внутреннего состояния работающего DHCP-сервера через протокол **OMAPI (Object Management Application Programming Interface)**.

> **Теоретическая база:** [Анализ трафика DHCP](../../../../Networking/Protocols/DHCP/dhcp_analysis_troubleshooting.md) — детальное описание процесса DORA и использования Wireshark.

## Основные концепции

### Ключевые системные артефакты

| Артефакт | Debian / Ubuntu | RHEL / Rocky / Alma |
| :--- | :--- | :--- |
| **Lease-файл** | `/var/lib/dhcp/dhcpd.leases` | `/var/lib/dhcpd/dhcpd.leases` |
| **Имя службы** | `isc-dhcp-server` | `dhcpd` |
| **Логи** | `journalctl -u isc-dhcp-server` | `journalctl -u dhcpd` |

### Интерпретация логов

Основные события, которые фиксируются в системном журнале:
- **DORA-процесс:** Последовательность `DHCPDISCOVER`, `DHCPOFFER`, `DHCPREQUEST`, `DHCPACK`. Отсутствие любого шага указывает на проблему (например, блокировка широковещания).
- **DHCPDECLINE:** Сообщение от клиента о том, что предложенный адрес уже занят в сети. Сервер пометит этот IP как `abandoned` (заброшенный).
- **DHCPINFORM:** Запрос клиентом дополнительных параметров (например, WPAD или DNS) без запроса IP-адреса.
- **Failover Status:** Сообщения `balanced`, `normal`, `communications-interrupted` (см. [настройку Failover](./isc_dhcp_server_failover.md)).

## Практические сценарии

### Глубокий анализ файла аренды

Файл `dhcpd.leases` содержит историю назначений. Пример разбора записи:

```text
lease 10.0.10.25 {
  starts 1 2026/07/20 12:00:00; # Начало аренды
  ends 2 2026/07/21 12:00:00;   # Конец аренды
  tstp 2 2026/07/21 12:00:00;   # Время синхронизации с партнером (Failover)
  cltt 1 2026/07/20 11:55:00;   # Время последнего контакта с клиентом (Client Last Transaction Time)
  binding state active;         # Текущий статус адреса
  next binding state free;      # Статус после истечения
  hardware ethernet 00:50:56:b1:22:33;
  uid "\001\000PV\261\"3";      # Client Identifier
  client-hostname "web-node-01";
}
```

### Диагностика через tcpdump

Для проверки прохождения трафика на сервере используйте фильтрацию по портам **UDP (User Datagram Protocol)** 67 и 68.

```bash
# Захват и расшифровка DHCP-пакетов в реальном времени
sudo tcpdump -i eth0 port 67 or port 68 -vv -n
```

### Использование omshell

Если в конфиге настроен порт OMAPI, можно проверять статус аренды без чтения файла с диска:

```bash
omshell
> server localhost
> port 7911
> key omapi-key "your_secret_base64"
> connect
> new lease
> set ip-address = 10.0.10.25
> open
# → выведет параметры аренды, если она существует
```

## Устранение неполадок

### Клиент не получает адрес

1. **Проверка доступности сервера:**
   ```bash
   # Проверка порта 67/udp снаружи
   nc -uvz <dhcp_server_ip> 67
   ```
2. **Проверка фильтрации пакетов:** Убедитесь, что порты 67/68 разрешены в **Firewall** (см. [DHCP Relay](./isc_dhcp_server_relay.md#настройка-firewall)).
3. **Проверка пулов (Pool Exhaustion):** В логах ищите `no free leases`. Это означает, что диапазон `range` полностью исчерпан.
4. **Проверка широковещания:** Если сервер не видит `DHCPDISCOVER`, проверьте настройки **VLAN** и наличие ретрансляторов (**Relay Agent**).

## Дополнительная информация

### Рекомендации по эксплуатации

- **Валидация перед рестартом:** Всегда запускайте `dhcpd -t -cf /etc/dhcp/dhcpd.conf`. Ошибка в одной точке (запятой или скобке) приведет к отказу всей службы.
- **Работа с leases:** Никогда не редактируйте `dhcpd.leases` при запущенном сервере. Для очистки аренды используйте `omshell` или остановите службу и удалите файл (с потерей состояния).
- **Authoritative режим:** Если сервер является единственным в сегменте, опция `authoritative;` обязательна. Она заставляет сервер принудительно сбрасывать неверные настройки клиентов через `DHCPNAK`.
