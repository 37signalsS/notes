# ISC DHCP: Обзор и архитектура

> **Важно:** Программный стек ISC DHCP официально достиг стадии **EOL (End of Life)** в 2022 году. Для новых инсталляций в 2026 году **настоятельно рекомендуется** использовать **[Kea DHCP](#kea-dhcp-современная-альтернатива)**. Данный раздел предназначен для поддержки унаследованных систем и планирования миграции.

---

## Определения

**DHCP (Dynamic Host Configuration Protocol)** — сетевой протокол прикладного уровня, обеспечивающий автоматическую настройку сетевых параметров узлов (IP-адрес, маска, шлюз, DNS) для минимизации ручного администрирования.

**ISC DHCP (Internet Systems Consortium DHCP)** — классическая реализация DHCP-сервера (`dhcpd`), ставшая стандартом де-факто для Unix-подобных систем на протяжении десятилетий.

**OMAPI (Object Management API)** — программный интерфейс, встроенный в ISC DHCP, позволяющий внешним утилитам (например, `omshell`) изменять конфигурацию и просматривать состояние аренды «на лету» без перезагрузки демона.

**Abandoned-аренда (заброшенный адрес)** — состояние аренды, при котором сервер получил `DHCPDECLINE` от клиента (клиент обнаружил конфликт IP через ARP). Адрес не выдается другим клиентам в течение `abandoned-lease-time`.

## Основные концепции

### Жизненный цикл запроса в dhcpd

Пакет DHCP проходит через следующие этапы внутри демона:

1.  **Приём кадра:** `dhcpd` слушает сырые сокеты (raw sockets) на интерфейсах, указанных в `/etc/default/isc-dhcp-server` (Debian) или `/etc/sysconfig/dhcpd` (RHEL). Без явного указания интерфейсов сервер может принимать запросы на всех активных интерфейсах, что представляет риск.
2.  **Определение подсети:** Сервер анализирует `giaddr` (Gateway IP Address) или IP-адрес интерфейса, на котором пришёл запрос, чтобы сопоставить его с секцией `subnet` в `dhcpd.conf`.
3.  **Проверка класса и пула:** Применяются фильтры `class` и ACL (`allow`/`deny`). Если клиент подходит под условие, ему предлагается адрес из соответствующего `range`.
4.  **Резервирование адреса:** Адрес помечается как зарезервированный в оперативной памяти.
5.  **Commit-before-ACK:** Перед отправкой `DHCPACK` сервер выполняет `fsync` записи об аренде в файл `dhcpd.leases`. Это критически важно для сохранности данных при внезапном отключении питания, но создаёт нагрузку на диск.
6.  **Отправка ответа:** `DHCPACK` отправляется клиенту. Если клиент находится в другой подсети, ответ направляется на адрес `giaddr` (Relay Agent).

### Архитектурные особенности

ISC DHCP является **stateful** (хранящим состояние) приложением. Он гарантирует целостность данных через строгий цикл записи в базу данных аренды.

*   **Демон `dhcpd`:** Однопоточный процесс, обрабатывающий запросы на портах UDP 67/68. Обработка запросов к одной подсети последовательна; высокая нагрузка на крупные пулы (тысячи аренд) может создавать задержки при медленных дисках.
*   **Цикл подтверждения (Commit-before-ACK):** Перед отправкой клиенту финального подтверждения (`DHCPACK`), сервер обязан сбросить (fsync) информацию об аренде в файл `dhcpd.leases`. Это предотвращает выдачу одного IP разным клиентам после внезапного сбоя сервера.
*   **Сырые сокеты (Raw Sockets):** Для взаимодействия с клиентами, у которых еще нет IP-адресов, демон работает напрямую с Ethernet-кадрами, что требует прав суперпользователя (**root**).
*   **Авторитарность:** Директива `authoritative;` (глобальная или на уровне `subnet`) указывает серверу активно исправлять неверные настройки клиентов через отправку `DHCPNAK`. Без этой директивы сервер игнорирует запросы на адреса из его пула, что полезно при переходе между DHCP-серверами.
*   **Однопоточность и масштабирование:** `dhcpd` обрабатывает запросы в один поток. При большом количестве аренд (более 5 000 активных) или высокой частоте обновлений (`DHCPREQUEST` при коротких `default-lease-time`) производительность ограничена скоростью записи на диск и однопоточностью CPU. Для масштабирования используется разделение на подсети и несколько инстансов `dhcpd`, каждый со своей конфигурацией.

### Технические требования

*   **Сетевой уровень:** Серверу необходим статический IP-адрес в подсети, которую он обслуживает (или доступ через Relay).
*   **Порты и протоколы:**
    *   **UDP 67:** Приём запросов (Discover/Request).
    *   **UDP 68:** Отправка ответов (Offer/Ack).
    *   **TCP 647:** Синхронизация в режиме **Failover**.
    *   **TCP 7911:** Порт управления **OMAPI** (по умолчанию).

### Структура системных файлов

| Файл / Директория | Описание | Дистрибутив |
| :--- | :--- | :--- |
| `/etc/dhcp/dhcpd.conf` | Основная конфигурация (иерархическая) | Все |
| `/etc/default/isc-dhcp-server` | Настройка интерфейсов и параметров запуска | Debian / Ubuntu |
| `/etc/sysconfig/dhcpd` | Параметры запуска и аргументы демона | RHEL / CentOS / Rocky |
| `/var/lib/dhcp/dhcpd.leases` | Актуальная база данных аренды | Debian / Ubuntu |
| `/var/lib/dhcpd/dhcpd.leases` | Актуальная база данных аренды | RHEL / Rocky |

### Правила обслуживания подсетей

`dhcpd` обслуживает **только** подсети, явно объявленные в конфигурации. Запросы от клиентов из необъявленных подсетей игнорируются. Это поведение (implicit deny) обеспечивает безопасность и предотвращает случайную выдачу адресов в сегментах, где DHCP не планировался.

Синтаксис `subnet` обязан сопровождаться маской сети и минимум одним `range` или `pool`. Блок `subnet` без `range` не выдаёт адреса, но может использоваться для передачи опций (например, `option routers`) через `host` declarations или Relay Agent.

### Работа с OMAPI: безопасность и эксплуатация

Порт OMAPI (TCP 7911) предоставляет доступ к оперативному состоянию `dhcpd`. В контексте SRE/SysAdmin:

*   **Ключ доступа:** OMAPI-ключ задаётся в `dhcpd.conf` в явном виде. Для брутфорса ключа требуется перебор пространства ~88 бит (base64). Рекомендуется использовать ключи длиной не менее 20 символов.
*   **Сетевая изоляция:** OMAPI должен быть доступен только с jump-хостов илиbastion-серверов. Блокируйте порт 7911 на фаерволе для рабочих станций.
*   **Типовые операции через omshell:**
    *   Просмотр состояния аренды (`binding-state`, `next binding state`).
    *   Ручное принудительное освобождение адреса (`set ip-address`, `open`, удаление записи).
    *   Перевод узла в `partner-down` при отказе партнёра по Failover.

### Резервное копирование и восстановление базы аренд

Файл `dhcpd.leases` является критически важным артефактом состояния. Без него все клиенты получат новые адреса после перезапуска (стирание истории), что может нарушить работу сетевого оборудования, привязанного по DNS-имени или статическим маршрутам.

```bash
# Создание бэкапа (во время работы сервера)
sudo cp /var/lib/dhcp/dhcpd.leases /backup/dhcpd.leases.$(date +%Y%m%d_%H%M%S)

# Проверка целостности: последняя запись должна заканчиваться на '}'
tail -5 /var/lib/dhcp/dhcpd.leases
```

При восстановлении сервер должен быть остановлен, чтобы избежать повреждения файла конкурентной записью.

### Управление службой: Debian/Ubuntu vs RHEL/Rocky

| Действие | Debian / Ubuntu | RHEL / Rocky / Alma |
| :--- | :--- | :--- |
| Имя службы | `isc-dhcp-server` | `dhcpd` |
| Запуск | `systemctl start isc-dhcp-server` | `systemctl start dhcpd` |
| Перезапуск | `systemctl restart isc-dhcp-server` | `systemctl restart dhcpd` |
| Статус | `systemctl status isc-dhcp-server` | `systemctl status dhcpd` |
| Включение в автозагрузку | `systemctl enable isc-dhcp-server` | `systemctl enable dhcpd` |

### Изменение конфигурации без простоя

ISC DHCP не поддерживает динамическую перезагрузку конфигурации (в отличие от Kea REST API). Любое изменение в `dhcpd.conf` требует полного перезапуска службы:

```bash
# 1. Проверка синтаксиса (обязательно!)
sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
# → Internet Systems Consortium DHCP Server ...
# → Configuration file syntax check failed.  # → остановка, исправить ошибки
# → success                                  # → можно перезапускать

# 2. Перезапуск
sudo systemctl restart isc-dhcp-server
```

Для минимизации простоя в парах Failover используется поочерёдный перезапуск (один узел остаётся обслуживать клиентов, пока второй обновляется).

## Справочник ключевых параметров dhcpd.conf

| Параметр | Уровень | Назначение |
| :--- | :--- | :--- |
| `authoritative;` | Global / Subnet | Сервер отправляет `DHCPNAK` для неверных запросов клиентов. |
| `ddns-update-style none;` | Global | Отключение динамического обновления DNS (рекомендуется для простых конфигураций). |
| `default-lease-time <сек>` | Global | Время аренды по умолчанию (например, `86400` = 24 часа). |
| `max-lease-time <сек>` | Global | Максимальное время аренды; также используется как `abandoned-lease-time`. |
| `log-facility local7;` | Global | Направление логов в syslog facility local7 (для выделения в отдельный файл). |
| `option domain-name "<домен>"` | Global / Subnet | DNS-суффикс для коротких имён. |
| `option domain-name-servers <IP>` | Global / Subnet | Список DNS-резолверов. |
| `option routers <IP>` | Subnet | Шлюз по умолчанию. |
| `option broadcast-address <IP>` | Subnet | Широковещательный адрес подсети. |
| `range <start> <end>` | Subnet / Pool | Диапазон выдаваемых динамических адресов. |
| `allow/deny members of "<класс>"` | Pool | Ограничение доступа к пулу для определённого класса клиентов. |
| `failover peer "<имя>"` | Global | Определение параметров failover-пары. |

## Дополнительная информация

### Kea DHCP — современная альтернатива

Kea DHCP была спроектирована с нуля для замены классического ISC DHCP. Для новых инсталляций в 2026 году Kea является рекомендованным выбором.

**Ключевые отличия от ISC DHCP:**
1.  **Модульность:** Весь функционал вынесен в подключаемые Hook-библиотеки (MySQL, RADIUS, HA, Flex ID).
2.  **Бэкенды БД:** Поддержка **MySQL**, **PostgreSQL** и **Cassandra** — горизонтальное масштабирование до миллионов записей.
3.  **REST API:** Управление арендами, перезагрузка конфигурации, статистика через JSON/HTTP вместо OMAPI.
4.  **Многопоточность:** Параллельная обработка пакетов без блокировок при fsync.
5.  **Глобальный HA:** Active-Standby через общий MySQL backend (вместо ISC Failover).

**Оценка готовности к миграции:**
Для принятия решения о миграции на Kea DHCP оцените:
*   Количество активных аренд (ISC DHCP эффективно масштабируется до ~5 000).
*   Наличие нестандартных Hook или сложной логики в `dhcpd.conf` (ISC expression language → Kea Hook library).
*   Требование к нулевому простоям (Kea поддерживает `config-reload` без перезапуска).
