# Утилита iproute2

## Определения

*   **`iproute2`** — это набор современных утилит командной строки для управления всеми аспектами сети в ядре Linux. Он заменяет устаревшие инструменты, такие как `ifconfig`, `route` и `arp`.
*   **Объект** — центральное понятие в `iproute2`. Основная команда `ip` принимает в качестве первого аргумента тип объекта, с которым нужно работать (например, `link`, `address`, `route`).

## Базовые концепции

`iproute2` предоставляет унифицированный интерфейс для конфигурации сети. Основной исполняемый файл — `ip`. Все настройки, сделанные с помощью `ip`, являются временными и будут сброшены после перезагрузки. Для сохранения настроек используются другие методы, описанные в [[Постоянная настройка сети в Linux|../Settings/persistent_network_configuration.md]].

Общий синтаксис команды `ip`:
`ip [опции] объект команда`
*   `опции`: Общие опции `ip` (например, `-s` для подробной статистики, `-d` для деталей).
*   `объект`: Тип сетевого объекта для управления (например, `link`, `address`, `route`).
*   `команда`: Действие, которое нужно выполнить над объектом (например, `show`, `add`, `del`, `set`).

Ключевые объекты `iproute2`:

*   `ip link` (`ip l`): Управление сетевыми устройствами (интерфейсами).
*   `ip address` (`ip a`): Управление IP-адресами.
*   `ip route` (`ip r`): Управление таблицей маршрутизации.
*   `ip neighbour` (`ip n`): Управление ARP-таблицей (для IPv4) и таблицей соседей NDP (для IPv6).
*   `ip rule`: Управление правилами маршрутизации (Policy-Based Routing).
*   `ip netns`: Управление сетевыми пространствами имен (network namespaces).

## Практические сценарии

### 1. Управление интерфейсами (`ip link`)

`ip link` позволяет управлять параметрами сетевых устройств, таких как их состояние (включено/выключено), MTU и MAC-адрес.

-   **Просмотреть все интерфейсы и их состояние:**
    ```bash
    ip link show
    # или коротко
    ip l
    ```
    В выводе можно увидеть:
    *   **`lo` (loopback)**: Виртуальный интерфейс, который замыкает устройство само на себя (`127.0.0.1`). Используется для диагностики и для сетевой коммуникации между процессами на одной машине, минуя физический сетевой адаптер.
    *   **`enpXsY` (например, `enp3s0`)**: Современные предсказуемые имена сетевых интерфейсов. `en` указывает на Ethernet, `pX` на номер шины PCI, `sY` на номер слота. Исторически часто использовались имена типа `eth0`, `eth1` и т.д.
    *   **`mtu` (Maximum Transmission Unit)**: Максимальный размер блока данных (кадра), который может быть передан за один раз через интерфейс (по умолчанию 1500 байт для Ethernet).

-   **Посмотреть статистику по интерфейсу (ошибки, дропы):**
    ```bash
    ip -s link show eth0
    ```
    *Рост счетчиков `errors` или `dropped` указывает на проблемы с сетью (кабель, оборудование) или драйвером.*
-   **Включить или выключить интерфейс:**
    ```bash
    sudo ip link set eth0 up
    sudo ip link set eth0 down
    ```
    *Виртуальные интерфейсы (например, туннели) всегда создаются в состоянии `DOWN` и требуют явного включения.*
-   **Изменить MTU (Maximum Transmission Unit):**
    ```bash
    sudo ip link set eth0 mtu 1400
    ```
-   **Изменить MAC-адрес:**
    *Изменение MAC-адреса требует, чтобы интерфейс был отключен.*
    ```bash
    sudo ip link set eth0 down
    sudo ip link set eth0 address 00:11:22:33:44:55
    sudo ip link set eth0 up
    ```

### 2. Управление IP-адресами (`ip address`)

`ip address` (или `ip a`) позволяет просматривать, добавлять и удалять IP-адреса на сетевых интерфейсах.

-   **Просмотреть все адреса:**
```bash
ip address show
# или в кратком виде (brief)
ip -br a
```
    В выводе `ip address show` может присутствовать флаг `secondary` рядом с адресом. Если на интерфейс назначено несколько IP-адресов, то один из них считается основным, остальные — вторичными. Система по умолчанию использует основной адрес для исходящих соединений, если не указано иное.
    
-   **Добавить или удалить IP-адрес:**
```bash
# Добавить основной IP-адрес
sudo ip address add 192.168.1.10/24dev eth0
# Добавить вторичный IP-адрес
sudo ip address add 192.168.1.11/24dev eth0

# Удалить IP-адрес
sudo ip address del 192.168.1.10/24dev eth0
```
    **Важный нюанс при удалении IP-адресов:**
    Если сетевой интерфейс получил IP-адрес и шлюз по умолчанию от DHCP-сервера, а затем этот IP-адрес (который является "первичным" с точки зрения получения по DHCP) будет удален, то **шлюз по умолчанию, связанный с этим DHCP-назначением, также будет удален из таблицы маршрутизации**. Это может привести к потере сетевой связности с внешними сетями, даже если на интерфейсе останутся другие (вторичные) IP-адреса, назначенные вручную.
```bash
# Пример ситуации:
# 1. eth0 получил 192.168.1.10/24 ишлюз 192.168.1.1 по DHCP.
# 2. Вручную добавлен 192.168.1.11/24на eth0.
# 3. Удаляем 192.168.1.10/24:
sudo ip address del 192.168.1.10/24dev eth0
# Результат: Из таблицы маршрутизациибудет удален маршрут по умолчаниючерез 192.168.1.1.
# Пинг до внешних ресурсов (например,8.8.8.8) перестанет работать сошибкой "Network is unreachable".
```

### 3. Управление маршрутизацией (`ip route`)

Маршрутизация — это процесс определения пути для сетевого трафика. Концепция подробно раскрыта в заметке о **[сетевом уровне модели OSI](../../../Networking/OSI_TCP_IP_Model/network_layer.md)**.

-   **Посмотреть таблицу маршрутизации:**
    ```bash
    ip route show
    # или коротко
    ip r
    ```
    *Ключевая строка в выводе — `default via 192.168.1.1 dev eth0`. Она указывает на **шлюз по умолчанию** (default gateway). Это адрес, на который система отправляет весь трафик для сетей, не указанных явно в таблице. Важно помнить, что при получении IP-адреса по DHCP, адрес шлюза по умолчанию также предоставляется DHCP-сервером.*

-   **Добавить/удалить маршрут:**
    ```bash
    # Добавить маршрут к сети 10.0.0.0/8 через шлюз 192.168.1.1
    sudo ip route add 10.0.0.0/8 via 192.168.1.1

    # Добавить шлюз по умолчанию
    sudo ip route add default via 192.168.1.1
    ```
    **Нюансы при добавлении маршрута по умолчанию:**
    Если в системе уже существует маршрут по умолчанию (например, полученный по DHCP или настроенный ранее), попытка добавить новый с помощью `ip route add default ...` приведет к ошибке `RTNETLINK answers: File exists`. В таком случае необходимо сначала удалить существующий маршрут по умолчанию.
    ```bash
    # Удалить существующий маршрут по умолчанию
    sudo ip route del default

    # Затем добавить новый
    sudo ip route add default via 192.168.1.2 dev eth0
    ```
-   **Проверить маршрут до конкретного IP (мощный инструмент отладки):**
    ```bash
    ip route get 8.8.8.8
    # Вывод: 8.8.8.8 via 192.168.1.1 dev eth0 src 192.168.1.10 uid 1000
    ```  
    *показывает, что для достижения цели будет использован шлюз `192.168.1.1` на интерфейсе `eth0` с исходящим IP `192.168.1.10`.*

### 4. Управление ARP-таблицей (`ip neighbour`)

Для доставки трафика в локальной сети система должна знать MAC-адрес устройства по его IP-адресу. Эту задачу решает протокол **[ARP (Address Resolution Protocol)](../../../Networking/Protocols/arp.md)**. Команда `ip neighbour` управляет локальным ARP-кэшем.

-   **Просмотреть ARP-таблицу (соответствие IP и MAC-адресов):**
    ```bash
    ip neighbour show
    ```
-   **Очистить ARP-кэш для интерфейса:**
    ```bash
    sudo ip neighbour flush dev eth0
    ```

## Расширенные детали

### 1. Сетевые пространства имен (`ip netns`)

`iproute2` является основным инструментом для работы с **network namespaces** — технологией изоляции сетевого стека, которая лежит в основе контейнеризации.

-   **Создать новое пространство имен:**
    ```bash
    sudo ip netns add my_namespace
    ```
-   **Выполнить команду внутри пространства имен:**
    ```bash
    # Внутри my_namespace будет виден только loopback-интерфейс
    sudo ip netns exec my_namespace ip a
    ```
-   **Управление интерфейсами между пространствами имен:**
    `iproute2` позволяет "перемещать" интерфейсы (например, один конец `veth`-пары) в другие пространства имен, обеспечивая связь контейнеров с хостом.
    ```bash
    # Переместить интерфейс veth-guest в my_namespace
    sudo ip link set veth-guest netns my_namespace
    ```

### 2. JSON-вывод для автоматизации

Большинство команд `iproute2` поддерживают флаг `-j` (`-json`) для вывода в формате JSON, что крайне удобно для парсинга в скриптах.

```bash
# Получить информацию об интерфейсах в JSON
ip -j link show
# Получить адреса в JSON
ip -j a
```

### 3. Управление туннелями

`iproute2` позволяет создавать различные типы **[сетевых туннелей](../../../Networking/Tunnels/tunneling_overview.md)**, которые инкапсулируют пакеты одного протокола в другой.

-   **Пример создания [GRE-туннеля](../../../Networking/Tunnels/gre.md):**
    ```bash
    # Создать туннель
    sudo ip tunnel add gre1 mode gre remote 203.0.113.2 local 198.51.100.1 ttl 255
    # Включить его
    sudo ip link set gre1 up
    # Назначить адрес
    sudo ip address add 10.0.0.1/30 dev gre1
    ```
    *Для создания туннелей также можно использовать более современный синтаксис `ip link add type <type> ...`.*

### 4. Traffic Control (`tc`) и эмуляция сети

`iproute2` включает утилиту `tc` (Traffic Control), которая используется для управления трафиком, формирования очередей и эмуляции сетевых условий.

-   **Подробнее об эмуляции сетевых проблем:** [tc netem: Инструмент эмуляции проблем сети](./tc_netem.md)
