# tc netem: Эмуляция сетевых проблем

## Определения

**`tc netem` (Network Emulator)** — это модуль управления трафиком (`tc`) в ядре Linux, который позволяет эмулировать различные сетевые условия и проблемы (задержки, потери пакетов, повреждения, дублирование) на сетевом интерфейсе. Он является частью утилиты `iproute2`.

**`qdisc` (Queuing Discipline)** — это механизм ядра Linux, который управляет очередями сетевых пакетов, определяя, как пакеты обрабатываются, откладываются, переупорядочиваются или отбрасываются. `netem` является одним из таких `qdisc` (дисциплин очереди).

**Rate Limiting** — ограничение пропускной способности канала (подробнее в [`tc`](./iproute2/tc.md)).

## Основные концепции

### Эмулируемые проблемы

* **Задержки (Delay)**: Введение искусственной задержки при передаче пакетов.
* **Потеря пакетов (Loss)**: Имитация потери определенного процента пакетов.
* **Повреждение пакетов (Corrupt)**: Симуляция повреждения пакетов в процессе передачи.
* **Дублирование пакетов (Duplicate)**: Создание дубликатов пакетов.
* **Изменение порядка (Reorder)**: Изменение порядка следования пакетов.
* **Ограничение пропускной способности (Bandwidth Limitation)**: Ограничение скорости передачи данных.

### Jitter (Разброс задержки) и Correlation (Корреляция)

При эмуляции задержек `tc netem` позволяет учитывать дополнительные параметры для более реалистичной симуляции:

* **Jitter (Разброс задержки)**: Величина, на которую реальная задержка пакета может отклоняться от базовой (средней) задержки. Например, при базовой задержке 200 мс и джиттере 40 мс, фактическая задержка будет колебаться от 160 мс до 240 мс.
* **Correlation (Корреляция)**: Показывает, насколько задержка текущего пакета зависит от задержки предыдущего. Высокая корреляция (`50%` или выше) имитирует более плавные изменения задержки, характерные для реальных сетей, где пакеты, следующие друг за другом, часто имеют схожие задержки. Низкая корреляция (`0%`) создает более случайные колебания.

### Distribution (Распределение задержки)

Для ещё более реалистичной эмуляции можно использовать различные распределения задержки:

* **uniform** — равномерное распределение (по умолчанию)
* **normal** — нормальное распределение (Гауссово)
* **pareto** — распределение Парето
* **paretonormal** — комбинация Парето и нормального

## Практические сценарии

### 1. Добавление задержки

Установка базовой задержки в 100 миллисекунд для интерфейса `eth0`.

```bash
sudo tc qdisc add dev eth0 root netem delay 100ms
```

**Синтаксис:** `delay <базовая_задержка> [jitter] [корреляция]`

**Пример с джиттером и корреляцией:** Задержка 200 мс с разбросом 40 мс и корреляцией 50%.

```bash
sudo tc qdisc add dev eth0 root netem delay 200ms 40ms 50%
```

**Пример с нормальным распределением:** Задержка 100 мс с джиттером 20 мс.

```bash
sudo tc qdisc add dev eth0 root netem delay 100ms 20ms distribution normal
```

### 2. Добавление потери пакетов

Имитация потери 70% пакетов для интерфейса `eth0`.

```bash
sudo tc qdisc add dev eth0 root netem loss 70%
```

**Синтаксис:** `loss <процент_потери> [корреляция]`

**Пример с корреляцией:** Потеря 10% пакетов с корреляцией 25%.

```bash
sudo tc qdisc add dev eth0 root netem loss 10% 25%
```

### 3. Повреждение пакетов

Имитация повреждения 50% пакетов для интерфейса `eth0`.

```bash
sudo tc qdisc add dev eth0 root netem corrupt 50%
```

**Синтаксис:** `corrupt <процент_повреждения> [корреляция]`

### 4. Дублирование пакетов

Имитация дублирования 40% пакетов для интерфейса `eth0`.

```bash
sudo tc qdisc add dev eth0 root netem duplicate 40%
```

**Синтаксис:** `duplicate <процент_дублирования> [корреляция]`

### 5. Изменение порядка пакетов (Reorder)

Эмуляция изменения порядка доставки пакетов.

```bash
# 30% пакетов доставляются с задержкой в 50ms
sudo tc qdisc add dev eth0 root netem delay 100ms reorder 30% 50ms
```

**Синтаксис:** `reorder <процент_пакетов> [корреляция_задержки]`

> **Важно:** `reorder` требует указания базовой задержки (`delay`).

### 6. Комбинированные эффекты

**Пример 1:** Дублирование 40% пакетов и задержка 200 мс.

```bash
sudo tc qdisc add dev eth0 root netem duplicate 40% delay 200ms
```

**Пример 2:** Комплексная эмуляция "плохой" сети (задержка + потери + джиттер).

```bash
sudo tc qdisc add dev eth0 root netem delay 150ms 30ms 25% loss 5% corrupt 2%
```

**Пример 3:** Эмуляция 3G-сети.

```bash
sudo tc qdisc add dev eth0 root netem delay 100ms 50ms loss 5% duplicate 2% reorder 10%
```

**Пример 4:** Эмуляция спутникового канала (высокая задержка, низкие потери).

```bash
sudo tc qdisc add dev eth0 root netem delay 600ms 50ms loss 0.1%
```

### 7. Просмотр текущей конфигурации

Чтобы посмотреть, какие `qdisc` настроены на интерфейсе:

```bash
tc qdisc show dev eth0
```

### 8. Удаление конфигурации

После завершения тестирования **крайне важно удалить** настроенную дисциплину очереди, чтобы вернуть нормальное поведение сети.

```bash
sudo tc qdisc del dev eth0 root netem
```

**Внимание:** Если при попытке удаления `tc qdisc del` выдает ошибку "RTNETLINK answers: No such file or directory", это означает, что `netem` не был настроен на этом интерфейсе.

### 9. Ограничение пропускной способности

> **Примечание:** Для ограничения пропускной способности используется не `netem`, а дисциплина `tbf` (Token Bucket Filter). Подробнее в [`tc`](./iproute2/tc.md).

```bash
# Ограничение исходящего трафика до 1 Мбит/с
sudo tc qdisc add dev eth0 root tbf rate 1mbit burst 32kbit latency 400ms
```

## Типовые сценарии тестирования

### Тестирование устойчивости приложения к задержкам

```bash
# Эмуляция WAN-канала с задержкой 200ms
sudo tc qdisc add dev eth0 root netem delay 200ms

# Запуск тестов приложения
# ...

# Очистка
sudo tc qdisc del dev eth0 root netem
```

### Тестирование обработки потерь пакетов

```bash
# Потеря 5% пакетов (типично для перегруженных сетей)
sudo tc qdisc add dev eth0 root netem loss 5%

# Проверка работы TCP (ретрансмиссии, congestion control)
watch -n 1 'ss -ti | grep -E "retrans|cwnd"'

# Очистка
sudo tc qdisc del dev eth0 root netem
```

### Тестирование VoIP/видеосвязи

```bash
# Эмуляция мобильного соединения с джиттером
sudo tc qdisc add dev eth0 root netem delay 80ms 40ms 25% loss 1%

# Мониторинг качества связи
# ...

# Очистка
sudo tc qdisc del dev eth0 root netem
```

### Тестирование распределённых систем (Consensus)

```bash
# Эмуляция межрегионального канала (между дата-центрами)
sudo tc qdisc add dev eth0 root netem delay 50ms 10ms

# Тестирование consensus-алгоритмов (Raft, Paxos)
# ...

# Очистка
sudo tc qdisc del dev eth0 root netem
```

## Дополнительная информация

### Предупреждения о типовых ошибках

| Ошибка | Последствия | Решение |
|--------|-------------|---------|
| Применение к неправильному интерфейсу | Блокировка SSH-сессии | Использовать `tc qdisc show` для проверки |
| Отсутствие очистки после тестов | Постоянная деградация сети | Всегда выполнять `tc qdisc del` |
| Комбинирование несовместимых параметров | Непредсказуемое поведение | Проверять совместимость параметров |
| Применение на production без тестов | Отказ сервиса | Тестировать на staging-окружении |
