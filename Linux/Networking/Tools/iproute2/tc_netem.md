# tc netem: Эмуляция сетевых проблем

## Определения

* **`tc netem` (Network Emulator)** — модуль управления трафиком (`tc`) в ядре Linux, входящий в пакет `iproute2`. Предназначен для эмуляции различных характеристик и проблем сетевых соединений (задержки, потери, повреждения, дублирование и изменение порядка пакетов).
* **`qdisc` (Queuing Discipline)** — дисциплина очереди, механизм ядра Linux, определяющий порядок обработки, буферизации и отбрасывания сетевых пакетов. `netem` является одной из таких дисциплин.

## Основные концепции

### Эмулируемые параметры

| Параметр | Описание | Применение |
|----------|----------|------------|
| **delay** | Искусственная задержка | Эмуляция WAN, спутниковых и мобильных каналов |
| **loss** | Потеря пакетов (%) | Тестирование устойчивости протоколов и приложений к потерям |
| **corrupt** | Повреждение данных | Проверка механизмов контроля целостности (checksum) |
| **duplicate** | Дублирование пакетов | Тестирование идемпотентности и механизмов дедупликации |
| **reorder** | Изменение порядка | Эмуляция многопутевой маршрутизации (multipath) |
| **rate** | Ограничение полосы | Тестирование при низкой пропускной способности |

### Джиттер (Jitter) и Корреляция (Correlation)

Для создания реалистичных сетевых условий `netem` позволяет настраивать вариативность параметров:

* **Jitter (Джиттер)** — разброс задержки относительно базового значения.
  * *Пример:* `delay 100ms 10ms` означает, что задержка будет варьироваться в диапазоне 90–110 мс.
* **Correlation (Корреляция)** — степень зависимости характеристики текущего пакета от предыдущего.
  * Высокая корреляция (например, 25% или 50%) имитирует всплески задержек или потерь, характерные для реальных перегруженных каналов.

### Распределения задержки (Distribution)

По умолчанию задержка распределяется равномерно (**uniform**). Для более точной симуляции можно указать другие типы распределений:

* **normal** — нормальное (Гауссово) распределение.
* **pareto** / **paretonormal** — распределения для моделирования сетей с длинными хвостами задержек.

```bash
# Пример: задержка 200мс ± 40мс с нормальным распределением
sudo tc qdisc add dev eth0 root netem delay 200ms 40ms distribution normal
```

## Практические сценарии

### Управление дисциплинами

| Действие | Команда | Примечание |
|----------|---------|------------|
| Добавить | `tc qdisc add` | Создает новую конфигурацию |
| Изменить | `tc qdisc change` | Обновляет существующую |
| Заменить | `tc qdisc replace` | Универсальный вариант (создает или обновляет) |
| Удалить | `tc qdisc del` | Очищает настройки интерфейса |

### Базовые примеры эмуляции

```bash
# 1. Задержка 100 мс (на интерфейсе eth0)
sudo tc qdisc add dev eth0 root netem delay 100ms

# 2. Потеря 5% пакетов
sudo tc qdisc add dev eth0 root netem loss 5%

# 3. Повреждение 2% пакетов (шум в данных)
sudo tc qdisc add dev eth0 root netem corrupt 2%

# 4. Дублирование 1% пакетов
sudo tc qdisc add dev eth0 root netem duplicate 1%
```

### Сложные сценарии

**Комбинирование эффектов:**

```bash
# Задержка 150мс ± 20мс + потеря 3% + повреждение 1%
sudo tc qdisc add dev eth0 root netem delay 150ms 20ms loss 3% corrupt 1%
```

**Эмуляция изменения порядка (reorder):**

```bash
# 25% пакетов отправляются сразу, остальные — с задержкой 10мс
sudo tc qdisc add dev eth0 root netem delay 10ms reorder 25% 50%
```

### Тестовые кейсы

* **Тестирование WAN:** установите `delay 100ms` и `loss 0.1%` для имитации межрегиональной сети.
* **Тестирование мобильных сетей (3G/LTE):** используйте `delay 100ms 50ms` и `loss 2%` для имитации нестабильного сигнала.
* **Спутниковые каналы:** установите большую задержку `delay 600ms`.
* **Тестирование идемпотентности API:** используйте `duplicate 5%` для проверки обработки повторных запросов.

## Дополнительная информация

### Типичные ошибки и ограничения

| Ошибка | Последствие | Решение |
|--------|-------------|---------|
| Задержка > 1с без учета RTO | Массовые ретрансмиссии TCP | Учитывайте механизмы RTO (Retransmission Timeout) при тестах |
| Забытая очистка | Постоянная деградация сети | Всегда выполняйте `tc qdisc del` после завершения тестов |
| Неверный интерфейс | Блокировка SSH-сессии | Будьте осторожны при применении правил к внешним интерфейсам |
| Использование netem для шейпинга | Неточное ограничение полосы | Для точного ограничения скорости используйте `tbf` или `htb` |

### Диагностика

```bash
# Просмотр текущих настроек
tc qdisc show dev eth0

# Просмотр статистики (счетчики отброшенных и задержанных пакетов)
tc -s qdisc show dev eth0

# Мониторинг ретрансмиссий TCP в реальном времени
watch -n 1 'ss -ti | grep -E "retrans|cwnd"'
```
