# ip tunnel: Управление сетевыми туннелями

## Определения

* **Сетевой туннель** — технология инкапсуляции пакетов одного протокола в пакеты другого для их передачи через промежуточную сеть.
* **`ip tunnel`** — специализированный объект утилиты `ip` для управления классическими туннелями (GRE, IPIP, SIT). В современной практике считается частично устаревшим и заменяется более универсальным объектом `ip link`.
* **L3-туннели (Routing)** — туннелирование на сетевом уровне (IP-в-IP). Пакеты маршрутизируются ядром.
* **L2-туннели (Bridging)** — передача Ethernet-кадров внутри IP-пакетов. Позволяют объединять удаленные сегменты сети в единый широковещательный домен (VXLAN, GRETAP, GENEVE).

## Основные концепции

### Эволюция управления: ip tunnel vs ip link

В современном сетевом стеке Linux существует два подхода к созданию туннельных интерфейсов:

1.  **Legacy (`ip tunnel`)**: Поддерживает только классические протоколы (IPIP, GRE, SIT) и ограничен IPv4-адресацией для конечных точек (endpoints).
2.  **Modern (`ip link add type ...`)**: Универсальный метод. Поддерживает все современные протоколы (VXLAN, GENEVE, GUE), работу через IPv6-эндпоинты и тонкую настройку аппаратных функций (Hardware Offload).

### Классификация протоколов туннелирования

| Протокол | Режим (mode) | Протокол/Порт | Назначение |
| :--- | :--- | :--- | :--- |
| **GRE** | `gre` | IP 47 | Универсальная инкапсуляция L3 (любой протокол в IP). |
| **GRETAP** | `gretap` | IP 47 | L2-туннель (Ethernet поверх GRE). |
| **ERSPAN** | `erspan` | IP 47 | Зеркалирование трафика L2 через GRE (версии v1 и v2). |
| **IPIP** | `ipip` | IP 4 | IPv4 внутри IPv4 (минимальные накладные расходы). |
| **SIT (6in4)** | `sit` | IP 41 | IPv6 внутри IPv4, стандарт для миграции на IPv6. |
| **VXLAN** | `vxlan` | UDP 4789 | L2-оверлей поверх UDP, стандарт для облаков и K8s. |
| **GENEVE** | `geneve` | UDP 6081 | Современный расширяемый туннель (стандарт OVN/Cilium). |
| **VTI** | `vti` | IP 50 (ESP) | Виртуальный интерфейс для связки с политиками IPsec. |
| **FOU / GUE** | `fou` / `gue` | UDP (любой) | Инкапсуляция в UDP для прохождения NAT и балансировки ECMP. |

### Ключевые технические параметры

*   **local** / **remote** — IP-адреса локальной и удаленной точек туннеля.
*   **ttl** — Time To Live внешнего заголовка. Рекомендуется `inherit` (наследование от внутреннего пакета) для корректной работы `traceroute`.
*   **key** / **id** — Идентификатор туннеля (32-битный для GRE, 24-битный VNI для VXLAN/GENEVE).
*   **nopmtudisc** — Отключение Path MTU Discovery (крайне не рекомендуется, ведет к фрагментации).
*   **dev** — Явная привязка туннеля к конкретному физическому интерфейсу.

## Практические сценарии

### Создание классического GRE-туннеля (Современный метод)

```bash
# 1. Создание интерфейса с ключом туннеля 100
sudo ip link add name gre1 type gre \
    local 198.51.100.1 remote 203.0.113.2 ttl inherit key 100

# 2. Активация и назначение IP
sudo ip link set gre1 up
sudo ip address add 10.0.0.1/30 dev gre1
```

### Настройка L2-мостика через GRETAP

Используется для объединения двух удаленных офисов в одну L2-сеть.

```bash
# 1. Создание L2 туннеля
sudo ip link add tap0 type gretap remote 203.0.113.2 local 198.51.100.1

# 2. Добавление туннеля в мост (Bridge)
sudo ip link set tap0 master br0
sudo ip link set tap0 up
```

### Настройка FOU (Foo Over UDP)

Инкапсуляция протоколов без портов (как GRE) в UDP для обхода "тупых" NAT и улучшения балансировки трафика провайдерами.

```bash
# 1. Настройка UDP-приемника для протокола 47 (GRE)
sudo ip fou add port 6666 ipproto 47

# 2. Создание туннеля, упакованного в UDP
sudo ip link add name gre_fou type gre \
    remote 203.0.113.2 local 198.51.100.1 \
    encap fou encap-sport auto encap-dport 6666
```

### Зеркалирование трафика через ERSPAN

```bash
# Создание ERSPAN-интерфейса для получения копии трафика с удаленного коммутатора
# erspan_ver 1 (Cisco) или 2 (Modern Linux)
sudo ip link add name erspan0 type erspan \
    local 192.168.1.1 remote 192.168.1.100 \
    erspan_ver 1 erspan 10
```

### Диагностика и мониторинг

```bash
# Детальный просмотр параметров (VNI, ключи, инкапсуляция)
ip -d link show type gre
ip -d link show type vxlan

# Просмотр статистики ошибок и дропов
ip -s link show dev gre1

# Проверка маршрутизации через туннель
ip route get 10.0.0.2
```

## Дополнительная информация

### Оптимизация MTU и MSS

Инкапсуляция неизбежно увеличивает размер пакета, что уменьшает полезную нагрузку.

| Комбинация | Накладные расходы (B) | Эффективный MTU (физика 1500) |
| :--- | :--- | :--- |
| **IPIP / SIT** | 20 | 1480 |
| **GRE (без ключа)** | 24 | 1476 |
| **GRE (с ключом)** | 28 | 1472 |
| **VXLAN** | 50 | 1450 |
| **WireGuard** | 80 | 1420 |
| **FOU + GRE** | 32 (20+8+4) | 1468 |

**Решение проблемы "зависших" соединений (MSS Clamping):**
Если на пути туннеля блокируются ICMP (PMTUD сломан), TCP-сессии будут обрываться. Необходимо принудительно ограничивать MSS:

```bash
# Подстройка MSS под MTU туннельного интерфейса gre1
sudo iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN \
     -o gre1 -j TCPMSS --clamp-mss-to-pmtu
```

### Поиск и устранение неисправностей

| Симптом | Вероятная причина | Решение |
| :--- | :--- | :--- |
| **Нет связи по туннелю** | Отсутствует маршрут к Endpoint | Проверить `ip route get <remote_ip>`. |
| **ICMP (ping) проходит, TCP виснет** | Проблема MTU/MSS | Применить MSS Clamping. |
| **dropped на интерфейсе** | Файрвол блокирует протокол | Разрешить IP 47 (GRE), 41 (SIT) или нужный UDP порт. |
| **Ошибки в статистике** | Несовпадение ключей (key) | Проверить `ip -d link` на обоих концах. |
