# tc netem: основы и концепции

## Определения

**`tc netem` (Network Emulator)** — модуль `tc` (пакет `iproute2`) для эмуляции сетевых условий: задержки, потери, повреждения, дублирование, изменение порядка пакетов.

**`qdisc` (Queuing Discipline)** — дисциплина очереди ядра Linux, управляющая обработкой, буферизацией и отбрасыванием пакетов. `netem` — одна из таких дисциплин.

---

## Эмулируемые параметры

| Параметр | Описание | Типичное применение |
|----------|----------|---------------------|
| **delay** | Искусственная задержка | Эмуляция WAN, спутниковых каналов |
| **loss** | Потеря пакетов (%) | Тестирование устойчивости к потерям |
| **corrupt** | Повреждение пакетов | Проверка целостности данных |
| **duplicate** | Дублирование пакетов | Тестирование дедупликации |
| **reorder** | Изменение порядка | Эмуляция многопутевой маршрутизации |
| **rate** | Ограничение скорости | Тестирование при низкой пропускной способности |

---

## Jitter и Correlation

* **Jitter (разброс)** — отклонение фактической задержки от базовой. Пример: `delay 200ms 40ms` → задержка 160–240 мс.
* **Correlation (корреляция)** — зависимость задержки текущего пакета от предыдущего. Высокая корреляция (50%+) имитирует плавные изменения, характерные для реальных сетей.

---

## Distribution (Распределение задержки)

Для реалистичной эмуляции используются различные распределения задержки:

| Распределение | Описание |
|---------------|----------|
| **uniform** | Равномерное распределение (по умолчанию) |
| **normal** | Нормальное распределение (Гауссово) |
| **pareto** | Распределение Парето |
| **paretonormal** | Комбинация Парето и нормального |

### Пример с нормальным распределением

```bash
# Задержка 500ms ± 400ms с нормальным распределением и 50% корреляцией
sudo tc qdisc add dev lo root netem delay 500ms 400ms 50 distribution normal
```

---

## Команды управления

| Команда | Описание |
|---------|----------|
| `tc qdisc add` | Добавить новую дисциплину |
| `tc qdisc change` | Изменить существующую (должна существовать) |
| `tc qdisc replace` | Изменить или добавить (универсальная) |
| `tc qdisc del` | Удалить дисциплину |

---

## Поведение при больших задержках

При задержке более 1 секунды TCP начинает проявлять поведение с ретрансмиссиями. Клиент может отправить SYN-пакет повторно до получения SYN-ACK от сервера. Это нормальное поведение TCP — механизм retransmission timeout (RTO).

```bash
# Задержка 1 секунда — вызовет повторные SYN-пакеты
sudo tc qdisc change dev lo root netem delay 1s
```

### Диагностика

Для диагностики используйте tcpdump:

```bash
tcpdump -i lo -nn port 12345
```

В выводе будут видны повторные SYN-пакеты от клиента и SYN-ACK от сервера.
