# ip link: Управление сетевыми интерфейсами

## Определения

* **`ip link`** — команда из пакета `iproute2`, предназначенная для управления сетевыми интерфейсами (устройствами уровней L1 и L2 модели OSI).
* Используется для настройки параметров канального уровня: состояния интерфейса (up/down), MTU, MAC-адреса, режима promiscuous и создания виртуальных устройств.

> **Важно:** `ip link` не управляет IP-адресами — для этого используется утилита [`ip address`](./ip_address.md).

## Основные концепции

### Типы интерфейсов

| Тип | Пример | Описание |
|-----|--------|----------|
| **lo** | `lo` | Loopback (127.0.0.1), для локальной связи |
| **Ethernet** | `enpXsY`, `eth0` | Физические адаптеры (Ethernet) |
| **Wireless** | `wlan0`, `wlpXsY` | Беспроводные адаптеры (Wi-Fi) |
| **Virtual** | `vethX`, `docker0` | Виртуальные пары (veth), мосты (bridge) |
| **Tunnel** | `gre1`, `ipip1`, `vxlan0` | Туннельные интерфейсы |
| **VLAN** | `eth0.100` | VLAN-интерфейсы (802.1Q) |
| **Bond** | `bond0` | Агрегация каналов (Link Aggregation) |

Подробное описание принципов работы интерфейсов приведено в заметке [Сетевые интерфейсы](../../Concepts/linux_network_interfaces.md).

### Состояния интерфейса

| Состояние | Описание |
|-----------|----------|
| **UP** | Интерфейс активен и готов к работе |
| **DOWN** | Интерфейс программно отключён |
| **UNKNOWN** | Состояние не определено (характерно для veth-пар) |
| **NO-CARRIER** | Отсутствует физический сигнал (кабель не подключен) |

### MTU (Maximum Transmission Unit)

Максимальный размер полезных данных в одном кадре (L2).

| Тип интерфейса | MTU по умолчанию |
|----------------|------------------|
| Ethernet | 1500 байт |
| Loopback | 65536 байт |
| VLAN | 1500 (может требовать уменьшения из-за заголовка 802.1Q) |
| GRE-туннель | 1476 (1500 - 24 байта заголовка) |
| VXLAN | 1450 (1500 - 50 байт заголовка) |

**Jumbo frames:** пакеты размером до 9000 байт. Для их работы требуется поддержка на всех сетевых устройствах в коммутируемом сегменте.

## Практические сценарии

### Просмотр информации об интерфейсах

```bash
# Список всех интерфейсов
ip link show

# Компактный вывод (одна строка на устройство)
ip -br link show

# Только активные (UP) интерфейсы
ip link show up

# Информация по конкретному интерфейсу
ip link show eth0

# Вывод со статистикой (пакеты, ошибки, дропы)
ip -s link show eth0

# Детальная информация (включая параметры конкретного типа устройства)
ip -d link show eth0
```

**Анализ статистики (`-s`):**

* **errors**: указывает на проблемы с оборудованием, кабелем или драйвером.
* **dropped**: свидетельствует о переполнении буферов (нехватка ресурсов CPU или настроек ядра).

### Управление состоянием интерфейса

```bash
# Включить интерфейс
sudo ip link set eth0 up

# Выключить интерфейс
sudo ip link set eth0 down

# Перезапуск интерфейса
sudo ip link set eth0 down && sudo ip link set eth0 up
```

> **Примечание:** Новые виртуальные интерфейсы (veth, bridge, tunnels) создаются в состоянии `DOWN`.

### Настройка MTU

```bash
# Установить стандартный MTU
sudo ip link set eth0 mtu 1400

# Включить поддержку Jumbo frames
sudo ip link set eth0 mtu 9000

# Настройка MTU для туннеля с учетом накладных расходов
sudo ip link set gre1 mtu 1476
```

### Изменение MAC-адреса

Для изменения MAC-адреса интерфейс должен быть предварительно выключен.

```bash
# 1. Отключить интерфейс
sudo ip link set eth0 down

# 2. Установить новый адрес
sudo ip link set eth0 address 00:11:22:33:44:55

# (Опционально) Сгенерировать случайный адрес
sudo ip link set eth0 address random

# 3. Включить интерфейс
sudo ip link set eth0 up
```

### Режим Promiscuous mode

Позволяет интерфейсу принимать все кадры, проходящие через него, даже если они не адресованы данному MAC. Необходим для анализа трафика (tcpdump) и работы сетевых мостов.

```bash
# Включить режим
sudo ip link set eth0 promisc on

# Выключить режим
sudo ip link set eth0 promisc off
```

### Создание виртуальных устройств

```bash
# Создание veth-пары (для контейнеров или namespace)
sudo ip link add veth-host type veth peer name veth-guest

# Создание VLAN-интерфейса (тегирование 802.1Q)
sudo ip link add link eth0 name eth0.100 type vlan id 100

# Создание сетевого моста (bridge)
sudo ip link add name br0 type bridge

# Создание агрегированного интерфейса (bonding)
sudo ip link add name bond0 type bond mode 802.3ad
```

### Диагностика драйвера

Хотя `ip link` предоставляет информацию об устройстве, данные о драйвере лучше получать через `ethtool` или `sysfs`.

```bash
# Использование ethtool (требуется установка)
ethtool -i eth0 | grep driver

# Проверка через sysfs
cat /sys/class/net/eth0/device/driver/module
```

## Дополнительная информация

### Типичные проблемы и решения

| Симптом | Возможная причина | Решение |
|---------|-------------------|---------|
| Статус `NO-CARRIER` | Проблема на физическом уровне | Проверить кабель, патч-панель или состояние порта на коммутаторе |
| Растут счетчики `errors` | Неисправность NIC или кабеля | Проверить физику, обновить драйвер или заменить сетевую карту |
| Растут счетчики `dropped` | Очереди интерфейса переполнены | Увеличить `netdev_max_backlog` в настройках ядра |
| Проблемы с прохождением больших пакетов | Несоответствие MTU (fragmentation) | Проверить работу PMTUD или принудительно уменьшить TCP MSS |
