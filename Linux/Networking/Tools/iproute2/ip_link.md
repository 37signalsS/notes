# ip link: Управление сетевыми интерфейсами

## Определения

* **`ip link`** — утилита из пакета `iproute2` для управления объектами канального уровня (L2) сетевого стека Linux.
* Позволяет изменять состояние интерфейсов, параметры MTU, MAC-адреса, создавать виртуальные устройства и настраивать аппаратные функции (SR-IOV, XDP).

> **Важно:** `ip link` работает на уровнях L1-L2. Для настройки IP-адресов (L3) используйте [`ip address`](./ip_address.md).

## Основные концепции

### Типы интерфейсов

| Тип | Назначение | Особенности |
|-----|------------|-------------|
| **lo** | Loopback | Локальная петля (127.0.0.1). Всегда присутствует. |
| **ether** | Физический Ethernet | Реальные сетевые карты (`eth0`, `enp3s0`). |
| **veth** | Virtual Ethernet | Работает парами. Используется для связи контейнеров и пространств имен (`netns`). |
| **bridge** | Сетевой мост | Программный коммутатор для объединения интерфейсов в одну L2-сеть. |
| **vlan** | 802.1Q VLAN | Виртуальные сети с тегированием трафика. |
| **macvlan** | MAC-based VLAN | Позволяет одному физическому интерфейсу иметь несколько MAC-адресов. |
| **ipvlan** | IP-based VLAN | Похож на macvlan, но все виртуальные интерфейсы делят один MAC-адрес. |
| **dummy** | Фиктивный интерфейс | Используется для назначения IP, которые должны быть доступны всегда (например, Anycast). |
| **vrf** | Virtual Routing & Forwarding | Изоляция таблиц маршрутизации на уровне интерфейсов. |
| **vxlan** | Virtual Extensible LAN | Туннелирование L2 поверх L3 (UDP). |

### Состояния интерфейса (Operstate)

| Статус | Описание |
|--------|----------|
| **UP** | Интерфейс программно включен и физически подключен. |
| **DOWN** | Интерфейс программно выключен. |
| **LOWERLAYERDOWN** | Программно включен, но отсутствует физический сигнал (нет кабеля). |
| **DORMANT** | Ожидание внешнего события (например, аутентификации 802.1X). |
| **UNKNOWN** | Состояние не может быть определено (нормально для многих виртуальных устройств). |

### MTU (Maximum Transmission Unit)

| Сценарий | Значение | Обоснование |
|----------|----------|-------------|
| Стандартный Ethernet | 1500 | Общепринятый стандарт. |
| Jumbo Frames | 9000 | Повышение производительности в локальных сетях (требует поддержки всеми узлами). |
| VXLAN | 1450 | 1500 минус 50 байт на заголовок VXLAN. |
| WireGuard | 1420 | 1500 минус 80 байт на инкапсуляцию. |

## Практические сценарии

### Просмотр информации

```bash
# Список всех интерфейсов (кратко)
ip -br link show
# → lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP> 
# → eth0             UP             52:54:00:12:34:56 <BROADCAST,MULTICAST,UP,LOWER_UP> 

# Детальная информация по конкретному типу (например, bridge)
ip -d link show type bridge

# Вывод в формате JSON для автоматизации
ip -j -p link show eth0
```

### Управление состоянием и именами

```bash
# Включить/выключить интерфейс
sudo ip link set eth0 up
sudo ip link set eth0 down

# Добавить альтернативное имя (altname) — доступно в современных ядрах
sudo ip link property add dev eth0 altname management0

# Изменить имя интерфейса (интерфейс должен быть DOWN)
sudo ip link set eth0 name lan0
```

### Настройка параметров L2

```bash
# Изменение MAC-адреса
sudo ip link set eth0 address 00:11:22:33:44:55

# Включение режима Promiscuous (прием всех пакетов)
sudo ip link set eth0 promisc on

# Установка MTU
sudo ip link set eth0 mtu 9000

# Отключение ARP на интерфейсе
sudo ip link set eth0 arp off
```

### Создание виртуальных устройств

```bash
# Создание veth-пары
sudo ip link add veth-host type veth peer name veth-container

# Создание VLAN (ID 10) поверх eth0
sudo ip link add link eth0 name eth0.10 type vlan id 10

# Создание Dummy-интерфейса
sudo ip link add dummy0 type dummy

# Создание VRF
sudo ip link add vrf-blue type vrf table 100
sudo ip link set vrf-blue up
```

### Привязка к Master-устройству (Enslaving)

Используется для добавления интерфейсов в Bridge, Bond или VRF.

```bash
# Добавить eth0 в мост br0
sudo ip link set eth0 master br0

# Исключить из моста
sudo ip link set eth0 nomaster

# Привязать интерфейс к VRF
sudo ip link set eth1 master vrf-blue
```

### Управление SR-IOV (Virtual Functions)

Если сетевая карта поддерживает SR-IOV, можно управлять виртуальными функциями (VF).

```bash
# Настроить MAC-адрес для 0-й виртуальной функции
sudo ip link set eth0 vf 0 mac 00:11:22:33:44:66

# Установить VLAN и QoS для VF
sudo ip link set eth0 vf 0 vlan 100 qos 1

# Ограничить скорость (Rate Limiting) для VF (100 Мбит/с)
sudo ip link set eth0 vf 0 rate 100
```

### Интеграция с XDP (eXpress Data Path)

Прикрепление eBPF программ для высокопроизводительной обработки пакетов.

```bash
# Прикрепить программу в режиме Generic (драйвер не поддерживает XDP нативно)
sudo ip link set dev eth0 xdpgeneric obj filter.o sec xdp

# Отключить XDP
sudo ip link set dev eth0 xdpgeneric off
```

## Диагностика и отладка

### Анализ статистики

```bash
ip -s link show eth0
```

**Интерпретация счетчиков:**
* **RX errors / TX errors:** Ошибки на физическом уровне, плохой кабель или проблемы с дуплексом.
* **dropped:** Пакеты отброшены ядром. Часто из-за переполнения очередей (`netdev_max_backlog`) или нехватки ресурсов CPU.
* **overrun:** Кольцевой буфер сетевой карты переполнен (ядро не успевает забирать пакеты).
* **mcast:** Количество принятых Multicast-пакетов.

### Группировка интерфейсов

Позволяет выполнять действия над множеством интерфейсов одновременно.

```bash
# Назначить группу интерфейсу
sudo ip link set eth0 group 42

# Выключить все интерфейсы группы 42
sudo ip link set group 42 down
```

## Дополнительная информация

### Типичные проблемы

| Симптом | Причина | Решение |
|---------|---------|---------|
| `RTNETLINK answers: Device or resource busy` | Попытка изменить параметр (MAC, Name) на активном (UP) интерфейсе. | Выключите интерфейс: `ip link set ... down`. |
| `NO-CARRIER` | Отсутствует линк на физике. | Проверьте кабель, патч-корд или порт коммутатора. |
| Пакеты проходят, но большие данные "виснут" | Несоответствие MTU на пути (Path MTU). | Проверьте MTU через `ping -s <size> -M do <IP>`. |
