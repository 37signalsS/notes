# ip neighbour: Управление соседями (ARP/NDP)

## Определения

* **`ip neighbour`** (синонимы: `ip neigh`, `ip n`) — объект утилиты `ip` для управления базой данных соседей (кэшем ARP для IPv4 и таблицей NDP для IPv6).
* **Сосед (Neighbour)** — сетевой узел, находящийся в том же сегменте канального уровня (L2), связь с которым осуществляется напрямую без участия маршрутизаторов.
* **ARP (Address Resolution Protocol)** — протокол разрешения сетевых адресов IPv4 в физические MAC-адреса.
* **NDP (Neighbor Discovery Protocol)** — протокол обнаружения соседей в сетях IPv6, выполняющий функции ARP, а также автоконфигурацию и поиск маршрутизаторов.

## Основные концепции

### Состояния записей (NUD — Neighbor Unreachability Detection)

Ядро Linux отслеживает состояние каждой записи в таблице соседей для обеспечения актуальности данных.

| Состояние | Описание |
|:---|:---|
| **REACHABLE** | Запись проверена и подтверждена: MAC-адрес известен, узел доступен. |
| **STALE** | Запись устарела: MAC-адрес известен, но требует подтверждения при следующей отправке. |
| **DELAY** | Пакет отправлен через STALE-запись, ядро ожидает подтверждения от L4 (TCP ACK). |
| **PROBE** | Активная проверка: отправляются ARP/NDP запросы (обычно 3 попытки). |
| **INCOMPLETE** | MAC-адрес еще не определен (отправлен первый запрос). |
| **FAILED** | Узел не ответил на запросы (ошибка разрешения). |
| **PERMANENT** | Статическая запись: добавлена вручную, не удаляется автоматически. |
| **NOARP** | Разрешение адресов на этом интерфейсе не требуется. |

### Флаги и атрибуты

* **router** (IPv6) — указывает, что сосед является маршрутизатором.
* **extern_learn** — запись была добавлена внешним протоколом управления (например, через EVPN или контроллер SDN).
* **proxy** — запись настроена для ответа на запросы от имени другого узла (Proxy ARP/NDP).

### Механизмы очистки и лимиты (Garbage Collection)

При большом количестве соседей (например, на гипервизорах или в сегментах с тысячами контейнеров) необходимо тюнинговать лимиты ARP/NDP таблиц через `sysctl`:

| Параметр | Значение по умолчанию | Описание |
|:---|:---|:---|
| `gc_thresh1` | 128 | Минимальное число записей, до которого GC не запускается. |
| `gc_thresh2` | 512 | "Мягкий" лимит. GC запускается через 5 секунд после превышения. |
| `gc_thresh3` | 1024 | "Жесткий" лимит. Новые записи не будут созданы, если таблица заполнена. |
| `base_reachable_time_ms` | 30000 | Базовое время жизни записи в состоянии REACHABLE. |

## Практические сценарии

### Просмотр таблицы соседей

```bash
# Показать все записи
ip neighbour show

# Краткий вывод (краткая форма)
ip -br neigh show

# Фильтрация по протоколу
ip -4 neigh show
ip -6 neigh show

# Просмотр записей конкретного интерфейса
ip neigh show dev eth0
```

### Управление записями

```bash
# Добавление статической записи (ARP-запрос отправляться не будет)
sudo ip neigh add 192.168.1.100 lladdr 00:11:22:33:44:55 dev eth0 nud permanent

# Изменение состояния записи (принудительная перепроверка)
sudo ip neigh change 192.168.1.100 dev eth0 nud probe

# Удаление записи
sudo ip neigh del 192.168.1.100 dev eth0
```

### Настройка Proxy ARP / Proxy NDP

Позволяет хосту отвечать своим MAC-адресом на запросы к IP-адресу, который находится за ним (в другом интерфейсе или пространстве имен).

```bash
# 1. Добавление записи для Proxy ARP
sudo ip neigh add proxy 192.168.2.10 dev eth0

# 2. Проверка proxy-записей
ip neigh show proxy dev eth0

# 3. Включение поддержки на уровне ядра (необходимо для работы proxy-записей)
sudo sysctl -w net.ipv4.conf.eth0.proxy_arp=1
sudo sysctl -w net.ipv6.conf.eth0.proxy_ndp=1
```

### Массовые операции (Очистка)

```bash
# Удалить все записи для конкретного интерфейса
sudo ip neigh flush dev eth0

# Удалить только устаревшие (STALE) записи
sudo ip neigh flush all nud stale
```

### Диагностика и мониторинг

```bash
# Проверить маршрут и состояние соседа для конкретного IP
ip neigh get 192.168.1.1 dev eth0

# Мониторинг изменений в таблице соседей в реальном времени
ip monitor neigh
```

### Типичные ошибки

| Ошибка | Возможная причина | Решение |
|:---|:---|:---|
| Состояние **INCOMPLETE** | Узел не отвечает на ARP/NDP запросы | Проверьте физическую связность, VLAN и настройки Firewall на удаленной стороне. |
| Таблица переполнена | Превышены лимиты `gc_thresh` | Увеличьте лимиты ядра через `sysctl`. |
| Неверный MAC-адрес | ARP Spoofing или конфликт IP | Используйте `arping -D` для обнаружения дубликатов IP. |
