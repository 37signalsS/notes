# tc: Управление трафиком (Traffic Control)

`iproute2` включает утилиту `tc` (Traffic Control), которая является основным инструментом для реализации QoS в Linux. Она позволяет управлять дисциплинами очередей (`qdisc`), классами и фильтрами для формирования, приоритизации и ограничения трафика.

## Основные концепции: Policing vs. Shaping

Как описано в заметке [**QoS (Quality of Service)**](../../../Networking/Concepts/qos.md), `policing` и `shaping` — это два ключевых механизма управления скоростью трафика:

* **Полисинг (Policing):** Жестко ограничивает скорость, отбрасывая (`drop`) все пакеты, которые превышают заданный лимит. Не использует буферизацию. Как правило, применяется для **входящего (`ingress`)** трафика, так как мы не можем управлять очередью на отправляющей стороне.
* **Шейпинг (Shaping):** "Сглаживает" пиковые нагрузки, помещая избыточные пакеты в буфер (очередь) для отправки позже, когда канал освободится. Это позволяет избежать потерь, но вносит задержку. Применяется для **исходящего (`egress`)** трафика.

## Практический сценарий: Ограничение входящего трафика (Policing)

Рассмотрим задачу ограничения скорости загрузки (входящего трафика) на интерфейсе `eth0` до 100 кбит/с. Для этого используется специальная `ingress` дисциплина очередей, которая перехватывает трафик на уровне ядра сразу после приема сетевым драйвером, еще до того, как он попадет в основной сетевой стек TCP/IP.

**Шаг 1: Проверка скорости до применения правил**

Сначала проверим скорость загрузки без каких-либо ограничений, чтобы иметь базовое значение для сравнения.

```bash
# Скачиваем тестовый файл, чтобы измерить скорость
wget http://speedtest.tele2.net/1MB.zip -O /dev/null
```

*Скорость будет максимальной для вашего канала.*

**Шаг 2: Просмотр существующих дисциплин**

Перед добавлением новой дисциплины полезно посмотреть, что уже настроено на интерфейсе. Это важно, так как `ingress` может существовать на интерфейсе только в одном экземпляре.

```bash
# Показать дисциплины очередей для интерфейса eth0
sudo tc qdisc show dev eth0
```

*Если для `ingress` ничего не настроено, вывод будет пустым или покажет стандартную исходящую очередь (например, `pfifo_fast`).*

**Шаг 3: Добавление `ingress` qdisc**

Дисциплина `ingress` — это специальная точка для подключения фильтров, обрабатывающих входящий трафик.

```bash
# Добавить ingress qdisc к интерфейсу eth0
# `handle ffff:` — это стандартный идентификатор (handle) для ingress
sudo tc qdisc add dev eth0 handle ffff: ingress
```

**Шаг 4: Добавление фильтра с полисингом**

Теперь к `ingress` qdisc нужно привязать фильтр, который будет применять правило ограничения скорости ко всему входящему IP-трафику.

```bash
# Добавить фильтр, который ограничивает весь IP-трафик до 100 кбит/с
sudo tc filter add dev eth0 parent ffff: protocol ip u32 match u32 0 0 police rate 100kbit burst 8k drop
```

Разберем команду:

* `filter add dev eth0 parent ffff:`: Добавляем фильтр к `ingress` qdisc на интерфейсе `eth0`.
* `protocol ip`: Фильтр будет применяться к IP-трафику.
* `u32 match u32 0 0`: Универсальный классификатор `u32`, который сопоставляет трафик с любым пакетом (`match u32 0 0` означает "сопоставить 32-битное значение 0 со смещением 0", что фактически означает "любой пакет"). Это простой и надежный способ "поймать" весь входящий трафик.
* `police rate 100kbit burst 8k drop`: Основное действие.
  * `rate 100kbit`: Устанавливает лимит скорости в 100 килобит в секунду.
  * `burst 8k`: Разрешает кратковременные "всплески" трафика сверх лимита, используя буфер (token bucket) размером 8 килобайт.
  * `drop`: Действие, которое нужно выполнить при превышении лимита — отбросить пакет.

**Шаг 5: Проверка работы и статистики**

После применения правила можно запустить загрузку и проверить статистику, чтобы увидеть, отбрасываются ли пакеты.

```bash
# Показать подробную статистику по фильтрам на ingress до начала загрузки
sudo tc -s filter show dev eth0 parent ffff:
# Обратите внимание на `dropped 0`

# Запускаем загрузку снова
wget http://speedtest.tele2.net/1MB.zip -O /dev/null
# Вы увидите, что скорость теперь ограничена примерно 100 кбит/с

# Снова проверяем статистику
sudo tc -s filter show dev eth0 parent ffff:
```

В выводе последней команды вы увидите, что счетчик отброшенных пакетов (`dropped`) стал ненулевым. Это подтверждает, что полисинг работает и избыточный трафик отбрасывается.

**Шаг 6: Удаление правила**

Чтобы удалить все правила и вернуть интерфейс в исходное состояние, достаточно удалить `ingress` qdisc.

```bash
sudo tc qdisc del dev eth0 ingress
```

## Приоритизация трафика с HTB и fq_codel

Хостовая дисциплина очередей позволяет защитить интерактивный трафик от фоновой репликации:

```bash
# Создание HTB (Hierarchical Token Bucket) с классами приоритета
tc qdisc replace dev eth0 root handle 1: htb default 20

# Корневой класс с ограничением скорости
tc class add dev eth0 parent 1: classid 1:1 htb rate 1gbit ceil 1gbit

# Класс приоритета 0 для интерактивного трафика (200 Мбит)
tc class add dev eth0 parent 1:1 classid 1:10 htb rate 200mbit prio 0

# Класс приоритета 1 для фонового трафика (800 Мбит)
tc class add dev eth0 parent 1:1 classid 1:20 htb rate 800mbit prio 1

# Добавление fq_codel к каждому классу для борьбы с bufferbloat
tc qdisc add dev eth0 parent 1:10 fq_codel
tc qdisc add dev eth0 parent 1:20 fq_codel
```

**Использование:**
* Маркируйте пакеты DSCP на стороне приложения/прокси
* Направляйте маркированный трафик в приоритетный класс (1:10)

> **Примечание**: Дисциплина `fq_codel` также может быть установлена по умолчанию через [`sysctl`](../Concepts/tcp_tuning.md#выбор-алгоритма-контроля-перегрузки) для всего системного стека.
