# ip netns: Управление сетевыми пространствами имён

## Определения

* **Network namespace (сетевое пространство имён)** — механизм изоляции сетевого стека в ядре Linux. Позволяет процессам иметь собственные сетевые интерфейсы, таблицы маршрутизации, правила межсетевого экрана и сокеты.
* **`ip netns`** — специализированная утилита из пакета `iproute2` для создания, удаления и настройки сетевых пространств имён.

> **Применение:** Сетевые пространства имён являются основой контейнеризации (Docker, Podman, Kubernetes). Например, каждый под Kubernetes использует собственное сетевое пространство имён.

## Основные концепции

### Изоляция ресурсов

Внутри каждого пространства имён изолированы следующие компоненты:

* **Интерфейсы:** включая виртуальную петлю (`lo`) и физические/виртуальные адаптеры.
* **Маршрутизация:** независимая таблица маршрутов.
* **Фильтрация:** отдельные правила `iptables` и `nftables`.
* **Порты:** возможность запускать сервисы на одних и тех же портах в разных пространствах имён на одном хосте.

### Типы пространств имён

| Тип | Описание |
|-----|----------|
| **default** | Основное пространство имён хоста, где по умолчанию находятся все физические интерфейсы. |
| **custom** | Пользовательские пространства имён, создаваемые для изоляции приложений или контейнеров. |

Подробный обзор механизмов изоляции в Linux приведен в заметке **[Пространства имён (namespaces)](../../../../Linux/Core/namespaces.md)**.

## Практические сценарии

### Создание и удаление

```bash
# Создать новое пространство имён
sudo ip netns add my_namespace

# Просмотреть список существующих пространств имён
ip netns list

# Удалить пространство имён
sudo ip netns delete my_namespace
```

### Выполнение команд внутри пространства имён

Для выполнения команд в контексте конкретного пространства имён используется команда `exec`.

```bash
# Просмотр сетевых интерфейсов (по умолчанию активен только lo в состоянии DOWN)
sudo ip netns exec my_namespace ip link

# Просмотр IP-адресов
sudo ip netns exec my_namespace ip address show

# Запустить интерактивную оболочки (bash) внутри пространства имён
sudo ip netns exec my_namespace bash

# Проверка сетевой связности
sudo ip netns exec my_namespace ping 8.8.8.8
```

### Связь между пространствами имён (veth-пары)

Для соединения пространств имён используются `veth` (virtual ethernet) интерфейсы, работающие как виртуальный патч-корд.

```bash
# 1. Создать veth-пару (veth-host и veth-ns)
sudo ip link add veth-host type veth peer name veth-ns

# 2. Переместить один конец пары в созданное пространство имён
sudo ip link set veth-ns netns my_namespace

# 3. Настройка интерфейса на стороне основного хоста
sudo ip address add 10.0.0.1/24 dev veth-host
sudo ip link set veth-host up

# 4. Настройка интерфейса внутри пространства имён
sudo ip netns exec my_namespace ip address add 10.0.0.2/24 dev veth-ns
sudo ip netns exec my_namespace ip link set veth-ns up
sudo ip netns exec my_namespace ip link set lo up

# 5. Проверка связности
ping 10.0.0.2
sudo ip netns exec my_namespace ping 10.0.0.1
```

### Мониторинг и отладка

```bash
# Просмотр PID процессов, запущенных в пространстве имён
ip netns pids my_namespace

# Просмотр таблицы маршрутизации внутри пространства имён
sudo ip netns exec my_namespace ip route show

# Просмотр ARP-таблицы (соседних устройств)
sudo ip netns exec my_namespace ip neighbour show

# Просмотр статистики интерфейсов
sudo ip netns exec my_namespace ip -s link show
```

### Настройка NAT для выхода в интернет

Чтобы процессы внутри изолированного пространства имён имели доступ к внешней сети, необходимо настроить маршрутизацию и трансляцию адресов (NAT) на хосте.

```bash
# 1. Включить пересылку IP-пакетов (IP forwarding)
sudo sysctl -w net.ipv4.ip_forward=1

# 2. Настроить NAT (MASQUERADE) на внешнем интерфейсе хоста (например, eth0)
sudo iptables -t nat -A POSTROUTING -s 10.0.0.0/24 -o eth0 -j MASQUERADE

# 3. Добавить маршрут по умолчанию внутри пространства имён
sudo ip netns exec my_namespace ip route add default via 10.0.0.1
```

## Дополнительная информация

### Ограничения и особенности

* **Жизненный цикл:** Пространство имён существует до тех пор, пока оно не будет удалено явно или пока в нем запущен хотя бы один процесс.
* **Интерфейсы:** При удалении пространства имён все виртуальные интерфейсы, находившиеся в нем, также удаляются. Физические интерфейсы возвращаются в пространство имён по умолчанию.
* **Производительность:** Использование `veth`-пар вносит минимальные накладные расходы, сопоставимые с работой стандартного сетевого стека.
