# ip rule: Управление правилами маршрутизации

## Определения

* **`ip rule`** (синонимы: `ip ru`) — специализированный объект утилиты `ip` из пакета `iproute2`, предназначенный для управления базой данных правил маршрутизации (**RPDB — Routing Policy Database**).
* **RPDB (Routing Policy Database)** — механизм в ядре Linux, который определяет, какую таблицу маршрутизации использовать для обработки конкретного пакета.
* **Policy-Based Routing (PBR)** — маршрутизация на основе политик. Метод, позволяющий принимать решение о выборе пути не только по адресу назначения (как в классической маршрутизации), но и по адресу источника, входящему интерфейсу, метке фаервола, UID пользователя и другим атрибутам пакета.

## Основные концепции

### Структура правила в RPDB

Каждое правило состоит из трех ключевых компонентов:
1.  **Приоритет (Priority / Preference)**: Число от 0 до 32767. Правила проверяются последовательно от меньшего к большему. Первое совпавшее правило (match) определяет дальнейшую судьбу пакета.
2.  **Селектор (Selector)**: Набор условий (фильтров), которым должен соответствовать пакет.
3.  **Действие (Action)**: Операция над совпавшим пакетом (обычно — указание таблицы маршрутизации для поиска).

### Стандартный набор правил

По умолчанию в Linux настроены три правила, обеспечивающие базовую работу системы:

| Приоритет | Селектор | Таблица | Назначение |
| :--- | :--- | :--- | :--- |
| **0** | `from all` | `local` | Обработка локальных, петлевых (loopback) и широковещательных адресов. |
| **32766** | `from all` | `main` | Основная таблица для стандартных и динамических маршрутов. |
| **32767** | `from all` | `default` | Резервная пустая таблица для пакетов, не попавших под иные правила. |

### Справочник селекторов (условий)

| Селектор | Описание | Технические нюансы |
| :--- | :--- | :--- |
| **from / to** | Адрес источника / назначения. | Поддерживает префиксы (`from 10.0.0.0/24`) и `not` (отрицание). |
| **iif / oif** | Входящий / исходящий интерфейс. | `iif lo` используется для трафика, генерируемого локально. |
| **fwmark** | Метка пакета из Netfilter. | Позволяет реализовать логику L7 (через `iptables`/`nftables`). |
| **uidrange** | Диапазон UID пользователя. | Критично для per-user routing (изоляция процессов). |
| **ipproto** | Номер или имя протокола IP. | Требует ядро 4.17+ (TCP, UDP, ICMP и др.). |
| **sport / dport** | Порты источника / назначения. | Требует ядро 4.17+; работает в связке с `ipproto`. |
| **l3mdev** | L3 Master Device (VRF). | Сопоставление пакетов, принадлежащих конкретному **[VRF](../../vrf.md)**. |
| **tos** | Поле Type of Service. | Классификация трафика по приоритетам QoS. |

### Типы действий и продвинутые параметры

*   **lookup / table <ID>** — Искать маршрут в указанной таблице (основное действие).
*   **suppress_prefixlength <N>** — Игнорировать таблицу, если найденный в ней маршрут имеет маску префикса меньше или равную N (например, `0` — игнорировать default gateway).
*   **suppress_ifgroup <ID>** — Игнорировать таблицу, если исходящий интерфейс принадлежит группе ID.
*   **blackhole** — Молчаливо отбросить пакет.
*   **unreachable** — Отбросить и отправить ICMP "Network Unreachable".
*   **prohibit** — Отбросить и отправить ICMP "Communication Administratively Prohibited".

## Практические сценарии

### Изоляция трафика пользователя (UID-routing)

Направить трафик пользователя с UID 1001 через таблицу 200 (например, в VPN-туннель).

```bash
sudo ip rule add uidrange 1001-1001 table 200 priority 1000
```

### Маршрутизация по портам (L4 PBR)

Направить весь исходящий трафик на порт 443 (HTTPS) через конкретный интерфейс (таблица 150). Требует ядро 4.17+.

```bash
sudo ip rule add ipproto tcp dport 443 table 150 priority 500
```

### Умный пропуск таблицы (suppress_prefixlength)

Использовать таблицу 100, только если в ней есть конкретный маршрут к подсети. Если там только маршрут по умолчанию (`0.0.0.0/0`), правило будет проигнорировано, и ядро перейдет к следующему.

```bash
sudo ip rule add from 10.10.10.0/24 table 100 suppress_prefixlength 0
```

### Использование меток фаервола (fwmark)

Реализация сложной логики (например, балансировка трафика конкретного приложения).

```bash
# 1. Маркировка HTTP-трафика в nftables
# nft add rule inet filter prerouting tcp dport 80 meta mark set 0x80

# 2. Создание правила для помеченных пакетов
sudo ip rule add fwmark 0x80 table 80 priority 300
```

### Комбинирование условий с исключением (not)

Направить весь трафик, **кроме** трафика в локальную сеть `192.168.0.0/16`, через таблицу `vpn_table`.

```bash
sudo ip rule add to not 192.168.0.0/16 table vpn_table priority 2000
```

### Удаление правил

```bash
# Удаление по атрибутам (необходимо полное совпадение параметров)
sudo ip rule del from 192.168.1.50 table 100

# Удаление по приоритету (наиболее надежный способ)
sudo ip rule del priority 1000
```

## Диагностика и устранение неисправностей

### Анализ RPDB

```bash
# Просмотр всех правил
ip rule show

# Детальный просмотр (включая подавление префиксов и VRF)
ip -d rule show

# Эмуляция выбора маршрута (важнейший инструмент отладки)
ip route get 8.8.8.8 from 192.168.1.50 iif eth1
# → В выводе будет указана выбранная таблица и шлюз.
```

### Проблема асимметрии и rp_filter

При использовании PBR ответный трафик может уходить через интерфейс, отличный от входящего. Если включен **Strict Reverse Path Forwarding (RPF)**, ядро отбросит такой пакет.

**Решение:** Установить `rp_filter` в режим `2` (Loose).

```bash
# Временное включение
sudo sysctl -w net.ipv4.conf.all.rp_filter=2

# Постоянное включение в /etc/sysctl.d/99-pbr.conf
# net.ipv4.conf.all.rp_filter = 2
```

## Дополнительная информация

### Сохранение конфигурации (Persistence)

Команды `ip rule` применяются немедленно, но не сохраняются после перезагрузки.

*   **systemd-networkd**: Секция `[RoutingPolicyRule]` в `.network` файлах.
*   **Netplan**: Секция `routing-policy:` в YAML-файлах.
*   **NetworkManager**: Команда `nmcli connection modify <name> +ipv4.routing-rules "from 1.2.3.4 table 100"`.
