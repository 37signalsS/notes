# ip rule: Управление правилами маршрутизации

## Определения

* **`ip rule`** — объект утилиты `ip` для управления базой данных правил маршрутизации (Routing Policy Database, RPDB).
* **RPDB (Routing Policy Database)** — механизм в ядре Linux, который определяет, какую таблицу маршрутизации использовать для обработки конкретного пакета.
* **Policy-Based Routing (PBR)** — метод маршрутизации, при котором выбор пути зависит не только от адреса назначения, но и от других атрибутов пакета (адрес источника, интерфейс, метка фаервола).

## Основные концепции

### Формат правила

Каждое правило состоит из трех основных частей:

1. **Приоритет** (Priority) — определяет порядок проверки. Чем меньше число, тем выше приоритет.
2. **Селектор** (Selector) — набор условий, которым должен соответствовать пакет.
3. **Действие** (Action) — что сделать с пакетом при совпадении условий (обычно — использовать конкретную таблицу маршрутизации).

### Стандартный набор правил

По умолчанию в Linux настроены три правила, которые обрабатывают большинство стандартных ситуаций:

| Приоритет | Селектор | Таблица | Назначение |
| :--- | :--- | :--- | :--- |
| `0` | `from all` | `local` | Локальные адреса, loopback и широковещательный трафик. |
| `32766` | `from all` | `main` | Основная таблица маршрутизации (где находятся обычные маршруты). |
| `32767` | `from all` | `default` | Пустая таблица для пакетов, не подошедших под предыдущие правила. |

### Селекторы (условия) правил

| Селектор | Описание | Пример |
| :--- | :--- | :--- |
| `from <prefix>` | По адресу источника (самый частый вариант). | `from 192.168.1.100` |
| `to <prefix>` | По адресу назначения. | `to 10.0.0.0/8` |
| `iif <name>` | По входящему сетевому интерфейсу. | `iif eth1` |
| `oif <name>` | По исходящему сетевому интерфейсу. | `oif eth0` |
| `fwmark <mark>` | По метке пакета (`iptables` / `nftables`). | `fwmark 0x1` |
| `uidrange <L-H>` | По диапазону UID пользователя (для per-user routing). | `uidrange 1000-1005` |
| `tos <value>` | По значению поля Type of Service. | `tos 0x10` |
| `ipproto <id>` | По протоколу (tcp, udp, icmp и др.). | `ipproto tcp` |
| `sport / dport` | По порту источника или назначения. | `dport 80` |

### Продвинутые действия и параметры

* **lookup <table_id>** — искать маршрут в указанной таблице.
* **suppress_prefixlength <N>** — игнорировать маршруты в таблице с маской меньше или равной N (полезно для пропуска `default via` в кастомных таблицах).
* **suppress_ifgroup <ID>** — игнорировать таблицу, если исходящий интерфейс принадлежит указанной группе.
* **unreachable** / **blackhole** / **prohibit** — различные варианты отбрасывания пакетов.

## Практические сценарии

### Маршрутизация на основе пользователя (uidrange)

Полезно для изоляции трафика конкретных системных пользователей или контейнеров.

```bash
# Направить трафик пользователя с UID 1001 через таблицу 200
sudo ip rule add uidrange 1001-1001 table 200 priority 1000
```

### Использование suppress_prefixlength

Позволяет «пропустить» таблицу, если в ней нет специфичного маршрута (только маршрут по умолчанию), и перейти к проверке следующих правил.

```bash
# Использовать таблицу 100, только если там есть маршрут точнее, чем /0
sudo ip rule add from 10.0.0.0/24 table 100 suppress_prefixlength 0
```

### Использование меток фаервола (fwmark)

Позволяет реализовать сложную логику, когда условия в `ip rule` недостаточны.

```bash
# 1. Маркировка HTTP-трафика через iptables
sudo iptables -t mangle -A PREROUTING -p tcp --dport 80 -j MARK --set-mark 0x80

# 2. Создание правила для помеченных пакетов
sudo ip rule add fwmark 0x80 table 80 priority 500
```

### Удаление правил

```bash
# Удаление правила по его атрибутам
sudo ip rule del from 192.168.1.50 table 100

# Удаление по приоритету (рекомендуется для точности)
sudo ip rule del priority 1000
```

### Комбинирование условий с исключением

Направлять весь трафик, **кроме** трафика в локальную сеть `192.168.0.0/16`, через таблицу `vpn_table`.

```bash
sudo ip rule add to not 192.168.0.0/16 table vpn_table
```

## Диагностика и устранение неисправностей

### Проверка RPDB

```bash
# Просмотр всех правил с их приоритетами
ip rule show

# Детальный просмотр (включая подавление префиксов и группы)
ip -d rule show

# Эмуляция выбора маршрута для конкретного пакета (важнейший инструмент)
ip route get 8.8.8.8 from 192.168.1.50 iif eth1
```

### Проблема асимметрии и rp_filter

При использовании PBR ответный трафик может уходить через другой интерфейс. Если включен **Strict Reverse Path Forwarding (RPF)**, ядро отбросит такие пакеты.

**Решение:** Установить `rp_filter` в режим `2` (Loose).

```bash
# Временное изменение
sudo sysctl -w net.ipv4.conf.all.rp_filter=2
sudo sysctl -w net.ipv4.conf.eth1.rp_filter=2

# Постоянное изменение в /etc/sysctl.d/99-pbr.conf
# net.ipv4.conf.all.rp_filter = 2
```

## Дополнительная информация

### Сохранение конфигурации

Команды `ip rule` вносят изменения только в текущую сессию ядра. После перезагрузки они будут утеряны.

* **systemd-networkd**: Используйте секцию `[RoutingPolicyRule]` в `.network` файлах.
* **Netplan**: Используйте секцию `routing-policy:` в YAML-конфигурации.
* **NetworkManager**: Используйте `nmcli connection modify <name> +ipv4.routing-rules ...`.
