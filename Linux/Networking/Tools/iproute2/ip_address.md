# ip address: Управление IP-адресами

## Определения

* **`ip address`** (синонимы: `ip addr`, `ip a`) — объект утилиты `ip` для управления IPv4 и IPv6 адресами на сетевых интерфейсах.
* **Primary Address** (основной адрес) — первый адрес в заданной подсети на интерфейсе. Используется ядром как адрес источника (`Source IP`) для исходящих пакетов, если не указано иное. Подробнее о логике выбора: **[Выбор исходного IP](../../SystemAdministration/routing.md#выбор-исходного-ip-source-ip-selection)**.
* **Secondary Address** (вторичный адрес) — дополнительные адреса в той же подсети. В Linux они логически привязаны к основному адресу.
* **Scope** (область видимости) — параметр, определяющий "расстояние", на котором адрес считается валидным (например, только для самого хоста или для всей сети).

> **Важно:** Все изменения, внесенные через `ip address`, являются **временными** и будут утеряны после перезагрузки. Для постоянной настройки используйте [systemd-networkd](../../Settings/Persistent_Network/systemd_networkd.md) или NetworkManager.

## Основные концепции

### Области видимости (Scope)

| Область | Описание |
|:---|:---|
| **global** | Адрес доступен отовсюду (глобально маршрутизируемый). |
| **link** | Адрес валиден только в пределах данного физического или логического линка (L2-сегмента). Типично для IPv6 Link-Local (`fe80::/10`). |
| **host** | Адрес валиден только внутри самого хоста (например, на интерфейсе `lo`). |

### Атрибуты и флаги адресов

* **dynamic** — адрес получен автоматически (например, через DHCP или SLAAC).
* **permanent** — адрес настроен вручную (статически).
* **deprecated** — адрес валиден, но его использование для новых соединений не рекомендуется (используется при перенумерации IPv6).
* **tentative** (IPv6) — адрес находится в процессе проверки на уникальность (DAD).
* **nodad** (IPv6) — отключает проверку Duplicate Address Detection для этого адреса (полезно для быстрой настройки или Anycast).
* **home** (IPv6) — помечает адрес как "Home Address" для Mobile IPv6.
* **mngtmpaddr** (IPv6) — указывает ядру генерировать временные адреса (RFC 4941 Privacy Extensions).
* **noprefixroute** — запрещает ядру автоматически создавать маршрут в таблицу маршрутизации для префикса этого адреса.

### Управление временем жизни (Lifetimes)

Для IPv6 адресов (и некоторых динамических IPv4) критически важны параметры времени жизни:

* **valid_lft** — общее время, в течение которого адрес считается валидным. По истечении этого времени адрес удаляется.
* **preferred_lft** — время, в течение которого адрес считается предпочтительным. После этого он переходит в состояние `deprecated`.

```bash
# Добавление адреса с ограниченным временем жизни
sudo ip address add 192.168.1.50/24 dev eth0 valid_lft 3600 preferred_lft 1800
```

### Взаимодействие с VRF (Virtual Routing and Forwarding)

При использовании VRF адреса назначаются на физические или виртуальные интерфейсы, которые затем привязываются к VRF-мастеру.

```bash
# Просмотр адресов в контексте конкретного VRF
ip address show vrf vrf-mgmt
```

## Практические сценарии

### Просмотр информации об адресах

```bash
# Вывод всех адресов на всех интерфейсах
ip address show

# Краткий (однострочный) вывод
ip -br address show

# Фильтрация по протоколу
ip -4 address show
ip -6 address show

# Просмотр адресов конкретного интерфейса
ip address show dev eth0
```

### Добавление адресов

```bash
# Добавление статического IPv4 адреса
sudo ip address add 192.168.1.10/24 dev eth0

# Добавление IPv6 адреса
sudo ip -6 address add 2001:db8::1/64 dev eth0

# Настройка Anycast адреса (IPv6)
# Используется nodad для предотвращения конфликтов при назначении одного IP на несколько хостов
sudo ip -6 address add 2001:db8:ffff::1/128 dev eth0 nodad anycast

# Добавление адреса с меткой (alias) для совместимости со старым ifconfig
sudo ip address add 10.0.0.1/24 dev eth0 label eth0:1
```

### Удаление и очистка

```bash
# Удаление конкретного адреса
sudo ip address del 192.168.1.10/24 dev eth0

# Очистка (удаление) всех адресов на интерфейсе
sudo ip address flush dev eth0
```

### Сохранение и восстановление состояния (Экспериментально)

Утилита `ip` позволяет экспортировать текущую конфигурацию адресов в бинарный формат и восстанавливать её.

```bash
# Сохранение текущих адресов в файл
ip address save > addresses.state

# Восстановление адресов из файла
sudo ip address restore < addresses.state
```

**⚠️ Внимание:** При удалении адреса, полученного по DHCP, ядро также удалит маршрут по умолчанию (default gateway), который был привязан к этому адресу. Это приведет к потере доступа к внешним сетям.

### Временные адреса (IPv6 Privacy Extensions)

Используются для предотвращения отслеживания хоста по его IPv6-адресу.

```bash
# Проверка наличия временных адресов
ip -6 address show eth0 | grep temporary

# Включение генерации через sysctl
sudo sysctl -w net.ipv6.conf.eth0.use_tempaddr=2
```

### Типичные проблемы

| Проблема | Возможная причина | Решение |
|:---|:---|:---|
| Сеть пропала после `ip addr del` | Удален основной адрес (и шлюз) | Добавьте адрес заново и проверьте `ip route` |
| Ошибка "File exists" | Адрес уже назначен | Проверьте `ip addr show` |
| IPv6-адрес в состоянии `tentative` | Идет проверка на дубликат (DAD) | Подождите несколько секунд |
| Не удается назначить адрес | Интерфейс в состоянии `DOWN` | Выполните `ip link set eth0 up` |
