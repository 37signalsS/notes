# ip address: Управление IP-адресами

## Определения

* **`ip address`** (синонимы: `ip addr`, `ip a`) — специализированный объект утилиты `ip` из пакета `iproute2`, предназначенный для управления адресами протоколов IPv4 и IPv6 на сетевых интерфейсах.
* **Основной адрес (Primary Address)** — первый адрес, назначенный в конкретной подсети на интерфейсе. Он служит адресом источника (`Source IP`) по умолчанию для исходящих пакетов, генерируемых самим хостом.
* **Вторичный адрес (Secondary Address)** — дополнительные адреса в той же подсети. В Linux они логически привязаны к основному адресу.
* **Область видимости (Scope)** — атрибут, определяющий логический радиус действия адреса (например, только внутри хоста или во всей глобальной сети).

> **Важно:** Все изменения, внесенные через `ip address`, применяются немедленно в ядре, но являются **временными**. Они будут утеряны после перезагрузки. Для постоянной настройки используйте системные конфигураторы (systemd-networkd, Netplan, NetworkManager).

## Основные концепции

### Классификация областей видимости (Scope)

| Область | Техническое описание |
| :--- | :--- |
| **global** | Глобально маршрутизируемый адрес, доступный за пределами локального сегмента. |
| **link** | Адрес валиден только в пределах данного L2-домена (например, IPv6 Link-Local `fe80::/10`). |
| **host** | Адрес ограничен пределами самого хоста (типично для интерфейса `lo`). |

### Атрибуты и флаги адресов

* **dynamic** — адрес получен автоматически (через DHCP или SLAAC).
* **permanent** — адрес настроен вручную (статически).
* **deprecated** — адрес валиден для приема трафика, но его использование для новых исходящих соединений не рекомендуется (используется при перенумерации IPv6).
* **tentative** — (IPv6) адрес находится в процессе проверки на уникальность (**DAD — Duplicate Address Detection**).
* **nodad** — (IPv6) отключает проверку дубликатов. Критично для Anycast или ускорения настройки.
* **mngtmpaddr** — (IPv6) указывает ядру генерировать временные адреса на основе префикса этого адреса (**RFC 4941 Privacy Extensions**).
* **noprefixroute** — запрещает ядру автоматически создавать маршрут в таблицу маршрутизации для префикса этого адреса.
* **home** — (IPv6) помечает адрес как "Home Address" для Mobile IPv6.

### Управление временем жизни (Lifetimes)

Для динамических сред и IPv6 критически важны параметры времени жизни:
* **valid_lft** (Valid Lifetime) — общее время (в секундах), в течение которого адрес считается валидным. По истечении этого времени адрес удаляется.
* **preferred_lft** (Preferred Lifetime) — время, в течение которого адрес считается предпочтительным. После его истечения адрес переходит в состояние `deprecated`.

### Взаимодействие с VRF (Virtual Routing and Forwarding)

При использовании VRF адреса назначаются на интерфейсы, которые затем привязываются к VRF-мастеру. Это позволяет изолировать адресные пространства на одном хосте.

```bash
# Просмотр адресов в контексте конкретного VRF
ip address show vrf vrf-mgmt
```

## Практические сценарии

### Оперативный просмотр и диагностика

```bash
# Вывод всех адресов на всех интерфейсах (подробно)
ip address show

# Краткий (однострочный) вывод для быстрой проверки
ip -br address show

# Фильтрация по протоколу
ip -4 address show
ip -6 address show

# Вывод в формате JSON для автоматизации (скрипты, мониторинг)
ip -j -p address show eth0
```

### Назначение и модификация адресов

```bash
# Добавление статического IPv4 адреса с указанием широковещательного адреса
sudo ip address add 192.168.1.10/24 brd + dev eth0

# Добавление IPv6 адреса
sudo ip -6 address add 2001:db8::1/64 dev eth0

# Настройка Anycast адреса (IPv6)
# Используется nodad для предотвращения конфликтов при назначении одного IP на несколько хостов
sudo ip -6 address add 2001:db8:ffff::1/128 dev eth0 nodad anycast

# Добавление адреса с меткой (alias) для совместимости со старым ifconfig
sudo ip address add 10.0.0.1/24 dev eth0 label eth0:mgmt

# Ограничение времени жизни адреса (например, для временного доступа)
sudo ip address add 172.16.0.5/24 dev eth0 valid_lft 3600 preferred_lft 1800
```

### Удаление и очистка интерфейсов

```bash
# Удаление конкретного адреса
sudo ip address del 192.168.1.10/24 dev eth0

# Полная очистка (удаление) всех адресов на интерфейсе
sudo ip address flush dev eth0
```

**Внимание:** При удалении основного адреса, полученного по DHCP, ядро может также удалить маршрут по умолчанию, привязанный к этому адресу, что приведет к потере сетевой связности.

### Механизмы приватности (IPv6 Privacy Extensions)

Используются для предотвращения отслеживания хоста по его статическому IPv6-адресу.

```bash
# Включение генерации временных адресов через sysctl
sudo sysctl -w net.ipv6.conf.all.use_tempaddr=2

# Проверка наличия временных адресов (флаг 'temporary' в выводе)
ip -6 address show eth0 | grep temporary
```

### Сохранение и восстановление состояния (Экспериментально)

Позволяет экспортировать текущую конфигурацию в бинарный формат и восстанавливать её.

```bash
# Сохранение текущих адресов в файл
ip address save > addresses.state

# Восстановление адресов из файла
sudo ip address restore < addresses.state
```

## Дополнительная информация

### Типичные проблемы

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| Сеть пропала после `ip addr del` | Удален основной адрес (Primary) и связанный шлюз. | Настройте `promote_secondaries=1` в sysctl или добавьте адрес заново. |
| Ошибка `File exists` | Данный IP уже назначен этому интерфейсу. | Проверьте `ip addr show`. |
| IPv6-адрес в состоянии `tentative` | Идет проверка на уникальность (DAD). | Подождите 1–2 секунды до перехода в состояние `global`. |
| Не удается назначить адрес | Сетевой интерфейс выключен (состояние `DOWN`). | Выполните `sudo ip link set <dev> up`. |
