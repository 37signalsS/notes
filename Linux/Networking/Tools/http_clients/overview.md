# Обзор HTTP-клиентов в Linux

> **Надёжность: 10/10** (Систематизированное сравнение стандартных инструментов)
> **Актуальность:** Август 2024 (проверено для curl 8.x, wget 1.21.x, httpie 3.x)

## Определения

**HTTP-клиент командной строки** — утилита для отправки HTTP-запросов и получения ответов непосредственно из терминала. В экосистеме Linux эти инструменты являются критически важными для:
- Тестирования и отладки REST/gRPC API.
- Автоматизации задач в CI/CD пайплайнах.
- Скачивания файлов и зеркалирования ресурсов.
- Мониторинга доступности сервисов (Healthchecks).

## Основные концепции

### 1. Тройка лидеров

В большинстве дистрибутивов и сценариев используются три основных инструмента, каждый из которых имеет свою специализацию:

| Клиент | Специализация | Основные протоколы |
| :--- | :--- | :--- |
| **[wget](./wget.md)** | Загрузка файлов и зеркалирование | HTTP, HTTPS, FTP |
| **[curl](./curl.md)** | Универсальный «швейцарский нож» для API | Почти все (HTTP, FTP, SCP, LDAP, SMB...) |
| **[httpie](./httpie.md)** | Интерактивная отладка API (Human-friendly) | HTTP, HTTPS |

### 2. Сводная таблица возможностей

| Характеристика | Wget | cURL | HTTPie |
| :--- | :--- | :--- | :--- |
| **Философия** | «Поставил и забыл» (Batch) | Универсальность (Swiss knife) | Удобство человека (UX) |
| **JSON** | Ручная сборка строки | Через заголовки и флаг `-d` | Автоматически (`key=val`) |
| **Вывод (UI)** | Прогресс-бар в лог | Сырой поток данных (Raw) | Цветной, форматированный |
| **Ошибка 4xx/5xx** | Возвращает ошибку (код > 0) | **Успех (код 0)**. Нужен `-f` | Возвращает ошибку (код 4) |
| **Многопоточность** | Нет (в wget2 — да) | Нет | Нет |
| **Скрипты** | Отлично (особенно зеркала) | Промышленный стандарт | Не рекомендуется (из-за веса) |
| **Зависимости** | Минимальные | Минимальные | Python (требует рантайм) |

### 3. Современные альтернативы

Помимо «классики», набирают популярность инструменты на базе Rust и Go, сочетающие скорость curl и удобство HTTPie:

- **xh:** (на Rust) Очень быстрая альтернатива HTTPie. Полностью совместима по синтаксису, но не требует Python.
- **curlie:** (на Go) Обертка над curl, которая добавляет форматирование вывода HTTPie, сохраняя всю мощь и флаги curl.

## Практические сценарии

### Сценарий 1. Когда использовать каждый инструмент?

1. **Используйте `wget`, если:**
   - Вам нужно скачать сайт целиком для офлайн-просмотра (`wget -r`).
   - Нужно скачать большой список файлов в фоне.
   - Требуется автоматическое продолжение загрузки при обрыве.

2. **Используйте `curl`, если:**
   - Вы пишете bash-скрипт или CI/CD пайплайн (максимальная переносимость).
   - Нужна детальная диагностика (DNS, TLS, тайминги).
   - Требуются специфические протоколы (SFTP, MQTT и др.).

3. **Используйте `httpie` (или `xh`), если:**
   - Вы вручную тестируете API и хотите видеть красивый JSON.
   - Нужно быстро отправить POST-запрос с несколькими полями без написания длинных заголовков.

### Сценарий 2. Сравнение синтаксиса на типовых задачах

**Отправка POST с JSON:**
```bash
# curl (длинно, но надёжно)
curl -f -X POST -H 'Content-Type: application/json' -d '{"id":1}' https://api.io/data

# httpie (быстро и красиво)
http POST https://api.io/data id:=1
```

**Проверка статуса (Healthcheck):**
```bash
# curl (требует внимания к кодам возврата!)
curl -fsS https://api.io/health || exit 1

# wget (работает "из коробки" как проверка)
wget --spider -q https://api.io/health
```

## Дополнительная информация

### 1. Рекомендации по безопасности

1. **Секреты:** Никогда не передавайте токены или пароли в открытом виде в строке команды (они попадут в `history`). Используйте переменные окружения или файлы конфигурации (`.netrc`).
2. **Проверка SSL:** Флаги `-k` (curl) и `--no-check-certificate` (wget) отключают проверку безопасности. Используйте их только в локальных тестах.
3. **Пайплайны:** В скриптах всегда используйте `set -e` вместе с `--fail` (для curl), чтобы ошибка сервера прерывала выполнение скрипта.

### 2. Инструменты для отладки

Для проверки работы ваших клиентов удобно использовать:
- **[httpbin.org](https://httpbin.org):** Эндпоинты для проверки всех типов запросов, заголовков и кодов ответов.
- **[badssl.com](https://badssl.com):** Для тестирования поведения клиентов при проблемах с сертификатами.
