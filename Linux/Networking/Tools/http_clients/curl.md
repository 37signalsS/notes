# cURL: Универсальный "швейцарский нож"

**cURL** (Client for URLs) — это чрезвычайно мощный и гибкий инструмент для передачи данных по множеству протоколов.

## Ключевые особенности и опции

* **Безопасность в скриптах:** В отличие от `wget`, `curl` по умолчанию **не** завершается с ошибкой при HTTP-статусах 4xx или 5xx. Для надежной работы в скриптах **всегда** используйте опцию `--fail`.

    ```bash
    # --fail (-f): завершиться с ошибкой (код 22) при HTTP-ошибках сервера
    # --show-error (-S): показывать ошибку, даже если используется -s (silent)
    curl -fsS http://httpbin.org/status/404
    ```

* **Работа с API:**

  * `-X, --request`: указать метод запроса (GET, POST, PUT, DELETE).
  * `-H, --header`: добавить заголовок.
  * `-d, --data`: отправить данные (формат `application/x-www-form-urlencoded`).

    ```bash
    curl -X POST -H "Content-Type: application/json" -d '{"key":"value"}' http://httpbin.org/post
    ```


* **Отправка файлов и форм:**
  * `-F, --form`: отправить данные в формате `multipart/form-data`.

    ```bash
    # -F, --form: отправить данные в формате multipart/form-data
    # @filename: прикрепить файл
    curl -F "user=John" -F "avatar=@/path/to/photo.jpg" http://httpbin.org/post

    # Отправка "сырых" бинарных данных
    # --data-binary @filename
    curl --data-binary @archive.zip http://httpbin.org/post
    ```

* **Отладка:**

    Для более глубокого анализа сетевых проблем, включая детальное измерение времени ответа DNS, установки TCP-соединения и TLS-рукопожатия, см. отдельную заметку: [Диагностика сетевых задержек с curl](../../../Diagnostics/Networking/curl_network_diagnostics.md).

    ```bash
    # -v, --verbose: показать подробную информацию о соединении и заголовках (менее детально, чем --trace)
    curl -v https://example.com
    ```

    Для максимально детального дампа обмена данными, включая TLS-информацию, используйте опцию `--trace <file>`.

    ```bash
    # --trace <file>: записать полный дамп обмена данными (включая бинарные и TLS) в файл
    curl --trace trace.log https://example.com
    ```

* **Аутентификация и Cookies:**

Помимо опций `--cookie` и `--cookie-jar` для работы с куками, `curl` также поддерживает файл `.netrc` для базовой аутентификации.

* **Подмена User-Agent:** Можно легко подменить заголовок `User-Agent` с помощью опции `-A` или `--user-agent`.

    ```bash
    curl -A "MyCustomAgent/1.0" https://example.com
    ```

* **Сохранение вывода в файл:** Для сохранения ответа сервера в файл используется опция `-o` (`--output`).

    ```bash
    curl -o hh.json "https://api.hh.ru/vacancies?text=сетевой%20инженер"
    ```

* **Работа с JSON и `jq`**: `curl` отлично работает в связке с утилитой `jq` для форматирования и обработки JSON-ответов.

    ```bash
    curl "https://api.hh.ru/vacancies?text=сетевой%20инженер" | jq .
    ```

### Определение публичного IP-адреса

`curl` может быть использован для быстрого определения вашего публичного IP-адреса, используя сторонние сервисы. Опция `-s` (`--silent`) подавляет вывод прогресса и ошибок `curl`, оставляя только сам IP-адрес.

**Примеры:**

```bash
curl -s ifconfig.me

curl 2ip.ru
```

## Дополнительная информация

### 1. Игнорирование ошибок SSL-сертификатов (`--insecure`, `-k`)

Иногда при работе с `curl` возникает ошибка, связанная с недействительным или отсутствующим SSL-сертификатом у целевого сайта.

Хотя пропуск проверки сертификата может быть полезен в целях разработки, важно понимать, что такие действия **повышают риск утечки данных**. Используйте этот метод только на доверенных ресурсах или в контролируемой среде.

Команда для игнорирования ошибок сертификата:

```bash
curl --insecure [URL]
```

или сокращенная версия:

```bash
curl -k [URL]
```

Эти параметры отключают проверку SSL-сертификата и позволяют подключаться даже к сайтам с проблемными или самоподписанными сертификатами.

**Пример использования:**

Допустим, вы выполняете запрос к сайту с недействительным сертификатом:

```bash
curl myawesomewebsite.com
```

Вы получите ошибку, например:

```
curl: (60) SSL: no alternative certificate subject name matches target host name 'myawesomewebsite.com'
```

Чтобы обойти проблему, выполните:

```bash
curl -k myawesomewebsite.com
```

Теперь запрос будет выполнен без проверки сертификата.

**Важное предупреждение:** Флаги `--insecure` и `-k` работают аналогично параметру `--no-check-certificate` в утилите `wget`. Всегда проверяйте, почему SSL-сертификат считается недействительным, и используйте параметр `-k` только в исключительных случаях.

### 2. Скрытые таймауты в cURL: Диагностика и Решения

Иногда при использовании `curl` в скриптах, CI/CD пайплайнах или на сервере, он может "повиснуть", не завершаясь и не выдавая ошибок.

По умолчанию `curl` не устанавливает жесткий общий таймаут для всей операции. Если удалённый сервер принял TCP-соединение, но затем не отдает тело ответа (например, из-за медленного reverse proxy, фильтрации контента или отображения CAPTCHA), `curl` может бесконечно ожидать данные.

Эта проблема особенно опасна в автоматизированных системах: автотестах, healthcheck’ах и системах мониторинга, где поведение `curl` считается надежным индикатором доступности сервиса. Зависший `curl` может привести к ложноположительным результатам мониторинга или "зависанию" пайплайнов.

**Решения**

Для предотвращения подобных ситуаций и обеспечения предсказуемого поведения `curl` всегда следует задавать явные лимиты времени.

1. **Общий таймаут для всей операции (`--max-time`)**

    Используйте опцию `--max-time`, чтобы ограничить максимальное время, которое `curl` будет ждать завершения всей операции (включая установление соединения, передачу данных и получение ответа).

    ```bash
    curl --max-time 10 https://example.com
    ```

    В этом примере `curl` завершится с ошибкой, если вся операция займет более 10 секунд.

2. **Более тонкая настройка таймаутов**

    Для более гранулированного контроля над поведением `curl` можно использовать комбинацию следующих опций:

    ```bash
    curl --connect-timeout 5 --speed-time 10 --speed-limit 100 https://example.com
    ```

    * `--connect-timeout <seconds>`: Устанавливает максимальное время (в секундах), которое `curl` будет ждать для установки TCP-соединения с хостом. Если соединение не устанавливается в течение этого времени, `curl` прерывает попытку.
        * *Пример:* `--connect-timeout 5` — ждать установки соединения не более 5 секунд.

    * `--speed-time <seconds>` и `--speed-limit <bytes>`: Эти две опции работают в паре. `curl` прервет операцию, если в течение `--speed-time` секунд средняя скорость передачи данных будет ниже `--speed-limit` байт в секунду.
        * *Пример:* `--speed-time 10 --speed-limit 100` — если в течение 10 секунд скорость передачи упадет ниже 100 байт/сек, `curl` завершится. Это особенно полезно для обнаружения "зависших" соединений, когда данные поступают очень медленно или прекратили поступать вовсе.

**Рекомендации**

* **Всегда задавайте явные лимиты:** Если `curl` запускается как часть healthcheck в контейнере, в CI/CD или любой автоматизированной системе, всегда задавайте явные лимиты времени.
* **Учитывайте нестабильные сети:** Особенно актуально для нестабильных сетевых окружений, где DNS может работать, TCP-соединение устанавливается, но передача данных идет медленно или прерывается.
* **Используйте `--fail`:** Для надежной работы в скриптах, помимо таймаутов, также рекомендуется использовать опцию `--fail` (или `-f`). Она заставит `curl` завершаться с ненулевым кодом выхода, если HTTP-статус ответа указывает на ошибку (4xx или 5xx).

    ```bash
    curl -f --max-time 10 https://example.com
    ```
