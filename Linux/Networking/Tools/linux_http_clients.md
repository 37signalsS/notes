# HTTP-клиенты в Linux

## Определения

*   **HTTP-клиент командной строки** — это утилита, позволяющая отправлять HTTP-запросы и получать ответы непосредственно из терминала. Они являются ключевыми инструментами для тестирования API, автоматизации задач и скачивания ресурсов.

### Краткая сравнительная таблица

| Задача                               | Wget                               | cURL                                                    | HTTPie                               |
| ------------------------------------ | ---------------------------------- | ------------------------------------------------------- | ------------------------------------ |
| **Основное назначение**              | Скачивание файлов, зеркалирование  | Универсальная передача данных, API, скрипты             | Удобная работа с API, интерактивность |
| **Скачать файл**                     | `wget <url>`                       | `curl -O <url>`                                         | `http --download <url>`              |
| **Продолжить скачивание**            | `wget -c <url>`                    | `curl -C - -O <url>`                                    | `http --download --continue <url>`   |
| **Отправить JSON**                   | Сложно, требует ручной сборки      | `curl -H 'Content-Type: ..' -d '{"a":1}'`               | `http POST <url> a=1` (по умолчанию) |
| **Отправить форму**                  | `--post-data='a=1&b=2'`            | `curl -d 'a=1&b=2'` или `curl -F 'a=1'`                 | `http -f POST <url> a=1 b=2`         |
| **Безопасность в скриптах (HTTP 404)** | Возвращает ошибку (wget2)          | **Не возвращает ошибку по умолчанию!** Нужен флаг `-f`. | Возвращает ошибку                    |
| **Дружелюбность вывода**             | Низкая (лог-файл)                  | Низкая (сырой вывод)                                    | Высокая (подсветка, форматирование)  |

## Базовые концепции

### 1. Основные клиенты

В Linux наиболее популярны три клиента, каждый со своей нишей:
*   **Wget:** Классическая утилита для надежного скачивания файлов и рекурсивной загрузки сайтов.
*   **cURL:** Универсальный "швейцарский нож" для передачи данных по множеству протоколов, стандарт для работы с API в скриптах.
*   **HTTPie:** Современный, дружелюбный к пользователю клиент, созданный для удобной интерактивной работы с API.

### 2. Концепции аутентификации

*   **BASIC:** Передает имя пользователя и пароль в заголовке `Authorization` в кодировке Base64. Небезопасно без HTTPS.
*   **DIGEST:** Механизм "вызов-ответ", который не передает пароль в открытом виде, но стал менее актуален с распространением HTTPS.
*   **BEARER:** Наиболее распространенный метод в современных API. Клиент отправляет токен (например, JWT) в заголовке `Authorization: Bearer <токен>`.
*   **На основе Cookies:** Сервер устанавливает cookie после входа, которые клиент автоматически отправляет с последующими запросами.

### 3. Инструменты для тестирования

*   **[httpbin.org](https://httpbin.org):** Тестовый API-сервер, который "отражает" полученные запросы, позволяя проверить, что именно было отправлено.
*   **[badssl.com](https://badssl.com):** Набор сайтов с некорректными SSL-сертификатами для тестирования обработки ошибок TLS.
*   **Встроенный веб-сервер Python:** `python3 -m http.server 8000`.

## Практические сценарии

В этом разделе подробно рассматривается использование каждого из трех основных клиентов для выполнения типичных задач.

### 1. Wget: Надежное скачивание и зеркалирование

**Wget** (GNU Wget) — это утилита, основное предназначение которой — надежное скачивание файлов и создание локальных зеркал веб-сайтов.

#### Ключевые особенности и опции GNU Wget

*   **Зеркалирование сайтов:**
    *   `wget` — очень полезный инструмент для создания локальных копий веб-сайтов.
    *   Опции:
        *   `-r`, `--recursive`: включить рекурсию.
        *   `-l <depth>`, `--level=<depth>`: глубина рекурсии (например, `inf` для бесконечной глубины).
        *   `-k`, `--convert-links`: преобразовать абсолютные ссылки в локальные (относительные) для офлайн-просмотра. Это позволяет перемещать зеркало на другой сервер без потери работоспособности ссылок.
        *   `-p`, `--page-requisites`: загрузить все ресурсы, необходимые для отображения страницы (CSS, JS, изображения).
        *   `--adjust-extension`: добавлять к файлам подходящие расширения (.html, .css).
    *   Пример:
        ```bash
        wget -r -l inf -k -p --adjust-extension http://localhost:8000
        ```
    *   Важно: если веб-сервер слушает только на IPv4, а `localhost` резолвится в IPv6, используйте `-4`.

*   **Обработка ошибок и коды возврата:**
    *   GNU Wget предоставляет более детальные сообщения об ошибках по сравнению с BusyBox-версией.
    *   Коды возврата (exit status) можно посмотреть в документации (`man wget` в разделе `EXIT STATUS`). Например, код `8` означает "Server issued an error response".
    *   В отличие от `curl` (по умолчанию), `wget` (особенно `wget2`) возвращает ненулевой код выхода при HTTP-ошибках (4xx, 5xx), что делает его безопасным для использования в скриптах с `set -e`.
    *   Опция `--debug` для получения максимально подробной информации о происходящем:
        ```bash
        wget --debug https://badssl.com/expired
        ```

*   **Загрузка файлов:**
    *   `-c`, `--continue`: продолжить оборванную загрузку с того места, где она прервалась. Это реализуется через заголовок HTTP `Range`.
        ```bash
        wget -c https://example.com/large-file.zip
        ```
    *   `-b`, `--background`: запустить `wget` в фоновом режиме.
    *   Поддержка цифровых подписей: `wget` может проверять цифровые подписи файлов, что полезно для загрузки дистрибутивов.
    *   Работа с Metalink: `wget` умеет извлекать адреса из Metalink-файлов и автоматически выбирать зеркала.

*   **Wget как API-клиент:**
    *   `--header='Header-Name: Header-Value'`: установка произвольных HTTP-заголовков.
    *   Передача данных формы: `wget` не имеет встроенной удобной опции для передачи параметров POST-запросов в виде формы (`application/x-www-form-urlencoded` или `multipart/form-data`), что делает его менее удобным для работы с некоторыми API по сравнению с `curl` или `HTTPie`. Данные приходится формировать вручную.
    *   Работа с куками:
        ```bash
        # Сохранить cookies, полученные от сервера
        wget --save-cookies cookies.txt http://example.com

        # Загрузить cookies из файла для отправки на сервер
        wget --load-cookies cookies.txt http://example.com
        ```
    *   Файл `.netrc`: для BASIC-аутентификации можно использовать файл `.netrc` в домашней директории пользователя. Однако он не поддерживает токены `Bearer`.

*   **Особые возможности:**
    *   Вывод в стандартный вывод: если в качестве файла вывода указать дефис (`-`), данные будут выведены на стандартный вывод.
    *   Скачивание файла с именем `-`: используйте `./-`.

### 2. cURL: Универсальный "швейцарский нож"

**cURL** (Client for URLs) — это чрезвычайно мощный и гибкий инструмент для передачи данных по множеству протоколов.

#### Ключевые особенности и опции

*   **Безопасность в скриптах:** В отличие от `wget`, `curl` по умолчанию **не** завершается с ошибкой при HTTP-статусах 4xx или 5xx. Для надежной работы в скриптах **всегда** используйте опцию `--fail`.
    ```bash
    # --fail (-f): завершиться с ошибкой (код 22) при HTTP-ошибках сервера
    # --show-error (-S): показывать ошибку, даже если используется -s (silent)
    curl -fsS http://httpbin.org/status/404
    ```
*   **Работа с API:**

    - `-X, --request`: указать метод запроса (GET, POST, PUT, DELETE).
    - `-H, --header`: добавить заголовок.
    - `-d, --data`: отправить данные (формат `application/x-www-form-urlencoded`).
    ```bash
    curl -X POST -H "Content-Type: application/json" -d '{"key":"value"}' http://httpbin.org/post
    ```
*   **Отправка файлов и форм:**
    - `-F, --form`: отправить данные в формате `multipart/form-data`.
    ```bash
    # -F, --form: отправить данные в формате multipart/form-data
    # @filename: прикрепить файл
    curl -F "user=John" -F "avatar=@/path/to/photo.jpg" http://httpbin.org/post

    # Отправка "сырых" бинарных данных
    # --data-binary @filename
    curl --data-binary @archive.zip http://httpbin.org/post
    ```
*   **Отладка:**

    Для более глубокого анализа сетевых проблем, включая детальное измерение времени ответа DNS, установки TCP-соединения и TLS-рукопожатия, см. отдельную заметку: [Диагностика сетевых задержек с curl](../../Diagnostics/Networking/curl_network_diagnostics.md).

    ```bash
    # -v, --verbose: показать подробную информацию о соединении и заголовках (менее детально, чем --trace)
    curl -v https://example.com
    ```
    Для максимально детального дампа обмена данными, включая TLS-информацию, используйте опцию `--trace <file>`.
    ```bash
    # --trace <file>: записать полный дамп обмена данными (включая бинарные и TLS) в файл
    curl --trace trace.log https://example.com
    ```

*   **Аутентификация и Cookies:** 

Помимо опций `--cookie` и `--cookie-jar` для работы с куками, `curl` также поддерживает файл `.netrc` для базовой аутентификации.

*   **Подмена User-Agent:** Можно легко подменить заголовок `User-Agent` с помощью опции `-A` или `--user-agent`.
    ```bash
    curl -A "MyCustomAgent/1.0" https://example.com
    ```

*   **Сохранение вывода в файл:** Для сохранения ответа сервера в файл используется опция `-o` (`--output`).
    ```bash
    curl -o hh.json "https://api.hh.ru/vacancies?text=сетевой%20инженер"
    ```

*   **Работа с JSON и `jq`**: `curl` отлично работает в связке с утилитой `jq` для форматирования и обработки JSON-ответов.
    ```bash
    curl "https://api.hh.ru/vacancies?text=сетевой%20инженер" | jq .
    ```

#### Определение публичного IP-адреса

`curl` может быть использован для быстрого определения вашего публичного IP-адреса, используя сторонние сервисы. Опция `-s` (`--silent`) подавляет вывод прогресса и ошибок `curl`, оставляя только сам IP-адрес.

**Примеры:**
```bash
curl -s ifconfig.me

curl 2ip.ru
```

### 3. HTTPie: Современный HTTP-клиент

**HTTPie** — это современный HTTP-клиент, созданный для удобства человека.

#### Ключевые особенности и синтаксис

*   **Интуитивный синтаксис:** Методы (`GET`, `POST`) указываются как подкоманды. Параметры запроса добавляются в виде пар `ключ==значение` для URL-параметров и `ключ=значение` для тела запроса. По умолчанию `HTTPie` отправляет данные тела запроса в формате JSON.
    ```bash
    # GET-запрос с URL-параметром
    # Эквивалентно curl "http://httpbin.org/get?name=John"
    http GET httpbin.org/get name==John

    # POST-запрос с JSON-телом (по умолчанию)
    # Эквивалентно curl -X POST -H "Content-Type: application/json" -d '{"name":"John"}' http://httpbin.org/post
    http POST httpbin.org/post name=John
    ```
    Для явного указания формата формы или multipart можно использовать опции `--form` или `--multipart`.

*   **Сессии:** `HTTPie` может автоматически сохранять и переиспользовать cookies, заголовки `Authorization` и другие данные между запросами в рамках одной сессии. Сессии могут быть именованными и сохраняться в домашней директории пользователя.
    ```bash
    # Создаем сессию с именем 'my_session' и логинимся
    http --session=my_session POST http://example.com/login user=test pass=123
    # Последующие запросы в этой сессии автоматически используют полученные cookies
    http --session=my_session GET http://example.com/profile
    ```

*   **Аутентификация:** Встроенная поддержка различных схем аутентификации, включая Basic, Digest и Bearer.
    ```bash
    # Basic аутентификация
    http -a user:password http://example.com/protected

    # Bearer токен
    http -A bearer -a YOUR_TOKEN_HERE http://example.com/api/resource
    ```

*   **Офлайн-режим:** Позволяет посмотреть, как будет выглядеть запрос, не отправляя его на сервер.
    ```bash
    # -o, --offline: не отправлять запрос, только показать его
    http --offline POST httpbin.org/post name=John
    ```

## Продвинутое использование и решение проблем

Этот раздел охватывает более сложные сценарии, методы отладки и сравнение инструментов.

### 1. Игнорирование ошибок SSL-сертификатов (`--insecure`, `-k`)

Иногда при работе с `curl` возникает ошибка, связанная с недействительным или отсутствующим SSL-сертификатом у целевого сайта.

Хотя пропуск проверки сертификата может быть полезен в целях разработки, важно понимать, что такие действия **повышают риск утечки данных**. Используйте этот метод только на доверенных ресурсах или в контролируемой среде.

Команда для игнорирования ошибок сертификата:

```bash
curl --insecure [URL]
```
или сокращенная версия:
```bash
curl -k [URL]
```
Эти параметры отключают проверку SSL-сертификата и позволяют подключаться даже к сайтам с проблемными или самоподписанными сертификатами.

**Пример использования:**

Допустим, вы выполняете запрос к сайту с недействительным сертификатом:
```bash
curl myawesomewebsite.com
```
Вы получите ошибку, например:
```
curl: (60) SSL: no alternative certificate subject name matches target host name 'myawesomewebsite.com'
```
Чтобы обойти проблему, выполните:
```bash
curl -k myawesomewebsite.com
```
Теперь запрос будет выполнен без проверки сертификата.

**Важное предупреждение:** Флаги `--insecure` и `-k` работают аналогично параметру `--no-check-certificate` в утилите `wget`. Всегда проверяйте, почему SSL-сертификат считается недействительным, и используйте параметр `-k` только в исключительных случаях.

### 2. Скрытые таймауты в cURL: Диагностика и Решения

Иногда при использовании `curl` в скриптах, CI/CD пайплайнах или на сервере, он может "повиснуть", не завершаясь и не выдавая ошибок. 

По умолчанию `curl` не устанавливает жесткий общий таймаут для всей операции. Если удалённый сервер принял TCP-соединение, но затем не отдает тело ответа (например, из-за медленного reverse proxy, фильтрации контента или отображения CAPTCHA), `curl` может бесконечно ожидать данные.

Эта проблема особенно опасна в автоматизированных системах: автотестах, healthcheck’ах и системах мониторинга, где поведение `curl` считается надежным индикатором доступности сервиса. Зависший `curl` может привести к ложноположительным результатам мониторинга или "зависанию" пайплайнов.

**Решения**

Для предотвращения подобных ситуаций и обеспечения предсказуемого поведения `curl` всегда следует задавать явные лимиты времени.

1.  **Общий таймаут для всей операции (`--max-time`)**

    Используйте опцию `--max-time`, чтобы ограничить максимальное время, которое `curl` будет ждать завершения всей операции (включая установление соединения, передачу данных и получение ответа).

    ```bash
    curl --max-time 10 https://example.com
    ```
    В этом примере `curl` завершится с ошибкой, если вся операция займет более 10 секунд.

2.  **Более тонкая настройка таймаутов**

    Для более гранулированного контроля над поведением `curl` можно использовать комбинацию следующих опций:

    ```bash
    curl --connect-timeout 5 --speed-time 10 --speed-limit 100 https://example.com
    ```

    *   `--connect-timeout <seconds>`: Устанавливает максимальное время (в секундах), которое `curl` будет ждать для установки TCP-соединения с хостом. Если соединение не устанавливается в течение этого времени, `curl` прерывает попытку.
        *   *Пример:* `--connect-timeout 5` — ждать установки соединения не более 5 секунд.

    *   `--speed-time <seconds>` и `--speed-limit <bytes>`: Эти две опции работают в паре. `curl` прервет операцию, если в течение `--speed-time` секунд средняя скорость передачи данных будет ниже `--speed-limit` байт в секунду.
        *   *Пример:* `--speed-time 10 --speed-limit 100` — если в течение 10 секунд скорость передачи упадет ниже 100 байт/сек, `curl` завершится. Это особенно полезно для обнаружения "зависших" соединений, когда данные поступают очень медленно или прекратили поступать вовсе.

**Рекомендации**

*   **Всегда задавайте явные лимиты:** Если `curl` запускается как часть healthcheck в контейнере, в CI/CD или любой автоматизированной системе, всегда задавайте явные лимиты времени.
*   **Учитывайте нестабильные сети:** Особенно актуально для нестабильных сетевых окружений, где DNS может работать, TCP-соединение устанавливается, но передача данных идет медленно или прерывается.
*   **Используйте `--fail`:** Для надежной работы в скриптах, помимо таймаутов, также рекомендуется использовать опцию `--fail` (или `-f`). Она заставит `curl` завершаться с ненулевым кодом выхода, если HTTP-статус ответа указывает на ошибку (4xx или 5xx).
    ```bash
    curl -f --max-time 10 https://example.com
    ```
