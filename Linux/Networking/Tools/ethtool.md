# ethtool: Диагностика и управление сетевыми адаптерами

## Определения

* **`ethtool`** — утилита командной строки для просмотра и изменения параметров физических сетевых интерфейсов (NIC), а также их диагностики.
* **Дуплекс** — режим передачи данных:
  * **Half-duplex** — передача или прием (по очереди).
  * **Full-duplex** — передача и прием одновременно.
* **Автосогласование (Auto-Negotiation)** — автоматический выбор наилучшего режима работы (скорость и дуплекс) между соединенными устройствами.
* **MTU (Maximum Transmission Unit)** — максимальный размер кадра.
* **RSS (Receive Side Scaling)** — аппаратная технология распределения пакетов по ядрам CPU (подробнее в [RSS, RPS, RFS](../Concepts/rss_rps_rfs.md)).
* **Checksum Offloading** — вычисление контрольных сумм пакетов переносится с CPU на NIC (подробнее в [Offloading](../Concepts/offloading.md)).

## Основные концепции

### Ключевые возможности

* **Просмотр и изменение параметров:** скорость, дуплекс, автосогласование, очереди.
* **Диагностика:** детальная статистика, самотесты, информация о драйвере.
* **Идентификация:** мигание светодиодного индикатора для физического обнаружения порта.

### Дуплексное несоответствие

Возникает при работе одного устройства в full-duplex, а другого в half-duplex. Причины:

* Отключение автосогласования на одном конце.
* Ручная установка несовместимых режимов.

**Последствия:** коллизии, потери пакетов, резкое падение производительности.

**Рекомендация:** всегда оставлять автосогласование включенным (`autoneg on`) на обоих концах.

### Кольцевые буферы (Ring Buffers)

Области памяти на сетевой карте для временного хранения входящих (RX) и исходящих (TX) пакетов. Недостаточный размер приводит к отбрасыванию пакетов (`dropped packets`) под нагрузкой.

### Interrupt Coalescing

Объединение прерываний для снижения нагрузки на CPU. Меньшие интервалы = меньше задержка, но больше прерываний.

### Оффлоуды (Offloads)

> Подробное описание в [Offloading](../Concepts/offloading.md).

* **GRO (Generic Receive Offload)** — укрупнение пакетов на уровне ядра.
* **LRO (Large Receive Offload)** — укрупнение пакетов аппаратно.
* **TSO (TCP Segmentation Offload)** — сегментация TCP аппаратно.
* **Checksum Offloading** — вычисление контрольных сумм аппаратно.
* **VLAN Offloading** — обработка VLAN-тегов аппаратно.

Отключение GRO/LRO снижает задержки для критичных по latency приложений.

## Практические сценарии

### Просмотр параметров и статистики

```bash
# Основные настройки (скорость, дуплекс, статус)
sudo ethtool enp0s3

# Детальная статистика (счетчики ошибок, дропов)
sudo ethtool -S enp0s3

# Информация о драйвере и прошивке
sudo ethtool -i enp0s3

# Проверка статуса оффлоудов
sudo ethtool -k enp0s3

# Краткий вывод только активных оффлоудов
sudo ethtool -k enp0s3 | grep "on"
```

### Изменение базовых параметров

```bash
# Принудительно установить 1000 Мбит/с, полный дуплекс
sudo ethtool -s enp0s3 speed 1000 duplex full autoneg off

# Вернуть автосогласование (рекомендуется)
sudo ethtool -s enp0s3 autoneg on
```

> Настройки сбрасываются после перезагрузки. Для сохранения используйте конфигурацию сети дистрибутива.

### Диагностика drops и overruns

Даже при стабильной сети пакеты могут теряться из-за переполнения кольцевых буферов (ring buffers) на NIC. Если очередь переполняется, пакеты сбрасываются, что приводит к ретрансмиссиям TCP, росту задержки и нагрузки на CPU.

Проверка статистики:

```bash
# Показать статистику ошибок и дропов на аппаратном уровне NIC
sudo ethtool -S eth0 | grep -E 'drop|overrun'

# Показать статистику потерь пакетов на уровне ядра
cat /proc/net/dev
```

Если наблюдаются повторяющиеся пики dropped packets или overruns, это обычно указывает на:

* Маленькие кольцевые буферы.
* Медленную обработку softirq.
* Steal time на виртуальной машине.

Для диагностики softirq:

```bash
# Проверить распределение нагрузки по softirq (Network Receive)
cat /proc/softirqs | grep NET_RX
```

### Настройка кольцевых буферов

```bash
# Проверить текущие и максимальные размеры
sudo ethtool -g enp0s3

# Установить максимальные размеры (пример: 4096)
sudo ethtool -G enp0s3 rx 4096 tx 4096
```

### Настройка коалесценции прерываний (Interrupt Coalescing)

```bash
# Проверить текущие настройки коалесценции прерываний
sudo ethtool -c eth0

# Установить минимальные интервалы для RX/TX (в микросекундах)
sudo ethtool -C eth0 rx-usecs 20 tx-usecs 20
```

* `rx-usecs` — максимальное время ожидания перед генерацией прерывания при приёме.
* `tx-usecs` — максимальное время ожидания перед генерацией прерывания при передаче.
* Меньшие значения = меньше задержка, но больше прерываний.

### Диагностика проблем с IRQ

```bash
# Проверить распределение прерываний по CPU
cat /proc/interrupts | grep eth0

# Проверить загрузку softirq по ядрам
cat /proc/softirqs | grep NET_RX

# Проверить статус irqbalance
systemctl status irqbalance

# Если irqbalance не активен — прерывания могут обрабатываться на одном CPU
# Это приводит к неравномерной нагрузке и потерям пакетов
```

**Решение:**

* Включить `irqbalance` для автоматического распределения
* Или вручную настроить affinity через `/proc/irq/<IRQ>/smp_affinity`

### Управление оффлоудами

> Подробное описание сценариев в [Offloading](../Concepts/offloading.md).

```bash
# Отключить GRO/LRO для снижения задержек (latency-критичные приложения)
sudo ethtool -K eth0 gro off lro off

# Отключить TSO для предсказуемой отправки пакетов
sudo ethtool -K eth0 tso off

# Включить обратно для максимальной пропускной способности
sudo ethtool -K eth0 gro on lro on tso on

# Проверить изменения
ethtool -k eth0 | grep -E "gro|lro|tso"
```

**Сценарии:**

* **Низкая латентность** (VoIP, HFT, онлайн-игры): отключить GRO/LRO/TSO
* **Высокая пропускная способность** (файловые серверы, CDN): включить все оффлоуды

### Идентификация порта и самотесты

```bash
# Заставить индикатор порта мигать в течение 15 секунд
sudo ethtool -p enp0s3 15

# Онлайн-тесты (не прерывают работу интерфейса в отличие от оффлайн тестов)
sudo ethtool -t enp0s3 online
```

### Управление многопоточной обработкой (RSS)

> Подробное описание технологий см. в [RSS, RPS, RFS](../Concepts/rss_rps_rfs.md).

```bash
# Показать текущее и максимальное количество очередей
ethtool -l enp0s3

# Установить количество комбинированных очередей (включает RSS)
sudo ethtool -L enp0s3 combined 8
```

### MTU и Jumbo Frames

```bash
# Установка MTU 9000 (требует поддержки всей сетью)
ip link set dev enp0s3 mtu 9000
```

**Требования:**

* Согласованность MTU по всему пути.
* Некорректный PMTU вызывает фрагментацию и ретрансмиссии.

## Дополнительная информация

### Сохранение настроек

Настройки `ethtool` сбрасываются после перезагрузки.

**RHEL/CentOS** (`/etc/sysconfig/network-scripts/ifcfg-enp0s3`):

```
ETHTOOL_OPTS="speed 1000 duplex full autoneg on"
```

**Debian/Ubuntu** (`/etc/network/interfaces`):

```
auto enp0s3
iface enp0s3 inet dhcp
    pre-up /sbin/ethtool -s $IFACE speed 1000 duplex full autoneg on
```

**systemd-networkd** (`/etc/systemd/network/10-eth.network`):

```ini
[Match]
Name=enp0s3

[Link]
Speed=1000
Duplex=full
AutoNegotiation=yes
```

### Типичные проблемы

| Проблема | Диагностика (`ethtool -S`) | Решение |
|----------|---------------------------|---------|
| Рост `rx_crc_errors` | Повреждение кадров | Проверить кабель, порт |
| Рост `collisions` | Дуплексное несоответствие | Включить автосогласование |
| `dropped` растет | Перегрузка буферов | Увеличить ring buffers |
