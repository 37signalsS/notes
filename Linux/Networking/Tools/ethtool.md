# ethtool: Диагностика и управление сетевыми адаптерами

## Определения

*   **`ethtool`** — это утилита командной строки для Linux, позволяющая просматривать и изменять параметры физических сетевых интерфейсов (сетевых карт), а также проводить их диагностику.

## Основные концепции

### Ключевые возможности

*   **Просмотр и изменение параметров:** Управление скоростью, дуплексом, автосогласованием, очередями и другими аппаратными возможностями.
*   **Диагностика:** Просмотр детальной статистики, запуск самотестов, получение информации о драйвере и прошивке.
*   **Идентификация:** Возможность заставить светодиодный индикатор сетевой карты мигать для физического обнаружения.

### Дуплекс и автосогласование

*   **Полудуплекс (Half-duplex)**: Устройство может либо отправлять, либо получать данные, но не одновременно.
*   **Полнодуплекс (Full-duplex)**: Передача и приём происходят одновременно, что значительно повышает эффективность.
*   **Автосогласование (Auto-Negotiation)**: Процесс, при котором два соединенных устройства автоматически выбирают наилучший общий режим работы (скорость и дуплекс).

**Дуплексное несоответствие (Duplex Mismatch)** — это серьезная проблема, возникающая, когда одно устройство на линии работает в полнодуплексном режиме, а другое — в полудуплексном. Это приводит к коллизиям, потерям пакетов и резкому падению производительности сети. Обычно происходит, когда на одном конце автосогласование включено, а на другом — принудительно выставлен режим. **Рекомендация:** всегда оставлять автосогласование включенным (`autoneg on`) на обоих концах соединения.

## Практические сценарии

### Просмотр параметров и статистики

```bash
# Показать основные настройки (скорость, дуплекс, статус соединения)
sudo ethtool enp0s3

# Показать детальную статистику (счетчики пакетов, ошибок, дропов)
# Рост счетчиков errors, dropped, rx_crc_errors или collisions указывает на проблемы.
sudo ethtool -S enp0s3

# Показать информацию о драйвере и прошивке
sudo ethtool -i enp0s3
```

### Изменение базовых параметров

```bash
# Пример: принудительно установить скорость 1000 Мбит/с и полный дуплекс
sudo ethtool -s enp0s3 speed 1000 duplex full autoneg off

# Вернуть автосогласование (рекомендуется)
sudo ethtool -s enp0s3 autoneg on
```

**Важно:** Настройки, сделанные через `ethtool`, сбрасываются после перезагрузки.

### 4. Тонкая настройка кольцевых буферов сетевых интерфейсов

*   **Проблема:** По умолчанию Linux может использовать заниженные размеры кольцевых буферов (ring buffers) для сетевых карт. Эти буферы — это небольшие области памяти на сетевой карте, которые используются для временного хранения входящих (RX) и исходящих (TX) пакетов перед их обработкой ядром или отправкой в сеть. Недостаточный размер буферов может привести к отбрасыванию пакетов (`dropped packets`) при высоких нагрузках, что снижает производительность сети и увеличивает задержки.

*   **Решение:** Увеличить размер кольцевых буферов до максимально поддерживаемого сетевой картой. Это позволяет сетевой карте обрабатывать больше пакетов без потерь и повышает отзывчивость сети при пиковых нагрузках.

*   **Как это сделать:**
    1.  **Проверить текущие и максимальные размеры буферов:**
        ```bash
        sudo ethtool -g <interface_name>
        # Например: sudo ethtool -g enp0s3
        ```
        В выводе вы увидите `RX:`, `TX:` и `Max:`.

    2.  **Установить новые размеры буферов (до максимальных):**
        ```bash
        sudo ethtool -G <interface_name> rx <N> tx <M>
        # Например, если Max: 4096, то:
        sudo ethtool -G enp0s3 rx 4096 tx 4096
        ```

*   **Выигрыш:** Повышение пропускной способности сети, снижение потерь пакетов и более плавная работа сетевых приложений при высоких нагрузках.

### 5. Настройка прерываний и оффлоудов для низкой латентности

#### Interrupt Coalescing (объединение прерываний)

Interrupt coalescing снижает нагрузку на CPU, но может добавлять задержку. Для низкой латентности уменьшайте интервалы:

```bash
# Установить минимальные интервалы для RX/TX (в микросекундах)
ethtool -C eth0 rx-usecs 20 tx-usecs 20
```

**Параметры:**
* `rx-usecs` — максимальное время ожидания перед генерацией прерывания при приёме
* `tx-usecs` — максимальное время ожидания перед генерацией прерывания при передаче
* Меньшие значения = меньше задержка, но больше прерываний

#### GRO/LRO (Generic/Large Receive Offload)

GRO/LRO укрупняют пакеты, повышая пропускную способность, но увеличивая задержку мелких запросов. Допустимо отключать для критичных L4/L7 путей:

```bash
# Отключение GRO и LRO для снижения задержек
ethtool -K eth0 gro off lro off
```

**Когда отключать:**
* Критичные по задержке приложения (трейдинг, игры)
* Микросервисы с малыми сообщениями
* Когда важнее latency, чем throughput

### 6. Просмотр статистики и диагностика

* **Детальная статистика:**

    ```bash
    # Ключ -S показывает счетчики пакетов, байтов, ошибок и дропов
    sudo ethtool -S enp0s3
    ```

    Рост счетчиков `errors`, `dropped`, `rx_crc_errors` или `collisions` указывает на аппаратные проблемы, проблемы с кабелем или дуплексное несоответствие.

* **Идентификация порта:**

    ```bash
    # Заставить индикатор порта мигать в течение 15 секунд
    sudo ethtool -p enp0s3 15
    ```

* **Запуск самотестов:**

    ```bash
    # Запустить онлайн-тесты (не прерывают работу интерфейса в отличие от оффлайн тестов)
    sudo ethtool -t enp0s3 online
    ```

    Результат покажет, прошел ли тест или были обнаружены ошибки.

### 7. Управление многопоточной обработкой (RSS)

`ethtool` позволяет настраивать количество очередей для **RSS (Receive Side Scaling)** — аппаратной технологии распределения пакетов по ядрам CPU.

```bash
# Показать текущее и максимальное количество очередей
ethtool -l enp0s3

# Установить количество комбинированных очередей (включает RSS)
sudo ethtool -L enp0s3 combined 8
```

> Подробное описание технологий **RSS, RPS и RFS** и их программной настройки находится в документе [**RSS, RPS, RFS: Многопоточная обработка сетевого трафика**](../Concepts/rss_rps_rfs.md).

### 8. MTU и Jumbo Frames

* **MTU (Maximum Transmission Unit)** — максимальный размер кадра
* **Jumbo frames** — кадры размером более 1500 байт (обычно 9000 байт)

**Преимущества jumbo frames:**
* Уменьшают накладные расходы и сериализацию при больших сообщениях
* Снижают нагрузку на CPU

**Требования:**
* Согласованность MTU по всему пути
* Некорректный PMTU вызывает фрагментацию и ретрансмиссии

```bash
# Установка MTU 9000 (требует поддержки всей сетью)
ip link set dev enp0s3 mtu 9000
```

## Дополнительная информация

### 1. Информация о драйвере и прошивке

Эта информация полезна при отладке проблем совместимости или поиске обновлений.

```bash
# Ключ -i показывает имя драйвера, его версию и версию прошивки
sudo ethtool -i enp0s3
```

**Пример вывода:**

```
driver: e1000e
version: 3.2.6-k
firmware-version: 0.13-3
bus-info: 0000:00:03.0
```

### Сохранение настроек

Настройки, сделанные через `ethtool`, сбрасываются после перезагрузки. Для их сохранения используйте конфигурационные файлы сетей вашего дистрибутива.

* **Для RHEL/CentOS (файлы `ifcfg-*`)**:
    Отредактируйте `/etc/sysconfig/network-scripts/ifcfg-enp0s3` и добавьте:

    ```
    ETHTOOL_OPTS="speed 1000 duplex full autoneg on"
    ```

* **Для Debian/Ubuntu (`/etc/network/interfaces`)**:
    Добавьте команду в описание интерфейса:

    ```
    auto enp0s3
    iface enp0s3 inet dhcp
        pre-up /sbin/ethtool -s $IFACE speed 1000 duplex full autoneg on
    ```

* **Для systemd-networkd**:
    В файле `.network` (например, `/etc/systemd/network/10-eth.network`) добавьте секцию `[Link]`:

    ```ini
    [Match]
    Name=enp0s3

    [Link]
    Speed=1000
    Duplex=full
    AutoNegotiation=yes
    ```
*   **Для RHEL/CentOS** (файлы `ifcfg-*`):
    В `/etc/sysconfig/network-scripts/ifcfg-enp0s3` добавьте:
    `ETHTOOL_OPTS="speed 1000 duplex full autoneg on"`

*   **Для Debian/Ubuntu** (`/etc/network/interfaces`):
    Добавьте команду в описание интерфейса: `pre-up /sbin/ethtool -s $IFACE speed 1000 duplex full autoneg on`

> Подробнее о настройке см. в [Постоянная настройка сети в Linux](../Settings/persistent_network_configuration.md).
