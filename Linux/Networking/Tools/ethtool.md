# ethtool: Диагностика и управление сетевыми адаптерами

## Определения

* **`ethtool`** — утилита командной строки для просмотра и изменения параметров физических сетевых интерфейсов (NIC), а также их диагностики.
* **Дуплекс (Duplex)** — режим передачи данных:
  * **Half-duplex** — передача или прием (по очереди).
  * **Full-duplex** — передача и прием одновременно.
* **Автосогласование (Auto-Negotiation)** — автоматический выбор наилучшего режима работы (скорость и дуплекс) между соединенными устройствами.
* **FEC (Forward Error Correction)** — алгоритм упреждающего исправления ошибок, критически важный для стабильности линков на скоростях 25G, 100G и выше.
* **Flow Control (Pause Frames)** — механизм управления потоком (IEEE 802.3x), позволяющий сетевой карте просить соседа приостановить передачу при переполнении внутренних буферов.
* **Netlink ethtool** — современный интерфейс взаимодействия утилиты с ядром (заменяет старый `ioctl`), обеспечивающий детальные сообщения об ошибках и поддержку JSON-вывода.
* **MTU (Maximum Transmission Unit)** — максимальный размер полезного блока данных в одном кадре.
* **RSS (Receive Side Scaling)** — аппаратная технология распределения пакетов по очередям и ядрам CPU (подробнее в [RSS, RPS, RFS](../Concepts/rss_rps_rfs.md)).
* **Разгрузка контрольных сумм (Checksum Offloading)** — перенос вычисления контрольных сумм пакетов с CPU на сетевую карту (подробнее в [Offloading](../Concepts/offloading.md)).
* **Jumbo Frames** — кадры с полезной нагрузкой до 9000 байт (против стандартных 1500). Требуют согласования MTU на всех участках линка (NIC, коммутатор, маршрутизатор).
* **NAPI (New API)** — механизм ядра Linux для обработки пакетов методом опроса (polling) вместо прерываний при высокой нагрузке. Позволяет NIC генерировать одно прерывание на пачку пакетов, а не на каждый пакет.

## Основные концепции

### Архитектура и современные возможности

Современные версии `ethtool` (v6.x+) активно используют Netlink для общения с ядром. Это дает несколько ключевых преимуществ:
1.  **JSON-вывод**: Флаг `--json` позволяет получать структурированные данные, удобные для автоматизации и мониторинга.
2.  **Режим мониторинга**: Команда `ethtool --monitor` позволяет отслеживать изменения состояния интерфейсов (link up/down, изменение параметров) в реальном времени.
3.  **Детальные ошибки**: Netlink возвращает расширенные сообщения (Extended ACK), объясняющие причину отказа в применении настройки.

### FEC (Forward Error Correction)

На сверхвысоких скоростях (25/100/400 Гбит/с) физический уровень подвержен высокому уровню шума. FEC позволяет исправлять битовые ошибки без повторной передачи кадров.
*   **RS (Reed-Solomon)**: Стандарт для 100G+ линков.
*   **BaseR (Firecode)**: Облегченный вариант для 25G.
*   **LLRS (Low Latency RS)**: Современный стандарт для минимизации задержек.

**Почему FEC критичен**: На скоростях 25G и выше битовая ошибка без FEC означает потерю всего кадра. FEC позволяет восстановить поврежденные биты математически, снижая BER (Bit Error Rate) с ~10⁻⁴ до ~10⁻¹². При некорректной работе FEC (оптика, кабель) счетчик `fec_uncorrectable_errors` растет — это прямой индикатор физической проблемы.

### Управление потоком (Flow Control)

Механизм предотвращает потерю пакетов (drops) при кратковременных перегрузках.
*   **RX Pause**: Сетевая карта слушает пауза-кадры от соседа и приостанавливает отправку.
*   **TX Pause**: Сетевая карта отправляет пауза-кадры соседу, когда ее приемные буферы заполнены.
*   **Важно**: В высокопроизводительных сетях с преобладанием TCP часто рекомендуют отключать TX Pause на серверах, чтобы избежать блокировки всей фабрики сети (Head-of-Line Blocking).

### Кольцевые буферы (Ring Buffers)

Кольцевые буферы — это аппаратные очереди в памяти NIC, через которые DMA-движок карты записывает принятые пакеты (RX) или считывает отправляемые (TX).

**Архитектура взаимодействия:**
1.  **DMA → Ring Buffer**: DMA-движок NIC записывает пакеты в кольцевой буфер по мере их поступления от физического уровня.
2.  **Ring Buffer → Ядро**: Механизм NAPI опрашивает буфер и забирает пакеты пачками (budget), передавая их в сетевой стек.
3.  **Потеря при переполнении**: Если ядро не успевает забирать пакеты (высокая нагрузка или малый буфер), DMA не может записать новый пакет — NIC отбрасывает его. Это отражается в счетчиках `rx_missed_errors` или `rx_fifo_errors`.

**Размер буферов**: Недостаточный размер ведет к `rx_missed_errors` или `dropped` при всплесках трафика. Рекомендуется увеличивать до максимума на серверах с высокой нагрузкой.

*   **TCP Data Split**: Функция (параметр `tcp-data-split` в `-G`), позволяющая аппаратно разделять заголовки TCP и данные в разные буферы для повышения эффективности кэша CPU.

### Объединение прерываний (Interrupt Coalescing)

Механизм накопления пакетов перед генерацией прерывания для CPU. Без коалесценции NIC генерирует прерывание на каждый пакет, что при 10G+ скорости создает непомерную нагрузку на CPU.
*   **Адаптивная коалесценция**: NIC динамически меняет интервалы прерываний в зависимости от интенсивности трафика. При низкой нагрузке — короткие интервалы (низкая задержка), при высокой — длинные (меньше прерываний).
*   **Ручная настройка**: Позволяет жестко задать задержку (usecs) для предсказуемости в задачах с низкой задержкой (HFT, Real-time).

**Взаимодействие с NAPI**: При превышении порога нагрузки ядро переключает NIC в режим NAPI (polling). Коалесценция работает на уровне прерываний, а NAPI — на уровне обработки. Оба механизма дополняют друг друга.

### Параметры разгрузки (Offloads)

> Подробное описание концепций в [Offloading](../Concepts/offloading.md).

* **GRO (Generic Receive Offload)** — программное укрупнение пакетов в ядре. Объединяет сегменты одного TCP-потока в один большой SKB перед обработкой в стеке. Снижает количество операций аллокации и обработки.
* **TSO (TCP Segmentation Offload)** — аппаратная нарезка крупных TCP-блоков (до 64 КБ) на стандартные сегменты (MTU). NIC получает большой пакет от ядра и сам разбивает его, вычисляя контрольные суммы.
* **LRO (Large Receive Offload)** — аппаратная агрегация пакетов в NIC. Устарел из-за проблем с маршрутизацией (теряются оригинальные заголовки). Заменен на GRO.
* **GSO (Generic Segmentation Offload)** — программный аналог TSO. Ядро выполняет сегментацию в последний момент, если NIC не поддерживает TSO.

**Практическое замечание**: При диагностике через `tcpdump` отключайте TSO (`ethtool -K eth0 tso off`), иначе пакеты отображаются в неразделанном виде (60 КБ+ вместо 1500 Б). Аналогично — GRO при анализе входящих потерь.

### Автосогласование (Auto-Negotiation)

Процесс автоматического согласования скорости и дуплекса между двумя устройствами. Определяется стандартом IEEE 802.3u.

**Порядок приоритетов**: 100G > 40G > 25G > 10G > 1G > 100M. Full Duplex всегда предпочтительнее Half Duplex.

**Duplex Mismatch** — классическая проблема, когда одно устройство настроено вручную (Full), а другое в Auto (падает в Half). Результат — колоссальное количество коллизий и CRC-ошибок. **Рекомендация**: всегда использовать Auto на обоих концах линка.

### MTU и Jumbo Frames

**MTU** определяет максимальный размер полезной нагрузки кадра. Стандартное значение — 1500 байт (Ethernet).

**Jumbo Frames** (MTU 9000) снижают накладные расходы на обработку пакетов за счет уменьшения их количества. Требования:
*   Все устройства на линке (NIC, коммутатор, маршрутизатор) должны поддерживать одинаковый MTU.
*   Несоответствие MTU приводит к тому, что крупные пакеты отбрасываются с ICMP Fragmentation Needed (Type 3, Code 4) или молча дропаются.

**Диагностика MTU**:
```bash
# Проверка MTU через ping (DF bit)
ping -M do -s 1472 <ip>    # 1472 + 28 (IP+ICMP заголовки) = 1500 → OK
ping -M do -s 8972 <ip>    # 8972 + 28 = 9000 → OK для Jumbo
```

## Практические сценарии

### Просмотр параметров и статистики

```bash
# Основные настройки (скорость, дуплекс, наличие линка)
sudo ethtool eth0

# Вывод в формате JSON (для скриптов)
sudo ethtool --json eth0

# Детальная статистика (счетчики ошибок, дропов, коллизий)
sudo ethtool -S eth0

# Информация о драйвере, версии прошивки и шине PCI
sudo ethtool -i eth0

# Мониторинг изменений состояния в реальном времени
sudo ethtool --monitor eth0
```

### Изменение физических параметров (Speed/Lanes)

```bash
# Установить 1000 Мбит/с, полный дуплекс и выключить автосогласование
sudo ethtool -s eth0 speed 1000 duplex full autoneg off

# Настройка количества физических линий (lanes) для 100G/400G+
sudo ethtool -s eth0 lanes 4

# Вернуть автосогласование (рекомендуемый режим)
sudo ethtool -s eth0 autoneg on
```

### Управление FEC (Forward Error Correction)

```bash
# Просмотр поддерживаемых и текущих режимов FEC
sudo ethtool --show-fec eth0

# Принудительная установка режима Reed-Solomon
sudo ethtool --set-fec eth0 encoding rs
```

### Настройка Flow Control (Pause Frames)

```bash
# Просмотр текущих настроек паузы
sudo ethtool -a eth0

# Отключить отправку пауза-кадров (TX), оставить прием (RX)
sudo ethtool -A eth0 tx off rx on
```

### Тюнинг буферов и производительности

```bash
# Проверить текущие и максимальные размеры Ring Buffers
sudo ethtool -g eth0

# Увеличить RX буфер до максимума (например, 4096)
sudo ethtool -G eth0 rx 4096

# Увеличить и RX, и TX буферы
sudo ethtool -G eth0 rx 4096 tx 4096

# Включить разделение данных TCP (на поддерживаемом железе)
sudo ethtool -G eth0 tcp-data-split on
```

### Работа с SFP и оптическими модулями

```bash
# Чтение диагностических данных (DOM) трансивера
# Показывает вендора, серийный номер, уровни сигнала (TX/RX Power) и температуру
sudo ethtool -m eth0

# Пример вывода:
#       Temperature:              35.00°C
#       Voltage:                  3.31 V
#       Bias Current:             7.50 mA
#       TX Power:                 -2.34 dBm
#       RX Power:                 -3.12 dBm
```

**Нормальные диапазоны для оптики:**
| Параметр | Норма | Действие при отклонении |
| :--- | :--- | :--- |
| RX Power | -18...-3 dBm | Низкий — грязный разъем, поврежденное волокно |
| TX Power | Зависит от класса SFP | Снижение — деградация лазера |
| Temperature | 0...70 C | Перегрев — вентиляция |
| Bias Current | Зависит от типа | Резкий рост — скорая деградация |

### Настройка очередей (RSS) и прерываний

```bash
# Показать количество очередей и их распределение
ethtool -l eth0

# Установить комбинированные очереди (обычно по числу ядер CPU)
sudo ethtool -L eth0 combined 8

# Включить адаптивную коалесценцию прерываний
sudo ethtool -C eth0 adaptive-rx on adaptive-tx on

# Ручная настройка коалесценции (для low-latency сценариев)
sudo ethtool -C eth0 rx-usecs 3 tx-usecs 3
```

### Управление оффлоудами

```bash
# Просмотр статуса всех ускорений
sudo ethtool -k eth0

# Отключить TSO для корректной диагностики через tcpdump
sudo ethtool -K eth0 tso off

# Включить GRO (по умолчанию включен)
sudo ethtool -K eth0 gro on

# Отключить GRO при диагностике потерь
sudo ethtool -K eth0 gro off
```

### Поддержка PTP и аппаратных таймстампов

Для высокоточной синхронизации времени (PTP) важно знать возможности сетевой карты.

```bash
# Просмотр возможностей таймстампинга (Hardware/Software)
sudo ethtool -T eth0
```

### Энергосбережение (EEE)

Energy Efficient Ethernet (IEEE 802.3az) снижает потребление энергии при низком трафике, но может вызывать задержки при "пробуждении" линка.

```bash
# Просмотр статуса EEE
sudo ethtool --show-eee eth0

# Отключение EEE (рекомендуется для минимизации задержек или при флапах порта)
sudo ethtool --set-eee eth0 eee off
```

**Когда отключать EEE:**
*   Серверы с высокой нагрузкой — EEE бесполезен и добавляет jitter.
*   Интерфейс периодически падает (flap) — некорректная реализация EEE на NIC/коммутаторе.
*   Требуется минимальная задержка (HFT, real-time).

### Идентификация и тестирование

```bash
# Заставить индикатор порта мигать 15 секунд (поиск кабеля в стойке)
sudo ethtool -p eth0 15

# Запуск самотестирования (может кратковременно прервать связь!)
sudo ethtool -t eth0 online
```

### Диагностика auto-negotiation и duplex mismatch

```bash
# 1. Проверить текущие параметры
sudo ethtool eth0 | grep -E "Speed|Duplex|Auto-negotiation|Link detected"

# 2. Если link detected: no — проблема на физическом уровне
#    Если speed не совпадает с ожидаемой — проблема согласования
#    Если duplex: Half на 1G+ — возможен mismatch

# 3. Исправление: вернуть auto-negotiation на обоих концах
sudo ethtool -s eth0 autoneg on

# 4. Или принудительно задать (если auto не работает):
sudo ethtool -s eth0 speed 10000 duplex full autoneg off
```

### Диагностика link flap

Flap (периодическое падение линка) — одна из самых неприятных проблем в сети.

```bash
# 1. Мониторинг состояния линка в реальном времени
ip monitor link

# 2. Проверка логов ядра
dmesg -T | grep -i "link\|carrier\|nic\|eth0"

# 3. Проверка ошибок NIC
ethtool -S eth0 | grep -E "error|drop|crc|miss|fec"

# 4. Проверка EEE (частая причина flap)
sudo ethtool --show-eee eth0

# 5. Проверка Temperature (перегрев NIC)
sudo ethtool -m eth0 | grep -i temp

# Типичные причины flap:
# - Поврежденный кабель или разболтанный коннектор
# - Неисправный SFP-модуль
# - EEE на несовместимом оборудовании
# - Перегрев NIC
# - Проблемы с питанием NIC
```

### Автоматизация и скрипты

```bash
# Сбор полной информации о NIC для анализа
#!/bin/bash
IFACE="${1:-eth0}"
echo "=== NIC Diagnostics: $IFACE ==="
echo "--- Basic Info ---"
sudo ethtool $IFACE
echo "--- Driver ---"
sudo ethtool -i $IFACE
echo "--- Ring Buffers ---"
sudo ethtool -g $IFACE
echo "--- Offloads ---"
sudo ethtool -k $IFACE
echo "--- Error Counters ---"
sudo ethtool -S $IFACE 2>/dev/null | grep -iE "error|drop|miss|crc|fec|collision"
echo "--- SFP DOM ---"
sudo ethtool -m $IFACE 2>/dev/null || echo "  No SFP DOM available"

# Автоматическое увеличение ring buffer при обнаружении дропов
#!/bin/bash
IFACE="eth0"
DROPS=$(sudo ethtool -S $IFACE 2>/dev/null | grep -E "rx_missed_errors|rx_fifo_errors" | awk '{sum+=$2} END {print sum}')
if [ "$DROPS" -gt 0 ]; then
    echo "Drops detected ($DROPS). Increasing ring buffer..."
    sudo ethtool -G $IFACE rx 4096 tx 4096
fi

# Мониторинг ошибок через watch
watch -n 1 'ethtool -S eth0 | grep -E "error|drop|crc|missed"'
```

### Сохранение настроек при перезагрузке

#### systemd-networkd (Современный стандарт)

Настройки задаются в `.link` файлах в каталоге `/etc/systemd/network/`.

```ini
# /etc/systemd/network/10-eth0.link
[Match]
OriginalName=eth0

[Link]
ReceiveRingBuffer=4096
TransmitRingBuffer=4096
TCPSegmentationOffload=no
GenericReceiveOffload=yes
# Настройка очередей (RSS)
Channels=8
```

#### Netplan (Ubuntu)

```yaml
network:
  version: 2
  ethernets:
    eth0:
      ethtool:
        ring:
          rx: 4096
          tx: 4096
        coalesce:
          adaptive-rx: true
```

#### NetworkManager (RHEL/CentOS)

```bash
# Через nmcli (настройки сохраняются в профиле соединения)
nmcli connection modify eth0 ethtool.rx-frames 4096 ethtool.tx-frames 4096
```

#### Legacy (/etc/network/interfaces)

```bash
iface eth0 inet static
    pre-up /sbin/ethtool -G eth0 rx 4096
```

## Справочник счетчиков ошибок (ethtool -S)

Понимание счетчиков ошибок NIC — ключ к быстрой диагностике физических проблем.

| Счетчик | Что означает | Типичная причина | Решение |
| :--- | :--- | :--- | :--- |
| `rx_crc_errors` | Ошибка контрольной суммы кадра | Поврежденный кабель, SFP, патч-панель, ЭМИ | Заменить кабель/SFP |
| `rx_missed_errors` | NIC не успел передать пакет в Ring Buffer | Переполнение буфера, высокая нагрузка | Увеличить Ring Buffers (`-G`) |
| `rx_fifo_errors` | Переполнение FIFO-буфера NIC | NIC перегружена, нет flow control | Увеличить ring buffer, проверить flow control |
| `tx_fifo_errors` | Переполнение TX FIFO | NIC не успевает отправлять | Проверить link speed, flow control |
| `rx_length_errors` | Некорректная длина кадра | Коллизии (half-duplex), битые фреймы | Проверить дуплекс, заменить кабель |
| `rx_frame_errors` | Ошибка выравнивания (alignment) | Физическая проблема | Заменить кабель/SFP |
| `collisions` | Коллизии | Half-duplex режим на 1G+ | Включить Full Duplex |
| `rx_pause_frames` | Входящие пауза-кадры | Коммутатор перегружен | Проверить коммутатор, настроить PFC |
| `tx_pause_frames` | Исходящие пауза-кадры | NIC отправила паузу соседу | Нормально для RX flow control |
| `fec_uncorrectable_errors` | FEC не смог исправить ошибки | Плохой сигнал (оптика, кабель) | Проверить оптику, уровень сигнала |
| `rx_words` / `tx_words` | Принято/отправлено слов (64-бит) | Информационный счетчик | Для расчета throughput |
| `rx_broadcast` / `tx_broadcast` | Broadcast пакеты | Широковещательный шторм | Проверить STP, loop |

## Типичные проблемы

| Проблема | Диагностика (`ethtool -S`) | Решение |
| :--- | :--- | :--- |
| Ошибки `rx_crc_errors` | Рост счетчика CRC | Заменить кабель, SFP или патч-панель |
| Ошибки `collisions` | Рост коллизий на 1G+ | Проверить дуплекс (должен быть full) |
| Рост `rx_missed_errors` | Перегрузка буферов NIC | Увеличить Ring Buffers (`-G`) |
| Входящие пауза-кадры | `rx_pause_frames` > 0 | Сосед (коммутатор) перегружен и просит подождать |
| Ошибки FEC | `fec_uncorrectable_errors` | Плохой сигнал на 25G/100G+, проверить оптику |
| Высокий jitter | Агрессивная коалесценция | Настроить `adaptive-rx` или уменьшить `rx-usecs` |
| Потери при <1% нагрузки | `rx_missed_errors` растет | Увеличить ring buffer, включить GRO |
| Link flap | `dmesg` — `link up/down` | Проверить кабель, SFP, EEE, температуру |
| MTU не применяется | Нет ошибок, но large packets падают | Проверить MTU на всех участках линка |

## Зависимости от драйверов NIC

Реализация `ethtool` зависит от драйвера. Не все опции доступны на всех картах.

| Драйвер | Поддерживаемые NIC | Особенности |
| :--- | :--- | :--- |
| **ixgbe** | Intel 82599/X520/X540/X550 (10G) | Полная поддержка RSS, FEC, Flow Control, PTP |
| **i40e** | Intel XL710/X710 (40G) | Поддержка FEC,advanced RSS, VXLAN offload |
| **ice** | Intel E810 (25/50/100G) | Поддержка LLRS, CyberSecurity, advanced FEC |
| **mlx5_core** | Mellanox ConnectX-5/6/7 (25-400G) | SR-IOV, DCQCN, RoCE, аппаратный hash |
| **bnxt_en** | Broadcom NetXtreme (10/25/100G) | Низкое энергопотребление, FEC |
| **tg3** | Broadcom Tigon3 (1G) | Минимальный набор опций |
| **e1000e** | Intel PRO/1000 (1G) | Базовая поддержка, высокая надежность |

**Проверка драйвера:**
```bash
ethtool -i eth0 | grep driver
# → driver: ixgbe
```
