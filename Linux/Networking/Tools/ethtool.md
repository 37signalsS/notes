# ethtool: Диагностика и управление сетевыми адаптерами

## Определения

* **`ethtool`** — утилита командной строки для просмотра и изменения параметров физических сетевых интерфейсов (NIC), а также их диагностики.
* **Дуплекс (Duplex)** — режим передачи данных:
  * **Half-duplex** — передача или прием (по очереди).
  * **Full-duplex** — передача и прием одновременно.
* **Автосогласование (Auto-Negotiation)** — автоматический выбор наилучшего режима работы (скорость и дуплекс) между соединенными устройствами.
* **MTU (Maximum Transmission Unit)** — максимальный размер полезного блока данных в одном кадре.
* **RSS (Receive Side Scaling)** — аппаратная технология распределения пакетов по очередям и ядрам CPU (подробнее в [RSS, RPS, RFS](../Concepts/rss_rps_rfs.md)).
* **Разгрузка контрольных сумм (Checksum Offloading)** — перенос вычисления контрольных сумм пакетов с CPU на сетевую карту (подробнее в [Offloading](../Concepts/offloading.md)).

## Основные концепции

### Ключевые возможности

* **Просмотр и изменение параметров:** скорость, дуплекс, автосогласование, количество очередей.
* **Диагностика:** детальная статистика (счетчики ошибок), самотесты железа, информация о драйвере и прошивке.
* **Идентификация:** физическое обнаружение порта (мигание светодиода).
* **Мониторинг SFP:** чтение параметров оптических модулей (температура, мощность сигнала).

### Дуплексное несоответствие (Duplex Mismatch)

Возникает при работе одного устройства в full-duplex, а другого в half-duplex.

**Причины:**
* Отключение автосогласования на одном конце при включенном на другом.
* Ручная установка несовместимых режимов.

**Последствия:** коллизии, огромные потери пакетов, резкое падение производительности.
**Рекомендация:** всегда оставлять автосогласование включенным (`autoneg on`) на обоих концах линка.

### Кольцевые буферы (Ring Buffers)

Области памяти на сетевой карте для временного хранения входящих (RX) и исходящих (TX) пакетов. Недостаточный размер приводит к отбрасыванию пакетов (`dropped packets`) при резких всплесках трафика.

### Объединение прерываний (Interrupt Coalescing)

Механизм накопления пакетов перед генерацией прерывания для CPU.
* **Меньшие интервалы:** ниже задержка (latency), но выше нагрузка на CPU (больше прерываний).
* **Большие интервалы:** выше пропускная способность, но растет задержка.

### Параметры разгрузки (Offloads)

> Подробное описание концепций в [Offloading](../Concepts/offloading.md).

* **GRO (Generic Receive Offload)** — программное укрупнение пакетов в ядре.
* **LRO (Large Receive Offload)** — аппаратное укрупнение пакетов на NIC.
* **TSO (TCP Segmentation Offload)** — аппаратная нарезка крупных TCP-блоков.
* **GSO (Generic Segmentation Offload)** — программный аналог TSO.

**Важно:** включенные оффлоуды (TSO/GRO) могут искажать вывод `tcpdump`, показывая пакеты размером более 1500 байт (до 64 КБ), что является нормой для внутренней обработки ядра, но не для физической сети.

## Практические сценарии

### Просмотр параметров и статистики

```bash
# Основные настройки (скорость, дуплекс, линк)
sudo ethtool eth0

# Детальная статистика (счетчики ошибок, дропов, коллизий)
sudo ethtool -S eth0

# Информация о драйвере, версии прошивки (firmware) и шине PCI
sudo ethtool -i eth0

# Показать перманентный (зашитый) MAC-адрес устройства
ethtool -P eth0

# Проверка статуса оффлоудов (ускорений)
sudo ethtool -k eth0
```

### Изменение базовых параметров

```bash
# Принудительно установить 1000 Мбит/с, полный дуплекс и выключить автосогласование
sudo ethtool -s eth0 speed 1000 duplex full autoneg off

# Вернуть автосогласование (рекомендуемый режим)
sudo ethtool -s eth0 autoneg on
```

### Диагностика потерь и переполнений (drops/overruns)

Если наблюдаются потери при отсутствии физических ошибок в `ethtool -S`, проверьте кольцевые буферы.

```bash
# Проверить текущие и максимально возможные размеры буферов
sudo ethtool -g eth0

# Увеличить RX буфер до максимума (например, 4096)
sudo ethtool -G eth0 rx 4096
```

### Работа с SFP и оптическими модулями

Утилита позволяет считывать диагностические данные (DOM) напрямую из трансивера.

```bash
# Чтение информации из EEPROM модуля (SFP/QSFP)
# Показывает вендора, серийный номер и уровни сигнала (RX/TX Power)
sudo ethtool -m eth0
```

### Настройка коалесценции прерываний

```bash
# Проверить текущие таймеры прерываний
sudo ethtool -c eth0

# Установить адаптивную коалесценцию (NIC сам подстраивается под нагрузку)
sudo ethtool -C eth0 adaptive-rx on adaptive-tx on

# Ручная установка задержки (в микросекундах)
sudo ethtool -C eth0 rx-usecs 20 tx-usecs 20
```

### Управление многопоточной обработкой (RSS)

Распределение трафика по очередям для параллельной обработки разными ядрами CPU.

```bash
# Показать количество очередей
ethtool -l eth0

# Установить 8 комбинированных очередей
sudo ethtool -L eth0 combined 8

# Просмотр таблицы косвенности (indirection table) RSS
ethtool -x eth0
```

### Управление оффлоудами

```bash
# Отключить GRO/LRO для минимизации задержек (HFT, Gaming, VoIP)
sudo ethtool -K eth0 gro off lro off

# Отключить TSO для корректной диагностики через tcpdump
sudo ethtool -K eth0 tso off
```

### Идентификация порта и тесты

```bash
# Заставить индикатор порта мигать 15 секунд (для поиска кабеля в стойке)
sudo ethtool -p eth0 15

# Запуск самотестирования (может кратковременно прервать связь!)
sudo ethtool -t eth0 online
```

### Энергосбережение (EEE)

```bash
# Просмотр статуса Energy Efficient Ethernet (IEEE 802.3az)
sudo ethtool --show-eee eth0
```

## Дополнительная информация

### Сохранение настроек при перезагрузке

Настройки `ethtool` по умолчанию не сохраняются.

**Ubuntu/Debian (Netplan):**
В новых версиях параметры можно передать в `transmit-hash-policy` или использовать `command` в `networkd-dispatcher`. Напрямую в Netplan поддержка `ethtool` ограничена:
```yaml
network:
  version: 2
  ethernets:
    eth0:
      receive-checksum-offload: false
```

**Ubuntu/Debian (Legacy `/etc/network/interfaces`):**
```bash
iface eth0 inet static
    pre-up /sbin/ethtool -G eth0 rx 4096
```

**RHEL/CentOS (NetworkManager):**
```bash
# Через nmcli (современный способ)
nmcli connection modify eth0 ethtool.rx-frames 4096 ethtool.tx-frames 4096

# Через ifcfg-файл (устаревший)
ETHTOOL_OPTS="speed 1000 duplex full autoneg on"
```

### Типичные проблемы

| Проблема | Диагностика (`ethtool -S`) | Решение |
| :--- | :--- | :--- |
| Ошибки `rx_crc_errors` | Рост счетчика CRC | Заменить кабель или патч-панель |
| Ошибки `collisions` | Рост коллизий | Проверить дуплекс (должен быть full) |
| Рост `rx_missed_errors` | Перегрузка буферов | Увеличить Ring Buffers (`-G`) |
| Низкая скорость при 1G+ | `Speed: 100Mb/s` | Проверить кабель (нужно 4 пары для 1G) |
