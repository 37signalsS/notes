# Оптимизация буферов TCP в Linux

## Определения

* **TCP (Transmission Control Protocol — протокол управления передачей) буферы** — области оперативной памяти ядра, выделяемые для временного хранения входящих (`rmem`) и исходящих (`wmem`) данных сетевых соединений.
* **Автотюнинг TCP** — встроенный в ядро Linux механизм, который динамически адаптирует размер буфера для каждого соединения в пределах заданных границ на основе текущей нагрузки и сетевых характеристик.
* **BDP (Bandwidth-Delay Product — произведение пропускной способности на задержку)** — физический объем данных, который может находиться в сетевом канале «в полете». Рассчитывается как произведение пропускной способности линка на **RTT (Round-Trip Time — время кругового обхода)**.

## Базовые концепции

### Иерархия параметров настройки

В Linux настройка буферов разделена на два уровня:

1. **Глобальный уровень (`net.core.*`)**: Устанавливает жесткие лимиты для всех типов сокетов (TCP, UDP, Unix sockets).
   * `net.core.rmem_max` — абсолютный максимум для буфера приема.
   * `net.core.wmem_max` — абсолютный максимум для буфера отправки.

2. **Уровень протокола (`net.ipv4.tcp_*`)**: Специфичные настройки для TCP, работающие в рамках глобальных лимитов.
   * `net.ipv4.tcp_rmem` — параметры буфера приема.
   * `net.ipv4.tcp_wmem` — параметры буфера отправки.

### Формат параметров tcp_rmem и tcp_wmem

Каждая директива принимает три целочисленных значения (в байтах): `min default max`.

| Значение | Описание | Типичное использование |
| :--- | :--- | :--- |
| **min** | Минимальный размер | Гарантированный объем памяти даже при сильной нехватке ресурсов. |
| **default** | Начальный размер | Используется при установлении соединения (Handshake). |
| **max** | Максимальный размер | Верхняя граница, до которой автотюнинг может расширять буфер. |

### Связь с Window Scaling

Размер буфера напрямую ограничивает размер окна приема. Для эффективного использования буферов более 64 КБ должно быть включено масштабирование окна (**Window Scaling**, **RFC 7323**). В Linux оно включено по умолчанию (`net.ipv4.tcp_window_scaling = 1`).

## Практические сценарии

### 1. Расчет оптимального размера буфера

Для полной утилизации канала размер буфера должен быть не меньше **BDP**.

**Пример расчета:**

* Канал: 1 Гбит/с (~125 МБ/с).
* RTT: 50 мс (0.05 с).
* **BDP** = 125 МБ/с × 0.05 с = **6.25 МБ**.

Следовательно, значение `max` в `tcp_rmem` и `tcp_wmem` должно быть как минимум 6.25 МБ (6 553 600 байт).

### 2. Применение настроек через sysctl

**Временное применение (до перезагрузки):**

```bash
sudo sysctl -w net.core.rmem_max=16777216
sudo sysctl -w net.core.wmem_max=16777216
sudo sysctl -w net.ipv4.tcp_rmem='4096 87380 16777216'
sudo sysctl -w net.ipv4.tcp_wmem='4096 65536 16777216'
```

**Постоянное сохранение (`/etc/sysctl.d/99-network.conf`):**

```ini
# Максимальный размер буферов 16 МБ
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
# min, default, max
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216
```

Применить: `sudo sysctl -p /etc/sysctl.d/99-network.conf`

### 3. Диагностика и мониторинг

Утилита `ss` позволяет просмотреть текущее состояние буферов активных соединений.

```bash
# Просмотр параметров памяти (rcv_space, snd_buf)
ss -tno state established

# Поиск соединений с переполненным буфером (Zero Window)
ss -tnio | grep 'win:0'
```

Если значение `rcv_space` постоянно упирается в установленный `max`, это признак необходимости увеличения буферов.

## Дополнительная информация

### Риски избыточной буферизации

Чрезмерное увеличение буферов может привести к проблеме **Bufferbloat (Раздувание буфера)** — резкому росту задержек из-за того, что пакеты долго стоят в очередях. Для борьбы с этим рекомендуется использовать современные дисциплины очередей, такие как `fq_codel` или `BBR`.

### Рекомендации по выбору значений (max)

| Сценарий | Значение | Обоснование |
| :--- | :--- | :--- |
| **Обычный сервер** | 4–8 МБ | Достаточно для большинства современных линков. |
| **Высокопроизводительный узел** | 16–32 МБ | Для 10 Гбит/с и выше. |
| **Геораспределенные системы** | 64 МБ+ | Для компенсации высокого RTT (межконтинентальные линки). |
