# Управление состоянием TIME_WAIT и ephemeral портами

> **SSoT:** полная информация по управлению TIME_WAIT и ephemeral портами — в [Оптимизация TCP в Linux](./tcp_congestion_algorithms.md)

## Определения

**TIME_WAIT** — состояние TCP-соединения после закрытия для обеспечения надежной доставки последних пакетов и предотвращения проблем с новыми соединениями.

## Проблематика

На серверах с большим количеством короткоживущих **исходящих** соединений (API-клиенты, сервисы с всплесками нагрузки) скапливается много сокетов в состоянии `TIME_WAIT`, занимая эфемерные порты. Ядро не может выделить новые порты для `connect()`, что приводит к блокировкам или ошибкам `Cannot assign requested address`.

## Диагностика

```bash
# Проверка текущего диапазона ephemeral портов
cat /proc/sys/net/ipv4/ip_local_port_range

# Общая статистика сокетов
ss -s

# Количество соединений в TIME_WAIT
ss -tan 'state time-wait' | wc -l
```

Если количество соединений в `TIME_WAIT` близко к размеру диапазона портов, новые исходящие соединения начинают ждать или падать.

## Настройка параметров

```bash
# Разрешить повторное использование сокетов TIME_WAIT (исходящие соединения)
sudo sysctl -w net.ipv4.tcp_tw_reuse=1

# Уменьшить время нахождения сокета в состоянии FIN-WAIT-2
sudo sysctl -w net.ipv4.tcp_fin_timeout=30

# Расширить диапазон эфемерных портов
sudo sysctl -w net.ipv4.ip_local_port_range="1024 65535"
```

> **Важно:** `net.ipv4.tcp_tw_recycle` удален в ядре 4.12+ из-за проблем с NAT. **Не использовать.**
