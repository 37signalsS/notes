# TCP Fast Open (TFO): Ускорение установки соединений

## Определения

**TCP Fast Open (TFO — быстрое открытие TCP)** — расширение протокола TCP (RFC 7413), позволяющее передавать данные прикладного уровня (например, HTTP-запрос) непосредственно в пакете SYN. Это исключает один цикл приема-передачи (RTT) при установке соединения, что критично для производительности веб-сервисов и микросервисов.

**TFO Cookie** — криптографический токен, генерируемый сервером для проверки IP-адреса клиента. Он защищает от атак с подменой адреса (IP Spoofing) и SYN-флуда, гарантируя, что клиент ранее уже успешно устанавливал соединение.

**RTT (Round-Trip Time)** — время, необходимое для прохождения сигнала от отправителя к получателю и обратно.

## Основные концепции

### Алгоритм работы

1.  **Первое соединение (Handshake):**
    - Клиент отправляет SYN с опцией запроса TFO Cookie.
    - Сервер отвечает SYN-ACK, содержащим Cookie.
    - Соединение устанавливается обычным образом.
2.  **Последующие соединения:**
    - Клиент отправляет SYN, содержащий сохраненный Cookie и данные (Payload).
    - Сервер проверяет Cookie. Если он валиден, сервер немедленно передает данные приложению, не дожидаясь ACK от клиента.
    - Сервер отправляет SYN-ACK, подтверждая прием данных.

**Экономия:** Время до получения первого байта ответа сокращается с **1.5 RTT** до **0.5 RTT**.

### Настройка через параметры ядра (sysctl)

Параметр `net.ipv4.tcp_fastopen` управляет поведением TFO через битовую маску:

| Бит | Значение | Режим | Описание |
| :--- | :--- | :--- | :--- |
| `0x1` | 1 | Клиент | Разрешить отправку данных в SYN (Client-side TFO). |
| `0x2` | 2 | Сервер | Разрешить прием данных в SYN (Server-side TFO). |
| `0x4` | 4 | Клиент (unsafe) | Отправлять данные в SYN без Cookie (риск спуфинга). |
| `0x200` | 512 | Сервер (unsafe) | Принимать данные в SYN без Cookie. |
| `0x400` | 1024 | Сервер (auto) | **(Kernel 4.11+)** Включать TFO для всех слушающих сокетов без модификации кода приложения. |

**Рекомендуемое значение для 2026 года:** `1027` (Клиент + Сервер + Авто-включение для всех сокетов).

### Защита от Blackhole (Middleboxes)

Сетевое оборудование (брандмауэры, NAT) часто дропает пакеты SYN с данными, считая их аномальными. Для борьбы с этим в Linux реализован механизм **TFO Blackhole**:
*   Если SYN с данными не получает ответа, ядро переходит к обычному рукопожатию.
*   `net.ipv4.tcp_fastopen_blackhole_timeout_sec` — определяет время (в секундах), на которое ядро отключает TFO для конкретного направления после обнаружения «черной дыры».

### Безопасность и атаки повтора

Главный риск TFO — **атаки повторного воспроизведения (Replay Attacks)**. Злоумышленник может перехватить SYN с данными (например, "купить товар") и отправить его повторно.
*   **Решение:** TFO должен использоваться **только для идемпотентных запросов** (HTTP GET, HEAD), которые не изменяют состояние сервера. Для критических операций (POST/PUT) требуется защита на уровне приложения.

## Практические сценарии

### 1. Системная конфигурация

```bash
# Включение TFO (Client + Server + Auto)
sudo sysctl -w net.ipv4.tcp_fastopen=1027

# Установка статического ключа (необязательно, рекомендуется ротация)
# Если не задано, ключ генерируется при загрузке
echo "deadbeefdeadbeefdeadbeefdeadbeef" | sudo tee /proc/sys/net/ipv4/tcp_fastopen_key
```

### 2. Поддержка в прикладном ПО и языках

*   **Nginx (1.5.8+):**
    ```nginx
    listen 443 ssl fastopen=256; # 256 — размер очереди TFO
    ```
*   **Python (3.7+):**
    ```python
    import socket
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.setsockopt(socket.IPPROTO_TCP, socket.TCP_FASTOPEN, 5)
    ```
*   **Go:** Требует использования `Control` функции в `net.Dialer` или сторонних библиотек для установки `TCP_FASTOPEN_CONNECT`.

### 3. Диагностика и мониторинг

Для анализа эффективности TFO используются счетчики `nstat`:

```bash
# Просмотр статистики TFO
nstat -az | grep -i FastOpen

# Ключевые метрики:
# TcpExtTCPFastOpenActive       — Успешные исходящие TFO (клиент)
# TcpExtTCPFastOpenPassive      — Успешные входящие TFO (сервер)
# TcpExtTCPFastOpenCookieCheck  — Количество проверок Cookie
# TcpExtTCPFastOpenBlackhole    — Количество обнаруженных Blackholes
```

Проверка конкретного соединения через `ss`:
```bash
ss -ti state established | grep tfo
# Результат "tfo:1" означает, что соединение использовало TFO.
```

## Дополнительная информация

### Сравнение с TLS 1.3 и QUIC

| Характеристика | TCP Fast Open | TLS 1.3 0-RTT | QUIC (HTTP/3) |
| :--- | :--- | :--- | :--- |
| **Уровень** | L4 (TCP) | L6/L7 (TLS) | L4 (UDP) |
| **Защита данных** | Открытый текст в SYN | Зашифровано | Зашифровано |
| **Проблема Replay** | Да | Да | Да |
| **Совместимость** | Средняя (Middleboxes) | Высокая | Высокая |
