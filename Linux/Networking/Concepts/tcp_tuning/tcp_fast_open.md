# TCP Fast Open (TFO)

## Определения

**TCP Fast Open (TFO)** — расширение TCP (RFC 7413), позволяющее начать передачу данных уже во время установления соединения, не дожидаясь завершения полного трёхстороннего рукопожатия. Экономия — 1 RTT на каждое соединение.

## Basic Concepts

### Сравнение handshake

**Классический TCP (3 RTT до данных):**

```
Клиент                          Сервер
  |  SYN ----------------------> |
  |  <------------------- SYN-ACK |
  |  ACK + данные -------------> |  ← данные только после handshake
```

**TCP Fast Open (1 RTT до данных):**

```
Клиент                          Сервер
  |  SYN + данные -------------> |  ← данные в первом пакете
  |  (TFO cookie + payload)      |
  |  <------------------- SYN-ACK |
  |  ACK ----------------------> |
```

### TFO Cookie

Для безопасности TFO использует криптографические cookies:

1. **Первое соединение:** клиент запрашивает cookie → сервер генерирует (на основе IP, порта, секрета) и возвращает в SYN-ACK → клиент сохраняет.
2. **Повторное соединение:** клиент отправляет SYN с cookie и данными → сервер проверяет → при валидности обрабатывает данные немедленно.

**Время жизни cookie:** определяется сроком действия ключа (`tcp_fastopen_key`). Явно настраиваемого таймера нет — cookie валидны до ротации ключа. Резервный ключ обеспечивает плавную ротацию без инвалидации активных cookie.

### Параметр `net.ipv4.tcp_fastopen` (битовая маска)

| Бит | Значение | Режим | Описание |
| :--- | :--- | :--- | :--- |
| `0x1` | 1 | Клиент | Отправлять данные в SYN при наличии cookie |
| `0x2` | 2 | Сервер | Принимать данные в SYN до завершения handshake |
| `0x4` | 4 | Клиент (без cookie) | Отправлять данные в SYN без проверки cookie |
| `0x200` | 512 | Сервер (без cookie) | Принимать данные в SYN при отсутствии cookie |
| `0x400` | 1024 | Сервер (auto) | Auto-enable для всех слушающих сокетов |

**По умолчанию:** `0x1` (клиент включён), сервер (`0x2`) — выключен.

**Рекомендуемое значение (клиент + сервер):**

```bash
sysctl -w net.ipv4.tcp_fastopen=3
```

## Practical Scenarios

### Проверка текущего состояния

```bash
# Текущее значение
sysctl net.ipv4.tcp_fastopen

# Через procfs
cat /proc/sys/net/ipv4/tcp_fastopen
```

### Включение TFO

**Временно:**

```bash
# Клиент и сервер
sudo sysctl -w net.ipv4.tcp_fastopen=3
```

**Постоянно** (`/etc/sysctl.d/99-network.conf`):

```ini
net.ipv4.tcp_fastopen = 3
```

Применение: `sudo sysctl -p /etc/sysctl.d/99-network.conf`

### Требования на уровне приложения

TFO требует явной поддержки приложением — недостаточно только включить sysctl.

| Приложение | Директива/Флаг | Версия |
| :--- | :--- | :--- |
| **nginx** | `fastopen=N` (в listen) | 1.13.0+ |
| **HAProxy** | `tcp-fastopen` (в frontend) | 1.8+ |
| **curl** | `--tcp-fastopen` | 7.49.0+ |
| **PostgreSQL** | Авто (при поддержке ОС) | 14+ |
| **MySQL** | Нет | (2026) |

**Пример nginx:**

```nginx
listen 443 ssl fastopen=256;
```

**Программный интерфейс (Linux):**

- Клиент: `sendmsg()` с флагом `MSG_FASTOPEN`
- Сервер: `recvmsg()` для получения данных до `accept()`

### Диагностика

```bash
# Статистика TFO (ядро 4.10+)
nstat -az | grep -i tfo
# TcpExtTCPFastOpenActive     — успешные TFO-соединения (клиент)
# TcpExtTCPFastOpenPassive    — успешные TFO-соединения (сервер)
# TcpExtTCPFastOpenCookieReq  — запрошены cookie
# TcpExtTCPFastOpenCookieSent — отправлены cookie
# TcpExtTCPFastOpenBlackhole  — отброены middlebox (SYN с данными)
```

**Интерпретация:**

- `TcpExtTCPFastOpenBlackhole` растёт → файрволы/NAT отбрасывают SYN с данными → отключить TFO.
- `Active`/`Passive` нулевые → приложение не использует TFO или не настроено.

### Ограничения и риски

- **Middlebox:** некоторые файрволы и NAT отбрасывают пакеты SYN с данными.
- **Первый запрос:** всегда требует полного handshake (для получения cookie).
- **HTTP/2 и длительные соединения:** эффект менее заметен — TFO оптимизирует установление, а не передачу.
- **Наиболее эффективен:** HTTP/1.1, API-вызовы, короткие соединения с множеством reconnect.
