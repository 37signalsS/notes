# TCP Fast Open (TFO): Ускорение установки соединений

## Определения

* **TCP Fast Open (TFO — быстрое открытие TCP)** — расширение протокола **TCP (Transmission Control Protocol — протокол управления передачей)**, описанное в **RFC (Request for Comments — рабочий запрос предложений) 7413**. Оно позволяет начать передачу данных прикладного уровня уже во время установления соединения (в первом пакете), не дожидаясь завершения полного трехстороннего рукопожатия.
* **Handshake (Рукопожатие)** — процесс установления связи между клиентом и сервером.
* **RTT (Round-Trip Time — время кругового обхода)** — время, необходимое для прохождения сигнала от отправителя к получателю и обратно.

## Базовые концепции

### Сравнение механизмов установки соединения

**Классический TCP (Данные передаются только после завершения рукопожатия):**

1. Клиент отправляет **SYN (Synchronize — синхронизация)**.
2. Сервер отвечает **SYN-ACK (Synchronize-Acknowledgment — синхронизация и подтверждение)**.
3. Клиент отправляет **ACK (Acknowledgment — подтверждение)** вместе с первыми данными.
*Итог:* Полезные данные достигают сервера через 1.5 RTT после начала процесса.

**TCP Fast Open (Данные передаются в первом пакете):**

1. Клиент отправляет пакет **SYN**, содержащий **TFO Cookie** и полезную нагрузку (данные).
2. Сервер проверяет Cookie и, если они валидны, немедленно передает данные приложению.
3. Сервер отвечает пакетом **SYN-ACK**, подтверждая получение данных.
*Итог:* Экономия 1 RTT на каждое соединение.

### Механизм TFO Cookie

Для защиты от атак типа «отказ в обслуживании» (**DoS — Denial of Service**) TFO использует криптографические куки:

1. **Первое соединение:** Клиент запрашивает Cookie в обычном SYN-пакете. Сервер генерирует их на основе IP-адреса клиента и своего секретного ключа, возвращая в SYN-ACK.
2. **Повторные соединения:** Клиент использует сохраненные Cookie для мгновенной отправки данных.

Срок жизни Cookie определяется временем ротации ключа `tcp_fastopen_key` в ядре. Использование резервного ключа обеспечивает плавную смену параметров без разрыва активных сессий.

### Параметр ядра net.ipv4.tcp_fastopen

Настройка осуществляется через битовую маску:

| Бит | Значение | Режим | Описание |
| :--- | :--- | :--- | :--- |
| `0x1` | 1 | Клиент | Разрешить отправку данных в SYN-пакете при наличии Cookie |
| `0x2` | 2 | Сервер | Разрешить прием данных в SYN-пакете до завершения рукопожатия |
| `0x4` | 4 | Клиент (unsafe) | Отправлять данные в SYN-пакете без проверки Cookie |
| `0x200` | 512 | Сервер (unsafe) | Принимать данные в SYN-пакете при отсутствии Cookie |
| `0x400` | 1024 | Сервер (auto) | Автоматическое включение для всех слушающих сокетов |

**Рекомендуемое значение:** `3` (клиент + сервер включены).

## Практические сценарии

### 1. Включение TFO на уровне системы

**Временное включение:**

```bash
sudo sysctl -w net.ipv4.tcp_fastopen=3
```

**Постоянное включение (через конфигурационные файлы sysctl):**

```ini
# /etc/sysctl.d/99-network.conf
net.ipv4.tcp_fastopen = 3
```

Применить изменения: `sudo sysctl -p /etc/sysctl.d/99-network.conf`

### 2. Настройка прикладного ПО

Включение TFO в ядре недостаточно — приложение должно явно поддерживать этот механизм.

* **Nginx:** `listen 443 ssl fastopen=256;` (в блоке `server`).
* **HAProxy:** параметр `tcp-fastopen` в секции `bind`.
* **Curl:** флаг `--tcp-fastopen`.

### 3. Диагностика и мониторинг

Для проверки эффективности TFO используется статистика сетевого стека:

```bash
nstat -az | grep -i tfo
```

Ключевые счетчики:

* **TcpExtTCPFastOpenActive:** Успешные исходящие соединения (клиент).
* **TcpExtTCPFastOpenPassive:** Успешные входящие соединения (сервер).
* **TcpExtTCPFastOpenBlackhole:** Количество отброшенных пакетов SYN с данными. Если этот счетчик быстро растет, значит промежуточное оборудование (**Middleboxes**) блокирует TFO-трафик.

## Дополнительная информация

### Ограничения и риски

* **Middleboxes:** Некоторые старые межсетевые экраны и **NAT (Network Address Translation — трансляция сетевых адресов)** могут отбрасывать SYN-пакеты, содержащие данные, считая их аномалией.
* **Идемпотентность:** TFO следует использовать только для идемпотентных запросов (например, **HTTP GET**), так как в случае сетевых сбоев пакет SYN с данными может быть доставлен повторно.
* **Эффективность:** Наибольший выигрыш TFO дает для коротких соединений, типичных для **API (Application Programming Interface)** и загрузки множества мелких ресурсов с **CDN (Content Delivery Network)**.
