# TCP Fast Open (TFO): Ускорение установки соединений

## Определения

* **TCP Fast Open (TFO — быстрое открытие TCP)** — расширение протокола **TCP (Transmission Control Protocol — протокол управления передачей)**, описанное в **RFC 7413**. Оно позволяет начать передачу данных прикладного уровня (например, HTTP-запрос) уже в первом пакете **SYN**, не дожидаясь завершения трехстороннего рукопожатия.
* **TFO Cookie** — криптографический токен, выдаваемый сервером клиенту при первом соединении. Он служит доказательством того, что клиент владеет своим IP-адресом, и защищает сервер от атак типа SYN-флуд с подменой адреса.
* **RTT (Round-Trip Time — время кругового обхода)** — время, необходимое для прохождения сигнала от отправителя к получателю и обратно.

## Базовые концепции

### Сравнение механизмов установки соединения

**Классический TCP (Данные после рукопожатия):**

1. Клиент → **SYN** (установка связи).
2. Сервер → **SYN-ACK** (подтверждение).
3. Клиент → **ACK** + **Данные** (подтверждение + первый запрос).
*Итог:* Данные прикладного уровня достигают сервера через **1.5 RTT**.

**TCP Fast Open (Данные в первом пакете):**

1. Клиент → **SYN** + **TFO Cookie** + **Данные**.
2. Сервер проверяет Cookie и немедленно передает данные приложению.
3. Сервер → **SYN-ACK** (подтверждение приема данных и соединения).
*Итог:* Данные достигают сервера через **0.5 RTT**. Экономия составляет **1 RTT**.

### Параметр ядра net.ipv4.tcp_fastopen

Настройка осуществляется через битовую маску в `sysctl`:

| Бит | Значение | Режим | Описание |
| :--- | :--- | :--- | :--- |
| `0x1` | 1 | Клиент | Разрешить отправку данных в SYN-пакете. |
| `0x2` | 2 | Сервер | Разрешить прием данных в SYN-пакете. |
| `0x4` | 4 | Клиент (unsafe) | Отправлять данные в SYN без проверки Cookie (риск спуфинга). |
| `0x200` | 512 | Сервер (unsafe) | Принимать данные в SYN без Cookie. |
| `0x400` | 1024 | Сервер (auto) | **(Kernel 4.11+)** Автоматическое включение TFO для всех слушающих сокетов без модификации кода приложения. |

**Рекомендуемое значение для 2026 года:** `3` (безопасный клиент и сервер) или `1027` (клиент + сервер + авто-включение).

### TFO vs TLS 1.3 vs QUIC

В современном стеке (2026) TFO часто рассматривается в сравнении с другими механизмами минимизации задержек:

| Характеристика | TCP Fast Open | TLS 1.3 0-RTT | QUIC (HTTP/3) |
| :--- | :--- | :--- | :--- |
| **Уровень OSI** | L4 (Транспортный) | L6/L7 (Безопасность) | L4/L7 (Интегрированный) |
| **Защита данных** | Данные в SYN **не шифруются** | Данные в 0-RTT **зашифрованы** | Полное шифрование |
| **Совместимость** | Низкая (Middleboxes часто дропают) | Высокая | Высокая (UDP) |
| **Основная ниша** | Внутренние API, микросервисы | Публичный HTTPS | Современный веб (стандарт) |

## Практические сценарии

### 1. Включение и настройка системы

**Постоянная конфигурация:**

```ini
# /etc/sysctl.d/99-tfo.conf
# Включение TFO для клиента и сервера
net.ipv4.tcp_fastopen = 3

# Ротация секретного ключа (рекомендуется обновлять раз в сутки)
# Если не задано, ядро генерирует ключ автоматически при загрузке
# net.ipv4.tcp_fastopen_key = <32-значный hex>
```

Применить: `sudo sysctl -p /etc/sysctl.d/99-tfo.conf`

### 2. Настройка прикладного ПО

Даже если в ядре установлен бит `0x400`, явная настройка в приложении обеспечивает лучший контроль.

*   **Nginx:**
    ```nginx
    server {
        listen 443 ssl fastopen=256; # 256 — размер очереди TFO-запросов
    }
    ```
*   **HAProxy:**
    ```haproxy
    bind *:443 ssl crt cert.pem tfo
    ```

### 3. Диагностика и мониторинг

Проверка счетчиков эффективности:

```bash
# Использование nstat для просмотра статистики TFO
nstat -az | grep -i tfo

# TcpExtTCPFastOpenActive — успешные исходящие TFO (клиент)
# TcpExtTCPFastOpenPassive — успешные входящие TFO (сервер)
# TcpExtTCPFastOpenCookieCheck — количество проверок Cookie
# TcpExtTCPFastOpenBlackhole — КРИТИЧНО: сколько SYN с данными было отброшено
```

Проверка конкретного сокета через `ss`:

```bash
# Просмотр параметров TFO для установленных соединений
ss -ti state established | grep -E "tfo|mss"
# → tfo:1 (означает, что TFO использовался)
```

## Дополнительная информация

### Риски и ограничения (Важно для 2026 года)

1.  **Атаки повторного воспроизведения (Replay Attacks):** Пакет SYN с данными может быть перехвачен и отправлен повторно.
    *   **Правило:** Используйте TFO **только для идемпотентных запросов** (например, HTTP GET). Никогда не используйте для POST/PUT, если на уровне приложения нет защиты от дубликатов.
2.  **Проблема Middleboxes:** Многие корпоративные файрволы и старые NAT-устройства считают SYN-пакет с данными аномалией и отбрасывают его. Это приводит к задержкам (таймаут и повторная отправка обычного SYN).
3.  **Приватность:** TFO Cookie привязан к IP-адресу и может использоваться для пассивного отслеживания перемещений пользователя между сетями. Из-за этого TFO отключен по умолчанию во многих современных браузерах.

### Резюме: когда использовать TFO?

*   **ДА:** Внутренние сети ЦОД, взаимодействие между микросервисами, высоконагруженные API мобильных приложений (при контроле обоих концов).
*   **НЕТ:** Публичный веб-трафик (лучше использовать HTTP/3 и TLS 1.3 0-RTT).
