# TCP Fast Open (TFO)

## Определения

**TCP Fast Open (TFO)** — расширение TCP (RFC 7413), позволяющее начать передачу данных уже во время установления соединения, не дожидаясь завершения полного трёхстороннего рукопожатия (three-way handshake).

## Принцип работы

### Классический TCP handshake (3 RTT)

```
Клиент                          Сервер
  |  SYN ----------------------> |
  |  (только флаг)               |
  |  <---------------------- SYN-ACK |
  |                              |
  |  ACK + данные -------------> |  ← данные только после handshake
  |                              |
```

### TCP Fast Open (1 RTT)

```
Клиент                          Сервер
  |  SYN + данные -------------> |  ← данные в первом пакете
  |  (TFO cookie + payload)      |
  |  <---------------------- SYN-ACK |
  |                              |
  |  ACK ----------------------> |
  |  (соединение установлено)    |
```

## TFO Cookie

Для безопасности TFO использует **cookies**:

### Процесс обмена cookie

1. **Первое соединение (без данных):**
   - Клиент отправляет SYN с опцией TFO (запрос cookie)
   - Сервер генерирует cookie (на основе IP, порта, секрета) и возвращает в SYN-ACK
   - Клиент сохраняет cookie для будущих соединений

2. **Повторное соединение (с данными):**
   - Клиент отправляет SYN с cookie и данными
   - Сервер проверяет cookie
   - Если валиден — обрабатывает данные немедленно

**Время жизни cookie:** 24 часа (настраивается в ядре).

## Настройка параметра `net.ipv4.tcp_fastopen`

| Значение | Режим | Описание |
| :--- | :--- | :--- |
| **0** | Выключено | TFO отключен |
| **1** | Только клиент | Отправлять данные в SYN, если сервер поддерживает |
| **2** | Только сервер | Принимать данные в SYN, если клиент отправил |
| **3** | Клиент + сервер | Полная поддержка (рекомендуется) |

```bash
# Включить полную поддержку TFO
sysctl -w net.ipv4.tcp_fastopen=3

# Постоянная настройка (/etc/sysctl.conf)
net.ipv4.tcp_fastopen = 3
```

## Требования для работы TFO

### На клиенте

- Ядро Linux 3.13+ (поддержка `tcp_fastopen`)
- Приложение должно использовать `sendmsg()` с флагом `MSG_FASTOPEN`

### На сервере

- Ядро Linux 3.13+
- Приложение должно вызывать `recvmsg()` для получения данных до `accept()`

### Поддержка приложениями

| Приложение | Поддержка | Версия |
| :--- | :--- | :--- |
| **nginx** | Да | 1.13.0+ (`fastopen on`) |
| **HAProxy** | Да | (`tcp-fastopen`) |
| **curl** | Да | (`--tcp-fastopen`) |
| **PostgreSQL** | Да | |
| **MySQL** | Нет | (2026) |

## Преимущества и ограничения

### Преимущества

- Сокращение задержки на 1 RTT (критично для мобильных сетей)
- Ускорение загрузки веб-страниц (особенно с множеством коротких соединений)
- Снижение нагрузки на сервер (меньше обработок handshake)

### Ограничения

- Требует поддержки на обеих сторонах
- Некоторые middlebox (файрволы, NAT) могут отбрасывать пакеты с данными в SYN
- Первый запрос к серверу всё ещё требует полного handshake (для получения cookie)

## Диагностика

```bash
# Проверка поддержки TFO в ядре
cat /proc/sys/net/ipv4/tcp_fastopen

# Проверка TFO в действии (tcpdump)
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0'

# Статистика TFO (ядро 4.10+)
nstat -az | grep -i tfo
# TcpExtTCPFastOpenActive — активные соединения с TFO
# TcpExtTCPFastOpenPassive — пассивные соединения с TFO
# TcpExtTCPFastOpenCookieSent — отправлено cookie
```

> **Примечание:** TFO наиболее эффективен для сценариев с множеством коротких соединений (HTTP/1.1, API-вызовы). Для HTTP/2 и длительных соединений эффект менее заметен.
