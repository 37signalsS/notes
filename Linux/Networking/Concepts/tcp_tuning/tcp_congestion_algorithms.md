# Алгоритмы управления перегрузкой TCP в Linux

Для изучения теоретических основ, формул и подробного сравнения алгоритмов (CUBIC, BBR, Reno) используйте основной справочник: **[Алгоритмы управления перегрузкой TCP](../../../../Networking/Protocols/TCP/congestion/tcp_congestion_algorithms.md)**.

## Определения

* **Алгоритм управления перегрузкой (Congestion Control Algorithm)** — логика ядра Linux, определяющая скорость отправки данных в зависимости от состояния сети.
* **Pacing (Сглаживание)** — механизм равномерного распределения пакетов во времени для предотвращения всплесков трафика (bursts), которые могут вызвать потери на промежуточном оборудовании.
* **BBR (Bottleneck Bandwidth and Round-trip time)** — современный алгоритм от Google, использующий модель пропускной способности и задержки вместо простой реакции на потери пакетов.

## Основные концепции

### Взаимодействие с дисциплинами очередей (qdisc)

Эффективность алгоритма в Linux напрямую зависит от выбранной дисциплины очереди.

* **BBR + `fq`**: Настоятельно рекомендуется использовать BBR совместно с дисциплиной **`fq` (Fair Queueing)**. Именно `fq` обеспечивает точный **Pacing**, необходимый для корректной работы BBR.
* **CUBIC + `fq_codel`**: Хорошо сочетается с **`fq_codel`** или **`cake`** для борьбы с проблемой **Bufferbloat** (раздувание буфера) на клиентских устройствах и домашних роутерах.

Подробнее о настройке очередей: [Дисциплины очередей TCP](./tcp_queueing_disciplines.md).

### Версионность и поддержка

* **CUBIC**: Алгоритм по умолчанию в большинстве дистрибутивов Linux. Стабилен и предсказуем.
* **BBR v1**: Внедрен в ядро Linux 4.9+.
* **BBR v3**: Доступен в экспериментальных ядрах и современных дистрибутивах (Fedora, Ubuntu HWE) с 2024-2025 гг. Обладает улучшенной «справедливостью» (fairness) по отношению к CUBIC-потокам.

## Практические сценарии

### Проверка состояния системы

```bash
# Список доступных алгоритмов, загруженных в ядро
sysctl net.ipv4.tcp_available_congestion_control
# → net.ipv4.tcp_available_congestion_control = cubic reno bbr

# Текущий алгоритм по умолчанию
sysctl net.ipv4.tcp_congestion_control

# Просмотр алгоритма и метрик для активных соединений
ss -ti
```

### Включение BBR (рекомендуется для Highload)

Для включения BBR необходимо ядро версии 4.9 или выше.

1. **Настройка конфигурации (`/etc/sysctl.d/99-bbr.conf`):**

    ```ini
    # Установка дисциплины очереди fq (необходима для pacing в BBR)
    net.core.default_qdisc = fq
    # Включение алгоритма BBR
    net.ipv4.tcp_congestion_control = bbr
    ```

2. **Применение настроек:**

    ```bash
    sudo sysctl --system
    ```

### Возврат к CUBIC

Если BBR вызывает деградацию производительности (например, в сетях с очень старым оборудованием):

1. **Изменение конфигурации (`/etc/sysctl.d/99-network.conf`):**

    ```ini
    net.core.default_qdisc = fq_codel
    net.ipv4.tcp_congestion_control = cubic
    ```

2. **Применение:** `sudo sysctl --system`
