# Дисциплины очередей TCP в Linux

## Определения

* **Дисциплина очередей (Queueing Discipline, qdisc)** — механизм ядра Linux, управляющий очередями сетевых пакетов перед их передачей драйверу сетевой карты (**NIC**). Он определяет алгоритм планирования, приоритизации и активного управления очередями (**AQM — Active Queue Management**).
* **Bufferbloat (Раздувание буфера)** — деградация производительности сети из-за чрезмерно больших буферов в промежуточных узлах, что приводит к росту задержек (Latency) и джиттера при высокой нагрузке.
* **Pacing (Сглаживание)** — механизм равномерного распределения пакетов во времени. Позволяет избежать всплесков трафика (Bursts), которые могут привести к потерям на коммутаторах с малым объемом памяти.
* **EDT (Earliest Departure Time)** — современная модель планирования в Linux (начиная с ядра 4.19), где каждому пакету назначается временная метка выхода, обеспечивающая сверхточный pacing.

## Базовые концепции

### Роль qdisc в сетевом стеке

Qdisc находится между сетевым стеком протоколов и драйвером интерфейса. В современных ядрах (2026) qdisc тесно интегрирован с механизмами **TSO (TCP Segmentation Offload)** и **GSO (Generic Segmentation Offload)**.

```text
[ Приложение ] → [ TCP Стек ] → [ GSO/TSO ] → [ qdisc (EDT) ] → [ NIC Driver ]
```

### Взаимодействие с алгоритмами перегрузки

Выбор qdisc критически влияет на эффективность алгоритмов контроля перегрузки:

| Алгоритм | Рекомендуемая qdisc | Обоснование |
| :--- | :--- | :--- |
| **BBR (v1/v2/v3)** | **`fq`** | BBR полагается на точный pacing. `fq` реализует EDT-планирование, что необходимо для расчета пропускной способности. |
| **CUBIC / Reno** | **`fq_codel`** | Эффективная изоляция потоков и борьба с Bufferbloat через алгоритм CoDel. |
| **Edge / WAN Shaper** | **`cake`** | Наиболее совершенный алгоритм для пограничных устройств, учитывающий NAT и приоритизацию трафика (DiffServ). |

### Основные типы дисциплин (2026)

*   **fq (Fair Queuing):** Современный стандарт для серверных систем. Поддерживает **EDT**, обеспечивает справедливое распределение полосы между сокетами и реализует pacing на уровне ядра. Необходим для BBR.
*   **fq_codel (Fair Queuing + CoDel):** «Золотой стандарт» для десктопов и общих нагрузок. Борется с bufferbloat, используя активное отбрасывание пакетов из «застоявшихся» очередей.
*   **CAKE (Common Applications Kept Enhanced):** Разработан для замены `fq_codel` на роутерах. Автоматически справляется с шейпингом, учитывает накладные расходы различных типов линков (DSL, Ethernet) и сохраняет низкую задержку для интерактивного трафика.
*   **clsact:** Специальная «пустая» qdisc, используемая как точка прикрепления для **eBPF-программ** (Ingress/Egress), позволяя реализовывать произвольную логику обработки трафика без классических очередей.
*   **mq (Multi-Queue):** Обертка для многоочередных сетевых карт, позволяющая распределять нагрузку по ядрам CPU.

## Практические сценарии

### 1. Проверка текущей конфигурации

```bash
# Текущая дисциплина по умолчанию в системе
sysctl net.core.default_qdisc

# Просмотр qdisc для всех интерфейсов
tc qdisc show

# Просмотр детальной статистики (дропы, backlog, pacing)
tc -s qdisc show dev eth0
```

### 2. Оптимизация сервера под BBRv3

Для работы BBRv3 необходимо убедиться, что используется дисциплина `fq`, которая обеспечивает pacing.

**Настройка через sysctl:**
```ini
# /etc/sysctl.d/99-bbr.conf
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
```

**Принудительная смена на работающем интерфейсе:**
```bash
sudo tc qdisc replace dev eth0 root fq
```

### 3. Борьба с Bufferbloat (Тест и решение)

**Диагностика:**
1.  Запустите непрерывный `ping` до шлюза или стабильного узла.
2.  Запустите тест скорости (загрузка канала на 100%).
3.  Если RTT в пинге вырастает более чем на 50–100 мс — у вас **Bufferbloat**.

**Решение для сервера/десктопа:**
```bash
# Установка fq_codel как наиболее универсального AQM
sudo tc qdisc replace dev eth0 root fq_codel
```

### 4. Настройка шейпинга на Edge-узле (CAKE)

Если сервер выступает в роли шлюза и необходимо ограничить скорость, сохранив низкую задержку:

```bash
# Ограничение исходящей скорости до 100 Мбит/с с использованием CAKE
sudo tc qdisc add dev eth1 root cake bandwidth 100mbit
```

## Дополнительная информация

### Выбор qdisc в 2026 году

*   **Серверы баз данных / API:** `fq` (для BBR и стабильного RTT).
*   **Рабочие станции / Игровые ПК:** `fq_codel` (минимум задержек).
*   **Домашние роутеры / VPN шлюзы:** `cake` (лучшее управление очередями при шейпинге).
*   **Виртуализация (veth/bridge):** `noqueue` (минимизация накладных расходов).

### Ограничения и особенности

*   **Offloading:** Некоторые функции qdisc могут конфликтовать с аппаратным оффлоадингом сетевых карт. При использовании сложных правил `tc` рекомендуется проверять корректность работы через `ethtool -S`.
*   **eBPF:** В 2026 году многие задачи классических qdisc (например, приоритизация) переносятся в eBPF-программы, прикрепленные к `clsact`.
