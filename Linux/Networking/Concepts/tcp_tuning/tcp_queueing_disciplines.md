# Дисциплины очередей TCP в Linux

## Определения

* **Дисциплина очередей (Queueing Discipline, qdisc)** — механизм ядра Linux, управляющий очередями пакетов на сетевых интерфейсах. Он определяет порядок обработки, приоритизацию и моменты отправки пакетов из системной очереди в драйвер сетевой карты.
* **Bufferbloat (Раздувание буфера)** — проблема избыточной буферизации в сетевых узлах (роутерах, свитчах), приводящая к высокой задержке и джиттеру при полной загрузке канала.
* **Kernel Pacing** — механизм сглаживания всплесков трафика, при котором ядро отправляет пакеты с определенными интервалами, предотвращая переполнение буферов промежуточного оборудования.

## Основные концепции

### Роль qdisc в сетевом стеке

Qdisc является последним звеном перед передачей данных драйверу сетевой карты (**NIC**). Он решает, какой пакет из очереди будет отправлен следующим, когда интерфейс готов к передаче.

```text
TCP-стек → [qdisc] → Драйвер NIC → Сеть
           ↑
    Планирование отправки
```

### Взаимодействие с алгоритмами управления перегрузкой

Алгоритм управления перегрузкой (CUBIC, BBR) определяет **объем** данных для отправки, а qdisc — **порядок и тайминг** их выхода в сеть.

| Алгоритм (Congestion Control) | Рекомендуемая qdisc | Обоснование |
| :--- | :--- | :--- |
| **BBR** | `fq` | BBR требует точного pacing — `fq` обеспечивает его на уровне ядра. |
| **CUBIC** | `fq_codel` | Эффективная борьба с bufferbloat для реактивных алгоритмов. |

### Типы дисциплин очередей

* **fq_codel (Fair Queuing + Controlled Delay)** — современный стандарт. Изолирует потоки (Fair Queuing) и активно управляет задержкой (CoDel), отбрасывая пакеты при росте очереди.
* **fq (Fair Queuing)** — обеспечивает точный pacing и справедливое распределение полосы. Необходим для корректной работы BBR.
* **pfifo_fast** — классическая очередь по умолчанию с тремя уровнями приоритетов. Не имеет механизмов борьбы с bufferbloat.
* **mq (Multi-Queue)** — используется в многопроцессорных системах для распределения нагрузки по нескольким очередям сетевой карты.
* **noqueue** — отсутствие очереди, используется для виртуальных интерфейсов (loopback, veth).

## Практические сценарии

### Проверка текущих настроек

```bash
# Дисциплина по умолчанию для новых интерфейсов
sysctl net.core.default_qdisc

# Текущие дисциплины на всех интерфейсах
tc qdisc show

# Статистика работы (дропы, задержки) для конкретного интерфейса
tc -s qdisc show dev eth0
```

### Изменение дисциплины по умолчанию

**Временно (до перезагрузки):**

```bash
# Для серверов с BBR
sudo sysctl -w net.core.default_qdisc=fq

# Для общего использования и борьбы с задержками
sudo sysctl -w net.core.default_qdisc=fq_codel
```

**Постоянно (`/etc/sysctl.d/99-network.conf`):**

```ini
net.core.default_qdisc = fq_codel
```

Применение: `sudo sysctl --system`

> **Важно:** Параметр `default_qdisc` применяется только к интерфейсам, поднятым **после** изменения настройки.

### Смена qdisc на активном интерфейсе

Для применения настроек без перезагрузки интерфейса используется утилита `tc`:

```bash
# Установка fq для работы с BBR
sudo tc qdisc replace dev eth0 root fq

# Установка fq_codel для борьбы с bufferbloat
sudo tc qdisc replace dev eth0 root fq_codel
```

### Диагностика Bufferbloat

Проблема проявляется как резкий рост RTT (пинга) при запуске передачи данных.

1. Запустите `ping -i 0.2 <gateway>`.
2. Начните тяжелую загрузку/отправку файла.
3. Если задержка вырастает в 5–10 раз — в сети присутствует bufferbloat.

**Проверка через tc:**

```bash
# Ищите значение qlen > 0 и наличие backlog
tc -s qdisc show dev eth0
```

Если `backlog` постоянно велик, а `drops` в `fq_codel` растут — значит дисциплина активно борется с перегрузкой.
