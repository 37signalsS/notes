# Настройка initcwnd в Linux: управление начальным окном

## Определения

* **initcwnd (Initial Congestion Window — начальное окно перегрузки)** — параметр **TCP (Transmission Control Protocol — протокол управления передачей)**, определяющий объём данных, который сервер может отправить сразу после установления соединения, не дожидаясь подтверждений **ACK (Acknowledgment)**.
* **MSS (Maximum Segment Size — максимальный размер сегмента)** — максимальный объём полезных данных в одном пакете. Для сетей Ethernet с **MTU (Maximum Transmission Unit — максимальная единица передачи)** 1500 байт стандартный MSS составляет 1460 байт.
* **initrwnd (Initial Receive Window — начальное окно приема)** — объём данных, который получатель готов принять в первой «волне» до получения первого ACK. В современных конфигах также фигурирует как **Initial Advertised Receive Window**.

## Базовые концепции

В ядре Linux значение `initcwnd` по умолчанию составляет 10 MSS (согласно RFC 5681), что эквивалентно примерно 14.6 КБ. Это значение является отправной точкой для алгоритма **Slow Start (Медленный старт)**.

**Ключевая особенность:** В Linux `initcwnd` настраивается не через `sysctl`, а индивидуально для каждого маршрута (route) в таблице маршрутизации. Это позволяет задавать разные окна для локальной сети и внешних интернет-соединений.

Теория «правила 14 КБ» и архитектурное влияние на производительность веб-приложений описаны в основном источнике: **[Правило 14 КБ и оптимизация initcwnd](../../../../Networking/Protocols/TCP/congestion/tcp_initcwnd_and_optimization.md)**.

## Практические сценарии

### 1. Проверка текущего значения

Если параметр не указан явно в выводе команды, ядро использует значение по умолчанию (10 MSS).

```bash
# Просмотр параметров для всех маршрутов
ip route show

# Просмотр для конкретного интерфейса
ip route show dev eth0
# → default via 192.168.1.1 dev eth0 proto dhcp metric 100 initcwnd 32 initrwnd 32
```

### 2. Временная настройка (до перезагрузки)

Изменения вступают в силу немедленно, но сбрасываются после перезапуска сетевого интерфейса или системы.

```bash
# Определение шлюза и интерфейса по умолчанию
GATEWAY=$(ip route | grep default | awk '{print $3}')
DEVICE=$(ip route | grep default | awk '{print $5}')

# Установка initcwnd=32 и initrwnd=32 (рекомендовано для 2026 года)
sudo ip route change default via "$GATEWAY" dev "$DEVICE" initcwnd 32 initrwnd 32
```

### 3. Постоянное сохранение настроек (Persistence)

В 2026 году рекомендуется использовать нативные средства управления сетью.

#### Через Netplan (Ubuntu 24.04+)

Netplan поддерживает параметры окна напрямую в YAML-конфигурации.

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: true
      routes:
        - to: default
          via: 192.168.1.1
          congestion-window: 32
          advertised-receive-window: 32
```

#### Через systemd-networkd

Параметры добавляются в секцию `[Route]`. Если адрес получается по DHCP, используйте переменную `_dhcp4`.

```ini
# /etc/systemd/network/10-eth0.network
[Match]
Name=eth0

[Network]
DHCP=ipv4

[Route]
Gateway=_dhcp4
InitialCongestionWindow=32
InitialAdvertisedReceiveWindow=32
```

#### Через NetworkManager (nmcli)

Для систем с **NetworkManager** (RHEL, Fedora, Desktop Ubuntu) предпочтительно использовать `nmcli` вместо скриптов-диспетчеров.

```bash
# Изменение существующего соединения
sudo nmcli connection modify "Wired connection 1" \
    +ipv4.routes "0.0.0.0/0 192.168.1.1 initcwnd=32 initrwnd=32"

# Применение настроек
sudo nmcli connection up "Wired connection 1"
```

### 4. Мониторинг активных сессий

Для проверки реального размера окна перегрузки в установленных сессиях используется утилита `ss`.

```bash
# Показать подробную информацию (включая cwnd) для всех TCP-соединений
ss -tin state established

# Фильтрация конкретного значения
ss -tin state established | grep -o 'cwnd:[0-9]*'
```

## Дополнительная информация

### Рекомендации по значениям (2026)

*   **10 MSS (Стандарт):** Оптимально для соединений со скоростью 1–10 Мбит/с.
*   **32 MSS:** Современный стандарт для широкополосного доступа и CDN. Позволяет передать ~46 КБ в первой волне.
*   **64 MSS:** Рекомендуется для высокоскоростных каналов (1 Гбит/с+) с высоким пингом (RTT).
*   **Внимание:** Значения выше **100** могут привести к потере пакетов на промежуточных маршрутизаторах с малыми буферами.

### Взаимодействие с BBR

При использовании алгоритма **BBR (Bottleneck Bandwidth and RTT)** влияние `initcwnd` на общую скорость потока ниже, так как BBR агрессивнее оценивает полосу. Однако для **первого RTT** (первый ответ сервера) `initcwnd` остается единственным фактором, определяющим скорость доставки данных.
