# Сетевые интерфейсы в Linux

## Определения

* **Сетевой интерфейс** — это программная абстракция в ядре Linux, которая представляет собой точку для отправки и приема сетевого трафика. Он может соответствовать как физическому устройству (сетевая карта), так и виртуальному (созданному программно).

## Базовые концепции

### 1. Физические интерфейсы

* **Примеры:** `eth0`, `enp3s0`, `wlan0`.

* Напрямую связаны с аппаратным обеспечением (Ethernet-карта, Wi-Fi адаптер).
* У каждого такого интерфейса есть уникальный физический MAC-адрес.
* Их состоянием (включен/выключен, IP-адреса) можно управлять с помощью утилиты [iproute2](../Tools/iproute2/overview.md).

### 2. Виртуальные интерфейсы

Они не привязаны к реальному "железу" и создаются программно для специальных задач.

* **`loopback` (`lo`)**: Виртуальный интерфейс, который указывает на саму систему (`localhost`). Используется для коммуникации процессов на одной машине. Всегда имеет IP-адрес `127.0.0.1`.

* **`bridge` (мост, например, `br0`)**: "Виртуальный свитч" 2-го уровня. Он объединяет несколько других интерфейсов (физических или виртуальных) в единый broadcast-домен, позволяя им общаться друг с другом. Широко используется в [Docker](Docker) и системах виртуализации (KVM, Proxmox). Подробнее об использовании мостов в Docker см. в [Драйвер сети: bridge](../../Docker/Docker_network/drivers/bridge.md).

* **`veth` (Virtual Ethernet)**: "Виртуальный патч-корд". `veth` интерфейсы всегда создаются парами. Все, что отправляется в один конец пары, выходит из другого. Это ключевая технология для контейнеризации, позволяющая соединить сетевой namespace контейнера с хост-системой. Подробнее о сетевых пространствах имен см. в [Сетевые Namespace в Linux](../../Core/namespaces.md#сетевые-пространства-имен).

* **`tun`/`tap`**: Позволяют программам из пространства пользователя (user-space) напрямую отправлять и получать сетевые пакеты. Основное применение — VPN (OpenVPN, WireGuard). Подробнее о различиях см. в [TUN/TAP интерфейсы](../../../Networking/Tunnels/tun_vs_tap.md).
  * **`tun`** (tunneling): Работает на 3-м уровне (IP-пакеты). Создает point-to-point соединение.
  * **`tap`** (terminal access point): Работает на 2-м уровне (Ethernet-кадры), эмулируя полноценный сетевой адаптер.

## Практические сценарии

### Создание моста (bridge)

Мосты используются для соединения виртуальных машин или контейнеров с физической сетью.

```bash
# 1. Создать интерфейс типа bridge
sudo ip link add name br0 type bridge

# 2. Поднять мост
sudo ip link set br0 up

# 3. Добавить физический интерфейс (например, eth0) в мост
# (eth0 при этом не должен иметь IP-адреса)
sudo ip link set eth0 master br0

# 4. Назначить IP-адрес самому мосту
sudo ip addr add 192.168.1.100/24 dev br0
```

Теперь `br0` является основным интерфейсом, а `eth0` просто "пробрасывает" трафик в него.

### Создание пары veth-интерфейсов

`veth`-пары часто используются для подключения контейнеров к мосту на хосте.

```bash
# 1. Создать пару с именами veth-host и veth-guest
sudo ip link add veth-host type veth peer name veth-guest

# 2. Подключить один конец (veth-host) к мосту
sudo ip link set veth-host master br0

# 3. Поднять оба интерфейса
sudo ip link set veth-host up
sudo ip link set veth-guest up # Этот интерфейс обычно перемещается в namespace контейнера
```

## Дополнительная информация

### Наименование интерфейсов

Исторически интерфейсы назывались `eth0`, `eth1` и т.д. Это приводило к проблемам, так как порядок мог меняться после перезагрузки.

Современные системы используют **Predictable Network Interface Names** (предсказуемые имена), которые кодируют информацию о расположении устройства.

* **`enp3s0`**: `en` (Ethernet), `p3` (номер шины PCI), `s0` (номер слота).
* **`wlp2s0`**: `wl` (Wireless LAN), `p2s0` (шина, слот).

Это гарантирует, что имя интерфейса останется постоянным. Подробнее о фиксации имен см. в [Постоянная настройка сети в Linux](../Settings/persistent_network_configuration.md#1-фиксация-имен-сетевых-интерфейсов).

### Bonding (агрегация каналов)

**Bonding** (агрегация каналов) — это технология объединения нескольких физических сетевых интерфейсов в один логический для увеличения пропускной способности и обеспечения отказоустойчивости.

Подробное описание режимов работы и настройки см. в основной заметке: [Агрегация каналов (Link Aggregation)](../../../Networking/Concepts/link_aggregation.md).
