# Сетевые интерфейсы в Linux

## Определения

* **Сетевой интерфейс** — это программная абстракция в ядре Linux, представляющая собой точку для отправки и приема сетевого трафика. Он может соответствовать как физическому устройству (**NIC — Network Interface Card**, сетевая карта), так и виртуальному, созданному программно.
* **Физический интерфейс** — программное представление аппаратного сетевого адаптера (**Ethernet**, **Wi-Fi**).
* **Виртуальный интерфейс** — логическое устройство, существующее только в памяти ядра для реализации сетевых функций (маршрутизация, туннелирование, изоляция).

## Базовые концепции

### 1. Физические интерфейсы

Физические интерфейсы напрямую связаны с аппаратным обеспечением. Каждому такому интерфейсу на канальном уровне **L2 (Data Link Layer)** соответствует уникальный **MAC-адрес (Media Access Control)**.

* **Примеры имен:** `eth0`, `enp3s0` (**Ethernet**), `wlan0` (**Wireless LAN**).
* **Управление:** Основным инструментом является утилита `ip` из пакета **iproute2**.

**Терминология:** В сетевой инженерии физический разъем называют «портом», а программный объект в ОС — «интерфейсом». IP-адрес назначается именно на интерфейс.

### 2. Виртуальные интерфейсы

Виртуальные интерфейсы создаются программно для реализации специфических сетевых сценариев.

#### Интерфейс обратной петли (Loopback)

Интерфейс `lo` указывает на саму систему (`localhost`). Используется для взаимодействия процессов внутри одного хоста.

* **Сеть Loopback:** Диапазон `127.0.0.0/8` (обычно используется `127.0.0.1`).
* **Особенности:** Трафик не покидает пределы хоста, обрабатывается сетевым стеком и сразу возвращается обратно. Интерфейс `lo` всегда должен быть активен для корректной работы многих системных служб.

#### Сетевой мост (Bridge)

Программный коммутатор **L2**, объединяющий несколько интерфейсов в единый широковещательный домен.

* **Применение:** Виртуализация (**KVM**, **Proxmox**), контейнеризация (**Docker**).
* **SSoT:** Подробное описание в разделе **[Linux Bridge](./linux_bridge.md)**.

#### Виртуальный Ethernet (veth)

Представляет собой «виртуальный патч-корд», который всегда создается парой. Пакет, отправленный в один интерфейс пары, мгновенно появляется на другом.

* **Применение:** Соединение сетевых пространств имен (**Network Namespaces**) контейнеров с сетевым стеком хоста.
* **SSoT:** См. раздел **[Сетевые пространства имен (Namespaces)](../../Core/namespaces.md#сетевые-пространства-имен)**.

#### Интерфейсы TUN/TAP

Интерфейсы, позволяющие приложениям из пространства пользователя (**User-space**) напрямую обрабатывать сетевой трафик.

* **TUN (Tunneling):** Работает на сетевом уровне **L3** с **IP (Internet Protocol)** пакетами.
* **TAP (Terminal Access Point):** Работает на канальном уровне **L2** с **Ethernet** кадрами.
* **SSoT:** Подробности в разделе **[TUN/TAP интерфейсы](../../../Networking/Tunnels/tun_vs_tap.md)**.

## Практические сценарии

### Диагностика интерфейса Loopback

Если `ping localhost` не работает, проверьте следующие шаги:

1. **Состояние интерфейса:** `ip link show lo` должен показывать `UP` или `UNKNOWN` (для `lo` это нормально). Если `DOWN` — включите: `sudo ip link set lo up`.
2. **Файл hosts:** Убедитесь, что в `/etc/hosts` есть запись `127.0.0.1 localhost`.
3. **Настройка резолвера:** Проверьте приоритет поиска в `/etc/nsswitch.conf` (строка `hosts: files dns`).
4. **Межсетевой экран (Firewall):** Убедитесь, что **iptables** или **nftables** не блокируют трафик на интерфейсе `lo`.

### Создание пары veth-интерфейсов

Пример создания канала связи между двумя точками:

```bash
# Создание пары veth-host и veth-guest
sudo ip link add veth-host type veth peer name veth-guest

# Активация интерфейсов
sudo ip link set veth-host up
sudo ip link set veth-guest up
```

## Дополнительная информация

### Именование интерфейсов (Predictable Names)

Современные системы используют предсказуемые имена интерфейсов, привязанные к физическому расположению устройства на шине **PCI (Peripheral Component Interconnect)**.

* **`enp3s0`**: `en` (Ethernet), `p3` (шина 3), `s0` (слот 0).
* **`wlp2s0`**: `wl` (Wireless LAN), `p2` (шина 2), `s0` (слот 0).

Это предотвращает изменение имен интерфейсов (например, `eth0` на `eth1`) при добавлении новых сетевых карт или обновлении ядра. Подробнее: **[Постоянная настройка сети](../Settings/Persistent_Network/systemd_networkd.md)**.

### Агрегация и оптимизация

* **Bonding/Teaming:** Объединение интерфейсов для отказоустойчивости и скорости. См. **[Агрегация каналов (Link Aggregation)](../../../Networking/Concepts/link_aggregation.md)**.
* **Performance Offloading:** Разгрузка **CPU** за счет функций **NIC** (**GRO/LRO/TSO**). См. **[Network Offloading](./offloading.md)**.
* **Многопоточность:** Распределение обработки прерываний по ядрам **CPU**. См. **[RSS, RPS, RFS](./rss_rps_rfs.md)**.
