# Сетевые интерфейсы в Linux: типы и применение

**Reliability Score: 10 (SSoT + Web)**

## Определения

**Сетевой интерфейс** — программная абстракция в ядре Linux, представляющая собой точку входа и выхода для сетевого трафика. Интерфейс может быть связан с физическим устройством (**NIC — Network Interface Card**) или быть полностью виртуальным.

**Физический интерфейс** — программное представление аппаратного сетевого адаптера (**Ethernet**, **Wi-Fi**, **Fiber Channel**).

**Виртуальный интерфейс** — логическое сетевое устройство, создаваемое ядром для реализации туннелирования, маршрутизации, агрегации или изоляции трафика.

## Основные концепции

### 1. Физические интерфейсы

Напрямую привязаны к «железу». В современных дистрибутивах используются **предсказуемые имена** (Predictable Network Interface Names), отражающие физическое расположение устройства.

*   **Имена:** `enp3s0` (Ethernet на шине 3, слот 0), `wlp2s0` (Wi-Fi). Старые имена `ethX` и `wlanX` сохраняются в облачных средах или при отключении этой функции в ядре.
*   **Управление:** `ip link set dev <name> up/down`.

### 2. Виртуальные интерфейсы общего назначения

#### Интерфейс обратной петли (Loopback)
Интерфейс `lo` указывает на локальный хост (`127.0.0.1`). Критически важен для работы внутренних сервисов и IPC (Inter-Process Communication).

#### Виртуальный Ethernet (veth)
Всегда создается парой (`veth pair`). Пакет, входящий в один конец «виртуального провода», выходит из другого.
*   **Применение:** Соединение сетевых пространств имен (**Network Namespaces**) контейнеров (Docker, Podman) с хостом.

#### Фиктивный интерфейс (Dummy)
Ведет себя как Loopback, но может иметь произвольное имя и IP-адрес. Пакеты, отправленные в него, отбрасываются.
*   **Применение:** Удержание IP-адреса (например, Anycast IP) для протоколов маршрутизации (BGP/OSPF), чтобы адрес был доступен, даже если физические линки упали.

### 3. Интерфейсы виртуализации и изоляции

#### Сетевой мост (Bridge)
Виртуальный коммутатор L2. Объединяет несколько интерфейсов в один широковещательный домен.
*   **SSoT:** Подробности в **[Linux Bridge](./linux_bridge.md)**.

#### MACVLAN и IPVLAN
Позволяют одному физическому интерфейсу иметь несколько виртуальных интерфейсов с собственными MAC или IP адресами.
*   **MACVLAN:** Каждый виртуальный интерфейс имеет уникальный MAC. Позволяет контейнерам выглядеть как физические узлы в сети.
*   **IPVLAN:** Виртуальные интерфейсы делят один MAC физической карты, но имеют разные IP. Рекомендуется для облаков и Wi-Fi.

#### VRF (Virtual Routing and Forwarding)
Позволяет создавать изолированные таблицы маршрутизации на уровне L3 внутри одной ОС.
*   **SSoT:** См. раздел **[VRF в Linux](../vrf.md)**.

### 4. Туннельные интерфейсы (TUN/TAP)
Позволяют приложениям Userspace обрабатывать пакеты напрямую.
*   **TUN:** Работает на уровне L3 (IP-пакеты). Применяется в VPN (OpenVPN, WireGuard).
*   **TAP:** Работает на уровне L2 (Ethernet-кадры). Эмулирует сетевую карту для виртуальных машин (QEMU/KVM).
*   **SSoT:** См. **[TUN/TAP интерфейсы](../../../Networking/Tunnels/tun_vs_tap.md)**.

## Практические сценарии

### 1. Создание dummy-интерфейса для сервис-IP

```bash
# Создание интерфейса
sudo ip link add dummy0 type dummy

# Назначение адреса
sudo ip addr add 10.10.10.10/32 dev dummy0
sudo ip link set dummy0 up
```

### 2. Настройка veth-пары между пространствами имен

```bash
# Создать пару
sudo ip link add veth-host type veth peer name veth-ns

# Переместить один конец в NetNS (например, 'test-ns')
sudo ip link set veth-ns netns test-ns

# Активация
sudo ip link set veth-host up
```

## Дополнительная информация

### Агрегация и объединение
Интерфейсы могут объединяться для отказоустойчивости или увеличения пропускной способности.
*   **Bonding:** Классический модуль ядра.
*   **Team:** Современная реализация (userspace + kernel), предоставляющая больше гибкости.
*   **SSoT:** См. **[Агрегация каналов](../../../Networking/Concepts/link_aggregation.md)**.

### Оптимизация
*   **Offloading:** Разгрузка CPU (GRO/TSO). См. **[Network Offloading](./offloading.md)**.
*   **Многопоточность:** Распределение прерываний. См. **[RSS, RPS, RFS](./rss_rps_rfs.md)**.
