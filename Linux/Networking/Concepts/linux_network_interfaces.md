# Сетевые интерфейсы в Linux: типы и применение

## Определения

**Сетевой интерфейс** — программная абстракция в ядре Linux, представляющая собой точку входа и выхода для сетевого трафика. Интерфейс может быть связан с физическим устройством (**NIC — Network Interface Card**) или быть полностью виртуальным.

**Физический интерфейс** — программное представление аппаратного сетевого адаптера (**Ethernet**, **Wi-Fi**, **Fiber Channel**).

**Виртуальный интерфейс** — логическое сетевое устройство, создаваемое ядром для реализации туннелирования, маршрутизации, агрегации или изоляции трафика.

## Основные концепции

### 1. Физические интерфейсы

Напрямую привязаны к аппаратному обеспечению. В современных дистрибутивах используются **предсказуемые имена** (Predictable Network Interface Names), отражающие физическое расположение устройства на шине.

*   **Имена:** `enp3s0` (Ethernet на шине 3, слот 0), `wlp2s0` (Wi-Fi). Старые имена `ethX` сохраняются в облачных средах или при отключении этой функции через параметры ядра (`net.ifnames=0`).
*   **Альтернативные имена (altnames):** Современные ядра позволяют назначать интерфейсу несколько имен. Это удобно для миграции или именования по ролям (например, `uplink0`).
    ```bash
    # Добавление альтернативного имени
    sudo ip link property add dev enp3s0 altname uplink0
    ```

### 2. Состояния интерфейсов

При просмотре через `ip link` интерфейс имеет несколько флагов состояния:
*   **UP:** Интерфейс программно активирован (`ip link set ... up`).
*   **LOWER_UP:** Физический уровень (L1) активен (кабель подключен, линк согласован).
*   **NO-CARRIER:** Физический линк отсутствует.
*   **PROMISC:** Смешанный режим (принимаются все пакеты, а не только адресованные этому MAC).

### 3. Виртуальные интерфейсы общего назначения

#### Интерфейс обратной петли (Loopback)
Интерфейс `lo` указывает на локальный хост (`127.0.0.1` / `::1`). Критически важен для работы внутренних сервисов и IPC (Inter-Process Communication).

#### Виртуальный Ethernet (veth)
Создается парой (`veth pair`). Работает как виртуальный патч-корд: пакет, входящий в один интерфейс, выходит из другого.
*   **Применение:** Соединение сетевых пространств имен (**Network Namespaces**) контейнеров (Docker, Podman) с мостами хоста.

#### Фиктивный интерфейс (Dummy)
Аналог Loopback, но с произвольным именем. Пакеты, отправленные в него, отбрасываются.
*   **Применение:** Удержание Anycast IP-адресов для протоколов маршрутизации (BGP/OSPF). Это позволяет адресу оставаться доступным в системе, даже если все физические интерфейсы упали.

### 4. Интерфейсы виртуализации и изоляции

#### Сетевой мост (Bridge)
Программный L2-коммутатор. Позволяет объединять физические и виртуальные интерфейсы в один сегмент сети.
*   **SSoT:** Подробности в **[Linux Bridge](./linux_bridge.md)**.

#### MACVLAN и IPVLAN
Механизмы создания множества виртуальных интерфейсов поверх одного физического (родительского).
*   **MACVLAN:** Каждому интерфейсу назначается уникальный MAC-адрес. Идеально для контейнеров, которым нужно выглядеть как физические хосты.
*   **IPVLAN:** Все интерфейсы делят MAC-адрес родителя, но имеют разные IP. Полезно в сетях с ограничением на количество MAC (Wi-Fi, облака).

#### VLAN (802.1Q)
Создание логических интерфейсов для тегированного трафика.
*   **Пример:** `eth0.10` для трафика с тегом VLAN 10.
*   **SSoT:** См. **[VLAN в Linux](../../../Networking/Protocols/VLAN/vlan_linux_diagnostics.md)**.

### 5. Туннельные и защищенные интерфейсы

#### TUN/TAP
Интерфейсы, позволяющие программам из Userspace читать и писать пакеты напрямую в стек ядра.
*   **TUN (L3):** Работает с IP-пакетами (VPN: OpenVPN, WireGuard).
*   **TAP (L2):** Работает с Ethernet-кадрами (Виртуализация: QEMU/KVM).
*   **SSoT:** См. **[TUN/TAP интерфейсы](../../../Networking/Tunnels/tun_vs_tap.md)**.

#### Современные инкапсуляции
*   **VXLAN / GENEVE:** L2 поверх L3. Используются в Overlay-сетях (Kubernetes, OpenStack).
*   **XFRM:** Интерфейс для IPsec трафика, позволяющий маршрутизировать защищенные пакеты как обычные.
*   **WireGuard:** Виртуальный интерфейс для одноименного протокола VPN.

#### VRF (Virtual Routing and Forwarding)
Позволяет разделять таблицу маршрутизации на уровне L3. Интерфейс, назначенный в VRF, использует свою таблицу маршрутизации и правил.
*   **SSoT:** См. раздел **[VRF в Linux](../vrf.md)**.

## Практические сценарии

### 1. Управление именами и состояниями

```bash
# Просмотр всех интерфейсов (кратко)
ip -brief link show

# Активация интерфейса
sudo ip link set dev enp3s0 up

# Добавление описания (alias)
sudo ip link set dev enp3s0 alias "Uplink to Core Switch"
```

### 2. Работа с виртуальными парами veth

```bash
# Создать пару
sudo ip link add veth0 type veth peer name veth1

# Переместить veth1 в другое сетевое пространство имен
sudo ip netns add my-ns
sudo ip link set veth1 netns my-ns

# Активировать интерфейсы
sudo ip link set veth0 up
sudo ip netns exec my-ns ip link set veth1 up
```

## Дополнительная информация

### Агрегация и отказоустойчивость
Интерфейсы можно объединять (Slave) в логические группы (Master) для повышения пропускной способности.
*   **Bonding:** Традиционный механизм ядра. Поддерживает режимы `balance-rr`, `active-backup`, `802.3ad` (LACP).
*   **Team:** Более современная и модульная реализация, часть логики которой вынесена в Userspace.
*   **SSoT:** См. **[Агрегация каналов](../../../Networking/Concepts/link_aggregation.md)**.

### Аппаратная разгрузка и eBPF
Современные интерфейсы поддерживают механизмы ускорения:
*   **Offloading (TSO, GSO, GRO):** Перенос сборки/разборки пакетов на сетевую карту.
*   **XDP (eXpress Data Path):** Позволяет запускать eBPF программы на самом низком уровне интерфейса (драйвер или NIC), обеспечивая экстремально быструю фильтрацию трафика до попадания в стек ядра.
