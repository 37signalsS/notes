# Сетевые интерфейсы в Linux

## Определения

* **Сетевой интерфейс** — это программная абстракция в ядре Linux, которая представляет собой точку для отправки и приема сетевого трафика. Он может соответствовать как физическому устройству (сетевая карта), так и виртуальному (созданному программно).

## Базовые концепции

### 1. Физические интерфейсы

* **Примеры:** `eth0`, `enp3s0`, `wlan0`.

* Напрямую связаны с аппаратным обеспечением (Ethernet-карта, Wi-Fi адаптер).
* У каждого такого интерфейса есть уникальный физический MAC-адрес.
* Их состоянием (включен/выключен, IP-адреса) можно управлять с помощью утилиты [iproute2](../Tools/iproute2/overview.md).

**Терминология:** В сетевых дискуссиях часто говорят "порт", имея в виду физический разъем (port), а "интерфейс" — программный (interface). На практике кабель вставляется в физический порт, а IP-адрес назначается на логический интерфейс.

### 2. Виртуальные интерфейсы

Они не привязаны к реальному "железу" и создаются программно для специальных задач.

* **`loopback` (`lo`)**: Виртуальный интерфейс, который указывает на саму систему (`localhost`). Используется для коммуникации процессов на одной машине.

    **Сеть Loopback (127.0.0.0/8):** Обратная петля — это не один адрес, а целая IP-сеть `127.0.0.0/8` с маской `255.0.0.0`. Каждый хост автоматически создает виртуальный интерфейс `lo` и назначает ему эту сеть. Наиболее распространенный адрес — `127.0.0.1`, но допустимо использование любого адреса из диапазона `127.0.0.1` – `127.255.255.255`.

    **Практический пример:** Веб-сервер и база данных работают на одной машине и общаются через сеть. Вместо использования реального IP-адреса или доменного имени, они могут обращаться друг к другу по адресу `127.0.0.1`, что обеспечивает максимальную скорость и не требует настройки сетевого оборудования.

    **Особенности:**
  * Трафик на `127.0.0.0/8` не покидает пределы хоста — он обрабатывается на сетевом уровне и сразу возвращается в стек
  * Интерфейс `lo` всегда активен и имеет состояние `UNKNOWN` (не `UP`), что является нормальным
  * Используется для тестирования сетевого стека, межпроцессного взаимодействия, изоляции сервисов

### Почему ping localhost может не работать?

Несмотря на то, что `localhost` является стандартным именем для интерфейса `lo`, команда `ping localhost` может завершиться ошибкой по следующим причинам:

1.  **Интерфейс `lo` выключен:** Самая частая причина. Если интерфейс `lo` принудительно переведен в состояние `down`, трафик на него не будет приниматься.
    *   *Проверка:* `ip link show lo`
    *   *Решение:* `sudo ip link set lo up`
2.  **Отсутствие записи в `/etc/hosts`:** Если системный резолвер не находит соответствие имени `localhost` IP-адресу `127.0.0.1` в файле `/etc/hosts` и пытается разрешить его через внешние DNS, запрос может провалиться или вернуть неверный адрес.
    *   *Проверка:* `cat /etc/hosts` (должна быть строка `127.0.0.1 localhost`)
3.  **Ошибки в настройке резолвера (`/etc/nsswitch.conf`):** Если в настройках приоритета поиска имен (`hosts`) отсутствует `files`, система может игнорировать `/etc/hosts`.
4.  **Блокировка через Firewall:** Правила `iptables` или `nftables` могут быть настроены так, чтобы блокировать входящий или исходящий трафик на интерфейсе `lo` (хотя это считается плохой практикой).
    *   *Проверка:* `sudo iptables -L -v`
5.  **IPv6 vs IPv4:** В современных системах `localhost` может резолвиться в `::1` (IPv6). Если стек IPv6 отключен или некорректно настроен, `ping` может выдать ошибку.
    *   *Решение:* Использовать `ping -4 localhost` для принудительного использования IPv4.

* **`bridge` (мост, например, `br0`)**: "Виртуальный свитч" 2-го уровня. Он объединяет несколько других интерфейсов (физических или виртуальных) в единый broadcast-домен, позволяя им общаться друг с другом. Широко используется в контейнеризации и системах виртуализации (KVM, Proxmox). Подробнее: [Драйвер сети: bridge в Docker](../../../Docker/Docker_network/drivers/bridge.md).

* **`veth` (Virtual Ethernet)**: "Виртуальный патч-корд". `veth` интерфейсы всегда создаются парами. Все, что отправляется в один конец пары, выходит из другого. Это ключевая технология для контейнеризации, позволяющая соединить сетевой namespace контейнера с хост-системой. Подробнее о сетевых пространствах имен см. в [Сетевые Namespace в Linux](../../Core/namespaces.md#сетевые-пространства-имен).

* **`tun`/`tap`**: Позволяют программам из пространства пользователя (user-space) напрямую отправлять и получать сетевые пакеты. Основное применение — VPN (OpenVPN, WireGuard). Подробнее о различиях см. в [TUN/TAP интерфейсы](../../../Networking/Tunnels/tun_vs_tap.md).
  * **`tun`** (tunneling): Работает на 3-м уровне (IP-пакеты). Создает point-to-point соединение.
  * **`tap`** (terminal access point): Работает на 2-м уровне (Ethernet-кадры), эмулируя полноценный сетевой адаптер.

## Практические сценарии

### Создание моста (bridge)

Мосты используются для соединения виртуальных машин или контейнеров с физической сетью.

```bash
# 1. Создать интерфейс типа bridge
sudo ip link add name br0 type bridge

# 2. Поднять мост
sudo ip link set br0 up

# 3. Добавить физический интерфейс (например, eth0) в мост
# (eth0 при этом не должен иметь IP-адреса)
sudo ip link set eth0 master br0

# 4. Назначить IP-адрес самому мосту
sudo ip addr add 192.168.1.100/24 dev br0
```

Теперь `br0` является основным интерфейсом, а `eth0` просто "пробрасывает" трафик в него.

### Создание пары veth-интерфейсов

`veth`-пары часто используются для подключения контейнеров к мосту на хосте.

```bash
# 1. Создать пару с именами veth-host и veth-guest
sudo ip link add veth-host type veth peer name veth-guest

# 2. Подключить один конец (veth-host) к мосту
sudo ip link set veth-host master br0

# 3. Поднять оба интерфейса
sudo ip link set veth-host up
sudo ip link set veth-guest up # Этот интерфейс обычно перемещается в namespace контейнера
```

> **Проблема конфликта маршрутов при нескольких veth-парах и решение через bridge:** [Драйвер сети: bridge — конфликт маршрутов](../../../Docker/Docker_network/drivers/bridge.md).

## Дополнительная информация

### Наименование интерфейсов

Исторически интерфейсы назывались `eth0`, `eth1` и т.д. Это приводило к проблемам, так как порядок мог меняться после перезагрузки.

Современные системы используют **Predictable Network Interface Names** (предсказуемые имена), которые кодируют информацию о расположении устройства.

* **`enp3s0`**: `en` (Ethernet), `p3` (номер шины PCI), `s0` (номер слота).
* **`wlp2s0`**: `wl` (Wireless LAN), `p2s0` (шина, слот).

Это гарантирует, что имя интерфейса останется постоянным. Подробнее о фиксации имен см. в [Постоянная настройка сети в Linux](../Settings/Persistent_Network/systemd_networkd.md).

### Bonding (агрегация каналов)

**Bonding** (агрегация каналов) — это технология объединения нескольких физических сетевых интерфейсов в один логический для увеличения пропускной способности и обеспечения отказоустойчивости.

Подробное описание режимов работы и настройки см. в основной заметке: [Агрегация каналов (Link Aggregation)](../../../Networking/Concepts/link_aggregation.md).
