# Linux Bridge: программный коммутатор в ядре

**Reliability Score: 10 (SSoT + Web)**

## Определения

**Linux Bridge (Мост)** — программный коммутатор канального уровня (**L2 — Data Link Layer**), реализованный непосредственно в ядре Linux. Он позволяет объединять несколько сетевых интерфейсов (физических, виртуальных или VLAN) в единый логический сегмент (broadcast-домен).

**Порты моста (Bridge Ports)** — интерфейсы, подключенные к мосту. При включении в мост интерфейс переходит в режим работы «slave» и перестает использовать собственные настройки сетевого уровня (**L3 — IP**), делегируя обработку входящих кадров мосту.

**FDB (Forwarding Database — база пересылки)** — внутренняя таблица моста, сопоставляющая MAC-адреса устройств с портами моста, через которые они доступны.

**VLAN Filtering** — механизм, позволяющий одному мосту обрабатывать несколько VLAN-тегов (**IEEE 802.1Q**) на портах, выполняя роль VLAN-aware коммутатора без создания множества отдельных виртуальных интерфейсов.

## Основные концепции

### Принцип работы

Linux Bridge имитирует поведение стандартного управляемого коммутатора:
1.  **Обучение (Learning):** Мост анализирует поле Source MAC во входящих кадрах и обновляет таблицу FDB.
2.  **Пересылка (Forwarding):** Если Destination MAC есть в FDB, кадр отправляется в соответствующий порт.
3.  **Лавинная рассылка (Flooding):** Если адрес неизвестен или является широковещательным, кадр рассылается во все порты, кроме порта-источника.

### Фильтрация и безопасность

Для фильтрации трафика на уровне моста используются следующие механизмы:
*   **ebtables / nftables:** Позволяют фильтровать кадры на основе Ethernet-заголовков (MAC-адреса, типы протоколов L2).
*   **br_netfilter:** Специальный модуль ядра, который позволяет передавать трафик моста на обработку в стек **iptables/nftables** уровня L3. Это критически важно для работы сетевых политик (NetworkPolicies) в Kubernetes.
    *   Параметры `sysctl`: `net.bridge.bridge-nf-call-iptables = 1` и `net.bridge.bridge-nf-call-arptables = 1`.

### Протокол STP (Spanning Tree Protocol)

Linux Bridge поддерживает классический STP для предотвращения петель в топологии. В современных высоконагруженных средах (ЦОД) STP на мостах часто отключают в пользу более сложных механизмов на уровне физической сети, чтобы избежать задержек при перестроении топологии.

## Управление и диагностика

### Основные команды

Современным стандартом является использование утилит `ip` и `bridge`.

- **Просмотр состояния портов:**
  ```bash
  bridge link
  ```
  Позволяет увидеть, какие интерфейсы подключены к мостам, их состояние (`UP`/`DOWN`) и параметры (например, `cost`, `priority`).

- **Проверка тегирования VLAN:**
  ```bash
  bridge vlan show
  ```
  Показывает конфигурацию VLAN на каждом порту (Trunk/Access), если включен режим `vlan_filtering`.

### Сценарий: Виртуализация KVM
Обычная схема выглядит так: 
1. Виртуальная машина создает **TAP-интерфейс** (например, `vnet0`) на хосте.
2. Этот интерфейс подключается к **Linux Bridge** (`br0`).
3. Мост пересылает трафик между `vnet0` и физическим интерфейсом (`eth0`).

```bash
# Пример проверки подключения TAP к мосту
ip link show master br0
```

## Практические сценарии

### 1. Управление через iproute2 и bridge-utils
...
```bash
# Создание моста br0
sudo ip link add name br0 type bridge
...
# Просмотр таблицы MAC-адресов
bridge fdb show dev br0
```

### 2. Настройка через systemd-networkd

Для постоянной конфигурации на серверах часто используется `systemd-networkd`.

**/etc/systemd/network/25-br0.netdev:**
```ini
[NetDev]
Name=br0
Kind=bridge

[Bridge]
STP=yes
VLANFiltering=yes
```

**/etc/systemd/network/25-br0-bind.network:**
```ini
[Match]
Name=eth0

[Network]
Bridge=br0
```

### 3. Настройка VLAN на портах (bridge vlan)

Если включен `vlan_filtering`, портам можно назначать тегированные и нетегированные VLAN.

```bash
# Назначить VLAN 10 на eth0 как нетегированный (PVID/Untagged)
sudo bridge vlan add dev eth0 vid 10 pvid untagged

# Назначить VLAN 20 на eth0 как тегированный (Tagged/Trunk)
sudo bridge vlan add dev eth0 vid 20
```

## Дополнительная информация

### Сравнение с Open vSwitch (OVS)

| Характеристика | Linux Bridge | Open vSwitch |
| :--- | :--- | :--- |
| **Реализация** | Ядро Linux | Ядро + Userspace демоны |
| **Сложность** | Низкая (часть ОС) | Высокая (требует настройки) |
| **SDN / OpenFlow** | Нет | Да (полная поддержка) |
| **Туннелирование** | Ограничено (VXLAN через ip link) | Глубокая интеграция (VXLAN, Geneve) |
| **Применение** | Docker, LXC, простые KVM | OpenStack, сложные SDN, DPDK |
