# Linux Bridge: Программный коммутатор в ядре

## Определения

* **Linux Bridge (Мост)** — программный коммутатор канального уровня **L2 (Data Link Layer — канальный уровень)** в ядре Linux. Он позволяет объединять несколько сетевых интерфейсов (физических портов, **VLAN (Virtual Local Area Network — виртуальная локальная сеть)** или виртуальных интерфейсов виртуальных машин) в единый логический сегмент.
* **Порты моста** — интерфейсы, подключенные к мосту. Они перестают работать как самостоятельные **L3 (Network Layer — сетевой уровень)** устройства (не имеют собственных IP-адресов) и становятся «прозрачными» портами коммутатора.

## Базовые концепции

### Принцип работы

Linux Bridge имитирует поведение физического коммутатора:

1. **Изучение (Learning)**: Анализирует входящие кадры и запоминает **MAC-адреса (Media Access Control — адрес управления доступом к среде)** подключенных устройств, формируя таблицу пересылки (FDB — Forwarding Database).
2. **Пересылка (Forwarding)**: Направляет кадр только в тот порт, где находится получатель.
3. **Широковещание (Flooding)**: Если адрес получателя неизвестен или является широковещательным, кадр рассылается во все порты, кроме порта-источника.

### Ключевые функции

* **STP (Spanning Tree Protocol — протокол остовного дерева)**: Предотвращает образование петель в сети при наличии избыточных соединений.
* **VLAN Filtering**: Позволяет мосту учитывать теги **IEEE 802.1Q** и разделять трафик на логические сегменты внутри одного моста.
* **Фильтрация трафика**: Взаимодействие с подсистемой **Netfilter** через модуль `br_netfilter`, что позволяет использовать `iptables` для фильтрации трафика, проходящего через мост.

## Практические сценарии

### 1. Создание моста и добавление интерфейсов

Для управления мостами рекомендуется использовать современные команды `iproute2`.

```bash
# Создание интерфейса моста br0
sudo ip link add name br0 type bridge

# Активация моста
sudo ip link set dev br0 up

# Добавление физического интерфейса eth0 в мост
sudo ip link set dev eth0 master br0

# Просмотр состояния мостов
ip link show type bridge
```

### 2. Управление с помощью brctl (устаревший метод)

В некоторых дистрибутивах всё ещё используется пакет `bridge-utils`.

```bash
# Показать все мосты и их порты
brctl show

# Включить STP на мосту
sudo brctl stp br0 on
```

### 3. Настройка VLAN на мосту (VLAN Filtering)

Современный способ создания VLAN-зависимых мостов без создания множества отдельных интерфейсов.

```bash
# Включение фильтрации VLAN
sudo ip link set dev br0 type bridge vlan_filtering 1

# Назначение VLAN 10 на порт eth0 как нетегированный (PVID)
sudo bridge vlan add dev eth0 vid 10 pvid untagged
```

## Дополнительная информация

### Сферы применения

* **Виртуализация (KVM/QEMU/LXC)**: Мост выступает в роли виртуального свитча, к которому подключаются **TAP-интерфейсы** виртуальных машин.
* **Контейнеризация (Docker)**: По умолчанию Docker создает мост `docker0` для связи контейнеров между собой и с внешней сетью через **NAT (Network Address Translation — трансляция сетевых адресов)**.
* **CNI (Container Network Interface)**: Плагины в Kubernetes используют мосты для организации сетевой связности подов на узле.

### Сравнение с Open vSwitch

| Характеристика | Linux Bridge | Open vSwitch (OVS) |
| :--- | :--- | :--- |
| **Сложность** | Простой, встроен в ядро | Сложный, требует доп. служб |
| **Производительность** | Высокая (в ядре) | Высокая (есть поддержка DPDK) |
| **Функционал** | Базовый L2, STP, VLAN | SDN, OpenFlow, VXLAN, GRE |
