# Оптимизация TCP в Linux

## Определения

*   **Оптимизация TCP** — это процесс настройки параметров сетевого стека ядра Linux для улучшения производительности TCP-соединений, снижения задержек и повышения пропускной способности.
*   **`TIME_WAIT`** — состояние TCP-соединения, в которое переходит одна из сторон после его закрытия для обеспечения надежной доставки последних пакетов и предотвращения проблем с новыми соединениями, использующими те же порты.
*   **BBR (Bottleneck Bandwidth and Round-trip time)** — современный алгоритм контроля перегрузки сети, разработанный Google, который оптимизирует пропускную способность и минимизирует задержки путем моделирования характеристик канала.

## Базовые концепции

Производительность сетевых соединений в Linux сильно зависит от настроек TCP/IP стека ядра. Две важные области для оптимизации на высоконагруженных серверах — это управление состоянием `TIME_WAIT` и выбор алгоритма контроля перегрузки. Все параметры настраиваются через [[sysctl|../../Linux/Core/sysctl.md]]. Для постоянного применения их следует добавлять в файл `/etc/sysctl.conf` и выполнять `sudo sysctl -p`.

## Практические сценарии

### 1. Управление состоянием `TIME_WAIT`

#### Что это такое?

Когда TCP-соединение закрывается, сторона, инициировавшая закрытие, переводит сокет в состояние `TIME_WAIT` на некоторое время (обычно 60 секунд, `2 * MSL`). Это необходимо для гарантии того, что все пакеты, "заблудившиеся" в сети, будут получены и не помешают новым соединениям.

#### Проблема

На серверах, обрабатывающих большое количество короткоживущих соединений (веб-серверы, прокси), может скапливаться огромное количество сокетов в состоянии `TIME_WAIT`. Каждый такой сокет занимает память и, что важнее, занимает один из доступных локальных портов (в диапазоне `ip_local_port_range`). Когда порты заканчиваются, сервер не может устанавливать новые исходящие соединения, что приводит к ошибкам `address already in use`.
Подробнее о состояниях TCP-соединений.

#### Диагностика

Для диагностики используется утилита `ss`. Подробнее см. [[Мониторинг сети|../../Diagnostics/network_monitoring.md]].

Подсчитать количество сокетов в состоянии `TIME_WAIT`:
```bash
ss -tan 'state time-wait' | wc -l
```

#### Решение

Два основных параметра `sysctl` помогают решить эту проблему:

1.  **`net.ipv4.tcp_tw_reuse`**: Разрешает ядру повторно использовать сокеты в состоянии `TIME_WAIT` для *новых исходящих* соединений, если это безопасно. Это наиболее эффективный и безопасный способ борьбы с нехваткой портов.
    ```ini
    # /etc/sysctl.conf
    # Разрешить повторное использование сокетов в состоянии TIME_WAIT
    net.ipv4.tcp_tw_reuse = 1
    ```
    **Важно:** Этот параметр безопасен и рекомендуется для большинства серверов. Он не затрагивает входящие соединения.

2.  **`net.ipv4.tcp_fin_timeout`**: Уменьшает время, в течение которого сокет находится в состоянии `FIN-WAIT-2` (одна из стадий закрытия соединения). По умолчанию `60`. Уменьшение этого значения помогает быстрее освобождать ресурсы.
    ```ini
    # /etc/sysctl.conf
    # Уменьшить время ожидания в FIN-WAIT-2
    net.ipv4.tcp_fin_timeout = 30
    ```

**Что насчет `tcp_tw_recycle`?**
Параметр `net.ipv4.tcp_tw_recycle` **устарел и считается опасным**. Он был удален из ядер Linux начиная с версии 4.12. Его использование может приводить к отбрасыванию легитимных пакетов от клиентов, находящихся за одним NAT. **Никогда не используйте `tcp_tw_recycle`**.

### 2. Алгоритм контроля перегрузки: BBR

**BBR (Bottleneck Bandwidth and Round-trip time)** — это современный алгоритм управления перегрузкой сети, разработанный Google. В отличие от классических алгоритмов, основанных на потерях (таких как CUBIC), BBR пытается смоделировать реальную пропускную способность канала и задержку.

Это позволяет достичь значительно более высокой производительности и низкой задержки, особенно в сетях с потерями или большой задержкой (Long-Fat Networks).

#### Принцип работы

1.  **Разведка:** BBR периодически ненадолго увеличивает скорость отправки, чтобы проверить, не выросла ли доступная пропускная способность канала.
2.  **Дренаж:** После разведки он, наоборот, немного снижает скорость, чтобы "осушить" возможные очереди пакетов на маршрутизаторах, тем самым уменьшая задержку (bufferbloat).
3.  **Стабильная работа:** Основное время BBR работает на рассчитанной оптимальной скорости, которая обеспечивает максимальную пропускную способность при минимальной задержке.

#### Как включить BBR

1.  **Проверка версии ядра:** BBR требует ядро Linux версии `4.9` или выше.
    ```bash
    uname -r
    ```

2.  **Проверка доступных алгоритмов:** Убедитесь, что `bbr` есть в списке.
    ```bash
    sysctl net.ipv4.tcp_available_congestion_control
    # Вывод должен содержать "bbr"
    ```

3.  **Настройка `sysctl`:** Добавьте следующие строки в `/etc/sysctl.conf`:
    ```ini
    # /etc/sysctl.conf

    # Включить Fair Queuing (обязательно для BBR)
    net.core.default_qdisc = fq

    # Установить BBR как алгоритм контроля перегрузки
    net.ipv4.tcp_congestion_control = bbr
    ```

4.  **Применение и проверка:**
    ```bash
    # Применить настройки
    sudo sysctl -p

    # Проверить, что BBR используется для текущих соединений
    ss -ti | grep bbr
    # Должен появиться вывод с информацией о соединениях, использующих bbr
    ```

BBR является отличным выбором для большинства современных серверов, особенно тех, которые отдают контент (веб-серверы, видеостриминг, файловые хранилища).
