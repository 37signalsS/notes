# RSS, RPS, RFS: Многопоточная обработка сетевого трафика

## Определения

* **RSS (Receive Side Scaling)** — аппаратная технология, реализованная в сетевых картах (NIC), которая распределяет входящие сетевые пакеты по нескольким очередям приема (RX queues), привязанным к разным ядрам CPU.
* **RPS (Receive Packet Steering)** — программная технология в ядре Linux, выполняющая функцию RSS на уровне ПО. Распределяет пакеты между CPU после получения сетевой картой.
* **RFS (Receive Flow Steering)** — программное расширение RPS, направляющее пакеты одного сетевого потока (flow) на то ядро CPU, где работает приложение, обрабатывающее этот поток. Повышает локальность кэша.
* **NUMA (Non-Uniform Memory Access)** — архитектура памяти, где время доступа к памяти зависит от расположения ядра CPU относительно физической памяти.

## Основные концепции

### Проблема одного ядра

На высокоскоростных сетевых интерфейсах (10 Гбит/с и выше) обработка прерываний (IRQ) от сетевой карты на одном ядре CPU становится «узким местом». Это приводит к:

* Неравномерному распределению нагрузки
* Увеличению задержек (latency)
* Потерям пакетов

### Принципы работы

**RSS (аппаратный уровень):**

1. Сетевая карта вычисляет хеш от полей пакета (4-tuple: IP источника/назначения, порт источника/назначения).
2. На основе хеша пакет помещается в одну из нескольких RX-очередей.
3. Каждая RX-очередь привязана к своему ядру CPU, которое обрабатывает прерывание.

**RPS (программный уровень):**

1. Пакет принимается сетевой картой (в одну очередь).
2. Ядро Linux вычисляет хеш и решает, какому CPU передать пакет.
3. Работает на любом оборудовании без специальной поддержки NIC.

**RFS (улучшение RPS):**

1. При выполнении системного вызова (`recv()`) ядро запоминает CPU сокета.
2. Новые пакеты для этого сокета направляются на то же ядро.
3. Увеличивает вероятность попадания в кэш CPU (`cache hit rate`).

### NUMA-оптимизация

В NUMA-системах критически важно размещение компонентов на одной ноде:

* Прерывания (IRQ) от NIC должны обрабатываться CPU той же NUMA-ноды, где установлена карта.
* Приложение должно быть привязано к ядрам той же NUMA-ноды (команда `numactl`).

## Практические сценарии

### Диагностика и мониторинг

```bash
# Проверка загрузки CPU по ядрам (выявление перегруженного ядра)
mpstat -P ALL 1

# Мониторинг программных прерываний (softirq)
watch -n 1 'cat /proc/softirqs'

# Просмотр статистики прерываний для сетевой карты
cat /proc/interrupts | grep eth0
```

### Настройка RSS

> Подробное управление аппаратными очередями через [`ethtool -L/-l`](../Tools/ethtool.md#управление-многопоточной-обработкой-rss).

RSS — предпочтительный вариант при поддержке сетевой картой.

### Настройка RPS

Используется при отсутствии аппаратной поддержки RSS или для дополнительной балансировки.

```bash
# Для очереди rx-0 разрешить обработку на CPU 0-3 (маска 0xf)
echo f > /sys/class/net/eth0/queues/rx-0/rps_cpus

# Для очереди rx-1 разрешить обработку на CPU 4-7 (маска 0xf0)
echo f0 > /sys/class/net/eth0/queues/rx-1/rps_cpus

# Рекомендация: не назначать RPS на CPU, обрабатывающие аппаратные прерывания
```

### Настройка RFS

Включается вместе с RPS для максимальной производительности.

```bash
# Установить глобальный размер таблицы отслеживания потоков
echo 32768 > /proc/sys/net/core/rps_sock_flow_entries

# Установить размер таблицы для конкретной RX-очереди
# Значение = rps_sock_flow_entries / <число_rx_очередей>
echo 4096 > /sys/class/net/eth0/queues/rx-0/rps_flow_cnt
```

### Привязка прерываний (IRQ Affinity)

Для NUMA-оптимизации или ручного распределения прерываний.

```bash
# Определить номер прерывания для очереди
IRQ_NUM=$(cat /proc/interrupts | grep 'eth0-rx-0' | awk '{print $1}' | tr -d ':')

# Привязать прерывание к CPU 0 (маска '1')
echo 1 > /proc/irq/$IRQ_NUM/smp_affinity

# Привязать к CPU 0-3 (маска 'f')
echo f > /proc/irq/$IRQ_NUM/smp_affinity
```

## Дополнительная информация

### Типичные проблемы и решения

| Проблема | Диагностика | Решение |
|----------|-------------|---------|
| Перегрузка одного CPU | `mpstat` показывает 100% на одном ядре | Проверить RSS через [`ethtool -l`](../Tools/ethtool.md#управление-многопоточной-обработкой-rss), настроить [`ethtool -L`](../Tools/ethtool.md#управление-многопоточной-обработкой-rss) или включить RPS |
| Высокий `cache miss rate` | Профилирование приложения | Включить RFS для обработки на одном ядре |
| Задержки между NUMA-нодами | `numactl --hardware` | Привязать IRQ и приложение к одной NUMA-ноде |
