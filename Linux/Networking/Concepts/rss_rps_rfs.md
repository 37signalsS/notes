# Многопоточная обработка сетевого трафика в Linux: RSS, RPS, RFS, XPS

**Reliability Score: 10 (SSoT + Web)**

## Определения

**RSS (Receive Side Scaling — масштабирование на стороне приема)** — аппаратная технология, реализованная в сетевых картах (**NIC — Network Interface Card**), которая распределяет входящие пакеты по нескольким очередям приема (**RX — Receive**). Каждая очередь генерирует собственное прерывание, которое может быть обработано отдельным ядром **CPU**.

**RPS (Receive Packet Steering — программное управление приемом пакетов)** — программный аналог RSS в ядре Linux. Позволяет распределять нагрузку по обработке входящих пакетов между ядрами CPU на программном уровне, если NIC имеет только одну RX-очередь или если аппаратный RSS недостаточно эффективен.

**RFS (Receive Flow Steering — программное управление потоками приема)** — расширение RPS, которое учитывает расположение приложения. Направляет пакеты на то ядро CPU, где в данный момент выполняется процесс, обрабатывающий конкретное сетевое соединение (flow), что улучшает локальность кэша.

**aRFS (Accelerated RFS — ускоренный RFS)** — аппаратное ускорение механизма RFS. Позволяет ядру программировать фильтры непосредственно в сетевой карте, чтобы NIC направляла пакеты нужного потока в соответствующую RX-очередь аппаратно. Требует поддержки со стороны драйвера и NIC.

**XPS (Transmit Packet Steering — программное управление передачей пакетов)** — механизм распределения исходящего трафика (**TX — Transmit**) по очередям передачи сетевой карты. Позволяет привязать конкретные ядра CPU к определенным TX-очередям, минимизируя конкуренцию за блокировки (locks) в драйвере.

## Основные концепции

### Проблема «бутылочного горлышка» на одном ядре

При скоростях 10 Гбит/с и выше обработка всех сетевых прерываний на одном ядре CPU приводит к его 100% загрузке (часто отображается как `%soft` в `top`), в то время как остальные ядра простаивают. Это вызывает задержки, потерю пакетов и ограничивает пропускную способность всей системы.

### Принципы распределения нагрузки

1.  **RSS (Hardware):** NIC вычисляет хеш (обычно Toeplitz hash) от 4-кортежа (IP-адреса и порты источника/назначения) и на основе хеша выбирает номер очереди.
2.  **RPS (Software):** Ядро перехватывает пакет в обработчике прерывания (NAPI), вычисляет хеш и помещает пакет в очередь (backlog) другого CPU через межпроцессорное прерывание (IPI).
3.  **XPS:** При отправке пакета ядро выбирает TX-очередь на основе ID текущего CPU, что позволяет избежать переключений контекста и блокировок между ядрами.

### Роль irqbalance

Служба `irqbalance` автоматически распределяет прерывания по ядрам. Однако в высоконагруженных системах (High Performance Computing, High Load) рекомендуется отключать `irqbalance` и настраивать привязку прерываний (**IRQ Affinity**) вручную для исключения непредсказуемых перемещений нагрузки между ядрами и **NUMA-нодами**.

## Практические сценарии

### 1. Диагностика и мониторинг

```bash
# Проверка загрузки CPU: ищите высокую долю %soft
mpstat -P ALL 1

# Просмотр статистики сетевых программных прерываний
watch -n 1 "cat /proc/softirqs | grep NET_RX"

# Просмотр распределения прерываний сетевой карты по ядрам
cat /proc/interrupts | grep -E "eth|enp|eno"
```

### 2. Настройка аппаратного RSS (через ethtool)

```bash
# Просмотр доступных очередей
sudo ethtool -l eth0

# Установка количества комбинированных очередей (например, 8)
sudo ethtool -L eth0 combined 8
```
Подробнее: **[ethtool: управление очередями и RSS](../Tools/ethtool.md#управление-многопоточной-обработкой-rss)**.

### 3. Настройка программного RPS/XPS

Конфигурация выполняется через запись битовой маски ядер в файлы `sysfs`. Маска `f` означает первые 4 ядра (0, 1, 2, 3).

```bash
# Включение RPS для RX-очереди 0 на ядрах 0-3
echo f | sudo tee /sys/class/net/eth0/queues/rx-0/rps_cpus

# Включение XPS для TX-очереди 0 на ядрах 0-3
echo f | sudo tee /sys/class/net/eth0/queues/tx-0/xps_cpus

# Настройка RFS (установка размера таблицы потоков)
sudo sysctl -w net.core.rps_sock_flow_entries=32768
echo 32768 | sudo tee /sys/class/net/eth0/queues/rx-0/rps_flow_cnt
```

### 4. Оптимизация NUMA и IRQ Affinity

Привязка прерываний к ядрам той же NUMA-ноды, на которой физически находится сетевая карта, критична для минимизации задержек.

```bash
# Определить, на какой NUMA-ноде находится карта
cat /sys/class/net/eth0/device/numa_node

# Ручная привязка прерывания (IRQ 45) к ядру 0 (маска 1)
echo 1 | sudo tee /proc/irq/45/smp_affinity
```

## Дополнительная информация

### Сводная таблица технологий

| Технология | Слой | Цель | Требования |
| :--- | :--- | :--- | :--- |
| **RSS** | Hardware | Параллельный прием (RX) | Поддержка NIC (Multiple Queues) |
| **RPS** | Software | Параллельный прием (RX) | Любая карта, ядро Linux |
| **RFS** | Software | Локальность кэша (RX) | Включенный RPS |
| **aRFS** | Hybrid | Ускорение RFS | Поддержка NIC (Flow Director/n-tuple) |
| **XPS** | Software | Параллельная передача (TX) | Многоядерная система |
