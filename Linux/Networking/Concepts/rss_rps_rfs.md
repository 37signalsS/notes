# RSS, RPS, RFS, XPS: Многопоточная обработка сетевого трафика

## Определения

* **RSS (Receive Side Scaling — масштабирование на стороне приема)** — аппаратная технология, реализованная в сетевых картах **NIC (Network Interface Card — сетевой адаптер)**, которая распределяет входящие сетевые пакеты по нескольким очередям приема (**RX — Receive**), привязанным к разным ядрам **CPU (Central Processing Unit — центральный процессор)**.
* **RPS (Receive Packet Steering — программное управление приемом пакетов)** — программная технология в ядре Linux, выполняющая функцию RSS на уровне программного обеспечения. Распределяет пакеты между CPU после их получения сетевой картой.
* **RFS (Receive Flow Steering — программное управление потоками приема)** — программное расширение RPS, направляющее пакеты одного сетевого потока (flow) на то ядро CPU, где работает приложение, обрабатывающее этот поток. Повышает локальность кэша процессора.
* **XPS (Transmit Packet Steering — программное управление передачей пакетов)** — механизм распределения исходящего трафика (**TX — Transmit**) по очередям передачи сетевой карты, предотвращающий конкуренцию между ядрами CPU за одну очередь.
* **NUMA (Non-Uniform Memory Access — неравномерный доступ к памяти)** — архитектура памяти, в которой время доступа к данным зависит от расположения ядра CPU относительно физической планки памяти.

## Базовые концепции

### Проблема одного ядра

На высокоскоростных интерфейсах (10 Гбит/с и выше) обработка прерываний **IRQ (Interrupt Request — запрос прерывания)** от сетевой карты на одном ядре CPU становится узким местом. Это приводит к неравномерному распределению нагрузки, увеличению задержек (latency) и потере пакетов.

### Принципы работы

**RSS (аппаратный уровень):**

1. NIC вычисляет хеш-сумму от заголовков входящего пакета (обычно по IP-адресам и портам источника/назначения).
2. На основе хеша пакеты распределяются по разным RX-очередям.
3. Каждая очередь привязывается к отдельному ядру CPU через **IRQ affinity (привязка прерываний)**.
4. Обработка трафика параллелится на аппаратном уровне.

**RPS (программный уровень):**

1. Пакет принимается NIC в одну очередь (или если RSS недостаточно эффективен).
2. Ядро Linux вычисляет хеш и передает пакет в очередь другого CPU для дальнейшей обработки.
3. Работает на любом оборудовании, не требуя поддержки со стороны NIC.

**RFS (оптимизация потоков):**

1. При выполнении системного вызова приложением ядро запоминает, на каком CPU работает соответствующий сокет.
2. Новые пакеты для этого сокета направляются на то же ядро, минимизируя перемещение данных между кэшами ядер.

## Практические сценарии

### 1. Диагностика загрузки ядер

Для выявления перегруженного ядра, обрабатывающего прерывания:

```bash
# Проверка загрузки CPU по ядрам (поле %soft — программные прерывания)
mpstat -P ALL 1

# Мониторинг сетевых softirq в реальном времени
watch -n 1 'cat /proc/softirqs | grep NET_RX'

# Просмотр статистики прерываний сетевой карты eth0
cat /proc/interrupts | grep eth0
```

### 2. Настройка аппаратного RSS

Управление количеством очередей осуществляется через `ethtool`.

```bash
# Посмотреть количество поддерживаемых и активных очередей
sudo ethtool -l eth0

# Установить 4 очереди (если поддерживается)
sudo ethtool -L eth0 combined 4
```

Подробнее: **[Утилита ethtool](../Tools/ethtool.md)**.

### 3. Настройка программного RPS/XPS

Используется, если NIC не поддерживает многопоточность или для тонкой настройки.

```bash
# Разрешить обработку RX-очереди 0 на ядрах 0-3 (маска f)
echo f > /sys/class/net/eth0/queues/rx-0/rps_cpus

# Разрешить передачу через TX-очередь 0 с ядер 0-3 (маска f)
echo f > /sys/class/net/eth0/queues/tx-0/xps_cpus
```

### 4. Привязка прерываний (IRQ Affinity)

Для исключения пересылки данных между **NUMA-нодами** рекомендуется привязывать прерывания к ядрам той же ноды, где находится NIC.

```bash
# Определить номер прерывания
cat /proc/interrupts | grep eth0

# Привязать прерывание к CPU 0 (маска 1)
echo 1 > /proc/irq/<IRQ_NUM>/smp_affinity
```

## Дополнительная информация

### Типичные проблемы

| Проблема | Признак | Решение |
| :--- | :--- | :--- |
| Перегрузка одного ядра | Высокий `%soft` на одном CPU | Включить RSS/RPS, настроить балансировку IRQ |
| Низкий `cache hit rate` | Просадка производительности приложения | Включить RFS |
| Конфликты на передаче | Ошибки в статистике TX | Настроить XPS |
| Межпроцессорные задержки | Активность на разных NUMA-нодах | Использовать `numactl`, привязать IRQ к локальной ноде |

### Взаимодействие с разгрузкой (Offloading)

Технологии агрегации пакетов (GRO, LRO) могут конфликтовать с механизмами балансировки, так как объединяют пакеты до их распределения по ядрам. При использовании GRO/LRO критически важно правильно настроить маски RPS.
