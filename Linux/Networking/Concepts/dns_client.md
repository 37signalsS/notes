# DNS-клиент в Linux: конфигурация и принципы работы

## Определения

* **DNS-клиент (Domain Name System — система доменных имен)** — программное обеспечение или компонент **ОС (Операционная Система)**, ответственный за разрешение доменных имен в **IP-адреса (Internet Protocol — межсетевой протокол)** и наоборот. В Linux управляется комбинацией конфигурационных файлов и служб.
* **Системный резолвер glibc (GNU C Library — библиотека С проекта GNU)** — механизм, использующий файл `/etc/nsswitch.conf` для определения порядка и источников разрешения имен.
* **NSS (Name Service Switch — переключатель служб имен)** — механизм Linux, определяющий источники данных для разрешения имен: локальные файлы (`files`), DNS (`dns`), **mDNS (Multicast DNS — многоадресный DNS)** (`mdns_minimal`) и другие.

## Базовые концепции

### Порядок разрешения имен

Разрешение доменных имен в Linux — многоэтапный процесс, управляемый конфигурационными файлами в строго определенном порядке.

```
Приложение (браузер, curl)
    ↓
Системный резолвер (glibc)
    ↓
/etc/nsswitch.conf (порядок: files → dns)
    ↓
┌─────────────────┬─────────────────┐
│   /etc/hosts    │   DNS-серверы   │
│   (локально)    │   (резолвер)    │
└─────────────────┴─────────────────┘
    ↓
DNS-кэш ОС (если включен, например systemd-resolved)
    ↓
┌─────────────────────────────────┐
│  Корневые DNS-серверы (.)       │
│  → TLD-серверы (.com, .ru)      │
│  → Авторитетные серверы         │
└─────────────────────────────────┘
```

**TLD (Top-Level Domain — домен верхнего уровня)** — часть доменного имени, расположенная в конце (например, `.com`, `.ru`).

### Файлы конфигурации

| Файл | Назначение |
| :--- | :--- |
| `/etc/nsswitch.conf` | Порядок разрешения (строка `hosts:`) |
| `/etc/hosts` | Локальная статическая таблица IP ↔ имя (наивысший приоритет) |
| `/etc/resolv.conf` | DNS-серверы, search-домены, опции резолвера |
| `/etc/systemd/resolved.conf` | Параметры `systemd-resolved` (кэширующий резолвер) |

## Практические сценарии

### 1. Настройка nsswitch.conf — порядок разрешения

Строка `hosts:` определяет последовательность источников и условия перехода между ними:

```
hosts:          files mdns_minimal [NOTFOUND=return] dns
```

| Источник | Описание |
| :--- | :--- |
| `files` | Проверка `/etc/hosts` (локальные переопределения) |
| `dns` | Запрос к DNS-серверам из `/etc/resolv.conf` |
| `mymachines` | Разрешение имен локальных контейнеров/ВМ (`systemd-machined`) |
| `mdns_minimal` | Multicast DNS для `.local` доменов (Avahi/Bonjour) |

В квадратных скобках указываются условия, которые могут остановить цепочку. Например, `[NOTFOUND=return]` означает: «если имя не найдено в этом источнике, прекратить поиск и не переходить к следующему».

### 2. Проверка системного резолвинга (getent)

Для проверки того, как система разрешает имя, следует использовать `getent`, а не `dig` или `nslookup`.

* **`getent hosts <domain>`** — использует системные библиотеки (glibc) и проходит по всей цепочке из `nsswitch.conf`.
* **`dig <domain>`** — обращается напрямую к DNS-серверу, игнорируя `/etc/hosts` и настройки NSS.

Если `getent` и `dig` возвращают разные IP — проблема в локальной конфигурации (`/etc/hosts` или порядок в `nsswitch.conf`).

### 3. Работа с /etc/hosts — локальная база данных

Статическая таблица соответствия IP-адресов и доменных имен.

* **Приоритет:** наивысший (если `files` стоит первым в `nsswitch.conf`). Если запись найдена в `/etc/hosts`, DNS-запрос не отправляется.
* **Формат:** `IP-адрес полное_имя_хоста короткое_имя`

    ```
    127.0.0.1   localhost
    10.20.30.40 fileserver.mycompany.local fileserver
    ```

Большинство процессов кэшируют результаты разрешения на момент запуска. При изменении `/etc/hosts` может потребоваться перезапуск процесса или очистка кэша резолвера (`resolvectl flush-caches`).

### 4. Настройка /etc/resolv.conf — DNS-серверы

Файл указывает системе, какие DNS-серверы использовать для запросов.

| Директива | Описание |
| :--- | :--- |
| `nameserver` | IP DNS-сервера (до 3 серверов, опрашиваются по порядку) |
| `search` | Список доменных суффиксов для коротких имен |
| `options` | Дополнительные параметры (например, `timeout:1`) |

**Пример:**

```
search mycompany.local
nameserver 8.8.8.8
nameserver 1.1.1.1
```

При `ping server1` система сначала попытается найти `server1.mycompany.local`.

## Дополнительная информация

### Служба systemd-resolved

В современных дистрибутивах за разрешение имен отвечает `systemd-resolved` — локальный кэширующий резолвер.

**Преимущества:**

* **Раздельный DNS (per-link):** **VPN (Virtual Private Network — виртуальная частная сеть)**, Wi-Fi и Ethernet не конфликтуют в настройках.
* **Кэширование:** повторные запросы не уходят в сеть, ускоряя работу.
* **Современные протоколы:** поддержка DNSSEC, **DoT (DNS-over-TLS — DNS поверх TLS)**, **LLMNR (Link-Local Multicast Name Resolution — разрешение имен в локальном сегменте)**.

**Принцип работы:**

1. Поднимает локальный DNS-сервер на адресе `127.0.0.53:53` (stub-резолвер).
2. `/etc/resolv.conf` превращается в симлинк на `/run/systemd/resolve/stub-resolv.conf`.

**Применение изменений:**

```bash
sudo systemctl restart systemd-resolved
```

### Интеграция с NetworkManager

**NetworkManager** может координировать работу с `systemd-resolved`:

```ini
# /etc/NetworkManager/NetworkManager.conf
[main]
dns=systemd-resolved
```

Конфликт возникает, когда обе службы пытаются управлять `/etc/resolv.conf` одновременно — файл может перезаписываться некорректно.
