# Network Offloading: GRO/LRO

**Offloading** — это технология переноса части задач по обработке сетевых пакетов с центрального процессора (CPU) на специализированное аппаратное обеспечение сетевой карты (NIC).

## Определения

- **GRO (Generic Receive Offload)**: Механизм в ядре Linux, который агрегирует несколько входящих пакетов, принадлежащих одному потоку, в один крупный "суперпакет" (SKB, `sk_buff`) перед их передачей в сетевой стек. Это значительно снижает количество пакетов, которые нужно обрабатывать ядру, и уменьшает overhead на каждый пакет. GRO является программной реализацией, работающей на уровне драйвера.

- **LRO (Large Receive Offload)**: Более старая и менее "умная" технология, выполняющая аналогичную функцию. LRO выполняется непосредственно на сетевой карте (аппаратно). Основной недостаток LRO в том, что он может нарушать TCP-семантику, объединяя пакеты с разными TCP-заголовками (например, флагами), что может приводить к проблемам при маршрутизации или для систем анализа трафика. По этой причине LRO в основном вытеснен технологией GRO.

## Принцип работы

1. Сетевая карта получает пакеты из сети.
2. Драйвер сетевой карты (для GRO) или сама карта (для LRO) анализирует пакеты.
3. Если пакеты принадлежат одному и тому же сетевому соединению (source/destination IP/port), они объединяются в один большой буфер.
4. Этот объединённый пакет передаётся сетевому стеку Linux как единое целое.

## Преимущества и недостатки

| Преимущества | Недостатки |
| :--- | :--- |
| **Снижение нагрузки на CPU** за счёт меньшего числа прерываний и обработок пакетов. | **Скрытая нагрузка на одно ядро CPU**: агрегированные пакеты обрабатываются тем ядром, которое обслуживает очередь RX. Без распределения прерываний (IRQ) и RPS вся работа концентрируется на одном ядре. |
| **Увеличение пропускной способности (throughput)**. | **Увеличение задержек (latency)**: время, затрачиваемое на ожидание и агрегацию пакетов, может приводить к небольшому росту latency. |
| **Снижение "затрат" на пакет (per-packet overhead)**. | **Проблемы с маршрутизацией и анализом трафика**: LRO может "ломать" TCP-семантику. GRO более безопасен в этом отношении. |
