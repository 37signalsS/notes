# Network Offloading: GRO, LRO, TSO

## Определения

* **Offloading (Сетевая разгрузка)** — технология переноса части задач по обработке сетевых пакетов с центрального процессора **CPU (Central Processing Unit)** на специализированное аппаратное обеспечение сетевой карты **NIC (Network Interface Card)** или на уровень ядра для оптимизации производительности.
* **GRO (Generic Receive Offload — общая разгрузка приема)** — механизм в ядре Linux, который агрегирует несколько входящих пакетов, принадлежащих одному потоку, в один крупный «суперпакет» **SKB (Socket Buffer — структура данных пакета в ядре)** перед передачей в сетевой стек. Программная реализация на уровне драйвера.
* **LRO (Large Receive Offload — большая разгрузка приема)** — аппаратная технология на NIC, выполняющая агрегацию входящих пакетов. Может нарушать семантику **TCP (Transmission Control Protocol)** при объединении пакетов с разными заголовками.
* **TSO (TCP Segmentation Offload — разгрузка сегментации TCP)** — механизм разделения крупных TCP-пакетов на более мелкие сегменты аппаратно на NIC перед отправкой в сеть.
* **GSO (Generic Segmentation Offload — общая разгрузка сегментации)** — программный аналог TSO на уровне ядра. Выполняет сегментацию пакетов непосредственно перед передачей драйверу NIC.
* **UFO (UDP Fragmentation Offload — разгрузка фрагментации UDP)** — аналог TSO для **UDP (User Datagram Protocol)** трафика.

## Базовые концепции

### Принцип работы

1. Сетевая карта получает пакеты из сети.
2. Драйвер NIC (для GRO) или сама карта (для LRO) анализирует заголовки.
3. Если пакеты принадлежат одному соединению (одинаковые IP-адреса и порты), они объединяются.
4. Объединенный пакет передается сетевому стеку Linux как единое целое, что снижает количество прерываний и нагрузку на CPU.

### Типы разгрузки

| Тип | Направление | Уровень | Описание |
| :--- | :--- | :--- | :--- |
| **GRO** | **RX (Receive — прием)** | Ядро/драйвер | Агрегация пакетов перед сетевым стеком |
| **LRO** | RX | Аппаратный | Агрегация пакетов на стороне NIC |
| **TSO** | **TX (Transmit — передача)** | Аппаратный | Сегментация больших TCP-пакетов |
| **GSO** | TX | Ядро | Программная сегментация (запасной вариант для TSO) |
| **Checksum** | RX/TX | Аппаратный | Вычисление контрольных сумм на NIC |
| **VLAN** | RX/TX | Аппаратный | Обработка тегов **VLAN (Virtual Local Area Network)** |

## Практические сценарии

### Проверка статуса параметров разгрузки

Для просмотра текущих настроек используется утилита `ethtool`.

```bash
# Проверка всех параметров разгрузки для интерфейса
sudo ethtool -k eth0

# Просмотр только активных параметров
sudo ethtool -k eth0 | grep "on"
```

### Временное изменение настроек

```bash
# Отключить GRO для минимизации задержек (latency)
sudo ethtool -K eth0 gro off

# Отключить TSO для отладки
sudo ethtool -K eth0 tso off

# Включить параметры обратно
sudo ethtool -K eth0 gro on tso on
```

### Сценарий: Оптимизация для низкой задержки (Latency)

Актуально для приложений реального времени, финансового трейдинга и VoIP.

```bash
# Отключение агрегации для мгновенной обработки каждого пакета
sudo ethtool -K eth0 gro off lro off tso off
```

### Сценарий: Диагностика трафика (tcpdump)

Hardware offload может существенно искажать результаты захвата трафика, так как `tcpdump` видит пакеты такими, какими их обрабатывает ядро, а не такими, какими они передаются в физическую среду.

#### Как это ломает диагностику

1.  **TSO/GSO (Исходящий трафик):** Ядро передает сетевой карте (NIC) один большой блок данных (до 64 КБ). Карта сама нарезает его на пакеты по 1500 байт (MSS) перед отправкой.
    - **В tcpdump:** Вы увидите гигантские исходящие пакеты по 30–60 КБ.
    - **Ложный вывод:** Можно ошибочно решить, что MTU на линке огромный или фрагментация сломана. В реальности в сеть уходят стандартные пакеты.
2.  **LRO/GRO (Входящий трафик):** NIC или ядро склеивает множество входящих пакетов в один большой перед передачей в сетевой стек.
    - **В tcpdump:** Вы увидите входящие пакеты, размер которых превышает MTU.
    - **Ложный вывод:** Ощущение «невозможных» пакетов в сети.

#### Рекомендации для «честной» диагностики

Если вы отлаживаете проблемы с MTU, фрагментацией или аномальным размером пакетов, необходимо временно отключить оффлоуды:

```bash
# Проверка текущего статуса
ethtool -k eth0 | grep -E "segmentation|receive"

# Отключение для диагностики
sudo ethtool -K eth0 tso off gso off lro off gro off

# Включение обратно после завершения работ
sudo ethtool -K eth0 tso on gso on gro on
```

**Альтернатива:** Захват трафика с зеркального порта коммутатора (SPAN). Там пакеты будут выглядеть именно так, как они передаются по проводу.
