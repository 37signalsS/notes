# Сетевая разгрузка в Linux: GRO, LRO, TSO, GSO

**Reliability Score: 10 (SSoT + Web)**

## Определения

**Сетевая разгрузка (Network Offloading)** — технология переноса части задач по обработке сетевых пакетов с центрального процессора (**CPU — Central Processing Unit**) на специализированное аппаратное обеспечение сетевой карты (**NIC — Network Interface Card**) или на уровень драйвера/ядра для оптимизации производительности.

**GRO (Generic Receive Offload — общая разгрузка приема)** — программный механизм в ядре Linux, который агрегирует несколько входящих пакетов одного потока в один крупный «суперпакет» (**SKB — Socket Buffer**) перед передачей в сетевой стек. GRO является более безопасной и универсальной альтернативой LRO.

**LRO (Large Receive Offload — большая разгрузка приема)** — аппаратная технология на стороне NIC, объединяющая входящие TCP-пакеты. **Важно:** LRO часто нарушает семантику TCP (например, объединяя пакеты с разными опциями TCP), что может привести к проблемам с маршрутизацией и диагностикой. В современных системах предпочтение отдается GRO.

**TSO (TCP Segmentation Offload — разгрузка сегментации TCP)** — аппаратный механизм, позволяющий сетевой карте самостоятельно разделять крупные блоки данных TCP на сегменты стандартного размера (MSS) перед отправкой в сеть. Это значительно снижает нагрузку на CPU при передаче больших объемов данных.

**GSO (Generic Segmentation Offload — общая разгрузка сегментации)** — программный аналог TSO на уровне ядра. Если сетевая карта не поддерживает TSO для конкретного протокола или типа пакета, ядро выполняет сегментацию в последний возможный момент (перед передачей драйверу), экономя циклы CPU на прохождение сетевого стека крупным пакетом.

**UFO (UDP Fragmentation Offload — разгрузка фрагментации UDP)** — устаревший механизм для UDP-трафика. Был удален из ядра Linux (начиная с версии 4.14) и заменен на **UDP GSO**.

## Основные концепции

### Принцип работы разгрузки на прием (RX)

1. Сетевая карта получает поток мелких пакетов.
2. Драйвер (для **GRO**) или карта (для **LRO**) анализирует заголовки (IP-адреса, порты, номера подтверждений TCP).
3. Пакеты, принадлежащие одному соединению, склеиваются в один большой буфер.
4. Сетевой стек ядра обрабатывает один большой пакет вместо 10–50 мелких, что сокращает количество прерываний и операций выделения памяти.

### Принцип работы разгрузки на передачу (TX)

1. Приложение передает ядру большой блок данных (до 64 КБ).
2. Сетевой стек формирует один гигантский пакет.
3. Если включен **TSO**, ядро передает этот пакет сетевой карте целиком.
4. Сетевая карта аппаратно нарезает его на сегменты (MTU/MSS), вычисляет контрольные суммы и отправляет в сеть.

### Сводная таблица типов разгрузки

| Тип | Направление | Реализация | Описание |
| :--- | :--- | :--- | :--- |
| **GRO** | **RX (Прием)** | Ядро/Драйвер | Безопасная программная агрегация |
| **LRO** | RX | Аппаратная | Аппаратная агрегация (может ломать трафик) |
| **TSO** | **TX (Передача)** | Аппаратная | Сегментация TCP на стороне NIC |
| **GSO** | TX | Ядро | Программная сегментация (fallback для TSO) |
| **Checksum** | RX/TX | Аппаратная | Вычисление контрольных сумм IP/TCP/UDP |
| **VXLAN/Tunnel** | RX/TX | Аппаратная | Разгрузка для инкапсулированного трафика (оверлейные сети) |

## Практические сценарии

Управление параметрами осуществляется с помощью утилиты **[ethtool](../Tools/ethtool.md)**.

### 1. Просмотр и изменение настроек

```bash
# Просмотр текущего статуса всех функций разгрузки
sudo ethtool -k eth0

# Отключение функций (например, для диагностики или при проблемах с VPN)
sudo ethtool -K eth0 gro off tso off

# Включение функций для повышения производительности
sudo ethtool -K eth0 gro on tso on
```

### 2. Сценарий: Диагностика трафика (tcpdump/Wireshark)

Технологии разгрузки создают «оптические иллюзии» при захвате трафика, так как инструменты перехватывают пакеты на уровне ядра, а не «на проводе».

#### Ложные аномалии:
*   **Гигантские пакеты:** Вы видите исходящие пакеты по 30–60 КБ в `tcpdump`. Это не нарушение MTU, а работа **TSO/GSO** (ядро еще не нарезало пакет).
*   **Ошибки контрольных сумм:** Wireshark может помечать пакеты как битые (Checksum Error), так как контрольная сумма еще не вычислена (это сделает NIC позже).

#### Рекомендация для диагностики:
Если вы отлаживаете проблемы с MTU, фрагментацией или странным поведением TCP, **всегда** временно отключайте оффлоуды:
```bash
sudo ethtool -K eth0 tso off gso off gro off lro off
```

### 3. Разгрузка туннелей (VXLAN, GENEVE)

В виртуализированных средах (Kubernetes, OpenStack) трафик часто инкапсулируется. Современные сетевые карты поддерживают **Tunnel Offloading**, позволяя выполнять TSO/CSUM внутри инкапсулированного пакета. Если оффлоад не поддерживается, нагрузка на CPU при использовании VXLAN возрастает в разы.

## Дополнительная информация

### Конфликты с многопоточной обработкой
Технологии агрегации (GRO/LRO) могут конфликтовать с механизмами распределения трафика по ядрам CPU. Если пакеты агрегируются слишком рано, они могут быть направлены на одно ядро, создавая бутылочное горлышко. В таких случаях требуется тонкая настройка **[RSS, RPS, RFS](./rss_rps_rfs.md)**.
