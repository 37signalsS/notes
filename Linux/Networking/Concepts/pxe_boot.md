# PXE: Загрузка по сети

## Определения

*   **PXE (Preboot Execution Environment)** — это стандартная среда, позволяющая компьютеру загружаться по сети, используя только свою сетевую карту, без необходимости в локальном загрузочном устройстве (жестком диске, USB).

## Базовые концепции

PXE является стандартом де-факто для автоматической установки ОС в дата-центрах, запуска бездисковых рабочих станций и систем восстановления.

### Компоненты PXE-инфраструктуры

1.  **Клиент:** Компьютер с сетевой картой, поддерживающей PXE.
2.  **DHCP-сервер:** Выдает клиенту IP-адрес и, что самое важное, передает информацию о местонахождении TFTP-сервера (`next-server`) и имени файла для загрузки (`filename`).
3.  **TFTP-сервер:** Простой файловый сервер, который отдает по сети **NBP (Network Boot Program)** — программу сетевой загрузки.
4.  **Файловый сервер (HTTP/NFS):** Хранит ядро, `initrd` и основной образ операционной системы.

### Процесс загрузки

1.  **BIOS/UEFI** инициализирует сетевую карту.
2.  Сетевая карта отправляет широковещательный **DHCP-запрос**.
3.  **DHCP-сервер** отвечает, предоставляя IP-адрес и опции `next-server` (IP TFTP-сервера) и `filename` (имя загрузчика, например `pxelinux.0` или `ipxe.efi`).
4.  Клиент скачивает **NBP** с TFTP-сервера в оперативную память и исполняет его.
5.  NBP (например, `PXELINUX`) скачивает свою конфигурацию, ядро Linux (`vmlinuz`) и `initrd`.
6.  Запускается ядро, которое монтирует корневую файловую систему по сети (через [[NFS|../Services/nfs.md]]/iSCSI) или начинает автоматическую установку ОС, скачивая файлы с HTTP-сервера.

Подробнее о [[процессе загрузки Linux|../../Core/boot_process.md]].

## Практические сценарии

### 1. Настройка PXE-загрузки в BIOS/UEFI

-   Войдите в BIOS/UEFI.
-   Найдите раздел `Boot` или `Advanced`.
-   Включите опцию `Network Boot` или `LAN Boot`.
-   Установите сетевую карту (`Network Adapter`, `Onboard LAN`) в качестве первого загрузочного устройства.

### 2. Развертывание PXE-сервера

-   **[[DHCP-сервер: Развертывание и настройка|../Services/dhcp_server.md]]**

-   **TFTP-сервер (например, `tftpd-hpa`):**
    -   В корневой директории TFTP (часто `/srv/tftp/`) размещаются:
        -   Загрузчик `pxelinux.0`.
        -   Директория `pxelinux.cfg/` с конфигурационными файлами.
        -   Ядро `vmlinuz` и `initrd`.

-   **HTTP/NFS-сервер:**
    -   Предоставляет доступ к файлам установки ОС (например, `kickstart` для CentOS/RHEL или `preseed` для Debian/Ubuntu).

## Дополнительная информация

### iPXE: продвинутый сетевой загрузчик

**iPXE** — это мощная open-source реализация PXE, которая значительно расширяет его возможности. В отличие от традиционного PXE, встроенного в прошивку, iPXE можно загрузить по цепочке (chainloading), и он умеет:
-   Загружать образы по **HTTP**, iSCSI, Fibre Channel.
-   Работать с Wi-Fi сетями.
-   Исполнять скрипты для сложной логики загрузки.
-   Проходить аутентификацию.

Это позволяет, например, отказаться от медленного и примитивного TFTP в пользу HTTP.

### PXE в средах UEFI

-   **Разные загрузчики:** Для Legacy BIOS и UEFI требуются разные загрузчики. `pxelinux.0` предназначен для BIOS, в то время как для UEFI обычно используются `.efi` файлы (например, `shim.efi`, `grubx64.efi` или `ipxe.efi`).
-   **Secure Boot:** В средах с включенным Secure Boot загрузчики `.efi` должны быть подписаны доверенным ключом. Это добавляет сложности в настройку, так как требуется подписывать загрузчики или использовать предписанные (shim).

### Безопасность

Стандартный PXE не включает в себя шифрование. Трафик между клиентом, DHCP и TFTP-сервером передается в открытом виде. Это создает риски:
-   **Rogue DHCP Server:** Злоумышленник может поднять свой DHCP-сервер и подсунуть клиенту вредоносный загрузчик.
-   **Перехват данных:** Конфигурационные файлы, передаваемые по TFTP, могут содержать чувствительную информацию.

Для защиты рекомендуется:

-   Использовать iPXE с загрузкой по HTTPS.
-   Изолировать PXE-сегмент сети (VLAN).
-   Использовать функции безопасности коммутаторов, такие как [[DHCP Snooping|../../../Networking/Protocols/dhcp.md#dhcp-snooping]].
