# Оптимизация сетевых каналов и снижение латентности

## Определения

* **Сетевая латентность (Network Latency — сетевая задержка)** — время, необходимое для передачи пакета данных от источника к получателю. Измеряется как в одну сторону, так и в обе (**RTT — Round-Trip Time**).
* **Bufferbloat (Раздувание буфера)** — проблема избыточной буферизации в сетевых устройствах, приводящая к непредсказуемым скачкам задержек и джиттеру при высокой нагрузке на канал.
* **Хвостовая латентность (Tail Latency — задержка в хвосте)** — метрики (**p95/p99**), отражающие время ответа для наихудших 5% или 1% запросов.
* **Джиттер (Jitter)** — вариация задержки между пакетами. Высокий джиттер критичен для **VoIP (Voice over IP)**, видеосвязи и систем реального времени.

## Базовые концепции

Латентность складывается из суммы задержек на разных этапах:

1. **Задержка распространения (Propagation Delay)** — время прохождения сигнала через физическую среду (зависит от скорости света и расстояния).
2. **Задержка передачи (Transmission Delay)** — время, необходимое для «выталкивания» всех бит пакета в канал (зависит от пропускной способности).
3. **Задержка обработки (Processing Delay)** — время на анализ заголовков маршрутизаторами и хостами.
4. **Задержка в очередях (Queuing Delay)** — время ожидания пакета в буферах оборудования при перегрузке.

### Цели оптимизации

* **Минимизация очередей** на всех уровнях сетевого стека.
* **Сокращение количества операций** (уменьшение числа рукопожатий **Handshakes**, использование **Zero-copy**).
* **Параллелизация обработки** прерываний и пакетов между ядрами **CPU (Central Processing Unit)**.
* **Приоритизация трафика** (маркировка критичных пакетов).

## Практические сценарии: Уровни оптимизации

### 1. Уровень ядра: Тюнинг TCP/IP стека

Параметры ядра позволяют адаптировать поведение стека под задачи (пропускная способность vs задержка).

| Направление | Описание | Основной источник |
| :--- | :--- | :--- |
| **Алгоритмы перегрузки** | Использование `BBR` вместо `CUBIC` для стабильного RTT | **[Алгоритмы контроля перегрузки](./tcp_tuning/tcp_congestion_algorithms.md)** |
| **Дисциплины очередей** | Борьба с bufferbloat через `fq_codel` или `Cake` | **[Дисциплины очередей TCP](./tcp_tuning/tcp_queueing_disciplines.md)** |
| **Буферы и очереди** | Настройка `netdev_max_backlog` и `somaxconn` | **[Тюнинг буферов TCP](./tcp_tuning/tcp_buffer_tuning.md)** |
| **Быстрое открытие** | **TCP Fast Open** для исключения RTT при установке связи | **[TCP Fast Open](./tcp_tuning/tcp_fast_open.md)** |

### 2. Уровень сетевой карты (NIC) и драйвера

Разгрузка центрального процессора и эффективное распределение прерываний.

* **Балансировка нагрузки:** Использование **RSS**, **RPS**, **RFS** для распределения обработки пакетов по ядрам.
  * *Подробнее:* **[RSS, RPS, RFS в Linux](./rss_rps_rfs.md)**.
* **Сетевая разгрузка (Offloading):** Перенос вычисления контрольных сумм и сегментации на **NIC (Network Interface Card)**.
  * *Подробнее:* **[Network Offloading (GRO/LRO/TSO)](./offloading.md)**.
* **Коалесценция прерываний (Interrupt Coalescing):** Объединение прерываний для снижения нагрузки на CPU (может увеличивать латентность).
  * *Управление:* **[Настройка ethtool](../Tools/ethtool.md)**.

### 3. Управление трафиком (QoS)

Использование **QoS (Quality of Service — качество обслуживания)** для защиты приоритетного трафика.

* **Инструмент tc (Traffic Control):** Классификация и приоритизация трафика на выходе из интерфейса.
  * *Подробнее:* **[Управление трафиком через tc](../Tools/iproute2/tc.md)**.
* **DSCP (Differentiated Services Code Point):** Маркировка пакетов на уровне **IP (Internet Protocol)** для приоритетной обработки сетевым оборудованием.

### 4. Уровень приложения и DNS

Оптимизация на уровне логики взаимодействия и протоколов.

* **DNS (Domain Name System):** Резолвинг часто становится причиной хвостовой латентности.
  * **Решение:** Локальное кэширование (**systemd-resolved**, **dnsmasq**).
  * *Диагностика:* **[DNS resolution performance](../../Diagnostics/Networking/dns/dns_resolution_performance.md)**.
* **HTTP (HyperText Transfer Protocol):** Переход на **HTTP/3 (QUIC)** для устранения блокировки начала очереди (**Head-of-Line Blocking**).
* **Connection Pooling:** Повторное использование установленных соединений для исключения фазы **Handshake**.

## Дополнительная информация

### Чек-лист быстрой диагностики

```bash
# Базовая проверка задержек и потерь
mtr -rwzc 100 8.8.8.8

# Проверка загрузки CPU сетевыми прерываниями (поле %soft)
mpstat -P ALL 1

# Просмотр статистики ошибок и дропов на интерфейсе
ethtool -S eth0 | grep -E "drop|error"

# Текущий алгоритм контроля перегрузки
sysctl net.ipv4.tcp_congestion_control
```
