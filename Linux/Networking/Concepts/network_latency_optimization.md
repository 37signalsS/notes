# Оптимизация сетевых каналов и снижение латентности

## Определения

**Сетевая латентность (Network Latency)** — время, необходимое для передачи пакета данных от источника к получателю. Ключевой показатель производительности сети.

**Bufferbloat** — проблема избыточной буферизации в сетевых устройствах, приводящая к непредсказуемым скачкам задержек и джиттеру.

**Хвостовая латентность (p95/p99 Latency)** — метрики, отражающие производительность для наихудших 5% или 1% запросов. Высокие значения указывают на периодические проблемы.

**Jitter** — вариация задержки между пакетами. Критичен для VoIP, видеостриминга, онлайн-игр.

## Основные концепции

Латентность складывается из нескольких компонентов:

1. **Время передачи** — зависит от пропускной способности канала
2. **Время распространения** — зависит от физического расстояния и среды
3. **Время обработки** — маршрутизаторы, коммутаторы, хосты
4. **Время ожидания в очередях** — основной источник задержек при перегрузках

### Цели оптимизации

1. **Уменьшить очереди** на всех уровнях стека
2. **Сократить количество операций** для обработки пакетов (рукопожатия, копирование данных)
3. **Параллелизировать обработку** для эффективного использования многоядерных систем
4. **Приоритизировать трафик** для критичных по задержкам приложений

## Практические сценарии: Уровни оптимизации

Оптимизация сетевой производительности — комплексная задача, затрагивающая несколько уровней системы.

### 1. Уровень ядра: Тюнинг TCP/IP стека

Настройки ядра через `sysctl` напрямую влияют на производительность.

| Параметр | Описание |
|----------|----------|
| **Алгоритмы контроля перегрузки** | Выбор между `CUBIC` (по умолчанию) и `BBR` | **[Оптимизация TCP](./tcp_tuning/tcp_congestion_algorithms.md)** |
| **Дисциплины очередей (Qdisc)** | `fq_codel`, `fq` для борьбы с bufferbloat | **[Оптимизация TCP](./tcp_tuning/tcp_queueing_disciplines.md)** |
| **Размеры буферов и очередей** | `somaxconn`, `netdev_max_backlog`, буферы TCP | **[Оптимизация TCP](./tcp_tuning/tcp_buffer_tuning.md)** |
| **TIME_WAIT управление** | `tcp_tw_reuse`, `tcp_fin_timeout` | **[Оптимизация TCP](./tcp_tuning/tcp_time_wait_management.md)** |
| **TCP Fast Open** | Сокращение handshake | **[Оптимизация TCP](./tcp_tuning/tcp_fast_open.md)** |

| Технология | Описание |

### DNS как источник задержек

DNS-резолвинг — частая причина **хвостовой латентности** (p95/p99). Задержка возникает не внутри приложения, а на этапе разрешения имени — до установления соединения.

**Источники задержек:**

| Причина | Механизм | Влияние |
|---------|----------|---------|
| **Блокирующий `getaddrinfo()`** | Вызов блокирует поток до получения ответа | В асинхронных сервисах влияет на все потоки |
| **Множественные nameserver'ы** | Запросы к каждому серверу по порядку из `/etc/resolv.conf` | +100–500 мс на каждый недоступный сервер |
| **IPv6 → IPv4 fallback** | При недоступности IPv6 происходит задержка до fallback | +50–200 мс |
| **Search-домены** | Поиск по списку доменов из `search` | Каждый домен — дополнительный запрос |
| **Медленные резолверы** | Высокая загрузка DNS или сетевые потери | Скачки от 5 мс до 500+ мс |

**Диагностика:**

```bash
# Трассировка задержек на DNS-вызовах
strace -tt -e trace=network,connect,recvfrom,sendto -p <pid>

# Измерение времени резолва
for i in {1..10}; do dig +stats example.com | grep "Query time"; done

# Проверка конфигурации
cat /etc/resolv.conf
```

**Оптимизация:**

1. **Кэширование на уровне ОС:** `nscd`, `systemd-resolved` (кэш включён по умолчанию)
2. **Кэширование на уровне приложения:** Встроенный DNS-кэш (если поддерживается фреймворком)
3. **Локальный резолвер:** `dnsmasq`, `unbound` для кэширования всех запросов
4. **Оптимизация `/etc/resolv.conf`:**
   ```
   search corp.local
   nameserver 10.0.0.1
   nameserver 8.8.8.8
   options timeout:1 attempts:2 ndots:1
   ```
5. **Для Kubernetes:** `NodeLocalDNS` для кэширования на каждой ноде

**См. также:** [Диагностика DNS-блокировок](../../Diagnostics/Networking/dns_diagnostics.md#сценарий-5-dns-resolution-как-узкое-место-производительности).

## Чек-лист оптимизации

### Быстрая диагностика

```bash
# 1. Измерить базовую задержку
ping -c 10 example.com

# 2. Проверить маршрут и потери
mtr -rwzc 100 example.com

# 3. Проверить загрузку CPU по ядрам
mpstat -P ALL 1

# 4. Проверить сетевые прерывания
watch -n 1 'cat /proc/interrupts | grep eth0'

# 5. Проверить offloading
ethtool -k eth0 | grep -E "on|off"

# 6. Проверить RSS очереди
ethtool -l eth0

# 7. Проверить TCP-параметры
sysctl -a | grep -E "net.ipv4.tcp|net.core"
```

### Приоритетные действия

| Приоритет | Действие | Ожидаемый эффект |
|-----------|----------|------------------|
| **1** | Включить BBR + fq | Снижение задержек на 20-40% |
| **2** | Настроить RSS/RPS | Равномерная загрузка CPU |
| **3** | Оптимизировать offloading | +20-40% пропускной способности |
| **4** | Увеличить буферы | Снижение потерь при всплесках |
| **5** | Настроить QoS | Приоритизация критичного трафика |
