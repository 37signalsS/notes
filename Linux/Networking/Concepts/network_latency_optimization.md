# Оптимизация сетевых каналов и снижение латентности

## Определения

*   **Сетевая латентность (Network Latency)**: Время, необходимое для передачи пакета данных от источника к получателю. Является ключевым показателем производительности сети.
*   **Bufferbloat**: Проблема избыточной буферизации в сетевых устройствах, которая приводит к непредсказуемым скачкам задержек и джиттеру.
*   **Хвостовая латентность (p95/p99 Latency)**: Метрики, отражающие производительность для наихудших 5% или 1% запросов. Высокие значения указывают на периодические проблемы, влияющие на пользовательский опыт.

# Основные концепции

Латентность в сети складывается из нескольких компонентов, но на практике доминируют два из них: **время ожидания в очередях** на сетевых устройствах и **время обработки пакетов** ядром и приложениями.

Цели оптимизации:
1.  **Уменьшить очереди** на всех уровнях стека.
2.  **Сократить количество операций**, необходимых для обработки пакетов (рукопожатия, копирование данных).
3.  **Параллелизировать обработку** для эффективного использования многоядерных систем.

# Практические сценарии: Уровни оптимизации

Оптимизация сетевой производительности — это комплексная задача, затрагивающая несколько уровней системы. Ниже приведен чек-лист для анализа и настройки.

### 1. Уровень ядра: Тюнинг TCP/IP стека
Настройки ядра, управляемые через `sysctl`, оказывают прямое влияние на производительность.
*   **Алгоритмы контроля перегрузки**: Выбор между `CUBIC` (по умолчанию) и `BBR`.
*   **Дисциплины очередей (Qdisc)**: Использование `fq_codel` или `fq` для борьбы с `bufferbloat`.
*   **Размеры буферов и очередей**: Настройка `somaxconn`, `netdev_max_backlog` и буферов TCP.
*   **Детальная информация**: [**Оптимизация TCP в Linux (`sysctl`)**](./tcp_tuning.md).

### 2. Уровень сетевой карты (NIC) и драйвера
Современные сетевые карты предоставляют аппаратные и программные механизмы для снижения нагрузки на CPU.
*   **Распределение нагрузки по ядрам CPU**: Использование `RSS` (аппаратно) или `RPS`/`RFS` (программно) для параллельной обработки пакетов.
*   **Объединение прерываний (Interrupt Coalescing)**: Снижение частоты прерываний для уменьшения накладных расходов.
*   **Offloading**: Перенос задач (GRO, LRO, Checksum Offload) с CPU на сетевую карту.
*   **Детальная информация**:
    *   [**RSS, RPS, RFS: Балансировка сетевой нагрузки по CPU**](./rss_rps_rfs.md).
    *   [**ethtool: Диагностика и управление сетевыми адаптерами**](../Tools/ethtool.md).

### 3. Уровень управления трафиком (QoS)
Используется для приоритизации важного трафика и ограничения менее важного.
*   **Инструмент**: `tc` (traffic control) из пакета `iproute2`.
*   **Задачи**: Создание иерархических очередей (HTB), маркировка пакетов (DSCP).
*   **Детальная информация**: [**tc: Управление трафиком**](../Tools/iproute2/tc.md).

### 4. Уровень приложения
Выбор протоколов и архитектуры приложения.
*   **Протоколы**: Использование `HTTP/2` или `HTTP/3` (QUIC) для мультиплексирования запросов.
*   **Соединения**: Применение `keep-alive` и пулов соединений для повторного использования TCP-сессий.
*   **Детальная информация**: [Оптимизация HTTP-протоколов](../../Networking/Protocols/http_protocols_optimization.md).

# Дополнительная информация

*   **Диагностика**: Для измерения эффективности оптимизаций и поиска узких мест используйте [инструменты диагностики сети](../network_diagnostics_tools.md) (`ss`, `ping`, `mtr`, `tcpdump`).
*   **Комплексный подход**: Наилучшие результаты достигаются при комплексной настройке всех уровней, а не только одного из них.
