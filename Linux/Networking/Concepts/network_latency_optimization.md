# Оптимизация сетевых каналов и снижение латентности

## Определения

**Сетевая латентность (Network Latency — сетевая задержка)** — временной интервал между отправкой запроса и получением ответа. Измеряется как задержка в одну сторону (One-Way Delay) или в обе (**RTT — Round-Trip Time**).

**Bufferbloat (Раздувание буфера)** — деградация качества связи из-за избыточной буферизации пакетов в промежуточных узлах или на сетевой карте, что приводит к росту задержек и джиттера при высокой нагрузке.

**Хвостовая латентность (Tail Latency)** — показатели задержки для наихудших сценариев (перцентили **p95**, **p99**, **p99.9**). Именно они определяют «ощущаемую» производительность распределенных систем.

**Джиттер (Jitter)** — колебание (вариация) сетевой задержки во времени. Критичен для приложений реального времени (VoIP, видеостриминг, биржевая торговля).

**Zero-copy** — технология передачи данных, исключающая их копирование между пространствами пользователя и ядра, что радикально снижает нагрузку на CPU и латентность.

## Базовые концепции

### Компоненты общей задержки

Латентность является производной от четырех физических и логических факторов:
1.  **Задержка распространения (Propagation Delay):** Ограничена скоростью света в среде передачи (волокно, медь).
2.  **Задержка сериализации (Serialization Delay):** Время на преобразование данных в битовый поток (зависит от пропускной способности канала).
3.  **Задержка обработки (Processing Delay):** Время на деинкапсуляцию, проверку контрольных сумм и принятие решения о маршрутизации.
4.  **Задержка в очередях (Queuing Delay):** Время ожидания в буферах при перегрузке интерфейсов.

### Влияние аппаратного обеспечения

На сверхнизких задержках (микросекунды) критичными становятся факторы хоста:
*   **NUMA-эффекты:** Доступ к сетевой карте из ядра CPU, находящегося на другом процессорном сокете, увеличивает задержку из-за использования шин QPI/UPI.
*   **CPU Power Management:** Переход процессора в глубокие состояния сна (**C-states**) и изменение частоты (**P-states**) вносят непредсказуемые задержки при «пробуждении» для обработки пакета.
*   **PCIe Latency:** Задержки на шине при передаче данных от NIC в RAM.

## Практические сценарии: Уровни оптимизации

### 1. Уровень ядра и сетевого стека

Тюнинг параметров `sysctl` для минимизации очередей и ускорения обработки.

| Параметр | Значение (Low Latency) | Описание |
| :--- | :--- | :--- |
| `net.ipv4.tcp_congestion_control` | `bbr` или `reno` | BBR минимизирует RTT; Reno может быть быстрее в локальных сетях без потерь. |
| `net.core.default_qdisc` | `fq` или `fq_codel` | Использование FQ необходимо для BBR и борьбы с Bufferbloat. |
| `net.ipv4.tcp_low_latency` | `1` | (Для старых ядер) Предпочитать низкую задержку пропускной способности. |
| `net.ipv4.tcp_fastopen` | `3` | Включение TFO для экономии 1 RTT при установке соединения. |
| `net.core.busy_poll` | `50` | Время (в мкс) ожидания пакетов в режиме активного опроса. |

### 2. Уровень сетевой карты (NIC) и прерываний

Переход от прерываний к прямому управлению или балансировке.

*   **Affinity & Isolation:** Привязка прерываний сетевой карты к конкретным ядрам (**IRQ Affinity**) и изоляция этих ядер от планировщика ОС (`isolcpus`).
    *   *Подробнее:* **[RSS, RPS, RFS в Linux](./rss_rps_rfs.md)**.
*   **Interrupt Coalescing:** Отключение объединения прерываний (`ethtool -C eth0 rx-usecs 0`) для немедленной обработки каждого пакета ценой роста нагрузки на CPU.
*   **NUMA Alignment:** Убедитесь, что приложение и прерывания NIC работают на одной NUMA-ноде.
    ```bash
    cat /sys/class/net/eth0/device/numa_node
    ```

### 3. Технологии Kernel Bypass (Обход ядра)

Для систем с требованиями задержек < 10 мкс стандартный стек ядра становится препятствием.

*   **XDP (eXpress Data Path):** Обработка пакетов на уровне драйвера с помощью eBPF до создания структуры `sk_buff`.
*   **AF_XDP:** Высокопроизводительный адресный семейство сокетов для передачи пакетов в Userspace без копирования.
*   **DPDK (Data Plane Development Kit):** Полный перенос сетевого стека в пространство пользователя.
    *   *SSoT:* **[Обзор DPDK](../../../Networking/Concepts/dpdk/dpdk_overview.md)**.

### 4. Оптимизация на уровне сокетов приложения

*   **TCP_NODELAY:** Отключение алгоритма Нагла. Пакеты отправляются немедленно, не дожидаясь заполнения буфера.
*   **SO_BUSY_POLL:** Позволяет сокету выполнять активный опрос драйвера вместо ожидания прерывания. Радикально снижает хвостовую латентность (p99).
*   **TCP_QUICKACK:** Принудительная отправка подтверждений без ожидания (отключает Delayed ACK).

## Дополнительная информация

### Диагностический чек-лист

Для поиска причин задержек используйте следующие инструменты:

1.  **Профилирование стека:** `bpftrace` для измерения времени прохождения пакета через функции ядра.
2.  **Анализ очередей:** `ss -i` (просмотр RTT и параметров конкретного TCP-соединения).
3.  **Аппаратный анализ:** `ethtool -S <iface>` (поиск дропов на уровне колец NIC).
4.  **Мониторинг джиттера:** `mtr` в режиме статистики или `iperf3` с UDP-тестом.

```bash
# Пример: просмотр RTT и отклонений для активных соединений
ss -tin
```

### Тюнинг для Real-Time систем

В критических сценариях (например, в промышленности) используется ядро с патчем **PREEMPT_RT**, которое делает обработку прерываний полностью вытесняемой, гарантируя предсказуемое время отклика.
