# Реализации протоколов маршрутизации в Linux

## Введение
В современном мире IT-инфраструктуры наблюдается все большее сближение таких областей, как Linux-администрирование и сетевые технологии. Если раньше "линуксоиды" и "сетевики" часто работали в разных плоскостях, то сегодня понимание того, как Linux работает с сетями, становится критически важным для инженеров обеих специализаций. Многие современные сетевые устройства, включая маршрутизаторы и коммутаторы, используют Linux в качестве своей операционной системы, что требует глубокого понимания внутренних механизмов маршрутизации и управления трафиком.

Эта заметка призвана систематизировать знания о том, как реализуются протоколы маршрутизации в Linux, рассмотреть архитектуру маршрутизаторов на базе этой ОС и сравнить различные программные реализации.


## Архитектура маршрутизатора в Linux
Любой маршрутизатор состоит из двух основных компонентов: Control Plane и Data Plane.

### Control Plane (Управляющая плоскость)
Отвечает за управление маршрутизатором, обмен маршрутной информацией с другими системами и хранение конфигурации, введенной администратором. В Linux Control Plane может быть реализована вручную администратором с помощью утилит `ip`, `tc` и т.д., или специализированным программным обеспечением для динамической маршрутизации.

### Data Plane (Плоскость данных)
Также известна как Forward Plane, занимается непосредственной передачей пакетов. В Linux ядро операционной системы выступает в роли Data Plane, реализуя маршрутизацию пакетов IPv4 и IPv6, таблицы маршрутизации и выбор маршрутов. Утилиты `ip route` и `ip neighbor` позволяют просматривать и управлять этими таблицами.

**Особенности ядра Linux как Data Plane:**
*   Ядро Linux эффективно форвардит пакеты, справляясь с высокими нагрузками (до 10 Гбит/с и более).
*   Ядро не хранит маршрутную информацию постоянно. При перезагрузке или отключении интерфейса маршруты, добавленные вручную, могут быть утеряны. Например, если вручную добавить маршрут через интерфейс, а затем перевести этот интерфейс в состояние `DOWN`, маршрут исчезнет из таблицы маршрутизации ядра. При возвращении интерфейса в состояние `UP` связанный с ним "connected" маршрут вернется, но вручную добавленный маршрут — нет. Это демонстрирует, что для поддержания актуального состояния маршрутов требуется внешний Control Plane.
*   Существуют гибридные варианты Data Plane, включающие аппаратные коммутаторы или ускорители (например, VPP), но обмен информацией с ними, как правило, происходит через ядро Linux.

### RIB (Routing Information Base) и FIB (Forwarding Information Base)
*   **FIB (Forwarding Information Base):** Это таблица маршрутизации, используемая Data Plane (ядром Linux) для быстрой пересылки пакетов.
*   **RIB (Routing Information Base):** Более полная база данных маршрутной информации, которая может содержать маршруты, полученные от различных протоколов, а также информацию о фильтрации и выборе лучших маршрутов. В сложных сценариях, когда используются несколько протоколов динамической маршрутизации (например, BGP для внешних связей и OSPF для внутренней сети), все маршруты сначала попадают в RIB. Здесь происходит их обработка, фильтрация и выбор оптимальных маршрутов, а затем лучшие маршруты устанавливаются в FIB ядра. Это позволяет осуществлять двусторонний обмен маршрутными данными между различными протоколами, например, перераспределять маршруты, полученные по BGP, в OSPF и наоборот.

## Типы маршрутизации
Маршрутизация подразделяется на два основных типа:

### Статическая маршрутизация
При статической маршрутизации администратор вручную создает и настраивает все маршруты. Эти маршруты остаются неизменными до тех пор, пока администратор не внесет изменения.

### Динамическая маршрутизация
При динамической маршрутизации системы автоматически обмениваются маршрутной информацией друг с другом с использованием специализированных протоколов. Это позволяет маршрутизаторам адаптироваться к изменениям в топологии сети без прямого вмешательства человека.

## Протоколы динамической маршрутизации
Для динамической маршрутизации существует множество протоколов, каждый из которых имеет свои особенности и области применения:

### BGP (Border Gateway Protocol)
Протокол граничного шлюза, используемый для обмена маршрутной информацией между автономными системами в Интернете.

### OSPF (Open Shortest Path First)
Протокол внутренней маршрутизации, использующий алгоритм состояния канала для определения кратчайшего пути в пределах одной автономной системы.

### Другие протоколы (RIP, ISIS, IGRP)
*   **RIP (Routing Information Protocol):** Простой протокол маршрутизации, использующий вектор расстояния.
*   **ISIS (Intermediate System to Intermediate System):** Протокол состояния канала, часто используемый в крупных сетях провайдеров.
*   **IGRP (Interior Gateway Routing Protocol):** Проприетарный протокол Cisco, использующий вектор расстояния.

## Реализации протоколов маршрутизации в Linux
### ExoBGP
ExoBGP — это реализация протокола BGP, разработанная компанией EXO Networks.

#### Особенности
*   Написана на Python, что делает ее легко изучаемой и модифицируемой.
*   Не устанавливает маршруты в ядро Linux (не взаимодействует с FIB). Ядро Linux служит только операционной системой для ее работы.
*   Не требует привилегий root, так как занимается только сетевыми соединениями и передачей маршрутов.

#### Применение
*   **Контроллеры SDN:** Для анонсирования маршрутов из внешних источников, когда сам контроллер не занимается передачей пакетов.
*   **Изучение протокола BGP:** Благодаря реализации на Python, ExoBGP удобна для понимания принципов работы BGP.
*   **Мониторинг и анализ:** Может использоваться для получения данных из BGP и их экспорта для анализа или построения собственных анализаторов.

#### Конфигурация
*   Устанавливается из репозиториев (например, `exoBGP` и `python3-exoBGP`).
*   Основные настройки процесса хранятся в `/etc/exobgp/exobgp.env`.
*   Конфигурация соседей и маршрутов по умолчанию не создается, но может быть задана в файле `exobgp.conf`.
### OpenBGPD и OpenOSPFD
OpenBGPD и OpenOSPFD — это демоны маршрутизации, разработанные в рамках проекта OpenBSD.

#### Особенности
*   Работают как на OpenBSD, так и на Linux.
*   Реализуют различные протоколы (BGP и OSPF соответственно), но не имеют общей Routing Information Base (RIB). Это означает, что функции прямой передачи маршрутов между OSPF и BGP отсутствуют.

#### Применение
*   Широко применяются на точках обмена трафиком (IXP) в качестве Route Server.
### Bird
Bird — это полноценный набор протоколов маршрутизации с общей Routing Information Base (RIB).

#### Особенности
*   Реализует множество протоколов: BGP, RIP, OSPF (v2, v3), BFD, Babel.
*   Имеет общую RIB, что позволяет централизованно управлять маршрутной информацией.
*   Все протоколы и RIB реализованы в одном процессе/бинаре. Это означает, что для добавления новых протоколов или взаимодействия с RIB требуется модификация и пересборка кода Bird.
*   Утилита `birdc` (Bird Control) используется для взаимодействия с демоном (просмотр статуса, маршрутов, протоколов), но не позволяет просматривать или изменять настройки конфигурации, так как они хранятся исключительно в файле.
*   Поддерживает статические маршруты, которые автоматически восстанавливаются при изменении состояния интерфейса.
### FRR (Free Range Routing)
FRR — это самый актуальный, живой и активно развивающийся проект в серии маршрутизирующих стеков, являющийся форком Quagga, которая, в свою очередь, была форком Zebra.

#### История (Zebra, Quagga)
*   **Zebra:** Изначальный проект, разработанный компанией IP Infusion. В какой-то момент автор прекратил его развитие, переключившись на коммерческую версию, что вызвало разочарование в сообществе.
*   **Quagga:** Форк Zebra, созданный сообществом в ответ на прекращение поддержки Zebra. Quagga прожила долгую и активную жизнь, но со временем также перестала активно развиваться. Несмотря на то, что Quagga иногда встречается в репозиториях, ее использование не рекомендуется из-за устаревания и отсутствия активной поддержки.
*   **FRR:** Актуальный форк Quagga, поддерживающий множество операционных систем, но с некоторыми функциями, доступными только в Linux. FRR является самым живым, активным и развитым проектом в этой серии.

#### Архитектура (Zebro)
*   **Модульность:** В отличие от Bird, FRR имеет модульную архитектуру. Каждый протокол реализован как отдельный процесс.
*   **Zebro:** Центральный процесс, который выступает в роли Routing Information Base (RIB). Он собирает маршруты от всех протоколов, фильтрует их, выбирает лучшие и устанавливает в ядро (FIB).
*   **API:** Zebro предоставляет API для взаимодействия с демонами, что позволяет разрабатывать собственные протоколы и распространять их как отдельные пакеты.
*   **Watchdog:** FRR включает отдельный демон Watchdog, который перезапускает упавшие процессы протоколов, повышая отказоустойчивость.

#### Особенности
*   Поддерживает широкий спектр протоколов, включая BGP, OSPF, RIP, ISIS, IGRP (протокол Cisco, не полностью безглючный, но в основном работает).
*   Каждый протокол работает как отдельный процесс, что повышает стабильность: падение одного протокола не влияет на другие.
*   Поддерживает механизмы изоляции, такие как VRF (Virtual Routing and Forwarding) и Policy-Based Routing. В Linux VRF реализованы через таблицы маршрутизации (`ip rule add table <ID>`) и присвоение интерфейсов. Важно отметить, что часть функциональности FRR, особенно связанная с продвинутыми сетевыми возможностями ядра (множественные таблицы маршрутизации, VRF, Multipath), доступна только в Linux из-за различий в реализации этих механизмов в других Unix-подобных системах.

#### Применение
*   Идеально подходит для построения полноценных маршрутизаторов на Linux, особенно в случаях, когда требуется не просто обмен маршрутами, а полноценная маршрутизация трафика.

#### Конфигурация
*   Конфигурация демонов FRR по умолчанию находится в файле `frr.conf` (или `frr-daemons.conf` для указания запускаемых демонов).
*   Настраивать FRR можно двумя способами:
    *   Вручную редактируя конфигурационные файлы.
    *   Через CLI, подобный Cisco, с помощью утилиты `vtysh`. Команды `show running-config` и `show ip bgp neighbors` позволяют просматривать текущую конфигурацию и статус соседей.

## Сценарии использования
Протоколы динамической маршрутизации и их реализации в Linux могут быть полезны в различных сценариях:

### Реальный маршрутизатор на Linux
*   **White Box коммутаторы:** Современные коммутаторы без предустановленной ОС позволяют пользователю самостоятельно выбрать и установить операционную систему, часто на базе Linux, с собственным стеком маршрутизации.
*   **Виртуальные маршрутизаторы:** Многие вендоры предлагают виртуальные маршрутизаторы, которые часто используют Linux в качестве базовой ОС.
*   **Ядро Linux + драйверы:** В таких случаях ядро Linux выступает в роли Data Plane, а специализированные драйверы отправляют маршрутную информацию в аппаратную фабрику коммутации.

### Look in the Glass
*   Системы, которые принимают маршруты от других источников и выдают их, но сами не занимаются маршрутизацией трафика.
*   Используются для отображения того, как определенный IP-адрес или сеть выглядит со стороны провайдера, который держит этот Look in the Glass. Это позволяет внешним пользователям проверять маршрутную информацию.
*   Как правило, маршрутизатор, служащий Look in the Glass, не занимается маршрутизацией трафика, чтобы предотвратить влияние на реальную сеть в случае компрометации. Маршрутная информация передается в одностороннем порядке (от реального маршрутизатора к Look in the Glass), что исключает возможность воздействия на реальный трафик через публично доступный интерфейс. В этом случае важна RIB, но маршруты обычно не попадают в FIB ядра.

### Route Server
*   Используется на точках обмена трафиком (IXP), где множество участников могут подключаться к общей сети.
*   Вместо того чтобы каждому участнику настраивать обмен маршрутами со всеми остальными (что привело бы к сложной full mesh топологии), Route Server предоставляет единую точку для обмена маршрутной информацией. Участники настраивают BGP-сессию только с Route Server, который затем распространяет маршруты между ними.
*   Route Server сам по себе не маршрутизирует трафик, он лишь служит для обмена информацией о маршрутах. В этом случае общая RIB важна, но маршруты обычно не попадают в FIB ядра.

### Раздача списков адресов (BGP)
*   BGP может использоваться не только для маршрутизации, но и для распространения списков IP-адресов.
*   Пример: компании, занимающиеся кибербезопасностью, используют BGP для раздачи списков невыделенных сетей. Трафик из таких сетей считается спуфингом, и его можно фильтровать на основе этих списков. В этом случае маршрутизатору, раздающему списки, не обязательно устанавливать маршруты в ядро.

## Заключение
Linux предоставляет гибкие возможности для реализации различных сценариев маршрутизации, от простых статических конфигураций до сложных динамических систем с использованием специализированного программного обеспечения. Выбор конкретной реализации зависит от требований к функциональности, модульности, производительности и удобству управления. FRR выделяется как наиболее современное и активно развивающееся решение для построения полноценных маршрутизаторов на базе Linux.
