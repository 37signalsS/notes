# Администрирование Policy-Based Routing

## Определения

**Администрирование PBR** — совокупность операций по развертыванию, мониторингу, отладке и обеспечению отказоустойчивости механизмов маршрутизации на основе политик.

Включает в себя проверку текущего состояния RPDB (Routing Policy Database), настройку параметров сетевого стека ядра и интеграцию правил в системные менеджеры конфигурации для их сохранения после перезагрузки.

Теоретические основы и архитектура PBR описаны в [главном разделе](./index.md).

---

## Основные концепции

### Инструментарий администратора

Для эффективного управления PBR используются следующие компоненты:

| Инструмент | Роль в администрировании |
| :--- | :--- |
| **`ip rule`** | Просмотр и модификация базы данных правил маршрутизации. |
| **`ip route`** | Управление кастомными таблицами маршрутизации, на которые ссылаются правила. |
| **`sysctl`** | Настройка `rp_filter` для предотвращения отбрасывания легитимного асимметричного трафика. |
| **`iptables / nftables`** | Мониторинг и проверка маркировки пакетов (fwmark). |

### Персистентность конфигурации

По умолчанию изменения, внесенные через команды `ip`, являются эфемерными и сохраняются только до перезагрузки системы. Основная задача администратора — перенести проверенные правила в конфигурационные файлы сетевого менеджера (systemd-networkd, NetworkManager, Netplan и др.).

## Практические сценарии

### Проверка и верификация конфигурации

Для аудита текущих настроек PBR используются следующие команды:

```bash
# Просмотр всех правил с их приоритетами
ip rule show

# Просмотр маршрутов в конкретной таблице (например, с ID 100)
ip route show table 100

# Детальный просмотр параметров правил (включая селекторы iif/oif)
ip -d rule show

# Эмуляция выбора маршрута для конкретного пакета (важнейший инструмент отладки)
ip route get 8.8.8.8 from 192.168.1.100 iif eth1
```

### Настройка персистентности (сохранение правил)

Примеры настройки для различных системных менеджеров:

#### Debian / Ubuntu (ifupdown)

Файл `/etc/network/interfaces`:

```bash
iface eth0 inet static
    address 192.168.1.100/24
    # Добавление правил при поднятии интерфейса
    post-up ip route add default via 192.168.1.1 table 100
    post-up ip rule add from 192.168.1.100 table 100 priority 1000
    # Удаление правил при опускании интерфейса
    pre-down ip rule del from 192.168.1.100 table 100 priority 1000
```

#### Systemd-networkd

Файл `/etc/systemd/network/10-eth0.network`:

```ini
[Route]
Gateway=192.168.1.1
Table=100

[RoutingPolicyRule]
From=192.168.1.100
Table=100
Priority=1000
```

#### Netplan

Файл `/etc/netplan/01-netcfg.yaml`:

```yaml
network:
  ethernets:
    eth0:
      addresses: [192.168.1.100/24]
      routing-policy:
        - from: 192.168.1.100
          table: 100
          priority: 1000
```

### Тюнинг параметров ядра (Reverse Path Filtering)

При использовании PBR для асимметричной маршрутизации механизм `rp_filter` может ошибочно классифицировать пакеты как спуфинг.

**Режимы фильтрации:**

- `1` (Strict) — строгая проверка (пакет отбрасывается, если ответный путь не через тот же интерфейс). Несовместимо с PBR.
- `2` (Loose) — ослабленная проверка (проверяется только наличие любого маршрута к источнику). **Рекомендуется для PBR.**

**Применение настроек:**

```bash
# Временная настройка
sudo sysctl -w net.ipv4.conf.all.rp_filter=2
sudo sysctl -w net.ipv4.conf.default.rp_filter=2

# Постоянная настройка в /etc/sysctl.d/99-pbr.conf
net.ipv4.conf.all.rp_filter = 2
net.ipv4.conf.default.rp_filter = 2
```

### Диагностика и устранение неисправностей

| Проблема | Диагностика | Решение |
| :--- | :--- | :--- |
| **Трафик игнорирует правила** | `ip rule show` | Проверить приоритеты (правила с меньшим числом выше). |
| **Ответы не уходят (Drop)** | `sysctl net.ipv4.conf.all.rp_filter` | Установить значение `2` (Loose mode). |
| **Конфликт таблиц** | `cat /etc/iproute2/rt_tables` | Убедиться, что ID таблиц уникальны и не перекрываются. |
| **Маркировка не срабатывает** | `iptables -t mangle -L -v` | Проверить счетчики пакетов в цепочках PREROUTING/OUTPUT. |
