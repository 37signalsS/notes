# Маршрутизация на основе политик (PBR) в Linux

## Определения

**Policy-Based Routing (PBR)** — механизм в ядре Linux, позволяющий выбирать таблицу маршрутизации на основе набора правил (политик). В отличие от традиционной маршрутизации (destination-based), где решение принимается только по IP-адресу назначения, PBR учитывает широкий спектр атрибутов: IP источника, входящий интерфейс, порт, протокол, а также метки пакетов (`fwmark`).

**Source-Based Routing (SBR)** — частный случай PBR, при котором маршрутизация осуществляется исключительно на основе адреса источника (селектор `from` в правиле).

---

## Основные концепции

### Требования к ядру

Для функционирования PBR ядро Linux должно быть собрано с поддержкой следующих опций:

- `CONFIG_IP_ADVANCED_ROUTER` — расширенные возможности маршрутизации.
- `CONFIG_IP_MULTIPLE_TABLES` — поддержка множественных таблиц маршрутизации.

Путь в конфигурации ядра: `Networking support → Networking options → TCP/IP networking`.

### Принцип работы

Стандартная маршрутизация в Linux использует одну главную таблицу (`main`) для всех решений. PBR расширяет эту модель, вводя **базу данных правил маршрутизации (RPDB)**. При поступлении пакета ядро последовательно проверяет правила в RPDB; первое подошедшее правило указывает, в какой таблице искать маршрут.

```
┌─────────────────┐
│   Входящий      │
│    пакет        │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Проверка       │
│  RPDB (ip rule) │
└────────┬────────┘
         │
    ┌────┴────┬─────────┐
    │         │         │
    ▼         ▼         ▼
┌───────┐ ┌─────────┐ ┌─────────┐
│ local │ │  table  │ │  main   │
│ (255) │ │  (100)  │ │  (254)  │
└───────┘ └─────────┘ └─────────┘
```

Процесс реализации PBR включает три компонента:

1.  **Множественные таблицы маршрутизации**: Создание пользовательских таблиц с независимыми шлюзами (Gateway). Имена и ID таблиц описываются в `/etc/iproute2/rt_tables`.
2.  **Правила маршрутизации (Rules)**: Команда `ip rule` определяет критерии выбора таблицы. Каждое правило имеет приоритет (от 0 до 32767).
3.  **Классификация трафика**: Определение пакетов по атрибутам L3/L4 или по меткам, установленным фаерволом.

### Маркировка трафика (fwmark)

Если встроенных селекторов `ip rule` недостаточно (например, нужно маршрутизировать трафик конкретного приложения по его PID или на основе сложных условий L7), используется маркировка пакетов средствами фаервола.

- **iptables**: Таблица `mangle`, действие `MARK` или `CONNMARK`.
- **nftables**: Современный подход, позволяющий устанавливать `meta mark` в цепочках `prerouting` или `output`.

```bash
# Пример маркировки в nftables
nft add rule inet filter prerouting ip saddr 192.168.1.50 meta mark set 0x1
```

Подробное описание синтаксиса `ip rule` приведено в разделе **[`ip rule & PBR`](../Tools/iproute2/ip_rule_pbr.md)**.

## Практические сценарии

### Асимметричная маршрутизация

**Проблема:** В системе с несколькими интерфейсами ответ на пакет, пришедший на интерфейс B, может уйти через интерфейс A (шлюз по умолчанию в таблице `main`). Это приводит к блокировкам со стороны фаерволов и механизмов защиты ядра (**Reverse Path Filtering**).

**Решение:** Создание правил, предписывающих отвечать через тот же интерфейс, на который пришел запрос, на основе IP-адреса источника.

```bash
# Использовать таблицу 100 для ответов с IP 192.168.1.10
sudo ip rule add from 192.168.1.10 table 100
```

### Резервирование каналов (Failover)

Использование PBR совместно с метриками маршрутов позволяет организовать автоматическое переключение на резервного провайдера.

- **Таблица `main`**: Содержит два маршрута по умолчанию с разными метриками (`metric 100` и `metric 200`).
- **PBR**: Гарантирует, что трафик, инициированный через конкретный интерфейс, всегда будет возвращаться через него, независимо от того, какой провайдер сейчас является "основным" в таблице `main`.

### Взаимосвязь с DNAT (проброс портов)

При пробросе портов на сервер с несколькими провайдерами PBR критически важен для сохранения симметрии трафика. Без PBR пакет, пришедший через Провайдера 2, будет "обработан" шлюзом по умолчанию Провайдера 1 в таблице `main`, и соединение будет разорвано.

Подробные примеры конфигурации см. в разделе **[Сценарии PBR](./scenarios.md)**.

## Современные альтернативы: VRF

**VRF (Virtual Routing and Forwarding)** — более современный и масштабируемый подход к разделению сетевых сред в Linux (ядро 4.4+). В отличие от PBR, где правила применяются к отдельным пакетам, VRF позволяет привязывать целые интерфейсы к изолированным таблицам маршрутизации.

- **Преимущество**: Отсутствие необходимости в сложной базе данных правил RPDB.
- **Применение**: Изоляция трафика менеджмента, создание независимых сетевых доменов для контейнеров или виртуальных машин.

Подробнее см. в разделе **[VRF в Linux](../vrf.md)**.
