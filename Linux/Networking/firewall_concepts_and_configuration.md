# Фильтрация трафика в Linux: iptables и nftables

Этот документ основан на лекции о `iptables` и `nftables` и предоставляет обзор концепций и практической настройки файрвола в Linux.

## 1. Основы: Netfilter и поток трафика

В основе фильтрации трафика в ядре Linux лежит подсистема **Netfilter**. Весь сетевой трафик, входящий, исходящий или проходящий через систему, обрабатывается ядром (`kernel space`), прежде чем он достигнет приложений (`user space`) или будет отправлен в сеть.

Netfilter предоставляет "хуки" (hooks) в ключевых точках обработки сетевого пакета. `iptables` и `nftables` используют эти хуки для применения наборов правил.

Основные пути трафика:
- **INPUT**: Трафик, предназначенный для локальных приложений на сервере.
- **OUTPUT**: Трафик, сгенерированный локальными приложениями.
- **FORWARD**: Трафик, проходящий через сервер из одной сети в другую (маршрутизация).

## 2. Управление файрволом

Существует несколько способов управления правилами Netfilter:

- **Прямое управление:**
  - `iptables`: Традиционная утилита для управления правилами IPv4.
  - `ip6tables`: Аналог для IPv6.
  - `arptables`, `ebtables`: Для других уровней сетевой модели.
  - `nft`: Современная утилита, заменяющая все вышеперечисленные.

- **Инструменты-надстройки:**
  - `ufw` (Uncomplicated Firewall): Упрощенный интерфейс, используемый по умолчанию в Ubuntu. Является надстройкой над `iptables`.
  - `firewalld`: Динамический менеджер файрвола, используемый по умолчанию в RHEL-based дистрибутивах. Может работать поверх `iptables` или `nftables`.

Для полного контроля и понимания рекомендуется использовать инструменты прямого управления.

## 3. Архитектура `iptables`

`iptables` организует правила в таблицы, которые содержат цепочки правил.

- **Таблицы (Tables):** Определяют общую категорию обработки пакетов.
  - `filter`: Основная таблица для фильтрации (разрешить/запретить). Используется по умолчанию.
  - `nat`: Для трансляции сетевых адресов (Network Address Translation). Используется для маскарадинга и проброса портов.
  - `mangle`: Для модификации заголовков IP-пакетов (например, TTL, ToS).
  - `raw`: Для исключения пакетов из системы отслеживания соединений (`conntrack`).

- **Цепочки (Chains):** Последовательность правил, привязанная к хукам Netfilter.
  - `INPUT`: Для входящих пакетов.
  - `OUTPUT`: Для исходящих пакетов.
  - `FORWARD`: Для маршрутизируемых пакетов.
  - `PREROUTING`: Обрабатывает пакеты сразу после их поступления на сетевой интерфейс.
  - `POSTROUTING`: Обрабатывает пакеты непосредственно перед их отправкой с сетевого интерфейса.

- **Правила (Rules):** Состоят из критериев (условий) и действия (target). Пакет сравнивается с правилами в цепочке по порядку, сверху вниз. Как только совпадение найдено, выполняется указанное действие, и обработка пакета в этой цепочке прекращается.

- **Действия (Targets):**
  - `ACCEPT`: Разрешить прохождение пакета.
  - `DROP`: Отбросить пакет. Отправитель не получает никакого ответа.
  - `REJECT`: Отклонить пакет. Отправителю возвращается сообщение об ошибке (например, `icmp port-unreachable`).
  - `LOG`: Записать информацию о пакете в системный лог. Обработка продолжается со следующего правила.

- **Политика по умолчанию (Default Policy):** Действие, которое применяется к пакету, если он прошел всю цепочку и не совпал ни с одним правилом. Для безопасности рекомендуется устанавливать политику в `DROP`.

## 4. `nftables`: Современная замена

В современных дистрибутивах Linux `iptables` является слоем совместимости поверх `nftables`.

- **Преимущества `nftables`:**
  - Единая утилита `nft` для всех протоколов.
  - Более производительный и гибкий синтаксис.
  - Атомарное обновление правил.

- **Проверка используемой системы:**
  ```bash
  sudo iptables -V
  # iptables v1.8.10 (nft_compat) -> означает, что используется nftables
  # iptables v1.8.10 (legacy) -> означает, что используется "старый" iptables
  ```

- **Просмотр набора правил `nftables`:**
  ```bash
  sudo nft list ruleset
  ```

Даже если система использует `nftables`, можно продолжать использовать синтаксис `iptables` благодаря слою совместимости.

## 5. Практическая настройка базового файрвола

**Цель:** Настроить безопасный файрвол для сервера, который обслуживает веб-сервисы и доступен по SSH.

**Основной принцип:** Запретить все, что не разрешено явно.

### Порядок настройки

1.  **Разрешить весь трафик на loopback-интерфейсе.** Это критически важно для корректной работы многих локальных сервисов.
    ```bash
    sudo iptables -A INPUT -i lo -j ACCEPT
    ```

2.  **Разрешить ICMP.** Протокол используется для диагностики сети (например, `ping`). Полная блокировка может затруднить отладку.
    ```bash
    sudo iptables -A INPUT -p icmp -j ACCEPT
    ```

3.  **Разрешить установленные и связанные соединения (Stateful Firewall).** Это самое важное правило. Оно позволяет пропускать ответный трафик для уже установленных соединений.
    ```bash
    sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
    ```

4.  **Блокировать невалидные пакеты.**
    ```bash
    sudo iptables -A INPUT -m conntrack --ctstate INVALID -j DROP
    ```

5.  **Разрешить новые входящие соединения.** Открываем только необходимые порты.
    ```bash
    # SSH (порт 22)
    sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT
    # HTTP (порт 80)
    sudo iptables -A INPUT -p tcp --dport 80 -m conntrack --ctstate NEW -j ACCEPT
    # HTTPS (порт 443)
    sudo iptables -A INPUT -p tcp --dport 443 -m conntrack --ctstate NEW -j ACCEPT
    ```

6.  **Установить политику по умолчанию в `DROP`.** Это финальный и самый опасный шаг. Убедитесь, что правило для SSH добавлено корректно, иначе вы потеряете доступ к серверу.
    ```bash
    sudo iptables -P INPUT DROP
    ```

### Полезные команды

- **Просмотр правил в таблице `filter`:**
  ```bash
  # -n: не преобразовывать IP и порты в имена
  # -v: подробный вывод (счетчики пакетов и байт)
  # -L: список правил
  # --line-numbers: показать номера строк
  sudo iptables -nvL --line-numbers
  ```

- **Вставка правила в определенную позицию:**
  ```bash
  # Вставить правило на первую позицию в цепочке INPUT
  sudo iptables -I INPUT 1 -s 1.2.3.4 -j DROP
  ```

- **Удаление правила:**
  ```bash
  # По номеру строки
  sudo iptables -D INPUT 1
  # По спецификации правила
  sudo iptables -D INPUT -s 1.2.3.4 -j DROP
  ```

- **Сброс всех правил (ОПАСНО!):**
  ```bash
  sudo iptables -F
  ```

## 6. Сохранение правил

Правила `iptables` по умолчанию не сохраняются после перезагрузки.

- **Ручное сохранение и восстановление:**
  ```bash
  sudo iptables-save > /etc/iptables/rules.v4
  sudo ip6tables-save > /etc/iptables/rules.v6
  
  sudo iptables-restore < /etc/iptables/rules.v4
  ```

- **Автоматизация в Debian/Ubuntu:**
  Используется пакет `iptables-persistent`.
  ```bash
  sudo apt update
  sudo apt install iptables-persistent
  ```
  При установке будет предложено сохранить текущие правила.
  
  Для сохранения измененных правил вручную:
  ```bash
  sudo netfilter-persistent save
  ```
  Сервис `netfilter-persistent` автоматически загрузит правила при старте системы.

## 7. Взаимодействие с Docker

Docker активно управляет правилами `iptables` для обеспечения сетевой изоляции и проброса портов.

- При запуске контейнера с пробросом портов (например, `-p 8080:80`) Docker добавляет правила в таблицу `nat` (цепочка `PREROUTING` и `OUTPUT`) и `filter` (цепочка `FORWARD`).
- **`DOCKER-USER` chain:** Docker создает специальную цепочку `DOCKER-USER` в таблице `filter`. Правила, добавленные в эту цепочку, выполняются *перед* любыми правилами, которые Docker создает автоматически. Это рекомендуемое место для добавления собственных правил, которые должны применяться к трафику контейнеров.
- **`DNAT` (Destination NAT):** Используется для перенаправления трафика с порта хоста на порт контейнера.
- **`MASQUERADE`:** Используется в цепочке `POSTROUTING` для исходящего трафика из контейнеров, чтобы подменять внутренний IP контейнера на IP хоста.
