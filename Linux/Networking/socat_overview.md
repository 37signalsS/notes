# Socat: универсальный сетевой ретранслятор

## Определения

* **socat (SOcket CAT)** — многофункциональная утилита командной строки, предназначенная для установки двух двунаправленных потоков данных и перенаправления данных между ними. В отличие от упрощенных аналогов, socat работает с «адресами», которые могут быть сетевыми сокетами, файлами, устройствами, программами или очередями сообщений.
* **Адрес (Address)** — ключевая концепция socat. Каждый аргумент команды — это описание конечной точки (например, `TCP-LISTEN:8080` или `FILE:/tmp/log.txt`).

## Основные концепции

### Отличие от Netcat (nc)

Хотя обе утилиты используются для работы с сокетами, socat является значительно более мощным инструментом, де-факто стандартом для SRE и системных администраторов.

| Характеристика | Netcat (nc) | Socat |
| :--- | :--- | :--- |
| **Протоколы** | TCP, UDP | TCP, UDP, SSL/TLS, SCTP, UNIX Sockets, PTY, TUN/TAP, POSIX MQ. |
| **Шифрование** | Отсутствует. | Нативная поддержка OpenSSL (клиент и сервер). |
| **Параллелизм** | Обычно одно соединение. | Опция `fork` для обработки множества клиентов. |
| **Изоляция** | Нет. | Поддержка `chroot`, `su`, `netns` (в v1.8+). |
| **Цепочки** | Через pipe в shell. | Встроенная логика объединения и фильтрации. |

### Ключевые опции адресов

* **`fork`** — создает дочерний процесс для каждого нового соединения. Позволяет socat работать как полноценный сервер.
* **`reuseaddr`** — позволяет биндить порт сразу после закрытия предыдущего соединения (игнорируя состояние TIME_WAIT).
* **`netns=<name>`** (v1.8+) — открывает сокет внутри указанного сетевого пространства имен без использования `ip netns exec`.
* **`range=<network>`** — ограничивает входящие подключения указанной подсетью (L3-авторизация).

## Практические сценарии

### 1. TCP-прокси с логированием
Пересылка трафика с порта 8080 на удаленный сервер с выводом передаваемых данных в консоль (режим `-v`).

```bash
socat -v TCP-LISTEN:8080,fork,reuseaddr TCP:10.0.0.5:80
```

### 2. Защищенный SSL/TLS туннель
Создание зашифрованного канала для приложения, которое не поддерживает TLS.

```bash
# На стороне сервера (терминация SSL)
socat OPENSSL-LISTEN:443,cert=server.pem,key=server.key,verify=0,fork TCP:localhost:8080

# На стороне клиента (инициация SSL)
socat TCP-LISTEN:8080,fork OPENSSL:server.example.com:443,verify=0
```

### 3. Проброс Unix-сокета в TCP
Позволяет обращаться к Docker API или локальной базе данных через сеть.

```bash
socat TCP-LISTEN:2375,range=127.0.0.1/32,reuseaddr,fork UNIX-CONNECT:/var/run/docker.sock
```

### 4. Создание виртуального последовательного порта (PTY)
Связывание двух виртуальных терминалов. Полезно для отладки ПО, работающего с COM-портами.

```bash
socat PTY,link=/tmp/ttyV0,rawer PTY,link=/tmp/ttyV1,rawer
```

### 5. Безопасный реверс-шелл (OpenSSL)
Запуск интерактивного шелла с шифрованием и ограничением привилегий.

```bash
# На стороне атакуемого/отлаживаемого узла
socat OPENSSL-LISTEN:443,cert=cert.pem,verify=0 EXEC:/bin/bash,su=nobody,chroot=/var/lib/jail
```

### 6. Работа с очередями сообщений (v1.8+)
Чтение из POSIX Message Queue и вывод в stdout.

```bash
socat POSIXMQ-READ:/my_queue,mq-prio=10 STDOUT
```

## Безопасность и лучшие практики

1. **Минимизация привилегий**: Всегда используйте опции `su=<user>` и `gid=<group>`, если запускаете socat от имени root.
2. **Изоляция**: Используйте `chroot` для ограничения доступа `EXEC` и `SYSTEM` адресов к файловой системе.
3. **Фильтрация**: Опция `range` должна быть обязательной для всех `LISTEN` адресов, открытых на внешних интерфейсах.
4. **Валидация SSL**: В продакшене всегда используйте `verify=1` и указывайте доверенный `cafile`.
5. **Статистика** (v1.8+): Используйте опцию `--statistics` для мониторинга объема переданных данных.

## Диагностика

```bash
# Проверка версии и доступных функций (SSL, IPv6, и т.д.)
socat -V

# Отладка соединения с максимальным уровнем детализации
socat -d -d -d TCP-LISTEN:8080 STDOUT
```
