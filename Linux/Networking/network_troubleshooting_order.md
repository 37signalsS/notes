# Порядок диагностики сетевых проблем в Linux

## Определения

**Диагностика сети** — это процесс выявления и устранения проблем подключения. Ключевой принцип: **сеть — это поток**, а не набор разрозненных компонентов. Проблема чаще всего кроется не в том, что вы думаете.

## Основные концепции

### Разрушение распространённых заблуждений

| Заблуждение | Реальность |
| :--- | :--- |
| «Есть IP — сеть работает» | IP может быть назначен не на тот интерфейс |
| «Пинг работает — всё работает» | Пинг может идти другим маршрутом или через ICMP |
| «Это firewall» | Firewall чаще всего ни при чём, проблема в маршрутизации |
| «Перезапуск сети поможет» | Может усугубить проблему, потеряв SSH |

### Пять проверок (всегда в этом порядке)

1. **Интерфейсы** → `ip addr show`
2. **Маршруты** → `ip route`
3. **Связность** → `ping`
4. **DNS** → `cat /etc/resolv.conf`, `nslookup`
5. **Firewall** → `iptables -L -n` (в последнюю очередь!)

> **Важно:** Нарушение этого порядка — основная причина потери времени на диагностику.

## Практические сценарии

### Сценарий 1: Проверка интерфейсов

**Команда:**
```bash
ip addr show
```

**Вопросы для самопроверки:**

1. Интерфейс активен (UP)?
2. У него правильный IP-адрес?
3. Это тот интерфейс, который вы себе представляете?

**Типичная ошибка:** Отладка `eth0`, тогда как реальный трафик идёт через `ens192`.

**Проверка:**
```bash
# Краткий вывод всех интерфейсов
ip -br addr

# Только активные интерфейсы
ip -br addr show up
```

### Сценарий 2: Проверка маршрутизации

**Команда:**
```bash
ip route
```

**Что искать:**

| Проблема | Симптом |
| :--- | :--- |
| Нет default route | `default via` отсутствует |
| Неправильный gateway | Указан неверный шлюз |
| Конфликт маршрутов | Несколько маршрутов к одной сети |

**Важно:** Если Linux не знает, куда отправлять пакеты, неважно, насколько правильны остальные настройки.

**Примеры:**
```bash
# Показать только маршрут по умолчанию
ip route | grep default

# Показать маршрут к конкретному хосту
ip route get 8.8.8.8
```

### Сценарий 3: Проверка связности (пинг)

**Команда:**
```bash
ping -c 3 8.8.8.8
```

**Интерпретация:**

| Результат | Вывод |
| :--- | :--- |
| Пинг проходит | IP-маршрутизация работает |
| Пинг не проходит | Проблема с маршрутизацией (не DNS, не firewall!) |

**Важно:** Не стоит слепо доверять пингу. Некоторые узлы блокируют ICMP.

### Сценарий 4: Проверка DNS

**Команды:**
```bash
cat /etc/resolv.conf
nslookup google.com
# или
dig google.com
```

**Типичная проблема:**
```bash
# nameserver указывает на локальный сервис, который не запущен
nameserver 127.0.0.1
```

**Диагностика:**

| Проверка | Вывод |
| :--- | :--- |
| `ping 8.8.8.8` работает, `ping google.com` нет | Проблема с DNS |
| `nslookup` не возвращает IP | DNS-сервер недоступен или не отвечает |

**Подробно:** [Диагностика DNS](./Services/BIND/overview.md)

### Сценарий 5: Проверка firewall (в последнюю очередь!)

**Команды:**
```bash
# Для iptables
iptables -L -n

# Для firewalld
firewall-cmd --list-all

# Для nftables
nft list ruleset
```

**Важно:** Firewall чаще всего оказывается **последним** в списке причин. Если маршрут настроен неправильно — firewall ни при чём.

## Дополнительная информация

### Комплексный порядок диагностики

| Шаг | Задача | Команда | Что проверяем |
| :--- | :--- | :--- | :--- |
| **1** | Интерфейсы | `ip addr show` | Активность, IP, правильный интерфейс |
| **2** | Маршруты | `ip route` | Default route, gateway, конфликты |
| **3** | Связность | `ping -c 3 8.8.8.8` | IP-маршрутизация работает |
| **4** | DNS | `nslookup google.com` | Разрешение имён |
| **5** | Firewall | `iptables -L -n` | Правила фильтрации |

### Пример диагностики «Сервер не подключается к базе данных»

```bash
# 1. Проверяем интерфейс
ip addr show
# Интерфейс UP? IP правильный?

# 2. Проверяем маршрут
ip route
# Есть default route? Правильный gateway?

# 3. Проверяем связность с БД
ping -c 3 <IP_базы_данных>
# Если не работает → проблема с маршрутизацией

# 4. Проверяем порт БД
nc -zv <IP_базы_данных> 5432
# Connection succeeded → порт открыт
# Connection refused → сервис не запущен
# Timed out → блокируется firewall

# 5. Только теперь firewall
iptables -L -n | grep 5432
```
