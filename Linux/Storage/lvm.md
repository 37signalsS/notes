# LVM (Logical Volume Manager)

LVM (Logical Volume Manager) — это система управления логическими томами в Linux, которая позволяет гибко управлять дисковым пространством. Она абстрагируется от физических дисков, позволяя объединять их в единое пространство, а затем создавать, изменять размер и удалять логические разделы без остановки системы. LVM решает ограничения традиционного разбиения дисков, такие как невозможность легко изменять размеры разделов или объединять пространство с разных физических дисков в единый логический том.

### LVM и Device Mapper

Важно понимать, что LVM не является самостоятельным модулем ядра. Вместо этого, LVM — это набор пользовательских утилит (`pvcreate`, `vgcreate`, `lvcreate` и др.), которые работают поверх фреймворка **Device Mapper** в ядре Linux.

**Device Mapper** — это универсальный слой ядра, который предоставляет обобщенную инфраструктуру для создания виртуальных блочных устройств и отображения (mapping) их секторов на другие блочные устройства.

-   **Device Mapper (ядро):** Предоставляет низкоуровневый механизм для создания "логических" устройств.
-   **LVM (пользовательское пространство):** Предоставляет высокоуровдобные инструменты и политику для удобного управления дисковым пространством (PV, VG, LV).

Проще говоря, **LVM — это удобный интерфейс к Device Mapper**. Помимо LVM, Device Mapper также является основой для других технологий, таких как шифрование дисков (`dm-crypt`/LUKS), программный RAID (`mdadm`) и `overlayfs`.

### Преимущества LVM

LVM предоставляет ряд значительных преимуществ по сравнению с традиционным управлением дисковыми разделами:

-   **Гибкость в управлении дисковым пространством:** Возможность объединять несколько физических дисков (или их разделов) в единую группу томов (Volume Group), создавая большой пул хранения.
-   **Динамическое изменение размера:** Легкое увеличение или уменьшение размера логических томов (Logical Volumes) "на лету", без необходимости перемонтирования или остановки сервисов (для увеличения).
-   **Онлайн-операции:** Многие операции, такие как изменение размера LV, добавление/удаление физических томов, могут выполняться без отмонтирования файловых систем и прерывания работы.
-   **Абстракция от физического расположения:** LVM абстрагирует логические тома от их физического расположения на дисках, что упрощает управление и позволяет перемещать данные между физическими томами.
-   **Снимки (Snapshots):** Возможность создавать "мгновенные" снимки логических томов для резервного копирования или тестирования, что позволяет "заморозить" состояние данных на определенный момент времени.
-   **Тонкое выделение ресурсов (Thin Provisioning):** Создание логических томов с виртуальным размером, превышающим доступное физическое пространство, с динамическим выделением места по мере необходимости.
-   **Преодоление ограничений таблиц разделов:** LVM позволяет создавать тома, превышающие ограничения MBR (например, 2 ТБ), и не привязан к специфике таблиц разделов (MBR/GPT) на уровне логических томов.

### Философия LVM и рекомендации по разметке

Благодаря гибкости LVM, подход к разметке дискового пространства на серверах значительно упрощается. Вместо того чтобы заранее жестко планировать размеры всех разделов, можно придерживаться следующей философии:

-   **Минимальное начальное выделение:** Выделяйте только необходимый минимум пространства для корневого раздела (`/`), `/boot` (который не должен быть на LVM) и, возможно, `/var`. Остальное пространство оставляйте свободным в Volume Group.
-   **Динамическое расширение:** По мере необходимости легко расширяйте логические тома, добавляя пространство из свободной VG. Это позволяет избежать ситуации, когда один раздел переполнен, а на других есть избыток свободного места.
-   **Простота добавления:** Добавление нового диска в систему и его включение в существующую Volume Group — это простая операция, которая мгновенно увеличивает доступный пул пространства.
-   **Избегайте преждевременной оптимизации:** Нет необходимости распределять все свободное пространство сразу. LVM позволяет добавлять его по мере необходимости, даже небольшими порциями (например, по мегабайту).

Такой подход значительно упрощает администрирование и снижает риски, связанные с неправильным планированием дискового пространства.

LVM вводит три уровня абстракции:

1.  **Physical Volume (PV) — Физический том**
    -   Это физический диск (`/dev/sdb`) или его раздел (`/dev/sdb1`), инициализированный для использования в LVM. Это базовый строительный блок.

2.  **Volume Group (VG) — Группа томов**
    -   Это "пул" дискового пространства, который объединяет один или несколько физических томов (PV) в единое целое.

3.  **Logical Volume (LV) — Логический том**
    -   Это аналог обычного раздела диска, который "нарезается" из пространства группы томов (VG). Именно логический том форматируется в файловую систему (ext4, xfs) и монтируется в каталог.

### Базовые единицы LVM: Экстенты (Extents)

В основе LVM лежат экстенты — минимальные непрерывные блоки данных, которыми оперирует LVM.

-   **PE (Physical Extent) — Физический экстент:** Каждая группа томов (VG) делится на физические экстенты одинакового размера. По умолчанию размер PE составляет **4 МБ**. Это самые маленькие "кирпичики" дискового пространства в VG. При инициализации диска как PV или добавлении его в VG, часть пространства (обычно 4 МБ) резервируется для хранения метаданных LVM, что может быть заметно при работе с небольшими дисками.

-   **LE (Logical Extent) — Логический экстент:** Логические тома (LV) состоят из логических экстентов. Размер LE обычно совпадает с размером PE. LVM создает карту, которая сопоставляет логические экстенты с физическими.

Проще говоря, когда вы создаете логический том, LVM выделяет для него набор LE, которые, в свою очередь, указывают на конкретные PE на физических дисках. Эта абстракция позволяет легко перемещать данные и изменять размеры томов, просто обновляя карту сопоставления LE и PE.

Схема сопоставления LE и PE может быть нелинейной, что является ключевым преимуществом LVM. Например:

-   Логические экстенты `1`, `2`, `3` могут быть напрямую сопоставлены с физическими экстентами `1`, `2`, `3` на диске.
-   При этом логический экстент `10` может быть сопоставлен с физическим экстентом `5`.
-   А логический экстент `16` — с физическим экстентом `6`.

Операционная система работает с единым, непрерывным логическим томом, в то время как LVM "под капотом" распределяет данные по физическим дискам наиболее эффективным способом. Это позволяет легко изменять размер томов и управлять пространством без привязки к физической разметке дисков.

### Просмотр информации

| Команда | Описание |
| :--- | :--- |
| `pvs` или `pvdisplay` | Показывает информацию о физических томах (PV). |
| `vgs` или `vgdisplay` | Показывает информацию о группах томов (VG). |
| `lvs` или `lvdisplay` | Показывает информацию о логических томах (LV). |

### Создание и настройка

1.  **Создание физического тома (PV):**
    ```bash
    pvcreate /dev/sdb
    ```

2.  **Создание группы томов (VG):**
    ```bash
    # Создать VG из одного диска
    vgcreate my_vg /dev/sdb

    # Создать VG из нескольких дисков
    vgcreate my_vg /dev/sdb /dev/sdc
    ```

3.  **Создание логического тома (LV):**
    ```bash
    # Создать LV размером 10 ГБ
    lvcreate -L 10G -n my_lv my_vg

    # Создать LV, используя весь оставшийся объем VG
    lvcreate -l 100%FREE -n my_lv my_vg
    ```

4.  **Форматирование и монтирование LV:**
    Путь к логическому тому обычно выглядит как `/dev/<имя_VG>/<имя_LV>`.
    ```bash
    # Форматирование в ext4
    mkfs.ext4 /dev/my_vg/my_lv

    # Создание точки монтирования и монтирование
    mkdir /data
    mount /dev/my_vg/my_lv /data
    ```

#### Последовательность создания логического тома

1.  **Инициализация физического тома (`pvcreate`):** Сначала необходимо пометить физический диск или раздел как готовый для использования в LVM.
    ```bash
    sudo pvcreate /dev/sdb1
    ```

2.  **Создание группы томов (`vgcreate`):** Затем один или несколько физических томов объединяются в группу, создавая единый пул дискового пространства.
    ```bash
    sudo vgcreate myvg /dev/sdb1
    ```

3.  **Создание логического тома (`lvcreate`):** Наконец, из пула группы томов "нарезается" логический том нужного размера, который уже можно форматировать и монтировать.
    ```bash
    sudo lvcreate -L 10G -n mylv myvg
    ```

### Изменение размеров

1.  **Расширение логического тома (LV):**
    Расширение LV — это безопасная и часто выполняемая операция.
    ```bash
    # Добавить 5 ГБ к существующему LV
    lvextend -L +5G /dev/my_vg/my_lv

    # Обновить файловую систему, чтобы она "увидела" новое пространство
    # Для ext2/3/4:
    resize2fs /dev/my_vg/my_lv
    # Для XFS:
    # xfs_growfs /dev/my_vg/my_lv
    ```
    **Важное примечание:** Для файловых систем `ext2/3/4` можно использовать опцию `-r` (`--resizefs`) с `lvextend`, чтобы автоматически расширить файловую систему после увеличения логического тома. Это позволяет выполнить операцию одной командой и без отмонтирования (для ext-семейства).
    ```bash
    # Добавить 5 ГБ к существующему LV и автоматически расширить ФС
    lvextend -L +5G -r /dev/my_vg/my_lv
    ```

    После создания или изменения разделов на физическом диске (например, с помощью `fdisk` или `parted`), операционная система может не сразу увидеть изменения. Для этого используйте команду `partprobe`, чтобы уведомить ядро о новой таблице разделов:
    ```bash
    sudo partprobe
    ```
    Также стоит помнить, что LVM не изменяет фундаментальные свойства файловых систем. Например, файловые системы типа XFS не поддерживают уменьшение размера, а ext4 не может быть уменьшена без предварительного отмонтирования. LVM лишь предоставляет гибкость в управлении блочным устройством, но ограничения файловой системы остаются.

    **О точности размеров (ГБ vs ГиБ):** При указании размеров (например, `-L 10G`) важно помнить о различиях между гигабайтами (10^9 байт) и гибибайтами (2^30 байт). Различные утилиты могут интерпретировать "ГБ" по-разному, что может привести к неточностям. Для максимальной точности рекомендуется:
    -   Использовать флаг `-l 100%FREE` для выделения всего доступного пространства.
    -   Использовать единицы измерения, присущие диску (например, секторы), если требуется абсолютная точность.

#### Расширение файловой системы без её отключения

1.  **Расширение блочного устройства:** Сначала необходимо увеличить размер нижележащего блочного устройства. Это может быть логический том LVM, раздел диска или RAID-массив.
    ```bash
    # Пример для LVM
    sudo lvextend -L +10G /dev/my_vg/my_lv
    ```

2.  **Расширение самой файловой системы:** После того как у тома появилось дополнительное пространство, нужно дать команду файловой системе, чтобы она его заняла.
    -   **Для ext2/3/4:**
        ```bash
        sudo resize2fs /dev/my_vg/my_lv
        ```
    -   **Для XFS:**
        ```bash
        sudo xfs_growfs /mount/point/for/xfs_volume
        ```
        *Примечание: `xfs_growfs` принимает в качестве аргумента точку монтирования, а не путь к устройству.*

2.  **Расширение группы томов (VG):**
    Если в VG закончилось место, ее можно расширить, добавив новый физический диск.
    ```bash
    # 1. Инициализировать новый диск как PV
    pvcreate /dev/sdd

    # 2. Добавить PV в существующую VG
    vgextend my_vg /dev/sdd
    ```

3.  **Уменьшение логического тома (LV):**
    **Внимание: Уменьшение LV — это рискованная операция, которая может привести к потере данных, если выполнена некорректно. Всегда делайте резервные копии перед уменьшением.**

    **Ограничения файловых систем:**
    -   **XFS:** Не поддерживает уменьшение размера вообще. Для уменьшения XFS необходимо сделать резервную копию данных, удалить файловую систему, создать ее заново с меньшим размером и восстановить данные.
    -   **ext2/3/4:** Поддерживает уменьшение размера, но **только в офлайн-режиме** (файловая система должна быть отмонтирована).
    -   **BTRFS:** Поддерживает уменьшение размера онлайн.

    **Безопасный подход к уменьшению ext2/3/4 LV:**
    1.  **Отмонтировать том:**
        ```bash
        umount /data
        ```
    2.  **Проверить файловую систему на ошибки:**
        ```bash
        e2fsck -f /dev/my_vg/my_lv
        ```
    3.  **Уменьшить файловую систему:** Уменьшайте файловую систему до размера, который *меньше* желаемого конечного размера LV, чтобы оставить небольшой запас.
        ```bash
        resize2fs /dev/my_vg/my_lv 14G # Сжать ФС до 14 ГБ, если LV будет 15 ГБ
        ```
    4.  **Уменьшить логический том:** Указывайте желаемый конечный размер LV.
        ```bash
        lvreduce -L 15G /dev/my_vg/my_lv
        ```
    5.  **Расширить файловую систему до максимального размера LV (опционально, но рекомендуется):** После уменьшения LV, файловая система будет меньше, чем доступное пространство на LV. Можно расширить ее, чтобы она заняла все доступное пространство.
        ```bash
        resize2fs /dev/my_vg/my_lv
        ```
    6.  **Смонтировать обратно:**
        ```bash
        mount /dev/my_vg/my_lv /data
        ```
    Этот подход с небольшим запасом при уменьшении файловой системы помогает избежать ошибок, связанных с различиями в расчетах размеров (ГБ vs ГиБ) между LVM и файловой системой.
### Полный практический сценарий: от создания до удаления LVM

Рассмотрим полный цикл работы с LVM: добавление нового диска, расширение существующей группы томов, создание и расширение нового логического тома "на лету", а затем полный демонтаж и удаление.

**Важное замечание:** Загрузочный каталог `/boot` не должен находиться на LVM-томе, так как загрузчик (GRUB) должен иметь возможность прочитать ядро и `initramfs` до того, как LVM-драйверы будут активированы. Поэтому `/boot` всегда выносится на отдельный, обычный раздел.

#### 1. Подготовка диска и создание Physical Volume (PV)

1.  **Добавьте новый физический диск** в систему. Он появится в выводе `lsblk` (например, как `/dev/sdc`).

2.  **Создайте раздел и пометьте его для LVM** с помощью `parted`.
    ```bash
    sudo parted /dev/sdc
    # (parted) mklabel gpt
    # (parted) mkpart primary 0% 100%
    # (parted) set 1 lvm on
    # (parted) quit
    ```

3.  **Создайте Physical Volume (PV)** на новом разделе.
    ```bash
    sudo pvcreate /dev/sdc1
    # Physical volume "/dev/sdc1" successfully created
    ```
    Проверьте результат командой `pvs`. Вы увидите новый PV, который пока не принадлежит ни одной группе томов (VG).

#### 2. Расширение Volume Group (VG)

Добавим наш новый PV в существующую группу томов (например, `ubuntu-vg`), чтобы увеличить ее общий объем.

```bash
# Узнаем имя существующей VG
sudo vgs

# Расширяем VG
sudo vgextend ubuntu-vg /dev/sdc1
# Volume group "ubuntu-vg" successfully extended
```
Проверьте результат командой `vgs`. Размер и свободное пространство группы должны увеличиться.

#### 3. Создание и монтирование Logical Volume (LV)

"Нарежем" из обновленной группы томов новый логический том.

1.  **Создайте LV:**
    ```bash
    # lvcreate -L [размер] -n [имя_LV] [имя_VG]
    sudo lvcreate -L 1G -n my_test_lv ubuntu-vg
    # Logical volume "my_test_lv" created.
    ```

2.  **Отформатируйте LV:**
    ```bash
    sudo mkfs.ext4 /dev/ubuntu-vg/my_test_lv
    ```

3.  **Смонтируйте LV:**
    ```bash
    sudo mkdir /opt/test
    sudo mount /dev/ubuntu-vg/my_test_lv /opt/test
    ```
    Не забудьте добавить соответствующую запись в `/etc/fstab` для постоянного монтирования.

#### 4. Расширение LV "на лету"

Представим, что место на томе `my_test_lv` заканчивается. Расширим его, не останавливая работу.

```bash
# Добавляем 500 МБ к LV и сразу изменяем размер файловой системы (ключ -r)
sudo lvextend -L +500M -r /dev/ubuntu-vg/my_test_lv
#  Size of logical volume ubuntu-vg/my_test_lv changed...
#  Logical volume ubuntu-vg/my_test_lv successfully resized.
#  resize2fs 1.46.5 (30-Dec-2021)
#  Filesystem at /dev/mapper/ubuntu--vg-my_test_lv is mounted on /opt/test; on-line resizing required
#  ...
#  The filesystem on /dev/mapper/ubuntu--vg-my_test_lv is now 393216 (4k) blocks long.
```
Ключ `-r` (`--resizefs`) автоматически выполняет `resize2fs` после расширения тома, что очень удобно.

#### 5. Полное удаление LVM-структур (в обратном порядке)

Если том больше не нужен, его можно безопасно удалить.

1.  **Отмонтируйте LV:**
    ```bash
    sudo umount /opt/test
    ```
    Также удалите соответствующую запись из `/etc/fstab`.

2.  **Удалите Logical Volume (LV):**
    ```bash
    sudo lvremove /dev/ubuntu-vg/my_test_lv
    # Do you really want to remove active logical volume my_test_lv? [y/n]: y
    # Logical volume "my_test_lv" successfully removed
    ```

3.  **Уменьшите Volume Group (VG), удалив из нее PV:**
    ```bash
    sudo vgreduce ubuntu-vg /dev/sdc1
    # Removed "/dev/sdc1" from volume group "ubuntu-vg"
    ```

4.  **Удалите Physical Volume (PV):**
    Это сотрет метаданные LVM с диска.
    ```bash
    sudo pvremove /dev/sdc1
    # Labels on physical volume "/dev/sdc1" successfully wiped.
    ```
После этих шагов раздел `/dev/sdc1` и сам диск `/dev/sdc` можно использовать для других целей или физически извлечь из системы.

### Замена физического диска в Volume Group (pvmove)

Одной из мощных возможностей LVM является возможность замены физического диска в группе томов без остановки работы системы и потери данных. Это особенно полезно при апгрейде дисков на более емкие или при выходе диска из строя.

**Процесс замены диска:**

1.  **Подготовка нового диска:**
    *   Подключите новый физический диск к системе.
    *   Создайте на нем раздел и инициализируйте его как Physical Volume (PV) с помощью `pvcreate`.
    ```bash
    sudo pvcreate /dev/sdd1 # Предполагаем, что /dev/sdd1 - это новый PV
    ```
    *   Добавьте новый PV в существующую Volume Group (VG), из которой вы хотите удалить старый диск.
    ```bash
    sudo vgextend my_vg /dev/sdd1
    ```

2.  **Перемещение данных со старого диска:**
    Используйте команду `pvmove` для перемещения всех данных (физических экстентов) со старого PV на свободное пространство в той же VG (которое теперь включает новый PV).
    ```bash
    sudo pvmove /dev/sdc1 # Переместить данные с /dev/sdc1 на другие PV в my_vg
    ```
    *Примечание:* Этот процесс может занять значительное время в зависимости от объема данных. LVM автоматически распределит данные по доступным PV.

3.  **Удаление старого диска из VG:**
    После завершения `pvmove` старый PV будет полностью свободен от данных. Теперь его можно безопасно удалить из Volume Group.
    ```bash
    sudo vgreduce my_vg /dev/sdc1
    ```

4.  **Удаление PV-меток со старого диска:**
    Очистите метаданные LVM со старого диска, чтобы его можно было использовать для других целей или физически извлечь.
    ```bash
    sudo pvremove /dev/sdc1
    ```
    Теперь диск `/dev/sdc` можно безопасно извлечь из системы.

### Продвинутые/Пограничные случаи: Передача пространства между Volume Group (костыльный метод)

В стандартной архитектуре LVM прямое перемещение свободного пространства или логических томов между разными Volume Group не предусмотрено. Однако, в некоторых экстренных или временных сценариях можно использовать "костыльный" метод, основанный на том, что LVM может работать с блочными устройствами, включая другие логические тома.

**Внимание:** Этот метод является обходным путем и не рекомендуется для постоянного использования. Он может усложнить управление и отладку. Используйте его только в случае крайней необходимости и на короткий промежуток времени.

**Сценарий:** У нас есть `VG_SOURCE` со свободным местом и `VG_DEST` с нехваткой места. Мы хотим "передать" 500 МБ из `VG_SOURCE` в `VG_DEST`.

1.  **Создать временный логический том (LV) в `VG_SOURCE`:**
    Создаем LV нужного размера в исходной группе томов. Этот LV будет служить "транспортом" для пространства.
    ```bash
    # Создаем LV "temp_lv" размером 500 МБ в VG_SOURCE
    lvcreate -L 500M -n temp_lv VG_SOURCE
    ```
    Теперь `/dev/VG_SOURCE/temp_lv` является блочным устройством.

2.  **Инициализировать временный LV как Physical Volume (PV):**
    Мы можем инициализировать этот только что созданный логический том как физический том LVM.
    ```bash
    # Инициализируем temp_lv как PV
    pvcreate /dev/VG_SOURCE/temp_lv
    ```

3.  **Добавить новый PV (который на самом деле LV) в `VG_DEST`:**
    Теперь мы можем добавить этот "виртуальный" PV в целевую группу томов.
    ```bash
    # Добавляем temp_lv (как PV) в VG_DEST
    vgextend VG_DEST /dev/VG_SOURCE/temp_lv
    ```
    `VG_DEST` теперь увидит дополнительное свободное пространство, "пришедшее" из `VG_SOURCE` через `temp_lv`.

4.  **Использовать пространство в `VG_DEST`:**
    Теперь вы можете использовать это пространство в `VG_DEST` для расширения существующих LV или создания новых.

5.  **Очистка (после использования пространства в `VG_DEST`):**
    После того как вы использовали переданное пространство в `VG_DEST` (например, расширили другой LV), `temp_lv` в `VG_DEST` станет пустым. Его можно удалить.
    ```bash
    # Удалить temp_lv из VG_DEST
    vgreduce VG_DEST /dev/VG_SOURCE/temp_lv

    # Удалить PV-метки с temp_lv
    pvremove /dev/VG_SOURCE/temp_lv

    # Удалить сам логический том temp_lv из VG_SOURCE
    lvremove /dev/VG_SOURCE/temp_lv
    ```
    Этот метод позволяет временно "одолжить" пространство между VG, но требует аккуратности и понимания того, что вы делаете.

### Рекомендации по использованию LVM

LVM является мощным инструментом, но его применение не всегда оправдано. Вот несколько рекомендаций, основанных на опыте:

-   **Серверные решения и продакшн-среды:** LVM крайне полезен на серверах, где требуется высокая гибкость в управлении дисковым пространством, возможность "горячего" изменения размеров томов, создания снимков для резервного копирования и легкой замены физических дисков без простоя.
-   **Виртуальные выделенные серверы (WDS/VDS):** Идеальный сценарий для LVM. Некоторые провайдеры облачных услуг могут ограничивать максимальный размер одного диска (например, не более 300 ГБ), но позволять подключать несколько таких дисков. LVM позволяет "прозрачно" объединить эти диски в единую группу томов, создавая логический том нужного размера (например, 1 ТБ), и легко расширять его в будущем, просто добавляя новые диски от провайдера.
-   **Планируемое расширение дискового пространства:** Если вы предполагаете, что в будущем потребуется добавлять диски или увеличивать существующие разделы, LVM значительно упростит эти операции.
-   **Домашние компьютеры/рабочие станции:** Для простых домашних систем, где нет частой необходимости в динамическом изменении дисковой конфигурации, LVM может быть избыточным. Традиционное разбиение на разделы часто является достаточным и более простым в настройке. Однако, если вы планируете будущие апгрейды дисков, использование LVM может сэкономить время и усилия.
-   **LVM и RAID:** В современных условиях часто используются программные RAID (например, `mdadm`) в сочетании с LVM поверх них. Это позволяет получить преимущества обоих решений: отказоустойчивость RAID и гибкость LVM. Однако, как отмечалось в лекции, иногда можно обойтись и без `mdadm`, используя возможности LVM по зеркалированию, если это актуально.

## 3. Снимки (Snapshots)

LVM позволяет создавать "мгновенные" снимки логических томов. Снимок — это копия LV на определённый момент времени, которая занимает место только для изменившихся с момента создания данных (copy-on-write).

-   **Назначение:** Создание консистентных резервных копий без остановки работы сервисов.

-   **Создание снимка:**
    ```bash
    # Создать снимок для /dev/my_vg/my_lv размером 1 ГБ
    lvcreate -L 1G -s -n my_lv_snapshot /dev/my_vg/my_lv
    ```

-   **Использование:**
    Вы можете смонтировать снимок как обычный том и скопировать с него данные.
    ```bash
    mkdir /mnt/snapshot
    mount /dev/my_vg/my_lv_snapshot /mnt/snapshot
    ```

-   **Удаление снимка:**
    ```bash
    umount /mnt/snapshot
    lvremove /dev/my_vg/my_lv_snapshot
    ```

## 4. Тонкие тома (Thin Provisioning)

Тонкие тома — это функция LVM, которая позволяет создавать логические тома с "виртуальным" размером, превышающим доступное физическое пространство. Дисковое пространство выделяется для них динамически, по мере записи данных.

### Компоненты

1.  **Тонкий пул (Thin Pool):**
    -   Это специальный логический том, который служит "контейнером" для тонких томов. Он содержит реальное дисковое пространство, которое будет выделяться по мере необходимости.
    -   Тонкий пул также хранит метаданные о том, какие блоки какому тонкому тому принадлежат.

2.  **Тонкий том (Thin Volume):**
    -   Это логический том с виртуальным размером, созданный внутри тонкого пула.
    -   При создании он не занимает места (кроме метаданных). Пространство из пула выделяется только тогда, когда на том записываются данные.

### Преимущества

-   **Эффективное использование пространства:** Вы можете создать множество томов с большим виртуальным размером, но они будут занимать ровно столько места, сколько данных на них записано.
-   **Гибкость:** Легко создавать и удалять тома без необходимости заранее жестко выделять пространство.
-   **Снимки:** Тонкие тома поддерживают создание эффективных снимков, которые также являются тонкими томами и занимают минимум места.

### Создание и управление

1.  **Создание тонкого пула:**
    ```bash
    # Создать тонкий пул my_thin_pool размером 100 ГБ в группе томов my_vg
    lvcreate -L 100G --thinpool my_thin_pool my_vg
    ```

2.  **Создание тонкого тома:**
    ```bash
    # Создать тонкий том my_thin_lv с виртуальным размером 1 ТБ внутри пула my_thin_pool
    lvcreate -V 1T --thin -n my_thin_lv my_vg/my_thin_pool
    ```
    *Обратите внимание: виртуальный размер (1 ТБ) может быть больше реального размера пула (100 ГБ).*

3.  **Мониторинг:**
    Важно следить за заполнением тонкого пула, так как при его переполнении запись во все тонкие тома внутри него станет невозможной.
    ```bash
    lvs -o+thin_pool,thin_count,thin_provisioned
    ```

4.  **Расширение пула:**
    Если место в пуле заканчивается, его можно расширить.
    ```bash
    lvextend -L +50G my_vg/my_thin_pool
    ```

## 5. LVM и процесс загрузки Linux

Если корневая файловая система (`/`) находится на логическом томе LVM, для успешной загрузки операционной системы требуется специальный механизм.

-   **Роль `initramfs`**: На начальном этапе загрузки ядро Linux монтирует временную файловую систему в памяти — `initramfs` (initial RAM file system).
-   **Драйверы и утилиты**: `initramfs` содержит минимальный набор драйверов и утилит (включая LVM), которые необходимы для обнаружения групп томов (VG) и активации логических томов (LV).
-   **Монтирование корня**: После того как утилиты из `initramfs` соберут и активируют LVM-том, на котором находится корневая ФС, ядро сможет смонтировать его как `/` и продолжить процесс загрузки в обычном режиме.

### Практический пример: от создания до горячей замены диска

Этот сценарий, основанный на практической демонстрации, показывает полный жизненный цикл управления LVM, включая создание, расширение и, что самое важное, "горячую" замену физического диска без остановки работы.

**Исходные данные:**
- Диск `/dev/sda` с разделом `/dev/sda1` размером 2 ГБ.

**Шаг 1: Создание базовой LVM-структуры**

1.  **Инициализация Physical Volume (PV):**
    ```bash
    pvcreate /dev/sda1
    ```

2.  **Создание Volume Group (VG):**
    ```bash
    vgcreate vg_test /dev/sda1
    ```

3.  **Создание Logical Volume (LV):**
    ```bash
    # Создаем LV размером 1 ГБ
    lvcreate -L 1G -n lv_test1 vg_test
    ```

4.  **Форматирование и монтирование:**
    ```bash
    mkfs.ext4 /dev/vg_test/lv_test1
    mkdir /mnt/test1
    mount /dev/vg_test/lv_test1 /mnt/test1
    ```

**Шаг 2: Расширение LV за счет нового диска**

Представим, что нам нужно увеличить размер `lv_test1`, но в `vg_test` больше нет места.

1.  **Подготовка нового раздела:**
    - Создаем на диске новый раздел, например, `/dev/sda2` размером 2 ГБ.
    - Уведомляем ядро об изменениях: `partprobe`

2.  **Добавление нового диска в LVM:**
    ```bash
    # Инициализируем новый раздел как PV
    pvcreate /dev/sda2
    # Расширяем нашу VG, добавляя в нее новый PV
    vgextend vg_test /dev/sda2
    ```
    Теперь в `vg_test` появилось дополнительное свободное пространство.

3.  **Расширение LV и файловой системы:**
    Используем ключ `-r` (`--resizefs`), чтобы LVM автоматически выполнил `resize2fs` после расширения тома.
    ```bash
    # Добавляем 1 ГБ к lv_test1 и автоматически расширяем файловую систему
    lvextend -L +1G -r /dev/vg_test/lv_test1
    ```
    Проверка с помощью `df -h` покажет, что размер файловой системы увеличился.

**Шаг 3: "Горячая" замена диска `/dev/sda1`**

Это самая интересная часть. Нам нужно заменить диск `/dev/sda1` на новый, не отмонтируя файловые системы и не останавливая сервисы.

1.  **Подготовка "эвакуационного" пространства:**
    - Для того чтобы освободить `/dev/sda1`, нам нужно, чтобы в VG было достаточно свободного места для перемещения всех его данных. Размер свободного места должен быть не меньше, чем объем данных на `/dev/sda1`.
    - Добавим еще один диск/раздел (`/dev/sda3`) в `vg_test` по аналогии с Шагом 2.

2.  **Перемещение данных (миграция экстентов):**
    Команда `pvmove` перемещает все экстенты с указанного PV на другие свободные PV в той же VG.
    ```bash
    # Запускаем миграцию данных с /dev/sda1. Это может занять много времени.
    pvmove /dev/sda1
    ```
    Эта операция происходит "на лету". После ее завершения PV `/dev/sda1` становится полностью свободным.

3.  **Извлечение старого диска из LVM:**
    ```bash
    # Удаляем PV из группы томов
    vgreduce vg_test /dev/sda1

    # Стираем LVM-метки с диска
    pvremove /dev/sda1
    ```

Теперь раздел `/dev/sda1` полностью выведен из-под управления LVM и может быть использован для других целей или физически удален из системы. Все данные при этом остались доступны на своих местах, так как LVM "прозрачно" переместил их на другие диски в группе.
