# Управление программным RAID с помощью mdadm

`mdadm` (multiple devices administration) — это стандартная утилита в Linux для создания и управления программными RAID-массивами.

RAID (Redundant Array of Independent Disks) — это технология объединения нескольких физических дисков в один логический массив для достижения одной или нескольких целей:
- **Увеличение объема**: Суммарный объем массива становится больше объема одного диска.
- **Повышение производительности**: Операции чтения и записи могут распараллеливаться между дисками.
- **Повышение отказоустойчивости**: Выход из строя одного или нескольких дисков не приводит к потере данных.

Существуют различные реализации RAID-контроллеров:
- **Программный RAID (Software RAID)**: Создается средствами операционной системы. Производительность зависит от ЦПУ системы, так как все операции по управлению массивом выполняет он. Это наиболее гибкий и дешевый вариант.
- **Аппаратный RAID (Hardware RAID)**: Управляется специальной платой (RAID-контроллером) со своим процессором и кэш-памятью. Обеспечивает максимальную производительность и не зависит от ОС, но является дорогостоящим решением.
- **Интегрированный RAID**: Гибридное решение, где функции контроллера встроены в чипсет материнской платы.

`mdadm` является инструментом для работы именно с программным RAID в Linux.

## Уровни RAID

-   **RAID 0 (Striping / Чередование)**:
    -   **Принцип**: Данные "нарезаются" на блоки (страйпы) и последовательно записываются на все диски массива. Это позволяет распараллелить операции чтения/записи.
    -   **Преимущества**: Максимальная производительность (скорость практически суммируется). Полезный объем равен сумме объемов всех дисков.
    -   **Недостатки**: **Нет отказоустойчивости.** Выход из строя любого диска приводит к потере **всех** данных на всем массиве.
    -   **Мин. дисков**: 2.
    -   **Применение**: Задачи, где скорость важнее надежности (например, временные файлы для видеомонтажа, кэш).

-   **RAID 1 (Mirroring / Зеркалирование)**:
    -   **Принцип**: Данные полностью дублируются (зеркалируются) на все диски в массиве.
    -   **Преимущества**: **Высокая отказоустойчивость.** Массив продолжает работать, пока функционирует хотя бы один диск.
    -   **Недостатки**: Потеря ёмкости. Полезный объем равен объему наименьшего диска. Скорость записи ограничена скоростью самого медленного диска.
    -   **Мин. дисков**: 2.
    -   **Применение**: Хранение операционной системы, баз данных, критически важных файлов.

-   **RAID 5 (Striping with Distributed Parity / Чередование с распределенным контролем четности)**:
    -   **Принцип**: Данные, как и в RAID 0, разбиваются на блоки и распределяются по дискам. Дополнительно для каждого блока данных вычисляется блок четности (контрольная сумма), который также записывается на один из дисков. Блоки данных и блоки четности равномерно "размазываются" по всем дискам.
    -   **Преимущества**: Хороший баланс между производительностью (чуть ниже, чем у RAID 0) и надёжностью. Полезный объем равен (N-1) * размер диска.
    -   **Недостатки**: Выдерживает отказ только **одного** диска. Операции записи медленнее из-за необходимости вычисления и записи блоков четности. Процесс восстановления (rebuild) после сбоя создает высокую нагрузку.
    -   **Мин. дисков**: 3 (до 16).
    -   **Применение**: Файловые серверы, хранилища данных.

-   **RAID 6 (Striping with Dual Parity)**:
    -   **Принцип**: Аналогичен RAID 5, но использует **два** блока четности для каждого блока данных, вычисленных по разным алгоритмам.
    -   **Преимущества**: Повышенная отказоустойчивость. Выдерживает одновременный отказ **двух** дисков.
    -   **Недостатки**: Более медленная запись, чем у RAID 5. Потеря ёмкости составляет 2 диска.
    -   **Мин. дисков**: 4.
    -   **Применение**: Критически важные хранилища данных большого объема.

-   **RAID 10 (1+0, Mirror of Stripes)**:
    -   **Принцип**: Комбинация зеркалирования и чередования. Сначала диски объединяются в пары с чередованием (RAID 0), а затем эти пары зеркалируются (RAID 1).
    -   **Преимущества**: Высокая скорость (как у RAID 0) и высокая надёжность (как у RAID 1). Может пережить отказ одного диска в каждой зеркальной паре.
    -   **Недостатки**: Теряется 50% ёмкости. Требуется минимум 4 диска, и их число должно быть четным.
    -   **Применение**: Высоконагруженные базы данных и серверы, где требуется и максимальная скорость, и высокая отказоустойчивость.

## Полный практический цикл управления RAID 1 (зеркало)

Рассмотрим на примере создания, управления сбоями и удаления массива `/dev/md0` из двух дисков: `/dev/sdb` и `/dev/sdc`.

### 1. Подготовка дисков

Для каждого диска, который будет участвовать в массиве, нужно создать раздел и пометить его для использования в RAID.

```bash
# Запускаем parted для первого диска
sudo parted /dev/sdb

# (parted) Создаем таблицу разделов GPT
mklabel gpt

# (parted) Создаем раздел на весь диск
mkpart primary 0% 100%

# (parted) Включаем флаг 'raid' для этого раздела
set 1 raid on

# (parted) Выходим
quit
```
Повторите те же действия для второго диска (`/dev/sdc`). Убедитесь, что на разделах нет старых метаданных RAID: `sudo mdadm --examine /dev/sdb1`. Если суперблок найден, его нужно затереть: `sudo mdadm --zero-superblock /dev/sdb1`.

### 2. Создание массива

1.  **Мониторинг в реальном времени (в отдельном терминале):**
    ```bash
    watch cat /proc/mdstat
    ```
    Это позволит наблюдать за состоянием RAID-массивов вживую.

2.  **Создание массива:**
    ```bash
    # /dev/md0 — имя будущего массива
    # --level=1 — уровень RAID (зеркало)
    # --raid-devices=2 — количество устройств в массиве
    # /dev/sdb1 и /dev/sdc1 — разделы-участники
    sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
    ```
    После выполнения команды в окне с `watch` начнется процесс синхронизации (resync).

### 3. Сохранение конфигурации и обновление ядра

1.  **Сохранение конфигурации массива:**
    Чтобы массив автоматически собирался при загрузке, его конфигурацию нужно сохранить в файл `/etc/mdadm/mdadm.conf`.
    ```bash
    # Эта команда просканирует существующие массивы и добавит их в файл конфигурации
    sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

2.  **Обновление initramfs:**
    Поскольку RAID-массив может быть необходим на ранних этапах загрузки, нужно обновить `initramfs`, чтобы ядро знало о конфигурации массива.
    ```bash
    sudo update-initramfs -u
    ```

### 4. Создание ФС и монтирование

1.  **Создание файловой системы** на массиве:
    ```bash
    sudo mkfs.ext4 /dev/md0
    ```

2.  **Монтирование и добавление в `/etc/fstab`** для автозагрузки:
    ```bash
    sudo mkdir /mnt/raid1
    sudo mount /dev/md0 /mnt/raid1
    # ...затем редактируем /etc/fstab, используя UUID массива (sudo blkid /dev/md0)
    ```

### 5. Мониторинг и управление сбоями

-   **Детальная информация:**
    ```bash
    sudo mdadm --detail /dev/md0
    ```
    Здесь виден статус массива (`State : active`), его участников (`active sync`) и процесс восстановления.

-   **Краткая информация в реальном времени:**
    ```bash
    watch cat /proc/mdstat
    ```
    В выводе `mdstat` для здорового RAID 1 вы увидите `[UU]`, где `U` означает, что диск активен (Up).

#### Сценарий 1: "Горячий" сбой и восстановление

1.  **Имитация сбоя**: Физически отключаем один из дисков или помечаем его как сбойный.
    ```bash
    sudo mdadm /dev/md0 --fail /dev/sdb1
    ```
    `cat /proc/mdstat` покажет статус `[_U]` или `[U_]`. Массив работает в **деградировавшем режиме (degraded mode)**. Данные по-прежнему доступны.

2.  **Удаление сбойного диска** из массива:
    ```bash
    sudo mdadm /dev/md0 --remove /dev/sdb1
    ```

3.  **Добавление нового/исправленного диска**:
    После подключения нового диска и его подготовки (шаг 1), добавляем его в массив.
    ```bash
    sudo mdadm /dev/md0 --add /dev/sdb1
    ```
    Начнется процесс восстановления (rebuild), за которым можно следить через `cat /proc/mdstat`.

#### Сценарий 2: "Холодный" сбой и восстановление из Maintenance Mode

Если система была выключена, один из дисков изъят, а потом система включена, `mdadm` может не собрать массив автоматически, и система загрузится в **режим обслуживания (maintenance mode)**.

1.  **Остановка массива**: В режиме обслуживания остановите неактивный массив.
    ```bash
    mdadm --stop /dev/md0
    ```

2.  **Принудительная сборка (Force Assemble)**: Соберите массив из оставшихся "живых" дисков.
    ```bash
    # --run заставляет массив запуститься, даже если не все диски на месте
    mdadm --assemble --run /dev/md0 /dev/sdc1
    ```

3.  **Проверка и перезагрузка**: Убедитесь, что массив активен (`cat /proc/mdstat`), смонтируйте его вручную, если нужно, и перезагрузите систему (`reboot`). После этого можно в штатном режиме заменить сбойный диск, как в Сценарии 1.

## Полный практический цикл управления RAID 5

Рассмотрим на примере создания, управления сбоями и расширения массива `/dev/md0`, собранного из трех дисков: `/dev/vdb`, `/dev/vdc`, `/dev/vdd`. Диск `/dev/vde` будет использоваться как запасной для имитации замены.

### 1. Создание массива

Предполагается, что диски уже подготовлены (созданы разделы с типом `linux_raid_autodetect`).

1.  **Создание массива RAID 5:**
    ```bash
    # --create /dev/md0 — имя будущего массива
    # --verbose — подробный вывод
    # --level=5 — уровень RAID
    # --raid-devices=3 — количество устройств в массиве
    sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 /dev/vdb /dev/vdc /dev/vdd
    ```

2.  **Мониторинг процесса создания:**
    Сразу после создания начнется процесс синхронизации (rebuild). За ним можно наблюдать в реальном времени.
    ```bash
    watch cat /proc/mdstat
    ```
    Вывод будет выглядеть примерно так, с указанием прогресса:
    ```
    md0 : active raid5 vdd[2] vdc[1] vdb[0]
          10475520 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/3] [UUU]
          [=>...................]  resync =  5.0% (524288/10475520) finish=1.5min speed=104857K/sec
    ```

### 2. Сохранение конфигурации, создание ФС и монтирование

1.  **Сохранение конфигурации массива:**
    Чтобы массив автоматически собирался при загрузке, его конфигурацию нужно сохранить в `/etc/mdadm/mdadm.conf`.
    ```bash
    # Сканируем массив и добавляем его в файл конфигурации
    sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
    ```

2.  **Обновление initramfs:**
    Это необходимо, чтобы ядро знало о конфигурации массива на ранних этапах загрузки.
    ```bash
    sudo update-initramfs -u
    ```

3.  **Создание файловой системы:**
    ```bash
    sudo mkfs.ext4 /dev/md0
    ```

4.  **Монтирование и добавление в `/etc/fstab`:**
    ```bash
    sudo mkdir /mnt/raid5
    sudo mount /dev/md0 /mnt/raid5
    
    # Получаем UUID для добавления в fstab
    sudo blkid /dev/md0
    
    # Добавляем строку в /etc/fstab:
    # UUID=<...uuid_from_blkid...> /mnt/raid5 ext4 defaults 0 2
    ```

### 3. Мониторинг и управление сбоями

-   **Детальная информация:**
    ```bash
    sudo mdadm --detail /dev/md0
    ```
    Вывод покажет состояние (`State : clean`), количество активных и рабочих дисков.

-   **Имитация сбоя диска:**
    Пометим один из дисков как сбойный.
    ```bash
    sudo mdadm /dev/md0 --fail /dev/vdb
    ```
    `cat /proc/mdstat` покажет массив в деградировавшем состоянии, например `[U_U]`. Массив продолжит работать. `mdadm --detail` покажет статус диска `faulty`.

-   **Удаление сбойного диска:**
    ```bash
    sudo mdadm /dev/md0 --remove /dev/vdb
    ```

-   **Добавление нового диска:**
    Добавляем новый (или "отремонтированный") диск в массив. В нашем случае это `/dev/vde`.
    ```bash
    sudo mdadm /dev/md0 --add /dev/vde
    ```
    Сразу после добавления начнется процесс восстановления (rebuild), за которым можно следить через `cat /proc/mdstat`. По завершении массив вернется в состояние `clean`.

### 4. Расширение массива (Grow)

`mdadm` позволяет добавлять диски в существующий RAID 5 массив "на лету".

1.  **Добавление нового диска в массив:**
    Допустим, мы хотим добавить диск `/dev/vdb` (который ранее был "сбойным", а теперь "исправлен") в массив, чтобы увеличить его объем.
    ```bash
    sudo mdadm /dev/md0 --add /dev/vdb
    ```
    Сначала диск будет добавлен как запасной (`spare`).

2.  **Запуск процесса расширения:**
    Указываем `mdadm`, что нужно изменить количество дисков в массиве с 3 до 4.
    ```bash
    # --grow — команда для изменения размера
    # --raid-devices=4 — новое количество дисков
    sudo mdadm --grow /dev/md0 --raid-devices=4
    ```
    Начнется длительный процесс `reshape`, во время которого данные будут перераспределены по всем четырем дискам. За прогрессом можно следить через `cat /proc/mdstat`.

3.  **Изменение размера файловой системы:**
    После завершения `reshape` сам массив станет больше, но файловая система на нем останется прежнего размера. Ее нужно расширить.
    ```bash
    # Для файловых систем ext2/3/4
    sudo resize2fs /dev/md0
    ```
    Теперь команда `df -h` покажет новый, увеличенный размер файловой системы.

4.  **Обновление конфигурации:**
    Не забудьте обновить конфигурационный файл после изменения состава массива.
    ```bash
    sudo mdadm --detail --scan | sudo tee /etc/mdadm/mdadm.conf
    sudo update-initramfs -u
    ```

## Полное удаление RAID-массива

1.  **Отмонтировать файловую систему**:
    ```bash
    sudo umount /dev/md0
    ```

2.  **Удалить запись из `/etc/fstab`**.

3.  **Остановить массив**:
    ```bash
    sudo mdadm --stop /dev/md0
    ```

4.  **Затереть суперблоки**: Это самый важный шаг. Он удаляет метаданные RAID с дисков-участников, после чего `mdadm` перестает их видеть как часть массива.
    ```bash
    # Замените на реальные диски вашего массива
    sudo mdadm --zero-superblock /dev/sdb1
    sudo mdadm --zero-superblock /dev/sdc1
    # ... и так далее для всех дисков
    ```

5.  **Удалить конфигурацию**: Удалите соответствующую строку из `/etc/mdadm/mdadm.conf`.

6.  **Обновить `initramfs`**:
    ```bash
    sudo update-initramfs -u
    ```
Теперь бывшие диски-участники свободны и могут использоваться для других целей.
