# `systemd-journald`: Централизованный сбор логов

## Определения

*   **`systemd-journald`** — это системная служба, которая централизованно собирает и управляет логами от всех компонентов операционной системы, включая ядро, службы и приложения.
*   **`journalctl`** — это утилита командной строки для просмотра, фильтрации и анализа логов, собранных `systemd-journald`. **Подробное описание утилиты `journalctl` и её использования находится в [Linux/Diagnostics/Logging/journalctl.md](../Diagnostics/Logging/journalctl.md).**

## Основные концепции

### Структурированное логирование

Ключевой особенностью `journald` является хранение данных в **структурированном бинарном формате**, а не в виде простого текста. Каждое сообщение автоматически обогащается метаданными, такими как служба-источник (unit), ID процесса (PID), ID пользователя (UID) и уровень приоритета.

В отличие от традиционных текстовых логов (например, в `rsyslog`), бинарный формат `journald` позволяет надежно фильтровать и анализировать данные по метаданным. Это устраняет необходимость в парсинге текстовых строк и делает отладку более эффективной.

### Хранение логов

1.  **Энергозависимое (Volatile):** По умолчанию логи хранятся в `/run/log/journal`. Эта директория монтируется как `tmpfs` и очищается при каждой перезагрузке системы.
2.  **Постоянное (Persistent):** Если создать директорию `/var/log/journal`, `journald` автоматически начнет использовать её для постоянного хранения логов, которые будут сохраняться между перезагрузками.

## Практические сценарии

### Настройка постоянного хранения

Чтобы логи сохранялись после перезагрузки:

```bash
# 1. Создание директории для постоянного хранения
sudo mkdir -p /var/log/journal

# 2. Перезапуск службы для применения изменений
sudo systemctl restart systemd-journald
```

Система автоматически начнет использовать новую директорию.

## Дополнительная информация

### Ограничение размера журнала

Чтобы логи не заняли весь диск, необходимо настроить лимиты в файле `/etc/systemd/journald.conf`:

```ini
[Journal]
# Максимальный общий размер журнала (например, 4 ГБ)
SystemMaxUse=4G

# Минимальный объем свободного места, который должен оставаться на диске
SystemKeepFree=15%

# Максимальный размер одного файла журнала
SystemMaxFileSize=200M
```

После изменения файла перезапустите службу: `sudo systemctl restart systemd-journald`. Проверить текущий размер журнала можно командой `journalctl --disk-usage`.

### Интеграция с `rsyslog`

Хотя `journald` отлично подходит для локального хранения и анализа, для пересылки логов на удаленные серверы часто используется [rsyslog](./rsyslog.md). `rsyslog` может забирать сообщения напрямую из `journald` для их дальнейшей фильтрации и отправки в централизованное хранилище.
