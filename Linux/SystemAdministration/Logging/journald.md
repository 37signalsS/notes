# systemd-journald: Централизованный сбор логов

## Определения

* **`systemd-journald`** — системная служба, централизованно собирающая логи от всех компонентов ОС (Операционная Система): ядро, службы, приложения, stdout/stderr (стандартный вывод / стандартный вывод ошибок) в структурированном бинарном формате.
* **`journalctl`** — утилита командной строки для просмотра и анализа логов, собранных `systemd-journald`. **Подробное описание утилиты `journalctl` находится в [journalctl_overview.md](../../Diagnostics/journalctl/journalctl_overview.md).**

## Базовые концепции

### Архитектура и принцип работы

`systemd-journald` работает как демон, управляемый системой инициализации systemd. Основные механизмы:

1. **Сбор логов:**
   * Перехватывает сообщения ядра через `kmsg`.
   * Получает логи от служб systemd через Unix-сокеты.
   * Собирает stdout/stderr сервисов.
   * Принимает сообщения через сокет, совместимый с syslog.

2. **Структурированное хранение:**
   * Каждое сообщение — набор пар `ключ=значение`.
   * Автоматически добавляемые поля: `_PID` (Process ID), `_UID` (User ID), `_COMM` (имя команды), `_EXE` (путь к исполняемому файлу).
   * Индексация для быстрого поиска по времени, идентификаторам и приоритету.

3. **Формат хранения:**
   * Бинарные файлы в `/run/log/journal/` (volatile — временные) или `/var/log/journal/` (persistent — постоянные).
   * Файлы именуются по UUID (Universally Unique Identifier) машины: `machine-id.journal`.
   * Автоматическая ротация (переключение на новый файл) при достижении лимитов.

### Поля журнала

Каждое сообщение в журнале содержит стандартные метаданные:

| Поле | Описание |
| :--- | :--- |
| `MESSAGE` | Текст сообщения |
| `PRIORITY` | Уровень приоритета (0–7, см. уровни приоритета syslog) |
| `_PID` | PID (Process ID) отправителя |
| `_UID` | UID (User ID) пользователя, от имени которого запущен процесс |
| `_COMM` | Имя исполняемого файла (короткое) |
| `_EXE` | Полный путь к исполняемому файлу |
| `_SYSTEMD_UNIT` | Имя systemd-юнита (сервиса) |
| `_HOSTNAME` | Имя хоста |
| `_MACHINE_ID` | UUID машины |
| `_BOOT_ID` | UUID текущей загрузки |
| `CODE_FILE`, `CODE_LINE` | Позиция в исходном коде (если доступно) |
| `MESSAGE_ID` | Уникальный идентификатор типа сообщения |

Полный список доступных полей: `journalctl --fields`.

### Уровни приоритета

Стандартные уровни приоритета согласно RFC 5424:

| Код | Уровень | Описание |
| :--- | :--- | :--- |
| 0 | `emerg` | Система неработоспособна |
| 1 | `alert` | Требуется немедленное действие |
| 2 | `crit` | Критические условия |
| 3 | `err` | Ошибки |
| 4 | `warning` | Предупреждения |
| 5 | `notice` | Нормальные, но значимые события |
| 6 | `info` | Информационные сообщения |
| 7 | `debug` | Отладочные сообщения |

### Хранение логов

1. **Энергозависимое (Volatile):** По умолчанию логи хранятся в `/run/log/journal`. Директория монтируется как `tmpfs` (временная файловая система в оперативной памяти) и очищается при перезагрузке.
2. **Постоянное (Persistent):** При наличии директории `/var/log/journal`, демон автоматически переходит в режим постоянного хранения.

**Проверка режима хранения:**

```bash
# Проверить текущий режим
ls -la /var/log/journal/ 2>/dev/null && echo "Persistent" || echo "Volatile"
# → Persistent

# Проверить размер журнала
journalctl --disk-usage
# → Archived and active journals take up 512.0M in the file system.
```

## Практические сценарии

### Настройка постоянного хранения

Для сохранения логов после перезагрузки:

```bash
# 1. Создание директории для постоянного хранения
sudo mkdir -p /var/log/journal

# 2. Установка прав (группа systemd-journal)
sudo chown root:systemd-journal /var/log/journal
sudo chmod 2755 /var/log/journal

# 3. Перезапуск службы
sudo systemctl restart systemd-journald
```

### Ограничение размера журнала

Настройка производится в `/etc/systemd/journald.conf` (секция `[Journal]`):

```ini
[Journal]
# Максимальный общий размер журнала
SystemMaxUse=500M

# Минимальный объем свободного места на диске
SystemKeepFree=15%

# Максимальный размер одного файла журнала
SystemMaxFileSize=100M

# Режим хранения: auto, persistent, volatile, none
Storage=auto

# Ограничение скорости записи (Rate Limiting)
RateLimitIntervalSec=5s
RateLimitBurst=10000
```

**Применение настроек:**

```bash
sudo systemctl restart systemd-journald
```

**Параметры лимитов:**

| Параметр | Описание | Пример |
| :--- | :--- | :--- |
| `SystemMaxUse` | Максимальный объем на диске | `500M`, `4G` |
| `SystemKeepFree` | Минимальный запас свободного места | `15%`, `10G` |
| `SystemMaxFileSize` | Лимит размера одного файла | `100M` |
| `RuntimeMaxUse` | Лимит для volatile-хранилища | `200M` |

### Очистка журнала

**Ручная очистка (Vacuuming):**

Подробные инструкции по очистке через `journalctl` описаны в:
**[Управление хранением и очистка journalctl](../../Diagnostics/journalctl/journalctl_management.md)**

**Автоматическая очистка через systemd-tmpfiles:**

Создать файл `/etc/tmpfiles.d/systemd-journald.conf`:

```conf
# Тип  Путь                     Режим Владелец Группа Возраст
R    /var/log/journal          -      -       -       -
e    /var/log/journal          -      -       -       14d
```

Параметр `Age` (14d) указывает, что файлы старше 14 дней будут удалены.

### Интеграция с syslog

Для поддержки старых приложений `journald` может пересылать сообщения в сокет syslog:

```ini
# В /etc/systemd/journald.conf
[Journal]
ForwardToSyslog=yes
```

## Дополнительная информация

### Безопасность и целостность

* **Защита от подделки:** Бинарный формат затрудняет ручное редактирование.
* **FSS (Forward Secure Sealing):** Криптографическое подписывание логов для обнаружения несанкционированных изменений.
* **ACL (Access Control List — список контроля доступа):** Доступ ограничен пользователями групп `systemd-journal`, `adm` и `wheel`.

### Производительность

* **Асинхронная запись:** Используется по умолчанию для снижения нагрузки на ввод-вывод.
* **Синхронная запись:** Можно настроить через `SyncIntervalSec`.

### Типичные проблемы

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| Логи пропадают после ребута | Режим volatile | Создать `/var/log/journal` |
| Журнал переполняет диск | Нет лимитов | Настроить `SystemMaxUse` |
| Высокая нагрузка на CPU | Интенсивный поток логов | Ограничить логирование в приложении или через `RateLimit` (CPU — Central Processing Unit) |
| Повреждение файлов | Сбой ФС (Файловая Система) | Удалить поврежденные файлы в `/var/log/journal/` |
