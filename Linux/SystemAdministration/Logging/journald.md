# systemd-journald: Современная система логирования

`journald` — это централизованная служба, которая собирает логи от всех компонентов системы (ядро, службы, приложения) в структурированном бинарном формате. Основной инструмент для работы — `journalctl`.

В отличие от текстовых логов `rsyslog`, `journald` хранит данные в бинарном формате, обогащая каждое сообщение полезными метаданными (например, от какой службы оно пришло, ID процесса, ID пользователя и т.д.).

## Просмотр логов (`journalctl`)

-   **Просмотр в реальном времени:**
    ```bash
    # Следить за всеми логами
    journalctl -f
    ```

-   **Фильтрация по службе (unit):**
    ```bash
    # Показать логи только для nginx и следить за ними
    journalctl -u nginx.service -f
    ```

-   **Фильтрация по времени:**
    ```bash
    # Логи за последний час
    journalctl --since "1 hour ago"

    # Логи за определённый период
    journalctl --since "2024-10-20 10:00:00" --until "2024-10-20 11:00:00"
    ```

-   **Фильтрация по уровню приоритета:**
    ```bash
    # Показать только ошибки (err) и более критичные сообщения
    journalctl -p err
    ```
    **Уровни (от высшего к низшему):** `emerg` (0), `alert` (1), `crit` (2), `err` (3), `warning` (4), `notice` (5), `info` (6), `debug` (7).

-   **Просмотр логов ядра (аналог `dmesg`):**
    ```bash
    journalctl -k
    ```

-   **Структурированный вывод:**
    `journald` хранит метаданные для каждого сообщения. Их можно вывести в формате JSON.
    ```bash
    # Вывести последние 5 сообщений в формате JSON
    journalctl -n 5 -o json-pretty
    ```

## Постоянное хранение и ограничение размера

По умолчанию `journald` хранит логи в `/run/log/journal` (очищается при перезагрузке).

1.  **Включение постоянного хранения:**
    Чтобы логи сохранялись после перезагрузки, необходимо изменить параметр `Storage` в `/etc/systemd/journald.conf` на `persistent` или создать директорию `/var/log/journal`.
    ```bash
    # Создание директории для постоянного хранения логов
    sudo mkdir -p /var/log/journal
    # Применение изменений (systemd-tmpfiles создаст необходимые файлы и установит права)
    sudo systemd-tmpfiles --create --prefix /var/log/journal
    sudo systemctl restart systemd-journald
    ```
    После этого `journald` будет автоматически использовать `/var/log/journal` для постоянного хранения.

2.  **Ограничение размера журнала:**
    Чтобы логи не заняли весь диск, настройте лимиты в `/etc/systemd/journald.conf`:
    ```ini
    [Journal]
    # Максимальный общий размер журнала (например, 4 ГБ)
    SystemMaxUse=4G

    # Минимальный объем свободного места, который должен оставаться
    SystemKeepFree=15%

    # Максимальный размер одного файла журнала
    SystemMaxFileSize=200M
    ```
    После изменения файла перезапустите службу: `sudo systemctl restart systemd-journald`.
    Проверить текущий размер журнала можно командой: `journalctl --disk-usage`.

---

В современных системах `journald` часто интегрируется с [rsyslog.md](./rsyslog.md) для пересылки логов на удаленные серверы.
