# auditd: Аудит событий безопасности

## Определения

**`auditd`** (Audit Daemon) — это система, которая отслеживает события безопасности на уровне ядра (системные вызовы). Она позволяет детально протоколировать действия в системе, отвечая на вопросы: **кто, когда, что и с каким объектом сделал**.

В отличие от `rsyslog` и `journald`, которые фокусируются на сообщениях от служб и приложений, `auditd` работает на более низком уровне. Это делает его мощным инструментом для отслеживания изменений в файловой системе, мониторинга доступа к важным файлам и расследования инцидентов безопасности.

## Базовые концепции

### Правила аудита (Audit Rules)

Работа `auditd` основана на наборе правил, которые определяют, какие события необходимо отслеживать. Правила могут быть заданы для:

- **Файлов и директорий:** Мониторинг чтения, записи, исполнения или изменения атрибутов.
- **Системных вызовов:** Отслеживание конкретных вызовов ядра.

### Ключи аудита (Audit Keys)

При создании правила можно указать **ключ** (`-k key_name`). Этот ключ представляет собой текстовую метку, которая добавляется ко всем событиям, сгенерированным этим правилом. Использование ключей значительно упрощает поиск и фильтрацию событий в логах.

## Практические сценарии

### Отслеживание изменений файла

1. **Установить правило для отслеживания.**
    Отследим, кто изменяет (`w`) или меняет атрибуты (`a`) файла `/etc/passwd`.

    ```bash
    # -w /path/to/file: путь к файлу
    # -p wa: права доступа (w - write, a - attribute change)
    # -k key_name: уникальный ключ для поиска
    sudo auditctl -w /etc/passwd -p wa -k passwd_changes
    ```

2. **Найти события в логе.**
    Для поиска по ключу используется `ausearch`. Логи хранятся в `/var/log/audit/audit.log`.

    ```bash
    sudo ausearch -k passwd_changes
    ```

    Вывод покажет `uid` (ID пользователя), `pid` (ID процесса) и команду, которая изменила файл.

3. **Сгенерировать отчет (опционально).**
    Утилита `aureport` помогает создавать сводные отчеты из логов аудита.

    ```bash
    # Отчет о событиях аутентификации
    sudo aureport -au
    ```

## Дополнительная информация

### Постоянное хранение правил

Правила, добавленные через `auditctl`, сбрасываются после перезагрузки. Для их постоянного хранения необходимо добавить их в файл `/etc/audit/rules.d/audit.rules` и перезапустить службу `auditd`.

```bash
# Пример добавления правила в файл
echo "-w /etc/passwd -p wa -k passwd_changes" | sudo tee -a /etc/audit/rules.d/audit.rules

# Перезапуск службы для применения правил
sudo systemctl restart auditd
```
