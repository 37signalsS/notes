# Аудит доступа: auditd

`auditd` — это система, которая отслеживает события на уровне ядра (системные вызовы). Она отвечает на вопросы: **кто, когда, что и с каким файлом сделал**. Это мощный инструмент для отслеживания изменений в системе и расследования инцидентов безопасности, дополняющий стандартные системы логирования.

В то время как `rsyslog` и `journald` фокусируются на сообщениях от служб и приложений, `auditd` работает на более низком уровне, перехватывая взаимодействие с ядром.

## Пример: отслеживание изменений файла

1.  **Установить правило для отслеживания.**
    Отследим, кто изменяет (`w`) или меняет атрибуты (`a`) файла `/etc/passwd`.
    ```bash
    # -w /path/to/file: путь к файлу
    # -p wa: права доступа (w - write, r - read, x - execute, a - attribute change)
    # -k key_name: уникальный ключ для поиска
    sudo auditctl -w /etc/passwd -p wa -k passwd_changes
    ```

2.  **Найти события в логе.**
    Для поиска по ключу используется `ausearch`. Логи хранятся в `/var/log/audit/audit.log`.
    ```bash
    sudo ausearch -k passwd_changes
    ```
    Вывод покажет `uid` (ID пользователя), `pid` (ID процесса) и команду, которая изменила файл.

3.  **Сгенерировать отчет (опционально).**
    Утилита `aureport` помогает создавать сводные отчеты из логов аудита.
    ```bash
    # Отчет о событиях аутентификации
    sudo aureport -au
    ```

**Важно:** Правила, добавленные через `auditctl`, сбрасываются после перезагрузки. Для постоянного хранения добавляйте их в файл `/etc/audit/rules.d/audit.rules`.
