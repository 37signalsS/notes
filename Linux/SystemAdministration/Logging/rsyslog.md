# rsyslog: Фильтрация и пересылка логов

## Определения

**`rsyslog`** (Rocket-fast System for Log Processing) — это высокопроизводительная служба для сбора, обработки и пересылки системных журналов. В современных Linux-системах её основная роль — получать логи от `systemd-journald`, фильтровать их и перенаправлять в различные места назначения, такие как текстовые файлы в `/var/log` или удаленные серверы.

`rsyslog` является ключевым компонентом для построения систем **централизованного логирования**.

## Базовые концепции

### Архитектура и модули

- **Модули ввода (Input Modules, `im`):** Отвечают за сбор логов (например, `imjournal` для `systemd-journald`, `imudp` для приема по UDP).
- **Модули вывода (Output Modules, `om`):** Отвечают за отправку логов (например, `omfile` для записи в файл, `omfwd` для пересылки на другой сервер).
- **Модули фильтрации (Filter Modules, `fm`):** Используются для фильтрации сообщений.
- **Модули парсинга (Parsing Modules, `pm`):** Предоставляют возможности для синтаксического анализа сообщений.

### Конфигурация и фильтрация

Правила сортировки логов описываются в `/etc/rsyslog.conf` и файлах в `/etc/rsyslog.d/`.

**Структура правила:** `источник.приоритет   действие`

- **Источник (Facility):** Категория сообщения (`auth`, `cron`, `kern`, `mail`, `local0-7`). Кастомные facility `local0-local7` используются для приложений, не подпадающих под стандартные категории (свои скрипты, сторонние программы).
- **Приоритет (Severity):** Уровень важности (`info`, `warning`, `err`, `crit`). Звездочка `*` означает любой уровень.
- **Действие (Action):** Куда отправить лог (путь к файлу, `@` для UDP-пересылки, `@@` для TCP).

**Примеры правил:**

```conf
# Все сообщения, связанные с аутентификацией, писать в /var/log/auth.log
auth,authpriv.*         /var/log/auth.log

# Все сообщения, кроме почтовых, писать в /var/log/syslog
# Знак минус перед путем означает асинхронную запись (буферизация в памяти) для повышения производительности
# Минус предотвращает блокировку при каждой записи, накапливая данные в буфере и записывая на диск пачками
mail.none;*.*           -/var/log/syslog
```

## Практические сценарии

### Настройка удаленного логирования (Centralized Logging)

#### Настройка сервера (получателя логов)

1. **Включите прием логов.** В `/etc/rsyslog.d/50-remote.conf` добавьте:

    ```conf
    # Включаем прием логов по TCP
    module(load="imtcp")
    input(type="imtcp" port="514")
    ```

2. **Создайте шаблон для сохранения.** Чтобы логи с разных хостов не смешивались, используется шаблон, который создает отдельные файлы для каждого хоста.

    ```conf
    # Создаем шаблон: /var/log/remote/HOSTNAME/PROGRAM.log
    template(name="RemoteHostLog" type="string"
             string="/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log")

    # Применяем шаблон ко всем входящим сообщениям
    *.* action(type="omfile" dynaFile="RemoteHostLog")
    ```

3. **Перезапустите rsyslog и откройте порт в брандмауэре.**

    ```bash
    sudo systemctl restart rsyslog
    sudo firewall-cmd --add-port=514/tcp --permanent && sudo firewall-cmd --reload
    ```

#### Настройка клиента (отправителя логов)

Чтобы отправить все логи на удаленный сервер, добавьте строку в `/etc/rsyslog.d/99-forward.conf`, заменив `remote-log-server` на IP вашего сервера.

```conf
# Отправка по TCP (надежно, с подтверждением доставки)
*.* @@remote-log-server:514
```

После этого перезапустите `rsyslog`: `sudo systemctl restart rsyslog`.

### Интеграция с `systemd-journald`

В современных системах `rsyslog` забирает логи из `journald` для дальнейшей обработки. Для этого используется модуль `imjournal`.

1. **Убедитесь, что модуль загружается.** В `/etc/rsyslog.conf` должна быть строка:

    ```conf
    # Загружаем модуль для чтения из journald
    module(load="imjournal")
    ```

2. **Перезапустите `rsyslog`**: `sudo systemctl restart rsyslog`.

Теперь `rsyslog` будет получать все сообщения из `journald` и обрабатывать их согласно своим правилам, включая отправку на удаленный сервер.

## Дополнительная информация

### Сжатие логов в реальном времени с `omprog`

Для серверов с интенсивным логированием можно настроить сжатие "на лету" с помощью модуля `omprog`, который передает логи внешней программе (например, `gzip`).

1. **Загрузите модуль** `omprog` в `rsyslog.conf`:

    ```
    module(load="omprog")
    ```

2. **Создайте скрипт-обработчик**, например, `/usr/local/bin/compress_logs.sh`:

    ```bash
    #!/bin/bash
    while read line; do
      echo "$line" | gzip >> /var/log/compressed_logs.gz
    done
    ```

    Сделайте его исполняемым: `sudo chmod +x /usr/local/bin/compress_logs.sh`.

3. **Направьте логи в скрипт**, добавив правило в `.conf` файл в `/etc/rsyslog.d/`:

    ```
    # Направляем все логи в скрипт сжатия
    *.* action(type="omprog" binary="/usr/local/bin/compress_logs.sh")
    ```

Это позволяет значительно экономить место на диске, но требует настройки ротации для сжатых файлов.
