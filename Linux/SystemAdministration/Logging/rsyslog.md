# rsyslog: Традиционная система логирования

`rsyslog` — это мощная и гибкая служба для сбора и обработки логов. Она может читать сообщения из различных источников (файлы, сокеты, ядро) и направлять их в файлы или на удаленный сервер.

Долгое время `rsyslog` был стандартом де-факто в большинстве дистрибутивов Linux.

## Архитектура и модули

`rsyslog` имеет модульную архитектуру, что позволяет ему быть очень гибким. Существуют четыре основных типа модулей:

-   **Модули ввода (Input Modules, `im`):** Отвечают за сбор информации из различных источников. Начинаются с префикса `im` (например, `imudp` для UDP, `imtcp` для TCP, `imuxsock` для Unix-сокетов, `imjournal` для `systemd-journald`).
-   **Модули вывода (Output Modules, `om`):** Отвечают за отправку логов в различные места назначения (файлы, удаленные серверы, базы данных). Начинаются с префикса `om` (например, `omfile` для файлов, `omfwd` для пересылки).
-   **Модули фильтрации (Filter Modules, `fm`):** Используются для фильтрации сообщений по различным параметрам.
-   **Модули парсинга (Parsing Modules, `pm`):** Предоставляют дополнительные возможности для синтаксического анализа сообщений.

## Конфигурация (`/etc/rsyslog.conf`)

Правила сортировки логов описываются в `/etc/rsyslog.conf` и файлах в `/etc/rsyslog.d/`.

**Структура правила:** `источник.приоритет действие`

-   **Источник (Facility):** Категория сообщения (`auth`, `cron`, `kern`, `mail`, `local0-7`).
-   **Приоритет (Severity):** Уровень важности (`debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`). Звездочка `*` означает любой уровень.
-   **Действие (Action):** Куда отправить лог (путь к файлу, `@` или `@@` для удаленного хоста).

**Пример правил:**
```conf
# Все сообщения, связанные с аутентификацией, писать в /var/log/auth.log
auth,authpriv.*         /var/log/auth.log

# Все сообщения, кроме auth, cron и mail, писать в /var/log/syslog
*.*;auth,authpriv.none;cron.none;mail.none -/var/log/syslog
```
*Знак `-` перед путем к файлу (например, `-` `/var/log/syslog`) означает **асинхронную запись**. Это повышает производительность, так как `rsyslog` не ждет сброса данных на диск после каждой записи. Однако это несет риск потери последних сообщений при внезапном сбое системы.*

## Настройка удаленного логирования (Centralized Logging)

`rsyslog` позволяет настроить централизованный сбор логов с нескольких машин на один сервер.

#### Настройка сервера (получателя логов)

1.  **Включите прием логов.** В файле `/etc/rsyslog.conf` или в новом файле `/etc/rsyslog.d/50-remote.conf` раскомментируйте или добавьте:
    ```conf
    # Включаем прием логов по UDP
    module(load="imudp")
    input(type="imudp" port="514")

    # Включаем прием логов по TCP
    module(load="imtcp")
    input(type="imtcp" port="514")
    ```
2.  **Создайте шаблон для сохранения.** Чтобы логи с разных хостов не смешивались, используется шаблон, который создает отдельные файлы для каждого хоста.
    ```conf
    # Создаем шаблон: /var/log/remote/HOSTNAME/PROGRAM.log
    template(name="RemoteHostLog" type="string"
             string="/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log")

    # Применяем шаблон ко всем входящим сообщениям
    *.* action(type="omfile" dynaFile="RemoteHostLog")
    ```
3.  **Перезапустите rsyslog и откройте порт в брандмауэре.**
    ```bash
    sudo systemctl restart rsyslog
    # Пример для firewalld
    sudo firewall-cmd --add-port=514/tcp --permanent
    sudo firewall-cmd --add-port=514/udp --permanent
    sudo firewall-cmd --reload
    ```

#### Настройка клиента (отправителя логов)

1.  **Настройте пересылку.** В `/etc/rsyslog.d/50-remote-client.conf` добавьте правило, заменяя `remote-log-server` на IP вашего сервера.
    ```conf
    # Для TCP (надежно, с подтверждением доставки)
    *.* @@remote-log-server:514

    # Для UDP (быстро, но без гарантии доставки)
    # *.* @remote-log-server:514
    ```
    - `@@` указывает на использование протокола TCP.
    - `@` указывает на использование протокола UDP.

2.  **Перезапустите rsyslog.**
    ```bash
    sudo systemctl restart rsyslog
    ```

## Интеграция с `systemd-journald`

В современных системах `rsyslog` часто работает совместно с `systemd-journald`, забирая из него логи для дальнейшей пересылки или обработки. Для этого используется модуль `imjournal`.

1.  **Настройка `rsyslog`:**
    Убедитесь, что в `/etc/rsyslog.conf` или в `/etc/rsyslog.d/` загружается модуль `imjournal`.
    ```conf
    # Загружаем модуль для чтения из journald
    module(load="imjournal")
    ```
2.  **Перезапустите `rsyslog`:**
    ```bash
    sudo systemctl restart rsyslog
    ```

Теперь `rsyslog` будет получать все сообщения из `journald` и обрабатывать их согласно своим правилам, включая отправку на удаленный сервер. Это позволяет сочетать преимущества структурированного локального хранения `journald` с мощными возможностями `rsyslog` по фильтрации и пересылке.
