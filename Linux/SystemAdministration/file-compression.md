# Утилиты сжатия файлов в Linux (gzip, bzip2, xz, zstd)

## Определения

- **Сжатие (Compression):** Процесс уменьшения объема данных путем перекодирования информации с использованием алгоритмов Eliminating redundancy. В Linux применяется для экономии дискового пространства и ускорения передачи данных по сети.
- **Архиватор (Archiver):** Утилита, объединяющая несколько файлов в единый контейнер (например, `tar`). Архивирование не подразумевает сжатие, но часто используется совместно с компрессорами.
- **Компрессор (Compressor):** Утилита, уменьшающая объем одного файла. В Linux классическими примерами являются `gzip`, `bzip2`, `xz` и современный `zstd` (Zstandard).
- **Zstandard (zstd):** Современный алгоритм сжатия с открытым исходным кодом, разработанный Facebook. Обеспечивает высокую скорость сжатия и декомпрессии при сопоставимой с `xz` степени сжатия. Часто используется в ядре Linux, Docker, GitLab и других инструментах.
- **Степень сжатия (Compression ratio):** Отношение размера сжатого файла к исходному. Чем ниже значение, тем лучше сжатие.
- **Потоковое сжатие (Streaming compression):** Режим, при котором утилита читает данные из stdin и пишет результат в stdout, что позволяет использовать компрессоры в конвейерах (pipes).

## Базовые концепции

### Принцип работы компрессоров

Все классические утилиты сжатия в Linux реализуют **потоковый режим** и по умолчанию **удаляют исходный файл** после успешного сжатия. Это поведение следует учитывать при работе в production-средах.

Алгоритмическая разница между `gzip` и `bzip2`:

1. **gzip (LZ77 + Huffman coding):**
   - Использует алгоритм DEFLATE (словарный метод LZ77 + кодирование Хаффмана).
   - Высокая скорость сжатия и декомпрессии.
   - Низкая нагрузка на CPU.
   - Коэффициент сжатия: ~2:1 до 3:1 для текстовых данных.

2. **bzip2 (Burrows-Wheeler Transform + Move-to-Front + Huffman coding):**
   - Использует преобразование Барроуза-Уиллера (BWT) для переупорядочивания символов перед кодированием.
   - Более высокий коэффициент сжатия, чем у gzip.
   - Заметно медленнее и требовательнее к CPU.
   - Коэффициент сжатия: ~3:1 до 4:1 для текстовых данных.

 3. **xz (LZMA2):**
    - Использует алгоритм LZMA2 (словарь + вероятностное кодирование).
    - Наивысший коэффициент сжатия среди трех.
    - Самая низкая скорость сжатия и декомпрессии.
     - Требует значительно больше оперативной памяти.

 4. **zstd (Zstandard):**
    - Современный алгоритм с открытым исходным кодом (Facebook/Meta).
    - Высокая скорость сжатия и распаковки при степени сжатия, сопоставимой с `xz`.
    - Низкое потребление CPU, поддерживает многопоточность (`-T0`).
    - Часто используется в ядре Linux, Docker, GitLab Runner и высоконагруженных системах.

### Утилита tar (Tape Archive)

Утилита `tar` (Tape ARchive — «ленточный архив») появилась в ранних версиях Unix для работы с магнитными лентами — основным носителем резервного копирования в 1970–1980-е годы. Её исходная задача заключалась не в сжатии, а в **объединении множества мелких файлов из разных директорий в один непрерывный монолитный поток байтов** (так называемый «тарбол»), удобный для последовательной записи на ленту.

В Unix строго соблюдается принцип разделения ответственности: **одна утилита выполняет одну задачу, но идеально**. Поэтому `tar` никогда не включала встроенное сжатие — за это отвечают отдельные компрессоры (`gzip`, `bzip2`, `xz`, `zstd`). При создании архива `tar` только копирует исходные файлы в единый контейнер, не изменяя их размер; оригиналы на диске остаются нетронутыми.

> **Ключевое отличие от Windows-архиваторов (ZIP/RAR):** В Windows сжатие и упаковка обычно объединены в одном инструменте. В Linux эти функции разделены: `tar` только упаковывает, компрессор только сжимает.

Это разделение позволяет комбинировать любые компрессоры с `tar` и использовать их в конвейерах (pipes).

#### Базовый синтаксис создания архива: флаг `-cvf`

Классическая комбинация для создания несжатого tar-архива — `-cvf`. Понимание каждого флага и порядка их указания критически важно, так как неправильный синтаксис является частой причиной ошибок на экзаменах LPIC-1 и в production.

**Расшифровка флагов:**

- **`-c`** (create) — команда создать новый архив. Этот флаг приказывает утилите, что мы хотим именно упаковать файлы в новый контейнер, а не распаковать существующий.
- **`-v`** (verbose) — «красноречивый» режим. Утилита выводит в stdout список всех файлов, которые упаковывает в данный момент. Полезно для визуального контроля прогресса и отладки.
- **`-f`** (file) — указывает, что результат нужно записать именно в файл на диске, а не отправить на ленточный накопитель (устройство, для которого изначально создавался `tar`).

**Железное правило порядка флагов:** флаг `-f` должен стоять **самым последним** в цепочке, прямо перед именем будущего архива. Если поместить имя файла не на последнее место, `tar` интерпретирует его как дополнительный источник для архивации, что приводит к ошибке или неожиданному результату.

```bash
# Правильно: флаг -f последний, сразу перед именем архива
tar -cvf project.tar /path/to/directory

# Неправильно: имя архива не после -f
tar -cv /path/to/directory project.tar
```

**Старый стиль Unix (POSIX-совместимый):** флаги можно указывать без дефисов. Утилита `tar` поддерживает оба варианта; на экзаменах LPIC-1 оба стиля могут встречаться:

```bash
# Современный стиль (с дефисом)
tar -cvf project.tar myproject

# Старый стиль Unix (без дефиса)
tar cvf project.tar myproject
```

Практический пример создания первого архива:

```bash
# Создание архива текущей директории
mkdir -p /tmp/myproject && cd /tmp/myproject
touch file1.txt file2.txt
tar -cvf project.tar .
# → на экране отображаются упаковываемые файлы (работа флага -v)
# → в директории появляется файл project.tar
```

### Расширения файлов

| Утилита | Расширение сжатого файла | Команда распаковки |
| :--- | :--- | :--- |
| **gzip** | `.gz` | `gunzip` |
| **bzip2** | `.bz2` | `bunzip2` |
| **xz** | `.xz` | `unxz` |
| **zstd** | `.zst` | `unzstd` |
| **zip** | `.zip` | `unzip` (отдельный формат, не путать с gzip) |
| **tar** | `.tar` | `tar -xf` (архиватор без сжатия) |

### Важное замечание

- **`.tar`** — это **архиватор без сжатия**. Он только объединяет файлы в единый поток.
- **`.gz`** — результат работы **gzip**.
- **`.zst`** — результат работы **zstd** (Zstandard).
- **`.zip`** — формат архиватора **zip** (PKZIP), который объединяет архивацию и сжатие в одном формате. Отличается от gzip/bzip2.
- **`.tar.gz`** или **`.tgz`** — контейнер tar, сжатый gzip.
- **`.tar.bz2`** или **`.tbz2`** — контейнер tar, сжатый bzip2.
- **`.tar.xz`** — контейнер tar, сжатый xz.
- **`.tar.zst`** — контейнер tar, сжатый zstd.

## Практические сценарии

### 1. Базовое сжатие и распаковка

По умолчанию все компрессоры удаляют исходный файл. Для сохранения оригинала используйте флаг `-k` (gzip 1.6+, bzip2) или перенаправление в `cat`.

```bash
# Сжатие с удалением оригинала (поведение по умолчанию)
gzip file.txt
bzip2 file.txt
xz file.txt

# Сжатие с сохранением оригинала
gzip -k file.txt
bzip2 -k file.txt
xz -k file.txt

# Распаковка (восстанавливает исходный файл)
gunzip file.txt.gz
bunzip2 file.txt.bz2
unxz file.txt.xz
```

### 2. Потоковое сжатие через pipe

При перенаправлении в pipe исходный файл не удаляется:

```bash
# Сжатие в pipe (исходный файл сохраняется)
gzip -c file.txt > file.txt.gz
bzip2 -c file.txt > file.txt.bz2
xz -c file.txt > file.txt.xz

# Использование в конвейерах
tar -cf - /var/log | gzip > logs.tar.gz
dd if=/dev/sda status=progress | gzip -c > sda_image.gz
```

### 3. Интеграция с tar

Для создания сжатых архивов используется флаг `-z` (gzip), `-j` (bzip2), `-J` (xz) или `--zstd` / `-a` (автоподбор по расширению):

```bash
# tar + gzip
tar -czvf archive.tar.gz /path/to/directory

# tar + bzip2
tar -cjvf archive.tar.bz2 /path/to/directory

# tar + xz
tar -cJvf archive.tar.xz /path/to/directory

# tar + zstd
tar --zstd -cf archive.tar.zst /path/to/directory

# Автоматический выбор по расширению (GNU tar)
tar -caf archive.tar.zst /path/to/directory

# Распаковка (tar определяет формат автоматически)
tar -xvf archive.tar.gz
tar -xvf archive.tar.bz2
tar -xvf archive.tar.xz
tar -xvf archive.tar.zst
```

### 3.5. ZIP — кроссплатформенный архиватор

Утилита `zip` объединяет упаковку и сжатие в одном формате, в отличие от Linux-подхода `tar` + отдельный компрессор. Это делает ZIP стандартом для обмена архивами с системами Windows, где нативные tar-архивы не поддерживаются без дополнительного ПО.

```bash
# Создание рекурсивного ZIP-архива (флаг -r обязателен)
zip -r project.zip myproject

# Распаковка
unzip project.zip

# Просмотр содержимого без распаковки
unzip -l project.zip
```

**Ключевые особенности:**
- Флаг `-r` (recursive) обязателен при архивации директорий; без него `zip` упакует только пустую папку.
- ZIP сохраняет права доступа и временные метки, но не поддерживает все атрибуты Unix (например, жесткие ссылки и расширенные ACL).
- Для распаковки используется `unzip`, для просмотра содержимого — `unzip -l`.

> **Экзаменационная ловушка:** На тестах LPIC-1 часто проверяют знание того, что ZIP — это самодостаточный формат, не требующий отдельного компрессора. Обратное верно для `tar`: он только упаковывает, а сжатие требует отдельного флага (`-z`, `-j`, `-J`).

### 3.6. 7-Zip в Linux

7-Zip также доступен в Linux. В зависимости от дистрибутива команда может называться `7z` или `7za`:

```bash
# Создание архива
7z a archive.7z directory/

# Распаковка
7z x archive.7z

# Просмотр содержимого
7z l archive.7z
```

7z интересен высокой степенью сжатия и дополнительными возможностями (например, создание зашифрованных архивов). Важно помнить, что сжатие и шифрование — разные задачи: обычный `.tar.gz` не становится защищённым только потому, что данные находятся внутри архива.

### 3.6. Просмотр содержимого архива и безопасная распаковка

Перед распаковкой большого архива проверьте его состав, чтобы избежать случайного перезаписывания файлов.

#### Просмотр без распаковки

```bash
# tar (флаг -t = list)
tar -tvf archive.tar.gz
# → -rw-r--r-- user/group   1234 2024-01-01 12:00 file.txt

# ZIP
unzip -l archive.zip

# 7-Zip
7z l archive.7z
```

#### Безопасная распаковка

По умолчанию `tar` распаковывает файлы в **текущую рабочую директорию**. Неизвестный архив лучше не распаковывать сразу в `/` или рабочую директорию проекта:

```bash
# Создайте отдельный каталог
mkdir -p /tmp/restore && cd /tmp/restore

# Извлеките архив
tar -xvf ../archive.tar.gz
```

Для извлечения в конкретную папку используйте заглавный флаг `-C` (change directory):

```bash
# Распаковка в /tmp/restore
tar -xvf archive.tar -C /tmp/restore
```

### 3.7. Разделение большого архива на части

Если архив размером несколько гигабайт нужно передать частями, используйте утилиту `split`:

```bash
# Разделить архив на части по 1 ГБ
split -b 1G backup.tar.zst backup.part-

# Получим файлы: backup.part-aa, backup.part-ab, ...

# Собрать обратно
cat backup.part-* > backup.tar.zst
```

### 4. Управление уровнем сжатия

Для gzip доступны уровни сжатия от 1 до 9 (по умолчанию — 6):

```bash
# Быстрое сжатие (уровень 1) — для низкоуровневых задач
gzip -1 file.txt

# Максимальное сжатие (уровень 9) — для холодного хранения
gzip -9 file.txt

# Баланс скорости и размера (уровень 6, по умолчанию)
gzip -6 file.txt

# Проверка сжатия без изменения файла
gzip -l file.txt.gz
```

Для bzip2 уровни сжатия от 1 до 9 (по умолчанию — 9):

```bash
# Быстрое сжатие
bzip2 -1 file.txt

# Максимальное сжатие (по умолчанию)
bzip2 -9 file.txt

# Анализ результата
bzip2 -t file.txt.bz2  # Проверка целостности
bzip2 -d -k file.txt.bz2  # Распаковка с сохранением оригинала
```

Для xz доступны уровни от 0 до 9, а также preset (preset=0..9e):

```bash
# Быстрое сжатие с низким использованием памяти
xz -0 file.txt

# Максимальное сжатие (по умолчанию preset=6)
xz -9 file.txt

# Экстремальное сжатие (большое потребление RAM)
xz -9e file.txt
```

Для zstd доступны уровни от 1 до 22 (по умолчанию — 3), а также специальные пресеты:

```bash
# Быстрое сжатие (уровень 1)
zstd -1 file.txt

# Баланс скорости и размера (по умолчанию)
zstd -3 file.txt

# Максимальное сжатие
zstd -19 file.txt

# Многопоточное сжатие (все ядра CPU)
zstd -T0 -3 file.txt

# Автоматический выбор по расширению в tar
tar -caf archive.tar.zst directory/
```

### 5. Параллельное сжатие

Для многоядерных систем используйте утилиты, поддерживающие параллелизм:

```bash
# pigz (parallel gzip) — заменяет gzip, использует все ядра CPU
pigz -p 4 file.txt

# pbzip2 (parallel bzip2) — параллельная версия bzip2
pbzip2 -p 4 file.txt

# pxz (parallel xz) — параллельная версия xz
pxz -p 4 file.txt

# zstd с встроенной многопоточностью
zstd -T0 -3 file.txt
```

### 6. Сжатие на лету при бэкапах

```bash
# Бэкап директории с максимальным сжатием xz
tar -cJf /backup/home_$(date +%F).tar.xz /home

# Бэкап с балансом скорости и размера (zstd)
tar --zstd -cf /backup/home_$(date +%F).tar.zst /home

# Потоковый бэкап PostgreSQL через gzip
pg_dump -U postgres mydb | gzip > mydb_$(date +%F).sql.gz

# Образ диска через bzip2 (лучшее сжатие, медленнее)
sudo dd if=/dev/sda status=progress | bzip2 -c > sda_image.bz2
```

### 7. Анализ и сравнение результатов

```bash
# Сравнение размеров
ls -lh file.txt file.txt.gz file.txt.bz2 file.txt.xz file.txt.zst

# Подробная статистика сжатия
gzip -l file.txt.gz
xz --list file.txt.xz
zstd -l file.txt.zst

# Оценка степени сжатия перед архивацией
echo "Тестовый текст для сжатия" | gzip | wc -c
echo "Тестовый текст для сжатия" | bzip2 | wc -c
echo "Тестовый текст для сжатия" | xz | wc -c
echo "Тестовый текст для сжатия" | zstd | wc -c
```

### 7. Бенчмарк форматов

На практике скорость и степень сжатия сильно зависят от типа данных. Ниже приведён примерный порядок для типичных файлов (текст, логи, образы):

| Формат | Сжатие | Распаковка | Размер | Примечание |
| :--- | :--- | :--- | :--- | :--- |
| **zstd** | ~0.25 c | ~0.04 c | ~18M | Лучший баланс для современных задач |
| gzip | ~1.00 c | ~0.17 c | ~25M | Универсальный, но уступает zstd |
| 7z | ~3.29 c | ~1.04 c | ~17M | Минимальный размер, медленное сжатие |
| xz | ~10.12 c | ~1.18 c | ~17M | Максимальное сжатие, очень медленный |

- Исходный файл: 28 MB (пример: видео MP4).
- zstd примерно **4× быстрее gzip** и **на порядок быстрее xz** при разнице в размере всего ~1 MB.

## Сравнение компрессоров

| Параметр | gzip | bzip2 | xz | zstd |
| :--- | :--- | :--- | :--- | :--- |
| **Алгоритм** | DEFLATE (LZ77 + Huffman) | BWT + Move-to-Front + Huffman | LZMA2 | Zstandard |
| **Степень сжатия** | Средняя | Высокая | **Наивысшая** | Высокая |
| **Скорость сжатия** | **Высокая** | Низкая | Очень низкая | **Экстремальная** |
| **Скорость декомпрессии** | **Высокая** | Средняя | Средняя/Низкая | **Наивысшая** |
| **Потребление RAM** | Низкое | Среднее | Высокое | Низкое/Среднее |
| **Совместимость** | Универсальная | Широкая | Ограниченная | Высокая (Linux 3.18+) |
| **Поддержка в tar** | `-z` | `-j` | `-J` | `--zstd` / `-a` |
| **Параллельные версии** | pigz | pbzip2 | pxz | Встроено (`-T0`) |

### Выбор компрессора

- **gzip:** Бэкапы, где важна скорость восстановления; передача по сети; широкие системы (почта, HTTP).
- **bzip2:** Архивирование данных для холодного хранения, где важен размер, но ресурсы CPU ограничены.
- **xz:** Максимальное сжатие для архивов, хранящихся длительное время; пакеты в дистрибутивах Linux (RPM, PKG).
- **zstd:** Современный выбор для бэкапов, логов, Docker-образов и high-load систем, где нужен баланс скорости и размера.
- **7z:** Когда требуется максимальное сжатие с дополнительными возможностями (шифрование, многотомность) и не критична скорость.

## Типичные ошибки и диагностика

### Ошибка: случайное удаление исходного файла

По умолчанию `gzip`, `bzip2`, `xz` и `zstd` удаляют исходный файл после сжатия.

```bash
# Проверка наличия флага сохранения
gzip --help | grep -i "keep"
bzip2 --help | grep -i "stdout"
xz --help | grep -i "stdout"
zstd --help | grep -i "keep"
```

### Ошибка: поврежденный архив

```bash
# Проверка целостности gzip-архива
gzip -t file.tar.gz && echo "OK" || echo "CORRUPTED"

# Проверка bzip2-архива
bzip2 -t file.tar.bz2 && echo "OK" || echo "CORRUPTED"

# Проверка xz-архива
xz -t file.tar.xz && echo "OK" || echo "CORRUPTED"

# Проверка zstd-архива
zstd -t file.tar.zst && echo "OK" || echo "CORRUPTED"
```

### Ошибка: недостаток памяти при работе с xz

xz требует значительного объема RAM (до 40–80% от размера несжатых данных). При нехватке памяти используйте `xz -T 1` (однопоточный режим) или снизьте preset.

```bash
# Ограничение числа потоков и памяти
xz -T 2 --memlimit-compress=50% file.txt
```

### Ошибка: неверный флаг tar

```bash
# Неправильно: tar использует внутренний gzip, но флаг -j (bzip2) указан
tar -cjvf archive.tar.gz /data  # Создаст битый архив

# Правильно: флаг соответствует алгоритму сжатия
tar -czvf archive.tar.gz /data   # gzip
tar -cjvf archive.tar.bz2 /data  # bzip2
tar -cJvf archive.tar.xz /data   # xz
tar --zstd -cf archive.tar.zst /data  # zstd
```

> **Экзаменационная ловушка — регистр букв:** флаги компрессии `tar` отличаются **только регистром символа**, поэтому на экзаменах (LPIC-1, тема 103.3) проверяют именно это:
> - `-z` (маленькая) — **gzip** (DEFLATE);
> - `-j` (маленькая) — **bzip2** (BWT);
> - **`-J` (большая) — xz** (LZMA2).
> - `--zstd` или `-a` — **zstd** (Zstandard).
>
> Перепутав `j` и `J`, вы создаёте поток одного компрессора внутри архива другого, и `tar` больше не сможет его прочитать (`gzip: stdin: not in gzip format`). Запомните простое правило: **`z`-gzip, `j`-bzip2, `J`-xz** (заглавная `J` — самая современная утилита).
>
> Дополнительная подводная камень в тестах — путаница `-c` (create, создание) и `-C` (change directory, смена каталога). При распаковке флаг компрессии **не нужен**: `tar` определяет алгоритм по содержимому и распаковывает одинаково `tar -xvf archive.tar.gz`, `tar -xvf archive.tar.bz2`, `tar -xvf archive.tar.xz` и `tar -xvf archive.tar.zst`.

### Ошибка: использование `-c` вместо `-C` при распаковке

При распаковке флаг `-c` (create) создаёт **новый пустой архив** вместо извлечения:

```bash
# Неправильно: создаст пустой архив вместо распаковки
tar -cvf archive.tar /data

# Правильно: извлечение
tar -xvf archive.tar
```

### Экзаменационные сценарии (LPIC-1, тема 103.3)

На экзамене LPIC-1 часто встречаются вопросы на распознавание правильного флага `tar` и поведение компрессоров. Типичный сценарий: дана задача (просмотр содержимого, извлечение, создание архива) и четыре варианта ответа с разными комбинациями флагов.

**Логика разбора типового вопроса:**

| Действие | Правильный флаг | Почему другие варианты неверны |
| :--- | :--- | :--- |
| Просмотр содержимого без распаковки | `-t` (table/list) | `-x` извлечёт файлы на диск; `-c` создаст новый пустой архив, уничтожив старый; `cat` выведет бинарный мусор в терминал |
| Создание архива | `-c` (create) | Без `-c` `tar` не создаст архив; `-x` попытается распаковать несуществующий файл |
| Извлечение файлов | `-x` (extract) | `-c` создаст пустой архив поверх существующего; без `-x` архив не распакуется |

> **Экзаменационная ловушка — «эгоистичные» компрессоры:** standalone-утилиты `gzip`, `bzip2`, `xz` и `zstd` по умолчанию работают эгоистично: они сжимают данные и создают архив, но при этом **полностью стирают исходный файл** с диска. Чтобы сохранить оригинал, необходимо использовать обёртки (например, `tar`), которые упаковывают файлы в контейнер, не удаляя исходники, или применять флаг `-k` (gzip 1.6+, bzip2) для сохранения оригинала при прямом сжатии.

> **Исторический контекст:** Утилита `tar` (Tape ARchive) появилась в Unix для работы с магнитными лентами — основным носителем резервного копирования в 1970–1980-е годы. Её задача — объединить множество файлов в один непрерывный поток, удобный для последовательной записи. Сжатие было выделено в отдельные компрессоры (`gzip`, `bzip2`, `xz`, `zstd`) в соответствии с философией Unix: одна утилита — одна задача, но идеально.

## Какие команды стоит запомнить

```bash
# Создать tar
tar -cf archive.tar directory/

# Создать tar.gz
tar -czf archive.tar.gz directory/

# Создать tar.xz
tar -cJf archive.tar.xz directory/

# Создать tar.zst
tar --zstd -cf archive.tar.zst directory/

# Автоматически выбрать алгоритм по расширению
tar -caf archive.tar.zst directory/

# Посмотреть содержимое
tar -tvf archive.tar.gz

# Распаковать
tar -xvf archive.tar.gz

# Создать ZIP
zip -r archive.zip directory/

# Распаковать ZIP
unzip archive.zip

# Создать 7z
7z a archive.7z directory/

# Распаковать 7z
7z x archive.7z
```

## Что в итоге выбрать

| Задача | Рекомендуемый формат |
| :--- | :--- |
| Максимальная совместимость в Linux | `.tar.gz` |
| Минимальный размер | `.tar.xz` или `.7z` |
| Высокая скорость и хороший размер | `.tar.zst` |
| Обмен с Windows/macOS | `.zip` |
| Шифрование + сжатие | `.7z` |
