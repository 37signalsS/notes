# Удаленный доступ к серверам

## 1. Стандартный доступ: SSH (Secure Shell)

SSH — это основной протокол для безопасного удаленного управления серверами. Подробное описание протокола, его настройка и рекомендации по безопасности находятся в документе [SSH (Secure Shell)](../../Linux/Security/ssh.md). Однако, если сервер перестает отвечать на SSH, необходимо использовать методы внеполосного управления.

## 2. Внеполосное управление (Out-of-Band Management, OOB)

Это набор технологий для доступа к серверу на аппаратном уровне, независимо от состояния операционной системы. Это ваш главный инструмент, если сервер "завис", не загружается, потерял сетевое соединение или не отвечает по SSH.

**Сервер не отвечает, как можно получить доступ, не находясь в ЦОДе?**  

Через IPMI или KVM over IP, если они есть на сервере. В противном случае — звонить дежурному инженеру ЦОДа.

### Платы управления: IPMI и его реализации

**IPMI (Intelligent Platform Management Interface)** – это стандарт интерфейса для удаленного мониторинга и управления физическим состоянием сервера.

Центральным элементом является **модуль управления (Baseboard Management Controller, BMC)**, который, по сути, представляет собой отдельный компьютер со своим ПО и сетевым интерфейсом, встроенным в материнскую плату.

**Основные проприетарные реализации BMC:**
*   **Dell:** **iDRAC** (integrated Dell Remote Access Controller)
*   **HP:** **iLO** (Integrated Lights-Out)
*   **Lenovo/IBM:** **IMM** (Integrated Management Module)
*   **Supermicro:** **IPMI** (использует стандартную спецификацию)
*   **Cisco:** **CIMC** (Cisco Integrated Management Controller)

**Ключевые возможности:**
*   **Удаленная консоль и доступ к BIOS:** Полный доступ к экрану, клавиатуре и мыши, возможность изменять настройки BIOS/UEFI.
*   **Управление питанием:** Принудительная перезагрузка (`Hard Reset`), включение/выключение сервера.
*   **Мониторинг состояния:** Отслеживание температурных датчиков, напряжения, состояния блоков питания, скорости вращения вентиляторов.
*   **Виртуальные носители (Virtual Media):** Удаленное подключение `.iso` образов для установки или восстановления ОС.

**Архитектура IPMI:**
BMC контроллеры подключаются через интерфейс **IPMB (Intelligent Platform Management Bus)** — это шина на основе I2C, по которой BMC перенаправляет команды к различным компонентам:
- Другим контроллерам (MCs)
- Сенсорам (Sensors)
- Энергонезависимому хранилищу (Non-Volatile Storage)

Такая архитектура обеспечивает изоляцию: администратор посылает команду на BMC, а уже BMC обращается к компонентам системы.

Подробнее о технологии можно почитать [в обзоре Selectel](https://selectel.ru/blog/ipmi-obzor-texnologii/).

### KVM-over-IP (IP-KVM)

**KVM over IP** (где KVM: **K**eyboard, **V**ideo, **M**ouse) — это, как правило, внешнее устройство, позволяющее передавать видеосигнал и ввод с мыши/клавиатуры по сети с использованием IP-протокола.

**Использование:**
При помощи KVM вы можете перезагрузить сервер, получить доступ в BIOS и к другим функциям, которые невозможно выполнить через терминал. Он полностью обособлен от операционной системы. Часто используется как последнее средство для серверов, не имеющих встроенного BMC, или когда доступ к IPMI по какой-то причине невозможен.

### Сравнение IPMI и KVM-over-IP

| Возможность | IPMI / BMC | Внешний KVM-over-IP |
| :--- | :---: | :---: |
| **Удаленная консоль (KVM)** | ✅ | ✅ |
| **Управление питанием** | ✅ | ❌ |
| **Монтирование образов (.iso)** | ✅ | ❌ |
| **Мониторинг датчиков** | ✅ | ❌ |
| **Тип решения** | Встроенное | Внешнее |

**Ключевое различие:** Традиционные внешние IP-KVM устройства предоставляют только базовый доступ к консоли. В то же время IPMI и его аналоги (iDRAC, iLO) — это комплексная система управления сервером на аппаратном уровне. Некоторые провайдеры могут предоставлять доступ к IP-KVM по запросу и на время, в отличие от постоянного доступа к IPMI.

### Последовательный консольный сервер (Serial Console Server)

Устройство, к которому через последовательные порты (COM) подключаются серверы или сетевое оборудование. Администратор подключается по SSH к консольному серверу, а с него получает доступ к текстовой консоли нужного устройства.

## 3. Графический удаленный доступ (In-Band)

В отличие от внеполосного управления, эти методы требуют работающей операционной системы и сетевого стека.

### VNC (Virtual Network Computing)

**VNC** — это программное обеспечение, которое представляет ваши «локальные» клавиатуру и мышь так, будто они напрямую подключены к любому другому удаленному серверу. Это позволяет легко и просто управлять файлами, ПО и настройками на удаленном сервере через графический интерфейс.

**Важно:** Протокол VNC сам по себе не является безопасным. Весь трафик передается в незашифрованном виде. Поэтому **всегда** используйте VNC в связке с SSH-туннелем.

#### Пример: Установка VNC-сервера (TigerVNC + XFCE) на Ubuntu

Эта инструкция показывает, как настроить легкий рабочий стол XFCE и получить к нему безопасный доступ через VNC, туннелированный через SSH.

**1. Установка графического окружения и VNC-сервера:**
```bash
# Обновляем пакеты
sudo apt update && sudo apt upgrade -y

# Устанавливаем легкую среду рабочего стола XFCE
sudo apt install xfce4 xfce4-goodies -y

# Устанавливаем TigerVNC
sudo apt install tigervnc-standalone-server -y
```

**2. Первоначальная настройка VNC:**
```bash
# Запустите vncserver, чтобы создать конфиг и задать пароль
vncserver
# Пароль должен быть от 6 до 8 символов.
# На вопрос о пароле "только для просмотра" (view-only) можно ответить 'n'.

# Остановите временный сеанс, который был запущен
vncserver -kill :1
```

**3. Настройка запуска XFCE:**
Отредактируйте файл `~/.vnc/xstartup`, чтобы VNC запускал XFCE.
```bash
# Сделайте резервную копию и создайте новый файл
mv ~/.vnc/xstartup ~/.vnc/xstartup.bak
nano ~/.vnc/xstartup
```
Добавьте в него следующее содержимое:
```bash
#!/bin/bash
xrdb $HOME/.Xresources
startxfce4 &
```
Сделайте файл исполняемым:
```bash
chmod +x ~/.vnc/xstartup
```

**4. Создание службы Systemd для автозапуска:**
Это позволит управлять VNC как стандартной службой. Создайте файл `/etc/systemd/system/vncserver@.service`:
```bash
sudo nano /etc/systemd/system/vncserver@.service
```
Вставьте в него следующий текст, **заменив `YOUR_USERNAME` на ваше имя пользователя**:
```ini
[Unit]
Description=Start TigerVNC server at startup
After=syslog.target network.target

[Service]
Type=forking
User=YOUR_USERNAME
Group=YOUR_USERNAME
WorkingDirectory=/home/YOUR_USERNAME

PIDFile=/home/YOUR_USERNAME/.vnc/%H:%i.pid
ExecStartPre=-/usr/bin/vncserver -kill :%i > /dev/null 2>&1
ExecStart=/usr/bin/vncserver -depth 24 -geometry 1280x800 -localhost :%i
ExecStop=/usr/bin/vncserver -kill :%i

[Install]
WantedBy=multi-user.target
```
-   Опция `-localhost` в `ExecStart` — ключевой элемент безопасности. Она заставляет VNC-сервер принимать подключения только с локальной машины (localhost), что делает невозможным прямое подключение извне и заставляет использовать SSH-туннель.

**5. Управление службой VNC:**
```bash
# Перезагрузить конфигурацию systemd
sudo systemctl daemon-reload

# Включить автозапуск службы для дисплея :1
sudo systemctl enable vncserver@1.service

# Запустить службу
sudo systemctl start vncserver@1.service

# Проверить статус
sudo systemctl status vncserver@1.service
```

**6. Подключение через SSH-туннель (безопасный способ):**
Никогда не открывайте порт VNC (5901) наружу. Вместо этого создайте SSH-туннель с вашего локального компьютера.

```bash
# ssh -L <локальный_порт>:localhost:<удаленный_порт> -N -f -l <user> <server_ip>
ssh -L 59001:localhost:5901 -N -f -l your_username your_server_ip
```
-   Эта команда перенаправляет порт `5901` с сервера на порт `59001` вашего локального компьютера.

Теперь откройте ваш VNC-клиент (например, TigerVNC Viewer, Remmina) и подключитесь к адресу `localhost:59001`. Вы увидите рабочий стол вашего удаленного сервера.
