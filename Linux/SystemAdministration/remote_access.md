# Удаленный доступ к серверам

## 1. Определения

**Удаленный доступ** — это совокупность методов и технологий для управления сервером на расстоянии. Доступ разделяется на два основных типа в зависимости от того, требуется ли для него работающая операционная система.

-   **Внутриполосное управление (In-Band Management)**: Доступ к серверу через его основную операционную систему и сетевой стек. Этот метод работает, только если ОС полностью загружена и функционирует нормально.
    -   **Примеры:** SSH, VNC, RDP.

-   **Внеполосное управление (Out-of-Band Management, OOB)**: Аппаратный доступ к серверу, независимый от состояния его операционной системы. Это основной инструмент для "оживления" зависшего, выключенного или недоступного по сети сервера.
    -   **Примеры:** IPMI (и его реализации iDRAC, iLO), IP-KVM, последовательные консоли.

-   **IPMI (Intelligent Platform Management Interface)**: Стандарт для встроенного в материнскую плату модуля управления (**Baseboard Management Controller, BMC**), который предоставляет OOB-доступ.
-   **IP-KVM (KVM-over-IP)**: Технология (часто в виде внешнего устройства), которая передает сигналы **K**eyboard, **V**ideo, **M**ouse по IP-сети. *Не следует путать с [KVM-виртуализацией](../../Linux/Virtualization/kvm_setup.md).*
-   **VNC (Virtual Network Computing)**: Протокол для графического удаленного доступа к рабочему столу (In-Band).

## 2. Базовые концепции

### Иерархия доступа

Администрирование сервера всегда следует принципу эскалации:

1.  **Попытка доступа по SSH:** Это стандартный, быстрый и безопасный способ управления.
2.  **Эскалация до OOB (IPMI/IP-KVM):** Если сервер не отвечает по SSH, не загружается или недоступен по сети, администратор переходит к внеполосному управлению.

### Возможности внеполосного управления (OOB)

Модули BMC (такие как Dell iDRAC, HP iLO, Supermicro IPMI) являются, по сути, отдельными компьютерами внутри сервера и предоставляют полный аппаратный контроль:

-   **Удаленная консоль:** Полный доступ к экрану, клавиатуре и мыши, как если бы вы физически находились у сервера. Позволяет заходить в BIOS/UEFI.
-   **Управление питанием:** Принудительное выключение, включение и перезагрузка (`Hard Reset`).
-   **Мониторинг состояния:** Отслеживание аппаратных датчиков (температура, напряжение, скорость вентиляторов).
-   **Виртуальные носители (Virtual Media):** Удаленное подключение `.iso` образов для установки или восстановления ОС.

### Аспекты безопасности

-   **Безопасность OOB:** Интерфейсы IPMI/iDRAC/iLO должны находиться в выделенной, изолированной сети управления. Предоставление доступа к ним из публичной сети является серьезной угрозой безопасности.
-   **Безопасность VNC:** Протокол VNC по умолчанию **не шифрует трафик**. Поэтому для безопасного использования VNC **всегда** должен туннелироваться через зашифрованное SSH-соединение.

## 3. Практические сценарии

### Сценарий 1: Стандартный доступ по SSH

Основной протокол для безопасного удаленного управления. Подробная информация о настройке и использовании находится в основной заметке: **[SSH (Secure Shell)](../../Linux/Security/ssh.md)**.

### Сценарий 2: Аварийный доступ через IPMI/iDRAC/iLO

Если сервер не отвечает, порядок действий следующий:

1.  Подключитесь к веб-интерфейсу или CLI модуля управления (например, iDRAC).
2.  Запустите удаленную консоль (Remote Console / Virtual KVM).
3.  Проанализируйте вывод на экране, чтобы понять причину сбоя (например, `Kernel Panic`).
4.  При необходимости выполните принудительную перезагрузку через интерфейс управления питанием.
5.  Если требуется переустановка ОС, подключите `.iso` образ через функцию `Virtual Media`.

### Сценарий 3: Настройка графического стола с помощью VNC и SSH-туннеля

Эта инструкция показывает, как настроить легкий рабочий стол XFCE на Ubuntu и получить к нему безопасный доступ.

**1. Установка окружения и VNC-сервера:**
```bash
# Обновляем пакеты и устанавливаем XFCE и TigerVNC
sudo apt update && sudo apt upgrade -y
sudo apt install xfce4 xfce4-goodies tigervnc-standalone-server -y
```

**2. Первоначальная настройка и запуск VNC:**
```bash
# Запустите vncserver, чтобы создать конфиг и задать пароль доступа (6-8 символов)
vncserver
# Остановите временный сеанс, он нам больше не нужен
vncserver -kill :1
```

**3. Конфигурация VNC для запуска XFCE:**
Создайте файл `~/.vnc/xstartup`, чтобы VNC запускал сеанс XFCE.
```bash
# Создаем исполняемый файл конфигурации
echo -e '#!/bin/bash\nxrdb $HOME/.Xresources\nstartxfce4 &' > ~/.vnc/xstartup
chmod +x ~/.vnc/xstartup
```

**4. Создание службы Systemd для автозапуска:**
Создайте файл `/etc/systemd/system/vncserver@.service`, **заменив `YOUR_USERNAME` на ваше имя пользователя**.
```bash
sudo tee /etc/systemd/system/vncserver@.service > /dev/null <<EOF
[Unit]
Description=Start TigerVNC server at startup
After=syslog.target network.target

[Service]
Type=forking
User=YOUR_USERNAME
Group=YOUR_USERNAME
WorkingDirectory=/home/YOUR_USERNAME

PIDFile=/home/YOUR_USERNAME/.vnc/%H:%i.pid
ExecStartPre=-/usr/bin/vncserver -kill :%i > /dev/null 2>&1
ExecStart=/usr/bin/vncserver -depth 24 -geometry 1280x800 -localhost :%i
ExecStop=/usr/bin/vncserver -kill :%i

[Install]
WantedBy=multi-user.target
EOF
```
> Опция `-localhost` в `ExecStart` является ключевым элементом безопасности. Она заставляет VNC-сервер принимать подключения только с `localhost`, делая прямое подключение извне невозможным.

**5. Управление службой VNC:**
```bash
# Перезагрузить конфигурацию systemd и включить автозапуск службы для дисплея :1
sudo systemctl daemon-reload
sudo systemctl enable vncserver@1.service

# Запустить службу и проверить ее статус
sudo systemctl start vncserver@1.service
sudo systemctl status vncserver@1.service
```

**6. Подключение через SSH-туннель (безопасный способ):**
С вашего локального компьютера создайте SSH-туннель, который перенаправит удаленный порт `5901` на ваш локальный порт `59001`.
```bash
# ssh -L <локальный_порт>:localhost:<удаленный_порт> -N -f -l <user> <server_ip>
ssh -L 59001:localhost:5901 -N -f -l your_username your_server_ip
```
После этого откройте ваш VNC-клиент (например, TigerVNC Viewer, Remmina) и подключитесь к адресу `localhost:59001`.

## 4. Дополнительная информация

### Сравнение IPMI и внешнего IP-KVM

| Возможность | IPMI / BMC (встроенное) | Внешний IP-KVM |
| :--- | :---: | :---: |
| **Удаленная консоль (KVM)** | ✅ | ✅ |
| **Управление питанием** | ✅ | ❌ |
| **Монтирование образов (.iso)** | ✅ | ❌ |
| **Мониторинг датчиков** | ✅ | ❌ |

**Ключевое различие:** IPMI и его аналоги — это комплексная система управления сервером. Внешние IP-KVM обычно предоставляют только базовый доступ к консоли.

### Проприетарные реализации IPMI/BMC

-   **Dell:** **iDRAC** (integrated Dell Remote Access Controller)
-   **HP:** **iLO** (Integrated Lights-Out)
-   **Lenovo/IBM:** **IMM** (Integrated Management Module)
-   **Cisco:** **CIMC** (Cisco Integrated Management Controller)
-   **Supermicro:** **IPMI** (стандартная спецификация)

### Последовательный консольный сервер (Serial Console Server)

Это альтернативный метод OOB, используемый для оборудования с последовательным портом (COM). Администратор подключается по SSH к консольному серверу, а уже с него получает текстовый доступ к консоли нужного устройства. Часто применяется для управления сетевым оборудованием (коммутаторы, маршрутизаторы).
