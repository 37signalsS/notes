# Удаленный доступ к серверам

## Определения

- **Удаленный доступ:** Совокупность методов и технологий для управления сервером на расстоянии через сетевые интерфейсы.
- **Внутриполосное управление (In-Band Management):** Доступ через основную операционную систему и сетевой стек. Примеры: SSH, VNC, RDP. Требует полностью работоспособной ОС и сетевых настроек внутри неё.
- **Внеполосное управление (Out-of-Band Management, OOB):** Аппаратный доступ к серверу, независимый от состояния операционной системы. Позволяет управлять сервером, даже если он выключен или ОС зависла.
- **IPMI (Intelligent Platform Management Interface):** Промышленный стандарт для встроенного модуля управления (**BMC — Baseboard Management Controller**), предоставляющего аппаратный OOB-доступ.
- **IP-KVM (KVM-over-IP):** Технология передачи сигналов клавиатуры, видео и мыши (Keyboard, Video, Mouse) по IP-сети. Не путать с [KVM-виртуализацией](../Virtualization/kvm/overview.md).
- **VNC (Virtual Network Computing):** Протокол для графического удаленного доступа к рабочему столу.

## Основные концепции

### Иерархия управления

В системном администрировании принято следовать иерархии доступа:

1. **Стандартный доступ (SSH):** Основной, быстрый и безопасный способ для текстовых команд.
2. **Аварийный доступ (OOB):** Используется при потере доступа по SSH, ошибках загрузки (Kernel Panic), необходимости настройки BIOS/UEFI или переустановки ОС.

### Возможности внеполосного управления (OOB)

Модули BMC (Dell iDRAC, HP iLO, Supermicro IPMI) функционируют как независимые компьютеры внутри сервера и предоставляют следующие возможности:

- **Удаленная консоль:** Визуальный доступ к экрану сервера с момента включения питания.
- **Управление питанием:** Принудительное включение, выключение и перезагрузка (Hard Reset).
- **Мониторинг:** Отслеживание состояния аппаратных датчиков (температура, напряжение, работа вентиляторов).
- **Виртуальные носители (Virtual Media):** Дистанционное подключение образов `.iso` для установки или восстановления системы.

### Безопасность удаленного доступа

- **Изоляция OOB:** Интерфейсы управления (IPMI/iDRAC/iLO) критически важно размещать в выделенной, изолированной сети управления (Management Network), недоступной из публичного интернета.
- **Туннелирование VNC:** Протокол VNC не имеет встроенного шифрования. Безопасное использование VNC требует создания SSH-туннеля.

## Практические сценарии

### 1. Безопасный консольный доступ (SSH)

SSH является основным инструментом администратора. Все вопросы настройки ключей, конфигурации сервера и безопасности описаны в специализированном разделе: [**SSH (Secure Shell)**](../Security/ssh/ssh_overview.md).

### 2. Аварийное восстановление через IPMI/iDRAC/iLO

Если сервер не отвечает по сети:

1. Подключитесь к веб-интерфейсу модуля управления (например, iDRAC).
2. Запустите удаленную консоль (Remote Console / Virtual KVM).
3. Проанализируйте причину сбоя (сообщения об ошибках при загрузке, зависание процессов).
4. При необходимости используйте функцию перезагрузки или подключите ISO-образ через Virtual Media для загрузки в режиме восстановления (Rescue Mode).

### 3. Настройка графического доступа VNC через SSH-туннель

Сценарий настройки на стороне сервера (Debian/Ubuntu):

**Подготовка и установка:**

```bash
sudo apt update
sudo apt install xfce4 xfce4-goodies tigervnc-standalone-server -y
```

**Настройка VNC-сервера:**

1. Задайте пароль командой `vncserver`.
2. Остановите сервер для настройки: `vncserver -kill :1`.
3. Сконфигурируйте запуск оболочки:

```bash
echo -e '#!/bin/bash\nxrdb $HOME/.Xresources\nstartxfce4 &' > ~/.vnc/xstartup
chmod +x ~/.vnc/xstartup
```

**Создание службы systemd:**
Создайте файл `/etc/systemd/system/vncserver@.service` с параметром `-localhost`, чтобы сервер не принимал внешние подключения напрямую.

**Подключение с клиентской машины:**
Создайте SSH-туннель:

```bash
ssh -L 59001:localhost:5901 -N -f user@server_ip
```

После этого подключитесь VNC-клиентом к адресу `localhost:59001`.

## Дополнительная информация

### Проприетарные реализации OOB

Разные производители используют собственные названия для систем управления:

- **Dell:** iDRAC (integrated Dell Remote Access Controller).
- **HP (HPE):** iLO (Integrated Lights-Out).
- **Lenovo/IBM:** IMM (Integrated Management Module).
- **Cisco:** CIMC (Cisco Integrated Management Controller).
- **Supermicro:** Generic IPMI.

### Сравнение IPMI и внешнего IP-KVM

| Возможность | Встроенный BMC (IPMI) | Внешний IP-KVM |
| :--- | :---: | :---: |
| Удаленная консоль | Да | Да |
| Управление питанием | Да | Нет |
| Монтирование образов | Да | Нет |
| Аппаратный мониторинг | Да | Нет |

### Консольные серверы (Serial Console)

Альтернативный метод OOB для управления через последовательный порт (Serial Port). Позволяет получить текстовый доступ к консоли сервера или сетевого оборудования даже при полном отказе сетевого стека Ethernet.

Подробнее о защите каналов связи: [SSH-туннели и проброс портов](../Security/ssh/ssh_usage_and_tunnels.md).
