# rsync — синхронизация файлов и каталогов

## Определения

- **rsync (Remote Sync):** Утилита для эффективной синхронизации файлов и каталогов между двумя путями (локальными или удаленными). Стандарт де-факто для инкрементального копирования в Linux.
- **Инкрементальная передача:** Метод копирования, при котором передаются только измененные части файлов, что значительно экономит трафик и время.
- **Дельта-кодирование (Remote Differential Compression):** Алгоритм rsync, разбивающий файлы на блоки и вычисляющий их контрольные суммы для поиска отличий без необходимости иметь обе копии файла на одной машине.
- **Алгоритм скользящей контрольной суммы (Rolling Checksum):** Позволяет быстро находить смещенные блоки данных внутри файла.
- **Delta-передача (diff):** Передача только отличающихся частей файлов, а не файлов целиком.
- **rsyncd:** Демон rsync, слушающий TCP/873 и обслуживающий запросы синхронизации без SSH.
- **rrsync (Restricted rsync):** Ограниченная версия rsync, запускаемая через forced command в SSH, которая разрешает только операции синхронизации в рамках заданной директории.
- **RPO/RTO в контексте rsync:** rsync влияет на RPO (частота запуска определяет максимальную потерю данных) и RTO (скорость инкрементальной передачи определяет время восстановления).

## Основные концепции

### Принцип работы

rsync оптимизирует передачу данных следующим образом:

1. Разбивает файлы на блоки фиксированного размера (по умолчанию 700 байт, в версии 3.x — адаптивный размер).
2. Вычисляет контрольные суммы (rolling checksum и хэш) для каждого блока.
3. Сравнивает блоки источника и назначения.
4. Передает только те блоки, которые отличаются или отсутствуют на приемнике.
5. **Согласование (Negotiation):** В версиях 3.2+ клиент и сервер автоматически договариваются о наиболее эффективных алгоритмах хеширования (например, xxHash) и сжатия (zstd/lz4).

**Почему rsync, а не `tar | ssh` или `dd`:**
- `tar | ssh` передает файлы целиком, без дельта-сжатия. При повторной синхронизации передается весь объём, даже если изменился 1 байт.
- `dd` работает на уровне блоков устройств, не имеет встроенного дельта-алгоритма и не сохраняет права/владельцев без дополнительных флагов.
- rsync передаёт только изменившиеся части, сохраняет все метаданные и корректно обрабатывает прерывания.

### Транспорт rsync

rsync поддерживает три режима транспорта:

1. **Локальный (Local):** Источник и приемник на одной машине.
   ```bash
   rsync -a /src/ /dst/
   ```
   Не использует сеть, но применяет дельта-алгоритм между двумя локальными путями.

2. **Удалённая оболочка (Remote Shell):** Использует SSH или RSH для создания канала.
   ```bash
   rsync -avz -e ssh /src/ user@host:/dst/
   ```
   Это режим по умолчанию при указании `user@host:`. Трафик шифруется.

3. **Демон (Daemon):** Подключение к rsyncd через собственный протокол (TCP/873).
   ```bash
   rsync -av /src/ backup_user@host::backup
   ```
   Трафик не шифруется. Требует отдельной конфигурации.

### Алгоритм дельта-передачи

Для поиска отличий между файлами rsync использует двухуровневую схему:

1. **Rolling checksum (Adler-32):** Быстрая, но не криптографически стойкая. Позволяет найти смещенные блоки за O(n) на файле. Используется на первом проходе для построения карты блоков.
2. **Strong hash (MD4/MD5 в старых версиях, xxHash в 3.2+):** Точная проверка совпадения блоков. Заменяет MD5 на xxHash по умолчанию в версиях 3.2+ для ускорения.

**Важно:** Rolling checksum позволяет находить блоки даже при вставке/удалении данных в начале файла (сдвиг всего содержимого), что невозможно при простом сравнении по смещению.

### Важность слеша в конце пути

Поведение утилиты критически зависит от наличия слеша в конце пути источника:

- `rsync -a /src/ /dst/` — копирует **содержимое** директории `/src/` в `/dst/`.
- `rsync -a /src /dst/` — копирует **саму директорию** `/src` внутрь `/dst/` (результат: `/dst/src/`).

## Практические сценарии

### 1. Базовые операции и флаги

Для большинства задач используется комбинация `-avzP`:

- `-a` (archive) — архивный режим: рекурсия, сохранение прав, владельцев, временных меток и символических ссылок. Эквивалентен `-rlptgoD`.
- `-v` (verbose) — подробный вывод процесса.
- `-z` (compress) — сжатие данных при передаче.
- `-P` — сочетание `--partial` (сохранение недокачанных файлов) и `--progress` (индикация скорости).

При миграции между системами с разными UID/GID используйте `--numeric-ids`, чтобы сохранять числовые идентификаторы владельцев, а не их имена (имена пользователей могут отличаться).

- `-A` — сохранение **ACL** (Access Control Lists). Не входит в `-a`.
- `-X` — сохранение **расширенных атрибутов** (xattrs, например, SELinux контексты). Не входит в `-a`.
- `-H` (hard-links) — сохранение жестких ссылок (требует много памяти при большом количестве файлов).
- `-S` (sparse) — эффективная обработка **разреженных файлов** (превращает пустые блоки в "дыры" на приемнике).
- `-x` (one-file-system) — не пересекать границы файловых систем (полезно при бэкапе корня `/`).
- `--checksum` (`-c`) — сравнение файлов по контрольным суммам вместо даты и размера (нагружает CPU).
- `--inplace` — обновляет файл "на месте". Полезно для огромных файлов (БД, образы), чтобы не создавать временную копию, но опасно при сбое.

```bash
# Синхронизация с сохранением всех атрибутов и обработкой разреженных файлов
rsync -avzHSX -P /src/ user@host:/dst/
```

### 2. Оптимизация для современных систем (rsync 3.2.0+)

Если обе стороны поддерживают rsync 3.2+, можно значительно ускорить процесс:

```bash
# Использование xxh3 для хеширования и zstd для сжатия (лучший баланс для средних сетей)
rsync -av --checksum-choice=xxh3 --compress-choice=zstd /src/ user@host:/dst/

# Использование lz4 для высокоскоростных сетей (минимальная задержка CPU)
rsync -av --compress-choice=lz4 /src/ user@host:/dst/

# Локальное копирование (без сжатия, режим целых файлов)
rsync -aW /src/ /dst/
```

### 3. Зеркалирование и удаление

Флаг `--delete` удаляет на приемнике файлы, которых больше нет на источнике.
**Важно:** Всегда используйте `--dry-run` (`-n`) перед запуском с удалением.

```bash
# Тестовый прогон (показывает, что БУДЕТ удалено)
rsync -avzn --delete /src/ /dst/

# Реальное зеркалирование
rsync -av --delete /src/ /dst/
```

**Дополнительные флаги для безопасного удаления:**
- `--delete-after` — удалять на приемнике файлы после успешной передачи (вместо удаления до синхронизации, как `--delete`).
- `--delete-excluded` — удаляет на приемнике файлы, которые исключены через `--exclude`.
- `--ignore-errors` — продолжает синхронизацию даже при ошибках удаления (полезно для файлов с правами только для чтения).

### 4. Исключение и фильтрация

- `--exclude-from='file.txt'` — чтение шаблонов исключения из файла.
- `--filter='rule'` — гибкие правила.

```bash
# Исключение по списку из файла
rsync -av --exclude-from='.rsyncignore' /src/ /dst/

# Пример правила фильтрации: исключить все, кроме конкретной папки
rsync -av --filter='+ /include_dir/' --filter='- /*' /src/ /dst/

# Исключение всех скрытых директорий
rsync -av --filter='- .*/' /src/ /dst/
```

**Пример `.rsyncignore`:**
```text
# Игнорировать кэши и временные файлы
.git/
node_modules/
*.log
*.tmp
.DS_Store
Thumbs.db
```

### 5. Резервное копирование с историей

Флаг `--link-dest` позволяет создавать инкрементальные бэкапы, используя жесткие ссылки для неизмененных файлов. Это создает "мгновенные снимки", которые занимают место только для измененных данных.

```bash
rsync -av --link-dest=/backup/latest /src/ /backup/$(date +%Y-%m-%d)/
# После завершения обновите ссылку latest:
# ln -snf /backup/$(date +%Y-%m-%d) /backup/latest
```

**Структура бэкапов:**
```text
/backup/
├── latest -> 2026-09-13
├── 2026-09-13/
├── 2026-09-12/
└── 2026-09-11/
```

### 6. Ограничение скорости и SSH

- `--bwlimit=1024` — ограничение в 1024 КБ/с (1 МБ/с).
- `-e 'ssh -p PORT'` — указание параметров SSH.

```bash
# Ограничение скорости и нестандартный порт SSH
rsync -avz -e 'ssh -p 2222' --bwlimit=5000 /src/ user@host:/dst/
```

**SSH через bastion (ProxyJump):**
```bash
# Прямой туннель через jump-хост
rsync -avz -e 'ssh -J bastion.example.com' /src/ user@internal-host:/dst/

# Или через конфиг SSH (~/.ssh/config)
# Host internal-host
#   ProxyJump bastion.example.com
rsync -avz /src/ user@internal-host:/dst/
```

### 7. Перемещение данных и докачка

**Перемещение файлов вместо копирования:**
Флаг `--remove-source-files` удаляет файлы на источнике после успешной передачи. Это превращает rsync в безопасную альтернативу `mv` для больших объёмов через сеть.

```bash
# Перенос данных между серверами с удалением источника
rsync -avz --remove-source-files /src/ user@host:/dst/
# После завершения проверьте, что приемник содержит все файлы
```

**Возобновляемые передачи:**
При прерывании rsync по умолчанию начинает передачу заново. Для докачки используйте:

- `--partial` (`-P` включает этот флаг) — сохраняет недокачанные файлы.
- `--partial-dir=/.rsync-partial` — хранит частичные файлы в отдельной директории (не засоряет целевую).
- `--append-verify` — дописывает данные в конец существующего файла и проверяет контрольные суммы (для логов, образов).

```bash
# Докачка с частичными файлами в отдельной директории
rsync -avzP --partial-dir=/.rsync-partial /large_file.iso user@host:/dst/

# Дописывание в существующий файл (для логов/образов)
rsync -avz --append-verify /var/log/syslog user@host:/dst/
```

### 8. Фильтрация по размеру и правам

**Фильтрация по размеру:**
```bash
# Только файлы меньше 100 МБ
rsync -av --max-size=100m /src/ /dst/

# Только файлы больше 1 ГБ
rsync -av --min-size=1g /src/ /dst/
```

**Исправление прав при передаче:**
```bash
# Принудительно установить права 644 на все файлы
rsync -av --chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r /src/ /dst/

# Принудительно установить владельца и группу на приемнике
rsync -av --chown=backup:backup /src/ user@host:/dst/
```

### 9. Проверка целостности и отчётность

Для аудита и compliance требуется знать, что именно было изменено:

```bash
# Подробный отчёт об изменениях (что, куда, сколько)
rsync -av --itemize-changes --stats /src/ /dst/

# Пример вывода:
# >f.st....  file.txt
# >f++++++  new_file.txt
# *deleting  removed_file.txt
```

**Верификация после передачи:**
```bash
# Полная проверка контрольными суммами (медленно, но точно)
rsync -avnc --delete /src/ /dst/
# Флаг -n (dry-run) показывает, какие файлы отличаются
# Если вывод пустой — синхронизация корректна
```

### 10. Работа в режиме демона (rsyncd)

rsync может работать как самостоятельный сервис (порт TCP/873). Трафик не шифруется.

**Пример `/etc/rsyncd.conf`:**
```text
uid = nobody
gid = nogroup
use chroot = yes
max connections = 4
log file = /var/log/rsyncd.log
pid file = /var/run/rsyncd.pid
lock file = /var/run/rsyncd.lock
secrets file = /etc/rsyncd.secrets

[backup]
path = /data/backups
read only = no
list = yes
auth users = backup_user

[logs]
path = /var/log
read only = yes
list = no
```

**Файл секретов `/etc/rsyncd.secrets` (права 600):**
```text
backup_user:StrongPassword123
```

**Использование:**
```bash
rsync -av /src/ backup_user@host::backup
```

### 11. Автоматизация и мониторинг

Для регулярных бэкапов используйте systemd timer вместо cron для лучшей интеграции с журналами и зависимостями.

**Пример `/etc/systemd/system/rsync-backup.service`:**
```ini
[Unit]
Description=Rsync backup to remote server
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/bin/rsync -avz --delete --stats /data/ backup@server:/backup/
StandardOutput=journal
StandardError=journal
```

**Пример `/etc/systemd/system/rsync-backup.timer`:**
```ini
[Unit]
Description=Daily rsync backup

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

**Активация:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now rsync-backup.timer
# Проверка статуса
systemctl list-timers | grep rsync
```

## Безопасность

### Ограничение через SSH (rrsync)

Для повышения безопасности рекомендуется использовать скрипт `rrsync` (Restricted rsync) в файле `authorized_keys`. Это позволяет разрешить пользователю только rsync-операции в пределах конкретной директории.

**Настройка в `~/.ssh/authorized_keys`:**
```text
command="/usr/bin/rrsync -ro /home/backup/data/",no-agent-forwarding,no-port-forwarding,no-pty,no-x11-forwarding ssh-ed25519 AAAAC3...
```
*Где `-ro` — режим только для чтения.*

### Режим демона в chroot jail

При использовании rsyncd ограничьте доступ через chroot:

```text
[backup]
path = /srv/rsync/backup
use chroot = yes
read only = no
auth users = backup_user
secrets file = /etc/rsyncd.secrets
```

**Требования к chroot:**
- Директория `path` и все её родительские элементы должны принадлежать root.
- Нельзя монтировать файловые системы с `noexec` или `nosuid` внутри chroot.
- Файл секретов должен находиться **вне** chroot или быть символической ссылкой.

### Временные файлы и атаки через symlinks

Используйте `--temp-dir` или `--partial-dir`, чтобы предотвратить:
- Заполнение диска временными файлами на приемнике при прерывании.
- Атаки через символические ссылки, указывающие на критичные директории.

```bash
# Хранить частичные файлы в отдельной директории
rsync -av --partial-dir=/.rsync-partial /src/ /dst/
```

### Противодействие уязвимостям (2024–2026)

В 2024–2026 годах были выявлены критические уязвимости (например, CVE-2024-12084), позволяющие обходить ограничения путей через специально сформированные символьные ссылки.
- **Рекомендация:** Используйте версию **rsync 3.4.4** (выпущена в июне 2026), в которой исправлены данные проблемы и регрессии версии 3.4.3.

## Диагностика и типичные ошибки

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `rsync: connection unexpectedly closed` | Прерывание SSH, неверный ключ, таймаут | Проверить `ssh -v user@host`, увеличить `--contimeout` |
| `rsync: error: some files could not be transferred (code 23)` | Проблемы с правами, файл занят | Проверить права на приемнике, использовать `--chmod`, исключить через `--exclude` |
| `Broken pipe` | Нехватка места, разрыв сети, OOM | Проверить `df -h`, `dmesg` на OOM, использовать `--partial` |
| `rsync: mkstemp failed` | Диск полон или права на целевую директорию | Проверить место и права, использовать `--temp-dir` |
| `Permission denied` на rsyncd | Неверный пароль или `secrets file` | Проверить права на `/etc/rsyncd.secrets` (должен быть 600) |
| `rsync error: error in rsync protocol data stream` | Несовместимые версии rsync | Обновить rsync на обеих сторонах |
| `Sparse file not allowed` | Файловая система FAT32 не поддерживает sparse | Использовать `--sparse` или переформатировать ESP |
| `file has vanished` | Файл удалён во время передачи | Использовать `--ignore-errors` или исключить через `--exclude` |

**Диагностические команды:**
```bash
# Проверка версии rsync на обеих сторонах
rsync --version

# Тест подключения через SSH
ssh -v user@host "rsync --version"

# Проверка свободного места на приемнике
ssh user@host "df -h /dst/"

# Просмотр логов rsyncd
sudo tail -f /var/log/rsyncd.log
```

## Коды завершения (Exit Codes)

| Код | Значение | Описание |
| :--- | :--- | :--- |
| **0** | Success | Успешное завершение. |
| **1** | Syntax error | Ошибка в аргументах или синтаксисе. |
| **11** | File I/O error | Ошибка ввода-вывода (нет места, нет прав). |
| **12** | Protocol stream error | Ошибка в потоке данных протокола. |
| **23** | Partial transfer | Частичная передача (некоторые файлы не скопированы). |
| **24** | Vanished source | Исходные файлы исчезли во время работы (например, временные файлы). |
| **30** | Timeout | Тайм-аут при передаче/приеме данных. |

## Дополнительная информация

### Сравнение средств передачи файлов

| Характеристика | scp | sftp | rsync |
| :--- | :--- | :--- | :--- |
| **Delta-передача** | Нет | Нет | **Да** |
| **Удаление файлов** | Нет | Да (`rm`) | **Да** (`--delete`) |
| **Эффективность** | Высокая (протокол) | Средняя | **Максимальная** для обновлений |
| **Синхронизация** | Нет | Нет | **Да** |

### Альтернативы

- **rclone:** Для работы с облачными хранилищами (S3, GDrive, Azure).
- **fpsync (fpart):** Для параллельного запуска нескольких процессов rsync при работе с миллионами мелких файлов. Использует `fpart` для разбиения файлового списка на чанки.
- **BorgBackup / Restic:** Для дедуплицированных и зашифрованных бэкапов.
- **zfs send/receive:** Для блочной синхронизации на уровне файловой системы.
- **[Модуль synchronize (Ansible)](../../Ansible/Modules/ansible_file_synchronization_modules.md):** Обертка над rsync для автоматизации.
