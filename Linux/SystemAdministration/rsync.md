# rsync — синхронизация файлов

## Определение

**rsync (Remote Sync)** — утилита для эффективной синхронизации файлов и каталогов между двумя путями (локальными или удаленными).

Основные особенности:

- **Инкрементальность:** передает только измененные части файлов, используя алгоритм дельта-кодирования.
- **Сохранение атрибутов:** может копировать права доступа, владельцев, временные метки, символические ссылки и другие метаданные.
- **Универсальность:** работает как по сети (через SSH или собственный демон rsync), так и локально.

## Основные концепции

### Принцип работы

`rsync` экономит трафик за счёт передачи только изменённых блоков:

1. Разбивает файлы на блоки фиксированного размера.
2. Вычисляет контрольные суммы (rolling checksum + хэш) для каждого блока.
3. Сравнивает блоки источника и назначения.
4. Передаёт только отличающиеся блоки.

### Важность слеша в конце пути

Слеш после источника меняет поведение утилиты:

- `rsync -a /src/ /dst/` — копирует **содержимое** директории `/src/` в `/dst/`.
- `rsync -a /src /dst/` — копирует **саму директорию** `/src` внутрь `/dst/` (результат: `/dst/src/`).

## Практические сценарии

### Базовый набор флагов

Для большинства задач используется комбинация `-avz`:

- `-a` (archive) — архивный режим: рекурсия, сохранение прав, владельца, временных меток и симлинков.
- `-v` (verbose) — подробный вывод прогресса.
- `-z` (compress) — сжатие трафика при передаче.
- `--progress` — показывает скорость и процент выполнения для каждого файла.

```bash
rsync -avz --progress /src/ user@host:/dst/
```

### Инкрементальный бэкап с историей

Флаг `--link-dest` позволяет создавать хардлинки на файлы, которые не изменились. Каждый бэкап выглядит полным, но занимает место только за счёт изменений:

```bash
rsync -av --link-dest=/backup/latest /src/ /backup/$(date +%Y-%m-%d)/
```

### Синхронизация с удалением

Флаг `--delete` удаляет на приёмнике те файлы, которых больше нет на источнике. Это полезно для создания точного зеркала.

```bash
# Зеркалирование локальной директории на удаленный сервер
rsync -av --delete /src/ user@host:/dst/
```

### Исключение файлов и директорий

Флаг `--exclude` позволяет пропускать файлы по шаблону. Можно указывать несколько раз.

```bash
rsync -av --exclude='*.log' --exclude='node_modules/' --exclude='.git/' /src/ /dst/
```

### Тестовый прогон (Dry run)

Флаг `-n` или `--dry-run` показывает, что именно будет сделано, без реального выполнения операций. Всегда рекомендуется использовать перед `--delete`.

```bash
rsync -avn --delete /src/ /dst/
```

### Ограничение скорости и докачка

- `--bwlimit` — ограничивает полосу пропускания в КБ/с.
- `--partial` — сохраняет частично переданные файлы при обрыве соединения (вместо их удаления), что позволяет продолжить передачу позже.
- `-P` — удобная комбинация `--partial` и `--progress`.

```bash
rsync -av --bwlimit=10000 --partial /src/ user@host:/dst/
```

### Удаленная синхронизация через SSH

По умолчанию `rsync` использует SSH. Если нужно указать специфические параметры SSH (например, порт):

```bash
rsync -avz -e 'ssh -p 2222' /src/ user@host:/dst/
```

## Дополнительная информация

### Сравнение с scp и sftp

| Характеристика | `scp` | `sftp` | `rsync` |
| :--- | :--- | :--- | :--- |
| **Назначение** | Разовое копирование | Интерактивная работа | Синхронизация |
| **Delta-передача** | Нет | Нет | Да |
| **Удаление файлов** | Нет | Да (`rm`) | Да (`--delete`) |
| **Скорость** | Высокая (простой протокол) | Средняя | Очень высокая для обновлений |

### Оптимизация для больших объемов

При переносе миллионов мелких файлов `rsync` может потреблять много памяти для построения списка файлов. В таких случаях стоит рассмотреть возможность разбиения задачи на части или использование более современных инструментов типа `rclone` (для облаков) или `zfs send/receive`.
