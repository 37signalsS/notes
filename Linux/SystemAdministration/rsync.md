# rsync — синхронизация файлов и каталогов

## Определения

- **rsync (Remote Sync):** Утилита для эффективной синхронизации файлов и каталогов между двумя путями (локальными или удаленными). Стандарт де-факто для инкрементального копирования в Linux.
- **Инкрементальная передача:** Метод копирования, при котором передаются только измененные части файлов, что значительно экономит трафик и время.
- **Дельта-кодирование (Remote Differential Compression):** Алгоритм rsync, разбивающий файлы на блоки и вычисляющий их контрольные суммы для поиска отличий без необходимости иметь обе копии файла на одной машине.
- **Алгоритм скользящей контрольной суммы (Rolling Checksum):** Позволяет быстро находить смещенные блоки данных внутри файла.

## Базовые концепции

### Принцип работы

rsync оптимизирует передачу данных следующим образом:

1. Разбивает файлы на блоки фиксированного размера.
2. Вычисляет контрольные суммы (rolling checksum и хэш) для каждого блока.
3. Сравнивает блоки источника и назначения.
4. Передает только те блоки, которые отличаются или отсутствуют на приемнике.
5. **Согласование (Negotiation):** В версиях 3.2+ клиент и сервер автоматически договариваются о наиболее эффективных алгоритмах хеширования (например, xxHash) и сжатия (zstd/lz4).

### Важность слеша в конце пути

Поведение утилиты критически зависит от наличия слеша в конце пути источника:

- `rsync -a /src/ /dst/` — копирует **содержимое** директории `/src/` в `/dst/`.
- `rsync -a /src /dst/` — копирует **саму директорию** `/src` внутрь `/dst/` (результат: `/dst/src/`).

## Практические сценарии

### 1. Базовые операции и флаги

Для большинства задач используется комбинация `-avzP`:

- `-a` (archive) — архивный режим: рекурсия, сохранение прав, владельцев, временных меток и символических ссылок. Эквивалентен `-rlptgoD`.
- `-v` (verbose) — подробный вывод процесса.
- `-z` (compress) — сжатие данных при передаче.
- `-P` — сочетание `--partial` (сохранение недокачанных файлов) и `--progress` (индикация скорости).

**Продвинутые флаги:**

- `-A` / `-X` — сохранение **ACL** (Access Control Lists) и **расширенных атрибутов** (xattrs). Не входят в `-a`.
- `-H` (hard-links) — сохранение жестких ссылок (требует много памяти при большом количестве файлов).
- `-S` (sparse) — эффективная обработка **разреженных файлов** (превращает пустые блоки в "дыры" на приемнике).
- `-x` (one-file-system) — не пересекать границы файловых систем (полезно при бэкапе корня `/`).
- `--checksum` (`-c`) — сравнение файлов по контрольным суммам вместо даты и размера (нагружает CPU).
- `--inplace` — обновляет файл "на месте". Полезно для огромных файлов (БД, образы), чтобы не создавать временную копию, но опасно при сбое.

```bash
# Синхронизация с сохранением всех атрибутов и обработкой разреженных файлов
rsync -avzHSX -P /src/ user@host:/dst/
```

### 2. Оптимизация для современных систем (rsync 3.2.0+)

Если обе стороны поддерживают rsync 3.2+, можно значительно ускорить процесс:

```bash
# Использование xxh3 для хеширования и zstd для сжатия (лучший баланс для средних сетей)
rsync -av --checksum-choice=xxh3 --compress-choice=zstd /src/ user@host:/dst/

# Использование lz4 для высокоскоростных сетей (минимальная задержка CPU)
rsync -av --compress-choice=lz4 /src/ user@host:/dst/

# Локальное копирование (без сжатия, режим целых файлов)
rsync -aW /src/ /dst/
```

### 3. Зеркалирование и удаление

Флаг `--delete` удаляет на приемнике файлы, которых больше нет на источнике.
**Важно:** Всегда используйте `--dry-run` (`-n`) перед запуском с удалением.

```bash
# Тестовый прогон (показывает, что БУДЕТ удалено)
rsync -avzn --delete /src/ /dst/

# Реальное зеркалирование
rsync -av --delete /src/ /dst/
```

### 4. Исключение и фильтрация

- `--exclude-from='file.txt'` — чтение шаблонов исключения из файла.
- `--filter='rule'` — гибкие правила.

```bash
# Исключение по списку из файла
rsync -av --exclude-from='.rsyncignore' /src/ /dst/

# Пример правила фильтрации: исключить все, кроме конкретной папки
rsync -av --filter='+ /include_dir/' --filter='- /*' /src/ /dst/
```

### 5. Резервное копирование с историей

Флаг `--link-dest` позволяет создавать инкрементальные бэкапы, используя жесткие ссылки для неизмененных файлов. Это создает "мгновенные снимки", которые занимают место только для измененных данных.

```bash
rsync -av --link-dest=/backup/latest /src/ /backup/$(date +%Y-%m-%d)/
# После завершения обновите ссылку latest:
# ln -snf /backup/$(date +%Y-%m-%d) /backup/latest
```

### 6. Ограничение скорости и SSH

- `--bwlimit=1024` — ограничение в 1024 КБ/с (1 МБ/с).
- `-e 'ssh -p PORT'` — указание параметров SSH.

```bash
rsync -avz -e 'ssh -p 2222' --bwlimit=5000 /src/ user@host:/dst/
```

### 7. Работа в режиме демона (rsyncd)

rsync может работать как самостоятельный сервис (порт TCP/873). Трафик не шифруется.

**Пример `/etc/rsyncd.conf`:**
```text
[backup]
path = /data/backups
read only = no
auth users = backup_user
secrets file = /etc/rsyncd.secrets
```

**Использование:**
```bash
rsync -av /src/ backup_user@host::backup
```

## Безопасность

### Ограничение через SSH (rrsync)

Для повышения безопасности рекомендуется использовать скрипт `rrsync` (Restricted rsync) в файле `authorized_keys`. Это позволяет разрешить пользователю только rsync-операции в пределах конкретной директории.

**Настройка в `~/.ssh/authorized_keys`:**
```text
command="/usr/bin/rrsync -ro /home/backup/data/",no-agent-forwarding,no-port-forwarding,no-pty,no-x11-forwarding ssh-ed25519 AAAAC3...
```
*Где `-ro` — режим только для чтения.*

### Противодействие уязвимостям (2024–2026)

В 2024–2026 годах были выявлены критические уязвимости (например, CVE-2024-12084), позволяющие обходить ограничения путей через специально сформированные символьные ссылки.
- **Рекомендация:** Используйте версию **rsync 3.4.4** (выпущена в июне 2026), в которой исправлены данные проблемы и регрессии версии 3.4.3.

## Коды завершения (Exit Codes)

| Код | Значение | Описание |
| :--- | :--- | :--- |
| **0** | Success | Успешное завершение. |
| **1** | Syntax error | Ошибка в аргументах или синтаксисе. |
| **11** | File I/O error | Ошибка ввода-вывода (нет места, нет прав). |
| **12** | Protocol stream error | Ошибка в потоке данных протокола. |
| **23** | Partial transfer | Частичная передача (некоторые файлы не скопированы). |
| **24** | Vanished source | Исходные файлы исчезли во время работы (например, временные файлы). |
| **30** | Timeout | Тайм-аут при передаче/приеме данных. |

## Дополнительная информация

### Сравнение средств передачи файлов

| Характеристика | scp | sftp | rsync |
| :--- | :--- | :--- | :--- |
| **Delta-передача** | Нет | Нет | **Да** |
| **Удаление файлов** | Нет | Да (`rm`) | **Да** (`--delete`) |
| **Эффективность** | Высокая (протокол) | Средняя | **Максимальная** для обновлений |
| **Синхронизация** | Нет | Нет | **Да** |

### Альтернативы

- **rclone:** Для работы с облачными хранилищами (S3, GDrive, Azure).
- **fpsync (fpart):** Для параллельного запуска нескольких процессов rsync при работе с миллионами мелких файлов.
- **BorgBackup / Restic:** Для дедуплицированных и зашифрованных бэкапов.
- **zfs send/receive:** Для блочной синхронизации на уровне файловой системы.
- **[Модуль synchronize (Ansible)](../../Ansible/Modules/ansible_file_synchronization_modules.md):** Обертка над rsync для автоматизации.
