# Восстановление пароля root в Linux

## Определения

**Восстановление пароля в Linux** — процедура сброса утерянного пароля пользователя (чаще всего `root`) путем прерывания стандартного процесса загрузки системы для получения привилегированного доступа. Это штатный метод администрирования при наличии физического доступа к машине или консоли управления.

## Основные концепции

Основной принцип — загрузить ядро Linux со специальными параметрами, которые вместо стандартной системы инициализации (`systemd` или `SysVinit`) запускают командную оболочку (`shell`) с правами `root`. Это позволяет выполнить необходимые команды до аутентификации.

Этот метод эффективен даже если учетная запись `root` заблокирована, а текущий пользователь не имеет прав `sudo`. В облачных средах **VPS (Virtual Private Server)** для этого обычно используется **VNC (Virtual Network Computing)** или Serial Console в панели управления провайдера.

### Ключевые этапы и понятия

1. **Редактирование параметров загрузчика GRUB (GRand Unified Bootloader):** Передача ядру инструкций о действиях после загрузки.
2. **Запуск `init`-оболочки:** Ядро запускает `/bin/bash` с **PID (Process Identifier)** 1, предоставляя полный контроль над системой.
3. **Монтирование корневой файловой системы:** Перемонтирование файловой системы в режим «чтение-запись» (`read-write`) для изменения пароля.
4. **Смена окружения ([chroot](../Core/chroot.md)):** «Переключение» на основную файловую систему сервера (особенно при использовании `rd.break` в `initramfs`).
5. **Контекст SELinux:** Создание файла `.autorelabel` в корне системы для перемаркировки SELinux при следующей загрузке, устраняющее проблемы безопасности меток файлов.

### Стратегии прерывания загрузки

- **`init=/bin/bash`**: Прямой запуск оболочки вместо системы инициализации. Универсальный и старый метод.
- **`rd.break`**: Параметр для `systemd`, останавливающий загрузку в `initramfs` до монтирования основной файловой системы. Предпочтительный метод для систем на базе **RHEL (Red Hat Enterprise Linux)** 7+.
- **Recovery Mode (Режим восстановления):** Пользовательский интерфейс в некоторых дистрибутивах (например, Ubuntu), автоматизирующий шаги и предоставляющий доступ к корневой оболочке.

### Особенности RHEL/CentOS с SELinux

На системах с SELinux после смены пароля через `chroot` необходимо восстановить контекст безопасности файлов и создать `/.autorelabel` для перемаркировки при следующей загрузке.

> **Подробная инструкция:** [SELinux при сбросе пароля](#selinux-при-сбросе-пароля)

## Практические сценарии

Все методы требуют редактирования меню загрузчика **GRUB** (клавиша `e` на выбранном пункте меню) и строки `linux` или `linuxefi`. Загрузка с новыми параметрами осуществляется по `Ctrl+X` или `F10`.

### 1. Универсальный метод (init=/bin/bash)

Подходит для большинства систем (Debian, Ubuntu, CentOS/RHEL).

1. В меню GRUB выберите нужное ядро и нажмите **`e`** для редактирования.
2. Найдите строку, начинающуюся с `linux`, и добавьте в её конец: `init=/bin/bash`.
3. Загрузитесь (`Ctrl+X` или `F10`). Вы попадете в shell от имени root без запроса пароля.
4. Корневая файловая система будет смонтирована только для чтения (`ro`). Перемонтируйте её в режим записи:

   ```bash
   mount -o remount,rw /
   ```

5. Выполните необходимые действия:
   - **Сброс пароля:** `passwd root` (или `passwd username`).
   - **Восстановление sudo:** Если sudo сломано или нет прав, можно добавить пользователя в `sudoers`:

     ```bash
     echo "username ALL=(ALL) NOPASSWD: ALL" >> /etc/sudoers
     ```

6. Для систем с SELinux создайте файл для перемаркировки: `touch /.autorelabel`.
7. Перезагрузите систему. Так как стандартные команды `reboot` могут не работать в этом окружении, используйте:

   ```bash
   exec /sbin/init
   ```

   *(Или `exec /sbin/init 6` для немедленной перезагрузки)*.

### 2. Современный метод для systemd (rd.break)

Предпочтителен для систем на базе RHEL 7+ (CentOS, AlmaLinux, Rocky Linux).

1. В GRUB добавьте `rd.break` в конец строки `linux`.
2. Перемонтируйте основной раздел системы (`/sysroot`) в режим записи: `mount -o remount,rw /sysroot`.
3. Переключитесь в `chroot` на файловую систему сервера: `chroot /sysroot`.
4. Смените пароль и создайте файл для перемаркировки SELinux: `passwd` и `touch /.autorelabel`.
5. Выйдите из `chroot` и перезагрузитесь: `exit` и `reboot`.

### 3. Режим восстановления в Ubuntu

Самый простой способ для Ubuntu, если доступен в меню GRUB.

1. В меню GRUB (нажмите `Shift`) выберите `Advanced Options for Ubuntu`, затем `(recovery mode)`.
2. В меню восстановления выберите `Root (Drop to root shell prompt)`.
3. Перемонтируйте файловую систему в режим записи: `mount -rw -o remount /`.
4. Смените пароль: `passwd username`.
5. Вернитесь в меню (`exit`) и выберите `Resume boot`.

### 4. Live-ISO или Rescue через IPMI

Универсальный метод, когда GRUB недоступен, система не загружается или требуется вмешаться на уровне дисков. Подходит для любых серверов с **IPMI (Intelligent Platform Management Interface)** / iDRAC / iLO.

Суть: сервер загружается не в основную ОС, а во временную live-систему (**ISO-образ** через IPMI или rescue-образ хостера). Оттуда монтируется диск основной системы и выполняется `chroot`.

1. Смонтируйте ISO через IPMI Virtual Media и загрузитесь в LiveCD.
2. Найдите основной диск:

```bash
lsblk
fdisk -l
```

1. Смонтируйте корневой раздел основной системы:

```bash
mount /dev/sdaX /mnt
```

1. Подготовьте окружение для `chroot`:

```bash
mount --bind /dev /mnt/dev
mount --bind /proc /mnt/proc
mount --bind /sys /mnt/sys
chroot /mnt
```

1. Смените пароль:

```bash
passwd
```

1. Для SELinux: `touch /.autorelabel`.
2. Выйдите и перезагрузитесь: `exit` и `reboot`.

### 5. Режим спасения (Rescue mode) у хостера

Самый спокойный вариант при наличии провайдера с поддержкой rescue mode (Hetzner, OVH и аналогичные).

1. Включите rescue mode в панели управления хостера.
2. Сервер перезагрузится в минимальную временную систему.
3. Подключитесь по SSH (логин и пароль обычно показывают в панели).
4. Найдите диск основной системы (`lsblk`, `fdisk -l`).
5. Смонтируйте и выполните `chroot` (как в методе Live-ISO выше).
6. Смените пароль и перезагрузитесь.

## Дополнительная информация

### Диагностика типовых проблем

- **`Authentication token manipulation error`**: файловая система не перемонтирована в режим `rw`.
- **`Failed to connect to bus` / `reboot` не работает**: перезагрузка в окружении без `systemd`. Используйте `exec /sbin/init 6` или `exec /sbin/init 0`.
- **Kernel panic после загрузки**: параметр `splash` в строке GRUB — удалите его.
- **Нет «Recovery Mode» в Ubuntu**: используйте метод `init=/bin/bash`, заменив `ro` на `rw`.

### Безопасность восстановления пароля

Процедура легитимна для администрирования, но уязвима при физическом доступе к машине. Меры защиты:

1. **Пароль на GRUB** — предотвращает редактирование параметров загрузки (не защищает от LiveCD). Настройка: [Безопасность GRUB](./grub.md#безопасность-grub).
2. **Шифрование дисков (LUKS/dm-crypt)** — единственная надёжная защита при физическом доступе; без пароля расшифровки данные недоступны даже с LiveCD.
3. **Пароль BIOS/UEFI** — блокирует загрузку с внешних носителей. Настройка: [BIOS и UEFI](../Core/firmware_bios_uefi.md#управление-параметрами-прошивки). Включает в себя **BIOS (Basic Input/Output System)** и **UEFI (Unified Extensible Firmware Interface)**.

### SELinux при сбросе пароля

На системах с SELinux (RHEL, CentOS) после смены пароля через `chroot` контекст `/etc/shadow` может быть нарушен.

- Если SELinux disabled в текущей сессии: `load_policy -i`.
- Проверка контекста: `ls -Z /etc/shadow`; восстановление: `restorecon /etc/shadow`.
- Автоматическая перемаркировка: `touch /.autorelabel` (или параметр `autorelabel=1` в GRUB).

> **Подробно о SELinux:** [SELinux: Механизмы и настройка](../../Security/Mechanisms/SELinux.md)
