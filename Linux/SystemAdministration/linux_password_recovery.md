# Восстановление пароля root в Linux

## 1. Определения

**Восстановление пароля в Linux** — процедура сброса утерянного пароля пользователя (чаще всего `root`) путем прерывания стандартного процесса загрузки системы для получения привилегированного доступа. Этот метод не является "взломом" или "подбором" пароля, а представляет собой штатный способ администрирования при наличии физического доступа к машине или ее консоли управления.

## 2. Базовые концепции

Основной принцип восстановления — загрузить ядро Linux со специальными параметрами, которые вместо стандартной системы инициализации (`systemd` или `SysVinit`) запускают командную оболочку (`shell`) с правами `root`. Это позволяет выполнить необходимые команды до того, как система потребует аутентификацию.

### Ключевые этапы и понятия:

1.  **Редактирование параметров загрузчика (GRUB):** На этом этапе мы сообщаем ядру, что нужно сделать после загрузки.
2.  **Запуск `init`-оболочки:** Ядро запускает `/bin/bash` как процесс с PID 1, предоставляя полный контроль над системой.
3.  **Монтирование корневой файловой системы:** По умолчанию, на раннем этапе загрузки файловая система монтируется в режиме "только для чтения" (`read-only`) для безопасности. Чтобы изменить пароль, ее необходимо перемонтировать в режим "чтение-запись" (`read-write`).
4.  **Смена окружения (`chroot`):** В некоторых сценариях (например, при использовании `rd.break`) мы попадаем во временную файловую систему `initramfs`. `chroot` позволяет "переключиться" на основную файловую систему сервера, чтобы команды (`passwd`) выполнялись в правильном контексте.
5.  **Контекст SELinux:** В системах с SELinux (RHEL, CentOS, AlmaLinux) изменение файлов (включая `/etc/shadow`, где хранятся хэши паролей) может нарушить их метки безопасности. Создание файла `.autorelabel` в корне системы заставляет SELinux выполнить полную перемаркировку при следующей загрузке, исправляя возможные проблемы с доступом.

### Стратегии прерывания загрузки:

-   **`init=/bin/bash`**: Прямая команда ядру запустить оболочку вместо системы инициализации. Универсальный и самый старый метод.
-   **`rd.break`**: Параметр для `systemd`, который останавливает загрузку в `initramfs`, до монтирования основной файловой системы. Это более современный и предпочтительный метод для систем на базе RHEL 7+.
-   **Recovery Mode (Режим восстановления):** Дружелюбный к пользователю интерфейс в некоторых дистрибутивах (например, Ubuntu), который автоматизирует многие шаги и предоставляет меню для доступа к корневой оболочке.

## 3. Практические сценарии

Все методы требуют входа в меню загрузчика **GRUB** (обычно клавиша `e` на выбранном пункте меню) и редактирования строки, начинающейся с `linux` или `linuxefi`. После внесения изменений система загружается с новыми параметрами по нажатию `Ctrl+X` или `F10`.

### Сценарий 1: Универсальный метод (`init=/bin/bash`)

Подходит для большинства систем, включая Debian, старые версии Ubuntu и CentOS.

1.  В GRUB добавьте `init=/bin/bash` в конец строки `linux`.
2.  После загрузки в командную строку перемонтируйте корневой раздел в режим записи:
    ```bash
    mount -o remount,rw /
    ```
3.  Смените пароль:
    ```bash
    passwd root # или passwd username
    ```
4.  Если система использует SELinux, создайте файл для перемаркировки:
    ```bash
    touch /.autorelabel
    ```
5.  Корректно перезагрузите систему:
    ```bash
    exec /sbin/init 6
    ```

### Сценарий 2: Современный метод для systemd (`rd.break`)

Предпочтителен для систем на базе RHEL 7+ (CentOS, AlmaLinux, Rocky Linux).

1.  В GRUB добавьте `rd.break` в конец строки `linux`.
2.  После загрузки в `emergency mode` перемонтируйте основной раздел системы (который находится в `/sysroot`) в режим записи:
    ```bash
    mount -o remount,rw /sysroot
    ```
3.  Переключитесь в `chroot` на файловую систему сервера:
    ```bash
    chroot /sysroot
    ```
4.  Смените пароль и создайте файл для перемаркировки SELinux:
    ```bash
    passwd
    touch /.autorelabel
    ```
5.  Выйдите из `chroot` и перезагрузитесь:
    ```bash
    exit
    reboot
    ```

### Сценарий 3: Режим восстановления в Ubuntu

Самый простой способ для Ubuntu, если он доступен в меню GRUB.

1.  При загрузке войдите в меню GRUB (может потребоваться нажать `Shift`), выберите `Advanced Options for Ubuntu`, а затем пункт с `(recovery mode)`.
2.  В появившемся меню восстановления выберите `Root (Drop to root shell prompt)`.
3.  Перемонтируйте файловую систему в режим записи:
    ```bash
    mount -rw -o remount /
    ```
4.  Смените пароль для нужного пользователя:
    ```bash
    passwd username
    ```
5.  Вернитесь в меню (`exit`) и выберите `Resume boot` для продолжения загрузки.

## 4. Дополнительная информация: Устранение неполадок

-   **`Authentication token manipulation error`**: Эта ошибка почти всегда означает, что вы забыли перемонтировать файловую систему в режим `rw` (`read-write`).
-   **`Failed to connect to bus` или `reboot` не работает**: Происходит при попытке перезагрузки в окружении, где не запущен `systemd`. Используйте `exec /sbin/init 6` (для перезагрузки) или `exec /sbin/init 0` (для выключения).
-   **`end Kernel panic`**: Часто вызывается параметром `splash` в строке загрузки. Попробуйте удалить его при редактировании параметров в GRUB.
-   **Нет пункта "Recovery Mode" в Ubuntu**: Если этот пункт отсутствует, используйте универсальный метод с `init=/bin/bash`, но предварительно замените в строке загрузки параметр `ro` (read-only) на `rw` (read-write) для удобства.
