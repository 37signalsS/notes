# Восстановление пароля root в Linux

## Определения

**Восстановление пароля в Linux** — процедура принудительного сброса утерянного пароля пользователя (чаще всего `root`) путем прерывания стандартного процесса загрузки системы для получения привилегированного доступа. Это штатный метод администрирования при наличии физического доступа к машине или консоли управления.

**Захват управления загрузкой (Boot Interception)** — прерывание работы загрузчика или начальной инициализации для запуска интерактивной оболочки (`shell`) с правами суперпользователя до момента аутентификации.

## Основные концепции

Основной принцип — загрузить ядро Linux со специальными параметрами, которые вместо стандартной системы инициализации (`systemd` или `SysVinit`) запускают командную оболочку (`/bin/bash`) с **PID 1**. Это позволяет выполнить административные действия до запуска служб безопасности и аутентификации.

### Ключевые технологические этапы

1.  **Редактирование параметров GRUB:** Клавиша `e` в меню позволяет передать ядру инструкции о действиях после загрузки (например, `init=/bin/bash` или `rd.break`).
2.  **Монтирование файловой системы:** Изначально корень монтируется в режиме «только чтение» (`ro`). Для записи изменений в `/etc/shadow` требуется перемонтирование в режим «чтение-запись» (`rw`).
3.  **Смена окружения ([chroot](../Core/chroot.md)):** Переключение на основную файловую систему сервера при загрузке с LiveCD или использовании `initramfs` (метод `rd.break`).
4.  **Контекст SELinux:** На системах с SELinux (RHEL, CentOS) сброс пароля «извне» нарушает метки безопасности. Файл `/.autorelabel` инициирует автоматическую перемаркировку всей ФС при следующей загрузке.
5.  **Сброс блокировок (Account Unlocking):** Если пароль верен, но учетная запись заблокирована из-за перебора попыток, используются утилиты `faillock` или `pam_tally2`.

### Матрица стратегий прерывания загрузки

| Метод | Параметр GRUB | Окружение | Доступ | Применение |
| :--- | :--- | :--- | :--- | :--- |
| **init=/bin/bash** | `init=/bin/bash` | Bash (вместо init) | Без пароля | Универсальный метод (Debian, Ubuntu, CentOS). |
| **rd.break** | `rd.break` | Initramfs shell | Без пароля | RHEL 7+, Fedora, работа с зашифрованными дисками. |
| **Emergency Mode** | `systemd.unit=emergency.target` | Минимальный systemd | С паролем root | Исправление ошибок в `/etc/fstab`. |
| **Recovery Mode** | Через меню GRUB | Интерактивное меню | Без пароля | Ubuntu и производные. |

## Практические сценарии

### 1. Универсальный метод (init=/bin/bash)

1.  В меню GRUB выберите нужное ядро и нажмите **`e`**.
2.  Найдите строку, начинающуюся с `linux`, и добавьте в её конец: `init=/bin/bash`. (Для ускорения можно заменить `ro` на `rw`).
3.  Загрузитесь (`Ctrl+X` или `F10`).
4.  Если ФС смонтирована как `ro`, перемонтируйте её:
    ```bash
    mount -o remount,rw /
    ```
5.  Смените пароль: `passwd root`.
6.  **Для систем с SELinux:** Создайте файл для перемаркировки: `touch /.autorelabel`.
7.  Перезагрузка: так как `reboot` может не работать, используйте `exec /sbin/init` или аппаратный сброс.

### 2. Современный метод для systemd (rd.break)

Используется в RHEL 7-9, CentOS Stream, AlmaLinux, Rocky Linux.

1.  Добавьте `rd.break` в конец строки `linux` в GRUB.
2.  После появления приглашения `switch_root:/#`:
    ```bash
    mount -o remount,rw /sysroot
    chroot /sysroot
    passwd root
    touch /.autorelabel
    exit
    reboot
    ```

### 3. Режим восстановления в Ubuntu

1.  В меню GRUB выберите `Advanced Options for Ubuntu` -> `(recovery mode)`.
2.  В меню выберите `Root (Drop to root shell prompt)`.
3.  Перемонтируйте ФС: `mount -o remount,rw /`.
4.  Смените пароль: `passwd username`.
5.  Выйдите и продолжите загрузку: `exit` -> `Resume boot`.

### 4. Работа с Live-ISO / IPMI (Rescue Mode)

Применяется, когда GRUB недоступен или поврежден. Используется через IPMI Virtual Media или Rescue-образ хостера (Hetzner, OVH).

1.  Загрузитесь с LiveCD.
2.  Найдите корневой раздел (и LVM, если есть):
    ```bash
    lsblk
    # Если LUKS зашифрован:
    cryptsetup luksOpen /dev/sda3 my_disk
    # Если LVM:
    vgscan && vgchange -ay
    ```
3.  Смонтируйте корневой раздел: `mount /dev/mapper/vg0-root /mnt`.
4.  **Важно:** Подготовьте окружение (Bind Mount):
    ```bash
    mount --bind /dev /mnt/dev
    mount --bind /proc /mnt/proc
    mount --bind /sys /mnt/sys
    mount --bind /run /mnt/run # Для доступа к современным сокетам
    ```
5.  Войдите в систему: `chroot /mnt`.
6.  Смените пароль: `passwd root`.
7.  Для SELinux: `touch /.autorelabel`.
8.  Выйдите и размонтируйте всё перед перезагрузкой.

### 5. Облачные среды (AWS, GCP, Azure)

*   **AWS:** Используйте **EC2 Serial Console** или примонтируйте EBS-диск к другому инстансу ("Helper") для ручного редактирования `/etc/shadow`.
*   **GCP:** Используйте **Serial Port 1** (интерактивная консоль).
*   **Azure:** Функция **"Reset password"** в панели управления (требует установленного Azure VM Agent).

### 6. Сброс блокировок учетных записей

Если пароль верный, но вход невозможен:
*   **faillock (RHEL 8+, Debian 11+):**
    ```bash
    faillock --user root --reset
    ```
*   **pam_tally2 (Старые системы):**
    ```bash
    pam_tally2 --user root --reset
    ```

## Укрепление безопасности (Hardening)

Процедура сброса пароля является вектором атаки при физическом доступе.

1.  **Пароль на GRUB:** Предотвращает несанкционированное изменение параметров загрузки. См. [**Безопасность GRUB**](./grub.md#безопасность-grub).
2.  **Шифрование дисков (LUKS):** Единственный надежный способ защиты данных. Без пароля расшифровки сброс пароля в ОС не дает доступа к файлам.
3.  **Пароль BIOS/UEFI:** Блокирует загрузку с внешних USB-носителей.
4.  **Контроль IPMI:** Ограничение доступа к интерфейсам удаленного управления (iDRAC, iLO).

## Диагностика и решение проблем

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `Authentication token manipulation error` | ФС в режиме `ro`. | `mount -o remount,rw /` |
| `passwd: pam_authentication(passwd:chauthtok): ...` | Блокировка в PAM. | Сбросить через `faillock` или проверить `/etc/pam.d/`. |
| Kernel panic после загрузки | Не удален параметр `splash` или `quiet`. | Удалите их в строке GRUB. |
| Система не принимает новый пароль | Нарушен контекст SELinux. | Используйте `touch /.autorelabel` или `restorecon /etc/shadow`. |

## Дополнительная информация

### SELinux при сбросе пароля

На системах с SELinux после `chroot` контекст `/etc/shadow` часто становится некорректным.
- Если система загружена, но `passwd` не работает: `load_policy -i`.
- Просмотр текущих меток: `ls -Z /etc/shadow`.
- Принудительная перемаркировка: параметр `autorelabel=1` в строке ядра GRUB.
