# Выключение и перезагрузка Linux-систем

## Определения

**Graceful Shutdown (Корректное выключение)** — процесс планового завершения работы ОС, включающий уведомление пользователей, остановку служб, сброс дисковых кэшей и размонтирование файловых систем.

**Halt** — состояние системы, при котором все процессы остановлены, но питание физически может не отключаться (зависит от ACPI).

**Power Off** — полное отключение питания системы после завершения процесса `halt`.

**Reboot** — перезапуск системы после корректного завершения всех процессов.

## Основные концепции

### Процесс корректного завершения

Когда инициируется выключение (командами `systemctl poweroff` или `shutdown`), система выполняет следующие шаги:
1.  **Уведомление:** Рассылка сообщений (wall) активным пользователям.
2.  **Остановка служб:** `systemd` отправляет `SIGTERM` всем процессам, давая им время на сохранение состояния. Если процесс не завершается за отведенное время (`DefaultTimeoutStopSec`), отправляется `SIGKILL`.
3.  **Сброс кэшей (Sync):** Все данные из оперативной памяти (Page Cache) принудительно записываются на физические диски.
4.  **Размонтирование:** Файловые системы переводятся в режим `read-only` или полностью размонтируются.
5.  **Остановка ядра:** Передача команды аппаратной прошивке на отключение питания.

### Инструменты управления

| Команда | Назначение | Особенности |
| :--- | :--- | :--- |
| **`halt`** | Остановка ЦПУ | Без флага `-p` может не выключить питание. |
| **`reboot`** | Перезагрузка | Эквивалент `systemctl reboot`. |
| **`shutdown`** | Плановое выключение | Поддерживает расписание (например, `shutdown +10 "Server maintenance"`) и отмену (`shutdown -c`). |
| **`poweroff`** | Выключение питания | Наиболее безопасный метод для десктопов и серверов. |

## Практические сценарии

### 1. Выключение в облачных средах (AWS, Yandex Cloud)

В облаках существует критическое различие между остановкой и уничтожением инстанса.

*   **Stop (Остановка):** Состояние аналогично выключенному физическому серверу. Данные на дисках сохраняются, вы платите только за хранение дисков.
*   **Terminate (Уничтожение):** Полное удаление ВМ.
    *   **ВНИМАНИЕ:** По умолчанию во многих облаках включена опция `Delete on Termination` для корневого диска. При нажатии Terminate вы **безвозвратно потеряете данные**.
*   **Termination Protection:** Настройка, предотвращающая случайное уничтожение критически важных серверов через API или консоль управления.

> **Рекомендация:** Всегда предпочитайте выключение «изнутри» ОС (`sudo poweroff`), чтобы система успела корректно сбросить кэши. Веб-консоль провайдера часто имитирует «выдергивание шнура из розетки».

### 2. Аварийная перезагрузка при зависании (Magic SysRq)

Если стандартные команды не работают (например, из-за сбоя диска или высокой нагрузки), используйте низкоуровневый механизм ядра:

```bash
# Последовательность REISUB (нажать Alt+SysRq + клавиша)
# R - перехватить клавиатуру (Raw)
# E - послать SIGTERM процессам (Terminate)
# I - послать SIGKILL процессам (Kill)
# S - сбросить кэши на диск (Sync)
# U - перемонтировать ФС в Read-Only (Unmount)
# B - немедленная перезагрузка (reBoot)
```
Подробно: [**Диагностика и SysRq**](../Diagnostics/Troubleshooting/reboot_troubleshooting.md#шаг-5-аварийная-перезагрузка-при-отказе-диска-magic-sysrq--reisub).
