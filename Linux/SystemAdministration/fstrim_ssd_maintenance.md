# fstrim: обслуживание SSD и NVMe

## Определения

**`fstrim`** — утилита командной строки Linux для отправки команды TRIM в файловую систему на твердотельном накопителе **SSD (Solid State Drive)** или **NVMe (Non-Volatile Memory Express)**. Команда TRIM информирует контроллер накопителя о том, какие логические блоки данных больше не используются файловой системой и могут быть физически очищены.

**TRIM / UNMAP / DISCARD** — команды интерфейсов **SATA (Serial ATA)**, **SCSI** и протокола **NVMe** (через Dataset Management), позволяющие **ОС (Операционная система)** уведомить накопитель об освобожденных блоках. Без TRIM SSD не всегда идентифицирует удаление файлов на уровне ФС, что ведет к деградации производительности при записи (**Write Amplification**).

## Основные концепции

### Механизм работы TRIM

В отличие от магнитных дисков (HDD), где данные могут перезаписываться напрямую, ячейки флеш-памяти (NAND) требуют предварительной очистки целого блока (Erase Block) перед записью:

1.  **Без TRIM:** Удаление файла помечает сектора как свободные только в метаданных ФС. Контроллер SSD считает их занятыми. При попытке записи в этот блок контроллер выполняет цикл **Read-Modify-Write**: читает блок, очищает его и записывает новые данные вместе со старыми. Это замедляет работу и увеличивает износ ячеек.
2.  **С TRIM:** ОС сообщает контроллеру, что блоки свободны. Контроллер выполняет очистку в фоновом режиме (**Garbage Collection**). При последующей записи данные пишутся сразу в чистые ячейки.

**Преимущества:**
- Поддержание стабильной скорости последовательной и случайной записи.
- Минимизация **Write Amplification Factor (WAF)** — снижение износа ячеек.
- Эффективная работа функции **Wear Leveling** (выравнивание износа).

### Типы TRIM в Linux

| Тип | Название | Метод реализации | Особенности |
| :--- | :--- | :--- | :--- |
| **Periodic TRIM** | Периодический | `fstrim.timer` (systemd) | **Рекомендуемый.** Минимальная нагрузка на I/O. Запускается по расписанию. |
| **Continuous TRIM** | Непрерывный | Опция монтирования `discard` | Выполняется мгновенно. Может вызывать задержки на старых SSD. |
| **Async TRIM** | Асинхронный | Опция `discard=async` (Btrfs) | Компромисс: TRIM-команды ставятся в очередь и выполняются асинхронно. |
| **Manual TRIM** | Ручной | Команда `fstrim -v /` | Используется для разовой оптимизации или диагностики. |

### Аппаратные особенности

1.  **Queued TRIM (SATA 3.1+):** Позволяет SSD обрабатывать TRIM в общей очереди команд без остановки других операций ввода-вывода. На старых дисках выполнение TRIM блокирует другие команды (не-Queued TRIM).
2.  **UASP (USB Attached SCSI Protocol):** Необходим для работы TRIM на внешних SSD, подключенных через USB. Если контроллер USB-моста не поддерживает UASP, TRIM работать не будет.

## Проверка поддержки TRIM

```bash
# Проверить поддержку TRIM для SATA SSD
sudo hdparm -I /dev/sda | grep "TRIM supported"

# Для NVMe устройств (Dataset Management / DSM)
sudo nvme id-ctrl /dev/nvme0 | grep -E "dsm|Dataset Management"

# Быстрая проверка поддержки всей цепочкой (DISC-GRAN > 0)
lsblk -D

# Проверить доступные устройства и выполнить тестовый запуск
sudo fstrim -v --all --dry-run
```

## Практические сценарии

### 1. Автоматизация через systemd-timer (Рекомендуется)

В современных дистрибутивах таймер включен по умолчанию и запускается раз в неделю.

```bash
# Проверить статус таймера
systemctl status fstrim.timer

# Включить и запустить, если отключен
sudo systemctl enable --now fstrim.timer

# Посмотреть логи последних запусков
journalctl -u fstrim.service

# Список всех таймеров и время следующего запуска fstrim
systemctl list-timers --all
```

### 2. TRIM в зашифрованных разделах (LUKS)

По умолчанию `cryptsetup` блокирует TRIM в целях безопасности (скрытие карты заполнения диска). Для включения требуется явное разрешение.

**Способ 1: Настройка в `/etc/crypttab`**
Добавьте опцию `discard` к соответствующему разделу:
```text
sda3_crypt UUID=... none luks,discard
```

**Способ 2: Настройка в загрузчике (GRUB)**
Если корень зашифрован, добавьте в `GRUB_CMDLINE_LINUX_DEFAULT`:
`rd.luks.options=discard`

**Проверка активации:**
```bash
sudo cryptsetup status <name_crypt> | grep discard
# → result: flags: allow_discards
```

### 3. Тонкое провизионирование (LVM Thin Pools)

В тонких пулах LVM команда TRIM критически важна для возврата физического пространства в пул. Без нее пул будет считаться заполненным, даже если данные внутри тома удалены.

Подробнее см.: [**LVM — Тонкое провизионирование**](../FileSystems/LVM/thin-provisioning.md).

### 4. Виртуализация (KVM/QEMU)

Чтобы гостевая ОС могла уменьшать размер разреженного файла-образа или возвращать блоки в Thin Pool хоста:
1.  Использовать контроллер `virtio-scsi`.
2.  Включить опцию `discard='unmap'` для диска в конфигурации VM (libvirt).

### 5. TRIM в программном RAID (mdadm)

Ядро Linux поддерживает передачу TRIM через массивы RAID 0, 1, 5 и 10.
-   Убедитесь, что все диски в массиве поддерживают TRIM.
-   Используйте периодический запуск `fstrim -av`. RAID 5/6 требует включения `devices/virtual/block/mdX/md/discard_threshold`.

### 6. Специфика файловых систем

*   **ZFS (autotrim):** По умолчанию выключен. 
    ```bash
    sudo zpool set autotrim=on <pool_name>
    sudo zpool trim <pool_name> # Ручной запуск
    ```
*   **Btrfs:** Рекомендуется использовать `discard=async` (начиная с ядра 5.6) для снижения нагрузки на контроллер.
*   **Swap на SSD:** Обязательно добавляйте `discard` в `/etc/fstab` для разделов подкачки.
    ```text
    /dev/sda2  none  swap  sw,discard  0  0
    ```

## Диагностика и решение проблем

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| `fstrim: /: the discard operation is not supported` | Оборудование, драйвер или слой (LUKS/LVM) не поддерживают TRIM | Проверить цепочку через `lsblk -D`, включить флаги `discard` в `crypttab` или `LVM`. |
| Файл образа VM не уменьшается после TRIM в госте | Диск VM настроен без `unmap` | Сменить драйвер на `virtio-scsi` и добавить `discard='unmap'`. |
| Высокая латентность (фризы) при удалении файлов | Включен `continuous trim` на старом SSD без Queued TRIM | Отключить опцию монтирования `discard`, использовать `fstrim.timer`. |
| TRIM не работает через USB | USB-мост не поддерживает UASP | Проверить `lsusb -t` (должен быть драйвер `uas`), заменить переходник/кейс. |

## Дополнительная информация

### Безопасность и риски

**Утечка данных в LUKS:** Включение TRIM на зашифрованном диске позволяет злоумышленнику с физическим доступом определить, какие области диска содержат данные (зашифрованный шум), а какие пусты (нули после TRIM). Это раскрывает реальный объем данных и тип ФС. Для большинства систем риск считается приемлемым.

### Рекомендации

1.  **Приоритет таймеру:** Используйте `fstrim.timer` вместо опции монтирования `discard`. Это обеспечивает более предсказуемую производительность I/O.
2.  **Over-provisioning:** Оставляйте 10-15% диска неразмеченным (unallocated). Это дает контроллеру SSD пространство для маневров Garbage Collection даже при полной ФС.
3.  **Noatime:** Используйте опцию монтирования `noatime` в `/etc/fstab` для минимизации лишних записей.
