# fstrim: обслуживание SSD и NVMe

## Определения

**`fstrim`** — утилита командной строки Linux для отправки команды TRIM в файловую систему на твердотельном накопителе **SSD (Solid State Drive)** или **NVMe (Non-Volatile Memory Express)**. Команда TRIM информирует контроллер накопителя о том, какие блоки данных больше не используются и могут быть безопасно очищены.

**TRIM** — команда интерфейсов **SATA (Serial ATA)** и протокола NVMe (через Dataset Management), позволяющая **ОС (Операционная система)** уведомить накопитель об освобожденных блоках. Без TRIM SSD не всегда идентифицирует удаление файлов на уровне ФС, что ведет к деградации производительности при записи (Write Amplification).

## Основные концепции

### Механизм работы TRIM

В отличие от магнитных дисков (HDD), где данные могут перезаписываться напрямую, ячейки флеш-памяти (NAND) требуют предварительной очистки целого блока (Erase Block) перед записью:

1.  **Без TRIM:** Удаление файла в ОС помечает сектора как свободные только в метаданных ФС. Контроллер SSD считает их занятыми. При попытке записи в этот блок контроллер вынужден сначала прочитать данные, очистить блок и записать новые данные (процесс Read-Modify-Write).
2.  **С TRIM:** ОС сообщает контроллеру, что блоки свободны. Контроллер выполняет очистку в фоновом режиме (Garbage Collection). При последующей записи данные пишутся сразу в чистые ячейки.

**Преимущества:**
- Поддержание стабильной скорости последовательной и случайной записи.
- Минимизация **Write Amplification Factor (WAF)** — снижение износа ячеек.
- Эффективная работа функции **Wear Leveling** (выравнивание износа).

### Типы TRIM в Linux

| Тип | Название | Метод реализации | Особенности |
| :--- | :--- | :--- | :--- |
| **Periodic TRIM** | Периодический | `fstrim.timer` (systemd) | Рекомендуемый метод. Минимальная нагрузка на I/O. |
| **Continuous TRIM** | Непрерывный | Опция монтирования `discard` | Выполняется мгновенно. Может снижать скорость при массовом удалении файлов. |
| **Manual TRIM** | Ручной | Команда `fstrim -v /` | Используется для разовой оптимизации или диагностики. |

### Проверка поддержки TRIM

```bash
# Проверить поддержку TRIM для SATA SSD
sudo hdparm -I /dev/sda | grep "TRIM supported"

# Для NVMe устройств
sudo nvme id-ctrl /dev/nvme0 | grep "Dataset Management" -A 1

# Проверить доступные устройства и выполнить тестовый запуск
sudo fstrim -v --all --dry-run
```

## Практические сценарии

### 1. Автоматизация через systemd-timer (Рекомендуется)

В современных дистрибутивах (Ubuntu, Debian, RHEL) таймер включен по умолчанию и запускается раз в неделю.

```bash
# Проверить статус таймера
systemctl status fstrim.timer

# Включить и запустить, если отключен
sudo systemctl enable --now fstrim.timer

# Посмотреть логи последних запусков
journalctl -u fstrim.service
```

### 2. TRIM в зашифрованных разделах (LUKS)

По умолчанию `cryptsetup` блокирует TRIM в целях безопасности (скрытие карты заполнения диска). Для включения требуется явное разрешение.

**Способ 1: Настройка в `/etc/crypttab`**
Добавьте опцию `discard` к соответствующему разделу:
```text
sda3_crypt UUID=... none luks,discard
```

**Способ 2: Настройка в загрузчике (GRUB)**
Если корень зашифрован, добавьте в `GRUB_CMDLINE_LINUX_DEFAULT`:
`rd.luks.options=discard`

**Проверка активации:**
```bash
sudo cryptsetup status <name_crypt> | grep discard
# → result: flags: allow_discards
```

### 3. Тонкое провизионирование (LVM Thin Pools)

В тонких пулах LVM команда TRIM критически важна для возврата физического пространства в пул. Без TRIM пул будет считаться заполненным, даже если вы удалили все данные внутри тома.

Подробнее см.: [**LVM — Тонкое провизионирование**](../FileSystems/LVM/thin-provisioning.md).

### 4. Виртуализация (KVM/QEMU)

Для того чтобы гостевая ОС могла выполнять TRIM на виртуальном диске (и тем самым уменьшать размер разреженного файла-образа или возвращать блоки в Thin Pool хоста), необходимо:
1.  Использовать контроллер `virtio-scsi`.
2.  Включить опцию `discard='unmap'` для диска в конфигурации VM (libvirt).

### 5. TRIM в программном RAID (mdadm)

Современное ядро Linux поддерживает передачу TRIM через массивы RAID 0, 1, 5 и 10.
-   Убедитесь, что все диски в массиве поддерживают TRIM.
-   Используйте периодический запуск `fstrim -av`.

### 6. Специфика ZFS (autotrim)

В ZFS (OpenZFS) по умолчанию TRIM выключен. Его можно включить на уровне пула:

```bash
# Включить непрерывный TRIM
sudo zpool set autotrim=on <pool_name>

# Запустить ручной TRIM пула
sudo zpool trim <pool_name>
```

## Диагностика и решение проблем

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| `fstrim: /: the discard operation is not supported` | Оборудование или драйвер не поддерживают TRIM | Проверить поддержку в `hdparm`, обновить прошивку. |
| Файл образа VM не уменьшается после TRIM в госте | Диск VM настроен без `unmap` | Сменить драйвер на `virtio-scsi` и добавить `discard='unmap'`. |
| Высокая латентность при удалении файлов | Включен `continuous trim` (`-o discard`) | Отключить опцию монтирования, использовать `fstrim.timer`. |

## Дополнительная информация

### Безопасность и риски

**Утечка данных в LUKS:** Включение TRIM на зашифрованном диске позволяет злоумышленнику определить, какие области диска содержат данные (зашифрованный шум), а какие пусты (нули после TRIM). Это может облегчить криптоанализ или определение типа ФС, но для 99% сценариев риск считается приемлемым по сравнению с деградацией SSD.

### Рекомендации

1.  **Приоритет таймеру:** Используйте `fstrim.timer` вместо опции монтирования `discard`. Это обеспечивает более предсказуемую производительность I/O.
2.  **Over-provisioning:** Оставляйте 10-15% диска неразмеченным (unallocated). Это дает контроллеру SSD дополнительное пространство для маневров Garbage Collection даже при заполненной ФС.
3.  **Noatime:** Используйте опцию монтирования `noatime` в `/etc/fstab` для минимизации лишних записей при каждом чтении файла.
