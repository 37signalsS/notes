# fstrim: Обслуживание SSD

## Определения

**`fstrim`** — утилита Linux для отправки команды TRIM в файловую систему на твердотельном накопителе (SSD/NVMe). Команда TRIM информирует контроллер накопителя о том, какие блоки данных больше не используются и могут быть очищены.

**TRIM** — команда ATA/SATA/NVMe, позволяющая ОС уведомить накопитель об освобожденных блоках. Без TRIM SSD не всегда "понимает", что файлы были удалены на уровне файловой системы.

## Базовые концепты

### Зачем нужен TRIM

В отличие от HDD, где данные могут перезаписываться напрямую, SSD требует предварительной очистки блоков перед записью:

1. **Без TRIM:** Удаление файла в ОС не очищает блоки на SSD → при новой записи требуется сначала очистить блок (медленно).
2. **С TRIM:** SSD заранее очищает помеченные блоки → последующая запись происходит быстрее.

**Преимущества регулярного TRIM:**
- Поддержание производительности записи
- Продление срока службы SSD (меньше циклов перезаписи)
- Снижение задержек при записи

### Типы TRIM

| Тип | Описание | Когда использовать |
| :--- | :--- | :--- |
| **Periodic TRIM (`fstrim`)** | Запуск по расписанию (cron/systemd timer) | Большинство сценариев |
| **Continuous TRIM (`discard`)** | TRIM выполняется при каждом удалении | Только для современных SSD с хорошей производительностью |
| **Manual TRIM** | Ручной запуск `fstrim -v /` | Разовая оптимизация, диагностика |

> **Важно:** Continuous TRIM (`mount -o discard`) может снижать производительность на старых SSD. Рекомендуется periodic TRIM через systemd-timer.

### Проверка поддержки TRIM

```bash
# Проверить поддержку TRIM для устройства
sudo hdparm -I /dev/sdX | grep TRIM

# Для NVMe
sudo nvme id-ctrl /dev/nvme0 | grep trim

# Проверить, смонтирована ли ФС с discard
mount | grep discard

# Проверить доступные устройства для fstrim
sudo fstrim -v --all --dry-run
```

## Практические сценарии

### Ручное выполнение

Для немедленной очистки неиспользуемых блоков:

```bash
# Очистка корневого раздела
sudo fstrim -v /

# Очистка всех смонтированных ФС с поддержкой TRIM
sudo fstrim -av

# Вывод подробной информации
sudo fstrim -v --verbose /
```

Команда выведет объем освобожденных данных (например, `/: 12.5 GiB trimmed`).

### Автоматическое выполнение с `systemd-timer`

Большинство дистрибутивов включают `fstrim.timer` для автоматической еженедельной очистки.

**Активация:**

```bash
# Включить таймер
sudo systemctl enable fstrim.timer

# Запустить таймер
sudo systemctl start fstrim.timer

# Проверить статус
sudo systemctl status fstrim.timer

# Посмотреть расписание
systemctl cat fstrim.timer
```

**Изменение расписания:**

Создайте override-файл для изменения частоты:

```bash
sudo systemctl edit fstrim.timer
```

```ini
[Timer]
# Запускать ежедневно в 03:00
OnCalendar=*-*-* 03:00:00
# Или каждые 12 часов
# OnCalendar=*-*-* *:00:00
# RandomizedDelay=1h
```

**Проверка выполнения:**

```bash
# Просмотр логов выполнения
journalctl -u fstrim.timer

# Последнее выполнение
systemctl list-timers fstrim.timer
```

### Настройка Continuous TRIM (опционально)

Для современных SSD можно включить автоматический TRIM при монтировании:

```bash
# Добавить discard в /etc/fstab
# Пример:
# UUID=xxx-yyy-zzz / ext4 defaults,discard 0 1

# Перемонтировать с discard
sudo mount -o remount,discard /
```

> **Предупреждение:** Continuous TRIM может снижать производительность на старых SSD. Проверяйте документацию производителя.

### Диагностика проблем

| Проблема | Диагностика | Решение |
| :--- | :--- | :--- |
| `fstrim: not supported` | `hdparm -I /dev/sdX` не показывает TRIM | Проверить поддержку SSD, обновить прошивку |
| `fstrim: mount point not mounted` | `mount \| grep /` | Убедиться, что ФС смонтирована |
| Таймер не запускается | `systemctl status fstrim.timer` | Включить `enable --now` |
| Медленная запись после TRIM | `iostat -x 1` | Проверить износ SSD (`smartctl -a`) |

## Дополнительная информация

### Связанные темы

- **Мониторинг состояния SSD:** [smartctl](../../Diagnostics/Hardware/smartctl.md) — проверка износа, температуры, переназначенных секторов
- **Файловые системы:** [ext4](../../FileSystems/ext4.md), [xfs](../../FileSystems/xfs.md), [btrfs](../../FileSystems/btrfs.md) — поддержка TRIM зависит от ФС
- **Планировщики задач:** [cron.md](./cron.md), [Systemd Timers](../../Core/systemd/timers.md) — автоматизация fstrim

### Рекомендации

1. **Periodic TRIM предпочтителен:** Еженедельный запуск через `fstrim.timer` достаточен для большинства сценариев.
2. **Не используйте `discard` на старых SSD:** Может снижать производительность.
3. **Проверяйте поддержку ФС:** ext4, xfs, btrfs поддерживают TRIM, но некоторые ФС (например, zfs) требуют дополнительной настройки.
4. **NVMe и TRIM:** Современные NVMe накопители хорошо обрабатывают periodic TRIM.
5. **Шифрованные диски:** LUKS поддерживает TRIM, но требует осторожности (может раскрыть информацию об использовании пространства).

### Безопасность

**TRIM и шифрование:** При использовании LUKS команда TRIM может раскрыть информацию о том, какие блоки заняты, а какие свободны. Это потенциальная утечка метаданных.

```bash
# Проверить, включен ли TRIM для LUKS
sudo cryptsetup status /dev/sdX

# При необходимости отключить TRIM в LUKS
# В /etc/crypttab добавить опцию: no-discard
```

Для большинства сценариев периодический TRIM на зашифрованных дисках безопасен, но в средах с высокими требованиями к безопасности следует оценить риски.
