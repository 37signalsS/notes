# Маршрутизация в Linux

## Определения

* **Маршрутизация (Routing):** Процесс определения пути для IP-пакетов от отправителя к получателю.
* **Таблица маршрутизации (Routing Table):** Набор правил в ядре, который используется для принятия решений о том, куда отправить пакет.
* **IP Forwarding (Пересылка IP):** Функция ядра Linux, позволяющая пересылать пакеты между сетевыми интерфейсами. Когда она включена, Linux-система может работать как маршрутизатор.

## Основные концепции

### Как работает маршрутизация?

Когда ядро получает IP-пакет, оно просматривает свою таблицу маршрутизации, чтобы найти наиболее подходящее правило. Правило состоит из:

* **Destination:** Целевая сеть или хост.
* **Gateway:** IP-адрес шлюза (маршрутизатора), через который нужно отправить пакет.
* **Genmask:** Маска подсети для целевой сети.
* **Interface:** Сетевой интерфейс, через который нужно отправить пакет.

**Маршрут по умолчанию (Default Route)** — это правило с `Destination` `0.0.0.0` (или `default`), которое используется, если ни одно другое правило не подошло.

### IP Forwarding

По умолчанию Linux-система не пересылает пакеты, полученные на один интерфейс, на другой. Она обрабатывает только пакеты, предназначенные ей самой. Чтобы превратить Linux в маршрутизатор, необходимо включить **IP Forwarding**.

Эта функция управляется параметром ядра `net.ipv4.ip_forward` (и `net.ipv6.conf.all.forwarding` для IPv6).

## Практические сценарии

### 1. Просмотр таблицы маршрутизации

Современный способ — использовать команду `ip route`.

```bash
# Показать основную таблицу маршрутизации
ip route show

# Пример вывода:
# default via 192.168.1.1 dev enp0s3  # Маршрут по умолчанию
# 192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.100 # Локальная сеть
```

### 2. Включение IP Forwarding

* **Проверить текущее состояние:**

    ```bash
    sysctl net.ipv4.ip_forward
    # net.ipv4.ip_forward = 0 (выключено)
    ```

* **Включить временно (до перезагрузки):**

    ```bash
    sudo sysctl -w net.ipv4.ip_forward=1
    ```

    *Или альтернативный способ:*

    ```bash
    echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
    ```

* **Включить постоянно:**
    1. Откройте файл `/etc/sysctl.conf` (или создайте новый файл в `/etc/sysctl.d/`).
    2. Добавьте или раскомментируйте строку:

        ```
        net.ipv4.ip_forward=1
        ```

    3. Примените изменения:

        ```bash
        sudo sysctl -p
        ```

### 3. Добавление и удаление маршрутов

* **Добавить маршрут к сети:**

    ```bash
    # Весь трафик в сеть 10.10.0.0/16 отправлять через шлюз 192.168.1.254
    sudo ip route add 10.10.0.0/16 via 192.168.1.254
    ```

* **Добавить маршрут к хосту:**

    ```bash
    sudo ip route add 172.16.5.5 via 192.168.1.1
    ```

* **Удалить маршрут:**

    ```bash
    sudo ip route del 10.10.0.0/16
    ```

> Эти маршруты также являются временными. Для постоянного добавления используйте конфигурационные файлы вашей ОС.

### 4. Маршрут по умолчанию (Default Gateway)

Маршрут по умолчанию используется, когда нужно отправить пакет в сеть, для которой нет явного маршрута.

```bash
# Добавить шлюз по умолчанию
sudo ip route add default via 192.168.1.1

# Удалить шлюз по умолчанию  
sudo ip route del default

# Посмотреть текущий default gateway
ip route | grep default
```

**Приоритет маршрутов:** Более специфичные маршруты (к конкретной подсети или хосту) имеют приоритет над шлюзом по умолчанию. Чем точнее маршрут, тем выше его приоритет.

### 5. Превращение Linux в роутер с NAT

Для организации доступа во внутреннюю сеть через NAT (как описано в [NAT (Network Address Translation)](../../Networking/Concepts/nat.md)):

1. Включите IP Forwarding (см. раздел 2)
2. Настройте NAT в файрволе (firewalld, iptables или nftables)

Подробнее см. **[NAT в Linux](../Networking/Concepts/nat.md#настройка-nat-в-firewalld-linux-router)**.

## Дополнительная информация

### Policy-Based Routing (PBR)

Для более сложных сценариев, когда маршрут нужно выбирать не только по адресу назначения, но и по адресу источника или другим критериям, используется **[Policy-Based Routing](../Networking/linux_policy_based_routing.md)**.
