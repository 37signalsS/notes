# Маршрутизация в Linux

## Определения

- **Маршрутизация (Routing):** Процесс выбора пути для передачи IP-пакетов от отправителя к получателю через промежуточные узлы.
- **Таблица маршрутизации (Routing Table):** Структура данных в ядре, содержащая набор правил для принятия решений о направлении трафика.
- **Пересылка пакетов (IP Forwarding):** Механизм ядра Linux, позволяющий пересылать пакеты между сетевыми интерфейсами. Необходим для работы Linux в режиме маршрутизатора.
- **Шлюз по умолчанию (Default Gateway):** Маршрут, используемый для отправки трафика в сети, для которых нет явных записей в таблице маршрутизации (сеть `0.0.0.0/0`).

## Основные концепции

### Принципы принятия решений

При получении или отправке пакета ядро анализирует таблицу маршрутизации. Каждое правило (маршрут) содержит:

- **Сеть назначения (Destination):** Целевая подсеть или конкретный хост.
- **Шлюз (Gateway):** IP-адрес следующего устройства на пути к цели.
- **Интерфейс (Interface):** Локальное сетевое устройство, через которое отправляется пакет.
- **Метрика (Metric):** Приоритет маршрута (чем меньше значение, тем выше приоритет).

Ядро всегда выбирает наиболее специфичный маршрут (принцип Longest Prefix Match). Например, маршрут к сети `/24` будет выбран вместо маршрута `/16` для адреса, попадающего в обе сети.

### Режим маршрутизатора (IP Forwarding)

По умолчанию Linux обрабатывает только те пакеты, которые адресованы ему самому (на его собственные IP-адреса). Если пакет предназначен для другого узла, ядро его отбрасывает. Включение `ip_forward` заставляет ядро проверять таблицу маршрутизации для всех входящих пакетов и пересылать их согласно правилам.

Подробнее о параметрах ядра: [sysctl](../Core/kernel/sysctl.md).

## Практические сценарии

### 1. Просмотр и анализ маршрутов

Основным инструментом является утилита `ip` из пакета `iproute2`.

```bash
# Показать основную таблицу маршрутизации
ip route show

# Узнать, какой путь выберет ядро для конкретного IP
ip route get 8.8.8.8
```

Разбор типичного вывода `ip route show`:
`default via 192.168.1.1 dev eth0 proto dhcp metric 100`

- `default`: шлюз по умолчанию (0.0.0.0/0).
- `via 192.168.1.1`: адрес следующего хопа (шлюза).
- `dev eth0`: физический интерфейс.
- `proto dhcp`: маршрут получен автоматически по DHCP.

Подробное описание полей и флагов: [ip route](../Networking/Tools/iproute2/ip_route.md).

### 2. Включение пересылки трафика

Для работы в качестве шлюза необходимо активировать `ip_forward`.

**Временное включение (до перезагрузки):**

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

**Постоянное включение:**
Отредактируйте файл `/etc/sysctl.conf` (или создайте файл в `/etc/sysctl.d/`):

```text
net.ipv4.ip_forward = 1
```

Примените изменения командой `sudo sysctl -p`.

### 3. Управление статическими маршрутами

Команды `ip route` применяются немедленно, но действуют только до перезагрузки.

```bash
# Добавить маршрут к сети через конкретный шлюз
sudo ip route add 10.10.0.0/16 via 192.168.1.254

# Установить шлюз по умолчанию
sudo ip route add default via 192.168.1.1

# Удалить маршрут
sudo ip route del 10.10.0.0/16
```

Синтаксис и примеры управления: [ip route: Управление таблицей маршрутизации](../Networking/Tools/iproute2/ip_route.md).

### 4. Настройка NAT (Network Address Translation)

Для организации доступа внутренней сети в интернет часто требуется настройка маскарадинга (Masquerade).

1. Включите IP Forwarding.
2. Добавьте правило в файрвол:

```bash
# Пример для nftables
nft add rule ip nat postrouting oifname "eth0" masquerade
```

Подробнее: [NAT в Linux](../../Networking/Concepts/nat/practical_scenarios.md).

## Дополнительная информация

### Постоянная настройка (Persistence)

Методы сохранения маршрутов зависят от сетевого менеджера дистрибутива:

- **Netplan (Ubuntu):** настройки в секции `routes` файлов `.yaml`.
- **NetworkManager (RHEL/Debian):** через `nmcli connection modify <conn> +ipv4.routes ...`.
- **systemd-networkd:** секции `[Route]` в файлах `.network`.

### Диагностика проблем

| Проблема | Инструмент | Описание |
| :--- | :--- | :--- |
| Проверка доступности хоста | `ping` | Базовая проверка связности |
| Трассировка пути пакета | `traceroute` / `mtr` | Выявление узла, на котором обрывается связь |
| Проверка правил фильтрации | `iptables` / `nft` | Поиск блокирующих правил в цепочке FORWARD |
| Анализ трафика | `tcpdump` | Проверка факта прохождения пакетов через интерфейс |
