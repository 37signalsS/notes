# Маршрутизация в Linux

## Определения

- **Маршрутизация (Routing):** Процесс выбора оптимального пути для передачи IP-пакетов от отправителя к получателю на основе таблиц маршрутизации.
- **Таблица маршрутизации (Routing Table):** База данных в ядре, содержащая правила (маршруты), определяющие, через какой интерфейс и шлюз должен быть отправлен пакет для достижения целевой сети.
- **LPM (Longest Prefix Match):** Алгоритм выбора наиболее специфичного маршрута (с самой длинной маской подсети) при наличии нескольких совпадений.
- **Пересылка пакетов (IP Forwarding):** Функция ядра, позволяющая узлу работать в качестве маршрутизатора, пересылая пакеты, адресованные другим узлам, между своими сетевыми интерфейсами.
- **RPDB (Routing Policy Database):** База данных правил, используемая для выбора таблицы маршрутизации в расширенных сценариях (**[PBR](../Networking/Policy_Based_Routing/index.md)**).

## Основные концепции

### Процесс принятия решений ядром

При получении или генерации пакета стек протоколов Linux выполняет следующие шаги:

1. **Проверка RPDB (`ip rule`):** Ядро проходит по списку правил. По умолчанию пакеты направляются в таблицу `main`.
2. **Поиск по LPM:** В выбранной таблице ищется маршрут, маска которого максимально соответствует адресу назначения.
3. **Выбор интерфейса и шлюза:** Если маршрут найден, пакет передается на соответствующий уровень L2 (ARP/NDP) для отправки через указанный интерфейс.
4. **Шлюз по умолчанию:** Если специфичного маршрута нет, используется запись `default` (`0.0.0.0/0`).

### Выбор исходного IP (Source IP Selection)

Для исходящих пакетов, инициированных самим хостом, ядро выбирает `Source IP` следующим образом:

1. **Атрибут `src`:** Если в маршруте явно указан параметр `src` (например, `ip route add ... src 1.2.3.4`), используется этот адрес.
2. **Привязка к сокету:** Если приложение явно выполнило `bind()` к адресу, используется он.
3. **Область видимости (Scope):** Если `src` не задан, ядро ищет первый доступный адрес на выходном интерфейсе с областью видимости `global`.

Проверка выбора: `ip route get <IP_назначения>`. Подробнее: **[ip route: атрибуты маршрутов](../Networking/Tools/iproute2/ip_route.md#атрибуты-маршрутов)**.

### Фильтрация обратного пути (rp_filter)

**Reverse Path Filtering** — механизм защиты от спуфинга и асимметричной маршрутизации. Ядро проверяет, пришел ли пакет через тот интерфейс, через который ушел бы ответ на него согласно таблице маршрутизации.

| Режим (`sysctl`) | Значение | Описание |
| :--- | :--- | :--- |
| **No Filtering** | `0` | Проверка отключена. Риск спуфинга, но разрешена любая асимметрия. |
| **Strict Mode** | `1` | Пакет отбрасывается, если входящий интерфейс не является оптимальным путем для ответа. |
| **Loose Mode** | `2` | Пакет принимается, если адрес источника достижим через *любой* интерфейс хоста. |

Настройка: `net.ipv4.conf.<interface>.rp_filter`. Режим `1` часто вызывает проблемы в сетях с несколькими провайдерами (см. **[PBR](../Networking/Policy_Based_Routing/index.md)**).

### Пересылка трафика (Forwarding)

Для работы Linux в качестве шлюза необходимо активировать `ip_forward`. Без этого ядро отбрасывает пакеты, IP-адрес назначения которых не принадлежит самому хосту.

Параметры:
- `net.ipv4.ip_forward`
- `net.ipv6.conf.all.forwarding`

## Практические сценарии

### 1. Просмотр и анализ маршрутов

Основным инструментом является утилита `ip` из пакета `iproute2`.

```bash
# Просмотр основной таблицы маршрутизации
ip route show

# Просмотр конкретной таблицы (для PBR)
ip route show table 100

# Эмуляция прохождения пакета (проверка маршрута и src IP)
ip route get 8.8.8.8
```

Подробное описание полей и флагов: **[ip route: команды и атрибуты](../Networking/Tools/iproute2/ip_route.md)**.

### 2. Включение режима маршрутизатора

**Временное включение:**
```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

**Постоянное включение (через конфигурацию):**
Создайте файл `/etc/sysctl.d/99-routing.conf`:
```text
net.ipv4.ip_forward = 1
net.ipv6.conf.all.forwarding = 1
```
Примените: `sudo sysctl --system`.

### 3. Управление статическими маршрутами

```bash
# Добавить маршрут к сети
sudo ip route add 10.50.0.0/16 via 192.168.1.254 dev eth0

# Добавить маршрут к конкретному хосту (Host Route)
sudo ip route add 1.1.1.1 via 192.168.1.1

# Удалить маршрут
sudo ip route del 10.50.0.0/16
```

### 4. Сохранение настроек (Persistence)

Маршруты, добавленные через `ip route`, исчезают после перезагрузки. Для постоянной настройки используйте сетевые менеджеры:

#### Netplan (Ubuntu)
Файл `/etc/netplan/*.yaml`:
```yaml
network:
  ethernets:
    eth0:
      routes:
        - to: 10.10.0.0/24
          via: 192.168.1.1
```

#### NetworkManager (RHEL/CentOS)
```bash
nmcli connection modify eth0 +ipv4.routes "10.10.0.0/24 192.168.1.1"
nmcli connection up eth0
```

#### systemd-networkd (Debian/Arch)
Файл `/etc/systemd/network/*.network`:
```ini
[Route]
Destination=10.10.0.0/24
Gateway=192.168.1.1
```

## Дополнительная информация

### Расширенные возможности

- **[Policy-Based Routing (PBR)](../Networking/Policy_Based_Routing/index.md):** Маршрутизация на основе IP источника, портов или меток (fwmark).
- **[VRF (Virtual Routing and Forwarding)](../Networking/vrf.md):** Создание полностью изолированных таблиц маршрутизации для интерфейсов.
- **ECMP (Equal Cost Multi-Path):** Распределение трафика между несколькими равнозначными шлюзами (балансировка).

### Диагностика

| Проблема | Инструмент | Команда / Действие |
| :--- | :--- | :--- |
| **Хост недоступен** | `ping` / `mtr` | Проверка связности и потерь на узлах |
| **Асимметрия / rp_filter** | `sysctl` | Проверить `net.ipv4.conf.all.rp_filter` |
| **Пакет не пересылается** | `tcpdump` | `tcpdump -i eth0 icmp` — проверка входа и выхода пакета |
| **Блокировка FW** | `nft` / `iptables` | Проверка цепочки `FORWARD` и правил `ACCEPT` |

См. также: **[iproute2: Обзор](../Networking/Tools/iproute2/overview.md)**, **[NAT в Linux](../../Networking/Concepts/nat/practical_scenarios.md)**.
