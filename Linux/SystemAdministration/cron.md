# Управление задачами по расписанию: Cron, Anacron, At, Systemd Timers

## Определения

- **Cron:** Классический системный демон-планировщик в Unix-подобных системах для автоматического выполнения команд или скриптов в указанное время или через заданные интервалы.
  - **Vixie Cron:** Традиционная реализация (V3), ставшая основой для большинства современных версий.
  - **Cronie:** Современный форк Vixie Cron, используемый в RHEL/CentOS/Fedora и Arch Linux. Поддерживает расширения, такие как вложенные файлы и интеграция с PAM.
- **Crontab (Cron Table):** Текстовый файл, содержащий расписание задач. Существуют пользовательские таблицы (хранятся в `/var/spool/cron/` или `/var/spool/cron/crontabs/`) и системные (в `/etc/`).
- **Anacron:** Планировщик, предназначенный для систем, работающих не круглосуточно (ноутбуки, рабочие станции). В отличие от cron, он работает с периодами (день, неделя, месяц) и гарантирует запуск пропущенных задач после включения системы.
- **At:** Утилита для однократного (разового) запуска команд в определенное время в будущем.
- **Batch:** Вариант `at`, который запускает задачи только тогда, когда нагрузка на систему (`load average`) опускается ниже определенного порога (по умолчанию 0.8).
- **Таймеры systemd (systemd Timers):** Современный механизм планирования в системах с systemd, обладающий более гибким управлением и глубокой интеграцией с системными юнитами. Подробнее: [Таймеры systemd](../Core/systemd/timers.md).

## Базовые концепции

### Структура расписания Cron

Формат строки в `crontab` состоит из пяти временных полей и команды:

```text
┌───────────── минута (0 - 59)
│ ┌───────────── час (0 - 23)
│ │ ┌───────────── день месяца (1 - 31)
│ │ │ ┌───────────── месяц (1 - 12)
│ │ │ │ ┌───────────── день недели (0 - 6) (Воскресенье=0 или 7)
│ │ │ │ │
* * * * * команда_для_выполнения
```

**Специальные символы:**

- `*`: Любое значение (каждую минуту, каждый час).
- `,`: Список значений (например, `1,15` — запуск 1-го и 15-го числа).
- `-`: Диапазон (например, `9-17` — каждый час с 9 до 17 включительно).
- `/`: Шаг (например, `*/5` — каждые 5 минут).

**Специальные сокращения (Shortcuts):**

| Сокращение | Эквивалент | Описание |
| :--- | :--- | :--- |
| `@reboot` | — | Запуск один раз при старте демона (после загрузки ОС) |
| `@hourly` | `0 * * * *` | Раз в час (в 0 минут) |
| `@daily` | `0 0 * * *` | Раз в день (в полночь) |
| `@weekly` | `0 0 * * 0` | Раз в неделю (в полночь воскресенья) |
| `@monthly` | `0 0 1 * *` | Раз в месяц (1-го числа в полночь) |
| `@yearly` | `0 0 1 1 *` | Раз в год (1 января в полночь) |

### Контекст выполнения и переменные окружения

Задачи выполняются в минимальном окружении, которое **не наследует** переменные из вашего интерактивного шелла (`~/.bashrc`, `~/.profile`).

- **PATH:** По умолчанию крайне ограничен (часто только `/usr/bin:/bin`). Рекомендуется явно задавать его в начале crontab или использовать абсолютные пути к бинарникам.
- **SHELL:** По умолчанию используется `/bin/sh`. Если ваш скрипт использует синтаксис bash, укажите `SHELL=/bin/bash`.
- **HOME:** Директория пользователя, от имени которого запускается задача.
- **MAILTO:** Указывает адрес для отправки вывода (stdout/stderr). Если `MAILTO=""`, уведомления отключены.
- **CRON_TZ:** Позволяет задать часовой пояс для конкретного файла расписания (поддерживается в Cronie).
- **Пустая строка:** Большинство реализаций требуют наличия пустой строки в конце файла `crontab`, иначе последняя задача может не выполниться.
- **Рабочий каталог:** По умолчанию — домашняя директория пользователя.

### Логика Anacron

Anacron проверяет, выполнялась ли задача в заданный период, сверяясь с метками времени в `/var/spool/anacron/`.

**Конфигурация:** `/etc/anacrontab`
Формат: `Период (дней) | Задержка (мин) | Идентификатор | Команда`

Параметры актуализации (характерно для Cronie/Anacron):
- **RANDOM_DELAY:** Максимальная случайная задержка в минутах, которая добавляется к базовой задержке задачи. Это предотвращает одновременный запуск множества задач при загрузке системы.
- **START_HOURS_RANGE:** Интервал времени (например, `03-22`), в котором Anacron разрешено запускать задачи.

### Системные директории и файлы

| Путь | Описание | Нюансы |
| :--- | :--- | :--- |
| `/etc/crontab` | Общий системный файл | Требует указания **пользователя** перед командой |
| `/etc/cron.d/` | Модульные файлы задач | Требует указания **пользователя**. Права должны быть `644`, владелец `root`. Имена не должны содержать точки (в ряде дистрибутивов) |
| `/etc/cron.daily/weekly/monthly/` | Скрипты периодического запуска | Обычно вызываются через `anacron` или системный `cron` |
| `/etc/cron.allow` / `/etc/cron.deny` | Контроль доступа | Белые и черные списки пользователей |
| `/var/spool/cron/crontabs/` | Пользовательские задачи | Файлы управляются командой `crontab -e` |
| `/var/spool/anacron/` | Метки времени Anacron | Хранят дату последнего успешного запуска |

## Практические сценарии

### 1. Управление пользовательскими задачами

Используется утилита `crontab`:

- `crontab -l` — вывод текущих задач.
- `crontab -e` — редактирование (с проверкой синтаксиса при сохранении).
- `crontab -r` — удаление всех задач текущего пользователя.
- `crontab -u username -e` — редактирование задач другого пользователя (требуются права root).

**Примеры:**

```bash
# Бэкап каждый день в 02:30
30 2 * * * /home/user/scripts/backup.sh

# Очистка логов 1-го числа каждого месяца в полночь
0 0 1 * * /usr/local/bin/cleanup_logs.sh
```

### 2. Системные задачи в `/etc/cron.d`

При создании файлов в этой директории необходимо указывать **имя пользователя**. Это стандарт при использовании инструментов автоматизации, таких как [Ansible](../../Ansible/ansible_introduction.md).

```text
# /etc/cron.d/monitor
# Формат: мин час дом мес дне пользователь команда
* * * * * root /usr/local/bin/check_health.sh
```

### 3. Переменные окружения и логирование

Переменные можно объявлять прямо в файле `crontab`.

```text
# В начале crontab
MAILTO=admin@example.com
PATH=/usr/local/bin:/usr/bin:/bin
SHELL=/bin/bash

# Логирование stdout и stderr в разные файлы
* * * * * user_q /home/user_q/script.sh > /var/log/script.log 2> /var/log/script.err

# Полное подавление вывода
0 2 * * * /home/user/silent_task.sh > /dev/null 2>&1
```

Просмотр логов:

```bash
# Системы с systemd
journalctl -u cron.service

# Традиционные логи
tail -f /var/log/syslog | grep CRON  # Debian/Ubuntu
tail -f /var/log/cron               # RHEL/CentOS
```

### 4. Предотвращение параллельного запуска (Locking)

Для защиты от наложения процессов используется `flock`:

```bash
# Запуск каждые 5 минут, только если предыдущий процесс завершен
*/5 * * * * root /usr/bin/flock -n /var/run/backup.lock /usr/local/bin/backup.sh
```
- `-n` (non-blocking): немедленный выход, если файл заблокирован.

### 5. Почему скрипт работает вручную, но не в Cron

#### 1. Ограниченный PATH
Cron использует минимальный `PATH` (обычно `/usr/bin:/bin`). Если скрипт вызывает `docker`, `aws`, `node` без полных путей, они не будут найдены.
- **Решение:** Используйте абсолютные пути (`/usr/local/bin/docker`) или задайте `PATH` в crontab.

#### 2. Неверная рабочая директория (CWD)
Cron запускает задачи из `$HOME` пользователя. Относительные пути внутри скрипта сломаются.
- **Решение:** Добавьте `cd $(dirname "$0")` в начало скрипта.

#### 3. Отсутствие TTY и интерактивности
В cron нет терминала. Команды, ожидающие ввода или использующие `sudo` (без `NOPASSWD`), завершатся ошибкой. Не подгружаются алиасы и функции из `~/.bashrc`.
- **Решение:** Проверьте скрипт на наличие интерактивных команд и используйте абсолютные пути.

#### 4. Разница в интерпретаторах (SHELL)
По умолчанию `/bin/sh` может указывать на `dash` (в Ubuntu/Debian), который не поддерживает специфичный синтаксис bash.
- **Решение:** Явно укажите `SHELL=/bin/bash` в crontab.

#### 5. Переменные окружения (ENV)
Cron не знает о переменных (`DB_PORT`, `API_TOKEN`), заданных в профиле пользователя.
- **Решение:** Подгружайте `.env` файл внутри скрипта: `set -a; source /path/to/.env; set +a`.

**Чек-лист отладки:**
```bash
# 1. Перенаправьте вывод в файл для анализа ошибок
* * * * * /path/to/script.sh > /tmp/cron_debug.log 2>&1

# 2. Имитируйте окружение cron для ручной проверки
env -i HOME="$HOME" SHELL=/bin/sh PATH=/usr/bin:/bin /path/to/script.sh
```

## Дополнительная информация

### Работа с разовыми задачами (At)

```bash
# Запуск через 10 минут
echo "/home/user/script.sh" | at now + 10 minutes

# Запуск в полночь
at midnight -f /home/user/script.sh

# Просмотр очереди и удаление
atq
atrm 5
```

### Безопасность и управление доступом

1. **Разграничение доступа:**
   - `/etc/cron.allow`: Если файл существует, только перечисленные в нем пользователи могут использовать cron.
   - `/etc/cron.deny`: Используется, если нет `cron.allow`.
2. **Права на скрипты:** Скрипты, запускаемые от `root`, не должны быть доступны на запись обычным пользователям (риск Privilege Escalation).
3. **Права на конфигурации:** Файлы в `/etc/cron.d/` должны иметь права `644`. Слишком широкие права (`777`, `666`) приведут к игнорированию файла демоном cron.
4. **Валидация имен:** В некоторых дистрибутивах (например, Debian) файлы в `/etc/cron.d/` с точкой в имени игнорируются планировщиком `run-parts`.

### Сравнение с Таймерами systemd

| Характеристика | Cron | Таймеры systemd |
| :--- | :--- | :--- |
| **Точность** | До минуты | До микросекунды |
| **Логирование** | Вывод в почту или файлы | Интеграция с `journald` |
| **Зависимости** | Нет | Поддержка зависимостей (сеть, монтирование) |
| **Ресурсы** | Минимальные | Контроль CPU/RAM через cgroups |
| **Пропущенные задачи** | Только через Anacron | Опция `Persistent=true` |

Подробное руководство по переходу: **[Таймеры systemd](../Core/systemd/timers.md)**.
