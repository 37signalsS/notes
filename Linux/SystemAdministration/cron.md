# Управление задачами по расписанию: Cron, Anacron, At, Systemd Timers

## Определения

- **Cron:** Классический системный демон в Unix-подобных системах для выполнения команд или скриптов в указанное время или через заданные интервалы.
- **Crontab (Cron Table):** Текстовый файл, содержащий расписание задач для конкретного пользователя или всей системы.
- **Anacron:** Планировщик, ориентированный на выполнение пропущенных задач. В отличие от cron, работает с периодами (день, неделя, месяц), что критично для систем, работающих не круглосуточно.
- **At:** Утилита для однократного запуска команд в будущем.
- **Batch:** Вариант `at`, запускающий задачи только при падении нагрузки на систему (load average) ниже определенного порога.
- **Таймеры systemd (systemd Timers):** Современная альтернатива cron в системах с systemd, интегрированная с системными юнитами. Подробнее: [Таймеры systemd](../Core/systemd/timers.md).

## Базовые концепции

### Структура расписания Cron

Формат строки в `crontab` состоит из пяти полей времени и команды:

```text
┌───────────── минута (0 - 59)
│ ┌───────────── час (0 - 23)
│ │ ┌───────────── день месяца (1 - 31)
│ │ │ ┌───────────── месяц (1 - 12)
│ │ │ │ ┌───────────── день недели (0 - 6) (Воскресенье=0 или 7)
│ │ │ │ │
* * * * * команда_для_выполнения
```

**Специальные символы:**

- `*`: Любое значение (каждую минуту, каждый час).
- `,`: Список значений (например, `1,15` — 1-е и 15-е числа).
- `-`: Диапазон (например, `9-17` — часы с 9 до 17 включительно).
- `/`: Шаг (например, `*/5` — каждые 5 минут).

### Контекст выполнения

Задачи выполняются в минимальном окружении, которое **не наследует** переменные из интерактивного шелла (`~/.bashrc`, `~/.profile`).

- `PATH` обычно ограничен (`/usr/bin:/bin`).
- Рабочий каталог по умолчанию — `$HOME` пользователя.
- Рекомендуется использовать **абсолютные пути** к бинарным файлам и скриптам.

### Логика Anacron

Anacron не привязан к конкретному времени суток. Он проверяет, выполнялась ли задача в заданный период (например, раз в день). Если система была выключена в момент планируемого запуска, anacron запустит задачу через несколько минут после включения системы.

**Конфигурация:** `/etc/anacrontab`
Формат: `Период (дней) | Задержка (мин) | Идентификатор | Команда`

### Системные директории и файлы

| Путь | Описание |
| :--- | :--- |
| `/etc/crontab` | Общий системный файл расписаний |
| `/etc/cron.d/` | Директория для модульных системных задач (предпочтительно для автоматизации) |
| `/etc/cron.daily/weekly/monthly/` | Скрипты для периодического выполнения (часто управляются anacron) |
| `/var/spool/cron/crontabs/` | Хранилище пользовательских crontab-файлов |
| `/var/spool/at/` | Очередь задач утилиты `at` |

## Практические сценарии

### 1. Управление пользовательскими задачами

Используется команда `crontab`:

- `crontab -l` — вывод списка текущих задач.
- `crontab -e` — редактирование (с проверкой синтаксиса при сохранении).
- `crontab -r` — удаление всех задач текущего пользователя.
- `crontab -u username -e` — редактирование задач другого пользователя (требуются права root).

**Примеры:**

```bash
# Бэкап каждый день в 02:30
30 2 * * * /home/user/scripts/backup.sh

# Очистка логов 1-го числа каждого месяца в полночь
0 0 1 * * /usr/local/bin/cleanup_logs.sh
```

### 2. Системные задачи в `/etc/cron.d`

При создании файлов в `/etc/cron.d` необходимо указывать **имя пользователя** после расписания. Это удобно для управления через [Ansible](../../Ansible/ansible_introduction.md).

```text
# /etc/cron.d/monitor
* * * * * root /usr/local/bin/check_health.sh
```

### 3. Переменные окружения и логирование

Для передачи переменных окружения их можно объявить прямо в файле `crontab` или подгружать внутри скрипта.

```text
# В начале crontab
MAILTO=admin@example.com
PATH=/usr/local/bin:/usr/bin:/bin

* * * * * user_q /home/user_q/script.sh
```

Просмотр логов выполнения:

```bash
# Для систем с systemd
journalctl -u cron.service

# Традиционные логи (в зависимости от дистрибутива)
grep CRON /var/log/syslog
# или
tail -f /var/log/cron
```

### 4. Использование At и Batch

Запуск разовых задач:

```bash
# Запуск через 10 минут
echo "/home/user/script.sh" | at now + 10 minutes

# Запуск в полночь
at midnight -f /home/user/script.sh

# Просмотр очереди задач
atq

# Удаление задачи по ID
atrm 5
```

`batch` не требует указания времени и запускает команду, когда `load average` системы опускается ниже 0.8.

## Дополнительная информация

### Безопасность и эскалация привилегий

Задачи, выполняемые от `root`, — частый вектор атаки:

1. **Слабые права на скрипты:** Если скрипт, запускаемый кроном, доступен на запись обычному пользователю, он может внедрить вредоносный код.
2. **Переменная PATH:** Если `PATH` не задан явно, злоумышленник может подменить легитимный бинарный файл своим в директории, которая проверяется раньше.
3. **Права на файлы:** Конфигурации в `/etc/cron.d/` должны иметь права `644` (или `600`) и принадлежать `root`.

### Сравнение с Таймерами systemd

| Характеристика | Cron | Таймеры systemd |
| :--- | :--- | :--- |
| Точность | До минуты | До микросекунды |
| Логирование | stdout/stderr в почту или файлы | Интеграция с `journald` |
| Зависимости | Нет | Поддержка зависимостей юнитов |
| Ресурсы | Минимальные | Гибкое управление через cgroups |

Подробное руководство по переходу: **[Таймеры systemd](../Core/systemd/timers.md)**.
