# Управление привилегиями: su и sudo

В Linux для выполнения задач, требующих прав суперпользователя (`root`) или другого пользователя, используются две основные команды: `su` и `sudo`. Хотя обе позволяют повышать привилегии, они работают по-разному и служат разным целям.

## `su` (Switch User / Substitute User)

Команда `su` позволяет **полностью переключить сессию** на другого пользователя. Если имя пользователя не указано, по умолчанию пытается переключиться на `root`.

-   `su <имя_пользователя>`: Переключиться на указанного пользователя. **Потребуется пароль целевого пользователя** (того, на которого вы переключаетесь).
-   `su -` или `su -l`: Переключиться на пользователя `root` с полным изменением окружения (загружаются переменные окружения, профиль и домашний каталог `root`).

Основной недостаток `su` — необходимость делиться паролем `root` со всеми, кому нужны права администратора, что является плохой практикой с точки зрения безопасности.

## `sudo` (Superuser Do)

Команда `sudo` позволяет **выполнить одну или несколько команд** от имени другого пользователя (по умолчанию `root`), не переключая всю сессию.

-   **Какой пароль спрашивает:** Пароль **вашего текущего пользователя**.
-   **Как работает:** `sudo` проверяет файл `/etc/sudoers`, чтобы определить, имеет ли **текущий пользователь** право выполнять указанную команду.
-   **Логирование:** Каждое действие, выполненное через `sudo`, записывается в системный журнал (например, `/var/log/auth.log`), создавая полный аудиторский след.

### Основные команды `sudo`

-   `sudo <команда>`: Выполнить команду с правами `root`.
-   `sudo -l`: Посмотреть список разрешенных команд для вашего пользователя.
-   `sudo -u <имя_пользователя> <команда>`: Выполнить команду от имени **любого другого пользователя**.
    ```bash
    # Выполнить команду ls от имени пользователя 'test'
    sudo -u test ls -la /home/test
    ```

### Получение интерактивной оболочки через `sudo`

-   `sudo -i [-u <имя_пользователя>]`: Запускает **интерактивную login-оболочку**. Это лучший способ "стать" другим пользователем. Окружение будет таким же, как если бы этот пользователь вошел в систему: загрузятся его `.profile`, `.bashrc`, а текущим каталогом станет его домашний каталог. Аналогично `su -`.
-   `sudo -s [-u <имя_пользователя>]`: Запускает **интерактивную non-login оболочку**. Запускает оболочку, указанную в переменной `SHELL`, но не симулирует полный вход в систему (не считывает `.profile`) и оставляет вас в текущем каталоге.

Если `<имя_пользователя>` не указано, используется `root`.

## Конфигурация `sudo`: файл `/etc/sudoers`

Этот файл определяет, какие пользователи и группы могут использовать `sudo`. **Его следует редактировать только с помощью команды `visudo`**, которая проверяет синтаксис перед сохранением, чтобы не заблокировать систему.

**Синтаксис правила:**
```
кто     хост=(от_имени_кого) что_делать
```
-   `кто`: Имя пользователя или `%имя_группы`.
-   `хост`: Хост, на котором действует правило (обычно `ALL`).
-   `от_имени_кого`: От имени какого пользователя можно выполнять команду (обычно `ALL` для `root`).
-   `что_делать`: Команда или список команд.

### Примеры правил

1.  **Права для пользователя:**
    ```
    # Пользователь alice может выполнять любые команды от имени root
    alice ALL=(ALL) ALL
    ```

2.  **Предоставление прав группе:**
    Для предоставления прав группе используется префикс `%`. В большинстве современных дистрибутивов (Debian, Ubuntu, CentOS) существует группа `sudo` или `wheel`, членство в которой дает полные права `sudo`. Добавление пользователя в эту группу — стандартный способ предоставления прав администратора.
    ```bash
    # Добавить пользователя в группу sudo (Debian/Ubuntu)
    usermod -aG sudo username
    ```
    Соответствующая строка в `/etc/sudoers`:
    ```
    # Все пользователи в группе sudo могут выполнять любые команды
    %sudo ALL=(ALL:ALL) ALL
    ```

3.  **Выполнение команд без пароля (`NOPASSWD`):**
    Позволяет выполнять определённые команды без ввода пароля. Это удобно для скриптов, но требует осторожности.
    ```
    # Пользователь charlie может перезапускать сервис nginx без пароля
    charlie ALL=(ALL) NOPASSWD: /usr/sbin/service nginx restart, /usr/sbin/service nginx status
    ```

## Системный вызов `setuid()`

`setuid()` — это системный вызов, который позволяет процессу изменить свой эффективный идентификатор пользователя (EUID), реальный идентификатор пользователя (RUID) и сохраненный идентификатор пользователя (SUID). Это критически важный механизм для управления привилегиями в Unix-подобных системах.

-   **`setuid(uid_t uid)`:** Устанавливает RUID, EUID и SUID процесса в значение `uid`. Если процесс имеет привилегии `root`, он может изменить свой UID на любой другой. Если процесс непривилегированный, он может изменить свой UID только на свой RUID или SUID.
-   **`seteuid(uid_t euid)`:** Изменяет только эффективный идентификатор пользователя (EUID). Это позволяет процессу временно получить или сбросить привилегии.
-   **`setreuid(uid_t ruid, uid_t euid)`:** Позволяет одновременно изменить реальный и эффективный идентификаторы пользователя.

Эти системные вызовы используются программами, которым необходимо временно повысить или понизить свои привилегии для выполнения определённых задач, например, для доступа к защищённым ресурсам или для выполнения действий от имени другого пользователя.
