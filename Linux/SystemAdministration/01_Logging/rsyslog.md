# rsyslog: Традиционная система логирования

`rsyslog` — это мощная и гибкая служба для сбора, обработки и пересылки системных журналов и логов приложений.

## Архитектура и модули

`rsyslog` имеет модульную архитектуру, что позволяет ему быть очень гибким. Основные типы модулей:

-   **Модули ввода (Input Modules, `im`):** Отвечают за сбор информации из различных источников (например, `imuxsock` для локальных сокетов, `imjournal` для `systemd-journald`, `imudp` для приема логов по UDP).
-   **Модули вывода (Output Modules, `om`):** Отвечают за отправку логов в различные места назначения (например, `omfile` для записи в файл, `omfwd` для пересылки на другой сервер).
-   **Модули фильтрации (Filter Modules, `fm`):** Используются для фильтрации сообщений по различным параметрам.
-   **Модули парсинга (Parsing Modules, `pm`):** Предоставляют дополнительные возможности для синтаксического анализа сообщений.

## Конфигурация (`/etc/rsyslog.conf`)

Правила сортировки логов описываются в `/etc/rsyslog.conf` и файлах в директории `/etc/rsyslog.d/`.

**Структура правила:** `источник.приоритет действие`

-   **Источник (Facility):** Категория сообщения (`auth`, `cron`, `kern`, `mail`, `local0-7`).
-   **Приоритет (Severity):** Уровень важности (`debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`). Звездочка `*` означает любой уровень.
-   **Действие (Action):** Куда отправить лог (путь к файлу, `@` для UDP-пересылки, `@@` для TCP).

**Примеры правил:**
```conf
# Все сообщения, связанные с аутентификацией, писать в /var/log/auth.log
auth,authpriv.*         /var/log/auth.log

# Записывать все критические ошибки в отдельные файлы для быстрого доступа
*.emerg                 /var/log/emergency.log
*.alert                 /var/log/alert.log

# Все сообщения, кроме почтовых, писать в /var/log/syslog
# Знак минус перед путем означает асинхронную запись для производительности
mail.none;*.*           -/var/log/syslog
```

### Сжатие логов в реальном времени с `omprog`

Для серверов с интенсивным логированием важно оптимизировать хранение журналов. `rsyslog` поддерживает сжатие логов в реальном времени с использованием модуля `omprog`, который позволяет передавать логи внешней программе.

#### 1. Подготовка

Убедитесь, что `rsyslog` и утилита `gzip` установлены:
```bash
# Для Debian/Ubuntu
sudo apt install rsyslog gzip
```

#### 2. Настройка

**Добавление модуля `omprog`**

Откройте конфигурационный файл `rsyslog` (`/etc/rsyslog.conf`) и добавьте строку для загрузки модуля `omprog`, если она отсутствует:
```
module(load="omprog")
```

**Создание скрипта для сжатия**

Создайте скрипт, который будет получать логи из `stdin` и сжимать их в файл:
```bash
sudo nano /usr/local/bin/compress_logs.sh
```
Содержимое скрипта:
```bash
#!/bin/bash
while read line; do
  echo "$line" | gzip >> /var/log/compressed_logs.gz
done
```
Сделайте скрипт исполняемым:
```bash
sudo chmod +x /usr/local/bin/compress_logs.sh
```

**Настройка `rsyslog` для использования скрипта**

Добавьте в конфигурацию `rsyslog` (например, в `/etc/rsyslog.d/60-compress.conf`) правило, которое будет направлять все логи (`*.*`) в ваш скрипт:
```
action(type="omprog" binary="/usr/local/bin/compress_logs.sh")
```
*Если вы хотите сжимать только определенные логи, измените селектор `*.*` на нужный, например `mail.*`.*

#### 3. Настройка ротации логов

Чтобы сжатый лог не рос бесконечно, настройте его ротацию. Создайте файл `/etc/logrotate.d/compressed_logs` со следующим содержанием:
```
/var/log/compressed_logs.gz {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```

#### 4. Применение изменений

После сохранения всех изменений перезапустите службу `rsyslog`:
```bash
sudo systemctl restart rsyslog
```

#### 5. Проверка

Отправьте тестовое сообщение в лог:
```bash
logger "Это тестовое сообщение для проверки сжатия логов."
```
Убедитесь, что логи сжаты и записаны в `/var/log/compressed_logs.gz`:
```bash
zcat /var/log/compressed_logs.gz
```
Вы должны увидеть ваше тестовое сообщение.

## Настройка удаленного логирования (Centralized Logging)

`rsyslog` позволяет настроить централизованный сбор логов с нескольких машин на один сервер.

#### Настройка сервера (получателя логов)

1.  **Включите прием логов.** В файле `/etc/rsyslog.conf` или в новом файле `/etc/rsyslog.d/50-remote.conf` раскомментируйте или добавьте:
    ```conf
    # Включаем прием логов по UDP
    module(load="imudp")
    input(type="imudp" port="514")

    # Включаем прием логов по TCP
    module(load="imtcp")
    input(type="imtcp" port="514")
    ```
2.  **Создайте шаблон для сохранения.** Чтобы логи с разных хостов не смешивались, используется шаблон, который создает отдельные файлы для каждого хоста.
    ```conf
    # Создаем шаблон: /var/log/remote/HOSTNAME/PROGRAM.log
    template(name="RemoteHostLog" type="string"
             string="/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log")

    # Применяем шаблон ко всем входящим сообщениям
    *.* action(type="omfile" dynaFile="RemoteHostLog")
    ```
3.  **Перезапустите rsyslog и откройте порт в брандмауэре.**
    ```bash
    sudo systemctl restart rsyslog
    # Пример для firewalld
    sudo firewall-cmd --add-port=514/tcp --permanent
    sudo firewall-cmd --add-port=514/udp --permanent
    sudo firewall-cmd --reload
    ```

#### Настройка клиента (отправителя логов)

Чтобы отправить все логи на удаленный сервер, добавьте одну из следующих строк в `/etc/rsyslog.conf` или в новый файл `/etc/rsyslog.d/`, заменив `remote-log-server` на IP вашего сервера.

```conf
# Отправка по UDP (быстро, без гарантии доставки)
*.* @remote-log-server:514

# Отправка по TCP (надежно, с подтверждением доставки)
*.* @@remote-log-server:514
```
После добавления правила перезапустите `rsyslog`:
```bash
sudo systemctl restart rsyslog
```


## Интеграция с `systemd-journald`

В современных системах `rsyslog` часто работает совместно с `systemd-journald`, забирая из него логи для дальнейшей пересылки или обработки. Для этого используется модуль `imjournal`.

1.  **Настройка `rsyslog`:**
    Убедитесь, что в `/etc/rsyslog.conf` или в `/etc/rsyslog.d/` загружается модуль `imjournal`.
    ```conf
    # Загружаем модуль для чтения из journald
    module(load="imjournal")
    ```
2.  **Перезапустите `rsyslog`:**
    ```bash
    sudo systemctl restart rsyslog
    ```

Теперь `rsyslog` будет получать все сообщения из `journald` и обрабатывать их согласно своим правилам, включая отправку на удаленный сервер. Это позволяет сочетать преимущества структурированного локального хранения `journald` с мощными возможностями `rsyslog` по фильтрации и пересылке.
