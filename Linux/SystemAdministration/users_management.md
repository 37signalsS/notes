# Управление пользователями и группами в Linux

## Определения

- **Пользователь (User):** Учетная запись, позволяющая человеку или процессу взаимодействовать с системой. Каждому пользователю присваивается уникальный идентификатор (**UID**).
- **Группа (Group):** Механизм для объединения пользователей с целью предоставления им общих прав доступа. Каждой группе присваивается уникальный идентификатор (**GID**).
- **Суперпользователь (root):** Специальный пользователь с UID 0, обладающий неограниченными правами в системе.
- **Первичная группа (Primary Group):** Основная группа пользователя, которая по умолчанию назначается создаваемым им файлам. У пользователя может быть только одна первичная группа.
- **Дополнительные группы (Supplementary Groups):** Группы, в которые пользователь может быть добавлен для получения дополнительных прав.
- **Системные и обычные пользователи:** В Linux принято соглашение о диапазонах UID.
  - **Системные пользователи (UID < 1000):** Зарезервированы для системных служб и демонов. Создание обычного пользователя в этом диапазоне нарушает конвенцию и может привести к конфликтам.
  - **Обычные пользователи (UID >= 1000):** Предназначены для интерактивного входа людей.

## Базовые концепции

### Файлы конфигурации

- **/etc/passwd:** Содержит основную информацию о пользователях.

    | Поле № | Пример | Описание |
    |---|---|---|
    | 1 | `daemon` | Имя пользователя |
    | 2 | `x` | Пароль (`x` означает, что хэш хранится в `/etc/shadow`) |
    | 3 | `1` | UID (User ID) |
    | 4 | `1` | GID (Group ID) — идентификатор *первичной* группы |
    | 5 | `daemon` | Комментарий (GECOS), часто полное имя |
    | 6 | `/usr/sbin` | Домашняя директория |
    | 7 | `/usr/sbin/nologin` | Оболочка входа (shell), запрещающая вход |

- **/etc/shadow:** Хранит хэши паролей и информацию о сроке их действия. **Доступен для чтения только `root`**.

    | Поле № | Пример | Объяснение |
    |---|---|---|
    | 1 | `magicfun` | Имя пользователя. |
    | 2 | `$6$...` или `!` или `*` | Хэш пароля. Формат: `$id$salt$hashed`. `id` (`6`) указывает на алгоритм (SHA-512), `salt` - соль, `hashed` - сам хэш. `!` или `*` означает, что учетная запись заблокирована. |
    | 3 | `20215` | Дата последней смены пароля (дней с 01.01.1970). |
    | 4 | `0` | Минимальный срок действия пароля (в днях). `0` — можно менять в любое время. |
    | 5 | `99999` | Максимальный срок действия пароля (в днях). |
    | 6 | `7` | Период предупреждения (в днях) до истечения срока действия пароля. |
    | 7 | (пусто) | Период неактивности (в днях), после которого учетная запись будет заблокирована, если пароль истек. |
    | 8 | (пусто) | Дата истечения срока действия учетной записи (дней с 01.01.1970). |
    | 9 | (пусто) | Зарезервировано для будущего использования. |

- **/etc/group:** Определяет группы и их членов.
- **/etc/gshadow:** Хранит защищенную информацию о группах (например, пароли групп, что используется редко).

### Хэширование паролей

Пароли в Linux хранятся не в открытом виде, а как **хэши** — результат работы **односторонней** математической функции. Восстановить пароль из хэша невозможно, можно лишь сравнить хэш введенного пароля с сохраненным.

Когда пользователь вводит пароль, система:

1. Берет введенный пароль.
2. Добавляет к нему **"соль" (salt)** — случайную строку, уникальную для каждого пользователя, которая хранится в открытом виде в `/etc/shadow`.
3. Прогоняет получившуюся строку (пароль + соль) через хэш-функцию (например, SHA-512).
4. Сравнивает полученный хэш с тем, что хранится в `/etc/shadow`.

Использование "соли" — это критически важная мера безопасности. Она гарантирует, что даже если два пользователя выберут одинаковый пароль, их хэши в `/etc/shadow` будут разными. Это делает неэффективными атаки с использованием "радужных таблиц" (заранее вычисленных хэшей для популярных паролей).

### Приватные группы пользователей (User Private Groups, UPG)

При создании нового пользователя (например, `useradd username`) без указания группы автоматически создается группа с таким же именем (`username`). Эта группа становится **первичной** для данного пользователя.

### Централизованное управление (Directory Services)

В крупных инфраструктурах локальное управление пользователями на каждой машине неэффективно. Вместо этого используется централизованная служба каталогов.

#### LDAP (Lightweight Directory Access Protocol)

**Определение:** LDAP (Lightweight Directory Access Protocol) — это протокол доступа к распределённой иерархической базе данных. Он используется для организации централизованного хранения и доступа к информации о пользователях, группах, компьютерах и других сетевых ресурсах.

-   **Принцип работы:** Linux-системы настраиваются так, чтобы запрашивать информацию о пользователях и выполнять аутентификацию через сеть у центрального сервера, такого как **OpenLDAP** или **Microsoft Active Directory**. Протокол использует TCP-порт 389.
-   **Использование:** Применяется для аутентификации пользователей и авторизации доступа к различным сервисам и системам.

-   **Ключевые технологии:**
  - **NSS (Name Service Switch):** Механизм, позволяющий системе получать информацию о пользователях/группах не только из `/etc/passwd`, но и из других источников (например, из сети).
  - **PAM (Pluggable Authentication Modules):** Гибкая система аутентификации, позволяющая подключать различные модули для проверки подлинности. Подробнее см. в [PAM (Pluggable Authentication Modules)](../../Security/pam_overview.md).
  - **SSSD (System Security Services Daemon):** Современный стандартный демон на Linux-клиентах, который подключается к службе каталогов, управляет аутентификацией и **кэширует учетные данные**, позволяя входить в систему даже при отсутствии сети.

## Практические сценарии

### Управление пользователями

#### Создание пользователей (`useradd`, `adduser`)

Настройки по умолчанию для `useradd` можно посмотреть командой `useradd -D` и изменить в файлах `/etc/default/useradd` и `/etc/login.defs`.

- **`adduser`**: интерактивная и более дружелюбная утилита.
- **`useradd`**: низкоуровневая утилита, удобная для скриптов.

```bash
# Интерактивное создание
sudo adduser test-user

# Создание со стандартными параметрами
sudo useradd test-user
```

**Ключевые флаги `useradd`:**

- **-m**: создаёт указанную домашнюю директорию, если она ещё не существует
- **-d /home/test-user**: устанавливает `/home/test-user` в качестве домашней директории
- **-c "Имя Фамилия"**: добавляет комментарий. Например, с именем пользователя
- **-g test**: указывает группу, в которую попадёт пользователь после создания. Можно использовать с GID или именем группы. Указанная группа должна существовать. Используется в сочетании с ключом -N (отменяет автоматическое создание группы с именем пользователя)
- **-G users,wheel**: указывает список дополнительных групп пользователя. Они перечисляются через запятую без пробелов
- **-s /bin/bash**: позволяет настроить доступ к shell. Например: `sudo adduser --shell /bin/sh user3`
- **-r**: создаёт системного пользователя. Используется, когда вам нужно настроить службу на работу из-под конкретного пользователя. По умолчанию данные таких пользователей не вносятся в `/etc/shadow`, для них не создаётся домашняя папка
- **-u**: позволяет указать свой UID, который будет присвоен новому пользователю. В качестве UID указывается положительное целое число. UID должен быть уникален
- **-e 2021-01-01**: указывает дату, до которой аккаунт будет активен. Дата задаётся в формате YYYY-MM-DD
- **-f 3**: указывает количество дней до блокировки пользователя, когда его пароль станет недействителен

Очень важно после создания пользователя настроить для него надёжный пароль.

```bash
sudo passwd test-user
```

#### Изменение пользователей (`usermod`)

Перед изменением данных пользователя рекомендуется убедиться, что он не активен в системе.

```bash
# Проверить запущенные процессы пользователя
pgrep -l -u username
# Проверить, залогинен ли пользователь
pinky username
```

**Ключевые флаги `usermod`:**

- **-l new-name**: Изменить имя пользователя.
- **-d /home/new-dir -m**: Изменить домашнюю директорию и перенести в нее старое содержимое.
- **-c "Комментарий"**: Изменить комментарий.
- **-a -G group**: **Добавить** пользователя в дополнительную группу. **Ключ `-a` (append) обязателен, иначе пользователь будет удален из всех остальных доп. групп!**
- **-g new_group**: Изменить *первичную* группу.
- **-L**: Заблокировать учетную запись.
- **-U**: Разблокировать учетную запись.
- **-s /bin/nologin**: Отключить пользователю возможность входа в систему.
- **-u new_UID**: Изменить UID пользователя.
- **-e YYYY-MM-DD**: Изменить дату истечения срока действия учетной записи.

#### Удаление пользователей (`userdel`)

```bash
# Удалить пользователя вместе с его домашней директорией и почтовым ящиком
sudo userdel -r username

# Принудительное удаление, даже если пользователь активен (использовать с осторожностью!)
sudo userdel -f username
```

### Управление группами

- **Создание группы:**

  ```bash
  sudo groupadd new-group
  # С указанием GID
  sudo groupadd -g 1500 new-group
  # Создание системной группы
  sudo groupadd -r new-sys-group
  ```

- **Изменение группы:**

  ```bash
  # Изменить имя
  sudo groupmod -n new-name old-name
  # Изменить GID
  sudo groupmod -g 1501 new-name
  ```

- **Удаление группы:** (нельзя удалить, если она является первичной для какого-либо пользователя)

  ```bash
  sudo groupdel test-group
  ```

- **Управление членством в группах:**

  ```bash
  # Добавить пользователя в группу (рекомендуемый способ)
  sudo usermod -aG groupname username

  # Удалить пользователя из группы
  sudo gpasswd -d username groupname
  ```

- **Переключение группы в текущей сессии:**

  ```bash
  # Запускает новую оболочку с измененной первичной группой
  newgrp new-group
  ```

### Управление политиками паролей (`chage`)

Команда `chage` (change age) позволяет детально управлять сроком действия паролей и учетных записей.

- **Просмотр текущих политик:** `sudo chage -l username`
- **Установить макс. срок действия пароля (90 дней):** `sudo chage -M 90 username`
- **Заставить сменить пароль при след. входе:** `sudo chage -d 0 username`
- **Установить дату истечения срока действия УЗ:** `sudo chage -E "YYYY-MM-DD" username`
- **Сделать УЗ бессрочной:** `sudo chage -E -1 username`
- **Предупреждать о смене за 7 дней:** `sudo chage -W 7 username`
- **Задать мин. срок между сменами (14 дней):** `sudo chage -m 14 username`

### Мониторинг пользователей

- **`id <username>`**: Выводит UID, GID (первичная группа) и `groups` (все группы).
- `who`: Показывает, кто из пользователей в данный момент вошел в систему.
- `w`: Более подробный вывод, чем у `who`, включая запущенные процессы. Подробнее см. в [w: Кто работает в системе](../../Diagnostics/Processes/w.md).
- `last`: Показывает историю последних входов в систему.

### Перенос пользователей между системами

Этот метод наиболее безопасен при переносе на "чистую" систему, чтобы избежать конфликтов UID/GID.

1. **Создайте резервные копии** на целевой машине.
2. **Скопируйте файлы конфигурации** с исходной машины:

    ```bash
    # На целевой машине
    scp root@source_machine:/etc/{passwd,shadow,group,gshadow} /tmp/
    # После проверки можно переместить в /etc/
    ```

3. **Скопируйте домашние директории**, сохраняя права:

    ```bash
    # На целевой машине
    rsync -avz root@source_machine:/home/ /home/
    ```

## Дополнительная информация

- **Повышение привилегий:** Для выполнения задач с правами `root` используются утилиты `su` и `sudo`. Подробнее см. в [Управлении привилегиями](./privilege_management.md).
- **Безопасность `/etc/shadow`:** Никогда не изменяйте права доступа к файлам `/etc/shadow` и `/etc/gshadow`. Некорректные права могут полностью заблокировать вход в систему или привести к небезопасной конфигурации.
- **Конфликты UID/GID:** При ручном переносе пользователей или редактировании файлов всегда следите за уникальностью UID и GID, чтобы избежать конфликтов, когда два пользователя или группы имеют одинаковый идентификатор.
