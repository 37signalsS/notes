# Управление пользователями и группами в Linux

## Основные концепции

### /etc/passwd

-   `/etc/passwd`: Содержит информацию о пользователях (имя, UID, GID, домашний каталог, оболочка).

| Поле № | Значение | Описание |
| --- | --- | --- |
| 1 | `daemon` | Имя пользователя |
| 2 | `x` | Пароль (обычно `x`, означает, что пароль хранится в `/etc/shadow`) |
| 3 | `1` | UID (user ID) — уникальный идентификатор пользователя |
| 4 | `1` | GID (group ID) — идентификатор основной группы |
| 5 | `daemon` | Полное имя или комментарий |
| 6 | `/usr/sbin` | Домашняя директория (может быть фиктивной) |
| 7 | `/usr/sbin/nologin` | Shell входа — запрещает вход (используется для системных пользователей) |

### /etc/shadow

-   `/etc/shadow`: Хранит хэши паролей пользователей и информацию о сроке их действия. **Этот файл доступен для чтения только `root`**.

| **Поле** | **Значение** | **Объяснение** |
| --- | --- | --- |
| 1 | magicfun | Имя пользователя |
| 2 | ! | **Учётная запись заблокирована** — вход невозможен |
| 3 | 20215 | Последняя смена пароля: день с 1970-01-01 (примерно 2025-04-28) |
| 4 | 0 | Можно сменить пароль сразу |
| 5 | 99999 | Пароль действителен практически бесконечно |
| 6 | 7 | Предупреждать за 7 дней |
| 7-9 | ::: | Не установлены значения неактивности и удаления |

### /etc/group и /etc/gshadow

-   `/etc/group`: Содержит информацию о группах.
-   `/etc/gshadow`: Хранит защищенную информацию о группах (например, пароли групп).

> **ВАЖНО:** Никогда не изменяйте права доступа к файлам `/etc/shadow` и `/etc/gshadow`. Неправильные права (например, предоставление доступа на чтение кому-либо, кроме `root`) могут привести к тому, что система не сможет корректно аутентифицировать пользователя или назначить ему правильные группы при входе. Это может полностью заблокировать вход в систему или привести к тому, что пользователь войдет с сильно урезанными правами.

### Первичная группа (User Private Groups)

1.  **Пользователь всегда состоит в группе:** Каждый пользователь должен состоять как минимум в одной (первичной) группе.
2.  **Автоматическое создание одноименной группы:** При создании нового пользователя (например, командой `useradd username`) без указания дополнительных параметров автоматически создается группа с таким же именем (`username`). Эта группа становится **первичной** для данного пользователя.

### Соглашение о диапазонах UID: системные и пользовательские

Технически, ядро Linux не будет возражать, если вы создадите пользователя с UID 500. Однако, это нарушает общепринятую конвенцию и создает риски безопасности и конфликты с системными пакетами.

- **Системные пользователи:** UID до 1000 (в некоторых дистрибутивах до 500) зарезервированы для системных учетных записей (служб, демонов).
- **Обычные пользователи:** UID от 1000 и выше предназначены для "человеческих" пользователей.

Нарушение этого правила создает систему, которую сложно и опасно администрировать, и может привести к конфликтам с системными пакетами, которые автоматически создают пользователей с предопределенными UID.

## Команды для управления пользователями

### Создание пользователей (`useradd`, `adduser`)

Эта команда имеет ряд настроек по умолчанию, которые задаются с помощью файлов `/etc/default/useradd` и `/etc/login.defs`. Увидеть основные можно с помощью команды:

```bash
useradd -D
```
- **GROUP**: GID группы, в которую пользователь будет добавлен после создания
- **HOME**:	базовый каталог, в котором будет размещена директория пользователя
- **INACTIVE**:	указывает время до блокировки пользователя, когда его пароль станет недействителен. Значение «-1» отключает опцию
- **EXPIRE**:	дата, до которой действителен аккаунт. По умолчанию не установлена — то есть без ограничений
- **SHELL**:	используется для настройки доступа к командной оболочке
- **SKEL**:	содержит путь к директории, в которой хранятся файлы по умолчанию. После создания пользователя они будут автоматически скопированы в его домашнюю папку
- **CREATE_MAIL_SPOOL**:	определяет, нужно ли создать папку для писем этого пользователя в `/var/spool/mail/`

Все эти настройки применяются, если использовать самый простой вариант команды создания пользователя без параметров:

```bash
useradd test-user
# или более интерактивная команда
adduser test-user
```

**Ключевые флаги `useradd`:**
- **-m**:	создаёт указанную домашнюю директорию, если она ещё не существует
- **-d /home/test-user**:	устанавливает `/home/test-user` в качестве домашней директории
- **-c "Имя Фамилия"**:	добавляет комментарий. Например, с именем пользователя
- **-g test**:	указывает группу, в которую попадёт пользователь после создания. Можно использовать с GID или именем группы. Указанная группа должна существовать. Используется в сочетании с ключом -N (отменяет автоматическое создание группы с именем пользователя)
- **-G users,wheel**:	указывает список дополнительных групп пользователя. Они перечисляются через запятую без пробелов
- **-s /bin/bash**:	позволяет настроить доступ к shell. Например: `sudo adduser --shell /bin/sh user3`
- **-r**:	создаёт системного пользователя. Используется, когда вам нужно настроить службу на работу из-под конкретного пользователя. По умолчанию данные таких пользователей не вносятся в `/etc/shadow`, для них не создаётся домашняя папка
- **-u**:	позволяет указать свой UID, который будет присвоен новому пользователю. В качестве UID указывается положительное целое число. UID должен быть уникален
- **-e 2021-01-01**:	указывает дату, до которой аккаунт будет активен. Дата задаётся в формате YYYY-MM-DD
- **-f 3**:	указывает количество дней до блокировки пользователя, когда его пароль станет недействителен

Очень важно после создания пользователя настроить для него надёжный пароль. 
```bash
passwd test-user
```

### Изменение данных пользователей (`usermod`)

Смена настроек для активного пользователя может привести к сбою системы. Поэтому перед изменением данных важно убедиться, что в текущий момент редактируемый пользователь не авторизован, под ним отсутствуют запущенные процессы, редактируемые файлы. Посмотреть список запущенных процессов пользователя `user` можно следующим образом: 

```bash
pgrep -l -u user
```
Проверить, авторизован ли пользователь, можно с помощью уже известной команды:

```bash
pinky user
```
Отредактировать данные существующего пользователя можно с помощью команды `usermod`. По структуре она похожа на предыдущую команду:

```bash
usermod [что поменять] [для какого пользователя]
```
**Ключевые флаги `usermod`:**
- **-l new-name**: меняет имя пользователя.
- **-d /home/new-dir -m**: меняет домашнюю директорию и переносит в нее старые данные.
- **-c "Комментарий"**:	меняет комментарий к пользователю
- **-a -G group**: **добавляет** пользователя в дополнительную группу. Например, `sudo usermod -aG sudo user1` добавит пользователя в группу `sudo`.
- **-L**: блокирует аккаунт.
- **-U**: снимает блокировку.
- **-s /bin/nologin**: отключает пользователю возможность входа в систему. Альтернатива: `sudo chsh -s /bin/sh <имя_пользователя>`.
- **-u new_UID**:	изменяет UID пользователя
- **-e YYYY-MM-DD**:	меняет дату, до которой аккаунт будет активен
- **-f DAYS**:	меняет количество дней до блокировки пользователя, когда его пароль станет недействителен


### Удаление пользователей (`userdel`)

Как и в случае с редактированием, перед удалением пользователя нужно убедиться, что под ним отсутствуют активные процессы.

```bash
userdel [опции] [пользователь]
```
- **-r**:	удаляет домашнюю директорию пользователя и почтовый ящик.
- **-f**:	принудительное удаление, даже если пользователь еще активен. **Использовать с осторожностью!**

## Команды для управления группами

### Создание групп (`groupadd`)
```bash
groupadd new-group
```
- **-g GID**: позволяет назначить свой GID для создаваемой группы.
- **-r**:	создаёт системную группу.

### Редактирование групп (`groupmod`)
```bash
groupmod [опции] [группа]
```
- **-n new-name**: меняет имя группы.
- **-g new-gid**: меняет GID группы.

### Удаление групп (`groupdel`)
Нельзя удалить группу, если она указана в качестве основной для какого-либо пользователя.
```bash
groupdel test-group
```

### Управление членством в группах (`gpasswd`, `usermod`)

- **Добавить пользователя в группу:**
  ```bash
  # Рекомендуемый способ
  usermod -a -G groupname username

  # Альтернативный способ
  gpasswd -a username groupname
  ```

- **Удалить пользователя из группы:**
  ```bash
  gpasswd -d username groupname
  ```

- **Изменить основную (первичную) группу пользователя:**
  ```bash
  usermod -g new_primary_group username
  ```
- **Переключить группу в текущей сессии:**
  ```bash
  newgrp new-group
  ```
  Эта команда позволяет переключить группу пользователя в рамках текущей сессии, а также автоматически добавляет запрошенную группу в список групп пользователя.

## Мониторинг пользователей

-   `who`: Показывает, кто из пользователей **в данный момент** залогинен в системе (онлайн). Читает информацию из файла `/var/run/utmp`.
-   `w`: Более подробный вывод, чем у `who`. Показывает, кто залогинен и **что они делают** (какие процессы запущены).
-   `last`: Показывает историю **последних входов** в систему, читая файл `/var/log/wtmp`. Полезна, чтобы увидеть, кто заходил в систему ранее (оффлайн).
-   `id <имя_пользователя>`: Выводит информацию о пользователе. 
    -   `uid`: User ID.
    -   `gid`: ID **первичной (основной) группы**. У пользователя она одна. Новые файлы по умолчанию создаются с этой группой.
    -   `groups`: Список ID всех групп, в которые входит пользователь (включая первичную и все **втористепенные**).

## Централизованное управление пользователями и доступом

Наиболее эффективным методом является интеграция Linux-систем с централизованной службой каталогов, такой как **FreeIPA**, **Microsoft Active Directory (AD)**, или другим **LDAP-совместимым** решением.

*   **Аутентификация (Authentication):** Выполняется централизованно. При входе пользователя система не проверяет локальный файл `/etc/shadow`, а обращается к службе каталогов (например, через протоколы Kerberos или LDAP) для проверки учетных данных.
*   **Авторизация (Authorization):** Также управляется из центра. Права доступа, членство в группах, и политики (например, правила `sudo`) определяются на сервере и применяются на всех подключенных машинах.

### Ключевые компоненты

1.  **Служба каталогов (Directory Service):**
    *   **FreeIPA:** Комплексное решение с открытым исходным кодом для Linux-сред. Объединяет в себе LDAP, Kerberos, DNS и управление политиками. Идеально для гомогенных Linux-инфраструктур.
    *   **Microsoft Active Directory (AD):** Стандарт для корпоративных Windows-сетей. Системы Linux легко интегрируются с AD, что делает его предпочтительным выбором для гибридных сред.
    *   **OpenLDAP:** Гибкое и мощное решение, но требует значительно больше ручной настройки для достижения того же уровня функциональности, что и FreeIPA или AD.

2.  **Клиентская сторона (Интеграция с Linux):**
    *   **SSSD (System Security Services Daemon):** Современный стандарт для подключения Linux-клиентов к центральным службам идентификации. Ключевое преимущество — **кэширование учетных данных**, что позволяет пользователям входить в систему даже при отсутствии сети (например, на ноутбуках). SSSD работает с FreeIPA, AD, и общими LDAP-серверами.
    *   **NSS (Name Service Switch) и PAM (Pluggable Authentication Modules):** Фундаментальные механизмы Linux, которые делают возможной централизованную аутентификацию. `nsswitch.conf` настраивается для получения информации о пользователях и группах из `sss`, а PAM-модули используют `sss` для проверки подлинности.

## Пароли и безопасность

### Хэширование паролей
**Хэш** — это результат работы **хэш-функции**, математического алгоритма, который преобразует входные данные любого размера в строку фиксированной длины. Этот процесс является **односторонним**, то есть восстановить исходные данные из хэша невозможно.

Ключевые свойства хэш-функции:
1.  **Детерминированность:** Один и тот же ввод всегда даёт один и тот же хэш.
2.  **Фиксированный размер вывода:** Результат (хэш) всегда будет иметь одинаковую длину.
3.  **Необратимость:** Невозможно восстановить исходные данные, зная только их хэш.
4.  **Сопротивление коллизиям:** Практически невозможно найти два разных набора входных данных, которые привели бы к одинаковому хэшу.

В Linux хэши используются для безопасного хранения паролей в файле `/etc/shadow`. Когда пользователь вводит пароль, система вычисляет его хэш и сравнивает с тем, что записан в файле. 

Именно поэтому безопасные системы никогда не предлагают функцию "восстановить пароль", а только "сбросить" или "заменить пароль".

### Автоматическая смена паролей пользователей и управление сроком действия учетных записей (chage)

Команда `chage` (change age) используется для изменения информации о сроке действия пароля пользователя и учетной записи. Это мощный инструмент для системного администратора в управлении безопасностью.

#### Просмотр информации о сроке действия пароля

Чтобы узнать, когда последний раз менялся пароль пользователя, когда он истекает, и другие параметры, используйте команду:
```bash
chage -l username
```
Эта команда отобразит:
*   Дату последней смены пароля.
*   Когда пароль истекает.
*   Сколько дней осталось до истечения.
*   Когда учетная запись истекает (экспайрится).
*   Минимальный и максимальный срок между сменами пароля.

#### Установка срока действия пароля

Чтобы принудительно установить срок действия пароля, например, в 90 дней, используйте опцию `-M` (maximum number of days between password change):
```bash
sudo chage -M 90 username
```
Пользователю потребуется сменить пароль по истечении этого срока.

#### Установка срока действия учетной записи

Для временных учетных записей можно установить дату, после которой учетная запись станет недействительной. Используйте опцию `-E` (expire date). Дата указывается в формате ГГГГ-ММ-ДД.
Например, для установки срока действия на 2 дня вперед:
```bash
sudo chage -E $(date -d "+2 days" +%Y-%m-%d) username
```
Чтобы деактивировать срок действия учетной записи (сделать ее бессрочной), используйте `-E -1`:
```bash
sudo chage -E -1 username
```

#### Установка периода неактивности

Если пользователь не меняет пароль после его истечения, можно установить период неактивности, после которого учетная запись будет заблокирована. Используйте опцию `-I` (inactive after password expiration). Например, 5 дней:
```bash
sudo chage -I 5 username
```
Чтобы снять ограничение на неактивность:
```bash
sudo chage -I -1 username
```

#### Предупреждение о смене пароля

Можно настроить предупреждение для пользователя о скорой необходимости сменить пароль. Используйте опцию `-W` (warning days). Например, за 7 дней:
```bash
sudo chage -W 7 username
```

#### Защита от частой смены паролей

Чтобы предотвратить слишком частую смену паролей (например, если пользователь пытается обойти политику или использует автоматические средства), можно задать минимальный срок между сменами пароля. Используйте опцию `-m` (minimum number of days between password change). Например, 14 дней:
```bash
sudo chage -m 14 username
```
Чтобы убрать ограничение (разрешить смену пароля в любой момент после его установки), используйте `-m 0`:
```bash
sudo chage -m 0 username
```

### Повышение привилегий

Для выполнения задач, требующих прав суперпользователя (`root`), используются утилиты `su` и `sudo`. Подробное их описание находится в заметке по [управлению привилегиями](./privilege_management.md).

## Перенос пользователей и групп между системами

1.  **Скопируйте файлы с исходной машины:**
    Используйте `scp` или `rsync` для копирования файлов на целевую машину.
    ```bash
    # Выполнять на целевой машине или указать путь назначения
    scp root@source_machine:/etc/passwd /etc/passwd
    scp root@source_machine:/etc/shadow /etc/shadow
    scp root@source_machine:/etc/group /etc/group
    ```

2.  **Перенесите домашние директории:**
    Этот метод не переносит домашние каталоги пользователей (`/home/username`). Их необходимо скопировать отдельно.
    ```bash
    # Рекомендуется использовать rsync для сохранения прав
    rsync -avz --progress root@source_machine:/home/ /home/
    ```

**Потенциальные риски**

-   **Конфликты UID/GID:** Этот метод может перезаписать существующих пользователей и группы на целевой машине.
-   **Чистые системы:** Метод наиболее безопасен при переносе на новую, "чистую" систему.
-   **Резервное копирование:** Всегда создавайте резервные копии оригинальных файлов на целевой машине перед их заменой.
