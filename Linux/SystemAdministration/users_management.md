# Управление пользователями и группами в Linux

## Определения

- **Идентификация:** Процесс распознавания субъекта по его идентификатору (имя пользователя, UID).
- **Аутентификация:** Процесс проверки подлинности субъекта (пароль, ключи, биометрия).
- **Авторизация:** Процесс предоставления субъекту определенных прав на выполнение действий в системе (чтение, запись, запуск).
- [**Определения пользователей и групп**](Users/users_definitions.md) — UID/GID, типы пользователей (root, системные, обычные), первичные и дополнительные группы.

## Основные концепции

Система управления доступом в Linux базируется на идентификации субъектов (пользователей) и их принадлежности к группам. Современная архитектура (2025–2026) включает следующие уровни:

- **Конфигурация:** Хранение учетных данных в системных файлах. Подробнее: [Файлы конфигурации](Users/users_config_files.md).
- **Декларативное управление (systemd-sysusers):** Современный стандарт создания системных пользователей и групп через конфигурационные файлы в `/etc/sysusers.d/`. Это заменяет императивные команды в скриптах установки. Подробнее: [systemd-sysusers](Users/systemd-sysusers.md).
- **Диспетчеризация (NSS):** Механизм **Name Service Switch** определяет источники данных. Файл `/etc/nsswitch.conf` задает приоритеты опроса локальных файлов, SSSD или Winbind.
- **Службы кэширования:** Для производительности используются демоны кэширования (`nscd`) или встроенные механизмы SSSD.
- **Схема групп:** Использование механизмов приватных групп. Подробнее: [Приватные группы пользователей (UPG)](Users/user_private_groups.md).
- **Изоляция (User Namespaces):** Механизм ядра для контейнеризации. Подробнее: [Пространства имен (Namespaces)](../Core/namespaces.md).
- **Безопасность паролей:** Хэширование **yescrypt** (стандарт с 2024 года) и защита от перебора через **pam_faillock** (заменил устаревший `pam_tally2`). Подробнее: [Хэширование паролей](Users/password_hashing.md) и [Блокировка учетных записей](Users/password_policy_chage.md).
- **Аутентификация:** Модульная система проверки подлинности. Подробнее: [Обзор PAM](../Security/pam_overview.md).
- **Многофакторная аутентификация (MFA):** Использование TOTP, FIDO2 и TPM2 через модули PAM (`pam_u2f`) и интеграцию с `systemd-homed`.

## Практические сценарии

### 1. Основные операции администрирования

Для управления учетными записями используются стандартные утилиты командной строки:

- [**Команды управления пользователями**](Users/user_commands.md) — `useradd`, `usermod`, `userdel`, `passwd`.
- [**Команды управления группами**](Users/group_commands.md) — `groupadd`, `groupmod`, `groupdel`, `gpasswd`.

**Управление настройками по умолчанию:**
- `/etc/login.defs`: Глобальные лимиты (UID_MIN, PASS_MAX_DAYS).
- `useradd -D`: Просмотр и изменение дефолтных параметров создания (shell, home).
- `/etc/skel/`: Шаблон домашней директории.

### 2. Современные методы управления

В современных инфраструктурах управление смещается в сторону декларативности и аппаратной защиты:

- **Декларативное создание системных пользователей:** Использование `systemd-sysusers`. Конфигурации в `/etc/sysusers.d/*.conf` позволяют автоматически создавать пользователей при загрузке или установке пакетов.
  - Рекомендуется использовать префикс `_` для системных аккаунтов (например, `_nginx`).
- **Декларативное создание (cloud-init):** Использование YAML для облачных сред.
- **Автоматизация через IaC:** Управление пользователями в масштабе через [Ansible](../../Ansible/Modules/ansible_security_and_user_management_modules.md) или [SaltStack](../../SaltStack/User_Creation.md).
- **Управление через systemd-homed:** Использование `homectl`. Домашние директории теперь — это самодостаточные LUKS2-образы, которые могут быть привязаны к FIDO2-токенам или TPM2.

### 3. Мониторинг и аудит

Контроль активности и проверка целостности:

- [**Мониторинг пользователей**](Users/user_monitoring.md) — `who`, `last`, `id`, аудит сессий.
- **Аудит безопасности:**
  - `lastlog`: Последний вход всех пользователей.
  - `faillock`: Просмотр и сброс неудачных попыток входа (заменил `pam_tally2`).
    - `sudo faillock --user <name>` — просмотр попыток.
    - `sudo faillock --user <name> --reset` — разблокировка.
- [**Аудит конфигурационных файлов**](Users/users_config_files.md#аудит-безопасности) — поиск дубликатов UID 0 и пустых паролей.

### 4. Перенос учетных записей

Сценарии миграции пользователей между серверами с сохранением идентификаторов и прав доступа описаны в:

## Дополнительная информация

### Безопасность и делегирование

- **Принцип наименьших привилегий:** Ограничение прав доступа только необходимым набором операций.
- **Управление привилегиями:** Использование `sudo`, `su` и Polkit для повышения прав. Подробнее: [Управление привилегиями](privilege_management.md).
- **Централизация:** Для крупных инфраструктур рекомендуется использование внешних каталогов. Подробнее: [LDAP и SSSD](Users/LDAP_SSSD/index.md).

### Современные подходы

- **systemd-homed:** Механизм, делающий домашние директории переносимыми и самодостаточными. Подробнее: [systemd-homed](Users/systemd-homed.md). Метаданные пользователя хранятся в JSON-записи внутри зашифрованного (LUKS2) образа. Поддерживает разблокировку через FIDO2 и TPM2.
- **Безопасность 2025–2026:**
    - **Passwordless (FIDO2/TPM2):** Полный отказ от паролей в пользу аппаратных токенов для входа и sudo.
    - **MFA для sudo:** Обязательное использование `pam_u2f` для подтверждения административных действий.
    - **Интеграция с TPM2:** Автоматическая разблокировка ключей SSH и домашних директорий через TPM2 при условии целостности загрузки (Secure Boot).
    - **Отказ от RSA:** Использование только **Ed25519**-ключей. Ключи RSA считаются небезопасными и отключаются на уровне системных криптополитик.
    - **Иммутабельность:** В системах типа Fedora Silverblue или NixOS пользователи управляются декларативно, а локальные изменения `/etc/passwd` могут сбрасываться.
