# Резервное копирование и восстановление в Linux

## 1. Определения

**Резервное копирование (Backup)** — процесс создания копий данных для их последующего восстановления в случае потери или повреждения.

**Восстановление (Recovery)** — процесс возврата данных или системы в работоспособное состояние с использованием резервных копий.

**Консистентность данных (Data Consistency)** — свойство данных находиться в непротиворечивом и логически корректном состоянии. Критически важно для резервного копирования.

Ключевые метрики, определяющие требования к процессу восстановления, такие как **RPO (Recovery Point Objective)** и **RTO (Recovery Time Objective)**, подробно описаны в основной заметке о концепциях SRE: **[Концепции SRE: SLA, SLO, SLI и метрики надежности](../../../Concepts/SRE/sre_concepts_main.md)**.

## 2. Базовые концепции: Стратегии резервного копирования

Выбор стратегии резервного копирования зависит от типа системы и требований к восстановлению. Ключевой вопрос — "что именно нужно защищать?", включая не только очевидные данные, но и конфигурации, системные задания (`crontab`) и т.д.

### Виртуальные машины (VMs)

Для виртуальных машин оптимальным решением являются **снапшоты (snapshots)**. Системы виртуализации (VMware, KVM, VirtualBox) позволяют создавать "мгновенные снимки" состояния всей ВМ (диски, память), что является простым и надежным способом получения полной и консистентной резервной копии.

### Физические серверы ("Bare Metal")

На физических серверах нет механизма снапшотов на уровне гипервизора. Основная задача — обеспечить **консистентность данных** без полной остановки системы.

-   **"Холодный" бэкап:** Остановка сервисов или всей системы перед копированием файлов. Гарантирует консистентность, но не всегда приемлем для работающих систем.
-   **"Горячий" бэкап:** Создание консистентной копии без полной остановки. Часто реализуется с помощью технологий, таких как **LVM Snapshots**, или специализированных утилит для конкретных приложений (например, `Percona XtraBackup` для MySQL).
-   **Копирование диска (`dd`):** Создает побайтовую копию диска. Для консистентности требует остановки операций записи на диск, фактически превращаясь в "холодный" бэкап.

## 3. Практические сценарии: Инструменты резервного копирования

### Файловые бэкапы: `rsync`

**Rsync** — мощная утилита для эффективной синхронизации файлов и каталогов, локально и удаленно. Используется для инкрементального копирования (передает только измененные части файлов), что экономит трафик и время.

**Ключевые особенности:**
-   **Инкрементальная синхронизация.**
-   **Удаленная синхронизация:** По SSH или rsync-демон.
-   **Сохранение атрибутов:** Права доступа, владельцы, временные метки.

**Пример использования:**
```bash
rsync -av --progress /path/to/src/ /path/to/dest/
rsync -avz --progress /local/path/ user@server:/remote/path/ # с сжатием
```

### Снимки на уровне хранилища: LVM Snapshots

**LVM (Logical Volume Manager)** — стандартный для Linux инструмент, позволяющий создавать "мгновенные снимки" (snapshots) блочных устройств. Этот механизм используется для получения консистентной копии файловой системы для "горячего" бэкапа без остановки работы приложений.

Подробнее о принципе работы и командах см. в основной заметке: **[LVM Snapshots](../FileSystems/lvm.md#снимки-snapshots)**.

### Создание образов: `genisoimage`

**genisoimage** — инструмент для создания образов файловой системы ISO 9660. Может использоваться для архивации больших объемов данных (например, директорий) в один файл-образ (`.iso`), который затем легко хранить или передавать.

**Пример использования:**
```bash
# Создать ISO-образ 'backup.iso' из содержимого каталога /path/to/data
genisoimage -o backup.iso -r /path/to/data
```

Специализированные решения для резервного копирования баз данных, таких как PostgreSQL, MySQL/MariaDB, рассматриваются в соответствующих разделах: [Резервное копирование баз данных](../../Databases/Concepts/backups.md).
