# Резервное копирование и восстановление в Linux

## Определения

**Резервное копирование (Backup)** — создание копий данных для их последующего восстановления в случае потери или повреждения.
**Восстановление (Recovery)** — возврат данных или системы в работоспособное состояние из резервных копий.
**Консистентность данных (Data Consistency)** — свойство данных находиться в непротиворечивом состоянии. Критически важно для резервного копирования.
Метрики восстановления, такие как **RPO (Recovery Point Objective)** и **RTO (Recovery Time Objective)**, описаны в [Концепции SRE: SLA, SLO, SLI и метрики надежности](../../Concepts/SRE/sre_concepts_main.md).

## Базовые концепции

### Виртуальные машины (VMs)

Оптимальное решение — **снапшоты (snapshots)**. Системы виртуализации (VMware, KVM, VirtualBox) позволяют создавать "мгновенные снимки" состояния ВМ (диски, память), обеспечивая полную и консистентную копию.

### Физические серверы ("Bare Metal")

На физических серверах отсутствует механизм снапшотов гипервизора. Требуется обеспечить консистентность данных без полной остановки системы.

- **"Холодный" бэкап:** Остановка сервисов или системы перед копированием. Гарантирует консистентность, но не всегда подходит для работающих систем.
- **"Горячий" бэкап:** Создание консистентной копии без полной остановки. Реализуется через технологии, например, [LVM Snapshots](../FileSystems/LVM/snapshots.md), или специализированные утилиты (например, `Percona XtraBackup` для MySQL).
- **Копирование диска (`dd`):** Побайтовое копирование диска. Для консистентности требует остановки операций записи, фактически становясь "холодным" бэкапом.

## Практические сценарии

### Файловые бэкапы: `rsync`

**Rsync** — утилита для эффективной синхронизации файлов и каталогов, локально и удаленно. Используется для инкрементального копирования (передает только измененные части файлов).

Подробнее о `rsync`, а также сравнение с `scp` и `sftp`: **[Инструменты командной строки SSH](../Security/ssh/ssh_cli_tools.md)**.

**Особенности:**

- Инкрементальная синхронизация.
- Удаленная синхронизация (по SSH или rsync-демон).
- Сохранение атрибутов (права, владельцы, метки).

**Пример:**

```bash
rsync -av --progress /path/to/src/ /path/to/dest/
rsync -avz --progress /local/path/ user@server:/remote/path/ # с сжатием
```

### Снимки на уровне хранилища: LVM Snapshots

**LVM (Logical Volume Manager)** — стандартный инструмент Linux для создания "мгновенных снимков" (snapshots) блочных устройств. Обеспечивает консистентную копию файловой системы для "горячего" бэкапа. Подробнее в [LVM Snapshots](../FileSystems/LVM/snapshots.md).

### Создание образов: `genisoimage`

**genisoimage** — инструмент для создания образов файловой системы ISO 9660. Применяется для архивации больших объемов данных (директорий) в один файл-образ (`.iso`).

**Пример:**

```bash
# Создать ISO-образ 'backup.iso' из содержимого каталога /path/to/data
genisoimage -o backup.iso -r /path/to/data
```

### Инкрементальные бэкапы: `tar`

Инкрементальный бэкап сохраняет только изменения, сделанные с момента последнего полного или инкрементального бэкапа. Это позволяет значительно экономить дисковое пространство и время резервного копирования.

**Ключевые понятия:**

- **Полный бэкап (Full Backup):** Копирование всех данных при каждом запуске.
- **Инкрементальный бэкап (Incremental Backup):** Копирование только измененных файлов с момента последнего бэкапа.
- **Метаданные (snar-файл):** Файл, в который `tar` записывает состояние файловой системы на момент последнего бэкапа. По ним определяется, какие файлы были изменены.

**Создание полного бэкапа:**

```bash
tar -cvzf /path/to/backup-full.tar.gz -g /path/to/backup.snar /path/to/dir
```

- `-g /path/to/backup.snar` — указывает файл метаданных. Если файла нет, создается полный бэкап и генерируется snar-файл.

**Создание инкрементального бэкапа:**

При повторном запуске с тем же snar-файлом `tar` создаст инкрементальный архив, содержащий только измененные файлы:

```bash
tar -cvzf /path/to/backup-incr-$(date +%Y%m%d).tar.gz -g /path/to/backup.snar /path/to/dir
```

**Восстановление:**

Инкрементальные бэкапы зависят от полного. Для восстановления нужно последовательно распаковать архивы в порядке их создания:

```bash
# 1. Восстановить полный бэкап
tar -xvzf /path/to/backup-full.tar.gz -C /restore/dir

# 2. Восстановить первый инкрементальный
tar -xvzf /path/to/backup-incr-20240101.tar.gz -C /restore/dir

# 3. Восстановить второй инкрементальный
tar -xvzf /path/to/backup-incr-20240102.tar.gz -C /restore/dir
```

**Автоматизация с помощью скрипта:**

Простой скрипт для управления инкрементальными бэкапами может включать:
- Функцию полного бэкапа (full)
- Функцию инкрементального бэкапа (backup)
- Функцию удаления старых бэкапов (delete)
- Логику разделения директорий: `current` (текущие бэкапы) и `old` (архивные полные бэкапы)

Пример логики для cron:
- Ежедневно (понедельник-суббота): инкрементальный бэкап
- Еженедельно (воскресенье): полный бэкап
