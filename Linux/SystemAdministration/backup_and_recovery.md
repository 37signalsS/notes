# Резервное копирование и восстановление в Linux

## Определения

- **Резервное копирование (Backup):** Процесс создания копий данных для их последующего восстановления в случае потери или повреждения.
- **Восстановление (Recovery):** Возврат данных или системы в работоспособное состояние из резервных копий.
- **Консистентность данных (Data Consistency):** Состояние данных, при котором они являются внутренне непротиворечивыми и пригодными для использования приложением.
- **RPO (Recovery Point Objective):** Целевая точка восстановления; максимально допустимый период потери данных.
- **RTO (Recovery Time Objective):** Целевое время восстановления; максимально допустимое время простоя системы.

Общая теория стратегий (правило 3-2-1, типы бэкапов) и метрики надежности подробно описаны в разделах [**Стратегии резервного копирования баз данных**](../../Databases/Concepts/backups.md) и [**Концепции SRE**](../../Concepts/sre_concepts_main.md).

## Основные концепции

### Виртуальные машины (VM)

Для виртуализированных сред (VMware, KVM, VirtualBox) основным методом защиты является создание **снимков (snapshots)**. Снимок фиксирует состояние дисков и (опционально) оперативной памяти, что позволяет мгновенно откатить всю ОС к контрольной точке.

### Физические серверы (Bare Metal)

При отсутствии гипервизора задача создания консистентной копии решается на уровне ОС или приложения:

- **Холодный бэкап:** Полная остановка сервисов. Гарантирует 100% консистентность, но создает простой (downtime).
- **Горячий бэкап:** Копирование на работающей системе. Методы:
  - **[Снимки LVM](../FileSystems/LVM/snapshots.md):** Создание "мгновенного снимка" на уровне блочного устройства.
  - **Специализированные утилиты:** Инструменты типа **Percona XtraBackup** (для MySQL), которые умеют согласовывать данные "на лету".
- **Клонирование диска:** Побайтовое копирование всего накопителя.

## Практические сценарии

### 1. Инкрементальное архивирование через tar

Утилита `tar` поддерживает инкрементальное архивирование с использованием файла метаданных (`snar`), где хранится состояние файловой системы на момент прошлого запуска.

**Создание полного бэкапа:**

```bash
# -g указывает на файл метаданных. Если его нет, tar создаст его и сделает полный бэкап.
tar -cvzf backup-full.tar.gz -g backup.snar /home/user/data
```

**Создание инкрементального бэкапа:**

```bash
tar -cvzf backup-incr-$(date +%Y%m%d).tar.gz -g backup.snar /home/user/data
```

### 2. Синхронизация данных через rsync

`rsync` — стандартный инструмент для зеркалирования директорий и инкрементальной передачи данных по сети (SSH).
Подробное руководство: [**rsync — синхронизация файлов**](./rsync.md).

### 3. Создание ISO-образов (xorriso)

В современных дистрибутивах вместо устаревшего `genisoimage` рекомендуется использовать `xorriso`, так как он лучше поддерживает современные стандарты (UEFI, гибридные образы).

```bash
# Создание ISO-образа
xorriso -as mkisofs -o backup.iso -R -J /path/to/source_data
```

### 4. Снимки LVM для консистентного копирования

Позволяет "заморозить" состояние тома и скопировать его как обычные файлы, пока система продолжает запись в основной том. Процедура:
1. Создание снимка (`lvcreate -s`).
2. Монтирование снимка.
3. Копирование данных.
4. Размонтирование и удаление снимка.

Полная процедура описана в разделе [**LVM — снимки**](../FileSystems/LVM/snapshots.md).

### 5. Поблочное копирование (dd)

Для клонирования дисков целиком. Рекомендуется использовать `pv` для мониторинга прогресса и `gzip` для сжатия "на лету".

```bash
# Создание сжатого образа диска с индикатором прогресса
sudo dd if=/dev/sda conv=sync,noerror bs=64K | pv | gzip -c > /path/to/backup/sda.img.gz

# Восстановление
gunzip -c sda.img.gz | pv | sudo dd of=/dev/sdb bs=64K
```
Подробности в [**Утилита dd**](../FileSystems/dd.md).

## Современные инструменты и подходы

### Bare Metal Recovery (ReaR и Clonezilla)

Для восстановления системы "с нуля" на голом железе используются специализированные решения:

- **Relax-and-Recover (ReaR):** Де-факто стандарт в Enterprise-сегменте Linux. Создает загрузочный ISO-образ с инструментами восстановления и скриптами для автоматического развертывания данных из бэкапа (Borg, TSM, NFS и др.).
- **Clonezilla:** Популярный инструмент для клонирования дисков и разделов. Поддерживает multicast-рассылку образов для массового развертывания.

### Снимки на уровне файловой системы (ZFS и Btrfs)

Современные ФС поддерживают мгновенные снимки с минимальными накладными расходами и возможность передачи дельты изменений (`send/receive`):

```bash
# Пример Btrfs
btrfs subvolume snapshot -r / /snapshots/root_backup
btrfs send /snapshots/root_backup | ssh remote_server btrfs receive /mnt/backups/
```

### Дедупликация и облака

При больших объемах данных рекомендуется использовать инструменты с чанковой дедупликацией, сжатием и шифрованием.

| Инструмент | Тип | Особенности |
| :--- | :--- | :--- |
| **BorgBackup** | Локальный/SSH | Очень высокая скорость, эффективная дедупликация. |
| **Restic** | Облачный | Нативная поддержка S3, Azure, GCS. Безсерверная архитектура. |
| **Veeam Agent** | Hybrid | Удобный UI/CLI, хорошая поддержка Bare Metal в бесплатной версии. |
| **Timeshift** | Desktop | Создание "точек восстановления" (снимков) ОС для быстрого отката. |

### Автоматизация: Cron и Systemd Timers

Для запуска бэкапов по расписанию в Linux используются:
- [**Cron**](./cron.md): Классический планировщик.
- **Systemd Timers:** Современная альтернатива. Позволяет задавать зависимости, лимиты ресурсов и мониторить статус выполнения через `systemctl`.
