# Резервное копирование и восстановление в Linux

## Определения

- **Резервное копирование (Backup):** Процесс создания копий данных для их последующего восстановления в случае потери или повреждения.
- **Восстановление (Recovery):** Возврат данных или системы в работоспособное состояние из резервных копий.
- **Консистентность данных (Data Consistency):** Состояние данных, при котором они являются внутренне непротиворечивыми и пригодными для использования приложением (особенно критично для БД).
- **RPO (Recovery Point Objective):** Максимально допустимый период потери данных.
- **RTO (Recovery Time Objective):** Максимально допустимое время восстановления системы.

Общая теория стратегий (правило 3-2-1, типы бэкапов) и метрики надежности подробно описаны в разделах [Стратегии резервного копирования](../../Databases/Concepts/backups.md) и [Концепции SRE](../../Concepts/sre_concepts_main.md).

## Основные концепции

### Виртуальные машины (VMs)

Для виртуализированных сред (VMware, KVM, VirtualBox) основным методом защиты является создание **снапшотов (snapshots)**. Снапшот фиксирует состояние дисков и (опционально) оперативной памяти, что позволяет мгновенно откатить всю ОС к контрольной точке.

### Физические серверы (Bare Metal)

При отсутствии гипервизора задача создания консистентной копии решается на уровне ОС или приложения:

- **Холодный бэкап:** Полная остановка сервисов. Гарантирует 100% консистентность, но создает простой (downtime).
- **Горячий бэкап:** Копирование на работающей системе. Методы:
  - **[Снапшоты LVM](../FileSystems/LVM/snapshots.md):** Создание "мгновенного снимка" на уровне блочного устройства.
  - **Специализированные утилиты:** Инструменты типа Percona XtraBackup (для MySQL), которые умеют согласовывать данные "на лету".
- **Клонирование диска (dd):** Побайтовое копирование всего накопителя. Обычно требует остановки записи для предотвращения порчи данных в образе.

## Практические сценарии

### 1. Инкрементальные бэкапы через `tar`

Утилита `tar` поддерживает инкрементальное архивирование с использованием файла метаданных (`snar`), где хранится состояние файловой системы на момент прошлого запуска.

**Создание полного бэкапа:**

```bash
# -g указывает на файл метаданных. Если его нет, tar создаст его и сделает полный бэкап.
tar -cvzf backup-full.tar.gz -g backup.snar /home/user/data
```

**Создание инкрементального бэкапа:**
При повторном использовании того же `snar`-файла `tar` сохранит в архив только новые или измененные файлы:

```bash
tar -cvzf backup-incr-$(date +%Y%m%d).tar.gz -g backup.snar /home/user/data
```

**Восстановление:**
Для восстановления необходимо последовательно распаковать полный архив, а затем все инкрементальные в хронологическом порядке.

### 2. Синхронизация файлов через `rsync`

`rsync` — стандартный инструмент для зеркалирования директорий и инкрементальной передачи данных по сети (SSH). Он передает только измененные части файлов (дельта-кодирование).
Подробное руководство: [**rsync — синхронизация файлов**](./rsync.md).

### 3. Создание ISO-образов

Для архивации данных в формат ISO 9660 (для записи на оптические диски или монтирования как виртуальных медиа) используется `genisoimage`.

```bash
# -o имя образа, -r сохранение прав доступа (Rock Ridge)
genisoimage -o backup.iso -r /path/to/source_data
```

### 4. Консистентный бэкап через LVM Snapshots

Позволяет "заморозить" состояние тома и скопировать его как обычные файлы, пока система продолжает запись в основной том.
Полная процедура описана в разделе [**LVM — снимки**](../FileSystems/LVM/snapshots.md).

## Дополнительная информация

### Современные инструменты с дедупликацией

При больших объемах данных рекомендуется использовать инструменты с встроенной дедупликацией на стороне клиента, сжатием и шифрованием.

| Инструмент | Тип | Основные преимущества |
| :--- | :--- | :--- |
| **BorgBackup** | Чанковая дедупликация | Очень высокая скорость, эффективное сжатие, работа по SSH. |
| **Restic** | Облачно-ориентированный | Нативная поддержка S3, Azure, GCS. Простая установка (один бинарник). |
| **Bacula / Bareos** | Enterprise | Сложные политики, поддержка ленточных библиотек, клиент-серверная модель. |

### Пример быстрого старта с BorgBackup

```bash
# Инициализация репозитория
borg init --encryption=repokey /path/to/backups/repo

# Создание архива (бэкапа)
borg create /path/to/backups/repo::Monday-$(date +%H%M) /etc /var/www

# Очистка старых бэкапов (оставить 7 дневных и 4 еженедельных)
borg prune --keep-daily=7 --keep-weekly=4 /path/to/backups/repo
```
