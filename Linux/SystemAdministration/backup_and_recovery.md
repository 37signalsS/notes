# Резервное копирование и восстановление в Linux

## Стратегии и подходы к резервному копированию

Прежде чем выбирать конкретный инструмент, важно определить стратегию резервного копирования. Самый сложный вопрос в резервном копировании — не "как делать", а "**что** делать".

Недооценка того, какие данные являются критичными, может привести к их потере. Классический пример — файл `crontab`. Команды `crontab -e` (редактировать) и `crontab -r` (удалить) расположены на клавиатуре рядом. Случайное нажатие `crontab -r` мгновенно и без подтверждения удаляет все запланированные задания пользователя. Если резервной копии этого файла нет, восстановить его будет невозможно. Это иллюстрирует важность анализа системы и определения всех компонентов, требующих защиты: не только очевидные базы данных и пользовательские файлы, но и конфигурации, скрипты и системные задания.

Выбор основного подхода зависит от типа системы:

1.  **Виртуальные машины (VMs):**
    *   **Снапшоты (Snapshots)** являются оптимальным решением. Хостинг-провайдеры и системы виртуализации (VMware, KVM, VirtualBox) позволяют создавать "мгновенные снимки" состояния всей машины, включая диски и память. Это самый простой и надежный способ получить полную, консистентную резервную копию ВМ.

2.  **Физические серверы ("Bare Metal"):**
    *   Здесь нет простого механизма снапшотов на уровне гипервизора. Основная задача — обеспечить **консистентность данных**, то есть гарантировать, что данные не изменятся в процессе их копирования.
    *   **"Холодный" бэкап:** Самый простой способ — остановить сервисы или всю систему и скопировать файлы. Не всегда приемлем для работающих систем.
    *   **"Горячий" бэкап:** Используются технологии, позволяющие создать консистентную копию без полной остановки. Ключевую роль здесь играют **LVM Snapshots** или специализированные утилиты для конкретных приложений (например, `Percona XtraBackup` для MySQL).
    *   **Копирование диска (`dd`):** Можно создать полную побайтовую копию диска, но для обеспечения консистентности необходимо остановить все операции записи на этот диск на время копирования, что фактически превращает этот метод в "холодный" бэкап.

## Инструменты для создания образов

### genisoimage

**genisoimage** — это инструмент командной строки для создания образов файловой системы ISO 9660. Хотя его основное предназначение — создание загрузочных CD/DVD-ROM, его можно использовать для архивации больших объемов данных в один файл-образ (`.iso`).

Это может быть полезно для создания резервной копии состояния системы или набора файлов, которые затем можно легко хранить или передавать.

**Ключевые особенности:**
- Создает стандартные ISO-образы, совместимые с большинством систем.
- Используется для создания загрузочных дисков.
- Подходит для архивации больших каталогов в один файл.

**Пример использования:**
```bash
# Создать ISO-образ 'backup.iso' из содержимого каталога /path/to/data
genisoimage -o backup.iso -r /path/to/data
```
*Опция `-r` устанавливает корректные права доступа для файлов.*

## Файловые бэкапы

### rsync

**Rsync** — это мощная утилита для быстрой и эффективной синхронизации файлов и каталогов, как локально, так и между удаленными хостами. Передача файлов и синхронизация каталогов — одна из распространенных операций, которая часто осуществляется в автоматическом режиме (например, для создания резервных копий или совместной обработки проектов). Rsync широко используется для создания резервных копий, миграции данных и поддержания актуальности файлов между различными системами. Rsync способна поддерживать коннект по зашифрованным каналам SSH и SSL.

**Ключевые особенности:**
-   **Инкрементальная синхронизация:** Передает только измененные части файлов, что значительно экономит трафик и время.
-   **Удаленная синхронизация:** Работает по сети, используя протоколы SSH или rsync-демон.
-   **Сохранение атрибутов:** Может сохранять права доступа, владельца, группы, временные метки и символические ссылки.
-   **Гибкость:** Множество опций для тонкой настройки поведения.

**Базовая команда:**
```bash
rsync -av --progress /path/to/src/ /path/to/dest/
```
-   `-a` — архивный режим. Сохраняет права, временные метки, символические ссылки.
-   `-v` — подробный вывод.
-   `--progress` — показывает прогресс для каждого файла.

Если Вы копируете по сети на удалённый сервер, добавьте флаг `-z` для сжатия:
```bash
rsync -avz --progress /local/path/ user@server:/remote/path/
```
Если копирование прервалось, просто запустите ту же команду ещё раз — `rsync` пропустит уже скопированные файлы и продолжит с того же места.

## Снимки файловой системы (Snapshots)

### LVM Snapshots

**LVM (Logical Volume Manager)** позволяет создавать "снимки" (snapshots) логических томов. Снапшот LVM — это консистентная копия тома в определенный момент времени, созданная по принципу **Copy-on-Write (CoW)**.

**Как это работает:**
1.  При создании снапшота создается новый логический том, который хранит не всю копию данных, а только те блоки, которые были изменены в оригинальном томе *после* создания снапшота.
2.  Оригинальный том остается доступным для записи и чтения.
3.  Резервное копирование производится с этого снапшота, который представляет собой "замороженное" состояние данных. Это позволяет получить консистентный бэкап, не останавливая работу сервисов на основном томе.

Это ключевая технология для создания "горячих" резервных копий на физических серверах, где нет возможности использовать снапшоты на уровне гипервизора.
