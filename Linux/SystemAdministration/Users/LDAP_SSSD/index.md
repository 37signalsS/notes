# Централизованное управление пользователями (LDAP, SSSD)

## Определения

- **LDAP (Lightweight Directory Access Protocol)** — сетевой протокол для доступа к распределенной иерархической базе данных (каталогу). Является отраслевым стандартом для хранения учетных записей и прав доступа.
- **SSSD (System Security Services Daemon)** — системный демон, обеспечивающий доступ локальной ОС к удаленным провайдерам идентификации (LDAP, AD, FreeIPA). Поддерживает кэширование, работу в offline-режиме и интеграцию с Kerberos.
- **NSS (Name Service Switch)** — системный механизм Linux, определяющий порядок поиска данных (пользователи, группы, хосты) в различных базах данных (файлы, SSSD, DNS).
- **PAM (Pluggable Authentication Modules)** — модульная архитектура Linux для управления аутентификацией приложений (sshd, login, su).
- **IdM (Identity Management)** — комплексные решения для управления жизненным циклом учетных данных (например, FreeIPA или Red Hat IdM).
- **Kerberos** — протокол сетевой аутентификации, обеспечивающий безопасную передачу учетных данных и реализацию механизмов Single Sign-On (SSO).

## Базовые концепции

### Архитектура SSSD

SSSD выступает посредником между системными вызовами ОС и внешними серверами каталогов. Его работа строится на взаимодействии нескольких провайдеров внутри одного домена:

1.  **id_provider**: Получение метаданных (UID, GID, домашняя папка, shell).
2.  **auth_provider**: Проверка подлинности (пароль или Kerberos тикет).
3.  **access_provider**: Управление доступом (разрешено ли пользователю X войти на этот хост).
4.  **chpass_provider**: Механизм смены пароля.

#### Схема прохождения запроса

```text
[ Приложение ]  -->  [ PAM (pam_sss) ]  --\
                                           --> [ SSSD (Daemon) ] --> [ LDAP/AD/IPA ]
[ Команда id ]  -->  [ NSS (nss_sss) ]  --/           |
                                               [ Local Cache (LDB) ]
```

### Ключевые компоненты интеграции

| Компонент | Файл / Механизм | Роль |
| :--- | :--- | :--- |
| **Локальные файлы** | `/etc/passwd`, `/etc/group` | Первичный источник данных для системных аккаунтов. |
| **Диспетчер NSS** | `/etc/nsswitch.conf` | Определяет приоритет: `passwd: files sss`. |
| **Конфигурация SSSD** | `/etc/sssd/sssd.conf` | Описание доменов, URIs серверов и параметров кэширования. |
| **Библиотеки NSS/PAM** | `libnss_sss.so`, `pam_sss.so` | Интерфейсы взаимодействия ОС с демоном SSSD. |

### Преимущества использования SSSD (2025–2026)

- **Нативное кэширование**: Позволяет входить в систему при обрыве связи с контроллером домена.
- **Интеграция с Active Directory**: Нативная поддержка провайдера `ad` с автоматическим маппингом SID в UID/GID.
- **Снижение нагрузки**: Уменьшает количество запросов к LDAP-серверу за счет локальной базы LDB.
- **Безопасность**: SSSD управляет защищенными соединениями (LDAPS/StartTLS) и Keytab-файлами Kerberos централизованно.

## Практические сценарии

### Выбор решения IdM

| Решение | Когда выбирать | Особенности |
| :--- | :--- | :--- |
| **OpenLDAP / 389DS** | Базовая централизация. | Гибкость схем, но требует ручной настройки Kerberos и политик. |
| **FreeIPA (IdM)** | Рекомендуется для Linux-окружений. | LDAP + Kerberos + DNS + CA + sudo-политики «из коробки». |
| **Active Directory** | Гетерогенные сети (Windows + Linux). | Интеграция через провайдер `ad` в SSSD с использованием `realmd`. |

Для настройки и администрирования используйте следующие разделы:

### Инструменты управления

- **`realmd`**: Утилита для упрощенного поиска доменов и автоматической настройки SSSD/Kerberos.
- **`sssctl`**: Современный интерфейс для инспекции состояния SSSD (онлайн-статус доменов, проверка кэша).
- **`adcli`**: Низкоуровневая утилита для манипуляций с учетными записями компьютеров в AD.

## Дополнительная информация

### Безопасность и соответствие

- **Шифрование**: Использование LDAPS (порт 636) или StartTLS (порт 389) является обязательным требованием. Передача паролей по открытому LDAP запрещена.
- **Kerberos (GSSAPI)**: Рекомендуется использовать аутентификацию по билетам (SSO) для доступа по SSH, что исключает необходимость ввода пароля на каждом хосте.
- **ID Mapping**: При интеграции с AD убедитесь, что схема маппинга SID в UID консистентна на всех серверах кластера для корректной работы NFS.
