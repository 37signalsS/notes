# Централизованное управление пользователями (LDAP, SSSD)

## Определения

- **LDAP** (Lightweight Directory Access Protocol) — протокол доступа к распределённой иерархической базе данных (каталогу), используемый для хранения учетных записей.
- **SSSD** (System Security Services Daemon) — системная служба для подключения к внешним каталогам с поддержкой кэширования и офлайн-аутентификации.
- **NSS** (Name Service Switch) — механизм операционной системы для получения информации о пользователях, группах и хостах из различных источников.
- **PAM** (Pluggable Authentication Modules) — модульная система в Linux для гибкой настройки механизмов аутентификации приложений.
- **AD** (Active Directory) — реализация службы каталогов от Microsoft, часто используемая как источник данных для SSSD.
- **TLS** (Transport Layer Security) — протокол защиты сетевых соединений, обязательный для обеспечения безопасности передачи паролей в LDAP.

## Базовые понятия

### Архитектура интеграции

Взаимодействие компонентов при запросе данных пользователя (например, командой `id` или при входе по SSH):

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  Приложение │ →  │     PAM     │ →  │   pam_sss   │ ────┐
│  (sshd, su) │    │ (Аутентиф.) │    │   (Модуль)  │     │
└─────────────┘    └─────────────┘    └─────────────┘     │
                                                          ↓
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  Команда    │ →  │     NSS     │ →  │   nss_sss   │ →  │    SSSD     │
│  (id, ls)   │    │  (Данные)   │    │   (Модуль)  │    │ (Кэш/Логика)│
└─────────────┘    └─────────────┘    └─────────────┘    └──────┬──────┘
                                                                │
                                                         ┌──────┴──────┐
                                                         │ LDAP Server │
                                                         │(389DS/AD/IPA)│
                                                         └─────────────┘
```

### Ключевые компоненты

| Компонент | Роль в системе | Особенности |
| :--- | :--- | :--- |
| **LDAP** | Источник истины | Хранит записи пользователей, групп, UID (User Identifier) и GID (Group Identifier) |
| **SSSD** | Посредник | Выполняет основные запросы, управляет очередями и обеспечивает работу при обрыве связи |
| **NSS** | Диспетчер данных | Настраивается через `/etc/nsswitch.conf`, определяет порядок поиска данных (files → sss) |
| **PAM** | Диспетчер доступа | Настраивается через `/etc/pam.d/`, подключает `pam_sss.so` для проверки паролей |

### Преимущества SSSD перед устаревшим nss-pam-ldapd

1. **Кэширование учётных данных:** пользователи могут входить в систему, даже если LDAP-сервер временно недоступен.
2. **Производительность:** уменьшение нагрузки на сеть и сервер каталогов за счёт локального хранения часто запрашиваемых данных.
3. **Множественные домены:** возможность одновременного подключения к нескольким разным LDAP-серверам или лесам AD.
4. **Безопасность:** SSSD работает от лица отдельного пользователя и безопасно управляет секретами в памяти.

## Практические сценарии

### Навигация по детальным руководствам

Интеграция LDAP/SSSD разделена на функциональные части для удобства администрирования:

- **Развертывание и конфигурация:** установка пакетов, настройка TLS-шифрования, создание файла `sssd.conf` и активация профилей NSS/PAM: [configuration.md](./configuration.md)
- **Администрирование и отладка:** инструменты диагностики (`sssctl`), решение типичных проблем со связью, очистка кэша и особенности работы с Active Directory: [operations.md](./operations.md)

### Когда выбирать SSSD

- Необходимо интегрировать Linux-серверы в существующий домен Active Directory.
- Требуется обеспечить доступ пользователям на удалённых объектах с нестабильным каналом связи.
- Нужна централизация управления UID/GID для корректной работы сетевых файловых систем (NFS).
