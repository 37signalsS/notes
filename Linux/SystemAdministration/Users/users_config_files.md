# Файлы конфигурации пользователей и групп

## Определения

- **`/etc/passwd`** — основная база данных пользователей (читаем всеми)
- **`/etc/shadow`** — хэши паролей и политики (только root)
- **`/etc/group`** — определения групп (читаем всеми)
- **`/etc/gshadow`** — защищённая информация о группах (только root)
- **`/etc/skel`** — шаблон домашней директории нового пользователя

## Базовые концепции

### Формат записей

Файлы используют формат `:`-разделённых полей. Каждая строка — одна запись.

## Практические сценарии

### /etc/passwd

Содержит основную информацию о пользователях. Доступен для чтения всем.

**Формат:** `username:password:UID:GID:GECOS:home_directory:shell`

| Поле | Пример | Описание |
| :--- | :--- | :--- |
| 1 | `daemon` | Имя пользователя |
| 2 | `x` | Пароль (`x` = хэш в `/etc/shadow`) |
| 3 | `1` | UID (User ID) |
| 4 | `1` | GID (Group ID) — первичная группа |
| 5 | `daemon` | GECOS — комментарий (полное имя) |
| 6 | `/usr/sbin` | Домашняя директория |
| 7 | `/usr/sbin/nologin` | Shell для входа |

**Оболочки для блокировки входа:**

| Shell | Описание |
| :--- | :--- |
| `/sbin/nologin` | Выводит сообщение о запрете входа (настраивается в `/etc/nologin.txt`) |
| `/bin/false` | Возвращает ошибку, не выводя сообщения |
| `/usr/sbin/nologin` | Аналогично `/sbin/nologin` (предпочтительно в Debian/Ubuntu) |

**Примеры использования:**

```bash
# Просмотр всех пользователей
cat /etc/passwd

# Поиск конкретного пользователя
grep username /etc/passwd

# Извлечь только имена пользователей
cut -d: -f1 /etc/passwd

# Обычные пользователи (UID >= 1000)
awk -F: '$3 >= 1000 {print $1, $7}' /etc/passwd

# Пользователи с возможностью входа (не nologin/false)
grep -v nologin /etc/passwd | grep -v false
```

### Добавление пользователя вручную (без useradd/adduser)

В экстренных ситуациях или при глубокой отладке пользователя можно добавить, редактируя файлы конфигурации напрямую.

**Шаги для добавления пользователя:**

1. **Определить UID и GID:** Выбрать свободные ID (обычно >= 1000).
2. **Добавить запись в `/etc/passwd`:**

    ```bash
    echo "newuser:x:1001:1001:New User:/home/newuser:/bin/bash" | sudo tee -a /etc/passwd
    ```

3. **Добавить запись в `/etc/group`:**

    ```bash
    echo "newuser:x:1001:" | sudo tee -a /etc/group
    ```

4. **Добавить запись в `/etc/shadow`:**
    Хэш можно сгенерировать через `openssl passwd -6`.

    ```bash
    echo "newuser:*:19000:0:99999:7:::" | sudo tee -a /etc/shadow
    ```

    (Символ `*` заблокирует вход до установки пароля через `passwd`).
5. **Создать домашнюю директорию и установить права:**

    ```bash
    sudo mkdir /home/newuser
    sudo cp -r /etc/skel/. /home/newuser/
    sudo chown -R 1001:1001 /home/newuser
    sudo chmod -R 700 /home/newuser
    ```

6. **Установить пароль:** `sudo passwd newuser`.

### /etc/shadow

Хранит хэши паролей и информацию о сроке их действия. **Доступен только root**.

**Формат:** `username:password:last_change:min:max:warn:inactive:expire:reserved`

| Поле | Пример | Описание |
| :--- | :--- | :--- |
| 1 | `magicfun` | Имя пользователя |
| 2 | `$6$...` | Хэш пароля или `!`/`*` (заблокирован) |
| 3 | `20215` | Дней с 01.01.1970 до последней смены пароля |
| 4 | `0` | Мин. срок между сменами пароля (дни) |
| 5 | `99999` | Макс. срок действия пароля (дни) |
| 6 | `7` | Дней предупреждения до истечения |
| 7 | (пусто) | Дней неактивности до блокировки |
| 8 | (пусто) | Дата истечения учётной записи |
| 9 | (пусто) | Зарезервировано |

**Формат хэша:** `$id$salt$hashed`. Подробнее о механизме хэширования — [password_hashing.md](./password_hashing.md).

| id | Алгоритм |
| :--- | :--- |
| `1` | MD5 |
| `2a` | Blowfish |
| `5` | SHA-256 |
| `6` | SHA-512 (современный стандарт) |
| `yescrypt` | Yescrypt (новый стандарт в Debian 11+) |

**Примеры использования:**

```bash
# Просмотр shadow (только root!)
sudo cat /etc/shadow

# Проверка заблокированных пользователей (! или *)
sudo grep ':!:' /etc/shadow
sudo grep ':\*:' /etc/shadow

# Пользователи без пароля (пустое поле)
sudo awk -F: '($2 == "") {print $1}' /etc/shadow

# Пользователи с бессрочным паролем (99999)
sudo awk -F: '($5 == 99999) {print $1}' /etc/shadow
```

### /etc/group

Определяет группы и их членов. Настройка сроков действия паролей выполняется через `chage` — [password_policy_chage.md](./password_policy_chage.md).

**Формат:** `group_name:password:GID:user_list`

| Поле | Пример | Описание |
| :--- | :--- | :--- |
| 1 | `sudo` | Имя группы |
| 2 | `x` | Пароль группы (редко используется) |
| 3 | `27` | GID (Group ID) |
| 4 | `user1,user2` | Список членов (через запятую) |

**Примеры использования:**

```bash
# Просмотр всех групп
cat /etc/group

# Поиск группы
grep sudo /etc/group

# Все группы с участниками
awk -F: '($4 != "") {print $1, $4}' /etc/group

# Группы конкретного пользователя
groups username
```

### /etc/gshadow

Хранит защищённую информацию о группах (пароли групп, администраторы). Используется редко.

**Формат:** `group_name:password:admins:members`

### /etc/skel

Содержит шаблоны файлов для домашней директории нового пользователя. Базовые определения UID/GID/UPG описаны в [users_definitions.md](./users_definitions.md).

```bash
# Просмотр содержимого
ls -la /etc/skel

# Типовое содержимое:
# .bashrc    - настройки bash
# .profile   - профиль окружения
# .bash_logout - действия при выходе
```

**Добавление своих шаблонов:**

```bash
# Копирование файла в скелет
sudo cp my_custom_config /etc/skel/

# Файлы будут скопированы при создании нового пользователя
sudo useradd -m newuser
```

## Лучшие практики

### Безопасность файлов и Векторы атак

**Эскалация привилегий через `/etc/passwd`:**
Изначально хэши паролей хранились непосредственно в `/etc/passwd`, доступном всем на чтение. Позже их вынесли в `/etc/shadow`. Однако Linux по-прежнему поддерживает старый формат.
Если файл `/etc/passwd` по ошибке имеет права на запись для непривилегированных пользователей (`chmod 666` или `777`), злоумышленник может дописать в него нового пользователя с UID 0 (root) и своим хэшем пароля, что приведет к немедленной эскалации привилегий:

```bash
# Пример вредоносной строки, добавляющей пользователя hacker с правами root
hacker:$6$...hash...:0:0:root:/root:/bin/bash
```

```bash
# Проверка прав на passwd (строго должен быть 644)
ls -l /etc/passwd
chmod 644 /etc/passwd

# Проверка прав на shadow (должен быть 640 или 600)
ls -l /etc/shadow
chmod 640 /etc/shadow
chown root:shadow /etc/shadow

# Проверка прав на group (должен быть 644)
ls -l /etc/group
chmod 644 /etc/group

# Проверка прав на gshadow (должен быть 640)
ls -l /etc/gshadow
chmod 640 /etc/gshadow
```

> **⚠️ Важно:** Никогда не изменяйте права на `/etc/shadow` и `/etc/gshadow` на более открытые. Это может заблокировать вход в систему.

### Резервное копирование

```bash
# Создание резервной копии перед изменениями
sudo cp /etc/passwd /etc/passwd.bak
sudo cp /etc/shadow /etc/shadow.bak
sudo cp /etc/group /etc/group.bak
sudo cp /etc/gshadow /etc/gshadow.bak

# Восстановление из backup
sudo cp /etc/passwd.bak /etc/passwd
```

### Аудит

```bash
# Пользователи без пароля
sudo awk -F: '($2 == "")' /etc/shadow

# Пользователи с пустым shell
awk -F: '($7 == "")' /etc/passwd

# UID 0 кроме root
awk -F: '($3 == 0 && $1 != "root")' /etc/passwd

# Проверка на дублирующиеся UID
cut -d: -f3 /etc/passwd | sort | uniq -d

# Проверка на дублирующиеся GID
cut -d: -f3 /etc/group | sort | uniq -d
```

## Дополнительная информация

### Связанные файлы

| Файл | Описание |
| :--- | :--- |
| `/etc/default/useradd` | Настройки `useradd` по умолчанию (параметры создания, SKEL, SHELL) |
| `/etc/login.defs` | Политики паролей (`PASS_MAX_DAYS`, `ENCRYPT_METHOD`), диапазоны UID/GID |
| `/etc/nologin.txt` | Сообщение, выводимое при входе через `/usr/sbin/nologin` |
| `/etc/securetty` | Терминалы, разрешённые для входа root |
| `/etc/pam.d/` | Модули аутентификации PAM — [pam_overview.md](../../Security/pam_overview.md) |
