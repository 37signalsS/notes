# Файлы конфигурации пользователей и групп в Linux

## Определения

- **`/etc/passwd`** — текстовая база данных, содержащая основную информацию об учетных записях пользователей. Файл доступен для чтения всем пользователям для корректного сопоставления UID с именами (например, утилитой `ls -l`).
- **`/etc/shadow`** — защищенный файл, содержащий зашифрованные хэши паролей и параметры политики их устаревания. Доступен только пользователю `root`.
- **`/etc/group`** — файл, определяющий группы в системе и их состав. Используется `ls -l` для отображения имен групп по GID.
- **`/etc/gshadow`** — файл с зашифрованной информацией о паролях групп и их администраторах.
- **`/etc/subuid` / `/etc/subgid`** — файлы, определяющие диапазоны дополнительных идентификаторов (subordinate IDs) для пользователя, используемые в механизмах User Namespaces (контейнеризация).
- **`/etc/skel`** — директория-шаблон, содержимое которой автоматически копируется в домашний каталог нового пользователя при использовании команды `useradd -m`.
- **`vipw` / `vigr`** — специализированные утилиты для безопасного редактирования файлов `/etc/passwd` и `/etc/group` с механизмом блокировки от одновременных изменений.

## Базовые концепции

### Структура и формат данных

Все системные базы данных пользователей используют формат CSV (Comma Separated Values), где в качестве разделителя выступает двоеточие (`:`). Каждая строка представляет собой одну запись.

### Детальный разбор /etc/passwd

**Формат:** `username:password:UID:GID:GECOS:home_directory:shell`

| Поле | Описание | Технические нюансы |
| :--- | :--- | :--- |
| **username** | Уникальное имя. | Обычно до 32 символов, только латиница, цифры и дефис. |
| **password** | Флаг пароля. | Символ `x` указывает на хранение хэша в `/etc/shadow`. |
| **UID** | User Identifier. | Числовой ID. 0 всегда зарезервирован за root. |
| **GID** | Group Identifier. | ID основной группы пользователя. |
| **GECOS** | Комментарий. | Содержит полное имя, номер офиса, рабочий и домашний телефоны (через запятую). |
| **home_directory** | Домашняя папка. | Абсолютный путь к личному пространству пользователя. |
| **shell** | Оболочка входа. | Путь к интерпретатору. Для блокировки входа используются `/usr/sbin/nologin` или `/bin/false`. |

### Детальный разбор /etc/shadow

**Формат:** `username:password:last_change:min:max:warn:inactive:expire:reserved`

| Поле | Описание | Примечание |
| :--- | :--- | :--- |
| **password** | Хэш пароля. | Префиксы `$y$`, `$6$` определяют алгоритм. Символы `!` или `*` в начале блокируют вход. |
| **last_change** | Дата смены. | Дней с эпохи Unix (1 января 1970 г.). |
| **min** | Минимум дней. | Минимальный интервал между сменами пароля (0 — нет ограничений). |
| **max** | Максимум дней. | Срок действия пароля (99999 — бессрочно). |
| **warn** | Предупреждение. | За сколько дней до истечения срока начать выдавать предупреждение. |
| **inactive** | Период покоя. | Дней после истечения пароля до полной блокировки аккаунта. |
| **expire** | Дата истечения. | Абсолютная дата блокировки аккаунта (в днях с эпохи Unix). |

### Механизмы поиска (NSS)

Файл **`/etc/nsswitch.conf`** определяет приоритет источников данных.
Строка `passwd: files sssd` означает, что система сначала проверит локальный `/etc/passwd`, а затем обратится к службе SSSD (LDAP/AD).

## Практические сценарии

### Безопасное редактирование баз данных

Никогда не редактируйте `/etc/passwd` или `/etc/group` обычными текстовыми редакторами напрямую. Это может привести к повреждению структуры или потере данных при одновременном запуске команд управления пользователями.

```bash
# Безопасное редактирование passwd
sudo vipw

# Безопасное редактирование shadow
sudo vipw -s

# Безопасное редактирование group
sudo vigr
```

### Проверка целостности файлов

После ручных правок или миграций необходимо убедиться в корректности структуры файлов.

```bash
# Проверка passwd и shadow
sudo pwck

# Проверка group и gshadow
sudo grpck
```

### Анализ и фильтрация данных

```bash
# Поиск пользователей с shell-доступом (bash/zsh)
grep -E '(/bin/bash|/bin/zsh)$' /etc/passwd

# Извлечение только имен и домашних директорий
awk -F: '{print $1, $6}' /etc/passwd

# Поиск заблокированных аккаунтов в shadow
sudo awk -F: '$2 ~ /^(!|\*)/ {print $1}' /etc/shadow
```

### Настройка подсистемы подчиненных ID (subuid/subgid)

Файлы важны для работы Podman/Docker в безрутовом режиме (Rootless).

```bash
# Формат: username:start_id:range
# Пример: выдать пользователю 65536 идентификаторов начиная с 100000
echo "user1:100000:65536" | sudo tee -a /etc/subuid
echo "user1:100000:65536" | sudo tee -a /etc/subgid
```

## Дополнительная информация

### Векторы атак и безопасность

1.  **Права доступа:**
    - `/etc/passwd`: `644` (чтение всеми).
    - `/etc/shadow`: `640` или `600` (только root).
    - Если `/etc/shadow` доступен на чтение обычному пользователю, злоумышленник может выполнить Offline Brute-force атаку.
2.  **Эскалация через GECOS:** Иногда в поле GECOS ошибочно записывают чувствительную информацию (пароли, пин-коды), которая становится видна всей системе.
3.  **Беспарольный вход:** Если второе поле в `/etc/passwd` пустое (не содержит даже `x`), некоторые старые конфигурации PAM могут разрешить вход без пароля.

### Резервное копирование и аудит

Перед внесением изменений всегда создавайте снимки состояния:
```bash
sudo cp /etc/passwd /etc/passwd.bak_$(date +%F)
sudo cp /etc/shadow /etc/shadow.bak_$(date +%F)
```

Для детального отслеживания изменений в этих файлах используйте подсистему `auditd`:
```bash
sudo auditctl -w /etc/passwd -p wa -k user_changes
```
