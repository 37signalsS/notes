# Портативные домашние директории (systemd-homed)

## Определения

- **systemd-homed** — системная служба, управляющая домашними директориями как самодостаточными и портативными объектами.
- **JSON Record** — структурированные метаданные пользователя (имя, пароль, SSH-ключи, лимиты), хранящиеся в криптографически подписанном формате внутри образа домашней директории или в `/var/lib/systemd/home/`.
- **homectl** — основная утилита командной строки для управления пользователями и их домашними директориями.
- **pam_systemd_home** — модуль PAM, обеспечивающий аутентификацию и автоматическое монтирование директории при входе пользователя.

## Основные концепции

Традиционный подход (файлы в `/etc/passwd`, `/etc/shadow`) имеет фундаментальный недостаток: метаданные пользователя отделены от его данных, что затрудняет перенос аккаунтов между системами и усложняет полное шифрование. `systemd-homed` инкапсулирует данные и метаданные в единый защищенный контейнер.

### Ключевые преимущества (2025–2026)
1. **Портативность:** Домашняя директория (LUKS-образ) содержит всё необходимое для работы пользователя. При подключении диска к новой системе служба автоматически обнаруживает и регистрирует пользователя.
2. **Шифрование "из коробки":** По умолчанию используется LUKS2 с поддержкой динамического изменения размера и онлайн-решифрования.
3. **Криптографическая целостность:** Метаданные (JSON Record) подписаны ключом хоста или ключом пользователя, что исключает несанкционированное изменение параметров аккаунта.
4. **Аппаратная аутентификация:** Нативная поддержка FIDO2, TPM2 и PKCS#11 (смарт-карты) для разблокировки ключей шифрования.
5. **Безопасность в режиме ожидания:** Возможность автоматического размонтирования и сброса ключей из памяти при приостановке системы (suspend).

## Типы хранилищ (Storage Backends)

| Тип | Описание | Рекомендация |
| :--- | :--- | :--- |
| **luks** | Зашифрованный образ LUKS2 (файл или раздел). | **Рекомендуется** для безопасности и портативности. |
| **fscrypt** | Шифрование на уровне файловой системы (ext4/f2fs). | Оптимально для систем без поддержки LUKS (например, Android/Embedded). |
| **subvolume** | Подтома Btrfs с использованием квот. | Удобно для управления снапшотами, но шифрование на уровне FS. |
| **directory** | Обычная директория в `/home/`. | Минимум преимуществ, не рекомендуется для новых систем. |
| **cifs** | Монтирование удаленной домашней папки по SMB/CIFS. | Для корпоративных сред и сетевых профилей. |

## Практические сценарии

### 1. Создание пользователя с шифрованием LUKS
Создадим пользователя `ivan` с выделением 20 ГБ места.

```bash
sudo homectl create ivan --storage=luks --disk-size=20G
# → Creating home for ivan...
# → Everything completed successfully.
```

### 2. Привязка к FIDO2 и SSH-ключам
`systemd-homed` позволяет хранить SSH-ключи прямо в JSON-записи пользователя, что делает их доступными сразу после монтирования.

```bash
# Привязка физического токена FIDO2
sudo homectl update ivan --enrolled-fido2-device=auto

# Добавление SSH-ключа в JSON-запись
sudo homectl update ivan --ssh-authorized-keys=@/path/to/id_ed25519.pub
```

### 3. Управление состоянием и инспекция

```bash
# Просмотр детальной JSON-записи пользователя
homectl inspect ivan
# → { "userName" : "ivan", "enforcePasswordPolicy" : true, ... }

# Активация (монтирование и расшифровка)
sudo homectl activate ivan

# Деактивация (размонтирование и блокировка)
sudo homectl deactivate ivan
```

### 4. Динамическое изменение размера
LUKS2 образы в `systemd-homed` поддерживают онлайн-ресайз.

```bash
sudo homectl resize ivan 50G
# → Resizing home of ivan to 50.0G...
# → Completed.
```

## Дополнительная информация

### Безопасность и аппаратные токены
- **TPM2:** Автоматическая разблокировка при условии неизменности аппаратной конфигурации (PCR-регистры).
- **PKCS#11:** Поддержка смарт-карт и аппаратных HSM.
- **Side-loading:** Если файл `.home` (JSON Record) поместить в `/var/lib/systemd/home/`, служба автоматически подхватит пользователя (полезно для "холодного" импорта).

### Режим ожидания (Suspend)
При переходе системы в спящий режим `systemd-homed` может переводить домашние директории в состояние "suspend", вымывая ключи шифрования из оперативной памяти. Это защищает от атак через прямое чтение памяти (Cold Boot attack).

```bash
# Настройка поведения при приостановке (в homed.conf)
SuspendMode=suspend
```

### Сравнение подходов

| Характеристика | Традиционный (/etc/passwd) | systemd-homed |
| :--- | :--- | :--- |
| **Метаданные** | Рассредоточены по `/etc/` | Инкапсулированы в JSON |
| **Шифрование** | Ручное (ecryptfs/LUKS) | Нативное (LUKS2) |
| **UID/GID** | Статические (привязаны к хосту) | Динамические (следуют за образом) |
| **Портативность** | Требует ручного переноса | Полностью автоматизирована |
