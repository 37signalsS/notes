# Хэширование паролей в Linux

## Определения

- **Хэш-функция** — односторонняя математическая функция, преобразующая входные данные (пароль) в строку фиксированной длины. Процесс необратим: невозможно восстановить исходный пароль из хэша.
- **Соль (Salt)** — случайная строка данных, уникальная для каждой учетной записи, которая добавляется к паролю перед хэшированием. Защищает от атак по предвычисленным таблицам (Rainbow Tables).
- **Радужные таблицы (Rainbow Tables)** — базы данных предварительно вычисленных хэшей для популярных паролей, используемые для мгновенного взлома систем без использования соли.
- **Итерации (Rounds)** — количество повторных циклов хэширования. Увеличение числа итераций замедляет процесс вычисления, делая перебор (Brute-force) экономически невыгодным.
- **Memory-hard алгоритмы** — алгоритмы хэширования (например, Argon2, Yescrypt), требующие значительного объема оперативной памяти. Это эффективно блокирует взлом с использованием специализированного оборудования (ASIC, GPU), которое оптимизировано под вычисления, а не под работу с памятью.

## Базовые концепции

### Механизм проверки пароля

В современных Linux-системах пароли хранятся в файле `/etc/shadow` в зашифрованном (хэшированном) виде. Процесс аутентификации включает следующие шаги:

1. Система получает имя пользователя и введенный пароль.
2. Из `/etc/shadow` извлекается строка хэша, содержащая идентификатор алгоритма и соль.
3. Система вычисляет хэш от введенного пароля, используя ту же соль и алгоритм.
4. Если вычисленный хэш совпадает с хранящимся в файле — пользователь считается аутентифицированным.

### Алгоритмы и их идентификаторы

Формат записи хэша: `$id$salt$hashed` или `$id$rounds=N$salt$hashed`.

| Идентификатор | Алгоритм | Префикс в shadow | Статус (2025–2026) |
| :--- | :--- | :--- | :--- |
| **`1`** | MD5 | `$1$` | **Устарел.** Небезопасен из-за высокой скорости вычисления. |
| **`2a/2y/2b`** | bcrypt | `$2a$`, `$2y$`, `$2b$` | **Приемлем.** Стандарт для BSD и многих веб-приложений. |
| **`5`** | SHA-256 | `$5$` | **Приемлем.** Постепенно вытесняется более стойкими версиями. |
| **`6`** | SHA-512 | `$6$` | **Рекомендуется.** Дефолтный стандарт для RHEL 7-9 и Debian 10. |
| **`y`** | **Yescrypt** | `$y$` | **Рекомендуется.** Современный стандарт (Ubuntu 22.04+, Debian 11+, Fedora 35+). |
| **`argon2id`** | Argon2 | `$argon2id$` | **Рекомендуется.** Лучший криптографический стандарт, поддерживается через модули PAM. |

### Почему Yescrypt и Argon2 лучше SHA-512?

Классические алгоритмы (SHA-512) являются **CPU-intensive**. Злоумышленник может использовать сотни GPU или специализированные чипы (ASIC) для параллельного перебора миллионов хэшей в секунду. 
**Yescrypt** и **Argon2** добавляют параметр **Memory Cost**. Для вычисления одного хэша требуется, например, 64 МБ оперативной памяти. Это делает массированную параллельную атаку на GPU невозможной, так как видеокарты имеют ограниченный объем быстрой памяти, который мгновенно исчерпывается.

## Практические сценарии

### Анализ используемых алгоритмов

```bash
# Проверка используемых алгоритмов для всех реальных пользователей (UID >= 1000)
sudo awk -F: '$3 >= 1000 {print $1}' /etc/passwd | xargs -I {} sudo grep "{}" /etc/shadow | cut -d: -f1,2

# Поиск пользователей с небезопасными хэшами (MD5 или без соли)
sudo grep -E '^\$1\$' /etc/shadow
```

### Настройка системного алгоритма по умолчанию

Настройка производится в конфигурационных файлах PAM и утилит управления пользователями.

#### 1. Настройка для новых пользователей через login.defs
Определяет, какой алгоритм будет использовать `useradd` и `passwd`.

```bash
# Отредактируйте /etc/login.defs
ENCRYPT_METHOD YESCRYPT

# Для SHA-512 можно настроить количество раундов (от 1000 до 999999999)
SHA_CRYPT_MIN_ROUNDS 10000
SHA_CRYPT_MAX_ROUNDS 50000
```

#### 2. Настройка через PAM (Debian/Ubuntu)
Файл `/etc/pam.d/common-password` управляет модулем `pam_unix.so`.

```text
# Пример перехода на yescrypt
password [success=1 default=ignore] pam_unix.so obscure yescrypt
```

#### 3. Настройка через authselect (RHEL/CentOS/Fedora)
```bash
# Просмотр текущих настроек
authselect current

# Включение SHA-512 с явным указанием раундов
sudo authselect select minimal with-sha512-rounds=10000
```

### Генерация хэшей вручную для скриптов

Часто требуется сгенерировать хэш для использования в Ansible или при создании пользователей через Cloud-init.

```bash
# Генерация Yescrypt (рекомендуется) через mkpasswd (пакет whois)
mkpasswd -m yescrypt "my_secure_password"
# → $y$j9T$v9M...

# Генерация SHA-512 через openssl
openssl passwd -6 -salt custom_salt "my_secure_password"

# Генерация через Python (удобно для кроссплатформенности)
python3 -c "import crypt; print(crypt.crypt('my_password', crypt.mksalt(crypt.METHOD_YESCRYPT)))"
```

### Принудительное обновление хэшей

Если вы сменили алгоритм в системе на более стойкий, старые хэши в `/etc/shadow` останутся прежними до тех пор, пока пользователи не сменят пароли.

```bash
# Принудительная смена пароля при следующем входе
sudo chage -d 0 username
```

## Дополнительная информация

### Безопасность файла /etc/shadow

Хэширование — это лишь часть защиты. Критически важно соблюдать права доступа к самому файлу:
- Владелец: `root:shadow` или `root:root`.
- Права доступа: `0640` или `0600`.
- Любой доступ на чтение для не-root пользователя означает возможность проведения **Offline-атаки** (взлом хэша на мощностях злоумышленника).

### Сравнение устойчивости к взлому

| Алгоритм | Соль | Защита от GPU | Масштабируемость |
| :--- | :--- | :--- | :--- |
| **MD5** | Да | Нет | Низкая |
| **SHA-512** | Да | Частично (через rounds) | Средняя |
| **bcrypt** | Да | Хорошая | Средняя |
| **Yescrypt** | Да | Отличная | Высокая (Memory-hard) |
| **Argon2id** | Да | Максимальная | Высокая (Memory/Time/Parallelism) |
