# Хэширование паролей в Linux

## Определения

- **Хэш-функция** — односторонняя математическая функция, преобразующая входные данные в строку фиксированной длины
- **Соль (salt)** — случайная строка, уникальная для каждого пароля, добавляемая перед хэшированием
- **Радужные таблицы** — заранее вычисленные таблицы хэшей для атак на пароли

## Базовые концепты

### Принцип работы

Когда пользователь вводит пароль, система:

1. Берёт введённый пароль
2. Добавляет **соль** — случайную строку, уникальную для каждого пользователя
3. Прогоняет результат через хэш-функцию
4. Сравнивает полученный хэш с хранящимся в `/etc/shadow`

### Зачем нужна соль

- **Уникальность:** Даже одинаковые пароли дают разные хэши
- **Защита от радужных таблиц:** Делает неэффективными предварительно вычисленные атаки
- **Усложнение перебора:** Каждая атака требует уникальных вычислений

## Алгоритмы хэширования

### Поддерживаемые алгоритмы

| ID | Алгоритм | Длина хэша | Статус |
| :--- | :--- | :--- | :--- |
| `1` | MD5 | 128 бит | ⚠️ Устарел, не рекомендуется |
| `2a` | Blowfish | 184 бита | Устарел |
| `2y` | Blowfish (corrected) | 184 бита | Устарел |
| `5` | SHA-256 | 256 бит | Приемлем |
| `6` | SHA-512 | 512 бит | ✅ Рекомендуется (стандарт) |
| `yescrypt` | Yescrypt | переменная | ✅ Новый стандарт (Debian 11+) |

### Формат хэша в /etc/shadow

```
$id$salt$hashed
```

**Пример:**

```
$6$rounds=5000$saltsalt$hashedvalue...
```

Где:

- `$6$` — идентификатор SHA-512
- `rounds=5000` — количество раундов (опционально)
- `saltsalt` — соль
- `hashedvalue` — сам хэш

### Сравнение алгоритмов

| Алгоритм | Безопасность | Производительность | Рекомендация |
| :--- | :--- | :--- | :--- |
| **MD5** | Низкая | Высокая | ❌ Не использовать |
| **SHA-256** | Хорошая | Средняя | ⚠️ Минимум |
| **SHA-512** | Высокая | Средняя | ✅ Рекомендуется |
| **Yescrypt** | Очень высокая | Низкая | ✅ Предпочтительно |
| **bcrypt** | Высокая | Низкая | ✅ Хорошо |
| **Argon2** | Очень высокая | Низкая | ✅ Лучший выбор |
| **scrypt** | Очень высокая | Низкая | ✅ Хорошо |

## Практические сценарии

### Проверка текущего алгоритма

```bash
# Просмотр хэшей (только root!)
sudo cat /etc/shadow

# Определение алгоритма по ID
sudo awk -F: '{print $1, substr($2, 1, 3)}' /etc/shadow

# Пример вывода:
# root $6$
# user $5$
```

### Изменение алгоритма хэширования

**Для PAM (системный уровень):**

```bash
# /etc/pam.d/common-password (Debian/Ubuntu)
# Добавить rounds параметр для SHA-512
password [success=1 default=ignore] pam_unix.so obscure sha512 rounds=5000

# Для yescrypt (если поддерживается)
password [success=1 default=ignore] pam_unix.so obscure yescrypt
```

**Для новых пользователей (login.defs):**

```bash
# /etc/login.defs
ENCRYPT_METHOD SHA512
# или
ENCRYPT_METHOD YESCRYPT

# Количество раундов
SHA_CRYPT_MIN_ROUNDS 5000
SHA_CRYPT_MAX_ROUNDS 5000
```

### Принудительная смена пароля с новым алгоритмом

```bash
# Сброс пароля пользователю
sudo passwd username

# Или через chage (принудительная смена при входе)
sudo chage -d 0 username
```

### Генерация хэша пароля

```bash
# С помощью openssl (SHA-512)
openssl passwd -6 "mypassword"

# С помощью mkpasswd (требуется пакет whois)
mkpasswd -m sha-512 "mypassword"

# С помощью Python
python3 -c "import crypt; print(crypt.crypt('mypassword', crypt.mksalt(crypt.METHOD_SHA512)))"

# С помощью Python (yescrypt, если доступен)
python3 -c "import crypt; print(crypt.crypt('mypassword', crypt.mksalt(crypt.METHOD_YESCRYPT)))"
```

### Обновление хэшей всех пользователей

```bash
# Скрипт для принудительной смены паролей
#!/bin/bash
for user in $(awk -F: '$3 >= 1000 {print $1}' /etc/passwd); do
    sudo chage -d 0 "$user"
    echo "Пароль пользователя $user будет сброшен при следующем входе"
done
```

## Лучшие практики

### Безопасность

1. **Минимум SHA-512:** Не используйте MD5 или DES
2. **Количество раундов:** Минимум 5000, лучше 10000+
3. **Длина пароля:** Минимум 12 символов
4. **Сложность:** Комбинация букв, цифр, спецсимволов
5. **Регулярная смена:** Каждые 60-90 дней для критичных систем

### Конфигурация для высокой безопасности

```bash
# /etc/login.defs
ENCRYPT_METHOD YESCRYPT
SHA_CRYPT_MIN_ROUNDS 10000
SHA_CRYPT_MAX_ROUNDS 20000
PASS_MAX_DAYS 90
PASS_MIN_DAYS 7
PASS_WARN_AGE 14
```

### Аудит

```bash
# Пользователи со слабыми хэшами (MD5)
sudo awk -F: '$2 ~ /^\$1\$/ {print $1}' /etc/shadow

# Пользователи без пароля
sudo awk -F: '($2 == "" || $2 == "!" || $2 == "*") {print $1}' /etc/shadow

# Проверка количества раундов
sudo grep -E '^\$6\$rounds=' /etc/shadow
```

## Дополнительная информация

### Уязвимости и атаки

| Тип атаки | Описание | Защита |
| :--- | :--- | :--- |
| **Радужные таблицы** | Предварительно вычисленные хэши | Соль |
| **Brute force** | Полный перебор | Сложные пароли, раунды |
| **Dictionary attack** | Перебор по словарю | Сложные пароли |
| **Collision attack** | Поиск коллизий | SHA-512, Argon2 |

### Будущие стандарты

- **Argon2** — победитель Password Hashing Competition (2015), рекомендуется для новых систем
- **Yescrypt** — используется по умолчанию в Debian 11+, Ubuntu 21.04+
- **bcrypt** — широко поддерживается, хорошая защита
