# Хэширование паролей в Linux

## Определения

- **Хэш-функция** — односторонняя математическая функция, преобразующая входные данные (пароль) в строку фиксированной длины. Процесс необратим в одну сторону.
- **Соль (salt)** — случайная строка данных, уникальная для каждой учетной записи, которая добавляется к паролю перед хэшированием для защиты от атак по предвычисленным таблицам.
- **Радужные таблицы (Rainbow Tables)** — предварительно вычисленные таблицы соответствий паролей их хэш-значениям, используемые для быстрого взлома хэшей без соли.
- **Итерации (Rounds)** — количество повторных циклов хэширования, выполняемых для замедления процесса перебора паролей (Brute-force).

## Базовые концепции

### Механизм проверки пароля

В Linux пароли никогда не хранятся в открытом виде. При аутентификации система выполняет следующие шаги:

1. Считывает имя пользователя и введенный пароль.
2. Извлекает **соль** и идентификатор алгоритма из файла `/etc/shadow`.
3. Вычисляет хэш от введенного пароля с использованием этой соли.
4. Сравнивает результат с хэшем, хранящимся в `/etc/shadow`. Если они совпадают — доступ разрешен.

### Роль соли и итераций

- **Защита от одинаковых хэшей:** Даже если два пользователя выберут одинаковый пароль, их хэши в `/etc/shadow` будут разными из-за уникальной соли.
- **Противодействие Rainbow Tables:** Соль делает невозможным использование готовых баз хэшей, так как злоумышленнику пришлось бы генерировать таблицы для каждой возможной соли.
- **Замедление перебора:** Увеличение количества итераций (раундов) делает каждую попытку проверки пароля более ресурсоемкой для процессора, что критично для защиты от перебора на GPU (Graphics Processing Unit).

### Алгоритмы хэширования

#### Формат записи в /etc/shadow

Запись имеет вид: `$id$salt$hashed` или `$id$rounds=N$salt$hashed`.

| Поле | Описание |
| :--- | :--- |
| **$id$** | Идентификатор алгоритма (например, `$6$` для SHA-512) |
| **rounds=N** | Количество итераций (необязательно, зависит от алгоритма) |
| **salt** | Строка соли |
| **hashed** | Результат хэширования |

#### Поддерживаемые алгоритмы

| ID | Название | Статус | Комментарий |
| :--- | :--- | :--- | :--- |
| `1` | **MD5** (Message Digest 5) | Устарел | Слишком быстрый, уязвим к коллизиям. |
| `2a`/`2y` | **bcrypt** (Blowfish) | Приемлем | Хорошая защита, используется в BSD (Berkeley Software Distribution) и некоторых Linux. |
| `5` | **SHA-256** | Приемлем | Часть семейства SHA-2 (Secure Hash Algorithm). |
| `6` | **SHA-512** | Рекомендуется | Стандарт для большинства современных дистрибутивов. |
| `yescrypt` | **Yescrypt** | Рекомендуется | Новый стандарт (Debian 11+, Ubuntu 22.04+). Масштабируемый по памяти. |

#### Сравнение современных алгоритмов

| Алгоритм | Устойчивость | Тип защиты | Использование |
| :--- | :--- | :--- | :--- |
| **SHA-512** | Высокая | CPU-intensive | Классический стандарт. |
| **Yescrypt** | Очень высокая | Memory-hard | Защита от перебора на специализированном оборудовании (ASIC (Application-Specific Integrated Circuit)/GPU). |
| **Argon2** | Максимальная | Memory/Time-hard | Современный криптографический стандарт (PHC winner — Password Hashing Competition). |

## Практические сценарии

### Анализ текущих хэшей

```bash
# Проверка используемых алгоритмов для всех пользователей
sudo awk -F: '{print $1, $2}' /etc/shadow | awk -F'$' '{print $1, $2}'

# Поиск пользователей с устаревшим MD5 (ID 1)
sudo grep '^\$1\$' /etc/shadow
```

### Настройка алгоритма по умолчанию

Параметры хэширования для новых паролей задаются в конфигурации PAM (Pluggable Authentication Modules).

```bash
# Debian/Ubuntu: редактирование /etc/pam.d/common-password
# Пример установки SHA-512 с 10000 раундами
password [success=1 default=ignore] pam_unix.so obscure sha512 rounds=10000

# RHEL/CentOS/Fedora: настройка через authselect или /etc/pam.d/password-auth
```

Настройка для утилит создания пользователей:

```bash
# /etc/login.defs
ENCRYPT_METHOD YESCRYPT
# Для SHA-512 можно указать раунды:
SHA_CRYPT_MIN_ROUNDS 5000
SHA_CRYPT_MAX_ROUNDS 10000
```

### Генерация хэшей вручную

```bash
# Использование openssl (SHA-512)
openssl passwd -6 "my_secret_password"

# Использование mkpasswd (пакет whois) — генерация yescrypt
mkpasswd -m yescrypt "my_secret_password"

# Использование Python для генерации хэша с солью
python3 -c "import crypt; print(crypt.crypt('password', crypt.mksalt(crypt.METHOD_SHA512)))"
```

### Аудит безопасности паролей

```bash
# Поиск учетных записей без установленного пароля (пустое поле хэша)
sudo awk -F: '($2 == "") {print $1}' /etc/shadow

# Поиск заблокированных учетных записей (! или *)
sudo awk -F: '($2 ~ /^!/ || $2 ~ /^\*/) {print $1}' /etc/shadow
```

## Дополнительная информация

### Векторы атак и защита

| Атака | Описание | Метод защиты |
| :--- | :--- | :--- |
| **Brute-force** | Перебор всех возможных комбинаций. | Длинные пароли + алгоритмы с большим количеством итераций. |
| **Dictionary** | Перебор по списку популярных слов и паролей. | Политика сложности паролей + блокировка после N попыток (pam_faillock). |
| **Rainbow Tables** | Использование баз предвычисленных хэшей. | **Соль** (salt) делает такие таблицы бесполезными. |
| **Offline Cracking** | Взлом украденного файла /etc/shadow. | Использование Memory-hard алгоритмов (Yescrypt, Argon2). |
