# Мониторинг пользователей и сессий

## Определения

- **Сессия (Session)** — период активности пользователя в системе, начинающийся с момента успешной аутентификации и заканчивающийся выходом (logout) или принудительным завершением.
- **Интерактивный вход** — вход пользователя через терминал (TTY), SSH-сессию или графическую оболочку (Display Manager).
- **Временные файлы (utmp/wtmp/btmp)** — бинарные файлы в каталоге `/var/log`, хранящие информацию о текущих сессиях, истории входов и неудачных попытках.
- **`loginctl`** — современная утилита `systemd` для управления пользователями и их сессиями.
- **Логин** — запись о входе пользователя в системных журналах.

## Базовые концепции

### Категории информации о пользователях

Для эффективного администрирования необходимо отслеживать несколько уровней данных:

| Тип данных | Описание | Основные команды |
| :--- | :--- | :--- |
| **Идентификаторы** | UID (User Identifier), GID (Group Identifier), состав групп. | `id`, `getent`, `groups` |
| **Активные сессии** | Список пользователей в системе и их текущая активность. | `who`, `w`, `users`, `loginctl` |
| **История входов** | Журнал успешных и неудачных попыток входа, перезагрузки. | `last`, `lastb`, `lastlog`, `faillock` |
| **Процессы** | Процессы, запущенные пользователем, и их иерархия. | `ps`, `pgrep`, `top`, `htop`, `pstree` |
| **Ресурсы** | Потребление CPU, RAM и I/O на уровне пользователя/сессии. | `systemd-cgtop`, `top -u` |
| **Файлы** | Открытые файлы, сетевые соединения и владение файловой системой. | `find`, `lsof` |

### Системные журналы (SSoT)

Информация мониторинга берется из следующих источников:

1. **`/var/run/utmp`**: Текущие сессии. Читается командами `who`, `w`, `users`.
2. **`/var/log/wtmp`**: История входов. Читается командой `last`.
3. **`/var/log/btmp`**: Ошибки аутентификации. Читается командой `lastb`.
4. **`/var/log/lastlog`**: Последний вход для каждого аккаунта. Читается командой `lastlog`.
5. **`/var/log/auth.log`** (Debian/Ubuntu) или **`/var/log/secure`** (RHEL): Текстовые логи аутентификации и использования `sudo`.

## Практические сценарии

### Проверка идентификаторов и групп

```bash
# UID, GID и все группы пользователя
id username

# Вывод только числовых ID
id -u username  # UID
id -g username  # Первичный GID
id -G username  # Все GID дополнительных групп

# Вывод имен вместо ID
id -un username # Имя пользователя
id -gn username # Имя первичной группы
id -Gn username # Имена всех групп

# Проверка через базу данных NSS (включая LDAP/AD)
getent passwd username
getent group wheel  # Список членов группы (для RHEL)
getent group sudo   # Список членов группы (для Debian/Ubuntu)
```

### Мониторинг активных сессий

#### Классические утилиты

```bash
# Кто сейчас в системе (кратко)
who

# Подробная информация (время входа, IP, текущая команда, Load Average)
w

# Список только имен пользователей
users

# Полная сводка со всеми деталями
who -a

# Сессии с проверкой статуса терминала (+/- — доступность для записи)
who -T

# Вывод с заголовками и временем бездействия (Idle)
who -Hu
```

#### Современное управление через systemd (loginctl)

```bash
# Список всех активных сессий
loginctl list-sessions

# Список авторизованных пользователей (включая тех, у кого только фоновые процессы)
loginctl list-users

# Детальный статус пользователя (дерево процессов, время входа, cgroup)
loginctl user-status username

# Подробности конкретной сессии
loginctl show-session <SESSION_ID>
```

### Анализ истории входов

```bash
# Последние входы в систему (считывает /var/log/wtmp)
last

# История входов конкретного пользователя
last username

# Поиск входов с конкретного терминала или IP
last pts/0
last 192.168.1.100

# Фильтрация по времени
last -s 2026-01-01  # С указанной даты
last -s 2026-01-01 -t 2026-02-01  # Диапазон

# Дополнительные флаги last
last -F  # Полные даты и время
last -i  # Показ IP-адресов вместо хостов
last -x  # Записи о выключениях (shutdown) и сменах runlevel

# Неудачные попытки входа (требует прав sudo)
sudo lastb

# Последний вход всех пользователей системы (включая системных)
lastlog
```

### Проверка процессов и ресурсов

```bash
# Все процессы пользователя с полной командной строкой
ps -u username -f

# Процессы в виде дерева с PID
pstree -p username

# Поиск процессов по имени (только PID)
pgrep -u username -l

# Интерактивный мониторинг в реальном времени
top -u username
htop -u username

# Мониторинг потребления ресурсов по контрольным группам (systemd)
# Позволяет видеть нагрузку, создаваемую конкретным пользователем
systemd-cgtop
```

### Проверка владения файлами и активности

```bash
# Поиск файлов пользователя в его домашней директории
find /home/username -type f

# Поиск файлов по всей системе (с подавлением ошибок доступа)
sudo find / -user username 2>/dev/null

# Файлы, измененные за последние 7 дней
find /home/username -type f -mtime -7

# Поиск больших файлов (>100MB)
find /home/username -type f -size +100M -exec ls -lh {} \;

# Список открытых файлов пользователя (сетевые сокеты, файлы данных)
sudo lsof -u username

# Только сетевые соединения пользователя
sudo lsof -i -u username
```

### Аудит безопасности и авторизаций

```bash
# Анализ логов через journalctl
# Все события, связанные с сессиями
journalctl -u systemd-logind.service

# Использование sudo конкретным пользователем
journalctl _COMM=sudo | grep username

# Поиск ошибок аутентификации (faillock)
sudo faillock --user username

# Сброс счетчика неудачных попыток (разблокировка)
sudo faillock --user username --reset

# Анализ действий в реальном времени
sudo tail -f /var/log/auth.log  # Debian/Ubuntu
sudo tail -f /var/log/secure    # RHEL/CentOS
```

## Дополнительная информация

### Принудительное завершение активности

В случае обнаружения нелегитимной активности или зависших сессий:

1.  **Завершение через `loginctl` (Рекомендуется):**
    ```bash
    # Завершение конкретной сессии
    sudo loginctl terminate-session <ID>
    # Завершение всех сессий и процессов пользователя
    sudo loginctl terminate-user username
    ```
2.  **Классический метод через `kill`:**
    ```bash
    # Послать SIGTERM всем процессам пользователя
    sudo kill -15 -u username
    # Принудительное завершение
    sudo kill -9 -u username
    ```

### Лучшие практики

1.  **Мониторинг `Linger`:** Проверьте, разрешено ли пользователю оставлять процессы после выхода:
    `loginctl show-user username --property=Linger`.
    Для изменения: `sudo loginctl enable-linger username`.
2.  **Аудит Brute-force:** Регулярно запускайте `lastb` или используйте инструменты типа `fail2ban`, которые анализируют журналы входов.
3.  **Безопасность SSH:** Запретите прямой вход `root` по SSH и ограничьте список разрешенных пользователей через `AllowUsers` или `AllowGroups`.
4.  **Аудит действий через `auditd`:** Для критически важных систем настройте детальный аудит всех системных вызовов пользователя. Подробнее см. [auditd — системный аудит](../../Logging/auditd.md).

### Сценарии для автоматизации

#### Отчёт по активности пользователя

```bash
#!/bin/bash
# user_activity_report.sh - расширенный отчёт по активности

USERNAME="$1"
if [[ -z "$USERNAME" ]]; then
    echo "Использование: $0 <username>"
    exit 1
fi

echo "=== ОТЧЁТ ПО ПОЛЬЗОВАТЕЛЮ: $USERNAME ==="
echo "Дата: $(date)"

echo -e "\n--- Идентификаторы и группы ---"
id "$USERNAME"

echo -e "\n--- Активные сессии (w) ---"
w "$USERNAME" || echo "Нет активных сессий"

echo -e "\n--- Статус systemd-logind ---"
loginctl user-status "$USERNAME" --no-pager

echo -e "\n--- Последние 5 входов (last) ---"
last -n 5 "$USERNAME"

echo -e "\n--- Попытки взлома (faillock) ---"
sudo faillock --user "$USERNAME"

echo -e "\n--- Открытые порты/соединения (lsof) ---"
sudo lsof -i -u "$USERNAME"

echo -e "\n--- Использование диска (home) ---"
sudo du -sh /home/"$USERNAME" 2>/dev/null || echo "Домашняя директория не найдена"
```
