# Управление группами

## Определения

- **`groupadd`** — утилита для создания новой группы в системе.
- **`groupmod`** — модификация параметров существующей группы (имя, GID).
- **`groupdel`** — удаление группы из системы.
- **`gpasswd`** — утилита для администрирования файла `/etc/group` и `/etc/gshadow`. Позволяет управлять членством, назначать администраторов групп и устанавливать пароли групп.
- **`groupmems`** — утилита для управления списком членов группы. Позволяет пользователям (при наличии прав) просматривать и изменять состав своих групп без использования `sudo`.
- **`newgrp`** — команда для смены текущего идентификатора группы (GID) в текущей сессии оболочки.
- **`sg`** (set group) — выполнение команды с альтернативным идентификатором группы.

## Базовые концепции

### Типы членства в группах

1. **Первичная группа (Primary Group):** Основная группа пользователя, идентификатор которой указан в файле `/etc/passwd`. Все файлы, создаваемые пользователем, по умолчанию наследуют GID этой группы.
2. **Дополнительные группы (Supplementary Groups):** Группы, в которые пользователь включен для расширения прав доступа (например, доступ к Docker, sudo или общим папкам).

### Идентификаторы групп (GID)

- **0:** Группа `root`.
- **1–999:** Системные группы (зависят от дистрибутива, обычно используются для сервисов).
- **1000+:** Пользовательские группы.

Подробную таблицу диапазонов см. в разделе [Определения пользователей и групп](./users_definitions.md#диапазоны-uid-и-gid).

## Практические сценарии

### Создание и удаление групп

```bash
# Создание обычной группы
sudo groupadd developers

# Создание группы с конкретным GID
sudo groupadd -g 1500 developers

# Создание системной группы (автоматический выбор GID из системного диапазона)
sudo groupadd -r sysadmins

# Удаление группы
sudo groupdel developers
```

> **Важно:** Удаление группы невозможно, если она является первичной для любого активного пользователя. Сначала измените первичную группу пользователя через `usermod -g`.

### Модификация групп

```bash
# Изменение имени группы
sudo groupmod -n new-name old-name

# Изменение GID группы
sudo groupmod -g 1501 group-name
```

### Управление членством в группах

#### Добавление и удаление пользователей

```bash
# Добавление в дополнительную группу (через usermod)
# Внимание: Ключ -a обязателен, иначе пользователь будет удален из других групп!
sudo usermod -aG docker username

# Добавление через gpasswd
sudo gpasswd -a username docker

# Удаление пользователя из группы
sudo gpasswd -d username docker
```

#### Использование groupmems

Утилита удобна для быстрой работы со списком членов группы:

```bash
# Просмотр членов группы (без sudo, если вы член этой группы)
groupmems -g developers -l

# Очистка всего списка членов группы
sudo groupmems -g developers -p
```

#### Администрирование групп (gpasswd)

`gpasswd` позволяет делегировать управление группой обычному пользователю:

```bash
# Назначение администратора группы
# Администратор сможет добавлять/удалять членов без использования sudo
sudo gpasswd -A username developers

# Установка списка членов группы (полная перезапись)
sudo gpasswd -M user1,user2,user3 developers
```

### Пароли групп и временный доступ

Пароли групп позволяют пользователям, не входящим в группу, временно получить её права.

```bash
# Установка пароля для группы
sudo gpasswd developers

# Вход в группу с использованием пароля
newgrp developers
# → система запросит пароль группы
```

### Просмотр информации о группах

```bash
# Список всех групп в системе
getent group

# Члены конкретной группы
getent group sudo | cut -d: -f4

# Группы текущего пользователя
groups
# Или для конкретного пользователя:
groups username
```

### Применение изменений без перезагрузки

После изменения состава групп изменения не подхватываются в текущих запущенных процессах (включая оболочку).

1. **Перезапуск текущей оболочки через `exec`:**
   ```bash
   exec su - $USER
   ```
2. **Запуск новой оболочки с новой группой через `newgrp`:**
   ```bash
   newgrp docker
   ```
3. **Выполнение разовой команды через `sg`:**
   ```bash
   sg docker -c "docker ps"
   ```

## Дополнительная информация

### Современные альтернативы (2025–2026)

Для автоматизации и облачных сред рекомендуется использовать декларативные подходы:

- **systemd-sysusers:** Позволяет описывать группы в файлах конфигурации `/etc/sysusers.d/`. При загрузке или вызове `systemd-sysusers` система гарантирует наличие указанных групп.
- **Ansible/Terraform:** В инфраструктурном коде используйте модули `ansible.builtin.group` вместо прямых вызовов `groupadd` для обеспечения идемпотентности.

### Привилегированные группы

| Группа | Назначение |
| :--- | :--- |
| `wheel` / `sudo` | Право выполнения команд от имени суперпользователя. |
| `docker` | Управление контейнерами без прав root (эквивалентно root по рискам). |
| `lxd` | Управление контейнерами LXD. |
| `systemd-journal` | Доступ к чтению всех системных логов через `journalctl`. |
| `adm` | Доступ к логам в `/var/log` (традиционный метод). |

### Распространенные ошибки

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| Изменения не вступили в силу | Группы кэшируются при входе | Используйте `exec su - $USER` или перезайдите в систему. |
| Пользователь пропал из групп | Вызвана `usermod -G` без `-a` | Всегда проверяйте наличие флага `-a`. |
| `groupdel: group ... is the primary` | Попытка удалить основную группу | Переназначьте первичную группу пользователю (`usermod -g`). |

### Лучшие практики

1. **Принцип UPG (User Private Groups):** Для каждого пользователя создавайте одноименную первичную группу. Это упрощает управление правами через `umask 002`.
2. **Минимизация использования `docker` группы:** Членство в этой группе дает полный контроль над хостом. Рассмотрите использование [Rootless Docker](../../Docker/Docker_security/host_daemon_hardening.md).
3. **Регулярный аудит:** Проверяйте состав критических групп (`sudo`, `wheel`, `shadow`) не реже одного раза в квартал. Используйте `getent group <name>`.
4. **Безопасность /etc/gshadow:** Этот файл содержит пароли групп в зашифрованном виде. Убедитесь, что права на него — `640` или `400`, владелец `root:root` или `root:shadow`.
