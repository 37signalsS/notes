# Управление группами

## Определения

- **`groupadd`** — утилита для создания новой группы в системе
- **`groupmod`** — модификация параметров существующей группы (имя, GID)
- **`groupdel`** — удаление группы из системы
- **`gpasswd`** — управление членством в группах, назначение администраторов и паролей групп
- **`newgrp`** — смена первичной группы пользователя в текущей сессии оболочки

## Базовые концепции

### Типы членства в группах

1. **Первичная группа (Primary Group):** Основная группа пользователя, прописанная в файле `/etc/passwd`. Файлы, создаваемые пользователем, по умолчанию принадлежат этой группе.
2. **Дополнительные группы (Supplementary Groups):** Группы, в которые пользователь добавлен для получения прав доступа к ресурсам (файлам, устройствам, сервисам).

### Идентификаторы групп (GID)

Диапазоны GID обычно совпадают с диапазонами UID (системные, пользовательские). Подробную таблицу диапазонов см. в [определениях пользователей и групп](./users_definitions.md#диапазоны-uid-и-gid).

## Практические сценарии

### Создание и удаление групп

```bash
# Создание обычной группы
sudo groupadd developers

# Создание группы с конкретным GID
sudo groupadd -g 1500 developers

# Создание системной группы (GID < 1000)
sudo groupadd -r sysadmins

# Удаление группы
sudo groupdel developers
```

> **Важно:** Нельзя удалить группу, если она является первичной для любого из существующих пользователей.

### Модификация групп

```bash
# Изменение имени группы
sudo groupmod -n new-name old-name

# Изменение GID группы
sudo groupmod -g 1501 group-name
```

### Управление членством в группах

Существует несколько способов управления составом групп.

#### Добавление пользователя

```bash
# Рекомендуемый способ через usermod
# Ключ -a (append) обязателен, иначе пользователь будет удален из других доп. групп
sudo usermod -aG docker username

# Через gpasswd (альтернатива)
sudo gpasswd -a username docker
```

#### Удаление пользователя из группы

```bash
# Только через gpasswd
sudo gpasswd -d username docker
```

#### Массовое управление (через gpasswd)

```bash
# Установить список всех членов группы (заменяет текущий список)
sudo gpasswd -M user1,user2,user3 developers

# Назначить администратора группы
# Администратор группы может добавлять/удалять членов без прав root
sudo gpasswd -A username developers
```

### Просмотр информации о группах

```bash
# Проверка текущих групп пользователя
id
groups

# Проверка всех групп в системе
getent group

# Просмотр конкретной группы и её членов
getent group sudo

# Список групп конкретного пользователя
groups username
```

### Работа с сессиями (newgrp)

Команда `newgrp` позволяет временно сменить первичную группу пользователя без перелогина. Это полезно, когда нужно создать файлы с определенной групповой принадлежностью.

```bash
# Смена первичной группы на 'project'
newgrp project

# Теперь создаваемые файлы будут принадлежать группе project
touch test_file
ls -l test_file

# Для возврата к исходной группе завершите текущую оболочку (exit)
exit
```

## Дополнительная информация

### Привилегированные группы

| Группа | Назначение | Дистрибутивы |
| :--- | :--- | :--- |
| `wheel` | Доступ к выполнению команд через `sudo` | RHEL, CentOS, Fedora, Arch |
| `sudo` | Доступ к выполнению команд через `sudo` | Debian, Ubuntu |
| `docker` | Доступ к Docker daemon без root | Все, где установлен Docker |
| `kvm` | Доступ к аппаратной виртуализации | Все |
| `libvirt` | Управление виртуальными машинами | Все |
| `video` | Доступ к графическим устройствам | Все |
| `audio` | Доступ к звуковым картам | Все |

### Распространенные ошибки

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| Изменения групп не видны | Кэширование прав в текущей сессии | Необходимо перезайти в систему или использовать `newgrp` |
| `groupdel: group is the primary group of another user` | Группа является основной для пользователя | Измените первичную группу пользователя через `usermod -g` |
| `usermod -G` удалил из групп | Пропущен ключ `-a` | Всегда используйте `usermod -aG` для добавления групп |

### Лучшие практики

1. **Использование `usermod -aG`:** Всегда проверяйте наличие ключа `-a` при добавлении пользователя в дополнительные группы.
2. **Системные группы:** Для служебных нужд используйте ключ `-r` при создании группы, чтобы выделить ей ID из системного диапазона.
3. **Безопасность:** Регулярно проводите аудит членов групп `sudo`, `wheel` и `docker` (подробнее: [мониторинг пользователей](./user_monitoring.md)).
