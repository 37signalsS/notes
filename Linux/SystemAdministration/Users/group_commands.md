# Управление группами в Linux (Императивный подход)

## Определения

- **`groupadd`** — низкоуровневая утилита для создания новой группы в системе.
- **`groupmod`** — утилита для модификации параметров существующей группы (имя, GID).
- **`groupdel`** — утилита для удаления группы.
- **`gpasswd`** — многофункциональный инструмент для администрирования файлов `/etc/group` и `/etc/gshadow`. Позволяет управлять членством, назначать администраторов групп и устанавливать пароли групп.
- **`groupmems`** — специализированная утилита для управления списком членов группы, позволяющая делегировать права просмотра и изменения состава группы пользователям без полного доступа `sudo`.
- **`newgrp`** — команда для переключения первичной группы пользователя в текущей сессии оболочки (запускает новый экземпляр shell).
- **`sg`** (set group) — выполнение конкретной команды с временным переключением GID (без запуска интерактивной оболочки).
- **`systemd-userdbd`** — современный сервис-агрегатор (2025–2026), объединяющий информацию о группах из различных источников (локальные файлы, LDAP, systemd-homed) в единый API.

## Базовые концепции

### Типы и иерархия членства

1.  **Первичная группа (Primary Group)**: Указывается в `/etc/passwd`. Все файлы, создаваемые пользователем, по умолчанию наследуют GID этой группы. Современный стандарт — **UPG (User Private Groups)**, где для каждого пользователя создается уникальная группа с тем же именем.
2.  **Дополнительные группы (Supplementary Groups)**: Описываются в `/etc/group`. Служат для делегирования прав на специфические ресурсы (Docker, sudo, сетевые шары).

### Диапазоны идентификаторов (GID)

| Диапазон | Тип групп | Назначение |
| :--- | :--- | :--- |
| **0** | `root` | Полный контроль над системой. |
| **1–999** | Системные | Резервируются для служб и демонов (например, `dbus`, `nginx`). |
| **1000+** | Пользовательские | Создаются для реальных пользователей и проектов. |

*Подробнее см. раздел [Определения пользователей и групп](./users_definitions.md).*

## Практические сценарии

### Создание и удаление групп

```bash
# Создание обычной группы
sudo groupadd developers

# Создание группы с принудительным GID
sudo groupadd -g 2500 prod_admins

# Разрешение дублирования GID (аналог useradd -o)
sudo groupadd -o -g 1000 legacy_group

# Создание системной группы (выбор GID < 1000)
sudo groupadd -r _containers

# Удаление группы
sudo groupdel developers
```
> **Внимание:** Группа не может быть удалена, если она является первичной для любого пользователя в системе.

### Модификация параметров

```bash
# Смена имени группы
sudo groupmod -n dev_backend developers

# Смена GID существующей группы
sudo groupmod -g 2600 dev_backend

# Смена GID с разрешением дублирования
sudo groupmod -o -g 1000 dev_backend
```

### Управление составом и делегирование (gpasswd)

Утилита `gpasswd` является наиболее безопасным способом управления членством.

```bash
# Добавление пользователя (удобно для скриптов)
sudo gpasswd -a username docker

# Удаление пользователя
sudo gpasswd -d username docker

# Назначение АДМИНИСТРАТОРА группы
# Этот пользователь сможет добавлять/удалять членов через gpasswd БЕЗ sudo
sudo gpasswd -A team_lead developers

# Полная перезапись списка членов группы (очистка старых)
sudo gpasswd -M user1,user2,user3 developers
```

### Пароли групп и временный доступ

Используется для предоставления прав группы пользователям, не входящим в неё официально.

```bash
# Установка пароля группы
sudo gpasswd developers

# Удаление пароля группы (сброс к беспарольному доступу)
sudo gpasswd -r developers

# Вход в группу через пароль (создает новую оболочку)
newgrp developers
# → пароль запрашивается интерактивно
```

### Работа в текущей сессии (exec, sg)

Изменения групп не вступают в силу мгновенно в уже запущенных процессах.

```bash
# 1. Перезапуск оболочки с обновлением групп
exec su - $USER

# 2. Выполнение команды в контексте другой группы (без смены shell)
sg docker -c "docker images"

# 3. Проверка текущих эффективных групп
id -Gn
```

## Дополнительная информация

### Аудит и инспекция

Для глубокого анализа состава групп рекомендуется использовать:

```bash
# Просмотр всех групп (включая сетевые через NSS)
getent group

# Использование утилиты members (требует установки)
members developers
# → user1 user2 user3

# Проверка файлов конфигурации
cat /etc/group | grep developers
cat /etc/gshadow | grep developers
```

### Современные группы 2026

В актуальных дистрибутивах (Debian 13+, RHEL 9+) активно используются группы для управления аппаратным доступом:
- **`input`**: Доступ к устройствам ввода (клавиатуры, мыши).
- **`render` / `video`**: Прямой доступ к GPU (ускорение графики, AI-вычисления).
- **`kvm`**: Доступ к виртуализации.

### Безопасность /etc/gshadow

Файл `/etc/gshadow` хранит пароли групп и список администраторов в зашифрованном виде.
- **Права доступа**: Должны быть строго `640` или `400`.
- **Владелец**: `root:root` или `root:shadow`.
- **Рекомендация**: Если пароли групп не используются, убедитесь, что в поле пароля стоит `!`, что блокирует возможность входа через `newgrp`.
