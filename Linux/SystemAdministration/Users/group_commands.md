# Управление группами в Linux (Императивный подход)

## Определения

- **`groupadd`** — низкоуровневая утилита для создания новой группы в системе.
- **`groupmod`** — утилита для модификации параметров существующей группы (имя, GID).
- **`groupdel`** — утилита для удаления группы.
- **`gpasswd`** — многофункциональный инструмент для администрирования файлов `/etc/group` и `/etc/gshadow`. Позволяет управлять членством, назначать администраторов групп и устанавливать пароли групп.
- **`groupmems`** — специализированная утилита для управления списком членов группы, позволяющая делегировать права просмотра и изменения состава группы пользователям без полного доступа `sudo`.
- **`newgrp`** — команда для переключения первичной группы пользователя в текущей сессии оболочки (запускает новый экземпляр shell).
- **`sg`** (set group) — выполнение конкретной команды с временным переключением GID (без запуска интерактивной оболочки).
- **`vigr`** — безопасное редактирование `/etc/group` с блокировкой файла, предотвращающее одновременные изменения.
- **`grpck`** — утилита проверки целостности файлов `/etc/group` и `/etc/gshadow` на предмет дубликатов, битых ссылок и синтаксических ошибок.
- **`getent group`** — универсальная команда для получения списка групп через NSS (включая LDAP/SSSD), а не только локальные файлы.
- **`members`** — утилита для удобного вывода списка членов группы (не встроенная, требует установки `members` пакета).
- **`systemd-userdbd`** — современный сервис-агрегатор (2025–2026), объединяющий информацию о группах из различных источников (локальные файлы, LDAP, systemd-homed) в единый API.
- **`systemd-sysusers`** — декларативная утилита для создания групп через конфигурационные файлы в `/etc/sysusers.d/` (источник SSoT: **[systemd-sysusers](./systemd-sysusers.md)**).

## Базовые концепции

### Типы и иерархия членства

1.  **Первичная группа (Primary Group)**: Указывается в `/etc/passwd`. Все файлы, создаваемые пользователем, по умолчанию наследуют GID этой группы. Современный стандарт — **UPG (User Private Groups)**, где для каждого пользователя создается уникальная группа с тем же именем. *Подробнее:* [Приватные группы (UPG)](./user_private_groups.md).
2.  **Дополнительные группы (Supplementary Groups)**: Описываются в `/etc/group`. Служат для делегирования прав на специфические ресурсы (Docker, sudo, сетевые шары).
3.  **Эффективный GID (Effective GID)**: GID процесса, который используется при проверке прав на файлы и ресурсы. При запуске процесса с SGID-битом или через `newgrp`/`sg` эффективный GID может временно меняться.
4.  **Сохраненный GID (Saved GID)**: Резервная копия реального GID, позволяющая процессу возвращаться к исходным правам после временного повышения привилегий.

### Диапазоны идентификаторов (GID)

| Диапазон | Тип групп | Назначение |
| :--- | :--- | :--- |
| **0** | `root` | Полный контроль над системой. |
| **1–999** | Системные | Резервируются для служб и демонов (например, `dbus`, `nginx`). |
| **1000+** | Пользовательские | Создаются для реальных пользователей и проектов. |

*Подробнее см. раздел [Определения пользователей и групп](./users_definitions.md).*

### Структура файла /etc/gshadow

Файл `/etc/gshadow` является защищенной копией `/etc/group`, содержащей зашифрованные пароли и список администраторов групп. Он существует для предотвращения несанкционированного чтения паролей групп через world-readable `/etc/group`.

**Формат:** `group_name:password:admins:members`

| Поле | Описание | Пример |
| :--- | :--- | :--- |
| **group_name** | Имя группы | `developers` |
| **password** | Зашифрованный пароль | `$6$rounds=100000$...` или `!` (заблокировано) |
| **admins** | Список администраторов группы (через запятую) | `alice,bob` |
| **members** | Полный список членов группы | `alice,bob,charlie` |

> **Важно:** Пароли групп редко используются в современных системах. Рекомендуется устанавливать `!` в поле пароля, чтобы предотвратить аутентификацию через `newgrp`.

### Иерархия членства и права

Группы в Linux реализуют иерархическую модель доступа:

1.  **Первичная группа** определяет владельца создаваемых файлов (GID in `/etc/passwd`).
2.  **Дополнительные группы** расширяют права на чтение/запись существующих ресурсов.
3.  **Эффективные права** процесса определяются пересечением прав всех групп, в которых состоит процесс (primary + supplementary).

**Пример:**
```bash
# Пользователь alice: primary=alice(1001), supplementary=docker(1002), sudo(27)
# При создании файла: владелец=alice:alice
# При доступе к /var/run/docker.sock: проверяется членство в docker
```

### Name Service Switch (NSS) и группы

Группы могут храниться не только в `/etc/group`, но и в LDAP, NIS или других источниках. NSS определяет порядок поиска:

```bash
# Пример /etc/nsswitch.conf
group: files sss
```

При вызове `getent group` система проверяет источники в указанном порядке. Если группа найдена в `files` (`/etc/group`), поиск прекращается. Если нет — обращается к `sss` (SSSD/LDAP).

*Подробнее см. раздел [Файлы конфигурации](./users_config_files.md).*

### Делегирование управления группами

Linux поддерживает три уровня привилегий для управления группами:

1.  **Суперпользователь (root)**: Полный доступ через `sudo groupadd`, `sudo gpasswd`.
2.  **Администратор группы**: Пользователь, назначенный через `gpasswd -A`, может добавлять/удалять членов БЕЗ sudo.
3.  **Обычный пользователь**: Может временно получить доступ через `newgrp` (если знает пароль группы) или запросить добавление у администратора.

Эта модель позволяет реализовать самообслуживание: администраторы инфраструктуры делегируют права на управление группами проектов тимлидам, не предоставляя полный sudo.

## Практические сценарии

### Безопасное редактирование и проверка целостности

Для предотвращения повреждения баз данных при одновременном редактировании используйте `vigr`:

```bash
# Безопасное редактирование /etc/group
sudo vigr

# Безопасное редактирование /etc/gshadow
sudo vigr -s
```

Эти утилиты блокируют файлы (`/etc/group.lock`) на время редактирования, предотвращая race conditions.

```bash
# Проверка /etc/group и /etc/gshadow на дубликаты и битые ссылки
sudo grpck -r

# Проверка с автоматическим исправлением (осторожно!)
sudo grpck -r -s
```

Флаг `-r` включает только чтение (dry-run), не внося исправлений автоматически.

### Создание и удаление групп

```bash
# Создание обычной группы
sudo groupadd developers

# Создание группы с принудительным GID
sudo groupadd -g 2500 prod_admins

# Разрешение дублирования GID (аналог useradd -o)
sudo groupadd -o -g 1000 legacy_group

# Создание системной группы (выбор GID < 1000)
sudo groupadd -r _containers

# Удаление группы
sudo groupdel developers
```
> **Внимание:** Группа не может быть удалена, если она является первичной для любого пользователя в системе.

### Модификация параметров

```bash
# Смена имени группы
sudo groupmod -n dev_backend developers

# Смена GID существующей группы
sudo groupmod -g 2600 dev_backend

# Смена GID с разрешением дублирования
sudo groupmod -o -g 1000 dev_backend
```

### Управление составом и делегирование (gpasswd)

Утилита `gpasswd` является наиболее безопасным способом управления членством.

```bash
# Добавление пользователя (удобно для скриптов)
sudo gpasswd -a username docker

# Удаление пользователя
sudo gpasswd -d username docker

# Назначение АДМИНИСТРАТОРА группы
# Этот пользователь сможет добавлять/удалять членов через gpasswd БЕЗ sudo
sudo gpasswd -A team_lead developers

# Полная перезапись списка членов группы (очистка старых)
sudo gpasswd -M user1,user2,user3 developers
```

### Делегирование через groupmems

Утилита `groupmems` позволяет пользователям управлять своей первичной группой (UPG) без sudo:

```bash
# Просмотр членов своей группы (для пользователя без sudo)
groupmems -g alice -l

# Добавление пользователя в свою первичную группу
groupmems -g alice -a bob

# Удаление пользователя из своей первичной группы
groupmems -g alice -d bob
```

> **Примечание:** `groupmems` работает только с первичной группой пользователя. Для управления другими группами требуется `gpasswd` или `sudo`.

### Пароли групп и временный доступ

Используется для предоставления прав группы пользователям, не входящим в неё официально.

```bash
# Установка пароля группы
sudo gpasswd developers

# Удаление пароля группы (сброс к беспарольному доступу)
sudo gpasswd -r developers

# Вход в группу через пароль (создает новую оболочку)
newgrp developers
# → пароль запрашивается интерактивно
```

### Инспекция и фильтрация через getent

Для работы с группами из LDAP/SSSD используйте `getent` вместо прямого чтения `/etc/group`:

```bash
# Список ВСЕХ групп (локальных + сетевых через NSS)
getent group

# Фильтрация конкретной группы (работает с LDAP)
getent group developers

# Извлечение списка членов группы
getent group developers | cut -d: -f4

# Список всех групп, в которых состоит пользователь (включая LDAP)
getent group | grep -E '^[^:]+:.+:.*username'

# Поиск групп по GID
getent group 2500
```

### Массовое управление группами

```bash
# Создание нескольких групп из списка
for g in developers qa devops; do
    sudo groupadd "$g"
done

# Массовое добавление пользователя в группы
USERNAME=alice
for g in developers qa devops; do
    sudo gpasswd -a "$USERNAME" "$g"
done

# Массовое удаление пользователя из всех дополнительных групп
# (сохраняет только первичную группу)
USERNAME=alice
PRIMARY_GID=$(id -g "$USERNAME")
for g in $(id -Gn "$USERNAME"); do
    if [ "$g" != "$PRIMARY_GID" ] && [ "$g" != "$(id -gn "$USERNAME")" ]; then
        sudo gpasswd -d "$USERNAME" "$g" 2>/dev/null || true
    fi
done
```

### Управление квотами группы (Project Quotas)

Для ограничения места на диске для группы используйте project quotas (XFS/ext4):

```bash
# Включение project quotas на XFS
sudo mount -o remount,prjquota /

# Создание проекта
echo "10000:/srv/projects/alpha" | sudo tee -a /etc/projects
echo "alpha:10000" | sudo tee -a /etc/projid

# Установка квот
sudo xfs_quota -x -c 'limit -p bsoft=10G bhard=15G alpha' /srv

# Проверка квот
sudo xfs_quota -x -c 'report -p' /srv
```

### Временный доступ через newgrp и sg

```bash
# 1. Переключение на группу в текущей сессии (интерактивно)
newgrp developers
# → Если у группы есть пароль, запрашивается ввод
id
# → gid=2500(developers)

# 2. Выполнение команды с временным GID (без смены shell)
sg docker -c "docker images"

# 3. Возврат к исходной группе (выход из newgrp)
exit

# 4. Проверка текущих эффективных групп
id -Gn
```

### Работа в текущей сессии (exec, sg)

Изменения групп не вступают в силу мгновенно в уже запущенных процессах.

```bash
# 1. Перезапуск оболочки с обновлением групп
exec su - $USER

# 2. Выполнение команды в контексте другой группы (без смены shell)
sg docker -c "docker images"

# 3. Проверка текущих эффективных групп
id -Gn
```

### Декларативное управление группами (systemd-sysusers)

Для создания групп через конфигурационные файлы используйте `systemd-sysusers`:

```bash
# /etc/sysusers.d/infra.conf
# Тип g = создать только группу
g _audit-logs - -
# Тип m = добавить пользователя в группу
m _web-app _audit-logs
# Резервирование ID
r _legacy-service 500-510

# Применение
sudo systemd-sysusers --dry-run
sudo systemd-sysusers

# Проверка
getent group _audit-logs
```

*Подробнее см. раздел [systemd-sysusers](./systemd-sysusers.md).*

### Сценарий автоматизации массового создания

```bash
#!/bin/bash
# create_groups.sh — создание групп из CSV
# Формат: group_name,gid,members

while IFS=, read -r group_name gid members; do
    # Создание группы
    if ! getent group "$group_name" &>/dev/null; then
        if [ -n "$gid" ]; then
            sudo groupadd -g "$gid" "$group_name"
        else
            sudo groupadd "$group_name"
        fi
        echo "Создана группа: $group_name"
    else
        echo "Группа $group_name уже существует"
    fi

    # Добавление членов
    if [ -n "$members" ]; then
        IFS=',' read -ra USER_LIST <<< "$members"
        for user in "${USER_LIST[@]}"; do
            sudo gpasswd -a "$user" "$group_name"
        done
        echo "Добавлены члены: $members"
    fi
done < groups.csv
```

### Современные группы 2026

В актуальных дистрибутивах (Debian 13+, RHEL 9+) активно используются группы для управления аппаратным доступом:
- **`input`**: Доступ к устройствам ввода (клавиатуры, мыши).
- **`render` / `video`**: Прямой доступ к GPU (ускорение графики, AI-вычисления).
- **`kvm`**: Доступ к виртуализации.

### Безопасность /etc/gshadow

Файл `/etc/gshadow` хранит пароли групп и список администраторов в зашифрованном виде.
- **Права доступа**: Должны быть строго `640` или `400`.
- **Владелец**: `root:root` или `root:shadow`.
- **Рекомендация**: Если пароли групп не используются, убедитесь, что в поле пароля стоит `!`, что блокирует возможность входа через `newgrp`.

### Troubleshooting

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `groupadd: GID уже существует` | Попытка занять GID без флага `-o`. | Используйте `-o` или автовыбор. |
| `groupdel: cannot remove user's primary group` | Группа является первичной для пользователя. | Сначала смените первичную группу пользователя через `usermod -g`. |
| `gpasswd: user unknown` | Пользователь не существует в NSS. | Проверьте `getent passwd username`. |
| `newgrp: authentication failure` | Неверный пароль группы или PAM блокировка. | Проверьте пароль через `sudo gpasswd developers` или используйте `getent group`. |
| `grpck: group 'x' has a duplicate entry` | Дублирование группы в `/etc/group` и `/etc/gshadow`. | Удалите дубликат через `vigr` или `grpck -s`. |
| `groupmems: Permission denied` | Пользователь не является членом группы или группа не существует. | Проверьте членство через `id -Gn`. |
| `Permission denied` при работе с `docker` | Пользователь не добавлен в группу `docker`. | `sudo gpasswd -a username docker` и перелогин/`exec su - $USER`. |
| `sg: unknown group` | Группа не найдена в NSS. | Проверьте `getent group groupname`. |

### Лучшие практики (2026)

1.  **Декларативность:** Для системных групп всегда используйте **[systemd-sysusers](./systemd-sysusers.md)** с типом записи `g`.
2.  **UPG:** Следуйте архитектуре User Private Groups — каждый пользователь = уникальная группа.
3.  **Именование:** Системные группы должны начинаться с `_` (например, `_nginx`).
4.  **Безопасное редактирование:** Всегда используйте `vigr` вместо прямого редактирования `/etc/group`.
5.  **Целостность:** Периодически запускайте `grpck -r` для проверки баз данных.
6.  **NSS:** Используйте `getent group` вместо `cat /etc/group` в скриптах для поддержки LDAP/SSSD.
7.  **Делегирование:** Назначайте администраторов групп через `gpasswd -A` вместо предоставления полного sudo.
8.  **Пароли групп:** Отключайте пароли групп (`gpasswd -r`) — они устарели и небезопасны.
9.  **Квоты:** Настраивайте project quotas для групп с большими объемами данных.
10. **Аудит:** Логируйте изменения через `auditd`: `sudo auditctl -w /etc/group -p wa -k group_modification`.

### Compliance-проверки

```bash
# CIS Benchmark: Поиск групп с GID 0
awk -F: '($3 == 0) {print $1}' /etc/group

# Поиск групп с паролем (не заблокированы)
sudo awk -F: '($2 != "" && $2 != "!" && $2 != "*") {print $1}' /etc/gshadow

# Проверка групп с множественными администраторами
sudo awk -F: '($3 != "" && $3 != "!") {print $1, $3}' /etc/gshadow

# Поиск пользователей с несколькими группами (возможная избыточность)
getent passwd | awk -F: '{print $1, $4}' | while read user gid; do
    supplementary=$(id -Gn "$user" | wc -w)
    if [ "$supplementary" -gt 5 ]; then
        echo "Пользователь $user состоит в $supplementary группах"
    fi
done
```
