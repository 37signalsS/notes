# Приватные группы пользователей (UPG)

## Определения

- **UPG (User Private Groups)** — схема организации групп в Linux, при которой для каждого нового пользователя автоматически создается персональная группа с идентичным именем и идентификатором (UID = GID).
- **Первичная группа (Primary Group)** — группа, идентификатор которой указан в файле `/etc/passwd`. Все файлы, создаваемые пользователем, по умолчанию наследуют GID этой группы.
- **`umask` (User File-Creation Mask)** — системная маска, определяющая права доступа, которые **не будут** установлены для новых файлов и директорий.
- **SGID (Set Group ID) на директорию** — специальный бит прав доступа (значение `2` в восьмеричном представлении), гарантирующий, что все новые объекты внутри директории будут наследовать её группу, а не первичную группу создателя.
- **USERGROUPS_ENAB** — параметр в `/etc/login.defs`, управляющий автоматическим созданием группы при создании пользователя и её удалением при ликвидации аккаунта.

## Базовые концепции

### Механизм работы и архитектурная цель UPG

Традиционная модель Unix использовала общие группы (например, `users` или `staff`) в качестве первичных. Это создавало дилемму безопасности:
1.  При `umask 022` файлы защищены от записи коллегами по группе, но совместная работа в общих папках требует ручного изменения прав (`chmod g+w`).
2.  При `umask 002` (права на запись для группы по умолчанию) файлы в домашних директориях пользователей становились уязвимы для всех членов общей группы `users`.

Схема UPG устраняет этот конфликт через связку **«Персональная группа + umask 002»**:
- Поскольку пользователь является единственным членом своей первичной группы, `umask 002` (права `rw-rw-r--`) абсолютно безопасен в его домашней директории.
- При переходе в общую проектную директорию с установленным битом **SGID**, тот же `umask 002` позволяет пользователям мгновенно обмениваться файлами с правом на запись, так как новые файлы автоматически получают GID проекта.

### Ключевые параметры конфигурации

Поведение подсистемы определяется в файле `/etc/login.defs`:

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| **`USERGROUPS_ENAB`** | `yes` | При создании пользователя `useradd` создаст группу с тем же именем. При удалении пользователя `userdel` удалит группу, если в ней не осталось других членов. |
| **`USERGROUPS_MOD`** | `002` | Если параметр установлен, то при совпадении UID и GID система будет использовать `umask 002` вместо дефолтного `022`. |

## Практические сценарии

### Диагностика и проверка состояния

```bash
# Проверка текущих идентификаторов и членства
id
# → uid=1001(alice) gid=1001(alice) groups=1001(alice),27(sudo)

# Проверка маски в текущей сессии
umask
# → 0002

# Проверка записей в системных базах (совпадение UID/GID)
grep "alice" /etc/passwd
# alice:x:1001:1001::/home/alice:/bin/bash

grep "alice" /etc/group
# alice:x:1001:
```

### Организация совместной работы (Модель UPG + SGID)

Это основной технический сценарий, ради которого внедрялась схема UPG.

```bash
# 1. Подготовка группы проекта и участников
sudo groupadd developers
sudo usermod -aG developers alice
sudo usermod -aG developers bob

# 2. Создание общей директории с правильными атрибутами
sudo mkdir -p /srv/shared_dev
sudo chown root:developers /srv/shared_dev

# 3. Установка SGID бита и прав доступа
# 2000 — SGID, 775 — rwxrwxr-x
sudo chmod 2775 /srv/shared_dev

# 4. Проверка совместной работы
# От имени alice:
touch /srv/shared_dev/config.yaml
# Файл автоматически получит группу developers и права -rw-rw-r--
# Bob сможет редактировать этот файл без дополнительных chmod/chgrp
```

### Ручное управление и исключения

В некоторых случаях требуется обойти механизм UPG (например, при миграции со старых систем или интеграции с жестко заданными правилами AD).

```bash
# Создание пользователя без приватной группы (флаг -N)
# В этом случае будет использована группа из /etc/default/useradd (обычно users или 100)
sudo useradd -N legacy_user

# Создание пользователя с принудительным назначением конкретной группы
sudo useradd -g users common_user

# Отключение UPG глобально
# В /etc/login.defs установите: USERGROUPS_ENAB no
```

### Автоматизация: Скрипт создания пользователя с проверкой UPG

```bash
#!/bin/bash
# create_user_safe.sh - автоматизация с учетом UPG

USERNAME=$1
COMMENT=$2

if [[ -z "$USERNAME" ]]; then
    echo "Использование: $0 <username> [комментарий]"
    exit 1
fi

# Проверка глобальной настройки
UPG_ENABLED=$(grep "^USERGROUPS_ENAB" /etc/login.defs | awk '{print $2}')
echo "Статус USERGROUPS_ENAB: $UPG_ENABLED"

# Создание пользователя
sudo useradd -m -c "$COMMENT" "$USERNAME"

# Техническая проверка результата
UID_VAL=$(id -u "$USERNAME")
GID_VAL=$(id -g "$USERNAME")

if [ "$UID_VAL" -eq "$GID_VAL" ]; then
    echo "OK: Схема UPG применена (UID $UID_VAL = GID $GID_VAL)"
else
    echo "WARNING: Схема UPG не сработала. UID($UID_VAL) != GID($GID_VAL)"
fi
```

## Дополнительная информация

### Технические рекомендации по применению

| Сценарий | Стратегия | Техническое обоснование |
| :--- | :--- | :--- |
| **Рабочие станции** | UPG + umask 002 | Стандартная изоляция данных пользователя при сохранении гибкости. |
| **Серверы приложений** | UPG (для каждого сервиса) | Гарантирует, что лог-файлы или кэш одного сервиса (например, `_nginx`) не будут доступны на запись другому (`_php-fpm`). |
| **Файловые серверы (NFS/SMB)** | UPG + SGID + ACL | Позволяет избежать «ада прав», когда новые файлы в общих папках становятся read-only для коллег. |
| **Интеграция с доменом (AD/IPA)** | Отключение UPG | В доменах используются централизованные GID. Локальные UPG могут вызвать конфликты при маппинге ID. |

### Инструменты аудита и поиска аномалий

Полезные `awk`-скрипты для проверки чистоты структуры:

```bash
# Поиск пользователей, у которых первичная группа не совпадает с именем пользователя (отход от UPG)
awk -F: '$1 != $4 {print "Аномалия: пользователь " $1 " имеет первичную группу " $4}' /etc/passwd

# Проверка групп в /etc/group, содержащих более одного участника (не являются приватными)
awk -F: 'NF==4 && $4!="" {n=split($4,a,","); if(n>1) print "Группа " $1 " имеет " n " участников: " $4}' /etc/group
```

### Тренды (2025–2026)

Современные системы всё чаще используют декларативные методы управления группами. Утилита **`systemd-sysusers`** по умолчанию реализует логику UPG при создании системных аккаунтов (тип `u`), создавая пару пользователь-группа с идентичным ID. Это подтверждает жизнеспособность архитектуры UPG как метода минимизации привилегий и упрощения прав доступа.
