# Приватные группы пользователей (UPG)

## Определения

- **UPG (User Private Groups)** — схема именования и организации групп в Linux, при которой для каждого нового пользователя автоматически создаётся отдельная группа с тем же именем.
- **Первичная группа (Primary Group)** — основная группа пользователя, идентификатор которой (GID) указан в файле `/etc/passwd`. Все файлы, создаваемые пользователем, по умолчанию наследуют идентификатор этой группы.
- **USERGROUPS** — параметр в конфигурационном файле `/etc/login.defs`, определяющий, будет ли автоматически создаваться приватная группа для нового пользователя.

## Базовые концепции

### Механизм работы UPG

Схема UPG была введена для упрощения управления правами доступа в многопользовательских средах. При создании пользователя без явного указания группы:

1. Система автоматически создаёт группу, имя которой совпадает с именем пользователя.
2. Эта группа назначается пользователю в качестве первичной.
3. По умолчанию **GID (Group ID)** этой группы совпадает с **UID (User ID)** пользователя.

**Пример:**

```bash
# Создание пользователя
sudo useradd alice

# Результат автоматической настройки:
# Пользователь: alice (UID 1001)
# Первичная группа: alice (GID 1001)
```

### Проверка конфигурации

Для проверки работы механизма UPG в системе используются следующие команды:

```bash
# Проверка глобальной настройки в login.defs
grep USERGROUPS /etc/login.defs
# USERGROUPS_ENAB yes — автоматическое создание включено

# Проверка идентификаторов пользователя
id alice
# uid=1001(alice) gid=1001(alice) groups=1001(alice)

# Проверка записей в системных файлах
grep alice /etc/passwd
# alice:x:1001:1001::/home/alice:/bin/bash

grep alice /etc/group
# alice:x:1001:
```

## Практические сценарии

### Отключение и настройка общих групп

В некоторых корпоративных средах использование UPG может быть нежелательным в пользу общих групп (например, `users`).

```bash
# Создание пользователя без приватной группы (флаг -N)
sudo useradd -N username

# Глобальное отключение в /etc/login.defs
# Измените на: USERGROUPS_ENAB no

# Создание пользователя с принудительным назначением общей группы
sudo groupadd developers
sudo useradd -g developers username
```

### Совместная работа и общие директории

Главный недостаток UPG проявляется при совместной работе: созданные пользователем файлы недоступны участникам других групп по умолчанию.

**Решение 1: Использование SGID (Set Group ID) на директории**

Бит **SGID (Set Group ID)** заставляет все файлы внутри директории наследовать группу самой директории, а не первичную группу создателя.

```bash
# Создание общей директории и группы проекта
sudo mkdir /shared/project
sudo groupadd project

# Установка владельца и SGID бита
sudo chown root:project /shared/project
sudo chmod 2775 /shared/project # 2 — это SGID бит

# Добавление пользователей в группу проекта
sudo usermod -aG project alice
sudo usermod -aG project bob

# Теперь файлы, созданные alice или bob, будут принадлежать группе project
```

**Решение 2: Смена первичной группы пользователя**

```bash
# Смена основной группы пользователя
sudo usermod -g project alice

# Проверка изменений
id alice
# uid=1001(alice) gid=1002(project) groups=1002(project),1001(alice)
```

### Автоматизация управления UPG

Скрипт для корректного создания пользователя с проверкой UPG:

```bash
#!/bin/bash
# create_user.sh

USERNAME=$1
COMMENT=$2

if [[ -z "$USERNAME" ]]; then
    echo "Использование: $0 <username> [комментарий]"
    exit 1
fi

# Создание пользователя (UPG применяется автоматически при USERGROUPS_ENAB=yes)
sudo useradd -m -c "$COMMENT" "$USERNAME"

# Проверка результата
if id "$USERNAME" &>/dev/null; then
    echo "Пользователь $USERNAME успешно создан"
    echo "UID/GID: $(id -u $USERNAME)/$(id -g $USERNAME)"
else
    echo "Ошибка при создании пользователя"
    exit 1
fi
```

## Дополнительная информация

### Лучшие практики и аудит

#### Рекомендации по использованию

| Сценарий | Рекомендация |
| :--- | :--- |
| **Персональные системы** | UPG является стандартом и не требует изменений. |
| **Серверы приложений** | UPG обеспечивает изоляцию сервисных аккаунтов. |
| **Файловые серверы** | Используйте SGID в сочетании с общими группами. |
| **Интеграция с AD/LDAP** | Обычно используются централизованные группы, UPG отключается. |

#### Инструменты аудита

Полезные команды для проверки целостности структуры групп:

```bash
# Поиск пользователей, у которых первичная группа не совпадает с их именем
awk -F: '$1 != $4 {print $1}' /etc/passwd

# Проверка групп, содержащих более одного участника
awk -F: 'NF==4 && $4!="" {n=split($4,a,","); if(n>1) print $1, n, $4}' /etc/group
```

#### Настройка umask

Для корректной совместной работы при использовании UPG часто рекомендуется устанавливать `umask 002`.

```bash
# Глобальная настройка в /etc/login.defs
USERGROUPS_MOD 002
```
