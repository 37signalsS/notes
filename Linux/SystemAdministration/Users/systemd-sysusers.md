# Декларативное управление пользователями (systemd-sysusers)

## Определения

- **systemd-sysusers** — системная утилита и одноименная служба, предназначенные для создания системных пользователей и групп на основе декларативных конфигурационных файлов.
- **sysusers.d** — формат и набор директорий (`/usr/lib/sysusers.d/`, `/etc/sysusers.d/`), где хранятся описания необходимых пользователей.
- **Идемпотентность** — свойство утилиты, позволяющее запускать её многократно без риска дублирования записей или изменения уже корректно настроенных идентификаторов.

## Основные концепции

В отличие от традиционных императивных команд (`useradd`), `systemd-sysusers` реализует декларативный подход: администратор описывает *желаемое состояние* (какие пользователи должны быть), а система гарантирует их наличие.

### Ключевые особенности (2025–2026)
1. **Воспроизводимость:** Гарантирует идентичный набор системных аккаунтов на всех узлах кластера или парка машин.
2. **Иммутабельность:** Основной инструмент для систем с неизменяемой корневой ФС (Fedora CoreOS, Silverblue), где `/etc/passwd` может быть защищен от прямой записи.
3. **Отложенная инициализация:** Пользователи создаются в момент первой загрузки или при выполнении команды, что упрощает сборку минимальных образов ОС.
4. **Интеграция с пакетами:** Разработчики ПО поставляют `.conf` файлы вместе с бинарными файлами, избавляя скрипты установки от необходимости ручного управления пользователями.
5. **Безопасность по умолчанию:** Создаваемые аккаунты автоматически получают `/usr/sbin/nologin` в качестве оболочки, если не указано иное.

### Механизм выбора идентификаторов
Утилита работает преимущественно в системном диапазоне (обычно UID < 1000). Если конкретный UID не указан, `systemd-sysusers` выберет первый свободный номер, начиная сверху диапазона (например, 999, 998...). Это минимизирует конфликты с пользователями, созданными вручную.

## Формат конфигурации

Файлы в `sysusers.d` состоят из строк, определяющих типы объектов и их атрибуты.

| Поле | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| **Type** | Тип записи (`u`, `g`, `m`, `r`). | — |
| **Name** | Имя пользователя или группы. | — |
| **ID** | UID/GID (число, `-` для автовыбора, или путь к файлу). | Автовыбор |
| **GECOS** | Описание (комментарий) в кавычках. | `System user/group` |
| **Home** | Домашняя директория. | `/` |
| **Shell** | Командная оболочка. | `/usr/sbin/nologin` |

### Типы записей
- **`u`**: Создать пользователя и первичную группу с тем же именем.
- **`g`**: Создать только группу.
- **`m`**: Добавить существующего пользователя в группу (членство).
- **`r`**: Зарезервировать диапазон UID/GID.

## Практические сценарии

### 1. Создание пользователя для фонового сервиса
Создадим пользователя `_web-app` с выделенной домашней директорией.

```bash
# /etc/sysusers.d/web-app.conf
u _web-app - "Web Application Service" /var/lib/web-app
```

### 2. Применение конфигурации на лету
Хотя система применяет настройки при загрузке, администратор может сделать это вручную:

```bash
# Проверка и создание
sudo systemd-sysusers
# → Creating group _web-app with gid 975.
# → Creating user _web-app (Web Application Service) with uid 975 and gid 975.

# Проверка создания через системный инструмент
id _web-app
# → uid=975(_web-app) gid=975(_web-app) groups=975(_web-app)
```

### 3. Управление членством в группах

```bash
# /etc/sysusers.d/groups.conf
g _audit-logs - -
m _web-app _audit-logs
# → Пользователь _web-app будет добавлен в дополнительную группу _audit-logs
```

### 4. Создание пользователя с конкретным ID
Используется для синхронизации ID в сетевых файловых системах (NFS) или контейнерах.

```bash
u _nfs-worker 450 "NFS Worker" /var/nfs -
```

## Дополнительная информация

### Иерархия и приоритеты
Systemd обрабатывает файлы в лексикографическом порядке (по имени) из следующих директорий (в порядке возрастания приоритета):
1. `/usr/lib/sysusers.d/` — настройки от дистрибутива и пакетов (не изменять).
2. `/run/sysusers.d/` — временные настройки (создаваемые в рантайме).
3. `/etc/sysusers.d/` — локальные настройки администратора (**наивысший приоритет**).

> **Совет:** Если в `/etc/` создать файл с тем же именем, что и в `/usr/lib/`, локальный файл полностью переопределит системный. Пустой файл в `/etc/` — способ "маскировки" (отключения) системного правила.

### Взаимодействие с systemd-tmpfiles
`systemd-sysusers` только создает записи в базе данных пользователей (`/etc/passwd`, `/etc/group`). Для автоматического создания домашних директорий с правильными правами доступа необходимо использовать [systemd-tmpfiles](../../Core/systemd/tmpfiles.md).

### Сравнение подходов

| Критерий | useradd (Императивный) | systemd-sysusers (Декларативный) |
| :--- | :--- | :--- |
| **Место вызова** | Скрипты (bash, python) | Статические файлы конфигурации |
| **Удаление** | `userdel` удаляет запись | Удаление файла **не удаляет** пользователя автоматически |
| **Идемпотентность** | Требует проверки `if id user...` | Встроена (просто игнорирует существующие) |
| **Целостность** | Риск "загрязнения" системы скриптами | Чистая база данных, управляемая конфигами |
