# Информация о системе Linux

## Определения

- **Системная информация:** Совокупность данных о конфигурации, состоянии и характеристиках программного и аппаратного обеспечения узла.
- **DMI (Desktop Management Interface) / SMBIOS:** Стандарт описания компонентов компьютера (BIOS, материнская плата, процессоры, память), доступный через таблицы в памяти.
- **Виртуальные файловые системы:** Механизмы ядра (`/proc`, `/sys`) для предоставления системных данных в виде текстовых файлов.

## Основные концепции

### Источники системной информации

Получение данных в Linux осуществляется через несколько уровней:

- **Интерфейсы ядра:** Прямое чтение из `/proc` (состояние процессов и параметры ядра) и `/sys` (атрибуты оборудования и драйверов).
- **Таблицы DMI:** Чтение низкоуровневых спецификаций оборудования, прошитых производителем.
- **Журналы событий:** Анализ сообщений ядра через `dmesg` для выявления событий инициализации и ошибок.
- **Служебные утилиты:** Инструменты (`hostnamectl`, `timedatectl`, `systemctl`), предоставляющие высокоуровневый интерфейс к системным настройкам.

### Особенности в виртуальных средах

На виртуальных машинах (VM) информация об оборудовании часто является эмулированной или абстрагированной гипервизором:

- Модель CPU может отображаться как "Common KVM processor".
- Серийные номера и производители оборудования могут указывать на вендора виртуализации (VMware, QEMU).
- Датчики температуры и напряжения обычно недоступны или показывают фиктивные значения.

## Практические сценарии

### 1. Версия ядра и дистрибутива

Для идентификации программного окружения используются следующие файлы и команды:

```bash
# Подробная информация о ядре (версия, архитектура, дата сборки)
uname -a

# Информация о дистрибутиве (стандарт LSB)
cat /etc/os-release

# Информация о ядре и версии компилятора
cat /proc/version
```

### 2. Управление именем хоста (Hostname)

Современным стандартом управления именем узла является `hostnamectl`.

```bash
# Просмотр текущего статуса (Hostname, OS, Kernel, Architecture)
hostnamectl

# Установка нового имени хоста (вносит изменения в /etc/hostname)
sudo hostnamectl set-hostname new-nodename
```

**Примечание:** После изменения имени хоста рекомендуется обновить файл `/etc/hosts`, чтобы избежать задержек при разрешении локального имени (локальная петля `127.0.1.1` или `127.0.0.1`).

### 3. Время работы и нагрузка (Uptime, Load Average)

Базовые показатели состояния системы — время непрерывной работы и средняя загрузка:

```bash
# Время работы, количество пользователей, LA за 1/5/15 минут
uptime
# → 12:17:58 up 111 days, 31 min,  1 user,  load average: 0.00, 0.01, 0.05

# Количество логических CPU (для интерпретации LA)
nproc
# → 4
```

Подробная интерпретация Load Average: [Планирование процессов: LA](../Core/processes/scheduling.md#интерпретация-load-average).

### 4. Состояние системы и уровни выполнения

В системах с systemd управление целевыми состояниями (таргетами) заменило традиционные runlevels.

```bash
# Текущий таргет по умолчанию (графический или консольный)
systemctl get-default

# Просмотр текущего состояния и предыдущего runlevel (для совместимости)
runlevel
```

Подробнее: [Юниты и таргеты systemd](../Core/systemd/systemd_units_overview.md).

### 5. Аппаратное обеспечение (Сводка)

Для детальной инвентаризации оборудования используйте специализированные инструменты.

- **Процессор (CPU):** Архитектура, ядра, кэш и частота.
  - Команда: `lscpu`
  - Подробно: [Диагностика CPU](../Diagnostics/Hardware/cpu_info.md).
- **Оперативная память (RAM):** Объем, слоты, тип и частота модулей.
  - Команда: `sudo dmidecode --type memory`
  - Мониторинг использования: [Статистика памяти](../Diagnostics/Memory/proc_meminfo.md).
- **Шины и периферия (PCI/USB):**
  - Команды: `lspci`, `lsusb`.
  - Подробно: [Инвентаризация оборудования](../Diagnostics/Hardware/hardware_listing.md).
- **Дисковая подсистема:** Блочные устройства, разделы и топология.
  - Команда: `lsblk`
  - Здоровье дисков: [Мониторинг SMART](../Diagnostics/Hardware/smartctl/index.md).

### 6. Датчики и аппаратный мониторинг

Для получения данных о температуре, напряжении и оборотах вентиляторов требуется пакет `lm-sensors`.

```bash
# Опрос доступных датчиков
sensors

# Сброс и повторное обнаружение датчиков (требует root)
sudo sensors-detect
```

На серверном оборудовании данные датчиков доступны через интерфейс управления IPMI:

```bash
# Просмотр параметров через ipmitool
sudo ipmitool sensor list
```
