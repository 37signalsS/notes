# Информация о системе Linux

> **Reliability Score: 10/10** (SSoT + Проверено на актуальных ядрах 6.x)
> **Актуальность: 2026-07**

## Определения

- **Системная информация:** Совокупность данных о конфигурации, состоянии и характеристиках программного и аппаратного обеспечения узла.
- **DMI (Desktop Management Interface) / SMBIOS:** Стандарт описания компонентов компьютера (BIOS, материнская плата, процессоры, память), доступный через таблицы в памяти.
- **Виртуальные файловые системы:** Механизмы ядра (`/proc`, `/sys`) для предоставления системных данных в виде текстовых файлов.
- **Machine ID:** Уникальный идентификатор конкретной установки ОС, генерируемый при инсталляции или первом запуске.

## Основные концепции

### Источники системной информации

Получение данных в Linux осуществляется через несколько уровней:

- **Интерфейсы ядра:** Прямое чтение из `/proc` (состояние процессов и параметры ядра) и `/sys` (атрибуты оборудования и драйверов).
- **Таблицы DMI:** Чтение низкоуровневых спецификаций оборудования, прошитых производителем.
- **Журналы событий:** Анализ сообщений ядра через `dmesg` для выявления событий инициализации и ошибок.
- **Служебные утилиты:** Инструменты (`hostnamectl`, `timedatectl`, `systemctl`), предоставляющие высокоуровневый интерфейс к системным настройкам.

### Особенности в виртуальных и облачных средах

На виртуальных машинах (VM) и в облаках информация об оборудовании часто является абстрагированной:

- **Гипервизоры:** Модель CPU может отображаться как "Common KVM processor", вендор — как "VMware", "QEMU" или "Microsoft Corporation" (Hyper-V).
- **Облачные метаданные:** В AWS, Azure, GCP и OpenStack данные об инстансе (ID, регион, роль) доступны через HTTP-сервисы метаданных (обычно по адресу `169.254.169.254`).
- **Датчики:** Температура и напряжение в VM обычно недоступны или показывают фиктивные значения.

## Практические сценарии

### 1. Сводная информация (Dashboard)

Для быстрого обзора системы (версия ОС, ядро, время работы, количество пакетов) используются современные инструменты:

```bash
# Современный стандарт для быстрой сводки
fastfetch

# Детальная текстовая сводка по всем компонентам (CPU, RAM, GPU, Network)
inxi -Fz
```

### 2. Версия ядра и дистрибутива

Идентификация программного окружения выполняется следующими командами:

```bash
# Подробная информация о ядро (версия, архитектура, дата сборки)
uname -a

# Стандартный файл идентификации дистрибутива (systemd)
cat /etc/os-release

# Версия ядра и компилятора (прямо из ядра)
cat /proc/version
```

### 3. Управление именем хоста и идентификаторами

Современным стандартом управления является `hostnamectl`. Утилита разделяет имена на три типа: **Static** (постоянное), **Transient** (динамическое) и **Pretty** (описательное).

```bash
# Просмотр статуса системы и machine-id
hostnamectl

# Установка статического имени хоста (вносит изменения в /etc/hostname)
sudo hostnamectl set-hostname --static new-nodename

# Просмотр уникального идентификатора системы
cat /etc/machine-id
```

### 4. Время работы и нагрузка (Uptime, Load Average)

Базовые показатели состояния системы:

```bash
# Время работы, количество пользователей, LA за 1/5/15 минут
uptime
# → 12:17:58 up 111 days, 31 min,  1 user,  load average: 0.00, 0.01, 0.05

# Количество логических CPU (для интерпретации LA)
nproc
```

Подробная интерпретация Load Average: [Планирование процессов: LA](../Core/processes/scheduling.md#интерпретация-load-average).

### 5. Состояние системы и уровни выполнения

В системах с systemd таргеты заменили традиционные runlevels.

```bash
# Текущий таргет по умолчанию (graphical.target или multi-user.target)
systemctl get-default

# Анализ времени загрузки системы (ядро + пользователи)
systemd-analyze
```

Подробнее: [Юниты и таргеты systemd](../Core/systemd/systemd_units_overview.md).

### 6. Аппаратное обеспечение (Ссылки на SSoT)

Для детальной инвентаризации используйте специализированные инструменты и SSoT-файлы:

- **Процессор (CPU):** Архитектура, ядра, кэш и топология — [Диагностика CPU](../Diagnostics/Hardware/cpu_info.md).
- **Общая инвентаризация:** Шины (PCI/USB), DMI/BIOS — [Инвентаризация оборудования](../Diagnostics/Hardware/hardware_listing.md).
- **Оперативная память (RAM):** Объем, типы модулей и статистика — [Статистика памяти](../Diagnostics/Memory/proc_meminfo.md).
- **Дисковая подсистема:** Блочные устройства и разделы — [Анализ блочных устройств](../Diagnostics/Filesystem/filesystem_and_disk_space_diagnostics.md#анализ-блочных-устройств-через-lsblk).
- **Датчики и мониторинг:** Температура и вольтаж — `sensors` (lm-sensors) или `ipmitool` (IPMI).
