## Создание пользователей и первичная группа (User Private Groups)

1.  **Пользователь всегда состоит в группе:** Каждый пользователь должен состоять как минимум в одной (первичной) группе.
2.  **Автоматическое создание одноименной группы:** При создании нового пользователя (например, командой `useradd username`) без указания дополнительных параметров автоматически создается группа с таким же именем (`username`). Эта группа становится **первичной** для данного пользователя.

### /etc/passwd

-   `/etc/passwd`: Содержит информацию о пользователях (имя, UID, GID, домашний каталог, оболочка).

| Поле № | Значение | Описание |
| --- | --- | --- |
| 1 | `daemon` | Имя пользователя |
| 2 | `x` | Пароль (обычно `x`, означает, что пароль хранится в `/etc/shadow`) |
| 3 | `1` | UID (user ID) — уникальный идентификатор пользователя |
| 4 | `1` | GID (group ID) — идентификатор основной группы |
| 5 | `daemon` | Полное имя или комментарий |
| 6 | `/usr/sbin` | Домашняя директория (может быть фиктивной) |
| 7 | `/usr/sbin/nologin` | Shell входа — запрещает вход (используется для системных пользователей) |

### /etc/shadow

-   `/etc/shadow`: Хранит хэши паролей пользователей и информацию о сроке их действия. **Этот файл доступен для чтения только `root`**.

| **Поле** | **Значение** | **Объяснение** |
| --- | --- | --- |
| 1 | magicfun | Имя пользователя |
| 2 | ! | **Учётная запись заблокирована** — вход невозможен |
| 3 | 20215 | Последняя смена пароля: день с 1970-01-01 (примерно 2025-04-28) |
| 4 | 0 | Можно сменить пароль сразу |
| 5 | 99999 | Пароль действителен практически бесконечно |
| 6 | 7 | Предупреждать за 7 дней |
| 7-9 | ::: | Не установлены значения неактивности и удаления |

-   `/etc/group`: Содержит информацию о группах.
-   `/etc/gshadow`: Хранит защищенную информацию о группах (например, пароли групп).

> **ВАЖНО:** Никогда не изменяйте права доступа к файлам `/etc/shadow` и `/etc/gshadow`. Неправильные права (например, предоставление доступа на чтение кому-либо, кроме `root`) могут привести к тому, что система не сможет корректно аутентифицировать пользователя или назначить ему правильные группы при входе. Это может полностью заблокировать вход в систему или привести к тому, что пользователь войдет с сильно урезанными правами.

## Перенос пользователей и групп между системами

1.  **Скопируйте файлы с исходной машины:**
    Используйте `scp` или `rsync` для копирования файлов на целевую машину.
    ```bash
    # Выполнять на целевой машине или указать путь назначения
    scp root@source_machine:/etc/passwd /etc/passwd
    scp root@source_machine:/etc/shadow /etc/shadow
    scp root@source_machine:/etc/group /etc/group
    ```

2.  **Перенесите домашние директории:**
    Этот метод не переносит домашние каталоги пользователей (`/home/username`). Их необходимо скопировать отдельно.
    ```bash
    # Рекомендуется использовать rsync для сохранения прав
    rsync -avz --progress root@source_machine:/home/ /home/
    ```

**Потенциальные риски**

-   **Конфликты UID/GID:** Этот метод может перезаписать существующих пользователей и группы на целевой машине, если их UID (User ID) или GID (Group ID) совпадают. Это особенно опасно для системных учётных записей.
-   **Чистые системы:** Метод наиболее безопасен при переносе на новую, "чистую" систему или на машину с идентичной базовой конфигурацией.
-   **Резервное копирование:** Всегда создавайте резервные копии оригинальных файлов на целевой машине перед их заменой.

## Что такое хэш-функция?

**Хэш** — это результат работы **хэш-функции**, математического алгоритма, который преобразует входные данные любого размера в строку фиксированной длины. Этот процесс является **односторонним**, то есть восстановить исходные данные из хэша невозможно, так как при преобразовании часть информации необратимо теряется.

Ключевые свойства хэш-функции:
1.  **Детерминированность:** Один и тот же ввод всегда даёт один и тот же хэш.
2.  **Фиксированный размер вывода:** Независимо от размера входных данных (будь то один символ или целый фильм), результат (хэш) всегда будет иметь одинаковую длину (например, 256 бит для SHA-256).
3.  **Необратимость:** Невозможно восстановить исходные данные, зная только их хэш. Это похоже на уравнение `x² = 4`, где, зная результат `4`, мы не можем однозначно сказать, был ли исходный `x` равен `2` или `-2`.
4.  **Сопротивление коллизиям:** Практически невозможно найти два разных набора входных данных, которые привели бы к одинаковому хэшу.

В Linux хэши используются для безопасного хранения паролей. В файле `/etc/shadow` хранятся не сами пароли, а их хэши. Когда пользователь вводит пароль, система вычисляет его хэш и сравнивает с тем, что записан в файле. Это гарантирует, что даже если злоумышленник получит доступ к этому файлу, он не сможет узнать реальные пароли пользователей.

Именно поэтому безопасные системы никогда не предлагают функцию "восстановить пароль", а только "сбросить" или "заменить пароль".
-   **Восстановление пароля (плохая практика):** Подразумевает, что сервис может прислать вам ваш старый пароль. Это возможно только если пароли хранятся в открытом виде или с помощью обратимого шифрования, что является грубым нарушением безопасности.
-   **Сброс пароля (хорошая практика):** Сервис не знает ваш старый пароль. Вместо этого он предоставляет одноразовый безопасный способ (например, ссылка на email) для установки **нового** пароля, хэш которого заменит старый.

## Мониторинг пользователей

-   `who`: Показывает, кто из пользователей **в данный момент** залогинен в системе (онлайн). Читает информацию из файла `/var/run/utmp`.
-   `w`: Более подробный вывод, чем у `who`. Показывает, кто залогинен и **что они делают** (какие процессы запущены).
-   `last`: Показывает историю **последних входов** в систему, читая файл `/var/log/wtmp`. Полезна, чтобы увидеть, кто заходил в систему ранее (оффлайн).
-   `id <имя_пользователя>`: Выводит информацию о пользователе. 
    -   `uid`: User ID.
    -   `gid`: ID **первичной (основной) группы**. У пользователя она одна. Новые файлы по умолчанию создаются с этой группой.
    -   `groups`: Список ID всех групп, в которые входит пользователь (включая первичную и все **втористепенные**).

## Соглашение о диапазонах UID: системные и пользовательские

Технически, ядро Linux не будет возражать, если вы создадите пользователя с UID 500 или запустите веб-сервер с UID 1500. Система будет работать. Однако это считается очень плохой практикой, и вот почему:

1.  **Нарушение общепринятой конвенции.** Это главный пункт. Весь мир Linux/Unix работает по соглашению: UIDs до 1000 (в некоторых дистрибутивах до 500) зарезервированы для системных учетных записей (служб, демонов), а всё, что выше — для обычных, "человеческих" пользователей. Нарушая это правило, вы создаете систему, которую сложно и опасно администрировать.

2.  **Риски безопасности.**
    *   **Пользователь с низким UID:** Если вы дадите пользователю UID, например, 70 (который может использоваться системным процессом), а потом установите пакет, который создает пользователя с таким же UID, ваш "человек" может внезапно стать владельцем системных файлов. Это прямой путь к нарушению безопасности.
    *   **Демон с высоким UID:** Системные службы часто имеют ограниченные права. Если вы запускаете демона под UID > 1000, другие системные утилиты и скрипты могут ошибочно принять его за обычного пользователя и, например, включить его в отчеты по дисковым квотам или в списки на резервное копирование домашних директорий.

3.  **Конфликты с системными пакетами.** При установке (`apt`, `yum`) многие пакеты (веб-серверы, базы данных) автоматически создают системного пользователя с заранее определенным UID из низкого диапазона. Если этот UID уже занят вашим "человеческим" пользователем, установка может завершиться с ошибкой или привести к непредсказуемым последствиям.

## Повышение привилегий: `su` против `sudo`

### `su` (substitute user)

-   **Что делает:** Переключает вас на сеанс другого пользователя. Если имя пользователя не указано, по умолчанию пытается переключиться на `root`.
-   **Какой пароль спрашивает:** Пароль **целевого пользователя** (того, на которого вы переключаетесь). Чтобы выполнить `su -`, вам нужно знать пароль `root`.
-   **Основной сценарий:** Полностью "стать" другим пользователем, получив его оболочку и окружение. Часто используется для перехода в сеанс `root`, если его пароль известен и включен.

### `sudo` (superuser do)

-   **Что делает:** Выполняет *одну или несколько команд* от имени другого пользователя (по умолчанию `root`), не переключая сеанс полностью.
-   **Какой пароль спрашивает:** Пароль **текущего пользователя** (вашего собственного).
-   **Как работает:** Проверяет файл `/etc/sudoers`, чтобы определить, имеет ли **текущий пользователь** (чей пароль и был введен) право выполнять указанную команду от имени целевого пользователя.
-   **Основной сценарий:** Временно повысить привилегии для выполнения конкретной административной задачи (установка ПО, редактирование конфигурационного файла). Это более безопасный и контролируемый подход, так как он не требует разглашения пароля `root` и позволяет гранулированно настраивать права.
-   **Логирование:** Каждое действие, выполненное через `sudo`, записывается в системный журнал (например, `/var/log/auth.log`), создавая полный аудиторский след.

#### Получение интерактивной оболочки через `sudo`

`sudo` также можно использовать для получения полноценной оболочки от имени другого пользователя, что является предпочтительной альтернативой `su`.

-   `sudo -i [-u <имя_пользователя>]`: Запускает **интерактивную login-оболочку**. Это лучший способ "стать" другим пользователем. Окружение будет таким же, как если бы этот пользователь вошел в систему: загрузятся его `.profile`, `.bashrc`, а текущим каталогом станет его домашний каталог.
-   `sudo -s [-u <имя_пользователя>]`: Запускает **интерактивную non-login оболочку**. Запускает оболочку, указанную в переменной `SHELL`, но не симулирует полный вход в систему (не считывает `.profile`) и оставляет вас в текущем каталоге.

Если `<имя_пользователя>` не указано, используется `root`.

### Создание пользователей

Эта команда имеет ряд настроек по умолчанию, которые задаются с помощью файлов `/etc/default/useradd` и `/etc/login.defs`. Увидеть основные можно с помощью команды:

```bash
useradd -D
```
- **GROUP**: GID группы, в которую пользователь будет добавлен после создания
- **HOME**:	базовый каталог, в котором будет размещена директория пользователя
- **INACTIVE**:	указывает время до блокировки пользователя, когда его пароль станет недействителен. Значение «-1» отключает опцию
- **EXPIRE**:	дата, до которой действителен аккаунт. По умолчанию не установлена — то есть без ограничений
- **SHELL**:	используется для настройки доступа к командной оболочке
- **SKEL**:	содержит путь к директории, в которой хранятся файлы по умолчанию. После создания пользователя они будут автоматически скопированы в его домашнюю папку
- **CREATE_MAIL_SPOOL**:	определяет, нужно ли создать папку для писем этого пользователя в `/var/spool/mail/`

Все эти настройки применяются, если использовать самый простой вариант команды создания пользователя без параметров:

```bash
useradd test-user
# или более интерактивная команда
adduser test-user
```

- **-m**:	создаёт указанную домашнюю директорию, если она ещё не существует
- **-d /home/test-user**:	устанавливает `/home/test-user` в качестве домашней директории
- **-c "Имя Фамилия"**:	добавляет комментарий. Например, с именем пользователя
- **-g test**:	указывает группу, в которую попадёт пользователь после создания. Можно использовать с GID или именем группы. Указанная группа должна существовать. Используется в сочетании с ключом -N (отменяет автоматическое создание группы с именем пользователя)
- **-G users,wheel**:	указывает список дополнительных групп пользователя. Они перечисляются через запятую без пробелов
- **-s /bin/bash**:	позволяет настроить доступ к shell. Например: `sudo adduser --shell /bin/sh user3`
- **-r**:	создаёт системного пользователя. Используется, когда вам нужно настроить службу на работу из-под конкретного пользователя. По умолчанию данные таких пользователей не вносятся в `/etc/shadow`, для них не создаётся домашняя папка
- **-u**:	позволяет указать свой UID, который будет присвоен новому пользователю. В качестве UID указывается положительное целое число. UID должен быть уникален
- **-e 2021-01-01**:	указывает дату, до которой аккаунт будет активен. Дата задаётся в формате YYYY-MM-DD
- **-f 3**:	указывает количество дней до блокировки пользователя, когда его пароль станет недействителен

Очень важно после создания пользователя настроить для него надёжный пароль. 
```bash
passwd test-user
```

### Изменение данных пользователей

Смена настроек для активного пользователя может привести к сбою системы. Поэтому перед изменением данных важно убедиться, что в текущий момент редактируемый пользователь не авторизован, под ним отсутствуют запущенные процессы, редактируемые файлы. Посмотреть список запущенных процессов пользователя `user` можно следующим образом: 

```bash
pgrep -l -u user
```
Проверить, авторизован ли пользователь, можно с помощью уже известной команды:

```bash
pinky user
```
Отредактировать данные существующего пользователя можно с помощью команды `usermod`. По структуре она похожа на предыдущую команду:

```bash
usermod [что поменять] [для какого пользователя]
```
Набор параметров расширен дополнительными опциями:
- **-m**:	создаёт новую директорию, указанную в качестве домашней (если её не существует), и переносит туда данные из старой
- **-d /home/users/new-test-user**:	меняет домашнюю директорию пользователя на `/home/users/new-test-user`
- **-c "Имя2 Фамилия2"**:	меняет комментарий к пользователю
- **-a -G users,wheel**:	добавляет пользователя в дополнительные группы. Например, `sudo usermod -aG sudo user1` добавит пользователя в группу `sudo`.
- **-s /bin/bash**:	меняет командную оболочку пользователя. Альтернатива: `sudo chsh -s /bin/sh <имя_пользователя>`.
- **-u 100500**:	изменяет UID пользователя
- **-e 2060-01-01**:	меняет дату, до которой аккаунт будет активен
- **-f 7**:	меняет количество дней до блокировки пользователя, когда его пароль станет недействителен
- **-l new-test-user**:	меняет имя пользователя на `new-test-user`
- **-L**:	блокирует аккаунт пользователя. Для этого в файле `/etc/shadow` перед хэшем пароля пользователя ставится символ «!»
- **-U**:	снимает блокировку с аккаунта (удаляет символ «!» из пароля в `/etc/shadow`)

То есть если мы захотим отредактировать данные пользователя `test-user`, созданного в примере выше, это будет выглядеть так:

```bash
usermod -l new-test-user -m -d /home/new-test-user -c "Имя2 Фамилия2" -u 100500 -e 3000-01-01 -f -1 test-user
```
В примере мы меняем логин — имя пользователя на `new-test-user`, изменяем домашнюю папку на `/home/new-test-user` с копированием файлов, меняем комментарий, UID пользователя, срок жизни аккаунта и отменяем блокировку в случае устаревания пароля.
При изменении данных пользователя система предпримет попытку автоматически указать новые данные для всех файлов и папок пользователя. Тем не менее, после редактирования нужно всё перепроверить и исправить права доступа, где они не изменились автоматически.

### Удаление пользователей

Как и в случае с редактированием, перед удалением пользователя нужно убедиться, что под ним отсутствуют активные процессы, не редактируются файлы. Иначе существует риск сбоя системы. В программу встроен механизм защиты, поэтому она не позволит удалить пользователя, если он авторизован или под ним работают какие-то службы.

Для удаления пользователей используется команда `userdel`. Её структура аналогична предыдущим:

```bash
userdel [что удаляем] [кого удаляем]
```
Основных параметра два: 
- **-r**:	удаляет папки пользователя: домашнюю директорию, почтовую очередь
- **-f**:	отключает механизм защиты. При использовании этой опции пользователь будет удалён даже при наличии запущенных процессов и пр. Используется на свой страх и риск, так как может привести к сбою системы

После удаления пользователей важно вручную проверить, что на сервере не осталось файлов или директорий, принадлежащих удалённому пользователю. 

#### Создание групп

Для создания групп используется команда `groupadd`:
```bash
groupadd new-group
```
Из параметров можно выделить следующие:
- **-f**:	если группа с указанным именем или GID уже существует, опция прерывает выполнение команды без соответствующей ошибки
- **-g 100500**:	позволяет назначить свой GID для создаваемой группы
- **-r**:	создаёт системную группу
- **-p p@ssw0rd**:	Устанавливает для группы пароль `p@ssw0rd`. Пароль запрашивается системой при попытке входа в группу с помощью команды `newgrp`.
Не рекомендуется к использованию из-за проблем с безопасностью. Настроенный таким образом пароль можно увидеть в истории команд.

#### Редактирование групп

Для редактирования групп используется команда `groupmod`. Список изменений задаётся с помощью параметров:
- **-g 100500**:	меняет GID группы на `100500`
- **-n another-name**:	меняет имя группы на `another-name`

Например, если нам нужно изменить имя группы `test-group` на имя `named-group`, команда будет выглядеть так:
```bash
groupmod -n named-group test-group
```

#### Удаление групп

Нельзя удалить группу, если она указана в качестве основной для какого-то существующего пользователя. Сначала нужно предварительно удалить этого пользователя из группы.

Само удаление группы выполняется одной командой:

```bash
groupdel test-group
```
Как и в случае удаления пользователей, нужно вручную проверить, что на сервере не осталось данных, принадлежащих удалённой группе.

### Управление пользователями в группе

Базовым инструментом для управления группами является утилита `gpasswd`. Она имеет несколько параметров, но с одной особенностью — в отличие от предыдущих примеров, здесь большинство параметров (кроме -A и -M) не сочетаются. То есть в команде может быть только один параметр за раз.

Структура команды проста:

```bash
gpasswd [что сделать] [в какой группе]
```
Рассмотрим опции команды подробнее: 
- **-a new-user**:	Добавляет пользователя `new-user` в группу
- **-d bad-user**:	Удаляет пользователя `bad-user` из группы
- **-A user1,user2,...**:	Доступна для использования привилегированным пользователям (с правами root). Назначает список пользователей-администраторов группы
- **-M user1,user2,...**:	Доступна для использования привилегированным пользователям. Назначает список участников группы
- **-r**:	Отключает пароль группы. После этого только члены группы смогут использовать команду `newgrp` для подключения к группе
- **-R**:	Отключает внешний доступ к группе. После этого только члены группы смогут использовать команду `newgrp` для подключения к группе

То есть если нам потребуется добавить пользователя в новую группу, достаточно будет использовать следующую команду: 

```bash
gpasswd -a new-user test-group
```
Также для добавления пользователей в новую группу используется описанная выше команда `usermod`. Следующий пример добавляет пользователя `test-user` в группу `new-group`: 

```bash
usermod -a -G new-group test-user
```
Или, если нужно указать группу `new-group` в качестве основной группы пользователя `test-user`:

```bash
usermod -g new-group test-user
```
Помимо этого, любой пользователь может сам авторизоваться и добавиться в новую группу с помощью команды: 

```bash
newgrp new-group
```
Эта команда позволяет переключить группу пользователя в рамках текущей сессии, а также автоматически добавляет запрошенную группу в список групп пользователя.
