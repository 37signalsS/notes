# Управление приоритетами пакетов в Apt (Pinning)

## Определения

Механизм "pinning" (приоритетов) в Apt позволяет гибко управлять, из какого репозитория и какая версия пакета будет установлена. Это особенно полезно, когда один и тот же пакет доступен в нескольких репозиториях (например, в официальном репозитории Ubuntu и в вашем приватном).

Эта заметка является частью цикла статей по [управлению пакетами в Linux](../../Linux/PackageManagement/linux_package_management_overview.md).

## Основные понятия

### Как Apt выбирает пакет?

По умолчанию Apt устанавливает пакет с самой высокой версией. Если версии одинаковы, предпочтение отдается репозиторию, который был объявлен раньше.

Приоритеты позволяют изменить это поведение. Каждой версии каждого пакета присваивается числовой приоритет. Apt попытается установить версию с самым высоким приоритетом.

### Просмотр приоритетов

Команда `apt-cache policy` показывает приоритеты всех настроенных репозиториев и уже установленных пакетов.

```bash
apt-cache policy
```

Чтобы увидеть приоритеты для конкретного пакета:

```bash
apt-cache policy nginx
```

Вывод покажет доступные версии, репозитории, из которых они доступны, и их приоритеты. "Кандидат на установку" — это версия, которую Apt выберет при `apt-get install`.

### Стандартные значения приоритетов

*   `> 1000`: Установить эту версию, даже если это приведет к понижению версии (downgrade).
*   `990 - 1000`: Приоритет для целевого релиза (target release).
*   `500 - 989`: Стандартный приоритет для версий из обычных репозиториев.
*   `100 - 499`: Приоритет для уже установленных версий и версий из репозиториев `backports`.
*   `1 - 99`: Приоритет для версий, которые не должны устанавливаться автоматически.
*   `< 0`: Запрещает установку этой версии.

## Практические сценарии

### Настройка приоритетов

Приоритеты настраиваются в файлах внутри директории `/etc/apt/preferences.d/`. Эти файлы работают совместно с файлами [источников репозиториев (`sources.list`)](../../Linux/PackageManagement/deb_repositories_sources_list.md). Рекомендуется создавать отдельный файл для каждого набора правил.

Например, создадим файл `/etc/apt/preferences.d/my-repo-prefs`.

#### Пример 1: Повысить приоритет всего репозитория

Это заставит Apt предпочитать пакеты из вашего репозитория всем остальным, даже если версии в нем ниже.

```
# /etc/apt/preferences.d/my-repo-prefs

# Объяснение: Предпочитать все пакеты из репозитория "My Private Repo"
Explanation: Prefer all packages from "My Private Repo"
# Выбираем репозиторий по его полю Origin
Package: *
Pin: origin "My Private Repo"
Pin-Priority: 990
```

*   `Package: *`: Правило применяется ко всем пакетам.
*   `Pin: origin "My Private Repo"`: Идентификатор репозитория. `Origin` можно узнать из вывода `apt-cache policy`.
*   `Pin-Priority: 990`: Устанавливаем высокий приоритет.

#### Пример 2: Повысить приоритет для конкретного пакета

Это полезно, если вы хотите "заморозить" версию определенного пакета из вашего репозитория.

```
# /etc/apt/preferences.d/my-repo-prefs

# Объяснение: Установить nginx только из нашего репозитория
Explanation: Install nginx only from our repository
Package: nginx
Pin: origin "My Private Repo"
Pin-Priority: 1001
```
Приоритет `1001` заставит Apt установить `nginx` из вашего репозитория, даже если это будет понижение версии.

#### Пример 3: Запретить установку пакета из определенного репозитория

```
# /etc/apt/preferences.d/block-nginx

Package: nginx
Pin: origin "nginx.org"
Pin-Priority: -1
```
Это правило запретит установку `nginx` из репозитория с `Origin` "nginx.org".

## Дополнительная информация

### Применение изменений

После создания или изменения файла в `/etc/apt/preferences.d/` необходимо обновить кэш Apt:

```bash
sudo apt-get update
```

После этого проверьте результат с помощью `apt-cache policy <package-name>`, чтобы убедиться, что кандидат на установку изменился в соответствии с вашими правилами.
