# Управление приоритетами пакетов в Apt (Pinning)

## Определения

Ниже приведены основные термины, используемые в механизме управления приоритетами пакетов в системах на базе DEB (Debian Package).

**Pinning (Приоритизация пакетов)** — механизм системы APT (Advanced Package Tool) для гибкого управления выбором источника и версии программного обеспечения. Позволяет вручную назначать приоритеты репозиториям или конкретным версиям пакетов.

**Приоритет (Pin Priority)** — числовое значение, определяющее предпочтительность версии пакета при установке или обновлении. Чем выше значение, тем больше вероятность выбора именно этой версии системой APT.

**Кандидат на установку (Candidate Version)** — версия пакета, которую система выберет автоматически при выполнении команд установки или обновления. Определяется на основе наивысшего текущего приоритета.

---

## Основные концепции

### Принцип выбора версии

По умолчанию APT выбирает версию с наибольшим номером из всех доступных репозиториев. Если номера версий идентичны, предпочтение отдается источнику, указанному выше в конфигурационных файлах. Механизм pinning позволяет изменить эту логику, основываясь на происхождении (origin), дистрибутиве, компоненте или архитектуре.

### Конфигурационные файлы

- **/etc/apt/preferences** — основной файл (традиционный метод).
- **/etc/apt/preferences.d/** — директория для хранения отдельных файлов правил (современный рекомендуемый метод). Файлы должны иметь расширение `.pref`.

### Стандартные диапазоны приоритетов

| Значение | Поведение системы |
| :--- | :--- |
| **> 1000** | Безусловная установка. Допускается автоматическое понижение версии (downgrade). |
| **990 – 1000** | Стандартный приоритет для целевого релиза дистрибутива. |
| **500 – 989** | Обычный приоритет для репозиториев стороннего ПО. |
| **100 – 499** | Приоритет для уже установленных версий и пакетов из раздела backports. |
| **1 – 99** | Низкий приоритет. Пакет не будет установлен автоматически, если не указан явно. |
| **< 0** | Запрет на установку данной версии или из данного источника. |

## Практические сценарии

### Просмотр текущих приоритетов

Для диагностики используйте команду `policy`:

```bash
# Показать приоритеты всех источников
apt-cache policy

# Проверить приоритеты для конкретного пакета
apt-cache policy nginx
```

### Пример 1: Фиксация версии конкретного пакета

Если необходимо всегда устанавливать пакет из определенного репозитория, игнорируя более свежие версии в официальных источниках:

```bash
# Создание файла /etc/apt/preferences.d/nginx.pref
Package: nginx
Pin: origin "nginx.org"
Pin-Priority: 1001
```

### Пример 2: Использование backports

Для автоматической установки пакетов из репозитория backports (по умолчанию они имеют низкий приоритет):

```bash
# Пример для Ubuntu 24.04 LTS (Noble Numbat)
Package: *
Pin: release a=noble-backports
Pin-Priority: 500
```

### Пример 3: Запрет установки из стороннего источника

Блокировка конкретного пакета из определенного репозитория:

```bash
Package: docker-ce
Pin: origin "download.docker.com"
Pin-Priority: -1
```

## Дополнительная информация

### Диагностика и отладка

Если система ведет себя неожиданно при выборе версий, используйте флаги отладки:

```bash
# Эмуляция установки с подробным выводом логики решателя зависимостей
apt-get install -s -o Debug::pkgProblemResolver=1 <имя_пакета>
```

### Рекомендации (Best Practices)

1. **Разделение файлов**: Всегда используйте директорию `/etc/apt/preferences.d/` вместо одного огромного файла.
2. **Имена файлов**: Давайте файлам осмысленные имена, соответствующие их назначению (например, `block-nginx.pref`).
3. **Минимализм**: Не используйте глобальные правила `Package: *` без явной необходимости, так как это может привести к нестабильности системы.
4. **Документирование**: Оставляйте комментарии внутри `.pref` файлов с объяснением причин установки конкретного приоритета.
