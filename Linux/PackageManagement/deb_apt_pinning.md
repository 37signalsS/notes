# Управление приоритетами пакетов в Apt (Pinning)

## Определения

Ниже приведены основные термины, используемые в механизме управления приоритетами пакетов в системах на базе DEB (Debian Package).

**Pinning (Приоритизация пакетов)** — механизм системы APT (Advanced Package Tool) для гибкого управления выбором источника и версии программного обеспечения. Позволяет вручную назначать приоритеты репозиториям или конкретным версиям пакетов.

**Pin-запись (Pin Entry)** — блок конфигурации в файлах предпочтений, описывающий правила выбора конкретного пакета или группы пакетов.

**Приоритет (Pin Priority)** — числовое значение, определяющее предпочтительность версии пакета при установке или обновлении. Чем выше значение, тем больше вероятность выбора именно этой версии системой APT.

**Кандидат на установку (Candidate Version)** — версия пакета, которую система выберет автоматически при выполнении команд установки или обновления. Определяется на основе наивысшего текущего приоритета среди доступных версий.

## Основные концепции

### Критерии выбора (Pin-Type)

Правила Pinning могут основываться на различных характеристиках пакета, указываемых в поле `Pin`:

1.  **version**: Фиксация конкретной версии или диапазона версий (например, `Pin: version 1.2.3*`).
2.  **release**: Выбор по характеристикам релиза из файла `Release`. Позволяет фильтровать по дистрибутиву, архиву или компоненту.
3.  **origin**: Выбор по имени хоста источника (например, `Pin: origin "repo.example.com"`).

#### Атрибуты поля Release

При использовании `Pin: release` можно уточнять следующие параметры:
- `a` (Archive/Suite) — имя дистрибутива (например, `stable`, `noble-backports`).
- `n` (Codename) — кодовое имя релиза (например, `bookworm`, `noble`).
- `c` (Component) — секция репозитория (например, `main`, `universe`).
- `l` (Label) — метка репозитория (указывается в конфиге репозитория, например `Label: MyRepo`).
- `o` (Origin) — организация-издатель (например, `Debian`, `Docker`).

### Стандартные диапазоны приоритетов

| Значение | Поведение системы |
| :--- | :--- |
| **> 1000** | Безусловная установка. Допускается автоматическое понижение версии (downgrade). |
| **990 – 1000** | Стандартный приоритет для целевого релиза дистрибутива. |
| **500 – 989** | Обычный приоритет для репозиториев стороннего ПО. |
| **100 – 499** | Приоритет для уже установленных версий и пакетов из раздела backports. |
| **1 – 99** | Низкий приоритет. Пакет не будет установлен автоматически, если не указан явно. |
| **< 0** | Блокировка: запрет на установку данной версии или из данного источника. |

### Репозитории Not-Automatic

Некоторые репозитории (например, `backports`) имеют в файле `Release` флаг `Not-Automatic: yes`. Это автоматически назначает их пакетам приоритет **1**, если не настроено иное правило pinning. Флаг `But-Automatic-Upgrades: yes` позволяет автоматически обновлять пакет, если он уже установлен в системе.

## Практические сценарии

### Просмотр текущих приоритетов

Для диагностики используйте команду `policy`:

```bash
# Проверить общие приоритеты источников
apt policy
# → result: список всех репозиториев с их P-значениями

# Проверить приоритеты для конкретного пакета
apt policy nginx
# → result: список доступных версий с указанием Candidate и текущих приоритетов
```

### Пример 1: Фиксация версии пакета (Version Pinning)

Если требуется удержать пакет на конкретной версии, предотвращая любые обновления:

```bash
# Файл /etc/apt/preferences.d/nginx.pref
Package: nginx
Pin: version 1.24.0-1~noble
Pin-Priority: 1001
```

### Пример 2: Использование backports (Archive Pinning)

Для автоматической установки и обновления пакетов из репозитория backports (Ubuntu 24.04):

```bash
# Файл /etc/apt/preferences.d/backports.pref
Package: *
Pin: release a=noble-backports
Pin-Priority: 500
```

### Пример 3: Приоритет по Label (Label Pinning)

Полезно для внутренних репозиториев (например, созданных через `reprepro`), чтобы их пакеты всегда были предпочтительнее официальных:

```bash
# Файл /etc/apt/preferences.d/internal-repo.pref
Package: *
Pin: release l="Custom Internal Repository"
Pin-Priority: 1001
```

### Пример 4: Блокировка источника (Negative Priority)

Полный запрет на установку любых пакетов из конкретного стороннего репозитория:

```bash
# Файл /etc/apt/preferences.d/block-docker.pref
Package: *
Pin: origin "download.docker.com"
Pin-Priority: -1
```

## Дополнительная информация

### Диагностика и отладка

Если APT выбирает неожиданную версию, используйте режим эмуляции с отладкой:

```bash
# Эмуляция установки с выводом логики выбора
apt-get install -s -o Debug::pkgProblemResolver=1 nginx
```

### Рекомендации (Best Practices)

1.  **Изоляция правил**: Всегда используйте директорию `/etc/apt/preferences.d/`. Это упрощает автоматизацию (Ansible/Terraform) и удаление правил.
2.  **Использование кавычек**: Если значение атрибута содержит пробелы (например, в `Label`), обязательно заключайте его в двойные кавычки.
3.  **Группировка**: Можно указывать несколько пакетов через пробел в поле `Package` или использовать маски (например, `libmysql*`).
4.  **Комментарии**: Используйте символ `#` для документирования причин введения конкретных приоритетов непосредственно в `.pref` файлах.
