# Приватный Apt-репозиторий с reprepro: Дополнительная информация

## Определения

Ниже приведены термины, описывающие расширенные аспекты управления репозиториями и обеспечения их безопасности.

**Управление GPG-ключами (GNU Privacy Guard)** — регламентированные процессы создания, ротации (продления), отзыва и защиты секретных ключей, используемых для подтверждения целостности репозитория.

**Альтернативы reprepro** — программные инструменты для организации APT-репозиториев (Advanced Package Tool), обладающие специфическими функциями, такими как наличие REST API (Representational State Transfer Application Programming Interface) или поддержка снапшотов (мгновенных снимков состояний).

---

## Основные концепции

### Жизненный цикл ключей GPG

Ключи подписи являются критическим элементом доверия. Их обслуживание включает:

- **Контроль срока действия**: Проверка даты истечения через вывод метаданных ключа.
- **Продление**: Обновление даты `expire` через интерактивную оболочку `gpg --edit-key`.
- **Компрометация**: Немедленный отзыв ключа через заранее сгенерированный сертификат отзыва в случае утечки секретной части.

### Стандарты безопасности

Для защиты производственных репозиториев рекомендуется соблюдать следующие правила:

1. **Изоляция секретов**: Секретный ключ должен храниться на выделенном сервере сборки или в аппаратном модуле безопасности, доступ к директории `~/.gnupg/` должен быть ограничен (права `chmod 700`).
2. **Разделение ролей**: Используйте выделенный GPG-ключ исключительно для репозитория, не совмещая его с личными ключами сотрудников.
3. **Защита канала**: Публикация должна осуществляться строго по протоколу HTTPS (Hypertext Transfer Protocol Secure) для предотвращения атак типа MitM (Man-in-the-Middle — «человек посередине»).

## Практические сценарии

### Сценарий: Диагностика и обслуживание

В процессе эксплуатации `reprepro` могут потребоваться сервисные команды для проверки целостности данных.

| Команда | Назначение |
| :--- | :--- |
| `reprepro -V check` | Полная проверка синтаксиса конфигурационных файлов. |
| `reprepro show <codename> <pkg>` | Вывод детальной информации о конкретной версии пакета. |
| `reprepro list <codename>` | Листинг всех зарегистрированных пакетов в дистрибутиве. |
| `reprepro export <codename>` | Принудительная регенерация всех индексных файлов (`Packages`, `Release`). |
| `reprepro verify` | Валидация соответствия файлов в `pool/` записям в базе данных `dbs/`. |

### Сценарий: Выбор инструментария

Сравнение популярных решений для организации внутренних репозиториев.

| Инструмент | Сильные стороны | Недостатки |
| :--- | :--- | :--- |
| **aptly** | Поддержка снапшотов (Snapshot), наличие REST API, удобное зеркалирование. | Более высокая сложность начальной конфигурации. |
| **reprepro** | Стабильность, простота (статические файлы), проверен временем. | Отсутствие встроенного API, ручное управление ключами. |
| **simple-repo** | Максимальная простота. | Отсутствие механизмов подписи и сложной логики компонентов. |
