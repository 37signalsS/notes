# Приватный Apt-репозиторий с reprepro: Определения и концепции

## Определения

Ниже приведены основные термины, используемые при создании и эксплуатации внутренних хранилищ программного обеспечения для систем на базе DEB (Debian Package).

**`reprepro`** — специализированная утилита для создания и управления репозиториями пакетов формата `.deb` (Debian, Ubuntu). Позволяет организовывать доставку собственного ПО, создавать локальные зеркала или поддерживать приватную инфраструктуру пакетов.

**GPG (GNU Privacy Guard) — подпись репозитория** — криптографическая подпись метаданных репозитория (файлы `Release`, `InRelease`). Гарантирует подлинность пакетов и защищает от атак типа MitM (Man-in-the-Middle — «человек посередине»). Без наличия доверенного ключа менеджер пакетов APT (Advanced Package Tool) выдаст предупреждение о безопасности или откажется устанавливать ПО.

**Дистрибутив (в контексте reprepro)** — логическое разделение репозитория по версиям ОС (Операционной Системы), например, `focal`, `noble`, `bullseye`. Один экземпляр `reprepro` может обслуживать множество дистрибутивов одновременно.

**Компонент** — категория пакетов внутри конкретного дистрибутива (например, `main`, `contrib`, `non-free`).

## Основные концепции

### Архитектура репозитория

При инициализации `reprepro` формирует следующую структуру каталогов:

```text
my-repo/
├── conf/
│   └── distributions      # Основной конфигурационный файл
├── dbs/                   # Внутренняя база данных состояний reprepro
├── dists/                 # Метаданные (индексы) для каждого дистрибутива
│   └── <codename>/
│       ├── main/
│       └── Release
├── pool/                  # Единое хранилище фактических .deb пакетов
│   └── main/
│       └── <package>/
└── <codename>/            # Символические ссылки для обратной совместимости
```

### Конфигурация дистрибутивов

Файл `conf/distributions` является центральным узлом настройки. Он описывает параметры публикации для каждого релиза.

| Поле | Описание | Пример |
| :--- | :--- | :--- |
| **Origin** | Уникальный идентификатор источника | `MyRepo` |
| **Label** | Человекочитаемое имя репозитория | `My Private APT Repository` |
| **Codename** | Кодовое имя релиза ОС | `focal`, `noble` |
| **Architectures** | Поддерживаемые архитектуры процессоров | `amd64`, `arm64`, `source` |
| **Components** | Список компонентов репозитория | `main`, `contrib` |
| **Description** | Краткое описание назначения | `Internal tools repository` |
| **SignWith** | ID (идентификатор) GPG-ключа для подписи | `ABCDEF1234567890` |
| **NotAutomatic** | Флаг, предотвращающий автообновление | `yes` (опционально) |

### Связь с Apt Pinning

Параметры `Origin` и `Label` из конфигурации `reprepro` критически важны для механизма **[Apt Pinning](../deb_apt_pinning.md)**. Они позволяют системе APT однозначно идентифицировать репозиторий и назначать пакетам из него специфические приоритеты (например, принудительное использование внутренней версии пакета вместо официальной).

## Практические сценарии

### Сценарий: Планирование структуры репозитория

Перед началом внедрения необходимо определить следующие параметры:

1. **Целевые ОС** — список релизов, для которых требуется сборка (например, `ubuntu 24.04` требует `noble`).
2. **Архитектуры** — необходимость поддержки не только `amd64`, но и `arm64` (для облачных сред или мобильных устройств).
3. **Категоризация ПО** — использование `main` для стабильных внутренних инструментов и, например, `testing` для экспериментальных сборок.
4. **Политика именования** — единый `Origin` для всех внутренних репозиториев организации для упрощения глобальной конфигурации Apt Pinning.
