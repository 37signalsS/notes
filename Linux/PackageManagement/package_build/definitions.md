# Сборка пакетов: Определения

## Определения

Ниже приведены основные термины, используемые в процессе создания пакетов для различных дистрибутивов Linux.

**Сборка пакета (Package Building)** — процесс преобразования исходного кода программы в бинарный пакет (`.deb` или `.rpm`) с использованием специализированного инструментария дистрибутива.

**Исходный пакет (Source Package)** — архив, содержащий исходный код, патчи, метаданные и инструкции для сборки.
- Формат DEB (Debian Package): `.dsc` + `.orig.tar.gz` + `.debian.tar.xz`.
- Формат RPM (Red Hat Package Manager): `.src.rpm`.

**Бинарный пакет (Binary Package)** — скомпилированный и упакованный файл программы, готовый к установке. Содержит исполняемые файлы, библиотеки, документацию и конфигурационные файлы.

**Метаданные (Metadata)** — структурированная информация о пакете: название, версия, зависимости, описание, информация о лицензии и контрольные суммы файлов.

**Спецификация (Spec File)** — текстовый файл с расширением `.spec`, описывающий метаданные, зависимости, инструкции сборки и установки для RPM-пакета. Включает секции `%prep`, `%build`, `%install`, `%files`.

**Директория debian (Debian Directory)** — каталог `debian/` в корне исходного кода, содержащий управляющие файлы для сборки DEB-пакета: `control`, `rules`, `changelog`, `copyright`, а также скрипты автоматизации (`preinst`, `postinst`, `prerm`, `postrm`).

**Журнал изменений (Changelog)** — файл истории изменений пакета, определяющий текущую версию и описывающий внесённые правки.
- Формат версии DEB: `upstream_version-debian_revision` (например, `1.2.3-4ubuntu5`).

**Чистое окружение (Clean Build Environment)** — изолированная среда (обычно `chroot` или контейнер), гарантирующая отсутствие скрытых системных зависимостей и воспроизводимость результатов.
- Инструменты: `pbuilder`, `sbuild` (DEB); `mock` (RPM).

**Фиктивный корень сборки (Build Root)** — временная директория, имитирующая корневую файловую систему (`/`), куда устанавливаются файлы программы на этапе выполнения команд `make install` или аналогичных перед их упаковкой в пакет.

**Зависимости сборки (Build Dependencies)** — пакеты, необходимые исключительно для компиляции и сборки целевого ПО. Указываются в поле `Build-Depends` (DEB) или `BuildRequires` (RPM).

**Макросы RPM (RPM Macros)** — предопределённые переменные в системе RPM (например, `%{_bindir}`, `%{_sysconfdir}`), используемые для обеспечения переносимости spec-файлов между различными версиями дистрибутивов.

**Скрипты сопровождения (Maintainer Scripts)** — исполняемые сценарии, запускаемые на различных этапах жизненного цикла пакета: перед установкой (`preinst`), после установки (`postinst`), перед удалением (`prerm`) и после удаления (`postrm`).

**Патч (Patch)** — файл с изменениями исходного кода, применяемый во время сборки.
- В DEB управляется через `quilt` и хранится в `debian/patches/`.
- В RPM указывается в spec-файле через директиву `PatchN:`.

**Архитектура пакета (Package Architecture)** — определение целевой платформы пакета:
- **Архитектурно-зависимые:** `x86_64`, `aarch64`, `i386`.
- **Архитектурно-независимые:** `all` (DEB) или `noarch` (RPM).

**Подпись пакета (Package Signing)** — использование GPG (GNU Privacy Guard) для создания цифровой подписи пакета, гарантирующей его подлинность и целостность при установке из внешних источников.

**Helper Tools (debhelper)** — набор автоматизированных скриптов в системе DEB, значительно упрощающих написание файла `debian/rules` за счёт автоматизации типовых задач (установка прав, сжатие документации и т.д.).

**Воспроизводимость сборки (Reproducible Build)** — свойство процесса, при котором идентичный исходный код всегда порождает побитово идентичные бинарные пакеты независимо от окружения, времени и пользователя, выполняющего сборку.

**Универсальные форматы (Universal Packages)** — современные форматы (Flatpak, Snap, AppImage), работающие независимо от пакетного менеджера дистрибутива и использующие механизмы песочниц (sandboxing).
