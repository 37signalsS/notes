# Сборка пакетов: Определения

## Определения

Ниже приведены основные термины, используемые в процессе создания пакетов для различных дистрибутивов Linux.

### Основные термины

**Сборка пакета (Package Building)** — процесс преобразования исходного кода программы в бинарный пакет (`.deb` или `.rpm`) с использованием специализированного инструментария дистрибутива.

**Исходный пакет (Source Package)** — архив, содержащий исходный код, патчи, метаданные и инструкции для сборки.
- **Формат DEB:** состоит из файлов `.dsc` (описание), `.orig.tar.gz` (оригинальный апстрим) и `.debian.tar.xz` (изменения дистрибутива). Основные форматы: `3.0 (quilt)` для стороннего ПО и `3.0 (native)` для ПО, разрабатываемого специально под дистрибутив.
- **Формат RPM:** представлен файлом `.src.rpm` (SRPM), объединяющим исходный код и spec-файл.

**Бинарный пакет (Binary Package)** — скомпилированный и упакованный файл программы, готовый к установке. Содержит исполняемые файлы, библиотеки, документацию и конфигурационные файлы.

**Метаданные (Metadata)** — структурированная информация о пакете: название, версия, зависимости, описание, информация о лицензии и контрольные суммы файлов.

**Эпоха (Epoch)** — числовой префикс версии (например, `1:2.3.4`), используемый для форсирования обновления пакета, если новая схема версионирования апстрима нарушает логику сравнения (например, переход с `20240101` на `1.0.0`).

### Управляющие файлы и структуры

**Спецификация (Spec File)** — текстовый файл с расширением `.spec`, описывающий метаданные, зависимости, инструкции сборки и установки для RPM-пакета. Включает секции `%prep` (распаковка), `%build` (компиляция), `%install` (установка в BuildRoot), `%files` (состав пакета).

**Директория debian (Debian Directory)** — каталог `debian/` в корне исходного кода, содержащий управляющие файлы для сборки DEB-пакета:
- **`control`**: метаданные и зависимости.
- **`rules`**: сценарий сборки (Makefile).
- **`changelog`**: история изменений и версия.
- **`copyright`**: информация о лицензиях.

**Макросы RPM (RPM Macros)** — предопределённые переменные в системе RPM (например, `%{_bindir}` для `/usr/bin`, `%{_sysconfdir}` для `/etc`), обеспечивающие переносимость spec-файлов между дистрибутивами.

**Helper Tools (debhelper)** — набор автоматизированных скриптов в системе DEB (вызываемых через команду `dh`), упрощающих написание файла `debian/rules` за счёт автоматизации типовых задач (анализ зависимостей, сжатие man-страниц).

### Окружение и процесс сборки

**Чистое окружение (Clean Build Environment)** — изолированная среда (`chroot` или контейнер), гарантирующая отсутствие скрытых зависимостей хост-системы.
- **Инструменты:** `sbuild`, `pbuilder`, `cowbuilder` (DEB); `mock` (RPM).

**Фиктивный корень сборки (Build Root)** — временная директория (`%{buildroot}` в RPM или `debian/tmp` в DEB), имитирующая корневую файловую систему (`/`), куда устанавливаются файлы программы перед их упаковкой.

**Зависимости сборки (Build Dependencies)** — пакеты, необходимые для компиляции (компиляторы, заголовочные файлы библиотеки `-dev` или `-devel`). Указываются в `Build-Depends` (DEB) или `BuildRequires` (RPM).

**Скрипты сопровождения (Maintainer Scripts)** — исполняемые сценарии, запускаемые на этапах жизненного цикла: `preinst`/`postinst` (до/после установки), `prerm`/`postrm` (до/после удаления).

**Патч (Patch)** — файл с изменениями исходного кода. В DEB управляется через систему `quilt`, в RPM — через директивы `Patch:` в spec-файле.

### Артефакты и архитектура

**Архитектура пакета (Package Architecture)**:
- **Архитектурно-зависимые:** `x86_64`, `aarch64`, `i386`.
- **Архитектурно-независимые:** `all` (DEB) или `noarch` (RPM).

**Debuginfo / Debugsource** — дополнительные пакеты, содержащие отладочные символы и исходный код соответственно. Генерируются автоматически при сборке для облегчения трассировки ошибок (например, через `gdb`).

**Подпись пакета (Package Signing)** — использование GPG для создания цифровой подписи, гарантирующей подлинность пакета.

**Воспроизводимость сборки (Reproducible Build)** — свойство процесса, при котором повторная сборка из тех же исходников дает побитово идентичный результат. Регулируется переменной `SOURCE_DATE_EPOCH`.

### Типы зависимостей периода выполнения

| Тип (DEB) | Тип (RPM) | Описание |
| :--- | :--- | :--- |
| **Depends** | **Requires** | Обязательные зависимости для работы. |
| **Pre-Depends** | **Requires(pre)** | Пакеты, которые должны быть полностью настроены ДО начала установки текущего пакета. |
| **Recommends** | — | Сильные, но не обязательные зависимости (устанавливаются по умолчанию). |
| **Suggests** | — | Дополнительные пакеты, расширяющие функционал. |
| **Conflicts** | **Conflicts** | Запрещает одновременную установку с указанным пакетом. |
| **Provides** | **Provides** | Позволяет пакету объявить, что он предоставляет функционал другого виртуального пакета. |
| **Replaces** | **Obsoletes** | Указывает, что пакет заменяет или поглощает функционал другого (старого) пакета. |
