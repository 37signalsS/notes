## Дополнительная информация

### Расчёт дискового пространства

Объём данных зависит от количества поддерживаемых релизов, архитектур и компонентов.

| Дистрибутив | Полное зеркало (x1 релиз) | Частичное (main only) |
| :--- | :--- | :--- |
| **Ubuntu 24.04** | ~300 GB | ~80 GB |
| **Ubuntu 22.04** | ~220 GB | ~60 GB |
| **Debian 12** | ~450 GB | ~90 GB |

**Рекомендации по планированию:**
- **Разделение данных**: Используйте выделенные логические тома (LVM) или дисковые разделы для `/var/spool/aptly` или `/var/spool/apt-mirror`.
- **Файловая система**: Предпочтительны XFS или Ext4. При использовании `aptly` важно следить за количеством инод (inodes) из-за множества мелких файлов метаданных.
- **Мониторинг**: Настройте оповещения при заполнении диска выше 85%, так как внезапное завершение синхронизации может повредить базу данных индексов.

### Оптимизация зеркалирования

#### Оптимизация в aptly
Инструмент `aptly` предлагает более глубокие механизмы управления данными:
- **Фильтрация по именам**: Загрузка только необходимых групп пакетов (например, `kernel`, `nvidia`).
- **Использование S3**: Хранение пула пакетов в объектном хранилище для масштабируемости.
- **Очистка базы данных**: Регулярно запускайте `aptly db cleanup` для удаления неиспользуемых ссылок на пакеты и освобождения места.
- **Snapshot-цикл**: Не храните слишком много старых снимков. Стандартная стратегия — `Actual`, `Previous` и `Stable`.

#### Оптимизация в apt-mirror
Для классического `apt-mirror` в файле `mirror.list` доступны следующие опции:
```bash
# Ограничение архитектур
set archs amd64

# Многопоточная загрузка (ускоряет синхронизацию при широком канале)
set nthreads 20

# Исключение исходных кодов (deb-src), если они не требуются
# (экономит до 30% места)
```

### Мониторинг и проверка целостности

#### Автоматизация проверок
Рекомендуется использовать периодические задания (Cron/Timer) не только для синхронизации, но и для проверки состояния зеркала.

```bash
# Проверка целостности базы данных aptly
aptly db check

# Мониторинг времени последнего обновления (age of mirror)
# Если файл Release старше 24 часов — зеркало считается устаревшим
find /var/www/html/ubuntu/dists/noble -name Release -mmin +1440
```

#### Скрипт уведомления об ошибках
Пример проверки статуса синхронизации:
```bash
#!/bin/bash
LOG_FILE="/var/log/apt-mirror.log"
if ! /usr/bin/apt-mirror > "$LOG_FILE" 2>&1; then
    tail -n 20 "$LOG_FILE" | mail -s "CRITICAL: APT Mirror Sync Failure" admin@example.com
fi
```

### Решение типичных проблем

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Hash Sum mismatch** | Пакет или индекс был обновлён в upstream во время синхронизации. | Перезапустить синхронизацию. В `aptly` использовать флаг `-force-update`. |
| **GPG: NO_PUBKEY** | Отсутствует ключ подписи в системе клиента. | Добавить ключ через `gpg --dearmor` в `/usr/share/keyrings/` и использовать опцию `signed-by` в `sources.list`. |
| **База данных заблокирована** | Некорректное завершение предыдущего процесса. | Удалить файл блокировки (например, `~/.aptly/db/LOCK` для aptly), предварительно убедившись, что процесс не запущен. |
| **Медленный apt update** | Слишком много мелких файлов PDiffs. | Отключить использование PDiffs на стороне клиента: `Acquire::PDiffs "false";`. |
