## Basic Concepts

### Назначение локального зеркала

| Преимущество | Описание |
| :--- | :--- |
| **Экономия трафика** | Пакеты скачиваются из интернета однократно, затем распространяются локально |
| **Ускорение обновлений** | Установка и обновление пакетов происходят быстрее (LAN vs WAN) |
| **Работа в изолированных сетях** | Управление пакетами в сетях без доступа к интернету (air-gapped environments) |
| **Контроль версий** | Возможность заморозить версии пакетов для стабильности |
| **Кэширование** | Сохранение старых версий для отката при необходимости |

### Архитектура зеркалирования

```
┌─────────────────┐      ┌──────────────────┐      ┌─────────────────┐
│   Интернет      │─────▶│  Сервер-зеркало  │─────▶│  Клиентские     │
│   Репозитории   │      │  (apt-mirror)    │      │  машины         │
│   (upstream)    │      │                  │      │                 │
└─────────────────┘      └──────────────────┘      └─────────────────┘
                                │
                                ▼
                         ┌──────────────────┐
                         │  Хранилище       │
                         │  /var/spool/     │
                         │  apt-mirror/     │
                         └──────────────────┘
```

### Принцип работы

1. **Первичная синхронизация** — `apt-mirror` скачивает полное содержимое указанных репозиториев (Packages, Sources, Release-файлы, .deb-пакеты)
2. **Инкрементальная синхронизация** — последующие запуски скачивают только изменения (delta), что значительно быстрее
3. **Раздача клиентам** — хранилище публикуется через HTTP-сервер (Apache, Nginx) или файловую систему (NFS)
4. **Настройка клиентов** — на клиентских машинах `sources.list` указывает на локальное зеркало

### Инструменты зеркалирования APT

| Инструмент | Назначение | Когда использовать |
| :--- | :--- | :--- |
| `apt-mirror` | Автоматическое зеркалирование APT-репозиториев | Полное копирование upstream-репо |
| `debmirror` | Гибкое зеркалирование с фильтрацией | Выборочное зеркалирование по архитектуре, секциям, ключевым словам |
| `reprepro` | Создание приватных репозиториев | Публикация собственных .deb-пакетов (не зеркалирование upstream) |

### Выбор между зеркалированием и приватным репозиторием

| Критерий | Зеркалирование (`apt-mirror`) | Приватный репозиторий (`reprepro`) |
| :--- | :--- | :--- |
| **Цель** | Копирование внешних репо | Публикация внутренних пакетов |
| **Источник** | Официальные репозитории | Собственные .deb-пакеты |
| **Подпись GPG** | Не требуется | Обязательна |
| **Типичный сценарий** | Оффлайн-инфраструктура, экономия трафика | CI/CD, доставка внутренних приложений |

## Additional Information

- **Расчёт дискового пространства** — Ubuntu 22.04 ~200 GB (полный), ~50 GB (main only); Debian 12 ~400 GB / ~80 GB
- **Оптимизация** — фильтрация по архитектурам, инкрементальная синхронизация, очистка старых пакетов
- **Мониторинг** — логирование синхронизации, уведомления об ошибках
- **Типовые проблемы** — 404 ошибки при изменении структуры репо, GPG-ошибки на клиентах, нехватка места
