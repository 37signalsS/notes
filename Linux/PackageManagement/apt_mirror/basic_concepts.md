## Основные концепции

### Назначение локального зеркала

| Преимущество | Описание |
| :--- | :--- |
| **Экономия трафика** | Пакеты скачиваются из внешних сетей однократно, затем распространяются по LAN. |
| **Скорость доставки** | Установка и обновление пакетов происходят на скорости локальной сети. |
| **Изолированные среды** | Обеспечение работы систем в закрытых контурах (air-gapped) без доступа к интернету. |
| **Стабильность (Snapshot)** | Фиксация состояния репозитория на определённый момент времени для предотвращения поломок при обновлении. |
| **Безопасность** | Возможность предварительной проверки пакетов перед их публикацией во внутреннем зеркале. |

### Архитектура зеркалирования

```
┌─────────────────┐       ┌──────────────────┐       ┌─────────────────┐
│   Интернет      │       │  Сервер-зеркало  │       │  Клиентские     │
│   Репозитории   │──────▶│ (aptly / mirror) │──────▶│  машины         │
│   (upstream)    │       │                  │       │  (Desktop/Srv)  │
└─────────────────┘       └──────────────────┘       └─────────────────┘
         │                         │                          ▲
         │                         ▼                          │
         │                ┌──────────────────┐        ┌───────┴──────┐
         │                │    Хранилище     │        │  Веб-сервер  │
         └───────────────▶│ (Disk / S3 / NFS)│───────▶│ (Nginx/Apache)│
                          └──────────────────┘        └──────────────┘
```

### Жизненный цикл зеркала

1.  **Конфигурация** — определение списка upstream-репозиториев, архитектур и компонентов в конфигурационном файле (`mirror.list` или конфиг `aptly`).
2.  **Синхронизация (Update)** — загрузка метаданных и пакетов. Современные инструменты используют инкрементальное обновление (только изменённые файлы).
3.  **Создание снимка (Snapshot)** — *рекомендуемый этап*. Фиксация состояния загруженных данных. Позволяет переключаться между версиями репозитория.
4.  **Публикация (Publish)** — раздача содержимого снимка через HTTP/HTTPS.
5.  **Потребление** — настройка клиентов через `sources.list` на URL локального зеркала.

### Инструменты зеркалирования APT

| Инструмент | Назначение | Особенности |
| :--- | :--- | :--- |
| **aptly** | Универсальный инструмент управления репозиториями | Поддержка снимков, REST API, работа с S3, объединение нескольких зеркал. **Рекомендуемый выбор**. |
| **apt-mirror** | Простое зеркалирование «один-в-один» | Легко настраивается, но ограничен в управлении версиями и не поддерживает снимки. |
| **debmirror** | Гибкое зеркалирование с фильтрацией | Мощные возможности фильтрации по секциям, приоритетам и регулярным выражениям. |

### Зеркалирование vs Приватный репозиторий

| Критерий | Зеркалирование | Приватный репозиторий |
| :--- | :--- | :--- |
| **Источник данных** | Внешние официальные зеркала | Собственные `.deb` пакеты компании |
| **GPG-подпись** | Проверка подписи издателя (Ubuntu/Debian) | Наложение собственной GPG-подписи |
| **Инструменты** | `aptly`, `apt-mirror`, `debmirror` | `reprepro`, `aptly` |
| **Управление версиями** | Обычно только актуальные версии | Полный контроль над жизненным циклом пакета |
| **Сценарий** | Экономия WAN-трафика, оффлайн-среды | CI/CD, доставка внутреннего ПО |

## Практические сценарии

Краткий перечень сценариев. Подробные инструкции доступны в файле **[Практические сценарии](./practical_scenarios.md)**.

| Сценарий | Описание |
| :--- | :--- |
| **Создание зеркала Ubuntu** | Настройка `aptly` или `apt-mirror`, публикация через Nginx. |
| **Обновление в air-gap** | Перенос синхронизированного хранилища на внешнем диске с помощью `rsync`. |
| **Безопасный переход** | Использование снимков для тестирования обновлений перед массовым деплоем. |
| **Объединение зеркал** | Создание единого источника из нескольких разных upstream-репозиториев. |

## Дополнительная информация

### Требования к ресурсам
- **Дисковое пространство**:
  - Ubuntu 22.04/24.04 (полное зеркало): ~250–300 GB на одну архитектуру.
  - Debian 11/12 (полное зеркало): ~400–500 GB.
  - Режим `main` only: сокращает объём в 3–4 раза.
- **Сеть**: Рекомендуется канал от 100 Мбит/с для первичной синхронизации.
