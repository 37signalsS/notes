# Зеркалирование APT: Определения

## Определения

**Локальное зеркало (Local Mirror)** — полная или частичная копия удалённого репозитория пакетов (например, Ubuntu, Debian), размещённая в локальной сети или на изолированном сервере. Служит для экономии WAN-трафика, ускорения доставки пакетов и работы в изолированных (air-gapped) средах.

**Репозиторий-источник (Upstream Repository)** — официальный или доверенный удалённый репозиторий, с которого синхронизируется локальное зеркало. Примеры: `archive.ubuntu.com`, `security.ubuntu.com`, `deb.debian.org`, `ppa.launchpad.net`.

**Синхронизация** — процесс обновления локального зеркала до актуального состояния репозитория-источника. Бывает первичной (полное копирование) и инкрементальной (только delta-изменения).

**APT (Advanced Package Tool)** — система управления пакетами в Debian/Ubuntu, использующая репозитории для установки, обновления и удаления ПО. Основные команды: `apt update`, `apt upgrade`, `apt install`.

**Индексы репозитория** — метаданные APT, содержащие информацию о доступных пакетах, версиях, зависимостях и контрольных суммах. Основные файлы: `Packages`, `Sources`, `Release`, `InRelease`.

**Кодовое имя (Codename)** — символическое имя версии дистрибутива (например, `focal`, `jammy` для Ubuntu или `bullseye`, `bookworm` для Debian). Используется в путях репозитория и конфигурации `sources.list`.

**Компоненты репозитория (Components)** — логические секции внутри репозитория:
- `main` — свободное ПО, официально поддерживаемое дистрибутивом.
- `restricted` — проприетарные драйверы и firmware (Ubuntu).
- `universe` — пакеты, поддерживаемые сообществом (Ubuntu).
- `multiverse` — ПО с ограниченной лицензией (Ubuntu).
- `non-free`, `contrib` — секции для несвободного ПО в Debian.

**Архитектура (Architecture)** — целевая платформа пакетов: `amd64`, `arm64`, `i386`, `source` (исходный код). Зеркалирование может включать одну или несколько архитектур.

**Пулы пакетов (Pool)** — единое хранилище `.deb`-файлов в репозитории, на которое ссылаются индексные файлы. Структура: `pool/<component>/<первая-буква>/<имя-пакета>/`. Это позволяет разным релизам использовать одну и ту же версию пакета без дублирования файлов.

**GPG (GNU Privacy Guard)** — инструмент для создания цифровых подписей. Используется для подтверждения подлинности индексов репозитория и предотвращения подмены пакетов.

**APT Secure** — механизм безопасности APT, проверяющий цепочку доверия от GPG-ключа до хэш-сумм каждого файла в репозитории.

**PDiffs (Patch Diffs)** — файлы дельта-обновлений индексов. Позволяют скачивать только изменения в `Packages` или `Sources`, значительно экономя трафик при ежедневной синхронизации.

**Снимок (Snapshot)** — копия репозитория, зафиксированная в определённый момент времени. Позволяет обеспечить воспроизводимость сборок и стабильность обновлений (реализуется инструментами типа `aptly`).

## Основные концепции

### Ключевые файлы APT-репозитория

| Файл | Назначение |
| :--- | :--- |
| `dists/<codename>/Release` | Метаданные релиза: компоненты, архитектуры, хэш-суммы индексных файлов. |
| `dists/<codename>/Release.gpg` | Отсоединённая GPG-подпись для файла `Release`. |
| `dists/<codename>/InRelease` | Совмещённый файл: метаданные `Release` и GPG-подпись в одном файле. |
| `dists/<codename>/<comp>/binary-<arch>/Packages` | Список бинарных пакетов с описаниями, зависимостями и хэшами. |
| `dists/<codename>/<comp>/source/Sources` | Список пакетов исходного кода. |
| `pool/` | Общее хранилище всех `.deb` и исходных файлов. |

### Экосистема Debian/Ubuntu

- **Debian** — стабильный дистрибутив, использующий репозитории `deb.debian.org` и `security.debian.org`. Основные ветки: `stable`, `testing`, `unstable`.
- **Ubuntu** — дистрибутив на базе Debian с собственным циклом релизов и репозиториями `archive.ubuntu.com`.
- **PPA (Personal Package Archive)** — пользовательские репозитории на платформе Launchpad для публикации свежих версий ПО.
- **Совместимость** — пакеты Ubuntu и Debian часто не взаимозаменяемы из-за различий в версиях системных библиотек (например, `libc`).

## Дополнительная информация

### Инструменты зеркалирования

Хотя традиционно используется `apt-mirror`, существуют современные альтернативы:
- **aptly** — мощный инструмент с поддержкой снимков (snapshots), публикации нескольких зеркал и REST API.
- **debmirror** — гибкая утилита с глубокой настройкой фильтрации по секциям и архитектурам.
