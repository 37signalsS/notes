# Зеркалирование APT: Определения

## Определения

Ниже приведены термины, используемые при работе с зеркалами репозиториев в экосистеме Debian и Ubuntu.

### Базовые понятия

**Локальное зеркало (Local Mirror)** — полная или частичная копия удалённого репозитория пакетов, размещённая в локальной сети или на изолированном сервере. Служит для экономии WAN-трафика, ускорения доставки пакетов и работы в изолированных (air-gapped) средах.

**Репозиторий-источник (Upstream Repository)** — официальный или доверенный удалённый репозиторий, с которого синхронизируется локальное зеркало. Примеры: `archive.ubuntu.com`, `security.ubuntu.com`, `deb.debian.org`.

**Синхронизация** — процесс обновления локального зеркала до актуального состояния репозитория-источника. Бывает первичной (полное копирование) и инкрементальной (только изменения).

**APT (Advanced Package Tool)** — система управления пакетами в Debian/Ubuntu, использующая репозитории для установки, обновления и удаления ПО.

**Индексы репозитория** — метаданные APT, содержащие информацию о доступных пакетах, версиях, зависимостях и контрольных суммах. Основные файлы: `Packages`, `Sources`, `Release`, `InRelease`.

**Кодовое имя (Codename)** — символическое имя версии дистрибутива (например, `focal`, `jammy` для Ubuntu или `bullseye`, `bookworm` для Debian).

**Компоненты репозитория (Components)** — логические секции внутри репозитория (например, `main`, `restricted`, `universe`, `multiverse` в Ubuntu; `main`, `non-free`, `contrib` в Debian).

**Архитектура (Architecture)** — целевая платформа пакетов: `amd64`, `arm64`, `i386`, `source` (исходный код).

**Пулы пакетов (Pool)** — единое хранилище `.deb`-файлов в репозитории, на которое ссылаются индексные файлы. Структура `pool/` позволяет разным релизам использовать одну и ту же версию пакета без дублирования.

### Структура и форматы

**DEB822** — современный многострочный формат конфигурации репозиториев (файлы `.sources`), пришедший на смену однострочному формату в `sources.list`. Поддерживает расширенные параметры и типизацию.

**Flat-репозиторий (Плоский репозиторий)** — репозиторий с упрощенной структурой, где пакеты и индексы находятся в одной директории без разделения на `pool` и `dists`. Часто используется для небольших приватных репозиториев.

**By-Hash** — механизм доступа к индексным файлам по их хэш-сумме. Предотвращает ошибку "Hash Sum mismatch", возникающую при обновлении индексов на сервере во время скачивания клиентом.

**Contents (Contents-<arch>.gz)** — индексный файл со списком всех файлов во всех пакетах репозитория. Используется инструментом `apt-file`.

**Translation (Translation-<lang>)** — индексы, содержащие переводы описаний пакетов на национальные языки.

**DEP-11 (AppStream)** — метаданные для программных центров, содержащие иконки, скриншоты и дополнительные описания приложений.

### Безопасность

**GPG (GNU Privacy Guard)** — инструмент для создания цифровых подписей, подтверждающих подлинность индексов репозитория.

**APT Secure** — механизм безопасности APT, проверяющий цепочку доверия от GPG-ключа до хэш-сумм каждого файла.

**Keyring (Связка ключей)** — файл или каталог (например, `/usr/share/keyrings/`), содержащий публичные GPG-ключи доверенных репозиториев.

**Signed-By** — опция в конфигурации репозитория (`sources.list` или DEB822), указывающая путь к конкретному ключу, которым должен быть подписан данный репозиторий.

### Прочее

**PDiffs (Patch Diffs)** — файлы дельта-обновлений индексов, позволяющие скачивать только изменения в `Packages`.

**Снимок (Snapshot)** — копия репозитория, зафиксированная в определённый момент времени для обеспечения воспроизводимости сборок (реализуется через `aptly`).

**apt-mirror** — простой инструмент для создания локальных зеркал APT-репозиториев. Хранит конфигурацию в `/etc/apt/mirror.list`, поддерживает базовую фильтрацию по архитектурам и компонентам, многопоточную загрузку и переменные окружения для прокси. Подходит для небольших сетей, где не требуется управление снимками.

**aptly** — продвинутый инструмент для управления APT-репозиториями и зеркалами. Поддерживает снимки (snapshots), объединение репозиториев, публикацию через HTTP/S3 и REST API. Использует базу данных (PostgreSQL или SQLite) для хранения метаданных о пакетах. Рекомендуется для средних и крупных инфраструктур.

**debmirror** — утилита для зеркалирования с расширенной фильтрацией пакетов по зависимостям, секциям и архитектурам. Подходит для создания частичных зеркал со сложными критериями отбора пакетов.

**apt-offline** — утилита для установки и обновления пакетов в air-gapped средах. Генерирует сигнатуру запроса на машине без доступа к сети, скачивает пакеты и индексы на машине с интернетом, затем устанавливает их из архива.

**apt-cacher-ng** — кэширующий HTTP-прокси для APT. Прозрачно кэширует запрашиваемые пакеты, уменьшая WAN-трафик в средних сетях без полного зеркала. Работает по принципу «первый запрос — полная загрузка, последующие — из кэша».

**dpkg** — низкоуровневый инструмент для установки, удаления и управления индивидуальными `.deb`-пакетами. APT использует `dpkg` как бэкенд для фактической установки файлов, но не управляет зависимостями на этом уровне.

**Sneakernet** — практика переноса данных между изолированными сетями с помощью физических носителей (USB, внешние диски). В контексте APT используется для первичного наполнения и последующего обновления air-gapped зеркал.

**Hash Sum mismatch** — ошибка APT, возникающая когда хэш-сумма скачанного файла не совпадает с указанной в индексе. Типичные причины: обновление индексов в upstream во время скачивания, повреждение кэша, ошибки сетевого оборудования. Устраняется повторным запуском синхронизации или отключением `Acquire::PDiffs "false"` на клиенте.

### Конфигурация APT

**sources.list** — основной конфигурационный файл APT в классическом однострочном формате (`deb`, `deb-src`). Располагается в `/etc/apt/sources.list`. Содержит URI репозиториев, кодовые имена релизов и компоненты.

**sources.list.d/** — директория для размещения дополнительных конфигурационных файлов репозиториев в формате `.list`. Позволяет пакетам (например, `docker-ce`) добавлять свои источники без редактирования основного файла. Файлы обрабатываются в алфавитном порядке.

**apt.conf.d/** — директория для drop-in конфигурации APT. Файлы в формате key-value (например, `99custom`) переопределяют настройки из `/etc/apt/apt.conf`. Приоритет определяется порядком загрузки (алфавитный) и вложенными каталогами.

**preferences** — файл `/etc/apt/preferences` для управления приоритетами пакетов (apt pinning). Позволяет зафиксировать версии пакетов или отдавать предпочтение определенным источникам.
