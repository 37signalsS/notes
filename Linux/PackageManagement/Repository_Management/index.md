# Управление репозиториями DNF

## Определения

Ниже приведены основные термины, описывающие структуру и механизмы работы хранилищ программного обеспечения в дистрибутивах на базе RPM (Red Hat Package Manager).

**Репозиторий DNF (Dandified YUM)** — сервер или локальный каталог, содержащий пакеты формата RPM и метаданные в формате, совместимом с пакетными менеджерами DNF и YUM. Конфигурация осуществляется через файлы в директории `/etc/yum.repos.d/`.

**Идентификатор репозитория (repo_id)** — уникальное краткое имя репозитория, используемое в конфигурационных файлах (в квадратных скобках `[repo_id]`) и командах DNF (например, `--enablerepo=repo_id`).

**GPG-ключ репозитория** — публичный криптографический ключ GPG (GNU Privacy Guard), используемый для проверки цифровой подписи пакетов и метаданных. Это гарантирует, что программное обеспечение не было изменено и было подписано доверенным источником.

**Metalink / Mirrorlist** — механизмы динамического выбора зеркал (серверов) для загрузки пакетов. Обеспечивают высокую доступность, отказоустойчивость и автоматическую балансировку нагрузки между серверами.

**BaseOS** — основной репозиторий в дистрибутивах RHEL 8+ и Fedora, содержащий минимальный набор пакетов, необходимых для работы ядра и базовой операционной системы. Гарантирует стабильность фундамента ОС.

**AppStream** — репозиторий (в RHEL 8+ и Fedora), содержащий прикладное программное обеспечение, модули и инструменты, которые могут иметь несколько версий (streams) и разную длительность поддержки.

## Основные концепции

### Структура .repo файла

Файлы конфигурации репозиториев используют формат INI и должны иметь расширение `.repo`. Они располагаются в директории `/etc/yum.repos.d/`.

| Параметр | Описание | Пример значения |
| :--- | :--- | :--- |
| `[repo_id]` | Уникальный идентификатор репозитория | `[fedora-updates]` |
| `name` | Человекочитаемое описание | `Fedora 40 - Updates` |
| `baseurl` | Прямой URL хранилища (http, https, ftp, file) | `https://dl.fedoraproject.org/...` |
| `mirrorlist` | URL списка доступных зеркал | `http://mirrors.fedoraproject.org/...` |
| `metalink` | URL metalink-файла (рекомендуется для Fedora) | `https://mirrors.fedoraproject.org/...` |
| `enabled` | Состояние репозитория: `1` — включён, `0` — выключен | `1` |
| `gpgcheck` | Проверка GPG-подписи каждого пакета | `1` |
| `gpgkey` | Путь или URL к файлу публичного ключа GPG | `file:///etc/pki/rpm-gpg/RPM-GPG-KEY` |
| `repo_gpgcheck` | Проверка подписи метаданных самого репозитория | `0` |
| `priority` | Приоритет (1 — наивысший, 99 — низший) | `50` |
| `cost` | Относительная "цена" доступа (меньше — предпочтительнее) | `1000` |
| `module_hotfixes` | Разрешить установку пакетов, перекрывающих модули | `1` |
| `metadata_expire` | Время актуальности кэша метаданных | `6h`, `1d`, `never` |
| `skip_if_unavailable` | Игнорировать репозиторий, если он недоступен | `1` |
| `proxy` | Прокси-сервер для данного репозитория | `http://proxy.example.com:3128` |

### Переменные в URL репозиториев

DNF поддерживает динамическую подстановку значений, что позволяет использовать универсальные пути для разных архитектур и версий ОС.

| Переменная | Описание | Источник |
| :--- | :--- | :--- |
| `$releasever` | Мажорная версия дистрибутива | `/etc/os-release` |
| `$basearch` | Базовая архитектура системы (x86_64, aarch64) | Ядро Linux |
| `$arch` | Конкретная архитектура CPU (i686, x86_64) | `uname -i` |
| `$uuid` | Уникальный идентификатор системы | `/etc/dnf/plugins/versionlock.conf` или `/var/lib/dnf/yumdb` |
| `$infra` | Тип инфраструктуры (например, `container`) | Автоопределение DNF |
| `$vars` | Пользовательские переменные | Файлы в `/etc/dnf/vars/` |

**Кастомные переменные:** Вы можете создать файл `/etc/dnf/vars/myvar` с содержимым `prod`, и использовать переменную `$myvar` в `.repo` файлах.

## Практические сценарии

Управление репозиториями осуществляется как путем прямого редактирования файлов, так и через специализированный инструментарий:

- **[Операции с репозиториями](./operations.md)** — команды `dnf config-manager`, `dnf repolist`, добавление и удаление источников, управление GPG-ключами.
- **[Создание собственного репозитория](./custom_repository.md)** — процедура подготовки локального RPM-хранилища с помощью `createrepo_c`.
- **[Зеркалирование YUM/DNF](../yum_dnf_repository_mirror.md)** — организация локального зеркала (upstream) для изолированных сред через `reposync`.

### Работа через dnf config-manager

Утилита `config-manager` (входит в `dnf-plugins-core`) позволяет безопасно изменять настройки:

```bash
# Добавление репозитория
sudo dnf config-manager --add-repo https://example.com/repo.repo

# Включение/выключение
sudo dnf config-manager --set-enabled <repo_id>
sudo dnf config-manager --set-disabled <repo_id>

# Установка произвольного параметра
sudo dnf config-manager --setopt=<repo_id>.priority=10 --save
```
