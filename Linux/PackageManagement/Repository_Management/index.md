# Управление репозиториями пакетов в Linux

## Определения

Ниже приведены ключевые термины, описывающие структуру и механизмы работы хранилищ программного обеспечения в экосистемах RPM (Red Hat Package Manager) и DEB (Debian Package).

**Репозиторий (Repository)** — структурированное хранилище пакетов и их метаданных (индексов), позволяющее пакетным менеджерам находить, скачивать и автоматически обновлять программное обеспечение. В Linux существуют две основные семейства репозиториев: RPM (для Fedora, RHEL, AlmaLinux, Rocky Linux) и DEB (для Debian, Ubuntu).

### Репозитории RPM (DNF/YUM)

**Репозиторий DNF (Dandified YUM)** — сервер или локальный каталог, содержащий пакеты формата RPM и метаданные в формате, совместимом с пакетными менеджерами DNF и YUM. Конфигурация осуществляется через файлы в директории `/etc/yum.repos.d/`. Современный менеджер DNF унаследовал всю файловую структуру директории `/etc/yum.repos.d/` от устаревшей утилиты YUM, поэтому конфигурационные файлы сохраняют расширение `.repo` и INI-совместимый синтаксис.

**Идентификатор репозитория (repo_id)** — уникальное краткое имя репозитория, используемое в конфигурационных файлах (в квадратных скобках `[repo_id]`) и командах DNF (например, `--enablerepo=repo_id`).

**GPG-ключ репозитория** — публичный криптографический ключ GPG (GNU Privacy Guard), используемый для проверки цифровой подписи пакетов и метаданных. Это гарантирует аутентичность и целостность ПО.

**Metalink / Mirrorlist** — механизмы динамического выбора зеркал.
- **Mirrorlist**: Возвращает простой список URL зеркал.
- **Metalink**: Возвращает XML-файл с метаданными о зеркалах, включая контрольные суммы и приоритеты, что обеспечивает более надёжный выбор.

**BaseOS / AppStream** — разделение репозиториев в RHEL 8+ и Fedora.
- **BaseOS**: Критические пакеты ядра и базовой системы.
- **AppStream**: Прикладное ПО, модули и инструменты с различными циклами обновления.

**Метаданные репозитория (Repodata)** — набор XML/zstd/SQLite индексов, описывающих зависимости, контрольные суммы и списки файлов всех пакетов. В DNF 4+ метаданные хранятся в SQLite для ускорения поиска; в устаревших системах — в XML. Ключевые файлы: `repomd.xml` (индекс индексов), `primary.xml`/`primary.sqlite` (список пакетов), `filelists.xml` (списки файлов), `modules.yaml` (модульные потоки AppStream).

**Дельта-пакет (Delta RPM / DRPM)** — сжатый пакет, содержащий только изменения между двумя версиями пакета. Позволяет сократить объём загрузки на 60–90% при обновлении небольших исправлений. В DNF 5 поддержка DRPM удалена из соображений производительности.

**Модульный поток (Module Stream)** — версия пакета или набора пакетов в репозитории AppStream. Например, `nodejs:18` и `nodejs:20` — разные потоки одного модуля. Клиент может активировать только один поток за раз.

**Createrepo_c** — утилита на C для создания локальных RPM-репозиториев. Генерирует `repodata` и индексы. Наследник `createrepo` на Python.

**Reposync** — плагин DNF для односторонней синхронизации репозитория. Поддерживает фильтрацию по архитектуре, пакетам, группам, загрузку дельта-пакетов и инкрементальное обновление.

**Repomanage** — утилита из `yum-utils` для управления версиями пакетов в локальном репозитории (удаление устаревших версий перед переиндексацией).

### Репозитории DEB (APT)

**APT-репозиторий** — сервер или локальный каталог, хранящий пакеты (`.deb`) и метаданные (индексы) в стандартизированной структуре. Позволяет системе APT (Advanced Package Tool) находить, устанавливать и автоматически обновлять программное обеспечение.

**sources.list** — основной конфигурационный файл (`/etc/apt/sources.list`), указывающий системе, по каким сетевым или локальным адресам искать пакеты. На современных системах (Debian 12+, Ubuntu 24.04+) этот файл может содержать только комментарий о миграции настроек в директорию `/etc/apt/sources.list.d/`.

**Файлы `.sources`** — конфигурационные файлы в директории `/etc/apt/sources.list.d/` с расширением `.sources`, использующие формат DEB822 (многострочные блоки). На Ubuntu 24.04+ файл `sources.sources` является основным хранилищем адресов репозиториев, заменяя классический `sources.list`.

**Release-файл** — текстовый метаданный файл в директории `dists/<suite>/`, содержащий информацию о дистрибутиве: дату выпуска, поддерживаемые архитектуры, список компонентов, хэш-суммы индексных файлов (`Packages`, `Sources`, `Contents`) и флаги безопасности (`Not-Automatic`, `But-Automatic-Upgrades`).

**InRelease** — объединённый файл, содержащий метаданные `Release` и встроенную подпись (clear-signed). Используется для проверки целостности репозитория без отдельного файла `Release.gpg`.

**Packages.gz / Packages** — индексный файл со списком всех доступных бинарных пакетов (`.deb`) в репозитории, их версий, зависимостях, размерах и контрольных суммах. Файл сжимается в `.gz` для экономии трафика.

**Sources** — индексный файл с исходными пакетами (`.dsc`, `.tar.gz`, `.debian.tar.xz`). Необходим для пересборки пакетов.

**Pool (Пул)** — глобальное хранилище всех файлов пакетов (`.deb`, `.dsc`, `.tar.gz`) внутри репозитория. Файлы организуются в иерархию по начальным буквам их названий, что позволяет использовать один и тот же файл в разных дистрибутивах без дублирования на диске.

**Suite (Сют)** — логическая группа дистрибутивов, объединённых общим циклом разработки. Примеры: `stable`, `testing`, `unstable` в Debian или `noble`, `jammy` в Ubuntu.

**Codename (Кодовое имя)** — символическое имя конкретного выпуска дистрибутива (например, `bookworm`, `noble`, `jammy`). Является первичным ключом для поиска пакетов в `sources.list`.

**Компонент репозитория (Section/Component)** — логическая секция пакетов (например, `main`, `universe`), разделяющая ПО по типу лицензии, происхождению и уровню поддержки.

**PPA (Personal Package Archive)** — персональные архивы пакетов в экосистеме Ubuntu (Launchpad), позволяющие разработчикам публиковать версии ПО, отличные от официальных.

**By-Hash** — механизм доступа к индексным файлам и пакетам по их хэш-сумме вместо имени файла. Предотвращает ошибку "Hash Sum mismatch" при обновлении индексов на сервере во время скачивания клиентом.

**PDiffs (Patch Diffs)** — файлы дельта-обновлений индексов, позволяющие скачивать только изменения в `Packages`, а не полный файл целиком. Уменьшает трафик при частых обновлениях репозиториев.

**apt preferences** — механизм управления приоритетами источников пакетов. Позволяет зафиксировать версии, отдавать предпочтение определённым репозиториям или блокировать пакеты. Подробнее в документе **[Управление приоритетами пакетов в Apt (Pinning)](../deb_apt_pinning.md)**.

**reprepro** — утилита для управления приватными APT-репозиториями. Поддерживает фильтрацию пакетов, подпись GPG, автоматическую переиндексацию.

**aptly** — современный инструмент для профессионального управления APT-репозиториями и зеркалами. Поддерживает снимки (Snapshots), REST API, объединение репозиториев.

**apt-mirror** — простая утилита для создания полных или частичных зеркал APT-репозиториев.

**debmirror** — утилита для зеркалирования с расширенной фильтрацией пакетов по зависимостям и секциям.

**apt-cacher-ng** — кэширующий прокси для APT, уменьшающий объём загружаемых данных в средних сетях.

## Основные концепции

### Типология репозиториев

В инфраструктуре DevOps/SRE репозитории классифицируют по назначению и источнику данных:

| Тип | RPM-экосистема | DEB-экосистема | Назначение |
| :--- | :--- | :--- | :--- |
| **Официальный (Base)** | `baseos`, `appstream`, `epel` | `main`, `restricted`, `universe` | Основные репозитории дистрибутива |
| **Сторонний (Third-party)** | Docker CE, EPEL, COPR | PPA, Docker CE, Grafana | ПО, не входящее в официальные каналы |
| **Приватный (Private)** | Custom repo (`createrepo_c`) | reprepro, aptly private | Внутреннее ПО организации |
| **Зеркало (Mirror)** | `reposync` + `createrepo_c` | aptly, apt-mirror, debmirror | Локальная копия для Air-Gapped сред |
| **Снимок (Snapshot)** | `createrepo_c` + hardlinks | aptly snapshot, snapshot.debian.org | Фиксация состояния для воспроизводимости |

### Структура репозиториев RPM

Конфигурация источников для DNF/YUM осуществляется через INI-файлы с расширением `.repo` в директории `/etc/yum.repos.d/`.

#### Параметры конфигурации `.repo` файла

| Параметр | Описание | Пример значения |
| :--- | :--- | :--- |
| `[repo_id]` | Уникальный идентификатор репозитория | `[fedora-updates]` |
| `name` | Человекочитаемое описание | `Fedora 40 - Updates` |
| `baseurl` | Прямой URL хранилища (http, https, ftp, file) | `https://dl.fedoraproject.org/...` |
| `mirrorlist` | URL списка доступных зеркал | `http://mirrors.fedoraproject.org/...` |
| `metalink` | URL metalink-файла | `https://mirrors.fedoraproject.org/...` |
| `enabled` | Состояние репозитория: `1` — включён, `0` — выключен | `1` |
| `gpgcheck` | Проверка GPG-подписи каждого пакета | `1` |
| `gpgkey` | Путь или URL к файлу публичного ключа GPG | `file:///etc/pki/rpm-gpg/RPM-GPG-KEY` |
| `repo_gpgcheck` | Проверка подписи метаданных самого репозитория | `0` |
| `priority` | Приоритет (1 — наивысший, 99 — низший) | `50` |
| `includepkgs` | Список пакетов, которые РАЗРЕШЕНО брать из этого репозитория | `nginx, php-*` |
| `exclude` | Список пакетов, которые ЗАПРЕЩЕНО брать из этого репозитория | `kernel*` |
| `metadata_expire` | Время актуальности кэша метаданных | `6h`, `1d`, `never` |
| `module_hotfixes` | Разрешить установку пакетов, перекрывающих модули | `1` |
| `failovermethod` | Метод перебора зеркал (`roundrobin` или `priority`) | `priority` |

`baseurl` — ключевой параметр для прямого указания URL хранилища пакетов. В отличие от `mirrorlist` и `metalink`, которые динамически выбирают зеркала, `baseurl` задаёт фиксированный адрес репозитория и является обязательным, если не используются `mirrorlist` или `metalink`. На экзаменационных тестах (например, LPIC-1) именно путь `/etc/yum.repos.d/` и параметр `baseurl` проверяются как ключевая файловая иерархия пакетных менеджеров RPM-семейства.

#### ЛAYOUT локального RPM-репозитория

```text
/var/www/html/repo/
├── x86_64/                 # Директория архитектуры (рекомендуется)
│   ├── Packages/           # (Опционально) Хранилище .rpm файлов
│   │   ├── app-1.0.rpm
│   │   └── lib-2.0.rpm
│   ├── repodata/           # Генерируется автоматически через createrepo_c
│   │   ├── repomd.xml      # Индекс индексов
│   │   └── *.xml.zst       # Сжатые таблицы пакетов
│   └── comps.xml           # Файл групп (если используется)
└── RPM-GPG-KEY-myrepo      # Публичный ключ для клиентов
```

### Структура репозиториев DEB

Конфигурация источников для APT осуществляется через файлы `/etc/apt/sources.list` и `/etc/apt/sources.list.d/*.list` (классический формат) или `/etc/apt/sources.list.d/*.sources` (современный DEB822).

#### Форматы файлов источников

**Традиционный формат (One-line):**
```bash
# Тип [Опции] URL Дистрибутив Компоненты
deb [arch=amd64 signed-by=/etc/apt/keyrings/repo.gpg] https://repo.example.com/debian bookworm main
```

**Современный формат (DEB822):**
```ini
Types: deb deb-src
URIs: https://deb.debian.org/debian
Suites: bookworm bookworm-updates bookworm-backports
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
Architectures: amd64 arm64
```

#### LAYOUT официального DEB-репозитория

```text
deb.debian.org/debian/
├── dists/
│   └── bookworm/
│       ├── Release
│       ├── InRelease
│       ├── Release.gpg
│       ├── main/
│       │   ├── binary-amd64/
│       │   │   ├── Packages
│       │   │   ├── Packages.gz
│       │   │   └── Release
│       │   └── binary-arm64/
│       │       └── ...
│       ├── contrib/
│       │   └── ...
│       └── non-free-firmware/
│           └── ...
└── pool/
    ├── main/
    │   └── a/
    │       └── app/
    │           └── app_1.0_amd64.deb
    ├── contrib/
    └── non-free-firmware/
```

Директория `dists/` содержит метаданные (индексы) с разделением по архитектурам и компонентам. Директория `pool/` содержит фактические `.deb`-файлы, организованные по начальным буквам названий пакетов для дедупликации между дистрибутивами.

### Безопасность и аутентификация

#### RPM (DNF/YUM)

Для доступа к защищённым (приватным) репозиториям используются параметры SSL/TLS и прокси:

- **SSL-сертификаты:**
  - `sslcacert`: Путь к сертификату CA для проверки сервера.
  - `sslclientcert`: Путь к клиентскому сертификату для аутентификации.
  - `sslclientkey`: Путь к приватному ключу клиента.
- **Прокси-сервер:**
  - `proxy`: URL прокси (например, `http://proxy.example.com:3128`).
  - `proxy_username` / `proxy_password`: Учетные данные для аутентификации на прокси.

Обязательно включайте `repo_gpgcheck=1` вместе с `gpgcheck=1` для защиты от атак подмены метаданных и пакетов.

#### DEB (APT)

Использование устаревшего `apt-key add` небезопасно, так как ключ добавляется в глобальное доверенное хранилище. Современный стандарт требует:
1. **Изоляция**: Ключи хранятся в `/etc/apt/keyrings/` (для сторонних) или `/usr/share/keyrings/` (для системных).
2. **Формат**: Ключи должны быть в бинарном формате (OpenPGP ASCII Armor должен быть конвертирован через `gpg --dearmor`).
3. **Привязка**: Использование опции `signed-by` в строке репозитория для жесткой привязки ключа к конкретному источнику.

#### Защита на сетевом уровне (SRE/DevOps)

Для критичных контуров используйте:
- **mTLS (Mutual TLS)**: Взаимная аутентификация клиента и сервера репозитория. Реализуется через Nginx/HAProxy с клиентскими сертификатами. Подробнее в документе **[Nginx: Настройка защищённого репозитория](../../../WebServers/Nginx/Scenarios/secure_apt_repository_guide.md)**.
- **Сетевая изоляция**: Размещайте репозиторий в отдельном сегменте сети (VLAN). Разрешите только исходящий HTTPS (443) для upstream и входящий HTTP/HTTPS (80/443) для клиентов.
- **Аудит**: Включите логирование доступа к репозиторию.

### Динамические переменные

#### RPM (DNF)

DNF поддерживает подстановку переменных для универсальности конфигураций:

| Переменная | Описание | Источник |
| :--- | :--- | :--- |
| `$releasever` | Мажорная версия дистрибутива | `/etc/os-release` |
| `$basearch` | Базовая архитектура (x86_64, aarch64) | Ядро Linux |
| `$arch` | Конкретная архитектура CPU (i686, x86_64) | `uname -i` |
| `$infra` | Тип инфраструктуры (например, `container`) | Автоопределение |

**Пользовательские переменные:** Любой файл в `/etc/dnf/vars/` создает переменную с именем файла и содержимым этого файла.

#### DEB (APT)

APT поддерживает подстановку через shell-расширение в DEB822 и классическом формате:

| Переменная | Описание | Пример |
| :--- | :--- | :--- |
| `$(lsb_release -cs)` | Кодовое имя дистрибутива | `noble`, `bookworm` |
| `$(dpkg --print-architecture)` | Основная архитектура | `amd64` |
| `$(lsb_release -is)` | Дистрибутив (lowercase) | `ubuntu`, `debian` |

> **Важно:** APT не поддерживает центральную директорию переменных, аналогичную `/etc/dnf/vars/`. Для универсальности используйте скриптовую подстановку или инструменты конфигурационного менеджмента (Ansible, Puppet).

## Практические сценарии

### Управление репозиториями DNF

Подробное руководство по CLI-управлению, GPG-ключам и фильтрации см. в документе **[Операции с репозиториями DNF](./operations.md)**.

Базовые команды для быстрого старта:

```bash
# Добавление репозитория через config-manager (DNF 4)
sudo dnf config-manager --add-repo https://example.com/repo.repo

# Добавление репозитория (DNF 5)
sudo dnf config-manager addrepo --from-repofile=https://example.com/repo.repo

# Список активных репозиториев
dnf repolist

# Детальная информация о репозиториях
dnf repoinfo

# Временное включение репозитория для одной операции
dnf install <package> --enablerepo=<repo_id>

# Перманентное включение/выключение
sudo dnf config-manager --set-enabled <repo_id>
sudo dnf config-manager --set-disabled <repo_id>

# Тонкая настройка приоритета
sudo dnf config-manager --setopt=<repo_id>.priority=10 --save
```

### Управление репозиториями APT

Подробное руководство по настройке источников, DEB822, Pinning и air-gapped средам см. в документе **[Управление репозиториями в Debian и Ubuntu (sources.list)](../deb_repositories_sources_list.md)**.

Базовые команды для быстрого старта:

```bash
# Обновление индексов
sudo apt update

# Просмотр политики источников
apt-cache policy

# Просмотр доступных версий пакета
apt-cache policy <package_name>

# Временное использование стороннего репозитория
sudo apt install <package_name> -t <release>
```

### Создание собственных репозиториев

#### RPM (createrepo_c)

Подробное руководство по созданию RPM-хранилищ, подписи GPG и группам см. в документе **[Создание собственных RPM-репозиториев](./custom_repository.md)**.

Ключевые этапы:
1. Подготовка структуры каталогов (`/var/www/html/repo/x86_64/`)
2. Размещение `.rpm` файлов
3. Генерация индексов: `createrepo_c --general-compress-type zstd --groupfile comps.xml /path/to/repo`
4. Подпись индексов: `gpg --detach-sign --armor repodata/repomd.xml`
5. Настройка клиента через `/etc/yum.repos.d/internal.repo`

#### DEB (reprepro)

Подробное руководство по созданию приватных APT-репозиториев см. в документе **[Приватный Apt-репозиторий с reprepro: Определения и концепции](../deb_private_apt_repository_reprepro/definitions_and_concepts.md)**.

### Air-Gapped среды (изолированные контуры)

В средах без доступа в интернет используйте следующие стратегии:

#### RPM
1. **Подготовка носителя**: На машине с выходом выполните `dnf reposync` с флагами `--download-metadata --downloadcomps --arch=x86_64`.
2. **Перенос**: Скопируйте каталог репозитория на внешний носитель (Sneakernet) или через промежуточный файловый сервер.
3. **Развёртывание**: Разместите в локальной сети, обеспечьте доступ через HTTP/HTTPS.
4. **Клиенты**: Настройте `/etc/yum.repos.d/airgap.repo` с `baseurl=http://local-mirror/...`, отключите все upstream-репозитории (`enabled=0`).

#### DEB
1. **Подготовка носителя**: На машине с выходом выполните `apt-get install --download-only` для необходимых пакетов, либо используйте `snapshot.debian.org` с фиксированной датой.
2. **Перенос**: Упакуйте `/var/cache/apt/archives/` и `/var/lib/apt/lists/` на внешний носитель.
3. **Развёртывание**: Разместите пакеты в структуре `pool/` и сгенерируйте индексы через `apt-ftparchive` или `reprepro`.
4. **Клиенты**: Настройте `sources.list` с указанием локального зеркала.

### Автоматизация и оркестрация

#### Systemd-таймеры для синхронизации

```ini
# /etc/systemd/system/repo-sync.service (RPM)
[Unit]
Description=RPM Repository Synchronization
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
User=nginx
Group=nginx
ExecStartPre=/usr/bin/dnf makecache --timer
ExecStart=/usr/bin/dnf reposync --repoid=baseos --download-path=/var/www/html/repos --newest-only --delete --download-metadata --downloadcomps
ExecStartPost=/usr/bin/createrepo_c --update --general-compress-type zstd /var/www/html/repos/baseos
```

```ini
# /etc/systemd/system/aptly-sync.service (DEB)
[Unit]
Description=Update aptly mirror and publish
After=network-online.target

[Service]
Type=oneshot
User=aptly
ExecStart=/usr/bin/aptly mirror update noble-main
ExecStartPost=/usr/bin/aptly snapshot create noble-snap-latest from mirror noble-main
ExecStartPost=/usr/bin/aptly publish switch noble noble-snap-latest
```

#### Интеграция с CI/CD

Приватные репозитории интегрируются в пайплайны для распространения внутреннего ПО:
1. **Сборка**: Пакет собирается в изолированной среде (`mock` для RPM, `sbuild`/`pbuilder` для DEB).
2. **Валидация**: `rpmlint` / `lintian`, сканирование уязвимостей (Trivy, Grype).
3. **Подпись**: `rpmsign --addsign` / `debsign`.
4. **Публикация**: Копирование в репозиторий + переиндексация + подпись `repomd.xml`/`Release`.
5. **Уведомление**: Отправка webhook в Slack/Telegram о новом релизе.

### Мониторинг и алертинг

Для production-инфраструктуры настройте мониторинг доступности и свежести зеркала.

#### Проверка доступности

```bash
# RPM
curl -s -o /dev/null -w "%{http_code}" http://repo.internal.local/alma9/baseos/repodata/repomd.xml
# → 200

# DEB
curl -s -o /dev/null -w "%{http_code}" http://repo.internal.local/ubuntu/dists/noble/Release
# → 200
```

#### Проверка свежести метаданных

```bash
# RPM
find /var/www/html/repos -name "repomd.xml" -exec stat -c "%Y %n" {} \;

# DEB
stat -c %y /var/www/html/ubuntu/dists/noble/InRelease
```

#### Метрики для Prometheus (node_exporter textfile collector)

```bash
#!/bin/bash
# /usr/local/bin/repo-metrics.sh
RELEASE_FILE_RPM="/var/www/html/repos/alma9/baseos/repodata/repomd.xml"
RELEASE_FILE_DEB="/var/www/html/ubuntu/dists/noble/InRelease"

echo "repo_rpm_last_update_seconds $(( $(date +%s) - $(stat -c %Y "$RELEASE_FILE_RPM") ))" > /var/lib/node_exporter/repo.prom
echo "repo_deb_last_update_seconds $(( $(date +%s) - $(stat -c %Y "$RELEASE_FILE_DEB") ))" >> /var/lib/node_exporter/repo.prom
echo "repo_size_bytes $(du -sb /var/www/html/repos | cut -f1)" >> /var/lib/node_exporter/repo.prom
```

### Типичные проблемы и решения

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Error: Failed to download metadata** (RPM) | Проблемы с сетью или DNS. | Проверьте `baseurl` в `.repo` и доступность зеркала через `curl`. |
| **GPG key retrieval failed** (RPM) | Блокировка порта 80/443 или битая ссылка. | Скачайте ключ вручную и используйте `rpm --import <file>`. |
| **Repo ... has no mirrorlist** (RPM) | Опечатка в конфиге или репозиторий удален. | Проверьте актуальность `mirrorlist` на сайте дистрибутива. |
| **GPG: NO_PUBKEY** (DEB) | Ключ репозитория отсутствует в keyring. | Убедитесь, что ключ добавлен через `gpg --dearmor` и указан в `signed-by`. |
| **404 Not Found** (DEB) | Неправильный URL, дистрибутив или архитектура. | Проверьте `dpkg --print-architecture` и наличие дистрибутива на upstream. |
| **Hash Sum mismatch** (DEB) | Индексы upstream обновились во время скачивания. | Выполните `sudo rm -rf /var/lib/apt/lists/* && sudo apt update`. |
| **Metadata conflict** (RPM) | Несовпадение версий метаданных в кэше. | `sudo dnf clean metadata --repo=<repo_id>` и повторная операция. |
| **Битый кэш** (DEB) | Некорректное завершение `apt update`. | Выполните `sudo apt clean && sudo apt update`. |
| **apt update зависает** (DEB) | Проблема с DNS или недоступность upstream. | Проверьте `curl -I http://deb.debian.org/debian/dists/bookworm/Release`. |
| **dnf repoclosure показывает неудовлетворённые зависимости** (RPM) | Частичное зеркало. | Используйте `--includepkgs` или зеркалируйте все required репозитории. |

### Рекомендации по эксплуатации

1.  **GPG-верификация**: Никогда не отключайте `gpgcheck` и `repo_gpgcheck`. Скопируйте GPG-ключи на сервер зеркала и указывайте путь к ним в `gpgkey` (через HTTP или локально). Подписывайте `repomd.xml` через `gpg --detach-sign --armor`.
2.  **Архитектуры**: Используйте флаг `--arch` (RPM) или опцию `Architectures:` (DEB), чтобы не выкачивать пакеты для неиспользуемых архитектур.
3.  **HTTPS**: Всегда предпочитайте `https://` для защиты от перехвата и инъекций (даже если используется проверка GPG).
4.  **Изоляция стороннего ПО**: При использовании репозиториев с широким составом пакетов (например, EPEL, Universe) используйте параметр `includepkgs` (RPM) или `Components:` (DEB) для ограничения набора устанавливаемого ПО.
5.  **Минимализм (Franken-Debian)**: Избегайте добавления репозиториев от других версий ОС (например, репозитории Ubuntu в Debian). Это нарушает стабильность зависимостей.
6.  **Очистка кэша**: При удалении стороннего ПО не забывайте удалять соответствующие файлы из `/etc/yum.repos.d/` или `/etc/apt/sources.list.d/` и устаревшие ключи.
7.  **Жёсткие ссылки**: При синхронизации нескольких репозиториев используйте общий пул и hardlinks для экономии дискового пространства.
8.  **Воспроизводимость**: Для критичных систем используйте snapshot.debian.org (DEB) или снапшоты зеркал (RPM) с фиксированной датой, чтобы гарантировать одинаковые версии пакетов.

## Сравнение инструментов и подходов

### Создание и обслуживание репозиториев

| Инструмент | Экосистема | Рекомендуемый сценарий |
| :--- | :--- | :--- |
| **createrepo_c** | RPM | Создание и обновление локальных RPM-репозиториев. Поддержка Zstd, Zchunk, модулей. |
| **reprepro** | DEB | Приватные APT-репозитории с фильтрацией, подписью и несколькими дистрибутивами. |
| **aptly** | DEB | Профессиональное управление: снимки, API, объединение репозиториев. |
| **reposync** | RPM | Синхронизация официальных репозиториев в локальное зеркало. |
| **apt-mirror** | DEB | Простая синхронизация «один-в-один» для небольших сетей. |
| **debmirror** | DEB | Сложная фильтрация пакетов по зависимостям и секциям. |

### Зеркалирование vs Приватный репозиторий

| Критерий | Зеркалирование | Приватный репозиторий |
| :--- | :--- | :--- |
| **Источник данных** | Официальные зеркала | Собственное ПО компании |
| **GPG-подпись** | Подпись издателя (Fedora/Debian) | Собственная GPG-подпись |
| **Управление** | Автоматическая синхронизация | Ручное или CI/CD добавление пакетов |
| **Цель** | Доступность и скорость | Распространение внутреннего ПО |

### Кэширующие прокси

| Инструмент | Экосистема | Объём кэша | Сценарий |
| :--- | :--- | :--- | :--- |
| **apt-cacher-ng** | DEB | Несколько ГБ | Средние сети (<50 серверов), есть выход в интернет |
| **Squid + custom** | RPM/DEB | Зависит от конфигурации | Крупные сети с тонкой настройкой правил кэширования |

## Дополнительная информация

### Особенности DNF 5

DNF 5 вносит значительные изменения в работу с репозиториями:
- **Ускорение загрузки метаданных:** За счет использования `libdnf5` на C++.
- **Delta RPM (DRPM):** Поддержка удалена, так как современные каналы связи делают этот механизм избыточным.
- **Синтаксис:** Команды стали более структурированными (например, `config-manager addrepo` вместо `--add-repo`).

### Рекомендации по безопасности

1.  **Изоляция стороннего ПО:** При использовании репозиториев с широким составом пакетов (например, EPEL) используйте параметр `includepkgs` в `.repo`, чтобы разрешить установку только нужных вам программ.
2.  **Проверка метаданных:** Всегда включайте `repo_gpgcheck=1` для собственных и критически важных репозиториев, чтобы защититься от подмены индексов.
3.  **Сетевая изоляция:** Размещайте зеркала в отдельном VLAN. Используйте mTLS для критичных контуров.
