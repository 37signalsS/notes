# Операции с репозиториями DNF

## Определения

Основные понятия, структура `.repo` файлов и типы системных репозиториев описаны в главном разделе **[Управление репозиториями](./index.md)**.

Ниже приведены термины, специфичные для выполнения операций:

**EPEL (Extra Packages for Enterprise Linux)** — репозиторий от сообщества Fedora, содержащий пакеты высокого качества, совместимые с RHEL-based системами. Часто является первым сторонним репозиторием, подключаемым в новой системе.

**COPR (Cool Other Package Repo)** — облачный сервис и инструмент для создания персональных репозиториев в экосистеме Fedora/RHEL. Позволяет пользователям собирать и распространять пакеты без прохождения длительного процесса включения в официальные ветки дистрибутива.

**Ключи GPG (GNU Privacy Guard)** — публичные криптографические ключи, используемые пакетным менеджером для подтверждения того, что метаданные и пакеты в репозитории не были подделаны и получены от доверенного владельца.

## Основные концепции

### Категории административных действий

Для эффективного управления программным окружением выделяют следующие группы операций:

| Категория | Описание | Основные инструменты |
| :--- | :--- | :--- |
| **Инвентаризация** | Получение списка источников, их статуса и детальных характеристик. | `dnf repolist`, `dnf repo info` |
| **Конфигурация** | Добавление, удаление, включение/выключение и изменение параметров репозиториев. | `dnf config-manager`, `dnf copr` |
| **Управление доверием** | Импорт GPG-ключей и настройка параметров проверки подписей. | `rpm --import`, `dnf config-manager --setopt` |
| **Диагностика** | Анализ доступности зеркал, проверка актуальности кэша и разрешение конфликтов. | `dnf makecache`, `dnf clean` |

### Методология управления источниками

1. **Декларативный подход**: Создание статичных `.repo` файлов в `/etc/yum.repos.d/`. Рекомендуется для автоматизации (Ansible, Terraform).
2. **Императивный подход**: Использование CLI-команд (`dnf config-manager`). Рекомендуется для быстрой настройки и внесения точечных изменений без прямого редактирования файлов.
3. **Пакетный подход**: Установка пакетов вида `*-release.rpm`. Рекомендуется для крупных сторонних проектов (Docker, PostgreSQL), так как пакет содержит и конфигурацию, и GPG-ключи.

## Практические сценарии

### Сценарий 1: Инвентаризация и фильтрация

Команды для получения информации о текущих источниках ПО.

```bash
# Список активных (enabled) репозиториев
dnf repolist

# Список всех настроенных репозиториев с их статусом
dnf repolist all

# Список репозиториев с подробной информацией (ID, имя, URL, GPG-статус)
dnf repo info

# Просмотр параметров конкретного репозитория
dnf repo info <repo_id>

# Фильтрация по статусу (только для DNF4)
dnf repolist --disabled
```

### Сценарий 2: Управление статусом и параметрами

Использование плагина `config-manager` для модификации существующих конфигураций.

```bash
# Включение репозитория
sudo dnf config-manager --set-enabled <repo_id>

# Временное включение репозитория для одной команды (без изменения конфига)
dnf upgrade --enablerepo=<repo_id>

# Изменение приоритета репозитория (требуется плагин priorities)
sudo dnf config-manager --setopt=<repo_id>.priority=10 --save

# Просмотр всех текущих настроек всех репозиториев (dump конфигурации)
dnf config-manager --dump
```

### Сценарий 3: Добавление новых источников

#### Использование config-manager

```bash
# Добавление репозитория по URL файла .repo
sudo dnf config-manager --add-repo https://example.com/project.repo

# Добавление репозитория по базовому URL (создает шаблонный конфиг)
sudo dnf config-manager --add-repo http://repo.internal.net/os/
```

#### Работа с COPR

```bash
# Поиск проекта в COPR
dnf copr search <query>

# Включение COPR-репозитория
sudo dnf copr enable <user/project>

# Выключение COPR-репозитория
sudo dnf copr disable <user/project>
```

#### Ручное создание конфигурации

Применяется, когда требуется задать специфичные переменные или пути.

```bash
sudo tee /etc/yum.repos.d/custom.repo << 'EOF'
[custom-repo]
name=Internal Custom Repo
baseurl=http://repo.corp.local/$basearch/
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-corp
EOF
```

### Сценарий 4: Управление GPG-ключами и безопасностью

```bash
# Импорт публичного ключа в базу данных RPM
sudo rpm --import https://keys.example.com/RPM-GPG-KEY-project

# Список всех импортированных ключей в системе
rpm -qa gpg-pubkey*

# Проверка подписи конкретного RPM-файла перед установкой
rpm -K package.rpm
```

### Сценарий 5: Работа с версиями и кэшем

```bash
# Принудительное перестроение кэша метаданных (после добавления репозитория)
sudo dnf makecache

# Очистка только метаданных репозиториев
sudo dnf clean metadata

# Запуск команд для другой версии дистрибутива (например, при подготовке зеркала)
dnf repolist --releasever=9
```

## Дополнительная информация

### Особенности DNF 5 (Fedora 41+, RHEL 10)

DNF 5 вносит изменения в синтаксис некоторых операций для обеспечения большей строгости и производительности:

| Операция | Команда DNF 4 | Команда DNF 5 |
| :--- | :--- | :--- |
| **Добавление репозитория** | `config-manager --add-repo <url>` | `config-manager addrepo <url>` |
| **Список репозиториев** | `repolist` | `repo list` (repolist — алиас) |
| **Информация** | `repoinfo` | `repo info` |
| **Путь к кэшу** | `/var/cache/dnf` | `/var/cache/libdnf5` |

### Диагностика типовых ошибок

| Ошибка | Причина и решение |
| :--- | :--- |
| **GPG check failed** | Ключ не импортирован или поврежден. Используйте `rpm --import`. |
| **Cannot retrieve metalink** | Сетевая недоступность или ошибка DNS. Проверьте `ping` до зеркала. |
| **Module hotfixes needed** | Пакет из стороннего репозитория скрыт модулем AppStream. Добавьте `module_hotfixes=true` в `.repo`. |
| **Variable $releasever not set** | Ошибка автоопределения версии. Укажите явно: `--releasever=X`. |

### Рекомендации по безопасности

1. **HTTPS везде**: Всегда используйте `https://` для `baseurl` и `gpgkey` во избежание MITM-атак.
2. **Изоляция конфигураций**: Не храните несколько репозиториев в одном `.repo` файле, если они относятся к разным проектам.
3. **Минимализм**: Отключайте (`enabled=0`) сторонние репозитории после установки нужного ПО, если не требуется автоматическое обновление.
