# Операции с репозиториями DNF

## Определения

Ниже приведены основные термины, описывающие процессы взаимодействия с хранилищами пакетов в дистрибутивах на базе RPM (Red Hat Package Manager).

**Операции с репозиториями** — совокупность действий по просмотру текущего состояния, добавлению новых или удалению существующих источников программного обеспечения, а также управлению механизмами доверия через цифровые подписи.

**DNF (Dandified YUM)** — современный пакетный менеджер, обеспечивающий установку, обновление и удаление программного обеспечения с автоматическим разрешением зависимостей.

**GPG (GNU Privacy Guard)** — программная реализация стандарта OpenPGP, используемая для создания цифровых подписей пакетов и метаданных репозиториев для обеспечения их подлинности.

**EPEL (Extra Packages for Enterprise Linux)** — проект репозитория, предоставляющий дополнительные пакеты высокого качества для дистрибутивов корпоративного уровня (RHEL, AlmaLinux, Rocky Linux).

---

## Основные концепции

### Категории административных действий

Для эффективного управления программным окружением выделяют следующие типы операций:

| Категория | Описание | Основные инструменты |
| :--- | :--- | :--- |
| **Просмотр** | Получение информации о доступных и активных источниках | `dnf repolist`, `dnf repoinfo` |
| **Управление** | Изменение статуса (включение/выключение) или создание новых конфигураций | `dnf config-manager` |
| **Ключи GPG** | Импорт публичных ключей доверенных издателей в базу данных | `rpm --import` |
| **Валидация** | Проверка целостности и подлинности файлов пакетов | `rpm --checksig`, `rpm -V` |

### Методология добавления источников

Выбор метода зависит от типа репозитория и требуемого уровня кастомизации:

1. **Использование `config-manager`**: рекомендуется для официальных репозиториев, предоставляющих готовый файл конфигурации по сетевому адресу (URL — Uniform Resource Locator).
2. **Ручное создание `.repo` файла**: применяется для внутренних или кастомных репозиториев, где требуется тонкая настройка параметров (например, приоритетов или исключений).
3. **Установка пакета `release`**: наиболее удобный способ для популярных репозиториев (EPEL, RPM Fusion), так как автоматически устанавливает не только конфигурацию, но и необходимые GPG-ключи.

## Практические сценарии

### Сценарий 1: Инвентаризация и изменение статуса

```bash
# Вывод списка только активных репозиториев
dnf repolist

# Вывод всех настроенных репозиториев с указанием их статуса
dnf repolist all

# Получение детальной информации о конкретном источнике (ID — Identifier)
dnf repoinfo <repo_id>

# Просмотр итоговой конфигурации всех источников
dnf config-manager --dump

# Включение ранее добавленного репозитория
sudo dnf config-manager --set-enabled <repo_id>

# Отключение репозитория без удаления конфигурационного файла
sudo dnf config-manager --set-disabled <repo_id>
```

---

### Сценарий 2: Подключение новых репозиториев

#### Использование встроенного менеджера конфигураций

```bash
# Добавление репозитория по прямой ссылке на .repo файл
sudo dnf config-manager --add-repo https://example.com/repo.repo

# Добавление с последующей настройкой параметров (например, включение проверки подписей)
sudo dnf config-manager --add-repo http://example.com/repo
sudo dnf config-manager --save --setopt=<repo_id>.gpgcheck=1
```

#### Создание конфигурации вручную

```bash
# Создание файла в директории /etc/yum.repos.d/
sudo tee /etc/yum.repos.d/example.repo << 'EOF'
[example]
name=Example Repository
baseurl=https://repo.example.com/centos/$releasever/os/$basearch/
gpgcheck=1
gpgkey=https://repo.example.com/RPM-GPG-KEY-example
enabled=1
EOF

# Обновление кэша метаданных для применения изменений
sudo dnf makecache
```

#### Установка через специализированные пакеты

```bash
# Подключение репозитория EPEL
sudo dnf install epel-release

# Подключение Docker-репозитория
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
```

### Сценарий 3: Управление цифровыми подписями GPG

Публичные ключи импортируются в системную базу данных RPM и получают идентификатор с префиксом `gpg-pubkey-`.

```bash
# Импорт ключа из локального файла
sudo rpm --import /path/to/gpg-key.pub

# Прямой импорт ключа по сетевому адресу (HTTPS — Hypertext Transfer Protocol Secure)
sudo rpm --import https://example.com/gpg-key.pub

# Вывод списка всех доверенных ключей в системе
rpm -qa gpg-pubkey*

# Просмотр подробной информации о конкретном ключе
rpm -qi gpg-pubkey-<key_id>

# Удаление ключа из списка доверенных
sudo rpm -e gpg-pubkey-<key_id>
```

### Сценарий 4: Контроль подлинности пакетов

```bash
# Проверка подписи уже установленного программного обеспечения
rpm -V <package_name>

# Валидация подписи конкретного файла пакета перед установкой
rpm -K <package_name.rpm>
```

**Интерпретация результатов проверки (`rpm -K`):**

| Результат | Значение |
| :--- | :--- |
| `digests signatures OK` | Подпись верна, файл не изменен. |
| `NOT FOUND` | В системе отсутствует публичный ключ для проверки. |
| `NOT OK` | Ошибка валидации — файл поврежден или подделан. |

## Дополнительная информация

### Диагностика типовых неисправностей

| Проблема | Возможная причина и решение |
| :--- | :--- |
| **GPG check failed** | Отсутствует ключ. Решение: импортировать через `sudo rpm --import <key_url>`. |
| **Cannot retrieve metalink** | Проблемы с сетевым соединением или DNS (Domain Name System). Проверить доступность URL. |
| **Repository not found** | Ошибка в параметре `baseurl` или временная недоступность сервера. |
| **404 Not Found** | Версия в переменной `$releasever` не поддерживается данным зеркалом. |

### Рекомендации по обеспечению безопасности

1. **Обязательная проверка**: всегда устанавливайте `gpgcheck=1` для всех внешних источников.
2. **Доверие ключам**: импортируйте GPG-ключи только по защищенным каналам (HTTPS) и из официальных источников.
3. **Минимизация рисков**: используйте HTTPS для `baseurl` во избежание атак типа "человек посередине" (MITM — Man-in-the-Middle).
4. **Актуализация данных**: регулярно выполняйте `dnf makecache` для получения свежих метаданных и информации о безопасности.
