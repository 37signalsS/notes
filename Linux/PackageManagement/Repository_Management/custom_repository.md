# Создание собственных RPM-репозиториев

## Определения

Ниже приведены основные термины, используемые при организации внутреннего хранилища программного обеспечения в дистрибутивах на базе RPM (Red Hat Package Manager).

**Собственный репозиторий** — локальный или сетевой каталог, содержащий специально подготовленные пакеты формата RPM и файлы метаданных, предназначенный для распространения программного обеспечения внутри организации или проекта.

**Метаданные репозитория** — набор файлов в формате XML (eXtensible Markup Language), расположенных в директории `repodata/`, которые описывают зависимости, контрольные суммы и списки файлов всех пакетов в репозитории.

**GPG-подпись репозитория** — результат применения криптографических алгоритмов GPG (GNU Privacy Guard) к пакетам и метаданным для подтверждения их подлинности и неизменности.

---

## Основные концепции

### Отличие от зеркалирования

Необходимо различать процесс создания уникального репозитория и зеркалирования существующего внешнего источника.

| Характеристика | Зеркалирование | Создание собственного репозитория |
| :--- | :--- | :--- |
| **Цель** | Локальная копия внешнего источника | Распространение собственного ПО |
| **Источник данных** | Удаленный upstream-репозиторий | Собранные вручную .rpm пакеты |
| **Ключевые утилиты** | `reposync`, `createrepo_c` | `createrepo_c`, `rpmsign` |
| **Источник информации** | **[Зеркалирование YUM/DNF](../../yum_dnf_repository_mirror.md)** | Данный документ |

### Структура каталогов

Типовая иерархия файлов в репозитории выглядит следующим образом:

```text
my-repo/
├── packages/           # Файлы пакетов .rpm
│   ├── app-1.0-1.el9.x86_64.rpm
│   ├── lib-2.3-1.el9.x86_64.rpm
│   └── repodata/       # Метаданные (создаются через createrepo_c)
│       ├── repomd.xml
│       ├── *-primary.xml.gz
│       └── *-filelists.xml.gz
├── RPM-GPG-KEY-myrepo  # Публичный ключ для проверки подписи
└── docs/               # Сопутствующая документация
```

### Используемый инструментарий

| Инструмент | Назначение |
| :--- | :--- |
| `createrepo_c` | Генерация и обновление метаданных в формате XML. |
| `rpm --addsign` | Внедрение цифровой подписи в заголовки RPM-пакетов. |
| `signrepo` | Создание цифровой подписи для файлов метаданных. |
| `gpg` | Генерация ключевых пар по алгоритму RSA (Rivest-Shamir-Adleman). |

## Практические сценарии

### Сценарий 1: Инициализация репозитория и публикация

#### 1. Подготовка структуры

```bash
mkdir -p ~/my-repo/packages
cp *.rpm ~/my-repo/packages/
```

#### 2. Генерация метаданных

```bash
cd ~/my-repo/packages

# Первичная инициализация
createrepo_c .

# Обновление метаданных при добавлении новых пакетов
createrepo_c --update .

# Полная переиндексация с удалением старых записей
createrepo_c --cleanup --update .
```

#### 3. Настройка доступа через HTTP

Для публикации используется протокол HTTP (Hypertext Transfer Protocol), обычно через веб-сервер Apache или Nginx.

```bash
# Размещение данных в корневой директории веб-сервера
sudo cp -r ~/my-repo/packages /var/www/html/my-repo

# Настройка SELinux (Security-Enhanced Linux), если механизм активен
sudo semanage fcontext -a -t httpd_sys_content_t "/var/www/html/my-repo(/.*)?"
sudo restorecon -Rv /var/www/html/my-repo

# Запуск службы веб-сервера (Apache)
sudo systemctl enable --now httpd
```

#### 4. Конфигурация клиента

Создайте файл `/etc/yum.repos.d/my-repo.repo` на целевых машинах:

```ini
[my-custom-repo]
name=My Custom Repository
baseurl=http://repo-server.local/my-repo/
gpgcheck=1
gpgkey=http://repo-server.local/my-repo/RPM-GPG-KEY-myrepo
enabled=1
```

### Сценарий 2: Обеспечение безопасности через GPG-подписи

#### 1. Создание ключа RSA

```bash
gpg --full-generate-key
# Рекомендуется: RSA (4096 бит), срок действия — по необходимости.
```

#### 2. Экспорт публичной части

```bash
gpg --export -a "Maintainer Name <email@example.com>" > ~/my-repo/RPM-GPG-KEY-myrepo
```

#### 3. Подпись отдельных пакетов

Для автоматизации настройте файл `~/.rpmmacros`:

```text
%_gpg_name Maintainer Name <email@example.com>
```

```bash
# Выполнение подписи
cd ~/my-repo/packages
for pkg in *.rpm; do
    rpm --addsign "$pkg"
done

# Проверка результата
rpm -K app-1.0-1.el9.x86_64.rpm
```

### Сценарий 3: Автоматизация регламентных работ

Использование планировщика задач `cron` (командный интерпретатор для запуска задач по времени) позволяет поддерживать актуальность индексов.

```bash
# Пример скрипта /etc/cron.daily/repo-update
#!/bin/bash
REPO_DIR="/var/www/html/my-repo"
LOG_FILE="/var/log/repo-update.log"

echo "[$(date)] Начало обновления репозитория" >> "$LOG_FILE"
createrepo_c --update "$REPO_DIR" >> "$LOG_FILE" 2>&1

if [ $? -eq 0 ]; then
    echo "Успешно завершено" >> "$LOG_FILE"
else
    echo "Ошибка обновления" >> "$LOG_FILE"
fi
```
