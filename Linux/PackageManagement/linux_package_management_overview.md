# Обзор управления пакетами в Linux: RPM и DEB

## Определения

В Linux существуют две основные экосистемы управления пакетами: **RPM** (Red Hat Linux) и **DEB** (Debian). Каждая экосистема включает ключевые компоненты:

*   **Пакет**: Архив, содержащий файлы программы и метаданные (версия, зависимости, контрольные суммы).
*   **Низкоуровневая утилита**: Инструмент для работы с отдельными файлами пакетов (`rpm` для RPM, `dpkg` для DEB). Устанавливает, удаляет, запрашивает информацию, но не разрешает зависимости.
*   **Высокоуровневая утилита**: Надстройка над низкоуровневыми утилитами (`dnf`/`yum` для RPM, `apt`/`apt-get`/`aptitude` для DEB). Работает с репозиториями, автоматически разрешает зависимости и управляет обновлениями.
*   **Репозиторий**: Сервер, хранящий коллекцию пакетов и их метаданных. Конфигурация репозиториев в Debian-системах подробно описана в [управлении репозиториями и файле sources.list](./deb_repositories_sources_list.md).

Знание низкоуровневых инструментов критически важно для работы в ограниченных окружениях (Docker, initrd) или для ручной сборки/распаковки пакетов.

| Характеристика              | RPM (Red Hat Package Manager) | DEB (Debian)                    |
| :-------------------------- | :---------------------------- | :------------------------------ |
| **Дистрибутивы**            | Fedora, CentOS, RHEL, openSUSE | Debian, Ubuntu, Mint            |
| **Файлы пакетов**           | `.rpm`                        | `.deb`                          |
| **Низкоуровневая утилита**  | `rpm`                         | `dpkg`                          |
| **Высокоуровневая утилита** | `dnf` (современный), `yum` (устаревший) | `apt`, `apt-get`, `aptitude`    |

## Основные понятия

### Принцип работы высокоуровневых пакетных менеджеров

Высокоуровневый менеджер пакетов (`dnf`, `apt`) — интеллектуальная надстройка над низкоуровневым (`rpm`, `dpkg`). Процесс установки:

1.  **Анализ зависимостей:** Определяет все необходимые пакеты для корректной работы.
2.  **Поиск в репозиториях:** Ищет пакеты и их зависимости в настроенных репозиториях. Возможно управление приоритетами версий через [Apt Pinning](./deb_apt_pinning.md) или использование [приватных репозиториев](./deb_private_apt_repository_reprepro.md).
3.  **Составление транзакции:** Формирует план установки.
4.  **Подтверждение:** Пользователь подтверждает операцию после ознакомления со списком пакетов, объемом загружаемых данных и необходимым дисковым пространством.
5.  **Загрузка и установка:** Загружает файлы пакетов (`.rpm` или `.deb`) и передает их низкоуровневой утилите для непосредственной установки файлов.

## Практические сценарии

### Получение файлов пакетов

Получение файла пакета без немедленной установки (например, для анализа или переноса).

#### DEB-based системы
*   **Скачать пакет:** `apt-get download <package_name>`
*   **Скачать пакет со всеми зависимостями (в кэш `/var/cache/apt/archives/`):** `apt-get install --download-only <package_name>`
*   **Поиск пакета по содержимому файла (утилита `apt-file`):**
    ```bash
    sudo apt-get update && sudo apt-get install apt-file && apt-file update
    apt-file search <file_path_or_name>
    ```
*   **Поиск пакета, которому принадлежит файл (`dpkg`):** `dpkg -S <file_path>`

#### RPM-based системы
*   **Скачать пакет:** `dnf download <package_name>`
*   **Скачать пакет со всеми зависимостями:** `dnf install --downloadonly <package_name>`
*   **Поиск пакета по содержимому файла:** `dnf provides '*/<file_name>'`

#### Поиск пакетов в веб-интерфейсе
*   **Debian:** [packages.debian.org](https://packages.debian.org/)
*   **Fedora/CentOS/RHEL:** [packages.fedoraproject.org](https://packages.fedoraproject.org/)

### Установка и удаление пакетов с помощью низкоуровневых утилит

`dpkg` и `rpm` не разрешают зависимости автоматически. Используются для ручной установки или при устранении проблем.

#### DEB-based системы (`dpkg`)
*   **Установка пакета из `.deb` файла:** `sudo dpkg -i <package_name.deb>` (`sudo apt-get install -f` для разрешения зависимостей).
*   **Удаление пакета (сохраняя конфиги):** `sudo dpkg -r <package_name>`
*   **Полное удаление пакета (с конфигами):** `sudo dpkg -P <package_name>`

#### RPM-based системы (`rpm`)
*   **Установка пакета из `.rpm` файла:** `sudo rpm -i <package_name.rpm>`
*   **Удаление пакета:** `sudo rpm -e <package_name>`

### Анализ файлов пакетов

Просмотр метаданных и содержимого пакетов без их установки.

#### DEB-based системы (`.deb`)
Структура `.deb` пакета включает: конфигурационные файлы, управляющую информацию (метаданные), контрольные суммы, постустановочные/предудаляющие/постудаляющие скрипты.
*   **Метаданные из файла пакета:** `dpkg --info <package_name.deb>`
*   **Содержимое файла пакета:** `dpkg --contents <package_name.deb>`
*   **Метаданные установленного пакета:** `dpkg -s <package_name>`
*   **Список файлов установленного пакета:** `dpkg -L <package_name>`

#### RPM-based системы (`.rpm`)
*   **Метаданные из файла пакета:** `rpm -qip <package_name.rpm>`
*   **Содержимое файла пакета:** `rpm -qlp <package_name.rpm>`
*   **Метаданные установленного пакета:** `rpm -qi <package_name>`
*   **Список файлов установленного пакета:** `rpm -ql <package_name>`

### Извлечение содержимого пакетов

Как получить файлы из пакета, не устанавливая его.

#### DEB-based системы
Пакет `.deb` — это архив `ar`, содержащий `control.tar.gz` (метаданные) и `data.tar.gz` (файлы).
*   **Распаковать с `dpkg-deb`:** `dpkg-deb --extract <package_name.deb> <output_dir>`
*   **Распаковать вручную с `ar`:** `ar x <package_name.deb>` (создаст `control.tar.gz`, `data.tar.gz`, `debian-binary`).

#### RPM-based системы
RPM-пакет содержит бинарный заголовок и `cpio` архив с содержимым.
*   **Распаковать с `rpm2cpio` и `cpio`:** `rpm2cpio <package_name.rpm> | cpio -idmv`

### Сборка пакетов

Процесс создания собственных пакетов `.deb` или `.rpm`.

#### DEB-based системы
*   **Получение исходников:** `apt-get source <package_name>` (требует раскомментированных `deb-src` репозиториев в `/etc/apt/sources.list`).
*   **Структура для сборки:** `debian/` директория содержит `control` (метаданные, зависимости), `rules` (сценарий сборки), `changelog` (история изменений, версия пакета).
*   **Изменение версии пакета:** Утилита `dch` (`debchange`).
*   **Процесс сборки:**
    ```bash
    sudo apt-get build-dep .
    cd <package_name-version>/
    dpkg-buildpackage -us -uc
    ```

#### RPM-based системы
*   **Получение исходников:** `dnf download --source <package_name>` (Source RPM пакеты `.src.rpm`).
*   **Структура для сборки:** `~/rpmbuild` (создается `rpmdev-setuptree`) содержит `SPECS`, `SOURCES`, `BUILD`, `RPMS`, `SRPMS`.
*   **Процесс сборки:**
    1.  **Установка Source RPM:** `rpm -i <package_name.src.rpm>`
    2.  **Установка зависимостей:** `dnf builddep ~/rpmbuild/SPECS/<package_name.spec>`
    3.  **Сборка:** `rpmbuild -ba ~/rpmbuild/SPECS/<package_name.spec>` (создаст `.rpm` и `.src.rpm` в `~/rpmbuild/RPMS/` и `~/rpmbuild/SRPMS/`).

## Дополнительная информация

### База данных установленных пакетов и устранение проблем

Каждая пакетная система ведет базу данных установленных пакетов.

#### DPKG
*   **Расположение:** `/var/lib/dpkg/`
*   **Статус пакетов:** `/var/lib/dpkg/status`
*   **Информация о файлах:** `/var/lib/dpkg/info/<package_name>.list`
*   **Файл блокировки:** `/var/lib/dpkg/lock` (предотвращает одновременный запуск `dpkg`/`apt`).

#### RPM
*   **Расположение:** `/var/lib/rpm/`
*   **Формат:** SQLite (`/var/lib/rpm/rpmdb.sqlite`) в современных системах.
*   **Восстановление базы:** `rpm --rebuilddb`
*   **Взаимодействие:** Только через `rpm` или высокоуровневые менеджеры.
