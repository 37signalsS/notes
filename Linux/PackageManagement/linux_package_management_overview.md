# Обзор управления пакетами в Linux: RPM и DEB

## Определения

В Linux существуют две основные экосистемы управления пакетами: **RPM**, изначально созданная для Red Hat Linux, и **DEB**, созданная для Debian. Каждая экосистема включает ключевые компоненты:

*   **Пакет**: Архив, содержащий файлы программы и метаданные (версия, зависимости, контрольные суммы).
*   **Низкоуровневая утилита** (`rpm`, `dpkg`): Инструмент для работы с отдельными файлами пакетов. Она может устанавливать, удалять, запрашивать информацию о пакетах, но не умеет автоматически разрешать зависимости.
*   **Высокоуровневая утилита** (`dnf`, `apt`): Надстройка над низкоуровневыми утилитами. Работает с репозиториями, автоматически находя, разрешая и устанавливая зависимости, а также управляя обновлениями.
*   **Репозиторий**: Сервер, хранящий коллекцию пакетов и их метаданных. Конфигурация репозиториев в Debian-системах подробно описана в заметке об [управлении репозиториями и файле sources.list](./deb_repositories_sources_list.md).

Знание низкоуровневых инструментов остается критически важным для работы в ограниченных окружениях (Docker, initrd) или для ручной сборки/распаковки пакетов, несмотря на то что современные высокоуровневые утилиты решают большинство повседневных задач.

| Характеристика              | RPM (Red Hat Package Manager) | DEB (Debian)                    |
| :-------------------------- | :---------------------------- | :------------------------------ |
| **Дистрибутивы**            | Fedora, CentOS, RHEL, openSUSE | Debian, Ubuntu, Mint            |
| **Файлы пакетов**           | `.rpm`                        | `.deb`                          |
| **Низкоуровневая утилита**  | `rpm`                         | `dpkg`                          |
| **Высокоуровневая утилита** | `dnf` (современный), `yum` (устаревший) | `apt`, `apt-get`, `aptitude`    |

## Основные понятия

### Принцип работы высокоуровневых менеджеров

Высокоуровневый менеджер пакетов (например, `dnf` или `apt`) выступает в роли интеллектуальной надстройки над низкоуровневым (`rpm` или `dpkg`). При выполнении команды `install` происходит следующий процесс:

1.  **Анализ зависимостей:** Менеджер анализирует метаданные запрашиваемого пакета, чтобы определить список всех других пакетов, необходимых для его корректной работы (зависимостей).
2.  **Поиск в репозиториях:** Он ищет необходимые пакеты и их зависимости в настроенных репозиториях. При этом возможно гибкое управление приоритетами версий с помощью механизма [Apt Pinning](./deb_apt_pinning.md) или создание [собственных приватных репозиториев](./deb_private_apt_repository_reprepro.md).
3.  **Составление транзакции:** Формируется полный план установки, включающий основной пакет и все его зависимости.
4.  **Подтверждение:** Пользователю выводится список всех пакетов, которые будут установлены, а также информация об общем объеме загружаемых данных и необходимом дисковом пространстве. Пользователь должен подтвердить операцию.
5.  **Загрузка и установка:** После подтверждения менеджер загружает файлы пакетов (`.rpm` или `.deb`) и передает их низкоуровневой утилите (`rpm` или `dpkg`) для непосредственной установки файлов в файловую систему.

## Практические сценарии

### Получение файлов пакетов

Иногда требуется скачать пакет в виде файла без его немедленной установки, например, для анализа или переноса на другую машину.

#### DEB-based системы

*   **Скачать пакет в текущую директорию:**
    ```bash
    apt-get download <package_name>
    ```
*   **Скачать пакет со всеми зависимостями (в кэш):** Пакеты кешируются в `/var/cache/apt/archives/`.
    ```bash
    apt-get install --download-only <package_name>
    ```
*   **Поиск пакета по содержимому файла:** Используется утилита `apt-file`.
    ```bash
    # Установка и обновление кэша утилиты
    sudo apt-get update
    sudo apt-get install apt-file
    apt-file update

    # Поиск пакета, содержащего указанный файл
    apt-file search <file_path_or_name>

    # Поиск пакета, которому принадлежит файл (dpkg):
    ```bash
    # Поиск пакета, которому принадлежит файл
    dpkg -S <file_path>
    # Пример:
    # dpkg -S /bin/ls
    # coreutils: /bin/ls
    ```

*   **Установка и удаление пакетов с помощью `dpkg`:**
    `dpkg` — это низкоуровневая утилита, которая работает напрямую с `.deb` файлами и **не умеет автоматически разрешать зависимости**. Она используется в основном для ручной установки пакетов или при устранении проблем.

    *   **Установка пакета из `.deb` файла:**
        ```bash
        sudo dpkg -i <package_name.deb>
        # или
        sudo dpkg --install <package_name.deb>
        ```
        Если у пакета есть неразрешенные зависимости, `dpkg` сообщит об ошибке. Их можно попытаться разрешить с помощью `sudo apt-get install -f`.

    *   **Удаление пакета, оставляя конфигурационные файлы:**
        ```bash
        sudo dpkg -r <package_name>
        # или
        sudo dpkg --remove <package_name>
        ```
        В этом случае сам пакет будет удален, но его конфигурационные файлы останутся в системе (например, в `/etc`), что может быть полезно для последующей переустановки с сохранением настроек.

    *   **Полное удаление пакета, включая конфигурационные файлы:**
        ```bash
        sudo dpkg -P <package_name>
        # или
        sudo dpkg --purge <package_name>
        ```
        Это полностью очищает систему от пакета и всех его настроек.

#### RPM-based системы

*   **Скачать пакет:**
    ```bash
    dnf download <package_name>
    ```
*   **Скачать пакет со всеми зависимостями:**
    ```bash
    dnf install --downloadonly <package_name>
    ```
*   **Поиск пакета по содержимому файла:**
    ```bash
    dnf provides '*/<file_name>'
    ```

#### Поиск пакетов в веб-интерфейсе

Для поиска пакетов для других архитектур или версий дистрибутивов удобно использовать официальные веб-порталы:

*   **Debian:** [packages.debian.org](https://packages.debian.org/) - Позволяет искать пакеты по имени, просматривать их содержимое и зависимости, а также скачивать `.deb` файлы для любой архитектуры (`amd64`, `arm64` и т.д.) и любого выпуска (Stable, Testing, Unstable).
*   **Fedora/CentOS/RHEL:** [packages.fedoraproject.org](https://packages.fedoraproject.org/) - Аналогичный портал для RPM-экосистемы. Позволяет находить пакеты и скачивать их для нужной версии дистрибутива и архитектуры.

### Анализ файлов пакетов

Инструменты для просмотра метаданных и содержимого пакетов без их установки.

#### DEB-based системы (`.deb`)

Структура `.deb` пакета, помимо непосредственно программного обеспечения, включает:
*   **Конфигурационные файлы:** Файлы настроек, которые могут быть изменены пользователем.
*   **Управляющая информация:** Метаданные пакета (зависимости, версия, описание).
*   **Контрольные суммы:** Проверочные суммы всех файлов внутри пакета для обеспечения целостности.
*   **Постустановочные скрипты:** Выполняются после установки пакета (например, создание ярлыков, настройка служб).
*   **Предудаляющие скрипты:** Выполняются перед удалением пакета.
*   **Постудаляющие скрипты:** Выполняются после удаления пакета (например, очистка остаточных файлов).

`dpkg` использует разные опции для анализа `.deb` файлов и для запроса информации об уже установленных в системе пакетах.

*   **Анализ `.deb` файла:**
    ```bash
    # Посмотреть метаданные из файла пакета
    dpkg --info <package_name.deb>

    # Посмотреть содержимое файла пакета (список файлов)
    dpkg --contents <package_name.deb>
    ```
*   **Запрос информации об установленном пакете:**
    ```bash
    # Посмотреть метаданные установленного пакета
    dpkg -s <package_name>

    # Посмотреть список файлов, принадлежащих установленному пакету
    dpkg -L <package_name>
    ```

#### RPM-based системы (`.rpm`)

`rpm` использует одинаковые опции для запроса информации, но с флагом `-p` (package) для файлов пакетов.

*   **Анализ `.rpm` файла:**
    ```bash
    # Посмотреть метаданные из файла пакета
    rpm -qip <package_name.rpm>
    ```
    *   `-q` (query) - запрос информации
    *   `-i` (info) - метаданные
    *   `-p` (package) - указание на файл пакета
    ```bash
    # Посмотреть содержимое файла пакета (список файлов)
    rpm -qlp <package_name.rpm>
    ```
    *   `-l` (list) - список файлов
*   **Запрос информации об установленном пакете:**
    ```bash
    # Посмотреть метаданные установленного пакета
    rpm -qi <package_name>

    # Посмотреть список файлов, принадлежащих установленному пакету
    rpm -ql <package_name>
    ```

### Извлечение содержимого пакетов

Как получить файлы из пакета, не устанавливая его.

#### DEB-based системы

Пакет `.deb` — это архив `ar`, содержащий два архива: `control.tar.gz` (метаданные) и `data.tar.gz` (файлы).

*   **Распаковать с помощью `dpkg-deb`:**
    ```bash
    # Создаст директорию <output_dir> с содержимым пакета
    dpkg-deb --extract <package_name.deb> <output_dir>
    ```
*   **Распаковать вручную с помощью `ar`:**
    ```bash
    ar x <package_name.deb>
    # В результате появятся файлы control.tar.gz, data.tar.gz и debian-binary
    ```

#### RPM-based системы

RPM-пакет имеет бинарный заголовок и payload (содержимое) в формате `cpio`.

> **Почему `cpio`, а не `tar`?**
> Формат RPM проектировался в начале 90-х. В то время существовало множество несовместимых между собой реализаций архиватора `tar` (GNU tar, tar из Solaris и т.д.). Чтобы обеспечить надежную распаковку пакета в любой системе, разработчики RPM выбрали `cpio` — простой, стабильный и стандартизированный в POSIX формат архива.

*   **Распаковать с помощью `rpm2cpio` и `cpio`:**
    ```bash
    rpm2cpio <package_name.rpm> | cpio -idmv
    ```
    *   `rpm2cpio` извлекает CPIO-архив из RPM и выводит его в `stdout`.
    *   `cpio -idmv`:
        *   `-i` (in) - режим извлечения
        *   `-d` (directories) - создавать директории по необходимости
        *   `-m` (modify-time) - сохранять время модификации файлов
        *   `-v` (verbose) - подробный вывод

### Сборка пакетов

Процесс создания собственных пакетов `.deb` или `.rpm`.

#### DEB-based системы

*   **Получение исходников пакета:** Для этого в `/etc/apt/sources.list` должны быть раскомментированы `deb-src` репозитории.
    ```bash
    apt-get source <package_name>
    ```
*   **Структура для сборки:**
    Основные файлы для сборки находятся в директории `debian/`:
    *   `control`: Метаданные, зависимости сборки (`Build-Depends`) и установки (`Depends`).
    *   `rules`: Makefile со сценарием сборки. Часто это просто обертка над стандартными командами `dh` (debhelper).
    *   `changelog`: История изменений. **Версия пакета берется из первой строки этого файла.**
*   **Изменение версии пакета:**
    Формат файла `changelog` очень строгий, поэтому для его изменения рекомендуется использовать утилиту `dch` (`debchange`).
    ```bash
    # Добавить новую запись в changelog и увеличить номер версии
    dch -i 
    # или для добавления локального суффикса (например, +custom1)
    dch --local custom "My custom changes"
    ```
*   **Процесс сборки:**
    ```bash
    # Установить зависимости для сборки из поля Build-Depends
    sudo apt-get build-dep .

    # Перейти в директорию с исходниками и запустить сборку
    cd <package_name-version>/
    dpkg-buildpackage -us -uc
    ```
    *   `-us -uc` отключает подпись пакета и changelog GPG-ключом.
    *   Готовые `.deb` пакеты появятся в директории на уровень выше.

#### RPM-based системы

*   **Получение исходников пакета:** В RPM-мире исходники распространяются в виде "source RPM" пакетов (`.src.rpm`).
    ```bash
    dnf download --source <package_name>
    ```
*   **Структура для сборки:**
    Сборка RPM происходит в специальной структуре директорий в домашнем каталоге пользователя (`~/rpmbuild`). Для создания этой структуры используется утилита `rpmdev-setuptree`:
    ```bash
    # Установить утилиту (в Fedora/CentOS)
    dnf install rpmdevtools
    # Создать структуру каталогов в ~/
    rpmdev-setuptree
    ```
    Основные поддиректории:
    *   `SPECS`: Каталог для `.spec` файлов.
    *   `SOURCES`: Каталог для исходных кодов (например, `tar.gz` архивов) и патчей.
    *   `BUILD`: Временный каталог, где происходит компиляция.
    *   `RPMS`: Сюда помещаются собранные бинарные `.rpm` пакеты.
    *   `SRPMS`: Сюда помещаются собранные исходные `.src.rpm` пакеты.
*   **Процесс сборки:**
    1.  **Установка Source RPM:** "Установка" скачанного `.src.rpm` пакета раскладывает его `.spec` файл в `~/rpmbuild/SPECS` и исходники в `~/rpmbuild/SOURCES`.
        ```bash
        rpm -i <package_name.src.rpm>
        ```
    2.  **Установка зависимостей:** Утилита `dnf builddep` установит все зависимости, перечисленные в `BuildRequires` в `.spec` файле.
        ```bash
        # Указать путь к .spec файлу
        dnf builddep ~/rpmbuild/SPECS/<package_name.spec>
        ```
    3.  **Сборка:** Запуск `rpmbuild` с указанием на `.spec` файл.
        ```bash
        rpmbuild -ba ~/rpmbuild/SPECS/<package_name.spec>
        ```
        *   Флаг `-ba` (build all) собирает и бинарный (`.rpm`), и source-пакет (`.src.rpm`).
        *   Готовые пакеты будут лежать в `~/rpmbuild/RPMS/` и `~/rpmbuild/SRPMS/`.

## Дополнительная информация

### База данных установленных пакетов и устранение проблем

Каждая пакетная система ведет свою базу данных установленных пакетов, в которой хранится информация о файлах, метаданных и статусе.

#### DPKG

*   **Расположение:** `/var/lib/dpkg/`
*   **Статус пакетов:** `/var/lib/dpkg/status` (текстовый файл со списком и состоянием всех пакетов).
*   **Информация о файлах:** `/var/lib/dpkg/info/<package_name>.list` (список файлов для каждого пакета).
*   **Файл блокировки:** `/var/lib/dpkg/lock`. Этот файл предотвращает одновременный запуск нескольких процессов `dpkg` или `apt`. Если пакетный менеджер "завис", нужно найти и завершить процесс, который удерживает этот лок, а не удалять файл вручную.

#### RPM

*   **Расположение:** `/var/lib/rpm/`
*   **Формат:** Исторически использовалась BerkeleyDB. Современные системы (Fedora, RHEL 8+) используют **SQLite** (`/var/lib/rpm/rpmdb.sqlite`).
*   **Восстановление базы:** Если база данных RPM повреждена, ее можно попытаться восстановить с помощью команды:
    ```bash
    rpm --rebuilddb
    ```
*   **Взаимодействие:** Ручное редактирование базы не предусмотрено. Все операции должны производиться только через утилиту `rpm` или высокоуровневые менеджеры (`dnf`, `yum`).
