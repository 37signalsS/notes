# Обзор управления пакетами в Linux: RPM и DEB

## Определения

**Пакет (Package)** — архив, содержащий файлы программы, метаданные (версия, зависимости, контрольные суммы), скрипты установки/удаления и документацию.

**Низкоуровневая утилита** — инструмент для работы с отдельными файлами пакетов: `rpm` (RPM) или `dpkg` (DEB). Устанавливает, удаляет, запрашивает информацию, но **не разрешает зависимости** автоматически.

**Высокоуровневая утилита** — надстройка над низкоуровневыми утилитами: `dnf`/`yum` (RPM) или `apt`/`apt-get`/`aptitude` (DEB). Работает с репозиториями, автоматически разрешает зависимости и управляет обновлениями.

**Репозиторий (Repository)** — сервер или локальный каталог, хранящий коллекцию пакетов и их метаданных в стандартизированной структуре. Позволяет пакетному менеджеру находить, устанавливать и обновлять ПО.

**Зависимость (Dependency)** — другой пакет, необходимый для корректной работы данного пакета.

**Транзакция (Transaction)** — атомарная операция установки, удаления или обновления пакетов, которая может быть отменена или повторена.

## Основные понятия

### Сравнение систем пакетов

| Характеристика              | RPM (Red Hat Package Manager) | DEB (Debian)                    |
| :-------------------------- | :---------------------------- | :------------------------------ |
| **Дистрибутивы**            | Fedora, CentOS, RHEL, openSUSE | Debian, Ubuntu, Mint            |
| **Файлы пакетов**           | `.rpm`                        | `.deb`                          |
| **Низкоуровневая утилита**  | `rpm`                         | `dpkg`                          |
| **Высокоуровневая утилита** | `dnf` (современный), `yum` (устаревший) | `apt`, `apt-get`, `aptitude`    |
| **База данных**             | `/var/lib/rpm/` (SQLite)      | `/var/lib/dpkg/` (текстовые файлы) |
| **Формат метаданных**       | RPM header + cpio archive     | ar archive + control.tar.gz     |

### Принцип работы высокоуровневых пакетных менеджеров

1. **Анализ зависимостей:** Определение всех необходимых пакетов для корректной работы.
2. **Поиск в репозиториях:** Поиск пакетов и их зависимостей в настроенных репозиториях. Возможно управление приоритетами версий через [Apt Pinning](./deb_apt_pinning.md) или использование [приватных репозиториев](./deb_private_apt_repository_reprepro.md).
3. **Составление транзакции:** Формирование плана установки с учётом зависимостей и конфликтов.
4. **Подтверждение:** Пользователь подтверждает операцию после ознакомления со списком пакетов, объёмом загружаемых данных и необходимым дисковым пространством.
5. **Загрузка и установка:** Загрузка файлов пакетов (`.rpm` или `.deb`) и передача их низкоуровневой утилите для непосредственной установки файлов.
6. **Обновление базы данных:** Обновление информации об установленных пакетах в системной базе данных.

## Практические сценарии

### Выбор дистрибутива

| Задача | Рекомендуемый дистрибутив | Обоснование |
| :--- | :--- | :--- |
| **Стабильность, долгосрочная поддержка** | Debian, RHEL, AlmaLinux, Rocky Linux | Консервативные версии пакетов, длительное время поддержки |
| **Свежие версии ПО** | Fedora, Ubuntu (не-LTS), openSUSE Tumbleweed | Частые обновления, новые функции |
| **Корпоративная среда** | RHEL, Ubuntu LTS, AlmaLinux | Коммерческая поддержка, сертификации |
| **Разработка и тестирование** | Fedora, Debian Testing | Баланс между стабильностью и актуальностью |

### Типовые операции

| Операция | DEB (apt) | RPM (dnf) |
| :--- | :--- | :--- |
| **Обновление кэша** | `apt update` | `dnf check-update` |
| **Обновление системы** | `apt upgrade` | `dnf upgrade` |
| **Установка пакета** | `apt install <pkg>` | `dnf install <pkg>` |
| **Удаление пакета** | `apt remove <pkg>` | `dnf remove <pkg>` |
| **Поиск пакета** | `apt search <query>` | `dnf search <query>` |
| **Информация о пакете** | `apt show <pkg>` | `dnf info <pkg>` |
