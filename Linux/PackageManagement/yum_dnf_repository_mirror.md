# Зеркалирование YUM/DNF-репозиториев

## Определения

Ниже приведены основные термины, используемые в процессе создания локальных копий репозиториев для систем на базе RPM (Red Hat Package Manager).

**Локальное зеркало (Local Mirror)** — полная или частичная копия удалённого репозитория пакетов, размещённая в локальной сети или на изолированном сервере. Позволяет экономить внешний трафик и обеспечивать доступ к программному обеспечению в закрытых контурах.

**Репозиторий-источник (Upstream Repository)** — официальный или доверенный удалённый сервер, с которым выполняется синхронизация локального зеркала.

**Синхронизация** — процесс обновления данных локального зеркала до состояния, идентичного источнику. Включает загрузку новых пакетов и удаление устаревших.

**Метаданные репозитория** — набор служебных файлов (например, в формате XML — eXtensible Markup Language), содержащих информацию о версиях пакетов, их зависимостях и контрольных суммах. Основным файлом описания является `repomd.xml`.

---

## Основные концепции

### Назначение зеркалирования

Использование локальных зеркал репозиториев для пакетных менеджеров DNF (Dandified YUM) и YUM (Yellowdog Updater, Modified) необходимо для решения следующих задач:

- **Ускорение обновлений**: Передача данных в локальной сети значительно быстрее загрузки через интернет.
- **Инфраструктура Air-Gapped**: Обеспечение работоспособности серверов в изолированных сетях без прямого доступа к интернету.
- **Контроль версий**: Возможность фиксации определенных версий пакетов для тестирования перед массовым развертыванием в промышленной среде.

### Архитектура процесса

Схема создания зеркала включает три последовательных этапа:

1. **Загрузка**: Утилита `reposync` скачивает пакеты из внешнего источника, сохраняя структуру директорий.
2. **Индексация**: Утилита `createrepo_c` анализирует скачанные пакеты и генерирует локальные метаданные.
3. **Публикация**: Веб-сервер (например, Apache HTTP Server или Nginx) предоставляет доступ к файлам клиентам по протоколу HTTP (HyperText Transfer Protocol).

### Инструментарий

- **reposync** — инструмент из состава `yum-utils`, предназначенный для зеркалирования удалённых репозиториев в локальные директории.
- **createrepo_c** — современная и высокопроизводительная реализация утилиты для создания метаданных RPM-репозиториев (написана на языке C).

## Практические сценарии

### Сценарий 1: Создание зеркала в системах на базе RHEL (Red Hat Enterprise Linux)

#### 1. Установка необходимых пакетов

```bash
sudo dnf install yum-utils createrepo_c httpd
```

#### 2. Синхронизация данных

```bash
# Создание директории для хранения репозиториев
sudo mkdir -p /var/www/html/yum

# Загрузка пакетов из репозитория с идентификатором 'baseos'
sudo reposync --gpgcheck -l --repoid=baseos --download-path=/var/www/html/yum
```

#### 3. Генерация метаданных

```bash
# Инициализация метаданных для загруженного репозитория
sudo createrepo_c /var/www/html/yum/baseos
```

#### 4. Настройка веб-сервера

```bash
# Запуск и добавление Apache в автозагрузку системы
sudo systemctl enable --now httpd

# Настройка брандмауэра для разрешения входящего HTTP-трафика
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
```

---

### Сценарий 2: Развертывание в изолированной сети (Air-Gapped)

1. Выполните синхронизацию и индексацию на сервере с доступом к внешней сети.
2. Перенесите содержимое директории `/var/www/html/yum` на целевой сервер в изолированном контуре.
3. Настройте конфигурационный файл репозитория (с расширением `.repo`) на клиентах, используя протокол `file://`:

```ini
[local-offline]
name=Local Offline Repository
baseurl=file:///mnt/repo/baseos/
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-release
```

## Дополнительная информация

### Расчет требуемого дискового пространства

Приблизительный объем данных для популярных дистрибутивов (актуально на 2024-2026 гг.):

| Дистрибутив | Только база (BaseOS) | Полное зеркало (AppStream + Base) |
| :--- | :--- | :--- |
| **RHEL 9 / AlmaLinux 9** | ~50 GB | ~200 GB |
| **Fedora (Текущий релиз)** | ~70 GB | ~300+ GB |

### Рекомендации по эксплуатации

- **Автоматизация**: Используйте планировщик задач `cron` или таймеры `systemd` для регулярного обновления зеркала.
- **Очистка**: Периодически используйте флаг `--delete` в `reposync` (если доступно в версии) для удаления пакетов, которые больше не присутствуют в источнике.
- **Безопасность**: Всегда используйте проверку цифровых подписей GPG (GNU Privacy Guard) для подтверждения подлинности загружаемого программного обеспечения.
