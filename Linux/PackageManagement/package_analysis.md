# Анализ и получение пакетов в Linux

## Определения

Ниже приведены основные термины, используемые при исследовании структуры и содержимого программного обеспечения в дистрибутивах Linux.

**Анализ пакета** — процесс изучения метаданных, содержимого, зависимостей и скриптов пакета без его обязательной установки в систему.

**Метаданные пакета** — структурированная информация о пакете: версия, зависимости, краткое и полное описание, сопровождающий (maintainer), размер и целевая архитектура процессора.

**Содержимое пакета** — полный перечень файлов и директорий с указанием прав доступа, которые будут развернуты в системе при установке.

**Scriptlets (Скрипты пакета)** — вспомогательные сценарии, исполняемые менеджером пакетов на различных этапах жизненного цикла (до или после установки/удаления).

## Основные концепции

### Структура пакетов

#### DEB (Debian Package)

Архив формата `ar`, содержащий три обязательных компонента:

- `debian-binary` — текстовый файл с версией формата пакета.
- `control.tar.gz` — метаданные и управляющие скрипты (`control`, `md5sums`, `preinst`, `postinst`, `prerm`, `postrm`).
- `data.tar.gz` — основной архив с файлами, предназначенными для установки в системные директории.

#### RPM (Red Hat Package Manager)

Сложная структура, состоящая из следующих секций:

- **Заголовок (Header)** — метаданные в бинарном формате.
- **Подпись (Signature)** — криптографическая подпись GPG (GNU Privacy Guard) для подтверждения подлинности и целостности.
- **Тело (Payload)** — архив в формате CPIO (Copy In and Out), содержащий файлы устанавливаемого программного обеспечения.

### Жизненный цикл скриптов

| Скрипт | Выполняется | Назначение |
| :--- | :--- | :--- |
| `preinst` / `%pre` | Перед установкой | Проверка системных условий, подготовка окружения. |
| `postinst` / `%post` | После установки | Регистрация сервисов, создание пользователей, финальная настройка. |
| `prerm` / `%preun` | Перед удалением | Остановка активных демонов, сохранение критических данных. |
| `postrm` / `%postun` | После удаления | Очистка временных файлов, уведомление системы об изменениях. |

## Практические сценарии

### Получение файлов пакетов без установки

#### Системы на базе APT (Advanced Package Tool)

```bash
# Скачать только файл пакета в текущую директорию
apt-get download <package_name>

# Скачать пакет со всеми зависимостями в локальный кэш (/var/cache/apt/archives/)
apt-get install --download-only <package_name>

# Поиск пакета по фрагменту пути или имени файла (требует apt-file)
sudo apt-get update && sudo apt-get install apt-file && apt-file update
apt-file search <file_path_or_name>

# Определение пакета, которому принадлежит существующий файл
dpkg -S <file_path>

# Поиск пакета, предоставляющего конкретную команду
apt-file search bin/<command_name>

# Анализ цепочки зависимостей (APT 3.2+)
# Показывает, почему пакет должен быть установлен в текущей конфигурации
apt why <package_name>

# Анализ конфликтов и блокировок (APT 3.2+)
# Объясняет причины невозможности установки пакета
apt why-not <package_name>
```

#### Системы на базе DNF (Dandified YUM)

```bash
# Скачать RPM-файл без установки
dnf download <package_name>

# Скачать пакет и его зависимости в указанную директорию
dnf install --downloadonly --destdir=/path/to/dir <package_name>

# Поиск пакета, предоставляющего файл или возможность (capability)
dnf provides '*/<file_name>'
dnf provides <command_name>

# Определение пакета по установленному в систему файлу
rpm -qf <file_path>
```

### Анализ метаданных и структуры архивов

#### Инструментарий DEB

```bash
# Информация о пакете из не установленного .deb файла
dpkg-deb --info <package_name.deb>

# Просмотр списка файлов внутри .deb архива
dpkg-deb --contents <package_name.deb>

# Статус и метаданные установленного в систему пакета
dpkg -s <package_name>

# Список всех файлов, установленных конкретным пакетом
dpkg -L <package_name>

# Просмотр только зависимостей пакета
dpkg -s <package_name> | grep Depends
```

#### Инструментарий RPM

```bash
# Чтение метаданных из файла .rpm
rpm -qip <package_name.rpm>

# Список файлов внутри не установленного .rpm пакета
rpm -qlp <package_name.rpm>

# Подробная информация об установленном ПО
rpm -qi <package_name>

# Список файлов установленного RPM-пакета
rpm -ql <package_name>

# Просмотр встроенных скриптов (scriptlets)
rpm -q --scripts <package_name>

# Анализ зависимостей (Requirements)
rpm -qR <package_name>
# или более наглядно через dnf
dnf deplist <package_name>
```

### Ручная распаковка (Extraction)

#### Извлечение из DEB

```bash
# Распаковка файлов в указанную директорию через dpkg-deb
dpkg-deb --extract <package_name.deb> <output_dir>

# Раздельное извлечение управляющих файлов (control) и данных (data)
dpkg-deb --control <package_name.deb> <control_dir>
dpkg-deb --extract <package_name.deb> <data_dir>

# Распаковка базовых архивов вручную
ar x <package_name.deb>
# Результат: debian-binary, control.tar.gz, data.tar.gz
```

#### Извлечение из RPM

```bash
# Преобразование RPM в поток CPIO и его распаковка
rpm2cpio <package_name.rpm> | cpio -idmv
# Флаги cpio: -i (извлечение), -d (создание директорий), -m (сохранение времени), -v (подробно)
```

## Дополнительная информация

### Низкоуровневые утилиты и их особенности

Утилиты `dpkg` и `rpm` работают напрямую с базой данных и файлами, не обращаясь к внешним репозиториям. Они не умеют автоматически разрешать зависимости, поэтому их основное назначение — диагностика и работа с локальными файлами.

| Операция | DEB (высокий уровень: apt) | DEB (низкий уровень: dpkg) | RPM (высокий уровень: dnf) | RPM (низкий уровень: rpm) |
| :--- | :--- | :--- | :--- | :--- |
| **Установка из файла** | `apt install ./pkg.deb` | `dpkg -i pkg.deb` | `dnf install ./pkg.rpm` | `rpm -i pkg.rpm` |
| **Разрешение зависимостей** | Автоматически | `apt-get install -f` | Автоматически | Вручную |
| **Удаление пакета** | `apt remove pkg` | `dpkg -r pkg` | `dnf remove pkg` | `rpm -e pkg` |
| **Проверка целостности** | `apt verify` (в новых версиях) | `debsums pkg` | `dnf verify` | `rpm -V pkg` |
