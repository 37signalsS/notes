# База данных установленных пакетов

## Определения

Ниже приведены основные термины, описывающие внутренние механизмы хранения информации о программном обеспечении в дистрибутивах Linux.

**База данных пакетов (Package Database)** — централизованное системное хранилище информации об установленных, удалённых и доступных пакетах. Содержит метаданные, списки файлов, статусы, зависимости и конфигурационные скрипты.

**DPKG (Debian Package Manager)** — низкоуровневая система управления пакетами в дистрибутивах на базе DEB, использующая текстовый формат хранения данных (плоские файлы).

**RPM (Red Hat Package Manager)** — система управления пакетами, использующая бинарные форматы хранения. В современных дистрибутивах (Fedora 33+, RHEL 9+) по умолчанию используется **SQLite**, в устаревших — Berkeley DB (BDB).

**Файл блокировки (Lock file)** — служебный механизм (например, `/var/lib/dpkg/lock-frontend`), предотвращающий одновременный доступ нескольких менеджеров пакетов к базе данных для предотвращения коррупции данных.

## Основные концепции

### Структура базы данных DPKG

В дистрибутивах Debian/Ubuntu база данных расположена в `/var/lib/dpkg/` и состоит из нескольких ключевых компонентов:

- **status**: Основной файл базы данных. Содержит метаданные всех пакетов, когда-либо известных системе, и их текущее состояние (Installed, Config-Files, Not-Installed).
- **available**: Информация о пакетах, доступных в репозиториях (используется преимущественно `dselect`, для `apt` данные хранятся в `/var/lib/apt/lists/`).
- **info/**: Директория, содержащая вспомогательные файлы для каждого пакета:
  - `.list`: Полный перечень файлов, принадлежащих пакету.
  - `.md5sums`: Контрольные суммы файлов для проверки целостности.
  - `.preinst`, `.postinst`, `.prerm`, `.postrm`: Управляющие скрипты пакета.

### Структура базы данных RPM

Располагается в `/var/lib/rpm/`. Современная реализация на SQLite обеспечивает более высокую надежность и устойчивость к сбоям по сравнению с BDB.
- **rpmdb.sqlite**: Основной файл БД в современных системах.
- **Packages**: Основной файл в старых системах (BDB-формат).

### Механизмы блокировок

В современных системах на базе APT используется многоуровневая блокировка:
1.  **lock-frontend**: Блокирует высокоуровневые операции (например, запуск `apt install`), позволяя при этом выполнять операции чтения.
2.  **lock**: Низкоуровневая блокировка самого `dpkg`.

## Практические сценарии

### Обслуживание базы данных DPKG (Debian/Ubuntu)

#### Запросы к базе данных (dpkg-query)

```bash
# Вывод списка всех установленных пакетов с их статусом
dpkg-query -l
# → result: список пакетов с префиксами ii (installed), rc (removed but config remains)

# Поиск пакета по шаблону в базе данных
dpkg-query -l 'nginx*'

# Получение пути к списку файлов конкретного пакета
ls /var/lib/dpkg/info/nginx-common.list
```

#### Восстановление при критических ошибках

```bash
# Исправление прерванной конфигурации пакетов
sudo dpkg --configure -a

# Безопасная очистка зависших блокировок (только если процессы apt/dpkg не запущены)
sudo fuser -vki /var/lib/dpkg/lock-frontend
sudo rm /var/lib/dpkg/lock-frontend
```

---

### Обслуживание базы данных RPM (Fedora/RHEL/CentOS)

#### Проверка целостности данных

```bash
# Проверка всех пакетов на расхождение с базой данных
rpm -Va
# → result: список файлов, где S (размер), 5 (MD5), T (время) не совпадают

# Проверка только файлов конфигурации
rpm -Vac
```

#### Восстановление базы данных

```bash
# Проверка базы данных на наличие повреждений
rpm --verifydb

# Перестроение базы данных (создание новых индексов из заголовков пакетов)
# Рекомендуется при ошибках "BDB0060 PANIC" или "database is locked"
sudo rpm --rebuilddb
```

## Дополнительная информация

### Журналирование и история

Отслеживание изменений в базе данных критически важно для аудита и отката изменений.

- **DNF History**: Позволяет просматривать историю транзакций (`dnf history list`) и отменять их (`dnf history undo <ID>`).
- **APT/DPKG Logs**:
  - `/var/log/dpkg.log`: Низкоуровневая запись всех изменений статусов пакетов.
  - `/var/log/apt/history.log`: Высокоуровневая запись команд, выполненных через `apt` (включая пользователя и время).

### Рекомендации (Best Practices)

1.  **Не редактируйте вручную**: Файлы в `/var/lib/dpkg/` или `/var/lib/rpm/` никогда не должны редактироваться текстовым редактором, это приведет к рассинхронизации системы.
2.  **Бэкап базы данных**: Перед сложными операциями обновления дистрибутива (dist-upgrade) рекомендуется делать бэкап директории `/var/lib/dpkg/` или `/var/lib/rpm/`.
3.  **Использование debsums**: Для систем Debian/Ubuntu всегда устанавливайте пакет `debsums` для возможности верификации базы данных, аналогичной `rpm -V`.
