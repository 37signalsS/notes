# База данных установленных пакетов

## Определения

Ниже приведены основные термины, описывающие внутренние механизмы хранения информации о программном обеспечении в дистрибутивах Linux.

**База данных пакетов (Package Database)** — централизованное системное хранилище информации об установленных, удалённых и доступных пакетах. Содержит метаданные, списки файлов, статусы, зависимости и конфигурационные скрипты.

**DPKG (Debian Package Manager)** — низкоуровневая система управления пакетами в дистрибутивах на базе DEB (Debian Package), использующая текстовый формат хранения базы данных.

**RPM (Red Hat Package Manager)** — система управления пакетами, использующая структурированные базы данных (Berkeley DB или SQLite — Structured Query Language) для хранения информации о составе системы.

**Файл блокировки (Lock file)** — служебный файл (например, `/var/lib/dpkg/lock`), предотвращающий одновременный запуск нескольких процессов изменения базы данных во избежание её повреждения.

## Основные концепции

### Назначение базы данных

- **Инвентаризация**: хранение точных версий и текущих статусов (установлен, удален, настроен) всего программного обеспечения.
- **Целостность**: возможность автоматической проверки соответствия файлов в системе их эталонным контрольным суммам, зафиксированным в базе данных.
- **Разрешение зависимостей**: предоставление информации высокоуровневым менеджерам (APT — Advanced Package Tool, DNF — Dandified YUM) для корректного построения дерева связей.
- **Владение файлами**: сопоставление любого файла в системных директориях с конкретным пакетом-владельцем.

### Сравнение систем хранения

| Характеристика | DPKG (Debian/Ubuntu) | RPM (RHEL/Fedora) |
| :--- | :--- | :--- |
| **Формат хранения** | Текстовые файлы (RFC 822-подобные) | Бинарный (SQLite или Berkeley DB) |
| **Путь к базе данных** | `/var/lib/dpkg/` | `/var/lib/rpm/` |
| **Списки файлов** | Отдельные файлы `.list` для каждого пакета | Интегрированы в структуру основной базы |
| **Журнал транзакций** | Текстовый лог `/var/log/dpkg.log` | Встроенная история в SQLite-базе |

## Практические сценарии

### Обслуживание базы данных DPKG (Debian/Ubuntu)

#### Диагностика состояния

```bash
# Проверка статуса установленного пакета (метаданные из БД)
dpkg -s <package_name>

# Определение пакета, которому принадлежит файл в системе
dpkg -S /path/to/file

# Проверка целостности файлов (требует пакет debsums)
debsums <package_name>
```

#### Восстановление при критических ошибках

```bash
# Завершение конфигурации всех прерванных установок
sudo dpkg --configure -a

# Исправление нарушенных зависимостей после ручного вмешательства
sudo apt-get install -f

# Удаление файлов блокировки (выполнять только при отсутствии активных процессов apt/dpkg)
sudo rm /var/lib/dpkg/lock*
sudo rm /var/cache/apt/archives/lock
```

---

### Обслуживание базы данных RPM (Fedora/RHEL/CentOS)

#### Проверка целостности

Система RPM позволяет быстро выявить расхождения между файлами на диске и данными в БД (права доступа, размер, контрольная сумма).

```bash
# Проверка конкретного пакета
rpm -V <package_name>

# Проверка всех пакетов в системе (может занять время)
rpm -Va
```

#### Восстановление и перестроение

При повреждении индексов или внезапном отключении питания база данных RPM может стать нечитаемой.

```bash
# Проверка базы данных на логические ошибки
rpm --verifydb

# Полное перестроение индексов (безопасно, восстанавливает структуру из файлов пакетов)
sudo rpm --rebuilddb
```

## Дополнительная информация

### Управление историей изменений

Современные пакетные менеджеры позволяют не только видеть список установленного ПО, но и отслеживать историю транзакций.

- **В системах RPM (DNF)**: Используется команда `dnf history`, позволяющая просматривать идентификаторы транзакций и выполнять операции отката (`undo`) или повтора (`redo`). Подробнее см. **[Практические сценарии DNF](./dnf_commands/practical_scenarios.md)**.
- **В системах DEB (APT 3.2+)**: Внедрена поддержка истории команд (history) и механизмов автоматического отката состояний, аналогичных системе DNF.
