# DNF — Глоссарий и определения

## Определения

Ниже приведены определения терминов, специфичных для пакетного менеджера DNF и RPM-экосистемы. Базовые понятия пакетного управления описаны в **[общем обзоре пакетных менеджеров](../linux_package_management_overview.md)**.

### Основные компоненты

**DNF (Dandified YUM)** — современный высокоуровневый пакетный менеджер для RPM-based систем. Решает проблемы YUM с производительностью и разрешением зависимостей.

**DNF 5** — следующее поколение DNF на C++. Обеспечивает максимальную производительность, унификацию API и уменьшение зависимостей самого менеджера (не требует Python).

**Libsolv** — библиотека разрешения зависимостей (SAT-solver), используемая в DNF, Zypper и других менеджерах.

**Libdnf / Libdnf5** — низкоуровневая библиотека, реализующая основную логику работы с репозиториями, пакетами и транзакциями.

**Hawkey** — высокоуровневая библиотека-обертка над `libsolv` для Python/C (используется в DNF 4).

**RPM (Red Hat Package Manager)** — формат пакетов и низкоуровневая утилита для их установки.

### Механизмы репозиториев

**Repodata (Метаданные)** — набор XML или SQLite файлов в репозитории, содержащий информацию о пакетах, зависимостях, контрольных суммах и GPG-подписях.

**Metadata Cache (Кэш метаданных)** — локальная копия `repodata` на машине пользователя. Позволяет выполнять поиск и расчет зависимостей без обращения к сети.

**Repository Priority (Приоритет репозитория)** — числовое значение, определяющее предпочтительный источник пакета при наличии одной и той же версии в разных репозиториях.

**COPR (Cool Other Package Repo)** — облачный сервис для сборки и хранения сторонних пользовательских репозиториев (аналог PPA).

**AppStream / BaseOS** — разделение репозиториев в RHEL 8+: `BaseOS` содержит ядро и базовую систему, `AppStream` — приложения и модули.

### Управление пакетами и зависимости

**Модуль (Module)** — логическая группа пакетов, представляющая конкретное приложение или стек (например, `nodejs`).
- **Stream (Поток)** — версия или ветка модуля (например, `nodejs:20`).
- **Profile (Профиль)** — вариант установки модуля (`common`, `minimal`, `development`).

**Слабые зависимости (Weak Dependencies)**:
- **Recommends** — устанавливаются по умолчанию, но не обязательны для работы.
- **Suggests** — дополнительные пакеты, предлагаемые пользователю.

**Boolean Dependencies (Булевы зависимости)** — использование логических выражений (`and`, `or`, `if`) в зависимостях пакета.

**Capabilities (Возможности)** — абстрактные имена (например, `webserver`), которые пакеты могут "предоставлять" (`Provides`) или "требовать" (`Requires`). Позволяют заменять пакеты (например, `nginx` и `httpd` оба предоставляют `webserver`).

**Obsoletes (Устаревание)** — механизм, позволяющий пакету объявить другой пакет устаревшим и заменить его при обновлении.

**DRPM (Delta RPM)** — пакет, содержащий только разницу между старой и новой версией RPM, что экономит трафик.

### Состояния и операции

**Транзакция** — атомарный набор операций по установке, удалению или обновлению пакетов.

**Transaction History (История)** — база данных всех выполненных транзакций, позволяющая выполнять откат (`rollback`) или отмену (`undo`).

**Environment Group (Группа окружения)** — верхнеуровневый набор групп пакетов (например, "Server with GUI").

**Package Group (Группа пакетов)** — именованный набор пакетов для конкретной задачи (например, "Development Tools").
