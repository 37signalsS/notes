# DNF — Глоссарий и определения

## Основные термины

Ниже приведены определения терминов, специфичных для пакетного менеджера DNF и RPM-экосистемы. Базовые понятия пакетного управления (пакет, зависимость, транзакция, репозиторий) описаны в **[общем обзоре пакетных менеджеров](../linux_package_management_overview.md)**.

**DNF (Dandified YUM)** — современный высокоуровневый пакетный менеджер для RPM-based дистрибутивов (Fedora, RHEL 8/9, CentOS, AlmaLinux, Rocky Linux). Является заменой устаревшего `yum`, обеспечивая более высокую скорость работы и предсказуемое разрешение зависимостей.

**DNF 5** — следующее поколение пакетного менеджера, написанное на C++ (в отличие от Python-версии DNF 4). Обеспечивает значительный прирост производительности, уменьшение объема метаданных и унификацию поведения CLI и библиотек. Становится стандартом в новых версиях Fedora (с 41+) и будущих релизах RHEL.

**RPM (Red Hat Package Manager)** — формат пакетов и низкоуровневая утилита для управления ими. Пакет RPM содержит скомпилированные файлы, метаданные, скрипты установки (pre/post install) и информацию о зависимостях.

**COPR (Cool Other Package Repo)** — сервис для создания и хранения пользовательских репозиториев (аналог PPA в Ubuntu). Позволяет разработчикам легко собирать и распространять пакеты, не входящие в официальные репозитории дистрибутива.

**GPG-ключ (GNU Privacy Guard)** — криптографический ключ для проверки цифровой подписи пакетов и метаданных. Подробное описание механизмов доверия приведено в разделе **[Управление репозиториями](../Repository_Management/index.md)**.

## Архитектура и зависимости

**Libsolv** — библиотека разрешения зависимостей, использующая алгоритм SAT-solver (Satisfiability). Обеспечивает быструю и корректную обработку сложных графов зависимостей.

**Слабые зависимости (Weak Dependencies)** — механизм RPM, позволяющий указывать необязательные пакеты:
- **Recommends** — пакеты, которые будут установлены по умолчанию, если не указано иное (могут быть удалены без вреда для основного пакета).
- **Suggests** — пакеты, которые расширяют функциональность, но не устанавливаются автоматически.

**Булевы зависимости (Boolean Dependencies)** — использование логических операторов (`if`, `and`, `or`, `else`) в метаданных пакета для описания условий установки (например, "установить пакет А, только если установлены Б и В").

**Транзакция** — атомарная операция (или набор операций), выполняемая DNF. Если один из этапов транзакции завершается сбоем, система может быть возвращена в исходное состояние (rollback), что гарантирует целостность базы данных пакетов.

**DRPM (Delta RPM)** — технология передачи только различий между версиями пакета вместо полной загрузки нового RPM-файла. Позволяет значительно экономить трафик при обновлениях.

## Механизмы модульности

**Модуль (Module)** — абстракция над набором пакетов, представляющая конкретное приложение или стек технологий (например, `nodejs`, `postgresql`). Модули позволяют управлять жизненным циклом ПО независимо от версии ОС.

**Stream** — конкретная версия или "ветка" внутри модуля (например, `postgresql:15`, `postgresql:16`). Пользователь выбирает нужный stream для установки.

**Профиль (Profile)** — предустановленный набор пакетов внутри модуля для конкретной роли (например, `common`, `server`, `client`, `development`).

**AppStream / BaseOS** — типы репозиториев в современных RPM-системах. Определения и структура описаны в разделе **[Управление репозиториями](../Repository_Management/index.md)**.

## Практические сценарии

Применение терминов в повседневных задачах. Командный справочник доступен в файле **[Практические сценарии DNF](./practical_scenarios.md)**.

| Задача | Ключевые понятия |
| :--- | :--- |
| **Выбор версии базы данных** | Модуль, Stream |
| **Экономия трафика при обновлении** | DRPM |
| **Установка рекомендуемых утилит** | Слабые зависимости |
| **Использование стороннего ПО** | COPR, GPG-ключ |
| **Анализ сбоя установки** | Транзакция, Libsolv |
