## Архитектура пакетного менеджера

### Эволюция: от YUM к DNF 5

Пакетный менеджер DNF (Dandified YUM) пришёл на смену YUM в Fedora 22 и RHEL 8, решив проблемы производительности, высокого потребления памяти и неэффективного разрешения зависимостей.

*   **DNF 4 (текущий стандарт):** Написан на Python, использует библиотеку `libsolv` (написанную на C) для разрешения зависимостей через SAT-solver. Для работы с метаданными и расширениями используется библиотека `hawkey`.
*   **DNF 5 (новое поколение):** Написан полностью на C++, что исключает накладные расходы интерпретатора Python. Все компоненты объединены в общую библиотеку `libdnf5`, обеспечивая идентичное поведение для CLI, плагинов и графических интерфейсов (например, Cockpit).

### Ключевые компоненты

1.  **Libsolv:** Библиотека, обеспечивающая быструю и корректную обработку зависимостей. Она строит граф пакетов и находит оптимальный путь установки или обновления.
2.  **Metadata Cache:** Локальная копия данных из репозиториев (списки пакетов, контрольные суммы, описания). DNF минимизирует количество запросов к серверу, работая с кэшем до истечения срока его жизни.
3.  **Transaction Database:** База данных истории операций (обычно SQLite в `/var/lib/dnf/history`). Позволяет просматривать детали прошлых установок и выполнять откат.

## Конфигурация системы

### Иерархия настроек

1.  **Глобальные настройки:** Файл `/etc/dnf/dnf.conf`. Параметры в секции `[main]` применяются ко всем операциям.
2.  **Настройки репозиториев:** Файлы в директории `/etc/yum.repos.d/*.repo`. Секции конкретных репозиториев могут переопределять глобальные параметры (например, `gpgcheck` или `proxy`).

### Глобальный файл конфигурации (dnf.conf)

Ниже приведены ключевые параметры оптимизации производительности и безопасности:

```ini
[main]
gpgcheck=1              # Обязательная проверка подписей всех пакетов
installonly_limit=3     # Лимит версий ядра (старые удаляются автоматически)
clean_requirements_on_remove=true  # Удаление зависимостей при удалении основного пакета
best=True               # Всегда предлагать версию пакета с максимальным номером
skip_if_unavailable=False  # Прерывать операцию, если репозиторий недоступен

# Оптимизация производительности
max_parallel_downloads=10  # Количество одновременных потоков загрузки (ускоряет upgrade)
fastestmirror=True      # Автоматический выбор самого быстрого зеркала по пингу
metadata_expire=6h      # Время жизни кэша метаданных (6 часов)
deltarpm=True           # Использование Delta RPM для экономии трафика (в DNF 4)
```

### Структура каталогов

| Путь | Назначение |
| :--- | :--- |
| `/etc/dnf/dnf.conf` | Основной конфигурационный файл. |
| `/etc/yum.repos.d/` | Файлы описания репозиториев. |
| `/var/cache/dnf/` | Кэш метаданных и скачанные RPM-пакеты. |
| `/var/lib/dnf/` | Системные данные DNF (история, состояния модулей). |
| `/var/log/dnf.log` | Основной журнал работы. |

## Механизмы работы

### Жизненный цикл метаданных

DNF загружает метаданные (`repodata`) при первом обращении или по истечении `metadata_expire`. Процесс включает:
1.  Загрузку `repomd.xml` (указатель на остальные файлы метаданных).
2.  Проверку контрольных сумм и GPG-подписей (если `repo_gpgcheck=1`).
3.  Загрузку основных списков пакетов (`primary.xml`) и данных о модулях.

### Обработка транзакций

Каждая операция изменения состояния системы (install, remove, upgrade) проходит через этапы:
1.  **Проверка зависимостей:** Построение графа и проверка конфликтов.
2.  **Скачивание:** Загрузка пакетов в кэш.
3.  **Тестовый прогон (Transaction Check):** Проверка целостности RPM-базы перед записью.
4.  **Исполнение:** Установка/удаление файлов и выполнение скриптов пакетов.
5.  **Запись в историю:** Сохранение результата операции.
