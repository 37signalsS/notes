# Создание приватного Apt-репозитория с помощью reprepro

## Определения

**`reprepro`** — это утилита для создания и управления репозиториями `.deb` пакетов для Debian, Ubuntu и их производных. Это мощный инструмент для организации доставки вашего собственного ПО или для создания зеркала существующих пакетов.

## Основные понятия

### Подпись репозитория (GPG)

Apt-репозитории должны быть подписаны GPG-ключом. Это криптографическая мера, позволяющая клиентам (серверам, которые будут использовать репозиторий) проверять подлинность пакетов. Без доверенного ключа `apt` откажется устанавливать пакеты из вашего репозитория, считая их небезопасными.

### Конфигурация дистрибутивов

Основной конфигурационный файл `reprepro` — это `conf/distributions`. Он описывает, какие дистрибутивы (например, `focal`, `buster`), компоненты (`main`, `contrib`) и архитектуры (`amd64`, `arm64`) будет обслуживать репозиторий.

*   `Origin`, `Label`: Имена, которые помогут идентифицировать репозиторий на клиенте (например, для [настройки приоритетов](./deb_apt_pinning.md)).
*   `Codename`: Кодовое имя релиза ОС, для которого предназначены пакеты (например, `focal` для Ubuntu 20.04, `buster` для Debian 10).
*   `SignWith`: ID GPG-ключа, который используется для подписи репозитория.

## Практический сценарий: Настройка репозитория с нуля

### Шаг 1: Установка и создание структуры

Сначала установим `reprepro` и создадим базовую структуру директорий для нашего репозитория.

```bash
sudo apt-get update
sudo apt-get install reprepro

# Создаем корневую директорию репозитория и поддиректорию для конфигурации
mkdir -p my-repo/conf
```

### Шаг 2: Создание GPG-ключа для подписи

Сгенерируем новый GPG-ключ.

```bash
# Следуйте интерактивным инструкциям. Рекомендуется выбрать RSA and RSA, 4096 бит.
gpg --gen-key
```

После создания узнайте ID ключа, который понадобится для конфигурации.

```bash
# Вывести список секретных ключей в длинном формате ID
gpg --list-secret-keys --keyid-format LONG
```

Вывод будет примерно таким, где `AABBCCDD11223344` — это ID вашего ключа:
```
sec   rsa4096/AABBCCDD11223344 2025-11-13 [SC]
      XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
uid                 [ultimate] Your Name <your.email@example.com>
```
Здесь `AABBCCDD11223344` — это ID вашего ключа.

Теперь экспортируем публичную часть ключа. Этот файл (`repo.key`) нужно будет распространить на все клиентские машины.

```bash
# Экспортируем публичную часть ключа. Этот файл (`repo.key`) нужно будет распространить на клиентские машины.
# Замените <ID_ВАШЕГО_GPG_КЛЮЧА> на реальный ID, полученный на предыдущем шаге.
gpg --export -a "<ID_ВАШЕГО_GPG_КЛЮЧА>" > my-repo/repo.key
```

### Шаг 3: Конфигурация репозитория

Создадим файл `my-repo/conf/distributions` и опишем в нем наш дистрибутив. Замените `<ID_ВАШЕГО_GPG_КЛЮЧА>` на свой.

```
# my-repo/conf/distributions

# Имя репозитория, которое будет видно клиентам
Origin: MyRepo
# Описание
Label: My Private APT Repository
# Кодовое имя дистрибутива (например, Ubuntu 20.04)
Codename: focal
# Архитектуры
Architectures: amd64
# Компоненты
Components: main
# Описание
Description: My private package repository
# Указываем ID GPG-ключа для подписи
SignWith: <ID_ВАШЕГО_GPG_КЛЮЧА>
```

### Шаг 4: Добавление пакетов

Добавим в репозиторий подготовленный `.deb` пакет.

```bash
# Переходим в директорию репозитория для удобства
cd my-repo

# Добавляем пакет в дистрибутив 'focal'
# reprepro попросит ввести пароль от GPG-ключа для подписи метаданных
reprepro includedeb focal /path/to/your/package_1.0_amd64.deb
```
После выполнения команды `reprepro` автоматически создаст всю необходимую структуру (`dists`, `pool`) и обновит метаданные.

### Шаг 5: Публикация репозитория (Nginx)

Репозиторий — это набор статических файлов, поэтому его легко опубликовать с помощью любого веб-сервера.

Пример конфигурации для Nginx:

```nginx
server {
    listen 80;
    server_name repo.your.domain;

    # Укажите полный путь к корневой директории вашего репозитория
    root /path/to/your/my-repo;

    location / {
        # Включаем листинг директорий для удобства просмотра
        autoindex on;
    }
}
```
Для защиты репозитория можно также настроить [аутентификацию по клиентским SSL-сертификатам](../../WebServers/Nginx/ssl_client_certificate_authentication.md).

### Шаг 6: Настройка клиента

Чтобы клиентская машина могла использовать ваш репозиторий:

1.  **Скопируйте публичный GPG-ключ (`repo.key`)** на клиентскую машину и добавьте его в доверенные.
    ```bash
    sudo cp repo.key /etc/apt/trusted.gpg.d/my-repo.asc
    ```

2.  **Создайте файл списка источников** `/etc/apt/sources.list.d/my-repo.list`.
    ```
    # /etc/apt/sources.list.d/my-repo.list
    deb [arch=amd64] http://repo.your.domain focal main
    ```

3.  **Обновите список пакетов.**
    ```bash
    sudo apt-get update
    ```
Теперь вы можете устанавливать пакеты из вашего приватного репозитория: `sudo apt-get install your-package`.
