## Определения

**Пространства имён (Namespaces)** — это одна из фундаментальных технологий ядра Linux, которая обеспечивает изоляцию и виртуализацию системных ресурсов. Она позволяет создавать для группы процессов "свой собственный мир", в котором они видят только те ресурсы, которые принадлежат их пространству имён.

## Основные концепции

* Изменение ресурса внутри пространства имён может быть невидимым снаружи.
* Позволяет монтировать ресурсы с изменением привилегий.
* Даёт возможность запускать процессы в полностью изолированной среде.
* Является основой для **контейнеров** и **подов** (в Kubernetes).

Именно `namespaces` вместе с **[cgroups](./cgroups.md)** лежат в основе технологии контейнеризации (Docker, Podman, Kubernetes).

### Типы пространств имён

1. **Mount (mnt):**
    * **Изолирует:** Точки монтирования файловых систем.
    * **Как работает:** Процессы в одном `mnt` namespace могут иметь свой собственный, уникальный набор смонтированных файловых систем, невидимый для других процессов. Это позволяет:
        * Создавать для процесса свою собственную корневую файловую систему (`/`), изолированную от хоста.
        * Иметь приватные точки монтирования. Например, можно смонтировать собственную, изолированную версию `/tmp`, `/sys` или `/proc`, что является основой для работы контейнеров.

2. **PID (Process ID):**
    * **Изолирует:** Идентификаторы процессов (PID).
    * **Как работает:**
        * Процессы внутри одного PID namespace видят только те процессы, которые находятся в том же самом namespace.
        * Каждый PID namespace имеет свою собственную, изолированную иерархию процессов, которая начинается с PID 1.
        * Первый процесс, созданный в namespace, получает PID 1 и становится "init-процессом" для этого namespace.
        * Если этот "init-процесс" (PID 1) завершается, ядро завершает все остальные процессы в этом namespace, и сам namespace уничтожается.
        * Снаружи (в родительском namespace) эти же процессы имеют другие, уникальные для всей системы PID.

3. **Network (net):**
    * **Изолирует:** Сетевой стек.
    * **Как работает:** Процесс в новом `net` namespace получает полностью изолированное сетевое окружение, которое включает:
        * **Сетевые интерфейсы:** Свой набор сетевых устройств, включая собственный `loopback` (`lo`).
        * **Таблицу маршрутизации:** Собственные правила маршрутизации.
        * **Правила Firewall:** Изолированные правила `iptables` или `nftables`.
        * **Сетевые сокеты:** Изолированные порты и сокеты.
    * Несколько процессов (или контейнеров) могут совместно использовать один и тот же network namespace, что позволяет им взаимодействовать через `localhost` (например, как в подах Kubernetes).

4. **User:**
    * **Изолирует:** Идентификаторы пользователей и групп (UID, GID).
    * **Как работает:** Позволяет создавать сопоставление (mapping) между пользователями внутри namespace и пользователями на хостовой системе.
        * Ключевая возможность — сопоставить UID 0 (`root`) внутри namespace с обычным, непривилегированным UID на хосте.
        * Таким образом, процесс может выполняться с полными правами администратора внутри своего namespace, но для основной системы он остается процессом с ограниченными правами. Это фундаментальный механизм для безопасной работы контейнеров (rootless containers).

5. **IPC (Inter-Process Communication):**
    * **Изолирует:** Механизмы межпроцессного взаимодействия, такие как семафоры, очереди сообщений и разделяемая память (System V IPC).

6. **UTS (UNIX Timesharing System):**
    * **Изолирует:** Имя хоста и доменное имя (`hostname`, `domainname`).
    * **Как работает:** Позволяет каждому контейнеру иметь своё собственное уникальное имя хоста.

### Управление пространствами имён

В ядре Linux существует три основных системных вызова для работы с пространствами имён:

* **`clone()`**: Создаёт новый процесс. При использовании специальных флагов (например, `CLONE_NEWPID`, `CLONE_NEWNET`) он сразу создаёт процесс в новом пространстве имён указанного типа. Это основной способ создания изолированных процессов "с нуля".
* **`unshare()`**: Позволяет уже существующему процессу "отсоединиться" от своего текущего пространства имён и перейти в новое. Процесс как бы создает новую "комнату" и переходит в нее, оставляя остальные процессы в старой.
* **`setns()`**: Позволяет процессу присоединиться к уже существующему пространству имён, на которое указывает файловый дескриптор. Это механизм "входа" в уже созданную "комнату".

Утилиты командной строки, такие как `unshare` и `nsenter`, являются удобными **обертками (wrappers)** над этими системными вызовами, предоставляя простой интерфейс для выполнения тех же действий из терминала.

## Практические сценарии

### Создание нового пространства имён с `unshare`

Утилита `unshare` позволяет запустить процесс, отделив его от родительских пространств имён и поместив в новые.

**Пример: Запуск изолированной оболочки**

```bash
# Запускаем новую оболочку bash в новых пространствах имён:
# --mount: новая файловая система (пустая)
# --uts: новое имя хоста
# --ipc: новая область IPC
# --net: новая сеть (только с интерфейсом lo)
# --pid --fork: новое дерево процессов (требует --fork)
# --user --map-root-user: новый пользователь, с маппингом текущего пользователя в root
sudo unshare --mount --uts --ipc --net --pid --fork --user --map-root-user bash

# Внутри этой оболочки:
hostname new-host # меняем имя хоста, снаружи оно не изменится
[`ps -ef`](../Diagnostics/Processes/ps.md) # видим только процесс bash и ps
```

### Вход в существующее пространство имён с `nsenter`

Утилита `nsenter` позволяет "войти" в одно или несколько пространств имён уже существующего процесса. Это чрезвычайно мощный инструмент для отладки контейнеров и изолированных процессов.

Для работы `nsenter` нужно указать PID целевого процесса, чьи пространства имён мы хотим использовать.

**Параметры:**

* `-t, --target <pid>`: PID целевого процесса.
* `-m, --mount[=<file>]`: Войти в пространство имён монтирования.
* `-u, --uts[=<file>]`: Войти в пространство имён UTS (имя хоста).
* `-i, --ipc[=<file>]`: Войти в пространство имён IPC.
* `-n, --net[=<file>]`: Войти в пространство имён сети.
* `-p, --pid[=<file>]`: Войти в пространство имён PID.
* `-U, --user[=<file>]`: Войти в пространство имён пользователя.

**Пример: Отладка Docker-контейнера**

Допустим, у нас запущен Docker-контейнер. Мы можем войти в его сетевое пространство имён, чтобы посмотреть его сетевые интерфейсы или прослушиваемые порты "изнутри".

```bash
# 1. Находим PID одного из процессов внутри контейнера
docker inspect <container_id> | grep Pid

# 2. Входим в сетевое пространство имён этого процесса
sudo nsenter -t <PID> -n ip addr
# Эта команда покажет сетевые интерфейсы так, как их "видит" контейнер.
```

### Инструменты для инспекции пространств имён

#### `lsns`: Список пространств имён

`lsns` (list namespaces) — это инструмент, позволяющий быстро посмотреть, какие процессы "сидят" в каких пространствах имён. Он незаменим для отладки систем с контейнерами, `systemd`-изоляторами или другими изолированными процессами.

Простейший запуск:

```bash
lsns
```

На выходе будет таблица: PID, тип namespace, время создания и другая информация. Это помогает понять, например, кто держит лишний mount namespace или почему сетевой стек не совпадает с основным.

**Фильтрация по типу:**

Можно фильтровать вывод `lsns` по конкретному типу пространства имён с помощью опции `-t`:

* **Все сетевые namespace:**

    ```bash
    lsns -t net
    ```

    Это полезно для диагностики сетевых настроек контейнеров.

* **Все PID namespace:**

    ```bash
    lsns -t pid
    ```

    Позволяет узнать, кто является владельцем конкретного PID namespace.
