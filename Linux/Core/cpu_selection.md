# Выбор конфигурации CPU: Однопроцессорные vs Многопроцессорные системы

## Определения

* **Однопроцессорная система (Single-socket)** — сервер с одним физическим процессором (одно гнездо CPU). Обеспечивает минимальную латентность за счет отсутствия межузловых взаимодействий.
* **Многопроцессорная система (Multi-socket)** — сервер с двумя и более физическими процессорами на одной материнской плате. Позволяет масштабировать количество ядер и объем памяти, но вносит сложность в виде архитектуры NUMA.
* **Гнездо CPU (Socket)** — физический разъем на материнской плате для установки процессора.

## Основные концепции

### Сравнение конфигураций

| Характеристика | Однопроцессорная система | Многопроцессорная система |
| :--- | :--- | :--- |
| **Стоимость** | Ниже (один CPU, меньше модулей RAM) | Выше (больше CPU, сложнее матплата) |
| **Латентность памяти** | Минимальная (прямой доступ) | Повышенная (влияние NUMA) |
| **Масштабируемость RAM** | Ограничена одним контроллером | Высокая (несколько контроллеров) |
| **Отказоустойчивость** | Одна точка отказа | Возможна работа при сбое одного CPU |
| **Лицензирование ПО** | Экономичнее (часто по сокетам) | Дороже (больше сокетов) |
| **Привязка к CPU** | Простая (единое пространство ядер) | Требует учета NUMA-топологии |

### Архитектурные особенности многопроцессорных систем

В системах с несколькими сокетами каждый процессор имеет собственный контроллер памяти. Доступ к «локальной» памяти (своего NUMA-узла) происходит быстро (~100 нс), а доступ к памяти «соседнего» процессора (через шину QPI/UPI/Infinity Fabric) создает задержки (~150–200 нс).

Для минимизации этого эффекта используются:

* **NUMA-aware планирование**: запуск процессов строго в рамках одного узла (`numactl`, `taskset`).
* **Режим Interleave**: равномерное распределение памяти по всем узлам (снижает пиковую скорость, но убирает резкие перекосы латентности).

## Практические сценарии

### Когда выбирать один процессор

* **Базы данных с высокой нагрузкой** (PostgreSQL, MySQL, Redis) — критична низкая задержка доступа к памяти.
* **Виртуализация с высокой плотностью** — упрощает распределение ресурсов без учета NUMA.
* **Узлы Kubernetes** — обеспечивает предсказуемую производительность для контейнеров.
* **Приложения, чувствительные к латентности** (HFT, real-time системы).

### Когда выбирать несколько процессоров

* **Параллельные вычисления** — рендеринг, компиляция кода, научные расчеты.
* **Экстремальные объемы RAM** — когда требуется больше памяти, чем может адресовать один процессор (например, In-memory БД больших объемов).
* **Batch-обработка данных** — важна общая пропускная способность, а не латентность отдельных запросов.

### Поиск и устранение неисправностей

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Падение производительности в Multi-socket | Миграция процесса между NUMA-узлами | Привязка через `numactl --cpunodebind` |
| Неравномерный износ ядер | Планировщик использует только первые ядра | Включить `irqbalance` или настроить affinity |
| Ошибка памяти при загрузке | Несовместимость модулей в разных каналах | Проверить схему установки RAM в руководстве к матплате |
