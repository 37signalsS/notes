# Выбор конфигурации CPU: Однопроцессорные vs Многопроцессорные системы

## Определения

* **Однопроцессорная система (Single-socket, 1P)** — сервер с одним физическим разъемом (гнездом) для установки CPU. Современные 1P-системы (например, на базе AMD EPYC «Turin» или Intel Xeon 6) предлагают до 192–288 ядер, становясь стандартом для большинства корпоративных задач.
* **Многопроцессорная система (Multi-socket, 2P/4P/8P)** — сервер с двумя и более физическими процессорами на одной материнской плате. Используется для задач, требующих экстремального объема оперативной памяти или максимального количества линий PCIe.
* **NUMA (Non-Uniform Memory Access)** — архитектура памяти, при которой время доступа к данным зависит от расположения процессора относительно модуля RAM. В современных CPU на базе чиплетов (CCD/Tiles) эффекты NUMA возникают даже **внутри одного сокета**.

## Основные концепции

### Сдвиг парадигмы (2024–2026)

Исторически двухсокетные системы (2P) были необходимы для преодоления лимитов по количеству ядер. В 2024–2026 годах ситуация изменилась:
- **Рост плотности ядер:** Один сокет AMD Zen 5 (192 ядра) или Intel Granite Rapids (128 P-ядер) превосходит 2P-системы предыдущих поколений по вычислительной мощности.
- **Внутренняя фрагментация:** Использование чиплетов привело к появлению «скрытых» NUMA-узлов внутри одного процессора. Это требует настройки **NPS (Nodes Per Socket)** в BIOS для корректной работы планировщика ОС.
- **CXL (Compute Express Link):** Технология CXL 2.0/3.0 позволяет расширять объем RAM и пулить её между серверами, устраняя одну из главных причин покупки 2P-серверов — нехватку слотов DIMM для памяти.

### Сравнение конфигураций

| Характеристика | Однопроцессорная (1P) | Многопроцессорная (2P+) |
| :--- | :--- | :--- |
| **TCO (Затраты)** | Минимальные (проще матплата, меньше RAM) | Высокие (сложная разводка, больше CPU) |
| **Латентность** | Низкая (отсутствие межузловых QPI/UPI) | Повышенная (переходы между сокетами) |
| **Лицензирование** | Выгодное (лицензии «на сокет») | Дорогое (требуется больше лицензий) |
| **NUMA-топология** | Упрощенная (NPS1/NPS4 внутри сокета) | Сложная (множество внешних узлов) |
| **Масштабируемость** | Ограничена лимитами одного CPU | Экстремальная (для In-memory БД) |

### Режимы NPS (Nodes Per Socket)

Для высокоядерных процессоров (64+ ядер) критически важна настройка топологии в BIOS:
- **NPS1:** Весь процессор представлен как один NUMA-узел. Максимальная пропускная способность, но выше средняя задержка.
- **NPS4:** Процессор логически делится на 4 узла. Минимальная задержка при правильной привязке процессов (pinning) к локальной памяти чиплетов.

## Практические сценарии

### Когда выбирать один процессор (1P)

*   **Виртуализация высокой плотности:** Современные CPU позволяют разместить сотни ВМ на одном узле без накладных расходов на межсокетное взаимодействие.
*   **Базы данных (PostgreSQL, Redis):** Один мощный CPU обеспечивает предсказуемое время доступа к памяти, что критично для OLTP-нагрузок.
*   **Узлы Kubernetes:** 1P-конфигурация устраняет сложность распределения ресурсов по NUMA-узлам для планировщика K8s, повышая стабильность задержек.
*   **Экономия на ПО:** Если лицензия (например, Oracle или VMware) привязана к количеству физических сокетов.

### Когда выбирать несколько процессоров (2P+)

*   **Экстремальный объем RAM:** Когда требуется более 4–6 ТБ оперативной памяти на один сервер (хотя CXL начинает закрывать эту нишу).
*   **GPU-фермы и ИИ:** Для задач обучения моделей, где требуется 80+ линий PCIe Gen5 для подключения нескольких ускорителей NVIDIA H100/H200.
*   **HPC (Научные расчеты):** Задачи с массивным параллелизмом, которые могут эффективно использовать сотни ядер в общей памяти.

### Поиск и устранение неисправностей

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| **Дисбаланс памяти** | Модули RAM установлены неравномерно по каналам. | Проверьте схему заполнения DIMM в мануале (обычно 12 или 16 каналов). |
| **Штраф NUMA на 1P** | Процессор работает в режиме NPS4 без учета топологии ОС. | Настройте NPS1 в BIOS или используйте `numactl` для привязки. |
| **Падение пропускной способности UPI** | Высокая нагрузка на межпроцессорную шину в 2P. | Оптимизируйте размещение данных так, чтобы процессы работали со «своей» памятью. |
