# CPU Selection: Single vs Multi-Socket

## Определения

**Single-socket** — система с одним физическим процессором (одно CPU-гнездо). **Multi-socket** — система с несколькими процессорами на одной материнской плате. Выбор конфигурации влияет на латентность памяти, масштабируемость, отказоустойчивость и стоимость эксплуатации.

## Основные концепции

### Сравнение конфигураций

| Аспект | **Один CPU (больше ядер)** | **Несколько CPU (меньше ядер каждый)** |
| :--- | :--- | :--- |
| **Стоимость** | Дешевле (1 сокет, меньше RAM-модулей) | Дороже (больше сокетов, больше RAM-слотов) |
| **Латентность памяти** | Ниже (единый контроллер памяти, нет NUMA) | Выше (NUMA, доступ к «чужой» памяти медленнее) |
| **Масштабируемость RAM** | Ограничена 1 каналом/контроллером | Выше (больше контроллеров и каналов памяти) |
| **Отказоустойчивость** | Одна точка отказа | При сбое одного CPU система может выжить |
| **Лицензирование ПО** | Дешевле (лицензии часто по сокетам) | Дороже (больше сокетов = больше лицензий) |
| **Производительность** | Лучше для латентно-чувствительных нагрузок | Лучше для пропускной способности (memory bandwidth) |
| **CPU pinning** | Проще (нет NUMA-нод) | Требует учёта NUMA-топологии |

### NUMA-эффект в многопроцессорных системах

В multi-socket системах каждый процессор имеет собственный контроллер памяти. Доступ к «своей» памяти (локальный NUMA-узел) занимает ~100 ns, к «чужой» (через шину QPI/UPI) — ~150–200 ns.

**Решение:** NUMA-aware scheduling (`numactl`, `taskset`) или `interleave` mode для равномерного распределения памяти.

## Практические сценарии

### Когда выбирать один CPU

- **Базы данных** (PostgreSQL, MySQL, Redis) — латентно-чувствительные нагрузки
- **Виртуализация** — проще управление, нет NUMA-эффектов
- **Kubernetes-ноды** — предсказуемая производительность
- **Latency-sensitive приложения** — минимальная задержка доступа к памяти

### Когда выбирать несколько CPU

- **Параллельные нагрузки** — рендеринг, компиляция, batch-обработка
- **Большой объём RAM** — когда требуется больше памяти, чем поддерживает один контроллер
- **Отказоустойчивость** — система может продолжить работу при сбое одного процессора
