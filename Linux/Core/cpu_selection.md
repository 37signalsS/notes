# Выбор конфигурации CPU: Однопроцессорные vs Многопроцессорные системы

## Определения

* **Однопроцессорная система (Single-socket, 1P)** — сервер с одним физическим разъемом (гнездом) для установки CPU. Современные 1P-платформы (например, на базе AMD EPYC «Turin» или Intel Xeon 6) предлагают до 192–288 ядер, становясь доминирующим стандартом для корпоративных задач.
* **Многопроцессорная система (Multi-socket, 2P/4P/8P)** — сервер с двумя и более физическими процессорами на одной материнской плате, объединенными скоростными шинами (UPI, Infinity Fabric).
* **NUMA (Non-Uniform Memory Access)** — архитектура, при которой время доступа к оперативной памяти зависит от её физического расположения относительно ядер CPU. В современных чиплетных процессорах эффекты NUMA возникают даже **внутри одного сокета**.
* **CXL (Compute Express Link)** — открытый стандарт интерконнекта, позволяющий расширять объем и пропускную способность памяти через шину PCIe, размывая традиционные границы между 1P и 2P системами.

## Основные концепции

### Сдвиг парадигмы (2024–2026)

Исторически двухсокетные системы (2P) были необходимы для преодоления лимитов по количеству ядер и объему RAM. В современных реалиях ситуация изменилась:

1.  **Плотность ядер и кэша:** Один современный CPU превосходит 2P-системы трехлетней давности. L3 кэш теперь часто разделен между группами ядер (CCD/Tiles), что превращает каждый чиплет в отдельный NUMA-узел внутри одного сокета.
2.  **Пропускная способность памяти:** Современные 1P-системы поддерживают до 12 каналов DDR5, обеспечивая ПСП свыше 400 ГБ/с, что достаточно для подавляющего большинства нагрузок.
3.  **CXL 3.0:** Позволяет подключать внешние пулы памяти. Это устраняет главный недостаток 1P — ограничение по количеству слотов DIMM на материнской плате.

### Сравнение характеристик

| Характеристика | Однопроцессорная (1P) | Многопроцессорная (2P+) |
| :--- | :--- | :--- |
| **Латентность памяти** | Минимальная (локальная) | Высокая (при обращении к памяти соседа) |
| **Межпроцессорная шина** | Отсутствует (нет UPI/QPI оверхеда) | Узкое место при интенсивном обмене данными |
| **Лицензирование** | Выгодное (на сокет/ядро) | Дорогое (умножается на кол-во сокетов) |
| **Энергоэффективность** | Высокая (Perf/Watt выше) | Ниже (оверхед на питание шин связи) |
| **Сложность настройки** | Низкая | Высокая (требует строгого NUMA-выравнивания) |

### Топология и режимы NPS (Nodes Per Socket)

Для процессоров с большим количеством ядер (64+) критически важна настройка **NPS** в BIOS:

- **NPS1 (Unified):** Весь сокет виден ОС как одна NUMA-нода. Подходит для задач, не умеющих работать с NUMA, но дает более высокую среднюю задержку.
- **NPS4 (Partitioned):** Сокет делится на 4 логических узла. Обеспечивает минимальную латентность при условии, что приложение привязано к ядрам и памяти внутри одного узла.
- **L3-as-NUMA:** В ядрах 6.x+ планировщик может трактовать каждый сегмент L3 кэша как границу NUMA, что критично для EEVDF-планировщика при распределении потоков.

## Практические сценарии

### Когда выбирать один процессор (1P)

*   **Микросервисы и Kubernetes:** 1P-узлы упрощают работу `Topology Manager`, исключая ситуации, когда CPU выделен на одной ноде, а память или GPU — на другой.
*   **Высокочастотный трейдинг и Low-latency:** Отсутствие переходов через межпроцессорную шину гарантирует предсказуемое время отклика.
*   **Базы данных (PostgreSQL, MySQL, Redis):** Для OLTP-нагрузок критична латентность доступа к памяти, а не её суммарный объем. Один мощный CPU с 12 каналами памяти — оптимальный выбор.
*   **Экономия TCO:** Матплаты для 1P проще в разводке и дешевле. Требуется меньше модулей RAM для заполнения всех каналов (актуально для DDR5).

### Когда выбирать несколько процессоров (2P+)

*   **In-Memory базы данных (SAP HANA, большие инстансы Memcached):** Когда требуется 8 ТБ+ оперативной памяти в одном адресном пространстве без использования CXL.
*   **Тяжелый AI-инференс без GPU:** Если задача требует огромного объема RAM для весов моделей, который не помещается в видеопамять.
*   **GPU-станции:** Для обеспечения 128+ линий PCIe Gen5 для подключения 8+ ускорителей (H100/B200) в режиме прямого доступа (P2P).

## Технические нюансы

### Ограничения TDP и охлаждения

Современные 1P-процессоры достигают TDP 400–500 Вт. 
- В 1P-конфигурации вся тепловая нагрузка сосредоточена в одной точке, что требует агрессивного воздушного или жидкостного охлаждения.
- В 2P-системах тепло распределено по двум зонам, что может быть проще для стандартных серверных шасси 1U/2U.

### Пропускная способность UPI/Infinity Fabric

В 2P-системах до 25-30% пропускной способности внутренних шин процессора может тратиться на поддержание когерентности кэшей между сокетами. Если ваше приложение активно обменивается данными между потоками, 1P-система с большим количеством ядер всегда будет быстрее 2P-системы с тем же суммарным числом ядер.

## Дополнительная информация

### Поиск и устранение неисправностей

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Низкая ПСП памяти** | Не все каналы памяти заполнены. | Убедитесь, что установлено 12 (AMD) или 8 (Intel) модулей RAM на сокет. |
| **Remote Node Access** | Процесс в 2P читает память соседа. | Используйте `numactl --membind` или включите `auto_numa_balancing`. |
| **Троттлинг на 1P** | Перегрев VRM или процессора. | Проверьте `sensors` и лимиты мощности в IPMI/BIOS. |
