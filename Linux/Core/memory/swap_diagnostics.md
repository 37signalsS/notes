# Диагностика Swap и Page Faults в Linux

## Определения

* **Page Fault (ошибка страницы)** — исключение, генерируемое устройством управления памятью (MMU — Memory Management Unit) при обращении процесса к виртуальной странице, которая в данный момент отсутствует в физической оперативной памяти (RAM — Random Access Memory). Подробнее: [Виртуальная и физическая память](./virtual_vs_physical_memory.md).
* **Minor fault (мягкий отказ)** — ситуация, когда страница уже находится в оперативной памяти (например, разделяемая библиотека), но еще не сопоставлена с таблицей страниц процесса. Обрабатывается быстро, без операций ввода-вывода.
* **Major fault (жёсткий отказ)** — ситуация, когда страница отсутствует в оперативной памяти и должна быть загружена с диска (из пространства подкачки или файлового кэша). Вызывает значительные задержки из-за дискового ввода-вывода (I/O — Input/Output).
* **Swap-in (si)** — чтение данных из пространства подкачки обратно в оперативную память.
* **Swap-out (so)** — выгрузка данных из оперативной памяти в пространство подкачки.

## Основные концепции

### Причины активности Swap при свободной памяти

Ядро Linux может проактивно выгружать редко используемые страницы в swap, чтобы высвободить оперативную память для дискового кэша (page cache). Это является штатным поведением: кэширование файлов ускоряет операции чтения, в то время как неактивные данные процессов сохраняются на диске.

**Проблема возникает, когда:** процессы начинают активно обращаться к ранее выгруженным страницам → возникают массовые **major page faults** → система тратит ресурсы на чтение с диска → возникают видимые задержки ("фризы").

### Взаимосвязь Swap и давления на память

Высокая активность операций подкачки является первичным симптомом дефицита оперативной памяти. Ключевые индикаторы:

| Метрика | Нормальное состояние | Признак проблемы |
| :--- | :--- | :--- |
| `si` / `so` (vmstat) | Близки к 0 | Стабильно ненулевые значения = активный свопинг. |
| `pswpin` / `pswpout` | Стабильные значения | Постоянный рост счетчиков = непрерывный ввод-вывод в swap. |
| `wa` (iowait) | < 5% | Рост одновременно с `si`/`so` = дисковые задержки из-за подкачки. |
| Нагрузка `kswapd` | Близка к 0% | Высокое потребление CPU (Central Processing Unit — центральный процессор) = ядро занято агрессивным высвобождением памяти. |

### Влияние "грязных" страниц (Dirty Pages)

`Dirty` страницы — это измененные данные в оперативной памяти, которые еще не были синхронизированы с диском. Чрезмерный рост этого показателя без своевременного сброса может вызывать внезапные всплески ввода-вывода (I/O spikes). Настройка параметров: **[Оптимизация памяти](./performance_tuning.md)**.

## Практические сценарии

### Алгоритм диагностики при задержках системы

**Симптом:** Сервер медленно реагирует на запросы, хотя утилита `free` показывает наличие свободной памяти.

#### 1. Проверка активных устройств подкачки

```bash
swapon --show
```

Команда отобразит список всех swap-разделов и файлов, их объем и процент использования.

#### 2. Мониторинг активности в реальном времени

```bash
vmstat 1
```

**Анализ ключевых колонок:**

* `si` (swap-in) — чтение из swap. Если значения растут, значит, процессы пытаются работать с данными, вытесненными на диск.
* `so` (swap-out) — запись в swap. Рост указывает на то, что ядро пытается освободить оперативную память.

**Интерпретация данных:**

* `si`/`so` = 0 → система работает стабильно в рамках оперативной памяти.
* Высокий `wa` (iowait) при активном `si`/`so` → подтверждает, что медлительность вызвана низкой скоростью диска при работе с подкачкой.

Подробное описание утилиты: **[vmstat](../../Diagnostics/Memory/vmstat.md)**.

#### 3. Анализ общего объема через meminfo

```bash
cat /proc/meminfo | grep Swap
```

Позволяет увидеть показатели `SwapTotal`, `SwapFree` и `SwapCached`. Подробнее: **[proc_meminfo](../../Diagnostics/Memory/proc_meminfo.md)**.

#### 4. Проверка системных счетчиков страниц

```bash
cat /proc/vmstat | grep -E 'pswpin|pswpout'
```

* `pswpout` — общее количество страниц, выгруженных в swap с момента загрузки.
* `pswpin` — количество страниц, возвращенных в оперативную память.

#### 5. Оценка давления на зоны памяти

```bash
cat /proc/zoneinfo | less
```

Значения `nr_free_pages` и `low` указывают, насколько близки зоны (DMA, Normal) к критическому порогу, при котором запускается принудительное освобождение памяти. Подробнее: **[кэширование и освобождение памяти](caching_and_reclaiming.md)**.

#### 6. Мониторинг демона kswapd

```bash
# Просмотр нагрузки на CPU от процесса kswapd
pidstat -t -p $(pgrep -d, kswapd0) 1
```

Высокое потребление ресурсов центрального процессора этим демоном означает, что ядро находится в состоянии "борьбы" за свободную память.

#### 7. Проверка лимитов cgroups (контейнеры и виртуализация)

```bash
cat /sys/fs/cgroup/memory/<cgroup>/memory.stat
```

Позволяет увидеть `total_rss` (RSS — Resident Set Size, объем физической памяти, занимаемый процессом) и `total_swap` для конкретной группы процессов. Подробнее: **[cgroups](../cgroups.md)**.

### Диагностика Page Faults (ошибок страниц)

Ошибки страниц могут замедлять работу приложения даже при низкой общей загрузке системы, так как время тратится на ожидание диска (особенно при **major faults**).

#### Инструментарий для анализа

* **vmstat** — дает общую картину по системе.
* **pidstat -r** — детализация ошибок страниц по конкретным процессам:

  ```bash
  pidstat -r 1
  ```

  Здесь `minflt/s` показывает мягкие отказы, а `majflt/s` — жесткие (с обращением к диску).
* **perf stat** — точный подсчет для команды или процесса:

  ```bash
  perf stat -e page-faults,minor-faults,major-faults <команда>
  ```

* **pmap -x <PID>** — детальная карта распределения памяти процесса.

#### Интерпретация паттернов

| Паттерн | Диагноз | Рекомендуемое действие |
| :--- | :--- | :--- |
| Высокие `minflt/s`, низкие `majflt/s` | Активная работа с памятью без дефицита RAM. | Вмешательство не требуется. |
| Высокие `majflt/s` + рост `si`/`so` | Критическая нехватка оперативной памяти. | Увеличить объем RAM или оптимизировать потребление. |
| Высокие `majflt/s` без `si`/`so` | Интенсивная работа с mmap-файлами или файловым кэшем. | Проверить логику доступа к файлам. |

## Дополнительная информация

### Выбор инструментария

Для оперативной оценки состояния используйте **[vmstat](../../Diagnostics/Memory/vmstat.md)**. Если необходимо подтвердить постоянную нагрузку на диск со стороны подкачки — анализируйте счетчики `/proc/vmstat`. Поиск конкретного процесса-виновника эффективнее всего выполнять через **[pidstat](../../Diagnostics/Processes/pidstat.md)**. Для глубокого анализа распределения памяти внутри процесса используйте **[pmap](../../Diagnostics/Memory/pmap.md)**. В контейнерных средах основным источником данных являются показатели **cgroups**.
