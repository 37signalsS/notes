# Кэширование и освобождение памяти в Linux

## Определения

* **Page Cache** (Страничный кэш): Область оперативной памяти (RAM), хранящая данные файлов, прочитанных с диска. Позволяет избежать повторных медленных операций ввода-вывода.
* **Buffer Cache** (Буферный кэш): Кэш метаданных файловой системы (суперблоки, дескрипторы групп, индексы). В современных ядрах интегрирован с Page Cache, но управляется отдельно.
* **Page Reclaim** (Освобождение страниц): Процесс вытеснения страниц из памяти для удовлетворения новых запросов на аллокацию.
* **kswapd**: Фоновый поток ядра, который выполняет освобождение памяти при достижении определенных порогов (водяных знаков).
* **Direct Reclaim** (Прямое освобождение): Режим, в котором процесс, запросивший память, сам вынужден заниматься ее освобождением, так как фоновый поток не справляется. Вызывает задержки (stalls).
* **Memory Watermarks** (Водяные знаки): Пороги свободной памяти (`min`, `low`, `high`), определяющие поведение подсистемы управления памятью.
* **LRU (Least Recently Used)**: Классический алгоритм выбора страниц для вытеснения на основе времени последнего обращения.
* **MGLRU (Multi-Gen LRU)**: Современный (с ядра 6.1) многопоколенный алгоритм LRU, значительно более эффективный на нагруженных системах.
* **Refault**: Ситуация, когда страница была вытеснена, но вскоре потребовалась снова. Указывает на слишком агрессивное вытеснение (thrashing).

## Основные концепции

### Экономика памяти в Linux

Ядро Linux следует принципу: **"Свободная память — это потраченная впустую память"**. Поэтому оно стремится занять всю доступную RAM страничным кэшем. 
Важно различать:
- **`free`**: Память, которая вообще не используется.
- **`available`**: Память, которая может быть мгновенно освобождена для приложений без ухода в swap (включает кэши за вычетом необходимых резервов).

### Алгоритмы выбора кандидатов (Reclaim Algorithms)

#### 1. Классический LRU (Active/Inactive Lists)
Ядро поддерживает два списка для каждой зоны памяти:
* **Active List**: "Горячие" страницы.
* **Inactive List**: Кандидаты на вытеснение.
Если к странице в Inactive списке обращаются, она переходит в Active. Если Active список переполняется, страницы перемещаются в Inactive.

#### 2. MGLRU (Multi-Gen LRU)
Вместо двух списков используется набор "поколений" (generations). Это позволяет ядру:
- Тратить меньше ресурсов CPU на сканирование памяти.
- Точнее определять, какие страницы действительно не нужны.
- Эффективнее работать в условиях Memory Pressure.

### Механизмы освобождения памяти

Освобождение памяти запускается, когда количество свободных страниц падает ниже водяных знаков.

1. **Фоновое освобождение (kswapd)**:
   - Начинается при `free < low`.
   - Просыпается `kswapd` и плавно вытесняет страницы в фоновом режиме.
   - Засыпает, когда `free >= high`.
   
2. **Прямое освобождение (Direct Reclaim)**:
   - Начинается при `free < min`.
   - Процесс блокируется и сам ищет свободные страницы. Это вызывает "фризы" системы.

### Водяные знаки памяти (Memory Watermarks)

Значения рассчитываются ядром автоматически на основе общего объема памяти и параметров `sysctl`.

| Watermark | Описание |
| :--- | :--- |
| **`min`** | Резерв для атомарных аллокаций ядра. Ниже этого порога аллокации для процессов запрещены. |
| **`low`** | Порог активации `kswapd`. |
| **`high`** | Порог остановки `kswapd`. |

### Механизм Watermark Boosting
При обнаружении фрагментации или резких всплесков аллокаций ядро может временно "поднять" водяные знаки (`boost`), чтобы заставить `kswapd` работать агрессивнее и подготовить больше свободных страниц заранее.

## Практические сценарии

### Анализ состояния через /proc/zoneinfo

```bash
cat /proc/zoneinfo | grep -A 5 "Node"
# → pages free     12345
# →        min      1000
# →        low      1250
# →        high     1500
```
Если `free` стабильно держится между `min` и `low`, система находится под давлением и постоянно выполняет очистку.

### Тюнинг параметров водяных знаков

1. **`vm.min_free_kbytes`**: Устанавливает значение `min`.
   - Увеличение помогает против внезапных всплесков (например, при работе с сетью).
   - Слишком большое значение может привести к преждевременному вызову OOM Killer.
   
2. **`vm.watermark_scale_factor`**: Управляет зазором между `min`, `low` и `high`.
   - Значение по умолчанию — 10 (0.1% от памяти).
   - Увеличение (до 100-500) позволяет `kswapd` просыпаться раньше, снижая риск входа в Direct Reclaim на системах с быстрым вводом-выводом.

3. **`vm.watermark_boost_factor`**: Управляет агрессивностью временного повышения водяных знаков. При значении 0 — механизм отключен.

### Диагностика эффективности через PSI

Используйте метрики PSI (Pressure Stall Information), чтобы понять, страдает ли производительность от процесса очистки.
```bash
cat /proc/pressure/memory
# → some avg10=2.45 avg60=1.50 avg300=1.10 total=...
# → full avg10=0.50 avg60=0.20 avg300=0.10 total=...
```
Рост `some` указывает на то, что задачи ждут освобождения памяти. Рост `full` — на критический дефицит, блокирующий всю систему. Подробнее: **[Pressure Stall Information (PSI)](../kernel/psi.md)**.

### Оценка Refaults через vmstat

```bash
vmstat -s | grep -i refault
# → workingset_refault_anon: ...
# → workingset_refault_file: ...
```
Высокая скорость роста этих счетчиков означает, что ядро вытесняет страницы, которые через мгновение нужны снова (Thrashing).

## Дополнительная информация

### Связь со Slab и Swap

* **SReclaimable**: Часть Slab-аллокатора, которая может быть очищена (inode/dentry кэш). Очисткой занимаются "шринкеры" (shrinkers). Подробнее: **[Slab Allocator](./slab_allocator.md)**.
* **Swap**: Если кэш файлов уже очищен, а памяти все еще не хватает, ядро начинает вытеснять анонимные страницы в Swap. Подробнее: **[Управление Swap](./swap_management.md)**.

### Влияние vm.vfs_cache_pressure

Параметр определяет приоритет очистки метаданных ФС (Slab) относительно страничного кэша. 
* Значение `100` — баланс. 
* Выше `100` — более агрессивная очистка метаданных (экономит память, но замедляет работу с ФС).

Подробнее о тюнинге всех параметров памяти: **[Оптимизация и тонкая настройка памяти](./performance_tuning.md)**.
