### 1. Определения

**Page Reclaim** — это процесс, при котором ядро Linux освобождает страницы памяти, вытесняя давно неиспользуемые данные, когда общее количество свободной памяти опускается ниже определенного порога.

**Dirty Page ("грязная" страница)** — это страница в оперативной памяти (RAM), содержимое которой было изменено, но эти изменения еще не были записаны на постоянное хранилище (диск).

**Writeback** — это фоновый процесс записи "грязных" страниц из кэша памяти на диск.

### 2. Основные концепции

#### Механизм Page Reclaim

Когда количество свободной памяти опускается ниже определенного порога, ядро активирует процесс `kswapd` для освобождения памяти.

1.  **Списки Active и Inactive:** Ядро делит страницы памяти на два списка:
    *   **Active list:** Страницы, к которым недавно были обращения.
    *   **Inactive list:** Страницы, которые давно не использовались и являются кандидатами на вытеснение.

2.  **Алгоритм работы `kswapd`:**
    *   Процесс сканирует в первую очередь `Inactive` список.
    *   Если страница **"чистая" (clean)** и ее данные совпадают с данными на диске (например, файловый кэш), она просто удаляется из памяти.
    *   Если страница **"грязная" (dirty)**, ее содержимое сначала должно быть записано на диск (в исходный файл или в [swap](./swap_management.md)). Только после этого страница освобождается.
    *   Ядро периодически "состаривает" страницы, перемещая их из `Active` в `Inactive` список, если к ним давно не было обращений.

#### "Грязные" страницы и Writeback

Для повышения производительности операций ввода-вывода ядро Linux не сразу записывает изменения на диск. Вместо этого оно помечает измененную страницу памяти как "грязную" и откладывает запись. Это позволяет группировать несколько небольших операций в одну более крупную и эффективную.

### 3. Практические сценарии

#### Тюнинг механизма Writeback

Поведение "грязных" страниц контролируется через параметры `sysctl` в `/proc/sys/vm/`:

-   `vm.dirty_background_ratio`: Процент системной памяти, который может быть заполнен "грязными" страницами, прежде чем фоновые процессы (`pdflush`/`kworker`) начнут их запись на диск.
-   `vm.dirty_ratio`: Абсолютный максимум "грязных" страниц в памяти. Когда этот порог достигнут, все новые операции записи **блокируются** до тех пор, пока часть "грязных" страниц не будет записана на диск. Это может вызывать "зависание" приложений.
-   `vm.dirty_expire_centisecs`: Максимальное время (в сотых долях секунды), которое страница может оставаться "грязной" перед принудительной записью.
-   `vm.dirty_writeback_centisecs`: Интервал, с которым `kworker` просыпается для проверки наличия "грязных" страниц, которые нужно записать.

### 4. Продвинутые детали

#### Режимы освобождения памяти

Существует два основных режима освобождения страниц:

1.  **Фоновое освобождение (Background Reclaim):**
    *   Выполняется процессом `kswapd`, когда количество свободных страниц падает ниже порога `pages_high`.
    *   `kswapd` пытается освободить память до тех пор, пока её количество не достигнет `pages_high`, работая в фоновом режиме и не блокируя пользовательские процессы.

2.  **Прямое освобождение (Direct Reclaim):**
    *   Происходит, когда процесс запрашивает память, а ее количество ниже минимального порога (`pages_min`).
    *   В этом случае процесс, запросивший память, **сам блокируется** и начинает синхронно освобождать страницы. Это может приводить к заметным задержкам в работе приложений.

Пороги (`watermarks`) настраиваются ядром автоматически, но их можно найти в `/proc/zoneinfo`. Понимание разницы между этими двумя режимами критически важно для диагностики проблем с производительностью, связанных с памятью. Активное прямое освобождение — явный признак серьезной нехватки RAM.
