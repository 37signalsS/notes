## Кэширование и освобождение памяти

### Механизм Page Reclaim

**Page Reclaim** — это процесс, при котором ядро Linux освобождает память, когда её становится недостаточно. Ядро пытается вытеснить из RAM страницы, которые давно не использовались.

**Как это работает:**

1.  **Списки Active и Inactive:** Ядро поддерживает два основных списка страниц памяти:
    *   **Active list:** Содержит страницы, к которым недавно были обращения.
    *   **Inactive list:** Содержит страницы, которые давно не использовались. Они являются кандидатами на вытеснение.

2.  **Процесс `kswapd`:** Когда количество свободной памяти опускается ниже определённого порога (`pages_low`), просыпается специальный процесс ядра `kswapd`. Его задача — сканировать страницы и освобождать память, пока её уровень не достигнет порога `pages_high`.

3.  **Алгоритм:**

    *   `kswapd` в первую очередь сканирует страницы из `Inactive` списка.
    *   Если страница "чистая" (clean), то есть её содержимое не было изменено и совпадает с данными на диске (например, это кэш файла), она просто удаляется из памяти.
    *   Если страница "грязная" (dirty), то есть была изменена (например, данные приложения), она сначала должна быть записана на диск (в swap или в исходный файл), и только потом её можно освободить.
    *   `kswapd` также периодически перемещает страницы из `Active` списка в `Inactive`, если к ним давно не было обращений, чтобы "состарить" их и сделать кандидатами на вытеснение.

### "Грязные" страницы (Dirty Pages) и Writeback

**Dirty Page** ("грязная" страница) — это страница в оперативной памяти (RAM), содержимое которой было изменено, но эти изменения еще не были записаны на постоянное хранилище (диск).

**Как это работает:**
Когда приложение записывает данные в файл, ядро Linux для повышения производительности не сразу сбрасывает их на диск. Вместо этого оно помечает соответствующую страницу памяти как "грязную" и откладывает запись. Это позволяет накапливать несколько операций записи и выполнять их более эффективно за один раз.

Процесс записи "грязных" страниц на диск называется **Writeback**.

**Управление через `sysctl`:**

Поведение этого механизма контролируется несколькими параметрами ядра в `/proc/sys/vm/`:

-   `vm.dirty_background_ratio`: Процент системной памяти, который может быть заполнен "грязными" страницами, прежде чем фоновые процессы ядра (`pdflush`/`kworker`) начнут их запись на диск.
-   `vm.dirty_ratio`: Максимальный процент системной памяти, который могут занимать "грязные" страницы. Когда этот порог достигнут, все новые операции ввода-вывода блокируются до тех пор, пока "грязные" страницы не будут записаны на диск. Это может вызывать "зависание" приложений, выполняющих запись.
-   `vm.dirty_expire_centisecs`: Максимальное время (в сотых долях секунды), в течение которого страница может оставаться "грязной" перед тем, как будет принудительно записана на диск.
-   `vm.dirty_writeback_centisecs`: Интервал, с которым просыпаются процессы ядра для проверки наличия "грязных" страниц, которые нужно записать.
