# Кэширование и освобождение памяти в Linux

## Определения

* **Page Reclaim**: Процесс освобождения [страниц памяти](./virtual_vs_physical_memory.md) ядром Linux путем вытеснения неиспользуемых данных при низком уровне свободной памяти.
* **Dirty Page ("грязная" страница)**: Страница в оперативной памяти (RAM), измененная, но не синхронизированная с постоянным хранилищем. Подробнее о записи грязных страниц и настройке dirty_* параметров см. в **[Оптимизации памяти](./performance_tuning.md)**.
* **Writeback**: Фоновый процесс записи "грязных" страниц из кэша памяти на диск.

## Основные концепции

### Механизм Page Reclaim

При снижении свободной памяти ниже `watermark` активируется `kswapd` для освобождения памяти.

* **Списки Active и Inactive**:
  * **Active list**: Недавно использованные страницы.
  * **Inactive list**: Давно неиспользуемые страницы, кандидаты на вытеснение.

* **Алгоритм работы `kswapd`**:
  * Сканирует `Inactive` список.
  * **"Чистые" страницы**: Удаляются из памяти (если совпадают с диском). В отличие от slab-кэшей (dentry, inode), которые освобождаются через [slab shrinker](./slab_allocator.md), page cache просто сбрасывается.
  * **"Грязные" страницы**: Записываются на диск (или в [swap](./swap_management.md)) перед освобождением.
  * Ядро перемещает старые страницы из `Active` в `Inactive` список.

### "Грязные" страницы и Writeback

Ядро откладывает запись изменений на диск, помечая страницы как "грязные", для оптимизации ввода-вывода.

## Практические сценарии

### Тюнинг механизма Writeback

Параметры dirty_* (`vm.dirty_background_ratio`, `vm.dirty_ratio`, `vm.dirty_expire_centisecs`, `vm.dirty_writeback_centisecs`) и рекомендации по настройке для различных workload подробно описаны в **[Оптимизации памяти](./performance_tuning.md)**.

## Дополнительная информация

### Режимы освобождения памяти

* **Фоновое освобождение (Background Reclaim)**:
  * Выполняется `kswapd` при падении свободной памяти ниже `pages_high`.
  * Работает в фоновом режиме, не блокируя пользовательские процессы.

* **Прямое освобождение (Direct Reclaim)**:
  * Происходит при запросе памяти, когда ее количество ниже `pages_min`.
  * Запрашивающий процесс блокируется и синхронно освобождает страницы, что может вызвать задержки.

Пороги (`watermarks`) находятся в `/proc/zoneinfo`. Активное прямое освобождение указывает на нехватку RAM. Детали метрик см. в [статистике памяти](../../Diagnostics/Memory/proc_meminfo.md).

### Водяные знаки памяти (Memory Watermarks)

Ядро Linux использует три уровня водяных знаков для управления памятью:

| Watermark | Описание |
| :--- | :--- |
| **WMARK_MIN** | Минимальный уровень. При достижении запускается прямое освобождение (direct reclaim) |
| **WMARK_LOW** | Порог для запуска фонового освобождения (kswapd) |
| **WMARK_HIGH** | Целевой уровень, до которого kswapd пытается освободить память |

Просмотр текущих значений:

```bash
cat /proc/zoneinfo | grep -E 'min|low|high'
```

**`vm.min_free_kbytes`** — параметр, контролирующий минимальный запас свободной памяти. Рекомендуется устанавливать в 2–3% от общего объёма RAM для серверов.
