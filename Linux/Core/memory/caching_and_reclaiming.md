# Кэширование и освобождение памяти

## Определения

* **Page Cache**: Системный кэш страниц в оперативной памяти (RAM), хранящий данные файлов с диска для ускорения повторного доступа.
* **Buffer Cache**: Кэш служебных структур (метаданных) файловой системы: суперблоки, таблицы inode, групповые дескрипторы.
* **Page Reclaim**: Процесс освобождения [страниц памяти](./virtual_vs_physical_memory.md) ядром Linux путем вытеснения неиспользуемых данных при нехватке свободного места.
* **kswapd**: Фоновый поток ядра, отвечающий за освобождение памяти. Активируется при достижении пороговых значений (watermarks).
* **Memory Watermarks (Водяные знаки)**: Пороговые значения свободной памяти (`min`, `low`, `high`), управляющие поведением подсистемы выделения памяти.
* **Active / Inactive Lists**: Списки страниц памяти, разделенные по частоте использования для определения кандидатов на вытеснение (алгоритм LRU — Least Recently Used).
* **Dirty Page (Грязная страница)**: Страница в RAM, содержимое которой было изменено приложением, но ещё не синхронизировано с диском.

## Основные концепции

### Принцип Linux: "Свободная память — потерянная память"

Ядро Linux стремится использовать всю доступную оперативную память под дисковый кэш. Это снижает количество дорогостоящих обращений к диску. Если приложению требуется память, ядро мгновенно освобождает нужный объем из кэша (reclaim). Таким образом, "мало свободной памяти" в Linux обычно не является признаком проблемы.

### Различия Page Cache и Buffer Cache

В современных ядрах Linux эти кэши интегрированы, но логически разделяются:

* **Page Cache**: Оперирует страницами данных файлов. Когда приложение читает файл, данные попадают сюда.
* **Buffer Cache**: Оперирует блоками диска и метаданными ФС. Необходим ядру для навигации по файловой системе.

Команда `free` объединяет их в столбце `buff/cache`.

### Механизм освобождения памяти (Page Reclaim)

Ядро управляет страницами памяти через два основных списка:

1. **Active List**: Страницы, к которым часто обращаются. Они защищены от немедленного вытеснения.
2. **Inactive List**: Кандидаты на вытеснение. Если к странице из этого списка обращаются, она перемещается в Active.

#### Режимы освобождения

* **Фоновое (Background Reclaim)**: Выполняется демоном `kswapd`. Начинается при достижении уровня `WMARK_LOW` и продолжается до `WMARK_HIGH`. Не блокирует работу приложений.
* **Прямое (Direct Reclaim)**: Происходит, когда свободная память падает ниже `WMARK_MIN`. Запрашивающий процесс приостанавливается и сам занимается освобождением памяти, что приводит к значительным задержкам (stalls).

### Понятие Available (Доступно)

Параметр `MemAvailable` — это оценка ядра, сколько памяти можно выделить новым процессам без ухода в swap.
Формула (упрощенно):
`available ≈ MemFree + (PageCache - min_reserve) + (ReclaimableSlab - min_reserve)`
Ядро оставляет небольшой резерв, который невозможно освободить без критического падения производительности.

### Водяные знаки памяти (Memory Watermarks)

Уровни контролируются для каждой зоны памяти (DMA, Normal и др.):

| Watermark | Поведение системы |
| :--- | :--- |
| **WMARK_MIN** | Критический порог. Запускается **Direct Reclaim**. Процессы "зависают" на аллокациях. |
| **WMARK_LOW** | Порог активации **`kswapd`** для фоновой очистки. |
| **WMARK_HIGH** | Целевой порог. `kswapd` засыпает, когда свободная память достигает этого уровня. |

## Практические сценарии

### Анализ состояния памяти через `free`

```bash
free -h
# Mem: 15Gi 1.2Gi 1.5Gi 200Mi 13Gi 14Gi
# ^            ^      ^      ^      ^      ^
# total      used   free  shared  buff/cache available
```

Если `available` значительно выше `free` — система работает нормально, используя память под кэш.

### Просмотр водяных знаков в реальном времени

Значения водяных знаков можно увидеть в файле `/proc/zoneinfo`:

```bash
cat /proc/zoneinfo | grep -E 'min|low|high|nr_free_pages'
```

Если `nr_free_pages` (текущая свободная память в страницах) приближается к `low` или `min`, следует ожидать роста нагрузки на CPU со стороны `kswapd` или задержек в приложениях.

### Настройка `vm.min_free_kbytes`

Этот параметр определяет уровень `WMARK_MIN`. Увеличение этого значения создает больший "запас" для внезапных всплесков аллокаций, предотвращая Direct Reclaim.

```bash
# Просмотр текущего значения (в КБ)
sysctl vm.min_free_kbytes

# Рекомендуемая настройка для высоконагруженных серверов (около 2-3% от RAM)
# Например, для 32 ГБ RAM:
sudo sysctl -w vm.min_free_kbytes=1048576
```

## Дополнительная информация

### Связь со Slab Allocator

Метаданные (inode/dentry) кэшируются в Slab. Они также участвуют в процессе освобождения памяти через механизм `slab shrinker`. Подробнее см. в **[Slab Allocator](./slab_allocator.md)**.

### Влияние на запись (Dirty Pages)

Настройка фоновой и синхронной записи "грязных" страниц на диск критически важна для предотвращения переполнения кэша. Подробные параметры `dirty_*` описаны в **[Оптимизации памяти](./performance_tuning.md)**.

### Диагностика через `/proc/meminfo`

Для детального анализа активных и неактивных списков, а также других метрик кэша, используйте **[Диагностику `/proc/meminfo`](../../Diagnostics/Memory/proc_meminfo.md)**.
