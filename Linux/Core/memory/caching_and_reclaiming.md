# Кэширование и освобождение памяти в Linux

## Определения

* **Page Reclaim**: Процесс освобождения [страниц памяти](./virtual_vs_physical_memory.md) ядром Linux путем вытеснения неиспользуемых данных при низком уровне свободной памяти.
* **Dirty Page ("грязная" страница)**: Страница в оперативной памяти (RAM), измененная, но не синхронизированная с постоянным хранилищем.
* **Writeback**: Фоновый процесс записи "грязных" страниц из кэша памяти на диск.

## Основные концепции

### Механизм Page Reclaim

При снижении свободной памяти ниже `watermark` активируется `kswapd` для освобождения памяти.

* **Списки Active и Inactive**:
  * **Active list**: Недавно использованные страницы.
  * **Inactive list**: Давно неиспользуемые страницы, кандидаты на вытеснение.

* **Алгоритм работы `kswapd`**:
  * Сканирует `Inactive` список.
  * **"Чистые" страницы**: Удаляются из памяти (если совпадают с диском).
  * **"Грязные" страницы**: Записываются на диск (или в [swap](./swap_management.md)) перед освобождением.
  * Ядро перемещает старые страницы из `Active` в `Inactive` список.

### "Грязные" страницы и Writeback

Ядро откладывает запись изменений на диск, помечая страницы как "грязные", для оптимизации ввода-вывода.

## Практические сценарии

### Тюнинг механизма Writeback

Поведение "грязных" страниц регулируется через `sysctl` параметры в `/proc/sys/vm/`:

* `vm.dirty_background_ratio`: Процент системной памяти для "грязных" страниц, после которого запускается фоновая запись.
* `vm.dirty_ratio`: Максимальный процент "грязных" страниц. При достижении этого порога новые операции записи блокируются.
* `vm.dirty_expire_centisecs`: Максимальное время (в сотых долях секунды) для "грязной" страницы до принудительной записи.
* `vm.dirty_writeback_centisecs`: Интервал пробуждения `kworker` для проверки "грязных" страниц.

## Дополнительная информация

### Режимы освобождения памяти

* **Фоновое освобождение (Background Reclaim)**:
  * Выполняется `kswapd` при падении свободной памяти ниже `pages_high`.
  * Работает в фоновом режиме, не блокируя пользовательские процессы.

* **Прямое освобождение (Direct Reclaim)**:
  * Происходит при запросе памяти, когда ее количество ниже `pages_min`.
  * Запрашивающий процесс блокируется и синхронно освобождает страницы, что может вызвать задержки.

Пороги (`watermarks`) находятся в `/proc/zoneinfo`. Активное прямое освобождение указывает на нехватке RAM. Детали метрик см. в [статистике памяти](../../Diagnostics/Memory/proc_meminfo.md).
