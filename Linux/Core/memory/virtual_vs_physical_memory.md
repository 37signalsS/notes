# Виртуальная и физическая память в Linux

## Определения

* **Физическая память (RAM)**: Аппаратный ресурс (модули оперативной памяти), доступный системе для хранения исполняемого кода и данных.
* **Виртуальная память**: Уровень абстракции, предоставляющий каждому процессу иллюзию владения непрерывным, изолированным адресным пространством, превышающим размер физической RAM.
* **MMU (Memory Management Unit)**: Аппаратный блок процессора, выполняющий преобразование виртуальных адресов в физические «на лету» при каждом обращении к памяти.
* **Страница (Page)**: Минимальный блок виртуальной памяти (стандарт — 4 КБ). Соответствующий блок в физической памяти называется **Frame** (кадр).
* **Таблицы страниц (Page Tables)**: Иерархические структуры данных в RAM, описывающие отображение виртуальных адресов на физические.
* **VMA (Virtual Memory Area)**: Структура данных в ядре, описывающая непрерывный диапазон виртуальных адресов с одинаковыми свойствами (права доступа, привязка к файлу).

## Основные концепции

### Иерархия таблиц страниц

В современных 64-битных системах x86_64 используется 4-уровневая (4-level paging) или 5-уровневая (5-level paging / LA57) иерархия таблиц:
* **4-level**: Позволяет адресовать до 128 ТБ (47 бит адреса).
* **5-level**: Расширяет адресное пространство до 64 ПБ (57 бит), что необходимо для серверов с экстремальным объемом RAM.

### Механизм трансляции и TLB

Каждое обращение к виртуальной памяти требует «прохода» по иерархии таблиц страниц (Page Table Walk), что слишком медленно.
* **TLB (Translation Lookaside Buffer)**: Аппаратный кэш внутри CPU, хранящий последние трансляции.
* **PCID / ASID**: Идентификаторы контекста процесса. Позволяют ядру не сбрасывать TLB при переключении контекста (Context Switch), что значительно повышает производительность в многозадачных средах.

### Безопасность и KPTI

**KPTI (Kernel Page Table Isolation)** — механизм защиты от уязвимости Meltdown.
Ядро поддерживает два набора таблиц страниц:
1. **Полный**: Используется только когда процессор находится в режиме ядра.
2. **Ограниченный**: Используется в пользовательском режиме (User Space), содержит только необходимый минимум адресов ядра.
*Плата за KPTI — накладные расходы на переключение таблиц при каждом системном вызове.*

### Жизненный цикл выделения памяти

Ядро использует ленивое выделение страниц (**Demand Paging**):

1. **malloc / mmap**: Ядро создает VMA в адресном пространстве процесса, но не выделяет физические кадры.
2. **Page Fault**: При попытке доступа к адресу возникает исключение.
   - **Minor Fault**: Страница уже в RAM (например, в Page Cache), ядро просто обновляет таблицу страниц.
   - **Major Fault**: Требуется чтение с диска (Swap или файл). Вызывает задержку процесса.
3. **Copy-on-Write (CoW)**: При `fork()` страницы памяти родителя и ребенка помечаются как `read-only`. Физическое копирование кадра происходит только в момент первой записи.

## Практические сценарии

### Проверка параметров трансляции

```bash
# Проверка размера стандартной страницы
getconf PAGESIZE # → 4096

# Проверка поддержки 5-уровневых таблиц страниц
grep la57 /proc/cpuinfo
```

### Анализ VMA процесса

```bash
# Посмотреть все области виртуальной памяти процесса
cat /proc/<PID>/maps

# Детальная статистика по использованию памяти в каждом сегменте
cat /proc/<PID>/smaps
```

### Диагностика задержек из-за Page Faults

Высокое количество **Major Faults** — индикатор дисковых задержек или нехватки RAM.

```bash
# Мониторинг Page Faults в реальном времени
sar -B 1 5
# → pgpgin/s (чтение страниц), fault/s (ошибки страниц), majflt/s (жесткие ошибки)
```
