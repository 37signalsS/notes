# Виртуальная и физическая память

## Определения

* **Физическая память (RAM)**: Аппаратные модули оперативной памяти (Random Access Memory), используемые процессором для хранения данных и выполнения машинного кода.
* **Виртуальная память**: Программная абстракция ядра Linux, предоставляющая каждому процессу собственное изолированное адресное пространство.
* **MMU (Memory Management Unit)**: Аппаратный блок процессора, выполняющий преобразование виртуальных адресов в физические.
* **Страница (Page)**: Минимальная единица управления памятью в Linux. Стандартный размер — 4 КБ.
* **Page Fault (Ошибка страницы)**: Событие, возникающее, когда процесс обращается к странице, которая в данный момент не отображена в физическую память.
* **Анонимные страницы (Anonymous Pages)**: Память, не связанная с файлами (стек, куча, данные `malloc`). При нехватке RAM выгружаются в [Swap](./swap_management.md).
* **File-backed страницы**: Память, отображённая на файлы (библиотеки, исполняемый код). Могут быть вытеснены из RAM и перечитаны с диска.

## Основные концепции

### Адресное пространство процесса

Каждый процесс видит память как непрерывный массив адресов, разделенный на логические сегменты:

```
  ┌─────────────────────┐  ← 0xFFFFFFFF... (kernel space)
  │   Ядро (kernel)     │  — Общее для всех процессов
  ├─────────────────────┤
  │       Стек          │  — Растёт вниз
  │       ↓             │
  │                     │
  │       ↑             │
  │       Куча (heap)   │  — Растёт вверх (malloc/brk/mmap)
  ├─────────────────────┤
  │  Сегмент данных     │  — Глобальные переменные
  ├─────────────────────┤
  │  Сегмент кода (.text)│ — Инструкции программы
  └─────────────────────┘  ← 0x0
```

### Механизм трансляции адресов

1. **Таблицы страниц (Page Tables)**: Иерархические структуры данных в RAM, где ядро хранит соответствия виртуальных страниц физическим кадрам.
2. **Трансляция**: MMU считывает таблицы страниц для преобразования адреса. Для ускорения используется **TLB (Translation Lookaside Buffer)** — кэш последних успешных трансляций.
3. **HugePages**: Использование страниц увеличенного размера (2 МБ или 1 ГБ) для снижения нагрузки на TLB и уменьшения размера таблиц страниц. Подробности см. в [Оптимизации памяти](./performance_tuning.md).

### Жизненный цикл выделения памяти

Ядро использует стратегию **Demand Paging** (выделение по требованию):

1. **Резервирование (Virtual Allocation)**: При вызове `malloc()` или `mmap()` ядро лишь резервирует диапазон виртуальных адресов. Физическая память не выделяется.
2. **Фактическое выделение**: При первом обращении к адресу возникает **Minor Page Fault**. Ядро находит свободный физический кадр, обнуляет его и записывает в таблицу страниц процесса.
3. **CoW (Copy-on-Write)**: При создании процесса через `fork()` родитель и ребенок используют общие физические страницы. Копирование страницы происходит только в момент попытки записи одним из процессов.

### Обратное давление (Memory Reclaim)

Когда свободная RAM заканчивается, ядро запускает механизм освобождения:

* Сначала удаляются "чистые" файловые страницы.
* "Грязные" страницы сбрасываются на диск.
* Анонимные страницы вытесняются в Swap.
* Ядро может освобождать кэши метаданных (см. [Slab Allocator](./slab_allocator.md)).

Детальное описание работы кэшей и механизмов очистки приведено в [Кэшировании и освобождении памяти](./caching_and_reclaiming.md).

## Практические сценарии

### Проверка размера страницы

Размер страницы в системе критичен для понимания фрагментации и настройки баз данных.

```bash
# Системный вызов для получения размера страницы
getconf PAGESIZE
# → 4096 (байты)
```

### Наблюдение за Page Faults

Анализ ошибок страниц позволяет выявить процессы, активно работающие с диском или интенсивно выделяющие память.

```bash
# Просмотр статистики для конкретного процесса
ps -o min_flt,maj_flt -p <PID>

# В реальном времени через sar (требует sysstat)
sar -B 1
```

* **Minor Faults**: Выделение новой памяти или доступ к уже загруженным библиотекам.
* **Major Faults**: Чтение данных с диска (Swap или файлы). Высокое значение указывает на I/O-latency.

### Анализ отображений процесса

```bash
# Просмотр сегментов памяти процесса
cat /proc/<PID>/maps
```

Показывает адреса, права доступа (rwx) и файлы, на которые отображена память.

## Дополнительная информация

### Memory Overcommit

Linux позволяет процессам резервировать больше виртуальной памяти, чем реально доступно в системе. Это безопасно, пока процессы не начинают активно использовать всю зарезервированную память. Настройка режимов Overcommit описана в [Оптимизации памяти](./performance_tuning.md).

### Метрики процесса (VSS, RSS, PSS)

Для понимания реального потребления памяти отдельным процессом используются специфические метрики:

* **VSS (Virtual Set Size)**: Весь объем виртуальной памяти.
* **RSS (Resident Set Size)**: Физическая память, занимаемая процессом.
* **PSS (Proportional Set Size)**: RSS с учетом разделяемых библиотек.

Подробное сравнение приведено в [Метриках потребления памяти процесса](./process_memory_metrics.md).
