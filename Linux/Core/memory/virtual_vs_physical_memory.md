## Физическая и виртуальная память

### 1. Определения

**Физическая память (RAM)** — это реальные аппаратные чипы на материнской плате, где процессор может непосредственно выполнять код и хранить данные.

**Виртуальная память** — это абстракция, создаваемая операционной системой, которая предоставляет каждому процессу его собственное изолированное адресное пространство. Процессы работают с виртуальными адресами, которые ядро и аппаратура (MMU) "на лету" преобразуют в физические.

### 2. Основные концепции

#### Механизм работы

И физическая, и виртуальная память делятся на небольшие блоки фиксированного размера, называемые **страницами** (pages).

1.  **Таблицы страниц (Page Tables):** Для каждого процесса ядро Linux ведет специальную карту — **таблицу страниц**. В ней для каждой виртуальной страницы процесса записано, где она находится на самом деле:
    *   В какой-то физической странице в ОЗУ.
    *   На жестком диске в **пространстве подкачки ([swap](./swap_management.md))**.
    *   Нигде (если память была запрошена, но еще не использовалась).

2.  **MMU (Memory Management Unit):** Это аппаратный блок в процессоре, который использует таблицы страниц для мгновенного преобразования виртуального адреса в физический при каждом обращении к памяти.

#### Ключевые преимущества

*   **Изоляция процессов:** Каждый процесс работает в своем собственном "пузыре" виртуальной памяти и не может повредить память другого процесса.
*   **Эффективное использование ОЗУ:** Общие библиотеки загружаются в физическую память только один раз, а их страницы отображаются в виртуальные адресные пространства всех процессов, которые их используют.
*   **Возможность использования памяти, превышающей ОЗУ:** Неактивные страницы памяти могут быть выгружены на диск в swap, освобождая RAM для более срочных задач.

#### Сравнение физической и виртуальной памяти

| Характеристика | Физическая память (RAM) | Виртуальная память |
| :--- | :--- | :--- |
| **Что это?** | Реальные аппаратные чипы. | Абстракция, создаваемая ОС. |
| **Скорость** | Очень высокая. | Значительно медленнее при доступе к данным на диске (swap). |
| **Размер** | Ограничен объемом установленных модулей ОЗУ. | Ограничен архитектурой процессора и размером диска. |
| **Доступ** | Прямой доступ имеет только ядро. | Процессы работают с виртуальными адресами. |

### 3. Практические сценарии

#### Проверка размера страницы

Размер страницы по умолчанию в большинстве систем — 4 КБ, но его можно проверить с помощью команды:
```bash
getconf PAGESIZE
# 4096
```
Знание размера страницы полезно при анализе производительности и работе с такими механизмами, как [HugePages](./performance_tuning.md#использование-hugepages).

### 4. Продвинутые детали

#### Чрезмерное выделение памяти (Memory Overcommit)

Linux часто использует механизм **"чрезмерного выделения" (overcommit)**, когда система *обещает* процессу больше виртуальной памяти, чем физически доступно в системе (RAM + swap). Это повышает эффективность использования ресурсов, так как программы часто резервируют память "про запас", но не используют её всю сразу.

Однако, если процессы действительно попытаются использовать всю выделенную им память, это может привести к ее нехватке и спровоцировать **[OOM Killer](./performance_tuning.md#риски-и-преимущества)**.

> Подробное описание режимов работы и тюнинга этого механизма находится в заметке **[Оптимизация и тонкая настройка памяти](./performance_tuning.md#управление-выделением-памяти-memory-overcommit)**.
