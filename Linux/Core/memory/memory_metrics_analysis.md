## Анализ метрик памяти (`/proc/meminfo`)

Когда вы смотрите на показатели памяти (например, в `top`, `free` или через `cat /proc/meminfo`), важно понимать, что именно они означают.

1. **Total** — Общий объём оперативной памяти (RAM), который распознаёт ядро Linux. Это не физический объем всей памяти, а объем, доступный системе после того, как ядро зарезервировало часть для своих нужд. То есть, это физический объем минус память, зарезервированная ядром. Эта метрика показывает, сколько памяти доступно для использования в пользовательском пространстве.
    
2. **Used** — Количество памяти, занимаемой процессами, включая их программный код.
    
3. **Free** — Память, которая прямо сейчас не задействована ни под процессы, ни под кэш. Важно понимать, что это не означает, что она полностью доступна для новых приложений; скорее, это память, которая системе "не нужна" в данный момент. Низкое значение `Free` не всегда является проблемой, так как Linux активно использует доступную память для кэширования. Ориентироваться только на этот столбец для оценки доступности памяти для новых приложений не рекомендуется.

4. **Shared** — Объем памяти, которая может быть разделена между несколькими процессами. Это используется для межпроцессного взаимодействия (IPC) и для загрузки общих библиотек. Вместо того чтобы загружать одну и ту же библиотеку в память для каждого процесса, она загружается один раз в разделяеемую память, и все процессы получают к ней доступ. Это позволяет эффективно использовать память.
    
5. **Buff/Cache**

    - **Buffers** — память, зарезервированная под буферизацию операций ввода-вывода (I/O). Сегодня это место, где данные компонуются в нужные фрагменты (например, для записи на диск блоками по 4 КБ, когда данные поступают меньшими частями). Это помогает оптимизировать операции записи.

    - **Cache** — память, используемая для кэширования файловых данных (page cache). Когда процессу требуется доступ к файлу с диска, система загружает его в кэш. При повторном чтении данные берутся из кэша, минуя медленный диск. Память организована в виде страниц (обычно по 4 КБ), и эта область, куда загружаются страницы файла, называется файловым кэшем. Также существует понятие "грязных страниц" (dirty pages) — это страницы в кэше, которые были изменены, но еще не записаны на диск. Ядро не выгружает кэшированные данные сразу после завершения процесса, так как их повторная загрузка с диска занимает больше времени, чем хранение в памяти "на всякий случай". Ядро предпочитает хранить данные в кэше, рассчитывая, что они могут понадобиться снова. Если приложению понадобится память, ядро автоматически «отдаст» часть кэша, так что buff/cache не означает «пропавшую» память. Если система хорошо нагружена и имеет большой объем кэша, это означает, что она эффективно использует доступную память.

6. **Available** — **Наиболее важный показатель.** Показывает объём памяти, который ядро может отдать под новые процессы без использования swap. Эта метрика учитывает `Free` и часть `Buff/Cache`, которую можно безболезненно освободить. Если программе потребуется больше памяти, система очистит часть кэша, чтобы предоставить ее. Высокое значение `Available` (например, более 50% от `Total`) при низком `Free` указывает на то, что система эффективно использует память для кэширования и при этом имеет достаточный резерв для новых приложений. Не стоит бояться низких значений в столбце `Free`, если `Available` показывает достаточный объем.
    
7. **Swap** — Когда системе не хватает физической памяти (или при определённой настройке swappiness), неиспользуемые страницы памяти могут выгружаться в swap-раздел (или файл). Если swap активно используется, это может указывать на нехватку RAM, но иногда ядро использует swap и при наличии свободной памяти, если считает, что выгрузка «простаивающих» страниц — более эффективный вариант.

### Другие важные метрики из `/proc/meminfo`

**Swap-пространство:**

-   `SwapTotal`: Общий размер раздела или файла подкачки.
-   `SwapFree`: Количество свободного места в swap.

**Страницы памяти:**

-   `Dirty`: Память, которая была измененена, но еще не записана на диск. Если система внезапно выключится, эти данные будут потеряны.
-   `Writeback`: Память, которая в данный момент записывается на диск.
-   `AnonPages`: Анонимные (нефайловые) страницы памяти, используемые процессами.
-   `Mapped`: Память, которая отображена в адресное пространство процессов (например, файлы или библиотеки).
-   `Shmem`: Объем разделяемой памяти (включая `tmpfs`).

**Память ядра:**

-   `Slab`: Память, используемая ядром для кэширования собственных структур данных (inodes, dentries и т.д.).
-   `SReclaimable`: Часть `Slab`, которую можно освободить при нехватке памяти.
-   `SUnreclaim`: Часть `Slab`, которую освободить нельзя.
-   `KernelStack`: Память, выделенная для стеков потоков ядра.
-   `PageTables`: Память, занимаемая таблицами страниц, которые используются для трансляции виртуальных адресов в физические.

**Управление памятью:**

-   `CommitLimit`: Общий объем виртуальной памяти, который система может выделить. Рассчитывается как `SwapTotal + (MemTotal * vm.overcommit_ratio / 100)`.
-   `Committed_AS`: Объем виртуальной памяти, который уже был выделен (запрошен) процессами. Если это значение приближается к `CommitLimit`, система близка к нехватке памяти.

**Огромные страницы (Huge Pages):**

-   `HugePages_Total` / `HugePages_Free` / `Hugepagesize`: Информация о количестве и размере "огромных страниц". Они используются для уменьшения накладных расходов на управление памятью для приложений, работающих с большими объемами данных (например, базы данных).
