# Метрики потребления памяти процесса

## Определения

* **VSS (Virtual Set Size)**: Общий объём виртуальной памяти, который процесс зарезервировал в своём адресном пространстве. В утилитах мониторинга часто обозначается как `VIRT` или `VSZ`.
* **RSS (Resident Set Size)**: Объём физической памяти (RAM), которую процесс фактически занимает в данный момент. Обозначается как `RES` или `RSS`.
* **PSS (Proportional Set Size)**: Показатель, учитывающий разделяемую память (Shared Memory) пропорционально количеству использующих её процессов.
* **USS (Unique Set Size)**: Объём физической памяти, который принадлежит исключительно данному процессу.
* **SHR (Shared Memory)**: Объём разделяемой памяти, которая может быть потенциально разделена с другими процессами (библиотеки, сегменты разделяемой памяти).

## Основные концепции

### VSS (Virtual Set Size) — Виртуальная память

* **Что включает:** Весь диапазон адресов, доступный процессу: код программы, данные, стек, куча (heap), разделяемые библиотеки, а также память, выделенная через `malloc`, но ещё не использованная физически.
* **Механизм:** VSS отражает только **резервирование** адресного пространства. Благодаря механизму [Memory Overcommit](./performance_tuning.md), сумма VSS всех процессов может многократно превышать объём физической RAM.
* **Когда важно:** Огромный VSS (сотни ГБ) может указывать на утечку адресного пространства или специфическое поведение аллокаторов, но сам по себе не означает дефицита RAM.

### RSS (Resident Set Size) — Резидентная память

* **Что включает:** Часть адресного пространства процесса, которая в данный момент находится в физической RAM.
* **Проблема разделяемой памяти:** RSS суммирует всю разделяемую память целиком для каждого процесса. Если 10 процессов используют одну библиотеку размером 10 МБ, RSS каждого увеличится на 10 МБ, хотя физически в памяти находится только одна копия библиотеки.
* **Использование:** RSS — стандартная метрика для быстрой оценки, но она вводит в заблуждение при анализе суммарного потребления системы.

### PSS (Proportional Set Size) — Пропорциональная память

* **Решение проблемы дублирования:** PSS делит размер разделяемых сегментов на количество процессов, которые их используют.
* **Формула:** `PSS = USS + (Shared Memory / Number of Users)`.
* **Пример:** Если 4 процесса используют библиотеку размером 4 МБ, каждому в PSS будет засчитано по 1 МБ.
* **Значимость:** Сумма PSS всех процессов даёт наиболее точную оценку того, сколько физической RAM занято процессами в системе.

### USS (Unique Set Size) — Уникальная память

* **Что включает:** Только те страницы физической памяти, которые отображены исключительно в данный процесс.
* **Практическая ценность:** Это объём памяти, который **будет освобождён немедленно**, если завершить данный процесс.
* **Диагностика:** USS — лучшая метрика для поиска утечек памяти в конкретном приложении.

## Практические сценарии

### Анализ с помощью `top`, `htop` и `ps`

Эти инструменты показывают VSS и RSS, что полезно для общего мониторинга.

* `ps aux`: колонка `VSZ` (в КБ) и `RSS` (в КБ).
* `top`: колонка `VIRT` и `RES`.
* `htop`: колонки `VIRT` и `RES`.

```bash
# Просмотр VSS и RSS для конкретного процесса
ps -o pid,vsz,rss,comm -p <PID>
```

Подробнее об инструментах: [ps](../../Diagnostics/Processes/ps.md), [top](../../Diagnostics/Processes/top.md).

### Точный анализ с помощью `smem`

Утилита `smem` считывает данные из `/proc` и рассчитывает PSS и USS, что недоступно стандартным средствам.

```bash
# Сортировка процессов по потреблению PSS (в процентах)
smem -p -s pss -r
```

Подробное руководство: [smem](../../Diagnostics/Memory/smem.md).

### Детальная разбивка через `/proc`

Для глубокого анализа конкретного процесса используются файлы интерфейса ядра:

* `/proc/<PID>/smaps`: подробная карта памяти с указанием PSS/RSS для каждого сегмента.
* `/proc/<PID>/status`: сводная информация (поля `VmSize`, `VmRSS`, `VmSwap`).
* `/proc/<PID>/statm`: компактный вывод метрик в страницах памяти.

## Дополнительная информация

### Сравнение метрик для различных задач

| Сценарий | Рекомендуемая метрика | Почему? |
| :--- | :--- | :--- |
| **Поиск утечки памяти** | **USS** | Отражает рост памяти, принадлежащей только этому процессу. |
| **Оценка нагрузки на систему** | **PSS** | Корректно учитывает разделяемые библиотеки без дублирования. |
| **Проверка лимитов (ulimit)** | **VSS** | Лимиты часто устанавливаются на общий объём виртуальной памяти. |
| **Быстрая проверка в консоли** | **RSS** | Доступна в `top`/`ps` без установки доп. утилит. |
