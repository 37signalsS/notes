## Определения

**VSS (Virtual Set Size) / VSZ** - Общий объем **виртуальной памяти**, доступный процессу.

**RSS (Resident Set Size) / RES** - Объем памяти, который процесс **реально занимает в физической RAM** в данный момент.

**PSS (Proportional Set Size)** - "Справедливая" доля физической памяти, занимаемая процессом, с пропорциональным учетом разделяемых библиотек.

**USS (Unique Set Size)** - Объем памяти, который является **уникальным** для данного процесса и будет освобожден после его завершения.

## Основные концепции

### VSS (Virtual Set Size)

- **Что включает:** Все, что отображено в адресное пространство процесса: его код, данные, стек, куча, разделяемые библиотеки, а также память, которая была запрошена (`malloc`), но еще не использовалась.
- **Ключевая особенность:** Сумма VSS всех процессов может **многократно превышать** объем физической RAM. Это нормально и является следствием работы [виртуальной памяти](./virtual_vs_physical_memory.md) и механизма [overcommit](./performance_tuning.md#управление-выделением-памяти-memory-overcommit). Большая цифра VSS не всегда указывает на проблему.

#### RSS (Resident Set Size)

- **Что включает:** Ресурсы процесса, которые сейчас находятся в RAM.
- **Проблема:** RSS суммирует **всю** разделяемую память. Если 10 процессов используют одну библиотеку размером 100 МБ, эти 100 МБ будут добавлены к RSS *каждого* из 10 процессов. Сумма RSS по системе неинформативна.

#### PSS (Proportional Set Size)

- **Как решает проблему RSS:** Учитывает разделяемую память пропорционально.
- **Формула:** `PSS = (Уникальная память) + (Разделяемая память / Количество процессов, которые ее используют)`.
- **Пример:** Если 2 процесса используют библиотеку на 100 МБ, в PSS каждого будет засчитано по 50 МБ. Сумма PSS всех процессов дает реалистичную оценку потребления RAM.

#### USS (Unique Set Size)

- **Что включает:** Только ту память, которая принадлежит исключительно данному процессу.
- **Главная ценность:** Это самый точный показатель того, **сколько физической памяти освободится, если завершить данный процесс**.

## Практические сценарии

### Анализ с помощью `top` и `ps`

Стандартные утилиты, как правило, показывают VSS (под заголовком `VIRT`) и RSS (`RES`). Этого достаточно для быстрой оценки, но не для точного анализа. Более подробная информация об утилите `ps` доступна в [ps.md](../../Diagnostics/Processes/ps.md).

```bash
ps aux | head
# USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
# root           1  0.0  0.1 169420 11988 ?        Ss   Dec12   0:02 /sbin/init
```

#### Точный анализ с помощью `smem`

Утилита `smem` — лучший инструмент для анализа, так как она по умолчанию показывает USS, PSS и RSS. Подробное использование утилиты `smem` описано в [smem.md](../../Diagnostics/Memory/smem.md).

```bash
# Установить smem (Debian/Ubuntu)
# sudo apt-get install smem

# Показать отчет по процессам, отсортированный по PSS
smem -t -p
```

#### Детальный анализ через `/proc`

Для самого глубокого анализа можно изучить файл `/proc/<PID>/smaps`, который содержит детальную разбивку по всем отображенным участкам памяти процесса.

## Дополнительная информация

### Какую метрику когда использовать?

- **Хочу понять, нет ли у процесса утечки памяти.**
  - **Смотрите на `USS` в динамике.** Постоянный рост уникальной памяти процесса — самый надежный признак утечки, так как эта память не разделяется с другими. Рост `PSS` и `RSS` также может указывать на утечку, но требует более внимательного анализа.

- **Хочу понять, сколько памяти освободится, если я убью процесс.**
  - **Смотрите на `USS`.** Это именно тот объем, который система вернет в свободное пользование.

- **Хочу понять, почему система тормозит из-за нехватки памяти.**
  - **Смотрите на сумму `PSS` по всем процессам.** Если она близка к общему объему RAM, значит, память действительно заканчивается. RSS в этом случае бесполезен.

- **Хочу понять, не запрашивает ли процесс слишком много виртуальной памяти.**
  - **Смотрите на `VSS`.** Огромное значение VSS (десятки или сотни гигабайт) может указывать на ошибку в программе, хотя само по себе это не всегда проблема.
