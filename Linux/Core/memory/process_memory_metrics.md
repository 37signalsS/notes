# Метрики потребления памяти процесса

## Определения

* **VSS (Virtual Set Size)**: Общий объём виртуальной памяти, который процесс зарезервировал в своём адресном пространстве. Включает неиспользуемые аллокации и отображенные файлы.
* **RSS (Resident Set Size)**: Объём физической памяти (RAM), которую процесс фактически занимает в данный момент. Делится на анонимную (Anonymous) и файловую (File-backed).
* **PSS (Proportional Set Size)**: Показатель, учитывающий разделяемую память (Shared Memory) пропорционально количеству использующих её процессов. Считается наиболее точным индикатором вклада процесса в общую нагрузку на RAM.
* **USS (Unique Set Size)**: Объём физической памяти, который принадлежит исключительно данному процессу. Это объём, который будет освобожден немедленно при завершении процесса.
* **WSS (Working Set Size)**: Рабочий набор — объём памяти, который был необходим процессу за последние интервалы времени для выполнения задач без задержек. Именно эта метрика критична для предотвращения OOM (Out Of Memory).
* **SHR (Shared Memory)**: Объём памяти, который может быть потенциально разделен с другими процессами (библиотеки, `tmpfs`, системные буферы).
* **Swap (Подкачка)**: Объём данных процесса, которые были выгружены из RAM на диск из-за дефицита оперативной памяти.

## Основные концепции

### VSS (Virtual Set Size) — Виртуальная память

* **Что включает**: Весь диапазон адресов, доступный процессу: код программы, данные, стек, куча (heap), разделяемые библиотеки, а также память, выделенная через `malloc`, но ещё не использованная физически.
* **Механизм**: VSS отражает только **резервирование** адресного пространства. Благодаря механизму [Memory Overcommit](./performance_tuning.md), сумма VSS всех процессов может многократно превышать объём физической RAM.
* **Диагностика**: Огромный VSS (сотни ГБ) может указывать на утечку адресного пространства или специфическое поведение аллокаторов (например, в Go или Java), но сам по себе не означает дефицита RAM.

### RSS (Resident Set Size) — Резидентная память

Это физическая память, реально занятая процессом. RSS состоит из двух ключевых компонентов:
1. **Anonymous RSS**: Память, не связанная с файлами (стек, куча, динамические данные). Рост этого показателя обычно указывает на реальное потребление или утечку.
2. **File-backed RSS**: Кэш страниц файлов, отображенных в память (библиотеки, исполняемые файлы, `mmap`). Ядро может легко освободить эту память, если она не изменена.

**Проблема разделяемой памяти**: RSS суммирует всю разделяемую память целиком для каждого процесса. Если 10 процессов используют одну библиотеку размером 10 МБ, RSS каждого увеличится на 10 МБ, хотя физически в памяти находится только одна копия.

### PSS (Proportional Set Size) — Пропорциональная память

* **Решение проблемы дублирования**: PSS делит размер разделяемых сегментов на количество процессов, которые их используют.
* **Формула**: `PSS = USS + (Shared Memory / Number of Users)`.
* **Пример**: Если 4 процесса используют библиотеку размером 4 МБ, каждому в PSS будет засчитано по 1 МБ.
* **Значимость**: Сумма PSS всех процессов даёт наиболее точную оценку того, сколько физической RAM занято процессами в системе.

### WSS (Working Set Size) — Рабочий набор

WSS — это подмножество RSS, которое активно используется процессом. 
* Если WSS процесса превышает доступную физическую RAM, система уходит в **Thrashing** (постоянный свопинг).
* **Kubernetes**: Метрика `working_set_bytes` включает RSS и часть Page Cache. Именно по этой метрике принимается решение о выселении (eviction) или OOM-завершении пода.

## Практические сценарии

### Анализ с помощью стандартных утилит

Большинство инструментов по умолчанию показывают только VSS (VIRT) и RSS (RES).

* `top`: Колонки `VIRT` и `RES`.
* `htop`: Колонки `VIRT` и `RES`.
* `ps aux`: Колонки `VSZ` (в КБ) и `RSS` (в КБ).

```bash
# Просмотр VSS и RSS для конкретного процесса
ps -o pid,vsz,rss,comm -p <PID>
# →   PID    VSZ   RSS COMMAND
# →  1234 150240  4096 nginx
```

### Точный анализ PSS и USS через smem и ps_mem

Утилиты `smem` и `ps_mem` рассчитывают PSS и USS, считывая данные из `/proc`.

```bash
# Сортировка процессов по потреблению PSS (в КБ)
smem -tk -s pss -r | head
# →   PID User     Command                         Swap      USS      PSS      RSS
# →  1234 root     nginx                              0     2.1M     3.5M     8.2M

# Удобный отчет по суммарному потреблению группами процессов
sudo ps_mem
# →  Private  +   Shared  =  RAM used	Program
# →  3.1 MiB  +   1.2 MiB =  4.3 MiB	nginx (4)
```

Подробные руководства: [smem](../../Diagnostics/Memory/smem.md), [ps](../../Diagnostics/Processes/ps.md).

### Детальная разбивка через интерфейс /proc

Интерфейс ядра предоставляет исчерпывающие данные для диагностики.

* `/proc/<PID>/smaps_rollup`: Самый эффективный способ получить агрегированные данные (RSS, PSS, USS) по процессу за один раз.
* `/proc/<PID>/smaps`: Детальная карта памяти по каждому сегменту. Используется для глубокого поиска утечек.
* `/proc/<PID>/status`: Сводная информация. Поля `VmSize` (VSS), `VmRSS` (RSS), `VmSwap` (Swap).

```bash
# Быстрое получение PSS и RSS для процесса
cat /proc/<PID>/smaps_rollup | grep -E "Rss|Pss"
# → Pss:                8520 kB
# → Pss_Anon:           4120 kB
# → Pss_File:           4400 kB

# Основные показатели и пиковое потребление из статуса
grep -E "VmRSS|VmSize|VmSwap|VmPeak" /proc/<PID>/status
# → VmPeak:          150240 kB (пиковое потребление VSS за все время)
# → VmSize:          150240 kB (текущий VSS)
# → VmRSS:             4096 kB (текущий RSS)
# → VmSwap:               0 kB (объем в свопе)
```

## Дополнительная информация

### Сравнение метрик для различных задач

| Сценарий | Рекомендуемая метрика | Почему? |
| :--- | :--- | :--- |
| **Поиск утечки памяти** | **USS / Pss_Anon** | Отражает рост памяти, принадлежащей только этому процессу или не связанной с файлами. |
| **Оценка нагрузки на систему** | **PSS** | Корректно учитывает разделяемые ресурсы без двойного счета. |
| **Оценка для K8s / OOM** | **WSS / RSS** | Отражает фактическое владение физическими страницами. |
| **Лимиты системы (ulimit)** | **VSS** | Лимиты часто устанавливаются на общий объём виртуальной памяти. |
