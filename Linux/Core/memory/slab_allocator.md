# Slab Allocator в Linux

## Определения

* **Slab Allocator**: Механизм управления памятью ядра Linux, предназначенный для эффективного выделения памяти под часто используемые объекты фиксированного размера (структуры данных).
* **Slab Cache** (Кэш слэбов): Логическая группировка объектов одного типа (например, `inode_cache`, `dentry`, `task_struct`). Каждый кэш управляет набором слэбов.
* **Slab** (Слэб): Один или несколько смежных листов (pages) физической памяти, разделенных на равные участки для хранения объектов. Слэб может находиться в одном из трех состояний: *full* (заполнен), *partial* (частично заполнен), *empty* (пуст).
* **Slab Object**: Индивидуальный экземпляр структуры данных, хранящийся внутри слэба.
* **kmalloc**: Кэши общего назначения для выделения памяти произвольного размера (например, `kmalloc-128`, `kmalloc-512`). Используются, когда для объекта не создан специализированный кэш.
* **SReclaimable**: Часть Slab-памяти (в `/proc/meminfo`), которую ядро может освободить под давлением (например, кэши VFS).
* **SUnreclaim**: Часть Slab-памяти, которую нельзя освободить (критические структуры ядра).
* **Slab Shrinker**: Обратный вызов (callback) в ядре, который вызывается механизмом освобождения памяти для уменьшения размера конкретного `SReclaimable`-кэша.

## Основные концепции

### Проблема, которую решает Slab

Стандартный аллокатор страниц (Buddy System) работает с минимальным размером в 4 КБ. Выделение памяти под структуры размером в десятки или сотни байт через Buddy System приводит к двум проблемам:
1. **Внутренняя фрагментация**: Большая часть страницы остается неиспользованной.
2. **Затраты на инициализацию**: Ядро тратит время на подготовку (инициализацию) и очистку сложных структур при каждом создании/удалении.

### Принцип работы Slab Allocator

1. **Кэширование объектов**: Вместо уничтожения объекта после использования, аллокатор помечает его как "свободный" и оставляет в памяти. При следующем запросе того же типа объект выдается мгновенно без повторной инициализации.
2. **Минимизация фрагментации**: Объекты плотно упаковываются в слэбы.
3. **NUMA-оптимизация**: Современные аллокаторы (SLUB) учитывают топологию системы, стараясь выделять объекты из памяти того же NUMA-узла, на котором исполняется поток.

### Кэши общего назначения (kmalloc)

Для небольших аллокаций, не привязанных к конкретному типу данных, ядро поддерживает набор кэшей `kmalloc-N`, где N — размер в байтах (обычно степени двойки: 8, 16, 32... 8192).
```bash
grep kmalloc /proc/slabinfo | head -n 5
# → kmalloc-8k          125    128   8192    4    8 : tunables    0    0    0 : slabdata     32     32      0
# → kmalloc-4k          452    512   4096    8    8 : tunables    0    0    0 : slabdata     64     64      0
```

### Механизм Slab Shrinker

Когда системе требуется память (свободная память опускается ниже вотермарка `low`), вызываются шринкеры. Они проходят по `SReclaimable`-кэшам и удаляют старые объекты. Самые известные потребители — **dentry** и **inode** (кэши путей и метаданных файлов). Подробнее о структурах VFS см. в **[Inodes и Dentries](../../FileSystems/links_inodes_dentries.md)**.

## Практические сценарии

### Диагностика разрастания Slab

Если `SUnreclaim` постоянно растет, это может указывать на утечку памяти в модуле ядра или драйвере. Рост `SReclaimable` обычно нормален для систем с интенсивным I/O.

**Просмотр общей статистики:**
```bash
grep -E 'Slab|SReclaimable|SUnreclaim' /proc/meminfo
# → Slab:             254320 kB
# → SReclaimable:     182140 kB
# → SUnreclaim:        72180 kB
```

**Анализ через slabtop:**
Утилита `slabtop` (требует прав root) позволяет сортировать кэши по объему памяти или количеству объектов.
```bash
# Сортировка по размеру кэша (клавиша 'c')
slabtop -o -s c
```
Популярные кэши:
* `dentry`: Кэш имен файлов. Растет при обращении к множеству разных файлов.
* `inode_cache`: Кэш метаданных файлов.
* `kernfs_node_cache`: Кэш структур `/sys` и `/proc`.
* `task_struct`: Информация о процессах.

**Детальный анализ через /proc/slabinfo:**
Файл содержит подробную статистику (требует `CONFIG_SLABINFO`).
```bash
cat /proc/slabinfo | column -t | head -n 5
# → name            <active_objs>  <num_objs>  <objsize>  <objperslab>  <pagesperslab>
# → nf_conntrack    452            500         320        12            1
```
* `active_objs`: Количество используемых объектов.
* `num_objs`: Общее количество выделенных объектов (включая свободные).
* `objsize`: Размер одного объекта в байтах.
* `objperslab`: Сколько объектов помещается в один слэб.

### Проверка в современных системах (SLUB)

В системах со SLUB-аллокатором детальную информацию о каждом слэбе можно найти в `/sys/kernel/slab/`.
```bash
# Список всех кэшей
ls -l /sys/kernel/slab/

# Информация о конкретном кэше (например, dentry)
cat /sys/kernel/slab/dentry/objects
```

### Slab и Control Groups (kmemcg)

Ядро может изолировать использование Slab-памяти между контейнерами (cgroups). 
* **Zombie Slabs**: Если cgroup удалена, но объекты в ее слэбах еще используются ядром (например, открытые файлы), слэбы остаются в памяти. В старых ядрах это приводило к утечкам "зомби-слэбов".
* **Проверка лимитов**: В современных системах память слэбов учитывается в `memory.current` контрольной группы.

### Тюнинг vm.vfs_cache_pressure

Параметр определяет приоритет очистки слэбов VFS по сравнению с Page Cache.
* `100` (default): Равный приоритет.
* `50`: Ядро будет в 2 раза менее охотно очищать inode/dentry.
* `200`: Агрессивная очистка метаданных (снижает производительность FS, но освобождает RAM).

Подробное описание параметров `sysctl` см. в **[Оптимизация памяти](./performance_tuning.md)**.

## Дополнительная информация

### Разновидности Slab Allocator

| Аллокатор | Описание | Статус |
| :--- | :--- | :--- |
| **SLAB** | Оригинальная реализация (Solaris-style). Использовала сложные очереди объектов. | Удален в Linux 6.8 (2024). |
| **SLOB** | Минималистичный аллокатор для встраиваемых систем (Kmalloc на базе списка). | Удален в Linux 6.4 (2023). |
| **SLUB** | Современный стандарт. Упрощенный дизайн, лучшая масштабируемость на многопроцессорных (SMP) системах, расширенная отладка. | **Единственный доступный с Linux 6.8.** |

### Полезные параметры загрузки ядра

* `slab_nomerge`: Запрещает объединение схожих по размеру кэшей. Полезно для безопасности (изоляция объектов разных типов) или отладки.
* `slub_debug`: Включает проверки целостности слэбов (может значительно снизить производительность).
