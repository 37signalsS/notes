# Управление Swap (файлом подкачки)


## Определения

*   **Swap (подкачка)** — это пространство на диске, которое операционная система использует, когда ей не хватает оперативной памяти (RAM), для выгрузки неактивных страниц памяти.
*   **Анонимные страницы (Anonymous Pages)** — страницы памяти, не связанные напрямую с файлом на диске (например, память стека или кучи процесса). При нехватке RAM они выгружаются в swap.
*   **Page Fault ("ошибка страницы")** — исключение от [MMU (Memory Management Unit)](./virtual_vs_physical_memory.md#механизм-работы), когда процесс обращается к виртуальной странице, которой нет в физической памяти. Ядро обрабатывает его, загружая страницу из swap или с диска.
*   **Swappiness** — параметр ядра (от 0 до 100), который контролирует, насколько агрессивно система будет использовать swap-пространство.

## Основные концепции

### Зачем нужен Swap?

1.  **Выгрузка неактивных данных:** Память, используемая процессами редко, может быть выгружена в swap. Это освобождает RAM для более важных задач: дискового кэша и активных приложений.
2.  **Резервное хранилище:** Swap — единственное место, куда ядро может временно выгрузить анонимные страницы.

### Что попадает в Swap? Анонимные страницы

В swap выгружаются **анонимные страницы** (`anonymous pages`). В отличие от файлового кэша, анонимные страницы уникальны. К ним относятся:
*   Память, выделенная программами (стек, куча).
*   Временные данные процессов.

### Как ядро освобождает память?

1.  **Сначала удаляет чистый кэш (Page Cache):** Самый быстрый способ.
2.  **Записывает "грязные" страницы (Dirty Pages) на диск:** Синхронизация измененных данных с файлами на диске.
3.  **Выгружает анонимные страницы в swap:** При недостаточности предыдущих шагов.

### Page Fault: Механизм подгрузки страниц

При обращении к выгруженной в swap странице возникает **Page Fault**. Ядро:
1.  Приостанавливает процесс.
2.  Находит страницу в swap-файле.
3.  Загружает её в RAM.
4.  Обновляет карту памяти процесса.
5.  Возобновляет работу процесса.

### Типы Swap: Раздел vs. Файл
| Характеристика | Swap-раздел | Swap-файл |
| :--- | :--- | :--- |
| **Производительность** | Традиционно быстрее, но на современных SSD разница незначительна. | Практически не уступает разделу. |
| **Гибкость** | **Низкая**. Размер сложно изменить. | **Высокая**. Легко создать, удалить или изменить размер. |
| **Использование** | Классический подход. | Современный и рекомендуемый. |

## Практические сценарии

### Проверка состояния swap

```bash
# Показать активные swap-устройства
swapon --show

# Показать использование RAM и swap
free -h
```

### Создание и управление Swap-файлом (рекомендуемый способ)

Рекомендуется использовать `fallocate` для мгновенного резервирования места.

```bash
# 1. Создать файл размером 4 ГБ
sudo fallocate -l 4G /swapfile

# 2. Установить права (доступ только для root)
sudo chmod 600 /swapfile

# 3. Отформатировать как swap
sudo mkswap /swapfile

# 4. Активировать
sudo swapon /swapfile

# 5. Сделать постоянным (добавить в [`/etc/fstab`](../FileSystems/mounting.md#структура-и-синтаксис-файла-etcfstab))
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Отключение и удаление Swap-файла

```bash
# 1. Деактивировать swap
sudo swapoff /swapfile

# 2. Удалить запись из [`/etc/fstab`](../FileSystems/mounting.md#структура-и-синтаксис-файла-etcfstab) (если она была добавлена)

# 3. Удалить сам файл
sudo rm /swapfile
```

### Тюнинг `vm.swappiness`

*   `100`: Максимально агрессивно выгружать в swap.
*   `60`: Стандарт для десктопов.
*   `10`: Рекомендуется для серверов.
*   `0-1`: Избегать swap до последней возможности (риск OOM).

```bash
# Проверить текущее значение
cat /proc/sys/vm/swappiness

# Временно изменить
sudo sysctl vm.swappiness=10

# Для постоянного изменения добавьте vm.swappiness=10 в /etc/sysctl.conf. Затем примените изменения: `sudo sysctl -p`.
```

## Дополнительная информация

### Философия использования Swap: Избегать или использовать?

1.  **"Swap как зло" (для production):** Любой свопинг на нагруженном сервере — это падение производительности. Предпочтительнее OOM Killer, чем медленная работа.
2.  **"Swap как подушка безопасности":** Небольшой swap (1–4 ГБ) может предотвратить сбой при кратковременных пиках потребления памяти.

**Итог:** Для критичных систем планировать ресурсы без swap, но иметь небольшой "аварийный" объем — разумная практика.

### Приоритет Swap (Swap Priority)

Для нескольких swap-устройств можно задать **приоритет** (от -1 до 32767). Устройство с более высоким приоритетом используется в первую очередь.

```bash
# 1. Отключить swap
sudo swapoff /swapfile

# 2. Включить с новым приоритетом
sudo swapon /swapfile -p 10

# 3. Закрепить в /etc/fstab
# `/swapfile none swap sw,pri=10 0 0` (см. [`/etc/fstab`](../FileSystems/mounting.md#структура-и-синтаксис-файла-etcfstab))
# /dev/sdb2   none swap sw,pri=5  0 0
```

### Рекомендации по размеру и `swappiness`

| Сценарий | Использовать Swap? | Рекомендуемый размер | Swappiness (`vm.swappiness`) |
| :--- | :--- | :--- | :--- |
| **Рабочая станция / Ноутбук** | Да, настоятельно | >= RAM (для гибернации), иначе 4-8 ГБ. | 60 |
| **Сервер БД (PostgreSQL и др.)** | С осторожностью | 1–4 ГБ ("подушка безопасности") | 1–10 |
| **Сервер приложений** | Да | ~0.5x RAM или 4–8 ГБ | 10–30 |
| **Системы с малым RAM (< 2ГБ)** | Обязательно | 1x – 2x RAM | 60 |
| **Системы с большим RAM (> 64ГБ)** | Да, небольшой | 4–16 ГБ | 10 |

### Рефакторинг: замена LVM-раздела на swap-файл

Если swap выделен как логический том (LV) в [LVM (Logical Volume Manager)](../../Linux/FileSystems/lvm.md), его можно преобразовать в swap-файл, а место отдать корневому разделу.

**Последовательность действий включает:** отключение текущего swap, удаление LVM-тома swap, расширение корневого LVM-тома и его файловой системы, а затем создание нового swap-файла. Подробные инструкции по управлению LVM-томами можно найти в разделе [Изменение размеров логических томов](../../Linux/FileSystems/lvm.md#изменение-размеров) и [Удаление логических томов](../../Linux/FileSystems/lvm.md#полный-жизненный-цикл-lvm). Создание swap-файла описано в этом документе выше.

> **Важно:** После таких изменений рекомендуется перезагрузка для проверки корректности конфигурации.
