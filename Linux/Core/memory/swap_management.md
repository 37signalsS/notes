# Управление Swap (подкачкой) в Linux

## Определения

* **Swap (подкачка)** — пространство на дисковом носителе, используемое ядром Linux для выгрузки неактивных [анонимных страниц](./virtual_vs_physical_memory.md) при дефиците оперативной памяти (RAM — Random Access Memory).
* **Анонимные страницы (Anonymous Pages)** — сегменты памяти, не связанные с файлом на диске (стек процесса, куча, данные, выделенные через `malloc`). При нехватке оперативной памяти они выгружаются в swap. Противоположность — [file-backed страницы](./virtual_vs_physical_memory.md), которые при необходимости просто удаляются из памяти и считываются заново с диска.
* **Swappiness** — параметр ядра (`vm.swappiness`, диапазон 0–200), определяющий баланс между вытеснением анонимных страниц в swap и очисткой файлового кэша. Начиная с ядра 3.5 значения выше 100 делают выгрузку в swap более агрессивной.
* **Swap-in (si)** — операция чтения страниц из пространства подкачки обратно в оперативную память.
* **Swap-out (so)** — операция записи страниц из оперативной памяти в пространство подкачки.

## Основные концепции

### Назначение Swap

1. **Высвобождение ресурсов** — редко используемые анонимные страницы перемещаются в swap, освобождая оперативную память для дискового кэша (page cache) и активных приложений.
2. **Предотвращение аварийных завершений** — swap является единственным резервным местом для выгрузки анонимных страниц. Без него при полном исчерпании оперативной памяти срабатывает механизм [OOM Killer (Out Of Memory Killer)](../processes/oom_killer_mechanism.md).

### Алгоритм освобождения памяти ядром

При дефиците оперативной памяти ядро выполняет очистку в следующем приоритете (подробнее: [кэширование и освобождение памяти](caching_and_reclaiming.md)):

1. **Сброс "чистого" файлового кэша (page cache)** — выполняется мгновенно, так как данные уже есть на диске.
2. **Синхронизация "грязных" страниц (dirty pages)** — запись измененных данных на диск перед их удалением из памяти.
3. **Выгрузка анонимных страниц в swap** — требует дисковых операций ввода-вывода (I/O — Input/Output).
4. **Активация OOM Killer** — если все ресурсы исчерпаны, ядро принудительно завершает процесс с наихудшим рейтингом (oom_score).

### Выбор типа Swap: Раздел против Файла

| Характеристика | Swap-раздел | Swap-файл |
| :--- | :--- | :--- |
| **Производительность** | Традиционно считался быстрее, но на современных твердотельных накопителях (SSD — Solid State Drive) разница нивелирована. | Практически идентична разделу. |
| **Гибкость** | **Низкая** — требует изменения таблицы разделов диска. | **Высокая** — легко создать, удалить или изменить размер. |
| **Применение** | Классический метод установки Linux. | Современный стандарт (используется по умолчанию в Ubuntu, Fedora). |

### Настройка параметра `vm.swappiness`

| Значение | Описание поведения |
| :--- | :--- |
| **90+** | Максимально агрессивная выгрузка в swap для сохранения максимального объема файлового кэша. |
| **60** | Значение по умолчанию (баланс между swap и page cache). |
| **10–30** | Оптимально для серверов (приоритет отдается сохранению приложений в оперативной памяти). |
| **0–1** | Минимальное использование swap (не отключает подкачку полностью, но минимизирует риск задержек). |

> **Примечание:** `swappiness=0` не гарантирует полного отсутствия свопинга. При экстремальном давлении на память ядро все равно задействует swap для спасения системы от зависания.

**Рекомендации по применению:**

| Контекст использования | Рекомендуемое значение Swappiness |
| :--- | :--- |
| Универсальные системы / Kubernetes | 60 (стандарт) |
| Серверы приложений (Java, Python) | 10–30 |
| Базы данных (PostgreSQL, MySQL, Oracle) | 1–10 |
| Системы с интенсивным файловым вводом-выводом | 90+ |

```bash
# Просмотр текущего значения
cat /proc/sys/vm/swappiness

# Временное изменение
sudo sysctl vm.swappiness=10

# Перманентное применение (через файл конфигурации sysctl)
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

Технические детали управления параметрами ядра: **[sysctl — управление параметрами ядра](../kernel/sysctl.md)**.

## Практические сценарии

### Инспекция текущего состояния

```bash
# Список активных устройств подкачки
swapon --show

# Сводная информация по оперативной памяти и swap
free -h

# Старый формат отображения активных разделов
swapon -s
```

### Создание Swap-файла (актуальный метод)

Для быстрого резервирования места рекомендуется использовать утилиту `fallocate`:

```bash
# 1. Создание файла нужного размера (например, 4 ГБ)
sudo fallocate -l 4G /swapfile

# 2. Ограничение прав доступа (только для суперпользователя)
sudo chmod 600 /swapfile

# 3. Подготовка структуры swap
sudo mkswap /swapfile

# 4. Активация подкачки
sudo swapon /swapfile

# 5. Настройка автоподключения при загрузке системы (/etc/fstab)
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Деактивация и удаление подкачки

```bash
# 1. Отключение swap
sudo swapoff /swapfile

# 2. Удаление соответствующей строки из /etc/fstab

# 3. Физическое удаление файла
sudo rm /swapfile
```

### Управление приоритетами (Swap Priority)

При наличии нескольких источников подкачки можно задать их приоритет (от -1 до 32767). Первым заполняется устройство с наибольшим числом:

```bash
# Активация с явным приоритетом
sudo swapon /swapfile -p 10

# Конфигурация в /etc/fstab
# /swapfile none swap sw,pri=10 0 0
```

### Рекомендации по определению объема

| Тип системы | Рекомендация | Объем |
| :--- | :--- | :--- |
| **Десктоп / Ноутбук** | Рекомендуется | >= RAM (для гибернации), иначе 4–8 ГБ. |
| **Сервер БД (PostgreSQL, MySQL)** | Минимальный объем | 1–4 ГБ ("подушка безопасности"). |
| **Сервер приложений** | Желателен | ~0.5x от объема RAM или 4–8 ГБ. |
| **Малый объем RAM (< 2 ГБ)** | Обязательно | 1x – 2x от объема RAM. |
| **Большой объем RAM (> 64 ГБ)** | Желателен небольшой | 4–16 ГБ. |
| **Узлы Kubernetes** | **Отключен** | Требование kubelet. |
| **Elasticsearch** | **Отключен** | Избежание пауз GC (Garbage Collector). |

> Процедура подготовки узлов Kubernetes: **[Подготовка ноды](../../../Kubernetes/Installation/HA_Cluster_Bare_Metal/k8s_ha_node_preparation.md)**.

## Дополнительная информация

### Стратегии использования: Экономия ресурсов против Стабильности

1. **"Swap как помеха"** — на высоконагруженных серверах свопинг приводит к резкой деградации производительности. Часто лучше допустить срабатывание OOM Killer, чем получить непредсказуемо медленную систему.
2. **"Swap как предохранитель"** — наличие небольшого объема подкачки позволяет системе пережить кратковременные пики потребления памяти без падения процессов.

### Zswap и Zram: Сжатие в оперативной памяти

* **Zswap** — механизм ядра, создающий сжатый кэш в оперативной памяти для страниц, направляемых в swap. Сокращает количество реальных дисковых операций записи.
* **Zram** — модуль, создающий виртуальное блочное устройство в оперативной памяти со сжатием данных. Используется как самостоятельное пространство подкачки без привязки к диску.

**Настройка Zram:**

```bash
# Загрузка модуля
modprobe zram num_devices=1

# Определение размера (например, 2 ГБ)
echo 2G > /sys/block/zram0/disksize

# Подготовка и включение
mkswap /dev/zram0
swapon /dev/zram0 -p 100
```

### Гибернация (Hibernation)

Процесс сохранения всего состояния оперативной памяти на диск с полным отключением питания.

* **Требование:** Объем swap должен превышать объем занятой оперативной памяти.
* **Конфигурация:** Требует настройки параметра `resume` в загрузчике и обновления образа initramfs.

### Перенос Swap из LVM в файл

Если область подкачки находится на логическом томе [LVM (Logical Volume Manager)](../../FileSystems/LVM/overview_concepts.md), ее можно перенести в файл для освобождения места в группе томов:

1. Отключение текущего тома (`swapoff`).
2. Удаление логического тома swap.
3. Расширение файловой системы целевого раздела.
4. Создание swap-файла по инструкции выше.
