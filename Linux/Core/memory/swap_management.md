## Управление Swap (файлом подкачки)

### 1. Определения

**Swap (подкачка)** — это пространство на диске, которое операционная система использует, когда ей не хватает оперативной памяти (RAM), для выгрузки неактивных страниц памяти.

**Анонимные страницы (Anonymous Pages)** — страницы памяти, не связанные напрямую с файлом на диске (например, память стека или кучи процесса). При нехватке RAM они выгружаются в swap.

**Page Fault ("ошибка страницы")** — исключение от MMU (Memory Management Unit), когда процесс обращается к виртуальной странице, которой нет в физической памяти. Ядро обрабатывает его, загружая страницу из swap или с диска.

**Swappiness** — параметр ядра (от 0 до 100), который контролирует, насколько агрессивно система будет использовать swap-пространство.

### 2. Основные концепции

#### Зачем нужен Swap?
Основная задача swap — не быть "аварийной" памятью, а позволить ядру более эффективно управлять имеющейся RAM. Активное использование swap (swapping) приводит к падению производительности, так как диски на порядки медленнее RAM.

1.  **Выгрузка неактивных данных:** Память, используемая процессами редко (например, только при запуске), может быть выгружена в swap. Это освобождает RAM для более важных задач: дискового кэша и активных приложений.
2.  **Резервное хранилище:** Swap — единственное место, куда ядро может временно выгрузить анонимные страницы.

#### Что попадает в Swap? Анонимные страницы

В swap выгружаются **анонимные страницы** (`anonymous pages`). В отличие от файлового кэша (копии данных с диска, которые можно просто очистить), анонимные страницы уникальны и не имеют другого источника. К ним относятся:
-   Память, выделенная программами для хранения переменных (стек, куча).
-   Временные данные процессов.

Без swap-пространства все анонимные страницы должны были бы постоянно находиться в RAM.

#### Как ядро освобождает память?
Когда памяти становится мало, ядро действует по следующему алгоритму:
1.  **Сначала удаляет чистый кэш (Page Cache):** Это самый быстрый способ, так как эти данные можно снова прочитать с диска.
2.  **Записывает "грязные" страницы (Dirty Pages) на диск:** Это измененные данные в памяти, которые еще не сохранены. Перед освобождением их необходимо синхронизировать с файлами на диске.
3.  **Выгружает анонимные страницы в swap:** Если предыдущих шагов недостаточно, ядро начинает перемещать анонимные страницы в swap.

#### Page Fault: Механизм подгрузки страниц

Когда процесс обращается к странице памяти, MMU процессора преобразует виртуальный адрес в физический. Если страница была выгружена в swap, возникает **Page Fault**. Ядро перехватывает это событие:

1.  Приостанавливает процесс.
2.  Находит нужную страницу в swap-файле.
3.  Загружает её в свободный слот в RAM.
4.  Обновляет карту памяти процесса.
5.  Возобновляет работу процесса, который теперь может получить доступ к данным.

#### Типы Swap: Раздел vs. Файл
| Характеристика | Swap-раздел | Swap-файл |
| :--- | :--- | :--- |
| **Производительность** | Традиционно считался быстрее, но на современных SSD разница незначительна. | Практически не уступает разделу по скорости. |
| **Гибкость** | **Низкая**. Размер сложно изменить. | **Высокая**. Легко создать, удалить или изменить размер "на лету". |
| **Использование** | Классический подход. | Современный и рекомендуемый в большинстве случаев. |

### 3. Практические сценарии

#### Проверка состояния swap
```bash
# Показать активные swap-устройства
swapon --show

# Показать использование RAM и swap
free -h
```

#### Создание и управление Swap-файлом (рекомендуемый способ)
Рекомендуется использовать `fallocate` для мгновенного резервирования места, что избегает фрагментации файла.

```bash
# 1. Создать файл размером 4 ГБ
sudo fallocate -l 4G /swapfile

# 2. Установить права (доступ только для root)
sudo chmod 600 /swapfile

# 3. Отформатировать как swap
sudo mkswap /swapfile

# 4. Активировать
sudo swapon /swapfile

# 5. Сделать постоянным (добавить в /etc/fstab)
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

#### Отключение и удаление Swap-файла

```bash
# 1. Деактивировать swap
sudo swapoff /swapfile

# 2. Удалить запись из /etc/fstab (если она была добавлена)

# 3. Удалить сам файл
sudo rm /swapfile
```

#### Тюнинг `vm.swappiness`
-   `100`: Максимально агрессивно выгружать в swap.
-   `60`: Стандарт для десктопов.
-   `10`: Рекомендуется для серверов (предпочитать сброс кэша).
-   `0-1`: Избегать swap до последней возможности (риск OOM).
```bash
# Проверить текущее значение
cat /proc/sys/vm/swappiness

# Временно изменить
sudo sysctl vm.swappiness=10

# Для постоянного изменения добавьте vm.swappiness=10 в /etc/sysctl.conf. Затем примените изменения: `sudo sysctl -p`.

```

### 4. Продвинутые детали

#### Философия использования Swap: Избегать или использовать?

1.  **"Swap как зло" (для production):** Любой свопинг на нагруженном сервере — это катастрофическое падение производительности. Лучше пусть приложение упадет от OOM Killer, чем будет медленно "умирать". Это делает проблему нехватки RAM явной и заставляет решать её.
2.  **"Swap как подушка безопасности":** Небольшой swap (1–4 ГБ) может спасти систему от сбоя при кратковременных пиках потребления памяти и полезен для выгрузки неактивных системных демонов.

**Итог:** Для критичных к производительности систем лучше планировать ресурсы так, чтобы swap не использовался, но иметь небольшой "аварийный" объем — разумная практика.

#### Приоритет Swap (Swap Priority)

Если используется несколько swap-устройств, можно задать для каждого **приоритет** (от -1 до 32767). Устройство с более высоким приоритетом используется в первую очередь. Это полезно для комбинации быстрого (SSD) и медленного (HDD) дисков.

```bash
# 1. Отключить swap
sudo swapoff /swapfile

# 2. Включить с новым приоритетом
sudo swapon /swapfile -p 10

# 3. Закрепить в /etc/fstab
# /swapfile none swap sw,pri=10 0 0
# /dev/sdb2   none swap sw,pri=5  0 0
```

#### Рекомендации по размеру и `swappiness`

| Сценарий | Использовать Swap? | Рекомендуемый размер | Swappiness (`vm.swappiness`) |
| :--- | :--- | :--- | :--- |
| **Рабочая станция / Ноутбук** | Да, настоятельно | >= RAM (для гибернации), иначе 4-8 ГБ. | 60 |
| **Сервер БД (PostgreSQL и др.)** | С осторожностью | 1–4 ГБ ("подушка безопасности") | 1–10 |
| **Сервер приложений** | Да | ~0.5x RAM или 4–8 ГБ | 10–30 |
| **Системы с малым RAM (< 2ГБ)** | Обязательно | 1x – 2x RAM | 60 |
| **Системы с большим RAM (> 64ГБ)** | Да, небольшой | 4–16 ГБ | 10 |

#### Рефакторинг: замена LVM-раздела на swap-файл
Если система использует LVM и swap выделен как логический том (LV), его можно преобразовать в swap-файл, а место отдать корневому разделу.
**Последовательность действий:**
1.  **Проверить LV:** `sudo lvs`

2.  **Отключить swap:** `sudo swapoff -a` и удалить соответствующую запись из `/etc/fstab`.
3.  **Удалить LV:** `sudo lvremove /dev/vg-name/swap_lv`
4.  **Расширить корневой LV:** `sudo lvextend -l +100%FREE /dev/vg-name/root_lv`
5.  **Изменить размер файловой системы:** `sudo resize2fs /dev/mapper/vg-name-root_lv` (для ext4)
6.  **Создать swap-файл**, как описано выше.
> **Важно:** После таких изменений рекомендуется перезагрузка для проверки корректности конфигурации.
