# Управление Swap (файлом подкачки)

## Определения

* **Swap (подкачка)** — это пространство на диске, которое операционная система использует, когда ей не хватает оперативной памяти (RAM), для выгрузки неактивных страниц памяти.
* **Анонимные страницы (Anonymous Pages)** — страницы памяти, не связанные напрямую с файлом на диске (например, память стека или кучи процесса). При нехватке RAM они выгружаются в swap.
* **Page Fault ("ошибка страницы")** — исключение от [MMU (Memory Management Unit)](./virtual_vs_physical_memory.md), когда процесс обращается к виртуальной странице, которой нет в физической памяти. Ядро обрабатывает его, загружая страницу из swap или с диска.
* **Swappiness** — параметр ядра (от 0 до 200), контролирующий агрессивность использования swap-пространства.

## Основные концепции

### Зачем нужен Swap?

1. **Выгрузка неактивных данных:** Память, используемая процессами редко, может быть выгружена в swap. Это освобождает RAM для более важных задач: дискового кэша и активных приложений.
2. **Резервное хранилище:** Swap — единственное место, куда ядро может временно выгрузить анонимные страницы.

### Что попадает в Swap? Анонимные страницы

В swap выгружаются **анонимные страницы** (`anonymous pages`). В отличие от файлового кэша, анонимные страницы уникальны. К ним относятся:

* Память, выделенная программами (стек, куча).
* Временные данные процессов.

### Как ядро освобождает память?

1. **Сначала удаляет чистый кэш (Page Cache):** Самый быстрый способ.
2. **Записывает "грязные" страницы (Dirty Pages) на диск:** Синхронизация измененных данных с файлами на диске.
3. **Выгружает анонимные страницы в swap:** При недостаточности предыдущих шагов.

### Page Fault: Механизм подгрузки страниц

При обращении к выгруженной в swap странице возникает **Page Fault**. Ядро:

1. Приостанавливает процесс.
2. Находит страницу в swap-файле.
3. Загружает её в RAM.
4. Обновляет карту памяти процесса.
5. Возобновляет работу процесса.

### Типы Swap: Раздел vs. Файл

| Характеристика | Swap-раздел | Swap-файл |
| :--- | :--- | :--- |
| **Производительность** | Традиционно быстрее, но на современных SSD разница незначительна. | Практически не уступает разделу. |
| **Гибкость** | **Низкая**. Размер сложно изменить. | **Высокая**. Легко создать, удалить или изменить размер. |
| **Использование** | Классический подход. | Современный и рекомендуемый. |

## Практические сценарии

### Проверка состояния swap

```bash
# Показать активные swap-устройства
swapon --show

# Показать использование RAM и swap
free -h
```

### Создание и управление Swap-файлом (рекомендуемый способ)

Рекомендуется использовать `fallocate` для мгновенного резервирования места.

```bash
# 1. Создать файл размером 4 ГБ
sudo fallocate -l 4G /swapfile

# 2. Установить права (доступ только для root)
sudo chmod 600 /swapfile

# 3. Отформатировать как swap
sudo mkswap /swapfile

# 4. Активировать
sudo swapon /swapfile

# 5. Добавить в `/etc/fstab` для постоянного подключения
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Анализ давления на память и Swap

Когда сервер медленно отвечает, но RAM вроде свободна, обычные `top`/`free` часто ничего не показывают. Эти команды позволяют увидеть скрытые "тормоза" памяти, указывающие на проблемы с производительностью из-за памяти или swap-активности.

Дополнительные инструменты диагностики:

* **`vmstat`** — детальная статистика по swap-in/swap-out и давлению памяти. Подробнее: [vmstat](../../Diagnostics/Memory/vmstat.md).
* **`pmap`** — анализ распределения памяти процесса. Подробнее: [pmap](../../Diagnostics/Memory/pmap.md).
* **`/proc/meminfo`** — исчерпывающая статистика по памяти системы. Подробнее: [proc_meminfo](../../Diagnostics/Memory/proc_meminfo.md).

1. **Проверяем, сколько страниц реально перемещается в swap**

    ```bash
    cat /proc/vmstat | grep -E 'pswpin|pswpout'
    ```

    Показывает количество страниц, записанных в swap (`pswpout`) и считанных обратно (`pswpin`). Даже если `RSS` процессов низкий, высокая активность этих счётчиков говорит о постоянном I/O swap. Высокие значения `pswpin` и `pswpout` могут указывать на то, что системе не хватает оперативной памяти, и она активно использует раздел подкачки, что замедляет работу.
2. **Смотрим давление памяти на уровне ядра**

    ```bash
    cat /proc/zoneinfo | less
    ```

    Отображает, какие зоны памяти (DMA, Normal, HighMem) близки к исчерпанию. Столбцы `nr_free_pages` и `low` помогают понять, когда ядро начинает активно использовать swap или `kswapd`. Подробнее о `kswapd` и reclaim-процессах: [кэширование и освобождение памяти](caching_and_reclaiming.md).
3. **Динамика использования swap и RAM по [cgroups](../cgroups.md) (для контейнеров/VM)**

    ```bash
    cat /sys/fs/cgroup/memory/<cgroup>/memory.stat
    ```

    Смотрим `total_rss`, `total_swap`, `unevictable`. Для production-контейнеров это часто более точный показатель нагрузки, чем `top` внутри контейнера. `<cgroup>` здесь — это путь к конкретной контрольной группе.
4. **Проверяем активность `kswapd` и reclaim процессов**

    ```bash
    pidstat -t -p $(pgrep -d, kswapd0) 1
    ```

    Показывает, сколько CPU тратит демон управления памятью (`kswapd`) на очистку и свопинг. Полезно, когда сервер медленно реагирует, но `load average` низкий. Высокое потребление CPU `kswapd` сигнализирует о том, что ядро тратит много ресурсов на управление памятью, пытаясь предотвратить OOM.

### Диагностика Page Faults

**Page faults** замедляют приложение, даже если CPU свободен. Время уходит не в вычисления, а в обработку отказов страниц — особенно **major faults** с чтением с диска.

**Типы page faults:**

- **Minor fault (мягкий отказ):** Страница уже в RAM, но отсутствует в таблице страниц процесса. Обрабатывается быстро, без I/O.
- **Major fault (жёсткий отказ):** Страница отсутствует в RAM и должна быть загружена с диска (из swap или файлового кэша). Вызывает задержки из-за дискового I/O.

**Инструменты диагностики:**

1. **`vmstat` — общая картина по системе**

    ```bash
    vmstat 1
    ```

    **Ключевые метрики:**
    - `si` / `so` — swap-in / swap-out (КБ/с). Ненулевые значения указывают на активный свопинг.
    - `wa` (iowait) — процент времени CPU в ожидании I/O. Рост `wa` вместе с `si`/`so` подтверждает проблемы с памятью.

    Подробное описание: [vmstat](../../Diagnostics/Memory/vmstat.md).

2. **`pidstat -r` — page faults по процессам**

    ```bash
    pidstat -r 1
    ```

    **Ключевые метрики:**
    - `minflt/s` — minor faults в секунду. Высокие значения означают интенсивную работу с памятью.
    - `majflt/s` — major faults в секунду. Рост указывает на нехватку RAM и чтение с диска.

    Сравнивайте процессы: кто генерирует больше `majflt/s`, тот создаёт нагрузку на подсистему памяти. Подробнее: [pidstat](../../Diagnostics/Processes/pidstat.md).

3. **`perf stat` — точный подсчёт faults**

    ```bash
    perf stat -e page-faults,minor-faults,major-faults <cmd>
    ```

    Даёт точное количество всех типов faults для конкретного процесса или команды.

4. **`/proc/<pid>/stat` — сырые счётчики процесса**

    ```bash
    cat /proc/<pid>/stat | awk '{print $10,$12}'
    ```

    Выводит накопленные значения minor faults (поле 10) и major faults (поле 12) для конкретного PID.

5. **`perf top` — анализ "горячих" точек кода**

    ```bash
    sudo perf top
    ```

    Если faults частые, `perf top` показывает, какие функции ядра или приложения вызывают наибольшую активность.

    Подробнее: [perf](../../Diagnostics/Performance/perf.md).

**Интерпретация результатов:**

- **Высокие `minflt/s` без роста `majflt/s`:** Нормальная работа с памятью, страницы переиспользуются из RAM.
- **Высокие `majflt/s` + рост `si`/`so`:** Критическая нехватка RAM, активный свопинг. Требуется увеличение памяти или оптимизация приложения.
- **Высокие `majflt/s` без `si`/`so`:** Приложение активно работает с файловым кэшем или mmap-файлами.

### Анализ распределения `dirty pages`

```bash
cat /proc/meminfo | grep -E 'Dirty|Writeback'
```

Если `Dirty` растёт, процессы создают много кэшируемых страниц, а ядро ещё не сбросило их на диск. Это может вызвать задержки и фоновые I/O spikes. Подробнее: [proc_meminfo](../../Diagnostics/Memory/proc_meminfo.md).

### Отключение и удаление Swap-файла

```bash
# 1. Деактивировать swap
sudo swapoff /swapfile

# 2. Удалить запись из `/etc/fstab` (если была добавлена)

# 3. Удалить сам файл
sudo rm /swapfile
```

### Тюнинг `vm.swappiness`

**Диапазон:** `vm.swappiness` имеет диапазон **0–200** (расширен с ядра Linux 3.5). Значения `101–200` делают свопинг более агрессивным, чем `100`.

| Значение | Поведение |
| :--- | :--- |
| **90+** | Агрессивный вынос анонимной памяти в swap для сохранения файлового кэша |
| **60** | Значение по умолчанию (баланс между swap и page cache) |
| **10** | Рекомендуется для серверов (приоритет сбросу файлового кэша) |
| **0–1** | Избегать swap до последней возможности (риск OOM, но не отключает swap полностью) |

**Примечание:** `swappiness=0` **не отключает swap полностью**. При высоком давлении памяти ядро всё равно будет использовать swap для предотвращения OOM.

```bash
# Проверить текущее значение
cat /proc/sys/vm/swappiness

# Временно изменить
sudo sysctl vm.swappiness=10
```

## Дополнительная информация

### Философия использования Swap: Избегать или использовать?

1. **"Swap как зло" (для production):** Любой свопинг на нагруженном сервере — это падение производительности. Предпочтительнее OOM Killer, чем медленная работа.
2. **"Swap как подушка безопасности":** Небольшой swap (1–4 ГБ) может предотвратить сбой при кратковременных пиках потребления памяти.

**Итог:** Для критичных систем планировать ресурсы без swap, но иметь небольшой "аварийный" объем — разумная практика.

### Приоритет Swap (Swap Priority)

Для нескольких swap-устройств можно задать **приоритет** (от -1 до 32767). Устройство с более высоким приоритетом используется в первую очередь.

```bash
# 1. Отключить swap
sudo swapoff /swapfile

# 2. Включить с новым приоритетом
sudo swapon /swapfile -p 10

# 3. Закрепить в /etc/fstab
# /swapfile none swap sw,pri=10 0 0
```

### Рекомендации по размеру и `swappiness`

| Сценарий | Использовать Swap? | Рекомендуемый размер | Swappiness (`vm.swappiness`) |
| :--- | :--- | :--- | :--- |
| **Рабочая станция / Ноутбук** | Да, настоятельно | >= RAM (для гибернации), иначе 4-8 ГБ. | 60 |
| **Сервер БД (PostgreSQL и др.)** | С осторожностью | 1–4 ГБ ("подушка безопасности") | 1–10 |
| **Сервер приложений** | Да | ~0.5x RAM или 4–8 ГБ | 10–30 |
| **Системы с малым RAM (< 2ГБ)** | Обязательно | 1x – 2x RAM | 60 |
| **Системы с большим RAM (> 64ГБ)** | Да, небольшой | 4–16 ГБ | 10 |

### Рефакторинг: замена LVM-раздела на swap-файл

Если swap выделен как логический том (LV) в [LVM (Logical Volume Manager)](../../FileSystems/LVM/overview_concepts.md), его можно преобразовать в swap-файл, а место отдать корневому разделу.

**Последовательность действий включает:** отключение текущего swap, удаление LVM-тома swap, расширение корневого LVM-тома и его файловой системы, а затем создание нового swap-файла. Подробные инструкции по управлению LVM-томами можно найти в разделе [Изменение размеров логических томов](../../FileSystems/LVM/management_operations.md) и [Удаление логических томов](../../FileSystems/LVM/management_operations.md). Создание swap-файла описано в этом документе выше.

> **Важно:** После таких изменений рекомендуется перезагрузка для проверки корректности конфигурации.

### Zswap и Zram: Swap в оперативной памяти

* **Zswap** — это модуль ядра Linux, который создает сжатое хранилище в оперативной памяти для страниц, которые обычно выгружались бы в swap-раздел на диске. Это позволяет:
  * Значительно **снизить I/O** на диск.
  * Ускорить работу системы при нехватке RAM.
  * Если памяти становится совсем мало, данные все равно выгружаются на дисковый swap.

* **Zram** (formerly compcache) — это модуль ядра, создающий **блочное устройство в оперативной памяти** (виртуальный диск), которое может использоваться как swap-пространство или для хранения временных данных. В отличие от zswap, zram использует отдельное пространство в RAM и не взаимодействует с дисковым swap напрямую.

  * **Использование zram как swap:**

        ```bash
        # Загрузить модуль с 2ГБ сжатого хранилища
        modprobe zram num_devices=1
        # Установить размер (в байтах или через единицы)
        echo 2G > /sys/block/zram0/disksize
        # Создать swap на устройстве
        mkswap /dev/zram0
        # Включить
        swapon /dev/zram0 -p 100
        ```

  * **Преимущества:** Эффективное использование RAM для swap-пространства (данные хранятся сжатыми). Особенно полезно на устройствах с малым объемом RAM или на embedded-системах.
  * **Недостатки:** Требует CPU ресурсов для сжатия/разжатия. Если RAM заполнена, система может начать использовать дисковый swap, что вызовет сильное замедление.

### Гибернация (Hibernation)

Гибернация — это режим, при котором все содержимое оперативной памяти сохраняется в swap-разделе (или файле), и система полностью выключается. При включении системы данные из swap загружаются обратно в RAM, восстанавливая состояние сессии.

* **Требования:** Swap-пространство должно быть больше, чем объем используемой RAM.
* **Настройка:** Требует настройки загрузчика (параметр `resume`) и, возможно, initramfs.
