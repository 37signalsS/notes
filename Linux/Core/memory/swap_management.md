## Управление Swap (файлом подкачки)

**Swap** (или файл подкачки) — это пространство на диске, которое операционная система использует, когда ей не хватает оперативной памяти (RAM). Если память заполнена, ядро Linux перемещает неактивные страницы памяти (данные) из RAM в swap-пространство, освобождая RAM для более важных задач. Это предотвращает сбои системы из-за нехватки памяти.

### Принцип работы и внутренние механизмы

#### Зачем нужна подкачка?

1.  **Выгрузка менее используемых страниц:** Если системе требуется больше памяти, чем физически доступно, ядро выгружает редко используемые страницы памяти в swap, освобождая RAM для текущего приложения, которому память нужна немедленно.
2.  **Освобождение памяти после инициализации:** Значительное количество страниц памяти может использоваться приложениями только на этапе запуска. После инициализации эти страницы становятся неактивными, и система может выгрузить их в swap, освобождая память для других приложений и дискового кэша.

#### Минусы

Основной недостаток swap — **производительность**. Операции с оперативной памятью (RAM) выполняются в наносекундах, в то время как операции с диском — в миллисекундах. Эта разница в скорости (в десятки тысяч раз) означает, что чем больше система совершает операций подкачки (swapping), тем медленнее она работает. Особенно это заметно, когда страницы постоянно выгружаются на диск, а затем почти сразу же загружаются обратно в память.

> Swap не является "аварийной" памятью на случай сбоя. Его основная задача — позволить системе более эффективно управлять имеющейся RAM.

#### Что записывается в Swap? Анонимные страницы.

В swap выгружаются так называемые **анонимные страницы** (`anonymous pages`). Это страницы памяти, которые не связаны напрямую с каким-либо файлом на диске. К ним относятся, например:
-   Память, выделенная программами для хранения переменных (стек, куча).
-   Временные данные процессов.

Такие страницы нельзя просто "удалить", когда не хватает памяти, потому что их содержимое уникально и не имеет другого источника. Если бы не было swap, их пришлось бы постоянно держать в RAM. Swap предоставляет ядру "резервное хранилище" для таких данных.

#### Связь с кэшем и "грязными страницами"

Чтобы понять роль swap, важно различать типы данных в памяти:

-   **Кэш памяти (Page Cache):** Копии данных с диска, которые система хранит в RAM для быстрого доступа. Если нужна память, страницы кэша можно безболезненно удалить — при необходимости их можно снова прочитать с диска.
-   **"Грязные" страницы (Dirty Pages):** Страницы в памяти, которые были изменены, но еще не записаны обратно на диск. Например, когда вы редактируете текстовый файл, изменения сначала попадают в память и помечаются как "грязные". Перед тем как освободить такую страницу, система **обязана** записать её содержимое на диск.
-   **Анонимные страницы:** Уникальные данные процессов, не связанные с файлами.

**Когда памяти становится мало, ядро действует по следующему алгоритму:**

1.  **Сначала удаляет чистый кэш:** Это самый простой и быстрый способ освободить память.
2.  **Записывает "грязные" страницы на диск:** Чтобы освободить эти страницы, их нужно сначала синхронизировать с файлами на диске.
3.  **Выгружает анонимные страницы в swap:** Если предыдущих шагов недостаточно, ядро начинает перемещать анонимные страницы в swap.

Таким образом, swap позволяет системе эффективно управлять памятью, сохраняя важные данные процессов (анонимные страницы) и освобождая RAM для более активных задач и дискового кэша.

#### Как ядро работает с памятью и Page Fault

Вся память в системе разбита на **страницы**. Для каждого процесса ядро поддерживает карту, которая связывает виртуальные адреса памяти процесса с физическими страницами в RAM.

Когда процесс обращается к странице памяти, **MMU (Memory Management Unit)** процессора преобразует виртуальный адрес в физический. Если страница находится в RAM, все происходит быстро.

Если же страница была выгружена в swap (или еще не загружена с диска), возникает исключительная ситуация — **Page Fault** ("ошибка страницы"). Ядро перехватывает это событие и выполняет следующие действия:
1.  Проверяет, имеет ли процесс право доступа к этой странице. Если нет — процесс получает сигнал `SEGFAULT` и аварийно завершается.
2.  Если доступ разрешен, ядро находит нужную страницу (в swap-файле или на диске), загружает её в свободный слот в RAM и обновляет карту памяти процесса.
3.  После этого процесс возобновляет свою работу с того места, где был прерван, и успешно получает доступ к данным.

### Существует два основных способа организации swap:

1.  **Swap-раздел (swap partition)**: Отдельный раздел на диске, предназначенный исключительно для подкачки.
2.  **Swap-файл (swap file)**: Специальный файл, расположенный внутри существующей файловой системы (например, `/swapfile`). Является более гибким и удобным решением.

#### Swap-раздел vs Swap-файл

Хотя исторически считалось, что отдельный раздел работает быстрее, на практике эта разница незначительна, особенно на современных дисках. Swap в виде файла позволяет на лету менять свой размер или вовсе его отключать, если экстренно понадобится доступное место. Это весомое преимущество, которое стоит использовать.

| Характеристика      | Swap-раздел                                       | Swap-файл                                           |
| ------------------- | ------------------------------------------------- | --------------------------------------------------- |
| **Производительность** | Традиционно считался быстрее, но на современных SSD разница незначительна. | Практически не уступает разделу по скорости.        |
| **Гибкость**        | **Низкая**. Размер сложно изменить без утилит для работы с разделами. | **Высокая**. Легко создать, удалить или изменить размер на лету. |
| **Использование**     | Классический подход, обязателен для старых систем. | Современный и рекомендуемый подход в большинстве случаев. |
| **Гибернация**      | Необходим для режима гибернации (сохранения состояния RAM на диск). | С современными ядрами Linux гибернация в swap-файл также возможна, но требует более сложной настройки. |

### Философия использования Swap: Избегать или использовать?

Существует два основных подхода к использованию swap в серверных окружениях:

1.  **Подход "Swap как зло":** Сторонники этого подхода утверждают, что на высоконагруженных производственных серверах swap следует отключать.
    *   **Аргументация:** Если приложению начинает не хватать оперативной памяти, его производительность при активном свопинге катастрофически падает. Пользователи сталкиваются с медленной работой сервиса, что может быть хуже, чем его полная недоступность. Отсутствие swap приводит к тому, что при нехватке памяти OOM Killer немедленно завершит "прожорливый" процесс. Это делает проблему видимой сразу, позволяя администраторам быстрее отреагировать (например, добавив RAM или оптимизировав приложение), вместо того чтобы сервис "тихо умирал" неделями.
    *   **Вывод:** Лучше спланировать систему с достаточным количеством RAM, чтобы swap не требовался. Пусть сервис упадет быстро, чем будет медленно деградировать.

2.  **Подход "Swap как подушка безопасности":** Этот подход рассматривает swap как необходимый защитный механизм.
    *   **Аргументация:** Небольшой swap-раздел (1–4 ГБ) может спасти систему от сбоя при кратковременных, неожиданных всплесках потребления памяти. Он также полезен для выгрузки неактивных страниц системных демонов, освобождая больше RAM для критически важных приложений. Некоторые приложения (например, определенные СУБД) в принципе требуют наличия swap для корректной работы.
    *   **Вывод:** Swap необходим, но его активное использование — это сигнал о нехватке RAM. `swappiness` при этом следует устанавливать в низкое значение (1-10).

**Итог:** Выбор стратегии зависит от конкретной задачи. Для домашних компьютеров и некритичных серверов наличие swap является нормой. Для высокопроизводительных систем, где деградация производительности недопустима, часто выбирают стратегию "без swap", но это требует более тщательного планирования и мониторинга ресурсов.

### Рекомендации по использованию для разных сценариев

| Сценарий | Использовать Swap? | Рекомендуемый размер | Swappiness (`vm.swappiness`) | Тип (Файл/Раздел) | Примечания |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Рабочая станция / Ноутбук** | Да, настоятельно | >= RAM (для гибернации), иначе 4-8 ГБ для систем > 8ГБ RAM. | 60 (стандарт) | Файл (гибкость) | Полезно для запуска множества приложений и необходимо для режима гибернации (suspend-to-disk). |
| **Сервер баз данных (MySQL, PostgreSQL)** | С большой осторожностью | 1–4 ГБ (как "подушка безопасности") | 1–10 | Раздел (производительность) | Активный свопинг критически снижает производительность БД. Swap здесь нужен только для предотвращения OOM killer. |
| **Сервер приложений (Web, Microservices)** | Да | 0.5x RAM или 4–8 ГБ | 10–30 | Файл (гибкость) | Предотвращает падение приложений при утечках памяти или неожиданных пиках нагрузки. |
| **Системы с малым объемом RAM (< 2ГБ)** | Обязательно | 1x – 2x RAM | 60 (стандарт) | Файл | Жизненно необходимо для работы системы. На устройствах с SD-картами (Raspberry Pi) интенсивный swap может ускорить износ карты. |

#### Создание и активация Swap-файла

Рекомендуемый способ создания swap-файла — использование утилиты `dd`, которая гарантированно запишет нули в файл, что является более надежной практикой.

```bash
# 1. Создать файл размером 1 ГБ с помощью dd
# of=/swap - путь к файлу
# bs=1024 - размер блока 1 КБ
# count=1000000 - количество блоков (1024 * 1000000 = ~1 ГБ)
sudo dd if=/dev/zero of=/swap bs=1024 count=1000000

# 2. Установить правильные права доступа (только root должен иметь доступ)
sudo chmod 0600 /swap

# 3. Отформатировать файл как swap-пространство
sudo mkswap /swap

# 4. Активировать swap-файл
sudo swapon /swap

# 5. Добавить запись в /etc/fstab для автоматического подключения при загрузке
echo '/swap swap swap defaults 0 0' | sudo tee -a /etc/fstab
```

> **Важное замечание:** Не рекомендуется создавать swap-файл с помощью `truncate` или `fallocate` (`truncate -s 1G /swap`, `fallocate -l 1G /swap`). Эти команды создают "разреженный" (sparse) файл мгновенно, не записывая в него данные физически. Для swap-файла предпочтительнее явное выделение и обнуление пространства с помощью `dd`.

#### Проверка состояния

```sh
# Показать активные swap-области
swapon --show

# Показать использование памяти и swap
free -h
```

#### Отключение и удаление Swap-файла

Если swap-файл больше не нужен, его можно отключить и удалить.

```bash
# 1. Отключить swap-файл (требуются права суперпользователя)
sudo swapoff /swap

# Чтобы отключить все активные swap-устройства:
# sudo swapoff -a

# 2. Удалить запись из /etc/fstab
# Закомментируйте или удалите строку '/swap swap swap defaults 0 0'

# 3. Удалить сам файл
sudo rm /swap
```

#### Рефакторинг: замена LVM-раздела на swap-файл

Если система использует LVM и swap выделен в виде отдельного логического тома (LV), его можно безопасно (но с осторожностью) преобразовать в swap-файл, а освободившееся место добавить к корневому разделу.

**Последовательность действий:**

1.  **Проверить список разделов:**

    ```bash
    sudo lvs
    # Пример вывода:
    # LV     VG          Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
    # root   web-01-vg   -wi-ao---- <27.51g
    # swap_1 web-01-vg   -wi-ao----  <1.54g
    ```

2.  **Отключить swap и удалить его из fstab:**

    ```bash
    # Отключить все swap-разделы
    sudo swapoff -a
    ```

    Сразу после этого **обязательно** закомментируйте или удалите соответствующую строку в `/etc/fstab`. Она может выглядеть так:
    `/dev/mapper/web--01--vg-swap_1 none swap sw 0 0`

3.  **Удалить логический том (LV) со swap:**

    ```bash
    # lvremove /dev/web-01-vg/swap_1
    # Do you really want to remove active logical volume web-01-vg/swap_1? [y/n]: y
    #   Logical volume "swap_1" successfully removed.
    ```

4.  **Расширить корневой раздел на все освободившееся место:**

    ```bash
    # lvextend -l +100%FREE /dev/web-01-vg/root
    #   Size of logical volume web-01-vg/root changed from <27.51 GiB (7042 extents) to 29.04 GiB (7435 extents).
    #   Logical volume web-01-vg/root successfully resized.
    ```

5.  **"Растянуть" файловую систему на весь раздел:**

    Увеличение раздела не означает автоматического увеличения файловой системы.

    ```bash
    # Для файловых систем ext2/ext3/ext4
    # resize2fs /dev/web-01-vg/root
    # resize2fs 1.47.2 (1-Jan-2025)
    # Filesystem at /dev/web-01-vg/root is mounted on /; on-line resizing required
    # old_desc_blocks = 4, new_desc_blocks = 4
    # The filesystem on /dev/web-01-vg/root is now 7613440 (4k) blocks long.
    ```

6.  **Проверить результат и создать swap-файл:**

    ```bash
    df -h | grep root
    # /dev/mapper/web--01--vg-root  29G  4.7G   23G  18% /
    ```
    После этого можно создавать swap-файл, как описано в инструкции выше.

> **Обязательно перезагрузите сервер** после завершения всех операций, чтобы убедиться в корректности изменений, особенно в `/etc/fstab`.

## Тюнинг параметров Swap

`vm.swappiness` — это параметр ядра Linux, который контролирует, насколько агрессивно система будет использовать swap. Значение варьируется от 0 до 100.

-   **`100`**: Максимально агрессивное использование swap. Ядро будет выгружать данные в swap очень активно.
-   **`60`**: Значение по умолчанию для большинства дистрибутивов.
-   **`10`**: Рекомендуемое значение для серверов и десктопов. Ядро будет неохотно использовать swap, предпочитая сначала очищать файловый кэш.
-   **`0 или 1`**: Ядро будет избегать swap любой ценой и прибегнет к нему только чтобы предотвратить OOM-ошибку.

**Как проверить текущее значение:**

```sh
cat /proc/sys/vm/swappiness
```

**Как временно изменить значение:**

```sh
sudo sysctl vm.swappiness=10
```

**Как изменить значение навсегда:**

Откройте файл `/etc/sysctl.conf` и добавьте или измените строку:

```
vm.swappiness=10
```

Затем примените изменения: `sudo sysctl -p`.

### Приоритет Swap (Swap Priority)

Если в системе используется несколько swap-устройств (файлов или разделов), можно задать для каждого из них **приоритет**. Устройство с более высоким приоритетом будет использоваться в первую очередь. Приоритеты могут быть в диапазоне от -1 до 32767.

Это полезно, например, если у вас есть быстрый SSD и медленный HDD. Вы можете создать swap-раздел на каждом из них и задать более высокий приоритет для swap на SSD.

**Как задать и изменить приоритет:**

1.  **Просмотр приоритетов:**

    ```sh
    swapon --show # или swapon -s
    ```

2.  **Изменение приоритета:** Нельзя изменить приоритет "на лету". Нужно сначала отключить swap, а затем включить его с новым приоритетом.

    ```bash
    # Пытаемся изменить приоритет активного swap - получаем ошибку
    sudo swapon -p 10 /swapfile
    # swapon: /swapfile: swapon failed: Устройство или ресурс занято

    # Правильный способ:
    # 1. Отключаем swap
    sudo swapoff /swapfile

    # 2. Включаем с новым приоритетом
    sudo swapon -p 10 /swapfile
    ```

3.  **Закрепление в `/etc/fstab`:** Чтобы приоритет сохранялся после перезагрузки, его нужно указать в опциях монтирования в файле `/etc/fstab`.

    ```
    # <file>        <mount point>   <type>  <options>         <dump>  <pass>
    /swapfile       none            swap    sw,pri=10         0       0
    /dev/sdb2       none            swap    sw,pri=5          0       0
    ```
