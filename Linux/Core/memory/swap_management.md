# Управление Swap (подкачкой)

## Определения

* **Swap (подкачка)** — пространство на диске, используемое ядром Linux для выгрузки неактивных [анонимных страниц](./virtual_vs_physical_memory.md) при нехватке оперативной памяти (RAM).
* **Анонимные страницы (Anonymous Pages)** — страницы памяти, не связанные с файлом на диске (стек, куча, `malloc`). При нехватке RAM выгружаются в swap. Противоположность — [file-backed страницы](./virtual_vs_physical_memory.md), которые просто удаляются из памяти и перечитываются с диска.
* **Swappiness** — параметр ядра (`vm.swappiness`, диапазон 0–200), контролирующий агрессивность использования swap-пространства. Расширен с ядра Linux 3.5. Значения `101–200` делают свопинг более агрессивным, чем `100`.
* **Swap-in (si)** — чтение страниц из swap в RAM.
* **Swap-out (so)** — запись страниц из RAM в swap.

## Основные концепции

### Зачем нужен Swap?

1. **Выгрузка неактивных данных** — редко используемые анонимные страницы переносятся в swap, освобождая RAM для дискового кэша (page cache) и активных приложений.
2. **Резервное хранилище** — swap — единственное место, куда ядро может выгрузить анонимные страницы. Без swap при исчерпании RAM срабатывает [OOM Killer](../processes/oom_killer_mechanism.md).

### Порядок освобождения памяти ядром

При нехватке RAM ядро действует в порядке приоритета (подробнее: [кэширование и освобождение памяти](caching_and_reclaiming.md)):

1. **Сброс чистого файлового кэша (page cache)** — мгновенно, страницы просто удаляются.
2. **Запись «грязных» страниц (dirty pages) на диск** — синхронизация изменённых данных.
3. **Выгрузка анонимных страниц в swap** — самый медленный вариант.
4. **OOM Killer** — если RAM и swap исчерпаны, ядро убивает процесс с наихудшим score.

### Типы Swap: Раздел vs. Файл

| Характеристика | Swap-раздел | Swap-файл |
| :--- | :--- | :--- |
| **Производительность** | Традиционно быстрее, но на современных SSD разница незначительна | Практически не уступает разделу |
| **Гибкость** | **Низкая** — размер сложно изменить | **Высокая** — легко создать, удалить, изменить размер |
| **Использование** | Классический подход | Современный и рекомендуемый |

### Тюнинг `vm.swappiness`

| Значение | Поведение |
| :--- | :--- |
| **90+** | Агрессивный вынос анонимной памяти в swap для сохранения файлового кэша |
| **60** | Значение по умолчанию (баланс между swap и page cache) |
| **10** | Рекомендуется для серверов (приоритет сбросу файлового кэша) |
| **0–1** | Избегать swap до последней возможности (риск OOM, но **не отключает** swap полностью) |

> **Примечание:** `swappiness=0` не отключает swap полностью. При высоком давлении памяти ядро всё равно будет использовать swap для предотвращения OOM.

**Рекомендации по сценариям:**

| Сценарий | Swappiness |
| :--- | :--- |
| General-purpose / Kubernetes | 60 (по умолчанию) |
| Серверы приложений | 10–30 |
| Базы данных (PostgreSQL, MySQL, Oracle) | 1–10 |
| Системы с большим файловым кэшем | 90+ |

```bash
# Проверить текущее значение
cat /proc/sys/vm/swappiness

# Временно изменить
sudo sysctl vm.swappiness=10

# Постоянно изменить (добавить в /etc/sysctl.conf)
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

Подробнее о `sysctl` см. в [sysctl — управление параметрами ядра](../kernel/sysctl.md).

## Практические сценарии

### Проверка состояния swap

```bash
# Показать активные swap-устройства
swapon --show

# Показать использование RAM и swap
free -h

# Подробная информация по swap-устройствам
swapon -s
```

### Создание Swap-файла (рекомендуемый способ)

Рекомендуется использовать `fallocate` для мгновенного резервирования места:

```bash
# 1. Создать файл размером 4 ГБ
sudo fallocate -l 4G /swapfile

# 2. Установить права (доступ только для root)
sudo chmod 600 /swapfile

# 3. Отформатировать как swap
sudo mkswap /swapfile

# 4. Активировать
sudo swapon /swapfile

# 5. Добавить в /etc/fstab для постоянного подключения
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Отключение и удаление Swap-файла

```bash
# 1. Деактивировать swap
sudo swapoff /swapfile

# 2. Удалить запись из /etc/fstab (если была добавлена)

# 3. Удалить сам файл
sudo rm /swapfile
```

### Приоритет Swap (Swap Priority)

Для нескольких swap-устройств можно задать приоритет (от -1 до 32767). Устройство с более высоким приоритетом используется в первую очередь:

```bash
# Включить с приоритетом 10
sudo swapon /swapfile -p 10

# Закрепить в /etc/fstab
# /swapfile none swap sw,pri=10 0 0
```

### Рекомендации по размеру

| Сценарий | Использовать Swap? | Рекомендуемый размер |
| :--- | :--- | :--- |
| **Рабочая станция / Ноутбук** | Да, настоятельно | >= RAM (для гибернации), иначе 4–8 ГБ |
| **Сервер БД (PostgreSQL, MySQL)** | С осторожностью | 1–4 ГБ («подушка безопасности») |
| **Сервер приложений** | Да | ~0.5x RAM или 4–8 ГБ |
| **Системы с малым RAM (< 2 ГБ)** | Обязательно | 1x – 2x RAM |
| **Системы с большим RAM (> 64 ГБ)** | Да, небольшой | 4–16 ГБ |
| **Kubernetes-ноды** | Отключён (требование kubelet) | 0 |
| **Elasticsearch** | Отключён (избегать GC пауз) | 0 |

> Подробнее об отключении swap для Kubernetes: [Подготовка ноды](../../../Kubernetes/Installation/HA_Cluster_Bare_Metal/k8s_ha_node_preparation.md).

## Дополнительная информация

### Философия использования Swap: Избегать или использовать?

1. **«Swap как зло» (для production)** — любой свопинг на нагруженном сервере означает падение производительности. Для критичных систем предпочтительнее OOM Killer, чем медленная работа.
2. **«Swap как подушка безопасности»** — небольшой swap (1–4 ГБ) может предотвратить сбой при кратковременных пиках потребления памяти.

**Итог:** Для критичных систем планировать ресурсы без swap, но иметь небольшой «аварийный» объём — разумная практика.

### Zswap и Zram: Swap в оперативной памяти

* **Zswap** — модуль ядра, создающий сжатое хранилище в RAM для страниц, которые обычно выгружались бы на диск. Снижает I/O, ускоряет работу при нехватке RAM. При полном заполнении данные сбрасываются на дисковый swap.
* **Zram** — модуль ядра, создающий блочное устройство в RAM (виртуальный диск), используемое как swap-пространство. В отличие от zswap, не взаимодействует с дисковым swap напрямую.

**Использование zram как swap:**

```bash
# Загрузить модуль
modprobe zram num_devices=1

# Установить размер
echo 2G > /sys/block/zram0/disksize

# Создать и активировать swap
mkswap /dev/zram0
swapon /dev/zram0 -p 100
```

**Преимущества:** Эффективное использование RAM (данные хранятся сжатыми). Полезно для систем с малым объёмом RAM и embedded-устройств.

**Недостатки:** Требует CPU-ресурсов для сжатия/разжатия. При заполнении RAM система начнёт использовать дисковый swap, что вызовет сильное замедление.

### Гибернация (Hibernation)

Режим, при котором содержимое RAM сохраняется в swap и система полностью выключается. При включении данные загружаются обратно, восстанавливая сессию.

* **Требования:** Swap-пространство должно быть больше объёма используемой RAM.
* **Настройка:** Требует настройки загрузчика (параметр `resume`) и initramfs.

### Рефакторинг: замена LVM-раздела на swap-файл

Если swap выделен как логический том в [LVM](../../FileSystems/LVM/overview_concepts.md), его можно преобразовать в swap-файл, а место отдать корневому разделу:

1. Отключить текущий swap (`swapoff`).
2. Удалить LVM-том swap.
3. Расширить корневой LVM-том и файловую систему.
4. Создать swap-файл (см. [Создание Swap-файла](#создание-swap-файла-рекомендуемый-способ)).

> **Важно:** После таких изменений рекомендуется перезагрузка для проверки корректности конфигурации.
