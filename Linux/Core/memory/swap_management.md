# Управление Swap (подкачкой) в Linux

## Определения

* **Swap (подкачка)** — пространство на дисковом носителе, используемое ядром Linux для выгрузки неактивных анонимных страниц при дефиците оперативной памяти (RAM — Random Access Memory).
* **Анонимные страницы (Anonymous Pages)** — сегменты памяти, не связанные с файлом на диске (стек процесса, куча, данные, выделенные через `malloc`). При нехватке оперативной памяти они выгружаются в swap.
* **File-backed страницы** — страницы памяти, отображенные на файлы (программы, библиотеки, данные). При нехватке памяти они могут быть просто удалены из RAM, так как их можно повторно прочитать с диска.
* **Swappiness** — параметр ядра (`vm.swappiness`), определяющий баланс между вытеснением анонимных страниц и очисткой файлового кэша. В современных ядрах (>= 5.8) диапазон значений расширен до 200.
* **MGLRU (Multi-Gen LRU)** — современная реализация алгоритма LRU (Least Recently Used), доступная с ядра 6.1. Группирует страницы в "поколения", что значительно повышает точность выбора кандидатов на выгрузку и эффективность работы swap.
* **Swap-in (si) / Swap-out (so)** — операции чтения из swap в RAM и записи из RAM в swap соответственно.
* **PSI (Pressure Stall Information)** — механизм ядра для отслеживания задержек (stalls), вызванных нехваткой памяти, CPU или I/O. Позволяет точно оценить, как часто процессы ждут освобождения памяти или работы swap.

## Основные концепции

### Назначение Swap

1. **Высвобождение ресурсов** — редко используемые анонимные страницы перемещаются в swap, освобождая оперативную память для активных приложений и дискового кэша (page cache).
2. **Предотвращение OOM (Out Of Memory)** — наличие swap дает ядру "подушку безопасности" для маневра при всплесках потребления памяти. Без swap при исчерпании RAM немедленно вызывается **[OOM Killer](../processes/oom_killer_mechanism.md)**.
3. **Эффективное использование RAM** — swap позволяет системе держать в памяти больше полезных данных (файлового кэша) вместо "мертвых" страниц фоновых служб.

### Алгоритм освобождения памяти (Reclaim)

При дефиците RAM ядро выполняет очистку в следующем приоритете (подробнее: **[кэширование и освобождение памяти](caching_and_reclaiming.md)**):

1. **Освобождение чистого файлового кэша** — страницы, не измененные с момента чтения с диска.
2. **Сброс "грязных" страниц (Dirty Pages)** — запись измененных данных на диск перед удалением из RAM.
3. **Выгрузка анонимных страниц в swap** — перемещение данных в пространство подкачки.
4. **Активация OOM Killer** — крайняя мера, если все вышеуказанные шаги не освободили достаточно памяти.

### Выбор типа Swap: Раздел против Файла

| Характеристика | Swap-раздел | Swap-файл |
| :--- | :--- | :--- |
| **Производительность** | Традиционно считался быстрее, но на современных SSD/NVMe разница отсутствует. | Идентична разделу. |
| **Гибкость** | **Низкая** — требует переразметки диска. | **Высокая** — легко изменить размер или удалить. |
| **Применение** | Устаревающий стандарт. | Современный стандарт (Ubuntu, Fedora, Arch). |

### Настройка параметра vm.swappiness

Параметр определяет соотношение "стоимости" выгрузки анонимных и файловых страниц.
* **0–10**: Минимальное использование swap. Рекомендуется для баз данных (PostgreSQL, MySQL), чтобы избежать задержек.
* **60**: Значение по умолчанию (баланс).
* **100**: Равный приоритет между очисткой кэша и использованием swap.
* **101–200 (ядро >= 5.8)**: Агрессивная выгрузка в swap. Полезно, если файловый кэш критически важен для производительности.

```bash
# Просмотр текущего значения
cat /proc/sys/vm/swappiness

# Временное изменение
sudo sysctl -w vm.swappiness=10
```

Подробное описание тюнинга: **[Оптимизация и тонкая настройка памяти](./performance_tuning.md)**.

## Практические сценарии

### Инспекция текущего состояния

```bash
# Список активных устройств и их использование
swapon --show

# Сводная информация по памяти
free -h

# Проверка PSI (если включено в ядре)
cat /proc/pressure/memory
# → some avg10=0.00 avg60=0.00 avg300=0.00 total=0
```

### Создание Swap-файла (Standard)

Для файловых систем ext4 и XFS:
```bash
# 1. Создание файла (4 ГБ)
sudo fallocate -l 4G /swapfile

# 2. Установка прав (критично для безопасности!)
sudo chmod 600 /swapfile

# 3. Форматирование
sudo mkswap /swapfile

# 4. Включение
sudo swapon /swapfile

# 5. Автозагрузка (/etc/fstab)
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Создание Swap-файла (BTRFS)

На BTRFS требуются дополнительные шаги для отключения CoW (Copy-on-Write) и компрессии:
```bash
# 1. Создание пустого файла
sudo truncate -s 0 /swapfile

# 2. Отключение CoW
sudo chattr +C /swapfile

# 3. Отключение компрессии (если используется)
sudo btrfs property set /swapfile compression none

# 4. Выделение размера и форматирование
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

### Приоритеты устройств подкачки

Если у вас несколько устройств (например, Zram и SSD), можно задать приоритет (чем выше число, тем выше приоритет):
```bash
# Включение с приоритетом 100
sudo swapon /dev/zram0 -p 100

# В /etc/fstab
/dev/zram0 none swap pri=100 0 0
```

### Рекомендации по объему

| Тип системы | Рекомендация | Комментарий |
| :--- | :--- | :--- |
| **Десктоп** | RAM + 2 ГБ | Для поддержки гибернации. |
| **Сервер БД** | 1–4 ГБ | "Подушка" для защиты от OOM при пиках. |
| **Kubernetes Node** | **Включен** (>= 1.28) | Раньше требовалось отключать, теперь поддерживается официально. |
| **Zram / Zswap** | 50% от RAM | Оптимально для систем с быстрым CPU и медленным диском. |

## Дополнительная информация

### Zswap и Zram: Сжатие в RAM

* **Zswap**: Сжимает страницы, которые направляются в swap, и хранит их в специальном пуле в RAM. Если пул переполняется, сжатые данные сбрасываются на физический диск.
* **Zram**: Создает виртуальное блочное устройство со сжатием. Часто используется как единственный swap на бездисковых системах или в контейнерах.

**Современная настройка (zram-generator):**
В современных дистрибутивах (Fedora, RHEL) используется `zram-generator`.
Конфигурация `/etc/systemd/zram-generator.conf`:
```ini
[zram0]
zram-size = ram / 2
compression-algorithm = zstd
```

### Гибернация (Hibernation)

Для гибернации размер swap должен быть не меньше объема используемой RAM. Также необходимо настроить параметр загрузчика `resume=UUID=<swap_partition_uuid>`.
