# Планирование процессов в Linux

## Определения

**Планировщик ядра (Scheduler)** — высокопроизводительный компонент ядра Linux, определяющий очередность и продолжительность выполнения задач на центральном процессоре (CPU). Его цель — обеспечить баланс между пропускной способностью системы и минимальными задержками (latency) для интерактивных приложений.

**Переключение контекста (Context Switching)** — процедура сохранения состояния текущего процесса (регистры, стек, программный счетчик) и восстановления состояния другого процесса. Различают два типа:
- **Добровольное (Voluntary):** Процесс сам отдает CPU, ожидая завершения ввода-вывода или засыпая.
- **Принудительное (Involuntary):** Планировщик прерывает процесс по истечении его кванта времени (preemption) или при появлении более приоритетной задачи.

**Средняя нагрузка (LA — Load Average)** — показатель, отражающий среднее количество задач в состояниях выполнения (Running), готовности к выполнению (Runnable) или непрерываемого сна (Uninterruptible Sleep / D-state). Рассчитывается как экспоненциально взвешенное скользящее среднее (EWMA) за периоды в 1, 5 и 15 минут.

**Очередь выполнения (Runqueue)** — фундаментальная структура данных ядра, содержащая список всех задач в состоянии готовности. В SMP-системах (Symmetric Multi-Processing) каждое ядро CPU имеет собственную индивидуальную очередь.

Подробнее о состояниях процессов см. в разделе [**Основные концепции**](./basic_concepts.md#состояния-процесса).

## Основные концепции

### Эволюция планировщиков Linux

В Linux фундаментальной единицей планирования является **"задача" (task)**. Ядро не делает различий между процессами и потоками — каждый поток рассматривается как отдельная задача.

| Версия ядра | Планировщик | Описание |
| :--- | :--- | :--- |
| **2.6.23 – 6.5** | **CFS (Completely Fair Scheduler)** | Использовал виртуальное время выполнения (`vruntime`) и красно-черные деревья для балансировки. |
| **6.6+ (октябрь 2023)** | **EEVDF (Earliest Eligible Virtual Deadline First)** | Текущий планировщик по умолчанию. Обеспечивает более точное соблюдение приоритетов и низкую латентность. |
| **6.12+ (ноябрь 2024)** | **EEVDF** | Код устаревшего CFS полностью удален из исходного кода ядра. |

#### Принцип работы EEVDF

Планировщик **EEVDF** заменяет концепцию накопления `vruntime` на расчет времени готовности и дедлайнов:
- **Eligible Time (Время готовности):** Момент времени, когда задача теоретически должна получить доступ к ресурсам CPU с учетом её приоритета (`nice`) и веса.
- **Virtual Deadline (Виртуальный дедлайн):** Срок, к которому задача должна завершить свой очередной квант времени.
- **Выбор задачи:** Планировщик выбирает задачу с самым ранним виртуальным дедлайном среди всех готовых к выполнению.

**Преимущества перед CFS:**
- Снижение задержек для интерактивных приложений (задачи с коротким квантом получают CPU быстрее).
- Более предсказуемое поведение `nice`: теперь он напрямую влияет на дедлайн, а не только на скорость накопления времени.

### Классы и политики планирования

| Класс | Политика | Описание |
| :--- | :--- | :--- |
| `SCHED_NORMAL` | EEVDF | Стандартные процессы (по умолчанию). |
| `SCHED_BATCH` | Пакетный | Оптимизация для длительных вычислений, реже переключает контекст. |
| `SCHED_IDLE` | Фоновый | Минимальный приоритет (ниже nice 19). |
| `SCHED_FIFO` | RT FIFO | Реальное время: выполняется до завершения или вытеснения более высоким RT-приоритетом. |
| `SCHED_RR` | RT Round-Robin | Реальное время: циклическое планирование с фиксированным квантом времени. |
| `SCHED_DEADLINE` | RT Deadline | Гарантированное время выполнения (CBS). Использует Runtime, Deadline и Period. |

### Приоритеты процессов: nice и PR

1. **`NI` (Nice):** Значение от `-20` (высший) до `+19` (низший). По умолчанию `0`. Влияет на "вес" задачи в планировщике.
2. **`PR` (Priority):** Реальный приоритет в ядре. Для обычных процессов: `PR = 20 + NI`. Для RT-процессов отображается как `RT` или отрицательное число.

### Интерпретация Load Average

В расчет LA включаются процессы в состоянии непрерываемого сна (**D-state**), ожидающие I/O. Поэтому высокий LA при низком %CPU — признак проблем с диском или сетью (NFS).

**Связь с количеством ядер CPU (N):**
- `LA ≈ N`: Система загружена полностью, очередей нет.
- `LA > N`: Задачи стоят в очереди. Если LA значительно превышает N, производительность деградирует.
- `LA < N`: Имеется запас вычислительной мощности.

**Пример для 4-ядерной машины:**
- `LA = 1.0` ≈ 25% загрузки CPU
- `LA = 4.0` ≈ 100% (все ядра заняты)
- `LA = 6.0` — очередь переполнена, задачи ждут.

### Источники данных: /proc/uptime и /proc/loadavg

Данные берутся напрямую из ядра через `procfs`:

- **`/proc/uptime`:** Два числа — общее время работы (сек) и суммарное время бездействия всех ядер.
- **`/proc/loadavg`:** Пять полей: LA за 1, 5, 15 минут; количество активных / общее число процессов; PID последнего созданного процесса.

```bash
# Просмотр /proc/loadavg напрямую
cat /proc/loadavg
# → 0.50 0.40 0.30 1/800 12345
#   ↑ LA1  ↑ LA5  ↑ LA15 ↑ активные/всего ↑ последний PID
```

### Математика Load Average: EWMA

Три значения LA — это экспоненциально взвешенное скользящее среднее (EWMA), где активность последнего временного окна имеет наибольший вес:
- **LA1** ≈ 63% активности за последнюю минуту + 37% предыстории.
- LA5 и LA15 имеют более "тяжелую" память о прошлых событиях.

## Практические сценарии

### Управление приоритетами (nice, renice)

```bash
# Запуск с низким приоритетом
nice -n 19 tar -czf backup.tar.gz /data

# Повышение приоритета работающего процесса (только root)
sudo renice -n -5 -p 1234
```

### Управление политиками реального времени (chrt)

```bash
# Запуск с политикой SCHED_RR и приоритетом 50
chrt -r 50 ./my_app

# Просмотр текущей политики
chrt -p 1234
```

### Привязка к ядрам (taskset)

Позволяет закрепить процесс за ядрами (CPU Affinity) для исключения миграции и улучшения работы L-кэша.

```bash
# Запуск на 0-м и 1-м ядрах
taskset -c 0,1 ./my_app
```

### Мониторинг переключений контекста (pidstat)

```bash
# Просмотр переключений каждые 2 секунды
pidstat -w 2
# → cswch/s (добровольные), nvcswch/s (принудительные)
```

### Диагностика узких мест

| Симптом | Вероятная причина | Инструменты |
| :--- | :--- | :--- |
| **Высокий LA + Высокий %CPU** | Нехватка CPU (CPU bottleneck) | `top`, `htop`, `pidstat` |
| **Высокий LA + Высокий %iowait** | Ожидание диска (I/O bottleneck) | `iotop`, `iostat -x 1` |
| **Высокий LA + Низкий %CPU** | Блокировки в ядре, сеть/NFS | `dstat`, `strace`, `PSI` |

## Дополнительная информация

### Информация о давлении на ресурсы (PSI)

**Pressure Stall Information (PSI)** — современный механизм для точного определения времени простоя из-за нехватки CPU, памяти или I/O. В отличие от LA, PSI четко разделяет причины.
Подробнее см. раздел [**PSI — статистика давления на ресурсы**](../kernel/psi.md).

### Влияние планировщика на ввод-вывод

Для управления приоритетами диска используются I/O Schedulers и утилита `ionice`.
Подробнее см. раздел [**Планировщики ввода-вывода**](../kernel/io_schedulers.md).
