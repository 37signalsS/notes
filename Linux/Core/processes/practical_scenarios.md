# Процессы в Linux: Практические сценарии

## Жизненный цикл выполнения команды в Shell

1. **Ожидание ввода:** Родительский процесс (оболочка `bash`, `zsh` и т.д.) ожидает ввода команды.
2. **Создание дочернего процесса (`fork`):** Как только вы нажимаете Enter, оболочка выполняет системный вызов `fork()`. Это создает точную копию процесса оболочки (дочерний процесс).
3. **Ожидание родителя (`wait`):** Оригинальный процесс оболочки (родитель) теперь выполняет системный вызов `wait()` (или `waitpid()`), который приостанавливает его и заставляет ждать, пока дочерний процесс не завершится.
4. **Замена процесса (`exec`):** Дочерний процесс выполняет системный вызов `exec()` (например, `execve`). Этот вызов заменяет код и память дочернего процесса (который до этого был копией `bash`) кодом и памятью программы `ls`. PID процесса при этом не меняется.
5. **Выполнение команды:** Процесс `ls` выполняется, выводит список файлов и директорий на стандартный вывод.
6. **Завершение (`exit`):** После успешного выполнения `ls` выполняет системный вызов `exit()`. Ядро освобождает ресурсы процесса и переводит его в состояние "зомби".
7. **Сигнал родителю (`SIGCHLD`):** Ядро отправляет родительскому процессу (оболочке) сигнал `SIGCHLD`, сообщая, что дочерний процесс завершился.
8. **Пробуждение родителя:** Сигнал `SIGCHLD` "пробуждает" родительскую оболочку от вызова `wait()`. Оболочка "собирает" информацию о статусе завершения дочернего процесса (тем самым "убивая" зомби) и выводит новое приглашение командной строки, готовая к следующей команде.

## Анализ и мониторинг процессов

### Виртуальная файловая система /proc

Ядро Linux представляет информацию о запущенных процессах и другие системные данные через специальную виртуальную файловую систему **procfs**, монтируемую в директорию `/proc`. Она существует только в оперативной памяти и генерируется "на лету".

- **`/proc/<PID>/`**: Директории, названные по PID'ам процессов. Содержат файлы с детальной информацией о каждом процессе:
  - `cmdline`: Команда, которой был запущен процесс.
  - `environ`: Переменные окружения процесса.
  - `status`: Структурированная информация о состоянии (PID, PPID, UID, GID, потребление памяти и др.).
  - `fd/`: Директория с символическими ссылками на открытые файловые дескрипторы.
- **`/proc/[файл]`**: Файлы с общесистемной информацией, например:
  - `version`: Версия ядра Linux.
  - `uptime`: Время работы системы.
  - `meminfo`: Информация о состоянии оперативной памяти.
  - `cpuinfo`: Информация о процессоре.

### Утилита `ps`

Утилита `ps` (process status) используется для просмотра "снимка" информации о текущих процессах.

**Ключи `ps`:**

- **Unix-style (с одним дефисом)**: `-e` (показать все процессы), `-f` (полный формат вывода).
- **BSD-style (без дефиса)**: `aux` (`a` - все процессы с терминалом, `u` - информация о владельце, `x` - все процессы без терминала).
- **GNU-style (с двумя дефисами)**: `--forest` (показать дерево процессов).

**Пример использования `ps -ef`:**

```bash
ps -ef | less -S
```

Вывод передается `less -S` для удобного просмотра без переноса строк.

**Основные столбцы вывода `ps -ef`:**

- **UID**: User ID — пользователь, запустивший процесс.
- **PID**: Process ID — идентификатор процесса.
- **PPID**: Parent Process ID — идентификатор родительского процесса.
- **C**: CPU utilization — использование CPU.
- **STIME**: Start time — время запуска процесса.
- **TTY**: Teletype — терминал, с которым связан процесс. `?` означает отсутствие терминала.
- **TIME**: CPU Time — общее процессорное время, затраченное на выполнение процесса.
- **CMD**: Command — команда, запустившая процесс.

### Динамический мониторинг с `watch`

Команда `watch` позволяет периодически выполнять другую команду, отображая ее вывод на экране. Это удобно для наблюдения за изменяющимися параметрами процессов.

```bash
# Обновлять вывод ps -ef каждые 2 секунды
watch "ps -ef"
```

## Получение информации о процессах

**Вариант получения PID и PPID:**

```sh
pstree -p
```

**Узнать PID процесса:**

```sh
pidof <name>
```

```sh
pgrep <name>
```

## Таблица состояний процессов

| Состояние | Описание | Когда возникает |
|-----------|----------|-----------------|
| **R** | Running/Runnable | Процесс выполняется или готов к выполнению |
| **S** | Sleeping | Процесс ожидает события (прерываемый сон) |
| **D** | Disk Sleep | Процесс ожидает I/O (непрерываемый сон) |
| **T** | Stopped | Процесс остановлен сигналом SIGSTOP/SIGTSTP |
| **Z** | Zombie | Процесс завершился, но родитель не забрал статус |
| **I** | Idle | Процесс бездействует |
