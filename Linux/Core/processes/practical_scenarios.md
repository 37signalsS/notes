# Process Monitoring and Practical Scenarios

## Определения

**Process Monitoring (мониторинг процессов)** — практика наблюдения за состоянием, ресурсами и жизненным циклом процессов в реальном времени или через периодические снимки.

Основные концепции процессов, жизненный цикл команд и описание утилит `ps`, `pstree`, `pidof`, `pgrep` см. в [**Basic Concepts**](./basic_concepts.md).

## Основные концепции

### Уровни мониторинга

| Уровень | Инструменты | Когда использовать |
| :--- | :--- | :--- |
| **Снимок (snapshot)** | `ps`, `pstree` | Быстрый анализ текущего состояния |
| **Динамическое наблюдение** | `watch`, `top`, `htop` | Отслеживание изменений в реальном времени |
| **Детализация процесса** | `/proc/<PID>/`, `strace` | Глубокая диагностика конкретного процесса |
| **Дерево зависимостей** | `pstree --forest` | Визуализация иерархии процессов |

### Виртуальная файловая система /proc

**procfs** — виртуальная файловая система ядра Linux, монтируемая в `/proc`. Существует только в RAM, генерируется динамически.

- **`/proc/<PID>/`** — информация о процессе:
  - `cmdline` — команда запуска (без пробелов, разделены `\0`)
  - `environ` — переменные окружения процесса
  - `status` — структурированные данные: PID, PPID, UID, GID, состояние памяти
  - `fd/` — символические ссылки на открытые файловые дескрипторы
  - `limits` — ресурсные лимиты процесса
  - `maps` — отображения памяти процесса
  - `stat` — статистика CPU, memory, I/O
- **`/proc/[файл]`** — общесистемная информация:
  - `version` — версия ядра
  - `uptime` — время работы системы
  - `meminfo` — состояние памяти
  - `cpuinfo` — информация о CPU
  - `loadavg` — средняя загрузка системы

## Практические сценарии

### Анализ состояния процесса через /proc

```bash
# Просмотр команды запуска (с разделителями)
cat /proc/<PID>/cmdline | tr '\0' ' '

# Переменные окружения процесса
cat /proc/<PID>/environ | tr '\0' '\n'

# Детальный статус процесса
cat /proc/<PID>/status

# Открытые файловые дескрипторы
ls -la /proc/<PID>/fd/

# Ресурсные лимиты
cat /proc/<PID>/limits

# Отображения памяти
cat /proc/<PID>/maps | head -20
```

### Динамический мониторинг с `watch`

Команда `watch` периодически выполняет команду и выводит результат на экран:

```bash
# Обновление каждые 2 секунды (по умолчанию)
watch "ps -ef | grep my-app"

# Обновление каждые 1 секунду
watch -n 1 "ps aux --sort=-%mem | head -20"

# Подсветка изменений (highlight)
watch -d "ps -eo pid,ppid,stat,%mem,%cpu,comm --sort=-%mem"

# Вывод заголовка с временем последнего обновления
watch -t "cat /proc/uptime"
```

### Быстрые справочные команды

```bash
# Полное дерево процессов с PID и именами команд
pstree -p -a

# Дерево с подробной информацией
pstree -p -u -a

# Найти PID процесса по имени (возвращает все совпадения)
pgrep -a my-app

# Найти PID точного имени исполняемого файла
pidof nginx

# Посмотреть родительский процесс процесса
ps -o pid,ppid,comm -p <PID>

# Какие процессы принадлежат пользователю
ps -u username -f

# Сортировка по потреблению памяти
ps aux --sort=-%mem | head -10

# Сортировка по потреблению CPU
ps aux --sort=-%cpu | head -10
```

### Диагностика аномальных процессов

```bash
# Определить путь к исполняемому файлу процесса
ls -la /proc/<PID>/exe

# Определить рабочую директорию процесса
ls -la /proc/<PID>/cwd

# Показать командную строку процесса без обрезки
cat /proc/<PID>/cmdline | tr '\0' ' ' && echo

# Определить, сколько памяти потребляет процесс
grep VmRSS /proc/<PID>/status
```

## Дополнительная информация

### Почему `watch` вместо постоянного `ps`

`watch` не потребляет ресурсы на постоянное выполнение команды — он выполняет команду периодически и показывает разницу с предыдущим выводом (с флагом `-d`). Это эффективнее, чем ручной запуск `ps` в цикле.

### Отличие `pidof` от `pgrep`

| Утилита | Поведение | Когда использовать |
| :--- | :--- | :--- |
| `pidof` | Ищет по точному имени исполняемого файла | Когда известно точное имя binary |
| `pgrep` | Ищет по шаблону в командной строке | Для поиска по части имени, аргументам, пользователю |

### Примечание о /proc

Файлы `/proc/<PID>/` существуют только пока жив процесс. При завершении процесса его директория в `/proc` удаляется автоматически. Файлы в `/proc` не занимают дисковое пространство — они генерируются ядром при чтении.
