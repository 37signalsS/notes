# Практические сценарии мониторинга процессов

## Определения

**Мониторинг процессов (Process Monitoring)** — это совокупность методов и инструментов для наблюдения за состоянием, использованием ресурсов и жизненным циклом выполняющихся в системе задач в режиме реального времени.

**Виртуальная файловая система /proc (procfs)** — интерфейс ядра Linux, представленный в виде файловой системы, который позволяет получать детальную информацию о процессах и изменять параметры ядра "на лету" без прямого доступа к памяти.

Базовые понятия процессов, жизненный цикл команд и описание основных утилит приведены в разделе [**Основные концепции**](./basic_concepts.md).

## Основные концепции

### Уровни наблюдения за системой

Для эффективной диагностики используются различные подходы в зависимости от глубины требуемого анализа:

| Уровень | Инструментарий | Сценарий использования |
| :--- | :--- | :--- |
| **Снимок состояния** | `ps`, `pstree`, `pgrep` | Быстрое получение информации о текущем наборе процессов. |
| **Интерактивный мониторинг** | `top`, `htop`, `atop` | Поиск процессов-потребителей CPU и RAM в реальном времени. |
| **Детальная диагностика** | `/proc/<PID>/`, `strace` | Глубокий анализ конкретной задачи, её системных вызовов и ресурсов. |
| **Событийный мониторинг** | `watch`, `dmesg`, `ebpf` | Отслеживание изменений состояния и аномального поведения. |

### Структура директории /proc/<PID>

Для каждого запущенного процесса ядро создает виртуальную директорию, содержащую актуальные данные о его работе:

- `cmdline` — полная командная строка запуска.
- `environ` — переменные окружения процесса.
- `status` — сводная информация: PID, PPID (Parent PID), UID (User ID), состояние памяти (RSS — Resident Set Size).
- `fd/` — список открытых файловых дескрипторов (файлы, сокеты, каналы).
- `limits` — текущие лимиты ресурсов процесса. Подробнее см. [**Использование ulimit**](./ulimit_usage.md).
- `stat` — статистические показатели для автоматизированного сбора метрик.

## Практические сценарии

### Анализ параметров процесса через /proc

В ситуациях, когда стандартных утилит недостаточно, прямое чтение из `/proc` дает наиболее полную картину:

```bash
# Чтение команды запуска (замена нулевых байтов пробелами)
cat /proc/<PID>/cmdline | tr '\0' ' ' && echo

# Просмотр переменных окружения процесса
cat /proc/<PID>/environ | tr '\0' '\n'

# Проверка использования оперативной памяти (RSS)
grep VmRSS /proc/<PID>/status

# Анализ открытых файлов и соединений
ls -la /proc/<PID>/fd/
```

### Мониторинг изменений с помощью утилиты `watch`

Утилита `watch` позволяет автоматизировать наблюдение за выводом команд, обновляя его через заданный интервал времени:

```bash
# Отслеживание появления конкретного процесса (обновление каждую секунду)
watch -n 1 "ps aux | grep nginx"

# Поиск процессов с максимальным потреблением памяти с подсветкой изменений
watch -d "ps aux --sort=-%mem | head -15"

# Мониторинг средней нагрузки системы (Load Average)
watch -t "cat /proc/loadavg"
```

### Типовые диагностические команды

```bash
# Визуализация иерархии процессов в виде дерева
pstree -p -a

# Дерево конкретного процесса с отображением его родителей (ancestors)
# -p: PIDs, -s: показать родителей, $(pgrep -o ...): старейший процесс (master)
pstree -p -s $(pgrep -o nginx)

# Поиск всех PID процессов по части имени
pgrep -a python
```

# Получение PID конкретного исполняемого файла
pidof mysqld

# Быстрая сортировка по потреблению CPU (процессорного времени)
ps -eo pid,ppid,%cpu,comm --sort=-%cpu | head -10

# Определение пути к исполняемому файлу работающего процесса
ls -l /proc/<PID>/exe
```

### Поиск "тяжелых" процессов (One-liners)

```bash
# Топ-5 процессов по количеству открытых файловых дескрипторов
for pid in /proc/[0-9]*/fd; do
    count=$(ls "$pid" 2>/dev/null | wc -l)
    [ "$count" -gt 0 ] && echo "$count $(ps -p $(basename $(dirname $pid)) -o comm=)"
done | sort -rn | head -5
```

## Дополнительная информация

### Выбор между pidof и pgrep

- **`pidof`**: Ищет строгое совпадение по имени исполняемого файла. Эффективен для сервисов и системных демонов.
- **`pgrep`**: Использует регулярные выражения и может искать по всей командной строке запуска. Незаменим для поиска скриптов (например, `pgrep -f myscript.py`).

### Особенности работы с /proc

1. **Динамичность:** Содержимое `/proc` генерируется ядром в момент обращения. Файлы не занимают места на диске.
2. **Жизненный цикл:** Директория `/proc/<PID>` мгновенно исчезает после завершения процесса.
3. **Безопасность:** Доступ к `/proc/<PID>/environ` и `/proc/<PID>/fd/` других пользователей обычно ограничен правами суперпользователя.
