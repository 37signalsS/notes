# Постоянная настройка лимитов ресурсов

## Определения

**Постоянные лимиты (Persistent Limits)** — настройки ресурсных ограничений, которые сохраняются после перезагрузки операционной системы. В отличие от временных лимитов, они применяются автоматически при запуске системных служб через **systemd** или при создании пользовательской сессии через **PAM (Pluggable Authentication Modules)**.

## Основные концепции

Постоянные лимиты настраиваются двумя основными способами в зависимости от объекта управления:

1. **systemd юнит-файлы** — современный стандарт для управления ресурсами системных служб (демонов). Лимиты устанавливаются непосредственно ядром при запуске процесса через системный вызов `setrlimit()`.
2. **`/etc/security/limits.conf`** — классический метод для настройки ограничений пользовательских сессий. Реализуется через модуль `pam_limits.so`.

Теоретические основы и иерархия приоритетов (cgroups, systemd, PAM) подробно описаны в разделе [**Концепции лимитов ресурсов**](./resource_limits_concepts.md).

## Практические сценарии

### Настройка лимитов для системной службы (systemd)

Для изменения лимитов конкретного сервиса рекомендуется использовать механизм `override.conf`, чтобы не изменять оригинальный юнит-файл дистрибутива.

```bash
# Открыть редактор для создания override-файла
sudo systemctl edit my-app.service
```

В открывшемся файле добавьте необходимые директивы:

```ini
[Service]
# NOFILE (Number of Open Files) — лимит на количество открытых файлов
LimitNOFILE=65536      
# NPROC (Number of Processes) — лимит на количество процессов и потоков
LimitNPROC=2048        
# CORE — лимит на размер core-файла (дампа памяти при крахе)
LimitCORE=infinity     
# AS (Address Space) — лимит на адресное пространство процесса
LimitAS=8G             
# Настройка приоритета для OOM (Out-of-Memory) Killer
# Значение -1000 защищает процесс от принудительного завершения при нехватке памяти
OOMScoreAdjust=-1000   
```

После сохранения изменений выполните:

```bash
sudo systemctl daemon-reload
sudo systemctl restart my-app
```

### Настройка лимитов для пользовательских сессий (PAM)

Классическая настройка через файл `/etc/security/limits.conf`.

```bash
# /etc/security/limits.conf
# <domain>  <type>  <item>    <value>
# ------------------------------------
# Настройка для всех пользователей (*)
*           soft    nofile    65536
*           hard    nofile    131072
# Лимиты для конкретного пользователя
student     hard    nproc     1024
```

Для применения изменений пользователь должен полностью завершить текущую сессию и войти в систему заново (re-login).

### Глобальные настройки для всех служб systemd

Если необходимо установить лимиты по умолчанию для всех сервисов системы, используйте файл конфигурации менеджера систем:

```bash
# /etc/systemd/system.conf
DefaultLimitNOFILE=65536
DefaultLimitNPROC=4096
```

Применение требует перезагрузки конфигурации демона: `sudo systemctl daemon-reload`.

## Дополнительная информация

### Сравнение методов настройки

| Сценарий | Механизм | Конфигурационный путь |
| :--- | :--- | :--- |
| Системная служба (демон) | systemd | `/etc/systemd/system/<service>.service.d/` |
| Сессия пользователя (SSH, GUI) | PAM | `/etc/security/limits.conf` |
| Глобальные лимиты служб | systemd | `/etc/systemd/system.conf` |
| Ограничения контейнеров | cgroups | Параметры среды выполнения (Docker, K8s) |
