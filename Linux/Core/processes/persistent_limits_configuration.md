# Постоянная настройка лимитов ресурсов в Linux

## Определения

**Постоянные лимиты (Persistent Limits)** — конфигурационные настройки, гарантирующие применение ограничений ресурсов (rlimits и cgroups) автоматически при загрузке системы или инициализации сессии.

**sysctl.d** — механизм ядра для установки общесистемных «потолков» ресурсов, которые действуют как абсолютные границы для всех остальных механизмов лимитирования.

**limits.d** — современный модульный подход к настройке PAM-лимитов, позволяющий разделять конфигурации разных приложений в отдельные файлы.

## Основные концепции

### Иерархия конфигурационных уровней

Для обеспечения надежности системы лимиты должны быть настроены на трех уровнях:
1.  **Ядерный уровень (System-wide):** Глобальные ограничения на общее число файлов или потоков в ОС.
2.  **Уровень сервисов/контейнеров:** Ограничения для демонов через systemd или рантаймы контейнеров.
3.  **Уровень пользователей (Session-level):** Ограничения для интерактивных оболочек и SSH-сессий.

### Методы обеспечения персистентности

| Уровень | Конфигурационный путь | Механизм применения |
| :--- | :--- | :--- |
| **Система** | `/etc/sysctl.d/*.conf` | Ядро Linux (при загрузке) |
| **Сервисы** | `/etc/systemd/system/<name>.service.d/*.conf` | systemd (через `setrlimit`) |
| **Пользователи** | `/etc/security/limits.d/*.conf` | PAM (при логине) |
| **Контейнеры** | `/etc/docker/daemon.json` или `config.toml` | Container Runtime |

## Практические сценарии

### Сценарий 1: Настройка системных «потолков» (sysctl)

Даже при установке `ulimit -n 1000000` процесс не сможет открыть столько файлов, если системный предел ниже. Это частая причина ошибок в высоконагруженных системах.

```bash
# Создание конфигурации для высоких нагрузок
sudo tee /etc/sysctl.d/99-highload.conf <<EOF
# Максимальное количество дескрипторов на один процесс (абсолютный предел)
fs.nr_open = 2097152
# Общее количество открытых файлов во всей системе
fs.file-max = 2097152
# Лимит на количество cgroups (актуально для K8s)
kernel.keys.maxkeys = 1000000
EOF

# Применение без перезагрузки
sudo sysctl --system
```

### Сценарий 2: Модульная настройка для пользователей (PAM)

Вместо редактирования `/etc/security/limits.conf` используйте директорию `.d`. Это стандарт для автоматизации (Ansible/Terraform).

```bash
# Настройка лимитов для пользователя приложения
sudo tee /etc/security/limits.d/app-user.conf <<EOF
appuser    soft    nofile    65536
appuser    hard    nofile    131072
appuser    soft    nproc     4096
appuser    hard    nproc     8192
EOF
```

### Сценарий 3: Расширенная настройка системных служб (systemd)

Для сервисов, работающих с большими объемами данных или множеством соединений, используйте `systemctl edit`.

```ini
# sudo systemctl edit my-service.service
[Service]
# rlimits (традиционные)
LimitNOFILE=524288
LimitNPROC=16384
LimitCORE=infinity

# cgroups (современные лимиты)
# Ограничение количества потоков (защита от fork bomb)
TasksMax=8192
# Жесткое ограничение памяти
MemoryMax=4G
# Приоритет выживания при OOM
OOMScoreAdjust=-900
```

### Сценарий 4: Лимиты по умолчанию для контейнеров (Docker/containerd)

Чтобы не указывать `--ulimit` при каждом запуске контейнера, настройте рантайм.

**Для Docker (`/etc/docker/daemon.json`):**
```json
{
  "default-ulimits": {
    "nofile": {
      "Name": "nofile",
      "Hard": 65536,
      "Soft": 65536
    }
  }
}
```

## Дополнительная информация

### Важные технические нюансы

1.  **Разница в синтаксисе:** В `limits.conf` используются значения в KB и количество, в systemd — суффиксы (`K`, `M`, `G`, `infinity`).
2.  **Порядок загрузки:** Файлы в `/etc/sysctl.d/` и `/etc/security/limits.d/` загружаются в лексикографическом порядке. Файл `99-custom.conf` переопределит настройки из `10-default.conf`.
3.  **Ошибки в system.conf:** Изменение `DefaultLimitNOFILE` в `/etc/systemd/system.conf` влияет на **все** сервисы. Будьте осторожны, так как слишком низкие значения могут помешать загрузке ОС.
4.  **Проверка:** После внесения изменений всегда проверяйте фактические лимиты работающего процесса:
    ```bash
    cat /proc/$(pgrep my-app)/limits
    ```
