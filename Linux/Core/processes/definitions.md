# Процессы в Linux: Определения

## Определения

### Пространство пользователя (Userspace) и пространство ядра (Kernelspace)

Операционная система Linux разделяет работу на два фундаментальных режима выполнения кода: **Userspace (пространство пользователя)** и **Kernelspace (пространство ядра)**. Это разделение базируется на аппаратных уровнях защиты процессора (Rings) и критически важно для обеспечения стабильности системы.

| Характеристика | Userspace (Пространство пользователя) | Kernelspace (Пространство ядра) |
| :--- | :--- | :--- |
| **Что выполняется?** | Прикладные программы, оболочки, библиотеки | Ядро ОС, драйверы, системные модули |
| **Уровень привилегий** | Низкий (Ring 3). Процессы изолированы | Максимальный (Ring 0). Полный доступ |
| **Доступ к железу** | Опосредованно через системные вызовы | Прямой и неограниченный |
| **Память** | Изолированное виртуальное пространство | Единое адресное пространство ядра |
| **Переключение** | Требует Trap/Exception для смены режима | Работает в привилегированном режиме |
| **Отказоустойчивость** | Сбой завершает только конкретный процесс | Ошибка ведет к Kernel Panic |

### Процесс и задача (Task)

**Процесс** — это экземпляр выполняемой программы, обладающий собственными ресурсами и контекстом безопасности. В ядре Linux нет жесткого разделения между процессами и потоками; обе сущности представлены структурой `task_struct` и называются **задачами (tasks)**.

Ключевые составляющие процесса:
- **Адресное пространство:** Личная виртуальная память процесса. Включает программный код (text), сегмент данных (data), кучу (heap) и стек вызовов (stack).
- **Контекст процесса:** Набор данных, необходимых ядру для управления процессом (состояние регистров, открытые файлы, переменные окружения).

### Поток (Thread) и легковесный процесс (LWP)

**Поток** — это отдельная линия выполнения в рамках процесса. В Linux потоки часто называют **легковесными процессами (LWP — Lightweight Processes)**.
- Все потоки одного процесса разделяют общее адресное пространство и системные ресурсы, но имеют собственные регистры процессора и стек.
- В Linux потоки реализуются через системный вызов `clone` с флагами, указывающими на разделение ресурсов (например, `CLONE_VM` для разделения памяти).
- Технически, с точки зрения ядра, поток — это задача (`task_struct`), у которой идентификатор группы потоков (**TGID**) совпадает с **PID** основного потока (лидера группы).

### Переключение контекста (Context Switch)

**Переключение контекста** — процедура сохранения состояния (контекста) текущей задачи и восстановления состояния другой задачи для её выполнения на процессоре.
- Это "невидимая" работа планировщика, позволяющая множеству процессов работать параллельно на одном ядре CPU (псевдопараллелизм).
- Переключение между потоками одного процесса ("внутрипроцессное") происходит быстрее, чем между разными процессами, так как не требует смены таблиц страниц памяти (MMU context).

### Атрибуты процесса (Паспорт процесса)

Каждый процесс обладает набором атрибутов, необходимых для управления и безопасности:
- **PID (Process Identifier):** Уникальный числовой идентификатор.
- **PPID (Parent PID):** Идентификатор родительского процесса.
- **TGID (Thread Group ID):** Идентификатор группы потоков (для пользователя это обычно и есть PID).
- **UID / GID:** Идентификаторы владельца и группы (Real, Effective, Saved).
- **Capabilities:** Набор привилегий, заменяющий классическое "всё или ничего" для пользователя root.
- **pidfd (PID File Descriptor):** Файловый дескриптор, привязанный к конкретной инкарнации процесса. Исключает риск отправки сигнала не тому процессу, если PID был переиспользован ядром.

### Системные вызовы (System Calls)

**Системный вызов** — программный интерфейс для перехода из Userspace в Kernelspace для выполнения привилегированных операций (ввод-вывод, управление процессами).

Механизмы ускорения:
- **vDSO (virtual Dynamic Shared Object):** Виртуальная библиотека, отображаемая ядром в память процесса. Позволяет выполнять "дешевые" системные вызовы (например, `gettimeofday`, `clock_gettime`) полностью в пространстве пользователя без дорогостоящего переключения режима CPU.
- **vsyscall:** Устаревший механизм (использовал фиксированные адреса), заменен на vDSO из соображений безопасности (ASLR).

## Основные концепции

### Механизм переключения режимов

Когда приложению нужно выполнить системный вызов:
1.  **Подготовка:** Аргументы помещаются в регистры.
2.  **Запрос:** Выполняется инструкция `syscall` (x86_64).
3.  **Переход:** Процессор переключается в Ring 0, ядро сохраняет контекст пользователя и выполняет запрос.
4.  **Возврат:** Ядро возвращает результат и переключает процессор обратно в Ring 3.

### Структура task_struct

Ядро хранит данные о каждой задаче в структуре `task_struct` (`include/linux/sched.h`). Основные поля:
- **`state`**: Текущее состояние (Running, Sleeping и др.).
- **`stack`**: Указатель на стек режима ядра.
- **`mm`**: Ссылка на дескриптор памяти процесса (таблицы страниц).
- **`pid`** и **`tgid`**: Идентификаторы.
- **`parent`**, **`children`**, **`sibling`**: Указатели на родственников в дереве процессов.
- **`files`**: Таблица открытых файловых дескрипторов.
- **`signal`** и **`sighand`**: Обработка сигналов.

### Виртуализация и Ring -1

В архитектурах с поддержкой виртуализации (Intel VT-x, AMD-V) существует режим **Ring -1** (VMX Root Mode), в котором работает гипервизор (KVM). Это позволяет изолировать гостевые операционные системы от хоста.

## Практические сценарии

### Анализ времени выполнения

Утилита `time` разделяет время работы программы:
- **user**: Время выполнения кода приложения в пространстве пользователя.
- **sys**: Время, проведенное ядром при обслуживании системных вызовов процесса.

```bash
time dd if=/dev/zero of=/dev/null count=1000000
# user    0m0.120s
# sys     0m0.450s  <-- Значительная часть времени ушла на syscalls (write/read)
```

### Идентификация потоков ядра

**Потоки ядра (Kernel Threads)** — служебные задачи, работающие только в Kernelspace.

Особенности отображения в `ps`:
- Название в квадратных скобках (например, `[kworker/0:1]`).
- Отсутствие адресного пространства пользователя (нет сегментов `text` или `stack` в Userspace).
- Не реагируют на сигналы Userspace (например, `kill -9`), так как никогда не переходят в режим пользователя для проверки очереди сигналов.

```bash
# Список потоков ядра, порожденных kthreadd (PID 2)
ps -efj | grep "\["
```

## Дополнительная информация

### Почему разделение критически важно

1.  **Безопасность:** Изоляция приложений друг от друга и от ядра.
2.  **Стабильность:** Сбой в прикладной программе не приводит к краху всей системы (Kernel Panic).
3.  **Управление ресурсами:** Ядро выступает арбитром при доступе к железу (CPU, RAM, диск).
