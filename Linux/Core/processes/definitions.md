# Процессы в Linux: Определения

## Definitions

### Userspace и Kernelspace

Операционная система разделяет работу на два фундаментальных режима: **Userspace (пространство пользователя)** и **Kernelspace (пространство ядра)**. Разделение необходимо для защиты ядра и стабильности системы.

| Характеристика | Userspace | Kernelspace |
| :--- | :--- | :--- |
| **Что работает?** | Прикладные программы, утилиты, библиотеки | Ядро ОС, драйверы, системные модули |
| **Привилегии** | Низкие. Процессы изолированы друг от друга | Полные. Неограниченный доступ к системе |
| **Доступ к оборудованию** | Нет прямого. Через системные вызовы | Прямой и неограниченный |
| **Доступ к памяти** | Изолированное виртуальное адресное пространство | Единое адресное пространство ядра |
| **Стабильность** | Сбой — падение одного приложения | Сбой — Kernel Panic всей системы |

### Процесс

**Процесс** — экземпляр выполняемой программы. Изолированная единица с собственным виртуальным адресным пространством, системными ресурсами (файловые дескрипторы, контекст безопасности, окружение, приоритет) и уникальным идентификатором (PID). Изоляция достигается механизмами ядра: **[пространствами имён (namespaces)](../namespaces.md)** (изоляция видимости ресурсов) и **[контрольными группами (cgroups)](../cgroups.md)** (ограничение потребления CPU, памяти).

### Поток (Thread)

**Поток** — наименьшая единица выполнения, планируемая ядром. Потоки одного процесса разделяют адресное пространство и ресурсы, что делает взаимодействие быстрым, но требующим синхронизации.

### Системные вызовы (System Calls)

**Системный вызов** — механизм, через который программа в userspace запрашивает у ядра выполнение привилегированной операции. Подробное описание: [Интерфейсы ядра Linux](../kernel/kernel_interfaces.md#Системные-вызовы-System-Calls).

## Basic Concepts

### Иерархия определений

```
Kernelspace
├── Ядро (kernel)
│   ├── Системные вызовы ← интерфейс для userspace
│   └── Драйверы устройств
└── Kernel Threads (потоки ядра)

Userspace
└── Процессы
    └── Потоки (threads)
```

## Practical Scenarios

### Как увидеть разницу на практике

```bash
# Процессы userspace — видны в ps
ps aux

# Потоки ядра — видны по квадратным скобкам
ps -eo pid,comm | grep '\['

# Системные вызовы процесса — трассировка
strace -p <PID>
```

## Additional Information

### Ring Protection

Разделение userspace/kernelspace реализуется через уровни привилегий процессора (ring 0–3):

- **Ring 0** — kernelspace (полный доступ к железу)
- **Ring 3** — userspace (ограниченный доступ)

В Linux используются только ring 0 и ring 3.

### Почему процессам нельзя напрямую обращаться к ядру

Прямой доступ к оборудованию из userspace привёл бы к:

- Конфликтам за ресурсы (два процесса пишут на диск одновременно)
- Нарушению безопасности (чтение чужой памяти)
- Нестабильности (ошибка в приложении = крах системы)

Системные вызовы — контролируемые «ворота» в kernelspace, где ядро проверяет права и валидирует запросы.
