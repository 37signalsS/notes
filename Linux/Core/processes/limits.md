## Определения

### Лимиты ресурсов

**Лимиты ресурсов** — это ограничения на потребление системных ресурсов (например, количество открытых файлов, объем памяти), устанавливаемые для каждого пользователя и процесса в Linux. Утилита `ulimit` позволяет просматривать и устанавливать эти лимиты.

### Fork Bomb

**Fork Bomb** — это атака типа "отказ в обслуживании", которая использует системный вызов `fork()` для экспоненциального создания процессов, быстро исчерпывая все доступные ресурсы системы.

## OOM Killer (Out-of-Memory Killer)

**OOM Killer** — это механизм ядра Linux, который автоматически срабатывает при нехватке оперативной памяти (RAM). Когда система находится в состоянии **Out of Memory (OOM)**, OOM Killer принудительно завершает один или несколько процессов, чтобы освободить память и предотвратить полный отказ системы.

### Как OOM Killer выбирает "жертву"

Выбор процесса для завершения основан на "очках негодности" (**oom_score**). Чем больше очков у процесса, тем выше вероятность, что он будет "убит".

Каждый процесс имеет три связанных файла в `/proc/<PID>/`:

-   `oom_score`: Текущее значение очков (от 0 до 1000). Это значение нельзя изменять напрямую.
-   `oom_score_adj`: Корректирующий коэффициент, который позволяет влиять на `oom_score`. Диапазон: от -1000 до +1000.
-   `oom_adj`: Устаревший аналог `oom_score_adj`. Диапазон: от -17 до +15. Изменение `oom_score_adj` автоматически пересчитывает `oom_adj`.

**Факторы, повышающие `oom_score` (увеличивают шанс быть убитым):**

-   Большое потребление оперативной памяти (RAM).
-   Наличие большого количества дочерних процессов, которые также потребляют память.
-   Высокое значение `nice` (низкий приоритет процесса).

**Факторы, понижающие `oom_score` (уменьшают шанс быть убитым):**

-   Процесс запущен от имени `root`.
-   Процесс имеет прямой доступ к оборудованию.
-   Малое время работы (недавно запущенные процессы имеют некоторую защиту).
-   Низкое значение `oom_score_adj`.

## Практические сценарии

### Управление лимитами ресурсов (`ulimit`)

Команда `ulimit` позволяет просматривать и устанавливать лимиты для **текущей сессии оболочки**.

-   **Посмотреть все текущие лимиты:**
    ```bash
    ulimit -a
    ```

-   **Посмотреть лимит на количество открытых файлов (`nofile`):**
    ```bash
    ulimit -n
    ```

-   **Посмотреть лимит на размер core-файла (`coredump`):**
    ```bash
    ulimit -c
    ```

-   **Установить новый "мягкий" лимит (например, для открытых файлов):**
    ```bash
    # Установить лимит в 4096 файлов
    ulimit -n 4096
    ```
    
Изменения, сделанные с помощью `ulimit`, действуют только в текущей сессии.

**Постоянная настройка лимитов:**

1.  **/etc/security/limits.conf** (классический способ):
    ```
    # <domain>      <type>  <item>         <value>
    # -------------------------------------------------
    # Запретить пользователю 'student' создавать большие файлы
    student         hard    fsize          102400

    # Увеличить лимит открытых файлов для всех пользователей
    *               soft    nofile         65536
    *               hard    nofile         131072
    ```

    -   `*`: Применить правило для всех пользователей.
    -   `soft`: "Мягкий" лимит, который пользователь может изменять в пределах "жесткого" лимита.
    -   `hard`: "Жесткий" лимит, который может быть изменен только пользователем `root`.
    -   `nofile`: Указывает, что мы настраиваем максимальное количество открытых файлов.

2.  **Юниты `systemd`** (современный способ):

    Для сервисов, управляемых `systemd`, лимиты устанавливаются прямо в юнит-файле. Это более надежный и предпочтительный метод для служб.

    ```ini
    # /etc/systemd/system/my-app.service
    [Service]
    # Лимит на количество открытых файлов
    LimitNOFILE=65536

    # Лимит на количество процессов
    LimitNPROC=1024

    # Лимит на размер core-файла
    LimitCORE=infinity
    ```

### Защита от «Fork Bomb»

Основной метод защиты — ограничение максимального количества процессов, которые может создать один пользователь.
```bash
# Установить лимит в 1024 процесса для текущей сессии
ulimit -u 1024
```

### Управление поведением OOM Killer

Вы можете повлиять на выбор OOM Killer, изменив значение `oom_score_adj` для процесса.

-   **Полностью отключить OOM Killer для процесса:**
    ```bash
    # Значение -1000 гарантирует, что процесс не будет убит
    sudo echo -1000 > /proc/<PID>/oom_score_adj
    ```

-   **Сделать процесс основной "целью" для OOM Killer:**
    ```bash
    # Максимальное значение делает процесс главным кандидатом на уничтожение
    sudo echo 1000 > /proc/<PID>/oom_score_adj
    ```
-   **Настройка в `systemd`:**
    ```ini
    [Service]
    OOMScoreAdjust=-1000
    ```
