## Определения

**Сигналы** — это программные прерывания, которые отправляются процессам для уведомления об определенных событиях. Они используются для управления поведением процессов.

## Основные концепции

### Основные типы сигналов

-   **`SIGTERM` (15):** Стандартный сигнал для **"мягкого уничтожения"** процесса. Это "вежливый" запрос на завершение. Процесс может перехватить этот сигнал, чтобы выполнить необходимые действия по очистке (сохранить данные, закрыть файлы и соединения, корректно завершить дочерние процессы). Если в программе не прописана специальная логика для `SIGTERM`, по умолчанию процесс будет завершен. Это сигнал, который команда `kill` отправляет по умолчанию.
-   **`SIGKILL` (9):** **"Жесткий"** сигнал для **немедленного и принудительного завершения** процесса. Используется как последнее средство в **критических ситуациях, когда процесс "повис"** или не реагирует на `SIGTERM`. Этот сигнал не может быть перехвачен или проигнорирован программой. Ядро операционной системы завершает процесс напрямую, не давая ему шанса на "уборку" ресурсов, файлов или соединений, а также без возможности сообщить родителю о своем завершении. Все потоки процесса завершаются.
-   **`SIGHUP` (1):** Уведомление о потере терминала. Исторически означал разрыв связи с управляющим терминалом. Сегодня многие демоны используют этот сигнал как команду для перечитывания своих конфигурационных файлов без полной остановки (например, `nginx -s reload` или `systemctl reload nginx`).
-   **`SIGINT` (2):** Сигнал прерывания с терминала (Interrupt). Отправляется при нажатии `Ctrl+C`. Похож на `SIGTERM`, процесс может его перехватить.
-   **`SIGQUIT` (3):** Сигнал "выхода" с терминала. Похож на `SIGINT`, но при этом дополнительно создает **`coredump`** (снимок памяти процесса), если это разрешено.
-   **`SIGSTOP` (17, 19, 23):** Безусловная остановка (приостановка) выполнения процесса. Этот сигнал не может быть перехвачен.
-   **`SIGCONT` (18, 19):** Возобновление работы процесса, который был остановлен (`SIGSTOP` или `SIGTSTP`).
-   **`SIGTSTP` (18, 20, 24):** Сигнал остановки с терминала (Terminal Stop), отправляется при нажатии `Ctrl+Z`. В отличие от `SIGSTOP`, этот сигнал может быть перехвачен или проигнорирован.
-   **`SIGCHLD` (17, 20):** Сигнал, отправляемый родительскому процессу при завершении или остановке его дочернего процесса. Это позволяет родительскому процессу "забрать" статус завершения потомка с помощью системного вызова `wait()`.

### Особенности использования SIGKILL и его последствия

Использование `SIGKILL` может иметь непредвиденные последствия, которые делают его инструментом последнего средства:

-   **Отсутствие очистки:** Поскольку процесс не имеет возможности перехватить `SIGKILL`, он не может выполнить никакую очистку перед завершением. Это может привести к потере данных, повреждению файлов или утечкам ресурсов (например, оставленные открытыми файловые дескрипторы, незакрытые сетевые соединения).
-   **Дочерние процессы:** `SIGKILL`, отправленный родительскому процессу, не будет автоматически передан его дочерним процессам. Дочерние процессы станут осиротевшими и будут переусыновлены процессом `init` (PID 1). Хотя `init` всегда корректно ждет своих дочерних процессов, чтобы предотвратить появление зомби, непосредственная внезапная смерть родителя может нарушить логику взаимодействия с дочерними процессами, особенно если дочерние процессы ожидают каких-либо данных или сигналов от родителя.
-   **Зомби-процессы:** Сам по себе `SIGKILL` не создает зомби-процессы. Зомби появляются, когда дочерний процесс завершается, но его родительский процесс еще не вызвал `wait()` или `waitpid()` для сбора статуса завершения дочернего процесса. Однако, если `SIGKILL` приводит к аварийному завершению родительского процесса, который *уже запустил, но еще не успел дождаться* своих завершившихся дочерних процессов, то эти дочерние процессы могут временно остаться зомби до тех пор, пока `init` не усыновит их и не выполнит `wait()`.
-   **Отсутствие обратной связи:** Убитый `SIGKILL` процесс не имеет возможности сообщить своему родителю или системе о том, что он был завершен именно этим сигналом. Статус завершения будет указывать на "убийство сигналом 9", но без дополнительных деталей, которые могли бы быть предоставлены при корректной обработке `SIGTERM`.

### Отправка сигналов

Для отправки сигналов используются утилиты `kill`, `pkill`, `killall`.

```bash
# Отправить сигнал SIGTERM процессу с PID 1234 (действие по умолчанию)
kill 1234

# Явно отправить сигнал SIGKILL
kill -9 1234
# или
kill -SIGKILL 1234

# Отправить сигнал SIGHUP всем процессам с именем 'nginx'
pkill -HUP nginx

# Завершить все процессы, принадлежащие пользователю 'user'
killall -u user
```

**Важно:** "Убить" зомби-процесс сигналом `SIGKILL` невозможно, так как он уже не является исполняемым кодом. Единственный способ его убрать — это завершить родительский процесс.
