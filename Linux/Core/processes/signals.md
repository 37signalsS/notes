# Сигналы процессов в Linux

## Определения

**Сигналы (Signals)** — это асинхронные программные прерывания, отправляемые процессам для уведомления о событиях. Они являются ключевым механизмом [**IPC (Inter-Process Communication — межпроцессное взаимодействие)**](./ipc.md) и используются для управления жизненным циклом процессов.

**Количество:** В Linux поддерживается 64 сигнала (номера 1–64).

- **1–32:** Стандартные сигналы POSIX (Portable Operating System Interface).
- **33–64:** Сигналы реального времени (RT — Real-Time signals).

**pidfd (PID File Descriptor)** — файловый дескриптор процесса, введённый в ядре Linux 5.3. Это уникальный ссылочный объект, который остается валидным для конкретного процесса даже при переиспользовании его PID (Process Identifier). Подробнее см. раздел [**pidfd: безопасное управление процессами**](./additional_info.md#pidfd-безопасное-управление-процессами).

## Основные концепции

### Жизненный цикл сигнала

1. **Генерация:** Сигнал создается ядром (например, при аппаратной ошибке), другим процессом (через системный вызов `kill()`) или пользователем (через сочетания клавиш в терминале).
2. **Доставка:** Сигнал доставляется целевому процессу. Он может оставаться в состоянии ожидания (pending), если процесс временно заблокировал его доставку.
3. **Обработка:** Процесс может отреагировать на сигнал одним из трех способов:
   - **Действие по умолчанию:** Завершение процесса, игнорирование сигнала или создание снимка памяти (coredump).
   - **Перехват (catch):** Выполнение пользовательской функции-обработчика (signal handler).
   - **Игнорирование:** Сигнал отбрасывается без последствий (сигналы `SIGKILL` и `SIGSTOP` игнорировать нельзя).

### Категории сигналов

| Категория | Сигналы | Назначение |
| :--- | :--- | :--- |
| **Завершение** | `SIGTERM`, `SIGKILL`, `SIGINT` | Корректное или принудительное завершение работы |
| **Управление** | `SIGSTOP`, `SIGCONT`, `SIGTSTP` | Приостановка и возобновление выполнения |
| **Уведомления** | `SIGCHLD`, `SIGHUP` | Передача информации о внешних событиях |
| **Ошибки** | `SIGSEGV`, `SIGFPE`, `SIGBUS` | Уведомление об аппаратных или программных сбоях |

### Таблица основных сигналов

| Сигнал | Номер | Описание | Действие по умолчанию | Перехват |
| :--- | :--- | :--- | :--- | :--- |
| **SIGHUP** | 1 | Разрыв связи (Hangup) | Завершение | Да |
| **SIGINT** | 2 | Прерывание с клавиатуры (Ctrl+C) | Завершение | Да |
| **SIGQUIT** | 3 | Выход (Ctrl+\\) | Завершение + coredump | Да |
| **SIGKILL** | 9 | Немедленное завершение | Завершение | **Нет** |
| **SIGTERM** | 15 | Корректное завершение | Завершение | Да |
| **SIGSTOP** | 19 | Безусловная остановка | Остановка | **Нет** |
| **SIGCONT** | 18 | Возобновление выполнения | Продолжение | Да |
| **SIGTSTP** | 20 | Остановка с терминала (Ctrl+Z) | Остановка | Да |
| **SIGCHLD** | 17 | Изменение статуса дочернего процесса | Игнорирование | Да |
| **SIGSEGV** | 11 | Ошибка сегментации (Invalid memory reference) | Завершение + coredump | Да |
| **SIGFPE** | 8 | Арифметическая ошибка (Floating-point exception) | Завершение + coredump | Да |
| **SIGALRM** | 14 | Сигнал таймера | Завершение | Да |
| **SIGUSR1/2** | 10/12 | Пользовательские сигналы | Завершение | Да |

> **Примечание:** Номера сигналов могут зависеть от архитектуры процессора. В скриптах и коде всегда рекомендуется использовать имена сигналов.

### Ключевые сигналы

#### SIGTERM (15) против SIGKILL (9)

| Характеристика | SIGTERM | SIGKILL |
| :--- | :--- | :--- |
| **Тип** | Запрос на корректное завершение | Принудительное завершение ядром |
| **Возможность перехвата** | Да | Нет |
| **Очистка ресурсов** | Процесс может выполнить cleanup | Шанс на очистку отсутствует |
| **Безопасность данных** | Сохранение данных перед выходом | Риск потери данных или повреждения ФС |
| **Использование** | `kill <PID>` (по умолчанию) | `kill -9 <PID>` (крайняя мера) |

**SIGTERM:** Позволяет процессу выполнить "мягкое" завершение (graceful shutdown): закрыть соединения, сохранить состояние, удалить временные файлы.

**SIGKILL:** Ядро убивает процесс мгновенно. Процесс не получает уведомления и не может корректно завершить работу.

> **Правило:** Всегда используйте сначала `SIGTERM`, и только если процесс не реагирует в течение некоторого времени, применяйте `SIGKILL`.

#### SIGHUP (1)

Первоначально означал разрыв связи с терминалом. В современных системных службах (nginx, systemd) часто используется для **перечитывания конфигурации** без остановки процесса.

#### SIGINT (2) и SIGQUIT (3)

- **SIGINT** — отправляется драйвером терминала при нажатии **`Ctrl+C`**. Процессы обычно перехватывают его для корректного выхода.
- **SIGQUIT** — отправляется при нажатии **`Ctrl+\`**. Аналогичен `SIGINT`, но дополнительно заставляет ядро создать **coredump**.

#### SIGSTOP (19) и SIGCONT (18)

- **SIGSTOP** — немедленная и безусловная остановка процесса ядром. Не может быть перехвачен.
- **SIGCONT** — возобновление работы процесса, ранее остановленного сигналами `SIGSTOP` или `SIGTSTP`.

#### SIGCHLD (17)

Отправляется родительскому процессу при завершении или остановке его потомка. Если родитель не обработает этот сигнал и не вызовет `wait()`, дочерний процесс может остаться в состоянии зомби. Подробнее см. заметку [**Устранение неполадок: Зомби-процессы**](./Troubleshooting/debugging.md#зомби-процессы).

### Сигналы реального времени (RT signals)

Имеют номера **34–64** и отличаются от стандартных следующими свойствами:

- Могут ставиться в очередь (если отправлено несколько одинаковых сигналов, они все будут доставлены).
- Гарантированный порядок доставки (от меньшего номера к большему).
- Позволяют передавать дополнительные данные вместе с сигналом.

## Практические сценарии

### Отправка сигналов из командной строки

| Утилита | Синтаксис | Применение |
| :--- | :--- | :--- |
| `kill` | `kill -<SIGNAL> <PID>` | Отправка конкретному процессу по его идентификатору |
| `pkill` | `pkill -<SIGNAL> <pattern>` | Отправка процессам, чье имя соответствует шаблону |
| `killall` | `killall -<SIGNAL> <name>` | Отправка всем процессам с указанным именем |

```bash
# Плавная остановка процесса
kill 1234

# Принудительное завершение всех процессов браузера
pkill -9 chrome

# Запрос на перечитывание конфигурации
pkill -HUP nginx

# Приостановка и возобновление процессов пользователя
killall -STOP -u developer
killall -CONT -u developer
```

### Отправка сигналов через pidfd

Использование традиционных PID подвержено состоянию гонки (race condition) из-за возможности переиспользования идентификаторов ядром. **pidfd** решает эту проблему, обеспечивая безопасную доставку сигнала именно тому процессу, для которого был открыт дескриптор.

Системный вызов `pidfd_send_signal()` гарантирует, что сигнал не уйдет "новому" процессу, занявшему старый PID. Детальное описание и примеры кода приведены в разделе [**pidfd: безопасное управление процессами**](./additional_info.md#pidfd-безопасное-управление-процессами).

### Корректное завершение в контейнерах

**Docker:**

- Команда `docker stop` сначала отправляет `SIGTERM`, ожидает (по умолчанию 10 секунд) и затем отправляет `SIGKILL`.
- В `Dockerfile` можно изменить сигнал остановки с помощью инструкции `STOPSIGNAL`.

**Kubernetes:**

- При удалении пода (Pod) контейнерам отправляется `SIGTERM`.
- Параметр `terminationGracePeriodSeconds` (по умолчанию 30с) определяет время до отправки `SIGKILL`.

Коды выхода: `137` означает завершение по `SIGKILL` (128+9), `143` — по `SIGTERM` (128+15). Подробнее см. заметку [**OOM Killer в контейнерах**](./oom_killer_containers.md).

### Инструменты для отладки

```bash
# Трассировка сигналов, получаемых процессом
strace -e trace=signal -p <PID>

# Просмотр маски сигналов процесса (в шестнадцатеричном виде)
cat /proc/<PID>/status | grep Sig
```

## Дополнительная информация

### Переносимость и стандарты

Хотя имена сигналов (например, `SIGTERM`) стандартизированы POSIX, их числовые значения могут различаться на разных архитектурах и UNIX-системах. Всегда используйте символьные имена в сценариях и программном коде для обеспечения переносимости.

### Связь с кодами завершения

Если процесс завершается из-за получения сигнала, его код выхода рассчитывается по формуле: `128 + номер сигнала`.

| Сигнал | Код выхода | Причина |
| :--- | :--- | :--- |
| **SIGINT** (2) | 130 | Завершено пользователем (Ctrl+C) |
| **SIGKILL** (9) | 137 | Завершено принудительно (OOM (Out-Of-Memory) Killer, kill -9) |
| **SIGTERM** (15) | 143 | Стандартное завершение по таймауту |

Подробный список кодов см. в разделе [**Коды завершения (Exit Codes)**](../../Shell/exit_codes.md).
