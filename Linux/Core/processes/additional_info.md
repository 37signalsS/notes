# Процессы в Linux: Дополнительная информация

## Определения

**pidfd (PID File Descriptor)** — файловый дескриптор, привязанный к конкретной структуре задачи в ядре. В отличие от числового PID, он гарантирует обращение к конкретной инкарнации процесса, исключая ошибки при переиспользовании идентификаторов.

**TGID (Thread Group ID)** — идентификатор группы потоков. С точки зрения пользователя это и есть привычный PID. Для всех потоков одного процесса TGID совпадает с PID основного потока (лидера группы).

**TID (Thread ID)** — уникальный идентификатор задачи в ядре. Каждый поток имеет свой TID. В однопоточном приложении PID = TGID = TID.

**PGID (Process Group ID)** — идентификатор группы процессов. Используется оболочкой для управления заданиями (Job Control). Например, все процессы в одном конвейере (`ls | grep`) имеют общий PGID.

**SID (Session ID)** — идентификатор сессии. Сессия — это набор групп процессов, обычно связанных с одним управляющим терминалом (tty).

## Основные концепции

### Иерархия идентификаторов

Ядро Linux организует задачи в многоуровневую структуру для эффективного управления ресурсами и сигналами:
1.  **Задачи (TIDs):** Минимальные единицы планирования.
2.  **Группы потоков (TGIDs/PIDs):** Наборы потоков, разделяющих адресное пространство.
3.  **Группы процессов (PGIDs):** Используются для рассылки сигналов всей группе (например, `SIGINT` при Ctrl+C).
4.  **Сессии (SIDs):** Группируют процессы одного логического входа пользователя.

### Эволюция системных вызовов создания

В Linux создание задач прошло путь от простого дублирования до гибкого конфигурирования:

- **`fork()` / `vfork()` (Legacy):** Устаревшие интерфейсы. В современной `glibc` реализованы через `clone()`.
- **`clone()` (Стандарт):** Позволяет создавать потоки или процессы, явно указывая флаги разделения ресурсов (`CLONE_VM`, `CLONE_FS` и т.д.).
- **`clone3()` (Modern, Linux 5.3+):** Использует структуру `struct clone_args`. Позволяет:
  - Автоматически получать `pidfd`.
  - Указывать размер и расположение стека более гибко.
  - Управлять PID-пространствами имен без лишних переключений.

### Механизмы ожидания завершения

| Вызов | Особенности |
| :--- | :--- |
| **`wait()`** | Ожидает завершения любого дочернего процесса. |
| **`waitpid()`** | Позволяет ждать конкретный PID или группу (PGID). |
| **`waitid()`** | Современный интерфейс (POSIX). Позволяет ждать процессы по PID, PGID или PID-пространству, поддерживает расширенные флаги (например, ожидание остановки потоков). |

### Процессы против Потоков: Глубокое сравнение

| Характеристика | Процесс | Поток (Thread) |
| :--- | :--- | :--- |
| **Системная сущность** | Задача с флагом `CLONE_VM` (выкл) | Задача с флагом `CLONE_VM` (вкл) |
| **Адресное пространство** | Изолированное (собственные таблицы страниц) | Общее (разделяемые таблицы страниц) |
| **Дескрипторы (FD)** | Своя таблица (по умолчанию) | Общая таблица |
| **Сигналы** | Свои обработчики и маски | Общие обработчики, свои маски |
| **Переключение контекста** | Требует смены MMU (дорого) | Без смены MMU (дешево) |

## Практические сценарии

### Безопасное управление через pidfd (C)

Использование `pidfd` исключает Race Condition при отправке сигналов.

```c
#include <sys/syscall.h>
#include <sys/wait.h>
#include <signal.h>
#include <unistd.h>
#include <poll.h>
#include <stdio.h>

int main() {
    pid_t target_pid = 1234; // Пример PID

    // 1. Открываем pidfd для процесса
    int pfd = syscall(SYS_pidfd_open, target_pid, 0);
    if (pfd == -1) {
        perror("pidfd_open");
        return 1;
    }

    // 2. Безопасно отправляем сигнал. 
    // Если процесс 1234 завершился и PID занят другим — ядро вернет ошибку, а не убьет чужой процесс.
    if (syscall(SYS_pidfd_send_signal, pfd, SIGTERM, NULL, 0) == -1) {
        perror("pidfd_send_signal");
    }

    // 3. Ждем завершения через epoll/poll (вместо waitpid)
    struct pollfd poll_data = { .fd = pfd, .events = POLLIN };
    poll(&poll_data, 1, -1);
    
    close(pfd);
    return 0;
}
```

### Мониторинг идентификаторов в терминале

Для просмотра иерархии групп и сессий используйте специфичные флаги `ps`:

```bash
# Вывод PID, PGID, SID и командной строки
ps -eo pid,pgid,sid,comm

# Идентификация лидера сессии (SID == PID)
ps -efj | grep "bash"
```

## Дополнительная информация

### Жизненный цикл PID 1 (Init)

- **Предк всего:** PID 1 — это первый процесс в пространстве пользователя. Любая программа, запущенная в системе (браузер, сервер, оболочка), является его прямым или косвенным потомком.
- **Спонтанные процессы:** Помимо PID 1, ядро при старте порождает "спонтанные" процессы (потоки ядра). Они обычно имеют низкие PID и отображаются в `ps` в квадратных скобках (например, `[kthreadd]`). Это части самого ядра, их не нужно настраивать или завершать вручную.
- **Reparenting:** Когда процесс-родитель умирает, все его дети «усыновляются» процессом с PID 1.
- **Zombie Reaping:** PID 1 обязан вызывать `wait()` для всех усыновленных процессов, чтобы очищать таблицу дескрипторов задач.
- **Игнорирование сигналов:** По умолчанию PID 1 игнорирует `SIGKILL` и `SIGTERM`, чтобы предотвратить случайную остановку системы. Его завершение приводит к немедленному падению (kernel panic) всей системы.
