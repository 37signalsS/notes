## Определения

### CRIU (Checkpoint/Restore In Userspace)

**CRIU** — это утилита для Linux, которая позволяет "заморозить" работающий процесс или группу процессов и сохранить их состояние в виде набора файлов на диске. Позже это состояние можно использовать для восстановления процессов с того же самого места, даже на другой машине.

### Exit code (Код завершения)

**Exit code** (код завершения) — это целочисленное значение, которое программа или команда возвращает после своего завершения. `0` обычно означает успешное завершение, ненулевые значения — ошибку.

### Coredump (Дамп памяти)

**Coredump** — это файл, содержащий снимок рабочего адресного пространства процесса в момент его аварийного завершения. Используется для посмертной отладки (post-mortem debugging), чтобы понять причину сбоя.

## Основные концепции

### Как работает CRIU

CRIU сохраняет практически все состояние процесса: память, PID, открытые файлы, сокеты (включая установленные TCP-соединения), каналы, таймеры и т.д.

**Зачем это нужно:**
-   **Живая миграция (Live Migration):** Перенос контейнеров или приложений между серверами практически без простоя.
-   **Ускорение запуска:** "Долгоиграющие" приложения можно быстро восстанавливать из сохраненного состояния.
-   **Отказоустойчивость:** Периодическое сохранение состояния критически важных процессов.

### Как работает Coredump

При аварийном завершении процесса, если это разрешено настройками системы, ядро создает файл coredump, содержащий полную копию памяти процесса и его состояния.

## Практические сценарии

### Checkpoint/Restore с помощью CRIU

1.  **"Заморозить" процесс (dump):**
    ```bash
    # -t <pid>: указать PID процесса
    # --images-dir: директория для сохранения файлов состояния
    sudo criu dump -t <PID> --images-dir /tmp/checkpoint
    ```
2.  **Восстановить процесс (restore):**
    ```bash
    # --daemon: запустить процесс в фоновом режиме
    # --restore-detached: отсоединиться от процесса после восстановления
    sudo criu restore --images-dir /tmp/checkpoint --daemon --restore-detached
    ```

### Просмотр файлов, используемых процессом (`lsof`)

`lsof` — утилита, которая показывает список открытых файлов для каждого процесса в системе.
```bash
lsof -p <PID>
```

**Примеры использования `lsof`:**
-   `lsof -u user`: Показать файлы, открытые определённым пользователем.
-   `lsof -c nginx | grep config`: Показать файлы, используемые `nginx` в качестве конфиг файла.
-   `lsof +D directory`: Показать процессы, использующие файлы в указанной директории.
-   Если вы удалили файл, но место на диске не освободилось, это может быть связано с тем, что файл всё ещё открыт каким-то процессом. Команда `lsof | grep deleted` поможет найти такие процессы.

## Восстановление удаленного исполняемого файла

Если вы случайно удалили скрипт или бинарный файл, пока он еще выполнялся, его можно восстановить. Ядро Linux не удаляет файл с диска (его inode и данные), пока хотя бы один процесс держит его открытым.

Процесс восстановления состоит из двух шагов:

1.  **Найти PID процесса.** Используйте `pgrep` или `ps`, чтобы найти идентификатор запущенного процесса.
    ```bash
    # Например, для скрипта 'my_script.sh'
    pgrep -f my_script.sh
    ```

2.  **Скопировать файл из `/proc`.** Исполняемый файл доступен по символической ссылке `/proc/<PID>/exe`. Даже после удаления исходного файла эта ссылка все еще указывает на данные в памяти.
    ```bash
    # Если PID равен 12345
    cp /proc/12345/exe /path/to/restored_script.sh
    ```
    Эта команда создаст точную копию удаленного файла.

## Exit code

**Exit code** (код завершения) — это целочисленное значение, которое программа или команда возвращает после своего завершения.

```bash
echo $?
```
-   **`0`**: Стандартное значение для успешного завершения.
-   **Ненулевые значения:** Указывают на ошибку или необычное завершение.
    -   `1`: Общая ошибка.
    -   `2`: Неправильное использование команды (например, неверные аргументы).
    -   `126`: Команда не может быть выполнена (например, из-за отсутствия прав).
    -   `127`: Команда не найдена.
    -   `128 + N`: Ошибки, связанные с сигналами (например, `130` — прерывание через `Ctrl+C`, так как `SIGINT` имеет номер 2).

### Диагностика утечек памяти

-   **`valgrind`**: Инструмент для обнаружения утечек памяти.
    ```bash
    valgrind --leak-check=full ./your-program
    ```
-   **`strace`**: Отслеживание системных вызовов для анализа выделения/освобождения памяти (`mmap`, `munmap`).
    ```bash
    strace -e trace=mmap,munmap -p <PID>
    ```

### Перезапуск процесса без остановки PID

**Пример:** Обновление Nginx

Вы перекомпилировали новый Nginx в `/usr/local/bin/nginx-new` и хотите подменить старый:

```bash
pidof nginx  # допустим, PID = 1234
sudo nsenter -t 1234 -m -u -i -n -p -- bash
cd /usr/local/bin
exec ./nginx-new -c /etc/nginx/nginx.conf
```
Новый бинарник работает в том же PID, открытые сокеты и дескрипторы остались на месте.

### Анализ сбоев: Coredump

**Coredump (дамп памяти)** — это файл, содержащий снимок рабочего адресного пространства процесса в момент его аварийного завершения. Он используется для посмертной отладки (post-mortem debugging), чтобы понять причину сбоя.

-   **`ulimit`**: Для создания coredump необходимо, чтобы лимит на его размер был установлен в ненулевое значение.
    ```bash
    # Разрешить создание coredump неограниченного размера
    ulimit -c unlimited
    ```

-   **`/proc/sys/kernel/core_pattern`**: Этот файл определяет, куда и в каком формате будут сохраняться дампы.

В современных системах с `systemd` процесс создания и управления дампами централизован.
-   **Конфигурация:** `/etc/systemd/coredump.conf`.
-   **`coredumpctl`**: Утилита для работы с сохранёнными дампами.
    ```bash
    # Показать список всех сохранённых дампов
    coredumpctl list
    # Показать подробную информацию о последнем сбое
    coredumpctl info
    # Извлечь дамп в файл для анализа в gdb
    coredumpctl dump <PID> -o my_coredump
    ```

## Расширенные детали

### `nsenter`: Вход в окружение процесса

Утилита `nsenter` позволяет "войти" в окружение другого процесса, используя его [пространства имён (namespaces)](../namespaces.md). Это мощный инструмент для отладки контейнеров и изолированных процессов.
Например, `sudo nsenter -t <PID> -n ip addr` покажет сетевые интерфейсы так, как их "видит" процесс с `<PID>`.
