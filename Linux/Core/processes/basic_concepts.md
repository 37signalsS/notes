# Основные концепции процессов в Linux

## Определения

**Процесс** — это выполняющийся экземпляр программы, обладающий собственными ресурсами и изолированный от других процессов. Фундаментальные понятия Userspace, Kernelspace и системных вызовов подробно описаны в разделе [**Процессы: Определения**](./definitions.md).

## Основные концепции

### Методы создания процессов

В Linux создание новых задач (tasks) осуществляется через три основных системных вызова:

- **`fork()`** — создаёт новый процесс путем полного дублирования текущего.
  - Дочерний процесс получает копию адресного пространства родителя (используя механизм Copy-on-Write) и идентичные дескрипторы открытых файлов.
  - Вызов возвращает `0` внутри дочернего процесса и PID (Process Identifier) созданного потомка в родительском процессе.
- **`exec()`** — семейство вызовов, которые заменяют текущий процесс новой программой.
  - PID, PPID (Parent PID) и открытые файловые дескрипторы сохраняются, но код и данные процесса полностью обновляются.
  - Типичный паттерн запуска утилит в Shell — это последовательность `fork()` + `exec()`.
- **`clone()`** — современный вызов, позволяющий гибко настраивать общие ресурсы (память, сигналы, дескрипторы) между родителем и потомком. Является базой для создания **потоков (threads)**.

### Механизм Copy-on-Write (CoW)

**Copy-on-Write (копирование при записи)** — это стратегия оптимизации памяти, при которой данные совместно используются несколькими процессами до тех пор, пока один из них не попытается внести изменения.

При выполнении `fork()` ядро не копирует физические страницы памяти родителя. Вместо этого оно помечает их как доступные только для чтения для обоих процессов. Физическое копирование страницы происходит только в момент попытки записи, что значительно ускоряет создание процессов и экономит оперативную память (RAM).

### Идентификация и иерархия процессов

Каждый процесс в системе имеет уникальный идентификатор **PID**.

#### Специальные процессы

- **PID 0 (idle / swapper):** Внутренняя задача ядра. Создается при инициализации и представляет собой контекст выполнения центрального процессора (CPU — Central Processing Unit), когда нет других готовых задач. Не виден в списке процессов Userspace.
- **PID 1 (init / systemd):** Первый процесс пространства пользователя, "прародитель" всех остальных процессов. Отвечает за запуск служб и "усыновление" осиротевших процессов.

#### Типы родственных связей

- **Процесс-сирота (Orphan):** Дочерний процесс, чей родитель завершил работу. Ядро переназначает родителя на процесс с PID 1 (init/systemd), который вызовет `wait()` при завершении orphan. Технически это не является проблемой.
- **Зомби-процесс (Zombie):** Дочерний процесс вызвал `exit()`, ядро освободило все ресурсы (память, файловые дескрипторы), но оставило запись в таблице процессов — пока родитель не заберёт код возврата через `wait()`. Запись не потребляет CPU или память, только занимает слот в таблице PID.

### Состояния процесса

В процессе жизненного цикла задача может находиться в одном из следующих состояний (отображаются в `top`, `htop`, `ps`):

| Состояние | Описание |
| :--- | :--- |
| **R** (Running/Runnable) | Выполняется на CPU в данный момент или стоит в очереди планировщика. |
| **S** (Sleeping) | Прерываемый сон. Ожидает события (ввод пользователя, сетевой пакет). |
| **D** (Disk sleep) | Непрерываемый сон. Ожидает завершения I/O (Input/Output). Не реагирует на сигналы. |
| **T** (Stopped) | Остановлен сигналом (например, `Ctrl+Z`) или находится под отладкой. |
| **Z** (Zombie) | Завершён, ожидает сбора статуса родителем. |

## Практические сценарии

### Жизненный цикл команды в Shell

Рассмотрим процесс выполнения команды `ls` в терминале:

1. **Ожидание:** Shell (`bash`) ждет ввода пользователя.
2. **Создание копии:** Shell вызывает `fork()`, создавая своего "двойника".
3. **Замена кода:** Дочерний процесс вызывает `exec(ls)`, становясь программой `ls`.
4. **Ожидание завершения:** Родительский Shell вызывает `wait()`, приостанавливая свою работу.
5. **Завершение:** Программа `ls` выполняет задачи и вызывает `exit()`, переходя в состояние зомби.
6. **Очистка:** Ядро отправляет сигнал `SIGCHLD` родителю. Shell просыпается, считывает статус выхода `ls` и удаляет его запись из таблицы процессов.

### Мониторинг через файловую систему /proc

Вся информация о процессах доступна в реальном времени через виртуальную файловую систему **procfs**, монтируемую в `/proc`:

```bash
# Команда запуска процесса
cat /proc/<PID>/cmdline
# → /usr/sbin/nginx-gdaemon off;

# Переменные окружения
cat /proc/<PID>/environ
# → PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/binHOME=/root...

# Статус процесса (PID, PPID, UID — User Identifier, Memory)
cat /proc/<PID>/status
# → Name:   nginx
# → Umask:  0000    0000    0000    0000
# → State:  S (sleeping)
# → Tgid:   1234
# → Ngid:   0
# → Pid:    1234
# → PPid:   1

# Список открытых файловых дескрипторов
ls -l /proc/<PID>/fd/
# → lrwx------ 1 root root 64 Jan  1 12:00 0 -> /dev/null
# → lrwx------ 1 root root 64 Jan  1 12:00 1 -> /dev/null
```

## Дополнительная информация

### Планирование и приоритеты

Ядро Linux распределяет процессорное время между задачами с помощью планировщика (современный стандарт — **EEVDF**). Пользователь может влиять на приоритет процесса через параметр `nice`.
Подробнее см. раздел [**Планирование процессов**](./scheduling.md).

### Опасности накопления зомби

Хотя зомби не потребляют CPU и RAM, они занимают записи в таблице процессов. Большое количество зомби (тысячи) = баг в родителе (не вызывает `wait()`). Исчерпание лимита PID блокирует запуск новых программ.

**Убить зомби напрямую нельзя** — нужно убить или починить родителя. После завершения родителя зомби усыновляются PID 1 и удаляются.

Подробнее см. раздел [**Зомби-процессы**](./additional_info.md#зомби-процессы-и-управление-их-жизненным-циклом).

### Потоки против процессов

Потоки одного процесса разделяют общее адресное пространство, что делает их создание "дешевле", но снижает уровень изоляции.
Подробнее см. раздел [**Процессы vs Потоки: концептуальное отличие**](./additional_info.md#процессы-vs-потоки-концептуальное-отличие).
