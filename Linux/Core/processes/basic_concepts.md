# Основные концепции процессов в Linux

## Определения

**Процесс** — это динамический объект, представляющий собой выполняющийся экземпляр программы, обладающий собственными ресурсами и изолированный от других процессов. В ядре Linux любая единица выполнения (процесс или поток) представлена структурой `task_struct` и называется **задачей (task)**.

Фундаментальные понятия Userspace, Kernelspace и системных вызовов подробно описаны в разделе [**Процессы: Определения**](./definitions.md).

## Основные концепции

### Анатомия процесса (Образ памяти)

При запуске программы ядро создает «образ» процесса в виртуальной памяти. Он состоит из нескольких функциональных сегментов:

| Сегмент | Назначение | Особенности |
| :--- | :--- | :--- |
| **Text (Code)** | Машинный код программы. | Только чтение (`read-only`), исполняемый. |
| **Data** | Инициализированные глобальные и статические переменные. | Чтение и запись. |
| **BSS** | Неинициализированные глобальные переменные. | Заполняется нулями при старте. |
| **Heap (Куча)** | Динамическая память (`malloc`, `new`). | Растет «вверх» к старшим адресам. |
| **Stack (Стек)** | Локальные переменные, аргументы функций, адреса возврата. | Растет «вниз» к младшим адресам. |
| **Memory Mapping**| Общие библиотеки (`.so`), отображение файлов (`mmap`). | Находится между стеком и кучей. |

### Методы создания процессов

В Linux создание новых задач осуществляется через механизмы дублирования и замещения образа.

- **`fork()`** — классический вызов, создающий полную копию родительского процесса.
  - Возвращает `0` в дочернем процессе и `PID` ребенка в родительском.
  - Использует механизм **Copy-on-Write (CoW)**: физические страницы памяти копируются только при попытке записи, что делает `fork()` крайне эффективным.
- **`exec()`** — семейство вызовов (`execve` и др.), заменяющих текущий образ процесса новой программой.
  - **Техническая деталь:** Файловые дескрипторы по умолчанию сохраняются при `exec`. Для предотвращения утечек ресурсов рекомендуется использовать флаг **`O_CLOEXEC`** при открытии файлов.
- **`clone()`** — универсальный вызов, лежащий в основе создания как процессов, так и **потоков (threads)**. Позволяет гибко выбирать, какие ресурсы разделять между родителем и потомком (память, файловая таблица, сигналы).
  - Подробное сравнение процессов и потоков приведено в [**Дополнительной информации**](./additional_info.md).

### Идентификация и иерархия

#### Уровни идентификации
Каждый процесс вписан в сложную иерархию:
1.  **PID (Process ID):** Уникальный идентификатор процесса.
2.  **PPID (Parent PID):** Ссылка на родителя.
3.  **PGID (Process Group ID):** Группирует процессы для управления заданиями (Job Control) и рассылки сигналов (например, всему конвейеру `ls | grep`).
4.  **SID (Session ID):** Группирует процессы в рамках одного входа пользователя (терминальной сессии).

#### Специальные процессы
- **PID 0 (idle):** Контекст ядра, когда CPU простаивает.
- **PID 1 (init / systemd):** «Отец всех процессов». Первый процесс Userspace.
  - **Reparenting:** «Усыновляет» процессы-сироты (**Orphan**), чей родитель завершился.
  - **Reaping:** Обязан собирать статусы завершения через `wait()` для предотвращения накопления **зомби-процессов**.

#### Пространства имен (Namespaces)
Механизм изоляции, позволяющий процессу иметь разные PID на разных уровнях:
- Внутри контейнера процесс может видеть себя под **PID 1**.
- На хосте тот же процесс будет иметь свой реальный глобальный **PID (например, 5678)**.

### Состояния процесса

Статус процесса отображается в `top`, `ps` (колонка `STAT`).

| Состояние | Код | Описание |
| :--- | :--- | :--- |
| **Running** | **R** | Выполняется или готов к выполнению (в очереди планировщика). |
| **Sleeping** | **S** | Прерываемый сон (Interruptible). Ожидает внешнего события (I/O). |
| **Uninterruptible**| **D** | Непрерываемый сон. Обычно ожидание дискового I/O. Не реагирует на сигналы. |
| **Stopped** | **T** | Остановлен сигналом управления (`SIGSTOP`, `Ctrl+Z`). |
| **Zombie** | **Z** | Завершен, но запись в таблице процессов осталась до вызова `wait()` родителем. |
| **Idle** | **I** | Бездействующий поток ядра (Kernel Thread). |

### Переключение контекста (Context Switch)

Ядро создает иллюзию параллелизма, быстро переключая процессор между задачами.
- **Стоимость:** Переключение между процессами «дорогое», так как требует смены таблиц страниц памяти и очистки кэшей процессора (TLB).
- **Потоки:** Переключение между потоками одного процесса дешевле, так как они разделяют адресное пространство.

## Практические сценарии

### Жизненный цикл команды в Shell

Выполнение `ls` в терминале:
1. **Wait:** Shell ждет ввода пользователя.
2. **Fork:** Shell создает дочерний процесс (свою копию).
3. **Exec:** Дочерний процесс заменяет себя кодом `/bin/ls`.
4. **Wait:** Shell блокируется до завершения ребенка.
5. **Exit & Cleanup:** `ls` завершается, Shell считывает код возврата и выводит приглашение к вводу.

### Диагностика владельца и прав

Информация о UID/GID доступна в `/proc/<PID>/status`. В Linux права определяются не только UID, но и **Capabilities** (гранулярные привилегии).

```bash
# Проверка прав текущего shell
grep CapEff /proc/$$/status
```

### Анализ зомби и сирот

**Зомби (Z)** не потребляют ресурсы, но занимают место в таблице процессов.
```bash
# Поиск зомби-процессов
ps aux | awk '$8=="Z" {print $2}'
```
Если зомби много, проблема в родителе (не вызывает `wait()`). Если родитель завершился, зомби переходят к PID 1 и зачищаются им автоматически.

### Трассировка и дерево процессов

```bash
# Визуализация иерархии с аргументами
pstree -ap

# Кто запустил конкретный процесс?
ps -o ppid= -p <PID>
```

## Дополнительная информация

### Среда окружения (Environment)

Процессы наследуют переменные окружения родителя. Это основной способ передачи конфигурации (например, `PATH`, `HOME`, `DB_URL`) в Linux. Список переменных процесса можно увидеть в `/proc/<PID>/environ` (разделены нулевым байтом).

### Безопасность и изоляция

- **Chroot:** Ограничение видимости файловой системы (старый метод).
- **Namespaces:** Изоляция ресурсов (PID, Network, Mount).
- **Capabilities:** Позволяют дать процессу право слушать порты < 1024 (`CAP_NET_BIND_SERVICE`) без выдачи полных прав `root`.
