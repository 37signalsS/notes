# Процессы в Linux: Основные концепции

## Basic Concepts

### Методы создания процессов

- **`fork()`** — создаёт новый процесс путем **точного дублирования** текущего.
  - **Возвращаемые значения:** возвращает `0` в дочернем процессе и PID созданного потомка в родительском процессе.
  - **Состояние:** дочерний процесс получает копию адресного пространства родителя (через Copy-on-Write) и те же открытые дескрипторы.

- **`exec()`** — **заменяет** текущий процесс новой программой. PID, PPID и открытые файловые дескрипторы сохраняются, но адресное пространство полностью заменяется кодом и данными новой программы.

  > Паттерн `fork()` + `exec()` — классический способ запуска команд в shell. Сначала создается копия shell (`fork`), затем эта копия заменяет себя нужной утилитой (`exec`).

- **`clone()`** — обеспечивает тонкую настройку общих ресурсов между родительским и дочерним процессами (память, файловые дескрипторы, таблица сигналов).

  > `clone()` — основа для создания **потоков** в Linux.

---

### Процессы vs Потоки

| Аспект | Процесс | Поток |
| :--- | :--- | :--- |
| **Память** | Изолированное адресное пространство | Общее адресное пространство процесса |
| **Ресурсы** | Свои дескрипторы, лимиты | Общие дескрипторы и ресурсы процесса |
| **Создание** | "Тяжелое" (требует копирования таблиц страниц) | "Легкое" (общие ресурсы) |
| **Изоляция** | Высокая (падение одного не влияет на другие) | Низкая (ошибка в потоке может свалить весь процесс) |

Подробное сравнение на уровне ядра: [Процессы vs Потоки: концептуальное отличие](./additional_info.md#процессы-vs-потоки-концептуальное-отличие).

### Copy-on-Write (CoW)

**Copy-on-Write** — стратегия, при которой данные не копируются при создании дубликата, а совместно используются до первой модификации.

При `fork()` родительский и дочерний процессы изначально используют одни и те же физические страницы памяти. Копия создаётся только при попытке записи. Это ускоряет создание процессов и экономит память.

### Идентификация и иерархия

**PID (Process ID)** — уникальный номер процесса. **PPID (Parent Process ID)** — PID родительского процесса. При достижении `/proc/sys/kernel/pid_max` PID циклически переиспользуются.

#### Идентификаторы ядра и userspace

| Идентификатор | Уровень | Описание |
| :--- | :--- | :--- |
| **TID (Thread ID)** | Ядро | Уникальный идентификатор потока. В ядре каждый поток — отдельная задача (task) |
| **TGID (Thread Group ID)** | Ядро | Объединяет потоки одного процесса. Все потоки имеют одинаковый TGID |
| **PID** | Userspace | Равен TGID главного потока. Для однопоточного процесса: TID = TGID = PID |

> Ядро оперирует `task_struct`, где каждая задача имеет свой TID. `execve` может завершить все потоки многопоточного процесса, оставив один — тогда TID может не совпадать с TGID и PID.

#### Специальные процессы

**PID 0 (idle / swapper):** Внутренняя задача ядра, не userspace-процесс. Создаётся ядром при инициализации.

- **Назначение:** первый контекст выполнения; после загрузки — idle task на каждом ядре CPU
- **Особенности:** не виден в `ps` и `/proc/`, создаётся ядром напрямую (не через `fork()`/`clone()`)
- **Многоядерность:** отдельный idle context для каждого ядра (swapper/0, swapper/1, ...)

  > "Swapper" — исторический артефакт. В современном Linux PID 0 **не отвечает за подкачку страниц**.

**PID 1 (init / systemd):** Первый процесс userspace, прародитель всех процессов.

- Запуск системных служб и демонов
- Усыновление осиротевших процессов
- Корректное завершение системы

  Завершение PID 1 приводит к kernel panic. Процесс защищён от OOM Killer (минимальный `oom_score`). Подробнее: [Механизм OOM Killer](./oom_killer_mechanism.md#как-oom-killer-выбирает-жертву).

**Процесс-сирота:** Дочерний процесс, родитель которого завершился. Усыновляется PID 1 (`init`/`systemd`), который ожидает завершения и освобождает ресурсы.

### Элементы процесса

- **`task_struct`** — центральная структура ядра с полной информацией о процессе (см. [определение процесса](./definitions.md#что-такое-процесс))
- **Контекст выполнения** — регистры процессора, счётчик команд
- **Файловые дескрипторы** — по умолчанию stdin, stdout, stderr
- **Адресное пространство** — виртуальная память процесса
- **Иерархия** — связи с родительским и дочерними процессами

### Типы процессов

- **User Processes** — запускаются пользователями в userspace
- **Kernel Processes/Threads** — работают исключительно в kernelspace
- **Daemons** — фоновые процессы, ожидающие событий

### Состояния процесса

**Жизненный цикл:** Created → Ready → Running → Waiting → Terminated

**Состояния (ps, top, htop):**

| Состояние | Описание |
| :--- | :--- |
| **R** (Running/Runnable) | Выполняется на CPU или готов к выполнению (стоит в очереди планировщика). |
| **S** (Sleeping) | Прерываемый сон (interruptible sleep). Ожидает события (ввод пользователя, сетевой пакет) или освобождения ресурса. Реагирует на сигналы. |
| **D** (Disk sleep) | Непрерываемый сон (uninterruptible sleep). Ожидает завершения I/O. Процесс **не реагирует на сигналы** (включая SIGKILL). Типичный сценарий: зависший NFS или проблемы с диском. |
| **T** (Stopped/Traced) | Остановлен сигналом (например, `SIGSTOP` или `Ctrl+Z`) или находится под отладкой (ptrace). |
| **Z** (Zombie) | Завершён, но запись в таблице процессов сохраняется, пока родитель не заберет статус через `wait()`. |
| **I** (Idle) | Поток ядра, находящийся в глубоком сне и не учитываемый в нагрузке (load average). |

### Зомби и сироты: жизненный цикл

1.  **Зомби (Zombie):** Когда процесс умирает, он освобождает все ресурсы (память, файлы), но его PID и статус выхода остаются в таблице процессов. Это нужно, чтобы родитель мог узнать, как завершился потомок. Если родитель не вызывает `wait()`, зомби остается в системе навсегда.
    -   **Опасность:** Исчерпание таблицы PID.
2.  **Сирота (Orphan):** Если родитель завершается раньше потомка, потомок усыновляется процессом `init` (PID 1). `init` гарантирует вызов `wait()` для всех своих «приемных детей».

## Practical Scenarios

### Жизненный цикл команды в Shell

1. **Ввод команды:** Shell (`bash`, `zsh`) ожидает ввода
2. **`fork()`:** Shell создаёт дочерний процесс
3. **`wait()`:** Родитель приостанавливается, ожидая завершения дочернего
4. **`exec()`:** Дочерний процесс заменяет себя новой программой
5. **`exit()`:** Программа завершается, переходит в состояние зомби
6. **`SIGCHLD`:** Ядро уведомляет родителя
7. **Сбор статуса:** Родитель вызывает `wait()`, освобождая запись зомби

### Мониторинг процессов

**`/proc/<PID>/`:**

- `cmdline` — команда запуска
- `environ` — переменные окружения
- `status` — PID, PPID, UID, GID, память
- `fd/` — открытые файловые дескрипторы

**Утилиты:**

```bash
ps -ef | less -S        # Снимок всех процессов
pstree -p               # Дерево процессов с PID
pidof <name>            # PID по имени
pgrep <name>            # Поиск процесса по имени
watch "ps -ef"          # Периодическое обновление
```

**Ключи `ps`:**

- Unix-style: `-e` (все), `-f` (полный формат)
- BSD-style: `aux` (все с владельцем)
- GNU-style: `--forest` (дерево)

## Additional Information

### Планировщик и единица планирования

Фундаментальной единицей планирования в Linux является **"задача" (task)**. Каждый поток рассматривается как отдельная задача, подлежащая планированию. Подробнее: [Планирование процессов](./scheduling.md).

### Многопоточность и clone()

`clone()` позволяет создавать потоки с общей памятью, файловыми дескрипторами и таблицей сигналов. Сравнение процессов и потоков: [Процессы vs Потоки](./additional_info.md#процессы-vs-потоки-концептуальное-отличие).

### Риски зомби-процессов

Зомби не потребляют память или CPU, но удерживают записи в таблице процессов. Массовое накопление зомби ведёт к исчерпанию PID и отказу в обслуживеании. Подробнее: [Чем опасны зомби](./additional_info.md#чем-опасны-зомби-процессы).
