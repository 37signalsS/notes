# Основные концепции процессов в Linux

## Определения

**Процесс** — это динамический объект, представляющий собой выполняющийся экземпляр программы, обладающий собственными ресурсами и изолированный от других процессов. Фундаментальные понятия Userspace, Kernelspace и системных вызовов подробно описаны в разделе [**Процессы: Определения**](./definitions.md).

## Основные концепции

### Методы создания процессов

В Linux создание новых задач (tasks) осуществляется через механизмы дублирования и замещения образа.

- **`fork()`** — классический системный вызов, создающий полную копию родительского процесса.
  - У `fork()` есть особенность, он возвращает **два разных значения одновременно**. Родителю он возвращает PID новорождённого потомка, а самому потомку — `0`. Так каждый из них понимает, кто он: родитель или ребёнок.
  - Дочерний процесс получает копию адресного пространства родителя (используя механизм **Copy-on-Write**) и идентичные дескрипторы открытых файлов.
- **`vfork()`** — оптимизированная версия для случаев, когда за созданием процесса сразу следует `exec()`. Родитель приостанавливается, а дочерний процесс использует адресное пространство родителя напрямую до момента вызова `exec` или `_exit`, что экономит ресурсы на копировании таблиц страниц.
- **`exec()`** — семейство вызовов (`execve`, `execl` и др.), которые заменяют текущий образ процесса (код, данные, стек) новой программой.
  - Если `fork()` создает "близнеца", то `exec()` "переодевает" этого близнеца в нужную нам программу. Вместе `fork + exec` — это стандартный способ запуска любой команды в Linux. PID и открытые дескрипторы (если не установлен флаг `O_CLOEXEC`) сохраняются.
- **`clone()`** — базовый вызов, позволяющий гибко настраивать общие ресурсы (память, сигналы, дескрипторы) между родителем и потомком. Является фундаментом для создания **потоков (threads)**.
- **`posix_spawn()`** — современный интерфейс (реализован через `clone` или `vfork`), часто используемый высокоуровневыми языками для эффективного запуска подпроцессов без накладных расходов на полное дублирование контекста.

### Механизм Copy-on-Write (CoW)

**Copy-on-Write (копирование при записи)** — это стратегия оптимизации, при которой страницы физической памяти совместно используются родительским и дочерним процессами до тех пор, пока один из них не попытается внести изменения. Только в момент записи происходит физическое копирование страницы. Это значительно ускоряет `fork()` и экономит RAM.

### Идентификация и иерархия процессов

#### Идентификаторы
- **PID (Process ID):** Уникальный идентификатор процесса.
- **TGID (Thread Group ID):** Идентификатор группы потоков, совпадающий с PID основного потока.
- **TID (Thread ID):** Уникальный идентификатор конкретного потока (в контексте ядра каждый поток — отдельная задача).

#### Пространства имен PID (PID Namespaces)
В современных системах с поддержкой контейнеризации иерархия процессов изолирована. Это приводит к тому, что **один и тот же процесс может иметь несколько разных PID одновременно**:
- **Внутри контейнера (Child Namespace)**: Процесс может иметь **PID 1**, считая себя единственным в системе.
- **На хостовой машине (Root Namespace)**: Тот же самый процесс виден ядру под своим реальным глобальным PID (например, **PID 12345**).
- **Изоляция**: Сигнальное поведение также ограничено пространством имен. Процесс с PID 1 внутри контейнера игнорирует сигналы `SIGKILL` или `SIGTERM`, если для них не установлен явный обработчик.


#### Специальные процессы
- **PID 0 (idle / swapper):** Внутренняя задача ядра. Представляет собой контекст выполнения CPU, когда нет других готовых задач. Не виден в Userspace.
- **PID 1 (init / systemd):** Первый процесс пространства пользователя, "прародитель" и **"отец всех процессов"**. Его PID всегда равен 1. Это корень гигантского семейного дерева процессов, все остальные процессы в системе — его прямые или косвенные потомки.
  Критические задачи:
  - Инициализация системы и запуск служб.
  - **Reparenting:** "Усыновление" процессов-сирот (Orphan), чей родитель завершился.
  - **Reaping ("Могильщик"):** PID 1 обязан собирать статусы завершения через `wait()` для всех усыновленных процессов, чтобы "хоронить" их и очищать таблицу дескрипторов задач.

#### Типы родственных связей
- **Процесс-сирота (Orphan):** Дочерний процесс, чей родитель завершил работу. Ядро переназначает его родителем процесс с PID 1.
- **Зомби-процесс (Zombie):** Дочерний процесс вызвал `exit()`, ядро освободило ресурсы (память, FD), но оставило запись в таблице процессов до тех пор, пока родитель не заберет код возврата через `wait()`.

### Состояния процесса

Статус процесса отображается в `top`, `htop`, `ps` в колонке `STAT`.

| Состояние | Код | Описание |
| :--- | :--- | :--- |
| **Running** | **R** | Выполняется на CPU или стоит в очереди выполнения (`runqueue`). |
| **Sleeping** | **S** | Прерываемый сон. Ожидает события (сеть, ввод). Прерывается сигналами. |
| **Uninterruptible**| **D** | Непрерываемый сон. Ожидает I/O (диск, **NFS**). Не реагирует на сигналы (даже `kill -9`). Процесс зависает "намертво", поможет только ребут. |
| **Stopped** | **T** | Остановлен сигналом управления заданиями (`Ctrl+Z`, `SIGSTOP`). |
| **Traced** | **t** | Остановлен отладчиком (`strace`, `gdb`). |
| **Zombie** | **Z** | Завершен (defunct), ожидает сбора статуса родителем через `wait()`. |
| **Idle** | **I** | Бездействующий поток ядра (Kernel Thread). |

**Дополнительные флаги подсостояний:**
- `s` — лидер сессии (обычно процесс оболочки).
- `+` — процесс находится в группе переднего плана (foreground).
- `l` — многопоточный процесс (NPTL).
- `<` — высокоприоритетный процесс (nice < 0).
- `N` — низкоприоритетный процесс (nice > 0).

## Практические сценарии

### Жизненный цикл команды в Shell

Разберем выполнение `ls` в терминале:
1. **Wait:** Shell (`bash`) ждет ввода.
2. **Fork:** Shell создает свою копию через `fork()`.
3. **Exec:** Дочерний процесс вызывает `exec(ls)`, заменяя код Bash кодом `ls`.
4. **Wait:** Родительский Shell вызывает `waitpid()`, блокируясь.
5. **Exit:** `ls` завершается и переходит в состояние зомби (Z).
6. **Cleanup:** Ядро отправляет `SIGCHLD` родителю. Shell считывает статус выхода, и запись `ls` удаляется.

### Владелец процесса и UID

Информация о правах процесса доступна в `/proc/<PID>/status`:
- **Real UID:** Пользователь, запустивший процесс.
- **Effective UID:** Определяет текущие права доступа (может меняться для SUID-файлов).
- **Saved UID:** Позволяет процессу восстанавливать права после временного переключения.
- **FS UID:** Используется специфично для проверок прав файловой системы.

```bash
grep Uid /proc/$$/status
# → Uid: 1000 1000 1000 1000 (Real, Effective, Saved, FS)
```

### Иерархия процессов (дерево)

Визуализация связей:
```bash
# Дерево с PID и аргументами
pstree -ap

# ps с флагом forest (визуальные отступы)
ps f
```

### htop: полезные комбинации клавиш

| Клавиша | Действие |
| :--- | :--- |
| **F5** | Переключение в древовидный режим (Hierarchy). |
| **Shift+H** | Показать/скрыть пользовательские потоки (Threads). |
| **Shift+K** | Показать/скрыть потоки ядра (Kernel Threads). |
| **F9** | Меню отправки сигналов процессу. |
| **s** | Трассировка системных вызовов через `strace`. |
| **l** | Список открытых файлов через `lsof`. |

### Практические эксперименты и диагностика

#### Приостановка процесса (Ctrl+Z)
Запустите команду и приостановите её:
```bash
cat /dev/urandom > /dev/null
# Нажмите Ctrl+Z -> [1]+ Stopped
ps u  # Увидите статус T
fg    # Вернуть в foreground
```

#### Диагностика D-state (WCHAN)
Состояние **D** возникает при блокировке на ресурсах. Чтобы понять причину, проверьте `wchan`:
```bash
cat /proc/<PID>/wchan
# → nfs_wait_bit_killable  <-- Проблема с NFS-сервером
# → __lock_page            <-- Ожидание страницы памяти (дисковый I/O)
```

#### Профессиональный инструментарий
```bash
# Быстрый поиск PID по шаблону
pgrep -u root -l nginx

# Остановка группы процессов по имени
pkill -TERM -f "my_app_worker"

# Кто занимает порт или файл?
fuser -v 80/tcp
```

### Мониторинг через файловую систему /proc

- `/proc/<PID>/cmdline` — полная командная строка.
- `/proc/<PID>/environ` — переменные окружения.
- `/proc/<PID>/status` — сводка (PID, PPID, UID, Memory, Signals).
- `/proc/<PID>/fd/` — список открытых дескрипторов (файлы, сокеты).
- `/proc/<PID>/maps` — карта виртуальной памяти.

## Дополнительная информация

### Опасности накопления зомби
Зомби не потребляют CPU или RAM, но занимают запись в таблице процессов. Исчерпание лимита PID блокирует запуск новых задач. 
**Решение:** Исправить родительский процесс (добавить `wait()`) или завершить родителя (тогда зомби перейдут к PID 1).

**Пример создания зомби (C):**
```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    int pid = fork();
    if (pid == 0) {
        exit(0); // Ребенок сразу выходит
    } else {
        sleep(60); // Родитель не вызывает wait(), ребенок становится зомби
    }
    return 0;
}
```
