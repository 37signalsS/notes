# Checkpoint/Restore и перенос процессов

## Definitions

**Checkpoint/Restore** — механизм сохранения полного состояния процесса и его последующего восстановления с помощью утилиты CRIU (Checkpoint/Restore In Userspace).

**Перенос процессов** — миграция запущенных процессов между терминалами, сессиями или серверами с сохранением состояния.

**ptrace** — системный вызов, позволяющий одному процессу наблюдать и управлять другим процессом.

---

## Basic Concepts

### Как работает CRIU

CRIU сохраняет состояние процесса, создавая снимок (checkpoint), который включает:

- **Memory pages** — содержимое оперативной памяти процесса
- **Открытые файловые дескрипторы** — сокеты, файлы, pipes
- **Таблицу процессов** — информацию о потоках и дочерних процессах
- **Сигналы** — ожидающие и заблокированные сигналы
- **Namespaces и cgroups** — привязку к пространствам имён и группам управления

При восстановлении процесс получает точно такое же состояние, какое было на момент создания checkpoint.

> Подробное описание CRIU, сценарии применения (живая миграция, ускорение запуска, отказоустойчивость) — в [Troubleshooting index](./index.md#как-работает-criu).

### Ограничения CRIU

- Не все процессы можно заморозить (процессы с активными сетевыми соединениями могут потерять связь)
- Требуется `root` или `CAP_CHECKPOINT_RESTORE`
- Некоторые типы файлов не поддерживаются (например, отдельные драйверы устройств)
- Процесс и восстанавливающая система должны иметь совместимые ядра и архитектуры

### Механизм `/proc/<PID>/exe`

Ядро Linux не удаляет файл с диска, пока хотя бы один процесс держит его открытым. Символическая ссылка `/proc/<PID>/exe` указывает на исполняемый файл процесса, даже если он был удалён из файловой системы.

### Пространства имён и `nsenter`

Утилита `nsenter` позволяет войти в namespaces существующего процесса, что даёт возможность выполнить команду в контексте этого процесса, сохраняя его PID и открытые ресурсы.

> Подробнее: [namespaces](../../namespaces.md)

## Practical Scenarios

### Checkpoint/Restore с помощью CRIU

#### 1. Создать checkpoint процесса

```bash
# -t <pid>: указать PID процесса
# --images-dir: директория для сохранения файлов состояния
sudo criu dump -t <PID> --images-dir /tmp/checkpoint
```

#### 2. Восстановить процесс из checkpoint

```bash
# --daemon: запустить процесс в фоновом режиме
# --restore-detached: отсоединиться от процесса после восстановления
sudo criu restore --images-dir /tmp/checkpoint --daemon --restore-detached
```

### Восстановление удалённого исполняемого файла

Если скрипт или бинарный файл был удалён во время выполнения, его можно восстановить. Ядро Linux не удаляет файл с диска (inode и данные), пока хотя бы один процесс держит его открытым.

#### Шаги восстановления

1. **Найти PID процесса.** Используйте [`pgrep`](../../../Diagnostics/Processes/ps.md) или [`ps`](../../../Diagnostics/Processes/ps.md):

    ```bash
    pgrep -f my_script.sh
    ```

2. **Скопировать файл из `/proc`.** Исполняемый файл доступен по символической ссылке `/proc/<PID>/exe`:

    ```bash
    cp /proc/12345/exe /path/to/restored_script.sh
    ```

    Команда создаст точную копию удалённого файла.

### Перезапуск процесса без изменения PID

Можно подменить исполняемый файл работающего процесса, используя [`nsenter`](../../namespaces.md) для входа в его namespaces и `exec` для запуска нового бинарника. Это позволяет сохранить PID, открытые сокеты и файловые дескрипторы.

```bash
# Находим PID старого процесса
pidof nginx  # допустим, PID = 1234

# Входим в его окружение и заменяем процесс новым
sudo nsenter -t 1234 -m -u -i -n -p -- bash -c 'exec /usr/local/bin/nginx-new -c /etc/nginx/nginx.conf'
```

> Подробнее: [namespaces](../../namespaces.md)

### Перенос запущенного процесса в новый терминал (reptyr)

**Ситуация:** процесс (скрипт, сборка, дамп) запущен без `screen` или `tmux`. Закрытие сессии убьёт процесс.

**Решение:** использование утилиты `reptyr` для перехвата процесса и его миграции в новую сессию (например, внутри `tmux`).

> Подробная инструкция и примеры использования — в [reptyr](../../../Diagnostics/Processes/reptyr.md).
