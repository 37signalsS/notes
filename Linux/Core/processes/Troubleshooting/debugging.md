# Отладка процессов: утечки памяти, дампы памяти и зомби-процессы

## Определения

**Отладка (Debugging) процессов** — совокупность методов выявления и устранения ошибок, связанных с жизненным циклом процесса, потреблением ресурсов и аварийными завершениями.

**Memory Leak (утечка памяти)** — состояние, при котором приложение выделяет память в RAM, но не освобождает её после завершения использования. Это приводит к деградации производительности и срабатыванию OOM Killer.

**Coredump (дамп памяти)** — снимок адресного пространства процесса в момент аварии. Используется для анализа состояния регистров, стека и переменных на момент сбоя.

**Zombie Process (зомби-процесс)** — процесс, который завершил выполнение (вызвал `exit`), но всё ещё занимает запись в таблице процессов ядра, так как его родитель не прочитал код завершения. В выводе `ps` такие процессы помечаются как `<defunct>`.

## Основные концепции

### Типичные проблемы жизненного цикла

- **Аварийные сигналы:** Ядро завершает процесс при получении критических сигналов:
    - `SIGSEGV` (Segmentation Violation) — обращение к недопустимому участку памяти.
    - `SIGFPE` (Floating-Point Exception) — арифметическая ошибка (например, деление на ноль).
    - `SIGQUIT` — запрос на завершение с созданием дампа памяти.
- **Жизненный цикл зомби:** Когда процесс завершается, он переходит в состояние `EXIT_ZOMBIE`. Он не потребляет CPU или RAM, но занимает слот в таблице процессов (PID). Если количество зомби достигает лимита `pid_max`, запуск новых процессов в системе блокируется.
- **Деградация из-за утечек:** Утечки памяти часто незаметны на ранних этапах. Основные симптомы: рост использования Swap, увеличение времени отклика системы и периодические "падения" крупных сервисов.

Подробная иерархия лимитов и их влияние на процессы описаны в разделе [**Концепции лимитов ресурсов**](../resource_limits_concepts.md).

## Практические сценарии

### Диагностика утечек памяти

#### 1. Использование Valgrind (Среда разработки)
Обеспечивает детальный анализ, но значительно замедляет работу приложения (в 10-50 раз). Подходит для тестов, но не для продакшена.
```bash
valgrind --leak-check=full --show-leak-kinds=all ./your_program
```

#### 2. Трассировка выделения памяти (eBPF / BCC)
Современный метод для продакшена. Утилита `memleak` из пакета BCC отслеживает аллокации с минимальными накладными расходами.
```bash
# Просмотр топ-10 утечек процесса каждые 5 секунд
sudo memleak -p <PID> -t 5
```

#### 3. Анализ системных вызовов (strace)
Помогает увидеть, запрашивает ли процесс новую память у ядра через `brk`, `sbrk` или `mmap`.
```bash
# Отслеживание вызовов управления памятью
strace -e trace=memory -p <PID>
```

#### 4. Прямой анализ через /proc
Проверка текущего потребления (RSS — физическая память, VmSize — виртуальная).
```bash
# Сводная информация по памяти процесса
cat /proc/<PID>/status | grep -iE "vm(size|rss|swap)"

# Детальная карта распределения (агрегированная)
cat /proc/<PID>/smaps_rollup
```

### Анализ аварийных завершений (Coredump)

#### 1. Разрешение дампов
```bash
# Проверить текущий лимит (0 означает, что дампы запрещены)
ulimit -c

# Разрешить создание дампов любого размера
ulimit -c unlimited
```

#### 2. Работа с coredumpctl
В системах с `systemd` дампы собираются автоматически.
```bash
# Список последних 10 падений
coredumpctl list | tail -n 10

# Отладка последнего падения конкретного исполняемого файла
coredumpctl gdb /usr/bin/nginx
```

Подробное руководство по глубокой отладке: [**Отладка через Coredump**](../../../Diagnostics/Troubleshooting/coredump_debugging.md).

### Устранение зомби-процессов

#### Поиск и идентификация
```bash
# Поиск по статусу Z (Zombie) или слову defunct
ps aux | grep -w Z
# ИЛИ через флаги состояния
ps -el | grep 'Z'
```

#### Методы устранения
1. **Сигнал SIGCHLD:** Отправьте родителю сигнал, чтобы он выполнил `wait()` и "собрал" зомби.
    ```bash
    kill -s SIGCHLD <PARENT_PID>
    ```
2. **Завершение родителя:** Если родитель игнорирует сигналы, его необходимо завершить (`kill -9`). После этого зомби станут "сиротами" и будут усыновлены процессом `init` (PID 1), который автоматически очищает таблицу процессов.
    > **Важно:** Если родителем является PID 1, убивать его нельзя. В этом случае зомби — признак ошибки в самом `init` или системе инициализации.
