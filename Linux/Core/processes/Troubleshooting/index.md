# Устранение неисправностей процессов

## Определения

**Troubleshooting (устранение неисправностей) процессов** — систематическая диагностика проблем с процессами в Linux: анализ кодов завершения, утечек памяти, аварийных завершений, зомби-процессов и механизмов сохранения состояния.

**Код завершения (Exit code)** — целочисленное значение (0–255), возвращаемое процессом при завершении. Значение `0` означает успех, любое другое — ошибку. Подробное описание — в [Коды возврата в Shell](../../../Shell/exit_codes.md).

**Дамп памяти (Coredump)** — снимок адресного пространства процесса в момент аварийного завершения (например, при сигналах `SIGSEGV` или `SIGQUIT`). Используется для посмертной (post-mortem) отладки.

**CRIU (Checkpoint/Restore In Userspace)** — утилита для заморозки процесса с сохранением его полного состояния (память, PID (Process Identifier), файлы, сокеты) в файлы-образы с возможностью последующего восстановления.

## Основные концепции

### Наблюдаемость процессов

Диагностика строится на трёх уровнях анализа:

1. **Метрики** — потребление CPU (Central Processing Unit), оперативной памяти, ресурсов I/O (Input/Output). Инструменты: `top`, `ps`, `pidstat`.
2. **Логи** — стандартный вывод процесса, системные журналы `syslog` и `journalctl`.
3. **Трассировки** — анализ системных вызовов и взаимодействия с ядром. Инструменты: `strace`, `perf`, `bpftrace`.

### Основные методы диагностики

- **Анализ состояний** — проверка колонки `STAT` в выводе `ps` (состояния `R` — выполнение, `D` — ожидание ввода-вывода, `Z` — зомби).
- **Проверка открытых ресурсов** — использование `lsof` для анализа файловых дескрипторов и сетевых соединений.
- **Трассировка системных вызовов** — использование `strace` для понимания, на каком этапе процесс «зависает» или получает ошибку от ядра.
- **Вход в контекст** — использование `nsenter` для работы внутри пространств имён (namespaces) процесса.
