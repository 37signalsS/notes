# Устранение неисправностей процессов

## Определения

### CRIU (Checkpoint/Restore In Userspace)

**CRIU** — это утилита для Linux, которая позволяет "заморозить" работающий процесс или группу процессов и сохранить их состояние в виде набора файлов на диске. Позже это состояние можно использовать для восстановления процессов с того же самого места, даже на другой машине.

### Код завершения (Exit code)

**Код завершения (Exit code)** — это целочисленное значение, которое программа или команда возвращает после своего завершения. Подробное описание кодов завершения см. в заметке [**Коды завершения (Exit codes)**](../../../Shell/exit_codes.md).

### Дамп памяти (Coredump)

**Дамп памяти (Coredump)** — это файл, содержащий снимок рабочего адресного пространства процесса в момент его аварийного завершения (часто в результате получения [сигнала](../signals.md), такого как `SIGSEGV` или `SIGQUIT`). Он используется для посмертной отладки (post-mortem debugging), чтобы понять причину сбоя.

## Basic Concepts

### Коды завершения (Exit Codes)

Код завершения можно проверить с помощью переменной `$?`.

| Код | Описание | Пример |
| :--- | :--- | :--- |
| **0** | Успешное завершение | Команда выполнилась без ошибок |
| **1** | Общая ошибка | Общая ошибка приложения |
| **2** | Неправильное использование | Неверные аргументы командной строки |
| **126** | Нет прав на выполнение | Файл есть, но нет прав на запуск |
| **127** | Команда не найдена | Опечатка в имени или нет в PATH |
| **128 + N** | Завершение сигналом | `130` = `128 + 2` (SIGINT), `137` = `128 + 9` (SIGKILL) |
| **130** | Прерывание (Ctrl+C) | SIGINT (сигнал 2) |
| **137** | OOM Kill / SIGKILL | SIGKILL (сигнал 9) — часто от OOM Killer |
| **143** | SIGTERM | Graceful shutdown (сигнал 15) |

```bash
# Проверить код завершения последней команды
ls /nonexistent
echo $?  # Вывод: 2

# Проверить код завершения успешно
ls /etc
echo $?  # Вывод: 0
```

### Как работает CRIU

CRIU сохраняет практически все состояние процесса: память, PID, открытые файлы, сокеты (включая установленные TCP-соединения), каналы, таймеры и т.д.

**Зачем это нужно:**

- **Живая миграция (Live Migration):** Перенос контейнеров или приложений между серверами практически без простоя.
- **Ускорение запуска:** "Долгоиграющие" приложения можно быстро восстанавливать из сохраненного состояния.
- **Отказоустойчивость:** Периодическое сохранение состояния критически важных процессов.

### Как работает Coredump

При аварийном завершении процесса, если это разрешено настройками системы, ядро создает файл coredump, содержащий полную копию памяти процесса и его состояния.

## Additional Information

### Связь с observability

Диагностика процессов является частью более широкой практики **Observability** (наблюдаемость системы). Подробнее см. в заметке [**Observability Overview**](../../../../Concepts/Observability_and_Monitoring/observability_overview.md).

**Три столпа observability применительно к процессам:**

1. **Метрики:** CPU, память, I/O (top, ps, pidstat)
2. **Логи:** Вывод приложения, syslog, journalctl
3. **Трассировки:** strace, perf, bpftrace
