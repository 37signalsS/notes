# Устранение неисправностей процессов в Linux

## Определения

**Troubleshooting (устранение неисправностей) процессов** — систематическая диагностика проблем: анализ кодов завершения, утечек памяти, аварийных завершений, зомби-процессов и механизмов сохранения состояния.

**Exit code (код завершения)** — целочисленное значение (0–255), возвращаемое процессом при завершении. Значение `0` означает успех, любое другое — ошибку. Подробное описание — в [Коды возврата в Shell](../../../Shell/exit_codes.md).

**Coredump (дамп памяти)** — снимок адресного пространства процесса в момент его аварийного завершения (например, при сигналах `SIGSEGV` или `SIGQUIT`). Используется для посмертной (post-mortem) отладки.

**OOM Killer (Out of Memory Killer)** — механизм ядра Linux, который принудительно завершает один или несколько процессов при критической нехватке оперативной памяти для поддержания стабильности системы.

**CRIU (Checkpoint/Restore In Userspace)** — утилита для "заморозки" работающего процесса с сохранением его полного состояния (память, PID, открытые файлы) в файлы-образы с возможностью последующего восстановления на этом же или другом хосте.

## Основные концепции

### Источники диагностических данных

Диагностика строится на анализе данных из нескольких независимых источников:

1.  **Метрики ресурсов:** Потребление CPU, RAM (RSS/VSZ), I/O и сетевой активности. Инструменты: `top`, `htop`, `ps`, `pidstat`.
2.  **Системные журналы:**
    -   `dmesg` — буфер сообщений ядра, критически важен для поиска записей о Segmentation fault, Kernel panic и срабатываниях OOM Killer.
    -   `journalctl` — системный журнал (systemd), содержащий логи сервисов и сообщения о сбоях юнитов.
3.  **Файловая система /proc:** Интерфейс ядра, предоставляющий детальную информацию о каждом процессе в реальном времени (например, `/proc/[pid]/status`, `/proc/[pid]/limits`, `/proc/[pid]/fd`).
4.  **Трассировки и отладка:** Анализ системных вызовов (`strace`), библиотечных вызовов (`ltrace`) и состояния потоков в реальном времени (`gdb`, `perf`, `bpftrace`).

### Уровни анализа (Методология)

-   **Прикладной уровень:** Анализ кодов возврата и логов самого приложения.
-   **Системный уровень:** Проверка лимитов ресурсов (`ulimit`), доступности файловых дескрипторов и состояния памяти.
-   **Уровень ядра:** Анализ взаимодействия с аппаратным обеспечением, обработка сигналов и работа в изолированных контекстах (namespaces).
