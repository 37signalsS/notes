# Конкурентность и синхронизация процессов в Linux

## Определения

**Конкурентность (Concurrency)** — способность операционной системы или приложения обеспечивать логическое выполнение нескольких задач в пересекающиеся периоды времени. В Linux это реализуется через вытесняющую многозадачность (preemptive multitasking).

**Состояние гонки (Race Condition)** — ситуация, при которой результат выполнения программы зависит от непредсказуемого порядка планирования потоков или процессов при доступе к разделяемому ресурсу.

**Критическая секция (Critical Section)** — участок кода, требующий эксклюзивного доступа к общему ресурсу. Должен выполняться атомарно относительно других потоков.

**Взаимоблокировка (Deadlock)** — состояние системы, при котором несколько процессов бесконечно ожидают ресурсы, захваченные друг другом.

**Голодание (Starvation)** — ситуация, при которой поток не может получить доступ к ресурсу в течение неоправданно долгого времени из-за того, что планировщик или механизмы синхронизации отдают приоритет другим потокам.

**Livelock** — состояние, при котором потоки постоянно меняют свои состояния в ответ на действия друг друга, но не совершают полезной работы (активное ожидание, не приводящее к прогрессу).

## Основные концепции

### Механизмы синхронизации в Userspace

В пространстве пользователя стандартом является библиотека **POSIX Threads (pthreads)**.

| Механизм | Описание | Область применения |
| :--- | :--- | :--- |
| **Мьютекс (Mutex)** | Взаимное исключение. Поток засыпает, если мьютекс занят. | Защита данных в памяти между потоками одного процесса. |
| **Futex (Fast Userspace Mutex)** | Низкоуровневая база для мьютексов в Linux. Позволяет выполнять операции без перехода в режим ядра, если нет конкуренции. | Реализация примитивов синхронизации в стандартных библиотеках (glibc). |
| **Семафор (Semaphore)** | Счётчик доступных ресурсов. Может использоваться между несвязанными процессами. | Ограничение доступа к пулу ресурсов (например, соединениям). |
| **Барьеры (Barriers)** | Точка сбора для группы потоков. Никто не проходит дальше, пока не соберутся все. | Параллельные вычисления, синхронизация этапов обработки. |

### Механизмы синхронизации в Kernelspace

Ядро Linux использует специализированные примитивы для обеспечения высокой производительности.

| Механизм | Описание | Особенности |
| :--- | :--- | :--- |
| **Спинлок (Spinlock)** | Активное ожидание в цикле. | Используется в контексте прерываний, где нельзя засыпать. |
| **RCU (Read-Copy-Update)** | Позволяет читать данные без блокировок, даже во время обновления. | Идеально для структур, которые часто читаются и редко пишутся (таблицы маршрутизации). |
| **Seqlock** | Последовательный замок. Читатель проверяет версию данных до и после чтения. | Используется для системного времени и счетчиков. |
| **Мьютексы ядра** | Аналогичны userspace мьютексам, переводят процесс в состояние сна (D/S). | Защита структур данных ядра в контексте процесса. |

### Барьеры памяти (Memory Barriers)

Современные процессоры и компиляторы могут изменять порядок выполнения инструкций (Out-of-Order Execution) для оптимизации производительности. 
**Барьеры памяти** — это инструкции, гарантирующие, что все операции записи/чтения, инициированные до барьера, будут завершены до выполнения операций после него. В многопоточном программировании без явных барьеров (или примитивов, их содержащих) один поток может увидеть данные в несогласованном состоянии.

## Практические сценарии

### Сценарий 1: Иерархическая блокировка (Борьба с Deadlock)

Чтобы избежать взаимной блокировки, необходимо установить строгий порядок захвата ресурсов (Lock Ordering).
- **Плохо:** Поток 1 берет A, затем B; Поток 2 берет B, затем A.
- **Хорошо:** Все потоки всегда берут ресурсы в алфавитном порядке (A, затем B).

### Сценарий 2: Инверсия приоритетов и наследование

Если низкоприоритетный поток (L) держит мьютекс, нужный высокоприоритетному (H), а среднеприоритетный (M) вытесняет L, поток H будет ждать бесконечно долго.
**Решение:** Протокол **Priority Inheritance**. Ядро временно повышает приоритет потока L до уровня H, чтобы он мог быстрее закончить работу и освободить мьютекс.

### Сценарий 3: Блокировка файлов (flock vs fcntl)

Синхронизация между независимыми процессами часто выполняется через файлы.
- **flock:** Блокировка на уровне всего файла. Проста в использовании, но грубая.
- **fcntl (POSIX record locking):** Позволяет блокировать отдельные диапазоны байтов внутри файла. Поддерживает типы блокировок (Read/Write).

```bash
# Использование flock в скриптах для предотвращения параллельного запуска
(
  flock -n 200 || exit 1
  # критическая секция
  echo "Выполнение задачи..."
  sleep 10
) 200>/var/lock/mylockfile
```

## Дополнительная информация

### Диагностика и отладка

1.  **Lockdep:** Встроенный в ядро валидатор, который анализирует зависимости блокировок и предупреждает о потенциальных Deadlocks еще до их возникновения.
2.  **perf lock:** Позволяет анализировать время удержания блокировок и конкуренцию (contention) в ядре.
3.  **bpftrace:** Позволяет писать скрипты для отслеживания задержек на мьютексах в реальном времени.

```bpftrace
# Отслеживание времени ожидания мьютексов pthreads (пример)
uprobe:/lib/x86_64-linux-gnu/libpthread.so.0:pthread_mutex_lock {
    @start[tid] = nsecs;
}
uprobe:/lib/x86_64-linux-gnu/libpthread.so.0:pthread_mutex_lock /@start[tid]/ {
    @latency = hist(nsecs - @start[tid]);
    delete(@start[tid]);
}
```
