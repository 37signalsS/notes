# Конкурентность и синхронизация процессов

## Определения → Базовые концепции → Практические сценарии → Дополнительная информация

## Определения

**Конкурентность (Concurrency)** — способность системы выполнять несколько задач одновременно (или имитировать одновременность через переключение контекста).

**Состояние гонки (Race Condition)** — ошибка проектирования многопоточной или многопроцессной системы, при которой результат выполнения зависит от непредсказуемого порядка доступа к общим ресурсам.

**Критическая секция (Critical Section)** — участок кода, в котором происходит доступ к общему ресурсу и который должен выполняться атомарно относительно других потоков/процессов.

## Базовые концепции

### Механизмы синхронизации

| Механизм | Описание | Основное отличие |
| :--- | :--- | :--- |
| **Мьютекс (Mutex)** | Взаимное исключение (один ключ). Владеть может только один поток. | **Свойство владения:** только тот, кто захватил мьютекс, может его освободить. |
| **Семафор (Semaphore)** | Счётчик ресурсов. Позволяет N потокам войти в критическую секцию. | **Сигнальный механизм:** один поток может "просигналить" (освободить) семафор для другого. |
| **Спинлок (Spinlock)** | Циклическое ожидание в цикле (busy-wait) до освобождения ресурса. | Не переводит поток в режим ожидания (sleep), экономит время на переключении контекста. |
| **Барьеры (Barriers)** | Точка синхронизации, которую все потоки должны достичь, прежде чем кто-либо продолжит. | Групповая синхронизация. |

### Мьютекс vs Семафор (Классическое сравнение)
1. **Мьютекс** — это как кабинка туалета: один человек зашёл, закрылся, вышел.
2. **Семафор** — это как количество велосипедов в прокате: если их 5, то 5 человек могут взять по одному. Шестой будет ждать, пока кто-то вернёт велосипед.
3. **Двоичный семафор** (со значениями 0 и 1) похож на мьютекс, но у него нет понятия владельца. Один процесс может заблокировать его, а другой — разблокировать.

## Практические сценарии

### Сценарий 1: Проблема Deadlock (Взаимоблокировка)
Ситуация, когда два процесса ждут ресурсы, захваченные друг другом.
*Пример:*
- Процесс A захватил Ресурс 1 и ждёт Ресурс 2.
- Процесс B захватил Ресурс 2 и ждёт Ресурс 1.
**Решение:** Всегда захватывать ресурсы в строго определённом иерархическом порядке.

### Сценарий 2: Инверсия приоритетов
Когда низкоприоритетный процесс удерживает мьютекс, который нужен высокоприоритетному процессу, блокируя его выполнение.
**Решение:** Протоколы наследования приоритетов (Priority Inheritance), когда процесс с мьютексом временно получает приоритет самого высокого из ожидающих его процессов.

## Дополнительная информация

### Проверка блокировок в Linux
Для отладки проблем с блокировками в userspace можно использовать `gdb` или `pstack`:
```bash
# Посмотреть стеки всех потоков процесса
pstack <PID>
# Или через gdb
gdb -p <PID> -ex "thread apply all bt" -ex "detach" -ex "quit"
```
