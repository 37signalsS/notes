# Конкурентность и синхронизация процессов

## Определения

**Конкурентность (Concurrency)** — способность операционной системы или приложения обрабатывать несколько задач одновременно. В однопроцессорных системах это достигается через быстрое переключение контекста (context switching), создающее иллюзию параллелизма.

**Состояние гонки (Race Condition)** — аномалия в многопоточных или многопроцессных системах, при которой результат выполнения программы зависит от непредсказуемого порядка чередования операций доступа к общим данным.

**Критическая секция (Critical Section)** — участок программного кода, в котором происходит доступ к разделяемому ресурсу (памяти, файлу, устройству). Этот участок должен выполняться атомарно относительно других потоков или процессов.

**Взаимоблокировка (Deadlock)** — ситуация, при которой несколько процессов находятся в состоянии бесконечного ожидания ресурсов, захваченных друг другом, что приводит к полной остановке их выполнения.

## Основные концепции

### Механизмы синхронизации

Для безопасного доступа к критическим секциям в Linux используются различные примитивы синхронизации:

| Механизм | Описание | Особенности |
| :--- | :--- | :--- |
| **Мьютекс (Mutex)** | Взаимное исключение (Mutual Exclusion). Примитив с состоянием "занят/свободен". | **Владение:** только поток, захвативший мьютекс, имеет право его освободить. |
| **Семафор (Semaphore)** | Счётчик, позволяющий N потокам одновременно обращаться к ресурсу. | **Сигнальный механизм:** один процесс может "просигналить" (освободить) семафор для другого. |
| **Спинлок (Spinlock)** | Ожидание в активном цикле (busy-wait) до момента освобождения ресурса. | Не переводит поток в сон, экономит время на переключении контекста, но потребляет CPU. |
| **Барьеры (Barriers)** | Точка синхронизации, в которой все участники группы должны дождаться друг друга. | Используется для групповой координации этапов вычислений. |

### Сравнение: Мьютекс vs Семафор

1. **Мьютекс** можно представить как единственную кабинку в помещении: один человек зашёл, закрыл дверь на замок, выполнил действия и вышел, открыв дверь.
2. **Семафор** — это пул ресурсов (например, прокатные велосипеды). Если доступно 3 велосипеда, 3 человека могут их взять. Четвёртый будет ждать возврата любого из них.
3. **Двоичный семафор** (со значениями 0 и 1) функционально похож на мьютекс, но у него отсутствует строгое понятие владельца — разблокировать его может любой процесс.

## Практические сценарии

### Сценарий 1: Предотвращение Deadlock

Классическая ситуация взаимоблокировки возникает при перекрестном захвате ресурсов:

- Процесс A захватил ресурс №1 и запрашивает ресурс №2.
- Процесс B захватил ресурс №2 и запрашивает ресурс №1.

**Решение:** Установление строгого иерархического порядка захвата ресурсов. Все процессы должны запрашивать ресурсы в одинаковой последовательности (например, всегда сначала №1, затем №2).

### Сценарий 2: Инверсия приоритетов

Проблема возникает, когда низкоприоритетный процесс удерживает мьютекс, необходимый высокоприоритетному процессу, в то время как процесс со средним приоритетом вытесняет низкоприоритетный, не давая ему освободить ресурс.

**Решение:** Использование протокола **наследования приоритетов (Priority Inheritance)**. В этом случае процесс, удерживающий ресурс, временно получает приоритет самого высокого из ожидающих этот ресурс процессов.

## Дополнительная информация

### Диагностика блокировок в Linux

Для анализа зависших процессов и поиска причин блокировок в пространстве пользователя (userspace) используются инструменты отладки:

```bash
# Просмотр стеков вызовов всех потоков процесса через pstack
pstack <PID>

# Использование gdb для анализа потоков
gdb -p <PID> -ex "thread apply all bt" -ex "detach" -ex "quit"
```

Для анализа блокировок на уровне ядра (kernelspace) применяется механизм **lockdep** (валидатор блокировок), который должен быть включен при сборке ядра.
