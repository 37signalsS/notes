# Использование ulimit в Linux

## Определения

**ulimit** — встроенная команда оболочки (shell builtin) для просмотра и временной настройки лимитов ресурсов текущей сессии и её дочерних процессов.

**Мягкий лимит (Soft limit)** — текущее действующее ограничение. Пользователь может увеличивать его до значения жесткого лимита самостоятельно.

**Жесткий лимит (Hard limit)** — верхняя граница для мягкого лимита. Повысить жесткий лимит может только суперпользователь (`root`).

Теория и типы лимитов описаны в [**Концепциях лимитов ресурсов**](./resource_limits_concepts.md).

## Основные концепции

### Особенности работы ulimit

- **Область действия:** Только текущий экземпляр shell и запущенные из него процессы.
- **Наследование:** Дочерние процессы получают те же лимиты, что и родительский shell.
- **Временный характер:** Настройки сбрасываются при закрытии терминала.
- **Приоритет:** Самый низкий приоритет в иерархии (не может превысить лимиты cgroups или systemd).

Для постоянных изменений используйте [**Постоянную настройку лимитов**](./persistent_limits_configuration.md).

## Практические сценарии

### Просмотр текущих лимитов

```bash
# Вывести все мягкие (soft) лимиты
ulimit -a

# Просмотр конкретного лимита: открытые файлы
ulimit -n

# Просмотр жестких (hard) лимитов
ulimit -Hn
```

### Установка лимитов в реальном времени

```bash
# Увеличение лимита открытых файлов до 4096 (не выше hard limit)
ulimit -n 4096

# Защита от Fork Bomb: ограничение числа процессов пользователя
ulimit -u 1024

# Ограничение размера виртуальной памяти (KB)
ulimit -v 2048000
```

### Диагностика проблем с лимитами

Если приложение сообщает об ошибке `Too many open files`:

1. **Проверить лимиты сессии:** `ulimit -n`.
2. **Узнать использование дескрипторов процессом:** `ls /proc/<PID>/fd/ | wc -l`.
3. **Сравнить с фактическими лимитами процесса:** `cat /proc/<PID>/limits | grep "Max open files"`.

## Дополнительная информация

### Использование в скриптах

```bash
#!/bin/bash
# Подготовка окружения перед запуском
ulimit -n 65536
exec ./my_app
```
