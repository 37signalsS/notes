# OOM Killer Mechanism

## Как OOM Killer выбирает "жертву"

Когда в Linux заканчивается оперативная память, система стоит перед критическим выбором: зависнуть полностью или пожертвовать одним из процессов, чтобы выжить. За это жёсткое, но необходимое решение отвечает механизм OOM Killer.

Он не убивает процессы случайно. Вместо этого для каждого вычисляется **"рейтинг плохости" (oom_score)**. Процесс с наивысшим рейтингом признаётся наименее важным и подлежит уничтожению. В расчёте участвуют почти все процессы, кроме `init` и потоков ядра (kernel threads).

Каждый процесс имеет три связанных файла в `/proc/<PID>/`:

| Файл | Диапазон | Описание | Кто изменяет |
| :--- | :--- | :--- | :--- |
| `oom_score` | 0–1000 | Текущее значение очков. Вычисляется ядром автоматически | Ядро (автоматически) |
| `oom_score_adj` | -1000–1000 | Корректирующий коэффициент для влияния на oom_score | Пользователь (вручную) |
| `oom_adj` | -17–15 | Устаревший аналог `oom_score_adj` | Устарел |

> **Важно:** Изменение `oom_score_adj` автоматически пересчитывает `oom_adj`.

**Формула расчёта итогового score:**

```
Итоговый score = oom_score (от ядра) + oom_score_adj (пользовательский)
```

**Факторы, повышающие `oom_score` (увеличивают шанс быть убитым):**

* Большое потребление оперативной памяти (RAM)
* Наличие большого количества дочерних процессов, которые также потребляют память
* Высокое значение `nice` (низкий приоритет процесса)
* Короткое время жизни процесса

**Факторы, понижающие `oom_score` (уменьшают шанс быть убитым):**

* Процесс запущен от имени `root`
* Процесс имеет прямой доступ к оборудованию
* Длительное время работы (недавно запущенные процессы имеют некоторую защиту)
* Низкое значение `oom_score_adj`
* Процесс является частью cgroup с собственными лимитами памяти
