# OOM Killer Mechanism

## Определения

**OOM Killer (Out-of-Memory Killer)** — механизм ядра Linux, принудительно завершающий процессы при критической нехватке оперативной памяти. Предотвращает полный отказ системы, жертвуя наименее важными процессами.

**oom_score** — рейтинг "кандидата на удаление", вычисляемый ядром для каждого процесса. Процесс с наивысшим рейтингом убивается первым.

**oom_score_adj** — корректирующий коэффициент (-1000…1000), позволяющий пользователю влиять на рейтинг процесса.

## Основные концепции

### Принцип работы

Когда свободная память RAM достигает критического уровня, ядро запускает OOM Killer. Он не выбирает процесс случайно — вместо этого для каждого процесса вычисляется **oom_score**, и процесс с наивысшим рейтингом уничтожается сигналом SIGKILL (код выхода 137).

В расчёте участвуют почти все процессы, кроме `init` (PID 1) и потоков ядра (kernel threads).

### Файлы `/proc/<PID>/` для управления OOM

| Файл | Диапазон | Описание | Кто изменяет |
| :--- | :--- | :--- | :--- |
| `oom_score` | 0–1000 | Текущий рейтинг процесса | Ядро (автоматически) |
| `oom_score_adj` | -1000–1000 | Корректирующий коэффициент для влияния на oom_score | Пользователь (вручную) |
| `oom_adj` | -17–15 | Устаревший аналог `oom_score_adj` | Устарел (не рекомендуется) |

> **Важно:** Изменение `oom_score_adj` автоматически пересчитывает `oom_adj`.

### Формула расчёта

```
Итоговый score = oom_score (от ядра) + oom_score_adj (пользовательский)
```

### Факторы, влияющие на `oom_score`

**Повышают рейтинг (увеличивают шанс быть убитым):**

- Большое потребление оперативной памяти (RAM)
- Наличие большого количества дочерних процессов, потребляющих память
- Высокое значение `nice` (низкий приоритет процесса)
- Короткое время жизни процесса

**Понижают рейтинг (уменьшают шанс быть убитым):**

- Процесс запущен от имени `root`
- Процесс имеет прямой доступ к оборудованию
- Длительное время работы
- Низкое значение `oom_score_adj`
- Процесс является частью cgroup с собственными лимитами памяти

## Практические сценарии

### Просмотр рейтинга процесса

```bash
# Проверить oom_score конкретного процесса
cat /proc/<PID>/oom_score

# Проверить корректировку рейтинга
cat /proc/<PID>/oom_score_adj

# Посмотреть оба значения вместе
echo "Score: $(cat /proc/<PID>/oom_score), Adj: $(cat /proc/<PID>/oom_score_adj)"
```

### Быстрая оценка всех процессов

```bash
# Топ-10 процессов по oom_score
for p in /proc/[0-9]*; do
    pid=${p##*/}
    [ -r $p/oom_score ] && printf "%4s %8s %s\n" \
        "$(cat $p/oom_score 2>/dev/null)" \
        "$pid" \
        "$(cat $p/comm 2>/dev/null)"
done 2>/dev/null | sort -nr | head -10
```

### Проверка защиты критичного процесса

```bash
# Установить максимальную защиту для процесса
echo -1000 | sudo tee /proc/<PID>/oom_score_adj

# Проверить результат
cat /proc/<PID>/oom_score_adj
```

## Дополнительная информация

### OOM Killer и cgroups

В контейнерах (Docker, Kubernetes) OOM Killer работает на двух уровнях:

- **Уровень хоста:** Ядро Linux может убить любой процесс контейнера как обычный процесс
- **Уровень cgroup:** При достижении `memory.max` (v2) или `memory.limit_in_bytes` (v1) OOM Killer убивает процессы внутри cgroup

Подробнее: [OOM Killer in Containers](./oom_killer_containers.md).

### OOM Killer и signal

OOM Killer завершает процесс сигналом **SIGKILL (9)**, который невозможно перехватить. Процесс не может выполнить очистку ресурсов — это отличает OOM Killer от планового завершения.

### Историческая справка

- Механизм OOM Killer появился в ядре Linux 2.4 (1999)
- В ядре 3.7 (2012) добавлен `oom_score_adj`, заменивший устаревший `oom_adj`
- В cgroups v2 (ядро 4.5+, 2016) добавлена поддержка `memory.oom.group` для группового завершения процессов
