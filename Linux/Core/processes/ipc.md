# Межпроцессное взаимодействие (IPC) в Linux

## Определения

**Межпроцессное взаимодействие (IPC — Inter-Process Communication)** — это набор механизмов и протоколов, которые позволяют независимым процессам обмениваться данными, уведомлениями и синхронизировать свою совместную работу.

## Основные концепции

### Механизмы IPC

#### Каналы (Pipes)

Классический механизм потоковой передачи данных.

- **Неименованные каналы (Anonymous Pipes):**
  - Полудуплексный режим (передача данных в одном направлении).
  - Используются для связи между родительским и дочерним процессами через системный вызов `pipe()`.
  - В командной оболочке создаются с помощью оператора конвейера `|`.
  
  ```bash
  # Пример конвейера в shell
  ls -la | grep ".txt" | wc -l
  ```

- **Именованные каналы (FIFO — First In, First Out):**
  - Обеспечивают связь между любыми процессами, даже не связанными родством.
  - Представлены как специальные файлы в файловой системе.
  - Поддерживают двустороннюю связь при использовании пары каналов.
  
  ```bash
  # Создание FIFO
  mkfifo /tmp/my_fifo
  
  # Запись данных
  echo "Hello" > /tmp/my_fifo
  
  # Чтение данных
  cat < /tmp/my_fifo
  ```

#### Очереди сообщений (Message Queues)

Асинхронный обмен дискретными сообщениями.

- Ядро управляет очередями, позволяя процессам отправлять сообщения с разными приоритетами.
- Сообщение удаляется из очереди сразу после прочтения.
- Поддерживает работу нескольких отправителей и получателей одновременно.

```c
// Пример использования на языке C
int msgid = msgget(key, IPC_CREAT | 0666);
msgsnd(msgid, &msg, size, 0);  // Отправить
msgrcv(msgid, &msg, size, type, 0);  // Получить
```

#### Разделяемая память (Shared Memory)

Наиболее производительный метод обмена данными.

- Ядро выделяет область физической памяти, которая проецируется в адресное пространство нескольких процессов.
- Данные передаются без лишнего копирования между адресными пространствами.
- **Внимание:** Требует использования внешних механизмов синхронизации (семафоров или мьютексов) для предотвращения состояния гонки (race conditions).

#### Семафоры (Semaphores)

Механизм синхронизации доступа к общим ресурсам.

- Семафор — это целочисленный счетчик, контролирующий доступ к ресурсу.
- Блокирует процесс, если ресурс занят, и пробуждает его при освобождении.
- Часто применяется для защиты критических секций в разделяемой памяти.

#### Сокеты (Sockets)

Универсальный механизм для локальной и сетевой коммуникации.

- **Unix Domain Sockets:** Оптимизированы для локального взаимодействия. Для адресации используют путь в файловой системе (например, `/var/run/docker.sock`). Подробнее см. [**Интерфейс сокетов (Socket API)**](../../../Networking/Concepts/socket_api.md).
- **Network Sockets:** Используются для связи по сети (TCP/IP).

#### Файлы (Files)

Обмен данными через запись и чтение общих файлов.

- Простой способ, но обладает низкой скоростью из-за дискового ввода-вывода (I/O).
- Требует блокировок (`flock`, `fcntl`) для обеспечения целостности.

#### Сигналы (Signals)

Программные прерывания для асинхронных уведомлений.

- Используются для передачи простых событий (остановка, прерывание, ошибка).
- Не предназначены для передачи структурированных данных.
- Подробное описание всех типов сигналов см. в заметке [**Сигналы процессов**](./signals.md).

### Сравнение механизмов IPC

| Механизм | Скорость | Сложность | Дуплекс | Синхронизация |
| :--- | :--- | :--- | :--- | :--- |
| **Каналы** | Средняя | Низкая | Полудуплекс | Автоматическая |
| **FIFO** | Средняя | Низкая | Полудуплекс | Автоматическая |
| **Очереди сообщений** | Средняя | Средняя | Полный | Автоматическая |
| **Разделяемая память** | **Высокая** | Высокая | Полный | Требуется внешняя |
| **Сокеты** | Средняя/Высокая | Средняя | Полный | Автоматическая |
| **Файлы** | Низкая | Низкая | Полный | Требуется внешняя |
| **Сигналы** | Высокая | Низкая | Однонаправленные | Нет |

## Практические сценарии

### Использование Unix Domain Sockets (Docker API)

Классический пример локального взаимодействия через сокет `/var/run/docker.sock`.

```bash
# Прямой вызов Docker API через Unix-сокет
curl --unix-socket /var/run/docker.sock http://localhost/containers/json

# Проверка типа файла сокета
ls -l /var/run/docker.sock
# → s-rw-rw---- 1 root docker 0 ... /var/run/docker.sock (префикс 's' означает socket)
```

### Конвейеры в командной строке (Anonymous Pipes)

```bash
# Передача вывода одной команды на вход другой
dmesg | grep -i error | tail -n 5
```

Здесь ядро создает два неименованных канала для связки трех процессов.

### Передача данных через именованный канал (FIFO)

```bash
# Создание канала
mkfifo /tmp/log_pipe

# Процесс-читатель (в одном терминале)
cat < /tmp/log_pipe

# Процесс-писатель (в другом терминале)
echo "$(date): System update started" > /tmp/log_pipe
```

### Управление разделяемой памятью (System V)

```bash
# Создать сегмент разделяемой памяти размером 1 КБ
ipcmk -M 1024

# Просмотреть список активных IPC-объектов
ipcs -m

# Удалить сегмент
ipcrm -m <shmid>
```

## Дополнительная информация

### Шина сообщений D-Bus

**D-Bus** — высокоуровневая система IPC, ставшая стандартом для современных Linux-дистрибутивов. Она абстрагирует низкоуровневые механизмы и предоставляет шину сообщений для RPC (Remote Procedure Call — удаленный вызов процедур) и уведомлений.

**Основные компоненты:**

- **System Bus (Системная шина):** Используется системными службами (systemd, NetworkManager) для глобальных событий.
- **Session Bus (Сессионная шина):** Создается для каждого пользовательского сеанса для общения графических приложений.

**Инструменты:**

- `busctl` — современная утилита для интроспекции D-Bus.
- `gdbus` — инструмент для работы с объектами D-Bus из скриптов.

### Сравнение POSIX (Portable Operating System Interface) IPC и System V IPC

В Linux сосуществуют две реализации механизмов IPC:

| Характеристика | System V IPC (Legacy) | POSIX IPC (Modern) |
| :--- | :--- | :--- |
| **Интерфейс** | `msgget()`, `shmget()`, `semget()` | `mq_open()`, `shm_open()`, `sem_open()` |
| **Идентификация** | Числовые ключи (IPC keys) | Именованные пути в ФС |
| **Видимость** | Команда `ipcs` | Файлы в `/dev/shm` и `/dev/mqueue` |
| **Рекомендация** | Использовать для старого ПО | Предпочтительно для новых разработок |

### Изоляция IPC через Namespaces

Механизмы IPC могут быть изолированы с помощью **IPC Namespaces**, что является критически важным для контейнеризации. Процессы в разных IPC-пространствах имен не могут видеть или использовать очереди сообщений, семафоры и разделяемую память друг друга.

Подробнее об изоляции ресурсов см. [**Namespaces (Пространства имён)**](../namespaces.md).

### Выбор механизма взаимодействия

1. **Родственные процессы:** Неименованные каналы (pipes).
2. **Локальные сервисы:** Unix Domain Sockets (высокая скорость и безопасность через права ФС).
3. **Максимальная производительность:** Разделяемая память (shared memory) + семафоры (semaphores).
4. **Сетевое взаимодействие:** Сетевые сокеты (TCP/UDP).
5. **Системные уведомления:** D-Bus.
6. **Критические асинхронные прерывания:** Сигналы (signals).
