# Межпроцессное взаимодействие (IPC) в Linux

## Определения

**Межпроцессное взаимодействие (IPC)** — это набор механизмов, которые позволяют процессам обмениваться данными и синхронизировать свою работу.

## Основные концепции

### Механизмы IPC

#### Каналы (Pipes)

Связь между процессами через буфер в памяти.

- **Неименованные каналы (Anonymous Pipes):**
  - Механизм является полудуплексным (данные передаются в одном направлении).
  - Используются для связи между родительским и дочерним процессами (`pipe()`).
  - Создаются в shell с помощью оператора `|`.
  
  ```bash
  # Пример в shell
  ls -la | grep ".txt" | wc -l
  ```

- **Именованные каналы (FIFO — First In, First Out):**
  - Связь между двумя не связанными процессами.
  - Являются полным дуплексом (двусторонняя связь при использовании двух каналов).
  - Специальные файлы в файловой системе (`mkfifo`).
  
  ```bash
  # Создать FIFO
  mkfifo /tmp/my_fifo
  
  # Записать данные
  echo "Hello" > /tmp/my_fifo
  
  # Прочитать данные
  cat < /tmp/my_fifo
  ```

#### Очереди сообщений (Message Queues)

Асинхронный обмен сообщениями между процессами.

- Ядро управляет очередями, сообщения могут иметь приоритеты.
- Как только сообщение прочитано, оно удаляется из очереди.
- Поддерживает множественных отправителей и получателей.

```c
// Пример использования в C
int msgid = msgget(key, IPC_CREAT | 0666);
msgsnd(msgid, &msg, size, 0);  // Отправить
msgrcv(msgid, &msg, size, type, 0);  // Получить
```

#### Разделяемая память (Shared Memory)

Самый быстрый способ IPC.

- Ядро выделяет область памяти, доступную нескольким процессам.
- Процессы читают и записывают данные напрямую, без копирования.
- Требует внешних механизмов синхронизации (семафоры, мьютексы) для предотвращения состояний гонки.

```c
// Пример использования в C
int shm_id = shmget(key, size, IPC_CREAT | 0666);
char *shm = shmat(shm_id, NULL, 0);  // Прикрепить
strcpy(shm, "Hello");  // Записать
shmdt(shm);  // Отсоединить
```

#### Семафоры (Semaphores)

Механизм для синхронизации доступа к общим ресурсам.

- Семафор представляет собой счетчик, который контролирует доступ к ресурсу.
- Блокирует ресурс при использовании одним процессом и освобождает по завершении.
- Часто используется вместе с разделяемой памятью.

```c
// Пример операций с семафором
struct sembuf op = {0, -1, 0};  // P-операция (захват)
semop(sem_id, &op, 1);

// ... критическая секция ...

op.sem_op = 1;  // V-операция (освобождение)
semop(sem_id, &op, 1);
```

#### Сокеты (Sockets)

Гибкий механизм для двунаправленной связи как на одной машине, так и по сети.

- **Unix Domain Sockets:**
  - Работают в пределах одной системы.
  - Используют файловую систему для адресации (например, `/var/run/docker.sock`).
  - Более эффективны, чем сетевые сокеты (не задействуют сетевой стек).
  - Подробное описание см. в заметке [**Интерфейс сокетов (Socket API)**](../../Networking/Concepts/socket_api.md).

- **Network Sockets:**
  - Используются для связи между процессами по сети (TCP/IP).
  - Поддерживают IPv4 и IPv6.

#### Файлы (Files)

Процессы могут обмениваться данными через общие файлы.

- Простой, но медленный способ IPC.
- Требует механизмов блокировки (`flock`, `fcntl`) для обеспечения целостности данных.

```bash
# Блокировка файла
flock /var/lock/mylock.lock -c "echo 'data' >> /tmp/shared.txt"
```

#### Сигналы (Signals)

Простейшая форма IPC для асинхронного уведомления.

- Используются для передачи уведомлений о событиях.
- Не предназначены для передачи больших объёмов данных.
- Подробнее см. в заметке [о сигналах](./signals.md).

### Сравнение механизмов IPC

| Механизм | Скорость | Сложность | Дуплекс | Синхронизация |
| :--- | :--- | :--- | :--- | :--- |
| **Каналы** | Средняя | Низкая | Полудуплекс | Автоматическая |
| **FIFO** | Средняя | Низкая | Полудуплекс | Автоматическая |
| **Очереди сообщений** | Средняя | Средняя | Полный | Автоматическая |
| **Разделяемая память** | **Высокая** | Высокая | Полный | Требуется внешняя |
| **Сокеты** | Средняя/Высокая | Средняя | Полный | Автоматическая |
| **Файлы** | Низкая | Низкая | Полный | Требуется внешняя |
| **Сигналы** | Высокая | Низкая | Однонаправленные | Нет |

## Практические сценарии

### Пример: Docker Socket (`/var/run/docker.sock`)

Классический пример использования Unix-сокета для локального IPC.

- **Docker Daemon (`dockerd`)** создает Unix-сокет `/var/run/docker.sock` и ожидает на нем API-запросы.
- **Docker CLI (клиент `docker`)** подключается к этому файлу (сокету) и отправляет команды демону.
- Демон обрабатывает запрос и возвращает ответ через тот же сокет.

```bash
# Прямой вызов Docker API через сокет
curl --unix-socket /var/run/docker.sock http://localhost/containers/json

# Проверка типа файла
file /var/run/docker.sock
# Вывод: /var/run/docker.sock: socket
```

Этот механизм подробно описан в разделе о [Unix-сокетах](../../Networking/Concepts/socket_api.md#unix-сокеты-af_unix).

### Пример: Pipe в shell

```bash
# Конвейер процессов
dmesg | grep -i error | mail -s "Errors" admin@example.com

# Здесь создаются два неименованных канала:
# 1. dmesg → grep
# 2. grep → mail
```

### Пример: Создание FIFO для связи процессов

```bash
# Терминал 1: Создать FIFO и читать из него
mkfifo /tmp/mypipe
cat < /tmp/mypipe

# Терминал 2: Записать в FIFO
echo "Hello from process 2" > /tmp/mypipe
```

### Пример: Разделяемая память с синхронизацией

```bash
# Создать разделяемую память (через ipcs)
ipcmk -M -s 1024  # Создать 1KB памяти

# Просмотреть
ipcs -m

# Удалить
ipcrm -m <shmid>
```

## Дополнительная информация

### D-Bus

**D-Bus** — это современная и наиболее мощная система межпроцессного взаимодействия (IPC) в Linux. Она предоставляет высокоуровневую шину сообщений, которая позволяет приложениям и системным службам общаться друг с другом, абстрагируясь от низкоуровневых деталей.

**Основные принципы и компоненты:**

- **Назначение:** D-Bus предоставляет стандартизированный способ для приложений запрашивать сервисы у других приложений (RPC), а также для отправки и получения широковещательных уведомлений (сигналов). Он является ключевым компонентом современных рабочих столов (GNOME, KDE) и системных служб.

- **Центральный демон (`dbus-daemon`):** Выступает в роли маршрутизатора сообщений. Приложения не связываются напрямую, а отправляют сообщения демону, который пересылает их адресату.

- **Две основные шины:**
  - **System Bus (Системная шина):** Единая шина для всей системы. Используется для взаимодействия системных сервисов (например, `systemd`, `NetworkManager`). Требует повышенных привилегий для доступа.
  - **Session Bus (Сессионная шина):** Создается для каждого пользовательского сеанса. Используется для коммуникации между приложениями в рамках одной сессии (например, взаимодействие файлового менеджера и текстового редактора).

- **Адресация и объекты:**
  - **Имя сервиса:** Уникальное имя, регистрируемое на шине (например, `org.freedesktop.Notifications`).
  - **Путь к объекту:** Иерархический путь к объекту внутри сервиса (например, `/org/freedesktop/Notifications`).
  - **Интерфейс:** Группа методов и сигналов, предоставляемых объектом (например, `org.freedesktop.Notifications`).

- **Типы сообщений:**
  - **Вызов метода (Method Call):** Синхронный или асинхронный запрос на выполнение операции (RPC).
  - **Возврат метода (Method Return):** Ответ на вызов метода, содержащий результат или ошибку.
  - **Сигнал (Signal):** Асинхронное уведомление о событии для всех подписчиков.
  - **Ошибка (Error):** Сообщение об ошибке выполнения вызова.

**Инструменты для работы с D-Bus:**

- `busctl`: Современная утилита для интроспекции и мониторинга D-Bus.

    ```bash
    # Показать список всех сервисов на системной шине
    busctl list
    
    # Мониторить сообщения
    busctl monitor
    
    # Вызвать метод
    busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager.ListUnits
    ```

- `dbus-send`: Устаревшая команда для отправки сообщений в D-Bus.

- `gdbus`: Утилита из пакета glib для работы с D-Bus.

### POSIX IPC vs System V IPC

В Linux существуют два семейства IPC-механизмов:

| Характеристика | **System V IPC** | **POSIX IPC** |
| :--- | :--- | :--- |
| **Стандарт** | UNIX System V (1983) | POSIX.1b (1993) |
| **Интерфейс** | `msgget()`, `semget()`, `shmget()` | `mq_open()`, `sem_open()`, `shm_open()` |
| **Файловая система** | Нет (использует ipc ids) | Да (через `/dev/shm`, `/dev/mqueue`) |
| **Права доступа** | Через `ipc permissions` | Через стандартные права файлов |
| **Современность** | Устаревший | Рекомендуется к использованию |

**Утилиты для управления:**

```bash
# System V IPC
ipcs -a      # Показать все IPC объекты
ipcs -m      # Разделяемая память
ipcs -s      # Семафоры
ipcs -q      # Очереди сообщений
ipcrm -m <id>  # Удалить shared memory
```

### Выбор механизма IPC

**Рекомендации по выбору:**

1. **Родитель-потомок:** Используйте каналы (pipes)
2. **Независимые процессы на одной машине:** Unix-сокеты или FIFO
3. **Высокая производительность:** Разделяемая память + семафоры
4. **Сетевое взаимодействие:** Сокеты (TCP/UDP)
5. **Системные сервисы:** D-Bus
6. **Простые уведомления:** Сигналы
