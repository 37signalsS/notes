## Определения

**Межпроцессное взаимодействие (IPC)** — это набор механизмов, которые позволяют процессам обмениваться данными и синхронизировать свою работу.

## Основные концепции

### Механизмы IPC

-   **Каналы (Pipes):** Связь между двумя взаимосвязанными процессами.
    -   **Неименованные каналы:** Механизм является полудуплексным, что означает, что первый процесс связан со вторым процессом. Для достижения полного дуплекса, т. е. для взаимодействия второго процесса с первым процессом, требуется другой канал. Используются для связи между родительским и дочерним процессами (`pipe()`).
    -   **Именованные каналы (FIFO):** Связь между двумя не связанными процессами. FIFO — это полный дуплекс, что означает, что первый процесс может взаимодействовать со вторым процессом и наоборот одновременно. Специальные файлы в файловой системе, которые ведут себя как каналы (`mkfifo`).

-   **Очереди сообщений (Message Queues):** Связь между двумя или более процессами с полной дуплексной пропускной способностью. Процессы будут связываться друг с другом, отправляя сообщение и извлекая его из очереди. Полученное сообщение больше не доступно в очереди. Ядро управляет очередями, сообщения могут иметь приоритеты.

*   **Разделяемая память (Shared Memory):** Самый быстрый способ IPC. Связь между двумя или более процессами достигается за счет совместного использования памяти всеми процессами. Совместно используемая память должна быть защищена друг от друга путем синхронизации доступа ко всем процессам. Ядро выделяет область физической памяти, которую несколько процессов могут отобразить в свои адресные пространства. Это позволяет им читать и записывать данные напрямую, без копирования. Требует внешней синхронизации для предотвращения состояний гонки.

-   **Семафоры (Semaphores):** Семафоры предназначены для синхронизации доступа к нескольким процессам. Когда один процесс хочет получить доступ к памяти (для чтения или записи), он должен быть заблокирован (или защищен) и освобожден при удалении доступа. Это должно быть повторено всеми процессами для защиты данных. Используются для синхронизации доступа к общим ресурсам (например, к разделяемой памяти). Семафор — это, по сути, счетчик, который контролирует доступ к ресурсу.

-   **Сокеты (Sockets):** Гибкий механизм для двунаправленной связи.
    -   **Unix Domain Sockets:** Работают в пределах одной системы и используют файловую систему для адресации (например, `/var/run/docker.sock`). Более эффективны, чем сетевые сокеты.
    -   **Network Sockets:** Используются для связи между процессами по сети.

-   **Файлы (Files):** Процессы могут обмениваться данными, записывая и читая информацию из общих файлов. Требует механизмов блокировки (`flock`, `fcntl`).

-   **Сигналы (Signals):** Сигнал — это механизм связи между несколькими процессами посредством сигнализации. Это означает, что исходный процесс отправит сигнал (распознанный по номеру), а целевой процесс обработает его соответствующим образом. Простейшая форма IPC, используемая для уведомления процесса о событии. Не предназначены для передачи данных. Подробнее см. в заметке [о сигналах](./signals.md).

Примечание. Почти все программы в этом руководстве основаны на системных вызовах в операционной системе Linux (выполняется в Ubuntu).

## Практические сценарии

### Пример: Docker Socket (`/var/run/docker.sock`)

-   **Docker Daemon (`dockerd`)** создает Unix-сокет `/var/run/docker.sock` и "слушает" его.
-   **Docker CLI (клиент `docker`)** подключается к этому файлу и отправляет через него API-запросы демону.
-   Демон обрабатывает запрос и отправляет ответ обратно через тот же сокет.

## Расширенные детали

### D-Bus

**D-Bus** — это современная и наиболее мощная система межпроцессного взаимодействия (IPC) в Linux. Она предоставляет высокоуровневую шину сообщений, которая позволяет приложениям и системным службам общаться друг с другом.

**Ключевые особенности:**
-   **Две шины:**
    -   **System Bus:** Глобальная шина для общесистемных служб.
    -   **Session Bus:** Отдельная шина для приложений, запущенных в рамках сессии одного пользователя.
-   **Механизмы:** Поддерживает вызовы удалённых процедур (RPC), отправку сигналов и получение свойств объектов.

**Инструменты для работы с D-Bus:**
-   `busctl`: Современная утилита для интроспекции и мониторинга D-Bus.
    ```bash
    # Показать список всех сервисов на системной шине
    busctl list
    ```
-   `dbus-send`: Команда для отправки сообщений в D-Bus.
