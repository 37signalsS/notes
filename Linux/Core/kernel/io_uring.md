# io_uring — асинхронный ввод-вывод

## Определения

**`io_uring`** — это высокопроизводительный интерфейс ядра Linux для выполнения асинхронных операций ввода-вывода (I/O) и системных вызовов. Представленный в ядре 5.1, он радикально меняет способ взаимодействия приложений с ядром, минимизируя накладные расходы на переключение контекста и копирование данных.

В 2024–2025 годах `io_uring` эволюционировал из механизма для работы с файлами в универсальную среду асинхронного исполнения, поддерживающую практически все типы системных вызовов, включая сетевые операции, управление процессами и работу с устройствами напрямую.

## Основные концепции

### Архитектура кольцевых буферов

В основе `io_uring` лежат два кольцевых буфера (rings), разделяемых (shared memory) между приложением и ядром:

1.  **Submission Queue (SQ)**: Очередь запросов. Приложение помещает сюда записи (SQE — Submission Queue Entries), описывающие операции (чтение, запись, ожидание сокета и др.).
2.  **Completion Queue (CQ)**: Очередь завершений. Ядро помещает сюда результаты (CQE — Completion Queue Events) выполненных операций.

**Механизм работы:**
- Приложение заполняет SQ и выполняет системный вызов `io_uring_enter()` для уведомления ядра.
- **SQPOLL (Submission Queue Polling)**: Опциональный режим, при котором ядро запускает отдельный поток для опроса SQ. В этом режиме приложение может отправлять запросы вообще без выполнения системных вызовов, что обеспечивает максимальную производительность.

### Ключевые возможности (2024–2025)

*   **Zero-Copy Networking**: Поддержка операций `SEND_ZC` и `RECV_ZC`, позволяющих передавать данные между сетевой картой и памятью приложения без промежуточного копирования в буферы ядра.
*   **Multishot-режим**: Позволяет одной записи в SQ инициировать серию событий в CQ (например, `accept` нескольких соединений или постоянный мониторинг состояния дочерних процессов).
*   **Registered Buffers**: Предварительная регистрация буферов памяти в ядре ускоряет ввод-вывод, избавляя ядро от необходимости каждый раз сопоставлять виртуальные адреса с физическими страницами (page mapping).
*   **Direct Descriptors**: Использование индексов во внутренней таблице ядра вместо классических файловых дескрипторов (FD), что снижает нагрузку на таблицу файлов процесса.

### Преимущества перед устаревшими интерфейсами

| Особенность | `read/write` (Sync) | `epoll` | `libaio` | `io_uring` |
| :--- | :--- | :--- | :--- | :--- |
| **Асинхронность** | Нет | Для сети — да | Частично (Direct I/O) | Полная |
| **Системные вызовы** | На каждую операцию | На группу событий | На группу (io_submit) | Минимально (или 0 с SQPOLL) |
| **Копирование данных** | Да | Да | Да | **Zero-Copy** (с ядром 6.x) |
| **Универсальность** | Низкая | Только сокеты | Только файлы | **Максимальная** |

## Практические сценарии

### Высоконагруженное системное ПО

*   **Базы данных (ScyllaDB, PostgreSQL)**: Использование `io_uring` для асинхронного доступа к дискам NVMe позволяет достигать миллионов IOPS на одном ядре CPU.
*   **Сетевые серверы (Nginx, QEMU)**: QEMU перевел основной цикл событий на `io_uring`, что значительно снизило задержки эмуляции ввода-вывода.
*   **Пользовательские драйверы (ublk)**: Реализация блочных устройств в пространстве пользователя через `io_uring` с производительностью, сопоставимой с нативными драйверами ядра.

### Безопасность и контроль доступа

Из-за большой мощности интерфейса `io_uring` требует особого внимания к безопасности:

*   **Ограничение через sysctl**:
    ```bash
    # 0 - разрешено всем
    # 1 - разрешено только CAP_SYS_ADMIN или группе kernel.io_uring_group
    # 2 - полностью запрещено
    sudo sysctl -w kernel.io_uring_disabled=1
    ```
*   **Фильтрация опкодов**: Современные версии `liburing` позволяют прикреплять BPF-фильтры к кольцу, чтобы запретить выполнение определенных операций (например, запретить `IORING_OP_OPENAT` для песочниц).
*   **Seccomp**: В облачных средах (Docker/Kubernetes) использование `io_uring` часто заблокировано по умолчанию через профили seccomp для минимизации поверхности атаки на ядро.

## Дополнительная информация

### Основные инструменты

- **liburing**: Рекомендуемая библиотека C для работы с интерфейсом (инкапсулирует сложные манипуляции с барьерами памяти).
- **fio**: Стандартный инструмент для тестирования производительности дисков с поддержкой `ioengine=io_uring`.
