# io_uring — асинхронный ввод-вывод

## Определения

**`io_uring`** — современный интерфейс ядра Linux для выполнения высокопроизводительного асинхронного ввода-вывода (I/O), представленный в ядре 5.1. Основная цель технологии — минимизировать накладные расходы на системные вызовы при интенсивных операциях чтения и записи.

## Основные концепции

### Проблемы традиционных интерфейсов

До появления `io_uring` интерфейсы ядра для ввода-вывода в Linux имели существенные недостатки:

- **Синхронный ввод-вывод (`read`, `write`):** блокирует выполнение процесса до завершения операции.
- **`epoll`:** эффективен для сетевых сокетов, но не поддерживает асинхронные дисковые операции.
- **`libaio` (Linux AIO):** сложный в использовании API, имеющий ряд ограничений (например, работа только с файлами, открытыми с флагом `O_DIRECT`) и требующий системных вызовов для каждой операции.

### Принцип работы: кольцевые буферы

Ключевая инновация `io_uring` — использование двух **кольцевых буферов**, разделяемых между приложением и ядром. Это позволяет осуществлять пакетную обработку запросов без переключения контекста процессора.

1. **Очередь запросов (Submission Queue, SQ):** приложение помещает сюда структуры запросов (SQE — Submission Queue Entry).
2. **Очередь завершений (Completion Queue, CQ):** ядро асинхронно выполняет операции и помещает результаты (CQE — Completion Queue Event) сюда.

**Процесс взаимодействия:**

1. Приложение заполняет SQ несколькими операциями.
2. Приложение выполняет **один** системный вызов `io_uring_enter()`, чтобы уведомить ядро о новых задачах или дождаться завершения текущих.
3. Ядро обрабатывает пачку запросов из SQ.
4. Приложение считывает результаты из CQ без необходимости делать системный вызов для каждого отдельного результата.

### Преимущества технологии

- **Высокая производительность:** значительное сокращение количества дорогостоящих переключений контекста между пространством пользователя и ядром.
- **Пакетная обработка:** возможность отправки и получения результатов множества операций за один системный вызов.
- **Настоящая асинхронность:** одинаково эффективная работа как с сетевым, так и с дисковым вводом-выводом.
- **Универсальность:** поддержка широкого спектра системных вызовов (`read`/`write`, `openat`, `accept`, `connect` и др.).

## Практические сценарии

### Области применения

Технология `io_uring` активно внедряется в высоконагруженное ПО:

- **Базы данных:** PostgreSQL, ScyllaDB — ускорение дисковых операций.
- **Веб-серверы и прокси:** Nginx, Envoy — оптимизация сетевого взаимодействия.
- **Виртуализация:** QEMU — асинхронная обработка ввода-вывода для гостевых систем.
- **Библиотеки:** `libuv` (Node.js), `tokio` (Rust) — как эффективный бэкенд для асинхронного выполнения.

### Ограничения и безопасность

**Версия ядра:** требуется ядро **5.1+**. Функциональность расширялась постепенно:

| Версия | Ключевые возможности |
| :--- | :--- |
| **5.1** | Базовые операции `read`/`write`, кольцевые буферы SQ/CQ |
| **5.5** | Общие очереди задач (`IORING_SETUP_ATTACH_WQ`) для нескольких колец |
| **5.6** | Сетевые операции (`sendmsg`, `recvmsg`, `accept`, `connect`) |
| **5.19** | Прямой проброс команд (`io_uring_cmd`) для NVMe-устройств |

**Контейнеризация и безопасность:** `io_uring` предоставляет широкий доступ к системным ресурсам, что расширяет поверхность атаки.

- **Docker/Containerd:** использование `io_uring` может быть ограничено профилями `seccomp` по умолчанию.
- **Kubernetes:** может потребоваться настройка `securityContext.capabilities` или использование профиля `unconfined`.
- **sysctl:** параметр `kernel.io_uring_disabled` (начиная с ядра 6.1) позволяет глобально отключить интерфейс или ограничить его использование.
