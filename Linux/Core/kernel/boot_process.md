# Процесс загрузки Linux

## Определения

**Процесс загрузки Linux** — это последовательность шагов, выполняемых компьютером от момента включения питания до полной готовности операционной системы к работе. Он включает в себя инициализацию оборудования, загрузку ядра, монтирование файловой системы и запуск всех системных служб.

## Основные концепции

### Инициализация оборудования (BIOS/UEFI)

1. При включении питания запускается базовая система ввода-вывода (**BIOS**) или ее современный аналог (**UEFI**).
2. Выполняется самотестирование при включении (**POST**), которое проверяет исправность ключевых компонентов.
3. После успешного POST прошивка ищет загрузочное устройство (жесткий диск, SSD, USB) в соответствии с порядком загрузки.
4. Управление передается загрузчику, найденному на этом устройстве.

### Загрузчик ОС (Bootloader)

- **Определение:** Загрузчик операционной системы — это системное программное обеспечение, обеспечивающее загрузку ОС непосредственно после включения компьютера (процедуры POST) и начальной загрузки.
- **Основная задача:** Загрузить ядро операционной системы в память.
- **Компоненты:**
  - **MBR/GPT:** Схема разметки диска. В первом секторе находится код, который указывает на местоположение загрузчика.
  - **GRUB2 (GRand Unified Bootloader 2):** Наиболее распространенный загрузчик в Linux.
- **Процесс:**
    1. GRUB2 считывает свою конфигурацию и отображает меню для выбора операционной системы или версии ядра.
    2. Загружает в оперативную память выбранное **ядро Linux** и временную файловую систему **`initramfs`**.
    3. Передает управление ядру.

### Ядро (Kernel) и `initramfs`

Ядро — центральный компонент ОС. Подробнее о его функциях и параметрах можно прочитать в документе [обзор ядра](./overview.md).

#### Ранняя инициализация ядра (общая часть)

После передачи управления от загрузчика ядро начинает выполнение со своего entry point:

**1. Распаковка ядра и стартовая настройка памяти**
- Ядро (`vmlinuz`) распаковывается
- Настраиваются таблицы страниц, базовая виртуальная память

**2. Инициализация базовых подсистем ядра**
- Планировщик (scheduler), прерывания (IRQ), таймеры
- VFS (Virtual File System) — программный слой-абстракция для работы с файлами
- Создаётся rootfs — внутренняя файловая система ядра, служащая пустым временным корнем до подключения initramfs

**3. Монтирование временного корня (initramfs)**
- `initramfs` (обычно cpio-архив) распаковывается ядром в RAM как временная rootfs
- Запускается `/init` из initramfs
- **Важно:** `initramfs` не равен `rootfs`. `rootfs` — внутренняя конструкция ядра, `initramfs` — пользовательское наполнение, разворачиваемое поверх `rootfs`

#### Зачем нужен initramfs?

Реальный корневой раздел часто «не доступен сразу»:
- Драйверы контроллера диска/ФС могут быть модулями
- Необходима сборка RAID/LVM
- Шифрование (LUKS)
- Нестандартные контроллеры, root по сети

`initramfs` предоставляет временное окружение для:
- Загрузки необходимых драйверов и модулей
- Сборки md-RAID, активации LVM (`vgchange -ay`)
- Открытия LUKS-контейнеров
- Поиска и монтирования корневого раздела по `root=`

#### Переход на настоящий root (switch_root)

После подготовки корневого раздела:

1. **Поиск root:** По параметру `root=` (UUID/LABEL/путь) находится корень и монтируется
2. **Переключение корня:**
   - `switch_root` — userspace-утилита в initramfs, переключает корень и делает `exec /sbin/init`
   - `pivot_root` — syscall для смены корневой ФС процесса
3. **Запуск init:** Выполняется `/sbin/init` от нового корня

**Просмотр содержимого initramfs:**
```bash
lsinitramfs /boot/initrd.img-$(uname -r) | less
```

### Система инициализации (`init`/`systemd`)

#### PID 1 — первый userspace-процесс

**PID 1** — первый постоянный userspace-процесс после передачи управления из initramfs:
- Отвечает за запуск сервисов, монтирования, жизненный цикл демонов
- Обрабатывает завершения (orphan-процессы)
- Его падение критично для системы

**Проверка:**
```bash
ps -p 1 -o comm=
# Вывод: systemd
```

#### systemd: targets и unit'ы

**systemd** запускает units, приводя систему к целевому состоянию (target):

- **default.target** — симлинк на `multi-user.target` (консоль) или `graphical.target` (GUI)
- **multi-user.target** — «серверный» режим (TTY, сеть, демоны)
- **graphical.target** — графический режим (display manager)

**Проверка текущего target:**
```bash
systemctl get-default
```

**Последовательность инициализации:**
1. Запуск `/sbin/init` (systemd)
2. Поднятие базовой системы через units
3. udev создаёт узлы в `/dev`, триггерит загрузку модулей
4. Поднятие сети (NetworkManager/systemd-networkd)
5. Запуск логинов (getty) и GUI (display manager)

Подробнее о `systemd` можно прочитать в файле [обзора systemd](../systemd/overview.md).

## Практические сценарии

### Частые вопросы о загрузке Linux

**Что происходит сразу после включения сервера, до появления Linux?**
> Запускается прошивка BIOS или UEFI, которая инициализирует оборудование и выбирает устройство загрузки.

**Что такое BIOS и UEFI в контексте загрузки?**
> Прошивка, выполняющая раннюю инициализацию платформы и управляющая стартом загрузки. Главное отличие: BIOS передаёт управление коду из первых секторов диска (MBR), UEFI запускает EFI-приложение с ESP и использует записи загрузки в NVRAM.

**Где посмотреть параметры, с которыми загрузилось ядро?**
```bash
cat /proc/cmdline
```

**Почему при загрузке Linux используется initramfs?**
> После старта ядро может не иметь доступных драйверов/инструментов для поиска и монтирования настоящего корневого раздела. `initramfs` предоставляет временную ФС с необходимыми драйверами для активации хранилищ (RAID/LVM/LUKS) и монтирования root.

**Что такое PID 1?**
> Первый userspace-процесс (обычно systemd), управляющий сервисами и состоянием системы. Его завершение приводит к остановке/перезагрузке системы.

### Пересборка `initramfs`

Иногда, после изменения конфигурации хранилища (например, LVM) или установки драйверов, может потребоваться пересобрать `initramfs`, чтобы включить в него новые модули. Команды для этого различаются в зависимости от дистрибутива:

- **Debian/Ubuntu:**

    ```bash
    sudo update-initramfs -u
    ```

- **RHEL/CentOS/Fedora/AlmaLinux:**

    ```bash
    sudo dracut -f
    ```
