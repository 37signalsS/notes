# Процесс загрузки ядра Linux

## Определения

### Ядро (Kernel)

**Ядро** — это центральная часть операционной системы, которая управляет ресурсами компьютера и предоставляет основные сервисы для всех остальных частей системы. Оно отвечает за управление памятью, процессами, файловыми системами и устройствами.

### initramfs (Initial RAM File System)

**initramfs** — это временная корневая файловая система, которая загружается в память на раннем этапе загрузки. Её основная задача — предоставить ядру необходимые инструменты и драйверы для монтирования настоящей корневой файловой системы, особенно если она находится на LVM, RAID или зашифрованном разделе.

### Система инициализации (init)

**Система инициализации** — это первый пользовательский процесс (с PID 1), который запускается ядром. Он отвечает за запуск всех остальных системных служб и демонов, приводя систему в рабочее состояние. В современных дистрибутивах Linux эту роль выполняет **`systemd`**.

## Полная цепочка загрузки (от включения до login)

Для понимания всего процесса "от кнопки до приглашения командной строки" следует рассматривать загрузку как последовательность передачи эстафеты:

1. **POST (Power-On Self-Test):** При включении питания аппаратное обеспечение выполняет самодиагностику.
2. **Прошивка (BIOS/UEFI):** Инициализирует оборудование и находит загрузочное устройство. Подробности: [BIOS и UEFI](../firmware_bios_uefi.md).
3. **Загрузчик (Bootloader - GRUB, systemd-boot):** Прошивка передает управление загрузчику (например, GRUB2), который показывает меню выбора ОС, загружает ядро (`vmlinuz`) и `initramfs` в оперативную память.
4. **Инициализация ядра:** Ядро распаковывается, настраивает базовые подсистемы памяти, процессора и прерываний.
5. **Монтирование `initramfs`:** Ядро монтирует временную файловую систему в RAM. Из нее загружаются драйверы, необходимые для доступа к настоящему корневому диску (например, драйверы RAID, LVM, файловых систем).
6. **Монтирование корневой ФС (`switch_root`):** Найдя настоящий корневой раздел, ядро перемонтирует его как `/` и освобождает память, занятую `initramfs`.
7. **Система инициализации (PID 1 - systemd):** Ядро запускает первый пользовательский процесс `/sbin/init` (обычно это `systemd`).
8. **Запуск сервисов (Targets):** `systemd` последовательно запускает системные службы, монтирует оставшиеся диски по `/etc/fstab`, настраивает сеть (`network.target`).
9. **Приглашение входа (Login):** На последнем этапе (обычно `multi-user.target` или `graphical.target`) `systemd` запускает сервис `getty` на виртуальных терминалах (TTY), который вызывает программу `/bin/login`, и пользователь видит приглашение командной строки или графический менеджер дисплеев (GDM, LightDM).

## Этапы загрузки ядра

> **Граница ответственности:** Ниже более подробно описаны этапы загрузки **начиная с передачи управления ядру от загрузчика**. Этапы BIOS/UEFI, работа загрузчика GRUB и подготовка до загрузки ядра описаны в заметке [BIOS и UEFI: Прошивка и старт системы](../firmware_bios_uefi.md).

Процесс загрузки после передачи управления от загрузчика можно разделить на следующие ключевые этапы:

### 1. Передача управления от загрузчика (GRUB)

- **Загрузчик** (например, GRUB2) считывает свою конфигурацию, загружает в память ядро (`vmlinuz`) и `initramfs` из каталога `/boot`.
- Он передает ядру параметры командной строки (просмотреть их можно в `cat /proc/cmdline`).
- Наконец, он передает управление ядру, запуская его выполнение.

**Важно:** MBR (Master Boot Record) устарел и не поддерживает диски >2 ТБ. Современный стандарт — **GPT** (GUID Partition Table) с загрузкой через **UEFI**.

### 2. Ранняя инициализация ядра

- Ядро распаковывается в памяти.
- Настраиваются базовые подсистемы: управление памятью, таблицы страниц, планировщик, прерывания.
- Создается временная внутренняя файловая система `rootfs`.

### 3. Монтирование `initramfs` и запуск `/init`

- Архив `initramfs` распаковывается поверх `rootfs`.
- Запускается скрипт `/init` из `initramfs`, который выполняет следующие задачи:
  - Загружает необходимые модули ядра (для дисковых контроллеров, файловых систем, LVM, RAID).
  - Активирует тома LVM (`vgchange -ay`) или собирает массивы RAID (`mdadm --assemble`).
  - При необходимости запрашивает пароль для расшифровки LUKS-контейнеров.

### 4. Переключение на корневую ФС (`switch_root`)

- Скрипт в `initramfs` находит настоящую корневую файловую систему, используя параметр `root=` из командной строки ядра.
- Корневая ФС монтируется во временный каталог (например, `/new_root`).
- Выполняется команда `switch_root`, которая меняет корень файловой системы с `initramfs` на настоящую ФС и запускает новую систему инициализации.

### 5. Запуск PID 1: `systemd`

- Запускается процесс `/sbin/init` (который в современных системах является `systemd`). Это первый процесс с PID 1.
- `systemd` анализирует свою конфигурацию и начинает запускать сервисы в соответствии с целевым уровнем (`target`).
- **`multi-user.target`**: Стандартный серверный режим с поддержкой сети и консольного входа.
- **`graphical.target`**: Режим для рабочих станций, который дополнительно запускает графический интерфейс.
- `systemd` управляет жизненным циклом всех служб и обеспечивает готовность системы к работе.

## Практические сценарии

### Загрузка в однопользовательский режим (Single-user mode)

Используется для восстановления системы, сброса пароля root или исправления ошибок в файлах конфигурации (например, в `/etc/fstab`).

**Пошаговая инструкция (для GRUB):**

1. **Перезагрузите сервер.**
2. В меню выбора ядер GRUB нажмите клавишу **`e`** (edit) на нужном ядре.
3. Найдите строку, начинающуюся с **`linux`** (она содержит параметры ядра, такие как `root=`, `ro`, `quiet`).
4. Перейдите в конец этой строки и через пробел добавьте одно из:
    - **`single`** или **`1`** (традиционный режим).
    - **`init=/bin/bash`** (если нужно получить шелл мгновенно, минуя систему инициализации).
5. Нажмите **`Ctrl+X`** или **`F10`** для загрузки с этими параметрами.
6. Система загрузится в консоль с правами `root` без запроса пароля (в большинстве случаев).
7. **Важно:** Корневая файловая система часто монтируется в режиме "только чтение" (`ro`). Чтобы внести изменения, перемонтируйте её:

    ```bash
    mount -o remount,rw /
    ```

8. После завершения работ перезагрузите систему командой `reboot` или `exec /sbin/init`.

### Анализ и диагностика загрузки

- **Просмотреть параметры ядра текущей загрузки:**

  ```bash
  cat /proc/cmdline
  ```

- **Просмотреть логи ядра и системных служб для текущей загрузки:**

  ```bash
  journalctl -b 0
  ```

- **Проанализировать логи предыдущей загрузки (если был сбой):**

  ```bash
  journalctl -b -1
  ```

- **Проанализировать время загрузки сервисов:**

  ```bash
  systemd-analyze blame
  ```

### Управление `initramfs`

Если вы изменили конфигурацию хранилища (LVM, RAID) или добавили модули ядра, которые нужны для загрузки, необходимо пересобрать `initramfs`.

- **Debian/Ubuntu:**

  ```bash
  # Обновить initramfs для текущего ядра
  sudo update-initramfs -u
  ```

- **RHEL/CentOS/Fedora/AlmaLinux:**

  ```bash
  # Принудительно пересоздать initramfs для текущего ядра
  sudo dracut --force
  ```

- **Arch Linux:**

  ```bash
  # Пересобрать initramfs для всех ядер
  sudo mkinitcpio -P
  ```

- **Просмотреть содержимое `initramfs`:**

  ```bash
  lsinitramfs /boot/initrd.img-$(uname -r) | less    # Debian/Ubuntu
  lsinitrd /boot/initramfs-$(uname -r).img | less    # RHEL/CentOS
  lsinitcpio /boot/initramfs-$(uname -r).img | less  # Arch
  ```

- **Включение модулей в initramfs:**

  При изменении конфигурации хранилища (LVM, RAID) необходимо пересобрать initramfs с нужными модулями.

  Подробные инструкции для различных дистрибутивов: **[GRUB — Включение lvm2 в initramfs](../../SystemAdministration/grub.md#включение-lvm2-в-initramfs)**.
