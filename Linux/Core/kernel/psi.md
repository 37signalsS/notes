# Pressure Stall Information (PSI) — статистика давления на ресурсы

## Определения

**Pressure Stall Information (PSI)** — механизм ядра Linux (начиная с версии 4.20), предназначенный для точного мониторинга «давления» на аппаратные ресурсы (CPU, память, I/O, IRQ). В отличие от классических метрик загрузки (Load Average), PSI количественно оценивает время, которое процессы теряют в ожидании доступа к ресурсу, что позволяет выявлять деградацию производительности на ранних стадиях.

## Основные концепции

### Принцип работы

PSI измеряет **stall time** — время простоя, в течение которого задачи не могли выполняться или замедлялись из-за нехватки ресурса.

| Ресурс | Что означает давление |
| :--- | :--- |
| **CPU** | Задачи готовы к выполнению, но ожидают свободного ядра (runqueue). |
| **Memory** | Задачи ожидают выделения страниц, работают в режиме reclaim или thrashing. |
| **I/O** | Задачи заблокированы в ожидании завершения операций чтения/записи. |
| **IRQ** | Задачи простаивают из-за высокой активности обработки прерываний (с ядра 6.x). |

### Метрики Some и Full

Каждый файл в `/proc/pressure/` предоставляет два типа метрик:

1.  **`some`**: Процент времени, в течение которого **хотя бы одна** задача была заблокирована из-за нехватки ресурса. Указывает на наличие конкуренции за ресурс и потенциальное снижение пропускной способности.
2.  **`full`**: Процент времени, в течение которого **все** не-idle задачи были заблокированы (ресурс полностью исчерпан). Указывает на критическое насыщение, при котором система перестает выполнять полезную работу.
    - *Примечание:* Для CPU метрика `full` не используется (всегда 0), так как наличие готовой задачи всегда означает прогресс выполнения хотя бы на одном ядре.

### Формат вывода

```bash
cat /proc/pressure/memory
# → some avg10=2.46 avg60=1.82 avg300=1.21 total=748381
# → full avg10=0.91 avg60=0.65 avg300=0.45 total=280381
```

- **`avg10/60/300`**: Скользящее среднее значение давления в процентах за последние 10, 60 и 300 секунд соответственно.
- **`total`**: Суммарное время простоя в микросекундах с момента загрузки системы.

### PSI vs Load Average

| Характеристика | Load Average | PSI |
| :--- | :--- | :--- |
| **Точность** | Усредненная длина очереди задач. | Точное время ожидания в микросекундах. |
| **Детализация** | Смешивает CPU и I/O (в Linux). | Разделяет CPU, память и I/O. |
| **Реакция** | Медленная (экспоненциальное затухание). | Мгновенная (через механизм триггеров). |
| **Применимость** | Косвенный индикатор нагрузки. | Прямой индикатор потери производительности. |

### Требования и активация

- **Ядро:** 4.20+ (базовый PSI), 6.x+ (IRQ pressure).
- **Конфигурация:** `CONFIG_PSI=y`.
- **Параметр загрузки:** В некоторых дистрибутивах (например, Ubuntu, Debian) PSI может быть отключен по умолчанию. Для активации добавьте в параметры ядра:
  ```bash
  psi=1
  ```
- **Накладные расходы:** Минимальны (~1–3%), но на крайне нагруженных системах могут быть заметны.

## Практические сценарии

### Настройка уведомлений через триггеры

PSI позволяет приложениям получать уведомления в реальном времени при превышении порогов давления через интерфейс `poll()`/`epoll()`. Это эффективнее, чем постоянный опрос (polling) файлов.

**Пример записи триггера:**
```bash
# Формат: <some|full> <порог_мкс> <окно_мкс>
# Сработать, если задержка 'some' превысит 150мс за 1 секунду:
echo "some 150000 1000000" > /proc/pressure/memory
```

### Использование в systemd-oomd

Современные системы используют `systemd-oomd` для превентивного завершения процессов при высоком давлении на память, не дожидаясь жесткого OOM ядра.

Настройка в `/etc/systemd/oomd.conf`:
- **`DefaultMemoryPressureLimit=60%`**: Порог давления.
- **`DefaultMemoryPressureDurationSec=20s`**: Время удержания порога перед срабатыванием.

### PSI в cgroups v2

Для каждой контрольной группы (cgroup) доступны свои метрики давления, что позволяет изолировать проблемы «шумных соседей».

```bash
# Метрики для конкретного сервиса или контейнера
cat /sys/fs/cgroup/system.slice/nginx.service/memory.pressure
```

### Мониторинг и алертинг

- **Критический порог:** `full avg10 > 10%` для памяти или I/O обычно означает серьезные проблемы с отзывчивостью.
- **Автомасштабирование:** Kubernetes может использовать PSI через `node-problem-detector` для принятия решения о вытеснении (eviction) подов или добавлении узлов.
- **Анализ задержек:** Сравнение `some` и `full` позволяет понять, затрагивает ли проблема всю систему или только отдельные цепочки задач.
