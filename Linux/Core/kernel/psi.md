# Pressure Stall Information (PSI)

## Определения

**Pressure Stall Information (PSI)** — это механизм ядра Linux (появился в ядре 4.20), который позволяет отслеживать "давление" на ключевые системные ресурсы: **CPU**, **память** и **ввод-вывод (I/O)**. В отличие от традиционных метрик загрузки, PSI показывает, *сколько времени* процессы **потеряли из-за нехватки** этого ресурса.

## Основные концепции

### Как работает PSI

PSI измеряет **"stall time"** — время простоя, в течение которого один или несколько процессов не могли выполняться, потому что ждали доступа к ресурсу, который уже полностью утилизирован.

- **Давление на CPU (`cpu`):** Процессов, готовых к выполнению, больше, чем доступных ядер.
- **Давление на память (`memory`):** Процессы ждут, пока ядро освободит страницы памяти.
- **Давление на I/O (`io`):** Процессы ждут завершения операций ввода-вывода.

### Формат вывода PSI

Каждый файл в `/proc/pressure/` содержит две строки: `some` и `full`.

- `some`: Показывает процент времени, в течение которого **хотя бы одна** задача была заблокирована из-за нехватки данного ресурса. Указывает на потерю пропускной способности.
- `full`: Показывает процент времени, в течение которого **все** не-idle процессы были заблокированы из-за нехватки данного ресурса. Указывает на серьезное насыщение ресурса.

**Пример вывода для `memory`:**

```
some avg10=2.46 avg60=1.82 avg300=1.21 total=748381
full avg10=0.91 avg60=0.65 avg300=0.45 total=280381
```

- `avg10`, `avg60`, `avg300`: Средний процент времени простоя за последние 10, 60 и 300 секунд.
- `total`: Общее время простоя в микросекундах.

## Практические сценарии

### Использование PSI

Информация доступна через файлы в `/proc/pressure/`:

```bash
# Показать "давление" на CPU
cat /proc/pressure/cpu

# Показать "давление" на память
cat /proc/pressure/memory

# Показать "давление" на ввод-вывод
cat /proc/pressure/io
```

### Практическое применение

PSI является мощным инструментом для:

- **Автомасштабирования:** Системы оркестрации могут принимать решение о добавлении новых узлов на основе метрик давления.
- **Раннего обнаружения проблем:** Мониторинг PSI позволяет обнаружить деградацию производительности до того, как она станет заметна пользователям.
- **Диагностики "шумных соседей":** Выявление процессов, создающих чрезмерное давление на ресурсы.

## Дополнительная информация

### PSI в `cgroups v2`

> **Примечание:** Полное описание контрольных групп находится в заметке [Control Groups (cgroups)](../cgroups.md).

PSI-метрики доступны для каждой контрольной группы (cgroup), что позволяет `systemd` или другим менеджерам принимать решения о процессах внутри cgroup (например, убить процесс при высоком давлении на память).

Для просмотра PSI конкретной cgroup:

```bash
cat /sys/fs/cgroup/<путь_к_cgroup>/memory.pressure
cat /sys/fs/cgroup/<путь_к_cgroup>/cpu.pressure
cat /sys/fs/cgroup/<путь_к_cgroup>/io.pressure
```

### Сравнение с традиционными метриками

| Метрика | Что показывает | Недостаток |
| :--- | :--- | :--- |
| **CPU usage** | Процент использования CPU | Не показывает, ждут ли процессы ресурсы |
| **Memory usage** | Объем использованной памяти | Не показывает, ждут ли процессы выделения памяти |
| **PSI** | Время простоя из-за нехватки ресурса | Прямо указывает на потерю производительности |

### Требования и ограничения

- **Ядро:** Требуется ядро Linux 4.20 или новее
- **Конфигурация ядра:** Должна быть включена опция `CONFIG_PSI=y`
- **Оверхед:** Минимальные накладные расходы (~1-3% CPU)
