# Вытесняющая многозадачность ядра (Kernel Preemption)

## Определения

**Вытесняющая многозадачность ядра (Kernel Preemption)** — это механизм планировщика Linux, позволяющий принудительно прерывать выполнение текущего процесса, даже если он находится в режиме ядра (Kernel Mode), для передачи процессорного времени более высокоприоритетной задаче.

В отличие от кооперативной многозадачности, где процесс должен сам явно отдать управление (yield), вытеснение гарантирует предсказуемое время отклика системы, что критично для интерактивных приложений и систем реального времени.

## Основные концепции

### Эволюция и механизмы

Исторически ядро Linux было невытесняемым: процесс в режиме системного вызова блокировал CPU до завершения операции или перехода в режим ожидания. Современное ядро (начиная с ветки 6.x) представляет собой высокоадаптивную систему с несколькими уровнями вытесняемости.

### Модели вытеснения (2024–2026)

| Модель | Параметр CONFIG | Описание | Применение |
| :--- | :--- | :--- | :--- |
| **No Forced Preemption** | `PREEMPT_NONE` | Вытеснение только при выходе из ядра или добровольно. | Высоконагруженные серверы (Throughput). |
| **Voluntary Preemption** | `PREEMPT_VOLUNTARY` | Явные точки `cond_resched()` в коде ядра. | Универсальные серверы. |
| **Preemptible Kernel** | `PREEMPT` | Вытеснение в любой точке, кроме критических секций (Spinlocks). | Десктопы, Low-latency системы. |
| **Lazy Preemption** | `PREEMPT_LAZY` | Новинка (ядро 6.13+). Откладывает вытеснение обычных задач, но сохраняет мгновенное для RT. | Оптимальный баланс для современных CPU. |
| **Real-Time Kernel** | `PREEMPT_RT` | Полное вытеснение (Mainline с 6.12). Заменяет spinlocks на спящие mutex. | Робототехника, промышленная автоматизация. |

### PREEMPT_DYNAMIC

Современные дистрибутивы (Ubuntu 24.04+, Fedora) используют механизм **PREEMPT_DYNAMIC**. Он позволяет изменять модель вытеснения на лету через параметры загрузки ядра без пересборки. Это достигается за счет использования `static_calls`, которые активируют или деактивируют точки вытеснения в бинарном коде ядра.

### Планировщик EEVDF

С переходом на планировщик **EEVDF** (Earliest Eligible Virtual Deadline First) в последних ядрах, механизмы вытеснения стали тесно связаны с «правом на исполнение» (eligibility) и дедлайнами задач, что минимизирует несправедливое вытеснение и улучшает локальность кэша процессора.

## Практические сценарии

### Определение текущей модели

```bash
# Проверка через dmesg при загрузке
dmesg | grep -i preemption
# → [    0.000000] Dynamic Preempt: voluntary

# Проверка через параметры сборки
grep CONFIG_PREEMPT /boot/config-$(uname -r)
```

### Динамическое переключение (Runtime)

Если ядро собрано с поддержкой `CONFIG_PREEMPT_DYNAMIC`, модель можно изменить через параметр загрузки в GRUB:

```bash
# В файле /etc/default/grub добавить:
GRUB_CMDLINE_LINUX_DEFAULT="... preempt=full"

# Или проверить доступность интерфейса в debugfs (если смонтировано)
cat /sys/kernel/debug/sched/preempt
# → (none) voluntary full lazy
```

### Измерение задержек планирования

Для проверки эффективности вытеснения под нагрузкой используется пакет `rt-tests`.

```bash
# Запуск cyclictest для оценки jitter (задержки отклика)
sudo cyclictest -p 95 -m -c 0 -n -l 10000
# → Max: показывает максимальную задержку в микросекундах. 
# На ядре PREEMPT_RT это значение должно быть < 10-20 мкс даже под нагрузкой.
```
