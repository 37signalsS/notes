# Вытесняющая многозадачность ядра (Kernel Preemption)

## Определения

**Вытесняющая многозадачность ядра (Kernel Preemption)** — это механизм планировщика Linux, позволяющий принудительно прерывать выполнение процесса, даже если он находится в режиме ядра (Kernel Mode), для передачи ресурсов более приоритетной задаче.

В отличие от кооперативной многозадачности, где процесс должен сам отдать управление (`yield`), вытеснение гарантирует предсказуемое время отклика (latency), что критично для интерактивных систем и реального времени (RT).

**Ключевые термины:**
- **Preemption Point:** Точка в коде ядра, где планировщик может безопасно переключить контекст.
- **Preempt Count:** Счетчик внутри структуры процесса (`thread_info`), указывающий, находится ли процесс в критической секции (например, удерживает Spinlock), где вытеснение запрещено.
- **Context Switch:** Процесс сохранения состояния текущей задачи и восстановления состояния новой.

## Архитектура и модели (Состояние на 2026 год)

В современных ядрах (7.x) выбор модели вытеснения стал более гибким благодаря механизму **PREEMPT_DYNAMIC**, позволяющему менять поведение планировщика без перекомпиляции.

### Модели вытеснения

| Модель | Параметр | Описание | Применение |
| :--- | :--- | :--- | :--- |
| **No Preemption** | `none` | Вытеснение только при выходе из ядра или добровольно. | Серверы с упором на Raw Throughput. |
| **Voluntary** | `voluntary` | Использование явных точек `cond_resched()`. | Универсальные серверные нагрузки. |
| **Full** | `full` | Вытеснение в любой точке, кроме критических секций. | Десктопы, низкая задержка. |
| **Lazy** | `lazy` | **Стандарт 2026 (6.13+).** Откладывает вытеснение обычных задач, но сохраняет мгновенное для RT. | Оптимальный баланс (Default в большинстве дистрибутивов). |
| **Real-Time** | `rt` | Полное вытеснение (Mainline с 6.12). Превращает spinlocks в спящие mutex. | Системы жесткого реального времени. |

### Планировщик EEVDF (Earliest Eligible Virtual Deadline First)

Пришедший на смену CFS (Completely Fair Scheduler), EEVDF в ядрах 6.12+ радикально изменил логику вытеснения:
- **Lag (Отставание):** Планировщик вычисляет разницу между временем, которое задача *должна* была получить, и временем, полученным по факту.
- **Виртуальные дедлайны:** Каждой задаче назначается дедлайн. Вытеснение происходит, когда у другой задачи дедлайн наступает раньше, а текущая задача уже «вычерпала» свою порцию времени (Lag < 0).
- **Time Slice Request:** Приложения могут запрашивать кванты времени через `sched_setattr()`, влияя на частоту вытеснения без изменения приоритета `nice`.

### Механизм Proxy Execution

Для решения проблемы **инверсии приоритетов** в вытесняемых ядрах 2026 года активно внедряется Proxy Execution:
- Если высокоприоритетная задача блокируется на ресурсе, удерживаемом низкоприоритетной задачей, она «одалживает» свой контекст выполнения держателю ресурса.
- Это позволяет низкоприоритетной задаче быстрее завершить критическую секцию под приоритетом (дедлайном) заблокированной задачи, минимизируя задержки вытеснения.

## Практические сценарии

### Определение активной модели

```bash
# Проверка текущей модели через dmesg
dmesg | grep -i preemption
# → [    0.000000] Dynamic Preempt: lazy

# Просмотр доступных моделей (требуется CONFIG_PREEMPT_DYNAMIC)
cat /sys/kernel/debug/sched/preempt
# → none voluntary full (lazy)
# (В скобках указана активная модель)
```

### Динамическая настройка (Runtime)

Если модель не заблокирована на этапе сборки, ее можно изменить на лету (требуется смонтированный `debugfs`).

```bash
# Переключение в режим полной вытесняемости для минимизации задержек
echo full | sudo tee /sys/kernel/debug/sched/preempt
# → full

# Проверка через параметры загрузки GRUB
cat /proc/cmdline | grep preempt
# → ... preempt=lazy ...
```

### Диагностика задержек (Jitter)

Для оценки того, как механизмы вытеснения справляются с нагрузкой, используется пакет `rt-tests`.

```bash
# Запуск теста на задержку отклика (cyclictest)
# -p 95: приоритет, -m: закрепить в памяти, -n: использовать clock_nanosleep
sudo cyclictest -p 95 -m -n -l 10000 -c 0
# → T: 0 ( 1234) P:95 I:1000 C: 10000 Min:      2 Act:    4 Avg:    5 Max:   12
# (Значение Max на ядрах 7.x с PREEMPT_LAZY/RT обычно < 15-20 мкс)
```

### Мониторинг вытеснения через eBPF

Современные инструменты на базе eBPF позволяют видеть, какие функции чаще всего вызывают вытеснение.

```bash
# Использование bpftrace для подсчета вытеснений по стеку вызовов
sudo bpftrace -e 'kprobe:preempt_count_add { @[stack] = count(); }'
# → @[...]: 42 (список функций, временно запрещающих вытеснение)
```
