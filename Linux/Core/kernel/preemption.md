# Вытесняющая многозадачность ядра (Kernel Preemption)

## Определения

**Вытесняющая многозадачность ядра (Kernel Preemption)** — механизм, позволяющий ядру Linux принудительно прерывать выполнение текущей задачи (даже если она выполняется в режиме ядра) для передачи процессорного времени (CPU — Central Processing Unit) более высокоприоритетной задаче.

## Основные концепции

### Проблема и решение

В ранних версиях ядро Linux было **невытесняемым (non-preemptive)** — процесс, вошедший в режим ядра (например, через системный вызов), не мог быть прерван планировщиком до выхода из этого режима или добровольной отдачи управления. Это приводило к непредсказуемым задержкам (latency) для высокоприоритетных задач.

**Вытесняемое ядро** позволяет планировщику прервать выполнение кода ядра практически в любой безопасной точке.

| Аспект | Влияние |
| :--- | :--- |
| **Преимущество** | Значительное улучшение отзывчивости системы и предсказуемости времени отклика (real-time свойства). |
| **Недостаток** | Незначительное увеличение накладных расходов на переключения контекста и усложнение кода синхронизации. |

### Модели вытеснения

При компиляции ядра выбирается одна из моделей, определяющая баланс между пропускной способностью и отзывчивостью:

| Модель | Параметр CONFIG | Описание | Основной сценарий |
| :--- | :--- | :--- | :--- |
| **No Forced Preemption** | `PREEMPT_NONE` | Ядро не вытесняется принудительно. Задача выполняется до завершения или явной блокировки. | Серверы, пакетная обработка данных. |
| **Voluntary Preemption** | `PREEMPT_VOLUNTARY` | Ядро содержит точки `cond_resched()`, в которых проверяется наличие приоритетных задач. | Десктопные системы, универсальные серверы. |
| **Preemptible Kernel** | `PREEMPT` | Вытеснение возможно в любой точке, кроме критических секций (удерживающих блокировки). | Системы с низкими задержками (low-latency). |

## Практические сценарии

### Проверка текущей модели вытеснения

Информацию о модели можно получить из конфигурационного файла ядра или сообщений при загрузке.

```bash
# Проверка через конфигурацию загруженного ядра
grep CONFIG_PREEMPT /boot/config-$(uname -r)
# → CONFIG_PREEMPT_VOLUNTARY=y
# → # CONFIG_PREEMPT_NONE is not set
# → # CONFIG_PREEMPT is not set
```

Значение `=y` указывает на активную модель.

### Измерение задержек (Latency)

Для оценки влияния модели вытеснения на стабильность времени отклика используется утилита `cyclictest`.

```bash
# Установка инструментов (Debian/Ubuntu)
sudo apt install -y rt-tests

# Запуск теста задержек
sudo cyclictest -p 80 -m -n -l 10000
# → T: 0 (1234) P:80 I:1000 C:10000 Min:      3 Act:    5 Avg:    6 Max:      22
```

Значение **Max** показывает максимальную задержку в микросекундах. На полностью вытесняемом ядре (`PREEMPT`) этот показатель будет значительно ниже и стабильнее под нагрузкой.
