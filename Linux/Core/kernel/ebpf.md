# eBPF (extended Berkeley Packet Filter) — виртуальная машина ядра

## Определения

**eBPF (extended Berkeley Packet Filter)** — это высокопроизводительная, событийно-ориентированная виртуальная машина внутри ядра Linux. Она позволяет безопасно выполнять пользовательский код в адресном пространстве ядра без необходимости изменения исходного кода ядра, загрузки модулей или перезагрузки системы.

**cBPF (classic BPF)** — предшественник eBPF, изначально разработанный для фильтрации сетевых пакетов (используется в `tcpdump`). eBPF расширяет cBPF, добавляя поддержку регистров, дополнительных структур данных (maps) и возможность прикрепления к различным точкам трассировки (tracepoints, kprobes).

## Основные концепции

### Механизм работы

eBPF решает проблему медленного внедрения новых функций в ядро, предоставляя безопасную песочницу для выполнения кода.

1. **Загрузка (Loading):** Пользовательское приложение (через системный вызов `bpf()`) загружает байт-код eBPF в ядро.
2. **Верификация (Verification):** **Верификатор (Verifier)** проверяет программу на безопасность: отсутствие бесконечных циклов, корректность доступа к памяти и лимиты инструкций. Это гарантирует, что eBPF-программа не приведет к панике ядра (kernel panic) или зависанию системы.
3. **JIT-компиляция:** Байт-код компилируется в машинные инструкции процессора для максимальной производительности.
4. **Прикрепление к событию (Attach):** Программа привязывается к определенной точке: системному вызову, сетевому интерфейсу (XDP), точке трассировки ядра (`tracepoint`) или функции (`kprobe`/`uprobe`).
5. **Выполнение и сбор данных:** При возникновении события программа выполняется и сохраняет результаты в **eBPF Maps** — общие структуры данных между ядром и пространством пользователя (userspace).

**BPF Type Format (BTF)** — формат метаданных, описывающий типы данных ядра. Позволяет eBPF-программам работать на разных версиях ядер без перекомпиляции (Compile Once – Run Everywhere, CO-RE).

## Практические сценарии

### Сетевые технологии и балансировка

* **XDP (eXpress Data Path):** Позволяет обрабатывать пакеты на уровне драйвера сетевой карты до входа в основной сетевой стек Linux. Используется для защиты от DDoS и высокопроизводительной балансировки.
* **Cilium:** CNI-плагин для Kubernetes, использующий eBPF для сетевой связности, безопасности (Network Policies) и балансировки нагрузки без использования `iptables`.

### Наблюдаемость и трассировка (Observability)

eBPF обеспечивает глубокий мониторинг системы с минимальными накладными расходами (**overhead**).

* **BCC (BPF Compiler Collection):** Набор инструментов для анализа производительности.

    ```bash
    # Отслеживание запуска новых процессов
    sudo execsnoop
    # → PCOMM            PID    PPID   RET ARGS

    # Анализ задержек дискового ввода-вывода
    sudo biolatency
    ```

* **bpftrace:** Высокоуровневый язык для написания скриптов диагностики «на лету».

    ```bash
    # Подсчет системных вызовов по процессам
    sudo bpftrace -e 'tracepoint:raw_syscalls:sys_enter { @[comm] = count(); }'
    ```

### Безопасность (Runtime Security)

В облачных средах eBPF позволяет отслеживать активность внутри контейнеров (файловые операции, сетевые соединения), не внедряя агенты в образы.

* **Falco:** Обнаруживает аномальное поведение (например, запуск shell в контейнере), перехватывая системные вызовы.
* **Tetragon:** Обеспечивает не только мониторинг, но и принудительное применение политик безопасности (enforcement) на уровне ядра.

## Дополнительная информация

### Требования

* **Версия ядра:** Минимум 4.4 (базовая поддержка), рекомендуется 5.8+ для полной функциональности (BTF, ring buffers).
* **Конфигурация:** `CONFIG_BPF=y`, `CONFIG_BPF_SYSCALL=y`, `CONFIG_BPF_JIT=y`.
