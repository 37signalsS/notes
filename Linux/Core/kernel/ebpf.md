## Определения

### eBPF (extended Berkeley Packet Filter)

**eBPF** — это универсальная, событийно-ориентированная виртуальная машина внутри ядра Linux, которая позволяет безопасно выполнять пользовательский код в пространстве ядра без необходимости его изменения или перезагрузки системы.

### cBPF (classic BPF)

**cBPF (classic BPF)** — это предшественник eBPF, изначально предназначенный только для фильтрации сетевых пакетов (используется такими инструментами как `tcpdump`).

## Основные концепции

### Проблема, которую решает eBPF

Традиционный способ добавления новой функциональности в ядро Linux — это долгий и сложный процесс. eBPF решает эту проблему, предоставляя безопасный и эффективный способ запускать пользовательский код в пространстве ядра без необходимости изменять код самого ядра или перезагружать систему.

### Как работает eBPF

1.  **Загрузка программы:** Пользовательское приложение (например, `opensnoop`) загружает eBPF-программу в ядро. Перед загрузкой **верификатор** проверяет код на безопасность (отсутствие циклов, недопустимых обращений к памяти).
2.  **Прикрепление к событию:** Программа прикрепляется к определенному событию, например, к [системному вызову](./kernel_interfaces.md#Системные-вызовы) `open()`.
3.  **Сбор данных:** Когда системный вызов `open()` происходит, eBPF-программа выполняется. Она может собирать данные (аргументы вызова, возвращаемое значение) и сохранять их в специальные структуры данных — **eBPF maps**.
4.  **Чтение из userspace:** Приложение в пространстве пользователя может читать данные из eBPF maps и отображать их.

### BPF Type Format (BTF)

**BTF (BPF Type Format)** — это формат метаданных, который хранит информацию о типах данных, используемых в ядре. BTF делает eBPF-программы более переносимыми и упрощает их разработку, так как отпадает необходимость в точной синхронизации с заголовочными файлами ядра.

## Практические сценарии


### 1. Сеть и балансировка нагрузки

-   **XDP (eXpress Data Path):** Позволяет обрабатывать сетевые пакеты на самом раннем этапе, еще до их входа в основной сетевой стек ядра. Это используется для высокопроизводительной защиты от DDoS, балансировки нагрузки и маршрутизации.
-   **Cilium:** Популярный CNI-плагин для Kubernetes, который использует eBPF для обеспечения сетевого взаимодействия между контейнерами, применения политик безопасности и балансировки нагрузки с высокой производительностью.

### 2. Наблюдаемость и трассировка (Observability & Tracing)

eBPF позволяет осуществлять глубокий, неинтрузивный мониторинг Linux-систем, предоставляя детальную информацию о работе ядра и приложений без остановки сервисов.

-   **BCC (BPF Compiler Collection):** Набор инструментов и библиотек на Python и C++, который позволяет видеть, что реально происходит в ядре и приложениях. Включает десятки готовых утилит для профилирования и трассировки системы:
    -   **`execsnoop`**: Отслеживает запуск новых процессов.
        ```bash
        sudo execsnoop
        ```
    -   **`tcplife`**: Показывает время жизни TCP-соединений.
        ```bash
        sudo tcplife
        ```
    -   **`funclatency`**: Измеряет задержки выполнения функций.
        ```bash
        sudo funclatency do_sys_open
        ```

-   **bpftrace:** Высокоуровневый язык трассировки, похожий на `awk` и `DTrace`, для написания коротких скриптов "на лету".
    -   **Подсчет системных вызовов `write` для `nginx`:**
        ```bash
        sudo bpftrace -e 'tracepoint:syscalls:sys_enter_write /comm == "nginx"/ { @[pid] = count(); }'
        ```
    -   **Отслеживание переповторной передачи TCP-пакетов:**
        ```bash
        sudo bpftrace -e 'tracepoint:tcp:tcp_retransmit_skb { @[comm] = count(); }'
        ```

### 3. Безопасность

-   **Falco:** Популярный инструмент для обнаружения аномальной активности и угроз в реальном времени. Falco использует eBPF для перехвата системных вызовов и сравнения их с набором правил безопасности.
-   **Tetragon:** Компонент безопасности от создателей Cilium, который также использует eBPF для мониторинга событий безопасности на уровне ядра.
