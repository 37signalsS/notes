# eBPF (extended Berkeley Packet Filter) — виртуальная машина ядра

## Определения

**eBPF (extended Berkeley Packet Filter)** — это универсальная, событийно-ориентированная виртуальная машина внутри ядра Linux. Она позволяет безопасно выполнять пользовательские программы в адресном пространстве ядра без необходимости модификации исходного кода ядра, загрузки модулей или перезагрузки системы. eBPF превращает ядро в программируемую платформу, позволяя динамически расширять его функциональность в области сетевого взаимодействия, безопасности и мониторинга.

**cBPF (classic BPF)** — изначальная реализация (1992 г.), предназначенная исключительно для фильтрации сетевых пакетов (например, в `tcpdump`). eBPF расширяет эту архитектуру, добавляя поддержку 64-битных регистров, дополнительных структур данных (maps) и возможность прикрепления к любым точкам выполнения в ядре и пользовательском пространстве.

## Основные концепции

### Жизненный цикл программы eBPF

1.  **Разработка:** Программа пишется на подмножестве C (или Rust) и компилируется в байт-код eBPF с помощью LLVM/Clang.
2.  **Загрузка:** Байт-код загружается в ядро через системный вызов `bpf()`.
3.  **Верификация (Verifier):** Самый важный этап безопасности. Ядро проверяет программу на:
    -   Отсутствие бесконечных циклов.
    -   Безопасный доступ к памяти (только в разрешенные области).
    -   Соответствие лимитам сложности (количество инструкций).
    -   Гарантированное завершение.
4.  **JIT-компиляция:** Проверенный байт-код компилируется в нативные машинные инструкции (x86, ARM и др.) для выполнения с нативной скоростью.
5.  **Прикрепление (Attachment):** Программа привязывается к событию (hook), такому как вход в системный вызов, прием сетевого пакета (XDP), срабатывание таймера или завершение функции.

### Ключевые механизмы современности (2024-2025)

*   **BTF (BPF Type Format) и CO-RE (Compile Once – Run Everywhere):** Набор технологий, позволяющий eBPF-программе работать на разных версиях ядер без перекомпиляции. `libbpf` использует метаданные BTF текущего ядра для автоматической корректировки смещений в структурах данных прямо в момент загрузки.
*   **eBPF Maps:** Структуры данных (хеш-таблицы, массивы, кольцевые буферы) для обмена информацией между программой в ядре и приложением в user-space, а также для сохранения состояния между вызовами eBPF-программ.
*   **Ring Buffer (Bpf Ringbuf):** Заменил старый `Perf Buffer`. Обеспечивает высокопроизводительную передачу событий из ядра в пространство пользователя с гарантированным порядком (FIFO) и меньшими накладными расходами на память.
*   **Helpers и kfuncs:**
    -   **Helpers:** Стабильные функции ядра, доступные eBPF-программам.
    -   **kfuncs (Kernel Functions):** Более гибкий и современный интерфейс, позволяющий вызывать функции ядра напрямую (если они помечены как доступные), что упрощает добавление новых возможностей в eBPF.
*   **sched_ext (Kernel 6.12+):** Революционный фреймворк, позволяющий реализовывать полноценные планировщики CPU на eBPF. Это дает возможность оптимизировать распределение ресурсов под специфические нагрузки (игры, БД) без изменения кода ядра.

## Практические сценарии

### Сетевая обработка и фильтрация

*   **XDP (eXpress Data Path):** Обработка пакетов на самом раннем уровне драйвера сетевой карты. Позволяет сбрасывать вредоносный трафик (DDoS) или реализовывать балансировщики нагрузки с производительностью, близкой к аппаратной.
*   **Замена kube-proxy:** Проекты вроде **Cilium** полностью заменяют громоздкие правила `iptables` на эффективные eBPF-карты, что критично для масштабируемости кластеров Kubernetes.

### Наблюдаемость и профилирование

eBPF позволяет собирать метрики с минимальным влиянием на систему (low overhead).

*   **Инструменты BCC и bpftrace:**
    ```bash
    # bpftrace: Подсчет прочитанных байт по процессам
    sudo bpftrace -e 'kretprobe:vfs_read { @[comm] = sum(retval); }'
    ```
*   **Continuous Profiling:** Системы (Parca, Pyroscope) используют eBPF для постоянного сбора стеков вызовов всех процессов, что позволяет находить «горячие точки» производительности даже в продакшене.

### Безопасность и Runtime Enforcement

*   **LSM-BPF:** Возможность писать политики безопасности для Linux Security Modules (LSM) на eBPF. Это позволяет блокировать подозрительные системные вызовы на основе сложной логики.
*   **Tetragon / Falco:** Обнаружение аномалий (например, изменение `LD_PRELOAD` или открытие чувствительных файлов) в реальном времени с возможностью немедленной блокировки процесса.

## Дополнительная информация

### Основные инструменты разработки

*   **libbpf:** Стандартная библиотека для создания современных портативных приложений eBPF.
*   **bpftool:** Основная утилита для инспекции и отладки eBPF-программ и карт в работающей системе.
*   **libbpf-bootstrap:** Рекомендуемый шаблон для начала разработки новых eBPF-инструментов.

### Требования

*   **Ядро:** Минимум 4.4, для современных функций (Ringbuf, BTF, LSM) — 5.8+, для `sched_ext` — 6.12+.
*   **Конфигурация ядра:**
    -   `CONFIG_BPF=y`
    -   `CONFIG_BPF_SYSCALL=y`
    -   `CONFIG_BPF_JIT=y`
    -   `CONFIG_DEBUG_INFO_BTF=y` (критично для CO-RE)
