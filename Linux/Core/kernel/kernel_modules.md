# Модули ядра Linux

## Определения

**Модуль ядра (Kernel Module)** — это скомпилированный кусок кода (имеет расширение `.ko` — kernel object), который можно подключить к ядру на лету (расширяет функциональность работающего ядра Linux без необходимости перезагрузки системы). 
К модулям относятся: драйверы устройств, файловые системы, сетевые протоколы, криптоалгоритмы. 

Благодаря модульной архитектуре ядро не таскает с собой всё подряд — нужное подгружается по требованию.

**Расположение модулей:**
Все скомпилированные модули лежат в `/lib/modules/$(uname -r)/`, где они разложены по категориям (например, `kernel/drivers/`, `kernel/fs/`, `kernel/net/`).

## Основные концепции

### Зависимости и маршрутизация (modprobe vs insmod)

Утилита `modprobe` — умная утилита для загрузки и выгрузки модулей. В отличие от прямого использования `insmod`, `modprobe`:
- Автоматически отслеживает, подтягивает и загружает зависимости.
- Ищет модули в стандартных путях.
- Работает с алиасами.

`modprobe` — базовый инструмент, без которого не настроить ни Kubernetes-ноду, ни туннелирование, ни кастомные сетевые правила.

### Причины для управления модулями

- **Отладка и тестирование:** Замена или тестирование новых версий драйверов.
- **Оптимизация системы:** Исключение ненужных модулей для уменьшения потребления памяти.
- **Безопасность:** Запрет загрузки уязвимых, нежелательных или конфликтующих модулей.
- **Разработка:** Легкая загрузка и выгрузка модулей в процессе разработки.

## Практические сценарии

### Просмотр информации о модулях

- **`lsmod`**: Выводит список всех загруженных в данный момент модулей.
- **`modinfo <имя_модуля>`**: Показывает подробную информацию о модуле (автор, описание, зависимости, доступные параметры).
  - Пример: `modinfo overlay`

### Загрузка модулей

- **`modprobe <имя_модуля>`**: Предпочтительный способ (разовая загрузка, живет до ребута). Автоматически найдет зависимости и подгрузит их.
  - Пример: `sudo modprobe overlay`
- **`insmod <путь_к_модулю.ko>`**: Загружает модуль напрямую, но не управляет зависимостями. Используется в основном для тестирования.
  - Пример: `sudo insmod /lib/modules/$(uname -r)/kernel/fs/vfat/vfat.ko`

### Выгрузка модулей

- **`modprobe -r <имя_модуля>`**: Выгружает модуль и его неиспользуемые зависимости.
  - Пример: `sudo modprobe -r overlay`
- **`rmmod <имя_модуля>`**: Выгружает модуль напрямую (без управления зависимостями).
- **Примечание:** Модуль не может быть выгружен, если он используется. Необходимо сначала остановить процессы или отмонтировать устройства, которые его используют.

### Управление параметрами модулей

- **Временно (при загрузке):**

    ```bash
    sudo modprobe pcspkr beep=0 # Отключить звук из динамика PC
    ```

- **Постоянно (через конфигурационный файл):**
    Создайте `.conf` файл в `/etc/modprobe.d/`.

    ```bash
    # /etc/modprobe.d/nobeep.conf
    options pcspkr beep=0
    ```

### Управление автозагрузкой

Разовая загрузка через `modprobe` живёт до ребута. Чтобы модуль подгружался автоматически, его необходимо прописать в конфигурацию.

- **Для автоматической загрузки:**
    Создайте файл со списком модулей (по одному на строку) в директории `/etc/modules-load.d/`.

    ```bash
    sudo nano /etc/modules-load.d/k8s.conf
    ```

    Внутри конфига:

    ```text
    br_netfilter
    overlay
    ```

    После ребута модули загрузятся автоматически.

### Блокировка модулей (Blacklist)

Иногда нужно запретить автозагрузку — например, если драйвер конфликтует или протокол уязвим.

- **Для запрета загрузки:**
    Добавьте `blacklist <имя_модуля>` в файл в директории `/etc/modprobe.d/`.

    ```bash
    sudo nano /etc/modprobe.d/blacklist-custom.conf
    ```

    Внутри конфига:

    ```text
    # Отключение Bluetooth
    blacklist btusb
    blacklist bluetooth
    ```

    **Важно:** После правки нужно пересобрать initramfs, если модуль грузится на ранней стадии загрузки:

    ```bash
    sudo update-initramfs -u   # Debian/Ubuntu
    sudo dracut -f             # RHEL/Fedora
    ```

### Принудительная выгрузка и удаление

- **Принудительная выгрузка:** `rmmod -f <имя_модуля>` — принудительная выгрузка, даже если модуль используется. **Опасно:** может вызвать панику ядра.
- **Полное удаление:** Физическое удаление `.ko`-файла предотвращает его загрузку:

    ```bash
    find /lib/modules/$(uname -r) -name "<модуль>.ko" -delete
    sudo depmod -a
    ```
