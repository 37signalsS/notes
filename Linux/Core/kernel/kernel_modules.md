# Модули ядра Linux

## Определения

**Модуль ядра (Kernel Module)** — скомпилированный объектный файл (имеет расширение `.ko` — Kernel Object), который может быть динамически подключен к работающему ядру Linux или выгружен из него без перезагрузки системы.

**LKM (Loadable Kernel Module)** — технология загружаемых модулей, позволяющая расширять возможности ядра (драйверы устройств, файловые системы, сетевые протоколы) по мере необходимости.

Благодаря модульной архитектуре ядро остается компактным, так как второстепенные компоненты подгружаются только при обнаружении соответствующего оборудования или запросе пользователя.

**Расположение модулей:**
Все модули хранятся в директории `/lib/modules/$(uname -r)/` и распределены по категориям (например, `kernel/drivers/`, `kernel/fs/`, `kernel/net/`).

## Основные концепции

### Управление зависимостями (modprobe vs insmod)

Для работы с модулями используются две основные утилиты:

- **`modprobe`**: «умный» инструмент для загрузки и выгрузки. Он автоматически находит модуль в стандартных путях, анализирует зависимости (через файл `modules.dep`) и загружает всю необходимую цепочку модулей.
- **`insmod`**: низкоуровневая утилита, которая загружает конкретный файл по указанному пути. Она не умеет разрешать зависимости и используется в основном при разработке.

### Жизненный цикл модуля

1. **Компиляция:** создание `.ko` файла из исходного кода.
2. **Загрузка:** помещение кода в память ядра и регистрация обработчиков.
3. **Работа:** выполнение функций в контексте ядра.
4. **Выгрузка:** освобождение ресурсов и удаление кода из памяти.

## Практические сценарии

### Анализ состояния модулей

```bash
# Список всех загруженных модулей
lsmod | head -n 5
# → Module                  Size  Used by
# → overlay               151552  0
# → xt_conntrack           16384  1

# Детальная информация о модуле (автор, описание, параметры)
modinfo overlay
# → filename:       /lib/modules/6.1.0-21-amd64/kernel/fs/overlayfs/overlay.ko
# → description:    Overlay filesystem
```

### Загрузка и выгрузка

```bash
# Загрузка модуля с автоматическим разрешением зависимостей
sudo modprobe br_netfilter
# → (без вывода при успехе)

# Выгрузка модуля и неиспользуемых зависимостей
sudo modprobe -r br_netfilter
```

**Примечание:** модуль нельзя выгрузить, если он используется системой или другим модулем (столбец `Used by` в `lsmod`).

### Настройка параметров и автозагрузки

**Постоянные параметры модулей:**
Создайте конфигурационный файл в `/etc/modprobe.d/`.

```bash
# /etc/modprobe.d/pcspkr.conf
options pcspkr beep=0
```

**Автоматическая загрузка при старте:**
Добавьте имя модуля в файл внутри `/etc/modules-load.d/`.

```bash
# /etc/modules-load.d/k8s.conf
br_netfilter
overlay
```

### Блокировка загрузки (Blacklist)

Для предотвращения загрузки нежелательных или конфликтных модулей:

1. Создайте файл в `/etc/modprobe.d/blacklist.conf`.
2. Добавьте строку `blacklist <имя_модуля>`.
3. После внесения изменений необходимо обновить **initramfs**:

```bash
# Debian/Ubuntu
sudo update-initramfs -u
# RHEL/Fedora
sudo dracut -f
```

### Принудительные действия

```bash
# Принудительная выгрузка используемого модуля (ОПАСНО!)
sudo rmmod -f <имя_модуля>
# → (может привести к Kernel Panic)

# Обновление базы зависимостей модулей
sudo depmod -a
```
