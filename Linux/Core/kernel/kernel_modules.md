# Модули ядра Linux

## Определения

**Модуль ядра (Kernel Module)** — это скомпилированный объектный файл (обычно с расширением `.ko`, `.ko.zst` или `.ko.xz`), содержащий код для расширения базовой функциональности ядра. Это позволяет динамически добавлять поддержку драйверов, файловых систем и сетевых протоколов без перезагрузки.

**LKM (Loadable Kernel Module)** — механизм, обеспечивающий модульность Linux, позволяя подгружать компоненты в адресное пространство ядра по требованию.

**In-tree vs Out-of-tree:**
- **In-tree:** Модули, находящиеся в основном дереве исходного кода ядра Linux. Обслуживаются сообществом, гарантированно совместимы с конкретной версией ядра.
- **Out-of-tree:** Сторонние модули (NVIDIA, ZFS, VirtualBox), разрабатываемые вне основного дерева. Требуют пересборки при обновлении ядра (обычно через DKMS).

## Основные концепции

### Жизненный цикл и механизмы (2024–2026)

1.  **Rust в ядре:** Начиная с версии 6.1, ядро поддерживает модули на **Rust**. Это устраняет целые классы ошибок управления памятью (Use-after-free, Double free) на этапе компиляции.
2.  **Загрязнение ядра (Kernel Taint):** Если загружается проприетарный или Out-of-tree модуль, ядро помечается как «загрязненное» (tainted). Это важный индикатор при анализе Kernel Panic.
    - Проверка: `cat /proc/sys/kernel/tainted` (0 — чистое ядро).
3.  **Безопасность и подпись:**
    - **Secure Boot + Lockdown:** Требуют обязательной подписи модулей.
    - `CONFIG_MODULE_SIG_FORCE=y`: Ядро откажется загружать любой модуль без валидной подписи.
4.  **Алиасы и udev:** Ядро сопоставляет оборудование с модулями через таблицу алиасов (`modules.alias`). При обнаружении устройства `udev` автоматически вызывает `modprobe` для загрузки нужного драйвера.

### Управление зависимостями

- **`modprobe`**: Основной инструмент. Использует `modules.dep` (создается `depmod`) для автоматической загрузки цепочки зависимостей.
- **`insmod`**: Загружает конкретный файл `.ko`. Игнорирует зависимости и не использует системные пути.

## Практические сценарии

### Анализ и инспекция

```bash
# Список модулей, отсортированный по количеству зависимостей
lsmod | sort -k3 -nr | head

# Подробная информация и проверка подписи
modinfo -F sig_key nvme  # Просмотр ключа подписи
modinfo -p usb_storage   # Только список параметров модуля

# Проверка символов (экспортируемых функций)
grep "T " /proc/kallsyms | grep "\[overlay\]"
```

### Диагностика и устранение неполадок

При проблемах с загрузкой модуля используйте системные логи:
```bash
# Просмотр сообщений ядра при загрузке модуля
sudo dmesg -w

# Ошибки modprobe через journalctl
journalctl -kt kernel | grep "module"
```

### Расширенное управление параметрами

Параметры можно передавать не только при загрузке, но и через аргументы ядра в загрузчике (GRUB):
```bash
# В /etc/default/grub (требует update-grub)
GRUB_CMDLINE_LINUX_DEFAULT="... usbcore.autosuspend=-1"

# Запрет загрузки модуля на уровне загрузчика
module_blacklist=pcspkr,ipv6
```

### Автоматизация через DKMS

DKMS (Dynamic Kernel Module Support) незаменим для проприетарных драйверов.
```bash
# Сборка модуля для конкретного ядра (если не собрался автоматически)
sudo dkms build -m nvidia -v 550.54 -k 6.8.0-generic
sudo dkms install -m nvidia -v 550.54 -k 6.8.0-generic
```
