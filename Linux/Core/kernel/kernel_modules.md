# Управление модулями ядра в Linux

## Определения

**Модуль ядра (Kernel Module, ko-файл)** — это исполняемый файл, который расширяет функциональность ядра Linux без необходимости перезагрузки всей системы. Модули позволяют динамически добавлять поддержку файловых систем, сетевых интерфейсов, драйверов оборудования и других функций.

## Основные концепции

Модули ядра загружаются автоматически при необходимости, но также могут управляться вручную.

### Загрузка модулей ядра

Если Linux не загрузил нужный модуль автоматически, его можно загрузить вручную.

*   **`modprobe <имя_модуля>`:** Предпочтительный способ загрузки модуля, так как он автоматически разрешает и загружает все необходимые зависимости.
    *   Пример: `modprobe vfat` (загрузка драйвера FAT32).
*   **`insmod <путь_к_модулю.ko>`:** Загружает модуль напрямую, но **не управляет зависимостями**. Используется, если `modprobe` не находит модуль, или для тестирования конкретного `.ko` файла.
    *   Пример: `insmod /lib/modules/$(uname -r)/kernel/drivers/net/<module>.ko`

### Удаление модулей ядра

Иногда требуется выгрузить модуль, например, для отладки, обновления или освобождения ресурсов.

### Выгрузка модуля

Напрямую удалить модуль ядра, который используется процессом, **невозможно** без предварительного прекращения его использования. Команды `modprobe -r` или `rmmod` завершатся ошибкой, если модуль имеет активные пользователи.

**Порядок действий, если модуль используется:**
1.  **Определить, какой процесс/устройство использует модуль:**
    *   Проверьте вывод `lsmod`, колонка `Used by` покажет, от каких модулей зависит данный.
    *   Для драйверов устройств, убедитесь, что устройство, управляемое этим драйвером, не используется (например, отмонтируйте файловую систему, если это драйвер диска, или отключите сетевой интерфейс).
    *   В более сложных случаях может потребоваться использовать `lsof` или `fuser` для поиска открытых файлов или процессов, использующих ресурсы, связанные с модулем, но это редко прямо указывает на модуль ядра.
2.  **Остановить процессы или отключить устройства**, использующие модуль.
3.  **Выгрузить модуль:**
    *   **`modprobe -r <имя_модуля>`:** Предпочтительный способ выгрузки модуля, так как он также выгружает все неиспользуемые зависимости.
    *   **`rmmod <имя_модуля>`:** Удаляет модуль.
    *   **Принудительная выгрузка:** `rmmod -f <имя_модуля>` (использовать с крайней осторожностью! Может привести к нестабильности системы или падению ядра).

---

*   **Как найти процессы, использующие модуль:**
    *   `lsmod | grep <имя_модуля>`: Показывает, загружен ли модуль.
    *   `lsof | grep <имя_модуля>`: Помогает найти файлы, открытые процессами, которые могут использовать модуль.

### Добавление модуля в автозагрузку

Чтобы модуль автоматически загружался при старте системы:

*   Добавьте имя модуля в файл `/etc/modules` (для старых систем) или создайте файл конфигурации в `/etc/modules-load.d/`.
    *   Пример (добавление в `/etc/modules`):
        ```bash
        echo "<имя_модуля>" | sudo tee -a /etc/modules
        ```

### Отключение автозагрузки модуля (Blacklisting)

Если модуль загружается автоматически, но его необходимо отключить:

*   **`blacklist <имя_модуля>`:** Добавьте эту строку в файл `.conf` в директории `/etc/modprobe.d/`. Чаще всего используется `/etc/modprobe.d/blacklist.conf`.
    *   Пример:
        ```bash
        echo "blacklist <имя_модуля>" | sudo tee -a /etc/modprobe.d/blacklist.conf
        ```
*   После внесения изменений необходимо обновить конфигурацию `initramfs` и перезагрузить систему:
    ```bash
    sudo update-initramfs -u
    reboot
    ```

## Зачем управлять модулями ядра?

*   **Отладка и тестирование:** Позволяет заменять или тестировать новые версии драйверов и других компонентов без полной пересборки ядра.
*   **Оптимизация системы:** Исключение ненужных модулей из загрузки может уменьшить потребление памяти и ускорить загрузку системы.
*   **Безопасность:** Запрет загрузки уязвимых, непроверенных или нежелательных модулей для повышения безопасности системы.
*   **Разработка драйверов:** Разработчики могут легко тестировать свои драйверы, загружая и выгружая их.

## Расширенные детали

### Полное удаление модуля из системы

Если модуль больше не нужен и его необходимо полностью удалить из файловой системы:

*   **Поиск и удаление:**
    ```bash
    find /lib/modules/$(uname -r) -name "<модуль>.ko" -delete
    ```
    *   **Внимание:** Удаляйте файлы модулей только если вы уверены, что они не используются и не понадобятся в будущем, так как это может нарушить работу системы.

### Просмотр информации о модулях

*   **`lsmod`:** Выводит список всех загруженных в данный момент модулей ядра.
*   **`modinfo <имя_модуля>`:** Показывает подробную информацию о модуле (автор, описание, зависимости, параметры).

### Параметры модулей

Многие модули ядра принимают параметры во время загрузки, что позволяет настраивать их поведение.

*   Параметры можно передать при загрузке с помощью `modprobe`:
    ```bash
    modprobe <имя_модуля> <параметр>=<значение>
    ```
    *   Пример: `modprobe pcspkr beep=0` (отключить звук из динамика PC).
*   Для постоянной передачи параметров создайте файл конфигурации в `/etc/modprobe.d/`:
    ```bash
    # /etc/modprobe.d/my_module.conf
    options <имя_модуля> <параметр>=<значение>
    ```
