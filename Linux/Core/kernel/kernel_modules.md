## Определения

**Модуль ядра (Kernel Module, ko-файл)** — это исполняемый файл, который расширяет функциональность работающего ядра Linux без необходимости перезагрузки системы. Модули позволяют динамически добавлять поддержку файловых систем, драйверов оборудования, сетевых протоколов и других функций.

## Основные концепции

### Модульная архитектура

Ядро Linux имеет модульную структуру, что позволяет ядру быть относительно небольшим, а дополнительную функциональность загружать по мере необходимости. Это обеспечивает гибкость и эффективность.

### Зависимости модулей

Утилита `modprobe` автоматически отслеживает и загружает/выгружает эти зависимости, что делает ее предпочтительным инструментом для управления модулями.

### Причины для управления модулями

-   **Отладка и тестирование:** Замена или тестирование новых версий драйверов.
-   **Оптимизация системы:** Исключение ненужных модулей для уменьшения потребления памяти.
-   **Безопасность:** Запрет загрузки уязвимых или нежелательных модулей.
-   **Разработка:** Легкая загрузка и выгрузка модулей в процессе разработки.

## Практические сценарии

### Просмотр информации о модулях

-   **`lsmod`**: Выводит список всех загруженных в данный момент модулей.
-   **`modinfo <имя_модуля>`**: Показывает подробную информацию о модуле (автор, описание, зависимости, доступные параметры).

### Загрузка модулей

-   **`modprobe <имя_модуля>`**: Предпочтительный способ. Автоматически разрешает и загружает все зависимости.
    -   Пример: `sudo modprobe vfat`
-   **`insmod <путь_к_модулю.ko>`**: Загружает модуль напрямую, но не управляет зависимостями. Используется для тестирования.
    -   Пример: `sudo insmod /lib/modules/$(uname -r)/kernel/fs/vfat/vfat.ko`

### Выгрузка модулей

-   **`modprobe -r <имя_модуля>`** или **`rmmod <имя_модуля>`**: Выгружает модуль и его неиспользуемые зависимости.
    -   Пример: `sudo modprobe -r vfat`
-   **Примечание:** Модуль не может быть выгружен, если он используется. Необходимо сначала остановить процессы или отмонтировать устройства, которые его используют.

### Управление параметрами модулей

-   **Временно (при загрузке):**
    ```bash
    sudo modprobe pcspkr beep=0 # Отключить звук из динамика PC
    ```
-   **Постоянно (через конфигурационный файл):**
    Создайте `.conf` файл в `/etc/modprobe.d/`.
    ```
    # /etc/modprobe.d/nobeep.conf
    options pcspkr beep=0
    ```

### Управление автозагрузкой

-   **Для автоматической загрузки:**
    Добавьте имя модуля в файл в директории `/etc/modules-load.d/`.
    ```bash
    # /etc/modules-load.d/vfat.conf
    vfat
    ```
-   **Для запрета автоматической загрузки (blacklisting):**
    Добавьте `blacklist <имя_модуля>` в файл в директории `/etc/modprobe.d/`.
    ```bash
    # /etc/modprobe.d/blacklist-pcspkr.conf
    blacklist pcspkr
    ```
    После этого может потребоваться обновить `initramfs` (`sudo update-initramfs -u` на Debian/Ubuntu) и перезагрузить систему.

## Дополнительная информация

### Принудительная выгрузка

Команда `rmmod -f <имя_модуля>` позволяет принудительно выгрузить модуль, даже если ядро считает, что он используется. **Это крайне опасно и может привести к немедленной панике ядра или нестабильности системы.** Использовать следует только в крайних случаях для отладки.

### Полное удаление модуля из системы

Если модуль больше не нужен, его можно физически удалить из файловой системы, чтобы он не мог быть загружен.
```bash
# Найти и удалить файл модуля
find /lib/modules/$(uname -r) -name "<модуль>.ko" -delete
# После этого обязательно обновить зависимости модулей
sudo depmod -a
```
