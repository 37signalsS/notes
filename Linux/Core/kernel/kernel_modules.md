# Модули ядра Linux

## Определения

**Модуль ядра (Kernel Module)** — это скомпилированный объектный файл (обычно с расширением `.ko`, `.ko.zst` или `.ko.xz`), который содержит код, расширяющий базовую функциональность ядра Linux. Модули позволяют динамически добавлять поддержку драйверов оборудования, файловых систем и сетевых протоколов без необходимости полной пересборки ядра или перезагрузки системы.

**LKM (Loadable Kernel Module)** — технология загружаемых модулей, обеспечивающая модульную архитектуру Linux. Это позволяет сохранять основной образ ядра (vmlinuz) компактным, подгружая только необходимые компоненты по требованию системы или пользователя.

## Основные концепции

### Жизненный цикл и механизмы (2024–2026)

1.  **Разработка и языки:** Исторически модули пишутся на языке C. Начиная с ядра 6.1 и выше, официально поддерживается разработка модулей на **Rust**, что значительно снижает риски уязвимостей, связанных с управлением памятью (Buffer Overflow, Use-after-free).
2.  **Компрессия:** В современных дистрибутивах стандартом стала компрессия модулей с использованием алгоритма **Zstd** (`CONFIG_MODULE_COMPRESS_ZSTD`). Это обеспечивает высокую скорость загрузки и декомпрессии по сравнению с Gzip/XZ.
3.  **Безопасность и подпись (Signing):** В режиме **Lockdown** (активируется через Secure Boot) ядро разрешает загрузку только модулей, имеющих валидную криптографическую подпись (PKCS#7). Неподписанные сторонние модули (например, NVIDIA, VirtualBox) требуют импорта Machine Owner Key (MOK).

### Управление зависимостями

Ядро отслеживает взаимосвязи между модулями (например, модуль `overlay` может зависеть от модулей файловых систем).
- **`modprobe`**: Высокоуровневая утилита. Автоматически находит модуль в `/lib/modules/$(uname -r)/`, анализирует файл зависимостей `modules.dep` и загружает всю необходимую цепочку.
- **`insmod`**: Низкоуровневая утилита для загрузки конкретного файла по пути. Не умеет разрешать зависимости.

## Практические сценарии

### Анализ и инспекция

```bash
# Список всех загруженных модулей и их использование
lsmod | head -n 5

# Просмотр метаданных модуля (версия, лицензия, параметры, подпись)
modinfo nvme
# → filename:       /lib/modules/.../kernel/drivers/nvme/host/nvme.ko.zst
# → sig_key:        ... (указывает на наличие подписи)

# Поиск модуля по имени файла
find /lib/modules/$(uname -r) -name "*virtio*"
```

### Загрузка и управление параметрами

```bash
# Загрузка модуля с параметром (например, изменение режима вложенной виртуализации)
sudo modprobe kvm_intel nested=1

# Проверка текущих параметров загруженного модуля
cat /sys/module/kvm_intel/parameters/nested
# → Y
```

### Автоматизация и Blacklisting

1.  **Автозагрузка при старте:** Добавьте имя модуля в файл конфигурации `systemd-modules-load`.
    ```bash
    # /etc/modules-load.d/k8s.conf
    br_netfilter
    overlay
    ```
2.  **Запрет загрузки (Blacklist):** Используется для предотвращения конфликтов или повышения безопасности.
    ```bash
    # /etc/modprobe.d/blacklist.conf
    blacklist pcspkr
    ```
3.  **Обновление initramfs:** После изменения черных списков или параметров, влияющих на загрузку дисков, необходимо обновить загрузочный образ.
    ```bash
    # Debian/Ubuntu
    sudo update-initramfs -u
    # RHEL/Fedora
    sudo dracut -f
    ```

### Использование DKMS (Dynamic Kernel Module Support)

DKMS используется для автоматической пересборки сторонних модулей (Out-of-tree) при каждом обновлении ядра. Это критично для таких систем как ZFS или драйверы видеокарт.
```bash
# Проверка статуса модулей DKMS
dkms status
```
