# Live Patching и kexec — обновление ядра без перезагрузки

## Определения

**Live Patching** — технология применения критических обновлений безопасности и багфиксов к работающему ядру Linux без остановки системы и её перезагрузки.

**kexec** — системный вызов, позволяющий загрузить новое ядро Linux непосредственно из текущего, минуя этапы BIOS/UEFI и аппаратной инициализации (POST — Power-On Self-Test).

## Основные концепции

### Принцип работы Live Patching

Инструменты Live Patching используют механизм трассировки функций ядра (`ftrace`) для перенаправления вызовов. Когда в ядре обнаруживается уязвимость, патч загружается как специальный модуль ядра, который подменяет адрес оригинальной функции на адрес исправленной версии в оперативной памяти.

* **Назначение:** устранение критических уязвимостей (CVE — Common Vulnerabilities and Exposures) в ядре.
* **Ограничение:** технология не позволяет обновлять структуры данных или выполнять мажорные обновления ядра; она эффективна только для замены кода функций.
* **Преимущество:** обеспечение непрерывности работы (High Availability) и исключение окон обслуживания для инфраструктурных узлов.

### Сравнение реализаций

| Решение | Разработчик | Дистрибутивы |
| :--- | :--- | :--- |
| **kpatch** | Red Hat | RHEL (Red Hat Enterprise Linux), AlmaLinux, Rocky Linux |
| **ksplice** | Oracle | Oracle Linux |
| **Canonical Livepatch** | Canonical | Ubuntu |
| **KernelCare** | TuxCare | Поддержка множества дистрибутивов (коммерческое) |

### Механизм быстрой перезагрузки (kexec)

`kexec` значительно сокращает время простоя системы при плановом обновлении ядра, так как пропускает самую долгую фазу — инициализацию оборудования прошивкой.

* **Отличие от Live Patching:** `kexec` всё же прерывает выполнение процессов пространства пользователя (Userspace), но делает это намного быстрее стандартной перезагрузки.
* **Использование в kdump:** механизм сбора дампов памяти при панике ядра использует `kexec` для мгновенного запуска «ядра-сборщика» (Capture Kernel). Подробнее см. в [**Паника ядра**](./kernel_panic.md).

## Практические сценарии

### Использование kexec для обновления ядра

После установки нового пакета ядра его можно загрузить в память и активировать.

**1. Установка инструментов:**

```bash
# RHEL/CentOS
sudo yum install kexec-tools -y

# Debian/Ubuntu
sudo apt install kexec-tools -y
```

**2. Подготовка нового ядра:**

```bash
# Загрузить образ ядра и initramfs (Initial RAM File System) в память
sudo kexec -l /boot/vmlinuz-$(uname -r) --initrd=/boot/initrd.img-$(uname -r) --reuse-cmdline
```

**3. Выполнение быстрого перехода:**

```bash
# Через systemd (рекомендуется)
sudo systemctl kexec

# Или напрямую
sudo kexec -e
```

### Проверка статуса Live Patching

```bash
# Список загруженных патчей (для систем с kpatch)
sudo kpatch list
# → Loaded patch modules:
# → kpatch_cumulative_update_1_0 [enabled]

# Проверка через sysfs
cat /sys/kernel/livepatch/*/enabled
# → 1
```
