# Живое обновление ядра: Live Patching и kexec

## Определения

**Live Patching (Живой патчинг)** — технология применения исправлений безопасности (CVE) и критических багфиксов к работающему ядру Linux без остановки системы и её перезагрузки. Механизм позволяет заменять код функций ядра «на лету», обеспечивая непрерывность работы (High Availability) критически важных сервисов.

**kexec** — системный вызов и механизм ядра, позволяющий загрузить и запустить новое ядро Linux непосредственно из текущего, минуя этапы инициализации оборудования (BIOS/UEFI) и самодиагностики (POST).

**Kexec Handover (KHO)** — современное расширение (начиная с ядра 6.16), позволяющее передавать состояние оперативной памяти (например, память виртуальных машин или файловые дескрипторы) от старого ядра новому при переходе через kexec, что сводит время простоя к миллисекундам.

## Основные концепции

### Механизмы работы Live Patching

В основе технологии лежит механизм трассировки функций `ftrace`.
1.  **Перенаправление вызовов:** Патч поставляется как модуль ядра. При активации `ftrace` подменяет адрес оригинальной функции на адрес исправленной версии в оперативной памяти.
2.  **Консистентность (Consistency Model):** Ядро использует механизм «постепенного перехода» (per-task consistency). Переключение на новый код происходит только тогда, когда поток выполнения находится в безопасном состоянии (вне патчируемой функции).
3.  **Теневые переменные (Shadow Variables):** Техника, позволяющая связывать дополнительные данные с объектами ядра без изменения структуры их описателей в памяти, что предотвращает нарушение бинарной совместимости (ABI).

### Эволюция kexec: от перезагрузки к Live Update (2025–2026)

Традиционный `kexec` требовал перезапуска всех приложений. Современный стек технологий меняет этот подход:
- **LUO (Live Update Orchestrator):** Фреймворк в ядре (6.19+), координирующий передачу ресурсов между ядрами.
- **Интеграция с systemd (v261+):** Позволяет сохранять файловые дескрипторы сервисов в специальном хранилище (`FD Store`), которое выживает после `kexec`. Это позволяет выполнять «мягкую перезагрузку» (soft-reboot), при которой ядро обновляется, но дерево процессов и их сетевые соединения сохраняются.

### Сравнение технологий патчинга

| Решение | Механизм переключения | Особенности |
| :--- | :--- | :--- |
| **Livepatch (Upstream)** | Постепенный (per-task) | Официальный стандарт ядра Linux. |
| **kpatch (Red Hat)** | Остановка CPU (stop-the-world) | Фокус на дистрибутивы семейства RHEL. |
| **KernelCare (TuxCare)** | Бинарный патчинг | Патчит не только ядро, но и библиотеки (glibc, openssl). |

## Практические сценарии

### Использование kexec для обновления мажорной версии

Если Live Patching предназначен для мелких фиксов, то `kexec` используется для полной замены ядра без долгого ожидания инициализации сервера.

**1. Подготовка нового ядра:**
```bash
# Загрузка ядра и initramfs в память
sudo kexec -l /boot/vmlinuz-6.12-lts \
     --initrd=/boot/initramfs-6.12-lts.img \
     --reuse-cmdline
```

**2. Выполнение быстрого перехода:**
```bash
# Инициировать переход через systemd (рекомендуется)
sudo systemctl kexec
```

### Проверка примененных патчей

Информация о состоянии живых патчей доступна через интерфейс `sysfs`.

```bash
# Список загруженных патчей
ls /sys/kernel/livepatch/

# Проверка активации конкретного фикса
cat /sys/kernel/livepatch/kpatch_cve_2025_1234/enabled
# → 1
```

### Использование Live Update (ядро 6.16+)

Для сервисов, поддерживающих сохранение состояния в systemd 261+:
```bash
# Проверка поддержки сохранения FD в юните
systemctl show my-database.service -p FileDescriptorStorePreserve
# → FileDescriptorStorePreserve=yes
```
