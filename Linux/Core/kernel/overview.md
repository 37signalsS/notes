# Ядро Linux: Обзор

## Определения

**Ядро (Kernel)** — это самый низкий уровень программного обеспечения и центральный, наиболее важный компонент операционной системы. Оно выступает в роли моста между программным обеспечением и аппаратной частью компьютера.

**Основные задачи ядра:**

- **Управление процессами:** Запуск, остановка и планирование процессов. (См. [Процессы в Linux](../processes/overview.md))
- **Управление памятью:** Распределение оперативной памяти, организация виртуальной памяти. (См. [Управление памятью](../memory/caching_and_reclaiming.md))
- **Управление устройствами:** Взаимодействие с оборудованием через драйверы.
- **Обработка системных вызовов:** Предоставление программам интерфейса для запроса услуг у ядра.

## Основные концепции

### Пространство ядра и пространство пользователя (Kernelspace vs Userspace)

Для обеспечения стабильности и безопасности система разделена на два режима:

- **Пространство ядра (Kernelspace):** Здесь работает ядро, имея неограниченный доступ ко всему оборудованию. Ошибка в этом режиме приводит к панике ядра (`Kernel Panic`).
- **Пространство пользователя (Userspace):** Здесь выполняются все остальные программы. Они имеют ограниченные права и для доступа к ресурсам должны обращаться к ядру.

Подробнее см. в [Userspace и Kernelspace](../processes/overview.md#userspace-и-kernelspace).

### Модульная архитектура

Ядро Linux имеет модульную структуру. **Модули** — это фрагменты кода (драйверы, файловые системы), которые можно динамически загружать и выгружать, расширяя функциональность без перезагрузки системы. Это позволяет сохранять ядро компактным и загружать компоненты только по мере необходимости.

> Детальное руководство по управлению модулями (команды `lsmod`, `modprobe`, `insmod`) находится в заметке **[Модули ядра (kernel_modules.md)](./kernel_modules.md)**.

### "Загрязнение" ядра (Kernel Taint)

**Taint-флаг** — это механизм ядра, который указывает на то, что система находится в нестандартном или потенциально нестабильном состоянии. "Загрязненное" ядро может усложнить диагностику, и разработчики ядра часто просят воспроизвести проблему на "чистом" ядре.

Состояние флага можно проверить командой `cat /proc/sys/kernel/tainted`. `0` — ядро чистое.

**Основные причины "загрязнения":**

- `P` (Proprietary Module): Загружен проприетарный (не-GPL) модуль, например, драйвер NVIDIA.
- `F` (Forcefully Loaded): Модуль был загружен принудительно (`insmod -f`).
- `O` (Out-of-tree Module): Загружен модуль, не входящий в официальное дерево исходного кода ядра.
- `W` (Warning): Ядро ранее выдало предупреждение.
- `M` (Machine Check Error): Произошёл аппаратный сбой.

## Практические сценарии

### Проверка версии ядра

```bash
# Показать версию ядра
uname -r
```

### Расположение и структура файлов ядра

Ядро Linux хранится в директории `/boot` в файле `vmlinuz`.

- **vmlinuz**: Основной файл ядра. Буква `z` в конце означает, что ядро сжато (обычно с помощью `gzip` или `xz`). Современные ядра также могут использовать сжатие `zstd`.
- **Размер**: Сжатое ядро обычно занимает около 8-10 МБ.
- **Несколько версий**: При обновлении системы новая версия ядра добавляется, а старая сохраняется. Это позволяет загрузиться со старой версии в случае проблем с новой.

**Модули ядра** хранятся в директории `/lib/modules/$(uname -r)/`.

### Просмотр загрузочных сообщений

```bash
# Показать сообщения, выведенные ядром во время загрузки
dmesg -H
```

### Настройка параметров ядра "на лету"

Многие параметры ядра можно изменять без перезагрузки с помощью `sysctl`.

```bash
# Пример: разрешить пересылку пакетов
sudo sysctl -w net.ipv4.ip_forward=1
```

> Подробнее см. **[Настройка параметров ядра (sysctl.md)](./sysctl.md)**.
