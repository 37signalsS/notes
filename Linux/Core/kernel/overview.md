# Ядро Linux: Обзор

## Определения

**Ядро (Kernel)** — центральный и наиболее важный компонент операционной системы, работающий на самом низком уровне программного обеспечения. Оно выступает посредником между аппаратным обеспечением компьютера и прикладными программами.

**Основные задачи ядра:**

- **Управление процессами:** планирование выполнения задач, переключение контекста, запуск и завершение процессов.
- **Управление памятью:** выделение оперативной памяти, организация виртуального адресного пространства.
- **Управление устройствами:** взаимодействие с оборудованием через драйверы.
- **Обработка системных вызовов:** предоставление интерфейса (Syscall) для взаимодействия приложений с ядром.

## Основные концепции

### Пространство ядра и пространство пользователя (Kernelspace vs Userspace)

Для обеспечения безопасности и стабильности операционная система разделяет выполнение кода на два режима:

- **Пространство ядра (Kernelspace):** режим выполнения с неограниченным доступом к оборудованию и памяти (Ring 0 процессора). Ошибка в этом режиме критична и приводит к **Kernel Panic**.
- **Пространство пользователя (Userspace):** режим выполнения прикладных программ с ограниченными правами (Ring 3 процессора). Для выполнения привилегированных действий программы должны обращаться к ядру через системные вызовы.

### Архитектура и модульность

Linux является **монолитным ядром**, что означает выполнение всех основных функций (управление памятью, процессами, файловыми системами) в едином адресном пространстве. Однако архитектура является **модульной**:

- **Модули ядра:** фрагменты кода (драйверы, протоколы, файловые системы), которые можно динамически загружать и выгружать без перезагрузки системы.
- Это позволяет сохранять базовый образ ядра компактным и расширять его функциональность по мере необходимости.

Подробнее об управлении модулями: [**Модули ядра (kernel_modules.md)**](./kernel_modules.md).

### Состояние «загрязнения» ядра (Kernel Taint)

**Taint-флаг** — механизм, указывающий на то, что ядро находится в нестандартном или потенциально нестабильном состоянии. Это важно для диагностики: разработчики часто не рассматривают баг-репорты от систем с «загрязнённым» ядром.

```bash
# Проверить состояние флага (0 — ядро чистое)
cat /proc/sys/kernel/tainted
# → 0
```

**Основные причины «загрязнения»:**

- `P` (Proprietary Module): загружен несвободный (проприетарный) драйвер (например, NVIDIA).
- `F` (Forcefully Loaded): модуль был загружен принудительно (`insmod -f`).
- `O` (Out-of-tree Module): загружен модуль, не входящий в официальное дерево ядра.
- `M` (Machine Check Error): произошёл аппаратный сбой, зафиксированный процессором.

## Практические сценарии

### Проверка версии ядра

```bash
uname -r
# → 6.1.0-21-amd64
```

### Структура файлов ядра

Основные компоненты ядра хранятся в директории `/boot` и `/lib/modules/`:

- **`/boot/vmlinuz-<version>`**: сжатый исполняемый файл ядра. Буква `z` означает сжатие (обычно `gzip` или `xz`).
- **`/lib/modules/$(uname -r)/`**: директория, содержащая все загружаемые модули для текущей версии ядра.

### Просмотр логов ядра

```bash
# Вывод сообщений кольцевого буфера ядра
sudo dmesg -H
```

Метрики и параметры работы ядра в реальном времени доступны через виртуальные файловые системы:

- **`/proc`**: информация о процессах и параметрах системы. См. [**procfs**](../../FileSystems/virtual_fs_proc.md).
- **`/sys`**: информация об устройствах и драйверах. См. [**sysfs**](../../FileSystems/virtual_fs_sys.md).

### Настройка параметров runtime

Параметры ядра можно изменять без перезагрузки с помощью утилиты `sysctl`.

```bash
# Пример: разрешить пересылку пакетов
sudo sysctl -w net.ipv4.ip_forward=1
# → net.ipv4.ip_forward = 1
```

Подробнее: [**Настройка параметров ядра (sysctl.md)**](./sysctl.md).
