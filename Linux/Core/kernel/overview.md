# Ядро Linux: Обзор

## Определения

**Ядро (Kernel)** — это центральный компонент операционной системы, работающий на самом низком уровне взаимодействия с оборудованием. Оно выступает абстрактным слоем между аппаратной частью (CPU, RAM, устройства) и прикладным программным обеспечением, обеспечивая безопасное и эффективное распределение ресурсов.

**Основные функции ядра:**

- **Управление процессами:** Планирование задач (Scheduler), переключение контекста, управление жизненным циклом потоков и процессов.
- **Управление памятью:** Выделение физической и виртуальной памяти, защита областей памяти процессов (Memory Protection), управление кэшем (Page Cache).
- **Изоляция и ресурсы:** Реализация механизмов **Namespaces** (изоляция видимости) и **Cgroups** (ограничение ресурсов), являющихся фундаментом контейнеризации.
- **Управление устройствами:** Взаимодействие с оборудованием через драйверы. Поддержка горячего подключения (Hotplug).
- **Сетевой стек:** Реализация протоколов передачи данных (TCP/IP, UDP, QUIC и др.) и маршрутизации.
- **Безопасность:** Контроль доступа (DAC/MAC), фильтрация системных вызовов (Seccomp), шифрование и аудит.

## Архитектура и разработка

### Тип ядра: Монолитность и модульность

Linux является **монолитным ядром**, что означает выполнение всех ключевых компонентов (планировщик, ФС, драйверы) в едином адресном пространстве для достижения максимальной производительности. Однако оно обладает высокой степенью модульности:

- **Модули ядра (LKM):** Код, который может динамически загружаться (`insmod`/`modprobe`) и выгружаться (`rmmod`) без перезагрузки. См. [**Управление модулями ядра**](./kernel_modules.md).
- **Rust в ядре (Stable с 7.x):** Начиная с версии 6.1 начата интеграция Rust, а к версии 7.x (2026) Rust признан вторым официальным языком разработки. Это радикально снижает количество ошибок безопасности, связанных с памятью (Use-after-free, Buffer overflow) в новых драйверах.

### Цикл разработки и версии (состояние на 2026 год)

Разработка координируется Линусом Торвальдсом и поддерживается сообществом через подсистемы (Subsystems).

| Тип релиза | Версия (Пример) | Описание |
| :--- | :--- | :--- |
| **Mainline/Stable** | **7.1** | Самая свежая версия с новейшими функциями (FRED, новый NTFS). |
| **LTS (Long Term)** | **6.18** | Поддержка до конца 2028 года. Рекомендуется для Enterprise-инфраструктур. |
| **SLTS (Super LTS)** | **6.12** | Удлиненный цикл поддержки (5-10 лет) для критических систем (Debian 13, RHEL 10). |

## Пространства выполнения (Rings)

Для защиты стабильности системы выполнение кода разделено на уровни привилегий:

1.  **Пространство ядра (Kernelspace):** Работает в Ring 0 процессора. Имеет полный неограниченный доступ к памяти и оборудованию. Ошибка здесь приводит к **Kernel Panic**.
2.  **Пространство пользователя (Userspace):** Работает в Ring 3. Приложения изолированы. Для доступа к ресурсам (файлы, сеть) они обязаны использовать интерфейс **системных вызовов (Syscalls)**. См. [**Интерфейсы ядра Linux**](./kernel_interfaces.md).

## Современные механизмы и технологии

### Расширяемость и производительность

- **eBPF (Extended Berkeley Packet Filter):** «Микросервисы в ядре». Позволяет безопасно выполнять пользовательский код внутри ядра. Используется для Observability, Networking (Cilium) и Security (Tetragon). См. [**eBPF — виртуальная машина ядра**](./ebpf.md).
- **io_uring:** Интерфейс для асинхронного ввода-вывода, значительно превосходящий классический `epoll` по производительности за счет минимизации переключений контекста. См. [**io_uring**](./io_uring.md).
- **PSI (Pressure Stall Information):** Метрики «давления» на ресурсы (CPU, Memory, I/O). Позволяют точно определить, является ли ресурс узким местом. См. [**Pressure Stall Information**](./psi.md).

### Планирование и многозадачность

- **EEVDF (Earliest Eligible Virtual Deadline First):** Основной планировщик задач (пришел на смену CFS). Обеспечивает более справедливое распределение времени и предсказуемые задержки.
- **Kernel Preemption:** Возможность прерывания кода ядра более важными задачами. В ядрах 6.13+ появилась модель `PREEMPT_LAZY` для баланса между пропускной способностью и отзывчивостью. См. [**Вытесняющая многозадачность ядра**](./preemption.md).

## Состояние «загрязнения» ядра (Kernel Taint)

Механизм **Taint** указывает на факторы, которые могут влиять на стабильность и затруднять отладку:

- `P` (Proprietary): Загружен проприетарный драйвер (например, NVIDIA).
- `F` (Force): Модуль загружен принудительно (`-f`), игнорируя проверку версий.
- `O` (Out-of-tree): Модуль скомпилирован вне официального дерева исходного кода ядра.
- `E` (Unsigned): Загружен модуль без валидной цифровой подписи (критично для Secure Boot).

Проверка состояния:
```bash
cat /proc/sys/kernel/tainted
# → 0 (чистое ядро) или числовой код (>0)
```

## Практические сценарии

### Идентификация и параметры

```bash
# Текущая версия ядра
uname -r
# → 7.1.0-arch1-1

# Просмотр параметров сборки (поддержка функций)
cat /boot/config-$(uname -r) | grep CONFIG_RUST
# → CONFIG_RUST=y

# Параметры, с которыми было загружено ядро
cat /proc/cmdline
# → BOOT_IMAGE=/vmlinuz-linux root=UUID=... rw loglevel=3 quiet
```

### Структура системных файлов

- **`/boot/vmlinuz-*`**: Сжатый образ исполняемого кода ядра.
- **`/lib/modules/$(uname -r)/`**: Каталог со всеми доступными модулями (`.ko`).
- **`/proc` (procfs)** и **`/sys` (sysfs)**: Виртуальные интерфейсы для взаимодействия с ядром «на лету».

### Настройка «на лету» (sysctl)

```bash
# Просмотр всех доступных параметров настройки
sysctl -a | head -n 5

# Временное изменение (например, включение IP Forwarding)
sudo sysctl -w net.ipv4.ip_forward=1
# → net.ipv4.ip_forward = 1
```

### Диагностика через логи

Логи ядра хранятся в кольцевом буфере (ring buffer) и доступны через `dmesg`. Подробное руководство см. в [**dmesg — Просмотр сообщений ядра**](../Diagnostics/Kernel/dmesg/index.md).

```bash
# Вывод сообщений ядра с человекочитаемыми метками времени
sudo dmesg -H

# Поиск критических ошибок (Panic, Oops, Error)
sudo dmesg | grep -iE "panic|oops|error|fail"
```
