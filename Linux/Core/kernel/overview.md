# Ядро Linux: Обзор

## Определения

**Ядро (Kernel)** — это центральный компонент операционной системы, работающий на самом низком уровне взаимодействия с оборудованием. Оно выступает абстрактным слоем между аппаратной частью (CPU, RAM, устройства) и прикладным программным обеспечением, обеспечивая безопасное и эффективное распределение ресурсов.

**Основные функции ядра:**

- **Управление процессами:** Планирование задач, переключение контекста, управление жизненным циклом потоков и процессов.
- **Управление памятью:** Выделение физической и виртуальной памяти, защита областей памяти процессов друг от друга.
- **Управление устройствами:** Взаимодействие с оборудованием через драйверы (встроенные или загружаемые).
- **Сетевой стек:** Реализация протоколов передачи данных (TCP/IP и др.).
- **Безопасность и разграничение прав:** Контроль доступа к системным ресурсам через системные вызовы.

## Основные концепции

### Архитектура: Монолитность и модульность

Linux является **монолитным ядром**, что означает выполнение всех ключевых компонентов (планировщик, файловые системы, драйверы) в едином адресном пространстве для достижения максимальной производительности. Однако оно обладает высокой степенью модульности:

- **Модули ядра (LKM):** Фрагменты кода, которые могут динамически загружаться (`insmod`/`modprobe`) и выгружаться (`rmmod`) без перезагрузки системы.
- **Rust в ядре (6.1+):** Начиная с версии 6.1, ядро официально поддерживает написание драйверов и модулей на языке Rust, что повышает безопасность работы с памятью по сравнению с традиционным C.

### Пространства выполнения (Rings)

Для защиты стабильности системы выполнение кода разделено на уровни привилегий:

1.  **Пространство ядра (Kernelspace):** Работает в Ring 0 процессора. Имеет полный доступ к памяти и железу. Ошибка здесь приводит к **Kernel Panic**.
2.  **Пространство пользователя (Userspace):** Работает в Ring 3. Приложения изолированы. Для доступа к железу или файлам они обязаны использовать интерфейс **системных вызовов (Syscalls)**.

### Современные механизмы расширения

- **eBPF (Extended Berkeley Packet Filter):** Позволяет безопасно выполнять пользовательский код внутри ядра без изменения его исходного кода или загрузки модулей. Используется для глубокого мониторинга, сетевой фильтрации (Cilium) и безопасности.
- **PSI (Pressure Stall Information):** Механизм анализа «давления» на ресурсы (CPU, память, I/O), позволяющий более точно диагностировать замедления системы.

### Состояние «загрязнения» ядра (Kernel Taint)

Механизм **Taint** указывает на факторы, которые могут влиять на стабильность и затруднять отладку:

- `P` (Proprietary): Загружен закрытый драйвер (например, NVIDIA).
- `F` (Force): Модуль загружен принудительно, игнорируя проверку версий.
- `O` (Out-of-tree): Модуль скомпилирован вне основного дерева исходного кода ядра.

Проверка состояния: `cat /proc/sys/kernel/tainted` (0 — «чистое» ядро).

## Практические сценарии

### Идентификация и информация о ядре

```bash
# Текущая версия ядра
uname -r
# → 6.12.0-lts

# Просмотр параметров сборки (поддержка функций)
cat /boot/config-$(uname -r) | grep CONFIG_PSI
```

### Структура системных файлов

- **`/boot/vmlinuz-*`**: Сжатый образ ядра.
- **`/lib/modules/$(uname -r)/`**: Библиотека модулей для текущего ядра.
- **`/proc` (procfs)** и **`/sys` (sysfs)**: Виртуальные файловые системы для взаимодействия с ядром в реальном времени.

### Управление параметрами «на лету»

Для настройки поведения ядра без перезагрузки используется утилита `sysctl` или прямая запись в `/proc/sys/`.

```bash
# Просмотр всех параметров
sysctl -a

# Изменение параметра (например, включение маршрутизации)
sudo sysctl -w net.ipv4.ip_forward=1
```

### Логирование и диагностика

Логи ядра хранятся в кольцевом буфере (ring buffer) и доступны через команду `dmesg`.

```bash
# Вывод последних сообщений ядра с отметками времени
sudo dmesg -H

# Поиск критических ошибок
sudo dmesg | grep -i "panic\|error\|fail"
```
