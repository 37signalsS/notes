## Определения

**Изоляция CPU (CPU Isolation)** — это набор техник, которые позволяют зарезервировать одно или несколько ядер процессора (CPU) для выполнения только определенных, критически важных задач, и оградить их от выполнения обычных системных процессов.

## Основные концепции

### Зачем нужна изоляция CPU?

Планировщик Linux по умолчанию стремится равномерно распределять нагрузку по всем ядрам. Однако для некоторых приложений даже малейшие задержки, вызванные переключением контекста, обработкой прерываний или фоновыми задачами, неприемлемы.

**Основные сценарии использования:**
-   **Приложения реального времени (Real-time):** Где требуется гарантированное и предсказуемое время отклика.
-   **Высокопроизводительные вычисления (HPC):** Для научных или финансовых расчетов, где "шум" от ОС должен быть минимизирован.
-   **Сетевые приложения с низкой задержкой (Low-latency networking):** Например, для высокочастотного трейдинга.
-   **Виртуализация:** Выделение эксклюзивных ядер для виртуальных машин.

### Ограничения `isolcpus`

Параметр `isolcpus` имеет ограничения:
-   Не защищает ядро от обработки на нем **прерываний (IRQ)**.
-   Некоторые потоки ядра все еще могут выполняться на изолированных ядрах.

## Практические сценарии

### Методы изоляции CPU

1.  **`isolcpus`: Изоляция от планировщика**
    -   Параметр загрузки ядра Linux, который указывает планировщику задач не использовать перечисленные ядра для автоматического размещения обычных процессов. Детали о параметрах загрузки см. в [процессе загрузки](./boot_process.md).
    -   **Пример конфигурации в `/etc/default/grub`:**
        ```
        # Изолировать ядра 2 и 3 (нумерация с 0)
        GRUB_CMDLINE_LINUX_DEFAULT="quiet splash isolcpus=2,3"
        ```
    -   После изменения конфигурации необходимо обновить GRUB (`sudo update-grub`) и перезагрузить систему.
    -   Чтобы запустить критически важное приложение на изолированных ядрах, необходимо явно привязать его к ним с помощью `taskset` или `numactl`.

2.  **`nohz_full`: Защита от "тиков" таймера**
    -   Параметр загрузки ядра, который отключает системный таймер ("tick") на указанных ядрах, когда на них выполняется только один процесс. Это устраняет периодические прерывания от таймера.
    -   `GRUB_CMDLINE_LINUX_DEFAULT="... nohz_full=2,3"`

3.  **Аффинити (сродство) прерываний**
    -   Чтобы полностью изолировать CPU, необходимо перенаправить прерывания от оборудования на неизолированные ядра. Подробнее об этом механизме см. в заметке о [прерываниях](./interrupts.md).
    -   Это делается изменением маски сродства для каждого прерывания в `/proc/irq/<номер_irq>/smp_affinity`.

## Расширенные детали

### `taskset` vs `numactl`

-   **`taskset`**: Простая утилита для привязки процесса к определенным ядрам CPU.
    ```bash
    # Запустить my_app на изолированном ядре 2
    taskset -c 2 ./my_app
    ```
-   **`numactl`**: Более мощная утилита, которая управляет политиками не только для CPU, но и для памяти в системах с архитектурой **NUMA**. Позволяет привязать процесс к ядрам и памяти одного и того же NUMA-узла.
