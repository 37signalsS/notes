# Изоляция CPU

## Определения

**Изоляция CPU (CPU Isolation)** — это комплекс мер на уровне ядра Linux и системных служб, направленный на резервирование определенных вычислительных ядер исключительно для выполнения критически важных задач. Целью изоляции является минимизация «дрожания» (jitter) и задержек за счет исключения вмешательства планировщика, прерываний и фоновых функций ядра на выделенных ядрах.

В современных системах (2024–2026 гг.) подход к изоляции эволюционировал от статических параметров загрузки к динамическому управлению через **cgroup v2** и **systemd**, что позволяет гибко перераспределять ресурсы без перезагрузки ОС.

## Основные концепции

### Проблема «шума» ядра

Даже если ядро исключено из общего планировщика, оно может замедляться из-за внутренних процессов:
1.  **Конфликты планировщика:** Попытки ядра запустить на изолированном ядре системные потоки.
2.  **Тики таймера:** Периодические аппаратные прерывания для обновления системного времени и квантов планировщика.
3.  **Обратные вызовы RCU (Read-Copy-Update):** Фоновая очистка памяти ядром.
4.  **Аппаратные прерывания (IRQ):** Обработка событий от сетевых карт, дисков и других устройств.

### Методы изоляции (Legacy vs Modern)

#### Статическая изоляция (Параметры ядра)
Исторически использовался параметр `isolcpus`, который полностью вырезал ядра из планировщика. В современных ядрах он считается **устаревшим (deprecated)** в пользу cgroups, но параметры для подавления «шума» ядра все еще актуальны:
- **`nohz_full=<cpus>`**: Переводит ядра в адаптивный режим без тиков. Если на ядре запущен только один процесс, системный таймер останавливается.
- **`rcu_nocbs=<cpus>`**: Переносит обработку RCU-коллбэков на неизолированные ядра (Housekeeping CPUs).
- **`irqaffinity=<cpus>`**: Указывает, на каких ядрах по умолчанию должны обрабатываться аппаратные прерывания.

#### Динамическая изоляция (cgroup v2 Partitions)
Современный стандарт (ядра 5.15+). Позволяет пометить группу ядер как `isolated` на лету через контроллер `cpuset`. При этом ядро автоматически отключает балансировку нагрузки для этих ядер.

## Практические сценарии

### Настройка «тишины» ядра через GRUB

Для достижения минимальных задержек необходимо подготовить ядра на этапе загрузки. Оставьте ядра 0 и 1 для системы, остальные изолируйте.

```text
# Пример для 8-ядерного процессора в /etc/default/grub:
GRUB_CMDLINE_LINUX_DEFAULT="... nohz_full=2-7 rcu_nocbs=2-7 irqaffinity=0,1"
```

### Динамическая изоляция через systemd

Современный и рекомендуемый способ запуска приложений на изолированных ядрах без прямой манипуляции с файловой системой `/sys/fs/cgroup`.

```bash
# Запуск приложения на ядрах 2-3 с включением режима изоляции раздела
systemd-run --property=AllowedCPUs=2-3 \
            --property=AllowedCPUsPartition=isolated \
            --slice=workload.slice \
            --scope \
            /usr/bin/my-latency-sensitive-app
```

### Мониторинг и проверка

Для подтверждения успешной изоляции:
1.  **Проверка планировщика:** `cat /sys/fs/cgroup/machine.slice/cpuset.cpus.partition` должно возвращать `isolated`.
2.  **Визуальный контроль:** В `htop` изолированные ядра должны показывать 0% нагрузки, если на них явно не запущены задачи.
3.  **Проверка прерываний:**
    ```bash
    # Убедитесь, что на ядрах 2-7 нет высокой активности прерываний
    watch -n 1 "cat /proc/interrupts"
    ```

### Изоляция в Kubernetes

В Kubernetes изоляция реализуется через **Static CPU Manager Policy**.
- Установите `--cpu-manager-policy=static` в конфигурации Kubelet.
- Поды в классе `Guaranteed` с целым числом CPU (например, `cpu: 2`) получат эксклюзивный доступ к изолированным ядрам.
