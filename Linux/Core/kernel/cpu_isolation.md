## Определения

**Изоляция CPU (CPU Isolation)** — это набор техник, которые позволяют зарезервировать одно или несколько ядер процессора (CPU) для выполнения только определенных, критически важных задач, и оградить их от выполнения обычных системных процессов.

## Основные концепции

### Назначение изоляции CPU

Планировщик Linux по умолчанию стремится равномерно распределять нагрузку по всем ядрам. Однако для некоторых приложений критичны даже малейшие задержки, вызванные переключением контекста, обработкой прерываний или фоновыми задачами.

**Основные сценарии применения:**
*   **Приложения реального времени (Real-time):** Требуется гарантированное и предсказуемое время отклика.
*   **Высокопроизводительные вычисления (HPC):** Минимизация "шума" от ОС для научных или финансовых расчетов.
*   **Сетевые приложения с низкой задержкой (Low-latency networking):** Например, для высокочастотного трейдинга.
*   **Виртуализация:** Выделение эксклюзивных ядер для виртуальных машин.

### Ограничения `isolcpus`

Параметр `isolcpus` имеет ограничения:
*   Не защищает ядро от обработки на нем **прерываний (IRQ)**.
*   Некоторые потоки ядра все еще могут выполняться на изолированных ядрах.

## Практические сценарии

### Методы изоляции CPU

1.  **`isolcpus`: Изоляция от планировщика**
    *   Параметр загрузки ядра Linux, который указывает планировщику задач не использовать перечисленные ядра для автоматического размещения обычных процессов. Детали о параметрах загрузки см. в [процессе загрузки](Linux/Core/kernel/boot_process.md).
    *   **Пример конфигурации в `/etc/default/grub`:**
        ```
        # Изолировать ядра 2 и 3 (нумерация с 0)
        GRUB_CMDLINE_LINUX_DEFAULT="quiet splash isolcpus=2,3"
        ```
    *   После изменения конфигурации необходимо обновить GRUB (`sudo update-grub`) и перезагрузить систему.
    *   Для запуска критически важного приложения на изолированных ядрах требуется явная привязка с помощью `taskset` или `numactl`.

2.  **`nohz_full`: Защита от "тиков" таймера**
    *   Параметр загрузки ядра, отключающий системный таймер ("tick") на указанных ядрах, когда на них выполняется только один процесс. Это устраняет периодические прерывания от таймера.
    *   Пример: `GRUB_CMDLINE_LINUX_DEFAULT="... nohz_full=2,3"`

3.  **Аффинити (сродство) прерываний**
    *   Для полной изоляции CPU необходимо перенаправить прерывания от оборудования на неизолированные ядра. Подробнее об этом механизме см. в заметке о [прерываниях](Linux/Core/kernel/interrupts.md).
    *   Конфигурируется изменением маски сродства для каждого прерывания в `/proc/irq/<номер_irq>/smp_affinity`.

## Дополнительная информация

### Инструменты привязки: `taskset` и `numactl`

*   **`taskset`**: Простая утилита для привязки процесса к определенным ядрам CPU.
    ```bash
    # Запустить my_app на изолированном ядре 2
    taskset -c 2 ./my_app
    ```
*   **`numactl`**: Более мощная утилита, управляющая политиками для CPU и памяти в системах с архитектурой [NUMA](../memory/performance_tuning.md#numa-локальность-памяти). Позволяет привязать процесс к ядрам и памяти одного NUMA-узла.
