# Изоляция CPU

## Определения

**Изоляция CPU (CPU Isolation)** — набор техник на уровне ядра Linux для резервирования определённых ядер процессора исключительно для выполнения критически важных задач. Изоляция предотвращает автоматическое планирование на этих ядрах обычных процессов, выполнение фоновых задач ядра и обработку прерываний.

**`isolcpus`** — параметр командной строки ядра, указывающий планировщику (scheduler) не использовать перечисленные ядра для запуска пользовательских задач по умолчанию.

## Основные концепции

### Цели изоляции

Стандартный планировщик Linux стремится равномерно распределять нагрузку по всем ядрам CPU (Central Processing Unit). Для высокопроизводительных приложений или систем реального времени это создает проблемы:

- **Переключение контекста (Context Switch):** остановка задачи для выполнения другой.
- **Дрожание (Jitter):** непредсказуемые задержки из-за вмешательства системных задач.
- **Промахи кэша (Cache Misses):** миграция задачи на другое ядро очищает L1/L2 кэши.

### Уровни изоляции

Одного параметра `isolcpus` недостаточно для полной изоляции, так как ядро продолжает выполнять служебные функции на этих ядрах.

1. **Изоляция от планировщика (`isolcpus`):** ядра исключаются из общего пула. Процессы попадают туда только через явную привязку (CPU Affinity).
2. **Отключение прерываний таймера (`nohz_full`):** переводит ядра в режим «без тиков» (tickless), когда на ядре выполняется только один процесс. Это устраняет периодические прерывания системного таймера.
3. **Перенос обратных вызовов RCU (`rcu_nocbs`):** механизм Read-Copy-Update часто создает нагрузку на CPU для очистки памяти. Этот параметр переносит обработку RCU (Read-Copy-Update) на неизолированные ядра.
4. **Изоляция от прерываний (IRQ Affinity):** аппаратные прерывания от сетевых карт или дисков по умолчанию могут обрабатываться на любом ядре. Для полной тишины их нужно перенаправить вручную.

## Практические сценарии

### Настройка через параметры GRUB

Для применения настроек необходимо отредактировать конфигурацию загрузчика (обычно `/etc/default/grub`) и обновить его.

```bash
# Пример: изолировать ядра 2 и 3 на 4-ядерной системе
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3"

# Обновить конфигурацию GRUB (Debian/Ubuntu)
sudo update-grub
# → Generating grub configuration file ...

# После перезагрузки проверить активные параметры
cat /proc/cmdline
# → BOOT_IMAGE=/vmlinuz-... quiet splash isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3
```

### Проверка изоляции от планировщика

После применения `isolcpus` обычные процессы не должны попадать на указанные ядра.

```bash
# Показать привязку процессов к ядрам (PSR — ядро, на котором запущен поток)
ps -eLo pid,psr,comm | head -n 10
# →   PID PSR COMMAND
# →     1   0 systemd
# →     2   1 kthreadd
```

Ядра 2 и 3 должны оставаться свободными от системных процессов.

### Перенаправление прерываний (IRQ Affinity)

Даже изолированные ядра могут обрабатывать прерывания (IRQ — Interrupt Request). Для их переноса используется файловая система `/proc/irq/`.

```bash
# Посмотреть, какие прерывания обрабатываются на ядрах (пример для ядра 2)
watch -n 1 "cat /proc/interrupts"

# Перенаправить прерывание 42 на ядра 0-1 (маска 0x3 = 0011 в двоичной)
echo 3 | sudo tee /proc/irq/42/smp_affinity
# → 3
```

Подробнее об управлении прерываниями: [**Прерывания (interrupts.md)**](./interrupts.md).
