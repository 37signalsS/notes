# Прерывания в ядре Linux

## Определения

**Прерывание (Interrupt)** — сигнал от аппаратного или программного обеспечения, требующий немедленного внимания процессора. Процессор приостанавливает текущую задачу и переходит к выполнению специального кода — **обработчика прерывания (ISR — Interrupt Service Routine)**.

**IRQ (Interrupt Request)** — аппаратная линия или логический идентификатор, используемый устройствами для отправки прерываний процессору.

## Основные концепции

### Двухуровневая система обработки

В Linux используется разделение обработки на две части для минимизации времени блокировки системы.

#### Уровень 1: Аппаратные прерывания (Hard IRQ)

- **Назначение:** выполнение минимально необходимой и срочной работы (например, чтение данных из буфера сетевой карты в оперативную память).
- **Контекст:** выполняется немедленно, прерывая другие задачи. На время работы другие прерывания на том же ядре обычно маскируются (отключаются).
- **Ограничение:** длительная работа в этом контексте «парализует» ядро, так как оно перестает реагировать на внешние события.

#### Уровень 2: Отложенная обработка (SoftIRQ и Tasklets)

Механизмы для выполнения «тяжелых» задач, инициированных аппаратным прерыванием.

**1. SoftIRQ (Software Interrupt Request)**
Основной механизм отложенной обработки в ядре.

- **Принцип работы:** после завершения Hard IRQ ядро помечает соответствующий SoftIRQ для выполнения. Обработчик запускается в подходящий момент (например, при выходе из системного вызова), когда прерывания уже включены.
- **Примеры использования:** сетевой стек (обработка пакетов), планировщик задач, таймеры.

**2. Tasklets**
Механизм поверх SoftIRQ, упрощающий разработку драйверов.

- **Особенности:** тасклеты одного типа гарантированно не выполняются параллельно на разных ядрах CPU, что избавляет от необходимости сложной синхронизации.

### Немаскируемые прерывания (NMI — Non-Maskable Interrupts)

Тип прерываний, которые нельзя игнорировать или отключить на уровне процессора. Используются для критических событий (аппаратные сбои) и сторожевых таймеров (**Watchdog**) для обнаружения зависаний ядра. Подробнее см. в [**Зависания ядра**](./lockups.md).

## Практические сценарии

### Диагностика прерываний

Просмотр статистики по всем прерываниям в системе:

```bash
cat /proc/interrupts
# →            CPU0       CPU1
# →   0:         15          0   IO-APIC   2-edge      timer
# →   1:         10          0   IO-APIC   1-edge      i8042
```

Анализ нагрузки по программным прерываниям (сетевой трафик, диск):

```bash
cat /proc/softirqs
# →                    CPU0       CPU1
# →           HI:          1          0
# →        TIMER:     123456     111222
# →       NET_RX:      45678       1234
```

Высокое значение в столбце `si` (softirq) утилиты `top` или `htop` указывает на интенсивную отложенную обработку.

### Управление привязкой прерываний (IRQ Affinity)

Привязка обработки прерываний к конкретным ядрам CPU позволяет оптимизировать производительность и локальность кэша.

```bash
# 1. Найти номер IRQ (например, для сетевого интерфейса eth0)
grep eth0 /proc/interrupts | awk '{print $1}' | tr -d ':'
# → 42

# 2. Привязать IRQ 42 к ядрам 0-3 (маска 0xf = 1111 в двоичной системе)
echo f | sudo tee /proc/irq/42/smp_affinity

# 3. Или использовать список ядер (человекочитаемый формат)
echo 0-3 | sudo tee /proc/irq/42/smp_affinity_list
```

**irqbalance** — системная служба, автоматически распределяющая прерывания по ядрам. При ручной настройке ее следует отключить:

```bash
sudo systemctl stop irqbalance
```

### Threaded IRQs (Потоковые прерывания)

Механизм выполнения ISR в контексте отдельного потока ядра (`kworker`). Это позволяет планировщику управлять приоритетом обработки прерывания.

```bash
ps aux | grep irq
# → root      123  0.0  0.0      0     0 ?        S    10:00   0:00 [irq/42-eth0]
```
