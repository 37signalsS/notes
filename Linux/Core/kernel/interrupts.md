# Прерывания в ядре Linux

## Определения

**Прерывание (Interrupt)** — сигнал от аппаратного или программного обеспечения, требующий немедленного внимания процессора. При получении прерывания процессор приостанавливает выполнение текущей задачи и переходит к выполнению специального кода — **обработчика прерывания (ISR — Interrupt Service Routine)**.

**IRQ (Interrupt Request)** — аппаратная линия или логический идентификатор, по которому устройство уведомляет процессор о событии. В современных системах классические линии заменены на **MSI/MSI-X (Message Signaled Interrupts)**, где прерывание передается как запись в определенную область памяти.

## Основные концепции

### Многоуровневая обработка (Split Handling)

Для минимизации задержек и предотвращения блокировки системы ядро Linux разделяет обработку прерывания на две или три фазы.

#### 1. Аппаратная фаза (Hard IRQ / Top Half)
- **Контекст:** Прерывает выполнение текущего кода на CPU.
- **Задача:** Выполнение минимально необходимых действий (квитирование прерывания, чтение статуса устройства, постановка задачи в очередь).
- **Особенности:** На время выполнения Hard IRQ другие прерывания на данном ядре маскируются (отключаются). Длительная работа здесь приводит к потере пакетов и «заиканию» системы.

#### 2. Программная фаза (SoftIRQ / Bottom Half)
- **Контекст:** Атомарный контекст прерывания, но с включенными аппаратными прерываниями.
- **Задача:** Тяжелая обработка данных (сетевой стек, дисковый ввод-вывод, таймеры).
- **Механизмы:**
  - **SoftIRQ:** Статический набор высокопроизводительных обработчиков (NET_RX, BLOCK, TASKLET и др.).
  - **Tasklets:** Устаревший механизм (deprecated в 2024+), работающий поверх SoftIRQ. Заменяется на потоковые прерывания или Workqueues.

#### 3. Потоковая фаза (Threaded IRQs / ksoftirqd)
- **Контекст:** Поток ядра (Process Context).
- **Задача:** Обработка прерываний, когда SoftIRQ не справляется или требуется приоритизация.
- **ksoftirqd/N:** Служебный поток на каждом ядре, который берет на себя обработку SoftIRQ, если нагрузка слишком высока (превышены лимиты по времени или итерациям в прерывании).

### Современные механизмы (2024-2025)

*   **MSI-X-IMS (Interrupt Message Store):** Новое поколение MSI-X, позволяющее устройствам (GPU, NVMe, SmartNIC) создавать тысячи векторов прерываний без ограничений PCI-таблиц. Критично для виртуализации (SIOV).
*   **Threaded NAPI:** Возможность выноса обработки сетевого трафика из общего SoftIRQ в выделенные потоки для каждой очереди сетевой карты. Это позволяет планировщику (scheduler) эффективно управлять сетевой нагрузкой.
*   **PREEMPT_RT в Mainline (Ядро 6.12+):** Полное слияние патчей реального времени делает почти все прерывания потоковыми по умолчанию, что обеспечивает детерминированное время отклика.

## Практические сценарии

### Диагностика распределения нагрузки

```bash
# Общая статистика аппаратных прерываний
cat /proc/interrupts

# Статистика программных прерываний (SoftIRQ)
cat /proc/softirqs
```

Высокое значение в столбце `%si` (SoftIRQ) в утилите `top` часто указывает на сетевую перегрузку или неэффективную балансировку.

### Управление IRQ Affinity

Привязка прерываний к конкретным ядрам CPU критична для производительности высокоскоростных сетей и баз данных.

```bash
# Установка маски (ядра 0 и 1: 2^0 + 2^1 = 3)
echo 3 | sudo tee /proc/irq/<IRQ_NUMBER>/smp_affinity

# Использование списка ядер (удобнее)
echo 0-3 | sudo tee /proc/irq/<IRQ_NUMBER>/smp_affinity_list
```

**Рекомендация:** При ручной настройке affinity необходимо отключать службу `irqbalance` (`systemctl stop irqbalance`), чтобы она не сбрасывала ваши настройки.

### Включение Threaded NAPI для сети

Для изоляции сетевой нагрузки от других системных задач:

```bash
# Включить выделенные потоки обработки для интерфейса eth0
echo 1 | sudo tee /sys/class/net/eth0/threaded
```
После этого в `ps aux` появятся потоки `napi/eth0-*`, которым можно назначать приоритеты и CPU affinity.
