# Планировщики ввода-вывода (I/O Schedulers)

## Определения

**Планировщик ввода-вывода (I/O Scheduler)** — компонент блочного слоя ядра Linux, управляющий очередностью передачи запросов на накопитель. Его задача — минимизировать накладные расходы на перемещение головок (для HDD), предотвратить "голодание" процессов и обеспечить требуемый баланс между пропускной способностью (**Throughput**) и задержками (**Latency**).

**blk-mq (Multi-Queue Block I/O Layer)** — современная многоочередная архитектура ввода-вывода, заменившая старый одноочередной блочный слой. Она позволяет масштабировать ввод-вывод на многоядерных системах, устраняя глобальную блокировку очереди.

## Основные концепции

### Архитектура Multi-Queue (blk-mq)

Архитектура разделяет процесс обработки на два уровня:
1.  **Программные очереди (Software Queues):** Создаются для каждого CPU (или группы ядер). Это исключает конкуренцию за блокировки при постановке запроса в очередь.
2.  **Аппаратные очереди (Hardware Queues):** Соответствуют количеству очередей, поддерживаемых контроллером (например, NVMe). Запросы из программных очередей объединяются и направляются в аппаратные.

### Механизмы работы современных планировщиков

#### 1. none (No-op)
Полное отсутствие планирования на уровне ядра. Запросы передаются драйверу устройства мгновенно.
- **Применение:** NVMe, облачные диски (где планирование делает гипервизор), высокопроизводительные SSD. На PCIe Gen5 накопителях использование любого планировщика, кроме `none`, часто приводит к деградации скорости из-за ограничений CPU.

#### 2. mq-deadline
Адаптация классического Deadline под blk-mq.
- **Принцип:** Разделяет очереди на чтение и запись. Каждому запросу назначается крайний срок (deadline). Чтение имеет приоритет над записью для предотвращения "замерзания" приложений.
- **Тюнинг:** `/sys/block/<dev>/queue/iosched/read_expire` (мс) — максимальное время ожидания чтения.

#### 3. Kyber
Легковесный планировщик, разработанный Facebook для быстрых NVMe.
- **Принцип:** Использует систему "токенов" (разрешений) для ограничения количества активных запросов. Kyber отслеживает задержки операций и, если они превышают целевой порог, уменьшает количество доступных токенов для фоновых задач, отдавая приоритет критическим чтениям.
- **Тюнинг:** `read_lat_nsec` и `write_lat_nsec` — целевые задержки в наносекундах.

#### 4. BFQ (Budget Fair Queuing)
Основан на алгоритме WF2Q+.
- **Принцип:** Выделяет каждому процессу "бюджет" (количество секторов или время диска). Если процесс выполняет последовательное чтение, он получает больший бюджет. Это обеспечивает плавную работу системы даже при интенсивной фоновой записи (например, при копировании больших файлов).
- **Минус:** Высокие накладные расходы на CPU.

## Практические сценарии

### Настройка и мониторинг

```bash
# Просмотр активного планировщика (указан в скобках)
cat /sys/block/sda/queue/scheduler
# → [mq-deadline] kyber bfq none

# Смена планировщика на лету
echo kyber | sudo tee /sys/block/sda/queue/scheduler
```

### Автоматизация через правила udev

Для обеспечения персистентности настроек используйте файл `/etc/udev/rules.d/60-io-schedulers.rules`:

```text
# NVMe: максимальная производительность без оверхеда
ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/scheduler}="none"

# SSD (SATA): баланс задержек
ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/rotational}=="0", ATTR{queue/scheduler}="mq-deadline"

# HDD: отзывчивость интерфейса при нагрузке
ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/rotational}=="1", ATTR{queue/scheduler}="bfq"
```

Применить правила: `sudo udevadm control --reload-rules && sudo udevadm trigger`.

### Рекомендации по выбору

1.  **Базы данных (OLTP):** `none` (для NVMe) или `mq-deadline`. Использование `bfq` на быстрых дисках снизит IOPS.
2.  **Виртуализация:** Внутри ВМ всегда `none`.
3.  **Десктоп/Рабочая станция:** `bfq` для устранения подтормаживаний при записи.
