# Планировщик ввода-вывода (I/O Scheduler)

## Определения

**Планировщик ввода-вывода (I/O Scheduler)** — это компонент ядра Linux, который управляет порядком выполнения запросов на чтение и запись для блочных устройств (HDD, SSD). Его основная задача — оптимизировать дисковые операции для достижения различных целей: минимизации задержек, обеспечения справедливости между процессами или максимизации пропускной способности.

## Основные концепции

### Эволюция: от одноочередных к многоочередным

-   **Старые планировщики (Single-Queue):** Исторически работали с одной очередью запросов на всё устройство. Подходили для медленных вращающихся дисков (HDD), но стали узким местом для современных многоядерных систем и сверхбыстрых NVMe SSD.

-   **Современные планировщики (Multi-Queue Block IO, `blk-mq`):** Современные ядра Linux используют фреймворк `blk-mq`, который предоставляет несколько очередей на одно блочное устройство (обычно по одной на каждое ядро CPU). Это позволяет избежать блокировок и значительно повысить производительность на быстрых накопителях.

## Практические сценарии

### Основные типы современных планировщиков (`blk-mq`)

1.  **`none`** (ранее `noop`) / **First-Come, First-Served (FCFS)**:
    -   **Принцип работы:** Самый простой планировщик. Он просто помещает все входящие запросы в очередь FIFO (First-In, First-Out) и практически не выполняет никакой сортировки или переупорядочивания (только базовое слияние запросов). По сути, это реализация принципа FCFS.
    -   **Когда использовать:** Идеально подходит для очень быстрых устройств, которые не выигрывают от сложной логики планирования, таких как **NVMe SSD**. Также является стандартом для виртуализированных сред, где реальное планирование выполняется на уровне гипервизора.

2.  **`mq-deadline`** / **Deadline:**
    -   **Принцип работы:** Гарантирует, что ни один запрос не будет "голодать" слишком долго. Каждому запросу назначается максимальное время ожидания (дедлайн). Планировщик отдает приоритет запросам, чей дедлайн истекает, что обеспечивает предсказуемость. Это прямая реализация алгоритма Deadline.
    -   **Когда использовать:** Хороший универсальный выбор, особенно для систем с базами данных (например, PostgreSQL, MySQL) и для SATA/SAS SSD, где важны предсказуемые и низкие задержки для операций чтения.

3.  **`bfq` (Budget Fair Queueing)** / (аналог **Completely Fair Queuing - CFQ**):
    -   **Принцип работы:** Сложный планировщик, ориентированный на обеспечение справедливости и низкой задержки для интерактивных приложений. Он выделяет каждому процессу "бюджет" на количество дисковых операций и пытается обеспечить равномерное распределение пропускной способности. Является логическим преемником идей планировщика **Completely Fair Queuing (CFQ)** из более старых ядер.
    -   **Когда использовать:** Отлично подходит для десктопных систем и для смешанных нагрузок, где важна отзывчивость интерфейса. Для чисто серверных нагрузок (особенно с быстрыми SSD) может создавать излишние накладные расходы.

4.  **`kyber`**:
    -   **Принцип работы:** Относительно новый планировщик, разработанный для очень быстрых устройств (NVMe). Он пытается достичь целевых задержек для запросов (например, 2 мс для чтения), динамически подстраивая свою агрессивность и глубину очереди.
    -   **Когда использовать:** Альтернатива `none` на современных серверах с NVMe-накопителями.

### Управление планировщиком (временно)

-   **Проверить текущий планировщик для устройства `nvme0n1`:**
    ```bash
    cat /sys/block/nvme0n1/queue/scheduler
    # Вывод: [none] mq-deadline kyber bfq
    ```
    Активный планировщик указан в квадратных скобках.

-   **Изменить планировщик временно (до перезагрузки):**
    ```bash
    # Установить планировщик 'mq-deadline' для nvme0n1
    echo mq-deadline | sudo tee /sys/block/nvme0n1/queue/scheduler
    ```

## Дополнительная информация

### Постоянное изменение планировщика (с помощью [udev](../udev.md))

Чтобы изменение сохранялось после перезагрузки, можно создать правило `udev`.

1.  Создайте файл `/etc/udev/rules.d/60-io-schedulers.rules`.
2.  Добавьте в него строки для нужного типа дисков:
    ```
    # Установить mq-deadline для всех дисков NVMe
    ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/scheduler}="mq-deadline"
    
    # Установить bfq для всех дисков SATA/SAS (sd*)
    ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/scheduler}="bfq"
    ```
3.  Перезагрузите правила `udev`:
    Более подробно об управлении правилами `udev` см. в разделе [Управление правилами `udev`](../Core/udev.md#Управление-правилами-udev).
