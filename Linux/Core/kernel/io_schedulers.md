# Планировщик ввода-вывода (I/O Scheduler)

## Определения

**Планировщик ввода-вывода (I/O Scheduler)** — компонент ядра Linux, управляющий порядком выполнения запросов на чтение и запись для блочных устройств: HDD (Hard Disk Drive — жесткий диск) и SSD (Solid State Drive — твердотельный накопитель).

**Основная задача планировщика:** оптимизация дисковых операций для минимизации задержек (latency), обеспечения справедливости распределения ресурсов между процессами или максимизации пропускной способности (throughput).

## Основные концепции

### Эволюция архитектуры: blk-mq

- **Одноочередные планировщики (Single-Queue):** историческая архитектура с одной глобальной очередью запросов на всё устройство. На многоядерных системах это приводило к **lock contention** (конкуренции за блокировку), делая очередь «узким местом». Допустимо для медленных HDD, но критично для быстрых SSD.
- **Многоочередные планировщики (Multi-Queue Block IO, `blk-mq`):** современный фреймворк, разделяющий ввод-вывод на множество программных очередей (software queues) — обычно по одной на каждое ядро CPU (Central Processing Unit). Они напрямую сопоставляются с аппаратными очередями (hardware queues) накопителей.
  - **Преимущества:** линейное масштабирование IOPS (Input/Output Operations Per Second) на многоядерных серверах и минимальные задержки для NVMe (Non-Volatile Memory Express) и производительных RAID-массивов.

## Практические сценарии

### Типы современных планировщиков (`blk-mq`)

1. **`none` (ранее `noop`) / FCFS (First-Come, First-Served):**
    - **Принцип:** простейшая очередь FIFO (First-In, First-Out). Практически не выполняет сортировку, только базовое слияние запросов.
    - **Применение:** идеален для **NVMe SSD** и виртуализированных сред, где планирование выполняется на уровне гипервизора.
2. **`mq-deadline`:**
    - **Принцип:** гарантирует дедлайн (максимальное время ожидания) для каждого запроса. Отдает приоритет операциям чтения, обеспечивая предсказуемость.
    - **Применение:** универсальный выбор для баз данных (PostgreSQL, MySQL) и SATA/SAS SSD. Часто используется по умолчанию.
3. **`bfq` (Budget Fair Queueing):**
    - **Принцип:** преемник планировщика CFQ (Completely Fair Queuing). Выделяет каждому процессу «бюджет» операций для обеспечения справедливости и низкой задержки.
    - **Применение:** десктопные системы и смешанные нагрузки, где важна отзывчивость интерфейса.
4. **`kyber`:**
    - **Принцип:** разработан для сверхбыстрых NVMe. Динамически подстраивает глубину очереди для достижения целевых задержек (например, 2 мс на чтение).
    - **Применение:** альтернатива `none` для высоконагруженных NVMe-серверов.

### Управление планировщиком

**Проверка текущего состояния:**

```bash
cat /sys/block/sda/queue/scheduler
# → [mq-deadline] none bfq kyber
```

Активный планировщик выделен квадратными скобками.

**Временное изменение (до перезагрузки):**

```bash
echo bfq | sudo tee /sys/block/sda/queue/scheduler
# → bfq
```

**Постоянная настройка через правила udev:**
Создайте файл `/etc/udev/rules.d/60-io-schedulers.rules`:

```text
# NVMe — используем mq-deadline для предсказуемости
ACTION=="add|change", KERNEL=="nvme[0-9]*", ATTR{queue/scheduler}="mq-deadline"

# SATA SSD — используем bfq для отзывчивости
ACTION=="add|change", KERNEL=="sd[a-z]", ATTR{queue/scheduler}="bfq"
```

Применение правил без перезагрузки:

```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
```
