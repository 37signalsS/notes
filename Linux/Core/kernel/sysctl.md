# Настройка параметров ядра (sysctl)

## Определения

**`sysctl`** — утилита и механизм ядра Linux, предназначенные для чтения и изменения параметров ядра в режиме реального времени (runtime) без необходимости перезагрузки системы.

**`/proc/sys/`** — виртуальная файловая система, через которую ядро экспортирует свои внутренние переменные в пространство пользователя. Утилита `sysctl` служит высокоуровневым интерфейсом к этой ФС, позволяя работать с параметрами в формате иерархических имен (например, `net.ipv4.ip_forward` вместо пути к файлу `/proc/sys/net/ipv4/ip_forward`).

Тюнинг параметров ядра критически важен для оптимизации систем под специфические нагрузки: базы данных (PostgreSQL, Redis), узлы Kubernetes, высокопроизводительные сетевые шлюзы и системы защиты от DDoS.

## Основные концепции

### Иерархия параметров

Параметры сгруппированы по функциональным разделам, что отражается в их именовании:

- **`net.*`** — Сетевой стек. Управление TCP/IP, ARP, маршрутизацией, фильтрацией пакетов и дисциплинами очередей (qdisc).
- **`vm.*`** — Виртуальная память. Настройка агрессивности использования Swap (`swappiness`), лимитов на количество карт памяти (`max_map_count`) и алгоритмов очистки кэша.
- **`kernel.*`** — Общие свойства ядра. Лимиты на количество процессов (`pid_max`), безопасность eBPF, параметры планировщика и поведение при сбоях (Panic).
- **`fs.*`** — Файловые системы. Лимиты на количество открытых дескрипторов (`file-max`) и подписки `inotify`.

### Ключевые параметры для современных систем (2024-2025)

| Параметр | Описание | Рекомендуемое значение (High Load) |
| :--- | :--- | :--- |
| `net.ipv4.tcp_congestion_control` | Алгоритм управления перегрузкой TCP. | `bbr` (требует `fq`) |
| `net.core.somaxconn` | Максимальный размер очереди прослушиваемых сокетов. | `65535` |
| `kernel.unprivileged_bpf_disabled` | Запрет eBPF для не привилегированных пользователей. | `1` (Hardened) |
| `vm.swappiness` | Склонность ядра вытеснять данные из RAM в Swap. | `10` (для серверов) |
| `fs.file-max` | Системный лимит открытых файлов. | `2097152` |

## Практические сценарии

### Основные команды управления

```bash
# Вывести все текущие параметры системы
sysctl -a

# Получить значение конкретного параметра
sysctl net.ipv4.ip_forward

# Временное изменение параметра (до перезагрузки)
sudo sysctl -w net.ipv4.ip_forward=1
```

### Постоянное сохранение настроек

Для сохранения настроек после перезагрузки используются конфигурационные файлы.

- **`/etc/sysctl.conf`** — устаревший метод, используется для общих системных настроек.
- **`/etc/sysctl.d/*.conf`** — современный стандарт. Позволяет разделять настройки по назначению (например, `99-kubernetes.conf`, `10-network-tuning.conf`).

**Пример файла `/etc/sysctl.d/99-server-tuning.conf`:**
```conf
# Включение BBR (актуально для ядер 4.9+)
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# Увеличение лимитов conntrack для высоконагруженных NAT/Firewall
net.netfilter.nf_conntrack_max = 1048576

# Защита от атак через eBPF
kernel.unprivileged_bpf_disabled = 1
```

### Применение конфигурации

```bash
# Применить изменения из всех файлов конфигурации
sudo sysctl --system

# Применить изменения из конкретного файла
sudo sysctl -p /etc/sysctl.d/99-server-tuning.conf
```

### Настройка в контейнеризированных средах (Kubernetes)

В Kubernetes параметры `sysctl` делятся на **безопасные** (safe) и **небезопасные** (unsafe). Безопасные параметры (например, `net.ipv4.tcp_keepalive_time`) можно настраивать напрямую в манифесте Pod через `securityContext.sysctls`. Небезопасные требуют настройки `kubelet` (флаг `--allowed-unsafe-sysctls`) или использования `InitContainers` с правами `privileged`.
