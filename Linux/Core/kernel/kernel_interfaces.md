# Интерфейсы ядра Linux

## Определения

**Интерфейсы ядра** — совокупность механизмов, через которые прикладное программное обеспечение взаимодействует с ядром операционной системы для выполнения привилегированных операций, получения данных о состоянии системы или управления оборудованием.

**Разделение привилегий (Userspace vs Kernelspace):** в Linux выполнение кода в пространстве пользователя (Ring 3) изолировано от пространства ядра (Ring 0). Прямой доступ к оборудованию запрещен; интерфейсы ядра являются единственными санкционированными путями взаимодействия.

## Основные концепции

### Системные вызовы (System Calls)

Основной программный интерфейс. Процесс помещает номер вызова и аргументы в регистры процессора и выполняет инструкцию `syscall`, инициируя переход в режим ядра.

- **Библиотечные обертки:** разработчики обычно используют функции стандартной библиотеки C (**glibc**), которые инкапсулируют логику системных вызовов. Например, функция `open()` внутри выполняет одноименный системный вызов.
- **vDSO (virtual Dynamic Shared Object):** механизм ускорения «легких» системных вызовов (например, `gettimeofday`), позволяющий выполнять их в пространстве пользователя без дорогостоящего переключения контекста.

### Виртуальные файловые системы (VFS)

Ядро экспортирует свои структуры данных и параметры через специальные файловые системы, позволяя управлять системой через стандартные операции чтения/записи файлов.

- **procfs (`/proc`):** информация о процессах и общесистемные метрики. См. [**procfs**](../../FileSystems/virtual_fs_proc.md).
- **sysfs (`/sys`):** иерархическое представление устройств, драйверов и модулей. См. [**sysfs**](../../FileSystems/virtual_fs_sys.md).
- **debugfs (`/sys/kernel/debug`):** интерфейс для отладки и трассировки (ftrace).
- **configfs (`/sys/kernel/config`):** интерфейс для создания и настройки объектов ядра (например, мишеней iSCSI).

### Специализированные интерфейсы

- **ioctl (Input/Output Control):** универсальный интерфейс для выполнения специфических для устройств операций, которые не укладываются в стандартную модель `read/write` (например, настройка параметров сетевой карты или извлечение лотка CD-ROM).
- **netlink:** сокетный интерфейс для обмена данными между ядром и пространством пользователя. Широко используется сетевым стеком (утилита `ip`), подсистемой аудита и механизмами горячего подключения устройств (uevent).
- **io_uring:** современный интерфейс для высокопроизводительного асинхронного ввода-вывода, минимизирующий количество системных вызовов. См. [**io_uring**](./io_uring.md).

## Практические сценарии

### Анализ взаимодействия через strace

Утилита **strace** позволяет перехватывать системные вызовы в реальном времени.

```bash
# Трассировка системных вызовов открытия файлов
strace -e openat ls /tmp
# → openat(AT_FDCWD, "/tmp", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY) = 3

# Статистика системных вызовов по времени и количеству
strace -c ls
# → % time     seconds  usecs/call     calls    errors syscall
# → ------ ----------- ----------- --------- --------- ----------------
# →  25.41    0.000122           4        28           read
```

### Просмотр доступных системных вызовов

```bash
# Получить список системных вызовов текущей архитектуры
ausyscall --dump | head -n 5
# → 0 read
# → 1 write
# → 2 open
```

### Диагностика сетевого стека (Netlink)

Утилиты `ss` и `ip` используют Netlink для получения данных из ядра значительно быстрее, чем при чтении текстовых файлов из `/proc`.

```bash
# Информация о сокетах через Netlink
ss -tln
# → State      Recv-Q     Send-Q     Local Address:Port     Peer Address:Port
```

### Связанные темы

- **Безопасность:** [Seccomp](../../Security/Mechanisms/Seccomp.md) — фильтрация системных вызовов для изоляции процессов.
- **Аудит:** [Auditd](../SystemAdministration/Logging/auditd.md) — логирование системных вызовов в целях безопасности.
- **Наблюдаемость:** [eBPF](./ebpf.md) — безопасное выполнение кода в ядре через точки прикрепления к интерфейсам.
- **Настройка параметров:** [sysctl](./sysctl.md) — управление параметрами через `/proc/sys/`.
