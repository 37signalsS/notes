# Интерфейсы ядра Linux

## Определения

**Интерфейсы ядра** — это совокупность механизмов, через которые прикладное программное обеспечение (Userspace) взаимодействует с ядром (Kernelspace). Эти интерфейсы обеспечивают безопасное выполнение привилегированных операций, управление аппаратными ресурсами и получение данных о состоянии системы.

В архитектуре Linux интерфейсы являются единственным легитимным способом преодоления границы между уровнями защиты (Ring 3 и Ring 0). Они гарантируют изоляцию процессов и стабильность системы за счет строгой валидации всех входящих запросов.

## Основные концепции

### Системные вызовы (System Calls)

Основной программный API ядра. Приложение инициирует переход в режим ядра, выполняя специальную инструкцию процессора (`syscall` на x86_64).

*   **vDSO (virtual Dynamic Shared Object):** Механизм ускорения «легких» вызовов. Ядро отображает небольшую библиотеку в память процесса, позволяя выполнять такие функции, как `gettimeofday` или современный `getrandom` (ядро 6.11+), без переключения контекста процессора.
*   **Современные вызовы (2024–2026):**
    *   **`mseal()` (6.10+):** Позволяет «запечатывать» области памяти, запрещая изменение их прав доступа или удаление до конца жизни процесса (защита от эксплойтов).
    *   **`futex2` (6.16+):** Новое поколение интерфейса синхронизации с поддержкой различных размеров переменных и оптимизацией для NUMA.
    *   **`pidfd`:** Управление процессами через файловые дескрипторы, что устраняет риск ошибок при переиспользовании PID.

### Виртуальные файловые системы (VFS)

Ядро предоставляет доступ к своим внутренним структурам и настройкам через файлы, следуя принципу «все есть файл».

*   **procfs (`/proc`):** Динамическая информация о процессах и системных метриках. См. [**procfs**](../../FileSystems/virtual_fs_proc.md).
*   **sysfs (`/sys`):** Объектная модель устройств, драйверов и модулей ядра. См. [**sysfs**](../../FileSystems/virtual_fs_sys.md).
*   **debugfs / configfs:** Специализированные интерфейсы для отладки и динамической конфигурации объектов ядра.

### Специализированные интерфейсы обмена данными

*   **Netlink:** Сокетный интерфейс для двустороннего обмена сообщениями. Используется сетевым стеком (утилита `ip`), подсистемами аудита и мониторинга событий оборудования.
*   **ioctl (Input/Output Control):** Универсальный «черный ход» для управления специфическими функциями драйверов, которые не укладываются в стандартную модель чтения/записи.
*   **io_uring:** Современная высокопроизводительная среда асинхронного исполнения системных вызовов. См. [**io_uring**](./io_uring.md).

### Программируемость через eBPF

Современное ядро Linux (2025+) все чаще рассматривается как программируемая среда. Интерфейс **eBPF** позволяет динамически внедрять пользовательскую логику в точки трассировки, сетевые хуки и системные вызовы. См. [**eBPF**](./ebpf.md).

## Практические сценарии

### Анализ взаимодействия через strace

Утилита позволяет увидеть «разговор» приложения с ядром.

```bash
# Трассировка с измерением времени выполнения syscall
strace -T ls /tmp
# → openat(..., "/tmp", ...) = 3 <0.000042>

# Статистика по количеству и ошибкам вызовов
strace -c ls
```

### Просмотр доступных системных вызовов

```bash
# Список всех syscall текущей архитектуры
ausyscall --dump | head -n 5
# → 0    read
# → 1    write
# → 2    open
```

### Использование vDSO getrandom (6.11+)

Для систем с ядром 6.11+ приложения могут генерировать энтропию на порядки быстрее.
```bash
# Проверить наличие vDSO в процессе
cat /proc/self/maps | grep vdso
# → 7ffd411f1000-7ffd411f3000 r-xp 00000000 00:00 0 [vdso]
```

### Безопасность: Ограничение интерфейсов

Для минимизации поверхности атаки рекомендуется фильтровать доступные приложению интерфейсы.
*   **Seccomp:** Позволяет запретить выполнение опасных системных вызовов. См. [**Seccomp**](../../Security/Mechanisms/Seccomp.md).
*   **BPF Tokens (6.9+):** Позволяют делегировать права на использование BPF (например, в контейнерах) без предоставления полных прав `CAP_SYS_ADMIN`.
