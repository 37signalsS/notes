# Интерфейсы ядра

## Определения

**Интерфейсы ядра** — механизмы, через которые программы пользовательского пространства запрашивают привилегированные операции, получают информацию о системе или управляют поведением ядра и драйверов.

## Основные концепции

В Linux пространство пользователя (user space) и пространство ядра (kernel space) строго разделены. Прямой доступ к оборудованию или внутренним структурам ядра запрещён. Интерфейсы ядра — единственный мост между ними.

### Системные вызовы (System Calls)

Основной интерфейс для запросов к ядру. Программа загружает номер системного вызова и аргументы в регистры процессора, затем выполняет инструкцию `syscall` — процессор переходит в режим ядра, выполняет операцию и возвращает результат.

- **glibc-обёртки:** Программисты вызывают функции (`open()`, `read()`, `fork()`), а не системные вызовы напрямую. [`glibc`](../glibc_vs_musl.md) инкапсулирует логику перехода в kernel mode.
- **Примеры:** `open`, `read`, `write`, `close`, `fork`, `execve`, `brk`.
- **Просмотр списка:** `ausyscall --dump` или `/usr/include/asm/unistd_64.h`.

### procfs (`/proc`)

Виртуальная файловая система, предоставляющая информацию о процессах и состоянии ядра в виде файлов.

- **Процессы:** `/proc/<pid>/cmdline`, `/proc/<pid>/fd/`, `/proc/<pid>/status`.
- **Ядро и система:** `/proc/cpuinfo`, `/proc/meminfo`, `/proc/cmdline`, `/proc/interrupts`.
- **Параметры runtime:** `/proc/sys/` — зеркалирует `sysctl` (см. **[sysctl](./sysctl.md)**).

Подробное руководство: **[Виртуальная файловая система /proc](../../FileSystems/virtual_fs_proc.md)**.

### sysfs (`/sys`)

Виртуальная файловая система, представляющая модель устройств и драйверов ядра. Каждый объект ядра (device, driver, bus, class) отображается как директория с атрибутами в виде файлов.

- **Устройства:** `/sys/devices/`, `/sys/class/`.
- **Драйверы:** `/sys/bus/*/drivers/`.
- **Блочные устройства:** `/sys/block/<dev>/queue/` — планировщик I/O, размеры секторов.

Подробное руководство: **[Виртуальная файловая система /sys](../../FileSystems/virtual_fs_sys.md)**.

### Дополнительные интерфейсы

- **`ioctl`** — управление устройствами и файловой системой через файловые дескрипторы. Используется для операций, не укладывающихся в `read`/`write` (настройка NIC, управление терминалами).
- **`debugfs`** (`/sys/kernel/debug/`) — отладочная ФС ядра, нестабильный API. Используется для трассировки (ftrace), анализа прерываний, отладки драйверов.
- **`netlink`** — двусторонний сокетный интерфейс для обмена данными между user space и ядром (сетевые подсистемы, uevent, audit).
- **`configfs`** (`/sys/kernel/config/`) — пользовательский интерфейс для создания и конфигурирования объектов ядра (target core, USB gadget).

## Практические сценарии

### Трассировка системных вызовов

**`strace`** — перехват и отображение системных вызовов процесса:

```bash
# Все системные вызовы процесса
strace ls

# Фильтрация по типу вызова
strace -e openat,read ls

# Подсчёт времени и частоты вызовов
strace -c ls
```

Подробнее: **[Tracing and Debugging](../../Diagnostics/Troubleshooting/tracing_and_debugging.md)**.

### Диагностика через `/proc` и `/sys`

```bash
# Информация о CPU
cat /proc/cpuinfo

# Исполняемый файл процесса PID 1
readlink /proc/1/exe

# Текущий планировщик I/O
cat /sys/block/sda/queue/scheduler
```

### Управление параметрами ядра

**`sysctl`** — интерфейс для чтения и изменения параметров ядра runtime:

```bash
# Просмотр всех параметров
sysctl -a

# Изменение параметра
sudo sysctl -w net.ipv4.ip_forward=1
```

Полное руководство: **[Настройка параметров ядра (sysctl.md)](./sysctl.md)**.
