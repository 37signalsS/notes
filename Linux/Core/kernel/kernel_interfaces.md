## Определения

**Интерфейсы ядра** — это строго определенные механизмы, с помощью которых программы пользовательского пространства (user space) запрашивают у ядра выполнение привилегированных операций, получают информацию о системе или управляют поведением ядра и драйверов.

## Основные концепции

Программы в Linux разделены на два уровня: непривилегированное пространство пользователя и привилегированное пространство ядра. Прямой доступ к оборудованию или внутренним данным ядра из пользовательского пространства запрещен. Интерфейсы служат мостом между этими двумя мирами.

### Системные вызовы (System Calls)

Это основной и самый старый интерфейс ядра. Системный вызов — это процедура, с помощью которой программа запрашивает у ядра выполнение определенной операции от ее имени.

- **Как это работает:** Программа не вызывает функцию ядра напрямую. Вместо этого она загружает идентификатор системного вызова и его аргументы в регистры процессора, а затем выполняет специальную инструкцию (`syscall` или `int 0x80`), которая переводит процессор в режим ядра. Ядро выполняет операцию и возвращает результат.
- **Роль `glibc`:** Программисты редко используют системные вызовы напрямую. Стандартная библиотека C ([[../glibc_vs_musl.md|`glibc`]]) предоставляет удобные функции-обертки (например, `open()`, `read()`, `fork()`), которые инкапсулируют логику системных вызовов.
- **Примеры:** `open`, `read`, `write`, `close`, `fork`, `execve`, `brk`.

### Виртуальная файловая система /proc (procfs)

`/proc` — это [[../../FileSystems/virtual_fs_proc.md|виртуальная файловая система]], предоставляющая информацию о запущенных процессах и состоянии ядра в виде обычных файлов. Эти файлы не существуют на диске, ядро создает их "на лету" при обращении. Подробнее см. [[../../FileSystems/virtual_fs_proc.md|Виртуальная файловая система /proc (procfs)]].

### Виртуальная файловая система /sys (sysfs)

`/sys` — это [[../../FileSystems/virtual_fs_sys.md|виртуальная файловая система]], которая представляет внутреннюю модель устройств ядра Linux, ориентированную на устройства и их связи. Подробнее см. [[../../FileSystems/virtual_fs_sys.md|Виртуальная файловая система /sys (sysfs)]].

## Практические сценарии

### Наблюдение за системными вызовами с [[../../Diagnostics/Troubleshooting/tracing_and_debugging.md|`strace`]]

Утилита `strace` позволяет перехватывать и отображать системные вызовы, которые делает процесс. Это мощный инструмент для отладки.

```bash
# Показать все системные вызовы, которые делает команда 'ls'
strace ls
```

### Чтение информации из `/proc`

```bash
# Посмотреть информацию о процессоре
cat /proc/cpuinfo

# Узнать, какой исполняемый файл соответствует процессу с PID 1
readlink /proc/1/exe
```

### Управление устройством через `/sys`

```bash
# Пример: Проверить текущий планировщик для диска sda
cat /sys/block/sda/queue/scheduler

# Изменить планировщик (требуются права root)
echo "mq-deadline" | sudo tee /sys/block/sda/queue/scheduler
```

## Дополнительная информация

### `seq_file`: API для генерации виртуальных файлов

Многие файлы в `/proc` и `/sys` могут содержать большой объем данных. Для упрощения их генерации в ядре существует API **`seq_file` (sequential file)**.

**Проблема, которую решает `seq_file`:**
До его появления разработчикам приходилось вручную управлять буфером для вывода, что было сложно и приводило к ошибкам.

**Как `seq_file` решает эти проблемы:**
`seq_file` предоставляет простой итераторный механизм, который генерирует данные "на лету" небольшими порциями по мере запроса, автоматически управляя буфером и экономя память ядра. Когда вы выполняете `cat /proc/meminfo`, именно `seq_file` используется ядром для последовательного форматирования и вывода информации о памяти.
