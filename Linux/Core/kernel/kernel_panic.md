## Определения

**Kernel Panic** — это критическая, невосстановимая ошибка ядра операционной системы, при которой оно не может безопасно продолжать работу. Система останавливается для предотвращения дальнейшего повреждения данных и, как правило, выводит на экран диагностическую информацию, после чего либо "зависает", либо автоматически перезагружается. Это аналог "синего экрана смерти" (BSOD) в Windows.

## Основные концепции

### Причины Kernel Panic

-   **Аппаратные сбои:** Неисправность оперативной памяти, процессора, диска.
-   **Ошибки в ядре или драйверах:** Самая частая причина. Разыменование нулевого указателя, доступ к неверной области памяти, взаимоблокировки (deadlocks).
-   **Повреждение файловой системы:** Критические ошибки в корневой файловой системе, которые ядро не может исправить.
-   **Некорректная конфигурация:** Ошибки в параметрах загрузки ядра.

### Настройка поведения при Kernel Panic: автоматическая перезагрузка

По умолчанию после Kernel Panic система может "зависнуть", чтобы дать администратору возможность увидеть сообщение об ошибке. Однако для серверов часто предпочтительнее автоматическая перезагрузка.

Это поведение контролируется параметром ядра `kernel.panic`.

*   **`kernel.panic = 0` (по умолчанию):** Ядро будет ожидать вечно, требуется ручное вмешательство.
*   **`kernel.panic > 0`:** Ядро перезагрузится через указанное количество секунд.
*   **`kernel.panic < 0`:** Ядро немедленно перезагрузится без какой-либо задержки.

**Как настроить:**

1.  **Временно (до следующей перезагрузки):**
    Установите перезагрузку через 10 секунд после паники.
    ```bash
    sudo sysctl -w kernel.panic=10
    ```

2.  **Постоянно:**
    Чтобы настройка сохранялась после перезагрузок, создайте файл `/etc/sysctl.d/99-kernel-panic.conf`:
    ```bash
    sudo nano /etc/sysctl.d/99-kernel-panic.conf
    ```
    Добавьте в него строку:
    ```
    kernel.panic = 10
    ```
    И примените настройки:
    ```bash
    sudo sysctl -p
    ```

### `kdump`: Механизм сбора аварийных дампов

Для "посмертного" анализа причин Kernel Panic используется механизм `kdump`.

**Как это работает:**
1.  **Резервирование памяти:** При загрузке системы для `kdump` резервируется небольшой участок оперативной памяти (с помощью параметра ядра `crashkernel=...`).
2.  **Загрузка "ядра-сборщика":** В эту зарезервированную память загружается второе, минималистичное ядро Linux (`crashkernel` или "capture kernel").
3.  **Срабатывание при панике:** Когда в основном ядре происходит паника, управление передаётся ядру-сборщику.
4.  **Сохранение дампа:** Ядро-сборщик сохраняет образ (дамп) всей оперативной памяти основного ядра в файл на диске (обычно в `/var/crash/`).

Этот механизм надежен, так как ядро-сборщик работает в чистом, нетронутом паникой окружении.

## Практические сценарии

### Анализ `crash dump`

После перезагрузки системы сохранённый дамп можно проанализировать с помощью специализированных утилит.

1.  **Настройка `kdump`:** Убедитесь, что `kdump` установлен и сервис активен.
    ```bash
    # Для RHEL/CentOS
    sudo yum install kdump
    sudo systemctl enable --now kdump.service

    # Для Debian/Ubuntu
    sudo apt install linux-crashdump
    ```

2.  **Анализ дампа с помощью `crash`:**
    Утилита `crash` позволяет в интерактивном режиме исследовать состояние системы в момент сбоя.
    ```bash
    # Для анализа требуется сам дамп и отладочные символы для упавшего ядра
    sudo crash /var/crash/127.0.0.1-2025-11-29-15:30:00/vmcore /usr/lib/debug/lib/modules/`uname -r`/vmlinux
    ```
    **Основные команды в `crash`:**
    -   `bt`: Показать backtrace (стек вызовов) для процесса, вызвавшего панику.
    -   `log` или `dmesg`: Показать лог ядра из дампа.
    -   `ps`: Показать список процессов в момент сбоя.
    -   `vm`: Показать информацию о состоянии виртуальной памяти.
    -   `files`: Показать открытые файлы для процесса.

3.  **Просмотр системных логов:**
    Первичную информацию о панике часто можно найти в системных логах **предыдущей загрузки**:
    ```bash
    # Логи ядра с предпоследней загрузки
    journalctl -k -b -1
    ```
