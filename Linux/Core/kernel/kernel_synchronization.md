# Механизмы синхронизации ядра Linux

## Определения

**Состояние гонки (Race Condition)** — это проблема, которая возникает, когда результат выполнения кода зависит от непредсказуемой последовательности событий, например, от того, в каком порядке несколько потоков получат доступ к общей переменной или ресурсу.

**Синхронизация в ядре** — набор механизмов для координации доступа к общим данным в многопроцессорных и многопоточных средах, предотвращающий состояния гонки и обеспечивающий целостность данных.

## Основные концепции

### Проблема: состояния гонки

Классический пример — инкремент счетчика: если два потока одновременно читают, инкрементируют и записывают одно и то же значение, конечный результат может быть некорректным.

### Традиционные механизмы блокировок (Locks)

Блокировки — это основной способ предотвращения состояний гонки. Поток, желающий получить доступ к ресурсу, сначала "захватывает" блокировку. Если она уже занята, поток ждет ее освобождения.

* **Мьютексы (Mutexes):** Блокировки, которые могут быть захвачены только одним потоком. Если мьютекс занят, другой поток "засыпает" (переходит в состояние ожидания). Подходят для защиты данных на длительное время.
* **Спинлоки (Spinlocks):** "Активные" блокировки. Если спинлок занят, поток не засыпает, а входит в цикл активного ожидания ("крутится"), постоянно проверяя освобождение. Используются для очень коротких критических секций, особенно в контексте прерываний.
* **Семафоры:** Счётные блокировки, позволяющие ограниченному числу потоков одновременно иметь доступ к ресурсу.
* **RW-блокировки (Read-Write Locks):** Позволяют множеству потоков читать данные одновременно, но запись блокирует все остальные потоки.

## Практические сценарии

### RCU (Read-Copy-Update)

RCU является одним из самых мощных и широко используемых lock-free механизмов в ядре Linux, оптимизированным для сценариев, где чтений гораздо больше, чем записей.

**Как работает RCU:**

1. **Чтение (Read):** Читатели получают доступ к данным абсолютно без каких-либо блокировок, работая с текущей версией данных.
2. **Запись (Update):** При изменении данных, писатель:
    * Создает их копию.
    * Вносит изменения в эту копию.
    * Атомарно меняет глобальный указатель на новую версию данных.
3. **Освобождение (Grace Period):** Старая версия данных не может быть освобождена немедленно. Писатель ждет "период благодати" — интервал, за который все читатели, начавшие работу до обновления указателя, гарантированно завершат свои операции. Только после этого старая копия данных безопасно удаляется.

**Когда использовать RCU:**

* Каталоги файловых систем (частое чтение, редкая запись)
* Таблицы маршрутизации
* Списки процессов и задач

## Дополнительная информация

### Проблемы блокировок

* **Снижение производительности:** Накладные расходы на постоянные блокировки и разблокировки.
* **Инверсия приоритетов:** Высокоприоритетная задача может простаивать, ожидая низкоприоритетную.
* **Deadlocks (взаимоблокировки):** Два или более потока могут бесконечно ожидать друг друга.
* **Convoying:** Медленный поток задерживает все последующие.

### Lock-free / Lockless программирование

**Lockless programming** — это подход к написанию кода, который избегает использования традиционных блокировок. Вместо блокировки потока используются другие механизмы, которые не останавливают выполнение.

* **Атомарные операции:** Операции (например, инкремент, сравнение с обменом), которые выполняются процессором как единое, неделимое действие, гарантируя, что никакая другая операция не может вмешаться.
* **Барьеры памяти (Memory Barriers):** Инструкции, которые говорят компилятору и процессору не переупорядочивать операции с памятью, обеспечивая правильный порядок видимости изменений другими ядрами CPU.
