# Механизмы синхронизации в ядре Linux

## Определения

**Состояние гонки (Race Condition)** — ситуация в многопоточной среде, при которой результат выполнения кода зависит от непредсказуемого порядка доступа потоков к общим данным.

**Синхронизация в ядре** — совокупность программных механизмов для координации доступа к разделяемым ресурсам. Она необходима для предотвращения повреждения структур данных в многопроцессорных (SMP — Symmetric Multiprocessing) системах и при обработке прерываний.

## Основные концепции

### Проблема параллелизма

В ядре Linux несколько потоков могут одновременно обращаться к одним и тем же данным: например, два процесса на разных ядрах CPU (Central Processing Unit) или основной код ядра и обработчик прерывания. Без синхронизации это приводит к потере целостности данных, утечкам памяти и критическим сбоям (**Kernel Panic**).

### Типы механизмов блокировки

| Механизм | Поведение при занятости ресурса | Область применения |
| :--- | :--- | :--- |
| **Мьютекс (Mutex)** | Поток засыпает (sleep), освобождая CPU | Длительные операции, процессный контекст |
| **Спинлок (Spinlock)** | Активное ожидание (busy-wait) в цикле | Короткие секции, контекст прерываний |
| **Семафор (Semaphore)** | Счётный ограничитель доступа | Пулы ресурсов (например, доступ к драйверу) |
| **RW-блокировка (Read-Write Lock)** | Разделение на читателей и писателей | Структуры с частым чтением |

### RCU (Read-Copy-Update)

Современный масштабируемый механизм синхронизации, позволяющий читать данные вообще без блокировок, даже во время их обновления.

**Принцип работы:**

1. **Чтение (Read):** читатели обращаются к данным через указатель без задержек.
2. **Обновление (Update):** писатель копирует структуру, вносит изменения и атомарно подменяет старый указатель на новый.
3. **Период ожидания (Grace Period):** старая копия данных удаляется только тогда, когда все читатели, начавшие работу до обновления, гарантированно завершили доступ.

**Применение:** таблицы маршрутизации, списки процессов, кэши файловых систем.

### Трудности синхронизации

- **Deadlocks (взаимоблокировки):** ситуация, когда два или более потока бесконечно ждут ресурсы, захваченные друг другом.
- **Инверсия приоритетов:** высокоприоритетная задача не может выполняться, так как ждёт ресурс, занятый низкоприоритетной задачей.
- **Накладные расходы (Overhead):** время, затрачиваемое на захват и освобождение блокировок, снижает общую производительность.

## Практические сценарии

### Выбор инструмента синхронизации

| Сценарий | Рекомендуемое решение |
| :--- | :--- |
| Защита данных в контексте процесса (может засыпать) | `mutex` |
| Защита данных в обработчике прерывания (нельзя засыпать) | `spinlock` |
| Очень частые чтения и редкие изменения | `RCU` |
| Неделимое изменение счетчика или флага | Атомарные операции (`atomic_t`) |

### Диагностика проблем синхронизации

При возникновении взаимоблокировок или слишком долгих ожиданий ядро может генерировать сообщения в системный лог.

```bash
# Поиск сообщений о зависших задачах или блокировках
dmesg | grep -iE "lockup|hung|deadlock"
# → [ 123.456] watchdog: BUG: soft lockup - CPU#1 stuck for 22s!

# Просмотр стека вызовов конкретного зависшего процесса (PID 1234)
sudo cat /proc/1234/stack
# → [<0>] __mutex_lock.isra.0+0x2d0/0x4a0
# → [<0>] ...
```

Подробнее о диагностике зависаний: [**Зависания ядра**](./lockups.md).
