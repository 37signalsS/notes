# Механизмы синхронизации ядра Linux

## Определения

**Состояние гонки (Race Condition)** — проблема, при которой результат выполнения кода зависит от непредсказуемой последовательности событий (порядка доступа потоков к общим данным).

**Синхронизация в ядре** — набор механизмов для координации доступа к общим данным в многопроцессорных и многопоточных средах, предотвращающий состояния гонки и обеспечивающий целостность данных.

## Основные концепции

### Проблема: состояния гонки

Классический пример — инкремент счётчика: если два потока одновременно читают, инкрементируют и записывают значение, результат будет некорректным. В ядре гонки приводят к повреждению структур данных, утечкам памяти и паникам.

### Традиционные блокировки

| Механизм | Поведение при занятости | Область применения |
| :--- | :--- | :--- |
| **Мьютекс (Mutex)** | Поток засыпает | Длительные критические секции, процессный контекст |
| **Спинлок (Spinlock)** | Активное ожидание (busy-wait) | Короткие секции, контекст прерываний |
| **Семафор** | Счётный, ограничивает число одновременных доступов | Пулы ресурсов |
| **RW-блокировка** | Множественные читатели / один писатель | Read-heavy структуры данных |

### RCU (Read-Copy-Update)

Lock-free механизм для сценариев с преобладанием чтений над записями.

**Принцип работы:**

1. **Read:** Читатели работают с данными без блокировок.
2. **Update:** Писатель создаёт копию данных, вносит изменения, атомарно подменяет указатель.
3. **Grace Period:** Старая версия удаляется после завершения всех читателей, начавших работу до подмены.

**Применение:** каталоги ФС, таблицы маршрутизации, списки процессов.

### Lock-free программирование

Подход, избегающий традиционных блокировок:

- **Атомарные операции:** Неделимые действия (inc, cmpxchg), выполняемые процессором как единая операция.
- **Барьеры памяти (Memory Barriers):** Запрещают переупорядочивание операций с памятью компилятором/CPU, обеспечивая корректную видимость изменений между ядрами.

### Проблемы блокировок

- **Накладные расходы:** Захват/освобождение блокировок замедляет выполнение.
- **Инверсия приоритетов:** Высокоприоритетная задача ждёт низкоприоритетную.
- **Deadlocks (взаимоблокировки):** Два потока бесконечно ждут друг друга.
- **Convoying:** Медленный поток задерживает очередь ожидающих.

## Практические сценарии

### Выбор механизма синхронизации

| Сценарий | Рекомендуемый механизм |
| :--- | :--- |
| Долгая защита данных (процессный контекст) | `mutex` |
| Короткая критическая секция, контекст прерываний | `spinlock` |
| Частое чтение, редкая запись | `rwlock` или `RCU` |
| Read-mostly данные (таблицы, списки) | `RCU` |
| Пул идентичных ресурсов | `semaphore` |

### Диагностика deadlock'ов

```bash
# Проверка зависших задач (soft/hard lockup)
dmesg | grep -i 'lockup\|hung task'

# Просмотр стека вызовов зависшего процесса
cat /proc/<pid>/stack

# Информация о мьютексах и блокировках (debug-ядро)
cat /sys/kernel/debug/mutex
```
