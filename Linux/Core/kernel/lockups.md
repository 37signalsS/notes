# Зависания ядра: Soft Lockup и Hard Lockup

## Определения

**Lockup (зависание)** — состояние ядра, при котором один или несколько CPU перестают отвечать на запросы планировщика или системы в течение длительного времени.

**Soft Lockup** — ядро «зацикливается» в контексте ядра на одном CPU и не возвращает управление планировщику. Прерывания (interrupts) при этом продолжают обрабатываться.

**Hard Lockup** — CPU полностью перестаёт реагировать на любые события, включая обычные прерывания. Обычно вызван бесконечным циклом с отключёнными локальными прерываниями.

## Основные концепции

### Механизм Watchdog

Для обнаружения зависаний ядро использует сторожевые таймеры (Watchdog):

| Тип | Механизм | Обнаружение |
| :--- | :--- | :--- |
| **Soft Lockup** | Поток `watchdog/N` на каждом CPU | Метка времени не обновляется дольше `kernel.watchdog_thresh` |
| **Hard Lockup** | NMI (Non-Maskable Interrupts) | Счётчик прерываний CPU не инкрементируется |

### Причины возникновения

- **Ошибки в драйверах:** бесконечные циклы, слишком длинные критические секции.
- **Взаимоблокировки (Deadlocks):** две или более задачи бесконечно ждут ресурсы друг друга.
- **Аппаратные сбои:** неисправность CPU, памяти, перегрев.
- **Interrupt storm:** экстремальная нагрузка на прерывания, имитирующая зависание.

## Практические сценарии

### Диагностика через системные журналы

При обнаружении зависания ядро выводит stack trace в `dmesg`. Пример сообщения:
`watchdog: BUG: soft lockup - CPU#1 stuck for 22s! [myservice:1234]`

```bash
# Поиск зависаний в текущей сессии
dmesg | grep -i lockup
# → [ 123.456] watchdog: BUG: soft lockup - CPU#1 stuck for 22s!

# Поиск в логах предыдущей загрузки
journalctl -k -b -1 | grep -i lockup
```

### Настройка параметров через sysctl

Управление поведением Watchdog осуществляется через [**sysctl**](./sysctl.md):

| Параметр | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `kernel.watchdog_thresh` | Порог обнаружения (секунды) | `10` (soft lockup = `watchdog_thresh × 2`) |
| `kernel.softlockup_panic` | Паника при soft lockup (`0`/`1`) | `0` |
| `kernel.nmi_watchdog` | Включение NMI watchdog (`0`/`1`) | `1` |
| `kernel.hardlockup_panic` | Паника при hard lockup (`0`/`1`) | `0` |

```bash
# Установить порог обнаружения 5 секунд
sudo sysctl -w kernel.watchdog_thresh=5
# → kernel.watchdog_thresh = 5

# Включить Kernel Panic при обнаружении soft lockup
sudo sysctl -w kernel.softlockup_panic=1
# → kernel.softlockup_panic = 1
```

Для сохранения настроек после перезагрузки используйте файлы в `/etc/sysctl.d/`.

### Инструменты глубокой диагностики

- **`perf`:** профилирование CPU для выявления «горячих» функций ядра:

  ```bash
  perf record -a -g -- sleep 10
  perf report
  ```

- **`ftrace`:** трассировка цепочек вызовов функций ядра в реальном времени.
- **`crash`:** анализ дампов памяти (vmcore) после паники ядра.
