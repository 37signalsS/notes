# Chroot — смена корневого каталога

## Определения

**Chroot (change root)** — системный вызов и утилита в Linux/Unix, позволяющая запустить процесс, для которого корневым каталогом `/` будет являться произвольно заданная директория. Процесс, запущенный внутри такого окружения (называемого «chroot jail» или «chroot-тюрьма»), не может получить доступ к файлам за пределами этого «корня» штатными средствами.

**История:**
Механизм появился в 1979 году в Version 7 Unix. Это старейшая технология изоляции в Linux, ставшая концептуальным фундаментом для современных контейнеров.

## Основные концепции

### Механизм работы

При вызове `chroot(2)` ядро изменяет указатель на корневой каталог в дескрипторе процесса (`task_struct`). Все последующие операции поиска пути (path lookup), начинающиеся с `/`, будут ограничены новым поддеревом файловой системы.

### Уровень изоляции

Важно понимать, что chroot обеспечивает изоляцию **только на уровне файловой системы**. Все остальные ресурсы остаются общими с основной системой:
- **Сеть:** общие интерфейсы и IP-адреса.
- **Процессы:** видны все процессы хоста (если смонтирован `/proc`).
- **Пользователи:** общая база UID/GID.
- **Память:** механизмы IPC (Shared Memory, Semaphores) не изолированы.

Для полной изоляции ресурсов используются **[Namespaces (Пространства имён)](./namespaces.md)**.

### Сравнение: chroot vs pivot_root

В современной контейнеризации (Docker, LXC) вместо `chroot` используется более мощный вызов `pivot_root`.

| Характеристика | chroot | pivot_root |
| :--- | :--- | :--- |
| **Область действия** | Текущий процесс и потомки. | Весь Mount Namespace. |
| **Безопасность** | Возможность «побега» для root. | Позволяет полностью отмонтировать старый корень. |
| **Требования** | Любая директория. | Новая директория должна быть точкой монтирования. |
| **Применение** | Восстановление системы, сборка ПО. | Рантаймы контейнеров (runc). |

### Безопасность и механизм «побега» (Escape)

**Chroot не является инструментом безопасности.** Root-пользователь внутри «тюрьмы» может выйти в реальный корень системы.

**Техническая детализация Double Chroot Escape:**
Метод основан на том, что вызов `chroot()` изменяет корень системы, но **не изменяет текущую рабочую директорию (CWD)** процесса, если она находится вне нового корня.
1. Процесс открывает дескриптор текущего каталога (внутри тюрьмы).
2. Создает временную поддиректорию и делает в нее `chroot`. Теперь «настоящий» корень процесса находится глубоко внутри тюрьмы.
3. Однако CWD процесса всё еще указывает на старое местоположение, которое теперь находится *выше* нового корня.
4. Процесс выполняет `chdir("..")` многократно. Поскольку CWD находится вне лимитов нового корня, проверки безопасности игнорируются, позволяя подняться до реального корня хоста.

## Практические сценарии

### 1. Создание минимального окружения (ldd-метод)

Для запуска программы в chroot необходимо скопировать саму программу и все библиотеки, от которых она зависит.

```bash
# 1. Создание структуры
mkdir -p /opt/mini-chroot/{bin,lib,lib64}

# 2. Копирование bash и его зависимостей
cp /bin/bash /opt/mini-chroot/bin/
# ldd показывает пути к .so файлам
ldd /bin/bash | grep -o '/lib.*\.[0-9]*' | xargs -I {} cp {} /opt/mini-chroot{}

# 3. Вход
sudo chroot /opt/mini-chroot /bin/bash
```

### 2. Изоляция через unshare (современный подход)

Использование `chroot` совместно с Namespaces позволяет создать гораздо более изолированную среду без влияния на хост.

```bash
# Создание нового Mount Namespace, User Namespace (маппинг в root)
# и выполнение chroot в одной команде
unshare --mount --user --map-root-user --root /opt/chroot-env /bin/sh
```
*Преимущество: можно монтировать псевдо-ФС внутри, не засоряя таблицу монтирования хоста.*

### 3. Монтирование ресурсов для полноценной работы

Если в chroot нужно выполнять сложные задачи (установка пакетов, компиляция), необходимо пробросить интерфейсы ядра.

```bash
# Монтирование псевдо-ФС
for dir in dev dev/pts proc sys run; do
    sudo mount --bind /$dir /opt/chroot-env/$dir
done

# Вход
sudo chroot /opt/chroot-env /bin/bash

# Очистка после работы (размонтирование в обратном порядке)
# Важно: если не размонтировать, удаление директории chroot может повредить хост!
```

### 4. Восстановление системы (Rescue)

Типичный сценарий при поломке загрузчика (GRUB) или потере пароля.
1. Загрузка с Live-USB.
2. Монтирование диска системы в `/mnt`.
3. Монтирование `/dev`, `/proc`, `/sys` (как в примере выше).
4. `chroot /mnt` и запуск команд восстановления (`grub-install`, `passwd`).

## Области применения

- **Восстановление системы:** переустановка загрузчика, восстановление initramfs.
- **Чистая сборка ПО:** использование `pbuilder`, `mock` или `debootstrap` для исключения влияния библиотек хоста на процесс компиляции.
- **Legacy-сервисы:** запуск старых приложений со специфичными версиями системных библиотек.
- **Безопасность демонов:** запуск сервисов (например, DNS или FTP) в chroot для ограничения доступа взломщика к ФС хоста.
