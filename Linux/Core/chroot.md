# Chroot — смена корневого каталога

## Определения

**Chroot (change root)** — системный вызов и одноимённая утилита в Unix-подобных системах, позволяющая запустить процесс с подменённым корневым каталогом `/`. Процесс, запущенный внутри такого окружения (называемого «chroot jail» или «chroot-тюрьма»), видит указанную директорию как корень файловой системы и не может получить доступ к файлам за её пределами.

**История:**
Механизм появился в 1979 году в Version 7 Unix. Это старейший и базовый способ изоляции в Linux — прямой предок современных технологий контейнеризации.

## Основные концепции

### Механизм работы

1. Ядро меняет для процесса значение корневого каталога на указанную директорию.
2. Процесс и все его дочерние процессы воспринимают эту директорию как `/`.
3. Поиск файлов по абсолютным путям начинается с этого нового корня.
4. Доступ к файлам выше нового корня становится невозможным штатными средствами.

### Уровень изоляции

Chroot обеспечивает изоляцию **только на уровне файловой системы**. Все остальные системные ресурсы остаются общими с хостом:

- **Процессы:** видны все процессы в системе (через `/proc`, если он смонтирован).
- **Сеть:** общий сетевой стек и интерфейсы.
- **Пользователи:** общая база UID/GID.
- **Межпроцессное взаимодействие (IPC):** не изолировано.

### Ограничения и безопасность

**Chroot — это не песочница (sandbox)** в современном понимании безопасности.

- **Побег (Escape):** root-процесс внутри chroot может выйти из него. Классический способ: создать внутри chroot еще одну директорию, сделать в нее `chroot`, а затем `cd ..` несколько раз до реального корня.
- **Уязвимости:** если внутри chroot есть доступ к устройствам (`/dev`) или системным вызовам, позволяющим монтировать ФС, изоляция может быть нарушена.

Для полноценной изоляции в Linux используются **[Namespaces — пространства имён](./namespaces.md)** и **[Cgroups — контрольные группы](./cgroups.md)**.

### Синтаксис и параметры

```bash
chroot [параметры] КАТАЛОГ [КОМАНДА [АРГУМЕНТЫ]]
```

Если команда не указана, запускается оболочка по умолчанию (из переменной `${SHELL}` или `/bin/sh`).

**Основные параметры:**

- `--userspec=USER:GROUP` — запустить команду от имени указанного пользователя и группы.
- `--groups=G_LIST` — задать список дополнительных групп (через запятую).
- `--skip-chdir` — не переходить в `/` после смены корня (остаться в текущей директории, если она внутри нового корня).

## Практические сценарии

### 1. Создание минимального окружения

Для работы bash внутри chroot необходимо скопировать исполняемый файл и все его зависимости (библиотеки).

```bash
# 1. Создание структуры директорий
mkdir -p /mnt/user/{bin,lib,lib64}

# 2. Копирование bash
cp /bin/bash /mnt/user/bin/

# 3. Копирование зависимостей (библиотеки)
# ldd показывает, какие .so файлы нужны bash
ldd /bin/bash | grep -o '/lib.*\.[0-9]*' | xargs -I {} cp {} /mnt/user{}

# 4. Запуск chroot
sudo chroot /mnt/user /bin/bash
```

Внутри этого окружения будет доступен только `bash`. Утилиты `ls`, `cat`, `mkdir` будут недоступны, пока их файлы и библиотеки не будут скопированы аналогично.

### 2. Восстановление системы и смена пароля

Используется при загрузке с LiveCD для обслуживания установленной системы.

```bash
# 1. Монтирование корневого раздела системы
mount /dev/sda1 /mnt

# 2. Монтирование системных директорий для работы инструментов
for i in /dev /dev/pts /proc /sys /run; do mount -B $i /mnt$i; done

# 3. Вход в систему через chroot
chroot /mnt /bin/bash

# 4. Выполнение необходимых операций (смена пароля, обновление GRUB)
passwd root
```

Подробнее: [Восстановление пароля в Linux](../SystemAdministration/linux_password_recovery.md).

### 3. Области применения

- **Восстановление системы:** переустановка загрузчика, сброс паролей, восстановление initramfs.
- **Сборка пакетов:** создание чистых окружений для компиляции ПО (например, debootstrap для Debian/Ubuntu).
- **Тестирование:** проверка скриптов установки в изолированной системе.
- **Legacy ПО:** запуск приложений, требующих старых версий библиотек.
- **Ограничение сервисов:** работа демонов (bind9, vsftpd) в chroot-окружении для минимизации ущерба при взломе.
