# Chroot — смена корневого каталога

## Определения

**Chroot (change root)** — системный вызов и одноимённая утилита в Unix-подобных системах, позволяющая запустить процесс с подменённым корневым каталогом `/`. Процесс, запущенный внутри такого окружения (называемого «chroot jail» или «chroot-тюрьма»), видит указанную директорию как корень файловой системы и не может получить доступ к файлам за её пределами.

**История:**
Механизм появился в 1979 году в Version 7 Unix. Это старейший и базовый способ изоляции в Linux — прямой предок современных технологий контейнеризации.

## Основные концепции

### Механизм работы

1. Ядро меняет для процесса значение корневого каталога на указанную директорию.
2. Процесс и все его дочерние процессы воспринимают эту директорию как `/`.
3. Поиск файлов по абсолютным путям начинается с этого нового корня.
4. Доступ к файлам выше нового корня становится невозможным штатными средствами.

### Уровень изоляции

Chroot обеспечивает изоляцию **только на уровне файловой системы**. Все остальные системные ресурсы остаются общими с хостом:

- **Процессы:** видны все процессы в системе (через `/proc`, если он смонтирован).
- **Сеть:** общий сетевой стек и интерфейсы.
- **Пользователи:** общая база UID/GID.
- **Межпроцессное взаимодействие (IPC):** не изолировано.

### Ограничения и безопасность

**Chroot — это не песочница (sandbox)** в современном понимании безопасности.

- **Побег (Escape):** root-процесс внутри chroot может выйти из него. Классический способ: создать внутри chroot еще одну директорию, сделать в нее `chroot`, а затем `cd ..` несколько раз до реального корня.
- **Уязвимости:** если внутри chroot есть доступ к устройствам (`/dev`) или системным вызовам, позволяющим монтировать ФС, изоляция может быть нарушена.

Для полноценной изоляции в Linux используются **[Namespaces — пространства имён](./namespaces.md)** и **[Cgroups — контрольные группы](./cgroups.md)**.

### Синтаксис и параметры

```bash
chroot [параметры] КАТАЛОГ [КОМАНДА [АРГУМЕНТЫ]]
```

Если команда не указана, запускается оболочка по умолчанию (из переменной `${SHELL}` или `/bin/sh`).

**Основные параметры:**

- `--userspec=USER:GROUP` — запустить команду от имени указанного пользователя и группы.
- `--groups=G_LIST` — задать список дополнительных групп (через запятую).
- `--skip-chdir` — не переходить в `/` после смены корня (остаться в текущей директории, если она внутри нового корня).

## Практические сценарии

### 1. Создание минимального окружения (вручную)

Самый быстрый способ создать изолированную среду для одной команды. Необходимо скопировать исполняемый файл и все его зависимости (библиотеки).

```bash
# 1. Создание структуры директорий
mkdir -p /opt/mini-chroot/{bin,lib,lib64}

# 2. Копирование bash
cp /bin/bash /opt/mini-chroot/bin/

# 3. Копирование зависимостей (библиотеки)
# ldd показывает, какие .so файлы нужны bash
ldd /bin/bash | grep -o '/lib.*\.[0-9]*' | xargs -I {} cp {} /opt/mini-chroot{}

# 4. Запуск chroot
sudo chroot /opt/mini-chroot /bin/bash
```

Внутри этого окружения будет доступен только `bash`. Утилиты `ls`, `cat`, `mkdir` будут недоступны, пока их файлы и библиотеки не будут скопированы аналогично.

### 2. Создание полноценного окружения (debootstrap)

Используется для тестирования пакетов или скриптов в чистой системе без развертывания контейнера. На Debian/Ubuntu утилита `debootstrap` разворачивает минимальный `rootfs`.

```bash
# Установка утилиты
sudo apt install debootstrap

# Развертывание минимального окружения (например, Debian Bookworm)
# Занимает несколько минут, создает полноценную иерархию директорий
sudo debootstrap --arch=amd64 bookworm /opt/chroot-env http://deb.debian.org/debian/
```

### 3. Монтирование псевдофайловых систем

Без монтирования системных ресурсов многие команды (например, `apt`, `ps`, `lsblk`) внутри `chroot` не будут работать корректно.

```bash
# Монтирование необходимых интерфейсов ядра
sudo mount -t proc proc /opt/chroot-env/proc
sudo mount -t sysfs sysfs /opt/chroot-env/sys
sudo mount --bind /dev /opt/chroot-env/dev
sudo mount --bind /dev/pts /opt/chroot-env/dev/pts

# Вход в окружение
sudo chroot /opt/chroot-env /bin/bash
```

Теперь `/` указывает на `/opt/chroot-env`. Можно устанавливать пакеты и тестировать конфигурации, не затрагивая хостовую систему.

### 4. Очистка окружения

После завершения работы необходимо корректно размонтировать ресурсы и удалить директорию.

```bash
# Выход из chroot (команда exit внутри сессии)

# Размонтирование (в обратном порядке)
sudo umount /opt/chroot-env/dev/pts
sudo umount /opt/chroot-env/dev
sudo umount /opt/chroot-env/sys
sudo umount /opt/chroot-env/proc

# Удаление файлов (если окружение больше не нужно)
sudo rm -rf /opt/chroot-env
```

### 5. Типичные сценарии использования

#### Восстановление системы (Rescue Mode)
Позволяет починить сломанный загрузчик (GRUB), пересобрать `initramfs` или сбросить пароль `root`, если система не загружается.
- Загрузиться с Live-USB.
- Монтировать раздел с основной ОС в `/mnt`.
- Выполнить монтирование псевдо-ФС и `chroot /mnt`.
- Работать в системе как в «живой».

#### Тестирование установки ПО
Проверка установки пакетов и их зависимостей в «чистом» окружении. Это гарантирует, что в скриптах установки нет скрытых зависимостей от пакетов, которые случайно оказались на хостовой машине.
- Позволяет проверить поведение скриптов `post-inst` без риска повредить хост.

## Области применения

- **Восстановление системы:** переустановка загрузчика, сброс паролей, восстановление initramfs.
- **Сборка пакетов:** создание чистых окружений для компиляции ПО (например, debootstrap для Debian/Ubuntu).
- **Тестирование:** проверка скриптов установки в изолированной системе.
- **Legacy ПО:** запуск приложений, требующих старых версий библиотек.
- **Ограничение сервисов:** работа демонов (bind9, [vsftpd](../Networking/Services/ftp/vsftpd_setup.md)) в chroot-окружении для минимизации ущерба при взломе.
