# CPU Pinning (Привязка к CPU)

## Определения

**CPU Pinning** (привязка к процессорным ядрам) — это механизм, который назначает процесс или поток для исполнения на определенном ядре (или наборе ядер) CPU. Это гарантирует, что операционная система не будет перемещать процесс между ядрами, что позволяет избежать накладных расходов, связанных с миграцией.

## Основные концепции

Основная цель CPU Pinning — **повышение предсказуемости производительности и снижение задержек**.

* **Улучшение использования кэша CPU**: Когда процесс постоянно выполняется на одном ядре, вероятность того, что его данные останутся в кэше этого ядра (L1/L2), значительно возрастает. Это устраняет задержки, связанные с промахами кэша, которые возникают при миграции процесса на другое ядро.
* **Устранение накладных расходов на переключение контекста**: Миграция процесса между ядрами заставляет планировщик ОС выполнять дополнительную работу и сбрасывать кэши, что вносит задержки.
* **Изоляция рабочих нагрузок**: Позволяет изолировать критически важные процессы от других задач, работающих в системе. Это предотвращает "борьбу" за ресурсы CPU и обеспечивает стабильную производительность для чувствительных к задержкам приложений.
* **Оптимизация для NUMA-архитектур**: В системах с неоднородным доступом к памяти (NUMA) привязка процесса к ядрам, расположенным на том же NUMA-узле, что и используемая им память, минимизирует задержки доступа к памяти.

В Linux привязка CPU реализуется несколькими способами:

* **Утилита `taskset`**: Простой инструмент командной строки для запуска процесса на указанных ядрах или изменения привязки уже запущенного процесса.
* **`cpuset` (cgroups)**: Более мощный механизм, являющийся частью Control Groups v1. Он позволяет ограничивать доступ процессов не только к ядрам CPU, но и к узлам памяти (NUMA nodes). Активно используется в системах контейнеризации, таких как Docker и Kubernetes.
* **Системный вызов `sched_setaffinity()`**: Программный интерфейс, позволяющий приложению самостоятельно управлять своей привязкой к ядрам.

## Практические сценарии

* **Виртуализация и контейнеризация**: Привязка виртуальных машин или контейнеров к физическим ядрам для гарантии производительности (например, `cpuset` в Kubernetes и Docker).
* **Высокопроизводительные вычисления (HPC)**: Для научных и финансовых расчетов, где важна минимальная задержка и стабильность вычислений.
* **Системы реального времени**: Для обеспечения предсказуемого времени отклика в промышленных и телекоммуникационных системах.
* **Базы данных и сетевые приложения**: Для обработки транзакций или сетевого трафика с высокой скоростью и низкими задержками.

**Пример с `taskset`**:

Запустить процесс `my_app` на ядре №2:

```bash
taskset -c 2 ./my_app
```

Изменить привязку для уже запущенного процесса с PID 1234, ограничив его ядрами 0 и 3:

```bash
taskset -pc 0,3 1234
```

## Дополнительная информация

Для более строгой изоляции на уровне ядра ОС используется механизм [изоляции CPU (`isolcpus`)](./kernel/cpu_isolation.md), который полностью убирает определенные ядра из-под управления планировщика задач общего назначения.
