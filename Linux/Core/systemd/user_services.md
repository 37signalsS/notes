# Пользовательские службы systemd

## Определения

Пользовательские службы `systemd` — это службы, которые запускаются и управляются от имени отдельного пользователя, а не от имени `root` для всей системы. Этот режим работы `systemd` называется "пользовательским режимом" (`systemd --user`). Экземпляр `systemd` в пользовательском режиме автоматически запускается при первом входе пользователя в систему и завершается после окончания последней сессии пользователя.

## Базовые концепции

### Преимущества

- **Безопасность**: Службы работают с правами пользователя, а не `root`, что соответствует принципу наименьших привилегий.
- **Изоляция**: Пользовательские службы изолированы от системных и от служб других пользователей.
- **Удобство**: Пользователю не нужны права `sudo` для управления своими службами.
- **Автозапуск**: Можно легко настроить запуск приложений при входе в систему (например, для запуска `syncthing`, кастомных скриптов, и т.д.).

## Расположение пользовательских юнит-файлов

- `~/.config/systemd/user/`: Основная директория для пользовательских юнитов. Имеет наивысший приоритет.
- `/etc/systemd/user/`: Для системных администраторов, чтобы предоставить юниты всем пользователям.
- `~/.local/share/systemd/user/`: Для юнитов, установленных локально (например, через `pip install --user`).
- `/usr/lib/systemd/user/`: Юниты, поставляемые с системными пакетами.

## Управление пользовательскими службами

```bash
# Запустить пользовательскую службу
systemctl --user start my_app.service

# Остановить службу
systemctl --user stop my_app.service

# Проверить статус
systemctl --user status my_app.service

# Включить автозапуск службы при входе пользователя в систему
systemctl --user enable my_app.service

# Отключить автозапуск
systemctl --user disable my_app.service

# Показать все пользовательские юниты
systemctl --user list-units
```

## Практические сценарии

### Пример: юнит для простого веб-сервера

1.  Создайте файл `~/.config/systemd/user/my_web_server.service`:

    ```ini
    [Unit]
    Description=My Personal Python Web Server

    [Service]
    # Укажите полный путь к исполняемому файлу
    ExecStart=/usr/bin/python3 -m http.server 8000 --directory %h/public_html
    Restart=always

    [Install]
    WantedBy=default.target
    ```
    - `%h` в `ExecStart` автоматически заменяется на домашнюю директорию пользователя.

2.  Перечитайте конфигурацию `systemd`:
    ```bash
    systemctl --user daemon-reload
    ```

3.  Включите и запустите службу:
    ```bash
    systemctl --user enable --now my_web_server.service
    ```

## Дополнительная информация

### Режим "linger"

По умолчанию пользовательский экземпляр `systemd` и его службы активны только тогда, когда пользователь вошел в систему (имеет активную сессию). Если вам нужно, чтобы службы пользователя (например, веб-сервер или бот) продолжали работать даже после его выхода из системы, необходимо включить для этого пользователя режим "linger".

```bash
# Включить linger для пользователя 'q'
sudo loginctl enable-linger q

# Отключить linger
sudo loginctl disable-linger q

# Проверить статус linger
loginctl show-user q | grep Linger
```
