# Управление службами (systemctl)

## Определения

- **Служба (Service):** В контексте `systemd` — это процесс или группа процессов, управляемых системой инициализации. Каждая служба определяется в конфигурационном файле, называемом **юнит-файлом** (например, `nginx.service`).
- **`systemctl`:** Основная утилита командной строки для взаимодействия с `systemd`. Она позволяет инспектировать и контролировать состояние системы и служб.

## Базовые концепции

### Управление состоянием службы

- **Запустить, остановить или перезапустить службу:**

    ```bash
    sudo systemctl start nginx.service
    sudo systemctl stop nginx.service
    sudo systemctl restart nginx.service
    ```

- **Перечитать конфигурацию без полного перезапуска:** Этот метод работает, только если служба его поддерживает.

    ```bash
    sudo systemctl reload nginx.service
    ```

- **Проверить статус службы:** Показывает, активна ли служба, ее PID, последние логи и иерархию cgroup.

    ```bash
    systemctl status nginx.service
    # 'Active (running)' — запущена; 'Inactive (dead)' — остановлена.
    ```

### Разница между `reload` и `restart`

- **`reload`**: "Вежливо" просит службу перечитать свой конфигурационный файл без прерывания работы. Существующие соединения не разрываются. Этот метод работает, только если служба его поддерживает.
- **`restart`**: "Жестко" останавливает все процессы службы и запускает их заново. Это всегда работает, но приводит к кратковременному простою.

### Управление автозапуском

- **Включить автозапуск службы при загрузке системы:**
    (создает символическую ссылку в `.wants/` каталоге нужного таргета)

    ```bash
    sudo systemctl enable nginx.service
    ```

- **Отключить автозапуск (удаляет симлинк):**

    ```bash
    sudo systemctl disable nginx.service
    ```

- **Проверить, включен ли автозапуск:**

    ```bash
    systemctl is-enabled nginx.service
    # Возможные статусы: enabled, disabled, static, masked
    ```

    *Статус `static` означает, что юнит не имеет секции `[Install]` и обычно запускается как зависимость другого юнита.*

### Обновление конфигурации systemd

После внесения изменений в юнит-файлы на диске, необходимо сообщить `systemd` о необходимости перечитать конфигурацию.

```bash
sudo systemctl daemon-reload
```

### Маскировка служб

Маскировка — это "абсолютный запрет" на запуск службы. Она создает символическую ссылку из юнита на `/dev/null`, что делает невозможным его запуск вручную или как зависимость. Это полезно для предотвращения конфликтов (например, между `NetworkManager` и `systemd-networkd`).

```bash
# Полностью запретить запуск службы
sudo systemctl mask NetworkManager.service

# Отменить маскировку
sudo systemctl unmask NetworkManager.service
```

## Практические сценарии

### Анализ состояния и зависимостей

```bash
# Показать все активные юниты
systemctl list-units

# Показать все установленные юнит-файлы и их статус автозагрузки
systemctl list-unit-files --type=service

# Показать юниты, от которых зависит служба (прямые зависимости)
systemctl list-dependencies nginx.service

# Показать юниты, которые зависят от этой службы (обратные зависимости)
systemctl list-dependencies --reverse nginx.service

# Показать все юниты, которые не смогли запуститься
systemctl --failed
```

### Редактирование и переопределение юнитов

Для изменения поведения службы без модификации оригинальных файлов используется `systemctl edit`.

- **Постоянные правки (`systemctl edit`):**
    Создает файл-дополнение (override) в `/etc/systemd/system/nginx.service.d/override.conf`, директивы, указанные в этом файле, будут иметь приоритет над оригинальным юнитом.

    ```bash
    sudo systemctl edit nginx.service
    ```

    **Пример: изменение команды запуска**

    ```ini
    [Service]
    # Сначала необходимо сбросить существующую директиву
    ExecStart=
    # А затем указать новую
    ExecStart=/usr/sbin/nginx -g 'daemon off; master_process on;'
    ```

    *При переопределении директив, которые могут встречаться несколько раз (например, `ExecStart`), сначала нужно сбросить их пустым значением (`ExecStart=`), а затем указать новое.*

- **Временные правки (до перезагрузки):**
    Флаг `--runtime` создает override-файл в `/run/systemd/system/`, который очищается при перезагрузке.

    ```bash
    systemctl edit --runtime my-service.service
    ```

- **Проверка, откат и валидация:**

    ```bash
    # Показать итоговый конфиг со всеми дополнениями
    systemctl cat my-service.service

    # Удалить override-файлы и вернуть юнит к состоянию по умолчанию
    systemctl revert my-service.service

    # Проверить синтаксис юнит-файла перед применением
    systemd-analyze verify /etc/systemd/system/my-custom.service
    ```

### Безопасный перезапуск в Production

- **"Мягкий" перезапуск:** Перезапускает сервис, только если он уже запущен.

    ```bash
    sudo systemctl try-restart my-service.service
    ```

- **Перечитать конфигурацию самого systemd:** Более "глубокая" операция, чем `daemon-reload`.

    ```bash
    sudo systemctl daemon-reexec
    ```

Для сервисов, использующих **socket activation**, перезапуск происходит без потерь запросов, так как сокет продолжает их слушать, пока сервис перезагружается.

## Дополнительная информация

### Логирование

- **Просмотр логов (`journalctl`):**
    `systemd` включает подсистему логирования `journald`. Для просмотра логов используется утилита `journalctl`.
    Подробное описание `journalctl` находится в основной заметке: **[systemd-journald: Современная система логирования](../../SystemAdministration/Logging/journald.md)**.

- **`logrotate` и службы `systemd`:**
    Многие приложения пишут текстовые логи, которые ротируются с помощью `logrotate`. `systemd` используется для отправки сигнала `reload` службе после ротации, чтобы она корректно переоткрыла лог-файл.

    Пример из `logrotate` для Nginx:

    ```
    /var/log/nginx/*.log {
        ...
        postrotate
            # Старый метод через PID-файл
            [ -f /var/run/nginx.pid ] && kill -USR1 `cat /var/run/nginx.pid`
            # Современный метод через systemd
            # systemctl reload nginx.service
        endscript
    }
    ```
