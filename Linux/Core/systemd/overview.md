# Systemd: Управление системой и службами

`systemd` — это современный менеджер системы и служб для Linux, который стал стандартом для большинства дистрибутивов. Он пришел на смену более ранним системам инициализации, таким как `SystemV` (`SysVinit`), и отвечает за инициализацию системы после загрузки ядра, а также за управление службами (демонами), сокетами, точками монтирования и другими системными ресурсами.

## Архитектура

-   **`systemd` (PID 1)**: Главный демон, который запускается ядром и управляет всеми остальными процессами в системе.
-   **`systemctl`**: Основной инструмент командной строки для взаимодействия с `systemd`. Отправляет команды демону через шину **D-Bus**.
-   **`journald`**: Демон, отвечающий за сбор и хранение логов в структурированном бинарном формате. Подробнее в [заметке о journald](../../SystemAdministration/Logging/journald.md).
-   **`udev`**: Управляет файлами устройств в `/dev` и обрабатывает события подключения/отключения оборудования.
-   **`networkd`, `timedated`, `logind`**: Специализированные демоны для управления сетью, временем и пользовательскими сессиями.

### Системы инициализации: SystemD vs SystemV (SysVinit)

#### SystemV и уровни выполнения (Runlevels)

**SystemV (SysVinit)** — это классическая система инициализации в Unix-подобных системах. Ее ключевая концепция — **уровни выполнения (run levels)**.

Уровень выполнения — это состояние системы, определяющее, какие службы и демоны должны быть запущены. Администратор может переключать систему между уровнями с помощью команды `init` или `telinit`.

**Стандартные уровни выполнения:**
*   **0 (`runlevel0.target`)**: Выключение системы.
*   **1 (`runlevel1.target`, `rescue.target`)**: Однопользовательский режим для восстановления. Запускается минимальный набор служб, доступен только `root`.
*   **2 (`runlevel2.target`)**: Многопользовательский режим без поддержки сети (в некоторых дистрибутивах, например, Debian, это стандартный многопользовательский режим с сетью).
*   **3 (`runlevel3.target`, `multi-user.target`)**: Стандартный многопользовательский режим с поддержкой сети (текстовая консоль).
*   **4 (`runlevel4.target`)**: Не используется, зарезервирован для пользовательских нужд.
*   **5 (`runlevel5.target`, `graphical.target`)**: Многопользовательский режим с графическим интерфейсом (GUI).
*   **6 (`runlevel6.target`, `reboot.target`)**: Перезагрузка системы.

#### Systemd и таргеты (Targets)

**Systemd** — это современная система инициализации, которая заменила `SysVinit`. Вместо уровней выполнения `systemd` использует концепцию **таргетов (targets)**.

Таргет — это точка синхронизации, которая объединяет группу юнитов (служб, сокетов, и т.д.). Таргеты могут наследоваться друг от друга. Например, `graphical.target` включает в себя все юниты из `multi-user.target` и добавляет к ним службы для графического интерфейса.

`systemd` обеспечивает обратную совместимость, сопоставляя старые уровни выполнения с новыми таргетами (указаны в скобках выше).

#### Ключевые преимущества Systemd над SysVinit

*   **Параллельный запуск служб:** `systemd` анализирует зависимости и запускает службы параллельно, что значительно ускоряет загрузку системы по сравнению с последовательным запуском в `init`.
*   **Декларативные unit-файлы:** Вместо сложных и хрупких shell-скриптов используются простые `.ini`-подобные файлы (`юниты`) для описания служб.
*   **Интегрированное управление логами:** `journald` централизованно собирает логи всех служб, что упрощает отладку. Не нужно анализировать множество разных лог-файлов.
*   **Автоматический перезапуск служб:** Встроенная возможность автоматически перезапускать "упавшие" сервисы.
*   **Простота конфигурации:** Единый и понятный синтаксис для управления службами, таймерами, точками монтирования и т.д.
*   **Богатый функционал:** `systemd` — это не просто система инициализации, а целый набор инструментов для управления системой, включая управление сессиями пользователей, сетевыми настройками, системным временем и многим другим.

## Диагностика и практические советы

### Как определить, что systemd используется в системе?

Существует несколько способов проверить, является ли `systemd` основной системой инициализации.

1.  **Проверка процесса с PID 1:**
    `systemd` работает как процесс с PID 1. Можно проверить, на какой исполняемый файл указывает `/proc/1/exe`:
    ```bash
    stat /proc/1/exe
    ```
    Если в выводе будет `File: /proc/1/exe -> /lib/systemd/systemd`, то системой управляет `systemd`.

2.  **Проверка файла `/sbin/init`:**
    В системах с `systemd` `/sbin/init` является символической ссылкой на исполняемый файл `systemd`.
    ```bash
    stat /sbin/init
    # или
    ls -l /sbin/init
    ```
    Вывод должен показать, что `/sbin/init` ссылается на `systemd` (например, `'/sbin/init' -> '../lib/systemd/systemd'`).

3.  **Наличие каталога `/run/systemd/system`:**
    Наличие этого каталога является надежным признаком того, что `systemd` активен в системе.
    ```bash
    ls /run/systemd/system
    ```
