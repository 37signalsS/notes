# systemd: Управление системой и службами

## Определения

* **`systemd`**: Современный менеджер системы и служб для Linux, ставший стандартом для большинства дистрибутивов. Он отвечает за инициализацию системы после загрузки ядра и управление жизненным циклом служб, сокетов, точек монтирования и других системных ресурсов.
* **`SysVinit (System V Initialization)`**: Классическая система инициализации в Unix-подобных системах, являющаяся предшественником `systemd`. Основана на последовательном запуске shell-скриптов.
* **`Upstart`**: Событийно-ориентированная (event-driven) система инициализации, разработанная Canonical (для Ubuntu). Использовалась как промежуточный этап между SysVinit и `systemd`.
* **Таргеты (Targets)**: Группы юнитов в `systemd`, представляющие определенное состояние системы или точку синхронизации. Являются современной заменой уровней выполнения (runlevels). Подробное соответствие описано в [Юниты, таргеты и зависимости](./systemd_units_overview.md).
* **Архитектура `systemd`**:
  * **`systemd` (PID 1)**: Главный демон (Process ID 1), который запускается ядром первым и управляет всеми остальными процессами.
  * **`systemctl`**: Основная утилита командной строки для управления `systemd` через системную шину сообщений **D-Bus (Desktop Bus)**.
  * **`journald`**: Демон, отвечающий за сбор и хранение логов в структурированном бинарном формате. См. [Journald: Централизованный сбор логов](../../SystemAdministration/Logging/journald.md).
* **`udev`**: Подсистема, управляющая файлами устройств в `/dev` и обрабатывающая события оборудования (hotplug). Генерирует **device-юниты**, позволяя службам реагировать на появление устройств. См. [Udev: динамическое управление устройствами](../udev.md).
* **Специализированные демоны**: `networkd` (сеть), `timedated` (время), `logind` (сессии пользователей), `resolved` (разрешение имен DNS (Domain Name System)).

## Основные концепции

### systemd против SysVinit (System V Initialization)

`systemd` кардинально меняет подход к инициализации, заменяя линейный запуск скриптов на параллельную активацию через **таргеты**. Это обеспечивает обратную совместимость, прозрачно сопоставляя старые runlevels с новыми целевыми состояниями.

### Ключевые преимущества systemd

* **Параллельный запуск**: Ускоряет загрузку за счет одновременного старта служб, чьи зависимости это позволяют.
* **Socket-based activation**: Служба запускается только при поступлении первого запроса на сетевой сокет, что экономит до 20–30% RAM (Random Access Memory).
* **Декларативные юниты**: Использование конфигурационных файлов в формате `.ini` вместо сложных скриптов упрощает поддержку.
* **Автоматический перезапуск**: Встроенный механизм восстановления упавших сервисов без участия администратора.
* **Управление ресурсами**: Интеграция с контрольными группами ядра для жесткого ограничения лимитов.

### Типы юнитов systemd

Менеджер `systemd` управляет различными типами системных ресурсов через юниты (службы, сокеты, таймеры и др.). Полный перечень типов юнитов, их назначение и ключевые параметры приведены в отдельном руководстве:

* **[Обзор юнитов systemd: типы и описание](./systemd_units_overview.md)**

### Управление ресурсами: Control Groups (cgroups)

`systemd` использует механизм [cgroups (Control Groups)](../cgroups.md) для изоляции процессов и установки лимитов на CPU (Central Processing Unit), память и I/O (Input/Output).

**Ключевые возможности:**

* Ограничение потребления ресурсов.
* Приоритезация важных служб над фоновыми.
* Групповое завершение всех процессов службы (предотвращение "зомби").
* Использование cgroups v2 для единой иерархии управления.

## Практические сценарии

### Как определить использование systemd в системе?

1. **Проверка процесса PID (Process ID) 1**:

    ```bash
    stat /proc/1/exe
    ```

   # → File: /proc/1/exe -> /lib/systemd/systemd

2. **Проверка симлинка `/sbin/init`**:

    ```bash
    ls -l /sbin/init
    ```

   # → lrwxrwxrwx 1 root root 20 Oct 18 12:00 /sbin/init -> ../lib/systemd/systemd

3. **Наличие активного runtime-каталога**:

    ```bash
    ls -d /run/systemd/system
    ```

   # → /run/systemd/system

### Визуализация иерархии процессов (systemd-cgls)

Утилита `systemd-cgls` отображает дерево контрольных групп, показывая, какие именно процессы запущены в рамках конкретной службы или контейнера.

```bash
systemd-cgls
```

# → Control group /

# → ├─system.slice

# → │ ├─nginx.service

# → │ │ ├─1184 nginx: master process

# → │ │ └─1185 nginx: worker process

# →

### Мониторинг ресурсов (systemd-cgtop)

Интерактивный инструмент для анализа потребления CPU и памяти в разрезе юнитов.

```bash
systemd-cgtop
```

# → Control Group                            Tasks   %CPU   Memory  Input/s Output/s

# → /                                          452    1.2     2.4G        -        -

# → /system.slice/nginx.service                  2    0.5    45.2M        -        -

### Лучшие практики

* **Безопасность**: Используйте `sandbox`-опции (`PrivateTmp=yes`, `ProtectSystem=full`) и запускайте службы от непривилегированных пользователей (`User=`).
* **Диагностика**: Перед применением новых юнитов всегда проверяйте их командой `systemd-analyze verify`.
* **Управление**: Используйте `systemctl edit` для создания переопределений (drop-ins), чтобы не модифицировать оригинальные файлы пакетов.
