# systemd: Обзор системы и менеджера служб

## Определения

* **`systemd`** — современный менеджер системы и служб для Linux, являющийся стандартом де-факто для большинства дистрибутивов. Он отвечает за инициализацию системы после загрузки ядра и управление жизненным циклом ресурсов через юниты (службы, сокеты, точки монтирования).
* **Менеджер процессов (PID 1)** — первый процесс, запускаемый ядром. Он управляет всеми остальными процессами, обеспечивая параллелизацию и контроль зависимостей.
* **Таргеты** — группы юнитов, представляющие состояние системы (например, многопользовательский режим или графическая оболочка). Являются заменой старых уровней выполнения (runlevels).
* **Шины сообщений (D-Bus и Varlink)** — механизмы межпроцессного взаимодействия, через которые `systemctl` и другие утилиты общаются с основным демоном `systemd`.
* **Архитектурные компоненты**:
    * **`journald`** — сбор и хранение логов в бинарном формате.
    * **`logind`** — управление сессиями пользователей и местами (seats).
    * **`resolved`** — сетевое разрешение имен с поддержкой DNSSEC и LLMNR.
    * **`networkd`** — сетевая конфигурация на основе декларативных файлов.
    * **`udev`** — управление устройствами и событиями оборудования.
* **Новые компоненты (v250+)**:
    * **`run0`** — современная замена `sudo`, работающая через API менеджера служб без использования SUID-битов.
    * **`systemd-oomd`** — демон мониторинга нехватки памяти (OOM), работающий на основе PSI (Pressure Stall Information).
    * **`systemd-homed`** — управление переносимыми домашними каталогами в виде зашифрованных LUKS-контейнеров.
    * **`systemd-repart`** — декларативное перераспределение разделов диска при первой загрузке или обновлении образа.

## Основные концепции

### Эволюция инициализации: systemd против SysVinit

`systemd` заменяет последовательный запуск громоздких shell-скриптов на параллельную активацию юнитов. Это не только ускоряет загрузку, но и делает состояние системы предсказуемым за счет строгого контроля зависимостей.

### Ключевые механизмы и преимущества

* **Socket-based activation** — «ленивый» запуск служб. `systemd` создает сокет сразу, а соответствующую службу запускает только при поступлении первого пакета. Это экономит RAM и позволяет запускать зависимые службы одновременно.
* **Декларативность** — конфигурация описывается в `.ini`-подобных файлах, что исключает ошибки логики, характерные для скриптов инициализации.
* **Интеграция с cgroup v2** — полная изоляция и иерархическое управление ресурсами (CPU, Memory, I/O). В современных версиях cgroup v1 считается устаревшим.
* **Soft-Reboot** — возможность перезапустить всё пользовательское пространство без перезагрузки ядра Linux, что критично для быстрых обновлений в облачных средах.
* **Image-Based Computing** — поддержка неизменяемых образов ОС через расширения сисетмы (`sysext`) и конфигурации (`confext`).

## Практические сценарии

### Идентификация системы инициализации

```bash
# Проверка процесса PID 1
stat /proc/1/exe
# → File: /proc/1/exe -> /lib/systemd/systemd

# Проверка активного рантайма
ls -d /run/systemd/system
# → /run/systemd/system
```

### Диагностика процесса загрузки

`systemd` предоставляет мощные инструменты для поиска узких мест при старте системы.

```bash
# Показать общее время загрузки (ядро + пользователи)
systemd-analyze
# → Startup finished in 2.5s (kernel) + 10.2s (userspace) = 12.7s

# Вывести цепочку юнитов, замедляющих старт
systemd-analyze critical-chain
# → multi-user.target @10.2s
# → └─docker.service @8.1s +2.1s

# Проверка синтаксиса всех загруженных юнитов
systemd-analyze verify
```

### Мониторинг иерархии ресурсов

```bash
# Просмотр дерева контрольных групп (процессы внутри служб)
systemd-cgls

# Интерактивный мониторинг потребления ресурсов юнитами
systemd-cgtop
```

### Рекомендации по эксплуатации

* **Безопасность**: Используйте песочницу для служб (`ProtectSystem=strict`, `PrivateDevices=yes`).
* **Модификация**: Всегда используйте `systemctl edit <unit>`, чтобы создавать drop-in файлы в `/etc`, не затрагивая оригинальные файлы в `/usr/lib`.
* **Автоматизация**: Для временных задач используйте `systemd-run`.
