# systemd-run: Запуск временных юнитов

## Определения

* **`systemd-run`** — это системная утилита для динамического запуска программ в изолированных временных сервисах (services) или контекстах управления (scopes). Она позволяет использовать все возможности systemd (ограничение ресурсов, изоляция, логирование) без создания постоянных конфигурационных файлов юнитов.
* **Временный юнит (Transient Unit)** — объект управления systemd, который создается «на лету» и автоматически удаляется после завершения процесса или перезагрузки системы.

## Основные концепции

### Режимы работы

| Режим | Флаг | Описание | Применение |
| :--- | :--- | :--- | :--- |
| **Service** | (по умолчанию) | Создаёт временный юнит `.service`. Процесс запускается асинхронно как дочерний процесс PID 1. | Фоновые задачи, отложенный старт, расписания. |
| **Scope** | `--scope` | Подключает текущий процесс и его потомков к новому контексту управления (scope-юниту). | Наложение ограничений на команды в текущей сессии shell. |

### Интерактивный режим

Современные версии `systemd-run` позволяют запускать интерактивные оболочки внутри контекста юнита, что удобно для отладки окружения.
* **`--shell` (`-S`)** — запускает интерактивную оболочку пользователя. Эквивалентно набору флагов `--pty --same-dir --wait --collect`.
* **`--pty` (`-t`)** — выделяет псевдо-терминал для взаимодействия с процессом.

### Ключевые параметры запуска

* **`--user`** — запуск юнита в контексте пользовательского менеджера systemd (не требует прав root для многих задач).
* **`-p`, `--property=`** — установка любой директивы из секций `[Service]`, `[Timer]` или `[Resource Control]` (например, `MemoryMax=512M`).
* **`--unit=`** — назначение уникального имени юниту (по умолчанию генерируется случайное `run-r*.service`).
* **`--working-directory=` (`-d`)** — установка рабочей директории (поддерживает `~` для домашних папок).
* **`--on-calendar=`** — превращает запуск в временный таймер по расписанию.

## Практические сценарии

### Ограничение ресурсов для сборки проекта

Использование `--scope` для мгновенного ограничения ресурсов `cgroups` без прерывания текущей сессии.

```bash
systemd-run --scope -p CPUQuota=30% -p MemoryMax=2G make build
# → Running scope as unit: run-rb1c2d3e4f5.scope
```
# → Процесс make будет ограничен 30% CPU и 2 ГБ RAM

### Запуск интерактивной оболочки с изоляцией

Создание безопасного окружения для тестирования «грязных» скриптов.

```bash
systemd-run --shell \
  -p PrivateTmp=yes \
  -p ProtectSystem=strict \
  -p CapabilityBoundingSet=""
# → Running as unit: run-r12345.service
# → (открывается новый shell с изолированной ФС и без привилегий)
```

### Создание временного таймера (расписания)

Запуск задачи очистки раз в сутки без создания файлов в `/etc/systemd/system/`.

```bash
systemd-run --on-calendar="daily" --unit=daily-cleanup /usr/local/bin/cleanup.sh
# → Running timer as unit: daily-cleanup.timer
# → Will run service as unit: daily-cleanup.service
```

### Запуск процесса от имени другого пользователя

Полезно для проверки прав доступа без переключения через `su`/`sudo`.

```bash
sudo systemd-run -p User=www-data --working-directory=~ --shell
# → Running as unit: run-r67890.service
# → (открывается shell от пользователя www-data в его домашней папке)
```

## Диагностика и управление

```bash
# Список всех временных юнитов
systemctl list-units "run-r*"

# Просмотр логов временной задачи
journalctl -u cleanup-task.service -f
# → Jun 10 10:00:00 host cleanup.sh[123]: Task started...

# Удаление (остановка) временного таймера
systemctl stop daily-cleanup.timer
```

## Дополнительная информация

### Сравнение с обычным запуском

| Характеристика | Прямой запуск (`./app`) | `systemd-run` |
| :--- | :--- | :--- |
| **Логирование** | Вывод в терминал | Централизованно в `journald` |
| **Ресурсы** | Лимиты `ulimit` (базово) | Полный контроль `cgroups` (I/O, CPU, RAM) |
| **Изоляция** | Нет (видит весь хост) | Настраиваемый Sandbox (Namespaces) |
| **Выживание** | Зависит от родителя | Независимо от сессии (если не `--scope`) |
