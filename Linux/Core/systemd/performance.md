# Анализ производительности загрузки с systemd-analyze

`systemd-analyze` — это мощный инструмент для анализа производительности процесса загрузки системы. Он помогает выявить "узкие места", определить, какие службы замедляют запуск, и визуализировать цепочку зависимостей.

## Основные команды

### Общее время загрузки
Команда без аргументов показывает общее время, затраченное на загрузку ядра и пространства пользователя (`userspace`).
```bash
# Показать общее время загрузки (ядро + userspace)
systemd-analyze
```
Пример вывода:
`Startup finished in 3.295s (kernel) + 12.185s (userspace) = 15.480s`

### Кто виноват? (`blame`)
Показывает время, затраченное на запуск каждого юнита, сортируя список по убыванию. Это позволяет быстро найти самые "медленные" службы.
```bash
# Время запуска каждого юнита, отсортированное по убыванию
systemd-analyze blame
```
Это одна из самых полезных команд для быстрой диагностики.

### Критическая цепь зависимостей (`critical-chain`)
Эта команда строит дерево зависимостей для указанного юнита (или для таргета по умолчанию) и показывает, какая последовательность запусков оказалась на "критическом пути", то есть напрямую влияла на общее время запуска.
```bash
# Показать критическую цепь зависимостей, замедливших загрузку
systemd-analyze critical-chain

# Показать критическую цепь для конкретного таргета, например, графического
systemd-analyze critical-chain graphical.target
```
Красным цветом выделяется время, которое юнит потратил на собственный запуск, а знаком `+` — время ожидания зависимостей.

### Генерация SVG-диаграммы
`systemd-analyze` может сгенерировать подробную SVG-диаграмму, на которой визуально представлен процесс загрузки всех юнитов.
```bash
# Сгенерировать plot.svg с диаграммой загрузки
systemd-analyze plot > plot.svg
```
Полученный SVG-файл можно открыть в любом веб-браузере. На диаграмме наглядно видно, какие процессы выполнялись параллельно, а какие ждали завершения других.
