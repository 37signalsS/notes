# systemd-analyze: Анализ производительности и диагностика

## Определения

**`systemd-analyze`** — это многофункциональная системная утилита в составе `systemd`, предназначенная для анализа процесса загрузки ОС (Операционная Система), проверки конфигурации юнитов и отладки временных расписаний. Она позволяет измерять время старта системы, выявлять узкие места в последовательности запуска и визуализировать зависимости между компонентами.

## Основные концепции

- **Фазы загрузки (Kernel против Userspace)**:
  - **Kernel time**: Время, затраченное ядром на инициализацию оборудования и загрузку драйверов до запуска первого процесса.
  - **Userspace time**: Время с момента запуска `systemd` (PID (Process ID) 1) до завершения активации всех необходимых служб (достижения `default.target`).
- **Критическая цепь (Critical Chain)**: Цепочка юнитов, которая в данный момент определяет общее время загрузки. Задержка любого элемента в этой цепи напрямую увеличивает время старта системы.
- **Юниты (Units)**: Базовые объекты управления `systemd`, производительность которых (время активации и готовности) анализируется утилитой.

## Практические сценарии

### Общий анализ времени старта

Команда без аргументов показывает сводную информацию о времени, затраченном на разных этапах загрузки.

```bash
systemd-analyze
# → Startup finished in 3.295s (kernel) + 12.185s (userspace) = 15.480s
```

### Поиск замедляющих служб (`blame`)

Выводит список всех активных юнитов, отсортированный по времени их запуска. Это первый шаг для поиска сервисов, которые тормозят систему.

```bash
systemd-analyze blame
# → 7.345s network-manager.service
# → 2.120s dev-sda2.device
# → 1.500s ssh.service
```

### Анализ критической цепи (`critical-chain`)

Позволяет увидеть дерево зависимостей, которые влияют на время достижения целевого состояния (по умолчанию — `default.target`).

```bash
systemd-analyze critical-chain
# → graphical.target @12.185s
# → └─multi-user.target @12.185s
# →   └─nginx.service @10.500s +1.685s
```

*Здесь `+1.685s` — время, затраченное именно на запуск nginx после готовности его зависимостей.*

### Визуализация загрузки (`plot`)

Создает подробную временную диаграмму запуска всех юнитов в формате SVG (Scalable Vector Graphics).

```bash
systemd-analyze plot > boot_analysis.svg
# → генерация файла boot_analysis.svg для просмотра в браузере
```

### Проверка конфигурации юнитов (`verify`)

Позволяет проверить файлы юнитов на наличие синтаксических ошибок и неверных директив перед их применением.

```bash
systemd-analyze verify /etc/systemd/system/my_service.service
# → вывод ошибок парсинга или предупреждений о зависимостях
```

### Отладка календарных событий (`calendar`)

Помогает проверить корректность написания расписания для таймеров (директива `OnCalendar=`).

```bash
systemd-analyze calendar "Mon *-*-* 03:00:00"
# → Next elapse: Mon 2024-06-10 03:00:00 MSK
# → From now: 2 days left
```

## Дополнительная информация

### Оптимизация и инструменты

- **Замена оболочки**: Использование `/bin/dash` вместо `/bin/bash` для системных скриптов может сократить время выполнения инициализации. Подробнее: [Типы оболочек](../../Shell/shell_intro.md).
- **Визуализация графов**: Команда `systemd-analyze dot` позволяет генерировать описание графа зависимостей в формате Graphviz.
