# systemd-analyze: Анализ производительности и диагностика

## Определения

* **`systemd-analyze`** — это многофункциональная системная утилита в составе `systemd`, предназначенная для глубокого анализа процесса загрузки, проверки безопасности юнитов, верификации конфигурации и отладки временных расписаний.
* **Критическая цепь (Critical Chain)** — последовательность юнитов, которая определяет общее время загрузки. Задержка любого элемента в этой цепи напрямую увеличивает время старта системы до целевого состояния.
* **Уровень подверженности (Exposure Level)** — метрика безопасности (от 0.0 до 10.0), вычисляемая на основе настроек изоляции и «песочницы» сервиса.

## Основные концепции

### Фазы загрузки системы

`systemd-analyze` разделяет время старта на несколько ключевых этапов:
* **Ядро (Kernel)** — инициализация оборудования и загрузка драйверов.
* **initrd** — время работы начальной файловой системы в оперативной памяти (если используется).
* **Пользовательское пространство (Userspace)** — время от запуска PID 1 до завершения активации всех юнитов в `default.target`.

### Анализ безопасности и изоляции

Начиная с версии v250+, утилита стала мощным инструментом аудита:
* **Песочница (Sandboxing)** — проверка использования директив `PrivateTmp`, `ProtectSystem`, `NoNewPrivileges`.
* **Фильтры системных вызовов (seccomp)** — анализ разрешенных групп системных вызовов через `SystemCallFilter`.
* **Доступ к ФС** — проверка ограничений на чтение/запись через `ProtectHome`, `ReadOnlyPaths`.

## Практические сценарии

### Анализ времени и узких мест загрузки

```bash
# Общая сводка времени старта
systemd-analyze
# → Startup finished in 3.2s (kernel) + 1.5s (initrd) + 12.1s (userspace) = 16.8s

# Список служб, отсортированных по времени запуска (blame)
systemd-analyze blame
# → 7.345s network-manager.service
# → 2.120s dev-sda2.device
# → 1.500s ssh.service

# Визуализация критической цепочки зависимостей
systemd-analyze critical-chain
# → graphical.target @12.185s
# → └─multi-user.target @12.185s
# →   └─nginx.service @10.500s +1.685s
```

### Аудит безопасности сервисов

Позволяет быстро оценить, насколько хорошо изолирован сервис от остальной системы.

```bash
# Оценка уровня безопасности конкретного юнита
systemd-analyze security nginx.service
# → UNIT            EXPOSURE PREDICTED LEVEL
# → nginx.service   9.6      UNSAFE
# → (выведет подробную таблицу с рекомендациями по укреплению)
```

### Тестирование условий и конфигурации

```bash
# Проверка условия без запуска юнита
systemd-analyze condition 'ConditionKernelVersion=>5.15'
# → Condition check succeeded.

# Проверка синтаксиса юнит-файла на наличие ошибок
systemd-analyze verify /etc/systemd/system/myapp.service

# Просмотр итоговой конфигурации с учетом всех переопределений (drop-ins)
systemd-analyze cat-config systemd/logind.conf
```

### Работа с фильтрами и версиями

```bash
# Список системных вызовов в определенной группе (для SystemCallFilter)
systemd-analyze syscall-filter @network-io
# → accept, bind, connect, listen, socket...

# Проверка корректности расписания таймера
systemd-analyze calendar "daily"
# → Next elapse: Tue 2024-06-11 00:00:00 UTC
# → From now: 12h left
```

## Дополнительная информация

### Инструменты визуализации

* **Генерация графика загрузки:** `systemd-analyze plot > boot.svg` — создает SVG-диаграмму со всеми процессами и их временем жизни.
* **Граф зависимостей:** `systemd-analyze dot | dot -Tsvg > dependencies.svg` — визуализирует иерархию связей `Wants/Requires` (требуется пакет `graphviz`).
