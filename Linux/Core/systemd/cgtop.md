# systemd-cgtop: Мониторинг ресурсов контрольных групп

## Определения

* **`systemd-cgtop`** — это интерактивная системная утилита для мониторинга потребления ресурсов (CPU, память, I/O) иерархиями контрольных групп (**cgroups**). В отличие от классических инструментов типа `top`, она агрегирует данные не по отдельным процессам, а по логическим объединениям — сервисам, пользователям и контейнерам.
* **Control Group (cgroup)** — механизм ядра Linux, позволяющий объединять процессы в иерархические группы для изоляции и ограничения ресурсов.

## Основные концепции

### Преимущества агрегации данных

В современных системах один сервис (например, веб-сервер или база данных) может состоять из десятков процессов. `systemd-cgtop` позволяет увидеть нагрузку на систему целиком от конкретного юнита (unit), избавляя администратора от необходимости вручную суммировать показатели отдельных PID (Process ID).

**Пример отображения в сравнении с top:**

Обычный `top` (разрозненные процессы):

```text
PID   USER      %CPU  COMMAND
101   www-data  15.0  php-fpm: pool www
102   www-data  12.0  php-fpm: pool www
```

`systemd-cgtop` (единый сервис):

```text
Control Group              Tasks   %CPU   Memory
/system.slice/php-fpm.service  2   27.0   124.5M
```

### Поддержка cgroup v2

Современные версии `systemd-cgtop` полностью поддерживают **cgroup v2** (unified hierarchy). В этой версии иерархия ресурсов едина, что делает мониторинг более консистентным. Процессы в v2 обычно находятся только в «листьях» дерева (сервисах или скоупах), а слайсы служат лишь контейнерами для организации.

### Требования к сбору метрик (Accounting)

Для того чтобы `systemd-cgtop` отображал данные по CPU, памяти и I/O, соответствующие контроллеры должны быть активированы в настройках systemd или конкретных юнитов. По умолчанию многие дистрибутивы включают их, но их можно настроить вручную в `/etc/systemd/system.conf` или в unit-файле:

```ini
[Service]
CPUAccounting=yes
MemoryAccounting=yes
IOAccounting=yes
```

## Практические сценарии

### Сортировка и фильтрация при запуске

Использование флагов помогает быстро выявить узкие места.

```bash
# Сортировка по потреблению памяти
systemd-cgtop --order=memory
# → список групп, где наверху будут потребители RAM

# Сортировка по дисковой нагрузке (I/O)
systemd-cgtop --order=io
# → мониторинг Input/Output операций в реальном времени
```

### Ограничение глубины и мониторинг контейнеров

При наличии большого количества вложенных групп (например, в Kubernetes или Docker) вывод может быть перегружен.

```bash
# Показать только верхние 2 уровня иерархии
systemd-cgtop --depth=2
# → вывод ограничен системными слайсами и верхними сервисами

# Мониторинг ресурсов конкретного контейнера (машины)
systemd-cgtop --machine=my_container
# → вывод только для указанной виртуальной машины или контейнера
```

### Пакетный режим для автоматизации

Для логирования или использования в скриптах можно использовать snapshot-режим.

```bash
# Однократный вывод «сырых» данных (в байтах)
systemd-cgtop --batch --iterations=1 --raw
# → Control Group                            Tasks   %CPU   Memory  Input/s Output/s
# → /                                          452    1200  2456789123        0        0
```

## Интерактивное управление

Во время работы утилиты можно изменять режим отображения с помощью горячих клавиш:

| Клавиша | Действие |
| :--- | :--- |
| **`c`** | Сортировать по CPU. |
| **`m`** | Сортировать по памяти. |
| **`i`** | Сортировать по I/O. |
| **`t`** | Сортировать по количеству задач (Tasks). |
| **`p`** | Сортировать по пути (Path). |
| **`+` / `-`** | Увеличить / уменьшить глубину отображения дерева. |
| **`r`** | Переключить режим рекурсивного подсчета (для cgroup v2). |
| **`%`** | Переключить CPU между процентами и временем. |
| **`q`** | Выход из программы. |
