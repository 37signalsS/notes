# Обзор юнитов systemd

## Определения

* **Юнит (Unit)** — это базовый объект управления в `systemd`, представляющий системный ресурс, службу или абстрактное состояние. Каждый юнит описывается текстовым файлом конфигурации с расширением, указывающим на его тип.
* **Экземпляр юнита** — динамически создаваемый объект в оперативной памяти (runtime), жизненным циклом которого управляет менеджер `systemd`.
* **Таргет (Target)** — специальный тип юнита, служащий для группировки других юнитов и определения целевого состояния системы (например, загрузка в многопользовательский режим).

## Основные концепции

### Типы юнитов

`systemd` поддерживает 11 типов юнитов, обеспечивающих полный контроль над ОС.

| Тип юнита | Описание | Применение |
| :--- | :--- | :--- |
| **`.service`** | Процесс или демон. | Запуск веб-серверов, баз данных, скриптов. |
| **`.socket`** | Сетевой порт или IPC-канал. | Активация службы при поступлении первого пакета. |
| **`.timer`** | Планировщик времени. | Запуск задач по расписанию (аналог cron). |
| **`.path`** | Мониторинг ФС. | Запуск службы при изменении файлов (через `inotify`). |
| **`.mount`** | Точка монтирования. | Управление дисками и разделами (вместо `/etc/fstab`). |
| **`.automount`** | Отложенный монтаж. | Монтирование диска только в момент обращения к нему. |
| **`.target`** | Логическая группа. | Определение состояний загрузки (runlevels). |
| **`.slice`** | Контейнер ресурсов. | Группировка юнитов для ограничения CPU/RAM через cgroups. |
| **`.scope`** | Внешние процессы. | Группировка процессов, запущенных не самим systemd. |
| **`.swap`** | Файл подкачки. | Управление областью swap. |
| **`.device`** | Устройство. | Представление физического оборудования в дереве юнитов. |

### Ключевые различия: Service vs Scope

* **`.service`**: Systemd сам запускает процесс (`fork/exec`). Конфигурация статична и хранится на диске.
* **`.scope`**: Systemd управляет уже работающими процессами, запущенными внешними инструментами (например, сессией пользователя или контейнером). Создаются динамически через API.

### Механизм Socket Activation

Позволяет `systemd` слушать сокеты до того, как службы будут запущены. Это ускоряет загрузку за счет параллелизации и экономит ресурсы (служба спит, пока к ней не обратились). При падении службы сокет остается открытым, и новые запросы не теряются.

### Состояния системы (Targets)

Таргеты заменяют старые уровни выполнения (runlevels) SysVinit.

| Состояние | Таргет | Описание |
| :--- | :--- | :--- |
| **Recovery** | `emergency.target` | Минимальный шелл, ФС в read-only. |
| **Single user**| `rescue.target` | Базовые службы, локальные ФС смонтированы. |
| **Server** | `multi-user.target` | Полноценная система без графической оболочки. |
| **Desktop** | `graphical.target` | Система с GUI (надстройка над multi-user). |
| **Userspace** | `soft-reboot.target` | (v254+) Перезагрузка ОС без перезапуска ядра. |

> **Совет для серверов:** Большинство дистрибутивов по умолчанию загружаются в графику (`graphical.target`). На сервере она не нужна и потребляет ресурсы. Чтобы установить текстовый режим как основной, используйте:
> ```bash
> sudo systemctl set-default multi-user.target
> ```

## Практические сценарии

### Анализ текущего окружения

```bash
# Узнать, к какому юниту относится текущий процесс
systemctl whoami
# → service: ssh.service
# → slice: system.slice

# Проверить таргет по умолчанию
systemctl get-default
# → multi-user.target

# Список всех активных юнитов определенного типа
systemctl list-units --type=socket
# → UNIT               LOAD   ACTIVE SUB    DESCRIPTION
# → docker.socket      loaded active running Docker Socket
```

### Управление состоянием

```bash
# Показать дерево зависимостей текущего таргета
systemctl list-dependencies

# Мгновенный переход в графический режим (без перезагрузки)
sudo systemctl isolate graphical.target

# Установка текстового режима как основного
sudo systemctl set-default multi-user.target
```

## Дополнительная информация

### Пути поиска юнит-файлов

`systemd` ищет конфигурации в следующем порядке приоритета:
1. `/etc/systemd/system/` — настройки администратора (высший приоритет).
2. `/run/systemd/system/` — динамические конфигурации времени выполнения.
3. `/usr/lib/systemd/system/` — юниты от пакетов дистрибутива (низший приоритет).

### Нововведения последних версий (v250+)

* **Credentials**: Безопасная передача секретов в юниты через зашифрованные файлы.
* **Exponential Backoff**: Параметры `RestartSteps` позволяют увеличивать паузу между попытками перезапуска упавшего сервиса.
* **Cgroup ExitType**: Возможность ждать завершения всей группы процессов в `.service`.
