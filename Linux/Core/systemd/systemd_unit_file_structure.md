# Структура юнит-файла systemd

## Определения

* **Юнит-файл (Unit file)** — текстовый конфигурационный файл в формате, схожем с INI, описывающий системный ресурс (службу, точку монтирования, устройство).
* **Секция** — логический блок параметров, заключенный в квадратные скобки (например, `[Unit]`).
* **Директива** — отдельный параметр в формате `Ключ=Значение`.
* **Drop-in файл** — файл-переопределение (обычно `override.conf`), позволяющий изменять параметры основного юнита без его редактирования.

## Основные концепции

### Базовые секции и их назначение

| Секция | Описание | Применимость |
| :--- | :--- | :--- |
| **`[Unit]`** | Метаданные, условия запуска и описание зависимостей. | Все типы юнитов. |
| **`[Service]`** | Настройки запуска, жизненного цикла и ресурсов процесса. | Только для `.service`. |
| **`[Install]`** | Инструкции для связывания юнита с таргетами (автозагрузка). | Все типы юнитов. |

### Секция [Unit]: Логика запуска

Помимо стандартных `Description` и `After`, секция управляет возможностью старта юнита.

* **`Condition...=`** — если условие ложно, юнит **пропускается** без сообщения об ошибке.
* **`Assert...=`** — если условие ложно, запуск юнита завершается с **ошибкой**.
* **Логика OR**: если указать несколько однотипных условий с префиксом `|` (например, `ConditionPathExists=|/etc/a`), запуск произойдет при выполнении хотя бы одного из них.

| Директива | Описание |
| :--- | :--- |
| `ConditionPathExists=` | Проверка наличия файла или директории. |
| `ConditionVirtualization=` | Проверка среды (например, `docker`, `kvm`, `vmware`). |
| `ConditionArchitecture=` | Проверка архитектуры процессора (например, `x86-64`). |
| `ConditionCredential=` | (v250+) Проверка наличия специфических учетных данных systemd. |

### Секция [Service]: Жизненный цикл процесса

Определяет, как именно запускается и останавливается приложение.

#### Порядок выполнения команд
1. **`ExecCondition=`** — (v243+) если команда возвращает не 0, юнит пропускается.
2. **`ExecStartPre=`** — подготовительные команды (например, создание папок).
3. **`ExecStart=`** — основная команда запуска (требуется абсолютный путь).
4. **`ExecStartPost=`** — команды после успешного запуска основного процесса.
5. **`ExecReload=`** — команда для перечитывания конфигурации приложения.
6. **`ExecStop=`** — команда для корректного завершения.

#### Управление выводом и логами
Директивы `StandardOutput` и `StandardError` поддерживают расширенные режимы (v240+):
* **`journal`** (по умолчанию) — запись в системный журнал.
* **`append:/path/to/file`** — дописывание в конец файла.
* **`truncate:/path/to/file`** — перезапись файла.

#### Завершение работы
* **`KillMode=`** — определяет, как убивать процессы. Рекомендуется `mixed` (SIGTERM главному процессу, SIGKILL остальным) или по умолчанию `control-group`.
* **`ExitType=cgroup`** — (v250+) systemd будет считать службу остановленной только тогда, когда **все** процессы в её cgroup завершатся.

## Практические сценарии

### Настройка переменных окружения

Рекомендуется использовать `EnvironmentFile` для хранения настроек вне юнит-файла.

```ini
[Service]
# "-" означает игнорирование ошибки, если файл отсутствует
EnvironmentFile=-/etc/default/myapp
ExecStart=/usr/bin/myapp --port ${PORT}
```

### Переопределение параметров (systemctl edit)

Никогда не редактируйте файлы в `/usr/lib/systemd/system/`. Используйте механизм drop-in.

```bash
# Откроет редактор для создания override.conf
sudo systemctl edit nginx.service
```

**Важное правило для списков:** при переопределении директив, которые могут встречаться несколько раз (например, `ExecStart`), сначала нужно очистить старое значение:

```ini
[Service]
ExecStart=
ExecStart=/usr/bin/nginx -g 'daemon off;'
```

### Пример современного юнита (v250+)

```ini
[Unit]
Description=Modern Microservice
ConditionVirtualization=container

[Service]
Type=notify
ExecSearchPath=/opt/myapp/bin:/usr/local/bin
ExecStart=myapp --config /etc/myapp/config.yaml
StandardOutput=append:/var/log/myapp.log

# Изоляция и безопасность
ProtectSystem=strict
PrivateTmp=yes
RestrictFileSystems=@common-block

[Install]
WantedBy=multi-user.target
```

## Дополнительная информация

### Иерархия путей

| Путь | Приоритет | Назначение |
| :--- | :--- | :--- |
| `/etc/systemd/system/` | **Высший** | Локальные настройки и переопределения. |
| `/run/systemd/system/` | Средний | Динамические юниты (времени выполнения). |
| `/usr/lib/systemd/system/` | Низший | Юниты, поставляемые пакетами ОС. |

### Валидация и отладка

```bash
# Проверка синтаксиса перед применением
systemd-analyze verify /etc/systemd/system/test.service

# Чтение итоговой конфигурации со всеми drop-ins
systemctl cat nginx.service

# Применение изменений после ручного редактирования
sudo systemctl daemon-reload
```
