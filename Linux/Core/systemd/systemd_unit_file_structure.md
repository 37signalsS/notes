# Структура юнит-файла systemd

## Определения

**Юнит-файлы (Unit files)** — это текстовые конфигурационные файлы в формате, схожем с INI (Initialization). Они состоят из нескольких логических секций, заключенных в квадратные скобки (например, `[Unit]`), внутри которых располагаются директивы в формате `Ключ=Значение`.
Комментарии в файлах начинаются с символа `#` или `;`.

## Основные концепции

### Базовые секции

Структура юнит-файла зависит от его типа, но три секции являются наиболее распространенными:

| Секция | Описание | Применимость |
| :--- | :--- | :--- |
| **`[Unit]`** | Метаданные, описание, порядок загрузки и зависимости. | Все типы юнитов. |
| **`[Service]`** | Параметры запуска, контроля и остановки процессов. | Только для сервисов (`.service`). |
| **`[Install]`** | Инструкции для `systemctl enable` (автозагрузка). | Почти все типы. |

### Секция [Unit] (Метаданные и зависимости)

Секция описывает общие свойства объекта и его связь с другими компонентами Операционной Системы (ОС).

| Директива | Описание |
| :--- | :--- |
| `Description=` | Краткое описание юнита (отображается при проверке статуса). |
| `Documentation=` | Ссылки на документацию (URI (Uniform Resource Identifier), manual-страницы). |
| `After=` / `Before=` | Определение **порядка** запуска относительно других юнитов. |
| `Requires=` | Жёсткая зависимость (активация требует запуска другого юнита). |
| `Wants=` | Мягкая зависимость (рекомендуется запуск другого юнита). |
| `ConditionPathExists=` | Условие запуска: юнит стартует только если указанный путь существует. |

### Секция [Service] (Управление процессом)

Секция определяет, как именно `systemd` должен запускать и контролировать службу.

| Директива | Описание |
| :--- | :--- |
| `Type=` | Тип запуска: `simple` (по умолчанию), `forking`, `oneshot`, `notify`. |
| `ExecStart=` | Основная команда для запуска процесса (требуется абсолютный путь). |
| `ExecStop=` | Команда для корректной остановки службы. |
| `Restart=` | Условие автоматического перезапуска (например, `always`, `on-failure`). |
| `User=` / `Group=` | Запуск процесса от имени конкретного пользователя или группы. |
| `EnvironmentFile=` | Путь к файлу с переменными окружения. |

### Секция [Install] (Автозапуск)

Секция используется только при выполнении команд Интерфейса командной строки (CLI, Command Line Interface) `enable` и `disable`.

| Директива | Описание |
| :--- | :--- |
| `WantedBy=` | Указывает таргет (target), в который юнит должен быть включен при автозагрузке. |
| `RequiredBy=` | Указывает таргет, для которого этот юнит является обязательным. |

## Практические сценарии

### Использование файла переменных окружения

Использование `EnvironmentFile` позволяет отделить конфигурацию и секретные данные от логики юнита.

1. **Создание файла конфигурации** (`/etc/myapp/config.env`):

    ```text
    DB_URL=postgres://localhost:5432/db
    API_KEY=super_secret_token
    ```

   # → права доступа на файл должны быть ограничены (например, `chmod 600`)

2. **Подключение в юнит-файле**:

    ```ini
    [Service]
    EnvironmentFile=/etc/myapp/config.env
    ExecStart=/usr/bin/myapp --db ${DB_URL}
    ```

### Переопределение параметров (Drop-in файлы)

Для изменения параметров системных служб без модификации оригинальных файлов (которые могут быть перезаписаны при обновлении ПО (Программное Обеспечение)) используйте механизм переопределений.

```bash
# Редактирование переопределений для nginx
sudo systemctl edit nginx.service
```

# → команда создаст директорию и файл /etc/systemd/system/nginx.service.d/override.conf

**Пример ограничения ресурсов в переопределении:**

```ini
[Service]
CPUQuota=50%
MemoryMax=2G
```

### Проверка и валидация

```bash
# Проверка синтаксиса файла перед активацией
systemd-analyze verify /etc/systemd/system/my-custom.service
# → вывод ошибок парсинга или предупреждений (пусто, если ошибок нет)

# Показать итоговую конфигурацию юнита со всеми переопределениями
systemctl cat nginx.service
# → вывод объединенного содержимого всех задействованных файлов

# Применение изменений после ручного редактирования файлов на диске
sudo systemctl daemon-reload
```

## Дополнительная информация

### Иерархия расположения файлов

| Директория | Приоритет | Назначение |
| :--- | :--- | :--- |
| `/etc/systemd/system/` | Высший | Настройки администратора и переопределения. |
| `/run/systemd/system/` | Средний | Динамически создаваемые юниты времени выполнения. |
| `/usr/lib/systemd/system/` | Низший | Юниты, поставляемые вместе с пакетами ПО. |
