# systemd-tmpfiles: Управление временными файлами и структурой ФС

## Определения

* **`systemd-tmpfiles`** — системный механизм для декларативного создания, удаления и управления объектами файловой системы (файлами, каталогами, сокетами, правами доступа). В современных системах это не просто инструмент очистки `/tmp`, а мощный механизм инициализации структуры ФС при загрузке системы или установке ПО.
* **Конфигурационные файлы (`tmpfiles.d`)** — текстовые файлы в формате `.conf`, описывающие правила обработки путей.
* **Transient Rules** — временные правила, передаваемые через системные учетные данные (`tmpfiles.extra`) или создаваемые «на лету».
* **Транзакционное применение** — все изменения применяются атомарно в рамках одного вызова `systemd-tmpfiles --create`. При ошибке часть изменений не применяется.
* **Credential-based tmpfiles** — механизм v250+, при котором правила временно импортируются из секретов Credentials в `tmpfiles.extra` и удаляются после выполнения.

## Основные концепции

### Архитектурные компоненты

`systemd-tmpfiles` работает через два основных системных юнита:
1. **`systemd-tmpfiles-setup.service`** — запускается на ранних этапах загрузки. Выполняет создание директорий, файлов и установку прав (типы `d`, `f`, `L`, `p`, `c`, `b`, `z` и др.).
2. **`systemd-tmpfiles-clean.timer`** — периодически запускает **`systemd-tmpfiles-clean.service`** (обычно раз в сутки) для очистки устаревших файлов на основе параметра «Возраст» (типы `d`, `D`, `e`).

### Жизненный цикл и точки применения

Правила `tmpfiles.d` выполняются не только при загрузке:
* **При загрузке системы** — через `systemd-tmpfiles-setup.service` на ранних этапах (после монтирования файловых систем, перед запуском большинства сервисов).
* **При установке пакетов** — пакетные менеджеры (rpm, deb) автоматически запускают `systemd-tmpfiles --create` для файлов из `/usr/lib/tmpfiles.d/`.
* **При старте пользовательских сессий** — через `systemd-tmpfiles-setup.service` в пользовательском экземпляре systemd (user instance).
* **Динамически через drop-ins** — файлы в `/run/tmpfiles.d/` применяются при каждом запуске `systemd-tmpfiles --create`.
* **Через Credentials** — правила из `tmpfiles.extra` применяются один раз при старте юнита.

### Взаимодействие с другими механизмами systemd

* **`systemd-sysusers`** — создает записи в `/etc/passwd` и `/etc/group`. `systemd-tmpfiles` использует эти записи для установки владельцев (`chown`) при создании файлов и директорий. Оба механизма часто используются вместе для полной инициализации окружения сервиса.
* **`systemd-till`** — таймеры и сервисы могут использовать `tmpfiles.d` для подготовки окружения перед запуском.
* **`systemd-run`** — временные юниты, созданные через `systemd-run`, наследуют окружение, подготовленное `tmpfiles.d`.
* **`systemd-oomd`** — может использовать `tmpfiles.d` для создания маркерных файлов состояния.
* **Секреты (Credentials)** — начиная с v250, секреты могут передаваться в `tmpfiles.extra` для безопасного создания файлов с чувствительными данными.

### Расположение и приоритет конфигурации

Правила обрабатываются в лексикографическом порядке имен файлов. Если файлы имеют одинаковые имена в разных директориях, применяется только один с наивысшим приоритетом:

| Путь | Назначение | Приоритет |
| :--- | :--- | :--- |
| **`/etc/tmpfiles.d/*.conf`** | Локальные настройки администратора | **Высший** |
| **`/run/tmpfiles.d/*.conf`** | Динамические правила времени выполнения (runtime) | Средний |
| **`/usr/lib/tmpfiles.d/*.conf`** | Правила от дистрибутива и установленных пакетов | Низший |

### Формат строки конфигурации

Каждая строка описывает одну операцию:
```text
Тип  Путь  Режим  Владелец  Группа  Возраст  Аргумент
```

Поля «Режим», «Владелец» и «Группа» необязательны для типов, которые не создают файлы (например, `e` для очистки). Если поле опущено, используются значения по умолчанию или не применяются.

#### Таблица типов директив (Создание и Очистка)

| Тип | Операция | Описание |
| :---: | :--- | :--- |
| **`d`** | Create Directory | Создает директорию, если её нет. Устанавливает права/владельца. |
| **`D`** | Create & Empty | Создает директорию и очищает её содержимое при вызове `--clean`. |
| **`e`** | Clean Dir | Очищает содержимое существующей директории по возрасту. |
| **`f`** | Create File | Создает пустой файл, если его нет. |
| **`F`** | Write File | Создает или перезаписывает файл (аналог `truncate`). |
| **`w`** | Write Content | Дописывает строку в файл. Поддерживает спецификаторы. |
| **`L`** | Symlink | Создает символическую ссылку. Цель — в Аргументе. |
| **`p`** | Named Pipe | Создает именованный канал (FIFO). |
| **`c` / `b`** | Device Node | Создает символьное (`c`) или блочное (`b`) устройство. |
| **`C`** | Truncate | Очищает содержимое существующего файла. |
| **`x`** | Ignore | Игнорирует путь, если он не существует. |
| **`r`** | Remove | Удаляет файл или директорию, если он существует. |
| **`R`** | Recursive Remove | Рекурсивно удаляет директорию и всё содержимое. |
| **`q`** | Quiet | Подавляет ошибки для данного пути. |
| **`!`** | Comment | Игнорирует строку (комментарий). |

#### Таблица типов директив (Права и Безопасность)

| Тип | Операция | Описание |
| :---: | :--- | :--- |
| **`z`** | Set Permissions | Устанавливает права, владельца и группу (без рекурсии). |
| **`Z`** | Recursive Set | Рекурсивно устанавливает права и восстанавливает контекст SELinux. |
| **`a` / `A`** | Set ACLs | Устанавливает POSIX ACL (рекурсивно для `A`). Суффикс `+` — добавить. |
| **`h` / `H`** | Set Attributes | Устанавливает атрибуты файлов (chattr), например `i` (immutable). |
| **`t` / `T`** | Set xattrs | Устанавливает расширенные атрибуты (xattrs). |
| **`S`** | Set SELinux Context | Устанавливает контекст SELinux для пути. |
| **`m`** | Set Mode | Устанавливает только права доступа (chmod). |
| **`p`** | Set Owner | Устанавливает только владельца (chown). |
| **`g`** | Set Group | Устанавливает только группу (chgrp). |

#### Специфические типы для Btrfs

* **`v` / `q` / `Q`** — создание subvolume, управление квотами и группами квот (qgroups) в файловой системе Btrfs.

### Спецификаторы (Specifiers)

В полях «Путь» и «Аргумент» используются переменные:
* **`%m`** — Machine ID хоста.
* **`%b`** — Boot ID текущей загрузки.
* **`%H`** — Hostname системы.
* **`%T` / `%V`** — Директории `/tmp` и `/var/tmp` соответственно.
* **`%u` / `%U`** — Имя и UID текущего пользователя.
* **`%h`** — Домашняя директория пользователя.
* **`%i`** — Идентификатор изображения (image identifier) для immutable ОС.
* **`%E`** — Директория состояния окружения (environment state directory).

### Синтаксис возраста (Age)

Поле «Возраст» поддерживает форматы:
* **`10s`** — секунды
* **`5m`** — минуты
* **`2h`** — часы
* **`1d`** — дни
* **`2w`** — недели
* **`1month`** — месяцы
* **`1y`** — годы

Очистка происходит только для файлов и директорий, которые **не изменялись** дольше указанного периода. Файлы, к которым происходил доступ (mtime), не удаляются.

## Практические сценарии

### 1. Настройка окружения для сервиса

Создание структуры в `/run` с правами для группы и ACL для мониторинга.
```ini
# /etc/tmpfiles.d/app-monitor.conf
# Тип  Путь            Режим  Пользователь  Группа    Возраст  Аргумент
d      /run/app-data   0750   app-user      www-data  -        -
a+     /run/app-data   -      -             -         -        u:monitor:r-x
```

### 2. Автоматическая очистка старых дампов

Удаление `.sql` файлов из `/var/backups/db/` старше 30 дней.
```ini
# /etc/tmpfiles.d/db-cleanup.conf
# Тип  Путь             Режим  Пользователь  Группа  Возраст  Аргумент
e      /var/backups/db  -      -             -       30d      -
```

### 3. Создание именованного канала (FIFO)

Полезно для интеграции старых приложений, ожидающих пайп.
```ini
# /etc/tmpfiles.d/legacy-pipe.conf
p      /run/app.pipe    0660   root          app-group -        -
```

### 4. Создание символических ссылок для совместимости

Перенаправление устаревших путей на новые расположения.
```ini
# /etc/tmpfiles.d/compat-symlinks.conf
L      /usr/local/bin/old-tool  -   -   -   -   /opt/new-tool/bin/old-tool
```

### 5. Подготовка директории для сокетов сервиса

Создание директории для Unix-сокета с правильными правами.
```ini
# /etc/tmpfiles.d/php-fpm.conf
d      /run/php-fpm       0750   root   www-data  -   -
```

### 6. Очистка кэша приложения по размеру или возрасту

Удаление файлов кэша старше 7 дней.
```ini
# /etc/tmpfiles.d/app-cache.conf
e      /var/cache/myapp   -   -   -   7d   -
```

### 7. Создание устройства или специализированного файла

Используется редко, но может потребоваться для legacy-интеграций.
```ini
# /etc/tmpfiles.d/legacy-device.conf
c      /dev/mydevice    0660   root   dialout  -   -
```

### 8. Очистка временных файлов при каждой загрузке

Удаление содержимого директории при каждом запуске.
```ini
# /etc/tmpfiles.d/temp-clean.conf
d      /tmp/app-temp    1777   root   root    -   -
```

## Диагностика и устранение неисправностей

```bash
# Чтение всей итоговой конфигурации (с учетом приоритетов)
systemd-tmpfiles --cat-config

# Принудительное выполнение создания и установки прав
sudo systemd-tmpfiles --create

# Режим предварительного просмотра (dry-run)
sudo systemd-tmpfiles --create --dry-run

# Очистка устаревших файлов (Age)
sudo systemd-tmpfiles --clean

# Применение правил только для конкретного файла конфигурации
sudo systemd-tmpfiles --create /etc/tmpfiles.d/my-app.conf

# Проверка синтаксиса конфигурации
sudo systemd-tmpfiles --create --dry-run /etc/tmpfiles.d/my-app.conf

# Просмотр статуса юнита очистки
systemctl status systemd-tmpfiles-clean.timer
systemctl status systemd-tmpfiles-clean.service

# Просмотр логов очистки
journalctl -u systemd-tmpfiles-clean.service -n 50
```

### Таблица диагностики

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| Директория не создается при загрузке | Ошибка синтаксиса в `.conf` или конфликт имен. | `systemd-tmpfiles --create --dry-run` для проверки; `journalctl -u systemd-tmpfiles-setup.service`. |
| Права доступа отличаются от указанных | Конфликт с правилом из более приоритетного файла (например, из пакета). | `systemd-tmpfiles --cat-config` для просмотра итоговых правил; переименуйте файл для изменения приоритета. |
| Файлы не удаляются по истечении Age | Файлы используются (mtime изменен) или `Age` указан некорректно. | `stat` для проверки mtime; убедитесь, что формат `Age` корректен (`30d`, а не `30`). |
| Ошибка «Invalid argument» при создании устройства | Некорректные параметры для `c`/`b` типа (major/minor). | Проверьте `major:minor` в аргументе; используйте `ls -l /dev/` для примеров. |
| Ссылка создается, но указывает на неверный путь | Относительный путь в аргументе интерпретируется относительно директории ссылки. | Используйте абсолютные пути в аргументе для `L` типа. |
| Правила из `/run/tmpfiles.d/` не применяются | Файл имеет неверное расширение или права. | Убедитесь, что файл заканчивается на `.conf` и доступен для чтения root. |

## Рекомендации по эксплуатации

1. **Приоритет конфигурации**: Помните, что `/etc/tmpfiles.d/` имеет высший приоритет. Используйте это для переопределения правил пакетов, но предпочитайте drop-in файлы через `systemctl edit` для сервис-специфичных настроек.
2. **Идемпотентность**: Все правила `tmpfiles.d` идемпотентны — их можно выполнять многократно без побочных эффектов. Это делает их безопасными для автоматизации.
3. **Версионирование**: Храните пользовательские `.conf` файлы в системе контроля версий (Ansible, Puppet, Chef). Это обеспечивает воспроизводимость конфигурации.
4. **Тестирование**: Всегда используйте `--dry-run` перед применением новых правил в production. Это позволяет выявить ошибки без воздействия на систему.
5. **Атомарность**: Не смешивайте правила из разных источников в одном файле. Разделяйте правила по файлам по назначению (сервис, очистка, безопасность).
6. **Спецификаторы**: Используйте `%m`, `%b`, `%H` для переносимости конфигурации между хостами. Это особенно важно в кластерных средах.
7. **Возраст для временных директорий**: Устанавливайте `Age` для `/tmp` и `/var/tmp` только если это требуется политикой безопасности. По умолчанию systemd-tmpfiles-clean.timer обрабатывает это автоматически.
8. **Взаимодействие с sysusers**: Для создания домашних директорий сервисных пользователей используйте комбинацию `systemd-sysusers` (создание пользователя) и `systemd-tmpfiles` (создание директории с правами).
9. **Credentials для секретов**: Для временных файлов с секретами используйте `tmpfiles.extra` через Credentials (v250+). Это исключает хранение секретов в конфигурационных файлах.
10. **Мониторинг**: Включайте логирование для `systemd-tmpfiles-clean.service` через `LogLevelMax=notice` в drop-in файле, если требуется отслеживать удаленные файлы.

## Различие /tmp и /var/tmp

| Характеристика | `/tmp` | `/var/tmp` |
| :--- | :--- | :--- |
| **Тип ФС** | Обычно `tmpfs` (RAM) | Дисковая ФС (HDD/SSD) |
| **Стойкость** | Очищается при перезагрузке | Сохраняется после перезагрузки |
| **Очистка** | 10 дней простоя (default) | 30 дней простоя (default) |
| **Размер** | Ограничен размером RAM/Swap | Ограничен размером диска |

## Ограничения и особенности

* `systemd-tmpfiles` не рекурсивно удаляет содержимое при использовании типа `d` (только создает). Для рекурсивной очистки используйте `D` или комбинацию `d` + `e`.
* В контейнерных средах (Docker, LXC) `systemd-tmpfiles-setup.service` может не запускаться, если PID 1 не systemd. В таких случаях используйте `systemd-tmpfiles --create` в entrypoint скрипте.
* Для правил из пакетов (`/usr/lib/tmpfiles.d/`) не редактируйте файлы напрямую. Используйте drop-in в `/etc/tmpfiles.d/` с тем же именем для переопределения.
* Спецификаторы `%h`, `%i` работают только в контексте пользовательских экземпляров systemd (`--user`) или образов ОС.
* Btrfs-specific типы (`v`, `q`, `Q`) игнорируются на других файловых системах без ошибок.
* `systemd-tmpfiles-clean.service` не удаляет файлы, у которых есть несколько жестких ссылок (hard links) — удаляется только последняя ссылка.
* В дистрибутивах с устаревшим systemd (< 230) поддержка некоторых типов директив (`a`, `A`, `h`, `H`, `t`, `T`) может быть ограничена.

## Меры безопасности и лучшие практики

1. **Sticky Bit**: Для общих директорий (как `/tmp`) используйте режим `1777`, чтобы предотвратить удаление чужих файлов.
2. **Неявное создание**: `systemd-tmpfiles` автоматически создает родительские каталоги с правами `0755` (владелец root), если они отсутствуют.
3. **Использование спецификаторов**: Это позволяет делать конфигурацию переносимой между хостами (например, используя `%m`).
4. **Минимальные права**: Устанавливайте минимально необходимые права (`0640` вместо `0666`). Избегайтеworld-writable файлов без Sticky Bit.
5. **SELinux/AppArmor**: При использовании `Z` или `S` типов убедитесь, что политики безопасности корректно обновляются.
6. **Аудит**: Регулярно проверяйте `/etc/tmpfiles.d/` на наличие неавторизованных изменений. Используйте `systemd-tmpfiles --cat-config` для просмотра итоговой конфигурации.
