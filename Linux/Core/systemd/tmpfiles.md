# systemd-tmpfiles: Управление временными файлами

## Определения

* **`systemd-tmpfiles`** — это системный механизм для декларативного создания, очистки и управления объектами файловой системы (файлами, каталогами, сокетами, правами доступа). В современных системах это не просто чистильщик `/tmp`, а мощный инструмент инициализации структуры ФС при загрузке или установке ПО.
* **Конфигурационные файлы (`tmpfiles.d`)** — текстовые файлы в формате `.conf`, описывающие правила обработки путей.

## Основные концепции

### Расположение и приоритет конфигурации

Правила обрабатываются в порядке приоритета. Если файлы имеют одинаковые имена в разных директориях, применяется только один с наивысшим приоритетом:

| Путь | Назначение | Приоритет |
| :--- | :--- | :--- |
| `/etc/tmpfiles.d/*.conf` | Локальные настройки администратора | **Высший** |
| `/run/tmpfiles.d/*.conf` | Динамические правила времени выполнения (runtime) | Средний |
| `/usr/lib/tmpfiles.d/*.conf` | Правила, поставляемые пакетами дистрибутива | Низший |

### Формат строки конфигурации

Каждая строка описывает одну операцию:
```text
Тип  Путь  Режим  Владелец  Группа  Возраст  Аргумент
```

#### Расширенная таблица типов директив

| Тип | Операция | Описание |
| :---: | :--- | :--- |
| **`d`** | Create Directory | Создает директорию, если её нет. Не трогает содержимое. |
| **`D`** | Create & Empty | Создает директорию и очищает её содержимое при вызове `--clean`. |
| **`f`** | Create File | Создает пустой файл. Если файл существует, не меняет его. |
| **`F`** | Write File | Создает или перезаписывает файл (аналог `truncate`). |
| **`w`** | Write Content | Записывает строку (из Аргумента) в существующий файл. Поддерживает спецификаторы. |
| **`L`** | Symlink | Создает символическую ссылку. Цель указывается в Аргументе. |
| **`a` / **`A`** | Set ACLs | Устанавливает POSIX Access Control Lists (рекурсивно для `A`). Суффикс `+` добавляет к существующим. |
| **`t`** / **`T`** | Set xattrs | Устанавливает Extended Attributes (рекурсивно для `T`). |
| **`h`** / **`H`** | Set Attributes | Устанавливает атрибуты файлов Linux (например, `i` — immutable). |
| **`e`** | Clean Dir | Очищает содержимое существующей директории по возрасту, но не создает её. |
| **`x`** | Exclude | Исключает путь из автоматической очистки. |
| **`Z`** | Restore Context | Рекурсивно восстанавливает права, владельца и контекст безопасности (SELinux). |

### Спецификаторы (Specifiers)

В полях «Путь» и «Аргумент» можно использовать переменные, которые раскрываются во время выполнения:
* **`%m`** — Machine ID хоста.
* **`%b`** — Boot ID текущей загрузки.
* **`%H`** — Hostname системы.
* **`%T`** — Директория для временных файлов (`/tmp`).
* **`%V`** — Директория для больших временных файлов (`/var/tmp`).

## Различие /tmp и /var/tmp

| Характеристика | `/tmp` | `/var/tmp` |
| :--- | :--- | :--- |
| **Тип ФС** | Обычно `tmpfs` (RAM/Swap) | Дисковая ФС (Root или отдельный раздел) |
| **Стойкость** | Очищается при перезагрузке | Сохраняется после перезагрузки |
| **Политика очистки** | По умолчанию 10 дней простоя | По умолчанию 30 дней простоя |
| **Назначение** | Мелкие эфемерные данные (сокеты, lock-файлы) | Крупные данные, кэши обновлений, сессии |

## Практические сценарии

### Настройка прав и ACL для веб-сервера

Создание структуры в `/run` с правами для группы и дополнительным ACL для пользователя-мониторинга.

```ini
# /etc/tmpfiles.d/web-app.conf
d  /run/web-app         0750 nginx www-data -
a+ /run/web-app         -    -      -        -  u:monitor:r-x
```

### Использование спецификаторов для логов

Создание уникальной директории для логов текущей загрузки.

```ini
# /etc/tmpfiles.d/boot-logs.conf
d /var/log/boot-%b 0755 root root 7d
```

### Управление через CLI

```bash
# Чтение всей итоговой конфигурации (с учетом приоритетов)
systemd-tmpfiles --cat-config
# → вывод всех правил из всех .conf файлов

# Создание всех объектов без удаления чего-либо
sudo systemd-tmpfiles --create
# → создание директорий и файлов по правилам d/f/L...

# Режим предварительного просмотра (dry-run)
sudo systemd-tmpfiles --create --dry-run
# → список действий, которые были бы выполнены

# Принудительная очистка устаревших файлов (Age)
sudo systemd-tmpfiles --clean
# → удаление файлов, превысивших срок хранения

# Безопасное удаление объектов (только типы r/R)
sudo systemd-tmpfiles --remove
```

### Автоматизация очистки

Очистка выполняется системным таймером, который запускает сервис раз в сутки.

```bash
# Проверка следующего запуска очистки
systemctl list-timers systemd-tmpfiles-clean.timer
# → NEXT                         LEFT     LAST                         PASSED
# → Tue 2024-06-11 10:00:00 UTC  23h left Mon 2024-06-10 10:00:05 UTC  1h ago
```

## Дополнительная информация

### Меры безопасности и лучшие практики

1. **Неявное создание**: При создании любого объекта (файла, сокета и т.д.) `systemd-tmpfiles` автоматически создаст все родительские директории с правами `0755` (владелец root), если они отсутствуют.
2. **Липкий бит (Sticky Bit)**: Для общих директорий (как `/tmp`) всегда используйте режим `1777`, чтобы пользователи могли удалять только свои файлы.
3. **Креды (Credentials)**: Начиная с systemd v252, можно передавать правила через `tmpfiles.extra` в системных учетных данных, что полезно для динамического конфигурирования без создания файлов на диске.
