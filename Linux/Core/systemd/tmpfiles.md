# systemd-tmpfiles: Управление временными файлами

## Определения

**`systemd-tmpfiles`** — системный механизм для создания, очистки и управления временными файлами и каталогами. Утилита обрабатывает директории `/tmp`, `/var/tmp`, `/run`, `/var/log` и кэш-директории согласно правилам, описанным в конфигурационных файлах. Она автоматически создаёт необходимые объекты с заданными правами доступа и удаляет устаревшие данные по истечении времени жизни.

> Централизованный сбор логов: [journald.md](../../SystemAdministration/Logging/journald.md). Планирование задач: [timers.md](./timers.md).

## Основные концепции

### Расположение конфигурационных файлов

Правила `systemd-tmpfiles` могут находиться в нескольких директориях, которые обрабатываются в порядке приоритета:

| Путь | Назначение | Приоритет |
| :--- | :--- | :--- |
| `/etc/tmpfiles.d/*.conf` | Пользовательские и локальные правила | Высший |
| `/run/tmpfiles.d/*.conf` | Динамические правила времени выполнения (runtime) | Средний |
| `/usr/lib/tmpfiles.d/*.conf` | Правила, поставляемые с пакетами ПО | Низший |

> Конфигурация в `/etc/` полностью переопределяет файл с тем же именем, находящийся в `/usr/lib/`.

### Формат строки конфигурации

Каждая строка в конфигурационном файле имеет следующий синтаксис:

```text
<тип> <путь> <режим> <владелец> <группа> <возраст> <аргумент>
```

| Поле | Описание | Пример |
| :--- | :--- | :--- |
| **тип** | Символ, определяющий операцию | `d`, `f`, `F` |
| **путь** | Абсолютный путь к объекту | `/run/myservice` |
| **режим** | Права доступа в восьмеричном формате | `0755`, `0644`, `-` |
| **владелец** | Имя пользователя или UID (User ID) | `nginx`, `-` |
| **группа** | Имя группы или GID (Group ID) | `nginx`, `-` |
| **возраст** | Срок хранения до автоматической очистки | `1d`, `30min`, `-` |
| **аргумент** | Дополнительные данные (содержимое, цель ссылки) | `-` |

### Таблица типов директив

| Тип | Операция | Очистка по возрасту | Пример |
| :---: | :--- | :---: | :--- |
| `d` | Создать директорию | Нет | `d /run/myservice 0755 user group -` |
| `D` | Создать директорию (с очисткой содержимого) | Да | `D /tmp/cache 0755 user group 1d` |
| `f` | Создать пустой файл (если не существует) | Нет | `f /run/myservice.pid 0644 user group -` |
| `F` | Создать или перезаписать файл | Да | `F /var/log/app.log 0640 user group 7d` |
| `w` | Записать строку в существующий файл | Нет | `w /proc/sys/vm/drop_caches - - - - 1` |
| `L` | Создать symlink (symbolic link) | Нет | `L /run/alias - - - - /var/target` |
| `c` | Создать символьное устройство | Нет | `c /dev/null 0666 root root -` |
| `b` | Создать блочное устройство | Нет | `b /dev/sda 0660 root disk -` |
| `p` | Создать FIFO (First-In, First-Out) канал | Нет | `p /run/mypipe 0600 user group -` |
| `x` | Исключить путь из автоматической очистки | Нет | `x /tmp/important - - - -` |
| `X` | Исключить из очистки, но разрешить удаление старых | Да | `X /var/tmp/old 0755 user group 7d` |
| `r` | Удалить директорию рекурсивно при старте | Нет | `r /var/cache/old - - - -` |
| `R` | Удалить директорию и всё содержимое | Нет | `R /tmp/olddir - - - -` |
| `v` | Создать subvolume в Btrfs (B-tree File System) | Нет | `v /var/lib/subvol 0755 user group -` |
| `Z` | Рекурсивно восстановить права и контекст | Нет | `Z /var/log/app 0640 user group -` |

> Символ `-` означает использование значений по умолчанию или отсутствие параметра.

### Различие `/tmp` и `/var/tmp`

Обе директории предназначены для временных файлов, но отличаются типом ФС, поведением при перезагрузке и политикой очистки.

| Характеристика | `/tmp` | `/var/tmp` |
| :--- | :--- | :--- |
| **Тип ФС** | Чаще всего tmpfs (RAM + Swap) | Обычная дисковая ФС (ext4, xfs) |
| **Переживает перезагрузку** | Нет (данные теряются) | Да |
| **Очистка systemd-tmpfiles** | При каждой перезагрузке + по правилам | Раз в 30 дней по умолчанию |
| **Размер** | Ограничен RAM (обычно 50% от RAM) | Ограничен размером раздела |

**Что куда класть:**

- `/tmp` — данные, живущие в рамках одной сессии: Unix-сокеты, pipe-файлы, lock-файлы, промежуточные буферы процессов, временные файлы скриптов
- `/var/tmp` — данные, которые должны пережить перезагрузку: кеш пакетного менеджера (apt хранит скачанные пакеты в `/var/tmp`), временные файлы установщиков, данные, нужные после рестарта сервиса

**Проверка текущего состояния:**

```bash
# Посмотреть, что смонтировано как tmpfs
mount | grep tmp

# Посмотреть политики очистки для /tmp и /var/tmp
systemd-tmpfiles --cat-config | grep -E "tmp|var/tmp"
```

## Практические сценарии

### Настройка окружения для сервиса

Создание директории в `/run` (которая очищается при каждой перезагрузке) для хранения PID (Process ID) файла и сокета.

```ini
# /etc/tmpfiles.d/myservice.conf
# Тип  Путь                      Режим  Владелец Группа  Возраст Аргумент
d      /run/myservice            0750   myuser   mygroup -       -
f      /run/myservice/pid        0644   myuser   mygroup -       -
L      /run/myservice.sock       -      -        -       -       /run/myservice/actual.sock
```

### Автоматическая очистка временных данных

Удаление архивных логов старше 30 дней и очистка временного кэша каждые 24 часа.

```ini
# /etc/tmpfiles.d/cleanup-rules.conf
# Очищать файлы в директории по маске
X      /var/log/myapp/archive/*.gz  0640  myuser  mygroup  30d
# Директория с очисткой содержимого
D      /var/cache/myapp/temp        0750  myuser  mygroup  1d
```

### Управление конфигурацией через CLI

```bash
# Применить правила создания (create)
sudo systemd-tmpfiles --create
# → создание файлов и директорий согласно всем .conf файлам

# Выполнить очистку устаревших данных (clean)
sudo systemd-tmpfiles --clean
# → удаление файлов, чей срок жизни (Age) истек

# Удалить объекты согласно правилам r/R
sudo systemd-tmpfiles --remove
# → удаление указанных путей

# Проверка конфигурации без внесения изменений
sudo systemd-tmpfiles --create --dry-run
# → вывод планируемых действий без модификации ФС
```

### Настройка периодической очистки

Автоматическая очистка обычно управляется системным таймером.

```bash
# Проверить статус таймера очистки
systemctl status systemd-tmpfiles-clean.timer
# → Active: active (waiting) ...

# Активировать таймер
sudo systemctl enable --now systemd-tmpfiles-clean.timer
# → создание симлинка и запуск таймера
```

## Дополнительная информация

### Приоритеты обработки

Файлы в директориях конфигурации обрабатываются в алфавитном порядке имен файлов. Если одно и то же имя файла присутствует в нескольких директориях (например, в `/etc/` и `/usr/lib/`), то файл из `/etc/` имеет абсолютный приоритет, а остальные игнорируются.

### Интеграция с подсистемами

`systemd-tmpfiles` является критически важным компонентом для других служб `systemd`:

* **journald**: Использует правила для ротации и очистки бинарных журналов в `/var/log/journal`.
* **X11/Wayland**: Управляет сокетами в `/tmp/.X11-unix`.

### Меры безопасности

1. **Права доступа**: Избегайте использования `0777`. Для разделяемых директорий используйте `sticky bit` (например, `1777` для `/tmp`).
2. **Секреты**: Файлы, содержащие чувствительные данные, должны создаваться с правами `0600` и принадлежать соответствующему сервисному пользователю.
3. **Исключения**: Используйте тип `x`, чтобы предотвратить случайное удаление важных данных системными скриптами очистки.
