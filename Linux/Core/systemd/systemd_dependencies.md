# Управление зависимостями в systemd

## Определения

* **Зависимости (Dependencies)** — это механизмы системы инициализации `systemd`, определяющие логические взаимосвязи и временной порядок активации юнитов. Они обеспечивают предсказуемое состояние системы, гарантируя, что службы будут запущены только при наличии необходимых ресурсов.
* **Логическая зависимость** — определяет, должен ли один юнит быть активирован вместе с другим. Директивы: `Wants`, `Requires`, `Upholds`, `BindsTo`, `PartOf`.
* **Порядок запуска (Ordering)** — определяет временную последовательность выполнения (кто за кем), но **не создает** логическую связь. Директивы: `After`, `Before`.

## Основные концепции

### Типы логических директив

Для надежной работы всегда комбинируйте логическую связь с директивами порядка (`After`/`Before`).

| Директива | Уровень связи | Поведение |
| :--- | :--- | :--- |
| **`Wants=`** | Слабая | Пытается запустить зависимый юнит. Если он не сможет стартовать, основной юнит всё равно запустится. |
| **`Requires=`** | Сильная | Обязательный юнит. Если он не запустится, основной юнит завершится с ошибкой. |
| **`Upholds=`** | Активная | (v247+) Пока запущен основной юнит, `systemd` будет поддерживать зависимый юнит в рабочем состоянии (перезапуская его при падении). |
| **`Requisite=`** | Проверочная | Проверяет наличие запущенного юнита. Если он не запущен, основной юнит немедленно падает, не пытаясь запустить зависимый. |
| **`BindsTo=`** | Жесткая | Связывает жизненные циклы. Если зависимый юнит пропадает (например, отключено USB-устройство), основной юнит мгновенно останавливается. |
| **`PartOf=`** | Групповая | Передает команды `restart` и `stop` от родительского юнита к дочернему. Не влияет на автоматический запуск. |
| **`Conflicts=`** | Отрицательная | Взаимное исключение. Запуск одного юнита автоматически останавливает другой. |

### Директивы порядка запуска

| Директива | Поведение |
| :--- | :--- |
| **`After=`** | Текущий юнит начнет запуск только после того, как перечисленные юниты успешно активируются. |
| **`Before=`** | Текущий юнит должен завершить запуск до того, как начнется активация перечисленных юнитов. |

### Матрица поведения при сбоях

| Директива | Сбой при старте зависимости | Падение зависимости во время работы |
| :--- | :--- | :--- |
| **`Wants=`** | Юнит запускается | Ничего не происходит |
| **`Requires=`** | Юнит **не** запускается | Ничего не происходит (по умолчанию) |
| **`Upholds=`** | Юнит запускается | Зависимость перезапускается |
| **`BindsTo=`** | Юнит **не** запускается | Юнит немедленно **останавливается** |

## Практические сценарии

### Ожидание готовности интернета

Зависимость `After=network.target` гарантирует только запуск сетевого стека, но не получение IP-адреса. Для сервисов, требующих связи, используйте `network-online.target`.

```ini
[Unit]
Description=Cloud Sync Service
Wants=network-online.target
After=network-online.target
```

### Связка микросервиса с базой данных

Используйте `Requires` для обязательного наличия БД и `After` для корректного порядка инициализации.

```ini
[Unit]
Description=API Backend
Requires=postgresql.service
After=postgresql.service
```

### Поддержка вспомогательного сервиса (v247+)

Если приложению нужен вспомогательный агент (например, лог-форвардер), который должен работать всегда, пока живо приложение.

```ini
[Unit]
Description=Main Application
Upholds=fluent-bit.service
After=fluent-bit.service
```

### Привязка к физическому устройству

Если сервис работает со специфическим оборудованием.

```ini
[Unit]
Description=Backup to USB Drive
BindsTo=dev-sdb1.device
After=dev-sdb1.device
```

## Дополнительная информация

### Диагностика дерева зависимостей

Для проверки связей и поиска ошибок конфигурации используйте встроенные инструменты:

```bash
# Просмотр дерева юнитов, необходимых для работы сервиса
systemctl list-dependencies nginx.service
# → nginx.service
# → ├─system.slice
# → └─network.target

# Реверсивные зависимости: кто зависит от данного юнита
systemctl list-dependencies --reverse nginx.service
# → nginx.service
# → └─multi-user.target
```

### Визуализация и типичные ошибки

* **Циклические зависимости**: Ситуация «A зависит от B, B зависит от A». В логах это отображается как `Found ordering cycle on...`. В таких случаях `systemd` принудительно разрывает цикл, отключая один из юнитов.
* **Зависимость без порядка**: Частая ошибка — указать `Requires=` без `After=`. В этом случае оба юнита начнут запускаться одновременно, и основной юнит может упасть, так как зависимость еще не успела проинициализироваться.

```bash
# Визуализация критической цепочки загрузки
systemd-analyze critical-chain
# → multi-user.target @10.2s
# → └─docker.service @8.1s +2.1s
```
