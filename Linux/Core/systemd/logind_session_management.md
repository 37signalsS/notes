# Управление сессиями и пользователями через loginctl

## Определения

* **`systemd-logind`** — системный демон, ответственный за отслеживание входов пользователей, управление их сессиями, выделяемыми ресурсами и жизненным циклом процессов. Демон также обрабатывает системные события, такие как нажатие кнопок питания или закрытие крышки ноутбука.
* **`loginctl`** — утилита Интерфейса командной строки (CLI, Command Line Interface) для взаимодействия с демоном `logind`. Она позволяет анализировать состояние активных пользователей и управлять их сеансами в Операционной Системе (ОС).

## Основные концепции

### Ключевые объекты управления

| Объект | Описание |
| :--- | :--- |
| **Сессия (Session)** | Один сеанс входа пользователя в ОС: через Протокол защищенной оболочки (SSH, Secure Shell), локальный терминал Телетайпа (TTY, Teletypewriter) или графическую оболочку. Каждая сессия имеет уникальный Идентификатор (ID). |
| **Пользователь (User)** | Учетная запись, которой может принадлежать несколько параллельных сессий. Для каждого активного пользователя запускается отдельный экземпляр `systemd --user`. |
| **Рабочее место (Seat)** | Логическое объединение устройств ввода-вывода (монитор, клавиатура). На серверах обычно присутствует только `seat0`. |

По умолчанию `systemd` завершает все фоновые процессы пользователя, когда тот закрывает последнюю активную сессию. Для обхода этого ограничения используется режим постоянной работы — **linger**.

## Практические сценарии

### Мониторинг активности пользователей

Для диагностики текущих подключений и состояния пользователей используются следующие команды:

```bash
# Список всех активных сессий в системе
loginctl list-sessions
# → SESSION  UID  USER   SEAT   TTY
# → 1        1000 user   seat0  tty1

# Список всех пользователей, авторизованных в данный момент
loginctl list-users
# → UID  USER
# → 1000 user

# Подробная информация о конкретном пользователе
loginctl user-status 1000
# → отображение дерева Идентификаторов процессов (PID) пользователя и статуса linger
```

### Управление сеансами

Администратор может инспектировать и принудительно завершать сессии.

```bash
# Просмотр дерева процессов конкретной сессии
loginctl session-status 1
# → ● 1 - user (1000)
# →    Service: login; ...
# →    Process: 1234 /bin/bash

# Принудительное завершение конкретной сессии (логаут)
loginctl terminate-session 1

# Завершение всех сессий конкретного пользователя
loginctl terminate-user username
```

### Настройка постоянной работы процессов (Linger)

Активация режима `linger` необходима для сервисов, которые должны продолжать выполнение (например, боты или веб-серверы) после отключения пользователя от системы.

```bash
# Разрешить пользователю сохранять процессы без активной сессии
sudo loginctl enable-linger username

# Проверить текущее состояние параметра Linger
loginctl show-user username --property=Linger
# → Linger=yes
```
