# Управление сессиями и пользователями в systemd-logind

## Определения

* **`systemd-logind`** — системный демон, отвечающий за отслеживание пользовательских входов, управление их сессиями, выделение ресурсов (через cgroups) и обработку аппаратных событий (кнопки питания, крышка ноутбука).
* **`loginctl`** — утилита командной строки для взаимодействия с `logind`.
* **Сессия (Session)** — отдельный сеанс входа пользователя (SSH, TTY, GUI). Каждая сессия помещается в собственный scope-юнит.
* **Рабочее место (Seat)** — логическое объединение устройств ввода-вывода (монитор, клавиатура). `seat0` — стандартное рабочее место.
* **Linger (Постоянство)** — режим, позволяющий пользовательскому менеджеру `systemd --user` и процессам продолжать работу после закрытия всех сессий пользователя.

## Основные концепции

### Жизненный цикл сессии и процессов

По умолчанию `systemd` придерживается политики «чистого выхода». Когда пользователь закрывает последнюю сессию, `logind` останавливает его экземпляр `systemd --user` и завершает все оставшиеся процессы.

* **Параметр `KillUserProcesses=`** в `logind.conf` определяет это поведение (по умолчанию `yes` во многих дистрибутивах).
* **Исключение**: процессы, запущенные через `systemd-run --user` или в рамках режима `linger`, выживают.

### Обработка событий питания

`logind` перехватывает нажатия кнопок и закрытие крышки, выполняя настроенные действия (`ignore`, `poweroff`, `reboot`, `halt`, `suspend`, `hibernate`, `lock`).

Основные параметры `logind.conf`:
* `HandlePowerKey=` — нажатие кнопки питания.
* `HandleLidSwitch=` — закрытие крышки ноутбука.
* `HandlePowerKeyLongPress=` — (v250+) удержание кнопки более 5 секунд.

### Контекст выполнения (XDG_RUNTIME_DIR)

При входе пользователя `logind` (совместно с `pam_systemd`) создает временную директорию `/run/user/$UID`.
* Директория монтируется как `tmpfs`.
* Размер ограничен параметром `RuntimeDirectorySize=` (по умолчанию 10% RAM).
* Используется для хранения сокетов D-Bus, сессионных данных и временных файлов.

## Практические сценарии

### Мониторинг активности

```bash
# Список всех активных сессий
loginctl list-sessions
# → SESSION  UID  USER   SEAT   TTY
# → 2        1000 admin  seat0  tty2

# Список авторизованных пользователей
loginctl list-users
# → UID  USER
# → 1000 admin

# Статус конкретного пользователя (включая дерево процессов)
loginctl user-status admin
# → admin (1000)
# →    Since: Mon 2024-06-10 ...
# →    State: active
```

### Управление сеансами

```bash
# Принудительное завершение сессии (Logout)
sudo loginctl terminate-session 2

# Блокировка экрана (если поддерживается графической оболочкой)
loginctl lock-session 2

# Активация режима Linger для фоновых задач
sudo loginctl enable-linger admin
# → проверка: loginctl show-user admin --property=Linger
# → Linger=yes
```

### Автоматическое завершение простаивающих сессий (v252+)

В файле `/etc/systemd/logind.conf` можно настроить таймаут бездействия:
```ini
[Login]
StopIdleSessionSec=1h
```

## Дополнительная информация

### Рекомендации по настройке logind.conf

| Параметр | Рекомендуемое значение | Описание |
| :--- | :--- | :--- |
| `KillUserProcesses=` | `no` | Позволяет процессам (например, `tmux` или `screen`) продолжать работу после выхода из SSH. |
| `UserStopDelaySec=` | `10s` | Задержка перед остановкой пользовательского менеджера (ускоряет повторный вход). |
| `InhibitDelayMaxSec=` | `5s` | Максимальное время, которое приложения могут удерживать выключение системы. |
