# Управление сессиями и пользователями в systemd-logind

## Определения

* **`systemd-logind`** — системный демон, ответственный за управление жизненным циклом пользовательских сессий, рабочих мест (seats) и обработку аппаратных событий электропитания.
* **Сессия (Session)** — контекст активности пользователя (SSH, TTY, GUI). Каждая сессия изолирована в собственном scope-юните (`session-N.scope`) в рамках контрольных групп (cgroups).
* **Рабочее место (Seat)** — логическое объединение аппаратных ресурсов (видеокарта, USB-контроллер, устройства ввода), позволяющее организовать независимую работу нескольких пользователей на одном хосте.
* **Linger (Постоянство)** — состояние пользователя, при котором его менеджер сервисов (`systemd --user`) и фоновые процессы запускаются при загрузке системы и не завершаются после выхода из всех сессий.
* **Ингибитор (Inhibitor Lock)** — механизм, позволяющий приложениям временно блокировать или задерживать операции выключения, сна или перезагрузки для завершения критических задач (например, запись диска или завершение фоновых задач).
* **`pam_systemd.so`** — PAM-модуль, который создает сессию при аутентификации, экспортирует переменные окружения и регистрирует пользователя в `logind`.
* **`user@.service`** — системный шаблонный юнит, отвечающий за запуск пользовательского экземпляра менеджера `systemd --user`.
* **`user-$UID.slice`** — системный слайс cgroups, в котором работают все процессы пользовательских служб и сессии.
* **Scope-юнит (`session-N.scope`)** — объект systemd, представляющий группу процессов конкретной сессии. Создается автоматически при логине.
* **D-Bus API** — интерфейс межпроцессного взаимодействия, через который утилиты (`loginctl`, `systemd-run`) и приложения общаются с `logind`.

## Основные концепции

### Архитектура и интеграция с PAM

`systemd-logind` не работает изолированно. Жизненный цикл сессии инициируется модулем PAM `pam_systemd.so`, который вызывается при успешной аутентификации в `/etc/pam.d/system-login`:

```ini
# /etc/pam.d/system-login
session optional pam_systemd.so
```

При входе пользователя PAM-модуль:
1. Создает scope-юнит `session-N.scope` в системном менеджере.
2. Экспортирует переменные окружения (`XDG_RUNTIME_DIR`, `XDG_SESSION_ID` и др.).
3. Регистрирует сессию в `logind`, назначает её на `seat0`.
4. Активирует `user@<UID>.service`, который запускает `systemd --user`.
5. Применяет политики из `/etc/systemd/logind.conf`.

При выходе:
1. PAM-модуль уведомляет `logind` о завершении сессии.
2. `logind` останавливает `session-N.scope` (SIGTERM → SIGKILL).
3. Если linger отключен и это последняя сессия — останавливается `user@<UID>.service`.
4. Очищается `/run/user/$UID` (если не настроено иначе).

### Классификация сессий и типов

`systemd` различает сессии по их происхождению и функциональности.

| Параметр | Значения | Описание |
| :--- | :--- | :--- |
| **Type** | `unspecified`, `tty`, `x11`, `wayland`, `mir`, `web`, `manager` | `manager` (v256+) — техническая сессия для `user@.service`. |
| **Class** | `user`, `greeter`, `lock-screen`, `background`, `background-light` | `background-light` (v256+) — сессия без запуска менеджера сервисов. |
| **State** | `online`, `active`, `closing` | `active` — сессия находится на переднем плане (фокусе) рабочего места. |

### Жизненный цикл и переменные окружения

При создании сессии `pam_systemd` экспортирует ключевые переменные окружения:
* `XDG_SESSION_ID`: Уникальный числовой идентификатор.
* `XDG_SESSION_TYPE`: Тип графического стека или терминала.
* `XDG_RUNTIME_DIR`: Путь к временной директории в памяти (`/run/user/$UID`).
* `XDG_SEAT`: Название рабочего места (обычно `seat0`).

### Механизм ингибиторов (Inhibitor Locks)

Приложения могут запрашивать блокировки через D-Bus. Существует два режима:
1. **Block**: Операция запрещена, пока замок не будет снят.
2. **Delay**: Операция задерживается на время, указанное в `InhibitDelayMaxSec` (по умолчанию 5 секунд), давая приложению время на корректное завершение.

**Сигналы v255+**: `logind` отправляет сигнал `PrepareForShutdownWithMetadata`, который содержит тип операции: `shutdown`, `reboot` или `soft-reboot`.

### Политика завершения процессов

Параметр `KillUserProcesses` в `/etc/systemd/logind.conf` определяет судьбу процессов после выхода:
* `yes`: Все процессы пользователя в данной сессии завершаются (SIGTERM, затем SIGKILL).
* `no` (по умолчанию во многих серверных дистрибутивах): Процессы продолжают работу. Это позволяет использовать `tmux` или `screen` без активации Linger.

## Практические сценарии

### Анализ активных сессий

```bash
# Список всех сессий с краткими метаданными
loginctl list-sessions

# Получение детальной информации в формате JSON (удобно для скриптов)
loginctl list-sessions --output=json | jq

# Просмотр статуса конкретной сессии и дерева её процессов
loginctl session-status 2
```

### Управление состоянием пользователя

```bash
# Проверка, разрешен ли пользователю фоновый запуск процессов
loginctl show-user admin -p Linger
# → Linger=no

# Активация режима Linger (создает файл /var/lib/systemd/linger/admin)
sudo loginctl enable-linger admin

# Принудительное завершение всех сессий и процессов пользователя
sudo loginctl terminate-user admin
```

### Диагностика ингибиторов

Если система отказывается выключаться или засыпать, проверьте активные блокировки:
```bash
# Список всех активных ингибиторов
systemd-inhibit --list

# Запуск процесса с блокировкой выключения (пример)
systemd-inhibit --why="Важное обновление БД" --who="DB-Admin" --mode=block /usr/local/bin/db-maintenance.sh
```

### Ограничение ресурсов рантайма

Если `/run/user/$UID` (tmpfs) переполняется, можно изменить лимит в `logind.conf`:
```ini
[Login]
RuntimeDirectorySize=2G
# Задержка удаления менеджера после выхода (ускоряет повторный вход)
UserStopDelaySec=10s
```

### Анализ ресурсов сессии

```bash
# Просмотр cgroup-иерархии для конкретной сессии
systemd-cgls /session-N.scope

# Мониторинг потребления ресурсов сессией
systemd-cgtop -b --raw | grep session
```

## Диагностика и устранение неисправностей

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `Failed to connect to bus` | Отсутствует `$XDG_RUNTIME_DIR` или D-Bus не запущен. | Убедитесь, что сессия активна: `loginctl list-sessions`. Проверьте `pam_systemd.so` в `/etc/pam.d/system-login`. |
| `Linger не работает` | Пользователь не добавлен в `/var/lib/systemd/linger/`. | Выполните `sudo loginctl enable-linger <user>`. |
| `Процессы убиты при выходе` | `KillUserProcesses=yes` в `logind.conf`. | Измените на `no` или включите linger для нужных пользователей. |
| `Seat не переключается` | Нет активных сессий на целевом seat или оборудование недоступно. | Проверьте `loginctl list-seats`, `loginctl seat-status seat0`. |
| `Ингибитор блокирует shutdown` | Приложение не снимает блокировку. | `systemd-inhibit --list` для поиска; принудительно завершите процесс. |
| `Runtime directory full` | `/run/user/$UID` переполнен. | Увеличьте `RuntimeDirectorySize=` или очистите временные файлы. |
| `Session зависает в closing` | Процесс не отвечает на SIGTERM. | Увеличьте `UserStopDelaySec=` или принудительно завершите процессы. |

## Рекомендации по эксплуатации

1. **Валидация PAM:** Убедитесь, что `pam_systemd.so` присутствует в `/etc/pam.d/system-login` и `/etc/pam.d/sshd`. Без этого сессии не будут регистрироваться.
2. **Linger для сервисных аккаунтов:** Включайте `loginctl enable-linger` для всех сервисных аккаунтов, чьи фоновые службы должны работать без активной сессии.
3. **Ресурсы `/run`:** Мониторьте использование `/run/user/$UID` через `df -h /run/user/`. Настройте `RuntimeDirectorySize=` для серверов с большим количеством пользователей.
4. **Ингибиторы:** Используйте `systemd-inhibit` для критических операций (бэкапы, обновления), но избегайте бесконечных блокировок.
5. **Завершение сессий:** Используйте `loginctl terminate-session` вместо `kill -9` — это корректно очищает cgroup и ресурсы.
6. **Аудит:** Регулярно проверяйте `journalctl -u systemd-logind.service` на предмет аномалий (множественные быстрые входы/выходы).
7. **Seats:** На серверах обычно используется только `seat0`. Если вы используете несколько графических рабочих мест, проверяйте `loginctl list-seats`.
8. **KillUserProcesses:** На серверах с `tmux`/`screen` оставляйте `KillUserProcesses=no`. На рабочих станциях с общей доступностью используйте `yes`.

## Ограничения и крайние случаи

* **SSH сессии:** При разрыве SSH-соединения сессия завершается, но linger сохраняет фоновые процессы. `tmux`/`screen` процессы переparent'ятся в init, если linger отключен.
* **Многопользовательские seats:** Требуют графического сервера (Xorg, Wayland). На headless-серверах используется только `seat0`.
* **cgroup delegation:** На некоторых дистрибутивах доступные контроллеры cgroup для пользовательских сессий могут быть ограничены политиками системы.
* **Гонка переменных:** `XDG_RUNTIME_DIR` создается при логине. При использовании `sudo` или `su` переменная может отсутствовать — используйте `machinectl shell` или явно экспортируйте путь.
* **Быстрый вход/выход:** При частом переключении пользователей сессии могут накапливаться в `closing` состоянии. Настройте `UserStopDelaySec=` для ускорения очистки.
* **Session recording:** Встроенной записи сессий нет. Для аудита используйте `tlog` или `script` в сочетании с `auditd`.
* **PAM порядок:** `pam_systemd.so` должен быть в session-секции PAM. Если модуль отсутствует, сессии не создаются, linger не работает.

## Очистка и обслуживание

### Принудительное завершение сессий

```bash
# Завершение конкретной сессии
sudo loginctl terminate-session <SESSION_ID>

# Завершение всех сессий пользователя
sudo loginctl terminate-user username
```

### Управление linger

```bash
# Проверка статуса
loginctl show-user username -p Linger

# Включение/отключение
sudo loginctl enable-linger username
sudo loginctl disable-linger username

# Просмотр пользователей с включенным linger
ls /var/lib/systemd/linger/
```

### Мониторинг и аудит

```bash
# События logind в реальном времени
journalctl -u systemd-logind.service -f

# Статистика сессий
loginctl list-sessions --no-pager

# Проверка seat-ов
loginctl list-seats
loginctl seat-status seat0
```

## Дополнительная информация

### Конфигурация logind.conf

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| `HandleLidSwitch=` | `suspend` | Действие при закрытии крышки (ignore, lock, suspend, reboot). |
| `IdleAction=` | `ignore` | Действие при бездействии системы. |
| `IdleActionSec=` | `30min` | Время ожидания перед `IdleAction`. |
| `StopIdleSessionSec=`| `infinity`| (v252+) Автоматическое завершение простаивающих сессий. |
| `KillUserProcesses=` | `no` | Завершать ли процессы пользователя после выхода. |
| `RuntimeDirectorySize=` | `10%` | Лимит размера `/run/user/$UID` (tmpfs). |
| `UserStopDelaySec=` | `0` | Задержка перед остановкой `user@.service` после выхода. |
| `InhibitDelayMaxSec=` | `5` | Максимальная задержка для режима `delay` ингибиторов. |
