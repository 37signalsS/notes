# Управление сессиями и пользователями в systemd-logind

## Определения

* **`systemd-logind`** — системный демон, ответственный за управление жизненным циклом пользовательских сессий, рабочих мест (seats) и обработку аппаратных событий электропитания.
* **Сессия (Session)** — контекст активности пользователя (SSH, TTY, GUI). Каждая сессия изолирована в собственном scope-юните (`session-N.scope`) в рамках контрольных групп (cgroups).
* **Рабочее место (Seat)** — логическое объединение аппаратных ресурсов (видеокарта, USB-контроллер, устройства ввода), позволяющее организовать независимую работу нескольких пользователей на одном хосте.
* **Linger (Постоянство)** — состояние пользователя, при котором его менеджер сервисов (`systemd --user`) и фоновые процессы запускаются при загрузке системы и не завершаются после выхода из всех сессий.
* **Ингибитор (Inhibitor Lock)** — механизм, позволяющий приложениям временно блокировать или задерживать операции выключения, сна или перезагрузки для завершения критических задач (например, запись диска или завершение подов в Kubernetes).

## Основные концепции

### Классификация сессий и типов

`systemd` различает сессии по их происхождению и функциональности.

| Параметр | Значения | Описание |
| :--- | :--- | :--- |
| **Type** | `unspecified`, `tty`, `x11`, `wayland`, `mir`, `web`, `manager` | `manager` (v256+) — техническая сессия для `user@.service`. |
| **Class** | `user`, `greeter`, `lock-screen`, `background`, `background-light` | `background-light` (v256+) — сессия без запуска менеджера сервисов. |
| **State** | `online`, `active`, `closing` | `active` — сессия находится на переднем плане (фокусе) рабочего места. |

### Жизненный цикл и переменные окружения

При создании сессии `pam_systemd` экспортирует ключевые переменные окружения:
* `XDG_SESSION_ID`: Уникальный числовой идентификатор.
* `XDG_SESSION_TYPE`: Тип графического стека или терминала.
* `XDG_RUNTIME_DIR`: Путь к временной директории в памяти (`/run/user/$UID`).
* `XDG_SEAT`: Название рабочего места (обычно `seat0`).

### Механизм ингибиторов (Inhibitor Locks)

Приложения могут запрашивать блокировки через D-Bus. Существует два режима:
1. **Block**: Операция запрещена, пока замок не будет снят.
2. **Delay**: Операция задерживается на время, указанное в `InhibitDelayMaxSec` (по умолчанию 5 секунд), давая приложению время на корректное завершение.

**Сигналы v255+**: `logind` отправляет сигнал `PrepareForShutdownWithMetadata`, который содержит тип операции: `shutdown`, `reboot` или `soft-reboot`.

### Политика завершения процессов

Параметр `KillUserProcesses` в `/etc/systemd/logind.conf` определяет судьбу процессов после выхода:
* `yes`: Все процессы пользователя в данной сессии завершаются (SIGTERM, затем SIGKILL).
* `no` (по умолчанию во многих серверных дистрибутивах): Процессы продолжают работу. Это позволяет использовать `tmux` или `screen` без активации Linger.

## Практические сценарии

### Анализ активных сессий

```bash
# Список всех сессий с краткими метаданными
loginctl list-sessions

# Получение детальной информации в формате JSON (удобно для скриптов)
loginctl list-sessions --output=json | jq

# Просмотр статуса конкретной сессии и дерева её процессов
loginctl session-status 2
```

### Управление состоянием пользователя

```bash
# Проверка, разрешен ли пользователю фоновый запуск процессов
loginctl show-user admin -p Linger
# → Linger=no

# Активация режима Linger (создает файл /var/lib/systemd/linger/admin)
sudo loginctl enable-linger admin

# Принудительное завершение всех сессий и процессов пользователя
sudo loginctl terminate-user admin
```

### Диагностика ингибиторов

Если система отказывается выключаться или засыпать, проверьте активные блокировки:
```bash
# Список всех активных ингибиторов
systemd-inhibit --list

# Запуск процесса с блокировкой выключения (пример)
systemd-inhibit --why="Важное обновление БД" --who="DB-Admin" --mode=block /usr/local/bin/db-maintenance.sh
```

### Ограничение ресурсов рантайма

Если `/run/user/$UID` (tmpfs) переполняется, можно изменить лимит в `logind.conf`:
```ini
[Login]
RuntimeDirectorySize=2G
# Задержка удаления менеджера после выхода (ускоряет повторный вход)
UserStopDelaySec=10s
```

## Дополнительная информация

### Конфигурация logind.conf

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| `HandleLidSwitch=` | `suspend` | Действие при закрытии крышки (ignore, lock, suspend, reboot). |
| `IdleAction=` | `ignore` | Действие при бездействии системы. |
| `IdleActionSec=` | `30min` | Время ожидания перед `IdleAction`. |
| `StopIdleSessionSec=`| `infinity`| (v252+) Автоматическое завершение простаивающих сессий. |
