# Синхронизация времени (NTP) в systemd

Точное время критически важно для работы многих системных служб, логирования и криптографии. `systemd` предоставляет встроенные инструменты для управления временем и его синхронизацией по сети с помощью протокола NTP (Network Time Protocol).

## `timedatectl`: Управление временем и датой

`timedatectl` — это основной инструмент для просмотра и изменения системного времени, даты и часового пояса.

```bash
# Показать текущий статус времени, включая статус синхронизации NTP
timedatectl status

# Включить или отключить синхронизацию по NTP
sudo timedatectl set-ntp true

# Установить часовой пояс
sudo timedatectl set-timezone Europe/Moscow
```

## `systemd-timesyncd`: Встроенный клиент NTP

`systemd-timesyncd` — это легковесный клиент SNTP (простая версия NTP), который встроен в `systemd`. Он предназначен для простых задач синхронизации и подходит для большинства клиентских машин и серверов, не требующих высочайшей точности.

-   **Статус:** Управляется через `timedatectl`.
-   **Конфигурация:** `/etc/systemd/timesyncd.conf`. Здесь можно указать кастомные NTP-серверы.
-   **Просмотр логов:**
    ```bash
    journalctl -u systemd-timesyncd
    ```

## `Chrony`: Продвинутый демон NTP

Для серверов, требующих высокой точности времени или работающих в сложных сетевых условиях, `chrony` является предпочтительной реализацией NTP. Он работает лучше при нестабильном интернет-соединении и быстрее синхронизирует время.

-   **Установка:** `sudo apt install chrony` или `sudo dnf install chrony`.
-   **Конфигурация:** `/etc/chrony/chrony.conf` (для RHEL-based систем) или `/etc/chrony.conf` (для Debian-based).
-   **Управление и диагностика (`chronyc`):**

    ```bash
    # Проверить источники времени и их статус
    chronyc sources

    # Показать детальную информацию о синхронизации
    chronyc tracking
    ```

-   **Важно:** При установке `chrony` он обычно автоматически отключает `systemd-timesyncd`, чтобы избежать конфликтов. `Chrony` является предпочтительным демоном времени для большинства современных систем благодаря своей точности и способности быстро адаптироваться к изменяющимся условиям сети.

### Настройка Chrony с аппаратным источником времени (GPS/PPS)

Когда в сети критично точное время (финансовые транзакции, логирование событий, биллинг, Kerberos), не стоит полагаться только на внешние NTP-сервера. Лучше настроить локальный time-сервер с аппаратным источником времени, таким как GPS-приемник.

**1. Аппаратный источник**
*   **GPS-приёмник с поддержкой PPS (Pulse Per Second):** Например, u-blox NEO, Garmin GPS 18x LVC. Сигнал PPS обеспечивает чрезвычайно точную метку начала каждой секунды.
*   **USB RTC-модули:** Более дешевая альтернатива, например, на базе чипов DS3231, которые предоставляют более стабильные аппаратные часы, чем стандартные системные.

**2. Установка ПО**
Для работы с GPS-приемником нам понадобятся `chrony`, `gpsd` и `gpsd-clients`. `gpsd` будет получать данные с GPS-устройства и передавать их `chrony` через разделяемую память (SHM).

```bash
sudo apt install chrony gpsd gpsd-clients
```

**3. Пример конфигурации `chrony.conf`**

Отредактируйте файл `/etc/chrony/chrony.conf`, чтобы он использовал GPS-данные.

```ini
# Удалите или закомментируйте стандартные пулы серверов (pool.ntp.org и т.д.)

# Ссылка на разделяемую память (SHM) от gpsd для получения времени
refclock SHM 0 refid GPS precision 1e-1

# Ссылка на сокет с сигналом PPS для высочайшей точности
# ttyS0 - это пример последовательного порта, к которому подключен PPS
refclock SOCK /var/run/chrony.ttyS0.sock refid PPS lock GPS

# Разрешить клиентам из локальной сети синхронизироваться с этим сервером
allow 192.168.0.0/16

# Объявить себя сервером с низким stratum, чтобы клиенты предпочитали нас
# даже если мы временно потеряем связь с GPS
local stratum 10
```

**4. Проверка**

После настройки и перезапуска `chrony` проверьте статус источников времени:
```bash
chronyc sources -v
```

Вы должны увидеть источники `GPS` и `PPS` в списке. Звездочка `*` рядом с `PPS` или `GPS` будет означать, что `chrony` успешно синхронизировался с этим источником.

Пример вывода:
```
MS Name/IP address         Stratum Poll Reach LastRx Last sample               
===============================================================================
#* GPS                           0   4   377    11   -263ns[ -379ns] +/-  104ms
#? PPS                           0   4   377    10   -501ns[ -617ns] +/- 1598ns
```
Здесь `chrony` использует `GPS` как основной источник времени.
