# Синхронизация времени в systemd

## Определения

* **`systemd-timesyncd`** — встроенный в `systemd` легковесный клиент протокола SNTP (Simple Network Time Protocol), предназначенный для синхронизации системных часов с удаленными серверами времени. Он заменяет полноценные серверы NTP (например, `ntpd`) в сценариях, где не требуется раздача времени другим узлам.
* **`timedatectl`** — утилита командной строки для управления системным временем, датой, часовыми поясами и службой синхронизации.
* **Stratum (Слой)** — показатель удаленности от эталонного источника времени (Stratum 0). Чем ниже число, тем выше точность.

## Основные концепции

### Системные и аппаратные часы (RTC)

В Linux существует два независимых счетчика времени:
1. **System Clock** — программные часы, поддерживаемые ядром. Именно их используют все приложения.
2. **RTC (Real Time Clock)** — аппаратные часы на материнской плате, работающие от батарейки. Нужны для сохранения времени при выключении питания.

**Рекомендация**: Всегда храните время в RTC в формате **UTC**. Использование локального времени (Local Time) приводит к проблемам при переходе на летнее/зимнее время и часто используется только в конфигурациях с Dual-boot (Windows).

### Системы без аппаратных часов

На устройствах вроде Raspberry Pi, где отсутствует RTC, `systemd-timesyncd` использует механизм сохранения состояния:
* **`SaveIntervalSec=`** — (v250+) интервал периодической записи текущего времени на диск.
* При загрузке система восстанавливает время из этой записи, предотвращая «прыжки» в 1970 год до момента установки связи с NTP-сервером.

## Практические сценарии

### Просмотр текущего статуса

```bash
timedatectl status
# →                Local time: Пн 2024-06-10 15:30:00 MSK
# →            Universal time: Пн 2024-06-10 12:30:00 UTC
# →                  RTC time: Пн 2024-06-10 12:30:00
# →                 Time zone: Europe/Moscow (MSK, +0300)
# → System clock synchronized: yes
# →               NTP service: active
# →           RTC in local TZ: no
```

### Диагностика синхронизации

```bash
# Человекочитаемый отчет о текущем сервере
timedatectl timesync-status
# →        Server: 162.159.200.1 (0.pool.ntp.org)
# → Poll interval: 34min 8s (min: 32s; max 34min 8s)
# →        Leap: normal
# →     Version: 4
# →     Stratum: 3
# →      Offset: -1.234ms
# →       Delay: 45.678ms
# →      Jitter: 0.567ms

# Машиночитаемый вывод всех параметров
timedatectl show-timesync --all
```

### Настройка серверов времени

Файл конфигурации: `/etc/systemd/timesyncd.conf`

```ini
[Time]
NTP=0.pool.ntp.org 1.pool.ntp.org
FallbackNTP=ntp.ubuntu.com
# Максимально допустимая задержка (по умолчанию 5s)
RootDistanceMaxSec=5
# Интервал сохранения времени на диск (для систем без RTC)
SaveIntervalSec=60
```

**Применение настроек:**
```bash
sudo systemctl restart systemd-timesyncd
```

### Управление часовыми поясами

```bash
# Поиск нужного пояса
timedatectl list-timezones | grep London

# Установка
sudo timedatectl set-timezone Europe/London
```

## Дополнительная информация

### Взаимодействие с другими NTP-клиентами

Если в системе установлен сторонний демон (например, `chrony` или `ntpd`), `systemd-timedated` автоматически определяет это. В таком случае `systemd-timesyncd` будет отключен, чтобы избежать конфликтов. Для сложных сетевых конфигураций (нужна роль сервера, поддержка PTP или высокая точность) рекомендуется переход на Chrony.
