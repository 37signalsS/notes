# Синхронизация времени в systemd

## Определения

* **NTP (Network Time Protocol):** Протокол для синхронизации внутренних часов компьютеров через сети с переменной латентностью.
* **`systemd-timesyncd`:** Легковесный клиент SNTP (Simple NTP), встроенный в `systemd`, предназначенный для базовой синхронизации времени на клиентских машинах и серверах, не требующих максимальной точности.
* **`Chrony`:** Более продвинутый демон NTP, предпочтительный для серверов, которым требуется высокая точность времени и стабильная работа в сложных сетевых условиях.

## Основные концепции

`systemd` предлагает встроенные инструменты для управления временем и его синхронизацией. Основным инструментом командной строки для настройки системного времени, даты и часового пояса является `timedatectl`.

### Утилиты для работы со временем

* **`timedatectl`:** Универсальная утилита для управления системными часами, часовым поясом и синхронизацией NTP.
  * Просмотр текущего статуса времени, включая статус синхронизации NTP:

        ```bash
        timedatectl status
        ```

  * Включение или отключение синхронизации по NTP (используя `systemd-timesyncd` по умолчанию):

        ```bash
        sudo timedatectl set-ntp true
        ```

  * Установка часового пояса:

        ```bash
        sudo timedatectl set-timezone Europe/Moscow
        ```

  * Просмотр списка доступных часовых поясов:

        ```bash
        timedatectl list-timezones
        ```

  * Управление режимом RTC (Real Time Clock): Linux по умолчанию считает, что RTC хранит время в UTC. Для совместимости с Windows (dual-boot) можно настроить использование локального времени:

        ```bash
        # Показать текущую настройку (0 = UTC, 1 = local)
        timedatectl status
        # Установить локальное время для RTC (для Windows dual-boot)
        sudo timedatectl set-local-rtc 1
        ```

* **`date`:** Утилита для просмотра и установки системного времени.

  * Просмотр текущего времени:

        ```bash
        date
        ```

  * Установка системного времени:

        ```bash
        sudo date -s "2024-01-15 10:30:00"
        ```

* **`hwclock`:** Утилита для работы с аппаратными часами (RTC).

  * Просмотр времени на RTC (硬件ные часы):

        ```bash
        sudo hwclock
        ```

  * Синхронизация системного времени в RTC:

        ```bash
        sudo hwclock --systohc
        ```

  * Синхронизация RTC в системное время:

        ```bash
        sudo hwclock --hctosys
        ```

### NTP и Stratum

NTP (Network Time Protocol) работает по иерархической системе уровней (stratum):
- **Stratum 0**: Атомные часы, GPS-приемники и другие высокоточные источники времени.
- **Stratum 1**: Серверы, синхронизирующиеся напрямую со Stratum 0.
- **Stratum 2**: Серверы, синхронизирующиеся со Stratum 1, и т.д.
- Максимальный уровень: 15.

Для обычных систем рекомендуется использовать публичные пулы NTP-серверов, такие как [pool.ntp.org](https://www.ntp.org/).

## Практические сценарии

### 1. Базовая синхронизация с `systemd-timesyncd`

`systemd-timesyncd` является клиентом SNTP (простая версия NTP) по умолчанию в `systemd` и подходит для большинства общих сценариев.

* **Конфигурация:** Основные настройки, включая указание кастомных NTP-серверов, можно задать в файле `/etc/systemd/timesyncd.conf`.
* **Просмотр логов:** Для диагностики работы `systemd-timesyncd`:

    ```bash
    journalctl -u systemd-timesyncd
    ```

### 2. Продвинутая синхронизация с `Chrony`

Для систем, требующих более высокой точности или работающих в условиях нестабильной сети, рекомендуется использовать `chrony`. При установке `chrony` обычно автоматически отключает `systemd-timesyncd` во избежание конфликтов.

* **Установка:**
  * Для Debian-подобных систем: `sudo apt install chrony`
  * Для RHEL-подобных систем: `sudo dnf install chrony`
* **Конфигурация:** Основной файл конфигурации:
  * `/etc/chrony/chrony.conf` (для RHEL-подобных)
  * `/etc/chrony.conf` (для Debian-подобных)

#### Настройка Chrony в качестве клиента

* **Использование пула серверов (рекомендуется):**

    ```ini
    # Для RHEL-подобных систем
    pool pool.ntp.org iburst
    
    # Или указание конкретных серверов
    # server 0.pool.ntp.org iburst
    # server 1.pool.ntp.org iburst
    # server 2.pool.ntp.org iburst
    # server 3.pool.ntp.org iburst
    ```

    * `pool`: Директива для использования DNS-имени, которое разрешается в несколько IP-адресов (рекомендуется для балансировки нагрузки).
    * `iburst`: Опция для ускорения начальной синхронизации при запуске сервиса. Отправляет несколько запросов вместо одного, что значительно сокращает время начальной синхро Нанизации.

####стройка Chrony в качестве NTP-сервера

Чтобы раздавать время другим машинам в локальной сети:

```ini
# Разрешить доступ для клиентов из указанных сетей
allow 192.168.10.0/24
allow 192.168.31.0/24

# Объявить себя сервером с указанным stratum при отсутствии интернета
# Позволяет раздавать время даже в изолированной сети
local stratum 10
```

* **`allow`**: Директива для разрешения синхронизации клиентам из указанной сети или хоста.
* **`local stratum`**: Позволяет chrony продолжать раздавать время, даже если нет связи с внешними NTP-серверами. Указывает stratum уровень, который будет объявлен клиентам.

#### Управление и диагностика (`chronyc`)

* Проверка источников времени и их статуса:

        ```bash
        chronyc sources
        ```

    * Символ `*` указывает на активный источник, с которым в данный момент синхронизируется система.
    * Символ `+` указывает на пригодные источники, которые могут использоваться в комбинации.
    * Символ `-` указывает на непригодные источники.
    * Символ `?` указывает на недоступные источники.

* Детальная информация о синхронизации:

        ```bash
        chronyc tracking
        ```

### 3. Настройка `Chrony` с аппаратным источником времени (GPS/PPS)

Для критически важных систем, где требуется максимально возможная точность времени (например, финансовые транзакции, биллинг, Kerberos), рекомендуется использовать локальный NTP-сервер с аппаратным источником времени (GPS-приемник с PPS или USB RTC-модуль).

* **Необходимое ПО:** Для работы с GPS-приемником требуются `chrony`, `gpsd` и `gpsd-clients`. `gpsd` получает данные с GPS-устройства и передает их `chrony` через разделяемую память (SHM).

    ```bash
    sudo apt install chrony gpsd gpsd-clients
    ```

* **Пример конфигурации `/etc/chrony/chrony.conf`:**

    ```ini
    # Удалите или закомментируйте стандартные пулы серверов (pool.ntp.org и т.д.)

    # Ссылка на разделяемую память (SHM) от gpsd для получения времени
    refclock SHM 0 refid GPS precision 1e-1

    # Ссылка на сокет с сигналом PPS для высочайшей точности
    # ttyS0 - это пример последовательного порта, к которому подключен PPS
    refclock SOCK /var/run/chrony.ttyS0.sock refid PPS lock GPS

    # Разрешить клиентам из локальной сети синхронизироваться с этим сервером
    allow 192.168.0.0/16

    # Объявить себя сервером с низким stratum, чтобы клиенты предпочитали нас
    # даже если мы временно потеряем связь с GPS
    local stratum 10
    ```

* **Проверка:** После настройки и перезапуска `chrony` проверьте статус источников времени:

    ```bash
    chronyc sources -v
    ```

    В выводе должны появиться источники `GPS` и `PPS`. Звездочка (`*`) рядом с `PPS` или `GPS` указывает на успешную синхронизацию с этим источником.

    Пример вывода:

    ```
    MS Name/IP address         Stratum Poll Reach LastRx Last sample
    ===============================================================================
    #* GPS                           0   4   377    11   -263ns[ -379ns] +/-  104ms
    #? PPS                           0   4   377    10   -501ns[ -617ns] +/- 1598ns
    ```

    В данном примере `chrony` использует `GPS` как основной источник времени.
