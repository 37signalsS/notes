# Таймеры systemd

## Определения

* **systemd Timers** — механизм планирования задач в системе инициализации `systemd`, современная альтернатива классическому демону `cron`. Таймер активирует соответствующий `.service` юнит (unit) по заданному расписанию или относительно определенного события.
* **Юнит сервиса (`.service`)** — описывает исполняемую задачу (что делать).
* **Юнит таймера (`.timer`)** — описывает расписание или условия запуска (когда делать).

Для корректной работы по умолчанию имена этих файлов должны совпадать (например, `backup.service` и `backup.timer`).

## Основные концепции

### Преимущества перед cron

| Характеристика | cron | systemd Timers |
| :--- | :--- | :--- |
| Логирование | Email/файлы (нестандартно) | `journald` (централизованное, с метаданными) |
| Пропущенные задачи | Не выполняются (кроме anacron) | `Persistent=true` — выполнение сразу после загрузки ОС |
| Зависимости | Отсутствуют | Полная поддержка `After=`, `Requires=`, `Wants=` |
| Ограничение ресурсов | Ограничено (nice/ionice) | Поддержка cgroups (`MemoryMax=`, `CPUQuota=`) |
| Точность и питание | Фиксированная (1 мин) | Группировка событий (`AccuracySec`) для экономии энергии |
| Параллелизм | Ограничено | Каждый запуск — изолированный процесс в своем слайсе |

### Типы триггеров таймеров

Существует два основных типа триггеров: монотонные (относительные) и календарные (абсолютные).

| Директива | Отсчёт времени | Когда использовать |
| :--- | :--- | :--- |
| `OnCalendar=` | Календарное (абсолютное) | Ежедневные/еженедельные задачи |
| `OnActiveSec=` | С момента активации таймера | Отложенный запуск после старта системы |
| `OnBootSec=` | С момента загрузки системы | Задачи, выполняемые при старте ОС |
| `OnUnitActiveSec=` | С момента последнего запуска юнита | Периодический повтор выполнения |
| `OnUnitInactiveSec=` | С момента последнего завершения | Запуск после периода простоя |
| `OnClockChange=` | Изменение системных часов | Реагирование на корректировку NTP или ручное изменение |
| `OnTimezoneChange=` | Изменение часового пояса | Обновление настроек при смене локации |

### Ключевые параметры секции [Timer]

* **`Persistent=true`** — если задача была пропущена (например, компьютер был выключен), она запустится немедленно при следующем включении. Требует наличия диска для хранения состояния.
* **`WakeSystem=true`** — позволяет таймеру пробуждать систему из режима сна (suspend) для выполнения задачи.
* **`AccuracySec=`** — окно точности (по умолчанию 1 мин). Увеличение значения позволяет системе реже "просыпаться", объединяя запуски разных таймеров, что экономит заряд батареи.
* **`RandomizedDelaySec=`** — добавляет случайную задержку, чтобы предотвратить одновременный запуск тяжелых задач на множестве серверов.
* **`FixedRandomDelay=true`** — делает случайную задержку постоянной для конкретного таймера (вычисляется на основе Machine ID), исключая "дребезг" времени запуска между перезагрузками.

## Практические сценарии

### Настройка ежедневного бэкапа

**Сервис** (`/etc/systemd/system/db-backup.service`):
```ini
[Unit]
Description=Database Backup Task

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup-db.sh
```

**Таймер** (`/etc/systemd/system/db-backup.timer`):
```ini
[Unit]
Description=Run database backup daily

[Timer]
OnCalendar=daily
Persistent=true
RandomizedDelaySec=15min
FixedRandomDelay=true

[Install]
WantedBy=timers.target
```

### Периодическая очистка кэша (раз в 15 минут)

```ini
[Timer]
OnBootSec=5min
OnUnitActiveSec=15min
AccuracySec=1s
```
Первый запуск через 5 минут после загрузки, далее — каждые 15 минут с момента последнего запуска.

### Пользовательские таймеры

Таймеры можно запускать от имени пользователя без прав root. Конфигурация размещается в `~/.config/systemd/user/`.

```bash
# Управление пользовательскими таймерами
systemctl --user enable --now my-task.timer
systemctl --user list-timers
```

## Диагностика и управление

```bash
# Просмотр всех таймеров в системе
systemctl list-timers --all
# → NEXT                         LEFT          LAST                         PASSED    UNIT                         ACTIVATES
# → Mon 2024-06-10 00:00:00 UTC  10h left      Sun 2024-06-09 00:00:05 UTC  13h ago   db-backup.timer              db-backup.service

# Проверка синтаксиса календаря
systemd-analyze calendar "weekly"
# →  Next elapse: Mon 2024-06-10 00:00:00 UTC
# →  From now: 10h left

# Просмотр логов срабатывания
journalctl -u db-backup.timer
# → Jun 09 00:00:05 server systemd[1]: db-backup.timer: Deployed...
```

## Дополнительная информация

### Форматы OnCalendar

* **Сокращения:** `minutely`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`.
* **Дни недели:** `Mon, Tue, Wed, Thu, Fri, Sat, Sun`. Пример: `Mon..Fri 10:00`.
* **Интервалы:** `*-*-* 00/2:00:00` (каждые 2 часа).
* **Специфические даты:** `*-*-01 04:00:00` (первое число каждого месяца).
