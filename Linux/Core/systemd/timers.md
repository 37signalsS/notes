# systemd Timers

## Определения

**systemd Timers** — механизм планирования задач в `systemd`, альтернатива `cron`. Таймер активирует соответствующий `.service` юнит по расписанию или относительно события. Для задачи требуется два файла: `.service` (что делать) и `.timer` (когда делать). Имена файлов должны совпадать.

> Временные таймеры без файлов: [systemd_run.md](./systemd_run.md). Базовая синхронизация времени: [time_synchronization.md](./time_synchronization.md).

## Базовые концепции

### Преимущества перед cron

| Характеристика | cron | systemd Timers |
| :--- | :--- | :--- |
| Логирование | Email/файлы (нестандартно) | `journald` (централизованное) |
| Пропущенные задачи | Не выполняются | `Persistent=true` — выполнение после загрузки |
| Зависимости | Нет (run at boot — проблема) | Полная поддержка `After=`, `Requires=` |
| Ограничение ресурсов | Нет (только `nice`) | `MemoryMax=`, `CPUQuota=` и др. |
| Часовые пояса | Системный (проблемы при изменении) | `OnCalendar=` использует локальное, `OnBootSec=` — монотонное |
| Параллелизм | Ограничено | Неограничено, каждый таймер — отдельный юнит |

### Типы триггеров таймеров

| Директива | Тип | Отсчёт | Когда использовать |
| :--- | :--- | :--- | :--- |
| `OnCalendar=` | Реальное время | Абсолютное расписание | Ежедневные/еженедельные задачи |
| `OnActiveSec=` | Монотонное время | После активации таймера | Отложенный первый запуск |
| `OnBootSec=` | Монотонное время | После загрузки системы | Задачи после boot |
| `OnStartupSec=` | Монотонное время | После запуска systemd | Однократная задача при старте |
| `OnUnitActiveSec=` | Монотонное время | После последнего запуска юнита | Периодический запуск |
| `OnUnitInactiveSec=` | Монотонное время | После последнего завершения юнита | Запуск после простоя |

### Ключевые директивы [Timer]

| Директива | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `OnCalendar=` | Расписание (календарное выражение) | — |
| `Persistent=` | Выполнить пропущенный запуск после загрузки | `false` |
| `AccuracySec=` | Точность запуска | `1min` |
| `RandomizedDelaySec=` | Случайная задержка (избегание пиков) | `0` |
| `Unit=` | Юнит для активации (если не совпадает с именем таймера) |同名 `.service` |
| `RemainAfterElapse=` | Оставить таймер активным после срабатывания (для одноразовых) | `false` |

## Практические сценарии

### Ежедневный бэкап

**Сервис** (`/etc/systemd/system/my_backup.service`):

```ini
[Unit]
Description=My Backup Script

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

**Таймер** (`/etc/systemd/system/my_backup.timer`):

```ini
[Unit]
Description=Run backup daily at 2 AM

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
AccuracySec=1s

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable --now my_backup.timer
```

> `Persistent=true` — если сервер был выключен в 2:00, бэкап выполнится при следующей загрузке. `AccuracySec=1s` — точный запуск (по умолчанию `1min`).

### Периодическая задача каждые 15 минут

```ini
[Timer]
OnUnitActiveSec=15min
OnBootSec=5min
```

Первый запуск через 5 минут после загрузки, далее — каждые 15 минут от предыдущего запуска.

### Запуск в определённое время с рандомизацией

```ini
[Timer]
OnCalendar=*-*-* 03:00:00
RandomizedDelaySec=300
Persistent=true
```

Запуск между 03:00 и 03:05 — полезно, если на нескольких серверах одинаковая задача и нужно избежать одновременной нагрузки.

### Одноразовый отложенный запуск

```ini
[Timer]
OnActiveSec=10min
RemainAfterElapse=true
```

Выполнится один раз через 10 минут после активации таймера. `RemainAfterElapse=true` оставляет таймер видимым в `list-timers`.

### Активация сервиса с другим именем

```ini
# /etc/systemd/system/maintenance.timer
[Timer]
OnCalendar=Sun *-*-* 04:00:00
Unit=weekly-cleanup.service
Persistent=true
```

Таймер `maintenance.timer` активирует `weekly-cleanup.service`. Без `Unit=` systemd ищет `maintenance.service`.

### Управление таймером

```bash
# Перечитать конфигурацию
sudo systemctl daemon-reload

# Включить и запустить
sudo systemctl enable --now my_backup.timer

# Проверить все таймеры
systemctl list-timers --all

# Логи таймера
journalctl -u my_backup.timer

# Логи задачи
journalctl -u my_backup.service

# Статус таймера
systemctl status my_backup.timer
```

## Дополнительная информация

### Форматы OnCalendar

| Формат | Описание | Пример |
| :--- | :--- | :--- |
| `*-*-* HH:MM:SS` | Ежедневно | `*-*-* 02:00:00` |
| `DOW *-*-* HH:MM:SS` | День недели | `Mon *-*-* 09:00:00` |
| `*-*-* HH:MM:SS/N` | Каждые N часов | `*-*-* 00:00:00/2` |
| `*-*-DD HH:MM:SS` | Определённое число | `*-*-01 03:00:00` (1-е число) |
| `*-*-WXXN HH:MM:SS` | N-я неделя месяца | `*-*-Wed1 12:00:00` |
| `*-*-1..7 HH:MM:SS` | Диапазон чисел | `*-*-1..7 02:00:00` |
| `hourly`, `daily`, `weekly`, `monthly`, `yearly` | Сокращения | `OnCalendar=daily` = `*-*-* 00:00:00` |

Проверка корректности расписания:

```bash
systemd-analyze calendar "*-*-* 02:00:00"
systemd-analyze calendar "Mon *-*-* 09:00:00"
```

### Специальные таргеты

| Таргет | Назначение |
| :--- | :--- |
| `timers.target` | Стандартный таргет для всех таймеров |
| `hourly.target` | Почасовые задачи |
| `daily.target` | Ежедневные задачи |
| `weekly.target` | Еженедельные задачи |
| `monthly.target` | Ежемесячные задачи |

### Типичные проблемы

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Неточное время срабатывания | `AccuracySec=1m` (по умолчанию) | Установить `AccuracySec=1s` |
| Таймер не виден | Не включён (`enable`) | `sudo systemctl enable <timer>` |
| Таймер не запускает сервис | Неверное имя `.service` | Указать `Unit=` или переименовать сервис |
| Запуск сразу после загрузки | `Persistent=true` наверстывает | Установить `Persistent=false`, если нежелательно |
| Таймер срабатывает не в то время | Неверный часовой пояс | Проверить `timedatectl`, убедиться в корректности |

### Отличия от systemd-run --on-calendar

| Характеристика | Timer-файл | `systemd-run --on-calendar` |
| :--- | :--- | :--- |
| Сохранение | Постоянный (файл на диске) | Временный (до перезагрузки) |
| Редактирование | Через файл, `daemon-reload` | Нельзя изменить, только удалить и создать |
| Применение | Продакшен, регулярные задачи | Быстрое тестирование, отладка |

Подробности о временных таймерах: [systemd_run.md](./systemd_run.md).
