# systemd Timers

## Определения

**systemd Timers** — это механизм планирования задач в операционных системах, использующих `systemd`, предоставляющий альтернативу традиционному `cron`.

## Базовые концепции

`systemd Timers` глубоко интегрированы в экосистему `systemd` и имеют ряд преимуществ перед `cron`:

* **Интеграция:** Глубокая интеграция с `systemd`, использование юнитов.
* **Надежность:** Гарантированное выполнение задач после загрузки системы, если время было пропущено (параметр `Persistent=true`).
* **Зависимости:** Поддержка зависимостей между юнитами `systemd`.
* **Логирование:** Централизованное и надежное логирование всех запусков и их результатов через `journald`.

Для планирования задачи с помощью `systemd` требуется два файла:

1. **Файл службы (`.service`):** Описывает *что* нужно сделать (например, `/etc/systemd/system/my_backup.service`).
2. **Файл таймера (`.timer`):** Описывает *когда* это нужно сделать. Имя файла таймера должно совпадать с именем файла службы.

## Практические сценарии

### Пример планирования ежедневного бэкапа

**1. Файл службы (`/etc/systemd/system/my_backup.service`):**

```ini
[Unit]
Description=My Backup Script

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

**2. Файл таймера (`/etc/systemd/system/my_backup.timer`):**

```ini
[Unit]
Description=Run backup script daily at 2 AM
RefuseManualStart=true
RefuseManualStop=true

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
AccuracySec=1s

[Install]
WantedBy=timers.target
```

В данном примере:

* `OnCalendar=*-*-* 02:00:00` — запускает задачу ежедневно в 2 часа ночи.
* `Persistent=true` — если система была выключена и время запуска пропущено, задача будет выполнена сразу после следующей загрузки.
* `AccuracySec=1s` — устанавливает точность запуска до одной секунды (по умолчанию `1m`).

### Управление таймером

1. **Перечитать конфигурацию `systemd`:**

    ```bash
    sudo systemctl daemon-reload
    ```

2. **Включить и запустить таймер:**

    ```bash
    sudo systemctl enable --now my_backup.timer
    ```

    (Важно: активируется `.timer`, а не `.service`).
3. **Проверить активные таймеры и время следующего запуска:**

    ```bash
    systemctl list-timers --all
    ```

4. **Просмотреть логи запусков конкретного таймера:**

    ```bash
    journalctl -u my_backup.timer
    ```

5. **Просмотреть логи самой выполненной задачи:**

    ```bash
    journalctl -u my_backup.service
    ```

## Дополнительная информация

### Форматы OnCalendar

| Формат | Описание | Пример |
| :--- | :--- | :--- |
| `*-*-* HH:MM:SS` | Ежедневно в указанное время | `*-*-* 02:00:00` — каждый день в 2:00 |
| `DOW YYYY-MM-DD HH:MM:SS` | Конкретный день недели | `Mon *-*-* 09:00:00` — каждый понедельник в 9:00 |
| `*-*-* HH:MM:SS/2` | Каждые 2 часа | `*-*-* 00:00:00/2` — каждые 2 часа |
| `*-*-01 HH:MM:SS` | Первое число месяца | `*-*-01 03:00:00` — 1-го числа в 3:00 |
| `*-*-WXX HH:MM:SS` | N-я неделя месяца | `*-*-Wed1 12:00:00` — первая среда месяца |
| `*-*-1..7 HH:MM:SS` | 1-7 число месяца | `*-*-1..7 02:00:00` — с 1 по 7 число в 2:00 |

**Специальные таргеты:**
- `hourly.target` — каждый час
- `daily.target` — каждый день
- `weekly.target` — каждую неделю
- `monthly.target` — каждый месяц
- `yearly.target` — каждый год

### Временные таймеры: `systemd-run`

Для создания временных (one-shot) задач без создания файлов юнитов можно использовать утилиту `systemd-run`. Такие таймеры существуют до перезагрузки системы или до выполнения условия.

```bash
# Запустить команду через 1 час
systemd-run --on-active="1h" --unit=touch-file /usr/bin/touch /tmp/test_file

# Запускать команду ежечасно (временный таймер)
systemd-run --on-boot="1h" --unit=hourly-task /usr/bin/some_script.sh
```

Ключи:
- `--on-active="time"` — запустить через указанное время после активации
- `--on-boot="time"` — запустить через указанное время после загрузки системы
- `--on-unit-active="time"` — запускать каждый раз после завершения предыдущего запуска (для периодических задач)
- `--unit=` — имя юнита

### Типичные проблемы и решения

* **Неточная сработка (`AccuracySec`):** По умолчанию `systemd` откладывает запуск таймеров до 1 минуты для экономии ресурсов (`AccuracySec=1m`). Для высокой точности установите `AccuracySec=1s` в секции `[Timer]`.
* **Таймер не запускается/не виден:**
  * Убедитесь, что таймер включен командой `sudo systemctl enable my-timer.timer`.
  * Проверьте статус `systemctl status your-timer.timer` на наличие ошибок.
  * Убедитесь, что вы работаете с `.timer`, а не `.service`.
* **Запуск сразу после загрузки, пропуская расписание (`Persistent`):** Если таймер настроен на ночное время, но срабатывает после утренней загрузки, это означает, что `Persistent=true` наверстывает пропущенный запуск. Если такое поведение нежелательно, установите `Persistent=false`.
* **Случайная задержка (`RandomizedDelaySec`):** Этот параметр добавляет случайную задержку к времени запуска, чтобы избежать пиковых нагрузок. Для максимальной точности установите `RandomizedDelaySec=0`.
* **Часовые пояса:** Убедитесь, что часовой пояс системы установлен корректно (`timedatectl`), так как `OnCalendar` использует локальное время.

### Инструменты отладки

* **`systemctl list-timers --all`**: Показывает все таймеры, их статус и следующее время срабатывания.
* **`systemctl status <имя_таймера>.timer`**: Детальная информация о конкретном таймере.
* **`journalctl -u <имя_сервиса>.service --since "1 hour ago"`**: Просмотр логов выполненной задачи.
* **`systemd-analyze calendar "*-*-* 03:00:00"`**: Проверяет интерпретацию расписания `systemd` и показывает следующие моменты срабатывания.
