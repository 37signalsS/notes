# Таймеры systemd (systemd Timers)

## Определения

**systemd Timers** — механизм планирования задач в системе инициализации `systemd`, современная альтернатива классическому демону `cron`. Таймер активирует соответствующий `.service` юнит (unit) по заданному расписанию или относительно определенного события.

Для настройки задачи требуется два файла:

1. **Юнит сервиса** (`.service`) — описывает, что именно нужно выполнить.
2. **Юнит таймера** (`.timer`) — описывает, когда или при каких условиях следует выполнить активацию.

Для корректной работы по умолчанию имена этих файлов должны совпадать (например, `backup.service` и `backup.timer`).

> Временные таймеры, создаваемые без конфигурационных файлов: [systemd_run.md](./systemd_run.md). Базовая синхронизация системного времени: [time_synchronization.md](./time_synchronization.md).

## Основные концепции

### Преимущества перед cron

| Характеристика | cron | systemd Timers |
| :--- | :--- | :--- |
| Логирование | Email/файлы (нестандартно) | `journald` (централизованное, с метаданными) |
| Пропущенные задачи | Не выполняются (кроме anacron) | `Persistent=true` — выполнение сразу после загрузки ОС |
| Зависимости | Отсутствуют | Полная поддержка `After=`, `Requires=`, `Wants=` |
| Ограничение ресурсов | Ограничено (nice/ionice) | Поддержка cgroups (`MemoryMax=`, `CPUQuota=`) |
| Часовые пояса | Системный | `OnCalendar=` использует локальное время, `OnBootSec=` — монотонное |
| Параллелизм | Ограничено | Каждый таймер — отдельный изолированный процесс |

### Типы триггеров таймеров

| Директива | Тип | Отсчёт | Когда использовать |
| :--- | :--- | :--- | :--- |
| `OnCalendar=` | Реальное время | Абсолютное расписание | Ежедневные/еженедельные задачи |
| `OnActiveSec=` | Монотонное время | С момента активации юнита таймера | Отложенный запуск после старта таймера |
| `OnBootSec=` | Монотонное время | С момента загрузки системы | Задачи, выполняемые вскоре после boot |
| `OnStartupSec=` | Монотонное время | С момента запуска systemd | Задачи инициализации сервисного менеджера |
| `OnUnitActiveSec=` | Монотонное время | С момента последнего запуска юнита | Периодический повтор выполнения |
| `OnUnitInactiveSec=` | Монотонное время | С момента последнего завершения юнита | Запуск после периода простоя |

### Ключевые директивы секции [Timer]

| Директива | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `OnCalendar=` | Расписание в формате календарного выражения | — |
| `Persistent=` | Выполнить пропущенный запуск после загрузки ОС (если задача была пропущена в офлайне) | `false` |
| `AccuracySec=` | Точность запуска (разрешение таймера) | `1min` |
| `RandomizedDelaySec=` | Случайная задержка запуска (для предотвращения пиковых нагрузок) | `0` |
| `Unit=` | Юнит для активации (если его имя отличается от имени таймера) | Одноименный `.service` |
| `RemainAfterElapse=` | Оставить таймер в активном состоянии после срабатывания | `false` |

## Практические сценарии

### Настройка ежедневного резервного копирования

**Юнит сервиса** (`/etc/systemd/system/my_backup.service`):

```ini
[Unit]
Description=My Backup Script

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

**Юнит таймера** (`/etc/systemd/system/my_backup.timer`):

```ini
[Unit]
Description=Run backup daily at 2 AM

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
AccuracySec=1s

[Install]
WantedBy=timers.target
```

```bash
# Активация таймера
sudo systemctl enable --now my_backup.timer
```

> Параметр `Persistent=true` гарантирует, что если сервер был выключен в 02:00, бэкап запустится сразу после следующего включения. `AccuracySec=1s` обеспечивает запуск секунда в секунду (по умолчанию используется окно в 1 минуту для экономии ресурсов CPU).

### Периодическая задача каждые 15 минут

```ini
[Timer]
OnUnitActiveSec=15min
OnBootSec=5min
```

Первый запуск произойдет через 5 минут после загрузки системы, далее — строго каждые 15 минут от времени предыдущего запуска.

### Запуск с использованием рандомизации

```ini
[Timer]
OnCalendar=*-*-* 03:00:00
RandomizedDelaySec=300
Persistent=true
```

Задача запустится в случайный момент между 03:00 и 03:05. Это критично при управлении парком серверов для распределения нагрузки на хранилище или сеть.

### Управление таймерами и диагностика

```bash
# Перечитать конфигурацию юнитов с диска
sudo systemctl daemon-reload

# Включить автозапуск и запустить немедленно
sudo systemctl enable --now my_backup.timer

# Просмотреть все активные и неактивные таймеры в системе
systemctl list-timers --all
# → NEXT                         LEFT          LAST                         PASSED    UNIT                         ACTIVATES
# → Sun 2024-06-09 02:00:00 MSK  12h left      Sat 2024-06-08 02:00:05 MSK  11h ago   my_backup.timer              my_backup.service

# Просмотр логов срабатывания таймера
journalctl -u my_backup.timer

# Просмотр логов выполнения самой задачи
journalctl -u my_backup.service

# Текущий статус юнита таймера
systemctl status my_backup.timer
# → ● my_backup.timer - Run backup daily at 2 AM
# →    Loaded: loaded (/etc/systemd/system/my_backup.timer; enabled; vendor preset: enabled)
# →    Active: active (waiting) since Sat 2024-06-08 10:00:00 MSK; 3h ago
```

## Дополнительная информация

### Форматы расписания OnCalendar

| Формат | Описание | Пример |
| :--- | :--- | :--- |
| `*-*-* HH:MM:SS` | Ежедневный запуск | `*-*-* 02:00:00` |
| `DOW *-*-* HH:MM:SS` | По определенным дням недели | `Mon *-*-* 09:00:00` |
| `*-*-* HH:MM:SS/N` | С интервалом в N часов/минут | `*-*-* 00:00:00/2` (раз в 2 часа) |
| `*-*-DD HH:MM:SS` | В конкретное число месяца | `*-*-01 03:00:00` (каждое 1-е число) |
| `hourly`, `daily`, `weekly` | Встроенные сокращения | `OnCalendar=daily` (аналог `00:00:00`) |

Инструмент для проверки синтаксиса расписания:

```bash
systemd-analyze calendar "Mon *-*-* 09:00:00"
# →  Iterating over timestamps, starting at Sat 2024-06-08 13:51:30 MSK.
# →  Next elapse: Mon 2024-06-10 09:00:00 MSK
```

### Типичные ошибки и их решение

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Неточное время запуска | Особенности планировщика (`AccuracySec`) | Установить `AccuracySec=1s` |
| Таймер неактивен после создания | Юнит не включен или не запущен | Выполнить `systemctl enable --now` |
| Сервис не запускается | Ошибка в имени файла или директиве `Unit=` | Проверить логи `journalctl -xe` и синтаксис файлов |
| Массовый запуск после boot | Эффект `Persistent=true` | Использовать `RandomizedDelaySec` для размытия нагрузки |

Сравнение с временными задачами через CLI (Command Line Interface): [systemd_run.md](./systemd_run.md).
