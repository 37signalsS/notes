# BIOS и UEFI: Прошивка и старт системы

## Определения

### BIOS (Basic Input/Output System)
**BIOS** — это низкоуровневое программное обеспечение, хранящееся на микросхеме материнской платы. Его основная задача — инициализация и тестирование аппаратных компонентов при включении компьютера (процесс POST), а затем запуск загрузчика операционной системы с MBR-диска.

### UEFI (Unified Extensible Firmware Interface)
**UEFI** — это современный стандарт прошивки, заменяющий BIOS. Он представляет собой более сложную среду, схожую с мини-операционной системой, которая предоставляет стандартизированный интерфейс для взаимодействия ОС с аппаратным обеспечением. UEFI работает с GPT-дисками и запускает EFI-приложения напрямую.

## Основные концепции

### Общий процесс старта
1.  **Reset Vector**: После подачи питания процессор начинает выполнение кода с предопределенного адреса (`0xFFFFFFF0` для x86). По этому адресу находится микросхема с прошивкой (BIOS или UEFI).
2.  **Инициализация платформы**: Прошивка выполняет инициализацию ключевых компонентов: контроллера памяти, шин и базовых устройств. В BIOS это происходит в рамках POST, в UEFI — через многоэтапную загрузку драйверов (DXE-фаза).
3.  **Выбор и запуск загрузчика**: Прошивка определяет, с какого устройства и какой файл загружать, после чего передает ему управление.

### Путь загрузки: BIOS + MBR
Этот классический путь основан на чтении первого 512-байтного сектора диска.

1.  **POST (Power-On Self Test)**: Проверка базового оборудования.
2.  **Чтение MBR (Master Boot Record)**: BIOS читает первый сектор (LBA 0) с диска. Если в конце сектора есть сигнатура `0x55AA`, он считается загрузочным.
3.  **Передача управления**: Управление передается коду в MBR (stage 1 загрузчика). Этот код слишком мал для сложных операций, поэтому он обычно загружает следующую, более крупную часть загрузчика (stage 2, например, `core.img` GRUB).
4.  **Загрузчик ОС (GRUB)**: Полноценный загрузчик находит и читает свою конфигурацию (например, `/boot/grub/grub.cfg`), после чего загружает в память ядро Linux (`vmlinuz`) и `initramfs`.
5.  **Переход к ядру**: Загрузчик передает ядру параметры командной строки и управление.

**Ограничения BIOS:**
*   **Диски**: Поддержка загрузки только с дисков до **2.2 ТБ** из-за схемы разметки MBR.
*   **Режим работы**: 16-битный режим, ограничивающий доступ к памяти (до 1 МБ).
*   **Безопасность**: Отсутствие механизмов проверки подлинности загрузчика.

### Путь загрузки: UEFI + GPT
Современный путь, который работает с файловыми системами и EFI-приложениями.

1.  **Инициализация UEFI**: Прошивка инициализирует оборудование и предоставляет сервисы для работы с устройствами.
2.  **UEFI Boot Manager**: Менеджер загрузки читает записи из **NVRAM**, чтобы определить, какое EFI-приложение запускать. Каждая запись указывает на конкретный `.efi`-файл на разделе ESP.
3.  **ESP (EFI System Partition)**: Специальный раздел с файловой системой FAT32, где хранятся загрузчики в виде `.efi`-файлов (например, `\EFI\ubuntu\grubx64.efi`).
4.  **Secure Boot**: Если функция включена, UEFI проверяет цифровую подпись EFI-приложения. Для Linux обычно используется цепочка `shim.efi` (подписан Microsoft) → `grubx64.efi` (подписан дистрибутивом) → ядро.
5.  **Запуск EFI-приложения**: UEFI запускает загрузчик (GRUB, systemd-boot) или напрямую ядро Linux, если оно скомпилировано с **EFI stub**.
6.  **Переход к ядру**: Аналогично BIOS, загрузчик передает управление ядру.

**Преимущества UEFI:**
*   **Диски**: Поддержка дисков до **9.4 ЗБ** благодаря схеме разметки GPT.
*   **Режим работы**: 32/64-битный режим с полным доступом к памяти.
*   **Безопасность**: **Secure Boot** для предотвращения запуска неавторизованного кода.
*   **Интерфейс**: Графический интерфейс с поддержкой мыши и сети.

### Сравнительная таблица

| Характеристика | BIOS | UEFI |
| :--- | :--- | :--- |
| **Схема разделов** | MBR | GPT |
| **Макс. объем диска** | ~2.2 ТБ | ~9.4 ЗБ |
| **Режим процессора** | 16-битный | 32/64-битный |
| **Безопасность** | Отсутствует | Secure Boot |
| **Интерфейс** | Текстовый | Графический |
| **Стартовый код** | MBR (LBA 0, 512 байт) | `.efi`-файл на ESP (FAT32) |
| **Конфигурация** | Настройки в CMOS | Переменные в NVRAM (`efibootmgr`) |

## Практические сценарии

### Проверка текущего режима загрузки
Определить, в каком режиме загружена система, можно, проверив наличие каталога `/sys/firmware/efi`:
```bash
# Если каталог существует, система загружена в режиме UEFI
ls /sys/firmware/efi
```

### Управление параметрами прошивки
Вход в меню настроек BIOS/UEFI (обычно по клавишам `Del`, `F2`, `F10`, `Esc` при старте) позволяет:
-   **Изменить порядок загрузки**: Указать приоритет для HDD, SSD, USB или сетевой загрузки (PXE).
-   **Включить/отключить Secure Boot**: Управление безопасной загрузкой.
-   **Активировать виртуализацию**: Включение Intel VT-x/AMD-V для работы гипервизоров.
-   **Настроить аппаратные компоненты**: Управление частотами, питанием и другими параметрами.

### Диагностика проблем при старте
- **POST-коды**: При ошибках на этапе POST BIOS издает звуковые сигналы или выводит коды, указывающие на неисправный компонент (память, видеокарта и т.д.).
- **Ошибки загрузчика**: Сообщения от GRUB (например, `error: no such partition`) указывают на проблемы с доступом к диску или конфигурационным файлам.

## Дополнительная информация

### Глоссарий терминов
*   **Reset Vector**: Архитектурно заданный адрес, с которого CPU начинает исполнение кода после сброса.
*   **POST (Power-On Self Test)**: Ранняя самодиагностика и инициализация оборудования.
*   **MBR (Master Boot Record)**: Первый сектор диска (512 байт), содержащий загрузочный код и таблицу разделов.
*   **GPT (GUID Partition Table)**: Современный стандарт разметки диска, использующий глобальные уникальные идентификаторы.
*   **ESP (EFI System Partition)**: Раздел FAT32, где UEFI хранит и откуда запускает загрузчики (`.efi`-файлы).
*   **NVRAM**: Энергонезависимая память в чипе UEFI, где хранятся переменные и порядок загрузки.
*   **Secure Boot**: Механизм UEFI, проверяющий криптографические подписи загрузчика и ядра для защиты от вредоносного ПО.
*   **shim.efi**: Прослойка, подписанная доверенным ключом Microsoft, которая позволяет загружать GRUB с подписью дистрибутива в режиме Secure Boot.
*   **EFI stub**: Функциональность ядра Linux, позволяющая ему быть запущенным напрямую как EFI-приложение без отдельного загрузчика.
