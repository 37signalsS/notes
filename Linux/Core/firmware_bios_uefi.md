# BIOS и UEFI: Основы и различия

## Определения

### BIOS (Basic Input-Output System)

Низкоуровневое программное обеспечение на микросхеме материнской платы, инициализирующее аппаратные компоненты и запускающее загрузчик ОС при включении ПК.

### UEFI (Unified Extensible Firmware Interface)

Современный стандарт прошивки, пришедший на смену BIOS, предлагающий расширенные возможности взаимодействия с аппаратным обеспечением и ОС. Функционально схож с мини-операционной системой, работающей поверх основной прошивки.

## Основные концепции

### Общий процесс старта системы

**Reset vector:** После подачи питания CPU выходит из reset и всегда начинает выполнение кода с архитектурно заданного адреса. На x86 фактическая точка старта — физический адрес `0xFFFFFFF0`. По этому адресу отображён ROM/flash с кодом прошивки. Reset vector и начальное состояние CPU определяются архитектурой процессора, а не BIOS или UEFI.

**Инициализация платформы:** Прошивка (BIOS или UEFI) выполняет раннюю инициализацию памяти и устройств:
- **BIOS** — выполняет инициализацию в рамках POST
- **UEFI** — через многоступенчатый процесс (в основном через DXE-драйверы), который подготавливает память и среду для работы с файловыми системами и сетью ещё до загрузки ОС

**Выбор устройства загрузки:** Boot Order не является универсальным линейным списком устройств:
- В **BIOS** это порядок попыток загрузки с устройств
- В **UEFI** это порядок записей загрузки в NVRAM, каждая из которых указывает на конкретное EFI-приложение

### Принципы работы BIOS

1. **POST (Power-On Self Test):** Самотестирование оборудования при старте ПК. При обнаружении ошибок BIOS сигнализирует звуком или кодами.
2. **Загрузка ОС:** После POST BIOS ищет и запускает загрузочную запись **MBR (Master Boot Record)**.
3. **CMOS:** Взаимодействие с энергонезависимой памятью CMOS для хранения настроек (конфигурация, время, параметры загрузки).

### Путь загрузки BIOS + MBR (классическая схема)

**Ключевая идея:** BIOS читает один сектор (512 байт) с начала диска (MBR), проверяет сигнатуру `0x55AA` в конце сектора и передаёт управление коду MBR.

**1. Чтение MBR (LBA 0)**
- BIOS читает первый логический сектор диска (512 байт)
- Структура MBR:
  - 446 байт — начальный загрузочный код (stage 1)
  - 64 байта — таблица разделов MBR (4 записи)
  - 2 байта — сигнатура `0x55AA` (magic number)
- Если сигнатура не найдена — диск считается незагрузочным

**2. Передача управления коду MBR**
- Код MBR слишком мал для работы с файловыми системами
- Обычно загружает следующую стадию загрузчика из заранее известных секторов (post-MBR gap) или передаёт управление загрузочному сектору активного раздела (PBR)
- Следующие стадии поднимают полноценный загрузчик (GRUB2: core.img/stage 1.5)

**3. Загрузчик (GRUB2)**
- Находит и читает конфигурацию (`/boot/grub/grub.cfg`)
- Показывает меню или выбирает default entry
- Загружает ядро `vmlinuz` и `initramfs`
- Передаёт ядру kernel command line (например: `root=`, `ro`, `quiet`)

**4. Переход в ядро**
- Загрузчик передаёт управление ядру с параметрами и адресами initramfs

```
Power on
-> BIOS init/POST
-> read MBR (LBA 0)
-> bootloader stage1 -> stage2 (GRUB)
-> load kernel + initramfs + cmdline
-> jump to kernel
```

### Ограничения BIOS

* **Диски:** Поддержка загрузки только с дисков до **2.1 ТБ** (использует MBR).
* **Режим:** Работа в **16-разрядном режиме** процессора, ограничение памяти 1 МБ.
* **Инициализация:** Проблемы с одновременной инициализацией нескольких устройств.

### Путь загрузки UEFI + GPT (современная схема)

**Ключевая идея:** UEFI запускает `.efi`-приложение с EFI System Partition (ESP), а не «код из первого сектора».

**1. UEFI Boot Manager и NVRAM**
- Прошивка хранит список записей загрузки в NVRAM (что запускать и откуда)
- Просмотр записей в Linux: `efibootmgr -v`
- **Fallback-механизм:** Если записи NVRAM отсутствуют, прошивка пытается запустить стандартный путь `\EFI\BOOT\BOOTX64.EFI`

**2. ESP (EFI System Partition)**
- Раздел с типом FAT32, где лежат загрузчики
- Типичные пути: `\EFI\<vendor>\*.efi` и fallback `\EFI\BOOT\BOOTX64.EFI`

**3. Secure Boot (если включён)**
- UEFI проверяет подпись запускаемого `.efi`
- Linux-дистрибутивы используют цепочку: `shim.efi` -> `grubx64.efi` -> kernel
- **shim** — прослойка, подписанная Microsoft (доверенный ключ), которая проверяет подпись GRUB по ключам дистрибутива

**4. EFI-приложение**
- Загрузчик является обычным EFI-приложением, запускаемым прошивкой напрямую с ESP
- **GRUB** — делает выбор записи и грузит `vmlinuz+initramfs`
- **systemd-boot** — читает entries с ESP и грузит ядро с EFI stub
- **EFI stub** — ядро Linux, собранное с поддержкой запуска напрямую как EFI-приложение (без отдельного загрузчика)

```
Power on
-> UEFI init
-> Boot Manager (NVRAM entries)
-> load \EFI\...\*.efi from ESP (FAT32)
-> bootloader (GRUB/systemd-boot)
-> load kernel + initramfs (or EFI-stub)
-> jump to kernel
```

### Преимущества UEFI

* **Большие диски:** Загрузка с дисков объемом свыше **2.2 ТБ** (до 9.4 ЗБ) благодаря **GPT (GUID Partition Table)**.
* **Режим:** Работа в **32-битном или 64-битном режиме**, что ускоряет запуск и расширяет доступ к памяти.
* **Интерфейс:** Графический интерфейс с поддержкой мыши.
* **Безопасность:** **Secure Boot** для проверки цифровых подписей загрузчика и ядра ОС, предотвращая запуск вредоносного кода.
* **Сеть:** Встроенная поддержка сетевой загрузки (PXE) и доступа к сети из прошивки.

### Сравнение BIOS и UEFI

| Характеристика | BIOS | UEFI |
| :--- | :--- | :--- |
| **Схема разделов** | MBR | GPT |
| **Макс. объем диска** | ~2.1 ТБ | ~9.4 ЗБ |
| **Режим процессора** | 16-битный | 32/64-битный |
| **Безопасность** | Отсутствует | Secure Boot |
| **Интерфейс** | Текстовый | Графический |
| **Стартовый код** | MBR (LBA0, 512 байт) | .efi на ESP (FAT32) |
| **Выбор загрузки** | Boot order в BIOS | Записи в NVRAM (`efibootmgr`) |
| **Типовые загрузчики** | GRUB, Syslinux | GRUB, systemd-boot, shim |

## Практические сценарии

* **Настройка порядка загрузки:** Выбор загрузочного устройства (HDD, SSD, USB, PXE) в UEFI/BIOS.
* **Включение/отключение Secure Boot:** Управление безопасной загрузкой для предотвращения загрузки неподписанного ПО.
* **Виртуализация:** Активация функций виртуализации (Intel VT-x/AMD-V) в UEFI/BIOS для работы гипервизоров.
* **Диагностика POST-кодов:** Интерпретация звуковых сигналов или кодов при запуске ПК для определения аппаратных проблем.

## Глоссарий терминов загрузки

### Прошивка и старт CPU

**Reset vector** — архитектурно заданная точка, с которой процессор начинает исполнение после сброса. На x86 это физический адрес `0xFFFFFFF0`.

**POST (Power-On Self Test)** — ранняя проверка и базовая инициализация оборудования при включении питания.

**DXE (Driver Execution Environment)** — основная фаза работы UEFI, в которой загружаются драйверы и создаются условия для запуска загрузчика ОС.

**CMOS** — энергонезависимая память на материнской плате, питаемая от батарейки, где BIOS хранит настройки.

**NVRAM (UEFI)** — память в чипе прошивки UEFI, где хранятся переменные загрузки (boot entries).

### BIOS/MBR загрузка

**LBA (Logical Block Addressing)** — метод адресации данных на диске линейной нумерацией блоков (0, 1, 2, …).

**MBR (Master Boot Record)** — первый сектор диска (LBA 0), содержащий загрузочный код и таблицу разделов.

**Magic number** — сигнатура `0x55AA` в конце MBR, подтверждающая, что сектор загрузочный.

**Stage 1 / Stage 1.5 / Stage 2** — условное деление загрузчика на стадии из-за ограничения размера MBR.

**Post-MBR gap** — пространство между MBR и началом первого раздела, используемое для размещения промежуточной стадии загрузчика.

**PBR (Partition Boot Record)** — загрузочный сектор раздела (активного).

### UEFI загрузка

**ESP (EFI System Partition)** — раздел FAT32 с загрузчиками `.efi`, который прошивка UEFI читает самостоятельно.

**EFI application** — бинарный файл в формате PE/COFF, который прошивка UEFI способна загрузить и выполнить.

**Fallback boot path** — стандартный путь `\EFI\BOOT\BOOTX64.EFI`, используемый при отсутствии записей NVRAM.

**Secure Boot** — механизм UEFI, проверяющий подписи EFI-компонентов при загрузке.

**shim** — небольшой EFI-загрузчик, подписанный Microsoft, который проверяет подпись GRUB/ядра по ключам дистрибутива.

**EFI stub** — поддержка в ядре Linux, позволяющая ему запускаться напрямую как EFI-приложение.
