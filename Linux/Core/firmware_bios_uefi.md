# BIOS и UEFI: Микропрограммы и загрузка системы

## Определения

**Firmware (Микропрограмма)** — специализированное ПО, записанное в энергонезависимую память материнской платы, которое обеспечивает начальную инициализацию оборудования и передачу управления загрузчику ОС.

**BIOS (Basic Input/Output System)** — классический стандарт прошивки (1970-е — 2010-е). Работает в 16-битном реальном режиме процессора, использует таблицу разделов MBR и ограничена дисками до 2.2 ТБ.

**UEFI (Unified Extensible Firmware Interface)** — современный стандарт, пришедший на смену BIOS. Представляет собой расширяемую среду с собственной файловой системой (FAT32), поддержкой сетевого стека, графического интерфейса и криптографической проверки компонентов (Secure Boot).

## Основные концепции

### Сравнение архитектур

| Характеристика | BIOS (Legacy) | UEFI (Modern) |
| :--- | :--- | :--- |
| **Режим CPU** | 16-bit Real Mode | 32/64-bit Protected/Long Mode |
| **Разметка диска** | MBR (Master Boot Record) | GPT (GUID Partition Table) |
| **Адресация диска** | LBA 32-bit (макс. 2.2 ТБ) | LBA 64-bit (макс. 9.4 ЗБ) |
| **Место загрузчика** | Первый сектор диска (512 байт) | Файл `.efi` на разделе ESP |
| **Безопасность** | Отсутствует | Secure Boot, интеграция с TPM2 |
| **Инициализация** | Последовательная (медленная) | Параллельная (быстрая) |
| **Интерфейс** | Текстовый, клавиатура | Графический, мышь, сеть (HTTP Boot) |

### Путь загрузки UEFI (Boot Path)

1.  **SEC (Security Phase):** Сброс CPU, переход на Reset Vector, инициализация временной памяти (Cache-as-RAM).
2.  **PEI (Pre-EFI Initialization):** Инициализация чипсета, основной памяти (RAM) и передача параметров следующей фазе.
3.  **DXE (Driver Execution Environment):** Загрузка драйверов устройств (диски, сеть, видео) из прошивки.
4.  **BDS (Boot Device Selection):** Чтение переменных из NVRAM, поиск загрузочных записей и запуск EFI-приложения (загрузчика).
5.  **TSL (Transient System Load):** Работа загрузчика (GRUB, systemd-boot) до вызова `ExitBootServices()`.
6.  **RT (Run Time):** Ядро ОС берет управление на себя, UEFI остается доступным только через Runtime Services (например, для доступа к переменным через `efivarfs`).

### Современные стандарты и технологии (2024–2026)

*   **Unified Kernel Image (UKI):** Объединение ядра Linux, `initramfs`, командной строки и микрокода в один подписанный `.efi` файл. Это позволяет UEFI проверять целостность всей системы через Secure Boot без доверия к промежуточным конфигам загрузчика.
*   **HTTP Boot:** Современная замена PXE, позволяющая загружать ОС напрямую по протоколам HTTP/HTTPS, что быстрее и надежнее традиционного TFTP.
*   **Secure Boot "2026 Cliff":** Переход на новые сертификаты Microsoft (2023 CA), так как старые ключи 2011 года истекают в 2026 году.
*   **Confidential Computing:** Расширения UEFI для изоляции памяти ВМ на аппаратном уровне (Intel TDX, AMD SEV-SNP).
*   **Coreboot / Libreboot:** Открытые альтернативы проприетарным UEFI, фокусирующиеся на минимализме и безопасности.

## Практические сценарии

### 1. Проверка режима загрузки и переменных

В Linux информация о режиме загрузки доступна через псевдофайловую систему `efivarfs`.

```bash
# Проверка наличия каталога (если пуст или отсутствует — загрузка в Legacy/BIOS)
ls /sys/firmware/efi/efivars

# Проверка типа таблицы разделов через fdisk
sudo fdisk -l /dev/sda | grep "Disklabel type"
# → Disklabel type: gpt (для UEFI) или dos (для BIOS)

# Проверка поддержки Secure Boot
bootctl status | grep "Secure Boot"
```

### 2. Управление записями через efibootmgr

Утилита позволяет изменять порядок загрузки и добавлять новые записи напрямую из ОС.

```bash
# Просмотр текущих записей (v — verbose для деталей)
sudo efibootmgr -v

# Изменение порядка загрузки (например, сначала запись 0004, затем 0001)
sudo efibootmgr -o 0004,0001

# Создание новой записи для загрузчика
# -d: диск, -p: номер раздела ESP, -L: метка, -l: путь к efi-файлу
sudo efibootmgr -c -d /dev/nvme0n1 -p 1 -L "Arch Linux" -l '\EFI\arch\grubx64.efi'

# Удаление записи (например, 0003)
sudo efibootmgr -b 0003 -B
```

### 3. Настройка Secure Boot с собственными ключами

Для полного контроля над безопасностью (Owner Mode) можно заменить ключи Microsoft на свои.

```bash
# Установка инструментов
sudo apt install sbsigntool efitools

# Проверка статуса ключей
sbkeysync --list
```
*Подробный процесс генерации и прошивки ключей описан в специализированных руководствах по Hardening.*

### 4. Выбор загрузчика: systemd-boot vs GRUB (2025)

| Критерий | systemd-boot | GRUB 2 |
| :--- | :--- | :--- |
| **Сложность** | Минимальная (текстовые файлы) | Высокая (машинная генерация конфига) |
| **Поддержка ФС** | Только FAT32 (ESP) | Практически любые (Btrfs, XFS, ZFS) |
| **Скорость** | Максимальная (нативный EFI) | Ниже (эмуляция среды) |
| **UKI** | Нативная поддержка | Требует настройки |
| **Dual-boot** | Сложен для Windows | Идеален (os-prober) |

### Устранение неполадок

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| **"No bootable device found"** | Повреждена запись в NVRAM или раздел ESP | Восстановить запись через `efibootmgr` с Live-USB. |
| **Secure Boot Violation** | Загрузчик не подписан доверенным ключом | Подписать `.efi` файл через `sbsign` или временно отключить Secure Boot в BIOS Setup. |
| **Пропал пункт загрузки Linux** | Windows Update затерла порядок в NVRAM | Использовать `efibootmgr -o` для восстановления приоритета. |
| **Система грузится только в BIOS** | Включен режим CSM (Compatibility Support Module) | Отключить CSM в настройках прошивки для использования чистого UEFI. |
