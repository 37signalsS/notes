# BIOS и UEFI: Микропрограммы и загрузка системы

## Определения

**Firmware (Микропрограмма)** — специализированное программное обеспечение, записанное в энергонезависимую память материнской платы. Оно отвечает за инициализацию оборудования (POST), настройку параметров питания и передачу управления загрузчику операционной системы.

**BIOS (Basic Input/Output System)** — классический стандарт прошивки (1975–2010 гг.). Работает в 16-битном реальном режиме процессора, использует таблицу разделов MBR и ограничена дисками объемом до 2.2 ТБ.

**UEFI (Unified Extensible Firmware Interface)** — современный интерфейс между прошивкой и ОС. UEFI представляет собой миниатюрную операционную систему с собственной файловой системой (FAT32), поддержкой сетевого стека, графического интерфейса и модульной архитектурой драйверов.

## Основные концепции

### Сравнение архитектур

| Характеристика | BIOS (Legacy) | UEFI (Modern) |
| :--- | :--- | :--- |
| **Режим процессора** | 16-bit Real Mode | 32/64-bit Protected/Long Mode |
| **Адресация памяти** | До 1 МБ | Весь объем RAM |
| **Таблица разделов** | MBR (Master Boot Record) | GPT (GUID Partition Table) |
| **Размер диска** | Макс. 2.2 ТБ | Макс. 9.4 ЗБ (LBA 64-bit) |
| **Расположение кода** | Первый сектор диска (512 Б) | Файлы `.efi` на разделе ESP |
| **Файловая система ESP** | FAT32 (VFAT) | FAT32 |
| **Безопасность** | Отсутствует | Secure Boot, TPM2, Measured Boot |
| **Инициализация** | Последовательная | Параллельная |

### Путь загрузки UEFI (PI Architecture)

Процесс загрузки UEFI строго стандартизирован и состоит из следующих этапов:

1.  **SEC (Security):** Первичная инициализация. Настройка временной памяти (Cache-as-RAM) для работы PEI.
2.  **PEI (Pre-EFI Initialization):** Инициализация чипсета и системной памяти (DRAM). Подготовка среды для DXE.
3.  **DXE (Driver Execution Environment):** Основной этап. Загрузка драйверов устройств (NVMe, USB, Network) и инициализация интерфейсов.
4.  **BDS (Boot Device Selection):** Выбор устройства загрузки на основе переменных NVRAM. Запуск EFI-приложения (загрузчика).
5.  **TSL (Transient System Load):** Работа загрузчика (GRUB, systemd-boot) до момента вызова `ExitBootServices()`.
6.  **RT (Run Time):** Ядро ОС берет управление. UEFI остается в памяти только в виде Runtime Services (доступ через `efivarfs`).

### Интеграция с TPM2 и Measured Boot

В режиме UEFI прошивка взаимодействует с модулем **TPM2** для записи «измерений» каждого этапа загрузки в регистры **PCR (Platform Configuration Registers)**:
- **PCR 0:** Хеш самого кода прошивки.
- **PCR 4:** Хеш загрузчика (shim/grub).
- **PCR 7:** Статус Secure Boot и база ключей.
- **PCR 8-9:** Хеши ядра Linux и командной строки (при использовании UKI).

Это позволяет реализовать **аттестацию загрузки**: ОС может убедиться, что ни один компонент не был подменен, прежде чем разблокировать ключи шифрования диска.

## Современные стандарты (2024–2026)

### Unified Kernel Image (UKI)

UKI — это объединение ядра, `initramfs`, микрокода и командной строки в единый подписанный `.efi` файл. 
- **Преимущество:** UEFI проверяет подпись всего образа целиком, исключая возможность подмены `initramfs` (который обычно не подписан в классической схеме).
- **Реализация:** Обеспечивается через `systemd-stub`.

### Secure Boot "2026 Cliff"

В 2026 году истекает срок действия корневых сертификатов Microsoft (2011 CA), которыми подписано большинство загрузчиков (Shim) и драйверов.
- **Влияние:** Системы, выпущенные после 2024 года, переходят на **Microsoft 2023 CA**. 
- **Действие:** На старых системах потребуется обновление базы `db` через прошивку или утилиты ОС, иначе новые загрузчики не пройдут проверку.

### Микрокод процессора (Early Loading)

Загрузка обновлений микрокода должна происходить максимально рано (Early Loading) для исправления критических уязвимостей (типа Spectre/Meltdown).
- **Метод:** Загрузчик передает микрокод ядру как отдельный `initrd`, который ядро считывает до инициализации планировщика.

### Confidential Computing (Intel TDX / AMD SEV)

UEFI обеспечивает аппаратную изоляцию виртуальных машин. Прошивка создает защищенные домены памяти, к которым не имеет доступа даже гипервизор хоста.

## Практические сценарии

### 1. Проверка режима загрузки

```bash
# 1. Проверка наличия переменных UEFI
[ -d /sys/firmware/efi ] && echo "UEFI Mode" || echo "Legacy Mode"

# 2. Список доступных переменных (через efivarfs)
ls /sys/firmware/efi/efivars | head -n 5

# 3. Проверка статуса Secure Boot
bootctl status | grep "Secure Boot"
```

### 2. Управление загрузкой через efibootmgr

```bash
# Просмотр текущего порядка загрузки
sudo efibootmgr -v

# Изменение порядка (BootOrder)
sudo efibootmgr -o 0001,0005,0000

# Добавление новой записи
sudo efibootmgr -c -d /dev/nvme0n1 -p 1 -L "My Linux" -l '\EFI\distro\grubx64.efi'

# Удаление записи 0004
sudo efibootmgr -b 0004 -B
```

### 3. Работа с CSM (Compatibility Support Module)

**CSM** — компонент UEFI, эмулирующий BIOS для загрузки старых ОС.
- **Внимание:** В современных системах (Intel Tiger Lake+ и AMD Zen 3+) CSM часто полностью отсутствует.
- **Рекомендация:** Всегда отключайте CSM для обеспечения работы Secure Boot и быстрой инициализации видеокарт (GOP вместо VBIOS).

### 4. Отсутствие /boot/efi при GPT-разметке (гибрид Legacy BIOS + GPT)

Отсутствие директории `/boot/efi` **не является признаком повреждения системы**. Это штатная ситуация, возникающая при сочетании GPT-разметки диска и загрузки в режиме Legacy BIOS (CSM или родной BIOS гипервизора).

**Суть гибридной схемы:**
- Диск размечен по стандарту GPT (таблица разделов существует).
- Гипервизор эмулирует загрузку через Legacy BIOS (CSM отключен или не поддерживается).
- Вместо ESP (EFI System Partition) используется скрытый раздел `BIOS boot` (флаг `bios_grub`), в который GRUB записывает свой `core.img`.
- Раздел ESP физически не создается, поэтому `/boot/efi` отсутствует.

**Проверка режима загрузки:**
```bash
# Определяет, в каком режиме работает ядро
[ -d /sys/firmware/efi ] && echo "UEFI Mode" || echo "Legacy BIOS"
```

**Когда ESP обязателен:**
ESP требуется только при загрузке в режиме UEFI. Формат раздела — FAT32 (VFAT), потому что микрокод UEFI физически не умеет читать нативные файловые системы Linux (ext4, XFS, Btrfs). Размер обычно 512 МБ – 1 ГБ.

## Дополнительная информация

### Поиск и устранение неисправностей

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **EFI Variables не найдены** | Ядро загружено без поддержки EFI или в Legacy режиме. | Проверьте параметры загрузки. Проверьте монтирование `efivarfs`. |
| **Secure Boot Violation** | Нарушена цепочка подписей. | Проверьте подпись `shim.efi` и ядра. Используйте `sbverify`. |
| **Дубликаты в загрузке** | Ошибки прошивки при записи в NVRAM. | Очистите записи через `efibootmgr` или сбросьте BIOS в Default. |
| **Отсутствует /boot/efi при GPT** | Диск размечен по GPT, но система загружена в Legacy BIOS (CSM). ESP не создавался. | Нормальное поведение. Для загрузки UEFI переключите режим прошивки на UEFI и создайте ESP (FAT32, флаг `esp`). |
