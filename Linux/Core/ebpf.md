# eBPF (extended Berkeley Packet Filter)

## Проблема: Медленная разработка ядра

Традиционный способ добавления новой функциональности в ядро Linux — это долгий и сложный процесс. Разработчику нужно убедить сообщество в необходимости фичи, пройти ревью кода и дождаться, пока новый код будет включен в upstream, а затем — в дистрибутивы. Этот цикл может занимать годы.

eBPF решает эту проблему, предоставляя безопасный и эффективный способ запускать пользовательский код в пространстве ядра без необходимости изменять код самого ядра или перезагружать систему.

## cBPF (classic BPF): Предшественник

Изначально BPF (Berkeley Packet Filter) был создан для фильтрации сетевых пакетов. Классический BPF (cBPF) позволял выполнять простой байт-код в ядре для принятия решений о пакетах (например, отбросить или пропустить).

Основное применение cBPF — это инструменты вроде `tcpdump` (подробнее см. [Wireshark и анализ сетевого трафика](../../Networking/ServicesAndTools/wireshark_and_packet_capture.md)), которые используют его для захвата только интересующего трафика.

Ограничение cBPF в том, что он был предназначен **только для сетевых взаимодействий**.

## eBPF: Эволюция

eBPF (extended BPF) — это значительное расширение cBPF. Это уже не просто фильтр пакетов, а универсальная, событийно-ориентированная виртуальная машина внутри ядра Linux.

eBPF позволяет прикреплять (attach) небольшие программы к различным точкам в ядре (syscalls, kprobes, tracepoints, сетевые события) и безопасно выполнять их при срабатывании этих событий.

### Как работает eBPF

1.  **Загрузка программы:** Пользовательское приложение (например, `opensnoop`) загружает eBPF-программу в ядро. Перед загрузкой **верификатор** проверяет код на безопасность (отсутствие циклов, недопустимых обращений к памяти).
2.  **Прикрепление к событию:** Программа прикрепляется к определенному событию, например, к системному вызову `open()`.
3.  **Сбор данных:** Когда системный вызов `open()` происходит, eBPF-программа выполняется. Она может собирать данные (аргументы вызова, возвращаемое значение) и сохранять их в специальные структуры данных — **eBPF maps**.
4.  **Чтение из userspace:** Приложение в пространстве пользователя может читать данные из eBPF maps и отображать их.

### BPF Type Format (BTF): Упрощение работы со структурами ядра

**BTF (BPF Type Format)** — это формат метаданных, который хранит информацию о типах данных, используемых в ядре (структуры, объединения, перечисления и т.д.). Эта информация встраивается в ядро и становится доступной для eBPF-программ.

**Зачем это нужно:**
До появления BTF eBPF-программам для доступа к полям структур ядра требовались заголовочные файлы ядра (`kernel headers`) на хосте, где происходила компиляция. Это создавало проблемы с переносимостью: программа, скомпилированная для одной версии ядра, могла не работать на другой.

BTF решает эту проблему, позволяя eBPF-программам во время выполнения получать информацию о структурах данных напрямую из ядра. Это делает eBPF-программы более переносимыми и упрощает их разработку, так как отпадает необходимость в точной синхронизации с заголовочными файлами ядра.

Таким образом, eBPF позволяет реализовать мощные инструменты для **наблюдаемости (observability)**, **безопасности** и **сетевого мониторинга**, не требуя изменений в ядре.

### Сферы применения и инструменты

Благодаря своей гибкости, eBPF используется в самых разных областях:

1.  **Сеть и балансировка нагрузки:**

    -   **XDP (eXpress Data Path):** Позволяет обрабатывать сетевые пакеты на самом раннем этапе, еще до их входа в основной сетевой стек ядра. Это используется для высокопроизводительной защиты от DDoS, балансировки нагрузки и маршрутизации.
    -   **Cilium:** Популярный CNI-плагин для Kubernetes, который использует eBPF для обеспечения сетевого взаимодействия между контейнерами, применения политик безопасности и балансировки нагрузки с высокой производительностью.

2.  **Наблюдаемость и трассировка (Observability & Tracing):**

    -   **BCC (BPF Compiler Collection):** Набор инструментов и библиотек для создания eBPF-программ на Python и C++. Включает десятки готовых утилит для профилирования и трассировки системы (`opensnoop`, `execsnoop`, `tcplife` и др.).
    -   **bpftrace:** Высокоуровневый язык трассировки, который позволяет писать короткие скрипты для сбора информации о работе ядра и приложений. Его синтаксис вдохновлен `awk` и `DTrace`.

3.  **Безопасность:**

    -   **Falco:** Популярный инструмент для обнаружения аномальной активности и угроз в реальном времени. Falco использует eBPF для перехвата системных вызовов и сравнения их с набором правил безопасности.
    -   **Tetragon:** Компонент безопасности от создателей Cilium, который также использует eBPF для мониторинга событий безопасности на уровне ядра.
