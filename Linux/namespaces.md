# Пространства имён (Namespaces) в Linux

**Пространства имён (Namespaces)** — это одна из фундаментальных технологий ядра Linux, которая обеспечивает изоляцию и виртуализацию системных ресурсов. Она позволяет создавать для группы процессов "свой собственный мир", в котором они видят только те ресурсы, которые принадлежат их пространству имён.

**Ключевые принципы:**

*   Изменение ресурса внутри пространства имён может быть невидимым снаружи.
*   Позволяет монтировать ресурсы с изменением привилегий.
*   Даёт возможность запускать процессы в полностью изолированной среде.
*   Является основой для **контейнеров** и **подов** (в Kubernetes).

Именно `namespaces` вместе с **[cgroups](./cgroups.md)** лежат в основе технологии контейнеризации (Docker, Podman, Kubernetes).

## Основные типы пространств имён

1.  **Mount (mnt):**
    -   **Изолирует:** Точки монтирования файловых систем.
    -   **Как работает:** Процессы в одном `mnt` namespace могут иметь свой собственный, уникальный набор смонтированных файловых систем, невидимый для других процессов. Это позволяет:
        -   Создавать для процесса свою собственную корневую файловую систему (`/`), изолированную от хоста.
        -   Иметь приватные точки монтирования. Например, можно смонтировать собственную, изолированную версию `/tmp`, `/sys` или `/proc`, что является основой для работы контейнеров.

2.  **PID (Process ID):**
    -   **Изолирует:** Идентификаторы процессов (PID).
    -   **Как работает:**
        -   Процессы внутри одного PID namespace видят только те процессы, которые находятся в том же самом namespace.
        -   Каждый PID namespace имеет свою собственную, изолированную иерархию процессов, которая начинается с PID 1.
        -   Первый процесс, созданный в namespace, получает PID 1 и становится "init-процессом" для этого namespace.
        -   Если этот "init-процесс" (PID 1) завершается, ядро завершает все остальные процессы в этом namespace, и сам namespace уничтожается.
        -   Снаружи (в родительском namespace) эти же процессы имеют другие, уникальные для всей системы PID.

3.  **Network (net):**
    -   **Изолирует:** Сетевой стек.
    -   **Как работает:** Процесс в новом `net` namespace получает полностью изолированное сетевое окружение, которое включает:
        -   **Сетевые интерфейсы:** Свой набор сетевых устройств, включая собственный `loopback` (`lo`).
        -   **Таблицу маршрутизации:** Собственные правила маршрутизации.
        -   **Правила Firewall:** Изолированные правила `iptables` или `nftables`.
        -   **Сетевые сокеты:** Изолированные порты и сокеты.
    -   Для связи с внешним миром (или другими namespace) обычно используются виртуальные Ethernet-пары (`veth`).
    -   Несколько процессов (или контейнеров) могут совместно использовать один и тот же network namespace, что позволяет им взаимодействовать через `localhost` (например, как в подах Kubernetes).

4.  **User:**
    -   **Изолирует:** Идентификаторы пользователей и групп (UID, GID).
    -   **Как работает:** Позволяет создавать сопоставление (mapping) между пользователями внутри namespace и пользователями на хостовой системе.
        -   Ключевая возможность — сопоставить UID 0 (`root`) внутри namespace с обычным, непривилегированным UID на хосте.
        -   Таким образом, процесс может выполняться с полными правами администратора внутри своего namespace, но для основной системы он остается процессом с ограниченными правами. Это фундаментальный механизм для безопасной работы контейнеров (rootless containers).

5.  **IPC (Inter-Process Communication):**
    -   **Изолирует:** Механизмы межпроцессного взаимодействия, такие как семафоры, очереди сообщений и разделяемая память (System V IPC).

6.  **UTS (UNIX Timesharing System):**
    -   **Изолирует:** Имя хоста и доменное имя (`hostname`, `domainname`).
    -   **Как работает:** Позволяет каждому контейнеру иметь своё собственное уникальное имя хоста.

## Управление пространствами имён

Для создания и управления пространствами имён в Linux используются следующие системные вызовы и утилиты:

*   **`clone()`**: Системный вызов, который создаёт новый процесс. При использовании специальных флагов (например, `CLONE_NEWPID`, `CLONE_NEWNET`) он создаёт процесс в новом пространстве имён указанного типа.
*   **`unshare()`**: Системный вызов, который позволяет процессу "отсоединиться" от своего текущего пространства имён и перейти в новое.
*   **`setns()`**: Системный вызов, который позволяет процессу присоединиться к уже существующему пространству имён.
*   **Утилиты командной строки:** `unshare`, `nsenter` — позволяют вручную создавать и входить в пространства имён из терминала, что полезно для отладки.
