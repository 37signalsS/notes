# Определения

**OpenPGP** — это протокол и спецификация, описывающая механизм, использующий преимущественно асимметричные алгоритмы для шифрования, подписи и дешифрования сообщений.

**GnuPG (GPG)** — это приложение с интерфейсом командной строки, реализующее спецификацию OpenPGP.

---

# Основные концепции

## Типы шифрования

| Характеристика | Симметричное шифрование | Асимметричное шифрование |
| :--- | :--- | :--- |
| **Количество ключей** | Один | Два (открытый и закрытый) |
| **Скорость** | Высокая | Низкая |
| **Управление ключами** | Сложное (требуется безопасная передача) | Простое (открытый ключ можно передавать свободно) |
| **Основное применение** | Шифрование больших объемов данных | Безопасный обмен ключами, цифровые подписи |

### Гибридное шифрование

На практике для достижения наилучших результатов используется комбинация обоих методов — **гибридное шифрование**, которое и лежит в основе PGP/GPG:

1. Для шифрования основного объема данных генерируется случайный, одноразовый **симметричный** ключ.
2. Данные шифруются с помощью этого быстрого симметричного ключа.
3. Сам симметричный ключ шифруется с помощью **асимметричного** шифрования (используя открытый ключ получателя).
4. Зашифрованные данные и зашифрованный симметричный ключ отправляются получателю.
5. Получатель использует свой закрытый ключ для расшифровки симметричного ключа, а затем этим симметричным ключом быстро расшифровывает основной объем данных.

## Асимметричная криптография в PGP

Концепция заключается в использовании двух связанных ключей:

- **Приватный (закрытый) ключ:** Используется для создания подписей и расшифровки сообщений. **Его необходимо хранить в строгом секрете.**
- **Публичный (открытый) ключ:** Производный от приватного, он используется для проверки подписей и шифрования сообщений для владельца приватного ключа. Его можно свободно распространять.

### Сеть доверия (Web of Trust)

В PGP для подтверждения подлинности личности используется **Сеть доверия (Web of Trust, WoT)**. Вместо централизованных удостоверяющих центров (CA), каждый участник сам решает, кому доверять, подписывая публичные ключи других пользователей своим приватным ключом.

### Мастер-ключ и подключи (Sub-keys)

Чтобы избежать необходимости перестраивать всю сеть доверия при компрометации ключа, используется система **мастер-ключей** и **подключей**:

- **Мастер-ключ (сертификационный ключ):**
  - Используется только для управления связкой: подписи и отзыва подключей, а также для подписи ключей других людей в рамках Web of Trust.
  - **Хранится в безопасном, изолированном месте (офлайн).**
  - Имеет срок истечения.
  - Для него заранее создается **сертификат отзыва** на случай компрометации.

- **Подключи (саб-ключи):**
  - Генерируются из мастер-ключа для повседневных операций: шифрования, подписи, аутентификации.
  - Могут быть отозваны мастер-ключом без необходимости отзывать всю связку.

# Практические сценарии

## 1. Первоначальная настройка

### Конфигурация клиента GPG

Создайте или отредактируйте файл `~/.gnupg/gpg.conf` для более удобного вывода:

```ini
keyid-format short
throw-keyids
no-emit-version
no-comments
```

### Настройка сервера ключей

Для публикации и получения публичных ключей настройте сервер по умолчанию в `~/.gnupg/gpg.conf`:

```ini
keyserver hkps://keys.openpgp.org
```

## 2. Создание и управление связкой ключей

### Генерация мастер-ключа

Для полного контроля над процессом используйте команду:

```sh
gpg --full-generate-key --expert
```

- **Тип ключа:** Рекомендуется `(9) ECC (sign and encrypt)`.
- **Кривая:** Рекомендуется `(1) Curve 25519`.
- **Срок действия:** Рекомендуется установить срок (например, `2y`), его можно будет изменить позже.
- **Данные (UID):** Введите реальные имя и Email. Эти данные будут привязаны к вашему ключу.

### Добавление подключей для разных задач

Войдите в режим редактирования, чтобы добавить отдельные ключи для подписи и аутентификации:

```sh
gpg --edit-key --expert <Ваш_UserID_или_KeyID>
```

Внутри редактора (`gpg>`) выполните:

1. **Добавить ключ для подписи:**
    - `addkey` → `(10) ECC (sign only)` → `(1) Curve 25519` → установить срок действия (например, `2y`).
2. **Добавить ключ для аутентификации:**
    - `addkey` → `(11) ECC (set your own capabilities)`
    - В диалоге действий отключите `Sign` (S) и включите `Authenticate` (A).
    - `(1) Curve 25519` → установить срок действия (например, `2y`).
3. Сохраните изменения: `save`.

## 3. Резервное копирование и безопасность

### Экспорт ключей и сертификата отзыва

- **Публичный ключ (для всех):**

    ```sh
    gpg --export -a <UserID> > public_key.asc
    ```

- **Приватные подключи (для ваших рабочих устройств):**

    ```sh
    gpg --export-secret-subkeys -a <UserID> > private_subkeys.asc
    ```

- **Приватный мастер-ключ (только для бэкапа):**

    ```sh
    gpg --export-secret-keys -a <UserID> > private_master_key.asc
    ```

- **Сертификат отзыва (на случай компрометации):**

    ```sh
    gpg -a --gen-revoke <UserID> > revocation_certificate.asc
    ```

**ВАЖНО:** Храните **мастер-ключ** и **сертификат отзыва** в разных, очень надежных и изолированных местах (например, на зашифрованных USB-накопителях в сейфе).

### Удаление мастер-ключа с рабочей машины

После создания бэкапов удалите секретный мастер-ключ с компьютера. Для повседневных задач используются только подключи.

```sh
# Укажите ID именно мастер-ключа с восклицательным знаком в конце!
gpg --delete-secret-key <MasterKeyID>!
```

## 4. Повседневные операции

### Импорт ключей

```sh
# Импорт публичных, приватных ключей или сертификатов отзыва
gpg --import <file.asc>
```

### Криптографические подписи

- **Создать "чистую" подпись (clear-sign, текст виден):**

    ```sh
    gpg --clear-sign file.txt
    ```

- **Создать отдельную подпись (detached, для бинарных файлов):**

    ```sh
    gpg --detach-sign -a file.zip
    ```

- **Проверить подпись:**

    ```sh
    # Для --detach-sign
    gpg --verify file.zip.asc file.zip
    # Для --clear-sign или --sign (файл содержит и подпись, и данные)
    gpg --decrypt signed_file.asc
    ```

### Шифрование и расшифровка

- **Асимметричное шифрование (для конкретного получателя):**

    ```sh
    # -e (encrypt), -r (recipient), -a (armored, текстовый формат)
    gpg -e -a -r <Recipient_UserID> file.txt
    ```

- **Шифрование с одновременной подписью:**

    ```sh
    gpg -e -a -s -r <Recipient_UserID> file.txt
    ```

- **Симметричное шифрование (защита паролем, без ключей):**

    ```sh
    # -c (symmetric cipher)
    gpg -c -a file.txt
    ```

- **Расшифровка:**

    ```sh
    gpg -d file.txt.asc
    # или
    gpg --decrypt file.txt.asc
    ```

### Работа с серверами ключей

- **Отправить свой ключ на сервер:**

    ```sh
    gpg --send-keys <UserID>
    ```

- **Получить ключ с сервера:**

    ```sh
    gpg --recv-keys <UserID_или_KeyID>
    ```

- **Обновить все локальные ключи с сервера:**

    ```sh
    gpg --refresh-keys
    ```

## 5. Интеграции

### Подпись коммитов в Git

1. **Настройте Git на использование вашего ключа подписи:**

    ```ini
    # ~/.gitconfig
    [user]
      email = ваш_email_из_uid
      name = ваше_имя
      signingkey = <ID_ключа_подписи>!
    ```

2. **Включите подпись по умолчанию для всех коммитов:**

    ```sh
    git config --global commit.gpgsign true
    ```

3. **Для создания подписанного коммита (если не включено по умолчанию):**

    ```sh
    git commit -S -m "Мой подписанный коммит"
    ```

### Аутентификация по SSH

GPG-Agent может выступать в роли ssh-agent.

1. **Включите поддержку SSH в `~/.gnupg/gpg-agent.conf`:**

    ```
    enable-ssh-support
    ```

2. **Получите keygrip вашего ключа аутентификации и добавьте его в `~/.gnupg/sshcontrol`:**

    ```sh
    gpg -K --with-keygrip <AuthKeyID>!
    # Вывод команды покажет keygrip, который нужно скопировать
    echo "СКОПИРОВАННЫЙ_KEYGRIP" >> ~/.gnupg/sshcontrol
    ```

3. **Настройте переменные окружения** в вашем `.bashrc` или `.zshrc`, чтобы система использовала сокет `gpg-agent` вместо `ssh-agent`.
4. **Экспортируйте публичный SSH-ключ** и добавьте его на сервер в `~/.ssh/authorized_keys`:

    ```sh
    gpg --export-ssh-key <AuthKeyID>!
    ```
