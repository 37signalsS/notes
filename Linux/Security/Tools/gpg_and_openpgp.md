# GPG и OpenPGP

## Определения

**OpenPGP** — открытый стандарт и протокол шифрования на основе асимметричных алгоритмов, предназначенный для шифрования, дешифрования и создания цифровых подписей сообщений и файлов.

**GnuPG (GPG)** — свободная программная реализация стандарта OpenPGP с интерфейсом командной строки, обеспечивающая высокий уровень защиты данных.

## Базовые концепции

### Типы шифрования

| Характеристика | Симметричное | Асимметричное |
| :--- | :--- | :--- |
| **Ключи** | Один (общий) | Пара (публичный + приватный) |
| **Скорость** | Высокая | Относительно низкая |
| **Управление** | Сложное (безопасная передача ключа) | Простое (публичный ключ открыт) |
| **Применение** | Шифрование больших объемов данных | Обмен ключами, цифровые подписи |

### Гибридное шифрование

GPG использует комбинацию обоих методов для достижения баланса между скоростью и безопасностью:
1.  Генерируется случайный одноразовый **симметричный ключ сессии**.
2.  Данные шифруются этим ключом (быстро).
3.  Ключ сессии шифруется **публичным ключом** получателя (асимметрично).
4.  Получатель расшифровывает ключ сессии своим **приватным ключом**, а затем расшифровывает сами данные.

### Структура ключей: Мастер-ключ и подключи

Для повышения безопасности в GPG используется иерархическая структура:

*   **Мастер-ключ (Certify - C):**
    *   Используется только для управления: создания/отзыва подключей и подписи чужих ключей.
    *   **Должен храниться офлайн** (на зашифрованном USB-накопителе или аппаратном токене).
    *   Имеет сертификат отзыва, создаваемый заранее.
*   **Подключи (Subkeys):**
    *   **Sign (S):** для создания цифровых подписей (например, коммитов в Git).
    *   **Encrypt (E):** для шифрования данных.
    *   **Authenticate (A):** для аутентификации (например, доступ по SSH).
    *   Могут быть легко отозваны и заменены без смены мастер-ключа.

### Сеть доверия (Web of Trust) и уровни доверия

В отличие от иерархической модели PKI (где есть корневой CA), в OpenPGP используется децентрализованная модель. Участники подтверждают подлинность ключей друг друга, подписывая их.

**Уровни доверия владельцу ключа (Trust levels):**
1.  **Unknown (Неизвестно):** уровень доверия не установлен.
2.  **None (Нет доверия):** вы не доверяете этому человеку в вопросе подписи других ключей.
3.  **Marginal (Ограниченное):** вы доверяете человеку, но для подтверждения ключа требуется минимум три таких подписи.
4.  **Full (Полное):** вы полностью доверяете человеку в вопросе проверки других ключей.
5.  **Ultimate (Абсолютное):** обычно устанавливается только для своих собственных ключей.

## Практические сценарии

### Настройка конфигурации

Рекомендуемые параметры в `~/.gnupg/gpg.conf` для улучшения приватности и безопасности:

```ini
# Использовать длинные ID ключей (защита от коллизий)
keyid-format long
with-fingerprint
# Скрывать идентификаторы получателей (усложняет мета-анализ)
throw-keyids
# Не выводить версию GPG и комментарии в сообщениях
no-emit-version
no-comments
# Выбор серверов ключей
keyserver hkps://keys.openpgp.org
```

### Генерация и управление ключами

```bash
# Создание мастер-ключ в экспертном режиме
gpg --full-generate-key --expert
# → result: Выберите тип ключа: (9) ECC (sign and encrypt)
# → result: Выберите кривую: (1) Curve 25519

# Добавление подключей
gpg --edit-key <Key_ID>
# В консоли gpg>
# addkey -> (10) ECC (sign only) -> Curve 25519 (для подписи)
# addkey -> (11) ECC (set own capabilities) -> включить только Authenticate (для SSH)
# save
```

### Резервное копирование и удаление секрета

```bash
# Экспорт публичной части
gpg --export -a <Key_ID> > public.asc

# Экспорт всей связки (только для бэкапа!)
gpg --export-secret-keys -a <Key_ID> > private_full.asc

# Экспорт только подключей для повседневного использования
gpg --export-secret-subkeys -a <Key_ID> > private_subkeys.asc

# Генерация сертификата отзыва (сделать СРАЗУ)
gpg --gen-revoke <Key_ID> > revoke.asc

# Удаление мастер-ключа с рабочей машины (после бэкапа!)
gpg --delete-secret-keys <Key_ID>!
```

### Продление срока действия ключа

Если срок действия ключа или подключа истекает, его можно продлить:

```bash
gpg --edit-key <Key_ID>
# Выбрать конкретный ключ (например, подключ 1): key 1
# Команда: expire
# Указать срок (например, 1y)
# save
# После этого нужно обновить ключ на серверах: gpg --send-keys <Key_ID>
```

### Использование аппаратных токенов (YubiKey)

Перенос ключей на смарт-карту (например, YubiKey) делает их неизвлекаемыми:

```bash
gpg --edit-key <Key_ID>
# Выбрать ключ: key 1
# Переместить на карту: keytocard
# Выбрать слот (Signature, Encryption или Authentication)
# save
```
*Внимание: операция перемещения необратима, убедитесь в наличии бэкапа.*

### Работа с цифровыми подписями

```bash
# Создание текстовой подписи (содержимое файла остается читаемым)
gpg --clear-sign document.txt

# Создание отдельного файла подписи (.sig)
gpg --detach-sign -a image.iso

# Проверка подписи
gpg --verify image.iso.asc image.iso
```

### Шифрование данных

```bash
# Асимметричное шифрование для получателя
gpg -e -a -r user@example.com sensitive_data.txt

# Симметричное шифрование (только пароль)
gpg -c -a secret_note.txt

# Расшифровка
gpg -d encrypted_file.asc
```

### Интеграция с Git и SSH

**Подпись коммитов Git:**
```bash
git config --global user.signingkey <Subkey_ID_Sign>!
git config --global commit.gpgsign true
```

**SSH-аутентификация через GPG-Agent:**
1.  В `~/.gnupg/gpg-agent.conf` добавить `enable-ssh-support`.
2.  Добавить Keygrip подключа аутентификации в `~/.gnupg/sshcontrol`.
3.  Прописать переменные окружения в `.bashrc`/`.zshrc`:
    ```bash
    export SSH_AUTH_SOCK=$(gpgconf --list-dirs agent-ssh-socket)
    gpgconf --launch gpg-agent
    ```

### Лучшие практики

1.  **ECC вместо RSA:** Используйте алгоритмы на эллиптических кривых (Curve 25519) — они быстрее и обеспечивают аналогичную стойкость при меньшем размере ключа.
2.  **Мастер-ключ офлайн:** Никогда не храните мастер-ключ на устройстве, подключенном к сети. Используйте его только для продления срока или смены подключей.
3.  **Срок действия:** Всегда устанавливайте дату истечения (не более 2 лет). Это заставляет регулярно проводить аудит безопасности ключей.
4.  **Специфические инструменты:** Для простых задач шифрования (без сложной системы доверия) рассмотрите современные альтернативы, такие как **age**, которые проще в использовании и лишены исторического наследия PGP.
5.  **Pinentry:** Используйте графические или консольные pinentry-утилиты для безопасного ввода пароля ключа.
