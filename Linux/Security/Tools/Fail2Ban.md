# Fail2Ban: Защита сервера от атак

## Определения

**Fail2Ban** — это система предотвращения атак brute-force, которая мониторит логи служб (например, `/var/log/auth.log`, журналы веб-серверов) на предмет IP-адресов, демонстрирующих вредоносные признаки (такие как слишком частые неудачные попытки входа в систему, поиск эксплойтов и т. д.). Она автоматически блокирует подозрительные IP-адреса, используя правила брандмауэра.

## Основные понятия

### Принцип работы

1.  **Мониторинг логов**: В реальном времени отслеживает логи служб (например, SSH, Apache, Nginx) на предмет подозрительной активности.
2.  **Обнаружение аномалий**: С помощью регулярных выражений (фильтров) ищет паттерны, указывающие на вредоносные действия, такие как многократные неудачные попытки входа или сканирование портов.
3.  **Временная блокировка**: При обнаружении заданного количества нарушений за определенный период времени (`maxretry`, `findtime`) Fail2Ban блокирует IP-адрес нарушителя на заданное время (`bantime`), добавляя правила в брандмауэр.
4.  **Автоматическая разблокировка**: По истечении `bantime` IP-адрес автоматически разблокируется.

### Особенности

*   Поддерживает различные бэкенды для блокировки (iptables, nftables, firewalld).
*   Гибкая настройка фильтров через регулярные выражения.
*   Возможность отправки уведомлений по email.
*   Интеграция с systemd journal.
*   Эффективное управление большим количеством IP-адресов через `ipset`.

## Практические сценарии

### 1. Установка

Для установки Fail2Ban:

*   **Debian/Ubuntu**:
    ```bash
    sudo apt update
    sudo apt install fail2ban ipset
    ```
*   **CentOS/RHEL**:
    ```bash
    sudo dnf install fail2ban
    ```

`ipset` рекомендуется для более эффективной блокировки большого количества IP-адресов, так как он позволяет хранить IP-адреса в хэшированных таблицах, что значительно быстрее, чем добавление множества отдельных правил в `iptables`.

### 2. Конфигурация

Основной файл конфигурации Fail2Ban находится по пути `/etc/fail2ban/jail.conf`. **Не рекомендуется изменять этот файл напрямую**, так как он может быть перезаписан при обновлении пакета. Вместо этого следует создать файл `jail.local`, который будет переопределять настройки из `jail.conf`.

```bash
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
```

#### Основные параметры в `jail.local`

В секции `[DEFAULT]` можно определить общие параметры, которые будут применяться ко всем "тюрьмам" (jails), если они не переопределены в конкретной секции:

*   `bantime`: Время блокировки IP-адреса в секундах (по умолчанию 10 минут).
*   `findtime`: Период времени в секундах, за который Fail2Ban сканирует логи на наличие ошибок (по умолчанию 10 минут).
*   `maxretry`: Количество неудачных попыток, прежде чем IP-адрес будет заблокирован (по умолчанию 5).
*   `destemail`: Адрес электронной почты для уведомлений.
*   `sendername`: Имя отправителя для уведомлений.
*   `mta`: Почтовый агент для отправки уведомлений.
*   `action`: Действие, которое будет выполняться при блокировке. По умолчанию используется `iptables-multiport`. Рекомендуется использовать `ipset` для повышения производительности:

    ```ini
    # Пример использования ipset
    banaction = iptables-ipset-protoall
    ```

#### Настройка "Тюрем" (Jails)

Jail — это набор правил для конкретной службы. В `jail.local` вы найдете множество предопределенных секций для различных служб. Для активации "тюрьмы" достаточно добавить секцию с `enabled = true`.

**Пример настройки для SSH:**

```ini
[sshd]
enabled = true
port = ssh
logpath = /var/log/auth.log ; Путь к логу SSH
maxretry = 3                 ; Количество неудачных попыток входа
bantime = 3600               ; Время блокировки IP-адреса (в секундах = 1 час)
findtime = 600               ; Период времени (в секундах = 10 минут)
```
*   `enabled = true`: Активирует эту "тюрьму".
*   `port`: Порт службы (можно указать несколько через запятую).
*   `filter`: Имя файла фильтра (без расширения `.conf`), который находится в `/etc/fail2ban/filter.d/`.
*   `logpath`: Путь к файлу журнала, который будет сканироваться.
*   `maxretry`: Количество неудачных попыток.
*   `findtime`: Период времени, за который Fail2Ban сканирует логи на наличие ошибок.
*   `bantime`: Время блокировки.

Пример фильтра для защиты от сканирования Nginx (ошибки 404):

```ini
[nginx-404]
enabled = true
port = http,https
logpath = /var/log/nginx/access.log
maxretry = 5
findtime = 300
```

#### Защита от DoS-атак с NGINX

Fail2Ban может использоваться для защиты NGINX от DoS-атак в сочетании с модулем `limit_req` NGINX.

1.  **Настройка NGINX `limit_req`**:
    В конфигурации NGINX (`nginx.conf`) определите зону ограничения запросов:

    ```nginx
    http {
        limit_req_zone $binary_remote_addr zone=mylimit:10m rate=3r/s;
        # ...
        server {
            # ...
            location / {
                limit_req zone=mylimit burst=5 nodelay;
                # ...
            }
        }
    }
    ```
    Здесь `rate=3r/s` означает 3 запроса в секунду, `burst=5` позволяет 5 запросов сверх лимита, `nodelay` означает, что запросы не будут задерживаться, а будут обрабатываться сразу, пока не превышен `burst`. Если `nodelay` не указан, запросы будут обрабатываться с частотой, определенной в `rate`. При превышении лимита NGINX возвращает ошибку 503.

2.  **Настройка Fail2Ban для NGINX `limit_req`**:
    Создайте или отредактируйте секцию `[nginx-limit-req]` в `jail.local`:

    ```ini
    [nginx-limit-req]
    enabled = true
    port = http,https
    filter = nginx-limit-req
    logpath = /var/log/nginx/error.log
    maxretry = 5
    findtime = 600
    bantime = 3600
    action = iptables-ipset-protoall[name=nginx-limit-req, port="http,https", protocol=tcp]
    ```

    *   `filter = nginx-limit-req`: Этот фильтр (находится в `/etc/fail2ban/filter.d/nginx-limit-req.conf`) ищет в логах NGINX записи о превышении лимита запросов (например, "limiting requests, excess").
    *   `logpath`: Путь к файлу `error.log` NGINX.
    *   `findtime` и `bantime`: Настройте эти параметры в соответствии с вашими потребностями. Для `nginx-limit-req` рекомендуется более осторожный `bantime` из-за возможности ложных срабатываний.

#### Изменение типа блокировки (DROP вместо REJECT)

По умолчанию `iptables` может использовать действие `REJECT`, которое отправляет ответный пакет нарушителю. Для более эффективной защиты от DoS-атак рекомендуется использовать `DROP`, который просто отбрасывает пакеты без уведомления отправителя.

Создайте файл `/etc/fail2ban/action.d/iptables-blocktype.local` (или отредактируйте `iptables-blocktype.conf` с осторожностью):

```ini
[Definition]
blocktype = DROP
```

### 3. Управление Fail2Ban

*   **Управление службой**:
    ```bash
    sudo systemctl start fail2ban
    sudo systemctl stop fail2ban
    sudo systemctl restart fail2ban
    sudo fail2ban-client reload # Перезагрузка конфигурации
    ```
*   **Проверка статуса**:
    ```bash
    sudo systemctl status fail2ban
    sudo fail2ban-client status
    sudo fail2ban-client status <jail_name> # Например, sshd
    ```
*   **Управление заблокированными IP**:
    ```bash
    # Разблокировать IP-адрес
    sudo fail2ban-client set <jail_name> unbanip <IP_address>
    # Заблокировать IP-адрес вручную
    sudo fail2ban-client set <jail_name> banip <IP_address>
    ```

## Дополнительная информация

### Интеграция и производительность
*   **`ipset`**: Настоятельно рекомендуется использовать `ipset` вместе с `fail2ban` для управления большими списками заблокированных IP-адресов. Это значительно производительнее, чем добавление отдельных правил `iptables` для каждого IP.
*   **`systemd journal`**: `fail2ban` может быть настроен на чтение логов напрямую из `systemd journal` вместо файлов, что является более современным подходом. Для этого в определении "тюрьмы" (jail) параметр `backend` должен быть установлен в `systemd`.

### Бэкенды блокировки
`fail2ban` поддерживает различные бэкенды для блокировки, что делает его гибким инструментом:
*   `iptables` (по умолчанию)
*   `nftables`
*   `firewalld`
*   `shorewall`

### Рекомендации
*   **Никогда не изменяйте `jail.conf`**. Всегда создавайте `jail.local` для внесения изменений. Это предотвратит их потерю при обновлении пакета `fail2ban`.
*   Регулярно проверяйте статус `fail2ban` (`sudo fail2ban-client status`) и логи (`/var/log/fail2ban.log`) для выявления аномалий или ложных срабатываний.
*   Для получения более подробной информации обратитесь к [официальной документации Fail2Ban](https://www.fail2ban.org/wiki/index.php/Main_Page).
