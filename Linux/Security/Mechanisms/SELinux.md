# SELinux (Security-Enhanced Linux): Управление и Практика

## Определения

**SELinux (Security-Enhanced Linux)** — это механизм принудительного контроля доступа (Mandatory Access Control, MAC), реализованный в ядре Linux. В отличие от стандартной модели дискреционного контроля доступа (Discretionary Access Control, DAC), где правами управляет владелец файла, SELinux применяет централизованные политики безопасности, которые не могут быть обойдены ни пользователями, ни процессами.

### Основные термины и понятия

#### MLS (Multi-Level Security) и MCS (Multi-Category Security)

Это механизмы мандатного управления доступом, которые по умолчанию редко используются в повседневной практике. Они характеризуются вертикальным уровнем контроля, используя метки.

* **Многоуровневая система безопасности (MLS):** Определяет иерархические уровни доступа (например, "совершенно секретно", "секретно", "конфиденциально").
* **Многокатегорийная система безопасности (MCS):** Определяет неиерархические категории доступа (например, "проект А", "проект Б").

#### RBAC (Role-Based Access Control)

Управление доступом на основе ролей. В SELinux это означает:

* **SELinux User:** Сущность, которая сопоставляется с обычным пользователем Linux.
* **Role:** Определяет, в какие домены может входить пользователь.
* **User:** Пользователь, который входит в определенную роль.

Пользователь, входящий в определенную роль, получает доступ к соответствующим доменам (наборам действий).

#### Type Enforcement (TE)

Это основной механизм принудительной типизации доступа в SELinux, с которым чаще всего приходится работать.

* **Контекст безопасности (Security Context):** Является меткой, атрибутом, который хранится в расширенных атрибутах файловой системы. Выглядит как строка `user:role:type:level` и объединяет в себе:
  * **SELinux User:** Пользователь SELinux.
  * **Role:** Роль.
  * **Type (Domain):** Тип (для объектов) или домен (для процессов).
  * **Sensitivity/Category:** Уровень чувствительности/категории (используется в MLS/MCS).

    Пример контекста: `system_u:object_r:httpd_port_t:s0`

* **Домен (Domain):** Для процессов домен определяет список разрешенных действий.
* **Тип (Type):** Для объектов (файлов, каталогов, портов) тип определяет, кто может получить к ним доступ.
* **Роль (Role):** Определяет, в какие домены может входить пользователь.

## Основные концепции

### Схема работы SELinux

1. **Субъект (процесс) с контекстом безопасности** пытается получить доступ к **объекту (файлу, порту) с контекстом безопасности**.
2. **SELinux** обращается к своим политикам (базе данных правил, загруженной в ядро).
3. На основе сопоставления контекстов субъекта и объекта, SELinux **разрешает** или **запрещает** доступ.
4. Все действия протоколируются.

SELinux работает путем сопоставления контекста субъекта (процесса) с контекстом объекта (файла, порта). Если политика разрешает взаимодействие между этими контекстами, действие выполняется; в противном случае — блокируется.

### Особенности применения

* **Гибкое ограничение прав:** SELinux позволяет гибко ограничивать права пользователей и процессов на уровне ядра.
* **Снижение рисков:** Снижает риски, возникающие вследствие ошибок разработчиков или компрометации приложений.
* **Изоляция процессов:** Ограничивает потенциально опасные или скомпрометированные процессы в правах.
* **Протоколирование действий:** SELinux записывает все свои действия в системный журнал, что критически важно для аудита.

### Режимы работы SELinux

* **`Enforcing`**: Режим по умолчанию. Политики безопасности активно применяются, все нарушения блокируются и записываются в лог.
* **`Permissive`**: Политики не применяются (нарушения не блокируются), но все действия, которые были бы запрещены, записываются в лог. Этот режим полезен для отладки и создания политик.
* **`Disabled`**: SELinux полностью отключен.

### Булевы значения (Booleans)

Булевы значения — это параметризованные политики, которые позволяют включать или отключать определенные функции SELinux без изменения всей политики. Они часто используются для разрешения или запрета общих сценариев.

### Фреймворк LSM (Linux Security Modules)

LSM — это фреймворк в ядре Linux, который предоставляет стандартизированную инфраструктуру для реализации различных моделей MAC. Он встраивает "хуки" в ключевые точки кода ядра, которые вызываются перед выполнением критически важных операций. SELinux является одной из реализаций, построенных на базе LSM.

## Практические сценарии

### Инструменты для работы с SELinux

* **`setools-console` пакет:** `semanage`, `seinfo`, `sesearch`, `audit2allow`.
* **`policycoreutils` пакет:** `restorecon`, `setenforce`, `sestatus`, `matchpathcon`.
* **`audit` пакет:** `auditctl`, `ausearch`, `aureport`.

### Управление режимами

* **Проверить текущий статус и режим:**

    ```bash
    sestatus
    getenforce
    ```

* **Временно переключить режим (до перезагрузки):**

    ```bash
    # Перевести в режим "только логирование"
    sudo setenforce 0 # или sudo setenforce Permissive
    # Вернуть в режим принудительного применения политик
    sudo setenforce 1 # или sudo setenforce Enforcing
    ```

* **Отключить SELinux навсегда (требуется перезагрузка):**
    1. Откройте файл `/etc/selinux/config` или `/etc/sysconfig/selinux`.
    2. Измените значение `SELINUX` на `permissive` или `disabled`.

        ```ini
        SELINUX=disabled
        ```

    3. Перезагрузите систему.

> **Важно:** Полностью отключить SELinux на лету (без перезагрузки) невозможно. Команда `setenforce 0` переводит SELinux только в режим `Permissive`, где политики не применяются, но сам механизм SELinux продолжает работать. Для полного отключения (`Disabled`) требуется изменение конфигурационного файла и перезагрузка системы. Это связано с тем, что при полном отключении SELinux необходимо перемаркировать файловую систему, что может быть выполнено только во время загрузки.

> В средах с повышенными требованиями к безопасности может быть настроено принудительное применение политики, игнорирующее этот конфигурационный файл.

### Просмотр и управление политиками

* **Просмотр контекстов безопасности:**
  * Для файлов и каталогов: `ls -Z` или `ls --context`

        ```bash
        ls -Z /var/www/html
        # Вывод: drwxr-xr-x. root root system_u:object_r:httpd_sys_content_t:s0 /var/www/html
        ```

  * Для процессов: [`ps -Z`](../../Diagnostics/Processes/ps.md)

        ```bash
        [`ps -Z aux | grep nginx`](../../Diagnostics/Processes/ps.md)
        # Вывод: system_u:system_r:httpd_t:s0 root 12345 ... nginx
        ```

* **Управление SELinux-пользователями, ролями и типами:**

    ```bash
    # Просмотр пользователей
    semanage user -l
    # Просмотр ролей
    semanage role -l
    # Просмотр типов
    seinfo -t
    ```

* **Управление портами:** SELinux контролирует, какие процессы могут слушать на определенных портах.

    ```bash
    # Просмотр разрешенных портов для типа httpd_port_t
    semanage port -l | grep http_port_t

    # Добавление нового порта для типа
    sudo semanage port -a -t http_port_t -p tcp 5080

    # Удаление порта
    sudo semanage port -d -t http_port_t -p tcp 5080
    ```

* **Управление файловыми контекстами:**

    ```bash
    # Просмотр правил файловых контекстов
    semanage fcontext -l | grep '/var/www'

    # Добавление правила для нового каталога
    sudo semanage fcontext -a -t httpd_sys_content_t "/srv/my_app(/.*)?"

    # Применение нового контекста к файлам
    sudo restorecon -Rv /srv/my_app
    ```

* **Управление булевыми значениями:**

    ```bash
    # Просмотр всех булевых значений
    getsebool -a

    # Включение/отключение значения (временно)
    sudo setsebool httpd_can_network_connect on

    # Включение/отключение значения (постоянно)
    sudo setsebool -P httpd_can_network_connect on
    ```

    **Примеры:** `httpd_can_network_connect`, `samba_enable_home_dirs`, `allow_ftpd_full_access`.

### Диагностика и устранение проблем

* **Логи аудита:** SELinux записывает отказы в `/var/log/audit/audit.log`.

    ```bash
    sudo tail -f /var/log/audit/audit.log | grep AVC
    ```

* **Использование `audit2allow`:** Анализирует логи и генерирует правила политики.
    1. **Сгенерировать модуль:**

        ```bash
        sudo grep "AVC" /var/log/audit/audit.log | audit2allow -M my_custom_policy
        ```

        Это создаст файлы `my_custom_policy.te` (исходный код) и `my_custom_policy.pp` (скомпилированный модуль).
    2. **Установить модуль:**

        ```bash
        sudo semodule -i my_custom_policy.pp
        ```

* **Пример: Изменение порта SSH:**
    1. Измените порт в `/etc/ssh/sshd_config` (например, на 5022).
    2. Добавьте порт в политику SELinux:

        ```bash
        sudo semanage port -a -t ssh_port_t -p tcp 5022
        ```

    3. Перезапустите `sshd`. При возникновении проблем — проверьте логи.
* **Пример: Изменение контекста для MySQL:**
    Если каталог данных MySQL изменен на `/srv/mysql`:
    1. Измените контекст каталога:

        ```bash
        sudo semanage fcontext -a -t mysqld_db_t "/srv/mysql(/.*)?"
        sudo restorecon -Rv /srv/mysql
        ```

    2. Перезапустите MySQL.

### SELinux и Docker

SELinux контролирует доступ контейнеров к файловой системе хоста.

* **Маркировка файлов:** Файлы, созданные контейнерами, получают контекст `container_file_t`.
* **Монтирование томов:** При монтировании томов используйте флаги для автоматической смены контекста:
  * `z`: Приватный, неразделяемый контекст.
  * `Z`: Общий, разделяемый контекст.

    ```bash
    docker run -v /host/path:/container/path:z my_image
    ```

## Дополнительная информация

### История создания

* Разработано Агентством национальной безопасности США (NSA).
* Впервые появилось в ядре Linux в 1998 году.
* В 2003 году вошло в состав ядра Linux 2.6 через фреймворк LSM (Linux Security Modules).

### Использование `mcstransd`

Для более удобного чтения меток MLS/MCS (например, `s0`) можно использовать демон `mcstransd`.

1. **Установить:** `sudo dnf install mcstrans` (RHEL/CentOS) или `sudo apt install mcstrans` (Debian/Ubuntu).
2. **Запустить:** `sudo systemctl start mcstransd`.
3. Теперь `ls -Z` будет показывать читаемые метки (например, `SystemLow` вместо `s0`).

### Заключение

**Важно:** Пользователь `root` с контекстом `unconfined_t` не ограничен SELinux. Это означает, что SELinux не применяет политики к процессам, запущенным от имени `root` в этом контексте.
