# SELinux

## Определения

**SELinux (Security-Enhanced Linux)** — механизм принудительного контроля доступа (Mandatory Access Control, MAC) в ядре Linux. Применяет централизованные политики безопасности, которые нельзя обойти пользователям или процессам, включая `root`.

**Проблема DAC:** стандартные права Linux (`rwx`) основаны на дискреционной модели — доступ определяется владельцем объекта. Это не защищает от вредоносного ПО, запущенного от имени пользователя, или процессов с повышенными привилегиями.

**Принцип MAC:** политики определяются централизованно и применяются на уровне ядра. Процесс с меткой «веб-сервер» не сможет читать файлы с меткой «документы_пользователей», даже если запущен от имени `root`.

### Ключевые термины

| Термин | Описание |
| :--- | :--- |
| **MAC (Mandatory Access Control)** | Мандатное управление доступом, политики определяются централизованно |
| **DAC (Discretionary Access Control)** | Дискреционное управление доступом, правами управляет владелец файла |
| **LSM (Linux Security Modules)** | Фреймворк в ядре Linux для реализации MAC. SELinux построен на базе LSM |
| **Контекст безопасности** | Метка в формате `user:role:type:level` в расширенных атрибутах файлов |
| **AppArmor** | Альтернативный LSM-модуль (Ubuntu, Debian, openSUSE). Основан на **путях**, а не метках |

### Компоненты контекста безопасности

| Компонент | Описание | Пример |
| :--- | :--- | :--- |
| **User** | Пользователь SELinux | `system_u`, `unconfined_u` |
| **Role** | Роль, определяющая доступные домены | `system_r`, `object_r` |
| **Type/Domain** | Тип для объектов, домен для процессов | `httpd_t`, `httpd_sys_content_t` |
| **Level** | Уровень чувствительности (MLS/MCS) | `s0`, `s0:c0.c1023` |

### Типы политик

| Тип | Описание | Применение |
| :--- | :--- | :--- |
| **TE (Type Enforcement)** | Основной механизм. Связывает процессы и объекты с типами, определяет правила взаимодействия | Базовый контроль доступа |
| **RBAC (Role-Based Access Control)** | Управление доступом на основе ролей | Ограничение ролей пользователей |
| **MLS (Multi-Level Security)** | Иерархические уровни: «совершенно секретно» > «секретно» > «открыто» | Военные, госсектор |
| **MCS (Multi-Category Security)** | Неиерархические категории: «проект А», «проект Б» | Изоляция контейнеров, мультитенант |

#### Type Enforcement (TE) — детализация

| Компонент | Описание | Пример |
| :--- | :--- | :--- |
| **Типизация объектов** | Файлы, сокеты, устройства получают тип | `httpd_sys_content_t`, `shadow_t` |
| **Типизация процессов** | Процессы работают в доменах (типах) | `httpd_t`, `sshd_t` |
| **Правила доступа** | Политика определяет разрешённые операции между типами | `httpd_t` читает `httpd_sys_content_t`, но не `shadow_t` |
| **Блокировка ядром** | Нарушения блокируются на уровне ядра | Даже процесс от `root` будет заблокирован |

## Основные концепции

### Схема работы

1. **Субъект** (процесс с контекстом) пытается получить доступ к **объекту** (файл, порт с контекстом)
2. SELinux проверяет политики (база данных правил в ядре)
3. На основе сопоставления контекстов — **разрешает** или **запрещает** доступ
4. Все действия протоколируются

### Режимы работы

| Режим | Описание | Применение |
| :--- | :--- | :--- |
| **Enforcing** | Политики активно применяются, нарушения блокируются и логируются | Производственная среда |
| **Permissive** | Политики не применяются, нарушения логируются | Отладка, создание политик |
| **Disabled** | SELinux полностью отключён | Не рекомендуется |

> **Важно:** `setenforce 0` переводит только в `Permissive`. Полное отключение (`Disabled`) требует перезагрузки для перемаркировки ФС.

### Особенности

- **Гибкое ограничение прав** — на уровне ядра
- **Снижение рисков** — от ошибок разработчиков или компрометации
- **Изоляция процессов** — ограничение скомпрометированных процессов
- **Протоколирование** — все действия записываются в журнал
- **Пользователь `root`** с контекстом `unconfined_t` не ограничен SELinux

## Практические сценарии

### 1. Проверка статуса и управление режимами

```bash
# Проверка текущего статуса
sestatus # → SELinux status: enabled
getenforce # → Enforcing

# Временное переключение (до перезагрузки)
sudo setenforce 0  # Permissive
sudo setenforce 1  # Enforcing

# Постоянное изменение: /etc/selinux/config
SELINUX=enforcing  # или permissive, disabled
```

### 2. Просмотр контекстов

```bash
# Файлы и каталоги
ls -Z /var/www/html # → unconfined_u:object_r:httpd_sys_content_t:s0 index.html

# Процессы
ps -Z aux | grep nginx # → system_u:system_r:httpd_t:s0 nginx
```

Подробнее о `ps`: [`ps`](../../Diagnostics/Processes/ps.md).

### 3. Управление пользователями, ролями, типами

```bash
# Просмотр соответствия системных пользователей пользователям SELinux
semanage login -l # → Login Name  SELinux User  MLS/MCS Range  Service

# Привязка пользователя к SELinux-пользователю
sudo semanage login -a -s staff_u user1

# Просмотр пользователей SELinux
semanage user -l # → SELinux User    Prefix    MCS Level  MCS Range

# Просмотр ролей
semanage role -l # → Role            Types

# Просмотр типов
seinfo -t # → Types: 4899
```

### 4. Переходы доменов (Domain Transitions)

Когда один процесс запускает другой, SELinux может разрешить или запретить переход в другой домен.

```bash
# Просмотр разрешённых переходов доменов
sesearch -T -s httpd_t # → type_transition httpd_t ...
```

### 5. Управление портами

```bash
# Разрешенные порты для типа http_port_t
semanage port -l | grep http_port_t # → http_port_t  tcp  80, 81, 443 ...

# Добавление нового порта
sudo semanage port -a -t http_port_t -p tcp 5080

# Удаление порта
sudo semanage port -d -t http_port_t -p tcp 5080
```

### 6. Управление файловыми контекстами

```bash
# Просмотр правил
semanage fcontext -l | grep '/var/www' # → /var/www(/.*)?  all files  system_u:object_r:httpd_sys_content_t:s0

# Добавление правила для нового каталога (постоянное изменение политики)
sudo semanage fcontext -a -t httpd_sys_content_t "/srv/my_app(/.*)?"

# Временное изменение контекста файла (до перезагрузки/перемаркировки)
sudo chcon -t httpd_sys_content_t /srv/my_app/index.html

# Восстановление контекста по умолчанию
sudo restorecon -Rv /srv/my_app # → Relabeled /srv/my_app from ... to ...
```

> **Примечание:** `chcon` — временное изменение, которое сбрасывается при `restorecon`. Рекомендуется использовать `semanage fcontext` для постоянных изменений.

### 7. Управление булевыми значениями

Параметризованные политики для включения/отключения функций без изменения всей политики:

```bash
# Просмотр всех значений
getsebool -a # → abrt_anon_write --> off ...

# Временное включение/отключение
sudo setsebool httpd_can_network_connect on

# Постоянное включение
sudo setsebool -P httpd_can_network_connect on
```

### 8. Диагностика и устранение проблем

```bash
# Логи аудита (отказы SELinux)
sudo tail -f /var/log/audit/audit.log | grep AVC # → type=AVC msg=audit(...): denied { read } ...

# Интерпретация причин отказа (почему доступ был запрещен)
sudo ausearch -m avc -ts recent | audit2why # → Was caused by: ...

# Принудительная перемаркировка файлов при загрузке
sudo touch /.autorelabel
# После перезагрузки система перемаркирует все файлы
```

**Экспорт и импорт политик:**

```bash
# Экспорт всех настроек (порты, контексты, булевы значения)
sudo semanage export -f selinux_settings.mod

# Импорт настроек
sudo semanage import -f selinux_settings.mod
```

**Создание модуля политики:**

```bash
# Генерация модуля из логов
sudo grep "AVC" /var/log/audit/audit.log | audit2allow -M my_custom_policy # → ...

# Установка модуля
sudo semodule -i my_custom_policy.pp
```

### 9. Примеры настройки

**Изменение порта SSH:**

```bash
# 1. Изменить порт в /etc/ssh/sshd_config (например, 5022)
# 2. Добавить порт в SELinux
sudo semanage port -a -t ssh_port_t -p tcp 5022
# 3. Перезапустить sshd
```

**Изменение каталога данных MySQL/MariaDB:**

```bash
# Для каталога /srv/mysql
sudo semanage fcontext -a -t mysqld_db_t "/srv/mysql(/.*)?"
sudo restorecon -Rv /srv/mysql # → Relabeled /srv/mysql ...
```

### 10. SELinux и контейнеры (Docker/Podman)

```bash
# Монтирование тома с автоматической сменой контекста
# z — приватный контекст (shared)
# Z — общий контекст (private/exclusive)
docker run -v /host/path:/container/path:z my_image # → ...
```

## Дополнительная информация

### История

- Разработано NSA (Агентство национальной безопасности США)
- Публичный релиз — 2000 год
- В составе ядра 2.6 (2003) через фреймворк LSM

### MCS (Multi-Category Security) — изоляция контейнеров

**MCS** — расширение SELinux для изоляции процессов и контейнеров на одном хосте с более тонкой сегментацией, чем стандартный Type Enforcement.

**Принцип работы:**

- Каждый процесс и объект получает набор категорий, определяющих доступ к «группам» данных
- MCS проверяет совместимость категорий при доступе к файлам, сокетам и другим ресурсам
- Даже если политики TE позволяют доступ, несовпадение категорий приведёт к отказу

**Формат метки MCS:**

```
system_u:system_r:container_t:s0:c123,c456
```

- `c123,c456` — MCS-категории, назначаемые контейнеру при старте
- Два контейнера с разными категориями не могут взаимодействовать, даже при одинаковом типе `container_t`

**Флаги монтирования томов:**

| Флаг | Описание | Применение |
| :--- | :--- | :--- |
| `:z` | Общая метка SELinux | Несколько контейнеров имеют доступ к одному volume |
| `:Z` | Приватная метка SELinux | Только один контейнер имеет доступ к volume |

**Отличие MCS от MLS:**

| Характеристика | MLS | MCS |
| :--- | :--- | :--- |
| **Структура** | Иерархическая (уровни) | Неиерархическая (категории) |
| **Пример** | «совершенно секретно» > «секретно» | «проект А», «проект Б» (равноправны) |
| **Комбинирование** | Доступ к нижним уровням | Любая комбинация категорий |
| **Основное применение** | Военные, госсектор | Изоляция контейнеров, мультитенант |

Подробнее: [Podman и SELinux](../../../Podman/podman_volumes_and_storage.md#изоляция-контейнеров-через-selinux-и-mcs).

### Чтение меток MLS/MCS

Для удобного чтения меток (например, `SystemLow` вместо `s0`):

```bash
# Установка
sudo dnf install mcstrans  # RHEL/AlmaLinux/Rocky Linux
sudo apt install mcstrans   # Debian/Ubuntu

# Запуск
sudo systemctl start mcstransd
```
