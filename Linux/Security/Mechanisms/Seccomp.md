# Seccomp (Secure Computing Mode)

## Определения

**Seccomp (Secure Computing Mode)** — это механизм безопасности в ядре Linux, который работает как "фильтр" системных вызовов (syscalls), доступных процессу. Его основная задача — ограничить поверхность атаки на ядро, запрещая процессу выполнять любые системные вызовы, кроме строго определённого набора. Это один из ключевых инструментов для изоляции приложений, особенно в контейнерах.

## Основные концепции

### Режимы работы

1. **`strict`**: Очень строгий режим, который разрешает процессу использовать только 4 системных вызова: `read()`, `write()`, `_exit()` и `sigreturn()`. Любая другая попытка системного вызова немедленно завершает процесс с сигналом `SIGKILL`. Этот режим обеспечивает максимальную безопасность, но подходит лишь для очень простых и предсказуемых программ.
2. **`filter` (seccomp-bpf)**: Гибкий режим, который позволяет определять произвольные правила фильтрации с помощью BPF (Berkeley Packet Filter). Администратор может создать "белый" или "черный" список системных вызовов, разрешая или запрещая их для процесса. Именно этот режим используется в Docker и Kubernetes для применения профилей безопасности.

### Seccomp и контейнеризация

Seccomp, наряду с **Namespaces** и **Capabilities**, является одним из фундаментальных строительных блоков, обеспечивающих изоляцию контейнеров в Linux. В то время как Namespaces изолируют ресурсы (файловую систему, сеть), а Capabilities ограничивают привилегии `root`, Seccomp ограничивает само взаимодействие процесса с ядром системы, что значительно снижает риски в случае компрометации приложения внутри контейнера.

## Практические сценарии

### 1. Проверка режима Seccomp у процесса

Информацию о режиме seccomp для конкретного процесса можно найти в файле `/proc/<PID>/status`.

```bash
# Проверить статус seccomp для текущей оболочки (PID = $$)
grep Seccomp /proc/$$/status
```

Возможные значения:

* `Seccomp: 0` — seccomp для этого процесса отключен.
* `Seccomp: 1` — процесс работает в режиме `strict`.
* `Seccomp: 2` — процесс работает с фильтром `seccomp-bpf`.

### 2. Применение в Docker

Docker по умолчанию использует seccomp-профиль, который блокирует около 44 из 300+ системных вызовов, считающихся опасными или редко используемыми в контейнерах.

* **Запуск с пользовательским профилем:**

    ```bash
    # custom_profile.json должен содержать правила seccomp в формате JSON
    docker run --security-opt seccomp=/path/to/custom_profile.json alpine
    ```

* **Полное отключение Seccomp (не рекомендуется):**

    ```bash
    docker run --rm -it --security-opt seccomp=unconfined alpine /bin/sh
    ```

### 3. Применение в Kubernetes

В Kubernetes профиль seccomp настраивается в контексте безопасности Пода или контейнера (`securityContext`).

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: seccomp-demo
spec:
  securityContext:
    seccompProfile:
      # Использует профиль по умолчанию, предоставляемый средой выполнения контейнеров (Docker, containerd)
      type: RuntimeDefault 
  containers:
  - name: test-container
    image: alpine
    command: ["sleep", "3600"]
    # Можно переопределить профиль на уровне контейнера
    securityContext:
      seccompProfile:
        # Отключает seccomp для этого конкретного контейнера
        type: Unconfined 
```

Доступные типы `seccompProfile`:

* `RuntimeDefault`: Профиль по умолчанию, предоставляемый средой выполнения.
* `Unconfined`: Seccomp не применяется.
* `Localhost`: Используется кастомный профиль, который должен находиться на узле в директории `<kubelet-root-dir>/seccomp/`.
