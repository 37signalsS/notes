# Seccomp (Secure Computing Mode)


**Seccomp** — это механизм безопасности в ядре Linux, который работает как "фильтр" системных вызовов (syscalls), доступных процессу. Его основная задача — ограничить поверхность атаки на ядро, запрещая процессу выполнять любые системные вызовы, кроме строго определённого набора. Это эффективный способ изоляции приложений, особенно в контейнерах.

Seccomp работает в двух режимах:

1.  **`strict`**: Очень строгий режим, который разрешает процессу использовать только 4 системных вызова: `read()`, `write()`, `_exit()` и `sigreturn()`. Любая другая попытка системного вызова завершает процесс с сигналом `SIGKILL`.
2.  **`filter` (seccomp-bpf)**: Гибкий режим, который позволяет определять произвольные правила фильтрации с помощью BPF (Berkeley Packet Filter). Этот режим используется в Docker и Kubernetes для применения профилей безопасности, которые разрешают только необходимые для работы контейнера системные вызовы.

### Практическое применение

#### Проверка режима Seccomp у процесса

Информацию о режиме seccomp для конкретного процесса можно найти в файле `/proc/<PID>/status`:

```bash
# Проверить статус seccomp для текущей оболочки
cat /proc/$$/status | grep Seccomp
```
-   `Seccomp: 0` — seccomp отключен.
-   `Seccomp: 1` — режим `strict`.
-   `Seccomp: 2` — режим `filter`.

#### Применение в Docker

Docker по умолчанию использует seccomp-профиль, который блокирует около 44 из 300+ системных вызовов, считающихся опасными или редко используемыми.

Можно запустить контейнер с кастомным профилем безопасности:

```bash
# Запуск контейнера с пользовательским JSON-файлом профиля seccomp
docker run --security-opt seccomp=/path/to/custom_profile.json alpine
```

Или полностью отключить seccomp (не рекомендуется):

```bash
docker run --security-opt seccomp=unconfined ...
```

Seccomp, наряду с Namespaces и Capabilities, является одним из фундаментальных строительных блоков, обеспечивающих изоляцию контейнеров в Linux.
