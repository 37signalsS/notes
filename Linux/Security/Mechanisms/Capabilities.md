## Определения

**Linux Capabilities** — это механизм ядра Linux, который разделяет всемогущество `root` (суперпользователя) на отдельные, гранулярные привилегии. Традиционная модель прав в Unix делит все процессы на две категории: непривилегированные и полностью привилегированные (`root`, UID 0). Такой подход "всё или ничего" небезопасен.

Capabilities позволяют процессу иметь только тот набор "способностей", который ему действительно необходим для работы. Например, веб-серверу для работы на порту 80 нужна только привилегия `CAP_NET_BIND_SERVICE`, а не полный доступ к системе.

## Основные понятия

Механизм Linux Capabilities повышает безопасность, гарантируя, что даже в случае компрометации процесса с ограниченным набором привилегий злоумышленник не получит полные права `root`. Это реализует **принцип наименьших привилегий**, фундаментальный для защищенных систем.

Ядро отслеживает пять наборов capabilities для каждого процесса:

* **`CapPrm` (Permitted):** Разрешенный набор, "супермножество" всех доступных capabilities.
* **`CapEff` (Effective):** Эффективный набор, используемый ядром для проверки привилегированных операций.
* **`CapInh` (Inheritable):** Наследуемый набор, передаваемый дочерним процессам при `execve`.
* **`CapBnd` (Bounding):** Ограничивающий набор, определяющий максимальный набор capabilities, которые процесс может получить.
* **`CapAmb` (Ambient):** Окружающий набор, сохраняющий привилегии для дочерних процессов.

## Практические сценарии

**1. Просмотр Capabilities:**

* **Для файла (с помощью `getcap`):** Проверяет capabilities, назначенные исполняемому файлу.

    ```bash
    getcap /bin/ping
    ```

    *(В некоторых системах путь может быть `/usr/bin/ping`)*
* **Для запущенного процесса:** Информация о capabilities процесса находится в `/proc/<PID>/status`.

    ```bash
    # Проверить capabilities текущей оболочки
    cat /proc/$$/status | grep Cap
    ```

    Вывод покажет пять наборов в виде битовых масок.

**2. Назначение и удаление Capabilities:**
Для управления file capabilities используется утилита `setcap`. Синтаксис: `setcap <capability_sets> <файл>`.

* **Примеры:**

    ```bash
    # Дать бинарному файлу право работать с сырыми сокетами (для ping)
    # '=' - точное присваивание, 'ep' - наборы Effective и Permitted
    sudo setcap cap_net_raw=ep /bin/ping

    # Дать бинарному файлу право слушать порты ниже 1024
    # '+' - добавление к существующим
    sudo setcap cap_net_bind_service=+ep /path/to/binary

    # Удалить все capabilities с файла
    sudo setcap -r /path/to/binary
    ```

* **Синтаксис операторов:** `+` (добавить), `-` (удалить), `=` (установить точно).
* **Синтаксис наборов:** `e` (Effective), `p` (Permitted), `i` (Inheritable).

## Дополнительная информация

* **Capabilities в контейнерах:** Являются фундаментальной технологией для безопасности контейнеров. Системы контейнеризации (Docker, Kubernetes) позволяют гранулярно управлять набором capabilities, доступных контейнеру, по умолчанию отключая большинство из них.
* **Современный `ping`:** В некоторых дистрибутивах `ping` может использовать непривилегированные ICMP-сокеты (ICMP Echo Sockets) вместо file capabilities (`cap_net_raw`), что делает его еще более безопасным.
