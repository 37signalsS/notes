# Linux Capabilities

## Определения

**Linux Capabilities** — это механизм ядра Linux, который разделяет всемогущество `root` (суперпользователя) на отдельные, гранулярные привилегии. Традиционная модель прав в Unix делит все процессы на две категории: непривилегированные и полностью привилегированные (`root`, UID 0). Такой подход "всё или ничего" небезопасен.

Capabilities позволяют процессу иметь только тот набор "способностей", который ему действительно необходим для работы. Например, веб-серверу для работы на порту 80 нужна только привилегия `CAP_NET_BIND_SERVICE`, а не полный доступ к системе.

## Основные концепции

### Преимущества
*   **Повышение безопасности:** Если процесс с ограниченным набором capabilities будет скомпрометирован, злоумышленник не получит полные права `root`.
*   **Принцип наименьших привилегий:** Процессы работают с минимально необходимым набором прав, что является фундаментальным принципом построения защищенных систем.

### Наборы Capabilities
Для каждого процесса ядро отслеживает пять наборов capabilities, которые определяют его привилегии:

*   **`CapPrm` (Permitted):** Разрешенный набор. Это "супермножество" всех capabilities, которыми процесс может обладать. Он может передавать их в наследуемый набор или использовать как эффективные, но не может получить capabilities, которых нет в этом наборе.
*   **`CapEff` (Effective):** Эффективный набор. Это набор capabilities, который ядро фактически проверяет при выполнении привилегированной операции.
*   **`CapInh` (Inheritable):** Наследуемый набор. Capabilities из этого набора могут быть унаследованы дочерними процессами при выполнении `execve`.
*   **`CapBnd` (Bounding):** Ограничивающий набор. Определяет максимальный набор capabilities, которые процесс может когда-либо получить. Если capability отсутствует в Bounding set, процесс не сможет добавить ее ни в Permitted, ни в Inheritable наборы.
*   **`CapAmb` (Ambient):** Окружающий набор. Позволяет некоторым образом сохранить привилегии для дочерних процессов, даже если они не были явно запущены с наследованием capabilities.

## Практические сценарии

### Просмотр Capabilities

*   **Для файла (с помощью `getcap`):**
    Проверяет capabilities, назначенные исполняемому файлу.
    ```bash
    getcap /bin/ping
    ```
    *В некоторых системах путь может быть `/usr/bin/ping`.*

*   **Для запущенного процесса:**
    Информацию о capabilities, которыми обладает процесс, можно найти в файле `/proc/<PID>/status`.
    ```bash
    # Проверить capabilities текущей оболочки
    cat /proc/$$/status | grep Cap
    ```
    Вывод покажет все пять наборов в виде битовых масок.

### Назначение и удаление Capabilities

Для управления capabilities, связанными с файлами, используется утилита `setcap`.

*   `setcap <capability_sets> <файл>`

**Примеры:**

```bash
# Дать бинарному файлу право работать с сырыми сокетами (нужно для ping)
# '=' означает точное присваивание, 'ep' — наборы Effective и Permitted
sudo setcap cap_net_raw=ep /bin/ping

# Дать бинарному файлу право слушать порты ниже 1024
# '+' означает добавление к существующим
sudo setcap cap_net_bind_service=+ep /path/to/binary

# Удалить все capabilities с файла
sudo setcap -r /path/to/binary
```
*   **Синтаксис операторов:** `+` (добавить), `-` (удалить), `=` (установить точно).
*   **Синтаксис наборов:** `e` (Effective), `p` (Permitted), `i` (Inheritable).

## Дополнительная информация

*   **Capabilities в контейнерах:** Технология capabilities является фундаментальной для безопасности контейнеров. Docker, Kubernetes и другие системы контейнеризации позволяют гранулярно управлять набором capabilities, доступных контейнеру, по умолчанию отключая большинство из них.
*   **Современный `ping`:** В некоторых современных дистрибутивах Linux `ping` может больше не использовать file capabilities (`cap_net_raw`). Вместо этого он использует непривилегированные ICMP-сокеты (ICMP Echo Sockets), что делает его еще более безопасным, так как ему вообще не требуются повышенные привилегии.
