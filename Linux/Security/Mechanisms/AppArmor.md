# AppArmor (Application Armor)

## Определения

**AppArmor** — это модуль безопасности ядра Linux, реализующий систему принудительного контроля доступа (Mandatory Access Control, MAC). В отличие от стандартной дискреционной модели прав (`DAC`), основанной на пользователях и группах, AppArmor накладывает ограничения на сами программы, независимо от того, кто их запускает.

*   **Профиль (Profile):** Набор правил, определяющий, к каким системным ресурсам (файлам, сетевым портам, capabilities) может получить доступ конкретное приложение. Профили хранятся в виде текстовых файлов в `/etc/apparmor.d/`.
*   **Режим принуждения (Enforce mode):** AppArmor активно применяет правила профиля и **блокирует** любые действия, нарушающие их. Нарушения записываются в системный журнал.
*   **Режим жалобы (Complain mode):** AppArmor **не блокирует** действия, нарушающие правила, но **регистрирует** их в журнале. Этот режим идеален для разработки и отладки новых профилей.

## Основные понятия

### Принцип работы
AppArmor использует фреймворк **Linux Security Modules (LSM)** для перехвата системных вызовов, которые делает приложение. Каждый вызов проверяется на соответствие правилам, загруженным для этого приложения. Если профиль для программы не загружен, AppArmor не применяет к ней никаких ограничений.

Ключевая особенность AppArmor — привязка правил к **путям исполняемых файлов**. Например, профиль для `/usr/sbin/nginx` будет применяться только к бинарному файлу, расположенному именно по этому пути.

### Структура профиля
Профили AppArmor — это текстовые файлы с простым синтаксисом.

*   **Путь к исполняемому файлу и флаги:**
    ```
    /usr/bin/ping flags=(complain) {
      ... правила ...
    }
    ```
*   **Правила доступа к файлам:**
    ```
    # Разрешить чтение
    /etc/hosts r,
    # Разрешить запись в лог
    /var/log/ping.log w,
    ```
    - `r` — чтение (read)
    - `w` — запись (write)
    - `x` — выполнение (execute)
    - `m` — отображение в память (memory map)
    - `l` — создание ссылки (link)
    - `k` — блокировка файла (lock)

*   **Capabilities:** Прямое предоставление приложению привилегий ядра.
    ```
    capability net_raw,
    ```

*   **Абстракции (`#include`):** Для упрощения профилей используются `#include` директивы, которые вставляют готовые наборы правил для общих задач (например, доступ к базовым библиотекам или сетевым службам).
    ```
    #include <abstractions/base>
    #include <abstractions/nameservice>
    ```

### AppArmor vs. SELinux
AppArmor и SELinux — две основные реализации MAC в Linux.
*   **AppArmor:** Основан на **путях**. Считается более простым в освоении и управлении. Используется по умолчанию в Debian, Ubuntu, openSUSE.
*   **SELinux:** Основан на **метках (labels)**, которые присваиваются каждому объекту системы (файлам, процессам). Предлагает более гранулярный, но и более сложный контроль. Используется по умолчанию в RHEL, Fedora, CentOS.

## Практические сценарии

### 1. Установка и проверка статуса
В большинстве Debian-based систем AppArmor предустановлен. Пакет `apparmor-utils` содержит полезные утилиты командной строки.
```bash
# Установка (если не установлен)
sudo apt update
sudo apt install apparmor apparmor-utils

# Проверка статуса
sudo aa-status
```
Команда `aa-status` выведет список всех загруженных профилей и их текущий режим (`enforce` или `complain`).

### 2. Управление профилями
*   **Перевод профиля в режим принуждения:**
    ```bash
    sudo aa-enforce /etc/apparmor.d/usr.bin.firefox
    ```
*   **Перевод профиля в режим жалоб:**
    ```bash
    sudo aa-complain /etc/apparmor.d/usr.bin.firefox
    ```
*   **Отключение профиля:**
    Профиль можно отключить, создав символическую ссылку на него в директории `/etc/apparmor.d/disabled/`.
    ```bash
    sudo ln -s /etc/apparmor.d/profile.name /etc/apparmor.d/disabled/
    sudo systemctl reload apparmor.service
    ```

### 3. Создание нового профиля
Для генерации профиля для нового приложения используется утилита `aa-genprof`.

1.  Запустите сканирование для вашего приложения:
    ```bash
    sudo aa-genprof /path/to/your/application
    ```
2.  В другом терминале запустите само приложение и используйте его функционал, чтобы AppArmor мог отследить его поведение.
3.  Вернитесь в первый терминал и нажмите `S` (Scan) для сканирования логов на предмет событий.
4.  `aa-genprof` будет поочередно показывать каждое зафиксированное действие и предлагать варианты правил (`Allow`, `Deny`, `Glob` и т.д.).
5.  После добавления всех правил нажмите `F` (Finish), чтобы сохранить профиль.

### 4. Обновление существующего профиля
Если приложение было обновлено или его поведение изменилось, можно обновить профиль с помощью `aa-logprof`. Эта утилита анализирует системный журнал на наличие записей о нарушениях правил AppArmor и в интерактивном режиме предлагает добавить новые правила в существующие профили.
```bash
sudo aa-logprof
```

## Дополнительная информация
*   **Расположение профилей:** `/etc/apparmor.d/`. Имя файла профиля соответствует полному пути к исполняемому файлу, где `/` заменяется на `.`. (например, `/bin/ping` -> `bin.ping`).
*   **Логирование:** События AppArmor (как блокировки, так и жалобы) записываются в системные журналы. Их можно посмотреть с помощью `journalctl -f` или в файлах `/var/log/syslog` или `/var/log/audit/audit.log`.
*   **Контекст:** AppArmor является одной из систем принудительного контроля доступа (MAC), описанных в общем обзоре [механизмов безопасности Linux](../Linux_Security_Mechanisms_Overview.md).
