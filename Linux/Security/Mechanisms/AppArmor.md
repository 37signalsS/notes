# AppArmor

## Definitions

**AppArmor (Application Armor)** — модуль безопасности ядра Linux, реализующий систему принудительного контроля доступа (Mandatory Access Control, MAC). В отличие от дискреционной модели прав (`DAC`), основанной на пользователях и группах, AppArmor накладывает ограничения на программы независимо от пользователя, запускающего их.

* **Профиль (Profile):** Набор правил, определяющий доступ приложения к системным ресурсам (файлам, сетевым портам, capabilities). Профили хранятся в `/etc/apparmor.d/`.
* **Режим принуждения (Enforce mode):** AppArmor применяет правила профиля и **блокирует** нарушения с записью в системный журнал.
* **Режим жалобы (Complain mode):** AppArmor **не блокирует** действия, но **регистрирует** нарушения в журнале. Используется для разработки и отладки профилей.

## Basic Concepts

Принцип работы AppArmor основан на использовании фреймворка **Linux Security Modules (LSM)** для перехвата системных вызовов. Каждый вызов проверяется на соответствие правилам из профиля, загруженного для приложения. Ключевая особенность — привязка правил к **путям исполняемых файлов**. Например, профиль для `/usr/sbin/nginx` будет применяться только к бинарному файлу, расположенному именно по этому пути. Если профиль для программы не загружен, AppArmor не применяет к ней никаких ограничений.

Профили AppArmor — это текстовые файлы с простым синтаксисом, включающим:

* **Путь к исполняемому файлу и флаги:** `/usr/bin/ping flags=(complain) { ... }`
* **Правила доступа к файлам:** `r` (чтение), `w` (запись), `x` (выполнение), `m` (отображение в память), `l` (создание ссылки), `k` (блокировка).

    ```
    /etc/hosts r,
    /var/log/ping.log w,
    ```

* **Capabilities:** Прямое предоставление привилегий ядра, например, `capability net_raw,`.
* **Абстракции (`#include`):** Вставка готовых наборов правил для общих задач (`#include <abstractions/base>`).

В отличие от **SELinux**, который основан на **метках (labels)**, присваиваемых каждому объекту системы, **AppArmor** основан на **путях**. Это делает его более простым в освоении и управлении. AppArmor используется по умолчанию в Debian, Ubuntu и openSUSE, тогда как SELinux — в RHEL, Fedora и CentOS.

## Practical Scenarios

### 1. Установка и проверка статуса

В Debian-based системах AppArmor обычно предустановлен. Пакет `apparmor-utils` содержит утилиты управления.

```bash
# Установка (если не установлен)
sudo apt update
sudo apt install apparmor apparmor-utils

# Проверка статуса (список профилей и их режимы)
sudo aa-status
```

### 2. Управление профилями

* **Перевод в режим принуждения:** `sudo aa-enforce /etc/apparmor.d/usr.bin.firefox`
* **Перевод в режим жалоб:** `sudo aa-complain /etc/apparmor.d/usr.bin.firefox`
* **Отключение профиля:**

    ```bash
    sudo ln -s /etc/apparmor.d/profile.name /etc/apparmor.d/disabled/
    sudo systemctl reload apparmor.service
    ```

### 3. Создание нового профиля

Утилита `aa-genprof` генерирует профиль в интерактивном режиме:

1. Запуск сканирования: `sudo aa-genprof /path/to/application`
2. В другом терминале — использование приложения для фиксации активности
3. В первом терминале — нажатие `S` для сканирования логов, пошаговое разрешение/запрет действий
4. Нажатие `F` для сохранения профиля

### 4. Обновление существующего профиля

Утилита `aa-logprof` анализирует журнал на наличие нарушений и предлагает обновить правила:

```bash
sudo aa-logprof
```

## Additional Information

* **Расположение профилей:** `/etc/apparmor.d/`. Имя файла соответствует пути к исполняемому файлу, где `/` заменяется на `.` (например, `/bin/ping` → `bin.ping`).
* **Логирование:** События AppArmor записываются в системные журналы и доступны через `journalctl -f` или в файлах `/var/log/syslog`, `/var/log/audit/audit.log`.
* **Контекст:** AppArmor — одна из систем принудительного контроля доступа (MAC), описанных в [обзоре механизмов безопасности Linux](../Linux_Security_Mechanisms_Overview.md).
* **Сравнение с SELinux:** [SELinux](./SELinux.md) основан на метках (labels), AppArmor — на путях файлов.
