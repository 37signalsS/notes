# AppArmor

## Определения

**AppArmor (Application Armor)** — модуль безопасности ядра Linux, реализующий систему принудительного контроля доступа (Mandatory Access Control, MAC). В отличие от дискреционной модели прав (`DAC`), основанной на пользователях и группах, AppArmor накладывает ограничения на программы независимо от пользователя, запускающего их.

Основная задача — ограничение возможностей приложения на уровне ядра: доступ к файлам, сетевые операции, capabilities. Даже если приложение скомпрометировано, оно не сможет выйти за пределы разрешений своего профиля.

* **Профиль (Profile):** Набор правил, определяющий доступ приложения к системным ресурсам. Профили хранятся в `/etc/apparmor.d/`.
* **Режим принуждения (Enforce mode):** AppArmor активно применяет правила и **блокирует** нарушения с записью в системный журнал.
* **Режим жалобы (Complain mode):** AppArmor **не блокирует** действия, но **регистрирует** (логирует) нарушения. Используется для отладки и разработки профилей.

## Основные концепции

Принцип работы AppArmor основан на использовании фреймворка **Linux Security Modules (LSM)** для перехвата системных вызовов. Ключевая особенность — привязка правил к **путям исполняемых файлов** (Path-based).

### Синтаксис профиля

Типичный профиль выглядит следующим образом:

```
/usr/bin/myapp {
  # Файлы, которые приложение читает
  /etc/myapp/config.yaml r,
  
  # Доступ к директории и её содержимому
  /var/log/myapp/ rw,
  /var/log/myapp/** rw,  # Рекурсивно покрывает все поддиректории

  # Сетевые операции
  network inet tcp,

  # Библиотеки и отображение в память
  /usr/lib/** rm,
  /lib/x86_64-linux-gnu/** rm,
}
```

**Флаги доступа:**

* `r`: чтение (read)
* `w`: запись (write)
* `x`: выполнение (execute)
* `m`: отображение в память (mmap)
* `k`: блокировка файлов (lock)
* `**`: рекурсивный поиск в поддиректориях

В отличие от **SELinux**, который использует метки объектов, AppArmor проще в освоении за счет использования привычных путей файловой системы.

## Практические сценарии

### 1. Установка и проверка статуса

```bash
# Установка утилит управления
sudo apt update && sudo apt install apparmor-utils

# Просмотр текущего статуса и загруженных профилей
sudo aa-status
```

### 2. Создание профиля с нуля

Для создания профиля не обязательно писать его вручную. Используется утилита `aa-genprof`, которая записывает активность приложения.

1. **Запуск генерации:**

   ```bash
   sudo aa-genprof /usr/bin/myapp
   ```

2. **Обучение:** В другом терминале запустите приложение и выполните все типичные сценарии работы (чтение конфигов, работа с сетью, запись логов).
3. **Сканирование:** Вернитесь в терминал с `aa-genprof`, нажмите `S` (scan) для анализа логов и `F` (finish) для завершения. Профиль сохранится в `/etc/apparmor.d/usr.bin.myapp`.

### 3. Отладка и уточнение профиля

Если приложение работает некорректно под AppArmor, используйте режим жалоб:

1. **Перевод в complain-режим:**

   ```bash
   sudo aa-complain /usr/bin/myapp
   ```

2. **Анализ логов:** Посмотрите нарушения, которые были бы заблокированы:

   ```bash
   journalctl | grep apparmor
   # Или интерактивно через aa-logprof
   sudo aa-logprof
   ```

   `aa-logprof` прочитает лог и предложит добавить новые правила в профиль.
3. **Возврат в enforce-режим:** Когда профиль готов, заблокируйте несанкционированную активность:

   ```bash
   sudo aa-enforce /usr/bin/myapp
   ```

### 4. Управление существующими профилями

* **Отключение профиля:**

  ```bash
  sudo ln -s /etc/apparmor.d/profile.name /etc/apparmor.d/disabled/
  sudo systemctl reload apparmor.service
  ```

## Дополнительная информация

* **Расположение профилей:** `/etc/apparmor.d/`. Имена файлов соответствуют путям к бинарникам (например, `/bin/ping` → `bin.ping`).
* **Логирование:** События фиксируются в `/var/log/syslog` или `/var/log/audit/audit.log` (если установлен auditd).
* **Сравнение с SELinux:** [SELinux](./SELinux.md) основан на метках (labels), AppArmor — на путях.
* **Контекст:** Описано в [обзоре механизмов безопасности Linux](../Linux_Security_Mechanisms_Overview.md).
