## Определения

**AppArmor (Application Armor)** — это модуль безопасности ядра Linux, реализующий систему принудительного контроля доступа (Mandatory Access Control, MAC). В отличие от стандартной дискреционной модели прав (`DAC`), основанной на пользователях и группах, AppArmor накладывает ограничения на сами программы, независимо от того, кто их запускает.

*   **Профиль (Profile):** Набор правил, определяющий, к каким системным ресурсам (файлам, сетевым портам, capabilities) может получить доступ конкретное приложение. Профили хранятся в виде текстовых файлов в `/etc/apparmor.d/`.
*   **Режим принуждения (Enforce mode):** AppArmor активно применяет правила профиля и **блокирует** любые действия, нарушающие их. Нарушения записываются в системный журнал.
*   **Режим жалобы (Complain mode):** AppArmor **не блокирует** действия, нарушающие правила, но **регистрирует** их в журнале. Этот режим идеален для разработки и отладки новых профилей.

## Основные понятия

Принцип работы AppArmor основан на использовании фреймворка **Linux Security Modules (LSM)** для перехвата системных вызовов. Каждый вызов проверяется на соответствие правилам из профиля, загруженного для приложения. Ключевая особенность — привязка правил к **путям исполняемых файлов**. Например, профиль для `/usr/sbin/nginx` будет применяться только к бинарному файлу, расположенному именно по этому пути. Если профиль для программы не загружен, AppArmor не применяет к ней никаких ограничений.

Профили AppArmor — это текстовые файлы с простым синтаксисом, включающим:
*   **Путь к исполняемому файлу и флаги:** ` /usr/bin/ping flags=(complain) { ... }`
*   **Правила доступа к файлам:** `r` (чтение), `w` (запись), `x` (выполнение), `m` (отображение в память), `l` (создание ссылки), `k` (блокировка).
    ```
    /etc/hosts r,
    /var/log/ping.log w,
    ```
*   **Capabilities:** Прямое предоставление привилегий ядра, например, `capability net_raw,`.
*   **Абстракции (`#include`):** Вставка готовых наборов правил для общих задач (`#include <abstractions/base>`).

В отличие от **SELinux**, который основан на **метках (labels)**, присваиваемых каждому объекту системы, **AppArmor** основан на **путях**. Это делает его более простым в освоении и управлении. AppArmor используется по умолчанию в Debian, Ubuntu и openSUSE, тогда как SELinux — в RHEL, Fedora и CentOS.

## Практические сценарии

**1. Установка и проверка статуса:**
В большинстве Debian-based систем AppArmor предустановлен. Пакет `apparmor-utils` содержит полезные утилиты.
```bash
# Установка (если не установлен)
sudo apt update
sudo apt install apparmor apparmor-utils

# Проверка статуса (список профилей и их режимы)
sudo aa-status
```

**2. Управление профилями:**
*   **Перевод в режим принуждения:** `sudo aa-enforce /etc/apparmor.d/usr.bin.firefox`
*   **Перевод в режим жалоб:** `sudo aa-complain /etc/apparmor.d/usr.bin.firefox`
*   **Отключение профиля:**
    ```bash
    sudo ln -s /etc/apparmor.d/profile.name /etc/apparmor.d/disabled/
    sudo systemctl reload apparmor.service
    ```

**3. Создание нового профиля:**
Утилита `aa-genprof` используется для генерации профиля в интерактивном режиме.
1.  Запустите сканирование: `sudo aa-genprof /path/to/application`
2.  В другом терминале используйте приложение, чтобы AppArmor зафиксировал его активность.
3.  В первом терминале нажмите `S` для сканирования логов, а затем пошагово разрешайте или запрещайте обнаруженные действия.
4.  Нажмите `F` для сохранения профиля.

**4. Обновление существующего профиля:**
Утилита `aa-logprof` анализирует системный журнал на наличие нарушений и предлагает обновить правила для существующих профилей.
```bash
sudo aa-logprof
```

## Дополнительная информация

*   **Расположение профилей:** `/etc/apparmor.d/`. Имя файла обычно соответствует пути к исполняемому файлу, где `/` заменяется на `.` (например, `/bin/ping` -> `bin.ping`).
*   **Логирование:** События AppArmor записываются в системные журналы и доступны через `journalctl -f` или в файлах `/var/log/syslog`, `/var/log/audit/audit.log`.
*   **Контекст:** AppArmor является одной из систем принудительного контроля доступа (MAC), описанных в общем обзоре [механизмов безопасности Linux](../Linux_Security_Mechanisms_Overview.md).
