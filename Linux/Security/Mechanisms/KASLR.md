# KASLR (Kernel Address Space Layout Randomization)

## Определения и терминология

**KASLR (Kernel Address Space Layout Randomization)** — механизм безопасности ядра Linux, который при каждой загрузке системы случайным образом изменяет базовый адрес расположения кода ядра, его модулей и ключевых структур данных в виртуальной памяти.

**Цель:** защита от эксплуатации уязвимостей типа **ROP (Return-Oriented Programming)** и переполнения буфера в пространстве ядра. Путем рандомизации адресов KASLR лишает атакующего возможности заранее знать точное расположение функций (например, `commit_creds`), что делает написание надежного эксплойта значительно более сложной задачей.

## Основные концепции

### Связь с ASLR

KASLR является расширением механизма **ASLR (Address Space Layout Randomization)**, применяемого к пользовательским процессам:

| Характеристика | ASLR | KASLR |
| :--- | :--- | :--- |
| **Уровень** | Пространство пользователя (Userspace) | Пространство ядра (Kernelspace) |
| **Что рандомизирует** | Стек, куча, библиотеки (`libc`), код процесса | Код ядра, модули, таблицы страниц |
| **Время смены адресов** | При каждом запуске процесса | При каждой загрузке ОС |

Подробнее об ASLR: [Защита памяти ядра и процессов](../Fstec/kernel_runtime_protection.md).

### Принцип работы

1.  **Энтропия:** Ядро получает случайные данные от аппаратных генераторов (например, инструкция `RDRAND` на процессорах Intel/AMD) или других источников энтропии.
2.  **Смещение (Offset):** На основе этих данных вычисляется случайное смещение.
3.  **Загрузка:** Ядро загружается в память по адресу `физический_базовый_адрес + смещение`.
4.  **Фиксация:** После завершения процесса загрузки адреса остаются неизменными до следующей перезагрузки.

### FG-KASLR (Function Granular KASLR)

Традиционный KASLR перемещает всё ядро как единый блок. **FG-KASLR** — это более продвинутый уровень рандомизации (активно обсуждается в 2024–2025 гг.), который:
- Перемещает каждую функцию ядра отдельно.
- Делает неэффективным знание адреса одной функции для вычисления адресов других (традиционный KASLR может быть полностью скомпрометирован утечкой одного адреса).
- **Ограничения:** значительно увеличивает время линковки при сборке ядра и может снижать производительность из-за ухудшения локальности кэша.

### Ограничения и векторы атак

KASLR не является абсолютной защитой и имеет известные уязвимости:

- **Information Leak (Утечка информации):** если уязвимость позволяет атакующему прочитать значение указателя из памяти ядра, он может вычислить базовое смещение и "разгадать" KASLR.
- **Side-Channel (Атаки по побочным каналам):**
    - **EntryBleed:** использование инструкции `prefetch` для измерения времени доступа к кэшу и определения адресов обработчиков системных вызовов.
    - **Linear Mapping Attacks:** атаки на область прямого отображения физической памяти, которая в некоторых архитектурах (например, ARM64) рандомизируется слабее.
- **Локальные атаки:** Для локального атакующего KASLR считается "слабой" защитой из-за обилия способов косвенного определения адресов через системные интерфейсы (например, `/proc/kallsyms` при недостаточных правах).

## Практические сценарии

### 1. Проверка статуса KASLR

**Метод 1: Проверка параметров загрузки**

```bash
cat /proc/cmdline | grep -q "nokaslr" && echo "KASLR disabled" || echo "KASLR potentially enabled"
```

**Метод 2: Сравнение адресов символов (самый надежный)**

1. Выполните: `sudo grep " T _stext" /proc/kallsyms` `# → ffffffff91000000 T _stext`
2. Перезагрузите систему.
3. Выполните команду снова. Если адрес изменился — KASLR активен.
   *Примечание: адрес `ffffffff81000000` часто является стандартным базовым адресом без смещения.*

### 2. Управление KASLR через GRUB

Управление осуществляется через параметры командной строки ядра в конфигурации загрузчика.

**Отключение KASLR (например, для отладки или обеспечения работы гибернации):**

1. Отредактируйте файл `/etc/default/grub`.
2. Добавьте `nokaslr` в переменную `GRUB_CMDLINE_LINUX_DEFAULT`.
3. Обновите конфигурацию:
    ```bash
    # Debian / Ubuntu / Astra Linux
    sudo update-grub

    # RHEL / CentOS / Fedora / AlmaLinux
    sudo grub2-mkconfig -o /boot/grub2/grub.cfg
    ```
4. Перезагрузите систему.

## Дополнительная информация

### KASLR и гибернация (Suspend-to-Disk)

Существует фундаментальный конфликт между KASLR и механизмом гибернации:
- При гибернации состояние памяти сохраняется на диск.
- Для успешного восстановления ядро должно загрузиться по тем же виртуальным адресам, по которым оно работало до "засыпания".
- KASLR при каждой загрузке выбирает новый адрес.
- **Итог:** В большинстве дистрибутивов KASLR автоматически отключается, если система настроена на использование гибернации.

### Связанные механизмы безопасности

- **KPTI (Kernel Page Table Isolation):** изоляция таблиц страниц ядра от пространства пользователя (защита от Meltdown).
- **SMEP / SMAP:** аппаратные технологии, запрещающие ядру исполнять код из пользовательских страниц или обращаться к ним без явного разрешения.
- **ASLR:** [Механизм рандомизации для пользовательских приложений](../Fstec/kernel_runtime_protection.md).
