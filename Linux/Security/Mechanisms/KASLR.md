# KASLR (Kernel Address Space Layout Randomization)

## Определения

**KASLR (Kernel Address Space Layout Randomization)** — это механизм безопасности ядра Linux, который при каждой загрузке системы размещает код самого ядра, его модули и ключевые структуры данных по случайным адресам в виртуальной памяти.

## Основные понятия

### Цель и принцип работы

Основная цель KASLR — усложнить эксплуатацию уязвимостей ядра. Многие атаки, такие как **возвратно-ориентированное программирование (ROP)**, требуют от злоумышленника знания точных адресов функций или "гаджетов" в памяти ядра для построения цепочки эксплойта.

KASLR делает эти адреса непредсказуемыми. При каждой загрузке ядро выбирает случайное смещение и размещает свой код и данные по этому новому базовому адресу. В результате атака, успешная на одной машине, с высокой вероятностью провалится на другой или даже после простой перезагрузки той же самой машины.

### Связь с ASLR

KASLR является прямым аналогом механизма **ASLR (Address Space Layout Randomization)**, но перенесенным с уровня пользовательских приложений на уровень ядра операционной системы.

### Ограничения и обход

KASLR — это важный, но не абсолютный механизм защиты. Он значительно повышает сложность атаки, но не устраняет сами уязвимости. Злоумышленники могут попытаться обойти KASLR, используя другие уязвимости, которые приводят к утечке информации (information leak). Если атакующий сможет найти способ узнать хотя бы один адрес в памяти ядра, он сможет вычислить базовое смещение и, таким образом, дерандомизировать расположение всех остальных структур.

## Практические сценарии

### Проверка статуса KASLR

#### 1. Сравнение адресов после перезагрузки (надежный метод)

Самый надежный способ — убедиться, что адреса в ядре действительно меняются между загрузками.

1.  **Посмотрите адрес любого символа ядра:**
    ```bash
    # Можно использовать head или grep
    sudo cat /proc/kallsyms | grep 'T _stext'
    ```
    Вывод будет примерно таким: `ffffffffa9000000 T _stext`. Запомните или запишите этот адрес.

2.  **Перезагрузите систему.**

3.  **Выполните ту же команду снова:**
    ```bash
    sudo cat /proc/kallsyms | grep 'T _stext'
    ```
    Если адрес изменился (например, стал `ffffffffb2800000 T _stext`), значит KASLR работает. Если адрес остался прежним, KASLR отключен.

#### 2. Проверка параметров загрузки ядра

Можно проверить, не был ли KASLR принудительно отключен при загрузке.
```bash
cat /proc/cmdline
```
Если в строке параметров вы видите `nokaslr`, механизм отключен. Отсутствие этого параметра обычно означает, что используется настройка по умолчанию (включено).

### Управление KASLR (через параметры загрузки)

Управление KASLR осуществляется через параметры, передаваемые ядру при загрузке (например, в конфигурации GRUB).

*   **Чтобы отключить KASLR:**
    Добавьте параметр `nokaslr` к строке загрузки ядра. Это может быть полезно для отладки или в некоторых специфических сценариях виртуализации, где рандомизация может мешать.

*   **Чтобы принудительно включить KASLR:**
    Добавьте параметр `kaslr`. Это требуется редко, так как KASLR включен по умолчанию.

Для внесения изменений отредактируйте файл `/etc/default/grub`, добавив параметр в строку `GRUB_CMDLINE_LINUX_DEFAULT`, а затем обновите конфигурацию GRUB (`sudo update-grub` в Debian/Ubuntu или `sudo grub2-mkconfig -o ...` в RHEL/CentOS).

## Дополнительная информация

*   **Статус по умолчанию:** KASLR включен по умолчанию в большинстве современных дистрибутивов Linux (начиная примерно с ядра 3.14).
*   **Контекст:** KASLR является одним из ключевых механизмов защиты от эксплуатации уязвимостей, описанных в общем обзоре [механизмов безопасности Linux](../Linux_Security_Mechanisms_Overview.md).
