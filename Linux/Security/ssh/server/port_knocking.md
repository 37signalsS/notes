# Port Knocking — технология скрытия портов

## Определения

**Port Knocking** (портовый «стук») — метод сетевой защиты, основанный на предоставлении доступа к закрытому порту (например, SSH) только после получения сервером серии пакетов («стуков») на определённую последовательность заранее заданных портов. Это позволяет скрыть наличие сервиса от автоматизированных сканеров и ботов.

**Single Packet Authorization (SPA)** — усовершенствованная форма Port Knocking, использующая один криптографически подписанный и зашифрованный пакет для авторизации. Лишена уязвимостей классического PK (перехват «стука», медлительность). Основной инструмент — **fwknop**.

**knockd** — легковесный демон, который прослушивает сетевой интерфейс в режиме ожидания заданных последовательностей и выполняет команды (обычно модификацию правил файрвола) при совпадении.

## Основные концепции

### Принцип работы

1. **Default Deny**: Целевой порт (22, 2239 и т.д.) полностью закрыт правилом `REJECT` или `DROP`.
2. **Мониторинг**: Демон (`knockd` или `fwknopd`) анализирует входящий трафик на уровне L2/L3 (через `libpcap`). Важно: демон видит пакеты даже если они отбрасываются файрволом.
3. **Триггер**: Клиент отправляет последовательность пакетов (например, TCP SYN на порты 7000, 8000, 9000).
4. **Динамическое правило**: При совпадении последовательности демон добавляет временное разрешающее правило в файрвол для IP-адреса клиента.
5. **Таймаут**: Через заданное время правило автоматически удаляется, но установленная сессия (например, SSH-туннель) сохраняется.

### Сравнение Port Knocking и SPA

| Характеристика | Port Knocking (knockd) | SPA (fwknop) |
| :--- | :--- | :--- |
| **Количество пакетов** | Несколько (обычно 3–5) | Один |
| **Безопасность** | Уязвим к Replay-атакам (перехвату «стука») | Защищен шифрованием и HMAC |
| **Скрытность** | «Стуки» видны в логах промежуточных систем | Пакет выглядит как случайный шум (UDP/ICMP) |
| **Сложность** | Очень прост в настройке | Требует генерации ключей и настройки клиента |
| **Работа за NAT** | Возможны проблемы при изменении портов/IP | Работает стабильно |

## Практические сценарии

### Вариант 1: Настройка knockd (iptables)

**Сценарий**: Динамическое открытие порта SSH (2239) на интерфейсе `enp3s0`.

#### 1. Установка компонентов

```bash
sudo apt update && sudo apt install knockd iptables-persistent -y
# → knockd is already the newest version...
# → iptables-persistent is already the newest version...
```

#### 2. Блокировка порта по умолчанию

```bash
sudo iptables -A INPUT -p tcp --dport 2239 -j REJECT --reject-with tcp-reset
sudo netfilter-persistent save
# → Running post-save-command... OK
```

#### 3. Конфигурация /etc/knockd.conf

```ini
[options]
    logfile = /var/log/knockd.log
    interface = enp3s0

[openSSH]
    sequence = 7000,8000,9000
    seq_timeout = 5
    command = /usr/sbin/iptables -I INPUT -s %IP% -p tcp --dport 2239 -j ACCEPT
    tcpflags = syn

[closeSSH]
    sequence = 9000,8000,7000
    seq_timeout = 5
    command = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --dport 2239 -j ACCEPT
    tcpflags = syn
```

#### 4. Активация и запуск

Отредактируйте `/etc/default/knockd`, установив `START_KNOCKD=1`.

```bash
sudo systemctl enable --now knockd
sudo systemctl status knockd
# → ● knockd.service - Port-Knocking daemon
# →    Active: active (running) since ...
```

### Вариант 2: Настройка knockd (nftables)

Для `nftables` рекомендуется использовать именованные наборы (sets) для управления списком разрешенных IP.

**Предварительная настройка nftables:**
```bash
nft add set inet filter knock_authorized { type ipv4_addr; flags timeout; }
nft add rule inet filter input ip saddr @knock_authorized tcp dport 2239 accept
```

**Конфигурация `/etc/knockd.conf`:**
```ini
[openSSH]
    sequence = 7001,8001,9001
    seq_timeout = 5
    command = /usr/sbin/nft add element inet filter knock_authorized { %IP% timeout 30s }
    tcpflags = syn
```

### Клиентская часть

Использование утилиты `knock`:

```bash
# Открытие (отправка последовательности)
knock <SERVER_IP> 7000 8000 9000
# → (пакеты отправлены)

# Подключение (в течение окна таймаута)
ssh user@<SERVER_IP> -p 2239

# Явное закрытие (если настроено в секции closeSSH)
knock <SERVER_IP> 9000 8000 7000
```

## Дополнительная информация

### Безопасность и ограничения

- **Replay Attacks**: Злоумышленник может перехватить последовательность «стуков» и повторить её для получения доступа. Port Knocking защищает от массового сканирования, но не от направленной атаки сниффером.
- **Ограничения NAT**: Если клиент находится за симметричным NAT, порты «стуков» могут быть переписаны маршрутизатором, что нарушит последовательность на стороне сервера.
- **IPv6**: Большинство версий `knockd` имеют ограниченную поддержку IPv6. Для сетей IPv6 рекомендуется использовать `fwknop` (SPA).
- **Автоматическое закрытие**: Рекомендуется использовать параметр `cmd_timeout` в `knockd.conf`, чтобы не полагаться на ручное закрытие порта.

### Альтернатива: Single Packet Authorization (SPA)

**SPA (fwknop)** решает проблемы Port Knocking:
1. **Зашифрованная нагрузка**: Пакет содержит зашифрованные AES или GnuPG данные (IP клиента, временная метка, случайная строка).
2. **Аутентификация**: Подпись HMAC гарантирует, что пакет отправлен доверенным клиентом.
3. **Невидимость**: SPA-пакет часто отправляется по UDP на порт, который выглядит закрытым, что делает его неотличимым от случайного шума.
