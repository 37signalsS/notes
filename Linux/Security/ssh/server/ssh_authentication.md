# Методы аутентификации SSH

## Определения

**Аутентификация по SSH-ключам** — это метод подтверждения личности пользователя с использованием пары криптографических ключей: приватного (секретного) и публичного (открытого). Приватный ключ хранится на клиенте и никогда не передаётся по сети. Публичный ключ размещается на сервере в файле `~/.ssh/authorized_keys`. При подключении сервер проверяет, соответствует ли приватный ключ публичному, используя криптографическую пару.

**Пара ключей (Key Pair)** — два взаимосвязанных криптографических ключа:
- **Приватный ключ (Private Key)** — секретный файл, хранящийся на клиенте. Должен быть защищён от утечки.
- **Публичный ключ (Public Key)** — открытый файл, который можно безопасно передавать и размещать на серверах. Не содержит секретной информации.

## Основные концепции

### Генерация пары ключей

Для генерации пары ключей используется утилита `ssh-keygen`. Ключи генерируются локально на клиенте.

**Базовая команда генерации:**
```bash
ssh-keygen -t <тип_ключа> -b <длина> -C "<комментарий>" -f <путь_к_файлу>
```

**Параметры:**
- `-t <тип>` — алгоритм ключа: `ed25519` (рекомендуется), `rsa`, `ecdsa`
- `-b <длина>` — длина ключа в битах (для RSA: минимум 2048, рекомендуется 4096)
- `-C "<комментарий>"` — комментарий (обычно email или описание ключа)
- `-f <путь>` — путь к файлу для сохранения (по умолчанию `~/.ssh/id_<тип>`)

**Примеры:**

```bash
# Генерация ключа ED25519 (рекомендуемый вариант, короткий и безопасный)
ssh-keygen -t ed25519 -C "user@example.com"

# Генерация ключа RSA с длиной 4096 бит
ssh-keygen -t rsa -b 4096 -C "user@example.com"

# Генерация ключа для конкретного проекта
ssh-keygen -t ed25519 -C "project-key" -f ~/.ssh/id_ed25519_project
```

После генерации будут созданы два файла:
- `~/.ssh/id_ed25519` — приватный ключ (защитите от утечки!)
- `~/.ssh/id_ed25519.pub` — публичный ключ (можно свободно передавать)

**Копирование публичного ключа на сервер:**
```bash
# Автоматическое копирование с установкой правильных прав
ssh-copy-id user@server

# Или вручную: скопировать содержимое ~/.ssh/id_*.pub и добавить в ~/.ssh/authorized_keys на сервере
```

### Типы SSH-ключей

| Тип ключа | Рекомендуемая длина | Преимущества | Недостатки |
| :--- | :--- | :--- | :--- |
| **ED25519** | Фиксированная (256 бит) | Короткие ключи, высокая производительность, современный алгоритм | Поддержка только в OpenSSH 6.5+ |
| **RSA** | 4096 бит (минимум 2048) | Широкая совместимость, проверенный алгоритм | Длинные ключи, медленнее ED25519 |
| **ECDSA** | 256-521 бит | Короткие ключи, высокая производительность | Сложнее в реализации, потенциальные уязвимости |

**Важно:** Безопасность ключа зависит не только от алгоритма, но и от длины. RSA 2048 бит считается минимально безопасным, RSA 4096 — с запасом на будущее. ED25519 имеет фиксированную длину и считается современным стандартом.

### Файл `~/.ssh/authorized_keys`

Файл на сервере содержит публичные ключи, которым разрешён доступ к учётной записи пользователя. Каждый ключ записывается в отдельной строке.

**Формат записи:**
```
<тип_ключа> <публичный_ключ> <комментарий>
```

**Пример:**
```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... user@example.com
```

### Файл конфигурации `/etc/ssh/sshd_config`

Это главный файл, определяющий поведение SSH-сервера. Ниже приведены ключевые директивы безопасности, касающиеся аутентификации.

- **Настройка методов аутентификации**
  - `PasswordAuthentication no`: Отключает аутентификацию по паролю.
  - **Запрет входа для `root`:**
    - `PermitRootLogin no`: Полностью запрещает прямой вход от имени `root`. Это заставляет злоумышленника сначала получить доступ к учетной записи обычного пользователя, а затем повышать привилегии.
    - `PermitRootLogin yes`: **(КРАЙНЕ НЕБЕЗОПАСНО!)** Разрешает прямой вход для `root` по паролю или ключу. **Настоятельно не рекомендуется для production-систем.** Использовать только в крайних случаях и только с аутентификацией по ключу, предварительно убедившись, что другой доступ к системе невозможен.
    - `prohibit-password`: Альтернативный вариант, который разрешает вход `root` только по SSH-ключу. Менее безопасен, чем `no`.
  - **Ограничение попыток входа:**
    - `MaxAuthTries 3`: Уменьшает количество попыток аутентификации, что замедляет атаки перебора (brute-force).
  - `PermitEmptyPasswords no`: Запрещает вход с пустыми паролями.
  - `PubkeyAuthentication yes`: Убеждается, что аутентификация по ключам включена.
  - `ChallengeResponseAuthentication no`: Отключает интерактивные методы аутентификации "вызов-ответ".
  - `GSSAPIAuthentication no`, `KerberosAuthentication no`: Отключает аутентификацию через Kerberos/GSSAPI, если она не используется, для уменьшения векторов атак.

### Контроль прав доступа

Для безопасной работы SSH требует строгих прав на файлы и каталоги. Неправильные разрешения могут привести к отказу в аутентификации по ключу.

- **Общее правило:** Конфиденциальные файлы (приватные ключи) должны быть доступны для чтения и записи только их владельцу (`600`), а содержащие их каталоги — только для просмотра и изменения владельцем (`700`).

| Путь                                  | Права | Владелец       | Описание                                                                                                                                                                                                           |
| ------------------------------------- | ----- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `~/.ssh` (на клиенте и сервере)       | `700` | Пользователь   | Каталог с конфигурацией и ключами.                                                                                                                                                                                 |
| `~/.ssh/authorized_keys` (на сервере) | `600` | Пользователь   | Файл с публичными ключами, которым разрешен доступ.                                                                                                                                                                |
| `~/.ssh/id_*` (на клиенте)            | `600` | Пользователь   | Приватные ключи пользователя. **Их утечка компрометирует доступ!**                                                                                                                                                   |
| `~/.ssh/id_*.pub` (на клиенте)        | `644` | Пользователь   | Публичные ключи, не содержат секретной информации.                                                                                                                                                                 |
| `~/.ssh/config` (на клиенте)          | `600` | Пользователь   | Файл конфигурации клиента SSH.                                                                                                                                                                                     |
| `/etc/ssh/ssh_host_*_key` (на сервере) | `600` | `root:root`    | Приватные ключи хоста.                                                                                                                                                                                             |
| `/etc/ssh/ssh_host_*_key.pub` (на сервере)|`644`| `root:root`    | Публичные ключи хоста.                                                                                                                                                                                             |

> **Важно:** Если права на `~/.ssh` или `~/.ssh/authorized_keys` слишком открыты (например, `775` или `664`), `sshd` отклонит аутентификацию по ключу, записав в лог ошибку, например: `Authentication refused: bad ownership or modes for directory /home/user/.ssh`.
