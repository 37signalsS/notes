# SSH (Secure Shell)

## Определения

**SSH (Secure Shell)** — сетевой протокол прикладного уровня для безопасного удалённого управления ОС и туннелирования TCP-соединений. Шифрует весь трафик (включая пароли) поверх TCP (порт 22 по умолчанию).

* **Как подключиться:** `ssh имя_пользователя@адрес_сервера` (например, `ssh admin@192.168.1.100`).

**Аутентификация хоста** — механизм проверки подлинности сервера через ключ хоста (host key) и файл `~/.ssh/known_hosts`. Защищает от атак «человек посередине» (MITM).

**SSH-сессия** — иерархия процессов: `sshd` (демон) → `sshd` (сессия пользователя) → PTS (псевдотерминал) → оболочка (bash/zsh) → команды. При разрыве соединения все процессы сессии завершаются.

### Сравнение с Telnet

| Характеристика | SSH (Secure Shell) | Telnet |
| :--- | :--- | :--- |
| **Безопасность** | **Высокая**. Трафик зашифрован. | **Низкая**. Данные (включая пароли) передаются открытым текстом. |
| **Аутентификация** | Проверка подлинности хоста и клиента. | Базовая (пароль), легко перехватить. |
| **Порт по умолчанию** | 22 | 23 |
| **Использование** | Стандарт для удаленного управления. | Устарел, используется только для диагностики портов. |

## Базовые концепции

### Этапы установления SSH-соединения

1. **TCP-handshake** — клиент подключается к серверу на порт 22 (или кастомный).
2. **Обмен версиями** — стороны выбирают общую версию протокола.
3. **Согласование алгоритмов** — шифрование (AES-256-GCM, ChaCha20), MAC (HMAC-SHA2), обмен ключами (Curve25519, ECDH), аутентификация хоста (RSA, ED25519).
4. **Key exchange** — генерация общего секрета (ключ сессии) через Diffie-Hellman/ECDH. Сервер передаёт host key, клиент проверяет по `~/.ssh/known_hosts`.
5. **Аутентификация пользователя** — пароль, публичный ключ, Kerberos и др.

### Аутентификация хоста и защита от MITM

При первом подключении клиент сохраняет отпечаток ключа сервера в `~/.ssh/known_hosts`. При повторном подключении происходит сверка. Изменение ключа вызывает блокировку с ошибкой `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`.

```bash
# Удалить запись об хосте (при переустановке ОС, замене сервера)
ssh-keygen -R <hostname_or_ip>
```

Первое подключение всегда должно выполняться вручную для проверки подлинности хоста перед использованием в автоматизации.

### Архитектура SSH-сессии

```
sshd (демон, порт 22)
  └── sshd: пользователь (сессия)
        └── pts/0 (псевдотерминал)
              └── bash (оболочка пользователя)
                    └── выполняемые команды
```

Для сохранения долгоживущих процессов при разрыве соединения используются терминальные мультиплексоры `screen` или `tmux` ([Управление сессиями](./ssh_session_management.md)).

## Дополнительная информация

### Стандарты и версии протокола

| Версия | Год | Статус | Примечание |
| :--- | :--- | :--- | :--- |
| SSH-1 | 1995 | Устарел | Уязвимости (CVE-2001-0144, MITM) |
| SSH-2 | 2006 | Актуален | RFC 4251–4256, разделён на транспортное, пользовательское и протоколы соединения |

### Рекомендуемые алгоритмы (2024+)

| Категория | Рекомендуемые | Не рекомендуются |
| :--- | :--- | :--- |
| **Шифрование** | `chacha20-poly1305@openssh.com`, `aes256-gcm@openssh.com` | `aes128-cbc`, `3des-cbc` |
| **KEX** | `curve25519-sha256`, `ecdh-sha2-nistp256` | `diffie-hellman-group1-sha1` |
| **Host Key** | `ssh-ed25519`, `ecdsa-sha2-nistp256` | `ssh-rsa` (SHA-1) |
| **MAC** | `hmac-sha2-256-etm@openssh.com` | `hmac-md5`, `hmac-sha1` |

### Порт по умолчанию и его изменение

Стандартный порт SSH — **22**. Изменение порта (директива `Port` в `sshd_config`) снижает шум от автоматических сканеров, но не является мерой безопасности. Для применения изменений требуется перезапуск `sshd`.
