# SSH (Secure Shell) — обзор

## Определения

**SSH (Secure Shell)** — защищенный сетевой протокол прикладного уровня, предназначенный для удаленного управления операционными системами, передачи файлов и туннелирования TCP-соединений. Шифрует весь трафик, включая учетные данные, обеспечивая конфиденциальность и целостность данных поверх небезопасных сетей.

*   **Порт по умолчанию:** 22/TCP.
*   **Основная реализация:** OpenSSH (OpenBSD Secure Shell).

**Аутентификация хоста** — процесс проверки подлинности удаленного сервера клиентом. Базируется на проверке публичного ключа сервера по локальной базе доверенных узлов (`~/.ssh/known_hosts`).

**Постквантовая криптография (PQC)** — современные алгоритмы шифрования и обмена ключами, устойчивые к атакам с использованием квантовых компьютеров. В OpenSSH 10.0+ гибридная PQC включена по умолчанию для защиты от угрозы «сохрани сейчас, расшифруй потом» (HNDL).

### Сравнение с Telnet

| Характеристика | SSH (Secure Shell) | Telnet |
| :--- | :--- | :--- |
| **Безопасность** | **Высокая**. Данные зашифрованы. | **Критически низкая**. Открытый текст. |
| **Аутентификация** | Хоста и клиента (ключи/сертификаты). | Только пароль (передается открыто). |
| **Целостность** | Контроль через MAC/AEAD. | Отсутствует. |
| **Применение** | Стандарт индустрии. | Устарел, только для диагностики портов. |

## Базовые концепции

### Этапы установления соединения

1.  **TCP Handshake** — стандартное трехстороннее рукопожатие на порт 22.
2.  **Согласование протокола** — обмен версиями (SSH-2.0).
3.  **Key Exchange (KEX)** — выбор алгоритмов и генерация общего секрета сессии. В современных версиях используются гибридные PQC-алгоритмы (ML-KEM + X25519).
4.  **Аутентификация сервера** — клиент проверяет Host Key сервера по базе `known_hosts`.
5.  **Аутентификация пользователя** — проверка прав доступа (публичный ключ, FIDO2, пароль).

### Защита от атаки «человек посередине» (MITM)

Механизм `known_hosts` предотвращает подмену сервера. Если публичный ключ сервера изменился, SSH заблокирует соединение с предупреждением.

**Действие при легитимном изменении (например, после переустановки ОС на сервере):**
```bash
ssh-keygen -R <hostname_or_ip>
# → result: /home/user/.ssh/known_hosts updated.
```

### Архитектура процессов и сессии

В ОС Linux сессия SSH представляет собой иерархию процессов:
1.  **sshd (Master)** — слушает порт и порождает дочерние процессы.
2.  **sshd (Privilege Separation)** — изолированный процесс для обработки аутентификации.
3.  **sshd (User session)** — процесс от имени пользователя, управляющий оболочкой (bash, zsh).
4.  **pts/N (Псевдотерминал)** — эмуляция терминала для интерактивной работы.

Для сохранения долгоживущих задач при разрыве связи используются `tmux` или `screen` ([Управление сессиями](./ssh_session_management.md)).

### Использование аппаратных ключей (FIDO2)

Для защиты от кражи ключей рекомендуется использовать аппаратные токены (YubiKey и аналоги) с типом ключа `ed25519-sk`.

```bash
# Генерация ключа, привязанного к аппаратному токену
ssh-keygen -t ed25519-sk -O resident -f ~/.ssh/id_ed25519_sk
# → result: Enter PIN for authenticator...
# → result: You may need to touch your authenticator to authorize key generation.
```
*   **resident** — позволяет восстановить ключ на новом ПК, считав его прямо с токена.
*   **verify-required** — принудительно требует PIN или касание при каждом использовании.

## Дополнительная информация

### Рекомендуемые алгоритмы (2026+)

| Категория | Рекомендуемые (OpenSSH 10.0+) | Устаревшие (отключать) |
| :--- | :--- | :--- |
| **KEX (Обмен ключами)** | `mlkem768x25519-sha256` (PQC), `sntrup761x25519-sha512` | `diffie-hellman-group1-sha1`, `nistp*` |
| **Host Key** | `ssh-ed25519`, `sk-ed25519@openssh.com` | `ssh-rsa` (SHA-1), `ssh-dss` |
| **Шифрование** | `chacha20-poly1305@openssh.com`, `aes256-gcm@openssh.com` | `aes128-cbc`, `3des-cbc` |
| **MAC** | `hmac-sha2-512-etm@openssh.com` | `hmac-md5`, `hmac-sha1` |

### Безопасность и критические уязвимости

*   **CVE-2024-6387 (regreSSHion):** Критическая уязвимость (RCE) в `sshd`. Требуется обновление до версии **9.8p1** или выше.
*   **SSH-сертификаты:** В крупных инфраструктурах рекомендуется переходить от `authorized_keys` к [SSH CA (Certificate Authority)](./server/ssh_certificate_authentication.md) для ограничения времени жизни ключей и централизованного отзыва доступа.

### Изменение порта и обфускация

Смена порта с 22 на произвольный (директива `Port` в `sshd_config`) эффективно снижает фоновый шум в логах от ботнетов, но не заменяет полноценную защиту.

```bash
# Подключение на нестандартный порт
ssh -p 2222 user@remote-host
# → result: Welcome to Linux ...
# → result: [user@remote-host ~]$
```
