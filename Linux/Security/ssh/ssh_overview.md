# SSH (Secure Shell): Обзор

SSH (Secure Shell) — это сетевой протокол прикладного уровня, предназначенный для безопасного удалённого управления системой и туннелирования TCP-соединений. Вся информация, включая пароли, передаётся в зашифрованном виде. SSH использует TCP на транспортном уровне для надёжной доставки данных.

Процесс подключения состоит из нескольких ключевых этапов.

1.  **Установка TCP-соединения:** Клиент инициирует TCP-соединение с сервером на указанный порт (по умолчанию 22).
2.  **Обмен версиями протокола:** Клиент и сервер сообщают друг другу поддерживаемые версии протокола SSH и выбирают общую.
3.  **Согласование алгоритмов:** Стороны договариваются об алгоритмах для:
        - Шифрования (AES-256-GCM, ChaCha20)
        - MAC(проверки целостности) (HMAC-SHA2)
        - Сжатия
        - Ключевого обмена (Diffie-Hellman, ECDH, Curve25519)
        - Хост-ключей (RSA, ED25519 и др.)
4.  **Обмен ключами сессии:** С помощью согласованного алгоритма (например, Diffie-Hellman) генерируется общий секретный ключ сессии. Этот ключ шифрует весь дальнейший трафик. На этом же этапе сервер доказывает свою подлинность клиенту, чтобы избежать атак "man-in-the-middle". Клиент проверяет ключ хоста (сервера) по своему файлу `~/.ssh/known_hosts`.
5.  **Аутентификация пользователя:** После установки зашифрованного канала клиент должен подтвердить своё право на доступ. Подробнее об этом в заметке [Аутентификация в SSH](./ssh_authentication.md).

## Анализ рукопожатия SSH в Wireshark

С помощью анализатора трафика, такого как Wireshark, можно наглядно увидеть все этапы установки SSH-соединения до начала шифрования.

1.  **Обмен версиями протокола:**
    *   Сразу после установки TCP-соединения клиент и сервер обмениваются сообщениями, содержащими версии поддерживаемого протокола (например, `SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.1`). Если версии несовместимы, соединение прерывается.

2.  **Согласование алгоритмов (`Key Exchange Init`):**
    *   Клиент и сервер отправляют друг другу сообщения `Key Exchange Init`. Каждый из этих пакетов содержит списки поддерживаемых алгоритмов для:
        *   Шифрования
        *   Проверки целостности (MAC)
        *   Ключевого обмена
        *   Сжатия
        *   Ключей хоста
    *   Стороны сравнивают списки и выбирают первые совпадающие алгоритмы в каждом списке для дальнейшего использования. Если общих алгоритмов не найдено, соединение разрывается.

3.  **Обмен ключами (Diffie-Hellman):**
    *   На основе выбранного алгоритма обмена ключами запускается механизм Диффи-Хеллмана для генерации общего сессионного ключа.
    *   Клиент генерирует временную (эфемерную) пару ключей и отправляет свой **публичный ключ** серверу.
    *   Сервер делает то же самое: генерирует свою временную пару и отправляет свой **публичный ключ** клиенту.
    *   Используя свой приватный ключ и публичный ключ другой стороны, клиент и сервер вычисляют общий секретный ключ. Этот ключ будет одинаковым у обеих сторон, но никогда не передавался по сети в открытом виде.

4.  **Новые ключи (`New Keys`):**
    *   После успешной генерации общего секрета обе стороны отправляют друг другу сообщение `New Keys`.
    *   Это сообщение сигнализирует о том, что вся последующая коммуникация будет зашифрована с использованием вычисленного сессионного ключа. Весь дальнейший трафик, включая этап аутентификации пользователя (передачу пароля или проверку по ключу), в Wireshark будет отображаться как `Encrypted Packet` и будет нечитаем.
