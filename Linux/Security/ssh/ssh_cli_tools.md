# Инструменты командной строки SSH

## Определения

**SSH CLI tools** — экосистема утилит командной строки, использующих протокол SSH (Secure Shell) для выполнения административных задач: управления файлами, синхронизации данных, настройки доступа и обеспечения устойчивых терминальных сессий.

### Основные утилиты

*   **`scp` (Secure Copy)** — классическая утилита для копирования файлов. В современных версиях OpenSSH (9.0+) работает поверх протокола SFTP.
*   **`sftp` (SSH File Transfer Protocol)** — интерактивный инструмент для управления файлами, поддерживающий полноценный набор операций (ls, rm, mkdir, chmod).
*   **`ssh-copy-id`** — специализированный скрипт для безопасной установки публичных ключей на удаленные серверы.
*   **`rsync`** — мощный инструмент для инкрементальной синхронизации (передает только измененные части файлов).

### Продвинутые инструменты

*   **`mosh` (Mobile Shell)** — замена стандартному SSH-клиенту для мобильных и нестабильных сетей (UDP-транспорт, локальное эхо).
*   **`sshfs`** — клиент файловой системы на базе FUSE для монтирования удаленных директорий. *Примечание: в 2024-2026 годах считается устаревающим, рекомендуется переход на `rclone mount`.*

## Базовые концепции

### Эволюция протокола scp

Исторически `scp` использовал протокол RCP, который имел серьезные проблемы с безопасностью (обработка glob-шаблонов на стороне сервера) и производительностью.

| Характеристика | scp (Legacy/RCP) | scp (Modern/SFTP) |
| :--- | :--- | :--- |
| **Протокол** | RCP (Remote Copy Protocol) | SFTP (Subsystem) |
| **Безопасность** | Низкая (уязвим к манипуляциям сервера) | Высокая (строгая изоляция путей) |
| **Globbing** | На стороне сервера (опасно) | На стороне клиента (безопасно) |
| **Флаг принуждения** | `-O` | По умолчанию (OpenSSH 9.0+) |

### Принцип работы mosh (State Synchronization Protocol)

В отличие от SSH, который передает поток байтов (byte stream), `mosh` синхронизирует состояние экрана (object state).
1.  **Аутентификация:** выполняется через стандартный SSH.
2.  **Транспорт:** переключается на UDP (порты 60000–61000).
3.  **Локальное эхо:** `mosh` немедленно отображает введенные символы, не дожидаясь ответа от сервера, что убирает задержку (lag).

## Практические сценарии

### Настройка доступа через ssh-copy-id

Самый надежный способ настроить беспарольный вход. Автоматически устанавливает правильные права на директорию `.ssh` и файл `authorized_keys`.

```bash
# Копирование ключа по умолчанию на сервер
ssh-copy-id user@remote-host
# → result: /usr/bin/ssh-copy-id: INFO: 1 key(s) remain to be installed -- if you are prompted now it is to install the new keys

# Использование конкретного ключа и нестандартного порта
ssh-copy-id -i ~/.ssh/id_ed25519.pub -p 2222 user@remote-host
```

### scp — копирование файлов и папок

В современных системах `scp` является оберткой над `sftp`, поэтому поддерживает те же флаги безопасности.

```bash
# Копирование директории через Jump-хост (Bastion)
scp -J bastion-user@bastion-host -r ./local-dir user@target-host:/tmp/

# Копирование с ограничением скорости (в Кбит/с), чтобы не забить канал
scp -l 8192 backup.tar.gz user@remote-host:/storage/
# → result: backup.tar.gz 100% 100MB 1.0MB/s 01:40
```

### sftp — автоматизация через batch mode

Интерактивный режим удобен для разовых задач, но `sftp` также поддерживает пакетную обработку.

```bash
# Выполнение команд из файла
sftp -b batch_commands.txt user@remote-host

# Inline-выполнение через Here Document
sftp user@remote-host <<EOF
  cd /var/www/html
  put index.html
  ls -l
  bye
EOF
```

### rclone — современная альтернатива sshfs

Поскольку `sshfs` практически не поддерживается, для монтирования рекомендуется использовать `rclone`. Он быстрее, стабильнее и поддерживает кэширование.

```bash
# Настройка удаленного подключения (выбрать тип SFTP)
rclone config

# Монтирование в фоновом режиме с кэшированием
rclone mount remote_ssh:/var/www ~/mnt/web --vfs-cache-mode full &
```

## Дополнительная информация

### Сравнение методов передачи файлов

| Инструмент | Плюсы | Минусы |
| :--- | :--- | :--- |
| **scp** | Простота, есть везде | Нет докачки, неэффективен для тысяч мелких файлов |
| **sftp** | Интерактивность, автоматизация | Медленнее, чем rsync на больших объемах |
| **rsync** | Скорость (дельты), зеркалирование | Требует установки `rsync` на обоих концах |
| **rclone** | Огромная гибкость, кэш, облака | Сложнее в первичной настройке |

### mosh: расширенные настройки

Для работы через Jump-хост или со специфическим SSH-конфигом используйте флаг `--ssh`:

```bash
mosh --ssh="ssh -J bastion" user@target-host
```

### Статус проектов (Health Check 2026)

*   **Mosh:** Статус "Feature Complete". Активной разработки новых функций нет, так как протокол SSP считается завершенным и безопасным.
*   **SSHFS:** Проект находится в статусе "Orphaned/Unmaintained". Рекомендуется миграция на **rclone** или нативные сетевые протоколы (NFS/SMB) поверх VPN.
*   **xxh:** Живой проект для переноса локального окружения (zsh/plugins) на любой сервер без root-прав. [GitHub xxh](https://github.com/xxh/xxh).
