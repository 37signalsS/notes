# Инструменты командной строки SSH

## Передача файлов и работа с файловой системой

### `scp` (Secure Copy)

Простая утилита для копирования файлов.

```bash
# Копирование локального файла на сервер
scp /path/to/local/file.txt user@server:/remote/path/

# Рекурсивное копирование директории с нестандартным портом (-P)
scp -P 2222 -r /local/dir user@server:/remote/dir

# Копирование файла с локальной машины на удаленную с указанием нестандартного порта
scp -P 2239 /path/to/local/new_file.txt root@192.168.150.148:/root/

# Копирование файла с удаленной машины на локальную с указанием нестандартного порта
scp -P 2239 root@192.168.150.148:/root/one.txt /path/to/local/

# Копирование с уданую (челенной на удаленрез локальную машину)
scp user1@server1:/file.txt user2@server2:/dest/

# Копирование с сжатием (-C) для ускорения передачи по медленной сети
scp -C -r /large_dir user@server:/path/

# Использование globbing (шаблонов) на удаленной стороне
scp user@server:/remote/path/*.log /local/dir/
```

### `rsync` (Remote Sync)

Мощная утилита для инкрементальной синхронизации файлов и каталогов. Работает локально, через SSH или через собственный rsync-демон.

**Как работает:**

- Разбивает файлы на блоки фиксированного размера.
- Вычисляет контрольные суммы (rolling checksum + хэш) для каждого блока.
- Сравнивает блоки источника и назначения.
- Передаёт только отличающиеся блоки, а не файлы целиком.

Это экономит трафик и время при повторных операциях.

**Базовый синтаксис:**

```bash
rsync [параметры] источник назначение
```

**Основные параметры:**

| Параметр | Описание |
| :--- | :--- |
| `-a` | Архивный режим: рекурсивность + сохранение прав, симлинков, таймстампов, владельцев. Почти всегда нужен. |
| `-v` | Подробный вывод (verbose). |
| `-z` | Сжатие при передаче (полезно по медленным каналам). |
| `-h` | Человеко-читаемые размеры (K, M, G). |
| `-P` | Комбинация `--partial` (докачка) и `--progress` (прогресс-бар). |
| `--delete` | Удаляет файлы в назначении, которых нет в источнике (зеркалирование). |
| `-n` / `--dry-run` | Тестовый прогон без реальных изменений. |
| `--exclude` | Исключает файлы/папки по шаблону (можно указывать несколько раз). |
| `-e` | Указывает удалённую оболочку, например `-e ssh`. |

**Примеры:**

```bash
# Локальное копирование папки
rsync -avh /home/user/data/ /backup/data/

# Отправка на удалённый сервер (push)
rsync -avz -e ssh /local/folder/ user@server:/remote/folder/

# Загрузка с сервера (pull)
rsync -avz -e ssh user@server:/remote/folder/ /local/folder/

# Тестовый прогон зеркалирования с удалением лишнего
rsync -avn --delete /source/ /dest/

# Синхронизация с прогрессом и докачкой
rsync -avzP /local/dir/ user@server:/remote/dir/
```

**Важность слеша:**

- `rsync source/ dest` — копирует **содержимое** директории source в dest
- `rsync source dest` — копирует **саму директорию** source в dest

**Исключения:**

```bash
# Исключить node_modules и .git
rsync -av --exclude='node_modules' --exclude='.git' /src/ /dest/

# Исключить по шаблону
rsync -av --exclude='*.log' --exclude='tmp/' /src/ /dest/
```

### `sftp` (SSH File Transfer Protocol)

Интерактивный протокол для работы с файлами поверх SSH. В отличие от FTP, работает на одном порту (22) и использует шифрование по умолчанию.

```bash
# Подключение к удаленному серверу
sftp user@server

# Основные команды в интерактивном режиме:
# ls, cd, pwd     # навигация
# get, put        # скачать/загрузить файл
# get -r, put -r  # рекурсивно для директорий
# mkdir, rmdir    # создать/удалить директорию
# rm              # удалить файл
# bye, quit       # выход
```

**Графические клиенты:**

- Linux: Nautilus (файловый менеджер) — подключение через `sftp://user@server`
- Windows: WinSCP, FileZilla

### Сравнение SCP, SFTP и RSYNC

| Характеристика | `scp` | `sftp` | `rsync` |
| :--- | :--- | :--- | :--- |
| **Назначение** | Разовое копирование | Интерактивная работа с файлами | Синхронизация/инкрементальное копирование |
| **Основной режим** | Командная строка | Интерактивный/командная строка | Командная строка |
| **ПередачаDelta** | Всегда копирует файл целиком | Всегда копирует файл целиком | Только изменения (дельты) |
| **Удаление файлов** | Нет | Нет | Да (`--delete`) |
| **Лучший сценарий** | Быстрое копирование небольших файлов | Навигация по удаленной ФС, управление файлами | Регулярные бэкапы, синхронизация больших директорий |

### `sshfs` (SSH File System)

Монтирует удаленную файловую систему локально, используя [FUSE](../../FileSystems/fuse.md), позволяя работать с файлами так, будто они находятся на вашем компьютере.

```bash
# Создать точку монтирования
mkdir ~/remote_server
# Смонтировать
sshfs user@server:/remote/path ~/remote_server
# Отмонтировать
fusermount -u ~/remote_server
```

### Сравнение `scp` и `rsync`

| Критерий | `scp` | `rsync` |
| :--- | :--- | :--- |
| **Простота** | Очень прост для базового копирования | Немного сложнее, больше опций |
| **Эффективность** | Всегда копирует файл целиком | Копирует только измененные блоки данных |
| **Возможности**| Только копирование | Синхронизация, исключение файлов, удаление |
| **Лучший сценарий** | Разовое копирование небольших файлов | Регулярная синхронизация, бэкапы, передача больших файлов |

## Интерактивные TUI-менеджеры

### `lazyssh`

**`lazyssh`** — это TUI (Text-based User Interface) менеджер для SSH, который предоставляет интерактивную оболочку для управления множеством серверов.

- **Ключевые возможности**:
  - Быстрое подключение к серверам из списка.
  - Дашборд для мониторинга статуса серверов.
  - Упрощенное управление файлами (копирование между клиентом и сервером).
  - Управление сессиями и навигация с помощью горячих клавиш.

- **[GitHub-репозиторий](https://github.com/adembc/lazyssh)

## Другие CLI инструменты

### `mosh` (Mobile Shell)

**`mosh`** — протокол удалённого доступа к терминалу, разработанный для работы в условиях нестабильных сетей. В отличие от SSH, использует UDP вместо TCP, что позволяет сохранять сессию при смене IP-адреса, обрыве связи или засыпании устройства.

- **Происхождение**: проект родился в MIT в 2012 году, опубликован на конференции USENIX. 13.6k звёзд на GitHub.
- **Лицензия**: GPL-3.0, написан на C++.
- **Платформы**: Linux, macOS, BSD, Android (Termux), iOS (Blink Shell).

#### Принцип работы

Mosh не заменяет SSH — он использует его для начальной аутентификации:

1. Клиент подключается через SSH для аутентификации.
2. После успешной аутентификации Mosh поднимает свой канал по UDP.
3. SSH-соединение закрывается, дальнейшая работа идёт через UDP.

#### Протокол SSP (State Synchronization Protocol)

Вместо TCP-потока байтов Mosh использует SSP:

- Синхронизирует **состояние экрана**, а не передаёт каждый байт.
- При потере пакетов промежуточные кадры пропускаются — как в видеостриме.
- Каждый UDP-датаграмм отдельно шифруется и аутентифицируется (AES-128-OCB3).

#### Ключевые возможности

- **Предиктивный локальный эхо**: клиент показывает нажатую клавишу мгновенно, не дожидаясь ответа сервера. На соединении с пингом 500 мс отклик падает с 500 мс до 5 мс.
- **Роуминг IP**: смена сети (Wi-Fi → LTE, включение VPN) не разрывает сессию.
- **Не требует root**: работает как обычный процесс пользователя.
- **Безопасность**: ноль серьёзных уязвимостей за 14 лет.

#### Установка

```bash
# Сервер (Debian/Ubuntu)
apt install mosh

# Клиент (Debian/Ubuntu)
apt install mosh

# Использование
mosh user@host
# или с указанием порта SSH
mosh --port=2222 user@host
```

#### Нюансы и ограничения

| Ограничение | Описание | Решение |
| :--- | :--- | :--- |
| **Нет скроллбэка** | Mosh синхронизирует только видимую область терминала | Использовать `tmux` или `screen` внутри сессии |
| **Нет port forwarding** | Не поддерживает проброс портов, agent forwarding, X11 | Для туннелей использовать SSH |
| **Не работает через Tor** | Tor использует только TCP, Mosh — UDP | Архитектурное ограничение |
| **Только терминал** | Интерактивный режим, без передачи файлов | Использовать `scp`/`rsync` отдельно |

### `xxh` (eXecute SHell)

**`xxh`** — инструмент, позволяющий запускать локально установленную оболочку (shell) на удаленном хосте через SSH, без необходимости ее предварительной установки или конфигурации на удаленном сервере.

- **Ключевые возможности**:
  - Использование предпочитаемой локальной оболочки (например, zsh, fish) на любом удаленном сервере.
  - Сохранение привычной конфигурации и плагинов оболочки при работе на удаленных системах.
  - Упрощение кросс-системной работы без необходимости синхронизации настроек оболочки.

- **[GitHub-репозиторий](https://github.com/xxh/xxh)
