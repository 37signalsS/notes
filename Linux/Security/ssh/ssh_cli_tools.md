# Инструменты командной строки SSH

## Определения

**SSH CLI tools** — экосистема утилит командной строки, использующих протокол SSH (Secure Shell) для выполнения административных задач: управления файлами, синхронизации данных, настройки доступа и обеспечения устойчивых терминальных сессий.

### Основные утилиты управления доступом

*   **`ssh-keygen`** — фундаментальный инструмент для создания, управления и конвертации пар ключей (публичных и приватных).
*   **`ssh-copy-id`** — скрипт для безопасной установки публичных ключей в `~/.ssh/authorized_keys` на удаленных серверах.
*   **`ssh-keyscan`** — утилита для массового сбора публичных ключей хостов. Позволяет автоматизировать заполнение `known_hosts`.
*   **`ssh-add`** — инструмент для добавления ключей в `ssh-agent`.

### Утилиты передачи и синхронизации файлов

*   **`scp` (Secure Copy)** — утилита для копирования файлов. В современных версиях OpenSSH (9.0+) работает как обертка над SFTP.
*   **`sftp` (SSH File Transfer Protocol)** — интерактивный инструмент для управления файлами (аналог FTP поверх SSH).
*   **`rsync`** — инструмент для инкрементальной синхронизации. Подробности см. в [**rsync — синхронизация файлов**](../SystemAdministration/rsync.md).

### Продвинутые и параллельные инструменты

*   **`pssh` (Parallel SSH)** — набор утилит (`pssh`, `pscp`, `prsync`) для параллельного выполнения команд и передачи файлов на множество хостов.
*   **`mosh` (Mobile Shell)** — замена SSH для нестабильных сетей (UDP, локальное эхо).
*   **`sshfs`** — монтирование удаленных директорий через FUSE. *Примечание: в 2026 году считается устаревающим, рекомендуется переход на `rclone mount`.*

## Базовые концепции

### Типы ключей и ssh-keygen

При генерации ключей в 2026 году приоритет отдается алгоритмам с короткой длиной ключа и высокой стойкостью.

| Алгоритм | Рекомендация | Особенности |
| :--- | :--- | :--- |
| **Ed25519** | **Default** | Максимальная безопасность, компактный размер ключа. |
| **RSA (4096)** | Совместимость | Медленнее, требует большой длины (4096 бит). SHA-1 версии запрещены. |
| **ECDSA** | Ограниченно | Использует NIST-кривые (потенциальные бэкдоры). |
| **Ed25519-SK** | **FIDO2** | Для работы с аппаратными токенами (YubiKey). |

### Эволюция протокола scp

Исторически `scp` использовал небезопасный протокол RCP. В современных системах он переведен на SFTP.

| Характеристика | scp (Legacy/RCP) | scp (Modern/SFTP) |
| :--- | :--- | :--- |
| **Протокол** | RCP (Remote Copy Protocol) | SFTP (Subsystem) |
| **Безопасность** | Низкая (уязвим к манипуляциям сервера) | Высокая (строгая изоляция путей) |
| **Globbing** | На стороне сервера (опасно) | На стороне клиента (безопасно) |

### Принцип работы mosh (State Synchronization Protocol)

`mosh` синхронизирует состояние экрана, а не поток байтов, что позволяет сохранять сессию при смене IP-адреса клиента или кратковременных обрывах связи.

## Практические сценарии

### ssh-keygen — создание ключей

```bash
# Создание ключа Ed25519 с комментарием
ssh-keygen -t ed25519 -C "admin@workstation" -f ~/.ssh/id_ed25519_prod
# → result: Your identification has been saved in /home/user/.ssh/id_ed25519_prod

# Изменение парольной фразы на существующем ключе
ssh-keygen -p -f ~/.ssh/id_ed25519_prod
```

### ssh-keyscan — автоматизация доверия (CI/CD)

Используется для предотвращения интерактивного вопроса "Are you sure you want to continue connecting?".

```bash
# Получение ключа сервера и добавление в known_hosts
ssh-keyscan -t ed25519 remote-host.com >> ~/.ssh/known_hosts
# → result: # remote-host.com:22 SSH-2.0-OpenSSH_9.8p1
```

### pssh — выполнение команды на 100 серверах

```bash
# Запуск команды на хостах из файла
pssh -h hosts.txt -l root -A -i "uptime"
# → result: [1] 14:30:05 [SUCCESS] 192.168.1.10
# → result: 14:30:05 up 10 days, 2:14, 1 user, load average: 0.01, 0.05, 0.00
```

### scp и sftp — передача файлов

```bash
# Копирование папки через Jump-хост
scp -J bastion-user@bastion -r ./src user@target:/tmp/

# Пакетная передача через SFTP
sftp user@remote-host <<EOF
  put config.yaml /etc/app/
  chmod 644 /etc/app/config.yaml
  bye
EOF
```

### Статус проектов (Health Check 2026)

*   **Mosh:** Статус "Feature Complete". Идеален для работы из транспорта или через нестабильный Wi-Fi.
*   **Parallel SSH:** `pssh` остается стандартом для быстрых ad-hoc операций, хотя для сложных задач рекомендуется **Ansible**.
*   **xxh:** Инструмент для тех, кто хочет иметь свой `fish`/`zsh` и конфиги на любом SSH-сервере без их установки. [GitHub xxh](https://github.com/xxh/xxh).
