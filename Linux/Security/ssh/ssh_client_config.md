# Конфигурация клиента SSH (`~/.ssh/config`)

## Определения

**Файл `~/.ssh/config`** — это конфигурационный файл SSH-клиента, который позволяет определять псевдонимы (алиасы) для удаленных хостов и задавать для них индивидуальные параметры подключения, такие как имя пользователя, порт, используемый ключ и другие. Это упрощает и автоматизирует процесс подключения к часто используемым серверам.

**Jump Host (узел-бастион)** — это промежуточный, специально защищенный сервер, который служит единой точкой входа во внутреннюю сеть. Подключение к внутренним ресурсам осуществляется "прыжком" через этот узел, что повышает безопасность и упрощает аудит.

**SSH Multiplexing (мультиплексирование)** — это техника, позволяющая повторно использовать одно TCP-соединение для нескольких сеансов SSH (включая `scp`, `sftp`, `git`). Это значительно ускоряет последующие подключения к тому же хосту, пропуская этапы рукопожатия и аутентификации.

## Основные концепции

### Структура файла `~/.ssh/config`

Файл состоит из блоков, каждый из которых начинается с директивы `Host`.

- **`Host <alias>`:** Определяет блок настроек для псевдонима `<alias>`.
- **`Host *`:** Определяет глобальные настройки, которые применяются ко всем хостам, если они не переопределены в более специфичном блоке.
- **Директивы:** Внутри блока указываются параметры, такие как:
  - `HostName`: Реальное имя хоста или IP-адрес.
  - `User`: Имя пользователя для входа.
  - `Port`: Порт SSH на сервере.
  - `IdentityFile`: Путь к приватному ключу для аутентификации.
  - `Compression`: Включает сжатие (`yes`/`no`).

### Принцип работы Jump Host

При использовании `ProxyJump` SSH-клиент сначала устанавливает защищенное соединение с **Jump Host**, а затем просит его создать "прозрачный" TCP-туннель до конечного целевого сервера. Весь дальнейший трафик к целевому серверу инкапсулируется в этот туннель.

### Принцип работы мультиплексирования

Первая сессия к хосту устанавливает "мастер-канал" и создает управляющий сокет (unix-файл). Все последующие сессии к этому же хосту подключаются к этому сокету, мгновенно получая доступ к уже установленному соединению без необходимости повторной аутентификации.

## Практические сценарии

> **Важно:** Для корректной работы SSH необходимо убедиться в правильности прав доступа к файлам. Для `~/.ssh/config` рекомендуются права `600`. Подробнее см. в разделе [Проверка и установка прав доступа](./server/ssh_server_security_overview.md#проверка-и-установка-прав-доступа).

### Базовая конфигурация

Файл `~/.ssh/config` позволяет задать псевдонимы и общие параметры:

```ini
# Псевдоним для рабочего сервера
Host work
  HostName spb-mx-i3.extrt.int.company.net
  User ivanov_i
  Port 2222
  IdentityFile ~/.ssh/id_work
  Compression yes

# Другой хост
Host home
  HostName myhome.dyndns.org
  User vasya
  PasswordAuthentication no
  IdentityFile ~/.ssh/id_rsa_home

# Настройки по умолчанию для всех хостов
Host *
  # Пользователь по умолчанию для всех подключений, если не указан явно для конкретного хоста.
  User root
  # Явное указание предпочитаемых методов аутентификации.
  # Порядок имеет значение. В данном примере сначала будет попытка по ключу, затем по паролю.
  # PreferredAuthentications publickey,password
  # Отключение аутентификации по ключу (полезно для отладки).
  # PubkeyAuthentication no
  # Включает перенаправление X11. Полезно для запуска графических приложений на удаленном сервере.
  # Отключаем X11 forwarding, потому что это обычное текстовое подключение.
  ForwardX11 no
  # Отправляет "keep alive" сообщения каждые 60 секунд, чтобы соединение не разрывалось из-за бездействия.
  ServerAliveInterval 60
  # Включает сжатие данных, что может быть полезно для медленных соединений, уменьшая объем передаваемого трафика.
  Compression yes
  # Отключает все интерактивные запросы (пароли, подтверждение хостов), используеться только в связке с ssh-ключами.
  # Крайне полезно для скриптов и автоматизации.
  # При необходимости аутентификации, которая требует интерактива(ввод пароля), соединение просто завершится с ошибкой, а не "зависнет".
  BatchMode yes
  # Уровень логирования для клиента SSH. Полезно для отладки проблем с подключением.
  # Возможные значения: QUIET, FATAL, ERROR, INFO, VERBOSE, DEBUG, DEBUG1, DEBUG2, DEBUG3.
  # LogLevel INFO
```

Теперь подключение выполняется командой `ssh work`.

### Настройка подключения через Jump Host (`ProxyJump`)

Это рекомендуемый способ для доступа к серверам во внутренней сети.

1. **Опишите Jump Host** в `~/.ssh/config`:

    ```ini
    Host bastion
        HostName 203.0.113.10
        User admin
    ```

2. **Опишите целевой сервер**, указав `ProxyJump`:

    ```ini
    Host internal-server
        HostName 192.168.1.100
        User app_user
        ProxyJump bastion
    ```

Теперь команда `ssh internal-server` автоматически подключится через `bastion`.

### Настройка SSH Multiplexing

1. **Создайте директорию для сокетов:**

    ```bash
    mkdir -p ~/.ssh/sockets
    chmod 700 ~/.ssh/sockets
    ```

2. **Добавьте директивы в `~/.ssh/config`** (обычно в блок `Host *`):

    ```ini
    Host *
      ControlMaster auto
      ControlPath ~/.ssh/sockets/%r@%h:%p
      ControlPersist 10m
      # Другие общие настройки...
      ServerAliveInterval 60
      Compression yes

    # Или для конкретного хоста
    Host myserver
        HostName 192.168.1.10
        User admin
        ControlMaster auto
        ControlPath ~/.ssh/sockets/%r@%h:%p
        ControlPersist 10m
    ```

    - `ControlMaster auto`: Автоматически создавать мастер-канал.
    - `ControlPath`: Шаблон для именования файлов сокетов.
    - `ControlPersist`: Оставлять мастер-канал активным в фоне 10 минут после закрытия последней сессии.

## Дополнительная информация

### `ProxyCommand` (старый способ для Jump Host)

Для старых версий OpenSSH (< 7.3) или более сложных сценариев вместо `ProxyJump` используется `ProxyCommand`:

```ini
Host internal-server
    HostName 192.168.1.100
    User app_user
    ProxyCommand ssh bastion -W %h:%p
```

Здесь `ssh bastion -W %h:%p` создает тот же туннель, что и `ProxyJump`.

### Управление мультиплексированными сессиями

Вы можете явно управлять мастер-каналами с помощью флага `-O`:

- **Проверить статус:** `ssh -O check my_alias`
- **Принудительно закрыть:** `ssh -O exit my_alias`

### Полезные директивы

- `BatchMode yes`: Отключает все интерактивные запросы (например, ввод пароля). Крайне полезно для скриптов, чтобы избежать "зависания" в ожидании ввода.
- `LogLevel INFO`: Устанавливает уровень детализации логов клиента (полезно для отладки).
- `PreferredAuthentications publickey,password`: Задает предпочитаемый порядок методов аутентификации.
