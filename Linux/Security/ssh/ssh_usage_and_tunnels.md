# Использование SSH: команды, файлы и туннели

## Удалённое выполнение команд

SSH позволяет выполнять команды на удалённом сервере без открытия интерактивной сессии.

```bash
# Простое выполнение команды
ssh user@server "ls -l /var/www"

# С запросом псевдо-терминала (-t) для интерактивных команд, таких как top или htop
ssh -t user@server "top"
```

## Копирование файлов и монтирование ФС

### `scp` (Secure Copy)

`scp` (Secure Copy) — это команда для безопасного копирования файлов между системами Linux или Unix через зашифрованное соединение SSH. Благодаря этому данные остаются защищёнными даже при попытках перехвата.

#### Примеры использования SCP

**Копирование файлов с локального на удалённый сервер**
Чтобы скопировать файл `test.txt` в каталог `/location2` на удалённом сервере:
```bash
scp test.txt username@destination:/location2
```

**Копирование всех файлов определённого типа**
Для передачи всех файлов `.txt` из домашнего каталога в удалённую систему:
```bash
scp ~/files/*.txt username@destination:/location/
```

**Переименование файлов во время копирования**
Чтобы скопировать файл `test.txt` и сохранить его на удалённой системе под новым именем:
```bash
scp test.txt username@destination:/location/renamed_file.txt
```

**Использование нестандартного порта**
Если сервер SSH настроен на порт 1234, используйте флаг `-P` (обратите внимание, что `scp` использует заглавную `-P`, в отличие от `ssh` с `-p` для порта):
```bash
scp -P 1234 test.txt username@destination:/location2/
```

#### Советы по использованию SCP

*   **Будьте осторожны с перезаписью файлов:** SCP автоматически перезаписывает файлы с одинаковым именем в каталоге назначения без предупреждения.
*   **Контроль разрешений:** Убедитесь, что у вас есть права на чтение/запись в исходной и целевой системах.
*   **Копирование директорий:** Для копирования директорий используйте флаг `-r` (рекурсивно).
    ```bash
    scp -r /path/to/local/dir username@destination:/path/to/remote/
    ```
*   **Стабильная передача больших файлов:** Для стабильной передачи больших файлов используйте SCP в сочетании с терминальным мультиплексором, например, `tmux` или `screen`, чтобы избежать потери прогресса при разрыве соединения.

---

### `rsync` (Remote Sync)
Более мощная утилита для синхронизации файлов и директорий. Эффективнее `scp` при повторной синхронизации, так как передает только измененные части файлов.

```bash
# Синхронизация локальной директории с удаленной
# -a: режим архивирования (сохраняет права, владельца, временные метки)
# -v: подробный вывод
# -z: сжатие данных при передаче
# --progress: показывает прогресс
rsync -avz --progress /local/dir/ user@server:/remote/dir/
```

### `sshfs` (SSH File System)
Монтирует удаленную файловую систему локально, позволяя работать с удаленными файлами так, как если бы они были на вашем компьютере.

```bash
# Установка (для Debian/Ubuntu)
sudo apt-get install sshfs

# Создание точки монтирования
mkdir -p /media/remote_server

# Монтирование
# -o reconnect: автоматически переподключаться при обрыве связи
sshfs user@server:/remote/path /media/remote_server -o reconnect

# Отмонтирование
fusermount -u /media/remote_server
```

## SSH-туннелирование (проброс портов)

SSH-туннели создают защищенные каналы для перенаправления сетевого трафика между машинами.

### Локальный проброс портов (`-L`)
Позволяет получить доступ к сервису на удалённом сервере (или в его сети) через порт на вашей локальной машине.

**Сценарий:** Доступ к базе данных `db.internal.host:5432`, которая доступна только с машины `gateway`.

```bash
# ssh -L <локальный_порт>:<целевой_хост>:<целевой_порт> user@ssh_server
ssh -L 5432:db.internal.host:5432 user@gateway
```
Теперь, подключаясь к `localhost:5432` на вашей машине, вы на самом деле будете работать с базой данных на `db.internal.host`.

### Удаленный проброс портов (`-R`)
Позволяет "выставить" сервис с вашей локальной машины в интернет через порт на удаленном публичном сервере.

**Сценарий:** Показать коллеге веб-приложение, работающее на вашем `localhost:3000`.

```bash
# ssh -R <удалённый_порт>:<локальный_хост>:<локальный_порт> user@ssh_server
ssh -R 8080:localhost:3000 user@public_server
```
Теперь любой, кто зайдет на `public_server:8080`, увидит ваше веб-приложение.

### Динамический проброс портов (`-D`)
Создает SOCKS-прокси на вашей локальной машине, который перенаправляет весь трафик через удаленный сервер.

**Сценарий:** Безопасный веб-серфинг через зашифрованный канал.

```bash
ssh -D 8080 -C user@server
```
Настроив браузер или систему на использование SOCKS5-прокси `localhost:8080`, весь ваш трафик будет идти через `server`.

## Проброс графического интерфейса (X11 Forwarding)

Позволяет запускать графические (GUI) приложения с удаленного сервера, при этом их окна будут отображаться на вашем локальном рабочем столе.

```bash
# Подключение с пробросом X11 (-X или -Y для "доверенного" проброса)
# -C включает сжатие, что полезно для медленных сетей
ssh -XYC user@server

# После подключения можно запустить, например, текстовый редактор с GUI
gedit .bashrc
```

## Проброс аутентификации (Agent Forwarding)

Позволяет использовать ваш локальный `ssh-agent` для аутентификации на следующем сервере в цепочке (`server2`), не оставляя приватный ключ на промежуточном хосте (`server1`).

**Сценарий:** Вы подключаетесь с вашего ноутбука на `server1`, а с него — на `server2`, используя один и тот же ключ с ноутбука.

### Прямое подключение (`-A`)
```bash
# Подключаемся к первому серверу с пробросом агента
ssh -A user@server1

# С него подключаемся ко второму, аутентификация пройдет через ваш локальный агент
ssh user@server2
```
> **Внимание:** Используйте с осторожностью. Если `server1` скомпрометирован, злоумышленник может использовать сокет вашего агента для доступа к другим серверам.

### Безопасный проброс через Jump Host (`ProxyCommand` или `-J`)
Этот метод более безопасен, так как промежуточный хост (`jump-server`) просто перенаправляет TCP-трафик, не имея доступа к сессии и агенту.

**Настройка в `~/.ssh/config`:**
```ini
Host final-server
  HostName 10.1.1.2
  User final_user
  ProxyCommand ssh -W %h:%p jump_user@jump-server.com
```

**Использование флага `-J` (рекомендуется для современных клиентов):**
```bash
ssh -J jump_user@jump-server.com final_user@10.1.1.2
```

## Подключение через Jump Host (Bastion Host)

Узел-бастион, или Jump Host, — это специально выделенный и защищенный сервер, который служит единственной точкой входа во внутреннюю сеть извне. Это промежуточный сервер, через который безопасно осуществляется доступ к инфраструктуре, содержащей десятки других серверов, которые не должны быть напрямую доступны из интернета.

### Задачи и преимущества Jump Host:

1.  **Сокращает поверхность атаки:** Из интернета доступен только один хост, что значительно снижает риски.
2.  **Упрощает доступ:** Нет необходимости помнить множество IP-адресов и логинов для каждого внутреннего сервера.
3.  **Централизованный контроль:** На бастионе можно вести подробные логи всех подключений и действий пользователей, что критически важно для аудита и безопасности.

### Настройка подключения через ProxyJump

Современные версии OpenSSH позволяют легко настроить подключение через Jump Host с помощью директивы `ProxyJump` в файле `~/.ssh/config`.

**Пример конфигурации `~/.ssh/config`:**
```ini
Host bastion
    HostName 203.0.113.10  # IP-адрес или доменное имя вашего бастиона
    User admin            # Пользователь для подключения к бастиону

Host internal-*           # Шаблон для внутренних серверов (например, internal-01, internal-db)
    ProxyJump bastion     # Указываем, что доступ к этим хостам идет через "bastion"
    User root             # Пользователь для подключения к внутренним серверам
```

Теперь достаточно выполнить одну команду:
```bash
ssh internal-01
```
И соединение будет автоматически установлено через `bastion` без каких-либо дополнительных команд.

### Этапы соединения с использованием ProxyJump:

1.  Ваш SSH-клиент устанавливает SSH-соединение с `jump-host.com` (в данном случае, `bastion`).
2.  После успешной аутентификации на `jump-хосте`, клиент запрашивает у него создание прозрачного TCP-туннеля до целевого сервера (например, `internal-01`) на порт 22.
3.  Поверх этого туннеля ваш клиент инициирует второе, полностью независимое SSH-соединение уже непосредственно с целевым сервером.
4.  В результате вы получаете интерактивную сессию на целевом сервере, при этом `jump-хост` выступает исключительно в роли транспортного посредника, не имея прямого доступа к содержимому вашей сессии с целевым сервером.
