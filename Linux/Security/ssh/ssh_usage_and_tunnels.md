# Практическое использование SSH и туннелирование

**Достоверность: 10/10 (Актуально для OpenSSH 9.x)**

## Определения

**SSH-туннелирование (Port Forwarding)** — механизм создания защищенного канала для инкапсуляции TCP (иногда и L3) трафика произвольных сервисов внутри SSH-сессии.

**X11 Forwarding** — протокол отображения графического интерфейса удаленных приложений на локальном X-сервере.

**Agent Forwarding** — проброс сокета локального агента аутентификации на удаленный хост, позволяющий использовать локальные ключи для дальнейших переходов без их физического копирования.

**SSH Multiplexing** — повторное использование одного TCP-соединения для нескольких параллельных SSH-сессий.

## Базовые концепции

### Инкапсуляция трафика

SSH выступает в роли защитной оболочки для других протоколов (HTTP, VNC, SQL). Это позволяет обходить ограничения межсетевых экранов, безопасно работать через публичные сети и получать доступ к ресурсам, которые не должны быть открыты вовне.

### Типы проброса портов

| Тип | Флаг | Описание | Основной сценарий |
| :--- | :--- | :--- | :--- |
| **Локальный** | `-L` | Удаленный ресурс становится доступен на локальном порту | Доступ к БД внутри закрытой сети предприятия |
| **Удаленный** | `-R` | Локальный ресурс становится доступен на порту сервера | Показ локального веб-сервера заказчику через VPS |
| **Динамический** | `-D` | Создает локальный SOCKS5-прокси | Обход блокировок, скрытие реального IP браузера |
| **Сетевой (L3)** | `-w` | Создает TUN/TAP интерфейсы (требует root) | Полноценный VPN на базе SSH |

### Безопасность многоступенчатых подключений

При работе через промежуточные узлы (Jump Hosts) критически важно не оставлять ключи на серверах.

| Механизм | Описание | Безопасность |
| :--- | :--- | :--- |
| **Agent Forwarding (`-A`)** | Сокет агента доступен на удаленном сервере | **Рискованно**: root на сервере может использовать ваш ключ |
| **ProxyJump (`-J`)** | Трафик идет транзитом через промежуточный узел | **Рекомендуется**: промежуточный узел не видит данных |

Подробнее о настройке бастионов: [Конфигурация клиента SSH](./ssh_client_config.md#настройка-подключения-через-jump-host-proxyjump).

## Практические сценарии

### Базовое подключение и управление ключами

```bash
# Подключение на нестандартный порт
ssh -p 2222 user@host

# Явное указание ключа (если их много)
ssh -i ~/.ssh/id_ed25519_prod user@host

# Добавление ключа на сервер (автоматизация)
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@host
```

### Удаленное выполнение команд

```bash
# Запуск скрипта на удаленном сервере без открытия шелла
ssh user@server "bash -s" < local_script.sh

# Интерактивная работа с программами, требующими терминал (top, htop)
ssh -t user@server "htop"
```

### Локальный проброс портов (`-L`)

Схема: `Локальный_ПК:Порт` → `SSH_Server` → `Целевой_Ресурс:Порт`.

```bash
# Доступ к Postgres (5432) на сервере через локальный порт 5555
ssh -L 5555:localhost:5432 user@db-server -N

# Доступ к веб-интерфейсу внутреннего сервера через шлюз
ssh -L 8080:10.0.0.15:80 user@gateway.company.com
```

**Опции для туннелей:**
- `-N` — не выполнять удаленную команду (только туннель).
- `-f` — перейти в фоновый режим после аутентификации.

### Удаленный проброс портов (`-R`)

Схема: `SSH_Server:Порт` → `SSH_Client` → `Локальный_Ресурс:Порт`.

```bash
# Сделать локальный порт 3000 доступным на сервере как 8080
ssh -R 8080:localhost:3000 user@vps.public.com
```

**Важно:** Чтобы порт был доступен для всего интернета (а не только для `localhost` сервера), в `/etc/ssh/sshd_config` на сервере должна быть опция `GatewayPorts yes`.

### Динамический проброс (`-D`)

Создает универсальный прокси-сервер.

```bash
# Запуск SOCKS5 прокси на порту 1080
ssh -D 1080 user@remote-proxy -N
```
В настройках браузера/приложения укажите: `SOCKS5`, `127.0.0.1`, порт `1080`.

### Туннелирование сетевого уровня (VPN на SSH)

Требует прав `root` на обеих сторонах и включенной опции `PermitTunnel yes` в `sshd_config`.

```bash
# Создание TUN-интерфейсов tun0 на клиенте и tun1 на сервере
ssh -w 0:1 root@server

# Далее настраиваются IP-адреса и маршрутизация
# (на клиенте) ip addr add 10.1.1.2/30 dev tun0 && ip link set tun0 up
# (на сервере) ip addr add 10.1.1.1/30 dev tun1 && ip link set tun1 up
```

## Управление сессиями и стабильность

### Мультиплексирование (`ControlMaster`)

Позволяет открывать новые сессии мгновенно, используя существующее TCP-соединение. Критически важно для Ansible и при работе с множеством туннелей.

Настройка в `~/.ssh/config`:
```ssh
Host *
  ControlMaster auto
  ControlPath ~/.ssh/sockets/%r@%h-%p
  ControlPersist 10m
```
Подробнее: [Настройка SSH Multiplexing](./ssh_client_config.md#настройка-ssh-multiplexing).

### Управляющие последовательности (Escape Characters)

Позволяют управлять активной SSH-сессией без ее разрыва. Работают только сразу после нажатия `Enter`.

| Комбинация | Действие |
| :--- | :--- |
| `~.` | Немедленно разорвать соединение (полезно при зависании) |
| `~^Z` | Отправить SSH в бэкграунд (возврат через `fg`) |
| `~C` | Открыть командную строку SSH (можно добавить туннель на лету) |
| `~?` | Вывести справку по всем последовательностям |

**Пример добавления туннеля в активной сессии:**
1. Нажать `Enter`.
2. Ввести `~C`.
3. В появившейся строке `ssh>` ввести: `-L 8080:localhost:80`.

### Инструменты для поддержания туннелей

- **`autossh`** — обертка над SSH, которая мониторит соединение и автоматически перезапускает его при разрыве.
  ```bash
  autossh -M 0 -o "ServerAliveInterval 30" -o "ServerAliveCountMax 3" -L 5432:localhost:5432 user@host
  ```
- **Mosh (Mobile Shell)** — замена SSH для нестандартных условий (высокий latency, смена IP клиента). Использует UDP и предсказание ввода.
- **Eternal Terminal (ET)** — альтернатива Mosh, сохраняющая TCP-соединение при переподключении.

## Дополнительная информация

### Сравнение методов проброса трафика

| Критерий | SSH Tunnel | iptables/nftables | VPN (WireGuard) |
| :--- | :--- | :--- | :--- |
| **Уровень** | L4 (TCP) / L7 | L3 / L4 | L3 (Network) |
| **Сложность** | Низкая (User-space) | Средняя (Ядро) | Средняя |
| **Производительность** | Средняя (TCP-in-TCP) | Высокая | Высокая |
| **Права** | Обычный пользователь | Root | Root |

### Безопасность: рекомендации

1. **Ограничение портов**: Используйте `LocalForward` и `RemoteForward` только для конкретных IP (не `0.0.0.0`), если это не требуется.
2. **Таймауты**: Всегда настраивайте `ServerAliveInterval`, чтобы избежать "зависших" соединений.
3. **Аутентификация**: Отключайте `PasswordAuthentication` в пользу ключей.
