# Практическое использование SSH

## Определения

**SSH-туннелирование (Port Forwarding)** — механизм создания зашифрованного канала для перенаправления TCP-трафика произвольных сервисов между локальной и удалённой машинами.

**X11 Forwarding** — технология запуска GUI-приложений на удалённом сервере с отображением окон на локальном рабочем столе.

**Agent Forwarding** — использование локального `ssh-agent` для аутентификации на промежуточных серверах без хранения приватных ключей на них.

## Базовые концепции

### Инкапсуляция трафика

Трафик других протоколов (HTTP, VNC, БД) «оборачивается» в зашифрованное SSH-соединение. Это позволяет безопасно работать с незашифрованными сервисами и получать доступ к ресурсам закрытых сетей.

### Типы проброса портов

| Тип | Флаг | Описание | Сценарий |
| :--- | :--- | :--- | :--- |
| **Локальный** | `-L` | Проброс удалённого порта на локальную машину | Доступ к БД на сервере без открытия порта наружу |
| **Удалённый** | `-R` | Проброс локального порта на удалённый сервер | Временный доступ к локальному сервису извне |
| **Динамический** | `-D` | SOCKS5-прокси через сервер | Весь трафик идёт через удалённый узел |

### Безопасность многоступенчатых подключений

| Механизм | Принцип работы | Риски |
| :--- | :--- | :--- |
| **Agent Forwarding (`-A`)** | «Одалживает» локальный `ssh-agent` промежуточному серверу | Скомпрометированный узел может использовать сокет агента |
| **Jump Host (`-J`)** | Промежуточный сервер — только транспортный посредник | Минимальные — нет доступа к данным сессии |

**Рекомендация:** Предпочитать `ProxyJump` (`-J`) вместо Agent Forwarding (`-A`). Подробнее: [Конфигурация клиента SSH](./ssh_client_config.md#настройка-подключения-через-jump-host-proxyjump).

## Практические сценарии

### Базовое подключение

```bash
# Стандартное подключение
ssh user@host

# С указанием порта
ssh -p 2222 user@host

# С явным указанием ключа
ssh -i ~/.ssh/id_ed25519_project user@host
```

Если имя пользователя не указано — используется текущий локальный пользователь. Первое подключение всегда выполнять вручную для подтверждения отпечатка ключа. При изменении ключа хоста: `ssh-keygen -R <host>`.

### Удалённое выполнение команд

```bash
# Одноразовая команда
ssh user@server "ls -l /var/www"

# Интерактивная команда (требуется псевдотерминал)
ssh -t user@server "top"
```

### Передача файлов

Инструменты передачи файлов (`scp`, `rsync`, `sftp`, `sshfs`, `mosh`): [Инструменты командной строки SSH](./ssh_cli_tools.md).

### Локальный проброс (`-L`)

Пробрасываем удалённый порт на локальную машину.

```bash
# Доступ к БД Postgres на сервере (localhost на сервере)
ssh -L 5432:localhost:5432 user@host
# Теперь локальный `psql -h localhost` подключается к Postgres на сервере.

# Доступ к БД db.internal:5432 через gateway
ssh -L 5433:db.internal:5432 user@gateway
# Теперь localhost:5433 → db.internal:5432
```

```bash
# Доступ к админке на порту 8088 (фоновый режим)
ssh -L 8088:localhost:8088 user@remote_server -N -f
# Открыть http://localhost:8088 в браузере
```

**Опции:** `-N` — не выполнять команду (только туннель), `-f` — фоновый режим.

### Удалённый проброс (`-R`)

Пробрасываем локальный порт на удалённый сервер. Полезно, когда нужно дать временный доступ к локальному сервису.

```bash
# Коллега подключается к public_server:8080 → видит ваш localhost:3000
ssh -R 8080:localhost:3000 user@public_server
```

Для работы требуется `GatewayPorts yes` в `/etc/ssh/sshd_config` на сервере.

### Динамический проброс (`-D`)

SOCKS5-прокси через сервер, весь трафик идёт через него.

```bash
ssh -D 1080 user@server
# Настроить браузер на SOCKS5-прокси localhost:1080
```

### Постоянные туннели (`~/.ssh/config`)

Для постоянных туннелей и автоматизации параметров стабильности используйте `~/.ssh/config`:

```ssh
Host myserver
  HostName server_ip
  User user
  LocalForward 5432 localhost:5432
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

**Параметры стабильности:**

- **`ServerAliveInterval`** — держит туннель живым через NAT, отправляя пустые пакеты.
- **`ServerAliveCountMax`** — лимит попыток без ответа.

Без этих настроек туннель может «тихо умереть» через несколько минут бездействия из-за ограничений промежуточного сетевого оборудования.

### Проброс графического интерфейса (X11 Forwarding)

```bash
# Подключение с пробросом X11
ssh -X user@server

# Запуск GUI-приложения
gedit .bashrc
```

`-X` — надёжный режим (с ограничениями безопасности), `-Y` — доверенный (без ограничений, для приложений, не работающих в `-X`).

> **Предупреждение:** X11 Forwarding не рекомендуется включать на серверах без необходимости — создаёт дополнительные риски безопасности при компрометации удалённой системы.

### Agent Forwarding

```bash
# Подключение к первому серверу с пробросом агента
ssh -A user@server1

# С него — ко второму, используя ключ с локальной машины
ssh user@server2
```

Для включения в конфиге: `ForwardAgent yes` в блоке `Host`.

## Дополнительная информация

### Сравнение Agent Forwarding и Jump Host

| Критерий | Agent Forwarding | Jump Host |
| :--- | :--- | :--- |
| **Безопасность** | Средний риск: сокет агента доступен на промежуточном узле | Минимальный риск: только транспорт |
| **Удобство** | Один ключ для всей цепочки | Ключи должны быть на каждом узле (или один на Jump Host) |
| **Когда использовать** | Редко, при отсутствии альтернативы | Всегда, когда возможен доступ через бастион |

### Альтернатива на сетевом уровне: iptables DNAT

Для постоянного доступа с высокой нагрузкой — проброс портов через iptables на промежуточном сервере. Работает на L3/L4, не требует SSH на промежуточном узле. Подробнее: [Проброс SSH через iptables](../../../Networking/Concepts/nat/practical_scenarios.md#проброс-ssh-через-iptables-альтернатива-ssh-proxyjump).

### Туннелирование: резюме

| Сценарий | Команда |
| :--- | :--- |
| Доступ к внутренней БД | `ssh -L local:remote_db user@gateway` |
| Демонстрация localhost | `ssh -R public:localhost user@server` |
| Безопасный веб-серфинг | `ssh -D 8080 user@server` |
| Доступ через бастион | `ssh -J bastion user@internal` |
| X11-приложение | `ssh -X user@server` |
