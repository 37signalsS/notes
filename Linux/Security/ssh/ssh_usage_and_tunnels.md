# Использование SSH: команды, файлы и туннели

## Удалённое выполнение команд

SSH позволяет выполнять команды на удалённом сервере без открытия интерактивной сессии.

```bash
# Простое выполнение команды
ssh user@server "ls -l /var/www"

# С запросом псевдо-терминала (-t) для интерактивных команд, таких как top или htop
ssh -t user@server "top"
```

## Копирование файлов и монтирование ФС

### `scp` (Secure Copy)
Простая утилита для копирования файлов по SSH.

```bash
# Копирование локального файла на удаленный сервер
scp /path/to/local/file user@server:/path/to/remote/

# Копирование файла с удаленного сервера на локальную машину
scp user@server:/path/to/remote/file /path/to/local/
```

### `rsync` (Remote Sync)
Более мощная утилита для синхронизации файлов и директорий. Эффективнее `scp` при повторной синхронизации, так как передает только измененные части файлов.

```bash
# Синхронизация локальной директории с удаленной
# -a: режим архивирования (сохраняет права, владельца, временные метки)
# -v: подробный вывод
# -z: сжатие данных при передаче
# --progress: показывает прогресс
rsync -avz --progress /local/dir/ user@server:/remote/dir/
```

### `sshfs` (SSH File System)
Монтирует удаленную файловую систему локально, позволяя работать с удаленными файлами так, как если бы они были на вашем компьютере.

```bash
# Установка (для Debian/Ubuntu)
sudo apt-get install sshfs

# Создание точки монтирования
mkdir -p /media/remote_server

# Монтирование
# -o reconnect: автоматически переподключаться при обрыве связи
sshfs user@server:/remote/path /media/remote_server -o reconnect

# Отмонтирование
fusermount -u /media/remote_server
```

## SSH-туннелирование (проброс портов)

SSH-туннели создают защищенные каналы для перенаправления сетевого трафика между машинами.

### Локальный проброс портов (`-L`)
Позволяет получить доступ к сервису на удалённом сервере (или в его сети) через порт на вашей локальной машине.

**Сценарий:** Доступ к базе данных `db.internal.host:5432`, которая доступна только с машины `gateway`.

```bash
# ssh -L <локальный_порт>:<целевой_хост>:<целевой_порт> user@ssh_server
ssh -L 5432:db.internal.host:5432 user@gateway
```
Теперь, подключаясь к `localhost:5432` на вашей машине, вы на самом деле будете работать с базой данных на `db.internal.host`.

### Удаленный проброс портов (`-R`)
Позволяет "выставить" сервис с вашей локальной машины в интернет через порт на удаленном публичном сервере.

**Сценарий:** Показать коллеге веб-приложение, работающее на вашем `localhost:3000`.

```bash
# ssh -R <удалённый_порт>:<локальный_хост>:<локальный_порт> user@ssh_server
ssh -R 8080:localhost:3000 user@public_server
```
Теперь любой, кто зайдет на `public_server:8080`, увидит ваше веб-приложение.

### Динамический проброс портов (`-D`)
Создает SOCKS-прокси на вашей локальной машине, который перенаправляет весь трафик через удаленный сервер.

**Сценарий:** Безопасный веб-серфинг через зашифрованный канал.

```bash
ssh -D 8080 -C user@server
```
Настроив браузер или систему на использование SOCKS5-прокси `localhost:8080`, весь ваш трафик будет идти через `server`.

## Проброс графического интерфейса (X11 Forwarding)

Позволяет запускать графические (GUI) приложения с удаленного сервера, при этом их окна будут отображаться на вашем локальном рабочем столе.

```bash
# Подключение с пробросом X11 (-X или -Y для "доверенного" проброса)
# -C включает сжатие, что полезно для медленных сетей
ssh -XYC user@server

# После подключения можно запустить, например, текстовый редактор с GUI
gedit .bashrc
```

## Проброс аутентификации (Agent Forwarding)

Позволяет использовать ваш локальный `ssh-agent` для аутентификации на следующем сервере в цепочке (`server2`), не оставляя приватный ключ на промежуточном хосте (`server1`).

**Сценарий:** Вы подключаетесь с вашего ноутбука на `server1`, а с него — на `server2`, используя один и тот же ключ с ноутбука.

### Прямое подключение (`-A`)
```bash
# Подключаемся к первому серверу с пробросом агента
ssh -A user@server1

# С него подключаемся ко второму, аутентификация пройдет через ваш локальный агент
ssh user@server2
```
> **Внимание:** Используйте с осторожностью. Если `server1` скомпрометирован, злоумышленник может использовать сокет вашего агента для доступа к другим серверам.

### Безопасный проброс через Jump Host (`ProxyCommand` или `-J`)
Этот метод более безопасен, так как промежуточный хост (`jump-server`) просто перенаправляет TCP-трафик, не имея доступа к сессии и агенту.

**Настройка в `~/.ssh/config`:**
```ini
Host final-server
  HostName 10.1.1.2
  User final_user
  ProxyCommand ssh -W %h:%p jump_user@jump-server.com
```

**Использование флага `-J` (рекомендуется для современных клиентов):**
```bash
ssh -J jump_user@jump-server.com final_user@10.1.1.2
```

## Подключение через Jump Host (Bastion Host)

Узел-бастион — это специально выделенный и защищенный сервер, который служит единственной точкой входа во внутреннюю сеть извне.

**Общий вид команды:**
```bash
ssh -J user@jump-host.com user@target-server.internal
```

**Этапы соединения:**
1.  Ваш SSH-клиент устанавливает SSH-соединение с `jump-host.com`.
2.  После аутентификации на jump-хосте, клиент просит его создать прозрачный TCP-туннель до `target-server.internal` на порт 22.
3.  Поверх этого туннеля ваш клиент инициирует второе, полностью независимое SSH-соединение уже с целевым сервером.
4.  В результате вы получаете интерактивную сессию на `target-server.internal`, а jump-хост выступает лишь в роли транспортного посредника.
