# Трюки с SSH для продуктивности

SSH — это не только удалённый терминал, но и мощный инструмент для повышения эффективности работы. 

Рассмотрим три полезных фишки: мультиплексирование, проброс портов и ProxyJump.

## 1. Мультиплексирование соединений (ControlMaster)

Обычно при каждом новом SSH-подключении создаётся отдельное TCP-соединение, что влечёт за собой задержки и потребление ресурсов из-за необходимости повторного прохождения рукопожатия и аутентификации.

**ControlMaster** позволяет использовать одно главное соединение (мастер-канал) для нескольких последующих сессий SSH. Это значительно ускоряет подключения, поскольку повторные сессии просто используют уже установленный мастер-канал.

### Настройка

Добавьте следующие строки в файл конфигурации клиента SSH (`~/.ssh/config`):

```ini
Host *
    ControlMaster auto
    ControlPath ~/.ssh/cm-%r@%h:%p
    ControlPersist 10m
```

*   `ControlMaster auto`: Автоматически создает мастер-канал, если его нет, и использует его, если он уже существует.
*   `ControlPath ~/.ssh/cm-%r@%h:%p`: Определяет путь к файлу сокета, который используется для управляющего соединения. `%r@%h:%p` гарантирует уникальное имя сокета для каждого пользователя, хоста и порта.
*   `ControlPersist 10m`: Указывает, что мастер-канал должен оставаться открытым в фоновом режиме в течение 10 минут после закрытия последней зависимой сессии. Это позволяет быстро повторно подключиться без ожидания создания нового мастер-канала.

После настройки новые подключения к одному серверу будут использовать уже открытое соединение, а не создавать новое.

## 2. Проброс портов (Port Forwarding)

SSH умеет безопасно «прокидывать» порты, что позволяет получать доступ к сетевым сервисам, которые иначе были бы недоступны.

*   ### Локальный проброс портов (`-L`)
    Позволяет получить доступ к сервису на удалённом сервере (или в его внутренней сети) через порт на вашей локальной машине.

    ```bash
    ssh -L 8080:localhost:80 user@server
    ```
    После выполнения этой команды, обращаясь к `localhost:8080` на вашей локальной машине, вы будете перенаправлены на `server:80`.

*   ### Удалённый проброс портов (`-R`)
    Позволяет "выставить" сервис с вашей локальной машины в интернет через порт на удаленном публичном сервере.

    ```bash
    ssh -R 9090:localhost:3000 user@server
    ```
    Теперь любой, кто зайдет на `server:9090`, увидит сервис, работающий на вашем `localhost:3000`.

*   ### Динамический проброс портов (SOCKS Proxy, `-D`)
    Создаёт SOCKS5-прокси на вашей локальной машине, который перенаправляет весь трафик через удаленный сервер.

    ```bash
    ssh -D 1080 user@server
    ```
    После настройки браузера или другого приложения на использование SOCKS5-прокси на `localhost:1080`, весь их сетевой трафик будет идти через `server` по зашифрованному каналу.

## 3. ProxyJump (перескакивание через bastion)

Если целевой сервер доступен только через промежуточный `bastion-хост` (или `jump-хост`), **ProxyJump** предоставляет удобный способ подключиться к нему напрямую, минуя ручное создание туннелей.

### Настройка в `~/.ssh/config`

```ini
Host internal-server
    HostName internal.example.com
    User user
    ProxyJump bastion-user@bastion.example.com
```

Теперь достаточно одной команды `ssh internal-server`, и соединение пройдёт через `bastion.example.com` автоматически, прежде чем установится на `internal.example.com`. Это упрощает управление соединениями и повышает безопасность, так как не требует открытия дополнительных портов на `bastion-хосте` или сохранения на нём приватных ключей.
