# Управление персистентными сессиями SSH

## Определения

**Терминальный мультиплексор** — специализированное ПО, позволяющее создавать и управлять несколькими независимыми терминальными сессиями в рамках одного физического или сетевого подключения. Обеспечивает разделение экрана на панели (panes) и окна (windows).

**Персистентная сессия (Persistent Session)** — сеанс работы в терминале, который продолжает выполнение на стороне сервера даже после отключения клиента. Состояние процессов, переменные окружения и вывод терминала сохраняются для последующего подключения.

**Роуминг-клиенты (Mosh, ET)** — инструменты, обеспечивающие бесшовное переподключение при смене IP-адреса клиента или временной потере связи без использования мультиплексоров на прикладном уровне.

**SSH Multiplexing** — технология повторного использования одного TCP-соединения для нескольких SSH-сессий. Не следует путать с терминальными мультиплексорами.

## Базовые концепции

### Проблема разрыва SSH-соединения

При стандартном SSH-подключении дерево процессов выглядит следующим образом:
`sshd (master) → sshd (user) → bash → [command]`.

При разрыве соединения (timeout, потеря сети, закрытие ноутбука):
1. Процесс `sshd (user)` завершается.
2. Ядро посылает сигнал `SIGHUP` (Signal Hang Up) всем дочерним процессам.
3. По умолчанию процессы, получившие `SIGHUP`, завершаются.

### Роль systemd-logind

В современных дистрибутивах (Debian 9+, RHEL 7+, Ubuntu 16.04+) демон `systemd-logind` управляет жизненным циклом пользовательских процессов.

**Параметр KillUserProcesses:**
Если в `/etc/systemd/logind.conf` установлено `KillUserProcesses=yes`, система принудительно завершает все процессы пользователя (включая `tmux` и `screen`) сразу после выхода последнего сеанса.

**Настройка персистентности:**
1. **Проверка статуса пользователя:**
   ```bash
   loginctl user-status $(whoami)
   # → Linger: no (процессы будут убиты при выходе)
   ```
2. **Включение режима Linger:**
   ```bash
   sudo loginctl enable-linger <username>
   ```
   Это заставляет систему запускать пользовательский менеджер сервисов при загрузке и не завершать его процессы после logout.

### Сравнение мультиплексоров

| Характеристика | `tmux` | `screen` | `Zellij` |
| :--- | :--- | :--- | :--- |
| **Язык разработки** | C | C | Rust |
| **Управление** | Префикс + клавиша | Префикс + клавиша | Модальное / шорткаты |
| **Разделение панелей** | Да (любое) | Ограниченно | Да (авто-лэйауты) |
| **Скриптуемость** | Высокая | Низкая | Плагины (WASM) |
| **Статус** | Стандарт де-факто | Legacy | Современная замена |

## Практические сценарии

### tmux (Terminal Multiplexer)

Наиболее популярный инструмент с клиент-серверной архитектурой.

```bash
# Установка
sudo apt install tmux     # → [OK]

# Запуск именованной сессии
tmux new -s work_session

# Список активных сессий
tmux ls
# → work_session: 1 windows (created Sat Aug  8 14:30:00 2026)

# Подключение к существующей сессии
tmux attach -t work_session

# Подключение с принудительным отключением других клиентов (исправляет размер экрана)
tmux attach -d -t work_session

# Уничтожение сессии
tmux kill-session -t work_session
```

**Основные горячие клавиши (префикс `Ctrl+B`):**

| Комбинация | Действие |
| :--- | :--- |
| `Ctrl+B, D` | Отключиться (Detach) — сессия останется в фоне |
| `Ctrl+B, %` | Разделить панель вертикально |
| `Ctrl+B, "` | Разделить панель горизонтально |
| `Ctrl+B, C` | Создать новое окно |
| `Ctrl+B, ,` | Переименовать текущее окно |
| `Ctrl+B, [` | Режим копирования (скролл истории) |

### GNU Screen

Используется преимущественно на старых системах или там, где `tmux` недоступен.

```bash
# Запуск
screen -S backup_task

# Список сессий
screen -ls
# → There is a screen on: 1234.backup_task (Detached)

# Подключение
screen -r backup_task

# Горячие клавиши (префикс Ctrl+A):
# Ctrl+A, D — Detach
# Ctrl+A, C — Создать окно
# Ctrl+A, K — Убить окно
```

### Zellij

Современная альтернатива на Rust с интуитивным интерфейсом и встроенными подсказками.

```bash
# Запуск
zellij

# Основные особенности:
# - Панель подсказок в нижней части экрана.
# - Поддержка мыши «из коробки».
# - Режимы: Locked, Pane, Tab, Resize, Scroll.
```

### Роуминг-клиенты (Mosh и ET)

Инструменты для работы в условиях нестабильной сети.

#### Mosh (Mobile Shell)
Использует UDP и State Synchronization Protocol.
- **Плюсы:** Мгновенный отклик (локальное эхо), выживает при смене IP.
- **Минусы:** Требует открытия UDP портов (60000-61000).
- Подробнее: [Принцип работы Mosh](./ssh_cli_tools.md#принцип-работы-mosh-state-synchronization-protocol).

#### Eternal Terminal (ET)
Сохраняет TCP-соединение через прокси-сервис.
- **Плюсы:** Поддерживает проброс портов (SSH Port Forwarding).
- **Минусы:** Требует установки демона на сервере.

## Продвинутые сценарии

### Перехват запущенного процесса (reptyr)

Если команда была запущена вне мультиплексора и связь может разорваться, её можно переместить в `tmux`.

```bash
# 1. Найти PID процесса
pgrep -l my_script # → 4567 my_script

# 2. Приостановить процесс в текущем терминале
Ctrl+Z
bg

# 3. Отвязать от текущего shell
disown my_script

# 4. Зайти в tmux и перехватить
tmux
reptyr 4567
```
Подробнее: [Утилита reptyr](../../Diagnostics/Processes/reptyr.md).

### Восстановление сессий после перезагрузки сервера

Для `tmux` рекомендуется использовать менеджер плагинов **TPM** и плагин **tmux-resurrect**.

В `~/.tmux.conf`:
```tmux
set -g @plugin 'tmux-plugins/tpm'
set -g @plugin 'tmux-plugins/tmux-resurrect'
set -g @plugin 'tmux-plugins/tmux-continuum'

set -g @continuum-restore 'on' # Автоматическое восстановление
```

### Совместная работа (Pair Programming)

1. **tmate** — форк tmux, который мгновенно предоставляет публичную (или приватную) ссылку для доступа к вашему терминалу.
   ```bash
   tmate
   # → ssh session: ssh user@tmate.io/unique-id
   ```
2. **tmux Shared Session** — использование общего сокета.
   ```bash
   # Создание сессии с общим доступом
   tmux -S /tmp/shared_socket new -s pair_prog
   # Выдача прав на сокет другому пользователю
   chmod 777 /tmp/shared_socket
   # Подключение второго пользователя
   tmux -S /tmp/shared_socket attach
   ```

### systemd-run для фоновых задач

Если нужен только запуск процесса в фоне с гарантией выживания после logout, без интерактивного терминала.

```bash
systemd-run --user --scope ./long_task.sh
# → Running scope as unit: run-u123.scope
```

## Дополнительная информация

### Рекомендуемый workflow

1. Подключиться по SSH.
2. Проверить наличие сессий: `tmux ls`.
3. Создать новую или подключиться к существующей: `tmux a -t main || tmux new -s main`.
4. Для критических задач (обновление ОС) — использование мультиплексора обязательно.
