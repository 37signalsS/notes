# Управление персистентными сессиями SSH

## Определения

**Терминальный мультиплексор** — программа для создания и управления несколькими независимыми терминальными сессиями в рамках одного окна или SSH-подключения. Позволяет разделять экран на панели и окна.

**Персистентная сессия (Persistent Session)** — терминальная сессия, продолжающая выполняться на сервере после отключения клиента. Сохраняет запущенные процессы и состояние терминала при разрывах сети или плановом отключении.

**Роуминг-клиенты (Mosh, ET)** — специализированные инструменты, обеспечивающие бесшовное переподключение при смене IP-адреса клиента или длительной потере связи без использования мультиплексоров.

## Базовые концепции

### Проблема разрыва SSH-соединения

При стандартном SSH-подключении все процессы являются дочерними по отношению к процессу SSH-сессии. При разрыве соединения (таймаут, потеря сети) родительский процесс `sshd` завершается, посылая сигнал `SIGHUP` всем дочерним задачам, что приводит к их остановке.

### Роль systemd-logind

В современных дистрибутивах (Debian 9+, RHEL 7+, Ubuntu 16.04+) по умолчанию может быть включен параметр `KillUserProcesses=yes`. Это означает, что при выходе последнего SSH-сеанса пользователя система принудительно завершает все его процессы, включая `tmux` и `screen`.

Для обеспечения реальной персистентности:
1.  **Глобально:** В файле `/etc/systemd/logind.conf` установить `KillUserProcesses=no`.
2.  **Для конкретного пользователя:**
    ```bash
    sudo loginctl enable-linger <username>
    ```
    Это заставляет систему запускать пользовательский менеджер сервисов при загрузке и не завершать его после выхода пользователя.

### Принцип работы мультиплексоров

Мультиплексор создаёт сессию на сервере независимо от SSH-подключения:

1. Подключение к серверу по SSH.
2. Запуск мультиплексора (`screen` или `tmux`) — создаётся отдельная серверная сессия.
3. Команды выполняются внутри сессии мультиплексора.
4. **Detach** — отключение от сессии (сессия продолжает работать в фоне).
5. **Attach** — повторное подключение к сессии с полным восстановлением состояния.

### Сравнение `screen` и `tmux`

| Характеристика | `screen` | `tmux` |
| :--- | :--- | :--- |
| **Лицензия** | GPL | ISC |
| **Разделение панелей** | Горизонтальное | Горизонтальное + вертикальное |
| **Скриптуемость** | Ограниченная | Полноценный API и конфиг |
| **Конфигурация** | `~/.screenrc` | `~/.tmux.conf` |
| **Клиент-серверная модель** | Да | Да (более гибкая) |
| **Распространённость** | Везде (Legacy) | Стандарт де-факто |
| **Статус** | Поддержка | Активная разработка |

**Рекомендация:** Для новых проектов предпочтителен `tmux` — более гибкое управление панелями, лучшая скриптуемость, активное сообщество.

## Практические сценарии

### GNU Screen

```bash
# Установка
sudo apt install screen    # Debian/Ubuntu
sudo dnf install screen    # RHEL/CentOS/Rocky

# Запуск именованной сессии
screen -S my_session

# Отключение (detach): Ctrl+A, затем D

# Список сессий
screen -ls

# Подключение к сессии
screen -r my_session
# Если сессия одна:
screen -r

# Подключение к занятой сессии (отключить другого клиента)
screen -d -r my_session

# Завершение сессии изнутри
exit

# Принудительное завершение извне
screen -X -S my_session quit
```

**Горячие клавиши (префикс `Ctrl+A`):**

| Комбинация | Действие |
| :--- | :--- |
| `Ctrl+A, C` | Создать новое окно |
| `Ctrl+A, N` | Следующее окно |
| `Ctrl+A, P` | Предыдущее окно |
| `Ctrl+A, "` | Список окон |
| `Ctrl+A, D` | Отключиться (detach) |
| `Ctrl+A, K` | Убить текущее окно |

### tmux

```bash
# Установка
sudo apt install tmux     # Debian/Ubuntu
sudo dnf install tmux     # RHEL/CentOS/Rocky

# Запуск именованной сессии
tmux new -s my_session

# Отключение (detach): Ctrl+B, затем D

# Список сессий
tmux ls

# Подключение к сессии
tmux attach -t my_session

# Подключение к занятой сессии
tmux attach -d -t my_session

# Завершение сессии изнутри
exit

# Уничтожение сессии извне
tmux kill-session -t my_session
```

**Горячие клавиши (префикс `Ctrl+B`):**

| Комбинация | Действие |
| :--- | :--- |
| `Ctrl+B, %` | Вертикальное разделение |
| `Ctrl+B, "` | Горизонтальное разделение |
| `Ctrl+B, Стрелки` | Навигация между панелями |
| `Ctrl+B, C` | Создать новое окно |
| `Ctrl+B, N` | Следующее окно |
| `Ctrl+B, P` | Предыдущее окно |
| `Ctrl+B, D` | Отключиться (detach) |
| `Ctrl+B, [` | Режим копирования/скролла |

### Конфигурация tmux

Пример `~/.tmux.conf`:

```ini
# Изменить префикс на Ctrl+A
set -g prefix C-a
unbind C-b
bind C-a send-prefix

# Нумерация окон с 1
set -g base-index 1

# Включить поддержку мыши
set -g mouse on

# Увеличить буфер скролла
set -g history-limit 50000

# Быстрое переименование окон
set -g allow-rename on
```

Применить настройки без перезапуска: `tmux source-file ~/.tmux.conf`.

### Современные альтернативы (Roaming Clients)

Когда мультиплексор избыточен или требуется работа в условиях крайне нестабильной сети (поезда, самолеты, мобильный интернет).

#### Mosh (Mobile Shell)

Обеспечивает «локальное эхо» и мгновенное восстановление при смене IP.
- **Особенности:** Использует UDP (порты 60000-61000), требует установки и на клиенте, и на сервере.
- **Подключение:** `mosh user@server`
- Подробнее: [Mosh в инструментах SSH](./ssh_cli_tools.md#принцип-работы-mosh-state-synchronization-protocol).

#### Eternal Terminal (ET)

Альтернатива Mosh, которая сохраняет полноценное TCP-соединение и поддерживает проброс портов (SSH Port Forwarding).
- **Особенности:** Работает через TCP (порт 2022 по умолчанию), не требует открытия широкого диапазона UDP-портов.
- **Подключение:** `et user@server:2022`

### Продвинутые сценарии

#### Восстановление сессий после перезагрузки сервера

По умолчанию `tmux` и `screen` теряют все окна при перезагрузке ОС сервера. Для решения проблемы в `tmux` используется плагин **tmux-resurrect** совместно с **tmux-continuum**.

1. **Установка (через TPM):** Добавить в `~/.tmux.conf`:
   ```tmux
   set -g @plugin 'tmux-plugins/tmux-resurrect'
   set -g @plugin 'tmux-plugins/tmux-continuum'
   set -g @continuum-restore 'on' # Автовосстановление при запуске tmux
   ```
2. **Результат:** `tmux` будет сохранять список окон и запущенные в них процессы каждые 15 минут.

#### Перенос запущенного процесса в мультиплексор (reptyr)

Если вы запустили долгую задачу (например, `rsync` или `apt upgrade`) в обычном SSH и забыли открыть `tmux`, её можно «спасти».

```bash
# 1. Приостановить процесс
Ctrl+Z
# 2. Узнать PID
jobs -l
# 3. Отвязать от текущего шелла
disown <command>
# 4. Войти в tmux и забрать процесс
tmux
reptyr <PID>
```
Подробнее: [Использование reptyr](../../Diagnostics/Processes/reptyr.md).

## Дополнительная информация

### Связь с мультиплексированием SSH

Не путать терминальные мультиплексоры (`screen`, `tmux`) с **SSH Multiplexing** (`ControlMaster`) — это разные механизмы:

| | Терминальный мультиплексор | SSH Multiplexing |
| :--- | :--- | :--- |
| **Назначение** | Сохранение сессии при разрыве, управление окнами | Ускорение повторных SSH-подключений |
| **Уровень** | Прикладной (терминал) | Транспортный (TCP-соединение) |
| **Инструменты** | `screen`, `tmux` | `ControlMaster`, `ControlPath` |

Подробнее: [SSH Multiplexing](./ssh_client_config.md#настройка-ssh-multiplexing).

### Рекомендуемый workflow

1. Подключиться к серверу по SSH.
2. Открыть `tmux` (или `screen`).
3. Выполнять задачи внутри tmux-сессии.
4. При необходимости отключиться — `Ctrl+B, D`.
5. Для долгосрочных задач настроить keep-alive в `~/.ssh/config`.

### nohup и disown — альтернативы для одиночных команд

Для сохранения одного процесса без полноценного мультиплексора:

```bash
# Запуск с игнорированием SIGHUP
nohup ./long_script.sh &

# «Отвязать» уже запущенный процесс от терминала
Ctrl+Z
bg
disown
```

Ограничение: нет интерактивного доступа к процессу. Для интерактивной работы — только мультиплексор.
