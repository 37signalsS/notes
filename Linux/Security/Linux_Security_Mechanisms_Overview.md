# Обзор механизмов безопасности в Linux

Этот документ представляет собой высокоуровневый обзор ключевых механизмов и концепций безопасности в операционной системе Linux.

## Модели контроля доступа

### Discretionary Access Control (DAC)
Стандартная модель прав в Linux, основанная на **правах доступа к файлам** (`rwx`) для владельца, группы и остальных. Подробно рассмотрена в заметке [Linux File Permissions](./Concepts/Linux_File_Permissions.md).

### Mandatory Access Control (MAC)
Более строгая модель, где права доступа применяются на основе общесистемных политик, которые не могут быть изменены пользователями. Реализуется через фреймворк **Linux Security Modules (LSM)**.

- **[SELinux](./Mechanisms/SELinux.md):** Реализация MAC, основанная на метках (контекстах безопасности) для процессов и объектов. Применяет детальные политики, разработанные для максимальной изоляции.

- **[AppArmor](./Mechanisms/AppArmor.md):** Реализация MAC, основанная на путях к файлам. Считается более простой в настройке по сравнению с SELinux.

## Изоляция и ограничение процессов

- **[Capabilities](./Mechanisms/Capabilities.md):** Механизм, который разделяет всемогущество `root` на отдельные, гранулярные привилегии, позволяя процессам работать с минимально необходимым набором прав.

- **[Seccomp](./Mechanisms/Seccomp.md):** Фильтр системных вызовов, который ограничивает набор операций, доступных процессу. Является ключевым элементом в изоляции контейнеров.

- **Изоляция процессов (`hidepid`):** Опция монтирования `/proc`, которая скрывает процессы других пользователей, предотвращая сбор информации о запущенных в системе сервисах.

## Защита ядра и памяти

- **[KASLR (Kernel Address Space Layout Randomization)](./Mechanisms/KASLR.md):** Механизм, который случайным образом размещает код ядра в памяти при каждой загрузке, усложняя эксплуатацию уязвимостей ядра.

- **ASLR (Address Space Layout Randomization):** Аналогичный механизм для пользовательских приложений, который рандомизирует расположение стека, кучи и библиотек в памяти.

## Аудит и мониторинг

- **[Проверка целостности файлов](./Concepts/File_Integrity_Checking.md):** Методы и инструменты (такие как `AIDE`, `debsums`, `rpm -Va`) для проверки того, что системные файлы не были изменены злоумышленником.

- **`auditd`:** Подсистема аудита ядра, позволяющая отслеживать и записывать события, связанные с безопасностью, такие как доступ к файлам и системные вызовы.

- **[Fail2Ban](./Tools/Fail2Ban.md):** Инструмент для автоматической защиты сервисов от атак методом перебора (brute-force).
