# Управление пользователями и группами в Linux

Этот документ описывает основные концепции и команды для управления пользователями и группами в операционных системах Linux.

## 1. Определения

- **Пользователь (User):** Учетная запись, позволяющая человеку или процессу взаимодействовать с системой. Каждому пользователю присваивается уникальный идентификатор (UID).
- **Группа (Group):** Механизм для объединения пользователей с целью предоставления им общих прав доступа к файлам и ресурсам. Каждой группе присваивается уникальный идентификатор (GID).
- **Суперпользователь (root):** Специальный пользователь с UID 0, обладающий неограниченными правами в системе.

## 2. Основные концепции

### Файлы конфигурации

- **/etc/passwd:** Содержит основную информацию о пользователях (имя, UID, GID, домашний каталог, оболочка).
- **/etc/shadow:** Содержит хэши паролей пользователей и информацию об истечении срока их действия. Доступен для чтения только пользователю `root`.
- **/etc/group:** Содержит информацию о группах и их членах.

### Типы групп

- **Первичная группа (Primary Group):** Основная группа пользователя, которая назначается при создании файлов.
- **Дополнительные группы (Supplementary Groups):** Группы, в которые пользователь может быть добавлен для получения дополнительных прав.

## 3. Практические сценарии

### Управление пользователями

- `useradd`: Создание нового пользователя.
- `usermod`: Изменение атрибутов существующего пользователя.
- `userdel`: Удаление пользователя.
- `passwd`: Изменение пароля пользователя.

### Управление группами

- `groupadd`: Создание новой группы.
- `groupmod`: Изменение атрибутов группы.
- `groupdel`: Удаление группы.
- `gpasswd`: Управление членами группы.

## 4. Продвинутые детали

### Повышение привилегий: `su` против `sudo`

Для выполнения административных задач, требующих прав суперпользователя, в Linux используются две основные команды: `su` и `sudo`. Хотя обе они служат для повышения привилегий, они работают по-разному и имеют разные сценарии использования.

#### `su` (Substitute User)

Команда `su` позволяет "переключиться" на другого пользователя, по умолчанию — на `root`.

-   **Как работает:** `su` запускает новую оболочку (shell) от имени целевого пользователя. Для переключения на `root` требуется ввести **пароль пользователя `root`**.
-   **Преимущества:**
    -   Простота использования.
-   **Недостатки:**
    -   **Безопасность:** Требует разглашения пароля `root` всем администраторам, что является плохой практикой. Если один из администраторов уходит, необходимо менять пароль `root` и сообщать его всем остальным.
    -   **Аудит:** `su` не регистрирует, какие именно команды выполнялись от имени `root`. В системных логах будет видно только, что пользователь `user` переключился на `root`, но не то, что он делал после этого.

#### `sudo` (Superuser Do)

Команда `sudo` позволяет выполнить одну или несколько команд от имени другого пользователя (по умолчанию `root`), не переключая сеанс полностью.

-   **Как работает:** Пользователь вводит свою команду, предваряя ее `sudo` (например, `sudo apt update`). Система запрашивает **пароль текущего пользователя**, а не `root`.
-   **Конфигурация:** Полномочия `sudo` настраиваются в файле `/etc/sudoers` (редактировать который следует только с помощью команды `visudo`). Этот файл позволяет очень гибко настроить:
    -   Кто из пользователей или групп может использовать `sudo`.
    -   Какие именно команды им разрешено выполнять.
    -   С каких хостов они могут это делать.
    -   Нужно ли запрашивать пароль для определенных команд.
-   **Преимущества:**
    -   **Безопасность:** Нет необходимости делиться паролем `root`. Пользователи используют свои собственные пароли.
    -   **Гранулярный контроль:** Можно предоставить пользователю права только на те команды, которые ему необходимы для работы (принцип наименьших привилегий).
    -   **Аудит:** Каждая команда, выполненная через `sudo`, подробно протоколируется в системных логах (обычно в `/var/log/auth.log` или `/var/log/secure`), включая имя пользователя, время и саму команду.

#### Сравнение и рекомендации

| Характеристика | `su` | `sudo` |
| :--- | :--- | :--- |
| **Требуемый пароль** | Пароль `root` | Пароль пользователя |
| **Уровень доступа** | Полный доступ (новая оболочка `root`) | Ограниченный (только разрешенные команды) |
| **Аудит (логирование)**| Только факт переключения | Каждая выполненная команда |
| **Конфигурация** | Не требуется | Гибкая настройка в `/etc/sudoers` |

**Рекомендация:** В подавляющем большинстве случаев **следует использовать `sudo`**. Это более безопасный, контролируемый и легко аудируемый способ повышения привилегий. Команду `su` стоит использовать только в редких случаях, например, для восстановления системы, когда `sudo` недоступен. На многих современных системах (например, Ubuntu) учетная запись `root` по умолчанию заблокирована (у нее нет пароля), и все административные задачи выполняются исключительно через `sudo`.
