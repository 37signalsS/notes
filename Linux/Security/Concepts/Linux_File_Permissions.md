# Права доступа, атрибуты и привилегии в Linux

## Определения

*   **Права доступа (Permissions):** Основной механизм безопасности в Linux, определяющий, какие действия (`чтение`, `запись`, `выполнение`) и кто (`владелец`, `группа`, `остальные`) может выполнять над файлом или директорией.
*   **Специальные права (Special Permissions):** Расширенные права (`SUID`, `SGID`, `Sticky Bit`), которые изменяют стандартное поведение системы при доступе к файлам и директориям, часто для временного повышения привилегий.
*   **ACL (Access Control Lists):** Расширенный механизм прав, который позволяет назначать разрешения для любого произвольного пользователя или группы, дополняя стандартную модель «владелец-группа-остальные».
*   **Атрибуты файлов (File Attributes):** Флаги, устанавливаемые на уровне файловой системы (например, флаг `immutable`), которые могут запрещать определённые действия с файлом даже для суперпользователя `root`.

## Основные понятия

### 1. Стандартная модель прав доступа (Discretionary Access Control)

Система прав строится на трех китах: для кого и какие права. Суперпользователь `root` (UID 0) является исключением и имеет неограниченный доступ к системе.

#### Субъекты доступа (для кого)

-   **Владелец (User):** Пользователь, создавший файл. Имеет полный контроль.
-   **Группа (Group):** Группа пользователей с одинаковыми правами доступа.
-   **Остальные (Others):** Все остальные пользователи системы.

#### Порядок применения прав

Система проверяет права доступа в строгой последовательности. Как только находится соответствие для пользователя, проверка останавливается.

1.  **Сначала Владелец (User):** Если текущий пользователь является владельцем файла, применяются **только права владельца**. Права группы и всех остальных игнорируются.
2.  **Затем Группа (Group):** Если пользователь не является владельцем, но входит в группу, которой принадлежит файл, применяются **только права группы**. Права для остальных игнорируются.
3.  **В конце Остальные (Others):** Если пользователь не является ни владельцем, ни членом группы, к нему применяются права для всех остальных.

#### Типы прав (какие права)

| Право | Для файла | Для директории |
| :--- | :--- | :--- |
| `r` (read) | Позволяет просматривать содержимое файла. | Позволяет читать информацию об именах файлов и подкаталогов, хранящихся в директории (т.е. выполнять команду `ls`). |
| `w` (write) | Позволяет изменять содержимое файла. | Позволяет создавать, удалять и переименовывать файлы в этом каталоге. |
| `x` (execute) | Позволяет запускать файл как программу или скрипт. | Позволяет войти в директорию (`cd`) и получить доступ к inode её файлов. |

> **Важное замечание о взаимосвязи прав:**
> *   **Для файлов:** Право на выполнение (`x`) практически бесполезно без права на чтение (`r`). Чтобы запустить скрипт или бинарный файл, системе необходимо сначала прочитать его содержимое.
> *   **Для директорий (принцип "проходимости"):** Право на выполнение (`x`) является ключевым. Оно позволяет "войти" в директорию и, таким образом, получить доступ к inode хранящихся в ней файлов и подкаталогов.
>     *   **Если убрать право `x` (директория "непроходима"):**
>         *   **Сценарий 1: Есть `r`, но нет `x`.** Можно получить список имен файлов в директории (`ls`), но нельзя получить никакой другой информации о них (размер, владелец, права через `ls -l`) и нельзя получить доступ к их содержимому, так как для доступа к inode требуется право `x`.
>         *   **Сценарий 2: Есть `w`, но нет `x`.** Право на запись (`w`) также становится бесполезным, так как невозможно создавать или удалять файлы, не имея доступа к inode директории.
>         *   **Итог:** Без права `x` любые другие права на директорию практически теряют смысл.
>     *   **Если есть `x`, но нет `r`:** Нельзя просмотреть список содержимого директории (`ls` не сработает). Однако, зная точное имя файла, можно получить доступ к самому файлу и его метаданным (например, с помощью `stat` или `cat`, если права на файл это позволяют).

#### Приоритет прав директории над правами файла
Удаление и переименование файла — это операция **записи в директорию**, а не в сам файл. Если у пользователя есть право `w` на директорию, он может удалить из неё любой файл, даже если файл принадлежит `root` и имеет права `000`. 
*(Это правило не действует, если на директорию установлен [Sticky Bit](#4-специальные-права-доступа)).*

### 2. Представление прав

Права можно представить в двух форматах, которые отображаются командой `ls -l`.

*   **Символьное представление:** `-rwxrw-r--`
    *   `rwx` (Владелец): чтение, запись, выполнение.
    *   `rw-` (Группа): чтение, запись.
    *   `r--` (Остальные): только чтение.
*   **Числовое (восьмеричное) представление:**
    | Число | Права | Описание |
    | :--- | :--- | :--- |
    | `7` | `rwx` | Полный доступ |
    | `6` | `rw-` | Чтение и запись |
    | `5` | `r-x` | Чтение и выполнение |
    | `4` | `r--` | Только чтение |
    | `2` | `-w-` | Только запись |
    | `1` | `--x` | Только выполнение |
    | `0` | `---` | Нет доступа |
    > **Пример:** Права `rwxr-xr--` в числовом виде будут `754`.

### 3. Маска прав по умолчанию (`umask`)
Когда в системе создается новый файл или директория, их права доступа определяются с помощью **маски создания файлов пользователя (umask)**. `umask` — это восьмеричное значение, которое определяет, какие биты прав **не должны быть установлены**.

-   **Базовые права для файлов:** `666` (`rw-rw-rw-`)
-   **Базовые права для директорий:** `777` (`rwxrwxrwx`)

Итоговые права вычисляются путем "вычитания" значения `umask` из базовых прав.

**Пример:** `umask 0022`
-   **Для нового файла:** `666` - `022` = `644` (`rw-r--r--`).
-   **Для новой директории:** `777` - `022` = `755` (`rwxr-xr-x`).

> **Пример для повышенной безопасности:**
> Установка `umask 077` гарантирует, что только владелец будет иметь доступ к новым файлам (`600`) и директориям (`700`). Это хорошая практика для домашних каталогов пользователей и для `root`.

### 4. Специальные права доступа

#### SUID (Set User ID)
-   **Назначение:** Устанавливается на **бинарные исполняемые файлы**. Позволяет любому пользователю выполнять файл с правами **владельца** этого файла.
-   **Обозначение:** `s` (вместо `x`) в секции прав владельца (`-rwsr-xr-x`). Если у владельца нет права на выполнение (`x`), то бит отображается как заглавная `S` (`-rwSr-xr-x`), что обычно указывает на ошибку конфигурации.
-   **Пример:** Утилита `passwd`. Обычный пользователь запускает ее, и она временно получает права `root` (владельца файла), чтобы изменить системный файл `/etc/shadow`.
-   **Важное замечание по безопасности:** SUID-бит **намеренно игнорируется на скриптах** (`.sh`, `.py` и т.д.). Это сделано для предотвращения эскалации привилегий. Ядро системы запускает не сам скрипт, а его интерпретатор (`/bin/bash`), и  вследствии передачи SUID-прав интерпретатор запускаеться с правами root (любой пользователь мог бы написать скрипт, поставить на него SUID-бит и получить root-шелл).

#### SGID (Set Group ID)
-   **Для файлов:** Работает аналогично SUID, но файл выполняется с правами **группы-владельца**.
-   **Для директорий (основное применение):** Все новые файлы и поддиректории, созданные в этой директории, автоматически наследуют ее группу.
-   **Обозначение:** `s` (вместо `x`) в секции прав группы (`-rwxr-sr-x`). Аналогично SUID, заглавная `S` (`-rwxr-Sr-x`) указывает на отсутствие права `x` у группы.

#### Sticky Bit
-   **Назначение:** В современных системах используется **только для директорий**. Если на директорию установлен Sticky Bit, удалить или переименовать файл в ней может только **владелец файла**, **владелец директории** или `root`.
-   **Кто может установить:** Право на изменение этого атрибута (`chmod +t`) есть только у **владельца директории** и у **суперпользователя (root)**.
-   **Обозначение:** `t` в поле прав выполнения для остальных (`drwxrwxrwt`). Если у "остальных" нет права `x`, бит отображается как заглавная `T` (`drwxrwxrwT`).
-   **Пример:** Директория `/tmp`, где все пользователи могут создавать файлы, но удалять могут только свои.

### 5. Списки контроля доступа (ACL)

ACL — это расширенный механизм прав, который позволяет назначать разрешения для любого пользователя или группы, дополняя стандартные права. Если для файла установлены расширенные права, в выводе `ls -l` появится знак `+`.

-   **ACL по умолчанию (Default ACL):** Особая возможность ACL для директорий. Все новые файлы и поддиректории, созданные внутри неё, будут автоматически наследовать эти права.
-   **Маска (Mask):** Маска в ACL определяет **максимально возможные права** для всех именованных пользователей и групп. Она работает как ограничитель. Например, если пользователю `alice` даны права `rw-`, а маска `r--`, то эффективные права `alice` будут только `r--`.

### 6. Атрибут неизменяемости (`immutable`)

Файл или директория с флагом `i` становятся "неприкосновенными". Их нельзя удалить, переименовать, изменить или создавать на них жёсткие ссылки. Даже пользователь `root` не сможет выполнить эти действия, пока флаг не будет снят.

### 7. Временные метки файла (`stat`)

Команда `stat` предоставляет подробную метаинформацию о файле из его inode.

-   **`Access` (atime):** Время **последнего доступа** к файлу (чтения). В современных системах обновляется с задержкой (опция `relatime`) для повышения производительности.
-   **`Modify` (mtime):** Время **последней модификации содержимого** файла. Это та дата, которую показывает `ls -l`.
-   **`Change` (ctime):** Время **последнего изменения метаданных** (статуса) файла: прав (`chmod`), владельца (`chown`), имени (`mv`). `ctime` обновляется всегда, когда меняется `mtime`.
-   **`Birth`:** Время "рождения" файла. Поддерживается не всеми файловыми системами.

## Практические сценарии

### 1. Просмотр прав и метаданных
*   **Просмотр прав и владельца:**
    ```bash
    ls -l <file>
    ```
*   **Просмотр с числовыми UID/GID:** Полезно, если имена не сопоставлены.
    ```bash
    ls -ln <file>
    ```
*   **Просмотр расширенных атрибутов:**
    ```bash
    lsattr <file>
    ```
*   **Просмотр ACL:**
    ```bash
    getfacl <file>
    ```
*   **Просмотр всей метаинформации из inode:**
    ```bash
    stat <file>
    ```

### 2. Управление правами и владельцами
> **Кто может изменять:** Права (`chmod`) и владельцев (`chown`) может менять только **владелец** файла или **суперпользователь (root)**.

*   **Изменение прав (`chmod`):**
    ```bash
    # Символьный режим (u,g,o,a | +,-,= | r,w,x)
    chmod u+x,go-w script.sh

    # Числовой режим
    chmod 755 script.sh       # rwxr-xr-x
    chmod 600 secret.txt      # rw-------
    ```
*   **Смена владельца и группы (`chown`, `chgrp`):**
    ```bash
    sudo chown alice file.txt
    sudo chgrp developers file.txt
    sudo chown alice:developers file.txt
    sudo chown -R alice:developers /srv/app # Рекурсивно
    ```

### 3. Управление `umask`
*   **Просмотр текущей маски:**
    ```bash
    umask     # Восьмеричное представление (e.g., 0022)
    umask -S  # Символьное (u=rwx,g=rx,o=rx)
    ```
*   **Установка маски для текущей сессии:**
    ```bash
    umask 0077
    ```
*   **Постоянная настройка umask:**
    *   **Для пользователя:** Добавить `umask 0077` в конец файла `~/.bashrc`.
    *   **Глобально:** Изменить параметр `UMASK` в файле `/etc/login.defs`.

### 4. Управление специальными правами
*   **Установка SUID:**
    ```bash
    chmod u+s /usr/bin/binary
    chmod 4755 /usr/bin/binary
    ```
*   **Установка SGID (на директорию):**
    ```bash
    chmod g+s /shared/directory
    chmod 2775 /shared/directory
    ```
*   **Установка Sticky Bit:**
    ```bash
    chmod +t /tmp/public_dir
    chmod 1777 /tmp/public_dir
    ```

### 5. Управление ACL
> Для работы с ACL может потребоваться пакет `acl` (`getfacl`, `setfacl`). Файловая система должна быть смонтирована с опцией `acl`.
*   **Добавить/изменить правило (`-m`):**
    ```bash
    setfacl -m u:alice:rw- /path/to/file
    setfacl -m g:testers:r-- /path/to/file
    ```
*   **Удалить правило (`-x`):**
    ```bash
    setfacl -x u:alice /path/to/file
    ```
*   **Удалить все расширенные правила ACL (`-b`):**
    ```bash
    setfacl -b /path/to/file
    ```
*   **Установить ACL по умолчанию для директории (`-d`):**
    ```bash
    # Все новые файлы в /shared получат эти права
    setfacl -m d:u:bob:rw-,d:g:project:rw- /shared
    ```

### 6. Управление атрибутами (`chattr`)
*   **Установить флаг неизменяемости:**
    ```bash
    sudo chattr +i /etc/hosts
    sudo chattr +i -R /etc/critical_configs/
    ```
*   **Снять флаг неизменяемости:**
    ```bash
    sudo chattr -i /etc/hosts
    ```

## Дополнительная информация
*   **Inode:** Вся метаинформация о файле, включая права доступа, хранится в его **inode**. Подробнее см. в документе о [файловой системе](../FileSystems/file_system.md#inode-индексный-дескриптор).
*   **Пользователи и группы:** Система прав тесно связана с концепцией пользователей и групп. См. [User_and_Group_Management.md](./User_and_Group_Management.md).
*   **Копирование:** Утилита `cp` по умолчанию создает файлы с правами, определенными `umask`. Чтобы сохранить исходные права и атрибуты, используйте флаг `cp -p` или `cp -a`.
