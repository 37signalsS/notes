# Проверка целостности файлов в Linux

## Определения

**Проверка целостности файлов** — это процесс проверки того, что файлы и программы в системе не были изменены или повреждены. Это критически важная задача безопасности, особенно на скомпрометированных серверах.

Когда злоумышленник получает `root`-доступ, он может подменить системные утилиты (`ls`, `ps`, `top`, `ss` и др.) на вредоносные версии, чтобы скрыть свое присутствие, перехватывать данные или создать бэкдоры. Регулярная проверка целостности позволяет обнаружить такие несанкционированные изменения.

## Основные концепции

В основе проверки целостности лежат два ключевых подхода:

1.  **Сравнение с эталоном из пакета.** Менеджеры пакетов (такие как `APT` и `YUM`/`DNF`) хранят метаданные о каждом файле, который они устанавливают, включая его контрольную сумму (обычно MD5 или SHA). Проверка целостности в этом случае — это пересчет контрольной суммы файла в системе и ее сравнение с эталонным значением из базы данных пакетного менеджера.
2.  **Использование снимков системы (снапшотов).** Системы обнаружения вторжений (HIDS), такие как **AIDE**, работают по другому принципу. Они создают детальный "снимок" (базу данных) состояния важных файлов и каталогов на "чистой" системе. Этот снимок включает контрольные суммы, права доступа, владельца, временные метки и другие атрибуты. Последующие проверки сравнивают текущее состояние системы с этим эталонным снимком и сообщают о любых расхождениях.

Первый подход прост и быстр, но ограничен только файлами, установленными через менеджер пакетов. Второй подход намного мощнее, так как позволяет отслеживать любые файлы, включая конфигурации, данные приложений и скрипты.

## Практические сценарии

### Сценарий 1: Проверка с помощью менеджеров пакетов

Этот метод — первая линия обороны, позволяющая быстро проверить ключевые системные бинарные файлы.

#### Для DEB-систем (Debian, Ubuntu)

Используется утилита `debsums`.

1.  **Установка:**
    ```bash
    sudo apt update && sudo apt install debsums
    ```

2.  **Проверка:**
    ```bash
    # Ключ -s (silent) выводит только измененные файлы
    sudo debsums -s
    ```
    Если команда ничего не выводит, значит, все файлы, установленные из пакетов, соответствуют своим эталонным контрольным суммам.

#### Для RPM-систем (CentOS, RHEL, Fedora)

Используется встроенная функциональность `rpm`.

1.  **Проверка:**
    ```bash
    # Ключ -V (verify), -a (all)
    sudo rpm -Va
    ```

2.  **Анализ вывода:**
    Команда `rpm -Va` выводит информацию только об измененных файлах. Чтобы отфильтровать только самые критичные изменения (изменение содержимого файла), используйте `grep`:
    ```bash
    sudo rpm -Va | grep '^..5'
    ```
    *   Каждый символ в выводе обозначает тип несоответствия. Пятая позиция (`5`) означает сбой проверки контрольной суммы MD5.
    *   Другие символы включают: `S` (размер), `M` (права доступа), `U` (владелец), `G` (группа), `T` (время модификации).

### Сценарий 2: Глубокая проверка с помощью AIDE

**AIDE (Advanced Intrusion Detection Environment)** — это мощный инструмент для детального мониторинга целостности файловой системы.

1.  **Установка:**
    ```bash
    # Для Debian/Ubuntu
    sudo apt install aide
    
    # Для CentOS/RHEL/Fedora
    sudo yum install aide
    ```

2.  **Инициализация (создание снимка):**
    Этот шаг необходимо выполнять на заведомо "чистой" системе.
    ```bash
    # Эта команда создает новую базу данных-снимок
    sudo aideinit
    ```
    После выполнения будет создан файл `/var/lib/aide/aide.db.new.gz`. Его необходимо сделать основной базой данных:
    ```bash
    sudo mv /var/lib/aide/aide.db.new.gz /var/lib/aide/aide.db.gz
    ```

3.  **Проверка целостности:**
    ```bash
    # Сравнение текущего состояния системы с базой данных
    sudo aide --check
    ```
    AIDE выведет подробный отчет обо всех изменениях: добавленных, удаленных и измененных файлах.

## Дополнительная информация

*   **Безопасность базы данных AIDE:** Эталонную базу данных (`aide.db.gz`) крайне важно хранить в безопасном месте, например, на read-only носителе или удаленном сервере. Если злоумышленник получит доступ к базе, он сможет изменить ее, чтобы скрыть свои следы.
*   **Автоматизация:** Проверки с помощью AIDE следует автоматизировать, настроив их регулярный запуск через `cron` или `systemd-timer`. Отчеты о проверках рекомендуется отправлять на централизованный сервер сбора логов или на почту администратора.
*   **Обновление базы данных:** После легитимных изменений в системе (например, обновления ПО или изменения конфигурации) базу данных AIDE необходимо обновить, чтобы зафиксировать новое "нормальное" состояние.
    ```bash
    # Сначала запустить проверку, чтобы увидеть изменения
    sudo aide --check
    # Если все изменения легитимны, обновить базу
    sudo aide --update
    # И заменить старую базу новой
    sudo mv /var/lib/aide/aide.db.new.gz /var/lib/aide/aide.db.gz
    ```
