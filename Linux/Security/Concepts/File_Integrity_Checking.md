# Проверка целостности бинарных файлов в Linux

Когда сервер скомпрометирован, особенно при получении `root`-доступа, нет гарантии, что системные утилиты, такие как `top`, `ps`, `ls`, `ss` и другие, являются настоящими. Злоумышленники часто подменяют эти бинарные файлы, чтобы скрыть свое присутствие или перехватывать данные.

Поэтому критически важно уметь проверять целостность системных бинарных файлов, чтобы убедиться, что они не были изменены.

## Проверка целостности пакетов

Современные системы управления пакетами (APT, YUM/DNF) предоставляют встроенные средства для проверки целостности файлов, установленных из пакетов.

### Для RPM-систем (CentOS, RHEL, Fedora, AlmaLinux)

Используйте команду `rpm -Va`, которая проверяет все установленные пакеты. Опция `-V` (verify) проверяет атрибуты файлов.

```bash
sudo rpm -Va | grep '^..5'
```

**Пояснение вывода `rpm -V`:**
*   Каждый символ в первой колонке указывает на несоответствие одного из атрибутов файла:
    *   `S` — размер файла.
    *   `M` — режим (permissions) или тип файла.
    *   `5` — контрольная сумма MD5 (самый важный индикатор подмены бинарника).
    *   `D` — Major/Minor номера устройства.
    *   `L` — путь к файлу.
    *   `U` — владелец (user).
    *   `G` — группа.
    *   `T` — время изменения (mtime).
*   `^..5` в `grep` означает поиск строк, где контрольная сумма (пятый символ) не совпадает.

Если команда выводит строки, это означает, что у файлов пакетов изменились контрольные суммы или другие атрибуты, что является серьезным поводом для беспокойства.

### Для DEB-систем (Debian, Ubuntu)

Для проверки целостности пакетов в DEB-системах рекомендуется использовать утилиту `debsums`.

**Установка `debsums`:**
```bash
sudo apt install debsums
```

**Проверка:**
```bash
sudo debsums -s
```

**Пояснение:**
*   Опция `-s` (silent) показывает только те файлы, контрольные суммы которых не совпадают с оригинальными, хранящимися в пакете.
*   `debsums` проверяет контрольные суммы MD5, хранящиеся в файлах `.deb`.

Если команда выводит файлы, это указывает на их изменение.

## AIDE (Advanced Intrusion Detection Environment)

AIDE — это мощная система обнаружения вторжений, основанная на проверке целостности файлов. Она работает путем создания "снимка" (базы данных) всех важных файлов в системе, включая их контрольные суммы, права доступа, владельцев и другие атрибуты. При последующих проверках AIDE сравнивает текущее состояние файлов с базой данных и сообщает о любых изменениях.

AIDE гораздо более гибок и детализирован, чем `rpm -Va` или `debsums`, так как позволяет отслеживать изменения любых файлов, а не только установленных из пакетов.

**Установка AIDE:**
```bash
sudo apt install aide # Для Debian/Ubuntu
# или
sudo yum install aide # Для CentOS/RHEL/Fedora
```

**Инициализация базы данных AIDE:**
Первый запуск AIDE используется для создания эталонной базы данных. Это очень важный шаг, так как эта база данных будет использоваться для всех последующих проверок. Ее необходимо создавать на "чистой" системе.

```bash
sudo aideinit # Для Debian/Ubuntu, это обычно запускает создание базы
# или
sudo aide --init # Для RPM-систем и если aideinit не сработает
```
После инициализации файл базы данных AIDE (обычно `/var/lib/aide/aide.db.new.gz`) нужно переименовать в основной файл базы (`/var/lib/aide/aide.db.gz`). Рекомендуется хранить эту базу данных на безопасном, защищенном от записи носителе.

**Проверка целостности:**
После создания базы данных можно запускать проверки.

```bash
sudo aide --check
```
Эта команда сравнит текущее состояние файлов с эталонной базой данных и выведет отчет обо всех изменениях (добавление, удаление, изменение).

**Автоматизация:**
AIDE можно настроить на регулярные проверки через `cron` или `systemd-timer`. Отчеты о проверках следует отправлять на удаленный сервер или по электронной почте.

AIDE позволяет мониторить системные изменения, даже если `debsums` и `rpm -V` не используются, или если изменения произошли в файлах, не входящих в пакеты.
