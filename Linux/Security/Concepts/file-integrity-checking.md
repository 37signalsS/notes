# Проверка целостности файлов в Linux

## Определения

**Проверка целостности файлов** — процесс подтверждения неизменности и целостности системных файлов и программ. Критична для безопасности скомпрометированных систем.

При получении `root`-доступа злоумышленник может подменять системные утилиты (например, `ls`, [`ps`](../../Diagnostics/Processes/ps.md), `top`, `ss`) для сокрытия активности, перехвата данных или создания бэкдоров. Регулярная проверка целостности выявляет подобные несанкционированные изменения.

## Основные концепции

Проверка целостности базируется на двух подходах:

1. **Сравнение с эталоном из пакета.** Менеджеры пакетов (`APT`, `YUM`/`DNF`) хранят метаданные установленных файлов, включая контрольные суммы (MD5, SHA). Проверка заключается в пересчете контрольной суммы файла в системе и сравнении ее с эталонным значением из базы данных пакетного менеджера.
2. **Использование снимков системы (снапшотов).** Системы обнаружения вторжений (HIDS), такие как **AIDE**, создают "снимок" (базу данных) чистого состояния важных файлов и каталогов. Снимок включает контрольные суммы, права доступа, владельца, временные метки. Последующие проверки сравнивают текущее состояние со снимком, выявляя расхождения.

Первый подход прост и быстр, но ограничен файлами, установленными через пакетный менеджер. Второй подход мощнее, отслеживая любые файлы, включая конфигурации и скрипты.

## Практические сценарии

### Проверка с помощью менеджеров пакетов

Метод "первой линии обороны" для быстрой проверки системных бинарных файлов.

#### Для DEB-систем (Debian, Ubuntu)

Используется `debsums`.

1. **Установка:**

    ```bash
    sudo apt update && sudo apt install debsums
    ```

2. **Проверка:**

    ```bash
    sudo debsums -s
    ```

    Флаг `-s` показывает только несовпадения (silent mode). Отсутствие вывода означает соответствие файлов эталонным контрольным суммам.

#### Для RPM-систем (CentOS, RHEL, Fedora)

Используется функциональность `rpm`.

1. **Проверка:**

    ```bash
    sudo rpm -Va
    ```

2. **Анализ вывода:**
    `rpm -Va` выводит только измененные файлы. Для фильтрации по изменению содержимого:

    ```bash
    sudo rpm -Va | grep '^..5'
    ```

    * `5` означает сбой проверки контрольной суммы MD5.
    * Другие символы: `S` (размер), `M` (права доступа), `U` (владелец), `G` (группа), `T` (время модификации).

### Глубокая проверка с помощью AIDE

**AIDE (Advanced Intrusion Detection Environment)** — инструмент для детального мониторинга целостности файловой системы.

1. **Установка:**

    ```bash
    # Для Debian/Ubuntu
    sudo apt install aide
    
    # Для CentOS/RHEL/Fedora
    sudo yum install aide
    ```

2. **Инициализация (создание снимка):**
    Выполняется на "чистой" системе.

    ```bash
    sudo aideinit
    ```

    Созданный `/var/lib/aide/aide.db.new.gz` перемещается в `/var/lib/aide/aide.db.gz`.

3. **Проверка целостности:**

    ```bash
    sudo aide --check
    ```

    AIDE выведет подробный отчет об изменениях: добавленных, удаленных, измененных файлах.

## Дополнительная информация

* **Безопасность базы данных AIDE:** Эталонную базу данных (`aide.db.gz`) следует хранить безопасно (read-only носитель, удаленный сервер) для предотвращения компрометации.
* **Автоматизация:** Проверки AIDE рекомендуется автоматизировать (`cron`, `systemd-timer`). Отчеты отправлять на централизованный сервер логов или почту.
* **Обновление базы данных:** После легитимных изменений (обновления ПО, конфигурации) базу данных AIDE необходимо обновить для фиксации нового "нормального" состояния.

    ```bash
    # Сначала запустить проверку, чтобы увидеть изменения
    sudo aide --check
    # Если все изменения легитимны, обновить базу
    sudo aide --update
    # И заменить старую базу новой
    sudo mv /var/lib/aide/aide.db.new.gz /var/lib/aide/aide.db.gz
    ```
