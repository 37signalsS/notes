# Управление правами файлов: Краткая справка

## Определения

**Управление правами** — совокупность команд и механизмов Linux для настройки доступа к файлам и директориям: изменения прав (`chmod`), владельцев (`chown`), масок (`umask`), расширенных прав (ACL) и атрибутов файловой системы (`chattr`).

**Ограничения модели DAC** — недостатки стандартной модели Discretionary Access Control, которые компенсируются расширенными механизмами (ACL, MAC). Подробнее: [обзор прав доступа](./overview_definitions.md#1-стандартная-модель-прав-доступа-discretionary-access-control-dac).

## Основные концепции

### Ограничения стандартной модели (DAC)

| Проблема | Описание | Компенсация |
| :--- | :--- | :--- |
| **Трудоёмкость настройки** | Управление для множества пользователей и сценариев громоздко | ACL, группы |
| **Проблема распространения** | Пользователь с `r` может скопировать и передать файл | MAC (SELinux, AppArmor) |
| **Централизация на пользователе** | Компрометация учётной записи = доступ ко всем ресурсам | MAC, изоляция процессов |

### Правила изменения прав

| Действие | Кто может | Команда |
| :--- | :--- | :--- |
| Изменить права (`chmod`) | Владелец файла или `root` | `chmod` |
| Сменить владельца (`chown`) | Только `root` | `chown` |
| Сменить группу (`chgrp`) | Владелец (если состоит в группе) или `root` | `chgrp`, `chown` |

## Практические сценарии

### Просмотр прав и метаданных

```bash
# Права и владелец
ls -l <file>

# Права с числовыми UID/GID
ls -ln <file>

# Расширенные атрибуты
lsattr <file>

# ACL
getfacl <file>

# Вся метаинформация из inode
stat <file>
```

### Изменение прав (chmod)

```bash
# Символьный режим
chmod u+x,go-w script.sh

# Числовой режим
chmod 755 script.sh       # rwxr-xr-x
chmod 600 secret.txt      # rw-------

# Только при изменении прав (-c)
chmod -c 744 my_file.txt
```

### Смена владельца и группы

```bash
# Смена владельца (только root)
sudo chown alice file.txt

# Смена группы
sudo chgrp developers file.txt

# Владелец и группа одновременно
sudo chown alice:developers file.txt

# Владелец + его основная группа
sudo chown bob: file.txt

# Рекурсивная смена
sudo chown -R alice:developers /srv/app
```

### Управление umask

**Umask** — маска, определяющая, какие биты прав **не должны быть установлены** при создании файлов и директорий.

| Объект | Базовые права | Причина |
| :--- | :--- | :--- |
| Файл | `666` (`rw-rw-rw-`) | Бит `x` не устанавливается из соображений безопасности |
| Директория | `777` (`rwxrwxrwx`) | Бит `x` необходим для «проходимости» |

Итоговые права = базовые права `&` `~umask` (побитовое И с инверсией маски).

**Распространённые значения:**

| Umask | Файлы | Директории | Сценарий |
| :--- | :--- | :--- | :--- |
| `0000` | `666` | `777` | Полностью открытые (не рекомендуется) |
| `0022` | `644` | `755` | Стандартное значение по умолчанию |
| `0027` | `640` | `750` | Групповой доступ, остальные исключены |
| `0077` | `600` | `700` | Только владелец (рекомендуется для `root`) |

```bash
# Просмотр
umask       # 0022 (восьмеричное)
umask -S    # u=rwx,g=rx,o=rx (символьное)

# Установка для текущей сессии
umask 0077

# Постоянная настройка:
#   Для пользователя: добавить в ~/.bashrc
#   Глобально: UMASK в /etc/login.defs
#   PAM: pam_umask.so umask=077 в /etc/pam.d/common-session
```

### Специальные права

```bash
# SUID
chmod u+s /usr/bin/binary
chmod 4755 /usr/bin/binary

# SGID (на директорию)
chmod g+s /shared/directory
chmod 2775 /shared/directory

# Sticky Bit
chmod +t /tmp/public_dir
chmod 1777 /tmp/public_dir
```

### ACL (кратко)

Развёрнутая документация: **[ACL, атрибуты и временные метки](./acl_immutable_timestamps.md)**.

```bash
# Добавить/изменить правило
setfacl -m u:alice:rw- /path/to/file

# Удалить правило
setfacl -x u:alice /path/to/file

# Удалить все ACL
setfacl -b /path/to/file

# ACL по умолчанию для директории
setfacl -d -m u:bob:rw-,d:g:project:rw- /shared
```

### Атрибуты файлов (кратко)

Развёрнутая документация: **[ACL, атрибуты и временные метки](./acl_immutable_timestamps.md)**.

```bash
# Установить флаг неизменяемости
sudo chattr +i /etc/hosts

# Снять флаг
sudo chattr -i /etc/hosts

# Просмотр атрибутов
lsattr /etc/hosts
```

## Диагностика и устранение проблем

Если стандартные права `chmod 777` не решают проблему с доступом, используйте следующие команды для поиска причины:

| Команда | Что проверяет |
| :--- | :--- |
| `namei -l /path/to/file` | Права на **все** директории по пути к файлу (принцип проходимости) |
| `getfacl <file>` | Наличие расширенных списков доступа (ACL) |
| `lsattr <file>` | Атрибуты файловой системы (например, `immutable`) |
| `ls -Z <file>` | Контекст безопасности SELinux |
| `ausearch -m avc -ts recent` | Последние отказы в доступе от SELinux |
| `aa-status` | Статус профилей AppArmor |
| `ps aux \| grep <name>` | От какого пользователя запущен процесс |

Подробный разбор причин отказа в доступе: **[почему chmod 777 не всегда решает проблему](./overview_definitions.md#диагностика-почему-chmod-777-не-всегда-решает-проблему)**.
