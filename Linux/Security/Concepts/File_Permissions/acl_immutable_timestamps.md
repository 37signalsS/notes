# ACL, Атрибуты и Временные Метки Файлов в Linux

## Определения

**Списки контроля доступа (ACL)** — расширенный механизм прав, дополняющий стандартную модель DAC («владелец-группа-остальные»). Позволяет назначать разрешения для произвольных пользователей и групп. Подробно стандартная модель описана в [обзоре прав доступа](./overview_definitions.md).

**Атрибуты файлов** — флаги на уровне файловой системы, управляющие поведением ядра при операциях с файлами. Ключевой атрибут безопасности — `immutable` (`i`).

**Временные метки** — метаинформация inode о времени событий файла (доступ, модификация, изменение статуса).

## Основные концепции

### Поддержка ACL

Перед использованием ACL необходимо убедиться, что файловая система поддерживает и имеет включённую поддержку ACL:

```bash
# Проверка монтирования с опцией acl
mount | grep acl

# Если ACL не включён — перемонтировать с поддержкой
mount -o remount,acl /home
```

> **Примечание:** Современные файловые системы (ext4, xfs) имеют ACL включёнными по умолчанию.

### Списки контроля доступа (ACL)

Если для файла установлены расширенные права, в выводе `ls -l` появится знак `+`.

* **Access ACL:** Права доступа к конкретному файлу или директории.
* **Default ACL:** Права по умолчанию для директорий. Все новые файлы и поддиректории автоматически наследуют эти права.
* **Mask:** Определяет **максимально возможные права** для всех именованных пользователей и групп. Работает как ограничитель. Например, если пользователю `alice` даны права `rw-`, а маска `r--`, то эффективные права `alice` будут только `r--`.

#### Пример вывода getfacl

```bash
getfacl myfile.txt
# file: myfile.txt
# owner: user1
# group: users
user::rw-
user:john:r--
group::r--
mask::r--
other::---
```

### Атрибуты файлов

Флаги, устанавливаемые через `chattr`, управляющие поведением ядра.

| Атрибут | Название | Эффект |
| :--- | :--- | :--- |
| `i` | immutable | Запрет на изменение, удаление, переименование, создание жёстких ссылок |
| `a` | append-only | Разрешено только дозаписывание в конец файла |
| `A` | noatime | Не обновлять `atime` при доступе |
| `d` | nodump | Исключить из резервного копирования (`dump`) |

**Управление атрибутами:**

| Команда | Описание | Пример |
| :--- | :--- | :--- |
| `chattr +i <файл>` | Установить флаг immutable | `chattr +i /etc/passwd` |
| `chattr -i <файл>` | Снять флаг immutable | `chattr -i /etc/passwd` |
| `lsattr <файл>` | Просмотр атрибутов | `lsattr /etc/passwd` |

> **Предостережение:** Флаг `immutable` — дополнительный слой защиты, а не замена контроля доступа. Не устанавливайте `+i` на файлы, которые должны регулярно изменяться.

### Временные метки файла

Команда `stat` предоставляет подробную метаинформацию о файле из его inode:

* **`Access` (atime):** Время **последнего доступа** к файлу (чтения). В современных системах обновляется с задержкой (опция `relatime`) для повышения производительности.
* **`Modify` (mtime):** Время **последней модификации содержимого** файла. Это та дата, которую показывает `ls -l`.
* **`Change` (ctime):** Время **последнего изменения метаданных** (статуса) файла: прав (`chmod`), владельца (`chown`), имени (`mv`). `ctime` обновляется всегда, когда меняется `mtime`.
* **`Birth`:** Время «рождения» файла. Поддерживается не всеми файловыми системами.

## Практические сценарии

### Управление ACL

> **Требования:** Пакет `acl` (`getfacl`, `setfacl`). Файловая система смонтирована с опцией `acl`.

#### Просмотр ACL

```bash
getfacl myfile.txt
getfacl /path/to/directory
```

#### Добавление и изменение ACL (setfacl)

```bash
# Разрешить пользователю john запись (rw) в файл
setfacl -m u:john:rw myfile.txt

# Разрешить группе developers выполнение (x)
setfacl -m g:developers:x myfile.txt

# Дать всем (other) полный доступ (rwx)
setfacl -m o::rwx myfile.txt

# Назначить по умолчанию права для всех новых файлов в папке
setfacl -d -m u:john:rwx project/
```

#### Удаление ACL

```bash
# Удалить ACL для конкретного пользователя
setfacl -x u:john myfile.txt

# Очистить все ACL-права файла
setfacl -b myfile.txt
```

### Применение атрибутов файлов

#### Защита критических файлов

```bash
# Защитить /etc/passwd и /etc/shadow от изменений
sudo chattr +i /etc/passwd
sudo chattr +i /etc/shadow

# Проверка
lsattr /etc/passwd  # ----i---------e----- /etc/passwd

# Попытка изменения завершится ошибкой:
echo "test" >> /etc/passwd
# bash: /etc/passwd: Operation not permitted
```

#### Защита логов от модификации

```bash
# Разрешить только дозапись (защита от удаления записей)
sudo chattr +a /var/log/auth.log
```

#### Временное снятие защиты

```bash
# Для легитимных изменений снять флаг
sudo chattr -i /etc/passwd
# Внести изменения...
sudo chattr +i /etc/passwd
```

### Просмотр временных меток

```bash
stat /path/to/file
```

Пример вывода:

```
  File: /etc/passwd
  Size: 2500       Blocks: 8          IO Block: 4096   regular file
Access: (0644/-rw-r--r--)  Uid: (    0/    root)   Gid: (    0/    root)
Access: 2024-01-15 10:30:00.000000000 +0000
Modify: 2024-01-10 08:15:00.000000000 +0000
Change: 2024-01-10 08:15:00.000000000 +0000
 Birth: 2023-06-01 12:00:00.000000000 +0000
```

## Дополнительная информация

* **Связь со стандартной моделью прав:** ACL и атрибуты дополняют, но не заменяют стандартную модель DAC. Подробнее: [обзор прав доступа](./overview_definitions.md), [специальные права](./special_permissions.md).
* **Автоматизация проверок:** Проверки целостности файлов (включая атрибуты) автоматизируются через `cron` или `systemd-timer`. Подробнее: [проверка целостности файлов](../file-integrity-checking.md).
* **Расширенные атрибуты (xattrs):** ACL хранятся в расширенных атрибутах файлов. Для просмотра xattr: `getfattr -d <file>`.
* **Краткая справка по управлению правами:** chmod, chown, umask, специальные права — [управление правами: quick reference](./permissions_management_quickref.md).
