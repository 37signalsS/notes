## Определения

**PAM (Pluggable Authentication Modules)** — это механизм, предоставляющий гибкий и модульный фреймворк для реализации сервисов аутентификации, авторизации и управления учетными записями в Linux-системах. Ключевая идея PAM — отделить приложения от нижележащих механизмов аутентификации, позволяя системным администраторам изменять политики безопасности без необходимости переписывать или перекомпилировать приложения.

- **Аутентификация (auth):** Проверка подлинности пользователя, как правило, с помощью пароля или ключа.
- **Учетная запись (account):** Проверка правил, связанных с учетной записью: не истек ли срок действия пароля, имеет ли пользователь право на доступ к сервису в данное время и т.д.
- **Сессия (session):** Задачи, выполняемые до и после предоставления доступа пользователю (например, логирование, монтирование домашних директорий).
- **Пароль (password):** Задачи, связанные с изменением пароля (проверка сложности, обновление токена аутентификации).

## Основные Концепции

#### 1. Архитектура

Приложение (например, `sshd` или `login`) вызывает библиотеку PAM с запросом на выполнение определенной задачи (например, аутентифицировать пользователя). PAM читает свою конфигурацию, определяет, какие модули необходимо выполнить, и запускает их в указанном порядке. После выполнения модули возвращают результат (успех или неудача) в PAM, который, в свою очередь, передает его приложению.

#### 2. Конфигурационные файлы

- **Основная директория:** `/etc/pam.d/`
  - Содержит отдельные конфигурационные файлы для каждого PAM-совместимого приложения (например, `sshd`, `su`, `login`).
- **Файлы конфигурации модулей:** `/etc/security/`
  - Содержит файлы для настройки поведения отдельных модулей, такие как `access.conf` для `pam_access.so` или `time.conf` для `pam_time.so`.

#### 3. Структура конфигурации в `/etc/pam.d/`

Каждая строка в файле сервиса имеет формат:
`[тип_модуля] [условие_успеха] [путь_к_модулю] [аргументы]`

- **Тип модуля:** `auth`, `account`, `session`, `password`.
- **Условие успеха (Control Flag):**
  - `required`: Модуль должен успешно выполниться. Если он завершается с ошибкой, итоговый результат будет отрицательным, но обработка остальных модулей в стеке продолжится.
  - `requisite`: Аналогично `required`, но при неудаче немедленно возвращает управление приложению с ошибкой, не выполняя остальные модули.
  - `sufficient`: Если модуль завершается успешно, PAM немедленно возвращает успех приложению, не выполняя оставшиеся модули в стеке (для данного типа).
  - `optional`: Успех или неудача этого модуля не является критичной для итогового результата.

## Практические Сценарии

#### Сценарий 1: Ограничение доступа по IP-адресу с помощью `pam_access.so`

**Задача:** Разрешить `root`-доступ по SSH только с IP-адреса системного администратора (`192.168.52.1`).

1. **Настроить правила доступа:**
    В файл `/etc/security/access.conf` добавляются правила. Порядок имеет значение.

    ```
    # Разрешить root с указанного IP
    + : root : 192.168.52.1
    # Запретить root со всех остальных адресов
    - : root : ALL
    ```

2. **Подключить модуль для сервиса:**
    В файл `/etc/pam.d/sshd` добавить строку, обычно в секцию `account`.

    ```
    #%PAM-1.0
    ...
    account    required     pam_access.so
    ...
    ```

#### Сценарий 2: Ограничение доступа по времени с помощью `pam_time.so`

**Задача:** Запретить пользователю `lessons` входить в систему по SSH в нерабочее время (с 18:00 до 24:00 в рабочие дни).

1. **Настроить временные ограничения:**
    В файл `/etc/security/time.conf` добавляется правило.

    ```
    # service;ttys;users;times
    sshd;*;lessons;!Wk1800-2400
    ```

    - `sshd`: сервис
    - `*`: любой tty
    - `lessons`: пользователь
    - `!Wk1800-2400`: запрет (`!`) в рабочие дни (`Wk`) с 18:00 до 24:00.

2. **Подключить модуль для сервиса:**
    В файл `/etc/pam.d/sshd` добавить строку.

    ```
    #%PAM-1.0
    ...
    account    required     pam_time.so
    ...
    ```

## Дополнительная информация

- **Ключевая особенность:** Изменения в конфигурационных файлах PAM (`/etc/pam.d/*` и `/etc/security/*`) применяются немедленно и не требуют перезапуска сервисов.
- **Часто используемые модули:**
  - `pam_access.so`: Контроль доступа на основе хоста, IP-адреса, имени пользователя.
  - `pam_time.so`: Ограничение доступа по времени.
  - `pam_limits.so`: Установка лимитов на системные ресурсы для пользовательских сессий.
  - `pam_unix.so`: Стандартный модуль для аутентификации с использованием `/etc/passwd` и `/etc/shadow`.
  - `pam_wheel.so`: Предоставляет root-привилегии (через `su`) только членам группы `wheel`.
