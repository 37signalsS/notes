# Конвейеры (Pipelines)

## Определения

- **Конвейер (Pipeline):** Механизм в командной оболочке, который позволяет связывать несколько команд таким образом, что стандартный вывод (`stdout`) одной команды напрямую передается на стандартный ввод (`stdin`) следующей. Основным оператором для создания конвейера является `|` (pipe).

- **Философия Unix:** Набор принципов для разработки программного обеспечения, который можно кратко сформулировать так:
  1. **Пишите программы, которые делают что-то одно и делают это хорошо.**
  2. **Пишите программы, которые работают вместе.**
  3. **Пишите программы, которые работают с текстовыми потоками**, так как это универсальный интерфейс.

## Базовые концепции

### Принцип работы конвейера

1. Первая команда выполняет свою работу и отправляет результат на свой стандартный вывод (`stdout`).
2. Оператор `|` "перехватывает" этот вывод и немедленно передает его на стандартный ввод (`stdin`) следующей команды.
3. Следующая команда обрабатывает полученные данные и, в свою очередь, может передать их дальше по цепочке.
4. Каждая команда в конвейере выполняется в **отдельном [subshell](bash_command_execution.md#группировка-команд)**, что важно для понимания области видимости переменных.

> Детальное описание операторов `|`, `&&`, `||`, `;` и логики их выполнения находится в документе [Логика обработки команд в Shell](bash_command_execution.md).

### Перенаправление `stdout` и `stderr` в конвейер: `|&`

- Оператор `|` по умолчанию передает только `stdout`.
- Оператор `|&` (доступен в Bash 4+) передает в конвейер **и `stdout`, и `stderr`**. Это является удобным сокращением для `2>&1 |`.

**Пример:**

```bash
# Ошибка от cat не попадет в grep
$ cat non_existent_file.txt | grep "No such file"
# Вывода не будет

# Ошибка будет перенаправлена и обработана grep
$ cat non_existent_file.txt |& grep "No such file"
cat: non_existent_file.txt: No such file or directory
```

### Инспектирование конвейера с помощью `tee`

Команда `tee` читает стандартный ввод и записывает его одновременно и в стандартный вывод, и в один или несколько файлов. Это позволяет "заглянуть" внутрь конвейера на любом его этапе, не прерывая поток данных.

```bash
# Показать список процессов и одновременно записать его в файл
ps aux | tee process_list.txt | grep "nginx"

# Ключ -a (append) дописывает в файл, а не перезаписывает его
ls -l | tee -a output.txt
```

## Практические сценарии

### 1. Подсчет количества запущенных процессов

Простой пример, демонстрирующий передачу вывода [`ps`](../Diagnostics/Processes/ps.md) на вход `wc` для подсчета строк.

```bash
ps aux | wc -l
```

### 2. Анализ прав доступа к файлам

Этот конвейер позволяет найти и посчитать уникальные наборы прав для файлов и каталогов в текущей директории.

```bash
ls -l | grep -v '^total' | cut -c 2-10 | sort | uniq -c | sort -nr
```

**Разбор цепочки:**

1. `ls -l`: Выводит список файлов в длинном формате.
2. `grep -v '^total'`: Удаляет итоговую строку `total ...`, которая не является файлом.
3. `cut -c 2-10`: Вырезает символы со 2-го по 10-й, что соответствует столбцу прав доступа (`rwxr-xr-x`).
4. `sort`: Сортирует строки, чтобы `uniq` мог корректно работать.
5. `uniq -c`: Схлопывает повторяющиеся строки и подсчитывает их количество.
6. `sort -nr`: Сортирует результат по числовому значению (`-n`) в обратном порядке (`-r`), чтобы самые частые права были вверху.

### 3. Получение информации о пользователях

Эта цепочка извлекает имена пользователей из `/etc/passwd` и для каждого выполняет команду `id`.

```bash
awk -F: '{print $1}' /etc/passwd | while read user; do id "$user"; done
```

**Разбор цепочки:**

1. `awk -F: '{print $1}' /etc/passwd`: Извлекает первое поле (имя пользователя) из файла, используя `:` как разделитель.
2. `while read user; do ...; done`: Цикл `while` построчно читает вывод `awk`. Каждая строка присваивается переменной `user`, которая затем используется в теле цикла для вызова команды `id`.

## Дополнительная информация

### Конвейеры и `xargs`

Иногда команды не могут принимать данные из `stdin` (например, `rm`, `cp`). В таких случаях `xargs` используется для преобразования потока `stdin` в аргументы командной строки.

**Пример:** Найти и удалить все файлы `.tmp`.

```bash
# Простого конвейера недостаточно, так как rm не читает stdin
find . -name "*.tmp" | xargs rm
```

`xargs` читает список файлов из вывода `find` и передает их как аргументы команде `rm`.
