# Операторы потоков данных и конвейеры в Shell

## Определения

- **Конвейер (Pipeline)** — механизм Shell (`|`), связывающий стандартный вывод (`stdout`) одной команды со стандартным вводом (`stdin`) следующей. Команды выполняются параллельно.
- **Подстановка процессов (Process Substitution)** — механизм (`<( )`, `>( )`), позволяющий использовать вывод команды или поток данных как путь к временному файлу (через `/dev/fd/`).
- **Именованный канал (Named Pipe / FIFO)** — специальный тип файла (`mkfifo`), работающий как буфер в оперативной памяти для асинхронного обмена данными между независимыми процессами.
- **xargs** — утилита для формирования командных строк на основе данных из `stdin`, позволяющая обходить ограничения на длину аргументов.
- **Сопроцесс (Co-process)** — механизм (команда `coproc`), запускающий процесс в фоне с созданием двустороннего канала связи (pipe) между родительским Shell и дочерним процессом.
- **GNU Parallel** — инструмент для параллельного выполнения задач на одном или нескольких узлах, обеспечивающий группировку вывода и расширенное управление очередями.

## Базовые концепции

### Механика работы конвейера

1.  **Параллельное выполнение**: Все команды в конвейере запускаются одновременно. Скорость всей цепочки ограничена самым медленным звеном (bottleneck).
2.  **Буферизация**: Данные передаются через буферы ядра. В Linux размер буфера канала по умолчанию составляет **64 КБ** (начиная с ядра 2.6.11). Если буфер заполнен, пишущий процесс блокируется (Backpressure).
3.  **Subshells**: Каждая часть конвейера выполняется в отдельной подоболочке.
    - *Проблема*: Изменения переменных внутри конвейера теряются.
    - *Решение*: Использование `shopt -s lastpipe` (в неинтерактивных скриптах) или перенаправление ввода через подстановку процессов: `done < <(command)`.

### Управление кодами возврата и ошибками

- **`$?`**: По умолчанию содержит код только **последней** команды конвейера.
- **`PIPESTATUS`**: Массив Bash, хранящий коды возврата всех этапов последнего конвейера.
  ```bash
  cmd1 | cmd2 | cmd3
  echo "${PIPESTATUS[@]}" # → 0 127 0 (пример: вторая команда не найдена)
  ```
- **`set -o pipefail`**: Опция, заставляющая конвейер возвращать код ошибки, если **хотя бы одна** из команд завершилась неудачно (не с 0).

## Работа с аргументами: xargs и ARG_MAX

### Ограничения системы
В Linux существует лимит на суммарный размер аргументов и переменных окружения (`ARG_MAX`). Если команда (например, `rm *`) выдает ошибку `Argument list too long`, необходимо использовать `xargs`.

### Ключевые опции xargs
- **`-0` (null)**: Использование разделителя NUL (`\0`). Критично для корректной обработки файлов с пробелами или переносами (в связке с `find -print0`).
- **`-I {}`**: Замена маркера `{}` аргументом в любой части команды.
- **`-n N`**: Группировка по N аргументов за один вызов.
- **`-P N`**: Параллельное выполнение до N процессов.
- **`-r` (no-run-if-empty)**: Не запускать команду, если ввод пуст.

## Продвинутые механизмы

### Сопроцессы (coproc)
Позволяют организовать интерактивный диалог с утилитой (например, `bc` или `openssl`) в фоновом режиме.

```bash
# Запуск калькулятора как сопроцесса
coproc MYCALC { bc; }
# Отправка данных (MYCALC[1] - дескриптор для записи)
echo "10 + 20" >&"${MYCALC[1]}"
# Чтение результата (MYCALC[0] - дескриптор для чтения)
read -r result <&"${MYCALC[0]}"
echo "Результат: $result"
```

### Управление буферизацией (stdbuf)
Утилиты типа `grep` или `sed` часто буферизируют вывод при работе через pipe, что мешает мониторингу в реальном времени.
- **`stdbuf -oL`**: Принудительное линейное (line-buffered) буферирование для `stdout`.
- **`stdbuf -i0 -o0`**: Полное отключение буферизации.

### Подстановка процессов (Process Substitution)
Позволяет передавать поток данных командам, которые принимают только пути к файлам.
```bash
# Сравнение двух удаленных конфигов через SSH
diff <(ssh srv1 "cat /etc/app.conf") <(ssh srv2 "cat /etc/app.conf")
```

## Практические сценарии

### Мониторинг скорости потока (pv)
Утилита **pv** (Pipe Viewer) позволяет визуализировать прогресс внутри конвейера.
```bash
# Копирование диска с отображением скорости и прогресса
dd if=/dev/sdb | pv -s 10G | dd of=/dev/sdc
```

### Разветвление потоков (tee и pee)
- **`tee`**: Направляет поток в файл и одновременно в `stdout`.
- **`pee`** (moreutils): Направляет один `stdin` на вход нескольким командам параллельно.
```bash
# Одновременная проверка лога на ошибки и архивация
tail -f app.log | pee "grep 'ERROR' > alerts.txt" "gzip > log_backup.gz"
```

### Именованные каналы (FIFO) для сложных топологий
Используются для связки процессов, запущенных в разное время или в разных терминалах.
```bash
mkfifo /tmp/data_stream
# В терминале 1:
cat < /tmp/data_stream | process_data
# В терминале 2:
generate_data > /tmp/data_stream
```

## Дополнительная информация

### Выбор инструмента для потоков

| Задача | Рекомендуемый инструмент |
| :--- | :--- |
| Прямая передача данных | `|` (Pipeline) |
| Сравнение выводов команд | `<( )` (Process Substitution) |
| Массовая обработка файлов | `find -print0 | xargs -0` |
| Параллелизация и распределение | `GNU Parallel` |
| Мониторинг и визуализация | `pv` |
| Двусторонний обмен с процессом | `coproc` |
