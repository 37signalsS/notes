# Операторы потоков данных и конвейеры в Shell

## Определения

- **Конвейер (Pipeline)** — механизм Shell для связывания нескольких команд, при котором стандартный поток вывода (`stdout`) одной команды напрямую передается на стандартный поток ввода (`stdin`) следующей. Оператор: `|`.
- **Подстановка процессов (Process Substitution)** — механизм, позволяющий использовать вывод команды или поток данных в качестве пути к временному файлу (дескриптору). Операторы: `<( )` и `>( )`.
- **Именованный канал (Named Pipe / FIFO)** — специальный тип файла в файловой системе, работающий по принципу «первым пришел — первым ушел», позволяющий независимым процессам обмениваться данными асинхронно.
- **xargs** — утилита для формирования и выполнения командных строк на основе данных, полученных из стандартного ввода.
- **Сопроцесс (Co-process)** — механизм (команда `coproc`), позволяющий запустить команду в фоновом режиме с двусторонним обменом данными через дескрипторы.

## Базовые концепции

### Механика работы конвейера

1.  **Одновременность**: Все команды в конвейере запускаются одновременно, а не последовательно. Данные передаются через буферы ядра по мере готовности.
2.  **Дочерние оболочки (Subshells)**: Каждая команда в конвейере выполняется в отдельном процессе `subshell`.
    - *Внимание*: Изменения переменных внутри конвейера (например, через `read`) не сохраняются в основной оболочке.
3.  **Объединение потоков (`|&`)**: Оператор `|` передает только `stdout`. Для передачи и `stdout`, и `stderr` одновременно используется `|&` (Bash 4+).

### Управление кодами возврата

По умолчанию переменная `$?` хранит код только **последней** команды конвейера.

- **PIPESTATUS**: Массив, содержащий коды возврата всех команд в последнем выполненном конвейере.
  ```bash
  false | true
  echo "${PIPESTATUS[0]} ${PIPESTATUS[1]}" # → 1 0
  ```
- **pipefail**: Опция (`set -o pipefail`), заставляющая конвейер возвращать код ошибки, если **хотя бы одна** из команд завершилась неудачно.

### Подстановка процессов (Process Substitution)

Позволяет обмануть команды, которые ожидают путь к файлу, передав им поток данных.

- **`<(command)`**: Вывод команды `command` становится доступен как файл для чтения.
- **`>(command)`**: Запись в этот «файл» передается на ввод `command`.

```bash
# Сравнение вывода двух команд напрямую
diff <(ls dir1) <(ls dir2)
```

## Работа с аргументами: xargs

`xargs` необходим, когда нужно передать список элементов (например, из `find`) в команду, которая принимает аргументы через командную строку, а не через `stdin`.

### Ключевые опции

- **`-I {}`**: Позволяет подставить аргумент в середину команды, заменяя `{}`.
- **`-n N`**: Передавать по `N` аргументов за один вызов команды.
- **`-0` (null)**: Обработка аргументов, разделенных символом NUL (`\0`). Критически важно для имен файлов с пробелами или переносами строк.
- **`-P N`**: Параллельное выполнение до `N` процессов одновременно.

```bash
# Параллельное сжатие логов в 4 потока
find /var/log -name "*.log" -print0 | xargs -0 -P 4 gzip
```

## Продвинутые механизмы

### Сопроцессы (coproc)

Позволяют организовать интерактивное взаимодействие со скриптом или утилитой в фоне.

```bash
coproc my_proc { bc; }
# Передаем данные на вход bc через fd сопроцесса
echo "2+2" >&"${my_proc[1]}"
# Читаем результат
read result <&"${my_proc[0]}"
echo "$result" # → 4
```

### Буферизация конвейеров

Многие утилиты (grep, sed, awk) используют буфер при выводе в канал. Это может привести к тому, что данные не будут отображаться в реальном времени.
**Решение**: использование утилиты `stdbuf`.

```bash
# Принудительный линейный буфер для мгновенного логирования
tail -f access.log | stdbuf -oL grep "error" | tee -a error.log
```

## Практические сценарии

### Группировка вывода нескольких команд

```bash
# Объединение заголовка и данных в один поток
{ echo "USER:HOST"; who; } | column -t
```

### Массовое переименование с проверкой

```bash
# Пробный запуск переименования
ls *.txt | xargs -I {} echo mv {} {}.bak
```

### Именованные каналы (FIFO) для сложных связей

```bash
mkfifo log_pipe
# Процесс-слушатель в фоне
grep "ERROR" < log_pipe > errors.log &
# Основной процесс пишет в канал
./my_app > log_pipe
```

## Дополнительная информация

### Выбор инструмента для потоков

| Задача | Инструмент |
| :--- | :--- |
| Связать выход одной команды со входом другой | `|` (Pipeline) |
| Сравнить вывод двух команд или функций | `<( )` (Process Substitution) |
| Передать список имен файлов в команду (rm, cp) | `xargs` |
| Разветвить поток в файл и на экран | `tee` |
| Интерактивный обмен данными с фоновым процессом | `coproc` |
| Межпроцессное взаимодействие через файлы | `mkfifo` |

### Ограничения длины командной строки

В Linux существует лимит на длину аргументов команды (`ARG_MAX`, обычно около 2МБ). Если `rm *` выдает ошибку "Argument list too long", единственным решением является использование конвейера и `xargs`:
`find . -type f | xargs rm` — `xargs` автоматически разбивает список на куски допустимой длины.
