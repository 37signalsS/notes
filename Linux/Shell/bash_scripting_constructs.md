# Конструкции для написания скриптов на Bash

## Определения

- **Управляющие конструкции (Control Structures):** Специальные блоки кода, которые позволяют управлять ходом выполнения скрипта. К ним относятся условные операторы (`if`, `case`) для принятия решений и циклы (`for`, `while`) для многократного выполнения команд.
- **Позиционные параметры и специальные переменные:** Переменные, которые автоматически создаются и заполняются оболочкой Bash для предоставления информации о самом скрипте, переданных ему аргументах и среде выполнения.

---

## Базовые концепции

### 1. Позиционные параметры и специальные переменные

- **Позиционные параметры:** Аргументы, переданные скрипту при запуске.
  - `$0`: Имя самого скрипта.
  - `$1`, `$2`, ...: Первый, второй и последующие аргументы.

- **Специальные переменные:**
  - `$#`: Общее количество аргументов.
  - `$*`: Все аргументы в виде **одной строки**.
  - `$@`: Все аргументы как **отдельные строки** (предпочтительно для итерации).
  - `$?`: [Код возврата](exit_codes.md) последней команды.
  - `$$`: PID текущего скрипта. Для более глубокого понимания того, как Bash управляет процессами и их PID (включая такие механизмы, как [fork()](../Core/processes/overview.md#fork-vs-clone-системные-и-библиотечные-вызовы)), см. документ [Процессы в Linux](../Core/processes/overview.md).
  - `$!`: PID последнего фонового процесса.

Подробное описание обычных переменных см. в [Переменные: локальные и переменные окружения](shell_variables.md), а правил использования кавычек — в [Кавычки: одинарные vs двойные](quoting.md).

### 2. Условные операторы

#### `if / else / elif`

- **Синтаксис:**

  ```bash
  if условие1; then
      # Команды, если условие1 истинно
  elif условие2; then
      # Команды, если условие2 истинно
  else
      # Команды, если ни одно из условий не истинно
  fi
  ```

- **Способы проверки условий:**
  1. **`[ ]` (одинарные скобки):** Псевдоним команды `test`. Это стандартный, переносимый способ.
     - `-f "file.txt"`: Файл существует.
     - `-d "dir"`: Директория существует.
     - `-z "$VAR"`: Переменная пуста.
     - `"$VAR1" = "$VAR2"`: Строки равны.
     - `"$INT1" -eq "$INT2"`: Числа равны.

  2. **`[[ ]]` (двойные скобки):** Расширенная, более мощная версия, встроенная в Bash. **Рекомендуется для использования в Bash-скриптах.**
     - Поддерживает `&&`, `||` для логических операций: `[[ -f "f" && -r "f" ]]`.
     - Поддерживает сопоставление с шаблоном: `[[ "$VAR" == *.txt ]]`.
     - Поддерживает регулярные выражения: `[[ "$VAR" =~ [0-9]+ ]]`.

#### `case`

Удобная альтернатива `if/elif/else` для проверки одной переменной на соответствие нескольким шаблонам.

- **Синтаксис:**

```bash
  case "$переменная" in
      "шаблон1")
          # Команды для шаблона 1
          ;; 
      "шаблон2" | "шаблон3")
          # Команды для шаблона 2 или 3
          ;; 
      *)
          # Команды по умолчанию
          ;; 
esac
```

### 3. Циклы

#### `for`

Используется для итерации по списку элементов или для выполнения C-подобного цикла.

- **Синтаксис:**

  ```bash
  # Итерация по элементам
  for item in 1 2 3; do
      echo "Элемент: $item"
  done

  # C-подобный цикл
  for (( i=0; i<5; i++ )); do
      echo "Итерация: $i"
  done
  ```

#### `while`

Выполняет блок команд, пока условие истинно.

- **Синтаксис:**

  ```bash
  count=0
  while [ $count -lt 5 ]; do
      echo "Счетчик: $count"
      count=$((count + 1))
  done
  ```

## Практические сценарии

### Сценарий 1: Проверка прав root в начале скрипта

```bash
if [ "$(id -u)" -ne 0 ]; then
    echo "Для выполнения этого скрипта требуются права root." >&2
    exit 1
fi

echo "Скрипт запущен с правами root."
```

### Сценарий 2: Обработка аргументов командной строки с помощью `case`

```bash
#!/bin/bash

ACTION=$1

case "$ACTION" in
    "start")
        echo "Запускаем сервис..."
        ;;
    "stop")
        echo "Останавливаем сервис..."
        ;;
    "status")
        echo "Проверяем статус сервиса..."
        ;;
    *)
        echo "Ошибка: неизвестная команда '$ACTION'." >&2
        echo "Используйте: $0 {start|stop|status}" >&2
        exit 1
        ;;
esac
```

### Сценарий 3: Итерация по файлам с помощью `for` и `if`

Этот скрипт перебирает все файлы `.log` в текущем каталоге и архивирует те, что не пусты.

```bash
#!/bin/bash

for logfile in *.log; do
    # Проверяем, существует ли файл и не пуст ли он
    if [[ -f "$logfile" && -s "$logfile" ]]; then
        echo "Архивируем $logfile..."
        tar -czf "$logfile.tar.gz" "$logfile"
    else
        echo "Пропускаем $logfile (не существует или пуст)."
    fi
done

echo "Готово."
```

## Дополнительная информация

### Безопасная обработка аргументов: `"$*"` vs `"$@"`

При работе с аргументами, содержащими пробелы или специальные символы, крайне важно правильно использовать кавычки.

- `"$*"`: Расширяется в **одну строку**, где все аргументы объединены первым символом из `$IFS`.
- `"$@"`: Расширяется в **отдельные слова**. Это почти всегда то, что вам нужно, особенно в циклах `for`.

**Пример:**

```bash
#!/bin/bash
# Скрипт: test.sh

echo "--- Использование \"$*\" ---"
for arg in "$*"; do
    echo "Аргумент: $arg"
done

echo ""

echo "--- Использование \"$@\" ---"
for arg in "$@"; do
    echo "Аргумент: $arg"
done
```

**Результат выполнения `./test.sh "arg 1" "arg 2"`:**

```
---
Использование "$*" ---
Аргумент: arg 1 arg 2

---
Использование "$@" ---
Аргумент: arg 1
Аргумент: arg 2
```

**Вывод:** Всегда используйте `"$@"` для безопасной и предсказуемой итерации по аргументам. Использование `$*` или `$@` без кавычек приведет к неконтролируемому разбиению по словам (word splitting) и может вызвать ошибки.

### Поведение `while read` в пайплайнах: Subshell

При использовании конструкции `command | while read variable; do ... done`, часть `while read` выполняется в отдельном дочернем процессе (subshell). Это означает, что любые изменения переменных внутри этого `while` цикла не будут доступны в родительской оболочке после завершения пайплайна.

**Пример:**

```bash
#!/bin/bash

counter=0
echo "1" | while read line; do
    counter=$((counter + 1))
    echo "Внутри subshell: counter=$counter"
done
echo "После subshell: counter=$counter"
```

**Результат:**

```
Внутри subshell: counter=1
После subshell: counter=0
```

Для сценариев, где необходимо сохранять изменения переменных из `while` цикла, рассмотрите альтернативные подходы, например, перенаправление ввода без создания пайплайна (`while read line < file.txt; do ... done`) или использование process substitution (`while read line; do ... done < <(command)`), или же сбор данных и последующую обработку в родительской оболочке. Подробнее об этом можно узнать в [Subshell в пайплайнах](../bash_scripting_execution.md#ловушка-subshell-в-пайплайнах) и [Понимание пайплайнов и Subshell](../operators_and_pipelines.md#понимание-пайплайнов-и-subshell).
