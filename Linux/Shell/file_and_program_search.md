# Поиск файлов и программ в Linux

## Определения

- **Поиск в реальном времени (Real-time search):** Метод сканирования файловой системы на физическом уровне при каждом вызове команды, без использования промежуточных баз данных или кэшированных индексов.
- **База данных locate:** Предварительно построенный индекс (`/var/lib/mlocate/mlocate.db`) всех файлов в системе, который требует периодического обновления командой `updatedb`.
- **Чувствительность к регистру (Case sensitivity):** Поведение команды, при котором строки `Result.conf` и `result.conf` считаются различными сущностями и не совпадают при сравнении.
- **Glob-шаблон:** Синтаксис подстановки, поддерживаемый утилитой `find`, включающий метасимволы `*` (любое количество символов), `?` (ровно один символ) и `[]` (диапазон символов).
- **mlocate:** Реализация утилиты `locate`, использующая инкрементальный индекс для быстрого поиска без полного переобхода ФС при каждом `updatedb`.
- **updatedb:** Команда, обновляющая базу данных индекса `locate`. Расписание обычно управляется через cron (`/etc/cron.d/mlocate`).
- **which:** Утилита для поиска исполняемого файла в переменной `$PATH` по имени команды.
- **type:** Встроенная команда Bash, определяющая тип сущности (алиас, функция, встроенная команда, исполняемый файл).
- **command -v:** POSIX-совместимый способ вывести путь к исполняемому файлу (аналог `which` для скриптов).
- **whereis:** Утилита для поиска бинарных файлов, исходников и man-страниц по имени программы.
- **hash:** Встроенная команда Bash, управляющая хеш-таблицей путей команд в текущей сессии. Позволяет проверять наличие команды без её запуска.
- **plocate:** Современная альтернатива `mlocate`, использующая инвертированный индекс (postings) и реранжирование. Значительно быстрее на больших системах.

## Основные концепции

### Утилита find

`find` — стандартная утилита POSIX для рекурсивного поиска файлов и каталогов в иерархии файловой системы. В отличие от `locate`, она не зависит от внешних баз данных и видит изменения файловой системы мгновенно.

**Архитектура работы:**
При каждом запуске `find` инициирует системный вызов `openat()` (или `getdents()` в старых ядрах) для обхода дерева каталогов, начиная с указанной точки старта. На каждом узле утилита проверяет:
1. Имя файла/каталога (inode → dentry → name)
2. Тип файла (поле `st_mode` inode)
3. Временные метки (atime, mtime, ctime)
4. Размер, права доступа, владельца и другие атрибуты

Это обеспечивает абсолютную точность результатов, но делает поиск в больших деревьях (например, `/`) ресурсоёмким по сравнению с индексными утилитами.

**Ключевое отличие от locate:**

| Критерий | `find` | `locate` |
| :--- | :--- | :--- |
| Источник данных | Прямой обход ФС в реальном времени | Предварительно построенная БД |
| Требует обновления | Нет | Да (`updatedb`) |
| Видит новые файлы | Да | Нет, пока БД не обновлена |
| Скорость на `/` | Медленная (секунды-минуты) | Быстрая (миллисекунды) |
| Гибкость критериев | Высокая (имя, тип, размер, время, права) | Только по имени/пути |

### Синтаксис команды

Порядок аргументов является строго обязательным. На экзаменах и в тестах неверный порядок считается ошибкой.

```text
find <точка_старта> <флаг_критерия> <значение>
```

- `<точка_старта>` — абсолютный (`/etc`) или относительный (`./docs`) путь к каталогу, в котором начинается обход.
- `<флаг_критерия>` — параметр, определяющий условие фильтрации (`-name`, `-type`, `-size`, `-mtime` и др.).
- `<значение>` — строковый шаблон или числовое значение, с которым сравниваются атрибуты файлов.

### Флаги поиска по имени

| Флаг | Описание |
| :--- | :--- |
| `-name <шаблон>` | Поиск с учётом регистра. Поддерживает glob-шаблоны (`*`, `?`, `[]`). |
| `-iname <шаблон>` | Поиск без учёта регистра. Буква `i` означает «ignore case». |
| `-path <шаблон>` | Поиск по полному пути (относительно точки старта). Поддерживает glob. |
| `-regex <шаблон>` | Поиск по полному пути с использованием POSIX регулярных выражений. |

**Важно:** Флаг `-name` жёстко чувствителен к регистру. Если в системе присутствует файл `Result.conf`, запрос `-name result.conf` не вернёт результатов. Для нечувствительного поиска используйте `-iname`.

### Поиск по типу файла

Флаг `-type` фильтрует объекты файловой системы по их классификации (поле `st_mode` inode):

| Символ | Тип файла |
| :--- | :--- |
| `f` | Обычный файл (regular file) |
| `d` | Каталог |
| `l` | Символическая ссылка |
| `b` | Блочное устройство |
| `c` | Символьное устройство |
| `s` | Сокет |
| `p` | Именованный канал (FIFO) |

```bash
# Найти все символические ссылки в /etc
find /etc -type l

# Найти все сокеты в системе
sudo find / -type s 2>/dev/null

# Найти только обычные файлы (исключая каталоги и ссылки)
find /var/log -type f -name "*.log"
```

### Поиск по размеру

Флаг `-size` позволяет фильтровать файлы по их объёму. Синтаксис использует математические знаки для указания неравенств и суффиксы для единиц измерения:

```text
-size <размер>
```

| Суффикс | Единица измерения | Примечание |
| :--- | :--- | :--- |
| `c` | Байты | Без суффикса или с `c` — точный размер в байтах. |
| `k` | Килобайты (1024 байт) | Заглавная `K` на экзамене LPIC-1 вызывает ошибку синтаксиса. |
| `M` | Мегабайты | **Обязательно заглавная** `M`. Маленькая `m` — это другой тип файла. |
| `G` | Гигабайты | Заглавная `G`. |

| Знак перед числом | Смысл |
| :--- | :--- |
| `+N` | Файлы **строго больше** N единиц. |
| `-N` | Файлы **строго меньше** N единиц. |
| `N` (без знака) | Файлы **ровно** N единиц. |

**Пример — найти все файлы больше 100 МБ:**

```bash
find /usr -type f -size +100M
# → /usr/share/icons/.../icon-theme.cache
# → /usr/lib/.../libapp.so.1
```

**Важно:** В экзаменационных тестах LPIC-1 намеренно проверяют регистр суффикса. Для мегабайта утилита `find` требует заглавную `M`; маленькая `m` означает другие единицы или не поддерживается как ожидается. Для килобайта утилита `find` требует **маленькую** `k`; заглавная `K` вызывает ошибку синтаксиса.

### Поиск по времени изменения

Флаг `-mtime` фильтрует файлы по времени последнего изменения **содержимого** (поле `mtime` inode). Время измеряется в полных днях — шаг 24 часа.

```text
-mtime <дни>
```

| Знак перед числом | Смысл |
| :--- | :--- |
| `-N` | Файлы, изменённые **менее** N дней назад (свежие). |
| `+N` | Файлы, изменённые **более** N дней назад (старые). |
| `N` (без знака) | Файлы, изменённые ровно N дней назад. |

**Пример — найти логи, изменённые за последние 2 дня:**

```bash
find /var/log -type f -mtime -2
# → /var/log/syslog
# → /var/log/nginx/access.log
```

**Пример — найти старые файлы для удаления:**

```bash
find /backup -name "*.gz" -mtime +7 -delete
# → удаляет архивы старше 7 дней
```

**Временные метки в Linux:**
- `mtime` (Modify) — изменение содержимого файла. Используется в `-mtime`.
- `atime` (Access) — время последнего чтения/запуска.
- `ctime` (Change) — время изменения метаданных (права, владелец, размер).

Для фильтрации по времени доступа существует отдельный флаг `-atime`, по времени метаданных — `-ctime`.

### Поиск по правам доступа

Флаг `-perm` фильтрует файлы по битам прав доступа. Синтаксис поддерживает два режима: точное совпадение и проверка всех установленных битов.

| Формат | Смысл |
| :--- | :--- |
| `-perm 0777` | Файлы ровно с правами 0777 (все биты должны совпасть). |
| `-perm -4000` | Файлы, у которых установлен бит SUID (маска проверяет наличие, а не точное совпадение). |
| `-perm /022` | Файлы, у которых установлен **хотя бы один** из битов 022 (другие/запись, другие/чтение). |

```bash
# Найти файлы с SUID-битом
find / -type f -perm -4000 2>/dev/null

# Найти файлы, доступные для записи другим (world-writable)
find /tmp -type f -perm -002

# Найти каталоги с sticky-битом (например, /tmp)
find / -type d -perm -1000
```

### Поиск по владельцу и группе

| Флаг | Описание |
| :--- | :--- |
| `-user <имя\|UID>` | Файлы, принадлежащие указанному пользователю. |
| `-group <имя\|GID>` | Файлы, принадлежащие указанной группе. |
| `-uid <UID>` | То же, что `-user`, но по числовому UID. |
| `-gid <GID>` | То же, что `-group`, но по числовому GID. |
| `-nouser` | Файлы, не принадлежащие ни одному существующему пользователю (сироты). |
| `-nogroup` | Файлы, не принадлежащие ни одной существующей группе. |

```bash
# Найти все файлы пользователя deploy в /var/www
find /var/www -user deploy -type f

# Найти "сирот" — файлы без владельца (после удаления пользователя)
find / -nouser -type f 2>/dev/null
```

### Выполнение действий над результатами

`find` поддерживает два механизма запуска команд для каждого найденного файла:

| Флаг | Описание |
| :--- | :--- |
| `-exec <команда> {} \;` | Выполнить команду для каждого файла. `{}` заменяется на путь. |
| `-exec <команда> {} +` | Выполнить команду с несколькими файлами за один вызов (эффективнее). |
| `-ok <команда> {} \;` | Аналог `-exec`, но запрашивает подтверждение перед каждым выполнением. |

```bash
# Найти все .log файлы и вывести их имена через ls -la
find /var/log -name "*.log" -type f -exec ls -la {} \;

# Более эффективно: передать все файлы сразу
find /var/log -name "*.log" -type f -exec ls -la {} +

# Безопасное удаление с подтверждением
find /tmp -name "*.tmp" -ok rm -f {} \;
```

### Исключение каталогов и путей

Для ускорения поиска можно исключать ненужные подкаталоги (например, `.git`, `node_modules`) или пропускать обход определённых путей:

| Флаг / Опция | Описание |
| :--- | :--- |
| `-path <шаблон>` | Пропустить пути, совпадающие с шаблоном. |
| `-prune` | Не обходить указанный каталог (обычно с `-o`). |
| `-maxdepth <N>` | Ограничить глубину обхода. |
| `-mindepth <N>` | Начинать проверку с уровня N. |

```bash
# Искать "TODO" во всех .py, исключая .git и __pycache__
find . -path ./vendor -prune -o -path ./.git -prune -o -name "*.py" -print

# Искать файлы только в текущем каталоге (без рекурсии)
find . -maxdepth 1 -type f -name "*.conf"
```

### Регулярные выражения в find

Флаги `-regex` и `-iregex` позволяют использовать POSIX-регулярные выражения для сопоставления **полного пути** от точки старта:

```bash
# Найти файлы, путь которых заканчивается на .conf или .cfg
find /etc -regex '.*\.\(conf\|cfg\)$'

# Без учёта регистра
find /etc -iregex '.*\.\(conf\|cfg\)$'
```

**Важно:** `-regex` сопоставляет полный путь, а не только имя файла. Для поиска по имени используйте `-name` или `-wholename` (где поддерживается).

### Утилита locate

`locate` — утилита для мгновенного поиска файлов по предварительно построенному индексу базы данных (`/var/lib/mlocate/mlocate.db`). В отличие от `find`, она не сканирует файловую систему в реальном времени, а обращается к готовому индексу.

**Архитектура работы:**
В системе работает фоновый демон `mlocate` (или `plocate`), который через системный cron (`/etc/cron.daily/mlocate`) обходит файловую систему и обновляет индекс имён файлов. При вызове `locate <шаблон>` утилита выполняет простой поиск по текстовому индексу, что обеспечивает скорость в миллисекунды даже на больших деревьях каталогов.

**Настройка:**
В конфигурационном файле `/etc/updatedb.conf` задаются директории, исключаемые из индекса (по умолчанию `tmpfs`, `proc`, `sysfs`):

```bash
# Пример содержимого /etc/updatedb.conf
PRUNEPATHS="/tmp /var/spool /media /home/.ecryptfs"
PRUNEFS="NFS nfsfs CIFS autofs iso9660 ncpfs coda devpts efivarfs"
```

**Ограничение:**
`locate` абсолютно слепа к файлам, созданным или удалённым после последнего обновления базы данных. Если файл появился только что, `locate` его не найдёт, пока база не будет обновлена.

**Принудительное обновление:**
Для немедленного обновления индекса используется команда `updatedb` (требует root-прав):

```bash
sudo updatedb
```

После обновления базы данные о новых файлах становятся доступны для поиска мгновенно.

### Поиск исполняемых файлов и команд

Для определения того, какая команда будет выполнена при вводе в Shell, используются встроенные утилиты. Они проверяют переменную `$PATH`, алиасы, функции и встроенные команды Bash.

| Утилита | Тип | Описание |
| :--- | :--- | :--- |
| `which` | Внешняя | Показывает полный путь к исполняемому файлу. Работает только для внешних команд (не для алиасов и функций). |
| `type` | Встроенная | Определяет тип сущности: alias, function, builtin, file. |
| `command -v` | Встроенная | POSIX-совместимый аналог `which`. Подходит для скриптов. |
| `whereis` | Внешняя | Ищет бинарный файл, исходники и man-страницу. |
| `hash` | Встроенная | Управляет кешем путей команд. Показывает, есть ли команда в кеше. |

**Различия:**

```bash
# which — только внешние команды
which ls
# → /bin/ls

which cd
# → (пусто, так как cd — встроенная команда)

# type — показывает все типы
type ls
# → ls — это псевдоним (alias) для 'ls --color=auto'
type cd
# → cd — встроенная команда bash
type myfunc
# → myfunc — функция

# command -v — POSIX-совместимый
command -v python3
# → /usr/bin/python3

# whereis — расширенный поиск (бинарник + man + исходники)
whereis python3
# → python3: /usr/bin/python3 /usr/share/man/man1/python3.1.gz

# hash — кеш путей текущей сессии
hash python3
# → (ничего, команда добавлена в кеш)
hash -t python3
# → /usr/bin/python3
hash -d python3
# → (удалена из кеша)
hash -r
# → (полный сброс кеша)
```

### Поиск с помощью fd

`fd` — современная альтернатива `find`, написанная на Rust. Игнорирует `.gitignore` по умолчанию, имеет интуитивный синтаксис и работает значительно быстрее на больших деревьях.

```bash
# Найти все .rs файлы
fd -e rs

# Найти каталоги с именем src
fd -t d -e src

# Поиск с учётом регистра
fd -i "readme"

# Исключить каталог
fd --exclude vendor -t f -e py
```

### Поиск с помощью ripgrep для файлов

`ripgrep (rg)` умеет искать не только текст, но и имена файлов:

```bash
# Найти все файлы с именем, содержащим "config"
rg --files | rg config

# Найти файлы по расширению с рекурсией
rg --files -g "*.yaml"
```

## Практические сценарии

### Базовый поиск по имени

```bash
# Найти файл result.conf в каталоге /etc
find /etc -name result.conf
# → /etc/result.conf
```

### Поиск без учёта регистра

```bash
# Найти файл независимо от регистра (Result.conf, result.conf, RESULT.CONF)
find /etc -iname result.conf
# → /etc/Result.conf
```

### Обработка ошибок доступа

```bash
# Подавление ошибок "Permission denied" при поиске от /
find / -name "nginx.conf" 2>/dev/null
```

### Поиск файлов, превышающих заданный размер

```bash
# Найти все файлы больше 100 МБ в /usr
find /usr -type f -size +100M
# → /usr/share/icons/.../icon-theme.cache
```

### Поиск файлов по времени последнего изменения

```bash
# Найти логи, изменённые за последние 2 дня (48 часов)
find /var/log -type f -mtime -2
# → /var/log/syslog
# → /var/log/nginx/access.log
```

### Комбинированный поиск (размер + время)

```bash
# Найти в /var/log файлы больше 5 МБ, изменённые за последние 2 дня
find /var/log -type f -size +5M -mtime -2
# → /var/log/myapp/error.log
```

### Удаление старых файлов по расписанию

```bash
# Удалить бэкапы старше 7 дней
find /backup -name "*.gz" -mtime +7 -delete
```

### Практическое использование locate

```bash
# Обновить базу данных locate (требует root)
sudo updatedb
# → база данных обновлена (дисковая активность)

# Быстрый поиск по индексу
locate result.conf
# → /etc/result.conf
```

#### Ловушка с новыми файлами

При создании нового файла `locate` может не найти его, так как база данных ещё не обновлена:

```bash
# Создать тестовый файл
touch /tmp/new_config.conf

# Попытка найти его через locate — файл не будет найден
locate new_config.conf
# → (пусто)

# Принудительное обновление базы
sudo updatedb

# Теперь locate видит файл мгновенно
locate new_config.conf
# → /tmp/new_config.conf
```

**Правило:** Если `locate` не находит файл, существование которого вы подтвердили, запустите `sudo updatedb` и повторите поиск.

### Поиск исполняемых файлов в PATH

```bash
# Проверить, где находится python3
which python3
# → /usr/bin/python3

# Узнать тип сущности
type python3
# → python3 — это псевдоним (alias) для '/usr/bin/python3'

# POSIX-совместимый вариант для скриптов
command -v python3
# → /usr/bin/python3

# Расширенный поиск (бинарник + man-страницы)
whereis python3
# → python3: /usr/bin/python3 /usr/share/man/man1/python3.1.gz
```

### Аудит SUID/SGID файлов

```bash
# Найти все SUID-файлы в системе (требует root)
find / -type f -perm -4000 2>/dev/null

# Найти SGID-файлы
find / -type f -perm -2000 2>/dev/null

# Найти файлы, одновременно имеющие SUID и SGID
find / -type f -perm -6000 2>/dev/null
```

### Поиск больших файлов для очистки диска

```bash
# Найти все файлы больше 1 ГБ, отсортировать по размеру
find / -xdev -type f -size +1G -exec ls -lh {} \; 2>/dev/null | sort -k5 -h -r | head -20
```

### Поиск пустых файлов и каталогов

```bash
# Найти пустые файлы
find /tmp -type f -empty

# Найти пустые каталоги
find /var -type d -empty

# Удалить пустые каталоги
find /opt -type d -empty -delete
```

### Поиск файлов по владельцу

```bash
# Найти все файлы пользователя deploy в /srv
find /srv -user deploy -type f

# Найти "сирот" (файлы без владельца) после миграции пользователей
find / -nouser -nogroup -type f 2>/dev/null
```

### Поиск изменённых за последний час конфигов

```bash
# Найти конфиги, изменённые за последний час (для аудита после deploy)
find /etc -type f -mmin -60 -name "*.conf"
```

### Обход subtree с исключениями

```bash
# Искать "TODO" в .py файлах, исключая .git и __pycache__
find . -path ./vendor -prune -o -path ./.git -prune -o -path ./__pycache__ -prune -o -name "*.py" -print
```

### Поиск с помощью fd (DevOps-сценарий)

### Ловушка с locate и новыми файлами

```bash
# Создать тестовый файл
touch /tmp/new_config.conf

# Попытка найти его через locate — файл не будет найден
locate new_config.conf
# → (пусто)

# Принудительное обновление базы
sudo updatedb

# Теперь locate видит файл мгновенно
locate new_config.conf
# → /tmp/new_config.conf
```

## Best Practices

1. **Подавление ошибок:** Добавляйте `2>/dev/null` к `find /`, чтобы скрыть `Permission denied`. Для отладки используйте `2>&1 | grep -i denied`.
2. **Приоритет `-delete`:** Используйте `-delete` вместо `-exec rm {} \;` — это быстрее и безопаснее (один проход, атомарное удаление).
3. **Избегайте `-exec` в цикле:** Используйте `+` вместо `\;` для пакетной обработки: `find ... -exec cmd {} +`.
4. **Изменяемость индекса:** Для поиска новых файлов используйте `find`; `locate` только для уже проиндексированных.
5. **Безопасность `locate`:** В `/etc/updatedb.conf` исключите чувствительные каталоги из индекса (`PRUNEPATHS`), чтобы `locate` не показывал их содержимое.
6. **Исключайте .git и node_modules:** В CI/CD используйте `fd` или `find -path ... -prune` для пропуска артефактов сборки.
7. **Проверяйте команду через `command -v`:** В скриптах используйте `command -v` вместо `which` для POSIX-совместимости.
8. **Не запускайте `find /` без ограничений:** Добавляйте `-xdev` (не уходить на другие ФС) и `-maxdepth`, если контекст позволяет.
9. **Используйте `-print0` + `xargs -0`:** При работе с именами файлов, содержащими пробелы или переводы строк.
10. **Атомарность:** При массовом перемещении или удалении проверяйте список файлов перед действием: `find ... -print | less`.

## Ограничения и edge cases

1. **Glob-шаблоны не рекурсивны по умолчанию:** `find /etc -name "*.conf"` рекурсивный, но `ls *.conf` — нет. Не путайте обход дерева с подстановкой имён.
2. **Ссылки в find:** По умолчанию `find` НЕ следует символическим ссылкам на каталоги. Для включения используйте `-L` (осторожно: возможны циклы).
3. **`-L` и циклы:** Если есть циклические ссылки (например, `dir/link -> dir`), `find -L` зациклится. Используйте `-P` (по умолчанию) или `-mount`/`-xdev`.
4. **locate и права:** База данных `locate` содержит только имена файлов, но не их права. Если у пользователя нет прав на чтение каталога, `locate` покажет файл, но `find` не найдёт его.
5. **Файлы с NUL-символами в именах:** Стандартный `find` и `locate` корректно обрабатывают такие имена, но многие скрипты ломаются. Используйте `-print0` + `xargs -0`.
6. **`updatedb` и bind-mounts:** По умолчанию `updatedb` индексирует каждый bind-mount отдельно, что дублирует записи в БД. Настройте `PRUNEFS` или используйте `--prunefs`.
7. **`which` и алиасы:** `which` не видит алиасы и функции Bash. Для проверки типа используйте `type`.
8. **`command -v` и не-NULL вывод:** В некоторых оболочках `command -v` возвращает непустой вывод даже при отсутствии команды. Используйте `command -V` для детального вывода или проверяйте `$?`.
9. **`find -delete` и порядок:** `-delete` должен быть последним флагом (перед точкой старта). `find ... -delete /path` — синтаксическая ошибка.

## Troubleshooting

| Симптом | Возможная причина | Решение |
| :--- | :--- | :--- |
| `find: paths must precede expression` | Неверный порядок аргументов | Проверьте, что точка старта указана ДО флагов: `find / -name foo`, а не `find -name foo /` |
| `find: unknown predicate '-d'` | Ошибка в флаге или опечатка | Убедитесь, что используется `-type d`, а не `-d` |
| `locate: command not found` | Пакет `mlocate` или `plocate` не установлен | Установите: `apt install mlocate` или `dnf install plocate` |
| `locate` не находит недавно созданный файл | База данных устарела | Запустите `sudo updatedb` или используйте `find` для новых файлов |
| `which` возвращает пустоту для `cd`, `source` | Это встроенные команды (builtins) | Используйте `type` или `command -V` вместо `which` |
| `find` зависает или работает очень долго | Обход сетевых ФС (NFS) или огромного дерева | Добавьте `-xdev`, `-maxdepth` или ограничьте точку старта |
| `find` находит циклические ссылки при `-L` | Циклический симлинк в дереве | Используйте `-P` (по умолчанию) или `-mount` для исключения |
| `find` игнорирует файлы в `.git` | Не настроено исключение | Используйте `-path ./.git -prune -o ...` или перейдите на `fd` |
| `updatedb` слишком медленный | Индексируется внешний диск или сетевой ресурс | Настройте `PRUNEFS` и `PRUNEPATHS` в `/etc/updatedb.conf` |
| `command -v` возвращает алиас вместо файла | В текущей сессии определён алиас | Используйте `\command -v` или `type -a` для полного списка |

## Дополнительная информация

### Связанные инструменты

- **`locate`:** Поиск по предварительно построенной БД. Быстрее `find`, но требует регулярного `updatedb`.
- **`plocate`:** Быстрая альтернатива `mlocate` с инвертированным индексом. Рекомендуется для серверов с большим количеством файлов.
- **`fd`:** Современная альтернатива `find` на Rust. Игнорирует `.gitignore` по умолчанию, имеет интуитивный синтаксис.
- **`rg` (ripgrep):** Поиск файлов по имени и содержимому. Совмещает преимущества `find` и `grep`.
- **`which` / `type` / `command -v`:** Поиск исполняемых файлов в `$PATH`.
- **`whereis`:** Поиск бинарных файлов, исходников и man-страниц.
- **`updatedb`:** Обновление базы данных индекса для `locate`.
