# Сигналы и trap в Bash: гарантированная очистка ресурсов

## Определения

- **Сигнал (Signal)** — асинхронное уведомение, отправляемое процессу ядром или другим процессом. Примеры: `SIGINT` (Ctrl+C), `SIGTERM` (корректное завершение), `SIGKILL` (принудительное завершение).
- **`trap`** — встроенная команда Bash, регистрирующая обработчик (функцию), который выполнится при получении указанного сигнала или при выходе из скрипта.
- **`EXIT`** — псевдосигнал, генерируемый оболочкой при завершении скрипта (нормальном или аварийном). Не является системным сигналом.
- **Cleanup (очистка)** — удаление временных файлов, lock-файлов, завершение фоновых процессов, закрытие соединений перед выходом.

См. также: [Сигналы процессов](../Core/processes/signals.md), [Коды возврата](exit_codes.md).

## Базовые концепции

### Синтаксис `trap`

```bash
trap 'команда' СИГНАЛ
trap функция СИГНАЛ
trap -l              # список доступных сигналов
trap -p              # показать зарегистрированные trap
trap - СИГНАЛ        # сбросить обработчик (действие по умолчанию)
trap '' СИГНАЛ       # игнорировать сигнал
```

### Ключевые сигналы для скриптов

Полная таблица всех 64 сигналов Linux: [Сигналы процессов](../Core/processes/signals.md) (SSoT). Ниже — только сигналы, наиболее релевантные для Bash-скриптов.

| Сигнал | Код | Описание | Когда срабатывает |
| :--- | :--- | :--- | :--- |
| `EXIT` | — | Выход из скрипта | Всегда при завершении (успех/ошибка) |
| `SIGINT` | 2 | Прерывание (Ctrl+C) | Пользователь нажал Ctrl+C |
| `SIGTERM` | 15 | Корректное завершение | `kill <pid>`, systemd stop |
| `SIGHUP` | 1 | Hangup | Закрытие терминала, отключение SSH |
| `ERR` | — | Ошибка команды | Только с `set -e`, при ненулевом exit code |
| `SIGKILL` | 9 | Принудительное завершение | **Не перехватывается** ядром |

> **Примечание:** `EXIT` и `ERR` — псевдосигналы Bash, не существуют на уровне ядра. Полные описания системных сигналов (`SIGINT`, `SIGTERM`, `SIGKILL`, `SIGHUP` и др.) — в [Сигналы процессов](../Core/processes/signals.md).

### Почему `trap cleanup EXIT` лучше `rm` в конце скрипта

```bash
# ❌ Ненадёжно — rm не выполнится при ошибке
tmpfile=$(mktemp)
process_data "$tmpfile"
rm -f "$tmpfile"  # Не выполнится, если скрипт упадёт выше

# ✅ Надёжно — cleanup выполнится всегда
tmpfile=$(mktemp)
cleanup() { rm -f "$tmpfile"; }
trap cleanup EXIT
process_data "$tmpfile"  # Даже при падении — файл будет удалён
```

**Механизм:** `EXIT` — это гарантия на уровне интерпретатора. Функция cleanup вызовется при любом выходе: нормальном (`exit 0`), аварийном (`set -e` + ошибка), по сигналу (`SIGINT`, `SIGTERM`).

## Практические сценарии

### Базовый шаблон: удаление временных файлов

```bash
#!/bin/bash
set -euo pipefail

tmpfile=$(mktemp)

cleanup() {
  rm -f "$tmpfile"
  echo "Временные файлы удалены"
}

trap cleanup EXIT

# Основная работа
echo "Processing..." > "$tmpfile"
cat "$tmpfile"
# cleanup вызовется автоматически
```

### Очистка нескольких ресурсов

```bash
#!/bin/bash
set -euo pipefail

tmpdir=$(mktemp -d)
lockfile="/tmp/myapp.lock"

cleanup() {
  rm -rf "$tmpdir"
  rm -f "$lockfile"
  echo "Очистка завершена"
}

trap cleanup EXIT

# Создание lock-файла
echo $$ > "$lockfile"

# Работа с временной директорией
mkdir -p "$tmpdir/logs"
```

### Перехват сигналов для graceful shutdown

```bash
#!/bin/bash
set -euo pipefail

running=true

shutdown() {
  echo "Получен сигнал завершения, останавливаем gracefully..."
  running=false
}

trap shutdown SIGINT SIGTERM

echo "PID: $$"
while $running; do
  echo "Working..."
  sleep 1
done

echo "Корректное завершение"
```

### Остановка фоновых процессов при выходе

```bash
#!/bin/bash
set -euo pipefail

# Запуск фонового процесса
sleep 3600 &
bg_pid=$!

cleanup() {
  echo "Останавливаем фоновый процесс $bg_pid"
  kill "$bg_pid" 2>/dev/null || true
  wait "$bg_pid" 2>/dev/null || true
}

trap cleanup EXIT

# Основная работа
echo "Фоновый процесс запущен"
sleep 5
```

### Обработка ошибок с `ERR`

```bash
#!/bin/bash
set -euo pipefail

error_handler() {
  line_number=$1
  echo "Ошибка на строке $line_number, выполняем cleanup..."
  # Логирование, отправка метрик, очистка
}

trap 'error_handler $LINENO' ERR

# Тест ошибки
false  # Завершится с exit code 1
```

### Игнорирование сигналов

```bash
# Игнорировать Ctrl+C во время критической операции
trap '' SIGINT
critical_operation
trap - SIGINT  # Восстановить обработку
```

## Дополнительная информация

### Что можно убирать через `trap`

- **Временные файлы и директории** (`mktemp`, `mktemp -d`)
- **Lock-файлы** (PID-файлы, блокировки ресурсов)
- **Фоновые процессы**, запущенные скриптом
- **Сетевые соединения** (закрытие сокетов, SSH-туннелей)
- **Docker-контейнеры** для тестов (`docker rm -f`)
- **Mount-точки** (`umount`)

### Перехват сигналов: краткая справка

Полная таблица — в [Сигналы процессов](../Core/processes/signals.md).

| Сигнал | Перехватывается | Типичное использование |
| :--- | :--- | :--- |
| `EXIT` | ✅ | Гарантированная очистка |
| `SIGINT` | ✅ | Обработка Ctrl+C |
| `SIGTERM` | ✅ | Graceful shutdown |
| `SIGHUP` | ✅ | Перезагрузка конфига |
| `ERR` | ✅ | Логирование ошибок (с `set -e`) |
| `SIGKILL` | ❌ | Принудительное завершение ядром |
| `SIGSTOP` | ❌ | Остановка процесса ядром |

### `EXIT` vs `ERR` vs `RETURN`

| Псевдосигнал | Когда срабатывает | Требования |
| :--- | :--- | :--- |
| `EXIT` | При любом выходе из скрипта | Всегда |
| `ERR` | При ненулевом exit code команды | `set -e` (errexit) |
| `RETURN` | При выходе из функции | Только внутри функций |

### Нюансы и ограничения

- **`SIGKILL` и `SIGSTOP` не перехватываются** — это гарантия ядра Linux. Процесс будет завершён без выполнения cleanup.
- **Subshell не наследует trap** — каждый subshell имеет собственный контекст сигналов.
- **`trap` внутри функции** — обработчик регистрируется в глобальном контексте, не только внутри функции.
- **`wait` после `kill`** — всегда используйте `wait $pid` после `kill`, чтобы избежать zombie-процессов.
