# Обработка сигналов и команда trap в Bash

## Определения

- **Signal (Сигнал)** — асинхронное уведомление, отправляемое процессу ядром или другим процессом для сообщения о событии. Примеры: `SIGINT` (прерывание), `SIGTERM` (завершение), `SIGKILL` (принудительное уничтожение).
- **`trap`** — встроенная команда Bash, предназначенная для перехвата сигналов и выполнения определенных действий (функций или команд) при их получении.
- **EXIT** — псевдосигнал Bash, возникающий при завершении работы оболочки (скрипта). Позволяет гарантированно выполнить действия перед выходом.
- **Cleanup (Очистка)** — процесс освобождения ресурсов (удаление временных файлов, закрытие соединений) перед завершением программы.

## Базовые концепции

### Синтаксис команды trap

Команда `trap` позволяет регистрировать обработчики для одного или нескольких сигналов.

```bash
trap 'команда' СИГНАЛ
trap функция СИГНАЛ
trap -l              # список всех доступных сигналов
trap -p              # просмотр установленных обработчиков
trap - СИГНАЛ        # сброс обработчика к действию по умолчанию
trap '' СИГНАЛ       # игнорирование сигнала
```

### Ключевые сигналы для автоматизации

Полный список системных сигналов представлен в разделе [Сигналы процессов](../Core/processes/signals.md). В Bash-скриптах чаще всего используются следующие:

| Сигнал | Код | Описание | Событие |
| :--- | :--- | :--- | :--- |
| **EXIT** | — | Завершение Bash | Любой выход из скрипта (нормальный или по ошибке) |
| **SIGINT** | 2 | Interrupt | Нажатие `Ctrl+C` пользователем |
| **SIGTERM** | 15 | Termination | Запрос на завершение (например, `kill` или `systemctl stop`) |
| **SIGHUP** | 1 | Hangup | Закрытие терминала или разрыв SSH-соединения |
| **ERR** | — | Error | Выполнение команды с ненулевым кодом возврата (при `set -e`) |
| **SIGKILL** | 9 | Kill | Принудительное завершение. **Не перехватывается** |

### Преимущества использования EXIT trap

Использование `trap cleanup EXIT` является более надежным подходом по сравнению с ручным удалением ресурсов в конце скрипта.

**Ненадежный подход:**

```bash
tmpfile=$(mktemp)
process_data "$tmpfile"
rm -f "$tmpfile"  # Команда не выполнится, если скрипт завершится с ошибкой выше
```

**Надежный подход:**

```bash
tmpfile=$(mktemp)
cleanup() { rm -f "$tmpfile"; }
trap cleanup EXIT
process_data "$tmpfile"  # Файл будет удален при любом исходе выполнения
```

Механизм `EXIT` гарантирует выполнение обработчика даже при возникновении фатальных ошибок или получении сигналов завершения.

## Практические сценарии

### Шаблон для удаления временных файлов

```bash
#!/bin/bash
set -euo pipefail

tmpfile=$(mktemp)

cleanup() {
  rm -f "$tmpfile"
  echo "Временные файлы удалены"
}

trap cleanup EXIT

# Основная логика
echo "Работа с данными..." > "$tmpfile"
```

### Реализация Graceful Shutdown

Позволяет корректно завершить работу долгоживущего процесса (например, воркера).

```bash
#!/bin/bash
set -euo pipefail

keep_running=true

shutdown_handler() {
  echo "Получен сигнал завершения. Остановка..."
  keep_running=false
}

trap shutdown_handler SIGINT SIGTERM

while $keep_running; do
  # Выполнение задачи
  sleep 1
done

echo "Процесс корректно завершен"
```

### Остановка фоновых процессов

```bash
#!/bin/bash
set -euo pipefail

sleep 3600 &
child_pid=$!

cleanup() {
  echo "Завершение фонового процесса $child_pid"
  kill "$child_pid" 2>/dev/null || true
  wait "$child_pid" 2>/dev/null || true
}

trap cleanup EXIT

echo "Основной скрипт запущен"
sleep 5
```

### Игнорирование сигналов (Critical Section)

Предотвращает прерывание критически важных операций пользователем.

```bash
# Начало критической секции: игнорировать SIGINT (Ctrl+C)
trap '' SIGINT

perform_atomic_transaction

# Возврат к стандартному поведению
trap - SIGINT
```

## Дополнительная информация

### Объекты для очистки

Через механизм `trap` рекомендуется освобождать следующие ресурсы:

- Временные файлы и директории (`mktemp`).
- Блокирующие файлы (lock-files/PID-files).
- Фоновые процессы (Child processes).
- Сетевые туннели и сокеты.
- Тестовые Docker-контейнеры.
- Точки монтирования (`mount`).

### Сравнение псевдосигналов Bash

| Тип | Условие срабатывания | Контекст |
| :--- | :--- | :--- |
| **EXIT** | Любой выход из Shell | Глобальный |
| **ERR** | Ненулевой код возврата команды | Глобальный (требует `set -e`) |
| **RETURN** | Выход из функции или выполнение `source` | Локальный для функции/файла |

### Ограничения и нюансы

- **Ядро Linux гарантирует**, что `SIGKILL` (9) и `SIGSTOP` (19) не могут быть перехвачены или проигнорированы.
- **Контекст Subshell**: дочерние процессы (subshells) не наследуют установленные `trap` родителя.
- **Зомби-процессы**: при завершении фоновых процессов через `kill` всегда используйте `wait`, чтобы избежать появления процессов-зомби.
