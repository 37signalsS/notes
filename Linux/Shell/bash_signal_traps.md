# Обработка сигналов и команда trap в Bash

## Определения

- **Сигнал (Signal)** — асинхронное уведомление, отправляемое процессу ядром или другим процессом для сообщения о событии.
- **Ловушка (Trap)** — механизм Bash для перехвата сигналов и выполнения заданного кода (обработчика) при их получении.
- **EXIT** — псевдосигнал Bash, возникающий при завершении работы оболочки (скрипта) по любой причине.
- **Очистка (Cleanup)** — процедура освобождения ресурсов (удаление временных файлов, закрытие соединений) перед выходом.

---

## Основные концепции

### Синтаксис команды trap

Команда `trap` регистрирует действия, которые должны быть выполнены при получении указанных сигналов.

```bash
trap 'команда' СИГНАЛ    # Выполнить команду при сигнале
trap функция СИГНАЛ      # Вызвать функцию при сигнале
trap -l                  # Список всех доступных сигналов
trap -p                  # Просмотр установленных обработчиков
trap - СИГНАЛ            # Сброс обработчика к значению по умолчанию
trap '' СИГНАЛ           # Игнорировать сигнал
```

### Ключевые сигналы и события

Полный список системных сигналов см. в: [Сигналы процессов](../Core/processes/signals.md). В Bash-скриптах чаще всего используются следующие:

| Событие | Описание | Когда возникает |
| :--- | :--- | :--- |
| **EXIT** | Завершение скрипта | При `exit`, завершении последней команды или фатальной ошибке. |
| **SIGINT** (2) | Прерывание | Нажатие `Ctrl+C`. |
| **SIGTERM** (15) | Завершение | Стандартный сигнал `kill` или остановка сервиса (systemd). |
| **SIGHUP** (1) | Отключение | Закрытие терминала или разрыв SSH-сессии. |
| **ERR** | Ошибка команды | Выполнение команды с ненулевым кодом (требует `set -e`). |
| **DEBUG** | Отладка | Перед выполнением каждой команды в скрипте. |
| **RETURN** | Возврат | При выходе из функции или выполнении `source`. |

### Сохранение кода возврата

При выполнении обработчика `trap` значение `$?` может измениться. Чтобы сохранить код ошибки основной программы, его нужно зафиксировать внутри обработчика.

```bash
cleanup() {
    local exit_code=$?
    echo "Скрипт завершен с кодом: $exit_code"
    # Выполнение очистки
    exit "$exit_code"
}
trap cleanup EXIT
```

## Наследование и контекст

### Наследование ловушек

По умолчанию функции и дочерние оболочки (subshells) не наследуют ловушки `ERR` и `DEBUG`. Для изменения этого поведения используются настройки `set`:

- **`set -E` (errtrace)** — функции, подстановки команд и subshell наследуют ловушку `ERR`.
- **`set -T` (functrace)** — функции, подстановки команд и subshell наследуют ловушку `DEBUG` и `RETURN`.

### Ловушки в Subshell

Дочерние оболочки (запускаемые через `( )`) наследуют обработчики сигналов, но они сбрасываются при вызове `exec` (запуске внешней команды).

## Практические сценарии

### Шаблон автоматической очистки (Best Practice)

Использование `EXIT` гарантирует очистку даже при ошибках, в отличие от ручного удаления файлов в конце файла.

```bash
#!/bin/bash
set -euo pipefail

TMP_DIR=$(mktemp -d)
cleanup() {
    rm -rf "$TMP_DIR"
    echo "Временная директория $TMP_DIR удалена"
}

trap cleanup EXIT

# Основная логика работы
touch "$TMP_DIR/data.txt"
```

### Graceful Shutdown (Безопасное завершение)

Позволяет скрипту завершить текущую итерацию перед выходом.

```bash
#!/bin/bash
keep_running=true

stop_handler() {
    echo "Получен сигнал завершения. Завершаем текущую задачу..."
    keep_running=false
}

trap stop_handler SIGINT SIGTERM

while $keep_running; do
    echo "Выполнение задачи..."
    sleep 5
done
echo "Процесс корректно завершен"
```

### Предотвращение прерывания (Critical Section)

Используется для защиты атомарных операций, которые не должны быть прерваны пользователем.

```bash
# Игнорировать Ctrl+C
trap '' SIGINT

# Критическая секция
cp -a /source /backup

# Восстановить стандартное поведение
trap - SIGINT
```

## Особенности и ограничения

1. **Сигналы, которые нельзя перехватить**: `SIGKILL` (9) и `SIGSTOP` (19) всегда обрабатываются ядром немедленно, процесс не может их увидеть или заблокировать.
2. **Ловушки и блокирующие команды**: Если скрипт ожидает завершения команды (например, `wait` или `sleep`), обработчик `trap` выполнится только **после** того, как команда завершится.
   - *Исключение*: В интерактивных оболочках или при использовании `wait` в некоторых версиях Bash, сигналы могут прерывать ожидание.
3. **Зомби-процессы**: Если скрипт запускает фоновые процессы (`&`), они не завершатся автоматически при закрытии скрипта. Их нужно убивать явно в обработчике `EXIT`.
