# Коды возврата в Shell

## Определения

- **Код возврата (Exit Code, Exit Status)** — целочисленное значение в диапазоне от 0 до 255, возвращаемое процессом операционной системе при завершении работы. Этот код служит индикатором результата выполнения программы.
- **Переменная `$?`** — специальная переменная оболочки (Shell), которая хранит код возврата последней выполненной команды. Значение переменной перезаписывается после каждого вызова новой команды.

## Основные концепции

### Интерпретация значений

- **`0`** — успешное завершение (Success).
- **`1–255`** — завершение с ошибкой (Failure). Конкретное число может указывать на тип возникшей проблемы.

### Сохранение кода возврата

Поскольку значение `$?` обновляется после каждой команды, для анализа кода конкретной операции его необходимо сохранить в локальную переменную сразу после выполнения целевой команды.

```bash
# Пример сохранения кода
ls /etc/shadow
LAST_EXIT_CODE=$?
echo "Код возврата команды ls: $LAST_EXIT_CODE"
```

### Формула сигналов (128 + N)

Если процесс завершается принудительно под воздействием системного сигнала, оболочка рассчитывает код возврата по формуле: **128 + номер_сигнала**. Например, прерывание через `Ctrl+C` (сигнал `SIGINT`, номер 2) дает код `130`.

### Таблица общепринятых кодов

| Код | Значение | Описание |
| :--- | :--- | :--- |
| **0** | Успех | Команда выполнена без ошибок |
| **1** | Общая ошибка | Неуказанная программная ошибка или ошибка выполнения |
| **2** | Неправильное использование | Ошибочные аргументы или синтаксис команды |
| **125** | Ошибка запуска | Специфично для Docker: `docker run` не смог стартовать контейнер |
| **126** | Невыполнимая команда | Файл найден, но нет прав на исполнение (`chmod +x`) |
| **127** | Команда не найдена | Ошибка в пути `$PATH` или опечатка в имени команды |
| **128** | Неверный аргумент выхода | Передан аргумент вне диапазона 0-255 |
| **130** | SIGINT (128+2) | Прерывание пользователем через `Ctrl+C` |
| **137** | SIGKILL (128+9) | Принудительное завершение (например, OOM Killer) |
| **139** | SIGSEGV (128+11) | Ошибка сегментации (обращение к неверному адресу памяти) |
| **143** | SIGTERM (128+15) | Сигнал корректного завершения процесса |

## Практические сценарии

### Проверка результата выполнения в скриптах

Использование кода возврата для ветвления логики является стандартной практикой автоматизации.

```bash
#!/bin/bash

# Поиск пользователя
grep -q "^root:" /etc/passwd

if [ $? -eq 0 ]; then
    echo "Пользователь найден"
else
    echo "Пользователь отсутствует"
fi
```

### Контроль качества в CI/CD конвейерах

Многие инструменты безопасности и тестирования позволяют явно задать код возврата для управления статусом сборки.

```bash
# Прекратить сборку (fail step), если найдены критические уязвимости
trivy image --severity HIGH,CRITICAL --exit-code 1 my-app:latest
```

### Диагностика прав доступа

Если команда возвращает код `126`, это прямой сигнал проверить права файла.

```bash
./script.sh
# Результат: Permission denied
echo $? # → 126

chmod +x ./script.sh
./script.sh
echo $? # → 0
```
