# Коды возврата в Shell

## Определения

* **Код возврата (Exit Code, Exit Status)** — это целочисленное значение в диапазоне от 0 до 255, которое возвращает каждый процесс или команда после своего завершения. Он информирует систему о том, как завершилась программа.
* **Переменная `$?`** — это специальная переменная в shell, которая **хранит код возврата последней выполненной команды**.

## Основные концепции

* **`0` (Успех):** Команда завершилась успешно, без ошибок.
* **`1-255` (Ошибка):** В процессе выполнения команды произошла ошибка. Конкретное число может указывать на причину.

Значение переменной `$?` перезаписывается после выполнения **каждой** новой команды. Если нужно сохранить код возврата для последующего использования, его необходимо немедленно присвоить другой переменной.

## Практические сценарии

* **Проверка успешного выполнения:**

    ```bash
    ls /etc/hosts
    # /etc/hosts
    
    echo $?
    # 0
    ```

* **Проверка ошибочного выполнения:**

    ```bash
    ls /не/существует
    # ls: cannot access '/не/существует': No such file or directory
    
    echo $?
    # 2 (или другое ненулевое значение)
    ```

* **Использование в скриптах для ветвления логики:**

    ```bash
    grep "user" /etc/passwd
    
    if [ $? -eq 0 ]; then
      echo "Пользователь найден."
    else
      echo "Пользователь не найден или произошла ошибка."
    fi
    ```

* **Сохранение кода возврата:**

    ```bash
    ls /не/существует
    LAST_EXIT_CODE=$?
    
    # Теперь можно выполнять другие команды, не боясь потерять исходный код
    echo "Команда 'ls' завершилась с кодом: $LAST_EXIT_CODE"
    
    echo "А код возврата последней команды 'echo' равен: $?" # Будет 0
    ```

## Дополнительная информация

Существуют общепринятые, хотя и не строго обязательные, значения кодов возврата:

*   **`0`**: Успешное выполнение.
*   **`1`**: Общая ошибка. Часто используется для обозначения неуказанной проблемы.
*   **`2`**: Неправильное использование (например, неверные аргументы командной строки).
*   **`125`**: Ошибка запуска `docker run` (специфично для Docker).
*   **`126`**: Команда найдена, но не может быть выполнена (Command invoked cannot execute). Чаще всего это проблема с правами на исполнение файла (`chmod +x`) или некорректный формат исполняемого файла.
*   **`127`**: Команда не найдена (Command not found). Опечатка в имени команды или отсутствие исполняемого файла в `$PATH`.
*   **`130 (128 + 2)`**: Завершение по `SIGINT`. Процесс был прерван, аналогично нажатию `Ctrl+C`. Коды выше 128 указывают на завершение по сигналу.
*   **`137 (128 + 9)`**: Завершение по `SIGKILL`. Процесс был "убит" немедленно и без возможности очистки ресурсов. Это наиболее распространенный код при:
    -   **`OOMKilled` (Out of Memory)**: Процесс превысил свой лимит по памяти, и ядро системы принудительно завершило его.
    -   Выполнении команды `kill -9` или аналогичной.
*   **`139 (128 + 11)`**: Завершение по `SIGSEGV` (Segmentation Fault). Произошла ошибка сегментации, указывающая на серьезную проблему в приложении (например, обращение к невалидной области памяти). Часто встречается в приложениях на C/C++ или в нативных расширениях для других языков.
*   **`143 (128 + 15)`**: Завершение по `SIGTERM`. Процесс получил сигнал о "вежливом" завершении, но не смог или не успел его обработать. Корректно написанное приложение должно перехватывать `SIGTERM` для graceful shutdown.
