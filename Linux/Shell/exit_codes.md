# Коды возврата в Shell

## Определения

- **Код возврата (Exit Code, Exit Status)** — целочисленное значение в диапазоне от 0 до 255, возвращаемое процессом родительской оболочке или операционной системе при завершении работы. Это основной способ межпроцессного взаимодействия для передачи результата выполнения.
- **Переменная `$?`** — специальный параметр оболочки, который хранит код возврата последней выполненной команды (или конвейера в целом). Значение обновляется немедленно после выполнения любой команды.

## Базовые концепции

### Интерпретация значений

- **`0`** — Успех (Success). Команда выполнена корректно.
- **`1–255`** — Ошибка (Failure). Любое ненулевое значение сигнализирует о сбое. Конкретное число часто (но не всегда) указывает на тип возникшей проблемы.

### Сохранение кода возврата

Так как `$?` меняется после каждой команды (включая `echo` или `[`), для анализа кода конкретной операции его необходимо сохранить в переменную сразу после вызова.

```bash
# Пример корректного сохранения
ls /nonexistent_file
rc=$?
# Теперь переменную rc можно анализировать многократно
if [ $rc -ne 0 ]; then
    echo "Ошибка! Код возврата: $rc"
fi
```

### Коды выхода и системные сигналы (128 + N)

Если процесс завершается принудительно под воздействием сигнала, оболочка устанавливает код возврата по формуле **128 + номер_сигнала**.

- `Ctrl+C` (SIGINT, 2) → **130**
- `OOM Killer` / `kill -9` (SIGKILL, 9) → **137**
- `SIGTERM` (15) → **143**

### Таблица общепринятых кодов

| Код | Значение | Описание |
| :--- | :--- | :--- |
| **0** | Успех | Команда завершена без ошибок. |
| **1** | Общая ошибка | Неспецифическая ошибка (например, деление на ноль или ошибки `let`). |
| **2** | Неправильное использование | Ошибки синтаксиса или неверные аргументы встроенных команд Bash. |
| **126** | Невыполнимая команда | Файл найден, но права на исполнение отсутствуют (`Permission denied`). |
| **127** | Команда не найдена | Опечатка в имени или файл отсутствует в путях `$PATH`. |
| **128** | Неверный аргумент выхода | Передан `exit` с аргументом вне диапазона 0-255. |
| **130** | SIGINT | Завершение пользователем через прерывание (Interrupt). |
| **137** | SIGKILL | Принудительное мгновенное завершение (часто из-за нехватки памяти). |

## Продвинутая работа с кодами возврата

### Конвейеры и массив PIPESTATUS

По умолчанию переменная `$?` хранит код возврата только **последней** команды в конвейере.

```bash
# Пример обманчивого успеха
cat nonexistent_file | sort
echo $? # → 0 (так как sort отработал успешно, несмотря на ошибку cat)
```

В Bash для доступа к кодам всех команд в конвейере используется массив `${PIPESTATUS[@]}`:

```bash
cat nonexistent_file | sort
echo "${PIPESTATUS[0]}" # Код cat (1)
echo "${PIPESTATUS[1]}" # Код sort (0)
```

### Стабильность скриптов: set -e и pipefail

Для создания надежных скриптов используются специальные режимы обработки ошибок:

- `set -e` (errexit): Оболочка немедленно прекращает выполнение скрипта, если любая команда возвращает ненулевой код (за исключением проверок в `if`, `while` и логических цепочек).
- `set -o pipefail`: Изменяет поведение конвейеров. Кодом возврата всей цепочки станет код самой правой команды, завершившейся с ошибкой (а не просто последней).

Рекомендуемый "безопасный" заголовок скрипта:
```bash
#!/bin/bash
set -euo pipefail
```

### Разница между exit и return

- **`exit N`**: Завершает работу текущей оболочки (скрипта или сабшелла) с кодом `N`.
- **`return N`**: Завершает выполнение функции или выполнение скрипта, вызванного через `source` (или `.`), возвращая код `N` в вызывающую среду, но **не** завершая основной процесс.

### Команды-заглушки: true и false

В Linux существуют две простейшие встроенные команды, которые не делают ничего, кроме возврата кода:
- `true` (или `:`): Всегда возвращает **0**.
- `false`: Всегда возвращает **1**.

Используются в бесконечных циклах (`while true`) или как значения по умолчанию.

## Практические сценарии

### Проверка в скриптах

```bash
# Идемпотентная проверка наличия пользователя
if grep -q "^admin:" /etc/passwd; then
    echo "Пользователь существует"
else
    # Обработка ошибки поиска (grep вернул 1)
    echo "Пользователь не найден"
fi
```

### Контроль качества в CI/CD

Использование `exit 1` для принудительного прерывания пайплайна при провале тестов или линтеров.

```bash
# Запуск тестов
npm test
if [ $? -ne 0 ]; then
    echo "Тесты провалены! Прекращение сборки."
    exit 1
fi
```

### Логические операторы (&& и ||)

Операторы позволяют строить компактные условия на основе кодов возврата:
- `command1 && command2` — выполнить `command2`, только если `command1` успешна (**0**).
- `command1 || command2` — выполнить `command2`, только если `command1` завершилась ошибкой (**не 0**).
