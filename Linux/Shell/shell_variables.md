# Переменные оболочки: локальные и окружения

## Определения

- **Переменная оболочки (Shell Variable):** Именованное хранилище для хранения данных (строк) в текущем сеансе командной оболочки. Переменные позволяют параметризовать команды и скрипты, делать их более гибкими.
- **Локальная переменная:** Переменная, доступная только в том процессе оболочки, где она была объявлена. Дочерние процессы не наследуют ее автоматически.
- **Переменная окружения (Environment Variable):** Специальный тип переменной оболочки, которая доступна не только в текущем процессе, но и во **всех дочерних процессах**, запущенных из этой оболочки. Переменные окружения формируют "среду" для программ.

## Базовые концепции

### Объявление локальной переменной

- **Синтаксис:** `VAR_NAME="VALUE"`
- **Область видимости:** Только в текущем сеансе или скрипте, где она была создана.
- **Наследование:** Дочерние процессы (например, другие скрипты или команды, запущенные из текущей оболочки) **не унаследуют** эту переменную.

**Пример:**

```bash
# Объявляем локальную переменную
MY_LOCAL_VAR="Hello from local"

# В текущей оболочке она доступна
echo "В текущей оболочке: $MY_LOCAL_VAR"
# Вывод: В текущей оболочке: Hello from local

# Запускаем новый bash-процесс (дочерний) и пытаемся прочитать переменную
bash -c 'echo "В дочернем процессе: $MY_LOCAL_VAR"'
# Вывод: В дочернем процессе:
# (пустая строка, переменная недоступна)
```

### Объявление переменной окружения (`export`)

- **Синтаксис:** `export VAR_NAME="VALUE"` или сначала `VAR_NAME="VALUE"`, затем `export VAR_NAME`.
- **Область видимости:** В текущем процессе оболочки и во **всех его дочерних процессах**.
- **Наследование:** Дочерние процессы наследуют экспортированные переменные родительской оболочки.

**Пример:**

```bash
# Объявляем и экспортируем переменную
export MY_ENV_VAR="Hello from environment"

# В текущей оболочке она доступна
echo "В текущей оболочке: $MY_ENV_VAR"
# Вывод: В текущей оболочке: Hello from environment

# Запускаем новый bash-процесс (дочерний) и пытаемся прочитать переменную
bash -c 'echo "В дочернем процессе: $MY_ENV_VAR"'
# Вывод: В дочернем процессе: Hello from environment
# (переменная доступна)
```

> Подробнее о влиянии контекста выполнения на область видимости переменных (особенно в конвейерах и `source` vs `subshell`) см. в [Выполнение скриптов в Bash: Subshell, Source и Shabang](bash_scripting_execution.md).

## Практические сценарии

### Временное изменение `PATH` для текущего сеанса

`PATH` — это переменная окружения, которая содержит список каталогов, где оболочка ищет исполняемые файлы.

```bash
# Добавить /usr/local/go/bin в PATH для текущего сеанса
export PATH="/usr/local/go/bin:$PATH"

# Проверить новое значение
echo $PATH
```

Если бы `PATH` не был экспортирован, другие команды, запущенные из этой оболочки, не "увидели" бы изменения.

### Передача конфигурации в приложение через переменные окружения

Многие приложения (особенно в контейнерах) используют переменные окружения для настройки.

```bash
# Задать порт для веб-сервера
export APP_PORT=8080

# Запустить приложение (предположим, оно читает APP_PORT)
./my_web_app
```

Таким образом, можно изменять поведение приложения, не модифицируя его код или конфигурационные файлы.

### Расширенная подстановка (Parameter Expansion)

Bash предоставляет механизмы для работы со значениями переменных "на лету".

- **`${VAR:-default}` (Значение по умолчанию):** Если переменная `VAR` не установлена или пуста, использовать `default`. Сама переменная `VAR` при этом не изменяется.

    ```bash
    # Если REGION не задана, будет использовано 'us-east-1'
    echo "Регион: ${REGION:-us-east-1}"
    ```

- **`${VAR:=default}` (Присвоить значение по умолчанию):** Если `VAR` не установлена или пуста, ей присваивается значение `default`.

- **`${VAR:?message}` (Проверка на существование):** Если `VAR` не установлена или пуста, вывести `message` в `stderr` и завершить скрипт. Очень полезно для обязательных параметров.

    ```bash
    # Прервет выполнение, если REQUIRED_VAR не задана
    : "${REQUIRED_VAR?Переменная REQUIRED_VAR не установлена}"
    ```
    
## Дополнительная информация

### Команды для работы с переменными

- **Просмотр:**
  - `set`: Выводит все переменные оболочки (локальные и окружения), функции и опции.
  - `env` или `printenv`: Выводит только переменные окружения.
  - `declare`: Выводит переменные с их атрибутами. `declare -x` показывает экспортированные переменные.
- **Удаление (`unset`):**
  - `unset MY_VAR`: Удаляет переменную (как локальную, так и из окружения).
- **Защита от изменений (`readonly`):**
  - `readonly MY_VAR="value"`: Создает переменную только для чтения.
  - `readonly MY_VAR`: Делает существующую переменную неизменяемой. Попытка изменить ее вызовет ошибку.

### "Чистая" среда с `env -i`

Иногда для тестов или изоляции требуется запустить команду в полностью пустом окружении, без наследования каких-либо переменных.

```bash
# Запустить bash с минимальным окружением
env -i PATH=/usr/bin:/bin bash -c 'env'
```

### Чувствительность к регистру и типы данных

- **Регистр:** Имена переменных чувствительны к регистру (`VAR` и `var` — это разные переменные). По соглашению, переменные окружения именуются в верхнем регистре (`PATH`, `HOME`), а локальные — в нижнем.
- **Типы:** Все переменные окружения являются строками. Массивы и другие структуры данных не могут быть корректно экспортированы и требуют специальной обработки (например, сериализации в строку).

### Часто используемые переменные окружения

- **`PATH`:** Путь поиска исполняемых файлов.
- **`HOME`:** Домашний каталог текущего пользователя.
- **`USER`:** Имя текущего пользователя.
- **`SHELL`:** Путь к текущей командной оболочке.
- **`LANG`:** Локаль системы.
- **`PS1`:** Строка приглашения командной строки (promt).
- **`TERM`:** Тип терминала.
- **`EDITOR` / `VISUAL`:** Редактор по умолчанию.
