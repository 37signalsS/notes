# Переменные оболочки: локальные, окружения и специальные

## Определения

- **Shell Variable (Переменная оболочки)** — именованная область памяти в текущем сеансе Shell, предназначенная для хранения строковых данных или массивов.
- **Local Variable (Локальная переменная)** — переменная, доступная только в текущем процессе оболочки. Не наследуется дочерними процессами.
- **Environment Variable (Переменная окружения)** — переменная, экспортированная в окружение текущего процесса (`export`) и доступная всем его потомкам.
- **Readonly Variable (Переменная только для чтения)** — переменная, которую нельзя изменить или удалить после объявления. Создается через `readonly` или `declare -r`. Атрибут наследуется дочерними процессами.
- **Export (Экспорт)** — пометка переменной флагом, разрешающим наследование дочерними процессами. Реализуется через `export VAR=val` или `declare -x VAR=val`.
- **Массив (Array)** — структура данных для хранения нескольких значений. Бывают индексированные (числовые индексы) и ассоциативные (ключ-значение).
- **Parameter Expansion** — встроенный механизм оболочки для извлечения, манипуляции и проверки значений переменных без вызова внешних утилит (например, `sed` или `awk`).
- **Nameref** — ссылочная переменная (`declare -n`), которая указывает на имя другой переменной, позволяя изменять её значение косвенно.
- **Subshell (Подоболочка)** — дочерний процесс оболочки, создаваемый для изоляции изменений переменных и состояния. В Bash возникает при группировке `( ... )`, в管道 `|`, подстановке процессов `$( ... )` или арности `(( ... ))`.
- **Source (dot command)** — выполнение скрипта в текущем контексте оболочки (`. file.sh` или `source file.sh`), что позволяет скрипту изменять переменные, функции и рабочую директорию вызывающей оболочки.
- **BASH_ENV** — переменная окружения, указывающая путь к файлу, который Bash читает при запуске неинтерактивных скриптов. Аналог `ENV` в POSIX-оболочках.
- **ENV (POSIX)** — переменная окружения в POSIX-совместимых оболочках (`dash`, `ash`, `ksh`, `sh`), аналогичная `BASH_ENV`. Используется в Alpine Linux, BusyBox и BSD.

## Базовые концепции

### Типы переменных и область видимости

| Тип | Команда | Наследование | Описание |
| :--- | :--- | :--- | :--- |
| **Локальная** | `VAR="val"` | Нет | Доступна только в текущем экземпляре Shell. |
| **Функциональная** | `local VAR="val"` | Нет | Доступна только внутри функции (Bash/Zsh). |
| **Readonly** | `readonly VAR="val"` или `declare -r VAR="val"` | Нет | Значение нельзя изменить или `unset` после объявления. Атрибут наследуется дочерними процессами. |
| **Окружения** | `export VAR="val"` | Да | Доступна текущему Shell и всем дочерним процессам. |

### Управление переменными: env, set, unset

- **`env`**: Выводит список всех переменных окружения.
- **`printenv`**: Аналог `env`, позволяет вывести значение конкретной переменной (`printenv PATH`).
- **`set`**: Выводит все переменные (окружения и локальные) и функции оболочки. Также используется для установки флагов оболочки (`set -e`).
- **`unset VAR`**: Удаляет переменную или функцию из текущей сессии.
- **`export -n VAR`**: Убирает флаг экспорта; переменная становится локальной.
- **`readonly VAR`**: Создает неизменяемую переменную. Эквивалентно `declare -r VAR`. Атрибут наследуется дочерними процессами, но они не могут изменить значение.
- **`readonly -a ARRAY`**: Делает весь массив доступным только для чтения.
- **`readonly -p`**: Выводит список всех readonly-переменных.
- **`set -a`** (`set -o allexport`): Автоматически экспортировать все переменные, объявленные после этой команды. Удобно при чтении env-файлов через `source` или `.`.
- **`set +a`**: Отключает автоматический экспорт.
- **`env -i CMD`**: Запускает команду с полностью пустым окружением. В GNU `env` даже `PATH` отсутствует, что гарантирует чистый запуск. Критично для воспроизводимых CI/CD-скриптов и тестов.
- **`env -u VAR CMD`**: Запускает команду, явно исключая `VAR` из окружения. Полезно для проверки, что программа не полагается на чувствительные переменные.
- **`env -C /dir CMD`**: Запускает команду, изменив рабочую директорию без использования `cd` в оболочке.
- **`env -S 'cmd arg1' -S 'arg2'`**: Разделяет строку команды на отдельные аргументы (GNU extension). Полезно при динамическом построении команд с переменными окружения.

### Переменные управления поведением Shell

- **`BASH_ENV`**: Путь к файлу, который Bash читает при запуске неинтерактивных скриптов. Позволяет инициализировать функции, алиасы и переменные в cron, systemd-юнитах и CI/CD-раннерах. Значение не наследуется автоматически — каждая новая оболочка читает его заново.
- **`ENV` (POSIX)**: Аналог `BASH_ENV` для POSIX-оболочек (`dash`, `ash`, `ksh`). Используется в Alpine Linux, BusyBox и BSD-системах.
- **`POSIXLY_CORRECT`**: Если установлена, GNU-утилиты и Bash переходят в строго POSIX-режим. В Bash отключает расширения Parameter Expansion, изменяет поведение `echo`, `test`, `[` и `[[`. Используется для проверки совместимости скриптов.

### Атрибуты и команда declare

Команда `declare` (или `typeset`) задает тип и поведение переменной:

- `declare -i VAR`: Целое число. Присваивание строки вызовет арифметическое вычисление.
- `declare -r VAR`: Только для чтения (Read-only). Нельзя изменить или `unset`.
- `declare -x VAR`: Экспортировать в окружение.
- `declare -u VAR`: Автоматический перевод в ВЕРХНИЙ регистр.
- `declare -l VAR`: Автоматический перевод в нижний регистр.
- `declare -a / -A`: Индексированный / ассоциативный массивы.

### Специальные и встроенные переменные

Обновляются оболочкой автоматически:

| Переменная | Описание |
| :--- | :--- |
| **`$?`** | Код возврата последней команды ([подробнее](./exit_codes.md)). |
| **`$$`** | PID текущего процесса оболочки. |
| **`$!`** | PID последнего фонового процесса. |
| **`$0`** | Имя скрипта или оболочки. |
| **`$1, $2...`** | Позиционные параметры (аргументы скрипта). |
| **`$#`** | Количество переданных аргументов. |
| **`$-`** | Текущие флаги оболочки (например, `himBH`). |
| **`$_`** | Последний аргумент предыдущей команды. |
| **`$IFS`** | Разделитель полей (Internal Field Separator). По умолчанию: пробел, табуляция, новая строка. |
| **`$PATH`** | Список директорий для поиска исполняемых файлов. |
| **`$PWD`** | Текущая рабочая директория (логический путь, может содержать симлинки). |
| **`$OLDPWD`** | Предыдущая рабочая директория. Используется командой `cd -`. |
| **`$HOME`** | Домашняя директория текущего пользователя. |
| **`$SHELL`** | Путь к оболочке, указанной в `/etc/passwd` (login-оболочка). |
| **`$SHLVL`** | Уровень вложенности оболочки. Увеличивается при каждом `bash` внутри `bash`. |
| **`$UID`** | Численный ID реального пользователя. |
| **`$EUID`** | Эффективный UID (меняется после `sudo`). |
| **`$GROUPS`** | Массив численных IDs групп, в которых состоит пользователь. |
| **`$RANDOM`** | Псевдослучайное целое число от 0 до 32767. `unset RANDOM` отключает генерацию. |
| **`$SECONDS`** | Количество секунд с момента запуска оболочки. |
| **`$LINENO`** | Номер текущей строки в скрипте или функции. |
| **`$BASH_SUBSHELL`** | Уровень вложенности subshell (0 в основной оболочке, увеличивается при `( ... )` и `$()`). |
| **`$BASH_COMMAND`** | Команда, которая выполняется в данный момент. Полезна в `trap DEBUG`. |
| **`$FUNCNAME`** | Массив имен функций, текущая функция в `${FUNCNAME[0]}`, родительская в `${FUNCNAME[1]}`, и т.д. |
| **`$BASH_SOURCE`** | Массив путей к исходникам функций/скриптов. Вместе с `$FUNCNAME` используется для трассировки стека. |
| **`$EPOCHSECONDS`** | Unix-timestamp (Bash 5.0+). Количество секунд с 1970-01-01 UTC. |
| **`$COMP_LINE`** / **`$COMP_POINT`** | Текущая строка и позиция курсора при автодополнении. Используются в кастомных completion-функциях. |

## Массивы в Bash

### Индексированные массивы

```bash
# Инициализация
declare -a APPS=("nginx" "redis" "postgres")
APPS+=("memcached") # Добавление

# Доступ
echo "${APPS[0]}"    # → nginx
echo "${APPS[@]}"    # → все элементы
echo "${#APPS[@]}"   # → 4 (длина массива)
echo "${!APPS[@]}"   # → 0 1 2 3 (индексы)

# Слайсинг (извлечение подмножества)
echo "${APPS[@]:1:2}" # → redis postgres

# Копирование массива
declare -a COPY=("${APPS[@]}")

# Read-only массив (Bash 4.2+)
declare -ar SERVICES=("cron" "sshd" "rsyslog")

# Удаление элемента (Bash 4.4+)
unset 'APPS[1]'       # удаляет "redis"
```

### Ассоциативные массивы (Bash 4.0+)

```bash
declare -A HOSTS
HOSTS=( ["srv1"]="10.0.0.1" ["srv2"]="10.0.0.2" )

echo "${HOSTS[srv1]}" # → 10.0.0.1

# Все ключи и значения
echo "${!HOSTS[@]}"   # → srv1 srv2
echo "${HOSTS[@]}"    # → 10.0.0.1 10.0.0.2

# Read-only ассоциативный массив
declare -Ar PORTS=( [http]=80 [https]=443 [ssh]=22 )

# Копирование ассоциативного массива
declare -A HOSTS_COPY
HOSTS_COPY=("${HOSTS[@]}")
```

### Чтение строк в массив: `mapfile` / `readarray`

```bash
# Читать вывод команды в массив (каждая строка — элемент)
mapfile -t SERVICES < <(systemctl list-unit-files --type=service --state=enabled --no-pager --no-legend | awk '{print $1}')

# Или с таймаутом и обработкой ошибок
mapfile -t -n 100 LINES < /var/log/nginx/access.log
```

## Parameter Expansion: манипуляция данными

Эффективная обработка строк средствами Shell.

| Синтаксис | Назначение |
| :--- | :--- |
| **`${VAR:-def}`** | Использовать `def`, если `VAR` пуста или не задана. |
| **`${VAR:=def}`** | Присвоить `def`, если `VAR` пуста (не работает для позиционных параметров). |
| **`${VAR:+alt}`** | Использовать `alt`, если `VAR` **не** пуста. |
| **`${VAR:?err}`** | Вывести `err` и выйти, если `VAR` пуста. |
| **`${#VAR}`** | Длина строки. |
| **`${VAR:off:len}`** | Извлечение подстроки. |
| **`${VAR#pat}`** / **`${VAR##pat}`** | Удалить кратчайший / длиннейший префикс. |
| **`${VAR%pat}`** / **`${VAR%%pat}`** | Удалить кратчайший / длиннейший суффикс. |
| **`${VAR/pat/str}`** | Заменить первое вхождение `pat` на `str`. |
| **`${VAR//pat/str}`** | Заменить все вхождения. |
| **`${VAR^}`** / **`${VAR^^}`** | В верхний регистр (первая буква / всё). |
| **`${VAR,}`** / **`${VAR,,}`** | В нижний регистр (первая буква / всё). |
| **`${VAR@Q}`** | Значение переменной, экранированное для повторного ввода (Quoted). |
| **`${!prefix*}`** / **`${!prefix@}`** | Имена всех переменных, начинающихся с `prefix`. `*` — одна строка через `$IFS`, `@` — отдельные имена. |
| **`${!NAME[@]}`** | Если `NAME` — массив, возвращает индексы. Если это имя переменной, возвращает значение переменной, на которую указывает `NAME` (косвенная ссылка). |
| **`${VAR@a}`** | Строка атрибутов переменной (`a` — array, `i` — integer, `r` — readonly, `x` — export). |
| **`${VAR@E}`** | Интерпретировать escape-последовательности (`\n`, `\t`). |
| **`${VAR@P}`** | Результат как имя переменной (promotion). |

## Практические сценарии

### Динамические переменные (Nameref)

Позволяет передавать массивы или изменять переменные внутри функций "по ссылке".

```bash
#!/bin/bash
function update_config() {
    declare -n target=$1
    target="new_configuration_value"
}

MY_CONF="old"
update_config MY_CONF
echo "$MY_CONF" # → new_configuration_value
```

### Парсинг путей и расширений

```bash
FILE="/var/log/nginx/access.log.gz"

echo "${FILE##*/}"   # → access.log.gz (basename)
echo "${FILE%/*}"    # → /var/log/nginx (dirname)
echo "${FILE%%.*}"   # → /var/log/nginx/access (путь без всех расширений)
echo "${FILE#*.}"    # → log.gz (только расширения)
```

### Безопасное использование переменных в скриптах

```bash
# Прекратить работу, если переменная не задана
: "${DB_URL:?Ошибка: DB_URL не определена}"

# Установка значения по умолчанию для опционального параметра
LOG_LEVEL="${LOG_LEVEL:-INFO}"
```

### Минимизация окружения для воспроизводимых запусков

```bash
# Запустить команду с чистым окружением (только PATH в некоторых реализациях,
# в GNU env даже PATH отсутствует — добавляйте явно)
env -i HOME="$HOME" USER="$USER" PATH="/usr/local/bin:/usr/bin:/bin" /usr/bin/python3 /opt/script.py

# Исключить чувствительную переменную из окружения дочернего процесса
env -u VAULT_TOKEN -- kubectl get pods -n production
```

### Сериализация и десериализация переменных

```bash
# Сохранить состояние переменных в файл (удобно для кеширования конфигураций)
declare -p CONFIG > /etc/myapp/.config.vars

# Восстановить
source /etc/myapp/.config.vars

# Сериализовать массив
declare -p SERVICES > /tmp/services.backup
```

### Передача массивов в функции

```bash
#!/bin/bash
process_services() {
    local -a services=("$@")  # Все аргументы как элементы массивы
    for svc in "${services[@]}"; do
        echo "Checking: $svc"
    done
}

SERVICES=("nginx" "redis" "postgres")
process_services "${SERVICES[@]}"
```

### Защита критичных констант через `readonly`

```bash
#!/bin/bash
readonly BASE_DIR="/srv/data"
readonly MAX_RETRIES=5

# Попытка изменения приведёт к ошибке и завершению скрипта
BASE_DIR="/tmp"  # bash: BASE_DIR: readonly variable
```

### Диагностика области видимости и subshell

```bash
#!/bin/bash
VAR="global"

show_var() {
    echo "Внутри функции: VAR=$VAR"
}

(   # Subshell: изменения здесь не влияют на родительскую оболочку
    VAR="subshell"
    show_var
    echo "После функции в subshell: VAR=$VAR"
)

echo "После subshell: VAR=$VAR"  # → global (не изменилось!)
```

> **SRE-заметка:** При отладке скриптов проверяйте, не попадаете ли вы в subshell неявно:
> - `cmd | while read line; do ...; done` — `while` выполняется в subshell, переменные внутри него не сохраняются.
> - `$(command)` — результат в subshell.
> - `(cd /tmp && cmd)` — изолированная смена директории.

## Дополнительная информация

### Жизненный цикл переменных (Dotfiles)

1.  **`/etc/environment`**: Статические пары `KEY=VALUE`, загружаемые PAM при входе (не скрипт!).
2.  **`~/.bash_profile`** / **`~/.profile`**: Выполняются один раз при логине (Login Shell). Место для `export PATH`.
3.  **`~/.bashrc`**: Выполняется для каждого нового окна терминала (Interactive Non-login Shell). Место для алиасов и функций.
4.  **`$BASH_ENV`**: Для неинтерактивных скриптов (cron, systemd, CI/CD). Указывает файл, который Bash читает как `.bashrc`.
5.  **`$ENV`** (POSIX): Для POSIX-оболочек в неинтерактивном режиме. Используется в Alpine, BusyBox.

> **SRE-заметка:** При настройке CI/CD-раннеров или Bastion-хостов проверяйте, какой тип сессии инициирует SSH (`ssh -t user@host 'bash -l -c "echo test"'` для принудительного login-режима). Отсутствие ожидаемого dotfile — частая причина неработающих алиасов, функций или `$PATH`.

### Область видимости: Subshell, Source, Exec

- **Subshell** `( ... )`: Изолированный дочерний процесс. Изменения переменных, `cd`, `umask` внутри него не затрагивают родительскую оболочку.
- **Source** `. file.sh` / `source file.sh`: Выполнение в текущем контексте. Скрипт может изменять переменные, функции и `cd`. Используется для активации виртуальных окружений (`source .venv/bin/activate`).
- **Exec** `exec env -i CMD`: Полная замена текущего процесса Shell на команду с новым окружением. Shell завершается, PID сохраняется. Используется для запуска init-процессов (systemd, Docker entrypoint) или запуска команды с очищенным окружением без лишнего процесса.
- **Практическое правило:** Если скрипт должен настроить среду для текущего пользователя — используйте `source`. Если он должен запустить изолированный процесс — используйте `( ... )` или `env -i`.

### Отладка переменных

- **`declare -p VAR`**: Вывести объявление переменной с её значением и атрибутами в синтаксисе, пригодном для повторного использования. Критично для отладки сложных структур.
- **`set -x` / `set +x`**: Включить/выключить трассировку выполнения. Показывает каждую команду перед выполнением. Для локализации проблемной строки используйте кастомный `PS4` ([подробнее](./shell_intro.md)).
- **`set -o nounset`** (`set -u`): Завершить скрипт при обращении к неопределенной переменной. Ловит опечатки в именах переменных.
- **`set -o errexit`** (`set -e`): Завершить скрипт при ненулевом коде возврата любой команды (если не в условиях `&&`/`||`).

### Переносимость: Bash vs POSIX

- **`typeset`**: Синоним `declare` в Bash и Zsh. В некоторых POSIX-оболочках (`ksh`) это основной способ объявления. Для максимальной переносимости используйте `export VAR=val` для простых переменных.
- **`BASH_SOURCE` vs `$0`**: `$0` возвращает имя скрипта только при прямом запуске. При `source` — имя вызывающей оболочки. `BASH_SOURCE` работает корректно и при `source`, и при прямом запуске, но есть только в Bash.
- **Ассоциативные массивы**: Доступны в Bash 4.0+ и Zsh. В POSIX `sh` и `dash` отсутствуют. Для переносимых скриптов используйте индексированные массивы или внешние утилиты (`awk`, `join`).
- **`ENV` vs `BASH_ENV`**: В Debian/Ubuntu `/bin/sh` — это `dash`, который читает `ENV`. В RHEL/CentOS/Fedora `/bin/sh` — `bash` в POSIX-режиме, который читает `BASH_ENV`. Для кросс-дистрибутивных скриптов устанавливайте обе переменные.

### Различия `"$*"` и `"$@"`

Имеют значение только в двойных кавычках:
- **`"$*"`**: Все аргументы как **одна строка**, разделенная первым символом `$IFS`.
- **`"$@"`**: Каждый аргумент как **отдельное слово**. Рекомендуется для циклов `for`.

> **SRE-заметка:** При передаче аргументов, содержащих пробелы или спецсимволы (например, путей к файлам или JSON-строк), всегда используйте `"$@"`. Использование `"$*"` оправдано только при явном необходимости склеить все аргументы в одну строку.
