# cut и wc

## Определения

- **cut** — утилита для извлечения_selected полей (колонок) или диапазонов байт/символов из каждой строки входного потока или файла. Входит в состав GNU coreutils. Работает как фильтр: не изменяет исходный файл, а выводит результат в `stdout`.
- **wc** (Word Count) — утилита для подсчета количества строк, слов, байт или символов во входном потоке или файлах. Чаще всего в DevOps/SRE используется для подсчета строк (`wc -l`), реже — для оценки размера данных (`wc -c`).
- **Поле (Field)** — часть строки, ограниченная разделителем (delimiter). В контексте `cut` под полем понимается диапазон символов между двумя последовательными разделителями.
- **Разделитель (Delimiter)** — символ или строка, определяющие границы полей в данных с фиксированной структурой (например, `:` в `/etc/passwd`, `,` в CSV).
- **Диспетчер строк (Line Discipline)** — механизм ядра, обрабатывающий ввод символов. Важен для понимания того, почему `wc -l` считает переводы строки (`\n`), а не "строки" в человеческом понимании.

## Базовые концепции

### cut: извлечение полей и символов

`cut` не является полноценным парсером CSV/TSV — он работает с одним символом-разделителем и не поддерживает quoted fields (поля в кавычках). Для сложных форматов используйте `awk` или `csvkit`.

#### Синтаксис

```text
cut ОПЦИЯ... [ФАЙЛ]...
```

#### Ключевые опции

| Опция | Длинная форма | Назначение |
| :--- | :--- | :--- |
| `-d СИМВОЛ` | `--delimiter=СИМВОЛ` | Указать разделитель полей (один байт). По умолчанию — TAB (`\t`). |
| `-f СПИСОК` | `--fields=СПИСОК` | Извлечь указанные номера полей. |
| `-b СПИСОК` | `--bytes=СПИСОК` | Извлечь указанные позиции байт. |
| `-c СПИСОК` | `--characters=СПИСОК` | Извлечь указанные позиции символов (multibyte-safe). |
| `-s` | `--only-delimited` | Игнорировать строки без разделителя. Без этого флага строки без делимитера выводятся целиком. |
| | `--output-delimiter=СТРОКА` | Заменить стандартный разделитель (`\t`) на указанную строку в выводе. |

#### Списки полей и диапазонов

Список в `-f` и `-b`/`-c` поддерживает гибкий синтаксис:

- `1,3,5` — отдельные поля/позиции
- `1-4` — диапазон от 1 до 4 включительно
- `1-3,5` — комбинация диапазона и одиночного значения
- `-3` — с первого по третье
- `5-` — с пятого до конца
- `1,3-5,7` — произвольная комбинация

```bash
# Извлечь 1-е и 3-е поля, заменить двоеточие на вертикальную черту
cut -d: -f1,3 --output-delimiter='|' /etc/passwd

# Извлечь символы с 1 по 10 включительно (полезно для коротких хэшей)
cut -c1-10 /proc/cpuinfo
```

#### Различие между `-b` и `-c`

- **`-b` (bytes)**: работает с сырыми байтами. В многобайтовых кодировках (UTF-8) символ может занимать несколько байт. `cut -b` может "разрезать" символ посередине, получив невалидный UTF-8.
- **`-c` (characters)**: работает с символами (characters), учитывая многобайтовость. Безопаснее для работы с Unicode-текстом.

```bash
# Опасный пример: разрез UTF-8 символа
echo "привет" | cut -b1-3
# → повреждённый вывод (некорректный UTF-8)

# Безопасный вариант
echo "привет" | cut -c1-3
# → прив
```

#### Поведение с отсутствующим разделителем

По умолчанию `cut` без флага `-s` выводит строку целиком, если разделитель в ней отсутствует. Это может привести к неожиданным результатам при фильтрации "грязных" данных.

```bash
# Файл с mixed delimiters: нормальные строки и строка без двоеточия
printf "alice:x:1000:1000::/home/alice:/bin/bash\ndata_without_colons\nbob:x:1001:1001::/home/bob:/bin/bash" > mixed.txt

# Без -s: строка без разделителя попадает в вывод целиком
cut -d: -f1 mixed.txt
# → alice
# → data_without_colons
# → bob

# С -s: только строки с разделителем
cut -d: -f1 -s mixed.txt
# → alice
# → bob
```

### wc: подсчет строк, слов и байт

`wc` — одна из немногих утилит, которая корректно работает с несколькими входными файлами, выводя индивидуальные счетчики для каждого файла и итоговую сумму.

#### Синтаксис

```text
wc [ОПЦИЯ]... [ФАЙЛ]...
wc [ОПЦИЯ]... < ФАЙЛ
```

#### Ключевые опции

| Опция | Длинная форма | Назначение |
| :--- | :--- | :--- |
| `-l` | `--lines` | Количество переводов строк (`\n`). Самый частый сценарий. |
| `-w` | `--words` | Количество слов (последовательности символов, разделенных пробелом/табуляцией/переводом строки). |
| `-c` | `--bytes` | Количество байт в файле/потоке. |
| `-m` | `--chars` | Количество символов (multibyte-aware). Для UTF-8 может отличаться от `-c`. |
| `-L` | `--max-line-length` | Длина самой длинной строки (в байтах). |

#### Как wc считает строки

`wc -l` считает количество символов перевода строки (`\n`), а не "строк" в смысле текстового редактора. Если последняя строка файла не заканчивается переводом строки, `wc -l` не учтёт её. Это стандартное поведение POSIX.

```bash
# Файл без завершающего \n
printf "строка1\nстрока2" > no_newline.txt
wc -l no_newline.txt
# → 1        # хотя визуально строк две

# Добавляем завершающий перевод строки
printf "строка1\nстрока2\n" > with_newline.txt
wc -l with_newline.txt
# → 2
```

#### Различие между `-c` и `-m`

- **`-c` (bytes)**: возвращает точный размер в байтах. Для ASCII-файлов совпадает с `-m`. Для UTF-8 с кириллицей/эмодзи — каждый символ может занимать 2–4 байта.
- **`-m` (chars)**: возвращает количество символов Unicode.

```bash
# UTF-8 строка с русскими символами (каждый символ = 2 байта)
echo "Привет" | wc -c
# → 13  (6 символов + \n = 7 * 2 байта в UTF-8? нет, в CP1251/UTF-8 по-разному)
# На практике: в UTF-8 "П" = 0xD0 0x41 = 2 байта, итого 12+1=13

echo "Привет" | wc -m
# → 7    (6 букв + 1 перевод строки)
```

## Практические сценарии

### Извлечение пользователей из /etc/passwd

Файл `/etc/passwd` использует двоеточие как разделитель. Первое поле — имя пользователя, шестое — домашний каталог, седьмое — оболочка.

```bash
# Все имена пользователей (первое поле)
cut -d: -f1 /etc/passwd
# → root
# → daemon
# → alice
# → bob

# Имена и оболочки (первое и седьмое поля)
cut -d: -f1,7 --output-delimiter=' → ' /etc/passwd
# → root → /bin/bash
# → alice → /usr/bin/zsh

# Домашние каталоги пользователей с UID >= 1000 (обычные пользователи)
awk -F: '$3 >= 1000 {print $1, $6}' /etc/passwd
```

### Подсчет пользователей с конкретной оболочкой

Классический экзаменационный сценарий LPIC-1: конвейер для фильтрации и подсчета.

```bash
# Сколько пользователей используют bash?
grep '/bin/bash$' /etc/passwd | wc -l
# → 5

# Количество уникальных оболочек в системе
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
# →     12 /bin/bash
# →      3 /usr/bin/zsh
# →      1 /sbin/nologin
```

### Анализ логов и текстовых данных

```bash
# Подсчет записей в системном логе
wc -l /var/log/syslog
# → 1247 /var/log/syslog

# Количество процессов, запущенных текущим пользователем
ps -u $USER -o comm= | wc -l
# → 23

# Подсчет файлов в текущей директории (включая скрытые)
ls -A1 | wc -l
# → 47

# Извлечение IP-адресов из логов nginx (последнее поле перед статус-кодом)
awk '{print $1}' /var/log/nginx/access.log | cut -d. -f1-4 | sort | uniq -c | sort -rn | head
```

### Работа с CSV и делимитерными данными

```bash
# Извлечение второго столбца из CSV (с заголовком)
head -1 data.csv | cut -d',' -f2
# → "email"

# Пропустить заголовок и извлечь email'ы всех пользователей
tail -n +2 data.csv | cut -d',' -f2
```

### Сравнение размеров сжатия (связка с tar/gzip)

```bash
# Оценка степени сжатия перед архивацией
echo "Тестовый текст для сжатия" | gzip | wc -c
# → 28

echo "Тестовый текст для сжатия" | bzip2 | wc -c
# → 45
```

### Извлечение версий из заголовков файлов

```bash
# JWT: декодирование payload (второе поле между точками)
echo "$TOKEN" | cut -d. -f2 | base64 -d 2>/dev/null | python3 -m json.tool

# SemVer: выделение major/minor/patch из тега
echo "v2.14.3" | cut -d. -f1 | sed 's/v//'
# → 2
```

## Дополнительная информация

### cut vs awk vs sed: когда что использовать

| Критерий | cut | awk | sed |
| :--- | :--- | :--- | :--- |
| **Разделитель** | Один символ | Любая строка (FS) | Требует ручного парсинга |
| **Логика** | Только выборка | Полноценный язык (условия, циклы, массивы) | Замена/удаление по regex |
| **Quoted fields** | Нет | Да | Нет |
| **Производительность** | Высокая (C, простая логика) | Средняя | Средняя |
| **Сложный парсинг** | Нет | Да | Ограниченно |

**Правило выбора:**
- `cut` — для быстрого вырезания колонок из простых delimiter-separated файлов (`/etc/passwd`, простые CSV без кавычек).
- `awk` — когда нужна логика (условия, вычисления, работа с несколькими файлами).
- `sed` — для замены текста, удаления строк, сложной трансформации.

### wc и конвейеры: нюансы подсчета

Когда `wc` читает из `stdin` (через pipe), она не знает имени файла и выводит только число:

```bash
ls | wc -l
# → 42

# Эквивалент с явным указанием файла
wc -l <(ls)
# → 42 /dev/fd/63
```

**Важно:** `wc -l` считает переводы строки. Если команда в начале конвейера выводит данные без завершающего `\n`, счет будет неверным.

### Ограничения cut в экзаменационных вопросах LPIC-1

На экзамене LPIC-1 (103.2) часто проверяют:
- `-d` — указание разделителя (это **ключевой** флаг, его забыть нельзя).
- `-f` — выбор поля (не путать с `-F`, который используется в `grep` для fixed-strings).
- `-b` — выбор позиций байт (не символов).
- `-s` — подавление строк без разделителя.

Частая ловушка: путать `cut -f` с `cut -F`. В `cut` флаг `-F` отсутствует — используется строчная `-f`.

Ещё одна типичная экзаменационная ловушка (LPIC-1 103.2) — перепутать **символ** (`-c`/`-b`) с **колонкой/полем** (`-f`):
- `cut -c3` вырезает **третий символ** каждой строки (позицию), а не третью колонку.
- `cut -d',' -f3` вырезает **третье поле (колонку)** по разделителю-запятой.
- При анализе CSV/разделённых данных всегда используйте связку `-d` (разделитель) + `-f` (номер поля); `-c` применяйте только для выборки фиксированных позиций символов (например, коротких хэшей).
