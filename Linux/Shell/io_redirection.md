# Перенаправление ввода-вывода в Shell

## Определения

- **Redirection (Перенаправление)** — механизм Shell для изменения стандартных источников ввода и потоков вывода команд.
- **Standard Streams (Стандартные потоки)** — три потока данных, доступные каждой программе по умолчанию:
  - **`stdin` (Standard Input, дескриптор `0`)** — стандартный ввод (по умолчанию — клавиатура).
  - **`stdout` (Standard Output, дескриптор `1`)** — стандартный вывод основного результата (по умолчанию — терминал).
  - **`stderr` (Standard Error, дескриптор `2`)** — стандартный поток сообщений об ошибках (по умолчанию — терминал).
- **File Descriptor (Файловый дескриптор)** — неотрицательное целое число, используемое ядром для идентификации открытого файла или потока данных.

## Основные концепции

### Перенаправление потока вывода (stdout)

- `команда > файл` — запись `stdout` в файл с его предварительной очисткой (перезапись).
- `команда >> файл` — добавление `stdout` в конец существующего файла.

```bash
ls -l > output.txt
echo "Append this line" >> output.txt
```

### Перенаправление потока ошибок (stderr)

- `команда 2> файл` — перенаправление только `stderr` (дескриптор `2`) в файл.

```bash
ls /nonexistent_directory 2> errors.log
```

### Одновременное перенаправление stdout и stderr

Существует два способа направить оба потока в один файл:

1. **POSIX-совместимый способ (классический):**

   ```bash
   команда > file.log 2>&1
   ```

   *Порядок важен: сначала `stdout` направляется в файл, затем `stderr` (2) перенаправляется туда же, куда направлен `stdout` (1).*

2. **Bash-специфичный способ (сокращенный):**

   ```bash
   команда &> file.log
   ```

   *Аналогично `&>> file.log` для добавления в конец файла.*

### Перенаправление стандартного ввода (stdin)

- `команда < файл` — чтение данных из файла вместо клавиатуры.

```bash
sort < names.txt
```

### Подавление вывода через `/dev/null`

Файл `/dev/null` («черная дыра») используется для игнорирования ненужного вывода.

```bash
# Подавление и вывода, и ошибок
команда > /dev/null 2>&1
```

## Практические сценарии

### Одновременный вывод на экран и в файл (`tee`)

Утилита `tee` читает `stdin` и записывает его одновременно в `stdout` (экран) и один или несколько файлов.

```bash
# Просмотр процесса выполнения с одновременным логированием
./deploy_script.sh | tee deploy.log

# Использование с флагом -a для дописывания в лог
./deploy_script.sh | tee -a deploy.log
```

### Here-documents (`<<`)

Используется для передачи многострочного текстового блока в `stdin` команды. Часто применяется для создания конфигурационных файлов.

```bash
cat <<EOF > config.json
{
  "name": "myapp",
  "version": "1.0.0"
}
EOF
```

### Here-strings (`<<<`)

Удобный способ передачи строки в `stdin` команды без использования `echo` и конвейера.

```bash
# Поиск подстроки в переменной
grep "error" <<< "$LOG_MESSAGE"
```

### Опасность обнуления файлов при перенаправлении

Распространенная ошибка — попытка записи результата команды в тот же файл, из которого она читает (например, `grep "pattern" file > file`). Поскольку оболочка обрабатывает перенаправление (`>`) **до** запуска самой команды, файл будет обнулен еще до того, как программа начнет чтение.

Подробный разбор и безопасные альтернативы (использование `sponge`, временных файлов или `sed -i`) описаны в разделе [Опасность `grep file > file`](./grep.md#опасность-grep-file--file).
