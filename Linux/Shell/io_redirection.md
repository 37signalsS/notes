# Перенаправление ввода-вывода в Shell

## Определения

- **Redirection (Перенаправление)** — механизм командной оболочки, позволяющий изменять стандартные источники ввода и потоки вывода команд.
- **Стандартные потоки (Standard Streams)** — три основных канала данных, открытых для каждого процесса по умолчанию:
  - **`stdin` (fd 0)** — стандартный ввод (источник данных).
  - **`stdout` (fd 1)** — стандартный вывод (основной результат).
  - **`stderr` (fd 2)** — стандартный поток ошибок (диагностические сообщения).
- **Файловый дескриптор (File Descriptor, fd)** — целое число, используемое операционной системой для ссылки на открытый ресурс (файл, сокет, канал).

---

## Базовые концепции

### Перенаправление вывода (stdout и stderr)

Оболочка позволяет направлять данные в файлы или другие ресурсы.

| Оператор | Назначение | Пример |
| :--- | :--- | :--- |
| `>` | Перезапись файла выводом `stdout` | `ls > files.txt` |
| `>>` | Добавление вывода `stdout` в конец файла | `echo "log" >> app.log` |
| `2>` | Перенаправление только ошибок (`stderr`) | `ls /root 2> error.log` |
| `2>>` | Добавление ошибок в конец файла | `cmd 2>> error.log` |
| `&>` | Перенаправление и `stdout`, и `stderr` одновременно (Bash) | `cmd &> all.log` |
| `&>>` | Добавление обоих потоков в конец файла | `cmd &>> all.log` |

### Перенаправление ввода (stdin)

| Оператор | Назначение | Описание |
| :--- | :--- | :--- |
| `<` | Чтение из файла | Команда получает содержимое файла вместо ввода с клавиатуры. |
| `<<` | **Heredoc** | Передача многострочного текстового блока в `stdin`. |
| `<<<` | **Herestring** | Передача строки (результата переменной) в `stdin`. |

## Продвинутая работа с дескрипторами

### Порядок перенаправления (Почему `2>&1 >file` не работает?)

Оболочка обрабатывает перенаправления **слева направо**. Это критически важно при объединении потоков.

- **ПРАВИЛЬНО:** `command > file.log 2>&1`
  1. `1` (stdout) направляется в `file.log`.
  2. `2` (stderr) направляется туда, куда в данный момент указывает `1` (т.е. в `file.log`).
- **НЕПРАВИЛЬНО:** `command 2>&1 > file.log`
  1. `2` направляется туда, куда указывает `1` (в данный момент — на экран).
  2. `1` направляется в `file.log`.
  *Результат: ошибки уйдут на экран, а основной вывод — в файл.*

### Использование кастомных дескрипторов (3-9)

Вы можете открывать собственные каналы данных для временного хранения или записи в разные файлы внутри скрипта через команду `exec`.

```bash
# Открытие дескриптора 3 для записи в файл
exec 3> custom_output.log

# Запись через дескриптор 3
echo "Запись в лог через fd 3" >&3

# Закрытие дескриптора
exec 3>&-
```

### Сетевые перенаправления (/dev/tcp и /dev/udp)

Bash позволяет перенаправлять данные напрямую в TCP/UDP сокеты, что полезно для простых проверок доступности без `nc` или `telnet`.

```bash
# Проверка доступности порта 80 на google.com
(echo > /dev/tcp/google.com/80) &>/dev/null && echo "Port is open"

# Отправка UDP пакета
echo "Hello" > /dev/udp/127.0.0.1/5000
```

## Практические сценарии

### Подавление вывода ("Черная дыра")

Использование специального устройства `/dev/null` для игнорирования ненужной информации.

```bash
# Игнорировать ошибки, но видеть результат
ls -l /root 2> /dev/null

# Полная тишина (подавление всего вывода)
command &> /dev/null
```

### Одновременный вывод и запись (`tee`)

Утилита `tee` позволяет "разветвлять" поток: данные идут и в файл, и в `stdout`.

```bash
# Просмотр логов в реальном времени с сохранением
tail -f access.log | grep "404" | tee -a 404_errors.log
```

### Безопасное обновление файла через перенаправление

Никогда не используйте `command < file > file`, так как файл будет обнулен до начала чтения.
**Безопасные варианты:**

1. Временный файл: `sort < a.txt > a.tmp && mv a.tmp a.txt`
2. Утилита `sponge` (moreutils): `sort < a.txt | sponge a.txt`
3. Редактирование на месте: `sed -i 's/old/new/g' a.txt`

## Дополнительная информация

### Буферизация и производительность

При перенаправлении вывода в файлы ядро ОС может буферизировать данные. Если требуется мгновенная запись (например, для отладки), используйте `stdbuf` или `unbuffer`.
