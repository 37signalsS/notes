# Перенаправление ввода-вывода в Shell

### Определения

*   **Перенаправление (Redirection)** — это механизм в командной оболочке, который позволяет изменять стандартные источники ввода и вывода для команд.
*   **Стандартные потоки (Standard Streams)** — три потока данных, которые по умолчанию доступны каждой программе:
    *   **`stdin` (стандартный ввод, дескриптор `0`)**: Источник данных для команды, по умолчанию — клавиатура.
    *   **`stdout` (стандартный вывод, дескриптор `1`)**: Место, куда команда отправляет свой основной результат, по умолчанию — терминал.
    *   **`stderr` (стандартный вывод ошибок, дескриптор `2`)**: Место, куда команда отправляет сообщения об ошибках, по умолчанию — терминал.
*   **Файловый дескриптор (File Descriptor)** — неотрицательное целое число, которое ядро использует для идентификации открытого файла или потока данных.

### Основные концепции

#### 1. Перенаправление вывода (`stdout`)

*   `команда > файл`: Перенаправляет `stdout` в `файл`, **перезаписывая** его содержимое.
    *   `ls -l > output.txt`
*   `команда >> файл`: Перенаправляет `stdout` в `файл`, **добавляя** данные в конец.
    *   `echo "Новая строка" >> output.txt`

#### 2. Перенаправление вывода ошибок (`stderr`)

*   `команда 2> файл`: Перенаправляет `stderr` (дескриптор `2`) в `файл`, перезаписывая его.
    *   `ls /nonexistent 2> errors.log`

#### 3. Объединение `stdout` и `stderr`

*   `команда > файл 2>&1`: Перенаправляет `stdout` в `файл`, а затем `stderr` туда же, куда и `stdout`. Порядок важен.
*   `команда &> файл`: Более короткий и современный синтаксис для `> файл 2>&1`.
    *   `make &> build.log` (записывает и успешный вывод, и ошибки в один лог).

#### 4. Перенаправление ввода (`stdin`)

*   `команда < файл`: Команда читает данные из `файла` вместо клавиатуры.
    *   `sort < names.txt`

#### 5. "Черная дыра" `/dev/null`

Это специальный файл, который отбрасывает все, что в него записывается, и не возвращает ничего при чтении. Используется для подавления нежелательного вывода.

*   `команда > /dev/null 2>&1`: Подавляет весь вывод (`stdout` и `stderr`) команды.

### Практические сценарии

#### Фатальная ошибка: `grep "pattern" file > file`

**Проблема:** Перенаправление (`>`) обрабатывается оболочкой **до** выполнения самой команды.
1.  Оболочка видит `> file` и **немедленно очищает этот файл**, готовя его к записи.
2.  Только после этого запускается `grep`, но к этому моменту `file` уже пуст.
3.  **Результат: необратимая потеря данных.**

**Решения:**
*   **Использовать временный файл (надежно):**
    ```bash
    grep "pattern" a.txt > a.tmp && mv a.tmp a.txt
    ```
*   **Использовать утилиту `sponge` (из пакета `moreutils`):**
    `sponge` "впитывает" весь ввод и только после его полного получения открывает и записывает файл назначения.
    ```bash
    grep "pattern" a.txt | sponge a.txt
    ```
*   **Использовать инструменты со встроенной функцией редактирования:**
    `sed`, `awk` и другие утилиты часто имеют опции для редактирования файлов "на месте".
    ```bash
    sed -i '/pattern/!d' a.txt # Удалит строки, НЕ соответствующие шаблону
    ```
