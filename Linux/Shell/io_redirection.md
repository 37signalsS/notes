# Перенаправление ввода-вывода в Shell

## Определения

- **Перенаправление (Redirection)** — механизм командной оболочки, позволяющий изменять стандартные источники ввода и потоки вывода команд, связывая их с файлами, устройствами или другими дескрипторами.
- **Файловый дескриптор (File Descriptor, fd)** — неотрицательное целое число, служащее уникальным идентификатором открытого ресурса (файла, сокета или канала) в таблице дескрипторов процесса.
- **Стандартные потоки (Standard Streams)** — три канала данных, открытых ядром для каждого процесса по умолчанию:
  - **`stdin` (fd 0)** — стандартный ввод (по умолчанию клавиатура).
  - **`stdout` (fd 1)** — стандартный вывод (основной результат работы).
  - **`stderr` (fd 2)** — стандартный поток ошибок (диагностические и отладочные сообщения).
- **Устройство терминала (TTY / PTY)**:
  - **TTY (Teletype)** — физическое или виртуальное терминальное устройство, связанное с сессией пользователя.
  - **PTY (Pseudo-Terminal)** — пара виртуальных устройств (master/slave), эмулирующих терминал для процессов. Привязка процесса к PTY определяет, будет ли он интерактивным и как обрабатывать сигналы (например, `Ctrl+C`).

## Базовые концепции

Оболочка обрабатывает операторы перенаправления **после** всех видов подстановок (expansions), но **до** фактического запуска команды.

### Основные операторы вывода

| Оператор | Назначение | Особенности |
| :--- | :--- | :--- |
| `>` | Запись `stdout` в файл | Перезаписывает (truncate) файл. |
| `>>` | Добавление `stdout` в файл | Дописывает данные в конец (append). |
| `2>` | Перенаправление `stderr` | Удобно для отделения ошибок от данных. |
| `&>` | `stdout` и `stderr` одновременно | Сокращение для `>file 2>&1` (только Bash/Zsh). |
| `&>>` | Добавление обоих потоков | Сокращение для `>>file 2>&1` (только Bash/Zsh). |
| `>|` | Принудительная перезапись | Игнорирует опцию `noclobber` (`set -C`). |
| `tee -a file` | Запись и дублирование потока | Дописывает в конец файла, не перезаписывая. |
| `tee -i` | Игнорировать `SIGINT` | Позволяет прервать `tee` через `Ctrl+C` без разрыва pipe. |

Одиночный оператор `>` управляет только дескриптором 1 (`stdout`). Чтобы поймать поток ошибок `stderr` (fd 2), нужно явно указать номер дескриптора перед оператором: `2>`.

### Операторы ввода

| Оператор | Назначение | Описание |
| :--- | :--- | :--- |
| `<` | Чтение из файла | Файл передается в `stdin` команды. |
| `<< EOF` | **Heredoc** | Передача многострочного блока. Если `EOF` в кавычках (`<<'EOF'`), подстановка переменных отключена. |
| `<<- EOF` | **Heredoc (Trim)** | Удаляет ведущие символы табуляции (Tabs) в начале строк. |
| `<<< "str"` | **Herestring** | Передача строки или переменной напрямую в `stdin`. |

### Работа с произвольными дескрипторами

Вы можете указывать номер дескриптора перед оператором (без пробела):
- `3>file.log` — открыть FD 3 для записи в файл.
- `cat <&3` — читать из FD 3.
- `exec 5>&-` — закрыть FD 5.

**Сценарий — структурированное логирование через выделенный дескриптор:**

```bash
# Открыть дескриптор 3 для дозаписи (append) в файл аудит-лога,
# писать независимо от stdout, затем закрыть дескриптор
exec 3>>audit.log
echo "$(date -Is) start" >&3
exec 3>&-
```

Дескриптор 3 дублирует вывод `stdout` через `>&3`, но пишет в отдельный файл — удобно для аудит-логов, отделенных от обычного вывода. Закрытие через `exec 3>&-` гарантирует сброс буфера и освобождение файла.

### Синтаксис дублирования дескрипторов

Полный синтаксис для дублирования и специализированного открытия:

- **`[n]<&word`** — дублировать ввод из `word` в дескриптор `n` (или `stdin`, если `n` опущен).
  - `exec 3>&1` — сохранить текущий `stdout` в `fd 3`.
  - `exec 1>&3` — восстановить `stdout` из `fd 3`.
- **`[n]>&word`** — дублировать вывод из `word` в дескриптор `n` (или `stdout`, если `n` опущен).
  - `cmd >&2` — отправить `stdout` команды в `stderr`.
- **`[n]<>word`** — открыть `word` для чтения и записи на дескрипторе `n`.

### Специальные устройства ввода-вывода

Ядро Linux предоставляет виртуальные устройства, которые можно использовать как источники или цели перенаправления:

- **`/dev/null`** — «черная дыра». Все записанные данные отбрасываются. При чтении возвращает EOF. Коды ошибок: `ENOSPC` при записи, `EIO` при чтении (в зависимости от реализации).
- **`/dev/zero`** — источник неограниченной последовательности нулевых байтов. Используется для создания пустых файлов или заполнения памяти.
- **`/dev/full`** — устройство, всегда возвращающее `ENOSPC` при записи и нули при чтении. Полезно для тестирования обработки нехватки места.
- **`/dev/urandom`** — источник криптографически стойких случайных байтов. Не блокируется при нехватке энтропии (в отличие от `/dev/random`).
- **`/dev/stdin`**, **`/dev/stdout`**, **`/dev/stderr`** — символические ссылки на текущие стандартные потоки процесса. Удобны для программ, которые не умеют работать с числовыми дескрипторами напрямую.
- **`/dev/tty`** — управляющий терминал текущего процесса. Позволяет читать из терминала или писать в него, даже если `stdin`/`stdout` перенаправлены.
- **`/dev/pts/N`** — конкретный псевдотерминал (slave side). Номер `N` изменяется при каждом новом подключении. Используется для адресации конкретных сессий.

### Наследование дескрипторов и фоновые задачи

- **`fork()`** — потомок получает полную копию таблицы дескрипторов родителя. Если родитель перенаправил `stdout` в файл, потомок будет писать в тот же файл.
- **`exec()`** — по умолчанию дескрипторы остаются открытыми в новой программе. Флаг `O_CLOEXEC` автоматически закрывает дескриптор при `exec`.
- **`nohup`** — перехватывает сигнал `SIGHUP` (который ядро отправляет процессу при закрытии управляющего терминала). Если `stdout`/`stderr` указывают на терминал, `nohup` перенаправляет их в `nohup.out`. `stdin` остается привязанным к терминалу, если не перенаправлен явно.
- **`disown`** (встроенная команда Bash) — удаляет задачу из таблицы jobs и предотвращает отправку `SIGHUP` при выходе из Shell.

## Продвинутая работа с дескрипторами

### Порядок обработки (Слева направо)

Shell связывает дескрипторы в том порядке, в котором они указаны в командной строке.

- **Корректно:** `cmd > file.log 2>&1`
  1. `fd 1` направляется в `file.log`.
  2. `fd 2` направляется туда, куда сейчас указывает `fd 1` (в `file.log`).
- **Ошибка:** `cmd 2>&1 > file.log`
  1. `fd 2` направляется туда, куда сейчас указывает `fd 1` (на экран).
  2. `fd 1` перенаправляется в файл.
  *Результат: ошибки попадут на экран, данные — в файл.*

### Управление через exec

Команда `exec` без аргументов изменяет дескрипторы для текущей оболочки персистентно.

```bash
# Сохранить текущий stdout в fd 3
exec 3>&1

# Перенаправить весь вывод скрипта в файл
exec > output.log 2>&1

echo "Этот текст уйдет в файл"

# Восстановить stdout и закрыть fd 3
exec 1>&3 3>&-

echo "Этот текст снова на экране"
```

### Динамические дескрипторы (Bash 4.1+)

Bash может автоматически подобрать свободный номер дескриптора и сохранить его в переменную.

```bash
# Открыть файл для чтения и записи, сохранив номер FD в переменную MY_FD
exec {MY_FD}<> /tmp/test_file

echo "Writing to dynamic FD $MY_FD" >&$MY_FD
cat <&$MY_FD

# Закрыть дескриптор
exec {MY_FD}>&-
```

### Сетевые сокеты (/dev/tcp и /dev/udp)

Bash предоставляет виртуальные пути для работы с сетью.

```bash
# Проверка доступности порта
if (echo > /dev/tcp/8.8.8.8/53) >/dev/null 2>&1; then
    echo "Google DNS is reachable"
fi

# Отправка HTTP-запроса
exec 3<>/dev/tcp/google.com/80
echo -e "GET / HTTP/1.1\r\nHost: google.com\r\nConnection: close\r\n\r\n" >&3
cat <&3
exec 3>&-
```

### Управление буферизацией

При перенаправлении вывода через pipe или в файл многие утилиты переключаются на блокировную буферизацию, что скрывает вывод в реальном времени.

```bash
# Принудительное линейное буферирование (вывод построчно)
stdbuf -oL grep "ERROR" /var/log/app.log | awk '{print $1}'

# Полное отключение буферизации (для двоичных данных или нестандартного вывода)
stdbuf -i0 -o0 cat /dev/ttyUSB0 | process_data

# unbuffer (из пакета expect) — обходной путь для утилит, игнорирующих stdbuf
unbuffer tail -f /var/log/syslog | grep --line-buffered "kernel"
```

**Важно:** `stdbuf` работает через обертки `LD_PRELOAD` и не влияет на статически скомпонованные бинарники.

### Блокировка файлов (flock)

Для атомарного обновления файлов из нескольких процессов используйте advisory locking. Это предотвращает гонки при одновременной записи.

```bash
# Блокировка файла на время выполнения блока
(
    flock -x 200
    echo "Backup started at $(date)" >> /var/log/backup.log
) 200>/var/log/backup.lock

# Однострочник с временным файлом
tmp=$(mktemp) && 
flock /etc/myapp.conf.lock 
cp /etc/myapp.conf "$tmp" && 
sed 's/port=8080/port=9090/' "$tmp" > /etc/myapp.conf && 
rm "$tmp"
```

**Примечание:** `flock` использует отдельный механизм ядра, не зависящий от файловых дескрипторов оболочки. Это advisory lock: он работает только если все учатники процесса используют `flock` или `fcntl`.

### Сигналы и каналы

- **`SIGPIPE`** — отправляется процессу, когда читающая сторона pipe закрывается (например, `head -n 5 | tail`). По умолчанию процесс завершается. В скриптах можно игнорировать сигнал: `trap '' PIPE`.
- **`SIGINT`** — `Ctrl+C` в терминале. При перенаправлении ввода/вывода через pipe или файл поведение может отличаться. Утилита `tee` с опцией `-i` игнорирует `SIGINT`, позволяя прервать только часть пайплайна.

```bash
# Игнорировать SIGPIPE для предотвращения преждевременного завершения
trap '' PIPE
curl -s http://slow-service | head -n 10
```

## Практические сценарии

### Паттерн "Тихое выполнение"

```bash
# Полное подавление вывода
command &>/dev/null

# Подавление только ошибок
ls non_existent_file 2>/dev/null
```

`/dev/null` — виртуальное символьное устройство, часто называемое «легальной чёрной дырой» или «цифровым унитазом». Всё, что записывается в `/dev/null`, бесследно исчезает. Это стандартный способ заглушить ненужные системные уведомления в скриптах.

### Использование tee для записи под sudo

Перенаправление `>` выполняется от имени текущего пользователя. Для записи в защищенные файлы используйте `tee`.

```bash
# ОШИБКА: sudo не влияет на >
sudo echo "config" > /etc/protected.conf

# ПРАВИЛЬНО:
echo "config" | sudo tee /etc/protected.conf >/dev/null
```

### Перенаправление внутри циклов и блоков

Вы можете перенаправить ввод или вывод для целого блока команд.

```bash
# Чтение файла построчно
while read -r line; do
    echo "Обработка: $line"
done < data.txt

# Логирование всего блока в файл
{
    echo "Начало операции: $(date)"
    tar -czf backup.tar.gz /data
    echo "Конец операции: $(date)"
} > backup.log 2>&1
```

### Безопасное обновление файла

Операция `cmd < file > file` уничтожит файл до того, как команда его прочитает.
**Рекомендация:**
1. Временный файл: `sort a.txt > a.tmp && mv a.tmp a.txt`.
2. Утилита `sponge`: `grep "pattern" file | sponge file`.

### Экзаменационные сценарии (LPIC-1 103.2)

- **Создание файла:** Оператор `>` создаёт целевой файл, если он не существует.
- **Экзаменационный вопрос — безопасное добавление даты в changelog:**
  ```bash
  echo "$(date)" >> changelog.txt
  ```
  `>>` безопасно дописывает данные в конец файла, не затрагивая существующее содержимое.
- **Различение операторов в тесте:**
  - `|` (pipe) — передаёт `stdout` одной команды в `stdin` следующей, не используется для записи в файл.
  - `<` — перенаправляет файл в `stdin` команды (ввод, а не вывод).
  - `>` — перезаписывает файл, что приводит к потере данных.
- **Перенаправление `stderr` в `/dev/null`:**
  - На экзамене LPIC-1 синтаксис `2>` проверяют постоянно.
  - Одиночный `>` или `> /dev/null` отправляет в пустоту только `stdout` (fd 1), а ошибки остаются на экране.
  - `&> /dev/null` или `&>/dev/null` объединяет оба потока и отправляет их в `/dev/null` — это подходит для полного подавления, но в тестах часто требуется подавить только ошибки.
  - Правильный ответ в тесте: явное перенаправление `stderr` через `2>/dev/null`.
- **Практическое правило:** В 95% случаев администрирования для добавления логов используется `>>`, а не `>`.

## Дополнительная информация

### Взаимодействие с ядром: /proc/self/fd/

В Linux дескрипторы процесса доступны как файлы. Это позволяет передавать потоки программам, требующим путь к файлу.

```bash
# Сравнение вывода двух команд
diff <(ls dir1) <(ls dir2)
# → result: оболочка создает временные именованные каналы или использует /dev/fd/N
```

### Различия между оболочками

- **Dash (/bin/sh в Debian/Ubuntu)**: Не поддерживает `&>`, `&>>`, `<<<`, `{fd}>file`. Для совместимости используйте `>file 2>&1`.
- **Bash**: Поддерживает все перечисленные расширения.
- **Zsh**: По умолчанию поддерживает мульти-перенаправление (аналог `tee` через `> file1 > file2`).
