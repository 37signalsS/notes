# Управление файлами: создание, удаление, копирование и перемещение

## Определения

- **touch** — утилита GNU coreutils для создания пустых файлов и обновления временных меток (atime, mtime) существующих файлов. Если файл не существует, создаётся пустой файл размером 0 байт. Если файл существует, **содержимое не изменяется** — обновляются только временные метки до текущего времени.
- **rm** (remove) — утилита GNU coreutils для удаления файлов и (с флагами) каталогов. Вызывает системный вызов `unlink()`. В server Linux нет корзины — файл удаляется сразу и безвозвратно.
- **rmdir** — утилита для удаления пустых каталогов. Не удаляет каталоги с содержимым; для этого используется `rm -r`.
- **cp** (copy) — утилита GNU coreutils для копирования файлов и каталогов. Создаёт новый объект файловой системы с собственным inode.
- **mv** (move) — утилита GNU coreutils для перемещения и переименования файлов и каталогов. В пределах одной файловой системы (ФС) выполняет атомарную смену записи в каталоге (dentry); между разными ФС работает как `cp` + `rm`.
- **rename** — утилита для массового переименования на основе регулярных выражений (Perl-выражения). Не входит в POSIX-основной набор; в Debian/Ubuntu часто предоставляется пакетом `rename`, в RHEL-семействе — `prename`. **Не предназначена** для одиночного переименования.
- **Рекурсивное копирование** — режим обработки каталогов, при котором копируется всё содержимое, включая вложенные подкаталоги и файлы.

## Базовые концепции

### Отсутствие команды `rn`

В Linux **нет** команды `rn` и встроенной утилиты `rename` для одиночного переименования. Попытка вызвать `rn` вернёт `command not found` (код выхода 127). Это частый ловушка на экзамене LPIC-1.

### Двойственная природа `mv`

Команда `mv` выполняет две logically разные операции, но технически — одну:

1. **Перемещение** между каталогами (в пределах одной ФС — атомарная смена dentry; между ФС — физическое копирование + удаление оригинала).
2. **Переименование** внутри одного каталога (меняется только имя dentry; inode и данные не затрагиваются).

### Копирование каталогов

Команда `cp` без дополнительных флагов работает **только с обычными файлами**. При попытке скопировать каталог возвращается ошибка:

```text
cp: -r not specified; omitting directory 'src'
```

Для копирования каталогов необходим флаг рекурсии:

- `-r`, `--recursive` — копировать каталоги рекурсивно
- `-a`, `--archive` — рекурсивное копирование с сохранением всех атрибутов (права, владелец, временные метки, симлинки)

### Семантика аргументов

```text
cp [ОПЦИИ] ИСТОЧНИК НАЗНАЧЕНИЕ
mv [ОПЦИИ] ИСТОЧНИК НАЗНАЧЕНИЕ
```

- Если НАЗНАЧЕНИЕ — существующий каталог, файл помещается внутрь.
- Если НАЗНАЧЕНИЕ — существующий файл, он **перезаписывается** без запроса подтверждения (без флага `-i`).
- Если НАЗНАЧЕНИЕ — не существующий путь, файл создаётся с этим именем.

## Создание файлов (`touch`)

### Основное назначение

Главная задача `touch` — изменение времени последнего доступа и модификации (atime, mtime) существующих файлов. Создание пустого файла является побочным эффектом, который используется чаще всего на практике.

### Семантика работы

```bash
touch [ОПЦИИ] ИМЯ_ФАЙЛА
```

| Сценарий | Результат |
| :--- | :--- |
| Файл не существует | Создаётся пустой файл размером 0 байт. Временные метки устанавливаются в текущее время. |
| Файл существует | Содержимое файла **не изменяется**. Обновляются atime и mtime до текущего времени. |
| Файл существует, указан флаг `-a` | Обновляется только atime. |
| Файл существует, указан флаг `-m` | Обновляется только mtime. |

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-a` | `--time=atime` | Обновить только atime (access time). |
| `-m` | `--time=mtime` | Обновить только mtime (modification time). |
| `-r` | `--reference=ФАЙЛ` | Установить временные метки такие же, как у указанного файла, вместо текущего времени. |
| `-t` | | Установить метки времени из аргумента формата `[[CC]YY]MMDDhhmm[.frac]`. |
| `-d` | `--date=СТРОКА` | Установить метки из произвольной строки даты (например, `"2024-01-01 12:00:00"`, `"yesterday"`, `"next Friday"`). |
| `-c` | `--no-create` | Не создавать файл, если он не существует; только обновлять метки времени. |

### Важные нюансы

- **`touch` не усекает содержимое** существующих файлов. Это распространённое заблуждение. Для усечения файла используется `truncate -s 0 file.txt` или `: > file.txt`.
- Временная метка `btime` (время создания) обновляется только при создании нового файла; `touch` не изменяет `btime` существующих файлов.
- Для создания файла требуются права на запись (`w`) и выполнение (`x`) в **родительском каталоге**, а не на самом файле.

### Практическое применение

- Создание пустышек для компиляции (`touch Makefile`):
  ```bash
  touch main.c Makefile README.md
  ```
- Обновление временных меток для инструментов сборки, которые проверяют freshness файлов:
  ```bash
  touch -m config.yaml
  ```
- Создание маркерных файлов для идемпотентных скриптов:
  ```bash
  touch /var/lib/myapp/.initialized
  ```
- Синхронизация временных меток с эталонным файлом (например, для согласованности артефактов сборки в распределённой среде):
  ```bash
  touch -r reference.tar.gz artifact.tar.gz
  ```
- Установка конкретной временной метки для тестирования логики устаревания (TTL-проверки):
  ```bash
  touch -t 202401010000 /tmp/old_log.txt
  ```
- Обновление только `atime` для аудита доступа без изменения `mtime`:
  ```bash
  touch -a /var/log/audit.log
  ```
- Создание файла с указанной временной меткой для имитации "старого" файла:
  ```bash
  touch -d "2024-01-01 12:00:00" /tmp/fake_old.txt
  ```

## Копирование файлов и каталогов (`cp`)

### Основные опции и флаги

`cp` создаёт новый объект файловой системы с собственным inode. В отличие от `mv`, копирование сохраняет источник.

```bash
cp [ОПЦИИ] ИСТОЧНИК НАЗНАЧЕНИЕ
```

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-r`, `-R` | `--recursive` | Рекурсивно копировать каталоги и их содержимое. |
| `-a` | `--archive` | Архивный режим: рекурсивное копирование с сохранением прав, владельцев, временных меток, симлинков, SUID/SGID и sticky-битов. Эквивалентен `-rd --preserve=all` в GNU coreutils. |
| `-p` | `--preserve[=СПИСОК]` | Сохранить указанные атрибументы. Без аргумента сохраняет: режим, владение, временные метки. Поддерживаемые: `mode`, `ownership`, `timestamps`, `context`, `links`, `xattr`, `all`. |
| `-u` | `--update` | Копировать только тогда, когда источник новее назначения или назначение не существует. Полезно для инкрементальной синхронизации. |
| `-n` | `--no-clobber` | Не перезаписывать существующие файлы. |
| `-i` | `--interactive` | Запрашивать подтверждение перед перезаписью. |
| `-v` | `--verbose` | Выводить имена копируемых файлов. |
| `-l` | `--link` | Создавать жёсткие ссылки вместо копирования (требует источник и назначение на одной ФС). |
| `-s` | `--symbolic` | Создавать символические ссылки вместо копирования. |
| `-d` | `--no-dereference --preserve=links` | Не разыменовывать симлинки и сохранять жёсткие ссылки. |
| `--reflink=auto\|always\|never` | | Copy-on-Write: при `always` использовать CoW (Btrfs, XFS с reflink). `auto` использует CoW, если поддерживается, иначе обычное копирование. |
| `--sparse=always\|auto\|never` | | Управление sparse-файлами. `always` создаёт разреженные файлы; `auto` (по умолчанию) учитывает "дыры". |
| `--backup[=управление]` | | Создавать резервную копию перед перезаписью (суффикс по умолчанию `~`). |
| `--remove-destination` | | Удалить существующее назначение перед копированием. |
| `--no-preserve=АТРИБУТ` | | Отключить сохранение указанного атрибута. |

### Сравнение `cp -a` и `cp -r`

| Параметр | `cp -r` | `cp -a` |
| :--- | :--- | :--- |
| Рекурсивность | Да | Да |
| Права доступа | Сбрасываются согласно umask | Сохраняются |
| Владелец | Текущий пользователь | Сохраняются (требует root для смены владельца) |
| Временные метки | Обновляются | Сохраняются |
| Символические ссылки | Разыменовываются (копируются цели) | Копируются как ссылки |
| Жёсткие ссылки | Разрываются (новый inode) | Сохраняются через `--link` |

### Жёсткие ссылки вместо копирования (`-l`)

Жёсткая ссылка не создаёт новый inode — обе записи каталога указывают на одни и те же данные. Это экономит место, но изменение данных по одной ссылке отражается на всех:

```bash
cp -al /var/lib/app/data/ /var/lib/app/data_snapshot/
```

Эта техника лежит в основе **`rsnapshot`** и аналогичных инструментов для создания моментальных снимков с минимальным потреблением диска. Подробнее о жёстких ссылках: [Жёсткие ссылки](../FileSystems/links_inodes_dentries.md#жесткие-ссылки-hard-links).

### Copy-on-Write (`--reflink`)

На ФС с поддержкой CoW (Btrfs, XFS с reflink, ZFS) копирование может выполняться мгновенно — данные не копируются, а делятся блоками до первого изменения любой из копий:

```bash
cp --reflink=always large_vm_image.qcow2 backup/
# → почти мгновенно, 0 дополнительного места до первой записи в любую копию
```

Если `--reflink=always` указан на ФС без поддержки CoW — команда завершится ошибкой. Используйте `--reflink=auto` для автоматического отката на обычное копирование. Подробнее о механизмах CoW: [Журналирование и Copy-on-Write в ФС](../FileSystems/fs_internals.md).

### Sparse-файлы (`--sparse`)

Sparse-файлы содержат "дыры" (zero regions), которые не занимают места на диске. Флаг `--sparse=always` создаёт разреженную копию даже для обычных файлов с большими нулевыми участками:

```bash
cp --sparse=always disk_image.img /backup/disk_image.img
# → только используемые блоки копируются, "дыры" не занимают место
du -h disk_image.img    # → фактический размер на диске
ls -lh disk_image.img   # → логический размер
```

## Перемещение и переименование (`mv`)

### Опции и флаги

`mv` выполняет перемещение или переименование. В пределах одной ФС использует атомарный системный вызов `rename(2)`; между разными ФС — копирует и удаляет оригинал.

```bash
mv [ОПЦИИ] ИСТОЧНИК НАЗНАЧЕНИЕ
```

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-i` | `--interactive` | Запрашивать подтверждение перед перезаписью существующего файла. |
| `-n` | `--no-clobber` | Не перезаписывать существующие файлы (выше приоритета, чем `-i`). |
| `-u` | `--update` | Перемещать только если источник новее назначения или назначение не существует. |
| `-v` | `--verbose` | Выводить имена перемещаемых файлов. |
| `-Z` | `--context=CTX` | Установить контекст SELinux для перемещенного объекта. |
| `--backup[=управление]` | | Создавать резервную копию перед перезаписью. |

### Перемещение между файловыми системами

При перемещении между разными точками монтирования `mv` не может использовать `rename(2)` — системный вызов возвращает ошибку `EXDEV`. В этом случае `mv` выполняет `cp` + `rm` внутри:

```text
mv: cannot move 'src/file' to 'dst/file': Invalid cross-device link
```

**DevOps-сценарий:** При миграции данных между LVM-томами используйте `rsync` с проверкой целостности вместо `mv`, чтобы избежать потери данных при сбое:

```bash
rsync -aH --progress /mnt/old_lv/data/ /mnt/new_lv/data/
diff -r /mnt/old_lv/data/ /mnt/new_lv/data/ && rm -rf /mnt/old_lv/data/
```

Подробнее о синхронизации: [rsync — синхронизация файлов](../SystemAdministration/rsync.md).

## Удаление файлов и каталогов (`rm`, `rmdir`)

### Команда `rm`

`rm` удаляет **имена** файлов из каталога, вызывая системный вызов `unlink()`. Данные на диске не стираются физически — удаляется только запись в каталоге (dentry), связывающая имя с Inode. Блоки данных помечаются как свободные только когда счётчик `i_nlink` достигает 0 и ни один процесс не держит файл открытым.

```bash
rm [ОПЦИИ] ФАЙЛ...
```

| Флаг | Описание |
| :--- | :--- |
| `-i` | Интерактивный режим: запрашивать подтверждение перед каждым удалением. |
| `-f`, `--force` | Игнорировать несуществующие файлы и никогда не запрашивать подтверждение. |
| `-I` | Запрашивать подтверждение **один раз** при удалении более 3-х файлов или при рекурсивном удалении. Безопасный компромисс между `-i` и `-f`: защищает от опечаток вроде `rm -rf *` без потери удобства. |
| `-v`, `--verbose` | Выводить имя каждого удаляемого файла. |
| `-r`, `-R`, `--recursive` | Рекурсивно удалять каталоги и их содержимое. |
| `-d` | Удалить пустые каталоги (эквивалентно `--dir`). |
| `--preserve-root` | Не удалять `/` при использовании с `-r`/`-R`. Поведение по умолчанию в GNU coreutils. |
| `--no-preserve-root` | Отключить защиту корня (ОПАСНО). Позволяет `rm -rf /` без ошибки. |
| `--one-file-system` | Не удалять файлы на других файловых системах при рекурсивном обходе. |
| `--no-ignore-new` | Рассматривать новые файлы как удаляемые при очистке. |

### Команда `rmdir`

`rmdir` удаляет **только пустые** каталоги. Если в каталоге есть файлы или подкаталоги, команда завершается с ошибкой:

```text
rmdir: failed to remove 'dir': Directory not empty
```

```bash
rmdir [ОПЦИИ] КАТАЛОГ...
```

| Флаг | Описание |
| :--- | :--- |
| `-p` | Удалить КАТАЛОГ и все его предков (родительские пустые каталоги). |
| `--ignore-fail-on-non-empty` | Игнорировать ошибки, если каталог не пуст. |

### Безопасность и опасные комбинации

- **`rm -rf /`** — ядерное оружие. При запуске от имени суперпользователя удаляет всю файловую систему. Никогда не используйте без 100% уверенности в пути.
- **`rm -rf *`** в корне пользователя (`~`) — мгновенное уничтожение всех данных пользователя.
- В server Linux **нет корзины**. Удалённый файл восстановить стандартными средствами нельзя.
- Для безопасного удаления можно использовать `trash-cli` (утилита, перемещающая файлы в `~/.local/share/Trash`), но она не входит в минимальный набор POSIX.

### Восстановление после `rm`

Физическое восстановление возможно только через специализированные инструменты (например, `extundelete`, `testdisk`), и только если блоки данных не были перезаписаны. Это трудоёмкий процесс без гарантии успеха. **Единственный надёжный способ — резервное копирование.**

## Практические сценарии

### Создание пустого файла

```bash
touch notes.txt
ls -l notes.txt
# → -rw-r--r-- 1 user user 0 Aug 29 12:00 notes.txt
```

### Обновление временных меток существующего файла

```bash
touch -m existing.log
# mtime обновлён до текущего времени, содержимое не изменено
```

### Создание нескольких файлов сразу

```bash
touch file1.txt file2.txt file3.txt
```

### Удаление файла

```bash
rm document.pdf
ls document.pdf
# → ls: document.pdf: No such file or directory
```

### Удаление с подтверждением

```bash
rm -i sensitive.conf
# rm: remove regular file 'sensitive.conf'? y
```

### Удаление каталога с содержимым (рекурсивно)

```bash
rm -r old_project/
```

### Принудительное рекурсивное удаление (игнорировать ошибки прав)

```bash
rm -rf cache/
```

### Удаление только пустого каталога

```bash
mkdir empty_dir
rmdir empty_dir
# Успешно

mkdir non_empty_dir
touch non_empty_dir/file.txt
rmdir non_empty_dir
# → rmdir: failed to remove 'non_empty_dir': Directory not empty
```

### Удаление нескольких пустых каталогов

```bash
rmdir dir1 dir2 dir3
```

### Рекурсивное удаление пустых родительских каталогов

```bash
mkdir -p a/b/c
rmdir a/b/c a/b a
# Удалит c, затем b (после удаления c), затем a (после удаления b)
```

### Копирование файла

```bash
cp file.txt /backup/file.txt
```

### Рекурсивное копирование каталога

```bash
cp -r project/ /backup/project/
# или с полным сохранением атрибутов:
cp -a project/ /backup/project/
```

### Перемещение файла в другой каталог

```bash
mv report.pdf /documents/2024/
```

### Переименование файла в текущем каталоге

```bash
mv old-name.log new-name.log
# Файл остаётся в той же директории, меняется только dentry.
```

### Перемещение с одновременным переименованием

```bash
mv /tmp/draft.txt /projects/2024/final-report.txt
```

### Атомарное обновление конфигурационного файла

```bash
# 1. Копировать на ту же ФС, что и целевой файл (иначе mv становится cp + rm)
cp nginx.conf nginx.conf.new
# → редактирование nginx.conf.new

# 2. Проверить синтаксис перед применением
nginx -t -c nginx.conf.new

# 3. Атомарная замена через rename(2) — в пределах одной ФС замена мгновенна
mv nginx.conf.new nginx.conf

# 4. Перезагрузить сервис без падения воркеров
systemctl reload nginx
```

Подробнее о паттерне атомарного обновления (включая `fsync` и `O_TMPFILE`): [Атомарные операции](../Concepts/atomic_operations.md).

### Массовое переименование по шаблону

```bash
# Debian/Ubuntu (пакет rename):
rename 's/\.log$/.txt/' *.log

# RHEL/CentOS/Fedora (prename):
rename 's/\.log$/.txt/' *.log
```

### Проверка работы rename

```bash
rename --version 2>/dev/null || prename --version 2>/dev/null || echo "rename не установлен"
```

## DevOps / SRE сценарии

### Ротация логов (log rotation)

В production-средах логи растут непрерывно. Паттерн ротации через `mv` + сигнал — используется `logrotate` и ручными скриптами:

```bash
# 1. Переименовать текущий лог (приложение продолжает писать в открытый fd)
mv /var/log/app.log /var/log/app.log.1

# 2. Создать новый пустой файл с теми же правами
touch /var/log/app.log
chmod 644 /var/log/app.log

# 3. Отправить сигнал приложению переоткрыть логи
kill -HUP $(cat /var/run/app.pid)
```

Если приложение **не** поддерживает `HUP`/переоткрытие логов, используйте `copytruncate` (cp + truncate) — но это **не атомарно** и может потерять записи, которые попали между copy и truncate. Подробнее: [logrotate](../Diagnostics/journalctl/journalctl_management.md).

### Blue-green deployment через символические ссылки

Для нулевого простоя при деплое приложения используется переключение симлинка на новую версию каталога:

```bash
# Структура:
# /opt/myapp/current  ->  /opt/myapp/releases/v2/
# /opt/myapp/releases/v1/
# /opt/myapp/releases/v2/

# 1. Развернуть новую версию в отдельный каталог
mkdir -p /opt/myapp/releases/v3
cp -a /tmp/build/* /opt/myapp/releases/v3/

# 2. Переключить симлинк атомарно (в пределах одной ФС)
ln -sfn /opt/myapp/releases/v3 /opt/myapp/current

# 3. Перезапустить сервис
systemctl reload myapp
```

`ln -sfn` использует `symlink(2)` + `rename(2)` внутри — операция атомарна. Подробнее о символических ссылках: [Символические ссылки](../FileSystems/links_inodes_dentries.md#символические-ссылки-symlinks).

### Очистка временных и старых файлов

**`find + rm`** и **`find -delete`** — стандартные паттерны для очистки по возрасту:

```bash
# Удалить файлы логов старше 7 дней (find + rm)
find /var/log -name "*.log" -type f -mtime +7 -exec rm -f {} \;

# Более эффективно: find -delete (один проход, без xargs)
find /tmp -type f -name "*.tmp" -mtime +1 -delete

# Удалить пустые каталоги после очистки
find /opt/app -type d -empty -delete
```

**DevOps-ловушка:** `*` в `rm -rf /tmp/*` не удаляет dotfiles (`.tmpfile`). Используйте `find /tmp -maxdepth 1 -name ".*" -type f -delete` или включите `dotglob` в bash.

### Создание резервной копии перед изменением

Перед изменением конфигурации или данных всегда создавайте резервную копию:

```bash
# Традиционный суффикс .bak
cp -p config.yaml config.yaml.bak.$(date +%Y%m%d%H%M%S)

# Или через скобки командной подстановки в имени
cp -p /etc/nginx/nginx.conf /etc/nginx/nginx.conf.$(date +%s).bak
```

Флаг `-p` (`--preserve`) сохраняет временные метки, что важно для аудита.

### Проверка целостности после копирования

После `cp` или `mv` между файловыми системами проверьте, что данные не повреждены:

```bash
# Сравнение хешей
sha256sum source.tar.gz dest.tar.gz
# → одинаковые хеши = копия цела

# Байт-в-байт сравнение
cmp source.tar.gz dest.tar.gz
# → без вывода = файлы идентичны

# Для каталогов: рекурсивное сравнение
diff -r /src/ /dst/
```

### Обрезка логов без удаления (truncate)

Чтобы очистить лог, не меняя inode (приложение держит открытый fd):

```bash
# Обрезать до 0 байт
truncate -s 0 /var/log/app.log

# Или через оболочной перенаправление
: > /var/log/app.log
```

В отличие от `rm` + `touch` (которые создают новый inode), `truncate` сохраняет старый fd — приложение не теряет дескриптор. Подробнее о truncate: [Перенаправление ввода-вывода](./io_redirection.md).

### Deduplication через жёсткие ссылки

Одинаковые файлы (например, образы ВМ или библиотеки) можно объединить через жёсткие ссылки для экономии места:

```bash
# Сначала найти дубликаты, затем заменить на жёсткие ссылки
fdupes -r -L /data/
# Или:
rdfind /var/lib/vz/images/
```

Жёсткая ссылка не занимает дополнительного inode и не создаёт копию данных — все ссылки указывают на одни и те же блоки. Подробнее о жёстких ссылках: [Жёсткие ссылки](../FileSystems/links_inodes_dentries.md#жесткие-ссылки-hard-links).

### Копирование с сохранением прав через `install`

Утилита `install` объединяет `cp` + `chmod` + `chown` в одном вызове — идеальна для скриптов деплоя:

```bash
# Установить файл с правами 644 и владельцем root:root
install -o root -g root -m 644 app.conf /etc/myapp/app.conf

# Создать директорию с правами 755
install -d -m 755 /opt/myapp/releases/
```

Подробнее: [Управление правами: install](../Security/Concepts/File_Permissions/permissions_management_quickref.md#4-создание-объектов-с-заданными-правами-install).

## Экзаменационные сценарии (LPIC-1 103.1)

### Вопрос 1: Создание пустого файла

**Типичный вопрос:** Какой командой создать пустой файл `notes.txt`?

- A. `create notes.txt` — не существует в Linux.
- B. `new notes.txt` — не существует в Linux.
- C. `touch notes.txt` — **правильный ответ**. Создаёт пустой файл или обновляет временные метки.
- D. `make notes.txt` — утилита `make` работает с Makefile, а не с созданием файлов.

### Вопрос 2: Удаление непустого каталога

**Типичный вопрос:** Какой командой удалить каталог `archive` со всем содержимым?

- A. `rm archive` — ошибка: `rm` не удаляет непустые каталоги.
- B. `rmdir archive` — ошибка: `rmdir` работает только с пустыми каталогами.
- C. `rm -r archive` — удаляет рекурсивно, но останавливается на файлах с защищёнными правами.
- D. `rm -rf archive` — **правильный ответ**. Рекурсивное принудительное удаление всего содержимого.

### Вопрос 3: Переименование файла

**Типичный вопрос:** Какой командой переименовать файл `old.log` в `new.log`?

- A. `rn old.log new.log` — не существует в Linux.
- B. `rename old.log new.log` — утилита `rename` существует, но служит для массового переименования по regex, синтаксис иной.
- C. `cp old.log new.log` — создаст копию, оригинал останется.
- D. `mv old.log new.log` — **правильный ответ**. Переименовывает файл.

### Вопрос 4: Поведение `touch` на существующем файле

**Типичный вопрос:** Что делает команда `touch existing.txt`, если файл уже существует?

- A. Удаляет файл и создаёт новый пустой.
- B. Усекает файл до нулевого размера.
- C. Обновляет временные метки (atime, mtime) без изменения содержимого — **правильный ответ**.
- D. Ничего не делает, выводит ошибку.

### Вопрос 5: Удаление пустого каталога

**Типичный вопрос:** Какой командой удалить пустой каталог `logs`?

- A. `rm logs` — неверно, `rm` удаляет только файлы.
- B. `rm -r logs` — работает, но избыточно для пустого каталога.
- C. `rmdir logs` — **правильный ответ**. Специальная утилита для пустых каталогов.
- D. `del logs` — не существует в Linux.

## Устранение неполадок

### `rm: cannot remove 'file': Text file busy` (ETXTBSY)

**Причина:** Файл является исполняемым образцом процесса, который запущен и работает. Ядро не позволяет удалить или заменить файл, пока он используется.

**Решение:**
1. Остановить процесс: `systemctl stop myapp` или `kill PID`.
2. Затем удалить/заменить файл.
3. Для systemd-юнитов используйте `ExecStartPre=/usr/bin/rm -f` с `ExecStart=/bin/true` для очистки PID-файлов.

### `mv: cannot move 'src' to 'dst': Invalid cross-device link` (EXDEV)

**Причина:** Перемещение между разными файловыми системами. `rename(2)` работает только внутри одной точки монтирования.

**Решение:** Использовать `rsync -a` + проверка целостности + `rm` источника, либо `cp -a` + `rm`.

### `cp: failed to preserve...` предупреждения

**Причина:** При `cp -a` некоторые атрибуты (расширенные атрибуты, ACL) могут не поддерживаться на целевой ФС.

**Решение:** Это обычно безопасно — используйте `--no-preserve=xattr` для подавления, либо `rsync -aAX` для полного сохранения.

### `rm: cannot remove 'dir': Permission denied`

**Причина:** Отсутствуют права на запись в родительский каталог.

**Диагностика:**
```bash
ls -ld /parent/dir
# → drwxr-xr-x 2 user user ... /parent/dir  (нет прав w)
```

**Решение:** `chmod u+w /parent/dir` или `sudo rm`.

### Файл не удаляется из-за атрибута `immutable`

**Причина:** Файл защищён расширенным атрибутом `immutable` (`chattr +i`).

**Диагностика:**
```bash
lsattr file.txt
# → ----i-------- file.txt
```

**Решение:**
```bash
chattr -i file.txt
rm file.txt
```

### `rm -rf` удалил не всё (частичное удаление)

**Причина:** Файлы с атрибутом `immutable` или открытые файлы, удерживаемые процессами.

**Диагностика:**
```bash
lsof +D /path/to/dir
```

### `touch: cannot touch 'file': Permission denied`

**Причина:** Недостаточно прав на запись в родительский каталог. Права на сам файл не важны — важны права на каталог.

**Решение:** Проверить права на родительский каталог: `ls -ld /path/to/parent/`.

### Потеря данных после `rm` — восстановление через hard link

**Сценарий:** Если файл удалён, но на него есть жёсткая ссылка (otкрытый процесс держит fd), данные сохраняются.

**Диагностика:**
```bash
# Найти процессы с открытыми файлами в удалённой директории
lsof +L1 /path/to/deleted/
```

Подробнее о восстановлении: [Восстановление после `rm`](#восстановление-после-rm).

## Дополнительная информация

### Поведение `mv` при пересечении границ ФС

| Сценарий | Механизм | Inode |
| :--- | :--- | :--- |
| Одна ФС | Атомарный `rename(2)` | Не меняется |
| Разные ФС | `cp` + `unlink()` оригинала | Меняется |

### Поведение `cp` и `mv` в контексте SELinux

- При **копировании** (`cp`) целевой файл наследует метку безопасности (SELinux context) целевой директории.
- При **перемещении** (`mv`) файл сохраняет исходную метку безопасности.

```bash
# Восстановление контекста после копирования:
restorecon -v /path/to/copied-file

# Перемещение с сохранением контекста:
mv /srv/old-app/ /srv/new-app/
# → контекст /srv/new-app/* остаётся от /srv/old-app/*
```

### Связанные команды

- `touch` — создание пустых файлов и обновление временных меток.
- `rm` / `rmdir` — удаление файлов и каталогов.
- `cp` — копирование файлов и каталогов.
- `mv` — перемещение и переименование.
- `mkdir` — создание каталогов.
- `ln` — создание жёстких и символических ссылок.
- `truncate` — усечение файла до заданного размера.
- `install` — копирование с одновременной установкой прав и владельца.
- `find` — поиск и массовая операции с файлами (включая `-delete`).
- `cmp` / `diff` — проверка целостности после копирования.
- `chattr` / `lsattr` — управление расширенными атрибутами (immutable).
- `rsync` — синхронизация с инкрементальными копиями.
