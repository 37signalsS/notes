# Поиск текста с помощью grep

## Определения

- **`grep` (Global Regular Expression Print)**: Универсальная консольная утилита для поиска строк, соответствующих заданному шаблону. Она считывает входные данные (файлы или стандартный ввод) и выводит те строки, которые содержат совпадения с регулярным выражением.
- **Шаблон (Pattern)**: Строка или регулярное выражение, определяющее критерии поиска.

---

## Базовые концепции

### Ключи и флаги управления поиском

| Ключ | Длинный ключ | Описание |
| :--- | :--- | :--- |
| `-i` | `--ignore-case` | Игнорировать регистр символов при поиске. |
| `-v` | `--invert-match` | Инвертировать поиск: выводить только те строки, которые **не** содержат шаблон. |
| `-r`, `-R` | `--recursive` | Рекурсивный поиск во всех файлах внутри указанной директории. |
| `-l` | `--files-with-matches` | Вывести только имена файлов, в которых найдено хотя бы одно совпадение. |
| `-L` | `--files-without-match` | Вывести только имена файлов, в которых **не** найдено ни одного совпадения. |
| `-c` | `--count` | Вывести только общее количество строк с совпадениями для каждого файла. |
| `-n` | `--line-number` | Предварять каждую выводимую строку её номером в исходном файле. |
| `-w` | `--word-regexp` | Поиск точного совпадения целого слова (окруженного пробелами или знаками пунктуации). |
| `-x` | `--line-regexp` | Поиск точного совпадения всей строки целиком. |
| `-E` | `--extended-regexp` | Использовать расширенный синтаксис регулярных выражений (ERE). |
| `-F` | `--fixed-strings` | Интерпретировать шаблон как обычную строку (литерал), а не регулярное выражение. Ускоряет поиск. |
| `-P` | `--perl-regexp` | Использовать синтаксис регулярных выражений Perl (PCRE). Поддерживает сложные конструкции. |
| `-q` | `--quiet`, `--silent` | Тихий режим. Ничего не выводит. Используется для проверки [кода выхода](exit_codes.md): `0` (найдено), `1` (нет). |
| `-o` | `--only-matching` | Выводить только ту часть строки, которая совпала с шаблоном, а не всю строку. |
| `-h` | `--no-filename` | Не выводить имена файлов в результатах при поиске по нескольким файлам. |
| `-H` | `--with-filename` | Всегда выводить имена файлов (по умолчанию при поиске в нескольких файлах). |
| `-f file` | `--file=file` | Читать список шаблонов из указанного файла (один шаблон на строку). |
| `-m N` | `--max-count=N` | Прекратить чтение файла после нахождения `N` совпадающих строк. |
| `-I` | | Игнорировать бинарные файлы (пропускать их). |
| `-a` | `--text` | Обрабатывать бинарный файл так, будто он текстовый. |
| `--color` | | Подсветка совпадений. Доступные режимы: `never`, `always`, `auto`. |

### Управление контекстом вывода

Иногда важно видеть не только саму строку, но и строки, расположенные рядом с ней.

| Ключ | Описание |
| :--- | :--- |
| `-A N` | `--after-context=N` — вывести `N` строк **после** совпадения. |
| `-B N` | `--before-context=N` — вывести `N` строк **до** совпадения. |
| `-C N` | `--context=N` — вывести `N` строк **вокруг** совпадения (до и после). |

## Практические сценарии

### Простой поиск в файле

```bash
# Поиск пользователя в файле passwd
grep "/bin/bash" /etc/passwd
```

### Поиск без учёта регистра и подсветка

```bash
# Поиск ошибок в логах с выделением цветом
grep -i --color "error" /var/log/syslog /var/log/messages
```

### Поиск нескольких шаблонов (логическое ИЛИ)

Существует два основных способа объединения шаблонов:

```bash
# 1. Использование расширенных регулярных выражений (-E) и символа |
grep -E "error|critical|warning" /var/log/syslog

# 2. Использование нескольких флагов -e (совместимо с BRE)
grep -e "error" -e "critical" /var/log/syslog
```

### Поиск точного слова или строки

```bash
# Найти только слово "bin", исключая "sbin", "binary" и т.д.
grep -w "bin" /etc/passwd

# Найти строку, которая полностью идентична "root" (без лишних символов)
grep -x "root" my_file.txt
```

### Рекурсивный поиск с гибкими исключениями

При работе с большими проектами важно исключать системные или временные файлы.

```bash
# Поиск "TODO" во всех файлах, кроме логов и директории .git
grep -r --exclude="*.log" --exclude-dir=".git" "TODO" .

# Искать только в файлах с расширением .py
grep -r --include="*.py" "def main" ./src
```

### Использование в скриптах для проверки условий (`-q`)

Флаг `-q` идеально подходит для логических веток в bash-скриптах.

```bash
# Проверить наличие пользователя перед выполнением действий
if grep -q "^root:" /etc/passwd; then
    echo "Пользователь root обнаружен."
fi

# Идемпотентное добавление строки в файл
LINE="127.0.0.1 myhost.local"
FILE="/etc/hosts"
if ! grep -qFx "$LINE" "$FILE"; then
    echo "$LINE" | sudo tee -a "$FILE" > /dev/null
fi
```

### Поиск специальных символов и экранирование

Символы, имеющие значение в регулярных выражениях (`.`, `*`, `[`, `]`, `(`, `)`, `$`, `^`, `|`, `\`), должны экранироваться обратным слэшем или заключаться в одинарные кавычки.

```bash
# Поиск строки "[DEBUG]" в логе
grep '\[DEBUG\]' app.log

# Поиск точки в конце предложения
grep '\.$' README.md
```

### Поиск в сжатых файлах (`zgrep`, `bzgrep`, `xzgrep`)

Утилиты-обертки позволяют искать текст в сжатых файлах без их предварительной распаковки.

```bash
# Поиск в архивном логе
zgrep -i "exception" /var/log/application.log.2.gz
```

### Обработка бинарных данных

```bash
# Извлечение текста из бинарного файла (например, поиск версии в исполняемом файле)
grep -a "Version:" ./my_app
```

## Дополнительная информация

### Режимы регулярных выражений

1. **BRE (Basic Regular Expressions)**: Режим по умолчанию. Большинство спецсимволов (`?`, `+`, `{`, `|`, `(`) воспринимаются как обычные символы, если они не экранированы (`\?`, `\+` и т.д.).
2. **ERE (Extended Regular Expressions)**: Активируется флагом `-E`. Спецсимволы работают "из коробки" без экранирования.
3. **PCRE (Perl Compatible Regular Expressions)**: Активируется флагом `-P`. Самый мощный синтаксис, поддерживающий "просмотр вперед/назад" (look-ahead/look-behind), нежадную типизацию и другие расширенные возможности.

> **Важно:** Устаревшие команды `egrep` и `fgrep` соответствуют `grep -E` и `grep -F`. В современных системах рекомендуется использовать `grep` с соответствующими флагами для обеспечения совместимости и соответствия стандартам POSIX.

### Опасность перенаправления `grep pattern file > file`

Перенаправление вывода (`>`) обрабатывается оболочкой (shell) **до** фактического запуска команды `grep`. В момент обработки `>` оболочка обнуляет (truncates) файл, чтобы подготовить его к записи. В итоге `grep` пытается читать уже пустой файл.

**Пример ошибки:**
```bash
# ОШИБКА — содержимое my_file.txt будет безвозвратно удалено!
grep "pattern" my_file.txt > my_file.txt
```

**Безопасные решения для редактирования файлов:**

1. **Использование временного файла (классический способ)**:
    ```bash
    grep "pattern" config.conf > config.conf.tmp && mv config.conf.tmp config.conf
    ```

2. **Утилита `sponge`** (из пакета `moreutils`):
    Она считывает весь ввод в память и записывает в файл только после закрытия входного потока.
    ```bash
    grep "pattern" config.conf | sponge config.conf
    ```

3. **Использование `sed -i`** (редактирование "на месте"):
    В некоторых случаях проще использовать `sed` для фильтрации строк.
    ```bash
    # Удалить все строки, НЕ содержащие "pattern"
    sed -i '/pattern/!d' config.conf
    ```

### Связанные инструменты и альтернативы

- **`pgrep`**: Специализированная утилита для поиска процессов по имени. [Сценарии использования](../Core/processes/practical_scenarios.md#выбор-между-pidof-и-pgrep).
- **`ripgrep (rg)`**: Современная замена `grep`, написанная на Rust. Работает значительно быстрее, учитывает `.gitignore` по умолчанию и имеет отличную цветовую индикацию.
- **`ack` / `ag` (The Silver Searcher)**: Инструменты, оптимизированные для поиска по коду, предшественники `ripgrep`.
- **[Регулярные выражения (RegEx)](./regular_expressions.md)**: Подробный справочник по синтаксису, используемому в `grep`.
