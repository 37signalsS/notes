# Поиск текста с помощью grep

## Определения

- **`grep` (Global Regular Expression Print):** Утилита командной строки для поиска текстовых данных по шаблону. Она читает входные данные (файл или поток) и выводит строки, содержащие совпадение с заданным [регулярным выражением](https://ru.wikipedia.org/wiki/Регулярные_выражения).
- **Шаблон (Pattern):** Строка или регулярное выражение, которое `grep` использует для поиска.

---

## Базовые концепции: Ключи (флаги)

Ключи изменяют поведение `grep` по умолчанию.

| Ключ | Длинный ключ | Описание |
| :--- | :--- | :--- |
| `-i` | `--ignore-case` | Игнорировать регистр символов при поиске. |
| `-v` | `--invert-match` | Инвертировать поиск: вывести строки, которые **не** содержат шаблон. |
| `-r`, `-R` | `--recursive` | Рекурсивно искать во всех файлах указанной директории. |
| `-l` | `--files-with-matches` | Вывести только имена файлов, в которых найдены совпадения. |
| `-c` | `--count` | Посчитать и вывести количество строк с совпадениями. |
| `-n` | `--line-number` | Показать номер строки перед каждой строкой с совпадением. |
| `-E` | `--extended-regexp` | Использовать расширенный синтаксис регулярных выражений (ERE). |
| `-F` | `--fixed-strings` | Искать точную строку, а не регулярное выражение. Ускоряет поиск. |
| `-q` | `--quiet`, `--silent` | "Тихий" режим. Ничего не выводить, только вернуть [код выхода](exit_codes.md) `0` (найдено) или `1` (не найдено). |
| `-A N` | `--after-context=N` | Показать `N` строк **после** совпадения. |
| `-B N` | `--before-context=N` | Показать `N` строк **до** совпадения. |
| `-C N` | `--context=N` | Показать `N` строк **вокруг** (до и после) совпадения. |

## Практические сценарии

### 1. Простой поиск в файле

Найти всех пользователей с оболочкой `/bin/bash`.

```bash
grep "/bin/bash" /etc/passwd
```

### 2. Поиск без учета регистра в нескольких файлах

Найти слово "error" или "ERROR" во всех лог-файлах.

```bash
grep -i "error" /var/log/syslog /var/log/messages
```

### 3. Рекурсивный поиск файлов по содержимому

Найти все файлы в текущей директории и ее поддиректориях, содержащие слово "TODO".

```bash
grep -r -l "TODO" .
```

### 4. Использование в скриптах для проверки условий (`grep -q`)

Флаг `-q` идеально подходит для использования в `if` или в связке с `&&` / `||`, так как он не выводит текст, а только возвращает код `0` (успех/найдено) или `1` (неудача/не найдено).

```bash
# Проверить, существует ли пользователь 'root', и вывести сообщение
if grep -q "^root:" /etc/passwd; then
    echo "Пользователь root существует."
fi

# Добавить строку в файл, только если ее там еще нет
LINE="127.0.0.1 myhost"
FILE="/etc/hosts"
# -F ищет точную строку, -x сопоставляет всю строку целиком
if ! grep -qFx "$LINE" "$FILE"; then
    echo "$LINE" | sudo tee -a "$FILE"
fi
```

### 5. Поиск в сжатых файлах (`zgrep`)

Для поиска в `.gz` архивах без их предварительной распаковки используется `zgrep`. Ключи те же, что и у `grep`.

```bash
# Найти ошибки в ротированных логах
zgrep -i "error" /var/log/syslog.2.gz
```

## Дополнительная информация

### Режимы регулярных выражений

- **BRE (Basic Regular Expressions):** Режим по умолчанию. Некоторые символы, такие как `?`, `+`, `{}`, `|`, `()`, теряют свое специальное значение и для их активации требуют обратного слэша (`\?`, `\+` и т.д.).
- **ERE (Extended Regular Expressions):** Активируется флагом `-E` (или использованием команды `egrep`). В этом режиме специальные символы работают как ожидается, без экранирования.
- **PCRE (Perl Compatible Regular Expressions):** Наиболее мощный движок, активируется флагом `-P`. Поддерживает look-arounds, non-greedy matching и другие продвинутые возможности.

### Опасность `grep file > file`

Никогда не используйте `grep` для фильтрации файла с одновременной записью в него же.
```bash
# НЕПРАВИЛЬНО! Это сотрет содержимое файла.
grep "pattern" my_file.txt > my_file.txt
```
Оболочка обрабатывает перенаправление `>` **до** запуска команды `grep`, обнуляя файл. Подробнее см. в [статье о перенаправлении ввода/вывода](io_redirection.md).
