# Поиск текста с помощью grep

## Определения

**grep** (Global Regular Expression Print) — универсальная консольная утилита для поиска строк, соответствующих заданному шаблону. Она считывает входные данные (файлы или стандартный ввод) и выводит те строки, которые содержат совпадения с регулярным выражением.

- **Шаблон (Pattern)**: Строка или регулярное выражение, определяющее критерии поиска.
- **Стандарты**: Утилита является частью POSIX. В Linux-системах преобладает **GNU grep**, обладающая расширенным функционалом. В macOS/BSD используется **BSD grep**, который может иметь отличия в производительности и поддержке некоторых флагов.
- **Отличие от `find`**: `find` ищет **файлы** по атрибутам (имя, размер, время), `grep` ищет **текст внутри** файлов или stdin. Это ключевое различие в экзаменационных вопросах LPIC-1.

### Внутренний механизм работы

Понимание принципа работы помогает выбирать правильные флаги и anticipating edge cases.

- **Алгоритм Бойера-Мура (Boyer-Moore)**: `grep` использует этот алгоритм для быстрого сканирования. Он сравнивает шаблон с текстом справа налево и пропускает участки, которые точно не могут совпасть. Это делает поиск фиксированных строк (`-F`) особенно быстрым на больших файлах.
- **Режимы движка**:
  - **DFA (Deterministic Finite Automaton)**: Используется для BRE/ERE. Гарантирует линейное время поиска относительно размера файла.
  - **NFA (Nondeterministic Finite Automaton)**: Используется для PCRE (`-P`). Мощнее, но может потреблять больше памяти на сложные шаблоны.
- **Буферизация и память**: `grep` читает данные блоками (обычно 64 КБ). При поиске с контекстом (`-A`, `-B`, `-C`) он хранит в памяти контекстные буферы для каждого совпадения.
- **Обработка бинарных файлов**: По умолчанию GNU `grep` определяет файл как бинарный, если встречает NUL-байт в первых 32 КБ, и выводит `Binary file matches`. Это защита от «мусора» в терминале.

## Базовые концепции

### Ключи и флаги управления поиском

| Ключ | Длинный ключ | Описание |
| :--- | :--- | :--- |
| `-i` | `--ignore-case` | Игнорировать регистр символов при поиске. |
| `-v` | `--invert-match` | Инвертировать поиск: выводить строки, которые **не** содержат шаблон. |
| `-r`, `-R` | `--recursive` | Рекурсивный поиск во всех файлах внутри директории. |
| `-l` | `--files-with-matches` | Вывести только имена файлов с совпадениями. |
| `-L` | `--files-without-match` | Вывести только имена файлов **без** совпадений. |
| `-c` | `--count` | Вывести количество строк с совпадениями для каждого файла. |
| `-n` | `--line-number` | Предварять строку её номером в исходном файле. |
| `-w` | `--word-regexp` | Поиск точного совпадения целого слова. |
| `-x` | `--line-regexp` | Поиск точного совпадения всей строки целиком. |
| `-E` | `--extended-regexp` | Использовать расширенный синтаксис регулярных выражений (ERE). |
| `-F` | `--fixed-strings` | Интерпретировать шаблон как литерал (ускоряет поиск). |
| `-P` | `--perl-regexp` | Использовать синтаксис регулярных выражений Perl (PCRE). |
| `-q` | `--quiet`, `--silent` | Тихий режим. Ничего не выводит, используется для проверки кодов выхода. |
| `-o` | `--only-matching` | Выводить только совпавшую часть строки, а не всю строку. |
| `-h` | `--no-filename` | Не выводить имена файлов в результатах поиска. |
| `-H` | `--with-filename` | Всегда выводить имена файлов (по умолчанию для нескольких файлов). |
| `-f file` | `--file=file` | Читать список шаблонов из указанного файла (один на строку). |
| `-m N` | `--max-count=N` | Прекратить чтение файла после нахождения `N` совпадающих строк. |
| `-I` | | Игнорировать бинарные файлы. |
| `-a` | `--text` | Обрабатывать бинарный файл как текстовый. |
| `--color` | | Подсветка совпадений (`never`, `always`, `auto`). |
| `-b` | `--byte-offset` | Выводить смещение в байтах от начала файла для каждого совпадения. |
| `--exclude-dir=DIR` | | Исключить указанные директории из рекурсивного поиска. |
| `--exclude=GLOB` | | Исключить файлы по glob-паттерну (например, `*.log`). |
| `--include=GLOB` | | Искать только в файлах, соответствующих glob-паттерну. |
| `--null` | `-Z` | Выводить `\0` после имени файла (полезно с `xargs -0`). |

### Управление контекстом вывода

Критически важно для анализа журналов, чтобы видеть события, предшествующие ошибке или следующие за ней.

| Ключ | Длинный ключ | Описание |
| :--- | :--- | :--- |
| `-A N` | `--after-context=N` | Вывести `N` строк **после** совпадения. |
| `-B N` | `--before-context=N` | Вывести `N` строк **до** совпадения. |
| `-C N` | `--context=N` | Вывести `N` строк **вокруг** совпадения (до и после). |

### Коды завершения (Exit Codes)

- **`0`**: Найдено хотя бы одно совпадение.
- **`1`**: Совпадений не найдено.
- **`2`**: Произошла системная ошибка (файл не найден, ошибка синтаксиса шаблона).

### Оптимизация производительности

Для ускорения поиска в гигантских файлах (сотни ГБ) рекомендуется использовать локаль `C`. Это отключает многобайтовую обработку UTF-8, что может ускорить поиск в 10–100 раз.

```bash
# Экстремально быстрый поиск в больших логах
LC_ALL=C grep "pattern" large_file.log
```

## Практические сценарии

### Базовый поиск и фильтрация

```bash
# Поиск пользователя в passwd
grep "/bin/bash" /etc/passwd

# Поиск ошибок без учета регистра с подсветкой
grep -i --color "error" /var/log/syslog

# Фильтрация вывода других команд через конвейер
ls -la | grep -i "work"
```

### Фильтрация истории команд

```bash
# Найти все команды, содержащие "docker", в истории
history | grep docker

# Поиск без учета регистра
history | grep -i "kubectl"
```

### Логическое ИЛИ и расширенные регулярные выражения

```bash
# 1. С использованием ERE (-E)
grep -E "error|critical|warning" /var/log/syslog

# 2. С использованием нескольких флагов -e
grep -e "error" -e "critical" -e "warning" /var/log/syslog
```

### Точные совпадения и рекурсия

```bash
# Найти только слово "bin", исключая "sbin"
grep -w "bin" /etc/passwd

# Рекурсивный поиск с исключениями
grep -r --exclude="*.log" --exclude-dir=".git" "TODO" .

# Поиск только в определенных файлах
grep -r --include="*.py" "def main" ./src
```

### Фильтрация по началу/концу строки (якоря)

Символы `^` и `$` привязывают шаблон к началу и концу строки соответственно. Подробнее о синтаксисе якорей — в [Регулярные выражения (RegEx)](./regular_expressions.md).

```bash
# Строго начало строки: найти строки, начинающиеся с "debian"
grep -E '^debian' /etc/apt/sources.list

# Строго конец строки: найти строки, заканчивающиеся на ".conf"
grep -E '\.conf$' /etc/

# Удалить пустые строки из вывода/файла
grep -v '^$' config.conf

# Удалить пустые строки и строки только из пробелов
grep -vE '^[[:space:]]*$' config.conf
```

Типичный сценарий: предварительная очистка логов или конфигов перед дальнейшим парсингом.

### Использование в скриптах (`-q`)

Идеально для проверки условий без вывода лишнего мусора в stdout.

```bash
# Идемпотентное добавление строки
LINE="127.0.0.1 myhost.local"
FILE="/etc/hosts"
if ! grep -qFx "$LINE" "$FILE"; then
    echo "$LINE" | sudo tee -a "$FILE" > /dev/null
fi
```

### Фильтрация и подсчёт событий в логах (экзамен LPIC-1 103.2)

Типичный экзаменационный паттерн раздела 103.2 — выбрать строки по шаблону и посчитать их количество через конвейер с `wc -l`.

```bash
# Подсчитать количество запросов с кодом 404 в логе доступа (без учёта регистра)
grep -i "404" /var/log/nginx/access.log | wc -l
# → 137

# Показать всё, КРОМЕ строк с 404 (инверсия поиска)
grep -v "404" /var/log/nginx/access.log
```

Ключевые моменты, проверяемые на экзамене:
- `grep -i` находит совпадения независимо от регистра (например, `404`, `GET /x 404`, `404 Not Found`), что критично, когда формат лога или сообщение об ошибке варьируется.
- `wc -l` считает переводы строк в выводе `grep`, то есть количество **найденных записей**, а не совпадений внутри одной строки.
- `grep -v "404"` выводит строки, **не** содержащие шаблон, — удобно для задачи «показать всё, кроме ошибок 404». Не путать с отсутствием флага: без `-v` выводятся только строки с 404.
- Порядок важен: сначала `grep` фильтрует поток, затем `wc -l` подсчитывает. Замена `wc -l` на `wc -c` дала бы размер в байтах, а не число строк.

### Продвинутый поиск с PCRE (-P)

Позволяет использовать "просмотр вперед/назад" (look-around) и извлекать только нужные части данных.

```bash
# Извлечение значения из конфига (используя look-behind)
# Находит значение переменной server_name, не включая само имя переменной в вывод
grep -oP '(?<=server_name\s)\S+' nginx.conf

# Извлечение IP-адресов
grep -oP '\d{1,3}(\.\d{1,3}){3}' access.log
```

### Сжатые файлы и бинарные данные

```bash
# Поиск в архивных логах
zgrep -i "exception" /var/log/app.log.1.gz

# Поиск текста в исполняемом файле
grep -a "Version:" ./binary_app
```

### Триаж инцидентов: быстрый анализ логов

При работе с инцидентами часто нужно быстро найти «виновника» среди тысяч строк логов. `grep` позволяет выделить критические события, игнорируя шум.

```bash
# Найти все критические ошибки в системном логе за последний час
journalctl --since "1 hour ago" | grep -iE "panic|oops|error|fail|crit"

# Найти ошибки, связанные с конкретным процессом
journalctl -u nginx --since "10 minutes ago" | grep -i "worker_connections"

# Показать только уникальные сообщения об ошибках (убрать дубликаты)
grep -i "error" /var/log/syslog | sort | uniq -c | sort -rn | head -20
```

### Аудит конфигураций на соответствие (Compliance)

`grep` используется для проверки, что конфигурационные файлы соответствуют политикам безопасности.

```bash
# Проверить, что SSH запрещает вход под root
grep -E '^PermitRootLogin\s+no' /etc/ssh/sshd_config

# Найти все файлы с открытым доступом 777
find /etc -type f -perm 0777 -exec grep -l "." {} \;

# Проверить, что в sudoers нет NOPASSWD для всех (ALL=(ALL) NOPASSWD: ALL)
grep -r "NOPASSWD: ALL" /etc/sudoers.d/
```

### Поиск секретов в репозитории (предварительная проверка)

Важно: этот сценарий использует `grep` только для локального аудита. Секреты не должны попадать в логи.

```bash
# Поиск потенциальных секретов (пароли, ключи) в текущем каталоге
grep -rniE "(password|api_key|secret|token)\s*[:=]\s*['\"][^'\"]+['\"]" .

# Поиск приватных ключей SSH
grep -rli "BEGIN RSA PRIVATE KEY" .

# Исключая .git и node_modules
grep -rniE "password|secret|token" . --exclude-dir={.git,node_modules,vendor}
```

### Интеграция с find и xargs

Для поиска по нескольким файлам с обработкой имён, содержащих пробелы, используйте `-print0` и `grep -Z`.

```bash
# Поиск "TODO" во всех .py файлах (пробелы в именах файлов безопасны)
find . -type f -name "*.py" -print0 | xargs -0 grep -n "TODO"

# То же через -exec (удобнее для сложных условий)
find /var/log -type f -name "*.log" -exec grep -l "OutOfMemory" {} \;
```

### Валидация целостности данных и diff

```bash
# Сравнить два конфига и показать только строки, которые отличаются (без самих строк)
diff -y --suppress-common-lines old.conf new.conf | grep -E "^[<>]"

# Найти строки, которые есть в new.conf, но отсутствуют в old.conf
grep -vxF -f old.conf new.conf

# Найти строки, которые есть в old.conf, но отсутствуют в new.conf
grep -vxF -f new.conf old.conf
```

### Мониторинг метрик и curl + grep

При диагностике сервисов часто нужно извлечь конкретную метрику из вывода Prometheus-style endpoints.

```bash
# Проверить, что etcd имеет лидера
curl -s http://localhost:2379/metrics | grep "etcd_server_has_leader"
# → etcd_server_has_leader 1

# Найти только ошибки в логах Grafana
journalctl -u grafana-server --no-pager | grep -i "error"

# Проверить, слушает ли процесс порт
ss -tlpn | grep ":3000"
```

### Создание отчётов

```bash
# Подсчитать уникальные IP в логе доступа (первое поле)
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -20

# Извлечь все email-адреса из логов

```

## Дополнительная информация

### Режимы регулярных выражений

1. **BRE (Basic Regular Expressions)**: Режим по умолчанию. Метасимволы `?`, `+`, `{`, `|`, `(` требуют экранирования (`\?`, `\+` и т.д.).
2. **ERE (Extended Regular Expressions)**: Флаг `-E`. Метасимволы работают без экранирования.
3. **PCRE (Perl Compatible)**: Флаг `-P`. Самый мощный синтаксис (нежадность, look-around).

Подробнее о синтаксисе — в [Регулярные выражения (RegEx)](./regular_expressions.md).

> **Примечание:** Устаревшие команды `egrep` и `fgrep` — это алиасы для `grep -E` и `grep -F` соответственно. Рекомендуется использовать флаги.

### GNU и BSD/macOS различия

| Характеристика | GNU grep (Linux) | BSD grep (macOS) |
| :--- | :--- | :--- |
| **По умолчанию** | BRE | BRE |
| **PCRE (`-P`)** | Поддерживается | Не поддерживается |
| **`--color`** | Поддерживается | Требует `--color=auto` или `GREP_OPTIONS` |
| **`--exclude-dir`** | Поддерживается | Поддерживается |
| **`-r` vs `-R`** | Оба рекурсивных | `-R` следует симлинкам, `-r` — нет |
| **Производительность** | Высокая (Boyer-Moore, многопоточность в новых версиях) | Базовая |

### Поведение на граничных случаях

| Случай | Поведение grep | Рекомендация |
| :--- | :--- | :--- |
| **Пустой файл** | Ничего не выводит, код возврата `1` | Ожидаемо; используйте `-L`, чтобы проверить пустоту |
| **Файл без завершающего `\n`** | Обрабатывает последнюю строку корректно | Нет проблем, grep читает до EOF |
| **Бинарный файл** | По умолчанию: `Binary file <name> matches` | Используйте `-a` или `--binary-files=text` для принудительной текстовой обработки |
| **Очень длинные строки (>128 КБ)** | Может замедлиться (переключение в линейный режим) | Разбить файл на части или использовать `-F` |
| **NUL-байты внутри файла** | `grep` останавливается на NUL (считает строку завершённой) | Используйте `-z` для обработки NUL-separated данных |
| **Имена файлов с пробелами** | Безопасно при использовании кавычек | Всегда используйте кавычки вокруг переменных |

### Опасность перенаправления `grep pattern file > file`

Оболочка (shell) обнуляет файл (`truncate`) **до** запуска `grep`. В итоге `grep` будет читать пустой файл.

**Безопасные решения:**

1. **Временный файл**:
   ```bash
   grep "pattern" config.conf > config.conf.tmp && mv config.conf.tmp config.conf
   ```
2. **Утилита `sponge`** (пакет `moreutils`):
   ```bash
   grep "pattern" config.conf | sponge config.conf
   ```
3. **Использование `sed -i`**:
   ```bash
   # Удалить всё, что не совпадает (аналог фильтрации grep)
   sed -i '/pattern/!d' config.conf
   ```

### Производительность

| Сценарий | Рекомендация | Ожидаемый эффект |
| :--- | :--- | :--- |
| **Большие файлы, фиксированный шаблон** | `grep -F` | В 10–100 раз быстрее за счёт Бойера-Мура |
| **Гигантские логи (>10 ГБ)** | `LC_ALL=C grep ...` | Ускорение в 10–100 раз (отключение UTF-8) |
| **Поиск только в заголовках файлов** | `head -n 1000 file \| grep` | Ограничивает объём чтения |
| **Поиск по сети (NFS)** | `grep -m 10` + кэш | Останавливается после первых совпадений, минимизирует сетевые чтения |
| **Многопоточность** | GNU `grep` с `--threads` (>= 3.1) | Распараллеливает чтение больших файлов |

### Безопасность и лучшие практики

- **Валидация ввода**: Никогда не передавайте в `grep` непроверенные пользовательские данные в шаблон без санитизации. Особенно актуально для скриптов, обрабатывающих аргументы командной строки.
- **Атомарность**: При изменении файлов через `grep` с перенаправлением используйте временные файлы и `mv`, чтобы избежать потери данных при прерывании.
- **Симлинки**: `grep -r` по умолчанию не следует симлинкам. Если нужно включить: `grep -r -L` (GNU) или `grep -r` (BSD/macOS). Будьте осторожны с `-R` на Linux — он может зациклить по `/proc`.
- **Обработка бинарных файлов**: Добавляйте `-I`, чтобы исключить бинарники из поиска и не засорять вывод.
- **Ограничение контекста**: При работе с логами в production не используйте неограниченный `-C` без `head`/`tail`, чтобы не вывести терабайты данных.

### Переменные окружения

| Переменная | Влияние на `grep` |
| :--- | :--- |
| `LC_ALL`, `LC_CTYPE` | Влияют на обработку многобайтовых символов и классы `[[:alpha:]]`. Для максимальной скорости установите `C`. |
| `GREP_OPTIONS` | Устаревшая переменная для глобальных опций (не рекомендуется в скриптах; используйте алиас `alias grep='grep --color=auto'`). |
| `POSIXLY_CORRECT` | Заставляет `grep` строго следовать POSIX, отключая некоторые GNU-расширения. |

| Код | Значение |
| :--- | :--- |
| `0` | Успешное завершение, найдено хотя бы одно совпадение |
| `1` | Совпадений не найдено |
| `2` | Ошибка открытия файла, неверные аргументы или внутренняя ошибка |

### Типичные ошибки и устранение неполадок

| Симптом | Возможная причина | Решение |
| :--- | :--- | :--- |
| `grep: binary file ... matches` | Файл содержит NUL-байты | Добавить флаг `-a` или `--binary-files=text` |
| Нет вывода, хотя совпадение есть | Неправильные кавычки (shell раскрыл `*`) | Использовать одинарные кавычки вокруг шаблона |
| `grep: ...: No such file or directory` | Файл не существует или опечатка в пути | Проверить путь, учесть регистр (macOS) |
| Медленный поиск в больших файлах | Нет `-F`/`LC_ALL=C` | Использовать `grep -F` или `LC_ALL=C grep` |
| `grep: warning: GREP_OPTIONS is deprecated` | Устаревшая переменная окружения | Удалить из `.bashrc`/`.zshrc`, перейти на алиас |
| Поиск по симлинкам не работает | `grep -r` не следует ссылкам на Linux | Добавить `-L` или использовать `find` + `xargs` |
| Не работает `grep -P` на macOS | BSD grep не поддерживает PCRE | Установить GNU grep: `brew install grep` и использовать `ggrep` |
| `grep: memory exhausted` | Слишком сложный PCRE-шаблон или огромный файл | Упростить шаблон, добавить `-F`, разбить файл |

### Поиск с номером строки и рекурсией

```bash
# Рекурсивный поиск с номерами строк и именами файлов
grep -rn 'panic:' /var/log/app/

# Инверсия: удалить комментарии и пустые строки из конфига
grep -v '^#' /etc/nginx/nginx.conf | grep -v '^[[:space:]]*$'
```

### Рипгреп (ripgrep / rg)

`ripgrep` — современная замена `grep`, написанная на Rust. По умолчанию уважает `.gitignore`, `.ignore` и `.rgignore`, ищет рекурсивно и использует все ядра CPU. Поддерживает почти все флаги `grep`, плюс собственные расширения.

```bash
# Быстрый поиск по типу файлов (замена --include)
rg 'TODO|FIXME|HACK' --type py -l

# Поиск с контекстом (аналог -C3)
rg 'panic' -C3 --glob '*.go'

# Поиск в скрытых и .gitignore-файлах
rg 'secret_key' --hidden --no-ignore

# Предпросмотр замены без записи в файл
rg 'old_value' --replace 'new_value' --passthru config.yaml

# Статистика поиска: совпадения, файлы, время
rg 'error' /var/log/ --stats 2>&1 | tail -5

# Поиск в бинарном файле (аналог grep -a)
rg -a 'password' /proc/<pid>/mem 2>/dev/null | strings | head -20
```

### Связанные инструменты и альтернативы

- **`ripgrep (rg)`**: Современная замена на Rust. Значительно быстрее, по умолчанию уважает `.gitignore`. Рекомендуется для DevOps.
- **`pgrep`**: Поиск процессов по имени. [Сценарии использования](../Core/processes/practical_scenarios.md).
- **`ack` / `ag` (The Silver Searcher)**: Поиск по исходному коду.
- **[Регулярные выражения (RegEx)](./regular_expressions.md)**: Подробный справочник по синтаксису.
