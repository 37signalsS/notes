### 1. Эмулятор терминала (Terminal Emulator)

Это **графическое приложение**, то есть окно, которое вы открываете, чтобы начать работу. Его единственная задача — предоставить вам интерфейс для взаимодействия с оболочкой (шеллом), обрабатывать ввод с клавиатуры и отображать текстовый вывод.

### 2. Шел / Оболочка (Shell)

Это **программа-интерпретатор**, которая работает *внутри* эмулятора терминала. Именно она принимает ваши команды, "понимает" их и говорит ядру операционной системы, что нужно сделать. Она также отвечает за переменные окружения (`$PATH`), скрипты (например, `.bashrc`) и управление процессами.


### 3. Командная строка (Command Line)

Это и есть сам **текстовый интерфейс** для ввода команд, который предоставляет вам шелл. Если точнее, это одна строка, в которой вы печатаете команду. Она обычно начинается с приглашения (prompt), например `user@hostname:~$`.

### Общая логика обработки команд в Shell

Чтобы понимать любой сложный случай, держите в голове следующий алгоритм, по которому действует оболочка (bash, zsh и т.д.).

#### Шаг 0: Чтение всей строки
Оболочка считывает **всю** командную строку целиком перед тем, как начать ее интерпретировать.

#### Шаг 1: Настройка перенаправлений ввода/вывода (`>`, `<`, `>>`)

Это **первое, что происходит, еще до запуска самой команды**. Оболочка ищет операторы перенаправления и настраивает файловые дескрипторы.

В стандартном варианте работы программы существуют три основных потока данных, каждый из которых связан с файловым дескриптором:
*   **`0` (stdin)**: Стандартный ввод. Программа читает данные из этого потока.
*   **`1` (stdout)**: Стандартный вывод. Программа записывает обычные результаты своей работы в этот поток.
*   **`2` (stderr)**: Стандартный вывод ошибок. Программа записывает сообщения об ошибках в этот поток.

По умолчанию все эти потоки связаны с терминалом.

*   **Перенаправление стандартного вывода (`>` и `>>`)**
    *   `>`: Перенаправляет `stdout` команды в файл, **перезаписывая** его содержимое, если файл существует. Если файла нет, он будет создан.
    *   `>>`: Перенаправляет `stdout` команды в файл, **добавляя** содержимое в конец файла. Если файла нет, он будет создан.

    **Пример:** `ls -l > output.txt`
    1.  Оболочка видит `> output.txt`.
    2.  Она немедленно пытается открыть `output.txt` для записи. Если нет прав, выдаст ошибку.
    3.  Если права есть, она **очищает файл** `output.txt` (или создает его).
    4.  Только после этого запускается команда `ls -l`, чей `stdout` уже направлен в `output.txt`.

*   **Перенаправление стандартного вывода ошибок (`2>`)**
    *   Для перенаправления `stderr` необходимо явно указать файловый дескриптор `2`.
    *   **Пример:** `ls /nonexistent 2> errors.log` — ошибки `ls` будут записаны в `errors.log`.

*   **Объединение потоков (`2>&1` и `&>`)**
    *   `2>&1`: Перенаправляет `stderr` (дескриптор 2) туда же, куда направлен `stdout` (дескриптор 1). Порядок важен: `> file 2>&1` сначала перенаправит `stdout` в `file`, а затем `stderr` туда же. Если написать `2>&1 > file`, то `stderr` будет направлен туда, куда `stdout` был направлен *до* перенаправления в `file`.
    *   `&>`: Сокращенная форма для перенаправления `stdout` и `stderr` в один и тот же файл. `command &> file` эквивалентно `command > file 2>&1`.

*   **Перенаправление стандартного ввода (`<`)**
    *   `command < input.txt`: Команда будет читать свой `stdin` из файла `input.txt`.

*   **Особый файл `/dev/null`**
    *   `/dev/null` — это специальный "пустой" файл в Unix-подобных системах, который действует как "черная дыра". Все, что в него записывается, исчезает, а при чтении из него не возвращается ничего.
    *   Часто используется для подавления нежелательного вывода: `command > /dev/null 2>&1` (подавить весь вывод).

*   **Дублирование вывода с `tee`**
    *   Команда `tee` позволяет одновременно направлять стандартный вывод команды как в файл, так и на стандартный вывод (консоль).
    *   **Пример:** `ls -l | tee output.txt` — вывод `ls -l` будет показан на экране и сохранен в `output.txt`.
    *   **Пример с добавлением:** `ls -l | tee -a output.txt` — добавит вывод в конец `output.txt`.
    *   **Дублирование `stderr`:** Для дублирования `stderr` необходимо сначала перенаправить его в `stdout`: `command 2>&1 | tee errors.txt`.

*   **Критический порядок интерпретации перенаправлений (проблема `grep file > file`)**
    *   **Важно:** Перенаправления (`>`) обрабатываются оболочкой **до** выполнения самой команды. Командная оболочка интерпретирует команду как бы "справа налево": сначала настраивается перенаправление, и только потом выполняется основная команда. Это может привести к необратимой потере данных, если входной и выходной файл совпадают.
    *   **Пример фатальной ошибки:** `grep "pattern" a.txt > a.txt`
        1.  Оболочка считывает всю командную строку.
        2.  Она видит оператор перенаправления `> a.txt` и **немедленно приступает к его обработке**.
        3.  Если файл `a.txt` существует, он **обнуляется (очищается)**. Если не существует, создается пустой файл.
        4.  Только после этого запускается команда `grep "pattern" a.txt`. Но поскольку `a.txt` уже пуст, `grep` не находит данных для чтения.
        5.  В результате `a.txt` становится пустым.
    *   **Решение:** Чтобы избежать такой потери данных, используйте временный файл или утилиты, которые поддерживают редактирование "на месте".
        ```bash
        # 1. Использование временного файла (самый надежный способ)
        grep "pattern" a.txt > a.tmp && mv a.tmp a.txt

        # 2. Использование `sponge` (из пакета moreutils)
        # sponge "впитывает" весь ввод и только потом записывает его в файл
        grep "pattern" a.txt | sponge a.txt

        # 3. Использование sed для редактирования на месте
        sed -i '/pattern/d' a.txt # Удалит строки, НЕ содержащие pattern
        ```



#### Шаг 2: Группировка в конвейеры (`|`)
Оболочка находит команды, соединенные пайпами (`|`), и группирует их в конвейеры. Важно понимать, что **конвейер имеет более высокий приоритет, чем управляющие операторы `&&` и `||`**.

*   **Пример:** `команда1 && команда2 | команда3`
    Оболочка видит это как: `(команда1) && (команда2 | команда3)`.
    Сначала будет выполнена `команда1`. Если она успешна, будет запущен конвейер `команда2 | команда3`.

*   **Перенаправление STDERR в STDIN конвейера**
    По умолчанию конвейер (`|`) перенаправляет только `stdout` предыдущей команды в `stdin` следующей. Чтобы перенаправить `stderr` в `stdin` следующей команды, можно использовать следующую конструкцию:
    ```bash
    # Пример: перенаправить stderr команды 'docker' в 'grep'
    docker run non_existent_image 2>&1 | grep "Error"
    ```
    Здесь `2>&1` перенаправляет `stderr` (`2`) в `stdout` (`1`), который затем передается по конвейеру в `grep`.

## Создание процессов в Linux

В Linux процессы не могут быть созданы "из ниоткуда". Каждый процесс является копией существующего процесса, измененной необходимым образом. Этот механизм называется **fork** (системный вызов `fork()`).

*   **Древовидная структура:** Процессы в Linux имеют древовидную структуру. Каждый процесс, за исключением нескольких корневых, имеет родительский процесс.
*   **Корневые процессы:**
    *   **`Init` / `SystemD` (PID 1):** Процесс в пространстве пользователя, который инициализируется ядром при загрузке системы. От него порождаются все остальные пользовательские процессы.
    *   **`KthreadD` (KernelThreadsD):** Процесс в пространстве ядра, отвечающий за управление потоками ядра.
*   **Жизненный цикл процесса:**
    1.  **Создание:** При выполнении внешней команды (например, `ls`) командный интерпретатор (Bash) сначала создает свою точную копию (дочерний процесс) с помощью `fork()`.
    2.  **Загрузка кода:** В этот новый дочерний процесс загружается исполняемый код внешней команды (например, `ls`).
    3.  **Выполнение:** Команда выполняется в дочернем процессе.
    4.  **Завершение:** После завершения работы команда сообщает об этом ядру, и ядро завершает дочерний процесс.
*   **Внутренние команды:** Для внутренних команд (built-ins, например, `cd`, `echo`) новый процесс не создается. Они выполняются непосредственно в текущем процессе оболочки.

### Порядок поиска и интерпретации команд

Когда вы вводите команду в Bash, оболочка следует строго определенному порядку для ее поиска и интерпретации. Понимание этого порядка критически важно для отладки и предсказуемого поведения скриптов.

1.  **Проверка алиасов (псевдонимов)**
    *   Bash сначала проверяет, не является ли введенная команда **алиасом**. Алиасы — это короткие, настраиваемые псевдонимы для более длинных команд или последовательностей команд.
    *   Если алиас найден, он заменяется на свою полную форму, и процесс интерпретации продолжается с этой новой командой.
    *   **Пример:** `ls` часто является алиасом для `ls --color=auto` или `ls -F`.
    *   Просмотреть текущие алиасы можно командой `alias`. Удалить алиас — `unalias <имя_алиаса>`.
    *   **Важно:** Алиасы действуют только в текущей сессии, если не прописаны в конфигурационных файлах (`.bashrc`, `.bash_profile`).

2.  **Проверка встроенных команд (built-ins)**
    *   Если команда не является алиасом, Bash проверяет, не является ли она **встроенной командой** (shell built-in). Это команды, которые являются частью самой оболочки Bash и не являются отдельными исполняемыми файлами на диске.
    *   **Примеры:** `cd`, `echo`, `pwd`, `type`, `export`, `source`.
    *   Встроенные команды выполняются быстрее, так как не требуют запуска нового процесса.
    *   **Определение типа команды:** Команда `type <команда>` (или `type -a <команда>`) поможет определить, является ли команда встроенной, алиасом или внешней.
        *   **Пример:** `type -a echo` может показать, что `echo` является как встроенной командой оболочки, так и внешней программой (`/usr/bin/echo`). В таких случаях Bash сначала выполнит встроенную версию.
        *   **Пример:** `type -a cd` покажет, что `cd` является встроенной командой оболочки (`cd is a shell builtin`).
        *   **Пример:** `type -a ls` может показать, что `ls` является алиасом, а затем внешней командой (`/usr/bin/ls`).

3.  **Проверка хеш-таблицы команд**
    *   Если команда не является алиасом и не является встроенной, Bash проверяет свою внутреннюю **хеш-таблицу** ранее найденных исполняемых файлов.
    *   Это оптимизация: если команда уже была найдена и выполнена ранее, Bash "помнит" ее полный путь и не тратит время на повторный поиск в `$PATH`.
    *   Просмотреть хеш-таблицу можно командой `hash`. Очистить ее — `hash -r`.
    *   **Важно:** Хеш-таблица значительно ускоряет выполнение команд, но может привести к неожиданному поведению, если исполняемый файл был перемещен, удален или заменен после того, как его путь был закеширован. В таком случае Bash может попытаться выполнить несуществующую команду или старую версию, пока хеш не будет очищен.

4.  **Поиск в переменной окружения `$PATH` (внешние команды)**
    *   Если команда не найдена на предыдущих шагах, Bash начинает поиск исполняемого файла в директориях, перечисленных в переменной окружения `$PATH`.
    *   `$PATH` — это список директорий, разделенных двоеточиями, в которых Bash ищет исполняемые файлы.
    *   **Примеры:** `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`.
    *   Поиск происходит **слева направо**. Как только первый исполняемый файл с таким именем найден, он и будет выполнен.
    *   **Формирование `$PATH`:** Переменная `$PATH` обычно формируется из нескольких источников:
        *   **Системные файлы:** Например, `/etc/profile` и файлы в `/etc/profile.d/` для всех пользователей.
        *   **Пользовательские файлы:** Например, `~/.bash_profile`, `~/.bashrc`, `~/.profile` для конкретного пользователя.
    *   **Внешние команды** — это обычные исполняемые файлы, расположенные на диске в одной из директорий, указанных в `$PATH`.
    *   **Примеры:** `ls`, `rm`, `grep`, `find`.
    *   **Важно:** Если в `$PATH` есть несколько файлов с одинаковым именем, будет выполнен тот, который находится в директории, указанной раньше в `$PATH`. Это может привести к неожиданному поведению, если, например, пользователь создал свой исполняемый файл с именем системной команды и поместил его в директорию, которая стоит раньше в `$PATH`.

5.  **Ошибка "command not found"**
    *   Если команда не найдена ни на одном из предыдущих шагов, Bash выдает ошибку `command not found`.

#### Внутренние vs. Внешние команды

*   **Внутренние команды (Built-ins):**
    *   Являются частью самой оболочки Bash.
    *   Выполняются непосредственно оболочкой, не требуют запуска нового процесса.
    *   Примеры: `cd`, `echo`, `pwd`, `type`, `export`, `source`.
    *   Всегда доступны, пока работает Bash.

*   **Внешние команды:**
    *   Являются отдельными исполняемыми файлами на диске.
    *   Bash находит их через `$PATH` (или по полному пути) и запускает как отдельные процессы.
    *   Примеры: `ls`, `rm`, `grep`, `find`, `vim`.
    *   Могут отсутствовать в системе (например, если файл удален или не установлен).

#### Нюансы работы с алиасами

*   Алиасы могут быть очень полезны для сокращения часто используемых команд или для добавления к ним стандартных опций.
*   **Создание алиаса:** `alias ll='ls -alF'`
*   **Удаление алиаса:** `unalias ll`
*   **Просмотр алиасов:** `alias`
*   **Важно:** Алиасы не являются рекурсивными. То есть, если вы создадите `alias a='ls'` и затем `alias b='a'`, то `b` не будет работать как `ls`. Алиас `a` будет заменен на `ls`, но затем `ls` не будет заменена на `ls -alF` (если `ls` сам является алиасом). Для вложенных алиасов или более сложной логики лучше использовать функции Bash.
*   **Потенциальные проблемы:** Злоумышленник может создать вредоносный алиас для системной команды (например, `alias rm='rm -rf /'`), что может привести к серьезным последствиям. Будьте осторожны с алиасами, особенно в общих системах.


### Код возврата (`$?`)

Каждая команда после своего завершения возвращает **код возврата** (exit code) — число от 0 до 255, которое сообщает о том, как она отработала. Это основа для всей логики в shell.

-   **`0`** — команда завершилась **успешно**.
-   **Любое другое число (не `0`)** — в процессе выполнения произошла **ошибка**.

Узнать код возврата последней выполненной команды можно с помощью специальной переменной `$?`.

```bash
# Выполняем успешную команду
ls /etc/hosts
# /etc/hosts

# Проверяем код возврата
echo $?
# 0

# Выполняем команду с ошибкой
ls /не/существует
# ls: cannot access '/не/существует': No such file or directory

# Проверяем код возврата
echo $?
# 2 (или другое ненулевое значение в зависимости от системы и типа ошибки)
```

**Важно:** Переменная `$?` хранит код возврата только **самой последней** команды. Сразу после `echo $?` ее значение станет `0`, так как сама команда `echo` выполнилась успешно.

Если вам нужно использовать код возврата более поздней команды, сохраните его в отдельную переменную:
```bash
ls /не/существует
LAST_EXIT_CODE=$?
echo "Код возврата предыдущей команды: $LAST_EXIT_CODE"
echo "Текущий код возврата (от echo): $?"
```

Именно на значении кода возврата (`0` или не `0`) основана работа управляющих операторов `&&` и `||`.

#### Шаг 3: Выполнение с учетом управляющих операторов (`&&`, `||`, `;`)
Эти операторы выполняются **последовательно, слева направо**, и определяют, будет ли запущена следующая команда (или конвейер).

*   **`&&` (Логическое "И")**
    *   **Логика:** `cmd1 && cmd2` -> Выполнить `cmd2` **только если** `cmd1` завершилась успешно (с кодом выхода 0).
    *   **Пример:** `mkdir backup && cp *.log backup/`
        1.  Выполняется `mkdir backup`.
        2.  Если папка успешно создана (код 0), выполняется `cp`.
        3.  Если `mkdir` выдает ошибку (например, папка уже есть), `cp` **не выполняется**.

*   **`||` (Логическое "ИЛИ")**
    *   **Логика:** `cmd1 || cmd2` -> Выполнить `cmd2` **только если** `cmd1` завершилась с ошибкой (код выхода не 0).
    *   **Пример:** `ping -c 1 google.com || echo "Хост недоступен"`
        1.  Выполняется `ping`.
        2.  Если `ping` успешен (код 0), `echo` **не выполняется**.
        3.  Если `ping` провалился (нет сети), `echo` **выполняется**.

*   **`;` (Последовательное выполнение)**
    *   **Логика:** `cmd1 ; cmd2` -> Выполнить `cmd2` **всегда**, независимо от кода возврата `cmd1`.
    *   **Пример:** `echo "Начало"; ls -l /nonexistent; echo "Конец"`
        1.  Выполнится `echo "Начало"`.
        2.  Выполнится `ls -l /nonexistent` (скорее всего, с ошибкой).
        3.  Выполнится `echo "Конец"`.

    **Однострочные скрипты:** Оператор `;` часто используется для написания однострочных скриптов, где несколько команд выполняются последовательно в одной строке.
    ```bash
    VAR="test"; echo $VAR; ls -l; echo "Готово"
    ```

**Комбинирование `&&` и `||` с `grep -q`:**
`grep` с опцией `-q` (quiet) не выводит найденные строки, а просто возвращает код выхода: `0` если совпадение найдено, `1` если нет. Это очень удобно для проверок в скриптах.

```bash
# Проверить наличие пользователя 'root' в /etc/passwd и вывести сообщение
grep -q "root" /etc/passwd && echo "Пользователь root существует." || echo "Пользователь root НЕ существует."

# Добавить строку в файл, если ее там нет
LINE="my_custom_entry"
FILE="/tmp/config.txt"
grep -q "$LINE" "$FILE" || echo "$LINE" >> "$FILE"
```

#### Группировка команд: `( ... )` и `{ ...; }`

Иногда нужно сгруппировать несколько команд, чтобы применить к ним общее действие (например, перенаправление) или контролировать их окружение.

*   **`( ... )` (Subshell / дочерняя оболочка)**
    *   **Логика:** Команды внутри круглых скобок выполняются в **новом, дочернем процессе оболочки (subshell)**.
    *   **Эффект:** Любые изменения окружения (смена каталога через `cd`, экспорт переменных) происходят только внутри этого subshell и **не влияют** на родительскую оболочку.
    *   **Пример:** `(cd /tmp && rm log.txt)`. Команда `rm` выполнится в `/tmp`, но ваш основной терминал останется в прежнем каталоге.

*   **`{ ...; }` (Grouping / группировка)**
    *   **Логика:** Команды внутри фигурных скобок выполняются в **текущей оболочке**.
    *   **Эффект:** Изменения окружения **сохраняются** после выполнения группы.
    *   **Синтаксис:** Требует пробела после `{` и точки с запятой `;` (или переноса строки) перед `}`.
    *   **Пример:** `{ cd /tmp; rm log.txt; }`. После выполнения этой группы ваш терминал будет находиться в каталоге `/tmp`.

#### Подстановка: `$()` и `<()`

*   **Подстановка команд: `$(команда)` или `` `команда` ``
    *   **Логика:** Оболочка сначала выполняет команду внутри `$(...)` (или обратных кавычек `` `...` ``), забирает её стандартный вывод (`stdout`) и подставляет его как текст в основную команду.
    *   **Пример:** `echo "Будет удалено: $(find . -name '*.tmp')"`
    *   **Примечание:** Синтаксис `$(...)` предпочтительнее, чем обратные кавычки (`` ` ``), так как он более читаем, может быть вложенным и лучше обрабатывает специальные символы. Обратные кавычки считаются устаревшим синтаксисом.

*   **Подстановка процессов: `<(команда)`**
    *   **Логика:** Это более продвинутая техника. Оболочка выполняет команду и предоставляет её вывод в виде специального временного файла. Основная команда видит этот "файл" как один из своих аргументов.
    *   **Пример:** `diff <(sort file1.txt) <(sort file2.txt)`. Вместо создания двух отсортированных файлов вручную, `diff` напрямую сравнивает выводы двух `sort`-процессов. Это эффективнее и чище.

#### Фоновые процессы: `&`

*   **Логика:** Оператор `&` в конце команды говорит оболочке запустить её в **фоновом режиме**.
*   **Эффект:** Оболочка не ждет завершения команды, а сразу возвращает вам управление (приглашение для ввода). Команда продолжает работать "сзади".
*   **Пример:** `sleep 300 &`
*   **Управление:** Командами `jobs` (посмотреть список фоновых задач), `fg` (вернуть на передний план) и `bg` (возобновить в фоне) можно управлять этими процессами.

### Расширенная таблица-шпаргалка

| Оператор | Тип | Порядок выполнения | Пример |
| :--- | :--- | :--- | :--- |
| `|` | Конвейер | **Одновременный** запуск. Данные текут слева направо. | `cat file \| grep word` |
| `&&` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая успешна. | `mkdir d && cd d` |
| `||` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая провалилась. | `ping host \|\| echo 'down'` |
| `;` | Управляющий | **Последовательный**. Вторая команда выполняется всегда. | `cmd1 ; cmd2` |
| `&` | Управляющий | Запускает команду в **фоновом режиме**. | `sleep 10 &` |
| `>` `>>` `<` | Перенаправление | **Настраивается оболочкой до запуска команды.** | `ls > file.txt` |
| `$(...)` | Подстановка | Выполняется **до** основной команды. Результат подставляется как аргумент. | `rm $(find . -name "*.tmp")` |
| `<(...)` | Подстановка | Выполняется **одновременно** с основной командой, результат виден как файл. | `diff <(sort f1) <(sort f2)` |
| `( ... )` | Группировка | Команды выполняются в **дочерней оболочке (subshell)**. | `(cd /tmp && pwd)` |
| `{ ...; }` | Группировка | Команды выполняются в **текущей оболочке**. | `{ cd /tmp; pwd; }` |


### Переменные: локальные и переменные окружения

В Bash существует два основных типа переменных, и понимание разницы между ними критически важно.

1.  **Локальные переменные (`VAR="VALUE"`)**
    -   **Область видимости:** Такая переменная доступна **только в текущем процессе оболочки**, где она была объявлена.
    -   **Наследование:** Дочерние процессы (например, скрипты или команды, запущенные из текущей оболочки) **не унаследуют** эту переменную.

    **Пример:**
    ```bash
    # Объявляем локальную переменную
    MY_VAR="local_value"

    # В текущей оболочке она доступна
    echo $MY_VAR
    # Вывод: local_value

    # Запускаем новый дочерний процесс bash и пытаемся прочитать переменную
    bash -c 'echo $MY_VAR'
    # Вывод: (пустая строка)
    ```

2.  **Переменные окружения (`export VAR="VALUE"`)**
    -   **Область видимости:** Команда `export` "продвигает" локальную переменную до переменной окружения. Она становится доступна не только в текущей оболочке, но и во **всех дочерних процессах**, которые будут из нее запущены.
    -   **Наследование:** Дочерние процессы наследуют все экспортированные переменные родительской оболочки.

    **Пример:**
    ```bash
    # Объявляем и экспортируем переменную
    export MY_EXPORTED_VAR="exported_value"

    # В текущей оболочке она доступна
    echo $MY_EXPORTED_VAR
    # Вывод: exported_value

    # Запускаем новый дочерний процесс bash
    bash -c 'echo $MY_EXPORTED_VAR'
    # Вывод: exported_value
    ```

**Ключевое правило:**
-   Используйте `VAR="VALUE"` для временных переменных, которые нужны только в текущем скрипте или сессии.
-   Используйте `export VAR="VALUE"` для переменных, которые должны быть доступны программам или скриптам, запускаемым из текущей оболочки (например, `JAVA_HOME`, `PATH`, конфигурационные параметры).

### Позиционные параметры и специальные переменные

В Bash-скриптах, помимо обычных переменных, существуют специальные переменные, которые автоматически заполняются значениями, переданными скрипту, или предоставляют информацию о его выполнении.

*   **Позиционные параметры:**
    Это аргументы, переданные скрипту при его запуске.
    *   `$0`: Имя самого скрипта, как он был вызван.
    *   `$1`, `$2`, `$3`, ...: Отдельные аргументы, переданные скрипту. `$1` — первый аргумент, `$2` — второй и так далее.

*   **Специальные переменные:**
    *   `$#`: Количество аргументов, переданных скрипту (без учета `$0`).
    *   `$*`: Все аргументы как **одна строка**, разделенные первым символом `$IFS` (по умолчанию пробелом). При использовании в двойных кавычках (`"$*"`) все аргументы объединяются в одну строку.
    *   `$@`: Все аргументы как **отдельные строки**. При использовании в двойных кавычках (`"$@"`) каждый аргумент сохраняет свою индивидуальность, что идеально для итерации в циклах.
    *   `$?`: Код возврата (exit code) последней выполненной команды. (Подробнее см. в разделе "Код возврата (`$?`)").
    *   `$$`: PID (идентификатор процесса) текущей оболочки или скрипта.
    *   `$!`: PID последнего запущенного фонового процесса.
    *   `$-`: Текущие опции оболочки.

    **Примечание:** При итерации по `$*` или `$@` без кавычек, Bash выполняет разбиение по словам (word splitting) и расширение глобов (pathname expansion), что может привести к неожиданным результатам, если аргументы содержат пробелы или специальные символы. Всегда используйте `"$@"` для безопасной обработки аргументов в циклах.

## Кавычки: одинарные vs двойные

### 1. Одинарные кавычки (`'`) 

Всё, что заключено в одинарные кавычки, интерпретируется **буквально**. Специальные символы, такие как `$`, `\`, ``` ` ```, не обрабатываются.

```sh
 echo 'Переменная $HOME не будет раскрыта'
```
Вывод:
```text
Переменная $HOME не будет раскрыта
```

### 2. Двойные кавычки (`"`) 

Двойные кавычки позволяют оболочке **интерпретировать** специальные символы. Это называется подстановкой (interpolation).

-   Переменные (`$VAR`) заменяются их значениями.
-   Конструкции `` `команда` `` или `$(команда)` заменяются результатом выполнения команды.

```sh
 echo "Ваш домашний каталог: $HOME"
```
Вывод:
```text
Ваш домашний каталог: /home/username
```

## Управляющие конструкции (Control Structures)

Bash, как Тьюринг-полный язык, предоставляет стандартные управляющие конструкции для создания логики в скриптах.

### Условные операторы: `if`, `else`, `elif`

Условные операторы позволяют выполнять блоки кода в зависимости от истинности или ложности некоторого условия.

*   **Синтаксис `if/else`:**
    ```bash
    if условие; then
        # Команды, если условие истинно
    else
        # Команды, если условие ложно
    fi
    ```

*   **Синтаксис `if/elif/else`:**
    ```bash
    if условие1; then
        # Команды, если условие1 истинно
    elif условие2; then
        # Команды, если условие2 истинно
    else
        # Команды, если ни одно из условий не истинно
    fi
    ```

*   **Проверка условий:**
    Условия в `if` могут быть выражены несколькими способами:
    1.  **Команда `test` или `[ ]` (одинарные квадратные скобки):**
        `test` — это внешняя команда, которая проверяет условия. `[ ]` — это алиас для `test`. Подробную информацию можно получить, выполнив `man test`.
        ```bash
        if test -f "myfile.txt"; then
            echo "Файл существует."
        fi

        # Эквивалентно:
        if [ -f "myfile.txt" ]; then
            echo "Файл существует."
        fi
        ```
        Основные операторы `test`:
        *   `-f FILE`: FILE существует и является обычным файлом.
        *   `-d FILE`: FILE существует и является директорией.
        *   `-e FILE`: FILE существует.
        *   `-z STRING`: Длина STRING равна нулю.
        *   `-n STRING`: Длина STRING не равна нулю.
        *   `STRING1 = STRING2`: STRING1 и STRING2 равны.
        *   `STRING1 != STRING2`: STRING1 и STRING2 не равны.
        *   `INT1 -eq INT2`: INT1 равно INT2.
        *   `INT1 -ne INT2`: INT1 не равно INT2.
        *   `INT1 -gt INT2`: INT1 больше INT2.
        *   `INT1 -ge INT2`: INT1 больше или равно INT2.
        *   `INT1 -lt INT2`: INT1 меньше INT2.
        *   `INT1 -le INT2`: INT1 меньше или равно INT2.

        **Пример проверки прав root:**
        ```bash
        if [ "$(id -u)" -ne 0 ]; then
            echo "Для выполнения этого скрипта требуются права root."
            exit 1
        fi
        ```

    2.  **`[[ ]]` (двойные квадратные скобки):**
        Это расширенная версия `test`, встроенная в Bash. Она более мощная и гибкая, поддерживает регулярные выражения, логические операторы (`&&`, `||`) и не требует экранирования некоторых символов.
        ```bash
        if [[ -f "myfile.txt" && -r "myfile.txt" ]]; then
            echo "Файл существует и доступен для чтения."
        fi

        if [[ "hello" == "hello" ]]; then
            echo "Строки равны."
        fi

        if [[ "version" =~ ^v[0-9]+\.[0-9]+$ ]]; then
            echo "Строка соответствует шаблону версии."
        fi
        ```

### Оператор `case`

Оператор `case` предоставляет удобный способ для выполнения различных блоков кода в зависимости от значения переменной или выражения. Он часто используется как более читабельная альтернатива длинным цепочкам `if/elif/else` при сравнении одной переменной с несколькими возможными значениями.

*   **Синтаксис `case`:**
    ```bash
    case "$переменная" in
        "шаблон1")
            # Команды, если переменная соответствует шаблон1
            ;;
        "шаблон2" | "шаблон3")
            # Команды, если переменная соответствует шаблон2 или шаблон3
            ;;
        *)
            # Команды, если переменная не соответствует ни одному из предыдущих шаблонов (по умолчанию)
            ;;
    esac
    ```
    Каждый блок `case` должен заканчиваться двойной точкой с запятой `;;`. `esac` закрывает конструкцию `case`.

*   **Пример использования `case`:**
    ```bash
    read -p "Введите 'start', 'stop' или 'status': " ACTION

    case "$ACTION" in
        "start")
            echo "Запускаем сервис..."
            ;;
        "stop")
            echo "Останавливаем сервис..."
            ;;
        "status")
            echo "Проверяем статус сервиса..."
            ;;
        *)
            echo "Неизвестная команда: $ACTION. Используйте 'start', 'stop' или 'status'."
            ;;
    esac
    ```

### Циклы: `for`, `while`

Циклы позволяют многократно выполнять блок команд.

*   **Цикл `for`:**
    Используется для итерации по списку элементов.
    ```bash
    # Итерация по списку строк
    for item in apple banana cherry; do
        echo "Фрукт: $item"
    done

    # Итерация по файлам
    for file in *.txt; do
        echo "Обработка файла: $file"
    done

    # Классический C-подобный цикл for
    for (( i=0; i<5; i++ )); do
        echo "Число: $i"
    done
    ```

*   **Цикл `while`:**
    Выполняет блок команд до тех пор, пока условие истинно.
    ```bash
    count=0
    while [ $count -lt 5 ]; do
        echo "Счетчик: $count"
        count=$((count + 1))
    done

    # Бесконечный цикл (выход по break или Ctrl+C)
    while true; do
        read -p "Введите что-нибудь (или 'exit' для выхода): " input
        if [[ "$input" == "exit" ]]; then
            break
        fi
        echo "Вы ввели: $input"
    done
    ```

    ```bash
            ;;
        *)
            # Команды, если переменная не соответствует ни одному из предыдущих шаблонов (по умолчанию)
            ;;
    esac
    ```
    Каждый блок `case` должен заканчиваться двойной точкой с запятой `;;`. `esac` закрывает конструкцию `case`.

*   **Пример использования `case`:**
    ```bash
    read -p "Введите 'start', 'stop' или 'status': " ACTION

    case "$ACTION" in
        "start")
            echo "Запускаем сервис..."
            ;;
        "stop")
            echo "Останавливаем сервис..."
            ;;
        "status")
            echo "Проверяем статус сервиса..."
            ;;
        *)
            echo "Неизвестная команда: $ACTION. Используйте 'start', 'stop' или 'status'."
            ;;
    esac
    ```

### Циклы: `for`, `while`

Циклы позволяют многократно выполнять блок команд.

*   **Цикл `for`:**
    Используется для итерации по списку элементов.
    ```bash
    # Итерация по списку строк
    for item in apple banana cherry; do
        echo "Фрукт: $item"
    done

    # Итерация по файлам
    for file in *.txt; do
        echo "Обработка файла: $file"
    done

    # Классический C-подобный цикл for
    for (( i=0; i<5; i++ )); do
        echo "Число: $i"
    done
    ```

*   **Цикл `while`:**
    Выполняет блок команд до тех пор, пока условие истинно.
    ```bash
    count=0
    while [ $count -lt 5 ]; do
        echo "Счетчик: $count"
        count=$((count + 1))
    done

    # Бесконечный цикл (выход по break или Ctrl+C)
    while true; do
        read -p "Введите что-нибудь (или 'exit' для выхода): " input
        if [[ "$input" == "exit" ]]; then
            break
        fi
        echo "Вы ввели: $input"
    done
    ```

### Выполнение скриптов: source vs. subshell

Помимо объявления переменных, способ запуска скрипта также влияет на окружение.

1.  **Запуск в дочерней оболочке (`./script.sh`)**
    -   **Механизм:** Когда вы делаете скрипт исполняемым (`chmod +x script.sh`) и запускаете его (`./script.sh`), оболочка создает **новый дочерний процесс (subshell)**, в котором и выполняются команды из скрипта.
    -   **Эффект:** Все изменения окружения (объявленные переменные, `cd`) остаются внутри этого дочернего процесса и **исчезают** после его завершения. Родительская оболочка остается неизменной. Это безопасный способ запуска, который не загрязняет текущее окружение.

2.  **Выполнение в текущей оболочке (`source script.sh` или `. script.sh`)**
    -   **Механизм:** Команда `source` (или ее короткий псевдоним `.`) выполняет команды из скрипта **в контексте текущей оболочки**, как если бы вы вводили их вручную. Новый процесс не создается.
    -   **Эффект:** Все изменения окружения, сделанные в скрипте (экспорт переменных, `cd`), **сохраняются** в вашей текущей сессии после завершения скрипта.
    -   **Основное применение:** Этот метод используется для загрузки конфигурационных файлов, файлов с переменными окружения (`source .env`) или для активации виртуальных окружений (например, `source venv/bin/activate` в Python).

**Наглядный пример:**

Допустим, `my_script.sh` содержит:
```bash
#!/bin/bash
MY_VAR="hello"
cd /tmp
```

Теперь сравним два способа запуска:

```bash
# 1. Запуск в subshell
$ pwd
/home/user
$ ./my_script.sh
$ echo $MY_VAR
# Вывод: (пустая строка)
$ pwd
/home/user
# Ничего не изменилось

# 2. Выполнение через source
$ pwd
/home/user
$ source ./my_script.sh
$ echo $MY_VAR
# Вывод: hello
$ pwd
/tmp
# Окружение изменилось!
```

### Влияние конвейеров (`|`) на область видимости переменных (Subshell)

Одной из частых причин ошибок в Bash-скриптах является недопонимание того, как конвейеры (`|`) влияют на область видимости переменных.

*   **Механизм:** Каждая команда в конвейере (`command1 | command2 | command3`) выполняется в **отдельном дочернем процессе (subshell)**. Это означает, что любые изменения переменных, сделанные внутри одной из команд конвейера, **не будут видны в родительской оболочке** или в последующих командах, выполняющихся вне этого конвейера.


*   **Как обойти проблему:**
    1.  **Использование временного файла:** Записать вывод первой команды во временный файл, а затем обработать его в основном скрипте.

    2.  **Перенаправление ввода из файла/here-string:** Если источник данных не является конвейером, можно перенаправить его ввод в цикл `while` без создания subshell.

    3.  **Использование `lastpipe` (Bash 4.2+):** Если последняя команда в конвейере является встроенной командой Bash (например, `read`, `while`), и опция `lastpipe` включена (`shopt -s lastpipe`), то эта команда будет выполняться в текущей оболочке, а не в subshell.

        **Примечание:** `lastpipe` работает только если скрипт не запущен в subshell (например, не является частью другого конвейера или не запущен в `(...)`).

## Bash-скрипты: Основы написания

**Bash-скрипт** — это обычный текстовый файл, содержащий последовательность команд для командного интерпретатора.

### Интерпретируемые и компилируемые языки

Важно понимать, что языки программирования делятся на интерпретируемые и компилируемые. Bash является **интерпретируемым** языком.

*   **Интерпретируемые языки:** Код выполняется построчно интерпретатором. Интерпретатор читает первую команду, переводит ее в машинный код и тут же выполняет, затем переходит ко второй команде и так далее, сверху вниз, до конца скрипта. Примеры: Bash, Python, JavaScript.
*   **Компилируемые языки:** Весь код сначала переводится в машинный код (компилируется) с помощью компилятора, а затем уже выполняется готовый исполняемый файл. Примеры: C, C++, Go.

Это различие влияет на процесс выполнения скриптов и обработку ошибок.

### Создание и запуск скрипта

1.  **Создайте файл:** `touch my_script.sh`
2.  **Добавьте команды:** Откройте файл в текстовом редакторе и добавьте команды, например:
    ```bash
    echo "Привет, мир!"
    ls -l
    ```
3.  **Запуск с указанием интерпретатора:** Вы можете запустить скрипт, передав его в качестве аргумента `bash`:
    ```bash
    bash my_script.sh
    ```

### Shabang (`#!`) и исполняемый файл

Чтобы запускать скрипт напрямую (как `./my_script.sh`), необходимо сделать две вещи:

1.  **Установить права на исполнение:**
    ```bash
    chmod +x my_script.sh
    ```

2.  **Указать интерпретатор с помощью "shabang":**
    **Shabang** — это специальная конструкция `#!` в самой первой строке файла, которая указывает операционной системе, какой интерпретатор использовать для выполнения этого скрипта.

    -   **`#!/bin/bash`** — самая распространенная форма. Она жестко указывает путь к `bash`.
    -   **`#!/usr/bin/env bash`** — более гибкая и предпочтительная форма. Она использует утилиту `env` для поиска `bash` в каталогах, перечисленных в переменной окружения `$PATH`. Это делает скрипт более переносимым между системами, где `bash` может находиться в другом месте (например, `/usr/local/bin/bash`).

    **Пример файла `my_script.sh` с shabang:**
    ```bash
    #!/usr/bin/env bash

    echo "Этот скрипт выполняется с помощью bash!"
    ```

    Теперь его можно запустить напрямую:
    ```bash
    ./my_script.sh
    ```

Если у вас есть права root, вы можете перенести скрипт в `/usr/local/bin`, чтобы сделать его доступным для всех пользователей системы без указания полного пути.

**Важно: Интерпретация Shabang**
    Понимание того, как `shabang` обрабатывается, критически важно:

    *   **Когда скрипт запускается как исполняемый файл (`./my_script.sh`):**
        Операционная система (точнее, ее загрузчик исполняемых файлов) анализирует первые два байта файла. Если она видит `#!`, то она запускает программу, указанную после `#!`, и передает ей путь к вашему скрипту в качестве первого аргумента.
        Например, для `#!/bin/bash` и запуска `./my_script.sh` система фактически выполняет `execve("/bin/bash", {"/bin/bash", "./my_script.sh"}, envp)`.
        Таким образом, `shabang` — это инструкция для **операционной системы**, а не для самой командной оболочки.

    *   **Когда скрипт запускается с явным указанием интерпретатора (`bash my_script.sh`):**
        В этом случае `shabang` полностью игнорируется. Командная оболочка `bash` (или любая другая, которую вы указали) читает файл `my_script.sh` как обычный текстовый файл. Строка `#!` воспринимается ею как комментарий (поскольку начинается с `#`).
        Это означает, что скрипт будет выполнен именно той оболочкой, которую вы указали в командной строке, независимо от того, что написано в `shabang`.

    Это различие объясняет, почему скрипт может вести себя по-разному в зависимости от способа его запуска. Например, если в `shabang` указан `#!/bin/bash`, но вы запускаете его как `sh my_script.sh`, то скрипт будет выполнен оболочкой `sh`, а не `bash`.

## Поиск по содержимому файлов: grep

Одной из самых мощных возможностей командной строки Linux является поиск текста внутри файлов. Основным инструментом для этой задачи является утилита **`grep`** (Global Regular Expression Print).

`grep` сканирует содержимое файлов на наличие строк, соответствующих заданному шаблону (обычному тексту или регулярному выражению), и выводит найденные строки.

### Базовое использование

```bash
# Найти слово "error" в файле "app.log"
grep "error" app.log
```

### Поиск в нескольких файлах и директориях

-   **Рекурсивный поиск (`-r` или `-R`):**
    Искать текст во всех файлах внутри директории и ее поддиректорий.
    ```bash
    # Найти "database connection failed" во всех файлах в /var/log/
    grep -r "database connection failed" /var/log/
    ```

-   **Поиск без учета регистра (`-i`):**
    ```bash
    grep -ri "database" /var/log/
    ```

-   **Показать только имена файлов (`-l`):**
    Вывести список файлов, в которых найдено совпадение, без самих строк.
    ```bash
    grep -rl "database" /etc/
    ```

-   **Показать номера строк (`-n`):**
    ```bash
    grep -n "main" my_script.py
    ```

-   **Инвертировать поиск (`-v`):**
    Найти все строки, которые **не** содержат шаблон.
    ```bash
    # Показать все строки в логе, кроме отладочных сообщений
    grep -v "DEBUG" app.log
    ```

### Комбинация `find` и `grep`

Для более сложного поиска (например, по файлам с определенным расширением) `grep` часто используется в связке с командой `find`.

```bash
# Найти текст "TODO" во всех файлах с расширением .py в текущей директории
find . -name "*.py" -exec grep -Hn "TODO" {} +
```
-   `find . -name "*.py"`: Находит все файлы, заканчивающиеся на `.py`.
-   `-exec ... {} +`: Выполняет команду `grep` для найденных файлов.
    -   `-H`: Показывает имя файла (нужно, так как `grep` получает файлы по одному).
    -   `{}`: Подставляет имя найденного файла.
    -   `+`: Выполняет `grep` для группы файлов за раз, что эффективнее, чем `\;`.

## Примеры использования команд и конвейеров

### Базовые команды и их аргументы

В Linux команды обычно имеют формат: `команда [ключи] [аргументы]`.
*   **Команда:** Что делать (например, `ls`).
*   **Ключи (опции):** Как делать (например, `-l` для `ls` — длинный формат вывода).
*   **Аргументы:** Над чем делать (например, `/etc` для `ls` — показать содержимое каталога `/etc`).

**Примеры:**
*   `ls`: Вывести содержимое текущего каталога.
*   `ls -l`: Вывести содержимое текущего каталога в длинном формате.
*   `ls -l /etc`: Вывести содержимое каталога `/etc` в длинном формате.
*   `cd`: (Change Directory) Изменить текущий каталог. Без аргументов возвращает в домашний каталог пользователя.
*   `pwd`: (Print Working Directory) Вывести текущий рабочий каталог.
*   `echo <текст>`: Вывести текст на стандартный вывод. Используется для вывода значений переменных (например, `echo $PATH`).

### Определение типа команды (`type`)

Команда `type` позволяет определить, является ли команда алиасом, встроенной командой или внешним исполняемым файлом.

```bash
type cd         # cd is a shell builtin
type ls         # ls is aliased to `ls --color=auto'
type -a ls      # ls is aliased to `ls --color=auto'
                # ls is /usr/bin/ls
```

### Управление хеш-таблицей команд (`hash`)

Bash кэширует пути к внешним командам для ускорения их поиска. Команда `hash` позволяет управлять этим кэшем.

*   `hash`: Показать содержимое хеш-таблицы.
*   `hash -r`: Очистить хеш-таблицу.

**Пример проблемы с хешированием:**
Если создать исполняемый файл с именем системной команды (например, `ls`) в директории, которая находится раньше в `$PATH`, чем оригинальная команда, и Bash уже закешировал путь к оригинальной команде, то будет выполняться оригинальная. После очистки хеша (`hash -r`) будет найдена и выполнена новая команда.



### Конвейеры (`|`)

Конвейеры позволяют передавать стандартный вывод одной команды на стандартный ввод другой.

**Пример:** Посчитать количество строк в выводе `ls -l`.
```bash
ls -l | wc -l
```
Здесь `stdout` команды `ls -l` передается на `stdin` команды `wc -l` (word count, опция `-l` для подсчета строк).

**Пример:** Найти уникальные права доступа к файлам в текущем каталоге.
```bash
ls -l | grep -v '^total' | cut -c 2-10 | sort | uniq -c
```
**Разбор:**
1.  `ls -l`: Выводит список файлов в длинном формате.
2.  `grep -v '^total'`: Удаляет строку, начинающуюся со слова "total" (которая не является файлом).
3.  `cut -c 2-10`: Вырезает символы со 2-го по 10-й, что соответствует столбцу прав доступа.
4.  `sort`: Сортирует полученные строки.
5.  `uniq -c`: Подсчитывает количество уникальных строк (уникальных наборов прав).

**Пример:** Получить полную информацию о каждом пользователе из `/etc/passwd`.
```bash
awk -F: '{print $1}' /etc/passwd | while read user; do id "$user"; done
```
**Разбор:**
1.  `awk -F: '{print $1}' /etc/passwd`: Использует `awk` для извлечения первого поля (имени пользователя) из файла `/etc/passwd`, используя `:` как разделитель полей.
2.  `while read user; do id "$user"; done`: Цикл `while` читает каждое имя пользователя и передает его команде `id`, которая выводит подробную информацию о пользователе.

### Дублирование вывода с `tee`

Команда `tee` позволяет одновременно выводить данные на экран и записывать их в файл.

```bash
ls -l | tee output.txt # Выведет на экран и запишет в output.txt
ls -l | tee -a output.txt # Выведет на экран и добавит в output.txt
```


## Инструменты и Утилиты

### Vim

-   **Нормальный режим (Normal Mode):** Основной режим для навигации и манипуляций текстом. Включается по умолчанию или по нажатию `Esc` / `Ctrl + c` / `Ctrl + [`.
-   **Режим вставки (Insert Mode):** Режим для набора текста. Включается командами `i`, `a`, `o` и др.
-   **Визуальный режим (Visual Mode):** Режим для выделения текста. Включается `v` (символьное), `V` (построчное), `Ctrl+v` (блочное).
-   **Командный режим (Command-Line Mode):** Режим для выполнения команд, начинающихся с `: `.

-   `h`, `j`, `k`, `l`: Перемещение влево, вниз, вверх, вправо.
-   `w`: Переместиться на начало следующего слова.
-   `b`: Переместиться на начало предыдущего слова.
-   `e`: Переместиться в конец текущего слова.
-   `gg`: В начало файла.
-   `G`: В конец файла.
-   `<N>G` или `:<N>`: Переместиться на строку с номером `N` (например, `20G`).
-   `^`: В начало строки (на первый непустой символ).
-   `0`: В самое начало строки (на первый символ).
-   `$`: В конец строки.
-   `H`, `M`, `L`: Переместиться на верх, середину, низ экрана.

-   `i`: Перейти в режим вставки **перед** курсором.
-   `a`: Перейти в режим вставки **после** курсором.
-   `o`: Вставить новую строку **ниже** текущей и перейти в режим вставки.
-   `O`: Вставить новую строку **выше** текущей и перейти в режим вставки.
-   `dd`: Удалить (вырезать) текущую строку.
-   `dw`: Удалить (вырезать) слово.
-   `d$`: Удалить (вырезать) от курсора до конца строки.
-   `yy`: Скопировать текущую строку.
-   `yw`: Скопировать слово.
-   `p`: Вставить **после** курсора.
-   `P`: Вставить **перед** курсором.
-   `u`: Отменить последнее действие.
-   `Ctrl + r`: Вернуть отмененное действие (redo).
-   `x`: Удалить символ под курсором.
-   `r`: Заменить один символ под курсором.
-   `cw`: Заменить слово.
-   `J`: Объединить текущую строку со следующей.


-   `v`: Включить визуальный режим (символьный).
-   `V` (Shift+v): Включить визуальный режим (построчный).
-   `Ctrl + v`: Включить визуальный режим (блочный).
-   `viw`: Выделить слово под курсором (inner word).
-   `vaw`: Выделить слово и пробел после него (a word).
-   `>`: Сдвинуть выделенный блок вправо (отступ).
-   `<`: Сдвинуть выделенный блок влево.
-   `=`: Автоматически выровнять выделенный код.


-   `/pattern`: Искать `pattern` от курсора вниз.
-   `?pattern`: Искать `pattern` от курсора вверх.
-   `n`: Найти следующее вхождение.
-   `N`: Найти предыдущее вхождение.
-   `*`: Искать слово под курсором (вперед).
-   `#`: Искать слово под курсором (назад).
-   `:%s/old/new/g`: Заменить все (`g`) вхождения `old` на `new` во всем файле (`%`).
-   `:%s/old/new/gc`: То же, но с подтверждением (`c`) каждой замены.


-   `:w`: Сохранить изменения.
-   `:q`: Выйти.
-   `:wq` или `:x`: Сохранить и выйти.
-   `:q!`: Выйти без сохранения.

### Горячие клавиши в shell

- **Ctrl + a**: переход в начало строки 
- **Ctrl + b**: переход на 1 символ назад 
- **Ctrl + c**: посылает программе SIGINT. Обычно, прерывает текущее задание 
- **Ctrl + d**: удаляет символ под курсором  
- **Ctrl + e**: переход к концу строки 
- **Ctrl + f**: переход на 1 символ вперёд 
- **Ctrl + k**: удаляет всё, до конца строки 
- **Ctrl + l**: очищает экран. Аналог команды `clear`. (csh, zsh)
- **Ctrl + r**: поиск по истории. Повторение поиска (листание результатов поиска). То есть инкрементальный поиск. 
- **Ctrl + j**: прекращает поиск и позволяет отредактировать найденную команду. Если поиск не производился, то аналогично нажатию return. 
- **Ctrl + t**: меняет символ под курсором на предыдущий. 
- **Ctrl + u**: удаляет все символы слева от курсора до начала строки. 
- **Ctrl + w**: удаляет символы слева от курсора до начала слова. 
- **Ctrl + xx**: переходит от текущей позиции курса в начало строки и обратно.
- **Ctrl + x @**: показывает возможные дополнения имени хоста (имена берутся из `/etc/hosts`)
- **Ctrl + z**: suspend'ит текущую задачу
- **Ctrl + x; Ctrl + e**: открывает `$EDITOR` для изменения введённой строки.
