# sed

> **Исторический контекст:** `sed` появился в Bell Labs в 1970-х и остаётся стандартным инструментом обработки текста в shell-скриптах и CI-пайплайнах.

## Определения

**sed** (Stream Editor) — потоковый текстовый редактор, выполняющий преобразования над текстовым потоком. В отличие от интерактивных редакторов (Vim, Nano), `sed` не открывает файл в окне: он считывает входные данные строку за строкой, применяет к каждой строке заданные правила преобразований и выводит результат в `stdout` или записывает его в файл.

- **Потоковый режим (Stream mode)**: `sed` работает как конвейерный фильтр — принимает данные из `stdin` или файла, обрабатывает их и отправляет в `stdout`.
- **In-place editing (режим на месте)**: модификация файлов напрямую без ручного копирования через перенаправление.
- **Pattern space**: внутренний буфер `sed`, в котором хранится текущая обрабатываемая строка.
- **BRE-движок**: `sed` использует синтаксис базовых регулярных выражений (BRE) по умолчанию, что требует экранирования метасимволов `()`, `{}`, `|`, `+`.
- **ERE-режим**: флаг `-E` включает расширенный синтаксис (ERE), где метасимволы работают без экранирования. Подробнее о диалектах — в [Регулярные выражения](./regular_expressions.md).

## Базовые концепции

### Принцип работы

1. `sed` считывает входной поток (файл или `stdin`) **последовательно, строку за строкой**.
2. Для каждой строки формируется **рабочий буфер (pattern space)**.
3. К буферу применяются команды в порядке их следования в скрипте.
4. После обработки строка выводится в `stdout` (если не подавлена командами).

По умолчанию `sed` не изменяет исходный файл — результат попадает на экран. Для записи изменений в файл требуется либо перенаправление `>`, либо флаг `-i`.

### Команда substitute (`s`)

Основная команда для замены текста. Синтаксис:

```bash
s/шаблон_поиска/строка_замены/[флаги]
```

> **Экзаменационная ловушка (LPIC-1):** В вопросах экзамена операция замены обозначается **строго буквой `s`** (от *substitute*). Буква `d` отвечает за удаление строк (delete), `p` — за принудительный вывод (print). Флаг `g` (global) является модификатором и ставится **в самом конце** выражения, перед закрывающей кавычкой.

**Важные нюансы:**
- Разделитель `/` можно заменять на любой символ (`.`, `|`, `:`), если шаблон содержит много слэшей (например, путей к файлам).
- По умолчанию заменяется **только первое** совпадение в строке.
- Флаг `g` (global) заменяет **все** совпадения в строке.
- Флаг `i` (case-insensitive) игнорирует регистр при сопоставлении.
- Флаг `p` (print) принудительно выводит строку (используется совместно с `-n`).

```bash
# Замена первого совпадения
echo "foo bar foo" | sed 's/foo/baz/'
# → baz bar foo

# Замена всех совпадений в строке
echo "foo bar foo" | sed 's/foo/baz/g'
# → baz bar baz

# Игнорирование регистра
echo "Foo bar FOO" | sed 's/foo/baz/gi'
# → baz bar baz

# Альтернативный разделитель (для путей)
sed 's|/usr/local/bin|/opt/app/bin|g' script.sh
```

### Флаг `-i` (in-place editing)

Для записи изменений напрямую в файл используется флаг `-i` (сокращение от `in-place`). Без этого флага `sed` работает в безопасном режиме: изменения выводятся в `stdout`, а файл остается нетронутым.

```bash
# Базовый in-place editing (GNU sed)
sed -i 's/параметр_старый/параметр_новый/' файл.conf

# Создание резервной копии с расширением .bak
sed -i.bak 's/параметр_старый/параметр_новый/' файл.conf
# → создаст файл.conf.bak с оригиналом и изменит файл.conf
```

Успешное выполнение `sed -i` не производит вывод в терминал. Если команда отработала без ошибок — экран остаётся чистым. Это нормальное поведение, а не признак зависания.

> **Важно:** Регистр флага имеет значение. За замену на месте отвечает **строго строчный** `-i`. Заглавный `-I` в некоторых дистрибутивах имеет совершенно иное назначение и не обеспечивает in-place editing.

### Другие команды

| Команда | Назначение | Пример |
| :--- | :--- | :--- |
| `s` | Замена (substitute) | `s/old/new/g` |
| `d` | Удаление строки (delete) | `/error/d` |
| `p` | Принудительный вывод (print) | `-n '/error/p'` |
| `a` | Добавление строки после текущей (append) | `3a\новая_строка` |
| `i` | Добавление строки перед текущей (insert) | `3i\новая_строка` |
| `c` | Замена всей строки (change) | `3c\новый_текст` |
| `y` | Транслитерация символов (трансформация) | `y/abc/ABC/` |
| `N` | Добавить следующую строку в pattern space (многострочный режим) | `N; s/\n/ /` |
| `H` | Добавить текущую строку в hold space | `H` |
| `h` | Заменить hold space текущей строкой | `h` |
| `G` | Добавить hold space в конец pattern space | `G` |
| `g` | Заменить pattern space содержимым hold space | `g` |
| `x` | Поменять местами pattern space и hold space | `x` |
| `r` | Вставить содержимое файла после текущей строки | `3r include.txt` |
| `w` | Записать текущую строку в файл (если совпала) | `/error/w errors.log` |
| `b` | Безусловный переход к метке | `:loop; d; b loop` |
| `t` | Условный переход (если была успешная замена) | `s/old/new/; t replace` |
| `=` | Вывести номер текущей строки | `/error/=` |
| `q` | Завершить обработку после текущей строки | `10q` |
| `:` | Определение метки для переходов | `:label` |

### Адресация

Команды можно применять не ко всему файлу, а к конкретным строкам или диапазону:

```bash
# Только ко второй строке
sed '2s/foo/bar/' file.txt

# К строкам 5-10
sed '5,10s/foo/bar/' file.txt

# К строкам, содержащим "error"
sed '/error/s/foo/bar/' file.txt

# К последней строке
sed '$s/foo/bar/' file.txt
```

### Флаг `-n` (suppress automatic printing)

Подавляет автоматический вывод обработанных строк. Используется вместе с `p` для точечного извлечения:

```bash
# Вывести только строки, содержащие "error" (аналог grep)
sed -n '/error/p' /var/log/syslog

# Вывести строки 5-10
sed -n '5,10p' large_file.txt
```

### Hold space и многострочная обработка

По умолчанию `sed` работает с одной строкой за раз (pattern space). Команды `N`, `H`, `h`, `G`, `g`, `x` позволяют работать с несколькими строками одновременно и использовать вспомогательный буфер (hold space).

```bash
# Объединить две строки через пробел (удалить символ новой строки между ними)
sed 'N; s/\n/ /' file.txt

# Найти строку "START" и вывести её вместе со следующей (многострочный блок)
sed -n '/START/{N; p}' file.txt

# Поменять местами две соседние строки
sed 'N; s/\(.*\)\n\(.*\)/\2\n\1/' file.txt

# Добавить строку из hold space в конец pattern space
sed 'H; $!d; x; s/^\n//' file.txt
```

**Применение в Sysadmin:**
- Объединение многострочных записей в конфигах (например, `keepalived` или `haproxy`).
- Извлечение блоков текста между маркерами (аналог `sed -n '/START/,/END/p'` с дополнительной логикой).
- Формирование отчётов из разрозненных строк логов.

### Ветвление и циклы

Команды `b` (branch) и `t` (test) реализуют условную и безусловную логику внутри sed-скрипта.

```bash
# Безусловный переход: пропустить обработку для строк, начинающихся с #
sed '/^#/b skip; s/foo/bar/g; :skip' config.conf

# Условный переход: заменить только если найдено совпадение
sed 's/old/new/; t replace; s/fallback/new/; :replace' file.txt

# Цикл: удалить все пустые строки и строки из пробелов (эквивалент grep -v)
sed ':a; /^[[:space:]]*$/d; N; s/\n/ /; ta' file.txt
```

### Чтение и запись файлов

Команды `r` (read) и `w` (write) позволяют включать содержимое внешних файлов и записывать результаты в отдельные файлы.

```bash
# Вставить содержимое header.txt после каждой строки с "## Section"
sed '/## Section/r header.txt' document.md

# Записать все строки, содержащие "error", в отдельный лог
sed -n '/error/w errors.log' /var/log/syslog

# Создать резервной копии строк перед удалением
sed -n '/deprecated/{p; w deprecated_backup.txt}; d' config.yml
```

### Дополнительные команды адресации

```bash
# Первая и последняя строка
sed '1s/foo/bar/' file.txt
sed '$s/foo/bar/' file.txt

# Диапазон от совпадения до конца файла
sed '/error/, $ s/old/new/g' file.txt

# Шаговое применение: заменить только в чётных строках
sed '2~2s/foo/bar/' file.txt

# Шаговое удаление: удалить каждую 3-ю строку
sed '3~3d' file.txt
```

> **Примечание:** Шаговое адресирование (`first~step`) доступно в GNU sed 4.2+ и BSD/macOS sed. В минимальных контейнерах (Alpine, Ubuntu 18.04) может отсутствовать.

### Различия GNU sed и BSD/macOS sed

Это критически важно при написании переносимых скриптов:

| Особенность | GNU sed (Linux) | BSD sed (macOS) |
| :--- | :--- | :--- |
| `-i` без аргумента | Работает (`-i` = edit in-place без бэкапа) | **Требует** аргумент (`-i ''` = без бэкапа, `-i .bak` = с бэкапом) |
| `-i` с расширением | `-i.bak` | `-i .bak` (пробел обязателен) или `-i.bak` |
| `\t` в замене | Интерпретируется как табуляция | Интерпретируется как литерал `\t` |

```bash
# macOS: edit in-place без бэкапа
sed -i '' 's/foo/bar/' file.txt

# macOS: edit in-place с бэкапом .bak
sed -i .bak 's/foo/bar/' file.txt

# Linux: edit in-place без бэкапа
sed -i 's/foo/bar/' file.txt

# Linux: edit in-place с бэкапом .bak
sed -i.bak 's/foo/bar/' file.txt
```

## Практические сценарии

### Базовый конвейер (pipe)

```bash
# Фильтрация и замена в выводе другой команды
echo "hello user" | sed 's/user/admin/'
# → hello admin

# Обработка вывода journalctl
journalctl -u nginx | sed 's/error/CRITICAL/g'
```

### Пакетное изменение конфигурационных файлов

```bash
# Изменение порта в конфиге (in-place)
sed -i 's/8080/9090/' /etc/nginx/nginx.conf

# С резервной копией
sed -i.bak 's/listen 80/listen 8080/' /etc/nginx/nginx.conf
# → /etc/nginx/nginx.conf.bak сохранен
```

### Удаление строк

Команда `d` (delete) полностью удаляет из потока строки, соответствующие указанному шаблону. В отличие от замены через `s`, команда `d` не оставляет в выходе даже пустых строк — совпадение выбрасывается целиком.

```bash
# Удалить все пустые строки
sed '/^$/d' file.txt

# Удалить строки 1-10
sed '1,10d' file.txt

# Удалить строки, содержащие "deprecated"
sed '/deprecated/d' config.yml

# Удалить строки, начинающиеся с комментария #
sed '/^#/d' config.ini
```

#### Регистр команды: `d` против `D`

В `sed` регистр имеет значение:

- **`d` (строчная)** — удаляет **всю строку** целиком из потока. Это стандартное поведение для большинства задач очистки.
- **`D` (заглавная)** — работает в многострочном режиме (требует включения флага `-N` или использования команды `N` для объединения строк). Удаляет текст только **до первого символа новой строки**, оставляя остаток многострочного буфера для дальнейшей обработки.

Для стандартной очистки конфигурационных файлов от комментариев используется **строго строчная** `d`.

#### Практический сценарий: зачистка конфига

```bash
# Просмотр: показать только рабочие параметры, убрав все комментарии
sed '/^#/d' nginx.conf

# Фиксация результата в файле (in-place editing)
sed -i '/^#/d' nginx.conf
```

Якорь `^` привязывает шаблон к самому началу строки, поэтому команда удаляет только строки, где `#` является первым символом (комментарии), а не вхождения `#` внутри значений параметров.

> **Важно (ловушка LPIC-1):** Без якоря `^` команда `sed '/#/d'` удаляет **все** строки, содержащие символ `#` где угодно — включая рабочие параметры с инлайн-комментарием в конце строки (например, `port 8080 # основной порт`). Для безопасной зачистки всегда используйте строго привязанный к началу строки шаблон `sed '/^#/d'`.

```bash
# ОПАСНО: сотрёт и строку параметра с пояснением в конце
sed '/#/d' config.conf

# БЕЗОПАСНО: удаляет только строки-комментарии (начинаются с #)
sed '/^#/d' config.conf
```

Удаление пустых строк и строк, состоящих только из пробелов, вместе с комментариями:

```bash
# Удалить пустые строки, строки из пробелов и строки с комментариями (ERE)
sed -E '/^\s*(#|$)/d' /etc/nginx/nginx.conf
```

### Принудительный вывод (print)

```bash
# Вывести только строки с "error" (аналог grep)
sed -n '/error/p' /var/log/syslog

# Вывести строки 5-10
sed -n '5,10p' large_file.txt
```

### Замена разделителей

Если шаблон или замена содержат `/` (например, пути), используйте другой разделитель:

```bash
# Замена пути к файлу
sed 's|/usr/local/bin|/opt/app/bin|g' script.sh

# Замена URL
sed 's|http://|https://|g' nginx.conf
```

### Расширенные возможности substitute

#### Группы захвата и обратные ссылки

В GNU `sed` поддерживаются группы захвата `\(...\)` в BRE и `(...)` в ERE, а также обратные ссылки `\1`–`\9` в строке замены.

```bash
# BRE: поменять местами два слова
echo "foo bar" | sed 's/\(.*\) \(.*\)/\2 \1/'
# → bar foo

# ERE: извлечение IP из строки лога
echo '2024-01-01 192.168.1.1 - -' | sed -E 's/.* ([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+) .*/\1/'
# → 192.168.1.1
```

> **Важно:** Обратные ссылки работают только в части замены (`s///`), а не в шаблоне поиска. В ERE-режиме (`-E`) для захвата используются обычные скобки `(...)`, обратная ссылка остаётся `\1`.

#### Регистровые преобразования (GNU sed)

GNU `sed` поддерживает модификаторы регистра в строке замены:

```bash
# \L — нижний регистр до \E
echo "FOO BAR" | sed 's/.*/\L&/'
# → foo bar

# \U — верхний регистр до \E
echo "foo bar" | sed 's/.*/\U&/'
# → FOO BAR

# \l — нижний регистр только первого символа
echo "FOO" | sed 's/.*/\l&/'
# → fOO

# \u — верхний регистр только первого символа
echo "foo" | sed 's/.*/\u&/'
# → Foo

# \E — сброс регистрового преобразования
echo "foo BAR" | sed 's/.*/\u\L&\E/'
# → Foo bar
```

#### Экранирование и специальные символы

В строке замены `&` обозначает всё найденное совпадение, а `\` используется для экранирования.

```bash
# & — вставка всего совпадения
echo "error: disk full" | sed 's/error/[&]/'
# → [error]: disk full

# Замена слеша в пути (альтернативный разделитель)
sed 's|/usr/local|/opt/local|g' /etc/fstab
```

### Обработка нескольких выражений

```bash
# Несколько команд через -e
sed -i -e 's/old1/new1/g' -e 's/old2/new2/g' file.txt

# Или через точку с запятой (в одинарных кавычках)
sed -i 's/old1/new1/g; s/old2/new2/g' file.txt
```

### Реверс файла (альтернатива `tac`)

Если `tac` отсутствует в системе, можно использовать `sed`:

```bash
# Инверсия строк файла
sed '1!G;h;$!d' file.txt
```

### Парсинг логов (nginx, syslog, journalctl)

Извлечение структурированных данных из логов — частная задача SRE.

```bash
# Вывести только IP адреса из лога nginx
sed -n 's/.* \([0-9]\+\.[0-9]\+\.[0-9]\+\.[0-9]\+\) .*/\1/p' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20

# Заменить уровни лога journalctl для отчёта
journalctl -u sshd --since "1 hour ago" | sed 's/\(.*\)error\(.*\)/\1CRITICAL\2/g'

# Удалить временные метки из лога, оставив только сообщение
sed 's/^[0-9-]\{10\}T[0-9:]\+\.[0-9]\+[+-][0-9]\{4\} //' app.log
```

### Массовое обновление конфигурационных файлов

```bash
# Обновление всех файлов resolv.conf в контейнерах/чанках
find /var/lib/containers -name resolv.conf -exec sed -i 's/nameserver 10.0.0.1/nameserver 10.0.0.2/g' {} +

# Разкомментировать и изменить параметр в sshd_config
sed -i 's/^#PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config

# Добавить опцию systemd-resolved в конфиг
sed -i 's/^#DNS=/DNS=10.0.0.2/' /etc/systemd/resolved.conf

# Отключить swap в fstab (удалить или закомментировать строки с swap)
sed -i '/ swap / s/^/#/' /etc/fstab
```

### Извлечение метаданных пакетов (dpkg/rpm)

```bash
# Вывести версию установленного пакета из базы dpkg
dpkg -s nginx | sed -n 's/^Version: //p'
# → 1.18.0-0ubuntu1.4

# Список всех установленных пакетов с версиями
dpkg -l | sed -n 's/^ii\s*\(\S*)\s*\(\S*).*/\1=\2/p'

# Извлечь Requires из spec-файла RPM
grep '^Requires:' package.spec | sed 's/Requires:\s*//'
```

### Обработка конфигов с переменными (без envsubst)

```bash
# Заменить плейсхолдеры на реальные значения
sed -e "s/{{DB_HOST}}/10.0.0.5/g" \
    -e "s/{{DB_PORT}}/5432/g" \
    -e "s/{{APP_NAME}}/payment-service/g" \
    app.conf.template > app.conf

# Чтение значения из переменной окружения в sed
DB_PASS="s3cret" sed "s/DB_PASS/${DB_PASS}/g" /tmpl/db.conf > /config/db.conf
```

### Интеграция с find + xargs для массовой замены

```bash
# Заменить внутренний домен на внешний во всех конфигах nginx
find /etc/nginx -type f -name '*.conf' -print0 | xargs -0 sed -i 's/internal.example.com/external.example.com/g'

# Безопасная массовая замена с dry-run
find /etc -type f -name '*.conf' -print0 | xargs -0 -I{} sed -i.bak 's/old/new/g' {}
find /etc -name '*.bak' -delete
```

### Валидация и dry-run паттерны

```bash
# Показать, что будет изменено, без записи
sed 's/old/new/g' /etc/nginx/nginx.conf | diff -u /etc/nginx/nginx.conf -

# Проверить синтаксис конфига после изменения
sed -i.bak 's/worker_processes 4/worker_processes auto/' /etc/nginx/nginx.conf && nginx -t

# Атомарная запись через временный файл
sed 's/old/new/g' config.conf > config.conf.tmp && mv config.conf.tmp config.conf
```

### Извлечение данных из /proc и системных файлов

```bash
# Показать только числовые значения из /proc/meminfo
sed -n 's/^\([A-Za-z]*\):\s*\([0-9]*\).*/\2/p' /proc/meminfo

# Извлечь параметры ядра из /etc/default/grub
sed -n 's/^GRUB_CMDLINE_LINUX_DEFAULT="\([^"]*\)".*/\1/p' /etc/default/grub
```

### Подготовка конфигов для deployment

```bash
# Универсальный шаблон: замена версии образа в values.yaml
sed -i "s|tag: .*|tag: ${VERSION}|" deploy/values.yaml

# Генерация конфига nginx из шаблона
sed -e "s|{{LISTEN_PORT}}|${PORT}|g" \
    -e "s|{{SERVER_NAME}}|${HOSTNAME}|g" \
    nginx.conf.tmpl > /etc/nginx/conf.d/app.conf

# Обновление retain-логов в logrotate
sed -i "s/rotate .*/rotate ${LOG_RETENTION_DAYS}/" /etc/logrotate.d/app
```

### Типичные ошибки

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `sed: 1: "s/foo/bar/": extra characters at the end of l` | На macOS попытка использовать GNU-синтаксис `-i` без аргумента | Используйте `-i ''` на macOS или `-i` на Linux |
| Замена не срабатывает | Разделитель `/` конфликтует с путем | Используйте альтернативный разделитель: `s|/path|/new|g` |
| Файл становится пустым | Ошибка в адресации или `d` без условия | Проверьте адресацию и условия удаления |
| `\t` заменяется на буквы `\t` | На macOS `\t` не интерпретируется как табуляция в BRE | Используйте реальный символ табуляции или переключитесь на ERE |
| Файл не меняется при использовании `-I` (заглавная) | `-I` (uppercase) в некоторых дистрибутивах имеет другое назначение | Используйте **строчный** `-i` для in-place editing |
| Замена срабатывает только в первой строке | Отсутствует флаг `g` в команде `s///` | Добавьте `g` для глобальной замены в строке |
| `sed` "зависает" на больших файлах | Накопление всего файла в hold space без вывода | Добавьте `-n` и явный `p` или ограничьте pattern space |
| `\n` не работает в замене (macOS) | В BSD sed `\n` в строке замены интерпретируется как литерал | Используйте реальный символ новой строки или переключитесь на GNU sed |
| `sed` игнорирует пустые строки при использовании `-z` | `-z` меняет разделитель на `\0`, строки разделяются NUL-байтами | Убедитесь, что входные данные действительно NUL-separated |
| Ошибка `unterminated address regex` | Неэкранированный `/` внутри BRE без смены разделителя | Смените разделитель на `|` или `:` |
| `&` в замене интерпретируется как совпадение, а не как `&` | Нужно экранировать: `\&` | Используйте `\&` для литерального `&` |
| `sed` выводит пустые строки между строками | Использование `N` без последующего объединения | Добавьте `s/\n/ /` или `P;D` для корректной работы |
| `-E` не работает на Ubuntu 16.04 | Устаревший GNU sed (< 4.2) без поддержки `-E` | Используйте `-r` (GNU sed) или обновите coreutils |
| `sed` не заменяет в симлинках при `-i` | `-i` следует по ссылке и модифицирует целевой файл | Это ожидаемое поведение; для безопасных скриптов проверяйте `readlink -f` |

## Дополнительная информация

### Переменные окружения

- **`SED_OPTIONS`**: В некоторых дистрибутивах (Debian, Ubuntu) используется для задания флагов по умолчанию. Обычно содержит `--preserve-root` или аналогичные безопасные опции.
- **`LC_ALL` / `LANG`**: Влияют на обработку многобайтовых символов. Для экстремальной производительности на больших файлах используйте `LC_ALL=C sed ...` (отключает UTF-8, ускоряет в 10–100 раз).
- **`POSIXLY_CORRECT`**: Если установлена, `sed` может изменять поведение некоторых расширенных функций в сторону строгого POSIX.

### Производительность

| Сценарий | Рекомендация |
| :--- | :--- |
| Большие файлы (>1 ГБ) | Используйте `LC_ALL=C`, избегайте hold space и многострочного режима (`N`) |
| Много файлов | `find ... -print0 \| xargs -0 sed -i` вместо цикла `for f in *` |
| Простая замена | `sed -i` быстрее, чем `perl -pi -e` из-за меньшего накладного расхода |
| Многострочная логика | Если `N`/`G`/`h` делают скрипт сложным, рассмотрите `awk` или `perl` |

### Безопасность и лучшие практики

1. **Всегда делайте резервную копию перед in-place editing:**
   ```bash
   sed -i.bak 's/old/new/g' /etc/nginx/nginx.conf
   # После проверки: rm /etc/nginx/nginx.conf.bak
   ```

2. **Используйте атомарные операции для критичных файлов:**
   ```bash
   sed 's/old/new/g' config.conf > config.conf.tmp && mv config.conf.tmp config.conf
   ```

3. **Проверяйте синтаксис перед применением:**
   ```bash
   sed 's/old/new/g' /etc/nginx/nginx.conf | nginx -t
   ```

4. **Избегайте `-i` в конвейерах с несколькими файлами разного типа:**
   ```bash
   find /etc -type f -name '*.conf' -exec sed -i.bak 's/old/new/g' {} +
   find /etc -name '*.bak' -delete  # cleanup
   ```

5. **Используйте одинарные кавычки для sed-скриптов**, чтобы предотвратить интерпретацию `$`, `` ` `` и `\` оболочкой.

### Сравнение с awk

| Утилита | Область применения | Преимущества |
| :--- | :--- | :--- |
| `sed` | Простая побайтовая замена, фильтрация строк | Быстрее, проще синтаксис для простых замен |
| `awk` | Структурированная обработка полей, вычисления | Работает с полями (`$1`, `$2`), условия, переменные, арифметика |

Для сложной манипуляции столбцами используйте `awk`. Для простой замены текста — `sed`.

### Взаимодействие с grep

Для задач "найти и заменить" часто используется комбинация:

```bash
# Найти файлы и заменить в них текст
grep -rl "pattern" /path | xargs sed -i 's/pattern/replacement/g'
```

### Коды возврата

- **`0`**: Успешное выполнение.
- **`1`**: Некорректные регулярные выражения или команды.
- **`2`**: Системная ошибка (файл не найден, нет прав).
