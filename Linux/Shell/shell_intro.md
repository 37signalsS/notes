# Введение в командную строку: Terminal, Shell, CLI

## Определения

- **Эмулятор терминала (Terminal Emulator)** — графическое приложение (например, Alacritty, iTerm2, GNOME Terminal, Kitty, Windows Terminal), которое предоставляет окно для ввода команд и отображения текстового вывода. Оно имитирует поведение исторических аппаратных терминалов, взаимодействуя с системой через псевдо-терминалы (PTY).
- **Командная оболочка (Shell)** — программа-интерпретатор, которая служит посредником между пользователем и ядром ОС. Она принимает команды, выполняет подстановки (expansions), управляет переменными окружения и процессами, реализует job control и сигнальную обработку.
- **Интерфейс командной строки (CLI)** — текстовый способ взаимодействия с ПО, основанный на вводе текстовых команд и получении текстовых ответов.
- **TTY / PTY (Teletype / Pseudo-Teletype)**:
  - **TTY**: В современном Linux — виртуальная консоль ядра (доступ через `Ctrl+Alt+F1...F6`).
  - **PTY**: Пара устройств (master/slave), используемая эмуляторами терминала, SSH и контейнерами для эмуляции физического терминала.
- **Приглашение (Prompt)** — строка текста (обычно переменная `$PS1`), указывающая на готовность Shell к вводу.
  - `$` (Доллар): Обычный пользователь.
  - `#` (Решётка): Суперпользователь (root).
- **PID (Process ID)** — уникальный идентификатор процесса в системе.
  - `$$` — PID текущей оболочки.
  - `$!` — PID последнего запущенного фонового процесса.
  - `$PPID` — PID родительского процесса.
- **Job** — команда или конвейер, запущенные в фоне (`&`). Shell назначает каждому job номер (`%1`, `%2`, ...), который используется для управления (`fg`, `bg`, `kill`).

## Базовые концепции

### Типы командных оболочек

| Оболочка | Описание | Особенности |
| :--- | :--- | :--- |
| **sh** | Bourne Shell. Прародитель большинства современных оболочек. | Строгое соответствие стандарту POSIX. |
| **bash** | Bourne Again Shell. Стандарт де-факто в Linux. | Совместима с `sh`, расширена массивами и функциями. |
| **dash** | Debian Almquist Shell. Легкая и быстрая. | Используется как `/bin/sh` в Debian/Ubuntu для ускорения скриптов загрузки. |
| **zsh** | Z Shell. Мощная альтернатива Bash. | Стандарт в macOS. Отличная автоподстановка и плагины (Oh-My-Zsh). |
| **fish** | Friendly Interactive Shell. | Упор на удобство пользователя "из коробки". **Не совместима** с POSIX/Bash. |

> **SRE-заметка:** В скриптах всегда используйте `#!/bin/sh` для максимальной переносимости или `#!/bin/bash`, если требуются специфичные функции (например, `${PIPESTATUS}`). Избегайте привязки к оболочкам вроде `fish` в автоматизации.

### Стандартные потоки данных

Каждый процесс в Shell по умолчанию связан с тремя файловыми дескрипторами:
1. **stdin (fd 0)** — стандартный ввод (клавиатура или конвейер).
2. **stdout (fd 1)** — стандартный вывод (экран или файл).
3. **stderr (fd 2)** — стандартный поток ошибок (вывод ошибок, диагностика).

Подробнее о манипуляциях потоками: [Перенаправление ввода-вывода](./io_redirection.md).
Подробнее о файловых дескрипторах, архитектуре ядра и лимитах: [Файловые дескрипторы](../FileSystems/file_descriptors.md).

### Встроенные и внешние команды

- **Встроенные (Built-ins)**: Часть исполняемого файла самой оболочки (`cd`, `export`, `alias`, `echo`, `source`, `exec`, `pwd`, `umask`, `jobs`, `fg`, `bg`, `disown`). Выполняются без порождения нового процесса.
- **Внешние (External)**: Самостоятельные бинарные файлы в системе (`ls`, `grep`, `docker`, `systemctl`). Shell ищет их в директориях, перечисленных в переменной `$PATH`.
- **Алиасы (Aliases)**: Псевдонимы команд, определяемые в оболочке (`alias ll='ls -la'`). Работают только в интерактивных сессиях; в скриптах отключены по умолчанию (`shopt -s expand_aliases`).

> **Важно:** `cd` — встроенная команда. Внешние команды не могут изменить рабочую директорию вызывающей оболочки. Это частая ошибка при написании скриптов.
> Подробнее о приоритетах поиска и хэшировании: [Логика обработки команд](./bash_command_execution.md).

### Специальные параметры и переменные

| Параметр | Значение |
| :--- | :--- |
| `$0` | Имя текущей оболочки или скрипта. |
| `$-` | Текущие опции Shell (например, `himBHs`). |
| `$?` | Код возврата последней выполненной команды. |
| `$$` | PID текущей оболочки. |
| `$!` | PID последнего фонового процесса. |
| `$PPID` | PID родительского процесса. |
| `$#` | Количество позиционных параметров. |
| `$*` / `$@` | Все позиционные параметры (разница в кавычках). |
| `$IFS` | Разделитель полей (Internal Field Separator). По умолчанию: пробел, таб, перевод строки. |

> **SRE-заметка:** `$$` и `$PPID` полезны для идентификации сессии SSH, родительского systemd-сервиса или проверки, что скрипт запущен из cron/at.
> Подробнее о переменных окружения и файлах инициализации: [Переменные оболочки](./shell_variables.md).

### Режимы сессий (Login vs Non-login)

Тип сессии определяет, какие конфигурационные файлы (dotfiles) будут загружены:

1. **Интерактивная сессия входа (Interactive Login)**: Выполняется при входе через SSH или TTY.
   - Читает: `/etc/profile` → `~/.bash_profile` (или `~/.profile`) → `~/.bashrc` (если импортируется).
2. **Интерактивная сессия без входа (Interactive Non-login)**: Обычное окно терминала в GUI.
   - Читает: `~/.bashrc`.
3. **Неинтерактивная сессия (Non-interactive)**: Выполнение скрипта.
   - Использует переменную `$BASH_ENV`.

> **Важно для DevOps:** При настройке CI/CD агентов или Bastion-хостов проверяйте, какой тип сессии инициирует SSH (`ssh -t user@host 'bash -l -c "echo test"'` для принудительного login-режима). Отсутствие ожидаемого dotfile — частая причина неработающих алиасов или `$PATH`.
> Подробнее: [Логика обработки команд](./bash_command_execution.md).

### Управление ресурсами и ограничениями

Shell наследует и может устанавливать ограничения процессов через `ulimit`:

| Команда | Описание | Типичное значение в production |
| :--- | :--- | :--- |
| `ulimit -n` | Максимальное количество открытых файловых дескрипторов (RLIMIT_NOFILE). | 65536 — 1048576 |
| `ulimit -u` | Максимальное количество процессов для пользователя (RLIMIT_NPROC). | 4096 — 32768 |
| `ulimit -f` | Максимальный размер создаваемого файла в блоких по 512 байт (RLIMIT_FSIZE). | unlimited |
| `ulimit -v` | Максимальный размер виртуальной памяти в KB (RLIMIT_AS). | unlimited |
| `ulimit -c` | Размер core dump файла (RLIMIT_CORE). | 0 (отключено в production) |

Для постоянного применения используются:
- `/etc/security/limits.conf` (PAM-модуль `pam_limits.so`).
- Systemd-юниты: `LimitNOFILE=`, `LimitNPROC=`, `LimitCORE=`.
- Контейнеры: `--ulimit nofile=1024:4096` в Docker/Podman.

> **SRE-заметка:** "Too many open files" (`EMFILE`) — одна из самых частых причин падения веб-серверов и баз данных. Проверяйте `ulimit -n` в systemd-сервисах отдельно от интерактивного терминала.
> Подробнее: [Файловые дескрипторы](../FileSystems/file_descriptors.md).

### История команд и аудит

| Переменная | Назначение |
| :--- | :--- |
| `$HISTFILE` | Файл истории (по умолчанию `~/.bash_history`). |
| `$HISTSIZE` | Количество команд, хранимых в памяти текущей сессии. |
| `$HISTFILESIZE` | Количество строк, сохраняемых в `$HISTFILE` при выходе. |
| `$HISTCONTROL` | Управление дубликатами и командами с пробелом (`ignorespace`, `ignoredups`, `erasedups`). |
| `$HISTTIMEFORMAT` | Формат отображения времени в `history` (например, `"%F %T "`). |

> **SRE-заметка:** Для compliance и безопасности используйте `HISTCONTROL=ignorespace` (команды, начинающиеся с пробела, не попадают в историю) и настройте `auditd` или `journald` для централизованного сбора истории. В production-скриптах history часто отключают (`set +o history` или `HISTSIZE=0`).

### Job Control и управление фоновыми задачами

| Команда / Переменная | Описание |
| :--- | :--- |
| `&` | Запуск команды в фоне. |
| `jobs` | Список активных job-ов текущей сессии. |
| `fg %1` | Вывести job №1 на передний план. |
| `bg %1` | Продолжить выполнение остановленного job №1 в фоне. |
| `disown -h %1` | Удалить job из таблицы Shell, чтобы он не получил `SIGHUP` при выходе. |
| `nohup cmd &` | Запуск процесса, игнорирующего `SIGHUP`. |
| `wait` | Ожидать завершения всех фоновых процессов. |
| `wait -n` | Ожидать завершения любого одного фонового процесса (Bash 4.3+). |
| `$!` | PID последнего фонового процесса. |

> **Важно:** При выходе из SSH-сессии Shell отправляет `SIGHUP` всем дочерним процессам. Для сохранения фоновых задач используйте `tmux`/`screen`, `disown` или `systemd-run --user --scope`.

### Трассировка и отладка Shell

| Инструмент | Назначение |
| :--- | :--- |
| `set -x` / `set +x` | Включить/выключить трассировку выполнения команд. |
| `PS4` | Префикс для строк трассировки. Например: `PS4='+${BASH_SOURCE}:${LINENO}:${FUNCNAME[0]}: '`. |
| `bash -x script.sh` | Запуск скрипта в режиме трассировки без изменения кода. |
| `trap 'echo ERROR at ${BASH_SOURCE}:${LINENO}' ERR` | Обработчик ошибок с указанием источника. |

> **SRE-заметка:** Для отладки проблем в production используйте `PS4` с `BASH_SOURCE` и `LINENO` — это позволяет быстро локализовать проблемный скрипт и строку без IDE. В сочетании с `exec 5> >(logger -t myscript)` вывод можно отправлять в `journalctl`.

## Практические сценарии

### Анализ текущего окружения

```bash
# Текущая оболочка по умолчанию (из /etc/passwd)
echo $SHELL

# Тип команды и её путь
type -a ls
# → ls is aliased to `ls --color=auto`
# → ls is /usr/bin/ls

# Проверка наличия утилиты без её запуска (безопасно для скриптов)
command -v kubectl >/dev/null && echo "K8s CLI найдена"

# PID текущей оболочки и родителя
echo "My PID=$$, PPID=$PPID"

# Последний фоновый PID
sleep 10 &
echo "Background PID=$!"
```

### Режимы сессий (Login vs Non-login)

Тип сессии определяет, какие конфигурационные файлы (dotfiles) будут загружены:

1. **Интерактивная сессия входа (Interactive Login)**: Выполняется при входе через SSH или TTY.
   - Читает: `/etc/profile` → `~/.bash_profile` (или `~/.profile`).
2. **Интерактивная сессия без входа (Interactive Non-login)**: Обычное окно терминала в GUI.
   - Читает: `~/.bashrc`.
3. **Неинтерактивная сессия (Non-interactive)**: Выполнение скрипта.
   - Использует переменную `$BASH_ENV`.

Подробнее о настройке и приоритетах переменных: [Переменные оболочки](./shell_variables.md).

### Управление PATH в production

```bash
# Безопасное добавление пути (исключает дубликаты)
case ":$PATH:" in
  *":/opt/myapp/bin:"*) ;;
  *) export PATH="/opt/myapp/bin:$PATH" ;;
esac

# Поиск команды без запуска
command -v vault >/dev/null 2>&1 || echo "Vault CLI missing"

# Сброс кэша путей (полезно после установки нового софта)
hash -r
```

> **SRE-заметка:** `which` — внешняя команда и не всегда доступна; используйте `command -v` или `type -a`. В продакшен-скриптах избегайте зависимости от `$PATH` — указывайте полный путь (`/usr/bin/jq`).

### Управление ulimit для sysadmin

```bash
# Проверить текущие лимиты
ulimit -a

# Установить лимит на открытые файлы для текущей сессии
ulimit -n 65536

# Постоянная настройка через limits.conf
# /etc/security/limits.conf
# admin soft nofile 65536
# admin hard nofile 1048576

# Для systemd-сервиса
# /etc/systemd/system/myapp.service
# [Service]
# LimitNOFILE=1048576
```

### Практика sudo и окружение

```bash
# Сохранить текущее окружение (включая PS1, PATH)
sudo -E env

# Запустить login-оболочку (полная инициализация root)
sudo -i

# Запустить не-login оболочку с текущим окружением
sudo -s

# Переключиться на другого пользователя без сброса окружения
sudo -u deploy -i

# NOPASSWD в /etc/sudoers (осторожно!)
# deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart myapp
```

> **Важно:** `sudo` по умолчанию сбрасывает `PATH` и переменные. Используйте `sudo -E` только если понимаете риски безопасности.

### Фоновые задачи и tmux/screen

```bash
# Запуск в фоне с nohup
nohup /opt/scripts/backup.sh > /var/log/backup.log 2>&1 &

# Удаление из таблицы jobs (не получит SIGHUP)
disown -h %1

# Альтернатива — tmux (рекомендуется)
tmux new -s maintenance
tmux attach -t maintenance
tmux kill-session -t maintenance
```

> **SRE-заметка:** `tmux` предпочтительнее `screen` в 2026 году: поддержка 256 цветов, UTF-8, clipboard, более активная разработка. Для автоматизации используйте `tmux new-session -d -s deploy "cmd"`.

### Запись и воспроизведение сессий

```bash
# Запись всей сессии в файл
script -q /tmp/session.log

# Воспроизведение
scriptreplay /tmp/session.log

# Запись с таймингом для replay
script -t=2 /tmp/session.timing
```

### Диагностика окружения

```bash
# Все переменные окружения
env | sort

# Встроенные переменные shell
set

# Экспортированные переменные
export -p

# Проверить, является ли текущая оболочка bash
test -n "$BASH_VERSION" && echo "Bash $BASH_VERSION"

# Проверить, интерактивна ли сессия
test -t 0 && echo "Interactive" || echo "Non-interactive"
```

### Смена оболочки пользователя

```bash
# Посмотреть список разрешенных оболочек
cat /etc/shells

# Сменить оболочку по умолчанию на zsh
chsh -s /bin/zsh
```

## Дополнительная информация

### Безопасность и управление сессиями

В современных системах за управление сессиями на уровне ОС отвечает `systemd-logind`. Это важно учитывать при работе с фоновыми процессами и мультиплексорами:
- Для сохранения сессий при отключении используйте `tmux` или `screen` ([управление сессиями SSH](../Security/ssh/ssh_session_management.md)).
- Процессы, запущенные в фоне через `&`, могут завершиться при выходе из Shell (SIGHUP), если не использовать `nohup` или `disown`.
- Права на dotfiles: `chmod 700 ~/.ssh`, `chmod 700 ~/.gnupg`. Никогда не делайте `~/.ssh` доступным для группы/остальных.
- Для аудита команд включайте `auditd` или настройте `journald` persistent storage.
