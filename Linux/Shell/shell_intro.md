# Введение в командную строку: Terminal, Shell, CLI

## Определения

- **Terminal Emulator (Эмулятор терминала)** — графическое приложение, предоставляющее окно для ввода команд и отображения текстового вывода. Служит интерфейсом для взаимодействия с оболочкой.
- **Shell (Командная оболочка)** — программа-интерпретатор, которая принимает команды от пользователя, передает их ядру операционной системы и управляет процессами, переменными и скриптами.
- **CLI (Command Line Interface)** — текстовый интерфейс взаимодействия пользователя с программным обеспечением, основанный на вводе команд в виде строк текста.
- **Prompt (Приглашение)** — индикатор готовности оболочки к приему команд (например, `user@hostname:~$`).

## Базовые концепции

### Типы командных оболочек

В современных Linux-системах используются различные реализации оболочек:

- **sh (Bourne Shell)** — исторический стандарт. В современных системах часто является ссылкой на `bash` или `dash` в режиме совместимости с POSIX.
- **bash (Bourne Again Shell)** — стандартная оболочка для интерактивной работы и написания скриптов в большинстве дистрибутивов Linux.
- **dash (Debian Almquist Shell)** — легковесная и быстрая оболочка, строго соответствующая стандарту POSIX. Часто используется как `/bin/sh` для выполнения системных скриптов.
- **zsh (Z Shell)** — мощная оболочка, совместимая с `bash`, но обладающая расширенным функционалом автодополнения и поддержки плагинов (например, Oh My Zsh).
- **fish (Friendly Interactive Shell)** — ориентирована на удобство пользователя "из коробки" (подсветка синтаксиса, умные подсказки), но имеет синтаксис, не полностью совместимый с POSIX.

### Взаимосвязь компонентов

Процесс взаимодействия с системой выглядит следующим образом:

1. Пользователь запускает **Terminal Emulator**.
2. Внутри терминала запускается экземпляр **Shell** (например, `bash`).
3. **Shell** выводит **Prompt**, ожидая ввода команды.

### Автодополнение (TAB)

Автодополнение — механизм ускорения ввода команд и путей:

- **Одиночное нажатие TAB** — достраивает имя команды или путь, если вариант уникален.
- **Двойное нажатие TAB** — выводит список всех доступных вариантов, если их несколько.

## Практические сценарии

### Определение текущей оболочки

```bash
# Проверка переменной окружения
echo $SHELL

# Проверка имени текущего процесса
echo $0
```

### Поиск местоположения исполняемых файлов

Для определения того, какая программа будет запущена, используются команды `which` и `type`:

```bash
# Поиск в директориях переменной $PATH
which ls

# Более детальная информация (видит алиасы и встроенные команды)
type ls
```

### Траблшутинг ошибки "command not found"

При возникновении данной ошибки следует проверить:

1. **Наличие программы** — установлена ли она в системе.
2. **Переменную $PATH** — находится ли путь к исполняемому файлу в списке путей поиска.
3. **Опечатки** — правильность написания имени команды.

## Дополнительная информация

### Режимы работы и конфигурационные файлы

Оболочки могут работать в разных режимах, что влияет на загрузку настроек:

- **Interactive login shell** (интерактивная оболочка входа) — запускается при входе в систему (консоль, SSH). Загружает `/etc/profile` и `~/.bash_profile` (или `~/.profile`).
- **Interactive non-login shell** (интерактивная оболочка без входа) — запускается при открытии нового окна терминала в GUI. Загружает `~/.bashrc`.
- **Non-interactive shell** (неинтерактивная оболочка) — используется для выполнения скриптов. Конфигурационные файлы интерактивной среды обычно не загружаются.
