# Введение в командную строку: Terminal, Shell, CLI

## Определения

- **Эмулятор терминала (Terminal Emulator)** — графическое приложение (например, Alacritty, iTerm2, GNOME Terminal), которое предоставляет окно для ввода команд и отображения текстового вывода. Оно имитирует поведение исторических аппаратных терминалов, взаимодействуя с системой через псевдо-терминалы (PTY).
- **Командная оболочка (Shell)** — программа-интерпретатор, которая служит посредником между пользователем и ядром ОС. Она принимает команды, выполняет подстановки (expansions), управляет переменными окружения и процессами.
- **Интерфейс командной строки (CLI)** — текстовый способ взаимодействия с ПО, основанный на вводе текстовых команд и получении текстовых ответов.
- **TTY / PTY (Teletype / Pseudo-Teletype)**:
  - **TTY**: В современном Linux — виртуальная консоль ядра (доступ через `Ctrl+Alt+F1...F6`).
  - **PTY**: Пара устройств (master/slave), используемая эмуляторами терминала, SSH и контейнерами для эмуляции физического терминала.
- **Приглашение (Prompt)** — строка текста (обычно переменная `$PS1`), указывающая на готовность Shell к вводу.
  - `$` (Доллар): Обычный пользователь.
  - `#` (Решётка): Суперпользователь (root).

## Базовые концепции

### Типы командных оболочек

| Оболочка | Описание | Особенности |
| :--- | :--- | :--- |
| **sh** | Bourne Shell. Прародитель большинства современных оболочек. | Строгое соответствие стандарту POSIX. |
| **bash** | Bourne Again Shell. Стандарт де-факто в Linux. | Совместима с `sh`, расширена массивами и функциями. |
| **dash** | Debian Almquist Shell. Легкая и быстрая. | Используется как `/bin/sh` в Debian/Ubuntu для ускорения скриптов загрузки. |
| **zsh** | Z Shell. Мощная альтернатива Bash. | Стандарт в macOS. Отличная автоподстановка и плагины (Oh-My-Zsh). |
| **fish** | Friendly Interactive Shell. | Упор на удобство пользователя "из коробки". **Не совместима** с POSIX/Bash. |

> **SRE-заметка:** В скриптах всегда используйте `#!/bin/sh` для максимальной переносимости или `#!/bin/bash`, если требуются специфичные функции (например, `${PIPESTATUS}`). Избегайте привязки к оболочкам вроде `fish` в автоматизации.

### Стандартные потоки данных

Каждый процесс в Shell по умолчанию связан с тремя файловыми дескрипторами:
1. **stdin (fd 0)** — стандартный ввод (клавиатура или конвейер).
2. **stdout (fd 1)** — стандартный вывод (экран или файл).
3. **stderr (fd 2)** — стандартный поток ошибок (вывод ошибок, диагностика).

Подробнее о манипуляциях потоками: [Перенаправление ввода-вывода](./io_redirection.md).

### Встроенные и внешние команды

- **Встроенные (Built-ins)**: Часть исполняемого файла самой оболочки (`cd`, `export`, `alias`). Выполняются без порождения нового процесса.
- **Внешние (External)**: Самостоятельные бинарные файлы в системе (`ls`, `grep`, `docker`). Shell ищет их в директориях, перечисленных в переменной `$PATH`.

Логика поиска и приоритеты выполнения детально описаны в [Логике обработки команд](./bash_command_execution.md).

### Работа со справочной информацией

1. **man (Manual pages)**: Официальные системные руководства.
2. **help**: Справка по встроенным командам оболочки (только для Bash).
3. **apropos**: Поиск команд по ключевым словам в их описании.
4. **tldr**: Лаконичные практические примеры (см. [инструментарий CLI](./cli-tools.md)).

## Практические сценарии

### Анализ текущего окружения

```bash
# Текущая оболочка по умолчанию (из /etc/passwd)
echo $SHELL

# Тип команды и её путь
type -a ls
# → ls is aliased to `ls --color=auto`
# → ls is /usr/bin/ls

# Проверка наличия утилиты без её запуска (безопасно для скриптов)
command -v kubectl >/dev/null && echo "K8s CLI найдена"
```

### Режимы сессий (Login vs Non-login)

Тип сессии определяет, какие конфигурационные файлы (dotfiles) будут загружены:

1. **Интерактивная сессия входа (Interactive Login)**: Выполняется при входе через SSH или TTY.
   - Читает: `/etc/profile` → `~/.bash_profile` (или `~/.profile`).
2. **Интерактивная сессия без входа (Interactive Non-login)**: Обычное окно терминала в GUI.
   - Читает: `~/.bashrc`.
3. **Неинтерактивная сессия (Non-interactive)**: Выполнение скрипта.
   - Использует переменную `$BASH_ENV`.

Подробнее о настройке и приоритетах переменных: [Переменные оболочки](./shell_variables.md).

### Смена оболочки пользователя

```bash
# Посмотреть список разрешенных оболочек
cat /etc/shells

# Сменить оболочку по умолчанию на zsh
chsh -s /bin/zsh
```

## Дополнительная информация

### Безопасность и управление сессиями

В современных системах за управление сессиями на уровне ОС отвечает `systemd-logind`. Это важно учитывать при работе с фоновыми процессами и мультиплексорами:
- Для сохранения сессий при отключении используйте `tmux` или `screen` ([управление сессиями SSH](../Security/ssh/ssh_session_management.md)).
- Процессы, запущенные в фоне через `&`, могут завершиться при выходе из Shell (SIGHUP), если не использовать `nohup` или `disown`.
