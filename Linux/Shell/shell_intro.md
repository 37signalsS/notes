# Введение в командную строку: Терминал, Оболочка, CLI

## Определения

* **Эмулятор терминала (Terminal Emulator):** графическое приложение (окно) для ввода команд и отображения вывода. Предоставляет интерфейс для взаимодействия с командной оболочкой.

* **Командная оболочка (Shell):** программа-интерпретатор, работающая внутри эмулятора терминала. Принимает команды, передаёт их ядру ОС, управляет переменными, скриптами и процессами.

* **Интерфейс командной строки (Command Line Interface, CLI):** текстовый интерфейс для взаимодействия с оболочкой. Состоит из строк ввода команд и вывода результатов. Включает **приглашение (prompt)** — индикатор готовности к вводу (например, `user@hostname:~$`).

## Типы командных оболочек

В современных Linux-системах сосуществуют несколько реализаций оболочек, оптимизированных под разные задачи:

* **sh (Bourne Shell):** исторический стандарт. В современных системах `/bin/sh` обычно является символической ссылкой на одну из оболочек, работающую в режиме совместимости с POSIX.
* **bash (Bourne Again Shell):** стандарт де-факто для интерактивной работы и скриптов в Linux. Обладает богатым функционалом (автодополнение, история, расширенные скриптовые конструкции).
* **dash (Debian Almquist Shell):** минималистичная и быстрая оболочка, строго следующая стандарту POSIX.
  * **Применение:** используется как `/bin/sh` в Debian/Ubuntu для выполнения системных скритов.
* **ksh (Korn Shell):** сочетает черты `sh` и `csh`. Послужила основой для многих функций `bash`. Популярна в корпоративных UNIX-системах (AIX, Solaris).
* **tcsh/csh (C Shell):** использует C-подобный синтаксис. Исторически популярна в BSD-системах.
* **zsh (Z Shell):** мощная оболочка, совместимая с `bash`, но с огромным количеством плагинов (Oh My Zsh) и улучшенным автодополнением. Стандартная оболочка в macOS.
* **fish (Friendly Interactive Shell):** фокусируется на удобстве пользователя "из коробки" (умные автоподсказки, подсветка синтаксиса), но имеет несовместимый с POSIX синтаксис скриптов.

**Какую оболочку использовать?**
* Для **написания скриптов** стандартом является `bash` (из-за распространенности) или `sh/dash` (для максимальной переносимости и скорости).
* Для **интерактивной работы** (ввода команд) часто выбирают `zsh` или `fish` из-за продвинутых визуальных функций и плагинов, облегчающих повседневные задачи.

## Основные концепции

#### Автодополнение (TAB)

Одной из самых полезных функций современных оболочек (особенно Bash) является автодополнение.
*   **Одиночный TAB:** достраивает команду или путь к файлу, если вариант единственный.
*   **Двойной TAB (TAB-TAB):** показывает список всех возможных вариантов завершения, если их несколько. Работает для команд, имён файлов, переменных окружения и даже параметров некоторых команд (при установленном пакете `bash-completion`).

#### Взаимосвязь компонентов

1. Открывается **эмулятор терминала** (например, GNOME Terminal).
2. Терминал запускает **оболочку** (например, `bash`).
3. Оболочка предоставляет **командную строку** для ввода команд.

## Практические сценарии

#### Траблшутинг: "command not found"

Если при запуске команды (например, `ifconfig -a`) вы получили ошибку `command not found`, возможны следующие причины:

1.  **Программа не установлена:** пакет может отсутствовать в системе.
    *   *Пример:* `ifconfig` входит в устаревший пакет `net-tools`. В современных дистрибутивах вместо неё используется `ip addr` из пакета `iproute2`.
2.  **Программа не в PATH:** исполняемый файл находится в директории, которой нет в переменной `$PATH`.
    *   *Решение:* Проверьте `/sbin` или `/usr/sbin` (многие системные утилиты доступны только там). Попробуйте запустить через полный путь: `/sbin/ifconfig`.
3.  **Опечатка:** проверьте правильность написания команды.

#### Как узнать свою текущую оболочку?

```bash
echo $SHELL
# /bin/bash

# Или, для большинства интерактивных оболочек:
echo $0
# bash
```

#### Как узнать, установлена ли программа и где она находится?

Команда `which` ищет исполняемый файл в директориях `$PATH` и выводит путь к первому найденному. Если программа не найдена — вывод отсутствует или возвращается ошибка (зависит от версии). Команда `type` (встроенная в bash) более надёжна, так как видит алиасы и функции.

```bash
which micro
/usr/bin/micro

type ls
# ls is aliased to `ls --color=auto'
```

## Дополнительная информация

### Режимы работы и файлы конфигурации

Оболочки работают в разных режимах, определяющих загружаемые файлы конфигурации (`startup files`).

* **Интерактивная login-оболочка (Interactive login shell):**
  * **Что это:** сессия при входе через консоль или SSH.
  * **Файлы конфигурации (Bash):** `/etc/profile` → первый найденный из `~/.bash_profile`, `~/.bash_login`, `~/.profile`.
  * **Назначение:** переменные окружения для всей сессии пользователя.

* **Интерактивная non-login-оболочка (Interactive non-login shell):**
  * **Что это:** сессия при открытии нового окна терминала в графическом интерфейсе.
  * **Файлы конфигурации (Bash):** `~/.bashrc`.
  * **Назначение:** алиасы, функции, настройки `prompt` для интерактивной работы.

* **Неинтерактивная оболочка (Non-interactive shell):**
  * **Что это:** оболочка, выполняющая скрипт.
  * **Файлы конфигурации (Bash):** обычно не загружаются — обеспечивается предсказуемая среда выполнения. Переменные окружения наследуются от родительского процесса.

Подробнее о переменных и файлах конфигурации см. в [Переменных и dotfiles](./shell_variables.md), об интерактивных утилитах и горячих клавишах — в [Инструментах командной строки](./cli-tools.md).
