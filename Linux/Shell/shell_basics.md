# Основы командной оболочки (Shell Basics)

Здесь будут собраны базовые понятия и операторы, общие для большинства командных оболочек в Linux.

## Эмулятор терминала, Оболочка и Командная строка

### 1. Эмулятор терминала (Terminal Emulator)

Это **графическое приложение**, то есть окно, которое вы открываете, чтобы начать работу. Его единственная задача — предоставить вам интерфейс для взаимодействия с оболочкой (шеллом), обрабатывать ввод с клавиатуры и отображать текстовый вывод.

### 2. Шел / Оболочка (Shell)

Это **программа-интерпретатор**, которая работает *внутри* эмулятора терминала. Именно она принимает ваши команды, "понимает" их и говорит ядру операционной системы, что нужно сделать. Она также отвечает за переменные окружения (`$PATH`), скрипты (например, `.bashrc`) и управление процессами.


### 3. Командная строка (Command Line)

Это и есть сам **текстовый интерфейс** для ввода команд, который предоставляет вам шелл. Если точнее, это одна строка, в которой вы печатаете команду. Она обычно начинается с приглашения (prompt), например `user@hostname:~$`.

## Порядок поиска и выполнения команд

Когда вы вводите команду, оболочка проходит несколько шагов для ее интерпретации:

1.  **Алиасы (Aliases):** Сначала проверяется, не является ли команда псевдонимом (`alias`).
2.  **Встроенные команды (Built-ins):** Если это не алиас, проверяется, не является ли команда встроенной в саму оболочку (`cd`, `echo`).
3.  **Хеш-таблица (Hash):** Оболочка смотрит в кэш путей к ранее выполненным командам.
4.  **Переменная `$PATH`:** Если команда не найдена, оболочка ищет исполняемый файл в директориях, перечисленных в переменной `$PATH`.
5.  **Ошибка:** Если ничего не найдено, выводится ошибка `command not found`.

Подробное описание этой логики, включая различия между внутренними и внешними командами, находится в документе [Продвинутые концепции Bash](./bash_advanced_concepts.md#Порядок-поиска-и-интерпретации-команд).

## Кавычки: одинарные vs двойные

### 1. Одинарные кавычки (`'`) 

Всё, что заключено в одинарные кавычки, интерпретируется **буквально**. Специальные символы, такие как `$`, `\`, ``` ` ```, не обрабатываются.

```sh
 echo 'Переменная $HOME не будет раскрыта'
```
Вывод:
```text
Переменная $HOME не будет раскрыта
```

### 2. Двойные кавычки (`"`)

Двойные кавычки позволяют оболочке **интерпретировать** специальные символы. Это называется подстановкой (interpolation).

- Переменные (`$VAR`) заменяются их значениями.
- Конструкции `` `команда` `` или `$(команда)` заменяются результатом выполнения команды.

```sh
 echo "Ваш домашний каталог: $HOME"
```
Вывод:
```text
Ваш домашний каталог: /home/username
```

## Переменные: локальные и переменные окружения

В Bash существует два основных типа переменных, и понимание разницы между ними критически важно.

1.  **Локальные переменные (`VAR="VALUE"`)**
    -   **Область видимости:** Такая переменная доступна **только в текущем процессе оболочки**, где она была объявлена.
    -   **Наследование:** Дочерние процессы (например, скрипты или команды, запущенные из текущей оболочки) **не унаследуют** эту переменную.

    **Пример:**
    ```bash
    # Объявляем локальную переменную
    MY_VAR="local_value"

    # В текущей оболочке она доступна
    echo $MY_VAR
    # Вывод: local_value

    # Запускаем новый дочерний процесс bash и пытаемся прочитать переменную
    bash -c 'echo $MY_VAR'
    # Вывод: (пустая строка)
    ```

2.  **Переменные окружения (`export VAR="VALUE"`)**
    -   **Область видимости:** Команда `export` "продвигает" локальную переменную до переменной окружения. Она становится доступна не только в текущей оболочке, но и во **всех дочерних процессах**, которые будут из нее запущены.
    -   **Наследование:** Дочерние процессы наследуют все экспортированные переменные родительской оболочки.

    **Пример:**
    ```bash
    # Объявляем и экспортируем переменную
    export MY_EXPORTED_VAR="exported_value"

    # В текущей оболочке она доступна
    echo $MY_EXPORTED_VAR
    # Вывод: exported_value

    # Запускаем новый дочерний процесс bash и пытаемся прочитать переменную
    bash -c 'echo $MY_EXPORTED_VAR'
    # Вывод: exported_value
    ```

**Ключевое правило:**
-   Используйте `VAR="VALUE"` для временных переменных, которые нужны только в текущем скрипте или сессии.
-   Используйте `export VAR="VALUE"` для переменных, которые должны быть доступны программам или скриптам, запускаемым из текущей оболочки (например, `JAVA_HOME`, `PATH`, конфигурационные параметры).

## Операторы управления командами и конвейеры

### Операторы управления командами

-   **`&` (Фоновый режим):** Запускает команду в фоновом режиме, не блокируя терминал.
    ```sh
    sleep 10 &
    ```
-   **`;` (Последовательное выполнение):** Выполняет команды одну за другой, независимо от успеха предыдущей.
    ```sh
    echo "Первая"; echo "Вторая"
    ```
-   **`&&` (Логическое И):** Вторая команда выполняется только в том случае, если первая завершилась успешно (код выхода 0).
    ```sh
    mkdir -p temp_dir && cd temp_dir
    ```
-   **`||` (Логическое ИЛИ):** Вторая команда выполняется только в том случае, если первая завершилась с ошибкой (код выхода не 0).
    ```sh
    ping -c 1 nonexistent-host || echo "Хост недоступен"
    ```

### Конвейеры (`|`)

Конвейеры позволяют передавать стандартный вывод одной команды на стандартный ввод другой.

-   **`|` (Канал, pipe):** Перенаправляет стандартный вывод (`stdout`) одной команды на стандартный ввод (`stdin`) другой.
    ```sh
    ps aux | grep "nginx"
    ```
-   **`|&` (Канал для stdout и stderr):** Перенаправляет и `stdout`, и `stderr`. Оператор `|&` направляет как стандартный вывод (stdout), так и стандартные ошибки (stderr) первой команды через конвейер на стандартный ввод (stdin) второй команды.
    **Пример без `|&` (ошибка не будет обработана):**
    ```bash
    $ cat non_existent_file.txt | grep "No such file"
    ```
    *Вывода не будет, так как `stderr` от `cat` не передается в `grep`.*

    **Пример с `|&` (ошибка будет обработана):**
    ```bash
    $ cat non_existent_file.txt |& grep "No such file"
    cat: non_existent_file.txt: No such file or directory
    ```
    Оператор `|&` в bash является сокращением для `2>&1 |`:
    ```bash
    $ cmd-1 2>&1 | cmd-2
    ```

### Философия Unix и конвейеры (pipelines)

Философия Unix гласит: "Пишите программы, которые делают что-то одно и делают это хорошо. Пишите программы, которые бы работали вместе". Конвейеры (`|`) — это прямое воплощение этого принципа. Они позволяют объединять простые, узкоспециализированные утилиты в цепочку для решения сложных задач без создания временных файлов.

**Как это работает:**
1.  Первая команда выполняет свою работу и отправляет результат на свой стандартный вывод (`stdout`).
2.  Конвейер (`|`) "ловит" этот вывод и немедленно передает его на стандартный ввод (`stdin`) следующей команды.
3.  Следующая команда обрабатывает полученные данные и, в свою очередь, может передать их дальше по цепочке.

#### Примеры использования команд и конвейеров

#### Базовые команды и их аргументы

В Linux команды обычно имеют формат: `команда [ключи] [аргументы]`.
*   **Команда:** Что делать (например, `ls`).
*   **Ключи (опции):** Как делать (например, `-l` для `ls` — длинный формат вывода).
*   **Аргументы:** Над чем делать (например, `/etc` для `ls` — показать содержимое каталога `/etc`).

**Примеры:**
*   `ls`: Вывести содержимое текущего каталога.
*   `ls -l`: Вывести содержимое текущего каталога в длинном формате.
*   `ls -l /etc`: Вывести содержимое каталога `/etc` в длинном формате.
*   `cd`: (Change Directory) Изменить текущий каталог. Без аргументов возвращает в домашний каталог пользователя.
*   `pwd`: (Print Working Directory) Вывести текущий рабочий каталог.
*   `echo <текст>`: Вывести текст на стандартный вывод. Используется для вывода значений переменных (например, `echo $PATH`).

### Конвейеры (`|`)

Конвейеры позволяют передавать стандартный вывод одной команды на стандартный ввод другой.

**Пример:** Посчитать количество строк в выводе `ls -l`.
```bash
ls -l | wc -l
```
Здесь `stdout` команды `ls -l` передается на `stdin` команды `wc -l` (word count, опция `-l` для подсчета строк).

**Пример:** Найти уникальные права доступа к файлам в текущем каталоге.
```bash
ls -l | grep -v '^total' | cut -c 2-10 | sort | uniq -c
```
**Разбор:**
1.  `ls -l`: Выводит список файлов в длинном формате.
2.  `grep -v '^total'`: Удаляет строку, начинающуюся со слова "total" (которая не является файлом).
3.  `cut -c 2-10`: Вырезает символы со 2-го по 10-й, что соответствует столбцу прав доступа.
4.  `sort`: Сортирует полученные строки.
5.  `uniq -c`: Подсчитывает количество уникальных строк (уникальных наборов прав).

**Пример:** Получить полную информацию о каждом пользователе из `/etc/passwd`.
```bash
awk -F: '{print $1}' /etc/passwd | while read user; do id "$user"; done
```
**Разбор:**
1.  `awk -F: '{print $1}' /etc/passwd`: Использует `awk` для извлечения первого поля (имени пользователя) из файла `/etc/passwd`, используя `:` как разделитель полей.
2.  `while read user; do id "$user"; done`: Цикл `while` читает каждое имя пользователя и передает его команде `id`, которая выводит подробную информацию о пользователе.

### Дублирование вывода с `tee`

Команда `tee` позволяет одновременно выводить данные на экран и записывать их в файл.

```bash
ls -l | tee output.txt # Выведет на экран и запишет в output.txt
ls -l | tee -a output.txt # Выведет на экран и добавит в output.txt
```

### Код возврата (`$?`)

Каждая команда после своего завершения возвращает **код возврата** (exit code) — число от 0 до 255, которое сообщает о том, как она отработала. Это основа для всей логики в shell.

-   **`0`** — команда завершилась **успешно**.
-   **Любое другое число (не `0`)** — в процессе выполнения произошла **ошибка**.

Узнать код возврата последней выполненной команды можно с помощью специальной переменной `$?`.

```bash
# Выполняем успешную команду
ls /etc/hosts
# /etc/hosts

# Проверяем код возврата
echo $?
# 0

# Выполняем команду с ошибкой
ls /не/существует
# ls: cannot access '/не/существует': No such file or directory

# Проверяем код возврата
echo $?
# 2 (или другое ненулевое значение в зависимости от системы и типа ошибки)
```

**Важно:** Переменная `$?` хранит код возврата только **самой последней** команды. Сразу после `echo $?` ее значение станет `0`, так как сама команда `echo` выполнилась успешно.

Если вам нужно использовать код возврата более поздней команды, сохраните его в отдельную переменную:
```bash
ls /не/существует
LAST_EXIT_CODE=$?
echo "Код возврата предыдущей команды: $LAST_EXIT_CODE"
echo "Текущий код возврата (от echo): $?"
```

## Перенаправление ввода/вывода

### Перенаправление стандартного вывода (`>` и `>>`)
*   `>`: Перенаправляет `stdout` команды в файл, **перезаписывая** его содержимое, если файл существует. Если файла нет, он будет создан.
*   `>>`: Перенаправляет `stdout` команды в файл, **добавляя** содержимое в конец файла. Если файла нет, он будет создан.

**Пример:** `ls -l > output.txt`
1.  Оболочка видит `> output.txt`.
2.  Она немедленно пытается открыть `output.txt` для записи. Если нет прав, выдаст ошибку.
3.  Если права есть, она **очищает файл** `output.txt` (или создает его).
4.  Только после этого запускается команда `ls -l`, чей `stdout` уже направлен в `output.txt`.

### Перенаправление стандартного вывода ошибок (`2>`)
*   Для перенаправления `stderr` необходимо явно указать файловый дескриптор `2`.
*   **Пример:** `ls /nonexistent 2> errors.log` — ошибки `ls` будут записаны в `errors.log`.

### Объединение потоков (`2>&1` и `&>`)
*   `2>&1`: Перенаправляет `stderr` (дескриптор 2) туда же, куда направлен `stdout` (дескриптор 1). Порядок важен: `> file 2>&1` сначала перенаправит `stdout` в `file`, а затем `stderr` туда же. Если написать `2>&1 > file`, то `stderr` будет направлен туда, куда `stdout` был направлен *до* перенаправления в `file`.
*   `&>`: Сокращенная форма для перенаправления `stdout` и `stderr` в один и тот же файл. `command &> file` эквивалентно `command > file 2>&1`.

### Перенаправление стандартного ввода (`<`)
*   `command < input.txt`: Команда будет читать свой `stdin` из файла `input.txt`.

### Особый файл `/dev/null`
*   `/dev/null` — это специальный "пустой" файл в Unix-подобных системах, который действует как "черная дыра". Все, что в него записывается, исчезает, а при чтении из него не возвращается ничего.
*   Часто используется для подавления нежелательного вывода: `command > /dev/null 2>&1` (подавить весь вывод).

### Критический порядок интерпретации перенаправлений (проблема `grep file > file`)
*   **Важно:** Перенаправления (`>`) обрабатываются оболочкой **до** выполнения самой команды. Командная оболочка интерпретирует команду как бы "справа налево": сначала настраивается перенаправление, и только потом выполняется основная команда. Это может привести к необратимой потере данных, если входной и выходной файл совпадают.
*   **Пример фатальной ошибки:** `grep "pattern" a.txt > a.txt`
    1.  Оболочка считывает всю командную строку.
    2.  Она видит оператор перенаправления `> a.txt` и **немедленно приступает к его обработке**.
    3.  Если файл `a.txt` существует, он **обнуляется (очищается)**. Если не существует, создается пустой файл.
    4.  Только после этого запускается команда `grep "pattern" a.txt`. Но поскольку `a.txt` уже пуст, `grep` не находит данных для чтения.
    5.  В результате `a.txt` становится пустым.
*   **Решение:** Чтобы избежать такой потери данных, используйте временный файл или утилиты, которые поддерживают редактирование "на месте".
    ```bash
    # 1. Использование временного файла (самый надежный способ)
    grep "pattern" a.txt > a.tmp && mv a.tmp a.txt

    # 2. Использование `sponge` (из пакета moreutils)
    # sponge "впитывает" весь ввод и только потом записывает его в файл
    grep "pattern" a.txt | sponge a.txt

    # 3. Использование sed для редактирования на месте
    sed -i '/pattern/d' a.txt # Удалит строки, НЕ содержащие pattern
    ```

### Расширенная таблица-шпаргалка операторов

| Оператор | Тип | Порядок выполнения | Пример |
| :--- | :--- | :--- | :--- |
| `|` | Конвейер | **Одновременный** запуск. Данные текут слева направо. | `cat file \| grep word` |
| `&&` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая успешна. | `mkdir d && cd d` |
| `||` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая провалилась. | `ping host \|\| echo 'down'` |
| `;` | Управляющий | **Последовательный**. Вторая команда выполняется всегда. | `cmd1 ; cmd2` |
| `&` | Управляющий | Запускает команду в **фоновом режиме**. | `sleep 10 &` |
| `>` `>>` `<` | Перенаправление | **Настраивается оболочкой до запуска команды.** | `ls > file.txt` |
| `$(...)` | Подстановка | Выполняется **до** основной команды. Результат подставляется как аргумент. | `rm $(find . -name "*.tmp")` |
| `<(...)` | Подстановка | Выполняется **одновременно** с основной командой, результат виден как файл. | `diff <(sort f1) <(sort f2)` |
| `( ... )` | Группировка | Команды выполняются в **дочерней оболочке (subshell)**. | `(cd /tmp && pwd)` |
| `{ ...; }` | Группировка | Команды выполняются в **текущей оболочке**. | `{ cd /tmp; pwd; }` |

## grep

`grep` (global regular expression print) — одна из самых мощных и часто используемых утилит для поиска текста в файлах или в потоке данных с использованием регулярных выражений.

**Основные ключи:**
-   `-i`: Игнорировать регистр.
-   `-v`: Инвертировать поиск (вывести строки, которые **не** содержат шаблон).
-   `-r` или `-R`: Рекурсивный поиск по всем файлам в директории.
-   `-l`: Вывести только имена файлов, содержащих шаблон.
-   `-c`: Посчитать количество строк, содержащих шаблон.
-   `-n`: Показать номера строк.
-   `-E`: Использовать расширенные регулярные выражения (ERE).
-   `-A <N>`: Показать N строк **после** совпадения.
-   `-B <N>`: Показать N строк **до** совпадения.
-   `-C <N>`: Показать N строк **вокруг** совпадения.

**Примеры:**
```bash
# Найти всех пользователей с оболочкой /bin/bash
grep "/bin/bash" /etc/passwd

# Найти слово "error" в логах, игнорируя регистр
grep -i "error" /var/log/syslog

# Найти все файлы в текущей директории, содержащие "TODO"
grep -r -l "TODO" .
```

## Bash-скрипты: Основы

**Bash-скрипт** — это текстовый файл, содержащий последовательность команд, которые выполняются командным интерпретатором Bash.

### Shabang (`#!`) и исполняемый файл

Чтобы запускать скрипт напрямую (как `./my_script.sh`), необходимо сделать две вещи:

1.  **Установить права на исполнение:**
    ```bash
    chmod +x my_script.sh
    ```

2.  **Указать интерпретатор с помощью "shabang":**
    **Shabang** — это конструкция `#!` в первой строке файла, которая указывает ОС, какой интерпретатор использовать.

    -   `#!/bin/bash` — Жестко указывает путь к `bash`.
    -   `#!/usr/bin/env bash` — **Предпочтительный вариант**. Ищет `bash` в `$PATH`, что делает скрипт более переносимым.

    **Пример (`my_script.sh`):**
    ```bash
    #!/usr/bin/env bash
    echo "Этот скрипт выполняется с помощью bash!"
    ```
    Теперь его можно запустить: `./my_script.sh`

### Позиционные параметры и специальные переменные

*   `$0`: Имя самого скрипта.
*   `$1`, `$2`, ...: Аргументы, переданные скрипту.
*   `$#`: Количество переданных аргументов.
*   `$@`: Все аргументы как отдельные строки (безопасный способ для итерации).
*   `$*`: Все аргументы как одна строка.
*   `$?`: Код возврата последней выполненной команды.
*   `$$`: PID (идентификатор процесса) текущего скрипта.
*   `$!`: PID последнего запущенного фонового процесса.

### Управляющие конструкции

#### Условные операторы: `if`, `else`, `elif`
```bash
if [[ "$USER" == "root" ]]; then
    echo "Вы - root."
elif [[ -f "/etc/hosts" ]]; then
    echo "Файл /etc/hosts существует."
else
    echo "Что-то другое."
fi
```
- Используйте `[[ ... ]]` вместо `[ ... ]` в Bash для большей надежности и функциональности.
- **Проверка файлов:** `-f` (файл), `-d` (директория), `-e` (существует).
- **Сравнение строк:** `==`, `!=`.
- **Сравнение чисел:** `-eq` (равно), `-ne` (не равно), `-gt` (больше), `-lt` (меньше).

#### Циклы: `for`, `while`
```bash
# Цикл for
for i in {1..3}; do
    echo "Номер: $i"
done

# Цикл while
count=0
while [ $count -lt 3 ]; do
    echo "Счетчик: $count"
    count=$((count + 1))
done
```

### Выполнение скриптов: `source` vs. subshell

1.  **Запуск в дочерней оболочке (`./script.sh`)**
    -   **Механизм:** Создается **новый дочерний процесс (subshell)**, в котором выполняются команды.
    -   **Эффект:** Изменения окружения (переменные, `cd`) **не влияют** на родительскую оболочку. Это безопасный способ запуска по умолчанию.

2.  **Выполнение в текущей оболочке (`source script.sh` или `. script.sh`)**
    -   **Механизм:** Команды выполняются **в контексте текущей оболочки**.
    -   **Эффект:** Все изменения окружения **сохраняются** в вашей сессии.
    -   **Применение:** Используется для загрузки конфигурационных файлов или активации виртуальных окружений (например, `source venv/bin/activate`).
