# Навигация по файловой системе: cd, pwd

## Определения

- **pwd (Print Working Directory)** — команда вывода полного абсолютного пути текущей рабочей директории от корня системы (`/`). Существует как встроенная команда оболочки и как внешняя утилита (`/usr/bin/pwd`).
- **cd (Change Directory)** — встроенная команда оболочки для перемещения между директориями.
- **Абсолютный путь** — полный путь от корня файловой системы (начинается с `/`).
- **Относительный путь** — путь относительно текущей рабочей директории. Может начинаться с имени директории или специальных символов (`.`, `..`).
- **Домашняя директория** — личная папка пользователя (`/home/<username>` для обычных пользователей, `/root` для root), обозначается тильдой (`~`).
- **OLDPWD** — переменная окружения, хранящая путь предыдущей рабочей директории.
- **PWD** — переменная окружения, хранящая путь текущей рабочей директории. Поддерживается большинством современных оболочек (Bash, Zsh, Ksh).

> **Важно:** `cd` — встроенная команда оболочки (built-in), а не внешняя утилита. Она выполняется в том же процессе Shell, поэтому может изменить рабочую директорию текущей сессии. Внешние команды (например, `ls`, `grep`) запускаются как отдельные процессы и не могут изменить состояние вызывающей оболочки. Подробнее о приоритете built-ins и внешних команд: [Введение в командную строку](./shell_intro.md).

## Базовые концепции

### Структура файловой системы Linux и FHS

В Linux нет аналога дисков `C:\` как в Windows. Файловая система представляет собой единое дерево с корнем `/`. Стандартная иерархия описывается в FHS (Filesystem Hierarchy Standard), что критично для SRE и Sysadmin при навигации по production-серверам:

```
/                    ← Корень системы (аналог C: в Windows)
├── bin/              ← Основные исполняемые файлы (cp, ls, bash)
├── sbin/             ← Системные исполняемые файлы (ifconfig, fdisk)
├── etc/              ← Конфигурационные файлы всего системы (критично для SRE)
├── var/
│   ├── log/          ← Логи сервисов, ядра и приложений (первое место при Troubleshooting)
│   ├── tmp/          ← Временные файлы, очищаемые при перезагрузке
│   └── lib/          ← Переменные данные библиотек и состояния сервисов
├── run/              ← Volatile runtime data (PID-файлы, sockets). Начиная с systemd, /var/run → /run
├── tmp/              ← Временные файлы, НЕ очищаемые при перезагрузке
├── home/             ← Домашние директории пользователей
│   └── user/         ← Домашняя директория пользователя (~)
├── root/             ← Домашняя директория суперпользователя
├── dev/              ← Файлы устройств
├── proc/             ← Виртуальная файловая система процессов ядра
├── sys/              ← Виртуальная файловая система устройств и драйверов
└── ...
```

**SRE-заметка:** При диагностике инцидентов 80% операций навигации происходит в `/etc`, `/var/log` и `/run`. Умение быстро перемещаться между этими директориями — базовый навык.

### Специальные обозначения путей

| Символ | Значение | Пример |
| :--- | :--- | :--- |
| `.` | Текущая директория (dentry-запись текущего каталога) | `cd .` — остаться на месте |
| `..` | Родительская директория (уровень выше) | `cd ..` |
| `/` | Корень файловой системы | `cd /` |
| `~` | Домашняя директория текущего пользователя | `cd ~` или `cd` |
| `~+` | Текущая рабочая директория (эквивалент `$PWD`) | `cd ~+` |
| `~-` | Предыдущая рабочая директория (эквивалент `$OLDPWD`) | `cd ~-` |
| `-` | Предыдущая директория (OLDPWD) | `cd -` |

> **Техническое уточнение:** `.` и `..` — это не просто текстовые ярлыки, а dentry (directory entry) в файловой системе. Их существование гарантировано стандартом POSIX. Каждый каталог содержит как минимум две записи: `.` (ссылка на себя) и `..` (ссылка на родителя). Это позволяет обходить файловую систему без знания абсолютных путей.

## Практические сценарии

### Определение текущего местоположения

```bash
pwd
# → /home/user/projects/ansible
```

**Когда использовать:** При потере ориентации в файловой системе после множества переходов, при копировании пути для документации, при отладке скриптов для проверки рабочего каталога. В Bash `pwd` — built-in, который читает значение переменной `$PWD`. Внешний `/usr/bin/pwd` всегда запрашивает реальный путь у ядра через системный вызов `getcwd()`.

### Перемещение в родительскую директорию

```bash
pwd
# → /home/user/projects/ansible

cd ..

pwd
# → /home/user/projects
```

**Экзамен LPIC-1:** `cd ..` — правильный ответ для поднятия на один уровень вверх. Другие варианты: `.` (текущая), `/` (корень), `~` (домой).

### Переход в корень системы

```bash
cd /

pwd
# → /
```

### Возврат в домашнюю директорию

Три эквивалентных способа:

```bash
# Способ 1: Тильда
cd ~

# Способ 2: Без аргументов (рекомендуется)
cd

# Способ 3: Через переменную окружения
cd $HOME
```

**Различие между `cd` и `cd ~`:**
- В большинстве случаев идентичны.
- При установке пользовательской оболочки, отличной от стандартной, `cd ~` может использовать другой механизм подстановки (например, в Zsh тильда раскрывается иначе при именованных директориях).

### Переход в предыдущую директорию

```bash
pwd
# → /home/user/projects

cd /etc/systemd

pwd
# → /etc/systemd

cd -

# → /home/user/projects
# Вывод: оболочка печатает новый путь при переходе
```

**Механизм:** Команда `cd -` использует переменную окружения `OLDPWD` (предыдущая директория). Эквивалентно `cd "$OLDPWD"`.

### Переход в конкретную директорию

```bash
# Абсолютный путь (от корня)
cd /var/log

# Относительный путь (от текущей директории)
cd ../tmp

# Составной путь
cd /home/user/projects/ansible/roles/webserver
```

## Расширенные команды навигации

### Стек директорий: pushd, popd, dirs

В Bash и Zsh доступны команды для работы со стеком директорий. Это значительно ускоряет работу при необходимости频繁 переключаться между несколькими местами:

```bash
# Показать текущий стек директорий
dirs
# → /home/user/projects ~/scripts /etc/nginx

# Добавить директорию в стек и перейти в неё
pushd /var/log/nginx

# Вернуться в предыдущую директорию из стека
popd

# Очистить весь стек (оставить только текущую директорию)
dirs -c
```

**SRE-сценарий:** Диагностика nginx требует переключения между `/etc/nginx`, `/var/log/nginx` и `/run`. Вместо ручного `cd` используйте `pushd`:

```bash
pushd /etc/nginx && nginx -t
pushd /var/log/nginx && tail -n 50 error.log
popd
popd
```

**Эквивалент:** `pushd +N` — перейти к N-ному элементу стека, `pushd -N` — заменить текущую директорию на N-ную.

### CDPATH — автоматический поиск директорий

Переменная `CDPATH` задаёт список директорий, в которых `cd` будет искать целевой каталог (аналогично `$PATH` для исполняемых файлов):

```bash
# Добавить /srv и /opt/app в поиск
export CDPATH=.:~/projects:/srv:/opt/app

# Теперь cd ищет 'configs' в CDPATH
cd configs
# Переходит в /srv/configs, если такая директория существует
```

**Важно:** Если `CDPATH` установлен, `cd` по умолчанию выводит полный путь перехода. Используйте `cd -q` для тихого режима (Bash 4+).

## Физические и логические пути (cd -P / cd -L / pwd -P / pwd -L)

### Проблема симлинков

В Linux симлинки (symbolic links) часто используются для организации совместимости и гибкости:

```bash
/var/run → /run
/etc/alternatives/awk → /usr/bin/gawk
/usr/bin/python → /usr/bin/python3.9
```

### Режимы навигации

- **Логический режим (по умолчанию, `cd -L`):** `cd` и `pwd` используют путь с учётом симлинков, как его видит оболочка в `$PWD`.
- **Физический режим (`cd -P`):** `cd` и `pwd` всегда разрешают симлинки и выводят реальный физический путь.

```bash
# Демонстрация разницы
cd /var/run
pwd
# → /var/run    (логический)

cd -P .
pwd
# → /run        (физический, реальный путь)
```

**SRE-важность:** В скриптах, работающих с `/var/run`, `/run` или `/etc/alternatives`, всегда используйте `pwd -P` или `cd -P`, чтобы избежать путаницы с неразрешёнными путями.

### Опции pwd

```bash
pwd -L
# Логический путь (значение $PWD)

pwd -P
# Физический путь (разрешённые симлинки)

pwd
# По умолчанию соответствует опции логического режима в Bash
```

## Встроенная и внешняя версия pwd

`pwd` существует в двух формах:

- **Built-in (оболочка):** Читает `$PWD`, не делает системных вызовов. Быстрее, но может возвращать логический путь с неразрешёнными симлинками.
- **Внешняя утилита (`/usr/bin/pwd`):** Вызывает `getcwd()` ядра, возвращает физический путь. Гарантированно точна, но медленнее на глубоких путях.

```bash
# Принудительно вызвать внешнюю версию
/usr/bin/pwd -P

# Проверить, какая версия используется
type pwd
# → pwd is a shell builtin
```

## Особенности и ограничения

### cd в неинтерактивных сессиях

Перемещение через `cd` в скриптах или конвейерах имеет особенности:

```bash
# НЕПРАВИЛЬНО: cd в дочернем процессе не влияет на родительский
cd /etc && ls        # ls выполнится в /etc, но следующая команда — в старом месте

find . -name "*.conf" -exec cd {} \;  # Бесполезно: cd в subshell

# ПРАВИЛЬНО: для скриптов используйте явные пути
for conf in /etc/*.conf; do
    echo "$conf"
done
```

### cd при sudo и смене пользователя

```bash
# sudo cd /root
# → sudo: cd: command not found
# cd — builtin, он не передаётся в sudo

# Правильный способ
sudo -s
cd /root

# Или через обёртку
sudo bash -c 'cd /root && whoami'
```

**Причина:** `sudo` ищет исполняемый файл в `$PATH`, но built-in команды не существуют как файлы. Поэтому `sudo cd` невозможен напрямую.

### Типичные ошибки

1. **Забытый пробел:** `cd..` вместо `cd ..` — оболочка ищет команду `cd..`, которой нет.

2. **cd в подпроцессе:**
   ```bash
   # Ошибка: cd выполнится в subshell, родительская оболочка не переместится
   (cd /tmp && rm -rf *)
   
   # После выполнения вы останетесь в исходной директории
   ```

3. **Прав доступа:** `cd` требует права выполнения (`x`) на все родительские директории целевого пути.

   ```bash
   cd /root
   # → bash: cd: /root: Permission denied
   ```

4. **Несуществующий путь:**
   ```bash
   cd /nonexistent
   # → bash: cd: /nonexistent: No such file or directory
   ```

5. **Нулевой байт в пути (Bash < 5.1):** Пути, содержащие NUL-байт, не поддерживаются. В Bash 5.1+ добавлена поддержка NUL-символов в аргументах.

6. **Переменная $PWD несогласована:** Если директория перемещена или переименована внешним процессом, `$PWD` может содержать устаревший логический путь. В этом случае `pwd -P` возвращает актуальный физический путь.

### Переменные окружения, связанные с навигацией

| Переменная | Описание | Использование |
| :--- | :--- | :--- |
| `PWD` | Текущая рабочая директория (логический путь) | `echo $PWD` — аналог `pwd` |
| `OLDPWD` | Предыдущая директория | `cd -` использует эту переменную |
| `HOME` | Домашняя директория | `cd $HOME` ≡ `cd ~` |
| `CDPATH` | Список директорий для автоматического поиска при `cd` | `export CDPATH=.:/srv:/opt/app` |
| `PWD -P` | Не переменная, но физический путь | `cd -P .` для обновления PWD до физического |

## Практические сценарии для DevOps, SRE и Sysadmin

### Навигация по стандартным директориям сервисов

Работа с конфигурациями и логами — ежедневная операция:

```bash
# Быстрый переход к конфигам и логам nginx
cd /etc/nginx
cd ../log/nginx

# Логи systemd
cd /var/log/syslog
cd /run/log/journal

# Volatile runtime data (PID, sockets)
cd /run
cd /run/systemd
cd /run/user/1000   # Директория пользовательских сервисов
```

### Использование $PWD в скриптах автоматизации

`$PWD` позволяет создавать воспроизводимые скрипты, не зависящие от абсолютных путей:

```bash
#!/bin/bash
# backup_configs.sh — пример резервного копирования из текущего проекта

TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="$PWD/backups"
CONFIG_SRC="$PWD/configs"

mkdir -p "$BACKUP_DIR"
tar -czf "$BACKUP_DIR/config_$TIMESTAMP.tar.gz" -C "$CONFIG_SRC" .

echo "Резервная копия создана в $BACKUP_DIR"
```

**Ansible-сценарий:** Использование `{{ playbook_dir }}` аналогично `$PWD`:

```yaml
- name: Копирование конфигураций из директории плейбука
  copy:
    src: "{{ playbook_dir }}/nginx/conf.d/"
    dest: /etc/nginx/conf.d/
    owner: root
    mode: '0644'
```

### Диагностика и разрешение проблем с путями

```bash
# Визуализировать все компоненты пути и права
namei -l /var/log/nginx/access.log
# drwxr-xr-x root root /
# drwxr-xr-x root root var
# drwxr-xr-x root root log
# drwxr-x--- adm   adm  nginx
# -rw-r----- adm   adm  access.log

# Получить физический абсолютный путь с разрешением симлинков
readlink -f /var/run/nginx.pid
# → /run/nginx.pid

# Проверить, является ли путь симлинком
file /var/run
# /var/run: symbolic link to /run

# Найти тип файловой системы для директории
df -T /var/log
```

### Работа в chroot, container и rescue environment

При работе в изолированных окружениях структура файловой системы может отличаться:

```bash
# Вход в chroot для восстановления системы
mount /dev/sda1 /mnt
chroot /mnt /bin/bash
pwd
# → /
# Корень теперь указывает на /mnt хостовой системы

# Внутри контейнера Docker (обычно /)
docker exec -it web bash
pwd
# → /

# Проверка текущего контекста файловой системы через /proc
cat /proc/1/root/cwd
# → /app (рабочая директория PID 1)
```

## Best Practices

1. **Используйте абсолютные пути в скриптах.** Относительные пути (`../configs`) ломаются при запуске скрипта из другого каталога. `cd` в скрипте должен быть точечным и явным.
2. **Разрешайте симлинки в production-скриптах.** Используйте `cd -P` или `pwd -P` для получения физического пути. Это исключает ошибки при работе с `/var/run`, `/run`, `/etc/alternatives`.
3. **Проверяйте доступность директории перед переходом.** В Bash 5+ доступен `cd -- "$dir"` для защиты от путей, начинающихся с дефиса.
4. **Не полагайтесь на `cd` в subshell.** Если необходимо выполнить последовательность команд в другой директории, используйте группировку `( cd /dir && cmd1 && cmd2 )` или явные пути.
5. **Логируйте `$PWD` в критичных скриптах.** При Troubleshooting знать, из какой директории был запущен скрипт, часто решает проблему.
6. **Используйте `pushd`/`popd` при частых переключениях.** Это снижает количество опечаток и позволяет возвращаться на несколько шагов назад через стек.
7. **Настройте `CDPATH` для частых директорий.** Ускорьте переход в `/srv/app`, `/var/log/nginx` через короткие имена.

## Диагностика и устранение проблем

### Проверка типа команды и разрешения

```bash
type cd
# → cd is a shell builtin

type pwd
# → pwd is a shell builtin
# → pwd is /usr/bin/pwd (в Zsh или при disable builtin)

# Проверить, не переопределена ли команда псевдонимом
alias cd
# → alias cd='cd --some-option' (если есть псевдоним)

# Вызвать оригинальную встроенную команду
\cd /path    # или builtin cd /path
```

### Проверка доступности директории

```bash
# Проверить существование и права
test -d /etc/nginx && echo "OK" || echo "MISSING"
# → OK

# Проверить execute bit на всех родителях
namei -l /etc/nginx/nginx.conf
```

### Разрешение конфликтов с симлинками

```bash
# Если PWD "застрял" на удалённом/переименованном симлинке
cd -P .
pwd
# → /real/path

# Принудительно обновить PWD без смены директории
cd . && pwd
```

### Определение реального пути текущей директории

```bash
# Способ 1: pwd -P
pwd -P

# Способ 2: readlink -f (работает из любой директории)
readlink -f .

# Способ 3: через /proc (Linux)
readlink /proc/self/cwd
```

## Экзамен LPIC-1 (103.1)

Топик 103.1 силлибуса LPIC-1 ("Архитектура системы Linux") требует понимания специальных обозначений путей и поведения команды `cd` без аргументов.

### Типичный экзаменационный вопрос

> **Вопрос:** Какой командой вернуться в домашнюю директорию из любого места файловой системы?

**Варианты ответа:**
- A. `cd .` — остаётся в текущей директории.
- B. `cd ..` — поднимается на один уровень вверх (родительская директория).
- C. `cd ~` — возвращается в домашнюю директорию текущего пользователя.
- D. `cd /` — переходит в корень файловой системы.

**Правильный ответ:** C (`cd ~`)

**Разбор вариантов:**
- **A (`cd .`)**: Точка (`.`) — это специальная запись dentry, указывающая на текущий каталог. Команда `cd .` не изменяет рабочую директорию.
- **B (`cd ..`)**: Две точки (`..`) указывают на родительский каталог. Используется для подъёма на один уровень вверх, а не для возврата домой.
- **C (`cd ~`)**: Тильда (`~`) — ярлык домашней директории текущего пользователя. `cd ~` и `cd` (без аргументов) являются эквивалентными способами вернуться домой.
- **D (`cd /`)**: Один слеш (`/`) — это корень файловой системы. Используется для перехода в корень, а не в домашнюю директорию.

### Дополнительные проверки на экзамене

- `cd` без аргументов — кратчайший способ вернуться в домашнюю директорию. Эквивалентно `cd ~` и `cd $HOME`.
- Команда `cd` — встроенная команда оболочки (built-in), поэтому она изменяет рабочую директорию текущей сессии. Внешние команды не могут этого сделать.
- Переменная окружения `HOME` хранит путь к домашней директории. `echo $HOME` покажет тот же путь, что и `cd ~`.
- `cd -` возвращает в предыдущую директорию и меняет `OLDPWD` местами с `PWD`.
- Текущая директория (`.`) и родительская (`..`) входят в каждый каталог по определению POSIX.
