# Команда ls — листинг файлов и скрытые объекты файловой системы

## Определения

- **ls** (list) — стандартная утилита POSIX для вывода списка файлов и каталогов. Входит в состав пакета GNU coreutils. Является внешней командой (external), исполняемый файл находится в `/usr/bin/ls`.
- **Dotfile** — файл или каталог, имя которого начинается с символа точки (`.`). В Linux отсутствует отдельный атрибут "скрытый" (hidden) как в NTFS; скрытие реализуется исключительно через соглашение об именовании.
- **Скрытый файл** — любой объект ФС, имя которого начинается с точки. Обычный режим `ls` пропускает такие объекты, что создаёт эффект невидимости.
- **Текущий каталог (`.`)**: специальная запись dentry (directory entry), являющаяся жёсткой ссылкой (hard link) на inode самого каталога.
- **Родительский каталог (`..`)**: специальная запись dentry, указывающая на inode родительского каталога в иерархии ФС.
- **Длинный формат (long format)** — режим вывода `ls -l`, отображающий метаданные: тип файла, права доступа, количество жёстких ссылок, владельца, группу, размер, временные метки и имя.

## Базовые концепции

### Механизм скрытия файлов в Linux

В Windows скрытие файла определяется атрибутом `FILE_ATTRIBUTE_HIDDEN` в записи NTFS. В Linux такого атрибута на уровне inode не существует. Скрытие файлов — это исключительно соглашение пользовательского пространства:

1. Имена файлов, начинающиеся с `.`, не выводятся обычным `ls`.
2. Оболочки (bash, zsh, fish) при подстановке имён (`*`, `?`) по умолчанию игнорируют dotfiles, если не задан флаг `dotglob` (bash) или соответствующих опций (zsh).
3. Утилита `ls` определяет, является ли файл "скрытым", проверяя первый символ имени через системный вызов `getdents64()`.

Это соглашение используется для конфигурационных файлов (`.bashrc`, `.gitconfig`, `.env`) и служебных каталогов (`.git`, `.ssh`, `.config`).

### Специальные записи каталога (`.` и `..`)

Каждый каталог в Linux содержит как минимум две записи, создаваемые автоматически ядром или `mkdir`:

| Запись | Назначение | Inode | Жёстких ссылок |
| :--- | :--- | :--- | :--- |
| `.` | Текущий каталог | Совпадает с inode каталога | `+1` к ссылкам каталога |
| `..` | Родительский каталог | Inode родителя | `+1` к ссылкам родителя |

Эти записи существуют физически в данных каталога и видны команде `ls -la`. Их наличие позволяет реализовать относительные пути (`cd ..`, `./script.sh`) и определять глубину вложенности каталогов.

### Ключевые флаги команды ls

#### Флаги видимости

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-a` | `--all` | Показывать все файлы, включая dotfiles, а также записи `.` и `..`. |
| `-A` | `--almost-all` | Показывать все файлы, кроме `.` и `..`. Полезно для подсчёта реального содержимого каталога. |
| `-d` | `--directory` | Показывать информацию о самом каталоге, а не его содержимом. |

#### Флаги формата вывода

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-l` | `--format=long` | Длинный формат: тип, права, ссылки, владелец, группа, размер, время, имя. |
| `-h` | `--human-readable` | Отображать размеры в человекочитаемом формате (КиБ, МиБ, ГиБ, ТиБ). Работает только с `-l` или `-s`. |
| `-s` | `--size` | Выводить размер в блоках по 1 КиБ перед каждым элементом. |
| `-1` | | Выводить по одному элементу на строку (полезно для конвейеров). |

#### Флаги сортировки

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-t` | `--sort=time` | Сортировка по времени модификации (mtime), от новых к старым. |
| `-S` | `--sort=size` | Сортировка по размеру, от большего к меньшему. |
| `-X` | `--sort=extension` | Сортировка по расширению файла (алфавитная). |
| `-U` | `--sort=none` | Без сортировки, в порядке, возвращаемом ФС (быстрее на больших каталогах). |
| `-r` | `--reverse` | Обратный порядок сортировки (от старых к новым, от меньшего к большему). |

#### Флаги рекурсии и обхода

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-R` | `--recursive` | Рекурсивный обход всех подкаталогов. |
| `-F` | `--classify` | Добавлять символ-индикатор (`/` для каталогов, `*` для исполняемых, `@` для символических ссылок, `=` для сокетов). |

### Формат длинного вывода (`ls -l`)

Каждая строка вывода `ls -l` содержит следующие поля:

```text
drwxr-xr-x 5 user group 4096 Aug 29 12:00 directory
```

| Поле | Пример | Описание |
| :--- | :--- | :--- |
| Тип и права | `drwxr-xr-x` | 1-й символ: тип (`d` — каталог, `-` — файл, `l` — ссылка, `c`/`b` — устройство, `s` — сокет, `p` — канал). Далее 9 символов: права владельца, группы, остальных. |
| Ссылки | `5` | Количество жёстких ссылок на inode. Для каталога = 2 + количество подкаталогов. |
| Владелец | `user` | Имя пользователя-владельца (из `/etc/passwd`). |
| Группа | `group` | Имя группы-владельца (из `/etc/group`). |
| Размер | `4096` | Размер в байтах. Для каталогов — размер записи dentry (обычно 4096). |
| Время | `Aug 29 12:00` | Время последней модификации (mtime). Для старых файлов показывается год. |
| Имя | `directory` | Имя файла или каталога. |

### Размеры: байты против человекочитаемого формата

По умолчанию `ls -l` выводит размер в байтах. Флаг `-h` (`--human-readable`) преобразует вывод:

```bash
ls -lh file.txt
# → -rw-r--r-- 1 user group 1.2K Aug 29 12:00 file.txt
```

Масштабирование:
- `K` = 1024 байта (КиБ)
- `M` = 1024 КиБ (МиБ)
- `G` = 1024 МиБ ( ГиБ)
- `T` = 1024 ГиБ (ТиБ)

Важно: флаг `-h` работает только в сочетании с `-l` или `-s`. Одиночный `ls -h` без этих флагов не изменит вывод.

### Отсутствующие флаги

В GNU coreutils **не существует** флага `--hidden` или `-H` для включения режима dotfiles. Распространённая ошибка на экзамене LPIC-1 — выбор варианта `ls -H`, который в GNU `ls` означает `--dereference-args` (разыменовывать символические ссылки в аргументах команды). Для отображения скрытых файлов используется исключительно `-a` или `-A`.

### Флаги метаданных и владельцев

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-g` | `--no-group` | Длинный формат, но без столбца группы (полезен при совпадении имён пользователя и группы). |
| `-o` | `--no-owner` | Длинный формат, но без столбца владельца. |
| `-n` | `--numeric-uid-gid` | Выводить числовые UID/GID вместо имён (ускоряет вывод на NFS и при отсутствии `/etc/passwd`). |
| `-i` | `--inode` | Выводить номер inode перед размером (полезно для сопоставления с `find -inum` или `stat`). |

### Флаги обработки непечатаемых символов

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-b` | `--escape` | Выводить непечатаемые символы в виде octal-последовательностей (`\012`). |
| `-q` | `--hide-control-chars` | Заменять непечатаемые символы на `?` (используется по умолчанию в интерактивных сессиях). |

### Флаги компоновки вывода

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-C` | | Выводить элементы по столбцам (вертикально), заполняя строки сверху вниз (поведение по умолчанию для TTY). |
| `-x` | `--format=across` | Выводить по столбцам, заполняя строки слева направо (удобно для широких мониторов). |
| `-m` | `--format=commas` | Выводить через запятую (полезно для генерации списков в скриптах). |
| `-1` | `--format=single-column` | Один элемент на строку (обязателен для конвейеров с `wc`, `xargs`, `while read`). |

### Флаги временных меток

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `-c` | `--time=ctime` | Сортировать/отображать по времени изменения inode (ctime). |
| `-u` | `--time=atime` | Сортировать/отображать по времени последнего доступа (atime). |
| `--time-style` | | Формат вывода времени. Пример: `--time-style=long-iso` (ISO 8601), `--time-style=+%Y-%m-%d`. |
| `--full-time` | | Выводить время в полном формате (включая секунды и наносекунды), игнорируя `--time-style`. |

### Флаги группировки и разыменования

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `--group-directories-first` | | Сначала каталоги, затем файлы (удобно для навигации). |
| `-H` | `--dereference-args` | Разыменовывать символические ссылки, указанные в командной строке. |
| `-L` | `--dereference` | При `-l` отображать информацию о целевом файле ссылки, а не о самой ссылке. |

### Цвета и индикаторы

| Флаг | Длинная форма | Описание |
| :--- | :--- | :--- |
| `--color` | | `auto` (по умолчанию в alias), `always`, `never`. В неинтерактивных сессиях alias не применяется. |
| `--indicator-style` | | `slash` (по умолчанию), `file-type`, `classify`, `none`. Управляет суффиксами `-F`. |

## Практические сценарии

### Просмотр всех файлов с полными метаданными

```bash
ls -la
# → -rw-r--r-- 1 user group 1234 Aug 29 12:00 .bashrc
# → -rw-r--r-- 1 user group  567 Aug 29 11:00 .profile
# → drwxr-xr-x 5 user group 4096 Aug 29 12:00 .
# → drwxr-xr-x 10 user group 4096 Aug 29 11:00 ..
# → -rw-r--r-- 1 user group 8901 Aug 29 10:30 document.pdf
```

Это стандартная комбинация, используемая администраторами для ежедневного обзора каталога. Она объединяет видимость всех объектов (`-a`) с детальной информацией (`-l`).

### Просмотр содержимого каталога без рекурсии

```bash
ls -ld /var/log
# → drwxr-xr-x 12 root root 4096 Aug 29 08:00 /var/log
```

Без флага `-d` команда `ls -l /var/log` вывела бы содержимое каталога. Флаг `-d` заставляет `ls` отображать метаданные самого аргумента.

### Человекочитаемые размеры с сортировкой

```bash
ls -lSh /var/log
# → -rw-r--r-- 1 root root 4.5M Aug 29 08:00 syslog
# → -rw-r--r-- 1 root root 1.2M Aug 28 08:00 auth.log
# → -rw-r--r-- 1 root root  45K Aug 27 08:00 dmesg
```

Комбинация `-lSh` (long, human-readable, sort by size) позволяет быстро найти самые большие файлы в каталоге.

### Рекурсивный обход с фильтрацией dotfiles

```bash
ls -laR ~ | grep "^\." | head -20
```

### Подсчёт только видимых файлов

```bash
ls -A1 | wc -l
# → 47
```

Флаг `-1` (единица) принудительно выводит один элемент на строку, что делает вывод пригодным для конвейера. В сочетании с `wc -l` это позволяет точнее подсчитать количество объектов, исключая `.` и `..`.

### Поиск самых старых файлов

```bash
ls -lt | tail -n 5
```

### Быстрая проверка структуры каталога

```bash
ls -laF
# → Индикаторы: / (каталог), * (исполняемый), @ (символическая ссылка)
```

### Аудит прав на критичные файлы

```bash
ls -ln /etc/passwd /etc/shadow /etc/sudoers /etc/ssh/sshd_config
# → -rw-r--r-- 1 0 0 2827 Aug 29 12:00 /etc/passwd
# → -rw-r----- 1 0 42 1234 Aug 29 12:00 /etc/shadow
```

Флаг `-n` выводит числовые UID/GID, что полезно при диагностике в контейнерах или на NFS, где локальные имена пользователей могут не совпадать с удалёнными. Проверка: права на `/etc/shadow` должны быть `0:0` (root:root) и `-rw-r-----`.

### Поиск файлов для освобождения места (дисковый квотинг)

```bash
ls -lSh /var/log | head -20
# → -rw-r----- 1 root root 4.5M Aug 29 08:00 syslog
# → -rw-r----- 1 root root 1.2M Aug 28 08:00 auth.log
```

Для системного администратора комбинация `-lSh` — первичный инструмент быстрого поиска кандидатов на ротацию или удаление. Сортировка по размеру (`-S`) ускоряет идентификацию больших файлов, а `-h` делает вывод читаемым.

### Проверка структуры каталогов сервисов

```bash
ls -la /opt/myapp/
# → drwxr-xr-x 3 app app 4096 Aug 29 10:00 .
# → drwxr-xr-x 5 app app 4096 Aug 29 09:00 ..
# → -rw-r--r-- 1 app app  512 Aug 29 10:00 app.conf
# → drwxr-xr-x 2 app app 4096 Aug 29 10:00 logs
# → -rwxr-xr-x 1 app app 8.5K Aug 29 10:00 run.sh
```

Перед запуском сервиса администратор проверяет наличие исполняемого файла (`*` при `-F`), каталога логов и конфигурации. Флаг `-la` исключает необходимость猜测 по невидимым dotfiles.

### Использование в скриптах и пайплайнах CI/CD

```bash
# Подсчёт файлов в каталоге deployment
DEPLOY_DIR="/opt/deployments/release-1.2.3"
ls -1 "$DEPLOY_DIR" | wc -l
# → 12

# Проверка наличия артефакта
if ls -1 "$DEPLOY_DIR"/*.tar.gz 1> /dev/null 2>&1; then
    echo "Артефакты найдены"
else
    echo "Артефакты отсутствуют" >&2
    exit 1
fi
```

Флаг `-1` принудительно переключает `ls` в режим одного элемента на строку, что делает вывод безопасным для `while read` и `xargs`. Без `-1` `ls` может использовать многоколоночный режим, который ломает парсинг.

### Верификация inode при расследовании проблем с файлами

```bash
ls -li /var/www/html/index.html
# → 1234567 -rw-r--r-- 1 www-data www-data 1024 Aug 29 12:00 index.html

# Сравнение с find (поиск всех жёстких ссылок на тот же inode)
find / -inum 1234567 2>/dev/null
```

При расследовании "пропавших" файлов или проверке жёстких ссылок `ls -li` (long + inode) позволяет мгновенно сопоставить inode с выводом `stat` и `find`. Владение `www-data:www-data` подтверждает корректность развёртывания веб-контента.

### Проверка символических ссылок и монтирований

```bash
ls -la /etc/nginx/sites-enabled/
# → lrwxrwxrwx 1 root root 35 Aug 29 10:00 default.conf -> /etc/nginx/sites-available/default.conf
# → lrwxrwxrwx 1 root root 31 Aug 29 10:00 api.conf -> /etc/nginx/sites-available/api.conf
```

Для SRE инженера визуальный контроль символьных ссылок в конфигурационных каталогах (Nginx, Apache, systemd, Supervisor) критичен. Символ `@` в первом столбце при `-F` или `l` в длинном формате сразу указывает на ссылку.

### Работа с NFS и сетевыми файловыми системами

```bash
ls -U /mnt/nfs/shared_dir | head -20
```

На NFS и Lustre команда `ls` может "зависнуть" на минуты при листинге каталогов с десятками тысяч файлов. Флаг `-U` (`--sort=none`) отключает сортировку и кэширование inode в памяти, снижая количество RPC-запросов. В крайних случаях используют `nfsstat -c` для диагностики задержек RPC и `ls` только после монтирования с `noac` (no attribute cache).

### Массовые операции через xargs

```bash
# Найти все файлы .log старше 30 дней и вывести их размер
find /var/log -name "*.log" -type f -mtime +30 -print0 | xargs -0 ls -lhS
```

Комбинация `find ... -print0 | xargs -0 ls -lhS` безопасно обрабатывает имена файлов с пробелами и переносами строк, сортируя результат по размеру. Это стандартный паттерн для подготовки к архивации или удалению логов.

### Проверка временных меток для аудита доступа

```bash
ls -lu /etc/crontab
# → -rw-r--r-- 1 root root 1147 Aug 25 14:30 /etc/crontab

ls -lc /etc/crontab
# → -rw-r--r-- 1 root root 1147 Aug 29 12:00 /etc/crontab
```

`-lu` показывает время последнего чтения (atime), `-lc` — время изменения inode (ctime). При аудите модификаций конфигурационных файлов `ctime` указывает, когда файл был изменён, даже если содержимое позже было возвращено к исходному состоянию.

### Диагностика: dotfiles в домашней директории

```bash
ls -la ~ | head -20
# Обычно показывает: .bashrc, .profile, .ssh/, .config/ и другие скрытые объекты
```

## Устранение неполадок

### Файл существует, но не отображается в `ls`

**Причина:** Имя начинается с точки.  
**Диагностика:**
```bash
ls -la | grep "partial_name"
```
**Решение:** Используйте `ls -la` или `ls -A` для отображения dotfiles.

### `ls -h` показывает байты вместо КиБ/МиБ

**Причина:** Устаревшая версия GNU coreutils (< 7.0) или использование `-h` без `-l`/`-s`.  
**Диагностика:**
```bash
ls --version
ls -lh /etc/passwd
```
**Решение:** В современных системах (Debian 11+, RHEL 8+, Ubuntu 20.04+) `-h` работает корректно. Убедитесь, что флаг используется с `-l`.

### `ls -L` не показывает скрытые файлы

**Причина:** Флаг `-L` (`--dereference`) в GNU `ls` означает разыменование символических ссылок, а не "длинный формат". Это распространённая путаница с `-l` (lowercase L).  
**Решение:** Для длинного формата используйте `ls -l`. Для скрытых файлов добавьте `-a`: `ls -la`.

### Нет вывода `.` и `..` при `ls -a`

**Причина:** Используется `ls -A` (`--almost-all`), который сознательно исключает `.` и `..`.  
**Решение:** Используйте `ls -a` для полного вывода со специальными записями.

### Медленный вывод `ls` в больших каталогах

**Причина:** `ls` по умолчанию проверяет права доступа и запрашивает информацию через `stat()` для каждого файла, что медленно на сетевых ФС (NFS) или при большом количестве файлов.  
**Решение:**
```bash
ls -U /mnt/nfs/large_dir
```
Флаг `-U` (`--sort=none`) отключает сортировку и ускоряет вывод, так как `ls` не сохраняет и не сортирует список файлов в памяти.

### NFS: `ls` показывает `stale file handle` или зависает

**Причина:** NFS-сервер недоступен или экспорт переэкспортирован. Ядро кэширует дескрипторы файлов (file handles), которые становятся невалидными после перезагрузки сервера или изменения экспорта.  
**Диагностика:**
```bash
ls /mnt/nfs/share
# → ls: cannot access '/mnt/nfs/share': Stale file handle

nfsstat -c
showmount -e nfs-server
```
**Решение:**
1. Перемонтировать экспорт: `umount /mnt/nfs/share && mount /mnt/nfs/share`.
2. Проверить `/etc/exports` на сервере и наличие подписки в `/etc/fstab` (используйте `noac` только при debugging; в продакшене это снижает производительность).
3. При частых `stale` — проверьте сетевые перебои или асинхронность записи на сервере.

### `ls` показывает `?` или некорректные имена файлов

**Причина:** Имена файлов содержат байты, не валидные для текущей локали (например, UTF-8 vs ISO-8859-1), или являются бинарными мусорными именами.  
**Диагностика:**
```bash
ls -b /path/to/dir
# → \000\001\002  (octal escape)
```
**Решение:** Переименовать файл с использованием корректной кодировки или удалить, если это артефакт повреждения ФС. Для просмотра raw-байт используйте `hexdump -C`.

### Несовпадение `ls` и `find` по размеру

**Причина:** Разные единицы измерения. `ls -l` показывает размер в байтах, а `find -size` по умолчанию использует блоки по 512 байт.  
**Диагностика:**
```bash
ls -l file.bin
# → -rw-r--r-- 1 root root 1536 Aug 29 12:00 file.bin

find . -name "file.bin" -size 1536c
# → ./file.bin
```
**Решение:** В `find` используйте суффикс `c` (bytes), `k` (KiB), `M` (MiB), `G` (GiB) для единообразия: `find / -size +100M`.

### `ls` показывает неверного владельца на NFS

**Причина:** ID-маппинг (ID mapping) NFS. Сервер отправляет UID/GID, а клиент преобразует их в имена через `/etc/passwd`. Если локального пользователя с таким UID нет, отображается числовой UID.  
**Диагностика:**
```bash
ls -ln /mnt/nfs/share
# → -rw-r--r-- 1 1050 100 4096 Aug 29 12:00 remote_file
```
**Решение:** Создать локального пользователя с соответствующим UID (`useradd -u 1050 remoteuser`) или настроить `idmapd.conf` для Kerberos-аутентификации.

### `ls` показывает нулевой размер у регулярного файла

**Причина:** Файл является sparse (разреженным). `ls -l` отображает логический размер, но блоки выделяются только для записанных данных.  
**Диагностика:**
```bash
ls -l large_sparse_file
# → -rw-r--r-- 1 root root 0 Aug 29 12:00 large_sparse_file

du -h large_sparse_file
# → 4.0K    large_sparse_file

ls -s large_sparse_file
# → 4 -rw-r--r-- 1 root root 0 Aug 29 12:00 large_sparse_file
```
**Решение:** Используйте `du` для фактического размера на диске и `ls -s` для размера в блоках. Для проверки разреженности: `filefrag -v large_sparse_file`.

### `ls` игнорирует символические ссылки в пайплайнах

**Причина:** При использовании `ls` в `while read` без `-L` или без явного `readlink` скрипт получает имя ссылки, а не целевой путь.  
**Диагностика:**
```bash
ls -la /etc/nginx/sites-enabled/ | awk '{print $9}'
# → default.conf (это имя ссылки, а не путь цели)
```
**Решение:** Для получения целей используйте:
```bash
find /etc/nginx/sites-enabled/ -type l -exec readlink -f {} \;
```

### `ls` и `ctime`/`mtime` путаница при бэкапах

**Причина:** Администраторы часто считают, что `ctime` отражает время изменения содержимого. На самом деле `ctime` меняется при изменении inode (права, владелец, имя, размер), а не только содержимого.  
**Диагностика:**
```bash
touch -r file.txt reference.txt
ls -lc file.txt
# → время изменится, хотя содержимое не менялось
```
**Решение:** Для отслеживания изменений содержимого используйте `mtime` (`ls -lt`). Для отслеживания любых изменений метаданных — `ctime` (`ls -lc`).

### Цвета не отображаются

**Причина:** В большинстве дистрибутивов `ls` является аliasом (`alias ls='ls --color=auto'`). В неинтерактивных сессиях или при использовании абсолютного пути `/bin/ls` alias не применяется.  
**Решение:**
```bash
ls --color=auto -la
```
Или установите alias в `~/.bashrc` / `~/.zshrc`:
```bash
alias ls='ls --color=auto'
```

## Экзамен LPIC-1 (103.1)

Топик 103.1 силлибуса LPIC-1 ("Архитектура системы Linux") требует понимания механизма скрытия файлов и комбинации флагов `ls`.

### Типичный экзаменационный вопрос

> **Вопрос:** Какой флаг или комбинация флагов `ls` выведет все файлы каталога, включая скрытые, с полными метаданными (права, владелец, размер, дата изменения)?

**Варианты ответа:**
- A. `ls -A`
- B. `ls -la`
- C. `ls -L`
- D. `cat .file`

**Правильный ответ:** B (`ls -la`)

**Разбор вариантов:**
- **A (`ls -A`)**: Показывает скрытые файлы, но пропускает записи `.` и `..`. Более того, без `-l` не выводит метаданные (права, размер, владелец).
- **B (`ls -la`)**: Правильный ответ. Объединяет `-l` (длинный формат с метаданными) и `-a` (все файлы, включая dotfiles и `.`/`..`). Это стандартная комбинация для административного обзора.
- **C (`ls -L`)**: В GNU `ls` флаг `-L` (`--dereference`) разыменовывает символические ссылки. Он не показывает скрытые файлы и не включает длинный формат.
- **D (`cat .file`)**: Команда `cat` выводит содержимое файла, но не его метаданные в файловой системе. К тому же `.file` — это пример имени, а не флаг.

### Дополнительные проверки на экзамене

- Флаг `-h` делает размеры читаемыми для человека, но только в сочетании с `-l` или `-s`.
- Флаг `-d` показывает свойства самой папки, а не её содержимого.
- Флага `--hidden` в GNU coreutils не существует.
- Записи `.` и `..` являются реальными файлами (directory entries), а не абстракцией оболочки.

## Дополнительная информация

### Переменные окружения и конфигурация

- **`LS_COLORS`**: Переменная окружения, определяющая цвета для разных типов файлов. Устанавливается пакетом `dircolors`. Пример для тёмной темы: `LS_COLORS='rs=0:di=01;34:ln=01;36:mh=00:pi=40;33:so=01;35:do=01;35:bd=40;33;01:cd=40;33;01:or=01;05;37;41:mi=01;05;37;41:su=37;41:sg=30;43:tw=30;42:ow=34;42:st=37;44:ex=01;32'`. Для светлой темы используйте `dircolors -p > ~/.dircolors` и отредактируйте значения.
- **`LS_OPTIONS`**: Используется в некоторых дистрибутивах (например, Slackware) для задания флагов по умолчанию.
- **`LS_BLOCK_SIZE`**: Переопределяет размер блока для вывода `ls -s` и `-l` (если не используется `-h`). Принимает суффиксы `K`, `M`, `G` (по умолчанию 1024). Если не задана, используются `BLOCK_SIZE` или `BLOCKSIZE`. Установка `LS_BLOCK_SIZE=1` заставит `ls -s` показывать размер в байтах.
- **`BLOCK_SIZE` / `BLOCKSIZE`**: Обрабатываются теми же утилитами, что и `LS_BLOCK_SIZE`, но имеют более низкий приоритет.
- **`QUOTING_STYLE`**: Управляет экранированием имён файлов. Значения: `shell` (по умолчанию), `shell-always`, `shell-escape`, `shell-escape-always`, `c`, `escape`, `clocale`, `locale`, `literal`. Пример: `QUOTING_STYLE=literal ls` покажет имена без кавычек, что удобно для копирования.
- **`TIME_STYLE`**: Формат вывода времени, если не указан `--time-style`. Пример: `TIME_STYLE=long-iso ls -l`.
- **Alias в оболочках**: В Debian/Ubuntu по умолчанию существует `alias ls='ls --color=auto'`. В minimal-установках (например, Alpine, CentOS minimal) alias может отсутствовать. Для неинтерактивных скриптов alias не применяется — используйте полный путь или явный флаг `--color=auto`.

### Связанные утилиты

- **`dir`**, **`vdir`**: Псевдонимы `ls`, с форматом вывода, приближенным к `ls -C` и `ls -l` соответственно.
- **`tree`**: Визуализация иерархии каталогов в виде древовидной структуры. Поддерживает показ скрытых файлов (`-a`).
- **`eza`**: Современная замена `ls` на Rust. Поддерживает иконки, цвета, Git-статус и вывод дерева (`--tree`). См. [Консольные редакторы и утилиты](./cli-tools.md).
- **`find`**: Для рекурсивного поиска с фильтрацией по имени, размеру, времени. Не предназначена для простого листинга.
- **`stat`**: Вывод детальных метаданных одного файла (inode, dev, atime, mtime, ctime).
- **`lsattr` / `chattr`**: Управление расширенными атрибутами ext2/3/4/XFS (immutable, append-only). Полезно при расследовании "невозможности удаления файла".
- **`getfacl`**: Просмотр расширенных ACL, которые `ls -l` не отображает (ограничение до 9 базовых прав).
