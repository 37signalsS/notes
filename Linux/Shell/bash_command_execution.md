# Логика обработки команд в Shell

## Определения

- **Логика обработки команд**: Последовательность действий shell от чтения строки до завершения всех указанных программ: разбор синтаксиса, приоритет операторов, управление процессами и потоками данных.
- **Связанные концепции**: [Эмулятор терминала и командная оболочка](shell_intro.md), [перенаправление ввода/вывода](io_redirection.md), [коды возврата ($?)](exit_codes.md).

## Базовые концепции

### Типы команд

- **Внешние команды (External Commands)**
  - Отдельные исполняемые файлы в файловой системе (`/bin/ls`, `/usr/bin/grep`).
  - Для каждой команды создается **дочерний процесс** (системные вызовы `fork`/`exec`).
  - Создание процессов: [Процессы в Linux](../Core/processes/basic_concepts.md).

- **Внутренние команды (Built-ins)**
  - Встроены в код Bash (`cd`, `echo`, `export`).
  - Выполняются в текущем процессе оболочки **без создания дочернего процесса**.

- **Алиасы (Aliases)**
  - Пользовательские псевдонимы для команд (`alias ll='ls -alF'`).
  - Оболочка заменяет алиас на его значение перед поиском команды.

### Порядок поиска команд

1. **Алиасы** — проверка и замена алиаса на полное значение.
2. **Built-ins** — проверка на встроенную команду (`cd`, `pwd`, `export`).
3. **Хеш-таблица** — кеш путей к ранее найденным внешним командам.
4. **Поиск в `$PATH`** — поиск исполняемого файла в директориях `$PATH` (слева направо). Первый найденный файл добавляется в хеш.
5. **`command not found`** — если команда не найдена ни на одном этапе.

### Порядок разбора и приоритеты

1. **Чтение строки** — оболочка считывает всю командную строку целиком.
2. **Конвейеры (`|`)** — группировка команд с пайпами (высший приоритет).
3. **Управляющие операторы (`&&`, `||`, `;`)** — последовательное выполнение блоков слева направо.

### Операторы и конструкции

#### Управляющие операторы

- **`&&`** — `cmd2` выполняется только если `cmd1` успешна (exit code 0).
- **`||`** — `cmd2` выполняется только если `cmd1` завершилась с ошибкой (exit code ≠ 0).
- **`;`** — `cmd2` выполняется всегда.

#### Группировка команд: `( ... )` и `{ ...; }`

- **`( ... )` (Subshell)** — команды выполняются в дочернем процессе. Изменения окружения не влияют на родительскую оболочку.
- **`{ ...; }` (Grouping)** — команды выполняются в текущей оболочке. Изменения окружения сохраняются.

#### Подстановка команд и процессов

- **`$(команда)`** — выполнение команды и подстановка её `stdout` в основную команду. Предпочтительнее `` `команда` ``.
- **`<(команда)` (Process Substitution)** — вывод команды предоставляется как временный файл для использования в качестве аргумента.

#### Фоновые процессы: `&`

- **Запуск** — команда выполняется в дочернем процессе без ожидания завершения. Оболочка выводит `[job_number] PID`.
- **Управление**:
  - `jobs` — список фоновых и приостановленных задач.
  - `fg %N` — вернуть задание `N` на передний план.
- **Вывод** — `stdout`/`stderr` выводятся в терминал. Для подавления: `cmd &> /dev/null`.
- **Связанные концепции**: Приостановка (`Ctrl+Z`), возобновление в фоне (`bg`). Подробности: [Инструменты CLI](cli-tools.md). Обработка сигналов для graceful shutdown: [Сигналы и trap](bash_signal_traps.md).

```bash
$ sleep 300 &
[1] 12345
```

## Практические сценарии

### Цепочки команд для надежного выполнения

```bash
# Создать директорию и скопировать файлы только при успехе mkdir
mkdir backup && cp *.log backup/
```

### Выполнение альтернативного действия

```bash
# Проверить хост и сообщить при недоступности
ping -c 1 google.com || echo "Хост недоступен"
```

### Изоляция изменений окружения

```bash
# Сборка в subshell без изменения текущего каталога
(cd /path/to/project && make)
echo "Исходный каталог: $(pwd)"
```

### Сравнение вывода без временных файлов

```bash
# Сравнить отсортированные списки пакетов
diff <(sort packages1.list) <(sort packages2.list)
```

### Перенаправление ошибок в конвейер

```bash
# Отфильтровать ошибки docker (stderr → stdout → grep)
docker run non_existent_image 2>&1 | grep "Error"
```

### Нюансы `cd` с `sudo`

`cd` — built-in команда, `sudo cd /path` завершится ошибкой `command not found`. `sudo` ищет внешний исполняемый файл, а `cd` меняет каталог только в текущем процессе оболочки.

#### Решения

1. **Subshell с `bash -c`**:
   ```bash
   sudo bash -c 'cd /root && ls -l'
   ```

2. **Интерактивная сессия root (`sudo su -`)**:
   ```bash
   sudo su -
   # работа от root
   exit
   ```

3. **Интерактивная оболочка root (`sudo -i` / `sudo -s`)**:
   - `sudo -i` — login-оболочка (полная инициализация окружения root).
   - `sudo -s` — non-login оболочка (использует `$SHELL`).

## Дополнительная информация

### Таблица операторов

| Оператор | Тип | Порядок выполнения | Пример |
| :--- | :--- | :--- | :--- |
| `|` | Конвейер | **Одновременный** запуск. Данные текут слева направо. | `cat file \| grep word` |
| `&&` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая успешна. | `mkdir d && cd d` |
| `||` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая провалилась. | `ping host \|\| echo 'down'` |
| `;` | Управляющий | **Последовательный**. Вторая команда выполняется всегда. | `cmd1 ; cmd2` |
| `&` | Управляющий | Запускает команду в **фоновом режиме**. | `sleep 10 &` |
| `>` `>>` `<` | Перенаправление | **Настраивается оболочкой до запуска команды.** | `ls > file.txt` |
| `$(...)` | Подстановка | Выполняется **до** основной команды. Результат подставляется как аргумент. | `rm $(find . -name "*.tmp")` |
| `<(...)` | Подстановка | Выполняется **одновременно** с основной командой, результат виден как файл. | `diff <(sort f1) <(sort f2)` |
| `( ... )` | Группировка | Команды выполняются в **дочерней оболочке (subshell)**. | `(cd /tmp && pwd)` |
| `{ ...; }` | Группировка | Команды выполняются в **текущей оболочке**. | `{ cd /tmp; pwd; }` |

### Сравнение типов команд

| Характеристика | Внутренняя (Built-in) | Внешняя (External) | Алиас (Alias) |
| :--- | :--- | :--- | :--- |
| **Источник** | Встроена в код `bash` | Отдельный файл на диске | Запись в памяти `bash` |
| **Процесс** | Новый процесс **не создается** | **Создается** дочерний процесс | Зависит от команды-оригинала |
| **Скорость** | Очень высокая | Медленнее (затраты на `fork`/`exec`) | Зависит от команды-оригинала |
| **Примеры** | `cd`, `export`, `pwd`, `type` | `ls`, `grep`, `find`, `docker` | `ll` -> `ls -l` |

### Нюансы и риски безопасности

- **Порядок в `$PATH`**: Директории в `$PATH` просматриваются слева направо. Если в `/home/user/bin` (которая стоит первой в `$PATH`) будет лежать скрипт с именем `ls`, он будет выполнен вместо системной утилиты `/bin/ls`. Это может быть использовано в зловредных целях. Никогда не ставьте текущую директорию (`.`) в начало `$PATH` в окружении суперпользователя.
- **Вредоносные алиасы**: Алиас может быть переопределен для выполнения опасных действий. Например, `alias sudo='rm -rf /'` — тривиальный, но показательный пример. Будьте внимательны, копируя и выполняя строки с `alias` из недоверенных источников.
