# Логика обработки и выполнения команд в Shell

## Определения

- **Жизненный цикл команды (Command Lifecycle)** — последовательность этапов, которые проходит строка ввода от момента нажатия `Enter` до завершения процесса.
- **Подстановка (Expansion)** — механизм замены специальных символов и конструкций (например, `*` или `$VAR`) на их реальные значения перед выполнением.
- **Разбиение на слова (Word Splitting)** — разделение результата расширений на отдельные аргументы на основе символов-разделителей `IFS`.
- **Хеш-таблица (Hash Table)** — внутренний кеш оболочки, хранящий пути к ранее найденным внешним командам для исключения повторного поиска в `$PATH`.

---

## Жизненный цикл выполнения команды

Когда вы вводите команду, Bash выполняет преобразования в строго определенном порядке:

1.  **Токенизация**: Разбиение строки на слова и операторы.
2.  **Генерация строк (Brace Expansion)**: Обработка `{a,b}`.
3.  **Подстановка тильды (Tilde Expansion)**: Замена `~` на путь к HOME.
4.  **Подстановка параметров и переменных**: Замена `$VAR` ([подробнее в shell_variables](./shell_variables.md)).
5.  **Арифметическая подстановка**: Вычисление `$(( ))`.
6.  **Подстановка команд**: Обработка `$(command)`.
7.  **Разбиение на слова (Word Splitting)**: Применяется к результатам этапов 4, 5 и 6 (если они не в кавычках).
8.  **Подстановка имен файлов (Globbing)**: Обработка `*`, `?`, `[ ]`.
9.  **Удаление кавычек (Quote Removal)**: Оболочка убирает `'` и `"`, использованные для защиты текста.
10. **Перенаправления**: Настройка потоков `stdin`, `stdout`, `stderr` ([подробнее в io_redirection](./io_redirection.md)).
11. **Выполнение**: Запуск команды.

## Приоритет поиска и управления командами

### Порядок поиска
1.  **Алиасы (Aliases)**: Псевдонимы (`alias`).
2.  **Ключевые слова (Keywords)**: Служебные слова (`if`, `while`).
3.  **Функции (Functions)**: Пользовательские функции.
4.  **Встроенные команды (Built-ins)**: Команды внутри Bash (`cd`, `export`).
5.  **Внешние команды (External)**: Файлы в `$PATH` или по абсолютному пути.

### Управление приоритетами (Bypassing)
- **`command <cmd>`**: Игнорирует алиасы и функции, запуская встроенную или внешнюю команду.
- **`builtin <cmd>`**: Запускает только встроенную команду, игнорируя функции и внешние бинарники.
- **`enable -n <cmd>`**: Отключает встроенную команду, заставляя Shell искать внешний файл в `$PATH`.
- **`\<cmd>`**: Обратный слэш перед командой отключает только алиасы.

## Управляющие операторы и группировка

### Операторы логической связи
- **`&&` (AND)**: Выполнение при коде возврата **0**.
- **`||` (OR)**: Выполнение при коде возврата **не 0**.
- **`;`**: Последовательное выполнение без условий.

### Группировка
- **`( commands )` — Subshell**: Выполняется в дочернем процессе. Смена директории или переменных **не влияет** на текущую оболочку.
- **`{ commands; }` — Current Shell**: Выполняется в текущем процессе. Требует пробелов и финальной `;`.

## Продвинутые механизмы

### Управление глоббингом (shopt)
Поведение подстановки имен файлов можно изменить через опции `shopt`:
- `shopt -s nullglob`: Если файлы не найдены, шаблон удаляется (а не остается как строка).
- `shopt -s dotglob`: Включает скрытые файлы (начинающиеся с `.`) в результаты `*`.
- `shopt -s nocaseglob`: Поиск без учета регистра.

### Хеш-таблица (hash)
Bash запоминает местоположение внешних команд. Если вы переместили бинарный файл, а Shell выдает ошибку "No such file", нужно очистить кеш:
- `hash`: Просмотр закешированных путей.
- `hash -r`: Полная очистка кеша.

## Практические сценарии

### Сравнение вывода команд (Process Substitution)
Механизм `<(command)` позволяет передать вывод команды туда, где ожидается путь к файлу.
```bash
# Сравнение содержимого двух директорий
diff <(ls dir1) <(ls dir2)
```

### Изоляция временных изменений
```bash
# Перейти в папку, выполнить команду и вернуться назад автоматически
(cd /tmp/test && ./run.sh)
```

### Обработка ошибок в длинных цепочках
```bash
# Выполнить очистку только если сборка и тесты прошли успешно
make build && make test && make clean
```

## Дополнительная информация

### Безопасность и PATH
Никогда не добавляйте `.` (текущую директорию) в начало переменной `$PATH`. Это позволяет злоумышленнику подменить системную команду (например, `ls`) вредоносным скриптом в текущей папке.
