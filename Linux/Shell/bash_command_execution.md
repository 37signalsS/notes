# Логика обработки команд в Shell

## Определения

- **Command Processing Logic (Логика обработки команд)** — последовательность действий Shell от момента считывания строки до завершения всех запущенных программ. Включает разбор синтаксиса, определение приоритетов операторов, поиск исполняемых файлов и управление процессами.
- **Subshell (Дочерняя оболочка)** — дочерний процесс Shell, наследующий окружение родителя, но работающий изолированно. Изменения в `subshell` (например, смена директории или создание переменных) не влияют на родительский процесс.
- **Exit Code (Код возврата)** — целочисленное значение (0–255), возвращаемое процессом при завершении для информирования о результате выполнения ([подробнее](./exit_codes.md)).

## Базовые концепции

### Типы команд

В Shell существует три основных типа команд, различающихся по способу выполнения:

1. **Aliases (Алиасы)** — пользовательские псевдонимы (например, `alias ll='ls -la'`). Оболочка заменяет имя алиаса на его значение на самом первом этапе обработки.
2. **Built-ins (Внутренние команды)** — команды, встроенные непосредственно в исполняемый файл оболочки (`cd`, `echo`, `export`). Выполняются в текущем процессе Shell без создания дочернего процесса.
3. **External Commands (Внешние команды)** — отдельные файлы в файловой системе (например, `/usr/bin/grep`). Для их запуска Shell использует системные вызовы `fork()` и `exec()`, создавая новый процесс.

### Порядок поиска команд

Когда пользователь вводит команду, Shell ищет её в следующем порядке:

1. Проверка на наличие **алиаса**.
2. Проверка на наличие **встроенной команды** (Built-in).
3. Поиск в **хеш-таблице** (кеш путей к ранее найденным внешним командам).
4. Поиск исполняемого файла в директориях, указанных в переменной **`$PATH`** (слева направо).
5. Если команда не найдена — ошибка `command not found`.

### Управляющие операторы и группировка

#### Операторы выполнения

- **`&&` (AND)** — выполнение следующей команды только при успешном завершении предыдущей (Exit Code 0).
- **`||` (OR)** — выполнение следующей команды только при ошибке предыдущей (Exit Code ≠ 0).
- **`;` (Semicolon)** — последовательное выполнение команд вне зависимости от их результата.
- **`|` (Pipeline)** — передача `stdout` (стандартного вывода) первой команды на `stdin` (стандартный ввод) второй.

#### Группировка команд

- **`( command1; command2 )`** — выполнение группы в **дочерней оболочке** (Subshell).
- **`{ command1; command2; }`** — выполнение группы в **текущей оболочке**. Требует точки с запятой в конце и пробелов внутри фигурных скобок.

### Фоновые процессы и управление задачами

- **`&`** — запуск команды в фоновом режиме. Shell возвращает управление немедленно, не дожидаясь завершения команды.
- **`jobs`** — список активных фоновых задач текущей сессии.
- **`fg` / `bg`** — перенос задачи на передний план (foreground) или продолжение выполнения в фоне (background).
- **`disown`** — удаление задачи из таблицы задач текущей оболочки. Предотвращает отправку сигнала **`SIGHUP`** (Signal Hangup) процессу при закрытии терминала, позволяя ему продолжить работу.

## Практические сценарии

### Изоляция изменений окружения (Subshell)

Использование круглых скобок позволяет временно изменить состояние (например, перейти в другую директорию) без влияния на основной скрипт.

```bash
# Выполнение сборки в поддиректории
(cd /tmp/project && make build)

# Текущая директория осталась прежней
pwd
```

### Сравнение вывода без временных файлов (Process Substitution)

Механизм `<(command)` позволяет передать вывод команды как путь к файлу.

```bash
# Сравнение списка файлов в двух директориях
diff <(ls dir1) <(ls dir2)
```

### Обработка ошибок в конвейерах

По умолчанию конвейер передает только `stdout`. Для передачи `stderr` (стандартного потока ошибок) используется `|&` (в Bash 4+).

```bash
# Поиск ошибки в выводе, включая сообщения об ошибках самого Docker
docker run my-image |& grep "Error"
```

### Нюансы использования `sudo` с встроенными командами

Команды типа `cd` не являются файлами, поэтому `sudo cd` завершится ошибкой.

```bash
# Неправильно: sudo не найдет файл 'cd'
sudo cd /root

# Правильно: запуск через дочернюю оболочку от root
sudo bash -c 'cd /root && ls'

## Механизмы расширения (Expansions)

Перед выполнением команды Bash производит ряд преобразований строки ввода.

### 1. Генерация строк (Brace Expansion)

Используется для создания произвольных строк по шаблону `{ }`.

```bash
# Диапазоны
echo {1..10}      # 1 2 3 ... 10
echo {a..z}      # a b c ... z

# Списки и префиксы
echo img_{01,02,03}.png  # img_01.png img_02.png img_03.png

# Быстрое создание бэкапа
cp file.txt{,.bak}       # эквивалентно cp file.txt file.txt.bak
```

### 2. Подстановка имен файлов (Globin)

Используется для поиска файлов в файловой системе. **Внимание**: это шаблоны Bash, а не регулярные выражения.

- **`*`** — любая строка (включая пустую).
- **`?`** — любой одиночный символ.
- **`[abc]`** — любой из указанных символов.
- **`[!abc]`** — любой символ, кроме указанных.

```bash
# Все .txt файлы
ls *.txt

# Файлы с одним символом в имени
ls ?

# Файлы, начинающиеся на букву или цифру
ls [a-zA-Z0-9]*
```

### 3. Подстановка команд и арифметики

- **`$(command)`** — заменяется на вывод команды.
- **`$((expression))`** — заменяется на результат вычисления.

## Дополнительная информация

### Сравнительная таблица операторов

| Оператор | Порядок | Условие выполнения | Пример |
| :--- | :--- | :--- | :--- |
| **`|`** | Одновременно | Данные текут слева направо | `ls | grep .txt` |
| **`&&`** | Последовательно | Первая команда успешна | `make && make install` |
| **`||`** | Последовательно | Первая команда провалилась | `ping host || echo error` |
| **`;`** | Последовательно | Всегда | `cmd1 ; cmd2` |
| **`&`** | Фоновый | Запуск в дочернем процессе | `long_job &` |

### Риски безопасности: Алиасы и PATH

- **Вредоносные алиасы**: Алиас может переопределить системную команду. Например, `alias sudo='my_malicious_script'` может быть использован для перехвата пароля. Всегда проверяйте конфигурационные файлы (`~/.bashrc`, `~/.profile`).
- **Порядок в `$PATH`**: Если текущая директория (`.`) стоит в начале `$PATH`, злоумышленник может подложить скрипт с именем `ls` в рабочую папку, и он будет выполнен вместо системной утилиты. Это критически опасно в окружении суперпользователя.
