# Логика обработки команд в Shell

## Определения

- **Логика обработки команд**: Последовательность действий, которую выполняет командная оболочка (shell) от момента чтения строки до завершения всех указанных в ней программ. Эта логика включает в себя разбор синтаксиса, определение приоритета операторов и управление потоками данных и процессов.
- **Связанные концепции**: Понимание этой логики требует знания базовых понятий, таких как [эмулятор терминала и командная оболочка](shell_intro.md), [перенаправление ввода/вывода](io_redirection.md) и [коды возврата ($?)](exit_codes.md).

## Основные концепции

### Порядок разбора и приоритеты

Командная оболочка обрабатывает строку не строго слева направо, а в соответствии с приоритетом встроенных операторов.

1.  **Чтение всей строки**: Оболочка считывает **всю** командную строку целиком перед тем, как начать ее интерпретировать.
2.  **Группировка в конвейеры (`|`)**: В первую очередь, оболочка находит команды, соединенные пайпами (`|`). **Конвейер имеет более высокий приоритет, чем управляющие операторы `&&` и `||`**.
3.  **Управляющие операторы (`&&`, `||`, `;`)**: После группировки конвейеров, оболочка выполняет получившиеся блоки последовательно, слева направо, в зависимости от управляющих операторов.

### Специальные операторы и конструкции

#### Управляющие операторы

- **`&&` (Логическое "И")**: `cmd1 && cmd2` -> Выполнить `cmd2` **только если** `cmd1` завершилась успешно (код выхода 0).
- **`||` (Логическое "ИЛИ")**: `cmd1 || cmd2` -> Выполнить `cmd2` **только если** `cmd1` завершилась с ошибкой (код выхода не 0).
- **`;` (Последовательное выполнение)**: `cmd1 ; cmd2` -> Выполнить `cmd2` **всегда**, независимо от кода возврата `cmd1`.

#### Группировка команд: `( ... )` и `{ ...; }`

- **`( ... )` (Subshell)**: Команды выполняются в **новом, дочернем процессе оболочки**. Изменения окружения (переменные, `cd`) **не влияют** на родительскую оболочку.
- **`{ ...; }` (Grouping)**: Команды выполняются в **текущей оболочке**. Изменения окружения **сохраняются**.

#### Подстановка команд и процессов

- **`$(команда)` или `` `команда` ``**: Оболочка выполняет команду и подставляет её **стандартный вывод (stdout)** в основную команду. `$(...)` является предпочтительным синтаксисом.
- **`<(команда)` (Process Substitution)**: Оболочка выполняет команду и предоставляет её вывод в виде **временного файла**, который можно использовать как аргумент для другой команды.

#### Фоновые процессы: `&`

- **`&`**: Запускает команду в **фоновом режиме**, не дожидаясь ее завершения.

## Практические сценарии

### Цепочки команд для надежного выполнения

Использование `&&` для последовательного выполнения команд, где каждая следующая зависит от успеха предыдущей.

```bash
# Создать директорию и только в случае успеха скопировать в нее файлы
mkdir backup && cp *.log backup/
```

### Выполнение альтернативного действия

Использование `||` для выполнения "запасного" действия в случае неудачи основного.

```bash
# Проверить доступность хоста и сообщить, если он недоступен
ping -c 1 google.com || echo "Хост недоступен"
```

### Изоляция изменений окружения

Использование `( ... )` для выполнения команд в другом каталоге без изменения текущего рабочего каталога.

```bash
# Выполнить сборку проекта в subshell, чтобы не "загрязнять" текущую сессию
(cd /path/to/project && make)
echo "Я все еще в исходном каталоге: $(pwd)"
```

### Сравнение вывода двух команд

Использование `<(...)` для сравнения отсортированного вывода двух файлов без создания временных файлов.

```bash
# Сравнить списки пакетов из двух разных источников
diff <(sort packages1.list) <(sort packages2.list)
```

### Перенаправление ошибок в конвейер

По умолчанию `|` передает только `stdout`. Чтобы анализировать ошибки, нужно перенаправить `stderr` в `stdout` с помощью `2>&1`.

```bash
# Найти только сообщения об ошибках при запуске контейнера
docker run non_existent_image 2>&1 | grep "Error"
```

## Дополнительная информация

### Таблица операторов

| Оператор | Тип | Порядок выполнения | Пример |
| :--- | :--- | :--- | :--- |
| `|` | Конвейер | **Одновременный** запуск. Данные текут слева направо. | `cat file \| grep word` |
| `&&` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая успешна. | `mkdir d && cd d` |
| `||` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая провалилась. | `ping host \|\| echo 'down'` |
| `;` | Управляющий | **Последовательный**. Вторая команда выполняется всегда. | `cmd1 ; cmd2` |
| `&` | Управляющий | Запускает команду в **фоновом режиме**. | `sleep 10 &` |
| `>` `>>` `<` | Перенаправление | **Настраивается оболочкой до запуска команды.** | `ls > file.txt` |
| `$(...)` | Подстановка | Выполняется **до** основной команды. Результат подставляется как аргумент. | `rm $(find . -name "*.tmp")` |
| `<(...)` | Подстановка | Выполняется **одновременно** с основной командой, результат виден как файл. | `diff <(sort f1) <(sort f2)` |
| `( ... )` | Группировка | Команды выполняются в **дочерней оболочке (subshell)**. | `(cd /tmp && pwd)` |
| `{ ...; }` | Группировка | Команды выполняются в **текущей оболочке**. | `{ cd /tmp; pwd; }` |
