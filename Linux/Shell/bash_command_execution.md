# Логика обработки команд в Shell

## Определения

- **Логика обработки команд**: Последовательность действий, которую выполняет командная оболочка (shell) от момента чтения строки до завершения всех указанных в ней программ. Эта логика включает в себя разбор синтаксиса, определение приоритета операторов и управление потоками данных и процессов.
- **Связанные концепции**: Понимание этой логики требует знания базовых понятий, таких как [эмулятор терминала и командная оболочка](shell_intro.md), [перенаправление ввода/вывода](io_redirection.md) и [коды возврата ($?)](exit_codes.md).

## Основные концепции

### Типы команд

- **Внешние команды (External Commands)**
  - Это отдельные исполняемые файлы, находящиеся в файловой системе (например, `/bin/ls` или `/usr/bin/grep`).
  - Для выполнения каждой такой команды оболочка создает **новый дочерний процесс** (через системные вызовы `fork` и `exec`).
  - Фундаментальные концепции создания процессов подробно описаны в заметке: [Процессы в Linux: Обзор](../Core/processes/overview.md).

- **Внутренние команды (Built-ins)**
  - Являются частью самой оболочки Bash и встроены в ее код (например, `cd`, `echo`, `export`).
  - Выполняются непосредственно в текущем процессе оболочки, **без создания нового процесса**, что делает их очень быстрыми.

- **Алиасы (Aliases)**
  - Это пользовательские псевдонимы или "короткие имена" для других команд (например, `alias ll='ls -alF'`).
  - Оболочка просто заменяет (подставляет) имя алиаса на его полное значение перед тем, как начать искать команду дальше.

### Порядок поиска команд

Первая найденная сущность и будет выполнена.

1. **Проверка на Алиасы (Aliases)**
    - Сначала Bash проверяет, не является ли введенное слово **алиасом**. Если да, то он заменяется на свое полное значение, и процесс поиска начинается заново уже с этим новым значением.

2. **Проверка на Встроенные команды (Built-ins)**
    - Если это не алиас, Bash проверяет, не является ли команда **встроенной** (`cd`, `pwd`, `export` и т.д.). Если да, она выполняется немедленно внутри самой оболочки.

3. **Проверка Хеш-таблицы (Hash Table)**
    - Если команда не встроенная, Bash обращается к своей внутренней **хеш-таблице**. Это кеш, где хранятся полные пути к внешним командам, которые уже были найдены ранее в этой сессии. Это делается для оптимизации, чтобы не сканировать файловую систему каждый раз.

4. **Поиск в переменной `$PATH`**
    - Если команды нет в хеше, Bash начинает **поиск исполняемого файла** в директориях, перечисленных в переменной окружения `$PATH`.
    - Поиск ведется **строго слева направо**. Первый же найденный исполняемый файл с совпадающим именем будет использован. Его путь добавляется в хеш-таблицу для будущих вызовов.

5. **Ошибка "command not found"**
    - Если команда не была найдена ни на одном из предыдущих этапов, Bash выводит ошибку `command not found`.

### Порядок разбора и приоритеты

Командная оболочка обрабатывает строку не строго слева направо, а в соответствии с приоритетом встроенных операторов.

1. **Чтение всей строки**: Оболочка считывает **всю** командную строку целиком перед тем, как начать ее интерпретировать.
2. **Группировка в конвейеры (`|`)**: В первую очередь, оболочка находит команды, соединенные пайпами (`|`). **Конвейер имеет более высокий приоритет, чем управляющие операторы `&&` и `||`**.
3. **Управляющие операторы (`&&`, `||`, `;`)**: После группировки конвейеров, оболочка выполняет получившиеся блоки последовательно, слева направо, в зависимости от управляющих операторов.

### Операторы и конструкции

#### Управляющие операторы

- **`&&` (Логическое "И")**: `cmd1 && cmd2` -> Выполнить `cmd2` **только если** `cmd1` завершилась успешно (код выхода 0).
- **`||` (Логическое "ИЛИ")**: `cmd1 || cmd2` -> Выполнить `cmd2` **только если** `cmd1` завершилась с ошибкой (код выхода не 0).
- **`;` (Последовательное выполнение)**: `cmd1 ; cmd2` -> Выполнить `cmd2` **всегда**, независимо от кода возврата `cmd1`.

#### Группировка команд: `( ... )` и `{ ...; }`

- **`( ... )` (Subshell)**: Команды выполняются в **новом, дочернем процессе оболочки**. Изменения окружения (переменные, `cd`) **не влияют** на родительскую оболочку.
- **`{ ...; }` (Grouping)**: Команды выполняются в **текущей оболочке**. Изменения окружения **сохраняются**.

#### Подстановка команд и процессов

- **`$(команда)` или `` `команда` ``**: Оболочка выполняет команду и подставляет её **стандартный вывод (stdout)** в основную команду. `$(...)` является предпочтительным синтаксисом.
- **`<(команда)` (Process Substitution)**: Оболочка выполняет команду и предоставляет её вывод в виде **временного файла**, который можно использовать как аргумент для другой команды.

#### Фоновые процессы: `&`

- **`&`**: Запускает команду в **фоновом режиме**, не дожидаясь ее завершения.

## Практические сценарии

### Цепочки команд для надежного выполнения

Использование `&&` для последовательного выполнения команд, где каждая следующая зависит от успеха предыдущей.

```bash
# Создать директорию и только в случае успеха скопировать в нее файлы
mkdir backup && cp *.log backup/
```

### Выполнение альтернативного действия

Использование `||` для выполнения "запасного" действия в случае неудачи основного.

```bash
# Проверить доступность хоста и сообщить, если он недоступен
ping -c 1 google.com || echo "Хост недоступен"
```

### Изоляция изменений окружения

Использование `( ... )` для выполнения команд в другом каталоге без изменения текущего рабочего каталога.

```bash
# Выполнить сборку проекта в subshell, чтобы не "загрязнять" текущую сессию
(cd /path/to/project && make)
echo "Я все еще в исходном каталоге: $(pwd)"
```

### Сравнение вывода двух команд

Использование `<(...)` для сравнения отсортированного вывода двух файлов без создания временных файлов.

```bash
# Сравнить списки пакетов из двух разных источников
diff <(sort packages1.list) <(sort packages2.list)
```

### Перенаправление ошибок в конвейер

По умолчанию `|` передает только `stdout`. Чтобы анализировать ошибки, нужно перенаправить `stderr` в `stdout` с помощью `2>&1`.

```bash
# Найти только сообщения об ошибках при запуске контейнера
docker run non_existent_image 2>&1 | grep "Error"
```

### Нюансы выполнения команды `cd` с `sudo`

Команда `cd` (change directory) является **встроенной командой оболочки Bash (built-in)**, а не внешней исполняемой программой.

Когда вы пытаетесь выполнить `sudo cd /path/to/directory`, `sudo` ищет исполняемый файл `cd` в `$PATH`. Поскольку `cd` не является внешним файлом, `sudo` не находит его и сообщает об ошибке `command not found` (или аналогичную, как в Debian 12: `command not found`, с пояснением, что `cd` - это built-in).

Это происходит потому, что `cd` изменяет текущий рабочий каталог непосредственно в контексте **текущей оболочки**. Запуск `cd` в новом процессе (который создает `sudo`) изменит каталог только для этого нового процесса, который тут же завершится, не повлияв на родительскую оболочку.

#### Решения

1. **Выполнение в подоболочке (subshell) с Bash:**
    Вы можете использовать `sudo` для запуска новой оболочки (`bash`) от имени `root`, которая затем выполнит `cd` и другие команды. Это позволяет временно получить привилегии `root` для выполнения нескольких команд, а затем вернуться в обычную сессию.

    ```bash
    # Запуск одной команды или цепочки команд в подоболочке root
    sudo bash -c 'cd /root && ls -l'
    ```

    Здесь `bash -c` запускает новую Bash-сессию, которая выполняется от имени `root`. Все команды внутри одинарных кавычек (`'...'`) выполняются в этой привилегированной подоболочке.

2. **Переключение на пользователя `root` с инициализацией окружения (`sudo su -`):**
    Это наиболее полный способ получить интерактивную сессию `root`, которая полностью инициализирует окружение суперпользователя (его домашний каталог, переменные окружения и т.д.).

    ```bash
    sudo su -
    # Теперь вы работаете как root. Можете выполнять 'cd' и другие команды.
    # После завершения работы выполните 'exit' для возврата к своему пользователю.
    ```

    Это действие аналогично `su -`, но использует `sudo` для повышения привилегий, запрашивая пароль текущего пользователя (если `sudo` настроен).

3. **Запуск интерактивной оболочки `root` (`sudo -i` или `sudo -s`):**
    Аналогично `sudo su -`, эти команды запускают интерактивную оболочку от имени `root`.
    - `sudo -i`: Запускает **login-оболочку**, полностью симулируя вход пользователя `root`.
    - `sudo -s`: Запускает **non-login оболочку**, используя оболочку, указанную в переменной `SHELL`, но не симулируя полный вход в систему.

    ```bash
    sudo -i
    # или
    sudo -s
    # Теперь вы работаете как root.
    ```

    После завершения работы выполните `exit`.

## Дополнительная информация

### Таблица операторов

| Оператор | Тип | Порядок выполнения | Пример |
| :--- | :--- | :--- | :--- |
| `|` | Конвейер | **Одновременный** запуск. Данные текут слева направо. | `cat file \| grep word` |
| `&&` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая успешна. | `mkdir d && cd d` |
| `||` | Управляющий | **Последовательный**. Вторая команда выполняется, если первая провалилась. | `ping host \|\| echo 'down'` |
| `;` | Управляющий | **Последовательный**. Вторая команда выполняется всегда. | `cmd1 ; cmd2` |
| `&` | Управляющий | Запускает команду в **фоновом режиме**. | `sleep 10 &` |
| `>` `>>` `<` | Перенаправление | **Настраивается оболочкой до запуска команды.** | `ls > file.txt` |
| `$(...)` | Подстановка | Выполняется **до** основной команды. Результат подставляется как аргумент. | `rm $(find . -name "*.tmp")` |
| `<(...)` | Подстановка | Выполняется **одновременно** с основной командой, результат виден как файл. | `diff <(sort f1) <(sort f2)` |
| `( ... )` | Группировка | Команды выполняются в **дочерней оболочке (subshell)**. | `(cd /tmp && pwd)` |
| `{ ...; }` | Группировка | Команды выполняются в **текущей оболочке**. | `{ cd /tmp; pwd; }` |

### Сравнение типов команд

| Характеристика | Внутренняя (Built-in) | Внешняя (External) | Алиас (Alias) |
| :--- | :--- | :--- | :--- |
| **Источник** | Встроена в код `bash` | Отдельный файл на диске | Запись в памяти `bash` |
| **Процесс** | Новый процесс **не создается** | **Создается** дочерний процесс | Зависит от команды-оригинала |
| **Скорость** | Очень высокая | Медленнее (затраты на `fork`/`exec`) | Зависит от команды-оригинала |
| **Примеры** | `cd`, `export`, `pwd`, `type` | `ls`, `grep`, `find`, `docker` | `ll` -> `ls -l` |

### Нюансы и риски безопасности

- **Порядок в `$PATH`**: Директории в `$PATH` просматриваются слева направо. Если в `/home/user/bin` (которая стоит первой в `$PATH`) будет лежать скрипт с именем `ls`, он будет выполнен вместо системной утилиты `/bin/ls`. Это может быть использовано в зловредных целях. Никогда не ставьте текущую директорию (`.`) в начало `$PATH` в окружении суперпользователя.
- **Вредоносные алиасы**: Алиас может быть переопределен для выполнения опасных действий. Например, `alias sudo='rm -rf /'` — тривиальный, но показательный пример. Будьте внимательны, копируя и выполняя строки с `alias` из недоверенных источников.
