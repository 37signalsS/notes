# Горячие клавиши и шорткаты Shell

## Определения

- **Горячие клавиши (Shortcuts)** — комбинации клавиш, предназначенные для ускорения ввода, редактирования команд и управления процессами в командной оболочке (Bash, Zsh) и эмуляторах терминала.
- **Readline** — библиотека, используемая Bash (и многими другими CLI-инструментами) для редактирования командной строки. Она определяет поведение большинства шорткатов в Emacs и Vi режимах.
- **ZLE (Zsh Line Editor)** — встроенный редактор строк в Zsh. Он мощнее Readline, поддерживает многострочное редактирование и более гибкую кастомизацию, хотя по умолчанию эмулирует поведение Readline.
- **POSIX Terminal Interface** — стандарт, определяющий базовые управляющие символы (такие как `Ctrl+C`, `Ctrl+Z`), которые обрабатываются драйвером терминала (TTY), а не самой оболочкой.
- **SIGHUP (Signal Hang Up)** — сигнал 1, отправляемый процессу при потере управляющего терминала (разрыв SSH, закрытие окна терминала). Процесс по умолчанию завершается. Игнорируется `nohup` и `disown`.
- **Kill-ring** — кольцевой буфер в Readline/ZLE, в котором хранятся последние несколько удаленных фрагментов текста. Позволяет циклически перебирать их через `Ctrl+Y` и `Alt+Y`.
- **Flow Control (XON/XOFF)** — механизм программного управления выводом терминала. `Ctrl+S` (XOFF) приостанавливает вывод, `Ctrl+Q` (XON) возобновляет. Часто конфликтует с поиском по истории.
- **Job Control** — механизм оболочки для управления несколькими активными задачами (jobs) в рамках одной сессии: запуск в фоне (`&`), приостановка (`Ctrl+Z`), возобновление (`fg`/`bg`), удаление из таблицы jobs (`disown`).
- **History Expansion** — механизм подстановки элементов истории перед выполнением команды (`!!`, `!$`, `^old^new`). Обрабатывается оболочкой до выполнения, не требует внешних утилит.
- **Readline Completion** — механизм автодополнения команд, путей, переменных и опций по нажатию `Tab`. В Bash управляется через Readline, в Zsh — через `compinit` и `compadd`.

## Базовые концепции

### Управление процессами и терминалом

Эти сочетания обычно обрабатываются драйвером TTY и работают до того, как команда получит ввод.

| Комбинация | Действие | Описание |
| :--- | :--- | :--- |
| **`Ctrl + C`** | `SIGINT` | Прервать выполнение текущего процесса. |
| **`Ctrl + Z`** | `SIGTSTP` | Приостановить процесс и вернуть управление терминалом. Процесс можно возобновить командой `fg` (передний план) или `bg` (фоновый режим). |
| **`Ctrl + D`** | `EOF` / `SIGHUP` | Посылает символ конца файла. Если строка пуста — завершает текущую сессию shell, отправляя `SIGHUP` всем фоновым задачам (они завершатся, если не защищены `nohup`/`disown`). |
| **`Ctrl + L`** | `clear` | Очистить экран. В отличие от команды `clear`, сохраняет текущую строку ввода. |
| **`Ctrl + S`** | `XOFF` | Приостановить вывод в терминал (Stop Output). Полезно для "заморозки" быстро бегущего текста. |
| **`Ctrl + Q`** | `XON` | Возобновить вывод в терминал после `Ctrl + S`. |
| **`Ctrl + \`** | `SIGQUIT` | Принудительно завершить процесс с созданием дампа памяти (Core Dump). |
| **`Ctrl + G`** | `Abort` | Прервать текущую операцию редактирования или инкрементальный поиск. |

### Фоновый режим выполнения команд

#### Запуск в фоновом режиме (`&`)

Если команда выполняется долго (копирование больших объёмов данных, сетевые операции, резервное копирование), её можно запустить сразу в фоновом режиме, добавив амперсанд (`&`) в конце команды:

```bash
sleep 100 &
# [1] 12345
```

Система выводит два значения:
- **`[1]`** — порядковый номер фоновой задачи (Job ID), используемый для управления задачей через `fg`, `bg`, `jobs`.
- **`12345`** — PID (Process Identifier) процесса в системе.

**Важно:** Job ID уникален только в рамках текущей сессии терминала. При открытии нового окна или перезапуске shell нумерация начинается заново. В отличие от PID, Job ID не является глобальным идентификатором системы.

После запуска терминал остаётся свободным для ввода других команд, а фоновая задача выполняется незаметно.

#### Приостановка и отправка в фон (`Ctrl+Z`)

Если команда уже запущена и заблокировала терминал, её можно приостановить комбинацией `Ctrl+Z`:

```bash
sleep 100
^Z
# [1]+  Stopped                 sleep 100
```

`Ctrl+Z` отправляет сигнал `SIGTSTP` (Terminal Stop), который:
- Мгновенно приостанавливает выполнение процесса (замораживает его).
- Возвращает управление терминалу.
- **Не завершает** процесс — в отличие от `Ctrl+C` (`SIGINT`), который уничтожает процесс.

После приостановки задачу можно:
- Возобновить в фоновом режиме: `bg`
- Вернуть в передний план: `fg`
- Оставить в приостановленном состоянии и продолжить работу в терминале

#### Разница между Ctrl+C и Ctrl+Z

| Комбинация | Сигнал | Действие | Когда использовать |
| :--- | :--- | :--- | :--- |
| **`Ctrl+C`** | `SIGINT` | Завершение процесса | Команда больше не нужна, нужно прервать выполнение |
| **`Ctrl+Z`** | `SIGTSTP` | Приостановка процесса | Нужно временно освободить терминал, но позже продолжить выполнение |

**Важно:** На экзаменах LPIC-1 и аналогичных проверяют это различие. `Ctrl+C` убивает процесс, `Ctrl+Z` — замораживает.

#### Управление фоновыми задачами

| Команда | Описание |
| :--- | :--- |
| `jobs` | Список задач текущей сессии терминала |
| `jobs -l` | Список задач с отображением PID |
| `fg %N` | Вернуть задачу N в передний план |
| `bg %N` | Возобновить задачу N в фоновом режим |
| `kill %N` | Завершить задачу N |
| `disown -h %N` | Удалить задачу N из таблицы jobs и запретить получение `SIGHUP` при выходе |
| `disown -a` | Удалить все задачи из таблицы jobs |

```bash
sleep 100 &
# [1] 12345

jobs
# [1]+  Running                 sleep 100 &

# Приостановить и отправить в фон (если задача в переднем плане)
^Z
# [1]+  Stopped                 sleep 100

bg
# [1]+ sleep 100 &

# Вернуть в передний план
fg
# sleep 100
```

#### Защита фоновых задач от SIGHUP (`nohup` и `disown`)

При закрытии терминала или разрыве SSH-сессии оболочка отправляет всем фоновым задачам сигнал `SIGHUP`, что приводит к их завершению. Для долгих операций (бэкапы, миграции, сборка артефактов) это недопустимо.

**`nohup`** — утилита, запускающая команду с игнорированием `SIGHUP` и перенаправляющая вывод в `nohup.out` (если не указан другой файл):

```bash
nohup /opt/scripts/backup.sh > /var/log/backup.log 2>&1 &
# [1] 12345
# nohup: ignoring input and appending output to 'nohup.out'
```

**`disown`** — встроенная команда Bash/Zsh, удаляющая задачу из таблицы jobs текущей оболочки:

```bash
sleep 1000 &
# [1] 12345

# Защищаем задачу от SIGHUP
disown -h %1

# Теперь можно безопасно выходить
exit
```

**Разница:**
- `nohup` устанавливает обработчик сигнала **до** запуска процесса.
- `disown` изменяет состояние задачи **в уже запущенном** процессе.
- `disown` без `-h` также предотвращает отправку `SIGHUP`, но `-h` оставляет задачу в состоянии Running/Stopped в таблице jobs (без `-h` задача удаляется из jobs полностью).

> **SRE-заметка:** `nohup` перенаправляет вывод в `nohup.out` по умолчанию. В production-скриптах всегда явно перенаправляйте stdout/stderr в нужные файлы, чтобы не засорять рабочие директории.

### Настройка терминала (`stty`)

Утилита `stty` управляет параметрами терминального устройства (TTY). В отличие от Readline-шорткатов, она работает на уровне драйвера терминала и влияет на обработку всех входных символов.

```bash
# Просмотр текущих настроек
stty -a

# Отключение XON/XOFF flow control (чтобы Ctrl+S работал для поиска по истории)
stty -ixon

# Сброс к разумным настройкам по умолчанию
stty sane

# Отключение эха (полезно для ввода паролей в скриптах)
stty -echo

# Включение эха
stty echo
```

**Практическое применение для Sysadmin:**
- **Serial console:** При работе с железом через COM-порт (IPMI, iDRAC, iLO) часто требуется ручная настройка скорости и параметров:
  ```bash
  # Настройка для подключения к serial console через screen
  screen /dev/ttyUSB0 115200
  # Или через minicom с предварительной настройкой stty
  stty 115200 cs8 -cstopb -parench < /dev/ttyUSB0
  ```
- **Диагностика:** Если терминал "глючит" после запуска бинарника (например, `cat` бинарного файла), восстановление:
  ```bash
  # Сброс всех модификаций терминала
  reset
  ```
- **Raw mode:** Для передачи "сырых" данных без интерпретации (например, при отладке последовательных протоколов):
  ```bash
  stty raw -echo < /dev/ttyS0
  ```

### Навигация по командной строке

| Комбинация | Действие |
| :--- | :--- |
| **`Ctrl + A`** | Перейти в начало строки. |
| **`Ctrl + E`** | Перейти в конец строки. |
| **`Alt + B`** | Перейти на одно слово назад (назад). |
| **`Alt + F`** | Перейти на одно слово вперед (вперед). |
| **`Ctrl + F`** | Перейти на один символ вперед. |
| **`Ctrl + B`** | Перейти на один символ назад. |
| **`Ctrl + XX`** | Прыжок между текущей позицией курсора и началом строки. |

### Редактирование текста

| Комбинация | Действие |
| :--- | :--- |
| **`Ctrl + U`** | Удалить текст от курсора до начала строки (в Bash) или всю строку (в Zsh). |
| **`Ctrl + K`** | Удалить текст от курсора до конца строки. |
| **`Ctrl + W`** | Удалить слово перед курсором (граница — пробел). |
| **`Alt + D`** | Удалить слово после курсора. |
| **`Alt + Backspace`** | Удалить слово перед курсором (граница — спецсимволы). |
| **`Ctrl + Y`** | Вставить (yank) последний удаленный фрагмент текста (из kill-ring). |
| **`Ctrl + H`** | Удалить символ перед курсором (аналог Backspace). |
| **`Ctrl + D`** | Удалить символ под курсором (если строка не пуста). |
| **`Ctrl + T`** | Поменять местами символ под курсором и символ перед ним (Transpose). |
| **`Alt + T`** | Поменять местами текущее слово и предыдущее. |
| **`Ctrl + _`** | Отменить последнее действие (Undo). |
| **`Alt + C`** | Сделать заглавной первую букву текущего слова и перейти к следующему. |
| **`Alt + U`** | Перевести слово после курсора в ВЕРХНИЙ регистр. |
| **`Alt + L`** | Перевести слово после курсора в нижний регистр. |
| **`Alt + #`** | Добавить `#` в начало строки (закомментировать) и отправить в историю. |
| **`Ctrl + X, Ctrl + E`** | Открыть текущую команду в `$EDITOR` для сложного редактирования. |

### Работа с историей и подстановками

| Комбинация / Команда | Действие |
| :--- | :--- |
| **`Ctrl + R`** | Обратный инкрементальный поиск по истории. |
| **`Ctrl + S`** | Прямой инкрементальный поиск (часто требует `stty -ixon`). |
| **`Ctrl + P`** | Предыдущая команда в истории (аналог стрелки вверх). |
| **`Ctrl + N`** | Следующая команда в истории (аналог стрелки вниз). |
| **`Alt + .`** или **`Alt + _`** | Вставить последний аргумент предыдущей команды. |
| **`Ctrl + O`** | Выполнить текущую команду и вывести следующую из истории (удобно для циклов). |
| **`!!`** | Выполнить последнюю команду целиком. |
| **`!$`** | Последний аргумент последней команды. |
| **`!*`** | Все аргументы последней команды. |
| **`^old^new`** | Повторить последнюю команду, заменив `old` на `new`. |
| **`history`** | Вывести список истории с номерами. |
| **`history -d N`** | Удалить команду с номером N из истории (без выполнения). |
| **`history -w`** | Принудительно записать текущую сессию в `$HISTFILE`. |
| **`history -r`** | Прочитать `$HISTFILE` в текущую сессию. |
| **`history -a`** | Добавить новые команды текущей сессии в `$HISTFILE`. |
| **`fc`** | Открыть последнюю команду в `$EDITOR` для повторного запуска или редактирования. |
| **`fc -l`** | Вывести последние команды без редактирования. |
| **`fc -s`** | Выполнить последнюю команду, подставив изменения (например, `fc -s old=new`). |

#### Переменные окружения истории

```bash
# Размер истории в памяти и на диске
export HISTSIZE=10000
export HISTFILESIZE=20000

# Игнорировать дубликаты и команды с ведущим пробелом
export HISTCONTROL=ignoreboth

# Игнорировать конкретные команды
export HISTIGNORE="ls:cd:cd -:pwd:exit:date:* --help"

# Добавлять время выполнения к каждой команде
export HISTTIMEFORMAT="%F %T "

# Файл истории
export HISTFILE=~/.bash_history

# Автоматически дописывать историю после каждой команды (для нескольких сессий)
shopt -s histappend
PROMPT_COMMAND='history -a'

# Не сохранять команды, начинающиеся с пробела (удобно для чувствительных данных)
export HISTCONTROL=ignorespace
```

> **SRE-заметка:** В shared-средах (sudo su -, tmux sessions) `histappend` + `PROMPT_COMMAND='history -a'` гарантирует, что команды из разных сессий не теряются. Для аудита комбинируйте `HISTTIMEFORMAT` с централизованным сбором `.bash_history`.

#### Очистка чувствительных команд

```bash
# Удалить последнюю команду из истории
history -d $((HISTCMD-1))

# Очистить всю историю текущей сессии
history -c

# Полностью запретить запись истории в текущей сессии
unset HISTFILE
```

> **Важно:** `history -c` не трогает файл на диске. Чтобы очистить и файл: `echo > ~/.bash_history && history -c && exit`.

#### Подстановка аргументов через Alt+.

```bash
# Создать директорию и перейти в неё
mkdir -p /etc/nginx/conf.d/vhosts
cd !$
# cd /etc/nginx/conf.d/vhosts

# Использовать последний аргумент предыдущей команды
cp /var/log/syslog /tmp/backup/
ls -l !$
# ls -l /tmp/backup/
```

### Автодополнение (Completion)

Нажатие `Tab` в пустой позиции или после части имени команды/пути/переменной запускает механизм автодополнения. Повторное нажатие `Tab` (если вариантов несколько) выводит список всех совпадений.

**Уровни автодополнения:**
1. **Команды:** Имена бинарных файлов из `$PATH`, алиасы, builtins, функции.
2. **Пути:** Автодополнение файлов и директорий с учетом `~`, переменных (`$VAR`), подстановки `~user`.
3. **Переменные:** Автодополнение `${VAR}` по `Tab`.
4. **Опции команд:** Зависит от конкретного инструмента (например, `git <Tab>` показывает `clone`, `pull`, `push`).

**Bash Readline Completion:**
```bash
# Включить показ всех вариантов сразу (вместо звучка)
set show-all-if-ambiguous on

# Игнорировать регистр при автодополнении
set completion-ignore-case on
```

**Zsh Completion (`compinit`):**
В Zsh автодополнение мощнее и работает из коробки для большинства CLI-утилит. Если не работает:
```bash
# Перегенерация кэша автодополнения
rm -f ~/.zcompdump*
compinit
```

### Kill-ring и продвинутое редактирование

Readline хранит удаленный текст в кольцевом буфере (kill-ring), позволяя извлекать не только последнее удаление, но и предыдущие.

| Комбинация | Действие |
| :--- | :--- |
| **`Ctrl + Y`** | Вставить (yank) последний удаленный фрагмент текста. |
| **`Alt + Y`** | После `Ctrl+Y` — заменить вставленный текст на более ранний элемент kill-ring (циклический переход). |
| **`Ctrl + Alt + Y`** | После `Ctrl+Y` — заменить на следующий элемент kill-ring без смены позиции. |
| **`Alt + 0`..`Alt + 9`** | Указать числовой аргумент для следующей команды (например, `Alt+5` + `Ctrl+D` удалит 5 символов). |

**Практический пример:**
```bash
# Вводим длинную команду
scp /var/www/html/user_documentation.pdf deploy@backup-server:/mnt/backup/

# Замечаем опечатку в середине, удаляем до курсора
^U
# Вся строка удалена в kill-ring

# Вставляем первую часть
scp 
# вставляем /var/www/html/ (если сохранили ранее)

# Но нужно не это, а старое значение — переключаем kill-ring
^Y → Alt+Y → Alt+Y
# Появится нужный фрагмент
```

## Практические сценарии

### Управление фоновыми задачами

Ситуация: запущена долгая команда, терминал заблокирован.

```bash
# Запуск долгой команды
sleep 100
# Терминал заблокирован...

# Приостановка и освобождение терминала
^Z
# [1]+  Stopped                 sleep 100

# Просмотр списка задач
jobs -l
# [1]+ 12345 Stopped (signal)        sleep 100

# Возобновление в фоновом режиме
bg
# [1]+ sleep 100 &

# Терминал свободен, задача выполняется в фоне
echo "Работаем дальше"
# Работаем дальше

# Возврат задачи в передний план (когда нужен результат)
fg
# sleep 100
```

### Запуск команды сразу в фоне

```bash
# Если известно, что команда долгая — запускаем сразу в фоне
sleep 100 &
# [1] 12345

# Терминал свободен сразу
ls -la
# ... вывод команды ...

# Проверка статуса фоновой задачи
jobs
# [1]+  Running                 sleep 100 &
```

### SRE: Долгая операция при обрыве SSH (`nohup` + `disown`)

Ситуация: нужно запустить бэкап, миграцию данных или длительный тест на удаленном сервере. При разрыве SSH обычные фоновые задачи завершатся (`SIGHUP`).

```bash
# Запуск с защитой от SIGHUP
nohup /opt/scripts/backup.sh > /var/log/backup.log 2>&1 &
# [1] 54321

# Или, если команда уже запущена в фоне:
sleep 1000 &
disown -h %1

# Теперь можно безопасно разрывать SSH
exit
```

> **Важно:** `nohup` по умолчанию пишет в `nohup.out`. В production всегда перенаправляйте вывод явно.

### SRE: Перехват забытого процесса (`reptyr`)

Ситуация: запустили долгую команду без `tmux`/`screen`, SSH обрывается. Утилита `reptyr` перехватывает процесс в текущий терминал.

```bash
# На старом терминале (который скоро закроется)
# Узнаем PID процесса
ps aux | grep long_running_task

# На новом терминале (в tmux или просто новом SSH)
sudo apt install reptyr
reptyr <PID>
```

> **См. также:** [Утилита `reptyr`](../Diagnostics/Processes/reptyr.md) — подробнее о перехвате процессов.

### SRE: Graceful shutdown скрипта (`trap` + `kill`)

Ситуация: скрипт запускает дочерние процессы (например, несколько инстансов утилиты). При `Ctrl+C` или `kill` нужно корректно очистить всех "детей".

```bash
#!/bin/bash
set -m

CHILDREN_PIDS=()

cleanup() {
    echo "Остановка дочерних процессов..."
    kill -TERM "${CHILDREN_PIDS[@]}" 2>/dev/null
    wait "${CHILDREN_PIDS[@]}" 2>/dev/null
    echo "Очистка завершена."
    exit 0
}

trap cleanup EXIT INT TERM

for i in {1..3}; do
    /usr/bin/long_task --param $i &
    CHILDREN_PIDS+=($!)
done

wait
```

> **См. также:** [Обработка сигналов и `trap`](./bash_signal_traps.md) — детали перехвата сигналов в Bash.

### SRE: Безопасная работа с историей

Ситуация: необходимо выполнить команду с паролем или токеном, не оставляя её в `.bash_history`.

```bash
# Способ 1: ведущий пробел (если HISTCONTROL=ignorespace)
 apt update -y

# Способ 2: отключение истории на одну команду
bash -c 'export HISTFILE=/dev/null; export HISTSIZE=0; curl -H "Authorization: Bearer SECRET" ...'

# Способ 3: удаление последней команды из истории
history -d $((HISTCMD-1))
```

```bash
# Повторить последнюю команду, заменив часть строки

# Нашли, что нужно искать WARN
```

### SRE: Диагностика терминала через `stty`

Ситуация: при подключении к serial console (IPMI/iDRAC) терминал отображает мусор или не реагирует на ввод.

```bash
# Проверка текущих настроек
stty -a

# Сброс к стандартным параметрам (9600 8N1 — частое значение по умолчанию)
stty sane 9600 < /dev/ttyS0

# Если нужно явно задать параметры
stty 115200 cs8 -cstopb -parenb < /dev/ttyUSB0
screen /dev/ttyUSB0 115200
```

### SRE: Использование `tmux` как альтернативы job control

При долгих операциях `tmux` надежнее, чем `nohup` + `&`, потому что сохраняет полное состояние терминала (включая интерактивные утилиты).

```bash
# Создать сессию и запустить команду
tmux new -s maintenance -d "tail -f /var/log/syslog"

# Подключиться потом
tmux attach -t maintenance

# Отключиться без остановки (Prefix = Ctrl+B, затем d)
tmux detach

# Список сессий
tmux ls
```

> **См. также:** [Управление персистентными SSH-сессиями](../../Security/ssh/ssh_session_management.md) — tmux, screen, tmate.

### Экзаменационный сценарий: выбор команды управления задачами

При решении тестовых вопросов важно различать команды по назначению:

| Задача | Команда |
| :--- | :--- |
| Вернуть процесс на передний план | `fg` |
| Показать список фоновых задач | `jobs` |
| Продолжить выполнение приостановленной задачи в фоне | `bg` |
| Завершить задачу по её номеру | `kill %N` |
| Удалить задачу из таблицы jobs (защита от SIGHUP) | `disown -h %N` |
| Запустить команду, игнорирующую SIGHUP | `nohup команда &` |

**Пример вопроса:** Для запуска приостановленной задачи в фоновом режиме используется команда `bg`. `fg` возвращает задачу в передний план, `jobs` только отображает список, а `continue` в Bash отсутствует.

### Быстрое исправление опечаток
Если вы ввели `sl -l /var/log` вместо `ls`:
```bash
$ sl -l /var/log
# Ошибка: command not found
$ ^sl^ls
# Выполнит: ls -l /var/log
```

### Использование `sudo` для последней команды
```bash
$ apt update
# Ошибка: Permission denied
$ sudo !!
```

### Навигация и создание структур
Создать директорию и сразу перейти в неё:

```bash
$ mkdir -p /etc/nginx/conf.d/vhosts
$ cd !$
```

### Отключение блокировки экрана (`Ctrl+S`)
Чтобы `Ctrl+S` работал для поиска в истории, а не "замораживал" терминал, добавьте в `~/.bashrc` или `~/.zshrc`:
```bash
# Отключает XON/XOFF flow control

```

Если вы пишете длинный конвейер (pipeline) и понимаете, что запутались, нажмите `Ctrl + X, Ctrl + E`. После сохранения файла в редакторе команда будет выполнена автоматически.

### Тонкая настройка через `.inputrc`

Библиотека Readline настраивается через файл `~/.inputrc`. Пример полезных настроек:
```bash
# Игнорировать регистр при автодополнении
set completion-ignore-case on

# Показывать все варианты дополнения сразу
set show-all-if-ambiguous on

# Поиск по истории с учетом уже введенного текста (стрелками)
"\e[A": history-search-backward
"\e[B": history-search-forward

# Удобные сочетания для word-boundary навигации (как в Bash)
"\e[1;5C": forward-word    # Ctrl+Right
"\e[1;5D": backward-word   # Ctrl+Left

# Включить меню автодополнения (Tab переключает варианты)
set menu-complete-display-prefix on
"\e[Z": menu-complete-backward  # Shift+Tab
```

### Тонкая настройка Zsh (`~/.zshrc`)

```bash
# Vi-mode
bindkey -v

# Автодополнение
autoload -U compinit && compinit
zstyle ':completion:*' menu select
zstyle ':completion:*' matcher-list 'm:{a-z}={A-Z}'  # ignore-case

# История
setopt HIST_IGNORE_ALL_DUPS   # удалять дубликаты
setopt HIST_FIND_NO_DUPS       # не показывать дубли при поиске
setopt HIST_SAVE_NO_DUPS       # не сохранять дубли в файл
setopt SHARE_HISTORY           # синхронизировать между сессиями
setopt EXTENDED_HISTORY        # сохранять время выполнения

# Удобные клавиши
bindkey '^R' history-incremental-search-backward
bindkey '^S' history-incremental-search-forward
bindkey '^A' beginning-of-line
bindkey '^E' end-of-line
bindkey '^K' kill-line
bindkey '^U' backward-kill-line
bindkey '^Y' yank
bindkey "^X^E" edit-command-line
```

### Serial console и `screen`/`minicom`

При работе с удаленным оборудованием через IPMI/iDRAC/iLO или простым COM-портом настройка терминала критична. Обычно требуется:
- Скорость: 9600, 19200, 57600 или 115200 бод.
- Формат: 8 данных бит, нет четности, 1 стоп-бит (8N1).

```bash
# Быстрый доступ через screen
screen /dev/ttyUSB0 115200
# Выход из screen: Prefix (Ctrl+A) + K

# Через minicom (с конфигурацией)
minicom -b 115200 -o -D /dev/ttyUSB0
```

Если терминал "засоряется" бинарным выводом, восстановите настройки:
```bash
reset
```

### Безопасность истории команд

В shared-средах (RDP, sudo su -, групповые серверы) история команд содержит чувствительные данные.

```bash
# Запретить запись истории в текущей сессии
unset HISTFILE

# Очистить историю текущей сессии
history -c

# Не сохранять команды, начинающиеся с пробела (Sensitive)
export HISTCONTROL=ignorespace

# Игнорировать дубликаты
export HISTCONTROL=ignoredups

# Игнорировать и то, и другое
export HISTCONTROL=ignoreboth

# Исключать из истории конкретные шаблоны
export HISTIGNORE="ls*:cd*:history*:exit*:git*"

# Удалить конкретную строку из истории текущей сессии
history -d <номер>
```

> **SRE-заметка:** Для соответствия compliance-требованиям (PCI-DSS, SOC2) настройте централизованный сбор `.bash_history` через auditd или rsyslog. Для привилегированных пользователей (root) используйте `script` или `scriptreplay` для записи полных сессий.
