# Экранирование и использование кавычек в Shell

## Определения

* **Экранирование (Quoting)** — механизм управления интерпретацией специальных символов оболочкой. Он определяет, будет ли символ обработан Shell (например, `$` как начало имени переменной) или воспринят как обычный текстовый символ (литерал).
* **Разбиение на слова (Word Splitting)** — процесс разделения строки на отдельные аргументы на основе символов-разделителей (по умолчанию: пробел, табуляция, новая строка). Контролируется переменной `IFS` (Internal Field Separator).
* **Глоббинг (Globbing)** — механизм подстановки имен файлов на основе шаблонов (метасимволы `*`, `?`, `[...]`).

## Базовые концепции

### Основные механизмы экранирования

| Механизм | Символы | Описание | Пример |
| :--- | :--- | :--- | :--- |
| **Одинарные кавычки** | `'...'` | Буквальная интерпретация всех символов внутри. Любые подстановки отключены. | `'$HOME'` → `$HOME` |
| **Двойные кавычки** | `"..."` | Частичная интерпретация. Подстановки `$`, `` ` ``, `\` и `!` остаются активными. | `"$HOME"` → `/home/user` |
| **Обратный слэш** | `\` | Экранирование следующего за ним одиночного символа. | `\$` → `$` |
| **ANSI-C Quoting** | `$'...'` | Интерпретация escape-последовательностей в стиле C (например, `\n`, `\t`). | `$'\n'` → новая строка |
| **Локализация** | `$"..."` | Перевод строки на текущий язык системы (если есть перевод). В обычном режиме ведет себя как двойные кавычки. | `$"Error"` → `Ошибка` |

### Поведение внутри двойных кавычек

Внутри двойных кавычек оболочка продолжает обрабатывать:
* `$` — подстановка переменных и результат выполнения команд `$(...)`.
* `` ` `` — устаревший формат подстановки команд.
* `\` — экранирует только символы `$`, `` ` ``, `"`, `\` и символ новой строки.
* `!` — история команд (только в интерактивном режиме).

### Экранирование в Heredoc и Herestring

Поведение Heredoc (`<<EOF`) зависит от того, экранирован ли ограничитель:
* **Без кавычек (`<<EOF`)**: переменные и команды внутри блока расширяются.
* **С кавычками (`<<'EOF'` или `<<"EOF"`)**: весь блок воспринимается буквально, подстановки отключены.

### Сравнение [ ... ] и [[ ... ]]

* В классическом тесте `[ "$VAR" = "val" ]` кавычки вокруг переменной **обязательны**, иначе при пустом значении возникнет синтаксическая ошибка.
* В расширенном тесте `[[ $VAR == "val" ]]` кавычки **необязательны** для простых переменных, так как `[[` подавляет word splitting. Однако они нужны справа от `==`, если нужно избежать сопоставления по шаблону (globbing).

## Практические сценарии

### Предотвращение разбиения на слова (Word Splitting)

Всегда используйте двойные кавычки при обращении к переменным, содержащим пути или имена файлов с пробелами.

```bash
FILE_NAME="my report.txt"

# ОШИБКА: rm воспримет это как два файла "my" и "report.txt"
rm $FILE_NAME 

# ПРАВИЛЬНО: rm получит один аргумент "my report.txt"
rm "$FILE_NAME"
```

### Безопасное экранирование данных для повторного использования

В Bash 4.4+ введен флаг `${VAR@Q}`, который возвращает значение переменной, уже экранированное для безопасного использования в качестве входных данных Shell.

```bash
USER_INPUT="'; rm -rf /; '"
SAFE_INPUT=${USER_INPUT@Q}
echo "Команда будет: echo $SAFE_INPUT"
# Результат: Команда будет: echo ''\''; rm -rf /; '\''/
```

### Обработка массивов

Различие между `"$*"` и `"$@"` критично при работе с массивами и аргументами скрипта.

```bash
args=("arg 1" "arg 2")

# "$*" — всё в одну строку: "arg 1 arg 2"
printf "[%s]\n" "${args[*]}"

# "$@" — сохраняет каждый элемент отдельно: "arg 1" "arg 2"
printf "[%s]\n" "${args[@]}"
```

### Вложенные кавычки

При вложении подстановок команд `$(...)` кавычки внутри них независимы от внешних.

```bash
# Внутренние кавычки вокруг $file не конфликтуют с внешними
result="$(grep "pattern" "$(ls "$dir")")"
```

## Дополнительная информация

### Риски использования eval

Использование `eval` часто требует сложного "многослойного" экранирования и несет риски инъекции команд, если входные данные не были должным образом обработаны (например, через `${VAR@Q}`).

### Типичные ошибки

| Ошибка | Последствие | Исправление |
| :--- | :--- | :--- |
| `echo $VAR` | Ошибка при наличии пробелов или спецсимволов в $VAR | `echo "$VAR"` |
| `echo 'Don't do this'` | Синтаксическая ошибка (незакрытая кавычка) | `"Don't do this"` или `'Don'\''t do this'` |
| `[[ "$VAR" == *.txt ]]` | Сопоставление со строкой "*.txt" буквально | `[[ "$VAR" == *.txt ]]` (без кавычек для шаблона) |
