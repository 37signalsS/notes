# Экранирование и использование кавычек в Shell

## Определения

* **Экранирование (Quoting)** — механизм управления интерпретацией специальных символов в командной строке. Определяет, будет ли символ обработан оболочкой (например, `$` как переменная) или воспринят буквально.
* **Word Splitting** — разбиение строки на отдельные аргументы по символам разделителей (пробел, табуляция, новая строка).
* **Globbing** — подстановка шаблонов имен файлов (`*`, `?`, `[...]`).

## Основные концепции

### Механизмы экранирования

| Механизм | Символы | Интерпретация | Пример |
|----------|---------|---------------|--------|
| **Одинарные кавычки** | `'...'` | Буквальная, нет подстановок | `'$HOME'` → `$HOME` |
| **Двойные кавычки** | `"..."` | Частичная, `$`, `` ` ``, `\` активны | `"$HOME"` → `/home/user` |
| **Обратный слэш** | `\` | Экранирование одного символа | `\$` → `$` |
| **ANSI-C Quoting** | `$'...'` | Escape-последовательности C | `$'\n'` → новая строка |

### Поведение в двойных кавычках

Символы, сохраняющие специальное значение:

* `$` — подстановка переменных ([`shell_variables.md`](./shell_variables.md)).
* `` ` `` (обратные кавычки) — подстановка команд.
* `\` — экранирование `$`, `` ` `", `"`.

### Word Splitting и безопасность

Ключевая роль двойных кавычек — предотвращение неконтролируемого разбиения на слова.

**Проблема:**

```bash
FILE_WITH_SPACES="my report.docx"
ls -l $FILE_WITH_SPACES  # Ошибка: два аргумента 'my' и 'report.docx'
```

**Решение:**

```bash
ls -l "$FILE_WITH_SPACES"  # Корректно: один аргумент
```

**Безопасная практика:** всегда заключать переменные в двойные кавычки (`"$VAR"`).

## Практические сценарии

### Буквальная строка

```bash
# Без подстановок
echo 'Переменная $HOME не будет раскрыта, как и `date`'
# Вывод: Переменная $HOME не будет раскрыта, как и `date`
```

### Подстановка переменных и команд

```bash
# С подстановками
echo "Привет, $USER! Сегодня $(date)."
# Вывод: Привет, q! Сегодня Чт фев 5 12:34:56 UTC 2026.
```

### Экранирование внутри двойных кавычек

```bash
# Вывод символа '$' как есть
echo "Стоимость товара: \$100"
# Вывод: Стоимость товара: $100
```

### Экранирование пробелов и спецсимволов

```bash
# Создание файла с пробелом в имени
touch "my new file.txt"
# или
touch my\ new\ file.txt
```

### Включение одинарной кавычки в строку

```bash
# Выход из одинарных, добавление кавычки, возврат
echo 'Это строка, содержащая одинарную кавычку.'"'"'
# Вывод: Это строка, содержащая одинарную кавычку.'
```

### ANSI-C Quoting

```bash
# Escape-последовательности в стиле C
echo $'Первая строка\nВторая строка\tТабуляция'
# Вывод:
# Первая строка
# Вторая строка Табуляция
```

**Поддерживаемые последовательности:**

* `\n` — новая строка
* `\t` — табуляция
* `\r` — возврат каретки
* `\\` — обратный слэш
* `\x41` — шестнадцатеричное значение

## Дополнительная информация

### Сравнительная таблица

| Конструкция | `$VAR` | `$(cmd)` | `\` | Globbing |
|-------------|--------|----------|-----|----------|
| `'строка'` | Нет | Нет | Нет | Нет |
| `"строка"` | **Да** | **Да** | Да (частично) | Нет |
| `\символ` | — | — | **Да** | — |
| `$'строка'` | Нет | Нет | **Да** (ANSI-C) | Нет |

### Частые ошибки

| Ошибка | Последствие | Исправление |
|--------|-------------|-------------|
| `$HOME` vs `'$HOME'` | подстановка vs буквальный текст | выбрать нужный механизм |
| `"$@"` vs `$@` | корректная передача аргументов | всегда `"$@"` |
| `*` vs `"*"` | globbing vs буквальная звёздочка | экранировать при необходимости |
