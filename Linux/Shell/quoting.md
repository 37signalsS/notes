# Экранирование и использование кавычек в Shell

## Определения

* **Экранирование (Quoting)** — это механизм, позволяющий управлять интерпретацией специальных символов в командной строке. Он определяет, будет ли символ обработан оболочкой (например, `$` как начало переменной) или воспринят буквально.

## Основные концепции

В Shell существуют три основных механизма экранирования:

### 1. Одинарные кавычки (`' '`) — Строгая/буквальная интерпретация

* **Поведение:** Все символы, заключенные в одинарные кавычки, теряют свое специальное значение и интерпретируются **буквально**.
* **Исключение:** Внутри одинарных кавычек невозможно использовать сам символ одинарной кавычки.

### 2. Двойные кавычки (`" "`) — Частичная интерпретация

* **Поведение:** Большинство символов воспринимаются буквально, но некоторые сохраняют специальное значение и обрабатываются оболочкой.
* **Обрабатываемые символы:**
  * `$`: Для подстановки переменных (`$HOME`).
  * `` ` `` (обратные кавычки): Для [подстановки команд](bash_command_execution.md#подстановка-команд-и-процессов).
  * `\` (обратный слэш): Для экранирования символов `$` и `"` внутри двойных кавычек.

### 3. Обратный слэш (`\`) — Экранирование одного символа

* **Поведение:** Убирает специальное значение у **одного** следующего за ним символа.

## Практические сценарии

* **Буквальная строка:**

    ```bash
    # '$HOME' будет выведен как текст, а не заменен на путь
    echo 'Переменная $HOME не будет раскрыта, как и `date`'
    # Вывод: Переменная $HOME не будет раскрыта, как и `date`
    ```

* **Подстановка переменных и команд:**

    ```bash
    # $USER будет заменен на имя пользователя, а $(date) — на текущую дату
    echo "Привет, $USER! Сегодня $(date)."
    # Пример вывода: Привет, q! Сегодня Чт фев  5 12:34:56 UTC 2026.
    ```

* **Экранирование внутри двойных кавычек:**

    ```bash
    # Чтобы вывести символ '$' как есть
    echo "Стоимость товара: \$100"
    # Вывод: Стоимость товара: $100
    ```

* **Экранирование пробелов и спецсимволов:**

    ```bash
    # Создание файла с пробелом в имени
    touch "my new file.txt"
    # или
    touch my\ new\ file.txt
    ```

* **Включение одинарной кавычки в строку:**

    ```bash
    echo 'Это строка, содержащая одинарную кавычку.'"'"
    # Вывод: Это строка, содержащая одинарную кавычку.'
    ```

* **Предотвращение разбиения на слова (Word Splitting):**

    Ключевая роль двойных кавычек — предотвращение неконтролируемого "разбиения на слова" (word splitting). Если переменная содержит пробелы, без кавычек оболочка передаст каждое слово как отдельный аргумент команде.

    ```bash
    FILE_WITH_SPACES="my report.docx"

    # Неправильно: команда 'ls -l' получит два аргумента: 'my' и 'report.docx'.
    # Это приведет к ошибке, если файла 'my' не существует.
    ls -l $FILE_WITH_SPACES

    # Правильно: команда 'ls -l' получит один аргумент: "my report.docx".
    ls -l "$FILE_WITH_SPACES"
    ```
    Это критически важно при работе с путями к файлам. **Безопасная практика — всегда заключать переменные в двойные кавычки (`"$VAR"`)**.

## Дополнительная информация

| Конструкция | Подстановка переменных (`$VAR`) | Подстановка команд (`$(cmd)`) | Интерпретация `\` |
| :--- | :---: | :---: | :---: |
| `'строка'` | Нет | Нет | Нет |
| `"строка"` | **Да** | **Да** | **Да** (только для `\`, `$`, `"`) |
| `\символ` | (не применимо) | (не применимо) | **Да** |

* **Подстановка команд:** Для получения более подробной информации о конструкциях `$(...)` и `` `...` `` см. документ [Логика обработки команд в Shell](bash_command_execution.md#подстановка-команд-и-процессов).
* **ANSI-C Quoting (`$'...'`):** Существует расширенный синтаксис `$'...'`, который позволяет интерпретировать escape-последовательности в стиле языка Си (например, `\n` для новой строки, `\t` для табуляции).

    ```bash
    echo $'Первая строка\nВторая строка'
    # Вывод:
    # Первая строка
    # Вторая строка
    ```
