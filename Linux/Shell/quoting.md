# Экранирование и использование кавычек в Shell

## Определения

* **Экранирование (Quoting)** — механизм управления интерпретацией специальных символов оболочкой. Определяет, будет ли символ обработан Shell (например, `$` как начало имени переменной) или воспринят как обычный текстовый символ (литерал).
* **Разбиение на слова (Word Splitting)** — процесс разделения строки на отдельные аргументы на основе символов-разделителей (по умолчанию: пробел, табуляция, новая строка). Контролируется переменной `IFS` (Internal Field Separator).
* **Глоббинг (Globbing)** — механизм подстановки имен файлов на основе шаблонов (метасимволы `*`, `?`, `[...]`).

## Основные концепции

### Механизмы экранирования

| Механизм | Символы | Интерпретация | Пример |
| :--- | :--- | :--- | :--- |
| **Одинарные кавычки** | `'...'` | Буквальная интерпретация всех символов внутри. Подстановки отключены. | `'$HOME'` → `$HOME` |
| **Двойные кавычки** | `"..."` | Частичная интерпретация. Подстановки `$`, `` ` ``, `\` и `!` остаются активными. | `"$HOME"` → `/home/user` |
| **Обратный слэш** | `\` | Экранирование следующего за ним одиночного символа. | `\$` → `$` |
| **ANSI-C Quoting** | `$'...'` | Интерпретация escape-последовательностей в стиле языка C. | `$'\n'` → новая строка |

### Поведение в двойных кавычках

Внутри двойных кавычек Shell продолжает обрабатывать следующие элементы:

* `$` — подстановка значений переменных ([`shell_variables.md`](./shell_variables.md)) и результат выполнения команд `$(...)`.
* `` ` `` — устаревший формат подстановки команд (backticks).
* `\` — используется для экранирования самих символов `$`, `` ` ``, `"`, `\` и новой строки.
* `!` — история команд (если включена в интерактивном режиме).

### Word Splitting и безопасность

Одной из важнейших задач использования двойных кавычек является предотвращение нежелательного разбиения переменных на отдельные слова, если их значения содержат пробелы.

**Проблема (без кавычек):**

```bash
FILE_NAME="my report.txt"
rm $FILE_NAME
# Shell выполнит: rm "my" "report.txt" -> ошибка, если файлов два или их нет.
```

**Решение (с кавычками):**

```bash
rm "$FILE_NAME"
# Shell выполнит: rm "my report.txt" -> корректное удаление одного файла.
```

**Правило:** всегда заключайте обращения к переменным в двойные кавычки (`"$VAR"`), чтобы избежать ошибок при обработке путей и имен файлов с пробелами.

## Практические сценарии

### Буквальная строка vs Подстановка

```bash
# Одинарные кавычки: текст "как есть"
echo 'Текущий путь: $PWD'
# Результат: Текущий путь: $PWD

# Двойные кавычки: значение переменной будет подставлено
echo "Текущий путь: $PWD"
# Результат: Текущий путь: /home/user/project
```

### Экранирование внутри строк

```bash
# Вывод символа доллара в двойных кавычках
echo "Цена: \$100"
# Результат: Цена: $100

# Использование кавычек разных типов
echo "It's a beautiful day"
echo 'Он сказал: "Привет"'
```

### Экранирование в стиле ANSI-C

Используется для вставки непечатных символов:

```bash
# Вставка табуляции и новой строки
echo $'Column1\tColumn2\nRow2'

# Использование шестнадцатеричных кодов (например, 'A')
echo $'\x41'
```

### Работа с аргументами: "$@" против "$*"

Различие проявляется при передаче аргументов скрипта дальше по конвейеру или другой функции:

* **`"$@"` (рекомендуется)** — раскрывается в список аргументов, где каждый аргумент защищен кавычками: `"arg1" "arg2" "arg3"`. Сохраняет пробелы внутри аргументов.
* **`"$*"`** — раскрывается в одну строку, где все аргументы разделены первым символом `IFS` (обычно пробелом): `"arg1 arg2 arg3"`.

```bash
# Скрипт wrapper.sh
ls -l "$@"  # Передаст имена файлов с пробелами корректно
```

## Дополнительная информация

### Сравнительная таблица механизмов

| Конструкция | `$VAR` | `$(cmd)` | `\` | Globbing |
| :--- | :--- | :--- | :--- | :--- |
| `'строка'` | Нет | Нет | Нет | Нет |
| `"строка"` | **Да** | **Да** | Да (частично) | Нет |
| `\символ` | — | — | **Да** | — |
| `$'строка'` | Нет | Нет | **Да** (ANSI-C) | Нет |

### Распространенные ошибки

| Ошибка | Последствие | Исправление |
| :--- | :--- | :--- |
| `echo $VAR` | Word Splitting при наличии пробелов в значении | `echo "$VAR"` |
| `ls *.txt` | Ошибка, если имен файлов слишком много или они содержат спецсимволы | Экранируйте или используйте циклы |
| `echo 'It's me'` | Синтаксическая ошибка (незакрытая кавычка) | `"It's me"` или `'It'\''s me'` |
