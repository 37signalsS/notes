# cat и less

## Определения

**cat** (concatenate) — стандартная утилита GNU coreutils для чтения файлов и конкатенации их содержимого с выводом в стандартный поток (`stdout`). По умолчанию выводит содержимое файла(ов) целиком, от первой до последней строки.

**less** — утилита для постраничного (пейджингового) просмотра текстовых файлов. Открывает файл в режиме только чтения и позволяет перемещаться по содержимому в любом направлении без загрузки всего файла в оперативную память.

## Базовые концепции

### Принцип работы cat

`cat` последовательно считывает данные из указанных файлов и передаёт их в `stdout`. При выводе в терминал текстовый файл отображается как единый непрерывный поток.

- **Маленькие файлы** (до нескольких тысяч строк, помещающихся на один экран): `cat` удобен, так как позволяет увидеть содержимое целиком без лишних действий.
- **Большие файлы** (логи, дампы, конфиги на десятки/сотни тысяч строк): `cat` «вываливает» весь текст за долю секунды. Основной экран терминала заполняется мгновенно, и для возврата к началу файла приходится скроллить вверх, что неудобно и неэффективно.

### Принцип работы less

`less` использует постраничный режим отображения:
- Файл не выводится целиком; вместо этого терминал показывает одну страницу за другой.
- Навигация возможна стрелками, `PgUp`/`PgDn`, пробелом (вперёд на экран) и `b` (назад на экран).
- Выход из режима просмотра — клавиша `q`.
- Файл открыт в режиме только чтения: случайное изменение или сохранение невозможно.

### Сравнение cat и less

| Характеристика | `cat` | `less` |
| :--- | :--- | :--- |
| Режим вывода | Непрерывный поток | Постраничный (пейджинг) |
| Навигация | Только скроллинг терминала | Вверх/вниз, поиск, переход к строке |
| Безопасность | Может привести к случайному редактированию, если открыт в редакторе | Режим только чтения, исключает случайное изменение |
| Потребление памяти | Считывает файл последовательно, но терминал буферизирует вывод | Загружает в память только видимую часть |
| Лучший сценарий | Короткие файлы, конкатенация нескольких файлов | Длинные логи, конфиги, любой файл больше экрана |

### TTY, stdin и буферизация

**cat** работает как простой фильтр байтов: читает из файлов или `stdin` и пишет в `stdout`. Когда вывод направлен в терминал (TTY), `stdout` обычно является буферизованным по строкам; при перенаправлении в pipe или файл буферизация может быть блочной (размер зависит от реализации libc, обычно 4–8 КБ). Это означает, что `cat bigfile | grep pattern` не выводит промежуточные результаты до заполнения буфера или закрытия `stdout`.

**less** захватывает терминал через termcap/terminfo, переключает его в «сырой» режим (raw mode) и управляет отображением напрямую. Внутри `less` используется двойная буферизация:
- **Входной буфер:** считывает данные блоками (по умолчанию 64 КБ, настраивается через `-b`).
- **Экранный буфер:** хранит только видимую часть для рендеринга.

При работе с pipe (`cmd | less`) `less` не знает общего размера данных, но всё равно буферизирует вход, чтобы обеспечить плавную прокрутку назад.

### Механизм пейджинга

Пейджинг (pagging) — это техника обработки данных, при которых программа загружает и отображает только часть набора (окно), а не весь объём. `less` реализует два режима:

1. **Режим файла:** при открытии файла напрямую (`less file.txt`) утилита может использовать `mmap()` или `lseek()` для произвольного доступа к данным. Это позволяет мгновенно переходить к концу файла (`G`) или к произвольной строке.
2. **Режим pipe:** при чтении из `stdin` (`cmd | less`) `less` не может перемещаться назад за пределами буфера. Для этого он сохраняет данные во временный файл (обычно в `/tmp` или в каталог, указанный через `$LESSOPEN`/`$LESSCLOSE`). Размер этого файла равен объёму входного потока.

Навигация привязана к строкам, а не к байтам, поэтому `less` отслеживает начало каждой строки. Это позволяет искать по содержимому (`/`, `?`) и переходить по номерам строк (`123g`).

## Практические сценарии

### Чтение коротких файлов через cat

```bash
# Вывод содержимого одного файла
cat /etc/hostname
# → my-server

# Конкатенация нескольких файлов в одном выводе
cat /etc/passwd /etc/group
```

### cat в скриптах и heredocs

`cat` часто используется для создания файлов из stdin или heredoc-вставок. Это один из самых частых паттернов в инициализации систем и развёртывании конфигураций.

```bash
# Создание файла через heredoc (переменные НЕ интерполируются)
cat > /etc/ssh/sshd_config << 'EOF'
PermitRootLogin no
PasswordAuthentication no
EOF

# Переменные интерполируются без кавычек
cat > /tmp/motd.sh << EOF
#!/bin/bash
echo "Welcome to $(hostname)"
EOF

# Добавление в конец файла
cat >> /var/log/install.log << 'EOF'
Package: nginx
Status: installed
EOF

# cat в пайплайне с tee для дублирования вывода
cat /var/log/syslog | tee /tmp/syslog_copy.log | grep "error"
```

### Полезные флаги cat

```bash
# Нумерация всех строк
cat -n /var/log/syslog
# →     1  Jan 01 00:00:01 host systemd[1]: Started ...
# →     2  Jan 01 00:00:02 host sshd[1234]: Accepted ...

# Нумерация только непустых строк
cat -b /var/log/syslog

# Подавление повторяющихся пустых строк
cat -s /etc/fstab

# Отображение символа конца строки ($) и табуляции (^I)
cat -E -T /etc/environment

# Показать все непечатаемые символы
cat -v /tmp/binary_dump.bin
```

### Просмотр длинных файлов через less

```bash
# Открыть файл в постраничном режиме
less /var/log/syslog

# Открыть с номером строк
less -N /var/log/syslog
```

### Навигация внутри less

| Действие | Клавиши |
| :--- | :--- |
| Выход | `q` |
| Вперёд на одну строку | `↓` / `Enter` / `e` |
| Назад на одну строку | `↑` / `y` / `k` |
| Вперёд на экран | `Пробел` / `f` |
| Назад на экран | `b` |
| Переход к началу файла | `g` |
| Переход к концу файла | `G` |
| Переход к строке N | `Ng` |
| Поиск вперёд | `/шаблон` + `Enter` |
| Поиск назад | `?шаблон` + `Enter` |
| Следующее совпадение | `n` |
| Предыдущее совпадение | `N` |
| Отметить текущую позицию | `m<буква>` |
| Перейти к метке | `'<буква>` |

### Полезные флаги less

```bash
# Нумерация строк
less -N /var/log/syslog

# Ограничение ширины (не переносить длинные строки)
less -S /var/log/syslog

# Автоматический выход, если содержимое помещается на один экран
less -F /var/log/syslog

# Сохранить содержимое при выходе (не очищать экран)
less -X /var/log/syslog

# Поиск без учёта регистра (после ввода символов)
less -i /var/log/syslog
# Внутри less: включить/выключить -I (Ctrl+I)
```

### Расширенные возможности less

```bash
# Фильтрация строк по шаблону (аналогично grep, но внутри less)
# Внутри less ввести: &pattern
# Пример: &ERROR — показать только строки с ERROR

# Открытие нескольких файлов
less /var/log/syslog /var/log/auth.log
# Внутри less: :n — следующий файл, :p — предыдущий

# Сохранение текущей позиции и возврат
# Внутри less: m'a — метка 'a', '' — возврат к предыдущей позиции

# Просмотр сжатого файла
zless /var/log/syslog.1.gz

# Просмотр с начала (аналог head) — переход к строке 1 и выход при невместимости на экран
less -FiNX /var/log/syslog

# Просмотр без очистки экрана (полезно для tail -f аналога)
less -F /var/log/syslog
```

### Просмотр бинарных и не-текстовых файлов

`cat` и `less` по умолчанию выводят байты как есть. Для бинарных файлов (дампы, исполняемые файлы, объекты `/proc` и `/sys`) это может привести к «мусору» в терминале и сбросу настроек TTY.

```bash
# Безопасный просмотр любого файла через file
file /bin/ls /var/log/syslog /dev/null
# → /bin/ls: ELF 64-bit LSB executable, x86-64
# → /var/log/syslog: ASCII text
# → /dev/null: character special

# Просмотр не-ASCII файлов через hexdump
hexdump -C /bin/ls | head -n 10

# strings — извлечение печатаемых строк
strings /usr/bin/ssh | grep -i "version" | head -5

# less с отключением сброса терминала
less -X /tmp/core_dump
# Если less «сломает» терминал: reset
```

### Просмотр сжатых архивов логов

```bash
# zless — просмотр gzip-архивов
zless /var/log/syslog.2.gz

# bzless, xzless — аналоги для bzip2 и xz
bzless /var/log/syslog.3.bz2
xzless /var/log/syslog.4.xz

# Просмотр всех сжатых ротаций по порядку
zless /var/log/syslog.*.gz | less -N
```

### less как системный пейджер

Переменные окружения `PAGER` и `LESS` управляют поведением пейджера для всей системы. Многие утилиты (man, git, systemd, ansible-doc) используют их автоматически.

```bash
# Установка less как пейджер по умолчанию
export PAGER=less
export LESS='-RF -g -i -M -X -z-4'

# -R: пропускать ANSI-коды цветов (для git diff, journalctl)
# -F: автоматически выходить, если текст помещается на экран
# -g: подсвечивать только текущее совпадение при поиске
# -i: поиск без учёта регистра
# -M: подробная строка статуса (имя файла, позиция, процент)
# -X: не очищать экран при выходе
# -z-4: размер скролла назад на 4 строки меньше экрана

# Проверка текущего пейджера
echo $PAGER
git config --global core.pager
man -w .
```

### Удалённый просмотр через SSH

```bash
# cat через SSH с пайпом в less — предотвращает потерю управления терминалом
ssh server "cat /var/log/syslog" | less -N

# Если файл большой, используйте -C (progress) или ограничьте
ssh server "tail -n 500 /var/log/syslog" | less -N

# Просмотр сжатого удалённого лога без временного файла
ssh server "zcat /var/log/syslog.2.gz" | less -N

# Для less на удалённом хосте требуется TTY (-t)
ssh -t server "less /var/log/syslog"
```

### Работа с разрешениями и sudo

```bash
# Просмотр системных файлов, доступных только root
sudo less /etc/shadow

# Чтение в переменную (НЕ передавайте cat через sudo напрямую в файл)
sudo cat /etc/shadow > /tmp/shadow_copy
# ОПАСНО: перенаправление выполняется от текущего пользователя, файл создаётся без прав root

# Безопасно: читаем и сразу передаём
sudo cat /etc/shadow | tee /tmp/shadow_copy > /dev/null

# Прямой cat через sudo без создания локального файла
sudo less /var/log/auth.log
```

### Интеграция с конвейерами

```bash
# Просмотр вывода длинной команды через less
ls -la /etc | less -N
history | less

# Безопасный просмотр удалённого файла без открытия редактора
ssh server "cat /etc/config" | less

# Фильтрация в пайплайне
journalctl -u sshd --no-pager | grep "Failed" | less -N

# cat с нулевым разделителем (для файлов с пробелами в именах)
find /var/log -name "*.log" -print0 | xargs -0 cat | less -N
```

### Интеграция с journalctl и systemd

```bash
# journalctl использует less как пейджер по умолчанию
journalctl -u sshd -n 1000 | less -N

# Отключение пейджинга при необходимости парсинга
journalctl -u sshd --no-pager | grep "Accepted"

# Просмотр логов юнита с последних загрузок
journalctl -u docker -b -1 --no-pager | tail -n 50 | less -N
```

### Просмотр специальных файлов

```bash
# /proc и /sys — виртуальные файлы, размер часто показывает 0
cat /proc/version
cat /proc/cpuinfo | grep "model name" | head -1

# Просмотр параметров ядра
cat /proc/sys/net/ipv4/ip_forward
# → 0

# /dev/null — всегда пуст
cat /dev/null

# Устройства: cat возвращает бинарные данные
cat /dev/urandom | head -c 16 | hexdump -C
```

## Экзаменационные сценарии (LPIC-1, тема 103.1)

Топик 103.1 силлабуса LPIC-1 («Архитектура системы Linux») требует умения выбирать правильный инструмент для просмотра файлов без риска их изменения.

### Типичный вопрос

**Вопрос:** Какой инструмент предназначен для безопасного постраничного просмотра длинных текстовых файлов?

**Варианты ответа:**
- A. `cat`
- B. `less`
- C. `head`
- D. `echo`

**Правильный ответ:** B (`less`).

**Обоснование:**
- `cat` выводит содержимое файла целиком, без пейджинга, и не защищает от случайного вывода огромного объёма данных.
- `head` показывает только начало файла.
- `echo` служит для вывода текста в терминал, а не для чтения файлов.
- `less` открывает файл в режиме только чтения с возможностью навигации в любом направлении.

### Дополнительные проверки на экзамене

- Клавиша `q` — обязательный элемент для запоминания; без неё сессия просмотра `less` не завершится.
- `more` — устаревший аналог `less`; поддерживает только движение вперёд, не является правильным ответом в контексте современного инструментария.
- Если в вопросе фигурирует «безопасный просмотр» или «режим только чтения», однозначно выбирается `less`.

## Troubleshooting

### Файл «уехал» за пределы экрана после cat

**Симптом:** После запуска `cat` на большом файле терминал показывает только последние строки, а начало файла недоступно без долгого скроллинга вверх.

**Диагностика:** Выполнена команда `cat` без перенаправления в пейджер.

**Решение:**
```bash
# Если терминал «залип» с длинным выводом, просто запустите clear или reset
clear
# или
reset

# Повторите просмотр через less
less /путь/к/файлу
```

### Ошибка: less не открывается, «No such file or directory»

**Симптом:** `less` завершается с ошибкой, хотя файл существует.

**Диагностика:** Проверьте, не перенаправляется ли `stdin` в `/dev/null` или иной конвейер, нарушающий работу пейджера.

**Решение:**
```bash
# Явно указать файл, а не pipe
less /etc/nginx/nginx.conf

# Если вывод уже в pipe, используйте -F или перенаправьте
command | less -F
```

### Поиск не работает внутри less

**Симптом:** Ввод `/шаблон` не приводит к переходу.

**Диагностика:** Регистрозависимость или пустой поисковый буфер.

**Решение:**
```bash
# Внутри less включить игнорирование регистра
# Нажать Ctrl+I или передать флаг -i при запуске
less -i /var/log/syslog
```

### cat «зависает» на специальных файлах и именованных каналах

**Симптом:** `cat` не завершается и не выводит данные.

**Диагностика:** Попытка чтения из FIFO, сокета или устройства, которые ожидают данных от другого процесса.

**Решение:**
```bash
# Проверка типа файла
file /path/to/object

# Для FIFO: открыть второй терминал и записать данные
cat > /tmp/myfifo

# Для блокирующих устройств: используйте timeout
timeout 2 cat /dev/ttyUSB0 || echo "Нет данных или устройство недоступно"

# /proc и /sys: обычно безопасны, но проверяйте размер
ls -la /proc/1/status
cat /proc/1/status
```

### less «сломать» терминал после сбоя

**Симптом:** После выхода из `less` (например, по `SIGKILL`) символы отображаются как есть, подсветка не работает.

**Диагностика:** `less` не успел восстановить терминальный режим.

**Решение:**
```bash
# Восстановление терминала
reset
# или
stty sane

# Профилактика: используйте -X, если не нужен alternaive buffer
less -X /var/log/syslog
```

### Broken pipe при cat в пайплайне

**Симптом:** `cat file | head -n 1` завершается с `SIGPIPE` или сообщением о broken pipe.

**Диагностика:** `head` закрыл pipe после получения нужного количества строк, а `cat` продолжал писать.

**Решение:**
```bash
# Игнорировать SIGPIPE (если это критично)
trap '' PIPE
cat hugefile | head -n 1

# Или используйте head как фильтр без cat
head -n 1 hugefile
```

## Best Practices

1. **Для коротких файлов** (до ~50 строк, конфиги, справка) используйте `cat`.
2. **Для любых файлов, размер которых превышает экран**, используйте `less` по умолчанию.
3. **Для логов** используйте `less` с нумерацией строк (`-N`) и, при необходимости, с отключением переноса (`-S`).
4. **Никогда не используйте `cat` для открытия файла в редакторе.** Это приводит к загрузке всего файла в терминал и повышает риск случайного изменения.
5. **При просмотре удалённых файлов** конвейером через SSH используйте `less` (`ssh host "cat file" | less`), чтобы не потерять управление терминалом.
6. **Для просмотра начала или конца файла** используйте специализированные утилиты `head` и `tail`, а не `less`.
7. **Для системного пейджера** установите `PAGER=less` и удобные флаги `LESS='-RF -g -i -M'`, чтобы `man`, `git diff` и `systemctl status` использовали единый комфортный интерфейс.
8. **При работе с бинарными/неизвестными файлами** всегда проверяйте тип через `file` перед `cat` или `less`, чтобы не повредить терминал.
9. **В скриптах и automation** используйте `cat` с heredoc для создания файлов, но избегайте `cat` для простого копирования (`cp` или `install` эффективнее и безопаснее).
10. **Для сжатых логов** используйте `zless`/`bzless`/`xzless` вместо ручного `gunzip | less`.
