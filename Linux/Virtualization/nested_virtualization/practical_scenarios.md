# Вложенная виртуализация — Практические сценарии

В данном файле приведены практические инструкции по настройке вложенной виртуализации в среде KVM/QEMU, а также примеры конфигураций для различных уровней иерархии. Теоретические основы описаны в [Вложенная виртуализация: Определения и концепции](./definitions_and_concepts.md).

## Определения

**Nested VT-x / SVM** — параметры модулей ядра KVM (`kvm_intel` и `kvm_amd`), отвечающие за активацию возможности проброса аппаратных инструкций виртуализации в гостевую систему.

**host-model** — режим настройки CPU в libvirt, при котором гостевой ОС передаются возможности физического процессора хоста в максимально совместимом виде.

**host-passthrough** — режим полной передачи всех флагов и характеристик физического CPU хоста в ВМ. Необходим для обеспечения максимальной производительности вложенных сред.

## Базовые концепции

### Порядок настройки вложенности

Для успешного запуска ВМ уровня L2 необходимо выполнить настройку на двух этапах:

1. **На уровне хоста (L0):** Активация вложенности в модулях ядра KVM.
2. **На уровне гипервизора (L1):** Проброс функций CPU в конфигурации ВМ первого уровня.

### Риски и стабильность

Включение вложенной виртуализации может снизить стабильность системы на уровне L1 и сделать невозможной живую миграцию (Live Migration) ВМ между хостами с разной архитектурой CPU.

## Практические сценарии

### Сценарий 1: Проверка и активация на хосте (L0)

**1. Проверка текущего статуса:**

```bash
# Для процессоров Intel
cat /sys/module/kvm_intel/parameters/nested
# → Ожидаемый результат: Y или 1

# Для процессоров AMD
cat /sys/module/kvm_amd/parameters/nested
# → Ожидаемый результат: Y или 1
```

**2. Включение без перезагрузки (временное):**

```bash
# Выгрузка и загрузка модуля с параметром (на примере Intel)
sudo modprobe -r kvm_intel
sudo modprobe kvm_intel nested=1
```

**3. Постоянная активация через конфигурацию:**
Создайте или отредактируйте файл `/etc/modprobe.d/kvm.conf`:

```text
# Для Intel
options kvm-intel nested=1
# Для AMD
options kvm-amd nested=1
```

### Сценарий 2: Настройка ВМ первого уровня (L1)

Чтобы внутри ВМ L1 можно было запустить гипервизор, ей необходимо передать функции виртуализации.

**Вариант А: Использование virsh (libvirt)**

```bash
virsh edit <имя_вм>
```

В секции `<cpu>` установите режим проброса:

```xml
<cpu mode='host-passthrough' check='none'/>
```

**Вариант Б: Запуск через QEMU CLI**

```bash
qemu-system-x86_64 -cpu host -enable-kvm ...
```

### Сценарий 3: Проверка доступности виртуализации внутри ВМ (L1)

После запуска ВМ уровня L1 необходимо убедиться, что она корректно получила расширения виртуализации от хоста L0.

**1. Выполнение проверки:**
Для верификации используется стандартный метод проверки аппаратной поддержки, описанный в [Установка KVM — Проверка](./../kvm/installation.md#сценарий-1-проверка-поддержки-аппаратной-виртуализации).

**2. Анализ результата:**
Если команда возвращает результат `> 0`, это означает успех. В этом случае внутри ВМ уровня L1 можно переходить к установке программного стека KVM.
