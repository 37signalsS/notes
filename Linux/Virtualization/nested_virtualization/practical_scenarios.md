# Вложенная виртуализация — Практические сценарии

В данном файле приведены практические инструкции по настройке вложенной виртуализации для различных архитектур (x86, ARM64) и платформ управления (Libvirt, Proxmox, Vagrant). Теоретические основы описаны в [Вложенная виртуализация: Определения и концепции](./definitions_and_concepts.md).

## Определения

**Nested VT-x / SVM** — параметры модулей ядра KVM (`kvm_intel` и `kvm_amd`), активирующие проброс аппаратных инструкций виртуализации в гостевую систему.

**host-passthrough** — режим работы CPU, при котором ВМ получает все флаги и инструкции физического процессора. Это обязательное условие для работы вложенной виртуализации с минимальными потерями производительности.

**Enlightened VMCS** — технология оптимизации для гипервизоров Microsoft (Hyper-V/Azure), снижающая накладные расходы на переключение контекста во вложенных средах.

## Базовые концепции

### Порядок настройки (Workflow)

Реализация вложенности всегда требует двух последовательных шагов:
1.  **L0 (Хост):** Активация поддержки вложенности на уровне ядра ОС.
2.  **L1 (ВМ):** Настройка конфигурации виртуальной машины для проброса функций CPU.

### Проверка аппаратной готовности
Перед началом настройки убедитесь, что на физическом хосте установлена утилита `virt-host-validate` (входит в пакет `libvirt-clients` или `libvirt-daemon`).

```bash
virt-host-validate
# → Должно быть: QEMU: Checking for device assignment IOMMU support : PASS
```

## Практические сценарии

### Сценарий 1: Настройка хоста (L0)

#### Для архитектуры x86_64 (Intel и AMD)
Проверьте текущий статус:
```bash
# Intel
cat /sys/module/kvm_intel/parameters/nested
# AMD
cat /sys/module/kvm_amd/parameters/nested
# → 'Y' или '1' — включено, 'N' или '0' — выключено.
```

Если выключено, создайте файл `/etc/modprobe.d/kvm-nested.conf`:
```text
# Для Intel
options kvm_intel nested=1
# Для AMD (в новых ядрах часто включено по умолчанию)
options kvm_amd nested=1
```
После этого перезагрузите модули:
```bash
sudo modprobe -r kvm_intel && sudo modprobe kvm_intel
```

#### Для архитектуры ARM64 (Apple M-series, Ampere)
Требуется ядро версии 6.16+ и поддержка расширения FEAT_NV. Настройка выполняется через параметры загрузки ядра.

1.  Отредактируйте `/etc/default/grub`:
    ```text
    GRUB_CMDLINE_LINUX_DEFAULT="... kvm-arm.mode=nested"
    ```
2.  Обновите конфигурацию GRUB (`update-grub`) и перезагрузитесь.

### Сценарий 2: Настройка ВМ первого уровня (L1)

#### Вариант А: Libvirt / virsh (Стандарт)
Отредактируйте XML-конфигурацию ВМ:
```bash
virsh edit <имя_вм>
```
Установите режим CPU:
```xml
<cpu mode='host-passthrough' check='none'>
  <!-- Рекомендуется для стабильности -->
  <feature policy='require' name='vmx'/> 
</cpu>
```

#### Вариант Б: Proxmox VE
Используйте утилиту `qm` для установки типа процессора:
```bash
qm set <vmid> --cpu host
```

#### Вариант В: Vagrant
Добавьте в `Vagrantfile` параметр для провайдера libvirt:
```ruby
config.vm.provider :libvirt do |lv|
  lv.nested = true
end
```

### Сценарий 3: Оптимизация для Windows / Hyper-V в L1
Если в качестве L1 используется Windows (с ролью Hyper-V) или Linux в Azure, необходимо включить «улучшения» (enlightenments).

В XML-конфигурации libvirt:
```xml
<features>
  <hyperv>
    <relaxed state='on'/>
    <vapic state='on'/>
    <spinlocks state='on' retries='8191'/>
    <stimer state='on'/>
    <synic state='on'/>
    <evmcs state='on'/> <!-- Обязательно для Intel -->
  </hyperv>
</features>
```

### Сценарий 4: Проверка внутри ВМ (L1)

После настройки и запуска ВМ L1, внутри неё должны появиться флаги виртуализации:
```bash
grep -Eoc '(vmx|svm)' /proc/cpuinfo
# → Результат > 0 означает успех.
```

Также рекомендуется запустить `virt-host-validate` внутри L1, чтобы убедиться, что модули KVM загружены и готовы к работе.

## Диагностика и решение проблем

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| `modprobe -r` выдает ошибку | Модуль занят активными ВМ | Остановите все запущенные ВМ на хосте. |
| Флаги в L1 не появились | CPU mode не установлен в `host` | Проверьте, что в конфиге нет `model='qemu64'` или аналогов. |
| Ошибка `VMX disabled by BIOS` | Аппаратная заблокировка | Проверьте настройки VT-x/AMD-V в BIOS/UEFI физического сервера. |
| Низкая скорость I/O в L2 | Отсутствие `virtio` | Используйте драйверы virtio для дисков и сети на всех уровнях. |
