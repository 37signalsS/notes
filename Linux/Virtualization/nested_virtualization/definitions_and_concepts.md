# Вложенная виртуализация (Nested Virtualization) — Определения и концепции

В данном файле рассматриваются теоретические основы вложенной виртуализации, иерархия уровней, архитектурные требования и современные оптимизации для её реализации в Linux (KVM).

## Определения

**Вложенная виртуализация (Nested Virtualization)** — технология, позволяющая запускать гипервизор (L1) внутри виртуальной машины, которая сама работает под управлением другого гипервизора (L0) на физическом оборудовании. Это создает многоуровневую среду выполнения.

**Иерархия уровней:**

| Уровень | Описание | Роль |
| :--- | :--- | :--- |
| **L0** | Bare-Metal | Физический сервер и основной гипервизор (напр., KVM на хосте). Работает в **VMX Root Mode** (Ring -1). |
| **L1** | Guest Hypervisor | Виртуальная машина первого уровня, внутри которой запущен собственный гипервизор. |
| **L2** | Nested Guest | Вложенная виртуальная машина, запущенная внутри L1. |

*Примечание: Теоретически количество уровней (L3, L4...) может быть больше, но на практике это редко используется из-за экспоненциального роста накладных расходов.*

## Базовые концепции

### Аппаратная поддержка (Требования 2025–2026)

Для эффективной работы вложенной виртуализации на уровне L0 необходима поддержка современных расширений CPU:

1.  **x86_64 (Intel):**
    *   **VT-x** + **EPT** (Extended Page Tables).
    *   **VMCS Shadowing:** Обязателен для современных нагрузок. Снижает количество перехватов (VM-Exits) при обращении L1 к структурам управления L2.
    *   Поддерживается на процессорах семейства Intel Core 5th gen+ и Xeon Scalable (Sapphire Rapids, Granite Rapids).
2.  **x86_64 (AMD):**
    *   **AMD-V** + **RVI** (Rapid Virtualization Indexing).
    *   Архитектура AMD (SVM) аппаратно более оптимизирована для вложенности («world switch» требует меньше инструкций).
    *   Поддерживается на процессорах Ryzen и EPYC (Zen 3/4/5).
3.  **ARM64 (ARMv8.4+ / ARMv9):**
    *   **FEAT_NV / FEAT_NV2:** Расширения, позволяющие гипервизору L1 работать в режиме EL1, перехватывая системные регистры без участия L0.
    *   **FEAT_NV2** (внедрено в 2025–2026 годах) радикально ускоряет доступ к структурам управления в памяти.

### Архитектура реализации в KVM

Механизм **Nested KVM** базируется на трансляции состояний и минимизации вмешательства L0:

*   **VM-Exits (Выходы):** Основной источник задержек. Когда L2 выполняет привилегированную инструкцию, происходит «выход». Современные ядра (6.12+) используют **Virtual EPT**, чтобы L0 мог напрямую обрабатывать промахи страниц L2, минуя L1.
*   **Enlightened VMCS (EVMCS):** Оптимизация, позволяющая L1 и L0 обмениваться данными через разделяемую память (Hyper-V/KVM). Критично для работы **WSL2** и **Android Emulator** внутри облачных ВМ.
*   **Posted Interrupts:** Технология, позволяющая L0 доставлять прерывания напрямую в L2, не прерывая выполнение L1.

### Поддержка облачными провайдерами (Статус 2026)

| Провайдер | Инстансы с поддержкой Nested VT | Примечания |
| :--- | :--- | :--- |
| **AWS** | Nitro-инстансы (C5/M5 и новее), Graviton 4 | На ARM используется кастомная оптимизация Nitro. |
| **Azure** | Серии Dv3/Dv4/Dv5, Ev3/Ev4/Ev5 | Активно используется для Confidential Computing и WSL2. |
| **GCP** | N1, N2, N2D, Z4 (новое в 2026) | Требуется флаг `minCpuPlatform` или `enable_nested_virtualization`. |

### Производительность и накладные расходы

В 2026 году, благодаря оптимизациям `guest_memfd` и аппаратным ускорениям, "налог" на вложенность снизился:
- **CPU-интенсивные задачи:** Потери производительности в L2 составляют **~5–10%** относительно L1.
- **I/O-интенсивные задачи:** Потери могут достигать **15–25%** из-за сложности маршрутизации прерываний. Использование **VirtIO-forwarding** обязательно.

### Экспресс-проверка поддержки на хосте (L0)

Перед настройкой необходимо убедиться, что аппаратная виртуализация доступна и активирована в ядре.

**1. Проверка флагов CPU (x86_64):**
```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
# → 0: Поддержка отсутствует или выключена в BIOS
# → 1+: Аппаратная поддержка присутствует
```

**2. Проверка статуса в модуле ядра (Intel):**
```bash
cat /sys/module/kvm_intel/parameters/nested
# → Y или 1: Вложенность включена (SSoT)
# → N или 0: Вложенность выключена
```

**3. Проверка для ARM64 (FEAT_NV):**
```bash
dmesg | grep -i "kvm.*nested"
# → [    1.234567] kvm [1]: nested virtualization enabled
```
