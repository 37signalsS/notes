# Вложенная виртуализация (Nested Virtualization) — Определения и концепции

В данном файле рассматриваются теоретические основы вложенной виртуализации, иерархия уровней, архитектурные требования и современные оптимизации для её реализации в Linux. Практические шаги по настройке приведены в [Вложенная виртуализация: Практические сценарии](./practical_scenarios.md).

## Определения

**Вложенная виртуализация (Nested Virtualization)** — технология, позволяющая запускать гипервизор (L1) внутри виртуальной машины, которая сама работает под управлением другого гипервизора (L0) на физическом оборудовании. Это создает многоуровневую среду выполнения.

**Иерархия уровней:**

| Уровень | Описание | Роль |
| :--- | :--- | :--- |
| **L0** | Bare-Metal | Физический сервер и основной гипервизор (напр., KVM на хосте). |
| **L1** | Guest Hypervisor | Виртуальная машина первого уровня, внутри которой запущен собственный гипервизор. |
| **L2** | Nested Guest | Вложенная виртуальная машина, запущенная внутри L1. |

*Примечание: Теоретически количество уровней (L3, L4...) может быть больше, но на практике это редко используется из-за катастрофического падения производительности.*

## Базовые концепции

### Требования к оборудованию

Для работы вложенной виртуализации на уровне L0 необходима аппаратная поддержка расширений CPU:

1.  **x86_64 (Intel):** Технология **VT-x** совместно с **EPT** (Extended Page Tables). Современные процессоры также поддерживают **VMCS Shadowing** (ускорение переключения контекста между L0 и L1).
2.  **x86_64 (AMD):** Технология **AMD-V** совместно с **RVI** (Rapid Virtualization Indexing). Архитектура AMD (SVM) исторически более приспособлена к вложенности благодаря меньшему количеству необходимых перехватов (VM-Exits).
3.  **ARM64 (ARMv8.3+):** Включает расширения **FEAT_NV** (Nested Virtualization), позволяющие эффективно выполнять гипервизор в режиме EL1.

### Архитектура реализации в KVM

Механизм вложенности в KVM (Nested KVM) базируется на трансляции состояний:

-   **VM-Exits:** Когда L2 выполняет привилегированную инструкцию, происходит «выход» из виртуальной машины. L0 перехватывает этот выход, определяет, предназначался ли он для L1, и передает управление гипервизору L1.
-   **Shadow VMCS / VMCB:** Для ускорения работы L0 создает «теневые» структуры управления виртуальной машиной, чтобы L1 мог изменять параметры L2 с минимальным вмешательством L0.
-   **Enlightened VMCS:** Оптимизация (актуальна для сред Hyper-V/Azure), позволяющая L1 и L0 обмениваться данными через разделяемую память, минуя часть дорогостоящих инструкций процессора.

### Поддержка облачными провайдерами

Современные облачные платформы поддерживают вложенную виртуализацию на специфических типах инстансов:
-   **AWS:** Инстансы на базе Nitro (напр., c5, m5) и bare-metal инстансы.
-   **Google Cloud:** Поддерживается для семейств N1, N2, N2D через флаг `minCpuPlatform`.
-   **Microsoft Azure:** Инстансы серий Dv3 и Ev3.

## Ограничения и особенности

-   **Производительность:** Накладные расходы на уровне L2 составляют от 5% до 20% для CPU-интенсивных задач и до 40% для I/O-интенсивных при отсутствии оптимизаций.
-   **Стабильность:** Сложность отладки возрастает экспоненциально. Сбои в L0 могут приводить к непредсказуемому поведению в L2.
-   **Безопасность:** Вложенность увеличивает поверхность атаки. Уязвимости типа «Side-channel» (Spectre/Meltdown) могут быть сложнее в митигации в многоуровневых средах.
-   **Живая миграция:** Миграция L1-хоста с запущенными L2-гостями часто требует идентичных версий гипервизора и моделей CPU на всех физических узлах.

## Практические сценарии

Основные методы проверки и настройки параметров модулей ядра описаны в специализированном файле: [Вложенная виртуализация: Практические сценарии](./practical_scenarios.md).

### Краткая проверка поддержки на хосте (L0)

```bash
# Проверка наличия флагов виртуализации в CPU
egrep -c '(vmx|svm)' /proc/cpuinfo
# → Результат > 0 означает наличие аппаратной поддержки (Intel/AMD)

# Проверка активации в ядре (на примере Intel)
cat /sys/module/kvm_intel/parameters/nested
# → Y или 1 означает, что вложенность включена
```
