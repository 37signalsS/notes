# Вложенная виртуализация (Nested Virtualization) — Определения и концепции

В данном файле рассматриваются теоретические основы вложенной виртуализации, иерархия уровней и архитектурные требования для её реализации в Linux. Практические шаги по настройке приведены в [Вложенная виртуализация: Практические сценарии](./practical_scenarios.md).

## Определения

**Вложенная виртуализация (Nested Virtualization)** — это технология, позволяющая запускать гипервизор внутри виртуальной машины (ВМ), которая сама работает под управлением другого гипервизора на физическом оборудовании.

**Уровни иерархии:**

- **L0 (Bare-Metal)** — физический сервер, на котором запущен основной гипервизор.
- **L1 (Guest Hypervisor)** — виртуальная машина первого уровня, внутри которой запущен собственный гипервизор.
- **L2 (Nested Guest)** — вложенная виртуальная машина, запущенная внутри L1.

## Базовые концепции

### Требования к оборудованию и системе

Для работы вложенной виртуализации на уровне L0 необходима поддержка специфических аппаратных расширений:

| Архитектура | Технология | Обязательные компоненты |
| :--- | :--- | :--- |
| **Intel** | VT-x | VT-x (виртуализация CPU) + EPT (Extended Page Tables) |
| **AMD** | AMD-V | AMD-V (виртуализация CPU) + RVI (Rapid Virtualization Indexing) |

Для проброса устройств (Passthrough) также требуется поддержка **IOMMU** (Intel VT-d или AMD-Vi).

### Архитектура реализации в KVM

Механизм вложенности в KVM (Nested KVM) работает по следующему принципу:

1. Гипервизор уровня L0 предоставляет гостевой ВМ (L1) «виртуализированные» инструкции процессора, необходимые для работы гипервизора.
2. Гипервизор уровня L1 управляет ВМ уровня L2, используя эти виртуализированные расширения.
3. KVM на уровне L0 перехватывает и транслирует наиболее критичные операции L1 → L2 для обеспечения безопасности и корректности выполнения кода.

### Ограничения и особенности

- **Производительность:** Каждый уровень вложенности добавляет накладные расходы (традиционно от 10% до 30%), особенно при операциях ввода-вывода (I/O).
- **Стабильность:** Не все функции управления питанием и расширенные наборы инструкций CPU корректно пробрасываются до уровня L2.
- **Миграция:** Живая миграция (Live Migration) ВМ уровня L1 может быть невозможна или ограничена, если внутри нее запущены активные ВМ уровня L2.

### Краткая проверка поддержки на хосте (L0)

```bash
# Проверка наличия флагов виртуализации в CPU
egrep -c '(vmx|svm)' /proc/cpuinfo
# → Результат > 0 означает наличие аппаратной поддержки
```
