# Вложенная виртуализация — Дополнительная информация

В данном файле собраны сведения о производительности, безопасности, сетевых особенностях и альтернативных решениях для вложенной виртуализации. Основные настройки приведены в [Вложенная виртуализация: Практические сценарии](./practical_scenarios.md).

## Определения

**Hugepages (Огромные страницы)** — механизм использования страниц памяти большого размера (2 МБ или 1 ГБ), снижающий нагрузку на TLB и таблицы страниц. Подробно см. в [Оптимизация памяти](../core/memory/performance_tuning.md).

**CPU Pinning (Привязка ядер)** — жесткое закрепление виртуальных процессоров ВМ за физическими ядрами хоста. Обязательно для минимизации задержек во вложенных средах. Подробно см. в [Привязка к процессору](../core/cpu_pinning.md).

**DinD (Docker-in-Docker)** — метод запуска контейнеров внутри контейнеров без использования вложенной гипервизорной виртуализации.

## Базовые концепции

### Оценка производительности

Вложенность неизбежно приводит к снижению производительности из-за дополнительных уровней абстракции:

| Уровень иерархии | CPU (относительно L0) | I/O (относительно L0) |
| :--- | :--- | :--- |
| **L0 (Host)** | 100% | 100% |
| **L1 (Guest)** | 95–99% | 90–95% |
| **L2 (Nested)** | 80–95% | 60–85% |

**Факторы деградации:**

- **VM-Exits:** Основной источник задержек. Каждая привилегированная операция в L2 может вызывать цепочку выходов (L2 → L0 → L1 → L0 → L2).
- **Shadow Paging:** Если EPT/RVI не проброшены корректно, гипервизор вынужден эмулировать таблицы страниц, что критично замедляет работу с памятью.
- **Прерывания:** Обработка прерываний во вложенных средах требует дополнительных циклов процессора для маршрутизации между уровнями.

**Методы оптимизации:**

- **EPT/RVI Passthrough:** Обязателен для предотвращения двойной трансляции адресов.
- **VMCS Shadowing (Intel):** Снижает количество VM-Exits при обращении L1 к структурам управления L2.
- **Enlightened VMCS:** Использование гипервызовов (Hypercalls) для прямого взаимодействия гипервизоров (актуально для сред Hyper-V).

### Сетевые особенности

Вложенная виртуализация накладывает ограничения на сетевой стек:

1.  **MAC Spoofing:** ВМ уровня L1 должна разрешать прохождение трафика с MAC-адресами вложенных ВМ (L2). Если на L1 включена фильтрация MAC, сеть в L2 не будет работать.
2.  **MTU Overhead:** При использовании туннельных протоколов (VXLAN, GRE) внутри L1, необходимо учитывать уменьшение MTU для L2 (обычно до 1450 или ниже), чтобы избежать фрагментации на уровне L0.
3.  **Promiscuous Mode:** Для классических мостов (Linux Bridge) на уровне L1 часто требуется включение режима `promisc` на интерфейсах, смотрящих в сторону L2.

### Безопасность

Вложенная виртуализация увеличивает поверхность атаки:

- **Уязвимости гипервизора:** Ошибки в коде L1 могут быть использованы для компрометации L0 («VM Escape»).
- **Side-channel атаки:** Многоуровневые среды более уязвимы к атакам типа Spectre и Meltdown. Проброс флагов защиты (mitigations) от L0 до L2 обязателен, но может значительно снизить производительность вложенных систем.
- **Изоляция:** Рекомендуется использовать механизмы **SELinux** или **AppArmor** на уровне L0 для ограничения прав процессов QEMU/KVM, представляющих ВМ первого уровня.

### Альтернативные подходы к изоляции

Если вложенная виртуализация архитектурно избыточна, применяются более легкие методы:

- **Kata Containers** — запуск контейнеров в легковесных microVM.
- **gVisor** — ядро-песочница (sandbox) в userspace для изоляции системных вызовов.
- **Firecracker** — специализированный гипервизор для microVM и бессерверных вычислений.
- **LXC/LXD** — системные контейнеры без вложенности ядер.

## Практические сценарии

### Сценарий 1: Мониторинг и диагностика

Для базовой проверки доступности KVM на уровнях L0 и L1 используйте методику из [Установка KVM — Проверка](../../kvm/installation.md#сценарий-1-проверка-и-подготовка-оборудования).

**Инструменты мониторинга:**

```bash
# Просмотр событий KVM в реальном времени (напр. VM-Exits)
sudo kvm_stat

# Просмотр загрузки ресурсов ВМ (libvirt)
virt-top
```

### Сценарий 2: Решение типичных проблем (Troubleshooting)

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Не применяется `nested=1` | Модуль ядра занят | Остановить все ВМ и перезагрузить модуль `kvm_intel/amd`. |
| Ошибка `VMX disabled` в L1 | BIOS/UEFI хоста L0 | Включить поддержку виртуализации в BIOS физического сервера. |
| Сеть в L2 недоступна | Блокировка MAC | Разрешить MAC Spoofing или включить Promiscuous mode на мосту L1. |
| L2 работает крайне медленно | Использование эмуляции | Проверить наличие `-cpu host` в параметрах запуска L1. |
