# Образы ВМ — Основные концепции

В данном файле рассматриваются стратегии организации дискового пространства для виртуальных машин (ВМ), архитектурные подходы к хранению данных и механизмы оптимизации производительности. Глоссарий терминов доступен в [Образы ВМ — Определения](./definitions.md).

## Способы организации хранилища

Выбор метода доступа к данным определяет баланс между производительностью I/O, гибкостью управления и возможностями масштабирования.

### 1. Файловые образы (File-based)
Виртуальный диск представлен в виде файла (`.qcow2`, `.raw`) в файловой системе хоста.
- **Преимущества:** Простота резервного копирования (копирование файла), поддержка цепочек снапшотов, легкая миграция.
- **Особенности:** Зависимость от производительности и фрагментации файловой системы хоста (ext4, XFS, ZFS).

### 2. Прямой блочный доступ (Block Device Passthrough)
Проброс физического диска, раздела или LVM-тома напрямую в ВМ.
- **Преимущества:** Минимальные задержки (отсутствие слоя ФС хоста), прямой доступ к аппаратным функциям.
- **Недостатки:** Сложность «живой» миграции, риск конфликтов при доступе к одному устройству со стороны хоста и гостя.

### 3. Сетевые блочные устройства (Network Block Storage)
Использование протоколов iSCSI, Fibre Channel или распределенных систем (Ceph RBD).
- **Преимущества:** Высокая доступность (HA), независимость данных от конкретного узла, централизованное управление.
- **Сценарии:** Корпоративные кластеры и облачные платформы.

## Форматы виртуальных дисков

| Формат | Поддержка | Особенности |
| :--- | :--- | :--- |
| **`raw`** | Все гипервизоры | Максимальная скорость. Нет метаданных. Поддерживает Sparse-файлы. |
| **`qcow2`** | KVM / QEMU | Поддержка снапшотов, CoW, сжатия (zstd), шифрования (LUKS) и динамического расширения. |
| **`vmdk`** | VMware / ESXi | Стандарт для корпоративного сегмента. Поддерживается в KVM через конвертацию. |
| **`vhdx`** | Hyper-V | Поддержка дисков до 64 ТБ, устойчивость к сбоям питания через логирование метаданных. |

### Особенности формата qcow2 (v3)
Современный стандарт `qcow2` в QEMU 5.1+ и выше (актуально для 2024–2026 гг.) включает:
- **Тип сжатия zstd:** Значительно превосходит `zlib` по скорости декомпрессии (до 5 раз быстрее), что ускоряет запуск ВМ из сжатых образов.
- **Шифрование LUKS:** Встроенная поддержка шифрования на уровне блоков внутри образа.
- **Extended L2 Tables:** Оптимизация для работы с очень большими образами и разреженными данными.

## Интерфейсы ввода-вывода (Virtio)

Выбор драйвера контроллера определяет функциональность и предел производительности I/O.

### Virtio-blk
Оптимизированный драйвер блочного устройства с минимальным стеком обработки.
- **Плюсы:** Наивысшая производительность для одиночных дисков, минимальные задержки (latency).
- **Минусы:** Ограниченная масштабируемость (каждый диск занимает PCI-слот), отсутствие поддержки сложных SCSI-команд.
- **Современность (QEMU 9.0+):** Поддержка `iothread-vq-mapping` позволяет распределять очереди одного диска между несколькими потоками (IOThreads) хоста.

### Virtio-scsi
Промышленный стандарт для сложных конфигураций.
- **Плюсы:** Огромная масштабируемость (тысячи дисков на один контроллер), поддержка SCSI UNMAP (для TRIM), SCSI Reservations (для кластеров).
- **Минусы:** Чуть больший оверхед стека по сравнению с blk (нивелируется в современных версиях).
- **Рекомендация:** Использование режима `virtio-scsi-single` обеспечивает баланс между изоляцией ресурсов и функциональностью SCSI.

## Механизмы оптимизации и управления

### Тонкое выделение и TRIM/Discard
**Thin Provisioning** позволяет выделять виртуальный объем (напр. 100 ГБ), фактически занимая лишь 1 ГБ.
- **Проблема:** При удалении файлов внутри ВМ файл-образ на хосте не уменьшается автоматически.
- **Решение:** Механизм **Discard/TRIM**. Гостевая ОС отправляет сигнал о неиспользуемых блоках, гипервизор освобождает их. Требует контроллера с поддержкой UNMAP (рекомендуется `virtio-scsi`) и опции `-drive ...,discard=unmap`.

### Режимы кэширования (Caching Modes)
- **`none`:** Кэш хоста игнорируется, используется прямой ввод-вывод (O_DIRECT). Рекомендуется для большинства рабочих нагрузок.
- **`writethrough`:** Запись подтверждается только после фиксации на физическом носителе. Максимальная безопасность, низкая скорость.
- **`writeback`:** Подтверждение сразу после записи в кэш хоста. Высокая скорость, риск потери данных при сбое.

### Уровни асинхронного ввода-вывода (AIO)
- **Native:** Использование нативного Linux AIO. Эффективно, но требует `cache=none`.
- **io_uring:** Стандарт 2024–2026 годов. Обеспечивает минимальный оверхед на системные вызовы через разделяемые кольцевые буферы. Значительно ускоряет IOPS на NVMe-накопителях.

### Предварительное выделение (Preallocation)
- **`metadata`:** Создает структуру метаданных заранее. Снижает фрагментацию при сохранении экономии места.
- **`falloc` / `full`:** Резервирует все физическое пространство. Исключает задержки при первом обращении к блоку.

## Жизненный цикл данных и снапшоты

### Copy-on-Write (CoW) и цепочки образов
Механизм CoW лежит в основе снапшотов и связанных клонов:
1. Базовый образ (Backing File) открыт только для чтения.
2. Все записи идут в новый слой (Delta).
3. При чтении: если данных нет в Delta, они считываются из Backing File.
4. **Оптимизация:** Длинные цепочки (`backing chains`) замедляют чтение. Рекомендуется периодическое выполнение `block-stream` для консолидации данных.
