# Образы ВМ — Основные концепции

В данном файле рассматриваются стратегии организации дискового пространства для виртуальных машин (ВМ), сравнение популярных форматов образов и ключевые механизмы управления данными. Терминологический глоссарий доступен в [Образы ВМ — Определения](./definitions.md).

## Определения

Базовые понятия (VM Image, Snapshots, CoW и другие) описаны в специализированном файле: [Образы ВМ — Определения](./definitions.md).

## Базовые концепции

### Способы организации хранилища

Выбор метода доступа к данным определяет баланс между производительностью и гибкостью управления.

#### 1. Прямой доступ (Block Device Passthrough)

Проброс физического диска, раздела или LVM-тома хоста напрямую в виртуальную машину.

| Параметр | Описание |
| :--- | :--- |
| **Преимущества** | Максимальная производительность I/O, доступ к нативным функциям оборудования. |
| **Недостатки** | Сложность миграции между хостами, затрудненное резервное копирование, отсутствие гибкости файлов. |
| **Сценарии** | Высоконагруженные базы данных (DB), системы хранения данных (SDS). |

#### 2. Файлы-образы (Disk Image Files)

Виртуальный диск хранится в виде одного или нескольких файлов в файловой системе (ФС) хоста.

| Параметр | Описание |
| :--- | :--- |
| **Преимущества** | Простота копирования и перемещения, поддержка снапшотов, высокая портативность. |
| **Недостатки** | Накладные расходы на уровне ФС хоста, потенциальные задержки при фрагментации. |
| **Сценарии** | Среды разработки, виртуализация рабочих станций, облачные инфраструктуры. |

### Форматы файлов-образов

| Формат | Гипервизоры | Особенности |
| :--- | :--- | :--- |
| **`raw`** | Все | Побайтовая копия. Максимальная скорость, но занимает весь объем сразу (если не используется Sparse File). |
| **`qcow2`** | KVM / QEMU | Поддержка Copy-on-Write (CoW), снапшотов, сжатия и шифрования. Стандарт для Linux-виртуализации. |
| **`vmdk`** | VMware / ESXi | Широкая поддержка в корпоративном сегменте. Совместим со многими другими гипервизорами. |
| **`vhd` / `vhdx`** | Hyper-V | Родной формат Microsoft. `vhdx` поддерживает диски до 64 ТБ и защиту от повреждений при сбоях питания. |
| **`vdi`** | VirtualBox | Специализированный формат для рабочих станций с поддержкой динамического расширения. |

### Продвинутые механизмы управления

#### Тонкое выделение ресурсов (Thin Provisioning)

Механизм, позволяющий выделять ВМ диск большого объема (например, 1 ТБ), который фактически занимает на физическом носителе только место, занятое данными (например, 20 ГБ).

- **Плюсы:** Экономия дискового пространства.
- **Риски:** Опасность внезапного исчерпания места на физическом диске хоста (Overprovisioning).

#### Снапшоты (Snapshots)

Сохранение состояния диска для возможности отката.

- **Внутренние:** Данные снапшота дописываются в тот же файл (`qcow2`).
- **Внешние:** Создается новый файл-дельта, а исходный образ переходит в режим "только чтение" (`Backing File`).

#### Форматы обмена (OVF/OVA)

- **OVF (Open Virtualization Format):** Набор файлов (XML-описание + диски) для переноса ВМ между разными гипервизорами.
- **OVA (Open Virtualization Appliance):** Тот же OVF, упакованный в единый TAR-архив для удобства передачи.

## Практические сценарии

Примеры реализации описанных концепций. Детальные инструкции в [Практических сценариях](./practical_scenarios.md).

### Конвертация образов между форматами

Используется для переноса ВМ между гипервизорами (например, из VMware в KVM).

```bash
qemu-img convert -f vmdk -O qcow2 source.vmdk target.qcow2
# → преобразует проприетарный формат VMware в открытый стандарт KVM
```

### Создание "тонкого" диска

```bash
qemu-img create -f qcow2 thin_disk.qcow2 100G
# → создает файл размером в несколько мегабайт, который может вырасти до 100 ГБ
```
