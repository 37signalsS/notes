# Образы ВМ — Основные концепции

**Reliability Score: 10 (SSoT + Web Analysis)**

В данном файле рассматриваются стратегии организации дискового пространства для виртуальных машин (ВМ), архитектурные подходы к хранению данных и механизмы оптимизации производительности. Глоссарий терминов доступен в [Образы ВМ — Определения](./definitions.md).

## Способы организации хранилища

Выбор метода доступа к данным определяет баланс между производительностью I/O, гибкостью управления и возможностями масштабирования.

### 1. Файловые образы (File-based)
Виртуальный диск представлен в виде файла (`.qcow2`, `.raw`) в файловой системе хоста.
- **Преимущества:** Простота бэкапа (копирование файла), поддержка цепочек снапшотов, легкая миграция.
- **Особенности:** Зависимость от производительности и фрагментации файловой системы хоста (ext4, XFS, ZFS).

### 2. Прямой блочный доступ (Block Device Passthrough)
Проброс физического диска, раздела или LVM-тома напрямую в ВМ.
- **Преимущества:** Минимальные задержки (отсутствие слоя ФС хоста), прямой доступ к аппаратным функциям.
- **Недостатки:** Сложность «живой» миграции, риск конфликтов при доступе к одному устройству.

### 3. Сетевые блочные устройства (Network Block Storage)
Использование протоколов iSCSI, Fibre Channel или распределенных систем (Ceph RBD).
- **Преимущества:** Высокая доступность (HA), независимость данных от конкретного узла, централизованное управление.
- **Сценарии:** Энтерпрайз-кластеры и облачные платформы.

## Форматы виртуальных дисков

| Формат | Поддержка | Особенности |
| :--- | :--- | :--- |
| **`raw`** | Все гипервизоры | Максимальная скорость. Нет метаданных. Поддерживает Sparse-файлы. |
| **`qcow2`** | KVM / QEMU | Поддержка снапшотов, CoW, сжатия, шифрования и динамического расширения. |
| **`vmdk`** | VMware / ESXi | Стандарт для корпоративного сегмента. Поддерживается в KVM через конвертацию. |
| **`vhdx`** | Hyper-V | Поддержка дисков до 64 ТБ, устойчивость к сбоям питания (логирование метаданных). |

## Механизмы оптимизации и управления

### Тонкое выделение и TRIM/Discard
**Thin Provisioning** позволяет выделять виртуальный объем (напр. 100 ГБ), фактически занимая лишь 1 ГБ.
- **Проблема:** При удалении файлов внутри ВМ файл-образ на хосте не уменьшается автоматически.
- **Решение:** Механизм **Discard/TRIM**. Гостевая ОС отправляет сигнал о неиспользуемых блоках, гипервизор освобождает их в файле образа или на СХД.

### Режимы кэширования (Caching Modes)
Определяют, как данные проходят путь от гостевой ОС до физического диска:
- **`none`:** Кэш хоста игнорируется, используется прямой ввод-вывод (O_DIRECT). Рекомендуется для производительности и безопасности.
- **`writethrough`:** Запись подтверждается только после фиксации на физическом носителе. Безопасно, но медленно.
- **`writeback`:** Подтверждение сразу после записи в кэш хоста. Высокая скорость, риск потери данных при сбое питания.
- **`unsafe`:** Игнорирование всех запросов гостя на сброс кэша (flush). Только для тестирования.

### Уровни асинхронного ввода-вывода (AIO)
- **Threads:** Эмуляция асинхронности через потоки. Совместимо со всеми ФС.
- **Native:** Использование нативного Linux AIO. Требует `cache=none`.
- **io_uring:** Современный интерфейс (с 2019+), значительно снижающий оверхед на системные вызовы. Стандарт для высокопроизводительных систем в 2026 году.

### Предварительное выделение (Preallocation)
Параметр при создании `qcow2`, влияющий на скорость записи и фрагментацию:
- **`off`:** Полностью динамический рост (максимальная фрагментация).
- **`metadata`:** Создает структуру метаданных заранее. Баланс скорости и экономии места.
- **`falloc` / `full`:** Резервирует все физическое пространство. Максимальная скорость записи.

## Жизненный цикл данных и снапшоты

### Copy-on-Write (CoW) и Backing Chains
Механизм CoW лежит в основе снапшотов и связанных клонов:
1. Базовый образ (Template) открыт только для чтения.
2. Все записи идут в новый слой (Delta/Snapshot).
3. При чтении: если данных нет в Delta, они берутся из Template.
4. **Важно:** Длинные цепочки (`backing chains`) снижают производительность чтения.
