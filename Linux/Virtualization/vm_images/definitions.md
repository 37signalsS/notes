# Образы ВМ — Определения

**Reliability Score: 9 (Internal Knowledge Base)**

В данном файле приведены определения ключевых терминов, связанных с образами виртуальных машин (ВМ), форматами дисков, механизмами управления хранилищем и инструментами подготовки шаблонов. Концептуальные основы и сравнение форматов представлены в [Образы ВМ — Основные концепции](./basic_concepts.md).

## Определения

### Основные понятия

**Образ ВМ (VM Image)** — файл или логическое устройство, содержащее полную копию операционной системы (ОС), конфигурационных файлов и данных приложений виртуальной машины.

**Дисковый образ (Disk Image)** — виртуальный жесткий диск ВМ, представленный в виде файла на хостовой системе. Популярные форматы: `raw`, `qcow2`, `vmdk`.

**Block Device Passthrough** — метод предоставления ВМ прямого доступа к физическому или логическому блочному устройству хоста (диск, раздел, LVM-том), минуя уровень файловой системы хоста для повышения производительности ввода-вывода.

**Тонкое выделение (Thin Provisioning)** — технология, при которой дисковое пространство на физическом носителе резервируется только по мере фактической записи данных гостевой ОС, что позволяет создавать образы с виртуальным размером больше физического.

**Разреженный файл (Sparse File)** — тип файла, в котором последовательности нулевых байтов заменяются метаданными, что позволяет файлу занимать на диске только место, занятое полезными данными.

**Золотой образ (Golden Image)** — настроенный эталонный шаблон ОС с предустановленным ПО и примененными политиками безопасности, используемый как база для развертывания множества идентичных виртуальных машин.

### Механизмы работы с данными

**Copy-on-Write (CoW)** — стратегия оптимизации записи, при которой оригинальные блоки данных остаются неизменными, а все изменения записываются в новый файл или область (дельта-диск).

**Базовый образ (Backing File)** — файл образа, используемый в качестве основы (только для чтения) для одного или нескольких зависимых дисков.

**Цепочка образов (Backing Chain)** — иерархическая структура файлов, где каждый последующий файл хранит только изменения относительно предыдущего (Базовый образ → Снапшот 1 → Снапшот 2).

**Снапшот (Snapshot)** — моментальный снимок состояния диска ВМ.
- **Внутренний снапшот:** хранится внутри самого файла образа (например, в заголовках `qcow2`).
- **Внешний снапшот:** создается как новый файл в цепочке (текущий диск становится `backing file` для нового записываемого файла).

**Block Stream (Потоковая передача блоков)** — процесс копирования данных из базового образа в текущий активный слой, что позволяет разорвать зависимость от базового файла.

**Block Commit (Фиксация блоков)** — процесс слияния изменений из верхнего слоя цепочки (снапшота) обратно в базовый образ.

### Автоматизация и инструменты

**Cloud-init** — промышленный стандарт для инициализации ВМ при первом запуске. Позволяет настраивать пользователей, SSH-ключи, сетевые интерфейсы и выполнять скрипты на основе переданных метаданных.

**libguestfs** — набор библиотек и инструментов (например, `guestfish`) для доступа и модификации содержимого дисков ВМ без их запуска.

**virt-sysprep** — утилита для «очистки» образа ВМ (удаление SSH-ключей, логов, идентификаторов машин) перед преобразованием его в шаблон для тиражирования.

**virt-v2v / virt-p2v** — инструменты для конвертации виртуальных машин из одной среды в другую (например, VMware в KVM) или физических серверов в виртуальные образы.

**qemu-img** — универсальная CLI-утилита для создания, конвертации, изменения размера и проверки целостности образов дисков в средах QEMU/KVM.

**qemu-nbd** — инструмент для монтирования образов дисков к хостовой системе через сетевое блочное устройство (Network Block Device).

## Базовые концепции

Краткий обзор ключевых архитектурных решений. Подробности см. в [Основных концепциях](./basic_concepts.md).

### Сравнение подходов к хранению

- **Файловые образы:** Максимальная гибкость и портативность. Поддерживают сложные цепочки снапшотов и сжатие.
- **Блочные устройства (LVM/ZVOL/Ceph RBD):** Высокая производительность за счет отсутствия оверхеда файловой системы хоста.

### Жизненный цикл подготовки образа

1. **Установка:** Чистая инсталляция ОС.
2. **Настройка:** Установка ПО и `cloud-init`.
3. **Очистка:** Выполнение `virt-sysprep` для удаления уникальных данных.
4. **Фиксация:** Преобразование в шаблон (Golden Image) в режиме "только для чтения".

## Практические сценарии

Примеры использования основных инструментов. Детальные инструкции в [Практических сценариях](./practical_scenarios.md).

### Получение метаданных образа

```bash
qemu-img info disk.qcow2
# → image: disk.qcow2
# → file format: qcow2
# → virtual size: 20 GiB (21474836480 bytes)
# → disk size: 1.5 GiB
# → backing file: base.qcow2 (если есть)
```

### Подготовка образа к тиражированию

```bash
virt-sysprep -a template.qcow2
# → [   0.0] Examining the guest...
# → [   5.0] Performing "bash-history" ...
# → [   5.0] Performing "machine-id" ...
# → Очищает системные идентификаторы для безопасности
```
