# LXC (Linux Containers) — системные контейнеры

## Определения

**LXC (Linux Containers)** — технология виртуализации на уровне ОС для запуска нескольких изолированных систем Linux (контейнеров) на одном хосте.

В отличие от Docker, который ориентирован на запуск одного приложения (App Containers), LXC предназначен для запуска полноценного системного окружения (**System Containers**). Внутри LXC-контейнера работает полноценная ОС с собственной init-системой (systemd, OpenRC), пакетным менеджером и системными службами.

## Основные концепции

### Архитектура и механизмы изоляции

LXC не является "легкой виртуальной машиной", так как у него нет собственного ядра и эмуляции аппаратного обеспечения. Он использует два ключевых механизма ядра Linux:

- **Namespaces (Пространства имен)**: изолируют видимость системных ресурсов. Процесс внутри контейнера "видит" только выделенные ему ресурсы.
  - *PID*: собственные идентификаторы процессов.
  - *Network*: выделенный сетевой стек (интерфейсы, IP, таблицы маршрутизации).
  - *Mount*: изолированная файловая система.
  - *User*: изоляция идентификаторов пользователей.
- **Cgroups (Control Groups)**: ограничивают и учитывают потребление ресурсов (CPU, память, ввод-вывод). Если Namespaces управляют видимостью, то Cgroups контролируют объемы потребления.

### Ключевые особенности

- **Общее ядро**: Контейнер использует ядро хоста. Это ограничивает запуск только Linux-дистрибутивов (нельзя запустить Windows или macOS).
- **Stateful (Состояние)**: LXC-контейнеры ориентированы на сохранение состояния. Все изменения в файловой системе сохраняются внутри контейнера, аналогично виртуальным машинам.
- **Производительность**: Отсутствие гипервизора и эмуляции железа обеспечивает нативную скорость работы. Накладные расходы на работу самого контейнера минимальны.
- **Интеграция с гипервизорами**: В системах вроде Proxmox LXC является основным типом контейнеризации, поддерживающим управление через GUI, лимиты ресурсов и сетевую конфигурацию.

### Безопасность

Безопасность LXC зависит от режима маппинга пользователей.

| Тип | Описание | Уровень безопасности |
| :--- | :--- | :--- |
| **Привилегированные (Privileged)** | Root в контейнере (UID 0) совпадает с Root на хосте. | Низкий. Риск выхода на хост при взломе ядра выше. |
| **Непривилегированные (Unprivileged)** | Используют User Namespaces. Root контейнера мапится на обычного пользователя хоста. | Высокий. Root внутри контейнера не имеет прав на хост-системе. |

## Практические сценарии

### Запуск Docker внутри LXC (Nesting)

Запуск Docker внутри LXC-контейнера возможен, но требует специфической настройки хоста (например, включение опций `Nesting` и `Keyctl` в Proxmox).

- **Плюсы**: Позволяет эффективно использовать ресурсы, избегая оверхеда полноценных ВМ.
- **Минусы и риски**:
  - Потенциальное снижение изоляции (вложенная контейнеризация).
  - Возможные конфликты при монтировании файловых систем и работе сетевых драйверов Docker.
  - Официально схема считается менее надежной, чем запуск Docker в полноценной ВМ.

## Дополнительная информация

### Сравнение с другими технологиями

| Критерий | Docker | LXC | VM (KVM) |
| :--- | :--- | :--- | :--- |
| **Тип** | Прикладной контейнер | Системный контейнер | Виртуальная машина |
| **Изоляция** | Процессная | Системная | Аппаратная |
| **Ядро** | Общее с хостом | Общее с хостом | Собственное |
| **Состояние** | Stateless | Stateful | Stateful |
| **Время старта** | Секунды | Секунды | Десятки секунд |

### Эксплуатационные особенности

- **Бэкапы и снапшоты**: В современных системах управления (Proxmox) поддерживаются инкрементальные бэкапы и снимки состояния LXC-контейнеров на лету.
- **Портативность**: LXC-контейнеры можно переносить между совместимыми хостами (экспорт/импорт архива), но они не имеют единого реестра образов, подобного Docker Hub.
- **Сеть**: Поддерживаются различные типы сетевого взаимодействия: от мостов (Bridge) до прямого проброса физических интерфейсов.
