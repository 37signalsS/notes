# LXC (Linux Containers) — системные контейнеры

В данном файле рассматривается технология LXC (Linux Containers), ее архитектура, механизмы изоляции и практические аспекты использования в качестве системных контейнеров.

## Определения

**LXC (Linux Containers)** — технология виртуализации на уровне операционной системы для запуска нескольких изолированных экземпляров Linux (контейнеров) на одном узле (хосте).

**System Containers (Системные контейнеры)** — тип контейнеризации, ориентированный на предоставление полноценного окружения ОС. В отличие от **App Containers (Прикладных контейнеров)** (например, Docker), внутри LXC работает полноценная система инициализации (systemd, OpenRC), пакетный менеджер и системные службы (cron, syslog, sshd).

**Unprivileged Containers (Непривилегированные контейнеры)** — контейнеры, использующие **User Namespaces** для маппинга идентификаторов пользователей (UID/GID). Root внутри контейнера не обладает правами администратора на хост-системе.

## Базовые концепции

### Архитектура и механизмы изоляции

LXC не является полноценной виртуальной машиной, так как не содержит собственного ядра и не эмулирует аппаратное обеспечение. Технология опирается на два фундаментальных механизма ядра Linux:

- **Namespaces (Пространства имен)** — изолируют видимость системных ресурсов:
  - **PID**: собственные идентификаторы процессов.
  - **Network**: выделенный сетевой стек (интерфейсы, IP, таблицы маршрутизации).
  - **Mount**: изолированные точки монтирования файловой системы.
  - **User**: изоляция идентификаторов пользователей и групп.
  - **UTS**: изоляция имен хостов и доменов.
  - **IPC**: изоляция межпроцессного взаимодействия.
- **Cgroups (Control Groups)** — управляют распределением и лимитами физических ресурсов (CPU, память, I/O).

### Ключевые особенности

- **Общее ядро**: Контейнер использует ядро хоста, что ограничивает запуск только Linux-дистрибутивов.
- **Stateful (Состояние)**: Изменения в файловой системе сохраняются внутри контейнера, что делает его похожим на классическую ВМ по опыту эксплуатации.
- **Производительность**: Отсутствие гипервизора обеспечивает нативную скорость выполнения процессов и минимальные задержки при операциях ввода-вывода.
- **Интеграция**: LXC является базовой технологией для платформ управления, таких как Proxmox, где поддерживается гибкая настройка ресурсов и сети через GUI.

### Безопасность

Безопасность LXC критически зависит от режима работы с пользователями:

| Режим | Описание | Уровень безопасности |
| :--- | :--- | :--- |
| **Привилегированный** | UID 0 контейнера совпадает с UID 0 хоста. | Низкий. Возможен выход на хост при эксплуатации уязвимостей ядра. |
| **Непривилегированный** | Используются **User Namespaces**. | Высокий. Root контейнера является обычным пользователем на хосте. |

## Практические сценарии

### Вложенная виртуализация (Nesting): Docker внутри LXC

Запуск Docker внутри LXC часто применяется для экономии ресурсов, чтобы избежать накладных расходов полноценных виртуальных машин.

**Требования (на примере Proxmox):**

1. Включение опции `Nesting` в конфигурации контейнера.
2. Поддержка `Keyctl` для корректной работы некоторых системных вызовов внутри вложенного контейнера.

**Особенности:**

- Позволяет запускать микросервисную инфраструктуру внутри одного системного контейнера.
- Требует внимательной настройки драйверов хранилища (Storage Drivers), например, `overlay2` или `vfs`.
- Рекомендуется использовать только в доверенных средах из-за потенциального расширения поверхности атаки.

## Дополнительная информация

### Сравнение контейнеров и виртуальных машин

| Критерий | Docker | LXC | VM (KVM) |
| :--- | :--- | :--- | :--- |
| **Тип** | Прикладной контейнер | Системный контейнер | Виртуальная машина |
| **Изоляция** | Процессная | Системная | Аппаратная |
| **Ядро** | Общее с хостом | Общее с хостом | Собственное |
| **Состояние** | Stateless | Stateful | Stateful |

### Эксплуатационные особенности

- **Резервное копирование**: Поддерживаются снимки состояния (Snapshots) и инкрементальные бэкапы без остановки контейнера.
- **Портативность**: Перенос осуществляется через экспорт/импорт архива корневой ФС, однако отсутствует глобальный реестр образов аналогичный Docker Hub.
- **Сеть**: Поддерживаются различные режимы: от стандартного моста (Bridge) до прямого проброса интерфейсов (Passthrough).
