# LXC (Linux Containers) — системные контейнеры

В данном файле рассматривается технология LXC (Linux Containers), ее архитектура, механизмы изоляции и практические аспекты использования в качестве системных контейнеров.

## Определения

**LXC (Linux Containers)** — технология виртуализации на уровне операционной системы для запуска нескольких изолированных экземпляров Linux (контейнеров) на одном узле (хосте). В узком смысле LXC — это набор инструментов (`lxc-*`) и библиотека (`liblxc`), предоставляющая интерфейс к механизмам изоляции ядра.

**LXD / Incus** — современные системы управления контейнерами, построенные поверх LXC. Они предоставляют REST API, более удобный CLI и расширенные возможности (живая миграция, управление сетями и хранилищами). Incus является форком LXD, созданным сообществом после перехода проекта LXD под полный контроль Canonical.

**System Containers (Системные контейнеры)** — тип контейнеризации, ориентированный на предоставление полноценного окружения ОС. В отличие от **App Containers (Прикладных контейнеров)** (например, Docker), внутри LXC работает полноценная система инициализации (systemd, OpenRC), пакетный менеджер и системные службы (cron, syslog, sshd).

**Unprivileged Containers (Непривилегированные контейнеры)** — контейнеры, использующие **User Namespaces** для маппинга идентификаторов пользователей (UID/GID). Root внутри контейнера не обладает правами администратора на хост-системе.

## Базовые концепции

### Архитектура и механизмы изоляции

LXC не является полноценной виртуальной машиной, так как не содержит собственного ядра и не эмулирует аппаратное обеспечение. Технология опирается на два фундаментальных механизма ядра Linux:

- **Namespaces (Пространства имен)** — изолируют видимость системных ресурсов:
  - **PID**: собственные идентификаторы процессов.
  - **Network**: выделенный сетевой стек (интерфейсы, IP, таблицы маршрутизации).
  - **Mount**: изолированные точки монтирования файловой системы.
  - **User**: изоляция идентификаторов пользователей и групп.
  - **UTS**: изоляция имен хостов и доменов.
  - **IPC**: изоляция межпроцессного взаимодействия.
- **Cgroups (Control Groups)** — управляют распределением и лимитами физических ресурсов (CPU, память, I/O).

### Хранилища (Storage Backends)

LXC поддерживает различные способы хранения корневой файловой системы контейнеров:

- **dir**: Обычная директория на ФС хоста. Простой способ, не требующий настройки, но не поддерживающий быстрые снимки.
- **Btrfs / ZFS**: Использование возможностей Copy-on-Write (CoW) данных ФС для мгновенного создания снимков и клонирования контейнеров.
- **LVM**: Создание логических томов для каждого контейнера. Позволяет жестко ограничить дисковое пространство на уровне блочного устройства.
- **OverlayFS**: Комбинирование неизменяемого базового слоя (образа) и слоя записи, аналогично Docker.

### Сетевые режимы

LXC предоставляет гибкие возможности настройки сети:

- **veth (Virtual Ethernet)**: По умолчанию. Контейнер подключается к мосту (bridge) на хосте через пару виртуальных интерфейсов.
- **macvlan**: Контейнер получает собственный MAC-адрес на физическом интерфейсе хоста, становясь полноценным участником внешней сети.
- **ipvlan**: Аналогично macvlan, но использует MAC-адрес хоста, работая на L3 (IP). Полезно при ограничениях на количество MAC-адресов.
- **phys**: Проброс физического сетевого интерфейса целиком внутрь контейнера.
- **none**: Контейнер имеет только локальную петлю (loopback), полная изоляция от сети.

### Ключевые особенности

- **Общее ядро**: Контейнер использует ядро хоста, что ограничивает запуск только Linux-дистрибутивов.
- **Stateful (Состояние)**: Изменения в файловой системе сохраняются внутри контейнера, что делает его похожим на классическую ВМ по опыту эксплуатации.
- **Производительность**: Отсутствие гипервизора обеспечивает нативную скорость выполнения процессов и минимальные задержки при операциях ввода-вывода.
- **Интеграция**: LXC является базовой технологией для платформ управления, таких как Proxmox, где поддерживается гибкая настройка ресурсов и сети через GUI.

### Безопасность

Безопасность LXC критически зависит от режима работы с пользователями:

| Режим | Описание | Уровень безопасности |
| :--- | :--- | :--- |
| **Привилегированный** | UID 0 контейнера совпадает с UID 0 хоста. | Низкий. Возможен выход на хост при эксплуатации уязвимостей ядра. |
| **Непривилегированный** | Используются **User Namespaces**. | Высокий. Root контейнера является обычным пользователем на хосте. |

## Управление и инструменты (CLI)

В классическом LXC управление осуществляется через набор утилит `lxc-*`.

### Основные команды

- **`lxc-create`**: Создание контейнера. Обычно требует указания шаблона (например, `-t download`).
- **`lxc-start`**: Запуск контейнера. Ключ `-d` запускает его в фоновом режиме.
- **`lxc-ls -f`**: Список контейнеров с подробной информацией (статус, IP, автозапуск).
- **`lxc-info -n <name>`**: Получение детальной статистики о ресурсах и состоянии контейнера.
- **`lxc-attach -n <name>`**: Выполнение команд внутри работающего контейнера (аналог `docker exec`).
- **`lxc-stop`**: Остановка контейнера.
- **`lxc-destroy`**: Удаление контейнера и его файловой системы.

### Пример конфигурации

Файлы конфигурации обычно располагаются в `/var/lib/lxc/<name>/config`.

```bash
# Имя и тип сети
lxc.net.0.type = veth
lxc.net.0.link = lxcbr0
lxc.net.0.flags = up
lxc.net.0.hwaddr = 00:16:3e:xx:xx:xx

# Путь к корневой ФС
lxc.rootfs.path = /var/lib/lxc/my-container/rootfs

# Лимиты ресурсов (Cgroups)
lxc.cgroup2.memory.max = 1G
lxc.cgroup2.cpuset.cpus = 0-1

# Автозапуск
lxc.start.auto = 1
lxc.start.delay = 5
```

## Практические сценарии

### Вложенная виртуализация (Nesting): Docker внутри LXC

Запуск Docker внутри LXC часто применяется для экономии ресурсов, чтобы избежать накладных расходов полноценных виртуальных машин.

**Требования (на примере Proxmox):**

1. Включение опции `Nesting` в конфигурации контейнера.
2. Поддержка `Keyctl` для корректной работы некоторых системных вызовов внутри вложенного контейнера.

**Особенности:**

- Позволяет запускать микросервисную инфраструктуру внутри одного системного контейнера.
- Требует внимательной настройки драйверов хранилища (Storage Drivers), например, `overlay2` или `vfs`.
- Рекомендуется использовать только в доверенных средах из-за потенциального расширения поверхности атаки.

## Дополнительная информация

### Сравнение контейнеров и виртуальных машин

| Критерий | Docker | LXC | VM (KVM) |
| :--- | :--- | :--- | :--- |
| **Тип** | Прикладной контейнер | Системный контейнер | Виртуальная машина |
| **Изоляция** | Процессная | Системная | Аппаратная |
| **Ядро** | Общее с хостом | Общее с хостом | Собственное |
| **Состояние** | Stateless | Stateful | Stateful |

### Эксплуатационные особенности

- **Шаблоны и образы**: LXC использует систему шаблонов (`templates`). Утилита `lxc-download` позволяет загружать готовые минимальные образы различных дистрибутивов (Debian, Ubuntu, CentOS, Alpine) из официальных репозиториев.
- **Резервное копирование**: Поддерживаются снимки состояния (Snapshots) и инкрементальные бэкапы без остановки контейнера. При использовании ZFS/Btrfs это происходит мгновенно.
- **Портативность**: Перенос осуществляется через экспорт/импорт архива корневой ФС. В отличие от Docker, образы LXC содержат полную ОС и обычно имеют больший объем.
- **Автозапуск**: Поддерживается встроенный механизм управления очередностью и задержками при загрузке хоста через параметры `lxc.start.*`.
- **Сеть**: Поддерживаются различные режимы: от стандартного моста (Bridge) до прямого проброса интерфейсов (Passthrough).
