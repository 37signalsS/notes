# Решение проблем KVM (Troubleshooting)

## Определения

**TCG (Tiny Code Generator)** — механизм программной эмуляции процессора в QEMU. Транслирует инструкции гостевого CPU на язык хостового CPU. В сотни раз медленнее аппаратной виртуализации (VT-x/AMD-V). Подробнее: [KVM Overview](./overview.md#связка-qemu--kvm).

**CPU mode (host-passthrough / host-model)** — режим проброса CPU хоста в гостевую ВМ. Определяет, какие инструкции процессора доступны гостевой ОС. Подробнее: [KVM Overview — CPU Mode](./overview.md#сценарий-2-проверка-режима-cpu-виртуальной-машины).

**Миграция ВМ** — перенос виртуальной машины с одного хоста KVM на другой. Может быть «живой» (live migration, без простоя) или «холодной» (с остановкой).

## Базовые концепции

### Причины деградации производительности

| Симптом | Возможная причина | Диагностика |
| :--- | :--- | :--- |
| Высокие задержки, свободные CPU/RAM | Откат на TCG-эмуляцию | `virsh dominfo`, логи KVM |
| Ошибки в логах | Несовместимость CPU хостов | `egrep -c '(vmx\|svm)' /proc/cpuinfo` |
| Абстрактный CPU-mode (`qemu64`, `kvm64`) | Неправильная конфигурация `<cpu>` | `virsh dominfo` |

### Режимы CPU в libvirt

| Режим | Когда использовать | Особенности |
| :--- | :--- | :--- |
| **`host-passthrough`** | Идентичные CPU на хостах | Пробрасывает все флаги CPU напрямую. Максимальная производительность |
| **`host-model`** | Разные CPU (гетерогенный кластер) | Выбирает совместимый набор инструкций. Безопаснее для миграции |
| **`qemu64`/`kvm64`** | По умолчанию | Базовый набор инструкций. Не использует возможности реального CPU |

### Механизм отката на TCG

При миграции ВМ на хост с другим CPU QEMU может не найти запрошенные функции процессора. В этом случае:

1. KVM не может предоставить запрошенные флаги CPU
2. QEMU автоматически переключается на TCG-эмуляцию
3. Производительность падает в сотни раз

Лог-сообщение:

```log
kvm: host doesn't support requested feature...
falling back to tcg
```

## Практические сценарии

### Сценарий 1: Снижение производительности после миграции

**Симптомы:** Увеличение задержек, падение отзывчивости, CPU/RAM хоста свободны.

**Шаг 1: Диагностика CPU-mode**

```bash
virsh dominfo <имя_вм>
```

Обратите внимание на строку `CPU mode`. Значения `qemu64`, `kvm64` или `custom` — признак проблемы.

**Шаг 2: Проверка возможностей домена**

```bash
virsh domcapabilities --domain <имя_вм>
```

**Шаг 3: Проверка аппаратной виртуализации на обоих хостах**

```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
```

Результат `0` означает, что виртуализация отключена в BIOS/UEFI хоста.

**Шаг 4: Исправление конфигурации CPU**

```bash
virsh edit <имя_вм>
```

В секции `<domain>` измените конфигурацию CPU:

**Одинаковые CPU на хостах:**

```xml
<cpu mode="host-passthrough"/>
```

**Разные CPU на хостах:**

```xml
<cpu mode="host-model"/>
```

**Шаг 5: Перезагрузка ВМ**

```bash
virsh destroy <имя_вм>
virsh start <имя_вм>
```

**Шаг 6: Подтверждение исправления**

```bash
virsh dominfo <имя_вм> | grep "CPU mode"
```

Ожидаемый результат: `host-passthrough` или `host-model`.

### Сценарий 2: ВМ не запускается после миграции

**Возможные причины:**

| Причина | Решение |
| :--- | :--- |
| Нет поддержки VT-x/AMD-V на целевом хосте | Включить в BIOS/UEFI |
| Несовместимые версии QEMU/libvirt | Обновить ПО на обоих хостах |
| Отсутствуют сетевые мосты | Воссоздать конфигурацию сети |
| Нет доступа к хранилищу | Настроить общий storage (NFS, iSCSI) |

### Сценарий 3: Проблемы с производительностью I/O

**Симптомы:** Медленная работа с диском/сетью в ВМ.

**Проверка использования virtio:**

```bash
virsh dumpxml <имя_вм> | grep -E "model.*virtio"
```

Если в выводе нет `virtio` — ВМ использует эмуляцию (`e1000`, `ide`). Рекомендуется изменить конфигурацию устройств на `virtio` для повышения производительности I/O. Подробнее: [KVM Overview — Virtio](./overview.md#механизм-паравиртуализации-virtio).

## Дополнительная информация

### Превентивные меры

- **Единая конфигурация CPU:** используйте `host-model` в кластерах с разнородным оборудованием
- **Мониторинг TCG:** настройте алерты на переключение в режим эмуляции
- **Тестирование миграции:** проверяйте миграцию до ввода в production
- **Версионирование:** синхронизируйте версии QEMU/libvirt на хостах
