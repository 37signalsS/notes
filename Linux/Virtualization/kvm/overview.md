# KVM: Обзор и архитектура

Этот файл описывает архитектуру KVM, связку QEMU+KVM и механизм virtio. Общие концепции виртуализации (типы гипервизоров, контейнеры vs ВМ) — в [Virtualization Overview](../virtualization_overview.md).

## Определения

**KVM (Kernel-based Virtual Machine)** — модуль ядра Linux, превращающий его в гипервизор 1-го типа (bare-metal). Выполняет инструкции процессора гостевой ОС напрямую на физическом CPU. Подробнее: [Virtualization Overview](../virtualization_overview.md).

**QEMU (Quick Emulator)** — эмулятор периферийных устройств: диски, сетевые карты, видео, USB, PCI. В связке с KVM отвечает за эмуляцию оборудования, пока KVM выполняет процессорные инструкции.

**libvirt** — набор инструментов для управления виртуализацией (API, демон `libvirtd`, CLI-утилиты `virsh`, `virt-install`). Предоставляет единый уровень абстракции для KVM и других гипервизоров. Подробнее: [KVM Management](./management.md).

**Virtio** — стандарт паравиртуализированных драйверов для оптимизации I/O в виртуализированных средах. Заменяет полную эмуляцию устройств эффективным интерфейсом через общую память.

## Базовые концепции

### Связка QEMU + KVM

KVM не работает без QEMU — это взаимодополняющие технологии:

| Компонент | Роль | Что выполняет |
| :--- | :--- | :--- |
| **KVM** | Гипервизор (модуль ядра) | Инструкции CPU гостя напрямую (VT-x/AMD-V) |
| **QEMU** | Эмулятор устройств | Диски, сеть, видео, USB, PCI |

**Без KVM:** QEMU использует TCG (Tiny Code Generator) — медленную программную трансляцию инструкций.

**С KVM:** инструкции CPU выполняются напрямую, QEMU эмулирует только периферию. Результат — производительность, близкая к bare-metal.

### KVM и кольца защиты (Protection Rings)

С аппаратной виртуализацией (VT-x/AMD-V) гостевая ОС получает прямой доступ к **Ring 0** (максимальные привилегии). Без аппаратной поддержки QEMU вынужден транслировать привилегированные инструкции через TCG, что значительно медленнее. Подробнее: [Virtualization Overview — Protection Rings](../virtualization_overview.md#кольца-защиты-protection-rings).

### Сравнение с альтернативами

| Решение | Гипервизор | Интеграция с Linux |
| :--- | :--- | :--- |
| **KVM** | Модуль ядра Linux | Нативная |
| **VirtualBox** | Собственный (не KVM) | Базовая |
| **VMware Workstation** | Собственный | Ограниченная |

KVM — единственное решение, где гипервизор является частью ядра Linux. Это обеспечивает минимальные накладные расходы и отсутствие дополнительной нагрузки от стороннего гипервизора. Подробнее: [Virtualization Overview — Сравнение](../virtualization_overview.md#сравнение-решений-для-рабочих-станций).

### Механизм паравиртуализации `virtio`

В отличие от полной эмуляции (когда гостевая ОС «думает», что работает с реальной сетевой картой), `virtio` предоставляет оптимизированный интерфейс:

1. **Осведомлённость:** Гость (драйверы `virtio-*`) и гипервизор (QEMU/KVM) «знают» о виртуализации
2. **Общая память:** Обмен данными через эффективные очереди (virtqueues) вместо эмуляции регистров устройства

**Преимущества:**

| Критерий | Эмуляция (e1000, IDE) | Virtio |
| :--- | :--- | :--- |
| **Производительность I/O** | Низкая (контекстные переключения) | Близка к bare-metal |
| **Накладные расходы CPU** | Высокие | Минимальные |
| **Поддержка** | Универсальная | Требует драйверы в госте |

**Типы устройств virtio:**

| Устройство | Назначение |
| :--- | :--- |
| `virtio-net` | Сетевой адаптер |
| `virtio-blk` | Дисковый контроллер |
| `virtio-scsi` | SCSI-контроллер для сложных конфигураций |
| `virtio-balloon` | Динамическое управление памятью гостя |

## Практические сценарии

### Сценарий 1: Проверка поддержки KVM

```bash
# Аппаратная виртуализация (результат > 0)
egrep -c '(vmx|svm)' /proc/cpuinfo

# Загруженные модули KVM
lsmod | grep -i kvm
```

Ожидаемый вывод `lsmod`:

- `kvm_intel` (или `kvm_amd`)
- `kvm` (базовый модуль)

### Сценарий 2: Проверка режима CPU виртуальной машины

Если ВМ работает с абстрактным CPU-профилем (`qemu64`, `kvm64`) вместо реальных возможностей хоста — она не использует все функции процессора:

```bash
virsh dominfo <имя_вм> | grep "CPU mode"
```

Рекомендуемые режимы: `host-model` или `host-passthrough`. Настройка через `virsh edit <имя_вм>` в секции `<cpu>`. Подробнее: [KVM Troubleshooting](./troubleshooting.md).

### Сценарий 3: Проверка использования virtio в ВМ

```bash
virsh dumpxml <имя_вм> | grep -E "model.*virtio"
```

Ожидаемый вывод — строки с `model type='virtio'` для сетевых и дисковых интерфейсов. Если используются `e1000` или `ide` — рекомендуется заменить на `virtio` для повышения производительности I/O.
