# KVM — Обзор и архитектура

В данном файле описывается архитектура KVM (Kernel-based Virtual Machine), взаимодействие с QEMU и механизм virtio. Общие принципы виртуализации (типы гипервизоров, контейнеры против ВМ) представлены в [Виртуализация: Обзор](../virtualization_overview.md).

## Определения

**KVM (Kernel-based Virtual Machine)** — модуль ядра Linux, обеспечивающий инфраструктуру для аппаратной виртуализации. Превращает ядро в гипервизор 1-го типа (bare-metal), позволяя гостевым операционным системам выполнять инструкции напрямую на физическом процессоре (CPU).

**QEMU (Quick Emulator)** — эмулятор и виртуализатор с открытым исходным кодом. В связке с KVM отвечает за эмуляцию периферийных устройств (диски, сетевые карты, USB, PCI), в то время как KVM обеспечивает высокопроизводительное выполнение кода гостя.

**libvirt** — открытый набор инструментов (API, демон `libvirtd`, утилиты `virsh`, `virt-install`) для управления виртуализацией. Служит уровнем абстракции для KVM, Xen, LXC и других решений. Подробнее: [Управление KVM](./management.md).

**Virtio** — стандарт паравиртуализированных драйверов, разработанный для оптимизации операций ввода-вывода (I/O). Вместо полной эмуляции оборудования использует эффективный механизм обмена данными через общую память.

## Базовые концепции

### Взаимодействие QEMU и KVM

KVM и QEMU дополняют друг друга, создавая полноценную среду виртуализации:

| Компонент | Роль | Функции |
| :--- | :--- | :--- |
| **KVM** | Гипервизор (ядро) | Выполнение инструкций CPU гостя (VT-x/AMD-V) |
| **QEMU** | Эмулятор (пользовательское пространство) | Эмуляция оборудования (диски, сеть, VGA, входные устройства) |

Если KVM недоступен, QEMU может работать в режиме TCG (Tiny Code Generator), выполняя программную трансляцию инструкций, что значительно медленнее аппаратного ускорения.

### Кольца защиты и аппаратное ускорение

Благодаря технологиям Intel VT-x и AMD-V, KVM позволяет гостевой ОС работать на уровне **Ring 0** (привилегированный режим) без конфликтов с хостовой ОС. Это минимизирует накладные расходы на переключение контекста между гостем и гипервизором. Подробнее о механизме колец защиты: [Виртуализация: Кольца защиты](../virtualization_overview.md#кольца-защиты-protection-rings).

### Сравнение с другими решениями

KVM является частью ядра Linux, что отличает его от сторонних гипервизоров (VirtualBox, VMware), требующих установки дополнительных модулей или работы в качестве отдельных приложений. Сводное сравнение гипервизоров доступно в разделе [Типы виртуализации](../virtualization_overview.md#типы-виртуализации).

### Паравиртуализация virtio

В отличие от полной эмуляции (например, сетевая карта Intel e1000), где гипервизор имитирует реальное физическое устройство, `virtio` предлагает оптимизированный путь:

1. **Осведомленность:** Гостевая ОС «знают», что она виртуализирована, и использует специальные драйверы.
2. **Производительность:** Передача данных происходит через очереди (virtqueues) в оперативной памяти, что исключает затратную эмуляцию регистров оборудования.

**Основные типы устройств virtio:**

- `virtio-net`: Высокоскоростной сетевой адаптер.
- `virtio-blk` / `virtio-scsi`: Оптимизированные дисковые контроллеры.
- `virtio-balloon`: Механизм динамического возврата неиспользуемой памяти хосту.

## Практические сценарии

### Проверка поддержки KVM

Для работы KVM необходима поддержка виртуализации на уровне процессора и корректная настройка модулей ядра. Подробные инструкции по проверке и активации приведены в разделе [Установка KVM — Проверка поддержки](./installation.md#сценарий-1-проверка-поддержки-аппаратной-виртуализации).

### Сценарий 2: Выбор режима CPU для производительности

По умолчанию виртуальные машины могут использовать универсальные профили (например, `qemu64`), которые не передают гостю все возможности физического процессора (AES-NI, AVX).

```bash
# Проверка текущего режима CPU через libvirt
virsh dominfo <имя_вм> | grep "CPU mode"
```

Для максимальной производительности рекомендуется использовать режимы `host-model` или `host-passthrough` в конфигурации ВМ.

### Сценарий 3: Использование virtio в конфигурации ВМ

Для повышения скорости работы дисковой и сетевой подсистем необходимо убедиться, что устройства используют драйвер `virtio`.

```bash
# Проверка типа модели устройств в XML-конфигурации
virsh dumpxml <имя_вм> | grep -E "model.*virtio"
```

Если используются эмулируемые устройства (`rtl8139`, `ide`), их следует заменить на аналоги `virtio` при наличии поддержки драйверов в гостевой ОС.
