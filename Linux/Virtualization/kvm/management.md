# Управление виртуальными машинами KVM

В данном файле рассматриваются инструменты и методы жизненного цикла виртуальных машин (ВМ) в среде KVM: создание, настройка, управление состояниями, снимками и хранилищами. Архитектура гипервизора описана в [KVM — Обзор и архитектура](./overview.md).

## Термины и инструменты

Основные архитектурные определения (KVM, QEMU, libvirt) представлены в разделе **[KVM — Обзор и архитектура](./overview.md#определения)**. Для повседневного управления используются следующие инструменты:

**virsh** — основная CLI-утилита для управления доменами (ВМ) через libvirt. Позволяет изменять состояние ВМ, редактировать XML-конфигурации, управлять сетью и хранилищами.

**virt-install** — утилита для автоматизированного развертывания новых ВМ. Поддерживает установку из ISO, сетевых репозиториев и автоматическую настройку через `cloud-init`.

**virt-viewer / virt-manager** — графические инструменты для доступа к консоли ВМ (через протоколы VNC или SPICE) и визуального управления.

**osinfo-query** — база данных параметров ОС, используемая для автоматической оптимизации конфигурации ВМ под конкретный дистрибутив.

## Базовые концепции

### Методы развертывания ВМ

В современной практике выделяют два основных подхода к созданию ВМ:

1. **Интерактивный (ISO):** Установка ОС с виртуального CD-ROM. Требует ручного ввода параметров в процессе установки.
2. **Автоматизированный (Cloud-init):** Использование готовых облачных образов (Cloud Images) и передача конфигурации (пользователи, SSH-ключи, скрипты) при первом запуске. Это стандарт для масштабируемых сред.

### Иерархия хранения (Storage)

Libvirt абстрагирует работу с дисками через два понятия:
- **Storage Pool (Пул):** Логическое место хранения (директория на диске, LVM-группа, NFS-шара, iSCSI-цель).
- **Storage Volume (Том):** Виртуальный диск (файл `qcow2`, LVM-логический том), расположенный внутри пула.

### Жизненный цикл и состояния домена

| Состояние | Описание | Команда перехода |
| :--- | :--- | :--- |
| **Running** | ВМ запущена и потребляет ресурсы. | `virsh start` |
| **Paused** | Выполнение приостановлено, состояние в RAM сохранено. | `virsh suspend` / `resume` |
| **Shut off** | ВМ выключена, конфигурация сохранена. | `virsh shutdown` / `destroy` |
| **Transient** | Временная ВМ без сохраненной конфигурации XML. | `qemu-system-*` |

## Практические сценарии

### Сценарий 1: Автоматизированное создание ВМ через Cloud-init

Современные версии `virt-install` позволяют настраивать гостевую ОС без создания вспомогательных ISO-образов.

```bash
# Развертывание Ubuntu 24.04 из облачного образа
virt-install \
  --name server-web-01 \
  --memory 2048 \
  --vcpus 2 \
  --os-variant ubuntu24.04 \
  --disk path=/var/lib/libvirt/images/server-web-01.qcow2,size=20,backing_store=/path/to/ubuntu-24.04-cloudimg.img \
  --network network=default,model=virtio \
  --cloud-init user-data=./user-config.yaml,root-ssh-key=/home/admin/.ssh/id_rsa.pub \
  --graphics none \
  --import
```

*Примечание: Параметр `--import` используется, если ОС уже установлена в базовом образе (`backing_store`).*

### Сценарий 2: Управление снимками (Snapshots)

Снимки позволяют сохранить состояние диска и оперативной памяти для быстрого отката. Рекомендуется использовать для ВМ с дисками в формате `qcow2`.

```bash
# 1. Создание снимка (с сохранением состояния памяти)
virsh snapshot-create-as --domain server-web-01 \
  --name "Pre-Upgrade" \
  --description "Перед обновлением ядра" \
  --pause

# 2. Просмотр списка снимков
virsh snapshot-list server-web-01

# 3. Откат к выбранному состоянию
virsh snapshot-revert server-web-01 --snapshotname "Pre-Upgrade" --running

# 4. Удаление снимка
virsh snapshot-delete server-web-01 --snapshotname "Pre-Upgrade"
```

### Сценарий 3: Динамическое изменение ресурсов (Hotplug)

Libvirt позволяет изменять объем памяти и количество CPU "на лету" (требует поддержки в гостевой ОС).

```bash
# Изменение объема оперативной памяти (текущее и в конфигурацию)
virsh setmem server-web-01 4G --live --config

# Изменение количества доступных vCPU
virsh setvcpus server-web-01 4 --live
```

### Сценарий 4: Управление хранилищами через virsh

Работа с пулами и томами вместо прямого обращения к файловой системе.

```bash
# 1. Создание и активация нового пула (директории)
virsh pool-define-as custom-pool dir --target /mnt/data/vms
virsh pool-autostart custom-pool
virsh pool-start custom-pool

# 2. Создание виртуального диска (тома) в пуле
virsh vol-create-as --pool custom-pool --name data-disk.qcow2 --capacity 50G --format qcow2

# 3. Подключение созданного диска к работающей ВМ
virsh attach-disk server-web-01 /mnt/data/vms/data-disk.qcow2 vdb --targetbus virtio --persistent
```

### Сценарий 5: Полезные команды для диагностики и доступа

| Задача | Команда |
| :--- | :--- |
| **Консольный доступ** | `virsh console <имя_вм>` (требует настройки ttyS0 в госте) |
| **Узнать IP-адрес** | `virsh domifaddr <имя_вм>` |
| **Автозапуск при загрузке** | `virsh autostart <имя_вм>` |
| **Информация о хосте** | `virsh nodeinfo` |
| **Редактирование XML** | `virsh edit <имя_вм>` |
