# Управление виртуальными машинами KVM

В данном файле рассматриваются инструменты и методы жизненного цикла виртуальных машин (ВМ) в среде KVM: создание, настройка, управление состояниями и удаление. Архитектура гипервизора описана в [KVM — Обзор и архитектура](./overview.md).

## Определения

**QEMU (Quick Emulator)** — эмулятор и виртуализатор, способный запускать ВМ как в связке с KVM (аппаратное ускорение), так и самостоятельно (программная эмуляция). В контексте управления часто используется для быстрого тестирования без регистрации в системе.

**libvirt** — стандартный уровень абстракции (API) и набор инструментов для управления виртуализацией. Позволяет работать с ВМ единообразно независимо от гипервизора. Основные компоненты: демон `libvirtd`, CLI-утилиты `virsh` и `virt-install`.

**virsh** — основная CLI-утилита для управления доменами (виртуальными машинами) через libvirt. Используется для изменения состояния ВМ, редактирования конфигураций и мониторинга.

**virt-install** — специализированная утилита для автоматизированного создания новых ВМ. Позволяет задать параметры диска, сети, ресурсов и источника установки ОС.

**osinfo-query** — инструмент для получения идентификаторов операционных систем. Эти идентификаторы необходимы `virt-install` для автоматической оптимизации конфигурации под конкретную ОС.

## Базовые концепции

### Методы создания виртуальных машин

| Метод | Инструмент | Постоянство (Persistence) | Основной сценарий |
| :--- | :--- | :--- | :--- |
| **Прямой запуск** | `qemu-system-*` | ❌ Отсутствует | Отладка ядра, быстрая проверка образа |
| **Управляемый домен** | `virt-install` + `virsh` | ✅ Присутствует | Постоянные серверы, production-среды |

### Пути и файлы по умолчанию в libvirt

| Ресурс | Стандартный путь | Описание |
| :--- | :--- | :--- |
| **ISO-образы** | `/var/lib/libvirt/boot/` | Рекомендуемое место для установочных носителей |
| **Диски ВМ** | `/var/lib/libvirt/images/` | Хранилище образов дисков (`qcow2`, `raw`) |
| **Конфигурации** | `/etc/libvirt/qemu/` | XML-файлы с описанием параметров каждой ВМ |

**Важно:** Редактирование XML-файлов напрямую не рекомендуется. Используйте команду `virsh edit <имя_вм>`.

### Выбор формата диска

Для большинства задач в KVM используется формат **qcow2**, поддерживающий снапшоты (snapshots) и динамическое расширение («тонкие» диски). Формат **raw** выбирается при необходимости исключить накладные расходы на уровне формата файла. Подробнее: [Образы ВМ — Основные концепции](../vm_images/basic_concepts.md).

## Практические сценарии

### Сценарий 1: Быстрый запуск образа через QEMU

Позволяет запустить ВМ без создания постоянной конфигурации в libvirt.

```bash
qemu-system-x86_64 \
  -enable-kvm \
  -m 2G \
  -cpu host \
  -drive file=ubuntu-server.qcow2,format=qcow2 \
  -netdev user,id=net0 \
  -device virtio-net-pci,netdev=net0 \
  -nographic
```

### Сценарий 2: Создание постоянной ВМ через virt-install

**1. Выбор идентификатора ОС:**

```bash
osinfo-query os | grep -i "ubuntu 24.04"
# → ubuntu24.04 | Ubuntu 24.04 LTS | 24.04 | http://ubuntu.com/ubuntu/24.04
```

**2. Создание и запуск процесса установки:**

```bash
sudo virt-install \
    --name=server-01 \
    --os-variant=ubuntu24.04 \
    --vcpu=2 \
    --ram=2048 \
    --graphics vnc \
    --cdrom=/var/lib/libvirt/boot/ubuntu-24.04.iso \
    --network bridge:virbr0,model=virtio \
    --disk path=/var/lib/libvirt/images/server-01.qcow2,size=20,bus=virtio,format=qcow2
# → Starting install...
# → Domain creation completed.
```

### Сценарий 3: Основные команды управления (virsh)

| Задача | Команда |
| :--- | :--- |
| Список всех ВМ | `virsh list --all` |
| Запуск выключенной ВМ | `virsh start server-01` |
| Выключение (ACPI) | `virsh shutdown server-01` |
| Принудительная остановка | `virsh destroy server-01` |
| Редактирование параметров | `virsh edit server-01` |
| Удаление регистрации ВМ | `virsh undefine server-01 --remove-all-storage` |

**Примечание:** Флаг `--remove-all-storage` при удалении ВМ автоматически стирает связанные файлы дисков.
