# Установка и настройка KVM

В данном файле приведено пошаговое руководство по подготовке системы, установке программного стека KVM/QEMU и первичной настройке среды виртуализации. Архитектурный обзор доступен в [KVM — Обзор и архитектура](./overview.md).

## Определения

**KVM (Kernel-based Virtual Machine)** — технология виртуализации в ядре Linux. Требует аппаратной поддержки со стороны процессора (Intel VT-x или AMD-V).

**QEMU (Quick Emulator)** — эмулятор аппаратного обеспечения, работающий совместно с KVM для создания полноценных виртуальных машин (ВМ).

**libvirt** — открытый интерфейс (API) и набор инструментов для управления ВМ. Включает демон `libvirtd` и консольные утилиты для повседневного администрирования. Подробнее: [Управление KVM](./management.md).

## Базовые концепции

### Требования к системе и среде

Перед началом установки необходимо убедиться в выполнении следующих условий:

| Параметр | Описание | Метод проверки |
| :--- | :--- | :--- |
| **Виртуализация CPU** | Поддержка на уровне архитектуры процессора | Проверка флагов в `/proc/cpuinfo` |
| **Настройки BIOS/UEFI** | Виртуализация должна быть явно включена в прошивке | Использование утилиты `kvm-ok` |
| **Группы пользователей** | Права на управление ресурсами libvirt | Наличие пользователя в группе `libvirt` |

### Компоненты программного стека

Стандартная установка в дистрибутивах на базе Debian/Ubuntu включает:

- `qemu-kvm`: Основной пакет гипервизора.
- `libvirt-daemon-system`: Системные службы для работы libvirt.
- `libvirt-clients`: Набор утилит (`virsh`, `virt-install`).
- `bridge-utils`: Инструменты для создания сетевых мостов.
- `virt-manager`: Графический интерфейс управления (опционально для серверов).

### Сетевая конфигурация по умолчанию

После установки `libvirt` автоматически создает виртуальный мост `virbr0`. Он работает в режиме NAT, обеспечивая ВМ доступ к внешней сети через IP-адрес хоста. Для предоставления ВМ «белого» IP или доступа к локальной сети на уровне L2 требуется настройка сетевого моста хоста (`br0`).

## Практические сценарии

### Сценарий 1: Проверка поддержки аппаратной виртуализации

Этот шаг является обязательным перед установкой пакетов.

**1. Проверка флагов процессора:**

```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
# → результат > 0 означает наличие аппаратной поддержки
```

**2. Глубокая проверка состояния системы:**

```bash
sudo apt update && sudo apt install -y cpu-checker
sudo kvm-ok
```

**Ожидаемый вывод:**

```text
INFO: /dev/kvm exists
KVM acceleration can be used
```

Если в выводе указано `KVM acceleration can NOT be used`, необходимо включить поддержку виртуализации (Intel VT или AMD-V) в настройках BIOS/UEFI.

### Сценарий 2: Установка и активация KVM

**1. Установка пакетов:**

```bash
sudo apt install -y qemu-kvm libvirt-daemon-system libvirt-clients bridge-utils
```

**2. Добавление текущего пользователя в группу управления:**

```bash
sudo adduser $USER libvirt
# → Для применения изменений необходимо перезайти в систему или выполнить 'newgrp libvirt'
```

**3. Проверка статуса службы:**

```bash
sudo systemctl status libvirtd
# → Должно быть: active (running)
```

### Сценарий 3: Верификация корректности установки

После установки и настройки прав следует убедиться, что гипервизор доступен.

**1. Проверка загрузки модулей ядра:**

```bash
lsmod | grep -i kvm
# → Вывод должен содержать kvm и kvm_intel (или kvm_amd)
```

**2. Проверка доступности libvirt через CLI:**

```bash
virsh list --all
# → Id   Name   State
# → --------------------
```

Если команда выполняется без ошибок (даже с пустым спичем), среда готова к работе.
