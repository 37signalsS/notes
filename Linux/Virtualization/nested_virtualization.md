# Вложенная виртуализация (Nested Virtualization)

> **Связанные файлы:** [Виртуализация overview](./virtualization_overview.md), [Образы ВМ](./virtual_machine_images.md)

---

## Определения

**Вложенная виртуализация** — возможность запускать гипервизор внутри виртуальной машины (ВМ). Позволяет создавать ВМ внутри ВМ.

**Уровни иерархии:**

| Уровень | Описание | Пример |
| :--- | :--- | :--- |
| **L0** | Физический хост | Сервер с KVM |
| **L1** | Гостевая ВМ на L0 | ВМ с запущенным KVM |
| **L2** | Вложенная ВМ на L1 | ВМ внутри ВМ L1 |

**Схема:**
```
┌────────────────────────────────────────────────────────┐
│ L0: Физический хост                                    │
│ ┌────────────────────────────────────────────────────┐ │
│ │ Гипервизор L0 (KVM/ESXi/Hyper-V)                   │ │
│ │ ┌────────────────────────────────────────────────┐ │ │
│ │ │ L1: Гостевая ВМ + Гипервизор L1                │ │ │
│ │ │ ┌────────────────────────────────────────────┐ │ │ │
│ │ │ │ L2: Вложенная ВМ                           │ │ │ │
│ │ │ │ ┌────────────────────────────────────────┐ │ │ │ │
│ │ │ │ │ Гостевая ОС L2                         │ │ │ │ │
│ │ │ │ └────────────────────────────────────────┘ │ │ │ │
│ │ │ └────────────────────────────────────────────┘ │ │ │
│ │ └────────────────────────────────────────────────┘ │ │
│ └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

## Основные концепции

### Требования

**Аппаратные (L0 хост):**

| Процессор | Технология | Дополнительно |
| :--- | :--- | :--- |
| **Intel** | VT-x + EPT | Обязательно оба |
| **AMD** | AMD-V + RVI | Обязательно оба |

**Проверка:**
```bash
# Флаги CPU
egrep -c 'vmx|svm' /proc/cpuinfo  # 0 = нет поддержки

# Детальная информация
lscpu | grep Virtualization
```

**BIOS/UEFI:**
- Включить виртуализацию (Intel VT-x / AMD-V)
- Включить IOMMU (Intel VT-d / AMD-Vi) для проброса устройств

---

### Архитектура KVM nested

**Механизм:**
- L0 KVM предоставляет L1 ВМ "виртуализированные расширения CPU"
- L1 гипервизор управляет L2 ВМ через стандартные инструкции виртуализации
- L0 KVM транслирует операции L1→L2

**Ограничения:**
- Не все функции KVM доступны для L2
- Производительность L2 ниже L1 (10-30% накладные расходы)
- Live-миграция L1 невозможна при запущенных L2

## Практические сценарии

### Включение в KVM (Linux)

#### 1. Проверка текущего состояния

```bash
# Проверка загруженных модулей
lsmod | grep -i kvm

# Статус nested (Intel)
cat /sys/module/kvm_intel/parameters/nested

# Статус nested (AMD)
cat /sys/module/kvm_amd/parameters/nested
```

**Значения:** `1` или `Y` = включено, `0` или `N` = выключено.

> **Примечание:** На Ubuntu nested virtualization включён по умолчанию.

#### 2. Временное включение (до перезагрузки)

```bash
# Intel
sudo modprobe -r kvm_intel
sudo modprobe kvm_intel nested=1

# AMD
sudo modprobe -r kvm_amd
sudo modprobe kvm_amd nested=1
```

#### 3. Постоянное включение

**Файл `/etc/modprobe.d/kvm.conf`:**
```
# Intel
options kvm-intel nested=1

# AMD
options kvm-amd nested=1
```

**Применение:**
```bash
# Перезагрузка модуля
sudo modprobe -r kvm_intel && sudo modprobe kvm_intel

# Или перезагрузка системы
sudo reboot
```

#### 4. Проверка внутри L1 ВМ

```bash
# Проверка флагов виртуализации
egrep "svm|vmx" /proc/cpuinfo
```

**Пустой вывод?** Требуется настройка ВМ:

**libvirt/virsh:**
```bash
virsh edit <vm-name>
```

**Добавить в XML:**
```xml
<cpu mode='host-model' check='partial'>
  <feature policy='require' name='vmx'/>  <!-- для Intel -->
  <feature policy='require' name='svm'/>  <!-- для AMD -->
</cpu>
```

**QEMU командная строка:**
```bash
qemu-system-x86_64 -cpu host ...
```

### Сценарии использования

#### 1. Разработка и тестирование

**Сценарий:** Тестирование гипервизоров, облачных платформ (OpenStack, Kubernetes + KubeVirt).

**Преимущества:**
- Один физический хост → множество вложенных ВМ
- Не требуется парк серверов
- Быстрое развертывание/удаление

#### 2. Облачные провайдеры

**Примеры:** AWS, Google Cloud, Azure.

**Использование:**
- Предоставление клиентам возможности запускать свои гипервизоры
- Изоляция арендаторов через вложенную виртуализацию

#### 3. Безопасность (Sandbox)

**Сценарий:** Запуск недоверенного ПО в дополнительном слое изоляции.

**Схема:**
```
Хост (L0) → ВМ-песочница (L1) → Подозрительное ПО (L2)
```

**Преимущества:**
- Дополнительный барьер при побеге из L2
- Изоляция сетевого трафика

#### 4. Обучение и лабораторные стенды

**Сценарий:** Создание сложных сетевых топологий на одном ПК.

**Примеры:**
- Кластер Kubernetes из нескольких ВМ
- Сеть с маршрутизаторами внутри ВМ
- Тестирование миграции ВМ

### Производительность

| Уровень | Производительность CPU | Производительность I/O |
| :--- | :--- | :--- |
| **L0 (нативная)** | 100% | 100% |
| **L1** | 90-95% | 85-95% |
| **L2** | 70-85% | 60-80% |

**Факторы влияния:**
- Тип нагрузки (CPU-bound vs I/O-bound)
- Поддержка EPT/RVI
- Количество уровней вложенности

**Оптимизация:**
- Использовать `-cpu host` для проброса флагов
- Включить hugepages на L0
- Использовать virtio для дисков и сети

---

### Troubleshooting

| Проблема | Решение |
| :--- | :--- |
| **nested=1 не применяется** | Проверить загрузку модуля (`lsmod \| grep kvm`) |
| **Нет флагов vmx/svm в L1** | Добавить `<cpu mode='host-model'>` в XML ВМ |
| **L2 не запускается** | Проверить поддержку EPT/RVI на L0 |
| **Низкая производительность L2** | Использовать virtio, hugepages, CPU pinning |
| **Live-миграция не работает** | Остановить L2 ВМ перед миграцией L1 |

## Дополнительная информация

### Ограничения

1. **Производительность:**
   - Накладные расходы 10-30% на уровень
   - I/O операции наиболее чувствительны

2. **Функциональность:**
   - Не все функции KVM доступны для L2
   - Ограниченная поддержка hotplug

3. **Миграция:**
   - Live-миграция L1 невозможна при запущенных L2
   - Требуется остановка вложенных ВМ

4. **Отладка:**
   - Сложнее диагностировать проблемы
   - Логи на нескольких уровнях

### Альтернативы

| Технология | Описание |
| :--- | :--- |
| **Docker-in-Docker (DinD)** | Контейнеры внутри контейнеров (без вложенной виртуализации) |
| **Kata Containers** | Контейнеры в microVM (альтернатива вложенной виртуализации) |
| **Firecracker** | MicroVM от AWS для изоляции workload |

### Инструменты мониторинга

```bash
# Проверка вложенной виртуализации
kvm-ok  # из пакета cpu-checker

# Статистика KVM
perf kvm stat record -p <pid>
perf kvm stat report

# Мониторинг ВМ (libvirt)
virt-top
```

### Безопасность

**Рекомендации:**
1. Изолировать L1 ВМ от критических ресурсов L0
2. Использовать SELinux/AppArmor для L1
3. Ограничить сеть между уровнями
4. Регулярно обновлять L0 и L1 гипервизоры

**Риски:**
- Уязвимости в гипервизоре L1 могут затронуть L0
- Побег из L2 → компрометация L1 → риск для L0
