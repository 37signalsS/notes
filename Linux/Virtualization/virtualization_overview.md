# Виртуализация и изоляция в Linux

> **Связанные файлы:** [Образы ВМ](./virtual_machine_images.md), [Вложенная виртуализация](./nested_virtualization.md), [VirtualBox](../../virtualbox.md)

## Определения

**Виртуализация** — технология создания виртуальных (а не физических) версий вычислительных ресурсов: операционных систем, серверов, устройств хранения или сетевых ресурсов.

**Изоляция** — легковесный подход, ограничивающий доступ процесса к системным ресурсам. В Linux существует несколько уровней виртуализации и изоляции.

**Эмуляция** — использование ПО для обеспечения среды выполнения с другой архитектурой. Эмуляторы полностью воссоздают поведение целевой системы, имитируя больше оборудования, чем ВМ.

**Гипервизор** — ПО для создания и управления виртуальными машинами, выделяющее им ресурсы хоста. Типы:
- **Тип 1 (bare-metal):** Работает непосредственно на оборудовании (KVM, Xen, ESXi)
- **Тип 2 (hosted):** Работает поверх ОС хоста (VirtualBox, VMware Workstation)

## Основные концепции

### Виртуализация против Эмуляции

1. **Основное назначение:**
    * **Виртуализация** ориентирована на **изоляцию** и эффективное использование ресурсов путем создания виртуальных барьеров между несколькими виртуальными средами, работающими в одной и той же физической среде.
    * **Эмуляция** сосредоточена на воссоздании **среды**, позволяя программному обеспечению работать в окружении, которое не соответствует его нативной архитектуре.

2. **Архитектура и выполнение:**
    * **Виртуализация:** Виртуализированная среда обычно использует **ту же самую базовую аппаратную архитектуру**, что и хост-система. Фактическое выполнение инструкций чаще всего происходит нативно на процессоре хоста (с небольшими накладными расходами из-за гипервизора), а не с помощью программной имитации. Виртуализированное приложение может предоставлять виртуализированные устройства, которые затем преобразуются в физические устройства, и узел виртуализации контролирует доступ к ним.
    * **Эмуляция:** Эмуляция — это использование программного обеспечения для обеспечения совершенно **другой среды выполнения или архитектуры**. Эмуляторы имитируют большее количество оборудования, чем виртуальные машины, так как им приходится полностью воссоздавать поведение целевой системы.

**Кратко:** Эмуляторы позволяют запускать ПО, предназначенное для другой аппаратной платформы, путем ее программной имитации. Виртуализация позволяет запускать несколько экземпляров той же или совместимой платформы на одном физическом оборудовании, используя изоляцию и близкое к нативному исполнению.

### Кольца защиты (Protection Rings)

Бинарный программный код на процессорах располагается на разных уровнях доступа к данным: от самого привилегированного (Ring 0) до самого ограниченного (Ring 3).

* **Ring 0:** Самый привилегированный уровень. Здесь работает ядро ОС, имея прямой доступ к оборудованию и памяти.
* **Ring 1, 2:** Промежуточные уровни (в современных ОС обычно не используются).
* **Ring 3:** Уровень пользовательских приложений. Доступ к ресурсам осуществляется через системные вызовы к ядру.

В KVM гостевая ОС получает доступ к Ring 0 через аппаратное ускорение хоста, что обеспечивает высокую скорость. Если аппаратная поддержка отсутствует, QEMU откатывается на механизм **TCG (Tiny Code Generator)** — программную трансляцию инструкций, которая значительно медленнее.

### Механизмы изоляции ядра Linux

* **Пространства имён (namespaces)**: Изолируют глобальные системные ресурсы (процессы, сеть, точки монтирования и т.д.) для групп процессов, делая их невидимыми или отдельными для других процессов.
* **Контрольные группы (cgroups)**: Механизм ядра для организации процессов в иерархические группы и управления их ресурсами (CPU, память, дисковый ввод-вывод).

## Практические сценарии

### Типы виртуализации

#### Полная виртуализация (гипервизоры)

Эмуляция полноценного оборудования для запуска независимых гостевых ОС на одном хосте.

- **[KVM](#kvm-kernel-based-virtual-machine)** — встроен в ядро Linux, тип 1
- **Xen** — гипервизор тип 1 с открытым исходным кодом
- **[VirtualBox](../../virtualbox.md)** — гипервизор тип 2 для рабочих станций
- **VMware ESXi** — коммерческий гипервизор тип 1

Современные гипервизоры поддерживают **[вложенную виртуализацию](./nested_virtualization.md)** — запуск гипервизора внутри ВМ.

#### Виртуализация на уровне ОС (контейнеры)

Контейнеры изолируют приложения и зависимости, используя общее ядро хоста. Легковеснее ВМ.

- **`systemd-nspawn`** — легковесные контейнеры от systemd
- **Docker** — платформа управления контейнерами, см. **[Docker overview](../../Docker/docker_overview.md)**
- **Podman** — daemonless-альтернатива Docker, см. **[Podman architecture](../../Podman/podman_daemonless_architecture.md)**
- **LXC** — классические системные контейнеры

#### Изоляция на уровне файловой системы

Базовый уровень изоляции, затрагивающий только файловую систему.

- **`chroot`** — изменение корневого каталога для процесса. Изоляция неполная: нет изоляции PID, сети, IPC, UID, ресурсов.

#### Ограничение ресурсов

- **`ulimit`** — лимиты ресурсов для сессии/процесса (открытые файлы, дочерние процессы)
- **`cgroups`** — иерархическое ограничение ресурсов (CPU, память, IO)

---

### KVM (Kernel-based Virtual Machine)

Модуль ядра Linux, превращающий его в гипервизор тип 1. Требует аппаратной поддержки виртуализации (Intel VT-x/AMD-V).

**Архитектура:**
- **KVM** — модуль ядра, отвечающий за выполнение кода гостевой ОС
- **QEMU** — эмуляция устройств (диски, сеть, USB)
- **`libvirt`** — высокоуровневое API для управления ВМ (опционально)

**Проверка поддержки:**
```bash
# Проверка флагов CPU
egrep -c 'vmx|svm' /proc/cpuinfo  # 0 = нет поддержки

# Проверка загруженного модуля KVM
lsmod | grep kvm
```

**Преимущества:**
- Минимальные накладные расходы (нативное выполнение инструкций)
- Интеграция с ядром Linux
- Поддержка live-миграции
- Совместимость с инструментами управления (libvirt, openstack)

### Виртуализация против Эмуляции

Контейнеризация — это метод изоляции, при котором приложения и их зависимости упаковываются в "контейнеры". Все контейнеры работают на одном ядре хост-системы, что делает их гораздо более легковесными и быстрыми по сравнению с виртуальными машинами.

* **`systemd-nspawn`**: Мощный инструмент для создания легковесных контейнеров, который является частью `systemd`. Его можно рассматривать как "chroot на стероидах".
* **Docker, Podman, LXC**: Полноценные платформы для управления жизненным циклом контейнеров, предоставляющие инструменты для сборки, запуска, распространения и оркестровки контейнеризированных приложений.

### Изоляция на уровне файловой системы

Это самый базовый уровень изоляции, который затрагивает только видимую часть файловой системы для процесса.

* **`chroot`**: Один из самых старых механизмов изоляции, известный еще со времен UNIX. Системный вызов и одноименная утилита `chroot` (change root) изменяет корневой каталог для текущего процесса и его дочерних процессов. Это создаёт простейшую форму изоляции, "запирая" процесс в определённой директории, от которой вычисляются все абсолютные пути.
  * **Как это работает:** Создаётся директория, которая будет новым корнем. Внутрь копируются необходимые исполняемые файлы и библиотеки. После запуска `chroot /path/to/new/root /bin/bash`, для процесса `bash` корневым каталогом (`/`) становится `/path/to/new/root`.
  * **Теоретические ограничения `chroot`:** Изоляция `chroot` является неполной и касается только файловой системы. Процесс по-прежнему делит с хостом:
    * Пространство процессов (PID).
    * Сетевой стек.
    * Межпроцессное взаимодействие (IPC).
    * Пользователей (UID).
    * Ресурсы (нет ограничений по CPU/памяти).
    Именно эти ограничения привели к необходимости создания более комплексных механизмов изоляции, таких как **пространства имён (namespaces)**.

### Ограничение ресурсов

Изоляция также включает в себя ограничение ресурсов, потребляемых процессом или группой процессов, чтобы предотвратить "голодание" других частей системы.

* **`ulimit`**: Базовая утилита командной строки для установки лимитов на ресурсы (например, максимальное количество открытых файлов или дочерних процессов) для текущей сессии или запускаемого процесса.
