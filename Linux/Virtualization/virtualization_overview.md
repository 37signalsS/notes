# Виртуализация и изоляция в Linux

Данный файл содержит обзор технологий виртуализации и механизмов изоляции в среде Linux, их сравнение и критерии выбора. Детальные инструкции по конкретным решениям приведены в соответствующих подразделах.

## Определения

**Виртуализация** — процесс создания программного (виртуального) представления физических ресурсов (процессоров, памяти, дисков, сетей). Позволяет запускать несколько независимых операционных систем на одном физическом сервере.

**Изоляция** — механизм ограничения доступа процесса к системным ресурсам и видимости других процессов без создания полноценной виртуальной машины.

**Эмуляция** — имитация аппаратного обеспечения одной архитектуры на другой с помощью программной трансляции инструкций.

**Гипервизор (VMM)** — специализированное ПО для управления виртуальными машинами и распределения ресурсов хоста.

- **Тип 1 (Bare-Metal):** работает напрямую на «железе» (KVM, Xen, ESXi).
- **Тип 2 (Hosted):** работает поверх основной ОС (VirtualBox, VMware Workstation).

### Современные гипервизоры в облаках

- **KVM (Kernel-based Virtual Machine):** на текущий момент является стандартом де-факто для большинства облачных провайдеров (включая российские). Превращает ядро Linux в гипервизор.
- **Xen:** исторически использовался в AWS EC2 на старте, но постепенно вытесняется KVM.
- **AWS Nitro:** специализированная разработка Amazon. Nitro выносит часть функций гипервизора (сеть, хранилище, безопасность) на отдельные аппаратные карты. Это практически обнуляет «налог на виртуализацию» и дает скорость, сопоставимую с Bare-Metal.

## Базовые концепции

### Виртуализация против Эмуляции

| Характеристика | Виртуализация | Эмуляция |
| :--- | :--- | :--- |
| **Производительность** | Близка к нативной | Значительно ниже (трансляция инструкций) |
| **Архитектура гостя** | Должна совпадать с хостом | Может отличаться (напр. ARM на x86) |
| **Примеры** | KVM, Xen | QEMU (TCG), DOSBox |

### Кольца защиты (Protection Rings)

Аппаратная виртуализация (**VT-x** / **AMD-V**) позволяет гостевой ОС работать в самом привилегированном режиме (**Ring 0**) без прямого конфликта с хостом. В отсутствие аппаратной поддержки гипервизор вынужден перехватывать и эмулировать привилегированные инструкции, что резко снижает скорость работы.

### Механизмы изоляции ядра

| Механизм | Роль | Примеры ресурсов |
| :--- | :--- | :--- |
| **Namespaces** | Изоляция видимости | PID, Network, Mount, User, UTS, IPC |
| **Cgroups** | Ограничение потребления | CPU, RAM, I/O, Network bandwidth |

Подробнее: [Пространства имён (namespaces)](../Core/namespaces.md) и [Контрольные группы (cgroups)](../Core/cgroups.md).

### Аппаратная поддержка виртуализации

| Технология | Intel | AMD | Назначение |
| :--- | :--- | :--- | :--- |
| **Виртуализация CPU** | VT-x | AMD-V | Выполнение инструкций гостя на физическом CPU |
| **Виртуализация памяти** | EPT | RVI | Ускорение работы с таблицами страниц (Nested Paging) |
| **Проброс устройств** | VT-d | AMD-Vi | Прямой доступ ВМ к PCI-устройствам (IOMMU) |

### Типы и выбор технологии

| Критерий | Docker (App) | LXC (System) | Виртуальные машины |
| :--- | :--- | :--- | :--- |
| **Изоляция** | Процессная | Системная | Аппаратная |
| **Ядро** | Общее с хостом | Общее с хостом | Собственное (любая ОС) |
| **Состояние** | Stateless (обычно) | Stateful | Stateful |
| **Время старта** | Секунды | Секунды | Десятки секунд |

**Рекомендации:**

- **Docker:** микросервисы, CI/CD, быстрый деплой приложений.
- **LXC:** замена легким ВМ для запуска системных сервисов (DNS, VPN). Подробнее: [LXC Overview](./lxc_overview.md).
- **ВМ (KVM):** запуск отличных от Linux ОС (Windows), максимальная изоляция, жесткое резервирование ресурсов.

## Практические сценарии

### Сценарий 1: Проверка готовности системы к виртуализации

Инструкции по проверке флагов CPU и активации модулей ядра KVM вынесены в специализированный раздел: [Установка KVM — Проверка поддержки](./kvm/installation.md#сценарий-1-проверка-поддержки-аппаратной-виртуализации).

### Сценарий 2: Оптимизация производительности ВМ

Для исключения накладных расходов при работе с CPU рекомендуется использовать режим `host-passthrough`. Это передает гостевой ОС все функции физического процессора (AES-NI, AVX). Подробнее о выборе режимов: [Диагностика KVM — Режимы CPU](./kvm/troubleshooting.md#режимы-cpu-в-libvirt).
