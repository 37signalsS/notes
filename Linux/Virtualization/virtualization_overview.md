# Виртуализация и изоляция в Linux

> **Связанные файлы:** [Образы ВМ](./virtual_machine_images.md), [Вложенная виртуализация](./nested_virtualization.md), [VirtualBox](../../virtualbox.md), [Docker overview](../../Docker/docker_overview.md), [Podman architecture](../../Podman/podman_daemonless_architecture.md)

## Определения

**Виртуализация** — технология создания виртуальных (а не физических) версий вычислительных ресурсов: операционных систем, серверов, устройств хранения или сетевых ресурсов.

**Изоляция** — легковесный подход, ограничивающий доступ процесса к системным ресурсам. В Linux существует несколько уровней виртуализации и изоляции.

**Эмуляция** — использование ПО для обеспечения среды выполнения с другой архитектурой. Эмуляторы полностью воссоздают поведение целевой системы.

**Гипервизор** — ПО для создания и управления ВМ, выделяющее ресурсы хоста.

- **Тип 1 (bare-metal):** Работает непосредственно на оборудовании (KVM, Xen, ESXi)
- **Тип 2 (hosted):** Работает поверх ОС хоста (VirtualBox, VMware Workstation)

## Основные концепции

### Виртуализация vs Эмуляция

| Критерий | Виртуализация | Эмуляция |
| :--- | :--- | :--- |
| **Назначение** | Изоляция, эффективное использование ресурсов | Запуск ПО для другой архитектуры |
| **Архитектура** | Та же, что у хоста (нативное выполнение) | Другая (программная имитация) |
| **Производительность** | Близка к нативной | Значительно ниже |
| **Примеры** | KVM, VirtualBox, Xen | QEMU (TCG), DOSBox |

**Кратко:** Эмуляторы запускают ПО для другой платформы через имитацию. Виртуализация запускает несколько экземпляров той же платформы на одном оборудовании.

### Кольца защиты (Protection Rings)

Уровни доступа к данным процессора:

| Кольцо | Описание | Использование |
| :--- | :--- | :--- |
| **Ring 0** | Максимальные привилегии | Ядро ОС, прямой доступ к оборудованию |
| **Ring 1-2** | Промежуточные | Обычно не используются |
| **Ring 3** | Минимальные привилегии | Пользовательские приложения |

**KVM:** Гостевая ОС получает доступ к Ring 0 через аппаратное ускорение. Без аппаратной поддержки QEMU использует **TCG (Tiny Code Generator)** — программную трансляцию (медленнее).

### Механизмы изоляции ядра Linux

| Механизм | Назначение | Примеры |
| :--- | :--- | :--- |
| **Namespaces** | Изоляция видимости ресурсов | PID, network, mount, UTS, IPC, user, cgroup, time |
| **Cgroups** | Ограничение потребления ресурсов | CPU, память, IO, network bandwidth |

**Namespaces** говорят процессу: *"Ты видишь только это"*.  
**Cgroups** говорят: *"Ты можешь использовать только столько"*.

## Практические сценарии

### Типы виртуализации

#### 1. Полная виртуализация (гипервизоры)

Эмуляция оборудования для запуска независимых гостевых ОС.

| Решение | Тип | Описание |
| :--- | :--- | :--- |
| **KVM** | 1 | Модуль ядра Linux, требует Intel VT-x/AMD-V |
| **Xen** | 1 | Гипервизор с открытым исходным кодом |
| **VirtualBox** | 2 | Гипервизор для рабочих станций, см. [VirtualBox](../../virtualbox.md) |
| **VMware ESXi** | 1 | Коммерческий гипервизор |

**Вложенная виртуализация:** Запуск гипервизора внутри ВМ. Подробно: [Nested Virtualization](./nested_virtualization.md).

#### 2. Виртуализация на уровне ОС (контейнеры)

Изоляция приложений с общим ядром хоста. Легковеснее ВМ.

| Решение | Описание |
| :--- | :--- |
| **`systemd-nspawn`** | Легковесные контейнеры от systemd |
| **Docker** | Платформа управления контейнерами, см. [Docker overview](../../Docker/docker_overview.md) |
| **Podman** | Daemonless-альтернатива, см. [Podman architecture](../../Podman/podman_daemonless_architecture.md) |
| **LXC** | Классические системные контейнеры |

#### 3. Изоляция на уровне файловой системы

**`chroot`** — изменение корневого каталога для процесса.

**Ограничения:**

- Нет изоляции PID, сети, IPC, UID
- Нет ограничений ресурсов
- Только файловая система

#### 4. Ограничение ресурсов

| Инструмент | Уровень | Описание |
| :--- | :--- | :--- |
| **`ulimit`** | Процесс/сессия | Лимиты: открытые файлы, дочерние процессы |
| **`cgroups`** | Группа процессов | Иерархическое ограничение: CPU, память, IO |

---

### KVM (Kernel-based Virtual Machine)

Модуль ядра Linux, превращающий его в гипервизор тип 1.

**Архитектура:**

- **KVM** — выполнение кода гостевой ОС
- **QEMU** — эмуляция устройств (диски, сеть, USB)
- **`libvirt`** — API управления ВМ (опционально)

**Проверка поддержки:**

```bash
# Флаги CPU (0 = нет поддержки)
egrep -c 'vmx|svm' /proc/cpuinfo

# Модуль KVM
lsmod | grep kvm
```

**Преимущества:**

- Минимальные накладные расходы
- Интеграция с ядром
- Live-миграция
- Совместимость с libvirt, OpenStack

## Дополнительная информация

### Сравнение: Контейнеры vs ВМ

| Критерий | Контейнеры | Виртуальные машины |
| :--- | :--- | :--- |
| **Уровень изоляции** | Процессная (ядро) | Аппаратная (гипервизор) |
| **Ядро** | Общее с хостом | Собственное |
| **Время старта** | Секунды | Десятки секунд |
| **Плотность** | Высокая | Ниже |
| **Образы** | Слоёные OCI | Монолитные (qcow2, vmdk) |
| **Совместимость** | Общая версия ядра | Любая гостевая ОС |
| **Безопасность** | Зависит от ядра хоста | Сильная граница гипервизора |

**Когда что выбирать:**

- **Контейнеры:** Микросервисы, CI/CD, масштабирование, высокая плотность
- **ВМ:** Смешанные ОС, монолиты, строгие границы безопасности
- **Гибрид:** Контейнеры внутри ВМ (многоарендность, регуляторные требования)

### Эволюция изоляции

```
chroot (1979) → namespaces (2002) → cgroups (2007) → LXC (2008) → Docker (2013)
```

**Историческая справка:**

- **1979:** `chroot` в UNIX V7 — изоляция файловой системы
- **2002:** Mount namespaces в Linux 2.4.19 — изоляция точек монтирования
- **2006-2007:** Cgroups — ограничение ресурсов
- **2008:** LXC — первый полноценный инструмент контейнеризации
- **2013:** Docker — массовое распространение контейнеров

### Аппаратная поддержка

| Технология | Intel | AMD | Назначение |
| :--- | :--- | :--- | :--- |
| **Виртуализация CPU** | VT-x | AMD-V | Аппаратная виртуализация |
| **Виртуализация памяти** | EPT | RVI | Ускорение работы с памятью |
| **Проброс устройств** | VT-d | AMD-Vi | IOMMU для прямого доступа |

**Требования для вложенной виртуализации:** VT-x + EPT (Intel) или AMD-V + RVI (AMD).
