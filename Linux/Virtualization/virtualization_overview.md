# Виртуализация и изоляция в Linux

## Definitions

**Виртуализация** — создание виртуальных (не физических) версий вычислительных ресурсов: ОС, серверов, устройств хранения, сетевых ресурсов.

**Изоляция** — легковесный подход, ограничивающий доступ процесса к системным ресурсам без полной виртуализации.

**Эмуляция** — программная имитация аппаратной платформы другой архитектуры. Эмулятор транслирует инструкции гостевого CPU на язык хостового CPU.

**Гипервизор (VMM)** — ПО для создания и управления ВМ, распределяющее ресурсы хоста между гостевыми ОС.

- **Тип 1 (bare-metal):** Работает непосредственно на оборудовании (KVM, Xen, ESXi)
- **Тип 2 (hosted):** Работает поверх ОС хоста (VirtualBox, VMware Workstation)

## Basic Concepts

### Виртуализация vs Эмуляция

| Критерий | Виртуализация | Эмуляция |
| :--- | :--- | :--- |
| **Назначение** | Изоляция, эффективное использование ресурсов | Запуск ПО для другой архитектуры |
| **Архитектура** | Та же, что у хоста (нативное выполнение) | Другая (программная имитация) |
| **Производительность** | Близка к нативной | Значительно ниже |
| **Примеры** | KVM, VirtualBox, Xen | QEMU (TCG), DOSBox |

### Кольца защиты (Protection Rings)

| Кольцо | Привилегии | Использование |
| :--- | :--- | :--- |
| **Ring 0** | Максимальные | Ядро ОС, прямой доступ к оборудованию |
| **Ring 1–2** | Промежуточные | Обычно не используются |
| **Ring 3** | Минимальные | Пользовательские приложения |

С аппаратной виртуализацией (VT-x/AMD-V) гостевая ОС получает доступ к Ring 0 напрямую. Без неё QEMU использует TCG — программную трансляцию инструкций.

### Механизмы изоляции ядра Linux

| Механизм | Назначение | Примеры |
| :--- | :--- | :--- |
| **Namespaces** | Изоляция видимости ресурсов | PID, network, mount, UTS, IPC, user, cgroup, time |
| **Cgroups** | Ограничение потребления ресурсов | CPU, память, IO, network bandwidth |

Namespaces говорят процессу: «Ты видишь только это». Cgroups говорят: «Ты можешь использовать только столько».

Подробнее: [Namespaces](../Core/namespaces.md), [Cgroups](../Core/cgroups.md).

### Контейнеры vs Виртуальные машины

| Критерий | Контейнеры | Виртуальные машины |
| :--- | :--- | :--- |
| **Уровень изоляции** | Процессная (ядро) | Аппаратная (гипервизор) |
| **Ядро** | Общее с хостом | Собственное |
| **Время старта** | Секунды | Десятки секунд |
| **Плотность** | Высокая | Ниже |
| **Образы** | Слоёные OCI | Монолитные (qcow2, vmdk) |
| **Совместимость** | Общая версия ядра | Любая гостевая ОС |
| **Безопасность** | Зависит от ядра хоста | Сильная граница гипервизора |

**Когда выбирать:**

- **Контейнеры:** микросервисы, CI/CD, масштабирование, высокая плотность
- **ВМ:** смешанные ОС, монолиты, строгие границы безопасности
- **Гибрид:** контейнеры внутри ВМ (многоарендность, регуляторные требования)

## Practical Scenarios

### Типы виртуализации

#### 1. Полная виртуализация (гипервизоры)

| Решение | Тип | Описание |
| :--- | :--- | :--- |
| **KVM** | 1 | Модуль ядра Linux, требует Intel VT-x/AMD-V. Подробнее: [KVM Overview](./kvm/overview.md) |
| **Xen** | 1 | Гипервизор с открытым исходным кодом |
| **VirtualBox** | 2 | Гипервизор для рабочих станций. Подробнее: [VirtualBox](../../virtualbox.md) |
| **VMware ESXi** | 1 | Коммерческий гипервизор |

**Сравнение решений для рабочих станций:**

| Критерий | VirtualBox | VMware Workstation | QEMU + KVM |
| :--- | :--- | :--- | :--- |
| **Лицензия** | Бесплатно (GPL v2 base) | Проприетарная (платная Pro) | Открытое (GPL) |
| **Производительность** | Средняя | Высокая | Нативная (близка к bare-metal) |
| **Гипервизор** | Собственный | Собственный | KVM (модуль ядра Linux) |
| **Интеграция с Linux** | Базовая | Ограниченная | Нативная (ядро) |

**Практические наблюдения:**

- **VirtualBox** — кроссплатформенное решение (Linux, macOS, Windows), подходит для базовых задач разработки
- **VMware Workstation Pro** — коммерческий продукт с высокой производительностью
- **QEMU + KVM** — оптимальное решение для Linux: KVM выполняет инструкции гостевой ОС напрямую, QEMU эмулирует устройства (диски, сеть, USB, видео)

**Вложенная виртуализация:** запуск гипервизора внутри ВМ. Подробнее: [Nested Virtualization](./nested_virtualization/practical_scenarios.md).

#### 2. Виртуализация на уровне ОС (контейнеры)

| Решение | Описание |
| :--- | :--- |
| **`systemd-nspawn`** | Легковесные контейнеры от systemd |
| **Docker** | Платформа управления контейнерами. Подробнее: [Docker Overview](../../Docker/docker_overview.md) |
| **Podman** | Daemonless-альтернатива Docker. Подробнее: [Podman Architecture](../../Podman/podman_daemonless_architecture.md) |
| **LXC** | Классические системные контейнеры |

#### 3. Изоляция на уровне файловой системы

**`chroot`** — изменение корневого каталога для процесса. Ограничения: нет изоляции PID, сети, IPC, UID; нет ограничений ресурсов.

#### 4. Ограничение ресурсов

| Инструмент | Уровень | Описание |
| :--- | :--- | :--- |
| **`ulimit`** | Процесс/сессия | Лимиты: открытые файлы, дочерние процессы |
| **`cgroups`** | Группа процессов | Иерархическое ограничение: CPU, память, IO |

### KVM: проверка поддержки

```bash
# Флаги CPU (0 = нет поддержки)
egrep -c 'vmx|svm' /proc/cpuinfo

# Модуль KVM
lsmod | grep kvm
```

**Преимущества KVM:** минимальные накладные расходы, интеграция с ядром, live-миграция, совместимость с libvirt/OpenStack. Подробнее: [KVM Overview](./kvm/overview.md), [KVM Management](./kvm/management.md), [KVM Troubleshooting](./kvm/troubleshooting.md).

## Additional Information

### Эволюция изоляции

```
chroot (1979) → namespaces (2002) → cgroups (2007) → LXC (2008) → Docker (2013)
```

### Аппаратная поддержка виртуализации

| Технология | Intel | AMD | Назначение |
| :--- | :--- | :--- | :--- |
| **Виртуализация CPU** | VT-x | AMD-V | Аппаратная виртуализация |
| **Виртуализация памяти** | EPT | RVI | Ускорение работы с памятью |
| **Проброс устройств** | VT-d | AMD-Vi | IOMMU для прямого доступа |

Требования для вложенной виртуализации: VT-x + EPT (Intel) или AMD-V + RVI (AMD).
