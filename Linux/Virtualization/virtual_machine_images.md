# Образы Виртуальных Машин

## 1. Введение в Хранение Данных ВМ

Гипервизор, управляющий работой виртуальных машин (ВМ), отвечает за выделение им системных ресурсов: процессорного времени, оперативной памяти и дискового пространства. Если с CPU и RAM всё относительно просто, то организация хранилища данных для ВМ предлагает несколько подходов, каждый со своими преимуществами и недостатками.

## 2. Способы Организации Хранилища

Существует два фундаментальных подхода к предоставлению дискового пространства для виртуальной машины.

### 2.1. Прямой доступ к блочным устройствам (Block Device Passthrough)

Этот метод заключается в "пробросе" блочного устройства хост-системы (например, физического диска, раздела, LVM-тома или даже USB-флешки) напрямую в гостевую ОС. Виртуальная машина получает эксклюзивный доступ к этому устройству и работает с ним как с физическим.

**Пример для QEMU/KVM:**
```bash
# Проброс устройства /dev/sdb в ВМ как диска с интерфейсом virtio
qemu-system-x86_64 \
    -enable-kvm \
    # ... другие опции ...
    -drive file=/dev/sdb,format=raw,if=virtio,cache=none
```

**Преимущества:**
-   **Максимальная производительность:** Отсутствие промежуточных слоёв абстракции обеспечивает скорость доступа к данным, близкую к нативной.
-   **Использование нативных функций:** Позволяет применять возможности системы управления томами хоста, например, LVM-снапшоты.

**Недостатки:**
-   **Сложность управления:** Миграция и резервное копирование такого диска требуют более сложных процедур по сравнению с файлами-образами.
-   **Риск конфликта доступа:** Хотя ядро Linux не блокирует устройство намертво, одновременный доступ к нему со стороны хоста и гостевой ОС может привести к повреждению данных.

### 2.2. Файлы-образы дисков (Disk Image Files)

Наиболее распространенный подход, при котором весь диск ВМ хранится в виде одного или нескольких файлов в файловой системе хоста.

**Преимущества:**
-   **Простота управления:** Файлы легко копировать, перемещать, архивировать и бэкапить стандартными средствами.
-   **Портативность:** Образ можно без труда перенести на другую хост-систему.

**Недостатки:**
-   **Накладные расходы:** Файловая система хоста и формат образа создают дополнительный слой, который может снижать производительность дисковых операций. На современных SSD этот эффект менее заметен.

## 3. Продвинутые Механизмы Хранения

### 3.1. "Тонкое" выделение ресурсов (Thin Provisioning)

**Концепция:** Механизм, при котором дисковое пространство выделяется ВМ не в полном объеме в момент создания диска, а по мере его фактического заполнения данными. Это позволяет создать для ВМ диск большого виртуального объема, который на хосте будет занимать лишь столько места, сколько данных в него записано.

**Реализации:**
-   **На уровне LVM:** Использование `Thinly-provisioned logical volumes`.
-   **На уровне файлов-образов:** 
    -   **Разреженные файлы (Sparse Files)** для формата `raw`.
    -   Встроенная поддержка в "умных" форматах, таких как `qcow2` и `vmdk`.

### 3.2. Снапшоты (Snapshots)

**Концепция:** "Снимок" состояния диска в определенный момент времени. Снапшоты позволяют зафиксировать состояние системы перед потенциально опасной операцией и, в случае неудачи, откатиться к этому состоянию. Они также являются основой для создания консистентных резервных копий работающей ВМ.

**Технология:** В основе механизма снапшотов лежит технология **Copy-on-Write (CoW)**. При создании снапшота основной образ диска становится доступным только для чтения. Когда гостевая ОС пытается изменить блок данных, этот блок сначала копируется в новое место (в файл снапшота), и уже там происходит запись. Таким образом, оригинальные данные остаются нетронутыми.

## 4. Форматы Файлов-Образов

| Формат | Разработчик | Описание и Поддержка | Ключевые Особенности |
| :--- | :--- | :--- | :--- |
| **`raw`** | - | "Сырой" образ, побайтовая копия диска. Поддерживается всеми гипервизорами. | Максимальная производительность, простота. Нет встроенной поддержки снапшотов. Thin provisioning реализуется через разреженные файлы (sparse files). |
| **`qcow2`** | QEMU | QEMU Copy-On-Write. Основной формат для KVM/QEMU. | Поддержка снапшотов, AES-шифрования, zlib/zstd сжатия, thin provisioning. |
| **`vmdk`** | VMware | Virtual Machine Disk. Основной формат для продуктов VMware. Широко поддерживается другими гипервизорами. | Поддержка снапшотов и thin provisioning. |
| **`vhd`/`vhdx`** | Microsoft | Virtual Hard Disk. Формат для Hyper-V. `vhdx` — более новая версия. | Широко поддерживается. |
| **`vdi`** | Oracle | VirtualBox Disk Image. Родной формат для VirtualBox. | Используется преимущественно в VirtualBox. |

## 5. Управление Образами с `qemu-img`

`qemu-img` — это мощная утилита из пакета QEMU для создания, конвертации, изменения размера и управления снапшотами образов.

### 5.1. Создание Образа

-   **Создание `raw` образа (разреженный файл на 5 ГБ):**
    ```bash
    # Метод 1: с помощью dd (создает файл, не занимающий места)
    dd if=/dev/zero of=test.raw bs=1 count=0 seek=5G
    
    # Метод 2: с помощью qemu-img
    qemu-img create -f raw test.raw 5G
    ```

-   **Создание `qcow2` образа (10 ГБ, с thin provisioning по умолчанию):**
    ```bash
    qemu-img create -f qcow2 test.qcow2 10G
    ```

### 5.2. Конвертация Форматов

-   **Общий синтаксис:** `qemu-img convert -f <имя_исходного_формата> -O <имя_целевого_формата> <исходный_файл> <целевой_файл>`

-   **Пример: Конвертация физического диска в `qcow2`:**
    ```bash
    qemu-img convert -f raw -O qcow2 /dev/sdb disk.qcow2
    ```

-   **Пример: `vmdk` в `qcow2`:**
    ```bash
    qemu-img convert -f vmdk -O qcow2 source.vmdk target.qcow2
    ```

### 5.3. Работа со Снапшотами (`qcow2`)

-   **Внутренние снапшоты (хранятся внутри основного файла образа):**
    ```bash
    # Создать снапшот
    qemu-img snapshot -c <имя_снапшота> <файл_образа.qcow2>

    # Показать список снапшотов
    qemu-img snapshot -l <файл_образа.qcow2>

    # Откатиться к состоянию снапшота
    qemu-img snapshot -a <имя_снапшота> <файл_образа.qcow2>
    
    # Удалить снапшот
    qemu-img snapshot -d <имя_снапшота> <файл_образа.qcow2>
    ```
-   **Внешние снапшоты (backing files):**
    Механизм, при котором создается новый `qcow2` файл, использующий оригинальный образ как "основу" (backing file), доступную только для чтения. Все изменения записываются в этот новый файл. Это позволяет использовать один "золотой образ" для множества ВМ, экономя дисковое пространство.
    ```bash
    # Создание delta-диска на основе базового образа
    qemu-img create -f qcow2 -b base_image.qcow2 -F qcow2 vm_delta.qcow2
    ```

## 6. Распространение ВМ: Формат OVF/OVA

-   **OVF (Open Virtualization Format):** Открытый стандарт для упаковки и распространения виртуальных машин. Представляет собой набор файлов:
    -   `*.ovf`: XML-файл, описывающий ВМ (виртуальное оборудование, настройки, ссылки на диски и т.д.).
    -   `*.vmdk` (или другой формат): Один или несколько файлов дисков.
    -   `*.mf`: Файл манифеста с контрольными суммами всех файлов пакета для проверки целостности.
-   **OVA (Open Virtualization Appliance):** Пакет OVF, упакованный в единый TAR-архив с расширением `.ova` для удобства распространения.

Несмотря на стандартизацию, реализации OVF/OVA от разных вендоров (например, VMware и Oracle VirtualBox) часто оказываются несовместимыми.

## 7. Автоматизация Сборки Образов

Для автоматизации рутинных процессов создания и настройки образов существуют специализированные инструменты:

-   **Packer (by HashiCorp):** Позволяет создавать идентичные образы ВМ для различных платформ (QEMU/KVM, VirtualBox, VMware, облачные провайдеры) из единого конфигурационного файла.
-   **Vagrant:** Инструмент для создания, настройки и управления легковесными, воспроизводимыми средами разработки на базе ВМ. Часто используется в связке с образами, подготовленными с помощью Packer.
