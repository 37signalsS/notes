# Образы Виртуальных Машин

## Определения

* **Образы Виртуальных Машин (ВМ)**: Файлы или блочные устройства, содержащие полную копию операционной системы и данных виртуальной машины, используемые гипервизорами для запуска ВМ.
* **Гипервизор**: Программное обеспечение, которое создает и запускает виртуальные машины, выделяя им системные ресурсы. Детальнее см. в [**общем обзоре виртуализации**](./virtualization_overview.md).
* **Прямой доступ к блочным устройствам (Block Device Passthrough)**: Метод предоставления ВМ эксклюзивного доступа к физическому блочному устройству хост-системы (например, диску, разделу, LVM-тому) без промежуточных слоев абстракции.
* **Файлы-образы дисков (Disk Image Files)**: Наиболее распространенный подход, при котором весь диск ВМ хранится в виде одного или нескольких файлов в файловой системе хоста.
* **"Тонкое" выделение ресурсов (Thin Provisioning)**: Механизм, при котором дисковое пространство выделяется ВМ по мере его фактического заполнения данными, а не в полном объеме при создании диска. Это позволяет создать диск большого виртуального объема, занимающий на хосте только фактически используемое пространство.
* **Снапшоты (Snapshots)**: "Снимок" состояния диска ВМ в определенный момент времени, позволяющий зафиксировать состояние системы и откатиться к нему при необходимости.
* **Copy-on-Write (CoW)**: Технология, лежащая в основе снапшотов. При изменении блока данных основной образ диска остается неизменным, а измененный блок копируется в новое место (файл снапшота), где и происходит запись.
* **OVF (Open Virtualization Format)**: Открытый стандарт для упаковки и распространения виртуальных машин, представляющий собой набор файлов (XML-описание ВМ, файлы дисков, манифест).
* **OVA (Open Virtualization Appliance)**: Пакет OVF, упакованный в единый TAR-архив с расширением `.ova` для удобства распространения.

## Основные Концепции

### Способы Организации Хранилища

Существует два фундаментальных подхода к предоставлению дискового пространства для виртуальной машины:

1. **Прямой доступ к блочным устройствам (Block Device Passthrough)**:
    * **Описание**: Метод "проброса" блочного устройства хост-системы (физического диска, раздела, LVM-тома или USB-флешки) напрямую в гостевую ОС, предоставляя ВМ эксклюзивный доступ.
    * **Преимущества**: Максимальная производительность (близкая к нативной), возможность использования нативных функций управления томами хоста (например, [**LVM-снапшоты**](../FileSystems/lvm.md#снимки-snapshots)).
    * **Недостатки**: Сложность миграции и резервного копирования, риск повреждения данных при одновременном доступе хоста и гостевой ОС.

2. **Файлы-образы дисков (Disk Image Files)**:
    * **Описание**: Весь диск ВМ хранится в виде одного или нескольких файлов в файловой системе хоста.
    * **Преимущества**: Простота управления (копирование, перемещение, архивирование), высокая портативность между хост-системами.
    * **Недостатки**: Дополнительные накладные расходы файловой системы хоста и формата образа, которые могут снижать производительность дисковых операций (менее заметно на современных SSD).

### Продвинутые Механизмы Хранения

* **"Тонкое" выделение ресурсов (Thin Provisioning)**:
  * **Реализации**: На уровне [**LVM**](../FileSystems/lvm.md) (через `Thinly-provisioned logical volumes` и снапшоты) или на уровне файлов-образов (разреженные файлы для `raw`, встроенная поддержка в `qcow2` и `vmdk`).
* **Снапшоты (Snapshots)**:
  * **Технология**: Основаны на механизме Copy-on-Write (CoW), который сохраняет оригинальные данные, записывая изменения в файл снапшота. Используются для создания консистентных резервных копий и откатов системы.

### Форматы Файлов-Образов

| Формат | Разработчик | Описание и Поддержка | Ключевые Особенности |
| :--- | :--- | :--- | :--- |
| **`raw`** | - | "Сырой" образ, побайтовая копия диска. Поддерживается всеми гипервизорами. | Максимальная производительность, простота. Нет встроенной поддержки снапшотов. Thin provisioning реализуется через разреженные файлы (sparse files). |
| **`qcow2`** | QEMU | QEMU Copy-On-Write. Основной формат для KVM/QEMU. | Поддержка снапшотов, AES-шифрования, zlib/zstd сжатия, thin provisioning. |
| **`vmdk`** | VMware | Virtual Machine Disk. Основной формат для продуктов VMware. Широко поддерживается другими гипервизорами. | Поддержка снапшотов и thin provisioning. |
| **`vhd`/`vhdx`** | Microsoft | Virtual Hard Disk. Формат для Hyper-V. `vhdx` — более новая версия. | Широко поддерживается. |
| **`vdi`** | Oracle | VirtualBox Disk Image. Родной формат для [**VirtualBox**](../../virtualbox.md). | Используется преимущественно в [**VirtualBox**](../../virtualbox.md). |

## Практические Сценарии

### Управление Образами с `qemu-img`

`qemu-img` — утилита из пакета QEMU для создания, конвертации, изменения размера и управления снапшотами образов, являющаяся ключевым компонентом экосистемы [**KVM/QEMU**](./overview.md).

#### Создание Образа

* **Создание `raw` образа (разреженный файл на 5 ГБ):**

    ```bash
    # Метод 1: с помощью dd (создает файл, не занимающий места)
    dd if=/dev/zero of=test.raw bs=1 count=0 seek=5G
    
    # Метод 2: с помощью qemu-img
    qemu-img create -f raw test.raw 5G
    ```

* **Создание `qcow2` образа (10 ГБ, с thin provisioning по умолчанию):**

    ```bash
    qemu-img create -f qcow2 test.qcow2 10G
    ```

#### Конвертация Форматов

* **Общий синтаксис:** `qemu-img convert -f <имя_исходного_формата> -O <имя_целевого_формата> <исходный_файл> <целевой_файл>`

* **Пример: Конвертация физического диска в `qcow2`:**

    ```bash
    qemu-img convert -f raw -O qcow2 /dev/sdb disk.qcow2
    ```

* **Пример: `vmdk` в `qcow2`:**

    ```bash
    qemu-img convert -f vmdk -O qcow2 source.vmdk target.qcow2
    ```

#### Работа со Снапшотами (`qcow2`)

* **Внутренние снапшоты (хранятся внутри основного файла образа):**

    ```bash
    # Создать снапшот
    qemu-img snapshot -c <имя_снапшота> <файл_образа.qcow2>

    # Показать список снапшотов
    qemu-img snapshot -l <файл_образа.qcow2>

    # Откатиться к состоянию снапшота
    qemu-img snapshot -a <имя_снапшота> <файл_образа.qcow2>
    
    # Удалить снапшот
    qemu-img snapshot -d <имя_снапшота> <файл_образа.qcow2>
    ```

* **Внешние снапшоты (backing files):**
    Механизм, при котором создается новый `qcow2` файл, использующий оригинальный образ как "основу" (backing file), доступную только для чтения. Все изменения записываются в этот новый файл. Это позволяет использовать один "золотой образ" для множества ВМ, экономя дисковое пространство.

    ```bash
    # Создание delta-диска на основе базового образа
    qemu-img create -f qcow2 -b base_image.qcow2 -F qcow2 vm_delta.qcow2
    ```

#### Изменение размера диска

Процесс состоит из двух этапов: увеличение объема файла-образа на хосте и расширение разделов/файловой системы внутри гостевой ОС.

1. **На стороне хоста (увеличение файла-образа):**
   * **QEMU/KVM:** `qemu-img resize <файл_образа.qcow2> +<размер>G` (например, `+10G`).

2. **Внутри гостевой ОС (Linux):**
   * **Пересканирование диска** (если ВМ не перезагружалась): `echo 1 > /sys/class/block/sdX/device/rescan`.
   * **Изменение таблицы разделов:** Использование `fdisk`, `parted` или `growpart` (пакет `cloud-utils`) для расширения раздела.
   * **Расширение файловой системы:**
     * `ext4`: `resize2fs /dev/sdXn`.
     * `XFS`: `xfs_growfs /mount/point`.
     * **LVM**: `pvresize /dev/sdXn` -> `lvextend -l +100%FREE /dev/mapper/vg-lv` -> `resize2fs` (или `xfs_growfs`).

#### Восстановление доступа к ВМ (при наличии доступа к диску)

Если доступ к ВМ по SSH или паролю утерян, его можно восстановить, смонтировав образ диска на хосте или в другой ВМ.

1. **Монтирование образа:**
   * **QEMU/KVM (через nbd):**

     ```bash
     sudo modprobe nbd max_part=8
     sudo qemu-nbd --connect=/dev/nbd0 <путь_к_образу.qcow2>
     sudo mount /dev/nbd0p1 /mnt
     ```

2. **Сброс пароля/ключа:**
   * **SSH-ключ:** Добавить публичный ключ в `/mnt/root/.ssh/authorized_keys`.
   * **Пароль root:**
     * `chroot /mnt passwd root` (требуется `mount --bind` для `/dev`, `/proc`, `/sys`).
     * Или ручная правка `/mnt/etc/shadow` (замена хеша пароля).

3. **Размонтирование:**

   ```bash
   sudo umount /mnt
   sudo qemu-nbd --disconnect /dev/nbd0
   ```

## Дополнительная Информация

### Распространение ВМ: Формат OVF/OVA

Несмотря на стандартизацию, реализации OVF/OVA от разных вендоров (например, VMware и Oracle [**VirtualBox**](../../virtualbox.md)) часто оказываются несовместимыми.

### Автоматизация Сборки Образов

Для автоматизации рутинных процессов создания и настройки образов существуют специализированные инструменты:

* **Packer (by HashiCorp)**: Позволяет создавать идентичные образы ВМ для различных платформ (QEMU/[**KVM**](./overview.md), [**VirtualBox**](../../virtualbox.md), VMware, облачные провайдеры) из единого конфигурационного файла.
* [**Vagrant**](../../Vagrant/vagrant_basic_workflow.md): Инструмент для создания, настройки и управления легковесными, воспроизводимыми средами разработки на базе ВМ. Часто используется в связке с образами, подготовленными с помощью Packer.
