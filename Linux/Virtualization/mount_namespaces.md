# Пространства имён монтирования (Mount Namespaces)

В данном файле рассматриваются механизмы изоляции файловых систем в Linux с использованием **Mount Namespaces** и управление распространением событий монтирования (**Mount Propagation**). Общий обзор всех типов пространств имен доступен в [Пространства имён (namespaces)](../Core/namespaces.md).

## Определения

**Mount namespace (`CLONE_NEWNS`)** — тип пространства имен в Linux, который изолирует таблицу монтирования для группы процессов. Каждый mount namespace имеет собственный независимый список точек монтирования, что позволяет процессам видеть различные структуры файловых систем.

**Mount propagation** — механизм, определяющий, как события монтирования или размонтирования (mount/umount) распространяются между различными пространствами имен.

**Peer group** — группа точек монтирования (в одном или нескольких пространствах имен), которые обмениваются событиями монтирования в режиме **shared**.

**Bind mount** — механизм «отражения» содержимого одной директории в другую, создавая альтернативную точку доступа к тем же данным.

## Базовые концепции

### Флаги распространения монтирования (Propagation flags)

Тип распространения определяется флагами при выполнении операции монтирования:

| Флаг | Поведение | Направление распространения |
| :--- | :--- | :--- |
| **`MS_SHARED`** | События распространяются на все точки монтирования в рамках peer group. | Двустороннее (Parent ↔ Child) |
| **`MS_PRIVATE`** | События монтирования внутри этой точки не выходят за пределы namespace. | Изолированное (по умолчанию) |
| **`MS_SLAVE`** | Точка получает события от «мастера» (parent), но не отправляет свои события обратно. | Одностороннее (Parent → Child) |
| **`MS_UNBINDABLE`** | Точка монтирования, которую запрещено использовать в качестве источника для bind mount. | — |

### Наследование при создании namespace

При вызове `clone(CLONE_NEWNS)` или `unshare --mount`:

1. Новый namespace получает точную копию таблицы монтирования родителя.
2. Вместе с точками монтирования копируются их флаги распространения (propagation flags).
3. Дальнейшая изоляция зависит от того, были ли точки помечены как `shared`, `private` или `slave` в родительском namespace.

### Таблица взаимодействия Parent и Child

Поведение при выполнении монтирования в зависимости от флагов:

| Флаг у Child | Операция в Parent | Операция в Child | Результат |
| :--- | :--- | :--- | :--- |
| **private** | `mount /dev/sdb1 /data` | — | Child **не видит** `/data` |
| **private** | — | `mount /dev/sdc1 /mnt` | Parent **не видит** `/mnt` |
| **shared** | `mount /dev/sdb1 /data` | — | Child **видит** `/data` |
| **shared** | — | `mount /dev/sdc1 /mnt` | Parent **видит** `/mnt` |
| **slave** | `mount /dev/sdb1 /data` | — | Child **видит** `/data` |
| **slave** | — | `mount /dev/sdc1 /mnt` | Parent **не видит** `/mnt` |

## Практические сценарии

### Изоляция в контейнерах Docker

Docker по умолчанию использует mount namespace с propagation `private`:

- Корневая файловая система контейнера полностью изолирована от хоста.
- **Bind mounts** (`-v` / `--mount`): если директория на хосте примонтирована как `shared`, изменения (новые монтирования внутри этой директории) могут стать видимы внутри контейнера.
- В современных версиях Docker можно явно задавать propagation для volume: `type=bind,source=/path,target=/path,bind-propagation=rslave`.

### Управление распространением на хосте

Изменение типа распространения для существующих точек монтирования:

```bash
# Сделать корень и все вложенные точки рекурсивно shared
mount --make-rshared /

# Сделать рекурсивно private (полная изоляция новых namespaces)
mount --make-rprivate /

# Сделать рекурсивно slave (одностороннее получение обновлений от хоста)
mount --make-rslave /
```

### Диагностика пространств имен процесса

Для анализа текущего состояния монтирований используются файлы в `/proc`:

```bash
# Идентификатор mount namespace процесса
ls -l /proc/<PID>/ns/mnt

# Просмотр детальной информации о точках монтирования и их флагах (propagation)
# Поле shared:X или master:X указывает на принадлежность к peer group
cat /proc/<PID>/mountinfo
```

## Дополнительная информация

### Системные вызовы ядра

| Вызов | Назначение |
| :--- | :--- |
| `clone(CLONE_NEWNS, ...)` | Создание нового процесса в новом mount namespace. |
| `unshare(CLONE_NEWNS)` | Вывод текущего процесса в новое пространство имен монтирования. |
| `setns(fd, CLONE_NEWNS)` | Присоединение процесса к существующему mount namespace (через файловый дескриптор). |
| `mount(..., MS_REC|MS_SHARED, ...)` | Изменение флагов распространения для точки монтирования. |
