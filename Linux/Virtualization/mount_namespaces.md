# Наследование и распространение точек монтирования (Mount Propagation)

**Наследование точек монтирования** — это механизм в Linux, определяющий, как события монтирования и отмонтирования файловых систем распространяются между различными [пространствами имён монтирования (mount namespaces)](../../Docker/Concepts/linux_isolation.md). Этот механизм является ключевым для понимания изоляции контейнеров.

Когда создается новый mount namespace, он получает копию точек монтирования своего родителя. Дальнейшее поведение зависит от флагов распространения (`propagation flags`).

### Основные понятия

1. **Peer Group (Группа равных):** Группа пространств имён, которые могут обмениваться событиями монтирования. Когда пространство имён создается как `shared`, оно попадает в peer group своего родителя.

2. **Propagation Flags (Флаги распространения):**
    * `MS_SHARED` (Общий): События монтирования/отмонтирования распространяются на все "равные" пространства в peer group. Если в одном из них что-то примонтировали, остальные это увидят.
    * `MS_PRIVATE` (Приватный): Точка монтирования является приватной. События не распространяются в другие пространства и не принимаются из них. Это поведение по умолчанию для новых пространств имен.
    * `MS_SLAVE` (Подчиненный): Пространство получает события от своего "мастера" (master), но не отправляет события обратно. Это однонаправленное распространение.
    * `MS_UNBINDABLE` (Непривязываемый): Предотвращает привязку этой точки монтирования в качестве bind mount в другом месте.

### Как это работает на практике

Представим два пространства имен: **Parent** и **Child**.

| Флаг у Child | Действие в Parent | Действие в Child | Результат |
| :--- | :--- | :--- | :--- |
| **private** | `mount /dev/sdb1 /data` | - | В Child ничего не изменится. |
| **private** | - | `mount /dev/sdc1 /mnt` | В Parent ничего не изменится. |
| **shared** | `mount /dev/sdb1 /data` | - | В Child появится точка монтирования `/data`. |
| **shared** | - | `mount /dev/sdc1 /mnt` | В Parent появится точка монтирования `/mnt`. |
| **slave** | `mount /dev/sdb1 /data` | - | В Child появится точка монтирования `/data`. |
| **slave** | - | `mount /dev/sdc1 /mnt` | В Parent **ничего не изменится**. |

### Применение в Docker

Docker активно использует эти механизмы:

* **Изоляция по умолчанию:** Файловая система контейнера по умолчанию создается в **приватном** пространстве имен, поэтому изменения ФС на хосте не влияют на контейнер, и наоборот.
* **Bind Mounts (`-v` или `--mount`):** Когда вы делаете `docker run -v /host/path:/container/path`, Docker, по сути, выполняет `mount --bind` из хостовой системы в пространство имен контейнера. Если исходная точка на хосте является частью `shared` peer group, то изменения могут распространяться.

### Управление

Изменить флаги распространения можно с помощью команды `mount`:

```bash
# Сделать / рекурсивно общим
mount --make-rshared /

# Сделать / рекурсивно приватным
mount --make-rprivate /

# Сделать / рекурсивно подчиненным
mount --make-rslave /
```

Эти команды особенно важны в средах, где нужно обеспечить контролируемое распространение монтируемых устройств (например, USB-дисков) в запущенные контейнеры.
