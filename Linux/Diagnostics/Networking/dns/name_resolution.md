# Порядок разрешения имён в Linux

## Как работает резолвинг

Разрешение имён управляется файлом `/etc/nsswitch.conf`. Стандартная строка:

```
hosts: files dns
```

**Порядок:**

1. **`files`** — проверка `/etc/hosts` (локальные переопределения)
2. **`dns`** — запрос к DNS-серверам из `/etc/resolv.conf`

> **Важно:** Запись в `/etc/hosts` может переопределять DNS, что часто маскирует проблемы.

## Полный порядок разрешения

```
Приложение (браузер, curl)
    ↓
Системный резолвер (glibc)
    ↓
/etc/nsswitch.conf (порядок: files → dns)
    ↓
┌─────────────────┬─────────────────┐
│   /etc/hosts    │   DNS-серверы   │
│   (локально)    │   (резолвер)    │
└─────────────────┴─────────────────┘
    ↓
DNS-кэш ОС (если включён)
    ↓
┌─────────────────────────────────┐
│  Корневые DNS-серверы (.)       │
│  → TLD-серверы (.com, .ru)      │
│  → Авторитетные серверы       │
└─────────────────────────────────┘
```

## Вектор атаки: `/etc/hosts`

Вредоносное ПО может добавлять записи в `/etc/hosts` для перенаправления трафика на фишинговые сайты. Проверка целостности:

```bash
# Сверить с известными записями
cat /etc/hosts

# Проверить изменения файла (если используется auditd)
ausearch -f /etc/hosts -i
```

**Важно:** Большинство запущенных процессов кэшируют результаты разрешения доменных имён. При изменении `/etc/hosts` запущенные процессы **не перечитывают его немедленно**. Требуется перезапуск процесса или очистка кэша.
