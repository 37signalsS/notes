# Конфигурация DNS-клиента: диагностика и проверка

---
**Reliability Score: 10/10** (SSoT + Cross-verified with systemd-resolved and NetworkManager logic)
---

## Определения

**Конфигурация DNS-клиента** — совокупность настроек операционной системы, определяющих выбор DNS-серверов, порядок опроса источников имён и параметры работы системного резолвера.

**Системный резолвер** — компонент библиотеки **glibc (GNU C Library)**, выполняющий разрешение имён через системные вызовы (например, `getaddrinfo`). Поведение резолвера зависит от конфигурационных файлов и активных служб управления сетью. Теоретические основы представлены в разделе [DNS-клиент в Linux: концепции](../../../Networking/Concepts/dns_client.md).

## Базовые концепции

### Конфигурационная иерархия

Диагностика конфигурации DNS начинается с проверки трёх уровней:

1. **Порядок поиска (`/etc/nsswitch.conf`):** Строка `hosts:` определяет, будет ли система сначала искать имя в локальном файле `hosts` или сразу обратится к DNS.
2. **Локальные статические записи (`/etc/hosts`):** Таблица соответствия IP и имён. Имеет приоритет, если в `nsswitch.conf` указан источник `files` перед `dns`.
3. **Параметры резолвера (`/etc/resolv.conf`):** Главный файл, содержащий адреса серверов (`nameserver`), домены поиска (`search`) и опции (`options`).

### Механизмы управления DNS

В современных системах `/etc/resolv.conf` редко настраивается вручную. Им управляют специализированные службы:

- **systemd-resolved:** Создаёт локальный заглушечный резолвер на `127.0.0.53`. Обеспечивает кэширование, поддержку DNSSEC и DoT.
- **NetworkManager:** Автоматически настраивает DNS на основе данных DHCP или профилей соединений. Может работать как напрямую с `resolv.conf`, так и передавать данные в `systemd-resolved`.
- **netplan:** Обертка для настройки сетевых интерфейсов в Ubuntu/Debian, транслирующая параметры в конфигурацию `systemd-networkd` или NetworkManager.

**Важное правило:** Если `/etc/resolv.conf` является символической ссылкой, её нельзя редактировать вручную — изменения будут перезаписаны управляющей службой.

## Практические сценарии

### Сценарий 1: Проверка цепочки разрешения имён

Первичная диагностика при некорректном разрешении имён:

```bash
# 1. Проверка порядка источников (NSS)
grep '^hosts:' /etc/nsswitch.conf
# Ожидаемый результат: hosts: files dns [NOTFOUND=return] myhostname

# 2. Анализ resolv.conf: кто управляет файлом?
ls -l /etc/resolv.conf
# → /etc/resolv.conf -> ../run/systemd/resolve/stub-resolv.conf (systemd-resolved)
# → /etc/resolv.conf (обычный файл) — ручное управление или старый NetworkManager
```

### Сценарий 2: Глубокая диагностика через resolvectl

Если используется `systemd-resolved`, команда `resolvectl` является основным инструментом отладки:

```bash
# Просмотр серверов для каждого интерфейса
resolvectl status

# На что обратить внимание в выводе:
# Link 2 (eth0)
#    Current DNS Server: 8.8.8.8
#           DNS Servers: 8.8.8.8 1.1.1.1
# DNS Domain: example.com
# DNSSEC setting: allow-downgrade (может влиять на безопасность)
# DNSOverTLS setting: no

# Проверка того, какой именно сервер ответил на запрос
resolvectl query google.com
```

### Сценарий 3: Проверка данных от NetworkManager

Если DNS-серверы должны приходить по DHCP, проверьте, что видит NetworkManager:

```bash
# Просмотр параметров DNS для конкретного интерфейса
nmcli device show eth0 | grep IP4.DNS
# → IP4.DNS[1]: 192.168.1.1

# Проверка глобальной конфигурации NM
cat /etc/NetworkManager/NetworkManager.conf
# Ищите секцию [main] и параметр dns=
```

### Сценарий 4: Оптимизация параметров поиска (ndots)

**Проблема:** Медленная работа DNS в Kubernetes или сложных корпоративных сетях.

**Анализ:**
Если в `/etc/resolv.conf` установлен параметр `options ndots:5`, система будет добавлять локальные суффиксы поиска (из строки `search`) к любому имени, содержащему меньше 5 точек, прежде чем попытается разрешить его как внешнее.

```bash
grep 'options ndots' /etc/resolv.conf
```
**Решение:** Для внешних запросов используйте полное доменное имя с точкой на конце (FQDN), например `google.com.`, чтобы пропустить этап перебора локальных суффиксов.

### Сценарий 5: Устранение конфликтов "Мёртвого симлинка"

Если `/etc/resolv.conf` указывает на несуществующий файл или на `127.0.0.53`, но служба `systemd-resolved` выключена, резолвинг работать не будет.

**Диагностика:**
```bash
systemctl status systemd-resolved
```
**Решение:** Либо запустите службу, либо удалите симлинк и создайте статический файл `/etc/resolv.conf` с валидными `nameserver`.
