# Детальный анализ DNS с помощью dig

---
**Reliability Score: 10/10** (SSoT + Web verified: BIND 9.18/9.20 features included)
---

## Определения

**`dig` (Domain Information Groper)** — утилита для выполнения DNS-запросов и получения детальной информации о доменах. Входит в состав пакета `dnsutils` (Debian) или `bind-utils` (RHEL). В отличие от `nslookup` или `host`, предоставляет полный вывод протокола: заголовки, секции ответа, статистику и флаги. Начиная с версии BIND 9.18, поддерживает современные протоколы шифрования (DoH, DoT) и структурированный вывод (JSON, YAML).

## Базовые концепции

### Установка

```bash
# Debian/Ubuntu
sudo apt-get install -y dnsutils

# RHEL/CentOS
sudo dnf install -y bind-utils

# Alpine
apk add bind-utils
```

### Структура вывода

```bash
dig example.com
```

Основные секции ответа:

1. **HEADER**: Общая информация (статус запроса, ID транзакции, количество записей в секциях).
2. **OPT PSEUDOSECTION**: Информация о расширениях EDNS (например, размер UDP-пакета, COOKIE).
3. **QUESTION SECTION**: Подтверждение запрашиваемого домена и типа записи.
4. **ANSWER SECTION**: Ресурсные записи, соответствующие запросу (искомый результат).
5. **AUTHORITY SECTION**: Список авторитетных серверов имен для домена (NS-записи).
6. **ADDITIONAL SECTION**: Дополнительная информация (например, IP-адреса NS-серверов).
7. **Статистика**: Время выполнения, используемый сервер, дата, размер сообщения и транспортный протокол (в новых версиях).

### Коды ответов и флаги

| Поле | Описание |
| :--- | :--- |
| **status: NOERROR** | Запрос выполнен успешно. |
| **status: NXDOMAIN** | Доменное имя не существует. |
| **status: SERVFAIL** | Ошибка на стороне DNS-сервера. |
| **status: REFUSED** | Запрос отклонён сервером (например, по ACL). |
| **flags: qr** | Response — это ответ (отсутствие флага означает запрос). |
| **flags: aa** | Authoritative Answer — ответ получен от владельца зоны (не из кэша). |
| **flags: rd** | Recursion Desired — клиент запросил рекурсию. |
| **flags: ra** | Recursion Available — сервер поддерживает рекурсию. |
| **flags: tc** | TrunCated — пакет был обрезан (требуется переход на TCP). |
| **flags: ad** | Authenticated Data — данные проверены через DNSSEC. |
| **flags: cd** | Checking Disabled — отключение проверки DNSSEC на стороне сервера. |

### Основные опции

| Опция | Описание |
| :--- | :--- |
| `+short` | Краткий вывод (только значения данных). |
| `+noall +answer` | Скрыть всё, кроме секции ответа. |
| `+trace` | Трассировка пути от корневых серверов до авторитетных. |
| `+stats` | Показать/скрыть статистику выполнения. |
| `+tcp` | Принудительное использование TCP вместо UDP. |
| `-x` | Обратный DNS-запрос (Reverse Lookup) — IP в домен. |
| `+dnssec` | Запросить записи DNSSEC и проверку подписей. |
| `+ttlid` | Отображать TTL для каждой записи в ответе. |
| `+json` | Вывод в формате JSON (BIND 9.18+). |
| `+yaml` | Вывод в формате YAML (BIND 9.18+). |

## Практические сценарии

### Сценарий 1: Базовый запрос и выбор типа записи

```bash
dig ya.ru            # Запрос A-записи (по умолчанию)
dig ya.ru MX         # Запрос почтовых серверов
dig ya.ru NS         # Запрос авторитетных серверов имен
dig ya.ru TXT        # Запрос текстовых записей (SPF/DKIM)
dig _http._tcp.example.com SRV  # Запрос SRV-записи
```

### Сценарий 2: Использование конкретного DNS-сервера

```bash
dig @8.8.8.8 example.com    # Опрос публичного резолвера Google
dig @1.1.1.1 example.com    # Опрос резолвера Cloudflare
```

### Сценарий 3: Обратный DNS-запрос (PTR)

```bash
dig -x 93.184.216.34 +short
# → example.com.

# Для IPv6
dig -x 2606:2800:220:1:248:1893:25c8:1946 +short
```

### Сценарий 4: Трассировка делегирования домена

Позволяет увидеть, как запрос проходит через корневые, TLD и авторитетные серверы.

```bash
dig google.com +trace
```

### Сценарий 5: Современные шифрованные протоколы (DoH/DoT)

Доступно в BIND 9.18+.

```bash
# DNS over TLS (DoT) на стандартном порту 853
dig +tls @1.1.1.1 example.com

# DNS over HTTPS (DoH) на порту 443 (использует POST /dns-query по умолчанию)
dig +https @8.8.8.8 example.com

# DoH с использованием GET и кастомного эндпоинта
dig +https-get +https=/dns-query @9.9.9.9 example.com
```

### Сценарий 6: Машиночитаемый вывод для автоматизации

```bash
# Вывод в JSON для парсинга через jq
dig example.com +json | jq '.answer[0].data'

# Вывод в YAML
dig example.com +yaml
```

### Сценарий 7: Диагностика за прокси (PROXYv2)

Используется для тестирования серверов за балансировщиками (BIND 9.20+).

```bash
dig +proxy @10.0.0.5 example.com
```

### Сценарий 8: Проверка DNSSEC и цепочки доверия

```bash
# Запрос записей DNSSEC
dig +dnssec example.com

# Проверка всей цепочки доверия от корня (требует утилиту delv)
delv example.com
# → ; fully validated
```

### Сценарий 9: Проверка возможности трансфера зоны (AXFR)

Используется для диагностики безопасности — в норме публичные серверы должны отклонять такой запрос.

```bash
dig @ns1.example.com example.com AXFR
```
