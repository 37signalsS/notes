# Диагностика DNS

## 1. Определение

Проблемы с разрешением доменных имён (DNS) — частая причина, по которой сетевые сервисы могут казаться недоступными, даже если сетевая связность на уровне IP-адресов в порядке.

## 2. Основные концепции

### Системный резолвер vs. Прямой опрос

-   **Системный резолвер:** Процесс, который приложения (`ping`, `curl`, браузер) используют для разрешения имён. Его поведение определяется файлами `/etc/nsswitch.conf` и `/etc/resolv.conf`. Как правило, он сначала проверяет локальные записи в `/etc/hosts`, а затем обращается к указанным DNS-серверам. **Это может маскировать проблемы с внешним DNS.**
-   **Утилиты прямого опроса (`dig`, `host`, `nslookup`):** Эти инструменты **игнорируют `/etc/hosts`** и напрямую отправляют запросы на DNS-сервер. Они незаменимы для "чистой" проверки DNS-записей и диагностики.

### `systemd-resolved`

На многих современных дистрибутивах `systemd-resolved` выступает в роли локального кэширующего DNS-резолвера. Для его диагностики используются следующие команды:
```bash
# Выполнить запрос через системный резолвер
resolvectl query example.com

# Проверить статус и статистику сервиса
resolvectl status
systemd-resolve --statistics
```
Растущий счётчик `Transactions in progress` или большое количество `Cache Misses` может указывать на проблемы.

## 3. Практические сценарии

### Инструменты для диагностики

#### `host` — Простой и быстрый
Самая простая утилита для быстрых DNS-запросов.
```bash
# Запросить A, AAAA и MX записи
host ya.ru

# Запросить конкретный тип записи (например, NS)
host -t NS habr.com
```

#### `nslookup` — Классический инструмент
Стандартная утилита, доступная в Linux и Windows.
```bash
nslookup ya.ru
```

#### `dig` — Мощный и детальный
`dig` (Domain Information Groper) — предпочтительный инструмент для администраторов из-за полноты выводимой информации.
```bash
# Запросить A-запись (по умолчанию)
dig habr.com

# Запросить MX-запись (почтовые серверы)
dig ya.ru MX
```

### Проблема в DNS или в сети?

1.  **Выполните тест через внешний резолвер:** `dig @1.1.1.1 example.com` (используя публичный DNS от Cloudflare). Если ответ приходит мгновенно, а от системного резолвера — медленно, значит, проблема локальная (например, в конфигурации `/etc/resolv.conf` или в работе `systemd-resolved`).

## 4. Продвинутые детали

### Трассировка DNS-запроса

Команда `dig +trace` позволяет отследить весь путь DNS-запроса от корневых серверов. Это крайне полезно для диагностики проблем делегирования домена.
```bash
dig ya.ru +trace
```

### Диагностика сетевых задержек

Для детального анализа сетевых задержек, включая время разрешения DNS, можно использовать `curl`. Этот метод подробно описан в заметке [Диагностика сетевых задержек с curl](./Tools/curl_network_diagnostics.md).
