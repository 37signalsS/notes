# Диагностика DNS

## Определения

-   **Системный резолвер:** Процесс, который приложения (`ping`, `curl`, браузер) используют для разрешения имён. Его поведение определяется системной конфигурацией (включая `/etc/hosts`), что может маскировать проблемы с внешними DNS-серверами.
-   **Утилиты прямого опроса (`dig`, `host`, `nslookup`):** Инструменты, которые напрямую отправляют запросы на DNS-сервер, игнорируя локальные настройки вроде `/etc/hosts`. Незаменимы для "чистой" проверки DNS-записей.
-   **`dig` (Domain Information Groper):** Предпочтительный инструмент для диагностики DNS из-за полноты выводимой информации и гибкости.

## Основные концепции

### `systemd-resolved`

На многих современных дистрибутивах `systemd-resolved` выступает в роли локального кэширующего DNS-резолвера. Все DNS-запросы от приложений сначала поступают к нему. Для его диагностики используются следующие команды:

```bash
# Выполнить запрос через системный резолвер
resolvectl query example.com

# Проверить статус и статистику сервиса
resolvectl status
systemd-resolve --statistics
```
Растущий счётчик `Transactions in progress` или большое количество `Cache Misses` может указывать на проблемы с вышестоящими DNS-серверами или сетевой связностью.

## Практические сценарии

### Основные инструменты

#### `host`
Простой инструмент для быстрых проверок.
```bash
# Запросить A, AAAA и MX записи
host ya.ru

# Запросить конкретный тип записи (например, NS)
host -t NS habr.com
```

#### `nslookup` 
Интерактивный инструмент, также подходит для простых запросов.
```bash
nslookup ya.ru
```

#### `dig` 
Наиболее мощный инструмент для детального анализа.
```bash
# Запросить A-запись (по умолчанию)
dig habr.com

# Запросить MX-запись (почтовые серверы)
dig ya.ru MX

# Отследить весь путь DNS-запроса от корневых серверов
dig ya.ru +trace
```

### Проблема в DNS или в сети?

Чтобы локализовать проблему, сравните ответ от системного резолвера и внешнего публичного DNS-сервера.

1.  **Выполните тест через внешний резолвер:** `dig @1.1.1.1 example.com` (используя DNS от Cloudflare).
2.  **Сравните результат:** Если ответ от внешнего сервера приходит мгновенно, а от системного резолвера (`dig example.com`) — медленно или с ошибкой, проблема локальная (например, в конфигурации `/etc/resolv.conf` или в работе `systemd-resolved`).
