# Диагностика HTTP-задержек: сеть или приложение

## Определения

Диагностика HTTP-задержек заключается в определении этапа, на котором происходит замедление: на уровне сети, TLS-рукопожатия или внутри самого приложения (бэкенда).

`curl` — основной инструмент для этой задачи. Опция `-w` (`--write-out`) выводит временные метрики, позволяя локализовать задержки на каждом этапе соединения.

> Полный справочник curl: **[cURL: Универсальный инструмент](../../Networking/Tools/http_clients/curl.md)**

## Основные концепции

### Логика разделения слоев

Запрос может казаться «медленным», но причина всегда локализована на одном из этапов:

1. **Сетевой слой (DNS и Connect):** Проблемы с резолвингом или сетевой связностью до сервера.
2. **Слой безопасности (TLS):** Задержки во время рукопожатия и криптографических операций.
3. **Слой приложения (TTFB):** Время, затраченное бэкендом на обработку запроса.
4. **Итог (Total):** Общее время выполнения.

**Правило:**

* Растет `dns` или `connect` — проблема **до** сервера (сеть).
* Растет `ttfb` — проблема **внутри** бэкенда (приложение).

### Ключевые метрики

| Метрика | Описание | Слой |
| :--- | :--- | :--- |
| `time_namelookup` | Время разрешения DNS-имени | Сеть |
| `time_connect` | Время установки TCP-соединения | Сеть |
| `time_appconnect` | Время завершения TLS-рукопожатия | TLS |
| `time_starttransfer` | TTFB (Time to First Byte) | Приложение |
| `time_total` | Общее время операции | Итог |

## Практические сценарии

### 1. Детальный анализ таймингов

Использование `curl` для получения точных цифр по каждому этапу:

```bash
curl -w "dns:%{time_namelookup} connect:%{time_connect} tls:%{time_appconnect} ttfb:%{time_starttransfer} total:%{time_total}\n" \
-o /dev/null -s https://example.com
```

### 2. Изоляция DNS-проблем

Сравнение обычного запроса с запросом по конкретному IP помогает локализовать задержки на этапе DNS.

```bash
curl --resolve example.com:443:93.184.216.34 https://example.com
```

*Опция `--resolve` применяет IP только для текущего вызова, являясь чистой альтернативой правке `/etc/hosts`.*

### 3. Отслеживание пауз в реальном времени

Команда `curl -v` позволяет увидеть, где именно возникает пауза (между подключением, TLS и ожиданием первого байта):

```bash
curl -v https://example.com
```

*Смысл не в тексте ответа, а в паузах между строками вывода таймингов.*

### 4. Проверка стабильности (цикл)

Если время ответа скачет — проблема чаще в сети или балансировке. Если оно стабильно высокое — в приложении или его зависимостях.

```bash
for i in {1..20}; do \
curl -o /dev/null -s -w "%{time_total}\n" https://example.com; \
done
```

### 5. Сравнение локального и внешнего пути

Помогает исключить влияние внешней сетевой инфраструктуры.

```bash
# Локальный запрос (внутри сервера или контура)
curl -o /dev/null -s -w "%{time_total}\n" http://127.0.0.1:8080

# Внешний запрос
curl -o /dev/null -s -w "%{time_total}\n" https://example.com
```

*Разница ключевая: если локально быстро, а снаружи медленно — виновата сеть/инфраструктура.*

### 6. Нагрузка как тест на предел (Stress Test)

Если задержка растет только под нагрузкой — это ограничение внутри сервиса (CPU, очереди, БД, пул соединений).

```bash
# Использование ApacheBench (ab)
ab -n 200 -c 20 https://example.com/

# Использование wrk
wrk -t2 -c50 -d10s https://example.com/
```

## Дополнительная информация

### Интерпретация результатов

| Метрика | Вероятная причина | Направление диагностики |
| :--- | :--- | :--- |
| Высокое `dns` | Медленный DNS-сервер | **[Диагностика DNS](./dns/overview.md)** |
| Высокое `connect` | Задержки TCP, файрвол, перегрузка сети | **[ss](./ss.md)**, **[tcpdump](./tcpdump.md)** |
| Высокое `tls` | CPU сервера, проблемы с сертификатом | Проверка сертификата, нагрузка на сервер |
| Высокое `ttfb` | Бэкенд долго обрабатывает запрос | Логи приложения, профилирование бэкенда |
