# Диагностика сетевых задержек с curl

## Определения

`curl` — это универсальная утилита для передачи данных с использованием различных сетевых протоколов. Помимо своей основной функции, она предоставляет мощные возможности для диагностики сетевых проблем, позволяя детально измерить время, затраченное на каждом этапе HTTP(S)-запроса.

## Основные концепции

С помощью опции `-w` (`--write-out`) `curl` может выводить подробную информацию о транзакции после её завершения. Специальные переменные, такие как `%{time_namelookup}`, позволяют разбить общее время запроса на составляющие.

**Ключевые этапы соединения:**

1.  `time_namelookup`: Время разрешения DNS-имени.
2.  `time_connect`: Время установки TCP-соединения с сервером.
3.  `time_appconnect`: Время завершения TLS-рукопожатия (для HTTPS).
4.  `time_pretransfer`: Общее время от начала до момента, когда можно начинать передачу данных.
5.  `time_starttransfer`: Время от начала до получения первого байта ответа.
6.  `time_total`: Общее время выполнения всей операции.

## Практические сценарии

### Анализ полного времени запроса

Следующая команда выполняет запрос, отбрасывает тело ответа (`-o /dev/null`), скрывает индикатор прогресса (`-s`) и выводит временные метрики каждого этапа.

```bash
curl -o /dev/null -s -w \
"DNS Lookup:    %{time_namelookup}s\n\
TCP Connection:  %{time_connect}s\n\
TLS Handshake:   %{time_appconnect}s\n\
Server Process:  %{time_starttransfer}s\n\
Total:           %{time_total}s\n" \
https://example.com
```

### Исключение влияния DNS

Чтобы изолировать проблемы с DNS, можно выполнить запрос напрямую к IP-адресу, "подсказав" `curl` правильное доменное имя для TLS-рукопожатия (SNI) и заголовка `Host`.

```bash
# Выполнить запрос к IP 93.184.216.34,
# но использовать доменное имя example.com для TLS и HTTP
curl --resolve example.com:443:93.184.216.34 https://example.com
```

Если с опцией `--resolve` запрос выполняется значительно быстрее, это однозначно указывает на проблемы с DNS.

## Дополнительная информация

### Интерпретация результатов

- Высокое `time_namelookup`: Указывает на медленный DNS-сервер или проблемы с разрешением имён.
- Высокое `time_connect`: Проблема с установкой TCP-соединения. Возможные причины: сетевые задержки, перегрузка сети, проблемы с файрволом.
- Высокое `time_appconnect` (для HTTPS): Задержка на этапе TLS-рукопожатия. Это может быть связано с медленной работой сервера (CPU) или проблемами с центром сертификации.
- Высокое `time_starttransfer` (при низких предыдущих значениях): Сетевое соединение установлено быстро, но сервер долго обрабатывает запрос перед тем, как отправить первый байт ответа. Это указывает на **проблему на стороне бэкенда** (медленный код, запрос к базе данных и т.д.).
