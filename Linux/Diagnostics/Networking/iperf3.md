# iperf3

## Определения

**`iperf3`** — консольная утилита для активного измерения максимально достижимой пропускной способности IP-сетей. Работает в клиент-серверном режиме, измеряет реальную скорость передачи данных между двумя хостами.

## Основные концепции

Тестирование требует запуска `iperf3` на двух хостах: **сервер** (приём трафика) и **клиент** (генерация трафика).

**Измеряемые метрики:**

| Метрика | Описание | Режим |
| :--- | :--- | :--- |
| **Bandwidth** | Пропускная способность (бит/с) | TCP, UDP |
| **Packet Loss** | Потери пакетов | UDP |
| **Jitter** | Вариация задержки пакетов (джиттер) | UDP |

### Основные аргументы

**Режимы:**

- `-s` — серверный режим (ожидание подключений)
- `-c <адрес>` — клиентский режим (подключение к серверу)

**Параметры теста:**

- `-p <порт>` — порт сервера (по умолчанию `5201`)
- `-t <сек>` — длительность теста (по умолчанию `10`)
- `-i <сек>` — интервал вывода промежуточных результатов
- `-P <n>` — количество параллельных TCP-потоков

**Полезные опции:**

- `-R` — reverse mode (реверсивный режим): сервер отправляет данные клиенту (проверка Download-канала)
- `-f <k/m/g>` — формат вывода: Kbits, Mbits, Gbits
- `-J` — вывод в формате JSON (для автоматизации)
- `-u` — режим UDP (по умолчанию используется TCP)
- `-b <скорость>` — целевая пропускная способность в UDP-режиме (например, `100M`)

## Практические сценарии

### Тестирование TCP (Upload)

Клиент отправляет данные на сервер — измеряется скорость исходящего трафика (Upload).

```bash
# На сервере (принимающая сторона)
iperf3 -s
# → Server listening on 5201

# На клиенте (отправляющая сторона)
iperf3 -c 192.168.1.10
# → [ ID] Interval           Transfer     Bandwidth
# → [  5]   0.00-10.00  sec  1.09 GBytes   941 Mbits/sec                  receiver
```

### Тестирование TCP (Download)

Ключ `-R` инвертирует направление потока данных без изменения ролей клиента и сервера.

```bash
# На клиенте
iperf3 -c 192.168.1.10 -R
# → [ ID] Interval           Transfer     Bandwidth
# → [  5]   0.00-10.00  sec  1.05 GBytes   905 Mbits/sec                  sender
```

### Тестирование UDP

Используется для оценки стабильности канала и потерь пакетов.

```bash
# На клиенте — UDP с целевой скоростью 100 Мбит/с
iperf3 -c 192.168.1.10 -u -b 100M
# → [ ID] Interval           Transfer     Bandwidth      Jitter    Lost/Total Datagrams
# → [  5]   0.00-10.00  sec   119 MBytes   100 Mbits/sec  0.025 ms  0/86184 (0%)
```

### Многопоточный тест для насыщения канала

Ключ `-P` позволяет задействовать несколько параллельных потоков, что критично для 10GbE+ сетей или каналов с высокой задержкой.

```bash
# Запуск теста в 10 потоков
iperf3 -c 192.168.1.10 -P 10
```

### Длительное тестирование и интервалы

Для выявления плавающих проблем со скоростью рекомендуется увеличивать время теста.

```bash
# Тест 60 секунд с выводом каждые 5 секунд
iperf3 -c 192.168.1.10 -t 60 -i 5
```

## Дополнительная информация

### Интерпретация результатов

- **Асимметрия каналов:** Значительная разница между результатами обычного теста и реверсивного (`-R`) указывает на асимметрию пропускной способности (типично для ADSL/PON).
- **Один поток vs Много потоков:** Если 10 потоков выдают значительно большую суммарную скорость, чем один — возможно, требуется оптимизация TCP-стека (TCP Window Scaling).
- **UDP потери:** Наличие потерь в UDP-тесте при загрузке ниже физического лимита указывает на перегрузку промежуточного оборудования или проблемы с качеством линии.
