# ss (Socket Statistics)

---
**Reliability Score: 10/10** (SSoT + Проверено на ядрах Linux 6.x+)
---

## Определения

**`ss`** (Socket Statistics) — основная консольная утилита в Linux для исследования сетевых сокетов. Входит в состав пакета `iproute2`. В отличие от устаревшего `netstat`, она получает информацию напрямую из адресного пространства ядра через интерфейс **netlink**, что позволяет мгновенно обрабатывать тысячи активных соединений.

## Основные концепции

### Преимущества перед netstat

| Характеристика | ss | netstat |
| :--- | :--- | :--- |
| **Источник данных** | `netlink` (бинарный интерфейс ядра) | `/proc` (парсинг текстовых файлов) |
| **Производительность** | O(1) — масштабируется линейно | O(n) — замедляется при росте числа сокетов |
| **Фильтрация** | Встроенный язык выражений | Требует внешних утилит (`grep`, `awk`) |
| **TCP-детали** | Полные (RTT, cwnd, MSS, алгоритм BBR) | Базовые счетчики |
| **Статус** | Активный стандарт | Устарела (deprecated) |

### Состояния TCP-соединений

Утилита позволяет фильтровать сокеты по их жизненному циклу:

- **LISTEN:** Ожидание входящих подключений (серверная часть).
- **ESTABLISHED:** Активная передача данных.
- **SYN-SENT / SYN-RECV:** Этапы "трехстороннего рукопожатия". Большое число `SYN-RECV` может указывать на SYN-flood атаку.
- **TIME-WAIT:** Соединение закрыто, но ядро удерживает запись для обработки задержанных пакетов.
- **CLOSE-WAIT:** Удаленная сторона закрыла соединение, локальное приложение еще нет (возможна утечка ресурсов в коде).

### Основные флаги

- `-t` / `-u`: TCP или UDP сокеты.
- `-x`: Unix domain сокеты (локальные сокеты процессов).
- `-4` / `-6`: Фильтрация только по IPv4 или IPv6.
- `-l`: Только слушающие (Listening) порты.
- `-a`: Все сокеты (Listening + Established).
- `-p`: Вывод PID и имени процесса (требует `sudo`).
- `-n`: Числовые значения (без разрешения имен через DNS/etc/services — работает быстрее).
- `-i`: Детальная TCP-статистика (RTT, cwnd, retrans).
- `-m`: Информация об использовании памяти каждым сокетом.
- `-s`: Сводный отчет по всем протоколам.

## Практические сценарии

### Анализ слушающих портов (IPv4 и IPv6)

Проверка, какие службы открыты для входящих соединений:

```bash
sudo ss -tulpn
# → Netid  State   Recv-Q  Send-Q  Local Address:Port  Peer Address:Port  Process
# → tcp    LISTEN  0       128     0.0.0.0:22          0.0.0.0:*          users:(("sshd",pid=1234))
# → tcp    LISTEN  0       511     [::]:80             [::]:*             users:(("nginx",pid=5678))
```

**Интерпретация:**
- `0.0.0.0:22` — SSH слушает на всех IPv4 интерфейсах.
- `[::]:80` — Nginx слушает на всех IPv6 интерфейсах.
- **Recv-Q:** Для LISTEN-сокета это текущий размер очереди `backlog`. Если `Recv-Q > 0`, приложение не успевает принимать новые соединения.

### Фильтрация по хосту и порту

`ss` поддерживает гибкий синтаксис для сужения поиска:

```bash
# Соединения с конкретным IP
ss -at dst 192.168.1.100

# Поиск всех соединений на HTTPS порт
ss -t '( dport = :443 or sport = :443 )'

# Соединения в конкретном состоянии
ss -t state time-wait
```

### Диагностика Unix-сокетов

Анализ локального взаимодействия процессов (например, Docker, PostgreSQL, Systemd):

```bash
sudo ss -x -p
# → Netid  State  Recv-Q  Send-Q  Local Address:Port  Peer Address:Port  Process
# → u_str  ESTAB  0       0       /run/docker.sock    * 12345            users:(("dockerd",pid=800))
```

### Глубокий анализ производительности (`ss -ti`)

Используется для поиска причин "тормозов" в сети без запуска `tcpdump`:

```bash
ss -ti dst 1.1.1.1
# → cubic wscale:7,7 rto:204 rtt:15.2/0.5 ato:40 mss:1448 
# → cwnd:10 bytes_acked:15002048 retrans:0/125 delivery_rate 120Mbps
```

**Ключевые метрики:**
- **rtt:** Реальное время кругового обхода. Первое число — среднее, второе — отклонение (jitter).
- **retrans:** `текущие/всего`. Рост общего числа ретрансмиссий говорит о потерях пакетов.
- **cwnd:** Окно перегрузки. Маленькое значение при хорошем канале — признак того, что TCP снизил скорость из-за прошлых потерь.
- **delivery_rate:** Реальная пропускная способность, которую видит стек TCP.

### Анализ потребления памяти (`ss -m`)

Помогает выявить сокеты, которые потребляют слишком много буферной памяти:

```bash
ss -tm
# → skmem:(r0,rb212992,t0,tb212992,f0,w0,o0,bl0,d0)
```
- **rb:** Приемный буфер (read buffer).
- **tb:** Буфер передачи (transmit buffer).

## Сравнение команд: netstat → ss

| Задача | netstat (Old) | ss (Modern) |
| :--- | :--- | :--- |
| Слушающие TCP/UDP с PID | `netstat -tulpn` | `ss -tulpn` |
| Все TCP соединения | `netstat -at` | `ss -at` |
| Статистика по протоколам | `netstat -s` | `ss -s` |
| Фильтр по порту 80 | `netstat -an | grep :80` | `ss -tn sport = :80` |
| Просмотр Unix-сокетов | `netstat -x` | `ss -x` |
| Маршруты (Routing) | `netstat -rn` | `ip route` |
