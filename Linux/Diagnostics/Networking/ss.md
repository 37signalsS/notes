# ss (Socket Statistics)

## Определения

`ss` (Socket Statistics) — это современная консольная утилита в Linux для просмотра информации о сетевых сокетах. Она является более быстрой и мощной альтернативой устаревшей команде `netstat`, так как получает информацию напрямую из ядра через интерфейс `netlink`.

## Основные концепции

`ss` позволяет просматривать активные TCP/UDP соединения, слушающие порты и процессы, которые их используют. Её высокая производительность делает её незаменимой на высоконагруженных серверах с большим количеством соединений.

### Ключевые состояния TCP соединений

`ss` отображает стандартные состояния TCP, которые важны для диагностики:

- **LISTEN:** Сервер ожидает входящих подключений на порту.
- **SYN-SENT:** Клиент отправил пакет SYN для начала установки соединения.
- **SYN-RECV:** Сервер получил SYN и отправил SYN-ACK. Часто наблюдается при [SYN-flood атаках](../../../Security/DoS/syn_flood.md).
- **ESTABLISHED:** Соединение установлено, данные могут передаваться.
- **FIN-WAIT-1/2, CLOSE-WAIT, TIME-WAIT:** Различные стадии корректного закрытия соединения. Большое количество соединений в `TIME-WAIT` может указывать на необходимость [тюнинга TCP](../../Networking/Concepts/tcp_tuning.md).

## Практические сценарии

### Просмотр слушающих портов

Самый частый сценарий — посмотреть, какие порты открыты и какие процессы их слушают.

```bash
# Показать все слушающие TCP и UDP порты с именами процессов
sudo ss -tulpn
```

- `-t`: Показывает только TCP-сокеты.
- `-u`: Показывает только UDP-сокеты.
- `-l`: Показывает только слушающие сокеты (`LISTEN`).
- `-p`: Показывает процесс, который использует сокет.
- `-n`: Не преобразовывать адреса и порты в имена (работает быстрее).
- `-a`: Показывает все сокеты (слушающие и не слушающие).

**Пример интерпретации вывода:**

```
tcp LISTEN 0 0.0.0.0:80 0.0.0.0:* users:(("nginx",pid=1234))
```

- `0.0.0.0:80` — сервис слушает на всех сетевых интерфейсах и доступен извне.
- `127.0.0.1:80` — сервис слушает только на локальном интерфейсе и доступен только внутри хоста.

### Фильтрация соединений

`ss` поддерживает мощный синтаксис фильтрации для поиска конкретных соединений.

```bash
# Показать все установленные TCP-соединения
ss -t state established

# Показать все соединения, связанные с портом 443 (как источником, так и назначением)
ss -t '( dport = :443 or sport = :443 )'

# Показать соединения с определённым хостом
ss -t dst 192.168.1.100
```

### Пример из жизни: отслеживание подключения к веб-серверу

1. На сервере `ss -tl | grep :80` покажет, что веб-сервер находится в состоянии `LISTEN`.
2. Когда клиент подключается, команда `ss -tnp state established dst :80` покажет новое соединение в состоянии `ESTABLISHED`.
3. После закрытия страницы в браузере соединение перейдет в состояние `TIME-WAIT` на некоторое время, что можно увидеть с помощью `ss -tn state time-wait`.

## Дополнительная информация

### Диагностика производительности TCP (`ss -ti`)

Флаг `-i` (`--info`) выводит детальную информацию о TCP-соединениях, что крайне полезно для глубокой диагностики.

```bash
# Показать детальную статистику по всем TCP-соединениям
ss -ti

# Отфильтровать по конкретному порту
ss -ti dst :443
```

**Ключевые поля в выводе:**

- **`rtt`**: Round-Trip Time — реальная задержка соединения и её вариация (`rtt:<время>/<отклонение>`).
- **`retrans`**: Количество повторных передач пакетов (`retrans:<текущее>/<всего>`).
- **`cwnd`**: Congestion Window — размер окна перегрузки; сколько данных TCP может отправить без ожидания подтверждения.
- **`bytes_sent/acked`**: Насколько эффективно идёт передача данных.

**Интерпретация проблем:**

- **Много `retrans`**: Явный признак потерь пакетов. Причины: перегруженная сеть, неисправное оборудование, проблемы с MTU.
- **Маленький `cwnd`**: TCP "задушен" из-за потерь. Пропускная способность соединения крайне низка.
- **Большой `rtt` без нагрузки**: Указывает на задержки на маршруте (firewall, VPN, география).

### Сводная статистика по сокетам

Для получения общей картины по использованию сокетов используется флаг `-s`.

```bash
$ ss -s
Total: 256 (kernel 304)
TCP:   10 (estab 3, closed 0, orphaned 0, syn-recv 0, time-wait 0/0), ports 0

Transport Total     IP        IPv6
*   304       -         -
RAW   1         0         1
UDP   8         5         3
TCP   10        7         3
...
```

Эта команда полезна для быстрой оценки нагрузки на сетевую подсистему.
