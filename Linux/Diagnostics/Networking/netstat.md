# `netstat`

## Определения

> **Предупреждение:** `netstat` является устаревшим инструментом. В современных дистрибутивах Linux он заменен на более быструю и информативную утилиту [`ss`](./ss.md). Рекомендуется использовать `ss`.

**`netstat`** — классическая утилита командной строки для просмотра информации о сетевых подключениях (входящих и исходящих), таблицах маршрутизации, статистике сетевых интерфейсов и т.д. Она может отображать информацию о различных типах сокетов: TCP, UDP, а также Unix-сокеты.

## Основные концепции

`netstat` позволяет получить "снимок" текущего состояния сетевых соединений и открытых портов.

### Частые флаги

- `-t`: Показать TCP-сокеты.
- `-u`: Показать UDP-сокеты.
- `-l`: Показать только слушающие (listening) сокеты.
- `-p`: Показать PID (идентификатор процесса) и имя процесса, которому принадлежит сокет.
- `-n`: Показать числовые адреса и порты (не разрешать имена хостов и служб).
- `-a`: Показать все сокеты (слушающие и не слушающие).
- `-r`: Показать таблицу маршрутизации.
- `-i`: Показать статистику по сетевым интерфейсам.

## Практические сценарии

### Просмотр слушающих портов

Просмотр всех слушающих TCP и UDP портов вместе с PID и именем процесса, который их открыл.

```bash
netstat -tulpn
```

### Поиск процесса по порту

Поиск процесса, который слушает конкретный порт (например, `8080`).

```bash
netstat -tulpn | grep :8080
```

### Просмотр таблицы маршрутизации

Отображение текущей таблицы маршрутизации ядра.

```bash
netstat -rn
```

### Просмотр статистики сетевых интерфейсов

Вывод статистики по байтам и пакетам, переданным через сетевые интерфейсы.

```bash
netstat -i
```

## Дополнительная информация

### Альтернатива: `ss` (Socket Statistics)

Утилита `ss` предоставляет схожую, но более подробную информацию о сокетах и работает значительно быстрее, особенно на системах с большим количеством соединений. Она является рекомендуемой заменой для `netstat`.

Например, команда `netstat -tulpn` эквивалентна:

```bash
ss -tulpn
```

Для получения более детальной информации о `ss` и её возможностях, обратитесь к основной статье: **[`ss` (Socket Statistics)](./ss.md)**.
