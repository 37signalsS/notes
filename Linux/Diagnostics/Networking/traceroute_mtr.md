# traceroute и mtr

## Definitions

`traceroute` и `mtr` — утилиты для трассировки маршрута IP-пакетов от источника до пункта назначения. Показывают последовательность маршрутизаторов (хопов) и измеряют задержки до каждого из них.

## Basic Concepts

### Принцип работы traceroute

`traceroute` отправляет пакеты с постепенно увеличивающимся `TTL` (Time To Live). Подробности о [TTL в IP-пакетах](../../../Networking/Protocols/IP_addressing/ip_overview.md#time-to-live-ttl).

1. Первый пакет с `TTL=1`: первый маршрутизатор уменьшает TTL до 0, отбрасывает пакет и возвращает [ICMP Time Exceeded](../../../Networking/Protocols/ICMP/icmp_time_exceeded.md) — определяется первый хоп.
2. Второй пакет с `TTL=2`: второй маршрутизатор возвращает ICMP Time Exceeded — определяется второй хоп.
3. Процесс продолжается до достижения конечного хоста.

### Принцип работы mtr

`mtr` (My Traceroute) объединяет `traceroute` и `ping`. Постоянно отправляет пакеты и отображает обновляемую статистику по каждому хопу:

| Метрика | Описание |
| :--- | :--- |
| **Loss%** | Процент потерянных пакетов |
| **Snt** | Количество отправленных пакетов |
| **Last** | Последняя задержка (RTT) |
| **Avg** | Средняя задержка |
| **Best** | Лучшая задержка |
| **Wrst** | Худшая задержка |
| **StDev** | Стандартное отклонение (стабильность задержки) |

### Интерпретация результатов

| Симптом | Значение |
| :--- | :--- |
| Высокий `Loss%` на одном хопе, далее OK | Маршрутизатор настроен не отвечать на ICMP/UDP (не проблема) |
| Нарастающие потери от хопа к концу | Реальная проблема на участке сети |
| Резкий рост `Avg`/`Wrst`, сохраняющийся далее | «Бутылочное горлышко» на этом хопе |
| Высокий `StDev` | Нестабильность канала (jitter) |

## Practical Scenarios

### Базовая трассировка (traceroute)

```bash
# Маршрут до хоста
traceroute ya.ru

# Без разрешения имён (ускорение)
traceroute -n ya.ru

# TCP-пакеты на порт 80 (обход firewall)
sudo traceroute -n -T -p 80 ya.ru
```

### Интерактивная диагностика (mtr)

```bash
# Интерактивный режим
mtr ya.ru
```

Рекомендуется оставить `mtr` на несколько минут для сбора репрезентативной статистики.

### Автоматический отчёт (mtr)

```bash
# 10 пакетов на каждый хоп, вывод отчёта
mtr -r -c 10 ya.ru

# Подробный отчёт: 100 пакетов, широкий формат, AS-номера
mtr -rwzc 100 ya.ru
# -r — режим отчёта (без интерактива)
# -w — широкий формат (полные имена)
# -z — показывать AS-номера
# -c — количество пакетов
```
