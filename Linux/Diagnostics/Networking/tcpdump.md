# tcpdump

## Определения

**`tcpdump`** — мощная консольная утилита для перехвата и анализа сетевого трафика (пакетный сниффер). Работает на уровне ядра через библиотеку `libpcap`, что позволяет захватывать «сырые» данные непосредственно с сетевого интерфейса.

Используется для сетевой диагностики, отладки распределенных приложений, анализа безопасности и исследования протоколов. Требует прав суперпользователя (`root`) или специальных разрешений (`CAP_NET_RAW`, `CAP_NET_ADMIN`).

## Основные концепции

### Принцип работы и фильтрация

`tcpdump` перехватывает пакеты до того, как они будут обработаны сетевым стеком ОС (для входящих) или после обработки (для исходящих). Для фильтрации используется синтаксис **BPF (Berkeley Packet Filter)**, который позволяет эффективно отсеивать ненужный трафик на уровне ядра, минимизируя нагрузку на систему.

### Ключевые возможности

- **Захват в реальном времени:** вывод заголовков и содержимого пакетов в консоль.
- **Сохранение в файл:** запись трафика в формате `.pcap` для последующего анализа.
- **Глубокий анализ заголовков:** поддержка большинства протоколов (IP, TCP, UDP, ICMP, ARP и др.).
- **Просмотр Payload:** отображение данных в форматах ASCII и HEX (шестнадцатеричный).

### TCP-флаги в выводе tcpdump

При анализе TCP-трафика `tcpdump` отображает флаги в квадратных скобках. Важно различать одиночные флаги и их распространенные комбинации:

| Флаг | Обозначение | Значение | Описание |
| :--- | :--- | :--- | :--- |
| **SYN** | `[S]` | Synchronize | Запрос на установку соединения |
| **SYN-ACK** | `[S.]` | SYN + ACK | Подтверждение запроса и встречный запрос |
| **ACK** | `[.]` | Acknowledgment | Подтверждение получения данных/пакета |
| **PSH** | `[P]` | Push | Указание немедленно передать данные приложению |
| **PSH-ACK** | `[P.]` | PSH + ACK | Передача данных с подтверждением получения |
| **FIN** | `[F]` | Finish | Запрос на корректное завершение соединения |
| **FIN-ACK** | `[F.]` | FIN + ACK | Подтверждение закрытия и встречное закрытие |
| **RST** | `[R]` | Reset | Немедленный сброс соединения (ошибка/отказ) |
| **URG** | `[U]` | Urgent | Наличие срочных данных |
| **ECE** | `[W]` | ECN-Echo | Уведомление о перегрузке сети |
| **CWR** | `[E]` | Congestion Window Reduced | Ответ на уведомление о перегрузке |

### Формат вывода и оптимизация

- `-n`: не разрешать IP-адреса в доменные имена (исключает лишние DNS-запросы).
- `-nn`: не разрешать ни IP, ни номера портов (максимальная производительность).
- `-t`, `-tt`, `-tttt`: настройка отображения временных меток (Timestamp).

## Практические сценарии

### Базовое управление захватом

```bash
# Список доступных интерфейсов
sudo tcpdump -D
# → 1.eth0 [Up, Running, Connected]
# → 2.any (Pseudo-device that captures on all interfaces) [Up, Running]

# Захват на конкретном интерфейсе без разрешения имен
sudo tcpdump -i eth0 -nn
# → 12:00:01.123 IP 192.168.1.10.54321 > 8.8.8.8.53: 123+ A? google.com. (28)

# Ограничение количества пакетов
sudo tcpdump -i eth0 -c 5
```

### Сохранение и чтение дампов (.pcap)

```bash
# Запись трафика в бинарный файл (рекомендуемый способ)
sudo tcpdump -i eth0 -w capture.pcap

# Чтение из файла с фильтрацией
tcpdump -r capture.pcap -nn port 80
```

> **Важно:** Флаг `-w` сохраняет «сырые» пакеты. Перенаправление вывода `>` сохраняет только текст, что делает невозможным глубокий анализ в Wireshark.

### Фильтрация (BPF-выражения)

```bash
# По протоколу
sudo tcpdump -i eth0 icmp

# По хосту (источник или назначение)
sudo tcpdump -i eth0 host 1.1.1.1

# По порту
sudo tcpdump -i eth0 port 443

# Сложные фильтры (логические операторы and, or, not)
# Трафик SSH с конкретного IP
sudo tcpdump -i eth0 'host 192.168.1.10 and port 22'

# Трафик HTTP или HTTPS, исключая конкретный хост
sudo tcpdump -i eth0 '(port 80 or port 443) and not host 192.168.1.50'
```

### Анализ содержимого и проблем

```bash
# Просмотр данных в ASCII (полезно для HTTP, SMTP)
sudo tcpdump -i eth0 -A port 80

# Просмотр в HEX и ASCII (анализ бинарных протоколов)
sudo tcpdump -i eth0 -X port 53

# Поиск пакетов со сбросом соединения (RST)
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-rst != 0'

# Анализ DNS-запросов с максимальной детализацией
sudo tcpdump -i eth0 -vvv port 53
```

## Особенности диагностики

### Влияние Hardware Offloading

Современные сетевые карты (NIC) используют технологии разгрузки (Offloading), которые могут вводить в заблуждение при анализе трафика через `tcpdump`. Поскольку захват происходит на уровне ядра, вы видите пакеты такими, какими их видит операционная система, а не такими, какими они реально передаются «в провод».

#### Типичные артефакты

1.  **Исходящий трафик (TSO/GSO):** Ядро передает сетевой карте один большой пакет (до 64 КБ), который NIC сама нарежет на фрагменты по 1500 байт перед отправкой.
    - **В tcpdump:** Вы увидите гигантские исходящие пакеты (например, 30–60 КБ).
    - **Риск:** Ошибочный вывод о некорректном MTU или гигантских кадрах (Jumbo Frames).
2.  **Входящий трафик (LRO/GRO):** NIC или драйвер склеивают множество входящих пакетов в один большой «суперпакет» перед передачей в ядро.
    - **В tcpdump:** Вы увидите входящие пакеты, размер которых превышает MTU интерфейса.

#### Как получить «честную» картину

Для точной диагностики проблем с MTU или фрагментацией необходимо временно отключить механизмы оффлоуда:

```bash
# Просмотр текущего статуса оффлоудов
ethtool -k eth0 | grep -E "segmentation|receive"

# Отключение для диагностики
sudo ethtool -K eth0 tso off gso off lro off gro off

# Включение обратно
sudo ethtool -K eth0 tso on gso on gro on
```

Подробнее о механизмах разгрузки см. в **[Network Offloading](../../Networking/Concepts/offloading.md)**.

## Дополнительная информация

### Диагностика TCP Handshake

Для проверки процесса установки соединения (3-way handshake) анализируйте первые три пакета:

1. `[S]` (SYN) — клиент → сервер.
2. `[S.]` (SYN-ACK) — сервер → клиент (подтверждение + готовность).
3. `[.]` (ACK) — клиент → сервер (финальное подтверждение).

Если после `[S]` не следует `[S.]`, сервер недоступен или пакеты блокируются Firewall.

### Глоссарий

- **BPF (Berkeley Packet Filter):** технология фильтрации пакетов в ядре.
- **Payload:** полезная нагрузка пакета (данные приложения).
- **RTT (Round-Trip Time):** время круговой задержки, можно оценить по разнице времени между `SYN` и `SYN-ACK`.
- **SNI (Server Name Indication):** расширение TLS, позволяющее увидеть имя хоста в зашифрованном трафике (виден в HEX-выводе).
