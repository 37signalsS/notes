# ping

## Определения

**`ping`** (Packet Internet Groper) — утилита для проверки сетевого подключения между хостами. Работает на сетевом уровне OSI, используя ICMP Echo Request/Echo Reply.

## Основные концепции

### Принцип работы

1. Отправитель передаёт ICMP Echo Request получателю
2. Получатель отвечает ICMP Echo Reply
3. Измеряется **RTT (Round-Trip Time)** — время прохождения пакета туда и обратно

### Что подтверждает успешный ping

- Целевой хост доступен
- Между хостами существует маршрут
- ICMP не блокируется файрволами

### Ограничения

- **ICMP может блокироваться:** файрволы и хосты часто игнорируют ICMP Echo Request
- **Не гарантирует работу сервисов:** хост может отвечать на ping, но HTTP/SSH могут быть недоступны
- **Не показывает асимметричные проблемы:** ping не выявляет односторонние потери

### Основные метрики

| Метрика | Описание |
| :--- | :--- |
| RTT | Время прохождения пакета туда и обратно (мс) |
| Packet Loss | Процент потерянных пакетов |
| Jitter (mdev) | Вариация задержки между пакетами |
| TTL | Количество хопов до цели (уменьшается на 1 каждым маршрутизатором) |

## Практические сценарии

### Базовая проверка доступности

```bash
# Непрерывный пинг (Ctrl+C для остановки)
ping ya.ru

# Отправить 5 пакетов
ping -c 5 ya.ru

# С интервалом 3 секунды
ping -i 3 ya.ru
```

### Диагностика потерь пакетов

```bash
# 100 пакетов для статистики
ping -c 100 ya.ru

# Пример вывода:
# 100 packets transmitted, 97 received, 3% packet loss, time 9914ms
# rtt min/avg/max/mdev = 10.2/12.5/45.3/5.2 ms
```

| Результат | Вывод |
| :--- | :--- |
| loss 0%, rtt стабильный | Сеть в норме |
| loss >5% | Потери — перегрузка, faulty оборудование |
| Высокий mdev | Нестабильная задержка (jitter) |
| 100% loss | Хост недоступен или ICMP блокируется |

### Проверка DNS через ping

```bash
ping google.com
# PING google.com (142.250.185.206): 56 data bytes
```

Если виден IP в скобках — DNS работает. Ошибка «Name or service not known» — проблема с DNS (подробнее: **[Диагностика DNS](./dns/overview.md)**).

### Тестирование MTU

```bash
# Проверка MTU 1500 (1472 + 28 байт заголовков)
ping -c 4 -s 1472 -M do 8.8.8.8

# Если ошибка «Frag needed» — уменьшить размер
ping -c 4 -s 1400 -M do 8.8.8.8
```

**Расчёт:** `MTU = размер_пакета + 28` (IP + ICMP заголовки). Флаг `-M do` устанавливает DF (Don't Fragment).

### Указание интерфейса

```bash
# С конкретного интерфейса
ping -I eth1 ya.ru

# С IP-адреса источника
ping -I 192.168.1.100 ya.ru
```

### TTL-трассировка

```bash
# TTL=1: первый хоп
ping -t 1 ya.ru
```

> Для полноценной трассировки используйте **[traceroute/mtr](./traceroute_mtr.md)**.

### Flood ping (стресс-тест)

```bash
sudo ping -f ya.ru
```

> **Осторожно:** создаёт нагрузку на сеть и хост. Только в тестовых средах.

### Непрерывный мониторинг

```bash
# С временными метками
ping -D ya.ru
```

## Дополнительная информация

### Интерпретация TTL

| TTL (ответ) | ОС (начальное значение) |
| :--- | :--- |
| 64 | Linux/Unix (начальное 64) |
| 128 | Windows (начальное 128) |
| 255 | Сетевое оборудование (начальное 255) |

**Формула:** `Хопы = начальное_TTL - полученное_TTL`

**Пример:** TTL=117 → 128-117 = **11 хопов** (если цель Windows).

### ICMP-типы ping

| Тип | Код | Описание |
| :--- | :--- | :--- |
| 0 | 0 | Echo Reply |
| 8 | 0 | Echo Request |
| 3 | 0–15 | Destination Unreachable |
| 11 | 0–1 | Time Exceeded |

### Если ping не проходит

1. **Проверьте ARP-кэш:** `ip neigh show` — наличие MAC-адреса цели означает работоспособность L2
2. **Если ARP есть, но ping не работает:** файрвол блокирует ICMP (Windows по умолчанию блокирует, Linux — `iptables`/`ufw`)
3. **Если ARP отсутствует:** проблема маршрутизации, хосты в разных подсетях, физическое подключение

Подробный алгоритм диагностики — **[Порядок диагностики сетевых проблем](../../Networking/network_troubleshooting_order.md)**.

### Альтернативы ping

Для случаев, когда ICMP блокируется, используйте TCP/UDP-проверку портов: **[hping3 и tcping](../../../Networking/Troubleshooting/ping_alternatives.md)**, проверку доступности сервисов через **[curl](./curl_network_diagnostics.md)**, комбинированный анализ через **[mtr](./traceroute_mtr.md)**.
