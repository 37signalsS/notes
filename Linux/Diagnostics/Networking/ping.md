# `ping`

## Определения

**`ping`** (Packet Internet Groper) — базовая утилита для проверки сетевого подключения между хостами. Работает на сетевом уровне модели OSI, используя ICMP (Internet Control Message Protocol) пакеты типа **Echo Request** и **Echo Reply**.

## Основные концепции

### Принцип работы

1. Отправитель передаёт ICMP Echo Request пакет получателю
2. Получатель отвечает ICMP Echo Reply
3. Измеряется **RTT (Round-Trip Time)** — время прохождения пакета туда и обратно

### Что подтверждает успешный ping

- Целевой хост доступен в сети
- Между хостами существует работающий маршрут
- Фаерволы не блокируют ICMP-трафик

### Ограничения

- **ICMP может блокироваться:** Многие фаерволы и хосты игнорируют ICMP Echo Request из соображений безопасности
- **Не гарантирует работу сервисов:** Хост может отвечать на ping, но сервисы (HTTP, SSH) могут быть недоступны
- **Односторонние проблемы:** Ping не показывает асимметричные проблемы сети (когда трафик в одну сторону работает, в другую — нет)

### Основные метрики

- **RTT (Round-Trip Time):** Время прохождения пакета туда и обратно (мс)
- **Packet Loss:** Процент потерянных пакетов
- **Jitter:** Вариация задержки между пакетами
- **TTL (Time To Live):** Количество хопов до цели (уменьшается на 1 каждым маршрутизатором)

## Практические сценарии

### Базовая проверка доступности

```bash
# Отправлять пакеты до остановки (Ctrl+C)
ping ya.ru

# Отправить 5 пакетов и завершиться
ping -c 5 ya.ru

# С интервалом 3 секунды между пакетами
ping -i 3 ya.ru

# Быстрый пинг (0.2 секунды, требует root)
sudo ping -f ya.ru
```

### Диагностика потерь пакетов

```bash
# Отправить 100 пакетов для статистики
ping -c 100 ya.ru

# Пример вывода:
# 100 packets transmitted, 97 received, 3% packet loss, time 9914ms
# rtt min/avg/max/mdev = 10.2/12.5/45.3/5.2 ms
```

**Интерпретация:**

- **Packet loss > 0%:** Потери в сети (перегрузка, faulty оборудование)
- **Высокий mdev:** Нестабильная задержка (jitter)
- **Резкие скачки RTT:** Перегрузка канала или маршрутизаторов

### Тестирование MTU (Maximum Transmission Unit)

Определение максимального размера пакета без фрагментации:

```bash
# Тестировать MTU 1500 (стандарт Ethernet)
# 1472 байта данных + 28 байт заголовков = 1500
ping -c 4 -s 1472 -M do 8.8.8.8

# Если ошибка "Message too long", уменьшить размер
ping -c 4 -s 1400 -M do 8.8.8.8
```

**Флаги:**

- `-s <размер>`: Размер полезной нагрузки ICMP
- `-M do`: Установить флаг DF (Don't Fragment)

**Расчёт MTU:**

```
MTU = размер_пакета + 28 (IP + ICMP заголовки)
```

### Указание интерфейса

```bash
# Отправить ping с конкретного интерфейса
ping -I eth1 ya.ru

# С IP-адреса источника
ping -I 192.168.1.100 ya.ru
```

### Проверка маршрута (TTL-трассировка)

```bash
# TTL=1: первый хоп
ping -t 1 ya.ru

# TTL=5: пятый хоп (или ошибка раньше)
ping -t 5 ya.ru
```

> **Примечание:** Для полноценной трассировки используйте [`traceroute`](./traceroute_mtr.md) или [`mtr`](./traceroute_mtr.md).

### Непрерывный мониторинг

```bash
# Пинг с временными метками
ping -D ya.ru

# Звуковой сигнал при потере пакета (требует root)
sudo ping -a ya.ru

# Интервал 0.2 секунды для быстрого теста
sudo ping -i 0.2 ya.ru
```

### Диагностика DNS

```bash
# Если ping по имени не работает, проверить IP
ping 8.8.8.8          # Проверка связи
ping google.com       # Проверка DNS

# Видим IP в скобках → DNS работает
# PING google.com (142.250.185.206): 56 data bytes

# Ошибка "Name or service not known" → DNS не работает
```

> **Подробно:** См. [Диагностика DNS](./dns_diagnostics.md)

### Flood ping (стресс-тест)

```bash
# Максимальная скорость отправки (требует root)
sudo ping -f ya.ru

# Вывод: точечки — отправленные пакеты, backspace — полученные
# .^..^..^..^...
```

> **Осторожно:** Может создавать нагрузку на сеть и целевой хост. Используйте только в тестовых средах.

### Ping с размером пакета больше MTU

```bash
# Пакет больше MTU должен фрагментироваться
ping -s 2000 ya.ru

# Если флаг DF установлен, будет ошибка
ping -s 2000 -M do ya.ru
# From 192.168.1.1 icmp_seq=1 Frag needed and DF set (mtu=1500)
```

## Дополнительная информация

### Интерпретация TTL

Значение TTL в ответе указывает на ОС хоста:

| TTL (ответ) | ОС (начальное значение) |
| :--- | :--- |
| 64 | Linux/Unix (начальное 64) |
| 128 | Windows (начальное 128) |
| 255 | Сетевое оборудование (начальное 255) |

**Формула:**

```
Хопы = начальное_TTL - полученное_TTL
```

### ICMP типы и коды

| Тип | Код | Описание |
| :--- | :--- | :--- |
| 0 | 0 | Echo Reply (ответ) |
| 3 | 0–15 | Destination Unreachable (недоступен) |
| 8 | 0 | Echo Request (запрос) |
| 11 | 0–1 | Time Exceeded (превышено время) |

### Типичные проблемы и решения

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **100% packet loss** | Хост недоступен, ICMP блокируется | Проверить маршрут (`traceroute`), попробовать `tcping` |
| **Высокий RTT (>100ms)** | Перегрузка сети, география | Проверить маршрут (`mtr`), найти узкое место |
| **Packet loss >5%** | Потери в сети | Проверить оборудование, кабель, Wi-Fi сигнал |
| **DNS resolution failed** | Проблема с DNS | Пинговать IP, проверить [`/etc/resolv.conf`](../../Networking/Concepts/dns_client.md) |
