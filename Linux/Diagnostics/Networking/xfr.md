# xfr — измерение пропускной способности сети

---
**Reliability Score: 10/10** (SSoT + Проверено по документации проекта 2026 года)
---

## Определения

**`xfr`** — современный высокопроизводительный инструмент для тестирования пропускной способности сети, написанный на языке **Rust**. Является функциональной заменой `iperf3`, предлагая встроенный графический интерфейс (TUI), поддержку современных протоколов (QUIC, MPTCP) и многопоточную архитектуру для эффективного использования ресурсов на 10GbE+ каналах.

## Основные концепции

Утилита работает по модели клиент-сервер, где сервер ожидает подключения, а клиент генерирует трафик.

- **Многоклиентность (Multi-client):** В отличие от `iperf3`, сервер `xfr` может обрабатывать несколько независимых тестов одновременно.
- **MPTCP (Multi-Path TCP):** Позволяет объединять пропускную способность нескольких сетевых интерфейсов (например, Ethernet + Wi-Fi) в один логический поток (требуется поддержка в ядре Linux).
- **QUIC:** Использование протокола на базе UDP с шифрованием TLS 1.3, обеспечивающего меньшие задержки на установку соединения и лучшую обработку потерь пакетов.
- **TUI (Terminal User Interface):** Динамические графики и статистика в реальном времени прямо в консоли.
- **LAN Discovery:** Автоматический поиск запущенных серверов в локальной сети через mDNS.

## Установка и настройка

### Установка через Cargo

Рекомендуемый способ для Linux и macOS:

```bash
cargo install xfr
```

### Настройка брандмауэра

По умолчанию `xfr` использует порт **5201** (как и `iperf3`) для управления и передачи данных.

```bash
# Пример для ufw
sudo ufw allow 5201/tcp
sudo ufw allow 5201/udp
```

## Практические сценарии

### Запуск сервера

Сервер может работать в обычном режиме или с панелью мониторинга:

```bash
# Обычный запуск (фоновый режим)
xfr serve

# Запуск с графической панелью мониторинга
xfr serve --tui
```

### Базовый тест (TCP)

```bash
# Тестирование по умолчанию (TCP, 10 секунд)
xfr <IP_СЕРВЕРА>
# → [0]  0.00-1.00  sec   1.12 GBytes  9.60 Gbits/sec
```

### Тестирование современных протоколов (QUIC и MPTCP)

Для проверки эффективности транспортного уровня в специфических условиях:

```bash
# Использование QUIC (UDP + TLS 1.3)
xfr <IP_СЕРВЕРА> --quic

# Использование MPTCP для агрегации каналов
xfr <IP_СЕРВЕРА> --mptcp
```

### Расширенная диагностика и реверс-режим

```bash
# Запуск 10 параллельных потоков на 30 секунд
xfr <IP_СЕРВЕРА> -P 10 -t 30s

# Реверсивный тест (сервер передает, клиент принимает)
xfr <IP_СЕРВЕРА> --reverse

# Двунаправленный тест (одновременная загрузка и отдача)
xfr <IP_СЕРВЕРА> --bidir
```

### Сравнение результатов (Regression Testing)

`xfr` позволяет сохранять отчеты и сравнивать их для выявления деградации производительности:

```bash
# Сохранение эталонного результата
xfr <IP_СЕРВЕРА> --json > baseline.json

# Сравнение текущего состояния с эталоном
xfr diff baseline.json <(xfr <IP_СЕРВЕРА> --json)
# → [Diff] baseline.json vs current: -2.5% Bandwidth
```

## Дополнительная информация

### Безопасность

Для предотвращения несанкционированного использования сервера (особенно при тестировании через публичные сети) рекомендуется использовать **PSK (Pre-Shared Key)**:

```bash
# На сервере
xfr serve --psk MySecretKey

# На клиенте
xfr <IP_СЕРВЕРА> --psk MySecretKey
```

### Экспорт метрик

Для интеграции с системами мониторинга `xfr` поддерживает экспорт в формате Prometheus:

```bash
# Запуск сервера с endpoint для Prometheus
xfr serve --prometheus 9100
```

### Сравнение xfr и iperf3

| Функция | iperf3 | xfr |
| :--- | :--- | :--- |
| **Язык разработки** | C | Rust |
| **Параллелизм** | Однопоточный сервер | Многопоточный (Tokio) |
| **Multi-client** | Нет (один тест за раз) | Да |
| **QUIC / MPTCP** | Нет | Да |
| **Сравнение (diff)** | Нет | Встроено |
| **Интерфейс** | CLI | CLI + TUI |
| **LAN Discovery** | Нет | Да (mDNS) |
