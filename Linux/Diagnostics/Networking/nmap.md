# nmap (Network Mapper)

---
**Reliability Score: 10/10** (SSoT + Проверено на боевых сценариях 2026 года)
---

## Определения

**`nmap`** (Network Mapper) — индустриальный стандарт и мощнейшая утилита с открытым исходным кодом для исследования сетей, сканирования портов и аудита безопасности. Она позволяет обнаруживать активные хосты, определять открытые порты, версии запущенных сервисов и типы операционных систем, формируя полную карту сетевой инфраструктуры.

## Основные концепции

`nmap` работает путем отправки специально сформированных IP-пакетов и анализа ответов от целевых узлов.

- **Обнаружение хостов:** определение того, какие IP-адреса активны в сети.
- **Сканирование портов:** выявление открытых TCP и UDP портов.
- **Определение версий (Version Detection):** опрос портов для идентификации конкретных приложений и их версий.
- **Определение ОС (OS Fingerprinting):** анализ тонких различий в реализации стека TCP/IP для определения типа и версии операционной системы.
- **NSE (Nmap Scripting Engine):** мощный скриптовый движок на языке Lua для автоматизации задач от сетевого аудита до поиска уязвимостей.

### Состояния портов

Интерпретация ответов `nmap` критически важна для понимания сетевой топологии и настроек брандмауэра:

| Состояние | Описание | Ответ от хоста |
| :--- | :--- | :--- |
| **open** | Порт принимает соединения. Служба активно слушает. | SYN/ACK (TCP) или ответ службы (UDP). |
| **closed** | Порт доступен, но за ним нет слушающей службы. | RST (TCP) или ICMP Port Unreachable (UDP). |
| **filtered** | Пакеты блокируются брандмауэром. Состояние неизвестно. | Нет ответа или ICMP Prohibited. |
| **unfiltered** | Порт доступен, но состояние (открыт/закрыт) не определено. | Только при ACK-сканировании (`-sA`). |
| **open\|filtered** | Нет ответа; порт либо открыт, либо защищен фильтром. | Типично для UDP или некоторых типов TCP (FIN, Null, Xmas). |

### Режимы сканирования

| Флаг | Тип | Особенности |
| :--- | :--- | :--- |
| `-sS` | **SYN Scan** | "Полуоткрытое" сканирование. Быстрое, не завершает TCP-рукопожатие. Стандарт для Stealth-режима. |
| `-sT` | **Connect Scan** | Использует системный вызов `connect()`. Полное рукопожатие. Оставляет записи в логах приложений. |
| `-sU` | **UDP Scan** | Медленное и менее надежное из-за отсутствия подтверждений на уровне протокола. Важно для DNS (53), DHCP (67/68), SNMP (161). |
| `-sA` | **ACK Scan** | Не определяет открытые порты, но используется для выявления правил фильтрации брандмауэра (Stateful vs Stateless). |
| `-sn` | **Ping Scan** | Отключает сканирование портов. Используется для инвентаризации активных хостов в подсети. |

## Практические сценарии

### Инвентаризация сети (Host Discovery)

Быстрый поиск живых хостов в подсети без сканирования портов:

```bash
# Обнаружение хостов в локальной сети
nmap -sn 192.168.1.0/24
# → Nmap scan report for 192.168.1.5
# → Host is up (0.00052s latency).
```

### Детальное сканирование целевого узла

Сочетание определения портов, версий и ОС:

```bash
# Агрессивное сканирование (включает -sV, -O, -sC и traceroute)
sudo nmap -A 10.0.0.15
# → 22/tcp  open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.1 (Ubuntu Linux; protocol 2.0)
# → 80/tcp  open  http    Apache httpd 2.4.52 ((Ubuntu))
# → OS details: Linux 5.0 - 5.14
```

### Сканирование IPv6

```bash
# Сканирование IPv6 адреса
nmap -6 2001:db8:85a3::8a2e:370:7334
```

### Оптимизация производительности (Тайминги)

Ускорение или замедление сканирования для обхода IDS или экономии времени:

```bash
# Т0 (параноидальный) ... Т5 (агрессивный)
# T4 рекомендуется для быстрых и надежных сетей
nmap -T4 192.168.1.1

# Ограничение скорости пакетов (полезно для слабых каналов)
nmap --min-rate 100 192.168.1.1
```

### Обход средств защиты (Firewall Evasion)

Техники для преодоления фильтрации и сокрытия активности:

```bash
# Фрагментация пакетов (разбиение заголовков)
nmap -f 192.168.1.1

# Подмена источника (Decoy) — хост скрывается среди реальных или фиктивных адресов
nmap -D 192.168.1.5,192.168.1.10,ME 192.168.1.1

# Изменение размера MTU
nmap --mtu 24 192.168.1.1
```

### Использование скриптов NSE

NSE позволяет выполнять глубокий аудит и поиск уязвимостей:

```bash
# Поиск известных уязвимостей (категория vuln)
nmap --script vuln 192.168.1.100

# Брутфорс паролей для конкретной службы (категория brute)
nmap -p 22 --script ssh-brute 192.168.1.100

# Получение информации из HTTP-заголовков
nmap -p 80 --script http-headers 192.168.1.0/24
```

### Форматы вывода и логирование

Для последующего анализа или автоматизации (например, через Python/Grep):

```bash
# Сохранение во всех основных форматах (нормальный, XML, grepable)
nmap -oA scan_results 192.168.1.1

# XML-формат для импорта в Zenmap или Metasploit
nmap -oX output.xml 192.168.1.1
```

## Дополнительная информация

### Технические нюансы

- **Права Root:** Для SYN-сканирования (`-sS`), определения ОС (`-O`) и большинства техник обхода защиты требуются привилегии суперпользователя, так как `nmap` должен формировать пакеты "вручную" через Raw Sockets.
- **UDP-сканирование:** Из-за особенностей протокола (отсутствие обязательного ответа), UDP-сканирование на порядок медленнее TCP и часто дает результат `open|filtered`. Для повышения точности используйте версию службы (`-sV`).
- **Тайминги:** Агрессивные режимы (`-T4`, `-T5`) могут перегрузить стек TCP/IP на старом оборудовании или встроенных системах (IoT), что приведет к ложноотрицательным результатам.
