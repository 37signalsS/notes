# nmap (Network Mapper)

## Определения

**`nmap`** (Network Mapper) — индустриальный стандарт и мощнейшая утилита с открытым исходным кодом для исследования сетей, сканирования портов и аудита безопасности. Она позволяет обнаруживать активные хосты, определять открытые порты, версии запущенных сервисов и типы операционных систем, формируя полную карту сетевой инфраструктуры.

**Архитектура и принцип работы:** `nmap` работает на уровне сетевого стека ОС, используя **raw sockets** для формирования кастомных IP-пакетов (при наличии root-прав) или системный вызов `connect()` в пользовательском пространстве (без root). Это позволяет контролировать каждый флаг TCP-заголовка, время жизни пакета (TTL) и порядок отправки, что критически важно для стелс-сканирования и точной идентификации сервисов.

## Основные концепции

`nmap` работает путем отправки специально сформированных IP-пакетов и анализа ответов от целевых узлов.

- **Обнаружение хостов (Host Discovery):** определение того, какие IP-адреса активны в сети.
- **Сканирование портов:** выявление открытых TCP и UDP портов.
- **Определение версий (Version Detection):** опрос портов для идентификации конкретных приложений и их версий.
- **Определение ОС (OS Fingerprinting):** анализ тонких различий в реализации стека TCP/IP для определения типа и версии операционной системы.
- **NSE (Nmap Scripting Engine):** мощный скриптовый движок на языке Lua для автоматизации задач от сетевого аудита до поиска уязвимостей.

### Принцип работы на уровне пакетов

Понимание механизмов `nmap` необходимо для корректной интерпретации результатов и выбора режима сканирования:

1. **Raw Socket Mode (root-режим):** `nmap` формирует пакеты вручную, устанавливая флаги TCP (SYN, ACK, FIN, URG, PSH) без участия ядра в установке полного соединения. В SYN-сканировании (`-sS`) целевой хост получает SYN, отвечает SYN/ACK (порт открыт) или RST (порт закрыт). `nmap` отправляет RST в ответ на SYN/ACK, не завершая трехэтапное рукопожатие. Это делает сканирование быстрым и незаметным в логах приложений.
2. **Connect Scan (`-sT`):** Использует стандартный `connect()` syscall. Ядро завершает полное TCP-рукопожатие. Этот метод оставляет записи в логах большинства демонов (auth.log, application logs), но работает без привилегий.
3. **UDP-сканирование (`-sU`):** Отправляет пустой UDP-датаграммой на целевой порт. Отсутствие ответа означает `open|filtered`; ICMP Port Unreachable (Code 3) означает `closed`. Скорость severely ограничена таймаутами на ICMP-ответы в большинстве ОС (Linux по умолчанию ограничивает ICMP-ошибки).
4. **ACK-сканирование (`-sA`):** Используется для определения правил файрвола. Открытый порт отвечает RST на ACK-пакет без установленного соединения; `filtered` — нет ответа или ICMP Prohibited.

### Состояния портов

Интерпретация ответов `nmap` критически важна для понимания сетевой топологии и настроек брандмауэра:

| Состояние | Описание | Ответ от хоста |
| :--- | :--- | :--- |
| **open** | Порт принимает соединения. Служба активно слушает. | SYN/ACK (TCP) или ответ службы (UDP). |
| **closed** | Порт доступен, но за ним нет слушающей службы. | RST (TCP) или ICMP Port Unreachable (UDP). |
| **filtered** | Пакеты блокируются брандмауэром. Состояние неизвестно. | Нет ответа или ICMP Prohibited (административно запрещено). |
| **unfiltered** | Порт доступен, но состояние (открыт/закрыт) не определено. | Только при ACK-сканировании (`-sA`). |
| **open\|filtered** | Нет ответа; порт либо открыт, либо защищен фильтром. | Типично для UDP или некоторых типов TCP (FIN, Null, Xmas). |

### Режимы сканирования

| Флаг | Тип | Особенности |
| :--- | :--- | :--- |
| `-sS` | **SYN Scan** | "Полуоткрытое" сканирование. Быстрое, не завершает TCP-рукопожатие. Стандарт для Stealth-режима. |
| `-sT` | **Connect Scan** | Использует системный вызов `connect()`. Полное рукопожатие. Оставляет записи в логах приложений. |
| `-sU` | **UDP Scan** | Медленное и менее надежное из-за отсутствия подтверждений. Важно для DNS (53), DHCP (67/68), SNMP (161). |
| `-sA` | **ACK Scan** | Используется для выявления правил фильтрации брандмауэра (Stateful vs Stateless). |
| `-sn` | **Ping Scan** | Отключает сканирование портов. Используется для инвентаризации активных хостов. |
| `-sF` / `-sN` / `-sX` | **FIN / Null / Xmas** | Обходят неstateful-файрволы. Используют нестандартные комбинации флагов TCP. |
| `-sI` | **Idle Scan** | Сканирование через "зомби"-хост. Полностью скрывает IP сканера. Требует подходящего зомби-хоста с предсказуемым IP ID. |
| `-f` | **Fragment Scan** | Разбивает пакеты на 8-байтовые фрагменты для обхода IDS/IPS и файрволов, не инспектирующих фрагментированный трафик. |

## Тайминги и производительность

### Шаблоны таймингов (Timing Templates)

`nmap` предоставляет 6 встроенных шаблонов, управляющих параллелизмом, таймаутами и задержками:

| Шаблон | Параметр | Характеристики | Сценарий использования |
| :--- | :--- | :--- | :--- |
| `-T0` | paranoid | Интервал 5 минут между пакетами, 1 параллельное соединение. | IDS-обход, максимальная скрытность. |
| `-T1` | sneaky | Интервал 15 секунд, 1 параллельное соединение. | Стелс-сканирование через busy IDS. |
| `-T2` | polite | Интервал 0.4 секунды, 1 параллельное соединение. | Медленное сканирование, минимизация нагрузки. |
| `-T3` | normal | По умолчанию. Адаптивные таймауты. | Стандартное использование. |
| `-T4` | aggressive | max-retries 3, timeout 500ms, 512 параллельных хостов. | Быстрые сканы в доверенных сетях. |
| `-T5` | insane | max-retries 1, timeout 250ms, 2048 параллельных хостов. | Сканирование огромных сетей с потерей точности. |

### Ручная настройка производительности

Для больших сетей и CI/CD-пайплайнов предпочтительно явное указание параметров вместо шаблонов:

```bash
# Параллельные хосты и таймауты
nmap --min-hostgroup 256 --max-hostgroup 1024 \
     --min-parallelism 64 --max-parallelism 256 \
     --host-timeout 30m \
     --max-retries 2 \
     --initial-rtt-timeout 500ms --max-rtt-timeout 2000ms \
     10.0.0.0/16
```

### Управление скоростью и лимитами

```bash
# Ограничение скорости для обхода rate-limit (например, в облачных firewall)
nmap --max-rate 50 10.0.0.0/24

# Минимальный интервал между пакетами
nmap --min-rate 10 10.0.0.0/24
```

## Практические сценарии

### Выбор целей и исключений

```bash
# Сканирование списка из файла
nmap -iL targets.txt

# Сканирование сети, исключая конкретные IP
nmap 192.168.1.0/24 --exclude 192.168.1.1,192.168.1.254
```

### Выбор портов для сканирования

```bash
# Сканирование конкретных портов
nmap -p 22,80,443 192.168.1.1

# Сканирование диапазона портов
nmap -p 1-1024 192.168.1.1

# Сканирование ВСЕХ портов (65535)
nmap -p- 192.168.1.1

# Сканирование 100 самых популярных портов
nmap --top-ports 100 192.168.1.1

# Быстрое сканирование (100 портов из nmap-services)
nmap -F 192.168.1.1
```

### Инвентаризация сети (Host Discovery)

Быстрый поиск живых хостов в подсети:

```bash
# Обнаружение хостов (ARP-запросы в локальной сети)
nmap -sn 192.168.1.0/24
```

**Сканирование в segmented сетях (VLANs, jump hosts):**

```bash
# Сканирование через jump host (через SSH)
nmap -Pn -sT -p 22,80,443 --source-port 53 192.168.2.0/24 \
  --route-dst 192.168.2.50 --traceroute

# Обнаружение хостов без ARP (через VPN/маршрутизатор)
nmap -sn -PE -PP -PM 10.0.0.0/24
```

### Детальное сканирование целевого узла

```bash
# Агрессивное сканирование (версии, ОС, скрипты, traceroute)
sudo nmap -A 10.0.0.15

# Определение версий с максимальной интенсивностью (0-9)
nmap -sV --version-intensity 9 10.0.0.15
```

**Сопоставление версий и CVE:**

```bash
# Экспорт в XML для последующего сопоставления с базой CVE
sudo nmap -sV --script vuln -oX scan_report.xml 10.0.0.15

# Быстрый поиск уязвимостей (только скрипты vuln)
sudo nmap --script vuln -p 22,80,443 10.0.0.15
```

### Скриптовый движок NSE

Категории скриптов: `auth`, `broadcast`, `default`, `discovery`, `dos`, `exploit`, `external`, `fuzzer`, `intrusive`, `malware`, `safe`, `version`, `vuln`.

```bash
# Запуск скриптов по умолчанию
nmap -sC 192.168.1.1

# Поиск уязвимостей
nmap --script vuln 192.168.1.100

# Помощь по конкретному скрипту
nmap --script-help http-enum

# Поиск HTTP-директорий и файлов
nmap --script http-enum 192.168.1.100
```

**NSE для задач SRE:**
```bash
# Проверка конфигурации SMB
nmap --script smb-security-mode 192.168.1.100

# Обнаружение DHCP-серверов в сети
sudo nmap --script broadcast-dhcp-discover

# Проверка SSL-конфигурации
nmap --script ssl-enum-ciphers -p 443 192.168.1.100
```

### Оптимизация и обход защиты

```bash
# Шаблоны таймингов (T0 - параноидальный, T5 - агрессивный)
nmap -T4 192.168.1.1

# Обход фильтрации через подмену источника (Decoy)
nmap -D RND:10 192.168.1.1

# Использование конкретного интерфейса и IP
nmap -e eth0 -S 10.0.0.1 192.168.1.1
```

### Продвинутая диагностика

```bash
# Показать причину состояния порта (почему open или filtered)
nmap --reason 192.168.1.1

# Отслеживание каждого отправленного/полученного пакета
nmap --packet-trace 192.168.1.1
```

### Форматы вывода

```bash
# Сохранение во всех форматах (scan.nmap, scan.xml, scan.gnmap)
nmap -oA scan_result 192.168.1.1

# Вывод в XML для анализа сторонними инструментами
nmap -oX report.xml 192.168.1.1
```

### DevOps/SRE практические сценарии

#### Сценарий 1: Сканирование в Docker/Podman

Сканирование из контейнера требует доступа к хостовой сети:

```bash
# Сканирование хоста из контейнера (--network host)
docker run --rm --network host instrumentisto/nmap -sn 192.168.1.0/24

# Сканирование внешней сети из Podman (масочная сеть)
podman run --rm --net=host alpine:latest nmap -sT -p 22,80 192.168.1.0/24
```

**Важно:** При использовании `--network host` контейнер имеет прямой доступ к сетевым интерфейсам хоста. В противном случае NAT и isolate сеть контейнера исказят результаты сканирования.

#### Сценарий 2: Compliance и hardening baseline

Регулярный аудит открытых портов для соответствия политикам безопасности:

```bash
# Эталонный список разрешенных портов
ALLOWED_PORTS="22,80,443,9100"

# Сканирование и извлечение открытых портов
OPEN_PORTS=$(sudo nmap -sT -p- --host-timeout 5m server01 | \
  awk '/^[0-9]+\/tcp/ {print $1}' | cut -d'/' -f1 | tr '\n' ',' | sed 's/,$//')

# Сравнение с эталоном
if [ "$OPEN_PORTS" != "$ALLOWED_PORTS" ]; then
  echo "ALERT: Unexpected ports detected on server01"
  echo "Expected: $ALLOWED_PORTS"
  echo "Actual:   $OPEN_PORTS"
  # Отправка в SIEM/alertmanager
fi
```

#### Сценарий 3: Валидация изменений firewall

Перед и после применения правил файрвола для подтверждения корректности:

```bash
# Baseline (до изменений)
sudo nmap -sS -p 22,80,443,8080,3306 prod-web-01 -oA baseline

# Применить изменения (например, ufw allow 8080/tcp)

# Post-change (после изменений)
sudo nmap -sS -p 22,80,443,8080,3306 prod-web-01 -oA post_change

# Сравнение
diff <(grep "open" baseline.nmap | awk '{print $1, $2}') \
     <(grep "open" post_change.nmap | awk '{print $1, $2}')
```

#### Сценарий 4: Scheduled мониторинг в CI/CD

Интеграция с GitHub Actions или GitLab CI для проверки развертывания:

```yaml
# .github/workflows/network-validation.yml
- name: Validate exposed ports
  run: |
    sudo nmap -sT -p 3000,8080,9090 ${{ vars.STAGING_HOST }} | \
    tee scan_report.txt
    grep -E "3000/tcp|8080/tcp|9090/tcp" scan_report.txt | grep -q "open"
```

#### Сценарий 5: Интеграция с Prometheus

Экспорт результатов сканирования в Prometheus-совместимый формат для исторического анализа:

```bash
# Сканирование и преобразование в metrics
nmap -p 22,80,443,9100 -oG - 192.168.1.0/24 | \
  awk '/\/open/ {print "nmap_port_state{host=\"" $2 "\",port=\"" $3 "\"} 1"} \
       /\/closed/ {print "nmap_port_state{host=\"" $2 "\",port=\"" $3 "\"} 0"}' \
  > nmap_metrics.prom
```

#### Сценарий 6: Сканирование с привязкой к CPU и NUMA

На высоконагруженных системах для стабильности таймингов:

```bash
# Привязка к конкретному CPU core
sudo nmap --min-parallelism 256 --max-parallelism 512 \
  --min-rate 500 --max-rate 1000 \
  -p 1-65535 10.0.0.0/24 &

# Привязка через taskset
taskset -c 0-3 sudo nmap -sS -p- --max-rate 2000 10.0.0.50

# Отключение irqbalance для стабильности (временно)
sudo systemctl stop irqbalance
```

## Интерпретация результатов

### Анализ версий сервисов

При запуске `-sV` `nmap` отправляет серию probe-запросов и сравнивает ответы с базой `version-mapping`. Уровень `9` (максимальный) увеличивает точность за счет большего количества запросов, но замедляет сканирование и повышает заметность.

```bash
# Вероятностное определение версии
sudo nmap -sV -p 22 192.168.1.1
# → 22/tcp open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.1 (Ubuntu Linux; protocol 2.0)
# Confidence: 100% — точное совпадение.
```

### Анализ определения ОС

OS Fingerprinting основан на анализе 12+ параметров TCP/IP стека:

- **TCP Initial Sequence Number (ISN):** Алгоритм генерации начального номера последовательности.
- **TCP Window Size:** Начальный размер окна и его динамика.
- **IP TTL:** Время жизни пакета по умолчанию.
- **IP DF (Don't Fragment):** Наличие флага DF по умолчанию.
- **TCP Options:** Поддерживаемые опции (MSS, SACK, Window Scale, Timestamp).
- **ICMP response:** Поведение на ICMP-запросы.

```bash
sudo nmap -O 192.168.1.1
# → OS details: Linux 5.4 - 5.15
# → OS CPE: cpe:/o:linux:linux_kernel:5
# → Aggressive OS guesses: Linux 5.4 - 5.15 (95%)
```

### Отличия open от filtered

| Паттерн | Вероятная причина |
| :--- | :--- |
| `filtered` на все порты | Хостовый файрвол (DROP), сетевой экран, несуществующий хост |
| `open|filtered` (UDP) | Порт открыт и не отвечает, или заблокирован |
| `open|filtered` (TCP FIN/NULL/Xmas) | Stateful firewall отбрасывает нестандартные пакеты |
| `unfiltered` (ACK) | Порт доступен, но правило stateful блокирует SYN |

## Типичные проблемы и решения

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Все порты `filtered` | Файрвол блокирует SYN/ACK пакеты | Использовать `-sT` (Connect), `-Pn` для обхода ICMP блокировки |
| UDP сканирование слишком медленное | Ограничение ICMP rate-limit в Linux | `--max-retries 1`, `--host-timeout 10m`, `nmap -sS` для TCP сначала |
| Требуется root, но нет прав | Raw sockets требуют CAP_NET_RAW | `sudo` или `setcap cap_net_raw+ep $(which nmap)` |
| Неточное определение ОС | Сканирование через NAT/VPN, цельный firewall | Использовать `--osscan-guess`, увеличить `--max-os-tries` |
| Сканирование тормозит | Высокий RTT, потеря пакетов | `--max-rtt-timeout 3000ms --initial-rtt-timeout 1000ms` |
| ICMP заблокирован | Хостовой firewall запрещает echo request | Использовать `-PE` (ICMP echo), `-PP` (ICMP timestamp), `-PM` (ICMP netmask request) |
| Сканирование IPv6 не работает | `nmap` собран без IPv6 поддержки | Убедиться в наличии `-6` флага, или собрать с `--enable-ipv6` |
| Masscan/Nmap конфликт | Два сканера на одном интерфейсе | Использовать разные интерфейсы (`-e`) или `--send-eth` |

## Дополнительная информация

### Технические нюансы

- **Права Root:** Требуются для операций с Raw Sockets (`-sS`, `-O`, `-sU`, обход FW). Без root используется `-sT` (Connect scan).
- **UDP-сканирование:** Крайне медленное из-за лимитов ICMP-ответов в ОС. Используйте `-sV`, чтобы заставить nmap отправить запрос приложения и подтвердить `open`.
- **Zenmap:** Официальный графический интерфейс (GUI) для Nmap, полезен для визуализации топологии сети.

### Edge Cases и ограничения

- **IPv6:** Сканирование IPv6 требует поддержки в ОС и утилите (`-6`). NDP (Neighbor Discovery Protocol) заменяет ARP, что влияет на host discovery.
- **Сканирование через NAT/VPN:** OS fingerprinting ненадежен за NAT из-за модификации TTL и TCP parameters шлюзом.
- **IDS/IPS:** Фрагментация (`-f`) и Decoy (`-D`) могут обойти простые системы обнаружения, но современные IDS (Snort, Suricata) с reassembly их распознают.
- **Высокоскоростные сети (10/40/100GbE):** Для портов выше 10GbE используйте `--min-rate` и `--max-hostgroup` для управления скоростью, иначе `nmap` может пропустить ответы из-за переполнения очереди.
- **SO_REUSEPORT и параллелизм:** На системах с множеством CPU cores `nmap` эффективно использует параллелизм. Для сканирования одного хоста параллелизм не дает эффекта; используйте `--min-parallelism` для сетей.
