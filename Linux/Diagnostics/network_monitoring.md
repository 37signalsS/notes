# Мониторинг сети

## Обзор сетевых утилит

### ss (Socket Statistics)

Современная замена `netstat`. Показывает информацию о сокетах (сетевых соединениях, слушающих портах).

`ss` (socket statistics) — это современная консольная утилита в Linux, которая является более быстрой и мощной альтернативой `netstat`. Она используется для вывода информации о сокетах.

Основные опции:

*   **`ss -t`**: Показывает только TCP-сокеты.
*   **`ss -u`**: Показывает только UDP-сокеты.
*   **`ss -a`**: Показывает все сокеты (LISTENING и NOT LISTENING).
*   **`ss -l`**: Показывает только LISTENING сокеты.
*   **`ss -n`**: Не разрешает имена служб и хостов.
*   **`ss -p`**: Показывает процесс, который использует сокет.
*   **`ss -e`**: Показывает расширенную информацию.
*   **`ss -s`**: Выводит сводную статистику по сокетам.

Пример команды для просмотра всех TCP-соединений, не разрешая имена, с указанием процессов:

```bash
ss -tlnp
```

Пример вывода:

```
Netid State    Recv-Q Send-Q Local Address:Port  Peer Address:Port
tcp   LISTEN   0      128    0.0.0.0:80          0.0.0.0:*      users:(("apache2",pid=1234,fd=5))
tcp   ESTAB    0      0      192.168.1.10:80     192.168.1.1:54321 users:(("apache2",pid=1235,fd=6))
```

При подключении к веб-серверу (например, Apache на порту 80), можно наблюдать изменения в состояниях соединений с помощью `ss` (или `netstat`).

1.  Когда веб-сервер запущен, `ss -tln` покажет его в состоянии `LISTEN` на порту 80.
2.  При открытии веб-страницы в браузере и обновлении `ss -tnp`, можно увидеть новые записи:
    *   Соединения в состоянии `SYN_SENT` (от клиента) или `SYN_RECEIVED` (на сервере), затем `ESTABLISHED`.
    *   После завершения обмена данными и закрытия соединения появятся состояния вроде `FIN_WAIT1`, `FIN_WAIT2`, `CLOSE_WAIT`, `TIME_WAIT`, отражающие процесс корректного завершения TCP-сессии.

### nmap (Network Mapper)

- `nmap scanme.nmap.org`: Быстрое сканирование популярных портов.
- `nmap -p 80 192.168.1.1`: Проверить TCP-порт 80.
- `nmap -sV 192.168.1.1`: Определить версии служб на открытых портах.


### ping

Отправляет ICMP-запросы для проверки доступности хоста и измерения задержки.
- `ping -c 5 ya.ru`: Отправить 5 пакетов.
- **Тестирование MTU:** `ping -c 4 -s 1472 -M do 8.8.8.8`.

### traceroute и mtr

Показывают маршрут (последовательность маршрутизаторов), по которому сетевые пакеты следуют до хоста назначения.
- `traceroute ya.ru`: Трассировка маршрута.
- `mtr ya.ru`: Объединяет `ping` и `traceroute`, показывая статистику по каждому узлу в реальном времени.

**`traceroute`** помогает определить, на каком узле (хопе) на пути к цели возникают задержки или потери трафика.

```bash
# Стандартная трассировка до хоста
traceroute example.com

# Полезные опции:
# -n: не разрешать IP-адреса в имена (ускоряет процесс)
# -T: использовать TCP-пакеты вместо ICMP (помогает обходить некоторые файрволы)
# -p 80: указать порт назначения (например, 80 для HTTP)
traceroute -n -T -p 80 example.com
```

**`mtr` (My Traceroute)** — это улучшенная версия `traceroute`, которая объединяет функциональность `ping` и `traceroute` и предоставляет статистику в реальном времени.

```bash
mtr example.com
```
`mtr` продолжает работать, постоянно обновляя данные о задержках и потерях на каждом хопе, что делает его гораздо более информативным для выявления нестабильных участков сети.

### tcpdump

Поскольку `tcpdump` взаимодействует напрямую с ядром операционной системы для перехвата пакетов, для его работы требуются привилегии суперпользователя.

*   **Запуск с `sudo`:**
    ```bash
    sudo tcpdump -i <interface_name>
    ```
    Используйте `sudo`, если ваш пользователь имеет соответствующие права.
*   **Переключение на пользователя `root`:**
    ```bash
    sudo -i
    tcpdump -i <interface_name>
    ```
    Этот метод удобен для длительной работы, чтобы не вводить `sudo` постоянно.

*   **Захват и вывод на экран (базовый):**
    ```bash
    sudo tcpdump -i <interface_name>
    ```
    Эта команда будет выводить все проходящие пакеты через указанный интерфейс. Для остановки используйте `Ctrl+C`.

*   **Просмотр доступных сетевых интерфейсов:**
    ```bash
    sudo tcpdump -D
    ```
    Выведет список всех доступных для захвата интерфейсов, включая физические, виртуальные и псевдоинтерфейсы (например, `any` для всех интерфейсов).

*   **Указание конкретного интерфейса:**
    ```bash
    sudo tcpdump -i eth0 # Захват трафика на интерфейсе eth0
    sudo tcpdump -i any  # Захват трафика на всех доступных интерфейсах
    ```
    Используйте ключ `-i` для выбора сетевого интерфейса.

*   **Отключение разрешения имен (DNS):**
    По умолчанию `tcpdump` пытается разрешить IP-адреса в доменные имена и номера портов в названия служб (например, 80 в `http`). Это может замедлять вывод и быть нежелательным.
    *   **Не разрешать IP-адреса:**
        ```bash
        sudo tcpdump -n -i <interface_name>
        ```
        Ключ `-n` предотвращает разрешение IP-адресов в доменные имена.
    *   **Не разрешать IP-адреса и порты:**
        ```bash
        sudo tcpdump -nn -i <interface_name>
        ```
        Ключ `-nn` предотвращает разрешение как IP-адресов, так и номеров портов.

*   **Ограничение количества пакетов:**
    ```bash
    sudo tcpdump -i <interface_name> -c 10
    ```
    Опция `-c` указывает количество пакетов для захвата, после чего `tcpdump` автоматически завершит работу.

*   **Подробный вывод (verbosity):**
    *   **Один уровень подробности:**
        ```bash
        sudo tcpdump -v -i <interface_name>
        ```
        Ключ `-v` увеличивает детализацию вывода (например, TTL, ID, общая длина пакета).
    *   **Два уровня подробности:**
        ```bash
        sudo tcpdump -vv -i <interface_name>
        ```
        Ключ `-vv` предоставляет еще больше деталей (например, опции TCP).
    *   **Максимальный уровень подробности:**
        ```bash
        sudo tcpdump -vvv -i <interface_name>
        ```
        Ключ `-vvv` дает максимальную детализацию.

*   **Вывод содержимого пакета в ASCII и HEX:**
    ```bash
    sudo tcpdump -X -i <interface_name>
    ```
    Ключ `-X` выводит содержимое пакета в шестнадцатеричном (HEX) и ASCII форматах. Это полезно для анализа данных на прикладном уровне.

*   **Захват и сохранение в файл:**
    ```bash
    sudo tcpdump -i <interface_name> -w output.pcap
    ```
    Опция `-w` сохраняет дамп в файл в формате `pcap`. Этот файл содержит "сырые" данные пакетов и может быть открыт в Wireshark или прочитан `tcpdump` с ключом `-r`.

*   **Чтение пакетов из файла:**
    ```bash
    tcpdump -r output.pcap
    tcpdump -r output.pcap -Xnn
    ```
    Ключ `-r` позволяет читать ранее сохраненный файл дампа. Можно комбинировать с другими ключами для форматирования вывода.

#### Фильтрация трафика TCPDump

`tcpdump` поддерживает мощные фильтры для выборочного захвата трафика. Фильтры могут быть основаны на протоколах, хостах, портах и других параметрах.

*   **Фильтрация по протоколу:**
    *   **ICMP (пинги):**
        ```bash
        sudo tcpdump -i <interface_name> icmp
        ```
        Покажет только ICMP-трафик (например, запросы и ответы `ping`).
    *   **UDP:**
        ```bash
        sudo tcpdump -i <interface_name> udp
        ```
        Покажет только UDP-трафик.
    *   **TCP:**
        ```bash
        sudo tcpdump -i <interface_name> tcp
        ```
        Покажет только TCP-трафик.

*   **Фильтрация по хосту:**
    ```bash
    sudo tcpdump -i <interface_name> host 192.168.1.1
    sudo tcpdump -i <interface_name> host example.com
    ```
    Захватывает трафик, где источником или получателем является указанный IP-адрес или доменное имя.

*   **Фильтрация по порту:**
    ```bash
    sudo tcpdump -i <interface_name> port 80
    sudo tcpdump -i <interface_name> port 53
    ```
    Захватывает трафик, идущий на или с указанного порта.

*   **Комбинирование фильтров (логические операторы):**
    Можно использовать логические операторы `and`, `or`, `not` для создания сложных фильтров. Скобки `()` используются для группировки условий, но их нужно экранировать в командной строке.

    *   **Трафик на определенный хост и порт:**
        ```bash
        sudo tcpdump -i <interface_name> host 192.168.1.1 and port 22
        ```
        Покажет SSH-трафик между вашим хостом и 192.168.1.1.
    *   **Трафик на хост по нескольким портам:**
        ```bash
        sudo tcpdump -i <interface_name> host 192.168.1.254 and \( port 80 or port 22 \)
        ```
        Покажет трафик на хост 192.168.1.254 по портам 80 или 22.
    *   **DNS-трафик (UDP порт 53):**
        ```bash
        sudo tcpdump -i <interface_name> udp and port 53
        ```

#### Анализ TCP-соединений и HTTP/HTTPS с TCPDump

`tcpdump` позволяет наблюдать за этапами установки и завершения TCP-соединений, а также за содержимым незашифрованного трафика.

*   **TCP Handshake (трехстороннее рукопожатие):**
    При установке TCP-соединения происходит обмен пакетами:
    1.  **SYN:** Клиент отправляет серверу пакет с флагом SYN (Synchronize Sequence Numbers).
    2.  **SYN/ACK:** Сервер отвечает пакетом с флагами SYN и ACK (Acknowledgement).
    3.  **ACK:** Клиент подтверждает получение пакета сервера пакетом с флагом ACK.
    `tcpdump` отображает эти флаги (например, `Flags [S]` для SYN, `Flags [S.]` для SYN/ACK, `Flags [.]` для ACK).

*   **Завершение соединения:**
    Соединение обычно завершается обменом пакетами с флагом FIN (Finish) или RST (Reset).

*   **Видимость HTTP-трафика:**
    При использовании `-X` для незашифрованного HTTP-трафика можно увидеть заголовки и даже часть содержимого HTTP-запросов и ответов в ASCII-формате. Например, `GET / HTTP/1.1` или `200 OK`.

*   **HTTPS-трафик:**
    Трафик по HTTPS (порт 443) зашифрован. `tcpdump` покажет обмен зашифрованными пакетами, но их содержимое (данные прикладного уровня) будет нечитаемым. Можно увидеть служебную информацию, такую как обмен сертификатами (Server Name Indication - SNI), но не сами данные.

*   **Пример анализа HTTP-соединения:**
    ```bash
    sudo tcpdump -nn -i <interface_name> -c 3 host <web_server_ip> and port 80
    ```
    Эта команда покажет первые 3 пакета TCP-соединения (SYN, SYN/ACK, ACK) к веб-серверу по порту 80, демонстрируя установку соединения.

*   **Пример анализа HTTP-трафика с содержимым:**
    ```bash
    sudo tcpdump -Xnn -i <interface_name> host <web_server_ip> and port 80
    ```
    Позволяет увидеть заголовки HTTP и данные в открытом виде.

*   **Пример анализа HTTPS-трафика:**
    ```bash
    sudo tcpdump -Xnn -i <interface_name> host <web_server_ip> and port 443
    ```
    Покажет зашифрованный трафик. Содержимое будет нечитаемым, но можно увидеть обмен сертификатами.

*   **Перенаправление вывода в файл (для анализа):**
    Для удобства анализа большого объема трафика можно перенаправить вывод `tcpdump` в текстовый файл:
    ```bash
    sudo tcpdump -nn -i <interface_name> > capture.txt
    ```
    Или использовать ключ `-w` для сохранения сырых пакетов, которые затем можно анализировать с помощью `tcpdump -r` или Wireshark.

*   **Отличие `-w` от перенаправления `>`:**
    *   `>`: Перенаправляет форматированный вывод `tcpdump` (текст, который вы видите на экране) в файл.
    *   `-w`: Записывает "сырые" данные пакетов в бинарный файл `.pcap`, который содержит полную информацию о пакетах и может быть использован другими инструментами анализа трафика (например, Wireshark). Запись через `-w` значительно быстрее и эффективнее для больших объемов данных.

*   **Отображение флагов TCP:**
    `tcpdump` использует сокращения для флагов TCP:
    *   `[S]` - SYN
    *   `[.]` - ACK
    *   `[P]` - PSH (Push)
    *   `[F]` - FIN
    *   `[R]` - RST (Reset)
    *   `[U]` - URG (Urgent)
    *   `[W]` - ECE (ECN-Echo)
    *   `[E]` - CWR (Congestion Window Reduced)

### iperf3

Утилита для измерения максимальной пропускной способности сети между двумя хостами.
-   **На хосте-сервере:**
    ```bash
    iperf3 -s
    ```

-   **На хосте-клиенте:**
    ```bash
    # Измерение скорости от клиента к серверу (upload)
    iperf3 -c <IP_адрес_сервера>

    # Измерение в обратную сторону, от сервера к клиенту (download)
    iperf3 -c <IP_адрес_сервера> -R
    
    # Тест с 10 параллельными потоками в течение 60 секунд
    iperf3 -c <IP_адрес_сервера> -t 60 -P 10
    ```

### Мониторинг трафика в реальном времени (TUI)

Простые утилиты для визуализации текущей скорости приёма и передачи данных на сетевых интерфейсах.

```bash
# Установить
sudo apt install nload bmon
# Запустить
nload

bmon
```

`iftop`

Подобно `top` для процессов, `iftop` отображает использование пропускной способности, показывая активные соединения и объем трафика между парами хостов.

```bash

```

Интерактивный инструмент, предоставляющий несколько режимов: общая статистика по интерфейсам, детальная статистика по протоколам, мониторинг отдельных TCP/UDP соединений.

```bash
sudo iptraf-ng
```

`jnettop`

Группирует трафик по хосту и порту, показывая, кто и куда передаёт больше всего данных.

```bash
sudo jnettop -i eth0
```

## Диагностика DNS

Проблемы с DNS — частая причина, по которой сервисы могут казаться недоступными, даже если сетевая связность на уровне IP-адресов в порядке.

### Разница между системным резолвером и утилитами

-   **Системный резолвер** (используется `ping`, `curl`, браузером): Следует правилам из `/etc/nsswitch.conf`, который обычно предписывает сначала проверить файл `/etc/hosts`, а затем обращаться к DNS-серверам из `/etc/resolv.conf`. Локальные записи в `/etc/hosts` могут скрыть реальные проблемы с DNS.
-   **Прямой опрос DNS** (`dig`, `nslookup`, `host`): Эти утилиты **игнорируют `/etc/hosts`** и напрямую отправляют запросы на DNS-сервер. Это делает их незаменимыми для "чистой" проверки DNS-записей.

### Диагностика: проблема с DNS или с сетью?

1.  **Проверьте полный путь разрешения** с помощью `dig +trace example.com`. Если запрос зависает, это указывает на проблемы с внешними DNS-серверами.
2.  **Выполните тест через конкретный внешний резолвер**, например `dig @1.1.1.1 example.com`. Если ответ приходит мгновенно, а без указания резолвера — медленно, значит, проблема локальная (например, в `systemd-resolved`).

### Диагностика `systemd-resolved`

```bash
# Выполнить запрос через resolvectl
resolvectl query example.com

# Проверить статус и статистику сервиса
```

### `host`

`host` — простая и быстрая утилита для выполнения DNS-запросов. По умолчанию она запрашивает записи типа `A`, `AAAA` и `MX`.

**Примеры использования:**


*   **Базовый запрос (A, AAAA, MX записи):**
    ```bash
    $ host ya.ru
    ya.ru has address 93.158.134.3
    ya.ru has IPv6 address 2a02:6b8::3
    ya.ru mail is handled by 10 mx.yandex.ru.
    ```
    В этом выводе `host` последовательно запросил A, AAAA и MX записи для домена `ya.ru`.

*   **CNAME запись (псевдоним):**
    ```bash
    $ host www.sazykin.ru
    www.sazykin.ru is an alias for sazykin.ru.
    sazykin.ru has address 178.248.237.227
    sazykin.ru has IPv6 address 2a02:6b8:0:1781::1
    ```
    Здесь `host` сначала определила псевдоним `www.sazykin.ru` для `sazykin.ru`, а затем IP-адреса для канонического имени `sazykin.ru`.

*   **Запрос конкретного типа записи (NS):**
    ```bash
    $ host -t NS habr.com
    habr.com name server ns1.yandex.net.
    habr.com name server ns2.yandex.net.
    ```
    Таким образом, вывод команды `host` более лаконичный, чем команды `nslookup`.

**Более подробный вывод (`-v`):**

```bash
host -v ya.ru
```

Флаг `-v` (verbose) показывает детали каждого запроса и ответа, включая секции вопроса и ответа.

### `dig`

`dig` (Domain Information Groper) — более мощная и гибкая утилита, предоставляющая подробную информацию о DNS-запросах. Она популярна среди системных администраторов за полноту выводимой информации. Вывод `dig` содержит гораздо больше диагностической информации, чем `host` и `nslookup`, и поэтому больше подходит для понимания того, что происходит в системе доменных имён, и для диагностики.

**Пример использования:**
По умолчанию `dig` запрашивает только `A`-запись.

```bash
dig habr.com
```

Вывод `dig` разделен на секции, что соответствует структуре DNS-пакета:

-   **HEADER:** Техническая информация о запросе и ответе (например, флаги `qr`, `rd`, `ra` и `status: NOERROR`).
-   **QUESTION SECTION:** Какой вопрос был задан (доменное имя, класс записи `IN`, тип записи `A`).
-   **ANSWER SECTION:** Полученный ответ (доменное имя, TTL, класс, тип и IP-адрес).
-   **ADDITIONAL SECTION:** Дополнительная информация, которая может быть полезна.
-   **Статистика:** Время выполнения запроса, использованный DNS-сервер и протокол транспортного уровня (например, UDP).

**Пример запроса NS-записей с дополнительной информацией:**

При запросе серверов имен для доменной зоны `dig` часто возвращает также их IP-адреса в секции `ADDITIONAL SECTION`, чтобы избежать дополнительных запросов.
```bash
dig yandex.ru NS

```

**Запрос конкретного типа записи:**

```bash
# Запросить MX-запись
dig ya.ru MX

# Запросить AAAA-запись
dig ya.ru AAAA
```

**Трассировка запроса (`+trace`):**

Флаг `+trace` позволяет увидеть весь путь рекурсивного запроса, начиная от корневых серверов. Это чрезвычайно полезно для диагностики проблем с делегированием домена.

```bash
$ dig ya.ru +trace
```

### `nslookup`

`nslookup` — одна из старейших утилит для DNS-запросов, доступна как в Linux, так и в Windows. Считается менее предпочтительной в Linux по сравнению с `dig` и `host`, но все еще широко используется.

```bash
nslookup ya.ru
```

`nslookup` также имеет интерактивный режим, который можно запустить, вызвав команду без аргументов.

### Диагностика сетевых задержек с помощью `curl`

`curl` умеет показывать время, затраченное на каждом этапе подключения.

```bash
curl -o /dev/null -s -w \
"DNS: %{time_namelookup}s\nTCP: %{time_connect}s\nTLS: %{time_appconnect}s\nStartTransfer: %{time_starttransfer}s\nTotal: %{time_total}s\n" \
https://example.com
```

-   **Большое `time_namelookup`**: Проблема в DNS.
-   **Большое `time_connect`**: Проблема с установкой TCP-соединения (сетевые задержки, файрвол).
-   **Большое `time_appconnect`**: Проблема на этапе TLS-рукопожатия (например, медленная работа сервера).
-   **Большое `time_starttransfer`**: Сервер долго обрабатывает запрос перед отправкой ответа.

Чтобы исключить влияние DNS, можно указать IP-адрес сервера напрямую:

```bash
curl --resolve example.com:443:93.184.216.34 https://example.com
```
