# Общая методология диагностики сервисов

## Definitions

**Диагностика сервисов (Troubleshooting)** — систематический процесс выявления причин сбоев, некорректного функционирования или низкой производительности программных систем.

**Принцип «снизу вверх» (Bottom-up)** — подход к диагностике, начинающийся с низшего уровня стека (физический сервер, ОС) и последовательно движущийся к верхнему (процесс, приложение, зависимости). Позволяет исключать возможные причины сбоя на каждом этапе.

## Basic Concepts

### Ключевые правила

1. **Не перезагружать!** — перезагрузка скрывает, а не решает проблему. Необходимо собрать максимум диагностической информации до принятия радикальных мер.

2. **Определить границы проблемы:**
   - Проблема затрагивает одного пользователя или всех?
   - Сбой на одном сервере или на всём кластере?
   - Произошёл ли сбой после недавних изменений в коде, конфигурации или инфраструктуре?

3. **Следовать принципу «снизу вверх»:** диагностика начинается с ОС и постепенно поднимается по стеку технологий, последовательно исключая причины.

### Уровни стека диагностики

| Уровень | Область | Ключевые инструменты |
| :--- | :--- | :--- |
| **1** | Сервер и ОС | `ping`, `ssh`, `htop`, `df`, `dmesg` |
| **2** | Процесс и порты | `systemctl`, `ps`, `ss` |
| **3** | Приложение и логи | `journalctl`, `tail -f`, `curl` |
| **4** | Зависимости | `telnet`, логи БД/кэшей |
| **5** | Конфигурация и код | `git log`, системы управления конфигурациями |

## Practical Scenarios

### Уровень 1: Сервер и ОС

**Доступность сервера:**

```bash
ping <server_ip>
ssh user@<server_ip>
```

Подробно: [SSH Overview](../../Security/ssh/ssh_overview.md)

**Системные ресурсы:**

```bash
# CPU/RAM
htop    # подробнее: [htop](../Processes/htop.md)
top     # подробнее: [top](../Processes/top.md)

# Дисковое пространство и inodes
df -h
df -i

# Системные ошибки (ядро, OOM Killer)
dmesg -T    # подробнее: [dmesg](../Kernel/dmesg/index.md)
```

Подробнее о диагностике дискового пространства: [Filesystem Diagnostics](../Filesystem/filesystem_and_disk_space_diagnostics.md)

### Уровень 2: Процесс и порты

**Статус процесса:**

```bash
systemctl status <service_name>    # подробнее: [systemd Service Management](../../Core/systemd/service_management.md)
ps aux | grep <process_name>       # подробнее: [ps](../Processes/ps.md)
```

**Сетевые порты:**

```bash
ss -tlpn | grep :<port>     # современная утилита: [ss](../Networking/ss.md)
netstat -tlpn | grep :<port> # устаревшая утилита
```

### Уровень 3: Приложение и логи

**Логи приложения:**

```bash
# systemd-сервисы
journalctl -u <service_name> -f    # подробнее: [journalctl](../journalctl.md)

# Классические лог-файлы
tail -f /var/log/<service_name>/error.log
```

**Локальный доступ:**

```bash
curl -v localhost:<port>
```

**Локальный файрвол:**

```bash
iptables -L -n
nft list ruleset
```

Подробнее: [Настройка файрвола в Linux](../../Networking/Settings/Persistent_Network/systemd_networkd.md)

### Уровень 4: Зависимости

**Проверка доступности БД, кэшей, микросервисов:**

```bash
telnet <db_host> <db_port>
```

Проверить статус и логи зависимых сервисов по текущему алгоритму.

### Уровень 5: Конфигурация и код

**Проверка изменений:**

```bash
git log    # история коммитов
```

Проверить системы управления конфигурациями (Ansible и др.) на предмет недавних запусков.
