# Восстановление системы при сбоях загрузки

## Определения

**Однопользовательский режим (Single-user mode)** — минимальный режим работы ОС, при котором запускается только одна консоль суперпользователя (root) без сетевых служб и многопользовательской среды. Используется для обслуживания и восстановления.

**Rescue Mode (Режим спасения)** — в `systemd` это состояние (`rescue.target`), при котором монтируются основные файловые системы и запускается минимум служб, необходимых для восстановления.

**Emergency Mode (Аварийный режим)** — в `systemd` это максимально примитивное состояние (`emergency.target`), при котором монтируется только корневая ФС в режиме `ro` (только чтение) и запускается оболочка. Сеть и другие диски не активны.

**Chroot (Change Root)** — операция смены корневого каталога для текущего процесса и его дочерних элементов. Позволяет «войти» в сломанную систему из LiveCD/другой ОС для ее починки.

## Основные концепции

### Стратегии восстановления

При невозможности штатной загрузки («черный экран», зависание на этапе `init`) применяются три подхода в порядке возрастания сложности:

1.  **Откат к снимку/образу:** Если система в облаке или на виртуальной машине, проще всего развернуть последний рабочий [снимок (snapshot)](../../SystemAdministration/backup_and_recovery.md#виртуальные-машины-vm).
2.  **Интерактивное восстановление:** Загрузка в Rescue или Emergency режим для ручной правки конфигов или исправления ФС.
3.  **Внешнее восстановление (Rescue Media):** Загрузка с отдельного носителя (LiveCD/LiveUSB), монтирование дисков сломанной системы и работа «со стороны».

### Режимы восстановления systemd

| Режим | Цель (Target) | Особенности |
| :--- | :--- | :--- |
| **Rescue** | `rescue.target` | Монтирует локальные ФС, сеть отключена. Требует пароль root. |
| **Emergency** | `emergency.target` | Минимум модулей, корень в `ro`. Для тяжелых случаев сбоя дисков. |

## Практические сценарии

### 1. Прерывание загрузки через GRUB (клавиша «E»)

Если система не грузится, можно изменить параметры ядра «на лету» в меню загрузчика:

1.  В меню GRUB выделите нужное ядро и нажмите клавишу **`e`**.
2.  Найдите строку, начинающуюся с `linux` (или `linux16`/`linuxefi`).
3.  Перейдите в конец строки и добавьте нужный параметр:
    *   Для перехода в Rescue mode: `systemd.unit=rescue.target` (или просто `single`).
    *   Для перехода в Emergency mode: `systemd.unit=emergency.target`.
4.  Нажмите **`Ctrl+X`** или **`F10`** для загрузки с этими параметрами.

### 2. Работа в спасательной оболочке

После входа в режим спасения (потребуется пароль root) система часто оказывается в ограниченном состоянии.

**Перемонтирование корня в режим записи:**
Часто корень монтируется как `read-only`, что не позволяет сохранять изменения.
```bash
mount -o remount,rw /
```

**Монтирование всех ФС из fstab:**
В Emergency режиме другие разделы (`/home`, `/var`) не подключены автоматически.
```bash
mount -a
```

**Ручная проверка файловой системы (fsck):**
Если загрузка прерывается из-за ошибок диска:
```bash
# Проверка конкретного раздела
fsck -y /dev/sda1
```

### 3. Восстановление в облачных средах

В облаках (AWS, Yandex Cloud) физический доступ к консоли часто ограничен или отсутствует (нет возможности нажать «E» в GRUB).

*   **Метод «Диск-спасатель»:**
    1.  Остановите поврежденную ВМ.
    2.  Отсоедините ее загрузочный диск.
    3.  Присоедините этот диск как дополнительный к другой, заведомо рабочей ВМ.
    4.  Смонтируйте диск, исправьте ошибки в конфигах (например, `/etc/fstab` или `/etc/ssh/sshd_config`).
    5.  Отсоедините диск и верните его на оригинальную ВМ.
*   **Серийная консоль (Serial Console):** Использование специализированных инструментов облачного провайдера (например, Yandex Cloud CLI или AWS Serial Console) для перехвата вывода загрузки и ввода команд.

### 4. Специфика FreeBSD (для сравнения)

В FreeBSD система инициализации и восстановления отличается от Linux:
*   **Файлы конфигурации:** Все настройки автозапуска живут в `/etc/rc.conf`. Правка `/etc/defaults/rc.conf` запрещена (перезаписывается при обновлении).
*   **Режим восстановления:** В меню загрузки есть пункт `Boot Single User`.
*   **Монтирование:** После входа в single-user mode нужно выполнить:
    ```bash
    # Для UFS
    mount -u /
    # Для ZFS
    zfs set readonly=off zroot/ROOT/default
    ```

## Дополнительная информация

### Безопасность и сброс пароля

Режимы спасения по умолчанию запрашивают пароль root. Если пароль утерян, стандартный Rescue mode не поможет. В этом случае используются методы прямого внедрения в процесс инициализации (например, `init=/bin/bash`).
Подробно: [**Восстановление пароля root**](../../SystemAdministration/linux_password_recovery.md).
