# Диагностика и решение проблем с низкой энтропией в Linux

## Определения

* **Энтропия (Entropy):** В контексте Linux — это уровень непредсказуемости или случайности, который ядро использует для генерации криптографически стойких случайных чисел. Источниками энтропии служат аппаратные прерывания от клавиатуры, мыши, дисковых операций и сетевой активности.
* **/dev/random:** Блокирующее устройство, которое возвращает случайные числа только тогда, когда в пуле энтропии накоплено достаточно "шума". Если энтропии не хватает, чтение из `/dev/random` блокируется до её накопления.
* **/dev/urandom:** Неблокирующее устройство, которое возвращает псевдослучайные числа. Если энтропии недостаточно, оно использует криптографический генератор для создания данных, что делает его быстрее, но теоретически менее случайным, чем `/dev/random` в момент нехватки энтропии.

## Основные концепции

### Проблема нехватки энтропии

В некоторых ситуациях, особенно в виртуальных машинах и контейнерах, система может "тормозить" без видимых причин: CPU не загружен, диски и сеть неактивны, но SSH-соединения устанавливаются с задержкой, TLS-рукопожатия зависают, а сервисы стартуют с паузами.

Причина часто кроется в нехватке энтропии. Ядру просто неоткуда брать "шум" для генерации случайных чисел, так как в виртуализированных средах почти нет аппаратных источников случайности (движений мыши, нажатий на клавиатуру, уникальных таймингов от дисковых операций).

Процессы, которым требуются криптографически стойкие случайные числа (для генерации ключей, сессионных идентификаторов, TLS-соединений), обращаются к `/dev/random` и "зависают" в ожидании, пока ядро накопит достаточно энтропии.

### Затронутые приложения

Чаще всего с этой проблемой сталкиваются:

* Приложения, использующие **TLS/SSL** для инициализации соединений.
* Процессы, генерирующие **криптографические ключи** (SSH, GPG).
* Приложения на **Java**, использующие `SecureRandom` (который по умолчанию может читать из `/dev/random`).
* Старые или специфические приложения, которые жестко привязаны к блокирующему `/dev/random` и не умеют использовать неблокирующий генератор.

## Практические сценарии

### Диагностика

1. **Проверка доступной энтропии:**
    Основной показатель — это файл `/proc/sys/kernel/random/entropy_avail`. Нормальные значения — сотни и тысячи. Значения около 0–100 указывают на острую нехватку.

    Для наблюдения в реальном времени:

    ```bash
    watch -n1 cat /proc/sys/kernel/random/entropy_avail
    ```

    Если при каждом SSH-логине или HTTPS-запросе число падает почти до нуля, проблема подтверждена.

2. **Трассировка процессов:**
    С помощью `strace` можно увидеть, что процесс "висит" именно на системном вызове `getrandom()` или на чтении из `/dev/random`.

    ```bash
    # strace -p <PID> -e getrandom,read
    ```

    Это покажет, что процесс заблокирован в ожидании случайных данных.

### Решение

Основная стратегия — установить программный генератор энтропии, который использует другие источники (например, состояние CPU) для генерации псевдослучайного "шума" и пополнения пула энтропии ядра.

#### Способ 1: Установка `haveged`

`haveged` (HArdware Volatile Entropy Gathering and Expansion daemon) — это демон, который использует алгоритм HAVEGE, основанный на колебаниях таймеров процессора, для генерации энтропии. Это наиболее простое и распространенное решение.

**Установка и запуск (Debian/Ubuntu):**

```bash
sudo apt update
sudo apt install haveged
sudo systemctl enable --now haveged
```

#### Способ 2: Установка `rng-tools`

`rng-tools` — это набор утилит, которые могут использовать аппаратные генераторы случайных чисел (TRNG), если они есть в системе (например, TPM-модули или специальные инструкции CPU). Если аппаратных источников нет, `rng-tools` также может служить источником энтропии.

**Установка и запуск (Debian/Ubuntu):**

```bash
sudo apt update
sudo apt install rng-tools
sudo systemctl enable --now rng-tools
```

### Проверка сохранения сида

Важно убедиться, что система сохраняет и восстанавливает начальное число (seed) для генератора случайных чисел между перезагрузками. Это обеспечивает наличие некоторого количества энтропии сразу после старта системы. За это отвечает служба `systemd-random-seed`.

**Проверка статуса:**

```bash
systemctl status systemd-random-seed
```

Служба должна быть активной (`active (exited)`).

## Дополнительная информация

* **`/dev/random` vs `/dev/urandom`:** В современных ядрах Linux (начиная с 5.6) разница между `/dev/random` и `/dev/urandom` практически стерлась. Оба используют один и тот же криптографически стойкий генератор (ChaCha20). `/dev/random` блокируется только на самой ранней стадии загрузки, пока генератор не будет полностью инициализирован. Для большинства приложений (включая криптографию) использование `/dev/urandom` является безопасным и предпочтительным.
* **Виртуализация:** Проблема нехватки энтропии особенно актуальна для `KVM`, `VirtualBox` и контейнеров, где взаимодействие с реальным "железом" минимально.
* Подробнее об устройстве `/dev/random` и `/dev/urandom` можно прочитать в заметке [**Файловая система /dev**](../../FileSystems/virtual_fs_dev.md).
