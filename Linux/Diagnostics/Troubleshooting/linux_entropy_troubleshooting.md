# Диагностика проблем с низкой энтропией в Linux

## Definitions

**Энтропия (Entropy)** — уровень непредсказуемости/случайности, используемый ядром Linux для генерации криптографически стойких случайных чисел. Источники: аппаратные прерывания клавиатуры, мыши, дисковых операций, сетевой активности.

**`/dev/random`** — блокирующее устройство. Возвращает случайные числа только при достаточном пуле энтропии. Чтение блокируется при нехватке.

**`/dev/urandom`** — неблокирующее устройство. Возвращает псевдослучайные числа; при нехватке энтропии использует криптографический генератор (ChaCha20).

**Пулы энтропии (Entropy Pool)** — накопленная ядром случайность от аппаратных событий.

## Basic Concepts

### Механизм проблемы

В виртуальных машинах и контейнерах система может «тормозить» без видимых причин: CPU не загружен, диски и сеть неактивны, но SSH-соединения устанавливаются с задержкой, TLS-рукопожатия зависают, сервисы стартуют с паузами.

**Причина:** ядру неоткуда брать «шум» для генерации случайных чисел — в виртуализированных средах минимальное взаимодействие с реальным оборудованием.

Процессы, требующие криптографически стойких случайных чисел (TLS, генерация ключей, сессионные идентификаторы), обращаются к `/dev/random` и блокируются в ожидании энтропии.

### Затронутые приложения

- Приложения, использующие **TLS/SSL**
- Процессы генерации **криптографических ключей** (SSH, GPG)
- **Java-приложения** с `SecureRandom` (по умолчанию читает из `/dev/random`)
- Приложения, жёстко привязанные к блокирующему `/dev/random`

## Practical Scenarios

### Диагностика

**Проверка доступной энтропии:**

```bash
cat /proc/sys/kernel/random/entropy_avail
```

Норма — сотни/тысячи. Значения 0–100 указывают на острую нехватку.

Мониторинг в реальном времени:

```bash
watch -n1 cat /proc/sys/kernel/random/entropy_avail
```

Если при каждом SSH-логине или HTTPS-запросе значение падает почти до нуля — проблема подтверждена.

**Трассировка процессов:**

```bash
strace -p <PID> -e getrandom,read
```

Покажет блокировку процесса на `getrandom()` или чтении `/dev/random`.

### Решение: haveged

`haveged` (HArdware Volatile Entropy Gathering and Expansion daemon) — демон, использующий алгоритм HAVEGE на основе колебаний таймеров CPU.

**Debian/Ubuntu:**

```bash
sudo apt update && sudo apt install haveged
sudo systemctl enable --now haveged
```

**CentOS/RHEL/Fedora:**

```bash
sudo dnf install haveged
sudo systemctl enable --now haveged
```

### Решение: rng-tools

`rng-tools` — утилиты для работы с аппаратными генераторами случайных чисел (TRNG: TPM-модули, инструкции CPU). При отсутствии аппаратных источников служит программным генератором.

**Debian/Ubuntu:**

```bash
sudo apt update && sudo apt install rng-tools
sudo systemctl enable --now rng-tools
```

**CentOS/RHEL/Fedora:**

```bash
sudo dnf install rng-tools
sudo systemctl enable --now rng-tools
```

### Проверка systemd-random-seed

Служба `systemd-random-seed` сохраняет и восстанавливает seed генератора между перезагрузками, обеспечивая начальную энтропию при старте системы.

```bash
systemctl status systemd-random-seed
```

Статус должен быть `active (exited)`.

## Additional Information

### `/dev/random` vs `/dev/urandom` в современных ядрах

Начиная с ядра **5.6** разница практически стёрлась. Оба устройства используют один CSPRNG (ChaCha20). `/dev/random` блокируется только на ранней стадии загрузки до инициализации генератора. Для большинства задач (включая криптографию) `/dev/urandom` безопасен и предпочтителен.

### Специфика виртуализации

Проблема особенно актуальна для `KVM`, `VirtualBox`, контейнеров — сред с минимальным взаимодействием с реальным оборудованием.
