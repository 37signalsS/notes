# Трассировка и отладка в Linux

## 1. Определение

-   **Мониторинг:** Непрерывный сбор и анализ данных о состоянии и производительности системы или приложения. Цель — выявление трендов, аномалий и своевременное оповещение о проблемах.
-   **Трассировка:** Запись и анализ последовательности событий или вызовов функций в программе или системе. Используется для понимания потока выполнения и выявления причин задержек или сбоев.
-   **Отладка:** Процесс выявления и устранения ошибок (багов) в программном обеспечении. Включает остановку выполнения программы, пошаговый просмотр кода и анализ состояния переменных.

## 2. Основные концепции

Трассировка и отладка позволяют заглянуть "внутрь" работающего процесса или ядра, чтобы понять их поведение на разных уровнях.

-   **Системные вызовы (System Calls):** Взаимодействие приложения с ядром (запросы на открытие файлов, сетевые операции). Основной инструмент — `strace`.
-   **Библиотечные вызовы (Library Calls):** Взаимодействие приложения с динамическими библиотеками (`.so`). Основной инструмент — `ltrace`.
-   **Использование ресурсов:** Анализ того, какие ресурсы (файлы, сокеты) использует процесс. Основной инструмент — `lsof`.
-   **Давление на ресурсы (Resource Pressure):** Механизмы ядра, такие как **Pressure Stall Information (PSI)**, позволяют оценить потери производительности из-за нехватки CPU, памяти или I/O.

## 3. Практические сценарии

### `strace`: Трассировка системных вызовов
`strace` перехватывает и записывает системные вызовы процесса. Незаменим для диагностики проблем с доступом к файлам ("Permission denied"), сетевыми соединениями и правами.

```bash
# Присоединиться к работающему процессу по его PID
sudo strace -p <PID>

# Запустить команду и отследить ее системные вызовы
strace ls -l /несуществующий_файл
```

### `ltrace`: Трассировка библиотечных вызовов
`ltrace` отслеживает вызовы функций из динамических библиотек. Полезно, когда системных вызовов недостаточно для понимания логики приложения (например, чтобы увидеть, с какими аргументами вызывается функция из библиотеки `libc`).

```bash
# Трассировать вызовы библиотек для команды
ltrace cat /dev/null
```

### `lsof`: Анализ открытых файлов
Утилита `lsof` показывает, какие файлы, сокеты и другие ресурсы открыты процессом. Подробно описана в основной заметке: [**`lsof` — Список открытых файлов**](./Tools/lsof.md).

## 4. Продвинутые детали

### Продвинутое использование `strace`
`strace` имеет мощные опции для детального анализа:

```bash
# Отследить процесс и все его дочерние процессы (-f),
# добавить микросекундные метки времени (-tt),
# и показать время, затраченное на каждый вызов (-T)
sudo strace -f -ttT <команда>

# Фильтровать только сетевые вызовы и попытки открыть файлы
strace -e trace=network,open ...
```

### Pressure Stall Information (PSI)
PSI — это механизм ядра, который предоставляет информацию о том, сколько времени процессы теряют из-за нехватки ресурсов. Это продвинутый инструмент для поиска "узких мест" в производительности. Подробнее см. в [заметке о PSI](../Core/kernel/psi.md).
