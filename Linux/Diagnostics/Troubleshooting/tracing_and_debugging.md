# Трассировка и отладка в Linux

## Определения

-   **Мониторинг:** Непрерывный сбор и анализ высокоуровневых метрик (CPU, RAM, I/O) для оценки общего состояния системы и выявления аномалий.
-   **Трассировка:** Детальная запись последовательности событий, таких как системные или библиотечные вызовы, для понимания потока выполнения программы и поиска узких мест.
-   **Отладка:** Интерактивный процесс поиска и устранения ошибок, включающий пошаговое выполнение кода, проверку переменных и остановку программы в контрольных точках.

## Основные концепции

Трассировка и отладка позволяют анализировать поведение работающего процесса или ядра на разных уровнях абстракции.

-   **Системные вызовы (System Calls):** Интерфейс взаимодействия приложения с ядром для выполнения привилегированных операций (открытие файлов, сетевые запросы, управление процессами). Основной инструмент для их отслеживания — `strace`.
-   **Библиотечные вызовы (Library Calls):** Обращения приложения к функциям, предоставляемым динамическими библиотеками (`.so`, например, `libc`). Основной инструмент — `ltrace`.
-   **Использование ресурсов:** Анализ ресурсов, которые использует процесс (открытые файлы, сетевые сокеты). Основной инструмент — `lsof`.
-   **Давление на ресурсы (Resource Pressure):** Оценка потерь производительности из-за нехватки ресурсов (CPU, Memory, I/O) с помощью механизма ядра **Pressure Stall Information (PSI)**.

## Практические сценарии

#### `strace`: Трассировка системных вызовов

`strace` перехватывает и логирует системные вызовы процесса и сигналы, которые он получает. Это незаменимый инструмент для диагностики проблем с доступом к файлам (`Permission denied`), сетевыми соединениями или некорректной работой с ресурсами.

-   **Присоединение к работающему процессу по его PID:**
    ```bash
    sudo strace -p <PID>
    ```

-   **Запуск и трассировка команды:**
    ```bash
    # Попытка прочитать несуществующий файл покажет ошибку ENOENT
    strace ls -l /несуществующий_файл
    ```

#### `ltrace`: Трассировка библиотечных вызовов

`ltrace` отслеживает вызовы функций из динамических библиотек. Полезен, когда системных вызовов недостаточно, и нужно понять логику работы приложения на более высоком уровне.

```bash
# Показывает, какие функции из libc вызываются командой cat
ltrace cat /dev/null
```

#### `lsof`: Анализ открытых файлов

Утилита `lsof` отображает информацию об открытых файлах, сокетах и других файловых дескрипторах для всех процессов в системе. Подробно описана в основной заметке: [**`lsof` — Список открытых файлов**](../Processes/lsof.md).

#### `gdb`: Интерактивная отладка

`gdb` (GNU Debugger) — это мощный интерактивный отладчик, который позволяет:
-   Запускать программу, указывая аргументы.
-   Останавливать выполнение в определённых точках (breakpoints).
-   Изучать значения переменных и состояние стека вызовов.
-   Изменять значения переменных "на лету".

-   **Присоединение к работающему процессу:**
    ```bash
    # Для этого может потребоваться отключение защиты ptrace
    # sudo sysctl -w kernel.yama.ptrace_scope=0
    sudo gdb -p <PID>
    ```

-   **Запуск и отладка программы:**
    ```bash
    # Запуск программы 'my_program' с аргументами 'arg1' и 'arg2' в gdb
    gdb --args my_program arg1 arg2
    ```
    Внутри сессии `gdb` можно использовать команды `run`, `break`, `next`, `step`, `print <var>`, `bt` (backtrace).

## Дополнительная информация

#### Продвинутое использование `strace`

`strace` предоставляет мощные опции для фильтрации и форматирования вывода:

-   **Отслеживание дочерних процессов и детальный вывод:**
    ```bash
    # -f: отслеживать дочерние процессы (fork/clone)
    # -tt: добавить микросекундные метки времени
    # -T: показать время, затраченное на каждый системный вызов
    sudo strace -f -ttT <команда>
    ```

-   **Фильтрация по типу вызовов:**
    ```bash
    # Отслеживать только сетевые вызовы и попытки открыть файлы
    strace -e trace=network,open,openat <команда>
    ```

#### Pressure Stall Information (PSI)

PSI — это механизм ядра (начиная с версии 4.20), который предоставляет метрики о том, сколько времени процессы теряют из-за нехватки ресурсов. Это более точный способ оценки "давления" на систему, чем `Load Average` или утилизация CPU. Подробнее см. в [заметке о PSI](../../Core/kernel/psi.md).
