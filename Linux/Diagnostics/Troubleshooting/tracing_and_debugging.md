# Трассировка и отладка в Linux

## Definitions

**Мониторинг** — непрерывный сбор высокоуровневых метрик (CPU, RAM, I/O) для оценки состояния системы.

**Трассировка** — детальный запис последовательности событий (системные/библиотечные вызовы) для анализа потока выполнения программы.

**Отладка** — интерактивный поиск и устранение ошибок: пошаговое выполнение, проверка переменных, контрольные точки.

**Системный вызов (Syscall)** — интерфейс взаимодействия приложения с ядром для привилегированных операций (файлы, сеть, процессы).

**Библиотечный вызов (Library Call)** — обращение приложения к функциям динамических библиотек (`.so`, `libc`).

**PSI (Pressure Stall Information)** — механизм ядра (≥4.20) для оценки потерь производительности из-за нехватки ресурсов (CPU, Memory, I/O).

## Basic Concepts

### Уровни абстракции

| Уровень | Что отслеживается | Инструмент |
| :--- | :--- | :--- |
| Системные вызовы | Взаимодействие приложения с ядром | `strace` |
| Библиотечные вызовы | Обращения к `.so`-библиотекам | `ltrace` |
| Открытые файлы/сокеты | Ресурсы, используемые процессом | `lsof` |
| Давление на ресурсы | Потери производительности (CPU/Memory/I/O) | PSI (`/proc/pressure/`) |
| Интерактивная отладка | Пошаговое выполнение, переменные, стек | `gdb` |

### Когда применять

- **`strace`** — `Permission denied`, сетевые проблемы, непонятные блокировки
- **`ltrace`** — системных вызовов недостаточно, нужна логика приложения
- **`lsof`** — утечки файловых дескрипторов, зависшие соединения
- **`gdb`** — анализ crash dump, пошаговое выполнение, модификация переменных
- **PSI** — более точная оценка «давления» на систему, чем Load Average

## Practical Scenarios

### strace: трассировка системных вызовов

**Механизм работы:** `strace` использует системный вызов `ptrace` — способ одному процессу контролировать другой. Когда `strace` подключается к приложению, ядро ставит его на паузу каждый раз при системном вызове, причём **дважды**:

1. **На входе** — чтобы прочитать, какой вызов выполняется и с какими аргументами
2. **На выходе** — чтобы прочитать, что вернуло ядро

Каждый системный вызов = две остановки. Приложение замирает, ждёт, пока `strace` запишет информацию, и только потом продолжает. Это влияет на производительность приложений с большим количеством системных вызовов.

```bash
# Присоединение к работающему процессу
sudo strace -p <PID>

# Запуск и трассировка команды
strace ls -l /несуществующий_файл    # покажет ENOENT
```

**Продвинутые опции:**

```bash
# -f: дочерние процессы (fork/clone)
# -tt: микросекундные метки времени
# -T: время выполнения каждого syscall
sudo strace -f -ttT <команда>

# Фильтрация по типу вызовов
strace -e trace=network,open,openat <команда>

# Сводка по системным вызовам (count)
strace -c <команда>
```

**Типичные сценарии:**

- **Приложение не стартует**, логи пустые, ошибка невнятная — `strace` покажет все файлы, которые приложение успешно открыло или не смогло открыть (`openat`, `stat`), и причина станет ясна.
- **Процесс завис**, но непонятно на чём — `strace -p <PID>` подключается к живому процессу и сразу показывает, на каком системном вызове он застрял.

### ltrace: трассировка библиотечных вызовов

```bash
# Вызовы функций из libc
ltrace cat /dev/null
```

Подробно: [`lsof` — Список открытых файлов](../Processes/lsof.md).

### gdb: интерактивная отладка

```bash
# Присоединение к процессу (может потребоваться отключение ptrace-защиты)
# sudo sysctl -w kernel.yama.ptrace_scope=0
sudo gdb -p <PID>

# Запуск с аргументами
gdb --args my_program arg1 arg2
```

Основные команды внутри `gdb`: `run`, `break`, `next`, `step`, `print <var>`, `bt` (backtrace).

> **Важно:** При присоединении отладчика (`gdb`, `strace`) процесс **останавливается** (статус `T` — Stopped/Traced). Все сигналы, предназначенные процессу, перехватываются отладчиком. Процесс не будет обрабатывать сигналы (включая SIGTERM), пока отладчик не отсоединится или не передаст сигнал явно (`signal SIGCONT` в gdb). Это критично при отладке production-сервисов — остановка процесса ведёт к недоступности сервиса.

## Additional Information

### Безопасность ptrace

По умолчанию `kernel.yama.ptrace_scope=1` — непривилегированные процессы не могут трассировать друг друга. Для отладки:

```bash
# Временно
sudo sysctl -w kernel.yama.ptrace_scope=0

# Постоянно (/etc/sysctl.d/10-ptrace.conf)
kernel.yama.ptrace_scope = 0
```

### PSI (Pressure Stall Information)

Доступен в ядре ≥4.20. Более точная метрика «давления» на систему, чем Load Average.

```bash
# Чтение метрик PSI
cat /proc/pressure/cpu
cat /proc/pressure/memory
cat /proc/pressure/io
```

Подробно: [PSI](../../Core/kernel/psi.md).
