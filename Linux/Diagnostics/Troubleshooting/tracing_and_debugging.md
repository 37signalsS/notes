# Трассировка и отладка в Linux

## Definitions

**Мониторинг** — непрерывный сбор высокоуровневых метрик (CPU, RAM, I/O) для оценки состояния системы.

**Трассировка** — детальный запис последовательности событий (системные/библиотечные вызовы) для анализа потока выполнения программы.

**Отладка** — интерактивный поиск и устранение ошибок: пошаговое выполнение, проверка переменных, контрольные точки.

**Системный вызов (Syscall)** — интерфейс взаимодействия приложения с ядром для привилегированных операций (файлы, сеть, процессы).

**Библиотечный вызов (Library Call)** — обращение приложения к функциям динамических библиотек (`.so`, `libc`).

**PSI (Pressure Stall Information)** — механизм ядра (≥4.20) для оценки потерь производительности из-за нехватки ресурсов (CPU, Memory, I/O).

**LD_PRELOAD** — переменная окружения, заставляющая динамический линковщик (`ld.so`) загружать указанные разделяемые библиотеки перед всеми остальными. Позволяет переопределять функции стандартных библиотек.

## Basic Concepts

### Уровни абстракции

| Уровень | Что отслеживается | Инструмент |
| :--- | :--- | :--- |
| Зависимости | Наличие и пути разделяемых библиотек (`.so`) | `ldd` |
| Подмена логики | Перехват и замена библиотечных функций | `LD_PRELOAD` |
| Системные вызовы | Взаимодействие приложения с ядром | `strace` |
| Библиотечные вызовы | Обращения к `.so`-библиотекам | `ltrace` |
| Открытые файлы/сокеты | Ресурсы, используемые процессом | `lsof` |
| Давление на ресурсы | Потери производительности (CPU/Memory/I/O) | [**PSI**](../../Core/kernel/psi.md) |
| Интерактивная отладка | Пошаговое выполнение, переменные, стек | `gdb` |

### Когда применять

- **`ldd`** — ошибки «библиотека не найдена», проверка путей линковки
- **`LD_PRELOAD`** — отладка (подмена `malloc`), временные фиксы, песочницы
- **`strace`** — `Permission denied`, сетевые проблемы, непонятные блокировки
- **`ltrace`** — системных вызовов недостаточно, нужна логика приложения
- **`lsof`** — утечки файловых дескрипторов, зависшие соединения
- **`gdb`** — анализ crash dump, пошаговое выполнение, модификация переменных
- **PSI** — более точная оценка «давления» на систему, чем Load Average

## Practical Scenarios

### LD_PRELOAD: Перехват функций

Механизм позволяет подменить стандартную функцию (например, из `libc.so`) на собственную реализацию без перекомпиляции приложения.

**Сценарии использования:**

1. **Профилирование:** подмена `malloc`/`free` для поиска утечек памяти.
2. **Отладка:** принудительный вывод аргументов функции в `stderr`.
3. **Hotfix:** исправление бага в закрытой библиотеке.
4. **Sandbox:** запрет на открытие определенных файлов через перехват `open`.

**Пример использования:**

```bash
# Запуск с подменой библиотеки
LD_PRELOAD=/path/to/my_lib.so ./my_app
```

### Сценарий: Бинарный файл завершается без вывода (Silent Exit)

Ситуация: вы запускаете программу, она мгновенно завершается, в консоли пусто, в системных логах ничего нет.

**Алгоритм диагностики:**

1. **Проверка кода возврата:**

    ```bash
    ./binary
    echo $?
    ```

    Любое значение, кроме `0`, указывает на ошибку. Значения `126` (проблемы с правами) и `127` (команда не найдена) — ключевые.

2. **Проверка зависимостей:**

    ```bash
    ldd ./binary
    ```

    Ищите строки `not found`. Если библиотек нет, программа может упасть до того, как успеет что-то напечатать.

3. **Захват stderr:**

    ```bash
    ./binary 2>&1 | less
    ```

    Возможно, ошибки пишутся в стандартный поток ошибок, который не отображается или перенаправлен.

4. **Трассировка системных вызовов (основной этап):**

    ```bash
    strace ./binary
    ```

    - Просмотрите последние 20-30 строк.
    - Ищите `exit_group(1)` или сигналы (`SIGSEGV`, `SIGILL`).
    - Ищите неудачные попытки открытия конфигов (`ENOENT`) или библиотек.

5. **Проверка лимитов и прав:**
    Проверьте `dmesg | tail` на наличие записей от `OOM Killer` или `AppArmor`/`SELinux`.

### strace: трассировка системных вызовов

**Механизм работы:** `strace` использует системный вызов `ptrace` — способ одному процессу контролировать другой. Когда `strace` подключается к приложению, ядро ставит его на паузу каждый раз при системном вызове, причём **дважды**:

1. **На входе** — чтобы прочитать, какой вызов выполняется и с какими аргументами
2. **На выходе** — чтобы прочитать, что вернуло ядро

Каждый системный вызов = две остановки. Приложение замирает, ждёт, пока `strace` запишет информацию, и только потом продолжает. Это влияет на производительность приложений с большим количеством системных вызовов.

```bash
# Присоединение к работающему процессу
sudo strace -p <PID>

# Запуск и трассировка команды
strace ls -l /несуществующий_файл    # покажет ENOENT
```

**Продвинутые опции:**

```bash
# -f: дочерние процессы (fork/clone)
# -tt: микросекундные метки времени
# -T: время выполнения каждого syscall
sudo strace -f -ttT <команда>

# Фильтрация по типу вызовов
strace -e trace=network,open,openat <команда>

# Сводка по системным вызовам (count)
strace -c <команда>
```

**Типичные сценарии:**

- **Приложение не стартует**, логи пустые, ошибка невнятная — `strace` покажет все файлы, которые приложение успешно открыло или не смогло открыть (`openat`, `stat`), и причина станет ясна.
- **Процесс завис**, но непонятно на чём — `strace -p <PID>` подключается к живому процессу и сразу показывает, на каком системном вызове он застрял.

#### Сценарий: Диагностика «полумертвого» сервиса

Типичная ситуация в проде: CPU почти ноль, процесс в списке есть, рестарт не помогает, логи либо отсутствуют, либо обрываются. Снаружи сервис выглядит «зависшим» без явных ошибок. Скорее всего, процесс застрял внутри системного вызова.

**Алгоритм отладки:**

1. **Подключение к процессу:**

    ```bash
    sudo strace -p <PID>
    ```

    Позволяет сразу увидеть текущее ожидание.

2. **Анализ задержек:**

    ```bash
    sudo strace -T -p <PID>
    ```

    Флаг `-T` показывает время выполнения каждого вызова. Если `connect`, `read` или `futex` висят по несколько секунд — это точка отказа.

3. **Многопоточные приложения:**

    ```bash
    sudo strace -f -p <PID> -tt
    ```

    - `-f` — отслеживать порожденные процессы и потоки.
    - `-tt` — добавляет временные метки с микросекундами (помогает понять, какой поток завис).

**Классификация причин по системным вызовам:**

- **`connect`** — проблемы с сетью или DNS (ожидание ответа от внешнего ресурса).
- **`read` / `write`** — проблемы с дисковой подсистемой или переполненные сокеты.
- **`futex`** — внутренние блокировки (deadlocks) внутри самого приложения.

**Быстрая проверка лимитов:**
Если `strace` показывает ошибки `EMFILE` или процесс ведет себя странно, проверьте количество открытых дескрипторов:

```bash
ls /proc/<PID>/fd | wc -l
```

Подробнее: [Диагностика лимитов открытых файлов](./troubleshooting_too_many_open_files.md).

```bash
# Вызовы функций из libc
ltrace cat /dev/null
```

### gdb: интерактивная отладка

```bash
# Присоединение к процессу (может потребоваться отключение ptrace-защиты)
# sudo sysctl -w kernel.yama.ptrace_scope=0
sudo gdb -p <PID>

# Запуск с аргументами
gdb --args my_program arg1 arg2
```

Основные команды внутри `gdb`: `run`, `break`, `next`, `step`, `print <var>`, `bt` (backtrace).

> **Важно:** При присоединении отладчика (`gdb`, `strace`) процесс **останавливается** (статус `T` — Stopped/Traced). Все сигналы, предназначенные процессу, перехватываются отладчиком. Процесс не будет обрабатывать сигналы (включая SIGTERM), пока отладчик не отсоединится или не передаст сигнал явно (`signal SIGCONT` в gdb). Это критично при отладке production-сервисов — остановка процесса ведёт к недоступности сервиса.

## Additional Information

### Безопасность ptrace

По умолчанию `kernel.yama.ptrace_scope=1` — непривилегированные процессы не могут трассировать друг друга. Для отладки:

```bash
# Временно
sudo sysctl -w kernel.yama.ptrace_scope=0

# Постоянно (/etc/sysctl.d/10-ptrace.conf)
kernel.yama.ptrace_scope = 0
```

### Pressure Stall Information (PSI)

Механизм ядра для точной оценки давления на систему. Позволяет разделять задержки по типам ресурсов (CPU, Memory, I/O).

Подробно: [**PSI — статистика давления на ресурсы**](../../Core/kernel/psi.md).
