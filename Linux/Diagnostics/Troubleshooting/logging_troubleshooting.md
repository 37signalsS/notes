# Диагностика и устранение неполадок логирования

## 1. Отсутствуют логи за временной интервал

**Симптомы:** При поиске в Grafana/Kibana отсутствуют записи за конкретный период, хотя сервис работал.

**Диагностика:**
1. Проверить статус journald: `systemctl status systemd-journald`
2. Проверить сообщения о подавлении логов (Rate Limiting):
   ```bash
   journalctl | grep "Suppressed"
   ```
3. Проверить, не работает ли journald в `volatile` режиме: `ls -la /var/log/journal/`
4. Проверить целостность файлов: `journalctl --verify`

**Решение:**
- Если включен Rate Limiting, увеличьте `RateLimitBurst` в `journald.conf`.
- Если режим `volatile`, создайте директорию `/var/log/journal/` и перезапустите службу.
- Если файлы повреждены, удалите их (предварительно сделав бэкап, если нужно) и перезапустите journald.

## 2. Переполнение диска (/var/log заполнен)

**Симптомы:** Ошибка "No space left on device", `df -h` показывает 100% на `/` или `/var`.

**Диагностика:**
1. Найти самые большие файлы: `sudo du -sh /var/log/* | sort -rh | head -10`
2. Проверить размер журнала: `journalctl --disk-usage`

**Решение:**
- **Очистка journald:**
  ```bash
  sudo journalctl --vacuum-size=500M  # Оставить только 500МБ
  sudo journalctl --vacuum-time=3d    # Оставить за последние 3 дня
  ```
- **Очистка текстовых файлов:** Проверьте, почему не сработал `logrotate`. Принудительно запустите: `sudo logrotate -f /etc/logrotate.conf`.
- **Ручное сжатие:** Если файл огромный и не ротирован, сжмите его: `gzip /var/log/app.log`.

## 3. Проблемы с удаленной пересылкой (Fluent Bit → Loki)

**Симптомы:** Логи есть на сервере (в journald/файлах), но их нет в центральной системе.

**Диагностика:**
1. Проверить логи агента: `journalctl -u fluent-bit -n 100`
2. Проверить сетевую связность: `curl -v http://loki.internal:3100/ready`
3. Проверить базу позиций (tail DB): если она повреждена, агент может перестать читать файлы.

**Решение:**
- Проверьте лимиты на стороне Loki (ошибка 429 Too Many Requests).
- Проверьте кардинальность меток (High Cardinality). Если Loki перегружен индексами, он может отклонять записи.
- Пересоздайте базу позиций Fluent Bit (`/var/log/flb_*.db`), если подозреваете повреждение.

## 4. Проблемы с ротацией (Удаленные открытые файлы)

**Симптомы:** Вы удалили большой лог-файл, но свободное место на диске не появилось.

**Диагностика:**
```bash
sudo lsof +L1 | grep "/var/log"
```
Если вы видите файлы со статусом `(deleted)`, значит процесс все еще держит их открытыми.

**Решение:**
- Перезапустите процесс, держащий файл.
- В будущем используйте `copytruncate` в `logrotate` или настройте приложение на обработку сигнала `SIGHUP`.

## 5. Корреляция логов

**Сценарий:** Нужно найти путь запроса через несколько микросервисов.

**Решение:**
Используйте `grep` или LogQL для поиска по `Correlation-ID` или `Trace-ID`:
```bash
# Поиск на одном хосте во всех логах
grep -r "req-abc-123" /var/log/

# Поиск в Loki
{env="prod"} |= "req-abc-123"
```
