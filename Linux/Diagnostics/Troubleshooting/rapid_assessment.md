# Быстрая диагностика сервера (30 секунд)

## Определения

**Rapid Assessment** — протокол первичной диагностики сервера, выполняемый за 30 секунд после подключения. Позволяет локализовать наиболее вероятные причины деградации производительности.

## Основные концепции

Протокол состоит из пяти последовательных команд, покрывающих CPU, память, диск и процессы:

```bash
# 1. Средняя нагрузка (LA) за 1/5/15 минут
uptime

# 2. Реально свободная память (колонка available)
free -h

# 3. Насыщенность диска (%util), латентность (await), IOPS (r/s, w/s)
iostat -xh 1 3

# 4. Блочное место и индексные дескрипторы
df -h
df -i

# 5. Процессы (сортировка по CPU через F6)
htop
```

## Практические сценарии

### Интерпретация метрик

**Load Average (`uptime`):** Три числа — EWMA за 1, 5, 15 минут. Учитываются процессы в состоянии runnable и uninterruptible sleep (D-state). На 4-ядерной машине `LA = 1.0` ≈ 25%, `LA = 4.0` ≈ 100%, `LA = 6.0` — очередь переполнена. Подробнее: [Планирование процессов и LA](../../Core/processes/scheduling.md).

**Память (`free -h`):** Смотреть на колонку **available** — единственный надёжный показатель реально свободной памяти. Подробнее: [/proc/meminfo](../Memory/proc_meminfo.md).

**Диск (`df -h`, `df -i`):** `/var/log` и `/tmp` — частые источники переполнения. `df -i` при 100% IUse% блокирует создание новых файлов. Расхождение `df` и `du` — признак deleted-but-open файлов (`lsof +L1`). Подробнее: [Диагностика ФС и дискового пространства](../Filesystem/filesystem_and_disk_space_diagnostics.md).

**I/O (`iostat -xh 1 3`):** `%util` — насыщенность диска, `await` — латентность, `r/s`/`w/s` — IOPS. Подробнее: [iostat](../Filesystem/iostat.md).

### Высокий iowait + низкий CPU util

```bash
# Поиск D-state процессов
ps -eo pid,stat,comm | awk '$2~/D/'

# Определение blocking kernel call
cat /proc/<PID>/wchan
```

Подробнее: [iostat](../Filesystem/iostat.md), [ps](../Processes/ps.md).
