# Восстановление прав на исполнение утилиты `chmod`

## Definitions

**chmod recovery** — процесс восстановления прав на исполнение утилиты `/bin/chmod` после их случайного удаления (например, командой `chmod -x /bin/chmod`).

**Системный вызов `chmod(2)`** — низкоуровневый интерфейс ядра Linux для изменения прав доступа к файлам. Большинство альтернативных методов восстановления основаны на прямом обращении к этому вызову в обход бинарного файла `/bin/chmod`.

## Basic Concepts

### Механизм проблемы

Утилита `chmod` — это исполняемый файл, требующий прав на запуск (`+x`). Если эти права сняты, ядро отказывается запускать процесс, и командная оболочка возвращает ошибку:

```bash
$ chmod 755 some_file
# → -bash: /bin/chmod: Permission denied
```

### Ключевые принципы восстановления

- **Использование интерпретаторов** — языки программирования (Python, Perl) имеют встроенные функции, вызывающие `chmod(2)` напрямую через стандартную библиотеку C (glibc).
- **Манипуляция существующими правами** — использование утилит (`cp`, `install`), которые могут создавать или изменять файлы, сохраняя или устанавливая бит исполнения.
- **Обход загрузчика** — запуск динамически скомпилированного бинарника через явный вызов динамического компоновщика (`ld-linux.so`).
- **Внешнее окружение** — использование LiveCD или монтирование файловой системы в другой системе, где `chmod` исправен.

## Practical Scenarios

### Сценарий 1: Интерпретаторы (Python/Perl)

Самый быстрый и надежный способ «изнутри» системы.

**Python 3:**
```bash
python3 -c 'import os; os.chmod("/bin/chmod", 0o755)'
# → (пустой вывод при успехе)
```

**Perl:**
```bash
perl -e 'chmod 0755, "/bin/chmod"'
# → (пустой вывод при успехе)
```

**Когда работает:** Если в системе установлен соответствующий интерпретатор и у него самого есть права на выполнение.

---

### Сценарий 2: Утилиты копирования и установки

**Метод с `cp` (Трюк с перезаписью):**
Если скопировать содержимое `/bin/chmod` в файл, который *уже* имеет права на выполнение, эти права сохранятся.
```bash
cp /bin/ls /tmp/chmod_tmp
cp /bin/chmod /tmp/chmod_tmp
/tmp/chmod_tmp 755 /bin/chmod
# → (права восстановлены)
```

**Метод с `install`:**
Команда `install` умеет устанавливать права доступа в процессе копирования.
```bash
install -m 755 /bin/chmod /tmp/chmod_fixed
/tmp/chmod_fixed 755 /bin/chmod
# → (права восстановлены)
```

---

### Сценарий 3: Динамический компоновщик

Позволяет запустить исполняемый файл, даже если у него нет бита `+x`, так как исполняемым в данном случае является сам компоновщик.

```bash
# Для 64-битных систем
/lib64/ld-linux-x86-64.so.2 /bin/chmod 755 /bin/chmod

# Для 32-битных систем
/lib/ld-linux.so.2 /bin/chmod 755 /bin/chmod
```

**Как найти путь к компоновщику:**
```bash
file /bin/chmod | grep interpreter
# → /bin/chmod: ELF 64-bit LSB pie executable, x86-64, ..., interpreter /lib64/ld-linux-x86-64.so.2, ...
```

---

### Сценарий 4: Оболочки и встроенные модули

**Zsh (встроенный модуль `zsh/files`):**
Zsh позволяет загрузить реализацию `chmod` как встроенную команду (builtin).
```zsh
zmodload zsh/files
chmod +x /bin/chmod
```

**BusyBox:**
Если в системе есть `busybox`, он обычно скомпилирован статически и содержит свою реализацию `chmod`.
```bash
busybox chmod 755 /bin/chmod
```

---

### Сценарий 5: Компиляция C-кода (Rescue Program)

Если в системе есть `gcc`, можно написать и скомпилировать минимальную программу.

```bash
echo '#include <sys/stat.h>
int main() { chmod("/bin/chmod", 0755); return 0; }' > restore.c
gcc restore.c -o restore
./restore
```

---

### Сценарий 6: Пакетный менеджер

Переустановка пакета восстанавливает права всех входящих в него файлов.

**Debian/Ubuntu:**
```bash
sudo apt install --reinstall coreutils
```

**RHEL/CentOS/Fedora:**
```bash
sudo dnf reinstall coreutils
```

---

### Сценарий 7: LiveCD / Внешнее монтирование

Если система не загружается или нет доступа к интерпретаторам.

1. Загрузиться с LiveCD.
2. Примонтировать корневой раздел: `mount /dev/sda1 /mnt`.
3. Исправить права: `chmod +x /mnt/bin/chmod`.

## Additional Information

### Сводная таблица методов

| Метод | Сложность | Требования |
| :--- | :--- | :--- |
| **Python/Perl** | Низкая | Наличие интерпретатора |
| **ld-linux** | Низкая | Знание пути к компоновщику |
| **cp/install** | Средняя | Наличие других исполняемых файлов |
| **BusyBox** | Низкая | Наличие `busybox` |
| **GCC** | Высокая | Наличие компилятора |
| **Reinstall** | Средняя | Доступ к сети/репозиториям |

### Порядок применения (Best Practice)

1. Попробовать **Python/Perl** (самый быстрый путь).
2. Попробовать **ld-linux** (если нет интерпретаторов).
3. Использовать **трюк с `cp`**, если предыдущие методы недоступны.
4. Переустановка пакета или LiveCD — в крайнем случае.

### Предотвращение

- Использование `chmod --preserve-root` для защиты от случайных рекурсивных правок в `/`.
- Регулярный аудит прав системных файлов (утилиты типа `debsums` или `rpm -V`).
