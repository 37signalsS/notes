# Восстановление прав на исполнение утилиты `chmod`

## Definitions

**chmod recovery** — процесс восстановления прав на исполнение утилиты `/bin/chmod` после их случайного удаления (например, командой `chmod -x /bin/chmod`).

**Системный вызов `chmod(2)`** — низкоуровневый интерфейс ядра Linux для изменения прав доступа к файлам, используемый как утилитой `chmod`, так и функциями языков программирования (Perl, Python и др.).

## Basic Concepts

### Механизм проблемы

Утилита `chmod` — это исполняемый файл, требующий прав на запуск (`+x`). При их снятии система возвращает ошибку:

```bash
$ chmod 755 some_file
-bash: /bin/chmod: Permission denied
```

### Ключевые принципы восстановления

- **Обход стандартной утилиты** — использование альтернативных инструментов, выполняющих системный вызов `chmod(2)`
- **Прямой запуск через загрузчик** — использование динамического компоновщика для обхода проверки прав
- **Внешнее окружение** — доступ к файловой системе извне (LiveCD, chroot)

## Practical Scenarios

### Сценарий 1: Интерпретаторы Perl/Python

Используются встроенные функции языков программирования для вызова `chmod(2)`.

**Perl:**
```bash
perl -e 'chmod 0755, "/bin/chmod"'
```

**Python (однострочник):**
```bash
python -c 'import os; os.chmod("/bin/chmod", 0o755)'
```

**Python (heredoc):**
```bash
python3 - <<'EOF'
import os
os.chmod("/bin/chmod", 0o755)
EOF
```

**Когда работает:** при наличии установленного интерпретатора с правами на исполнение.

### Сценарий 2: BusyBox

BusyBox содержит встроенную реализацию `chmod`.

```bash
busybox chmod 755 /bin/chmod
```

**Когда работает:** при наличии установленного `busybox` (часто в минимальных/встраиваемых системах).

### Сценарий 3: Динамический компоновщик

Запуск утилиты через динамический компоновщик обходит стандартную проверку прав.

```bash
# 64-битные системы
/lib64/ld-linux-x86-64.so.2 /bin/chmod 755 /bin/chmod

# 32-битные системы
/lib/ld-linux.so.2 /bin/chmod 755 /bin/chmod
```

**Проверка пути к компоновщику:**
```bash
file /bin/chmod | grep interpreter
```

**Когда работает:** в большинстве дистрибутивов Linux с динамически скомпилированным `chmod`.

### Сценарий 4: Переустановка пакета

Полная переустановка пакета `coreutils`, содержащего `chmod`.

**Debian/Ubuntu:**
```bash
sudo apt-get install --reinstall coreutils
```

**CentOS/RHEL/Fedora:**
```bash
sudo yum reinstall coreutils
# или
sudo dnf reinstall coreutils
```

**Когда работает:** при наличии пакетного менеджера и доступа к репозиториям.

### Сценарий 5: LiveCD/LiveUSB

Крайняя мера — загрузка с внешнего носителя.

1. Загрузить систему с LiveCD/LiveUSB
2. Примонтировать корневую ФС:
   ```bash
   mount /dev/sdXN /mnt
   ```
3. Восстановить права:
   ```bash
   chmod 755 /mnt/bin/chmod
   ```
4. Отмонтировать и перезагрузиться:
   ```bash
   umount /mnt && reboot
   ```

**Когда работает:** при невозможности восстановить систему изнутри.

## Additional Information

### Порядок применения методов

Рекомендуется применять методы в следующем порядке:
1. Perl/Python → 2. BusyBox → 3. Динамический компоновщик → 4. Переустановка пакета → 5. LiveCD

### Предотвращение проблемы

- **Избегайте** команд вида `chmod -R ... /` или `chmod -x` на системных утилитах
- **Используйте** `--preserve-root` для рекурсивных операций
- **Тестируйте** команды изменения прав в staging-окружении
