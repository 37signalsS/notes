# Диагностика утечек файловых дескрипторов и файловых блокировок

## Definitions

**Утечка файловых дескрипторов (FD Leak)** — ситуация, когда процесс не закрывает файловый дескриптор после завершения работы с ресурсом. Приводит к исчерпанию лимитов и ошибке `Too many open files`. Подробнее: [Диагностика "too many open files"](./troubleshooting_too_many_open_files.md).

**Файловая блокировка (File Lock)** — механизм синхронизации доступа к файлу. Некорректное управление блокировками вызывает зависание процессов, ожидающих ресурс.

**FLOCK** — блокировка на уровне файла через системный вызов `flock()`. Advisory-блокировка, не принудительная.

**POSIX Lock (fcntl)** — блокировка на уровне диапазонов байтов через `fcntl()`. Более гранулярная, чем FLOCK.

**Advisory Locking** — режим, при котором процессы добровольно проверяют блокировку перед доступом. Ядро не принуждает.

**Mandatory Locking** — принудительный режим: ядро блокирует доступ к файлу независимо от желания процессов.

## Basic Concepts

### Почему стандартные утилиты могут не помочь

`lsof` полагается на данные `/proc`, которые могут быть неактуальны. Процесс может удерживать дескриптор или блокировку на файле, который кажется свободным.

### Типичные симптомы

- Зависание утилит резервного копирования
- «Подвисание» баз данных (SQLite, etc.) без ошибок в логах
- Невозможность удалить/изменить файл, который не используется видимыми процессами

### Типы блокировок

| Тип | Вызов | Гранулярность | Принудительная |
| :--- | :--- | :--- | :--- |
| FLOCK | `flock()` | Весь файл | Нет (advisory) |
| POSIX | `fcntl()` | Диапазон байтов | Нет (advisory) |
| Mandatory | — | — | Да (ядро) |

## Practical Scenarios

### Сценарий 1: Поиск процесса, удерживающего файл

**Через `/proc`:**

```bash
ls -l /proc/*/fd 2>/dev/null | grep <имя_файла>
```

Поиск символических ссылок в директориях FD всех процессов. Подробнее: [`/proc`](../../FileSystems/virtual_fs_proc.md).

**Через `fuser`:**

```bash
fuser -v <путь_к_файлу>
```

### Сценарий 2: Анализ файловых блокировок

```bash
# Текущие блокировки
lslocks

# Мониторинг в реальном времени
watch -n 1 lslocks
```

**Ключевые поля:**

| Поле | Описание |
| :--- | :--- |
| `COMMAND`, `PID` | Процесс, удерживающий блокировку |
| `TYPE` | Тип (`FLOCK`, `POSIX`) |
| `MODE` | Режим (`READ`, `WRITE`). WRITE — частая причина зависаний |

### Сценарий 3: Анализ процесса и системных лимитов

```bash
# Информация о процессе
ps -fp <PID>

# Детальный анализ FD процесса
lsof -p <PID>
```

Подробнее: [`lsof`](../Processes/lsof.md).

Проверка системных лимитов: [Файловые дескрипторы — мониторинг](../../FileSystems/file_descriptors.md).

### Сценарий 4: Трассировка open/close через strace

```bash
sudo strace -e trace=openat,close -p <PID>
```

Подробнее: [Трассировка и отладка](./tracing_and_debugging.md).

### Сценарий 5: Типичные причины утечек на уровне кода

**HTTP-клиент без пула соединений:** Каждый запрос создаёт новое соединение, под нагрузкой они накапливаются быстрее, чем закрываются.

```go
// ПЛОХО: новый клиент на каждый запрос
http.Get(url)

// ЛУЧШЕ: общий клиент с настроенным Transport
var client = &http.Client{
   Transport: &http.Transport{
       MaxIdleConns:        100,
       MaxIdleConnsPerHost: 10,
       IdleConnTimeout:     90 * time.Second,
   },
}
```

**Подключения к БД без пула:** Большинство драйверов используют пул по умолчанию, но только если переиспользовать экземпляр `*sql.DB` (именно он и есть пул).

**Файлы открываются в горячем цикле без гарантии закрытия:** Если функция открывает файл и при ошибке выходит раньше времени, не вызывая `close()` / `defer .Close()` / `with` / `try-with-resources`, каждый такой сбой оставляет неуправляемый FD.

**Горутины/потоки, бесконечно удерживающие сокеты:** Пул воркеров, бесконтрольно растущий под нагрузкой, создаёт воркер на каждое соединение, и каждый воркер удерживает свой FD.

**Кэш открытых файлов без вытеснения:** Долгоживущий процесс накапливает FD бесконечно.

Во всех этих случаях исправление на уровне кода — единственное правильное решение. Повышение ulimit только маскирует утечку.
