# Диагностика ошибки "too many open files"

## Определения

**Файловый дескриптор** — это уникальный идентификатор (обычно неотрицательное целое число), который процесс использует для доступа к открытому файлу, сокету или другому ресурсу ввода-вывода. Подробнее см. в заметке [о файловых дескрипторах](../../FileSystems/file_descriptors.md).

Ошибка "too many open files" возникает, когда процесс пытается открыть новый файловый дескриптор, но исчерпывает установленные для него лимиты.

## Основные концепции

В Linux существуют "мягкие" (soft) и "жесткие" (hard) лимиты на количество открытых файлов. 
-   **Soft limit:** Текущий действующий лимит для процесса. Любой процесс может увеличить свой soft limit до значения hard limit.
-   **Hard limit:** Максимально возможное значение для soft limit. Изменить hard limit может только процесс с правами суперпользователя (root).

Лимиты могут быть установлены на разных уровнях: для пользователя, для системы в целом или для конкретного сервиса. Подробно механизмы управления лимитами описаны в заметке [**об управлении лимитами процессов в Linux**](../../Core/processes/limits.md).

## Практические сценарии

#### Шаг 1: Подсчет открытых дескрипторов

С помощью утилиты [lsof](../Processes/lsof.md) можно посчитать, сколько файловых дескрипторов уже использует процесс.

```bash
# Посчитать количество открытых файлов для процесса с <PID>
sudo lsof -p <PID> | wc -l
```
Если это число близко к лимиту, вы на верном пути.

#### Шаг 2: Проверка лимитов процесса

```bash
# Прочитать лимиты из /proc
grep "Max open files" /proc/<PID>/limits
```
**Пример вывода:**
```
Max open files            8192                 65535                files
```
Здесь `8192` — это soft limit, а `65535` — hard limit.

#### Шаг 3: Проверка лимитов пользователя и системы

-   **Для текущей сессии:**
    ```bash
    ulimit -n
    ```
-   **На уровне сервиса (`systemd`):**
    Проверьте файл юнита (`/etc/systemd/system/<service_name>.service`) на наличие параметра `LimitNOFILE`.
    ```ini
    [Service]
    LimitNOFILE=10000
    ```
-   **На уровне системы:**
    Глобальные лимиты для пользователей определяются в файле `/etc/security/limits.conf`.

## Дополнительная информация

#### Динамическая трассировка с `strace`

Если вы подозреваете утечку файловых дескрипторов (файлы открываются, но не закрываются), можно использовать [strace](./tracing_and_debugging.md) для отслеживания системных вызовов `openat` и `close` в реальном времени.

```bash
# Отслеживать вызовы openat() и close() для процесса <PID>
sudo strace -e trace=openat,close -p <PID>
```
