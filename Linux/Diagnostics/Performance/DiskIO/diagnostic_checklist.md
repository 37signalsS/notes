# Быстрый чеклист диагностики дискового I/O

## Определения

- **Block I/O**: Операции на уровне блочного устройства, видимые ядру.

## Основные концепции

### Последовательность диагностики

1. Общий I/O на устройствах → 2. Статистика по устройствам → 3. I/O по процессам → 4. Поиск файловых операций → 5. Детальная трассировка

## Практические сценарии

### Чеклист команд

```bash
# 1. Общий I/O на устройствах
vmstat 1
# Смотри: bi/bo (блоки в/из), wa (iowait %)

# 2. Статистика по устройствам
iostat -xz 1
# Смотри: %util, await, avgqu-sz
# Важно: await > 20 мс (HDD) или > 1 мс (SSD) — высокая задержка

# 3. I/O по процессам (интерактивно)
pidstat -d 1
# Сравнивай сумму с vmstat — если не сходится, процесс не попадает в сэмпл

# 4. Кто открывает/пишет файлы
fatrace | head -50
# Показывает все файловые операции в реальном времени

# 5. Детальный I/O к диску (каждый запрос)
biosnoop | head -50
# Требует bcc-tools. Показывает процесс, сектор, размер, задержку

# 6. Проверка на deleted files (открытые, но удалённые)
lsof +L1
# Файлы занимают место, но не видны в ФС

# 7. Статистика по cgroup
cat /sys/fs/cgroup/*/io.stat
# Для systemd: /sys/fs/cgroup/system.slice/<unit>/io.stat

# 8. Ошибки диска в ядре
dmesg | tail -100
# Ищи: "I/O error", "timeout", "reset", "blocked"

# 9. Dirty pages в памяти
cat /proc/meminfo | grep -E "Dirty|Writeback"
# Высокое значение — ядро ждёт сброса

# 10. Детальная статистика устройств (альтернатива iostat)
cat /proc/diskstats
# Поля 6-7: io_ticks, weighted_io_ticks — рост указывает на задержки
```

> **Совет:** Для мониторинга в реальном времени используйте `iostat -x`, а `/proc/diskstats` — для кастомных скриптов и исторического анализа.
