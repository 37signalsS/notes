# Чек-лист диагностики дискового ввода-вывода (I/O)

Данный документ представляет собой пошаговый алгоритм выявления причин деградации производительности дисковой подсистемы — от быстрого анализа до глубокой трассировки.

## Определение

- **I/O Wait (`wa`)**: Процент процессорного времени, в течение которого CPU простаивал, ожидая завершения дисковых операций. Высокие значения (>15%) указывают на наличие узкого места.
- **Pressure Stall Information (PSI)**: Механизм ядра Linux для измерения реального «голодания» ресурсов. Более точный индикатор, чем `iowait`, особенно в многоядерных и облачных системах.
- **Uninterruptible Sleep (D-state)**: Состояние процесса, ожидающего завершения I/O. Такие процессы увеличивают `Load Average` и не могут быть завершены сигналом `SIGKILL`.
- **Latency (Задержка)**: Время выполнения одного запроса (включая очередь). Измеряется в миллисекундах (мс).

## Основные концепции

### Иерархия диагностики

Эффективный поиск проблем I/O строится по принципу «от общего к частному»:

1.  **Обзор системы**: Подтверждение наличия давления на I/O (PSI, `iowait`).
2.  **Анализ устройств**: Поиск конкретного диска или раздела с высокими задержками (`await`).
3.  **Поиск процесса**: Идентификация приложения, генерирующего основную нагрузку (`iotop`, `pidstat`).
4.  **Детализация операций**: Анализ конкретных файлов и системных вызовов (`fatrace`, `strace`).
5.  **Трассировка задержек**: Использование eBPF для поиска «хвостов» латентности (`biolatency`).
6.  **Аппаратная проверка**: Поиск ошибок в логах ядра и проверка здоровья через SMART.

## Практические сценарии

### Шаг 1: Оценка системного давления (PSI и vmstat)

Современный способ начать диагностику — проверить файлы PSI.

```bash
# Проверка давления на I/O (avg10 > 10 — признак проблем)
cat /proc/pressure/io
# → result: some avg10=15.20 avg60=10.05 avg300=5.00 total=1234567

# Общая сводка активности
vmstat 1 5
# → result: (смотреть колонки wa, bi, bo, si, so)
```

**Критические признаки:**
- `wa > 20%`: Диск не справляется.
- `si`/`so > 0`: Активный свопинг, создающий вторичную нагрузку на I/O.

### Шаг 2: Статистика по блочным устройствам (iostat)

Определите, какой именно диск перегружен и как он себя ведет.

```bash
# Расширенная статистика (обновление 1с)
iostat -xz 1
# → result: (смотреть await, avgqu-sz, %util)
```

**Нормативы:**
- `%util > 90%`: Устройство на пределе пропускной способности.
- `await`: Для HDD > 20 мс, для SSD > 1 мс — признак перегрузки или деградации.
- `avgqu-sz > 2`: Постоянная очередь запросов.

### Шаг 3: Поиск виновника среди процессов (iotop/pidstat)

```bash
# Просмотр I/O процессов в реальном времени
sudo iotop -o
# → result: (показывает только процессы, совершающие I/O прямо сейчас)

# Кумулятивная статистика (наиболее точный метод)
pidstat -d 1
# → result: (kB_rd/s, kB_wr/s, iodelay)
```

Если виновники не найдены, но `iowait` высок — изучите [Невидимый ввод-вывод](./invisible_io.md).

### Шаг 4: Анализ файлов и ФС (fatrace/mount)

```bash
# Мониторинг обращений к файлам (требует прав root)
sudo fatrace | head -20
# → result: app(1234): W /var/lib/mysql/data.db

# Проверка опций монтирования (ищите sync, noatime, barrier)
mount | grep -E "ext4|xfs|nfs"
```

**Важно:** Опция `sync` или отсутствие `noatime` может значительно замедлять запись на SSD и БД.

### Шаг 5: Продвинутая трассировка (eBPF)

Используйте, если средние значения в норме, но есть жалобы на периодические «замирания».

```bash
# Гистограмма задержек выполнения I/O
sudo biolatency-bpfcc 1 10
# → result: визуализирует распределение задержек (ищите "хвосты" > 100ms)

# Трассировка каждого конкретного запроса
sudo biosnoop-bpfcc | head -20
# → result: (время, процесс, диск, латентность каждой операции)
```

### Шаг 6: Облачный троттлинг и аппаратные логи

В облачных средах (AWS/GCP/Azure) задержка часто вызвана исчерпанием лимитов IOPS/Burst.

```bash
# Поиск сообщений о блокировках и ошибках в логах ядра
dmesg | grep -iE "i/o|error|blocked|timeout"
# → result: blk_update_request: I/O error, dev sda...
```

Если обнаружены аппаратные ошибки, переходите к [SMART-диагностике](../Hardware/smartctl/disk_health_check.md).

## Дополнительная информация

### Установка инструментов

Большинство утилит входят в пакеты:
- **`sysstat`**: `iostat`, `pidstat`.
- **`iotop`**: `iotop`.
- **`bcc-tools`** / **`bpfcc-tools`**: eBPF скрипты (`biolatency`).
- **`fatrace`**: `fatrace`.
