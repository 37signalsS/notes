# /proc/diskstats — статистика блочных устройств

## Определение

**`/proc/diskstats`** — это низкоуровневый интерфейс ядра Linux, предоставляющий кумулятивные счетчики активности для всех зарегистрированных блочных устройств (физических дисков, разделов, LVM-томов, MD-RAID и виртуальных устройств типа loop/zram).

Данные из `/proc/diskstats` являются первоисточником для большинства диагностических утилит, включая `iostat`, `sar`, `vmstat`, а также для экспортеров систем мониторинга (Prometheus Node Exporter, Zabbix Agent).

## Основные концепции

### Формат данных и версии ядра

Каждая строка в файле представляет собой снимок счетчиков для конкретного устройства. Количество полей в строке росло вместе с развитием подсистемы I/O ядра:
- **Linux < 4.18**: 14 полей (базовая статистика чтения/записи).
- **Linux 4.18+**: 18 полей (добавлена статистика Discard/TRIM).
- **Linux 5.5+**: 20 полей (добавлены Flush-запросы для обеспечения целостности данных).

### Детальная расшифровка полей

| № | Поле | Описание |
| :--- | :--- | :--- |
| 1 | Major number | Основной номер драйвера устройства. |
| 2 | Minor number | Порядковый номер устройства в рамках драйвера. |
| 3 | Device name | Имя устройства (например, `sda`, `nvme0n1`, `dm-0`). |
| 4 | Reads completed | Общее количество успешно завершенных операций чтения. |
| 5 | Reads merged | Количество операций чтения, объединенных планировщиком I/O (например, два запроса к соседним секторам объединяются в один). |
| 6 | Sectors read | Количество прочитанных секторов. **Всегда 512 байт**, независимо от физического размера сектора диска. |
| 7 | Time spent reading (ms) | Суммарное время, затраченное на все операции чтения (от момента постановки в очередь до завершения). |
| 8 | Writes completed | Общее количество успешно завершенных операций записи. |
| 9 | Writes merged | Количество операций записи, объединенных планировщиком I/O. |
| 10 | Sectors written | Количество записанных секторов (в единицах по 512 байт). |
| 11 | Time spent writing (ms) | Суммарное время, затраченное на все операции записи. |
| 12 | I/O in progress | Количество операций, находящихся в обработке в данный момент. Значение инкрементируется при выдаче запроса и декрементируется при его завершении. |
| 13 | Time spent doing I/O (ms) | Время, в течение которого поле 12 было ненулевым. Позволяет рассчитать общую утилизацию устройства. |
| 14 | Weighted I/O time (ms) | Интеграл длины очереди по времени. Каждое изменение поля 12 умножается на время с момента последнего изменения. Служит для точного расчета `avgqu-sz`. |
| 15 | Discards completed | Количество успешно выполненных операций отмены (TRIM/Unmap). |
| 16 | Discards merged | Количество объединенных операций Discard. |
| 17 | Sectors discarded | Количество секторов, помеченных как свободные. |
| 18 | Time spent discarding | Суммарное время, затраченное на выполнение Discard. |
| 19 | Flush requests completed | Количество выполненных Flush-запросов (сброс аппаратного кэша диска на пластины/флеш). |
| 20 | Time spent flushing | Суммарное время, затраченное на выполнение Flush-запросов. |

## Практические сценарии

### Расчет классических метрик iostat

Поскольку все значения в `/proc/diskstats` являются нарастающими (counters), для получения мгновенных значений нужно взять два снимка с интервалом $\Delta t$.

#### 1. Утилизация (%util)
Метрика показывает, какую часть времени диск был занят хотя бы одной операцией.
$$\%util = \frac{\Delta \text{Field\_13}}{\Delta t} \times 100\%$$

#### 2. Средняя длина очереди (avgqu-sz)
Использует взвешенное время для учета всех всплесков внутри интервала.
$$avgqu\text{-}sz = \frac{\Delta \text{Field\_14}}{\Delta t}$$

#### 3. Среднее время ожидания (await)
Общее время, проведенное запросом в очереди и в обработке диском.
$$await = \frac{\Delta \text{Field\_7} + \Delta \text{Field\_11}}{\Delta \text{Field\_4} + \Delta \text{Field\_8}}$$

### Скрипты для быстрого анализа

#### Извлечение статистики для конкретного диска
```bash
# Получение данных для диска sda
awk '$3 == "sda"' /proc/diskstats
```

#### Мониторинг "Flush-штормов" (для ядер 5.5+)
Частые Flush-запросы могут указывать на неоптимальную работу БД или журналов ФС (синхронная запись).
```bash
watch -n1 "awk '\$3 == \"sda\" {print \"Flush requests:\", \$19, \"| Time:\", \$20 \"ms\"}' /proc/diskstats"
```

## Дополнительная информация

### Нюансы интерпретации

1. **Размер сектора**: Важно помнить, что ядро всегда считает сектор равным 512 байтам в данном интерфейсе. Для перевода в мегабайты: `(sectors * 512) / 1024 / 1024`.
2. **Виртуальные устройства**: Для LVM (`dm-*`) или MD-RAID некоторые поля могут быть всегда равны нулю (например, merged requests), так как объединение происходит на уровне нижележащих физических устройств.
3. **Flush и целостность**: Высокое время в поле 20 при малом количестве запросов в поле 19 может указывать на проблемы с прошивкой диска или аппаратным контроллером RAID без BBU/Flash-защиты.
