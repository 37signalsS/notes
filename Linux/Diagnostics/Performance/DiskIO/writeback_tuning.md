# Настройка writeback: параметры ядра

## Определение

- **Грязные страницы (Dirty Pages)**: Страницы оперативной памяти в системном кэше (Page Cache), которые содержат изменённые приложением данные, ещё не записанные на физический диск.
- **Обратная запись (Writeback)**: Фоновый механизм ядра Linux по сбросу изменённых данных из оперативной памяти на устройство хранения.

## Основные концепции

Ядро Linux использует отложенную запись для повышения производительности дисковой подсистемы. Параметры `vm.dirty_*` позволяют сбалансировать скорость работы, риск потери данных при сбое и отзывчивость системы.

### Ключевые параметры тюнинга

| Параметр | По умолчанию | Описание | Рекомендация |
| :--- | :--- | :--- | :--- |
| **`vm.dirty_background_ratio`** | 10 | % RAM, при котором фоновые потоки (`kworker`) начинают асинхронную запись. Не блокирует приложения. | 5–10% |
| **`vm.dirty_ratio`** | 20 | % RAM, при котором процесс принудительно блокируется до освобождения памяти (I/O Stall). | 10–40% |
| **`vm.dirty_background_bytes`** | 0 | Альтернатива `ratio` в байтах. Имеет приоритет над `ratio`. | 64MB–256MB |
| **`vm.dirty_bytes`** | 0 | Альтернатива `ratio` в байтах. Имеет приоритет над `ratio`. | 512MB–1GB |
| **`vm.dirty_expire_centisecs`** | 3000 | Время (в 0.01 сек), по истечении которого страница помечается как «старая» и готовая к сбросу. | 3000 (30с) |
| **`vm.dirty_writeback_centisecs`** | 500 | Интервал (в 0.01 сек) пробуждения потоков `kworker` для проверки наличия «старых» страниц. | 500 (5с) |

### Проблема больших объёмов оперативной памяти

На современных серверах с 128 ГБ+ RAM значения по умолчанию (10%/20%) становятся опасными:
- **10% от 128 ГБ** = 12.8 ГБ грязных данных в памяти.
- При внезапном сбросе такого объёма возникает «I/O storm», полностью блокирующий диск на несколько секунд или даже минут.
- **Решение**: Использовать абсолютные значения через `vm.dirty_bytes` и `vm.dirty_background_bytes`, чтобы ограничить кэш записи разумными пределами (например, до 1–2 ГБ), которые диск способен сбросить быстро.

## Практические сценарии

### Просмотр и временная настройка

```bash
# Просмотр текущих значений параметров грязных страниц
sysctl -a | grep vm.dirty
# → result: vm.dirty_background_ratio = 10, vm.dirty_ratio = 20 ...

# Временное изменение (сбросится после перезагрузки)
sudo sysctl -w vm.dirty_ratio=15
sudo sysctl -w vm.dirty_background_ratio=7
# → result: vm.dirty_ratio = 15, vm.dirty_background_ratio = 7
```

### Профили настройки под разные нагрузки

#### Базы данных (PostgreSQL, MySQL) и низкая задержка

Цель: минимизировать риск потери данных и избежать замираний (stalls) при сбросе.

```bash
# Более агрессивный фоновый сброс
vm.dirty_background_ratio = 5
vm.dirty_ratio = 10
vm.dirty_writeback_centisecs = 300
vm.swappiness = 1
```

#### Системы с большим объёмом RAM (128 ГБ+)

Цель: ограничение абсолютного размера кэша для предотвращения I/O storms.

```bash
# Ограничение 256 МБ для фона и 1 ГБ для блокировки
vm.dirty_background_bytes = 268435456
vm.dirty_bytes = 1073741824
```

#### Файловые серверы (высокая пропускная способность)

Цель: максимальное накопление данных для последовательной записи большими блоками.

```bash
vm.dirty_background_ratio = 20
vm.dirty_ratio = 40
vm.dirty_writeback_centisecs = 1000
```

### Сохранение настроек (постоянно)

```bash
# Создание конфигурационного файла
cat << EOF | sudo tee /etc/sysctl.d/99-writeback.conf
vm.dirty_ratio = 10
vm.dirty_background_ratio = 5
vm.dirty_expire_centisecs = 3000
vm.dirty_writeback_centisecs = 300
EOF
# → result: (создан файл /etc/sysctl.d/99-writeback.conf)

# Применение изменений
sudo sysctl --system
# → result: * Applying /etc/sysctl.d/99-writeback.conf ...
```
