# Настройка writeback: параметры ядра

## Определение

- **Грязные страницы (Dirty Pages)**: Страницы оперативной памяти в системном кэше (Page Cache), которые содержат изменённые приложением данные, ещё не записанные на физический диск.
- **Обратная запись (Writeback)**: Фоновый механизм ядра Linux по сбросу изменённых данных из оперативной памяти на устройство хранения.

## Основные концепции

Ядро Linux использует отложенную запись для повышения производительности дисковой подсистемы. Параметры `vm.dirty_*` позволяют сбалансировать скорость работы, риск потери данных при сбое и отзывчивость системы.

### Ключевые параметры тюнинга

| Параметр | По умолчанию | Описание | Рекомендация |
| :--- | :--- | :--- | :--- |
| **`vm.dirty_background_ratio`** | 10 | % RAM, при котором фоновые потоки (`kworker`) начинают асинхронную запись. Не блокирует приложения. | 5–10% |
| **`vm.dirty_ratio`** | 20 | % RAM, при котором процесс принудительно переводится в синхронный режим записи (блокируется) до освобождения памяти. | 10–40% |
| **`vm.dirty_expire_centisecs`** | 3000 | Максимальное время (в 0.01 сек), в течение которого страница может оставаться «грязной». | 3000–6000 |
| **`vm.dirty_writeback_centisecs`** | 500 | Интервал (в 0.01 сек), с которым просыпаются потоки сброса для проверки Page Cache. | 300–500 |
| **`vm.swappiness`** | 60 | Степень агрессивности вытеснения страниц в swap. Влияет на баланс между кэшем и анонимной памятью. | 1–10 (БД), 60 (общее) |

### Механизмы сброса данных

1. **Асинхронный сброс**: При достижении `vm.dirty_background_ratio` ядро начинает фоновую запись. Приложения продолжают работать без задержек.
2. **Синхронный сброс (Stalls)**: При достижении `vm.dirty_ratio` ядро блокирует новые записи от приложений до тех пор, пока объём грязных страниц не снизится. Это вызывает ощутимые «подвисания» (I/O stalls).

## Практические сценарии

### Просмотр и временная настройка

```bash
# Просмотр текущих значений всех параметров dirty pages
sysctl -a | grep vm.dirty

# Временное изменение (сбросится после перезагрузки)
sudo sysctl -w vm.dirty_ratio=15
sudo sysctl -w vm.dirty_background_ratio=7
```

### Профили настройки под разные нагрузки

#### Базы данных и системы с низкой задержкой

Цель: избежать внезапных блокировок («I/O storms») и минимизировать риск потери данных.

```bash
vm.dirty_ratio = 10
vm.dirty_background_ratio = 5
vm.dirty_writeback_centisecs = 300
vm.swappiness = 1
```

#### Файловые серверы и бэкапы (высокая пропускная способность)

Цель: максимально использовать Page Cache для объединения мелких записей в большие блоки.

```bash
vm.dirty_ratio = 40
vm.dirty_background_ratio = 20
vm.dirty_writeback_centisecs = 500
```

#### Медленные накопители (HDD, сетевые диски)

Цель: увеличить лимиты, чтобы позволить планировщику I/O эффективнее группировать запросы.

```bash
vm.dirty_ratio = 30
vm.dirty_background_ratio = 15
vm.dirty_writeback_centisecs = 300
```

### Сохранение настроек (постоянно)

Для сохранения параметров после перезагрузки необходимо внести их в `/etc/sysctl.conf` или создать файл в `/etc/sysctl.d/`:

```bash
# Пример создания конфигурационного файла
cat << EOF | sudo tee /etc/sysctl.d/99-writeback.conf
vm.dirty_ratio = 10
vm.dirty_background_ratio = 5
vm.dirty_expire_centisecs = 3000
vm.dirty_writeback_centisecs = 300
EOF

# Применение изменений без перезагрузки
sudo sysctl --system
```
