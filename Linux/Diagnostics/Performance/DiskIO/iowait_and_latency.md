# Низкий iowait при высокой задержке диска

## Определения

- **I/O Wait (`wa`)**: Процент времени, в течение которого процессор простаивал, ожидая завершения операций ввода-вывода. Высокое значение указывает на bottleneck в дисковой подсистеме.

## Основные концепции

### Проблема

Метрики выглядят нормально: `iowait` низкий, CPU свободен, но операции с диском выполняются медленно.

### Причина

`iowait` показывает только время, когда CPU простаивает в ожидании I/O. Если процессы находятся в очереди на диск, но CPU не заблокирован, `iowait` остаётся низким.

### Механизм

1. Процессы отправляют I/O запросы и переходят в `D-state` (uninterruptible sleep)
2. Запросы накапливаются в очереди устройства (`avgqu-sz`)
3. CPU переключается на другие задачи → `iowait` не растёт
4. Латентность диска (`await`) высокая, но CPU не ждёт активно

## Практические сценарии

### Диагностика

```bash
# Ключевая команда — расширенная статистика iostat
iostat -x 1

# Ключевые поля:
# - await > 20 мс (HDD) или > 1 мс (SSD) — высокая задержка
# - avgqu-sz > 1-2 — растущая очередь
# - %util может быть умеренным (не 100%)
```

### Типичные сценарии

- **Burst-запись:** Writeback, логи, бэкапы — короткие всплески записи
- **Смешанная нагрузка read/write:** Устройство не успевает обслуживать очередь равномерно
- **Медленный диск:** Латентность устройства высокая, но очередь не блокирует CPU

> **Важно:** Смотрите не на `iowait`, а на `await` и `avgqu-sz` в `iostat -x`.
