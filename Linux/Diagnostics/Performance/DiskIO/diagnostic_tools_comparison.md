# Сравнение инструментов диагностики дискового ввода-вывода (I/O)

В данном разделе представлен обзор и классификация утилит, используемых для анализа производительности дисковой подсистемы в Linux.

## Определение

- **Уровни диагностики**: Иерархический подход к поиску проблем, начинающийся с общего состояния устройства (латентность, утилизация) и заканчивающийся детальным анализом конкретных файловых операций и системных вызовов.
- **Блочный ввод-вывод (Block I/O)**: Операции на уровне блочного устройства (диска или раздела), которые обрабатываются ядром.

## Основные концепции

### Классификация по уровням анализа

| Уровень | Инструменты | Что позволяют увидеть |
| :--- | :--- | :--- |
| **Устройство** | `iostat -xz`, `vmstat`, `/proc/diskstats` | Общая утилизация, латентность (`await`), длина очереди. |
| **Процесс** | `iotop`, `pidstat -d`, `/proc/<pid>/io` | Распределение нагрузки (чтение/запись) между процессами. |
| **Файл** | `fatrace`, `lsof` | Конкретные файлы, к которым идут обращения, и дескрипторы. |
| **Блок** | `biosnoop`, `blktrace` | Каждый отдельный запрос I/O с точной задержкой и сектором. |

### Сравнительные характеристики утилит

| Инструмент | Уровень | Преимущества | Ограничения |
| :--- | :--- | :--- | :--- |
| **`iostat`** | Устройство | Золотой стандарт для анализа латентности и пропускной способности. | Не привязывает нагрузку к конкретным процессам. |
| **`iotop`** | Процесс | Интерактивный интерфейс, удобен для быстрого поиска. | Может пропускать кратковременные всплески нагрузки. |
| **`pidstat -d`** | Процесс | Точная интервальная статистика, удобен для скриптов. | Не отображает ядерные потоки (например, flush). |
| **`fatrace`** | Файл | Видны все обращения к ФС в реальном времени. | Не предоставляет данных об объёме (Байтах) I/O. |
| **`biosnoop`** | Блок | Показывает задержку каждого запроса и «виновника». | Требует наличия `bcc-tools` / eBPF в системе. |
| **`blktrace`** | Блок | Максимально полная трассировка всех событий очереди. | Сложность интерпретации сырого вывода. |
| **`/proc/<pid>/io`**| Процесс | Кумулятивная статистика с момента старта процесса. | Не подходит для мониторинга в реальном времени. |

## Практические сценарии

### Выбор инструмента в зависимости от задачи

**1. Подтверждение проблемы на диске**
Если система «тормозит», начните с **`iostat -xz 1`**. Ориентируйтесь на `await` (задержка > 20 мс для HDD — проблема) и `avgqu-sz` (очередь > 2).

**2. Поиск процесса-виновника**
Если `iostat` подтвердил нагрузку, используйте **`iotop -o`** или **`pidstat -d 1`**. Если в списке только `kworker`, изучите раздел [Невидимый I/O](./invisible_io.md).

**3. Идентификация файлов при анонимной нагрузке**
Если процесс известен, но непонятно, что он пишет, запустите **`fatrace`** или проверьте открытые файлы через **`lsof -p <PID>`**.

**4. Расследование «затыков» оборудования**
Если подозревается медленный контроллер или диск, используйте **`biosnoop`** для анализа задержки конкретных аппаратных запросов.

### Системные требования

| Инструмент | Пакет | Режим запуска | Зависимости ядра |
| :--- | :--- | :--- | :--- |
| `iostat` / `pidstat` | `sysstat` | Пользователь | — |
| `iotop` | `iotop` | Root | `CONFIG_TASKSTATS` |
| `fatrace` | `fatrace` | Root | `CONFIG_FANOTIFY` |
| `biosnoop` | `bpfcc-tools` | Root | eBPF / BPF |
