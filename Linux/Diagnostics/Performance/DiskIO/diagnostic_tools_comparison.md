# Сравнение инструментов диагностики дискового ввода-вывода (I/O)

В данном разделе представлен обзор и классификация утилит, используемых для анализа производительности дисковой подсистемы в Linux — от базовых счётчиков до глубокой eBPF-трассировки.

## Определение

- **Уровни диагностики**: Иерархический подход к поиску проблем, начинающийся с системного давления (PSI) и состояния устройства, и заканчивающийся детальным анализом конкретных файловых операций и секторов диска.
- **Блочный ввод-вывод (Block I/O)**: Операции на уровне блочного устройства (диска или раздела), которые обрабатываются ядром и планировщиком.
- **Pressure Stall Information (PSI)**: Метрики ядра, показывающие время ожидания ресурсов (I/O, CPU, RAM) из-за их дефицита.

## Основные концепции

### Классификация по уровням анализа

| Уровень | Инструменты | Что позволяют увидеть |
| :--- | :--- | :--- |
| **Система (PSI)** | `cat /proc/pressure/io` | Общее «голодание» системы по вводу-выводу. |
| **Устройство** | `iostat -xz`, `vmstat`, `/proc/diskstats` | Общая утилизация, латентность (`await`), длина очереди. |
| **Контейнер / Cgroup**| `systemd-cgtop`, `io.stat` | Нагрузка и лимиты (Throttling) в рамках конкретной группы. |
| **Процесс** | `iotop`, `pidstat -d`, `/proc/<pid>/io` | Распределение нагрузки (чтение/запись) между процессами. |
| **Файл** | `fatrace`, `lsof` | Конкретные файлы, к которым идут обращения, и дескрипторы. |
| **Блок (eBPF)** | `biolatency`, `biosnoop`, `biotop` | Гистограммы задержек, трассировка каждого запроса. |

### Сравнительные характеристики утилит

| Инструмент | Уровень | Преимущества | Ограничения |
| :--- | :--- | :--- | :--- |
| **`PSI`** | Система | Самый точный индикатор влияния I/O на задержки приложений. | Требует ядро 4.20+, не показывает источник. |
| **`iostat`** | Устройство | Золотой стандарт для анализа латентности оборудования. | Не привязывает нагрузку к процессам. |
| **`syswatch`** | Комплексный | Наглядный TUI, автоматический анализ причин (Insights). | Требует установки, не хранит долгую историю. |
| **`iotop`** | Процесс | Интерактивный режим, удобен для быстрого поиска. | Может пропускать всплески < 1с. |
| **`pidstat -d`** | Процесс | Точная интервальная статистика, удобен для скриптов. | Не отображает ядерные потоки (Writeback). |
| **`fatrace`** | Файл | Видны все обращения к ФС в реальном времени. | Не предоставляет данных об объёме (Байтах). |
| **`biolatency`**| Блок | Показывает "хвосты" задержек через гистограммы. | Требует eBPF (bcc-tools). |
| **`biosnoop`** | Блок | Показывает задержку каждой конкретной операции. | Высокая нагрузка при очень интенсивном I/O. |

## Практические сценарии

### Выбор инструмента в зависимости от задачи

**1. Первичная оценка влияния на систему**
Начните с проверки PSI, чтобы понять, является ли I/O причиной «тормозов» приложений.
```bash
cat /proc/pressure/io
# → result: some avg10=15.20 (высокое давление, I/O — узкое место)
```

**2. Подтверждение проблемы на уровне железа**
Используйте `iostat` для анализа латентности конкретного диска.
```bash
iostat -xz 1
# → result: await > 20ms (для HDD) или > 1ms (для SSD)
```

**3. Поиск процесса-виновника**
Если диск перегружен, найдите самое активное приложение.
```bash
sudo iotop -o
# → result: показывает PID и скорость чтения/записи активных процессов
```

**4. Анализ распределения задержек (Outliers)**
Если средняя задержка в норме, но есть жалобы на редкие фризы, используйте eBPF.
```bash
sudo biolatency-bpfcc 1 10
# → result: гистограмма с распределением латентности запросов
```
