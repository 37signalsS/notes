# `perf`

## Определение

**`perf`** — официальный инструмент профилирования производительности в ОС Linux. Он использует аппаратные счётчики производительности процессора (Performance Monitoring Units, PMU) и программные точки трассировки ядра для глубокого анализа работы системы и приложений. `perf` позволяет выявлять «горячие» функции, промахи кэша, задержки планировщика и другие узкие места на уровне кода.

## Основные концепции

### Механизмы сбора данных

- **Событийно-ориентированный подход:** `perf` отслеживает конкретные события (циклы CPU, инструкции, промахи кэша L1/LLC, переключения контекста).
- **Сэмплирование (Sampling):** Инструмент периодически прерывает выполнение процессора (например, с частотой 99 Гц) и записывает текущий указатель инструкций и стек вызовов. Это позволяет статистически определить, на какие участки кода тратится больше всего времени.
- **Инструментирование (Instrumentation):** Использование статических (tracepoints) и динамических (kprobes, uprobes) точек трассировки для анализа логики работы ядра и приложений.

### Файлы данных

Результаты работы подкоманды `perf record` сохраняются в бинарный файл `perf.data` в текущей директории. Для его анализа используются другие подкоманды (`perf report`, `perf script`).

### Требования

Для полноценной работы `perf` необходимы:

- Права суперпользователя (`root`).
- Установленные пакеты: `linux-tools-common` и версию для текущего ядра `linux-tools-$(uname -r)`.
- Настройка `kernel.perf_event_paranoid` (обычно значение `1` или `-1` для расширенного доступа).

## Практические сценарии

### Мониторинг функций в реальном времени (`perf top`)

Отображает наиболее активные функции ядра и пользовательских приложений в реальном времени, аналогично утилите `top`.

```bash
sudo perf top
```

### Запись и анализ профиля (`perf record` и `perf report`)

Сбор детальной статистики выполнения процесса для последующего глубокого анализа.

```bash
# Сбор данных с частотой 99 Гц, включая граф вызовов (-g) для конкретного PID
sudo perf record -F 99 -p <PID> -g -- sleep 10

# Интерактивный анализ сохранённого отчёта (perf.data)
perf report
```

### Анализ аппаратных событий и ошибок страниц (`perf stat`)

Подсчёт общего количества событий за время выполнения команды.

```bash
# Подсчёт отказов страниц (page faults) для новой команды
perf stat -e page-faults,minor-faults,major-faults <команда>

# Анализ работающего процесса в течение 10 секунд
perf stat -e page-faults,minor-faults,major-faults -p <PID> sleep 10
```

- **`minor-faults`:** страница памяти уже в RAM, но не в таблице страниц процесса (нормальное поведение).
- **`major-faults`:** требуется чтение с диска (признак нехватки RAM или активного использования `mmap`). Подробнее — в [Управление Swap](../../Core/memory/swap_management.md#диагностика-page-faults).

### Диагностика задержек планировщика (`perf sched`)

Анализ времени ожидания процессов в очереди на выполнение (Runnable state).

```bash
# Запись событий планировщика для всей системы
sudo perf sched record -a sleep 10

# Вывод таблицы задержек (latencies)
sudo perf sched latency
```

Ключевые метрики: `avg delay` (среднее время ожидания CPU), `max delay` (максимальный «затык»).

### Трассировка системных вызовов (`perf trace`)

Легковесная альтернатива `strace` с меньшими накладными расходами.

```bash
# Отслеживание системных вызовов futex (ожидание блокировок) в реальном времени
sudo perf trace -e futex
```

### Визуализация через Flame Graphs

Для создания наглядных схем («пламенных графиков») используются скрипты Брендана Грегга.

```bash
# 1. Запись профиля с графами вызовов
sudo perf record -F 99 -ag -- sleep 30

# 2. Преобразование в промежуточный формат
perf script | ./stackcollapse-perf.pl > out.perf-folded

# 3. Генерация SVG-файла
./flamegraph.pl out.perf-folded > perf-flamegraph.svg
```

## Дополнительная информация

### Визуальный анализ

Flame Graphs позволяют быстро идентифицировать самые широкие «полки» — функции, в которых приложение проводит больше всего времени. Скрипты для генерации доступны в [репозитории FlameGraph](https://github.com/brendangregg/FlameGraph).
