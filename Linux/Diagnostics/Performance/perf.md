# `perf`

## Определение

`perf` — это мощный и официальный инструмент для профилирования производительности в Linux. Он использует счетчики производительности процессора (Performance Monitoring Units, PMU) для глубокого анализа работы как ядра, так и пользовательских приложений, позволяя выявлять "узкие места" на уровне функций.

## Основные концепции

- **Событийно-ориентированный подход:** `perf` работает, отслеживая события, такие как циклы CPU, промахи кэша, переключения контекста или вызовы функций.
- **Сэмплирование (Sampling):** `perf` периодически прерывает выполнение системы (например, 99 раз в секунду) и записывает, какая функция выполнялась в этот момент. Статистический анализ этих "сэмплов" показывает, какие функции потребляют больше всего ресурсов.
- **`perf.data`:** Бинарный файл, в который `perf record` сохраняет собранные данные о производительности для последующего анализа.

## Практические сценарии

> **Примечание:** Для работы `perf` могут потребоваться права `root` и установка дополнительных пакетов (например, `linux-tools-common`, `linux-tools-$(uname -r)`).

**Мониторинг "горячих" функций в реальном времени (`perf top`)**

Аналог `top`, но на уровне функций. Показывает, какие функции (в ядре или приложениях) потребляют больше всего CPU в данный момент.

```bash
sudo perf top
```

**Запись и анализ профиля (`perf record` & `perf report`)**

1.  **Записать профиль** работы процесса с указанным PID:
    ```bash
    # Сбор данных с частотой 99 Гц, включая граф вызовов (-g)
    sudo perf record -F 99 -p <PID> -g -- sleep 10
    ```
2.  **Проанализировать отчет:**
    `perf report` читает созданный `perf.data` и представляет интерактивный отчет, где можно "проваливаться" в вызовы функций.
    ```bash
    perf report
    ```

## Дополнительная информация

### Создание Flame Graphs

Данные, собранные с помощью `perf record -g`, идеально подходят для визуализации в виде **Flame Graphs** — мощного инструмента для наглядного представления профиля производительности. Для этого требуются скрипты Брендана Грегга.
```bash
# 1. Записать данные с графом вызовов
sudo perf record -F 99 -ag -- sleep 30

# 2. Сгенерировать "свернутый" стек
perf script | ./stackcollapse-perf.pl > out.perf-folded

# 3. Создать SVG-график
./flamegraph.pl out.perf-folded > perf-flamegraph.svg
```
Это позволяет одним взглядом оценить, какие ветви кода являются самыми "горячими".

### Анализ задержек планировщика (`perf sched`)

Бывают ситуации, когда `load average` низкий и `CPU idle` высокий, но приложение всё равно работает медленно. Часто причина кроется не в самих вычислениях, а в задержках планировщика (`scheduler latency`) — ядро по какой-то причине не отдает процессорное время готовому к работе процессу. `perf sched` помогает диагностировать именно такие проблемы.

#### Что показывает `perf sched latency`?

Команда измеряет, сколько времени процесс проводит в состоянии `Runnable` после пробуждения, но перед тем, как ему фактически выделят CPU для выполнения. Если эти задержки велики, значит, процесс "тормозит" не из-за своего кода, а из-за высокой конкуренции за процессорное время или неоптимальных настроек планировщика.

#### Практические сценарии

1.  **Сбор данных о событиях планировщика**
    Команда `perf sched record` собирает события, связанные с работой планировщика.
    ```bash
    # Дайте системе поработать под нагрузкой 10–30 секунд
    sudo perf sched record sleep 30
    ```
    После выполнения в текущем каталоге будет создан файл `perf.data`.

2.  **Анализ задержек**
    Команда `perf sched latency` обрабатывает собранные данные и показывает сводную статистику по задержкам.
    ```bash
    sudo perf sched latency
    ```
    В выводе обращайте внимание на:
    -   **`avg delay`**: средняя задержка планирования.
    -   **`max delay`**: максимальная (пиковая) задержка.
    -   **Конкретные PID и имена процессов**, испытывающие наибольшие задержки.

3.  **Поиск процессов, страдающих от задержек**
    Чтобы отсортировать вывод и найти процессы, которые дольше всех ждут CPU, можно использовать `sort`.
    ```bash
    sudo perf sched latency | sort -k5 -n
    ```
    Эта команда сортирует процессы по пятому полю (средняя задержка), показывая главных "пострадавших".

**Анализ системных вызовов и блокировок (`perf trace`)**

`perf trace` — это аналог `strace`, но с меньшими накладными расходами. Он позволяет отслеживать системные вызовы для конкретного процесса или всей системы. Это особенно полезно для диагностики проблем, связанных с блокировками, например, при поиске причин **[tail latency](./diagnosing_tail_latency.md)**.

Пример отслеживания ожиданий на `futex` (механизм блокировок в ядре):

```bash
# Отслеживать системные вызовы futex для всей системы
sudo perf trace -e futex
```
Если в выводе много долгих ожиданий, это может указывать на высокую конкуренцию за блокировки в приложении.

#### Дополнительная информация

Анализ задержек планировщика является практическим дополнением к теоретическим основам работы [планировщика задач в Linux](../../Core/processes/scheduling.md).
