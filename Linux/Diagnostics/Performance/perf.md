# `perf`

## Определения

`perf` — официальный инструмент профилирования производительности в Linux. Использует счётчики производительности процессора (Performance Monitoring Units, PMU) для анализа работы ядра и пользовательских приложений, позволяя выявлять узкие места на уровне функций.

Для оперативного мониторинга системы в реальном времени используются [`dstat`](./dstat.md), для долгосрочного анализа — [`sar`](./sar.md) и [`atop`](./atop.md).

## Основные концепции

- **Событийно-ориентированный подход:** `perf` отслеживает события: циклы CPU, промахи кэша, переключения контекста, вызовы функций.
- **Сэмплирование (Sampling):** `perf` периодически прерывает выполнение системы (например, 99 раз/с) и записывает выполняемую функцию. Статистический анализ сэмплов показывает функции с наибольшим потреблением ресурсов.
- **`perf.data`:** бинарный файл, в который `perf record` сохраняет данные для последующего анализа.

## Практические сценарии

> Для работы `perf` требуются права `root` и пакеты `linux-tools-common`, `linux-tools-$(uname -r)`.

### Мониторинг функций в реальном времени (`perf top`)

Аналог `top` на уровне функций. Показывает функции ядра и приложений с наибольшим потреблением CPU.

```bash
sudo perf top
```

### Запись и анализ профиля (`perf record` и `perf report`)

```bash
# Сбор данных с частотой 99 Гц, включая граф вызовов
sudo perf record -F 99 -p <PID> -g -- sleep 10

# Интерактивный анализ отчёта с возможностью навигации по вызовам
perf report
```

### Подсчёт page faults (`perf stat`)

```bash
# Подсчёт отказ страниц для команды
perf stat -e page-faults,minor-faults,major-faults <cmd>

# Для работающего процесса
perf stat -e page-faults,minor-faults,major-faults -p <PID> sleep 10
```

Типы событий:

- **`page-faults`:** общее количество отказов страниц.
- **`minor-faults`:** мягкие отказы — страница уже в RAM, обрабатываются без I/O.
- **`major-faults`:** жёсткие отказы — страница загружается с диска (swap или файловый кэш), вызывают задержки.

Интерпретация: высокие `minor-faults` — нормальная работа с памятью; высокие `major-faults` — нехватка RAM, свопинг или активная работа с mmap-файлами. Подробнее — в [Управление Swap](../../Core/memory/swap_management.md#диагностика-page-faults).

### Анализ задержек планировщика (`perf sched`)

Диагностирует ситуации, когда процесс готов к выполнению, но ядро не предоставляет CPU. Используется при высоком `CPU idle` и низком отклике приложения.

```bash
# Сбор событий планировщика
sudo perf sched record sleep 30

# Анализ задержек
sudo perf sched latency

# Сортировка по средней задержке (по 5-му полю)
sudo perf sched latency | sort -k5 -n
```

Ключевые метрики: `avg delay` (средняя задержка), `max delay` (пиковая задержка). Связанная тема: [планировщик задач Linux](../../Core/processes/scheduling.md).

### Анализ системных вызовов и блокировок (`perf trace`)

Аналог `strace` с меньшими накладными расходами. Применяется для диагностики блокировок, в т.ч. при анализе [tail latency](./diagnosing_tail_latency.md).

```bash
# Отслеживание futex-вызовов для всей системы
sudo perf trace -e futex
```

Высокое количество длительных ожиданий указывает на конкуренцию за блокировки в приложении.

### Создание Flame Graphs

Данные `perf record -g` визуализируются в виде Flame Graphs с помощью скриптов Б. Грегга:

```bash
# Запись с графом вызовов
sudo perf record -F 99 -ag -- sleep 30

# Генерация свёрнутого стека
perf script | ./stackcollapse-perf.pl > out.perf-folded

# Создание SVG
./flamegraph.pl out.perf-folded > perf-flamegraph.svg
```

## Дополнительная информация

Flame Graphs предоставляют наглядное представление профиля производительности, позволяя идентифицировать наиболее ресурсоёмкие ветви кода. Для генерации требуются скрипты `stackcollapse-perf.pl` и `flamegraph.pl` из [репозитория Brendan Gregg](https://github.com/brendangregg/FlameGraph).
