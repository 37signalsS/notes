# `syswatch`

## Определение

**`syswatch`** — это современная интерактивная панель для диагностики и мониторинга ресурсов отдельного хоста с текстовым пользовательским интерфейсом (TUI). Инструмент разработан как единая точка входа («first-look tool») для случаев, когда система работает медленно или нестабильно. Он объединяет возможности `htop`, `iostat`, `nettop` и `df`, дополняя их интеллектуальным анализом аномалий.

Инструмент кроссплатформенный (macOS и Linux) и написан на языке **Rust**.

## Основные концепции

### Timeline и сессии (Session Scrubbing)

Ключевое отличие `syswatch` — сохранение состояния всех метрик в памяти в рамках текущей сессии.
- **Scrubbing:** Пользователь может «перематывать» время назад с помощью стрелок, чтобы увидеть состояние системы в момент пиковой нагрузки.
- **Запись и воспроизведение:** Утилита позволяет записывать сессии в файлы `.swr` (клавиша `R`) и воспроизводить их позже (`syswatch --replay file.swr`) для проведения ретроспективного анализа (постмортем).

### Вкладка Insights (Аналитика)

Использует эвристические алгоритмы для обнаружения проблем и выводит их в виде карточек на понятном языке. Примеры детектируемых событий:
- **Thrashing:** Чрезмерная активность Swap.
- **Memory Pressure:** Критическая нехватка оперативной памяти.
- **Runaway Processes:** Процессы с аномальным потреблением ресурсов.

### Комплексный охват (12 вкладок)

Инструмент предоставляет детальные данные по следующим направлениям:
- **CPU:** Нагрузка по ядрам и процессам.
- **Memory:** Глубокая аналитика (PSS, Private, Swap, Footprint).
- **Disk & Filesystem:** Латентность I/O и свободное место.
- **Net:** Сетевая активность в реальном времени.
- **GPU & Power:** Статистика видеокарт и энергопотребления (особенно детально для Apple Silicon через `ioreg`).
- **Services:** Статус служб `systemd` (Linux) или `launchd` (macOS).

### Принцип «No Sudo»

Инструмент спроектирован для работы с правами обычного пользователя. Если для получения определенных метрик (например, `powermetrics`) требуются повышенные привилегии, `syswatch` корректно отметит это ограничение в интерфейсе, не прерывая работу.

## Установка

```bash
# macOS / Linux (через Homebrew)
brew install syswatch

# Linux (через Cargo, требуется Rust 1.75+)
cargo install syswatch

# NixOS
nix-shell -p syswatch

# Arch Linux (AUR)
paru -S syswatch
```

Также доступны бинарные файлы на странице [GitHub Releases](https://github.com/matthart1983/syswatch/releases).

## Практические сценарии

### Ретроспективный анализ всплеска нагрузки

Если вы получили алерт о кратковременном скачке CPU, который уже спал:
1. Запустите `syswatch`.
2. Перейдите на вкладку **Timeline**.
3. Используйте стрелки для поиска момента всплеска.
4. Проверьте вкладку **Procs** в этом временном срезе, чтобы найти процесс-виновник.

### Быстрая диагностика «тормозов» сервера

1. Запустите утилиту и сразу перейдите на вкладку **Insights** (клавиша `i` или переключение табов).
2. Ознакомьтесь с карточками проблем. Если `syswatch` видит утечку памяти или деградацию диска, он явно укажет на это.
3. Используйте вкладку **Overview** для сопоставления сетевой нагрузки с дисковым вводом-выводом.

## Дополнительная информация

### Сравнение с аналогами

| Инструмент | Преимущества | Ключевая фишка |
| :--- | :--- | :--- |
| [`htop`](../Processes/htop.md) | Легкость, управление процессами (kill) | Интерактивное управление |
| [`atop`](./atop.md) | Хранение логов на диске | Постоянная история (дни/недели) |
| **`syswatch`** | **Insights** и **Timeline сессии** | Анализ причин «человеческим» языком |

### Ограничения

- **Read-Only:** Инструмент предназначен только для диагностики. В нем нельзя убить процесс или перезапустить службу (в отличие от `htop`).
- **Single-Host:** Мониторинг только локального хоста. Для сетевого мониторинга разработчик предлагает отдельный инструмент — `NetWatch`.
