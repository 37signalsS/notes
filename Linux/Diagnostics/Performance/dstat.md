# `dstat` (Versatile Resource Statistics)

## Определение

**`dstat`** — это универсальный инструмент для мониторинга производительности системы в реальном времени. Утилита объединяет возможности классических инструментов, таких как [`vmstat`](../Memory/vmstat.md), [`iostat`](../Filesystem/iostat.md), `netstat` и `ifstat`, предоставляя единый поток данных с цветовой индикацией. Она позволяет наблюдать за всеми ресурсами системы одновременно, выявлять корреляции между нагрузками и экспортировать данные для последующего анализа.

## Основные концепции

### Эволюция: dstat, dool и pcp-dstat

Оригинальный проект `dstat` (Python 2) официально признан устаревшим (deprecated). В современных системах 2025–2026 годов используются два основных наследника:

1.  **`pcp-dstat` (Performance Co-Pilot):**
    *   **Статус:** Промышленный стандарт (входит в состав PCP 7.x).
    *   **Особенности:** Поддерживает удаленный мониторинг, ретроспективный анализ (воспроизведение логов) и интеграцию с OpenTelemetry/Prometheus.
    *   **Рекомендация:** Использовать в Production-окружениях и облачных инфраструктурах.
2.  **`dool`:**
    *   **Статус:** Прямой форк оригинального `dstat`, портированный на Python 3.
    *   **Особенности:** Полная совместимость со старыми Python-плагинами. Не требует установки серверных компонентов (демонов).
    *   **Рекомендация:** Использовать для быстрой локальной отладки и на системах без PCP.

### Преимущества мониторинга в режиме «свитка»

В отличие от интерактивных утилит ([`top`](../Processes/top.md), [`htop`](../Processes/htop.md)), которые обновляют экран, `dstat` выводит данные построчно (rolling log). Это критически важно для:
- **Обнаружения всплесков (spikes):** Кратковременные пики нагрузки не исчезают с экрана.
- **Корреляционного анализа:** Можно визуально сопоставить момент роста сетевого трафика с ростом нагрузки на диск или CPU.
- **Цветовой индикации:** Значения (B, KB, MB, GB) подсвечиваются разными цветами, что позволяет мгновенно оценить масштаб нагрузки.

### Установка

```bash
# Debian / Ubuntu (pcp-dstat часто идет как 'dstat' по умолчанию)
sudo apt install pcp-system-tools  # pcp-dstat
sudo apt install dool              # dool

# RHEL / Fedora / CentOS
sudo dnf install pcp-system-tools

# Arch Linux
sudo pacman -S dool
```

## Практические сценарии

### Комплексный мониторинг ресурсов

Запуск без параметров выводит базовый набор: CPU, диски, сеть, пейджинг и системные прерывания.

```bash
dstat 1 10
# 1 — интервал в секундах, 10 — количество отсчетов
```

### Выявление процессов-виновников нагрузки

Плагины `--top-*` показывают имя процесса и значение нагрузки в каждой строке.

```bash
# Процессы, потребляющие максимум CPU, RAM и I/O прямо сейчас
dstat -c --top-cpu --top-mem --top-io
```

### Диагностика сетевого стека

Удобно для отслеживания состояний соединений без использования `ss` или `netstat`.

```bash
# Статистика TCP-сокетов (listening, active, time_wait)
dstat --tcp --socket
```

### Анализ эффективности диска (utilization)

Позволяет увидеть, насколько «занято» устройство в процентах времени (аналог `%util` в `iostat`).

```bash
dstat -d --disk-util
```

### Экспорт данных в CSV

Идеально для подготовки графиков или импорта в Excel после нагрузочного тестирования.

```bash
dstat --output performance_report.csv -cdn 5 100
```

## Дополнительная информация

### Возможности PCP 7.x (pcp-dstat)

В версиях 2025–2026 годов `pcp-dstat` получил значительные обновления:
- **Наносекундная точность:** Высокое разрешение временных меток.
- **Новые домены метрик:** Поддержка **Valkey**, **Btrfs**, **GPU (Apple Silicon)** и энергетических сенсоров.
- **Удаленный просмотр:** Мониторинг другого хоста через `dstat --host <hostname>`.

### Полезные плагины и флаги

- `-y`, `--sys`: Статистика прерываний (int) и переключений контекста (csw).
- `--vm-adv`: Расширенная статистика виртуальной памяти (dirty, writeback).
- `--nfs3`, `--nfsd4`: Мониторинг сетевых файловых систем.
- `--innodb-buffer`: Статистика буфера InnoDB для баз данных.

### Сравнение с аналогами

- **[`sar`](./sar.md):** Основной инструмент для долгосрочного хранения истории. `dstat` лучше для «живой» отладки.
- **[`atop`](./atop.md):** Более тяжелый инструмент с бинарными логами и интерактивным интерфейсом.
- **[`vmstat`](../Memory/vmstat.md):** Стандарт де-факто для минималистичного вывода (есть везде), но проигрывает в наглядности.
