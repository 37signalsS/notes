# Диагностика проблем дискового ввода-вывода (I/O) в Linux

**Диагностика дисковой подсистемы** — это процесс выявления узких мест (bottlenecks) между приложениями и физическими накопителями. Данный документ является обзорным и координирующим; детальные разборы отдельных аспектов вынесены в специализированные заметки.

## Определение

- **I/O Wait (`wa`)**: Процент времени, в течение которого центральный процессор (CPU) простаивал, ожидая завершения операций ввода-вывода. Высокое значение указывает на перегрузку дисковой подсистемы.
- **Uninterruptible Sleep (D-state)**: Состояние процесса, ожидающего завершения I/O операции. Такие процессы увеличивают показатель `Load Average` и не могут быть прерваны сигналами (включая `SIGKILL`).
- **Dirty Pages (Грязные страницы)**: Измененные данные в оперативной памяти (Page Cache), которые еще не были записаны на постоянный носитель.
- **Writeback**: Фоновый процесс ядра Linux по сбросу грязных страниц из оперативной памяти на диск.
- **Direct I/O**: Операции чтения или записи, выполняемые в обход системного кэша страниц (Page Cache).

## Основные концепции

### Жизненный цикл ввода-вывода в ядре

Процесс записи данных обычно проходит следующие этапы:

1. Приложение вызывает `write()`.
2. Ядро копирует данные в **Page Cache** (страница становится «грязной»).
3. Приложение получает подтверждение успешной записи (асинхронно).
4. Потоки **`kworker/u*:flush-*`** сбрасывают данные на блочное устройство согласно настройкам **Writeback**.

### Уровни диагностики

Диагностика должна проводиться сверху вниз по стеку:

1. **Уровень приложений**: Идентификация процессов, генерирующих нагрузку ([`iotop`](../Filesystem/iotop.md), [`pidstat`](../Processes/pidstat.md)).
2. **Уровень ядра**: Анализ состояния очередей, Page Cache и планировщиков ([`vmstat`](../Memory/vmstat.md), [Writeback](./DiskIO/writeback_tuning.md)).
3. **Уровень устройств**: Мониторинг латентности и пропускной способности аппаратных средств ([`iostat`](../Filesystem/iostat.md)).

## Практические сценарии

### Алгоритм быстрого поиска проблем

1. Проверить `top` или `htop` на наличие высокого `%wa` и процессов в статусе `D`.
2. Оценить общую нагрузку на диски через `iostat -x 1`. Критичные метрики: `await` (задержка) и `avgqu-sz` (очередь).
3. Найти виновника через `iotop -o`.
4. Если `iotop` не показывает активности, изучить проблему [«невидимого» ввода-вывода](./DiskIO/invisible_io.md).
