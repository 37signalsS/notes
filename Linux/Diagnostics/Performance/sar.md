# `sar` (System Activity Reporter)

## Определение

**`sar` (System Activity Reporter)** — основная системная утилита из пакета `sysstat`, предназначенная для сбора, отчёта и анализа данных о производительности системы. Ключевое отличие `sar` от инструментов реального времени (таких как [`top`](../Processes/top.md) или [`htop`](../Processes/htop.md)) заключается в способности работать с историческими данными, накопленными за длительный период. Это делает её незаменимым инструментом для ретроспективного анализа инцидентов (post-mortem).

## Основные концепции

### Архитектура sysstat

`sar` является частью экосистемы `sysstat`, которая разделена на компоненты сбора и отображения данных:
- **`sadc` (System Activity Data Collector):** Бэкенд-утилита, которая опрашивает счетчики ядра и записывает их в бинарном формате.
- **`sa1` и `sa2`:** Скрипты-обертки для `sadc`. `sa1` собирает данные, `sa2` генерирует ежедневный текстовый отчет.
- **`sar`:** Фронтенд для чтения бинарных данных и отображения их в человекочитаемом текстовом виде.
- **`sadf`:** Утилита для экспорта данных `sar` в различные форматы (CSV, XML, JSON, SVG).

Связанные утилиты в пакете:
- [`iostat`](../Filesystem/iostat.md) — статистика дисковой подсистемы.
- [`pidstat`](../Processes/pidstat.md) — статистика по конкретным процессам.
- `mpstat` — детальный мониторинг многопроцессорных систем.

### Формат и хранение данных

Данные сохраняются в бинарных файлах, которые невозможно прочитать обычным текстовым редактором:
- **Пути:** `/var/log/sysstat/` (Debian/Ubuntu) или `/var/log/sa/` (RHEL/CentOS).
- **Файлы `saDD`:** Бинарные данные за день месяца `DD`.
- **Файлы `sarDD`:** Текстовые отчеты за день `DD` (генерируются скриптом `sa2`).

В современных версиях `sysstat` (12+) используется оптимизированная упаковка данных, что снижает нагрузку на дисковое пространство на 25–40%.

### Установка и активация

Для работы ретроспективного анализа службу необходимо явно включить.

```bash
# Установка
sudo apt install sysstat      # Debian/Ubuntu
sudo dnf install sysstat      # RHEL/CentOS/Fedora
sudo pacman -S sysstat         # Arch Linux

# Включение сбора (Debian/Ubuntu)
# В файле /etc/default/sysstat установите ENABLED="true"

# Активация служб
sudo systemctl enable --now sysstat
sudo systemctl enable --now sysstat-collect.timer
```

## Практические сценарии

### Анализ процессора и очередей

```bash
# Текущая нагрузка CPU (интервал 1с, 5 раз)
sar -u 1 5
# %user, %system, %iowait, %steal (актуально для VM), %idle

# Просмотр статистики по всем ядрам отдельно
sar -P ALL 1 1

# Состояние очередей и Load Average
sar -q 1 5
# runq-sz (очередь на выполнение), plist-sz (кол-во процессов), ldavg-1/5/15
```

### Мониторинг памяти и кэша

```bash
# Использование оперативной памяти
sar -r 1 5
# kbmemfree, kbmemused, %memused, kbbuffers, kbcached, kbshmem (shared memory)

# Статистика подкачки (Swap)
sar -S 1 5

# Интенсивность работы с памятью (Paging)
sar -B 1 5
# majflt/s (major faults — чтение с диска), pgscank/s (сканирование страниц)
```

### Дисковая подсистема и ввод-вывод

```bash
# Статистика по блочным устройствам с именами
sar -d -p 1 5
# tps (транзакций в сек), await (среднее время ответа), avgqu-sz (очередь)

# Статистика использования TTY и серийных портов
sar -y 1 5
```

### Сетевая активность

```bash
# Суммарный трафик по интерфейсам (пакеты, байты)
sar -n DEV 1 5

# Ошибки на сетевых интерфейсах
sar -n EDEV 1 5

# Статистика сокетов и сетевого стека
sar -n SOCK,TCP,UDP 1 1
# active/s (исходящие соединения), passive/s (входящие), retrans/s (ретрансмиссии)
```

### Современные возможности вывода (v12+)

```bash
# Человекочитаемый формат (K, M, G вместо байт)
sar -r --human 1 1

# Отображение минимумов, максимумов и средних значений в конце отчета
sar -u -x ALL 1 10

# Использование постоянных имен устройств (UUID/LABEL)
sar -d --persistence
```

### Работа с архивами и экспортом

Для анализа прошлых дней используется флаг `-f`.

```bash
# Чтение данных за 10-е число текущего месяца
sar -u -f /var/log/sysstat/sa10

# Выбор конкретного интервала времени
sar -q -s 09:00:00 -e 10:30:00 -f /var/log/sysstat/sa$(date +%d)

# Генерация SVG-графика за текущий день (через sadf)
sadf -g /var/log/sysstat/sa$(date +%d) -- -A > performance_report.svg

# Экспорт в JSON для внешней обработки
sadf -j -f /var/log/sysstat/sa01 -- -u > cpu_stats.json
```

## Дополнительная информация

### Настройка глубины хранения (Retention)

Параметры хранения логов находятся в `/etc/sysstat/sysstat`.
- `HISTORY`: Количество дней хранения (по умолчанию 7 или 28).
- `COMPRESSAFTER`: Через сколько дней сжимать старые логи (утилитой bzip2/gzip).
- Если `HISTORY` > 28, файлы будут организованы в поддиректории по месяцам.

### Белые пятна и ограничения

- **Миграция страниц:** Метрики `pgprom/s` и `pgdem/s` показывают перемещение данных между типами памяти (например, Optane и DDR).
- **Softnet:** `sar -n SOFT` помогает диагностировать перегрузку программного бэклога сетевых прерываний.
- **Ограничения:** `sar` собирает данные с дискретностью (обычно 10 минут по умолчанию). Всплески короче этого интервала могут быть сглажены и не видны на исторических графиках. Для секундной детализации используйте `atop`.

### Интеграция с другими инструментами

- **[`atop`](./atop.md):** Утилита `atopsar` предоставляет аналогичный интерфейс для чтения логов `atop`.
- **[`sos report`](../sos_report.md):** При генерации отчета всегда включайте историю `sar` командой `sos report -k sar.all-sar=on`.
- **ksar:** Стороннее Java-приложение для построения графиков из текстового вывода `sar`.
