# `sar`

## Определение

**`sar` (System Activity Reporter)** — системная утилита из пакета `sysstat`, предназначенная для сбора, отчёта и анализа данных о производительности системы. В отличие от инструментов реального времени ([`top`](../Processes/top.md), [`htop`](../Processes/htop.md)), `sar` позволяет анализировать исторические данные, что критично для расследования инцидентов, произошедших в прошлом (постмортем).

## Основные концепции

### Архитектура sysstat

`sar` является частью набора инструментов `sysstat`, который также включает:
- [`iostat`](../Filesystem/iostat.md) — статистика ввода-вывода.
- [`pidstat`](../Processes/pidstat.md) — статистика по отдельным процессам.
- `mpstat` — детальная статистика по ядрам CPU.
- `sadc` — бэкенд для сбора бинарных данных.

### Режимы работы

1.  **Режим реального времени:** Сбор и отображение статистики "на лету" с заданным интервалом.
2.  **Режим отчёта:** Чтение бинарных логов, собранных фоновым демоном, для анализа прошлых периодов.

### Сбор данных (sadc)

Фоновый процесс **`sadc` (System Activity Data Collector)** собирает метрики и сохраняет их в бинарные файлы.
- **Пути к логам:** обычно `/var/log/sysstat/` (Debian/Ubuntu) или `/var/log/sa/` (RHEL/CentOS).
- **Имена файлов:** `saDD`, где `DD` — число месяца. Бинарные файлы `saDD` можно прочитать только с помощью `sar`.

### Установка и настройка sysstat

Это ключевой этап для возможности ретроспективного анализа.

```bash
# Debian / Ubuntu
sudo apt update && sudo apt install sysstat

# RHEL / CentOS / Fedora
sudo dnf install sysstat

# Arch Linux
sudo pacman -S sysstat
```

**Включение сбора данных:**

1.  **Debian/Ubuntu:** отредактируйте `/etc/default/sysstat`, установив `ENABLED="true"`.
2.  **Активация службы:**
    ```bash
    sudo systemctl enable --now sysstat
    # Также убедитесь, что включен сборщик (обычно через таймер или cron)
    sudo systemctl enable --now sysstat-collect.timer
    ```

## Практические сценарии

### Анализ использования CPU (`-u`, `-P`)

```bash
# Текущая нагрузка (интервал 1с, 5 раз)
sar -u 1 5
# %user, %nice, %system, %iowait, %steal, %idle

# Нагрузка по конкретным ядрам
sar -P ALL 1 1
```

### Анализ памяти и подкачки (`-r`, `-S`, `-B`)

```bash
# Использование оперативной памяти
sar -r 1 5
# kbmemfree, kbmemused, %memused, kbbuffers, kbcached

# Использование Swap
sar -S 1 5

# Статистика подкачки (swapping activity)
sar -W 1 5
# pswpin/s, pswpout/s (ввод/вывод страниц в swap)

# Статистика страниц (paging)
sar -B 1 5
# pgpgin/s, pgpgout/s, fault/s (ошибки страниц), majflt/s (major faults)
```

### Анализ дискового ввода-вывода (`-d`)

```bash
# Статистика по блочным устройствам
sar -d -p 1 5
# -p преобразует номера устройств в имена (напр., sda)
# tps (транзакций в сек), rd_sec/s, wr_sec/s, avgqu-sz (очередь), await (латентность)
```

### Анализ сетевой статистики (`-n`)

Утилита `sar` предоставляет богатую сетевую диагностику через флаг `-n`.

```bash
# Трафик и пакеты по интерфейсам
sar -n DEV 1 5

# Ошибки интерфейсов (отброшенные пакеты, коллизии)
sar -n EDEV 1 5

# Статистика сокетов (TCP, UDP, RAW)
sar -n SOCK 1 1

# Статистика TCP (активные/пассивные открытия, ошибки)
sar -n TCP 1 1
```

### Очереди и средняя нагрузка (`-q`)

Аналог команды `uptime`, но с историей.

```bash
sar -q 1 5
# runq-sz (очередь на выполнение), plist-sz (кол-во процессов), ldavg-1/5/15
```

### Работа с историческими данными (`-f`, `-s`, `-e`)

По умолчанию `sar` показывает данные за текущий день из стандартного лога.

```bash
# Чтение лога за конкретный день (напр., 10-е число)
sar -u -f /var/log/sysstat/sa10

# Фильтрация по времени (с 10:00 до 12:00)
sar -q -s 10:00:00 -e 12:00:00 -f /var/log/sysstat/sa$(date +%d)
```

## Дополнительная информация

### Конфигурация хранения (Retention)

Срок хранения логов настраивается в файле `/etc/sysstat/sysstat`.
- Параметр `HISTORY`: определяет, сколько дней хранить логи (по умолчанию часто 7 или 28).
- Если значение > 28, логи будут сохраняться в поддиректории по месяцам.

### Интеграция с другими инструментами

- **[`atop`](./atop.md):** утилита `atopsar` позволяет генерировать отчёты в стиле `sar` из логов `atop`. Это полезно, если `sysstat` не был настроен, но работал `atop`.
- **[`sos report`](../sos_report.md):** при сборе данных для поддержки можно включить полный архив `sar` флагом `-k sar.all-sar=on`.

### Визуализация данных

Бинарные файлы `sar` можно визуализировать с помощью:
- **ksar:** Java-утилита для построения графиков из вывода `sar`.
- **SVG:** современные версии `sar` поддерживают экспорт в JSON/XML для последующей обработки (`sar --legacy -o log.file`).
