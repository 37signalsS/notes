# `atop`

## Определение

**`atop`** — это продвинутый интерактивный полноэкранный монитор производительности для Linux, предназначенный для глубокого анализа ресурсов системы. В отличие от стандартных инструментов ([`top`](../Processes/top.md), [`htop`](../Processes/htop.md)), `atop` специализируется на ведении исторических логов и предоставляет наиболее полную картину использования CPU, памяти, дисков и сети, включая данные о завершенных процессах.

## Основные концепции

### Исторический анализ (Snapshots)

Ключевая особенность `atop` — наличие фонового демона (`atop.service`), который через равные промежутки времени делает «снимки» (snapshots) состояния всей системы и записывает их в бинарный файл. Это позволяет SRE-специалистам проводить ретроспективный анализ (постмортем) инцидентов, которые уже завершились.

### Комплексный мониторинг ресурсов

`atop` агрегирует данные из `/proc`, сетевого стека и счетчиков ресурсов:
- **CPU:** нагрузка на ядра, частота, время в прерываниях (`irq`, `softirq`), стел-тайм (`steal`).
- **Memory:** использование RAM, swap, кэш (page cache), грязные страницы (`dirty`), детализация по процессам (RSS, VSIZE, ошибки страниц).
- **Disk I/O:** нагрузка на конкретные блочные устройства, очереди, латентность, время обслуживания (`serv`).
- **Network:** трафик по интерфейсам. Для детализации по процессам требуется модуль ядра `netatop`.
- **GPU:** при установленном демоне `atopgpud` отображает статистику видеокарт (NVIDIA).

### Цветовая индикация

Утилита автоматически подсвечивает критические значения нагрузки цветом:
- **Голубой (Cyan):** нормальная работа.
- **Красный (Red):** ресурс исчерпан или находится под критической нагрузкой.
- **Желтый (Yellow):** пограничное состояние.

## Установка и настройка

### Установка пакета

```bash
# Debian / Ubuntu
sudo apt update && sudo apt install atop

# RHEL / CentOS / Fedora
sudo dnf install atop

# Arch Linux
sudo pacman -S atop
```

### Настройка фонового сбора данных

Для работы режима отчётов необходимо включить службу:

```bash
# Запуск и добавление в автозагрузку
sudo systemctl enable --now atop
```

**Конфигурация (Retention & Interval):**
Параметры сбора настраиваются в файлах `/etc/default/atop` (Debian/Ubuntu) или `/etc/sysconfig/atop` (RHEL):
- **`LOGINTERVAL`**: интервал между снимками в секундах (по умолчанию 600с). Для детальной диагностики рекомендуется 60с.
- **`LOGGENERATIONS`**: сколько дней хранить логи (обычно 28 дней).

## Практические сценарии

### Интерактивный режим (Real-time)

Запуск команды `atop` открывает текущее состояние системы.

**Горячие клавиши (View selection):**
- **`g`**: общий вид (по умолчанию).
- **`m`**: детализация по **памяти** (RSS, VSS, ошибки страниц).
- **`d`**: детализация по **дисковой активности** (чтение/запись, отмена операций).
- **`n`**: детализация по **сетевой активности** (требует `netatop`).
- **`s`**: информация о **планировании** (scheduling) и потоках.
- **`v`**: детальная информация о процессах (пользователь, время запуска, статус завершения).
- **`y`**: отображение **потоков** (threads) внутри процессов.

**Горячие клавиши (Sorting):**
- **`C`**: сортировка по потреблению **CPU**.
- **`M`**: сортировка по потреблению **RAM**.
- **`D`**: сортировка по активности **диска**.
- **`N`**: сортировка по **сети**.

### Анализ исторических логов

Для просмотра данных за прошлые периоды используется флаг `-r`.

```bash
# Открыть лог за текущие сутки (автоматический поиск файла)
atop -r

# Открыть конкретный файл лога
atop -r /var/log/atop/atop_20240725

# Навигация внутри лога:
# t — переход к СЛЕДУЮЩЕМУ временному срезу.
# T — переход к ПРЕДЫДУЩЕМУ временному срезу.
# b — переход к конкретному времени (например, 14:00).
# r — возврат в начало лога.
```

### Генерация отчетов с помощью atopsar

Утилита `atopsar` позволяет получать агрегированную статистику в текстовом виде (аналог `sar`).

```bash
# Сводный отчет по CPU за весь день из лога
atopsar -c -r /var/log/atop/atop_20240725

# Просмотр нагрузки на диски
atopsar -d -r /var/log/atop/atop_20240725

# Список 10 самых активных процессов за период
atopsar -p -r /var/log/atop/atop_20240725
```

## Дополнительная информация

### Детальные метрики памяти процесса

В режиме `m` (memory) утилита предоставляет специфические показатели:
- **`MINFLT` / `MAJFLT`**: количество малых (из кэша) и серьезных (с диска) ошибок страниц. Высокий `MAJFLT` — верный признак нехватки RAM и активного свопинга.
- **`RSIZE`**: резидентный размер (физическая память, занятая процессом).
- **`VGROW` / `RGROW`**: рост виртуальной и резидентной памяти с момента последнего снимка. Полезно для поиска утечек.
- **`SWAPSZ`**: объем памяти процесса, вытесненный в SWAP.

### Работа с netatop (Network per process)

Стандартный `atop` видит общий трафик интерфейсов. Для привязки трафика к процессам необходимо установить модуль ядра `netatop`:
1. Установите заголовки ядра: `sudo apt install linux-headers-$(uname -r)`.
2. Соберите и загрузите модуль (обычно через DKMS или вручную с [официального сайта](https://www.atoptool.nl/downloadnetatop.php)).
3. Запустите демон `netatopd.service`.
