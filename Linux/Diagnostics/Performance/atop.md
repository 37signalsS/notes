# `atop`

## Определения

`atop` — это интерактивный полноэкранный монитор производительности, который, в отличие от `top`, способен вести исторические логи системной активности. Это позволяет не только наблюдать за системой в реальном времени, но и анализировать проблемы, произошедшие в прошлом.

Для долгосрочного анализа также используется [`sar`](./sar.md) из пакета `sysstat`, который собирает статистику в бинарные логи.

## Основные концепции

- **Исторический анализ:** `atop` запускает фоновый демон, который периодически записывает "снимки" состояния системы в лог (обычно `/var/log/atop/`). Это его ключевое преимущество.
- **Комплексные метрики:** В одном окне агрегирует нагрузку на CPU, память, диски и сеть по каждому процессу, что избавляет от необходимости запускать несколько утилит одновременно.
- **Ресурсоемкие процессы:** `atop` подсвечивает процессы, которые являются основной причиной нагрузки на систему, что упрощает их идентификацию.

## Практические сценарии

### Интерактивный мониторинг

Запуск `atop` без аргументов открывает интерактивный режим, похожий на [`htop`](../Diagnostics/Processes/htop.md).

- **`m`**: переключиться на детальную информацию по использованию **памяти**.
- **`d`**: переключиться на детальную информацию по **дискам**.
- **`n`**: переключиться на детальную информацию по **сети**.
- **`t`**: перейти к следующему временному срезу (при анализе лога).

### Анализ исторических данных

```bash
# Открыть лог atop за сегодняшний день для анализа
atop -r

# Открыть конкретный файл лога
atop -r /var/log/atop/atop_YYYYMMDD
```

## Дополнительная информация

### Детальный анализ памяти процесса

В режиме анализа памяти (`m`) `atop` предоставляет подробную информацию о потреблении памяти:

- **`MINFLT` (Minor Page Faults):** Счетчик **малых отказов страниц**. Показывает, сколько раз процесс обращался к страницам памяти, которые уже были в RAM, но не были в его таблице страниц. Большое количество `MINFLT` — это нормально.
- **`MAJFLT` (Major Page Faults):** Счетчик **серьезных отказов страниц**. Показывает, сколько раз процессу приходилось считывать страницу памяти с диска. Постоянный рост этого счетчика указывает на нехватку RAM и активный свопинг.
- **`VSTEXT`**: Виртуальный размер **сегмента кода**.
- **`VSLIBS`**: Виртуальный размер **разделяемых библиотек**.
- **`VDATA`**: Виртуальный размер **сегмента данных и кучи** (heap).
- **`VSTACK`**: Виртуальный размер **стека**.
- **`VSIZE` (Virtual Size):** Общий размер **виртуальной памяти** (`VIRT` в `top`).
- **`RSIZE` (Resident Size):** Общий размер **резидентной памяти**, т.е. реальный объем RAM, занимаемый процессом (`RES` в `top`).
- **`SWAPSZ` (Swapped Size):** Объем памяти процесса, который был выгружен в swap.
- **`MEM`:** Процент использования физической памяти процессом.

### Генерация отчетов в стиле `sar`

Утилита `atopsar` может генерировать текстовые отчеты из бинарных логов `atop`, аналогично `sar`.

```bash
# Сгенерировать отчет по использованию CPU (-P ALL) за весь день из лога atop
atopsar -P ALL -r /var/log/atop/atop_YYYYMMDD
```
