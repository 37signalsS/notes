# `atop`

## Определение

**`atop`** — это продвинутый интерактивный полноэкранный монитор производительности для Linux. В отличие от стандартных инструментов вроде [`top`](../Processes/top.md) или [`htop`](../Processes/htop.md), `atop` специализируется на ведении исторических логов системной активности. Это позволяет не только отслеживать состояние системы в реальном времени, но и проводить ретроспективный анализ инцидентов.

## Основные концепции

### Исторический анализ

Ключевое преимущество `atop` — наличие фонового демона, который через равные промежутки времени делает «снимки» (snapshots) состояния всей системы и записывает их в бинарный файл (обычно в `/var/log/atop/`).

### Комплексный мониторинг

`atop` агрегирует в одном интерфейсе данные по всем основным ресурсам:

- **CPU:** нагрузка на ядра, частота, время прерываний.
- **Память:** использование RAM, swap, кэш, детализация по процессам.
- **Диски:** нагрузка на конкретные блочные устройства, очереди, задержки (LVM, RAID).
- **Сеть:** трафик по интерфейсам (требует модуля `netatop` для детализации по процессам).

### Цветовая индикация

Утилита автоматически подсвечивает критические значения нагрузки цветом:

- **Голубой:** нормальная работа.
- **Красный:** ресурс исчерпан или находится под критической нагрузкой.

## Установка и настройка

Для использования исторических данных необходимо установить пакет и включить соответствующую службу.

```bash
# Debian / Ubuntu
sudo apt install atop

# RHEL / CentOS / Fedora
sudo dnf install atop

# Arch Linux
sudo pacman -S atop
```

**Включение службы сбора данных:**

```bash
# Запуск и добавление в автозагрузку
sudo systemctl enable --now atop
```

Интервал сбора данных по умолчанию (обычно 600 секунд) можно изменить в файле конфигурации (например, `/etc/default/atop` или `/etc/atop/atop.daily`).

## Практические сценарии

### Интерактивный режим

Запуск без параметров открывает текущее состояние системы.

**Горячие клавиши:**

- **`m`**: сортировка и детализация по использованию **памяти**.
- **`d`**: детализация по активности **дисковой подсистемы**.
- **`n`**: детализация по **сетевой активности** (если доступно).
- **`v`**: детальная информация о процессах (пользователь, время запуска).
- **`P`**: сортировка по потреблению **CPU**.
- **`M`**: сортировка по потреблению **RAM**.

### Анализ исторических логов

Для просмотра данных за прошлые периоды используется флаг `-r`.

```bash
# Открыть лог за текущие сутки
atop -r

# Открыть конкретный файл лога (например, за вчера)
atop -r /var/log/atop/atop_20240520

# Навигация внутри лога:
# t — переход к следующему временному срезу.
# T — переход к предыдущему временному срезу.
# b — переход к конкретному времени (например, 14:00).
```

### Использование atopsar

Утилита `atopsar` входит в пакет `atop` и позволяет генерировать текстовые отчеты в стиле [`sar`](./sar.md).

```bash
# Сводный отчет по CPU за все время в логе
atopsar -c -r /var/log/atop/atop_20240520

# Просмотр нагрузки на диски
atopsar -d -r /var/log/atop/atop_20240520
```

## Дополнительная информация

### Детальные метрики памяти процесса

В режиме `m` утилита предоставляет специфические показатели:

- **`MINFLT` / `MAJFLT`**: количество малых и серьезных ошибок страниц (page faults). Постоянный рост `MAJFLT` указывает на активное чтение с диска из-за нехватки RAM.
- **`VSTEXT` / `VSLIBS`**: объем виртуальной памяти под код процесса и разделяемые библиотеки.
- **`VDATA` / `VSTACK`**: объем виртуальной памяти под данные (кучу) и стек процесса.
- **`RSIZE`**: резидентный размер (реально занятая физическая память).
- **`SWAPSZ`**: объем памяти процесса, вытесненный в раздел подкачки.
