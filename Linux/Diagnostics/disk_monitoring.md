# Мониторинг дисковой подсистемы

## Анализ дискового I/O

### iotop

`iotop` — это "top для дискового I/O". Утилита показывает, какие именно процессы активно читают или пишут на диск. Незаменима, если `top` показывает высокое значение `iowait`.

**Описание колонок вывода:**
-   **PID (TID)**: Идентификатор процесса (или потока).
-   **USER**: Пользователь, от имени которого запущен процесс.
-   **DISK READ / WRITE**: Скорость чтения с диска и записи на диск для конкретного процесса.
-   **SWAPIN**: Процент времени, который процесс тратит на перемещение данных в раздел подкачки (swap).
-   **IO>**: Процент времени, который процесс проводит в ожидании завершения операций ввода-вывода. Высокое значение (>90%) для процесса при невысокой скорости записи/чтения — явный признак проблем с диском.
-   **COMMAND**: Имя процесса или команда, которой он был запущен.

**Полезные опции:**
-   `-o` или `--only`: Показывать только те процессы, которые в данный момент активно выполняют операции I/O.
-   `-P` или `--processes`: Отображать только процессы, скрывая отдельные потоки.
-   `-u <имя_пользователя>`: Отслеживать активность только указанного пользователя.
-   `-p <PID>`: Мониторить только конкретный процесс по его ID.
-   `-k`: Отображать скорость в килобайтах в секунду.
-   `-b` или `--batch`: Включить неинтерактивный режим для записи в лог.
-   `-n <число>`: Завершить работу после указанного числа обновлений (используется вместе с `-b`).

**Интерактивное управление:**
-   **Стрелки влево/вправо**: Изменить колонку для сортировки.
-   **r**: Инвертировать порядок сортировки.
-   **o**: Включить/выключить режим отображения только активных процессов (аналог ключа `-o`).
-   **q**: Выйти из программы.

### iostat

Утилита из пакета **sysstat**, которая предоставляет детальную численную статистику по операциям ввода-вывода на дисках.

- `iostat -xtc`: Показать расширенную статистику с временными метками.
- `iostat -dx -m -t 1 3 /dev/nvme1`: Статистика для диска `/dev/nvme1` каждую секунду 3 раза.
- **Ключевые колонки:** `r/s`, `w/s`, `rMB/s`, `wMB/s`, `await` (среднее время ожидания), `%util` (процент занятости).

Если `iotop` показывает общую картину, то `iostat` предоставляет более детальную, численную статистику по дискам.

**Пример команды:**
```bash
# Показывает статистику по устройствам (d) расширенную статистику (-x)
# в мегабайтах (-m) с временными метками (-t) каждую секунду (1)
# всего три раза для диска nvme1
iostat -dx -m -t 1 3 /dev/nvme1
```

**Ключевые колонки в выводе:**
-   `r/s` и `w/s`: Количество операций чтения и записи в секунду.
-   `rMB/s` и `wMB/s`: Скорость чтения и записи в мегабайтах в секунду.
-   `await`: Среднее время ожидания (в миллисекундах) для выполнения операций ввода-вывода. Высокое значение (например, 20 мс для HDD) — явный признак "тормозов" диска.
-   `%util`: Процент времени, в течение которого устройство было занято. Если это значение приближается к 100%, диск работает на пределе своей производительности.

**Время доступа к блоку**
В контексте `iotop` и дисковых операций, "доступ к блоку" (block device access) является фундаментальной операцией. Когда процесс читает или пишет данные, он обращается к блочному устройству (например, `/dev/sda`). Время, необходимое для выполнения этой операции, критически важно.
-   **Нормальная работа:** В здоровой системе время доступа к блокам минимально (доли секунды).
-   **Деградация:** При проблемах с диском это время резко возрастает. Процесс, запросивший операцию, "зависает" в ожидании, увеличивая свой показатель `IO>` в `iotop` и внося вклад в Load Average.

### ionice

Команда `ionice` позволяет управлять приоритетом операций ввода-вывода (I/O) для процессов в Linux. Это полезно для оптимизации использования дисковых ресурсов, особенно на серверах с высокой нагрузкой, где конкурируют множество процессов.

**Зачем использовать `ionice`?**

1.  **Устранение конфликтов:** Вы можете снизить влияние ресурсоемких процессов на более важные задачи.
2.  **Оптимизация производительности:** Используется для повышения скорости критически важных операций, таких как базы данных или резервное копирование.
3.  **Контроль ресурсов:** Администратор может задать точные правила, определяя, какой процесс и с каким приоритетом будет работать с диском.

**Основные классы приоритетов `ionice`:**

*   **Idle (Класс 3):** Процесс выполняет операции ввода-вывода только тогда, когда диск не занят другими задачами.
*   **Best-effort (Класс 2, значение по умолчанию):** I/O операции выполняются с указанным приоритетом (от 0 — самый высокий, до 7 — самый низкий).
*   **Realtime (Класс 1):** Процесс получает доступ к диску немедленно, игнорируя другие задачи. Использовать с осторожностью!

**Примеры использования `ionice`:**

1.  **Установить минимальный приоритет для резервного копирования:**
    Если вы запускаете резервное копирование с помощью `rsync` и не хотите, чтобы оно замедляло сервер:
    ```bash
    ionice -c3 rsync -a /source /destination
    ```

2.  **Проверить текущий приоритет процесса:**
    Для процесса с PID 1234:
    ```bash
    ionice -p 1234
    ```
    Вывод покажет текущий класс и приоритет процесса.

3.  **Установить высокий приоритет для базы данных:**
    Если нужно ускорить работу MySQL:
    ```bash
    ionice -c1 -p $(pgrep mysqld)
    ```

4.  **Запуск ресурсоемкого скрипта с низким приоритетом:**
    Для минимизации влияния скрипта на другие задачи:
    ```bash
    ionice -c2 -n7 ./heavy_script.sh
    ```

### dstat

Универсальная утилита, которая является заменой для `vmstat`, `iostat` и `ifstat`. `dstat` позволяет в реальном времени собирать и отображать статистику по различным системным ресурсам: CPU, дискам, сети, памяти и т.д.

**Примеры использования:**
```bash
# Стандартный вывод: CPU, диск, сеть, paging, система
dstat

# Показать наиболее загруженный по CPU и I/O процесс
dstat --top-cpu --top-io

# Показать статистику только по дискам
dstat -d
```

### pidstat

Утилита из пакета `sysstat`, которая предоставляет детальную статистику по конкретным процессам, включая использование CPU, памяти и I/O.

**Примеры использования:**
```bash
# Мониторинг I/O для всех процессов с интервалом в 1 секунду
pidstat -d 1

# Мониторинг I/O для конкретного процесса (замените <PID> на ID процесса)
pidstat -d -p <PID> 1
```

## Анализ использования дискового пространства

### df (disk free)

`df` — это утилита, предназначенная для отображения информации о свободном и занятом дисковом пространстве на смонтированных файловых системах. Работает очень быстро, так как считывает информацию из **суперблока** файловой системы.
По умолчанию `df` выводит информацию в блоках (обычно 1КБ). Для более удобного чтения используются следующие опции:

**Полезные опции:**
```bash
# Показать свободное место в человекочитаемом формате
df -h

# Показать использование inode (индексных дескрипторов)
df -i
```
Если `inode` используется на 100%, вы не сможете создавать новые файлы, даже если на диске есть свободное место.

---

### du (disk usage)

`du` рекурсивно подсчитывает, сколько места на диске занимают файлы и директории. В отличие от `df`, `du` реально проходит по файловой системе, считывая размеры каждого файла и каталога. Это делает её более медленной, но она показывает фактический объем данных.

**Полезные опции:**

-   `-h` (`--human-readable`): Выводить размеры в удобном для человека формате (K, M, G).
-   `-s` (`--summarize`): Показать только итоговую сумму для указанной директории, не показывая размеры вложенных файлов и папок.
-   `-d <N>` или `--max-depth=<N>`: Установить глубину рекурсии. Например, `--max-depth=1` покажет размеры всех файлов и директорий на первом уровне вложенности.
-   `-c` (`--total`): Показать итоговую сумму в конце списка.

**Примеры использования `du`:**

```bash
# Узнать общий (суммарный) размер текущей директории
du -sh .

# Узнать, сколько места занимает конкретная директория
sudo du -sh /var/log

# Показать размеры всех директорий внутри /var на один уровень вглубь и отсортировать их по размеру
sudo du -h --max-depth=1 /var | sort -rh
```

## Диагностика здоровья диска


### smartctl

`smartctl` — утилита для считывания данных S.M.A.R.T. (Self-Monitoring, Analysis, and Reporting Technology) с жестких дисков и SSD для оценки их состояния и прогнозирования сбоев.

1.  **Установка:**
    ```bash
    sudo apt-get install smartmontools # Debian/Ubuntu
    sudo yum install smartmontools     # CentOS/RHEL
    ```

2.  **Просмотр общей информации о здоровье диска:**
    ```bash
    # Замените /dev/sda на ваш диск
    sudo smartctl -H /dev/sda
    ```
    В выводе ищите строку `SMART overall-health self-assessment test result`. Значение `PASSED` говорит о том, что диск считает себя исправным.

3.  **Просмотр всех S.M.A.R.T. атрибутов:**
    ```bash
    sudo smartctl -a /dev/sda
    ```
    Эта команда выводит подробную таблицу с атрибутами.
    
    **Ключевые S.M.A.R.T.-атрибуты для предсказания отказов:**
    -   **`Reallocated_Sectors_Ct`** (ID 5): Количество переназначенных секторов. Рост этого значения — первый тревожный сигнал, указывающий на то, что диск начал находить и заменять плохие сектора.
    -   **`Current_Pending_Sector_Ct`** (ID 197): Секторы, ожидающие перераспределения. Это секторы, которые диск обнаружил как потенциально ненадежные и попытается переназначить при следующей записи. Если диск не может их исправить, он может скоро выйти из строя.
    -   **`Uncorrectable_Sector_Ct`** (ID 198): Неисправимые секторы. Это необратимо поврежденные секторы, которые диск не может ни исправить, ни перенести. Их появление часто предвещает скорую поломку.
    -   **`UDMA_CRC_Error_Count`** (ID 199) / **`CRC Errors`**: Ошибки интерфейса SATA/NVMe. Указывают на проблемы с кабелем, разъемом или контроллером, а не с самим диском. Тем не менее, могут приводить к потере данных.
    -   **`Power_On_Hours`** (ID 9): Количество часов, которые диск был включён. Это показывает "возраст" диска. HDD редко живут больше 5-7 лет, SSD – до 3-5 лет при высокой нагрузке.
    -   **`SSD_Wear_Leveling_Count`** (ID 177) / **`Wear_Leveling_Count`**: Степень износа ячеек памяти у SSD. Если значение (обычно в процентах от 0 до 100) приближается к 100% износа, диск скоро выйдет из строя.

    Рост или появление критических значений в этих атрибутах — явный признак надвигающейся проблемы.

## Продвинутый мониторинг и предсказание отказов

### Автоматический мониторинг дисков в Zabbix

В Zabbix существуют готовые шаблоны для S.M.A.R.T., что упрощает интеграцию.

1.  **Установка Zabbix Agent (если не установлен):**
    ```bash
    sudo apt install zabbix-agent # Для Debian/Ubuntu
    # sudo yum install zabbix-agent # Для CentOS/RHEL
    ```

2.  **Установка smartmontools:**
    ```bash
    sudo apt install smartmontools
    ```

3.  **Настройка Zabbix Agent для сбора данных S.M.A.R.T.:**
    Добавьте следующие параметры в конфигурационный файл агента `/etc/zabbix/zabbix_agentd.conf`. Эти параметры позволяют агенту обнаруживать диски и собирать их S.M.A.R.T. атрибуты.

    ```ini
    # UserParameter для обнаружения дисков
    UserParameter=smartctl.discovery, sudo /usr/local/bin/smartctl_discovery.sh

    # UserParameter для получения значения конкретного S.M.A.R.T. атрибута
    # $1 - имя устройства (например, sda), $2 - имя атрибута (например, Reallocated_Sector_Ct)
    UserParameter=smartctl.info[*], sudo smartctl -A /dev/$1 | grep "$2" | awk '{print $NF}'
    ```
    **Примечание:** Для корректной работы `UserParameter` может потребоваться создать скрипт `/usr/local/bin/smartctl_discovery.sh` (который будет выводить JSON со списком дисков) и настроить `sudoers` для Zabbix-агента, чтобы он мог выполнять `smartctl` и `smartctl_discovery.sh` без пароля.

4.  **Перезапуск Zabbix Agent:**
    ```bash
    sudo systemctl restart zabbix-agent
    ```

5.  **Импорт шаблона в Zabbix:**
    Импортируйте шаблон "SMART Monitoring" (или аналогичный, доступный для вашей версии Zabbix) в ваш Zabbix-сервер и привяжите его к соответствующему хосту.

После этих шагов Zabbix будет автоматически отслеживать состояние дисков, собирать S.M.A.R.T. данные и позволит настроить алерты на критические изменения.

### Мониторинг дисков в Prometheus + Grafana

Если в инфраструктуре уже используется Prometheus, можно легко добавить мониторинг S.M.A.R.T. с помощью `node_exporter`.

1.  **Запуск `node_exporter` с коллектором `smartmon`:**
    `node_exporter` должен быть запущен с флагом, который активирует сбор метрик S.M.A.R.T. Для этого требуется, чтобы `smartctl` был установлен в системе и `node_exporter` имел права на его вызов (обычно через `sudo` без пароля).

    ```bash
    # Пример запуска с нужным коллектором
    ./node_exporter --collector.smartmon
    ```
    Для полноценной работы может потребоваться настройка `sudoers`, чтобы `node_exporter` мог выполнять `smartctl` без пароля.

2.  **Настройка Prometheus:**
    Добавьте в конфигурационный файл `prometheus.yml` задачу для сбора метрик с `node_exporter`.

    ```yaml
    scrape_configs:
      - job_name: 'node_exporter'
        static_configs:
          - targets: ['localhost:9100']
    ```

3.  **Визуализация в Grafana:**
    Для наглядного отображения данных можно использовать готовые дашборды. Например, дашборд с ID `12433` (Node Exporter Full) или `12430` (SMART Monitoring) является популярным выбором. Его можно импортировать в Grafana через меню "Dashboards" -> "Import".

    Это позволяет отслеживать динамику ключевых атрибутов S.M.A.R.T. (например, `Reallocated_Sectors_Ct`) и настраивать алерты на аномальные изменения.
