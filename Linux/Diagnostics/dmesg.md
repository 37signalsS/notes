# dmesg: Просмотр сообщений ядра

`dmesg` (сокращение от _display message_ или _driver message_) — это утилита командной строки для просмотра сообщений из **кольцевого буфера ядра**. Она незаменима для диагностики проблем с оборудованием и драйверами, особенно во время и сразу после загрузки системы.

Кольцевой буфер — это структура данных фиксированного размера в памяти ядра, где хранятся логи. Когда буфер заполняется, новые сообщения начинают перезаписывать самые старые.

## Использование `dmesg`

### Основные команды

-   **Простой вывод (может быть очень большим):**
    ```bash
    dmesg
    ```

-   **Вывод с постраничной навигацией:**
    ```bash
    dmesg | less
    ```

-   **Человекочитаемый вывод с раскрашиванием (`-H`):**
    ```bash
    dmesg -H
    ```

-   **Читаемый формат времени (`-T`):**
    Вместо секунд с момента загрузки `dmesg` покажет обычные дату и время.
    ```bash
    dmesg -T
    ```

-   **Показать уровень (facility) и приоритет (level) сообщений (`-x`):**
    ```bash
    dmesg -x
    ```

-   **Вывод в реальном времени (следить за новыми сообщениями):**
    Аналогично `tail -f`.
    ```bash
    dmesg -w
    # или
    dmesg --follow
    ```

### Фильтрация вывода

-   **Фильтрация по уровню сообщений:**
    ```bash
    # Показать только ошибки и критические сообщения
    dmesg --level=err,crit
    ```
    Уровни: `emerg`, `alert`, `crit`, `err`, `warn`, `notice`, `info`, `debug`.

-   **Фильтрация по устройству (facility):**
    ```bash
    # Показать сообщения, относящиеся только к пользователям
    dmesg --facility=user
    ```
    Facilities: `kern`, `user`, `mail`, `daemon`, `auth`, `syslog`, `lpr`, `news`.

-   **Комбинация полезных флагов:**
    (Человекочитаемый вывод, время, уровни, постраничный просмотр)
    ```bash
    dmesg -HTx | less
    ```

### Управление буфером

-   **Очистить кольцевой буфер (требует прав `root`):**
    ```bash
    sudo dmesg -C
    ```
    Полезно перед отладкой, чтобы отделить старые сообщения от новых.

-   **Посмотреть размер буфера:**
    ```bash
    dmesg --buffer-size
    ```

## `dmesg` и `journald`

В современных системах с `systemd` логи ядра также собираются в `journald` и доступны через команду `journalctl`. `journalctl` предоставляет более мощные средства для фильтрации и анализа.

-   **Показать сообщения ядра из журнала:**
    ```bash
    journalctl -k
    # или
    journalctl --dmesg
    ```

-   **Следить за новыми сообщениями ядра:**
    ```bash
    journalctl -fk
    ```

Тем не менее, `dmesg` остается быстрым и удобным инструментом для оперативной диагностики, особенно в окружениях, где `journald` может быть недоступен (например, в initramfs).
