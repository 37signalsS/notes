# `traceroute` и `mtr` — Трассировка маршрута

## 1. Определение

`traceroute` и `mtr` — это сетевые диагностические утилиты, которые позволяют отследить маршрут следования IP-пакетов от источника до пункта назначения. Они показывают последовательность маршрутизаторов (хопов), через которые проходят пакеты, и измеряют задержки до каждого из них.

## 2. Основные концепции

### `traceroute`

`traceroute` работает, отправляя последовательность пакетов с постепенно увеличивающимся значением `TTL` (Time To Live).
1. Первый пакет отправляется с `TTL=1`. Первый же маршрутизатор на пути уменьшает `TTL` до 0, отбрасывает пакет и отправляет источнику ICMP-сообщение "Time Exceeded". Так определяется первый хоп.
2. Второй пакет отправляется с `TTL=2`. Он доходит до второго маршрутизатора, который возвращает "Time Exceeded". Так определяется второй хоп.
3. Процесс продолжается до тех пор, пока пакет не достигнет конечного хоста.

Это позволяет построить карту маршрута и измерить задержку до каждого узла.

### `mtr`

`mtr` (My Traceroute) объединяет функциональность `traceroute` и `ping`. Он в реальном времени постоянно отправляет пакеты и отображает обновляемую статистику по каждому хопу, включая:
- **Loss%:** Процент потерянных пакетов.
- **Snt:** Количество отправленных пакетов.
- **Last, Avg, Best, Wrst:** Последняя, средняя, лучшая и худшая задержка (RTT).
- **StDev:** Стандартное отклонение, показывающее стабильность задержки.

Это делает `mtr` гораздо более мощным инструментом для диагностики постоянных проблем с сетью, таких как потеря пакетов или нестабильные задержки на определённом участке.

## 3. Практические сценарии

### `traceroute`: Простая трассировка

```bash
# Посмотреть маршрут до хоста ya.ru
traceroute ya.ru
```

Для обхода фаерволов, которые могут блокировать стандартные UDP или ICMP пакеты `traceroute`, можно использовать TCP-пакеты.

```bash
# Использовать TCP-пакеты на порт 80 (HTTP)
# -n - не разрешать IP в имена для ускорения
sudo traceroute -n -T -p 80 ya.ru
```

### `mtr`: Интерактивная диагностика

`mtr` является предпочтительным инструментом для глубокого анализа.

```bash
# Запустить интерактивную трассировку
mtr ya.ru
```
Оставьте `mtr` работать на несколько минут, чтобы собрать репрезентативную статистику. Потери пакетов (Loss%) или высокие задержки (Avg, Wrst) на определённом хопе укажут на проблемный узел в сети.

## 4. Продвинутые детали

### `mtr`: Режим отчёта

Для автоматического сбора данных `mtr` можно запустить в режиме отчёта, который отправит указанное количество пакетов и выведет результат.

```bash
# Отправить 10 пакетов на каждый хоп и вывести отчёт
mtr -r -c 10 ya.ru
```

### Интерпретация результатов

- **Потери на одном хопе:** Если один узел показывает 100% потерь, но последующие узлы отвечают нормально, это, скорее всего, означает, что данный маршрутизатор просто настроен не отвечать на ICMP/UDP пакеты, и это не является проблемой.
- **Нарастающие потери:** Если потери начинаются с определённого хопа и продолжаются до конца (или увеличиваются), это указывает на реальную проблему на этом или последующих участках сети.
- **Высокая задержка:** Резкое увеличение задержки на одном из хопов, которое сохраняется для всех последующих, указывает на "бутылочное горлышко" в сети.
