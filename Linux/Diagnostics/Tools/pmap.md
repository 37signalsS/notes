# `pmap` — Карта памяти процесса

## 1. Определение

`pmap` (Process Memory Map) — это утилита, которая отображает подробную карту памяти указанного процесса. Она позволяет увидеть, из каких сегментов состоит его виртуальное адресное пространство, их размеры, права доступа и сколько реальной физической памяти (RSS) они занимают.

## 2. Основные концепции

`pmap` получает информацию непосредственно из файла `/proc/<PID>/maps` и `/proc/<PID>/smaps`, представляя её в более удобном для анализа виде. Вывод `pmap` показывает каждый "маппинг" (отображение) в адресном пространстве процесса.

Каждый маппинг представляет собой непрерывный диапазон виртуальной памяти и имеет следующие атрибуты:
- **Адрес:** Начальный адрес сегмента в виртуальной памяти.
- **Размер:** Размер сегмента.
- **Права доступа:** `r` (чтение), `w` (запись), `x` (исполнение), `s` (разделяемый), `p` (приватный).
- **RSS (Resident Set Size):** Объём физической памяти, который фактически занимает этот сегмент.
- **Источник:** Файл, который отображен в этот сегмент (например, исполняемый файл, библиотека) или `[anon]` для анонимной памяти (например, куча или стек).

## 3. Практические сценарии

### Просмотр карты памяти процесса

Для просмотра карты памяти процесса необходимо знать его PID.

```bash
# Показать базовую карту памяти для процесса с <PID>
pmap <PID>
```

### Расширенный формат

Наиболее полезным является расширенный формат (`-x`), который показывает больше деталей, включая RSS.

```bash
# Показать расширенную информацию о памяти процесса
pmap -x <PID>
```

В выводе этой команды особенно важна последняя строка `total`, которая суммирует `RSS` и показывает общее потребление физической памяти процессом.

### Очень расширенный формат

Флаг `-X` предоставляет максимальную детализацию, аналогичную содержимому `/proc/<PID>/smaps`.

```bash
# Показать самую подробную информацию
pmap -X <PID>
```
Это позволяет увидеть такие метрики, как `PSS` (Proportional Set Size) и `USS` (Unique Set Size) для каждого маппинга.

## 4. Продвинутые детали

### Анализ утечек памяти

`pmap` может быть полезен для грубого анализа утечек памяти. Если периодически запускать `pmap -x <PID>` и наблюдать за ростом `[anon]` сегментов, это может указывать на то, что процесс выделяет память в куче и не освобождает её.

### Определение используемых библиотек

Вывод `pmap` наглядно показывает, какие разделяемые библиотеки (`.so`) загружены в адресное пространство процесса и какой объём памяти они занимают. Это может быть полезно для разрешения конфликтов версий или анализа зависимостей.
