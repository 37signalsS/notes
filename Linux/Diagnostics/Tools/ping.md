# `ping` — Проверка доступности хоста

## 1. Определение

`ping` — это базовая утилита для проверки сетевого подключения между хостами. Она работает путем отправки ICMP (Internet Control Message Protocol) пакетов типа "echo request" на целевой хост и ожидания ответа "echo reply".

## 2. Основные концепции

Успешный обмен пакетами `ping` подтверждает, что:
- Целевой хост доступен в сети.
- Между исходным и целевым хостами существует работающий маршрут.
- Нет фаерволов, блокирующих ICMP-трафик.

Основная измеряемая метрика — **RTT (Round-Trip Time)**, время, за которое пакет доходит до цели и возвращается обратно.

## 3. Практические сценарии

### Простая проверка доступности

```bash
# Отправить пакеты на хост ya.ru до остановки вручную (Ctrl+C)
ping ya.ru
```

### Ограничение количества пакетов

Для автоматических проверок полезно ограничивать количество отправляемых пакетов.

```bash
# Отправить 5 пакетов и завершить работу
ping -c 5 ya.ru
```

### Изменение интервала

Можно изменить интервал между отправкой пакетов.

```bash
# Отправлять пакеты каждые 0.2 секунды (флуд-режим)
sudo ping -f ya.ru

# Отправлять пакеты каждые 3 секунды
ping -i 3 ya.ru
```

## 4. Продвинутые детали

### Тестирование MTU

`ping` можно использовать для определения максимального размера пакета (MTU) на пути к хосту, что критически важно для диагностики проблем с фрагментацией.

```bash
# Отправить пакет размером 1472 байта с флагом "Don't Fragment" (не фрагментировать)
ping -c 4 -s 1472 -M do 8.8.8.8
```

- **`-s 1472`**: Устанавливает размер полезной нагрузки ICMP. 1472 байта + 28 байт (заголовки IP и ICMP) = 1500 байт, стандартный MTU для Ethernet.
- **`-M do`**: Устанавливает флаг DF (Don't Fragment). Если пакет такого размера не может пройти через какой-либо узел без фрагментации, утилита вернет ошибку, и нужно пробовать меньший размер.

### Указание интерфейса

Если на машине несколько сетевых интерфейсов, можно указать, какой из них использовать.

```bash
# Отправить ping с интерфейса eth1
ping -I eth1 ya.ru
```
