# `fio` — Тестирование производительности I/O

## 1. Определение

`fio` (Flexible I/O Tester) — это мощная утилита для бенчмаркинга и стресс-тестирования систем хранения данных (I/O). Она позволяет эмулировать различные типы дисковой нагрузки и измерять ключевые метрики производительности, такие как IOPS и пропускная способность.

## 2. Основные концепции
- **Паттерны нагрузки:** `fio` может симулировать последовательный (sequential) и случайный (random) доступ на чтение и запись, что позволяет имитировать нагрузку от разных приложений (например, базы данных, файловые серверы).
- **Механизмы I/O:** Поддерживает различные движки ввода-вывода (`ioengine`), такие как синхронный `sync`, асинхронный `libaio` и современный `io_uring`, что позволяет проводить тесты в разных режимах.
- **Ключевые метрики:** В отчетах `fio` предоставляет важнейшие показатели:
    - **BW (Bandwidth):** Пропускная способность (MB/s).
    - **IOPS:** Операции ввода-вывода в секунду.
    - **Latency (lat):** Задержки на выполнение операций.

## 3. Практические сценарии
### Базовый тест последовательной записи
```bash
# Записать 1GB данных блоками по 1MB в файл testfile
fio --name=seq_write --rw=write --bs=1M --size=1G --filename=./testfile
```

### Тест случайного чтения (типично для БД)
```bash
# Прочитать 1GB данных случайными блоками по 4KB
fio --name=rand_read --rw=randread --bs=4k --size=1G --filename=./testfile
```

### Смешанная нагрузка с несколькими потоками
```bash
# Эмулировать нагрузку с 4 потоками и глубиной очереди 32
fio --name=multithread --rw=randrw --bs=4k --numjobs=4 --iodepth=32 --size=1G --filename=./testfile --group_reporting
```

## 4. Продвинутые детали
### Ключевые параметры для кастомизации
- `--rw`: Режим операции (`read`, `write`, `randread`, `randwrite`, `randrw`).
- `--bs`: Размер блока (например, `4k`, `1M`).
- `--size`: Общий объем данных для операции.
- `--numjobs`: Количество параллельных задач (потоков).
- `--ioengine`: Механизм I/O (`libaio`, `sync`, `io_uring`).
- `--iodepth`: Глубина очереди запросов для асинхронных движков.

Интерпретация результатов `fio` позволяет получить конкретные цифры вместо абстрактного "диск медленный". Например, "1500 IOPS при random read 4K с задержкой 15 ms".
