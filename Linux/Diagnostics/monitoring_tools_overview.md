# Утилиты командной строки для мониторинга производительности

В Linux существует множество утилит для анализа производительности системы в реальном времени. Этот документ описывает наиболее распространенные из них.

## Комплексные утилиты

### top
`top` — это стандартная утилита, которая предоставляет динамический обзор процессов и использования системных ресурсов.

**Ключевые особенности:**
- **Режим потоков:** Нажатие `Shift + H` переключает отображение с процессов на потоки. Это полезно для анализа многопоточных приложений. Процесс, потребляющий более 100% CPU, является многопоточным.
- **Изменение частоты обновления:** Нажатие `s` позволяет изменить интервал обновления (по умолчанию 3 секунды). Установка в 1 секунду делает картину более динамичной.
- **Пакетный режим (`-b`):** Позволяет выводить "снимки" состояния процессов в неинтерактивном режиме, что можно использовать для простого логирования.

### atop
`atop` — это мощный инструмент мониторинга, который можно назвать "комбайном". Внешне он похож на `top`, но предоставляет гораздо больше метрик и, что самое важное, **пишет историю**.

- **Демон в фоне:** `atop` запускает фоновый демон, который периодически записывает состояние системы в лог (`/var/log/atop/`). Это позволяет анализировать проблемы производительности постфактум.
- **Комплексные метрики:** В одном окне отображает нагрузку на CPU, память, **диски** и **сеть**.
- **Детализация по процессам:** Показывает не только использование CPU и памяти процессом, но и его дисковую активность (чтение/запись), что является частичной заменой `iotop`.

### htop
`htop` — это улучшенная, более интерактивная и наглядная версия `top`. Обычно требует доустановки. По функциональности схож с `top`, но предоставляет более удобный интерфейс для управления процессами, сортировки и навигации.

## Специализированные утилиты

### vmstat
`vmstat` (virtual memory statistics) — утилита для мониторинга виртуальной памяти, процессов, I/O и CPU. Особенно полезна для анализа активности подкачки (swap).

- **Ключевые колонки:**
  - `si` (swap-in): Память, загруженная из swap в RAM. Постоянно высокое значение — признак нехватки RAM.
  - `so` (swap-out): Память, выгруженная из RAM в swap.
  - `bi` (blocks in): Блоки, полученные с блочного устройства (чтение с диска).
  - `bo` (blocks out): Блоки, отправленные на блочное устройство (запись на диск).
- **Режим обновления:** `vmstat 1` будет выводить статистику каждую секунду.

### free
Утилита `free` предоставляет краткую сводку об использовании оперативной (RAM) и swap-памяти.
- `free -h`: Выводит информацию в человекочитаемом формате (килобайты, мегабайты, гигабайты).
- `free -m`: Выводит информацию в мегабайтах.

### df / du
Эти утилиты используются для анализа дискового пространства.

- **`df` (disk free):** Показывает **свободное место** на смонтированных файловых системах. Отрабатывает мгновенно.
  - `df -h`: Человекочитаемый формат.
  - `df -i`: Показывает использование **inodes**. Если inodes закончатся, новые файлы создавать будет нельзя, даже при наличии свободного места.
- **`du` (disk usage):** Показывает, **сколько места занимают** файлы и директории. Работает медленно, так как рекурсивно обходит каталоги.
  - `du -sh /path/to/dir`: Показать суммарный размер директории.
  - `du -h --max-depth=1 /path/to/dir`: Показать размеры всех поддиректорий на первом уровне вложенности.

### iotop
`iotop` — это "top для дискового I/O". Показывает, какие именно процессы активно читают или пишут на диск. Незаменим, если `top` показывает высокое значение `iowait`.

### mpstat
`mpstat` (multi-processor statistics) — выводит статистику по каждому ядру CPU. Полезна для выявления неравномерной нагрузки, когда один поток утилизирует одно ядро на 100%, а общая загрузка CPU невысока.

### pidstat
`pidstat` — утилита для сбора статистики по конкретным процессам. Особенно полезна для отслеживания **короткоживущих процессов**, которые сложно заметить в `top`.

### sar
`sar` (System Activity Report) — мощный инструмент из пакета `sysstat`, который может собирать и отображать исторические данные о производительности практически всех подсистем: CPU, памяти, дисков, сети.

- **Пример для сети:** `sar -n DEV 1` будет показывать сетевую статистику (пакеты в секунду, байты в секунду) для каждого интерфейса с интервалом в 1 секунду.

### ss
`ss` (socket statistics) — современная замена утилиты `netstat`. Используется для анализа сетевых сокетов.

- **Ключевая команда:**
  ```bash
  # Показать все слушающие TCP и UDP порты, процессы, которые их используют, и числовые значения
  ss -tulpan
  ```

### perf
`perf` — это ультимативный инструмент для профилирования производительности, встроенный в ядро Linux. Он позволяет заглянуть "внутрь" процессов и ядра.

- **`perf top`**: В реальном времени показывает, какие **функции** (символы) в ядре и пользовательских программах потребляют больше всего процессорного времени. Это позволяет точно определить источник нагрузки, вплоть до конкретной функции в коде.

### pmap
`pmap` (process memory map) — утилита, которая показывает подробную карту памяти указанного процесса. Она позволяет увидеть, из каких сегментов (код, данные, библиотеки) состоит виртуальное адресное пространство процесса и сколько реальной памяти (RSS) занимает каждый из них.

- **Ключевая команда:**
  ```bash
  # Показать расширенную информацию о карте памяти процесса
  pmap -x <PID>
  ```
  Вывод `pmap` помогает понять, как именно процесс использует память, и идентифицировать крупные сегменты, такие как загруженные библиотеки или анонимные выделения.

### smem
`smem` — это продвинутая утилита для анализа потребления памяти, которая умеет корректно считать разделяемую память и показывать "справедливые" метрики.

- **Ключевые особенности:**
  - **Показывает PSS и USS:** В отличие от `top` или `ps`, `smem` по умолчанию оперирует метриками **PSS** (Proportional Set Size) и **USS** (Unique Set Size), которые дают более реалистичную картину потребления памяти.
  - **Гибкая отчетность:** Позволяет генерировать отчеты по пользователям, процессам, отображать данные в виде графиков.
- **Пример:**
  ```bash
  # Показать потребление памяти по процессам, отсортированное по PSS
  smem -p

  # Показать потребление памяти по пользователям
  smem -u
  ```
