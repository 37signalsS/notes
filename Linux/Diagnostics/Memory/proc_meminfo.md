# `/proc/meminfo`

## Определения

Виртуальный файл `/proc/meminfo` предоставляет исчерпывающую статистику об использовании ядром оперативной (RAM) и swap-памяти в реальном времени. Это основной источник "сырых" данных для многих утилит мониторинга, таких как `free`, `top` и [`vmstat`](./vmstat.md).

## Основные концепции

### Ключевые показатели: `MemAvailable` vs `MemFree`

Linux стремится максимально эффективно использовать доступную RAM, поэтому "свободная" память (`MemFree`) почти всегда будет занята дисковым кэшем. Это не проблема, а особенность работы ядра.

- **`MemFree`**: Память, которая прямо сейчас не задействована ни под процессы, ни под кэш. В здоровой системе её значение обычно невелико.
- **`Buffers` и `Cached`**: Память, используемая для хранения метаданных файловой системы и данных файлов (page cache), к которым недавно обращались. Это ускоряет повторный доступ. Ядро может легко освободить эту память, если она понадобится приложениям.
- **`MemAvailable`**: **Ключевой показатель**, отражающий, сколько памяти реально доступно для запуска новых приложений без обращения к swap. Он учитывает `MemFree` и ту часть кэша, которую можно безболезненно очистить.

### Типы памяти: Активная, Неактивная, Анонимная, Файловая

Ядро классифицирует память для более эффективного управления:

- **Активная (`Active`) vs. Неактивная (`Inactive`)**: Ядро делит память на "активную" (используется прямо сейчас) и "неактивную" (использовалась недавно). При нехватке ресурсов первой освобождается неактивная память.
- **Анонимная (`Active(anon)`, `Inactive(anon)`)**: Память, не связанная напрямую с файлами. В основном это память процессов: куча (heap) и стек (stack).
- **Файловая (`Active(file)`, `Inactive(file)`)**: Память, используемая для дискового кэша (page cache).

### Водяные знаки памяти (Memory Watermarks)

Ядро использует три порога свободной памяти для управления выделением и освобождением страниц:

| Watermark | Описание |
| :--- | :--- |
| **`min`** | Минимальный уровень. При достижении запускается **прямое освобождение** (direct reclaim) — процессы блокируются для освобождения памяти |
| **`low`** | Порог для запуска **фонового освобождения** демоном [`kswapd`](../../Core/memory/caching_and_reclaiming.md) |
| **`high`** | Целевой уровень, до которого `kswapd` пытается освободить память |

> **Важно:** Активное прямое освобождение (когда процессы вынуждены сами освобождать память) указывает на критическую нехватку RAM. Просмотр текущих значений: `cat /proc/zoneinfo | grep -E 'min|low|high'`.
>
> Подробнее о механизмах освобождения памяти — в [Кэшировании и освобождении памяти](../../Core/memory/caching_and_reclaiming.md).

### Полный справочник параметров `/proc/meminfo`

#### Основные метрики

| Параметр | Описание |
|----------|----------|
| `MemTotal` | Общий объем физической RAM |
| `MemFree` | Количество полностью свободной, неиспользуемой памяти |
| `MemAvailable` | Оценка памяти, доступной для новых приложений без своппинга. **Основной показатель для оценки свободной памяти.** |
| `Buffers` | Кэш метаданных файловой системы |
| `Cached` | Кэш данных файлов (страничный кэш) |
| `SwapCached` | Память, выгруженная в swap и снова загруженная в RAM, но оставшаяся в swap-файле для быстрой повторной выгрузки |

#### Классификация памяти

| Параметр | Описание |
|----------|----------|
| `Active` | Активно используемая память |
| `Inactive` | Недавно использовавшаяся память, кандидат на освобождение |
| `Active(anon)` / `Inactive(anon)` | Анонимная память процессов (heap, stack) |
| `Active(file)` / `Inactive(file)` | Память, используемая для кэширования файлов |
| `Unevictable` | Страницы памяти, которые нельзя выгрузить в swap (заблокированные `mlock()` или `ramfs`) |
| `Mlocked` | Память, заблокированная процессом через `mlock()` |

#### Swap-пространство

| Параметр | Описание |
|----------|----------|
| `SwapTotal` | Общий размер раздела или файла подкачки |
| `SwapFree` | Количество свободного места в swap |

#### Страницы памяти

| Параметр | Описание |
|----------|----------|
| `Dirty` | Память, изменённая, но ещё не записанная на диск |
| `Writeback` | Память, записываемая на диск в данный момент |
| `AnonPages` | Анонимные (нефайловые) страницы памяти, используемые процессами |
| `Mapped` | Память, отображённая в адресное пространство процессов (файлы, библиотеки) |
| `Shmem` | Объём разделяемой памяти (включая `tmpfs`) |

#### Память ядра

| Параметр | Описание |
|----------|----------|
| `Slab` | Память для кэширования структур данных ядра (inodes, dentries). Делится на `SReclaimable` и `SUnreclaim`. Подробнее — [Slab Allocator](../../Core/memory/slab_allocator.md) |
| `KernelStack` | Память, выделенная для стеков потоков ядра |
| `PageTables` | Память таблиц страниц для трансляции виртуальных адресов в физические |
| `VmallocTotal` / `VmallocUsed` | Область виртуальной памяти ядра для больших непрерывных участков |

#### Управление памятью

| Параметр | Описание |
|----------|----------|
| `CommitLimit` | Общий объём виртуальной памяти, который система может выделить: `SwapTotal + (MemTotal * vm.overcommit_ratio / 100)` |
| `Committed_AS` | Объём виртуальной памяти, уже запрошенный процессами. При приближении к `CommitLimit` система близка к нехватке памяти |

#### Huge Pages

| Параметр | Описание |
|----------|----------|
| `HugePages_Total` / `HugePages_Free` / `Hugepagesize` | Информация об "огромных страницах" для снижения накладных расходов при больших объёмах данных. Подробнее — [Оптимизация памяти](../../Core/memory/performance_tuning.md) |

## Практические сценарии

### Оценка реального свободного места

Чтобы понять, сколько памяти доступно для приложений, следует анализировать `MemAvailable`, а не `MemFree`.

```bash
# Посмотреть доступную память в kB
grep MemAvailable /proc/meminfo
```

### Диагностика нехватки памяти

Признаки нехватки RAM:

- **Низкое значение `MemAvailable`**: Основной индикатор.
- **Постоянный рост `SwapUsed`**: Система вынуждена выгружать данные из RAM на медленный диск.
- **Высокое значение `Active(anon)`**: Указывает, что память потребляют процессы, а не дисковый кэш. Может быть признаком утечки памяти в приложении.
- **Рост `Committed_AS` до `CommitLimit`**: Показывает, что процессы запросили почти всю доступную виртуальную память.

### Диагностика давления inode/dentry в кэше

После массового сканирования файловой системы (например, `rsync`, `find`, бэкап) свободная RAM может резко уменьшиться, хотя `SwapUsed` нулевой и процессы не потребляют много памяти.

Это происходит из-за того, что ядро кэширует метаданные миллионов файлов (inode и dentry) в `Slab`. Этот кэш ускоряет повторный доступ, но при однократном обходе приводит к раздуванию кэша, который не освобождается немедленно.

**Шаги диагностики:**

1. **Проверить рост Slab-кэша:**
    Сравните `Slab`, `SReclaimable` (освобождаемый) и `SUnreclaim` (неосвобождаемый). Если `Slab` и особенно `SReclaimable` велики, память занята кэшем ядра.

    ```bash
    cat /proc/meminfo | grep -E "Slab|SReclaimable|SUnreclaim"
    ```

2. **Определить, что именно занимает Slab:**
    Проверьте, какие структуры лидируют. В данном случае это будут `dentry` и `*_inode_cache`.

    ```bash
    # Показать топ потребителей в Slab
    slabtop -o
    
    # Или отфильтровать вручную
    cat /proc/slabinfo | grep -E "dentry|inode"
    ```

**Вывод:** Если `SReclaimable` занимает гигабайты, а `slabtop` показывает `dentry` и `inode_cache` наверху, значит, память занята кэшем метаданных VFS. Теоретически этот кэш освобождается при нехватке памяти (`memory pressure`), но если система не испытывает давления, кэш может "висеть" долгое время.

## Дополнительная информация

### Связь с другими утилитами

`/proc/meminfo` является источником "сырых" данных для утилит [`top`](../Processes/top.md) и [`vmstat`](./vmstat.md). Эти утилиты агрегируют и форматируют данные из `meminfo`, предоставляя их в более удобном виде.

### Связь с механизмом кэширования и reclaim

Данные `/proc/meminfo` тесно связаны с механизмами кэширования и освобождения памяти ядром. Параметр `Slab` отражает состояние slab-кэша, описанного в [Slab Allocator](../../Core/memory/slab_allocator.md), а водяные знаки (`min`, `low`, `high`) управляют работой демона [`kswapd`](../../Core/memory/caching_and_reclaiming.md).
