# `/proc/meminfo` и диагностика памяти

## 1. Определение

Виртуальный файл `/proc/meminfo` предоставляет исчерпывающую статистику об использовании ядром оперативной (RAM) и swap-памяти в реальном времени. Это основной источник "сырых" данных для многих утилит мониторинга, таких как `free`, `top` и `vmstat`.

## 2. Основные концепции

### Кэширование и доступная память

Linux стремится максимально эффективно использовать доступную RAM, поэтому "свободная" память (`MemFree`) почти всегда будет занята дисковым кэшем. Это не проблема, а особенность работы ядра.

-   **Кэш (`Cached`, `Buffers`):** Память, используемая для хранения данных файлов, к которым недавно обращались. Это ускоряет повторный доступ к ним. Ядро может легко освободить эту память, если она понадобится приложениям.
-   **Доступная память (`MemAvailable`):** **Ключевой показатель**, отражающий, сколько памяти реально доступно для запуска новых приложений без обращения к swap. Он учитывает свободную память и ту часть кэша, которую можно безболезненно очистить.

### Активная vs. Неактивная память

Ядро делит память на "активную" (используется прямо сейчас) и "неактивную" (использовалась недавно). При нехватке ресурсов первой освобождается неактивная память.

### Анонимная vs. Файловая память

-   **Анонимная память (`Active(anon)`, `Inactive(anon)`):** Память, не связанная напрямую с файлами. В основном это память процессов: куча (heap) и стек (stack).
-   **Файловая память (`Active(file)`, `Inactive(file)`):** Память, используемая для дискового кэша (page cache).

## 3. Практические сценарии

### Оценка реального свободного места

Чтобы понять, сколько памяти доступно для приложений, используйте `MemAvailable`.
```bash
# Посмотреть доступную память в kB
cat /proc/meminfo | grep MemAvailable
```

### Диагностика нехватки памяти

Признаки нехватки RAM:
-   **Низкое значение `MemAvailable`**.
-   **Постоянный рост `SwapUsed`**: Система вынуждена выгружать данные из RAM на медленный диск.
-   **Высокое значение `Active(anon)`**: Указывает, что память потребляют процессы, а не дисковый кэш. Это может быть признаком утечки памяти в приложении.

### Инвентаризация физической памяти (RAM)

Для получения информации об установленных модулях RAM используется `dmidecode`.
```bash
# Показать информацию о каждом модуле RAM
sudo dmidecode -t memory
```
Эта команда покажет детальную информацию о каждом слоте памяти: производитель, объем, скорость, тип и т.д.

## 4. Справочник ключевых параметров

-   `MemTotal`: Общий объем физической RAM.
-   `MemFree`: Количество полностью свободной, неиспользуемой памяти.
-   `MemAvailable`: Оценка памяти, доступной для новых приложений без своппинга.
-   `Buffers`: Кэш метаданных файловой системы.
-   `Cached`: Кэш данных файлов (страничный кэш).
-   `SwapCached`: Память, которая была выгружена в swap, а затем снова загружена в RAM, но все еще остается в swap-файле для быстрой повторной выгрузки.
-   `Active`: Активно используемая память.
-   `Inactive`: Недавно использовавшаяся память, кандидат на освобождение.
-   `Active(anon)` / `Inactive(anon)`: Анонимная память процессов.
-   `Active(file)` / `Inactive(file)`: Память, используемая для кэширования файлов.
-   `Unevictable`: Страницы памяти, которые нельзя выгрузить в swap (заблокированные `mlock()` или `ramfs`).
-   `Mlocked`: Память, заблокированная процессом через `mlock()`.
-   `Slab`: Память, используемая ядром для собственных структур данных.
-   `VmallocTotal` / `VmallocUsed`: Область виртуальной памяти ядра для больших непрерывных участков.
