# /proc/meminfo — статистика памяти ядра

## Определения

Виртуальный файл `/proc/meminfo` предоставляет исчерпывающую статистику об использовании ядром оперативной (RAM) и swap-памяти в реальном времени. Это основной источник данных для большинства утилит системного мониторинга, таких как `free`, `top` и [`vmstat`](./vmstat.md).

## Основные концепции

### Ключевые показатели: MemAvailable vs MemFree

Ядро Linux стремится максимально эффективно использовать доступную оперативную память, поэтому "полностью свободная" память (`MemFree`) обычно составляет малую часть общего объёма, так как остальное занято дисковым кэшем.

- **MemFree**: Память, которая в данный момент не задействована ни процессами, ни системным кэшем.
- **Buffers** и **Cached**: Память, используемая для временного хранения данных файлов и метаданных файловой системы (page cache). Ядро может немедленно освободить эту память, если она потребуется приложениям.
- **MemAvailable**: Самый важный показатель для системного администратора. Это оценка объёма памяти, который реально доступен для запуска новых приложений без ухода системы в swap. Он учитывает `MemFree` и ту часть кэша, которую можно безопасно очистить.

### Классификация типов памяти

Для эффективного управления ядро делит страницы памяти на категории:

- **Активная (Active)** vs. **Неактивная (Inactive)**: Память, используемая в данный момент, и память, к которой давно не было обращений (кандидат на выгрузку).
- **Анонимная (Active(anon), Inactive(anon))**: Память процессов, не связанная с файлами на диске (куча, стек, сегменты данных).
- **Файловая (Active(file), Inactive(file))**: Память, в которой закэшировано содержимое файлов.

### Водяные знаки памяти (Memory Watermarks)

Ядро использует три порога (watermarks) для управления выделением и освобождением страниц:

| Watermark | Описание |
| :--- | :--- |
| **min** | Критический уровень. При его достижении запускается прямое освобождение (direct reclaim), что приводит к блокировке процессов до высвобождения памяти. |
| **low** | Порог активации фонового демона [`kswapd`](../../Core/memory/caching_and_reclaiming.md), который начинает плавно освобождать память. |
| **high** | Целевой уровень, до которого `kswapd` пытается довести объём свободной памяти. |

> **Важно:** Постоянное нахождение на уровне `min` указывает на критическую нехватку RAM. Текущие значения можно посмотреть в `/proc/zoneinfo`.
> Подробнее об алгоритмах освобождения — в [Кэшировании и освобождении памяти](../../Core/memory/caching_and_reclaiming.md).

### Справочник параметров /proc/meminfo

#### Основные метрики

| Параметр | Описание |
|:---|:---|
| `MemTotal` | Общий объем физической оперативной памяти. |
| `MemFree` | Полностью свободная, неиспользуемая память. |
| `MemAvailable` | Оценка памяти, доступной для новых приложений. **Основной индикатор.** |
| `Buffers` | Кэш метаданных файловой системы. |
| `Cached` | Страничный кэш (page cache) данных файлов. |
| `SwapCached` | Память, которая была в swap, загружена в RAM, но копия всё ещё хранится в swap. |

#### Классификация страниц

| Параметр | Описание |
|:---|:---|
| `Active` / `Inactive` | Уровни активности использования страниц. |
| `Active(anon)` / `Inactive(anon)` | Анонимная память (динамическая память процессов). |
| `Active(file)` / `Inactive(file)` | Память дискового кэша. |
| `Unevictable` | Память, которую нельзя выгрузить (например, заблокированная через `mlock`). |
| `Mlocked` | Объём памяти, принудительно заблокированной в RAM. |

#### Подкачка (Swap)

| Параметр | Описание |
|:---|:---|
| `SwapTotal` | Общий размер всех разделов и файлов подкачки. |
| `SwapFree` | Доступное свободное место в swap. |

#### Служебные метрики

| Параметр | Описание |
|:---|:---|
| `Dirty` | Данные в RAM, изменённые, но ещё не записанные на диск. |
| `Writeback` | Данные, записываемые на диск в данный момент. |
| `AnonPages` | Общий объём анонимных страниц памяти. |
| `Mapped` | Память, отображённая в адресное пространство процессов (библиотеки, файлы). |
| `Shmem` | Объём разделяемой памяти (shared memory, `tmpfs`). |

#### Память ядра

| Параметр | Описание |
|:---|:---|
| `Slab` | Память под кэш структур данных ядра. Подробнее: [Slab Allocator](../../Core/memory/slab_allocator.md). |
| `KernelStack` | Память для стеков выполнения потоков ядра. |
| `PageTables` | Память, занятая таблицами страниц (трансляция адресов). |
| `VmallocTotal` / `VmallocUsed` | Использование области виртуальной памяти ядра. |

#### Управление и лимиты

| Параметр | Описание |
|:---|:---|
| `CommitLimit` | Максимальный объём виртуальной памяти, который можно выделить без риска сбоя (зависит от настроек Overcommit). |
| `Committed_AS` | Объём виртуальной памяти, фактически запрошенный процессами. |

#### Huge Pages — огромные страницы

| Параметр | Описание |
|:---|:---|
| `HugePages_Total` | Общее количество выделенных Huge Pages. |
| `HugePages_Free` | Количество неиспользуемых Huge Pages. |
| `Hugepagesize` | Размер одной Huge Page (обычно 2MB или 1GB). |

Подробнее о настройке — в [Оптимизации памяти](../../Core/memory/performance_tuning.md).

## Практические сценарии

### Оценка реального запаса памяти

Для определения возможности запуска новых сервисов или расширения текущих следует смотреть на `MemAvailable`.

```bash
grep MemAvailable /proc/meminfo
# → MemAvailable:    1524380 kB
```

### Диагностика утечек памяти

Если `MemAvailable` постоянно снижается, а `Active(anon)` или `Slab` постоянно растёт при стабильной нагрузке, это может указывать на утечку памяти в приложении или ядре.

```bash
# Проверка анонимной памяти (память процессов)
grep "Active(anon)" /proc/meminfo

# Проверка Slab-кэша (память ядра)
grep Slab /proc/meminfo
```

### Диагностика давления дискового кэша

Если `Dirty` страницы занимают значительный объём, а система "фризит" при записи, это указывает на задержки дисковой подсистемы.

```bash
grep -E "Dirty|Writeback" /proc/meminfo
# → Dirty:              512 kB
# → Writeback:            0 kB
```

Детальный анализ структур Slab и их очистки описан в статье [Slab Allocator](../../Core/memory/slab_allocator.md).

## Дополнительная информация

### Взаимосвязь с инструментарием

`/proc/meminfo` является первичным источником данных. Утилиты мониторинга лишь агрегируют эти значения:

- [`vmstat`](./vmstat.md) — показывает динамику изменений параметров `swap`, `free`, `buff`, `cache`.
- `free` — форматирует `MemTotal`, `MemFree`, `Buffers`, `Cached` и `MemAvailable` в удобную таблицу.
- [`top`](../Processes/top.md) — отображает эти же метрики в заголовке интерфейса.

### Связь с механизмами ядра

Состояние параметров в `/proc/meminfo` напрямую зависит от работы механизмов кэширования и освобождения памяти, описанных в [Core/memory/caching_and_reclaiming.md](../../Core/memory/caching_and_reclaiming.md). Метрики Slab-аллокатора детализируются в [Core/memory/slab_allocator.md](../../Core/memory/slab_allocator.md).
