# vmstat — статистика виртуальной памяти

## Определения

**`vmstat`** (Virtual Memory Statistics) — классическая системная утилита командной строки (входит в пакет `procps-ng`), предназначенная для оперативного мониторинга состояния ресурсов системы. Она предоставляет моментальный снимок активности процессов, использования RAM, работы подкачки (swap), интенсивности ввода-вывода (I/O) и нагрузки на CPU.

## Основные концепции

### Механизм получения данных

Утилита является интерпретатором виртуальных файлов ядра:
- `/proc/meminfo` — данные о памяти.
- `/proc/stat` — общая статистика CPU и прерываний.
- `/proc/vmstat` — детальные счетчики виртуальной памяти.
- `/proc/slabinfo` — статистика Slab-аллокатора (для `-m`).

### Особенности вывода
- **Первая строка:** Всегда содержит **средние значения** с момента загрузки системы (`uptime`), а не текущие показатели.
- **Интервальный режим:** При запуске `vmstat 1` последующие строки показывают дельту (изменения) за последнюю секунду.
- **Широкий формат (-w):** Рекомендуется для современных систем с большим количеством ядер, чтобы избежать "съезда" колонок.

### Расшифровка ключевых полей

| Группа | Поле | Описание | Индикатор проблем |
| :--- | :--- | :--- | :--- |
| **procs** | `r` | Очередь выполнения (runnable). | `r > ядер CPU` — процессор перегружен. |
| | `b` | Процессы в Uninterruptible sleep. | `b > 0` — ожидание диска или сетевого I/O. |
| **memory** | `swpd` | Использованный Swap. | Рост при малом `free` — нехватка RAM. |
| | `free` | Полностью свободная память. | Близкое к 0 — норма при высоком `cache`. |
| | `buff` | Метаданные файловых систем. | — |
| | `cache` | Page Cache (файловый кэш). | Высокое значение — эффективно для I/O. |
| **swap** | `si` / `so` | Swap-in / Swap-out (КБ/с). | Постоянные значения > 0 — Memory Thrashing. |
| **io** | `bi` / `bo` | Blocks in/out (считано/записано). | Высокие значения при высоком `wa`. |
| **system** | `in` | Прерывания в секунду. | Аномальный рост — проблемы с драйверами. |
| | `cs` | Context Switches (переключения). | Высокий `cs` при низком CPU — лишние потоки. |
| **cpu** | `us` / `sy` | Время User / System. | Высокий `sy` (>30%) — накладные расходы ядра. |
| | `wa` | I/O Wait (ожидание диска). | `wa > 15%` — дисковая подсистема тормозит. |
| | `st` | Steal time (украденное время). | `st > 0` — гипервизор перегружен (Overselling). |

## Практические сценарии

### 1. Детальная статистика дисков (-d)

Показывает сводную статистику по всем блочным устройствам: количество чтений, записей и объединенных (merged) запросов.

```bash
vmstat -d
# Колонки: reads (total, merged, sectors, ms), writes (total, merged, sectors, ms), IO (cur, s)
```
- **ms (milliseconds):** Суммарное время, затраченное на чтение/запись. Позволяет косвенно оценить латентность.

### 2. Анализ конкретных разделов (-p)

Полезно для изоляции нагрузки на конкретный раздел (например, корень `/` vs `/data`).

```bash
# Базовые счетчики для раздела sda1
vmstat -p /dev/sda1
```

### 3. Диагностика Slab-аллокатора (-m)

Позволяет увидеть, какие структуры ядра (inode, dentry, сетевые буферы) потребляют память. Требует прав **root**.

```bash
sudo vmstat -m | sort -k 2 -nr | head -n 10
```
- **Cache:** Название кэша (например, `ext4_inode_cache`).
- **Num:** Количество активных объектов.
- **Total:** Общее количество выделенных объектов.
- **Pages:** Количество физических страниц под данный кэш.

### 4. Счетчик создания процессов (-f)

Показывает общее количество форков (`fork`, `vfork`, `clone`) с момента загрузки.

```bash
vmstat -f
# Полезно для поиска "fork-bomb" или скриптов, порождающих слишком много короткоживущих процессов.
```

### 5. Добавление временных меток (-t)

Критично при длительном мониторинге в лог-файл.

```bash
vmstat -t 5 > vmstat_monitor.log
```

## Дополнительная информация

### Взаимодействие с PSI (Pressure Stall Information)

Хотя `vmstat` показывает симптомы (очереди в `r`, ожидание в `wa`), он не дает понимания, **насколько сильно** страдают процессы. 
- Если `vmstat` показывает высокий `wa`, проверьте `/proc/pressure/io`.
- Если `vmstat` показывает активный `si/so`, проверьте `/proc/pressure/memory`.

### Полезные флаги форматирования

- `-S M`: Вывод в мегабайтах (удобнее для анализа RAM на современных серверах).
- `-n`: Вывести заголовок только один раз (удобно для конвейеров).
- `-a`: Показать активную/неактивную память (Active/Inactive) вместо Buffers/Cache.
