# vmstat — статистика виртуальной памяти

## Определения

`vmstat` (Virtual Memory Statistics) — это утилита командной строки, предназначенная для оперативного мониторинга состояния системы. Она агрегирует данные о процессах, использовании оперативной памяти, активности подкачки (swap), операциях ввода-вывода (I/O), системных прерываниях и загрузке центрального процессора.

## Основные концепции

Утилита выводит информацию в виде строк, где первая строка после заголовка обычно содержит средние значения с момента загрузки системы. Последующие строки отражают статистику за конкретный интервал времени, если он был указан при запуске.

### Расшифровка полей вывода

Вывод `vmstat` разделен на логические секции:

- **procs (Процессы):**
  - `r` (runnable): Количество процессов, ожидающих процессорного времени (очередь выполнения).
  - `b` (blocked): Процессы в состоянии "непрерываемого сна" (обычно ожидание дискового I/O).
- **memory (Память):**
  - `swpd`: Объем используемой памяти в разделе подкачки (swap).
  - `free`: Объем полностью свободной оперативной памяти.
  - `buff`: Память, выделенная под буферы (метаданные файловой системы).
  - `cache`: Память, используемая под страничный кэш (содержимое файлов).
- **swap (Подкачка):**
  - `si` (swap-in): Скорость чтения данных из swap в RAM (КБ/с).
  - `so` (swap-out): Скорость выгрузки данных из RAM в swap (КБ/с).
- **io (Ввод-вывод):**
  - `bi` (blocks in): Блоков, считанных с диска (блоков/с).
  - `bo` (blocks out): Блоков, записанных на диск (блоков/с).
- **system (Система):**
  - `in`: Количество прерываний в секунду, включая прерывания таймера.
  - `cs`: Количество переключений контекста (context switches) в секунду.
- **cpu (Процессор):**
  - `us`: Время, затраченное на выполнение кода пользователя.
  - `sy`: Время, затраченное на выполнение кода ядра.
  - `id`: Время простоя (idle).
  - `wa`: Время ожидания завершения ввода-вывода (I/O wait).
  - `st`: Время, "украденное" гипервизором у виртуальной машины (steal time).

## Практические сценарии

### Мониторинг в реальном времени

Для наблюдения за динамикой изменений рекомендуется указывать интервал обновления.

```bash
# Обновлять статистику каждую секунду
vmstat 1

# Пример вывода:
# procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
#  r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
#  1  0      0 456780  12340 987650    0    0     4    20   50  120  2  1 96  1  0
```

### Диагностика дефицита памяти (Thrashing)

Если колонки `si` и `so` стабильно показывают высокие значения, это признак "пробуксовки" (thrashing) — ситуации, когда система тратит больше времени на перемещение данных между RAM и диском, чем на полезную работу.

- **Высокий `so`:** Система принудительно освобождает память, вытесняя данные на диск.
- **Высокий `si`:** Процессы пытаются получить доступ к данным, которые только что были выгружены в swap.

### Анализ дисковых задержек

- **Рост колонки `b`:** Указывает на наличие процессов, заблокированных операциями ввода-вывода.
- **Высокий `wa` (I/O wait):** Процессор простаивает, так как все активные задачи ждут ответа от дисковой подсистемы.

## Дополнительная информация

### Удобство чтения

Флаг `-S` позволяет изменить единицы измерения (по умолчанию КБ).

```bash
# Выводить данные в мегабайтах
vmstat -S M 1
```

### Статистика по дискам и разделам

Флаг `-d` выводит суммарную статистику по активности всех дисковых устройств.

```bash
# Показать статистику дисков
vmstat -d
```

### Использование в связке с другими утилитами

`vmstat` предоставляет общую "температуру по больнице". Если он выявил аномалии, для уточнения причин используйте:

- [`pmap`](./pmap.md) — чтобы увидеть, какой именно сегмент памяти процесса растет.
- [`smem`](./smem.md) — для точного подсчета PSS/USS потребления конкретных приложений.
- `top` или `htop` — для идентификации процессов с высокой загрузкой CPU или RAM.
