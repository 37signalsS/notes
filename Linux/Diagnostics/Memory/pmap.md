# pmap — карта памяти процесса

## Определения

`pmap` (Process Memory Map) — утилита командной строки, входящая в пакет `procps-ng`, которая отображает подробную карту памяти одного или нескольких процессов. Она визуализирует структуру виртуального адресного пространства, позволяя анализировать сегменты кода, данных, стека, кучи и загруженные разделяемые библиотеки.

## Основные концепции

Утилита работает как интерпретатор файлов ядра `/proc/<PID>/maps` (базовая информация) и `/proc/<PID>/smaps` (детальная статистика). Каждая строка вывода представляет собой непрерывный диапазон виртуальных адресов — "маппинг".

### Ключевые метрики и атрибуты

- **Address:** Начальный виртуальный адрес сегмента.
- **Kbytes:** Размер сегмента в килобайтах (Virtual Size).
- **RSS (Resident Set Size):** Фактически занятая физическая память (RAM).
- **PSS (Proportional Set Size):** Доля физической памяти с учётом разделяемых библиотек (если библиотека 1 МБ разделена между 10 процессами, каждому запишется 100 КБ).
- **Dirty:** "Грязные" страницы — изменённые данные в RAM, не синхронизированные с диском.
- **Mode (Права доступа):**
  - `r` — чтение, `w` — запись, `x` — исполнение.
  - `s` — разделяемый (shared), `p` — приватный (private/copy-on-write).
- **Mapping:** Источник сегмента (файл библиотеки, исполняемый файл или системные метки `[anon]`, `[stack]`, `[heap]`, `[vvar]`, `[vdso]`).

### Права доступа

Для просмотра карты памяти собственных процессов достаточно прав текущего пользователя. Для анализа процессов других пользователей или системных служб требуются права **root** (через `sudo`), так как доступ к `/proc/<PID>/smaps` ограничен в целях безопасности.

## Практические сценарии

### Базовый обзор адресного пространства

Используется для быстрой проверки структуры процесса.

```bash
# Показать базовую карту памяти
pmap <PID>

# Пример вывода:
# 000055799988a000    148K r-x-- bash
# 0000557999aa5000      4K r---- bash
# ...
# total            14040K
```

### Анализ приватной памяти и устройств (-d)

Формат `-d` (device) удобен для быстрого поиска объема приватной (writeable/private) памяти, что является лучшим индикатором реального потребления RAM процессом.

```bash
# Показать информацию о сегментах и устройствах
pmap -d <PID>

# В нижней строке:
# mapped: 14040K writeable/private: 512K shared: 0K
```

### Расширенная диагностика с PSS (-x / -X)

Режим `-x` показывает RSS и Dirty страницы. Режим `-X` добавляет PSS и другие детальные метрики из `smaps`.

```bash
# Детальный профиль памяти (наиболее часто используемый)
pmap -x <PID>

# Максимальная детализация (включая PSS)
pmap -X <PID>
```

### Поиск сегментов с наибольшим потреблением (сортировка)

Полезно для идентификации конкретной библиотеки или области кучи, потребляющей ресурсы.

```bash
# Найти топ-20 сегментов по RSS (Resident Set Size) для выявления утечек
pmap -x <PID> | sort -k 3 -n -r | head -n 20

- `-x` — расширенный формат (RSS, Dirty).
- Сортировка по 3-й колонке (RSS) позволяет быстро найти аномально большие анонимные регионы (`[anon]`), что часто является признаком утечки.

### Просмотр флагов ядра (-XX)

Выводит абсолютно все поля, доступные в `smaps`, включая внутренние флаги ядра (`VmFlags`).

```bash
# Полный дамп всей информации о памяти процесса
pmap -XX <PID>
```

## Дополнительная информация

### Сравнение методов анализа

| Метод | Плюсы | Минусы |
| :--- | :--- | :--- |
| **`pmap`** | Удобный форматированный вывод, агрегация по PID | Статический снимок |
| **`cat /proc/PID/smaps`** | Не требует внешних утилит | Трудно читаемый "сырой" текст |
| **[`smem`](./smem.md)** | Сводные отчеты по всей системе, графики | Часто требует отдельной установки |

### Типичные ошибки диагностики

1.  **Ориентация только на Kbytes/VSS:** Ошибка "у процесса 2 ГБ памяти" часто означает лишь зарезервированное виртуальное пространство. Всегда смотрите на **RSS** или **PSS**.
2.  **Игнорирование [anon]:** Анонимная память (`[anon]`) — это чаще всего динамически выделенная память (malloc) или стек. Именно здесь обычно "прячутся" утечки.
3.  **Запуск без sudo:** Без прав суперпользователя `pmap` может показать только базовые адреса без детальной статистики RSS/PSS для чужих процессов.
