# smem — утилита точного анализа памяти

## Определения

`smem` — инструмент командной строки (написанный на Python), предназначенный для детального анализа потребления оперативной памяти в Linux. В отличие от традиционных утилит (`top`, `ps`), `smem` корректно учитывает разделяемую память (Shared Memory), распределяя её между процессами пропорционально, что даёт объективную картину реальной нагрузки на систему.

## Основные концепции

### Ключевые метрики (USS, PSS, RSS)

Для понимания вывода `smem` необходимо различать три типа метрик:

- **USS (Unique Set Size):** Уникальная память процесса. Это объём RAM, который используется исключительно данным процессом. При его завершении этот объём освобождается немедленно. Рост USS — верный признак утечки памяти.
- **PSS (Proportional Set Size):** Пропорциональная память. Считается как `USS + (Shared Memory / Количество пользователей)`. Сумма PSS всех процессов в системе наиболее точно отражает общий объём занятой RAM.
- **RSS (Resident Set Size):** Резидентная память. Общий объём физической памяти, к которой имеет доступ процесс. Суммирование RSS по всем процессам бессмысленно, так как разделяемые библиотеки будут учтены многократно.

### Источники данных и зависимости

- **Системные файлы:** `smem` считывает данные из `/proc/<PID>/smaps` и `/proc/meminfo`.
- **Права доступа:** Для получения точных данных (особенно PSS/USS) для всех процессов требуются права **root** (через `sudo`). Без них утилита покажет только данные процессов текущего пользователя.
- **Python:** Утилита требует наличия интерпретатора Python.
- **Библиотеки:** Для построения графиков (`--pie`, `--bar`) требуется установленная библиотека `matplotlib`.

### Утилита smemcap

В комплекте с `smem` часто идет скрипт `smemcap`. Он предназначен для сбора данных (`/proc/smaps`, `/proc/meminfo` и др.) в один tar-архив. Это полезно для диагностики на нагруженных серверах, где запуск тяжелого Python-скрипта нежелателен: данные собираются быстро, а анализируются позже на другой машине.

## Практические сценарии

### Базовый анализ процессов

Просмотр списка процессов с сортировкой по реальному потреблению (PSS) и итоговой строкой.

```bash
# -t (totals): итоги, -k (abbreviate): человекочитаемые единицы, -s (sort): поле сортировки
sudo smem -tk -s pss -r | head -n 20

# Пример вывода:
#   PID User     Command                         Swap      USS      PSS      RSS
#  1234 mysql    /usr/sbin/mysqld                   0   850.2M   880.5M   960.1M
#  5678 root     /usr/bin/dockerd                   0    80.1M    95.4M   120.2M
```

### Группировка данных

Агрегация данных позволяет быстро понять, какой пользователь или сервис потребляет больше всего ресурсов.

```bash
# Группировка по пользователям
smem -u -k

# Поиск всех процессов конкретного приложения по регулярному выражению
smem -P "^nginx" -tk
```

### Анализ разделяемых библиотек (Mapping mode)

Позволяет увидеть, какие именно файлы или библиотеки потребляют память в системе.

```bash
# Показать потребление памяти в разрезе библиотек/маппингов
smem -m -k | sort -k 4 -n -r | head
```

### Работа с архивами данных (smemcap)

Сбор данных на удаленном сервере и их анализ локально.

```bash
# На сервере: собрать данные
sudo smemcap > server_memory_snapshot.tar

# Локально: проанализировать архив
smem -S server_memory_snapshot.tar -tk
```

### Визуализация распределения памяти

Для работы данных команд в системе должен быть установлен Python-пакет `python3-matplotlib`.

```bash
# Построить круговую диаграмму (pie chart) по именам процессов
smem --pie name -c "pss"

# Построить столбчатую диаграмму (bar chart) для топ-10 процессов
smem --bar name -c "pss" -n 10
```

## Дополнительная информация

### Сравнение с альтернативами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **`smem`** | Самый точный расчет PSS/USS, группировка, графики | Требует Python, медленнее бинарных утилит |
| **`ps_mem`** | Очень легкий (один Python-файл), быстрый | Меньше опций фильтрации и группировки |
| **[`pmap`](./pmap.md)** | Встроен в `procps-ng`, детальная карта сегментов | Сложно агрегировать данные по всей системе |
| **`top` / `htop`** | Интерактивность, реальное время | RSS дает ложное представление о разделяемой памяти |

### Основные аргументы форматирования

- `-p`, `--percent`: Показать значения в процентах от общего объема памяти.
- `-n`, `--numeric`: Использовать числовые UID вместо имен пользователей.
- `-a`, `--autosize`: Автоматическая ширина колонок под текущий терминал.
- `-w`, `--system`: Показать сводку по системной памяти (Kernel, Cache, Free).
