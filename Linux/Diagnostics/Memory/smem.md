# smem — утилита анализа памяти

## Определения

`smem` — это инструмент командной строки для детального анализа потребления оперативной памяти в Linux. В отличие от традиционных утилит (`top`, `ps`), `smem` обеспечивает высокую точность за счет корректного учета разделяемой памяти (Shared Memory), разделяя её между процессами пропорционально.

## Основные концепции

### Ключевые метрики

`smem` оперирует тремя основными показателями, которые позволяют оценить реальную нагрузку процесса на RAM:

- **USS (Unique Set Size):** Уникальная память, используемая только данным процессом. Этот объём будет освобождён немедленно при завершении процесса.
- **PSS (Proportional Set Size):** Пропорциональная доля физической памяти. Включает USS и долю разделяемых библиотек, разделенную на количество их пользователей.
- **RSS (Resident Set Size):** Общая физическая память, занимаемая процессом. Не учитывает разделение ресурсов, поэтому суммирование RSS по всем процессам дает завышенный результат.

> **Важно:** Теоретические основы и детальное сравнение метрик приведены в статье [Метрики потребления памяти процесса](../../Core/memory/process_memory_metrics.md).

### Требования к правам доступа

Для полноценной работы `smem` требуются права суперпользователя (root).

- **Без прав root:** Утилита отображает данные только для процессов текущего пользователя. Данные о процессах других пользователей и системных сервисах будут недоступны или неточны.
- **С правами root:** Доступен анализ всех процессов системы через чтение файлов `/proc/<PID>/smaps`, что гарантирует максимальную точность метрик PSS и USS.

## Практические сценарии

### Анализ процессов

Базовый отчет по процессам с итоговой строкой и сортировкой по PSS.

```bash
# Показать отчет с итогами в человекочитаемом формате
smem -tk -s pss -r

# Пример вывода:
#   PID User     Command                         Swap      USS      PSS      RSS
#  1234 user     /usr/bin/firefox                   0   450.2M   480.5M   560.1M
#  5678 root     /usr/bin/Xorg                      0    80.1M    95.4M   120.2M
# -------------------------------------------------------------------------------
#    22 users    125 commands                       0     1.2G     1.5G     2.1G
```

### Группировка данных

Агрегация потребления памяти по пользователям или именам процессов.

```bash
# Потребление памяти в разрезе пользователей
smem -u -k

# Потребление памяти конкретным сервисом (например, nginx)
smem -P nginx -k
```

### Системный обзор

Просмотр общей картины распределения памяти, включая кэш ядра и нераспределенную память.

```bash
# Системная статистика
sudo smem -w -k

# Пример вывода:
# Area                           Used      Cache   Noncache
# kernel/reserve                120.5M         0     120.5M
# cache                         850.2M    850.2M          0
# free                            2.1G         0       2.1G
```

### Визуализация (диаграммы)

`smem` может генерировать простые графические отчеты (требуется библиотека `matplotlib`).

```bash
# Круговая диаграмма распределения PSS между процессами
smem --pie name -c "pss"

# Столбчатая диаграмма для топ-процессов
smem --bar name -c "pss" -n 10
```

## Дополнительная информация

### Справочник аргументов форматирования

| Флаг | Описание |
|:-----|:---------|
| `-k`, `--abbreviate` | Отображать суффиксы единиц измерения (K, M, G) |
| `-t`, `--totals` | Выводить строку с итоговыми суммами |
| `-p`, `--percent` | Показывать значения в процентах от общей памяти |
| `-r`, `--reverse` | Обратный порядок сортировки |
| `-s SORT` | Поле для сортировки (`uss`, `pss`, `rss`, `swap`) |
| `-c COLUMNS` | Выбор конкретных колонок для отображения |

### Специальные параметры

| Флаг | Описание |
|:-----|:---------|
| `-a`, `--autosize` | Автоматическая подстройка ширины колонок под терминал |
| `-n`, `--numeric` | Использовать числовые UID вместо имен пользователей |
| `-S SOURCE` | Чтение данных из архива (созданного `smemcap`), а не из `/proc` |
