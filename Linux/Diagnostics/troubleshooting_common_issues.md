# Поиск и устранение неисправностей в Linux

Этот документ описывает методы диагностики и решения распространенных проблем в операционной системе Linux.

---

### 1. Процесс заполняет диск логами

*   **Симптомы:** Свободное место на диске быстро уменьшается. Команда `df -h` показывает 100% использование диска.
*   **Диагностика:**
    1.  Определить, какой файл или директория быстро растет. Начните с определения корневой директории, которая занимает больше всего места (см. пункт 2). Чаще всего, это файлы в `/var/log/` или временные файлы в `/tmp/`.
    2.  Использовать утилиту `lsof` (List Open Files), чтобы найти процесс, который удерживает открытым или активно пишет в этот файл/директорию. Это особенно полезно, если файл был удален, но место не освободилось, так как процесс все еще держит его открытым.
        ```bash
        # Найти процесс, пишущий в конкретный файл
        lsof /path/to/large/file.log

        # Найти процессы, удерживающие открытые файлы в директории
        lsof +D /path/to/directory
        ```
    3.  Команда `lsof` покажет имя процесса, его PID и дескриптор файла.
*   **Решение:**
    1.  После определения PID процесса, его можно завершить (осторожно, это может повлиять на работу системы):
        ```bash
        kill <PID>
        ```
    2.  Чтобы найти расположение исполняемого файла процесса или его командную строку:
        ```bash
        ls -l /proc/<PID>/exe
        cat /proc/<PID>/cmdline # Показать командную строку
        ```
    3.  После остановки процесса можно безопасно удалить большой лог-файл, чтобы освободить место. Если файл был удален до остановки процесса, но место не освободилось, остановка процесса приведет к освобождению места.

### 2. Поиск и удаление больших файлов

*   **Симптомы:** Недостаточно места на диске.
*   **Диагностика:**
    1.  Использовать утилиту `du` (disk usage) для поиска больших файлов и директорий.
    2.  Начать с корневого каталога и искать самые большие директории:
        ```bash
        # Показывает размер директорий первого уровня в / и сортирует по убыванию
        du -sh /* | sort -rh
        ```
    3.  Повторять команду для "подозрительных" директорий, чтобы найти источник проблемы.
*   **Причина:** В данном примере большой файл, имитирующий лог `journald`, был найден в `/var/log/`.
*   **Решение:**
    1.  Удалить ненужный большой файл:
        ```bash
        rm /path/to/large/file
        ```
    2.  **Важно:** Если проблема с настоящим логом `journald`, его нельзя просто удалять. Используйте `journalctl` для очистки:
        ```bash
        # Ограничить размер журнала до 100 МБ
        journalctl --vacuum-size=100M
        
        # Ограничить хранение логов последними 3 днями
        journalctl --vacuum-time=3d
        ```
