# Диагностика системы: sos report и sosdiff

## Определение

**`sos report`** — универсальный инструмент диагностики для Linux, написанный на языке Python. Он предназначен для сбора исчерпывающих диагностических данных из системы (конфигурации, журналы, вывод команд) без внесения изменений в её конфигурацию. Является стандартом де-факто для служб поддержки (Red Hat, Oracle, Ubuntu) при анализе и устранении неполадок.

**`sosdiff`** — специализированная утилита (входит в пакет `oled` для Oracle Linux или доступна в экосистеме `sos`) для сравнения двух отчётов. Она позволяет выявлять различия между "рабочей" и "проблемной" системами, сравнивать конфигурации или отслеживать изменения на одном сервере во времени.

## Базовые концепции

### Назначение и возможности

С выходом версии 4.x инструмент перешёл на модульную архитектуру и Python 3. Он автоматизирует сбор информации из сотен источников:
- **Конфигурации**: файлы из `/etc` и специфичные настройки приложений.
- **Журналы**: логи из `/var/log`, данные `journald` и `auditd`.
- **Вывод команд**: системные утилиты (`ip`, `ps`, `df`, `lsmod`, `lspci` и др.).
- **Производительность**: данные `sar` (из пакета `sysstat`), статистика PSI (Pressure Stall Information).
- **Ядро**: параметры `sysctl`, структуры из `/proc` и `/sys`, информация о загруженных модулях.
- **Оборудование**: данные `dmidecode`, состояние дисковых подсистем и сетевых контроллеров.

### Структура диагностического архива

После распаковки архива (`tar -xf <file>.tar.xz`) создаётся иерархия каталогов, имитирующая корень файловой системы.

**Ключевые символические ссылки в корне архива (для быстрого доступа):**
- `cmdline` — параметры загрузки ядра.
- `dmidecode` — подробная информация о BIOS, CPU и оперативной памяти.
- `installed-rpms` / `dpkg-query` — полные списки установленного ПО.
- `lspci` — устройства на шине PCI.
- `uname` — версия ядра и архитектура.
- `uptime` — время работы и показатели Load Average.

**Основные каталоги:**
- `etc/` — точные копии конфигурационных файлов системы.
- `sos_commands/` — текстовые файлы с выводом выполненных диагностических команд, сгруппированные по плагинам (например, `sos_commands/networking/ip_addr`).
- `sos_reports/` — отчёты в форматах HTML (для просмотра в браузере), TXT и JSON.
- `var/log/` — системные и прикладные журналы.

### Возможности sosdiff

Утилита выполняет интеллектуальное сравнение двух архивов, группируя различия по категориям:
- **Пакеты**: различия в версиях и составе установленного ПО.
- **Ядро**: несовпадения в загруженных модулях и параметрах `sysctl`.
- **Сеть**: сравнение конфигурации интерфейсов, таблиц маршрутизации и правил файрвола.
- **Монтирование**: различия в точках монтирования и опциях файловых систем.

## Практические сценарии

### Установка инструментов

**RHEL / Oracle Linux / CentOS / Fedora:**
```bash
# Oracle Linux 8/9, RHEL 8/9
sudo dnf install sos

# Oracle Linux 6/7, CentOS 7
sudo yum install sos
```

**Ubuntu / Debian:**
```bash
sudo apt update && sudo apt install sosreport
```

### Сбор диагностических данных (sos report)

**Стандартный сбор (рекомендуемый):**
```bash
sudo sos report --batch --all-logs -k sar.all-sar=on
# → архив сохраняется в /var/tmp/sosreport-hostname-YYYY-MM-DD-xxxxxx.tar.xz
```

**Ключевые параметры и особенности:**
- `--batch` — неинтерактивный режим (автоответ на вопросы об имени хоста или номере тикета).
- `--all-logs` — сбор всех журналов без усечения (важно для глубокого анализа, если место позволяет).
- `-k sar.all-sar=on` — сбор истории `sar` за весь доступный период (по умолчанию собирается только за последние 24 часа).
- `--build` — создание отчёта в виде дерева директорий без архивации (полезно при критической нехватке места в `/var/tmp`).
- `--encrypt` — шифрование архива с помощью GPG для безопасной передачи вендору.

**Версионные нюансы:**
- **Oracle Linux 9**: может потребоваться явное включение плагина `sar` через `-e sar`, если он не активен по умолчанию.
- **Устаревшие системы (OL 6/7)**: используется старая команда `sosreport` (без пробела).

### Управление плагинами

Просмотр списка доступных плагинов и их текущего статуса:
```bash
sudo sos report -l
```

Запуск конкретных плагинов или передача им опций:
```bash
# Сбор данных только по сети и дискам
sudo sos report -n network,block

# Исключение тяжелых плагинов
sudo sos report -e devicemapper
```

### Работа в облачных средах (Cloud Integration)

В версиях 4.x плагины для AWS, Azure и GCP активируются автоматически и собирают данные из сервисов метаданных (IMDS).

| Облако | Плагин | Собираемые данные |
| :--- | :--- | :--- |
| **AWS** | `aws` | Тип инстанса, VPC ID, IAM-роли, логи `aws-cli`. |
| **Azure** | `azure` | Данные IMDS, конфигурация RHUI, расширения агента. |
| **GCP** | `gcp` | Проект, зона, конфигурация Google Guest Agent. |

**Таймауты**: если доступ к IMDS заблокирован, сбор может зависнуть. Используйте `-k <plugin>.timeout=30`.

### Анонимизация и очистка данных (sos clean)

Удаление чувствительной информации (IP-адреса, пароли, ключи, MAC-адреса) с сохранением консистентности (одинаковые IP заменяются на одинаковые хеши).

**Сбор с одновременной очисткой (sos 4.x+):**
```bash
sudo sos report --clean --batch
```

**Очистка существующего архива:**
```bash
sudo sos clean /var/tmp/sosreport-file.tar.xz --keywords MyProjectName
# → будет создан файл с суффиксом -obfuscated.tar.xz
```

### Сбор в кластере (sos collect)

Позволяет запустить сбор данных на группе хостов (Kubernetes, Pacemaker) одновременно через SSH.
```bash
sudo sos collect --nodes=node1,node2,node3 --batch
```

### Сравнение отчётов через sosdiff

```bash
oled sosdiff report_before/ report_after/
```

**Полезные флаги:**
- `-d, --detail` — детальный вывод (diff) изменений внутри конфигурационных файлов.
- `-o, --override` — игнорирование различий в версиях ОС (полезно при миграции).
- `-c, --color` — включение цветовой подсветки в выводе.

### Конфигурация по умолчанию

Глобальные настройки задаются в файле `/etc/sos/sos.conf`:
```ini
[global]
batch = yes

[report]
all-logs = yes
enable-plugins = sar, network

[plugin_options]
sar.all-sar=on
```

## Устранение неполадок (Troubleshooting)

### Ошибки при выполнении
1.  **Зависания**: запустите с флагом `-vvv` (вербозность), чтобы увидеть, на какой команде или файле происходит задержка.
2.  **Нехватка места**: укажите альтернативную директорию через `--tmp-dir <path>`.
3.  **Ошибки памяти (OOM)**: при очистке огромных логов через `sos clean`. В этом случае рекомендуется использовать `--build` и очищать логи по отдельности.

## Дополнительная информация

### Быстрый анализ содержимого архива
Примеры поиска информации в распакованном отчёте:
```bash
# Проверка параметров загрузки ядра
cat proc/cmdline

# Поиск ошибок в логах с привязкой к дате
grep -i "error" var/log/messages | grep "Aug 09"

# Проверка состояния конкретного интерфейса
cat sos_commands/networking/ip_addr | grep -A 5 "eth0"
```

### Рекомендации по эксплуатации
1.  **Скорость реакции**: собирайте отчёт немедленно при обнаружении аномалий, пока журналы не были перезаписаны (`logrotate`).
2.  **Эталонный слепок**: сохраняйте `sos report` сразу после успешного развёртывания системы для последующего сравнения в случае сбоев.
3.  **Безопасность**: всегда используйте `sos clean` перед отправкой отчётов внешним вендорам или в публичные трекеры.
