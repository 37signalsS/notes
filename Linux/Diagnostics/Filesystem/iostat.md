# iostat

## Определения

- **`iostat` (input/output statistics — статистика ввода-вывода):** Утилита из пакета `sysstat` для мониторинга статистики ввода-вывода блочных устройств и использования CPU. Собирает данные напрямую из интерфейса ядра `/proc/diskstats`.
- **IOPS (количество операций ввода-вывода в секунду):** Метрики `r/s` (чтение) и `w/s` (запись). Ключевой показатель для транзакционных нагрузок, таких как базы данных (БД).
- **Пропускная способность (`rMB/s`, `wMB/s` или `rkB/s`, `wkB/s`):** Скорость передачи данных в МБ/с или КБ/с. Важна для последовательных операций (бэкапы, потоковое видео).
- **`await` (Average Wait):** Среднее время (в мс) от момента создания запроса до завершения его обслуживания. Включает время в очереди планировщика и время фактической обработки устройством.
- **`aqu-sz` (Average Queue Size):** Средняя длина очереди запросов к устройству. В современных версиях заменяет или уточняет `avgqu-sz`.
- **`f_await` (Flush Await):** Среднее время выполнения операций сброса кэша (flush). Критично для анализа производительности записи в БД.
- **`%util` (Utilization):** Процент времени, в течение которого устройство было занято обработкой запросов.
- **`svctm` (Service Time):** Среднее время обслуживания запроса. **Устаревший показатель**, не рекомендуется к использованию в ядрах версии 2.6.38 и выше, так как он не учитывает параллелизм современных устройств.

## Основные концепции

`iostat` позволяет получить объективную картину производительности дисковой подсистемы и ответить на вопрос: «Справляется ли оборудование с текущей нагрузкой?». В отличие от `iotop`, который идентифицирует виновников нагрузки, `iostat` анализирует состояние самих устройств.

### Ключевые метрики для диагностики

| Метрика | Норма для HDD | Норма для SSD/NVMe | Признак проблемы |
| :--- | :--- | :--- | :--- |
| `await` | < 20 мс | < 1 мс | Значительные задержки или переполнение очереди |
| `aqu-sz` | < 2 | < 1 (на один поток) | Постоянно растущая очередь запросов |
| `%util` | < 80% | < 90% | Устройство близко к пределу возможностей |
| `r_await`/`w_await` | — | — | Разделение задержек на чтение и запись |

**Важное примечание:** Высокое значение `%util` не всегда означает проблему. Для современных SSD и RAID-массивов полная утилизация может достигаться при сохранении низкой латентности за счет параллельной обработки запросов. Критическим признаком перегрузки является высокий `await` при высокой утилизации.

### Интерпретация полей расширенной статистики (`-x`)

**Статистика центрального процессора (CPU):**

- `%user`: Время выполнения в пользовательском режиме (приложения).
- `%system`: Время выполнения в режиме ядра (системные вызовы, драйверы).
- `%iowait`: Время, в течение которого CPU простаивал в ожидании завершения операций ввода-вывода. Высокий показатель при низкой загрузке CPU — признак дискового узкого места.
- `%idle`: Время простоя без выполнения каких-либо задач.

**Статистика дисковых устройств (Device):**

- `rrqm/s`, `wrqm/s`: Количество запросов на чтение/запись, объединенных планировщиком ввода-вывода (merge).
- `r/s`, `w/s`: Количество завершенных операций чтения и записи в секунду (IOPS).
- `rkB/s`, `wkB/s` (`rMB/s`, `wMB/s`): Пропускная способность в КБ/с или МБ/с.
- `rareq-sz`, `wareq-sz`: Средний размер запроса на чтение и запись (в КБ). Помогает понять характер нагрузки (Small Random vs Large Sequential).
- `avgrq-sz`: Средний размер запроса в секторах.
- `avgqu-sz` / `aqu-sz`: Средняя длина очереди запросов.
- `await`: Среднее время ожидания (мс), включая время в очереди.
- `r_await`, `w_await`: Латентность отдельно для чтения и записи.
- `f_await`: Латентность операций сброса кэша (flush).
- `%util`: Процент времени утилизации устройства (bandwidth utilization).

## Практические сценарии

### Мониторинг в реальном времени

```bash
# Исключение "первого отчета" и обновление каждые 2 секунды
iostat -dx -y 2

# Статистика в МБ/с с указанием временных меток
iostat -dxmt 2

# Мониторинг только активных устройств (скрыть простаивающие)
iostat -dxz 1

# Отображение имен LVM вместо dm-X
iostat -dxN 1

# Мониторинг конкретного устройства (например, nvme1n1)
iostat -dx 1 5 /dev/nvme1n1

# Быстрая оценка: человекочитаемый формат, 3 замера с интервалом 1 с
iostat -xh 1 3
```

### Диагностика узких мест ввода-вывода (I/O Bottleneck)

1. **Оценка задержек:** Если `await` стабильно выше 20 мс для HDD или 1 мс для SSD — дисковая подсистема перегружена.
2. **Проверка очереди:** Значение `aqu-sz` (или `avgqu-sz`) больше 1–2 указывает на то, что запросы скапливаются в очереди.
3. **Облачный Throttling:** В облачных средах (AWS EBS, GCP PD) `iowait` может быть низким, но `await` высоким из-за ограничений провайдера. Подробности в разделе **[Низкий iowait при высокой задержке диска](../Performance/DiskIO/iowait_and_latency.md)**.
4. **Поиск виновника:** Если `iostat` подтверждает проблему на уровне устройства, используйте `iotop -o` или `pidstat -d 1` для поиска конкретных процессов.

### Сбор данных для анализа

```bash
# Сохранение данных в формате JSON для автоматизированной обработки (ELK, Python)
iostat -dx -o JSON 2 300 > iostat_log.json

# Запись расширенной статистики в текстовый файл
iostat -dx 2 60 > iostat_log.txt
```

## Дополнительная информация

### Типичные ошибки интерпретации

- **Проблема первого отчета:** По умолчанию первый вывод `iostat` содержит средние значения **с момента загрузки системы**. Эти данные бесполезны для анализа текущей нагрузки. Всегда используйте флаг `-y` (чтобы пропустить первый отчет) или запускайте утилиту с интервалом (например, `2 10`) и игнорируйте первую итерацию.
- **Интерпретация %util:** На SSD и RAID-массивах 100% утилизация не означает, что диск "захлебнулся", так как они могут обрабатывать множество запросов параллельно. Главный критерий здесь — `await`.

### Взаимосвязь с iowait и Load Average

Процессы, находящиеся в состоянии `uninterruptible sleep` (ожидание ввода-вывода, статус `D` в `ps` или `top`), напрямую влияют на показатель `Load Average`. Высокие значения `await` и `%util` в `iostat` обычно коррелируют с ростом `iowait` и `Load Average`.

**Команды для проверки:**

```bash
# Просмотр процессов в состоянии D
ps -eo pid,stat,wchan:20,comm | awk '$2 ~ /D/ {print}'

# Определение kernel-функции, блокирующей процесс
cat /proc/<PID>/wchan
# → Примеры: wait_on_page_bit (ожидание чтения с диска), jbd2_log_wait_commit (ожидание коммита в журнал ext4)

# Мониторинг системных вызовов и очередей через vmstat
vmstat 1 5
```
