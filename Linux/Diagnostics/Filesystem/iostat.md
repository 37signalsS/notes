# iostat

## Определения

- **`iostat` (input/output statistics — статистика ввода-вывода):** Утилита из пакета `sysstat` для мониторинга статистики ввода-вывода блочных устройств. Фокусируется на производительности физических и логических дисков, а не на отдельных процессах.
- **IOPS (количество операций ввода-вывода в секунду):** Метрики `r/s` (чтение) и `w/s` (запись). Ключевой показатель для транзакционных нагрузок, таких как базы данных (БД).
- **Пропускная способность (`rMB/s`, `wMB/s`):** Скорость передачи данных в МБ/с (Мегабайт в секунду). Важна для последовательных операций, таких как работа файловых серверов или создание резервных копий (бэкапов).
- **`await`:** Среднее время ожидания запроса ввода-вывода (I/O), включая время в очереди и время фактической обработки устройством, измеряется в миллисекундах (мс).
- **`%util`:** Процент времени, в течение которого устройство было занято обработкой запросов.
- **`svctm`:** Среднее время обслуживания запроса. **Устаревший показатель**, не рекомендуется к использованию в ядрах версии 2.6.38 и выше.

## Основные концепции

`iostat` позволяет получить объективную картину производительности дисковой подсистемы и ответить на вопрос: «Справляется ли оборудование с текущей нагрузкой?». В отличие от `iotop`, который идентифицирует виновников нагрузки, `iostat` анализирует состояние самих устройств.

### Ключевые метрики для диагностики

| Метрика | Норма для HDD | Норма для SSD | Признак проблемы |
| :--- | :--- | :--- | :--- |
| `await` | < 20 мс | < 1 мс | Значительные задержки или переполнение очереди |
| `%util` | < 80% | < 90% | Устройство близко к пределу возможностей |
| `r_await`/`w_await` | — | — | Разделение задержек на чтение и запись |
| `avgqu-sz` | < 2 | < 1-2 | Постоянно растущая очередь запросов |

**Важное примечание:** Высокое значение `%util` не всегда означает проблему. Для современных SSD и RAID-массивов полная утилизация может достигаться при сохранении низкой латентности. Критическим признаком перегрузки является высокий `await` при высокой утилизации.

### Интерпретация полей расширенной статистики (`-x`)

**Статистика центрального процессора (CPU):**

- `%user`: Время выполнения в пользовательском режиме.
- `%system`: Время выполнения в режиме ядра.
- `%iowait`: Время, в течение которого CPU простаивал в ожидании завершения операций ввода-вывода.
- `%idle`: Время простоя без выполнения задач.

**Статистика дисковых устройств (Device):**

- `rrqm/s`, `wrqm/s`: Количество запросов на чтение/запись, объединенных планировщиком ввода-вывода (merge).
- `r/s`, `w/s`: Количество операций чтения и записи в секунду (IOPS).
- `rkB/s`, `wkB/s`: Пропускная способность в КБ/с (Килобайт в секунду).
- `avgrq-sz`: Средний размер запроса в секторах.
- `avgqu-sz`: Средняя длина очереди запросов.
- `await`: Среднее время ожидания (мс), включая очередь.
- `%util`: Процент времени утилизации устройства.

## Практические сценарии

### Мониторинг в реальном времени

```bash
# Расширенная статистика по всем дискам с обновлением каждые 2 секунды
iostat -dx 2

# Статистика в МБ/с с указанием временных меток
iostat -dxmt 2

# Мониторинг конкретного устройства (например, nvme1n1)
iostat -dx 1 5 /dev/nvme1n1

# Быстрая оценка: человекочитаемый формат, 3 замера с интервалом 1 с
iostat -xh 1 3
```

### Диагностика узких мест ввода-вывода (I/O Bottleneck)

1. **Оценка задержек:** Если `await` стабильно выше 20 мс для HDD или 1 мс для SSD — дисковая подсистема перегружена.
2. **Проверка очереди:** Значение `avgqu-sz` больше 1–2 указывает на то, что запросы скапливаются в очереди.
3. **Поиск виновника:** Если `iostat` подтверждает проблему на уровне устройства, используйте `iotop -o` для поиска конкретных процессов.

### Низкий iowait при высокой задержке

Ситуация, когда `%iowait` остается низким, но дисковые операции выполняются медленно, часто встречается на многоядерных системах. Подробный разбор этого явления приведен в разделе **[Низкий iowait при высокой задержке диска](../Performance/DiskIO/iowait_and_latency.md)**.

### Сбор данных для анализа

```bash
# Сохранение данных в формате JSON для автоматизированной обработки
iostat -dx -o JSON 2 300 > iostat_log.json

# Запись расширенной статистики в текстовый файл
iostat -dx 2 60 > iostat_log.txt
```

## Дополнительная информация

### Взаимосвязь с iowait и Load Average

Процессы, находящиеся в состоянии `uninterruptible sleep` (ожидание ввода-вывода, статус `D` в `ps` или `top`), напрямую влияют на показатель `Load Average`. Высокие значения `await` и `%util` в `iostat` обычно коррелируют с ростом `iowait` и `Load Average`.

**Команды для проверки:**

```bash
# Просмотр процессов в состоянии D
ps aux | awk '$8 ~ /D/ {print}'

# Альтернативный поиск D-state процессов (точное поле STAT)
ps -eo pid,stat,comm | awk '$2~/D/'

# Определение kernel-функции, блокирующей процесс
cat /proc/<PID>/wchan
```

**High iowait + Low CPU util:** Если `%iowait` высок, а `%CPU` низок — ищите D-state процессы. Команда `cat /proc/<PID>/wchan` показывает, какая функция ядра блокирует процесс (например, `wait_on_page_bit`, `md_open`). Это ключ к пониманию причины ожидания.

```bash
# Мониторинг системных вызовов и очередей через vmstat
vmstat 1 5
```
