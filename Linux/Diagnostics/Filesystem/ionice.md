# `ionice`

## Определения

- **`ionice`:** Утилита для управления приоритетом дисковых операций ввода-вывода (I/O) для процессов.
- **Классы планирования I/O:**
  - **Idle (Класс 3):** Самый низкий приоритет. Доступ к диску только когда он полностью свободен.
  - **Best-effort (Класс 2):** Приоритет по умолчанию. 8 уровней приоритета (0–7, где 0 — высший).
  - **Realtime (Класс 1):** Наивысший приоритет. Немедленный доступ к диску. **Требует root.**

## Основные концепции

`ionice` предотвращает ситуации, когда фоновые задачи (бэкапы, индексация, сбор логов) замедляют критичные приложения (БД, веб-серверы).

**Важно:** `ionice` работает только с планировщиками I/O, поддерживающими приоритеты (например, `bfq`, `cfq`). Для `none`/`noop` и некоторых SSD-планировщиков эффект может отсутствовать.

**Проверка текущего планировщика:**

```bash
cat /sys/block/sda/queue/scheduler
# Вывод: [none] mq-deadline kyber bfq
# Если активен 'none' или 'kyber' — ionice может не работать
```

## Практические сценарии

### Запуск процесса с низким приоритетом

```bash
# rsync с минимальным приоритетом (Idle)
ionice -c3 rsync -a /source /destination

# Бэкап с низким приоритетом Best-effort
ionice -c2 -n7 tar -czf backup.tar.gz /data
```

### Изменение приоритета запущенного процесса

```bash
# Установить высокий приоритет для процесса с PID
sudo ionice -c2 -n0 -p <PID>

# Realtime приоритет для MySQL (с осторожностью!)
sudo ionice -c1 -p $(pgrep mysqld)

# Снизить приоритет для фоновой задачи
sudo ionice -c2 -n7 -p <PID>
```

### Проверка текущего приоритета

```bash
# Проверить приоритет I/O для процесса
ionice -p 1234

# Вывод: idle: prio=0 / best-effort: prio=4 / realtime: prio=0
```

### Комбинация с `nice` (CPU + I/O приоритет)

```bash
# Запуск с низким приоритетом CPU и I/O
nice -n19 ionice -c3 rsync -a /source /destination

# Для уже запущенного процесса
renice -n10 -p <PID>
ionice -c2 -n6 -p <PID>
```

## Дополнительная информация

### Таблица сценариев использования

| Сценарий | Класс | Приоритет | Обоснование |
| :--- | :--- | :--- | :--- |
| Бэкапы, синхронизация | Idle (3) | — | Не влиять на основную нагрузку |
| Фоновая обработка логов | Best-effort (2) | 6–7 | Низкий приоритет |
| Обычные приложения | Best-effort (2) | 4 | По умолчанию |
| Базы данных (продакшн) | Best-effort (2) | 0–2 | Высокий приоритет |
| Критичные БД (RT-требования) | Realtime (1) | 0 | Только при необходимости |

### Ограничения

- **Realtime класс:** Требует `CAP_SYS_NICE` (root). Неправильное использование может привести к голоданию других процессов.
- **Планировщики:** Не все планировщики поддерживают приоритеты (см. выше).
- **Контейнеры:** В Docker требуется `--cap-add=SYS_NICE` или `--privileged`.
- **SSD/NVMe:** На быстрых накопителях эффект может быть менее заметен.

### Cgroups для гранулярного контроля

`ionice` — простой инструмент для отдельных процессов. Для комплексного управления I/O используйте **cgroups**:

```bash
# Ограничить IOPS для группы процессов (cgroups v2)
echo "1000" > /sys/fs/cgroup/io.max
echo "<PID>" >> /sys/fs/cgroup/cgroup.procs
```

**См.:** [Cgroups](../../Core/cgroups.md), [Планировщики I/O](../../Core/kernel/io_schedulers.md)

### Диагностика

```bash
# 1. Проверить текущий приоритет процесса
ionice -p <PID>

# 2. Оценить эффект через iotop
sudo iotop -o -p <PID>

# 3. Проверить общую нагрузку через iostat
iostat -x 2
```
