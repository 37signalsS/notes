# `ionice`

## Определения

- **`ionice`:** Утилита для управления приоритетом операций ввода-вывода (I/O — Input/Output) для процессов в операционной системе Linux.
- **Классы планирования I/O:**
  - **Idle (Класс 3):** Самый низкий приоритет. Процесс получает доступ к диску только тогда, когда ни один другой процесс не запрашивает операции ввода-вывода в течение определенного окна времени.
  - **Best-effort (Класс 2):** Приоритет по умолчанию для большинства процессов. Включает 8 уровней (0–7, где 0 — наивысший).
  - **Realtime (Класс 1):** Наивысший приоритет. Процесс получает немедленный доступ к диску, игнорируя другие запросы. Требует прав суперпользователя (root).

## Основные концепции

Утилита `ionice` позволяет предотвратить ситуации, когда ресурсоемкие фоновые задачи (например, создание резервных копий, индексация файлов или сбор логов) замедляют работу критически важных приложений, таких как базы данных или веб-серверы.

**Важные примечания:**

1. **Поддержка планировщиками:** `ionice` эффективно работает только с планировщиками ввода-вывода, поддерживающими систему приоритетов (например, `bfq` или `cfq`). При использовании планировщиков `none`, `noop` или `mq-deadline` эффект может быть минимальным или отсутствовать.
2. **Тип накопителя:** На современных твердотельных накопителях (SSD — Solid State Drive) и устройствах NVMe (Non-Volatile Memory Express) разница между приоритетами часто менее заметна из-за высокой параллельности операций.

**Проверка активного планировщика:**

```bash
cat /sys/block/sda/queue/scheduler
# → [none] mq-deadline kyber bfq
# Если в квадратных скобках указан 'none' — ionice может не работать
```

## Практические сценарии

### Запуск процесса с низким приоритетом

Используется для задач, которые не должны мешать основной работе системы.

```bash
# Запуск rsync с минимальным приоритетом (Idle)
ionice -c3 rsync -a /source /destination

# Запуск архивации с низким уровнем класса Best-effort
ionice -c2 -n7 tar -czf backup.tar.gz /data
```

### Изменение приоритета работающего процесса

Требуется идентификатор процесса (PID — Process Identifier).

```bash
# Установить наивысший уровень Best-effort для процесса
sudo ionice -c2 -n0 -p <PID>

# Перевести процесс в класс Realtime (использовать с осторожностью)
sudo ionice -c1 -p $(pgrep mysqld)
```

### Просмотр текущего приоритета

```bash
# Проверить настройки приоритета для конкретного PID
ionice -p 1234
# → best-effort: prio 4
```

### Совместное использование с `nice`

Комплексное ограничение нагрузки на центральный процессор (CPU — Central Processing Unit) и дисковую подсистему.

```bash
# Запуск с минимальным приоритетом на CPU и диск
nice -n19 ionice -c3 rsync -a /source /destination
```

## Дополнительная информация

### Рекомендации по выбору классов

| Сценарий использования | Класс | Приоритет | Обоснование |
| :--- | :--- | :--- | :--- |
| Резервное копирование | Idle (3) | — | Полное исключение влияния на систему |
| Ротация логов | Best-effort (2) | 7 | Минимальный приоритет в общем классе |
| Пользовательское ПО | Best-effort (2) | 4 | Стандартное значение |
| Базы данных | Best-effort (2) | 0–2 | Повышенный приоритет для снижения задержек |
| Критичные системы реального времени | Realtime (1) | 0 | Прямой доступ к оборудованию (риск зависаний) |

### Ограничения и альтернативы

1. **Права доступа:** Использование класса Realtime требует привилегии `CAP_SYS_NICE`. Ошибка в настройке этого класса может привести к "голоданию" (starvation) остальных процессов и нестабильности системы.
2. **Cgroups:** `ionice` управляет приоритетами на уровне отдельных процессов. Для более точного контроля и лимитирования ресурсов (например, ограничения IOPS или пропускной способности) в современных системах рекомендуется использовать **Control Groups (cgroups)**.
3. **Контейнеризация:** В Docker для работы `ionice` может потребоваться флаг `--cap-add=SYS_NICE` или привилегированный режим.
