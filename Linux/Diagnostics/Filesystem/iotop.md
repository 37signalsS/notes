# `iotop`

## Определения

- **`iotop`:** Интерактивная утилита для мониторинга активности ввода-вывода (I/O — Input/Output) в реальном времени с детализацией по процессам.
- **`IO>`:** Процент времени, которое процесс провел в ожидании завершения операций ввода-вывода (состояние `uninterruptible sleep`).
- **`DISK READ/WRITE`:** Фактическая скорость чтения или записи для каждого процесса (КБ/с или МБ/с).
- **`SWAPIN`:** Процент времени, потраченного на ожидание страниц из области подкачки (Swap). Актуально при нехватке оперативной памяти (RAM — Random Access Memory).
- **`PID (Process Identifier)`:** Уникальный номер, идентифицирующий процесс в операционной системе.

> **Примечание:** В современных дистрибутивах часто используется `iotop-c` (реализация на языке C) вместо оригинальной версии на Python. Они полностью совместимы по функциональности и интерфейсу.

## Основные концепции

Утилита `iotop` позволяет определить, какой конкретно процесс создает нагрузку на дисковую подсистему в данный момент.

Это незаменимый инструмент в случаях, когда:

- Утилита `top` показывает высокий показатель `%wa` (iowait).
- `iostat` подтверждает наличие узкого места (bottleneck) в системе ввода-вывода.

**Ключевые индикаторы производительности:**

- **`IO>` близок к 100%:** Процесс заблокирован операциями ввода-вывода. Это главный кандидат на анализ и оптимизацию.
- **Высокий `DISK WRITE`:** Свидетельствует об интенсивной записи данных (например, работа баз данных, создание резервных копий или активное логирование).
- **Высокий `SWAPIN`:** Указывает на активное использование области подкачки из-за нехватки физической оперативной памяти.

## Практические сценарии

### Интерактивный мониторинг

```bash
# Базовый запуск (требуются права root)
sudo iotop

# Отображение только активных процессов (рекомендуемый режим)
sudo iotop -o

# Отображение текущей скорости без накопления данных
sudo iotop -a

# Группировка по процессам, а не по отдельным потокам
sudo iotop -P

# Мониторинг активности конкретного пользователя
sudo iotop -u www-data

# Мониторинг конкретных процессов по их PID
sudo iotop -p 1234,5678
```

### Неинтерактивный режим (скрипты и логирование)

```bash
# Вывод 3 отчетов с интервалом в 5 секунд в файл
sudo iotop -b -n 3 -d 5 > /var/log/iotop_report.log

# Фоновый мониторинг с постоянной записью в лог-файл
sudo iotop -b -d 10 >> /var/log/iotop.log &
```

### Интерактивное управление

В режиме реального времени можно использовать горячие клавиши для управления выводом:

| Клавиша | Действие |
| :--- | :--- |
| **← / →** | Смена колонки для сортировки |
| **`r`** | Изменение порядка сортировки (прямой/обратный) |
| **`o`** | Включение режима "только активные процессы" |
| **`a`** | Переключение между текущей скоростью и накопленным объемом |
| **`q`** | Выход из программы |

## Дополнительная информация

### Системные требования

- **Права доступа:** Необходимы права `root` или наличие привилегии `CAP_SYS_ADMIN`.
- **Ядро:** Требуется поддержка механизмов `taskstats` (параметры `CONFIG_TASKSTATS` и `CONFIG_TASK_IO_ACCOUNTING`).
- **Файловая система:** Файловая система `/proc` должна быть смонтирована без ограничений доступа к статистике процессов (опции `hidepid=0` или `hidepid=1`).

### Ограничения

- **Контейнеризация:** При запуске внутри Docker или Kubernetes может потребоваться флаг `--privileged` или специфические настройки безопасности.
- **Сетевые файловые системы:** Статистика ввода-вывода для NFS (Network File System) или CIFS (Common Internet File System) может отображаться не полностью.
- **Современные накопители (SSD/NVMe):** Из-за очень высокой скорости работы таких дисков показатели `IO>` могут оставаться низкими даже при значительных объемах передаваемых данных.

### Альтернативные инструменты

- `pidstat -d 1` — детальная статистика ввода-вывода по процессам с историей.
- [iostat](./iostat.md) — общая статистика производительности дисковых устройств.
- `blktrace` — низкоуровневая трассировка операций блочных устройств.
