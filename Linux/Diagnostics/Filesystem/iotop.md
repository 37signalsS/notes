# `iotop`

## Определения

- **`iotop`:** Интерактивная утилита для мониторинга дисковой активности (I/O) в реальном времени с разбивкой по процессам.
- **`IO>`:** Процент времени, которое процесс провел в ожидании завершения операций ввода-вывода (состояние `uninterruptible sleep`).
- **`DISK READ/WRITE`:** Фактическая скорость чтения/записи для каждого процесса (КБ/с или МБ/с).
- **`SWAPIN`:** Процент времени, потраченного на ожидание страниц из swap (актуально при нехватке памяти).

> **Примечание:** В современных дистрибутивах может использоваться `iotop-c` (C-версия) вместо оригинальной Python-версии. Обе совместимы по функциональности.

## Основные концепции

`iotop` отвечает на вопрос: **"Какой процесс сейчас нагружает диск?"**

Если `top` показывает высокий `%wa` (iowait), а `iostat` подтверждает I/O bottleneck, `iotop` помогает найти конкретный процесс-виновник.

**Ключевые индикаторы:**

- **`IO>` ≈ 100%:** Процесс постоянно ожидает I/O — главный кандидат на оптимизацию
- **Высокий `DISK WRITE`:** Активная запись (бэкапы, логи, БД)
- **Высокий `SWAPIN`:** Нехватка RAM, активный swap

## Практические сценарии

### Интерактивный мониторинг

```bash
# Базовый запуск (требует root)
sudo iotop

# Только активные процессы (рекомендуется)
sudo iotop -o

# Без накопления (показывает текущую скорость)
sudo iotop -a

# Только процессы, а не потоки
sudo iotop -P

# Мониторинг конкретного пользователя
sudo iotop -u www-data

# Мониторинг конкретного PID
sudo iotop -p 1234,5678
```

### Неинтерактивный режим (скрипты, логирование)

```bash
# 3 отчета с интервалом 5 секунд в файл
sudo iotop -b -n 3 -d 5 > /var/log/iotop_report.log

# Постоянный мониторинг с логированием
sudo iotop -b -d 10 >> /var/log/iotop.log &
```

### Интерактивное управление

| Клавиша | Действие |
| :--- | :--- |
| **← / →** | Изменить колонку сортировки |
| **`r`** | Инвертировать порядок сортировки |
| **`o`** | Режим "только активные" (как `-o`) |
| **`a`** | Переключить накопление/скорость |
| **`q`** | Выход |
| **`h`** | Справка |

## Дополнительная информация

### Требования для работы

- **Права:** Требуется `root` или `CAP_SYS_ADMIN`
- **Ядро:** Поддержка `taskstats` (CONFIG_TASKSTATS, CONFIG_TASK_IO_ACCOUNTING)
- **Файловая система:** `/proc` должен быть смонтирован с опцией `hidepid=0` или `hidepid=1`

### Ограничения и особенности

- **Контейнеры:** В Docker/K8s может требоваться `--privileged` или `CAP_SYS_ADMIN`
- **NFS/CIFS:** I/O статистика может быть неполной для сетевых ФС
- **SSD/NVMe:** Высокая скорость может давать низкие значения `IO>` даже при большой нагрузке

### Альтернативы

| Инструмент | Преимущество |
| :--- | :--- |
| `pidstat -d 1` | I/O по PID с историей |
| [iostat](./iostat.md) | Общая статистика устройств |
| `blktrace` | Низкоуровневая трассировка I/O |
