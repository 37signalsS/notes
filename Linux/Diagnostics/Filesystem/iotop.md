# `iotop`

## Определения

- **`iotop`:** Интерактивная утилита, подобная `top`, для мониторинга дисковой активности (I/O) в реальном времени с разбивкой по процессам.
- **`IO>`:** Ключевой показатель `iotop`. Показывает процент времени, который процесс провел в ожидании завершения операций ввода-вывода.
- **`DISK READ/WRITE`:** Фактическая скорость чтения с диска и записи на диск для каждого процесса.

## Основные концепции

Основная задача `iotop` — быстро ответить на вопрос: **"Какой именно процесс сейчас нагружает диск?"**.

Если система испытывает проблемы с производительностью, и другие утилиты (например, `top`) показывают высокое значение `iowait` (`%wa`), `iotop` является первым инструментом для поиска виновника.

Процесс со значением `IO>` близким к 100% — это главный подозреваемый. Это означает, что он практически все свое время "застревает", ожидая ответа от диска, что и создает "бутылочное горлышко" в дисковой подсистеме.

## Практические сценарии

### Интерактивный мониторинг

```bash
# Базовый запуск (требует прав root)
sudo iotop

# Показать только процессы, которые активно работают с диском
sudo iotop -o

# Показать только процессы, а не потоки
sudo iotop -P

# Мониторить активность пользователя 'www-data'
sudo iotop -u www-data
```

*Для работы `iotop` необходим доступ к данным ядра, поэтому утилита всегда запускается с `sudo`.*

### Неинтерактивный режим (для скриптов)

`iotop` можно использовать в пакетном режиме для логирования.

```bash
# Записать 3 отчета с интервалом в 5 секунд в файл
sudo iotop -b -n 3 -d 5 > /var/log/iotop_report.log
```

## Дополнительная информация

### Интерактивное управление

В интерактивном режиме доступны следующие команды:

- **Стрелки влево/вправо**: Изменить колонку для сортировки.
- **`r`**: Инвертировать порядок сортировки.
- **`o`**: Включить/выключить режим "только активные" (аналог ключа `-o`).
- **`a`**: Переключить отображение между суммарной и средней скоростью I/O.
- **`q`**: Выйти.

### Связь с `iostat`

Инструменты `iotop` и `iostat` отлично дополняют друг друга в диагностике проблем с I/O:

- **`iotop`** показывает, **кто** (какой процесс) создает нагрузку.
- **[iostat](./iostat.md)** показывает, **как** дисковая подсистема справляется с этой нагрузкой (утилизация, время отклика, IOPS).
