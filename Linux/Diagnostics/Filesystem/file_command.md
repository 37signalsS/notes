# file

## Определения

- **`file`:** Универсальная утилита командной строки для определения типа данных внутри файла. В отличие от ОС Windows, `file` в Linux/Unix игнорирует расширение и анализирует фактическую структуру байтов.
- **libmagic:** Библиотека, на которой основана утилита `file`. Она содержит логику сопоставления сигнатур и предоставляет API для других программ (например, файловых менеджеров или веб-серверов).
- **Магические числа (Magic Numbers):** Константы или уникальные последовательности байтов, расположенные в определенных смещениях (обычно в начале) файла.
- **MIME-тип (Multipurpose Internet Mail Extensions):** Стандартизированный идентификатор формата контента, состоящий из типа и подтипа (например, `text/yaml`), используемый для автоматизации обработки данных.
- **Полиглот (Polyglot file):** Файл, который является валидным для нескольких форматов одновременно (например, одновременно JPEG и ELF). Утилита `file -k` позволяет обнаруживать все совпадения.
- **Сигнатура (Signature):** Шаблон в базе данных libmagic, описывающий уникальные байты, смещение, длину и опциональные проверки (endianness, версия формата) для идентификации конкретного типа файла.

## Основные концепции

Утилита `file` выполняет последовательно три уровня проверок:

1.  **Проверка файловой системы (Filesystem tests):** Анализ результата системного вызова `stat`. Позволяет сразу определить пустой файл, директорию, символьную ссылку, сокет или блочное устройство. Этот этап предшествует чтению содержимого и обеспечивает мгновенную идентификацию для не-REG-файлов.
2.  **Проверка магических чисел (Magic tests):** Сравнение содержимого файла с базой данных сигнатур (`/usr/share/misc/magic.mgc`). Это основной этап идентификации бинарных форматов (ELF, PDF, ZIP). Применяется только если `stat` определил файл как `S_IFREG` (обычный файл).
3.  **Текстовые проверки (Language tests):** Если файл не является бинарным, утилита ищет специфические текстовые последовательности (например, `#!`, `<html>`, `---` для YAML), чтобы определить кодировку и язык разметки/программирования.

### Внутренняя механика libmagic

База данных сигнатур (`magic.mgc`) хранит не просто список "начальных байтов", а структурированные шаблоны:

- **Смещение (Offset):** Абсолютное или относительное положение проверяемых байтов. Поддерживаются отрицательные смещения (от конца файла) и значения из предыдущих матчей.
- **Длина и тип:** Проверяемые байты могут быть `byte`, `short`, `long`, `string`, `date`, `leshort` (little-endian) и т.д.
- **Условия и логика:** Поддерживаются проверки `>`, `<`, `&`, `^`, `=` в одном правиле, а также вложенные проверки через `>&` (переход по смещению после частичного совпадения).

**Приоритет правил:** В одном файле `magic` правила обрабатываются сверху вниз. Первое совпадение определяет тип, если не установлен флаг `-k`. Это важно для кастомных баз: специфичные правила должны размещаться выше общих.

### База данных сигнатур

- **Системная БД:** Обычно `/usr/share/misc/magic` (исходный текст) и `/usr/share/misc/magic.mgc` (скомпилированная биinarная форма). Файл `.mgc` создается утилитой `file -C` и содержит индексы для быстрого поиска.
- **Пользовательская БД:** Можно расширять правила, создавая файлы в `/etc/magic` или `~/.magic`. Файлы объединяются с системной базой в алфавитном порядке (пути из `/etc/magic` обрабатываются перед `~/.magic`).
- **Версионность:** База данных жестко привязана к версии пакета `file`. При обновлении пакета старые `.mgc` пересоздаются. Для воспроизводимости в автоматизации копируют системный `magic` или используют контейнеры с фиксированной версией `file`.

### Взаимодействие с утилитой `stat`

Утилиты `file` и `stat` дополняют друг друга:
- `stat` показывает **файловую систему**-уровень: тип (`S_IFREG`, `S_IFDIR`...), права, владельца, размер, inode, время доступа.
- `file` показывает **содержимое**-уровень: внутренний формат данных внутри `S_IFREG`, кодировку, архитектуру ELF.

```bash
# Комбинированный анализ: тип ФС + внутренний формат
stat --format='%F %s bytes' /usr/bin/ls && file -b /usr/bin/ls
# → Regular file 168656 bytes
# → ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked
```

## Практические сценарии

### Идентификация и автоматизация

```bash
# Определение типа без вывода имени файла (идеально для переменных в скриптах)
TYPE=$(file -b --mime-type config.yaml)
# → text/plain (или text/yaml в зависимости от версии БД)

# Массовая проверка файлов из списка
file -f list_of_files.txt

# Вывод информации о кодировке текста
file -i script.py
# → script.py: text/x-python; charset=utf-8
```

### Валидация артефактов в CI/CD пайплайнах

```bash
# Проверка архитектуры собранного бинарника перед публикацией
ARTIFACT=build/myapp-linux-amd64
file -b "$ARTIFACT"
# → ELF 64-bit LSB executable, x86-64

# Верификация формата скачанного ISO-образа
file -b --mime-type ubuntu-22.04.iso
# → application/x-iso9660-image

# Проверка, что загруженный пользователем файл является именно тем, за что себя выдает
UPLOAD=/var/www/uploads/report.xlsx
EXT=$(basename "$UPLOAD" | sed 's/.*\.//')
MIME=$(file -b --mime-type "$UPLOAD")
if [[ "$MIME" != application/vnd* ]]; then
  echo "ALERT: $UPLOAD has MIME $MIME but extension .$EXT"
fi
```

### Инцидент-респонс и цифровая криминалистика

```bash
# Анализ подозрительного файла на предмет множественных форматов (polyglot)
file -k malware_sample
# → malware_sample: PE32 executable (GUI) Intel 80386, for MS Windows
# → malware_sample: JPEG image data
# Вторая строка означает внедренный payload

# Проверка вложения электронной почты на маскировку под документ
file -z invoice.pdf.gz
# → invoice.pdf.gz: gzip compressed data, from Unix, last modified: ...
# → PDF document, version 1.4

# Определение архитектуры неизвестного бинарника при реагировании на инцидент
file -b /tmp/suspicious_binary
# → ELF 32-bit LSB executable, ARM, EABI5 version 1 (SYSV)

# Поиск всех исполняемых файлов в каталоге загрузов (опытного пользователя)
sudo find /home -type f -executable -exec file -b --mime-type {} \; | sort | uniq -c | sort -rn
```

### Массовый аудит файловой системы

```bash
# Поиск всех файлов с неожиданным типом (например, исполняемых в /etc)
find /etc -type f -exec file -b --mime-type {} \; | grep application/x-executable

# Сканирование директории и группировка по типам (DevOps: контроль загрузок, compliance)
find /opt/deployments -type f -print0 | xargs -0 file -b --mime-type | sort | uniq -c | sort -rn

# Поиск исполняемых файлов без расширений (потенциальные угрозы в /tmp)
find /tmp -type f -executable ! -name "*.*" -exec ls -la {} \;

# Аудит с контекстом владельца (кто разместил нестандартные файлы)
find /var/www -type f -exec sh -c 'echo "$(stat -c "%U:%G" "$1") $(file -b "$1")"' _ {} \;
```

### Интеграция с мониторингом и алертингом

```bash
# Проверка роста типа файлов в критичной директории (например, появление бинарников в /etc)
if find /etc -type f -exec file -b --mime-type {} \; | grep -q 'application/x-executable'; then
  logger -p local0.warn "ALERT: executable detected in /etc"
fi

# Мониторинг появления новых форматов в каталоге загрузок (Raspberry Pi / IoT)
WATCH_DIR=/srv/images
while inotifywait -r -e create "$WATCH_DIR"; do
  find "$WATCH_DIR" -type f -mmin -1 -exec file -b {} \;
done | tee -a /var/log/file-watch.log
```

### Автоматизация и парсинг вывода

```bash
# Машинночитаемый вывод для Python/jq (формат -F)
file -b -F pn /usr/bin/ls
# p/usr/bin/ls
# →ELF 64-bit LSB executable, x86-64...

# Получение только MIME-типа для web-сервера (Nginx/Apache)
find /var/www -type f -print0 | xargs -0 file -b --mime-type | sort | uniq -c
#    142 text/html
#     87 application/javascript
#     12 image/jpeg

# Фильтрация только текстовых файлов для конфигурационного аудита
find /etc -type f \( -name '*.conf' -o -name '*.yml' -o -name '*.json' \) -print0 | \
  xargs -0 file -b --mime-type | grep -c '^text/'
```

### Анализ контейнерных образов и слоев (локальный)

```bash
# Проверка типа файла внутри директории слоя контейнера (Docker/containerd)
LAYER=/var/lib/docker/overlay2/.../diff
find "$LAYER" -type f -exec file -b {} \; | head

# Определение архитектуры образа без запуска контейнера
docker save localhost/myapp:latest | tar -xf - -O manifest.json | jq -r '.[0]'

# Извлечение и проверка бинарника из образа
docker create --name tmp-check localhost/myapp:latest
docker cp tmp-check:/usr/local/bin/myapp /tmp/
file -b /tmp/myapp
# → ELF 64-bit LSB executable, x86-64, version 1 (SYSV)
docker rm tmp-check
```

### Диагностика загрузочных носителей и разделов

```bash
# Определение типа разделения диска (GPT/MBR) через файловую систему
sudo file -s /dev/sda1
# → /dev/sda1: Linux rev 1.0 ext4 filesystem data, ...

# Проверка ISO-образа перед записью на флешку
file -b --mime-type fedora-40.iso
# → application/x-iso9660-image

# Анализ MBR/GPT без монтирования
sudo dd if=/dev/sda bs=512 count=1 | file -
# → /dev/stdin: DOS/MBR boot sector
```

### Глубокая диагностика и безопасность

```bash
# Продолжать поиск всех возможных совпадений (не останавливаться на первом)
file -k suspicious_file
# → Помогает выявить "матрешки" или файлы с внедренными данными

# Анализ содержимого внутри сжатых архивов (поддерживает gz, bz2, zip)
file -z backup.tar.gz

# Определение файловой системы на неразмеченном диске
sudo file -s /dev/nvme0n1p1
```

### Работа в macOS (Darwin)

На macOS утилита `file` может возвращать специфические типы, такие как `Mach-O 64-bit executable arm64` для Apple Silicon. База данных магических чисел в macOS также включает специфические сигнатуры для форматов Apple (например, `.dmg`, `.plist`).

## Дополнительная информация

### Ключевые параметры

| Опция | Описание | Пример |
| :--- | :--- | :--- |
| `-b`, `--brief` | Не выводить имя файла перед результатом | `file -b data.bin` |
| `-i`, `--mime` | Показать MIME-тип и кодировку | `file -i index.html` |
| `-f`, `--files-from` | Читать имена файлов из указанного файла | `file -f targets.log` |
| `-k`, `--keep-going` | Показать все найденные совпадения, а не только первое | `file -k polyglot.jpg` |
| `-L`, `--dereference` | Следовать по символьным ссылкам (по умолчанию проверяет саму ссылку) | `file -L /usr/bin/python` |
| `-s`, `--special-files` | Читать специальные файлы (устройства), которые обычно игнорируются | `file -s /dev/sda` |
| `-C`, `--compile` | Скомпилировать файл магических чисел для ускорения работы | `file -C my_magic` |
| `-z`, `--uncompress` | Распаковать сжатые файлы для анализа внутреннего содержимого | `file -z archive.tar.gz` |
| `-r`, `--raw` | Выводить необработанные символы (escape-последовательности) | `file -r binary.bin` |
| `-N`, `--no-pad` | Не дополнять вывод отступами для выравнивания | `file -N script.py` |
| `-F`, `--separator` | Указать разделитель между результатами для нескольких файлов | `file -F$'\t' *.log` |
| `-m`, `--magic-file` | Использовать пользовательскую базу сигнатур вместо системной | `file -m /etc/magic/custom.mgc artifact` |

### Машинночитаемый вывод (формат -F)

Утилита поддерживает вывод в формате, удобном для парсинга, где каждое поле начинается с однобуквенного префикса:

```bash
file -F pn /usr/bin/ls
# p/usr/bin/ls
# ELF 64-bit LSB executable, x86-64...

# Доступные префиксы: b (basename), c (0-terminated command), d (device number),
# i (inode), n (link count), p (path/name), s (size), t (type)
```

### Современные MIME-типы и сигнатуры

| MIME-тип | Примечание |
| :--- | :--- |
| `text/yaml` или `text/plain` | Файлы конфигурации (часто зависят от версии `libmagic`) |
| `application/json` | Структурированные данные |
| `application/x-executable` | Бинарные файлы Linux (ELF) |
| `application/x-mach-binary` | Бинарные файлы macOS (Mach-O) |
| `application/vnd.apple.pkpass` | Специфические форматы Apple |
| `application/x-iso9660-image` | Образы оптических дисков |
| `application/zlib` | Сырые сжатые потоки (deflate) |
| `application/gzip` | Архивы gzip |
| `application/x-zerosize` | Пустые файлы (нулевого размера) |

### Ограничения и нюансы

- **Ложноположительные срабатывания:** Случайные последовательности байтов в текстовых файлах иногда могут быть ошибочно приняты за магические числа редких форматов. Особенно часто это происходит на коротких файлах (< 16 байт).
- **Производительность с `-z`:** Распаковка "на лету" для анализа содержимого архивов может быть медленной для очень больших файлов. Для массового сканирования используйте `-z` только на кандидатах, предварительно отфильтрованных по расширению.
- **Точность:** Утилита определяет формат, но не валидирует его (например, поврежденный PDF может быть определен как PDF). Для глубокой валидации используйте специализированные инструменты (`pdfinfo`, `jq .` для JSON, `yamllint`).
- **Полиглоты:** Файлы, валидные в нескольких форматах, определяются по первому совпадению в базе. Используйте `file -k` для обнаружения всех форматов.
- **Ограничение чтения:** `file` по умолчанию читает ограниченное количество байтов (определяется в правилах magic). Очень большие файлы не считываются полностью.
- **Зависимость от версии libmagic:** Сигнатуры обновляются вместе с пакетом. Формат вывода может отличаться между Debian 11 и Ubuntu 22.04 для одного и того же файла.
- **Виртуальные файлы:** `/proc`, `/sys`, временные файлы в `/tmp` могут возвращать неоднозначные результаты или пустую строку, так как их "содержимое" генерируется ядром динамически.
- **Пустые файлы:** Определяются на этапе filesystem tests как `empty`, без обращения к magic базе.

### Типичные проблемы и решения

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| Неверный тип для короткого файла | Файл слишком мал для уникальной сигнатуры | Используйте `file -k` или дополнительную проверку содержимого |
| `file` зависает на NFS | NFS-сервер недоступен, `file` блокируется на `stat` | Используйте `timeout 5s file ...` или `-b` (если доступна в версии) |
| Разный вывод на разных серверах | Разные версии `libmagic`/`file` | Фиксируйте версию в контейнере или проверяйте на эталонной системе |
| Ложное срабатывание `text/plain` на бинарник | Отсутствие сигнатуры в magic базе | Добавьте пользовательское правило в `/etc/magic` |
| Не работает `file -k` на старых системах | Устаревшая версия `file` (< 5.0) | Обновите пакет `file` из бэкпортов или собрать из исходников |
| Ошибка `magic: no magic files loaded` | Повреждена база `/usr/share/misc/magic.mgc` | Переустановите пакет `file`: `apt reinstall file` или `dnf reinstall file` |
| Долгая работа на тысячах файлов | Линейный вызов `file` для каждого файла | Используйте `xargs` с батчингом: `find ... -print0 \| xargs -0 -P4 file -b` |

### Рекомендации (Best Practices)

1. **Комбинируйте с `stat`:** Для полной картины используйте `file` вместе с `stat` — один показывает метаданные ФС, второй — внутренний формат.
2. **Используйте `-k` для полиглотов:** В сценариях безопасности и форензики всегда добавляйте `-k`, чтобы не пропустить внедренные payload.
3. **Фиксируйте версию libmagic в автоматизации:** Для reproducible builds и audit используйте контейнеры или виртуальные окружения с зафиксированной версией пакета `file`.
4. **Не полагайтесь на MIME-тип для безопасности:** `file -i` полезен для веб-серверов, но злоумышленник может создать файл, у которого MIME=`image/jpeg`, а содержимое — ELF-бэкдор. Используйте `file -k` + хеширование.
5. **Создавайте пользовательские базы для проприетарных форматов:** Если ваша компания использует кастомные бинарные форматы, описывайте их в `/etc/magic` — это позволит `file` корректно идентифицировать артефакты без расширений.
6. **Экранируйте вывод в скриптах:** При парсинге вывода `file` используйте `-F` с уникальным разделителем (например, `\0` или `\t`), а не пробел, так как пути к файлам могут содержать пробелы.
