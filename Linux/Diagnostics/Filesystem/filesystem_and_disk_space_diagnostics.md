# Диагностика файловых систем и дискового пространства

## Определения

- **Файловая система:** Структура для организации, хранения и доступа к файлам. Подробнее см. в [обзоре файловых систем](../../FileSystems/partitions_and_filesystems.md).
- **Дисковое пространство:** Общий объем данных, который можно хранить на диске. Диагностика включает анализ как общего, так и занятого/свободного пространства.
- **`df` (disk free):** Утилита, показывающая сводную информацию о дисковом пространстве на уровне всей файловой системы. Читает данные из [суперблока](../../FileSystems/fs_internals.md#Суперблок-Superblock), поэтому работает быстро.
- **`du` (disk usage):** Утилита, рекурсивно обходящая каталоги для подсчета реального размера, занимаемого файлами. Работает медленнее, но предоставляет точную информацию для конкретных директорий.
- **Inode (индексный дескриптор):** Структура данных, хранящая метаданные о файле (права, владелец и т.д.). Каждому файлу соответствует свой inode, и их количество ограничено. Подробное описание находится в статье [о ссылках и Inode](../../FileSystems/links_inodes_dentries.md).

## Основные концепции

Ключевое различие между `df` и `du` заключается в их подходе к подсчету. `df` оперирует информацией на уровне файловой системы в целом (сколько блоков выделено), тогда как `du` анализирует непосредственно файлы.

Это различие приводит к расхождениям в их выводах, особенно в двух случаях:

1. **Удаленные, но используемые файлы:** Когда файл удален, но все еще открыт каким-либо процессом, `du` перестает его видеть, но `df` продолжает учитывать занимаемое им место, так как оно не будет освобождено до закрытия файла процессом.
2. **Нехватка Inodes:** Система может сообщать об ошибке "No space left on device", даже если `df -h` показывает наличие свободного места. Это происходит, когда заканчиваются свободные inodes. В этом случае `df -i` покажет 100% использование inode'ов.

### Подробное сравнение `df` и `du`

- **`df` (disk free)** показывает использование диска с точки зрения файловой системы, считывая информацию из **суперблока**. Он мгновенно предоставляет данные о том, сколько всего блоков занято и свободно на разделе. `df` не пересчитывает занятое место, а получает уже готовую информацию. Это делает его очень быстрым и подходящим для мониторинга общего состояния дискового пространства.
- **`du` (disk usage)** рекурсивно подсчитывает суммарный размер конкретных файлов и директорий, проходя по файловой системе. Это более медленная операция, так как она реально пересчитывает объемы данных, но она показывает фактический объем данных, занимаемый файлами. `du` полезен для определения, какие каталоги или файлы занимают больше всего места.

Ни одна из утилит не является "лучше" другой; они служат разным целям. `df` дает быстрый обзор состояния файловой системы, а `du` — детальную информацию о занятом пространстве конкретными файлами и каталогами.

Более полный список причин расхождений между `df` и `du`:

1. **Удаленные, но открытые файлы:** Если файл был удалён, но всё ещё используется каким-либо процессом (дескриптор файла открыт), `du` не будет учитывать этот файл, а `df` будет, так как место на диске еще не освобождено до тех пор, пока процесс не закроет файл.
2. **Блочное выделение:** `df` считает выделенные блоки, а `du` — фактический размер данных. Если у вас много мелких файлов, которые не полностью заполняют свои блоки, `df` может показать больший объем, чем `du`, поскольку файловая система выделяет место блоками фиксированного размера.
3. **Точки монтирования:** `df` показывает информацию только для смонтированных файловых систем, тогда как `du` может подсчитывать размер файлов в директориях, которые могут быть точками монтирования для других файловых систем.

## Практические сценарии

### `mount`: Просмотр смонтированных систем

Утилита `mount` без аргументов показывает, какие файловые системы и куда примонтированы. Подробное описание команды и способов монтирования находится в статье об [управлении монтированием](../../FileSystems/mounting.md).

```bash
# Показать все точки монтирования
mount | column -t
```

### `lsblk`: Просмотр блочных устройств

Утилита `lsblk` позволяет просмотреть список всех блочных устройств, их размеры, точки монтирования и взаимосвязи. Она особенно полезна для быстрого выявления новых, еще не размеченных физических дисков.

```bash
lsblk
```

Подробнее об использовании `lsblk` см. в разделе [Просмотр блочных устройств](../../FileSystems/partitions_and_filesystems.md#просмотр-блочных-устройств-lsblk).

### `df`: Анализ свободного пространства

Показывает использование дискового пространства на уровне файловых систем.

```bash
# Показать свободное место в человекочитаемом формате (GB, MB)
df -h

# Показать использование inode (важно для диагностики)
df -i
```

Если `df -i` показывает использование 100%, это означает, что исчерпаны индексные дескрипторы.

### `du`: Анализ занятого пространства

Подсчитывает, сколько места занимают конкретные файлы и директории.

```bash
# Узнать общий размер текущей директории
du -sh .

# Найти самые "тяжелые" директории внутри /var (на 1 уровень вглубь)
# sort -rh сортирует результат по убыванию
sudo du -h --max-depth=1 /var | sort -rh
```

## Дополнительная информация

Для более глубокого анализа производительности дисков (I/O) используются специализированные инструменты, такие как [iostat](./iostat.md) и [iotop](./iotop.md), которые показывают статистику операций ввода-вывода, а не только занятое пространство.
