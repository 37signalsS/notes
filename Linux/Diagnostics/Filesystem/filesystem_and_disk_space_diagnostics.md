# Диагностика файловых систем и дискового пространства

## Определения

- **Файловая система:** Структура для организации, хранения и доступа к файлам.
- **Дисковое пространство:** Общий объем данных, который можно хранить на накопителе. Диагностика включает анализ как общего, так и занятого или свободного пространства.
- **`df` (disk free — свободное место на диске):** Утилита, показывающая сводную информацию о дисковом пространстве на уровне всей файловой системы. Читает данные из суперблока, поэтому работает быстро.
- **`du` (disk usage — использование диска):** Утилита, рекурсивно обходящая каталоги для подсчета реального объема, занимаемого файлами. Работает медленнее, но предоставляет точную информацию для конкретных директорий.
- **Inode (index node — индексный дескриптор):** Структура данных, хранящая метаданные о файле (права, владелец, временные метки, указатели на блоки). Каждому файлу соответствует свой индексный дескриптор. Количество дескрипторов фиксировано при создании файловой системы (для Ext2/3/4 — Extended File System) или выделяется динамически (XFS, Btrfs).

## Основные концепции

### Различия в механизмах подсчета

- **`df` (disk free):** Показывает использование диска на уровне всей файловой системы. Утилита считывает метаданные из суперблока, где хранится сводная информация о количестве выделенных и свободных блоков. Это обеспечивает практически мгновенный результат, но не отражает реальный объем данных в конкретных каталогах.
- **`du` (disk usage):** Рекурсивно обходит каталоги и подсчитывает суммарный размер файлов. Эта операция выполняется медленнее, но предоставляет точную информацию о том, какие именно файлы и директории занимают место.

Из-за различий в подходе данные этих утилит могут не совпадать.

### Причины расхождений между данными `df` и `du`

1. **Удаленные, но открытые файлы:** Если процесс удалил файл, но все еще удерживает его открытым (не закрыл файловый дескриптор), занимаемое им место не освобождается. `du` перестает видеть этот файл, так как его нет в каталоге, но `df` продолжает учитывать занимаемые им блоки до тех пор, пока процесс не завершится или не закроет файл.
2. **Разреженные файлы (sparse files) и блочное выделение:** Файловые системы выделяют пространство блоками фиксированного размера. `du` показывает фактический объем данных в файле, тогда как `df` считает общее количество выделенных блоков. Это приводит к разнице, особенно для множества мелких файлов (каждый занимает минимум один блок) или для разреженных файлов, которые имеют большой логический размер, но фактически занимают на диске значительно меньше места.
3. **Точки монтирования:** `df` отображает статистику для каждой смонтированной файловой системы отдельно. В то же время `du` подсчитывает размер каталога, который может быть точкой монтирования для другой файловой системы (поведение по умолчанию). Чтобы `du` не пересекал границы файловых систем, используется флаг `-x` (`--one-file-system`).

### Механизм удаленных открытых файлов

Команда `rm` выполняет системный вызов `unlink()`, который удаляет только запись в каталоге (жесткую ссылку на inode). Индексный дескриптор и его блоки данных уничтожаются ядром только при одновременном выполнении двух условий:

1. **link count = 0** — нет ни одной жесткой ссылки на inode в каталогах
2. **Нет открытых файловых дескрипторов (FD)** — ни один процесс не держит файл открытым

Пока хотя бы один процесс удерживает открытый FD на удаленный файл, файл продолжает существовать в `/proc/<pid>/fd/` и занимать место на диске.

```text
каталог          inode          блоки на диске
/var/log/  --> app.log  -->  [блок1][блок2][блок3]
               ^
               | открытый дескриптор
               nginx (PID 1234, FD 7)

после rm (unlink):
каталог          inode          блоки на диске
/var/log/  --> (удалено) -->  [блок1][блок2][блок3]
               ^                    ^
               | FD (PID 1234)      | всё ещё занято!
```

`du` обходит `/var/log/` — файла там нет, объем не учитывается. `df` обращается к суперблоку — блоки помечены как занятые. **Прямой эффект:** `df` покажет, что место не освободилось после `rm`. Освобождение произойдёт только после закрытия всех FD (выход процесса или явный `close()`).

**Типичный сценарий:** Система ротации логов настроена на удаление старого лога через `rm`. Сервис (например, nginx или Java-приложение) держит файл открытым на запись. Процесс продолжает писать в удаленный файл, блоки заполняются, `df` показывает рост использования, `du` не находит потребителя места. Это продолжается до перезапуска процесса или полного исчерпания ресурсов накопителя.

**Диагностика и восстановление:**

```bash
# Поиск удаленных, но открытых файлов
lsof | grep deleted
# → nginx   1234  root    7w  REG  8,1  1048576  123456 /var/log/app.log (deleted)

# Список всех открытых FD процесса
ls -la /proc/<PID>/fd/
# → lrwx------ 1 root root 64 Jan  1 12:00 7 -> /var/log/app.log (deleted)

# Восстановление удаленного файла (если FD ещё жив)
cp /proc/<PID>/fd/<FD> /etc/restored.conf
# → (файл восстановлен)
```

**Почему `rm + touch` не работает для ротации логов:**

- `rm` удаляет ссылку на старый inode (файл продолжает жить через FD процесса)
- `touch` создаёт новый файл с новым inode
- Процесс продолжает писать в старый (unlinked) inode через старый FD
- Место не освобождается

**Правильный способ обнуления лога без перезапуска:**

```bash
truncate -s 0 /path/to/log
# → (размер файла обнулен, место освобождено)
```

`truncate` обнуляет содержимое файла на месте — inode и FD остаются валидными. Процесс продолжает писать с нулевого смещения.

### Диагностика нехватки индексных дескрипторов (Inodes)

Каждый файл и каталог потребляет ровно один inode. Таблица inode создаётся при `mkfs` с фиксированным размером — по умолчанию 1 inode на каждые 16 КБ блочного пространства для ext4.

Система может сообщать об ошибке `"No space left on device"` (на устройстве не осталось места), даже если `df -h` показывает наличие свободного пространства. Это происходит, когда в файловой системе заканчиваются свободные индексные дескрипторы. Если IUse% = 100% — запись новых файлов невозможна, даже при свободных гигабайтах.

**Команды для диагностики:**

```bash
# Проверка использования индексных дескрипторов (IUse% = 100% — диагноз)
df -i
# → Filesystem      Inodes   IUsed   IFree IUse% Mounted on
# → /dev/sda1      1048576 1048576       0  100% /

# Проверка конкретной файловой системы
df -ih /var
# → Filesystem     Inodes IUsed IFree IUse% Mounted on
# → /dev/sdb1        6.3M  5.1M  1.2M   81% /var

# Поиск каталога с наибольшим числом файлов
find /var -xdev -printf '%h\n' | sort | uniq -c | sort -rn | head -20
# →  54321 /var/spool/postfix/maildrop
# →  12345 /var/lib/php/sessions
```

**Типичные причины исчерпания дескрипторов:**

- **Множество мелких файлов:** Спам в `/tmp`, очереди в `/var/spool/postfix`, неочищаемые PID-файлы, тысячи пустых лог-файлов, кэши пакетных менеджеров (Composer, npm, pip), сессии PHP.
- **Файловые системы Ext (Extended File System):** Количество дескрипторов фиксируется при создании файловой системы.

**Решение:**

1. **Очистка:** Удалить мусорные файлы из проблемных каталогов.
2. **Пересоздание ФС:** Если проблема повторяется — создать файловую систему с меньшим `bytes-per-inode`. Для ext4 значение по умолчанию — 16384 (16 КБ). Уменьшение до 4096 увеличивает лимит inode в 4 раза:

   ```bash
   mkfs.ext4 -i 4096 /dev/sdX
   # → (создание ФС с увеличенным количеством inode)
   ```

   Текущий ratio можно проверить через:

   ```bash
   tune2fs -l /dev/sdX | grep 'Inode ratio'
   # → Inode ratio:              16384
   ```

3. **Миграция** на XFS или Btrfs — эти ФС используют динамическое выделение индексных дескрипторов.

Для Ext-файловых систем увеличение количества индексных дескрипторов невозможно без пересоздания файловой системы.

## Практические сценарии

### План быстрой диагностики

```bash
# 1. Общее состояние дискового пространства (особенно /var/log, /tmp)
df -h
# → Filesystem      Size  Used Avail Use% Mounted on
# → /dev/sda1        50G   48G  2.0G  96% /

# 2. Проверка использования индексных дескрипторов
df -i
# → Filesystem     Inodes IUsed IFree IUse% Mounted on
# → /dev/sda1        3.2M  1.5M  1.7M   47% /

# 3. Поиск самых больших директорий (глубина 2 уровня)
du -h --max-depth=2 / | sort -rh | head -20
# → 12G     /var/log
# → 8G      /var/lib/docker

# 4. Поиск файлов размером более 1 ГБ (Гигабайта)
find / -type f -size +1G -exec ls -lh {} \; 2>/dev/null
# → -rw-r--r-- 1 root root 2.5G Jan 1 12:00 /var/log/huge.log

# 5. Проверка удаленных, но открытых файлов
lsof +L1 2>/dev/null
# → COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NLINK      NODE NAME
# → nginx    1234 root    7w   REG    8,1 10485760     0    123456 /var/log/app.log (deleted)
```

> **Расхождение `df -h` vs `du -sh`:** `df` читает суперблок ФС — быстро, но не учитывает удалённые файлы, которые держит открытый дескриптор. `du` рекурсивно суммирует реальные файлы. Расхождение между ними — признак deleted-but-open файлов (см. `lsof +L1`).

### Просмотр смонтированных систем через `mount`

Утилита `mount` без аргументов показывает, какие файловые системы и куда примонтированы.

```bash
# Просмотр всех точек монтирования в табличном виде
mount | column -t
# → sysfs       on  /sys                   type  sysfs       (rw,nosuid,nodev,noexec,relatime)
# → /dev/sda1   on  /                      type  ext4        (rw,relatime)
```

### Анализ блочных устройств через `lsblk`

Утилита `lsblk` (list block devices) позволяет просмотреть список всех блочных устройств, их размеры и точки монтирования.

```bash
lsblk
# → NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
# → sda      8:0    0   50G  0 disk 
# → └─sda1   8:1    0   50G  0 part /
```

### Анализ свободного пространства через `df`

```bash
# Вывод в человекочитаемом формате
df -h
# → Filesystem      Size  Used Avail Use% Mounted on
# → /dev/sda1        50G   25G   25G  50% /

# Вывод типов файловых систем
df -hT
# → Filesystem     Type      Size  Used Avail Use% Mounted on
# → /dev/sda1      ext4       50G   25G   25G  50% /

# Исключение временных файловых систем (tmpfs)
df -h -x tmpfs -x devtmpfs
# → (покажет только физические накопители)
```

### Анализ занятого пространства через `du`

```bash
# Общий размер текущей директории
du -sh .
# → 1.5G    .

# Поиск крупнейших директорий внутри /var
sudo du -h --max-depth=1 /var | sort -rh
# → 12G     /var
# → 8G      /var/lib

# Подсчет количества индексных дескрипторов по директориям
du --inodes -S / | sort -rh | head -20
# → 45000   /var/lib/docker/overlay2
```

Для интерактивного анализа рекомендуется использовать утилиту `ncdu` (ncurses disk usage).

### Сценарий: Очистка диска от работающего процесса

Если диск переполнен из-за работающего приложения, которое активно пишет логи, простое удаление файлов может не помочь, если процесс держит их открытыми.

**1. Поиск процесса и его файлов:**

```bash
# 1. Находим идентификатор процесса (PID — Process Identifier)
PID=$(pgrep -f "имя_бинаря")

# 2. Список файлов, открытых процессом для записи
sudo lsof -p $PID | grep -E ' (w|u) '
# → app_bin 1234 root    7w   REG    8,1 10485760 123456 /var/log/app.log
```

**2. Анализ занимаемого объема:**

```bash
# Показать размеры открытых файлов для конкретного процесса
sudo lsof -p $PID -s | awk '$5 == "REG" {print $7, $9}' | sort -n
# → 10485760 /var/log/app.log
```

**3. Безопасная очистка без остановки сервиса:**
Если обнаружен огромный лог-файл, который нельзя удалить (место не освободится), следует выполнить обнуление (truncate). Процесс продолжит писать в тот же файл, но с нулевого смещения.

```bash
# Обнуление через перенаправление (truncate)
> /var/log/app.log
# → (файл обнулен)

# Если файл уже удален через rm, но место не освободилось
# Используем номер файлового дескриптора (например, 7) из вывода lsof
> /proc/$PID/fd/7
# → (занятые блоки освобождены)
```

Процесс обращения через дескриптор в `/proc` обходит файловую систему, где файл уже помечен как удаленный. Ядро обнуляет блоки, и свободное место на накопителе мгновенно увеличивается.

### Ситуация: На диске есть место, но создать файл нельзя

1. **Исчерпание дескрипторов (Inodes):** Проверьте через `df -i`.
2. **Зарезервированное пространство для суперпользователя:** Файловые системы Ext резервируют 5% места для `root`. При заполнении более чем на 95% обычные пользователи не могут записывать данные. Подробнее см. в статье об [устранении нехватки места на диске](../../FileSystems/disk_space_troubleshooting.md).
3. **Удаленные, но открытые файлы:** Место занято процессом, который не закрыл дескриптор удаленного файла. Используйте `lsof +L1`.
