# Диагностика файловых систем и дискового пространства

## Определения

- **Файловая система:** Структура для организации, хранения и доступа к файлам. Подробнее см. в [обзоре файловых систем](../../FileSystems/partitions_and_filesystems.md).
- **Дисковое пространство:** Общий объем данных, который можно хранить на диске. Диагностика включает анализ как общего, так и занятого/свободного пространства.
- **`df` (disk free):** Утилита, показывающая сводную информацию о дисковом пространстве на уровне всей файловой системы. Читает данные из [суперблока](../../FileSystems/fs_internals.md), поэтому работает быстро.
- **`du` (disk usage):** Утилита, рекурсивно обходящая каталоги для подсчета реального размера, занимаемого файлами. Работает медленнее, но предоставляет точную информацию для конкретных директорий.
- **Inode (индексный дескриптор):** Структура данных, хранящая метаданные о файле (права, владелец, временные метки, указатели на блоки). Каждому файлу соответствует свой inode. Количество inode фиксировано при создании ФС (Ext2/3/4) или выделяется динамически (XFS, Btrfs). Подробная теория — в [Ссылки, Inode и Dentry](../../FileSystems/links_inodes_dentries.md).

## Основные концепции

### Ключевые различия в подсчете

- **`df` (disk free):** Показывает использование диска на уровне файловой системы. Утилита считывает метаданные из **суперблока**, где хранится сводная информация о количестве выделенных и свободных блоков. Это обеспечивает практически мгновенный результат, но не отражает реальный размер данных в конкретных каталогах.
- **`du` (disk usage):** Рекурсивно обходит каталоги и подсчитывает суммарный размер файлов. Эта операция медленнее, но предоставляет точную информацию о том, какие именно файлы и директории занимают место.

Из-за этих различий в подходе выводы утилит могут расходиться.

### Причины расхождений между `df` и `du`

1. **Удаленные, но открытые файлы:** Если процесс удалил файл, но все еще удерживает его открытым (не закрыл файловый дескриптор), занимаемое им место не освобождается. `du` перестает видеть этот файл, так как его нет в каталоге, но `df` продолжает учитывать занимаемые им блоки до тех пор, пока процесс не завершится или не закроет файл.
2. **Разреженные файлы (sparse files) и блочное выделение:** Файловые системы выделяют пространство блоками фиксированного размера. `du` показывает фактический размер данных в файле, тогда как `df` считает общее количество выделенных блоков. Это приводит к разнице, особенно для множества мелких файлов (каждый занимает минимум один блок) или для разреженных файлов, которые имеют большой логический размер, но занимают на диске значительно меньше места.
3. **Точки монтирования:** `df` отображает статистику для каждой смонтированной файловой системы отдельно. В то же время `du` подсчитывает размер каталога, который может быть точкой монтирования для другой файловой системы (поведение по умолчанию). Чтобы `du` не пересекал границы файловых систем, используется флаг `-x` (`--one-file-system`).

### Механизм удалённых открытых файлов

Когда процесс открывает файл, ядро создаёт **файловый дескриптор** — ссылку на **inode**. Inode хранит метаданные файла (права, владелец, размер, список блоков на диске). Пока хотя бы один дескриптор на inode открыт, ядро не удаляет блоки с диска.

При `rm` удаляется только запись в каталоге (hardlink). Inode и данные остаются, пока счётчик ссылок не упадёт до нуля.

```
каталог          inode          блоки на диске
/var/log/  --> app.log  -->  [блок1][блок2][блок3]
               ^
               | открытый дескриптор
               nginx (pid 1234, fd 7)

после rm:
каталог          inode          блоки на диске
/var/log/  --> (удалено) -->  [блок1][блок2][блок3]
               ^                    ^
               | дескриптор         | всё ещё занято!
               nginx (pid 1234, fd 7)
```

`du` обходит `/var/log/` — файла там нет, не считает. `df` смотрит на суперблок — блоки заняты, считает. Отсюда расхождение.

**Классический сценарий:** Logrotate настроен на `rm` старого лога. Сервис (nginx, java) держит файл открытым на запись. Процесс продолжает писать в удалённый файл, блоки заполняются, `df` показывает рост, `du` ничего не находит. Это продолжается до перезапуска процесса или полного исчерпания диска.

### Диагностика нехватки Inodes

Система может сообщать об ошибке `"No space left on device"`, даже если `df -h` показывает наличие свободного места. Это происходит, когда в файловой системе заканчиваются свободные **inodes**.

**Диагностика:**

```bash
# Проверка использования inode
df -i

# Поиск директорий с наибольшим количеством файлов (inodes)
du --inodes -S / | sort -rh | head -20

# Альтернатива: find для подсчёта файлов в директориях
find /var -type f | wc -l
```

**Типичные причины исчерпания inodes:**

- **Множество мелких файлов:** Кэши (Composer, npm, pip), сессии PHP, почтовые очереди, логи
- **Файловые системы Ext2/3/4:** Количество inode фиксировано при создании (параметр `-i` в `mkfs`)
- **Решение:** Очистка кэшей, миграция на XFS/Btrfs (динамические inode), пересоздание ФС с `-i 4096`

> **Важно:** Для Ext-файловых систем увеличение количества inode невозможно без пересоздания ФС. См. [Увеличение количества Inodes](../../FileSystems/links_inodes_dentries.md#увеличение-количества-inodes-ext234).

## Практические сценарии

### Быстрая диагностика: чек-лист

```bash
# 1. Общее состояние дискового пространства
df -h

# 2. Проверка использования inode
df -i

# 3. Поиск самых больших директорий
du -h --max-depth=2 / | sort -rh | head -20

# 4. Поиск файлов >1GB
find / -type f -size +1G -exec ls -lh {} \; 2>/dev/null

# 5. Проверка удалённых, но открытых файлов
lsof +L1 2>/dev/null
```

### `mount`: Просмотр смонтированных систем

Утилита `mount` без аргументов показывает, какие файловые системы и куда примонтированы. Подробное описание команды и способов монтирования находится в статье об [управлении монтированием](../../FileSystems/mounting/index.md).

```bash
# Показать все точки монтирования
mount | column -t
```

### `lsblk`: Просмотр блочных устройств

Утилита `lsblk` позволяет просмотреть список всех блочных устройств, их размеры, точки монтирования и взаимосвязи. Она особенно полезна для быстрого выявления новых, еще не размеченных физических дисков.

```bash
lsblk
```

Подробнее об использовании `lsblk` см. в разделе [Просмотр блочных устройств](../../FileSystems/partitions_and_filesystems.md#просмотр-блочных-устройств-lsblk).

### `df`: Анализ свободного пространства

Показывает использование дискового пространства на уровне файловых систем.

```bash
# Показать свободное место в человекочитаемом формате
df -h

# Показать использование inode
df -i

# Показать тип файловой системы каждой переменной
df -hT

# Исключить временные ФС (tmpfs, devtmpfs)
df -h -t ext4 -t xfs -t btrfs
```

**Поля вывода `df`:**

- **Filesystem:** Устройство или ФС
- **Size:** Общий размер
- **Used:** Занято
- **Avail:** Доступно (с учётом резерва root)
- **Use%:** Процент использования
- **Mounted on:** Точка монтирования

### `du`: Анализ занятого пространства

Подсчитывает, сколько места занимают конкретные файлы и директории.

```bash
# Узнать общий размер текущей директории
du -sh .

# Найти самые "тяжелые" директории внутри /var (на 1 уровень вглубь)
sudo du -h --max-depth=1 /var | sort -rh

# Не пересекать границы ФС
du -hx --max-depth=2 / | sort -rh | head -20

# Подсчёт количества файлов (inodes) по директориям
du --inodes -S / | sort -rh | head -20

# Показать размер всех файлов и директорий (включая файлы внутри)
du -a -h /path | sort -rh | head -20
```

**Интерактивный анализ:** `ncdu` (ncurses disk usage) — удобная консольная утилита для навигации по ФС и быстрого удаления файлов.
```bash
# Просканировать текущую директорию
ncdu

# Не пересекать границы ФС (быстрее и безопаснее)
ncdu -x /
```

**Основные флаги `du`:**

| Флаг | Описание |
| :--- | :--- |
| `-s` (summary) | Только общая сумма для указанной директории |
| `-h` (human-readable) | Человекочитаемый формат (K, M, G) |
| `-a` (all) | Показывать размер **всех файлов**, а не только директорий |
| `--max-depth=N` | Ограничить глубину рекурсии |
| `-x` (one-file-system) | Не пересекать границы файловых систем |
| `--inodes` | Считать inode, а не байты |

**Поля вывода `du --inodes`:**

- Количество inode — число файлов и директорий
- Помогает выявить источники исчерпания inode (кэши, сессии, логи)

### Сценарий: Очистка диска от работающего процесса (Go-бинар)

Ситуация: диск переполнен из-за работающего приложения (например, Go-бинаря), которое активно пишет логи или временные данные. Простое удаление файлов может не помочь, если процесс продолжает держать их открытыми.

**1. Поиск процесса и его файлов**
Если известно имя бинарного файла:
```bash
# 1. Находим PID
PID=$(pgrep -f "имя_бинаря")

# 2. Смотрим, какие файлы открыты процессом для записи (w) или чтения/записи (u)
sudo lsof -p $PID | grep -E ' (w|u) '

# 3. В реальном времени: какие файлы процесс открывает/пишет прямо сейчас
# Помогает, если процесс создает много мелких файлов
sudo strace -p $PID -e trace=openat,write,creat -s 80
```

**2. Анализ занимаемого места**
```bash
# Показать размеры открытых файлов для конкретного процесса
sudo lsof -p $PID -s | awk '$5 == "REG" {print $7, $9}' | sort -n

# Найти "тяжелые" директории рядом с местом запуска бинаря
du -h --max-depth=1 $(dirname $(readlink -f /proc/$PID/exe)) | sort -rh
```

**3. Безопасная очистка без остановки сервиса**
Если вы нашли огромный лог-файл, который нельзя просто удалить (`rm`), так как место не освободится:
```bash
# ОБНУЛЕНИЕ (truncate) — самый безопасный способ для логов
# Процесс продолжит писать в тот же файл, но с нулевого смещения.
> /var/log/app.log
# ИЛИ
truncate -s 0 /var/log/app.log

# Если файл уже УДАЛЕН (через rm), но место не освободилось:
# Используем магию /proc и номер дескриптора (FD) из lsof (например, 7w)
> /proc/$PID/fd/7
```

**Где еще искать в Go-приложениях:**
- `/tmp`: временные файлы (могут расти бесконтрольно при неправильной работе с `os.CreateTemp`).
- `GOCACHE`: если на ВМ случайно была запущена сборка или тесты.
- Встроенные БД: LevelDB, BoltDB, Badger (ищите файлы `.db`, `.log`, `.sst`).

#### Ситуация: На диске занято 50% места, а создать файл даже под root не получается. В чем проблема?

1. **Исчерпание Inodes:**
   - **Диагностика:** `df -i` покажет 100% использование
   - **Причина:** Множество мелких файлов (кэши, сессии, почта)
   - **Решение:** Очистка кэшей, миграция на XFS/Btrfs

2. **Зарезервированное пространство для `root`:**
   - **Описание:** Ext2/3/4 резервируют 5% места для root. При заполнении >95% даже root не может писать.
   - **Диагностика:** `df -h` показывает ~95-100% использования
   - **Аварийное решение:** Временно обнулить резерв:

     ```bash
     sudo tune2fs -m 0 /dev/sdXN
     ```

   - **После очистки:** Вернуть резерв:

     ```bash
     sudo tune2fs -m 5 /dev/sdXN
     ```

   - **Подробнее:** [Устранение нехватки места на диске](../../FileSystems/disk_space_troubleshooting.md)

3. **Удаленные, но открытые файлы:**
   - **Описание:** Процесс удалил файл, но держит его открытым — место не освобождается
   - **Диагностика:**

     ```bash
     # Найти удалённые, но открытые файлы
     lsof +L1 2>/dev/null

     # Или через /proc
     find /proc/*/fd -type l -lname '/path/to/deleted/file' 2>/dev/null
     ```

   - **Решение:** Перезапустить процесс или очистить файл без перезапуска:

     ```bash
     # Найти PID и FD (номер дескриптора) процесса
     lsof +L1
     # COMMAND  PID  USER  FD   TYPE  DEVICE  SIZE/OFF    NLINK  NODE   NAME
     # nginx   1234  www   7w   REG   8,1     2147483648  0      12345  /var/log/app.log (deleted)

     # Сигнал процессу для переоткрытия логов (если поддерживает SIGHUP)
     kill -HUP <PID>

     # Или перезапустить службу
     systemctl restart <service>

     # Освободить место БЕЗ перезапуска — обнулить через /proc
     > /proc/1234/fd/7
     ```

     **Как работает `/proc/<PID>/fd/<FD>`:** `procfs` — псевдофайловая система в памяти. Каталог `/proc/<PID>/fd/` содержит симлинки на все открытые дескрипторы процесса. Обращение через дескриптор обходит файловую систему, где файл уже «удалён». Ядро обнуляет блоки, `df` сразу показывает освободившееся место, процесс продолжает писать в тот же дескриптор.

   - **Мониторинг:**

     ```bash
     # Удалённые открытые файлы > 100 МБ
     lsof +L1 -F s | awk '/^s/ && substr($0,2)+0 > 104857600 {count++} END {print count+0}'
     ```

     Prometheus + node_exporter: метрика `node_filefd_allocated` — резкий рост при падении свободного места указывает на эту проблему.

   - **Предотвращение:** Настроить `copytruncate` в logrotate — [Ротация логов](../../SystemAdministration/Logging/logging_overview.md#ротация-логов-logrotate).

   - **Подробнее:** [lsof — диагностика открытых файлов](../Processes/lsof.md)
