# Диагностика ошибки "too many open files" в Linux

## 1. Определения

**Файловый дескриптор** — это уникальный идентификатор (обычно неотрицательное целое число), который процесс использует для доступа к открытому файлу, сокету или другому ресурсу ввода-вывода.

Ошибка "too many open files" возникает, когда процесс пытается открыть новый файловый дескриптор, но исчерпывает установленные для него лимиты.

## 2. Основные концепции

В Linux существуют "мягкие" (soft) и "жесткие" (hard) лимиты на количество открытых файлов:
-   **Soft limit:** Текущий действующий лимит для процесса. Любой процесс может увеличить свой soft limit до значения hard limit.
-   **Hard limit:** Максимально возможное значение для soft limit. Изменить hard limit может только процесс с правами суперпользователя (root).

Эти лимиты могут быть установлены на разных уровнях: для пользователя, для системы в целом или для конкретного сервиса (например, через systemd).

## 3. Практические сценарии диагностики

### Шаг 1: Проверка лимитов для конкретного процесса

Чтобы узнать лимиты для запущенного процесса, необходимо знать его PID.

```bash
grep "Max open files" /proc/<PID>/limits
```
*Замените `<PID>` на идентификатор вашего процесса.*

**Пример вывода:**
```
Max open files            8192                 65535                files
```
Здесь `8192` — это soft limit, а `65535` — hard limit.

### Шаг 2: Проверка лимитов для текущего пользователя

Этот способ позволяет увидеть лимиты, которые будут применяться к новым процессам, запущенным от вашего пользователя.

```bash
ulimit -n
```

### Шаг 3: Проверка лимитов на уровне systemd

Если ваше приложение запускается как сервис через `systemd`, лимиты могут быть определены в его конфигурационном файле.

**Путь к файлу:** `/etc/systemd/system/<service_name>.service` или `/lib/systemd/system/<service_name>.service`.

Найдите секцию `[Service]` и параметр `LimitNOFILE`:

```ini
[Service]
LimitNOFILE=10000
```

### Шаг 4: Проверка системных лимитов

Глобальные лимиты для пользователей часто определяются в файле `/etc/security/limits.conf`.

**Пример содержимого:**
```
#<domain>      <type>  <item>         <value>
*           hard    nofile     65535
*           soft    nofile      8192
```
Здесь `*` означает "для всех пользователей".

### Шаг 5: Подсчет открытых файлов процессом

Команда `lsof` (List Open Files) позволяет увидеть, какие именно файлы и сокеты открыты процессом в данный момент.

```bash
# Посчитать количество открытых файлов
lsof -p <PID> | wc -l

# Посмотреть список открытых файлов
lsof -p <PID>
```

## 4. Расширенная диагностика

### Использование strace для отслеживания системных вызовов

Если есть подозрение, что приложение открывает файлы и не закрывает их (утечка файловых дескрипторов), можно использовать `strace` для отслеживания системных вызовов `open`, `openat` и `close`.

```bash
strace -e trace=open,openat,close -p <PID>
```
Это позволит в реальном времени видеть, какие файлы открываются и закрываются процессом, и выявить аномалии.
