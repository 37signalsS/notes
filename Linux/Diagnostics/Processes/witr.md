# Утилита `witr`

## Определения

**`witr`** (Why Is That Running) — современная диагностическая утилита с открытым исходным кодом, написанная на Rust, предназначенная для быстрого выяснения причин запуска процессов в Linux. Она агрегирует данные из различных подсистем ядра и пространства пользователя, предоставляя единый отчет о «генеалогии» процесса, его сетевой активности и потенциальных рисках.

Утилита особенно эффективна в ситуациях, когда в системе обнаружен незнакомый процесс, и требуется мгновенно восстановить цепочку его запуска (запущен ли он интерактивно через SSH, является ли частью системного сервиса `systemd` или запущен планировщиком `cron`).

## Основные концепции

### Источники информации и механизмы

`witr` работает как интеллектуальный агрегатор, собирая данные из:
- **`procfs`** (`/proc`): считывает атрибуты процесса (стартовое время, рабочий каталог, переменные окружения, UID/GID) и его иерархию (PPID).
- **`cgroups` и `systemd`**: сопоставляет PID с контрольными группами через `/proc/[PID]/cgroup`. Это позволяет точно определить принадлежность процесса к `systemd`-юниту (service, scope, slice) или сессии пользователя.
- **Сетевой стек**: анализирует `/proc/net/` (аналог [`ss`](../Networking/ss.md)) для поиска прослушиваемых портов и активных соединений, привязанных к процессу.

### Анализ цепочки запуска (Lineage)

В отличие от стандартного `pstree`, `witr` фокусируется на **логической ответственности**. Она прослеживает цепочку до PID 1 (обычно `systemd`) или лидера сессии, помогая отличить:
- **Интерактивные процессы**: цепочка ведет к `sshd` или эмулятору терминала.
- **Системные службы**: процесс находится внутри `.service` юнита.
- **Периферийные задачи**: дочерние процессы других приложений (например, воркеры Nginx или PHP-FPM).

### Автоматический аудит контекста

Утилита помечает потенциально аномальные характеристики процесса:
- **Public Listening**: процесс открыл сокет на `0.0.0.0` или `::`, что делает его доступным извне.
- **Root execution**: выполнение от суперпользователя (риск эскалации при компрометации).
- **Suspicious Path**: запуск из путей, часто используемых вредоносным ПО для обхода проверок (`/tmp`, `/dev/shm`, `/var/tmp`).

## Практические сценарии

### Установка

Утилита устанавливается через пакетный менеджер Rust.

```bash
# Установка через cargo
cargo install witr

# Принудительное обновление
cargo install --force witr
```

Репозиторий проекта: [github.com/pranshuparmar/witr](https://github.com/pranshuparmar/witr)

### Базовая диагностика процесса

```bash
# Анализ процесса по имени
witr nginx

# Анализ конкретного PID
witr --pid 1234
```

**Пример интерпретации отчета:**
```text
Target: /usr/bin/python3 (PID: 2100)
Why: Запущен пользователем 'admin' внутри SSH-сессии (sshd.service).
Listening: *:8080 (TCP)
Warnings:
  - Процесс слушает внешние интерфейсы (0.0.0.0).
  - Процесс запущен с правами Root.
```

### Поиск виновника занятого порта

Если необходимо быстро понять, какое приложение заняло порт и зачем оно запущено:

```bash
# Поиск по порту с полным контекстом запуска
witr --port 8080
```

### Расследование инцидентов (Incident Response)

Если в `top` обнаружен подозрительный процесс с высокой нагрузкой:
1. Выполните `witr --pid <PID>`.
2. Проверьте поле **Why It Exists**. 
3. Если цепочка обрывается на `sshd` неизвестного пользователя — это признак взлома сессии.
4. Если процесс запущен из `/tmp`, изучите его окружение (клавиша `e` в `htop` или просмотр `/proc/[PID]/environ`).

## Дополнительная информация

### Сравнение с классическими инструментами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **`witr`** | **Агрегированный отчет (Сеть + cgroups + Lineage) за один вызов.** | Требует установки Rust; не во всех дистрибутивах есть «из коробки». |
| [`ps auxf`](./ps.md) | Стандарт, визуальное дерево. | Нет информации о портах и четкой привязки к systemd. |
| [`lsof -i`](./lsof.md) | Глубокий аудит дескрипторов. | Громоздкий вывод, нет данных о происхождении процесса. |
| `pstree` | Легкость, визуализация иерархии. | Нет метаданных (порты, юниты, риски). |

### Ограничения

- **Зависимость от метаданных ядра**: Если процесс использует техники маскировки (например, подмена `argv` или запуск через `memfd_create`), `witr` может отображать неполные данные.
- **Требования к привилегиям**: Для доступа к сетевой информации других пользователей и данным `/proc` требуется `sudo`.
