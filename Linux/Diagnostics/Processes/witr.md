# Утилита `witr`

## Определения

**`witr`** (Why Is That Running) — современная диагностическая утилита с открытым исходным кодом, написанная на Rust, предназначенная для быстрого выяснения причин запуска процессов в Linux. Она агрегирует данные из различных подсистем ядра и пространства пользователя, предоставляя единый отчет о «генеалогии» процесса, его сетевой активности и потенциальных рисках.

Утилита полезна в ситуациях, когда в системе обнаружен подозрительный или незнакомый процесс, и требуется мгновенно понять его происхождение (запущен ли он вручную, через `systemd`, `cron` или является дочерним процессом другого приложения).

## Основные концепции

### Источники информации

`witr` работает как интеллектуальный агрегатор, собирая данные из:
- **`procfs`** (`/proc`): время старта, рабочая директория, переменные окружения, UID/GID.
- **`systemd`**: сопоставление PID с конкретными юнитами (services, scopes, slices).
- **Сетевой стек** (аналог [`ss`](../Networking/ss.md)): информация о прослушиваемых портах и установленных соединениях.

### Анализ цепочки запуска (Lineage)

В отличие от стандартного `pstree`, `witr` не просто показывает дерево, а анализирует логическую цепочку ответственности.
Пример вывода цепочки:
`systemd (1) → sshd (1200) → bash (1540) → python3 (2100)`
Это позволяет сразу отличить фоновый сервис от интерактивной сессии пользователя.

### Автоматический аудит безопасности

Утилита проводит базовый анализ контекста процесса и помечает потенциальные угрозы:
- **Public Listening**: процесс слушает порт на внешнем интерфейсе (`0.0.0.0`), что может быть опасно без защиты.
- **Root execution**: процесс запущен от имени суперпользователя без явной необходимости.
- **Suspicious Path**: процесс запущен из временных директорий (`/tmp`, `/dev/shm`) или корня (`/`).

## Практические сценарии

### Установка

Утилита распространяется через пакетный менеджер Rust.

```bash
# Установка через cargo (рекомендуется)
cargo install witr

# Обновление до последней версии
cargo install --force witr
```

Репозиторий проекта: [github.com/pranshuparmar/witr](https://github.com/pranshuparmar/witr)

### Базовая диагностика процесса

```bash
# Анализ процесса по имени (интерактивный выбор при наличии дублей)
witr nginx

# Анализ конкретного PID
witr --pid 1234
```

**Пример интерпретации отчета:**
```text
Target: /usr/bin/python3 (PID: 2100)
Why: Запущен пользователем 'admin' через интерактивную сессию SSH.
Listening: *:8080 (TCP)
Warnings:
  - Процесс слушает внешние интерфейсы.
  - Исполняемый файл не имеет подписи (если применимо).
```

### Поиск «владельца» порта

Если порт занят и стандартный `lsof` выдает слишком много шума:

```bash
# Найти процесс, занимающий порт, с полным контекстом его запуска
witr --port 8080
```

### Расследование инцидентов

Если в `top` замечен странный процесс с высокой нагрузкой:
1. Выполните `witr --pid <PID>`.
2. Посмотрите на поле **Why It Exists**.
3. Если процесс является дочерним для `kworker` или `systemd-journald`, это может указывать на системную активность. Если он запущен из `/tmp` через `curl | bash`, это явный признак компрометации.

## Дополнительная информация

### Сравнение с классическими инструментами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **`witr`** | **Комплексный отчет (Сеть + systemd + Дерево) в одном окне.** | Требует установки Rust/Cargo. |
| [`ps auxf`](./ps.md) | Доступен везде по умолчанию. | Нужно вручную искать связи и порты. |
| [`lsof -i`](./lsof.md) | Детальная работа с дескрипторами. | Сложный для быстрого визуального анализа вывод. |
| `pstree` | Очень легкий, наглядное дерево. | Не дает контекста (кто запустил, какие порты). |

### Ограничения

- **Зависимость от systemd**: Наилучшие результаты (определение сервисов) достигаются в системах с `systemd`.
- **Права доступа**: Для анализа процессов, запущенных другими пользователями, требуется `sudo`.
