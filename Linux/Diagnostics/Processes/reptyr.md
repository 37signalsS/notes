# Утилита `reptyr`

## Определения

**`reptyr`** — специализированная утилита интерфейса командной строки (CLI — Command Line Interface), предназначенная для перехвата запущенного процесса из одной терминальной сессии и его переноса в другую без остановки выполнения.

## Основные концепции

### Назначение инструмента

Типичный сценарий использования возникает, когда длительный процесс (сборка программного обеспечения, миграция базы данных или передача файлов) был запущен в обычной сессии Secure Shell (SSH) без использования терминальных мультиплексоров (`tmux` или `screen`). При разрыве сетевого соединения такой процесс получит сигнал `SIGHUP` и принудительно завершится. `reptyr` позволяет «спасти» выполнение, переместив процесс в стабильную сессию мультиплексора.

### Принцип работы

Утилита использует системный вызов `ptrace` для временной приостановки целевого процесса. В этот момент `reptyr` выполняет перехват файловых дескрипторов, связанных со стандартными потоками ввода-вывода (stdin, stdout, stderr), и перенаправляет их на управляющий терминал новой сессии. Для ядра Linux этот процесс выглядит как смена управляющего терминала (controlling terminal) процесса.

### Требования и безопасность

Для корректной работы требуются права суперпользователя (root) или специфические настройки ядра. В современных дистрибутивах Linux возможность использования `ptrace` для процессов, не являющихся дочерними, ограничена механизмом **Yama LSM** (параметр `ptrace_scope`) в целях безопасности.

**Временное разрешение перехвата:**

```bash
echo 0 | sudo tee /proc/sys/kernel/yama/ptrace_scope
```

**Перманентная настройка:**
Отредактируйте файл `/etc/sysctl.d/10-ptrace.conf` (или создайте новый):
```text
kernel.yama.ptrace_scope = 0
```
И примените изменения: `sudo sysctl -p /etc/sysctl.d/10-ptrace.conf`.

Подробнее об ограничениях: [Защита среды выполнения ядра](../Security/Fstec/kernel_runtime_protection.md#уровни-ограничений-ptrace_scope).

**Установка:**

```bash
# Debian/Ubuntu
sudo apt install reptyr

# RHEL/CentOS/Fedora
sudo dnf install reptyr
```

## Практические сценарии

### Перенос работающего процесса в tmux

Рассмотрим пример переноса утилиты `top` из обычного терминала в сессию `tmux`.

1. **Приостановка процесса**: Нажмите `Ctrl+Z` в текущем терминале.
2. **Перевод в фоновый режим**:

   ```bash
   bg
   ```

3. **Определение идентификатора процесса (PID — Process Identifier)**:

   ```bash
   jobs -l
   # [1]+  7972 Stopped (signal)     top
   ```

4. **Отвязка от текущей оболочки (Shell)**:
   Это необходимо, чтобы старая оболочка не пыталась управлять процессом или закрыть его при выходе.

   ```bash
   disown top
   ```

5. **Запуск и подключение**: Войдите в новую сессию (например, `tmux`) и выполните перехват по PID:

   ```bash
   reptyr 7972
   ```

### Перехват процесса другого пользователя

Если процесс запущен другим пользователем, `reptyr` должен запускаться через `sudo`:

```bash
sudo reptyr <PID>
```
**Важно:** Процесс унаследует переменные окружения и права исходного владельца, но его управляющим терминалом станет ваш текущий терминал.

## Дополнительная информация

### Ограничения и особенности

- **Сложные интерфейсы (TUI)**: Программы, использующие сложные библиотеки отрисовки (например, специфичные версии `ncurses`), могут некорректно восстанавливать интерфейс. В таких случаях часто помогает принудительная перерисовка экрана (обычно `Ctrl+L`).
- **Специфические дескрипторы**: `reptyr` перехватывает основные дескрипторы (0, 1, 2). Если процесс использует дополнительные файловые дескрипторы для общения с исходным терминалом, они могут быть потеряны.
- **Setuid-программы**: Перехват процессов с установленным битом `setuid` (например, запущенных через `sudo` программ) может быть запрещен ядром даже при `ptrace_scope = 0`.
- **Зомби и фоновые процессы**: `reptyr` не может перехватить процесс, который уже стал зомби или находится в процессе завершения.

### Сравнение с альтернативами

| Метод | Когда использовать | Плюсы | Минусы |
| :--- | :--- | :--- | :--- |
| **`reptyr`** | Процесс уже запущен без мультиплексора. | Позволяет «спасти» процесс без перезапуска. | Требует настройки `ptrace`, не всегда стабилен с TUI. |
| **`nohup`** | До запуска процесса. | Простота, гарантированное игнорирование `SIGHUP`. | Весь вывод идет в файл, нет интерактивности. |
| **`disown`** | Процесс уже запущен, но связь еще есть. | Отвязывает процесс от Shell. | Не дает возможности перехватить ввод-вывод. |
