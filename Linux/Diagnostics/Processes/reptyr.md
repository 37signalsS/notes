# reptyr — перенос процесса в новый терминал

## Определения

**reptyr** — утилита командной строки, предназначенная для перехвата запущенного процесса из одной терминальной сессии и переноса его в другую.

---

## Базовые концепции

### Зачем это нужно

Часто случается ситуация, когда тяжелый или длительный процесс (сборка проекта, перенос файлов, дамп базы данных, проверка размера огромной директории) запущен в обычной SSH-сессии без использования мультиплексоров (`tmux`, `screen`). Если соединение разорвется, процесс получит сигнал SIGHUP и завершится. `reptyr` позволяет спасти такой процесс, переместив его внутрь стабильной сессии `tmux` или `screen`.

### Принцип работы

`reptyr` использует системный вызов `ptrace` для присоединения к работающему процессу, перехвата его файловых дескрипторов, связанных с терминалом (stdin, stdout, stderr), и перенаправления их на новый управляющий терминал.

### Требования и установка

Утилита обычно доступна в стандартных репозиториях:

```bash
sudo apt install reptyr
```

Для работы `reptyr` требуется возможность использовать `ptrace` на процессах, не являющихся дочерними. В современных дистрибутивах это может быть ограничено параметром `yama ptrace_scope`.

Чтобы временно разрешить перехват:

```bash
echo 0 | sudo tee /proc/sys/kernel/yama/ptrace_scope
```

## Практические сценарии

### Перенос процесса в tmux (на примере top)

Рассмотрим ситуацию, когда процесс `top` запущен в обычном терминале и его нужно перенести в `tmux`.

1. **Запуск процесса**:

   ```bash
   top
   ```

2. **Приостановка процесса**: Нажмите `Ctrl+Z` в терминале с процессом.

3. **Отправка в фон**:

   ```bash
   bg
   ```

4. **Проверка состояния и PID**:

   ```bash
   jobs -l
   # [1]+  7972 Stopped (signal)     top
   ```

   Здесь `7972` — это PID процесса.

5. **Отвязка от текущей сессии**:

   ```bash
   disown top
   ```

6. **Подключение в новой сессии**:
   Запустите `tmux` (или `screen`), войдите в него и выполните:

   ```bash
   reptyr 7972
   ```

После этого интерфейс `top` появится в окне `tmux`.

## Дополнительная информация

### Ограничения

- **Сложные интерфейсы**: Программы с очень активной или специфической псевдографикой (например, `opencode`) могут зависнуть при переносе — интерфейс может не появиться.
- **Стабильность**: Простые консольные утилиты и классические TUI-программы (например, `mc` — Midnight Commander) обычно переносятся без проблем.
- **Права доступа**: Перенос процессов других пользователей требует прав `root`.
