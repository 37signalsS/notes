# Утилита `htop`

## Определения

**`htop`** — интерактивный системный монитор процессов с текстовым интерфейсом (TUI), являющийся современной и расширенной альтернативой классической утилите [`top`](./top.md). 

**Ключевые преимущества:**
- **Наглядность:** Графические шкалы и цветовая кодировка ресурсов.
- **Интерактивность:** Поддержка прокрутки (вертикальной и горизонтальной) и управления мышью.
- **Функциональность:** Управление сигналами, приоритетами (nice/ionice), просмотр файлов и переменных окружения без выхода из программы.

## Основные концепции

### Структура интерфейса

`htop` получает данные из `/proc` (на Linux), агрегируя информацию о CPU, памяти, Swap и процессах.

#### Верхняя панель (Индикаторы)
Отображает текущую нагрузку на систему. Цветовая легенда (по умолчанию):

- **ЦП (CPU)**:
  - **Синий**: процессы с низким приоритетом (`nice > 0`).
  - **Зеленый**: пользовательские процессы.
  - **Красный**: системные процессы (ядро).
  - **Оранжевый**: время ожидания ввода-вывода (IO wait).
  - **Аквамариновый**: виртуализация (Steal time).
- **Память (Mem)**:
  - **Зеленый**: занято процессами.
  - **Синий**: буферы.
  - **Желтый/Оранжевый**: кэш страниц.

> **Совет:** В современных версиях (3.0+) доступны метрики **PSI** (Pressure Stall Information), показывающие давление на CPU, RAM и I/O. Настройка через `F2` -> `Meters`.

#### Список процессов
Таблица содержит стандартные поля (`PID`, `USER`, `RES`, `CPU%` и др.). В отличие от `top`, `htop` позволяет прокручивать список вправо, чтобы увидеть полную командную строку (`COMMAND`).

## Практические сценарии

### Основные режимы запуска

```bash
# Базовый запуск
htop

# Запуск с фильтром по пользователю
htop -u admin

# Режим отображения только конкретных PID
htop -p 1234,5678

# Сортировка по памяти при старте
htop -s PERCENT_MEM
```

### Интерактивные команды (Горячие клавиши)

#### Управление видом и навигация
| Клавиша | Действие |
| :--- | :--- |
| **`F5`** / **`t`** | Переключение в древовидный режим (Tree view) — иерархия родитель/потомок. |
| **`H`** / **`K`** | Скрыть/показать пользовательские потоки и потоки ядра. |
| **`F2`** / **`S`** | Меню настроек (Setup): цвета, столбцы, индикаторы, экраны. |
| **`F10`** / **`q`** | Выход. |

#### Поиск и фильтрация
| Клавиша | Действие |
| :--- | :--- |
| **`F3`** / **`/`** | Поиск процесса (переход к следующему совпадению). |
| **`F4`** / **`\`** | **Интерактивный фильтр**: скрывает все процессы, не подходящие под шаблон. |
| **`u`** | Выбор процессов конкретного пользователя. |

#### Управление и аудит процесса
| Клавиша | Действие |
| :--- | :--- |
| **`F9`** / **`k`** | Отправить сигнал (Kill menu). По умолчанию `SIGTERM`. |
| **`F7`** / **`F8`** | Изменение приоритета (`nice`). Требует root для повышения приоритета. |
| **`i`** | Изменение приоритета ввода-вывода (**ionice**). |
| **`e`** | Показать **переменные окружения** процесса. |
| **`l`** | Список открытых файлов через [`lsof`](./lsof.md). |
| **`s`** | Трассировка системных вызовов через `strace`. |
| **`a`** | Установка **CPU Affinity** (привязка процесса к конкретным ядрам). |

### Диагностика производительности

#### Анализ многопоточных приложений
Если процесс (например, Java или Go) потребляет 400% CPU, нажмите **`H`**, чтобы увидеть детализацию по каждому потоку. Это поможет найти конкретный поток-виновник. Подробнее: [Поиск проблемного потока](./thread_cpu_troubleshooting.md).

#### Проверка блокировок на I/O
В списке процессов столбец `S` (Status) со значением **`D`** указывает на непрерываемый сон. Если таких процессов много, проверьте индикатор `IO wait` в верхней панели.

## Дополнительная информация

### Новое в htop 3.x
- **Поддержка вкладок (Screens)**: Возможность настроить разные наборы столбцов и индикаторов на отдельных экранах (`F2` -> `Screens`).
- **Счетчики GPU**: Поддержка мониторинга NVIDIA/AMD (требует соответствующей сборки пакета).
- **Индикаторы давления (PSI)**: Визуализация `some` и `full` задержек ресурсов.

### Сравнение с аналогами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| [`top`](./top.md) | Всегда в системе, стандарт POSIX. | Меньшая наглядность, сложнее навигация. |
| [`atop`](../Performance/atop.md) | Исторические логи, детальный I/O. | Сложный интерфейс. |
| **`btop`** | Исключительная визуализация, графики. | Выше потребление ресурсов самой утилиты. |
| [`syswatch`](../Performance/syswatch.md) | Timeline и автоматические подсказки (Insights). | Необходимость отдельной установки. |

### Ограничения
- **Статичность истории**: `htop` не умеет показывать, что происходило 5 минут назад. Для этого используйте `atop` или `sar`.
- **Оверхед**: На системах с огромным количеством ядер (256+) и процессов обновление `htop` может само потреблять до 5-10% одного ядра.
