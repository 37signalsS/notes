# Утилита `htop`

## Определения

**`htop`** — интерактивный монитор процессов с текстовым пользовательским интерфейсом (TUI — Text User Interface), расширенная альтернатива классической утилите [`top`](./top.md). Предоставляет возможность горизонтальной и вертикальной прокрутки списка, полное отображение командных строк и интуитивно понятное управление сигналами процессов через функциональные клавиши.

**Ключевые особенности:**

- Наглядная визуализация загрузки центрального процессора (CPU — Central Processing Unit) по ядрам.
- Поддержка управления с помощью мыши.
- Возможность древовидного отображения иерархии процессов.
- Удобная фильтрация и поиск.

## Основные концепции

### Архитектура и интерфейс

`htop` получает данные из виртуальной файловой системы `/proc`, аналогично утилитам [`top`](./top.md) и [`ps`](./ps.md), но предлагает более современную визуализацию системных метрик.

**Верхняя панель (Индикаторы):**
В верхней части экрана отображаются графические шкалы использования ресурсов:

- **CPU**: загрузка каждого ядра с цветовой кодировкой (пользовательские процессы, системные вызовы, приоритетные задачи, ожидание ввода-вывода).
- **Mem**: использование оперативной памяти (RAM — Random Access Memory) с разбивкой на используемую, буферы и кэш.
- **Swp**: использование пространства подкачки (Swap).

### Столбцы таблицы процессов

| Столбец | Описание |
| :--- | :--- |
| `PID` | Идентификатор процесса (Process Identifier) |
| `USER` | Имя пользователя-владельца процесса |
| `PRI` | Приоритет планировщика ядра |
| `NI` | Значение nice (пользовательский приоритет от -20 до +19) |
| `VIRT` | Общий объем виртуальной памяти — см. [метрики памяти](../../Core/memory/process_memory_metrics.md) |
| `RES` | Резидентная память (RSS) — фактически занятый объем в RAM |
| `SHR` | Объем разделяемой памяти |
| `CPU%` | Процент использования мощностей CPU |
| `MEM%` | Процент использования физической памяти RAM |
| `TIME+` | Суммарное процессорное время, затраченное процессом |
| `COMMAND` | Полная командная строка запуска процесса |

## Практические сценарии

### Основные способы запуска

```bash
# Базовый запуск в интерактивном режиме
htop

# Запуск с правами суперпользователя (root) для управления всеми процессами
sudo htop

# Мониторинг конкретного пользователя
htop -u username

# Запуск с сортировкой по потреблению памяти
htop --sort-key=PERCENT_MEM
```

### Интерактивное управление

#### Работа с отображением и навигация

| Клавиша | Действие |
| :--- | :--- |
| `F5` / `t` | Переключить режим отображения в виде дерева (Tree view) |
| `F2` / `S` | Открыть меню настроек интерфейса (Setup) |
| `F1` / `h` | Вызов справки по горячим клавишам |
| `F10` / `q` | Выход из программы |
| `1` | Переключение между режимами отображения CPU (агрегированный/по ядрам) |
| `H` | Скрыть/показать пользовательские потоки (Threads) |
| `K` | Скрыть/показать потоки ядра |

#### Фильтрация, поиск и сортировка

| Клавиша | Действие |
| :--- | :--- |
| `F3` / `/` | Поиск процесса по части имени |
| `F4` / `\` | Интерактивный фильтр (скрыть процессы, не соответствующие шаблону) |
| `F6` / `>` | Выбор столбца для сортировки |
| `u` | Выбор процессов конкретного пользователя из списка |

#### Управление процессами

| Клавиша | Действие |
| :--- | :--- |
| `F9` / `k` | Отправить сигнал процессу (по умолчанию SIGTERM) |
| `F7` / `[` | Увеличить приоритет процесса (уменьшить nice) — требует прав root |
| `F8` / `]` | Уменьшить приоритет процесса (увеличить nice) |
| `l` | Просмотреть список открытых процессом файлов через [`lsof`](./lsof.md) |
| `s` | Трассировка системных вызовов процесса через `strace` |
| `a` | Привязка процесса к конкретным ядрам CPU (CPU Affinity) |

### Диагностика системных проблем

#### Идентификация утечек памяти

1. Запустите `htop`.
2. Нажмите `F6` и выберите сортировку по столбцу `MEM%`.
3. Отслеживайте процессы с аномально высоким или постоянно растущим значением `RES`.
4. Для детального анализа приватной памяти используйте утилиту [`smem`](../Memory/smem.md).

#### Анализ зависших процессов

Если система медленно реагирует, проверьте колонку `S` (Status):

- Процессы в состоянии **D** (Uninterruptible Sleep) ожидают завершения операций ввода-вывода (I/O — Input/Output).
- Процессы в состоянии **Z** (Zombie) завершены, но ожидают подтверждения от родительского процесса. Подробнее: [основные концепции процессов](../../Core/processes/basic_concepts.md).

## Дополнительная информация

### Конфигурация

Параметры программы сохраняются в файле `~/.config/htop/htoprc`. Рекомендуется настраивать интерфейс через встроенное меню `F2`:

- **Meters**: выбор и размещение индикаторов в заголовке.
- **Display options**: настройка графических параметров, индикация потоков и цветов.
- **Columns**: добавление или удаление столбцов таблицы.

### Сравнение с аналогичными инструментами

| Инструмент | Преимущества | Недостатки | Сценарий использования |
| :--- | :--- | :--- | :--- |
| [`top`](./top.md) | Стандарт POSIX, доступен везде | Ограниченная навигация | Минимальные серверные окружения |
| [`atop`](../Performance/atop.md) | Ведение исторических логов | Высокий порог освоения | Ретроспективный анализ инцидентов |
| [`syswatch`](../Performance/syswatch.md) | Аналитика и Timeline сессии | Требует установки Go | Быстрый поиск причин аномалий |
| [`ps`](./ps.md) | Точные статические снимки | Не подходит для мониторинга | Скрипты и разовые проверки |
| `btop` | Современная визуализация | Требует больше ресурсов | Персональные рабочие станции |

### Ограничения

- **Необходимость установки**: часто отсутствует в стандартном наборе минимальных образов операционных систем.
- **Потребление ресурсов**: при большом количестве ядер и процессов сам `htop` может создавать заметную нагрузку на CPU.
- **Отсутствие истории**: показывает только текущее состояние ресурсов. Для анализа прошлых событий используйте [`sar`](../Performance/sar.md) или [`syswatch`](../Performance/syswatch.md).
