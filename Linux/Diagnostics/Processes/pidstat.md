# Утилита `pidstat`

## Определения

**`pidstat`** — специализированная системная утилита, входящая в пакет `sysstat`, предназначенная для мониторинга использования ресурсов отдельными процессами в операционной системе Linux. В отличие от [`top`](./top.md), которая ориентирована на общую картину системы, `pidstat` фокусируется на детализированной статистике конкретных идентификаторов процессов (PID — Process Identifier).

Утилита позволяет получать отчеты по нагрузке на центральный процессор (CPU), использованию оперативной памяти (RAM), операциям ввода-вывода (I/O), переключениям контекста и ресурсам ядра в реальном времени или за заданный интервал.

**Ключевые особенности:**
- **Фокус на PID:** Идеальна для глубокого анализа конкретного приложения.
- **Интервальная статистика:** Возможность сбора данных с накоплением (историческая статистика за период), что позволяет видеть динамику, а не мгновенный снимок.
- **Детекция «фантомов»:** Эффективное обнаружение короткоживущих процессов за счет настройки высокой частоты опроса.
- **Детализация до потоков:** Поддержка анализа на уровне отдельных потоков выполнения (Threads/LWP).

### Внутренний механизм сбора данных

`pidstat` является частью пакета `sysstat` и использует два основных источника данных ядра:

1. **`/proc/<pid>/stat` и `/proc/<pid>/status`** — чтение мгновенных счетчиков процесса (время CPU, память, количество потоков).
2. **Ядерный аккаунтинг (`taskstats`)** — начиная с ядер 2.6.x, Linux предоставляет структуру `taskstats` через netlink-сокет, что позволяет получать детальную статистику (включая I/O и переключения контекста) без парсинга `/proc`. `pidstat` использует этот механизм для метрик `-d` и `-w`.
3. **`/proc/<pid>/io`** — для точного учета байтов, прочитанных/записанных процессом (включая кэшированные операции).

Важно: между сэмплами `pidstat` вычисляет дельту (разницу) счетчиков и делит на интервал, поэтому результат — это усредненная скорость за период, а не мгновенное значение.

## Основные концепции

### Сравнение с инструментами мониторинга

| Инструмент | Назначение | Интерактивность | История (интервалы) |
| :--- | :--- | :--- | :--- |
| [`top`](./top.md) | Общий обзор состояния системы. | Высокая | Нет |
| [`htop`](./htop.md) | Удобный визуальный мониторинг. | Высокая | Нет |
| [`ps`](./ps.md) | Статический снимок состояния. | Нет | Нет |
| **`pidstat`** | **Детальная статистика по ресурсам процессов.** | **Низкая** | **Да** |
| [`sar`](../Performance/sar.md) | Историческая статистика по всей системе. | Нет | Да |
| [`atop`](../Performance/atop.md) | Комплексный аудит ресурсов и процессов. | Высокая | Да |

### Режимы сбора данных

`pidstat` поддерживает три основных режима работы:
1. **Суммарный отчет:** `pidstat -u` — отображает среднюю статистику с момента загрузки (uptime) системы.
2. **Непрерывное наблюдение:** `pidstat -u 1` — выводит обновляемые данные каждую секунду.
3. **Фиксированная серия:** `pidstat -u 2 10` — выполняет 10 замеров с интервалом в 2 секунды, в конце выводит усредненный результат.

### Ключевые группы метрик

#### Центральный процессор (-u)
- **`%usr`**: время выполнения кода в пространстве пользователя (Userspace).
- **`%system`**: время на системные вызовы в пространстве ядра (Kernelspace).
- **`%guest`**: время, затраченное на работу виртуальных машин (Guest OS).
- **`%CPU`**: суммарный процент использования ресурсов CPU всеми ядрами.
- **`%wait`**: время, которое процесс провел в ожидании доступного CPU (в очереди runqueue). Высокое значение указывает на нехватку вычислительных ресурсов или throttle через cgroup.

#### Ввод-вывод (-d)
Отображает активность дисковой подсистемы:
- **`kB_rd/s`**: объем данных, прочитанных с диска (КБ/сек).
- **`kB_wr/s`**: объем данных, записанных на диск.
- **`kB_ccwr/s`**: объем данных, запись которых была отменена (например, удаление временного файла до сброса на диск).
- **`iodelay`**: задержка процесса в ожидании завершения операций I/O (в тактах процессора). Высокий показатель — признак перегрузки дисковой подсистемы.

**Важно:** `pidstat -d` учитывает только файловый I/O через VFS. Скрытые операции (writeback ядра, swap, `io_uring`) могут не отражаться. Для полной картины используйте [`iotop`](../Filesystem/iotop.md) и [PSI](../../Core/kernel/psi.md).

#### Оперативная память (-r)
- **`minflt/s`**: малые ошибки страниц (minor faults) в секунду (страница найдена в кеше RAM).
- **`majflt/s`**: серьезные ошибки страниц (major faults), требующие обращения к диску или swap. Рост этого показателя — критический признак нехватки RAM.
- **`VSZ`**: объем выделенной виртуальной памяти (КБ).
- **`RSS`**: резидентная память — сколько физической RAM процесс занимает на самом деле.

**Примечание:** Для точного анализа разделяемой памяти используйте PSS/USS через [`smem`](../../Diagnostics/Memory/smem.md) или [`pmap`](../../Diagnostics/Memory/pmap.md). RSS может переоценивать потребление из-за разделяемых библиотек.

#### Переключение контекста (-w)
- **`cswch/s`**: добровольные переключения (voluntary) — процесс сам отдает CPU (ожидание I/O, сокета).
- **`nvcswch/s`**: принудительные переключения (non-voluntary) — ядро прерывает процесс (исчерпание кванта времени, высокая конкуренция).

#### Ресурсы ядра (-v)
- **`threads`**: количество активных потоков.
- **`fd-nr`**: количество открытых файловых дескрипторов.

## Практические сценарии

### Мониторинг нагрузки на CPU

```bash
# Текущая загрузка CPU всеми активными процессами
pidstat -u 1

# Наблюдение за конкретным PID (например, 1234)
pidstat -p 1234 1

# Фильтрация по имени процесса с полной командной строкой
pidstat -u -C "nginx" -l 1

# Мониторинг всех процессов с детализацией по потокам (-t)
pidstat -u -t 1 5

# Топ-5 процессов по среднему удельному CPU за интервал
pidstat -u 1 1 | sort -k4 -nr | head -n 6
```

Детальный разбор анализа потоков см. в [Поиск потока, потребляющего CPU внутри процесса](./thread_cpu_troubleshooting.md).

### Диагностика дисковой активности

```bash
# Поиск «виновника» высокой I/O нагрузки
pidstat -d 1

# Детализация I/O до уровня потоков (актуально для баз данных)
pidstat -d -t -p 1234 1
```

**Интерпретация:**
- Высокие значения `kB_wr/s` часто указывают на работу БД, систем логирования или бэкапов.
- Высокий `iodelay` означает, что процесс «замирает», ожидая ответа от диска.

**Важно:** `pidstat -d` не учитывает writeback ядра и `io_uring`. Для скрытого I/O см. [Невидимый ввод-вывод](../../Diagnostics/Performance/DiskIO/invisible_io.md).

### Выявление утечек памяти

```bash
# Мониторинг параметров памяти с интервалом 5 секунд
pidstat -r 5

# Идентификация процесса с постоянным ростом RSS и VSZ
pidstat -r -p 1234 5
```

Для глубокого анализа сегментов памяти (PSS, USS, heap vs file-backed) используйте [Метрики потребления памяти процесса](../../Core/memory/process_memory_metrics.md).

### Анализ многопоточных приложений (Java, Go)

```bash
# Показать статистику по всем потокам (LWP) конкретного процесса
pidstat -t -p 1234 1
```

Для сопоставления TID с Java-потоками (`nid`) и расширенного профилирования см. [Поиск потока, потребляющего CPU внутри процесса](./thread_cpu_troubleshooting.md).

### Экспорт и фоновое логирование

```bash
# Сохранение данных в формате CSV для импорта в таблицы (Excel/Pandas)
pidstat -u 1 -o - > report.csv

# Фоновое логирование комплексной статистики (CPU, RAM, I/O)
nohup pidstat -urd 10 > pidstat_debug.log &
```

### Мониторинг переключений контекста (Context Switches)

```bash
# Выявление процессов с высокой конкуренцией за CPU
pidstat -w 1

# Корреляция с vmstat: если cs > 8000, локализуйте виновника
pidstat -w -u 1 5 | grep -E "PID|cs"
```

### Мониторинг через cron для исторического анализа

```bash
# Сбор статистики каждые 5 минут в течение часа для анализа тенденций
# (добавьте в crontab: */5 * * * * /usr/bin/pidstat -urd -o /var/log/pidstat_$(date +\%Y\%m\%d).csv)
pidstat -urd -o /var/log/pidstat_$(date +%Y%m%d_%H%M).csv 5 12
```

### Валидация лимитов systemd-сервисов

```bash
# Проверка, не достигает ли сервис лимитов CPUQuota или MemoryMax
pidstat -p $(systemctl show --property=MainPID --value myapp.service) -u -r 5
```

### Отладка деградации сервиса

```bash
# Комплексный снимок состояния проблемного PID
pidstat -p <PID> -d -r -w -u 1 5
```

### Корреляция с cgroup v2

```bash
# Сопоставление статистики pidstat с cgroup-лимитами
# Показывает, throttled ли процесс через cgroup CPU
cat /sys/fs/cgroup/system.slice/myapp.service/cpu.stat
# → usage_usec  nr_throttled_usec  throttled_time
```

### Аудит и compliance

```bash
# Фиксация потребления ресурсов критичными процессами для отчета
pidstat -u -r -d -w -o /audit/pidstat_$(date +%Y%m%d).csv 60 24
```

## Производительность и масштабирование

**Оверхед утилиты:** `pidstat` работает в userspace, читая `/proc` и опрашивая `taskstats`. На системах с >1000 процессами и интервалом <0.5с сама утилита может создавать заметную нагрузку (до 1-2% CPU на большом наборе процессов).

**Рекомендации:**
- Для систем с 1000+ процессов используйте фильтр `-p <PID>` или `-C <name>` вместо глобального опроса.
- Интервал < 0.1с может привести к пропуску сэмплов из-за задержек планирования.
- При очень высокой частоте обновления (`-d 0.01`) предпочтительнее `perf` или `bpftrace`, которые используют eBPF с меньшим overhead.

**Сравнение overhead:**
| Метод | Overhead | Применимость |
| :--- | :--- | :--- |
| `pidstat -u 1` | ~0.1-0.5% CPU | Ежедневный мониторинг |
| `pidstat -d 0.1` | ~1-3% CPU | Детальная диагностика I/O |
| `perf stat -p <PID>` | ~0.5-2% CPU | Профилирование конкретного процесса |
| `bpftrace` | <0.5% CPU | Высокочастотная трассировка |

## Типичные ошибки и их решение

| Ошибка / Симптом | Причина | Решение |
| :--- | :--- | :--- |
| **`pidstat: Not enough processes to monitor`** | Все процессы завершились или указан неверный фильтр `-C` | Проверьте фильтр: `pidstat -C "nginx" 1` ищет по `comm`, а не по аргументам командной строки. Для поиска по полной строке используйте `pgrep -f` для получения PID, затем `pidstat -p <PID>`. |
| **Нулевые значения `kB_wr/s` при активности диска** | I/O происходит через writeback ядра или `io_uring`, которые `pidstat -d` не учитывает | Используйте [`iotop`](../Filesystem/iotop.md) или [`biolatency-bpfcc`](../../Diagnostics/Performance/DiskIO/troubleshooting_scenarios.md) для полной картины. |
| **Не видно чужих PID** | `/proc` смонтирован с `hidepid=2` или запуск без root | Переподключите `/proc` без `hidepid` или используйте `sudo`. Для I/O и контекстных переключений чужих процессов root обязателен. |
| **Высокий overhead при частом опросе** | Интервал слишком мал для количества процессов | Увеличьте интервал, добавьте фильтр `-p` или перейдите на `perf`/`bpftrace` для высокочастотного сбора. |
| **`%CPU` > 100% на многоядерной системе** | Это нормально: процесс использует несколько ядер одновременно | Для расчета утилизации на одно ядро делите `%CPU` на количество ядер. `top` показывает то же поведение. |
| **RSS растет, но `pidstat -r` показывает стабильность** | Процесс выделяет память через `mmap` (VSS растет), но не трогает страницы (RSS стабилен) | Нормальное поведение. RSS отражает только физически загруженные страницы. |
| **`pidstat -d` показывает `iodelay=0` при тормозах** | Процесс блокируется в ядре (D-state), а не на ожидании I/O у себя в контексте | Используйте `vmstat 1` и `cat /proc/<PID>/wchan` для диагностики D-state. |

## Ограничения

- **Hidepid:** Если `/proc` смонтирован с опцией `hidepid=2`, обычный пользователь увидит в `pidstat` только свои процессы. Статистика I/O для чужих PID будет недоступна.
- **Права доступа:** Для мониторинга I/O (`-d`) и переключений контекста других пользователей требуются права **root**.
- **Оверхед:** При очень высокой частоте обновления (`-d 0.01`) сама утилита может создавать заметную нагрузку на систему.
- **Короткоживущие процессы:** При интервале 1с процессы, живущие <100мс, могут не попасть в выборку. Для их детекции используйте `pidstat -d 0.1` или [`execsnoop` через bpftrace](../../Core/processes/practical_scenarios.md).
- **io_uring:** Асинхронный I/O через `io_uring` (начиная с ядра 5.1) не всегда корректно отражается в `pidstat -d`, так как операции выполняются в контексте ядра, а не процесса.
- **Кластеризация:** В системах с тысячами процессов фильтрация по имени (`-C`) работает только с полем `comm` (первые 15 символов), а не с полной командной строкой.

| Инструмент | Уровень | Таймсериес | Требует root | Лучшее применение |
| :--- | :--- | :--- | :--- | :--- |

| **`top`** | Система/Процесс | Нет | Нет | Интерактивный поиск виновника |
| **`htop`** | Система/Процесс | Нет | Нет | Визуальный мониторинг, управление |
| **`ps`** | Процесс | Нет | Нет | Одиночный снимок, фильтрация |

## Дополнительная информация

### Установка и настройка

Пакет `sysstat` является обязательным требованием.
- **Ubuntu/Debian**: `sudo apt install sysstat`
- **RHEL/CentOS**: `sudo dnf install sysstat`

Для активации постоянного сбора данных (необходимо для `sar`, но полезно и для `pidstat`):
`sudo systemctl enable --now sysstat`
