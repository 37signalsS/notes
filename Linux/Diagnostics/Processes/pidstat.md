# Утилита `pidstat`

## Определения

**`pidstat`** — системная утилита, входящая в пакет `sysstat`, предназначенная для мониторинга использования ресурсов отдельными процессами в операционной системе Linux. Она позволяет получать детальную статистику по нагрузке на центральный процессор (CPU — Central Processing Unit), использованию оперативной памяти (RAM — Random Access Memory), операциям ввода-вывода (I/O — Input/Output) и другим параметрам в реальном времени или с заданным интервалом.

**Ключевые особенности:**

- Фокусировка на статистике конкретных идентификаторов процессов (PID — Process Identifier), в отличие от [`top`](./top.md), ориентированного на общую картину системы.
- Возможность сбора данных с накоплением (историческая статистика за интервал).
- Эффективное обнаружение короткоживущих процессов за счет настройки частоты опроса.
- Поддержка детализации до уровня отдельных потоков выполнения (threads).

**Требования:** Необходимо наличие установленного пакета `sysstat`.

## Основные концепции

### Сравнение с другими инструментами мониторинга

| Инструмент | Основное назначение | Интерактивность | История (интервалы) |
| :--- | :--- | :--- | :--- |
| [`top`](./top.md) | Общий обзор состояния системы | Высокая | Нет |
| [`htop`](./htop.md) | Удобный визуальный мониторинг процессов | Высокая | Нет |
| [`ps`](./ps.md) | Статический снимок состояния процессов | Нет | Нет |
| **`pidstat`** | **Детальная статистика по ресурсам процессов** | **Низкая** | **Да** |
| [`atop`](../Performance/atop.md) | Комплексный мониторинг ресурсов и процессов | Высокая | Да |

### Режимы сбора данных

1. **Суммарный отчет:** `pidstat -u` (статистика с момента загрузки системы).
2. **Непрерывное наблюдение:** `pidstat -u 1` (вывод обновляемых данных каждую секунду).
3. **Фиксированная серия:** `pidstat -u 2 10` (выполнить 10 замеров с интервалом в 2 секунды).

### Ключевые группы метрик

#### Центральный процессор (-u)

Позволяет понять, как процесс распределяет нагрузку:

- `%usr`: время в пространстве пользователя (Userspace).
- `%system`: время, затраченное на системные вызовы в пространстве ядра (Kernelspace).
- `%CPU`: суммарный процент использования ресурсов процессора.

#### Ввод-вывод (-d)

Отображает активность дисковой подсистемы для каждого процесса:

- `kB_rd/s`: объем данных, прочитанных с диска (КБ/сек).
- `kB_wr/s`: объем данных, записанных на диск.
- `iodelay`: задержка процесса в ожидании завершения операций I/O (в тактах процессора).

#### Оперативная память (-r)

Предоставляет данные об управлении памятью:

- `minflt/s`: количество малых ошибок страниц (minor faults) в секунду (страница найдена в RAM, но не в таблице страниц процесса).
- `majflt/s`: количество серьезных ошибок страниц (major faults), требующих обращения к диску/swap. Рост этого показателя — признак нехватки RAM.
- `VSZ`: объем виртуальной памяти, выделенной процессу (КБ).

Подробное описание метрик памяти доступно в разделе [метрики памяти процессов](../../Core/memory/process_memory_metrics.md).

## Практические сценарии

### Мониторинг нагрузки на CPU

```bash
# Текущая загрузка CPU всеми активными процессами
pidstat -u 1

# Наблюдение за конкретным процессом по его PID
pidstat -p 1234 1

# Мониторинг всех процессов с фильтрацией по имени команды
pidstat -u -C "nginx" 1
```

### Диагностика дисковой активности

Сценарий: поиск процесса, который создает аномальную нагрузку на диск.

```bash
# Мониторинг I/O в реальном времени
pidstat -d 1

# Детализация I/O до уровня потоков (threads) процесса
pidstat -d -t -p 1234 1
```

**Интерпретация результатов:**

- Высокие значения `kB_wr/s` часто указывают на работу баз данных, систем логирования или выполнение резервного копирования.
- Высокий `iodelay` свидетельствует о том, что процесс «замирает» в ожидании ответа от дисковой подсистемы.

### Выявление утечек памяти

```bash
# Мониторинг параметров памяти с интервалом 5 секунд
pidstat -r 5

# Идентификация процесса с постоянным ростом VSZ и %MEM
pidstat -r -p 1234 5
```

### Работа с многопоточными приложениями

Для анализа нагрузки, создаваемой отдельными потоками (например, в Java-приложениях):

```bash
# Показать статистику по всем потокам конкретного PID
pidstat -t -p 1234 1
```

### Экспорт данных для анализа

```bash
# Сохранение данных в формате CSV (Comma-Separated Values) для последующего импорта в таблицы
pidstat -u 1 -o - > report.csv

# Фоновое логирование комплексной статистики
nohup pidstat -urd 10 > pidstat_debug.log &
```

## Дополнительная информация

### Установка и настройка sysstat

Утилита `pidstat` входит в состав пакета `sysstat`. Инструкции по установке и включению сбора данных см. в разделе [Установка и настройка sysstat](../Performance/sar.md#установка-и-настройка-sysstat).

### Сравнение с аналогами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| [`top`](./top.md) / [`htop`](./htop.md) | Наглядность, интерактивность | Сложность анализа динамики по одному процессу |
| [`ps`](./ps.md) | Идеально для разовых проверок и простых скриптов | Отсутствие информации об интервальной нагрузке |
| [`atop`](../Performance/atop.md) | Сохранение полной истории системы | Высокая сложность настройки и интерфейса |

### Ограничения

- **Требует установки**: не входит в стандартный набор утилит базового образа многих дистрибутивов.
- **Права доступа**: для мониторинга процессов других пользователей и получения детальных метрик I/O требуются права суперпользователя.
