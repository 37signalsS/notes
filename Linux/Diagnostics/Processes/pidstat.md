# Утилита `pidstat`

## Определения

**`pidstat`** — специализированная системная утилита, входящая в пакет `sysstat`, предназначенная для мониторинга использования ресурсов отдельными процессами в операционной системе Linux. В отличие от [`top`](./top.md), которая ориентирована на общую картину системы, `pidstat` фокусируется на детализированной статистике конкретных идентификаторов процессов (PID — Process Identifier).

Утилита позволяет получать отчеты по нагрузке на центральный процессор (CPU), использованию оперативной памяти (RAM), операциям ввода-вывода (I/O), переключениям контекста и ресурсам ядра в реальном времени или за заданный интервал.

**Ключевые особенности:**
- **Фокус на PID:** Идеальна для глубокого анализа конкретного приложения.
- **Интервальная статистика:** Возможность сбора данных с накоплением (историческая статистика за период), что позволяет видеть динамику, а не мгновенный снимок.
- **Детекция «фантомов»:** Эффективное обнаружение короткоживущих процессов за счет настройки высокой частоты опроса.
- **Детализация до потоков:** Поддержка анализа на уровне отдельных потоков выполнения (Threads/LWP).

## Основные концепции

### Сравнение с инструментами мониторинга

| Инструмент | Назначение | Интерактивность | История (интервалы) |
| :--- | :--- | :--- | :--- |
| [`top`](./top.md) | Общий обзор состояния системы. | Высокая | Нет |
| [`htop`](./htop.md) | Удобный визуальный мониторинг. | Высокая | Нет |
| [`ps`](./ps.md) | Статический снимок состояния. | Нет | Нет |
| **`pidstat`** | **Детальная статистика по ресурсам процессов.** | **Низкая** | **Да** |
| [`atop`](../Performance/atop.md) | Комплексный аудит ресурсов и процессов. | Высокая | Да |

### Режимы сбора данных

`pidstat` поддерживает три основных режима работы:
1. **Суммарный отчет:** `pidstat -u` — отображает среднюю статистику с момента загрузки (uptime) системы.
2. **Непрерывное наблюдение:** `pidstat -u 1` — выводит обновляемые данные каждую секунду.
3. **Фиксированная серия:** `pidstat -u 2 10` — выполняет 10 замеров с интервалом в 2 секунды, в конце выводит усредненный результат.

### Ключевые группы метрик

#### Центральный процессор (-u)
- **`%usr`**: время выполнения кода в пространстве пользователя (Userspace).
- **`%system`**: время на системные вызовы в пространстве ядра (Kernelspace).
- **`%guest`**: время, затраченное на работу виртуальных машин (Guest OS).
- **`%CPU`**: суммарный процент использования ресурсов CPU всеми ядрами.

#### Ввод-вывод (-d)
Отображает активность дисковой подсистемы:
- **`kB_rd/s`**: объем данных, прочитанных с диска (КБ/сек).
- **`kB_wr/s`**: объем данных, записанных на диск.
- **`kB_ccwr/s`**: объем данных, запись которых была отменена (например, удаление временного файла до сброса на диск).
- **`iodelay`**: задержка процесса в ожидании завершения операций I/O (в тактах процессора). Высокий показатель — признак перегрузки дисковой подсистемы.

#### Оперативная память (-r)
- **`minflt/s`**: малые ошибки страниц (minor faults) в секунду (страница найдена в кеше RAM).
- **`majflt/s`**: серьезные ошибки страниц (major faults), требующие обращения к диску или swap. Рост этого показателя — критический признак нехватки RAM.
- **`VSZ`**: объем выделенной виртуальной памяти (КБ).
- **`RSS`**: резидентная память — сколько физической RAM процесс занимает на самом деле.

#### Переключение контекста (-w)
- **`cswch/s`**: добровольные переключения (voluntary) — процесс сам отдает CPU (ожидание I/O, сокета).
- **`nvcswch/s`**: принудительные переключения (non-voluntary) — ядро прерывает процесс (исчерпание кванта времени, высокая конкуренция).

#### Ресурсы ядра (-v)
- **`threads`**: количество активных потоков.
- **`fd-nr`**: количество открытых файловых дескрипторов.

## Практические сценарии

### Мониторинг нагрузки на CPU

```bash
# Текущая загрузка CPU всеми активными процессами
pidstat -u 1

# Наблюдение за конкретным PID (например, 1234)
pidstat -p 1234 1

# Фильтрация по имени процесса с полной командной строкой
pidstat -u -C "nginx" -l 1
```

### Диагностика дисковой активности

```bash
# Поиск «виновника» высокой I/O нагрузки
pidstat -d 1

# Детализация I/O до уровня потоков (актуально для баз данных)
pidstat -d -t -p 1234 1
```

**Интерпретация:**
- Высокие значения `kB_wr/s` часто указывают на работу БД, систем логирования или бэкапов.
- Высокий `iodelay` означает, что процесс «замирает», ожидая ответа от диска.

### Выявление утечек памяти

```bash
# Мониторинг параметров памяти с интервалом 5 секунд
pidstat -r 5

# Идентификация процесса с постоянным ростом RSS и VSZ
pidstat -r -p 1234 5
```

### Анализ многопоточных приложений (Java, Go)

```bash
# Показать статистику по всем потокам (LWP) конкретного процесса
pidstat -t -p 1234 1
```

### Экспорт и фоновое логирование

```bash
# Сохранение данных в формате CSV для импорта в таблицы (Excel/Pandas)
pidstat -u 1 -o - > report.csv

# Фоновое логирование комплексной статистики (CPU, RAM, I/O)
nohup pidstat -urd 10 > pidstat_debug.log &
```

## Дополнительная информация

### Установка и настройка

Пакет `sysstat` является обязательным требованием.
- **Ubuntu/Debian**: `sudo apt install sysstat`
- **RHEL/CentOS**: `sudo dnf install sysstat`

Для активации постоянного сбора данных (необходимо для `sar`, но полезно и для `pidstat`):
`sudo systemctl enable --now sysstat`

### Безопасность и ограничения

- **Hidepid**: Если `/proc` смонтирован с опцией `hidepid=2`, обычный пользователь увидит в `pidstat` только свои процессы. Статистика I/O для чужих PID будет недоступна.
- **Права доступа**: Для мониторинга I/O (`-d`) и переключений контекста других пользователей требуются права **root**.
- **Оверхед**: При очень высокой частоте обновления (`-d 0.01`) сама утилита может создавать заметную нагрузку на систему.
