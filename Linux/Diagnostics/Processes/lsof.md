# `lsof`

## Определение

`lsof` (list open files) — это утилита командной строки, которая показывает список [открытых файлов и файловых дескрипторов](../../FileSystems/file_descriptors.md) и процессов, которые их используют. В Unix-подобных системах "всё есть файл", поэтому `lsof` может отображать информацию не только о файлах на диске, но и о сетевых сокетах, каналах (pipes) и устройствах.

## Основные концепции

`lsof` получает информацию из файловой системы `/proc`, агрегируя данные о файловых дескрипторах каждого процесса. Это позволяет ответить на ключевые вопросы диагностики:

-   Какой процесс держит открытым конкретный файл или каталог?
-   Какой процесс слушает определённый сетевой порт?
-   Какие файлы открыты конкретным пользователем или процессом?

## Практические сценарии

### Поиск процесса по файлу или порту

```bash
# Показать, какой процесс держит файл /var/log/syslog
sudo lsof /var/log/syslog

# Показать, какой процесс слушает TCP-порт 8080
sudo lsof -i :8080
```

### Анализ активности процесса или пользователя

```bash
# Показать все открытые файлы для процесса с указанным PID
sudo lsof -p <PID>

# Показать все открытые файлы пользователя www-data
sudo lsof -u www-data
```

### Диагностика проблем с дисковым пространством: место не освободилось после удаления

Иногда после удаления больших файлов (`rm file.log`) команда `df -h` показывает, что свободное место не увеличилось.

Это происходит, когда какой-либо запущенный процесс всё ещё использует этот "удалённый" файл. В файловых системах Linux удаление файла командой `rm` лишь убирает его имя (ссылку) из директории. Сами данные на диске (inode и блоки данных) остаются нетронутыми до тех пор, пока хотя бы один процесс держит этот файл открытым (имеет открытый файловый дескриптор).

Чтобы найти процесс, который удерживает удалённый файл, можно использовать `lsof` (list open files).

- **Способ 1: Поиск по статусу "deleted"**
  ```sh
  sudo lsof | grep deleted
  ```
  Эта команда покажет список процессов и файлы, которые они держат открытыми, несмотря на удаление.

- **Способ 2: Поиск по количеству ссылок**
  ```sh
  sudo lsof +L1
  ```
  Эта команда использует встроенную функцию `lsof` для поиска файлов, у которых количество ссылок (link count) меньше 1, то есть удалённых файлов.

**Решение:**
Чтобы освободить место, нужно заставить процесс "отпустить" файл. Есть несколько способов:

1.  **Перезапустить сервис/процесс (рекомендуемый способ):**
    Если файл удерживается системной службой (например, `nginx` или `rsyslog`), самым безопасным способом будет её перезапуск.
    ```sh
    sudo systemctl restart <имя_сервиса>
    ```
    Это заставит процесс корректно завершиться и освободить все файловые дескрипторы.

2.  **Завершить процесс:**
    Если это не критичный сервис, можно просто завершить процесс, используя его PID из вывода `lsof`.
    ```sh
    kill <PID>
    ```

3.  **"Очистить" файл без перезапуска (рискованный способ):**
    В некоторых случаях, когда перезапуск сервиса нежелателен, можно очистить содержимое файла, не удаляя его. Это можно сделать, обрезав файл до нулевого размера через его файловый дескриптор в `/proc`.
    ```sh
    # sudo truncate -s 0 /proc/<PID>/fd/<номер_дескриптора>
    #
    # Пример для лог-файла nginx, который был удалён, но удерживается процессом с PID 1234
    # Путь к файлу и номер дескриптора можно найти в выводе lsof
    sudo truncate -s 0 /proc/1234/fd/5 
    ```
    - `truncate -s 0` обрезает файл до нулевого размера, что немедленно освобождает дисковое пространство.
    - `/proc/<PID>/fd/<номер_дескриптора>` — это специальный путь, который позволяет получить доступ к файлу через открытый дескриптор процесса.

## Дополнительная информация

### Диагностика утечек файловых дескрипторов

Если процесс потребляет слишком много файловых дескрипторов, это может привести к ошибке "too many open files".

```bash
# Посчитать количество открытых файлов для процесса
sudo lsof -p <PID> | wc -l
```

Анализ полного вывода `lsof -p <PID>` может показать, какие именно файлы постоянно открываются и не закрываются.

### Отслеживание сетевых соединений

```bash
# Показать все TCP-соединения
sudo lsof -i TCP

# Показать все установленные (ESTABLISHED) соединения
sudo lsof -i TCP:ESTABLISHED
```

### Фильтрация по типу доступа

```bash
# Найти все файлы, открытые процессом <PID> для записи (write)
sudo lsof -p <PID> | grep " w"
```
