# Утилита `lsof`

## Определения

**`lsof`** (list open files) — стандартная системная утилита в Linux и Unix, предназначенная для отображения списка всех открытых файлов и процессов, которые их используют. Поскольку в архитектуре Unix «всё есть файл», утилита предоставляет детальную информацию не только о данных на диске, но и о сетевых соединениях, каналах (pipes), устройствах и разделяемых библиотеках.

Утилита является основным инструментом для диагностики утечек ресурсов, блокировок файловых систем и анализа сетевой активности процессов.

## Основные концепции

### Механика работы

`lsof` является pure-read утилитой и не использует системные вызовы типа `ptrace`. Вместо этого она сканирует виртуальную файловую систему `/proc`:
- `/proc/<PID>/fd/` — символические ссылки на все открытые дескрипторы процесса.
- `/proc/<PID>/cmdline` — командная строка процесса.
- `/proc/<PID>/maps` — отображённые в память регионы (включая разделяемые библиотеки `.so`).
- `/proc/net/tcp`, `/proc/net/tcp6`, `/proc/net/udp`, `/proc/net/unix` — таблицы сетевых соединений.

Для получения полной картины по всей системе (включая процессы других пользователей и ядра) требуются права **root**.

Ядерные потоки (kthreadd) отображаются в `lsof`, но имеют ограниченный набор дескрипторов (обычно только `cwd`, `rtd`, `txt`).

### Интерпретация вывода (Колонки)

| Столбец | Описание |
| :--- | :--- |
| **COMMAND** | Имя команды, связанной с процессом. |
| **PID** | Идентификатор процесса. |
| **TID** | Идентификатор потока (если применимо). |
| **USER** | Имя пользователя (или UID), которому принадлежит процесс. |
| **FD** | **File Descriptor**: Номер дескриптора или код специального типа. |
| **TYPE** | Тип файла (REG, DIR, CHR, BLK, IPv4, IPv6, UNIX, FIFO и др.). |
| **DEVICE** | Номера устройств (major, minor) через запятую. |
| **SIZE/OFF** | Размер файла или смещение (offset) в байтах. |
| **NODE** | Номер индексного дескриптора (inode) на диске. |
| **NAME** | Путь к файлу или описание сетевого соединения. |

#### Детализация столбца FD (File Descriptor)
Этот столбец содержит критически важную информацию о режиме работы с файлом:
- **`cwd`**: текущий рабочий каталог (current working directory).
- **`rtd`**: корневой каталог (root directory).
- **`txt`**: программный текст (исполняемый файл).
- **`mem`**: файл, отображённый в память (memory-mapped file, например, библиотека `.so`).
- **`[0-9]+[rwu]`**: числовой дескриптор и режим доступа:
    - **`r`** (read) — только чтение.
    - **`w`** (write) — только запись.
    - **`u`** (read and write) — чтение и запись.
- **`[0-9]+u`**: блокирующий дескриптор (установлена advisory-блокировка через `flock` или `fcntl`).

### Логика фильтрации (AND vs OR)

По умолчанию `lsof` объединяет фильтры через логическое **ИЛИ** (OR).
- `lsof -u user1 -i` → покажет файлы пользователя `user1` **ИЛИ** любые сетевые соединения.
- `lsof -a -u user1 -i` → флаг **`-a`** включает логику **И** (AND), показывая сетевые соединения, принадлежащие **только** пользователю `user1`.

## Практические сценарии

### Диагностика сетевых портов и соединений

**Задача:** Глубокий анализ сетевой активности.

```bash
# Список всех сетевых соединений (ускоренный режим без DNS и имён сервисов)
sudo lsof -nP -i

# Найти процессы, слушающие (LISTEN) по протоколу TCP
sudo lsof -nP -iTCP -sTCP:LISTEN

# Кто слушает конкретный порт
sudo lsof -i :80

# Получить только PID процесса на порту (для автоматизации)
lsof -t -i :8080

# Получить PID и немедленно завершить процесс на порту
lsof -t -i :8080 | xargs -r kill

# Поиск соединений к конкретному хосту
sudo lsof -i @1.2.3.4

# Сокеты в состоянии CLOSE_WAIT (потенциальная утечка)
sudo lsof -i TCP -sTCP:CLOSE-WAIT
```

### Анализ удалённых (Deleted) файлов

**Проблема:** Место на диске занято удалёнными файлами (Ghost files).

```bash
# Поиск всех удалённых, но открытых файлов (статус +L1 ищет ссылки < 1)
sudo lsof +L1

# Быстрый поиск через grep
sudo lsof | grep deleted
```

**Решение:** Для освобождения места без остановки службы можно обнулить файл через его дескриптор:
`echo > /proc/<PID>/fd/<FD_NUMBER>`

### Блокировки при размонтировании (umount)

Если система выдает ошибку `target is busy`:

```bash
# Найти все процессы, использующие файлы в указанной точке монтирования
sudo lsof +D /mnt/data

# Проверить, кто держит конкретный файл открытым перед размонтированием
lsof /mnt/data/critical.db

# Показать конкретные дескрипторы процесса (только текст и память)
lsof -p <PID> -a -d txt,mem

# Быстрая остановка: найти PID, удерживающий файл, и завершить его
lsof -t /mnt/data/file.log | xargs -r kill
```

### Блокировки пакетных менеджеров (dpkg/apt/dnf/yum)

**Проблема:** При установке или обновлении пакетов появляется ошибка `Could not get lock` или `Waiting for cache lock`.

**Причина:** Другой процесс удерживает advisory-блокировку на файле блокировки пакетного менеджера (например, `/var/lib/dpkg/lock-frontend`, `/var/cache/dnf/metadata_lock.pid`).

```bash
# Debian/Ubuntu: найти процесс, держащий блокировку dpkg
sudo lsof /var/lib/dpkg/lock-frontend
sudo lsof /var/lib/apt/lists/lock

# RHEL/CentOS/Fedora: аналогично для dnf/yum
sudo lsof /var/cache/dnf/metadata_lock.pid
sudo lsof /var/run/yum.pid
```

**Решение:**
```bash
# Идентифицировать PID и завершить зависший процесс
kill -9 <PID>

# В крайнем случае — удалить устаревший lock-файл и восстановить БД пакетов
rm /var/lib/dpkg/lock-frontend
dpkg --configure -a
```

### Диагностика Stale File Handle (NFS/ESTALE)

**Проблема:** На клиенте NFS появляется ошибка `Stale File Handle` или процессы зависают при доступе к файлам на сетевом ресурсе.

**Причина:** Файл был удалён или пересоздан на NFS-сервере, а клиентский дескриптор стал недействительным.

```bash
# Найти процессы, удерживающие устаревшие дескрипторы NFS
sudo lsof | grep /mnt/nfs

# Принудительное «ленивое» размонтирование (если umount зависает)
sudo umount -l /mnt/nfs
sudo mount -a
```

### Аудит безопасности и библиотек

```bash
# Показать используемый контекст безопасности (SELinux/AppArmor)
sudo lsof -Z

# Список всех разделяемых библиотек (.so), загруженных процессом
sudo lsof -p <PID> | grep mem

# Список процессов, открывших файлы в каталоге /tmp (поиск подозрительной активности)
sudo lsof +D /tmp
```

### Диагностика systemd-сервисов и логов

**Задача:** Определить, какой сервис удерживает файл (например, старый лог после logrotate или конфиг, который нельзя изменить).

```bash
# Все файлы, открытые процессами systemd-юнита (найти по имени сервиса)
sudo lsof -c systemd-

# Проверить, держит ли сервис старый лог-файл после logrotate
sudo lsof | grep /var/log/nginx/access.log

# Поиск всех процессов, пишущих в /var/log (поиск зависших логов)
sudo lsof +D /var/log
```

### Использование в скриптах (Машинный формат)

Флаг **`-F`** позволяет выводить данные в формате, удобном для парсинга (каждое поле на новой строке с префиксом).

```bash
# Вывод PID (p) и имени файла (n) для процесса 1234
sudo lsof -p 1234 -F pn
```

## Дополнительная информация

### Основные флаги и опции

| Флаг | Описание |
| :--- | :--- |
| `-u <user>` | Фильтр по имени пользователя или UID. |
| `-p <PID>` | Фильтр по идентификатору процесса. |
| `-i` | Вывод сетевых файлов (IP-сокеты). Можно уточнить: `-i4`, `-i6`, `-iTCP`, `-iUDP`, `-iTCP:80`. |
| `-a` | Логическое «И» (AND) между фильтрами. |
| `-t` | Terse output — выводить только PID. |
| `+D <dir>` | Рекурсивный поиск во всех файлах внутри директории. |
| `-c <name>` | Фильтр по имени команды (начало имени процесса). |
| `-n` / `-P` | Отключить DNS-резолвинг и преобразование портов (критично для скорости). |
| `+L1` | Поиск файлов, у которых количество ссылок меньше 1 (удалённые файлы). |
| `-r [sec]` | Режим обновления каждые N секунд (по умолчанию 15). |
| `-Z` | Вывод контекста безопасности (SELinux/AppArmor). |
| `-U` | Поиск только Unix domain сокетов. |
| `-d <FD>` | Фильтр по конкретному номеру дескриптора или диапазону (например, `-d 1-3` или `-d 1,3,5`). |
| `-g <PGID>` | Фильтр по идентификатору группы процессов (PGID). |
| `-s <size>` | Выводить размер файла в блоке SIZE/OFF (например, `-s k` для килобайт). |
| `-b` | Запретить `lsof` на выполнение операций, которые могут заблокироваться (например, stat на зависших NFS). |

### Производительность и масштабирование

1.  **Зависания на больших системах:** На системах с тысячами процессов или большим количеством сокетов `lsof` без флагов `-n` и `-P` может зависать на минуты из-за попытки DNS-резолва. Всегда используйте `-nP` в production-скриптах.
2.  **hidepid:** Если `/proc` смонтирован с опцией `hidepid=2`, обычный пользователь не увидит процессов других в `lsof`. Для работы с полным списком требуются права `root`.
3.  **Явная блокировка:** При диагностике проблем с NFS или повреждённых ФС используйте флаг `-b`, чтобы `lsof` не завис на stat-запросах.
4.  **Ядро:** Некоторые дескрипторы ядра (например, связанные с eBPF или специфичными драйверами) могут не отображаться полностью.
5.  **Скорость:** На системах с >10 000 процессов `lsof` может работать 1–10 секунд. Для быстрых проверок используйте `fuser` или прямой обход `/proc/*/fd`.

### Типичные ошибки и их решения

| Ошибка / Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `lsof: WARNING: compiled for 4.3.0 kernel, user wants 5.15.0` | Версия `lsof` устарела для текущего ядра | Обновить пакет `lsof` из репозитория дистрибутива. |
| `lsof: can't read kernel memory` | `lsof` скомпилирован под другую архитектуру ядра | Переустановить `lsof`. |
| `Permission denied` при чтении `/proc/<PID>/fd/` | Процесс принадлежит другому пользователю и включен `hidepid=2` | Запускать через `sudo`. |
| Нет вывода для ожидаемого процесса | Процесс завершился; PID переиспользован | Использовать `pidfd` (Linux 5.3+) или `/proc/PID/starttime` для проверки. |
| Зависание на больших системах | DNS-резолвинг или зависшая ФС | Добавить `-nP`, `-b`, ограничить фильтрами. |

### Сравнение с аналогами

| Инструмент | Преимущества | Когда выбирать |
| :--- | :--- | :--- |
| **`lsof`** | Максимальная детализация (файлы, сокеты, библиотеки). | Глубокий аудит ресурсов процесса. |
| [`ss`](../Networking/ss.md) | Скорость работы, детальная TCP-статистика. | Диагностика сетевого стека. |
| `fuser` | Простота: сразу показывает PID для файла/порта. | Быстрое высвобождение заблокированных ресурсов. |
| [`lsns`](./lsns.md) | Показывает namespaces. | Диагностика контейнеров. |
| [`nsenter`](./nsenter.md) | Вход в пространства имен. | Активная отладка внутри изоляции. |
