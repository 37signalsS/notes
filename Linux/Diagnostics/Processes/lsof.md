# `lsof`

## Определения

**`lsof`** (list open files) — утилита для отображения списка открытых файлов и файловых дескрипторов процессов. В Unix-подобных системах «всё есть файл», поэтому `lsof` показывает не только файлы на диске, но и сетевые сокеты, каналы (pipes), устройства и другую межпроцессную коммуникацию.

**Ключевые особенности:**

- Получает данные из `/proc`, агрегируя информацию о файловых дескрипторах
- Требует прав root для полной информации по всем процессам
- Поддержка фильтрации по пользователю, процессу, порту, типу файла

## Основные концепции

### Что считается «открытым файлом»

В контексте `lsof`:

- **Файлы на диске** — обычные файлы, каталоги
- **Сетевые сокеты** — TCP/UDP соединения
- **Каналы (pipes)** — межпроцессное взаимодействие
- **Сокеты домена Unix** — локальная IPC
- **Устройства** — `/dev/*`
- **Библиотеки** — загруженные `.so` файлы

### Типы файлов (TYPE)

| Тип | Описание |
| :--- | :--- |
| `REG` | Обычный файл (regular file) |
| `DIR` | Каталог (directory) |
| `CHR` | Символьное устройство (character device) |
| `BLK` | Блочное устройство (block device) |
| `FIFO` | Канал (pipe) |
| `UNIX` | Сокет домена Unix |
| `IPv4` / `IPv6` | Сетевой сокет |
| `DEL` | Удалённый файл (удалён, но держится процессом) |

### Состояния файловых дескрипторов

| Код | Описание |
| :--- | :--- |
| `r` | Read — открыт для чтения |
| `w` | Write — открыт для записи |
| `u` | Read/Write — открыт для чтения и записи |
| `-` | Неизвестный режим |

## Практические сценарии

### Поиск процесса по файлу

```bash
# Какой процесс держит конкретный файл
sudo lsof /var/log/syslog

# Поиск по каталогу (рекурсивно)
sudo lsof +D /var/log

# Поиск по точному пути (без рекурсии)
sudo lsof +d /var
```

### Анализ процесса или пользователя

```bash
# Все открытые файлы процесса по PID
sudo lsof -p 1234

# Все открытые файлы пользователя
sudo lsof -u www-data

# Исключить пользователя из вывода
sudo lsof -u ^root

# Несколько пользователей
sudo lsof -u user1,user2
```

### Диагностика сетевых соединений

```bash
# Все сетевые соединения
sudo lsof -i

# Только TCP-соединения
sudo lsof -i TCP

# Только UDP
sudo lsof -i UDP

# Конкретный порт
sudo lsof -i :8080

# Диапазон портов
sudo lsof -i :1-1024

# По состоянию соединения
sudo lsof -i TCP:ESTABLISHED
sudo lsof -i TCP:LISTEN

# По хосту/IP
sudo lsof -i @192.168.1.100
```

### Поиск процесса по порту

```bash
# Какой процесс слушает порт 80
sudo lsof -i :80

# Альтернатива через fuser
sudo fuser 80/tcp
```

### Диагностика проблем с дисковым пространством

**Проблема:** После удаления больших файлов (`rm file.log`) команда `df -h` показывает, что место не освободилось.

**Причина:** Процесс держит удалённый файл открытым. Данные не освобождаются, пока процесс не закроет файловый дескриптор.

**Решение:**

```bash
# Найти удалённые, но удерживаемые файлы
sudo lsof | grep deleted

# Альтернативный способ (link count < 1)
sudo lsof +L1

# Поиск по конкретному пути
sudo lsof +L1 /var/log
```

**Варианты решения:**

1. **Перезапустить сервис (рекомендуется):**

   ```bash
   sudo systemctl restart nginx
   ```

2. **Завершить процесс:**

   ```bash
   kill <PID>
   # Или принудительно (если процесс не отвечает):
   kill -9 <PID>
   ```

3. **Очистить файл без перезапуска (через /proc):**

   ```bash
   # Найти PID и FD в выводе lsof
   sudo truncate -s 0 /proc/<PID>/fd/<FD>
   ```

**Важно:** Использование `kill -9` (SIGKILL) должно быть крайней мерой, так как процесс не сможет корректно освободить ресурсы.

### Диагностика утечек файловых дескрипторов

```bash
# Посчитать количество открытых файлов для процесса
lsof -p <PID> | wc -l

# Лимит файловых дескрипторов
cat /proc/<PID>/limits | grep "open files"

# Найти процессы с большим количеством FD
lsof -u <user> | awk '{print $2}' | sort | uniq -c | sort -rn | head
```

Ошибка «too many open files» указывает на исчерпание лимита. Подробно: [limits.md](../../Core/processes/limits.md).

### Фильтрация по типу доступа

```bash
# Файлы, открытые для записи
sudo lsof -p <PID> | grep " w"

# Файлы, открытые для чтения
sudo lsof -p <PID> | grep " r"
```

### Поиск по типу файла

```bash
# Только сокеты
sudo lsof -t -i

# Только файлы устройств
sudo lsof -t +D /dev

# IPC объекты (pipes, sockets)
sudo lsof -t -a -p $$ -d 0
```

### Вывод в машиночитаемом формате

```bash
# Вывод без заголовков (для скриптов)
lsof -n -P -F

# Поля: p=PID, f=FD, n=имя, t=тип
lsof -p 1234 -F pfn
```

## Дополнительная информация

### Основные опции

| Опция | Описание |
| :--- | :--- |
| `-p <PID>` | Фильтр по PID |
| `-u <user>` | Фильтр по пользователю |
| `-i` | Сетевые файлы |
| `-c <comm>` | Фильтр по имени команды |
| `+D <dir>` | Поиск по каталогу (рекурсивно) |
| `+d <dir>` | Поиск по каталогу (без рекурсии) |
| `+L` | Поиск по link count |
| `-t` | Только PID (для скриптов) |
| `-n` | Не разрешать имена (быстрее) |
| `-P` | Не разрешать порты (быстрее) |
| `-F` | Машинный формат вывода |
| `-v` | Подробный режим |

### Сравнение с аналогами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| `fuser` | Простой поиск по порту/файлу | Меньше деталей |
| `ss` / `netstat` | Сетевые соединения | Только сеть |
| [`/proc/*/fd`](../../FileSystems/file_descriptors.md) | Низкоуровневый доступ | Неудобно |

### Ограничения

- **Требует root:** Для полной информации по чужим процессам
- **Производительность:** Может быть медленным на системах с тысячами процессов
- **Моментальный снимок:** Данные актуальны на момент вызова
