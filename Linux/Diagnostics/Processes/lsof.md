# Утилита `lsof`

## Определения

**`lsof`** (list open files) — стандартная системная утилита в Linux и Unix, предназначенная для отображения списка всех открытых файлов и процессов, которые их используют. Поскольку в архитектуре Unix «всё есть файл», утилита предоставляет детальную информацию не только о данных на диске, но и о сетевых соединениях, каналах (pipes), устройствах и разделяемых библиотеках.

Утилита является основным инструментом для диагностики утечек ресурсов, блокировок файловых систем и анализа сетевой активности процессов.

## Основные концепции

### Механика работы

`lsof` считывает информацию из виртуальной файловой системы `/proc`. Для получения полной картины по всей системе (включая процессы других пользователей и ядра) требуются права **root**.

### Типы ресурсов

В выводе `lsof` «открытым файлом» считается любой из следующих объектов:
- **REG (Regular File)**: Обычные файлы и директории.
- **DIR (Directory)**: Каталоги.
- **CHR / BLK**: Символьные и блочные устройства.
- **IPv4 / IPv6 / UNIX**: Сетевые сокеты и сокеты домена Unix.
- **FIFO / PIPE**: Каналы межпроцессного взаимодействия.
- **DEL**: Удалённые файлы, дескрипторы которых всё ещё удерживаются процессами.

### Логика фильтрации (AND vs OR)

По умолчанию `lsof` объединяет фильтры через логическое **ИЛИ** (OR).
- `lsof -u user1 -i` → покажет файлы пользователя `user1` **ИЛИ** любые сетевые соединения.
- `lsof -a -u user1 -i` → флаг **`-a`** включает логику **И** (AND), показывая сетевые соединения, принадлежащие **только** пользователю `user1`.

## Практические сценарии

### Диагностика сетевых портов

**Задача:** Найти процесс, который занял порт и мешает запуску сервиса.

```bash
# Список всех сетевых соединений (ускоренный режим без DNS)
sudo lsof -nP -i

# Кто слушает конкретный порт
sudo lsof -i :80

# Получить только PID процесса на порту (удобно для скриптов)
lsof -t -i :8080

# Убить процесс, занимающий порт 8080 (комбинированный вызов)
kill -9 $(lsof -t -i :8080)
```

> **Совет:** Используйте флаги **`-n`** (запрет разрешения имен/DNS) и **`-P`** (запрет преобразования номеров портов в названия сервисов) для мгновенного получения результата на нагруженных системах.

### Анализ удалённых (Deleted) файлов

**Проблема:** Диск заполнен, `du` показывает мало данных, а `df` — отсутствие места.
**Причина:** Процесс пишет в файл, который был удалён командой `rm`, но дескриптор не был закрыт.

```bash
# Поиск всех удалённых, но открытых файлов
sudo lsof +L1

# Альтернативный поиск по ключевому слову
sudo lsof | grep deleted
```

**Решение:** Чтобы освободить место без перезапуска процесса, можно обнулить файл через его дескриптор:
`echo > /proc/<PID>/fd/<FD_NUMBER>`

### Блокировки при размонтировании (umount)

Если система выдает ошибку `target is busy` при попытке размонтировать диск или USB-накопитель:

```bash
# Найти все процессы, использующие файлы в указанной точке монтирования
sudo lsof +D /mnt/data
```

### Мониторинг в реальном времени

`lsof` поддерживает режим периодического обновления (аналог `top`):

```bash
# Обновлять список открытых файлов процесса каждые 3 секунды
lsof -p <PID> -r 3
```

## Дополнительная информация

### Основные флаги и опции

| Флаг | Описание |
| :--- | :--- |
| `-u <user>` | Фильтр по имени пользователя или UID. |
| `-p <PID>` | Фильтр по идентификатору процесса. |
| `-i` | Вывод сетевых файлов (IP-сокеты). |
| `-a` | Логическое «И» между фильтрами. |
| `-t` | Terse output — выводить только PID (для автоматизации). |
| `+D <dir>` | Рекурсивный поиск во всех файлах внутри директории. |
| `-c <name>` | Фильтр по имени команды (начало имени процесса). |
| `-F` | Вывод в машинно-ориентированном формате для парсинга. |

### Переменные окружения

- **`LSOF_TCP_PORT_LIST`**: позволяет переопределить стандартный список портов (редко используется).
- **`LSOF_ON_DEVICE_CA`**: управление кэшированием имен устройств для ускорения работы на системах с огромным количеством `/dev` узлов.

### Сравнение с аналогами

| Инструмент | Преимущества | Когда выбирать |
| :--- | :--- | :--- |
| **`lsof`** | Максимальная детализация (файлы, сокеты, библиотеки). | Глубокий аудит ресурсов процесса. |
| [`ss`](../Networking/ss.md) | Скорость работы, детальная TCP-статистика. | Диагностика сетевого стека. |
| `fuser` | Простота: сразу показывает PID для файла/порта. | Быстрое «убийство» процесса, мешающего размонтированию. |
| `lsns` | Изоляция: показывает namespaces. | Диагностика контейнеров. |

### Ограничения и безопасность

1.  **Hidepid**: Если `/proc` смонтирован с опцией `hidepid=2`, обычный пользователь не увидит процессы других пользователей в `lsof`, даже если файлы открыты в общедоступных каталогах.
2.  **Производительность**: На системах с сотнями тысяч открытых сокетов запуск `lsof` без флага `-n` может привести к зависанию из-за попыток разрешить IP в доменные имена.
