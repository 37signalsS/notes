# Утилита `lsof`

## Определения

**`lsof`** (list open files) — утилита для отображения списка открытых файлов и файловых дескрипторов (FD — File Descriptor) процессов. В Unix-подобных системах «всё есть файл», поэтому `lsof` показывает не только объекты на диске, но и сетевые сокеты, каналы (pipes), устройства и другие механизмы межпроцессного взаимодействия (IPC — Inter-Process Communication).

**Ключевые особенности:**

- Извлекает данные из виртуальной файловой системы `/proc`, агрегируя информацию о дескрипторах.
- Требует прав суперпользователя (root) для получения полной информации обо всех процессах в системе.
- Обладает мощным механизмом фильтрации по пользователю, идентификатору процесса (PID — Process Identifier), сетевому порту и типу файла.

## Основные концепции

### Типы ресурсов, считающихся «открытыми файлами»

В контексте работы `lsof` к открытым файлам относятся:

- **Файлы на диске** — обычные файлы и каталоги (директории).
- **Сетевые сокеты** — активные соединения по протоколам TCP (Transmission Control Protocol) и UDP (User Datagram Protocol).
- **Каналы (pipes)** — однонаправленные потоки данных для взаимодействия процессов.
- **Сокеты домена Unix** — локальные сокеты для быстрой передачи данных между процессами на одном хосте.
- **Устройства** — файлы в директории `/dev/*` (например, терминалы или дисковые разделы).
- **Библиотеки** — загруженные в память разделяемые объекты (`.so` файлы).

### Классификация типов файлов (TYPE)

| Тип | Описание |
| :--- | :--- |
| `REG` | Обычный файл (regular file) |
| `DIR` | Каталог (directory) |
| `CHR` | Символьное устройство (character device) |
| `BLK` | Блочное устройство (block device) |
| `FIFO` | Именованный канал (First In, First Out) |
| `UNIX` | Сокет домена Unix |
| `IPv4` / `IPv6` | Сетевой сокет стека IP |
| `DEL` | Удалённый файл (удалён с диска, но удерживается процессом) |

### Режимы доступа к файлам

| Код | Описание |
| :--- | :--- |
| `r` | Read — файл открыт для чтения |
| `w` | Write — файл открыт для записи |
| `u` | Read/Write — файл открыт для чтения и записи одновременно |

## Практические сценарии

### Поиск процесса по файлу или директории

```bash
# Определить, какой процесс использует конкретный файл
sudo lsof /var/log/syslog

# Рекурсивный поиск по всему дереву каталогов
sudo lsof +D /var/log

# Поиск только в указанной директории (без вложенных каталогов)
sudo lsof +d /var
```

### Анализ по пользователю или процессу

```bash
# Показать все открытые файлы процесса по его PID
sudo lsof -p 1234

# Все открытые файлы конкретного системного пользователя
sudo lsof -u www-data

# Исключить пользователя из вывода (символ '^')
sudo lsof -u ^root
```

### Мониторинг сетевой активности

```bash
# Все активные сетевые соединения системы
sudo lsof -i

# Фильтрация только по протоколу TCP
sudo lsof -i TCP

# Поиск соединений по их состоянию
sudo lsof -i TCP:ESTABLISHED
sudo lsof -i TCP:LISTEN

# Соединения с конкретным хостом или IP-адресом
sudo lsof -i @192.168.1.100
```

### Поиск процесса по порту

**Сценарий:** Сервис не запускается с ошибкой «Address already in use». Нужно найти, кто занял порт.

```bash
# Какой процесс слушает порт 80
sudo lsof -i :80

# Фильтрация только слушающих сокетов (без установленных соединений)
sudo lsof -i TCP:8080 -sTCP:LISTEN

# Быстрое получение только PID (флаг -ti — terse, только PID)
lsof -ti TCP:8080 -sTCP:LISTEN

# Бескомпромиссное убийство процесса на порту
kill $(lsof -ti TCP:8080 -sTCP:LISTEN)

# Альтернатива через утилиту fuser
sudo fuser 80/tcp

# Убить процесс на порту через fuser
fuser -k 8080/tcp
```

> **Примечание:** `ss -tlnp sport = :8080` — альтернатива без `sudo` для процессов текущего пользователя.

### Диагностика проблем с дисковым пространством

**Проблема:** Файлы логов удалены (`rm`), но команда `df -h` показывает, что место на диске не освободилось.
**Причина:** Процесс продолжает удерживать дескриптор удалённого файла.

```bash
# Найти удалённые, но всё ещё удерживаемые ресурсы
sudo lsof | grep deleted

# Альтернативный поиск по количеству ссылок (link count < 1)
sudo lsof +L1
```

**Решение:** Перезапустить сервис или обнулить файл через `/proc` (где FD — номер дескриптора):

```bash
sudo truncate -s 0 /proc/<PID>/fd/<FD>
```

### Диагностика утечек ресурсов

```bash
# Посчитать количество открытых файлов для процесса
lsof -p <PID> | wc -l

# Найти процессы пользователя с наибольшим количеством открытых файлов
lsof -u <user> | awk '{print $2}' | sort | uniq -c | sort -rn | head
```

### Работа в автоматизированных сценариях

Для использования в скриптах полезны флаги краткого вывода:

```bash
# Получить только PID процессов, использующих сетевые соединения
sudo lsof -t -i

# Вывод в машинно-ориентированном формате (поля p=PID, f=FD, n=имя)
lsof -p 1234 -F pfn
```

## Дополнительная информация

### Сравнение с аналогичными инструментами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| `fuser` | Удобен для быстрой идентификации по порту или точке монтирования | Меньше диагностических данных |
| [`ss`](../Networking/ss.md) | Специализированный инструмент для анализа сетевого стека | Не показывает файлы на диске |
| [`/proc/*/fd`](../../FileSystems/file_descriptors.md) | Прямой доступ к данным ядра без сторонних утилит | Требует ручного парсинга |

### Типичные проблемы и ошибки

| Ситуация | Решение |
| :--- | :--- |
| **Port already in use** | `lsof -i :<PORT>` → `kill -9 <PID>` |
| **Target is busy (umount)** | `lsof +D /mnt/data` → завершить найденные процессы |
| **Volume не удаляется (Docker)** | `lsof +D /var/lib/docker/volumes/...` |
| **Место не освободилось (rm)** | `lsof | grep deleted` → перезапуск процесса |
