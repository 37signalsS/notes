# Утилита `top`

## Определения

**`top`** — стандартная консольная утилита Unix-подобных систем для динамического мониторинга процессов и системных ресурсов в реальном времени. Входит в пакет `procps-ng` (Linux) или `procps` (BSD/macOS).

**Ключевые особенности:**

- Встроена в базовую поставку большинства дистрибутивов
- Минимальное потребление ресурсов центрального процессора (CPU — Central Processing Unit) и оперативной памяти (RAM — Random Access Memory)
- Поддержка пакетного режима для автоматизации
- Интерактивное управление отображением

## Основные концепции

Интерфейс `top` разделён на две части: **сводная информация** (заголовок) и **список процессов**.

### Сводная информация

#### Время и uptime

**Пример:** `top - 14:50:30 up 2 days, 4:21, 1 user, load average: 0.05, 0.08, 0.07`

| Поле | Описание |
| :--- | :--- |
| `14:50:30` | Текущее системное время |
| `up 2 days, 4:21` | Uptime — время работы системы с момента загрузки |
| `1 user` | Количество активных пользовательских сессий (см. [`w`](./w.md)) |
| `load average` | Средняя нагрузка за 1, 5, 15 минут (см. [интерпретацию LA](../../Core/processes/scheduling.md#интерпретация-load-average)) |

#### Статистика задач (Tasks)

**Пример:** `Tasks: 114 total, 1 running, 113 sleeping, 0 stopped, 0 zombie`

| Состояние | Описание |
| :--- | :--- |
| `total` | Общее количество процессов |
| `running` | Выполняются или готовы к выполнению (R) |
| `sleeping` | В прерываемом сне (S), ожидают события |
| `stopped` | Остановлены сигналом (T) |
| `zombie` | Завершены, но не освобождены родителем (Z) — см. [основные концепции процессов](../../Core/processes/basic_concepts.md) |

#### Статистика CPU (Cpu(s))

| Метрика | Описание | Когда стоит обратить внимание |
| :--- | :--- | :--- |
| `us` (user) | Пользовательские процессы | >80% — высокая нагрузка от приложений |
| `sy` (system) | Ядро и системные вызовы | >30% — проблемы с драйверами или интенсивный ввод-вывод (I/O) |
| `ni` (nice) | Процессы с изменённым приоритетом | — |
| `id` (idle) | Простой процессора | <20% — система под высокой нагрузкой |
| `wa` (iowait) | Ожидание завершения операций ввода-вывода (I/O) | >15% — bottleneck дисковой подсистемы, см. [`iotop`](../Filesystem/iotop.md) |
| `hi` (hardware irq) | Аппаратные прерывания | >10% — возможные проблемы с оборудованием |
| `si` (software irq) | Программные прерывания | Высокое значение часто указывает на сетевую нагрузку |
| `st` (steal) | Время, «украденное» гипервизором | >5% — перегрузка хоста виртуализации |

> **Важно:** Низкий `iowait` не гарантирует отсутствие проблем с диском. Если задержка `await` в [`iostat -x`](../Filesystem/iostat.md) высока, а очередь `avgqu-sz` растёт — диск перегружен.

#### Детальное описание Steal Time (st)

**Steal time** — это время, в течение которого виртуальная машина (VM) готова к выполнению, но не получает доступ к физическому CPU из-за конкуренции с другими VM на том же гипервизоре.

**Причины возникновения:**

1. **Перегрузка хоста:** Слишком много виртуальных машин на одно физическое ядро.
2. **«Шумные соседи»:** Другие VM потребляют избыточное количество ресурсов.

**Диагностика и решение:**
При значении `st > 5%` производительность приложений может значительно снизиться. Для критичных сервисов рекомендуется использовать привязку к ядрам (CPU pinning). Подробнее: [CPU Pinning](../../Core/cpu_pinning.md).

#### Память (KiB Mem / KiB Swap)

**Пример:**

```
KiB Mem :  2048000 total,  130000 free, 1200000 used,  718000 buff/cache
KiB Swap:  1024000 total,  800000 free,  224000 used. 1800000 avail Mem
```

| Поле | Описание |
| :--- | :--- |
| `total` | Общий объём оперативной памяти или swap |
| `free` | Полностью свободная память |
| `used` | Память, занятая процессами |
| `buff/cache` | Буферы и кэш страницы — освобождаются ядром при необходимости |
| `avail Mem` | Реально доступная память для запуска новых приложений |

Подробный разбор метрик памяти: [метрики памяти процесса](../../Core/memory/process_memory_metrics.md).

### Список процессов

| Столбец | Описание |
| :--- | :--- |
| `PID` | Идентификатор процесса |
| `USER` | Владелец процесса |
| `PR` | Приоритет планировщика (может быть `rt` — real-time) |
| `NI` | Значение nice (приоритет от -20 до +19) |
| `VIRT` | Виртуальная память (VSS — Virtual Set Size) |
| `RES` | Резидентная память (RSS — Resident Set Size) — фактически занятая RAM |
| `SHR` | Разделяемая память |
| `S` | Состояние процесса (R, S, D, Z, T) |
| `%CPU` | Процент использования CPU (100% = одно ядро) |
| `%MEM` | Процент использования физической памяти |
| `TIME+` | Суммарное время использования CPU |
| `COMMAND` | Команда запуска |

## Практические сценарии

### Интерактивный режим

```bash
# Базовый запуск
top

# Обновление каждые 2 секунды
top -d 2

# Мониторинг конкретного процесса
top -p <PID>

# Сортировка по потреблению памяти при запуске
top -o %MEM
```

#### Горячие клавиши

| Клавиша | Действие |
| :--- | :--- |
| `1` | Показать загрузку по каждому ядру CPU отдельно |
| `H` | Режим отображения потоков (threads) |
| `M` | Сортировка по использованию памяти (`RES`) |
| `P` | Сортировка по загрузке CPU (по умолчанию) |
| `T` | Сортировка по суммарному времени работы процесса (`TIME+`) |
| `k` | Завершить процесс (kill) по PID |
| `u` | Фильтр по имени пользователя |
| `W` | Сохранить текущие настройки в конфигурационный файл |
| `q` | Выход |

### Пакетный режим для скриптов

```bash
# Сохранить один снимок состояния в файл
top -bn1 > system_state.txt

# Получить только строку с загрузкой CPU
top -bn1 | grep "Cpu(s)"
```

### Диагностика проблем

1. **Высокая нагрузка:** Отсортировать процессы по `%CPU` (клавиша `P`) и проверить состояние `st` (steal time).
2. **Диагностика потоков:** Если процесс грузит CPU, но непонятно, какая часть кода виновата, используйте режим отображения потоков (клавиша `H`) для поиска конкретного **TID**. Подробнее: **[Поиск проблемного потока внутри процесса](./thread_cpu_troubleshooting.md)**.
3. **Ожидание ввода-вывода:** Если `wa` (iowait) высокий, использовать [`iotop`](../Filesystem/iotop.md) для поиска виновника.
4. **Утечки памяти:** Мониторить рост `RES` у процессов и проверять доступную память в строке `avail Mem`.

## Дополнительная информация

### Сравнение с аналогами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| [`htop`](./htop.md) | Более наглядный интерфейс, поддержка мыши | Часто требует отдельной установки |
| [`atop`](../Performance/atop.md) | Ведение исторических логов | Сложнее в освоении |
| [`ps`](./ps.md) | Идеален для разовых снимков и простых скриптов | Не динамический |

### Ограничения

- **Отсутствие истории:** `top` показывает только текущее состояние. Для ретроспективного анализа используйте [`sar`](../Performance/sar.md) или [`atop`](../Performance/atop.md).
- **Точность памяти:** Для глубокого анализа разделяемой памяти лучше использовать [`smem`](../Memory/smem.md).
