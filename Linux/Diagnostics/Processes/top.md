# top

### Определения

`top` — это стандартная консольная утилита в Unix-подобных системах, которая предоставляет динамический, обновляемый в реальном времени обзор запущенных процессов и использования системных ресурсов, таких как CPU и оперативная память.

### Основные концепции

Интерфейс `top` разделен на две основные части: **сводная информация** (вверху) и **список процессов** (внизу).

#### 1. Сводная информация (Header)

Первые строки вывода `top` содержат общую информацию о состоянии системы.

**Пример:** `top - 14:50:30 up 2 days,  4:21,  1 user,  load average: 0.05, 0.08, 0.07`

- **`top - 14:50:30`**: Текущее системное время.
- **`up 2 days, 4:21`**: Uptime — время работы системы без перезагрузки.
- **`1 user`**: Количество активных пользовательских сессий. Информацию о залогиненных пользователях также можно увидеть с помощью утилиты `w`.
- **`load average: 0.05, 0.08, 0.07`**: Средняя нагрузка (Load Average) за последние 1, 5 и 15 минут. Подробнее см. в заметке о [**планировщике и LA**](../Core/processes/scheduling.md#load-average-la).

**Статистика по задачам — `Tasks`**

**Пример:** `Tasks: 114 total,   1 running, 113 sleeping,   0 stopped,   0 zombie`

Эта строка показывает распределение процессов по их состояниям:
- **`total`**: Общее количество процессов в системе.
- **`running`**: Количество процессов, которые в данный момент либо выполняются на CPU, либо находятся в очереди на выполнение.
- **`sleeping`**: Количество процессов, которые находятся в прерываемом сне (`S`), ожидая события.
- **`stopped`**: Количество остановленных процессов (состояние `T`), например, сигналом `SIGSTOP`.
- **`zombie`**: Количество "зомби"-процессов (состояние `Z`). Подробное описание этого состояния и связанных с ним рисков см. в [**Обзоре процессов в Linux**](../../Core/processes/overview.md#чем-опасны-зомби-процессы).

**Показатели CPU — `Cpu(s)`**

Строка `Cpu(s)` показывает, как процессорное время распределяется между различными задачами (в процентах).

- **`us` (user)**: Время выполнения пользовательских процессов. Высокое значение указывает на активную работу приложений.
- **`sy` (system)**: Время выполнения кода ядра. Высокое значение может свидетельствовать о проблемах с драйверами или интенсивном вводе-выводе.
  > Это время, которое процессор тратит на **системные вызовы (syscalls)**. Системный вызов — это механизм, с помощью которого приложение запрашивает у ядра операционной системы выполнение какой-либо операции, например, чтение файла с диска, отправку данных по сети или создание нового процесса.
- **`ni` (nice)**: Время, выделенное процессам с измененным (пониженным) приоритетом.
- **`id` (idle)**: Время простоя процессора.
- **`wa` (iowait)**: Время ожидания завершения операций ввода-вывода (диск, сеть). Высокое значение (`>15-20%`) — ключевой признак того, что узким местом является дисковая или сетевая подсистема. Для поиска виновника используется [iotop](./iotop.md).
- **`hi` (hardware interrupts)**: Время обработки аппаратных прерываний. Это процессорное время, затраченное на обслуживание запросов от аппаратных устройств (например, сетевой карты, дискового контроллера, клавиатуры).
- **`si` (software interrupts)**: Время обработки программных прерываний, которые часто связаны с сетевыми пакетами, таймерами, межпроцессным взаимодействием или системными вызовами, связанными с I/O.
- **`st` (steal)**: "Украденное" время, актуально для виртуальных машин. Показывает, сколько CPU-времени гипервизор отнял у виртуальной машины или машин для своих нужд. Для физического компьютера этот параметр всегда равен нулю.

**Статистика по памяти — `KiB Mem` и `KiB Swap`**

**Пример:**
`KiB Mem :  2048000 total,   130000 free,  1200000 used,   718000 buff/cache`
`KiB Swap:  1024000 total,   800000 free,   224000 used.  1800000 avail Mem`

- **`KiB Mem`**: Статистика по физической памяти (RAM).
  - **`total`**: Общий объем установленной RAM.
  - **`free`**: Объем полностью свободной, неиспользуемой памяти. **Это значение часто бывает обманчиво мало.**
  - **`used`**: Объем памяти, используемый процессами.
  - **`buff/cache`**: Объем памяти, используемый ядром для кэширования дисковых операций (buffers/cache). Linux агрессивно использует свободную RAM для кэша, чтобы ускорить доступ к данным. Эта память считается "доступной" и будет немедленно освобождена, если приложениям потребуется больше RAM.
- **`KiB Swap`**: Статистика по файлу/разделу подкачки.
  - **`total`**, **`free`**, **`used`**: Общий, свободный и используемый объем swap-пространства.
  - **`avail Mem`**: (В строке Swap) Примерный объем памяти, доступный для запуска новых приложений без использования swap. Это более реалистичная оценка "свободной" памяти, чем поле `free`.

> **Ключевой принцип:** Не стоит беспокоиться, если поле `free` показывает малое значение. Реально доступная память — это сумма `free` и `buff/cache`. Пока система не использует активно `swap`, с памятью, скорее всего, все в порядке.

#### 2. Список процессов

- **`PID`**: Идентификатор процесса.
- **`USER`**: Пользователь, от имени которого запущен процесс.
- **`PR`**, **`NI`**: Приоритет и "Nice" значение процесса.
- **`VIRT`**: Объем **виртуальной памяти**, запрошенной процессом.
- **`RES`**: Объем **резидентной (физической) памяти**, фактически занимаемый в ОЗУ.
- **`SHR`**: Объем **разделяемой памяти**.
- **`S`**: Состояние процесса (R, S, D, Z, T). Подробное описание каждого состояния см. в [**Обзор процессов в Linux**](../../Core/processes/overview.md#состояния-процесса).
- **`%CPU`**: Процент использования CPU одним процессом.
- **`%MEM`**: Процент использования физической памяти.
- **`TIME+`**: Общее процессорное время, использованное процессом с момента запуска.
- **`COMMAND`**: Команда, которой был запущен процесс.

> Детальный разбор метрик потребления памяти (`VIRT`, `RES` и др.) вы найдете в заметке [**Мониторинг памяти**](../Memory/process_memory_metrics.md).

### Практические сценарии

#### Интерактивные команды

В `top` можно использовать горячие клавиши для управления отображением:

- **`1`**: Переключить отображение между суммарной статистикой по CPU и статистикой по каждому ядру отдельно. Помогает выявить неравномерную нагрузку.
- **`Shift + H`**: Переключить режим отображения с процессов на потоки. Незаменимо для анализа многопоточных приложений.
- **`s`**: Изменить интервал обновления (в секундах).
- **`k`**: "Убить" процесс (потребуется ввести PID и сигнал).
- **`Shift + P`**: Отсортировать процессы по использованию CPU (по умолчанию).
- **`Shift + M`**: Отсортировать процессы по использованию памяти (`RES`).

#### Пакетный режим

`top` можно использовать для сбора данных в неинтерактивном режиме, что полезно для логирования и анализа.

```bash
# Сделать 3 "снимка" с интервалом в 5 секунд и сохранить в файл
top -b -n 3 -d 5 > top_log.txt
```

- **`-b`**: Включает пакетный режим.
- **`-n`**: Количество "снимков", которые нужно сделать перед завершением.

---

### Дополнительная информация

- **`%CPU` > 100%**: Значение 100% в колонке `%CPU` соответствует полной загрузке **одного процессорного ядра**. Многопоточные приложения могут показывать значения более 100% (например, 200% для двух ядер), что является нормой и говорит об эффективном использовании нескольких ядер.
- **Альтернативы**: Для более удобного интерактивного анализа часто используются [**htop**](./htop.md) и [**atop**](../Performance/atop.md), а также [**systemd-cgtop**](../../Core/systemd/cgtop.md) для мониторинга использования ресурсов Control Groups.
