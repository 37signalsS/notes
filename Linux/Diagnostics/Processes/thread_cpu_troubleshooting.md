# Поиск потока, потребляющего CPU внутри процесса

## Определения

*   **TID (Thread ID)** — идентификатор потока на уровне ядра Linux (также называется **LWP — Light Weight Process**). В рамках одного процесса (PID) каждый поток имеет уникальный TID.
*   **PID (Process ID)** — идентификатор основного процесса. Для однопоточного приложения PID и TID совпадают.
*   **Call Graph (Граф вызовов)** — иерархия вызовов функций, позволяющая понять, какая функция вызвала текущую.

## Этап 1: Идентификация проблемного потока (top)

Классический `top` показывает суммарную нагрузку на процесс. Чтобы увидеть нагрузку по потокам, используется режим **Threads**.

```bash
# Запуск top для конкретного процесса в режиме отображения потоков
top -H -p <PID>
```

**Действия:**
1. Нажмите `H`, чтобы переключиться в режим отображения потоков (если запустили без флага `-H`).
2. В столбце `PID` (который в этом режиме отображает **TID**) найдите потоки с максимальным значением `%CPU`.
3. Запомните **TID** самого активного потока.

---

## Этап 2: Профилирование потока (perf)

Утилита `perf` позволяет понять, в каких именно функциях поток проводит больше всего времени.

### Профилирование всего процесса
Если нужно увидеть общую картину по всем потокам процесса:

```bash
# Запись профиля процесса на 30 секунд с построением графа вызовов (-g)
sudo perf record -g -p <PID> sleep 30

# Просмотр отчета
sudo perf report
```

### Профилирование конкретного потока
Для детального анализа только одного TID:

```bash
# Запись профиля конкретного потока
sudo perf record -g -t <TID> sleep 30

# Просмотр отчета с фильтром по TID
sudo perf report --tid <TID>
```

В интерактивном меню `perf report` функции отсортированы по **Overhead** (нагрузке). Используйте клавишу `Enter`, чтобы «раскрыть» стек вызовов и увидеть, какая логика приложения приводит к нагрузке.

## Этап 3: Снимок состояния (gdb)

Если нужно быстро посмотреть, что поток делает прямо сейчас («заморозить» его), используется отладчик `gdb`.

### Соответствие TID и потоков GDB
У `gdb` своя нумерация потоков, которая не совпадает с системным TID. Чтобы сопоставить их:

```bash
# Подключение к процессу
sudo gdb -p <PID>

# Вывод списка всех потоков
(gdb) info threads
```

В выводе `info threads` ищите значение `LWP <TID>`. Оно соответствует TID из `top`.

### Анализ стека вызовов
Переключитесь на нужный поток и посмотрите его состояние:

```bash
# Переключение на поток по номеру из левой колонки gdb (Id)
(gdb) thread <N>

# Вывод текущего стека вызовов
(gdb) bt

# Вывод стека с локальными переменными (более детально)
(gdb) bt full
```

### Снятие стека всех потоков (Batch mode)
Для быстрого сохранения состояния всех потоков без интерактивного режима:

```bash
sudo gdb -p <PID> -batch -ex "thread apply all bt" 2>/dev/null
```

---

## Резюме: Алгоритм действий

1.  **Найти TID:** `top -H -p <PID>` → найти самый тяжелый TID.
2.  **Профилировать:** `perf record -g -t <TID> sleep 30` → понять, какая функция «горячая».
3.  **Проверить стек:** `gdb -p <PID>` → `info threads` → `thread <N>` → `bt` → увидеть контекст выполнения кода в реальности.
