# Утилита `w`

## Определения

**`w`** — стандартная системная утилита в Linux (часть пакета `procps-ng`), предназначенная для отображения информации о пользователях, находящихся в системе в данный момент, и их текущей активности.

Утилита является «комбайном», который агрегирует данные из `/var/run/utmp` и файловой системы `/proc`, фактически объединяя функционал `uptime`, `who` и [`ps`](./ps.md).

## Основные концепции

### Источники данных

`w` получает информацию из нескольких ключевых мест:
- **`utmp`** (`/var/run/utmp`): текущие активные сессии.
- **`/proc`**: информация о процессах (PID, использование CPU).
- **`/proc/loadavg`**: средняя нагрузка на систему.

### Структура вывода

Вывод утилиты состоит из заголовочной строки и таблицы пользователей.

#### Заголовочная строка (Header)
Аналогична выводу команды `uptime`.
```bash
 14:20:01 up 45 days, 12:05,  3 users,  load average: 0.15, 0.08, 0.02
```
| Поле | Описание |
| :--- | :--- |
| `14:20:01` | Текущее системное время. |
| `up 45 days...` | Время аптайма системы. |
| `3 users` | Общее количество активных сессий. |
| `load average` | Средняя нагрузка за 1, 5 и 15 минут. |

Для интерпретации Load Average в production-среде используйте нормализацию по числу ядер. Подробнее: [Планирование процессов: интерпретация LA](../../Core/processes/scheduling.md#интерпретация-load-average).

#### Таблица пользователей
```text
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU WHAT
admin    pts/0    10.0.0.5         12:00    1:20s  0.15s  0.05s htop
guest    tty1     -                14:10    5.00s  0.01s  0.01s -bash
```

| Столбец | Описание |
| :--- | :--- |
| `USER` | Имя залогиненного пользователя. |
| `TTY` | Имя терминала (например, `tty1` для локальных консолей или `pts/X` для SSH). |
| `FROM` | Удалённый хост или IP-адрес (если применимо). |
| `LOGIN@` | Время входа пользователя в систему. |
| `IDLE` | Время бездействия (с момента последнего нажатия клавиши). |
| `JCPU` | **Job CPU**: Суммарное время CPU всех процессов, запущенных на данном терминале. |
| `PCPU` | **Process CPU**: Время CPU текущего процесса, указанного в поле `WHAT`. |
| `WHAT` | Текущая выполняемая команда (с аргументами). |

## Практические сценарии

### Быстрая диагностика активности

```bash
# Базовый вывод
w

# Вывод без заголовка (удобно для скриптов)
w -h

# Показать только конкретного пользователя
w username

# Интерактивное обновление (раз в секунду)
watch -n 1 w
```

### Анализ удалённых подключений

```bash
# Отображение IP-адресов вместо имен хостов (ускоряет работу при проблемах с DNS)
w -n

# Переключение отображения поля FROM (зависит от настроек дистрибутива по умолчанию)
w -f
```

### Детальный мониторинг процессов

```bash
# Показать PID процессов в поле WHAT (современная опция procps-ng)
w -p
# → user1 pts/0 10.0.0.5 10:30 1.02s 0.05s 0.01s htop [12345]

# Короткий формат (без времени CPU)
w -s
```

### Использование в конвейерах (Pipelines)

```bash
# Подсчет количества уникальных пользователей в системе
w -h | awk '{print $1}' | sort -u | wc -l

# Поиск пользователей, использующих конкретную оболочку или инструмент
w | grep 'zsh'
```

### Диагностика инцидентов (Incident Response)

При получении алерта о высокой нагрузке или подозрительной активности `w` используется как первый инструмент для оценки состояния узла:

```bash
# Шаг 1: Общая оценка (аналог uptime, но с детализацией по пользователям)
w -h
# → load average: 4.20, 3.80, 3.50  — сравните с числом ядер (nproc)

# Шаг 2: Определение источников нагрузки
# Сортируем пользователей по JCPU (суммарная нагрузка на терминал)
w -h | sort -k4 -rn | head -5

# Шаг 3: Перекрестная проверка с top/ps
# Если PCPU у пользователя близок к 100%, привязываемся к конкретному PID
w -p | awk 'NR>1 && $7 > 0.5 {print $1, $8}' | while read user pid; do
  echo "Пользователь $user, PID: $pid"
  ps -p "$pid" -o pid,ppid,user,%cpu,%mem,stat,start,time,comm
done
```

### Аудит безопасности

```bash
# Поиск неожиданных удалённых подключений
w -n | awk 'NR>1 {print $3}' | sort -u

# Проверка активности от несистемных пользователей (UID >= 1000)
w -h | awk 'NR>1 && $1 !~ /^(root|admin|ubuntu|centos|ec2-user)$/ {print $0}'

# Обнаружение сессий с аномально высокой нагрузкой на терминал (возможен brute-force или майнинг)
w -h | awk 'NR>1 && $4+0 > 5.0 {print $0}'
```

### Мониторинг и автоматизация

```bash
#!/bin/bash
# check_user_activity.sh — мониторинг активности пользователей для SRE
THRESHOLD=3600  # 1 час бездействия

while read -r user tty from login idle jcpu pcpu what; do
  # Пропускаем заголовок и системных пользователей
  [[ "$user" =~ ^(USER|root|admin)$ ]] && continue

  # Конвертируем IDLE в секунды для сравнения
  idle_secs=$(echo "$idle" | awk -F'[m s]' '{if ($2 == "") print $1; else print $1*60+$3}')

  if [ "$idle_secs" -gt "$THRESHOLD" ]; then
    echo "[WARN] Пользователь $user бездействует ${idle} на $tty"
  fi
done < <(w -h)

# Интеграция с journald для аудита (требует systemd)
# Журналирование входов/выходов через loginctl см. в [Управление сессиями systemd](../../../Linux/Core/systemd/logind_session_management.md)
```

### Корреляция Load Average и процессов пользователя

```bash
# Получаем LA из заголовка w и сравниваем с количеством ядер
LA=$(w -h | awk -F'load average: ' '{print $2}' | awk -F', ' '{print $1}')
NCORES=$(nproc)

if (( $(echo "$LA > $NCORES" | bc -l) )); then
  echo "LA ($LA) превышает число ядер ($NCORES). Анализ пользовательских процессов:"
  w -h | sort -k4 -rn | head -5
else
  echo "Нагрузка в норме: LA=$LA, cores=$NCORES"
fi
```

## Устранение неисправностей

### Типичные ошибки и их причины

| Симптом | Причина | Диагностика | Решение |
| :--- | :--- | :--- | :--- |
| `w` показывает только текущего пользователя, хотя другие точно онлайн | Включен `hidepid` в `/proc` | `grep hidepid /proc/mounts` | Используйте `sudo` или отключите `hidepid` для диагностических целей |
| В поле `FROM` отображается `-` для SSH-сессий | `UseDNS no` в `sshd_config` или PAM не логирует | `grep UseDNS /etc/ssh/sshd_config` | Включите `UseDNS yes` или полагайтесь на IP (`w -n`) |
| IPv6-адрес обрезается в `FROM` | `PROCPS_FROMLEN` слишком мал или старая версия `procps` | `echo $PROCPS_FROMLEN` | Установите `PROCPS_FROMLEN=40` или обновите пакет |
| `w` не видит графические сессии в systemd | N/A | `loginctl list-sessions` vs `w` | Это ожидаемо: `w` читает `utmp`, который может не записываться GUI-сессиями |
| Поле `WHAT` показывает обобщённую команду (`-bash`, `sshd:`) | Нормальное поведение PTY/SSH | N/A | Используйте `w -p` + `ps -p <PID> -o args=` для полной командной строки |

### Частые проблемы

**1. Нет данных в `utmp`**
```bash
# Проверка целостности utmp
sudo utmpdump /var/run/utmp | head -20

# Если файл поврежден, перезагрузите систему (utmp пересоздается при загрузке)
```

**2. Подозрительная активность при нормальном LA**
```bash
# Пользователь бездействует долго, но процесс активен (возможен ботнет)
w -h | awk 'NR>1 && $5 !~ /-/ && $5+0 > 3600 {print $0}'

# Дополнительная проверка через ps
ps -u suspicious_user -o pid,stat,%cpu,%mem,cmd
```

**3. Неожиданные пользователи в системе**
```bash
# Список всех пользователей с shell и активной сессией
w -h | awk 'NR>1 {print $1}' | sort -u | while read u; do
  getent passwd "$u"
done
```

## Валидация и верификация

### Проверка корректности работы

```bash
# 1. Сравнение количества сессий w и who
w_users=$(w -h | tail -n +2 | wc -l)
who_users=$(who | wc -l)
echo "w: $w_users, who: $who_users"
# → Должно совпадать (или отличаться не более чем на 1 из-за race condition)

# 2. Проверка актуальности данных utmp
sudo stat /var/run/utmp
# → Modify time должен быть не старше нескольких секунд

# 3. Валидация заголовка Load Average
head -1 /proc/loadavg
# → Сравните с выводом w
```

### Верификация в production-среде

```bash
# Снимок состояния для отчёта
{
  echo "=== $(date) ==="
  echo "--- w ---"
  w -h
  echo "--- ps по терминалам ---"
  w -h | awk 'NR>1 {print $2}' | while read tty; do
    ps -t "$tty" -o pid,ppid,user,%cpu,%mem,stat,cmd
  done
} > /tmp/snapshot_$(hostname)_$(date +%Y%m%d_%H%M%S).txt
```

## Рекомендации и очистка

### Best Practices

1. **Используйте `w` как первый инструмент в методологии быстрой диагностики** (см. [Быструю диагностику](../../Diagnostics/Troubleshooting/rapid_assessment.md)). Он даёт контекст за 1 секунду.
2. **Не полагайтесь только на `WHAT`**: поле отражает `argv[0]`, который можно подменить. Для доверия используйте `w -p` + `readlink /proc/<PID>/exe` или `ps -p <PID> -o args=`.
3. **Комбинируйте с `top`/`htop`**: `w` показывает пользователя, но не детали памяти. Для полной картины используйте [`top`](./top.md) с сортировкой по `%CPU` или `RES`.
4. **Коррелируйте LA с типом процессов**: высокий LA при низком `%CPU` в `w` указывает на I/O-bound процессы (состояние `D`). Детали: [Диагностика I/O](../../Diagnostics/Performance/DiskIO/).
5. **Логируйте подозрительные `FROM`**: при настройке SSH (например, [усиление SSH-сервера](../../Security/ssh/server/ssh_hardening_best_practices.md)) фиксируйте внешние IP в SIEM.

### Очистка и безопасность

- **Завершение неавторизованных сессий**: `loginctl terminate-session <ID>` (предпочтительно) или `pkill -u <user>`.
- **Очистка `utmp`**: при повреждении файла система пересоздаст его при загрузке. Для срочной очистки без перезагрузки используйте `utmpdump` + `utmpdump -r` (осторожно).
- **Удаление следов**: `w` не пишет логи. Для аудита входов используйте `last`, `lastlog`, `journalctl -u systemd-logind`.

## Ограничения и крайние случаи

### Известные ограничения

- **Графические сессии**: в некоторых окружениях GNOME/KDE сессии могут не регистрироваться в `utmp`, поэтому `w` их не покажет. Используйте `loginctl list-sessions` как источник истины.
- **Контейнеры**: внутри контейнера `w` работает, но покажет только процессы контейнера. Для хостовой информации требуется доступ к `/proc` хоста.
- **Масштаб**: на узлах с сотнями сессий вывод `w` может быть неудобен. Используйте `w -h | awk ...` для агрегации.
- **Время бездействия (IDLE)**: resets при любом событии ввода (включая мышь в X11). Для точного отслеживания активности используйте `auditd` или `ttyload`.
- **PTY vs TTY**: `w` не различает физические консоли и виртуальные терминалы (pts) в поле `TTY` кроме обозначения. Для определения физического устройства используйте `who -Hu`.

### Поведение в нестандартных сценариях

- **SSH с `ForceCommand`**: поле `WHAT` покажет принудительную команду, а не оболочку.
- **tmux/screen**: `w` показывает `tmux: client` или `screen` как текущий процесс. Для деталей используйте `tmux list-sessions` / `screen -ls`.
- **NFS и зависшие процессы**: процессы в `D-state` (ожидание NFS) увеличивают Load Average, но не потребляют CPU. `w` покажет их в таблице, но `PCPU` будет 0. Детали: [Uninterruptible Sleep](../../Diagnostics/Performance/DiskIO/invisible_io.md).
- **hidepid**: если `/proc` смонтирован с `hidepid=2`, обычный пользователь увидит только свои процессы в `WHAT`. Используйте `sudo w` для полной картины.

## Дополнительная информация

### Основные опции

| Короткая | Длинная | Описание |
| :--- | :--- | :--- |
| `-h` | `--no-header` | Не выводить заголовочную строку. |
| `-u` | `--no-current` | Игнорировать текущий процесс при расчете PCPU. |
| `-s` | `--short` | Краткий формат: убирает LOGIN@, JCPU и PCPU. |
| `-f` | `--from` | Переключить отображение столбца FROM. |
| `-i` | `--ip-addr` | Показывать IP-адрес вместо хоста (синоним `-n` в некоторых версиях). |
| `-p` | `--pids` | Показать PID текущего процесса в WHAT. |
| `-o` | `--old-style` | Использовать «старый» формат вывода (с пустыми полями для IDLE < 1 мин). |

### Переменные окружения

Использование переменных позволяет настроить поведение `w` без передачи флагов:

- **`PROCPS_USERLEN`**: определяет ширину столбца USER (по умолчанию 8). Полезно для длинных системных имен.
- **`PROCPS_FROMLEN`**: определяет ширину столбца FROM (по умолчанию 16). Полезно для IPv6 или длинных FQDN.

### Сравнение инструментов мониторинга сессий

| Инструмент | Уровень | Ключевая особенность |
| :--- | :--- | :--- |
| `w` | Процессный | Показывает, **что** делает пользователь прямо сейчас. |
| `who` | Сессионный | Только список вошедших пользователей и их терминалы. |
| `last` | Исторический | Информация о прошлых входах из `/var/log/wtmp`. |
| `loginctl` | Systemd | Управление сессиями на уровне `systemd-logind`. |

### Модернизация: `w` vs `loginctl`

В современных системах с `systemd` утилита `w` всё еще полезна для быстрой оценки активности CPU, однако `loginctl` предоставляет больше контроля над самой сессией:

```bash
# Список всех сессий через systemd
loginctl list-sessions

# Подробная информация о конкретной сессии (включая cgroups)
loginctl show-session <ID>

# Завершение сессии пользователя
loginctl terminate-session <ID>
```

### Безопасность и ограничения

- **Права доступа**: Обычный пользователь может запускать `w`, но если в системе включен механизм `hidepid` для `/proc`, `w` может не увидеть процессы других пользователей в поле `WHAT`.
- **Зависимость от `utmp`**: Если приложение (например, некоторые эмуляторы терминалов в GUI или специфичные SSH-конфигурации) не регистрирует сессию в `utmp`, `w` её не увидит.
- **Маскировка**: Опытные пользователи могут изменять `argv[0]` своих процессов, что отразится в поле `WHAT`, вводя администратора в заблуждение.
- **IPv6**: В старых версиях `procps` поле `FROM` может обрезать длинные IPv6-адреса. Рекомендуется использовать `PROCPS_FROMLEN`.
