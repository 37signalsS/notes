# `ps`

## Определения

**`ps`** (process status) — стандартная утилита для создания снимка (snapshot) текущих процессов системы. Входит в пакет `procps-ng` (Linux) или `procps` (BSD/macOS).

**Ключевые особенности:**

- Предоставляет статичный снимок на момент вызова (в отличие от [`top`](./top.md)/[`htop`](./htop.md))
- Встроена в базовую поставку всех дистрибутивов
- Гибкий формат вывода для скриптовой автоматизации
- Поддержка нескольких стилей опций (BSD, System V, GNU)

## Основные концепции

### Стили опций

`ps` поддерживает три стиля опций, что часто вызывает путаницу:

| Стиль | Пример | Особенности |
| :--- | :--- | :--- |
| **BSD** | `ps aux` | Без дефиса, наиболее популярен |
| **System V** | `ps -ef` | С одним дефисом, POSIX-совместимый |
| **GNU** | `ps -eo pid,comm` | С длинными опциями, максимальная гибкость |

> **Рекомендация:** Используйте BSD-стиль (`aux`) для интерактивной работы и GNU-стиль (`-o`) для скриптов.

### Ключевые поля

| Поле | Описание |
| :--- | :--- |
| `USER` | Владелец процесса |
| `PID` | Идентификатор процесса |
| `PPID` | Идентификатор родительского процесса |
| `%CPU` | Процент использования CPU |
| `%MEM` | Процент использования памяти |
| `VSZ` / `VIRT` | Виртуальная память (КБ) — см. [process_memory_metrics.md](../../Core/memory/process_memory_metrics.md) |
| `RSS` / `RES` | Резидентная память (КБ) |
| `TTY` | Терминал управления |
| `STAT` | Состояние процесса (см. ниже) |
| `START` | Время запуска |
| `TIME` | Суммарное время CPU |
| `COMMAND` / `CMD` | Командная строка |

#### Состояния процессов (STAT)

| Код | Описание |
| :--- | :--- |
| `R` | Running — выполняется или готов к выполнению |
| `S` | Sleeping — прерываемый сон (ожидание события) |
| `D` | Disk sleep — непрерываемый сон (ожидание I/O) |
| `Z` | Zombie — завершён, не освобождён родителем |
| `T` | Stopped — остановлен сигналом |
| `I` | Idle — бездействующий поток |

**Модификаторы:** `<` (высокий приоритет), `N` (низкий приоритет), `s` (лидер сессии), `+` (фоновый процесс)

Подробно: [basic_concepts.md](../../Core/processes/basic_concepts.md#состояния-процесса).

## Практические сценарии

### Базовый просмотр процессов

```bash
# Все процессы (BSD-стиль, наиболее популярный)
ps aux

# Все процессы (System V-стиль)
ps -ef

# Только процессы текущего пользователя
ps

# Процессы текущего терминала
ps T
```

### Поиск процессов

```bash
# Найти процессы по имени (классический способ)
ps aux | grep nginx

# Найти процессы без grep в выводе
ps aux | grep '[n]ginx'

# Точный поиск по имени процесса (GNU-стиль)
ps -C nginx

# Найти процессы пользователя
ps -u www-data

# Найти процессы по PID
ps -p 1234,5678,9012
```

### Древовидное отображение

```bash
# BSD-стиль
ps auxf

# System V-стиль
ps -ef --forest

# Только дерево для конкретного процесса
ps --ppid 1234 -f
```

Показывает иерархию родительско-дочерних процессов. Полезно для понимания зависимостей сервисов.

### Сортировка процессов

```bash
# Топ-10 по потреблению памяти
ps aux --sort=-%mem | head -n 11

# Топ-10 по потреблению CPU
ps aux --sort=-%cpu | head -n 11

# Сортировка по времени запуска (старые процессы)
ps aux --sort=start_time

# Сортировка по использованию памяти (возрастание)
ps aux --sort=%mem
```

### Кастомный формат вывода

Флаг `-o` позволяет указать точный набор полей для вывода:

```bash
# Указать конкретные поля
ps -eo pid,%cpu,%mem,comm

# Свои заголовки столбцов
ps -eo pid,comm:20,%cpu,%mem

# Вывод для скриптов (без заголовков)
ps -eo pid,comm --no-headers

# Подробный вывод с аргументами
ps -eo pid,user,args
```

**Полезные поля для `-o`:**

- `pid` — ID процесса
- `ppid` — ID родителя
- `comm` — имя команды
- `args` — полная командная строка
- `%cpu`, `%mem` — процент использования
- `etime` — время жизни процесса
- `lstart` — точное время запуска
- `state` — состояние

### Мониторинг в реальном времени

```bash
# Обновляемый вывод (аналог top, но для ps)
watch -n 1 'ps aux --sort=-%cpu | head -n 10'

# Непрерывный мониторинг процесса
watch -n 2 'ps -p 1234 -o pid,%cpu,%mem,etime,args'
```

### Скриптовая автоматизация

```bash
# Получить PID процесса по имени
PID=$(ps -C nginx -o pid=)

# Проверить, запущен ли процесс
if ps -p "$PID" > /dev/null; then
    echo "Process $PID is running"
fi

# Посчитать количество процессов пользователя
ps -u www-data --no-headers | wc -l

# Найти все zombie-процессы
ps aux | awk '$8 ~ /Z/ {print $2}'

# Завершить все процессы с именем "test"
ps -C test -o pid= | xargs kill
```

### Диагностика проблем

#### Поиск процессов, потребляющих ресурсы

```bash
# Топ-5 по CPU
ps aux --sort=-%cpu | head -n 6

# Топ-5 по памяти
ps aux --sort=-%mem | head -n 6

# Процессы с высоким временем CPU
ps -eo pid,comm,%cpu,time --sort=-%cpu | head -n 10
```

#### Поиск zombie-процессов

```bash
# Все зомби
ps aux | awk '$8 ~ /Z/ {print}'

# Только PID зомби
ps aux | awk '$8 ~ /Z/ {print $2}'
```

**Что такое зомби-процесс (Zombie)?**
Это процесс, который завершил выполнение (вызвал `exit()`), но его запись остается в таблице процессов, пока родительский процесс не прочитает статус завершения через системный вызов `wait()`.

**Что случится, если родитель умрет раньше?**
Процесс-потомок станет «сиротой» и будет усыновлен процессом `init` (PID 1), который автоматически вызывает `wait()`, очищая таблицу процессов.

**Чем опасны зомби?**
Они не потребляют CPU или RAM, но занимают запись в таблице процессов. При их накоплении может произойти исчерпание лимита PID, что сделает невозможным запуск новых процессов в системе.

Подробно о зомби: [basic_concepts.md](../../Core/processes/basic_concepts.md).

#### Поиск процессов в состоянии D (uninterruptible sleep)

```bash
# Процессы, ожидающие I/O
ps aux | awk '$8 ~ /D/ {print}'
```

Часто указывает на проблемы с диском или сетевым ресурсом (NFS).

#### Анализ долгоживущих процессов

```bash
# Процессы, работающие дольше всех
ps -eo pid,comm,etime --sort=-etime | head -n 10

# Процессы, запущенные сегодня
ps -eo pid,comm,lstart | grep "$(date +%H:%M)"
```

## Дополнительная информация

### Сравнение с аналогами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| [`top`](./top.md) | Интерактивный, реальное время | Не для скриптов |
| [`htop`](./htop.md) | Цветной интерфейс, деревья | Требует установки |
| [`pidstat`](./pidstat.md) | Статистика с интервалом | Требует sysstat |

### Ограничения

- **Снимок:** Данные актуальны только на момент вызова
- **Нет истории:** Для исторических данных — [`atop`](../Performance/atop.md) или [`sar`](../Performance/sar.md)
- **Ограниченная детализация:** Для глубокого анализа I/O — [`pidstat`](./pidstat.md), памяти — [`smem`](../Memory/smem.md).
