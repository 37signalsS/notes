# Утилита `ps`

## Определения

**`ps`** (process status) — стандартная утилита для создания снимка (snapshot) текущих процессов системы. Входит в пакет `procps-ng` (Linux) или `procps` (BSD/macOS).

**Ключевые особенности:**

- Предоставляет статичный снимок на момент вызова (в отличие от интерактивных [`top`](./top.md) или [`htop`](./htop.md))
- Встроена в базовую поставку практически всех дистрибутивов Linux
- Обладает гибким форматом вывода, удобным для скриптовой автоматизации
- Поддерживает несколько стилей опций (BSD, System V, GNU)

## Основные концепции

### Стили опций

`ps` поддерживает три стиля написания аргументов, что часто вызывает путаницу при чтении документации:

| Стиль | Пример | Особенности |
| :--- | :--- | :--- |
| **BSD** | `ps aux` | Опции пишутся без дефиса. Самый популярный стиль в интерактивной работе. |
| **System V** | `ps -ef` | Опции пишутся с одним дефисом. POSIX-совместимый стиль. |
| **GNU** | `ps --pid 1` | Используются длинные опции с двойным дефисом. |

> **Рекомендация:** Используйте BSD-стиль (`aux`) для быстрого осмотра системы и GNU-стиль (`-o`) для точного выбора полей в скриптах.

### Ключевые поля вывода

| Поле | Описание |
| :--- | :--- |
| `USER` | Владелец процесса (эффективный пользователь) |
| `PID` | Process Identifier — уникальный идентификатор процесса |
| `PPID` | Parent Process Identifier — идентификатор родительского процесса |
| `%CPU` | Процент использования ресурсов процессора |
| `%MEM` | Процент использования оперативной памяти (RSS к общему объему) |
| `VSZ` / `VIRT` | Виртуальная память (КБ) — см. [метрики памяти](../../Core/memory/process_memory_metrics.md) |
| `RSS` / `RES` | Resident Set Size — физическая память, занятая процессом (КБ) |
| `STAT` | Текущее состояние процесса (см. ниже) |
| `START` | Время запуска процесса |
| `TIME` | Суммарное время использования CPU |
| `COMMAND` / `CMD` | Имя команды или полный путь с аргументами |

### Состояния процессов (STAT)

Код состояния может состоять из основного символа и дополнительных модификаторов.

| Код | Описание |
| :--- | :--- |
| **R** | Running — процесс выполняется или ожидает своей очереди (Runnable) |
| **S** | Sleeping — прерываемый сон (ожидание события) |
| **D** | Disk sleep — непрерываемый сон (ожидание ввода-вывода, I/O) |
| **Z** | Zombie — процесс завершён, но запись в таблице процессов ещё не удалена |
| **T** | Stopped — остановлен сигналом управления или отладчиком |
| **I** | Idle — бездействующий поток ядра |

**Основные модификаторы:**

- `<` — высокий приоритет (nice)
- `N` — низкий приоритет
- `s` — лидер сессии
- `+` — находится в группе процессов переднего плана (foreground)

Подробное описание жизненного цикла процессов: [Основные концепции процессов](../../Core/processes/basic_concepts.md#состояния-процесса).

## Практические сценарии

### Базовый просмотр процессов

```bash
# Вывод всех процессов системы (BSD-стиль)
ps aux

# Вывод всех процессов (System V-стиль)
ps -ef

# Процессы текущего пользователя в текущем терминале
ps

# Все процессы пользователя www-data
ps -u www-data
```

### Поиск и фильтрация

```bash
# Найти процесс по имени (через grep)
ps aux | grep nginx

# Найти процессы по PID
ps -p 1234,5678

# Найти все процессы, кроме указанного пользователя
ps -U root -u root -N
```

### Древовидное отображение и иерархия

Помогает понять, какой процесс запустил текущий (например, какой worker принадлежит какому master-процессу).

```bash
# Дерево процессов (BSD-стиль)
ps auxf

# Дерево с отображением PPID (System V)
ps -ef --forest

# Только дочерние процессы для конкретного PID
ps --ppid 1234
```

### Сортировка по ресурсам

```bash
# Топ-10 процессов по потреблению оперативной памяти
ps aux --sort=-%mem | head -n 11

# Топ-10 процессов по потреблению CPU
ps aux --sort=-%cpu | head -n 11

# Сортировка по времени работы (самые старые вверху)
ps aux --sort=start_time
```

### Кастомный формат вывода (для скриптов)

Использование флага `-o` (output) позволяет извлекать только необходимые данные без лишнего "шума".

```bash
# Вывести только PID и имя команды
ps -eo pid,comm

# Вывести данные без заголовков столбцов
ps -o pid,user,comm --no-headers

# Свои заголовки для столбцов
ps -eo pid,comm:20,etime="TIME_ELAPSED"
```

**Часто используемые поля для `-o`:**

- `pid`, `ppid` — идентификаторы
- `user`, `group` — владельцы
- `pcpu`, `pmem` — ресурсы
- `comm` — краткое имя команды
- `args` — полная командная строка
- `etime` — прошедшее время с момента запуска

### Диагностика проблем

#### Поиск процессов в состоянии D (ожидание I/O)

Процессы в этом состоянии нельзя убить даже через `kill -9`, так как они ожидают ответа от ядра или оборудования.

```bash
# Найти все процессы, застрявшие в Disk Sleep
ps aux | awk '$8 ~ /D/ {print}'

# Точный поиск по полю STAT (без ложных срабатываний на заголовок)
ps -eo pid,stat,comm | awk '$2~/D/'
```

**Определение причины блокировки D-state:**

Файл `/proc/<PID>/wchan` содержит имя kernel-функции, в которой процесс находится в состоянии непрерываемого сна:

```bash
cat /proc/1234/wchan
# → wait_on_page_bit
```

Типичные значения: `wait_on_page_bit` (ожидание страничного кэша), `md_open` (ожидание software RAID), `lock_page` (блокировка страницы памяти). Это позволяет понять, какой именно ресурс вызывает задержку.

#### Поиск зомби-процессов

```bash
# Показать всех зомби
ps aux | awk '$8 ~ /Z/ {print}'

# Найти родителя зомби-процесса (чтобы "вылечить" зомби)
ps -o ppid= -p <ZOMBIE_PID>
```

#### Процессы с высоким временем CPU

```bash
# Показать процессы, которые суммарно потребили больше всего времени процессора
ps -eo pid,comm,pcpu,time --sort=-time | head -n 10
```

## Дополнительная информация

### Сравнение с аналогами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| [`top`](./top.md) | Динамическое обновление, интерактивность | Неудобен для логирования и скриптов |
| [`htop`](./htop.md) | Визуализация, управление мышью, фильтры | Часто отсутствует в минимальных образах ОС |
| [`pidstat`](./pidstat.md) | Статистика по конкретным PID во времени | Требует установки пакета `sysstat` |

### Ограничения

- **Статичность:** Выводит состояние на момент вызова. Для отслеживания скачков нагрузки используйте интерактивные утилиты.
- **Точность памяти:** `ps` показывает RSS, который включает разделяемые библиотеки. Для точного анализа приватной памяти процесса (PSS/USS) рекомендуется использовать `smem`.
- **Зависимость от /proc:** Если файловая система `/proc` недоступна или повреждена, `ps` не сможет работать.
