# `dmesg` — Просмотр сообщений ядра

## 1. Определение

`dmesg` (сокращение от _display message_ или _driver message_) — это утилита командной строки для просмотра сообщений из **кольцевого буфера ядра**. Она незаменима для диагностики проблем с оборудованием и драйверами, особенно во время и сразу после загрузки системы.

## 2. Основные концепции

### Кольцевой буфер ядра

Кольцевой буфер — это структура данных фиксированного размера в памяти ядра, где хранятся логи. Когда буфер заполняется, новые сообщения начинают перезаписывать самые старые. Это обеспечивает сбор логов даже на самых ранних этапах загрузки системы.

### Уровни и источники сообщений

- **Уровень (level):** Определяет важность сообщения. Стандартные уровни включают `emerg`, `alert`, `crit`, `err`, `warn`, `notice`, `info`, `debug`.
- **Источник (facility):** Указывает на подсистему ядра, сгенерировавшую сообщение, например `kern`, `user`, `daemon`, `auth`.

### Интеграция с `systemd-journald`

В современных системах с `systemd` логи ядра также собираются в `journald` и доступны через команду `journalctl -k` или `journalctl --dmesg`. `journalctl` предоставляет более мощные средства для фильтрации, но `dmesg` остается быстрым инструментом для оперативной диагностики, особенно в окружениях, где `journald` недоступен (например, в `initramfs`).

## 3. Практические сценарии

### Базовый просмотр логов

```bash
# Вывод с постраничной навигацией
dmesg | less

# Вывод с читаемым форматом времени и раскрашиванием
dmesg -T -H
```

### Фильтрация вывода
```bash
# Показать только ошибки и критические сообщения
dmesg --level=err,crit

# Фильтрация по источнику (например, сообщения от USB-подсистемы)
dmesg | grep -i usb
```

### Мониторинг в реальном времени
Эта команда работает аналогично `tail -f`, позволяя отслеживать новые сообщения ядра в реальном времени.
```bash
dmesg -w
# или
dmesg --follow
```

### Фильтрация вывода

-   **Фильтрация по уровню сообщений:**
    ```bash
    # Показать только ошибки и критические сообщения
    dmesg --level=err,crit
    ```
    Уровни: `emerg`, `alert`, `crit`, `err`, `warn`, `notice`, `info`, `debug`.

-   **Фильтрация по устройству (facility):**
    ```bash
    # Показать сообщения, относящиеся только к пользователям
    dmesg --facility=user
    ```
    Facilities: `kern`, `user`, `mail`, `daemon`, `auth`, `syslog`, `lpr`, `news`.

-   **Комбинация полезных флагов:**
    (Человекочитаемый вывод, время, уровни, постраничный просмотр)
    ```bash
    dmesg -HTx | less
    ```

### Управление буфером
```bash
# Очистить кольцевой буфер (требует прав root)
# Полезно перед отладкой для изоляции новых сообщений.
sudo dmesg -C

# Посмотреть размер буфера
dmesg --buffer-size
```

### Расшифровка ошибок ядра

#### Ошибка `__ratelimit`

Эта ошибка возникает, когда система пытается записать слишком много логов за короткий промежуток времени. В целях защиты от перегрузки ядро ограничивает частоту сообщений, чтобы избежать избыточного заполнения лога и снижения производительности.

**Пример:**

```
[<time>] __ratelimit: 29 msgs suppressed
```

Это означает, что 29 сообщений были подавлены, чтобы не замедлить работу системы. Частые ошибки в логах — это всегда повод обратить внимание на то, что вызывает их. Чаще всего это связано с драйверами, приложениями, или в случае высоких нагрузок — избыточным логированием.

**Что делать:**
*   Проверьте, какие процессы или модули генерируют сообщения. Используйте `dmesg -T | grep "ratelimit"` и анализируйте сообщения вокруг.
*   Изучите приложение, которое вызывает чрезмерное логирование. Возможно, его конфигурация позволяет уменьшить уровень детализации логов.
*   Попробуйте уменьшить частоту логов или настроить их на более эффективную обработку.

#### Ошибка `unreachable code`

Когда ядро пытается выполнить код, который по каким-то причинам недоступен, вы увидите ошибку типа `unreachable code`. Это может произойти из-за неправильной работы модуля, ошибки в коде ядра или несовместимости компонентов. Ошибки такого рода не всегда ведут к крашу, но они могут быть сигналом о проблемах с настройкой системы.

**Пример:**

```
[<time>] unreachable code reached at kernel/xxx.c
```

**Что делать:**
*   Проверьте, какие модули ядра загружены (`lsmod`) и их конфигурации. Возможно, конфликтуют два модуля.
*   Убедитесь, что используемые драйверы и ядро совместимы. Это особенно актуально после обновлений ядра или установки сторонних драйверов.
*   Рассмотрите возможность обновления или переустановки модулей, которые упоминаются в ошибке.
