# Troubleshooting с dmesg: ошибки оборудования и ядра

## Определения

**Troubleshooting (поиск и устранение неисправностей) с помощью dmesg** — это процесс выявления и интерпретации критических сообщений ядра, указывающих на сбои аппаратного обеспечения, конфликты драйверов или программные ошибки внутри самого ядра.

---

## Базовые концепции

### Интерпретация критических событий

Сообщения в `dmesg` часто являются «последним словом» системы перед сбоем. При анализе следует обращать внимание на:

- **Call Trace:** Стек вызовов функций ядра, указывающий на место возникновения ошибки (часто при Kernel Panic).
- **Oops/Panic:** Сообщения о серьезных нарушениях в работе ядра.
- **Hardware Error (EDAC/MCE):** Сообщения от подсистем контроля ошибок оборудования.

---

## Практические сценарии

### Расшифровка системных ошибок ядра

#### Ошибка `__ratelimit: ... msgs suppressed`

Означает, что ядро проигнорировало часть однотипных сообщений для предотвращения «заваливания» логами.

- **Причина:** Высокая интенсивность событий за короткий промежуток времени.
- **Что делать:** Анализировать сообщения, предшествующие `__ratelimit`, для поиска первопричины флуда.

#### Ошибка `unreachable code reached`

Критическое указание на логическую ошибку в коде ядра или модуля.

- **Причины:** Ошибки в драйверах, повреждение памяти или несовместимость версий.
- **Что делать:** Проверить список загруженных модулей (`lsmod`) и стабильность текущей версии ядра.

---

### Диагностика аппаратных сбоев

#### Ошибки дисковой подсистемы (SATA/NVMe)

Признаки проблем с диском или интерфейсом:

```text
[12345.678903] blk_update_request: I/O error, dev sda, sector 12345678
```

- **Диагностика:** Проверка SMART и логов контроллера.
- **Основной источник:** [**Диагностика дисков через smartctl**](../../Hardware/smartctl/index.md)

#### Ошибки оперативной памяти (ECC/EDAC)

Ошибки, обнаруженные контроллером памяти:

- `CE` (Correctable Error) — исправлено ECC.
- `UE` (Uncorrectable Error) — критическая ошибка, требующая замены модуля.
- **Диагностика:** Тестирование через `memtest86+`.

#### Перегрев процессора (Thermal throttling)

Сообщения о превышении температурного порога:

```text
[12345.678902] CPU0: Package temperature above threshold, cpu clock throttled
```

- **Что делать:** Проверить систему охлаждения и текущие показатели сенсоров.
- **Основной источник:** [**Информация о CPU и перегреве**](../../Hardware/cpu_info.md)

---

### Настройка и тюнинг логирования

#### Изменение размера кольцевого буфера

Если важные сообщения перезаписываются слишком быстро, необходимо увеличить размер буфера.

**Постоянное изменение (через GRUB):**

1. Отредактируйте `/etc/default/grub`:

   ```bash
   GRUB_CMDLINE_LINUX="log_buf_len=16M"
   ```

2. Обновите конфигурацию:

   ```bash
   sudo update-grub  # Debian/Ubuntu
   ```

**Параметры управления логированием:**

| Параметр | Описание |
|----------|----------|
| `log_buf_len=N` | Размер буфера (например, 1M, 4M, 16M). |
| `loglevel=N` | Уровень детализации вывода на консоль. |
| `earlyprintk` | Включение вывода на самых ранних этапах загрузки. |
