# Использование dmesg: просмотр и фильтрация

## Определения

**Практическое использование dmesg** включает в себя методы навигации по сообщениям ядра, применение фильтров для поиска специфических событий и управление состоянием кольцевого буфера.

---

## Базовые концепции

### Параметры отображения времени

`dmesg` предоставляет несколько способов интерпретации меток времени (timestamps), что критично при корреляции событий с системными логами:

- **`-T` (reltime):** Преобразование секунд после загрузки в человекочитаемую дату и время.
- **`-d` (delta):** Показ разницы во времени между соседними сообщениями.
- **`-H` (human):** Улучшенный формат вывода с раскрашиванием и постраничной навигацией.

### Уровни и источники (Facility & Level)

Фильтрация на уровне самой утилиты позволяет отсечь нерелевантный шум:

- **Уровни:** `err`, `warn`, `info`, `debug` и др.
- **Источники:** `kern`, `user`, `auth`, `daemon`.

---

## Практические сценарии

### Базовый просмотр логов

```bash
# Вывод с постраничной навигацией
dmesg | less

# Вывод с читаемым форматом времени и раскрашиванием
dmesg -T -H
```

---

### Мониторинг в реальном времени

Команда работает аналогично `tail -f`, позволяя отслеживать новые сообщения ядра в реальном времени.

```bash
dmesg --follow # или dmesg -w
```

---

### Фильтрация вывода

- **По содержимому (аналог `grep`):**

    ```bash
    # Поиск сообщений, связанных с USB
    dmesg | grep -i usb

    # Поиск информации о конкретном диске
    dmesg | grep sdb
    ```

- **По уровню важности:**

    ```bash
    # Показать только ошибки и предупреждения
    dmesg --level=err,warn
    ```

- **По источнику (подсистеме):**

    ```bash
    # Показать сообщения, относящиеся только к процессам аутентификации
    dmesg --facility=auth
    ```

- **Комбинация флагов для удобного анализа:**

    ```bash
    # Человекочитаемый вывод (-H), время (-T) и декодирование источника/уровня (-x)
    dmesg -HTx | less
    ```

---

### Управление буфером

```bash
# Очистить кольцевой буфер (требует прав root)
# Полезно перед отладкой для изоляции новых сообщений.
sudo dmesg -C

# Посмотреть текущий размер буфера
dmesg --buffer-size
```

---

### Поиск событий OOM Killer

Для обнаружения фактов принудительного завершения процессов из-за нехватки памяти используются следующие фильтры:

```bash
# Поиск сообщений об OOM Killer
dmesg -T | grep -iE "oom|killed process"

# Поиск процессов, убитых из-за нехватки памяти
dmesg -T | grep -i "out of memory"
```

Детальный разбор полей лога OOM (anon-rss, total-vm), методология расследования и способы предотвращения описаны в специализированном руководстве:
> **Основной источник:** [**Диагностика OOM Killer**](../../../Core/processes/oom_killer_diagnostics.md)
