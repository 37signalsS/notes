# Использование dmesg: просмотр и фильтрация

## Определения

**Практическое использование dmesg** включает методы навигации по сообщениям ядра, применение фильтров для поиска специфических событий, экспорт данных в структурированные форматы и управление состоянием кольцевого буфера.

---

## Базовые концепции

### Параметры отображения времени

`dmesg` предоставляет гибкие способы интерпретации временных меток для корреляции с системными логами:

*   **`-T` (`--ctime`):** Преобразование секунд после загрузки в человекочитаемую дату и время.
*   **`-d` (`--delta`):** Отображение разницы во времени между соседними сообщениями.
*   **`-H` (`--human`):** Улучшенный формат вывода с раскрашиванием и автоматическим использованием пейджера.

### Идентификация источника (Caller ID)

В современных ядрах (при наличии `CONFIG_PRINTK_CALLER`) доступен вывод идентификатора вызывающего объекта:
*   **`--caller`:** Добавляет префикс с ID потока или процессора, инициировавшего запись. Это критично для отладки состояний гонки (race conditions).

---

## Практические сценарии

### Базовый просмотр и мониторинг

```bash
# Вывод последних сообщений с читаемым временем и раскрашиванием
dmesg -TH

# Мониторинг новых сообщений в реальном времени (аналог tail -f)
dmesg --follow  # или dmesg -w
```

### Экспорт данных в JSON

Для автоматизации и передачи данных в системы мониторинга (или обработки через `jq`) используйте:

```bash
# Вывод в формате JSON
dmesg --json  # или dmesg -J
```

---

### Фильтрация вывода

Встроенные фильтры эффективнее, чем конвейеры с `grep`, так как они обрабатываются на уровне утилиты:

*   **По уровню важности:**
    ```bash
    # Показать только ошибки и критические состояния
    dmesg --level=err,crit

    # Показать всё, начиная с уровня предупреждения и выше
    dmesg --level=warn+
    ```

*   **По источнику (подсистеме):**
    ```bash
    # Сообщения только от процессов аутентификации
    dmesg --facility=auth
    ```

*   **По содержимому (поиск):**
    ```bash
    # Поиск информации о конкретном диске или USB-устройстве
    dmesg | grep -iE "usb|sda|nvme"
    ```

---

### Управление состоянием буфера

```bash
# Очистить кольцевой буфер (требует прав root)
# Рекомендуется перед воспроизведением ошибки для изоляции новых логов.
sudo dmesg -C

# Прочитать сообщения и СРАЗУ очистить буфер
sudo dmesg -c

# Показать размер кольцевого буфера
dmesg --buffer-size
```

---

### Анализ событий OOM Killer

Для выявления процессов, принудительно завершенных из-за нехватки памяти:

```bash
# Поиск записей OOM Killer с метками времени
dmesg -T | grep -iE "oom|killed process"
```
