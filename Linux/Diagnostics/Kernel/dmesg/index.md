# `dmesg` — Просмотр сообщений ядра

## Определения

**`dmesg`** (сокращение от _display message_ или _driver message_) — утилита командной строки для просмотра и управления сообщениями из **кольцевого буфера ядра**. Незаменима для диагностики проблем с оборудованием, драйверами и ядром, особенно во время и сразу после загрузки системы.

**Кольцевой буфер ядра (kernel ring buffer)** — структура данных фиксированного размера в памяти ядра для хранения логов. При заполнении новые сообщения перезаписывают самые старые, обеспечивая сбор логов на ранних этапах загрузки.

---

## Основные понятия

### Кольцевой буфер ядра

Кольцевой буфер — это структура данных фиксированного размера в памяти ядра, где хранятся логи. Когда буфер заполняется, новые сообщения начинают перезаписывать самые старые. Это обеспечивает сбор логов даже на самых ранних этапах загрузки системы.

**Размер буфера по умолчанию:** зависит от дистрибутива и конфигурации ядра (обычно 256 КБ – 2 МБ). Размер можно изменить через параметр ядра `log_buf_len`.

### Уровни и источники сообщений

- **Уровень (level):** Определяет важность сообщения. Стандартные уровни включают `emerg`, `alert`, `crit`, `err`, `warn`, `notice`, `info`, `debug`.
- **Источник (facility):** Указывает на подсистему ядра, сгенерировавшую сообщение, например `kern`, `user`, `daemon`, `auth`.

Полный список уровней (от критического к отладочному):

| Уровень | Число | Описание |
|---------|-------|----------|
| `emerg` | 0 | Система неработоспособна |
| `alert` | 1 | Требуется немедленное действие |
| `crit` | 2 | Критические условия |
| `err` | 3 | Условия ошибки |
| `warn` | 4 | Предупреждения |
| `notice` | 5 | Нормальные, но значимые события |
| `info` | 6 | Информационные сообщения |
| `debug` | 7 | Отладочные сообщения |

Основные источники: `kern`, `user`, `mail`, `daemon`, `auth`, `syslog`, `lpr`, `news`.

### Временные метки

`dmesg` поддерживает несколько форматов отображения времени:

- **Без флага:** Время в секундах с момента загрузки ядра (например, `[ 123.456789]`)
- **`-T` (ctime):** Читаемый формат с датой и временем (например, `Mon Jan 15 10:30:45 2024`)
- **`-t` (delta):** Время относительно предыдущего сообщения
- **`-d` (delta):** Дельта времени с точностью до микросекунд
- **`-x` (decode):** Отображение источника и уровня в виде префиксов

> **Важно:** Флаг `-T` требует, чтобы `systemd-journald` или `rsyslog` синхронизировали часы ядра с системным временем. В системах без `systemd` может отображаться некорректное время.

### Интеграция с `systemd-journald`

В современных системах с `systemd` логи ядра также собираются [`systemd-journald`](../../../SystemAdministration/Logging/journald.md) и доступны через команду [`journalctl -k`](../../journalctl.md) или `journalctl --dmesg`. [`journalctl`](../../journalctl.md) предоставляет более мощные средства для фильтрации, но `dmesg` остаётся быстрым инструментом для оперативной диагностики, особенно в окружениях, где `journald` недоступен (например, в `initramfs`).

### Интерфейс `/proc/kmsg`

Кольцевой буфер ядра также доступен через виртуальный файл `/proc/kmsg`. Этот файл предоставляет прямой доступ к сообщениям ядра в реальном времени:

```bash
# Чтение сообщений из /proc/kmsg (требует root)
sudo cat /proc/kmsg
```

**Ограничения:**

- Одновременно читать `/proc/kmsg` может только один процесс
- Чтение файла может мешать работе системных демонов логирования
- Для большинства задач используйте `dmesg` вместо прямого чтения `/proc/kmsg`
