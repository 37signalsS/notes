# dmesg — Просмотр сообщений ядра

## Определения

**`dmesg`** (display message) — утилита командной строки для просмотра и управления сообщениями из **кольцевого буфера ядра** (kernel ring buffer). Это первичный инструмент диагностики, позволяющий анализировать события, происходящие на самом низком уровне системы: инициализацию оборудования, загрузку драйверов и критические ошибки ядра.

**Кольцевой буфер ядра** — структура данных фиксированного размера в оперативной памяти ядра. При заполнении новые сообщения перезаписывают самые старые. Это гарантирует сохранение логов даже при сбоях дисковой подсистемы.

---

## Базовые концепции

### Кольцевой буфер и его параметры

Кольцевой буфер обеспечивает сбор диагностических данных с первых секунд загрузки системы, когда файловые системы ещё не примонтированы.

*   **Размер буфера:** Настраивается параметром ядра `log_buf_len` (обычно от 256 КБ до 16 МБ).
*   **Механизм доступа:** Современные версии `dmesg` используют интерфейс `/dev/kmsg` (рекомендуется), в то время как устаревшие полагались на системный вызов `syslog(2)`.

### Уровни важности и источники

Каждое сообщение в буфере имеет атрибуты:
1.  **Уровень (Level):** Важность события (от `emerg` до `debug`).
2.  **Источник (Facility):** Подсистема, сгенерировавшая лог (`kern`, `user`, `daemon` и др.).

| Уровень | Описание | Приоритет |
| :--- | :--- | :--- |
| `emerg` | Система неработоспособна | 0 |
| `alert` | Требуется немедленное вмешательство | 1 |
| `crit` | Критическая ошибка | 2 |
| `err` | Ошибка выполнения | 3 |
| `warn` | Предупреждение | 4 |
| `notice` | Значимое штатное событие | 5 |
| `info` | Информационное сообщение | 6 |
| `debug` | Отладочные данные | 7 |

### Форматы меток времени

По умолчанию `dmesg` отображает время в секундах с момента старта ядра.
*   **`-T` (`--ctime`):** Преобразование в реальную дату и время (может быть неточным после выхода из режима сна/suspend).
*   **`-H` (`--human`):** Удобный для чтения формат с раскрашиванием и автоматическим использованием пейджера.

### Безопасность и права доступа

В современных защищенных дистрибутивах (Hardened) доступ к `dmesg` для обычных пользователей ограничен.
*   **Параметр `kernel.dmesg_restrict`:**
    *   `0`: Доступ разрешен всем пользователям.
    *   `1`: Доступ разрешен только пользователям с привилегиями `CAP_SYSLOG` (обычно через `sudo`).
*   **Проверка статуса:** `sysctl kernel.dmesg_restrict`.

## Практические сценарии

### Выбор инструмента: dmesg vs journalctl

| Характеристика | `dmesg` | `journalctl -k` |
| :--- | :--- | :--- |
| **Источник** | Прямо из RAM (Ring Buffer) | База данных на диске (`journald`) |
| **Глубина архива** | Только текущая сессия (до переполнения буфера) | История за многие загрузки |
| **Зависимости** | Работает без запущенных демонов (в `initramfs`) | Требует работающий `systemd-journald` |
| **Скорость** | Максимальная | Зависит от объема базы данных |

**Когда использовать `dmesg`:**
*   Диагностика на ранних этапах загрузки.
*   Поиск причин внезапных перезагрузок (Kernel Panic).
*   Отладка драйверов и модулей ядра в реальном времени.
*   Работа в системах без `systemd`.

### Основные области применения

1.  **Инициализация оборудования:** Проверка распознавания CPU, RAM, контроллеров и дисков.
2.  **Сбои драйверов:** Поиск сообщений об ошибках модулей или прошивок (Firmware).
3.  **Диагностика памяти:** Анализ срабатываний OOM Killer.
4.  **События ввода-вывода:** Мониторинг ошибок файловых систем и блочных устройств.
