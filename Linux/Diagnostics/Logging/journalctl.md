# `journalctl`

## Определения

`journalctl` — это утилита командной строки для просмотра и анализа логов, собранных `systemd-journald`, централизованной службой управления журналами в современных дистрибутивах Linux. Она позволяет просматривать логи ядра, системных сервисов и приложений, включая их стандартный вывод (stdout) и вывод ошибок (stderr).

## Основные концепции

Служба `systemd-journald` собирает логи со всего окружения `systemd` в структурированном двоичном формате. В отличие от простых текстовых логов, это позволяет:

-   Централизованно хранить все системные сообщения.
-   Обогащать логи метаданными (например, именем сервиса, PID процесса).
-   Производить быструю и мощную фильтрацию по различным полям.

По умолчанию логи могут храниться в памяти и не сохраняться между перезагрузками. Для постоянного хранения необходимо создать директорию `/var/log/journal`.

## Практические сценарии

### Просмотр логов сервиса

```bash
# Показать все логи для сервиса nginx.service
sudo journalctl -u nginx.service

# Показать последние 100 строк и следить за новыми логами в реальном времени
sudo journalctl -u nginx.service -n 100 -f
```

### Фильтрация по времени

```bash
# Показать логи за последний час
sudo journalctl --since "1 hour ago"

# Показать логи между определенными датами
sudo journalctl --since "2023-10-26 18:00:00" --until "2023-10-26 18:10:00"
```

### Просмотр сообщений ядра

Эквивалентно использованию команды `dmesg`.

```bash
# Показать сообщения ядра для текущей загрузки
sudo journalctl -k

# Следить за новыми сообщениями ядра
sudo journalctl -kf
```

## Дополнительная информация

### Анализ загрузок системы

`journalctl` отслеживает логи для разных сессий загрузки системы, что критически важно для диагностики причин сбоев и перезагрузок.

```bash
# Показать список всех зарегистрированных загрузок
journalctl --list-boots

# Показать логи для предыдущей загрузки (идентификатор -1)
# Полезно для анализа причин сбоя, который привел к перезагрузке
journalctl -b -1 -r
```

Флаг `-r` (`--reverse`) выводит логи от новых к старым, что удобно для быстрого поиска последних событий перед сбоем.

### Альтернативные способы просмотра вывода процесса

Если сервис настроен так, что `journalctl` не показывает его вывод, можно прибегнуть к прямому анализу файловых дескрипторов процесса через `/proc`.

1.  **Найти PID процесса:** `systemctl status <имя_сервиса>`
2.  **Проверить, куда направлен вывод:** Файловые дескрипторы `1` (stdout) и `2` (stderr) в директории `/proc/<PID>/fd/` покажут, куда процесс пишет свои логи.
    ```bash
    ls -l /proc/<PID>/fd/
    ```
3.  **Прочитать вывод напрямую:** Если вывод направлен в пайп или файл, его можно прочитать.
    ```bash
    tail -f /proc/<PID>/fd/1
    ```
