# journalctl — Обзор и основные концепции

## Определения

**`journalctl`** — утилита командной строки для просмотра, фильтрации и анализа логов, собранных службой `systemd-journald`. Является основным инструментом для работы с журналом systemd.

**`systemd-journald`** — системная служба, централизованно собирающая логи от всех компонентов ОС (ядро, службы, приложения, stdout/stderr) в структурированном бинарном формате. Подробная конфигурация демона описана в [journald.md](../../SystemAdministration/Logging/journald.md).

## Основные концепции

### Централизованное и структурированное логирование

Служба `systemd-journald` собирает логи со всего окружения `systemd` (ядро, системные сервисы, приложения, stdout/stderr) в структурированном бинарном формате.

В отличие от традиционных текстовых логов (например, `rsyslog`), это обеспечивает:

- **Централизацию:** Все системные сообщения хранятся в одном месте.
- **Обогащение метаданными:** Каждое сообщение автоматически получает метаданные: имя сервиса, PID (Process ID), UID (User ID), уровень приоритета, boot-id и другие.
- **Мощную и быструю фильтрацию:** Возможность фильтровать логи по любым метаданным без парсинга текстовых строк.

### Хранение логов

Логи `systemd-journald` могут храниться двумя способами:

| Тип | Расположение | Описание |
| :--- | :--- | :--- |
| **Энергозависимое (Volatile)** | `/run/log/journal` | Директория монтируется как `tmpfs` и очищается при каждой перезагрузке системы. |
| **Постоянное (Persistent)** | `/var/log/journal` | Если директория существует, `systemd-journald` автоматически начинает использовать её для постоянного хранения. |

Настройка хранения логов (лимиты размера, режим) выполняется в `/etc/systemd/journald.conf`.

### Уровни приоритета логов

`journalctl` позволяет фильтровать сообщения по их уровню приоритета (от 0 до 7), используя ключ `-p` или `--priority`:

| Уровень | Значение | Описание |
| :--- | :--- | :--- |
| `0` | emerg | Система непригодна для использования (System is unusable) |
| `1` | alert | Требуется немедленное вмешательство (Action must be taken immediately) |
| `2` | crit | Критическое состояние (Critical conditions) |
| `3` | err | Ошибки (Error conditions) |
| `4` | warning | Предупреждения (Warning conditions) |
| `5` | notice | Нормальные, но значимые события (Normal but significant condition) |
| `6` | info | Информационные сообщения (Informational messages) |
| `7` | debug | Отладочные сообщения (Debug-level messages) |

### Сессии загрузки (Boots)

Каждая перезагрузка системы получает уникальный идентификатор `Boot ID`. `journalctl` позволяет просматривать логи конкретной сессии:
- Текущая загрузка: `journalctl -b 0` (или просто `-b`).
- Предыдущая загрузка: `journalctl -b -1`.
- Список доступных загрузок: `journalctl --list-boots`.

### Каталог сообщений (Message Catalog)

Многие системные сообщения в журнале снабжены дополнительной справочной информацией в «каталоге сообщений».
- Использование ключа `-x` (или `--catalog`) добавляет к выводу пояснения к ошибкам, ссылки на документацию и советы по решению проблем.

### Логи ядра (Kernel Logs)

`journalctl` может выступать заменой команде `dmesg`.
- Ключ `-k` (или `--dmesg`) выводит только сообщения ядра. В отличие от стандартного `dmesg`, `journalctl` позволяет просматривать историю сообщений ядра за прошлые загрузки.

## Дополнительная информация

### Производительность и оптимизация

`journalctl` использует индексы для быстрого поиска по времени и метаданным.
- **Бинарный формат:** Обеспечивает высокую скорость записи и чтения, но требует специальных утилит для просмотра.
- **Автоматическая ротация:** При достижении лимитов (заданных в `journald.conf`) старые логи автоматически удаляются по принципу FIFO.
- **Эффективный поиск:** Всегда предпочтительна фильтрация по метаданным (`-u`, `-p`, `--since`) — она использует индексы. Текстовый поиск (`-g` или `grep`) требует полного сканирования и работает значительно медленнее.

### Безопасность и целостность

- **Права доступа:** Доступ к логам ограничен пользователями групп `systemd-journal`, `adm` и `wheel`.
- **FSS (Forward Secure Sealing):** Технология криптографического подписывания журнала. Позволяет обнаружить несанкционированное изменение или удаление записей в архиве логов (требует предварительной настройки ключей).
- **Изоляция:** Бинарный формат усложняет незаметное редактирование отдельных строк лога по сравнению с текстовыми файлами.
