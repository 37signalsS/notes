# Управление хранением и очистка journalctl

## Определения

**Vacuum (очистка)** — процесс удаления старых записей журнала по заданным критериям (размер, время, количество файлов). Выполняется вручную через `journalctl --vacuum-*` или автоматически при достижении лимитов.

**Лимиты хранения** — параметры конфигурации `systemd-journald`, определяющие максимальный объем дискового пространства для логов и политику ротации файлов.

## Основные концепции

### Принципы управления хранением

Управление логами `journalctl` состоит из двух уровней:

1. **Конфигурация демона** — настройка `/etc/systemd/journald.conf` определяет поведение `systemd-journald`: режим хранения (persistent/volatile), лимиты размера, частоту ротации. Подробная конфигурация описана в [journald.md](../../SystemAdministration/Logging/journald.md).
2. **Ручное управление** — команды `journalctl` для мониторинга использования дискового пространства и принудительной очистки журналов.

### Автоматическая ротация

При достижении лимитов (`SystemMaxUse`) старые логи автоматически удаляются по принципу FIFO (First In, First Out — первым пришел, первым ушел). Это обеспечивает непрерывную работу системы без ручного вмешательства.

### Маскировка чувствительных данных

`journalctl` поддерживает автоматическую маскировку конфиденциальных полей (пароли, токены, секретные ключи) при выводе.

## Практические сценарии

### Мониторинг использования дискового пространства

```bash
# Проверить текущий размер журнала
journalctl --disk-usage
```

### Ручная очистка журнала (vacuum)

```bash
# Оставить только последние 500 МБ логов
sudo journalctl --vacuum-size=500M

# Оставить логи только за последние 2 дня
sudo journalctl --vacuum-time=2d

# Оставить только N последних файлов журнала
sudo journalctl --vacuum-files=5
```

**Параметры очистки:**

| Параметр | Описание | Пример |
|----------|----------|--------|
| `--vacuum-size=` | Ограничение по общему размеру | `500M`, `2G` |
| `--vacuum-time=` | Ограничение по времени хранения | `2d`, `1week` |
| `--vacuum-files=` | Ограничение по количеству файлов | `5`, `10` |

### Маскировка конфиденциальных данных

```bash
# Скрывать значения полей PASSWORD, SECRET и других
journalctl --mask
```

По умолчанию маскируются поля: `PASSWORD`, `PASSPHRASE`, `SECRET`, `_PASSWORD`, `_PASSPHRASE`.

### Диагностика проблем с journald

```bash
# Проверка статуса службы
systemctl status systemd-journald

# Показать доступные поля метаданных
journalctl --fields

# Временное включение отладочного логирования
sudo systemctl kill -s SIGUSR1 systemd-journald
```

### Типичные проблемы и решения

| Проблема | Возможная причина | Решение |
|----------|-------------------|---------|
| Показываются логи только текущей загрузки | Не настроено постоянное хранение | Создать `/var/log/journal` и перезапустить службу. |
| Логи занимают слишком много места | Не настроены лимиты | Настроить `SystemMaxUse` в `journald.conf`. |
| Нет логов от конкретного сервиса | Сервис пишет в свой файл, а не в journald | Проверить `StandardOutput` в юните сервиса. |

## Дополнительная информация

### Производительность и ограничения

`journalctl` использует индексы для быстрого поиска. Бинарный формат обеспечивает высокую скорость работы, но требует специальных утилит для просмотра. Для долгосрочного хранения (месяцы/годы) рекомендуется пересылка логов в rsyslog или специализированные системы: ELK Stack (Elasticsearch, Logstash, Kibana), Loki или Splunk.

### Интеграция с другими системами

**rsyslog:** Модуль `imjournal` позволяет `rsyslog` забирать сообщения из `journald` для дальнейшей обработки. Подробнее в [rsyslog.md](../../SystemAdministration/Logging/rsyslog.md).

**auditd:** Для глубокого аудита событий безопасности используется отдельная подсистема `auditd`. Подробнее в [auditd.md](../../SystemAdministration/Logging/auditd.md).
