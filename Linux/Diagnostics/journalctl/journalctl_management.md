# Управление хранением и очистка journalctl

## Определения

**Vacuum (очистка)** — процесс удаления старых записей журнала по заданным критериям (размер, время, количество файлов). Выполняется вручную через `journalctl --vacuum-*` или автоматически при достижении лимитов, настроенных в `journald.conf`.

**Лимиты хранения** — параметры конфигурации `systemd-journald`, определяющие максимальный объем дискового пространства для логов и политику ротации файлов.

## Основные концепции

### Принципы управления хранением

Управление логами journalctl состоит из двух уровней:

1. **Конфигурация демона** — настройка `/etc/systemd/journald.conf` определяет поведение `systemd-journald`: режим хранения (persistent/volatile), лимиты размера, частоту ротации. Подробная конфигурация описана в [journald.md](../../SystemAdministration/Logging/journald.md).

2. **Ручное управление** — команды `journalctl` для мониторинга использования дискового пространства и принудительной очистки журналов.

### Автоматическая ротация

При достижении лимитов (`SystemMaxUse`) старые логи автоматически удаляются по принципу FIFO (first in, first out). Это обеспечивает непрерывную работу системы без ручного вмешательства.

### Маскировка чувствительных данных

`journalctl` поддерживает автоматическую маскировку конфиденциальных полей (пароли, токены, секретные ключи) при выводе.

## Практические сценарии

### Мониторинг использования дискового пространства

```bash
# Проверить текущий размер журнала
journalctl --disk-usage
```

**Пример вывода:**

```
Archived and active journals take up 2.3G in total.
```

### Ручная очистка журнала (vacuum)

```bash
# Оставить только последние 500 МБ логов
sudo journalctl --vacuum-size=500M

# Оставить логи только за последние 2 дня
sudo journalctl --vacuum-time=2d

# Оставить только N последних файлов журнала
sudo journalctl --vacuum-files=5
```

**Параметры vacuum:**

| Параметр | Описание | Пример |
|----------|----------|--------|
| `--vacuum-size=` | Ограничение по общему размеру | `500M`, `2G` |
| `--vacuum-time=` | Ограничение по времени хранения | `2d`, `1week` |
| `--vacuum-files=` | Ограничение по количеству файлов | `5`, `10` |

### Маскировка конфиденциальных данных

```bash
# Автоматически скрывать значения полей PASSWORD, SECRET и т.д.
journalctl --mask
```

По умолчанию маскируются поля: `PASSWORD`, `PASSPHRASE`, `SECRET`, `_PASSWORD`, `_PASSPHRASE`.

### Диагностика проблем с journald

```bash
# Проверка статуса службы
systemctl status systemd-journald

# Показать доступные поля метаданных
journalctl --fields

# Включение отладочного логирования (временное увеличение уровня)
sudo systemctl kill -s SIGUSR1 systemd-journald
```

### Типичные проблемы и решения

| Проблема | Возможная причина | Решение |
|----------|-------------------|---------|
| `journalctl` показывает только логи текущей загрузки | Не настроено persistent storage | Создать `/var/log/journal` и перезапустить `systemd-journald` (см. [journald.md](../../SystemAdministration/Logging/journald.md)) |
| Логи занимают слишком много места | Не настроены лимиты | Настроить `SystemMaxUse` в `/etc/systemd/journald.conf` |
| Нет логов от конкретного сервиса | Сервис пишет в свой файл, а не в journald | Проверить конфигурацию сервиса или настроить интеграцию (см. [rsyslog.md](../../SystemAdministration/Logging/rsyslog.md)) |
| `journalctl -g` не находит текст | Поиск регистрозависимый или текст в экранированном поле | Использовать `grep` после `journalctl` или `-g "pattern"` с правильным паттерном |

## Дополнительная информация

### Производительность и ограничения

`journalctl` использует индексы для быстрого поиска по времени, PID, UID и другим полям. Бинарный формат обеспечивает высокую скорость записи и чтения, но требует специальных утилит для просмотра. Для архивации логов на месяцы/годы рекомендуется пересылка в rsyslog или специализированные системы (ELK Stack, Loki, Splunk).

### Интеграция с другими системами логирования

**rsyslog:** Модуль `imjournal` позволяет `rsyslog` забирать сообщения из `journald` для фильтрации и пересылки. Настройка описана в [rsyslog.md](../../SystemAdministration/Logging/rsyslog.md).

**dmesg:** Для просмотра только логов ядра можно использовать [`dmesg`](../Kernel/dmesg/index.md). `journalctl -k` предоставляет больше возможностей фильтрации и долгосрочного хранения.

**auditd:** Для аудита событий безопасности используется [`auditd`](../../SystemAdministration/Logging/auditd.md) — отдельная подсистема, не связанная с `journald`.
