# Управление хранением и очистка journalctl

## Определения

**Vacuum (Очистка)** — процесс удаления архивных (неактивных) файлов журнала для освобождения дискового пространства на основе заданных критериев (размер, время, количество файлов). Выполняется вручную через `journalctl --vacuum-*` или автоматически при достижении лимитов.

**Ротация (Rotation)** — закрытие текущего активного файла журнала и создание нового. Это необходимо для применения новых параметров конфигурации или перед выполнением очистки, так как очищаются только неактивные файлы.

**Целостность (Integrity)** — состояние данных в журнале, при котором они не повреждены и (при использовании FSS) не были несанкционированно изменены. Проверяется командой `--verify`.

## Основные концепции

### Уровни управления хранением

Управление логами `journalctl` состоит из двух уровней:

1. **Декларативный (Конфигурация):** Настройка параметров в `/etc/systemd/journald.conf` (`SystemMaxUse`, `RuntimeMaxUse`, `MaxFileSec` и др.). Демон `systemd-journald` автоматически следит за тем, чтобы база не превышала лимиты. Подробно см. в [journald.md](../../SystemAdministration/Logging/journald.md).
2. **Оперативный (Ручное управление):** Использование утилиты `journalctl` для немедленного освобождения места, синхронизации данных или проверки базы на ошибки.

### Жизненный цикл управления данными

Для корректного и безопасного обслуживания журнала рекомендуется придерживаться следующей последовательности операций:
1. **Sync:** Записать все данные из временных буферов на физический диск.
2. **Rotate:** Перевести текущие активные файлы в состояние архивных.
3. **Vacuum:** Удалить старые архивные файлы (активные файлы никогда не удаляются механизмом vacuum).

### Автоматическая ротация

При достижении лимитов (`SystemMaxUse`) или истечении времени жизни файла (`MaxFileSec`) старые логи автоматически удаляются демоном по принципу FIFO (First In, First Out). Это обеспечивает непрерывную работу системы без ручного вмешательства.

## Практические сценарии

### Мониторинг использования ресурсов

```bash
# Проверить текущий объем, занимаемый журналом на диске
journalctl --disk-usage

# Проверка состояния службы и ошибок в последних сообщениях
systemctl status systemd-journald
```

### Ручная очистка журнала (Vacuuming)

Команды очистки затрагивают только **архивные** файлы. Для максимального эффекта рекомендуется выполнить ротацию перед очисткой.

```bash
# Оставить логи только за последние 2 дня
sudo journalctl --vacuum-time=2d

# Ограничить общий объем 500 мегабайтами
sudo journalctl --vacuum-size=500M

# Оставить не более 5 архивных файлов
sudo journalctl --vacuum-files=5
```

**Параметры очистки:**

| Параметр | Описание | Пример |
| :--- | :--- | :--- |
| `--vacuum-size=` | Ограничение по общему размеру | `500M`, `2G` |
| `--vacuum-time=` | Ограничение по времени хранения | `2d`, `1week` |
| `--vacuum-files=` | Ограничение по количеству файлов | `5`, `10` |

### Техническое обслуживание и диагностика

#### Синхронизация и ротация
Используется перед бэкапом или при необходимости немедленно применить изменения в конфигурации.

```bash
# Сбросить буферы на диск и дождаться завершения операции
sudo journalctl --sync

# Принудительно закрыть текущие файлы и начать новые
sudo journalctl --rotate
```

#### Проверка целостности
Помогает выявить повреждения базы данных после аварийных отключений или сбоев оборудования.

```bash
# Проверить все файлы журнала на внутреннюю согласованность
sudo journalctl --verify
```

#### Перенос логов из памяти на диск (Flush)
Если система была загружена в режиме `volatile` (логи только в RAM), а затем появилась точка монтирования `/var/log/journal`, эта команда перенесет накопленные данные на диск.

```bash
sudo journalctl --flush
```

### Управление через сигналы
В скриптах автоматизации можно использовать системные сигналы для управления демоном:

| Сигнал | Команда / Эквивалент | Описание |
| :--- | :--- | :--- |
| `SIGUSR1` | `journalctl --flush` | Перенос логов из `/run` в `/var` |
| `SIGRTMIN+1` | `journalctl --rotate` | Выполнить немедленную ротацию |

```bash
# Пример отправки сигнала ротации демону
sudo systemctl kill -s SIGRTMIN+1 systemd-journald
```

### Типичные проблемы и решения

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| `Vacuum` не освобождает место | Удаляются только архивные файлы | Выполните `journalctl --rotate` перед очисткой. |
| Файлы помечены как `Corrupt` | Сбой файловой системы или питания | Проверьте через `--verify`. Поврежденные файлы придется удалить вручную из `/var/log/journal`. |
| Логи занимают место в `/run` | Не настроено постоянное хранение | Создайте `/var/log/journal` и выполните `journalctl --flush`. |

## Дополнительная информация

### Интеграция с системами анализа

Для долгосрочного хранения или централизованного анализа (SIEM, системы наблюдаемости) рекомендуется экспорт данных:
- **Loki:** Агент `promtail` или `fluent-bit` для сбора логов в реальном времени.
- **ELK Stack:** Использование `Filebeat` с модулем `journald`.
- **rsyslog:** Локальная пересылка в `rsyslog` для записи в текстовые файлы или отправки на удаленный лог-сервер. Подробнее в [rsyslog.md](../../SystemAdministration/Logging/rsyslog.md).
