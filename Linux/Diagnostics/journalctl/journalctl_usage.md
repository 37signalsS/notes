# Использование journalctl — Практические сценарии

## Определения

**Фильтрация по метаданным** — механизм отбора записей на основе структурированных полей базы данных `journald` (PID, UID, юнит, время). Это самый быстрый способ поиска, так как он использует индексы.

**Полнотекстовый поиск** — поиск по содержимому сообщения (`MESSAGE`). Выполняется через ключ `-g` (внутренняя реализация) или через конвейер в `grep`.

**Курсор (Cursor)** — уникальная непрозрачная строка-идентификатор конкретной записи в журнале. Позволяет возобновлять чтение логов с точного места в автоматизированных системах.

## Основные концепции

### Контекст выполнения

По умолчанию `journalctl` показывает системные логи. Для работы с логами пользовательских сервисов (запущенных через `systemctl --user`) используется флаг `--user`.
```bash
# Логи пользовательского инстанса systemd
journalctl --user -u my-app.service
```

### Обработка вывода

- **Пейджер:** По умолчанию используется `less`. Флаг `--no-pager` отключает его (важно для скриптов).
- **Длинные строки:** По умолчанию длинные сообщения обрезаются. Флаг `-a` (`--all`) заставляет `journalctl` выводить данные полностью, даже если они содержат непечатные символы или очень длинные строки.
- **Интеграция со справочником:** Флаг `-x` (`--catalog`) добавляет к сообщениям об ошибках пояснительные тексты из каталога `systemd`, включая ссылки на документацию.

## Практические сценарии

### Навигация и базовый просмотр

```bash
# Просмотр от новых к старым
journalctl -r

# Последние 50 строк и режим ожидания новых (follow)
journalctl -n 50 -f

# Логи ядра за текущую загрузку
journalctl -k -b 0
```

### Фильтрация по времени

`journalctl` понимает как абсолютные (ISO 8601), так как и относительные форматы времени.

```bash
# Относительное время
journalctl --since "20 min ago"
journalctl --since "yesterday"
journalctl --since "2 days ago"

# Абсолютный диапазон
journalctl --since "2024-05-01 12:00:00" --until "2024-05-01 13:00:00"

# Использование UTC времени
journalctl --since "2024-05-01 12:00:00" --utc
```

### Сложная фильтрация по метаданным

Фильтры по разным полям объединяются как **И (AND)**, фильтры по одному и тому же полю — как **ИЛИ (OR)**.

```bash
# Логи nginx ИЛИ sshd (одно поле - OR)
journalctl -u nginx.service -u sshd.service

# Ошибки (p 3) конкретного процесса (PID 123) (разные поля - AND)
journalctl _PID=123 -p 3

# Комбинированная логика: (nginx ИЛИ ssh) И (приоритет >= err)
journalctl -u nginx -u sshd + -p err
```
*Примечание: знак `+` разделяет группы фильтров, позволяя строить сложные логические выражения.*

### Форматирование и точность времени

```bash
# Формат ISO 8601 (удобен для парсинга)
journalctl -o short-iso

# Максимальная точность (микросекунды)
journalctl -o short-precise

# Компактный формат (только сообщение, без даты и хоста)
journalctl -o cat
```

### Работа в автоматизированных системах

Для надежной передачи логов в системы мониторинга без пропусков используются курсоры.

```bash
# Получить курсор последней записи
journalctl -n 1 --show-cursor

# Начать чтение логов ПОСЛЕ указанного курсора
journalctl --after-cursor="s=80e7..."
```

### Идентификация источников (Метаданные)

Если неизвестно имя юнита, можно фильтровать по пути к файлу или идентификаторам:

```bash
# Все сообщения от конкретного бинарного файла
journalctl /usr/sbin/nginx

# Все сообщения от процессов конкретного пользователя
journalctl _UID=1000

# Сообщения ядра, связанные с конкретным устройством
journalctl _KERNEL_DEVICE=+pci:0000:00:1f.6
```

## Дополнительная информация

### Производительность и ограничения

1. **Индексы vs Grep:** Фильтрация по `-u`, `-p`, `_PID`, `--since` выполняется мгновенно. Поиск по `-g` или `grep` требует декомпрессии и вычитки всех записей с диска.
2. **Бинарные данные:** Если приложение пишет бинарные данные в stdout, `journalctl` может скрыть их. Используйте `-a`, чтобы увидеть "сырой" вывод.
3. **Объем вывода:** При работе с очень большими журналами (ГБ данных) избегайте вызовов без ограничений по времени (`--since`), так как это создает высокую нагрузку на I/O.

### Лучшие практики

- **Для отладки в реальном времени:** Используйте `journalctl -f -u <unit> -o short-precise`.
- **Для расследования инцидентов:** Всегда добавляйте `-x`, чтобы получить контекст ошибки от разработчиков системы.
- **Для скриптов:** Используйте `--no-pager --output=json` для получения машиночитаемых данных.
