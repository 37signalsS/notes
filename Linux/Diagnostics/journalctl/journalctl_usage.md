# Использование journalctl — Практические сценарии

## Определения

**Output format (формат вывода)** — способ представления записей журнала при просмотре. `journalctl` поддерживает различные форматы: человекочитаемый (по умолчанию), JSON, syslog, cat (только сообщение).

**Фильтрация по метаданным** — механизм отбора записей журнала по полям метаданных (PID, UID, юнит, время, приоритет, исполняемый файл), а не по текстовому содержимому сообщений.

## Основные концепции

### Принцип работы с pagингом

По умолчанию `journalctl` выводит результаты через pager (`less`), что позволяет навигировать по большим объемам логов. Для отключения pagинга используется флаг `--no-pager`, что удобно в скриптах и конвейерах.

### Типы фильтрации

Фильтрация в `journalctl` делится на два типа:

1. **По метаданным** — быстрая фильтрация через индексы журнала (`-u`, `-p`, `--since`, `_PID`, `_UID`)
2. **По содержимому** — поиск текста в сообщениях (`-g` или внешний `grep`)

Фильтрация по метаданным предпочтительнее — она использует индексы и работает значительно быстрее текстового поиска.

### Форматы вывода

Выбор формата зависит от задачи: человекочитаемый формат для интерактивного анализа, JSON для автоматизированной обработки скриптами, syslog для совместимости с legacy-системами.

## Практические сценарии

### Базовый просмотр логов

```bash
# Все логи (в обратном хронологическом порядке)
journalctl

# Логи в реальном времени (поток событий)
journalctl -f

# Логи ядра (аналог dmesg)
journalctl -k

# Логи ядра в реальном времени
journalctl -kf

# Логи с последней загрузки
journalctl -b

# Логи с предыдущей загрузки
journalctl -b -1

# Список всех зарегистрированных загрузок
journalctl --list-boots

# Логи от новых к старым (обратный порядок)
journalctl -r
```

### Фильтрация по службе (unit)

```bash
# Логи конкретного сервиса
journalctl -u nginx.service

# Логи сервиса в реальном времени
journalctl -u nginx.service -f

# Логи нескольких сервисов
journalctl -u sshd.service -u httpd.service
```

### Фильтрация по времени

```bash
# За последний час
journalctl --since "1 hour ago"

# С определенной даты и времени
journalctl --since "2023-10-26 18:00:00"

# Между двумя датами
journalctl --since "2023-10-26 18:00:00" --until "2023-10-26 18:10:00"
```

### Фильтрация по процессам, пользователям и исполняемым файлам

```bash
# По идентификатору процесса (PID)
journalctl _PID=1234

# По идентификатору пользователя (UID)
journalctl _UID=1000

# По пути к исполняемому файлу
journalctl /usr/lib/systemd/systemd

# По конкретному исполняемому файлу (поле EXE)
journalctl EXE=/usr/sbin/nginx
```

### Фильтрация по уровню приоритета

```bash
# Только ошибки и более критичные сообщения
journalctl -p err

# Диапазон уровней (предупреждения и ошибки)
journalctl -p warning..err
```

### Поиск по содержимому логов

```bash
# Встроенный поиск journalctl (быстрее, использует индексы)
journalctl -u nginx.service -g "error"

# Традиционный grep (регистронезависимый)
journalctl -u nginx.service --no-pager | grep -i "error"
```

### Экспорт в различные форматы

```bash
# JSON (одна строка на запись — для скриптов)
journalctl -u nginx.service --output=json

# JSON (красивый, многострочный — для анализа)
journalctl -u nginx.service --output=json-pretty

# JSON с экранированием (для парсинга SSE)
journalctl -u nginx.service --output=json-sse

# Традиционный syslog-формат
journalctl -u nginx.service --output=syslog

# Только сообщение (без метаданных)
journalctl -u nginx.service --output=cat
```

### Подсчет и анализ событий

```bash
# Подсчитать количество ошибок сервиса
journalctl -u nginx.service -p err --no-pager | wc -l

# Статистика по уровням логирования
journalctl -u nginx.service --no-pager | awk '{print $5}' | sort | uniq -c
```

### Сравнение логов между загрузками

```bash
# Логи сервиса за текущую загрузку
journalctl -u nginx.service -b 0

# Логи сервиса за предыдущую загрузку
journalctl -u nginx.service -b -1
```

### Мониторинг конкретных полей метаданных

```bash
# Показать подробные метаданные (verbose output)
journalctl -u nginx.service -o verbose

# Фильтрация по конкретному полю в verbose-режиме
journalctl -u nginx.service -o verbose | grep _PID
```

## Дополнительная информация

### Лучшие практики использования

**Производительность:** Всегда предпочтительна фильтрация по метаданным (`-u`, `-p`, `--since`) — она использует индексы журнала. Текстовый поиск (`-g` или `grep`) требует полного сканирования записей.

**Скрипты и автоматизация:** Используйте `--no-pager` для отключения pagинга и `--output=json` для структурированного вывода, удобного в парсинге.

**Долгосрочный анализ:** Для сравнения поведения сервиса между загрузками используйте флаги `-b 0` (текущая) и `-b -1` (предыдущая).
