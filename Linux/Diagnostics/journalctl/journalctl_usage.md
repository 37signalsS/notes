# Использование journalctl — Практические сценарии

## Определения

**Формат вывода (Output format)** — способ представления записей журнала при просмотре. `journalctl` поддерживает различные форматы: человекочитаемый (по умолчанию), JSON, syslog, cat (только сообщение).

**Фильтрация по метаданным** — механизм отбора записей журнала по полям метаданных: PID (Process ID — идентификатор процесса), UID (User ID — идентификатор пользователя), юнит, время, приоритет, исполняемый файл.

## Основные концепции

### Работа с пейджером

По умолчанию `journalctl` выводит результаты через пейджер (`less`), что позволяет перемещаться по большим объемам логов. Для отключения пейджера используется флаг `--no-pager`, что необходимо в скриптах и конвейерах.

### Типы фильтрации

Фильтрация в `journalctl` делится на два типа:

1. **По метаданным** — быстрая фильтрация через индексы журнала (`-u`, `-p`, `--since`, `_PID`, `_UID`).
2. **По содержимому** — поиск текста в сообщениях (`-g` или внешний `grep`).

Фильтрация по метаданным предпочтительнее, так как она использует индексы и работает значительно быстрее текстового поиска.

### Форматы вывода

Выбор формата зависит от задачи:

- Человекочитаемый формат — для интерактивного анализа.
- JSON (JavaScript Object Notation) — для автоматизированной обработки скриптами.
- syslog — для совместимости с традиционными системами сбора логов.

## Практические сценарии

### Базовый просмотр логов

```bash
# Все логи (в обратном хронологическом порядке)
journalctl

# Логи в реальном времени (поток событий)
journalctl -f

# Логи ядра (аналог dmesg)
journalctl -k

# Логи ядра в реальном времени
journalctl -kf

# Логи с последней загрузки
journalctl -b

# Логи с предыдущей загрузки
journalctl -b -1

# Список всех зарегистрированных загрузок
journalctl --list-boots

# Логи от новых к старым (обратный порядок)
journalctl -r
```

### Фильтрация по службе (unit)

```bash
# Логи конкретного сервиса
journalctl -u nginx.service

# Логи сервиса в реальном времени
journalctl -u nginx.service -f

# Логи нескольких сервисов
journalctl -u sshd.service -u httpd.service
```

### Фильтрация по времени

```bash
# За последний час
journalctl --since "1 hour ago"

# С начала текущего дня
journalctl --since today

# С определенной даты и времени
journalctl --since "2024-01-15 10:00:00" --until "2024-01-15 11:00:00"

# Между двумя датами
journalctl --since "2023-10-26 18:00:00" --until "2023-10-26 18:10:00"
```

### Фильтрация по процессам, пользователям и файлам

```bash
# По идентификатору процесса (PID)
journalctl _PID=1234

# По идентификатору пользователя (UID)
journalctl _UID=1000

# По пути к исполняемому файлу
journalctl /usr/lib/systemd/systemd

# По конкретному исполняемому файлу (поле EXE)
journalctl EXE=/usr/sbin/nginx
```

### Фильтрация по уровню приоритета

Уровни: `0 emerg`, `1 alert`, `2 crit`, `3 err`, `4 warning`, `5 notice`, `6 info`, `7 debug`.

```bash
# Только ошибки и более критичные сообщения (по имени уровня)
journalctl -p err

# Диапазон уровней (цифровой формат)
journalctl -p 0..3

# Диапазон уровней (предупреждения и ошибки)
journalctl -p warning..err
```

### Вывод последних N строк

```bash
# Последние 50 строк
journalctl -n 50

# Последние 100 строк для конкретного сервиса
journalctl -u nginx -n 100
```

### Поиск по содержимому логов

```bash
# Встроенный поиск journalctl (быстрее, использует индексы)
journalctl -u nginx.service -g "error"

# Традиционный grep (без пейджера для конвейеров)
journalctl -u nginx --no-pager | grep "error"

# Перенаправление вывода в файл без пейджера
journalctl --since today --no-pager > /tmp/today.log
```

### Комбинирование фильтров

```bash
# Ошибки конкретного сервиса за последний час без пейджера
journalctl -u nginx -p err --since "1 hour ago" --no-pager

# Логи ядра за последние 30 минут
journalctl -k --since "30 min ago"

# Логи конкретного сервиса за последние 30 минут в реальном времени
journalctl -u nginx --since "30 min ago" -f
```

### Экспорт в различные форматы

```bash
# JSON (одна строка на запись — для скриптов)
journalctl -u nginx.service --output=json

# JSON (красивый, многострочный — для анализа)
journalctl -u nginx.service --output=json-pretty

# JSON с экранированием (Server-Sent Events)
journalctl -u nginx.service --output=json-sse

# Традиционный syslog-формат
journalctl -u nginx.service --output=syslog

# Только сообщение (без метаданных)
journalctl -u nginx.service --output=cat
```

### Сравнение логов между загрузками

```bash
# Логи сервиса за текущую загрузку
journalctl -u nginx.service -b 0

# Логи сервиса за предыдущую загрузку
journalctl -u nginx.service -b -1
```

### Мониторинг подробных метаданных

```bash
# Показать подробные метаданные (verbose output)
journalctl -u nginx.service -o verbose

# Фильтрация по конкретному полю в verbose-режиме
journalctl -u nginx.service -o verbose | grep _PID
```

## Дополнительная информация

### Лучшие практики использования

**Производительность:** Всегда предпочтительна фильтрация по метаданным (`-u`, `-p`, `--since`) — она использует индексы журнала. Текстовый поиск (`-g` или `grep`) требует полного сканирования всех записей.

**Скрипты и автоматизация:** Используйте `--no-pager` для отключения пейджера и `--output=json` для получения структурированного вывода, который легко парсить программно.

**Долгосрочный анализ:** Для сравнения поведения сервиса между загрузками системы используйте флаги `-b 0` (текущая загрузка) и `-b -1` (предыдущая загрузка).
