# Диагностика и информация о CPU

## Определения

**`/proc/cpuinfo`** — виртуальный файл в системе `/proc`, предоставляющий детальную информацию от ядра о каждом логическом процессорном ядре (частота, кэш, флаги инструкций, известные уязвимости).

**`lscpu`** — утилита, агрегирующая данные из `/proc/cpuinfo` и `/sys` для представления архитектуры CPU и топологии системы (сокеты, ядра, потоки) в удобном человекочитаемом формате.

**`dmidecode`** — инструмент для чтения таблиц DMI (SMBIOS), позволяющий получить низкоуровневые аппаратные спецификации напрямую из BIOS/UEFI (модель, серийные номера, физические характеристики разъемов).

**`nproc`** — простая утилита для вывода количества доступных вычислительных юнитов (ядер/потоков), используемая преимущественно в скриптах.

**CPU Scaling Governor** — механизм ядра Linux, динамически управляющий частотой процессора в зависимости от текущей нагрузки и выбранного профиля энергопотребления.

## Базовые концепции

### Источники данных и их различия

| Источник | Уровень данных | Основное назначение |
| :--- | :--- | :--- |
| **Ядро (`lscpu`, `/proc/cpuinfo`)** | Операционный | Информация о том, как ОС видит и использует процессор. |
| **BIOS (`dmidecode`)** | Аппаратный | Информация о физическом железе, сокетах и спецификациях производителя. |
| **Sysfs (`/sys/devices/...`)** | Реальное время | Текущее состояние (частота, лимиты, температура) в динамике. |

### Топология процессора

Понимание иерархии ресурсов критично для оптимизации производительности (CPU pinning) и настройки виртуализации:

- **Socket (Сокет):** Физический разъем на материнской плате для установки процессора.
- **Core (Ядро):** Независимый вычислительный блок внутри процессора.
- **Thread (Поток/Логическое ядро):** Логический вычислительный юнит (технология Hyper-Threading), делящий ресурсы физического ядра.
- **NUMA (Non-Uniform Memory Access):** Архитектура многопроцессорных систем, где доступ к локальной памяти сокета быстрее, чем к памяти другого сокета.

### Виртуализация и CPU

В виртуальных средах информация о CPU отражает настройки гипервизора:

- Без включенной **Nested Virtualization** гостевая ОС не увидит флаги аппаратного ускорения (`vmx` для Intel, `svm` для AMD).
- Модель процессора может отображаться как эмулированная (например, "Common KVM processor").

Подробнее см. [Обзор виртуализации](../../Virtualization/virtualization_overview.md).

## Практические сценарии

### Идентификация архитектуры и топологии (`lscpu`)

```bash
# Общая сводка по архитектуре и ресурсам
lscpu

# Проверка количества физических сокетов и ядер на сокет
lscpu | grep -E "Socket|Core|Thread"

# Подробная таблица топологии (онлайн-статус, сокеты, ядра)
lscpu -e
```

### Детальный анализ характеристик ядер (`/proc/cpuinfo`)

```bash
# Модель процессора и поддерживаемые инструкции (флаги)
grep -E "model name|flags" /proc/cpuinfo | head -n 2

# Проверка поддержки аппаратной виртуализации
grep -E "vmx|svm" /proc/cpuinfo

# Поиск известных аппаратных уязвимостей (Spectre, Meltdown и др.)
grep "bugs" /proc/cpuinfo | head -n 1

# Количество логических ядер (потоков)
grep -c "^processor" /proc/cpuinfo
```

### Низкоуровневая аппаратная информация (`dmidecode`)

Используется для инвентаризации и проверки физических характеристик сокетов.

```bash
# Детальная информация о физических процессорах
sudo dmidecode -t processor

# Проверка максимальной частоты, поддерживаемой оборудованием (из BIOS)
sudo dmidecode -t processor | grep "Max Speed"

# Просмотр серийных номеров (asset management)
sudo dmidecode -t processor | grep "Serial Number"
```

### Управление частотой и профилями (Scaling Governor)

Проверка и настройка режимов энергопотребления через интерфейс `sysfs`.

```bash
# Текущий профиль (governor) для всех ядер
cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

# Доступные профили (performance, powersave, schedutil и др.)
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors

# Текущая частота ядер в кГц
cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq
```

Подробнее о настройке профилей производительности см. [tuned](../../Core/tuned.md).

### Диагностика перегрева и троттлинга

Троттлинг (снижение частоты) происходит при достижении критических температур.

```bash
# Поиск сообщений о температурных событиях в журнале ядра
dmesg | grep -iE "thermal|throttl"

# Проверка статуса троттлинга в реальном времени (на некоторых системах)
grep -i "thermal" /proc/cpuinfo
```

## Дополнительная информация

### Выбор конфигурации: Один мощный CPU vs Несколько CPU

При проектировании серверов выбор между одним многоядерным процессором и несколькими сокетами влияет на латентность:

| Аспект | Один CPU (много ядер) | Несколько CPU |
| :--- | :--- | :--- |
| **Латентность памяти** | Минимальная (нет NUMA-переходов) | Выше (из-за межпроцессорного взаимодействия) |
| **Пропускная способность** | Ограничена одним контроллером | Выше (суммируются каналы памяти сокетов) |
| **Отказоустойчивость** | Единая точка отказа | Выше (система может продолжить работу при сбое CPU) |
| **Стоимость** | Обычно ниже (проще плата и охлаждение) | Выше (сложная топология, больше лицензий ПО) |

**Рекомендация:** Для баз данных (OLTP) и задач, чувствительных к задержкам, предпочтительнее один мощный CPU. Для параллельных вычислений (HPC, рендеринг) — многопроцессорные системы.
