# Диагностика и информация о CPU

## Определения

- **`/proc/cpuinfo`**: Псевдофайл в файловой системе `/proc`, предоставляющий необработанную информацию от ядра о каждом логическом процессорном ядре.
- **`lscpu`**: Утилита командной строки, которая собирает и агрегирует данные из `/proc/cpuinfo` и `/sys`, представляя их в удобном для чтения формате.
- **`dmidecode`**: Инструмент для извлечения низкоуровневой информации об аппаратном обеспечении компьютера из таблиц DMI (Desktop Management Interface).
- **`nproc`**: Утилита для быстрого получения количества доступных процессорных ядер.
- **DMI/SMBIOS**: Стандарт, позволяющий операционной системе получать данные напрямую от BIOS/UEFI, включая детальные спецификации компонентов, такие как модель процессора, серийные номера и производитель.

## Основные концепции

### Разница в источниках данных

| Источник | Данные от | Преимущества | Ограничения |
|----------|-----------|--------------|-------------|
| `lscpu`, `/proc/cpuinfo` | Ядро Linux | Отражает реальное состояние с точки зрения ОС | Не показывает скрытые от ядра детали |
| `dmidecode` | BIOS/UEFI (DMI/SMBIOS) | Показывает аппаратные спецификации от производителя | Зависит от качества заполнения таблиц DMI |
| `/sys/devices/system/cpu/` | Ядро Linux (sysfs) | Детальная информация о состоянии CPU в реальном времени | Требует знания структуры директорий |

### Уровни детализации

- **`/proc/cpuinfo`**: Подробная, но "сырая" информация для каждого логического ядра отдельно (processor, vendor_id, cpu MHz, cache size, flags).
- **`lscpu`**: Агрегированная и структурированная сводка с топологией (сокеты, ядра, потоки, кэши).
- **`dmidecode -t processor`**: Низкоуровневые характеристики из BIOS (максимальная частота, статус сокетов, характеристики модулей памяти).

### Виртуализация и CPU

На виртуальных машинах информация о CPU отражает виртуализированное окружение:

- `/proc/cpuinfo` показывает CPU гостевой ОС
- `dmidecode` может показывать информацию о виртуальном BIOS
- Флаги виртуализации (`vmx`, `svm`) могут отсутствовать без nested virtualization

Подробнее см. [Виртуализация в Linux](../../Virtualization/virtualization_overview.md).

## Практические сценарии

### `lscpu`: Быстрый обзор архитектуры CPU

```bash
# Базовая информация
lscpu

# Только количество ядер
lscpu | grep '^CPU(s):'

# Информация о кэшах
lscpu | grep -i cache

# Проверка поддержки виртуализации
lscpu | grep -i virtualization

# Вывод в формате JSON (для скриптов)
lscpu -J

# Сравнение онлайн/офлайн ядер
lscpu -e
```

**Ключевые поля вывода:**

| Поле | Описание |
|------|----------|
| `Architecture` | Архитектура (x86_64, aarch64, i686) |
| `CPU(s)` | Общее количество логических ядер |
| `Core(s) per socket` | Количество физических ядер на сокет |
| `Socket(s)` | Количество процессорных сокетов |
| `NUMA node(s)` | Количество NUMA-нод (важно для серверов) |
| `Vendor ID` | Производитель (GenuineIntel, AuthenticAMD) |
| `CPU op-mode(s)` | Поддерживаемые режимы (32-bit, 64-bit) |
| `Byte Order` | Порядок байт (Little Endian, Big Endian) |
| `Virtualization` | Поддержка аппаратной виртуализации (VT-x, AMD-V) |
| `L1d/L1i/L2/L3 cache` | Размеры кэшей данных, инструкций, уровней 2 и 3 |
| `CPU MHz` | Текущая частота (может меняться с governor) |
| `CPU max/min MHz` | Диапазон поддерживаемых частот |
| `BogoMIPS` | Индикатор производительности (не для сравнений) |
| `Flags` | Поддерживаемые инструкции (sse, avx, aes, и т.д.) |

### `/proc/cpuinfo`: Детальная информация по ядрам

```bash
# Просмотр всей информации
cat /proc/cpuinfo

# Только модель процессора
grep 'model name' /proc/cpuinfo | head -1

# Поддерживаемые инструкции (flags)
grep 'flags' /proc/cpuinfo | head -1

# Количество логических ядер
grep -c '^processor' /proc/cpuinfo

# Физические ядра на сокет
grep 'cpu cores' /proc/cpuinfo | sort -u

# Проверка поддержки виртуализации Intel
grep -E 'vmx|nested' /proc/cpuinfo

# Проверка поддержки виртуализации AMD
grep -E 'svm|nested' /proc/cpuinfo

# Частота каждого ядра (может отличаться при dynamic scaling)
grep 'cpu MHz' /proc/cpuinfo
```

**Ключевые поля на каждое ядро:**

| Поле | Описание |
|------|----------|
| `processor` | Номер логического ядра |
| `vendor_id` | Производитель CPU |
| `cpu family`, `model`, `stepping` | Идентификаторы модели |
| `model name` | Полное название модели |
| `cpu MHz` | Текущая частота ядра |
| `cache size` | Размер L2 кэша |
| `physical id` | Номер физического сокета |
| `siblings` | Количество логических ядер в сокете |
| `core id` | Номер физического ядра |
| `cpu cores` | Количество физических ядер в сокете |
| `flags` | Поддерживаемые инструкции CPU |
| `bugs` | Известные уязвимости (spectre_v1, spectre_v2, mds, и т.д.) |

### `dmidecode`: Аппаратные детали процессора

Используется для получения специфических аппаратных данных из BIOS/UEFI.

```bash
# Информация о процессоре
sudo dmidecode -t processor

# Только тип сокета
sudo dmidecode -t processor | grep -i socket

# Максимальная частота из BIOS
sudo dmidecode -t processor | grep -i "max speed"

# Информация о сокетах (включая пустые)
sudo dmidecode -t 4

# Серийный номер процессора (если доступен)
sudo dmidecode -t processor | grep -i serial
```

**Когда использовать `dmidecode` вместо `lscpu`:**

- Определение точной модели CPU для инвентаризации
- Проверка максимальной поддерживаемой частоты
- Информация о статусах сокетов (заполнен/пуст)
- Серийные номера для asset management

### `nproc`: Быстрое получение числа ядер

```bash
# Количество доступных онлайн ядер
nproc

# Общее количество (включая офлайн)
nproc --all

# В скриптах для настройки параллелизма
make -j$(nproc)
```

### `/sys`: Информация о состоянии CPU в реальном времени

```bash
# Текущий governor для каждого ядра
cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

# Доступные governor'ы
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors

# Текущая частота (kHz)
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq

# Мин/макс частота
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_min_freq
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_max_freq

# Информация о topology (сокеты, ядра, потоки)
ls /sys/devices/system/cpu/
```

**Типы CPU governor:**

- `performance`: Максимальная производительность
- `powersave`: Энергосбережение
- `ondemand`: Динамическое масштабирование по нагрузке
- `conservative`: Более плавное масштабирование, чем ondemand
- `schedutil`: Современный governor на основе планировщика (рекомендуется)

Подробнее о CPU governor см. [CPU Frequency Scaling](../../Core/cpu_pinning.md).

### Диагностика проблем с CPU

```bash
# Проверка троттлинга (thermal throttling)
grep -i "thermal" /proc/cpuinfo
dmesg | grep -i "thermal\|throttl"

# Проверка известных уязвимостей (spectre, meltdown)
grep 'bugs' /proc/cpuinfo | head -1

# Проверка стабильности частоты
watch -n1 "grep 'cpu MHz' /proc/cpuinfo | head -4"

# NUMA topology
numactl --hardware

# Проверка изоляции CPU (cpu pinning)
cat /proc/cmdline | grep isolcpus
```

## Дополнительная информация

### Надёжность источников

| Источник | Надёжность | Примечания |
|----------|------------|------------|
| `lscpu` | Высокая | Данные от ядра, актуальное состояние |
| `/proc/cpuinfo` | Высокая | Прямой интерфейс ядра |
| `dmidecode` | Средняя | Зависит от качества DMI таблиц от производителя |
| `/sys` | Высокая | Реальное состояние в реальном времени |

### Связанные инструменты

- **`top`, `htop`, `pidstat`**: Мониторинг использования CPU процессами — см. [Диагностика процессов](../Processes/)
- **`perf`**: Профилирование производительности CPU — см. [perf](../Performance/perf.md)
- **`sar`**: Исторические данные использования CPU — см. [sar](../Performance/sar.md)
- **`numactl`**: Управление NUMA affinity — см. [NUMA](../../Core/cpu_pinning.md)

## Дополнительная информация

### Выбор конфигурации CPU: один мощный vs несколько менее мощных

| Аспект | **Один CPU (больше ядер)** | **Несколько CPU (меньше ядер каждый)** |
| :--- | :--- | :--- |
| **Стоимость** | Дешевле (1 сокет, меньше RAM-модулей) | Дороже (больше сокетов, больше RAM-слотов) |
| **Латентность памяти** | Ниже (единый контроллер памяти, нет NUMA) | Выше (NUMA, доступ к «чужой» памяти медленнее) |
| **Масштабируемость RAM** | Ограничена 1 каналом/контроллером | Выше (больше контроллеров и каналов памяти) |
| **Отказоустойчивость** | Одна точка отказа | При сбое одного CPU система может выжить |
| **Лицензирование ПО** | Дешевле (лицензии часто по сокетам) | Дороже (больше сокетов = больше лицензий) |
| **Производительность** | Лучше для латентно-чувствительных нагрузок | Лучше для пропускной способности (memory bandwidth) |

**Рекомендации:**

- **Один CPU** — для баз данных (PostgreSQL, MySQL, Redis), виртуализации, Kubernetes-нод, latency-sensitive приложений
- **Несколько CPU** — для параллельных нагрузок (рендеринг, компиляция, batch), когда нужен максимальный объём RAM

**Проверка NUMA-топологии:**

```bash
# Показать NUMA-ноды и их топологию
numactl --hardware

# Показать распределение ядер по NUMA-нодам
lscpu | grep -i numa
```
