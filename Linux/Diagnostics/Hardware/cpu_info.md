# Диагностика и информация о CPU

## Определения

**`/proc/cpuinfo`** — виртуальный файл в системе `/proc`, предоставляющий детальную информацию от ядра о каждом логическом процессорном ядре (частота, кэш, флаги инструкций, известные уязвимости).

**`lscpu`** — утилита, агрегирующая данные из `/proc/cpuinfo` и `/sys` для представления архитектуры CPU и топологии системы (сокеты, ядра, потоки) в удобном человекочитаемом формате. Поддерживает структурированный вывод в JSON (`-J`).

**`dmidecode`** — инструмент для чтения таблиц DMI (SMBIOS), позволяющий получить низкоуровневые аппаратные спецификации напрямую из BIOS/UEFI (модель, серийные номера, физические характеристики разъемов).

**`cpuid`** — специализированная утилита для дампинга подробной информации о функциях процессора, полученной напрямую через инструкцию CPUID (преимущественно для x86 архитектур).

**`hwinfo --cpu`** — комплексная утилита для инвентаризации, предоставляющая детальный технический отчет о процессоре, включая ревизии и специфические идентификаторы.

**`turbostat`** — утилита (из пакета `linux-cpupower`), отображающая реальную частоту ядер (включая Turbo Boost), энергопотребление (RAPL) и C-states в реальном времени.

**`cpupower`** — набор инструментов для управления параметрами энергопотребления процессора, частотными лимитами и профилями производительности (governors).

**`nproc`** — простая утилита для вывода количества доступных вычислительных юнитов (ядер/потоков), используемая преимущественно в скриптах.

## Базовые концепции

### Источники данных и их различия

| Источник | Уровень данных | Основное назначение |
| :--- | :--- | :--- |
| **Ядро (`lscpu`, `/proc/cpuinfo`)** | Операционный | Информация о том, как ОС видит и использует процессор. |
| **BIOS (`dmidecode`)** | Аппаратный | Информация о физическом железе, сокетах и спецификациях производителя. |
| **Sysfs (`/sys/devices/...`)** | Реальное время | Текущее состояние (частота, лимиты, температура, уязвимости). |

### Топология и современные архитектуры

Понимание иерархии ресурсов критично для оптимизации производительности (CPU pinning) и настройки виртуализации:

- **Socket (Сокет):** Физический разъем на материнской плате.
- **Core (Ядро):** Независимый вычислительный блок.
- **Hybrid Architecture (Гибридные архитектуры):**
    - **Intel (Performance/Efficient):** **P-cores** (производительные) и **E-cores** (энергоэффективные).
    - **ARM (big.LITTLE):** Кластеры мощных («big») и простых («LITTLE») ядер для экономии энергии.
- **Thread (Поток/Логическое ядро):** Логический юнит (Hyper-Threading/SMT), делящий ресурсы физического ядра.
- **NUMA (Non-Uniform Memory Access):** Архитектура, где память привязана к конкретным сокетам/чиплетам. Доступ к «своей» памяти быстрее.

### Виртуализация и CPU

В виртуальных средах информация о CPU отражает настройки гипервизора:

- Без включенной **Nested Virtualization** гостевая ОС не увидит флаги аппаратного ускорения (`vmx` для Intel, `svm` для AMD). На ARM64 наличие поддержки проверяется флагом `virt`.
- Модель процессора может отображаться как эмулированная (например, "Common KVM processor").

Подробнее см. [Обзор виртуализации](../../Virtualization/virtualization_overview.md).

## Практические сценарии

### Идентификация архитектуры и топологии (`lscpu`)

```bash
# Общая сводка по архитектуре и ресурсам
lscpu

# Вывод в формате JSON для автоматизации
lscpu -J

# Проверка типов ядер (P-cores / E-cores) и кэша
lscpu -e

# Просмотр топологии кэша
lscpu -C

# Просмотр NUMA-узлов
lscpu -G
```

### Детальный анализ характеристик ядер (`/proc/cpuinfo`)

```bash
# Модель процессора и поддерживаемые инструкции (флаги)
grep -E "model name|flags" /proc/cpuinfo | head -n 2

# Сравнение ключевых флагов x86 vs ARM64
# x86: vmx, svm, aes, avx, sse4_2
# ARM: virt, fp, asimd, aes, crc32

# Проверка поддержки аппаратной виртуализации (x86)
grep -E "vmx|svm" /proc/cpuinfo

# Проверка поддержки виртуализации и SIMD на ARM64
lscpu | grep -iE "virt|asimd"

# Количество логических ядер (потоков)
grep -c "^processor" /proc/cpuinfo
```

### Низкоуровневая аппаратная информация

Требует прав `root`. Показывает физические данные, прошитые в BIOS.

```bash
# Детальная информация о физических процессорах
sudo dmidecode -t processor

# Технический отчет от hwinfo
hwinfo --cpu

# Просмотр версии микрокода (Microcode)
grep "microcode" /proc/cpuinfo | head -n 1
```

### Управление частотой и профилями (Scaling Governor)

Современные системы используют `intel_pstate`, `amd-pstate` или универсальные драйверы `cpufreq`.

```bash
# Текущий профиль (governor) для всех ядер
cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
# → performance (макс. частота) или powersave (энергосбережение)

# Получение подробной информации о частотах через cpupower
sudo cpupower frequency-info

# Реальный мониторинг частот, вольтажа и Turbo Boost (turbostat)
sudo turbostat --Interval 1
```

Подробнее о настройке профилей производительности см. [tuned](../../Core/tuned.md).

### Проверка уязвимостей CPU

Современный и надежный способ проверки состояния защиты от Spectre, Meltdown и др.

```bash
# Список всех уязвимостей и статус их исправления (mitigation)
grep . /sys/devices/system/cpu/vulnerabilities/*

# → /sys/devices/system/cpu/vulnerabilities/itlb_multihit:KVM: Mitigation: VMX unsupported
# → /sys/devices/system/cpu/vulnerabilities/l1tf:Mitigation: PTE Inversion
# → /sys/devices/system/cpu/vulnerabilities/meltdown:Mitigation: PTI
# → /sys/devices/system/cpu/vulnerabilities/spectre_v1:Mitigation: usercopy/swapgs barriers and __user pointer sanitization
```

### Диагностика перегрева и троттлинга

Троттлинг (снижение частоты) происходит при достижении критических температур.

```bash
# Мониторинг температуры ядер в реальном времени (пакет lm-sensors)
watch sensors

# Поиск сообщений о температурных событиях в журнале ядра
dmesg | grep -iE "thermal|throttl"
# → CPU0: Package temperature above threshold, cpu clock throttled

# Проверка лимитов температуры в sysfs
cat /sys/class/thermal/thermal_zone*/temp
```
