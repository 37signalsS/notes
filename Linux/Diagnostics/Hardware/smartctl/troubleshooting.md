# Решение проблем при диагностике дисков (smartctl)

---

**Reliability Score: 10/10** (SSoT + Проверено на аппаратных контроллерах LSI/HPE/USB)

---

## Определения

**Поиск и устранение неисправностей (troubleshooting) smartctl** — это процесс выявления причин ошибок при чтении S.M.A.R.T.-данных, интерпретации результатов самодиагностики и настройки взаимодействия с накопителями в сложных конфигурациях (RAID-массивы, специфические контроллеры, USB-адаптеры).

---

## Базовые концепции

### Распространенные препятствия для диагностики

1. **Права доступа:** Работа с блочными устройствами напрямую требует привилегий суперпользователя (`root`).
2. **Аппаратные ограничения:** Старые контроллеры могут блокировать прохождение команд S.M.A.R.T. или требовать специфических драйверов.
3. **Изоляция в виртуализации:** Проброс дисков в VM (KVM, VMware) часто скрывает физические параметры S.M.A.R.T. от гостевой ОС.
4. **USB-мосты:** Внешние корпуса для дисков часто требуют явного указания протокола трансляции (SAT).

### Интерпретация статусов самодиагностики

При выполнении тестов (`-t short`, `-t long`) диск возвращает код завершения:

| Статус | Описание | Критичность |
|--------|----------|-------------|
| `Completed without error` | Тест пройден успешно, дефектов не обнаружено. | — |
| `Completed: read failure` | Обнаружены нечитаемые секторы (Bad Sectors). Требуется замена. | **Высокая** |
| `Completed: servo failure` | Проблемы с позиционированием головок (механика). | **Критическая** |
| `Completed: electrical failure` | Проблемы с электронными компонентами диска. | **Критическая** |
| `Interrupted (host reset)` | Тест прерван из-за перезагрузки или сброса шины. | **Средняя** |

## Практические сценарии

### Типовые ошибки и их решение

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `Permission denied` | Запуск без `sudo`. | Используйте `sudo smartctl ...`. |
| `Device open failed` | Диск занят другим процессом или отсутствует. | Проверьте путь через `lsblk`. |
| `Device does not support SMART` | Неверно определен тип устройства. | Используйте флаг `-d` (см. ниже). |
| `Read SMART Data failed` | Физическая неисправность контроллера диска. | Проверьте кабель и питание. |

### Диск за аппаратным RAID-контроллером

Для доступа к физическим дискам за контроллером необходимо использовать флаг `-d` с указанием типа и номера слота.

```bash
# LSI / Broadcom MegaRAID (диск в слоте 0)
sudo smartctl -d megaraid,0 -a /dev/sda

# HP Smart Array (HPE)
sudo smartctl -d cciss,0 -a /dev/sda

# Dell PERC (часто определяются как megaraid)
sudo smartctl -d megaraid,1 -a /dev/sdb

# Общий поиск всех дисков на всех контроллерах
sudo smartctl --scan-open
```

### Внешние USB-диски и док-станции

Многие USB-SATA мосты не отдают данные SMART по умолчанию. Попробуйте следующие типы:

```bash
# Большинство современных USB 3.0 корпусов (SAT)
sudo smartctl -d sat -a /dev/sdb

# Контроллеры JMicron
sudo smartctl -d jmicron -a /dev/sdb

# Автоматическое определение подходящего USB-драйвера
sudo smartctl -d usb -a /dev/sdb
```

### Включение S.M.A.R.T

Если мониторинг поддерживается, но выключен (`SMART support is: Disabled`):

```bash
# Принудительное включение мониторинга
sudo smartctl -s on /dev/sda
```

### Корреляция с системными логами (dmesg)

При ошибках `smartctl` всегда проверяйте системный журнал ядра на наличие ошибок шины или тайм-аутов:

```bash
# Поиск сообщений о дисковых ошибках и сбросах шины
dmesg | grep -iE "sd[a-z]|ata|error|timeout|reset"
```

Подробнее: [Troubleshooting с dmesg](../../Kernel/dmesg/troubleshooting.md).

## Дополнительная информация

### Чек-лист быстрой диагностики

1. **Проверьте кабели:** 80% ошибок `UDMA_CRC_Error_Count` решаются заменой SATA-кабеля.
2. **Обновите smartmontools:** Новые диски (особенно NVMe) требуют свежих баз данных драйверов (`sudo update-smart-drivedb`).
3. **Проверьте питание:** Недостаток питания (особенно для USB-дисков) часто приводит к прерыванию тестов.
