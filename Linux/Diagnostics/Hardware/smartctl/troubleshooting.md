# Решение проблем при диагностике дисков (smartctl)

## Определения

**Поиск и устранение неисправностей (troubleshooting) smartctl** — это процесс выявления причин ошибок при чтении S.M.A.R.T.-данных, интерпретации результатов самодиагностики и настройки взаимодействия с накопителями в сложных конфигурациях (RAID-массивы, специфические контроллеры, USB-адаптеры, виртуализация).

---

## Базовые концепции

### Типовые препятствия для диагностики

1.  **Права доступа:** Прямое обращение к блочным устройствам требует привилегий суперпользователя (`root`).
2.  **Аппаратная блокировка:** Некоторые RAID-контроллеры и USB-мосты скрывают команды S.M.A.R.T. или требуют инкапсуляции через специфические драйверы.
3.  **Виртуализация и облако:**
    *   **ВМ (KVM/VMware):** Для доступа к SMART требуется проброс устройства (PCI Passthrough). Виртуальные диски (`virtio-blk`) обычно не отдают физические параметры.
    *   **Облачные диски (EBS, Azure Disk):** Не поддерживают SMART, так как являются сетевыми блочными устройствами. Диагностика проводится через API провайдера.
4.  **Устаревшие базы данных:** Новые модели дисков могут распознаваться некорректно без обновления `smartd-drivedb`.

### Интерпретация статусов самодиагностики

При выполнении тестов (`-t short`, `-t long`) диск возвращает код завершения, который можно увидеть в `smartctl -l selftest`:

| Статус | Описание | Критичность |
| :--- | :--- | :--- |
| **`Completed without error`** | Тест пройден успешно, физических дефектов не обнаружено. | — |
| **`Completed: read failure`** | Найден нечитаемый сектор. Прямой признак деградации поверхности/ячеек. | **Высокая** |
| **`Completed: servo failure`** | Проблемы с механикой (актуатор, шпиндель). | **Критическая** |
| **`Completed: electrical failure`** | Неисправность электрических цепей или контроллера. | **Критическая** |
| **`Interrupted (host reset)`** | Тест прерван из-за сброса шины или перезагрузки системы. | **Средняя** |

## Практические сценарии

### Типовые ошибки и их решение

| Ошибка | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `Permission denied` | Запуск от обычного пользователя. | Используйте `sudo smartctl ...`. |
| `Device open failed` | Устройство занято, защищено или путь неверный. | Проверьте путь через `lsblk` или `fdisk -l`. |
| `Device does not support SMART` | Неверный тип устройства или SMART выключен. | Используйте флаг `-d` или `-s on`. |
| `Read SMART Data failed` | Сбой контроллера или несовместимый USB-мост. | Попробуйте другой тип драйвера (`-d sat`). |

### Диск за аппаратным RAID-контроллером

Для доступа к дискам в массиве необходимо «пробросить» команды через драйвер контроллера.

```bash
# LSI / Broadcom MegaRAID (диск в слоте 0)
sudo smartctl -d megaraid,0 -a /dev/sda

# HP Smart Array (HPE)
sudo smartctl -d cciss,0 -a /dev/sda

# Dell PERC (обычно использует драйвер megaraid)
sudo smartctl -d megaraid,1 -a /dev/sdb

# Автоматический поиск дисков за всеми контроллерами
sudo smartctl --scan-open
```

### Внешние USB-диски и док-станции

Многие USB-контроллеры требуют явного указания протокола трансляции (**SAT — SCSI to ATA Translation**).

```bash
# Попытка универсальной трансляции (рекомендуется)
sudo smartctl -d sat -a /dev/sdb

# Для старых контроллеров JMicron
sudo smartctl -d jmicron -a /dev/sdb

# Если устройство является NVMe-диском в USB-боксе
sudo smartctl -d sntjmicron -a /dev/sdb
```

### Принудительное включение SMART

Если диагностика поддерживается, но деактивирована:

```bash
# Активация мониторинга и автоматического сохранения логов
sudo smartctl -s on -o on -S on /dev/sda
```

### Корреляция с системным журналом (dmesg)

Ошибки `smartctl` часто сопровождаются сообщениями ядра о сбоях на шине. Для NVMe-накопителей это критично, так как проблема может быть в PCIe-линке.

```bash
# Поиск I/O ошибок и сбросов линка
dmesg | grep -iE "sd[a-z]|ata|nvme|error|timeout|reset"
# → result: blk_update_request: I/O error, dev sda, sector ...
```

*   [**Troubleshooting с dmesg**](../../Kernel/dmesg/troubleshooting.md) — общие принципы.
*   [**Диагностика NVMe: AER и Reset**](../nvme-errors-diagnostics.md) — глубокий анализ PCIe-ошибок.

## Дополнительная информация

### Чек-лист быстрого исправления

1.  **Проверка кабелей:** Ошибки `UDMA_CRC_Error_Count` в 90% случаев исправляются заменой SATA-кабеля или переподключением разъема.
2.  **Обновление баз данных:** Если диск определяется как `Unknown model`, обновите базу данных драйверов:
    ```bash
    sudo update-smart-drivedb
    ```
3.  **Температурный режим:** Если тест прерывается с ошибкой `Aborted by host`, проверьте температуру. Некоторые диски прекращают тесты при перегреве.
4.  **Sense Data (SAS):** При анализе SAS-дисков обращайте внимание на коды Sense (например, `Sense Key: Medium Error`). Они точно указывают на физический сбой.
