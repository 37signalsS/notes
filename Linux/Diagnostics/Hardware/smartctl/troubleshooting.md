# Решение проблем при диагностике дисков (smartctl)

## Определения

**Поиск и устранение неисправностей (troubleshooting) smartctl** — это процесс выявления причин ошибок при чтении S.M.A.R.T.-данных, интерпретации результатов самодиагностики и настройки взаимодействия с накопителями в сложных конфигурациях (RAID-массивы, специфические контроллеры).

---

## Базовые концепции

### Распространенные препятствия для диагностики

1. **Аппаратные ограничения:** старые контроллеры или диски могут не поддерживать команды S.M.A.R.T. или блокировать их передачу (особенно в RAID-массивах).
2. **Программные блокировки:** S.M.A.R.T. может быть отключен на уровне прошивки или ОС для экономии ресурсов или из-за политик безопасности.
3. **Ошибки интерфейса:** проблемы с кабелями или портами могут имитировать аппаратные ошибки диска.

### Интерпретация статусов самодиагностики

При выполнении тестов (`-t short`, `-t long`) диск возвращает код завершения, который требует расшифровки:

| Статус | Описание | Критичность |
|--------|----------|-------------|
| `Completed without error` | Тест пройден успешно, дефектов не обнаружено. | — |
| `Completed: read failure` | Обнаружены нечитаемые секторы (Bad Sectors). | **Высокая** |
| `Completed: servo failure` | Проблемы с позиционированием головок (механика). | **Критическая** |
| `Completed: electrical failure` | Проблемы с электронными компонентами диска. | **Критическая** |
| `Aborted by host` | Тест был прерван пользователем или операционной системой. | — |

## Практические сценарии

### Диск за RAID-контроллером

Если `smartctl` не видит диск за аппаратным контроллером, необходимо явно указать тип устройства через флаг `-d`.

```bash
# LSI MegaRAID (диск в первом слоте)
sudo smartctl -d megaraid,0 -a /dev/sda

# 3ware RAID-контроллер
sudo smartctl -d 3ware,0 -a /dev/twe0

# Общий поиск доступных устройств на контроллере
sudo smartctl --scan
```

### Включение S.M.A.R.T

Если утилита сообщает, что S.M.A.R.T. поддерживается, но отключен (`SMART support is: Disabled`):

```bash
# Принудительное включение мониторинга на диске
sudo smartctl -s on /dev/sda
```

### Корреляция с системными логами (dmesg)

При обнаружении ошибок в `smartctl` необходимо проверить сообщения ядра на наличие ошибок ввода-вывода (I/O errors):

```bash
# Поиск сообщений о дисковых ошибках
dmesg | grep -iE "sd[a-z]|ata|error|timeout"
```

Подробнее о диагностике через логи ядра см. в [Troubleshooting с dmesg](../../Kernel/dmesg/troubleshooting.md).

### Расширенная диагностика NVMe (nvme-cli)

Если данных `smartctl` недостаточно для NVMe-накопителя, используйте специализированную утилиту `nvme-cli`:

```bash
# Просмотр детального лога здоровья
sudo nvme smart-log /dev/nvme0n1

# Информация о самодиагностике и ошибках
sudo nvme health-info /dev/nvme0n1
```
