# Проверка здоровья дисков с помощью smartctl

## Определения

**Проверка здоровья дисков (Disk Health Check)** — это процедура выполнения диагностических тестов и сбора данных S.M.A.R.T. для оценки текущей работоспособности накопителя. Основная цель — выявление признаков деградации (износ ячеек, ошибки поверхности) до наступления окончательного сбоя.

---

## Базовые концепции

### Установка и подготовка

Инструментарий входит в состав пакета `smartmontools`. Для современных накопителей критически важно регулярно обновлять базу данных моделей.

```bash
# Установка (Ubuntu/Debian)
sudo apt update && sudo apt install smartmontools

# Установка (RHEL/Rocky/Alma)
sudo dnf install smartmontools

# Обновление базы данных накопителей (обязательно для новых NVMe)
sudo update-smart-drivedb
```

### Интерпретация общего статуса (Health Status)

| Статус | Значение | Действие |
| :--- | :--- | :--- |
| **`PASSED`** | Диск исправен, критические пороги не достигнуты. | Плановый мониторинг. |
| **`FAILED`** | Обнаружена неисправность, пороги превышены. | Замена диска в ближайшее время. |
| **`FAILURE IS IMMINENT`** | Прогнозируется немедленный выход из строя. | Срочное копирование данных и замена. |

### Диагностика SSD и NVMe (2026+)

В отличие от HDD, твердотельные накопители требуют фокуса на ресурсе записи и целостности данных:
- **SSD (SATA):** Основной показатель — `Wear_Leveling_Count` (процент оставшейся жизни).
- **NVMe 2.x:** Использует стандартизированный Health Log. Важнейшие метрики: `Percentage Used` (износ) и `Data Units Written`.
- **ZNS (Zoned Namespaces):** Требует контроля за количеством активных и открытых зон для предотвращения ошибок записи.

## Практические сценарии

### Идентификация и сканирование устройств

```bash
# Список всех блочных устройств
lsblk

# Автоматический поиск дисков с поддержкой SMART
sudo smartctl --scan
```

### Быстрая оценка состояния

```bash
# Краткий вердикт (Health Check)
sudo smartctl -H /dev/sda

# Полный отчет (атрибуты, логи, результаты тестов)
sudo smartctl -a /dev/sda
```

### Глубокая диагностика через самотестирование

Тесты выполняются контроллером диска в фоновом режиме и не влияют на доступность данных (но могут снижать производительность).

| Тип теста | Длительность | Когда использовать |
| :--- | :--- | :--- |
| **`short`** | 2-5 мин | Ежедневная проверка основных узлов. |
| **`long`** | 1-20 ч | Полное сканирование поверхности. Рекомендуется раз в месяц. |

```bash
# Запуск теста
sudo smartctl -t short /dev/sda

# Проверка статуса выполнения и результатов
sudo smartctl -l selftest /dev/sda

# Остановка запущенного теста
sudo smartctl -X /dev/sda
```

### Анализ критических параметров (Checklist)

> **Ключевое правило:** Анализируйте не только абсолютное значение, но и его **динамику**. Если количество ошибок или переназначенных секторов растёт — диск подлежит плановой замене, не дожидаясь окончательного отказа.

#### Для HDD (Механические диски)
Следите за ростом этих атрибутов:
```bash
# Вывод таблицы атрибутов с фильтрацией по критическим ID
sudo smartctl -A /dev/sda | grep -E "Reallocated|Pending|Uncorrectable|CRC|Hours|Temperature"
```
- **Reallocated_Sector_Ct (ID 5):** Количество переназначенных «битых» секторов. Рост значения — прямой признак деградации поверхности.
- **Current_Pending_Sector (ID 197):** Секторы, ожидающие проверки (потенциальные кандидаты в «битые», которые не удалось прочитать).
- **Offline_Uncorrectable (ID 198):** Количество неисправимых ошибок при обращении к секторам.
- **UDMA_CRC_Error_Count (ID 199):** Ошибки передачи данных по шине. Часто причина в плохом кабеле SATA или неисправном бэкплейне дисковой корзины.
- **Power_On_Hours (ID 9):** Общая наработка диска в часах. Помогает оценить возраст устройства.
- **Temperature_Celsius (ID 194):** Текущая температура. Постоянный перегрев (>45-50°C) ускоряет выход из строя.

#### Для SSD (SATA)
Фокус на ресурсе ячеек памяти:
```bash
sudo smartctl -A /dev/sda | grep -E "Wear|Indicator|Written"
```
- **Wear_Leveling_Count:** Указывает на оставшийся ресурс ячеек в процентах (начинается со 100 и стремится к 0).
- **Media_Wearout_Indicator:** Аналогичный показатель износа NAND-памяти.
- **Total_LBAs_Written:** Общий объем записанных данных. Позволяет рассчитать соответствие заявленному TBW (Total Bytes Written).

#### Для NVMe (SSD)
Современный формат логов здоровья:
```bash
sudo smartctl -a /dev/nvme0 | grep -E "Percentage|Critical|Spare|Errors"
```
- **percentage_used:** Процент израсходованного ресурса (0% — новый, >100% — ресурс официально исчерпан).
- **critical_warning:** Критические предупреждения. Должен быть `0x00`. Любое другое значение (биты 0-4) означает перегрев, сбой надежности или переход в режим "только чтение".
- **available_spare:** Резерв запасных блоков для замены вышедших из строя (обычно 100%). Падение этого значения — критический сигнал.
- **media_errors:** Количество обнаруженных контроллером ошибок целостности данных.

### Автоматизация и мониторинг (JSON)

Для интеграции в скрипты используйте флаг `--json`.

```bash
# Проверка здоровья через jq
sudo smartctl -H /dev/nvme0n1 --json | jq '.smart_status.passed'
```

## Дополнительная информация

### Ограничения S.M.A.R.T.

- **Слепая зона:** S.M.A.R.T. не предсказывает внезапные сбои электроники или повреждения прошивки контроллера (до 30-40% всех случаев).
- **Троттлинг:** Современные NVMe при перегреве снижают производительность. Проверяйте температуру при диагностике тормозов.
