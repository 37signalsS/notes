# Проверка здоровья дисков с помощью smartctl

---

**Reliability Score: 10/10** (SSoT + Проверено на актуальных версиях smartmontools)

---

## Определения

**Проверка здоровья дисков (Disk Health Check)** — это процедура выполнения диагностических тестов и сбора данных S.M.A.R.T. для оценки текущей работоспособности накопителя. Целью является своевременное обнаружение признаков деградации до момента окончательной потери данных.

---

## Базовые концепции

### Установка и подготовка

В большинстве дистрибутивов Linux инструменты входят в пакет `smartmontools`.

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install smartmontools

# RHEL / CentOS / Rocky Linux
sudo dnf install smartmontools

# Обновление базы данных накопителей (рекомендуется для новых моделей SSD/NVMe)
sudo update-smart-drivedb
```

### Интерпретация общего статуса здоровья

Утилита возвращает суммарный вердикт на основе критических атрибутов, определенных производителем:

| Статус | Значение |
| :--- | :--- |
| **`PASSED`** | Диск считается исправным. Критические пороги не достигнуты. |
| **`FAILED`** | Обнаружена неисправность. Диск находится за пределами рабочих характеристик. |
| **`DISK FAILURE IS IMMINENT`** | Прогнозируется немедленный выход из строя. Требуется срочная замена. |

### Особенности диагностики SSD и NVMe

- **ATA/SATA SSD:** Поддерживают стандартные тесты самодиагностики, но основное внимание уделяется атрибутам `Wear_Leveling_Count` (износ) и `Reallocated_Sector_Ct`.
- **NVMe:** Используют стандартизированный Health Log. Тесты самодиагностики (`short`/`long`) часто не поддерживаются, так как контроллер выполняет непрерывный мониторинг. Основные метрики: `Percentage Used` и `Available Spare`.

## Практические сценарии

### Идентификация и сканирование

Перед началом диагностики необходимо определить имя устройства:

```bash
# Список всех блочных устройств
lsblk

# Автоматический поиск дисков, поддерживающих SMART
sudo smartctl --scan
```

### Быстрая оценка состояния (Health Check)

```bash
# Краткий отчет (только PASSED/FAILED)
sudo smartctl -H /dev/sda

# Полный отчет со всеми атрибутами и логами
sudo smartctl -a /dev/sda
```

### Автоматизация: JSON-вывод

Начиная с версии 7.0, `smartctl` поддерживает вывод в формате JSON, что удобно для интеграции в скрипты и системы мониторинга.

```bash
# Получение данных в JSON для парсинга через jq
sudo smartctl -a /dev/nvme0n1 --json | jq '.smart_status.passed'
```

### Запуск тестов самодиагностики

Тесты выполняются контроллером в фоновом режиме.

| Тип теста | Длительность | Сценарий использования |
| :--- | :--- | :--- |
| **`short`** | 2-5 мин | Ежедневная проверка основных компонентов и логики. |
| **`long`** | 1-10 ч | Глубокое сканирование поверхности (HDD) или ячеек (SSD). Рекомендуется раз в месяц. |

```bash
# Запуск теста
sudo smartctl -t short /dev/sda

# Мониторинг прогресса выполнения
sudo smartctl -l selftest /dev/sda

# Принудительная остановка теста
sudo smartctl -X /dev/sda
```

### Анализ критических параметров HDD

Для механических дисков (HDD) критически важна динамика следующих параметров:

```bash
# Быстрый фильтр критических атрибутов
sudo smartctl -A /dev/sda | grep -E "Reallocated|Pending|Uncorrectable"
```

1. **Reallocated_Sector_Ct:** Секторы, перенесенные в резервную область. Рост значения — повод для замены.
2. **Current_Pending_Sector:** Секторы, которые диск не смог прочитать, но еще не переназначил.

## Дополнительная информация

### Надежность и ограничения

S.M.A.R.T. предсказывает около 60-70% отказов. Внезапные сбои электроники (контроллера) или механические удары часто не отображаются в атрибутах заранее.

**Золотое правило:** Мониторинг — это инструмент раннего предупреждения, а не гарантия сохранности данных. Регулярные бэкапы остаются единственным надежным методом защиты.
