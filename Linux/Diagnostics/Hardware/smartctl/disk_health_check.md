# Проверка здоровья дисков с помощью smartctl

## Определения

**Проверка здоровья дисков (Disk Health Check)** — это процедура выполнения диагностических тестов и сбора данных S.M.A.R.T. для оценки текущей работоспособности накопителя. Целью является своевременное обнаружение признаков деградации до момента окончательной потери данных.

---

## Базовые концепции

### Установка инструментария

В большинстве дистрибутивов Linux инструменты входят в пакет `smartmontools`.

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install smartmontools

# RHEL / CentOS / Rocky Linux
sudo dnf install smartmontools
```

### Интерпретация общего статуса здоровья

Утилита возвращает суммарный вердикт на основе критических атрибутов, определенных производителем:

| Статус | Значение |
|--------|----------|
| **`PASSED`** | Диск считается исправным. Критические пороги не достигнуты. |
| **`FAILED`** | Обнаружена неисправность. Диск находится за пределами рабочих характеристик. |
| **`DISK FAILURE IS IMMINENT`** | Прогнозируется немедленный выход из строя. Требуется срочная замена. |

### Различия в диагностике ATA и NVMe

Несмотря на использование одной утилиты, методы проверки различаются:

- **ATA/SATA:** Опирается на выполнение тестов самодиагностики и анализ длинного списка атрибутов.
- **NVMe:** Использует стандартизированные флаги здоровья и счетчики износа. Большинство NVMe-дисков поддерживают только базовые тесты или не поддерживают их вовсе, полагаясь на непрерывный самомониторинг.

## Практические сценарии

### Обнаружение накопителей

Перед началом диагностики необходимо определить имя устройства в системе:

```bash
# Список всех дисков и разделов
lsblk

# Детальная инвентаризация (с именами производителей)
sudo smartctl --scan
```

Подробнее об инвентаризации см. в [hardware_listing.md](../hardware_listing.md).

### Быстрая проверка состояния

Первый шаг при подозрении на неисправность:

```bash
# Общий статус (поддерживается всеми типами дисков)
sudo smartctl -H /dev/sda

# Вывод всей доступной информации (атрибуты, логи, версии прошивок)
sudo smartctl -a /dev/sda
```

### Запуск тестов самодиагностики

Тесты выполняются самим контроллером диска в фоновом режиме, не прерывая работу ОС (но могут снижать производительность I/O).

| Тип теста | Длительность | Когда использовать |
|-----------|--------------|--------------------|
| **`short`** | 2-5 мин | Быстрая проверка электроники и участков поверхности. |
| **`long`** | 1-8 ч | Полное сканирование всей поверхности диска. |

```bash
# Запуск короткого теста
sudo smartctl -t short /dev/sda

# Запуск длительного теста
sudo smartctl -t long /dev/sda

# Проверка статуса выполнения или результата последнего теста
sudo smartctl -l selftest /dev/sda

# Принудительная остановка текущего теста
sudo smartctl -X /dev/sda
```

Расшифровка ошибок теста (read failure, servo failure) приведена в [руководстве по решению проблем](./troubleshooting.md#интерпретация-статусов-самодиагностики).

### Анализ журналов ошибок и износа

```bash
# Просмотр последних зарегистрированных ошибок оборудования
sudo smartctl -l error /dev/sda

# Быстрый поиск индикаторов износа (для SSD и NVMe)
sudo smartctl -a /dev/sda | grep -iE "wear|percent|written"
```

### Быстрый поиск критических атрибутов

Для HDD наиболее важными являются атрибуты, связанные с дефектами поверхности. Их можно быстро отфильтровать одной командой:

```bash
# Поиск переназначенных и нестабильных секторов, а также времени наработки
sudo smartctl -a /dev/sda | grep -E "Reallocated|Pending|Uncorrectable|Power_On"
```

- **Reallocated_Sector_Ct:** Количество переназначенных секторов. Любое ненулевое значение — тревожный сигнал.
- **Current_Pending_Sector:** Нестабильные секторы, ожидающие переназначения.
- **Offline_Uncorrectable:** Секторы, которые не удалось восстановить при фоновом сканировании.

### Дополнительные инструменты для NVMe

Помимо `smartctl`, для NVMe-накопителей часто используется специализированная утилита `nvme-cli`:

```bash
# Установка
sudo apt install nvme-cli

# Просмотр лога здоровья
sudo nvme smart-log /dev/nvme0
```

## Дополнительная информация

### Надежность и ограничения

Результат `PASSED` не является гарантией 100% надежности. SMART хорошо предсказывает постепенную деградацию, но внезапные отказы контроллера или электроники обычно не видны заранее.

**Золотое правило:** Бэкап важнее мониторинга. Даже идеальные показатели не гарантируют, что диск не откажет завтра.
