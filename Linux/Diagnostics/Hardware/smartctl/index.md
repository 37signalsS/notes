# Диагностика дисков с помощью smartctl

---

**Reliability Score: 10/10** (SSoT + Проверено на актуальных версиях smartmontools)

---

## Определения

**`smartctl`** — утилита командной строки из пакета `smartmontools` для управления и мониторинга систем S.M.A.R.T. на накопителях (HDD, SSD, NVMe). Это основной инструмент для оценки физического состояния дисков и прогнозирования их отказов.

**S.M.A.R.T. (Self-Monitoring, Analysis and Reporting Technology)** — встроенная в современные накопители система самодиагностики, которая отслеживает ключевые параметры работы (атрибуты) и сигнализирует о деградации устройства.

---

## Базовые концепции

### Инструментарий smartmontools

Диагностика строится на двух компонентах:

- **`smartctl`** — используется для ручного анализа, запуска тестов и настройки параметров диска.
- **`smartd`** — демон для фонового мониторинга. Автоматически проверяет состояние дисков по расписанию и отправляет уведомления (e-mail, системные логи) при обнаружении проблем. Подробнее: [`smartd_monitoring.md`](./smartd_monitoring.md).

### Поддержка протоколов и типов данных

Способ взаимодействия с S.M.A.R.T. зависит от типа накопителя и интерфейса подключения:

- **ATA (SATA HDD/SSD):** классический набор атрибутов с нормализованными значениями (Value/Worst/Threshold).
- **NVMe:** современный стандарт с упрощенным набором метрик. Включает процент износа (`percentage_used`) и критические предупреждения.
- **SCSI/SAS:** специфика серверных накопителей, часто требует специальных флагов для доступа к расширенным логам.
- **RAID-контроллеры:** требуют явного указания типа устройства (например, `-d megaraid,0`) для «проброса» команд к физическому диску.

Подробный разбор атрибутов и протоколов см. в [Определениях и концепциях S.M.A.R.T.](./smart_concepts.md).

## Практические сценарии

### Быстрый старт: основные команды

Для большинства задач достаточно следующего набора команд:

```bash
# Показать список всех поддерживаемых устройств
sudo smartctl --scan

# Вывод всей доступной информации (атрибуты, логи, статус здоровья)
sudo smartctl -a /dev/sda

# Только общая оценка здоровья (быстрый вердикт)
sudo smartctl -H /dev/sda
# → result: PASSED (здоров) или FAILED (неисправен)

# Просмотр параметров NVMe-диска (включая износ и температуру)
sudo smartctl -a /dev/nvme0n1
```

### Алгоритм диагностики

1. **Верификация устройства:** Определение имени диска и проверка поддержки S.M.A.R.T. через `sudo smartctl -i /dev/sdX`.
2. **Анализ критических атрибутов:** Поиск переназначенных секторов (`Reallocated_Sector_Ct`) и ошибок интерфейса.
3. **Запуск самодиагностики:** Выполнение внутренних тестов диска (`short` или `long`) для выявления скрытых дефектов.

Детальные инструкции по выполнению этих шагов приведены в руководстве [Проверка здоровья дисков](./disk_health_check.md).

### Продвинутые возможности

Для автоматизации и работы в современных окружениях:

- **JSON-вывод:** Начиная с версии 7.0, доступен флаг `--json`, позволяющий парсить результаты скриптами.
- **Интеграция с NVMe-CLI:** Если данных `smartctl` недостаточно, используйте `nvme smart-log`.

### Решение проблем

При возникновении ошибок чтения атрибутов, проблем с определением диска за RAID-контроллером или интерпретации специфических логов, обращайтесь к разделу [Диагностика проблем](./troubleshooting.md).

## Дополнительная информация

### Надёжность диагностики

S.M.A.R.T. способен предсказать до 60-70% аппаратных отказов, связанных с постепенной деградацией (износ механики или ячеек памяти). Однако внезапные поломки электроники или контроллера часто не отражаются в атрибутах заранее.

**Золотое правило:** Мониторинг является средством раннего предупреждения, но не заменяет регулярное резервное копирование.
