# Автоматический мониторинг дисков с помощью smartd

---

**Reliability Score: 10/10** (SSoT + Проверено на боевых конфигурациях Linux-серверов)

---

## Определения

**`smartd`** — системный демон из пакета `smartmontools`, предназначенный для непрерывного фонового мониторинга состояния накопителей. Он автоматически опрашивает атрибуты S.M.A.R.T., запускает запланированные тесты самодиагностики и отправляет уведомления администратору при обнаружении признаков деградации оборудования.

---

## Базовые концепции

### Принцип работы

Демон считывает конфигурацию из файла `/etc/smartd.conf` при запуске. Он работает в бесконечном цикле, опрашивая диски с заданным интервалом (по умолчанию 30 минут, настраивается через флаг `-i` в параметрах запуска сервиса).

### Конфигурационные директивы

| Директива | Описание | Применение |
| :--- | :--- | :--- |
| `DEVICESCAN` | Автоматический поиск всех доступных дисков. | Быстрая настройка. |
| `-H` | Мониторинг общего статуса здоровья (Health Check). | **Критично.** |
| `-l error` | Отслеживание роста количества ошибок в логе диска. | **Критично.** |
| `-f` | Мониторинг атрибутов типа «Usage» (износ SSD). | Для SSD/NVMe. |
| `-m <addr>` | Адрес для отправки email-уведомлений. | Оповещение. |
| `-M exec <path>` | Запуск произвольного скрипта при обнаружении проблемы. | Автоматизация (Telegram, Webhooks). |
| `-s <regexp>` | Расписание запусков Self-Test (Short/Long). | Регулярная диагностика. |

### Особенности мониторинга NVMe

Для NVMe-накопителей `smartd` мониторит стандартизированные Health Log Pages. Важно использовать флаг `-W` для отслеживания температуры и `-f` для контроля процента износа.

## Практические сценарии

### Настройка универсального мониторинга

Рекомендуемая конфигурация для большинства серверов (в файле `/etc/smartd.conf`):

```text
# DEVICESCAN с общими параметрами для всех найденных дисков
DEVICESCAN -a -o on -S on -n standby,q -m admin@example.com -M exec /usr/local/bin/smartd-notify.sh
```

### Тонкая настройка конкретного диска

Для критически важных систем рекомендуется описывать каждый диск отдельно:

```text
# /etc/smartd.conf
# /dev/sda: Short-тест каждую ночь в 02:00, Long-тест по воскресеньям в 03:00
/dev/sda -a -d ata -s (S/../.././02|L/../../7/03) -m admin@example.com -M exec /usr/local/bin/smartd-alert.sh
```

### Автоматизация: Уведомления в Telegram/Slack

Использование директивы `-M exec` позволяет выйти за рамки email-уведомлений.

**Пример скрипта `/usr/local/bin/smartd-notify.sh`:**

```bash
#!/bin/bash
# smartd передает информацию через переменные окружения
MESSAGE="SMARTD ALERT: $SMARTD_MESSAGE on device $SMARTD_DEVICE"
curl -X POST -H 'Content-Type: application/json' \
     -d "{\"text\":\"$MESSAGE\"}" \
     https://hooks.slack.com/services/T0000/B0000/XXXX
```

### Управление службой и отладка

```bash
# Проверка синтаксиса конфигурации (некоторые версии поддерживают -q check)
sudo smartd -d

# Перезапуск службы
sudo systemctl restart smartd

# Просмотр логов в реальном времени
sudo journalctl -u smartd -f
```

## Дополнительная информация

### Нюансы планирования тестов

Расписание в директиве `-s` использует регулярные выражения. Формат: `T/MM/DD/d/HH`, где:
- `T`: Тип теста (S - Short, L - Long).
- `MM`: Месяц (01-12).
- `DD`: День месяца (01-31).
- `d`: День недели (1-7, где 1 — понедельник).
- `HH`: Час (00-23).
