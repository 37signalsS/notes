# Автоматический мониторинг дисков (smartd)

## Определения

**`smartd`** — системный демон из пакета `smartmontools`, предназначенный для непрерывного фонового мониторинга состояния накопителей. Он автоматически опрашивает атрибуты S.M.A.R.T., запускает запланированные тесты самодиагностики и отправляет уведомления администратору при обнаружении признаков деградации оборудования.

---

## Базовые концепции

### Конфигурационный файл

Основная настройка демона выполняется в файле `/etc/smartd.conf`. По умолчанию в большинстве дистрибутивов включена директива `DEVICESCAN`, которая заставляет демон автоматически обнаруживать и мониторить все доступные накопители.

### Параметры мониторинга (директивы)

В конфигурации используются флаги, определяющие глубину проверки каждого устройства:

| Директива | Описание |
|-----------|----------|
| `-H` | Проверка общего статуса здоровья (Health status). |
| `-f` | Мониторинг атрибутов типа «Usage» (износ). |
| `-t` | Отслеживание изменений во всех атрибутах. |
| `-l error` | Мониторинг журнала ошибок контроллера. |
| `-l selftest` | Мониторинг результатов тестов самодиагностики. |
| `-C ID` | Уведомление при появлении Pending Sectors (для HDD). |
| `-m addr` | Адрес электронной почты для отправки уведомлений. |
| `-M test` | Отправка тестового письма при каждом запуске демона (для проверки почты). |

## Практические сценарии

### Настройка уведомлений

Пример конфигурации для мониторинга всех дисков с отправкой уведомлений только при изменении статуса:

```text
# /etc/smartd.conf
DEVICESCAN -a -m admin@example.com -M onchange
```

Пример для конкретного NVMe-накопителя с ежедневным отчетом:

```text
/dev/nvme0n1 -H -a -m admin@example.com -M daily
```

### Управление службой

```bash
# Включение автозапуска и немедленный старт
sudo systemctl enable --now smartd

# Перезагрузка после изменения конфигурации
sudo systemctl restart smartd

# Просмотр последних событий мониторинга
journalctl -u smartd -n 50
```

### Проверка системы оповещений

Чтобы убедиться, что почтовые уведомления работают корректно, добавьте временную директиву `-M test` в `/etc/smartd.conf` и перезапустите службу. Демон отправит сообщение при старте.

```bash
# Пример строки для теста
/dev/sda -m admin@example.com -M test
```

## Дополнительная информация

### Надежность мониторинга

`smartd` является критически важным компонентом для серверных систем, так как позволяет обнаружить проблему до того, как она приведет к отказу файловой системы. Однако следует помнить, что не все типы отказов (например, внезапная поломка электроники) могут быть предсказаны заранее.
