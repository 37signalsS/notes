# Определения и концепции S.M.A.R.T.

## Определения

**S.M.A.R.T. (Self-Monitoring, Analysis, and Reporting Technology)** — встроенная в накопители система самодиагностики, предназначенная для мониторинга физического состояния устройства и прогнозирования аппаратных сбоев.

**Атрибут S.M.A.R.T.** — отдельный количественный показатель состояния (например, количество циклов включения, температура, счетчик переназначенных секторов).

**NVMe Health Log** — современный стандарт мониторинга для протокола NVMe (версии 1.x–2.4+), заменяющий вендор-специфичные атрибуты ATA на жестко стандартизированный набор критических предупреждений и счетчиков износа.

**SCSI Log Pages** — механизм отчетности для SAS-накопителей, использующий страницы логов (например, Page 03h для ошибок чтения) вместо классических ID атрибутов.

## Базовые концепции

### Типы накопителей и протоколы мониторинга

Логика самодиагностики зависит от интерфейса подключения и архитектуры контроллера:

| Тип накопителя | Протокол | Ключевая особенность |
| :--- | :--- | :--- |
| **HDD (SATA)** | ATA/ATAPI | Большое количество атрибутов, описывающих механику (шпиндель, позиционирование головок). |
| **SATA SSD** | ATA/ATAPI | Фокус на износе ячеек NAND и управлении резервными блоками. |
| **NVMe SSD** | NVMe 2.0+ | Стандартизированный набор параметров. В версиях 2.1–2.4 добавлены метрики вольтажа и PQC (Post-Quantum Cryptography). |
| **SAS HDD/SSD** | SCSI (SPC-7) | Счетчики ошибок чтения/записи/верификации. Использование Sense Data для расшифровки ошибок. |
| **NVMe ZNS** | ZNS Command Set | Специфичная диагностика зон (Zoned Namespaces): количество сбросов, активных зон и ошибок Zone Append. |

### Ключевые показатели для анализа

#### Жесткие диски (HDD)

| Атрибут | ID | Описание | Критичность |
| :--- | :--- | :--- | :--- |
| `Reallocated_Sector_Ct` | 5 | Количество секторов, перенесенных в резервную область. Свидетельствует о дефектах поверхности. | **Высокая** |
| `Current_Pending_Sector` | 197 | Нестабильные секторы, ожидающие переназначения. Прямой признак физического повреждения. | **Высокая** |
| `UDMA_CRC_Error_Count` | 199 | Ошибки передачи данных по шине. Обычно вызваны плохим кабелем или контактом. | **Средняя** |
| `Spin_Retry_Count` | 10 | Ошибки раскрутки шпинделя. Признак износа мотора или подшипника. | **Высокая** |

#### Твердотельные накопители (SSD/NVMe)

| Параметр | Описание | Критичность |
| :--- | :--- | :--- |
| `Percentage Used` | Износ в процентах от гарантированного ресурса (Endurance). При 100% диск может перейти в Read-only. | **Высокая** |
| `Critical Warning` | Битовая маска (0x01 — перегрев, 0x02 — отказ контроллера, 0x08 — режим только чтение). | **Критическая** |
| `Media and Data Integrity Errors` | Количество обнаруженных некорректируемых ошибок данных. Признак деградации NAND. | **Критическая** |
| `Available Spare` | Оставшееся резервное пространство для замены дефектных ячеек. | **Высокая** |

### Интерпретация значений ATA (SATA)

Для дисков SATA важно различать три типа значений:
1.  **VALUE (Current):** Текущий «запас прочности» (обычно от 100 до 1). Снижается при ухудшении параметра.
2.  **THRESH (Threshold):** Нижний порог, установленный производителем. Если `VALUE < THRESH`, диск считается неисправным.
3.  **RAW_VALUE:** Реальные данные (например, точное количество секторов или температура в градусах).

## Практические сценарии

### Алгоритм оценки необходимости замены

| Сценарий | Признаки | Действие |
| :--- | :--- | :--- |
| **Критический сбой** | `Critical Warning != 0` или `VALUE < THRESH`. | Немедленное резервное копирование и замена. |
| **Активная деградация** | Постоянный (даже медленный) рост переназначенных секторов. | Плановая замена. Диск более не надежен. |
| **Износ SSD** | `Percentage Used` приближается к 100%. | Мониторинг задержек (Latency) и плановая замена. |
| **Ошибки интерфейса** | Рост `UDMA_CRC_Error_Count` при стабильных остальных параметрах. | Замена кабеля/шлейфа или переподключение в другой порт. |

### Особенности SAS и ZNS

- **SAS (SCSI):** Вместо классических атрибутов анализируйте страницы логов через `smartctl -l error`. Особое внимание на `Growth Defect List`.
- **NVMe ZNS:** Используйте `smartctl -l zoned` для проверки специфичных счетчиков зон. Высокое количество сбросов зон может указывать на неэффективную работу приложения с диском.

## Дополнительная информация

### Ограничения и точность

S.M.A.R.T. является системой прогнозирования, а не абсолютной гарантией:
1.  **Внезапные отказы:** До 40% дисков выходят из строя внезапно (электроника, прошивка) без предварительного изменения атрибутов.
2.  **Вендор-специфичность:** В SATA-дисках ID атрибутов могут различаться. Всегда проверяйте базу данных `smartd-drivedb`.
3.  **Виртуализация:** В облачных средах и при использовании некоторых RAID-контроллеров физические атрибуты могут быть скрыты гипервизором.
