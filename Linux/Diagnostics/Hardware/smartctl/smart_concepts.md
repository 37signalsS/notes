# Определения и концепции S.M.A.R.T.

## Определения

**S.M.A.R.T. (Self-Monitoring, Analysis, and Reporting Technology)** — встроенная в накопители система самодиагностики, предназначенная для мониторинга физического состояния устройства и прогнозирования аппаратных сбоев.

**Атрибут S.M.A.R.T.** — отдельный количественный показатель состояния (например, количество циклов включения, температура, счетчик переназначенных секторов).

**Самотестирование (Self-test)** — фоновая процедура, выполняемая контроллером накопителя для проверки целостности ячеек памяти (SSD/NVMe) или поверхности пластин (HDD). SMART поддерживает короткие (`short`) и расширенные (`long`) тесты.

**Порог S.M.A.R.T. (Threshold)** — нижнее граничное значение для атрибута, установленное производителем. При достижении текущего значения порога диск генерирует событие, улавливаемое `smartd`.

**Офлайн-сбор данных (Offline Data Collection)** — фоновый процесс, при котором диск выполняет проверки во время простоя (если активирована директива `-o on` в `smartctl`). Результаты сохраняются в атрибуты без прерывания работы.

**Автосохранение (Auto-save)** — механизм (`-S on`), при котором SMART-атрибуты автоматически сохраняются в энергонезависимую память накопителя через заданный интервал.

**NVMe Health Log** — современный стандарт мониторинга для протокола NVMe (версии 1.x–2.4+), заменяющий вендор-специфичные атрибуты ATA на жестко стандартизированный набор критических предупреждений и счетчиков износа.

**SCSI Log Pages** — механизм отчетности для SAS-накопителей, использующий страницы логов (например, Page 03h для ошибок чтения) вместо классических ID атрибутов.

## Базовые концепции

### Типы накопителей и протоколы мониторинга

Логика самодиагностики зависит от интерфейса подключения и архитектуры контроллера:

| Тип накопителя | Протокол | Ключевая особенность |
| :--- | :--- | :--- |
| **HDD (SATA)** | ATA/ATAPI | Большое количество атрибутов, описывающих механику (шпиндель, позиционирование головок). |
| **SATA SSD** | ATA/ATAPI | Фокус на износе ячеек NAND и управлении резервными блоками. |
| **NVMe SSD** | NVMe 2.0+ | Стандартизированный набор параметров. В версиях 2.1–2.4 добавлены метрики вольтажа и PQC (Post-Quantum Cryptography). |
| **SAS HDD/SSD** | SCSI (SPC-7) | Счетчики ошибок чтения/записи/верификации. Использование Sense Data для расшифровки ошибок. |
| **NVMe ZNS** | ZNS Command Set | Специфичная диагностика зон (Zoned Namespaces): количество сбросов, активных зон и ошибок Zone Append. |

### Архитектура S.M.A.R.T. в ATA/SATA

Для SATA-накопителей SMART реализован через набор атрибутов, каждый из которых описывается записью фиксированной структуры.

#### Структура записи атрибута

| Поле | Описание |
| :--- | :--- |
| **ID** | Уникальный числовой идентификатор (1–255). |
| **NAME** | Символьное имя (например, `Reallocated_Sector_Ct`). |
| **FLAG** | 16-битная маска, определяющая поведение атрибута (Pre-Fail, Old-Age, Online). |
| **VALUE** | Нормализованный текущий запас (обычно 1–253). 100 = новый диск, 1 = критический износ. |
| **WORST** | Худшее зафиксированное нормализованное значение. |
| **THRESH** | Нижний порог производителя. Если `VALUE < THRESH`, диск считается неисправным. |
| **TYPE** | Категория: `Pre-fail` (критичный) или `Old-age` (износ). |
| **UPDATED** | Как обновляется: `Always` (в реальном времени) или `Offline` (при запуске офлайн-сбора). |
| **WHEN_FAILED** | `-` если `VALUE >= THRESH`; иначе содержит дату последнего превышения порога. |
| **RAW_VALUE** | Необработанные данные сенсора (например, точное количество переназначенных секторов). |

#### Флаги атрибутов

| Флаг | Значение |
| :--- | :--- |
| **Pre-Fail** | Атрибут критичен для прогнозирования отказа. Снижение `VALUE` ниже `THRESH` означает высокую вероятность сбоя. |
| **Old-Age** | Атрибут отслеживает износ от нормальной эксплуатации. Важен для планирования замены, но не означает немедленного отказа. |
| **Online** | Атрибут обновляется во время обычных операций ввода-вывода. |
| **Offline** | Атрибут обновляется только во время офлайн-сбора (требует `-o on`). |

#### Механизм автономного сбора и автосохранения

- **`-o on` (Offline data collection):** Активирует фоновую проверку поверхности/ячеек во время простоя диска. Результаты записываются в атрибуты типа `Offline`.
- **`-S on` (Auto-save):** Автоматически сохраняет SMART-атрибуты в энергонезависимую память накопителя. Без этого флага атрибуты сбрасываются при обесточивании.

#### Механизм порогов и событий

Каждый атрибут имеет порог `THRESH`, установленный производителем. При снижении `VALUE` ниже `THRESH`:
1. Диск возвращает статус `FAILED` на запрос `smartctl -H`.
2. `smartd` (при настроенном мониторинге) генерирует событие и выполняет указанные действия (`-m`, `-M exec`).

### NVMe Health Log Page — структура

Для NVMe-накопителей SMART-статус отображается через стандартизированный `Health Log Page` (LSP 0x02), что устраняет вендор-специфичность ATA-атрибутов.

#### Ключевые поля Health Log Page

| Поле | Описание | Диапазон |
| :--- | :--- | :--- |
| **Critical Warning** | Битовая маска критических предупреждений. | 0x00 = OK, 0x01 = перегрев, 0x02 = отказ контроллера, 0x08 = только чтение |
| **Percentage Used** | Процент израсходованного гарантированного ресурса (TBW). | 0–255 (255 = 100% износа) |
| **Temperature** | Текущая температура в Кельвинах. | — |
| **Available Spare** | Процент оставшегося резервного пространства для замены дефектных ячеек. | 0–100% |
| **Available Spare Threshold** | Порог, при достижении которого генерируется критическое предупреждение. | Производитель-зависимый |
| **Data Units Read/Written** | Объем прочитанных/записанных данных (в 512-байтовых блоках). | — |
| **Host Read/Write Commands** | Количество команд чтения/записи от хоста. | — |
| **Controller Busy Time** | Время, в течение которого контроллер был занят операциями. | — |
| **Power Cycles** | Количество циклов включения/выключения. | — |
| **Unsafe Shutdowns** | Количество аварийных отключений питания. | — |

#### Ограничения `smartctl` для NVMe

`smartctl` предоставляет подмножество данных Health Log Page. Для полной диагностики используйте `nvme-cli` (v2.x+), который даст доступ к:
- **Persistent Event Log** (NVMe 1.4+): хронология критических событий (temperature throttling, firmware commits).
- **Error Log:** детальные коды ошибок (SC, SCT, CDW1).
- **Telemetry Log:** данные для отправки вендору.
- **Identify Controller/Namespace:** детали версии прошивки, размера блоков, поддерживаемых функций.

### SCSI Log Pages для SAS

Вместо классических атрибутов ATA, SAS-накопители используют страницы логов (Log Pages), определенные в SPC-4/SPC-7.

#### Критически важные страницы

| Page | Назначение | Ключевые данные |
| :--- | :--- | :--- |
| **0x03h** | Error counters | Счетчики ошибок чтения/записи/верификации. |
| **0x02h** | Temperature | Текущая и максимальная температура. |
| **0x0Ah** | Self-test results | Результаты предыдущих самотестов. |
| **0x1Dh** | Background scan results | Результаты фонового сканирования поверхности. |

#### Sense Data

При ошибках SAS возвращает коды Sense (ASC/ASCQ), которые позволяют точно определить причину сбоя:
- `Medium Error` — физический дефект носителя.
- `Hardware Error` — сбой контроллера или электроники.
- `Aborted Command` — прерывание команды (часто из-за таймаута).

### Механика самотестирования

Самотестирование выполняется firmware контроллера и не зависит от ОС.

#### Типы тестов

| Тип | Описание | Влияние на производительность |
| :--- | :--- | :--- |
| **Short** | Быстрая проверка основных узлов (электроника, контроллер, начальные блоки). | Минимальное (2–5 мин). |
| **Long** | Полное сканирование поверхности/ячеек. Для HDD проверяет все секторы; для SSD/NVMe — износ NAND. | Заметное (1–20 ч), может снижать IOPS. |
| **Conveyor** | Тестирование в режиме конвейера (поддерживается не всеми дисками). | Среднее. |

#### Captive vs Non-Captive

- **Non-Captive (по умолчанию):** Тест выполняется в фоне параллельно с обычными операциями. Доступ к диску сохраняется, но latency может увеличиваться.
- **Captive (`-C`):** Тест захватывает диск исключительно для диагностики. Данные недоступны для чтения/записи до завершения теста. Используется для глубокой диагностики при подозрении на скрытые дефекты.

#### Offline Data Collection и самотестирование

При активации `-o on`, диск периодически выполняет офлайн-сбор данных, который:
- Обновляет атрибуты типа `Offline` (например, `Reallocated_Sector_Ct` может обновиться только после офлайн-сбора).
- Выполняется в приоритетах ниже, чем пользовательский I/O, поэтому не прерывает работу.
- Может быть запущен вручную через `smartctl -t offline /dev/sdX`.

### Архитектура `smartd`

Демон `smartd` работает в модели опроса (polling) с реакцией на события.

#### Жизненный цикл

1. **Инициализация:** При старте systemd-службы `smartd` читает `/etc/smartd.conf` и выполняет сканирование устройств (`DEVICESCAN` или явный список).
2. **Опрос:** С заданным интервалом (по умолчанию 1800 секунд / 30 минут, настраивается флагом `-i`) демон считывает атрибуты здоровья всех указанных устройств.
3. **Анализ:** Изменения атрибутов, провалы тестов или статус `FAILED`/`FAILURE IS IMMINENT` триггерят события.
4. **Реакция:** Выполняются действия из конфигурации: отправка email (`-m`), запуск скрипта (`-M exec`) или логирование.

#### Важно для SRE

`smartd` реагирует на события быстрее, чем система скрейпинга Prometheus, так как работает по pull-модели на уровне хоста. Однако для исторических трендов и корреляции с другими метриками (CPU, память, сеть) необходима интеграция с внешними системами мониторинга.

## Ключевые показатели для анализа

### Жесткие диски (HDD)

| Атрибут | ID | Описание | Критичность |
| :--- | :--- | :--- | :--- |
| `Reallocated_Sector_Ct` | 5 | Количество секторов, перенесенных в резервную область. Свидетельствует о дефектах поверхности. | **Высокая** |
| `Current_Pending_Sector` | 197 | Нестабильные секторы, ожидающие переназначения. Прямой признак физического повреждения. | **Высокая** |
| `UDMA_CRC_Error_Count` | 199 | Ошибки передачи данных по шине. Обычно вызваны плохим кабелем или контактом. | **Средняя** |
| `Spin_Retry_Count` | 10 | Ошибки раскрутки шпинделя. Признак износа мотора или подшипника. | **Высокая** |

### Твердотельные накопители (SSD/NVMe)

| Параметр | Описание | Критичность |
| :--- | :--- | :--- |
| `Percentage Used` | Износ в процентах от гарантированного ресурса (Endurance). При 100% диск может перейти в Read-only. | **Высокая** |
| `Critical Warning` | Битовая маска (0x01 — перегрев, 0x02 — отказ контроллера, 0x08 — режим только чтение). | **Критическая** |
| `Media and Data Integrity Errors` | Количество обнаруженных некорректируемых ошибок данных. Признак деградации NAND. | **Критическая** |
| `Available Spare` | Оставшееся резервное пространство для замены дефектных ячеек. | **Высокая** |

### Эквиваленция параметров по протоколам

Одна и та же физическая характеристика может называться по-разному в зависимости от протокола:

| Концепт | ATA/SATA | NVMe | SAS |
| :--- | :--- | :--- | :--- |
| **Износ ресурса** | `Media_Wearout_Indicator` | `Percentage Used` | `Wear_Leveling_Count` (через Log Pages) |
| **Температура** | `Temperature_Celsius` (ID 194) | `Temperature` (Health Log) | Page 02h |
| **Ошибки чтения** | `Read_Error_Rate` | `Media and Data Integrity Errors` | Page 03h |
| **Ошибки записи** | `Write_Error_Rate` | `Write Errors` | Page 03h |
| **Переназначенные сектора** | `Reallocated_Sector_Ct` (ID 5) | `Data Units Written` + `Critical Warning` | `Growth Defect List` |

### Интерпретация значений ATA (SATA)

Для дисков SATA важно различать три типа значений:
1.  **VALUE (Current):** Текущий «запас прочности» (обычно от 100 до 1). Снижается при ухудшении параметра.
2.  **THRESH (Threshold):** Нижний порог, установленный производителем. Если `VALUE < THRESH`, диск считается неисправным.
3.  **RAW_VALUE:** Реальные данные (например, точное количество секторов или температура в градусах).

## Практические сценарии

### Методология интерпретации атрибутов

Анализ S.M.A.R.T. — это не проверка абсолютных значений, а отслеживание **динамики**. SRE должен следовать следующей концептуальной модели:

1.  **Базовый снимок (Baseline):** При вводе диска в эксплуатацию запишите текущие значения ключевых атрибутов. Это позволит отличить старения от внезапных скачков.
2.  **Мониторинг трендов:** Ежедневный рост `Reallocated_Sector_Ct` даже на 1–2 сектора — сигнал плановой замены. Резкий скачок (например, с 0 до 50 за час) указывает на катастрофическую деградацию поверхности.
3.  **Корреляция типов:** Если растут одновременно `Reallocated_Sector_Ct` и `UDMA_CRC_Error_Count`, проблема, скорее всего, в кабеле/порте, а не в самих ячейках. Если растут только `Reallocated_Sector_Ct` — деградирует сам носитель.
4.  **Критический масс:** Для SSD/NVMe одновременное падение `Available Spare` и рост `Critical Warning` требуют немедленной замены, даже если `Percentage Used` еще не достиг 100%.

### Алгоритм оценки необходимости замены

| Сценарий | Признаки | Действие |
| :--- | :--- | :--- |
| **Критический сбой** | `Critical Warning != 0` или `VALUE < THRESH`. | Немедленное резервное копирование и замена. |
| **Активная деградация** | Постоянный (даже медленный) рост переназначенных секторов. | Плановая замена. Диск более не надежен. |
| **Износ SSD** | `Percentage Used` приближается к 100%. | Мониторинг задержек (Latency) и плановая замена. |
| **Ошибки интерфейса** | Рост `UDMA_CRC_Error_Count` при стабильных остальных параметрах. | Замена кабеля/шлейфа или переподключение в другой порт. |

### Особенности SAS и ZNS

- **SAS (SCSI):** Вместо классических атрибутов анализируйте страницы логов через `smartctl -l error`. Особое внимание на `Growth Defect List`.
- **NVMe ZNS:** Используйте `smartctl -l zoned` для проверки специфичных счетчиков зон. Высокое количество сбросов зон может указывать на неэффективную работу приложения с диском.

### Выбор инструмента: smartctl vs nvme-cli

| Задача | Рекомендуемый инструмент |
| :--- | :--- |
| Общий статус здоровья (PASSED/FAILED) | `smartctl -H` |
| Просмотр атрибутов SATA/SAS | `smartctl -A` |
| Запуск самотестов SATA | `smartctl -t short/long` |
| JSON-автоматизация и скрипты | `smartctl --json` |
| Persistent Event Log (NVMe 1.4+) | `nvme persistent-event-log` |
| Телеметрия для вендора | `nvme telemetry-log` |
| Детальный Error Log (SC, SCT) | `nvme error-log` |
| Управление namespace и firmware | `nvme` |

## Дополнительная информация

### Ограничения и точность

S.M.A.R.T. является системой прогнозирования, а не абсолютной гарантией:
1.  **Внезапные отказы:** До 40% дисков выходят из строя внезапно (электроника, прошивка) без предварительного изменения атрибутов.
2.  **Вендор-специфичность:** В SATA-дисках ID атрибутов могут различаться. Всегда проверяйте базу данных `smartd-drivedb`.
3.  **Виртуализация:** При использовании некоторых RAID-контроллеров физические атрибуты могут быть скрыты.

### Вендор-специфичные особенности

Производители по-разному реализуют атрибуты и пороги:
- **Seagate:** Использует расширенные атрибуты для SSD (например, `End-to-End_Error`). Обновите `smartd-drivedb` после каждого выпуска новых моделей.
- **Western Digital:** Для некоторых линеек WD Red скрывает `Reallocated_Sector_Ct` до порогового значения; рост `Current_Pending_Sector` становится первым признаком.
- **Samsung:** В NVMe SSD критически важен атрибут `Percentage Used`, но `Available Spare` может показывать 100% даже при 90% износе из-за агрессивной перераспределительной политики.
- **Intel:** В SATA SSD атрибут `Media_Wearout_Indicator` инвертирован: снижение от 100 к 0 означает нормальный износ, а не рост надежности.

### Стратегия мониторинга парка оборудования

Для SRE, управляющего парком из 100+ дисков, рекомендована следующая концептуальная стратегия:
1.  **Уровни алертов:**
    - **Warning:** `Percentage Used > 80%`, `Available Spare < 20%`, рост `Reallocated_Sector_Ct`.
    - **Critical:** `Critical Warning != 0`, `VALUE < THRESH`, `Completed: read failure` в selftest.
2.  **Частота опроса:** Для SSD/NVMe достаточно ежедневного опроса `smartd`. Для HDD в критичных системах — каждые 6 часов из-за скорости деградации механики.
3.  **Планирование замены:** Заменяйте диски на Warning-уровне в течение 30 дней. На Critical-уровне — немедленно.
4.  **База данных моделей:** Поддерживайте `smartd-drivedb` в актуальном состоянии через cron:
    ```bash
    0 3 * * 0 root /usr/sbin/update-smart-drivedb
    ```
