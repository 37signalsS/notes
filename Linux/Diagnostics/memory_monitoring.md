# Мониторинг памяти

## `free`: Сводная информация об использовании памяти

Команда `free` предоставляет краткую информацию о занятой и свободной физической и swap-памяти.

**Полезные опции:**
```sh
free -h # Человекочитаемый формат (G, M, K)
free -m # В мегабайтах
```

**Расшифровка вывода `free`:**

| Поле       | Значение | Что означает                                                                 |
|------------|----------|-----------------------------------------------------------------------------|
| **total**  | 7.7G     | Вся оперативная память в системе, после того, как ядро зарезервировало часть для своих нужд.                                           |
| **used**   | 3.2G     | Память, занятая процессами (но не вся реально используется, total - free - buff/cache).      |
| **free**   | 843M     | Полностью свободная память (не используется ни для чего).                   |
| **shared** | 123M     | Память, разделяемая между процессами (например, shared libraries, IPC).     |
| **buff/cache** | 3.7G | Память, занятая кэшем и буферами (может быть освобождена при необходимости).|
| **available** | 2.9G | Реальная физическая память, которую система может выделить новым процессам без запуска механизма подкачки (swapping). Это наиболее точный показатель свободной памяти для приложений.(≈ free + часть buff/cache).  |

### Почему Linux активно использует память для кэширования?

Linux активно использует свободную оперативную память для кэширования дисковых операций. Когда процесс читает данные с диска, эти данные попадают в страничный кэш (page cache) в RAM. Даже после завершения процесса, который инициировал чтение, эти данные могут оставаться в кэше.

Это сделано намеренно для повышения производительности: операции доступа к диску значительно медленнее, чем доступ к RAM. Если другому процессу понадобятся те же данные, ядро вернет их из кэша, а не будет снова читать с диска. Таким образом, "съеденная" под `buff/cache` память не является потерянной — ядро немедленно освободит ее, как только она понадобится какому-либо приложению.

*   **Итоговая свободная память** — это та память, которая ни нужна ни для кэша, ни для чего-то ещё.
*   Если в вашем дистрибутиве нет поля `available`, его примерное значение можно рассчитать как: `free + (~70% от buff/cache)`.

### Какие ситуации будут указывать на возможную проблему?

*   Значение `available` (или `free + buff/cache`) близко к нулю или очень мало.
*   В логах ядра появляются сообщения `Out-of-Memory Killer` (OOM Killer).
    ```bash
    dmesg -T | grep -i "out of memory"
    ```

## `/proc/meminfo`: Подробная статистика памяти

Файл `/proc/meminfo` предоставляет исчерпывающую статистику об использовании оперативной и swap-памяти. Рассмотрим ключевые параметры:

**Общая память:**
-   `MemTotal`: Общий объем физической RAM.
-   `MemFree`: Количество полностью свободной, неиспользуемой памяти. Это "сырой" показатель, который часто бывает низким, так как Linux стремится использовать свободную память для кэширования.
-   `MemAvailable`: **Наиболее важный показатель для оценки свободной памяти.** Это оценка того, сколько памяти доступно для запуска новых приложений без необходимости выгрузки данных в swap. Включает `MemFree` и часть кэша, которую можно безболезненно освободить.

**Кэш и буферы:**

-   `Buffers`: Память, используемая для временного хранения "сырых" дисковых блоков. Это кэш метаданных файловой системы.
-   `Cached`: Память, используемая для кэширования данных, прочитанных с диска (page cache). При повторном чтении файла данные будут взяты отсюда, а не с медленного диска.
-   `SwapCached`: Память, которая была выгружена в swap, а затем снова загружена в RAM, но все еще остается в swap-файле. Если понадобится, ее можно будет быстро выгрузить обратно, не записывая на диск заново.

**Активная и неактивная память:**

-   `Active`: Память, которая активно используется в данный момент.
-   `Inactive`: Память, которая использовалась, но сейчас неактивна. Является основным кандидатом на вытеснение (reclaiming) при нехватке памяти.
-   `Active(anon)` / `Inactive(anon)`: Анонимная память (не связанная с файлами), которая активно/неактивно используется. Это, как правило, память процессов (стек, куча).
-   `Active(file)` / `Inactive(file)`: Память, используемая для кэширования файлов, которая активно/неактивно используется.
-   `Unevictable`: Страницы памяти, которые нельзя выгрузить в swap (например, заблокированные с помощью `mlock()`).
-   `Mlocked`: Память, заблокированная процессом с помощью системного вызова `mlock()`. Гарантированно не будет выгружена в swap.

## Утилиты для мониторинга памяти

### vmstat

Утилита `vmstat` предоставляет информацию о процессах, памяти, подкачке, вводе-выводе, системных прерываниях и активности процессора.

-   **Режим обновления:** `vmstat 1` выводит статистику каждую секунду.

В контексте swap особенно важны два поля в её выводе:
-   **`si` (swap-in):** Объем памяти, загруженный из swap-раздела в RAM (в килобайтах в секунду). Постоянно высокое значение `si` свидетельствует о том, что системе не хватает оперативной памяти.
-   **`so` (swap-out):** Объем памяти, выгруженный из RAM в swap-раздел (в килобайтах в секунду). Высокое значение `so` говорит о том, что система активно освобождает RAM, перемещая неактивные страницы в swap.

---

### smem

Продвинутая утилита, которая корректно считает разделяемую память.

-   **Ключевые метрики:**
    -   **PSS (Proportional Set Size):** "Справедливая" доля разделяемой памяти плюс приватная память. Дает более реалистичную оценку.
    -   **USS (Unique Set Size):** Чисто приватная память процесса. Рост USS — явный кандидат на утечку.
-   **Примеры:**
    -   `smem -p`: По процессам.
    -   `smem -u`: По пользователям.

---

### pmap

`pmap` показывает подробную карту памяти процесса, позволяя увидеть, из каких сегментов (код, данные, библиотеки) состоит его адресное пространство и сколько реальной памяти (RSS) они занимают.

-   `pmap -x <PID>`: Показать расширенную информацию.

---

### `/proc/<PID>/smaps_rollup`

Для быстрой и точной оценки реального потребления памяти процессом, в обход неточностей `top`.
```bash
cat /proc/<PID>/smaps_rollup
```
-   **Ключевые поля:**
    -   `Rss`: Реальный объем физической памяти.
    -   `Private_Clean / Private_Dirty`: Память, принадлежащая только этому процессу. Рост этого показателя может указывать на утечки.
    -   `Shared_Clean / Shared_Dirty`: Память, разделяемая с другими процессами.
