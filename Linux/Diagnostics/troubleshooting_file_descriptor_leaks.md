# Локализация утечек файловых дескрипторов и блокировок

## Проблема и симптомы

Иногда утечки файловых дескрипторов или активные блокировки проявляются неочевидно. Процессы, которые использовали файлы, вроде бы уже завершились, но дескрипторы остаются открытыми, блокируя ресурсы. `lsof` при этом может не показывать проблему.

Типичные симптомы:
*   Зависание утилит резервного копирования (backup).
*   «Подвисание» баз данных, таких как SQLite или Postgres, без явных ошибок в логах.
*   Невозможность удалить или изменить файл, который, казалось бы, ничем не занят.

## Шаг 1: Прямая проверка через `/proc` (когда `lsof` не помогает)

Первый и самый надежный способ — посмотреть открытые дескрипторы напрямую в файловой системе `/proc`. Этот метод позволяет найти процесс, удерживающий ресурс, даже если `lsof` молчит.

```bash
ls -l /proc/*/fd | grep <имя_файла>
```

Вывод покажет `PID` процесса, в директории `fd` которого находится ссылка на искомый файл.

## Шаг 2: Проверка и анализ блокировок (`lslocks`)

Если файл не просто открыт, а заблокирован, утилита `lslocks` поможет это выяснить.

```bash
lslocks
```

Ключевые поля в выводе:
*   **`TYPE`**: Тип блокировки (`POSIX` или `FLOCK`).
*   **`MODE`**: Режим (`READ` или `WRITE`). `WRITE`-блокировка почти всегда является причиной «зависшей» операции.

Для наблюдения за блокировками в динамике, особенно под нагрузкой, используйте `watch`:
```bash
watch -n 1 lslocks
```

## Шаг 3: Идентификация процесса, держащего файл или блокировку

После получения `PID` (из `/proc` или `lslocks`), можно получить о нем детальную информацию:
```bash
ps -fp <PID>
```

Утилита `fuser` — еще один мощный инструмент для определения, какие процессы используют указанный файл.
```bash
fuser -vm <путь_к_файлу>
```
*   `-v`: Включает подробный режим.
*   `-m`: Указывает, что нужно искать процессы на смонтированной файловой системе, где находится файл.

## Шаг 4: Проверка системных лимитов

Иногда проблемы могут быть связаны не с конкретной блокировкой, а с достижением общесистемных лимитов на количество открытых файловых дескрипторов.

*   **Текущее состояние:**
    ```bash
    cat /proc/sys/fs/file-nr
    ```
    Вывод состоит из трех чисел:
    1.  `allocated file handles`: Количество выделенных файловых дескрипторов.
    2.  `allocated free file handles`: Количество свободных выделенных дескрипторов.
    3.  `maximum file handles`: Максимальное количество файловых дескрипторов.

*   **Максимальный лимит:**
    ```bash
    cat /proc/sys/fs/file-max
    ```
    Если первое число из `file-nr` близко к значению в `file-max`, это указывает на исчерпание лимита в системе.
