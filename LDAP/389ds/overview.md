# 389 Directory Server (389DS)

## Определения

**389DS** — enterprise-сервер каталогов (LDAPv3) с открытым исходным кодом, разрабатываемый Red Hat. Рекомендуется как **современная замена OpenLDAP**.

> **Актуальная версия:** 3.0+ (ноябрь 2025). Документация: [port389.org](https://www.port389.org/docs/389ds/)

**Ключевые преимущества перед OpenLDAP:**

* Стабильная работа и предсказуемое поведение
* Встроенная multi-master репликация
* CLI-утилиты (`dsconf`, `dsctl`) и веб-консоль
* Активная поддержка и развитие (в отличие от деприкейтед OpenLDAP в SLES 15+)

## Базовые концепции

### Архитектура

* **Бэкенд:** LMDB (по умолчанию), поддержка BerkeleyDB (устаревает)
* **Конфигурация:** `cn=config` (динамическая, без перезагрузки)
* **Схема:** Расширяемая, совместима с RFC 2307/4512
* **Плагины:** Модульная архитектура (аутентификация, репликация, аудит)

### Терминология

| Термин | Описание |
| :--- | :--- |
| **Suffix** | Корневой DN дерева (например, `dc=example,dc=com`) |
| **Backend** | База данных для хранения записей suffix |
| **Replica** | Копия базы на другом сервере |
| **Agreement** | Настройка репликации между серверами |
| **ACI** | Access Control Instructions (аналог ACL в OpenLDAP) |
| **DIT** | Directory Information Tree (иерархия записей) |

## Дополнительная информация

### Требования к ресурсам

#### Минимальные требования

| Ресурс | Значение | Примечание |
| :--- | :--- | :--- |
| **CPU** | 2 ядра | Для тестовых сред |
| **RAM** | 2 ГБ | Зависит от размера базы и нагрузки |
| **Диск** | 10 ГБ+ | SSD рекомендуется для B-дерева |

### Production-рекомендации

* **RAM:** 4–8 ГБ для кэширования (389DS активно использует кэш)
* **CPU:** 4+ ядра для высокой нагрузки
* **Диск:** NVMe SSD, отдельный том для `/data/db`
* **Сеть:** Выделенный VLAN для репликации

### Безопасность

#### Базовые меры

* **LDAPS (порт 3636)** или **StartTLS (порт 3389)** — обязательно в production
* **Firewall:** Ограничить доступ к портам (только доверенные IP)
* **Сертификаты:** Использовать доверенные CA (не self-signed в production)
* **Пароли:** Сложные пароли для Directory Manager и replication user
* **ACI:** Минимальные привилегии по умолчанию

### Дополнительные меры

* **Password Policy:** Требования к сложности, срок действия
* **Account Lockout:** Блокировка после неудачных попыток
* **Audit Logging:** Логирование изменений (плагин Audit Log)
* **Certificate Mapping:** Аутентификация по клиентским сертификатам
