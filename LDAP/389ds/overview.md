# Обзор 389 Directory Server (389DS)

## Определения

**389 Directory Server (389DS)** — современный, масштабируемый LDAP-сервер корпоративного уровня с открытым исходным кодом. Разрабатывается сообществом под эгидой Red Hat и является основой для Red Hat Directory Server и FreeIPA.

**LDAPv3** — основной протокол доступа к данным, полностью поддерживаемый 389DS.

**LMDB (Lightning Memory-Mapped Database)** — высокопроизводительный движок хранения данных, который стал стандартным и единственным бэкендом в версиях 3.x, полностью заменив устаревший BerkeleyDB (BDB).

## Базовые концепции

### Ключевые особенности версии 3.x

1.  **Полный переход на LMDB:** Начиная с версии 3.1.3, поддержка BerkeleyDB полностью удалена. LMDB обеспечивает более высокую производительность на чтение и упрощенное управление памятью.
2.  **Современное управление:** Использование утилит `dsconf` (конфигурация) и `dsctl` (управление инстансами) вместо прямого редактирования LDIF.
3.  **JSON-логирование:** Поддержка вывода логов аудита и ошибок в формате JSON для интеграции с современными системами мониторинга (ELK, Splunk, Grafana Loki).
4.  **Безопасность:** Поддержка современных алгоритмов хеширования паролей (например, `YESCRYPT`) и улучшенная интеграция с TLS.

### Архитектура и терминология

| Термин | Описание |
| :--- | :--- |
| **Instance (Экземпляр)** | Изолированный процесс LDAP-сервера со своей конфигурацией и БД. |
| **Suffix (Суффикс)** | Корневой DN дерева (например, `dc=example,dc=com`), определяющий область базы данных. |
| **Backend (Бэкенд)** | Реализация хранилища (в версиях 3.x — LMDB) для конкретного суффикса. |
| **Changelog** | База данных, в которой хранятся изменения для нужд репликации или аудита. |
| **ACI (Access Control Instructions)** | Механизм управления доступом, хранящийся в атрибутах самих записей. |

### Сравнение с OpenLDAP

| Характеристика | OpenLDAP | 389 Directory Server |
| :--- | :--- | :--- |
| **Конфигурация** | `cn=config` или текстовый файл | Динамическая через `cn=config` и `dsconf` |
| **Репликация** | Syncrepl (pull-модель) | Multi-master (push-модель), до 20+ мастеров |
| **Удобство** | Требует глубоких знаний LDIF | Удобные CLI-инструменты и Web UI (Cockpit) |
| **Масштабируемость** | Высокая, но сложная в настройке | Оптимизирована для миллионов записей "из коробки" |

## Практические сценарии

### Выбор метода развертывания

1.  **Docker/Podman:** Идеально для CI/CD, тестирования и микросервисной архитектуры. См. [Развертывание в Docker](./docker.md).
2.  **Bare-metal/VM:** Рекомендуется для крупных инсталляций, требующих максимальной производительности дисковой подсистемы и LMDB.
3.  **Kubernetes:** Развертывание через StatefulSets для облачных окружений. См. [Kubernetes Deploy](./k8s_deploy/k8s-administration.md).

### Типовые задачи администрирования

-   **Расширение функционала:** Включение и настройка [Плагинов](./plugins.md).
-   **Обеспечение отказоустойчивости:** Настройка [Репликации](./replication.md).

## Дополнительная информация

### Системные требования для версии 3.x

| Ресурс | Минимально | Рекомендуется (Production) |
| :--- | :--- | :--- |
| **CPU** | 2 ядра | 4+ ядра |
| **RAM** | 2 ГБ | 8 ГБ+ (LMDB активно использует кэш ОС) |
| **Диск** | 10 ГБ | SSD/NVMe (критично для LMDB) |

### Рекомендации по безопасности (Hardening)

-   **TLS:** Использование порта 636 (LDAPS) или StartTLS обязательно. Самоподписанные сертификаты допустимы только в песочницах.
-   **Политики паролей:** Настройка минимальной длины, сложности и блокировки учетных записей через Password Policy плагин.
-   **Ограничение доступа:** Анонимный доступ должен быть ограничен только Root DSE.
-   **Обновления:** Регулярное обновление до последних минорных версий для защиты от известных уязвимостей (например, CVE-2025-2487).
