# Архитектура систем Feature Toggles

### Определения

- **Архитектура Feature Toggles** — это набор компонентов и подходов, которые обеспечивают централизованное управление флагами, их доставку в приложение и принятие решений о включении/отключении функциональности.

### Основные концепции

#### 1. Ключевые компоненты

```
┌─────────────────────────────────────────────────────────────┐
│                    ПРИЛОЖЕНИЕ (APPLICATION)                 │
│                                                             │
│  ┌───────────┐      ┌───────────┐      ┌───────────┐        │
│  │ Проверка  │      │ Проверка  │      │ Проверка  │        │
│  │  флага A  │      │  флага B  │      │  флага C  │        │
│  └─────┬─────┘      └─────┬─────┘      └─────┬─────┘        │
│        └──────────────────┼──────────────────┘              │
│                           │                                 │
│                   ┌───────▼───────┐                         │
│                   │   Клиент/SDK    │                         │
│                   │ Feature Toggle  │                         │
│                   └───────┬───────┘                         │
└───────────────────────────┼─────────────────────────────────┘
                            │
           ┌────────────────┼────────────────┐
           │                │                │
┌──────────▼────────┐┌──────▼──────┐┌────────▼─────────┐
│ Файл конфигурации ││ База данных ││ Внешний сервис   │
│   (YAML/JSON)     ││ (Postgres,  ││ (LaunchDarkly,   │
│                   ││  MongoDB)   ││   Unleash)       │
└───────────────────┘└─────────────┘└──────────────────┘
```
- **Клиент/SDK:** Библиотека в коде приложения, которая запрашивает состояние флагов и принимает решение.
- **Хранилище конфигурации:** Источник правды о состоянии флагов.

#### 2. Способы хранения состояния флагов

1.  **Файлы конфигурации (для простых случаев):**
    - **Плюсы:** Простота, версионирование в Git.
    - **Минусы:** Требуется переразвертывание для изменения флага.
    ```yaml
    # features.yaml
    features:
      new-checkout: true
      dark-mode: false
    ```

2.  **База данных (для динамики):**
    - **Плюсы:** Флаги можно изменять "на лету" через UI.
    - **Минусы:** Требуется собственная разработка UI и API для управления.
    ```sql
    CREATE TABLE feature_flags (
        name VARCHAR(255) PRIMARY KEY,
        enabled BOOLEAN DEFAULT false,
        strategy VARCHAR(50)
    );
    ```

3.  **Специализированные сервисы (SaaS или Self-Hosted):**
    - **Плюсы:** Готовое решение с UI, SDK, аудитом, A/B-тестами и сложными правилами.
    - **Примеры:** LaunchDarkly, Unleash, Flagsmith.
