# Архитектура систем Feature Toggles

### Определения

**Архитектура Feature Toggles** — набор компонентов и подходов для централизованного управления флагами, доставки конфигурации в приложение и принятия решений о включении/отключении функциональности.

---

## Basic Concepts

### Ключевые компоненты

```
┌─────────────────────────────────────────────────────────────┐
│                    ПРИЛОЖЕНИЕ (APPLICATION)                 │
│                                                             │
│  ┌───────────┐      ┌───────────┐      ┌───────────┐        │
│  │ Проверка  │      │ Проверка  │      │ Проверка  │        │
│  │  флага A  │      │  флага B  │      │  флага C  │        │
│  └─────┬─────┘      └─────┬─────┘      └─────┬─────┘        │
│        └──────────────────┼──────────────────┘              │
│                           │                                 │
│                   ┌───────▼───────┐                         │
│                   │   Клиент/SDK    │                         │
│                   │ Feature Toggle  │                         │
│                   └───────┬───────┘                         │
└───────────────────────────┼─────────────────────────────────┘
                            │
           ┌────────────────┼────────────────┐
           │                │                │
┌──────────▼────────┐┌──────▼──────┐┌────────▼─────────┐
│ Файл конфигурации ││ База данных ││ Внешний сервис   │
│   (YAML/JSON)     ││ (Postgres,  ││ (LaunchDarkly,   │
│                   ││  MongoDB)   ││   Unleash)       │
└───────────────────┘└─────────────┘└──────────────────┘
```

**Клиент/SDK** — библиотека в коде приложения, точка входа для проверки флагов:

| Функция | Описание |
| :--- | :--- |
| Запрос конфигурации | Получение состояния флагов из хранилища |
| Кэширование | Локальное хранение для производительности |
| Контекстные решения | Учет ID пользователя, сессии, региона |
| Safe fallback | Возврат значения по умолчанию при недоступности хранилища |

**Хранилище конфигурации** — централизованное хранилище состояния всех флагов.

---

### Сравнение подходов к хранению

| Подход | Плюсы | Минусы | Когда использовать |
| :--- | :--- | :--- | :--- |
| **Файлы конфигурации** (YAML/JSON) | Простота, версионирование в Git | Требует переразвертывания для изменения | Простые проекты, статичные флаги |
| **База данных** | Динамическое изменение через UI | Нужна своя разработка UI/API | Средняя сложность, внутреннее управление |
| **Специализированные сервисы** (LaunchDarkly, Unleash, Flagsmith) | Готовый UI, SDK, аудит, A/B-тесты, сложные правила | Зависимость от вендора, стоимость | Production, сложные сценарии, команда >5 человек |

## Practical Scenarios

### Сценарий 1: Файлы конфигурации

```yaml
# features.yaml
features:
  new-checkout:
    enabled: true
  dark-mode:
    enabled: false
  beta-feature:
    enabled: true
    strategy: percentage
    percentage: 10
```

**Процесс изменения:**
1. Изменить файл в Git
2. Создать pull request
3. После мержа — переразвертывание приложения

**Применимость:** Статичные флаги, редкие изменения, небольшие проекты.

---

### Сценарий 2: База данных

```sql
CREATE TABLE feature_flags (
    name VARCHAR(255) PRIMARY KEY,
    enabled BOOLEAN DEFAULT false,
    strategy VARCHAR(50),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO feature_flags (name, enabled, strategy)
VALUES ('new-checkout', true, 'percentage');
```

**Процесс изменения:**
1. Изменение через админ-панель или прямой SQL-запрос
2. Мгновенное применение без переразвертывания

**Применимость:** Внутренние инструменты, команды с ресурсами на разработку UI.

---

### Сценарий 3: Специализированный сервис (Unleash)

```python
from UnleashClient import UnleashClient

client = UnleashClient(
    url="https://unleash.mycompany.com/api",
    app_name="my-app",
    custom_headers={'Authorization': 'API_TOKEN'}
)
client.initialize_client()

context = {'userId': user.id, 'sessionId': session.id}
if client.is_enabled("new-payment-flow", context=context):
    process_new_payment()
else:
    process_legacy_payment()
```

**Процесс изменения:**
1. Изменение в веб-UI провайдера
2. Мгновенное применение через SDK
3. Встроенный аудит и метрики

**Применимость:** Production-системы, A/B-тесты, канареечные релизы, команды с высокими требованиями к отказоустойчивости.
