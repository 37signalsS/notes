# Сценарии использования Feature Toggles

## Определения

- **Сценарии использования** — это типовые архитектурные и бизнес-задачи, которые эффективно решаются с помощью механизма переключения функциональности в реальном времени.

---

## Основные концепции

### Критерии выбора сценария

Выбор конкретного подхода зависит от бизнес-цели и требуемой скорости реакции системы:

| Цель | Сценарий | Тип флага | Динамичность |
| :--- | :--- | :--- | :--- |
| Постепенный запуск | Canary Deployment | Экспериментальный / Релизный | Высокая |
| Снижение рисков | Kill Switch (Аварийный выключатель) | Операционный | Критически высокая |
| Ограниченный доступ | Бета-тестирование | Флаг разрешений / Релизный | Средняя |
| Проверка гипотез | A/B тестирование | Экспериментальный | Высокая |

### Общие принципы реализации

Независимо от сценария, при реализации следует придерживаться следующих принципов:
- **Контекст запроса**: Передача атрибутов пользователя (ID, роль, версия приложения) для принятия точечных решений.
- **Отказоустойчивость**: Обязательное наличие значений по умолчанию (Fallbacks) на случай сбоя системы управления флагами.
- **Прослеживаемость**: Логирование факта проверки флага для последующего аудита и анализа метрик.

Подробности технической реализации — в документе **[Реализация Feature Toggles](./implementation.md)**.

## Практические сценарии

### Сценарий 1: Canary Deployment (Канареечный релиз)

Постепенное включение новой функциональности для ограниченной группы пользователей с целью мониторинга стабильности.

- **Тип флага:** [Экспериментальный](./types.md#экспериментальные-флаги-experiment-toggles) или [Релизный](./types.md#релизные-флаги-release-toggles).

**Пример реализации (Python):**
```python
# Определение процента раскатки из конфигурации
rollout_percentage = feature_flags.get_value('new-ui-rollout', default=0)

# Детерминированное хеширование для стабильности опыта пользователя
user_hash = hash(user.id) % 100
if user_hash < rollout_percentage:
    show_new_ui()
else:
    show_legacy_ui()
```

### Сценарий 2: Аварийный выключатель (Kill Switch)

Механизм мгновенного отключения функциональности при обнаружении критических ошибок или чрезмерной нагрузки на инфраструктуру.

- **Тип флага:** [Операционный (Ops Toggle)](./types.md#операционные-флаги-ops-toggles).

**Пример (Python/Flask):**
```python
@app.route('/api/v1/recommendations')
def recommendations():
    # Если рекомендательный сервис перегружен, отключаем его мгновенно
    if not feature_flags.is_enabled('enable-recommendations', default=True):
        return get_static_popular_items() 
    
    return get_personalized_recommendations()
```

### Сценарий 3: Бета-тестирование и Dark Launching

Предоставление доступа к новым функциям только определенным сегментам (например, сотрудникам компании или Early Adopters).

- **Тип флага:** [Флаг разрешений](./types.md#флаги-разрешений-permission-toggles).

**Пример реализации:**
```python
# Проверка вхождения пользователя в сегмент бета-тестеров
if feature_flags.is_enabled('next-gen-dashboard', context={'user_id': user.id}):
    render_next_gen_dashboard()
```

### Сценарий 4: A/B Тестирование

Сравнение эффективности различных реализаций функции для выбора варианта с лучшими бизнес-метриками.

- **Тип флага:** [Экспериментальный](./types.md#экспериментальные-флаги-experiment-toggles).

**Пример реализации:**
```python
variant = feature_flags.get_variant('checkout-flow-test', context={'user_id': user.id})

if variant == 'one-page':
    render_one_page_checkout()
elif variant == 'multi-step':
    render_multi_step_checkout()
else:
    render_default_checkout()
```
