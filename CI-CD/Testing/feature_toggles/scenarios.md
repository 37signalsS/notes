# Сценарии использования Feature Toggles

## Определения

**Сценарии использования** — это типовые архитектурные и бизнес-задачи, которые эффективно решаются с помощью механизмов динамического управления функциональностью (Feature Flags) в рантайме.

---

## Основные концепции

### Критерии выбора сценария

Выбор подхода зависит от бизнес-цели, допустимого уровня риска и требуемой скорости реакции системы.

| Цель | Сценарий | Тип флага | Динамичность |
| :--- | :--- | :--- | :--- |
| **Постепенный запуск** | Canary Deployment | Релизный / Экспериментальный | Высокая |
| **Снижение рисков** | Kill Switch / Circuit Breaker | Операционный | Критическая |
| **Ограниченный доступ** | Бета-тестирование / Dark Launch | Флаг разрешений | Средняя |
| **Проверка гипотез** | A/B Тестирование | Экспериментальный | Высокая |
| **Миграция данных** | Shadow Read / Dual Write | Операционный | Высокая |

### Общие принципы реализации

1.  **Контекст запроса (Context-awareness):** Передача атрибутов пользователя (ID, Geo, Bucket, Device) для принятия гранулярных решений.
2.  **Отказоустойчивость (Fallbacks):** Наличие захардкоженных значений по умолчанию на случай недоступности системы управления флагами.
3.  **Обсервабилити (Observability):** Каждое переключение должно сопровождаться метриками и событиями в логах для анализа влияния на систему.

## Практические сценарии

### Сценарий 1: Канареечный релиз (Canary Deployment)

Постепенное включение новой функции для процента пользователей с целью мониторинга стабильности (ошибки, задержки).

**Пример реализации (Python/SDK):**
```python
# Использование детерминированного хеширования по user_id
if ff_client.is_enabled("new-payment-checkout", context={"user_id": user.id}):
    return render_modern_checkout()
return render_legacy_checkout()
```

### Сценарий 2: Аварийный выключатель (Kill Switch)

Мгновенное отключение ресурсоемкой или сбойной функции при деградации инфраструктуры.

**Сценарий:** При росте нагрузки на БД выше 90% SRE отключает "блок рекомендаций", чтобы спасти основной функционал покупки.
```python
@app.route('/product/<id>')
def product_page(id):
    product = db.get_product(id)
    # Если Kill Switch активен, возвращаем страницу без рекомендаций
    recommendations = []
    if ff_client.is_enabled("enable-recommendations"):
        recommendations = ai_service.get_related(id)
    
    return render_template('product.html', product=product, recs=recommendations)
```

### Сценарий 3: Разрыв цепи (Circuit Breaker)

Ручное или автоматическое отключение интеграции с внешним нестабильным API.

**Сценарий:** Внешний сервис рассылок начал отвечать с задержкой 5 сек. Чтобы не блокировать поток заказов, интеграция временно отключается (фолбек — запись в очередь для последующей отправки).

### Сценарий 4: Бета-тестирование и сегментация

Предоставление доступа к функциям на основе ролей или вхождения в список (White List).

```python
# Доступ только для сотрудников и участников бета-программы
if user.is_staff or ff_client.is_enabled("next-gen-editor", context={"user_id": user.id}):
    enable_experimental_features()
```

### Сценарий 5: Миграция данных (Shadow Read / Dual Write)

Безопасный переход с одной БД/API на другую без простоя.

1.  **Dual Write:** Записываем данные в старую и новую системы.
2.  **Shadow Read:** Читаем из старой (основной) и новой (теневой). Сравниваем результаты, логируем расхождения.
3.  **Switch:** Переключаем флаг на чтение из новой системы как основной.

### Сценарий 6: Управление стоимостью облака (Cost Optimization)

Динамическое отключение функций, требующих дорогих вычислений (например, GPU-рендеринг или детализированная аналитика) во время пиковых нагрузок или превышения бюджета.
