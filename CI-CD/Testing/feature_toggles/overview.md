# Обзор Feature Toggles

## Определения

- **Feature Toggle (Feature Flag)** — это механизм разработки программного обеспечения, позволяющий изменять поведение системы во время выполнения без изменения исходного кода и повторного развертывания (deploy).
- **Ключевая концепция:** Полное отделение процесса развертывания кода (Deployment) от процесса выпуска функциональности (Release/Expose).

---

## Основные концепции

### Проблема: Долгоживущие ветки и "Merge Hell"

Традиционный подход с использованием долгоживущих веток (Feature Branches) для каждой новой функции приводит к ряду проблем:
- Сложные слияния (Merge Hell) из-за накопления большого количества изменений.
- Задержка интеграции кода, что противоречит принципам Continuous Integration.
- Трудности при тестировании взаимодействия нескольких новых функций до их слияния в основную ветку.

### Решение: Trunk-Based Development и Feature Toggles

Feature Toggles являются критически важным инструментом для реализации **[Trunk-Based Development](../../../Git/git_workflows.md#3-trunk-based-development-tbd)**. Все разработчики ежедневно интегрируют свой код в основную ветку (`main`/`master`). 

Если функция еще не готова или не должна быть видна пользователям, она оборачивается в условие проверки флага:

```python
if feature_flags.is_enabled("new_payment_method"):
    # Новая логика
    process_new_payment()
else:
    # Старая логика
    process_legacy_payment()
```

**Преимущества подхода:**
- **Continuous Integration (CI):** Код всегда находится в интегрированном и рабочем состоянии.
- **Минимизация конфликтов:** Ветки живут часы, а не недели.
- **Снижение рисков:** Возможность мгновенно отключить проблемную функцию в production (Kill Switch).
- **Гибкость релизов:** Маркетинг или Product-менеджеры могут включать функции в удобное время без участия DevOps-инженеров.

### Компромиссы и цена использования

- **Технический долг:** Каждый флаг добавляет условную логику, которую необходимо удалять после стабилизации функции.
- **Сложность тестирования:** Увеличивается количество комбинаций состояний системы (флаг включен/выключен).
- **Управление конфигурацией:** Требуется надежная система для хранения и быстрой доставки состояний флагов в приложение.

## Практические сценарии

Feature Toggles позволяют реализовывать сложные стратегии доставки, подробнее описанные в документе **[Сценарии использования](./scenarios.md)**:

- **Canary Deployment**: Постепенное включение функции для процента пользователей (например, 1% → 5% → 25% → 100%).
- **A/B Тестирование**: Сравнение бизнес-метрик для разных групп пользователей.
- **Dark Launching**: Тестирование нагрузки новой функции в production без отображения изменений в интерфейсе пользователя.
- **Kill Switch**: Мгновенное отключение функционала при обнаружении критических ошибок или деградации производительности.
