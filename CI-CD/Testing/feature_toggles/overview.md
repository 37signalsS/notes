# Обзор: Feature Toggles (Feature Flags)

### Определения

- **Feature Toggle (Feature Flag)** — это техника в разработке ПО, которая позволяет включать или отключать функциональность приложения во время выполнения без изменения кода и повторного развертывания.
- **Ключевая идея:** Отделение развертывания кода (deployment) от выпуска функциональности (release).

### Основные концепции

#### Проблема: Долгоживущие ветки

Традиционный подход с долгоживущими ветками для каждой новой функции приводит к сложным и рискованным слияниям (merge hell), задерживает интеграцию и тестирование.

```
ТРАДИЦИОННЫЙ ПОДХОД (Long-lived branches):

main:     ●────●────●────●────●────●────●────●
           │                   │
feature-A: ●────●────●────●────┘ (merge)
                                
feature-B:      ●────●────●────●────●────┘ (merge - конфликты!)
```

#### Решение: Trunk-Based Development с Feature Toggles

С флагами все разработчики могут постоянно интегрировать свою работу в основную ветку (`main`), что является ключевым принципом **[Trunk-Based Development](../../CI-CD/ci_cd_patterns.md#1-trunk-based-development-tbd)**. Незавершенная функциональность просто скрыта за выключенным флагом, что позволяет отделить развертывание кода от его выпуска.

```
С Feature Toggles (Trunk-based development):

main:     ●────●────●────●────●────●────●────●────●────●
          │    │    │    │    │    │    │    │    │
          A    A    A    A    B    B    B    B    C
          
Все фичи в main, но скрыты:
- feature A: toggle=OFF (в разработке)
- feature A: toggle=ON  (в проде)
- feature B: toggle=OFF (в разработке)
```

**Преимущества:**

- **Непрерывная интеграция:** Код интегрируется в `main` ежедневно.
- **Минимум конфликтов:** Ветки живут часы, а не недели.
- **Снижение риска:** Позволяет реализовать Canary-релизы и A/B-тестирование.
- **Быстрый откат:** Проблемную функцию можно мгновенно отключить в production.
