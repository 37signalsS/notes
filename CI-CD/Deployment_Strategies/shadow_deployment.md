# Shadow Deployment (Traffic Mirroring)

## Определения

**Shadow Deployment (Теневое развертывание)**, также известное как **Traffic Mirroring (Зеркалирование трафика)** — стратегия развертывания, при которой реальный пользовательский трафик копируется и отправляется на новую версию сервиса ("shadow"), не затрагивая основной поток запросов. Ответы от теневой версии игнорируются и не возвращаются пользователю. Основная цель — протестировать новую версию под реальной нагрузкой без риска для пользователей.

Подробнее об обзоре стратегий — в [Core_Concepts/deployment_strategies.md](../Core_Concepts/deployment_strategies.md), сравнение — в [comparison.md](./comparison.md).

## Основные концепции

### Ключевые идеи

- **Копирование трафика**: Входящие запросы к стабильной версии дублируются на уровне прокси или service mesh.
- **Отсутствие влияния на пользователя**: Пользователь получает ответ только от стабильной ("primary") версии. Результаты работы "shadow" версии никак не влияют на пользователя.
- **Тестирование под реальной нагрузкой**: Позволяет проверить производительность, выявить ошибки и регрессии в условиях, максимально приближенных к боевым.
- **Безопасность для stateful-сервисов**: Критически важно, чтобы "shadow" версия не выполняла операции, изменяющие состояние (например, запись в базу данных, отправка сообщений в очередь), или использовала отдельные, изолированные окружения (stub-сервисы, временная БД).

### Схема работы

1. Вся система работает на стабильной версии **V1**.
2. Новая версия **V2 (shadow)** развертывается параллельно.
3. На уровне маршрутизатора (например, Istio VirtualService, Nginx) настраивается зеркалирование: 100% трафика идет на **V1**, а его копия ("fire and forget") — на **V2**.
4. Инженеры анализируют метрики, логи и трейсы от **V2**, сравнивая их с поведением **V1**.
5. Ищутся аномалии: рост ошибок, увеличение задержки, падения, утечки памяти.
6. После подтверждения стабильности **V2** можно проводить полноценное развертывание с помощью другой стратегии (например, Blue-Green или Rolling Update).

## Практические сценарии

### Реализация с помощью Istio

Istio позволяет легко настроить зеркалирование трафика с помощью `VirtualService`.

```yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: my-app-mirror
spec:
  hosts:
    - "my-app.example.com"
  http:
    - route:
        # 100% трафика направляется на стабильную версию v1
        - destination:
            host: my-app
            subset: v1
          weight: 100
      # Та же самая порция трафика зеркалируется на v2 (shadow)
      mirror:
        host: my-app
        subset: v2
      # Указывает процент зеркалируемого трафика.
      # Если не указано, зеркалируется 100%.
      mirror_percent: 100 
```

В этом примере весь трафик к сервису `my-app` будет обработан подами с `subset: v1`, а его копия будет отправлена подам с `subset: v2`.

Подробнее о трафике в Istio — в [Service Mesh Traffic Management](../../Service_Mesh/traffic_management.md).

## Дополнительная информация

### Преимущества и недостатки

| Преимущества | Недостатки |
| :--- | :--- | :--- |
| **Максимальная безопасность для пользователя** (нулевой радиус поражения) | **Удвоенная стоимость инфраструктуры** (как и в Blue-Green) |
| **Тестирование на реальном, непредсказуемом трафике** | **Сложность для stateful-сервисов** (риск двойной записи) |
| **Отличный способ проверить производительность и нефункциональные требования** | **Требует продвинутых инструментов** (Service Mesh, Ingress-контроллеры) |
| **Позволяет выявить редкие ошибки, не воспроизводимые в тесте** | **Ответы от shadow-версии игнорируются**, что не позволяет проверить весь цикл взаимодействия с клиентом. |

### Когда использовать Shadow Deployment?

- Перед выкаткой критически важных изменений, где цена ошибки очень высока.
- Для тестирования производительности новой версии на реальном профиле нагрузки.
- Для проверки правильности работы нового кода, который не изменяет состояние (например, рефакторинг алгоритма расчета).
- Как финальный этап проверки перед Canary или Blue-Green развертыванием.
