# SAST (Static Application Security Testing)

## Definitions

**SAST (Static Application Security Testing)** — метод анализа безопасности, проверяющий исходный код, байт-код или бинарные файлы приложения без его запуска. Также известен как «тестирование белого ящика».

SAST-сканеры анализируют код на наличие уязвимостей, отслеживая поток данных от «источника» (например, пользовательский ввод) до «приёмника» (например, выполнение SQL-запроса), и выявляют небезопасные конструкции и логические ошибки.

## Basic Concepts

### Цели и охват

- **Превентивность:** Обнаружение дефектов на ранних стадиях разработки (до сборки и развёртывания).
- **Полное покрытие:** Анализ всей кодовой базы, включая код, не выполняемый при динамическом тестировании.
- **Зависимость от правил:** Качество анализа зависит от набора правил (ruleset), поддержки языков и фреймворков.

### Типы обнаруживаемых уязвимостей

SAST эффективен для поиска уязвимостей в коде: инъекции (SQL, Command, LDAP), XSS, небезопасная десериализация, path traversal, секреты в коде, криптографические ошибки, логические ошибки авторизации.

Полный список уязвимостей с сопоставлением по инструментам — в [обзоре уязвимостей SAST/DAST](./sast_dast_vulnerabilities.md).

### Ограничения

- **Ложноположительные срабатывания:** Часты при отсутствии контекстного анализа (например, если данные уже валидированы).
- **Скорость:** Полный анализ крупного проекта может занимать значительное время.
- **Сложность настройки:** Требует тонкой настройки правил и политик для снижения «шума».

## Practical Scenarios

### Интеграция в CI/CD

SAST встраивается на ранних этапах конвейера:

- **На уровне IDE:** Плагины для мгновенной обратной связи разработчику.
- **Pre-commit хуки:** Быстрая проверка изменённых файлов перед коммитом.
- **Pull/Merge Request:** Инкрементальный анализ только новых изменений.
- **Этап сборки (Build):** Полный анализ всего приложения.

### Пример: Уязвимость SQL-инъекции

SAST обнаруживает код, где данные из `request` попадают в `execute` без параметризации.

```python
# Уязвимо: конкатенация строки
user_id = request.args.get("id")
sql = f"SELECT * FROM users WHERE id = {user_id}"
cursor.execute(sql)
```

### Пример: Исправленный код

Параметризованный запрос предотвращает инъекцию.

```python
# Безопасно: параметризованный запрос
user_id = request.args.get("id")
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
```

## Additional Information

- **Инкрементальный анализ:** Большинство инструментов поддерживают сканирование только изменённого кода (diff-скан), что сокращает время проверок в CI/CD.
- **Baseline:** Установка базового уровня позволяет фокусироваться только на новых уязвимостях после последней проверки.

SAST — часть комплексной стратегии безопасности, включающей [DAST](./dast_overview.md) и [тестирование безопасности в CI/CD](./sast_dast_cicd_integration.md).
