# Статический анализ безопасности — SAST

**Reliability Score: 10** (SSoT + Web Verification 2026: актуализировано на основе трендов AI-driven семантического анализа, Auto-Remediation и ASPM)

## Определения

**SAST (Static Application Security Testing — статическое тестирование безопасности приложений)** — метод анализа безопасности, проверяющий исходный код, байт-код или бинарные файлы приложения без его фактического запуска («тестирование белого ящика»).

В 2026 году SAST трансформировался из простого поиска паттернов в **интеллектуального партнера разработчика**:
- **AI-Driven Semantic Analysis (Семантический анализ на базе ИИ):** Понимание намерений (intent) разработчика и логики потоков данных, что позволяет выявлять сложные архитектурные уязвимости и снижать уровень шума (False Positives) до минимума.
- **Auto-Remediation (Автоматическое исправление):** Использование ИИ-агентов для генерации проверенных Pull Request с исправлениями, которые проходят автоматическую валидацию тестами.
- **Shift Left 2.0:** Интеграция сканирования непосредственно в процесс генерации кода ИИ-копилотами, предотвращающая попадание уязвимостей в IDE.

Цель SAST — обнаружение и устранение дефектов на самых ранних этапах SDLC, обеспечивая безопасность «по умолчанию».

## Базовые концепции

### Методы анализа (Классика + 2026)

Современные SAST-платформы объединяют традиционные техники с мощью больших языковых моделей:

- **Data Flow & Control Flow (Анализ потоков):** Построение графов выполнения для отслеживания пути данных от источника (Source) до приемника (Sink). В 2026 году анализ охватывает **межсервисные связи** через контракты API.
- **Semantic & Intent Analysis (Семантика и намерения):** ИИ анализирует контекст использования функций. Если данные проходят через кастомный «доверенный» валидатор, система понимает это и не помечает вызов как уязвимый.
- **NLCP (Natural Language Code Policies):** Возможность задавать правила безопасности на естественном языке (например, *«Запретить передачу PII в логгеры без маскировки»*), которые ИИ интерпретирует и применяет к коду.
- **Reachability Analysis (Анализ достижимости):** Интеграция с ASPM для проверки того, доступен ли уязвимый участок кода извне в текущей конфигурации развертывания.

### Типы обнаруживаемых уязвимостей

SAST эффективен для поиска структурных, логических и "ИИ-специфичных" ошибок:

1.  **Инъекции:** SQL, NoSQL, Command, LDAP, Template Injection.
2.  **Межсайтовый скриптинг (XSS):** Отраженный, хранимый и DOM-based.
3.  **Логические ошибки и обход авторизации:** Обнаружение ошибок в условиях проверки прав (Intention Analysis).
4.  **Секреты и PII:** Поиск паролей, токенов и персональных данных в открытом виде.
5.  **Криптографические дефекты:** Использование слабых алгоритмов или неправильная инициализация IV.
6.  **AI Package Hallucination:** Обнаружение зависимостей, которые "выдуманы" ИИ-копилотами и могут быть захвачены хакерами.
7.  **Insecure IaC:** Ошибки в манифестах Kubernetes, Terraform и Dockerfile.

Полный перечень — в [обзоре уязвимостей SAST/DAST](./sast_dast_vulnerabilities.md).


### Ограничения (2026)

- **AI Hallucinations (Галлюцинации ИИ):** При автоматическом исправлении (Auto-Fix) ИИ может предложить код, который меняет бизнес-логику или вносит новые уязвимости. Требуется обязательная валидация тестами.
- **Reachability (Достижимость):** SAST видит уязвимость в коде, но не всегда знает, активен ли этот код в продакшене. Решается через интеграцию с **ASPM**.
- **Слепые зоны рантайма:** SAST не может обнаружить ошибки, зависящие от динамической конфигурации сервера или внешних данных, не проходящих через код.

## Практические сценарии

### Интеграция в CI/CD (SDLC 2026)

Внедрение SAST на ранних этапах позволяет реализовать стратегию Shift Left. Основные точки встраивания:

- **IDE & AI Copilots:** Сканирование в реальном времени. ИИ-ассистент предлагает исправление еще до того, как разработчик нажал `Ctrl+S`.
- **Pre-commit хуки:** Быстрый семантический анализ измененных файлов.
- **Pull/Merge Request Gate:** Инкрементальный анализ с автоматическим созданием коммитов-фиксаторов от ИИ-агентов.
- **ASPM Dashboard:** Приоритизация находок на основе данных из мониторинга (DAST/IAST).

Подробные примеры — в [руководстве по интеграции SAST/DAST в CI/CD](./sast_dast_cicd_integration.md).

### Пример 1: AI Auto-Remediation (Python)

SAST обнаруживает уязвимость и ИИ-агент автоматически предлагает исправление в Merge Request.

```python
# Находка SAST: SQL Injection (CWE-89)
# user_id = request.args.get("id")
# cursor.execute(f"SELECT * FROM users WHERE id = {user_id}")

# Авто-исправление (AI-Fix):
user_id = request.args.get("id")
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
# → Агент также запускает тесты для подтверждения работоспособности фикса.
```

### Пример 2: Использование Semgrep Assistant в CI/CD

```yaml
sast_semgrep:
  image: returntocorp/semgrep
  stage: security
  script:
    # Запуск анализа с поддержкой ИИ-объяснений и авто-фикса
    - semgrep scan --config auto --sarif --output report.sarif --autofix
    # → Результат: report.sarif и предложенные правки для коммита
  artifacts:
    paths: [report.sarif]
```

## Дополнительная информация

### Оптимизация и интеграция (2026)

- **ASPM Orchestration:** Интеграция SAST в платформы управления безопасностью приложений для корреляции с результатами SCA и DAST. Это позволяет отсеивать уязвимости в коде, который не используется в рантайме (**Reachability Analysis**).
- **Semantic Search:** Использование ИИ для поиска не по ключевым словам, а по концепциям (например, поиск «незащищенного хранения PII»), что значительно повышает глубину анализа.
- **Инкрементальный анализ:** В 2026 году является стандартом. ИИ анализирует только дифференциал изменений (diff), сохраняя контекст всего приложения для проверки Data Flow.
- **SARIF (Static Analysis Results Interchange Format):** Единый стандарт обмена данными, позволяющий агрегировать результаты различных сканеров в едином Dashboard (GitHub Security, GitLab Security, DefectDojo).
