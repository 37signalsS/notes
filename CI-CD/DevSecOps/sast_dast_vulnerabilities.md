# Уязвимости SAST и DAST

## Определения

**SAST (Static Application Security Testing — статическое тестирование безопасности приложений)** и **DAST (Dynamic Application Security Testing — динамическое тестирование безопасности приложений)** специализируются на разных типах уязвимостей из-за различий в подходах к анализу:

- **SAST** анализирует исходный код, конфигурации и зависимости без запуска приложения.
- **DAST** анализирует поведение работающего приложения через его внешние интерфейсы.

## Базовые концепции

### Уязвимости, обнаруживаемые SAST

Статический анализ просматривает код и конфигурации, выстраивая логические цепочки от ввода данных («источник») до их обработки («приёмник»).

**Характерные находки:**

- **Инъекции (Injections):**
  - **SQL (Structured Query Language — язык структурированных запросов) Injection:** небезопасная конкатенация строк в запросах к базе данных.
  - **Command Injection:** передача нефильтрованного пользовательского ввода в системные вызовы ОС.
  - **LDAP (Lightweight Directory Access Protocol — облегченный протокол доступа к каталогам) / NoSQL Injection:** формирование запросов к директориям или нереляционным базам данных.
- **Межсайтовый скриптинг (XSS — Cross-Site Scripting):** отсутствие экранирования при вставке данных в шаблоны HTML/JavaScript.
- **Небезопасная десериализация:** использование функций десериализации, позволяющих выполнять произвольный код.
- **Обход пути (Path traversal):** небезопасная обработка путей к файлам, позволяющая доступ за пределы разрешенной директории.
- **Секреты в коде:** хардкод токенов, ключей **API (Application Programming Interface — программный интерфейс приложения)** и паролей.
- **Криптографические ошибки:** использование слабых алгоритмов (MD5, SHA-1), отсутствие соли или фиксированные векторы инициализации.
- **Логические ошибки авторизации:** пропуск проверок прав доступа в коде функций.

### Уязвимости, обнаруживаемые DAST

Динамический анализ взаимодействует с работающим приложением через сетевые протоколы, заголовки и параметры запросов.

**Характерные находки:**

- **XSS (отражённый и хранимый):** подтверждение возможности внедрения скриптов через формы и параметры.
- **Подделка межсайтовых запросов (CSRF — Cross-Site Request Forgery):** отсутствие защитных токенов в чувствительных операциях.
- **Уязвимости аутентификации:** слабые политики паролей, возможность фиксации сессии, отсутствие флагов безопасности (`HttpOnly`, `Secure`) у cookie.
- **Открытые редиректы:** перенаправления пользователя на произвольные сайты через параметры URL.
- **Небезопасные заголовки безопасности:** отсутствие или неверная настройка **HSTS (HTTP Strict Transport Security — механизм принудительного использования безопасного соединения HTTP)**, **CSP (Content Security Policy — политика защиты контента)**, X-Frame-Options.
- **Утечки информации:** избыточные сообщения об ошибках, раскрывающие детали реализации сервера или базы данных.
- **Подделка запросов на стороне сервера (SSRF — Server-Side Request Forgery):** возможность заставить сервер отправить запрос во внутреннюю сеть.
- **Ошибки конфигурации CORS (Cross-Origin Resource Sharing — механизм совместного использования ресурсов между разными источниками):** избыточное доверие к произвольным источникам (Origin).

### Сопоставление возможностей обнаружения

| Уязвимость | Пример | Инструмент обнаружения |
| :--- | :--- | :--- |
| **SQL Injection** | Конкатенация запросов в коде | SAST, DAST (SAST находит больше путей) |
| **Command Injection** | Вызовы `os.system()` или `exec()` | SAST |
| **XSS** | Отражённый через параметр URL | SAST, DAST (DAST подтверждает эксплуатацию) |
| **CSRF** | Операции без анти-CSRF токенов | DAST |
| **Небезопасные заголовки** | Отсутствие CSP или HSTS | DAST |
| **Небезопасная десериализация** | Вызов `pickle.loads()` или `yaml.load()` | SAST |
| **Секреты в коде** | Токены в исходных файлах | SAST |
| **Path Traversal** | Конкатенация путей с `../` | SAST, DAST |
| **SSRF** | Запросы к `http://localhost/...` | DAST |
| **Ошибки авторизации** | Отсутствие проверки ролей в функции | SAST |

## Практические сценарии

### Пример: Внедрение команд (Command Injection) в Python

Инструмент SAST обнаружит использование опасной функции с переменной, полученной из ввода пользователя.

```python
# Уязвимо: прямое использование ввода пользователя в команде ОС
host = request.args.get("host")
os.system("ping -c 1 " + host) 
# → Результат: SAST выдаст предупреждение о возможности Command Injection
# Например, если host = "8.8.8.8; rm -rf /"
```

```python
# Безопасно: использование защищенных методов запуска процессов
host = request.args.get("host")
subprocess.run(["ping", "-c", "1", host], check=True)
# → Результат: SAST пропустит этот код, так как subprocess.run предотвращает инъекцию команд
```

## Дополнительная информация

### Нюансы обнаружения

- **SAST:** склонен к ложноположительным срабатываниям (не видит контекст выполнения), но незаменим для поиска уязвимостей в бизнес-логике и неактивном коде. Эффективен на самых ранних этапах (Shift Left).
- **DAST:** подтверждает реальную эксплуатируемость уязвимостей и находит ошибки конфигурации окружения, но может пропустить эндпоинты, не обнаруженные краулером. Требует развернутой среды.
- **Комбинирование:** сочетание обоих подходов обеспечивает максимальное покрытие, позволяя выявлять как ошибки реализации в коде, так и дефекты настройки рантайма.
