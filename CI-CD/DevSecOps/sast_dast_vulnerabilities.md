# Типичные уязвимости, выявляемые SAST и DAST

## Определения

SAST- и DAST-сканеры специализируются на разных типах уязвимостей из-за фундаментальных различий в их подходах. SAST анализирует код, а DAST — поведение работающего приложения.

## Основные концепции

### Что чаще всего находит SAST

Статический анализ просматривает исходный код и конфигурации, выстраивая цепочки «источник → преобразование → приёмник».

**Характерные находки:**

- **Инъекции в коде:**
  - **SQL Injection:** При конкатенации строк в запросах.
  - **Command Injection:** При передаче пользовательского ввода в системные команды.
  - **LDAP/NoSQL Injection:** При составлении запросов из неконтролируемых данных.
- **XSS в шаблонах:** Неэкранированные вставки в HTML/JS, опасные вызовы рендеринга.
- **Десериализация небезопасных форматов:** Использование небезопасных десериализаторов.
- **Обработка файлов и путей:** Path traversal (`../`), небезопасные загрузки.
- **Секреты в коде:** Хардкод токенов, ключей, паролей.
- **Криптографические ошибки:** Использование MD5/SHA-1, отсутствие соли, фиксированные векторы инициализации (IV).
- **Потенциальные уязвимости авторизации:** Пропуск проверок прав доступа.

### Что чаще всего находит DAST

Динамический анализ взаимодействует с работающим приложением, проверяя его входные точки, заголовки и ответы.

**Характерные находки:**

- **Отражённые и хранимые XSS:** Внедрение скриптов в параметры и поля форм с подтверждением их выполнения.
- **CSRF (Cross-Site Request Forgery):** Отсутствие анти-CSRF токенов.
- **Уязвимости аутентификации и сессий:** Слабые политики паролей, фиксация сессии, отсутствие флагов `HttpOnly`/`Secure` у cookie.
- **Открытые редиректы:** Перенаправления на внешние домены через параметры URL.
- **Неправильные заголовки безопасности:** Отсутствие HSTS, CSP, X-Frame-Options.
- **Утечки информации:** Листинг директорий, избыточные сообщения об ошибках.
- **SSRF (Server-Side Request Forgery):** Попытки заставить сервис обращаться к внутренним ресурсам.
- **Ошибки конфигурации CORS:** Доверие к произвольным Origin.

## Практические сценарии

### Сопоставление категорий уязвимостей

| Категория | Пример | Кому «проще» обнаружить |
| :--- | :--- | :--- |
| **SQL Injection** | Конкатенация запросов | Оба (SAST быстрее на коде) |
| **Command Injection** | `os.system()`/`Runtime.exec()` | SAST |
| **XSS** | Отражённый через параметр | Оба (DAST подтверждает эксплуатацию) |
| **CSRF** | Отсутствие токенов | DAST |
| **Небезопасные заголовки**| Отсутствие HSTS/CSP | DAST |
| **Десериализация** | Небезопасные декодеры | SAST |
| **Секреты в коде** | API-ключи, токены | SAST |
| **Path Traversal** | `../` в путях к файлам | Оба |
| **SSRF** | Запросы к внутренним хостам | DAST |
| **Ошибки авторизации** | Пропуск проверки ролей в коде | SAST |

### Пример: Command Injection (Python)

```python
# Уязвимо
host = request.args.get("host")
os.system("ping -c 1 " + host) # host может быть "google.com; rm -rf /"
```

```python
# Безопаснее
host = request.args.get("host")
# Аргументы передаются как список, предотвращая инъекцию
subprocess.run(["ping", "-c", "1", host], check=True)
```

## Дополнительная информация

### Нюансы обнаружения

- **SAST** склонен к «ложноположительным» срабатываниям, так как не видит контекст выполнения (например, работа WAF или уже проведенная валидация). Однако он незаменим для поиска уязвимостей в логике и тех частях кода, которые не активны в тестовой среде.
- **DAST** подтверждает реальную возможность эксплуатации уязвимости и находит ошибки конфигурации окружения. Однако он может пропустить уязвимости в неиспользуемых ветках кода или скрытых эндпоинтах.
- **Комбинация** этих подходов является наиболее эффективной стратегией, позволяя покрывать как ошибки реализации, так и дефекты конфигурации.

Понимание того, [какой инструмент что находит](../DevSecOps/sast_vs_dast.md), помогает правильно выстроить [процесс безопасной разработки](../DevSecOps/devsecops_overview.md).
