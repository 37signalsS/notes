# Уязвимости SAST и DAST

## Определения

Для обеспечения безопасности приложений в рамках **AppSec (Application Security)** используются различные методы тестирования, специализирующиеся на определенных типах угроз:

- **SAST (Static Application Security Testing — статическое тестирование безопасности приложений):** анализ исходного кода, конфигураций и зависимостей без запуска приложения («белый ящик»).
- **DAST (Dynamic Application Security Testing — динамическое тестирование безопасности приложений):** анализ поведения работающего приложения через его внешние интерфейсы («черный ящик»).
- **IAST (Interactive Application Security Testing — интерактивное тестирование безопасности приложений):** гибридный метод, использующий агентов внутри приложения для анализа кода и потоков данных в реальном времени («серый ящик»).
- **SCA (Software Composition Analysis — анализ состава ПО):** выявление уязвимостей в сторонних библиотеках и компонентах (Open Source). Подробнее: **[анализ зависимостей и SBOM](../../Security/Supply_Chain_Security/dependency_and_sbom_analysis.md)**.

## Базовые концепции

### Уязвимости, обнаруживаемые SAST

Статический анализ просматривает код и конфигурации, выстраивая логические цепочки от ввода данных («источник») до их обработки («приёмник»).

**Характерные находки:**

- **Инъекции (Injections):**
  - **SQL Injection:** небезопасная конкатенация строк в запросах к базе данных.
  - **Command Injection:** передача нефильтрованного пользовательского ввода в системные вызовы ОС.
  - **LDAP / NoSQL Injection:** формирование запросов к директориям или нереляционным базам данных.
- **Межсайтовый скриптинг (XSS — Cross-Site Scripting):** отсутствие или некорректное экранирование при вставке данных в шаблоны HTML/JavaScript.
- **Небезопасная десериализация:** использование функций десериализации, позволяющих выполнять произвольный код.
- **Обход пути (Path traversal):** небезопасная обработка путей к файлам, позволяющая доступ за пределы разрешенной директории.
- **Секреты в коде (Hardcoded Secrets):** наличие токенов, ключей API и паролей в исходном коде или конфигурационных файлах.
- **Криптографические ошибки:** использование слабых алгоритмов (MD5, SHA-1), отсутствие соли или фиксированные векторы инициализации.
- **Логические ошибки авторизации:** пропуск проверок прав доступа в коде функций.
- **Ошибки конфигурации инфраструктуры (IaC — Infrastructure as Code):** небезопасные настройки в Dockerfile, Terraform-манифестах или конфигурациях Kubernetes (например, запуск от root, отсутствие ограничений ресурсов).

### Уязвимости, обнаруживаемые DAST

Динамический анализ взаимодействует с работающим приложением через сетевые протоколы, заголовки и параметры запросов, имитируя действия злоумышленника.

**Характерные находки:**

- **XSS (отражённый и хранимый):** подтверждение возможности внедрения и исполнения скриптов в браузере.
- **Подделка межсайтовых запросов (CSRF — Cross-Site Request Forgery):** отсутствие защитных токенов в чувствительных операциях.
- **Уязвимости аутентификации:** слабые политики паролей, возможность фиксации сессии, отсутствие флагов безопасности (`HttpOnly`, `Secure`) у cookie.
- **API-специфичные уязвимости:**
  - **BOLA (Broken Object Level Authorization):** доступ к чужим данным через подмену ID в URL/теле запроса.
  - **Массовое назначение (Mass Assignment):** возможность перезаписи чувствительных полей объекта через входные данные API.
- **Открытые редиректы:** перенаправления пользователя на произвольные сайты через параметры URL.
- **Небезопасные заголовки безопасности:** отсутствие или неверная настройка HSTS, CSP, X-Frame-Options.
- **Утечки информации:** избыточные сообщения об ошибках, раскрывающие детали реализации сервера или базы данных.
- **Подделка запросов на стороне сервера (SSRF — Server-Side Request Forgery):** возможность заставить сервер отправить запрос во внутреннюю сеть или к метаданным облачного провайдера.
- **Ошибки конфигурации CORS (Cross-Origin Resource Sharing):** избыточное доверие к произвольным источникам.

### Сопоставление возможностей обнаружения

| Уязвимость | Тип | SAST | DAST | SCA | IAST |
| :--- | :--- | :---: | :---: | :---: | :---: |
| **SQL Injection** | Код/Логика | Да | Да | Нет | Да |
| **XSS** | Интерфейс | Да | Да | Нет | Да |
| **Секреты в коде** | Конфигурация| Да | Нет | Нет | Нет |
| **Уязвимые библиотеки** | Зависимости | Нет | Нет | Да | Нет |
| **CSRF / Заголовки** | Рантайм | Нет | Да | Нет | Да |
| **Command Injection** | Код/Система | Да | Нет | Нет | Да |
| **IaC (Docker/K8s)** | Инфраструктура| Да | Нет | Нет | Нет |
| **SSRF** | Сеть | Нет | Да | Нет | Да |

## Практические сценарии

### Пример: Внедрение команд (Command Injection) в Python

Инструмент SAST обнаружит использование опасной функции с переменной, полученной из ввода пользователя.

```python
# Уязвимо: прямое использование ввода пользователя в команде ОС
host = request.args.get("host")
os.system("ping -c 1 " + host) 
# → Результат: SAST выдаст предупреждение о возможности Command Injection
# Например, если host = "8.8.8.8; rm -rf /"
```

```python
# Безопасно: использование защищенных методов запуска процессов
host = request.args.get("host")
subprocess.run(["ping", "-c", "1", host], check=True)
# → Результат: SAST пропустит этот код, так как subprocess.run предотвращает инъекцию команд
```

## Дополнительная информация

### Нюансы обнаружения

- **SAST:** склонен к ложноположительным срабатываниям (False Positives), так как не видит контекст выполнения. Незаменим для поиска уязвимостей в бизнес-логике и "спящем" коде. Реализует концепцию **Shift Left** (безопасность на ранних этапах).
- **DAST:** подтверждает реальную эксплуатируемость уязвимостей и находит ошибки конфигурации окружения. Ограничен областью видимости краулера и требует развернутой, стабильной среды.
- **IAST:** обеспечивает высокую точность за счет доступа и к коду, и к контексту выполнения, но требует поддержки конкретного технологического стека и наличия автотестов для покрытия путей выполнения.
- **OAST (Out-of-band Application Security Testing):** расширение DAST для обнаружения "слепых" уязвимостей (например, Blind SSRF), когда приложение не возвращает ответ напрямую, но выполняет сетевое взаимодействие с внешним контролируемым сервером.
