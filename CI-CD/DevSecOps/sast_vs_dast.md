# SAST vs DAST — сравнение подходов

## Определения

В 2026 году обеспечение безопасности приложений (Application Security Testing — AST) эволюционировало от разрозненных сканеров к интегрированным системам оркестрации. Основные методы анализа включают:

- **SAST (Static Application Security Testing):** анализ «белого ящика». Исследование исходного кода, байт-кода или бинарных файлов без запуска приложения. В 2026 году SAST использует ИИ для семантического анализа намерений (Intent Analysis), что позволяет обнаруживать сложные логические ошибки и автоматически генерировать исправления (**AI Auto-Remediation**).
- **DAST (Dynamic Application Security Testing):** анализ «черного ящика». Тестирование работающего приложения через внешние интерфейсы (HTTP, API, WebSocket). Современные инструменты реализуют **Autonomous Pentesting**, используя ИИ-агентов для имитации действий атакующего и исследования нестандартных путей выполнения API.
- **OAST (Out-of-band Application Security Testing):** расширение DAST, использующее внешние коллбэк-серверы для обнаружения «слепых» уязвимостей (Blind SQLi, Blind SSRF), которые не возвращают ответ непосредственно в HTTP-сессию.
- **IAST (Interactive Application Security Testing):** анализ «серого ящика». Гибридный метод, объединяющий статику и динамику. Стандартом 2026 года стал **Zero-Instrumentation IAST** на базе **eBPF**, который наблюдает за поведением приложения на уровне ядра без внедрения агентов в код.
- **SCA (Software Composition Analysis):** анализ сторонних библиотек и зависимостей. Современный SCA работает по принципу **Living SBOM**, отслеживая уязвимости в реальном времени.
- **ASPM (Application Security Posture Management):** мета-слой оркестрации, который собирает данные от всех AST-инструментов, устраняет дубликаты и приоритизирует риски на основе **анализа достижимости (Reachability Analysis)**.

## Базовые концепции

### Сравнительная матрица AST-технологий (2026)

| Критерий | SAST (AI-driven) | DAST (Autonomous) | IAST (eBPF-based) |
| :--- | :--- | :--- | :--- |
| **Принцип** | Белый ящик (статический) | Черный ящик (динамический) | Серый ящик (гибридный) |
| **Этап SDLC** | Написание кода, сборка | Тестирование, Staging, Prod | Тестирование и Runtime |
| **Точность** | Средняя (снижена за счет AI) | Высокая (минимум FP) | Максимальная (ядро видит всё) |
| **Покрытие** | 100% исходного кода | Только активные маршруты | Только исполняемый код |
| **Reachability** | Теоретическая (Data Flow) | Подтвержденная (внешняя) | Фактическая (Runtime вызовы) |
| **Скорость** | Высокая (инкрементально) | Низкая (полный скан) | Реальное время (мониторинг) |
| **AI поддержка** | Auto-Fix и анализ логики | Автономный фаззинг API | Детекция аномалий вызовов |

### Зоны ответственности и классы уязвимостей

Каждый метод эффективен против определенных классов угроз, описанных в **OWASP Top 10 (2025/2026)**:

- **Преимущества SAST:**
  - Поиск секретов и жестко закодированных ключей.
  - Обнаружение уязвимостей IaC (небезопасные Dockerfile, Helm-чарты).
  - Выявление атак на workflow (например, Cordyceps через небезопасные CI-события).
  - Анализ потоков данных (Taint Analysis) в коде, который редко вызывается.
- **Преимущества DAST:**
  - Обнаружение ошибок конфигурации сервера (неправильные заголовки CORS/CSP).
  - Проверка механизмов аутентификации и сессий в рантайме.
  - Поиск уязвимостей API (BOLA/IDOR) через перебор идентификаторов.
  - Выявление инфраструктурных дыр (уязвимые версии TLS, открытые порты).
- **IAST (eBPF) как связующее звено:**
  - Подтверждает, что уязвимый код, найденный SAST, реально исполняется и имеет доступ к чувствительным системным ресурсам (файлам, сети).

### Анализ достижимости (Reachability Analysis)

В 2026 году ключевой метрикой является не просто наличие уязвимости, а её достижимость. ASPM-платформа коррелирует данные:
1. **SAST** находит уязвимую функцию в коде.
2. **SCA** подтверждает, что эта функция принадлежит сторонней библиотеке.
3. **eBPF-IAST** сообщает, что в процессе тестирования эта функция ни разу не была вызвана.
4. **Результат:** Приоритет уязвимости снижается, блокировка пайплайна отменяется (VEX-аттестация).

## Практические сценарии

### Комбинированный конвейер безопасности (DevSecOps 2026)

Эффективная стратегия подразумевает распределение инструментов по этапам жизненного цикла:

1. **IDE (Shift Left):** AI-SAST плагины проверяют код в реальном времени. Ошибки исправляются до коммита через AI-предложения.
2. **PR / Merge Request:** Инкрементальный SAST и SCA. Анализируется только дифф. Блокировка происходит только при критических находках с высокой вероятностью.
3. **Review Environment:** Автономный DAST сканирует развернутую версию фичи. ИИ-агент автоматически авторизуется и исследует новые API-эндпоинты.
4. **Staging / QA:** eBPF-IAST собирает данные о выполнении кода во время работы автотестов.
5. **ASPM Correlation:** Консолидация всех отчетов в формате **SARIF** и принятие решения о релизе.

### Пример: Конфигурация GitLab CI с SARIF-интеграцией

Использование единого формата SARIF позволяет ASPM-платформам (например, Cycode или DefectDojo) бесшовно агрегировать результаты.

```yaml
stages: [test, security, deploy]

variables:
  ASPM_URL: "https://aspm.example.com"

# Статический анализ с выводом в SARIF
sast_ai:
  stage: security
  image: registry.example.com/sec/sast-ai:latest
  script:
    - sast-tool scan --format sarif --output report.sast.sarif
  artifacts:
    reports:
      sast: report.sast.sarif

# Динамический анализ на временном окружении
dast_autonomous:
  stage: security
  needs: ["deploy_review"]
  image: registry.example.com/sec/dast-ai:latest
  script:
    - dast-agent --target $REVIEW_URL --auth-mode oidc --format sarif --out report.dast.sarif
  artifacts:
    reports:
      dast: report.dast.sarif

# Синхронизация с ASPM для корреляции
aspm_sync:
  stage: security
  needs: ["sast_ai", "dast_autonomous"]
  script:
    - curl -X POST -F "file=@report.sast.sarif" $ASPM_URL/upload
    - curl -X POST -F "file=@report.dast.sarif" $ASPM_URL/upload
    - ./check-quality-gate.sh --project $CI_PROJECT_ID
```

## Дополнительная информация

### AI-Driven Remediation: автоисправление уязвимостей

В 2026 году SAST-инструменты не просто указывают на строку кода, а генерируют **Remediation PR**.
- **Процесс:** ИИ анализирует контекст уязвимости, подбирает безопасный паттерн (например, заменяет конкатенацию на параметризованный запрос), создает новую ветку и запускает юнит-тесты для проверки отсутствия регрессий.
- **Преимущество:** Сокращение времени MTTR (Mean Time To Repair) с дней до минут.

### Рекомендации по выбору и настройке

- **SAST:** Выбирайте инструменты с поддержкой семантического анализа. Избегайте «шумных» сканеров, которые не учитывают контекст (например, наличие фильтрации на входе).
- **DAST:** Для современных Single Page Applications (SPA) и микросервисов необходимы инструменты, умеющие работать с OpenAPI/Swagger схемами и поддерживающие состояние (stateful scanning).
- **Ресурсы:** SAST дешевле в эксплуатации, так как не требует инфраструктуры для запуска приложения. DAST требует выделенных мощностей и настройки тестовых данных.
