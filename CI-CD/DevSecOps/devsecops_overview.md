# DevSecOps: обзор методологии

## Определения

**DevSecOps (Development, Security, Operations)** — методология интеграции задач безопасности на каждом этапе жизненного цикла разработки программного обеспечения (SDLC — Software Development Life Cycle), обеспечивающая комплексный подход к защите.

**SAST (Static Application Security Testing — статическое тестирование безопасности приложений)** — метод анализа безопасности, проверяющий исходный код или бинарные файлы приложения без его запуска. Подробно: [SAST](./sast_overview.md).

**DAST (Dynamic Application Security Testing — динамическое тестирование безопасности приложений)** — метод анализа безопасности работающего приложения через его внешние интерфейсы. Подробно: [DAST](./dast_overview.md).

## Основные концепции

### Принципы DevSecOps

- **Shift Left (Сдвиг влево):** Раннее внедрение проверок безопасности, начиная с этапов написания кода и открытия Pull Request / Merge Request (PR/MR).
- **Автоматизация:** Встраивание автоматических сканеров безопасности в конвейер непрерывной интеграции и доставки (CI/CD).
- **Непрерывность:** Регулярное выполнение проверок на всех этапах жизненного цикла приложения.
- **Комплексность:** Сочетание различных методов анализа (SAST, DAST, SCA), управления секретами и защиты инфраструктуры.

### Инструменты и классификации

- **Инструменты статического анализа:** Checkov (анализ IaC — Infrastructure as Code), SonarQube, Bandit (Python), Semgrep, gosec (Go).
- **Инструменты динамического анализа:** OWASP ZAP, Burp Suite.
- **Сетевой контроль (CI-раннеры):** [Harden-Runner](../../Github_CI/network-security.md) (GitHub Actions).
- **Классификации уязвимостей:** CWE (Common Weakness Enumeration — общий перечень типов программных уязвимостей), CVE (Common Vulnerabilities and Exposures — общеизвестные уязвимости и дефекты информационной безопасности).

## Практические сценарии

### Внедрение в CI/CD конвейер

Основным практическим сценарием DevSecOps является настройка автоматизированных проверок, которые блокируют продвижение кода при обнаружении критических проблем.

**Типовой процесс:**

1. Анализ кода (SAST) при создании Merge Request.
2. Проверка зависимостей на известные уязвимости (SCA — Software Composition Analysis).
3. Динамическое сканирование (DAST) после развертывания на тестовом окружении.
4. Установка порогов качества (Quality Gates) для автоматического провала сборки.

Подробные примеры конфигураций и скриптов для различных систем (GitLab CI, Jenkins) приведены в [руководстве по интеграции безопасности](./sast_dast_cicd_integration.md).

## Дополнительная информация

### Преимущества подхода

- Сокращение стоимости исправления уязвимостей за счет их раннего обнаружения.
- Повышение общей безопасности продукта без значительного замедления темпов разработки.
- Прозрачность состояния безопасности для всех участников команды.
