# DevSecOps — обзор методологии

**Reliability Score: 10** (SSoT + Web Verification 2026: актуализировано на основе стандартов ASPM, AI-driven Security и Living SBOM)

## Определения

**DevSecOps (Development, Security, Operations)** — методология интеграции практик безопасности на всех этапах жизненного цикла разработки программного обеспечения (**SDLC — Software Development Life Cycle**). В 2026 году DevSecOps перешел от разрозненных сканеров к единой экосистеме управления рисками.

**ASPM (Application Security Posture Management)** — центральная категория инструментов 2026 года, которая консолидирует данные из всех AST-сканеров, устраняет дубликаты и приоритизирует уязвимости на основе **достижимости (Reachability Analysis)**.

**AST (Application Security Testing)** — методы тестирования безопасности, дополненные ИИ:
- **SAST (Static AST):** анализ кода с использованием ИИ для семантического понимания и авто-исправлений. Подробно: [SAST](./sast_overview.md).
- **DAST (Dynamic AST):** автономный ИИ-пентестинг работающего приложения. Подробно: [DAST](./dast_overview.md).
- **SCA (Software Composition Analysis):** анализ зависимостей через концепцию **Living SBOM** и VEX-отчетов.
- **IAST (Interactive AST):** рантайм-анализ, в 2026 году реализуемый через **eBPF** без изменения кода приложения.

**Supply Chain Security 2.0** — комплексная защита цепочки поставок, включающая проверку целостности (SLSA), аттестации и подпись всех артефактов.

## Базовые концепции

### Принципы DevSecOps (2026)

- **Shift Left 2.0:** Безопасность в IDE через AI-копилотов, блокирующих уязвимости до коммита.
- **Reachability-First:** Приоритизация только тех уязвимостей, которые физически могут быть исполнены в рантайме.
- **Policy as Code (PaC):** Использование Kyverno или OPA для принудительного соблюдения политик на уровне кластера и IaC.
- **Auto-Remediation:** Автоматическая генерация и валидация ИИ-агентами Pull Request с исправлениями безопасности.
- **NHI Security (Non-Human Identities):** Защита и аудит прав доступа ИИ-агентов и сервисных аккаунтов.

### Инструменты и классификации (2026)

| Категория | Инструменты | Назначение |
| :--- | :--- | :--- |
| **ASPM** | Cycode, Apiiro, Snyk AppRisk | Оркестрация и корреляция всех находок безопасности. |
| **SAST** | Snyk DeepCode, Checkmarx Fusion | Семантический анализ кода с поддержкой ИИ. |
| **SCA / SBOM** | Trivy, Grype, Syft | Работа с Living SBOM и VEX-анализом. |
| **IaC Security** | Checkov, Terrascan, KICS | Проверка Terraform, Helm и Dockerfile. |
| **Secret Scan** | Gitleaks, TruffleHog | Поиск секретов в Git и Slack/Jira (MCP-векторы). |
| **DAST** | XBOW, Penligent, Nuclei | Автономный пентестинг и API Security. |
| **Runtime Sec** | Falco, Tetragon (eBPF) | Обнаружение аномалий в ядре без оверхеда. |
| **AI Security** | Giskard, Lakera | Тестирование LLM на инъекции и галлюцинации. |

**Классификации и стандарты:**
- **OWASP Top 10 CI/CD (2025):** риски инфраструктуры доставки.
- **SLSA (Supply-chain Levels for Software Artifacts):** уровни защиты цепочки поставок.
- **VEX (Vulnerability Exploitability eXchange):** статус эксплуатируемости уязвимостей.

## Практические сценарии

### Жизненный цикл безопасности (DevSecOps SDLC 2026)

1.  **Написание кода (IDE):** AI-копилот с встроенным SAST блокирует уязвимости «на лету».
2.  **Pull Request / Merge Request:**
    *   **Incremental SAST:** анализ только диффа изменений.
    *   **Living SBOM Update:** автоматическое обновление графа зависимостей.
    *   **Auto-Fix:** ИИ-агент создает коммит с исправлением найденных багов.
3.  **Сборка (Build):**
    *   **Attestation:** подпись образа через Sigstore/Cosign.
    *   **Vulnerability Scan:** проверка базового образа на Zero-day.
4.  **Развертывание (Deploy):**
    *   **Admission Control:** Kyverno проверяет подпись артефакта и отсутствие Critical CVE.
    *   **ASPM Correlation:** подтверждение того, что уязвимость из PR не «всплыла» в стейджинге.
5.  **Эксплуатация (Run):**
    *   **eBPF Runtime Monitoring:** отслеживание аномальных системных вызовов.
    *   **Dynamic SBOM:** сопоставление запущенных библиотек в памяти с реестром уязвимостей.

Подробные примеры — в [руководстве по интеграции безопасности](./sast_dast_cicd_integration.md).

## Дополнительная информация

### Основные вызовы при внедрении (2026)

1.  **AI Hallucinations:** Риск внесения новых ошибок при использовании ИИ для автоматического исправления кода.
2.  **Alert Fatigue (Усталость от алертов):** Несмотря на ASPM, количество событий безопасности растет. Требуется жесткая приоритизация.
3.  **NHI Governance:** Управление тысячами токенов и прав доступа для ИИ-агентов.

### Метрики эффективности

- **Reachability Rate:** Процент уязвимостей, которые подтверждены как эксплуатируемые в рантайме (цель — снижение этого показателя).
- **MTTR (Mean Time to Remediate):** Среднее время от обнаружения до деплоя исправленной версии.
- **AI Fix Accuracy:** Точность автоматических исправлений, сгенерированных ИИ (процент фиксов, принятых разработчиками).
- **Security Debt (Безопасный долг):** Объем неисправленных критических уязвимостей в активных сервисах.
