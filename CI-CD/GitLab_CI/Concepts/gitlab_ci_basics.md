# Основы GitLab CI/CD

## Определения

*   **Конвейер (Pipeline)** — это высокоуровневая структура, которая определяет полный цикл CI/CD. Конвейеры состоят из этапов и задач и запускаются автоматически при коммитах, создании Merge Request или по расписанию.

*   **Этапы (Stages)** — группируют задания (jobs) и определяют порядок их выполнения. Задания в одном этапе выполняются параллельно, а сами этапы — последовательно.

*   **Задачи (Jobs)** — отдельные независимые задачи, которые выполняют определенный набор команд (скриптов) для выполнения таких действий, как сборка, тестирование или развертывание.

*   **`.gitlab-ci.yml`** — это YAML-файл в корне репозитория, который является единой точкой конфигурации для всех компонентов конвейера.

*   **Скрипты (Script)** — набор shell-команд, которые выполняет GitLab Runner в рамках одной задачи.

*   **GitLab CI/CD** — это встроенный в GitLab инструмент для автоматизации всех этих процессов.

*   **Принцип DRY (Don't Repeat Yourself)** — подход к разработке, направленный на снижение повторения информации. В контексте GitLab CI это означает создание переиспользуемых компонентов пайплайнов.

## Основные концепции

### Файл `.gitlab-ci.yml`

*   **Имя файла:** Имя `.gitlab-ci.yml` является обязательным.
*   **Расположение:** Файл должен находиться в корневой директории репозитория.
*   **Формат:** Используется синтаксис YAML. Важно использовать пробелы для отступов, а не табы.

GitLab автоматически обнаруживает этот файл и запускает пайплайны при коммитах в репозиторий.

### Ключевые слова

#### `stages`

Определяет последовательность выполнения этапов. Следующий этап начнется только после успешного завершения всех задач предыдущего.
*Пример:* `lint`, `test`, `build`, `deploy`.

#### `script`

Основной блок команд, которые выполняются в задаче. Если любая из команд завершается с ошибкой, задача помечается как неуспешная.

#### `before_script` и `after_script`

*   `before_script`: выполняет команды **перед** основным `script` в той же shell-сессии. Если `before_script` завершается с ошибкой, задача считается проваленной, и основной `script` не выполняется. Переменные, определенные здесь, доступны в `script`.
*   `after_script`: выполняет команды **после** `script`, даже если тот завершился неудачно. Выполняется в **отдельной** shell-сессии, поэтому переменные из `script` и `before_script` в нем недоступны. Не влияет на итоговый статус задачи.

### Механизмы переиспользования (DRY)

GitLab CI предоставляет мощные инструменты для следования принципу DRY:

*   **`extends`**: Позволяет задаче наследовать конфигурацию от другой.
*   **YAML Anchors (`&`) и Aliases (`*`)**: Стандартный механизм YAML для повторного использования фрагментов кода.
*   **`!reference`**: Специальный тег GitLab CI для ссылки на другие элементы в конфигурации. [Предпочтительнее YAML якорей](../Advanced/gitlab_ci_reusable_pipelines.md), так как лучше поддерживается линтером.
*   **`include`**: Включает конфигурацию из других файлов (локальных, удаленных или из других проектов).
*   **CI/CD Components**: Позволяют создавать версионируемые и переиспользуемые модули пайплайнов.

Подробное описание этих механизмов и их практическое применение можно найти в статье:
*   [Создание переиспользуемых и композитных пайплайнов](../Advanced/gitlab_ci_reusable_pipelines.md)

## Практические сценарии

### Пример базовой структуры `.gitlab-ci.yml`

```yaml
stages:
  - build
  - test

build_job:
  stage: build
  script:
    - echo "Performing build..."
    - build_command

test_job_lint:
  stage: test
  script:
    - echo "Running linter..."
    - linter_command

test_job_unit:
  stage: test
  script:
    - echo "Running unit tests..."
    - unit_test_command
```

## Дополнительная информация

### Встроенный CI Линтер (CI Lint)

GitLab предоставляет встроенный валидатор для проверки синтаксиса `.gitlab-ci.yml`. Он помогает находить синтаксические ошибки до коммита.

*   **Расположение:** `CI/CD` -> `Editor` в веб-интерфейсе GitLab (в старых версиях `Pipelines` -> `CI Lint`).
*   **Ключевая особенность:** При использовании `include` и `extends` линтер отображает **полностью "развернутую"** конфигурацию, что является незаменимым инструментом для отладки сложных пайплайнов.
