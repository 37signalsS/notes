# Основы GitLab CI/CD

## Определения

Иерархия компонентов в GitLab CI/CD строится по принципу "от общего к частному".

* **[Конвейер (Pipeline)](https://docs.gitlab.com/ee/ci/pipelines/)**: Высокоуровневая структура, которая определяет полный цикл CI/CD. Состоит из этапов и запускается по различным событиям (коммит, Merge Request, расписание).

* **[Этап (Stage)](https://docs.gitlab.com/ee/ci/yaml/#stages)**: Группирует задачи и определяет порядок их выполнения. Все задачи одного этапа выполняются параллельно, а сами этапы — последовательно.

* **[Задача (Job)](https://docs.gitlab.com/ee/ci/jobs/)**: Минимальная единица работы. Выполняет определенный набор команд (скриптов) для сборки, тестирования или развертывания.

## Основные концепции

### Файл `.gitlab-ci.yml`

Это YAML-файл в корне репозитория, который является единой точкой конфигурации для всего конвейера. GitLab автоматически обнаруживает его и выполняет описанные в нем инструкции.

### Ключевые слова для структуры

* **`stages`**: Определяет последовательность выполнения этапов. Следующий этап начнется только после успешного завершения всех задач предыдущего.
* **`image`**: Указывает Docker-образ, который будет использоваться для выполнения задачи. Может быть задан глобально или для конкретной задачи.
* **`variables`**: Определяет переменные окружения, доступные внутри задач. Может быть задан глобально или для конкретной задачи.

### Ключевые слова для задач

* **`stage`**: Присваивает задачу определенному этапу из списка `stages`.
* **`script`**: Основной и обязательный блок. Содержит shell-команды, которые выполняет Runner.
* **`before_script`**: Выполняет команды **перед** основным `script`. Если `before_script` завершается с ошибкой, задача считается проваленной, и `script` не выполняется.
* **`after_script`**: Выполняет команды **после** `script`, даже если тот завершился неудачно. Не влияет на итоговый статус задачи и выполняется в отдельной shell-сессии.

### Механизмы переиспользования (DRY)

Для избежания дублирования кода GitLab CI предлагает несколько механизмов, таких как `extends`, `!reference` и `include`.

Подробное описание этих механизмов см. в статье: **[Создание переиспользуемых и композитных пайплайнов](../Advanced/gitlab_ci_reusable_pipelines.md)**.

## Практические сценарии

### Сценарий 1: Базовый пайплайн "Hello World"

Этот пример демонстрирует базовую структуру с двумя этапами. Задачи `test:lint` и `test:unit` на этапе `test` будут запущены параллельно после успешного завершения `build_job`.

```yaml
# Определение последовательности этапов
stages:
  - build
  - test

# Глобальные переменные, доступные во всех задачах
variables:
  APP_VERSION: "1.0.0"

build_job:
  stage: build
  script:
    - echo "Building the app version $APP_VERSION..."
    - sleep 10 # Имитация сборки
    - echo "Build successful."

test:lint:
  stage: test
  script:
    - echo "Running linter..."
    - sleep 5
    - echo "No linting errors found."

test:unit:
  stage: test
  script:
    - echo "Running unit tests..."
    - sleep 15
    - echo "All tests passed."
```

### Сценарий 2: Использование `before_script` для подготовки

`before_script` идеально подходит для подготовительных команд, которые должны выполняться перед каждой задачей.

```yaml
# Задаем образ по умолчанию для всех задач
default:
  image: alpine:3.19

stages:
  - deploy

deploy:
  stage: deploy
  before_script:
    # Эти команды выполнятся перед основным скриптом
    - echo "Logging in to the registry..."
    - apk add --no-cache curl
    - echo "Login successful."
  script:
    - echo "Deploying the application..."
    - curl http://example.com/deploy-hook
  after_script:
    # Эта команда выполнится в любом случае
    - echo "Logging out from the registry."
```

## Дополнительная информация

* **CI Lint Tool**: Для проверки синтаксиса `.gitlab-ci.yml` перед коммитом используйте встроенный валидатор. Он находится в UI GitLab в разделе `CI/CD` -> `Editor`. Это незаменимый инструмент для отладки, так как он показывает полностью "развернутую" конфигурацию со всеми `include`.

* **Полный справочник ключевых слов**: Детальное описание всех доступных ключевых слов и их опций можно найти в [официальной документации GitLab](https://docs.gitlab.com/ee/ci/yaml/index.html).
