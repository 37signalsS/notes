# Переменные и Секреты в GitLab CI/CD

## Определения

*   **Переменные CI/CD** — это динамические значения, которые можно передавать в пайплайн GitLab CI/CD для управления его поведением, конфигурацией или для хранения чувствительных данных (секретов).

*   **Защищенная переменная (`Protected`)** — переменная, доступная только в пайплайнах, запускаемых для защищенных веток или тегов. Используется для хранения секретов, связанных с production-средами.

*   **Маскированная переменная (`Masked`)** — переменная, значение которой скрывается в логах выполнения задач, предотвращая случайную утечку. Для маскирования значение должно быть однострочным, без пробелов, длиной не менее 8 символов.

*   **Переменная типа `File`** — переменная, содержимое которой GitLab Runner записывает во временный файл, а сама переменная хранит путь к этому файлу. Используется для многострочных секретов, таких как SSH-ключи или `.pem` файлы.

*   **Предопределенные переменные** — набор переменных, которые GitLab автоматически предоставляет в каждом пайплайне, содержащих информацию о коммите, проекте, пайплайне и т.д.

*   **Внешние хранилища секретов** — сторонние системы (например, HashiCorp Vault), используемые для безопасного централизованного хранения и управления секретами, с которыми GitLab CI может интегрироваться для получения секретов "на лету".

## Основные концепции

### Объявление и атрибуты переменных

Переменные определяются в настройках проекта (`Settings > CI/CD > Variables`) и могут иметь следующие характеристики:

*   **Типы переменных:**
    *   **`Variable`**: Стандартная пара "ключ-значение", передаваемая как переменная окружения.
    *   **`File`**: Содержимое переменной сохраняется во временный файл на Runner'е, а в пайплайн передается путь к этому файлу. Идеально для сертификатов, ключей и других многострочных данных.

*   **Атрибуты переменных:**
    *   **`Protected`**: Ограничивает доступ к переменной только для пайплайнов, запущенных в [защищенных ветках](https://docs.gitlab.com/ee/user/project/protected_branches.html) или тегах.
    *   **`Masked`**: Скрывает значение переменной в логах. Требует, чтобы значение было однострочным, без пробелов и длиной минимум 8 символов.

### Предопределенные переменные GitLab CI

GitLab автоматически инжектирует множество предопределенных переменных, начинающихся с префикса `CI_`. Они предоставляют контекст о текущем пайплайне, коммите и проекте.

**Наиболее часто используемые:**

*   `CI=true`: Индикатор того, что скрипт выполняется в среде CI/CD.
*   `CI_COMMIT_BRANCH`: Имя текущей ветки.
*   `CI_COMMIT_SHORT_SHA`: Короткий хеш (8 символов) текущего коммита.
*   `CI_PROJECT_NAME`: Имя текущего проекта.
*   `CI_PIPELINE_ID`: Уникальный идентификатор текущего пайплайна.
*   `CI_JOB_TOKEN`: Временный токен, используемый для аутентификации при взаимодействии с GitLab API, Container Registry или другими репозиториями в рамках того же проекта.

### Продвинутые техники управления секретами

#### 1. Шифрование на уровне приложения (например, `ansible-vault`)

*   **Принцип:** Секреты шифруются с помощью внешних инструментов (`ansible-vault`) и сохраняются в зашифрованном виде в переменных GitLab CI. Пароль для расшифровки хранится отдельно и безопасно (например, в Kubernetes-секрете). Пайплайн дешифрует переменные "на лету" во время выполнения.
*   **Преимущества:** Позволяет скрыть содержимое секретов от лиц, имеющих доступ к GitLab, но не к хранилищу пароля.
*   **Недостатки:** Требует ручного управления процессом шифрования/дешифрования и хранением ключа.

#### 2. Интеграция с HashiCorp Vault

*   **Принцип:** GitLab CI/CD имеет встроенную поддержку интеграции с HashiCorp Vault. Во время выполнения задачи Runner аутентифицируется в Vault (используя уникальный JWT-токен), получает временный доступ и запрашивает необходимые секреты напрямую из Vault. Секреты никогда не хранятся в GitLab.
*   **Преимущества:**
    *   **Высокая безопасность:** Секреты динамически извлекаются и имеют короткий срок жизни.
    *   **Централизация:** Единое место для управления всеми секретами, политиками доступа и аудита.
    *   **Динамические секреты:** Возможность генерации учетных данных (например, для БД) с ограниченным сроком действия.
*   **Практическое применение:** Для детального пошагового руководства по настройке смотрите [Практическое руководство: Интеграция GitLab CI с HashiCorp Vault](../GitLab_CI/Tutorials/vault_kubernetes_integration.md).
