# Централизация шаблонов через `include:project`

## Определения

**`include:project`** — механизм GitLab CI для подключения внешних YAML-файлов из других проектов. Позволяет централизованно управлять шаблонами пайплайнов.

**Контекст этапа:** Решение проблемы дублирования кода (boilerplate) через вынос общей конфигурации в центральный репозиторий шаблонов.

## Базовые концепции

### Архитектура централизованного подхода

```
┌─────────────────────────────────────────────────────────┐
│  Репозиторий шаблонов: group/ci-templates               │
│  └── docker-build.yml (централизованная конфигурация)   │
└─────────────────────────────────────────────────────────┘
                          ↓ include:project
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  Проект 1    │  │  Проект 2    │  │  Проект N    │
│  .gitlab-ci  │  │  .gitlab-ci  │  │  .gitlab-ci  │
└──────────────┘  └──────────────┘  └──────────────┘
```

### Типы `include`

| Тип | Синтаксис | Сценарий |
| :--- | :--- | :--- |
| **Project** | `include:project` | Шаблоны из другого проекта |
| **Local** | `include:local` | Файлы внутри одного проекта |
| **Remote** | `include:remote` | Файлы по URL |
| **Template** | `include:template` | Шаблоны GitLab (CI/CD Catalog) |

### Версионирование шаблонов

```yaml
include:
  - project: 'group/ci-templates'
    ref: v1.0.0  # Тег (рекомендуется)
    file: '/docker-build.yml'
```

**Best Practice:** Используйте теги (`ref: v1.0.0`) вместо веток для фиксации версии шаблона.

## Практические сценарии

### Создание репозитория шаблонов

**Репозиторий:** `group/ci-templates`

**Файл:** `docker-build.yml`

```yaml
# ci-templates/docker-build.yml
build-docker-image:
  stage: docker-build
  image: docker:24.0
  services:
    - docker:24.0-dind
  variables:
    DOCKER_TLS_CERTDIR: "/certs"
    IMAGE_TAG: $CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_JOB_TOKEN $CI_REGISTRY
    - docker build -t $IMAGE_TAG .
    - docker push $IMAGE_TAG
```

### Использование в проекте

```yaml
# .gitlab-ci.yml проекта
stages:
  - docker-build

include:
  - project: 'group/ci-templates'
    ref: v1.0.0
    file: '/docker-build.yml'
```

### Преимущества подхода

| Преимущество | Описание |
| :--- | :--- |
| **Централизация** | Изменения вносятся в одном месте |
| **Стандартизация** | Все проекты используют одинаковую конфигурацию |
| **Упрощение** | `.gitlab-ci.yml` проекта содержит только `include` |

### Новые проблемы

| Проблема | Описание |
| :--- | :--- |
| **Отсутствие гибкости** | Невозможно кастомизировать шаблон под конкретный проект |
| **Жёсткая конфигурация** | Все проекты вынуждены использовать одинаковые `image`, `variables` |
