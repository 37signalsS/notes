# Централизация шаблонов через `include:project`

## Определения

**Централизация шаблонов** — второй этап эволюции pipelines, заключающийся в выносе повторяющейся конфигурации в отдельный репозиторий.

**Контекст этапа:** Решение проблемы дублирования кода (boilerplate) через механизм [include:project](../include_keyword.md#includeproject).

## Базовые концепции

### Архитектура централизованного подхода

```
┌─────────────────────────────────────────────────────────┐
│  Репозиторий шаблонов: group/ci-templates               │
│  └── docker-build.yml (централизованная конфигурация)   │
└─────────────────────────────────────────────────────────┘
                          |
                          | include:project
                          V
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  Проект 1    │  │  Проект 2    │  │  Проект N    │
│  .gitlab-ci  │  │  .gitlab-ci  │  │  .gitlab-ci  │
└──────────────┘  └──────────────┘  └──────────────┘
```

### Принцип работы

Вместо копирования 20+ строк YAML в каждый проект разработчик подключает один файл из центрального репозитория. Это обеспечивает централизованное управление логикой `build` или `deploy`.

**Важно:** Для стабильности необходимо использовать теги (`ref: v1.0.0`) при подключении шаблонов.

## Практические сценарии

### Настройка центрального репозитория

**Репозиторий:** `group/ci-templates`
**Файл:** `docker-build.yml`

```yaml
# ci-templates/docker-build.yml
build-docker-image:
  stage: docker-build
  image: docker:24.0
  services:
    - docker:24.0-dind
  variables:
    DOCKER_TLS_CERTDIR: "/certs"
    IMAGE_TAG: $CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_JOB_TOKEN $CI_REGISTRY
    - docker build -t $IMAGE_TAG .
    - docker push $IMAGE_TAG
```

### Подключение в целевом проекте

```yaml
# .gitlab-ci.yml проекта
stages:
  - docker-build

include:
  - project: 'group/ci-templates'
    ref: v1.0.0
    file: '/docker-build.yml'
```

### Преимущества и недостатки

| Характеристика | Описание |
| :--- | :--- |
| **Преимущества** | Централизованное управление версиями, стандартизация pipelines, чистый `.gitlab-ci.yml`. |
| **Недостатки** | Отсутствие гибкости (нельзя поменять одну строку в шаблоне), "жёсткая" конфигурация. |
