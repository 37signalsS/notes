# Установка Self-Hosted GitLab CE с помощью Docker

## Определения

* **GitLab CE (Community Edition)**: Бесплатная и открытая версия платформы GitLab, предназначенная для самостоятельного размещения на собственных серверах (self-hosted).
* **Self-Hosted**: Модель развертывания, при которой ПО устанавливается и обслуживается на собственной инфраструктуре.
* **Docker-образ GitLab**: Официально поддерживаемый, предварительно сконфигурированный пакет, содержащий все компоненты GitLab (Nginx, PostgreSQL, Redis и т.д.).

## Основные концепции

* **Файл конфигурации `gitlab.rb`**: Единый источник истины для настройки GitLab. Находится по пути `/etc/gitlab/gitlab.rb` внутри контейнера.
* **Внешний URL (`external_url`)**: Критически важный параметр в `gitlab.rb`, определяющий основной адрес GitLab. Используется для генерации ссылок и интеграций.
* **Сохранение данных (Data Volumes)**: Ключевые директории из контейнера монтируются на хост-машину для обеспечения сохранности данных (`/etc/gitlab`, `/var/log/gitlab`, `/var/opt/gitlab`).

## Пошаговая установка

### Предварительные требования

* **Сервер Linux** (например, Ubuntu 22.04) с `sudo` доступом. Рекомендуется минимум 4 ядра CPU и 4 ГБ RAM.
* **Установленный Docker**.
* **Доменное имя** (например, `gitlab.example.com`), DNS `A`-запись которого указывает на публичный IP-адрес вашего сервера.
* **Открытые порты** в брандмауэре: `80` (для HTTP и Let's Encrypt) и `443` (для HTTPS).

### Шаг 1: Подготовка директорий на хосте

Вся конфигурация, логи и данные GitLab будут храниться в `/srv/gitlab` на хост-машине. Это упрощает управление и резервное копирование.

```bash
sudo mkdir -p /srv/gitlab/{config,logs,data}
sudo chown -R $(whoami) /srv/gitlab/
```

### Шаг 2: Создание базовой конфигурации

1. Создайте файл `gitlab.rb`:

    ```bash
    touch /srv/gitlab/config/gitlab.rb
    ```

2. Задайте основной URL вашего будущего инстанса. **Замените `gitlab.example.com` на ваше доменное имя.**

    ```bash
    echo "external_url 'https://gitlab.example.com'" | tee /srv/gitlab/config/gitlab.rb
    ```

    *Если домен доступен извне, GitLab автоматически попытается выпустить SSL-сертификат от Let's Encrypt.*

### Шаг 3: Запуск Docker-контейнера GitLab

```bash
sudo docker run --detach \
  --hostname gitlab.example.com \
  --publish 443:443 --publish 80:80 \
  --name gitlab \
  --restart always \
  --volume /srv/gitlab/config:/etc/gitlab \
  --volume /srv/gitlab/logs:/var/log/gitlab \
  --volume /srv/gitlab/data:/var/opt/gitlab \
  gitlab/gitlab-ce:16.11.1-ce.0
```

**Разбор команды:**

* `--detach`: Запуск в фоновом режиме.
* `--hostname`: Имя хоста контейнера (должно совпадать с доменом).
* `--publish`: Проброс портов 443 (HTTPS) и 80 (HTTP) с хоста на контейнер.
* `--name gitlab`: Удобное имя для контейнера.
* `--restart always`: Автоматический перезапуск контейнера при сбоях или после перезагрузки сервера.
* `--volume ...`: Монтирование директорий с хоста в контейнер для постоянного хранения данных.
* `gitlab/gitlab-ce:16.11.1-ce.0`: Используем актуальную, но **зафиксированную** версию образа.

### Шаг 4: Ожидание и проверка

Первый запуск GitLab может занять **5-15 минут**, так как происходит внутренняя конфигурация всех сервисов.

```bash
# Следим за логами в реальном времени
sudo docker logs -f gitlab
```

Процесс завершен, когда в логах прекратится активный вывод.

### Шаг 5: Получение пароля администратора

При первом запуске GitLab генерирует случайный пароль для пользователя `root`.

```bash
# Пароль можно получить только после полного запуска всех сервисов
sudo docker exec gitlab cat /etc/gitlab/initial_root_password
```

**Внимание:** Этот файл удаляется после первой реконфигурации. Скопируйте пароль — это ваш единственный шанс его получить.

### Шаг 6: Первый вход

1. Откройте в браузере ваш домен (`https://gitlab.example.com`).
2. Войдите, используя логин `root` и пароль, полученный на предыдущем шаге.
3. Система немедленно потребует сменить пароль. Сделайте это.

## Рекомендации по администрированию

* **Работа под `root`**: Используйте `root` только для первоначальной настройки. Для повседневных задач создайте отдельного пользователя с правами администратора.
* **Регистрация пользователей**: Отключите публичную регистрацию в **Admin Area > Settings > General > Sign-up restrictions**, если ваш GitLab не является публичным.
* **Безопасность**: Включите принудительную двухфакторную аутентификацию (2FA) для всех пользователей.
* **GitLab Flow**: Ознакомьтесь с [практическим руководством по использованию GitLab Flow](./gitlab_flow.md) для оптимизации процессов разработки.
* **Резервное копирование**: Настройте регулярное резервное копирование с помощью встроенной утилиты `gitlab-backup`.
* **Обновления**: Регулярно обновляйте ваш экземпляр GitLab до последних версий.
