# Установка и администрирование Self-Hosted GitLab CE

## Определения

-   **GitLab CE (Community Edition)**: Бесплатная и открытая версия платформы GitLab, предназначенная для самостоятельного размещения на собственных серверах (self-hosted). Она предоставляет полный набор инструментов для DevOps-цикла: от управления Git-репозиториями до CI/CD, мониторинга и многого другого.
-   **Self-Hosted**: Модель развертывания, при которой организация самостоятельно устанавливает, настраивает и обслуживает программное обеспечение на своей инфраструктуре, в отличие от использования облачного SaaS-решения.
-   **Docker-образ GitLab**: Официально поддерживаемый, предварительно сконфигурированный пакет, содержащий все компоненты GitLab (Nginx, PostgreSQL, Redis, и т.д.), готовый к запуску в виде Docker-контейнера.

## Основные концепции

-   **Файл конфигурации `gitlab.rb`**: Единый источник истины для настройки всех аспектов работы GitLab. Этот файл находится внутри контейнера по пути `/etc/gitlab/gitlab.rb`. При запуске контейнера GitLab выполняет команду `gitlab-ctl reconfigure`, которая применяет все настройки из этого файла к внутренним сервисам.
-   **Внешний URL (`external_url`)**: Критически важный параметр в `gitlab.rb`, который определяет основной адрес, по которому будет доступен GitLab. Он используется для генерации всех ссылок, интеграции с Git и корректной работы CI/CD. Если домен доступен извне, GitLab автоматически пытается настроить HTTPS с помощью Let's Encrypt.
-   **Сохранение данных (Data Volumes)**: Для обеспечения сохранности данных при перезапуске или обновлении контейнера, ключевые директории из контейнера монтируются на хост-машину:
    -   `/etc/gitlab` (конфигурация): Содержит `gitlab.rb` и другие файлы настроек.
    -   `/var/log/gitlab` (логи): Логи всех сервисов GitLab.
    -   `/var/opt/gitlab` (данные): Базы данных, репозитории, артефакты и другие пользовательские данные.

## Практические сценарии

### Установка GitLab CE с помощью Docker

Это практическое руководство описывает пошаговый процесс развертывания self-hosted экземпляра GitLab CE на сервере с установленным Docker.

#### Шаг 1: Подготовка окружения на хост-машине

Вам понадобится сервер с установленным Docker и доменным именем, которое указывает на IP-адрес этого сервера.

1.  **Создайте рабочую директорию:** Вся конфигурация, логи и данные GitLab будут храниться здесь. Это упрощает управление и резервное копирование.
    ```bash
    sudo mkdir -p /srv/gitlab
    cd /srv/gitlab
    ```

2.  **Экспортируйте переменную окружения:** Это упростит последующие команды.
    ```bash
    export GITLAB_HOME=$(pwd)
    ```

#### Шаг 2: Подготовка конфигурационного файла `gitlab.rb`

1.  **Создайте файл `config/gitlab.rb` на хосте:**
    ```bash
    mkdir -p $GITLAB_HOME/config
    touch $GITLAB_HOME/config/gitlab.rb
    ```

2.  **Добавьте базовую конфигурацию:**
    ```bash
    # Замените 'gitlab.example.com' на ваше доменное имя
    echo "external_url 'https://gitlab.example.com'" | sudo tee $GITLAB_HOME/config/gitlab.rb
    ```

#### Шаг 3: Запуск Docker-контейнера GitLab

```bash
sudo docker run --detach \
  --hostname gitlab.example.com \
  --publish 443:443 --publish 80:80 \
  --name gitlab \
  --restart always \
  -v $GITLAB_HOME/config:/etc/gitlab \
  -v $GITLAB_HOME/logs:/var/log/gitlab \
  -v $GITLAB_HOME/data:/var/opt/gitlab \
  gitlab/gitlab-ce:14.8.6-ce.0
```

**Разбор команды:**
*   `--detach` (`-d`): Запускает контейнер в фоновом режиме.
*   `--hostname`: Устанавливает имя хоста контейнера (должно совпадать с доменом).
*   `--publish`: Пробрасывает порты 443 (HTTPS) и 80 (HTTP).
*   `--name gitlab`: Дает контейнеру удобное имя.
*   `--restart always`: Контейнер будет автоматически перезапускаться при сбоях и после перезагрузки сервера.
*   `-v ...`: Монтирует директории с хоста в контейнер для персистентного хранения данных.
*   `gitlab/gitlab-ce:14.8.6-ce.0`: Указывается конкретная версия GitLab Community Edition.

#### Шаг 4: Ожидание и проверка

Первый запуск GitLab может занять **от 5 до 15 минут**. Вы можете следить за процессом с помощью логов:
```bash
sudo docker logs -f gitlab
```
Дождитесь, пока в логах перестанут активно появляться новые сообщения.

#### Шаг 5: Получение пароля администратора

При первом запуске GitLab генерирует случайный пароль для пользователя `root`.

```bash
# Пароль можно получить только после полного запуска всех сервисов
sudo docker exec gitlab cat /etc/gitlab/initial_root_password
```
Скопируйте выведенный пароль. Этот файл автоматически удаляется после первой реконфигурации, поэтому получить пароль нужно как можно скорее.

#### Шаг 6: Первый вход

1.  Откройте в браузере ваш домен (`https://gitlab.example.com`).
2.  На странице входа введите:
    *   **Username:** `root`
    *   **Password:** Пароль, который вы скопировали на предыдущем шаге.
3.  Войдите в систему и сразу же смените пароль администратора.

## Дополнительная информация

### Лучшие практики администрирования GitLab

#### Управление пользователями и доступом

*   **Избегайте работы под `root`**: После установки создайте обычного пользователя с правами администратора для повседневной работы. Используйте `root` только для первоначальной настройки.
*   **Используйте функцию `Impersonate`**: Администраторы могут временно "входить" под учетной записью любого пользователя для отладки проблем с доступом или интерфейсом.
*   **Интеграция с IdP**: Для централизованного управления учетными записями настройте интеграцию с LDAP, Active Directory или другим SSO-провайдером.

#### Безопасность

*   **Отключите публичную регистрацию**: В разделе **Admin Area > Settings > General** снимите флажок `Sign-up enabled`, если ваш GitLab не является публичным.
*   **Принудительная 2FA**: Включите обязательное использование двухфакторной аутентификации для всех пользователей для повышения уровня безопасности.
*   **Ограничение доступа по IP**: Настройте список разрешенных IP-адресов для доступа к вашему экземпляру GitLab.
*   **Гранулярные права доступа**: Выдавайте пользователям минимально необходимые права. Для внешних подрядчиков используйте роли с ограниченным временем действия.

#### Оптимизация рабочего процесса

*   **Используйте GitLab Flow**: Ознакомьтесь с [практическим руководством по использованию GitLab Flow](./gitlab_flow.md), чтобы оптимизировать процессы разработки и ветвления.

#### Обслуживание и мониторинг

*   **Резервное копирование**: Настройте регулярное резервное копирование с помощью встроенной утилиты `gitlab-backup`.
*   **Обновления**: Регулярно обновляйте ваш экземпляр GitLab до последних версий, чтобы получать новые функции и исправления безопасности.
*   **Сборка мусора (Garbage Collection)**: Периодически запускайте сборку мусора в репозиториях для очистки ненужных объектов и уменьшения занимаемого дискового пространства.
