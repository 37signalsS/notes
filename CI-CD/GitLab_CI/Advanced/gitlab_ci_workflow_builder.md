### Определения

**Строительные блоки GitLab CI/CD** — это набор ключевых слов в файле `.gitlab-ci.yml`, которые позволяют конструировать пайплайны различной сложности, управляя потоком выполнения, передачей данных и эффективностью.

-   **`stages`**: Определяют высокоуровневую последовательность выполнения этапов (например, `build`, `test`, `deploy`). Задания внутри одного этапа выполняются параллельно.
-   **`jobs`**: Конкретные задачи, выполняемые Runner'ами. Каждое задание привязано к определённому этапу и содержит набор инструкций для выполнения.
-   **`artifacts`**: Механизм для сохранения результатов выполнения задания (собранные бинарные файлы, отчёты) и передачи их между заданиями, в том числе на разных этапах и Runner'ах.
-   **`cache`**: Механизм для кэширования файлов (например, зависимостей) между запусками пайплайнов для ускорения сборок.

### Основные концепции

#### Поток выполнения: `stages` и `jobs`

-   Порядок `stages` определяет логику всего пайплайна: переход к следующему этапу происходит только после успешного завершения всех заданий в текущем.
-   Все `jobs` внутри одного `stage` запускаются параллельно (если достаточно свободных Runner'ов).
-   Если хотя бы одно `job` в `stage` проваливается, по умолчанию весь пайплайн останавливается.

#### Передача данных: `artifacts`

Артефакты — это гарантированный способ передать данные между `jobs`. Они сохраняются на сервере GitLab после успешного завершения задания и доступны для скачивания как из UI, так и в последующих заданиях.

**Специализированные типы артефактов:**

-   **`artifacts:reports`**: Используется для интеграции отчетов в интерфейс GitLab, что позволяет визуализировать результаты.
    -   **`junit`**: Отчеты о тестах в формате JUnit XML. Отображаются на вкладке "Tests" в пайплайне.
    -   **`cobertura`**: Отчеты о покрытии кода. Отображаются в Merge Request.
    -   **`sast`**, **`dast`**, **`dependency_scanning`**: Отчеты о безопасности. Интегрируются в Security Dashboard.

    ```yaml
    test_job:
      stage: test
      script:
        - run_tests.sh
      artifacts:
        reports:
          junit: junit-report.xml
          cobertura: coverage.xml
    ```

-   **`artifacts:dotenv`**: Позволяет передавать переменные окружения между `jobs`. Файл формата `.env` загружается как артефакт, и все переменные из него автоматически становятся доступными в последующих `jobs`.

    ```yaml
    # Job 'setup'
    setup_job:
      stage: setup
      script:
        - echo "MY_VARIABLE=hello" > build.env
      artifacts:
        reports:
          dotenv: build.env

    # Job 'deploy'
    deploy_job:
      stage: deploy
      script:
        - echo $MY_VARIABLE # Выведет "hello"
      needs:
        - job: setup_job
          artifacts: true # Обязательно для получения dotenv артефакта
    ```

#### Ускорение сборок: `cache`

Кэш предназначен для ускорения повторных запусков пайплайнов путем сохранения файлов, таких как `node_modules` или `.m2`, между `jobs`.

-   **Отличие от артефактов:** Кэш не гарантирует наличие данных. Он может быть очищен в любой момент. Его основная цель — ускорение, а не передача критически важных результатов.
-   **Область видимости:** Кэш может быть общим для всех пайплайнов проекта.

Более подробную информацию о стратегиях кэширования, ключах и политиках см. в документе **[Кэширование в GitLab CI](../Advanced/gitlab_ci_caching.md)**.
