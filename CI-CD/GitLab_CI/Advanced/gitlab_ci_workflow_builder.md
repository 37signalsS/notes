# Конструктор рабочих процессов GitLab CI

> **Примечание:** Этот файл содержит краткую справку по базовым концепциям. Подробная информация доступна в связанных документах.

## Краткая справка

### Основные элементы

- **`stages`**: Определяют высокоуровневую последовательность выполнения этапов (например, `build`, `test`, `deploy`). Задания внутри одного этапа выполняются параллельно.
- **`jobs`**: Конкретные задачи, выполняемые Runner'ами. Каждое задание привязано к определённому этапу и содержит набор инструкций для выполнения.
- **`artifacts`**: Механизм для сохранения результатов выполнения задания (собранные бинарные файлы, отчёты) и передачи их между заданиями, в том числе на разных этапах и Runner'ах.
- **`cache`**: Механизм для кэширования файлов (например, зависимостей) между запусками пайплайнов для ускорения сборок.

### Поток выполнения

- Порядок `stages` определяет логику всего пайплайна: переход к следующему этапу происходит только после успешного завершения всех заданий в текущем.
- Все `jobs` внутри одного `stage` запускаются параллельно (если достаточно свободных Runner'ов).
- Если хотя бы одно `job` в `stage` проваливается, по умолчанию весь пайплайн останавливается.

### Передача данных: `artifacts`

Артефакты — это гарантированный способ передать данные между `jobs`. Они сохраняются на сервере GitLab после успешного завершения задания и доступны для скачивания как из UI, так и в последующих заданиях.

**Специализированные типы артефактов:**

- **`artifacts:reports`**: Используется для интеграции отчетов в интерфейс GitLab, что позволяет визуализировать результаты (тесты, покрытие кода, уязвимости).
- **`artifacts:dotenv`**: Позволяет передавать переменные окружения между `jobs` путем создания специального `.env` артефакта.

### Ускорение сборок: `cache`

Кэш предназначен для ускорения повторных запусков пайплайнов путем сохранения файлов, таких как `node_modules` или `.m2`, между `jobs`.

- **Отличие от артефактов:** Кэш не гарантирует наличие данных. Его основная цель — ускорение, а не передача критически важных результатов.
- **Область видимости:** Кэш может быть общим для всех пайплайнов проекта.

### Практические сценарии

#### Сценарий 1: Передача артефактов между стадиями

Этот пример показывает, как собрать приложение на стадии `build` и передать скомпилированный бинарный файл на стадию `test`.

```yaml
stages:
  - build
  - test

build_app:
  stage: build
  script:
    - echo "Building the application..."
    - echo "my-app-binary" > my-app
  artifacts:
    paths:
      - my-app # Сохраняем файл 'my-app' как артефакт

test_app:
  stage: test
  script:
    - echo "Testing the application..."
    - cat my-app # Файл 'my-app' автоматически загружен и доступен
  dependencies:
    - build_app # Явно указываем, что это задание зависит от артефактов 'build_app'
```

#### Сценарий 2: Интеграция отчетов о тестах и покрытии

Здесь `artifacts:reports` используется для загрузки в GitLab отчетов о результатах тестов (`junit`) и покрытии кода (`cobertura`), что позволяет видеть их прямо в интерфейсе Merge Request.

```yaml
test_job:
  stage: test
  script:
    - run_tests.sh # Этот скрипт генерирует junit-report.xml и coverage.xml
  artifacts:
    reports:
      junit: junit-report.xml
      cobertura: coverage.xml
```

#### Сценарий 3: Передача переменных окружения с помощью `dotenv`

Задание `setup_job` создает файл `build.env` и объявляет его `dotenv` артефактом. Переменные из этого файла (`MY_VARIABLE`) автоматически становятся доступны в последующих заданиях, таких как `deploy_job`.

```yaml
stages:
  - setup
  - deploy

setup_job:
  stage: setup
  script:
    - echo "MY_VARIABLE=hello-world" > build.env
    - echo "ANOTHER_VAR=123" >> build.env
  artifacts:
    reports:
      dotenv: build.env

deploy_job:
  stage: deploy
  script:
    - echo "Deploying with MY_VARIABLE=$MY_VARIABLE" # Выведет "Deploying with MY_VARIABLE=hello-world"
    - echo "ANOTHER_VAR is $ANOTHER_VAR" # Выведет "ANOTHER_VAR is 123"
  dependencies:
    - setup_job # Указываем зависимость от задания, создающего dotenv артефакт
```
