# Parent-child пайплайны

## Определения

**Parent-child pipeline** — downstream пайплайн, выполняемый в том же проекте, что и родительский. Используется для декомпозиции сложных конфигураций `.gitlab-ci.yml`.

## Основные концепции

### Характеристики и ограничения

- **Контекст выполнения:** Задачи дочернего пайплайна выполняются в том же проекте, с тем же `ref` и `commit SHA`, что и родительский.
- **Ограничение вложенности:** Максимальная глубина составляет два уровня (внук).
- **Видимость:** Дочерние пайплайны не отображаются в общем списке пайплайнов проекта, а видны только на странице родительского пайплайна.
- **Запуск:** Не могут быть запущены вручную, только через триггер в родительском пайплайне.
- **Ресурсы:** Используют те же раннеры и настройки, что и родительский пайплайн (с некоторыми [ограничениями по наследованию переменных](./variable_inheritance.md)).
- **Отмена:** Автоматически отменяются вместе с родительским пайплайном, если он настроен как `interruptible`.

## Практические сценарии

### Базовый пример

```yaml
# Родительский .gitlab-ci.yml
stages:
  - test
  - deploy

child-pipeline:
  stage: test
  trigger:
    include:
      - local: path/to/child-pipeline.yml
```

### Child pipeline конфигурация

```yaml
# path/to/child-pipeline.yml
stages:
  - test

run_tests:
  stage: test
  script:
    - npm install
    - npm test
  tags:
    - docker
```

### Динамическая генерация

Генерация конфигурации child pipeline во время выполнения родительского пайплайна. Используется для монорепозиториев и сложных сценариев.

Подробный пример с Python и Jinja2: [Динамическая генерация](./dynamic_generation.md).

## Дополнительная информация

### Варианты использования

- Декомпозиция монолитного `.gitlab-ci.yml` на логические блоки
- Изоляция expensive jobs в отдельный pipeline
- Улучшение читаемости конфигурации
- Повторное использование через `include`
