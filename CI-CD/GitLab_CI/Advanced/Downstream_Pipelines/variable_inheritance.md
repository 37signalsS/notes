# Наследование переменных в downstream-пайплайнах

## Определения

**Наследование переменных** — это механизм передачи контекста, параметров и секретов из родительского (upstream) пайплайна в дочерний (downstream). Способ передачи определяет приоритет данных и их видимость в дочернем процессе.

## Основные концепции

### Иерархия приоритетов

Переменные, переданные в downstream-пайплайна, в его контексте получают статус **Pipeline Variables**. Они имеют один из самых высоких приоритетов и переопределяют переменные проекта и группы.

**Порядок приоритетов (от высшего к низшему):**
1. Переменные пайплайна (переданные через `trigger:forward`, API или UI).
2. Переменные проекта и группы.
3. Переменные из `dotenv` отчётов.
4. Переменные задания (`job:variables`).
5. Глобальные переменные YAML (`variables:`).
6. Предопределённые переменные GitLab (`CI_*`).

### Механизмы передачи (trigger:forward)

Ключевое слово `forward` управляет потоком данных из родительского пайплайна.

| Параметр | Описание | По умолчанию (P-C) | По умолчанию (M-P) |
| :--- | :--- | :---: | :---: |
| **`yaml_variables`** | Переменные из блока `variables` текущего задания и файла | `true` | `false` |
| **`pipeline_variables`** | Переменные, с которыми был запущен родитель (API/UI) | `true` | `false` |

**Пример ограничения передачи:**
```yaml
trigger-secure:
  trigger:
    project: my-group/downstream-project
    forward:
      yaml_variables: true
      pipeline_variables: false # Исключить переменные ручного запуска
```

### Блокировка наследования (inherit)

Для полной изоляции дочернего пайплайна от глобального контекста родителя используется `inherit:variables:false`.

```yaml
isolated-job:
  inherit:
    variables: false
  variables:
    ONLY_THIS: "value"
  trigger:
    include: child.yml
```

## Практические сценарии

### Использование Pipeline Inputs (Рекомендуемый стандарт 18.x)

С выходом **GitLab 18.0** использование `spec:inputs` становится предпочтительным способом передачи параметров конфигурации.

**Преимущества:**
- **Валидация:** проверка типов (`string`, `number`, `boolean`) до старта пайплайна.
- **Неизменяемость:** инпуты интерполируются в YAML до создания пайплайна и не могут быть переопределены в runtime.
- **Безопасность:** чёткая спецификация ожидаемых данных.

**Вызов с использованием inputs:**
```yaml
deploy-production:
  trigger:
    include:
      - local: ci/deploy-template.yml
        inputs:
          stage_name: "prod"
          replica_count: 3
```

### Динамическая передача через dotenv

Используется для передачи данных, которые генерируются во время выполнения (например, ID артефакта или динамический тег образа).

```yaml
# Upstream
generate-build:
  stage: build
  script:
    - echo "IMAGE_TAG=$(date +%s)" > build.env
  artifacts:
    reports:
      dotenv: build.env

# Downstream (автоматически получит IMAGE_TAG как переменную пайплайна)
trigger-deploy:
  stage: deploy
  trigger: my-group/deploy-project
```

## Дополнительная информация

### Рекомендации по безопасности

- **Не передавайте маскированные секреты** через `trigger:variables` в Multi-project пайплайны. При такой передаче свойство маскирования может быть потеряно. Используйте внешние хранилища (Vault, AWS Secrets Manager).
- **Изолируйте контекст:** используйте `forward:pipeline_variables:false`, если не уверены в безопасности данных, вводимых пользователями при ручном запуске.
- **Приоритет Inputs:** если в дочернем пайплайне определён `input` и передана переменная с тем же именем, `input` имеет приоритет на этапе формирования YAML, но переменная останется доступна в среде выполнения.
