# Правила запуска задач (rules)

## Определения

`rules` — рекомендуемый способ контроля запуска отдельных задач. Правила проверяются по порядку (first match), первое совпадение определяет поведение задачи.

**Поддерживаемые ключи:**
- `if`: логические условия на базе переменных.
- `changes`: запуск при изменении конкретных файлов.
- `exists`: запуск при наличии файлов в репозитории.
- `when`: режим запуска (`on_success`, `manual`, `never` и др.).
- `allow_failure`: управление критичностью ошибки (поддерживает `exit_codes`).
- `variables`: переопределение переменных для конкретного правила.
- `needs`: динамическое определение зависимостей (GitLab 16.0+).
- `start_in`: задержка для `when: delayed`.

## Основные концепции

По умолчанию задачи запускаются согласно разделу `stages`. Директива `rules` переопределяет это поведение:

- Задача включается в пайплайн только при совпадении правила.
- Если ни одно правило не совпало — задача исключается.
- `when: never` в начале списка правил позволяет явно блокировать запуск в нежелательных условиях.

**Динамические зависимости (rules:needs):**
Позволяет менять список родительских задач в зависимости от условий (например, на ветке `main` ждать сборку артефакта, а на feature-ветке — нет).

### Ограничение: видимость переменных

Правила `rules` вычисляются в момент создания пайплайна. Это означает:
1. Переменные из других задач (через `artifacts:reports:dotenv`) **недоступны** в блоке `rules`.
2. Переменные, созданные в `script`, не влияют на выполнение правил.
3. Доступны только предопределённые переменные GitLab (`CI_*`), переменные проекта, группы и переменные, переданные при триггере.

```yaml
# ОШИБКА: переменная из другой job недоступна в rules
next_job:
  rules:
    - if: '$UPSTREAM_VERSION == "1.0"' # $UPSTREAM_VERSION не будет видна здесь
```

## Практические сценарии

**Запуск только для Merge Request:**

```yaml
test_job:
  stage: test
  script:
    - npm run test
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
```

**Запуск для MR в определённую ветку:**

```yaml
test_mr_to_main:
  script:
    - npm run test
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event" && $CI_MERGE_REQUEST_TARGET_BRANCH_NAME == "main"'
```

**Запуск при изменении файлов (монорепозитории):**

```yaml
# Запуск только при изменении frontend-кода
test_frontend:
  script:
    - npm run test
  rules:
    - changes:
        - "frontend/**/*"
        - "package.json"
        - "pnpm-lock.yaml"

# Запуск только при изменении backend-кода
test_backend:
  script:
    - pytest
  rules:
    - changes:
        - "backend/**/*"
        - "requirements.txt"
```

**Точное отслеживание изменений (compare_to):**
В монорепозиториях важно сравнивать изменения не только с текущим коммитом, но и с базовой веткой (особенно для новых веток).

```yaml
test_component:
  rules:
    - changes:
        paths:
          - "component/**/*"
        compare_to: 'refs/heads/main' # сравнение с main
```

**Динамические зависимости (needs):**
Разный набор зависимых задач для разных веток.

```yaml
deploy:
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
      needs: ["build_prod", "test_all"]
    - if: '$CI_COMMIT_BRANCH != "main"'
      needs: ["build_dev"] # более быстрый путь для разработчиков
```

**Условная обработка ошибок (exit_codes):**
Продолжать выполнение, если задача упала с определённым кодом.

```yaml
optional_scan:
  rules:
    - if: '$CI_PIPELINE_SOURCE == "push"'
      allow_failure:
        exit_codes:
          - 137 # OOM или специфический код сканера
```

**Комбинированное правило для деплоя:**

```yaml
deploy_job:
  stage: deploy
  script:
    - ./deploy.sh
  rules:
    # Автоматический деплой для main
    - if: '$CI_COMMIT_BRANCH == "main"'
      when: on_success
    # Ручной деплой для staging
    - if: '$CI_COMMIT_BRANCH == "staging"'
      when: manual
    # Запрет для остальных веток
    - when: never
```

## Дополнительная информация

### Ключевые условия

| Условие | Описание | Пример |
| :--- | :--- | :--- |
| `if` | Проверка переменных | `if: '$CI_COMMIT_BRANCH == "main"'` |
| `changes` | Изменения файлов | `changes: - "src/**/*"` |
| `exists` | Существование файлов | `exists: - "docker-compose.yml"` |
| `compare_to` | База для сравнения `changes` | `compare_to: 'refs/heads/main'` |

### Режимы запуска (when)

| Режим | Описание |
| :--- | :--- |
| `on_success` | При успехе всех предыдущих (по умолчанию) |
| `on_failure` | Только если предыдущая задача упала |
| `always` | Всегда, независимо от статуса |
| `manual` | Ручной запуск из интерфейса |
| `delayed` | Запуск с задержкой (`start_in`) |
| `never` | Исключить задачу из пайплайна |
