# Справочник директив GitLab CI/CD

## Определения

**Справочник директив** — это центральный технический документ (SSoT), описывающий синтаксис, назначение и технические нюансы ключевых слов в файле `.gitlab-ci.yml`. В отличие от концептуальных обзоров, данный файл фокусируется на глубоких деталях реализации и актуальных возможностях версий GitLab 17.x–19.x.

## Глобальные директивы (Global Keywords)

### `default`
Набор настроек, применяемых ко всем задачам пайплайна, если они не переопределены внутри самой задачи.
- **Включает:** `image`, `services`, `before_script`, `after_script`, `tags`, `cache`, `artifacts`, `interruptible`, `retry`, `timeout`.
- **Нюанс:** С версии 19.x использование этих ключей на верхнем уровне вне блока `default` считается устаревшим.

### `stages`
Определяет список и порядок выполнения стадий.
- **Тип:** Массив строк.
- **Поведение:** Задачи одной стадии выполняются параллельно (в рамках доступных Runner'ов). Если стадия не указана в задаче, она по умолчанию попадает в стадию `test`.

### `workflow`
Глобальное управление созданием всего пайплайна.
- **`rules`**: Условия, при которых пайплайн вообще будет запущен (подробнее — в **[Правилах запуска](./job_rules.md)**).
- **`auto_cancel` (16.0+):** Автоматическая отмена старых пайплайнов.
  - `on_new_commit`: `interruptible` (по умолчанию) или `none`.
  - `on_job_failure`: `all` (отмена всех задач при падении одной) или `none`.

### `include` (17.0+)
Подключение внешних YAML-файлов или компонентов.
- **Типы:** `local`, `project`, `remote`, `template`, `component`.
- **`inputs`**: Передача параметров в подключаемые файлы (требует блока `spec:inputs` в источнике).

## Директивы управления выполнением (Execution Control)

### `rules`
Условное включение задач в пайплайн.
- **Назначение:** Замена устаревшим `only`/`except`.
- **Ключевые слова:** `if`, `changes`, `exists`, `when`, `allow_failure`, `variables`, `needs`.
- **Техническая SSoT:** **[job_rules.md](./job_rules.md)**.

### `needs` (DAG)
Создание направленного ациклического графа для ускорения пайплайна.
- **Возможности:** Игнорирование границ стадий, опциональные зависимости (`optional: true`), кросс-проектные зависимости (`project`).
- **Матричные зависимости (16.3+):** Связь конкретных инстансов `parallel:matrix`.
- **Техническая SSoT:** **[dag_with_needs.md](./dag_with_needs.md)**.

### `parallel`
Запуск нескольких копий задачи.
- **`matrix`**: Позволяет запустить задачу с разными комбинациями переменных.
- **Технические нюансы:** Лимит на количество задач в матрице зависит от настроек GitLab (обычно до 200). Подробнее — в **[Матричных сборках](./matrix_builds_and_serialization.md)**.

### `trigger`
Создание Downstream пайплайнов (Multi-project или Parent-Child).
- **`strategy: depend`**: Заставляет родительскую задачу ждать завершения дочернего пайплайна.

### `interruptible`
Указывает, может ли задача быть отменена при появлении нового пайплайна в той же ветке (используется вместе с `workflow:auto_cancel`).

### `resource_group`
Механизм сериализации (мьютекс) для задач, которые не могут выполняться одновременно (например, деплой на одно окружение).

## Артефакты и кэширование (Data Management)

### `artifacts`
Передача файлов между стадиями.
- **`paths`**: Список файлов/директорий.
- **`reports`**: Специализированные отчеты (junit, cobertura, dotenv, sbom).
- **`expire_in`**: Время хранения на сервере (по умолчанию 30 дней).
- **`when`**: `on_success` (по умолчанию), `on_failure`, `always`.

### `cache`
Временное хранилище для ускорения сборки.
- **`key`**: Уникальный идентификатор кэша (поддерживает переменные и `files`).
- **`policy`**: `pull-push` (по умолчанию), `pull`, `push`.
- **`untracked`**: Кэширование всех файлов, не отслеживаемых Git.

## Безопасность и интеграция (Security)

### `id_tokens` (16.x+)
Генерация OIDC токенов для беспарольной аутентификации во внешних облаках (AWS, GCP, Vault).
- **Синтаксис:**
  ```yaml
  id_tokens:
    MY_TOKEN:
      aud: https://vault.example.com
  ```

### `secrets` (19.2+ GA)
Интеграция со встроенным **GitLab Secrets Manager** или внешними хранилищами.
- **Поведение:** Динамическая инъекция секретов в среду выполнения задачи без их сохранения в переменных.

## Дополнительная информация

### Приоритет переменных (версия 19.x)
1. Переменные, заданные вручную при запуске (Web UI/API).
2. Переменные в блоке `job:variables`.
3. Переменные в блоке `workflow:rules:variables`.
4. Входные параметры `spec:inputs`.
5. Переменные проекта/группы (настройки GitLab).
6. Предопределенные переменные (`CI_*`).
7. Переменные в `default:variables`.
