# Кэширование и артефакты в GitLab CI — Обзор

## Определения

**Кэширование в GitLab CI** — механизм сохранения файлов и директорий между запусками задач или пайплайнов для ускорения сборки за счёт повторного использования зависимостей.

**Артефакты в GitLab CI** — файлы или директории, сохраняемые после выполнения задачи и передаваемые между стадиями пайплайна для доставки результатов сборки.

**Распределённый кэш** — механизм хранения кэша в централизованном хранилище (S3, GCS), доступном всем Runner'ам.

**Локальный кэш** — кэш, хранящийся на конкретном Runner'е и доступный только задачам, выполняющимся на этом Runner'е.

## Основные концепции

### Кэш vs. Артефакты

| Признак | Кэш (`cache`) | Артефакты (`artifacts`) |
| :--- | :--- | :--- |
| **Назначение** | Ускорение задач (зависимости) | Передача результатов (билды, отчёты) |
| **Гарантия** | Не гарантируется (может быть удалён) | Гарантируются на сервере |
| **Хранение** | Локально на Runner'е или в S3/GCS | На сервере GitLab |
| **Срок жизни** | Бессрочно (до ручной очистки) | 30 дней по умолчанию (настраиваемо) |
| **Область** | Между пайплайнами одной ветки | Между стадиями одного пайплайна |
| **Загрузка** | Автоматически в начале задачи | Явно через `dependencies` или по умолчанию |

### Архитектура кэширования

Кэширование в GitLab CI работает на двух уровнях:

1. **Локальное хранилище** — кэш сохраняется в директории Runner'а (например, `/home/gitlab-runner/.local/share/gitlab-runner/cache`). Доступен только задачам на этом Runner'е.
2. **Распределённое хранилище (S3, GCS)** — кэш загружается в объектное хранилище. Доступен всем Runner'ам проекта, что является лучшей практикой для командной работы.

### Жизненный цикл кэша

1. **Поиск** — перед выполнением скрипта задачи GitLab ищет кэш по ключу (сначала основной, затем резервные `fallback_keys`).
2. **Загрузка** — если кэш найден, он распаковывается в рабочую директорию.
3. **Выполнение задачи** — выполняется секция `script`.
4. **Обновление** — после успешного выполнения задачи (если `policy` установлена в `pull-push` или `push`), кэш из указанных `paths` архивируется и загружается в хранилище.

### Типы ключей кэша

| Тип | Пример | Когда использовать |
| :--- | :--- | :--- |
| Статический | `key: "global-cache"` | Глобальный кэш для всех веток (не рекомендуется) |
| Динамический | `key: "$CI_COMMIT_REF_SLUG"` | Раздельный кэш по веткам |
| По файлам | `key: { files: [package-lock.json] }` | Автообновление при изменении зависимостей |
| Fallback | `fallback_keys: [cache-main]` | Резервный кэш при отсутствии основного |

Подробнее о ключах и политиках — в [документации по ключам кэша](./cache_keys.md).

## Практические сценарии

### Пример комбинации кэша и артефактов

```yaml
build:
  stage: build
  script:
    - npm ci
    - npm run build
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - node_modules/
    policy: pull-push
  artifacts:
    paths:
      - dist/
    expire_in: 1 week

test:
  stage: test
  script:
    - npm test
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - node_modules/
    policy: pull
  dependencies:
    - build
  artifacts:
    reports:
      junit: test-results.xml
```

**Объяснение:**

- **Кэш** (`cache`) используется для `node_modules`, ускоряя `npm ci` в обеих задачах.
- **Артефакты** (`artifacts`) используются для передачи собранной директории `dist/` из `build` в `test` и для сохранения отчёта о тестировании `junit.xml`.

## Дополнительная информация

### Настройка распределённого кэша

Для включения распределённого кэша требуется конфигурация Runner'а в файле `/etc/gitlab-runner/config.toml`:

```toml
[runners.cache]
  Type = "s3"
  Shared = true
  [runners.cache.s3]
    ServerAddress = "s3.amazonaws.com"
    BucketName = "gitlab-runner-cache"
    AccessKey = "YOUR_ACCESS_KEY"
    SecretKey = "YOUR_SECRET_KEY"
```

### Ограничения и рекомендации

| Категория | Рекомендация / Ограничение |
| :--- | :--- |
| **Размер и кол-во** | Максимум 4 кэша на задачу. Размер ограничен настройками сервера (обычно 100 МБ). |
| **Ключи** | Используйте ключи по файлам зависимостей для автоматической инвалидации кэша. |
| **Артефакты** | Всегда устанавливайте `expire_in` для артефактов, чтобы не переполнять хранилище GitLab. |
| **Безопасность** | Не кэшируйте файлы, содержащие секреты или чувствительные данные. |
| **Разделение** | Разделяйте кэш и артефакты: кэш для зависимостей, артефакты для результатов сборки. |
