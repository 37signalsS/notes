# Продвинутые рабочие процессы GitLab CI/CD

## Определения

**Продвинутые рабочие процессы GitLab CI/CD** — набор директив и механизмов для управления сложными пайплайнами: условный запуск, оптимизация выполнения через DAG, матричные сборки, сериализация развертываний.

**Ключевые директивы:**

- `workflow:rules` — глобальное правило создания пайплайна.
- `rules` — условный запуск отдельных задач.
- `needs` — создание DAG для ускорения выполнения.
- `parallel:matrix` — запуск задачи с разными комбинациями переменных.
- `resource_group` — сериализация выполнения для защиты от гонок состояний.

Подробные определения и лучшие практики см. в [Определениях и рекомендациях по директивам](./workflow_rules/directives_definitions.md).

## Основные концепции

### Архитектура управления пайплайнами

Продвинутые рабочие процессы решают три основные задачи:

1. **Контроль запуска** — когда и при каких условиях создавать пайплайн и задачи.
2. **Оптимизация выполнения** — ускорение через параллелизм и DAG.
3. **Безопасность развертывания** — предотвращение гонок состояний при деплое.

### Связь с базовыми концепциями

Базовая структура пайплайна (`stages` → `jobs` → `script`) определяет последовательное выполнение. Продвинутые директивы могут изменять эту модель: `needs` позволяет задачам запускаться вне очереди, `rules` динамически включают/исключают задачи, `parallel:matrix` мультиплицирует их, а `resource_group` добавляет очереди.

### Версионирование и совместимость

Современные версии GitLab (17+) предлагают новые механизмы, такие как **типизированные параметры пайплайна (`inputs`)** и **переиспользуемые компоненты**, которые упрощают управление сложными конфигурациями. Для безопасной аутентификации во внешних системах используется **OIDC** (`CI_JOB_JWT_TOKEN`).

Подробнее см. в [Переменные и Best Practices](./workflow_rules/variables_best_practices.md).

## Практические сценарии

В следующих документах приведены подробные разборы практических сценариев с примерами кода.

### Контроль запуска пайплайнов и задач

- **Проблема:** Дублирование пайплайнов при push в ветку с открытым MR.
- **Решение:** Использование `workflow:rules` для определения глобальных правил запуска.
- **Проблема:** Запуск всех тестов в монорепозитории при любом изменении.
- **Решение:** Применение `rules:changes` для условного запуска задач.

Подробнее см. в [Правилах запуска задач](./workflow_rules/job_rules.md).

### Ускорение пайплайна через DAG

- **Проблема:** Задачи ожидают завершения всей стадии, хотя их зависимости уже выполнены.
- **Решение:** `needs` для создания графа зависимостей (DAG) между задачами, что позволяет им стартовать раньше.

Подробнее см. в [DAG с `needs`](./workflow_rules/dag_with_needs.md).

### Матричное тестирование и защита окружений

- **Проблема:** Необходимость тестирования на нескольких версиях ПО (например, Python 3.10, 3.11, 3.12).
- **Решение:** Использование `parallel:matrix` для автоматического создания задач под каждую комбинацию.
- **Проблема:** Гонки состояний при одновременном развертывании в production из разных пайплайнов.
- **Решение:** `resource_group` для сериализации выполнения задач, нацеленных на один и тот же ресурс.

Подробнее см. в [Матричных сборках и сериализации](./workflow_rules/matrix_builds_and_serialization.md).

## Дополнительная информация

### Ограничения

- `workflow:rules` не поддерживает `start_in`, `allow_failure`, `needs`.
- `changes` не работает для `workflow:rules` (только для `job:rules`).
- Максимум 1000 downstream-пайплайнов в одной иерархии.
