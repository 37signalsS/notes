### Настройка кэширования

**Кэширование** позволяет сохранять файлы и директории между запусками задач (job) или пайплайнов для ускорения выполнения и сокращения времени сборки, избегая повторной загрузки зависимостей.

**Основные принципы кэширования:**
*   **Цель:** Ускорить пайплайны, сохраняя часто используемые файлы (например, зависимости проекта `node_modules`, `vendor/`, `.m2/`).
*   **Область действия:** Кэш может быть общим для всего пайплайна или специфичным для отдельных задач.
*   **Ключ кэша (`cache:key`):** Определяет уникальность кэша. Если ключ меняется, кэш перестраивается. Позволяет контролировать, когда кэш должен быть создан заново или переиспользован.

**Пример базового кэширования зависимостей NPM:**

```yaml
variables:
  npm_config_cache: "$CI_PROJECT_DIR/.npm" # Указываем путь для кэша NPM

cache:
  key: "$CI_COMMIT_REF_SLUG" # Ключ кэша по имени ветки/тега
  paths:
    - node_modules/
    - .npm/

install_dependencies:
  stage: build
  script:
    - npm ci --cache .npm --prefer-offline # Устанавливаем зависимости, используя локальный кэш
  cache:
    key: "$CI_COMMIT_REF_SLUG-$CI_JOB_NAME" # Более специфичный ключ для этой задачи
    paths:
      - node_modules/
    policy: pull-push # Загружает кэш перед job, сохраняет после

test_job:
  stage: test
  script:
    - npm run test
  cache:
    key: "$CI_COMMIT_REF_SLUG-install_dependencies" # Используем ключ кэша от предыдущей задачи
    paths:
      - node_modules/
    policy: pull # Только загружает существующий кэш
```

**Стратегии определения ключа кэша (`cache:key`):**

*   **По содержимому файлов (рекомендуется для зависимостей):**
    ```yaml
    cache:
      key:
        files:
          - package-lock.json # Кэш будет перестраиваться только при изменении этого файла
      paths:
        - node_modules/
    ```
*   **По ветке (для разных веток разные кэши):**
    ```yaml
    cache:
      key: "$CI_COMMIT_REF_NAME"
      paths:
        - vendor/
    ```
*   **Глобальный кэш (один кэш для всего проекта):**
    ```yaml
    cache:
      key: "global-cache"
      paths:
        - .m2/repository/
    ```

**Политики кэширования (`cache:policy`):**

*   `pull-push` (по умолчанию) - Загружает кэш перед выполнением задачи, а затем сохраняет его после успешного завершения.
*   `pull` - Только загружает существующий кэш. Не сохраняет изменения после выполнения задачи.
*   `push` - Только сохраняет кэш после выполнения задачи. Не пытается загрузить существующий кэш.

**Важные моменты:**

*   **Кэш не гарантирован:** GitLab Runner может очистить кэш в любой момент (например, из-за нехватки места). Не полагайтесь на кэш для хранения критически важных данных.
*   **Артефакты vs. Кэш:** Для критически важных файлов, которые должны быть доступны в последующих задачах и гарантированно сохранены, используйте [артефакты](CI-CD/GitLab_CI/Advanced/gitlab_ci_workflow_builder.md#artifacts-results-of-job-execution), а не кэш.
*   **Скорость:** Кэш обычно работает быстрее артефактов, так как он предназначен для временного хранения и переиспользования в рабочей среде Runner'а, тогда как артефакты должны быть загружены на сервер GitLab.
