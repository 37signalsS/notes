# Паттерны CI/CD

## Определения

**Паттерн CI/CD** — проверенный, эффективный и воспроизводимый подход к решению типовых задач в процессах непрерывной интеграции, доставки и развертывания. Применение паттернов направлено на минимизацию рисков при релизах, сокращение Time-to-Market и повышение стабильности систем.

Паттерны являются прямыми решениями для соответствующих [анти-паттернов CI/CD](./ci_cd_antipatterns.md).

## Основные концепции

### Взаимосвязь ключевых паттернов

Паттерны CI/CD наиболее эффективны при комплексном применении, формируя целостную стратегию поставки ПО:

1. **Trunk-Based Development (TBD)** — модель разработки с единой основной веткой. Описание в [Рабочие процессы в Git](../Git/git_workflows.md#3-trunk-based-development-tbd).
2. **Feature Flags (фиче-флаги)** — управление доступностью кода во время выполнения без повторного деплоя. См. [Обзор Feature Toggles](./Testing/feature_toggles/overview.md).
3. **Branch Protection Rules (правила защиты веток)** — политики, блокирующие слияние кода без прохождения автоматизированных проверок и ревью. См. [Защита веток в Git](../Git/git_branching.md#защита-веток-branch-protection).
4. **Immutable Artifacts (иммутабельные артефакты)** — принцип "одной сборки", при котором артефакт (например, Docker-образ) создается один раз и продвигается по всем средам без пересборки. См. [Управление артефактами](./artifact_management.md).

### Классификация паттернов

* **Организационные:** TBD, Branch Protection — определяют культуру взаимодействия в команде и политики безопасности.
* **Технические:** Feature Flags, Immutable Artifacts — реализуются на уровне архитектуры приложения и инфраструктурных конвейеров.

## Практические сценарии

### Комбинирование паттернов в пайплайне

Типовой жизненный цикл изменения с применением комплекса паттернов обеспечивает высокую скорость обратной связи и надежность релиза:

1. **Разработка и локальная проверка:**
    * Создается короткоживущая ветка от `main` (TBD).
    * Новая функциональность инкапсулируется в [feature flag](./Testing/feature_toggles/overview.md).
    * Ветка защищена [правилами защиты](../Git/git_branching.md#защита-веток-branch-protection), требующими успешного прохождения CI-пайплайна.

2. **Интеграция:**
    * После прохождения проверок код вливается в `main`.
    * Feature flag в состоянии `false` гарантирует, что незавершенный код не влияет на текущих пользователей.

3. **Доставка и развертывание:**
    * Система сборки создает один [иммутабельный артефакт](./artifact_management.md).
    * Этот же артефакт последовательно развертывается в staging и production окружениях. Конфигурация сред передается через переменные окружения.
    * Активация функциональности на продакшене происходит через переключение флага без участия CI/CD пайплайна.

4. **Обработка инцидентов и откат:**
    * При обнаружении багов в новой фиче флаг мгновенно выключается, восстанавливая работоспособность системы.
    * При критических инфраструктурных сбоях выполняется быстрый возврат к предыдущему стабильному [иммутабельному артефакту](./artifact_management.md).
