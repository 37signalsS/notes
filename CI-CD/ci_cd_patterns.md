# CI/CD: Паттерны и лучшие практики

## Определения

**Паттерн CI/CD** — проверенный, эффективный и воспроизводимый подход к решению типичных задач в процессах непрерывной интеграции и доставки. Применение паттернов повышает скорость, стабильность и безопасность жизненного цикла разработки ПО.

**Связь с анти-паттернами:** каждый паттерн является решением для одного или нескольких [анти-паттернов CI/CD](./ci_cd_antipatterns.md).

## Основные концепции

### Взаимосвязь паттернов

Паттерны CI/CD работают в комплексе:

1. **Trunk-Based Development** задаёт поток изменений в кодовой базе
2. **Feature Flags** позволяют безопасно интегрировать незавершённый код в `main`
3. **Branch Protection Rules** гарантируют прохождение проверок перед слиянием
4. **Immutable Artifacts** обеспечивают повторяемость развёртывания

### Классификация паттернов

- **Организационные:** TBD, Branch Protection — регулируют процесс разработки
- **Технические:** Feature Flags, Immutable Artifacts — реализуются на уровне кода и инфраструктуры

## Практический сценарий: Комбинация паттернов в пайплайне

Рассмотрим типичный поток изменений с применением всех четырёх паттернов:

1. **Разработка фичи:**
   - Разработчик создаёт короткоживущую ветку от `main` (TBD)
   - Реализация скрывается за [feature flag](./Testing/feature_toggles/overview.md)
   - Ветка защищена [правилами защиты](../Git/git_branching.md#защита-веток-branch-protection): требуются CI-проверки и ревью

2. **Слияние в main:**
   - После прохождения CI и ревью ветка вливается в `main`
   - Feature flag остаётся выключенным для пользователей

3. **Сборка и развёртывание:**
   - Пайплайн собирает [иммутабельный артефакт](./artifact_management.md) (Docker-образ)
   - Артефакт разворачивается на staging с выключенным флагом
   - После тестирования флаг включается для production

4. **Откат при проблеме:**
   - Feature flag выключается без переразвёртывания
   - При необходимости — откат к предыдущему [иммутабельному артефакту](./artifact_management.md)
