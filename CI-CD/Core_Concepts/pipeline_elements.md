# Ключевые элементы CI/CD конвейера

*   **Триггеры (Triggers):**
    *   События, запускающие пайплайн.
    *   *Примеры:* `push` в ветку, `merge request`, запуск по расписанию, создание тега релиза, ручной запуск.

*   **Исполнители (Runners/Agents):**
    *   Изолированные среды (виртуальные машины, контейнеры), в которых выполняются шаги (jobs) пайплайна.

*   **Этапы (Stages):**
    *   Логические группы шагов, выполняемые последовательно.
    *   *Примеры:* `build` -> `test` -> `security_scan` -> `package` -> `release` -> `deploy`.

*   **Артефакты (Artifacts):**
    *   Результаты выполнения шагов, которые сохраняются и передаются между этапами.
    *   *Примеры:* собранные бинарные файлы, пакеты (`.jar`, `.deb`), Docker-образы. Хранятся в специализированных репозиториях (Artifact-хранилища, Docker Registry).

*   **Среды (Environments):**
    *   Изолированные окружения, для которых выполняется развертывание.
    *   *Типичная схема:* `dev` -> `stage` -> `prod`. Продвижение (promotion) артефактов означает, что один и тот же неизменяемый артефакт последовательно развертывается в разных средах.

*   **Политики (Policies):**
    *   Набор правил, управляющих жизненным циклом пайплайна.
    *   *Примеры:* quality gates (пороги качества, например, покрытие тестами >80%), ручные подтверждения (approvals), правила защиты веток, условия для автоматического развертывания.

*   **Кэширование (Caching):**
    *   Механизм сохранения зависимостей и промежуточных результатов между запусками пайплайна для ускорения сборок.

*   **Управление секретами (Secrets Management):**
    *   Практика безопасного хранения и предоставления доступа к чувствительным данным (паролям, API-ключам, токенам). Секреты должны храниться во внешних системах (например, HashiCorp Vault, AWS Secrets Manager) и вводиться в среду выполнения (runtime) на лету, а не храниться в коде или артефактах.
