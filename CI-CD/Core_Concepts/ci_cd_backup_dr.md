# Резервное копирование и DR для CI/CD

## Определения

- **Backup** — создание копии данных для восстановления при потере/повреждении.
- **Restore** — процесс возврата системы из резервной копии.
- **RPO (Recovery Point Objective)** — максимально допустимая потеря данных (например, «не более 24 ч»).
- **RTO (Recovery Time Objective)** — максимально допустимое время простоя.
- **DR (Disaster Recovery)** — план восстановления после крупного сбоя (потеря узла/контура).
- **Immutable Backup** — копия, защищённая от изменения/удаления (WORM, объектные блокировки), см. [Immutable Storage в изолированных средах](./air_gapped_environments.md).
- **Репликация** — непрерывное копирование на вторичный узел/площадку.

## Основные концепции

### Что бэкапить в инфраструктуре CI/CD

1. **Реестр образов** (Harbor/Nexus) — слои и метаданные; без него пайплайн не соберёт ничего.
2. **Артефакты сборки** (бинарники, чарты, пакеты) — зеркало зависимостей.
3. **Конфигурация CI как код** — `.gitlab-ci.yml`, `Jenkinsfile`, переменные окружений (хранить в git + mirror).
4. **Состояние раннеров** — их конфигурации и ключи (не сами раннеры, а их описание).
5. **Секреты и ключи** — Vault/УЦ экспорты в зашифрованном виде.
6. **Метаданные БД** — состояние пайплайнов, история деплоев (для аудита RCA).

### RPO/RTO для CI/CD

Инфраструктура CI не «несёт продукт», но её простой блокирует выпуски. RTO раннеров — минуты (поднять новые из образа), RPO реестра — часы (реплика/зеркало). Критичные артефакты должны иметь копию вне контура (offsite/air-gap bundle).

### Иммутабельность и проверка

Бэкап бесполезен, если не проверен restore. Обязателен регулярный тест восстановления. Целостность — через `sha256` + подпись (cosign/GPG). Хранилище — append-only/WORM, чтобы скомпрометированный узел не стёр копию.

## Практические сценарии

### Сценарий 1: Бэкап реестра Docker/Harbor

```bash
# Экспорт образов в архив (offline-бандл)
skopeo sync --src docker --dest dir registry.internal/library /backup/registry-$(date +%F)
# Либо на уровне хранилища (см. [Docker backup/restore](../../Docker/Docker_fs/docker_backup_restore.md))
# Снимок тома /var/lib/registry + экспорт метаданных БД Harbor
```

### Сценарий 2: Бэкап артефактов (rsync + контрольная сумма)

```bash
rsync -a --delete --checksum /var/lib/nexus/storage /backup/nexus/
sha256sum /backup/nexus/* > /backup/nexus.manifest.sha256
gpg --detach-sign /backup/nexus.manifest.sha256   # подпись целостности
```

### Сценарий 3: Бэкап конфигурации CI как кода

```bash
# Весь CI-конфиг в git + зеркало вне контура (sneakernet/periodic sync)
git bundle create ci-config-$(date +%F).bundle --all
# Копия на физически изолированный носитель (air-gapped)
```

### Сценарий 4: Runbook восстановления после потери реестра

```text
1. Поднять чистый узел реестра (из золотого образа).
2. Восстановить том из снимка / импортировать dir:-бандл через skopeo.
3. Проверить подписи: cosign verify --key cosign.pub registry.internal/library/*
4. Поднять раннеры (systemd unit из бэкап-конфигов).
5. Прогнать smoke-пайплайн: build -> push -> deploy canary.
```

## Дополнительная информация

### Типичные ошибки

- **Бэкап без теста восстановления** — при аварии выясняется, что копия битая.
- **Секреты в открытом бэкапе** — утечка при краже носителя.
- **Нет offsite-копии** — локальный бэкап гибнет вместе с контуром (пожар/диск).
- **Бэкап реестра без метаданных БД** — образы есть, но связи/теги потеряны.
