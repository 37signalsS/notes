# Глоссарий: Ключевые элементы CI/CD конвейера

## Определения

Этот документ служит центральным глоссарием для основных компонентов, из которых состоит любой CI/CD пайплайн.

**Назначение:** Краткие определения с ссылками на SSoT-файлы для подробной информации.

---

## Основные концепции

### Пайплайн (Pipeline) {#пайплайн-pipeline}

**Описание:** Полностью автоматизированный процесс, описывающий все шаги для сборки, тестирования и развертывания ПО. Состоит из одного или нескольких этапов (Stages).

**SSoT:** [Типичный поток и пример пайплайна](./pipeline_workflow.md), [CI/CD: Обзор](../ci_cd_overview.md)

---

### Триггер (Trigger) {#триггер-trigger}

**Описание:** Событие, которое автоматически запускает пайплайн.

**Примеры:**
- `push` в ветку
- Создание merge request
- Запуск по расписанию (cron)
- Вызов через API

**SSoT:** [GitLab CI Basics — Rules](../GitLab_CI/Concepts/gitlab_ci_basics.md#rules)

---

### Исполнитель (Runner / Agent) {#исполнитель-runner-agent}

**Описание:** Рабочая машина или контейнер, который выполняет задачи (jobs) пайплайна. Исполнители обеспечивают изолированную и воспроизводимую среду для выполнения шагов.

**SSoT:** [Обзор GitLab Runners и Executor'ов](../GitLab_CI/Advanced/gitlab_ci_runners_executors.md)

---

### Этап (Stage) {#этап-stage}

**Описание:** Логическая группа задач, которые выполняются на определенной фазе пайплайна. Этапы выполняются последовательно (например, `build` → `test` → `deploy`), а задачи внутри одного этапа — параллельно.

**SSoT:** [GitLab CI Basics — Stages](../GitLab_CI/Concepts/gitlab_ci_basics.md#stages)

---

### Задача (Job / Step) {#задача-job-step}

**Описание:** Конкретная команда или скрипт, выполняемый исполнителем. Это минимальная единица работы в пайплайне.

**SSoT:** [GitLab CI Basics — Job](../GitLab_CI/Concepts/gitlab_ci_basics.md#задача-job)

---

### Артефакт (Artifact) {#артефакт-artifact}

**Описание:** Результат выполнения задачи, который сохраняется и передается между этапами. В отличие от кэша, артефакты гарантированно сохраняются.

**Примеры:** Бинарные файлы, Docker-образы, отчеты о тестах.

**SSoT:**
- [Управление артефактами — общая теория](../artifact_management.md)
- [Артефакты в GitLab CI](../GitLab_CI/Advanced/gitlab_ci_caching/artifacts.md)
- [Кэш vs. Артефакты](../GitLab_CI/Advanced/gitlab_ci_caching/caching_overview.md#кэш-vs-артефакты)

---

### Кэш (Cache) {#кэш-cache}

**Описание:** Механизм сохранения файлов (например, зависимостей) между запусками пайплайна для ускорения сборок. Сохранность кэша не гарантируется.

**SSoT:**
- [Кэширование в GitLab CI — обзор](../GitLab_CI/Advanced/gitlab_ci_caching/caching_overview.md)
- [Ключи кэша и политики](../GitLab_CI/Advanced/gitlab_ci_caching/cache_keys.md)
- [Лучшие практики кэширования](../GitLab_CI/Advanced/gitlab_ci_caching/cache_best_practices.md)

---

### Среда (Environment) {#среда-environment}

**Описание:** Изолированное окружение, в котором развертывается и тестируется приложение.

**Типичная схема:** `development` → `staging` → `production`

**SSoT:**
- [Deployment Strategies — модели развертывания](./deployment_strategies.md)
- [Стратегии развертывания](../Deployment_Strategies/comparison.md)

---

### Управление секретами (Secrets Management)

**Описание:** Практика безопасного хранения, ротации и предоставления доступа к чувствительным данным (паролям, API-ключам) во время выполнения пайплайна.

**SSoT:**
- [Управление секретами в CI/CD](../DevSecOps/secrets_management.md)
- [Безопасное управление секретами в Docker](../../Docker/Docker_security/secrets_management.md)

## Практические сценарии

### Типичный поток пайплайна

Пример последовательности этапов и задач см. в документе [Типичный поток и пример CI/CD пайплайна](./pipeline_workflow.md).

### Взаимосвязь элементов

```
Триггер → Пайплайн → [Этапы → [Задачи → Исполнитель]]
                         ↓
                    Артефакты/Кэш → Среда
```

1. **Триггер** инициирует **пайплайн**
2. Пайплайн выполняет **этапы** последовательно
3. Внутри этапов **задачи** выполняются параллельно на **исполнителях**
4. **Артефакты** передаются между задачами, **кэш** ускоряет повторные запуски
5. Финальная задача разворачивает приложение в **среде**
