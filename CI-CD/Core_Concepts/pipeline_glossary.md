# Глоссарий пайплайнов CI/CD

## Определения

**Глоссарий пайплайнов** — это справочный документ, содержащий определения ключевых элементов и терминов, используемых при построении конвейеров непрерывной интеграции и доставки ПО **([CI/CD — Continuous Integration / Continuous Delivery](../ci_cd_overview.md))**.

**Назначение:** Предоставление кратких и точных определений с указанием основных документов для детального изучения каждой темы.

---

## Основные концепции

### Пайплайн (Pipeline) {#пайплайн-pipeline}

**Описание:** Автоматизированный процесс, описывающий жизненный цикл изменений кода от сборки до развертывания. Состоит из последовательности этапов (Stages).

**Основной документ:** **[CI/CD: Обзор](../ci_cd_overview.md)**, **[Типичный поток и пример пайплайна](./pipeline_workflow.md)**

---

### Триггер (Trigger) {#триггер-trigger}

**Описание:** Событие, инициирующее автоматический запуск пайплайна.

**Примеры:**

- `push` в репозиторий.
- Создание **[Merge Request (MR)](../../Git/git_workflows.md)**.
- Запуск по расписанию (cron).
- Вызов через Webhook или API.

**Основной документ:** **[Основы GitLab CI/CD — управление потоком выполнения](../GitLab_CI/Concepts/gitlab_ci_basics.md#управление-потоком-выполнения)**

---

### Исполнитель (Runner / Agent) {#исполнитель-runner-agent}

**Описание:** Изолированная среда (машина, контейнер или под), выполняющая задачи (Jobs) пайплайна.

**Основной документ:** **[Обзор GitLab Runners и Executor'ов](../GitLab_CI/Advanced/gitlab_ci_runners_executors.md)**

---

### Этап (Stage) {#этап-stage}

**Описание:** Логическая группа задач, выполняемых на определенной фазе жизненного цикла (например, `build`, `test`, `deploy`). Этапы выполняются последовательно.

**Основной документ:** **[Основы GitLab CI/CD — стадии пайплайна](../GitLab_CI/Concepts/gitlab_ci_basics.md#типовые-стадии-пайплайна-lifecycle)**

---

### Задача (Job / Step) {#задача-job-step}

**Описание:** Минимальная единица работы в пайплайне — конкретный скрипт или команда, выполняемая исполнителем.

**Основной документ:** **[Основы GitLab CI/CD — ключевые слова для задач](../GitLab_CI/Concepts/gitlab_ci_basics.md#ключевые-слова-для-задач)**

---

### Артефакт (Artifact) {#артефакт-artifact}

**Описание:** Результат выполнения задачи (бинарные файлы, отчеты, Docker-образы), который сохраняется и может передаваться между этапами.

**Основной документ:** **[Управление артефактами](../artifact_management.md)**

---

### Кэш (Cache) {#кэш-cache}

**Описание:** Временное хранилище файлов (например, зависимостей пакетов) для ускорения повторных запусков пайплайна. В отличие от артефактов, сохранность кэша не гарантируется.

**Основной документ:** **[Кэширование в GitLab CI](../GitLab_CI/Advanced/gitlab_ci_caching/caching_overview.md)**

---

### Среда (Environment) {#среда-environment}

**Описание:** Инфраструктурное окружение, в котором развертывается приложение (например, `development`, `staging`, `production`).

**Основной документ:** **[Окружения и развертывания в GitLab CI](../GitLab_CI/Concepts/environments_and_deployments.md)**, **[Модели развертывания](./deployment_strategies.md)**, **[Сравнение стратегий развертывания](../Deployment_Strategies/comparison.md)**

---

### Управление секретами (Secrets Management) {#управление-секретами-secrets-management}

**Описание:** Безопасное хранение и передача чувствительных данных (паролей, токенов) в задачи пайплайна без их раскрытия в коде.

**Основной документ:** **[Управление секретами в CI/CD](../DevSecOps/secrets_management.md)**

---

## Практические сценарии

### Взаимосвязь компонентов

```
Триггер → Пайплайн → [Этапы → [Задачи → Исполнитель]]
                         ↓
                    Артефакты/Кэш → Среда
```

1. **Триггер** инициирует выполнение всего **пайплайна**.
2. **Пайплайн** управляет последовательностью **этапов**.
3. **Задачи** внутри этапов распределяются по доступным **исполнителям**.
4. **Артефакты** передают результаты между этапами, а **кэш** ускоряет установку зависимостей.
5. Финальные задачи разворачивают код в целевой **среде**.
