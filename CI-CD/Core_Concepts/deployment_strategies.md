# Стратегии и модели развертывания

## Определения

- **Модель развертывания (Deployment Model)** — архитектурный подход, определяющий способ доставки изменений в целевую среду. В 2026 году ключевым отличием является не только направление команд (**Push** vs **Pull**), но и уровень автономности (**Autonomous Delivery**).

- **Стратегия развертывания (Rollout Strategy)** — технический метод обновления работающего приложения (например, Blue/Green, Canary). Определяет, как происходит замена версии v1 на v2 с точки зрения трафика и ресурсов.

- **Развертывание (Deployment) vs Выпуск (Release)** — разделение процесса на техническую доставку кода (Deployment) и открытие доступа пользователям к новому функционалу (Release).

- **Progressive Delivery (Прогрессивная поставка)** — метод постепенной раскатки функционала с использованием инструментов управления трафиком, **Feature Flags** и автоматизированной проверки показателей здоровья (Health Checks).

- **Autonomous Delivery (Автономная доставка, 2026)** — использование AI-агентов для непрерывного анализа рисков, автоматического принятия решений о раскатке трафика и немедленного отката при обнаружении аномалий (Causal AI Analysis).

## Основные концепции

### Модели развертывания: Push vs Pull

#### Push-модель (CI-ориентированная)
CI-пайплайн активно инициирует соединение с целевой средой.
- **Инструменты:** **[Ansible](../../Ansible/ansible_introduction.md)**, GitLab CI, GitHub Actions.
- **Эволюция 2026:** Широкое использование **OIDC (OpenID Connect)** для беспарольной аутентификации пайплайна в кластерах и облаках, что решает проблему хранения статических секретов.
- **Подробнее:** **[Безопасность в CI/CD](../DevSecOps/devsecops_overview.md)**.

#### Pull-модель (GitOps)
Агент внутри кластера отслеживает состояние Git и синхронизирует среду.
- **Инструменты:** **[ArgoCD](../../GitOps/ArgoCD/argocd_overview.md)**, **[Flux](../../GitOps/flux.md)**.
- **Преимущества:** Нативная защита от **State Drift** (рассинхронизации состояния) и отсутствие необходимости открывать API кластера наружу.
- **Подробнее:** **[Обзор GitOps](../../GitOps/GitOps_overview.md)**.

### Стратегии развертывания

В 2026 году выбор стратегии неразрывно связан с управлением трафиком через **Gateway API**.

| Стратегия | Принцип работы | Риск простоя | Ресурсы | Особенности 2026 |
| :--- | :--- | :--- | :--- | :--- |
| **Recreate** | Удаление v1 → запуск v2. | Высокий | 1x | Только для Dev-сред или несовместимых миграций БД. |
| **Rolling Update** | Поэтапная замена v1 на v2. | Нет | 1.25x | Стандарт Kubernetes (maxSurge). |
| **Blue/Green** | Запуск v2 рядом с v1. | Нет | 2x | Мгновенный откат через переключение Service/Gateway. |
| **Canary** | Раскатка v2 на % трафика. | Нет | 1x+ | Постепенное тестирование. Инструменты: Argo Rollouts, Flagger. |
| **Shadow** | Зеркалирование трафика на v2. | Нет | 2x | Тестирование под реальной нагрузкой без влияния на пользователей. |

#### Управление трафиком: Ingress vs Gateway API
В 2025–2026 годах **Kubernetes Gateway API** стал стандартом де-факто для реализации стратегий раскатки, заменив классический Ingress.
- **Gateway API:** Позволяет декларативно описывать веса трафика (Traffic Splitting) и A/B тестирование на уровне L7 без необходимости внедрения тяжелых Service Mesh в простых сценариях.
- **Интеграция:** Argo Rollouts и Flagger нативно поддерживают Gateway API для управления Canary-выпусками.

### Прогрессивная поставка и AI-верификация
Современный процесс раскатки (Rollout) включает в себя автоматизированный анализ:
1. **Анализ метрик (Analysis Templates):** Автоматическая проверка Error Rate и Latency между шагами Canary.
2. **AI-агенты (Agentic SRE):** Использование специализированных агентов для обнаружения причинно-следственных связей сбоев (Causal AI) и инициации **автономного отката** до того, как сработают стандартные алерты.
3. **FinOps & GreenOps:** Предварительная оценка стоимости ресурсов (Resource Request) и углеродного следа новой версии до начала деплоя.

## Практические сценарии

### Выбор стратегии

1. **Микросервисы с высокими требованиями к SLA:** Использование **Argo Rollouts** с Canary-стратегией и автоматизированной верификацией через Prometheus/Datadog.
2. **Критичные изменения БД:** Стратегия **Expand and Contract** совместно с Blue/Green развертыванием приложения.
3. **Тестирование производительности:** **Shadow Deployment** (зеркалирование) через Istio или Gateway API для проверки новой версии под 100% продуктивной нагрузки.

### Принципы надежности
- **Иммутабельность:** Артефакт (Docker-образ) собирается один раз. Любые изменения конфигурации — это новый релиз.
- **Anti-Affinity:** Настройка правил размещения подов на разных узлах для предотвращения сбоев при Rolling Update.
- **Readiness/Liveness Probes:** Обязательные проверки, без которых ни одна стратегия не обеспечит Zero Downtime.
