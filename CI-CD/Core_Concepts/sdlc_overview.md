# SDLC: Жизненный цикл разработки программного обеспечения

## Определения

- **SDLC (Software Development Life Cycle)** — жизненный цикл разработки программного обеспечения. Это структурированный процесс, описывающий этапы создания ПО от зарождения идеи до вывода из эксплуатации. Цель SDLC — обеспечить предсказуемое качество, соблюдение сроков и бюджета при минимизации рисков.

- **Жизненный цикл ПО** — полный период существования программного продукта, включающий проектирование, разработку, тестирование, внедрение, эксплуатацию и снятие с поддержки (**EOL — End of Life**).

## Основные концепции

### Фазы классического SDLC

Традиционный жизненный цикл состоит из последовательных этапов:

1. **Анализ требований (Requirements)**
   - Сбор и документирование бизнес-требований.
   - Определение целей, ограничений и ресурсов.
   - Результат: **PRD (Product Requirements Document)**.

2. **Проектирование (Design)**
   - Создание архитектуры системы, проектирование БД и API.
   - Выбор стека технологий.
   - Результат: **ADR (Architecture Decision Record)**, схемы и макеты.

3. **Разработка (Implementation)**
   - Написание исходного кода.
   - Проведение Code Review и статического анализа (**SAST**).
   - Результат: код в системе контроля версий **([Git](../../Git/git_basics.md))**.

4. **Тестирование (Testing)**
   - Проверка функциональности (Unit, интеграционные, системные тесты).
   - Подробнее об уровнях: **[Типы и уровни тестирования](../../Testing/testing_types_unit_integration_e2e.md)**.
   - Результат: отчеты о тестировании и исправленные дефекты.

5. **Развертывание (Deployment)**
   - Выпуск продукта в продуктивную среду (production).
   - Настройка инфраструктуры и автоматизация деплоя.

6. **Эксплуатация и поддержка (Maintenance)**
   - Мониторинг и обеспечение **[SLA](../../Concepts/sre_concepts_main.md)**.
   - Исправление ошибок и выпуск обновлений.
   - Внедрение **наблюдаемости (Observability)** для проактивного выявления проблем.

7. **Вывод из эксплуатации (Retirement)**
   - Миграция данных и отключение систем.

### Современные подходы: Shift-Left и Shift-Right

В современных Agile и DevOps методологиях границы между фазами размываются, а ключевые активности смещаются по временной шкале:

- **Shift-Left (Сдвиг влево):** Перенос тестирования и проверок безопасности на самые ранние этапы цикла (планирование и разработка). Позволяет находить ошибки раньше, когда их исправление стоит дешевле.
- **Shift-Right (Сдвиг вправо):** Расширение контроля качества на этап эксплуатации. Включает тестирование в продакшене (Canary, A/B тесты), мониторинг реального пользовательского опыта и хаос-инжиниринг.

### Модели SDLC

| Модель | Описание | Когда применять |
| :--- | :--- | :--- |
| **Waterfall** | Линейная последовательность фаз. | Проекты со стабильными, жесткими требованиями. |
| **Agile** | Итеративная разработка короткими циклами. | Продуктовая разработка, стартапы. |
| **V-Model** | Тестирование планируется параллельно разработке. | Критически важные системы (медицина, авиация). |
| **Spiral** | Итерации с глубоким анализом рисков. | Крупные и крайне рискованные проекты. |
| **DevOps** | Непрерывный цикл (бесконечность) интеграции и доставки. | SaaS, высоконагруженные веб-сервисы. |

### Связь SDLC и CI/CD

**CI/CD** — это техническая автоматизация этапов разработки, тестирования и развертывания внутри SDLC. Подробности см. в **[CI/CD: Обзор](../ci_cd_overview.md)**.

```
SDLC (Весь процесс):
  Идея → Анализ → Проектирование → [Разработка → Тестирование → Деплой] → Эксплуатация

CI/CD (Автоматизация):
                                  └────────── Pipeline ──────────┘
```

### Безопасность (DevSecOps)

Интеграция безопасности в SDLC подразумевает проверки на каждом этапе:
- **Планирование:** Threat Modeling (моделирование угроз).
- **Разработка:** SAST и проверка секретов.
- **Тестирование:** DAST (динамический анализ) и SCA (анализ зависимостей).
- **Эксплуатация:** Мониторинг безопасности и управление уязвимостями.

Подробнее: **[DevSecOps: Обзор](../DevSecOps/devsecops_overview.md)**.

## Практические сценарии

### Выбор модели разработки

1. **Жесткие требования и бюджет:** Waterfall или V-Model.
2. **Неопределенность и потребность в обратной связи:** Agile (Scrum/Kanban).
3. **Высокая скорость релизов и автоматизация:** DevOps/SRE.

### Метрики эффективности

Для оценки зрелости SDLC используются следующие показатели:

| Метрика | Описание |
| :--- | :--- |
| **Lead Time for Changes** | Время от коммита до попадания кода в production. Подробнее: **[DORA метрики](./dora_metrics.md)**. |
| **Cycle Time** | Время работы над задачей (от "In Progress" до завершения). |
| **Defect Density** | Плотность ошибок (количество багов на единицу кода). |
| **MTTR** | Среднее время восстановления сервиса после сбоя. |

## Дополнительная информация

### Сравнение SDLC и CI/CD

| Аспект | SDLC | CI/CD |
| :--- | :--- | :--- |
| **Масштаб** | Весь процесс управления продуктом. | Автоматизация технической доставки. |
| **Фокус** | Методология и организация. | Инструменты и пайплайны. |
| **Участники** | Все роли (от бизнеса до Ops). | Инженеры, тестировщики, DevOps. |
