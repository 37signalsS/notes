# SDLC: Жизненный цикл разработки программного обеспечения

## Определения

**SDLC (Software Development Life Cycle — жизненный цикл разработки программного обеспечения)** — структурированный процесс создания программного обеспечения, описывающий этапы от первоначальной идеи до вывода из эксплуатации. Цель — обеспечение предсказуемого качества, соблюдение сроков и бюджета, а также эффективное управление рисками.

**Жизненный цикл ПО** — полный период существования программного обеспечения: от проектирования и разработки через эксплуатацию до снятия с поддержки (EOL — End of Life).

## Основные концепции

### Фазы классического SDLC

Классический (каскадный) жизненный цикл состоит из последовательных фаз:

1. **Планирование и анализ требований (Requirements)**
   - Сбор, анализ и документирование требований заинтересованных сторон (stakeholders)
   - Определение бизнес-целей, ограничений, сроков и бюджета
   - Результат: документ с требованиями (PRD — Product Requirements Document)

2. **Проектирование (Design)**
   - Архитектурное проектирование системы
   - Проектирование баз данных, API, интерфейсов
   - Выбор технологического стека
   - Результат: запись архитектурного решения (ADR — Architecture Decision Record), схемы, макеты

3. **Разработка (Implementation / Development)**
   - Написание кода согласно утвержденному дизайну
   - Code review, статический анализ (SAST — Static Application Security Testing)
   - Unit-тестирование
   - Результат: исходный код в системе контроля версий **([Git](../../Git/git_basics.md))**

4. **Тестирование (Testing)**
   - Интеграционное тестирование
   - Системное тестирование
   - Приемочное тестирование (UAT — User Acceptance Testing)
   - Результат: отчеты о тестировании, список дефектов. Подробнее об уровнях: **[Типы и уровни тестирования](../../Testing/testing_types_unit_integration_e2e.md)**.

5. **Развертывание (Deployment)**
   - Выпуск в продуктивное окружение (production)
   - Настройка инфраструктуры, мониторинга, логирования
   - Результат: работающее приложение, доступное пользователям

6. **Эксплуатация и сопровождение (Maintenance)**
   - Мониторинг работоспособности
   - Исправление дефектов, выпуск патчей
   - Обновление зависимостей
   - Результат: стабильная работа, **[SLA (Service Level Agreement — соглашение об уровне обслуживания)](../../Concepts/sre_concepts_main.md)**

7. **Вывод из эксплуатации (Retirement / EOL)**
   - Миграция данных, отключение сервисов
   - Информирование пользователей
   - Архивирование кода и документации
   - Результат: корректное завершение жизненного цикла

### Модели SDLC

| Модель | Описание | Преимущества | Недостатки | Когда применять |
|:-------|:---------|:-------------|:-----------|:----------------|
| **Waterfall (Каскадная)** | Последовательные фазы без возврата | Простота, предсказуемость, четкая документация | Негибкость, позднее обнаружение ошибок | Стабильные требования, регулируемые отрасли |
| **Agile (Гибкая)** | Итеративная разработка короткими циклами (спринтами) | Гибкость, быстрая обратная связь, адаптивность | Сложность долгосрочного планирования | Изменяющиеся требования, стартапы |
| **Iterative** | Повторяющиеся циклы с постепенным улучшением | Ранний выпуск рабочей версии | Риск разрастания объема (scope creep) | Проекты с нечеткими требованиями |
| **Spiral** | Итерации с акцентом на управление рисками | Раннее выявление рисков | Сложность, высокие накладные расходы | Крупные, рискованные проекты |
| **V-Model** | Каждая фаза разработки имеет соответствующую фазу тестирования | Высокое качество, раннее планирование тестов | Жесткость, как у Waterfall | Системы с высокими требованиями к надежности |
| **DevOps** | Непрерывная интеграция, доставка и развертывание | Быстрый time-to-market, автоматизация | Требует зрелой культуры и инструментов | Продуктовые команды, SaaS |

### SDLC и CI/CD

CI/CD (Continuous Integration / Continuous Delivery — непрерывная интеграция / непрерывная доставка) — это **автоматизация технических аспектов** фаз разработки, тестирования и развертывания в рамках SDLC.

Подробное описание концепций и процессов CI/CD приведено в документе **[CI/CD: Обзор](../ci_cd_overview.md)**.

```
SDLC (полный цикл):
  Планирование → Проектирование → Разработка → Тестирование → Развертывание → Эксплуатация

CI/CD (автоматизация внутри SDLC):
                    ┌─ CI ──┐         ┌────── CD ──────┐
  Планирование → Проектирование → [Коммит → Сборка → Тесты → Деплой] → Эксплуатация
                                    ←────── Feedback Loop ──────→
```

### Безопасность в SDLC (DevSecOps)

DevSecOps интегрирует проверки безопасности на каждом этапе SDLC:

| Фаза SDLC | Практики безопасности |
|:----------|:----------------------|
| Планирование | Анализ угроз (threat modeling), определение требований к безопасности |
| Проектирование | Обзор архитектуры безопасности, выбор безопасных зависимостей |
| Разработка | SAST, проверка секретов, линтинг безопасности |
| Тестирование | DAST (Dynamic Application Security Testing), SCA (Software Composition Analysis), анализ Docker-образов |
| Развертывание | Сканирование инфраструктуры (IaC — Infrastructure as Code), проверка конфигураций |
| Эксплуатация | Непрерывный мониторинг, управление уязвимостями, реагирование на инциденты |

Подробная информация: [DevSecOps: обзор методологии](../DevSecOps/devsecops_overview.md)

## Практические сценарии

### Выбор модели SDLC

**Критерии выбора:**

1. **Стабильность требований:**
   - Стабильные → Waterfall, V-Model
   - Изменяющиеся → Agile, Iterative

2. **Критичность системы:**
   - Высокая (медицина, авиация) → V-Model, Spiral
   - Средняя/низкая → Agile, DevOps

3. **Размер команды и проекта:**
   - Большая распределенная команда → Waterfall (с четкой документацией)
   - Небольшая кросс-функциональная команда → Agile, DevOps

4. **Time-to-market:**
   - Критичен → Agile, DevOps
   - Не критичен → Waterfall, Spiral

### Метрики эффективности SDLC

| Метрика | Что измеряет | Как улучшить |
|:--------|:-------------|:-------------|
| **Lead Time** | Время от идеи до production | Автоматизация CI/CD, уменьшение размера изменений |
| **Cycle Time** | Время от начала разработки до выпуска | Параллелизм, устранение блокировок |
| **Defect Density** | Количество дефектов на единицу кода | Code review, автоматическое тестирование, SAST |
| **Requirements Volatility** | Частота изменения требований | Улучшение анализа требований, Agile-подход |
| **Test Coverage** | Процент кода, покрытого тестами | Написание тестов до/во время разработки, TDD (Test-Driven Development) |

Формализованные метрики эффективности доставки — [Метрики DORA (DevOps Research and Assessment)](./dora_metrics.md).

### Типичные проблемы и решения

| Проблема | Причина | Решение |
|:---------|:--------|:--------|
| Срыв сроков | Нереалистичное планирование, scope creep | Буферы, Agile-итерации, приоритизация (MoSCoW — Must have, Should have, Could have, Won't have) |
| Низкое качество | Пропуск фаз тестирования, спешка | Автоматизация тестов, code review, CI-gates |
| Проблемы безопасности | Security в конце цикла | Shift Left, DevSecOps, автоматические сканеры |
| Плохая коммуникация | Silos между командами | Кросс-функциональные команды, DevOps-культура |
| Технический долг | Быстрые хаки вместо правильных решений | Рефакторинг в бэклоге, лимиты на tech debt |

## Дополнительная информация

### Сравнение SDLC и CI/CD

| Аспект | SDLC | CI/CD |
|:-------|:-----|:------|
| **Объем** | Полный жизненный цикл ПО | Автоматизация сборки, тестов, деплоя |
| **Фокус** | Процесс, управление, качество | Скорость, надежность, воспроизводимость |
| **Роль** | Стратегическая (что и зачем делать) | Тактическая (как автоматизировать) |
| **Участники** | PM (Project Manager), BA (Business Analyst), Architects, Developers, QA (Quality Assurance), Ops (Operations) | Developers, QA, DevOps Engineers |

CI/CD — это **инструментальная реализация** части SDLC, отвечающая за техническую доставку кода.
