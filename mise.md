# mise — универсальный менеджер версий и исполнитель задач

## Определения

**`mise`** (ранее `rtx`) — это высокопроизводительный полиглотный менеджер версий инструментов, исполнитель задач (task runner) и менеджер переменных окружения, написанный на Rust.

Его главная цель — унифицировать управление версиями инструментов, переменными окружения и скриптами в рамках одного проекта. Это обеспечивает консистентность и воспроизводимость рабочего окружения («Development Environment as Code») как для локальной разработки, так и для CI/CD-систем, решая проблему «на моей машине всё работает».

## Основные концепции

**Основные проблемы, которые решает `mise`:**

*   **Долгая и сложная настройка:** Традиционно требуется ручная установка и управление версиями таких инструментов, как Node.js, Python, Go, Terraform, kubectl.
*   **Конфликты версий:** Разные проекты требуют разные версии одного и того же инструмента.
*   **Несоответствие окружений:** Различия между локальным окружением разработчика и CI/CD-пайплайном.
*   **Сложность существующих решений:** Инструменты вроде Docker, Make или Nix решают проблему частично и могут привносить свои сложности (например, `devbox` основан на `Nix`).
*   **Производительность:** В отличие от `asdf` (написанного на Bash), `mise` практически не вносит задержек при запуске команд или смене директорий благодаря реализации на Rust.

### Установка и активация
`mise` может работать как через механизм шимов (shims), так и через прямую интеграцию с оболочкой (shell activation).

**1. Установка бинарного файла:**
```bash
curl https://mise.jdx.dev/install.sh | sh
```
Инструмент будет установлен в `~/.local/bin/mise`.

**2. Активация в оболочке (рекомендуемый способ):**
Добавьте следующую строку в файл конфигурации вашего shell (например, `~/.bashrc`, `~/.zshrc` или `~/.config/fish/config.fish`):
```bash
# Для bash
eval "$(~/.local/bin/mise activate bash)"
# Для zsh
eval "$(~/.local/bin/mise activate zsh)"
```
Это позволяет `mise` динамически изменять `PATH` при переходе в директорию проекта и автоматически экспортировать переменные окружения.

### Ключевые особенности `mise`
* **Скорость:** Написан на языке Rust, что обеспечивает высокую производительность.
* **Универсальность:** Заменяет множество специализированных инструментов:
  * Менеджеры версий (например, `nvm` для Node.js, `pyenv` для Python).
  * Активаторы окружения (например, `direnv`).
  * Системы запуска задач (например, `make`, `just`, `task`).
* **Независимость от Nix:** В отличие от некоторых альтернатив, `mise` имеет собственную систему управления пакетами, что делает его более простым в освоении и использовании для тех, кто не работает с Nix.
* **Гибкость установки:** Может получать инструменты не только из своего репозитория, но и из различных источников (GitHub Releases, npm, Cargo, Pip, Go).

### Механизм хранения и изоляции
`mise` устанавливает все инструменты в **изолированную директорию внутри домашнего каталога пользователя**. По умолчанию это `~/.local/share/mise/installs/`. Он **никогда не изменяет системные директории** (например, `/usr/bin`, `/usr/local/bin`), что исключает конфликты с глобально установленными утилитами и не требует прав суперпользователя (`sudo`).

Например, если вы указываете `terraform = "1.8.4"`, `mise` скачает эту версию и разместит её по пути типа:
`~/.local/share/mise/installs/terraform/1.8.4/bin/terraform`

### Управление версиями и механизм шимов
`mise` использует умный механизм, основанный на переменной окружения `PATH` и так называемых "шимах" (shims).

1.  **Личная "библиотека" инструментов:** Когда `mise` видит требование к определённой версии инструмента (`terraform = "1.8.4"`), он скачивает её и сохраняет в вашей личной "библиотеке" (`~/.local/share/mise/installs/`). Если потребуется другая версия (`terraform = "1.7.0"`), она будет скачана и сохранена рядом. Таким образом, у вас может быть несколько версий одного и того же инструмента.
2.  **Переменная окружения `PATH`:** При установке `mise` добавляет специальную директорию `~/.local/share/mise/shims` **в самое начало** вашей переменной `PATH`. Эта директория `shims` содержит маленькие исполняемые файлы (которые также называются "шимами") с теми же именами, что и ваши инструменты (например, `terraform`, `node`, `kubectl`).
3.  **Принцип работы шима:**
    *   Когда вы вводите команду (например, `terraform`) в терминале, ваша оболочка (shell) начинает искать исполняемый файл в директориях, перечисленных в `PATH`, начиная с первой.
    *   Она находит и запускает "шим" `~/.local/share/mise/shims/terraform`.
    *   Этот "шим" — это не сам инструмент, а небольшая программа-диспетчер. Она анализирует текущий контекст (например, наличие файла `.mise.toml` в вашей текущей директории), определяет, какая версия `terraform` должна быть активна (например, `1.8.4`).
    *   Затем "шим" мгновенно передает выполнение команды настоящему исполняемому файлу `terraform` по его реальному пути (`~/.local/share/mise/installs/terraform/1.8.4/bin/terraform`).

### Бэкенды и реестры (Plugins)
`mise` поддерживает несколько источников установки:
*   **Core:** Встроенная поддержка Node.js, Python, Go, Rust, Ruby и др.
*   **asdf:** Полная совместимость с плагинами `asdf`.
*   **vfox / aqua:** Поддержка альтернативных менеджеров пакетов.
*   **Прямые ссылки:** Установка через `cargo:`, `npm:`, `pipx:`, `go:`, `ubicloud:` или GitHub Releases.

Примеры установки:
```bash
mise use cargo:ripgrep   # Установка через Rust Cargo
mise use npm:prettier    # Установка через NPM
mise use go:github.com/golangci/golangci-lint/cmd/golangci-lint@latest
```

### Приоритет конфигураций
`mise` ищет настройки в следующем порядке (от высшего к низшему):
1.  Переменные окружения (например, `MISE_NODE_VERSION`).
2.  Локальный файл проекта `.mise.toml` (или `.rtx.toml`).
3.  Файл `.tool-versions` (совместимость с `asdf`).
4.  Глобальный конфиг пользователя `~/.config/mise/config.toml`.
5.  Системный конфиг `/etc/mise/config.toml`.

### Безопасность и "доверие" (Trust)
Файлы конфигурации `.mise.toml` могут содержать задачи (`[tasks]`) и изменять переменные окружения, что потенциально позволяет выполнять произвольный код.
*   **mise trust:** При первом обнаружении нового или измененного `.mise.toml` инструмента заблокирует выполнение задач и экспорт переменных до подтверждения пользователем.
*   **Команда:** `mise trust` или `mise trust .mise.toml`.
*   **Рекомендация:** Никогда не выполняйте `mise trust` для файлов из непроверенных источников.

### Проверка механизмов работы
* **`which <tool_name>`:** Покажет путь к "шиму" (например, `which terraform` может вернуть `~/.local/share/mise/shims/terraform`).
* **`mise which <tool_name>`:** Покажет путь к реальному исполняемому файлу, используемому `mise` (например, `mise which terraform` может вернуть `~/.local/share/mise/installs/terraform/1.8.4/bin/terraform`).
* **`echo $PATH`:** Покажет порядок директорий в вашей переменной `PATH`, демонстрируя, что `shims`-директория находится в начале.

## Практические сценарии

Основное применение `mise` в DevOps — стандартизация и автоматизация рабочего окружения для всей команды и CI/CD-пайплайнов. Это позволяет декларативно управлять инструментами и задачами, решая проблему «у меня на машине работает» при работе с кодом инфраструктуры.

Ниже представлен пример для репозитория, содержащего конфигурации Terraform и плейбуки Ansible.

**Пример 1: Файл `.mise.toml`**
Создайте в корне репозитория файл `.mise.toml` для определения всех необходимых инструментов и задач:

```toml
# .mise.toml
[tools]
terraform = "1.8.4"
terragrunt = "0.58.11"
ansible = "9.5.1" # mise сам установит необходимые зависимости (например, через pipx)

kubectl = "1.29.3"
helm = "3.14.4"
k9s = "0.32.4"

jq = "1.7.1"
yq = "4.44.1"

python = "3.11"

# ==============================================================================
# Определяем задачи (tasks) для упрощения рутинных операций.
# Это эффективная замена Makefiles или набора bash-скриптов.
# ==============================================================================
[tasks]

# Форматирование и проверка кода Terraform в текущей директории
[tasks.tf-lint]
description = "Форматирует и валидирует Terraform код"
run = [
  "terraform fmt -recursive",
  "terraform validate",
]

# Создание плана Terraform (terraform plan)
[tasks.tf-plan]
description = "Создает план изменений Terraform"
run = "terraform plan -out=tfplan"
# Опционально: можно задать рабочую директорию, если код лежит не в корне
# dir = "infrastructure/production/"

# --- Задачи для Ansible ---

[tasks.ansible-lint]
description = "Проверяет синтаксис Ansible плейбука"
run = "ansible-playbook --syntax-check playbook.yml"

# --- Задачи для Kubernetes ---

[tasks.k8s-connect]
description = "Настраивает kubectl для подключения к Yandex Cloud Managed Kubernetes кластеру"
# Пример команды, которую больше не нужно запоминать.
# private = true предотвратит случайное логирование чувствительной информации
run = "yc managed-kubernetes cluster get-credentials --name my-cluster --context k8s-context"
private = true

# --- Комплексная задача для CI/CD ---

[tasks.ci-test]
description = "Задача для CI: проверяет Terraform и Ansible код"
# Зависит от других задач
depends_on = ["tf-lint", "ansible-lint"]
run = "echo 'CI tests passed!'"
```

**Пример 2: Использование в CI/CD (GitHub Actions)**
Те же самые задачи могут быть использованы в CI/CD-пайплайнах, гарантируя, что в CI используются те же версии инструментов, что и у инженеров локально.

```yaml
# .github/workflows/ci.yml
name: CI for Infrastructure
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup mise and tools
        uses: jdx/mise-action@v2
        # mise-action автоматически прочитает .mise.toml и установит все инструменты

      - name: Run Terraform Lint and Validate
        run: mise run tf-lint

      - name: Run Ansible Syntax Check
        run: mise run ansible-lint

      - name: Run CI Tests
        run: mise run ci-test
```

## Дополнительная информация

### Сравнение с альтернативами

| Инструмент | База | Скорость | Task Runner | Особенности |
| :--- | :--- | :--- | :--- | :--- |
| **mise** | Rust | Высокая | Да | Все-в-одном, замена direnv, asdf, make |
| **asdf** | Bash | Низкая | Нет | Огромная экосистема плагинов, медленные шимы |
| **direnv** | Go | Высокая | Нет | Только переменные окружения |
| **devbox** | Nix | Средняя | Да | Базируется на Nix, гарантирует идеальную изоляцию |
