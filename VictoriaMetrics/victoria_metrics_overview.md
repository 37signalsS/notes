# Обзор VictoriaMetrics

VictoriaMetrics — это масштабируемая, высокопроизводительная и экономичная база данных временных рядов (TSDB), предназначенная для долгосрочного хранения метрик и являющаяся эффективной альтернативой Prometheus. Она поддерживает протокол удаленной записи (RemoteWrite) Prometheus и может служить полной заменой стека Prometheus.

## Режимы установки

VictoriaMetrics может быть установлена в двух основных режимах:

*   **Single-node:** Все компоненты собраны в один бинарный файл. Подходит для небольших инсталляций.
*   **Cluster-node:** Компоненты являются отдельными бинарными файлами и запускаются независимо друг от друга, что обеспечивает высокую доступность и горизонтальное масштабирование. Этот режим является более эффективным и предпочтительным для production-сред.

## Компоненты кластерного режима VictoriaMetrics

В кластерном режиме VictoriaMetrics состоит из нескольких ключевых компонентов:

1.  **VM Storage (`vmstorage`):**
    *   Реализует TSDB (Time Series Database), где непосредственно хранятся метрики.
    *   Является stateful-приложением, но может масштабироваться для реализации шардирования данных.

2.  **VM Insert (`vminsert`):**
    *   Принимает данные от Prometheus-серверов через протокол RemoteWrite.
    *   Вставляет данные в `vmstorage`.
    *   Является stateless-приложением, что позволяет легко масштабировать его для повышения отказоустойчивости.
    *   Отвечает за логику шардирования: определяет, в какой конкретный `vmstorage` отправить данные. Это снимает с Prometheus необходимость реализовывать логику работы с шардами.
    *   Поддерживает репликацию данных, вставляя метрики сразу в несколько `vmstorage` для повышения отказоустойчивости.

3.  **VM Select (`vmselect`):**
    *   Извлекает данные из `vmstorage`.
    *   Является stateless-приложением и может быть масштабирован.
    *   Выполняет дедубликацию данных в случае использования репликации в кластере VictoriaMetrics.
    *   Предоставляет API для запросов метрик (например, для Grafana).

4.  **VM Auth (`vmauth`):**
    *   Позволяет настроить аутентификацию и авторизацию для всего кластера VictoriaMetrics.
    *   Обеспечивает логическое разделение `vmstorage` на несколько отдельных баз данных (тенант), аналогично `Namespace` в Kubernetes.
    *   Позволяет создавать различные учетные записи для разных тенантов, гарантируя, что каждый экземпляр Prometheus-сервера будет записывать данные в свой тенант.

## Дополнительные утилиты VictoriaMetrics

VictoriaMetrics также включает ряд полезных утилит:

*   **VM Backup (`vmbackup`):** Утилита для создания резервных копий `vmstorage`. Поддерживает резервное копирование как на файловую систему, так и во внешние облачные провайдеры (например, Google Cloud, Amazon S3).
*   **VM Restore (`vmrestore`):** Утилита для восстановления данных из резервных копий, созданных с помощью `vmbackup`.
*   **VM Alert (`vmalert`):** Аналог Prometheus Alertmanager. Поддерживает тот же синтаксис конфигурационных файлов, что и Alertmanager, что упрощает миграцию. Разработан с учетом решения проблем, присущих стеку Prometheus Alertmanager Grafana. Для его настройки используется консольная утилита `vmalert-cli`.
*   **VM Agent (`vmagent`):** Выполняет роль Prometheus Server, осуществляя скрапинг метрик с различных экспортеров. Имеет такой же синтаксис конфигурационных файлов, как и Prometheus Server, что позволяет использовать его как полную замену Prometheus для сбора метрик.

## Преимущества VictoriaMetrics

*   **Горизонтальное масштабирование и отказоустойчивость:** Благодаря кластерной архитектуре и разделению компонентов, VictoriaMetrics легко масштабируется и обеспечивает высокую доступность.
*   **Долгосрочное хранение:** Эффективно решает проблему долгосрочного хранения метрик, которая является ограничением для Prometheus.
*   **Совместимость с Prometheus:** Полностью поддерживает протокол RemoteWrite и синтаксис конфигурационных файлов Prometheus Alertmanager и Prometheus Server, что облегчает миграцию.
*   **Тенанты:** Позволяет логически разделять данные для разных команд или проектов, обеспечивая изоляцию и безопасность.
*   **Эффективность:** Разработана с учетом оптимизации использования ресурсов и производительности.
