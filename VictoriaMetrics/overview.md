# VictoriaMetrics: Обзор

## 1. Определения

**VictoriaMetrics** — это высокопроизводительная, экономичная и масштабируемая [система мониторинга](./../Concepts/Observability_and_Monitoring/observability_definitions.md) и база данных временных рядов ([TSDB](./../Prometheus/concepts/tsdb.md)). Она часто используется как решение для долгосрочного хранения (Long-Term Storage) метрик [Prometheus](./../Prometheus/overview.md), являясь альтернативой таким системам, как [Thanos](./../Prometheus/scaling/thanos_overview.md) и [Mimir](./../Mimir/mimir_overview.md).

## 2. Базовые концепции

### Режимы работы

VictoriaMetrics может быть установлена в двух режимах:

* **Single-node:** Все компоненты в одном бинарном файле, подходит для небольших инсталляций.
* **Cluster:** Компоненты разворачиваются независимо, обеспечивая высокую доступность и масштабирование. Этот режим предпочтителен для production.

### Ключевые особенности

* **Высокая производительность и эффективность:** VictoriaMetrics оптимизирована для быстрой вставки и выборки данных, а также для эффективного использования ресурсов (CPU, RAM, дисковое пространство). Разработчики заявляют о хорошей производительности даже при использовании медленных HDD-дисков.
* **Протокол `remote_write`:** Легко интегрируется с Prometheus через стандартный механизм [`remote_write`](./../Prometheus/scaling/remote_read_write.md), выступая в роли централизованного хранилища.
* **Горизонтальное масштабирование:** Компоненты системы могут быть развернуты в кластере для обеспечения высокой доступности и масштабируемости.
* **Сжатие данных:** Эффективно сжимает данные для экономии дискового пространства, сохраняя при этом полную гранулярность (в отличие от downsampling'а в Thanos).
* **MetricsQL:** Предлагает расширенный язык запросов `MetricsQL`, который обратно совместим с [PromQL](./../Prometheus/concepts/promql/selectors_operators.md), но добавляет новые функции для более удобного анализа данных.
* **Мульти-тенатность:** Компонент `vmauth` позволяет логически разделять данные для разных команд или проектов, обеспечивая изоляцию.
* **Дедупликация:** Умеет выполнять дедупликацию данных при сборе метрик от нескольких реплик Prometheus.

### Архитектура кластерного режима

VictoriaMetrics имеет простую и понятную архитектуру, состоящую из нескольких ключевых компонентов.

#### Основные компоненты

1. **`vminsert`**
    * **Назначение:** Компонент, отвечающий за прием данных (stateless).
    * **Функции:**
        * Принимает данные от Prometheus по протоколу `remote_write`.
        * Распределяет (шардирует) входящие данные между доступными узлами `vmstorage`.
        * Выполняет дедупликацию метрик и репликацию на лету.
        * Легко масштабируется горизонтально за балансировщиком нагрузки.

2. **`vmstorage`**
    * **Назначение:** Основной компонент хранения данных (stateful).
    * **Функции:**
        * Реализует TSDB, хранит временные ряды на локальном диске.
        * Отвечает за сжатие данных.
        * Масштабируется путем добавления новых узлов в кластер для шардирования.

3. **`vmselect`**
    * **Назначение:** Компонент для выполнения запросов (stateless).
    * **Функции:**
        * Принимает запросы на `MetricsQL` или `PromQL`.
        * Запрашивает необходимые данные у всех узлов `vmstorage`.
        * Агрегирует результаты и возвращает их клиенту (например, [Grafana](../Grafana/grafana_overview.md)).
        * Выполняет дедупликацию данных при чтении.
        * Легко масштабируется горизонтально.

4. **`vmauth`**
    * **Назначение:** Прокси для аутентификации и авторизации.
    * **Функции:**
        * Обеспечивает логическое разделение (тенанты) хранилища.
        * Позволяет разным экземплярам Prometheus писать данные в изолированные пространства.

#### Дополнительные компоненты

* **`vmagent`** — легковесный агент для сбора метрик. Может полностью заменить [Prometheus](../Prometheus/overview.md) в роли scraper'а. Собирает метрики с различных источников и отправляет их в одно или несколько хранилищ VictoriaMetrics или другие системы, поддерживающие `remote_write`.
  * **Ключевые особенности:**
    * Поддержка конфигурации Prometheus (тот же формат `scrape_configs`).
    * Stateless — не хранит данные локально (кроме буферизации при сбоях), что позволяет легко масштабировать как `Deployment` в Kubernetes.
    * Гибкая репликация и шардинг — может отправлять метрики в несколько хранилищ, имеет продвинутые возможности фильтрации и модификации меток.
    * Решение проблемы с перезагрузкой — при изменении конфигурации перезапускается только `vmagent`, а основной сервис хранения работает без прерываний.
  * **Мониторинг:** Веб-интерфейс (порт `8429`) с эндпоинтом `/targets` для проверки состояния таргетов.

* **`vmalert`** — выполняет запросы к VictoriaMetrics (или другой `PromQL`-совместимой системе), вычисляет правила алертинга и отправляет уведомления в [Alertmanager](../Prometheus/alertmanager.md). Подробнее: [vmalert](./vmalert_overview.md).

* **`vmbackup` / `vmrestore`** — утилиты для создания и восстановления резервных копий данных из `vmstorage`. Поддерживают локальную ФС и объектные хранилища (S3, GCS).

## 3. Практические сценарии

### Сравнение с Thanos

| Характеристика | VictoriaMetrics | Thanos |
| :--- | :--- | :--- |
| **Основной метод интеграции** | `remote_write` API | `Sidecar` + `Object Storage` |
| **Хранилище данных** | Локальные диски узлов `vmstorage` | Объектное хранилище (S3, GCS, Azure Blob Storage) |
| **Оптимизация хранения** | Сжатие данных (сохранение гранулярности) | Downsampling (понижение гранулярности) |
| **Язык запросов** | `MetricsQL` (расширение `PromQL`) | `PromQL` |
| **Модель разработки** | Коммерческая компания с Open Source версией. Может привести к vendor-lock, особенно при использовании `MetricsQL`. | Проект под эгидой CNCF. Полностью открытый и управляемый сообществом. |
| **Сложность** | Считается более простой в развертывании и эксплуатации. | Может быть более сложной из-за большего количества компонентов и зависимости от Object Storage. |

## 4. Дополнительная информация

VictoriaMetrics интегрируется с экосистемой мониторинга: [Prometheus](../Prometheus/overview.md) (совместимость через `remote_write` API), [Grafana](../Grafana/grafana_overview.md) (datasource через Prometheus-compatible API), [Alertmanager](../Prometheus/alertmanager.md) (получает алерты от vmalert), [Kubernetes](../Kubernetes/kubernetes_overview.md) (рекомендуемая платформа для оркестрации кластера).
