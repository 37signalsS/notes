# VictoriaMetrics — обзор

**Надёжность: 10** (SSoT + данные 2024–2026)

## Определения

**VictoriaMetrics** — это высокопроизводительная, экономичная и горизонтально масштабируемая платформа для сбора и хранения данных наблюдаемости (Observability). Изначально разработанная как база данных временных рядов (TSDB) для метрик, к 2026 году система эволюционировала в универсальный стек, объединяющий метрики, логи и трейсы.

VictoriaMetrics является стандартом де-факто для долгосрочного хранения (Long-Term Storage, LTS) в экосистеме [Prometheus](./../Prometheus/overview.md), предлагая более простую эксплуатацию и высокую плотность упаковки данных по сравнению с [Thanos](./../Prometheus/scaling/thanos_overview.md) и [Mimir](./../Mimir/mimir_overview.md).

## Базовые концепции

### Режимы работы

1. **Single-node:** все функции в одном бинарном файле. Идеально для небольших систем (< 1 млн точек в секунду) и простоты управления.
2. **Cluster:** распределённая архитектура из независимых компонентов. Обеспечивает высокую доступность (HA), масштабирование до сотен миллионов метрик в секунду и мульти-тенантность.

### Ключевые особенности

* **Экстремальная эффективность:** агрессивное сжатие данных (в 10–15 раз лучше стандартных TSDB) и низкое потребление ресурсов (CPU/RAM). Оптимизирована для работы даже на медленных HDD.
* **MetricsQL:** расширенный язык запросов, полностью совместимый с [PromQL](./../Prometheus/concepts/promql/selectors_operators.md), но добавляющий функции для аналитики, прогнозирования и работы с пропусками в данных.
* **Поддержка современных стандартов:** нативная поддержка [OpenTelemetry](./../OpenTelemetry/architecture_signals.md), Prometheus Native Histograms и автоматическая дедупликация данных от HA-пар Prometheus.
* **Мульти-тенантность:** изоляция данных для разных проектов или команд через идентификаторы `accountID:projectID` в URL.

### Единая платформа наблюдаемости (Unified Observability)

К 2026 году VictoriaMetrics включает в себя специализированные решения для всех типов сигналов:
* **VictoriaLogs:** масштабируемая система управления логами. Отличается высокой скоростью поиска и минимальными затратами на хранение за счёт отсутствия тяжелых индексов (схема schema-less).
* **VictoriaTraces:** (GA с 2026) полнофункциональное хранилище трейсов, совместимое с API Tempo и Jaeger.
* **vmanomaly:** модуль на базе машинного обучения (AI) для автоматического обнаружения аномалий в поведении метрик без ручной настройки порогов.

### Архитектура кластерного режима

#### Основные компоненты

1. **`vminsert`**
    * Принимает данные по протоколам `remote_write`, OpenTelemetry, InfluxDB и др.
    * Распределяет данные между узлами `vmstorage`.
    * **Обновление 2026:** поддержка «умной» маршрутизации (slowness-based rerouting) — обход медленных или перегруженных узлов хранения для минимизации задержек на запись.

2. **`vmstorage`**
    * Хранит данные на диске. Не имеет разделяемого состояния (Shared-Nothing Architecture).
    * Автоматически переходит в режим read-only при критическом заполнении диска.

3. **`vmselect`**
    * Выполняет запросы MetricsQL/PromQL, агрегируя данные со всех `vmstorage`.
    * Оптимизирован для выполнения тяжелых запросов за счёт многоуровневого кэширования.

4. **`vmauth`**
    * Прокси-сервер для аутентификации (JWT, OIDC, Basic Auth) и маршрутизации запросов между тенантами.

#### Дополнительные компоненты

* **`vmagent`** — агент для сбора метрик (scraper). Может заменять Prometheus. Поддерживает сложную фильтрацию, переименование меток и буферизацию данных на диске при обрыве связи с центральным хранилищем.
* **`vmalert`** — выполнение правил алертинга. Может использовать в качестве источника данных не только метрики VictoriaMetrics, но и логи из VictoriaLogs.
* **`vmbackup` / `vmrestore`** — утилиты для инкрементального резервного копирования в S3, GCS или локальное хранилище.

## Практические сценарии

### Сравнение с альтернативами

| Характеристика | VictoriaMetrics | Thanos | Grafana Mimir (v3.x) |
| :--- | :--- | :--- | :--- |
| **Сложность** | Низкая (единый стек) | Высокая (много компонентов) | Средняя |
| **Хранилище** | Локальные диски / EBS | Объектное (S3/GCS) | Объектное (S3/GCS) |
| **Сжатие данных** | Экстремальное | Среднее (через Downsampling) | Высокое |
| **Интеграция** | `remote_write` | Sidecar / Receiver | `remote_write` |
| **Типы данных** | Метрики, Логи, Трейсы | Метрики | Метрики |
| **AI/Аномалии** | Встроено (vmanomaly) | Нет | Grafana Machine Learning |

## Дополнительная информация

VictoriaMetrics рекомендуется использовать в Kubernetes через **VictoriaMetrics Operator**, который автоматизирует деплой, обновление и управление правилами алертинга через [VMRule](./vmalert_rules_management_with_manifests.md).
