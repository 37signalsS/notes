Ceph is a software that creates a distributed fault-tolerant object storage. Ceph does not require special hardware. Ordinary servers with network cards and disks are sufficient. Internally, Ceph stores data as objects, but provides clients with access in various ways, such as RBD, a block device with thin provisioning and snapshots support. CephFS is a distributed POSIX-compatible file system. And Rados Gateway provides S3 and Swift compatible RESTful interface. CephFS can be imagined as a shared disk connected simultaneously to all servers, and all servers work with this disk. RBD as a virtual hard drive connected to a server, and the server works with this disk exclusively. These two methods are provided by the operating system. Your application may not even realize that the files are located somewhere far away. It works with them as if they are local. To work with Rados Gateway, your application must be able to use the appropriate interface. In this lecture, we will use CephFS and RBD.

Что же представляет из себя цеф с точки зрения администратора?
 Поверхоперационной системы работают демоны цефа, выполняющие различные роли кластера.
 Есть несколько типов демонов, но вот основные, которые нам понадобятся.
 Mono - демон мониторинга, модуль управления, точка подключения клиентов.
 OSD - демон хранения, занимается хранением данных.
 MDS - сервер методанных, нужен нам, когда мы используем цеф FFS.
 И менеджер - демон менеджер, который используется для мониторинга ресурсов и выдачи метрик.
 Соответственно, в зависимости от того, какие именно демоны запущены на сервере,
 сервер может выступать в разных ролях. Один сервер может быть сервером мониторинга,
 и в то же время сервером хранения данных. А другой сервер может хранить данные и выступать
 в роли сервера MDS. Каким образом цеф хранит данные? Для организации хранения данных используются
 пулы. На слайде - это большие цветные прямоугольники. Это такая логическая абстракция, которая имеет
 набор различных параметров. Таких, как size, фактор репликации. Показывает, сколько копить данных нам
 надо хранить. MinSize - минимальное количество живых реплик, который необходимо для работы
 пулы, о роли и права доступа. Pgnum - количество Placement Group. На слайде - это такие квадратики
 внутри пулов. Placement Group - это связующее звено между физическим уровнем хранения данных дисками
 и логической организацией пулами. Пулы состоят из Placement Group. В Placement Group хранятся объекты
 данных. На слайде - это такие кружочки внутри квадратиков. В зависимости от фактора репликации
 Placement Group хранит объекты на требуемое количестве OSD. Например, при size равном 3,
 Placement Group хранит 3 копий данных на трех разных OSD. OSD - это демон хранилища. В простейшем
 случае каждый демон хранит данные на отдельно блочном устройстве, грубо говоря, на жестком диске.
 Минимальный размер кластера - это один монитор и одна OSD. Но минимально необходимое количество для
 обеспечения отказа устойчивости - это три монитора и три OSD. Соответственно, когда мы будем
 устанавливать кластерцев, мы будем использовать три сервера, и на каждом из серверов мы запустим
 по одному экземпляру каждого типа демона. С простыми вещами закончены. Теперь давайте
 посмотрим на более сложную штуку, которую называется crush. Я зачитаю. Карта репликаций,
 управляемых масштабируемым хешированием. Контроллер Replication Under Scalable Hashing. Алгоритм crush
 позволяет клиентам цефа самостоятельно рассчитывать, на каком именно OSD надо хранить данные. И общаться
 с этим OSD напрямую. Такой подход позволяет цефу избежать единой точки отказа и избежать проблем
 с физическими лимитами на производительность отдельных серверов. Как вы видите на слайде,
 изначально в карте crush записано распределение OSD по отдельным серверам. Также в карту вы
 можете добавить распределение по стойкам, дата центром и лучам электропитания. Настроить правила
 алгоритмы crush таким образом, что отключение одной стойки с серверами не приводило бы к
 потере всех копий данных. Также карты crush можно использовать для создания пула,
 в которой будут размечать данные только на быстрых серверах или только на медленных. В случае
 больших и сложных кластеров автора цефа категорически советуют создавать свои собственные правила
 и свою собственную карту crush, потому что дефолтные настройки хорошо работают только в самых
 простых случаях.
