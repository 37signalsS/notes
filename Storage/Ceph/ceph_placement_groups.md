# Расчет количества Placement Group (PG) в Ceph

Вычисление оптимального количества Placement Group (PG) является одной из сложных задач при настройке Ceph. Ключевая сложность заключается в необходимости найти баланс между количеством PG, хранящихся на одном OSD, и их размером.

*   **Много PG на OSD:** Требует больше оперативной памяти (RAM) для хранения информации об их расположении.
*   **Мало PG на OSD:** Приводит к увеличению размера каждой PG, что замедляет процедуру ребалансировки кластера, так как перемещается больший объем данных.

Эмпирическое правило для OSD: **1 ГБ RAM на 1 ТБ дискового пространства**.

## Формула для расчета общего количества PG

Для расчета общего количества PG в кластере используется следующая формула, которая стремится к значению **100-300 PG на OSD**. Калькуляторы часто используют 100 как базовое значение.

```
Total PGs = (Total number of OSDs * 100) / max_replication_factor
```

**Пример:**
Для кластера с 3 OSD и фактором репликации `3`:
`Total PGs = (3 * 100) / 3 = 100`
Таким образом, для всего кластера рекомендуется иметь около 100 PG.

## Распределение PG по пулам

Общее количество PG необходимо распределить между пулами.

### Простой подход (равномерное распределение)

Самый простой способ — разделить общее количество PG поровну между пулами.

**Пример:**
Если у нас есть 3 пула (например, `rbd`, `cephfs_data`, `cephfs_metadata`), то на каждый пул выделяется примерно по 33 PG (100 / 3).

### Проблема простого подхода

Этот подход не учитывает, что в разных пулах может храниться разное количество данных. Если в пуле `cephfs_data` хранится 100 ГБ, а в пуле `rbd` — 10 ГБ, то размер отдельной PG в этих пулах будет отличаться в 10 раз, что неэффективно.

### Рекомендуемый подход (пропорциональное распределение)

Более правильный подход — распределять PG пропорционально **ожидаемому объему данных** в каждом пуле.

*   Если ожидается, что в пуле будет храниться 50% от всей информации в кластере, ему следует выделить 50% от общего количества PG.
*   Если 90% информации, то 90% PG.

Этот подход требует прогнозирования будущего использования дискового пространства.

## Динамическое изменение количества PG

Ceph позволяет динамически изменять количество PG в пуле, что полезно при добавлении новых OSD в кластер.

*   **Увеличение:** Если количество OSD увеличивается, можно увеличить и общее количество PG в кластере, а затем увеличить их число в самых больших пулах.
*   **Уменьшение:** В последних версиях Ceph появилась возможность уменьшать количество PG, если объем данных в пуле сократился.

**Внимание:** Операция изменения количества PG является **дорогостоящей**. Во время этого процесса происходит ребалансировка данных, что создает высокую нагрузку на кластер и может снизить производительность для клиентских операций. Злоупотреблять этой функцией не стоит.

## Использование степеней двойки

Чтобы процесс ребалансировки проходил легче и быстрее, рекомендуется устанавливать количество PG в пулах равным **степеням двойки** (например, 32, 64, 128, 256...).

Когда вы увеличиваете количество PG (например, с 32 до 64), Ceph делит каждую существующую PG ровно пополам. Половина данных остается на месте, а вторая половина переносится в новое место в соответствии с картой CRUSH. Это значительно упрощает и ускоряет процесс ребалансировки.
