# Администрирование и основные команды Ceph

## Проверка статуса кластера: `ceph status`

После успешной установки кластера, первым шагом является проверка его состояния с помощью команды `ceph status`. Вывод этой команды предоставляет полную сводку о здоровье и работе всех компонентов.

```
$ ceph status

  cluster:
    id:     <cluster_id>
    health: HEALTH_OK

  services:
    mon: 3 daemons, quorum node1,node2,node3 (age 2m)
    mgr: ingress1(active, since 2m), standbys: node1, node2
    mds: cephfs:1 {0=ingress1=up:active} 2 up:standby
    osd: 3 osds: 3 up (since 2m), 3 in (since 2m)

  data:
    pools:   2 pools, 64 pgs
    objects: 0 objects, 0 B
    usage:   3.0 GiB used, 27 GiB / 30 GiB avail
    pgs:     64 active+clean
```

### Разбор вывода команды

1.  **`cluster`**:
    *   **`id`**: Уникальный идентификатор кластера в шестнадцатеричном формате.
    *   **`health`**: Общее состояние кластера. `HEALTH_OK` — идеальное состояние, говорящее, что с кластером все в порядке. Другие состояния (например, `HEALTH_WARN`, `HEALTH_ERR`) указывают на проблемы.

2.  **`services`**:
    *   **`mon`**: Состояние демонов-мониторов. `3 daemons, quorum ...` означает, что все три монитора работают и достигли кворума, что необходимо для их корректной работы.
    *   **`mgr`**: Состояние демонов-менеджеров. Один менеджер всегда находится в состоянии `active`, остальные — в `standby`, готовые взять на себя управление в случае отказа активного.
    *   **`mds`**: Состояние серверов метаданных для CephFS. Аналогично менеджерам, один MDS активен, остальные в режиме ожидания. `cephfs:1` говорит о том, что для файловой системы `cephfs` активен один MDS.
    *   **`osd`**: Состояние демонов хранения. `3 osds: 3 up, 3 in` означает, что в кластере 3 OSD, все они запущены (`up`) и участвуют в распределении данных (`in`).

3.  **`data`**:
    *   **`pools`**: Сводка по пулам. `2 pools, 64 pgs` показывает, что в кластере 2 пула и 64 Placement Group (PG) в сумме. (В данном примере Ansible создал два пула для CephFS по 32 PG в каждом).
    *   **`objects`**: Количество объектов, хранящихся в кластере. `0 objects, 0 B` в свежеустановленном кластере.
    *   **`usage`**: Использование дискового пространства.
        *   `3.0 GiB used`: Место, занятое служебными данными Ceph (например, для CephFS).
        *   `27 GiB / 30 GiB avail`: `30 GiB` — это общая "сырая" емкость всех OSD-дисков. `27 GiB` — доступное пространство.
        *   **Важно:** Доступное пространство — это не то же самое, что полезное пространство для записи. Из-за фактора репликации (по умолчанию `size=3`), запись 1 ГБ данных займет 3 ГБ на дисках. Таким образом, из 27 ГБ доступного пространства полезными для записи будут только 9 ГБ (27 / 3).
    *   **`pgs`**: Состояние Placement Group.
        *   `64 active+clean`: Идеальное состояние. Все 64 PG активны и "чисты" (все реплики в порядке).
        *   При проблемах (ребалансировка, восстановление) здесь будут отображаться другие состояния PG (например, `recovering`, `backfilling`, `degraded`).

## Подключение и работа с RBD-образами

Для использования RBD-образов на клиентских машинах необходимо выполнить ряд шагов.

1.  **Установка клиентского ПО Ceph:**
    На клиентской машине, которая будет работать с RBD-образами, необходимо установить клиентское ПО Ceph. Рекомендуется использовать ту же версию Ceph, что и на кластере.
    ```bash
    # Пример для CentOS: установка репозитория и пакета Ceph
    sudo yum install -y centos-release-ceph-luminous # Замените luminous на актуальный релиз
    sudo yum install -y ceph-common
    ```
    Пакет `ceph-common` установит необходимые утилиты и зависимости.

2.  **Настройка клиента (ceph.conf и keyring):**
    Для подключения к кластеру Ceph клиентской машине потребуется информация о мониторах кластера и ключ доступа.
    *   **`ceph.conf`**: Файл конфигурации Ceph, содержащий секцию `[global]` с `mon_host`, где перечислены IP-адреса мониторов кластера.
    *   **`ceph.client.<user>.keyring`**: Файл с токеном доступа для пользователя, от имени которого будет производиться подключение. Этот файл должен находиться в каталоге `/etc/ceph/`.

    ```bash
    # Пример содержимого ceph.conf на клиенте
    # /etc/ceph/ceph.conf
    [global]
    mon_host = 172.21.0.10,172.21.0.11,172.21.0.12 # IP-адреса ваших мониторов
    ```
    Keyring файл будет автоматически найден Ceph, если он назван по шаблону `ceph.client.<имя_пользователя>.keyring`.

3.  **Маппинг RBD-образа:**
    Для того чтобы RBD-образ стал доступен как блочное устройство, его необходимо "замапить".
    ```bash
    sudo rbd map <имя_образа> --pool <имя_пула> --id <имя_пользователя>
    ```
    *   `<имя_образа>`: Название RBD-образа (например, `disk1`).
    *   `<имя_пула>`: Пул, в котором находится RBD-образ (например, `kube`).
    *   `<имя_пользователя>`: Имя пользователя Ceph (например, `user`). Ceph автоматически добавит префикс `client.` и найдет соответствующий keyring файл.

    **Пример:**
    ```bash
    sudo rbd map disk1 --pool kube --id user
    ```

4.  **Обработка ошибок `RBD image features set mismatch`:**
    Если вы столкнулись с ошибкой `RBD image features set mismatch`, это означает, что ядро вашей клиентской системы не поддерживает все функции RBD, включенные в образе. Ceph предложит команду для отключения этих функций.
    ```bash
    rbd feature disable <имя_пула>/<имя_образа> <список_фич_для_отключения>
    ```
    Эту команду необходимо выполнить на сервере, где есть административный доступ к кластеру Ceph.
    **Пример:**
    ```bash
    sudo rbd feature disable kube/disk1 layering, striping, ... # Пример фич для отключения
    ```
    После отключения несовместимых функций на кластере, повторите команду `rbd map` на клиенте.

5.  **Создание файловой системы на RBD-устройстве:**
    После успешного маппинга RBD-образ будет доступен как блочное устройство (например, `/dev/rbd0`). На нем необходимо создать файловую систему.
    ```bash
    sudo mkfs.ext4 /dev/rbd0
    ```

6.  **Монтирование файловой системы:**
    Создайте точку монтирования и смонтируйте RBD-устройство.
    ```bash
    sudo mkdir /mnt/rbd
    sudo mount /dev/rbd0 /mnt/rbd
    ```

7.  **Проверка монтирования:**
    ```bash
    df -h
    ```
    Вы увидите смонтированное устройство и его размер. Теперь вы можете записывать данные в `/mnt/rbd`.

8.  **Автоматическое монтирование:**
    Для автоматического монтирования RBD-образа при загрузке системы, его сначала необходимо замапить (например, через `rbdmap.service`), а затем добавить запись для самого устройства (например, `/dev/rbd0`) в `/etc/fstab`. Процесс аналогичен монтированию CephFS, где ключевую роль играет опция `_netdev`. Подробный пример с `fstab` и файлом секрета можно найти в разделе **[Автоматическое монтирование CephFS](cephfs_setup_and_usage.md#5-автоматическое-монтирование-cephfs-fstab)**.
