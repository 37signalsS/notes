# Базовый рабочий процесс в Vagrant

## Определения

**Жизненный цикл Vagrant (Vagrant Workflow)** — стандартизированная последовательность этапов управления виртуальной средой: от инициализации проекта до полной очистки ресурсов.

**Vagrantfile** — декларативный файл конфигурации на языке Ruby, описывающий целевое состояние инфраструктуры (образ ОС, сетевые интерфейсы, ресурсы и скрипты автоматизации).

**Provisioning (Провижининг)** — процесс автоматической настройки гостевой ОС сразу после её запуска (установка ПО, конфигурация сервисов, загрузка данных).

## Базовые концепции

### Основные команды жизненного цикла

| Команда | Действие | Описание |
| :--- | :--- | :--- |
| **`vagrant init`** | Инициализация | Создает базовый `Vagrantfile`. |
| **`vagrant validate`**| Валидация | Проверяет синтаксис `Vagrantfile` на наличие ошибок. |
| **`vagrant up`** | Запуск | Создает, запускает и настраивает ВМ. |
| **`vagrant ssh`** | Подключение | Открывает защищенный терминал к ВМ. |
| **`vagrant reload`** | Перезагрузка | Перезапускает ВМ для применения изменений конфигурации. |
| **`vagrant halt`** | Остановка | Корректно выключает виртуальную машину. |
| **`vagrant destroy`** | Удаление | Полностью удаляет ВМ и связанные с ней диски. |

### Управление состоянием (Snapshot)

Снимки состояния (Snapshots) позволяют сохранять текущую точку работы и возвращаться к ней при сбоях.

| Команда | Описание |
| :--- | :--- |
| **`vagrant snapshot save <name>`** | Создает именованный снимок состояния ВМ. |
| **`vagrant snapshot restore <name>`** | Возвращает ВМ к указанному снимку. |
| **`vagrant snapshot list`** | Показывает все доступные снимки для текущей ВМ. |
| **`vagrant snapshot delete <name>`** | Удаляет снимок для освобождения места. |

### Глобальное управление и статус

Vagrant отслеживает все запущенные машины в системе.

```bash
# Просмотр статуса всех ВМ в текущем проекте
vagrant status

# Список всех ВМ, известных Vagrant в системе (включая другие проекты)
vagrant global-status

# Очистка записей о машинах, которые были удалены вручную (мимо Vagrant)
vagrant global-status --prune
```

## Практические сценарии

### Сценарий 1: Быстрый старт проекта

```bash
# 1. Создание рабочей директории
mkdir my-project && cd my-project

# 2. Инициализация проекта с образом Ubuntu 24.04
vagrant init bento/ubuntu-24.04

# 3. Валидация конфигурации перед запуском
vagrant validate

# 4. Развертывание среды
vagrant up
```

### Сценарий 2: Тестирование изменений (Snapshot-workflow)

Используйте снимки перед запуском деструктивных скриптов или обновлением системного ПО.

```bash
# Создание точки восстановления
vagrant snapshot save before-upgrade

# Выполнение рискованных действий
vagrant ssh -c "sudo apt-get upgrade -y"

# Если что-то пошло не так — откат
vagrant snapshot restore before-upgrade
```

### Сценарий 3: Выполнение команд и проверка ресурсов

```bash
# Выполнение команды внутри ВМ без входа в интерактивную сессию
vagrant ssh -c "free -m"
# → result: сводка использования памяти гостевой ОС

# Проверка использования диска
vagrant ssh -c "df -h /vagrant"
# → result: информация о монтировании общей папки
```

### Сценарий 4: Приостановка работы

Если вам нужно временно освободить CPU и RAM хоста, но сохранить состояние запущенных приложений.

```bash
# Сохранение состояния RAM на диск (аналог гибернации)
vagrant suspend

# Быстрое возобновление (в 2-3 раза быстрее полного vagrant up)
vagrant resume
```

## Дополнительная информация

### Сравнение методов остановки

| Метод | Скорость | Ресурсы (RAM) | Данные на диске | Сценарий |
| :--- | :--- | :--- | :--- | :--- |
| **`suspend`** | Очень быстро | Освобождает | Сохраняются (Snapshot) | Перерыв на 1-2 часа |
| **`halt`** | Средне | Освобождает | Сохраняются | Конец рабочего дня |
| **`destroy`** | — | Освобождает | **Удаляются** | Завершение проекта |

### Рекомендации по эксплуатации

1.  **Проверка перед удалением:** Всегда проверяйте `vagrant global-status` перед очисткой места, чтобы не удалить активные рабочие среды.
2.  **Идемпотентность:** Пишите свои скрипты провижининга так, чтобы повторный запуск `vagrant provision` не приводил к дублированию настроек или ошибкам.
3.  **Локальный кэш:** Образы (boxes) хранятся в `~/.vagrant.d/boxes/`. Если место заканчивается, используйте `vagrant box prune` для удаления старых версий.
4.  **Отладка:** При возникновении ошибок используйте `VAGRANT_LOG=info vagrant up` для получения подробного вывода процесса загрузки.
