# Базовый рабочий процесс в Vagrant

## Определения

**Жизненный цикл Vagrant (Vagrant Workflow)** — последовательность этапов управления виртуальной машиной (ВМ), от создания конфигурации до полного удаления ресурсов.

**Vagrantfile** — файл конфигурации проекта, описывающий желаемое состояние инфраструктуры (образ, сеть, ресурсы, провижининг).

**Provisioning (Провижининг)** — процесс автоматической настройки операционной системы внутри ВМ после её запуска (установка пакетов, настройка конфигураций, развёртывание кода).

## Базовые концепции

### Основные команды жизненного цикла

| Команда | Действие | Описание |
| :--- | :--- | :--- |
| **`vagrant init`** | Инициализация | Создание дефолтного `Vagrantfile` в текущей директории |
| **`vagrant up`** | Запуск | Создание, запуск ВМ и запуск провижининга (при первом старте) |
| **`vagrant ssh`** | Подключение | Вход в консоль ВМ по протоколу SSH |
| **`vagrant reload`** | Перезагрузка | Перезапуск ВМ для применения изменений в `Vagrantfile` (CPU, RAM, сеть) |
| **`vagrant halt`** | Остановка | Корректное завершение работы гостевой ОС |
| **`vagrant destroy`** | Удаление | Полная очистка ресурсов ВМ (диски, конфигурация у провайдера) |

### Механизм работы `vagrant up`

При выполнении команды запуска Vagrant проходит следующие этапы:

1. Поиск образа (box) в локальном кэше (`~/.vagrant.d/boxes/`).
2. Загрузка образа из [Vagrant Cloud](https://app.vagrantup.com/boxes/search), если он отсутствует локально.
3. Импорт образа в целевой провайдер (Libvirt, VirtualBox и др.).
4. Настройка сетевых интерфейсов и общих папок.
5. Запуск ВМ и ожидание готовности SSH.
6. Выполнение скриптов автоматизации (provisioning), если это первый запуск.

### Управление изменениями: `reload` и `provision`

| Команда | Перезапуск ОС | Запуск Provisioning | Сценарий использования |
| :--- | :---: | :---: | :--- |
| **`vagrant reload`** | ✅ | ❌ | Изменили ресурсы (RAM) или сеть в `Vagrantfile` |
| **`vagrant provision`** | ❌ | ✅ | Обновили только скрипты настройки (Ansible, Shell) |
| **`vagrant reload --provision`** | ✅ | ✅ | Полное обновление конфигурации и перенастройка |

> Подробное описание автоматизации настройки см. в [Vagrant Provisioning](./vagrant_provisioning.md).

## Практические сценарии

### Сценарий 1: Создание нового проекта

```bash
# Создание директории и инициализация образа
mkdir my-dev-env && cd my-dev-env
vagrant init bento/ubuntu-24.04

# Запуск ВМ
vagrant up
```

### Сценарий 2: Подключение и проверка состояния

```bash
# Проверка текущего статуса ВМ
vagrant status

# Вход в систему
vagrant ssh

# Выполнение одиночной команды без входа в интерактивную сессию
vagrant ssh -c "df -h"
```

### Сценарий 3: Приостановка и возобновление работы

Если требуется освободить ресурсы хоста без выключения ВМ:

```bash
# Сохранение состояния RAM на диск (аналог гибернации)
vagrant suspend

# Быстрое возобновление работы
vagrant resume
```

### Сценарий 4: Очистка ресурсов

```bash
# Остановка ВМ
vagrant halt

# Удаление ВМ без подтверждения (флаг -f)
vagrant destroy -f
```

## Дополнительная информация

### Сравнение методов остановки

| Метод | Скорость | Ресурсы (RAM) | Данные на диске | Контекст |
| :--- | :--- | :--- | :--- | :--- |
| **`suspend`** | Очень быстро | Освобождает | Сохраняются (Snapshot) | Временный перерыв |
| **`halt`** | Средне | Освобождает | Сохраняются | Конец рабочего дня |
| **`destroy`** | — | Освобождает | **Удаляются** | Завершение проекта |

### Рекомендации по эксплуатации

1. **Проверка статуса:** Всегда проверяйте `vagrant status` перед выполнением `destroy`, чтобы избежать удаления нужной машины в мульти-машинных окружениях.
2. **Идемпотентность:** Пишите скрипты провижининга так, чтобы их можно было запускать многократно через `vagrant provision` без ошибок.
3. **Версионирование:** Добавляйте `.vagrant/` в `.gitignore`, но всегда храните `Vagrantfile` в репозитории проекта.
4. **Уровни отладки:** Если `vagrant up` зависает, используйте переменную `VAGRANT_LOG=info vagrant up` для диагностики. Подробнее в [Диагностика Vagrant](./vagrant_troubleshooting/basic_concepts.md).
