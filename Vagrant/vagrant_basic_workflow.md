# Базовый рабочий процесс Vagrant

## Жизненный цикл виртуальной машины

1. **Инициализация (`init`)**: Создание конфигурационного файла `Vagrantfile`, который описывает будущую машину.
2. **Создание и запуск (`up`)**: Развертывание и запуск ВМ на основе `Vagrantfile`. На этом же этапе может происходить первоначальная настройка (provisioning).
3. **Взаимодействие (`ssh`)**: Подключение к работающей машине для выполнения задач.
4. **Изменение состояния**:
    * **Применение конфигурации (`reload`, `provision`)**: Внесение изменений в работающую ВМ.
    * **Пауза (`suspend`, `resume`)**: Быстрое сохранение и восстановление состояния.
    * **Остановка (`halt`)**: Корректное выключение машины.
5. **Уничтожение (`destroy`)**: Полное удаление ВМ и связанных с ней ресурсов.

## Практический сценарий: управление окружением

### Шаг 1: Инициализация проекта

Создаем `Vagrantfile` с помощью команды `vagrant init`.

```bash
# Инициализация с использованием образа (box) Ubuntu 22.04
vagrant init ubuntu/jammy64
```

Будет создан минимальный `Vagrantfile`:

```ruby
# Vagrantfile
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
end
```

## Запуск окружения

Команда `vagrant up` скачивает box (если его нет в кэше), создает и запускает виртуальную машину согласно `Vagrantfile`.

```bash
# Запуск с указанием провайдера (например, VirtualBox)
vagrant up --provider=virtualbox
```

### Шаг 3: Подключение и проверка статуса

Vagrant автоматически настраивает SSH-доступ. Команда `vagrant status` показывает текущее состояние.

```bash
# Подключиться к машине
vagrant ssh

# Проверить статус (выполняется на хосте, не в ВМ)
vagrant status
```

### Шаг 4: Применение изменений

Для применения изменений в `Vagrantfile` или повторного запуска скриптов настройки используются следующие команды:

```bash
# Перезагрузить машину для применения изменений в Vagrantfile
vagrant reload

# Запустить только provisioning на работающей машине
vagrant provision

# Перезагрузить и принудительно применить provisioning
vagrant reload --provision
```

### Шаг 5: Управление состоянием (пауза, выключение)

* `vagrant suspend`: Сохраняет текущее состояние ВМ на диск ("поставить на паузу").
* `vagrant resume`: Восстанавливает ВМ из сохраненного состояния.
* `vagrant halt`: Корректно выключает гостевую ОС.

### Шаг 6: Удаление окружения

Команда `vagrant destroy` **безвозвратно** удаляет виртуальную машину и все ее данные.

```bash
vagrant destroy -f # Флаг -f для подтверждения без дополнительного запроса
```

При выполнении `destroy` происходит следующее:

1. **Уничтожаются виртуальные машины**, определенные в `Vagrantfile`.
2. **Удаляются диски** этих ВМ. **Все данные внутри ВМ теряются.**
3. **Очищаются метаданные Vagrant** (директория `.vagrant`).

## Дополнительная информация

При уничтожении окружения (`vagrant destroy`) некоторые артефакты **не удаляются** для экономии времени и ресурсов при последующих запусках:

* **Базовый образ (box):** Он останется в кэше Vagrant (`~/.vagrant.d/boxes`).
* **Файлы проекта:** `Vagrantfile` и другие ваши файлы остаются нетронутыми.
* **Пул хранения провайдера:** Сам пул не затрагивается, удаляются только созданные Vagrant тома внутри него.
