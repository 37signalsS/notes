# Конфигурация сети в Vagrant

## Базовые концепции: типы сетей

### 1. Проброс портов (Forwarded Port)

Позволяет "пробросить" порт с хост-машины на порт в гостевой ВМ. Это самый простой способ получить доступ к сервису (например, веб-серверу), запущенному внутри ВМ, с вашей основной машины через `localhost`.

### 2. Приватная сеть (Private Network)

Также известна как **Host-only**. Создает сетевой интерфейс, доступный **только** между хост-машиной и гостевыми ВМ. Другие устройства в вашей физической сети не будут видеть эти ВМ. Идеальна для создания изолированных окружений, например, для стенда из нескольких ВМ, которые должны общаться между собой.

### 3. Публичная сеть (Public Network)

Также известна как **Bridged**. "Подключает" виртуальную машину напрямую к вашей физической локальной сети. ВМ получит собственный IP-адрес из того же диапазона, что и ваш компьютер, и будет видна другим устройствам в сети как полноценный участник.

## Практические сценарии

### Сценарий 1: Доступ к веб-серверу через проброс портов

Запросы, приходящие на порт `8080` хост-машины, будут перенаправлены на порт `80` гостевой ВМ.

**`Vagrantfile`:**

```ruby
config.vm.network "forwarded_port", guest: 80, host: 8080
```

Теперь сервис, запущенный в ВМ на порту 80, доступен по адресу `http://localhost:8080` на хосте.

### Сценарий 2: Создание изолированной сети для нескольких ВМ

Создается Host-only сеть, и ВМ присваивается статический IP-адрес `192.168.50.4`.

**`Vagrantfile`:**

```ruby
config.vm.network "private_network", ip: "192.168.50.4"
```

Другой машине в этом же `Vagrantfile` можно присвоить адрес `192.168.50.5`, и они смогут общаться друг с другом по этим адресам.

### Сценарий 3: Подключение ВМ к локальной сети

ВМ получит IP-адрес от DHCP-сервера в вашей физической локальной сети (например, от вашего роутера).

**`Vagrantfile`:**

```ruby
# ВМ получит IP-адрес от DHCP-сервера в вашей локальной сети
config.vm.network "public_network"
```

При первом запуске Vagrant попросит вас выбрать, какой из физических сетевых интерфейсов хоста использовать для создания моста (bridge).

## Дополнительная информация

### Сравнительная таблица

| Тип сети | Доступность ВМ | Основной сценарий использования |
| --- | --- | --- |
| **Forwarded Port** | С хост-машины по `localhost:<host_port>` | Простой доступ к конкретному сервису (веб-сервер, база данных). |
| **Private Network** | Только с хоста и других ВМ в том же окружении | Создание изолированных кластеров и многокомпонентных стендов. |
| **Public Network** | Для всех устройств в физической локальной сети | Предоставление доступа к ВМ другим участникам сети (например, для демонстрации). |
