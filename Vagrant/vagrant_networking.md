# Настройка сети в Vagrant

## Определения

**Сетевые интерфейсы Vagrant** — программные механизмы, обеспечивающие сетевое взаимодействие между хост-системой, виртуальными машинами (ВМ) и внешней сетью.

**Forwarded Port (проброс портов)** — сопоставление порта на хост-машине с портом в гостевой системе, позволяющее обращаться к сервисам ВМ через `localhost` хоста.

**Private Network (приватная сеть)** — изолированный сетевой сегмент, доступный только хосту и ВМ в рамках одного окружения (Host-only).

**Public Network (публичная сеть)** — сетевой интерфейс, подключающий ВМ напрямую к физической сети через сетевой мост (Bridge).

## Базовые концепции

### Типы сетей в Vagrant

| Тип | Назначение | Доступность |
| :--- | :--- | :--- |
| **Forwarded Port** | Доступ к сервисам | Хост-система |
| **Private Network** | Межмашинное взаимодействие | Хост + ВМ окружения |
| **Public Network** | Полноценный сетевой узел | Вся локальная сеть |

### 1. Проброс портов (Forwarded Port)

Используется для предоставления доступа к портам гостевой ОС. Vagrant прослушивает порт на хосте и перенаправляет трафик на указанный порт ВМ.

**Особенности:**

- Работает через протоколы TCP (по умолчанию) и UDP.
- Может возникать конфликт, если порт на хосте уже занят другим процессом.

### 2. Приватная сеть (Private Network)

Обеспечивает создание виртуальной локальной сети. Идеально подходит для кластерных решений (например, K8s или БД), где требуется стабильное взаимодействие между узлами.

**Методы назначения IP:**

- **Static IP:** явное указание адреса (рекомендуется для стабильности).
- **DHCP:** автоматическое получение адреса (зависит от провайдера виртуализации).

### 3. Публичная сеть (Public Network)

ВМ становится полноправным участником локальной сети, к которой подключен хост. Она получает IP-адрес от внешнего DHCP-сервера или настраивается статически.

## Практические сценарии

### Сценарий 1: Базовый проброс портов

Настройка доступа к веб-серверу (Nginx/Apache) и базе данных.

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"
  
  # Проброс порта 8080 хоста на 80 порт ВМ
  config.vm.network "forwarded_port", guest: 80, host: 8080
  
  # Проброс с защитой от конфликтов (Vagrant сам выберет свободный порт на хосте)
  config.vm.network "forwarded_port", guest: 3306, host: 3306, auto_correct: true
end
```

### Сценарий 2: Создание кластерной сети

Конфигурация для взаимодействия нескольких машин по фиксированным IP.

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"
  
  # Статический IP
  config.vm.network "private_network", ip: "192.168.50.10"
  
  # Создание нескольких машин в цикле
  (1..2).each do |i|
    config.vm.define "app-#{i}" do |app|
      app.vm.network "private_network", ip: "192.168.50.#{10 + i}"
    end
  end
end
```

### Сценарий 3: Настройка сетевого моста (Bridge)

Подключение ВМ к корпоративной или домашней сети.

```ruby
Vagrant.configure("2") do |config|
  # Автоматический выбор моста
  config.vm.network "public_network"
  
  # Явное указание интерфейса и статического IP
  config.vm.network "public_network", bridge: "enp0s3", ip: "192.168.1.150"
end
```

### Сценарий 4: Комбинированная сеть

Типовая настройка для сложной разработки: SSH, HTTP и внутренняя шина данных.

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"
  
  # Внешний доступ к API
  config.vm.network "forwarded_port", guest: 8000, host: 8000
  
  # Внутренняя сеть для связи с БД
  config.vm.network "private_network", ip: "10.0.0.10"
end
```

## Дополнительная информация

### Сравнение характеристик

| Характеристика | Forwarded Port | Private Network | Public Network |
| :--- | :--- | :--- | :--- |
| **Изоляция** | Высокая | Очень высокая | Низкая |
| **Простота** | Высокая | Средняя | Низкая (зависит от DHCP) |
| **Маршрутизация** | Только к порту | Полная (внутри сети) | Полная (внешняя) |

### Диагностика сетевых соединений

Команды для проверки состояния сети внутри ВМ:

```bash
# Проверка IP-адресов интерфейсов
vagrant ssh -c "ip addr"

# Проверка таблицы маршрутизации
vagrant ssh -c "ip route"

# Проверка доступности соседнего узла
vagrant ssh -c "ping -c 3 192.168.50.11"
```

### Решение типичных проблем

- **Конфликт портов:** используйте параметр `auto_correct: true` в настройках `forwarded_port`.
- **IP не назначается (Private):** убедитесь, что подсеть не конфликтует с существующими сетями на хосте (например, Docker или VPN).
- **Bridge не работает:** проверьте права доступа Vagrant к сетевым интерфейсам хоста (особенно актуально для Linux).
