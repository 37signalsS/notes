# Vagrant Troubleshooting — Дополнительная информация

## Профилактика проблем

### Регулярная очистка и обслуживание

Со временем Vagrant может накапливать устаревшие метаданные и образы, что приводит к конфликтам и нехватке места.

```bash
# Очистить записи о несуществующих ВМ в кэше хоста
vagrant global-status --prune

# Удалить старые версии используемых box'ов
vagrant box prune

# Удалить конкретный неиспользуемый образ
vagrant box remove <box-name>
```

### Глубокий сброс плагинов

Если стандартные команды обновления плагинов не решают проблему несовместимости (часто бывает после обновления Ruby или Vagrant), используйте полное удаление пользовательских плагинов с последующей чистой установкой:

```bash
vagrant plugin expunge --reinstall
```

### Управление версиями (Version Locking)

Для предотвращения рассинхронизации окружений у разных разработчиков, жестко фиксируйте версии компонентов.

**В Vagrantfile:**
Обязательно указывайте `box_version`, чтобы предотвратить автоматическое скачивание мажорных обновлений операционной системы, которые могут сломать провижининг.

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"
  # Фиксация версии с разрешением только патч-обновлений
  config.vm.box_version = "~> 202501.0"
end
```

**В документации проекта (README.md):**
Фиксируйте минимально необходимые версии для запуска проекта:

```bash
# Текущая версия среды
vagrant --version

# Требуемые плагины
vagrant plugin list
```

## Безопасность и бэкапы

### Бэкапы перед критическими изменениями

Никогда не выполняйте деструктивные операции в ВМ без предварительного создания снимка состояния (Snapshot). Поддержка зависит от провайдера (отлично работает в Libvirt и VirtualBox).

**Управление снимками:**
```bash
# 1. Сохранить текущее состояние перед изменениями
vagrant snapshot save "pre-ansible-upgrade"

# 2. Просмотреть доступные снимки
vagrant snapshot list

# 3. Откатиться к сохраненному состоянию при сбое
vagrant snapshot restore "pre-ansible-upgrade"

# 4. Удалить снимок для освобождения места
vagrant snapshot delete "pre-ansible-upgrade"
```

### Экспорт данных и документирование

Если снимок сделать невозможно, используйте резервное копирование данных:
- **Экспорт данных:** Используйте `rsync` или `scp` (через `vagrant ssh-config`) для копирования важных баз данных или логов на хост.
- **Журнал изменений:** Вносите все изменения конфигурации провайдера (объем памяти, сеть) и скриптов провижининга исключительно через Git-коммиты в `Vagrantfile`.
