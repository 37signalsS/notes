# Vagrant Troubleshooting — Основные концепции

## Определения

**Рассинхронизация состояния (State Desync)** — ситуация, когда локальные метаданные Vagrant (директория `.vagrant/`) не соответствуют реальному состоянию виртуальной машины в гипервизоре. Основной индикатор — файл `.vagrant/machines/<name>/<provider>/id`, содержащий уникальный идентификатор ВМ у провайдера.

**Изоляция метаданных (`VAGRANT_DOTFILE_PATH`)** — механизм изменения пути к директории `.vagrant/`. Ошибки в этом параметре часто приводят к тому, что Vagrant «теряет» уже запущенные машины.

**Коммуникатор (Communicator)** — программный мост, через который Vagrant отправляет команды внутрь ВМ. Основные типы: `ssh` (Linux) и `winrm` (Windows). Проблемы с коммуникатором блокируют этапы провижининга и монтирования папок.

**SSH-ключ Vagrant** — приватный ключ, используемый для управления ВМ. По умолчанию используется «небезопасный» ключ (`~/.vagrant.d/insecure_private_key`), который заменяется на уникальный при первом запуске.

## Основные источники проблем

1.  **Инфраструктурные:** Ошибки сетевых мостов, конфликты IP-адресов, нехватка дискового пространства или RAM на хосте.
2.  **Синхронизация времени (Clock Drift):** Расхождение времени между хостом и гостем может приводить к ошибкам в работе SSL/TLS, Kerberos и баз данных.
3.  **Программные конфликты:** Несовместимость версий Vagrant и плагинов, отсутствие Guest Additions внутри образа, блокировки антивирусом или файрволом.
4.  **Прокси-серверы:** Отсутствие настроек `http_proxy` блокирует скачивание образов и установку плагинов (требуется плагин `vagrant-proxyconf`).
5.  **Специфика Apple Silicon:** Использование x86 образов на архитектуре ARM64 без соответствующей эмуляции (см. [Vagrant на Apple Silicon](../vagrant_macos_apple_silicon.md)).

## "Золотой молоток": полный сброс

Если стандартные методы не помогают, используйте процедуру полной очистки. **Внимание:** Все данные внутри ВМ будут безвозвратно удалены.

```bash
# 1. Принудительное удаление (даже если ВМ не видна Vagrant)
vagrant destroy -f

# 2. Удаление локальных метаданных проекта
rm -rf .vagrant

# 3. Очистка глобального кэша состояний
vagrant global-status --prune
```

## Диагностика и восстановление

### Проверка компонентов

```bash
# Глобальный статус всех ВМ в системе
vagrant global-status

# Проверка установленных образов
vagrant box list

# Проверка и обновление плагинов
vagrant plugin list
vagrant plugin update
```

### Восстановление плагинов
Часто требуется после обновления версии Vagrant или Ruby в системе.
- `vagrant plugin repair` — попытка исправить зависимости.
- `vagrant plugin expunge --reinstall` — полное удаление и повторная установка всех пользовательских плагинов (самый надежный метод).

## Уровни логирования и переменные

Vagrant управляется через переменные окружения, позволяющие получить детальный отчет о сбоях.

| Переменная | Значения | Описание |
| :--- | :--- | :--- |
| **`VAGRANT_LOG`** | `debug`, `info`, `warn`, `error` | Уровень детализации вывода в консоль. |
| **`VAGRANT_LOG_FILE`**| `/path/to/log.txt` | Запись лога в файл (рекомендуется для debug). |
| **`VAGRANT_DEFAULT_PROVIDER`** | `virtualbox`, `libvirt` | Принудительный выбор провайдера при отладке. |
| **`VAGRANT_NO_PARALLEL`** | `true` | Отключает параллельный запуск (полезно при дебаге гонок ресурсов). |

**Пример запуска с отладкой в файл:**
```bash
VAGRANT_LOG=debug VAGRANT_LOG_FILE=vagrant_debug.log vagrant up
```

## Рекомендации по анализу логов

При изучении `debug` лога ищите следующие паттерны:
- `DEBUG ssh`: проблемы с аутентификацией или таймауты подключения.
- `DEBUG interface`: ошибки создания сетевых мостов или захвата IP.
- `DEBUG guest`: ошибки определения типа ОС гостя.
- `ERROR`: критические сбои API провайдера (VirtualBox, Libvirt).
- `Plugin error`: несовместимость расширений с текущей версией ядра/Vagrant.
