# Vagrant Troubleshooting — Основные концепции

## Определения

**Рассинхронизация состояния (State Desync)** — ситуация, когда локальные метаданные Vagrant (директория `.vagrant/`) не соответствуют реальному состоянию виртуальной машины в гипервизоре. Основной индикатор — файл `.vagrant/machines/<name>/<provider>/id`, содержащий уникальный идентификатор ВМ у провайдера.

**Провайдер (Provider)** — программный модуль, обеспечивающий взаимодействие Vagrant с гипервизором (VirtualBox, Libvirt, VMware).

**Box** — сжатый образ виртуальной машины, используемый как шаблон. Ошибки в образе могут приводить к сбоям на этапе импорта или SSH-подключения.

**SSH-ключ Vagrant** — приватный ключ, используемый для управления ВМ. По умолчанию используется «небезопасный» ключ (`~/.vagrant.d/insecure_private_key`), который заменяется на уникальный при первом запуске (если не настроено иное).

## Основные источники проблем

1.  **Инфраструктурные:** Ошибки сетевых мостов (Bridge), конфликты IP-адресов, нехватка дискового пространства или RAM на хосте.
2.  **Программные:** Несовместимость версий Vagrant и плагинов, отсутствие Guest Additions внутри образа.
3.  **Права доступа:** Запуск команд от `sudo` там, где это не требуется (может повредить права на `.vagrant/`), или блокировки антивирусом/файрволом.
4.  **Специфика Apple Silicon:** Использование x86 образов на архитектуре ARM64 без соответствующей эмуляции (см. [Vagrant на macOS](../vagrant_macos_apple_silicon.md)).

## "Золотой молоток": полный сброс

Если стандартные методы не помогают, используйте процедуру полной очистки. **Внимание:** Все данные внутри ВМ будут безвозвратно удалены.

```bash
# 1. Принудительное удаление (даже если ВМ не видна Vagrant)
vagrant destroy -f

# 2. Удаление локальных метаданных проекта
rm -rf .vagrant

# 3. Очистка глобального кэша состояний
vagrant global-status --prune
```

## Диагностика и восстановление

### Проверка компонентов

```bash
# Глобальный статус всех ВМ в системе
vagrant global-status

# Проверка установленных образов
vagrant box list

# Проверка и восстановление плагинов
vagrant plugin list
vagrant plugin repair
```

### Глубокая очистка плагинов
Если `repair` не помогает, используйте полную переустановку:
```bash
vagrant plugin expunge --reinstall
```

## Уровни логирования и переменные

Vagrant управляется через переменные окружения, которые позволяют получить детальный отчет о сбоях.

| Переменная | Значения | Описание |
| :--- | :--- | :--- |
| **`VAGRANT_LOG`** | `debug`, `info`, `warn`, `error` | Уровень детализации вывода в консоль. |
| **`VAGRANT_LOG_FILE`**| `/path/to/log.txt` | Запись лога в файл (рекомендуется для debug). |
| **`VAGRANT_CWD`** | Путь к директории | Изменение рабочей директории поиска Vagrantfile. |

**Пример запуска с отладкой в файл:**
```bash
VAGRANT_LOG=debug VAGRANT_LOG_FILE=vagrant_debug.log vagrant up
```

## Рекомендации по анализу логов

При изучении `debug` лога ищите следующие ключевые слова:
- `DEBUG ssh`: проблемы с аутентификацией или доступностью порта.
- `DEBUG interface`: ошибки создания сетевых интерфейсов.
- `ERROR`: критические сбои API провайдера.
