# Vagrant Troubleshooting — Основные концепции

## Определения

**Рассинхронизация состояния** — несоответствие между метаданными Vagrant (директория `.vagrant/`) и реальным состоянием ВМ у провайдера. Наиболее частая причина ошибок.

**Провайдер (Provider)** — платформа виртуализации (VirtualBox, Libvirt и др.). Подробное описание: [Провайдеры в Vagrant](../vagrant_providers.md).

**Box** — базовый образ ВМ. Подробное описание: [Образы (Boxes) в Vagrant](../vagrant_providers.md).

**SSH-ключ Vagrant** — стандартный приватный ключ для подключения к ВМ (обычно `~/.vagrant.d/insecure_private_key`).

## Основные источники проблем

1. **Рассинхронизация состояния** — локальное состояние `.vagrant/` не соответствует реальному состоянию ВМ у провайдера.
2. **Окружение хоста** — прокси, права доступа, файрвол, настройки сети.
3. **Специфика провайдера** — уникальные ошибки VirtualBox, Libvirt, VMware.
4. **Проблемы с box'ами** — устаревшие, повреждённые или несовместимые образы.

## "Золотой молоток": полный сброс

```bash
# 1. Уничтожить ВМ
vagrant destroy -f

# 2. Удалить локальные метаданные
rm -rf .vagrant

# 3. Очистить кэш глобальных состояний
vagrant global-status --prune
```

> **Внимание!** Этот метод **уничтожает все данные** внутри ВМ. Используйте только когда другие способы не помогли.

## Диагностика состояния

```bash
# Глобальный статус всех ВМ
vagrant global-status

# Проверка box'ов
vagrant box list

# Проверка плагинов
vagrant plugin list

# Информация о системе Vagrant
vagrant --version
vagrant --debug
```

## Уровни логирования

```bash
# Минимальный
VAGRANT_LOG=warn vagrant up

# Подробный
VAGRANT_LOG=info vagrant up

# Отладочный
VAGRANT_LOG=debug vagrant up 2>&1 | tee debug.log
```
