# Решение проблем в Vagrant

## Основные источники проблем

1.  **Рассинхронизация состояния**: Наиболее частая проблема. Состояние, записанное в локальной директории `.vagrant`, расходится с реальным состоянием ВМ у провайдера (VirtualBox, Libvirt).
2.  **Окружение хоста**: Проблемы, вызванные конфигурацией машины, на которой запущен Vagrant (настройки прокси, права доступа, работа файрвола).
3.  **Специфика провайдера**: Ошибки, уникальные для конкретного провайдера виртуализации (например, именование дисков в Libvirt).

### "Золотой молоток": полный сброс

1.  `vagrant destroy -f`: Корректно уничтожает ВМ и связанные с ней ресурсы у провайдера.
2.  `rm -rf .vagrant`: Удаляет локальные метаданные проекта, заставляя Vagrant "забыть" о существовании машины.

**Внимание!** Этот метод **уничтожает все данные** внутри ВМ.

## Практические сценарии

### Сценарий 1: Работа через прокси-сервер

**Проблема:** Vagrant не может скачать образы (`box`) или выполнить сетевые операции внутри ВМ (например, `apt-get update`).

**Решение:** Настроить переменные окружения для прокси на хост-машине.

```bash
# Стандартные переменные для утилит Linux
export http_proxy="http://user:pass@proxy.example.com:port/"
export https_proxy="http://user:pass@proxy.example.com:port/"

# Специальные переменные для самого Vagrant
export VAGRANT_HTTP_PROXY="${http_proxy}"
export VAGRANT_HTTPS_PROXY="${https_proxy}"
```
Для автоматизации можно использовать плагин `vagrant-proxyconf`.

### Сценарий 2: Ошибка "уже существующего диска" в Libvirt

**Симптом:** `vagrant up` завершается с ошибкой, сообщая, что диск уже существует, хотя в пуле хранения его нет.

**Причина:** Рассинхронизация между метаданными Vagrant и состоянием `libvirt` после некорректного удаления ВМ.

**Решение:** Принудительно очистить состояние.

1.  **Уничтожить все ВМ в проекте**, чтобы `libvirt` удалил все свои записи о них:
    ```bash
    vagrant destroy -f
    ```

2.  **Удалить локальное состояние Vagrant:**
    ```bash
    rm -rf .vagrant
    ```

3.  **Повторить запуск:**
    ```bash
    vagrant up
    ```

### Сценарий 3: Ошибки из-за именования в Libvirt

**Проблема:** Ошибки при создании ВМ или дисков, связанные с именованием.

**Причина:** Имя домена ВМ в Libvirt формируется как `имя_проекта_имя_машины`. Нижнее подчеркивание (`_`) в имени машины (`config.vm.define`) может вызывать конфликты.

**Решение:** Всегда использовать дефис (`-`) вместо нижнего подчеркивания в именах, задаваемых через `config.vm.define`.

- **Правильно:** `config.vm.define "web-server"`
- **Неправильно:** `config.vm.define "web_server"`
