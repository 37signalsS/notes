# Советы и решение проблем в Vagrant

## Работа через прокси-сервер
Если ваша хост-машина находится за прокси, необходимо передать его настройки Vagrant, чтобы он мог скачивать образы и выполнять другие сетевые операции. Это делается через переменные окружения.

```bash
export http_proxy="http://user:pass@proxy.example.com:port/"
export https_proxy="http://user:pass@proxy.example.com:port/"

# Переменные для самого Vagrant
export VAGRANT_HTTP_PROXY="${http_proxy}"
export VAGRANT_HTTPS_PROXY="${https_proxy}"
```
Для автоматической установки этих переменных можно использовать плагин `vagrant-proxyconf`.

## Сброс состояния проекта
Иногда `vagrant status` может показывать неверный статус или возникают другие проблемы, связанные с состоянием машин. В этом случае можно безопасно удалить внутреннюю директорию Vagrant (`.vagrant`), где хранятся метаданные о созданных машинах.

```bash
# Внимание: это действие удалит только метаданные Vagrant (ID машины, данные о провайдере).
# Сама виртуальная машина у провайдера (в VirtualBox, Libvirt) не будет затронута.
rm -rf .vagrant
```
После этого `vagrant up` попытается создать машину заново, что может вызвать конфликт, если старая ВМ все еще существует у провайдера. Обычно этот метод используется вместе с `vagrant destroy`.

## Проблема: Рассинхронизация состояния диска (Libvirt)

**Симптом:** При запуске `vagrant up` возникает ошибка, связанная с уже существующим диском, хотя физически этого файла нет в пуле хранения `libvirt`.

**Причина:** Такое несоответствие возникает, если Vagrant или `libvirt` сохранили запись о диске в своем внутреннем состоянии, но сам диск был удален некорректно (вручную или в результате сбоя).

**Решение:** Необходимо принудительно очистить состояние Vagrant и `libvirt` для данной ВМ.

1.  **Уничтожить все ВМ, управляемые Vagrant в проекте:**
    Эта команда корректно удалит виртуальные машины и связанные с ними записи в `libvirt`.
    ```bash
    vagrant destroy -f
    ```

2.  **Удалить локальное состояние Vagrant:**
    Эта команда очистит кэш и метаданные проекта.
    ```bash
    rm -rf .vagrant
    ```
3.  **Повторить запуск:**
    Теперь `vagrant up` должен выполниться без ошибок.

## Именование ВМ и дисков в Libvirt
Имя домена виртуальной машины в Libvirt формируется из имени каталога проекта и имени, заданного в `config.vm.define`. Например, для проекта `my-project` и машины `web`, полное имя домена будет `my-project_web`.

**Важно:** Не используйте нижнее подчеркивание (`_`) в именах, определенных через `config.vm.define`. Это может привести к ошибкам. Используйте дефис (`-`).
