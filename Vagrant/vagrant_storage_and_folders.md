# Управление хранилищем и общими папками в Vagrant

## Определения

**Общая папка (Synced Folder)** — программный механизм синхронизации директорий между хост-системой и гостевой операционной системой виртуальной машины (ВМ). Позволяет работать с исходным кодом проекта на хосте, выполняя и тестируя его в изолированном окружении.

**Виртуальный диск (Virtual Disk)** — логическое блочное устройство, используемое ВМ для хранения данных (ОС, базы данных, кэш). Может быть основным (root) или дополнительным.

**Точка монтирования (Mount Point)** — директория в файловой системе гостевой ОС, через которую осуществляется доступ к содержимому общей папки или виртуального диска.

## Базовые концепции

### Сравнение методов хранения

| Характеристика | Общие папки (Synced Folders) | Виртуальные диски (Disks) |
| :--- | :--- | :--- |
| **Назначение** | Исходный код, конфиги | БД, логи, тяжелые данные |
| **Производительность**| Зависит от протокола (NFS/Virtiofs) | Максимальная (нативная ФС) |
| **Синхронизация** | Двусторонняя (кроме rsync) | Отсутствует (только внутри ВМ) |
| **Доступность** | Хост и ВМ | Только ВМ |

### Типы общих папок

| Тип | Провайдер | Скорость | Особенности |
| :--- | :--- | :--- | :--- |
| **VirtualBox Shared**| VirtualBox | Средняя | Требует Guest Additions. |
| **NFS** | Linux / macOS | Высокая | Рекомендуется для больших проектов. |
| **Virtiofs** | Libvirt / QEMU | Экстремальная| Современный стандарт для KVM. |
| **rsync** | Любой | Высокая | Односторонняя (Host -> VM), нет задержек ФС. |
| **SMB** | Windows | Высокая | Стандарт для Windows-хостов. |

## Практические сценарии

### Сценарий 1: Конфигурация общих папок

**Расширенная настройка прав доступа:**

```ruby
Vagrant.configure("2") do |config|
  # Отключение стандартной синхронизации /vagrant
  config.vm.synced_folder ".", "/vagrant", disabled: true
  
  # Монтирование с кастомными правами (owner/group должны существовать в ВМ)
  config.vm.synced_folder "src/", "/var/www/html",
    owner: "www-data",
    group: "www-data",
    mount_options: ["dmode=755,fmode=644"]
end
```

**Использование Virtiofs ( Libvirt / QEMU):**

Требует современных версий Vagrant (2.4+) и плагина `vagrant-libvirt`.

```ruby
config.vm.synced_folder ".", "/vagrant", type: "virtiofs"
```

**Оптимизация rsync для node_modules:**

```ruby
config.vm.synced_folder ".", "/app",
  type: "rsync",
  rsync__exclude: [".git/", "node_modules/", "dist/"],
  rsync__args: ["--verbose", "--archive", "--delete", "-z"]
```

### Сценарий 2: Управление дополнительными дисками

**Использование команды vagrant disk (Vagrant 2.4+):**

Vagrant позволяет декларативно описывать дополнительные диски, которыми можно управлять через CLI.

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"
  
  # Описание дополнительного диска
  config.vm.disk :disk, name: "data_disk", size: "20GB"
end
```

**Команды управления:**
```bash
# Просмотр информации о дисках
vagrant disk list

# Изменение размера (поддерживается не всеми провайдерами)
vagrant disk resize --name data_disk --size 40GB
```

### Сценарий 3: Ручная инициализация диска в Linux

После добавления диска в конфигурацию, его нужно подготовить внутри гостевой ОС.

```bash
# 1. Поиск нового устройства (обычно /dev/vdb или /dev/sdb)
vagrant ssh -c "lsblk"

# 2. Создание файловой системы
vagrant ssh -c "sudo mkfs.ext4 /dev/vdb"

# 3. Монтирование и настройка автозагрузки
vagrant ssh -c "sudo mkdir -p /data && \
  echo '/dev/vdb /data ext4 defaults 0 0' | sudo tee -a /etc/fstab && \
  sudo mount -a"
```

## Дополнительная информация

### Диагностика и отладка

```bash
# Проверка активных точек монтирования
vagrant ssh -c "mount | grep vagrant"

# Проверка использования диска
vagrant ssh -c "df -hT"

# Логирование процесса монтирования при запуске
VAGRANT_LOG=debug vagrant up
```

### Лучшие практики

1.  **Производительность:** Для сред разработки на Linux используйте **Virtiofs** или **NFS**. Избегайте стандартных папок VirtualBox на проектах с >1000 файлов.
2.  **Исключения rsync:** Всегда исключайте директории `.git`, `node_modules`, `vendor` и логи. Это значительно ускоряет выполнение `vagrant up`.
3.  **Безопасность:** Не монтируйте корень хоста или чувствительные директории (`~/.ssh`) внутрь ВМ.
4.  **Сетевые задержки:** При использовании NFS убедитесь, что файрвол хоста разрешает входящие соединения от ВМ (порты nfs, mountd, portmapper).
