# Ansible Pull: Pull-режим управления конфигурацией

В стандартной модели Ansible работает в режиме **push**: контрольный узел "проталкивает" конфигурацию на управляемые машины. Однако существует и альтернативный подход — **pull**, реализуемый с помощью утилиты `ansible-pull`.

`ansible-pull` — это простой скрипт, который объединяет в себе `git` и `ansible-playbook`. Он скачивает плейбук из Git-репозитория и запускает его локально.

## 1. Концепция и сценарии использования

Основная идея `ansible-pull` заключается в том, что управляемые узлы сами отвечают за обновление своей конфигурации. Вместо того чтобы центральный сервер подключался к сотням или тысячам машин, каждая машина в заданное время (например, по cron) обращается к Git-репозиторию, скачивает актуальные плейбуки и применяет их к себе (`localhost`).

**Преимущества:**

*   **Масштабируемость:** Этот подход снимает ограничение на количество хостов, которыми может управлять одна машина. Вы ограничены только пропускной способностью вашего Git-сервера (GitHub, GitLab), что позволяет управлять огромными парками машин.
*   **Децентрализация:** Можно создавать "кластеры" управляемых машин, каждая со своим "лидером", который берет плейбуки из центрального репозитория и раскатывает их на свою группу.
*   **Работа по расписанию:** Легко интегрируется с `cron` для периодического обновления конфигурации.

**Недостатки:**

*   **Зависимость от Git:** Если Git-репозиторий недоступен, обновления не произойдут. Однако система продолжит работать с последней примененной конфигурацией.
*   **Сложность переконфигурации:** Управление самими "пуллерами" может стать проблемой, требующей "мастер-ноды" Ansible для их настройки.
*   **Установка Ansible на каждом узле:** На каждую управляемую машину необходимо установить `ansible`.

## 2. Практика: Использование `ansible-pull`

### 2.1. Базовый пример с публичным репозиторием

Допустим, у нас есть публичный Git-репозиторий с простым плейбуком `test.yml`:

```yaml
# test.yml
- name: Test Pull
  hosts: localhost
  connection: local
  tasks:
    - name: Echo message
      ansible.builtin.debug:
        msg: "Hello from ansible-pull!"
```

**Шаги для запуска:**

1.  **Создать директорию для плейбуков:**
    ```bash
    mkdir ~/ansible-pull-test
    ```

2.  **Запустить `ansible-pull`:**
    ```bash
    ansible-pull \
      -U https://github.com/user/my-public-repo.git \
      -d ~/ansible-pull-test \
      test.yml
    ```
    *   `-U` (`--url`): URL Git-репозитория.
    *   `-d` (`--directory`): Директория для клонирования репозитория. Важно указывать полный путь, так как `ansible-pull` может некорректно работать с относительными путями.
    *   `test.yml`: Имя плейбука, который нужно запустить после клонирования.

    При первом запуске `ansible-pull` склонирует репозиторий и выполнит плейбук. При последующих — сделает `git pull` и выполнит плейбук только если были изменения.

### 2.2. Пример с приватным репозиторием

Для работы с приватными репозиториями необходимо настроить SSH-аутентификацию по ключу, так как интерактивный ввод пароля не подходит для автоматизации.

**Шаги:**

1.  **Сгенерировать SSH-ключ:**
    Создайте отдельный ключ для этой цели, чтобы не использовать ключ по умолчанию.
    ```bash
    ssh-keygen -t rsa -b 4096 -f ~/.ssh/ansible_pull_github
    ```
    Не устанавливайте кодовую фразу, если планируете использовать ключ в автоматических `cron` задачах.

2.  **Добавить публичный ключ в GitHub:**
    Скопируйте содержимое `~/.ssh/ansible_pull_github.pub` и добавьте его в `Settings > SSH and GPG keys > New SSH key` в вашем GitHub аккаунте. Дайте ему осмысленное имя (например, `ansible-pull-server-1`).

3.  **Настроить SSH-клиент:**
    Чтобы `git` (и `ansible-pull`) знал, какой ключ использовать для доступа к `github.com`, создайте или отредактируйте файл `~/.ssh/config`:

    ```
    Host github.com
      HostName github.com
      User git
      IdentityFile ~/.ssh/ansible_pull_github
    ```
    Эта конфигурация указывает SSH-клиенту использовать заданный ключ при всех подключениях к `github.com`.

4.  **Запустить `ansible-pull` с SSH URL:**
    Теперь можно использовать SSH URL вашего приватного репозитория.
    ```bash
    ansible-pull \
      -U git@github.com:user/my-private-repo.git \
      -d ~/ansible-pull-private \
      main.yml
    ```
    `ansible-pull` успешно подключится, используя настроенный SSH-ключ, скачает репозиторий и выполнит плейбук.

### Автоматизация в Production
В продакшен-среде добавление ключей в GitHub можно автоматизировать через API GitHub, используя, например, модуль `uri` в Ansible или `curl`. Это позволяет полностью автоматизировать подготовку новых серверов для работы в pull-режиме.
