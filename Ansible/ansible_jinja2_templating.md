# Ansible: Шаблонизация с Jinja2

## Определения

**Jinja2** — это популярный шаблонизатор для Python, используемый Ansible для динамического создания файлов. Он позволяет вставлять в текстовые файлы переменные, выполнять циклы и условные конструкции, обеспечивая гибкость в управлении конфигурациями. Шаблоны обрабатываются модулем `ansible.builtin.template`, и по соглашению, файлы шаблонов имеют расширение `.j2`.

## Основные концепции: Синтаксис и конструкции

### Переменные

Для вывода значения переменной используется конструкция `{{ my_variable }}`. Для доступа к элементам словаря используется точечная нотация: `{{ my_dict.key }}`.

Если переменная может быть не определена, рекомендуется использовать фильтр `default` для предотвращения ошибок.
```jinja
# Если 'user' не определен, будет использовано "guest"
Hello, {{ user | default("guest") }}
```

Для определения переменной непосредственно внутри шаблона используется команда `{% set my_variable = "value" %}`.

### Цикл `for`

Циклы используются для итерации по элементам списка.
```jinja
# inventory - это список словарей
{% for item in inventory %}
Сервер {{ loop.index }}: {{ item.name }} (IP: {{ item.ip }})
{% endfor %}
```
- `loop.index` возвращает текущий индекс итерации (начиная с 1).
- `loop.index0` возвращает индекс, начиная с 0.

### Условия `if`

Условные конструкции позволяют выводить блоки текста в зависимости от истинности выражения.

```jinja
{% if enable_ssl %}
server {
    listen 443 ssl;
    ssl_certificate /etc/nginx/ssl/cert.pem;
{% else %}
server {
    listen 80;
{% endif %}
    # ... общие директивы
}
```
- Проверка на существование переменной: `{% if my_var is defined %}`.
- Проверка на вхождение в список: `{% if 'db' in server_roles %}`.
- Условия можно комбинировать с помощью `and` и `or`.

### Фильтры

Фильтры применяются к переменным через символ `|` для их преобразования.

#### `default`

Задает значение по умолчанию, если переменная не определена.

```jinja
# Выведет "there", если first_name не определен
{{ first_name | default("there") }}

# Выведет "there", если first_name не определен ИЛИ является пустой строкой/False
{{ first_name | default("there", true) }}
```

#### `replace`

Заменяет подстроку в строке.

```jinja
# Заменит "Personnel" на "HR"
{{ department | replace("Personnel", "HR") }}
```
Фильтры можно объединять в цепочки: `{{ my_var | filter1 | filter2 }}`.

## Практические сценарии

### Пример: Шаблон конфигурации Nginx

Это пример показывает, как сгенерировать конфигурационный файл Nginx на основе шаблона и переменных, определенных в Ansible.

#### 1. Переменные в Ansible (например, в `group_vars/all.yml`)

```yaml
nginx_worker_processes: 4
nginx_http_port: 80
enable_nginx_status_page: true
allowed_status_ips:
  - 192.168.1.10
  - 10.0.0.5
```

#### 2. Шаблон `nginx.conf.j2`

```jinja
# /etc/nginx/nginx.conf

worker_processes {{ nginx_worker_processes | default(2) }};

events {
    worker_connections 1024;
}

http {
    server {
        listen {{ nginx_http_port }};
        server_name _;

        location / {
            root /usr/share/nginx/html;
            index index.html;
        }
        
        {# Используем условие 'if' для добавления опционального блока #}
        {% if enable_nginx_status_page %}
        location /nginx_status {
            stub_status;
            allow 127.0.0.1;
            
            {# Используем цикл 'for' для генерации списка разрешенных IP #}
            {% for ip in allowed_status_ips %}
            allow {{ ip }};
            {% endfor %}
            
            deny all;
        }
        {% endif %}
    }
}
```

#### 3. Задача в плейбуке

```yaml
- name: Generate nginx configuration from template
  ansible.builtin.template:
    src: nginx.conf.j2  # Путь к файлу шаблона
    dest: /etc/nginx/nginx.conf # Путь для сгенерированного файла на целевом хосте
    owner: root
    group: root
    mode: '0644'
  notify: Restart nginx # Уведомляем обработчик для перезапуска сервиса
```
Эта задача возьмет шаблон `nginx.conf.j2`, подставит в него значения переменных `nginx_worker_processes`, `nginx_http_port` и т.д., и создаст на целевом хосте готовый файл `/etc/nginx/nginx.conf`.

## Дополнительная информация

### Лучшие практики

*   **Используйте суффикс `.j2`**: Всегда называйте файлы шаблонов с расширением `.j2`, чтобы их было легко отличить от статичных файлов.
*   **Кавычки для выражений**: В YAML-файлах Ansible заключайте Jinja2-выражения в кавычки, чтобы избежать ошибок парсинга.
    *   **Плохо:** `my_var: {{ some_value }}/path`
    *   **Хорошо:** `my_var: "{{ some_value }}/path"`
*   **Не усложняйте шаблоны**: Избегайте слишком длинных и сложных цепочек фильтров или вложенной логики. Если логика становится сложной, лучше подготовить данные заранее в плейбуке (например, с помощью `set_fact`) или вынести логику в кастомный фильтр.
*   **Используйте `default`**: Всегда используйте фильтр `default` для переменных, которые могут отсутствовать, чтобы сделать плейбуки более предсказуемыми и отказоустойчивыми.
