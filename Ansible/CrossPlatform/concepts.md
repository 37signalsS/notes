# Кроссплатформенные плейбуки Ansible: Концепции

## Определения

- **Кроссплатформенный плейбук (Cross-Platform Playbook)** — плейбук, спроектированный для успешного выполнения на различных Операционных Системах (ОС) путем адаптации задач к целевому окружению.
- **Факты Ansible (`ansible_facts`)** — набор переменных, которые Ansible автоматически собирает с управляемого узла. Эти факты содержат системную информацию: сетевые интерфейсы, версия ОС, семейство ОС.
- **`ansible_os_family`** — ключевой факт Ansible, который группирует операционные системы по семействам (например, `Debian` для Ubuntu/Debian, `RedHat` для CentOS/RHEL/Fedora). Это основная переменная, используемая для построения условной логики.

## Базовые концепции

### Ключевые принципы разработки

Для создания поддерживаемых кроссплатформенных сценариев следует придерживаться следующих правил:

1. **Используйте `ansible_os_family`**: это основа для построения условной логики. В современных версиях Ansible рекомендуется обращаться к фактам через словарь: `ansible_facts['os_family']`.
2. **Разделяйте задачи**: выносите специфичные для ОС задачи в отдельные файлы и подключайте их динамически.
3. **Абстрагируйтесь через переменные**: не используйте жестко заданные пути, имена пакетов или служб в задачах. Определяйте их в `vars/` или `defaults/`.
4. **Предпочитайте нативные модули**: специализированные модули (например, `apt` или `yum`) часто предоставляют больше контроля, чем универсальный модуль `package`.

### Динамическое включение задач через `include_tasks`

Ключевым инструментом является использование модуля `ansible.builtin.include_tasks` в сочетании с условием `when`. Это позволяет "встраивать" нужный набор задач в процессе выполнения плейбука.

Пример организации `roles/nginx/tasks/main.yml`:

```yaml
---
- name: Включение задач для Debian-семейства
  ansible.builtin.include_tasks: debian.yml
  when: ansible_facts['os_family'] == "Debian"

- name: Включение задач для RedHat-семейства
  ansible.builtin.include_tasks: redhat.yml
  when: ansible_facts['os_family'] == "RedHat"
```

### Использование переменных по умолчанию (`defaults`)

В ролях Ansible директория `defaults/` используется для задания переменных с самым низким приоритетом. Это идеальное место для параметров, которые могут различаться между ОС, но должны иметь разумное значение "из коробки".

Пример `roles/nginx/defaults/main.yml`:

```yaml
nginx_http_port: 80
```

Если переменная не переопределена в инвентаре или через `vars`, Ansible использует значение из `defaults`.

## Практические сценарии

### Адаптация системно-зависимых параметров

Разные ОС используют разные имена пользователей и групп для сервисов. Вместо копирования задач можно использовать тернарный оператор или словари переменных.

**Пример:** Настройка группы для Nginx (в Debian это `www-data`, в RedHat — `nginx`).

```yaml
- name: Создание systemd-юнита из шаблона
  ansible.builtin.template:
    src: service.j2
    dest: /etc/systemd/system/myapp.service
  vars:
    # Определение группы на лету
    nginx_group: "{{ 'nginx' if ansible_facts['os_family'] == 'RedHat' else 'www-data' }}"
```

### Проверка состояния системы с помощью `stat`

Для принятия решений на основе состояния файловой системы используется модуль `ansible.builtin.stat`. Это позволяет избежать ошибок при обращении к путям, специфичным для конкретной ОС.

```yaml
- name: Проверка наличия директории конфигурации
  ansible.builtin.stat:
    path: /etc/nginx/conf.d
  register: nginx_conf_dir

- name: Копирование конфига, если директория существует
  ansible.builtin.copy:
    src: custom.conf
    dest: /etc/nginx/conf.d/
  when: nginx_conf_dir.stat.exists
```
