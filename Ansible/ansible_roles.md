# Ansible: Роли и коллекции

## Определения

**Роль (Role)** — базовая единица переиспользования в Ansible. Предопределенная структура файлов и каталогов, которая инкапсулирует набор задач, переменных, шаблонов и обработчиков для автоматизации настройки конкретного компонента системы (например, роль для установки Nginx). Переход от плейбука к роли целесообразен, когда сценарий автоматизации усложняется, и возникает необходимость в переиспользовании кода и лучшей структуризации.

**Коллекция (Collection)** — более крупная структура, современный способ распространения контента Ansible. Коллекция может включать в себя несколько ролей, плагинов, модулей и документации, объединенных для работы с целой экосистемой (например, `community.postgresql` содержит всё для управления PostgreSQL).

## Основные концепции

### Назначение ролей

Хотя автоматизацию можно описывать в одном плейбуке, это приводит к созданию громоздких и трудноподдерживаемых файлов. Роли решают эту проблему, предоставляя механизм декомпозиции кода на логические модули, которые легко переиспользовать в разных проектах.

### Компоненты роли

Любой сценарий Ansible состоит из четырех основных компонентов, которые инкапсулируются в ролях:

1. **Задачи (Tasks)** — атомарные шаги, каждый из которых вызывает один из [модулей Ansible](Modules/ansible_modules_overview.md) (`apt`, `copy`, `service` и т.д.).
2. **Переменные (Variables)** — позволяют параметризовать роли и плейбуки.
3. **Шаблоны (Templates)** — файлы `.j2` с использованием шаблонизатора [Jinja2](ansible_jinja_templating.md) для создания динамических конфигураций.
4. **Обработчики (Handlers)** — специальные задачи для перезапуска сервисов, которые выполняются только один раз при получении [уведомления (`notify`)](PlaybookStructure/basics.md#обработчики-handlers-и-уведомления-notify).

### Стандартная структура каталогов

Ansible автоматически распознает предопределенную структуру каталогов и файлов внутри роли. Это позволяет фреймворку находить задачи, обработчики, шаблоны и переменные без явного указания путей.

Подробное описание назначения каждого каталога и рекомендации по организации — в **[Структура роли](Roles/structure.md)**.

### Управление ролями

**Создание и использование:** Каркас роли создается через `ansible-galaxy role init`, наполняется задачами и подключается в плейбуках. Практическое руководство — в [Roles/usage.md](Roles/usage.md).

**Ansible Galaxy:** Официальный репозиторий для поиска и установки готовых ролей и коллекций. Управление зависимостями через `requirements.yml` описано в [Roles/galaxy.md](Roles/galaxy.md).

**Git-менеджмент:** Альтернативный подход — ручное управление версиями ролей через Git. См. [Roles/git_management.md](Roles/git_management.md).

## Практические сценарии

### Сценарий 1: Базовое использование роли

Роли подключаются в плейбуке с помощью ключевого слова `roles`. По умолчанию Ansible ищет роли в директории `roles/`, расположенной рядом с плейбуком.

```yaml
---
- name: Настройка веб-серверов
  hosts: webservers
  become: true
  roles:
    - common
    - nginx
```

### Сценарий 2: Передача параметров в роль

Переменные позволяют настраивать поведение роли без изменения её внутреннего кода.

```yaml
---
- name: Настройка Nginx с пользовательским портом
  hosts: webservers
  roles:
    - role: nginx
      nginx_port: 8080
      nginx_worker_processes: 4
```

Более сложные сценарии, включая условное выполнение и использование тегов, приведены в **[Практическом руководстве: Использование ролей](Roles/usage.md#практические-сценарии)**.
