# Ansible — роли и коллекции

## Определения

**Роль (Role)** — основной механизм декомпозиции и переиспользования кода в Ansible. Это предопределенная структура файлов и каталогов, которая инкапсулирует задачи, переменные, шаблоны и обработчики для автоматизации конкретного компонента системы (например, роль для установки Nginx). Роли позволяют сделать плейбуки лаконичными и модульными.

**Коллекция (Collection)** — современный формат распространения контента Ansible (начиная с версии 2.10). Включает в себя роли, модули, плагины (фильтры, тесты, lookup) и документацию. Это основной способ поставки обновлений для модулей, не входящих в минимальное ядро (**ansible-core**). Пакет **ansible** (community version) представляет собой набор наиболее популярных коллекций.

## Основные концепции

### Роли: декомпозиция и повторное использование

Использование ролей целесообразно, когда сценарий автоматизации становится сложным. Вместо одного огромного YAML-файла логика разбивается на независимые блоки.

**Ключевые особенности ролей:**
*   **Изоляция:** Переменные роли по умолчанию имеют ограниченную область видимости.
*   **Зависимости:** Метаданные в `meta/main.yml` позволяют автоматически подключать другие роли.
*   **Компоненты:** Задачи (tasks), переменные (defaults/vars), шаблоны (templates), файлы (files) и обработчики (handlers). Подробнее: [Структура роли](./Roles/structure.md).

### Коллекции: современный стандарт

Коллекции решили проблему «раздутого» ядра Ansible, позволив сообществу и вендорам развивать свои модули независимо.

*   **FQCN (Fully Qualified Collection Name — полное имя коллекции):** Формат `namespace.collection_name.module`. Пример: `ansible.builtin.copy` или `community.docker.docker_container`. Использование FQCN обязательно для предотвращения конфликтов имен, если установлены коллекции с одинаковыми именами модулей.
*   **Версионирование:** Коллекции поддерживают семантическое версионирование, что критично для стабильности инфраструктуры как кода (IaC).

## Управление и доставка

### Инструментарий Galaxy и требования

Официальный инструмент для управления контентом — **[Ansible Galaxy](./Roles/galaxy.md)**.
Рекомендуется описывать зависимости в файле `requirements.yml`:
```yaml
---
roles:
  - name: geerlingguy.nginx
    version: 3.1.1

collections:
  - name: community.postgresql
    version: ">=2.0.0"
```
Установка: `ansible-galaxy install -r requirements.yml`.

### Среды выполнения (Execution Environments)

Современный стандарт доставки Ansible-автоматизации. **Execution Environment (EE)** — это контейнерный образ, который включает в себя:
*   Версию `ansible-core`.
*   Необходимые коллекции.
*   Системные зависимости и Python-библиотеки.
*   [Ansible Runner](https://ansible-runner.readthedocs.io/) для запуска задач.
Это гарантирует идентичность среды разработки и эксплуатации.

## Тестирование и валидация

### Molecule

**[Molecule](./ansible_testing_with_molecule.md)** — основной фреймворк для тестирования ролей. Он позволяет:
1.  Инициализировать тестовую среду (Docker, Vagrant, Cloud).
2.  Применить роль (**converge**).
3.  Проверить состояние системы (**verify**).
4.  Выполнить линтинг (ansible-lint).

Использование Molecule является признаком высокого качества кода (Production Grade) в Ansible-разработке.
