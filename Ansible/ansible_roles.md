# Ansible — роли и коллекции

## Определения

**Роль (Role)** — основной механизм декомпозиции и переиспользования кода в Ansible. Это предопределенная структура файлов и каталогов, которая инкапсулирует задачи, переменные, шаблоны и обработчики для автоматизации конкретного компонента системы (например, роль для установки Nginx). Роли позволяют сделать плейбуки лаконичными и модульными.

**Коллекция (Collection)** — современный формат распространения контента Ansible (начиная с версии 2.10). Коллекция является более крупной структурой и может включать в себя несколько ролей, модулей, плагинов (фильтры, тесты, lookup) и документацию. Это основной способ поставки обновлений для модулей, не входящих в ядро (`ansible-core`).

## Основные концепции

### Роли: декомпозиция и повторное использование

Использование ролей целесообразно, когда сценарий автоматизации становится сложным. Вместо одного огромного YAML-файла вы разбиваете логику на независимые блоки, которые можно легко подключать к разным проектам.

**Компоненты роли:**
1. **Задачи (Tasks)** — атомарные действия, вызывающие [модули Ansible](./Modules/ansible_modules_overview.md).
2. **Переменные (Variables)** — настройки по умолчанию (`defaults/`) и жестко заданные переменные (`vars/`). Подробнее в [Приоритетах переменных](./PlaybookStructure/variables.md).
3. **Шаблоны (Templates)** — динамические конфигурационные файлы [Jinja2](./ansible_jinja_templating.md).
4. **Обработчики (Handlers)** — задачи, выполняемые только по [уведомлению (notify)](./PlaybookStructure/basics.md#обработчики-и-идемпотентность).
5. **Метаданные (Meta)** — описание зависимостей роли от других ролей.

### Коллекции: современный стандарт

С разделением проекта на `ansible-core` (минимальное ядро) и пакет `ansible` (сообщество), коллекции стали основным способом доставки новых возможностей.

* **FQCN (Fully Qualified Collection Name)** — полное имя ресурса в формате `namespace.collection_name.resource`. Пример: `ansible.builtin.copy` или `community.docker.docker_container`. Использование FQCN гарантирует отсутствие конфликтов имен.
* **Структура коллекций:** В отличие от ролей, коллекции имеют жесткий неймспейс (пространство имен), что позволяет устанавливать их глобально или локально в проект без риска перезаписать чужой контент.

## Управление и конфигурация

### Инициализация и поиск

**Создание каркаса:**
```bash
# Для роли
ansible-galaxy role init my_role

# Для коллекции
ansible-galaxy collection init my_namespace.my_collection
```

**Пути поиска (Search Paths):**
Ansible ищет контент в директориях, указанных в `ansible.cfg`. По умолчанию это:
* **Роли:** `./roles`, `~/.ansible/roles`, `/usr/share/ansible/roles`, `/etc/ansible/roles`.
* **Коллекции:** `~/.ansible/collections`, `/usr/share/ansible/collections`.

Их можно переопределить через параметры `roles_path` и `collections_path`.

### Управление зависимостями

Официальный репозиторий для ролей и коллекций — **[Ansible Galaxy](./Roles/galaxy.md)**.
Рекомендуется описывать все зависимости проекта в файле `requirements.yml`:

```yaml
---
roles:
  - name: geerlingguy.nginx
    version: 3.1.1

collections:
  - name: community.postgresql
    version: ">=2.0.0"
```
