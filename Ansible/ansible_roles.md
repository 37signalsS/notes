# Ansible: Роли и коллекции

Хотя можно писать всю автоматизацию в одном большом плейбуке, это быстро приводит к созданию громоздких и трудноподдерживаемых файлов. Поэтому в Ansible основным способом организации и переиспользования кода являются **роли** и **коллекции**.

## Определения

**Роль (Role)** — базовая единица переиспользования в Ansible. Предопределенная структура файлов и каталогов, которая инкапсулирует набор задач, переменных, шаблонов и обработчиков для автоматизации настройки конкретного компонента системы (например, роль для установки Nginx). Переход от плейбука к роли целесообразен, когда сценарий автоматизации усложняется, и возникает необходимость в переиспользовании кода и лучшей структуризации.

**Коллекция (Collection)** — более крупная структура, современный способ распространения контента Ansible. Коллекция может включать в себя несколько ролей, плагинов, модулей и документации, объединенных для работы с целой экосистемой (например, `community.postgresql` содержит всё для управления PostgreSQL).

## Основные концепции

### Компоненты роли

Любой сценарий Ansible состоит из четырех основных компонентов, которые инкапсулируются в ролях:

1. **Задачи (Tasks)** — атомарные шаги, каждый из которых вызывает один из [модулей Ansible](Modules/ansible_modules_overview.md) (`apt`, `copy`, `service` и т.д.).
2. **Переменные (Variables)** — позволяют параметризовать роли и плейбуки.
3. **Шаблоны (Templates)** — файлы `.j2` с использованием шаблонизатора [Jinja2](ansible_jinja2_templating.md) для создания динамических конфигураций.
4. **Обработчики (Handlers)** — специальные задачи для перезапуска сервисов, которые выполняются только один раз при получении [уведомления (`notify`)](PlaybookStructure/basics.md#обработчики-handlers-и-уведомления-notify).

### Стандартная структура каталогов

Роль имеет предопределенную структуру, которую Ansible распознает автоматически:

- `tasks/main.yml` — основные задачи роли (точка входа)
- `handlers/main.yml` — обработчики уведомлений
- `templates/` — Jinja2-шаблоны конфигураций
- `files/` — статические файлы для копирования
- `defaults/main.yml` — переменные по умолчанию (низкий приоритет)
- `vars/main.yml` — константы роли (высокий приоритет)
- `meta/main.yml` — метаданные и зависимости роли

Полное описание структуры — в [Roles/structure.md](Roles/structure.md).

### Управление ролями

**Создание и использование:** Каркас роли создается через `ansible-galaxy init`, наполняется задачами и подключается в плейбуках. Практическое руководство — в [Roles/usage.md](Roles/usage.md).

**Ansible Galaxy:** Официальный репозиторий для поиска и установки готовых ролей и коллекций. Управление зависимостями через `requirements.yml` описано в [Roles/galaxy.md](Roles/galaxy.md).

**Git-менеджмент:** Альтернативный подход — ручное управление версиями ролей через Git. См. [Roles/git_management.md](Roles/git_management.md).

## Практические сценарии

### Сценарий 1: Базовое подключение роли

```yaml
---
- name: Configure servers
  hosts: webservers
  become: true
  roles:
    - set_time
```

### Сценарий 2: Подключение с параметрами

```yaml
- name: Configure Nginx
  hosts: webservers
  roles:
    - role: nginx
      nginx_port: 8080
      nginx_worker_processes: 8
```

### Сценарий 3: Условное подключение

```yaml
- name: Deploy database
  hosts: all
  roles:
    - role: postgresql
      when: db_type == "postgresql"
```

### Сценарий 4: Использование внешних ролей из Galaxy

```yaml
- name: Setup web server
  hosts: webservers
  roles:
    - geerlingguy.nginx
    - geerlingguy.php
```

Предварительная установка: `ansible-galaxy install geerlingguy.nginx geerlingguy.php`
