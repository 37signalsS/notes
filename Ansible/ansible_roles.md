# Ansible: Роли и Коллекции

Хотя можно писать всю автоматизацию в одном большом плейбуке, это быстро приводит к созданию громоздких и трудноподдерживаемых файлов. Поэтому в Ansible основным способом организации и переиспользования кода являются **роли** и **коллекции**.

## Определения

* **Роль (Role)**: Базовая единица переиспользования в Ansible. Это предопределенная структура файлов и каталогов, которая инкапсулирует набор задач, переменных, шаблонов и обработчиков для автоматизации настройки конкретного компонента системы (например, роль для установки Nginx).
* **Коллекция (Collection)**: Более крупная структура, которая является современным способом распространения контента Ansible. Коллекция может включать в себя несколько ролей, плагинов, модулей и документации, объединенных для работы с целой экосистемой (например, коллекция `community.postgresql` содержит всё для управления PostgreSQL).

## Основные концепции

### Компоненты роли

Любой сценарий Ansible состоит из четырех основных компонентов, которые инкапсулируются в ролях:

1. **Задачи (Tasks):** Атомарные шаги, каждый из которых вызывает один из [модулей Ansible](Modules/ansible_modules_overview.md) (`apt`, `copy`, `service` и т.д.).
2. **Переменные (Variables):** Позволяют параметризовать роли и плейбуки.
3. **Шаблоны (Templates):** Файлы `.j2` с использованием шаблонизатора [Jinja2](ansible_jinja2_templating.md) для создания динамических конфигураций.
4. **Обработчики (Handlers):** Специальные задачи для перезапуска сервисов, которые выполняются только один раз при получении [уведомления (`notify`)](PlaybookStructure/basics.md#обработчики-handlers-и-уведомления-notify).
