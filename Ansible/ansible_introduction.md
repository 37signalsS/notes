# Введение в Ansible

## Определения

**Ansible** — это система автоматизации ИТ-инфраструктуры с открытым исходным кодом, предназначенная для управления конфигурациями, развертывания приложений и оркестрации сложных ИТ-процессов.

**Декларативность** — основной подход Ansible, при котором пользователь описывает целевое состояние системы, а инструмент самостоятельно определяет необходимые действия для его достижения. Подробнее см. в [Основных концепциях](./ansible_core_concepts.md).

**Agentless (Без агентов)** — архитектурная особенность, при которой для управления узлами не требуется установка на них специального ПО (агентов). Связь осуществляется через стандартные протоколы (SSH для Linux, WinRM для Windows).

**Идемпотентность** — свойство, гарантирующее, что повторное выполнение одной и той же операции не приведет к изменениям, если система уже находится в желаемом состоянии.

## Основные концепции

### Архитектура и компоненты

1.  **Узел управления (Control Node):** Машина, на которой установлен Ansible. С неё запускаются все команды и сценарии.
2.  **Управляемые узлы (Managed Nodes):** Целевые серверы, сетевые устройства или облачные ресурсы, которыми управляет Ansible.
3.  **Инвентарь (Inventory):** Список хостов и групп хостов (статический файл или динамический скрипт).
4.  **Модули (Modules):** Исполняемые блоки кода, выполняющие конкретные задачи (установка пакетов, копирование файлов). Современный стандарт требует использования **FQCN** (например, `ansible.builtin.apt`).
5.  **Плейбуки (Playbooks):** Сценарии автоматизации, написанные на языке **YAML**.

### Преимущества использования

- **Минимальный порог входа:** Использование человекочитаемого формата YAML и шаблонов **Jinja2**.
- **Единообразие инфраструктуры:** Исключение «серверов-снежинок» (уникальных серверов, настроенных вручную).
- **Масштабируемость:** Возможность управления тысячами узлов одновременно.
- **Безопасность:** Интеграция с **Ansible Vault** для шифрования чувствительных данных.

## Практические сценарии

### Использование Ad-hoc команд

**Ad-hoc команды** — это быстрые одноразовые задачи, выполняемые в терминале без написания плейбука.

**Синтаксис:** `ansible <pattern> -m <module> -a "<arguments>"`

#### Проверка связи (модуль `ping`)
Проверяет доступность хостов и наличие Python.
```bash
ansible all -m ping
```

#### Управление пакетами (модуль `package`)
Универсальный модуль, выбирающий подходящий менеджер пакетов (`apt`, `yum`, `dnf`) автоматически.
```bash
# Установка nginx на группу web (требуется sudo)
ansible web -m package -a "name=nginx state=present" --become
```

#### Сбор информации (модуль `setup`)
Получение детальных фактов о системе в формате JSON.
```bash
ansible all -m setup --tree /tmp/facts
```

#### Выполнение команд оболочки (модуль `shell`)
Используется, когда нужен функционал shell (пайпы, перенаправления).
```bash
ansible all -m shell -a "df -h | grep /dev/sda"
```

## Дополнительная информация

### Рекомендации

- Для постоянных задач всегда используйте плейбуки вместо ad-hoc команд.
- Используйте **FQCN** (Fully Qualified Collection Name) для обеспечения совместимости и ясности.
- Храните инвентарь в системе контроля версий (Git).
