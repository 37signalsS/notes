# Введение в Ansible

## Определения

**Ansible** — это система с открытым исходным кодом для автоматизации управления конфигурациями, развертывания приложений и оркестрации. Она использует **декларативный язык** — способ описания желаемого конечного состояния системы, а не шагов по его достижению (например, "пакет nginx должен быть установлен", а не "скачай и установи nginx"). Ansible работает без агентов (agentless) и подключается к управляемым узлам по SSH.

## Основные концепции

### Ключевые преимущества

- **Быстрое освоение**: Достаточно поверхностного понимания синтаксиса YAML и Jinja2.
- **Без агентов (Agentless)**: Нет необходимости устанавливать специальное ПО на управляемые хосты; нужен только SSH и Python. Это упрощает развертывание и снижает накладные расходы.
- **Декларативность и Идемпотентность**: Вы описываете *желаемое состояние* системы, а Ansible берет на себя его достижение. Благодаря [идемпотентности](ansible_core_concepts.md#идемпотентность), повторные запуски не приводят к изменениям, если система уже в нужном состоянии.
- **Большое количество модулей**: Широкий набор готовых [модулей](Modules/ansible_modules_overview.md) для различных задач, от управления пакетами до работы с облачными провайдерами.
- **Расширяемость**: Возможность писать собственные модули и плагины.

## Практические сценарии

### Ad-hoc команды

**Ad-hoc команды** — это способ выполнения быстрых, одноразовых задач на управляемых узлах напрямую из командной строки, без написания плейбуков. Это основной инструмент для оперативного управления, сбора информации и проверки состояния систем.

**Общий синтаксис:**
`ansible <pattern> [options]`

- `<pattern>`: Целевые хосты из файла инвентаря (например, `all`, `webservers`, `server1`).
- `-m <module>`: Используемый модуль (по умолчанию `command`).
- `-a "<arguments>"`: Аргументы для модуля.

#### Пример 1: Проверка подключения (`ping`)

Модуль `ping` — это основной способ проверить, что Ansible может подключиться к хосту, выполнить на нем Python-код и получить ответ.

```bash
# Проверить доступность всех хостов из инвентаря
ansible all -m ping
```

Успешный ответ `pong` подтверждает, что соединение установлено и Python на удаленном хосте доступен.

#### Пример 2: Выполнение команд (`command` и `shell`)

- **`command`**: для простых команд без конвейеров (`|`) или перенаправлений (`>`).
- **`shell`**: для выполнения сложных скриптов в полноценной оболочке узла.

```bash
# Узнать uptime на всех серверах (используется модуль command по умолчанию)
ansible all -a "uptime"

# Посмотреть содержимое корневого каталога с помощью модуля shell
ansible all -m shell -a "ls -la /"
```

#### Пример 3: Сбор информации о системе (`setup`)

Модуль `setup` собирает обширную информацию (факты) об управляемом хосте: от данных об ОС и сети до сведений о дисках и памяти.

```bash
# Собрать факты для хоста 'server1' и вывести в формате JSON
ansible server1 -m setup
```

## Дополнительная информация

Ad-hoc команды отлично подходят для простых задач, но для сложной оркестрации и воспроизводимой автоматизации используются [плейбуки](PlaybookStructure/basics.md), которые являются сердцем Ansible.

Для глубокого изучения рекомендуется следующий маршрут:
1. [Основные концепции](ansible_core_concepts.md) — понимание модели работы
2. [Настройка и установка](ansible_setup_and_config.md) — подготовка окружения
3. [Структура плейбуков](PlaybookStructure/basics.md) — синтаксис и компоненты
4. [Роли](ansible_roles.md) — организация кода
