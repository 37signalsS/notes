# Ansible Introduction

## Определения

**Ansible** — система с открытым исходным кодом для автоматизации управления конфигурациями, развертывания приложений и оркестрации. Использует **декларативный язык** — описание желаемого конечного состояния системы, а не шагов для его достижения. Работает без агентов (agentless), подключение к управляемым узлам по SSH.

## Основные концепции

### Ключевые преимущества

- **Быстрое освоение** — достаточно понимания синтаксиса YAML и Jinja2.
- **Без агентов (Agentless)** — не требует ПО на управляемых хостах, нужны только SSH и Python.
- **Декларативность и идемпотентность** — описание *желаемого состояния* системы. Благодаря [идемпотентности](ansible_core_concepts.md#идемпотентность), повторные запуски не изменяют систему при достижении целевого состояния.
- **Большое количество модулей** — широкий набор [модулей](Modules/ansible_modules_overview.md) для различных задач.
- **Расширяемость** — возможность писать собственные модули и плагины.

## Практические сценарии

### Ad-hoc команды

**Ad-hoc команды** — это способ выполнения быстрых, одноразовых задач на управляемых узлах напрямую из командной строки, без написания плейбуков. Это основной инструмент для оперативного управления, сбора информации и проверки состояния систем.

**Общий синтаксис:**
`ansible <pattern> [options]`

- `<pattern>`: Целевые хосты из файла инвентаря (например, `all`, `webservers`, `server1`).
- `-m <module>`: Используемый модуль (по умолчанию `command`).
- `-a "<arguments>"`: Аргументы для модуля.

#### Пример 1: Проверка подключения (`ping`)

Модуль `ping` — это основной способ проверить, что Ansible может подключиться к хосту, выполнить на нем Python-код и получить ответ.

```bash
# Проверить доступность всех хостов из инвентаря
ansible all -m ping
```

Успешный ответ `pong` подтверждает, что соединение установлено и Python на удаленном хосте доступен.

#### Пример 2: Выполнение команд (`command` и `shell`)

- **`command`**: для простых команд без конвейеров (`|`) или перенаправлений (`>`).
- **`shell`**: для выполнения сложных скриптов в полноценной оболочке узла.

```bash
# Узнать uptime на всех серверах (используется модуль command по умолчанию)
ansible all -a "uptime"

# Посмотреть содержимое корневого каталога с помощью модуля shell
ansible all -m shell -a "ls -la /"
```

#### Пример 3: Сбор информации о системе (`setup`)

Модуль `setup` собирает обширную информацию (факты) об управляемом хосте: от данных об ОС и сети до сведений о дисках и памяти.

```bash
# Собрать факты для хоста 'server1' и вывести в формате JSON
ansible server1 -m setup
```
