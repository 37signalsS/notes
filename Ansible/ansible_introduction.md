# Введение в Ansible

## Определения

**Ansible** — система с открытым исходным кодом для автоматизации управления конфигурациями, развертывания приложений и оркестрации. Использует **декларативный язык** — описание желаемого конечного состояния системы, а не последовательности шагов для его достижения. Работает по модели без агентов (**agentless**), подключаясь к управляемым узлам по протоколу **SSH (Secure Shell)**.

## Базовые концепции

### Ключевые преимущества

- **Борьба с «серверами-снежинками» (Snowflake Servers)** — без автоматизации серверы со временем становятся уникальными из-за ручных правок. Ansible позволяет привести инфраструктуру к единому согласованному состоянию.
- **Быстрое освоение** — достаточно понимания синтаксиса **YAML (YAML Ain't Markup Language)** и шаблонизатора **Jinja2**.
- **Работа без агентов (Agentless)** — не требует установки специализированного программного обеспечения на управляемых хостах, необходимы только SSH и интерпретатор Python.
- **Декларативность и идемпотентность** — описание *желаемого состояния* системы. Благодаря [идемпотентности](ansible_core_concepts.md#идемпотентность), повторные запуски не вносят изменений, если целевое состояние уже достигнуто.
- **Широкая библиотека модулей** — готовые [модули](Modules/ansible_modules_overview.md) для управления пакетами, пользователями, облачными ресурсами и сетевым оборудованием.
- **Расширяемость** — возможность создания собственных модулей и плагинов на языке Python.

## Практические сценарии

### Выполнение Ad-hoc команд

**Ad-hoc команды** — это способ выполнения быстрых, одноразовых задач на управляемых узлах напрямую из командной строки без написания плейбуков. Это основной инструмент для оперативного управления, сбора информации и проверки состояния систем.

**Общий синтаксис:**
`ansible <pattern> [options]`

- `<pattern>`: Целевые хосты из файла инвентаря (например, `all`, `webservers`, `server1`).
- `-m <module>`: Используемый модуль (по умолчанию `command`).
- `-a "<arguments>"`: Аргументы для модуля.

#### Пример 1: Проверка подключения (модуль `ping`)

Модуль `ping` проверяет возможность подключения к хосту, выполнение на нем кода Python и получение ответа.

```bash
# Проверить доступность всех хостов из инвентаря
ansible all -m ping
```

Успешный ответ `pong` подтверждает, что соединение установлено и среда исполнения на удаленном хосте готова.

#### Пример 2: Выполнение системных команд (`command` и `shell`)

- **`command`**: используется для простых команд без поддержки переменных окружения оболочки, конвейеров (`|`) или перенаправлений (`>`).
- **`shell`**: используется для выполнения сложных команд в полноценной оболочке целевого узла.

```bash
# Узнать время работы (uptime) на всех серверах
ansible all -a "uptime"

# Просмотр содержимого каталога через оболочку
ansible all -m shell -a "ls -la /tmp"
```

#### Пример 3: Сбор информации о системе (модуль `setup`)

Модуль `setup` собирает обширную информацию (факты) об управляемом хосте: данные об операционной системе, сетевых интерфейсах, дисках и памяти.

```bash
# Сбор фактов для хоста 'server1' и вывод в формате JSON
ansible server1 -m setup
```
