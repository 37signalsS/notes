# Введение в Ansible

## Определения

**Ansible** — это система автоматизации ИТ-инфраструктуры с открытым исходным кодом, предназначенная для управления конфигурациями, развертывания приложений и оркестрации сложных ИТ-процессов.

**Декларативность** — основной подход Ansible, при котором пользователь описывает целевое состояние системы, а инструмент самостоятельно определяет необходимые действия для его достижения. Подробнее см. в [Основных концепциях](./ansible_core_concepts.md).

**Agentless (безагентная архитектура)** — архитектурная особенность, при которой для управления узлами не требуется установка на них специального ПО (агентов). Связь осуществляется через стандартные протоколы (SSH для Linux, WinRM для Windows).

**Идемпотентность** — свойство, гарантирующее, что повторное выполнение одной и той же операции не приведет к изменениям, если система уже находится в желаемом состоянии.

## Основные концепции

### Архитектура и компоненты

1.  **Узел управления (Control Node):** Машина, на которой установлен Ansible. С неё запускаются все команды и сценарии. Поддерживаются только Unix-подобные системы (Linux, macOS, WSL2).
2.  **Управляемые узлы (Managed Nodes):** Целевые серверы, сетевые устройства или облачные ресурсы, которыми управляет Ansible. Для управления Linux-системами на них обязательно должен быть установлен **Python 3**.
3.  **Инвентарь (Inventory):** Список хостов и групп хостов (статический файл или динамический скрипт).
4.  **Модули (Modules):** Исполняемые автономные блоки кода, выполняющие конкретные задачи (установка пакетов, копирование файлов). Современный стандарт требует использования полного имени ресурса — **FQCN (Fully Qualified Collection Name)** (например, `ansible.builtin.apt`).
5.  **Плейбуки (Playbooks):** Сценарии автоматизации, описывающие шаги развертывания и написанные на языке **YAML**.

### Разделение пакетов: ansible-core и ansible

Для решения проблем с масштабированием проекта и скоростью выпуска обновлений, экосистема разделена на два компонента:
- **ansible-core**: Минимальное ядро системы, содержащее движок выполнения, CLI-утилиты (`ansible`, `ansible-playbook`) и набор базовых модулей (`ansible.builtin`). Обновляется строго по циклу релизов ядра.
- **ansible (Community пакет)**: Большой метапакет, включающий в себя `ansible-core` и тысячи модулей и плагинов от сообщества, упакованных в **Коллекции (Collections)**.

### Преимущества использования

- **Минимальный порог входа:** Использование человекочитаемого формата YAML и системы шаблонизации **Jinja2**.
- **Единообразие инфраструктуры:** Исключение «серверов-снежинок» (уникальных серверов, настроенных вручную и невоспроизводимых автоматически).
- **Масштабируемость:** Возможность управления тысячами узлов одновременно благодаря Push-архитектуре и параллельному выполнению.
- **Безопасность:** Отсутствие постоянно запущенных агентов, использование стандартных механизмов аутентификации ОС (SSH-ключи) и интеграция с **Ansible Vault** для криптографической защиты чувствительных данных.

## Практические сценарии

### Использование Ad-hoc команд

**Ad-hoc команды** — это быстрые одноразовые задачи, выполняемые в терминале без написания плейбука. Они оптимальны для первичной проверки или массового выполнения простых команд.

**Синтаксис:** `ansible <pattern> -m <module> -a "<arguments>"`

#### Проверка связи (модуль `ping`)
Проверяет доступность хостов по протоколу связи (по умолчанию SSH) и наличие интерпретатора Python на удаленной стороне.
```bash
ansible all -m ping
# → server1.example.com | SUCCESS => { "ansible_facts": { "discovered_interpreter_python": "/usr/bin/python3" }, "changed": false, "ping": "pong" }
```

#### Управление пакетами (модуль `package`)
Универсальный модуль, выбирающий подходящий менеджер пакетов (`apt`, `yum`, `dnf`) автоматически. Флаг `--become` включает повышение привилегий (sudo).
```bash
# Установка nginx на группу web
ansible web -m package -a "name=nginx state=present" --become
# → web1.example.com | CHANGED => { "changed": true, "name": ["nginx"], "state": "present" }
```

#### Сбор информации (модуль `setup`)
Получение детальных фактов о системе (сетевые интерфейсы, ОС, железо) в формате JSON с сохранением в локальные файлы.
```bash
ansible all -m setup --tree /tmp/facts
# → Результаты собираются и сохраняются в файлы внутри директории /tmp/facts для каждого целевого хоста
```

#### Выполнение команд оболочки (модуль `shell`)
Используется, когда необходим функционал командной оболочки (конвейеры, перенаправления). Для простых команд без спецсимволов безопаснее использовать `ansible.builtin.command`.
```bash
ansible all -m shell -a "df -h | grep /dev/sda"
# → db1.example.com | CHANGED | rc=0 >> /dev/sda1  50G  20G  30G  40% /
```

## Дополнительная информация

### Рекомендации

- Для повторяющихся задач и управления конфигурацией всегда используйте плейбуки вместо ad-hoc команд, так как они обеспечивают идемпотентность и контроль версий.
- Используйте **FQCN** при вызове модулей для обеспечения обратной совместимости.
- Храните инвентарь (статический) и плейбуки в системе контроля версий (Git).
