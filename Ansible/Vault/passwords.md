# Ansible Vault: Управление паролями

## Определения

- **Источник пароля (Password Source)**: Метод, с помощью которого Ansible получает ключ для расшифровки данных. Выбор метода зависит от требований к автоматизации и уровня безопасности.
- **Идентификатор хранилища (Vault ID)**: Метка (например, `dev`, `prod`), позволяющая связать зашифрованный файл с конкретным паролем или источником при использовании нескольких хранилищ.

## Основные концепции

### Иерархия и приоритеты

Ansible ищет пароль в определенном порядке. Первый найденный источник считается приоритетным:

1. **Аргументы командной строки**: Флаги `--vault-id`, `--vault-password-file` или `--ask-vault-pass`.
2. **Переменная окружения**: `ANSIBLE_VAULT_PASSWORD_FILE` (указывает путь к файлу или скрипту).
3. **Конфигурационный файл**: Параметр `vault_password_file` в секции `[defaults]` файла `ansible.cfg`.

**Важное замечание по переменным окружения:** Ansible **не поддерживает** прямую передачу пароля через переменную окружения (например, `ANSIBLE_VAULT_PASSWORD`) из соображений безопасности. Переменная может указывать только на файл или исполняемый скрипт.

## Практические сценарии

### Сценарий 1: Интерактивный ввод пароля

Самый безопасный способ для ручного запуска, так как пароль не сохраняется на диске и не передается в открытом виде.

```bash
# Простой запрос пароля
ansible-playbook site.yml --ask-vault-pass
# → Vault password: (ввод пароля)

# Запрос пароля для конкретного идентификатора (Vault ID)
ansible-playbook site.yml --vault-id prod@prompt
# → Vault password (prod): (ввод пароля)
```

### Сценарий 2: Использование статического файла

Удобно для локальной разработки, но требует осторожности.

1. **Создание файла**:
    ```bash
    echo "your_password" > .vault_pass
    chmod 600 .vault_pass
    ```
2. **Настройка в `ansible.cfg`**:
    ```ini
    [defaults]
    vault_password_file = .vault_pass
    ```

> **Безопасность:** Никогда не добавляйте файлы с паролями в систему контроля версий. Обязательно внесите их в `.gitignore`.

### Сценарий 3: Исполняемый скрипт (интеграция с менеджерами секретов)

Если файл, указанный в `vault_password_file`, имеет права на выполнение (`+x`), Ansible запустит его и будет использовать вывод (STDOUT) в качестве пароля.

**Пример скрипта для получения пароля из переменной окружения (`vault_env.sh`):**
```bash
#!/bin/bash
# Ansible не читает пароль из переменной напрямую, но этот скрипт пробросит его
echo "$MY_SECRET_VAULT_PASSWORD"
```

**Пример интеграции с внешним хранилищем:**
```bash
#!/bin/bash
# Пример для HashiCorp Vault или системного брелока
pass show ansible/vault/prod-key
```

### Сценарий 4: Передача пароля в CI/CD (например, GitLab CI)

Поскольку хранить файлы в репозитории нельзя, пароль передается через временный файл или исполняемый скрипт-прослойку.

```yaml
deploy:
  script:
    - export MY_SECRET_VAULT_PASSWORD=$VAULT_TOKEN # Переменная из настроек CI/CD
    - ansible-playbook deploy.yml --vault-password-file ./scripts/vault_env.sh
```
