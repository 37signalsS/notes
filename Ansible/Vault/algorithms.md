# Ansible Vault: Алгоритмы шифрования

## Определения

- **Криптографическая схема (Cipher Suite)**: Набор алгоритмов, обеспечивающих защиту данных. В Ansible Vault используется фиксированная схема, которую пользователь не может изменить, что гарантирует высокий уровень безопасности и совместимость между версиями.
- **PBKDF2 (Password-Based Key Derivation Function 2)**: Функция формирования ключа на основе пароля. Она делает перебор паролей (брутфорс) вычислительно дорогим за счет тысяч итераций хеширования.
- **KDF (Key Derivation Function)**: Функция формирования ключа, преобразующая входной секрет (пароль) в криптографически стойкие ключи для шифрования и аутентификации.
- **HMAC (Hash-based Message Authentication Code)**: Код аутентификации сообщений, использующий хеш-функцию. Обеспечивает проверку целостности и подлинности данных.
- **CTR (Counter Mode)**: Режим счетчика в блочном шифровании, превращающий блочный шифр в потоковый. Позволяет шифровать данные произвольной длины и обеспечивает высокую производительность.

## Основные концепции

### Компоненты защиты

Ansible Vault реализует схему **Encrypt-then-MAC** (шифрование, затем аутентификация). Это современный стандарт, предотвращающий атаки на расшифровку модифицированных данных.

| Компонент | Технология | Описание |
| :--- | :--- | :--- |
| **Шифрование** | `AES-256-CTR` | Advanced Encryption Standard (продвинутый стандарт шифрования) с ключом 256 бит. Режим CTR обеспечивает параллелизацию и отсутствие необходимости в дополнении (padding) данных. |
| **Производная ключа** | `PBKDF2-HMAC-SHA256` | Использует хеш-функцию SHA-256 (Secure Hash Algorithm). В Ansible зафиксировано **10 000 итераций** и 32-байтная случайная соль (Salt). |
| **Целостность (MAC)** | `HMAC-SHA256` | Гарантирует, что данные не были изменены злоумышленником. Если MAC не совпадает, Ansible прерывает расшифровку. |
| **Библиотека Python** | `cryptography` | Современная библиотека, используемая в `ansible-core` 2.x для всех криптографических операций. |

### Формирование ключа (KDF Details)

При расшифровке Ansible выполняет следующие шаги:
1. Берет ваш пароль и 32 байта соли из заголовка файла.
2. Пропускает их через 10 000 итераций PBKDF2-HMAC-SHA256.
3. Генерирует **80 байт** производных данных, которые делятся на:
   - **Первые 32 байта**: Ключ шифрования (Cipher Key).
   - **Следующие 32 байта**: Ключ HMAC (MAC Key).
   - **Последние 16 байт**: Вектор инициализации (IV — Initialization Vector).

**Важное замечание по безопасности (2024-2025):** 10 000 итераций считается низким значением по современным стандартам (OWASP рекомендует 600 000+). Это делает Ansible Vault уязвимым к перебору на мощных видеокартах (GPU). **Рекомендуется использовать пароли длиной более 20 символов с высокой энтропией.**

### Версии формата (заголовки)

Первая строка файла — это метаданные, определяющие логику обработки:
- `$ANSIBLE_VAULT;1.1;AES256`: Формат Ansible 1.5+. Требует последовательного перебора всех предоставленных паролей.
- `$ANSIBLE_VAULT;1.2;AES256;prod`: Формат Ansible 2.4+. Содержит **Vault ID** (`prod`), позволяющий мгновенно выбрать нужный ключ из списка.

**Data Tagging (Core 2.19+):** В новых версиях Ansible улучшена внутренняя обработка секретов через тип `EncryptedString`, что повышает надежность защиты от утечек в логи, не меняя при этом базовые алгоритмы шифрования.

## Практические сценарии

### Анализ заголовка файла

Вы можете проверить параметры шифрования, не расшифровывая файл:
```bash
head -n 1 secrets.yml
# → $ANSIBLE_VAULT;1.2;AES256;production
```

### Обновление формата (Rekey)

Для повышения удобства управления (перехода на формат 1.2 с Vault ID) используйте команду смены ключа:
```bash
ansible-vault rekey --vault-id production@prompt secrets.yml
```
Это перешифрует файл с использованием актуального заголовка и позволит быстрее находить нужный пароль в CI/CD (Continuous Integration / Continuous Delivery).
