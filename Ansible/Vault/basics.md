# Ansible Vault: Основы

## Определения

- **Ansible Vault**: Встроенный в Ansible механизм для шифрования секретов, таких как пароли, ключи API (Application Programming Interface) и сертификаты SSL (Secure Sockets Layer). Он позволяет безопасно хранить чувствительные данные в системе контроля версий (Git) вместе с кодом автоматизации.
- **Хранилище (Vault)**: Зашифрованный YAML-файл (YAML Ain't Markup Language) или отдельная зашифрованная строка, содержащие секреты.
- **AES-256**: Стандартный алгоритм симметричного шифрования, используемый Ansible Vault для защиты данных.

## Основные концепции

### Принципы работы

Ansible Vault шифрует данные "на лету" во время выполнения плейбука. Для этого Ansible требуется доступ к паролю (или нескольким паролям). Зашифрованные данные помечаются заголовком `$ANSIBLE_VAULT;1.1;AES256`, который указывает на версию формата и используемый алгоритм.

### Источники паролей

Существует несколько способов предоставить пароль для расшифровки:

1. **Интерактивный ввод**: Флаг `--ask-vault-pass`.
2. **Файл пароля**: Флаг `--vault-password-file` или переменная окружения `ANSIBLE_VAULT_PASSWORD_FILE`.
3. **Vault ID**: Современный способ (с Ansible 2.4+), позволяющий использовать несколько паролей с метками: `--vault-id label@path_to_password_file`.

> **Важно:** При использовании файлов паролей обязательно добавляйте их в `.gitignore`, чтобы избежать случайной публикации секретов.

### Основные команды

- `create <file>`: Создать новый зашифрованный файл.
- `edit <file>`: Безопасно отредактировать зашифрованный файл.
- `encrypt <file>`: Зашифровать существующий файл.
- `decrypt <file>`: Расшифровать файл (не рекомендуется для хранения в Git).
- `view <file>`: Показать содержимое зашифрованного файла без его расшифровки на диске.
- `rekey <file>`: Сменить пароль для зашифрованного файла.
- `encrypt_string`: Зашифровать отдельную строку для вставки в обычный YAML-файл.

## Практические сценарии

### Сценарий 1: Работа с зашифрованными файлами

Обычно используется для создания файлов переменных для конкретных окружений (inventory vars).

1. **Создание файла**:

    ```bash
    ansible-vault create group_vars/all/vault.yml # → Vault password: (ввод пароля)
    ```

    В редакторе определяются переменные:

    ```yaml
    # group_vars/all/vault.yml
    db_password: "MySecretPassword"
    api_key: "12345-abcde"
    ```

2. **Запуск плейбука**:

    ```bash
    # С интерактивным вводом
    ansible-playbook deploy.yml --ask-vault-pass

    # С использованием файла пароля
    ansible-playbook deploy.yml --vault-password-file .vault_pass
    ```

### Сценарий 2: Шифрование отдельных переменных (Inline Vault)

Позволяет хранить зашифрованные значения внутри обычных YAML-файлов.

1. **Шифрование строки**:

    ```bash
    ansible-vault encrypt_string 'MySecretValue' --name 'db_password'
    # → New Vault password: (ввод пароля)
    # → db_password: !vault |
    # →   $ANSIBLE_VAULT;1.1;AES256
    # →   353432...
    ```

2. **Использование**:
    Вставьте полученный блок в файл с переменными. Ansible автоматически распознает тег `!vault`.

### Сценарий 3: Использование Vault ID

Полезно, когда разные группы секретов (например, `prod` и `dev`) зашифрованы разными паролями.

```bash
ansible-playbook site.yml --vault-id dev@.vault_pass_dev --vault-id prod@.vault_pass_prod
```
