# Ansible Vault: Использование нескольких хранилищ

Для разделения секретов по окружениям (dev, stage, prod) или командам можно использовать несколько Vault, каждый со своим паролем. Это делается с помощью идентификаторов (`vault-id`).

## Как это работает

1. При шифровании файла вы указываете его "имя" (ID) и источник пароля:

    ```bash
    # Шифруем файл для prod, пароль будет запрошен в консоли
    ansible-vault encrypt --vault-id prod@prompt group_vars/prod/secrets.yml
    
    # Шифруем файл для dev, пароль берется из файла
    ansible-vault encrypt --vault-id dev@./dev_pass.txt group_vars/dev/secrets.yml
    ```

    Зашифрованный файл будет содержать заголовок, указывающий на ID, который использовался при шифровании, например:

    ```
    $ANSIBLE_VAULT;1.1;AES256;prod
    ```

2. При запуске плейбука вы указываете, какой пароль использовать для какого ID:

    ```bash
    ansible-playbook my_playbook.yml 
      --vault-id prod@~/.prod_vault_pass 
      --vault-id dev@~/.dev_vault_pass
    ```

    Ansible автоматически применит правильный пароль к каждому зашифрованному файлу. Если `--vault-id` не указан, используется хранилище по умолчанию.

## Нюансы поведения `--vault-id`

По умолчанию Ansible довольно "снисходителен" к указанным `--vault-id`. Если вы предоставите несколько Vault ID и паролей (например, `id` и `non-id`):

```bash
ansible-playbook encrypted_playbook.yml --vault-id id@my_password.txt --vault-id non-id@another_password.txt
```

Ansible сначала попробует расшифровать файл паролем, соответствующим `id`, указанному в заголовке файла. Если это не сработает (или ID в заголовке файла отсутствует/не совпадает), он **переберет все остальные предоставленные пароли**, пытаясь найти подходящий. Это может быть как удобно, так и сбивать с толку.

Чтобы принудительно использовать только один конкретный `vault-id` для расшифровки, его нужно указать явно и убедиться, что он совпадает с тем, что был использован при шифровании.
