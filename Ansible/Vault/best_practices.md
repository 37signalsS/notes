# Ansible Vault: Лучшие практики

## Безопасность в логах (`no_log: true`)

Даже если переменная зашифрована в Vault, ее значение может **попасть в логи** при выполнении плейбука, если задача выводит свои параметры в консоль.

**Пример проблемы:**

```yaml
- name: Create database user
  community.postgresql.postgresql_user:
    name: "{{ db_user }}"
    password: "{{ db_password }}" # db_password из Vault
```

В логе выполнения `ansible-playbook` с высоким уровнем детализации (`-vvv`) можно будет увидеть реальное значение `db_password`.

**Решение:**
Добавляйте `no_log: true` к любой задаче, которая работает с чувствительными данными. Эта директива скроет все параметры задачи из логов.

```yaml
- name: Create database user
  community.postgresql.postgresql_user:
    name: "{{ db_user }}"
    password: "{{ db_password }}"
  no_log: true # <-- ВАЖНО
```

Это маскирует *всю* задачу, а не только одно поле, но это необходимая мера безопасности.

## Дополнительная информация

* Vault предназначен для хранения *существующих* секретов. Для генерации новых паролей используйте модуль [`ansible.builtin.password`](../../ansible_common_modules.md#7-модули-для-работы-с-паролями-и-чувствительными-данными).

### Предостережение: Шифрование общих ролей

Ansible Vault — отличный инструмент для защиты секретов, но его использование в общих ролях, которые распространяются или совместно используются с другими разработчиками, может вызвать проблемы.

**Проблема:** Если вы как разработчик зашифруете всю свою роль (например, `tasks/main.yml` или `templates/my_config.j2`) и отправите ее коллегам, они не смогут легко просматривать и отлаживать код роли, не имея пароля. Это значительно усложняет ревью кода, понимание логики и поиск ошибок, так как содержимое файлов будет нечитаемым.

**Рекомендация:** Шифруйте только те файлы или переменные, которые действительно содержат чувствительные данные (пароли, ключи, токены). Основную логику роли и шаблоны, не содержащие секретов, оставляйте в открытом виде. Секреты должны быть вынесены в отдельные зашифрованные файлы (например, `group_vars/all/vault.yml` или `host_vars/my_host/vault.yml`), которые используются ролями.
