# Ansible: Пример кроссплатформенной установки LEMP на Ubuntu и CentOS

Этот документ представляет собой практический пример плейбука для развертывания стека LEMP (Linux, Nginx, MySQL, PHP) на серверах под управлением Ubuntu и CentOS.

Для получения дополнительной информации о методах создания кроссплатформенных плейбуков см. [Кроссплатформенные плейбуки Ansible](cross_platform_playbooks.md).

---

## 1. Подготовка и запуск

1.  **Скопируйте материалы:** Убедитесь, что все необходимые файлы (плейбук, роли) находятся в рабочей директории на `controlnode`.
2.  **Установите зависимости:** Для работы с MySQL/MariaDB плейбуку требуется коллекция `community.mysql`.
    ```bash
    ansible-galaxy collection install community.mysql
    ```
3.  **Запустите плейбук:**
    ```bash
    ansible-playbook playbook.yml
    ```

После успешного выполнения плейбука на обоих серверах будет развернут веб-сервер с PHP.

## 2. Проверка результата

Вы можете проверить доступность сайтов, обратившись к ним в браузере по IP-адресам:
*   **Ubuntu:** `http://192.168.51.4`
*   **CentOS:** `http://192.168.51.3`

Чтобы проверить работу PHP и подключение к базе данных, вы можете добавить запись в ваш локальный файл `hosts` (на вашем компьютере, не на сервере):
```
192.168.51.3 php-test.com
```
После этого откройте в браузере `http://php-test.com` и `http://php-test.com/test-connection.php`.

## 3. Анализ вывода плейбука (PLAY RECAP)

После выполнения `ansible-playbook` выводит итоговую статистику по каждому хосту.

```
PLAY RECAP *********************************************************************
centos_server          : ok=24   changed=19   unreachable=0    failed=0    skipped=4    rescued=0    ignored=0   
ubuntu_server          : ok=21   changed=14   unreachable=0    failed=0    skipped=4    rescued=0    ignored=0
```

*   `ok`: Общее количество успешно выполненных задач (включая `changed`).
*   `changed`: Количество задач, которые внесли изменения в систему.
*   `unreachable`: Хост был недоступен.
*   `failed`: Задача завершилась с ошибкой.
*   `skipped`: Задача была пропущена (например, из-за условия `when`).

Разное количество `ok` и `changed` для `centos_server` и `ubuntu_server` является нормальным и ожидаемым, так как плейбук выполняет разные наборы задач для каждого семейства ОС. Например, для CentOS устанавливается дополнительный репозиторий EPEL, что увеличивает количество шагов.
