# Ansible: Vault

Ansible Vault — это встроенный в Ansible механизм для шифрования секретов, таких как пароли, API-ключи и SSL-сертификаты. Он позволяет безопасно хранить чувствительные данные в системе контроля версий вместе с остальным кодом автоматизации.

См. также: [Обзор Ansible](ansible_overview.md)

## Основные команды

Все команды `ansible-vault` запрашивают пароль для доступа к зашифрованному хранилищу.

*   **Создание нового зашифрованного файла:**
    ```bash
    ansible-vault create secrets.yml
    ```
    Откроется текстовый редактор для ввода данных.

*   **Редактирование существующего файла:**
    ```bash
    ansible-vault edit secrets.yml
    ```

*   **Шифрование существующего файла:**
    ```bash
    ansible-vault encrypt plain_secrets.yml
    ```
    Будет создан зашифрованный файл `plain_secrets.yml`.

*   **Расшифровка файла:**
    ```bash
    ansible-vault decrypt secrets.yml
    ```
    Это следует делать только при необходимости и не хранить расшифрованные файлы в репозитории.

*   **Просмотр содержимого без редактирования:**
    ```bash
    ansible-vault view secrets.yml
    ```

*   **Смена пароля хранилища:**
    ```bash
    ansible-vault rekey secrets.yml
    ```

## Использование Vault в плейбуках

Существует несколько способов предоставить пароль от Vault при запуске плейбука.

*   **Интерактивный запрос (`--ask-vault-pass`):**
    Самый безопасный метод для локального запуска.
    ```bash
    ansible-playbook my_playbook.yml --ask-vault-pass
    ```

*   **Файл с паролем (`--vault-password-file`):**
    Пароль хранится в файле, права на который должны быть строго ограничены. Этот метод подходит для CI/CD систем.
    ```bash
    # Создание файла с паролем
    echo "MySecretPassword" > ~/.vault_pass.txt
    chmod 600 ~/.vault_pass.txt

    # Запуск плейбука
    ansible-playbook my_playbook.yml --vault-password-file ~/.vault_pass.txt
    ```
    **Важно:** Добавьте файл с паролем в `.gitignore`.

*   **Переменная окружения (`ANSIBLE_VAULT_PASSWORD`):**
    Еще один способ для автоматизированных систем.
    ```bash
    export ANSIBLE_VAULT_PASSWORD="MySecretPassword"
    ansible-playbook my_playbook.yml
    ```

## Лучшие практики

*   **Один репозиторий:** Храните зашифрованные файлы переменных (`vars`) вместе с плейбуками в одном репозитории.
*   **Разделение секретов:** Используйте разные файлы для разных окружений (development, staging, production) и/или типов секретов (базы данных, API).
*   **Ограничение доступа:** Используйте разные пароли для разных уровней доступа.
*   **CI/CD:** В системах непрерывной интеграции используйте переменные окружения или защищенные хранилища секретов (HashiCorp Vault, AWS Secrets Manager) для передачи пароля от Ansible Vault.
