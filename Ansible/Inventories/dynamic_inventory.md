# Dynamic inventory в Ansible

## Определения

- **Dynamic inventory (Динамический инвентарь)**: Механизм Ansible, который формирует список хостов и их переменные "на лету", обращаясь к внешнему источнику правды (облачная платформа, CMDB, API). В отличие от статического файла, он всегда отражает актуальное состояние инфраструктуры.

## Основные концепции

### Когда это необходимо

- **Эфемерные среды и автоскейлинг**: Облачные экземпляры создаются и удаляются слишком часто, статический список моментально устаревает.
- **Мультиоблако и мультиаккаунты**: Необходимо объединять ресурсы из нескольких провайдеров и учетных записей.
- **Теги/метки как источник групп**: Возможность формировать группы по метаданным (`Role`, `Environment`, `Stage`, `Owner`) без правок инвентаря.
- **Контейнерные платформы**: Получение актуального списка узлов и сервисов через API кластеров (Kubernetes, Nomad).
- **CMDB**: Синхронизация с корпоративными каталогами и системами учета.

### Способы реализации

1. **Inventory plugins**: Предпочтительный, нативный способ. Ansible предоставляет плагины для большинства облаков и сервисов (например, `amazon.aws.aws_ec2`, `google.cloud.gcp_compute`, `community.digitalocean.digitalocean`).
2. **Исполняемые скрипты**: Любой исполняемый файл (`.py`, `.sh`, etc.), который при запуске с флагом `--list` возвращает JSON в специальном формате. Этот способ считается устаревающим, но все еще поддерживается.
3. **Комбинированный подход**: Директория `inventories/` может содержать несколько источников (статические и динамические файлы), которые Ansible объединяет в один инвентарь.

### Производительность и кэширование

Обращения к внешним API могут замедлять генерацию инвентаря. Для решения этой проблемы рекомендуется:

- **Включать кэширование** на уровне инвентарного плагина или глобально в `ansible.cfg`.
- **Использовать фильтры** в конфигурации плагина, чтобы ограничивать область поиска.
- **Использовать `compose`** для hostvars только для действительно необходимых переменных.
- **"Прогревать" кэш** в CI/CD пайплайнах, запуская `ansible-inventory` перед основным плейбуком.

**Пример настройки кэширования в `ansible.cfg`:**

```ini
[inventory]
enable_plugins = aws_ec2, yaml, ini, script
cache = True
cache_plugin = jsonfile
cache_timeout = 600
cache_connection = .cache/inventory
```

## Практические сценарии

### Сравнение статического и динамического подходов

| Критерий | Статический инвентарь | Динамический инвентарь |
| :--- | :--- | :--- |
| **Актуальность** | Требует ручного обновления | Вытягивается из источника правды |
| **Масштабируемость** | Ограничена размером файла | Горизонтально масштабируется |
| **Человеческий фактор**| Высокий риск ошибок | Снижается за счет автоматизации |
| **Группировка** | Ручные группы | Автоматически, по тегам/фильтрам |
| **Производительность**| Быстро локально | Требует кэширования для API |

### Пример: Динамический инвентарь с `amazon.aws.aws_ec2`

Это YAML-файл, который описывает, как получать и структурировать хосты из AWS.

**`inventories/aws_ec2.yml`:**

```yaml
plugin: amazon.aws.aws_ec2

# Специфичные параметры для AWS
regions:
  - eu-central-1
filters:
  tag:Env: prod
  instance-state-name: running
hostnames:
  - tag:Name
  - private-ip-address

# Общие параметры для постобработки
compose:
  ansible_host: private_ip_address
  env: tags.Env
keyed_groups:
  - key: tags.Env
    prefix: env
  - key: placement.availability_zone
    prefix: az
groups:
  web: "'nginx' in (tags.get('Role', '') | lower)"
  bastion: "tags.get('Role') == 'bastion'"

# Кэширование
cache: true
cache_plugin: jsonfile
cache_connection: .cache/aws
cache_timeout: 600

strict: false
```

- `regions` и `filters` ограничивают область поиска.
- `hostnames` задаёт приоритет источников для имени хоста в инвентаре.
- `compose`, `keyed_groups` и `groups` создают удобные переменные и группы на основе тегов.

Для просмотра итогового инвентаря используется команда:

```bash
ansible-inventory -i inventories/aws_ec2.yml --graph
```

### Пример: Собственный скрипт динамического инвентаря

Любой скрипт, который выводит JSON в определенном формате, может служить источником инвентаря.

**`inventory.py`:**

```python
#!/usr/bin/env python3
import json, sys

if '--list' in sys.argv:
    print(json.dumps({
        "app": {
            "hosts": ["app1", "app2"]
        },
        "_meta": {
            "hostvars": {
                "app1": {"ansible_host": "1.2.3.4"}
            }
        }
    }))
elif '--host' in sys.argv:
    print(json.dumps({}))
```
