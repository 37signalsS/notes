# Учебное пособие: Создание первого Playbook для Nginx

В этом руководстве мы пошагово создадим Ansible Playbook для автоматической установки и настройки веб-сервера Nginx на удаленном хосте. Мы пройдем путь от пустого файла до рабочего веб-сервера с кастомной страницей.

**Цели:**
1.  Познакомиться со структурой Ansible Playbook.
2.  Научиться использовать модули `apt`, `file` и `copy`.
3.  Понять концепции идемпотентности и повышения привилегий (`become`).

См. также:
*   [Обзор Ansible](ansible_overview.md)
*   [Ansible: Плейбуки](ansible_playbooks.md)

---

## 1. Что такое Playbook?

**Playbook** (плейбук) — это сердце Ansible. Термин заимствован из американского футбола, где "playbook" — это книга тренера со сценариями игры. В Ansible плейбук — это YAML-файл, который содержит сценарий, описывающий желаемое состояние системы. Вместо того чтобы последовательно выполнять команды вручную, вы декларируете, какой результат хотите получить, а Ansible сам определяет, как этого достичь.

Плейбуки пишутся на языке YAML. Ключевые особенности:
- Файл обычно начинается с `---` (не обязательно, но является хорошей практикой).
- Структура основана на отступах (строго 2 пробела).
- Комментарии начинаются с символа `#`.

## 2. Структура и первый запуск

Любой плейбук — это **список (массив)**, состоящий из одного или нескольких **"плеев" (plays)**. В YAML массив обозначается дефисом (`-`). Каждый плей, в свою очередь, — это набор задач для определенной группы хостов.

Создадим наш первый плейбук `playbook.yml`:

```yaml
---
# Наш первый плейбук для развертывания LEMP-стека
- name: Configure web server
  hosts: all
```
- `-`: Этот дефис означает начало первого (и единственного) элемента в нашем списке плеев.
- `name`: Описание того, что делает этот плей.
- `hosts: all`: Указывает, что плей будет применяться ко всем хостам из нашего инвентарного файла.

Запустим его. Для этого используется команда `ansible-playbook`.

```bash
# -i inventory.ini указывает на файл с хостами
ansible-playbook playbook.yml -i inventory.ini
```

Результат выполнения:
```
PLAY [Configure web server] *************************************************

TASK [Gathering Facts] ******************************************************
ok: [server1]

PLAY RECAP ******************************************************************
server1                    : ok=1    changed=0    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
```
Ansible выполнил одну задачу по умолчанию — **`Gathering Facts`**. На этом этапе специальный модуль Ansible подключается к хосту и собирает о нем всю возможную информацию (ОС, версии, IP-адреса, память, диски и т.д.). Эти "факты" затем можно использовать как переменные в последующих задачах плейбука.

## 3. Добавление задач (Tasks)

Теперь добавим конкретные шаги для настройки сервера. Задачи описываются в секции `tasks`. Как и плеи в плейбуке, `tasks` — это **список (массив)** задач, которые выполняются последовательно.

### Задача 1: Установка Nginx

Добавим задачу для установки Nginx с помощью модуля `apt`.

```yaml
---
- name: Configure web server
  hosts: all
  become: true # <-- Добавили повышение привилегий

  tasks:
    - name: Install nginx via apt # Имя задачи для понятного вывода
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: yes
```

Разберем эту задачу:
- `become: true`: При первом запуске плейбук, скорее всего, завершится с ошибкой прав доступа, так как по умолчанию Ansible выполняет команды от имени текущего пользователя (`vagrant`), а установка пакетов требует прав `root`. Директива `become: true` на уровне плея говорит Ansible выполнять все задачи с повышенными привилегиями (через `sudo`).
- `ansible.builtin.apt`: Мы используем **полное имя модуля (FQCN)**. Это лучшая практика, так как она позволяет избежать конфликтов, если в системе установлено несколько коллекций с модулями с одинаковыми короткими именами (например, `apt`).
- `name: nginx`: Имя пакета, который мы хотим установить.
- `state: present`: Декларативный параметр. Мы говорим: "пакет nginx должен **присутствовать** в системе". Если он уже установлен, Ansible ничего не сделает. Если его нет — установит. Другой вариант — `latest`, который обновит пакет, если доступна новая версия.
- `update_cache: yes`: Аналог команды `apt-get update`. Обновляет кэш пакетов перед установкой.

Запустим плейбук еще раз. Теперь вывод будет содержать нашу задачу, и она будет помечена как `changed`, так как в систему были внесены изменения.

### Идемпотентность в действии

**Идемпотентность** — это фундаментальное свойство Ansible, которое означает, что повторный запуск одной и той же операции не приведет к дополнительным изменениям, если система уже находится в желаемом состоянии.

Если запустить наш плейбук во второй раз, Ansible не будет переустанавливать Nginx. Модуль `apt` проверит, что пакет `nginx` уже присутствует в системе, и ничего не будет делать. Задача `Install nginx` будет помечена зеленым цветом и статусом `ok`, подтверждая, что система уже соответствует описанному состоянию.

### Стандартная конфигурация Nginx в Ubuntu

После установки пакета Nginx на Ubuntu система автоматически настраивает базовую конфигурацию, готовую к работе. Ключевые моменты этой конфигурации:

-   **Основной конфигурационный файл:** `/etc/nginx/nginx.conf`.
-   **Включения:** Этот файл загружает конфигурации для виртуальных хостов из директории `/etc/nginx/sites-enabled/`.
-   **Сайт по умолчанию:** В `sites-enabled` находится символическая ссылка на файл `/etc/nginx/sites-available/default`, который описывает стандартный сайт.
-   **Корневая директория:** По умолчанию файлы сайта отдаются из `/var/www/html`.
-   **Страница-заглушка:** При обращении к серверу вы увидите стандартную страницу приветствия Nginx, которая находится в `/var/www/html/index.nginx-debian.html`.

## 4. Управление файлами и контентом

Теперь заменим стандартную страницу приветствия Nginx на нашу.

### Задача 2: Удаление стандартной директории

Удалим стандартное содержимое, чтобы на его место положить наше. Используем модуль `ansible.builtin.file`.

```yaml
# ... (внутри секции tasks)
    - name: Remove default html directory
      ansible.builtin.file:
        path: /var/www/html
        state: absent # Убедиться, что директория отсутствует
```
- `path`: Путь к файлу или директории.
- `state: absent`: Гарантирует, что по указанному пути ничего не будет. Если директория существует, Ansible ее удалит. Это чистый способ избавиться от стандартной страницы Nginx и другого содержимого по умолчанию перед развертыванием нашего сайта.

### Задача 3: Копирование нашего сайта

Скопируем файлы нашего сайта с управляющей машины на целевой хост с помощью модуля `ansible.builtin.copy`.

Предположим, что рядом с плейбуком у нас есть папка `files/html/...` с файлами нашего лендинга.

```yaml
# ... (внутри секции tasks)
    - name: Copy our landing page content
      ansible.builtin.copy:
        src: files/html # Что копируем (относительно плейбука)
        dest: /var/www/ # Куда копируем
        owner: vagrant
        group: vagrant
        mode: '0755' # Права доступа
```
- `src`: Путь к файлу или директории на управляющей машине.
- `dest`: Путь назначения на удаленном хосте. При копировании директории модуль `copy` создает ее внутри `dest`. То есть, `src: files/html` скопируется в `/var/www/html`.
- `owner`, `group`, `mode`: Задают владельца, группу и права доступа для скопированных файлов. Это важный шаг: при ручной настройке нам пришлось бы менять владельца директории `/var/www/` (которая по умолчанию принадлежит `root`) с помощью команды `chown`, чтобы наш пользователь (`vagrant`) мог в нее записывать. Ansible делает это автоматически для скопированных файлов, обеспечивая правильные права доступа.

## 5. Полный Playbook и результат

Итоговый плейбук выглядит так:

```yaml
---
# playbook.yml
- name: Configure Nginx Web Server
  hosts: all
  become: true

  tasks:
    - name: Install nginx via apt
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: yes

    - name: Remove default html directory
      ansible.builtin.file:
        path: /var/www/html
        state: absent

    - name: Copy our landing page content
      ansible.builtin.copy:
        src: files/html # Директория с вашим сайтом
        dest: /var/www/
        owner: vagrant
        group: vagrant
        mode: '0755'
```

После запуска этого плейбука Nginx будет установлен, а по IP-адресу вашего сервера будет открываться ваша кастомная страница. Мы успешно автоматизировали процесс развертывания! Дальше можно добавлять задачи для настройки PHP, MySQL и других компонентов вашего приложения.
