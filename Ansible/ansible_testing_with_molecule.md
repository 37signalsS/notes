# Тестирование ролей Ansible с помощью Molecule

Molecule — это фреймворк для автоматизированного тестирования ролей и плейбуков Ansible. Он позволяет создавать временные, изолированные окружения (с помощью Docker, Vagrant, облачных провайдеров), применять к ним ваш код и проверять, что он работает корректно. Это ключевой инструмент для внедрения практик CI/CD в разработку Ansible-автоматизации.

## 2. Зачем нужен Molecule?

Представьте, что вы написали сложную роль. Чтобы убедиться в ее работоспособности, вам нужно:
1.  Поднять тестовый сервер (или несколько).
2.  Запустить на нем плейбук с вашей ролью.
3.  Вручную проверить, что все настроилось правильно.
4.  Повторить это для разных операционных систем.

Molecule автоматизирует этот процесс. Он позволяет:
*   **Инициализировать роль** со всей необходимой тестовой обвязкой.
*   **Интегрироваться в CI/CD пайплайны** (GitLab CI, Jenkins) для автоматического прогона тестов при каждом коммите.
*   **Создавать и уничтожать тестовые окружения** на лету, используя различные "драйверы" (Docker, Vagrant, OpenStack и др.).
*   **Проводить линтинг** кода (`ansible-lint`) как один из шагов тестирования.

## 3. Установка

Molecule является Python-пакетом и устанавливается через `pip`. Рекомендуется устанавливать его вместе с драйвером, который вы планируете использовать (например, Docker), и линтером.

```bash
# Установка Molecule с поддержкой Docker и ansible-lint
pip install "molecule[docker,lint]"

# Иногда могут потребоваться системные зависимости
# sudo apt-get install python3-pip libssl-dev
```
> **Примечание о версиях:**
> Molecule тесно связан с версией Ansible. Если вы сталкиваетесь с ошибками совместимости, может потребоваться установить конкретную версию Molecule, совместимую с вашей версией Ansible.
> `pip install molecule==X.Y.Z`

## 4. Инициализация роли и структура тестов

Для создания новой роли вместе с тестовой структурой Molecule используется команда `init role`.

```bash
molecule init role my_new_role
```
Эта команда создаст стандартную структуру `ansible-galaxy` и добавит в нее директорию `molecule/`. Внутри нее находится сценарий тестирования `default`.

```
my_new_role/
└── molecule/
    └── default/
        ├── create.yml      # Плейбук для создания тестового инстанса
        ├── destroy.yml     # Плейбук для уничтожения инстанса
        ├── converge.yml    # Основной плейбук, применяющий вашу роль
        ├── molecule.yml    # Главный файл конфигурации сценария
        └── verify.yml      # Плейбук для проверки состояния системы после converge
```
Вы можете создавать несколько сценариев тестирования (например, для разных ОС) с помощью команды `molecule init scenario <scenario_name>`.

## 5. Файл конфигурации `molecule.yml`

Это сердце тестового сценария. В нем описывается, как Molecule должен проводить тестирование.

**Пример `molecule.yml`:**
```yaml
---
dependency:
  name: galaxy
driver:
  name: docker
platforms:
  - name: instance
    image: "geerlingguy/docker-ubuntu2004-ansible:latest"
    pre_build_image: true
provisioner:
  name: ansible
verifier:
  name: ansible
```

**Ключевые секции:**

*   `dependency`: Определяет, как управлять зависимостями роли (например, скачивать их с помощью `ansible-galaxy`).
*   `driver`: Указывает, какой инструмент использовать для создания тестовых окружений.
    *   `docker`: (самый популярный) для запуска тестов в контейнерах.
    *   `vagrant`: для создания полноценных виртуальных машин.
    *   `delegated`: Molecule не управляет созданием инстансов. Вы должны предоставить их сами (например, если у вас есть постоянные тестовые серверы).
*   `platforms`: Описывает тестовые инстансы, которые будут созданы. Это, по сути, инвентарь для вашего теста. Здесь можно указать имя, образ, группы и другие параметры.
*   `provisioner`: Инструмент, который будет применять конфигурацию. Почти всегда это `ansible`.
*   `verifier`: Инструмент для проверки. `ansible` — стандартный верифаер, который использует плейбук `verify.yml` для запуска тестов (например, с помощью модуля `assert`).

### Плейбуки сценария

*   `create.yml` и `destroy.yml`: Эти плейбуки готовят и уничтожают окружение. Если вы используете драйверы `docker` или `vagrant`, Molecule сгенерирует их содержимое автоматически. Если `delegated` — вы должны описать здесь, как получить доступ к вашим машинам.
*   `converge.yml`: Основная задача этого плейбука — применить тестируемую роль к созданному инстансу.
    ```yaml
    ---
    - name: Converge
      hosts: all
      tasks:
        - name: "Include my_new_role"
          include_role:
            name: "my_new_role"
    ```
*   `verify.yml`: Здесь вы пишете тесты, которые проверяют, что роль отработала корректно.
    ```yaml
    ---
    - name: Verify
      hosts: all
      gather_facts: false
      tasks:
        - name: Check that Nginx is installed
          ansible.builtin.package:
            name: nginx
            state: present
          check_mode: true
          register: nginx_pkg
        
        - name: Assert that nginx package is present
          ansible.builtin.assert:
            that:
              - not nginx_pkg.changed
            fail_msg: "Nginx package was not installed"
            success_msg: "Nginx package is present"
    ```

## 6. Жизненный цикл и команды

Molecule предоставляет набор команд для управления всем циклом тестирования.

*   `molecule test`: Запускает полный цикл тестирования по умолчанию:
    1.  `dependency`: Установка зависимостей.
    2.  `lint`: Проверка кода линтером.
    3.  `cleanup`: Очистка (если нужна).
    4.  `destroy`: Уничтожение старых инстансов.
    5.  `syntax`: Проверка синтаксиса плейбуков.
    6.  `create`: Создание инстансов.
    7.  `prepare`: Подготовка инстансов (если есть `prepare.yml`).
    8.  `converge`: Запуск основного плейбука.
    9.  `idempotence`: Повторный запуск `converge` для проверки идемпотентности.
    10. `verify`: Запуск тестов из `verify.yml`.
    11. `destroy`: Уничтожение инстансов.

*   **Отдельные команды:** Вы можете запускать каждый шаг по отдельности, что очень удобно для отладки.
    *   `molecule create`: Создать окружение.
    *   `molecule converge`: Применить роль.
    *   `molecule login`: Подключиться к тестовому инстансу по SSH.
    *   `molecule verify`: Запустить тесты.
    *   `molecule destroy`: Уничтожить окружение.

> **Практический совет:**
> Если ваша роль требует предварительной настройки серверов (например, установки определенного ПО), используйте для этого плейбук `prepare.yml` в сценарии. Molecule выполнит его после создания инстанса и до `converge`.
