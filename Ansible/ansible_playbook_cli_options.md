# Ansible: Ключи командной строки для `ansible-playbook`

Команда `ansible-playbook` имеет множество ключей, которые позволяют гибко управлять процессом выполнения плейбуков. Ниже рассмотрены наиболее важные и часто используемые из них.

### `--diff`
Показывает изменения в файлах, управляемых через шаблоны или другие модули. Вместо простого статуса `changed` (желтый), Ansible выведет `diff` в стиле Git, показывая, что именно было добавлено или удалено. Это очень полезно для отладки и контроля изменений.

### `--force-handlers`
Заставляет Ansible выполнять обработчики (`handlers`) даже в том случае, если выполнение плейбука было прервано из-за ошибки в одной из задач.

**Сценарий использования:**
Представьте, что плейбук настраивает несколько сервисов. Первые задачи успешно меняют конфигурацию `sshd` и уведомляют хэндлер о необходимости перезапуска. Но затем одна из последующих задач (например, установка пакета) падает из-за отсутствия интернет-соединения.
*   **Без `--force-handlers`**: Выполнение прервется, и хэндлер для `sshd` не будет вызван. При следующем запуске плейбука задача конфигурации `sshd` вернет `ok` (так как конфигурация уже изменена), и хэндлер снова не будет вызван, оставляя сервис со старой конфигурацией.
*   **С `--force-handlers`**: Ansible выполнит все "накопленные" хэндлеры перед завершением работы, гарантируя, что система останется в более консистентном состоянии, даже если плейбук не завершился полностью.

Рекомендуется использовать этот ключ в CI/CD и при автоматических запусках.

### `--inventory` (короткая форма: `-i`)
Указывает путь к файлу инвентаризации, в котором определены хосты и группы для выполнения плейбука.

```bash
ansible-playbook -i /path/to/inventory.ini playbook.yml
```

### `--limit`
Ограничивает выполнение плейбука только указанными хостами или группами из файла инвентаризации. Это позволяет иметь общий инвентарь для всей инфраструктуры, но выполнять задачи только на подмножестве хостов. Очень полезно для тестирования и отладки.

```bash
# Выполнить плейбук только на хосте web1
ansible-playbook -i inventory.ini --limit web1 playbook.yml

# Выполнить плейбук на всех хостах в группе 'database'
ansible-playbook -i inventory.ini --limit database playbook.yml
```

### `--step`
Включает пошаговое выполнение плейбука. Перед каждой задачей Ansible будет запрашивать подтверждение (`y` - yes, `n` - no, `c` - continue), позволяя вам контролировать процесс. В основном используется для отладки.

### `--become`
Указывает Ansible на необходимость повышения привилегий (обычно через `sudo`) для выполнения задач. Даже если `become: yes` указано в самом плейбуке, этот ключ можно использовать для явного указания или переопределения этого поведения при запуске.

### `--ask-pass` (короткая форма: `-k`)
Запрашивает пароль для SSH-подключения. Используется, если аутентификация на удаленных хостах настроена по паролю, а не по SSH-ключам.

### `--ask-become-pass` (короткая форма: `-K`)
Запрашивает пароль для повышения привилегий (`sudo`). Используется, если пользователь, под которым подключается Ansible, требует ввода пароля для выполнения `sudo`.
