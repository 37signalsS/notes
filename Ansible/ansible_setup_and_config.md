# Установка и настройка Ansible

## Определения

**Контрольный узел (Control Node)** — машина, на которой установлен Ansible и с которой запускаются команды и плейбуки. Требует наличия Python. **Управляемый узел (Managed Node)** — целевой сервер или устройство, которым управляет Ansible. В большинстве случаев требует только наличие SSH-доступа и интерпретатора Python. **Инвентарь (Inventory)** — файл (`.ini`, `YAML` и др.), который описывает управляемые узлы, их группы и переменные подключения. Является основой для целеуказания в Ansible. **Ad-hoc команда** — быстрые однострочные команды (подробно в [Введении в Ansible](./ansible_introduction.md#ad-hoc-команды)). **`ansible.cfg`** — основной конфигурационный файл Ansible, определяющий его поведение, пути к файлам, настройки подключения по умолчанию. **Плагин подключения (Connection Plugin)** — компонент, отвечающий за способ подключения к управляемному узлу: `ssh` (по умолчанию), `local`, `docker`, `winrm`.

## Основные концепции

### Файл конфигурации (`ansible.cfg`)

Файл `ansible.cfg` позволяет централизованно управлять настройками самого Ansible, избавляя от необходимости каждый раз указывать одни и те же параметры в командной строке.

**Иерархия и приоритет**

Ansible ищет файл `ansible.cfg` в нескольких местах в строгом порядке. Будет использован **первый найденный** файл. Порядок приоритета (от высшего к низшему):

1. **Переменная окружения `ANSIBLE_CONFIG`**: Путь к файлу конфигурации задан явно.
2. **`ansible.cfg` в текущей директории**: Самый распространенный и рекомендуемый способ, так как он позволяет иметь индивидуальные настройки для каждого проекта.
3. **`~/.ansible.cfg`**: Скрытый файл конфигурации в домашней директории текущего пользователя.
4. **/etc/ansible/ansible.cfg**: Глобальный конфигурационный файл для всей системы.

### Файл инвентаризации (`inventory`)

Файл инвентаризации определяет хосты и группы хостов, которыми вы управляете.

#### Форматы инвентаря: INI, YAML и JSON

Ansible поддерживает три основных формата для файлов инвентаризации: INI (классический), YAML и JSON.

**INI-формат**

Прост для чтения и плоских структур.

```ini
# inventory.ini
[webservers]
web1.example.com
web2.example.com ansible_port=2222

[dbservers]
db1.example.com

[servers:children]
webservers
dbservers
```

**YAML-формат**

Предпочтителен для сложных структур, так как позволяет определять вложенные группы и переменные более наглядно.

```yaml
# inventory.yml
all:
  children:
    webservers:
      hosts:
        web1.example.com:
        web2.example.com:
          ansible_port: 2222
    dbservers:
      hosts:
        db1.example.com:
    servers:
      children:
        webservers:
        dbservers
```

**JSON-формат**

Используется реже, преимущественно для динамических инвентарей.

```json
{
  "webservers": {
    "hosts": {
      "web1.example.com": {},
      "web2.example.com": {"ansible_port": 2222}
    }
  },
  "dbservers": {
    "hosts": {
      "db1.example.com": {}
    }
  }
}
```

**Метагруппа `all`:** специальная группа, объединяющая все хосты и все группы в инвентаре. Переменные, определённые для `all`, применяются глобально ко всем управляемым узлам. Например, глобальная переменная `ansible_python_interpreter` указывает путь к интерпретатору Python для всех хостов.

#### Переменные инвентаря

Подробное описание переменных инвентаря (`host_vars`, `group_vars`), их приоритета и области видимости — в [Переменные и факты Ansible](./PlaybookStructure/variables.md).

**Переменные подключения**

Параметры подключения задаются как переменные, привязанные к хосту:

- `ansible_host`: IP-адрес или DNS-имя целевой машины.
- `ansible_user`: Имя пользователя для SSH-подключения.
- `ansible_ssh_private_key_file`: Путь к приватному SSH-ключу.

> **Внимание:** Хранение паролей в открытом виде (`ansible_ssh_pass`) **крайне небезопасно**. Для реальных проектов **всегда** используйте [Ansible Vault](./Vault/basics.md).

> Для поиска всех доступных переменных для плагина подключения используйте: `ansible-doc -t connection ssh`.

### Типы подключений (Connection Plugins)

Плагин для хоста задается через переменную `ansible_connection`. Узнать, какие плагины доступны, можно командой `ansible-doc -t connection -l`.

**Базовые плагины подключения:**

- `ssh`: Стандартное подключение (по умолчанию).
- `local`: Для выполнения задач на самом контрольном узле.
- `docker`: Для подключения к Docker-контейнерам. В современных версиях требуется полное имя коллекции (FQCN), например `community.docker.docker`.
- `winrm`: Для подключения к машинам Windows.

**Плагины подключения для сетевого оборудования:**

Сетевые модули Ansible имеют важное отличие: они **выполняются на управляющем узле**, а не на управляемом устройстве. Это связано с тем, что на большинстве сетевого оборудования (маршрутизаторы, коммутаторы) отсутствует возможность запускать Python-код.

- `ansible.netcommon.network_cli`: Подключение через CLI over SSH. Основной способ для работы с Cisco EOS, Juniper JunOS и другими сетевыми ОС. Команды передаются через SSH-сессию как интерактивные команды CLI.
- `ansible.netcommon.netconf`: Подключение через NETCONF (XML over SSH). Требует поддержки NETCONF на сетевом устройстве.
- `ansible.netcommon.httpapi`: Подключение через HTTP/HTTPS API. Используется для устройств с REST API (например, MikroTik RouterOS).
- `ansible.netcommon.network_cli` с `telnet`: Для устаревших устройств, поддерживающих только Telnet.

Пример использования в инвентаре для сетевого устройства:

```ini
[cisco_switches]
192.168.1.60 ansible_network_os=cisco.eos.eos ansible_connection=ansible.netcommon.network_cli ansible_user=admin ansible_ssh_pass=password
```

Просмотр всех доступных сетевых модулей:

```bash
ansible-doc -l | grep eos
```

Документация по сетевой автоматизации: [docs.ansible.com](https://docs.ansible.com/ansible/latest/network/index.html).

## Практические сценарии

### Установка и проверка подключения

#### Установка Ansible (рекомендуемый способ `pip`)

```bash
python3 -m venv ansible_env
source ansible_env/bin/activate
pip install ansible
```

#### Генерация конфигурационного файла

Для создания базового конфигурационного файла с настройками по умолчанию используйте команду:

```bash
ansible-config init --disabled > ansible.cfg
```

#### Настройка `ansible.cfg` и `inventory`

**Пример `ansible.cfg`:**

```ini
[defaults]
inventory = ./inventory
remote_user = ansible_user
private_key_file = /path/to/your/private_key
host_key_checking = false
deprecation_warnings = False
roles_path = ./roles
```

**Пример `inventory`:**

```ini
[servers]
server1 ansible_host=192.168.51.4
```

#### Проверка подключения

Проверка подключения и ad-hoc команды подробно описаны в [Введении в Ansible](./ansible_introduction.md#ad-hoc-команды).
