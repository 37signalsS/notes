# Установка и настройка Ansible

## Определения

- **Контрольный узел (Control Node)** — машина, на которой установлен Ansible и с которой запускаются команды и плейбуки. Требует наличия интерпретатора Python.
- **Управляемый узел (Managed Node)** — целевой сервер или устройство, которым управляет Ansible. Требует наличия SSH-доступа и интерпретатора Python.
- **Инвентарь (Inventory)** — файл, описывающий управляемые узлы, их группы и переменные подключения.
- **Ad-hoc команда** — однострочная команда для быстрого выполнения задачи (подробно в [Введении в Ansible](./ansible_introduction.md#ad-hoc-команды)).
- **ansible.cfg** — основной конфигурационный файл Ansible.
- **Плагин подключения (Connection Plugin)** — компонент, отвечающий за способ связи с управляемым узлом (например, `ssh`, `local`, `docker`, `winrm`).

## Базовые концепции

### Файл конфигурации — ansible.cfg

Файл `ansible.cfg` позволяет централизованно управлять настройками самого Ansible, избавляя от необходимости каждый раз указывать одни и те же параметры в командной строке.

**Иерархия и приоритет**

Ansible ищет файл `ansible.cfg` в нескольких местах в строгом порядке. Будет использован **первый найденный** файл. Порядок приоритета (от высшего к низшему):

1. **Переменная окружения `ANSIBLE_CONFIG`**: путь к файлу конфигурации задан явно.
2. **`ansible.cfg` в текущей директории**: рекомендуемый способ, позволяющий иметь индивидуальные настройки для каждого проекта.
3. **`~/.ansible.cfg`**: скрытый файл конфигурации в домашней директории текущего пользователя.
4. **/etc/ansible/ansible.cfg**: глобальный конфигурационный файл для всей системы.

### Файл инвентаризации — Inventory

Файл инвентаризации определяет хосты и группы хостов, которыми вы управляете.

#### Форматы инвентаря

Ansible поддерживает три основных формата для файлов инвентаризации: INI (классический), YAML и JSON.

**Формат INI**

Прост для чтения и плоских структур.

```ini
# inventory.ini
[webservers]
web1.example.com
web2.example.com ansible_port=2222

[dbservers]
db1.example.com

[servers:children]
webservers
dbservers
```

**Формат YAML**

Предпочтителен для сложных структур, так как позволяет определять вложенные группы и переменные более наглядно.

```yaml
# inventory.yml
all:
  children:
    webservers:
      hosts:
        web1.example.com:
        web2.example.com:
          ansible_port: 2222
    dbservers:
      hosts:
        db1.example.com:
    servers:
      children:
        webservers:
        dbservers
```

**Метагруппа `all`:** специальная группа, объединяющая все хосты и все группы в инвентаре. Переменные, определённые для `all`, применяются глобально ко всем управляемым узлам.

#### Переменные инвентаря

Подробное описание переменных инвентаря (`host_vars`, `group_vars`), их приоритета и области видимости — в руководстве [Переменные и факты Ansible](./PlaybookStructure/variables.md).

**Переменные подключения**

Параметры подключения задаются как переменные, привязанные к хосту:

- `ansible_host`: **IP (Internet Protocol)** адрес или **DNS (Domain Name System)** имя целевой машины.
- `ansible_user`: имя пользователя для **SSH (Secure Shell)** подключения.
- `ansible_ssh_private_key_file`: путь к приватному SSH-ключу.

> **Внимание:** хранение паролей в открытом виде (`ansible_ssh_pass`) **крайне небезопасно**. Для реальных проектов всегда используйте [Ansible Vault](./Vault/basics.md).

### Типы подключений

Плагин для хоста задается через переменную `ansible_connection`. Узнать список доступных плагинов можно командой:

```bash
ansible-doc -t connection -l
```

**Базовые плагины подключения:**

- `ssh`: стандартное подключение по протоколу SSH (используется по умолчанию).
- `local`: для выполнения задач на самом контрольном узле.
- `docker`: для управления Docker-контейнерами.
- `winrm`: для подключения к машинам под управлением Windows.

> **Практический совет:** Если Ansible запускается **внутри** контейнера (например, `postgres-master`) для настройки этого же контейнера, используйте `ansible_connection=local` в инвентаре для этого хоста. Это предотвратит попытки Ansible подключиться к самому себе через SSH, что часто невозможно или избыточно в контейнеризированных средах.

**Сетевое оборудование:** сетевые устройства используют специализированные плагины (`network_cli`, `netconf`, `httpapi`). Подробное описание принципов работы с сетью — в [Автоматизации сетевого оборудования](./ansible_network_automation.md).

### Управление привилегиями

Для выполнения задач с правами суперпользователя используется директива `become`. Подробнее о безопасности и лучших практиках см. [Рекомендации по безопасности](ansible_security_best_practices.md).

## Практические сценарии

### Установка и проверка подключения

#### Установка Ansible

**Через pip (рекомендуемый способ):**

```bash
# Создание виртуального окружения
python3 -m venv ansible_env
source ansible_env/bin/activate
# Установка полного пакета Ansible
pip install ansible
```

Пакет `ansible` включает `ansible-core` и популярные коллекции. `pip install ansible-core` устанавливает только ядро без коллекций. Рекомендуется использовать виртуальные окружения (**venv**).

**PEP 668 (Externally Managed Environment):** в современных дистрибутивах (например, Ubuntu 23.04+) установка через `pip` вне виртуального окружения заблокирована. Подробнее — [Менеджмент Python](../Linux/Development/python_management.md#pep-668-externally-managed-environment).

#### Генерация конфигурационного файла

Для создания базового конфигурационного файла с настройками по умолчанию:

```bash
ansible-config init --disabled > ansible.cfg
```

#### Настройка проекта

**Пример `ansible.cfg`:**

```ini
[defaults]
inventory = ./inventory
remote_user = ansible_user
private_key_file = /path/to/your/private_key
host_key_checking = false
deprecation_warnings = False
roles_path = ./roles

# Явное указание интерпретатора Python для подавления предупреждений
interpreter_python = auto_silent
```

Для настройки параметров производительности см. [Оптимизацию производительности Ansible](./ansible_performance_tuning.md).

**Пример `inventory`:**

```ini
[servers]
server1 ansible_host=192.168.51.4
```

#### Проверка подключения

Проверка подключения выполняется ad-hoc командой:

```bash
ansible all -m ping
# → server1 | SUCCESS => { "ansible_facts": { "discovered_interpreter_python": "/usr/bin/python3" }, "changed": false, "ping": "pong" }
```

### Сбор фактов

Ansible автоматически собирает информацию об управляемых узлах. **Всегда используйте словарь `ansible_facts`** для обращения к системным данным:

- Правильно: `{{ ansible_facts['distribution'] }}`
- Устаревающее: `{{ ansible_distribution }}`

Подробнее — в [Переменные и факты Ansible](./PlaybookStructure/variables.md).
