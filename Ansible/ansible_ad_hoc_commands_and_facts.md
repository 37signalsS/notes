# Ansible: Ad-Hoc команды и Факты

Ansible предоставляет возможность быстро выполнять команды на управляемых узлах без создания полноценных плейбуков. Это называется "Ad-Hoc командами" и очень удобно для быстрой проверки состояния или сбора информации.

## 1. Ad-Hoc команды

Ad-Hoc команды позволяют запустить один модуль на одном или нескольких хостах.

### Пример 1: Использование модуля `command` (модуль по умолчанию)

Если модуль не указан явно, Ansible использует модуль `command`.

```bash
ansible localhost -a "date"
```
**Объяснение:**
*   `ansible localhost`: Выполнить команду на хосте `localhost`.
*   `-a "date"`: Передать аргумент `date` (команду для выполнения) в модуль `command`.

**Результат:**
Команда `date` будет выполнена на `localhost`, и Ansible вернет статус выполнения.

### Пример 2: Использование модуля `setup` (сбор фактов)

Модуль `setup` собирает обширную информацию (факты) об управляемом хосте.

```bash
ansible localhost -m setup
```
**Объяснение:**
*   `ansible localhost`: Выполнить команду на хосте `localhost`.
*   `-m setup`: Указать модуль `setup`.

**Результат:**
Ansible выведет большой объем JSON-данных, содержащих информацию о системе, такую как IP-адреса, операционная система, версии, ядро, жесткие диски и т.д. Эти "факты" автоматически собираются при первом соединении с сервером и могут быть использованы в плейбуках как переменные.

### Пример 3: Использование модуля `ping` на удаленных серверах

Модуль `ping` используется для проверки доступности и работоспособности Ansible на удаленных хостах.

```bash
ansible ws01,ws02,ws03 -m ping -i inventory.ini -u bond --ask-pass
```
**Объяснение:**
*   `ansible ws01,ws02,ws03`: Выполнить команду на указанных хостах.
*   `-m ping`: Использовать модуль `ping`.
*   `-i inventory.ini`: Указать файл инвентаря (например, `inventory.ini`), где определены хосты `ws01`, `ws02`, `ws03`.
*   `-u bond`: Указать пользователя `bond` для SSH-подключения.
*   `--ask-pass`: Запросить пароль для SSH-подключения.

**Результат:**
Если подключение успешно, каждый хост вернет `pong`, подтверждая, что Ansible может успешно соединиться и выполнить модуль.

## 2. Файл инвентаризации

Файл инвентаризации (`inventory.ini` или любой другой) определяет список управляемых хостов.

**Пример `inventory.ini`:**
```ini
ws01 ansible_host=192.168.1.101
ws02 ansible_host=192.168.1.102
ws03 ansible_host=192.168.1.103
```
*   `ws01`, `ws02`, `ws03`: Псевдонимы хостов, которые используются в командах и плейбуках.
*   `ansible_host`: Переменная, указывающая IP-адрес или DNS-имя целевого сервера, к которому должен обращаться Ansible.

**Примечание:** Для более сложных инвентарей рекомендуется использовать группы хостов и хранить параметры подключения в файлах `group_vars` или `host_vars`, а чувствительные данные шифровать с помощью [Ansible Vault](../ansible_vault.md).
