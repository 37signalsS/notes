# Ansible: Выполнение плейбуков

В реальных сценариях автоматизации используется не выполнение отдельных команд, а **плейбуки** (playbooks) — YAML-файлы, содержащие упорядоченный список задач для выполнения на серверах. Сами серверы, на которых нужно выполнять задачи, определяются в файле **инвентаризации** (inventory).

## 1. Запуск плейбука

Для запуска плейбука используется команда `ansible-playbook`.

```bash
ansible-playbook -i inventory.ini --ask-pass playbook.yml
```
**Ключи команды:**
*   `ansible-playbook`: Команда для запуска выполнения плейбука.
*   `-i inventory.ini`: Указывает путь к файлу инвентаризации, где перечислены целевые хосты.
*   `--ask-pass` (или `-k`): Запрашивает пароль для SSH-подключения к удаленным хостам.
*   `playbook.yml`: Путь к файлу плейбука.

Для более подробного обзора ключей см. [Ключи командной строки для `ansible-playbook`](ansible_playbook_cli_options.md).

## 2. Анализ вывода выполнения

При запуске плейбука Ansible предоставляет подробный вывод, который можно разбить на несколько частей:

### PLAY
```
PLAY [Install and start nginx] ********************************************
```
*   `PLAY`: Обозначает начало выполнения "плея" (play) или, как его можно перевести, "проигрыша".
*   `[Install and start nginx]`: Это имя (`name`), которое вы задали для данного плея в плейбуке.

### TASK
```
TASK [Gathering Facts] ******************************************************
ok: [ws01]

TASK [install nginx] *******************************************************
changed: [ws01]

TASK [config nginx] ********************************************************
ok: [ws01]
```
*   **`TASK [Gathering Facts]`**: Первая задача по умолчанию. Ansible собирает информацию (факты) о целевой системе.
*   **`TASK [install nginx]`**: Выполнение задачи с именем `install nginx`.
    *   `changed`: Означает, что задача внесла изменения в систему (например, установила пакет, которого не было).
    *   `ok`: Означает, что система уже находилась в нужном состоянии, и никаких изменений не потребовалось.
*   Длительность выполнения задачи может сильно варьироваться. Установка пакетов обычно занимает больше времени, чем изменение конфигурационных файлов.

### PLAY RECAP
```
PLAY RECAP *****************************************************************
ws01                       : ok=5    changed=4    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
ws02                       : ok=5    changed=4    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
ws03                       : ok=5    changed=4    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
```
*   `PLAY RECAP`: Итоговая сводка по всем хостам, на которых выполнялся плейбук.
*   `ok`: Количество задач, которые успешно завершились без внесения изменений.
*   `changed`: Количество задач, которые внесли изменения.
*   `unreachable`: Количество хостов, до которых не удалось достучаться.
*   `failed`: Количество задач, которые завершились с ошибкой. **Если `failed > 0`, это означает, что плейбук не был выполнен успешно.**

## 3. Структура плейбука с несколькими "плеями"

Плейбук может состоять из нескольких "плеев", каждый из которых нацелен на свою группу хостов.

**Пример `playbook.yml`:**
```yaml
---
- name: Install and Start Nginx
  hosts: front
  remote_user: bond
  become: yes
  tasks:
    # ... задачи для Nginx ...

- name: Install and Start Apache
  hosts: back-end
  remote_user: bond
  become: yes
  tasks:
    # ... задачи для Apache ...
```
*   **`hosts: front`**: Эта директива указывает Ansible, что данный плей должен выполняться на хостах, входящих в группу `front` в файле инвентаризации.
*   **`remote_user: bond`**: Указывает пользователя для SSH-подключения, заменяя ключ `-u` в командной строке.
*   **`become: yes`**: Говорит Ansible, что для выполнения задач на целевом сервере нужно получить права `root` (аналог `sudo`).

## 4. Группы в инвентаре

Инвентарь может содержать не только список хостов, но и группы, которые объединяют хосты по логическому признаку.

**Пример `inventory.ini`:**
```ini
[red00]
ws01 ansible_host=192.168.1.101
ws02 ansible_host=192.168.1.102
ws03 ansible_host=192.168.1.103

[front]
ws01

[back-end]
ws02
ws03
```
*   При указании `hosts: front` в плейбуке, Ansible автоматически найдет эту группу в инвентаре и выполнит плей на всех хостах, входящих в нее (в данном случае, только на `ws01`).
*   Аналогично, `hosts: back-end` заставит Ansible выполнить плей на хостах `ws02` и `ws03`.
