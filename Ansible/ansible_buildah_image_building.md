# Сборка образов контейнеров с помощью Buildah и Ansible-bender

## Определения

- **Buildah**: Инструмент для создания OCI-совместимых образов контейнеров без необходимости в Docker-демоне. Позволяет собирать образы с помощью shell-скриптов или `Dockerfile`.
- **Ansible-bender**: Утилита-мост между высокоуровневой структурой Ansible и низкоуровневыми командами Buildah. Позволяет описывать сборку образа с помощью [плейбуков Ansible](ansible_playbook_structure.md).

## Основные концепции

В то время как Buildah предоставляет гибкость, он является низкоуровневым инструментом, и написание сложных сборочных скриптов на `bash` может быть громоздким. `ansible-bender` решает эту проблему, позволяя использовать всю мощь Ansible — роли, модули, переменные и шаблоны — для описания процесса сборки.

**Преимущества подхода:**

- **Унификация**: Весь пайплайн, от конфигурации серверов до сборки образов, описывается в Ansible.
- **Переиспользование кода**: Существующие роли и таски могут быть использованы для сборки образов.
- **Структура и читаемость**: Сборочный процесс описывается в декларативном стиле, свойственном Ansible.

**Пример скрипта на чистом Buildah:**

```bash
#!/usr/bin/env bash
set -x
# Создаем рабочий контейнер
ctrl=$(buildah from fedora)
# Выполняем команды и настраиваем
buildah run "$ctrl" -- dnf update -y && dnf install -y lighttpd
buildah config --cmd "/usr/sbin/lighttpd -D -f /etc/lighttpd/lighttpd.conf" "$ctrl"
buildah config --port 80 "$ctrl"
# Коммитим финальный образ
buildah commit "$ctrl" my-lighttpd-image
```

## Практические сценарии

### 1. Установка

Для работы требуется Python > 3.6, а также утилиты `buildah` и `podman`.

1. **Установите `ansible-bender`:**

    ```bash
    sudo pip3 install ansible-bender
    ```

2. **Установите `buildah` и `podman`:**

    ```bash
    sudo yum -y install buildah podman
    ```

### 2. Пример плейбука для сборки

Плейбук для `ansible-bender` выглядит как обычный плейбук, но переменные для сборки объявляются внутри словаря `ansible_bender`.

```yaml
# playbook.yml
- name: Демонстрация функциональности ansible-bender
  hosts: localhost
  vars:
    # Все переменные для сборки помещаются в словарь ansible_bender
    ansible_bender:
      # Базовый образ, на основе которого будет идти сборка
      base_image: python:3-alpine
      
      # Имя финального образа
      target_image:
        name: my-nice-app
        
      # Настройки рабочего контейнера, в котором будет идти сборка
      working_container:
        # Монтируем директорию с плейбуком в /src внутри контейнера
        volumes:
          - '{{ playbook_dir }}:/src'
          
      # Рабочая директория для запуска команд внутри контейнера
      working_dir: /src
      
      # Метаданные (лейблы) для финального образа
      labels:
        built-by: 'ansible-bender'
        
      # Переменные окружения для финального образа
      environment:
        FILE_TO_PROCESS: README.md
        
  # Задачи, которые будут выполнены внутри контейнера в процессе сборки
  tasks:
    - name: Показать содержимое рабочей директории
      command: 'ls -lha /src'

    - name: Проверить наличие файла
      stat:
        # Используем переменную окружения, определенную выше
        path: "{{ lookup('env','FILE_TO_PROCESS') }}"
      # Здесь можно выполнять любые задачи: устанавливать пакеты, копировать файлы, вызывать роли и т.д.
```

### 3. Процесс сборки и управление

- **Запуск сборки:**

    ```bash
    ansible-bender build playbook.yml
    ```

    Вывод команды будет аналогичен стандартному выводу `ansible-playbook`.

- **Управление сборками:**

    ```bash
    # Просмотр списка сборок
    ansible-bender list-builds
    
    # Получение логов конкретной сборки
    ansible-bender get-logs <BUILD_ID>
    ```

## Дополнительная информация

**Когда использовать этот подход?**
Если ваша инфраструктура уже построена на `Dockerfile`, переход может не иметь смысла. Этот подход наиболее полезен, если вы хотите унифицировать весь пайплайн на Ansible или если сложность сборки выходит за рамки возможностей `Dockerfile`.

**Возможные проблемы:**
На CentOS 7 Ansible из стандартных репозиториев может быть установлен под Python 2, с которым `ansible-bender` не работает. В этом случае установите Ansible через `pip3`.
