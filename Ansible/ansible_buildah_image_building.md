# Сборка образов контейнеров с помощью Buildah и Ansible-bender

## Определения

В то время как `Dockerfile` является стандартным способом для определения и сборки образов контейнеров, существуют и альтернативные подходы. Использование Ansible для описания процесса сборки позволяет унифицировать все процессы в рамках единого инструмента управления конфигурацией. Этот документ описывает использование связки **Buildah** и **Ansible-bender** для сборки образов без `Dockerfile`.

*   **Buildah**: Инструмент, который позволяет создавать OCI-совместимые образы контейнеров, не требуя для этого запуска Docker-демона. Его основное преимущество в том, что он позволяет собирать образы с помощью обычных shell-скриптов.
*   **Ansible-bender**: Утилита, которая служит мостом между высокоуровневой структурой Ansible и низкоуровневыми возможностями Buildah. Она позволяет писать обычные [плейбуки Ansible](ansible_playbook_structure.md) для описания процесса сборки образа, а `ansible-bender` берет на себя всю работу по взаимодействию с Buildah.

## 1. Что такое Buildah?

**Пример скрипта для сборки с Buildah:**
```bash
#!/usr/bin/env bash
set -x

# 1. Создаем рабочий контейнер на основе базового образа
ctrl=$(buildah from "${1:-fedora}")

# 2. Выполняем команды внутри контейнера
buildah run "$ctrl" -- dnf update -y
buildah run "$ctrl" -- dnf install -y lighttpd

# 3. Настраиваем конфигурацию образа
buildah config --annotation "com.example.build.host=$(uname -n)" "$ctrl"
buildah config --cmd "/usr/sbin/lighttpd -D -f /etc/lighttpd/lighttpd.conf" "$ctrl"
buildah config --port 80 "$ctrl"

# 4. "Запекаем" (коммитим) рабочий контейнер в финальный образ
buildah commit "$ctrl" "${2:-$USER/lighttpd}"
```

**Проблема с Buildah:**
Как видно из примера, Buildah является довольно низкоуровневым инструментом. Написание сложных сборочных скриптов на `bash` может быть громоздким и сложным в поддержке.

## 2. Ansible-bender: Ansible + Buildah

**Ansible-bender** — это утилита, которая служит мостом между высокоуровневой структурой Ansible и низкоуровневыми возможностями Buildah. Она позволяет вам писать обычные [плейбуки Ansible](ansible_playbook_structure.md) для описания процесса сборки образа, а `ansible-bender` берет на себя всю работу по взаимодействию с Buildah.

**Преимущества:**
*   **Унификация:** Весь пайплайн, от конфигурации серверов до сборки образов, описывается с помощью Ansible.
*   **Переиспользование кода:** Вы можете использовать существующие роли, модули и переменные для сборки образов.
*   **Структура и отладка:** Вы получаете все преимущества Ansible: четкую структуру, систему отладки, управление переменными.

> **Когда это использовать?**
> Если ваша инфраструктура уже построена на `Dockerfile`, переход может не иметь смысла. Этот подход наиболее полезен, если вы хотите унифицировать весь пайплайн на Ansible или если сложность сборки выходит за рамки возможностей `Dockerfile`.

## 3. Установка

Для работы `ansible-bender` требуется Python > 3.6.

1.  **Установите `ansible-bender`:**
    ```bash
    sudo pip3 install ansible-bender
    ```
2.  **Установите `buildah`:**
    ```bash
    sudo yum -y install buildah
    ```
3.  **Установите `podman`:**
    `podman` используется для управления собранными образами (хранение, просмотр).
    ```bash
    sudo yum -y install podman
    ```
> **Возможные проблемы:** На CentOS 7 Ansible из стандартных репозиториев может быть установлен под Python 2, с которым `bender` не работает. В этом случае установите Ansible через `pip3`.

## 4. Пример плейбука для `ansible-bender`

Плейбук для сборки образа выглядит как обычный плейбук Ansible, но с некоторыми особенностями.

```yaml
# playbook.yml
- name: Demonstration of ansible-bender functionality
  hosts: localhost
  vars:
    # Все переменные для сборки помещаются в словарь ansible_bender
    ansible_bender:
      # Базовый образ, на основе которого будет идти сборка
      base_image: python:3-alpine
      
      # Имя финального образа
      target_image:
        name: a-very-nice-image
        
      # Настройки рабочего контейнера, в котором будет идти сборка
      working_container:
        # Монтируем директорию с плейбуком в /src внутри контейнера
        volumes:
          - '{{ playbook_dir }}:/src'
          
      # Рабочая директория для запуска команд внутри контейнера
      working_dir: /src
      
      # Метаданные (лейблы) для финального образа
      labels:
        built-by: 'root'
        
      # Переменные окружения для финального образа
      environment:
        FILE_TO_PROCESS: README.md
        
  # Задачи, которые будут выполнены ВНУТРИ контейнера в процессе сборки
  tasks:
    - name: Run a sample command
      command: 'ls -lha /src'

    - name: Stat a file
      stat:
        # Используем переменную окружения, определенную выше
        path: "{{ lookup('env','FILE_TO_PROCESS') }}"
      # Здесь можно выполнять любые задачи: устанавливать пакеты, копировать файлы, вызывать роли и т.д.
```

## 5. Процесс сборки и управление

### Сборка образа
Для запуска сборки используется команда `ansible-bender build`.

```bash
ansible-bender build playbook.yml
```
Вывод будет очень похож на стандартный вывод `ansible-playbook`.

### Управление сборками

`ansible-bender` предоставляет команды для управления сборками:

*   **Просмотр списка сборок:**
    ```bash
    ansible-bender list-builds
    ```
*   **Получение логов конкретной сборки:**
    ```bash
    ansible-bender get-logs <BUILD_ID>
    ```
