# Ansible: Модули синхронизации файлов

## Определения

**Модули синхронизации файлов** — это инструменты Ansible для эффективной передачи больших объемов данных и синхронизации директорий между хостами. Основным инструментом является модуль `ansible.posix.synchronize`, который представляет собой оптимизированную обертку над системной утилитой `rsync`.

## Основные концепции

### Модуль `ansible.posix.synchronize`

В отличие от модуля `ansible.builtin.copy`, который передает файлы целиком через канал Ansible, `synchronize` использует алгоритм `rsync`, передающий только измененные части файлов. Это значительно снижает нагрузку на сеть и ускоряет деплой.

**Ключевые особенности:**
- **Эффективность**: Использование дельта-алгоритмов `rsync` для минимизации трафика.
- **Идемпотентность**: Модуль автоматически сверяет метаданные и содержимое, выполняя действия только при наличии расхождений.
- **Транспорт**: По умолчанию `synchronize` инициирует собственное SSH-соединение от имени пользователя, запустившего Ansible (обычно локального пользователя).
- **Требования**: Утилита `rsync` должна быть установлена как на контрольном узле (localhost), так и на целевых хостах.

### Важные параметры

- **`mode`**: Направление синхронизации.
  - `push` (по умолчанию): С локальной машины на удаленный хост.
  - `pull`: С удаленного хоста на локальную машину (удобно для сбора бэкапов).
- **`delete`**: Если `yes`, удаляет в целевой директории файлы, которых нет в источнике. Позволяет поддерживать зеркальную копию.
- **`archive`**: (по умолчанию `yes`) Включает флаг `-a` в rsync (рекурсия, сохранение прав, владельцев, ссылок и временных меток).
- **`checksum`**: Если `yes`, rsync будет сравнивать файлы по контрольным суммам, а не по времени модификации и размеру (более точно, но медленнее).
- **`rsync_opts`**: Список дополнительных флагов для передачи напрямую в rsync (например, `--exclude`, `--bwlimit`).
- **`use_ssh_args`**: Если `yes`, заставляет модуль использовать SSH-настройки из `ansible.cfg` (включая ProxyJump и SSH-ключи). Критично для работы через Bastion-хосты.

## Практические сценарии

### Синхронизация статического контента (Push)
Создание точной копии локальной директории на сервере с очисткой устаревших файлов.

```yaml
- name: Деплой статики сайта
  ansible.posix.synchronize:
    src: src/dist/
    dest: /var/www/html/
    delete: yes
    recursive: yes
    rsync_opts:
      - "--exclude=.git"
      - "--exclude=node_modules"
```

### Сбор данных с серверов (Pull)
Загрузка логов или бэкапов с группы серверов в локальное хранилище.

```yaml
- name: Сбор логов приложения
  ansible.posix.synchronize:
    mode: pull
    src: /var/log/myapp/
    dest: "./collected_logs/{{ inventory_hostname }}/"
```

### Работа в сложных сетевых окружениях (Vagrant, SSH Jump)
Модуль `synchronize` часто вызывает ошибки аутентификации в Vagrant или при использовании нестандартных SSH-ключей, так как он работает «в обход» основного транспорта Ansible.

**Решение для Vagrant или SSH-тоннелей:**
1. Используйте `use_ssh_args: yes` для наследования настроек подключения.
2. При малых объемах данных отдавайте предпочтение `ansible.builtin.copy` или `ansible.builtin.template`.

```yaml
- name: Синхронизация с использованием SSH-аргументов Ansible
  ansible.posix.synchronize:
    src: files/
    dest: /opt/app/
    use_ssh_args: yes
```
