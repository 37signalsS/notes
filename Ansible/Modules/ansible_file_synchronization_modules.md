# Ansible: Модули синхронизации файлов

## Определения

**Модули синхронизации файлов** — это инструменты Ansible, предназначенные для эффективной передачи больших объемов данных и зеркалирования директорий между узлами. Основным инструментом является модуль `ansible.posix.synchronize`, который представляет собой оптимизированную обертку над системной утилитой **rsync**.

**rsync (Remote Sync)** — протокол и утилита для минимизации сетевого трафика путем передачи только измененных частей файлов (дельта-алгоритм).

**FQCN (Fully Qualified Collection Name)** — полное имя модуля (`ansible.posix.synchronize`). Использование FQCN необходимо для корректного разрешения плагина из коллекции `ansible.posix`.

## Основные концепции

### Механизм работы ansible.posix.synchronize

В отличие от стандартного модуля `ansible.builtin.copy`, который передает файлы через внутренний канал Ansible (обычно SFTP или SCP), `synchronize` инициирует прямое соединение `rsync`.

**Ключевые особенности:**
- **Эффективность**: Использование дельта-копирования для передачи только диффов.
- **Транспорт**: Модуль открывает **отдельное SSH-соединение** от имени пользователя, запустившего Ansible. Это может вызвать проблемы с аутентификацией, если не настроен беспарольный доступ или `use_ssh_args`.
- **Зависимости**: Утилита `rsync` должна быть установлена как на контрольном узле, так и на всех целевых хостах.
- **Делегирование**: По умолчанию `synchronize` работает между контрольным узлом и управляемым хостом. С помощью `delegate_to` можно настроить синхронизацию между двумя удаленными серверами.

### Критически важные параметры

- **`mode`**: Направление синхронизации.
  - `push` (по умолчанию): С локальной машины на удаленный хост.
  - `pull`: С удаленного хоста на локальную машину (удобно для сбора бэкапов).
- **`delete`**: Если `yes`, удаляет в целевой директории файлы, которых нет в источнике. Позволяет поддерживать зеркальную копию.
- **`archive`**: (по умолчанию `yes`) Включает флаг `-a` в rsync (рекурсия, сохранение прав, владельцев, ссылок и временных меток).
- **`checksum`**: Если `yes`, rsync будет сравнивать файлы по контрольным суммам, а не по времени модификации и размеру (более точно, но медленнее).
- **`rsync_opts`**: Список дополнительных флагов для передачи напрямую в rsync (например, `--exclude`, `--bwlimit`).
- **`use_ssh_args`**: Если `yes`, заставляет модуль использовать SSH-настройки из `ansible.cfg` (включая ProxyJump и SSH-ключи). Критично для работы через Bastion-хосты.

## Практические сценарии

### Зеркалирование статического контента (Push)
Передача дистрибутива приложения с очисткой устаревших файлов и исключением служебных директорий.

```yaml
- name: "Синхронизация статики веб-сайта"
  ansible.posix.synchronize:
    src: "dist/"
    dest: "/var/www/html/app/"
    delete: yes
    recursive: yes
    rsync_opts:
      - "--exclude=.git"
      - "--exclude=*.log"
```

### Сбор бэкапов с удаленных хостов (Pull)
Модуль `ansible.builtin.fetch` не умеет скачивать директории целиком. Для этого используется `synchronize` в режиме `pull`.

```yaml
- name: "Выгрузка бэкапов баз данных на контрольный узел"
  ansible.posix.synchronize:
    mode: pull
    src: "/var/backups/db/"
    dest: "./storage/backups/{{ inventory_hostname }}/"
```

### Синхронизация через Bastion-хост
Использование настроек транспорта Ansible для работы в изолированных сетях.

```yaml
- name: "Передача файлов через SSH Jump"
  ansible.posix.synchronize:
    src: "configs/"
    dest: "/etc/myapp/"
    use_ssh_args: yes
```

### Синхронизация между двумя удаленными серверами
Копирование данных напрямую с `db_master` на `db_slave`.

```yaml
- name: "Копирование данных между серверами"
  ansible.posix.synchronize:
    src: "/data/db_dump/"
    dest: "/data/db_dump/"
  delegate_to: "db_master"
```
*Примечание: В этом сценарии `db_master` должен иметь SSH-доступ к `db_slave`.*
