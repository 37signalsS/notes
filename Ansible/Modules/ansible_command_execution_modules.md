# Ansible: Модули выполнения команд

## Определения

**Модули выполнения команд** — это группа инструментов Ansible (`command`, `shell`, `raw`, `script`, `expect`), предназначенных для запуска произвольных команд и скриптов на управляемых хостах. В отличие от декларативных модулей (например, `ansible.builtin.apt` или `ansible.builtin.service`), они работают императивно и используются как «последнее средство» (last resort), когда специализированный модуль для конкретной задачи отсутствует или не покрывает нужный функционал.

## Основные концепции

### Сравнение модулей

| Модуль | Среда выполнения | Ключевые особенности |
| :--- | :--- | :--- |
| **`ansible.builtin.command`** | Напрямую (exec) | Самый безопасный (не интерпретирует спецсимволы). Не поддерживает конвейеры (`|`), перенаправления (`>`), переменные окружения оболочки. |
| **`ansible.builtin.shell`** | Через `/bin/sh` (по умолчанию) | Поддерживает все возможности оболочки (pipes, redirects, variables). Степень свободы выше, но выше и риск ошибок безопасности. |
| **`ansible.builtin.raw`** | SSH/WinRM напрямую | Выполняет команду «как есть» без использования Python на хосте. Критичен для начальной настройки (bootstrapping). |
| **`ansible.builtin.script`** | Локальный скрипт | Копирует скрипт с контрольного узла на хост и выполняет его одним шагом. |
| **`ansible.builtin.expect`** | Через `pexpect` | Для автоматизации интерактивных диалогов (вопрос-ответ). Требует Python-библиотеку `pexpect` на хосте. |

### Параметры идемпотентности

По умолчанию модули выполнения команд **не являются идемпотентными** и всегда возвращают статус `changed`. Для предотвращения лишних действий используйте следующие параметры:

- **`creates`**: Путь к файлу. Команда выполнится только в том случае, если этот файл **не существует**.
- **`removes`**: Путь к файлу. Команда выполнится только в том случае, если этот файл **существует**.
- **`chdir`**: Смена рабочей директории перед выполнением команды.

### Управление статусом задачи

Для корректного отображения изменений в отчетах и запуска обработчиков (`handlers`) используйте директивы плейбука:

- **`changed_when`**: Условие, при котором задача считается изменившей систему.
  - `changed_when: false` — для команд проверки или чтения данных.
  - `changed_when: "'created' in result.stdout"` — на основе вывода команды.
- **`failed_when`**: Условие, при котором задача считается проваленной (например, если ненулевой код возврата допустим).

## Практические сценарии

### Безопасное использование параметров в shell

При передаче переменных в `ansible.builtin.shell` всегда используйте фильтр `quote` для защиты от инъекций команд.

```yaml
- name: Поиск файла по имени из переменной
  ansible.builtin.shell:
    cmd: "ls -l /var/www/{{ user_input | quote }}"
  register: file_info
  changed_when: false
```

### Начальная настройка системы (Bootstrapping)

Использование `ansible.builtin.raw` для установки Python на «чистые» серверы, где Ansible еще не может работать через стандартные модули.

```yaml
- name: Установка Python на Ubuntu без Python
  ansible.builtin.raw: apt-get update && apt-get install -y python3
  become: true
  changed_when: true
  gather_facts: false # Факты невозможно собрать без Python
```

### Работа с локальными скриптами

Модуль `ansible.builtin.script` автоматически обрабатывает копирование и удаление временного файла скрипта.

```yaml
- name: Выполнение сложной диагностики системы
  ansible.builtin.script:
    cmd: scripts/check_raid_status.py --verbose
    creates: /var/log/raid_health.report
```

### Автоматизация интерактивных команд

Используйте `ansible.builtin.expect` для команд, которые не поддерживают неинтерактивный режим.

```yaml
- name: Инициализация кастомного приложения
  ansible.builtin.expect:
    command: /opt/bin/app-init
    responses:
      (?i)Enter your name: "admin"
      (?i)Continue\? \[y/n\]: "y"
  no_log: true # Рекомендуется для защиты данных ввода
```

## Дополнительная информация

### Безопасность и лучшие практики
- **FQCN**: Всегда используйте полное имя модуля (например, `ansible.builtin.command`).
- **Синтаксис**: Предпочитайте современный YAML-синтаксис с использованием ключа `cmd` вместо «свободной формы» (free-form).
- **Специализированные модули**: Перед использованием `shell` проверьте, нет ли нативного модуля. Список основных модулей см. в [Обзор часто используемых модулей](ansible_modules_overview.md).
- **Валидация**: Используйте `executable` в модуле `shell`, если требуется специфическая оболочка (например, `/bin/bash`).
