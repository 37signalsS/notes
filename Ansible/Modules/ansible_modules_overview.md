# Ansible: Обзор модулей

## Определения

**Модули Ansible** — это автономные единицы кода (плагины), которые выполняют конкретные задачи на управляемых хостах. В отличие от плагинов, которые работают непосредственно на контрольном узле, модули копируются на целевой хост, выполняются там и возвращают результат в формате JSON.

**Идемпотентность** — фундаментальное свойство модуля, гарантирующее, что повторное выполнение задачи не приведет к изменениям в системе, если она уже находится в желаемом состоянии. Большинство нативных модулей Ansible идемпотентны по умолчанию.

**FQCN (Fully Qualified Collection Name)** — полное имя модуля, включающее пространство имен и коллекцию (например, `ansible.builtin.copy`). Начиная с версии 2.10, использование FQCN является обязательным стандартом для предотвращения конфликтов имен между модулями из разных коллекций.

**ansible-core** — базовый пакет, содержащий движок Ansible и минимальный набор «встроенных» модулей (`ansible.builtin`). Остальные модули поставляются через **Коллекции** (Collections).

### Требования к окружению
Начиная с **Ansible 2.17**, поддержка Python 2.7 и 3.6 на управляемых узлах прекращена. Для работы модулей требуется **Python 3.7+**.

## Основные концепции

### Жизненный цикл выполнения модуля
1.  **Подготовка**: Ansible упаковывает код модуля и его зависимости (`module_utils`) в zip-архив.
2.  **Передача**: Архив копируется на управляемый узел (обычно в `/tmp`).
3.  **Исполнение**: Код распаковывается и запускается в интерпретаторе Python целевого узла.
4.  **Ответ**: Модуль выводит JSON-структуру в `stdout`.
5.  **Очистка**: Временные файлы удаляются (если не установлена переменная окружения `ANSIBLE_KEEP_REMOTE_FILES=1`).

### Желаемое состояние (параметр state)
Большинство декларативных модулей используют параметр `state` для описания целевого состояния:
- `present` / `installed`: Ресурс должен существовать.
- `absent` / `removed`: Ресурс должен быть удален.
- `latest`: Установка или обновление до последней доступной версии.
- `started` / `stopped`: Управление состоянием демонов.
- `merged` / `replaced` / `overridden`: Специфичные состояния для сетевых и инфраструктурных модулей.

### Общие параметры задач
Помимо параметров самого модуля, существуют директивы уровня задачи, влияющие на выполнение:
- `become`: Повышение привилегий (sudo/doas).
- `no_log`: Скрытие чувствительных данных (пароли, ключи) из вывода и логов.
- `ignore_errors`: Продолжение выполнения плейбука при ошибке конкретного модуля.
- `check_mode`: Возможность запретить выполнение модуля в режиме dry-run (`check_mode: false`).

### Безопасность и защищенные условия (Hardened Conditionals)
В современных версиях Ansible (в рамках исправления CVE-2023-5764) переменные из внешних источников (включая результаты модулей) помечаются как «небезопасные».
- **Запрещено**: Использовать вставки Jinja2 внутри `when` (например, `when: "{{ result.changed }}"`).
- **Рекомендуется**: Обращаться к переменным напрямую: `when: result.changed`.

## Практические сценарии

### Комплексный сценарий: Установка, проверка и обработка результата
Пример использования модуля с регистрацией состояния и кастомными критериями успеха.

```yaml
- name: "Установка и проверка веб-сервера"
  ansible.builtin.dnf:
    name: nginx
    state: latest
  become: true
  register: nginx_install
  failed_when: 
    - nginx_install.rc != 0
    - "'package not found' in nginx_install.msg"

- name: "Анализ изменений"
  ansible.builtin.debug:
    msg: "Nginx был обновлен до последней версии"
  when: nginx_install.changed
```

### Режимы диагностики
Запуск модулей в безопасном режиме для анализа планируемых изменений:
```bash
# Проверка изменений без их применения (dry-run)
ansible-playbook site.yml --check

# Проверка с выводом детальной разницы в конфигах
ansible-playbook site.yml --check --diff
```

### Работа с документацией (ansible-doc)
Утилита `ansible-doc` позволяет получать справку без доступа к интернету.

```bash
# Просмотр полной справки и примеров
ansible-doc ansible.builtin.copy

# Вывод краткого шаблона (snippet) для вставки в плейбук
ansible-doc -s ansible.builtin.file

# Список всех установленных коллекций и их модулей
ansible-galaxy collection list
```
