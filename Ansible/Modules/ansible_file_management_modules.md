# Ansible: Модули управления файлами

## Определения

**Модули управления файлами** — это группа специализированных инструментов Ansible (`ansible.builtin`), предназначенных для манипуляций с файловой системой на управляемых хостах. Они позволяют декларативно описывать состояние файлов, директорий и их содержимого, обеспечивая идемпотентность и безопасность операций.

**Атомарность (Atomic Move)** — механизм, используемый большинством файловых модулей (`copy`, `template`, `lineinfile` и др.). Вместо прямого редактирования файла Ansible создает временную копию (обычно в той же директории), вносит изменения в неё, проверяет успешность записи и затем заменяет оригинал системным вызовом `rename`. Это гарантирует, что при сбое в процессе записи файл не останется поврежденным.

**FQCN (Fully Qualified Collection Name)** — полное имя модуля (например, `ansible.builtin.template`). Использование FQCN является обязательным стандартом для предотвращения конфликтов имен и обеспечения предсказуемости выполнения.

## Основные концепции

### Группы модулей по назначению

1.  **Управление структурой и атрибутами:**
    *   `ansible.builtin.file`: Создание директорий, симлинков, управление правами, владельцами и удаление (`state: absent`).
    *   `ansible.builtin.stat`: Сбор фактов о файле (существование, контрольные суммы, права). Используется для принятия решений в последующих задачах через `register`.
    *   `ansible.builtin.find`: Рекурсивный поиск файлов по шаблонам, дате или размеру.
    *   `ansible.builtin.tempfile`: Создание гарантированно уникальных временных файлов или директорий на управляемом хосте.
2.  **Перенос и получение данных:**
    *   `ansible.builtin.copy`: Копирование с контрольного узла или внутри удаленного хоста (`remote_src: yes`).
    *   `ansible.builtin.template`: Генерация файлов из шаблонов [Jinja2](../ansible_jinja_templating.md). Обрабатывается на контрольном узле.
    *   `ansible.builtin.fetch`: Копирование файлов с хостов на контрольный узел. **Ограничение**: Работает только с файлами; для выгрузки директорий используйте `ansible.posix.synchronize` в режиме `pull`.
    *   `ansible.builtin.get_url`: Загрузка файлов по HTTP/HTTPS/FTP напрямую на управляемый хост.
    *   `ansible.builtin.unarchive`: Распаковка архивов. Требует наличия `tar`, `unzip` или `xz` на целевом хосте в зависимости от формата.
3.  **Редактирование содержимого:**
    *   `ansible.builtin.lineinfile`: Управление отдельными строками (добавление, замена, удаление).
    *   `ansible.builtin.blockinfile`: Вставка многострочных блоков текста, защищенных маркерами.
    *   `ansible.builtin.replace`: Массовая замена текста по регулярным выражениям.
    *   `ansible.builtin.assemble`: Сборка (конкатенация) одного файла из нескольких фрагментов, находящихся в директории.

### Критически важные параметры

-   **`validate`**: Выполнение команды проверки синтаксиса перед финальной заменой файла (например, `validate: '/usr/sbin/visudo -cf %s'`). Символ `%s` заменяется на путь к временному файлу.
-   **`remote_src`**: Определяет местоположение источника. Если `yes`, `src` ищется на управляемом хосте.
-   **`unsafe_writes`**: Позволяет Ansible изменять файлы, когда атомарная перезапись невозможна (например, при монтировании файлов напрямую в Docker-контейнеры через `bind mount` или на сетевых FS без поддержки `rename`).
-   **`backup`**: Создает резервную копию файла с временной меткой в той же директории перед внесением изменений.

### Права доступа, атрибуты и SELinux

Файловые модули поддерживают расширенное управление атрибутами:
- **`owner` / `group`**: Установка владельца и группы.
- **`mode`**: Права доступа. Рекомендуется использовать восьмеричный формат в кавычках (`'0644'`).
- **`attributes`**: Флаги файловой системы Linux (например, `i` — запрет на изменение (immutable), `a` — только для дозаписи). Требует поддержки файловой системой (ext4, xfs).
- **SELinux**: Параметры `setype`, `seuser`, `serole`, `selevel` для управления контекстом безопасности. Если SELinux включен, Ansible пытается сохранить контекст при атомарном перемещении.

## Практические сценарии

### Создание директорий и рекурсивное управление правами
Использование `recurse: yes` позволяет применить права ко всем вложенным объектам (только при `state: directory`).

```yaml
- name: "Настройка директории для хранения данных"
  ansible.builtin.file:
    path: /var/lib/myapp
    state: directory
    owner: myuser
    group: mygroup
    mode: '0750'
    recurse: yes
```

### Безопасное обновление конфигурации Sudoers
Модуль `template` с валидацией предотвращает блокировку доступа к системе из-за синтаксических ошибок.

```yaml
- name: "Настройка прав sudo для разработчиков"
  ansible.builtin.template:
    src: sudoers_developers.j2
    dest: /etc/sudoers.d/developers
    owner: root
    group: root
    mode: '0440'
    validate: '/usr/sbin/visudo -cf %s'
```

### Распаковка артефактов из S3/HTTP
Если архив загружается через `get_url`, используйте `remote_src: yes` в `unarchive`.

```yaml
- name: "Развертывание приложения из архива"
  ansible.builtin.unarchive:
    src: /tmp/app_v1.tar.gz
    dest: /opt/app
    remote_src: yes
    creates: /opt/app/bin/start.sh # Пропустить, если файл уже существует
```

### Редактирование системных конфигураций (`lineinfile`)
Эффективно для изменения конкретных параметров без замены всего файла.

```yaml
- name: "Включение пересылки трафика IPv4"
  ansible.builtin.lineinfile:
    path: /etc/sysctl.conf
    regexp: '^net.ipv4.ip_forward'
    line: 'net.ipv4.ip_forward=1'
    state: present
    backup: yes
```

### Сбор логов с проверкой размера
Сначала ищем файлы по критериям, затем выгружаем их на контрольный узел.

```yaml
- name: "Поиск тяжелых логов"
  ansible.builtin.find:
    paths: /var/log/myapp
    size: 10M
    age: 1d
  register: log_files

- name: "Выгрузка найденных логов на контрольный узел"
  ansible.builtin.fetch:
    src: "{{ item.path }}"
    dest: "./backup_logs/{{ inventory_hostname }}/"
    flat: yes
  loop: "{{ log_files.files }}"
```
