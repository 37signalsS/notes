# Ansible: Модули управления пакетами

## Определения

**Модули управления пакетами** — это группа специализированных инструментов Ansible (`ansible.builtin`), предназначенных для автоматизации жизненного цикла программного обеспечения на управляемых хостах. Они абстрагируют команды системных пакетных менеджеров, обеспечивая декларативный способ установки, обновления и удаления ПО.

**Абстракция менеджера** — возможность использовать универсальный модуль `ansible.builtin.package`, который автоматически определяет тип ОС и вызывает соответствующий нативный модуль (`apt`, `dnf`, `zypper` и др.).

**FQCN (Fully Qualified Collection Name)** — обязательный стандарт именования модулей (например, `ansible.builtin.apt`), предотвращающий конфликты с модулями из сторонних коллекций.

## Основные концепции

### Типы модулей по назначению

1.  **Системные (Нативные)**:
    *   `ansible.builtin.apt`: Для Debian, Ubuntu и производных.
    *   `ansible.builtin.dnf`: Для RHEL 8+, Fedora, AlmaLinux. Поддерживает **DNF5** в последних версиях Ansible (2.17+).
    *   `ansible.builtin.yum`: Для RHEL 7 и старых систем на базе RPM.
    *   `ansible.builtin.zypper`: Для SUSE/openSUSE.
    *   `community.general.pacman`: Для Arch Linux.
2.  **Контейнеризированные и универсальные**:
    *   `community.general.snap`: Управление пакетами Snap (Ubuntu, CentOS).
    *   `community.general.flatpak`: Управление пакетами Flatpak.
3.  **Языковые и прикладные**:
    *   `ansible.builtin.pip`: Пакеты Python. В современных ОС (Ubuntu 24.04+) требует использования виртуальных окружений из-за **PEP 668**.
    *   `community.general.npm`: Пакеты Node.js.
    *   `community.general.gem`: Пакеты Ruby.
4.  **Управление источниками**:
    *   `ansible.builtin.deb822_repository`: Современный формат репозиториев для Debian/Ubuntu.
    *   `ansible.builtin.apt_repository` / `ansible.builtin.yum_repository`: Традиционные способы добавления репозиториев.
    *   `ansible.builtin.rpm_key`: Управление GPG-ключами для RPM-систем.

### Идемпотентность и параметры состояния (state)

Все модули пакетов следуют принципу идемпотентности через параметр `state`:
- `present` (по умолчанию): Пакет должен быть установлен. Если он уже есть, действия не предпринимаются.
- `installed`: Синоним `present`, считается устаревшим в некоторых контекстах, но поддерживается.
- `latest`: Установка или обновление до самой свежей версии в репозитории. **Внимание**: Может нарушить стабильность системы, если версия обновится неожиданно.
- `absent`: Пакет должен быть удален.
- `fixed`: В некоторых модулях позволяет зафиксировать версию (pinning).

**Важные флаги:**
- `update_cache`: (обычно `yes/no`) Обновление индексов репозиториев перед выполнением задачи.
- `allow_downgrade`: Разрешает установку более старой версии, чем текущая (только для нативных модулей).
- `autoremove`: Удаление неиспользуемых зависимостей.

## Практические сценарии

### Оптимизированная установка в Debian/Ubuntu
Использование `cache_valid_time` предотвращает лишние обращения к сети.

```yaml
- name: "Установка базового ПО с оптимизацией кэша"
  ansible.builtin.apt:
    name:
      - curl
      - git
      - htop
    state: present
    update_cache: yes
    cache_valid_time: 86400 # Обновлять не чаще раза в сутки
    autoremove: yes
    purge: yes # Удалять конфигурационные файлы при удалении пакета
```

### Установка в современных RPM-системах (DNF/DNF5)
Поддержка специфических функций, таких как установка групп пакетов.

```yaml
- name: "Установка группы инструментов разработки через DNF"
  ansible.builtin.dnf:
    name: "@Development Tools"
    state: present
    update_only: no # Разрешить установку, а не только обновление
    disable_gpg_check: no
```

### Управление Python-пакетами (PEP 668)
В новых дистрибутивах (Ubuntu 24.04+) прямая установка в системный Python запрещена.

```yaml
- name: "Установка приложения в изолированное окружение"
  ansible.builtin.pip:
    name: "flask>=3.0.0"
    state: present
    virtualenv: /opt/web_app/venv
    virtualenv_command: python3 -m venv
```

### Использование package_facts для аудита
Сбор данных о ПО для последующих проверок безопасности.

```yaml
- name: "Анализ установленного ПО"
  ansible.builtin.package_facts:
    manager: auto

- name: "Прерывание, если установлена уязвимая версия"
  ansible.builtin.assert:
    that:
      - "ansible_facts.packages['openssl'][0].version is version('3.0.0', '>=')"
    fail_msg: "Обнаружена критическая уязвимость в OpenSSL!"
  when: "'openssl' in ansible_facts.packages"
```

### Работа с универсальными пакетами Snap
Пример установки инструментов с указанием канала.

```yaml
- name: "Установка классического Snap-пакета"
  community.general.snap:
    name: go
    channel: 1.22/stable
    classic: yes
```
