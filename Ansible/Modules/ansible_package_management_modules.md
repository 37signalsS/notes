# Ansible: Модули управления пакетами

## Определения

**Модули управления пакетами** — это инструменты Ansible для установки, обновления и удаления программного обеспечения на управляемых хостах. Они абстрагируют работу системных пакетных менеджеров (APT, YUM, DNF, APK и др.), обеспечивая декларативный способ управления составом ПО.

## Основные концепции

### Типы модулей

1. **Универсальные (`package`)**: Пытаются автоматически определить системный менеджер пакетов. Удобны для кроссплатформенных задач, но поддерживают только базовые параметры (`name`, `state`).
2. **Нативные (`apt`, `yum`, `dnf`)**: Специфичны для конкретных ОС. Предоставляют полный контроль над возможностями менеджера (управление кэшем, репозиториями, исключениями).
3. **Языковые (`pip`, `npm`, `gem`)**: Управляют библиотеками и пакетами внутри конкретных экосистем программирования.
4. **Управление репозиториями (`apt_repository`, `yum_repository`)**: Позволяют добавлять сторонние источники ПО и GPG-ключи.

### Идемпотентность

Модули управления пакетами идемпотентны: если пакет уже находится в целевом состоянии, повторный запуск задачи не внесет изменений. Однако степень идемпотентности зависит от значения `state`:

* `state: present` — гарантирует наличие пакета, но **не обновляет** уже установленный. Полная идемпотентность.
* `state: latest` — при каждом запуске проверяет наличие более новой версии и обновляет, если доступна. Идемпотентен по факту (повторный запуск при актуальной версии — `ok`), но снижает предсказуемость: между запусками плейбука версия пакета может измениться.
* `state: absent` — гарантирует отсутствие пакета.

### Выбор состояния: present vs latest

Для пакетов, где конкретная версия не важна (системные зависимости, утилиты) — используйте `state: present`.

**Почему `present`, а не `latest`?**

* **Предсказуемость:** `present` не обновляет пакет, если он уже установлен. Плейбук не вносит незапланированных изменений.
* **Стабильность:** `latest` при каждом запуске может обновить пакет до новой версии, что способно привести к неожиданным изменениям в поведении системы.
* **Производительность:** `present` не тратит время на проверку репозитория на наличие новых версий.

**Когда использовать `latest`:**

* Установка конкретной версии через параметр `version:` (но это требует явного указания версии).
* Сценарии обновления системы, где цель — всегда иметь последнюю версию (например, агенты мониторинга).
* Временные/тестовые окружения.

**Рекомендация:** `present` — безопасный выбор по умолчанию. `latest` применяйте осознанно, когда это действительно нужно.

**Для production:** если требуется воспроизводимость (исключить сюрпризы при обновлении репозитория) — фиксируйте точную версию пакета. Это самый детерминированный подход:

```yaml
- name: Установка Docker с фиксацией версии
  ansible.builtin.apt:
    name:
      - docker-ce=5:28.3.3-1~ubuntu.24.04~noble
      - docker-ce-cli=5:28.3.3-1~ubuntu.24.04~noble
    state: present
```

```yaml
- name: Установка системных зависимостей (версия не важна)
  ansible.builtin.apt:
    name:
      - apt-transport-https
      - ca-certificates
      - curl
      - gnupg
      - lsb-release
    state: present # Не `latest` — версии не важны
```

См. также [bad practice: избыточное обновление пакетов](../ansible_bad_practices.md).

### Сравнение универсального и нативных модулей

| Характеристика | `package` (универсальный) | `apt` / `yum` / `dnf` (нативные) |
| :--- | :--- | :--- |
| **Простота** | Высокая (один модуль для всех ОС) | Средняя (нужна условная логика) |
| **Функциональность** | Базовая | Полная (кэш, репозитории, версии) |
| **Надежность** | Средняя | Высокая (предсказуемое поведение) |
| **Рекомендация** | Простые задачи, быстрые прототипы | Production-окружения, сложные роли |

## Практические сценарии

### Системные пакеты (Debian/Ubuntu)

Использование `apt` с обновлением кэша.

```yaml
- name: Установка Nginx с обновлением кэша
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: yes
    cache_valid_time: 3600 # Обновлять кэш, только если он старше 1 часа
```

### Системные пакеты (RHEL/CentOS/Fedora)

Для современных систем (RHEL 8+, Fedora) рекомендуется использовать `dnf`, для старых — `yum`.

```yaml
- name: Установка Apache через DNF
  ansible.builtin.dnf:
    name: httpd
    state: present
```

### Управление репозиториями

Добавление стороннего источника (на примере Docker для Ubuntu). Современный способ с использованием формата **DEB 822** (рекомендуется вместо устаревшего `apt_repository`):

```yaml
- name: Создание директории для ключей
  ansible.builtin.file:
    path: /etc/apt/keyrings
    state: directory
    mode: '0755'

- name: Скачивание GPG-ключа Docker
  ansible.builtin.get_url:
    url: https://download.docker.com/linux/ubuntu/gpg
    dest: /etc/apt/keyrings/docker.asc
    mode: '0644'

- name: Добавление репозитория Docker (формат DEB 822)
  ansible.builtin.deb822_repository:
    name: docker
    types: deb
    uris: https://download.docker.com/linux/ubuntu
    suites: "{{ ansible_facts['distribution_release'] }}"
    components: stable
    architectures: amd64
    signed_by: /etc/apt/keyrings/docker.asc
    state: present
```

### Языковые пакеты (Python/Node.js)

```yaml
- name: Установка Python-библиотеки в virtualenv
  ansible.builtin.pip:
    name: requests
    virtualenv: /opt/venv

- name: Глобальная установка пакета npm
  community.general.npm:
    name: pm2
    global: yes
```

### Получение информации об установленных пакетах

```yaml
- name: Сбор фактов об установленных пакетах
  ansible.builtin.package_facts:
    manager: auto

- name: Проверка наличия пакета в фактах
  ansible.builtin.debug:
    msg: "Пакет curl установлен"
  when: "'curl' in ansible_facts.packages"
```
