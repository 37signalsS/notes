# Ansible: Модули управления пакетами

## Определения

**Модули управления пакетами** — это инструменты Ansible для установки, обновления и удаления программного обеспечения на управляемых хостах. Они абстрагируют работу системных пакетных менеджеров (APT, DNF, Yum, APK и др.), обеспечивая декларативный способ управления составом ПО.

## Основные концепции

### Типы модулей по назначению

1.  **Универсальные (`package`)**: Автоматически определяют системный менеджер пакетов. Идеальны для простых кроссплатформенных задач, но поддерживают только общие параметры (`name`, `state`).
2.  **Нативные (`apt`, `dnf`, `yum`, `zypper`)**: Специфичны для конкретных дистрибутивов. Предоставляют полный доступ к функциям менеджера: очистка кэша, работа с репозиториями, фиксация версий (pinning).
3.  **Языковые (`pip`, `npm`, `gem`, `maven`)**: Управляют зависимостями внутри конкретных сред программирования.
4.  **Управление репозиториями (`deb822_repository`, `apt_repository`, `yum_repository`)**: Добавление сторонних источников ПО и управление GPG-ключами.

### Идемпотентность и выбор состояния (state)

Модули управления пакетами стремятся к идемпотентности: если целевое состояние достигнуто, повторный запуск не вносит изменений.

*   `state: present` (рекомендуется): Гарантирует наличие пакета. Если пакет уже установлен, Ansible ничего не делает. Это самый стабильный и предсказуемый вариант для production.
*   `state: latest`: Всегда обновляет пакет до последней доступной версии. Это снижает предсказуемость, так как версия ПО может измениться между запусками плейбука без явного указания в коде.
*   `state: absent`: Гарантирует отсутствие пакета.

**Фиксация версии (Version Pinning):** Для максимальной детерминированности рекомендуется указывать точную версию пакета.
```yaml
- name: Установка Docker конкретной версии
  ansible.builtin.apt:
    name: docker-ce=5:28.3.3-1~ubuntu.24.04~noble
    state: present
```

### Сравнение универсального и нативных модулей

| Характеристика | `package` (универсальный) | `apt` / `dnf` / `yum` (нативные) |
| :--- | :--- | :--- |
| **Кроссплатформенность** | Высокая (один код для всех ОС) | Низкая (требует условий `when`) |
| **Функциональность** | Ограничена (базовые действия) | Полная (кэш, ключи, специфичные опции) |
| **Рекомендация** | Быстрые прототипы, простые утилиты | Сложные роли, production-системы |

## Практические сценарии

### Системные пакеты (Debian/Ubuntu)
Использование `apt` с управлением кэшем для оптимизации времени выполнения.

```yaml
- name: Установка Nginx с обновлением кэша
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: yes
    cache_valid_time: 3600 # Обновлять кэш, только если он старше 1 часа
    autoremove: yes       # Удалить неиспользуемые зависимости
    purge: yes            # Удалить конфиги при удалении (если state: absent)
```

### Системные пакеты (RHEL/CentOS/Fedora)
Для современных систем (RHEL 8+, Fedora) используется `dnf`. Модуль `yum` является оберткой над `dnf` в новых ОС, но сохраняется для совместимости с RHEL 7.

```yaml
- name: Установка Apache через DNF
  ansible.builtin.dnf:
    name: httpd
    state: present
    disable_gpg_check: no
```

### Современное управление репозиториями (DEB 822)
Использование формата DEB 822 является стандартом для новых версий Debian/Ubuntu.

```yaml
- name: Добавление репозитория Docker
  ansible.builtin.deb822_repository:
    name: docker
    types: deb
    uris: https://download.docker.com/linux/ubuntu
    suites: "{{ ansible_facts['distribution_release'] }}"
    components: stable
    signed_by: https://download.docker.com/linux/ubuntu/gpg
    state: present
```

### Языковые пакеты (Python/Pip)
Изоляция зависимостей через виртуальные окружения.

```yaml
- name: Установка библиотек в Virtualenv
  ansible.builtin.pip:
    name: 
      - requests
      - flask
    virtualenv: /opt/my_app/venv
    virtualenv_command: python3 -m venv
```

### Сбор данных об установленном ПО
Использование `package_facts` для проверки состояния системы перед выполнением логики.

```yaml
- name: Сбор фактов о пакетах
  ansible.builtin.package_facts:
    manager: auto

- name: Уведомление, если установлена старая версия
  ansible.builtin.debug:
    msg: "Внимание: обнаружена версия {{ ansible_facts.packages['openssl'][0].version }}"
  when: "'openssl' in ansible_facts.packages"
```
