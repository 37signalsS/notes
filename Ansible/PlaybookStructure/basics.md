# Ansible: структура плейбука

## Определения

**Плейбук (Playbook)** — YAML-файл, содержащий один или несколько «плеев» (`plays`) для описания желаемого состояния системы и шагов по его достижению. Основной инструмент оркестрации в Ansible.

**Плей (Play)** — основной строительный блок плейбука. Сопоставляет группу хостов из инвентаря с набором задач, которые необходимо на них выполнить.

**Задача (Task)** — отдельная атомарная операция (например, установка пакета, копирование файла). Каждая задача вызывает определенный [модуль Ansible](../Modules/ansible_modules_overview.md).

**Обработчик (Handler)** — специальная задача, которая выполняется только один раз в конце плея и только после получения уведомления от другой задачи. Используется для таких действий, как перезапуск сервисов.

## Базовые концепции

### Структура и порядок выполнения

Плей в плейбуке — это словарь YAML, определяющий, **что** и **где** будет выполняться. Современный стандарт требует использования полного имени модулей (**FQCN — Fully Qualified Collection Name**).

```yaml
---
- name: Настройка веб-серверов
  hosts: webservers
  become: true
  gather_facts: true
  
  pre_tasks:
    - name: Проверка доступности порта 80
      ansible.builtin.wait_for:
        port: 80
        state: started
        timeout: 5

  roles:
    - common
    - { role: nginx, nginx_port: 8080 }

  tasks:
    - name: Установка Nginx
      ansible.builtin.apt:
        name: nginx
        state: present
      notify: Перезапуск Nginx

  post_tasks:
    - name: Финальная проверка работоспособности
      ansible.builtin.uri:
        url: http://localhost
        return_content: true

  handlers:
    - name: Перезапуск Nginx
      ansible.builtin.service:
        name: nginx
        state: restarted
```

### Ключевые директивы

* `name`: Описание плея или задачи для логов.
* `hosts`: Целевые хосты или группы (например, `web`, `all`, `build:run`).
* `become: true`: Повышение привилегий (sudo).
* `gather_facts: true/false`: Сбор системных данных (IP, ОС) перед выполнением. Отключение ускоряет работу, если факты не нужны.
* `connection`: Тип подключения (`ssh` — по умолчанию, `local` — выполнение на контрольном узле).
* `vars`: Словарь переменных уровня плея.
* `roles`: Список [ролей](../ansible_roles.md) для включения.

### Иерархия выполнения задач

Ansible строго соблюдает последовательность:
1. **`pre_tasks`**: Задачи до выполнения всех ролей.
2. **`roles`**: Подключенные роли.
3. **`tasks`**: Основные задачи плея.
4. **`post_tasks`**: Задачи после ролей и основных задач.
5. **`handlers`**: Выполняются в самом конце, если были уведомлены через `notify`.

> Переменные из роли доступны только в рамках того плея, где роль подключена. Между плеями контекст изолирован.

### Обработчики и идемпотентность

Обработчики помогают избежать ненужных перезагрузок сервисов, обеспечивая **идемпотентность** (система не меняется, если она уже в целевом состоянии).

1. Задача (например, правка конфига) отправляет `notify`, только если статус — `changed`.
2. В конце плея Ansible выполняет все накопленные уведомления.
3. Принудительный запуск обработчиков в середине плея:
   ```yaml
   - name: Принудительно применить изменения
     ansible.builtin.meta: flush_handlers
   ```

## Практические сценарии

### Настройка нового сервера (Bootstrap)

Сценарий, объединяющий базовую настройку и установку приложения.

```yaml
---
- name: Подготовка системы
  hosts: all
  become: true
  gather_facts: false # Отключаем, если Python еще не установлен

  tasks:
    - name: Установка Python для работы Ansible
      ansible.builtin.raw: apt-get update && apt-get install -y python3
      changed_when: false

- name: Установка и настройка приложения
  hosts: app_servers
  become: true
  gather_facts: true

  vars:
    app_user: deploy

  tasks:
    - name: Создание пользователя
      ansible.builtin.user:
        name: "{{ app_user }}"
        state: present

    - name: Копирование конфигурации
      ansible.builtin.template:
        src: app.conf.j2
        dest: /etc/app.conf
      notify: Перезапуск приложения

  handlers:
    - name: Перезапуск приложения
      ansible.builtin.service:
        name: myapp
        state: restarted
```
