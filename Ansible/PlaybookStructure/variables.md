# Ansible: переменные и факты

## Определения

**Переменные (Variables)** — именованные значения, используемые для параметризации плейбуков и ролей. Позволяют адаптировать код под разные окружения (dev/prod) без изменения самой логики задач. Могут содержать строки, числа, списки и сложные объекты (словари).

**Факты (Facts)** — системные данные об управляемом хосте (ОС, IP-адреса, диски, память), которые Ansible автоматически собирает перед выполнением задач. Доступны через переменную `ansible_facts`.

**Магические переменные (Magic Variables)** — зарезервированные внутренние переменные Ansible (например, `inventory_hostname`, `hostvars`), значения которых вычисляются автоматически и не могут быть изменены пользователем.

## Базовые концепции

### Типы и область видимости

*   **Глобальные**: Передаются через командную строку (`extra vars`).
*   **Уровня плея**: Определяются в `vars`, `vars_files` или загружаются через `include_vars`.
*   **Уровня хоста/группы**: Задаются в инвентаре или файлах каталогов `group_vars/` и `host_vars/`.
*   **Уровня роли**: Значения по умолчанию (`defaults/`) и жестко заданные переменные роли (`vars/`).

### Иерархия приоритетов (от низшего к высшему)

Ansible использует сложную систему приоритетов (около 22 уровней). Основные этапы:
1.  **Defaults роли** (`defaults/main.yml`) — самый низкий приоритет.
2.  **Групповые переменные инвентаря** (`group_vars/all`, затем конкретные группы).
3.  **Переменные хоста в инвентаре** (`host_vars/`).
4.  **Факты хоста** (`ansible_facts`).
5.  **Переменные плейбука** (`vars`, `vars_files`, `vars_prompt`).
6.  **Переменные роли** (`vars/main.yml`).
7.  **Переменные задач и блоков** (`vars` внутри task/block).
8.  **Зарегистрированные переменные** (`set_fact`, `register`).
9.  **Параметры ролей и включений** (`include_role`, `include_tasks`).
10. **Extra vars** (`-e` в командной строке) — **наивысший** приоритет, переопределяют всё.

### Работа с фактами

По умолчанию сбор фактов (`gather_facts: true`) происходит в начале каждого плея. 
Рекомендуется использовать современный синтаксис обращения через словарь `ansible_facts`:
*   `ansible_facts['os_family']` вместо устаревшего `ansible_os_family`.
*   `ansible_facts['distribution_version']` для уточнения версии ОС.

### Полезные магические переменные

*   `inventory_hostname`: Имя хоста в инвентаре (может отличаться от реального hostname).
*   `hostvars`: Доступ к переменным других хостов (например, `hostvars['db_server']['ansible_facts']['eth0']['ipv4']['address']`).
*   `groups`: Список всех групп и входящих в них хостов.
*   `group_names`: Список групп, в которых состоит текущий хост.

## Практические сценарии

### Сценарий 1: Установка пакетов в зависимости от ОС

Использование фактов для обеспечения кроссплатформенности плейбука.

```yaml
- name: Установка веб-сервера
  ansible.builtin.package:
    name: "{{ web_package }}"
    state: present
  vars:
    web_package: "{{ 'httpd' if ansible_facts['os_family'] == 'RedHat' else 'apache2' }}"
```

### Сценарий 2: Синхронизация системного имени хоста

Приведение реального имени сервера в соответствие с именем в инвентаре.

```yaml
- name: Настройка hostname
  ansible.builtin.hostname:
    name: "{{ inventory_hostname }}"
  when: ansible_facts['nodename'] != inventory_hostname
```

### Сценарий 3: Использование данных другого хоста

Например, настройка приложения на работу с IP-адресом базы данных, полученным из фактов.

```yaml
- name: Генерация конфига приложения
  ansible.builtin.template:
    src: app_conf.j2
    dest: /etc/myapp/app.conf
  vars:
    db_internal_ip: "{{ hostvars['db_node']['ansible_facts']['default_ipv4']['address'] }}"
```
