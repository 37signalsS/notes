# Ansible: Продвинутые возможности плейбуков и отладка

## Продвинутые возможности

### Структурирование плейбуков (import_tasks vs include_tasks)

* `import_tasks` (статическое включение): Содержимое файла вставляется на этапе парсинга (до выполнения). **Не работает с `loop`**.
* `include_tasks` (динамическое включение): Файл подключается в процессе выполнения. **Работает с `loop`**.

```yaml
- name: Включить задачи для Debian-подобных систем
  ansible.builtin.include_tasks: debian.yml
  when: ansible_os_family == "Debian"
```

### Выполнение задач на других хостах (delegate_to)

Позволяет выполнить задачу на другой машине (чаще всего `localhost`), а не на целевом хосте.

```yaml
- name: Find .war files on the control node
  ansible.builtin.find:
    paths: /path/to/local/artifacts
    patterns: "*.war"
  delegate_to: localhost
  register: found_artifacts
```

### Оптимизация производительности

Вопросы оптимизации и параллелизма (такие как `forks`, `async`, `throttle`, `until`) подробно рассмотрены в документе **[Ansible: Оптимизация производительности](../ansible_performance_tuning.md)**.

## Отладка плейбуков

* `-v, -vvv`: Увеличение уровня детализации вывода.
* `--syntax-check`: Проверка синтаксиса YAML.
* `--check`: "Сухой прогон" (dry run) без внесения реальных изменений.
* `--step`: Интерактивное пошаговое выполнение.
* `--limit`: Ограничение выполнения на конкретном хосте.
* `--start-at-task`: Начало выполнения с указанной задачи.
* `debug`: Модуль для вывода значений переменных.
* `debugger`: Ключевое слово для вызова интерактивного отладчика на конкретной задаче.
