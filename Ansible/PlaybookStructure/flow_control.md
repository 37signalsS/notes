# Ansible: управление ходом выполнения

## Определения

**Управление ходом выполнения (Flow Control)** — механизмы Ansible, позволяющие динамически определять логику выполнения задач в зависимости от состояния системы, результатов предыдущих шагов или внешних условий.

**Условная конструкция (`when`)** — директива, определяющая выполнение задачи на основе логического выражения Jinja2.

**Цикл (`loop`)** — итератор, позволяющий выполнять одну задачу многократно для списка элементов. Современный стандарт, заменивший устаревшие `with_*`.

**Регистрация (`register`)** — механизм захвата и сохранения полного JSON-ответа модуля в переменную для последующего анализа и использования в логике плейбука.

**Тег (Tag)** — метка, позволяющая выборочно запускать или пропускать части плейбука при запуске через командную строку.

## Базовые концепции

### Условные конструкции и циклы

*   **`when`**: Принимает логические выражения. Список условий трактуется как логическое «И» (AND). Для логического «ИЛИ» (OR) используются явные операторы `or`.
*   **`loop`**: Перебирает список элементов. Текущий элемент доступен через переменную `item`. Поддерживает сложные структуры (словари, вложенные списки через фильтры).

### Регистрация и переопределение статусов

*   **`register`**: Захватывает полный объект ответа. Ключевые поля: `changed` (были ли изменения), `failed` (сбой), `stdout` (стандартный вывод), `rc` (код возврата).
*   **`changed_when`**: Позволяет вручную задать условие, при котором задача считается изменившей систему. Важно для модулей `shell` и `command`, которые по умолчанию всегда возвращают `changed: true`.
*   **`failed_when`**: Позволяет определить специфические условия сбоя, переопределяя стандартную логику модуля (например, если ненулевой код возврата является допустимым).

### Обработка ошибок

*   **`ignore_errors: true`**: Выполнение продолжается даже при сбое задачи. Статус остается `failed` (красный).
*   **`block`, `rescue`, `always`**: Группировка задач для обработки исключений.
    *   **`block`**: Основной набор задач.
    *   **`rescue`**: Выполняется только при ошибке внутри `block`.
    *   **`always`**: Выполняется в любом случае (аналог `finally`).

### Тегирование

Теги позволяют сегментировать плейбук.
*   **Специальные теги**:
    *   `always`: Задача выполняется всегда, если не пропущена явно через `--skip-tags always`.
    *   `never`: Задача никогда не выполняется, если не вызвана явно через `--tags never`.
    *   `tagged` / `untagged`: Встроенные фильтры для запуска только помеченных или только непомеченных задач.

## Практические сценарии

### Сценарий 1: Проверка версии и условное обновление

Использование `register` и `when` для предотвращения лишних действий.

```yaml
- name: Проверить текущую версию приложения
  ansible.builtin.command: /usr/bin/myapp --version
  register: app_check
  changed_when: false # Команда чтения не меняет состояние

- name: Обновить приложение, если версия не соответствует
  ansible.builtin.shell: /usr/bin/myapp --upgrade
  when: "'1.5.0' not in app_check.stdout"
  notify: Перезапустить сервис
```

### Сценарий 2: Гарантированная очистка (Block-Always)

Использование блоков для удаления временных файлов независимо от успеха операции.

```yaml
- name: Работа с временными данными
  block:
    - name: Создать временную директорию
      ansible.builtin.file:
        path: /tmp/app_build
        state: directory

    - name: Сборка приложения
      ansible.builtin.command: /usr/bin/make_build --dir /tmp/app_build
  
  always:
    - name: Удалить временную директорию
      ansible.builtin.file:
        path: /tmp/app_build
        state: absent
```

### Сценарий 3: Итерация по списку объектов

```yaml
- name: Настройка системных пользователей
  ansible.builtin.user:
    name: "{{ item.name }}"
    shell: "{{ item.shell | default('/bin/bash') }}"
    state: present
  loop:
    - { name: 'deploy', shell: '/bin/sh' }
    - { name: 'admin' }
```
