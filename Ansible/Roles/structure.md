# Структура роли Ansible

## Определения

**Структура роли** — стандартизированная организация каталогов и файлов в роли Ansible, которая позволяет фреймворку автоматически находить и выполнять ресурсы (задачи, обработчики, шаблоны, переменные).

**Каталог роли** — директория с предопределенной структурой подкаталогов, каждый из которых имеет специфическое назначение в жизненном цикле выполнения роли.

---

## Основные концепции

### Стандартная структура каталогов

| Каталог | Назначение |
| :--- | :--- |
| `tasks/` | Основные задачи роли (`main.yml` — входная точка) |
| `handlers/` | Обработчики уведомлений (перезапуск сервисов) |
| `templates/` | Jinja2-шаблоны конфигураций (`.j2`) |
| `files/` | Статические файлы для копирования |
| `defaults/` | Переменные по умолчанию (низкий приоритет) |
| `vars/` | Константы роли (высокий приоритет) |
| `meta/` | Метаданные и зависимости роли |
| `tests/` или `molecule/` | Тесты роли |

### Описание каталогов

**`tasks/main.yml`** — главный файл с задачами, точка входа для роли. Ansible автоматически ищет и выполняет его при вызове роли. Здесь описывается основная логика автоматизации.

**`handlers/main.yml`** — файл с обработчиками. Они выполняются только при вызове из задач через `notify`.

**`files/`** — каталог для хранения статических файлов (бинарные файлы, скрипты), которые нужно скопировать на целевой узел без изменений с помощью модуля `ansible.builtin.copy`.

**`templates/`** — каталог для хранения шаблонов конфигурационных файлов (`.j2`), которые обрабатываются модулем `ansible.builtin.template` с использованием движка [Jinja2](../ansible_jinja_templating.md).

**`defaults/main.yml`** — переменные по умолчанию (версии ПО, стандартные порты). Имеют самый низкий приоритет и могут быть легко переопределены.

**`vars/main.yml`** — переменные с высоким приоритетом, не предназначенные для переопределения извне (константы роли).

**`meta/main.yml`** — метаданные роли: автор, лицензия, поддерживаемые платформы и зависимости от других ролей.

**`tests/`** — каталог для тестов роли, обычно с использованием [Molecule](../ansible_testing_with_molecule.md).

### Создание структуры через ansible-galaxy

Команда `ansible-galaxy role init` автоматически создает полную структуру каталогов:

```bash
ansible-galaxy role init my_new_role
```

Результат:

```
my_new_role/
├── defaults/
│   └── main.yml
├── files/
├── handlers/
│   └── main.yml
├── meta/
│   └── main.yml
├── README.md
├── tasks/
│   └── main.yml
├── templates/
├── tests/
│   ├── inventory
│   └── test.yml
└── vars/
    └── main.yml
```

## Практические сценарии

### Сценарий 1: Сравнение `defaults/main.yml` и `vars/main.yml`

| Параметр | `defaults/main.yml` | `vars/main.yml` |
| :--- | :--- | :--- |
| **Назначение** | Значения по умолчанию для переопределения | Константы роли (не для переопределения) |
| **Приоритет** | Самый низкий | Высокий (переопределяет инвентарь и плейбук) |
| **Пример** | `nginx_worker_processes: 4` | `nginx_config_path: /etc/nginx/nginx.conf` |

**Лучшая практика:** Большинство переменных определяйте в `defaults/main.yml` для гибкости. `vars/main.yml` используйте только для внутренних констант роли.

### Сценарий 2: Настройка зависимостей в `meta/main.yml`

Зависимости указывают роли, которые должны быть выполнены перед текущей:

```yaml
# meta/main.yml в роли 'my_app'
dependencies:
  - role: geerlingguy.nginx
  - role: geerlingguy.postgresql
    vars:
      postgresql_version: "14" # Передача параметров в зависимую роль
```

### Сценарий 3: Организация шаблонов и файлов

**Структура для роли `nginx`:**

```
roles/nginx/
├── files/
│   ├── nginx.conf          # Статический конфиг
│   └── ssl/
│       └── dhparam.pem     # Параметры SSL (Secure Sockets Layer)
├── templates/
│   ├── nginx.conf.j2       # Динамический конфиг
│   └── sites/
│       └── default.j2      # Шаблон виртуального хоста
└── tasks/
    └── main.yml
```

**Использование в задачах:**

```yaml
- name: Copy static config
  ansible.builtin.copy:
    src: nginx.conf
    dest: /etc/nginx/nginx.conf

- name: Deploy dynamic config
  ansible.builtin.template:
    src: sites/default.j2
    dest: /etc/nginx/sites-available/default
```

## Дополнительная информация

### Приоритеты переменных

Полная иерархия приоритетов (от низкого к высокому):

1. `defaults/main.yml` в роли
2. Переменные из инвентаря
3. Переменные из `group_vars/` и `host_vars/`
4. `vars/main.yml` в роли
5. `--extra-vars` в командной строке

Подробное описание — в [PlaybookStructure/variables.md](../PlaybookStructure/variables.md).
