# Структура роли Ansible

## Определения

**Структура роли** — стандартизированная организация каталогов и файлов в роли Ansible, которая позволяет фреймворку автоматически находить и выполнять ресурсы (задачи, обработчики, шаблоны, переменные).

**Каталог роли** — директория с предопределенной структурой подкаталогов, каждый из которых имеет специфическое назначение в жизненном цикле выполнения роли.

---

## Основные концепции

### Стандартная структура каталогов

| Каталог / Файл | Назначение |
| :--- | :--- |
| `tasks/` | Основные задачи роли (`main.yml` — входная точка) |
| `handlers/` | Обработчики уведомлений (перезапуск сервисов) |
| `templates/` | Jinja2-шаблоны конфигураций (`.j2`) |
| `files/` | Статические файлы для копирования |
| `defaults/` | Переменные по умолчанию (низкий приоритет) |
| `vars/` | Константы роли (высокий приоритет) |
| `meta/` | Метаданные, зависимости и спецификации аргументов |
| `library/` | Собственные модули на Python (внутренние для роли) |
| `filter_plugins/` | Пользовательские фильтры Jinja2 |
| `lookup_plugins/` | Пользовательские плагины поиска данных |
| `molecule/` | Современные тесты роли (рекомендуется вместо `tests/`) |

### Описание каталогов и ключевых файлов

**`tasks/main.yml`** — главный файл с задачами, точка входа для роли. Ansible автоматически ищет и выполняет его при вызове роли.

**`handlers/main.yml`** — файл с обработчиками. Они выполняются только при получении уведомления через `notify`.

**`library/`**, **`filter_plugins/`**, **`lookup_plugins/`** и др. — каталоги для расширения функциональности Ansible внутри роли. Позволяют поставлять специфические модули или фильтры вместе с ролью.

**`files/`** — статические файлы (скрипты, конфиги), копируемые модулем `ansible.builtin.copy`.

**`templates/`** — динамические шаблоны [Jinja2](../ansible_jinja_templating.md), обрабатываемые модулем `ansible.builtin.template`.

**`defaults/main.yml`** — переменные по умолчанию с самым низким приоритетом. Предназначены для настройки пользователем.

**`vars/main.yml`** — внутренние переменные роли с высоким приоритетом. Не рекомендуются для переопределения извне.

**`meta/main.yml`** — метаданные роли: автор, лицензия, платформы и зависимости.

**`meta/argument_specs.yml`** — современный способ описания и валидации входных параметров роли. Позволяет задавать типы данных, значения по умолчанию и обязательность параметров.

**`molecule/`** — каталог для тестирования роли с помощью фреймворка [Molecule](../ansible_testing_with_molecule.md).

### Создание структуры через ansible-galaxy

Команда `ansible-galaxy role init` автоматически создает полную структуру каталогов:

```bash
ansible-galaxy role init my_new_role
```

Результат:

```
my_new_role/
├── defaults/
│   └── main.yml
├── files/
├── handlers/
│   └── main.yml
├── meta/
│   └── main.yml
├── README.md
├── tasks/
│   └── main.yml
├── templates/
├── tests/
│   ├── inventory
│   └── test.yml
└── vars/
    └── main.yml
```

## Практические сценарии

### Сценарий 1: Сравнение `defaults/main.yml` и `vars/main.yml`

| Параметр | `defaults/main.yml` | `vars/main.yml` |
| :--- | :--- | :--- |
| **Назначение** | Значения по умолчанию для переопределения | Константы роли (не для переопределения) |
| **Приоритет** | Самый низкий | Высокий (переопределяет инвентарь и плейбук) |
| **Пример** | `nginx_worker_processes: 4` | `nginx_config_path: /etc/nginx/nginx.conf` |

**Лучшая практика:** Большинство переменных определяйте в `defaults/main.yml` для гибкости. `vars/main.yml` используйте только для внутренних констант роли.

### Сценарий 2: Настройка зависимостей в `meta/main.yml`

Зависимости указывают роли, которые должны быть выполнены перед текущей:

```yaml
# meta/main.yml
dependencies:
  - role: geerlingguy.nginx
  - role: geerlingguy.postgresql
    vars:
      postgresql_version: "14" # Передача параметров в зависимую роль
```

### Сценарий 3: Валидация аргументов через `meta/argument_specs.yml`

Позволяет Ansible автоматически проверять входные данные при вызове роли:

```yaml
# meta/argument_specs.yml
argument_specs:
  main:
    short_description: Основная входная точка роли
    options:
      nginx_port:
        type: int
        default: 80
        description: Порт для прослушивания
      nginx_user:
        type: str
        required: true
        description: Пользователь, от которого работает сервис
```

### Сценарий 4: Использование плагинов внутри роли

Если роль требует специфического фильтра Jinja2, его можно разместить прямо в каталоге роли:

```
roles/my_custom_role/
├── filter_plugins/
│   └── custom_filters.py
└── tasks/
    └── main.yml
```

В `tasks/main.yml` фильтр будет доступен автоматически:

```yaml
- name: Use custom filter
  ansible.builtin.debug:
    msg: "{{ 'some_text' | my_custom_filter }}"
```

### Сценарий 5: Организация шаблонов и файлов

**Структура для роли `nginx`:**

```
roles/nginx/
├── files/
│   ├── nginx.conf          # Статический конфиг
│   └── ssl/
│       └── dhparam.pem     # Параметры SSL
├── templates/
│   ├── nginx.conf.j2       # Динамический конфиг
│   └── sites/
│       └── default.j2      # Шаблон виртуального хоста
└── tasks/
    └── main.yml
```

**Использование в задачах:**

```yaml
- name: Copy static config
  ansible.builtin.copy:
    src: nginx.conf
    dest: /etc/nginx/nginx.conf

- name: Deploy dynamic config
  ansible.builtin.template:
    src: sites/default.j2
    dest: /etc/nginx/sites-available/default
```

## Дополнительная информация

### Приоритеты переменных

Иерархия приоритетов (от самого низкого к самому высокому):

1. `defaults/main.yml` в роли
2. Переменные из инвентаря (групповые и хостовые)
3. `vars/main.yml` в роли
4. Переменные, переданные как аргументы при вызове роли
5. Extra vars (`-e` в CLI)

Подробное описание — в [PlaybookStructure/variables.md](../PlaybookStructure/variables.md).
