# Ansible: Практическое руководство по переменным

Этот документ демонстрирует различные способы определения, использования и переопределения переменных в Ansible на практических примерах.

Для получения справочной информации о приоритете переменных см. [Ansible: Плейбуки](ansible_playbooks.md#где-определять-переменные-и-их-приоритет).

---

## 1. Определение переменных в инвентаре

Переменные можно определять непосредственно в файле инвентаря (`hosts.ini`).

### Переменные для конкретного хоста
Можно объявить переменную для одного узла. Это может быть как одиночное значение, так и массив.

```ini
[centos]
192.168.51.3 test=13123 testvar=["abc","222"]
```

### Переменные для группы хостов
Также можно объявить переменные для целой группы.

```ini
[centos]
192.168.51.3

[centos:vars]
test=13123
testvar=["abc","222"]
```

### Переменные для всех хостов
Чтобы объявить переменные для всех групп, используется `all:vars`.

```ini
[all:vars]
test=13123
testvar=["abc","222"]

[centos]
192.168.51.3
192.168.51.5

[ubuntu]
192.168.51.4
```

## 2. Использование переменных в плейбуках и факты

Ansible собирает "факты" о системе (`ansible_facts`), которые доступны как обычные переменные. Например, `ansible_date_time` содержит информацию о текущем времени на удаленном хосте.

**Пример плейбука:**
```yaml
# playbook.yml
---
- hosts: all
  tasks:
    - name: Test vars
      debug:
        msg: "Variable is set to {{ test }}. Time is {{ ansible_date_time.iso8601_basic_short }}"
      when: version is not defined or version < 8.0

    - name: Print all package facts
      debug:
        var: ansible_facts.packages
      # Этот таск можно раскомментировать, чтобы получить полный вывод фактов о пакетах.
```

При запуске этого плейбука `ansible-playbook playbook.yml` таск "Test vars" выведет значение переменной `test` и текущее время, взятое из фактов.

## 3. Переопределение переменных

Приоритет переменных — ключевая концепция в Ansible. Переменные, определенные на более высоком уровне, переопределяют те, что определены на более низком.

### Переопределение в плейбуке
Вы можете переопределить переменную прямо в плейбуке.

**Пример:**
Раскомментируем строку в плейбуке, чтобы переопределить `ansible_date_time`.

```yaml
# playbook.yml
---
- hosts: all
  vars:
    ansible_date_time: "notime" # Переопределяем переменную
  tasks:
    - name: Test vars
      debug:
        msg: "Variable is set to {{ test }}. Time is {{ ansible_date_time }}"
```

Теперь при запуске плейбука в сообщении будет "notime" вместо реального времени.

### Переопределение через командную строку (высший приоритет)
Переменные можно переопределить при запуске `ansible-playbook` с помощью ключа `-e` (`--extra-vars`). Этот способ имеет **самый высокий приоритет**.

**Пример 1: Переопределение одной переменной**
```bash
ansible-playbook playbook.yml -e "ansible_date_time=newtime"
```
Результат таска "Test vars" теперь покажет `newtime`.

**Пример 2: Переопределение нескольких переменных**
Переменные можно перечислять через запятую.

```bash
ansible-playbook playbook.yml -e "ansible_date_time=newtime,test_var=newtest"
```
Теперь в выводе будут использоваться `newtime` и `newtest`.

Это демонстрирует гибкость управления конфигурацией в Ansible, позволяя адаптировать выполнение плейбуков под разные сценарии без изменения самого кода.
