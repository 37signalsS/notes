# Ansible: Структура проекта

## Определения

**Структура проекта Ansible** — логическая организация каталогов и файлов, предназначенная для хранения плейбуков (playbooks), ролей (roles), инвентаря (inventory), переменных и конфигурационных файлов. Грамотное структурирование обеспечивает масштабируемость автоматизации и упрощает поддержку кода в команде.

**Контрольный узел (Control Node)** — управляющая машина с установленным Ansible, на которой хранится структура проекта и запускаются сценарии.

## Базовые концепции

### Ключевые компоненты проекта

| Компонент | Назначение | Основное руководство |
|---|---|---|
| `ansible.cfg` | Конфигурация проекта: пути к ролям, настройки SSH, плагины | [Установка и настройка Ansible](../ansible_setup_and_config.md) |
| `inventory/` | Описание управляемых узлов (хостов), их групп и параметров подключения | [Установка и настройка Ansible](../ansible_setup_and_config.md) |
| `group_vars/` | Переменные, применяемые к группам хостов | [Переменные и факты](../PlaybookStructure/variables.md) |
| `host_vars/` | Индивидуальные переменные хостов (имеют приоритет над групповыми) | [Переменные и факты](../PlaybookStructure/variables.md) |
| `roles/` | Каталог для локальных ролей проекта | [Роли Ansible](../ansible_roles.md) |
| `playbooks/` | Директория со сценариями (YAML-файлами), описывающими логику автоматизации | [Основы плейбуков](../PlaybookStructure/basics.md) |
| `requirements.yml` | Описание внешних зависимостей (ролей и коллекций) для загрузки | [Управление ролями](../Roles/galaxy.md) |

**Безопасность:** Конфиденциальные данные (пароли, токены) в каталогах переменных должны храниться в зашифрованном виде. Рекомендуется использовать расширение `.vault.yml` и инструмент **[Ansible Vault](../Vault/basics.md)**.

## Практические сценарии

### Сценарий: Стандартная структура проекта для нескольких окружений

Данная структура является оптимальной для большинства задач, так как позволяет четко разделить настройки для сред разработки (Stage) и эксплуатации (Prod).

```text
.
├── ansible.cfg           # Глобальные настройки проекта
├── requirements.yml      # Список внешних ролей (Ansible Galaxy)
├── inventory/            # Каталог инвентаря
│   ├── prod/             # Окружение Production
│   │   ├── hosts.ini     # Список хостов
│   │   ├── group_vars/   # Переменные групп (prod)
│   │   └── host_vars/    # Переменные хостов (prod)
│   └── stage/            # Окружение Staging
│       ├── hosts.ini
│       ├── group_vars/
│       └── host_vars/
├── playbooks/            # Точки входа (плейбуки)
│   ├── site.yml          # Мастер-плейбук (оркестрация всего проекта)
│   ├── webservers.yml    # Настройка веб-серверов
│   └── dbservers.yml     # Настройка баз данных
└── roles/                # Локальные роли (специфичные для проекта)
    └── internal_app/     # Пример структуры роли описан в Roles/structure.md
```

**Ключевые файлы:**

- **`site.yml`**: основной файл, который обычно импортирует другие плейбуки через `import_playbook`.
- **`ansible.cfg`**: здесь важно указать пути для поиска ролей, чтобы Ansible «видел» как локальные, так и загруженные роли:

  ```ini
  [defaults]
  roles_path = ./roles:~/.ansible/roles:/usr/share/ansible/roles
  inventory = ./inventory/stage/hosts.ini
  ```

## Дополнительная информация

### Иерархия и приоритеты

- **Переменные**: детальное описание того, как `host_vars` переопределяют `group_vars`, приведено в документе **[Переменные и факты](../PlaybookStructure/variables.md)**.
- **Роли**: для понимания внутренней организации каталогов внутри `roles/` (tasks, handlers, templates) используйте руководство **[Структура роли](../Roles/structure.md)**.
- **Масштабирование**: при работе с тысячами хостов или облачными провайдерами используйте механизмы **[динамического инвентаря](../dynamic_inventory.md)**.
- **Антипаттерны**: типичные ошибки при организации структуры (например, отсутствие префиксов у переменных) рассмотрены в **[Ansible Bad Practices](../ansible_bad_practices.md)**.
