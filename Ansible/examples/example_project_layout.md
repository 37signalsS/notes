# Типовая структура проекта в Ansible

## Определения

**Структура проекта Ansible** — логическая организация файлов и каталогов, обеспечивающая масштабируемость, переиспользование кода и удобную командную разработку.

**Иерархия переменных** — порядок, в котором Ansible ищет значения переменных. Правильная структура каталогов (`group_vars`, `host_vars`) позволяет эффективно управлять настройками для разных окружений (Staging, Production).

**Контрольный узел (Control Node)** — машина, на которой хранится код проекта и запускаются команды управления инфраструктурой.

## Базовые концепции

### Ключевые компоненты проекта

| Компонент | Назначение | Ссылка на SSoT |
|---|---|---|
| `ansible.cfg` | Конфигурация проекта (пути к ролям, настройки SSH). | [Настройка Ansible](../ansible_setup_and_config.md) |
| `inventory/` | Список хостов и групп (статический или динамический). | [Инвентарь](../ansible_setup_and_config.md) |
| `group_vars/` | Переменные для групп хостов (например, `all.yml`). | [Переменные](../PlaybookStructure/variables.md) |
| `host_vars/` | Индивидуальные параметры конкретных серверов. | [Переменные](../PlaybookStructure/variables.md) |
| `roles/` | Каталог для локальных ролей проекта. | [Роли в Ansible](../ansible_roles.md) |
| `collections/` | Директория для внешних коллекций (Ansible Collections). | [Galaxy](../Roles/galaxy.md) |
| `playbooks/` | Точки входа (сценарии автоматизации). | [Основы плейбуков](../PlaybookStructure/basics.md) |
| `requirements.yml` | Список зависимостей (ролей и коллекций) для загрузки. | [Galaxy](../Roles/galaxy.md) |

**Безопасность:** Секреты (пароли, ключи) должны храниться в зашифрованном виде. Рекомендуется использовать расширение `.vault.yml` и инструмент **[Ansible Vault](../Vault/basics.md)**.

## Практические сценарии

### Сценарий: Структура проекта для мульти-окружений

Разделение настроек для сред разработки (Stage) и эксплуатации (Prod) через вложенные каталоги инвентаря.

```text
.
├── ansible.cfg              # Глобальные настройки
├── requirements.yml         # Внешние зависимости (Galaxy)
├── inventory/               # Каталог инвентаря
│   ├── prod/                # Среда Production
│   │   ├── hosts.ini        # Хосты
│   │   └── group_vars/      # Переменные групп Prod
│   └── stage/               # Среда Staging
│       ├── hosts.ini
│       └── group_vars/
├── collections/             # Загруженные коллекции
├── roles/                   # Локальные роли проекта
│   └── common/              # См. ../Roles/structure.md
└── playbooks/               # Сценарии (Entry points)
    ├── site.yml             # Главный плейбук
    └── deploy_app.yml       # Развертывание приложения
```

**Настройка `ansible.cfg`:**

Важно указать корректные пути для поиска ролей и коллекций:

```ini
[defaults]
inventory = ./inventory/stage/hosts.ini
roles_path = ./roles:~/.ansible/roles
collections_path = ./collections
```

**Главный плейбук (`playbooks/site.yml`):**

Используется для оркестрации и вызова других сценариев через `ansible.builtin.import_playbook`.

## Дополнительная информация

### Иерархия переменных

При использовании структуры с вложенными `group_vars` (внутри `inventory/stage/`), переменные из этих каталогов имеют приоритет над глобальным каталогом `group_vars/` в корне проекта. Подробнее о приоритетах — в **[Переменные в Ansible](../PlaybookStructure/variables.md)**.

### Масштабирование

При работе с облачными провайдерами (AWS, Yandex Cloud) рекомендуется использовать **[динамический инвентарь](../dynamic_inventory.md)**, который автоматически формирует списки хостов на основе тегов и API.
