# Структура проекта Ansible

## Определения

- **Структура проекта Ansible**: Организация каталогов и файлов, которая определяет, где хранятся плейбуки, роли, инвентарь, переменные и другие компоненты. Правильная структура критически важна для поддержки, масштабирования и повторного использования кода автоматизации.

## Основные концепции

### Ключевые каталоги и файлы

- **`ansible.cfg`**: Корневой файл конфигурации, определяющий глобальные настройки проекта. Подробнее см. в [Установка и настройка Ansible](../ansible_setup_and_config.md).
- **`inventory/`**: Каталог для файлов [инвентаря](../ansible_setup_and_config.md), описывающих хосты и группы.
- **`group_vars/` и `host_vars/`**: Каталоги для переменных. Ansible автоматически загружает переменные из файлов, названных в честь групп (`group_vars/webservers.yml`) или хостов (`host_vars/db-server-01.yml`). Это основной способ параметризации плейбуков.
- **`roles/`**: Каталог для хранения [ролей](../ansible_roles.md) — основного способа организации и переиспользования кода.
- **`*.yml`**: [Плейбуки](../PlaybookStructure/advanced.md), описывающие логику автоматизации, обычно находятся в корне проекта.

> **Безопасность**: Для хранения секретов (паролей, ключей API) в `group_vars/` и `host_vars/` следует использовать **[Ansible Vault](../Vault/basics.md)**. Файлы с зашифрованными переменными рекомендуется называть с суффиксом `.vault.yml`, например `group_vars/all/vault.yml`.

## Практические сценарии

### Сценарий 1: Стандартная структура проекта

Наиболее распространенная и рекомендуемая структура, подходящая для большинства проектов.

```
/
├── ansible.cfg
├── inventory/
│   ├── prod/
│   │   ├── hosts.ini
│   │   ├── group_vars/
│   │   └── host_vars/
│   └── stage/
│       ├── hosts.ini
│       ├── group_vars/
│       └── host_vars/
├── playbooks/
│   ├── site.yml
│   └── web.yml
├── roles/                # Локальные роли проекта
│   └── base/
└── requirements.yml      # Файл для зависимостей (роли, коллекции)
```

**Описание компонентов:**

- **`requirements.yml`**: Определяет внешние роли и коллекции, которые устанавливаются через `ansible-galaxy install -r requirements.yml`.
- **`site.yml`**: "Мастер-плейбук", который обычно включает другие плейбуки или роли для полной настройки инфраструктуры.
- **`group_vars/all/`**: Переменные в этом каталоге применяются ко всем хостам.

Настройка путей в `ansible.cfg` позволяет Ansible находить роли и коллекции:

```ini
[defaults]
roles_path = ./roles
collections_paths = ./collections
```

### Сценарий 2: Продвинутая структура со скриптом-оберткой

Этот подход используется в сложных системах, где плейбуки могут генерироваться динамически.

```
/
├── ansible.cfg
├── core/
│   ├── roles/
│   └── plays/            # Каталог с "шаблонами" плейбуков
├── inventory/
│   ├── client_A/
│   └── client_B/
├── logs/
└── deploy.sh             # Скрипт-обертка для запуска
```

**Описание компонентов:**

- **`core/plays/`**: Содержит не готовые плейбуки, а шаблоны, из которых скрипт-обертка `deploy.sh` генерирует итоговый плейбук перед запуском.
- **`deploy.sh`**: Основная точка входа, которая конструирует и запускает `ansible-playbook`.
- **Недостатки**: Усложняет проект и требует поддержки дополнительного скрипта, что делает его менее очевидным для новых участников команды.
