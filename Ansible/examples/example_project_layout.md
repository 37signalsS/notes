# Структура проекта Ansible

## Определения

**Структура проекта Ansible** — организация каталогов и файлов для хранения плейбуков, ролей, инвентаря, переменных и других компонентов. Правильная структура критична для поддержки, масштабирования и переиспользования кода.

## Основные концепции

### Ключевые компоненты проекта

| Компонент | Назначение | SSoT |
|---|---|---|
| `ansible.cfg` | Файл конфигурации проекта: пути, настройки по умолчанию | [Установка и настройка Ansible](../ansible_setup_and_config.md) |
| `inventory/` | Файлы инвентаря (хосты, группы, переменные подключения) | [Установка и настройка Ansible](../ansible_setup_and_config.md) |
| `group_vars/` | Переменные для групп хостов | [Переменные и факты](../PlaybookStructure/variables.md) |
| `host_vars/` | Переменные для отдельных хостов (приоритет выше `group_vars`) | [Переменные и факты](../PlaybookStructure/variables.md) |
| `roles/` | Локальные роли проекта | [Роли Ansible](../ansible_roles.md) |
| `playbooks/` | Плейбуки — логика автоматизации | [Основы плейбуков](../PlaybookStructure/basics.md) |
| `requirements.yml` | Зависимости: внешние роли и коллекции из Ansible Galaxy | [Управление ролями](../Roles/galaxy.md) |

**Безопасность:** Секреты (пароли, ключи) в `group_vars/` и `host_vars/` храните зашифрованными через **[Ansible Vault](../Vault/basics.md)**. Рекомендуемый формат: `.vault.yml` (например, `group_vars/all/vault.yml`).

## Практические сценарии

### Сценарий 1: Стандартная структура проекта

Рекомендуемая структура для большинства проектов:

```
/
├── ansible.cfg
├── inventory/
│   ├── prod/
│   │   ├── hosts.ini
│   │   ├── group_vars/
│   │   └── host_vars/
│   └── stage/
│       ├── hosts.ini
│       ├── group_vars/
│       └── host_vars/
├── playbooks/
│   ├── site.yml
│   └── web.yml
├── roles/                # Локальные роли проекта
│   └── base/
└── requirements.yml      # Зависимости (роли, коллекции)
```

**Описание компонентов:**

- **`requirements.yml`** — определяет внешние роли и коллекции для установки через `ansible-galaxy install -r requirements.yml`. Подробности в **[Управление ролями с Ansible Galaxy](../Roles/galaxy.md)**.
- **`site.yml`** — мастер-плейбук, включающий другие плейбуки или роли для полной настройки инфраструктуры.
- **`group_vars/all/`** — переменные применяются ко всем хостам инвентаря.
- **`ansible.cfg`** — настройка путей:

```ini
[defaults]
roles_path = ./roles
collections_paths = ./collections
```

### Сценарий 2: Продвинутая структура со скриптом-оберткой

Подход для сложных систем с динамической генерацией плейбуков:

```
/
├── ansible.cfg
├── core/
│   ├── roles/
│   └── plays/            # Шаблоны плейбуков
├── inventory/
│   ├── client_A/
│   └── client_B/
├── logs/
└── deploy.sh             # Скрипт-обертка
```

**Описание компонентов:**

- **`core/plays/`** — шаблоны плейбуков, из которых `deploy.sh` генерирует итоговые файлы.
- **`deploy.sh`** — точка входа: конструирует и запускает `ansible-playbook`.
- **Недостатки** — усложняет проект, требует поддержки дополнительного скрипта, менее очевидно для новых участников.

## Дополнительная информация

**Приоритеты переменных:** Полная иерархия приоритетов (`defaults` → `group_vars` → `host_vars` → `extra-vars`) описана в **[Переменные и факты Ansible](../PlaybookStructure/variables.md)**.

**Множественные окружения:** Для разделения prod/stage/dev используйте подкаталоги в `inventory/` с отдельными `group_vars` и `host_vars` для каждого окружения.

**Динамический инвентарь:** Для облачных провайдеров и изменяемой инфраструктуры см. **[Dynamic inventory](../dynamic_inventory.md)**.
