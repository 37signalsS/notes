# Ansible: Пример структуры проекта

При работе с Ansible существует множество подходов к организации файлов и каталогов. В этом документе описывается один из практических примеров структуры большого проекта, который использует генерацию плейбуков из шаблонов.

---

## 1. Общая структура каталогов

```
/
├── core/
│   ├── roles/
│   └── plays/
├── inventory/
├── logs/
├── deploy.sh
└── ansible.cfg
```

### `ansible.cfg`
Файл конфигурации Ansible, который находится в корне проекта. Он определяет основные параметры, такие как пути к ролям и инвентарю, настройки SSH и другие. Ansible автоматически подхватывает этот файл, если запускается из корневой директории проекта.

### `core/`
Центральный каталог, содержащий всю логику автоматизации.

*   **`core/roles/`**: Здесь хранятся все роли Ansible, сгруппированные по их функциональному назначению (например, `nginx`, `mysql`, `users`).
*   **`core/plays/`**: Этот каталог содержит **шаблоны плейбуков**. Вместо того чтобы писать статические плейбуки, этот подход подразумевает создание "заготовок" плейбуков, которые затем обрабатываются и превращаются в готовые к выполнению файлы.

### `inventory/`
В этом каталоге хранятся файлы инвентаризации для разных окружений или клиентов. Это позволяет четко разделить список хостов (что настраиваем) от логики автоматизации (как настраиваем).

### `logs/`
Каталог для хранения логов выполнения `ansible-playbook`.

### `deploy.sh` (скрипт-обертка)
Это специальный скрипт, который является основной точкой входа для запуска автоматизации. Он выполняет следующие действия:
1.  **Поиск серверов:** Анализирует файлы в директории `inventory/` для определения целевых хостов.
2.  **Генерация плейбука:** Берет один из шаблонов из `core/plays/`, подставляет в него необходимые переменные (например, имена хостов) и создает временный, готовый к выполнению плейбук.
3.  **Запуск `ansible-playbook`:** Запускает сгенерированный плейбук.

Такой подход с генерацией плейбуков обеспечивает дополнительную гибкость и позволяет динамически строить сценарии выполнения в зависимости от входных параметров.
