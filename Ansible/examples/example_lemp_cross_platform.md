# Ansible: Пример кроссплатформенной установки LEMP на Ubuntu и CentOS

## Определения

**LEMP** — это акроним, обозначающий набор программного обеспечения с открытым исходным кодом, обычно используемого для размещения динамических веб-сайтов и веб-приложений. LEMP состоит из:
*   **L**inux (операционная система)
*   **E**Nginx (веб-сервер)
*   **M**ySQL/MariaDB (система управления базами данных)
*   **P**HP (язык программирования)

**Кроссплатформенный плейбук Ansible** — это плейбук, разработанный для успешного выполнения на различных операционных системах или дистрибутивах (например, Ubuntu и CentOS), адаптируя задачи под специфику каждой платформы.

## Базовые концепции

Данный пример демонстрирует применение **кроссплатформенных плейбуков Ansible** для развертывания стека LEMP на двух различных семействах операционных систем: Debian-подобных (Ubuntu) и RedHat-подобных (CentOS). Основная идея заключается в использовании **фактов Ansible**, таких как `ansible_os_family`, для условного выполнения задач, специфичных для каждой ОС.

Для более глубокого понимания методов создания кроссплатформенных плейбуков обратитесь к документу **[Кроссплатформенные плейбуки Ansible](../cross_platform_playbooks.md)**.

## Практические сценарии

### Подготовка и запуск

Для выполнения плейбука на целевых машинах (Ubuntu и CentOS) необходимо выполнить следующие шаги:

1.  **Скопируйте материалы:** Убедитесь, что все необходимые файлы (плейбук, роли, инвентарь) находятся в рабочей директории на `controlnode`.
2.  **Установите зависимости:** Для работы с MySQL/MariaDB плейбуку требуется коллекция `community.mysql`. Установите её:
    ```bash
    ansible-galaxy collection install community.mysql
    ```
3.  **Запустите плейбук:** Выполните плейбук, указав ваш файл инвентаря:
    ```bash
    ansible-playbook -i your_inventory.ini playbook.yml
    ```

### Проверка результата

После успешного выполнения плейбука вы сможете получить доступ к развернутым веб-серверам:

*   **Ubuntu:** `http://192.168.51.4` (замените на актуальный IP вашей Ubuntu-машины)
*   **CentOS:** `http://192.168.51.3` (замените на актуальный IP вашей CentOS-машины)

Для удобства проверки PHP и подключения к базе данных можно добавить запись в ваш локальный файл `hosts` (на вашем компьютере, не на сервере Ansible):
```
192.168.51.3 php-test.com
```
После этого откройте в браузере `http://php-test.com` и `http://php-test.com/test-connection.php` для проверки.

## Дополнительная информация

### Анализ вывода плейбука (PLAY RECAP)

После выполнения `ansible-playbook` выводит итоговую статистику по каждому хосту в разделе `PLAY RECAP`. Это суммарные данные о выполненных, измененных, пропущенных или завершившихся с ошибкой задачах.

```
PLAY RECAP *********************************************************************
centos_server          : ok=24   changed=19   unreachable=0    failed=0    skipped=4    rescued=0    ignored=0   
ubuntu_server          : ok=21   changed=14   unreachable=0    failed=0    skipped=4    rescued=0    ignored=0
```

*   `ok`: Общее количество успешно выполненных задач (включая `changed`).
*   `changed`: Количество задач, которые внесли изменения в систему.
*   `unreachable`: Хост был недоступен.
*   `failed`: Задача завершилась с ошибкой.
*   `skipped`: Задача была пропущена (например, из-за условия `when`).

Разное количество `ok` и `changed` для `centos_server` и `ubuntu_server` является нормальным и ожидаемым, так как плейбук выполняет разные наборы задач для каждого семейства ОС (например, для CentOS устанавливается дополнительный репозиторий EPEL).

Для подробного анализа и интерпретации вывода выполнения плейбуков обратитесь к документу **[Ansible: Выполнение плейбуков](../ansible_playbook_execution.md#анализ-вывода-выполнения)**.
