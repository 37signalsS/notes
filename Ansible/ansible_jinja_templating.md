# Ansible — шаблонизация Jinja2

## Определения

**Jinja2** — это мощный шаблонизатор для Python, используемый в Ansible для динамической генерации текстовых файлов (конфигураций, скриптов, манифестов). Он позволяет использовать переменные, условную логику, циклы и фильтры непосредственно внутри файлов.

**Шаблон (Template)** — текстовый файл (обычно с расширением `.j2`), содержащий статический текст и вставки Jinja2. В Ansible шаблоны обрабатываются модулем `ansible.builtin.template` на стороне контрольного узла перед отправкой результата на управляемый хост.

## Основные концепции

### Переменные и комментарии

Вывод значения переменной: `{{ variable_name }}`.
Доступ к вложенным данным: `{{ my_dict.key }}` или `{{ my_list[0] }}`.

Комментарии (не попадают в итоговый файл):
```jinja
{# Это комментарий Jinja2 #}
```

### Управление пробелами

Jinja2 сохраняет все переносы строк и пробелы по умолчанию. Чтобы убрать лишние отступы, используются символы `-`:
- `{%-` — убирает пробелы перед блоком.
- `-%}` — убирает пробелы после блока.

```jinja
{% if items -%}
    Contains items
{%- endif %}
```

### Циклы и условия

**Цикл `for`:**
```jinja
{% for user in users %}
user: {{ user.name }}
{% endfor %}
```
Внутри цикла доступен объект `loop` (например, `loop.last`, `loop.index0`).

**Условие `if`:**
```jinja
{% if env == 'prod' %}
debug: false
{% elif env == 'dev' %}
debug: true
{% else %}
debug: default
{% endif %}
```

### Фильтры и тесты

Фильтры изменяют данные (используется символ трубы `|`), а тесты проверяют их состояние (`is`).

**Популярные фильтры трансформации:**
- `default('value')`: Значение по умолчанию, если переменная не определена.
- `combine(other_dict)`: Глубокое слияние словарей.
- `regex_replace('pattern', 'replacement')`: Замена подстрок с использованием регулярных выражений (например, `{{ server_name | regex_replace('\\.local$', '.com') }}`).
- `map('attribute', 'id')`: Извлечение конкретного атрибута из списка объектов.
- `selectattr('status', 'equalto', 'active')`: Фильтрация списка объектов по заданному атрибуту.

**Фильтры конвертации форматов:**
- `to_nice_json` / `to_nice_yaml`: Красивое форматирование структур данных в JSON/YAML строку.
- `from_json` / `from_yaml`: Парсинг JSON/YAML строк в объекты Python (словарь/список). Критически важно при работе с ответами API или чтении внешних файлов.

**Популярные тесты:**
- `is defined` / `is undefined`: Проверка существования переменной.
- `is failed` / `is succeeded`: Проверка статуса выполнения предыдущей задачи (используется с конструкцией `register`).

### Макросы (Macros)

Макросы позволяют создавать переиспользуемые блоки конфигурации, работая аналогично функциям в программировании.

```jinja
{% macro render_vhost(port, domain) %}
server {
    listen {{ port }};
    server_name {{ domain }};
    root /var/www/{{ domain }};
}
{% endmacro %}

{{ render_vhost(80, 'example.com') }}
```

## Практические сценарии

### Динамическая конфигурация Nginx

#### 1. Переменные в Ansible (`vars/main.yml`)
```yaml
vhosts:
  - { name: "app1", port: 8080 }
  - { name: "app2", port: 8081 }
enable_compression: true
```

#### 2. Шаблон `nginx.conf.j2`
```jinja
# {{ ansible_managed }}
http {
    {% if enable_compression -%}
    gzip on;
    gzip_types text/plain application/json;
    {%- endif %}

    {% for host in vhosts %}
    server {
        listen {{ host.port }};
        server_name {{ host.name }}.local;
    }
    {% endfor %}
}
```

#### 3. Использование в плейбуке с валидацией
Использование параметра `validate` является **обязательным стандартом безопасности** при генерации конфигураций. Это гарантирует, что Ansible не запишет синтаксически некорректный файл, который может "положить" сервис.

```yaml
- name: Развертывание конфигурации Nginx
  ansible.builtin.template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    # %s — это временный файл, который Ansible создаст для проверки
    validate: /usr/sbin/nginx -t -c %s
  notify: Restart Nginx
# → web1.example.com | CHANGED => { "changed": true, "dest": "/etc/nginx/nginx.conf" }
```

## Дополнительная информация

### Служебные переменные Ansible в шаблонах

- `ansible_managed`: Строка-заголовок, указывающая, что файл управляется Ansible (настраивается в `ansible.cfg`). Рекомендуется добавлять в начало каждого шаблона в виде комментария.
- `template_host`: Имя контрольного узла, с которого запущен плейбук.
- `template_path`: Полный путь к исходному файлу шаблона `.j2`.
- `template_run_date`: Дата и время рендеринга шаблона.

### Лучшие практики

1.  **Кавычки в YAML:** Если значение в YAML-файле плейбука начинается с символа `{{`, оно обязательно должно быть в кавычках (иначе парсер YAML выдаст ошибку): `msg: "{{ var_name }}"`.
2.  **Экранирование (Raw):** Для вывода текста, который содержит синтаксис, похожий на Jinja2 (например, шаблоны Helm или метрики Prometheus), используйте блок `raw`, чтобы Ansible не пытался их отрендерить:
    ```jinja
    {% raw %}
    {{ prometheus_metric_name }}
    {% endraw %}
    ```
3.  **Безопасность (Command Injection):** Обязательно используйте фильтр `quote` при подстановке переменных в shell-скрипты внутри шаблонов (например, `echo {{ user_input | quote }}`).
4.  **Разделение логики:** Выносите сложную алгоритмическую логику подготовки данных из шаблонов в сам плейбук (используя `set_fact`) или в кастомные фильтры на Python. Шаблон должен быть максимально "глупым" и читаемым.
