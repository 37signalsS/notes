### Синхронизация

*   `git fetch <имя_репозитория>`: Загружает всю историю (коммиты, ветки, теги) из указанного удаленного репозитория, но **не применяет** эти изменения к вашей рабочей копии/ветке, а просто обновляет удаленную ветку origin/main(например) до ее состояния на сервере. 

*   `git pull <имя_репозитория> <имя_ветки>`: Это составная команда, которая по сути выполняет `git fetch`, а затем `git merge` (или `git rebase`)  **для предовращение появление конфликтов иногда лучше сначала притянуть изенения, смотреться, а уже потом их применять к своей ветке/репозиторию**. Она не только загружает, но и сразу пытается слить изменения в вашу текущую ветку.

    **Сценарий 1: Pull из другого удаленного репозитория**
    Полезно, когда вы работаете с форком и хотите синхронизироваться с основным проектом (который обычно добавляют как `upstream`).
    ```bash
    # Добавляем основной репозиторий как "upstream"
    git remote add upstream https://github.com/original/project.git
    # Стягиваем изменения из ветки main основного проекта в нашу текущую ветку
    git pull upstream main
    ```

    **Сценарий 2: Pull из другой ветки того же репозитория**
    Вы можете стянуть изменения из ветки коллеги (`feature-B`) в свою (`feature-A`).
    ```bash
    # Находясь в ветке feature-A
    git pull origin feature-B
    ```
    Это создаст коммит слияния, объединяющий `feature-B` в `feature-A`.

    **Сценарий 3: Использование `pull --rebase` для чистой истории**
    Чтобы избежать лишних коммитов слияния (`Merge branch 'main' into...`), особенно при обновлении своей feature-ветки из `main`, используется `pull` с флагом `--rebase`.
    ```bash
    # Находясь в своей feature-ветке
    git pull --rebase origin main
    ```

### Как посмотреть изменения после fetch

После того как вы сделали `git fetch`, вы можете сравнить состояние сервера с вашей локальной работой, прежде чем сливать изменения.

**1. Посмотреть список новых коммитов (краткий обзор):**

Позволяет увидеть, какие коммиты есть на сервере, но еще нет у вас.
```bash
# Показывает коммиты, которые есть в origin/main, но нет в вашем локальном main
git log main..origin/main
```

**2. Посмотреть все изменения в коде (детально):**

Показывает все строки кода, которые были добавлены и удалены во всех новых коммитах.
```bash
git diff main..origin/main
```

**3. Посмотреть файл целиком (как он выглядит на сервере):**

Показывает содержимое конкретного файла из удаленной ветки, не затрагивая вашу локальную версию, а эта же команда но без указания имени файла показывает информацию о последнем коммите в удалённой ветке `origin/main`, включая изменения, которые он внёс.
```bash
# Синтаксис: git show <ветка>:<путь_к_файлу>
git show origin/main:src/app/main.go
```

*   `git push <имя> <ветка>`: Отправляет локальные изменения.

**Связать локальную ветку с удалённой и отправить изменения:**

```bash
git push --set-upstream origin <имя_ветки>
```

**Принудительная отправка (используйте с осторожностью!):**

*   `git push --force`: Перезаписывает историю в удалённой ветке. **Опасно!**
*   `git push --force-with-lease`: Более безопасная версия. Отклонит push, если кто-то другой внёс изменения.
