# Манипуляции с историей: отмена, исправление и переписывание

Git предоставляет мощные инструменты для изменения коммитов и истории. Важно понимать разницу между "безопасной" отменой изменений и "опасным" переписыванием истории, особенно при работе в команде.

## Отмена и исправление локальных изменений

### Отмена `git add` (убрать файл из индекса)

Если вы добавили файл в индекс (`git add`), но передумали включать его в коммит:

```bash
git reset <имя_файла>
```

### Отмена изменений в рабочей директории

Если вы хотите отменить все локальные изменения в файле и вернуть его к состоянию последнего коммита:

```bash
git restore <имя_файла>
```

## Отмена коммитов

Существует два основных способа отмены коммитов: `revert` (безопасный) и `reset` (опасный для общей истории).

### `git revert`: Безопасная отмена

`git revert <хэш>` создаёт **новый** коммит, который является инверсией указанного коммита. Этот способ не изменяет существующую историю, а дописывает её.

**Преимущества:**
*   Безопасен для публичных (общих) веток, так как не переписывает историю.
*   Сохраняет историю проекта, явно показывая, что коммит был отменён.

**Когда использовать:** Всегда, когда нужно отменить изменения в ветке, с которой работают другие люди (`main`, `develop`).

### `git reset`: Перемещение указателя ветки

`git reset <хэш>` **перемещает** указатель текущей ветки (`HEAD`) на другой коммит, фактически "удаляя" из истории все коммиты, которые были после него.

**Внимание:** `git reset` переписывает историю. Если вы сделали `push` до `reset`, вам придётся использовать принудительный `push` (`--force-with-lease`), чтобы обновить удаленную ветку. Это может привести к потере работы у коллег, которые основывали свои изменения на "удалённой" вами истории.

**Когда использовать:** Только в локальных, приватных ветках, или если вы абсолютно уверены, что никто другой не использует эти коммиты. Также используется для удаления случайно закоммиченных секретов.

**Режимы `git reset`:**

*   `--soft HEAD~1`: Отменяет последний коммит, но оставляет его изменения в индексе (staged), готовыми к новому коммиту.
*   `--mixed HEAD~1` (по умолчанию): Отменяет коммит, оставляет изменения в рабочей директории, но убирает их из индекса.
*   `--hard HEAD~1`: Полностью удаляет коммит и все связанные с ним изменения из истории и рабочей директории. **Самый опасный режим.**

### `git commit --amend`: Исправление последнего коммита

Команда `git commit --amend` позволяет внести изменения в самый последний коммит, не создавая нового. Это форма переписывания истории.

**Основные сценарии:**

1.  **Изменение сообщения последнего коммита:**
    ```bash
    git commit --amend -m "Новое, более корректное сообщение"
    ```

2.  **Добавление забытых файлов в последний коммит:**
    ```bash
    # 1. Добавляем пропущенные файлы в индекс
    git add forgotten_file.py
    # 2. Выполняем amend с опцией --no-edit, чтобы сохранить старое сообщение
    git commit --amend --no-edit
    ```

## Продвинутые техники переписывания истории

### Автоматическая очистка истории с `--fixup` и `--autosquash`

Для поддержания чистой и логичной истории коммитов мелкие исправления ("fix typo", "add log") следует объединять с исходными коммитами.

**Принцип работы:**

1.  `git commit --fixup <хэш_коммита>`: Создает коммит-исправление для указанного коммита.
2.  `git rebase -i --autosquash <базовый_коммит>`: Запускает интерактивный rebase, который автоматически подставляет `fixup`-коммиты к их "родителям" для схлопывания.

**Пример:**

```bash
# 1. Находим опечатку в коммите dc4efa9 и исправляем ее в коде
$ git add main.go

# 2. Создаем fixup-коммит
$ git commit --fixup dc4efa9

# 3. Запускаем интерактивный rebase с авто-склеиванием
$ git rebase -i --autosquash <коммит_до_dc4efa9>
```
Git откроет редактор с уже готовым планом. Вам останется только сохранить и закрыть его.

### Глобальное переписывание истории (`git-filter-repo`)

Для удаления файла из всей истории (например, случайно закоммиченного секрета) рекомендуется использовать `git-filter-repo` вместо устаревшей `git filter-branch`.

**Внимание:** Это мощный и разрушительный инструмент. Обязательно сделайте резервную копию репозитория перед использованием.

```bash
# Пример: удалить файл secret.txt из всей истории
git filter-repo --path secret.txt --invert-paths
```

## Восстановление данных ("Машина времени" Git)

Если что-то пошло не так при переписывании истории, Git предоставляет механизмы для восстановления "потерянных" данных.

### `git reflog`: Журнал всех перемещений HEAD

`git reflog` — это ваш лог безопасности. Он отслеживает все изменения указателя `HEAD`, включая переключения веток, коммиты и `reset`.

```bash
# Показать историю перемещений HEAD
git reflog

# Пример вывода:
# 2a5a921 HEAD@{0}: reset: moving to HEAD~1
# 3b4a1b2 HEAD@{1}: commit: добавил новую фичу
# ...

# Восстановиться к нужному состоянию
git reset --hard HEAD@{1}
```

### `git fsck`: Поиск "висячих" объектов

Если коммит был "потерян" (например, после `reset`), но не был еще удален сборщиком мусора, его можно найти с помощью `git fsck`.

```bash
git fsck --lost-found
```
Эта команда покажет "висячие" коммиты (dangling commits), которые не принадлежат ни одной ветке. Затем вы можете восстановить такой коммит, создав на его основе новую ветку.
