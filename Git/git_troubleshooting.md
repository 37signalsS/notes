# Git: Устранение неполадок и отладка

## Определения

* **Устранение неполадок Git:** Процесс диагностики и решения проблем, возникающих при работе с Git, включая проблемы с подключением, аутентификацией, конфликтами и неожиданным поведением.
* **Отладка транспорта:** Получение подробной информации о коммуникации Git с удаленными репозиториями по протоколам HTTP/HTTPS или SSH для выявления проблем.
* **Окончания строк (CRLF/LF):** Различия в символах, обозначающих конец строки в текстовых файлах, используемые различными операционными системами (CRLF в Windows, LF в Unix/Linux/macOS).
* **`core.autocrlf`:** Конфигурационная настройка Git, управляющая автоматическим преобразованием окончаний строк при коммите и выгрузке файлов.
* **`git bundle`:** Инструмент для упаковки Git-репозитория или его части в один файл, позволяющий передавать изменения без прямого сетевого подключения.

## Базовые концепции

### Диагностика проблем с подключением (транспортные протоколы)

Git использует HTTP/HTTPS и SSH для обмена данными с удаленными репозиториями. Проблемы с этими протоколами могут проявляться как ошибки при клонировании, получении (`fetch`, `pull`) или отправке (`push`) изменений. Увеличение уровня детализации вывода Git помогает понять, что происходит на уровне сетевого взаимодействия и аутентификации.

* **HTTP/HTTPS:** Для отладки HTTP-соединений Git использует библиотеку cURL. Подробный вывод cURL может показать проблемы с прокси, SSL-сертификатами, учетными данными или ограничениями сети.
* **SSH:** Отладка SSH-соединений выявляет проблемы с SSH-ключами, правами доступа, конфигурацией `ssh-agent` или серверной частью SSH.

### Проблемы с окончаниями строк

Несоответствие в окончаниях строк между операционными системами (`CRLF` в Windows против `LF` в Unix-подобных системах) может привести к нежелательным "изменениям" в файлах, конфликтам слияния и проблемам в кроссплатформенных проектах. Git предоставляет настройку `core.autocrlf` для автоматического управления этим преобразованием.

### Работа в офлайн-режиме (`git bundle`)

`git bundle` — это эффективное решение для сценариев, когда сетевое подключение ограничено или отсутствует. Он позволяет "упаковать" коммиты и объекты Git в один бинарный файл, который можно передать по USB или другим способом, а затем "распаковать" на другом компьютере.

## Практические сценарии

### Отладка проблем с транспортом

#### Отладка HTTP/HTTPS-соединений

Используйте переменную окружения `GIT_CURL_VERBOSE` для получения подробного вывода от cURL:

```bash
# Для отладки операций git clone через HTTPS
GIT_CURL_VERBOSE=1 git clone <url_репозитория>

# Для отладки других HTTP/HTTPS операций
GIT_CURL_VERBOSE=1 git pull # или git push
```

Это покажет заголовки запросов/ответов, коды состояния HTTP и возможные ошибки аутентификации или сети.

#### Отладка SSH-соединений

Используйте переменную окружения `GIT_SSH_COMMAND` с флагом `-vvv` для `ssh` для получения подробного вывода:

```bash
# Для отладки операций Git через SSH (например, клонирования)
GIT_SSH_COMMAND="ssh -vvv" git clone <ssh_url_репозитория>

# Или для всех последующих SSH-операций в текущей сессии
export GIT_SSH_COMMAND="ssh -vvv"
git pull # или git push
unset GIT_SSH_COMMAND # Отключить отладку
```

Флаг `-vvv` обеспечивает максимальный уровень детализации, показывая процесс установления соединения, попытки аутентификации (с какими ключами) и любые ошибки.

### Управление окончаниями строк (`core.autocrlf`)

Настройте Git для правильной обработки окончаний строк:

```bash
# Проверить текущую глобальную настройку
git config --global core.autocrlf

# Рекомендуется для Windows: Git преобразует CRLF в LF при коммите и LF в CRLF при выгрузке.
git config --global core.autocrlf true

# Рекомендуется для Linux/macOS: Git преобразует CRLF в LF при коммите, но не изменяет LF при выгрузке.
git config --global core.autocrlf input

# Отключить автоматическое преобразование (используйте осторожно, только если понимаете риски)
git config --global core.autocrlf false
```

### Git Bundle: Работа в офлайн-режиме

#### Создание "бандла" (пакета репозитория)

* **Создание бандла со всей историей:**

    ```bash
    git bundle create repo.bundle --all
    ```

    Эта команда создаст файл `repo.bundle`, содержащий все ветки и их полную историю.

* **Создание инкрементального бандла:**

    ```bash
    git bundle create updates.bundle HEAD ^<хеш_коммита_или_ветки_с_которой_начать_инкрементал>
    ```

    Например, `git bundle create updates.bundle main ^origin/main` создаст бандл с изменениями из ветки `main`, которых нет в `origin/main`.

#### Использование "бандла" (клонирование и обновление)

* **Клонирование репозитория из бандла:**
    На другом компьютере вы можете клонировать репозиторий из бандла, как если бы это был удаленный репозиторий:

    ```bash
    git clone repo.bundle my-repo
    ```

* **Получение обновлений из бандла:**
    Если у вас уже есть репозиторий, и вы хотите получить обновления из другого бандла:

    ```bash
    # Добавление бандла как временного удаленного репозитория
    git remote add offline-updates updates.bundle

    # Получение обновлений из бандла
    git pull offline-updates main

    # Удаление временного удаленного репозитория (опционально)
    git remote remove offline-updates
    ```

    `git bundle` очень полезен для передачи больших репозиториев по медленным сетям, для работы в условиях ограниченной или отсутствующей связи, а также для создания резервных копий.
