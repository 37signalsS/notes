# Инструменты Git TUI и CLI

## Определения

**TUI (Terminal User Interface)** — текстовый пользовательский интерфейс, работающий внутри терминала. Предоставляет интерактивные элементы управления (меню, списки, панели) без необходимости использования графического сервера (X11/Wayland).

**Git TUI-инструменты** — утилиты для визуализации истории Git, интерактивного стейджинга и управления репозиторием непосредственно в терминале.

**CLI-расширения (Pagers)** — инструменты, улучшающие стандартный вывод команд Git (например, `git diff` или `git log`), добавляя синтаксическую подсветку, выравнивание и интерактивность.

**Forge CLI** — официальные инструменты командной строки от провайдеров хостинга Git (GitHub, GitLab), позволяющие управлять Pull/Merge Requests, Issue и CI/CD прямо из терминала.

**Jujutsu (jj)** — современная система контроля версий, полностью совместимая с Git, но предлагающая иную архитектуру (отсутствие индекса, автоматический rebase, безопасность операций).

## Базовые концепции

### Категории инструментов

| Категория | Инструменты | Назначение |
| :--- | :--- | :--- |
| **Полноценные клиенты** | `lazygit`, `gitui`, `jjui` | Управление всем жизненным циклом (add, commit, rebase, push) |
| **Визуализация и Diff** | `git-delta`, `tig`, `difftastic` | Улучшение читаемости изменений и графа коммитов |
| **Интерактивный CLI** | `forgit`, `fzf`, `git-absorb` | Быстрый поиск, нечеткий выбор и автоматизация рутины |
| **Forge (GitHub/GitLab)** | `gh`, `glab` | Управление PR/MR, Issue и пайплайнами CI/CD |
| **Альтернативный VCS** | `jj` (Jujutsu) | Совместимая с Git система с автоматическим rebase и отменой действий |

### Основные TUI-клиенты

*   **lazygit**: Самый популярный и функциональный TUI-клиент (Go). Поддерживает сложные интерактивные перебазирования (rebase), построчное индексирование (staging) и визуализацию графа.
*   **gitui**: Клиент на Rust для максимальной производительности на огромных монорепозиториях. Имеет строгий панельный интерфейс.
*   **tig**: Классический инструмент на C. В основном используется для быстрого просмотра истории и стейджинга отдельных строк (hunks).

### Современные CLI-улучшения

*   **git-delta**: Современный пейджер (замена `less`). Добавляет подсветку синтаксиса, нумерацию строк и боковой (side-by-side) просмотр diff.
*   **difftastic**: Дифференциальный инструмент, понимающий структуру кода (AST). Сравнивает не строки, а логические блоки (функции, циклы).
*   **git-absorb**: Утилита для автоматического разнесения изменений по коммитам (`commit --fixup`) на основе затронутых строк.
*   **gh / glab**: Официальные CLI для взаимодействия с GitHub и GitLab. Позволяют создавать PR, проверять статус CI/CD и управлять секретами.

## Практические сценарии

### Сценарий 1: Настройка git-delta (рекомендуемый diff-пейджер)

`git-delta` значительно улучшает читаемость `git diff` и `git show`.

**Установка:**
```bash
# macOS
brew install git-delta

# Cargo (Rust)
cargo install git-delta
```

**Настройка в `~/.gitconfig`:**
```ini
[core]
    pager = delta

[interactive]
    diffFilter = delta --color-only

[delta]
    navigate = true    # переход между чанками по n/N
    light = false      # использовать темную тему
    side-by-side = true # включить боковой просмотр по умолчанию
    line-numbers = true

[merge]
    conflictstyle = zdiff3
```

### Сценарий 2: Автоматический fixup с git-absorb

Когда нужно внести правки в старые коммиты по результатам ревью, `git-absorb` делает это автоматически.

**Алгоритм работы:**
1.  Внесите изменения в файлы.
2.  Запустите:
    ```bash
    git absorb
    ```
3.  Инструмент найдет коммиты, которые меняли эти же строки, и создаст для них `fixup!` коммиты.
4.  Выполните интерактивный rebase для применения: `git rebase -i --autosquash`.

### Сценарий 3: Полноценное управление через lazygit

**Установка:**
```bash
# macOS
brew install lazygit
```

**Ключевые возможности:**
1.  **Интерактивный Rebase**: Клавиша `e` на коммите — редактирование, `s` — склеивание (squash).
2.  **Работа с чанками**: `Enter` в панели файлов -> выбор конкретных строк -> `space` для добавления в индекс.
3.  **Undo/Redo**: Поддержка отмены последних действий (включая коммиты и сбросы) через `Ctrl+z`.

### Сценарий 4: Работа с Pull Requests через GitHub CLI (gh)

**Основные команды:**
```bash
# Создать PR с заполнением из заголовка коммита и открытием в браузере
gh pr create --fill --web

# Просмотреть статус текущих проверок CI/CD
gh pr checks

# Просмотреть дифф текущего PR
gh pr diff

# Список открытых issue с фильтром по метке
gh issue list --label "bug"
```

### Сценарий 5: Сравнение инструментов

| Критерий | lazygit | gitui | jj (Jujutsu) | git-delta |
| :--- | :--- | :--- | :--- | :--- |
| **Язык** | Go | Rust | Rust | Rust |
| **Тип** | Full TUI | Full TUI | CLI / VCS | CLI Pager |
| **Индекс (Staging)** | Да | Да | Нет (авто) | Н/Д |
| **Производительность** | Высокая | Экстремальная | Высокая | Высокая |
| **Сложный Rebase** | Отлично | Базово | Автоматически | Н/Д |
| **Side-by-side Diff** | Через конфиг | Да | Нет (через пейджер) | Да (лучший) |

## Дополнительная информация

### Выбор инструмента
1.  Если нужен **основной интерфейс** вместо командной строки — выбирайте **lazygit**.
2.  Для **огромных монорепозиториев** (>100GB или миллионы файлов) — используйте **gitui**.
3.  Для **улучшения вывода** `git diff` обязательно установите **git-delta**.
4.  Для **автоматизации чистки истории** — используйте **git-absorb**.
5.  Для **интеграции с Forge (GitHub/GitLab)** — установите **gh** или **glab**.
