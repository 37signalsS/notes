# Инструменты для работы с Git (TUI и CLI)

## Определения

**TUI (Terminal User Interface)** — текстовый пользовательский интерфейс, работающий внутри терминала, предоставляющий интерактивные элементы управления (меню, кнопки, списки) без использования графического сервера (GUI).

**Git TUI-инструменты** — утилиты для визуализации истории Git, управления ветками и коммитами непосредственно в терминале.

---

## Базовые концепции

### Категории инструментов

| Категория | Инструменты | Назначение |
| :--- | :--- | :--- |
| **Визуализация истории** | `git-igitt`, `tig`, `gitui` | Просмотр графа коммитов и веток |
| **Полноценные клиенты** | `lazygit`, `gitui` | Управление репозиторием (add, commit, push, merge) |
| **Просмотр diff** | `tig`, `git-igitt` | Быстрый просмотр изменений |
| **Разрешение конфликтов** | `lazygit`, `git mergetool` | Интерактивное разрешение конфликтов слияния |

### Основные инструменты

**git-igitt** — специализированный инструмент для визуализации истории Git с акцентом на читаемые графы веток прямо в терминале.

**lazygit** — один из самых популярных TUI-клиентов для Git, предоставляющий полный спектр возможностей управления репозиторием.

**tig** — классический TUI-инструмент для просмотра истории и diff-ов.

**gitui** — быстрый TUI-клиент, написанный на Rust, с акцентом на производительность.

## Практические сценарии

### Сценарий 1: Установка git-igitt

Для установки требуется менеджер пакетов Rust — `cargo`:

```bash
# Установка через cargo
cargo install git-igitt
```

Если Rust не установлен:

```bash
curl https://sh.rustup.rs -sSf | sh
```

Бинарные файлы также можно скачать со [страницы релизов GitHub](https://github.com/mlange-42/git-igitt/releases).

### Сценарий 2: Использование git-igitt

Запуск в корне Git-репозитория:

```bash
git-igitt
```

**Навигация:**

- **Стрелки вверх/вниз:** Перемещение по списку коммитов
- **Стрелки влево/вправо:** Переключение между списком коммитов и панелью diff/информации
- **Esc / Q:** Выход из программы

### Сценарий 3: Установка lazygit

```bash
# macOS (Homebrew)
brew install lazygit

# Linux (Ubuntu/Debian)
sudo add-apt-repository ppa:lazygit-team/release
sudo apt-get update
sudo apt-get install lazygit

# Через go
go install github.com/jesseduffield/lazygit@latest
```

### Сценарий 4: Использование lazygit

```bash
# Запуск в корне репозитория
lazygit

# Запуск с указанием директории
lazygit -p /path/to/repo
```

**Основные возможности:**

- **Files:** Добавление файлов в индекс (пробел), просмотр diff
- **Worktrees:** Управление рабочими деревьями
- **Local branches:** Создание, переключение, удаление веток
- **Remotes:** Управление удалёнными репозиториями
- **Tags:** Создание и просмотр тегов
- **Stash:** Управление stash

### Сценарий 5: Установка tig

```bash
# macOS
brew install tig

# Ubuntu/Debian
sudo apt-get install tig

# CentOS/RHEL
sudo yum install tig
```

### Сценарий 6: Использование tig

```bash
# Просмотр истории
tig

# Просмотр истории конкретного файла
tig <файл>

# Просмотр статуса репозитория
tig status

# Просмотр веток
tig branch
```

### Сценарий 7: Использование git-crypt для шифрования секретов в репозитории

**git-crypt** — это утилита, позволяющая шифровать выбранные файлы в Git-репозитории, используя GPG-ключи. Таким образом, секреты (например, конфигурационные файлы) могут храниться в репозитории в зашифрованном виде, и расшифровать их сможет только тот, у кого есть соответствующий GPG-ключ.

**Инициализация `git-crypt` в репозитории:**

```bash
git-crypt init
```

**Добавление пользователя по GPG-ключу:**

```bash
git-crypt add-gpg-user USER_ID # USER_ID — это ID GPG-ключа пользователя
```

**Указание файлов для шифрования (.gitattributes):**

Для того чтобы `git-crypt` знал, какие файлы шифровать, их необходимо указать в файле `.gitattributes` в корне репозитория.

```
# secrets.env будет шифроваться
secrets.env filter=git-crypt diff=git-crypt
```

После этого, файл `secrets.env` будет храниться в репозитории в зашифрованном виде, а на локальной машине пользователя с доступом — в обычном текстовом виде.

**Важно:** Ни один из этих способов не заменяет полноценный менеджер секретов, но каждый из них закрывает конкретную дыру лучше, чем голый `.env`.
