### Gitflow

**Основные ветки:**
*   `main` (или `master`): Стабильные релизы.
*   `develop`: Основная ветка для разработки.

**Вспомогательные ветки:**
*   `feature/*`: Для новых функций (от `develop`).
*   `release/*`: Для подготовки релиза (от `develop`).
*   `hotfix/*`: Для срочных исправлений (от `main`).

**Визуальная схема:**
```
      hotfix/*
         |
main ------o-----------o-------------------o----->
         / \
       /   \       /   \
release/*   \       /   \         release/*
       |     \     /     \           |
develop ---o----o---o---o---o---o---o---o--->
         \ / \ / \ / \ / \ / \ / \ / \
 feature/*     feature/*     feature/*
```

#### Процесс разработки: Git Flow

1.  **Feature Branch:** Разработка ведется в отдельной ветке, созданной от `develop`.
2.  **Pull/Merge Request (PR/MR):** По завершении работы создается PR в `develop`.
3.  **CI/CD и ревью:** Автоматически запускаются проверки (сборка, тесты, линтеры). Код просматривают ревьюеры (в первую очередь тимлид).
4.  **Merge:** После одобрения ветка сливается в `develop`.
5.  **Тестирование:** `develop` периодически сливается в `staging`/`pre-prod` для полного тестирования.
6.  **Релиз:** Код из `develop` или `staging` сливается в `master`/`main` и выкатывается на продакшн.
