# Файлы версий — Version Files

## Определения

**Version Files** (файлы версий) — конфигурационные файлы, содержащие сведения о конкретной версии языка программирования, рантайма, библиотеки или системного инструмента, необходимых для работы проекта.

**Миссия:** Обеспечение идентичности рабочего окружения (Reproducible Environments) на машинах разработчиков, серверах сборки и в продакшене. Они решают проблему «работает только у меня» и автоматизируют переключение контекста при переходе между проектами.

---

## Основные концепции

### Классификация файлов версий

#### 1. Специализированные (Mono-language)
Ориентированы на один конкретный стек:
- `.node-version` / `.nvmrc` — Node.js.
- `.ruby-version` — Ruby (rbenv, rvm).
- `.python-version` — Python (pyenv, uv).
- `.java-version` — Java (jenv).
- `rust-toolchain.toml` — Rust (rustup). Позволяет фиксировать не только версию, но и компоненты (clippy, rust-src).
- `.sdkmanrc` — JVM-стек и инструменты сборки (Gradle, Maven).
- `go.mod` — хотя это файл зависимостей, директива `go 1.x` используется инструментами для выбора рантайма.

#### 2. Универсальные (Polyglot / Modern)
Управляют всем стеком проекта в одном месте:
- `.tool-versions` — стандарт, введенный `asdf`, поддерживаемый `mise`. Формат: `tool version`.
- `.mise.toml` — расширенный формат для `mise`. Поддерживает диапазоны версий, переменные окружения (`[env]`) и задачи (`[tasks]`).
- `.envrc` — файл для `direnv`. Позволяет загружать не только переменные, но и активировать окружения через хуки (например, `use flake` для Nix).

### Сравнение менеджеров версий

| Инструмент | Языки | Файлы | Особенности |
| :--- | :--- | :--- | :--- |
| **asdf** | Все (плагины) | `.tool-versions` | Стандарт индустрии, огромная база плагинов. |
| **mise** | Все | `.mise.toml`, `.tool-versions` | На Rust (очень быстрый), встроенный task runner, заменяет direnv. |
| **nvm / fnm** | Node.js | `.nvmrc`, `.node-version` | Узкая специализация, высокая стабильность. |
| **pyenv / uv** | Python | `.python-version` | uv — современная и быстрая альтернатива на Rust. |
| **rustup** | Rust | `rust-toolchain.toml` | Официальный инструмент, глубокая интеграция. |

### Механизм работы: Шиммы (Shims) vs PATH
Большинство менеджеров используют один из двух подходов:
1. **Шиммы (Shims):** Создание "прослоек" в директории, которая всегда находится в `PATH`. Шимм анализирует текущую папку и вызывает нужный бинарный файл.
2. **Динамический PATH:** Инструмент (как `mise` или `direnv`) перехватывает событие смены директории в shell и динамически модифицирует переменную `PATH`.

## Практические сценарии

### Сценарий 1: Автоматизация с .tool-versions (asdf/mise)
Идеально для Fullstack-проектов.

```text
# .tool-versions в корне проекта
nodejs 20.12.2
python 3.12.3
terraform 1.8.5
kubectl 1.30.0
```

При входе в директорию:
```bash
# mise автоматически определит версии и применит их
node -v # → v20.12.2
```

### Сценарий 2: Безопасность и "доверие" (Trust)
Версионные файлы могут выполнять произвольный код (особенно `.envrc` или `.mise.toml` с задачами).

**Правила безопасности:**
- **mise:** При изменении `.mise.toml` или первом входе инструмент запросит подтверждение: `mise trust`. Не доверяйте файлам из непроверенных источников.
- **direnv:** Требует явного `direnv allow` для активации скриптов в `.envrc`.

### Сценарий 3: Использование в контейнерах и CI
Файлы версий — отличный источник метаданных для Docker и CI/CD.

```dockerfile
# Пример использования .node-version в Dockerfile (псевдокод)
FROM node:$(cat .node-version)-slim
COPY . .
RUN npm install
```

В GitHub Actions `mise-action` или `setup-node` могут автоматически считывать эти файлы, избавляя от дублирования версий в YAML-конфигах.

## Дополнительная информация

### Белые пятна и рекомендации

- **Git и .gitignore:** Файлы версий **ОБЯЗАТЕЛЬНО** должны быть в репозитории. Исключение — локальные переопределения (например, `.tool-versions.local`), которые стоит добавить в `.gitignore`.
- **Nix (flake.nix):** Современный подход к абсолютно воспроизводимым средам. Может сосуществовать с `mise` через интеграцию в `.envrc`.
- **Devcontainers:** Файл `devcontainer.json` часто дополняет файлы версий, описывая не только рантайм, но и расширения IDE и системные зависимости.
