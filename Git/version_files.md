# Файлы версий — Version Files

## Определения

**Version Files** — конфигурационные файлы, содержащие сведения о версии языка программирования, рантайма или системного инструмента. Они используются менеджерами версий (Version Managers) для автоматического переключения рабочего окружения при входе в директорию проекта.

Использование таких файлов гарантирует, что все разработчики в команде и CI/CD-пайплайны используют идентичные версии инструментов, что минимизирует проблему «работает только на моей машине».

---

## Базовые концепции

### Классификация файлов версий

#### 1. Моноязыковые файлы (Legacy & Specialized)
Используются специализированными менеджерами для конкретного языка.
- `.node-version` — поддерживается `fnm`, `nodenv`, `asdf`, `mise`, `volta`.
- `.nvmrc` — классический файл для `nvm`, также понимается `fnm`, `asdf` и `mise`.
- `.ruby-version` — стандарт для `rbenv`, `rvm`, `chruby`.
- `.python-version` — используется `pyenv`.
- `.java-version` — для `jenv`.
- `.go-version` — понимается `asdf-golang` и `mise`.
- `rust-toolchain` / `rust-toolchain.toml` — стандарт для `rustup`.
- `.sdkmanrc` — для `SDKMAN!` (Java, Kotlin, Scala, Groovy, Gradle, Maven).

#### 2. Мультиязычные файлы (Modern Polyglot)
Позволяют описать весь стек проекта в одном файле.
- `.tool-versions` — стандарт для `asdf` и `mise`.
- `.mise.toml` — современный формат для `mise` (ранее `rtx`), поддерживающий не только версии, но и переменные окружения, а также задачи (tasks).

#### 3. Неявные (Implicit) файлы версий
Файлы управления зависимостями, которые могут содержать требования к версии рантайма:
- `package.json` — поле `engines` в Node.js.
- `go.mod` — директива `go 1.x` в Go.
- `Gemfile` — инструкция `ruby "x.x.x"` в Ruby.
- `pyproject.toml` / `poetry.lock` — в Python.

### Порядок поиска (Resolution Order)
Большинство инструментов следуют логике:
1. **Environment Variables:** Явное указание через переменные (например, `NODE_VERSION`).
2. **Local File:** Поиск файла в текущей директории.
3. **Upward Search:** Рекурсивный поиск в родительских директориях до корня диска.
4. **Global/Legacy:** Глобальные настройки пользователя (например, `~/.tool-versions` или `~/.node-version`).

## Практические сценарии

### Сценарий 1: Фиксация версии Node.js через .nvmrc
Самый распространенный способ в экосистеме JavaScript.

```bash
# Создать файл с версией
echo "20.11.0" > .nvmrc

# Активировать версию (требуется nvm)
nvm use
# → Found '/project/.nvmrc' with version <20.11.0>
# → Now using node v20.11.0
```

### Сценарий 2: Использование .tool-versions (asdf / mise)
Удобно для проектов с несколькими инструментами (например, Ruby + Node.js + Terraform).

```text
# .tool-versions
ruby 3.3.0
nodejs 20.11.0
terraform 1.8.0
```

Команды для работы:
```bash
# Установить все инструменты, описанные в файле
asdf install
# или
mise install
```

### Сценарий 3: Переход на .mise.toml
`mise` предлагает более мощный формат TOML для управления окружением.

```toml
# .mise.toml
[tools]
node = "20"
python = "3.12"
terraform = "1.8"

[env]
NODE_ENV = "development"
```
