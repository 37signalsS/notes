# Git — основы

## Определения

**Система контроля версий (СКВ)** — инструмент для отслеживания изменений в файлах, координации совместной работы и управления версиями исходного кода.

**Git** — распределённая система контроля версий (РСКВ), созданная Линусом Торвальдсом в 2005 году для разработки ядра Linux.

**Типы СКВ:**

* **Централизованные (ЦСКВ):** История хранится на одном сервере (SVN, Perforce). Недостаток — единая точка отказа и полная зависимость от сети для любых операций с историей.
* **Распределённые (РСКВ):** Каждый разработчик имеет полную копию репозитория со всей историей (Git, Mercurial). Преимущество — автономная работа, высокая скорость операций и надёжность.

### Основные термины

* **Репозиторий (Repository):** Хранилище всей истории проекта, метаданных и объектов. На локальном диске представлено скрытой директорией `.git`.
* **Рабочий каталог (Working Directory):** Директория с актуальными файлами проекта, которые редактируются в данный момент.
* **Индекс (Staging Area):** Промежуточная область, куда добавляются изменения для включения в следующий коммит.
* **Коммит (Commit):** Снимок состояния проекта в определённый момент времени. Содержит изменения, сообщение, автора, дату и ссылку на родительский коммит.
* **Ветка (Branch):** Перемещаемый указатель на последний коммит в определённой цепочке изменений.
* **HEAD:** Указатель на текущую ветку или конкретный коммит.
* **Detached HEAD:** Состояние, когда HEAD ссылается напрямую на коммит, а не на ветку. Применяется для инспекции старых версий кода.

## Базовые концепции

### Жизненный цикл файлов

1. **Untracked** — новый файл, о котором Git ещё не знает.
2. **Modified** — отслеживаемый файл с изменениями, которые ещё не добавлены в индекс.
3. **Staged** — изменения добавлены в индекс и готовы к включению в следующий коммит.
4. **Committed** — изменения сохранены в локальной базе данных репозитория.

### Конфигурация

Перед началом работы необходимо настроить имя пользователя и email, которые будут привязаны к коммитам.

```bash
# Настройка глобальных параметров
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"

# Проверка настроек
git config --list
# → user.name=Your Name
# → user.email=your.email@example.com
```

Подробно: [git_configuration.md](./git_configuration.md).

### Игнорирование файлов: `.gitignore`

Файл `.gitignore` указывает Git, какие файлы или директории не следует отслеживать (логи, временные файлы, секреты).

```bash
# Пример содержимого .gitignore
node_modules/    # Игнорировать директорию
*.log            # Игнорировать все файлы с расширением .log
.env             # Игнорировать файлы с секретами
```

Подробно: [git_ignore.md](./git_ignore.md).

### Синхронизация: `fetch` против `pull`

* `git fetch` — загружает новые данные из удалённого репозитория, но не интегрирует их в рабочую копию. Безопасная операция.
* `git pull` — загружает и автоматически сливает (merge) изменения в текущую ветку. Эквивалентно `fetch` + `merge`.

Подробно: [git_synchronization.md](./git_synchronization.md).

### Интеграция изменений: `merge` против `rebase`

* **Merge:** Создаёт новый "коммит слияния", сохраняя полную историю обеих веток. Не изменяет существующие коммиты.
* **Rebase:** "Переносит" ваши изменения поверх изменений целевой ветки, создавая линейную историю. Переписывает историю (изменяет хэши коммитов).

Подробно: [git_branching.md](./git_branching.md).

## Практические сценарии

### Сценарий 1: Инициализация и клонирование

```bash
# Создание нового репозитория
git init --initial-branch=main
# → Initialized empty Git repository in /path/to/project/.git/

# Клонирование существующего репозитория
git clone https://github.com/user/repo.git
```

### Сценарий 2: Базовый рабочий процесс

```bash
# Просмотр статуса (краткий формат)
git status -s
# → M  modified_file.txt
# → ?? new_file.txt

# Добавление файлов в индекс
git add new_file.txt
git add .              # Добавить все изменения

# Фиксация изменений
git commit -m "feat: add new functionality"
# → [main 1a2b3c4] feat: add new functionality
# → 1 file changed, 10 insertions(+)
```

### Сценарий 3: Анализ истории

```bash
# Краткий граф истории
git log --oneline --graph --all
# → * 1a2b3c4 (HEAD -> main) feat: add new functionality
# → * d5e6f7g Initial commit

# Статистика изменений по файлам
git log --stat

# Просмотр изменений в конкретном коммите
git show 1a2b3c4
```

### Сценарий 4: Сравнение изменений

```bash
# Рабочий каталог vs Индекс
git diff

# Индекс vs Последний коммит
git diff --staged

# Рабочий каталог vs Последний коммит
git diff HEAD
```

### Сценарий 5: Управление файлами

```bash
# Переименование/перемещение (сохраняет историю в Git)
git mv old_name.txt new_name.txt

# Удаление из Git и с диска
git rm file.txt

# Удаление только из Git (файл остаётся на диске)
git rm --cached file.txt
```

### Сценарий 6: Отмена изменений

```bash
# Убрать файл из индекса (unstage)
git restore --staged <file>

# Отменить локальные изменения в файле (discard changes)
git restore <file>

# Исправить последний коммит (изменить сообщение или добавить файлы)
git commit --amend -m "new message"

# Временное сохранение изменений без коммита ([подробнее](./git_stash.md))
git stash
git stash pop  # Применить и удалить из стека
```

### Сценарий 7: Работа с ветками

```bash
# Создание и переключение на новую ветку
git switch -c feature/cool-stuff
# → Switched to a new branch 'feature/cool-stuff'

# Переключение на существующую ветку
git switch main

# Список веток
git branch
# → * feature/cool-stuff
# →   main
```

### Сценарий 8: Удалённые репозитории

```bash
# Список удалённых репозиториев
git remote -v
# → origin  https://github.com/user/repo.git (fetch)
# → origin  https://github.com/user/repo.git (push)

# Отправка изменений
git push origin feature/cool-stuff

# Безопасная принудительная отправка (после rebase)
git push --force-with-lease
```

## Продвинутые инструменты

### Бинарный поиск ошибок: `bisect`

Помогает найти коммит, который внёс баг, используя бинарный поиск.

```bash
git bisect start
git bisect bad HEAD           # Текущая версия сломана
git bisect good v1.0.0        # В этой версии бага точно не было

# Git будет переключать коммиты, проверяйте их:
git bisect good               # Если всё работает
git bisect bad                # Если баг воспроизводится

git bisect reset              # Возврат в исходное состояние
```
