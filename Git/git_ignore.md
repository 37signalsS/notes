# Игнорирование файлов в Git

## Определения

**`.gitignore`** — текстовый файл, содержащий шаблоны имен файлов и директорий, которые Git должен исключить из отслеживания.

**Игнорируемые файлы** — ресурсы проекта, не подлежащие версионированию. К ним относятся временные файлы ОС и IDE, логи, артефакты сборки, зависимости (например, `node_modules`) и чувствительные данные (секреты, `.env`).

---

## Базовые концепции

### Синтаксис паттернов

Git использует расширенный синтаксис glob-шаблонов для определения правил игнорирования:

| Паттерн | Описание |
| :--- | :--- |
| `*.log` | Все файлы с расширением `.log` во всех директориях |
| `build/` | Директория `build` и всё её содержимое |
| `/TODO` | Файл `TODO` только в корне репозитория |
| `!important.log` | Инверсия — не игнорировать файл, даже если он попадает под другие правила |
| `docs/**/*.txt` | Все файлы `.txt` в директории `docs` и всех её поддиректориях |
| `**/temp/` | Все директории с именем `temp` на любом уровне вложенности |

### Иерархия и порядок проверки

Git проверяет правила в строгом порядке. Последующие уровни могут переопределять предыдущие:

1. **`.gitignore` в директории:** Правила применяются к текущей папке и вложенным в неё. Файлы в поддиректориях имеют приоритет над файлами в родительских папках.
2. **`.git/info/exclude`:** Локальные правила для конкретного клона репозитория. Эти правила не коммитятся и не передаются другим разработчикам.
3. **Глобальный файл конфигурации:** Настраивается через `core.excludesFile` (обычно `~/.gitignore_global`). Применяется ко всем репозиториям пользователя на данной машине.

### Важные нюансы

* **Отслеживаемые файлы:** `.gitignore` игнорирует только файлы, которые ранее **не были** добавлены в индекс Git. Если файл уже находится под контролем версий, добавление его в `.gitignore` не прекратит его отслеживание.
* **Игнорируемые директории:** Если Git проигнорировал родительскую директорию (например, `logs/`), он не будет заглядывать внутрь. Поэтому правило исключения `!logs/important.log` **не сработает**, пока не будет добавлено исключение для самой директории: `!logs/`.
* **Пустые директории:** Git не отслеживает пустые папки. Чтобы сохранить структуру директорий, обычно используют пустой файл `.gitkeep`.

## Практические сценарии

### Сценарий 1: Отладка правил игнорирования

Если файл неожиданно игнорируется (или наоборот), используйте `check-ignore` для выяснения причины:

```bash
# Проверить, почему файл игнорируется, и показать правило
git check-ignore -v path/to/file.log
# → .gitignore:15:*.log  path/to/file.log
```

### Сценарий 2: Удаление файла, который уже отслеживается

Для прекращения отслеживания файла без его удаления с диска:

```bash
# Удалить файл из индекса
git rm --cached config.json
# → rm 'config.json'

# Добавьте его в .gitignore, чтобы он не попал в индекс снова
echo "config.json" >> .gitignore

# Закоммитьте изменения
git commit -m "chore: stop tracking config.json"
```

### Сценарий 3: Принудительное добавление проигнорированного файла

Иногда нужно добавить файл в репозиторий, несмотря на правила в `.gitignore`:

```bash
# Использовать флаг --force
git add -f ignored_but_necessary.lib

# Проверить статус
git status
# → new file:   ignored_but_necessary.lib
```

### Сценарий 4: Глобальное игнорирование системного "мусора"

Настройка правил для файлов, создаваемых ОС (например, `.DS_Store` в macOS или `Thumbs.db` в Windows):

```bash
# Создать файл глобальных исключений
echo ".DS_Store" >> ~/.gitignore_global

# Привязать его к конфигурации Git
git config --global core.excludesFile ~/.gitignore_global
```

### Сценарий 5: Скрытие локальных изменений в отслеживаемых файлах

Если файл должен быть в репозитории (например, шаблон конфига), но вы хотите менять его локально без коммитов:

* **`assume-unchanged`:** Git просто перестает проверять изменения. Сбрасывается при `git reset --hard`.
* **`skip-worktree`:** Более надежный вариант для локальных конфигов. Сохраняется при операциях с ветками.

```bash
# Пометить файл как неизменяемый
git update-index --skip-worktree config/database.yml

# Список файлов с этим флагом
git ls-files -v | grep ^S
# → S config/database.yml

# Вернуть отслеживание
git update-index --no-skip-worktree config/database.yml
```
