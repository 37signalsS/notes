# Git Worktree — параллельные рабочие директории

## Определения

**Git Worktree (`git worktree`)** — механизм для одновременной работы с несколькими ветками в одном репозитории через отдельные рабочие директории. Добавлен в Git 2.5 (2015).

**Физическая реализация:** Worktree создаёт новый рабочий каталог (директорию) с файлом `.git`, содержащим ссылку на оригинальную `.git`-директорию. Все worktree одного репозитория разделяют общую базу объектов, refs и HEAD.

### Зачем нужен worktree

Worktree решает задачи, для которых stash неудобен или недостаточен:

| Сценарий | stash | worktree |
|----------|-------|----------|
| Срочный баг-фикс во время работы | Да | Да (параллельно) |
| Сравнение двух веток в IDE | Нет (нужно переключаться) | Да (два окна) |
| Долгая параллельная работа | Нет (синхронный pop/push) | Да (истинная параллельность) |
| Несколько задач одновременно | Нет (один стек) | Да (неограниченно) |

**Worktree — это не продвинутый stash, а другая абстракция:** stash синхронен (остановился → спрятал → переключился → достал), worktree параллелен (два окна, две ветки, одна база объектов). Аналогия: stash — однопоточный код с time-slicing, worktree — многопоточный код на нескольких ядрах.

## Базовые концепции

### Как это работает

```bash
# Создать новый worktree для hotfix-ветки
git worktree add ../hotfix main
# → Preparing worktree (checking out 'main')
# → Создана директория ../hotfix/ с файлом .git -> ../source/.git

# Перейти в новую директорию и работать как с обычным репозиторием
cd ../hotfix
# Все git-команды работают штатно
# Коммиты, ветки — всё общее с исходным репозиторием
```

Внутри созданной директории:
```bash
cat ../hotfix/.git
# → gitdir: /path/to/source/.git/worktrees/hotfix
```

### Привязка к ветке

Каждый workthread привязан к одной ветке. Нельзя одновременно открыть один и тот же branch в двух worktree (Git блокирует):

```bash
git worktree add ../hotfix main
git worktree add ../hotfix2 main
# → fatal: 'main' is already checked out at '/path/to/hotfix'
```

### Список worktree

```bash
git worktree list
# → /path/to/source          a1b2c3d [main]
# → /path/to/hotfix          e5f6g7h [hotfix]
# → /path/to/feature         i9j0k1l [feature]
```

### Удаление worktree

```bash
# Удаление в два шага: удалить директорию, затем очистить метаданные
rm -rf ../hotfix
git worktree prune                    # Удалить записи об отсутствующих worktree

# Или одной командой (Git 2.17+)
git worktree remove ../hotfix
```

## Практические сценарии

### Сценарий 1: Параллельная работа над фичей и баг-фиксом

```bash
# Текущая работа в main
git worktree add ../bugfix main
cd ../bugfix
# Правим баг, коммитим, пушим

# Возвращаемся к основной работе
cd ../source
# Продолжаем без stash, без коммитов
```

### Сценарий 2: Эксперимент без риска

```bash
git worktree add ../experiment feature
cd ../experiment
# Пробуем радикальные изменения, не боясь сломать основную ветку
# После эксперимента: rm -rf ../experiment && git worktree prune
```

### Сценарий 3: Работа с Git Submodules в worktree

Worktree не затрагивает submodules — они остаются общими через `.gitmodules`.

## Особенности и ограничения

- **Локальность:** Worktree — сугубо локальная фича. `git push` не отправляет информацию о worktree.
- **Разделяемые refs:** Все worktree видят все ветки, но одна ветка может быть зачекаутена только в одном worktree.
- **Мусор:** После удаления директории worktree вручную необходимо выполнять `git worktree prune`, иначе `git worktree list` будет показывать "dangling" записи.
- **Производительность:** Все worktree используют один `.git/objects` — нет дублирования объектов.
- **Pre-commit hooks:** Хуки срабатывают в том worktree, где выполняется команда.
- **Submodules:** Не клонируются повторно для каждого worktree.
- **Совместимость:** Работает с `git rebase`, `git merge` и другими операциями — они учитывают блокировку веток.

Сравнение с `git clone`:

| Критерий | git worktree | git clone |
|----------|-------------|-----------|
| Размер | Одна база объектов (экономия) | Полная копия history |
| Общие refs | Да | Нет |
| Блокировка веток | Да | Нет |
| Переключение между ветками | Через IDE/терминал | Через IDE/терминал |
