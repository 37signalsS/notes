# Конфигурация Git — git config

## Определения

* **Конфигурация Git (`git config`):** Механизм для настройки параметров Git на различных уровнях (системном, глобальном, локальном), управляющий поведением команд, интерфейсом, сетевым взаимодействием и безопасностью.
* **Уровни конфигурации:** Иерархическая система настроек, где более специфичный уровень (локальный) переопределяет более общий (системный).
* **Окончания строк (CRLF/LF):** Символы завершения строки, различающиеся в Windows (`CRLF` — `\r\n`) и Unix-системах (`LF` — `\n`). Несогласованность приводит к конфликтам и ложным изменениям в истории.
* **`core.autocrlf`:** Основной параметр, отвечающий за автоматическую конвертацию окончаний строк в процессе перемещения файлов между индексом и рабочей директорией.
* **`core.fileMode`:** Настройка, определяющая, должен ли Git отслеживать изменения прав доступа (исполняемого бита) файлов в файловой системе.
* **SSH-подпись коммитов:** Метод верификации автора коммита с использованием SSH-ключа вместо GPG.
* **`ssh-agent`:** Фоновая программа, предназначенная для хранения расшифрованных приватных ключей в памяти, что избавляет пользователя от повторного ввода парольной фразы (passphrase).
* **`git-crypt`:** Утилита для прозрачного симметричного шифрования файлов «на лету» при их добавлении в индекс, позволяющая безопасно хранить секреты в публичных репозиториях.
* **`core.fsmonitor`:** Инструмент мониторинга файловой системы, ускоряющий работу `git status` в репозиториях с огромным количеством файлов.

## Базовые концепции

### Иерархия уровней конфигурации

Git ищет настройки в следующем порядке, используя значение из последнего найденного уровня:

1.  **Системный (`--system`):** Параметры для всех пользователей и всех репозиториев в системе. Файл: `$(prefix)/etc/gitconfig` (требует прав администратора).
2.  **Глобальный (`--global`):** Параметры текущего пользователя. Файл: `~/.gitconfig` или `~/.config/git/config`. Это место для персональных данных и настроек интерфейса.
3.  **Локальный (`--local`):** Параметры конкретного репозитория. Файл: `.git/config`. Имеет приоритет над всеми остальными.

### Управление окончаниями строк (CRLF ↔ LF)

Неправильная настройка может привести к тому, что Git будет видеть изменения в каждой строке файла при простом открытии его в редакторе на другой ОС.
*   **Логика Git:** Внутри базы объектов Git (в репозитории) файлы всегда должны храниться с окончаниями `LF`.
*   **Логика Рабочей директории:** На диске разработчика файлы могут быть в `CRLF` (Windows) или `LF` (Linux/macOS).
Параметр `core.autocrlf` управляет мостами между этими состояниями.

### Игнорирование изменений прав доступа (`core.fileMode`)

Git отслеживает изменения прав доступа (режимы `100644` для обычных файлов и `100755` для исполняемых). На Linux/macOS это критично для скриптов. Однако на Windows (NTFS) или при использовании сетевых шар права доступа часто эмулируются некорректно, что вызывает ложные срабатывания.
*   **`true`:** Git реагирует на `chmod`.
*   **`false`:** Git игнорирует метаданные прав доступа, фокусируясь только на содержимом.

### Безопасность и шифрование

*   **Верификация (GPG/SSH):** Позволяет Git-хостингам (GitHub, GitLab) отображать значок "Verified", гарантируя, что коммит пришел от владельца ключа, а не был подделан.
*   **Шифрование (git-crypt):** Интегрируется через атрибуты Git (`filter`), автоматически зашифровывая файлы при `git push` и расшифровывая при `git checkout`. Это позволяет хранить `.env` или сертификаты прямо в коде, если у разработчика есть ключ.

## Практические сценарии

### Сценарий 1: Первоначальная настройка профиля и инструментов

```bash
# Идентификация автора
git config --global user.name "Ivan Ivanov"
git config --global user.email "ivan@example.com"

# Настройка редактора (vim, nano, code --wait)
git config --global core.editor "vim"

# Поведение при pull (рекомендуется rebase для чистой истории)
git config --global pull.rebase true

# Кэширование паролей HTTPS (на 1 час)
git config --global credential.helper 'cache --timeout=3600'
```

### Сценарий 2: Настройка кроссплатформенной работы (Line Endings)

```bash
# Для Windows: конвертировать в CRLF при checkout, в LF при commit
git config --global core.autocrlf true

# Для Linux/macOS: конвертировать CRLF в LF при commit (на случай, если они попали), не трогать при checkout
git config --global core.autocrlf input

# Проверка текущих настроек всех уровней
git config --list --show-origin
```

### Сценарий 3: Исправление проблем с правами доступа (`core.fileMode`)

Если после массового изменения прав (`chmod -R 755`) Git показывает изменения, которых нет в коде:

```bash
# Отключить отслеживание прав локально
git config core.fileMode false

# Способ "откатить" изменения прав в индексе без сброса кода:
git diff -p -R --no-color | grep -E "^(diff|(old|new) mode)" | git apply
```

### Сценарий 4: Подпись коммитов через SSH-ключи (Git 2.34+)

Более простой способ, чем GPG, если у вас уже есть SSH-ключ.

```bash
# 1. Установить формат подписи
git config --global gpg.format ssh

# 2. Указать путь к публичному ключу
git config --global user.signingkey ~/.ssh/id_ed25519.pub

# 3. Включить обязательную подпись для всех коммитов
git config --global commit.gpgsign true

# 4. Проверка подписи в логе
git log --show-signature
```

### Сценарий 5: Работа с SSH-агентом и несколькими ключами

Если у вас разные ключи для работы и личных проектов.

**Запуск и добавление ключа:**
```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_work
```

**Настройка алиасов в `~/.ssh/config`:**
```ini
# Рабочий аккаунт
Host github-work
    HostName github.com
    IdentityFile ~/.ssh/id_ed25519_work
    User git

# Личный аккаунт
Host github-personal
    HostName github.com
    IdentityFile ~/.ssh/id_ed25519_personal
    User git
```
*Клонирование:* `git clone git@github-work:company/project.git`.

### Сценарий 6: Оптимизация для больших репозиториев

```bash
# Включить мониторинг файловой системы (ускоряет git status)
git config --global core.fsmonitor true

# Параллельная загрузка объектов (8 потоков)
git config --global fetch.parallel 8
git config --global submodule.fetchJobs 8

# Ускорение за счет графа коммитов
git config --global core.commitGraph true
git config --global fetch.writeCommitGraph true
```

### Сценарий 7: Прозрачное шифрование с git-crypt

1.  **Инициализация:** `git-crypt init`
2.  **Добавление пользователя:** `git-crypt add-gpg-user user@email.com`
3.  **Настройка атрибутов в `.gitattributes`:**
    ```text
    *.env filter=git-crypt diff=git-crypt
    secrets/*.json filter=git-crypt diff=git-crypt
    ```
4.  **Проверка состояния:** `git-crypt status -v` (покажет, какие файлы зашифрованы).

### Сценарий 8: Настройка шаблона сообщения коммита (commit.template)

Позволяет автоматически предзаполнять редактор при выполнении `git commit`.

```bash
# 1. Создать файл шаблона
echo -e "type(scope): subject\n\nbody\n\nfooter" > ~/.gitmessage

# 2. Указать путь к шаблону в глобальном конфиге
git config --global commit.template ~/.gitmessage
```
Подробнее о форматах и Conventional Commits — в [git_commit_template.md](./git_commit_template.md).
