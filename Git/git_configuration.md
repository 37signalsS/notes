# Конфигурация Git

## Определения

* **Конфигурация Git (`git config`):** Механизм для настройки параметров Git на различных уровнях (системном, глобальном, локальном) для управления поведением Git.
* **SSH-ключи:** Криптографические ключи, используемые для безопасной аутентификации при взаимодействии с удаленными репозиториями Git.
* **`ssh-agent`:** Программа, кэширующая приватные SSH-ключи в памяти для избежания повторного ввода паролей.
* **`.gitignore`:** Файл, используемый для указания Git, какие файлы или директории следует игнорировать и не включать в систему контроля версий.
* **Верификация коммитов (GPG):** Процесс цифровой подписи коммитов с использованием GPG-ключей для подтверждения авторства и целостности изменений.
* **`git-crypt`:** Утилита для прозрачного шифрования отдельных файлов в Git-репозитории, позволяющая хранить секреты в публичных репозиториях.

## Базовые концепции

### Уровни конфигурации Git

1. **Системный (`--system`):** Применяется ко всем пользователям системы и всем их репозиториям. Настройки хранятся в файле `$(prefix)/etc/gitconfig`.
2. **Глобальный (`--global`):** Применяется ко всем репозиториям текущего пользователя. Настройки хранятся в файле `~/.gitconfig` или `~/.config/git/config`.
3. **Локальный (`--local`, по умолчанию):** Применяется только к текущему репозиторию. Настройки хранятся в файле `.git/config` внутри репозитория.

### Игнорирование файлов

Файл `.gitignore` играет ключевую роль в поддержании чистоты репозитория, предотвращая случайное добавление временных файлов, логов, скомпилированных артефактов или чувствительных данных. Правила в `.gitignore` могут быть специфичными для директории, в которой находится файл, или глобальными.

### Безопасность Git

* **Верификация коммитов:** GPG-подпись коммитов позволяет убедиться, что коммит был создан конкретным разработчиком и его содержимое не было изменено после создания.
* **Шифрование файлов в репозитории:** Для хранения конфиденциальных данных в репозитории (даже если он публичный) можно использовать такие инструменты, как `git-crypt`, которые обеспечивают прозрачное шифрование/расшифровку файлов.

## Практические сценарии

### Первоначальная настройка Git

```bash
# Установка глобальных параметров для всех ваших репозиториев
git config --global user.name "Ваше Имя"
git config --global user.email "ваш@email.com"

# Настройка редактора по умолчанию для сообщений коммитов
git config --global core.editor "nano"

# Кэширование учетных данных для HTTPS на 1 час (3600 секунд)
git config --global credential.helper 'cache --timeout=3600'
```

### Аутентификация по SSH

#### Создание нового SSH-ключа

```bash
# Создание ключа с указанием файла сохранения и комментария
ssh-keygen -t ed25519 -C "ваш@email.com" -f ~/.ssh/id_ed25519_project
# Вам будет предложено ввести кодовую фразу для защиты ключа.
```

#### Добавление ключа в `ssh-agent`

```bash
# Запуск ssh-agent (если он еще не запущен)
eval "$(ssh-agent -s)"

# Добавление приватного ключа в ssh-agent
ssh-add ~/.ssh/id_ed25519_project

# Установка правильных прав доступа для директории и файла ключа
chmod 600 ~/.ssh/id_ed25519_project
chmod 700 ~/.ssh
```

#### Управление несколькими SSH-ключами (`~/.ssh/config`)

Настройка `~/.ssh/config` позволяет указать, какой SSH-ключ использовать для конкретного хоста.

```ini
# Стандартный ключ для GitHub
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519

# Ключ для конкретного проекта или организации на GitHub
Host project-alias
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_project
```

После такой настройки можно клонировать репозиторий, используя псевдоним:
`git clone git@project-alias:user/repo.git`

### Игнорирование файлов с помощью `.gitignore`

Примеры паттернов для файла `.gitignore`:

| Паттерн              | Описание                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `*.log`              | Игнорировать все файлы с расширением `.log`.                                                                                        |
| `build/`             | Игнорировать директорию `build` и все ее содержимое.                                                                                |
| `/TODO`              | Игнорировать файл `TODO` только в корневой директории репозитория.                                                                  |
| `!important.log`     | Не игнорировать `important.log`, даже если он подпадает под правило `*.log`. **Важно:** правило исключения (`!`) не сработает, если родительская директория уже исключена. |
| `docs/**/*.txt`      | Игнорировать все файлы `.txt` в директории `docs` и всех ее поддиректориях.                                                          |

#### Временное игнорирование изменений в отслеживаемом файле

```bash
# Начать игнорировать изменения в файле, который уже находится в репозитории
git update-index --assume-unchanged <файл>

# Возобновить отслеживание изменений в файле
git update-index --no-assume-unchanged <файл>
```

### Безопасность и шифрование

#### Верификация коммитов (GPG)

Для настройки подписи коммитов GPG-ключом:

* [Верификация коммитов GPG](https://habr.com/ru/articles/754128/)

#### Шифрование файлов в репозитории (`git-crypt`)

1. **Инициализация в репозитории:**

    ```bash
    git-crypt init
    ```

2. **Добавление доверенных GPG-ключей:**

    ```bash
    git-crypt add-gpg-user "ваш@email.com"
    ```

3. **Настройка шифрования файлов:**
    Создайте или отредактируйте файл `.gitattributes` в корне репозитория и укажите, какие файлы следует шифровать:

    ```
    secret.json filter=git-crypt diff=git-crypt
    config/passwords.env filter=git-crypt diff=git-crypt
    ```

4. **Блокировка/разблокировка (обычно не требуется вручную после настройки):**

    ```bash
    git-crypt lock    # Зашифровать все отслеживаемые файлы
    git-crypt unlock  # Расшифровать все отслеживаемые файлы
    ```
