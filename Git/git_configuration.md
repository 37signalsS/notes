# Конфигурация Git

Правильная настройка Git и связанных инструментов — ключ к эффективной и безопасной работе.

## Глобальная и локальная конфигурация (`git config`)

Git хранит настройки на нескольких уровнях. Основные — глобальный (для всех ваших проектов) и локальный (для текущего проекта).

### Первоначальная настройка

В первую очередь необходимо указать ваше имя и адрес электронной почты. Эта информация будет встроена в каждый создаваемый вами коммит.

```bash
# Установка глобальных параметров
git config --global user.name "Ваше Имя"
git config --global user.email "ваш@email.com"
```

### Полезные настройки

**Настройка редактора по умолчанию:**
```bash
# Использовать nano в качестве редактора для сообщений коммитов
git config --global core.editor "nano"
```

**Кэширование учетных данных для HTTPS:**
Позволяет не вводить логин и пароль при каждом обращении к удаленному репозиторию.
```bash
# Запомнить учетные данные на 1 час
git config --global credential.helper 'cache --timeout=3600'
```

## Аутентификация по SSH

Использование SSH-ключей — это более безопасный и удобный способ взаимодействия с удаленными репозиториями, чем HTTPS с логином/паролем.

### Создание нового SSH-ключа

Рекомендуется использовать алгоритм `ed25519`.

```bash
# -f указывает на файл для сохранения ключа, что полезно для разделения ключей по проектам или сервисам
ssh-keygen -t ed25519 -C "ваш@email.com" -f ~/.ssh/id_ed25519_project
```

### Добавление ключа в ssh-agent

`ssh-agent` — это фоновый процесс, который кэширует ваш приватный ключ, избавляя от необходимости вводить пароль от ключа каждый раз.

```bash
# Запуск агента
eval "$(ssh-agent -s)"
# Добавление ключа в агент
ssh-add ~/.ssh/id_ed25519_project
# Установка правильных прав доступа
chmod 600 ~/.ssh/id_ed25519_project
chmod 700 ~/.ssh
```

### Управление несколькими ключами (`~/.ssh/config`)

Вы можете настроить, какой ключ использовать для какого хоста, в файле `~/.ssh/config`.

```ini
# Стандартный ключ для GitHub
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519

# Ключ для конкретного проекта на GitHub
Host project-alias
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_project
```

После такой настройки можно клонировать репозиторий, используя псевдоним:
`git clone git@project-alias:user/repo.git`

> Для получения более подробной информации о SSH, генерации ключей и управлении ими, обратитесь к основному документу [SSH (Secure Shell)](../Linux/Security/ssh.md).

## Игнорирование файлов (`.gitignore`)

Файл `.gitignore` указывает Git, какие файлы или директории следует игнорировать. Это необходимо для файлов, которые генерируются автоматически, содержат секреты или специфичны для локальной среды разработки.

| Паттерн              | Описание                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `*.log`              | Игнорировать все файлы с расширением `.log`.                                                                                        |
| `build/`             | Игнорировать директорию `build` и все ее содержимое.                                                                                |
| `/TODO`              | Игнорировать файл `TODO` только в корневой директории.                                                                              |
| `!important.log`     | Не игнорировать `important.log`, даже если он подпадает под правило `*.log`. **Важно:** правило не сработает, если родительская папка уже исключена. |
| `docs/**/*.txt`      | Игнорировать все файлы `.txt` в директории `docs` и всех ее поддиректориях.                                                          |

### Временное игнорирование отслеживаемого файла

Иногда нужно временно прекратить отслеживание изменений в файле, который уже находится в репозитории (например, локальный файл конфигурации).

```bash
# Начать игнорировать изменения в файле
git update-index --assume-unchanged <файл>

# Возобновить отслеживание изменений
git update-index --no-assume-unchanged <файл>
```

## Безопасность и шифрование

### Верификация коммитов (GPG)

Вы можете подписывать свои коммиты с помощью GPG-ключа для подтверждения их подлинности. Это гарантирует, что коммит был сделан именно вами и не был изменен.
[Инструкция на Habr: Верификация коммитов GPG](https://habr.com/ru/articles/754128/)

### Шифрование файлов (Git Crypt)

Для хранения секретов (паролей, токенов) прямо в репозитории используется `git-crypt`. Он позволяет шифровать отдельные файлы, которые остаются зашифрованными в удаленном репозитории, но автоматически расшифровываются в вашей локальной рабочей копии.

1.  **Инициализация:** `git-crypt init`
2.  **Добавление доверенных GPG-ключей:** `git-crypt add-gpg-user "ваш@email.com"`
3.  **Настройка шифрования:** Создайте файл `.gitattributes` и укажите, какие файлы шифровать (например, `secret.json filter=git-crypt diff=git-crypt`).
4.  **Блокировка/разблокировка:** `git-crypt lock` / `git-crypt unlock`.
