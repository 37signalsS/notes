## Git Hooks: Автоматизация проверок

Git Hooks — это скрипты, которые Git запускает автоматически при определенных событиях (коммит, пуш, мерж и т.д.). Они находятся в директории `.git/hooks` вашего репозитория.

Один из самых полезных хуков — `pre-push`. Он срабатывает перед отправкой коммитов на удаленный сервер, что делает его идеальным моментом для быстрой проверки кода.

- **Экономия ресурсов CI/CD**: Простые проверки (синтаксис, поиск секретов) выполняются локально, не загружая CI/CD раннеры.
- **Стандартизация кода**: Обеспечивается соблюдение единых правил форматирования и качества кода для всей команды.
- **Предотвращение ошибок**: Снижается вероятность ошибок в основной ветке (`main`) или на продуктивном окружении.

### Примеры проверок для `pre-push` хука

- **Запуск линтеров**: `eslint`, `pylint`, `shellcheck`.
- **Проверка синтаксиса**: `python -m py_compile`, `terraform validate`.
- **Поиск закоммиченных секретов**: Использование инструментов вроде `truffleHog` или `git-secrets`.
- **Запуск модульных тестов**.
- **Проверка формата коммитов**.

### Готовые примеры для `pre-push`

Чтобы использовать эти примеры, скопируйте код в файл `.git/hooks/pre-push` и сделайте его исполняемым:

```bash
chmod +x .git/hooks/pre-push
```

#### Поиск утерянных секретов

Этот хук ищет в последних 10 коммитах строки, которые могут быть секретами (пароли, токены, ключи).

```bash
#!/bin/bash

echo "🛡️ Проверяем на наличие секретов..."

# Используем git-secrets или аналогичный инструмент.
# Данный пример использует простой grep для демонстрации.
if git log -p -n 10 --oneline | grep -E "(password|token|key)"; then
    echo "❌ Обнаружен возможный секрет в истории коммитов! Проверьте последние изменения."
    exit 1
else
    echo "✅ Подозрительных строк не найдено."
fi
```
> **Примечание:** Для более надежного поиска секретов рекомендуется использовать специализированные инструменты, такие как `git-secrets` или `truffleHog`.

### Как поделиться хуками с командой

По умолчанию директория `.git/hooks` не отслеживается системой контроля версий. Чтобы вся команда могла использовать одинаковые хуки, придерживайтесь следующего подхода:

1.  **Создайте директорию для хуков** в вашем репозитории (например, `scripts/git-hooks`).
2.  **Сохраните скрипты хуков** в этой директории.
3.  **Настройте их автоматическое копирование** или создание символических ссылок при инициализации проекта. Это можно сделать с помощью скрипта в `Makefile` или инструкции в `README.md`.

**Пример команды для создания символической ссылки:**

```bash
ln -s -f ../../scripts/git-hooks/pre-push .git/hooks/pre-push
```
