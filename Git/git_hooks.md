# Git Hooks: Автоматизация проверок

## Определения

* **Git Hooks:** Скрипты, которые Git запускает автоматически при определенных событиях в жизненном цикле репозитория (например, коммит, пуш, мерж). Они позволяют автоматизировать задачи, обеспечивать соблюдение стандартов и предотвращать ошибки.
* **Клиентские хуки (Client-Side Hooks):** Хуки, выполняемые на локальной машине разработчика. Используются для проверки кода *до* его отправки в репозиторий.
* **Серверные хуки (Server-Side Hooks):** Хуки, выполняемые на удаленном Git-сервере. Используются для применения политик на уровне всей команды или проекта.
* **`pre-commit`:** Клиентский хук, срабатывающий перед созданием коммита.
* **`pre-push`:** Клиентский хук, срабатывающий перед отправкой коммитов на удаленный сервер.
* **`pre-receive`:** Серверный хук, запускающийся, когда сервер получает `push` от клиента.

## Базовые концепции

### Назначение и расположение Git Hooks

Git Hooks являются мощным механизмом для автоматизации процессов разработки. Они представляют собой исполняемые скрипты (написанные на любом языке, поддерживаемом системой, например, Bash, Python, Ruby), которые находятся в директории `.git/hooks` каждого репозитория. По умолчанию в этой директории находятся примеры хуков с расширением `.sample`. Чтобы активировать хук, нужно переименовать файл, удалив расширение `.sample` и сделать его исполняемым.

### Категории и распространенные Git Hooks

#### Клиентские хуки (Client-Side Hooks)

Выполняются на локальной машине разработчика. Они позволяют проверять код на ранних стадиях, до того как он будет отправлен на сервер.

* **`pre-commit`**: Срабатывает перед созданием коммита. Используется для:
  * Линтинга и форматирования кода (`eslint`, `prettier`, `black`).
  * Проверки синтаксиса.
  * Поиска отладочных выражений (например, `console.log`).
    Если скрипт завершается с ненулевым кодом, коммит отменяется.
* **`commit-msg`**: Проверяет сообщение коммита на соответствие стандартам (например, наличие номера задачи, соблюдение паттерна).
* **`pre-push`**: Срабатывает перед отправкой коммитов на удаленный сервер (`git push`). Это последняя возможность "поймать" проблемы локально (например, запустить быстрые тесты или сканирование на секреты), прежде чем они станут видны другим.

#### Серверные хуки (Server-Side Hooks)

Выполняются на удаленном сервере, где хостится репозиторий. Используются для применения глобальных политик, контроля качества и интеграции с CI/CD системами.

* **`pre-receive`**: Запускается, когда сервер получает `push`. Здесь можно:
  * Запустить тесты или более глубокий анализ кода.
  * Проверить права доступа пользователя.
  * Убедиться, что история не была принудительно перезаписана в защищенные ветки.
    Если скрипт завершается неудачно, `push` отклоняется.
* **`post-receive`**: Срабатывает после успешного `push`. Идеален для:
  * Запуска CI/CD пайплайнов.
  * Отправки уведомлений (например, в Slack).
  * Обновления внешних систем (например, проектного трекера).

### Фреймворки для управления хуками

Ручное управление хуками может быть сложным, особенно в больших командах. Фреймворки значительно упрощают их установку, конфигурацию и синхронизацию:

* **[pre-commit](https://pre-commit.com/):** Популярный фреймворк для управления клиентскими хуками. Позволяет легко подключать готовые проверки для множества языков и инструментов. Конфигурируется через файл `.pre-commit-config.yaml`.
* **Husky (для JavaScript/Node.js):** Позволяет управлять хуками через `package.json`, делая их частью проекта для JS-разработчиков.

## Практические сценарии

### Как поделиться хуками с командой

Директория `.git/hooks` не отслеживается Git'ом. Чтобы обеспечить использование одних и тех же хуков всей командой, следуйте этим шагам:

1. **Создайте отдельную директорию** в вашем репозитории для хранения скриптов хуков (например, `scripts/git-hooks/`).
2. **Сохраните ваши скрипты хуков** (например, `pre-commit`, `pre-push`) в этой директории. Убедитесь, что они исполняемые (`chmod +x`).
3. **Настройте автоматическую установку хуков** при инициализации проекта. Это можно сделать одним из способов:
    * **Скрипт установки:** Добавьте в `Makefile`, `package.json` (для JS-проектов) или отдельный установочный скрипт команду, которая будет создавать символические ссылки из `.git/hooks` на ваши скрипты.

        ```bash
        # Пример команды для создания символической ссылки на pre-push хук:
        ln -s -f ../../scripts/git-hooks/pre-push .git/hooks/pre-push
        ```

        (Путь `../../scripts/git-hooks/pre-push` зависит от расположения вашей директории с хуками относительно `.git/hooks/`.)
    * **`git config core.hooksPath`:** Укажите Git, где искать хуки.

        ```bash
        git config core.hooksPath scripts/git-hooks
        ```

        Этот метод удобен, так как позволяет Git автоматически использовать скрипты из указанной директории, без создания симлинков вручную.
