# Конфигурация редакторов (EditorConfig)

## Определения

**EditorConfig** — кроссплатформенный стандарт для определения и поддержания единого стиля форматирования кода в различных редакторах и IDE.

**`.editorconfig`** — конфигурационный файл в формате INI, содержащий правила форматирования (отступы, кодировки, переносы строк), которые автоматически применяются поддерживаемыми редакторами при открытии файла.

---

## Базовые концепции

### Иерархия и наследование

EditorConfig использует систему поиска "снизу вверх" по дереву директорий:

1. **Поиск:** При открытии файла редактор ищет файл `.editorconfig` в текущей директории и во всех родительских директориях до корня файловой системы.
2. **`root = true`:** Эта директива в начале файла останавливает поиск выше по дереву. Рекомендуется устанавливать её в корне репозитория проекта.
3. **Наследование:** Правила из файлов, находящихся ближе к открытому файлу, переопределяют правила из файлов в вышележащих директориях.
4. **Специфичность:** Внутри одного файла секции, расположенные ниже, переопределяют вышележащие при совпадении паттернов имен файлов.

### Основные директивы

| Директива | Значения | Описание |
| :--- | :--- | :--- |
| `indent_style` | `space`, `tab` | Стиль отступа (пробелы или табуляция). |
| `indent_size` | число, `tab` | Количество пробелов в одном отступе. |
| `tab_width` | число | Ширина символа табуляции (по умолчанию равно `indent_size`). |
| `end_of_line` | `lf`, `crlf` | Символ конца строки (рекомендуется `lf` для кроссплатформенности). |
| `charset` | `utf-8`, `latin1` | Кодировка файла. |
| `trim_trailing_whitespace` | `true`, `false` | Удаление лишних пробелов в конце строк. |
| `insert_final_newline` | `true`, `false` | Гарантированное наличие пустой строки в конце файла. |
| `max_line_length` | число, `off` | Ограничение максимальной длины строки. |

## Практические сценарии

### Сценарий 1: Универсальный шаблон проекта

Базовая конфигурация, подходящая для большинства современных проектов.

```ini
# Остановить поиск в родительских папках
root = true

# Глобальные настройки для всех файлов
[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

# Настройки для специфичных расширений
[*.py]
indent_size = 4

[Makefile]
indent_style = tab

# Исключение для Markdown (пробелы в конце могут значить перенос строки)
[*.md]
trim_trailing_whitespace = false
```

### Сценарий 2: Интеграция с линтерами (Prettier, ESLint)

Многие современные инструменты форматирования (например, **Prettier**) автоматически учитывают настройки из `.editorconfig`, если они не переопределены в их собственных конфигах. Это позволяет использовать `.editorconfig` как единственный источник правды для базовых настроек стиля.

### Сценарий 3: Автоматическая проверка в CI/CD

Использование `editorconfig-checker` для валидации кода на соответствие правилам.

```bash
# Запуск проверки всех файлов в репозитории
editorconfig-checker
# → 23 files checked, 0 errors found.

# Если найдены ошибки форматирования
# → index.js:15:20: trailing-whitespace: line has trailing whitespace
```

## Дополнительная информация

### Поддержка в редакторах

* **Встроенная поддержка:** IntelliJ IDEA (и вся линейка JetBrains), PyCharm, Visual Studio, GitHub (веб-интерфейс).
* **Через плагины:** VS Code (плагин `EditorConfig for VS Code`), Vim, Sublime Text.

### Официальные ресурсы

* **[Официальный сайт EditorConfig](https://editorconfig.org/):** Спецификация и примеры.
* **[EditorConfig Checker (GitHub)](https://github.com/editorconfig-checker/editorconfig-checker):** Инструмент для автоматической валидации правил.
