### Отмена и исправление изменений

**Отмена `git add` (убрать файл из индекса):**

```bash
git reset <имя_файла>
```

**Отмена локальных изменений в файле:**

```bash
git restore <имя_файла>
```

**Отмена коммитов (`reset` vs `revert`):**

*   `git revert <хэш>`: Создаёт **новый** коммит, отменяющий изменения, которые еще не были отправлены, так и те изменения, что были отправлены в удаленный репозиторий. **Рекомендуется при работе в команде**.
*   `git reset <хэш>`: **Перемещает** указатель `HEAD`, если он не был еще отправлен в удаленный репозиторий (если был отправлен, то пушить через `git push --force-with-lease`), изменяя историю. **Опасно при работе в команде из-за изменения истории, использовать только при единоличной работе, например, в своей ветке, или если необходимо удалить случайно отправленный в удаленный репозиторий секрет.**

**Режимы `git reset`:**

*   `--soft HEAD~1`: Отменяет коммит, но оставляет изменения в индексе (staged).
*   `--mixed HEAD~1` (по умолчанию): Отменяет коммит, изменения остаются в рабочей директории и удаляються из индекса.
*   `--hard HEAD~1`: Полностью удаляет коммит и все связанные с ним изменения.

**Изменение последнего коммита (`git commit --amend`)**

Команда `git commit --amend` позволяет внести изменения в самый последний коммит. Это мощный инструмент для исправления мелких ошибок, обновления сообщения коммита или добавления забытых файлов.

**Важно:** Используйте `amend` только для коммитов, которые еще не были отправлены в общий удаленный репозиторий (`push`). Изменение уже отправленных коммитов равносильно переписыванию общей истории и может вызвать проблемы у ваших коллег. Если вам все же необходимо это сделать, используйте `git push --force-with-lease`.

**Основные сценарии использования:**

1.  **Изменение сообщения последнего коммита:**
    ```bash
    git commit --amend -m "Новое, более корректное сообщение"
    ```

2.  **Добавление забытых файлов в последний коммит:**
    Допустим, вы сделали коммит, но забыли включить в него один или несколько файлов.

    ```bash
    # 1. Добавляем пропущенные файлы в индекс
    git add forgotten_file.py

    # 2. Выполняем amend. Git добавит проиндексированные файлы
    # к последнему коммиту, создав новый коммит взамен старого.
    # Флаг --no-edit сохраняет исходное сообщение коммита.
    git commit --amend --no-edit
    ```

**Полный сброс до удалённого состояния:**

```bash
git fetch --all
git reset --hard origin/main # Замените main на нужную ветку
```

**Очистка рабочей директории:**

```bash
git clean -n      # Показать, какие файлы будут удалены
git clean -fd     # Удалить неотслеживаемые файлы и директории
```

### Восстановление данных

**`git reflog`**: Журнал всех изменений `HEAD`. Помогает найти "потерянные" коммиты.

```bash
git reflog
git reset --hard HEAD@{индекс} # Восстановиться к нужному состоянию
```

**`git fsck`**: Проверяет целостность базы данных и находит "висячие" коммиты.

```bash
git fsck --lost-found
```

**Восстановление удалённого файла:**

```bash
# 1. Найти хэш коммита, где файл существовал
git rev-list -n 1 HEAD -- <путь_к_файлу>

# 2. Восстановить файл из этого коммита
git checkout <хэш>^ -- <путь_к_файлу>
```

**Возврат одного файла к состоянию из другого коммита:**


```bash
git checkout <хэш_коммита> -- <имя_файла>
```
