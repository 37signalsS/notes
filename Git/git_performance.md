# Git: Оптимизация производительности

## Определения

**Оптимизация производительности Git** — совокупность техник, настроек и инструментов для ускорения операций Git (clone, fetch, status, log) при работе с репозиториями большого объема (Monorepos) или в условиях ограниченных ресурсов.

**Scalar** — надстройка над Git (встроена с версии 2.38), автоматически настраивающая набор функций для эффективного управления репозиториями уровня "монорепозиторий" (тысячи файлов и коммитов).

**Фоновое обслуживание (Background Maintenance)** — механизм Git для выполнения ресурсоемких задач (сжатие объектов, обновление графов коммитов) в фоновом режиме по расписанию, предотвращающий задержки при интерактивной работе.

**FSMonitor (File System Monitor)** — демон, отслеживающий изменения файлов на уровне ОС. Позволяет `git status` мгновенно определять измененные файлы без полного сканирования диска.

**Граф коммитов (Commit-Graph)** — бинарный файл-индекс (`.git/objects/info/commit-graph`), кэширующий метаданные коммитов для кратного ускорения навигации по истории и построения графов.

**Поверхностное клонирование (Shallow Clone)** — загрузка только последних $N$ коммитов истории.

**Частичное клонирование (Partial Clone)** — загрузка объектов (файлов или деревьев) только в момент обращения к ним, а не в процессе клонирования.

## Базовые концепции

### Проблемы масштабирования
При росте репозитория (монорепозитории) стандартный Git сталкивается с двумя узкими местами:
1.  **Объем данных:** Передача гигабайт истории по сети.
2.  **Сканирование диска:** Проверка состояния 100 000+ файлов при каждом вызове `git status`.

### Сводная таблица методов оптимизации

| Метод | Что ускоряет | Когда использовать |
| :--- | :--- | :--- |
| **Scalar** | Все операции в гигантских репозиториях | Рекомендуется для репозиториев >10 000 файлов. |
| **Background Maintenance** | Стабильность производительности | Всем пользователям для предотвращения "тормозов" `git gc`. |
| **FSMonitor** | `git status` и `git add` | Монорепозитории, медленные HDD или сетевые диски. |
| **Commit-Graph** | `git log`, `git branch --contains` | Глубокая история, сложные графы веток. |
| **Shallow Clone** | `git clone` (трафик и время) | Одноразовые CI/CD сборки. |
| **Partial Clone** | `git clone` (трафик) | Работа с частью монорепозитория. |
| **Sparse Checkout** | `checkout` и `status` | Когда нужны файлы только из определенных подпапок. |

## Практические сценарии

### Сценарий 1: Использование Scalar для крупных проектов
Scalar — это "лучшие практики в одну команду". Он включает частичное клонирование, фоновое обслуживание и Sparse Checkout.

```bash
# Клонирование нового репозитория через Scalar
scalar clone <url>

# Регистрация уже существующего репозитория в Scalar
cd <path_to_repo>
scalar register
```

### Сценарий 2: Фоновое обслуживание (Maintenance)
Позволяет избежать внезапных пауз на выполнение `git gc`.

```bash
# Запустить фоновое обслуживание по расписанию (hourly, daily, weekly)
git maintenance start

# Проверить текущие зарегистрированные задачи
git maintenance status
```

### Сценарий 3: Мгновенный статус (FSMonitor)
Критически важно для репозиториев с огромным количеством файлов.

```bash
# Включить встроенный монитор файловой системы
git config core.fsmonitor true

# Теперь git status будет отрабатывать почти мгновенно
git status
```

### Сценарий 4: Ускорение истории (Commit-Graph)
Ускоряет построение дерева коммитов и поиск по ним.

```bash
# Создать индекс графа коммитов (включая Bloom-фильтры для быстрого поиска по путям)
git commit-graph write --reachable --changed-paths

# Настроить автоматическое обновление графа при каждом получении данных
git config fetch.writeCommitGraph true
```

### Сценарий 5: Быстрая настройка через feature.manyFiles
Включает сразу несколько оптимизаций для работы с большим количеством файлов.

```bash
# Включает index.version=4, commit-graph и другие настройки
git config feature.manyFiles true
```

### Сценарий 6: Клонирование в CI/CD (Shallow & Partial)
Для минимизации времени сборки и нагрузки на сеть.

**Поверхностный клон (только последний коммит):**
```bash
git clone --depth 1 --no-tags <url>
```

**Blobless клон (история коммитов без файлов, файлы скачиваются при checkout):**
```bash
git clone --filter=blob:none <url>
```
*Этот метод лучше Shallow Clone для CI, если планируется выполнение `git merge` или `git cherry-pick`.*
