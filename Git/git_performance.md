# Git: Оптимизация производительности

## Определения

**Оптимизация производительности Git** — применение техник и команд для ускорения операций Git, особенно при работе с большими репозиториями или в условиях ограниченной сети.

**Поверхностное клонирование (Shallow Clone)** — техника клонирования, при которой загружается только часть истории коммитов (например, только последние N коммитов), а не весь репозиторий.

**Частичное клонирование (Partial Clone)** — механизм, позволяющий клонировать репозиторий без полного содержимого всех объектов (файлов или деревьев), загружая их по мере необходимости.

**Blobless Clone** — вид частичного клонирования, при котором загружается история коммитов и структура директорий (деревья), но не сами файлы (blobs). Файлы загружаются только при обращении к ним.

**Treeless Clone** — вид частичного клонирования, при котором загружается история коммитов и корневое дерево, но не вложенные деревья. Объекты деревьев и файлов загружаются при `checkout`.

**`git bundle`** — инструмент для упаковки репозитория или его части в один файл для удобной передачи, особенно в условиях отсутствия сети.

## Базовые концепции

### Проблемы производительности

При работе с большими Git-репозиториями или в средах с низкой пропускной способностью сети (например, CI/CD пайплайны), стандартные операции Git, такие как `git clone`, могут выполняться медленно и потреблять значительные ресурсы. Это происходит из-за того, что Git по умолчанию клонирует всю историю всех файлов.

### Методы оптимизации

| Метод | Что сокращает | Когда использовать |
| :--- | :--- | :--- |
| **Shallow Clone** | Глубину истории коммитов | CI/CD сборки, когда нужны только последние изменения |
| **Partial Clone** | Количество загружаемых объектов | Монорепозитории с большим количеством файлов |
| **Blobless Clone** | Загрузку файлов (blobs) | Когда нужна структура проекта, но не все файлы |
| **Treeless Clone** | Загрузку деревьев | Когда нужен только последний checkout |
| **git bundle** | Сетевые зависимости | Офлайн-передача, резервное копирование |
| **Git LFS** | Размер репозитория | Большие бинарные файлы (графика, видео) |

## Практические сценарии

### Сценарий 1: Поверхностное клонирование для CI/CD

```bash
# Клонировать только последний коммит (максимально быстро)
git clone --depth 1 <url_репозитория>

# Клонировать последние N коммитов
git clone --depth <N> <url_репозитория>

# Клонировать только определённую ветку
git clone --depth 1 --branch main <url_репозитория>
```

**Разворачивание поверхностной копии:**
```bash
# Получить полную историю после поверхностного клонирования
git fetch --unshallow
```

### Сценарий 2: Частичное клонирование для монорепозитория

```bash
# Treeless Clone — для работы с последними файлами
git clone --filter=tree:0 <url_репозитория>

# Blobless Clone — для работы со структурой без файлов
git clone --filter=blob:none <url_репозитория>

# Комбинированный фильтр
git clone --filter=blob:none:tree:0 <url_репозитория>
```

### Сценарий 3: Git Bundle для офлайн-передачи

```bash
# Создать бандл со всей историей
git bundle create repo.bundle --all

# Создать инкрементальный бандл (только новые коммиты)
git bundle create updates.bundle main ^origin/main

# Проверить содержимое бандла
git bundle verify repo.bundle

# Клонировать из бандла
git clone repo.bundle project-dir

# Применить бандл к существующему репозиторию
git pull repo.bundle main
```

### Сценарий 4: Оптимизация клонирования в CI/CD

Для GitHub Actions:
```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 1  # Поверхностное клонирование
```

Для GitLab CI:
```yaml
variables:
  GIT_DEPTH: 1  # Поверхностное клонирование
```

### Сценарий 5: Работа с большими бинарными файлами

Для репозиториев с графикой, видео, архивами используйте Git LFS:

```bash
# Установить LFS
git lfs install

# Отслеживать большие файлы
git lfs track "*.psd"
git lfs track "*.mp4"

# Закоммитить конфигурацию
git add .gitattributes
git commit -m "Configure LFS tracking"
```

Подробное руководство в [git_lfs.md](./git_lfs.md).
