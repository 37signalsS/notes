# Git LFS (Large File Storage)

## Определения

* **Git LFS (Large File Storage):** Расширение для Git, предназначенное для эффективного управления большими бинарными файлами (изображения, видео, датасеты). Оно заменяет реальные файлы в репозитории на текстовые указатели, сохраняя сами данные на удаленном LFS-сервере.

## Базовые концепции

### Механизм работы

Традиционный Git хранит полную историю всех версий каждого файла. Для тяжелых бинарных данных это приводит к экспоненциальному росту размера директории `.git`.

**Git LFS работает следующим образом:**
1. В локальном репозитории вместо файла `image.psd` (например, 500 МБ) хранится текстовый файл-указатель (около 100-200 байт).
2. Указатель содержит SHA-256 хеш оригинального файла.
3. При операциях `checkout` или `pull` Git LFS перехватывает запрос и скачивает нужную версию файла с LFS-сервера в локальный кэш (`.git/lfs/objects`).

### Преимущества

* **Производительность:** Клонирование репозитория происходит мгновенно, так как скачиваются только маленькие указатели.
* **Экономия места:** На диске разработчика находятся только те версии файлов, которые используются в текущем `checkout`.
* **Масштабируемость:** Позволяет хранить терабайты данных, не нарушая работу Git.

### Git LFS vs. Native Partial Clone

С развитием Git появилась альтернатива — **Partial Clone** (`git clone --filter=blob:none`).

| Характеристика | Git LFS | Git Partial Clone |
| :--- | :--- | :--- |
| **Тип** | Внешнее расширение | Нативная функция Git |
| **Хранение** | Отдельный LFS-сервер | Тот же Git-сервер |
| **Когда использовать** | Огромные бинарные файлы, которые редко меняются | Файлы, которые нужны Git для сборки, но не всегда нужны локально |
| **Сложность** | Требует настройки `.gitattributes` | Проще в использовании (просто флаг при клонировании) |

## Практические сценарии

### Установка и инициализация

```bash
# Установка хуков LFS в глобальный конфиг Git
git lfs install
# → Updated Git hooks.
# → Git LFS initialized.
```

### Отслеживание файлов

Правила отслеживания сохраняются в файле `.gitattributes`.

```bash
# Начать отслеживание всех PSD файлов
git lfs track "*.psd"
# → Tracking "*.psd"

# Добавить .gitattributes в индекс (обязательно для совместной работы)
git add .gitattributes
git commit -m "chore: configure LFS tracking for PSD files"
```

### Блокировка файлов (File Locking)

Бинарные файлы невозможно объединить (merge). Чтобы избежать конфликтов, используется механизм блокировки.

```bash
# Заблокировать файл для редактирования
git lfs lock design.psd
# → Locked design.psd

# Список всех заблокированных файлов
git lfs locks
# → design.psd  User Name  ID:123

# Разблокировать файл
git lfs unlock design.psd
# → Unlocked design.psd
```

### Оптимизация для CI/CD

В пайплайнах часто не нужны тяжелые файлы (например, если тестируется только код).

```bash
# Пропустить загрузку LFS-объектов при клонировании
export GIT_LFS_SKIP_SMUDGE=1
git clone https://github.com/user/repo.git
```

### Обслуживание и очистка

Локальный кэш LFS может быстро разрастись.

```bash
# Удалить старые LFS-объекты, на которые не ссылаются локальные коммиты
git lfs prune
# → 12.5 GB removed

# Проверить целостность локальных объектов
git lfs fsck
```

### Миграция существующих файлов

Если файлы уже находятся в истории Git, их нужно перенести через перезапись истории.

```bash
# Анализ истории на наличие тяжелых файлов
git lfs migrate info --everything --top=10

# Миграция всех ZIP и MP4 файлов во всех ветках
git lfs migrate import --everything --include="*.zip,*.mp4"
# → Rewriting commits...
# → Done!

# После миграции необходим force push
git push --force --all
```

## Дополнительная информация

### Полезные команды

```bash
# Показать переменные окружения и конфигурацию LFS
git lfs env
# → Endpoint=https://github.com/user/repo.git/info/lfs ...

# Список файлов, отслеживаемых LFS в текущей ветке
git lfs ls-files
# → 1a2b3c... * image.png

# Текущий статус загрузки/выгрузки
git lfs status

# Проверить объем занимаемого места
git lfs du -h
# → 1.2 GB  .git/lfs/objects
```
