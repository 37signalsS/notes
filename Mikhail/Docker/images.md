# **Docker-образы: от создания до распространения**

---

## **1. Что такое образ Docker?**

**Образ (Image)** — это неизменяемый (immutable) шаблон, который содержит все необходимое для запуска приложения: код, среду выполнения, библиотеки, переменные окружения и конфигурационные файлы. Образы состоят из слоев, доступных только для чтения, что обеспечивает эффективность хранения и переиспользования.

---

## **2. Жизненный цикл образа: основные команды**

| Команда | Описание |
| :--- | :--- |
| `docker build -t <имя>:<тег> .` | Собирает образ из `Dockerfile` в текущей директории. |
| `docker images` | Показывает все образы, имеющиеся на хосте. |
| `docker pull <имя>:<тег>` | Скачивает образ из registry (например, Docker Hub). |
| `docker push <имя>:<тег>` | Загружает образ в registry. |
| `docker rmi <имя>:<тег>` | Удаляет образ. |
| `docker tag <исходный> <целевой>` | Создает новый тег (алиас) для существующего образа. |
| `docker history <имя>:<тег>` | Показывает слои, из которых состоит образ, и команды их создания. |

---



### **None-образы**

Эти образы обычно появляются в двух ситуациях:

- После сборки нового образа с тем же именем и тегом
- Когда вы пересобираете образ с уже существующим именем (my-image:latest), старый образ становится `<none>`, потому что Docker сохраняет его слои, но он больше не связан с актуальным тегом.

**Промежуточные слои сборки (<none>, но с ID)**

При сборке Docker-образа создаются промежуточные слои. Они не имеют имени, но могут оставаться в системе, если:

- Сборка была прервана.
- Образ был удалён, но слои остались (из-за зависимостей других образов).

## **4. Очистка: "висячие" (dangling) и неиспользуемые образы**

**"Висячие" образы** (отображаются как `<none>:<none>`) — это слои, на которые больше не ссылается ни один тегированный образ. Чаще всего они появляются, когда вы пересобираете существующий образ с тем же тегом — старый образ теряет тег и становится "висячим".

| Команда | Описание |
| :--- | :--- |
| `docker images -f "dangling=true"` | Находит все "висячие" образы. |
| `docker image prune` | Удаляет все "висячие" образы. |
| `docker image prune -a` | Удаляет все неиспользуемые образы (те, на основе которых нет запущенных контейнеров). |

## **5. Продвинутые и нерекомендуемые практики**

### **Реверс-инжиниринг образов**

Если `Dockerfile` утерян, можно попытаться восстановить его из существующего образа. Эти утилиты анализируют слои образа и генерируют `Dockerfile`, который мог бы его создать. Они запускаются как Docker-контейнеры и требуют доступа к Docker-сокету.

- **[dduvnjak/dockerfile-from-image](https://github.com/dduvnjak/dockerfile-from-image)** 
  ```sh
  sudo docker run -v /var/run/docker.sock:/var/run/docker.sock --rm dduvnjak/dockerfile-from-image <IMAGE_ID>
  ```

- **[laniksj/dfimage](https://github.com/LanikSJ/dfimage)** 
  ```sh
  sudo docker run -v /var/run/docker.sock:/var/run/docker.sock --rm laniksj/dfimage <IMAGE_ID>
  ```

- **[mrhavens/dedockify](https://github.com/mrhavens/Dedockify)** 
  ```sh
  sudo docker run -v /var/run/docker.sock:/var/run/docker.sock --rm mrhavens/dedockify <IMAGE_ID>
  ```
---

### **`docker commit`: анти-паттерн для создания образов**

Команда `docker commit <контейнер> <новый_образ>` создает образ из текущего состояния контейнера. **Это плохая практика, потому что:**
- **Нарушает воспроизводимость:** Невозможно понять, как образ был создан, в отличие от `Dockerfile`.
- **Раздувает образ:** Включает в себя временные файлы, логи и другие артефакты, которые не нужны в финальном образе.
- **Скрывает историю:** Заменяет понятную историю слоев одной командой `commit`.

### **Объединение слоев (`--squash`)**

Флаг `docker build --squash` объединяет все слои, созданные в `Dockerfile`, в один. 
- **Плюс:** Может незначительно уменьшить размер финального образа.
- **Минус:** Полностью **уничтожает кэширование слоев**, что делает последующие сборки очень медленными.

Используйте эту опцию, только если каждый байт в итоговом образе критичен, и вы готовы пожертвовать скоростью сборки. 


### **Сохранение и загрузка образов (`save` и `load`)**

Эти команды используются для сохранения и загрузки образов целиком, включая все их слои и историю.

- **`docker save`**: Создает `.tar`-архив из одного или нескольких образов.
  ```sh
  docker save -o my_images.tar my-image:latest another-image:1.0
  ```

- **`docker load`**: Загружает образы из `.tar`-архива.
  ```sh
  docker load -i my_images.tar
  ```
---

### **Экспорт и импорт контейнеров (`export` и `import`)**

Эти команды работают с файловой системой контейнера, а не с образом.

- **`docker export`**: Создает `.tar`-архив файловой системы запущенного или остановленного контейнера. **История слоев при этом теряется.**
  ```sh
  docker export my-container > my_container.tar
  ```

- **`docker import`**: Создает новый образ из `.tar`-архива файловой системы.
  ```sh
  cat my_container.tar | docker import - my-new-image:latest
  ```
