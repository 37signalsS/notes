# **Логирование и мониторинг в Docker**

---

## **1. Логирование контейнеров**

### **Команда `docker logs`**

Основной инструмент для просмотра логов, которые приложение внутри контейнера выводит в `STDOUT` и `STDERR`.

| Команда | Описание |
| :--- | :--- |
| `docker logs <id_контейнера>` | Показать все логи для контейнера. |
| `docker logs -f <id_контейнера>` | Выводить логи в реальном времени (режим follow). |
| `docker logs --tail 30 <id_контейнера>` | Показать последние 30 строк логов. |
| `docker logs --since 10m <id_контейнера>` | Показать логи за последние 10 минут. |

### **Физическое расположение логов**

По умолчанию Docker использует лог-драйвер `json-file`. Логи для каждого контейнера хранятся на хост-машине в виде JSON-файлов.

- **Путь к файлу логов:** `/var/lib/docker/containers/<id_контейнера>/<id_контейнера>-json.log`

> **NOTE:** Управление логами (ротация, ограничение размера) настраивается через конфигурацию лог-драйвера в файле `daemon.json` или при запуске контейнера.

## **2. Мониторинг ресурсов**

### **Команда `docker stats`**

Предоставляет информацию об использовании ресурсов всеми запущенными контейнерами в реальном времени.

| Команда | Описание |
| :--- | :--- |
| `docker stats` | Показать динамическую статистику по CPU, памяти, сети и I/O для всех контейнеров. |
| `docker stats <id_контейнера>` | Показать статистику только для указанного контейнера. |
| `docker stats --no-stream` | Показать однократный снимок статистики и выйти. |

Данные для `docker stats` собираются из **cgroups** — механизма ядра Linux. Вы можете найти сырые метрики в псевдофайловой системе cgroups, например:
- **Память:** `/sys/fs/cgroup/memory/docker/<long_id>/memory.stat`
- **CPU:** `/sys/fs/cgroup/cpu/docker/<long_id>/cpuacct.stat`

### **Команда `docker system df`**

Показывает, сколько дискового пространства занимают компоненты Docker.

```bash
# Вывод команды покажет размер, занимаемый образами, контейнерами и томами
docker system df
```

## **3. Сбор метрик для Prometheus**

Для интеграции с системами мониторинга, такими как Prometheus, необходимо предоставлять метрики в специальном формате. Это можно сделать несколькими способами.

### **Метрики Docker Демона**

Сам Docker может отдавать метрики о своей работе. Для этого нужно отредактировать конфигурационный файл `/etc/docker/daemon.json`:

```json
{
  "metrics-addr": "0.0.0.0:9323",
  "experimental": true
}
```

После перезапуска демона метрики будут доступны по адресу `http://<хост>:9323/metrics`.

### **Метрики приложений**

Современные приложения часто имеют встроенную возможность отдавать метрики (например, через клиентские библиотеки Prometheus). Стандартным эндпоинтом для этого является `/metrics`. Вам нужно лишь опубликовать порт контейнера.

```yaml
# docker-compose.yml
services:
  my-app:
    image: my-awesome-app
    ports:
      - "8080:8080" # Порт приложения
      - "9090:9090" # Порт для метрик
```

### **Внешние экспортеры: cAdvisor**

Когда встроенных метрик демона недостаточно, используются внешние инструменты. **cAdvisor (Container Advisor)** от Google — самый популярный из них.

- **Назначение:** Собирает, агрегирует и предоставляет в удобном виде детальную информацию о потреблении ресурсов и производительности контейнеров.
- **Преимущества:** Дает гораздо больше метрик, чем `docker stats` или встроенный экспортер демона.
- **Запуск:** Обычно запускается как еще один Docker-контейнер.

*   [draganm/missing-container-metrics](https://github.com/draganm/missing-container-metrics)
*   [google/cadvisor](https://github.com/google/cadvisor)
