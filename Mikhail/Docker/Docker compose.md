Создает сеть между контейнерами и дает доступ между контейнерами по именам контейнеров. Рестартить не надо, изменения которые сделанных с volumes на хосте автоматически подтягиваются

Часто используется version: 2 так как с переходом на 3 версию часть функционала перенесли в docker swarm

```
name: taxi

services:
  web:
    build: .
    image: taxi
    restart: always
    env_file:
      - .env.production
    depends_on:
      - database:
        condition: service_healthy
    ports:
      - "100.64.0.13:3845:3000"
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://127.0.0.1:3000/api/health || exit 1"]
      interval: 2s
      start_period: 30s

  database:
    image: paradedb/paradedb
    restart: always
    ports:
      - "100.64.0.13:3856:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: IiQx4oSSM6JrjZHLf3pXNgBw7KTIjzRg
      POSTGRES_DB: taxi
      PGDATA: /database
    user: 0:0
    volumes:
      - /mnt/external1/taxi/database:/database
    healthcheck:
      test: ["CMD-SHELL", "sh -c 'pg_isready -U postgres -d taxi'"]
      interval: 10s
      timeout: 30s
      retries: 3
      start_period: 80s
```

Политики рестарта бывают:
no(по умолчанию, контейнер не будет перезапущен автоматически, если он завершится или завершится с ошибкой.),
on-failure:5(контейнер будет перезапущен только в случае завершения с ненулевым кодом выхода-ошибка, можно указать максимальное количество попыток перезапуска-5),
always(контейнер всегда будет перезапущен, независимо от причины завершения успешно или с ошибкой),
unless-stopped(контейнер будет перезапущен автоматически, если он был остановлен не вручную, например, из-за сбоя или перезагрузки Docker).

100.64.0.13:3845:3000 - 3845 внешний порт, доступен из клира; второй порт это порт в контейнере

start_period:: - время в течение которого проверка состояния не будет выполняться после старта контейнера, что позволяет базе данных инициализироваться.

volumes - Монтирует локальное (/mnt/external1/taxi/database) в контейнер в каталог /database.

depends_on - Зависимость старта от другого контейнера

user: 0:0 - Запуск от рута


```
 healthcheck:
      test: ["CMD-SHELL", "sh -c 'pg_isready -U postgres -d taxi'"]
      interval: 10s # Проверяет соединение каждые 10 секунд.
      timeout: 30s # Если проверка не проходит за 30 секунд, она считается неудачной.
      retries: 3 # Максимальное количество попыток — 3.
      start_period: 80s # Начальный период ожидания перед первой проверкой 80 секунд.

```


# **Обновление версии образа у запущенного контейнера**

В блоке services необходимо определить параметры deploy. Важным параметром здесь является order. Он указывает Docker сначала создать и запустить новый контейнер с обновлённой версией образа. После запуска нового контейнера трафик будет перенаправлен на него, а старый контейнер будет остановлен и удалён.

Эта конфигурация лучше всего работает в сочетании с опцией replicas, чтобы развернуть несколько экземпляров одного и того же контейнера и обеспечить высокую доступность.

```
deploy
  update_config:
    parallelism: 1
    delay: 10s
    order: start-first
```
