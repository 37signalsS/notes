# **Docker Compose: Оркестрация многоконтейнерных приложений**

### **`docker compose` (v2) vs. `docker-compose` (v1)**

- **`docker compose` (v2, без дефиса):** Современный плагин, интегрированный в Docker CLI. Написан на Go. 
- **`docker-compose` (v1, с дефисом):** Устаревшая версия, отдельный исполняемый файл на Python.

---

## **2. Пример файла `docker-compose.yml`**



```yaml
# Имя проекта, которое будет использоваться как префикс для контейнеров и сетей
name: taxi

services:
  # Сервис веб-приложения
  web:
    # Собрать образ из Dockerfile в текущей директории
    build: .
    # Имя для собранного образа
    image: taxi-app
    restart: always
    # Загрузить переменные окружения из файла
    env_file:
      - .env.production
    # Проброс портов: ХОСТ:КОНТЕЙНЕР
    ports:
      - "100.64.0.13:3845:3000"
    # Зависимость от другого сервиса
    depends_on:
      database:
        condition: service_healthy
    # Проверка состояния приложения
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://127.0.0.1:3000/api/health || exit 1"]
      interval: 2s
      start_period: 30s

  # Сервис базы данных
  database:
    image: paradedb/paradedb
    restart: always
    ports:
      - "100.64.0.13:3856:5432"
    # Переменные окружения напрямую в файле
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: IiQx4oSSM6JrjZHLf3pXNgBw7KTIjzRg
      POSTGRES_DB: taxi
      PGDATA: /database
    # Запуск от имени root (UID 0, GID 0)
    user: "0:0"
    # Монтирование тома для хранения данных
    volumes:
      - /mnt/external1/taxi/database:/database
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d taxi"]
      interval: 10s
      timeout: 30s
      retries: 3
      start_period: 80s
```

## **3. Ключевые директивы сервиса**

- `build` vs. `image`:
  - `image`: Указывает готовый образ из registry (например, Docker Hub).
  - `build`: Указывает путь к директории с `Dockerfile` для сборки образа локально.

- `ports`: Пробрасывает порты в формате `IP:ХОСТ_ПОРТ:КОНТЕЙНЕР_ПОРТ` или `ХОСТ_ПОРТ:КОНТЕЙНЕР_ПОРТ`.

- `volumes`: Монтирует директории или именованные тома в контейнер (`ХОСТ_ПУТЬ:КОНТЕЙНЕР_ПУТЬ`). Изменения в файлах на хосте мгновенно отражаются в контейнере.

- `environment` и `env_file`:
  - `environment`: Позволяет задать переменные окружения прямо в YAML-файле.
  - `env_file`: Загружает переменные из указанного файла (например, `.env`).

- `depends_on`: Определяет порядок запуска сервисов. В примере `web` не запустится, пока `database` не станет `healthy`.

- `user`: Запускает процесс внутри контейнера от имени указанного пользователя (`user:group` или `user`). Использование `user: "0:0"` (root) может быть небезопасно.

- `restart`: Определяет политику перезапуска контейнера.

| Политика | Описание |
| :--- | :--- |
| `no` | Не перезапускать (по умолчанию). |
| `on-failure` | Перезапускать только при завершении с ошибкой. Можно добавить `:<число_попыток>`. |
| `always` | Перезапускать всегда, кроме случаев, когда контейнер остановлен вручную. |
| `unless-stopped` | Перезапускать всегда, даже после перезагрузки демона, кроме остановки вручную. |

- `healthcheck`: Позволяет Docker проверять работоспособность приложения внутри контейнера.
  - `test`: Команда для проверки.
  - `interval`: Периодичность проверок.
  - `timeout`: Время ожидания ответа.
  - `retries`: Количество неудачных попыток до смены статуса на `unhealthy`.
  - `start_period`: Время, которое дается контейнеру на запуск до начала проверок.

## **4. Основные команды `docker compose`**

| Команда | Описание |
| :--- | :--- |
| `docker compose up` | Создает и запускает контейнеры. С флагом `-d` (detached) запускает в фоновом режиме. Флаг `--build` принудительно пересобирает образы. |
| `docker compose down` | Останавливает и удаляет контейнеры, сети. С флагом `-v` удаляет и тома (volumes). |
| `docker compose ps` | Показывает статус контейнеров, запущенных через Compose. |
| `docker compose logs` | Выводит логи сервисов. С флагом `-f` (follow) выводит логи в реальном времени. |
| `docker compose exec <сервис> <команда>` | Выполняет команду внутри работающего контейнера (например, `docker compose exec web sh`). |
| `docker compose run <сервис> <команда>` | Запускает новый контейнер для выполнения одноразовой команды. |
| `docker compose build` | Собирает или пересобирает образы для сервисов. |
| `docker compose pull` | Скачивает последние версии образов для сервисов. |
| `docker compose config` | Проверяет и отображает итоговую конфигурацию после применения всех переменных и шаблонов. |

## **5. Продвинутые темы**

- **Масштабирование:** Можно запустить несколько экземпляров одного сервиса:
  ```sh
  docker compose up -d --scale <имя-сервиса>=<количество>
  ```

- **Секция `deploy`:** Используется для определения конфигурации развертывания в **Docker Swarm**, например, для настройки стратегии обновлений (`update_config`) или количества реплик. Большинство этих опций игнорируются обычным `docker compose up`.
