- **Lower layer(s)** : Только для чтения (например, базовый образ контейнера).
- **Upper layer** : Для записи (изменения, созданные в контейнере).
- **Merged view** : Объединённое представление всех слоёв, которое видит пользователь или процесс.
# **Как OverlayFS используется в Docker?**

Docker использует OverlayFS как один из драйверов хранилища (storage driver). 

- **Структура слоёв:**
    - **Base layer (нижний слой):** Содержит только для чтения данные из базового образа (например, `ubuntu:latest`).
    - **Upper layer (верхний слой):** Содержит все изменения, сделанные в контейнере (например, создание файлов, изменение конфигураций).
    - **Work directory:** Временная директория, используемая OverlayFS для внутренних операций.
    - **Merged directory:** Объединённое представление всех слоёв, которое монтируется в контейнер.
    
- **Пример пути к слоям Docker:**
    - Docker хранит слои в каталоге `/var/lib/docker/overlay2/`.
    - Каждый слой представлен отдельной директорией.

# **Как работает изменение данных в OverlayFS?**

- **Copy-on-write (CoW):**
    
    - Если процесс в контейнере пытается изменить файл из нижнего слоя, этот файл копируется в верхний слой, и изменения применяются только к копии. Это называется **copy-on-write** .
    - Благодаря этому механизм не затрагивает оригинальные данные в нижнем слое, что делает работу с образами эффективной.
- **Пример:**
    
    - Нижний слой содержит файл `/etc/nginx/nginx.conf`.
    - Если вы изменяете этот файл в контейнере, он копируется в верхний слой, и изменения применяются там. Нижний слой остаётся неизменным.
