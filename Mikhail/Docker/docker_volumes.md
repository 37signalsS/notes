# **Управление данными в Docker: Volumes, Bind Mounts и tmpfs**

--- 

## **1. Почему данные нужно хранить отдельно?**

Контейнеры по своей природе **эфемерны** (временны). Когда контейнер удаляется, все данные, созданные внутри его записываемого слоя, теряются навсегда. Для приложений, которым необходимо сохранять состояние (базы данных, загруженные файлы, логи), такой подход неприемлем.

Docker решает эту проблему, позволяя хранить данные **вне контейнера**, на хост-машине. Для этого существует три основных механизма.

--- 

## **2. Сравнение способов хранения данных**

| Характеристика | Docker Volumes | Bind Mounts | tmpfs Mounts |
| :--- |
| **Где хранятся** | Директория на хосте, управляемая Docker (`/var/lib/docker/volumes/`) | Любой файл или директория на хосте | В оперативной памяти (RAM) хоста |
| **Управление** | Через Docker CLI (`docker volume ...`) | Вручную пользователем | Управляется Docker, но временно |
| **Персистентность** | **Да.** Сохраняются после удаления контейнера | **Да.** Файлы остаются на хосте | **Нет.** Исчезают при остановке контейнера |
| **Основной сценарий**| Хранение данных приложений (БД, статика) | Разработка, проброс конфигов | Хранение временных, некритичных данных |
| **Безопасность** | Высокая. Данные изолированы | Низкая. Возможны конфликты прав доступа | Высокая. Данные не пишутся на диск |

--- 

## **3. Docker Volumes (Рекомендуемый способ)**

**Volume (том)** — это директория на хосте, которой полностью управляет Docker. Это предпочтительный способ для хранения персистентных данных.

**Ключевые преимущества:**
- **Независимость:** Тома существуют отдельно от жизненного цикла контейнера.
- **Безопасность:** Данными управляет Docker, что предотвращает случайное изменение из других процессов.
- **Переносимость:** Легко бэкапить, мигрировать и использовать совместно с другими контейнерами.

**Пример: Запуск PostgreSQL с именованным томом**

```sh
# 1. Создаем именованный том
docker volume create postgres-data

# 2. Запускаем контейнер, монтируя том в директорию данных PostgreSQL
docker run --name my-postgres-db -d \
    -e POSTGRES_PASSWORD=mysecretpassword \
    --mount type=volume,source=postgres-data,target=/var/lib/postgresql/data \
    postgres:14
```
- `--mount type=volume,source=postgres-data,target=/var/lib/postgresql/data`: Мы монтируем том `postgres-data` в директорию `/var/lib/postgresql/data` внутри контейнера.
- Краткий синтаксис (более старый, но популярный): `-v postgres-data:/var/lib/postgresql/data`.

### **Команды для управления томами**

| Команда | Описание |
| :--- | :--- |
| `docker volume create <имя>` | Создать новый том. |
| `docker volume ls` | Показать все тома. |
| `docker volume inspect <имя>` | Показать детальную информацию о томе (включая путь на хосте). |
| `docker volume rm <имя>` | Удалить том. |
| `docker volume prune` | Удалить все неиспользуемые тома. |

## **4. Bind Mounts**

**Bind Mount** — это прямое монтирование файла или директории с хост-машины в контейнер. 

**Основное применение:**
- **Разработка:** Проброс исходного кода в контейнер для "живой" перезагрузки.
- **Конфигурация:** Передача конфигурационных файлов (например, `nginx.conf`).

**Пример: Проброс исходного кода**

```sh
# Монтируем текущую директорию (pwd) в /app внутри контейнера
docker run -d --name my-app \
  --mount type=bind,source="$(pwd)",target=/app \
  node:18-alpine
```
- **Внимание:** Bind mounts могут создавать проблемы с правами доступа, так как UID/GID пользователя на хосте может не совпадать с UID/GID внутри контейнера.

--- 

## **5. tmpfs Mounts (Для временных данных)**

**tmpfs** монтирует директорию в оперативную память хоста. Данные не записываются на диск и исчезают при остановке контейнера.

**Основное применение:**
- Хранение временных файлов или секретов, которые не должны оставаться на диске.

**Пример:**

```sh
docker run -d --name temp-work \
  --mount type=tmpfs,destination=/app/cache \
  nginx:latest
```

--- 

## **6. Лучшие практики**

1.  **Предпочитайте Volumes:** Для данных приложений (базы данных, загрузки) всегда используйте именованные тома. Они более предсказуемы и безопасны.
2.  **Используйте Bind Mounts для разработки:** Они идеальны для проброса исходного кода и конфигураций, но не для данных.
3.  **Указывайте абсолютные пути:** Для `bind mounts` всегда используйте абсолютные пути, чтобы избежать неоднозначности.
4.  **Не изменяйте данные в томах напрямую:** Управляйте данными через контейнеры или официальные утилиты (например, `pg_dump`), а не путем прямого редактирования файлов в `/var/lib/docker/volumes/`.
5.  **`--volumes-from` устарело:** Ранее этот флаг использовался для совместного использования томов. Современный подход — монтировать один и тот же именованный том к нескольким контейнерам.
