# **OverlayFS: Слоеная файловая система Docker**

---

## **1. Что такое OverlayFS?**

**OverlayFS** — это современная **объединяющая файловая система** (union filesystem), которую Docker использует в качестве основного драйвера хранения (`storage driver`). Она позволяет "накладывать" одну файловую систему поверх другой. Результат — объединенное представление, в котором видны файлы и директории из всех слоев.

- **Структура слоёв:**
    - **Base layer (нижний слой):** Содержит только для чтения данные из базового образа (например, `ubuntu:latest`).
    - **Upper layer (верхний слой):** Содержит все изменения, сделанные в контейнере (например, создание файлов, изменение конфигураций).
    - **Work directory:** Временная директория, используемая OverlayFS для внутренних операций.
    - **Merged directory:** Объединённое представление всех слоёв, которое монтируется в контейнер.

---

## **2. Принцип Copy-on-Write (CoW)**

- **Чтение файла:** Если процесс читает файл, который существует только в `lowerdir`, он считывается напрямую без каких-либо накладных расходов.

- **Изменение файла:**
  1.  Процесс пытается изменить файл, существующий в `lowerdir`.
  2.  OverlayFS перехватывает эту операцию.
  3.  Файл **копируется** из `lowerdir` в `upperdir`.
  4.  Все дальнейшие изменения записываются в копию файла в `upperdir`.
  5.  Оригинальный файл в `lowerdir` остается нетронутым.

- **Удаление файла:**
  1.  Процесс пытается удалить файл, существующий в `lowerdir`.
  2.  Файл не удаляется физически. Вместо этого в `upperdir` создается специальный файл-маркер (**whiteout**), который скрывает оригинальный файл.
  3.  В объединенном представлении (`merged`) файл больше не виден.

---

## **3. Как OverlayFS используется в Docker?**

- **Слои образа → `lowerdir`**
  Все слои Docker-образа (из `Dockerfile`) монтируются как нижние слои (`lowerdir`), доступные только для чтения.

- **Слой контейнера → `upperdir`**
  При запуске контейнера (`docker run`) Docker создает для него новый пустой верхний слой (`upperdir`), куда будут записываться все изменения.

- **Файловая система контейнера → `merged`**
  То, что видит процесс внутри контейнера, — это и есть объединенное представление (`merged`), которое прозрачно объединяет неизменяемый образ и записываемый слой контейнера.

**Где это хранится?**

Docker хранит все слои, рабочие директории и объединенные представления в директории `/var/lib/docker/overlay2/`.
Каждый слой представлен отдельной директорией.

---

## **4. Преимущества для Docker**

1.  **Эффективность хранения:** Если у вас есть 10 контейнеров, запущенных из одного образа, его слои хранятся на диске только в одном экземпляре. Записываются только уникальные изменения для каждого контейнера.

2.  **Быстрый запуск контейнеров:** Docker не нужно копировать всю файловую систему. Он просто создает новый пустой `upperdir`, что занимает миллисекунды.

3.  **Неизменяемость образов (Immutability):** Механизм CoW гарантирует, что базовые образы никогда не изменяются, что делает окружение предсказуемым и стабильным.
