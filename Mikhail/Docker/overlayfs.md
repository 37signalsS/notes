# **OverlayFS: Слоеная файловая система Docker**

---

## **1. Ключевая идея: слои и объединение**

**OverlayFS** — это современная **объединяющая файловая система** (union filesystem), которую Docker использует по умолчанию. Она позволяет "накладывать" одну файловую систему поверх другой, создавая единое представление из нескольких слоев.

Представьте, что вы накладываете друг на друга прозрачные пленки:
- **Нижние слои (`lowerdir`)**: Это базовые пленки с исходным изображением (например, ОС Ubuntu). Они доступны **только для чтения**.
- **Верхний слой (`upperdir`)**: Это прозрачная пленка поверх остальных, на которой вы можете рисовать. Все изменения (создание, изменение, удаление файлов) записываются именно сюда.
- **Объединенное представление (`merged`)**: То, что вы видите в итоге — объединенное изображение со всех пленок. Это и есть файловая система внутри вашего контейнера.

```
+---------------------------------+
| Merged View (ФС Контейнера)     | <--- То, что вы видите
+---------------------------------+
               ^
 (запись идет в upperdir)
               |
+---------------------------------+
| Upperdir (Слой контейнера R/W)  | <--- Все изменения здесь
+---------------------------------+
| Lowerdir 1 (Слой образа RO)     | <--- Неизменяемые слои
+---------------------------------+
| Lowerdir 2 (Слой образа RO)     |
+---------------------------------+
```

---

## **2. Принцип Copy-on-Write (CoW)**

OverlayFS эффективно управляет файлами благодаря механизму **"Копирование при записи" (Copy-on-Write)**.

- **Чтение файла**: Если файл существует только в нижних слоях (`lowerdir`), он считывается напрямую без каких-либо накладных расходов. Это очень быстро.

- **Изменение файла**:
  1. Когда процесс пытается изменить файл из `lowerdir`, OverlayFS перехватывает операцию.
  2. Файл **копируется** из `lowerdir` в `upperdir` (этот процесс называется **copy up**).
  3. Все дальнейшие изменения записываются в копию файла в `upperdir`.
  4. Оригинальный файл в `lowerdir` остается нетронутым.

- **Удаление файла**:
  1. Когда процесс удаляет файл из `lowerdir`, он не стирается физически.
  2. Вместо этого в `upperdir` создается специальный файл-маркер (**whiteout**), который просто скрывает оригинальный файл.
  3. В объединенном представлении (`merged`) файл больше не виден.

---

## **3. Как OverlayFS используется в Docker**



- **Слои образа → `lowerdir`**: Все слои Docker-образа (из `Dockerfile`) монтируются как нижние слои (`lowerdir`), доступные **только для чтения**.
- **Слой контейнера → `upperdir`**: При запуске контейнера (`docker run`) Docker создает для него новый пустой верхний слой (`upperdir`), куда будут записываться все изменения.
- **Файловая система контейнера → `merged`**: То, что видит процесс внутри контейнера, — это и есть объединенное представление (`merged`), которое прозрачно объединяет неизменяемый образ и записываемый слой контейнера.

**Где это хранится?**
Docker хранит все слои и директории в `/var/lib/docker/overlay2/`. Каждому слою и контейнеру соответствует своя директория.

---

## **4. Преимущества для Docker**

1.  **Экономия места на диске**: Если у вас есть 10 контейнеров, запущенных из одного образа, его слои хранятся на диске **в одном экземпляре**. Записываются только уникальные изменения для каждого контейнера.

2.  **Мгновенный запуск контейнеров**: Docker не нужно копировать всю файловую систему. Он просто создает новый пустой `upperdir`, что занимает миллисекунды.

3.  **Гарантия неизменяемости (Immutability)**: Механизм CoW гарантирует, что базовые образы никогда не изменяются, что делает окружение предсказуемым и стабильным.
