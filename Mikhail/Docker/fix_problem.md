# **Docker: Справочник команд и руководство по отладке**

---

## **1. Справочник команд**

### **1.1. Контейнеры**

**Жизненный цикл:**
| Команда | Описание |
| :--- | :--- |
| `docker run <образ>` | Создает и запускает контейнер. `-d` — фоновый режим. `--rm` — удалить после завершения. |
| `docker start <контейнер>` | Запускает остановленный контейнер. |
| `docker stop <контейнер>` | Корректно останавливает контейнер (`SIGTERM`, затем `SIGKILL`). |
| `docker restart <контейнер>` | Перезапускает контейнер. |
| `docker pause / unpause` | "Замораживает" и "размораживает" все процессы в контейнере. |
| `docker rm <контейнер>` | Удаляет остановленный контейнер. `-f` — принудительно. |

**Получение информации:**
| Команда | Описание |
| :--- | :--- |
| `docker ps` | Показывает запущенные контейнеры. `-a` — все. |
| `docker logs <контейнер>` | Показывает логи. `-f` — в реальном времени. `--tail N` — последние N строк. |
| `docker inspect <контейнер>` | Выводит подробную информацию в JSON (IP-адрес, тома, сети). |
| `docker stats <контейнер>` | Показывает потребление ресурсов (CPU, RAM, сеть) в реальном времени. |
| `docker top <контейнер>` | Показывает процессы, запущенные внутри контейнера. |
| `docker port <контейнер>` | Отображает маппинг портов контейнера на порты хоста. |

**Взаимодействие:**
| Команда | Описание |
| :--- | :--- |
| `docker exec -it <контейнер> <команда>` | Выполняет команду внутри работающего контейнера (например, `bash`). |
| `docker attach <контейнер>` | Подключается к основному процессу (PID 1) контейнера. |
| `docker cp <откуда> <куда>` | Копирует файлы между хостом и контейнером. |
| `docker update --memory 1G <контейнер>` | Динамически обновляет ресурсы работающего контейнера. |

### **1.2. Образы**

| Команда | Описание |
| :--- | :--- |
| `docker images` или `docker image ls` | Показывает все образы на хосте. |
| `docker build -t <имя>:<тег> .` | Собирает образ из `Dockerfile` в текущей директории. |
| `docker pull <образ>:<тег>` | Скачивает образ из registry. |
| `docker push <образ>:<тег>` | Загружает образ в registry. |
| `docker rmi <образ>` | Удаляет образ. |
| `docker history <образ>` | Показывает слои, из которых состоит образ. |

### **1.3. Сети и Тома**

| Команда | Описание |
| :--- | :--- |
| `docker network ls` | Показывает сети. |
| `docker network inspect <сеть>` | Выводит подробную информацию о сети. |
| `docker volume ls` | Показывает тома. |
| `docker volume inspect <том>` | Выводит подробную информацию о томе. |

## **2. Очистка системы**

| Команда | Описание |
| :--- | :--- |
| `docker container prune` | Удаляет все остановленные контейнеры. |
| `docker image prune` | Удаляет "висячие" образы. `-a` — все неиспользуемые. |
| `docker volume prune` | Удаляет неиспользуемые тома. |
| `docker network prune` | Удаляет неиспользуемые сети. |
| `docker system prune` | **Основная команда.** Удаляет все неиспользуемые объекты. `-a` — удалит и неиспользуемые образы. `--volumes` — удалит и тома. |

## **3. Руководство по отладке**

### **3.1. Доступ к контейнеру с помощью `nsenter` (когда `docker exec` не работает)**

**Проблема:** Контейнер завис, не отвечает, либо в нем отсутствует оболочка (`/bin/sh`, `/bin/bash`), что делает невозможным использование `docker exec`.

**Шаг 1: Запустите контейнер с доступом к PID-пространству хоста**

Флаг `--pid=host` позволяет процессам внутри контейнера видеть все процессы на хост-машине. Это необходимо, чтобы `nsenter` мог найти нужный процесс.

```sh
docker run -d --pid=host --name my-app my-image
```

**Решение:**

Использовать утилиту `nsenter`, чтобы попасть внутрь пространства имён (namespaces) контейнера напрямую, в обход `docker exec`. Это спасает, если контейнер завис или внутри нет `bash`/`sh`.

**Шаг 1: Узнаём PID контейнера**

```bash
# Узнаём PID контейнера
docker inspect --format '{{.State.Pid}}' <container_id>
```

**Шаг 2: Подключаемся напрямую к его namespace**

```bash
# Подключаемся напрямую к его namespace
nsenter --target <PID> --mount --uts --ipc --net --pid
```

По умолчанию nsenter запустит оболочку, указанную в переменной окружения $SHELL пользователя, от которого вы выполняете nsenter. Теперь вы внутри окружения контейнера, как в обычном `chroot`. 


### Отладка контейнеров без shell и root (`distroless`)

Использование образов без оболочки (`/bin/sh`) и без `root` пользователя (например, `distroless`) — это лучшая практика для создания безопасных и минималистичных контейнеров. Однако это усложняет отладку, так как стандартный `docker exec -it <container> /bin/sh` не работает.

Вот несколько эффективных способов для отладки таких контейнеров:

#### **1. `docker exec` с указанием другого пользователя и shell**

Если в образе все же есть shell, но он запускается от пользователя без прав, вы можете попробовать запустить его от имени `root` (если это возможно).

```sh
docker exec -it --user root <container_name> /bin/sh
```

#### **2. Создание эфемерного отладочного контейнера**

Это самый чистый и рекомендуемый подход. Вы запускаете временный контейнер с полным набором инструментов (например, `ubuntu` или `alpine`) в тех же пространствах имён, что и ваш основной контейнер.

-   **Сетевое пространство имён:** Позволяет слушать трафик, проверять открытые порты (`netstat`, `ss`). 
    ```sh
docker run -it --rm --network=container:<target_container_name> nicolaka/netshoot
    ```
    *`nicolaka/netshoot` — это специальный образ, содержащий огромное количество сетевых утилит.*

-   **Пространство имён процессов (PID):** Позволяет видеть и отлаживать процессы целевого контейнера (`ps`, `top`, `strace`). 
    ```sh
docker run -it --rm --pid=container:<target_container_name> alpine
    ```

#### **3. `docker cp` для копирования файлов**

Вы можете копировать логи, конфигурационные файлы или даже бинарные файлы из работающего контейнера на хост для их анализа.

```sh
docker cp <container_name>:/path/to/logfile.log /local/path/logfile.log
```

#### **4. `docker debug` (экспериментальная возможность)**

В новых версиях Docker появляется команда `docker debug`, которая упрощает процесс создания отладочных контейнеров. Она автоматически создает копию вашего контейнера, но с возможностью переопределить `entrypoint` или добавить отладочные инструменты.

```sh
# Эта команда создаст копию контейнера, но вместо его ENTRYPOINT запустит /bin/sh
docker debug my-app -it --image=alpine --entrypoint=/bin/sh
```

**Решение 3: Копирование файлов с помощью `docker cp`**
Если вам нужно проанализировать логи или конфигурационные файлы, просто скопируйте их на хост.
```sh
docker cp my-app:/path/to/logfile.log /local/path/logfile.log
```

### **3.3. Ошибка `file not found` в Alpine для скомпилированного бинарного файла**

**Проблема:** Бинарный файл, скомпилированный в Ubuntu/Debian, не запускается в Alpine с ошибкой `file not found` или `error while loading shared libraries`.

**Причина:** Несовместимость стандартных библиотек C. В большинстве дистрибутивов используется `glibc`, а в Alpine — легковесная `musl libc`.

**Решение 1 (Лучшее): Пересобрать приложение в Alpine.**
Используйте многоэтапную сборку, где на первом этапе вы компилируете приложение внутри `alpine`-образа.

**Решение 2 (Компромисс): Установить `glibc` в Alpine.**
Это "грязный", но иногда необходимый способ.
```dockerfile
FROM alpine:3.18

# Устанавливаем пакет совместимости с glibc
ENV GLIBC_VERSION="2.35-r1"
RUN apk add --no-cache wget ca-certificates && \
    wget -q -O /etc/apk/keys/sgerrand.rsa.pub https://alpine-pkgs.sgerrand.com/sgerrand.rsa.pub && \
    wget "https://github.com/sgerrand/alpine-pkg-glibc/releases/download/${GLIBC_VERSION}/glibc-${GLIBC_VERSION}.apk" && \
    apk add --no-cache glibc-${GLIBC_VERSION}.apk && rm -f glibc-*.apk

# Теперь можно запускать glibc-совместимые приложения
COPY ./my-glibc-app /usr/local/bin/
CMD ["my-glibc-app"]
```

### **3.4. Использование своих alias'ов в контейнере**

**Проблема:** Ваши привычные alias'ы и функции из `~/.bashrc` не работают внутри контейнера.

**Решение:** Смонтировать `bashrc` с хоста в контейнер при запуске.

```sh
docker run -it \
  -v ~/.bashrc:/root/.bashrc \
  --env BASH_ENV=/root/.bashrc \
  ubuntu bash
```

### **Подключение к контейнеру (`attach`)**

Команда `docker attach` подключает ваш терминал к стандартному вводу/выводу/ошибкам (STDIN/STDOUT/STDERR) основного процесса (PID 1) в контейнере.

```sh
docker attach <container_name>
```

**Важно:** Если вы выйдете из сессии `attach` с помощью `Ctrl+C`, это отправит сигнал `SIGKILL` и остановит контейнер. Чтобы отсоединиться, не останавливая контейнер, используйте последовательность `Ctrl+P`, `Ctrl+Q`.
### **Инспекция объектов (`inspect`)**

`docker inspect` предоставляет подробную информацию о любом объекте Docker (контейнере, образе, томе, сети) в формате JSON.

```sh
# Получить IP-адрес контейнера
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' my-container
```
### **История образа (`history`)**

`docker history` показывает все слои, из которых состоит образ, их размер и команды, которыми они были созданы. Это очень полезно для анализа и оптимизации `Dockerfile`.

```sh
docker history my-image:latest
```
