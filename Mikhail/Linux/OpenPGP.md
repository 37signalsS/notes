OpenPGP - это протокол и спецификация, описывающая механизм, использующий преимущественно асимметричные алгоритмы для шифрования, подписи и дешифрования сообщений.

**GnuPG (GPG)** - это приложение, реализующее спецификацию OpenPGP.

---

## Асимметричная криптография

Концепция асимметричного шифрования заключается в использовании двух ключей:

-   **Приватный ключ:** Используется для создания подписей и расшифровки сообщений. **Его необходимо хранить в секрете.**
-   **Публичный ключ:** Производный от приватного, он используется для проверки подписей и шифрования сообщений для владельца приватного ключа. Его можно свободно распространять.

### Асимметричная криптография в PGP

В PGP для подтверждения подлинности личности используется **Сеть доверия (Web of Trust, WoT)**. Вместо централизованных удостоверяющих центров (CA), каждый участник сам решает, кому доверять, подписывая публичные ключи других пользователей.

Чтобы избежать необходимости перестраивать всю сеть доверия при компрометации ключа, в PGP используется система **мастер-ключей** и **саб-ключей (подключей)**:

-   **Мастер-ключ (сертификационный ключ):**
    -   Используется только для управления связкой: подписи и отзыва саб-ключей, а также для подписи ключей других людей.
    -   **Хранится в безопасном, изолированном месте (офлайн).**
    -   Имеет срок истечения.
    -   Для него создается **сертификат отзыва** на случай компрометации.

-   **Саб-ключи (подключи):**
    -   Используются для повседневных операций: шифрования, подписи, аутентификации.
    -   Подписываются мастер-ключом.
    -   Могут быть отозваны мастер-ключом без необходимости отзывать всю связку.

### Конфигурация

Создайте или отредактируйте файл `~/.gnupg/gpg.conf`:

```ini
keyid-format short
throw-keyids
no-emit-version
no-comments
```

## Создание связки ключей

### 1. Генерация ключей

Для полного контроля над процессом используйте команду:

```sh
gpg --full-generate-key --expert
```

-   **Выберите тип ключа:** Рекомендуется `(9) ECC (sign and encrypt)`.
-   **Выберите кривую:** Рекомендуется `(1) Curve 25519`.
-   **Установите срок действия:** Рекомендуется установить срок (например, `2y` - 2 года), его можно будет изменить позже.
-   **Введите данные (UID):** Имя, Email. Эти данные будут привязаны к вашему ключу.

### 2. Редактирование ключей и добавление саб-ключей

Войдите в режим редактирования:

```sh
gpg --edit-key --expert <Ваш_UserID_или_KeyID>
```

Внутри редактора (`gpg>`) рекомендуется добавить отдельные саб-ключи для подписи и аутентификации:

1.  **Добавить ключ:** `addkey`
2.  **Ключ для подписи:** Выберите `(10) ECC (sign only)`, кривую `25519` и срок действия (например, `2m` - 2 месяца).
3.  **Ключ для аутентификации:**
    -   Выберите `(11) ECC (set your own capabilities)`.
    -   Отключите `Sign` (S) и включите `Authenticate` (A).
    -   Установите срок действия.

После всех операций сохраните изменения командой `save`.

### 3. Экспорт ключей и сертификата отзыва

-   **Публичный ключ (для всех):**
    ```sh
    gpg --export -a <UserID> > public_key.asc
    ```
-   **Приватные саб-ключи (для ваших устройств):**
    ```sh
    gpg --export-secret-subkeys -a <UserID> > private_subkeys.asc
    ```
-   **Приватный мастер-ключ (для бэкапа):**
    ```sh
    gpg --export-secret-keys -a <UserID> > private_master_key.asc
    ```
-   **Сертификат отзыва (на случай компрометации):**
    ```sh
    gpg -a --gen-revoke <UserID> > revocation_certificate.asc
    ```

**ВАЖНО:** Храните **мастер-ключ** и **сертификат отзыва** в разных, очень надежных и изолированных местах (например, на зашифрованных флешках в сейфе).

### 4. Удаление мастер-ключа из связки

После создания бэкапов удалите мастер-ключ с рабочего компьютера, чтобы использовать только саб-ключи.

```sh
# Укажите ID именно мастер-ключа с восклицательным знаком!
gpg --delete-secret-key <MasterKeyID>!
```

## Работа с GPG

### Импорт ключей

```sh
# Импорт публичных, приватных ключей или сертификатов отзыва
gpg --import <file.asc>
```

### Криптографические подписи

-   **Создать "чистую" подпись (текст виден):**
    ```sh
    gpg --clear-sign file.txt
    ```
-   **Создать отдельную подпись (для бинарных файлов):**
    ```sh
    gpg --detach-sign -a file.zip
    ```
-   **Проверить подпись:**
    ```sh
    # Для --detach-sign
    gpg --verify file.zip.asc file.zip
    # Для --clear-sign или --sign
    gpg --decrypt signed_file.asc
    ```

### Шифрование

-   **Асимметричное шифрование (для получателя):**
    ```sh
    # -e - encrypt, -r - recipient, -a - armored (text)
    gpg -e -a -r <Recipient_UserID> file.txt
    ```
-   **Шифрование с подписью:**
    ```sh
    gpg -e -a -s -r <Recipient_UserID> file.txt
    ```
-   **Симметричное шифрование (по паролю):**
    ```sh
    # -c - symmetric cipher
    gpg -c -a file.txt
    ```
-   **Расшифровка:**
    ```sh
    gpg -d file.txt.asc
    # или
    gpg --decrypt file.txt.asc
    ```

## Сервера ключей

Сервера ключей (`keys.openpgp.org`, `keyserver.ubuntu.com`) используются для публикации и синхронизации публичных ключей.

-   **Настроить сервер по умолчанию в `~/.gnupg/gpg.conf`:**
    ```ini
    keyserver hkps://keys.openpgp.org
    ```
-   **Отправить свой ключ на сервер:**
    ```sh
    gpg --send-keys <UserID>
    ```
-   **Получить ключ с сервера:**
    ```sh
    gpg --recv-keys <UserID_или_KeyID>
    ```
-   **Обновить все ваши ключи с сервера:**
    ```sh
    gpg --refresh-keys
    ```

## Интеграции

### Подпись коммитов в Git

1.  **Настройте Git:**
    ```ini
    # ~/.gitconfig
    [user]
      email = ваш_email_из_uid
      name = ваше_имя
      signingkey = <ID_ключа_подписи>!
    ```
2.  **Подписывайте коммиты:**
    ```sh
    git commit -S -m "Мой подписанный коммит"
    ```
3.  **Включить подпись по умолчанию:**
    ```sh
    git config --global commit.gpgsign true
    ```

### Аутентификация по SSH

GPG-Agent может заменить ssh-agent.

1.  **Включите поддержку SSH в `~/.gnupg/gpg-agent.conf`:**
    ```
    enable-ssh-support
    ```
2.  **Добавьте keygrip вашего ключа аутентификации в `~/.gnupg/sshcontrol`:**
    ```sh
    # Получить keygrip
    gpg -K --with-keygrip <AuthKeyID>!
    # Добавить keygrip в файл
    echo "ВАШ_KEYGRIP" >> ~/.gnupg/sshcontrol
    ```
3.  **Настройте переменные окружения** в вашем `.bashrc` или `.zshrc` для использования сокета gpg-agent.
4.  **Экспортируйте публичный SSH-ключ** и добавьте его на сервер в `~/.ssh/authorized_keys`:
    ```sh
    gpg --export-ssh-key <AuthKeyID>!
    ```
