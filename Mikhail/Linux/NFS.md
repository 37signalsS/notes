# NFS (Network File System)

**NFS (сетевая файловая система)** — это протокол, который позволяет монтировать файловые системы удалённого хоста и работать с ними так, как если бы они были локальными. Это обеспечивает централизованное хранение данных и удобный доступ к ним с различных машин в сети.

## Компоненты NFS

Для работы NFS необходимы несколько ключевых компонентов:

-   **Поддержка ядром:** Ядро Linux должно поддерживать файловую систему NFS.
-   **RPC (Remote Procedure Call):** NFS использует удалённые вызовы процедур для обмена данными между клиентом и сервером.
-   **Portmap (или rpcbind):** Эта служба сопоставляет запросы RPC с соответствующими службами NFS. Когда процесс RPC запускается, он сообщает `portmap` свой номер порта. Клиент сначала обращается к `portmap`, который перенаправляет его на нужный порт службы.

Доступ к `portmap` можно контролировать с помощью файлов `/etc/hosts.allow` и `/etc/hosts.deny`, что позволяет ограничить доступ ко всем RPC-службам на сервере.

## Настройка NFS-сервера

### 1. Установка

Для настройки сервера требуется пакет `nfs-kernel-server`.

### 2. Конфигурация экспорта

Основной конфигурационный файл — `/etc/exports`. В нём указывается, какие директории на сервере будут доступны клиентам и с какими правами.

Формат записи:
```ini
<директория> <клиент1>(<опции>) <клиент2>(<опции>)
```

-   `<директория>` — полный путь к папке, которую нужно сделать доступной.
-   `<клиент>` — IP-адрес, имя хоста или подсеть, которым разрешён доступ.
-   `<опции>` — права доступа и другие параметры:
    -   `ro`: только чтение (по умолчанию).
    -   `rw`: чтение и запись.
    -   `sync`: сервер отвечает на запросы только после записи изменений на диск (надежно, но медленнее).
    -   `async`: сервер отвечает до фактической записи на диск (быстрее, но менее надежно).
    -   `no_root_squash`: разрешает пользователю `root` на клиенте иметь права `root` на сервере (небезопасно).

**Пример:**
```ini
/srv/data 10.9.8.1(rw,sync) 10.9.0.0/255.255.0.0(ro,sync)
```

### 3. Применение изменений

После внесения изменений в `/etc/exports` необходимо обновить информацию для служб NFS. Это можно сделать без перезапуска.

```sh
sudo exportfs -a
```

Или перезапустить сам сервис:

```sh
sudo systemctl restart nfs-kernel-server
```

## Настройка NFS-клиента

### 1. Установка

Для подключения к NFS-серверу требуется пакет `nfs-common`.

### 2. Просмотр доступных ресурсов

Чтобы узнать, какие файловые системы доступны на сервере, используйте команду `showmount`.

```sh
showmount -e <IP_адрес_сервера>
```
Например:
```sh
showmount -e 172.168.1.4
```

### 3. Монтирование

Для временного монтирования сетевой папки используется команда `mount`.

```sh
sudo mount -t nfs <IP_сервера>:<путь_на_сервере> <локальная_точка_монтирования>
```
Например:
```sh
sudo mount -t nfs 172.168.1.4:/opt/data/nfs /mnt/nfs
```

### 4. Отмонтирование

```sh
sudo umount /mnt/nfs
```

### 5. Автоматическое монтирование при загрузке

Чтобы сетевая папка монтировалась автоматически при старте системы, необходимо добавить запись в файл `/etc/fstab`.

```
<IP_сервера>:<путь_на_сервере> <локальная_точка_монтирования> nfs auto,nofail,noatime,nolock,intr,tcp,actimeo=1800 0 0
```
Например:
```
172.168.1.4:/opt/data/nfs /mnt/nfs nfs auto,nofail,noatime,nolock,intr,tcp,actimeo=1800 0 0
```
- `nofail`: система не будет останавливать загрузку, если NFS-сервер недоступен.
