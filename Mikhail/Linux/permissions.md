# Права доступа в Linux

В Linux права доступа к файлам и директориям являются фундаментальным механизмом обеспечения безопасности. Они определяют, какие действия пользователи и группы могут выполнять с файлами.

## Основные права доступа

Существует три основных типа прав:

-   `r` (read) - Чтение: Позволяет просматривать содержимое файла или директории.
-   `w` (write) - Запись: Позволяет изменять содержимое файла или создавать/удалять файлы в директории.
-   `x` (execute) - Выполнение: Позволяет запускать файл как программу или входить в директорию.

Эти права назначаются для трех категорий пользователей:

-   **Владелец (user):** Пользователь, который создал файл.
-   **Группа (group):** Группа пользователей, которая имеет определенные права доступа к файлу.
-   **Остальные (others):** Все остальные пользователи.

### Символьное и числовое представление

Права доступа можно представлять в символьном и числовом (восьмеричном) виде.

**Пример:** `-rwxrw-r--`

-   Первый символ (`-`) означает тип файла (в данном случае, обычный файл).
-   `rwx`: права для владельца (чтение, запись, выполнение).
-   `rw-`: права для группы (чтение, запись).
-   `r--`: права для остальных (только чтение).

**Числовое представление:**

| Бинарный | Восьмеричный | Права доступа | Представление |
| :--- | :--- | :--- | :--- |
| `000` | `0` | Нет доступа | `---` |
| `001` | `1` | Выполнение | `--x` |
| `010` | `2` | Запись | `-w-` |
| `011` | `3` | Запись + Выполнение | `-wx` |
| `100` | `4` | Чтение | `r--` |
| `101` | `5` | Чтение + Выполнение | `r-x` |
| `110` | `6` | Чтение + Запись | `rw-` |
| `111` | `7` | Чтение + Запись + Выполнение | `rwx` |

## Утилиты для управления правами

### `chmod`

Утилита `chmod` используется для изменения прав доступа к файлам и директориям.

**Примеры:**

-   `chmod u+x file.txt` - Добавить право на выполнение для владельца.
-   `chmod g-w file.txt` - Убрать право на запись для группы.
-   `chmod o=r file.txt` - Установить права только на чтение для остальных.
-   `chmod 755 file.txt` - Установить права `rwxr-xr-x`.

### `chown`

Утилита `chown` используется для изменения владельца и/или группы файла.

**Примеры:**

-   `chown alice file.txt` - Сделать `alice` владельцем файла.
-   `chown :developers file.txt` - Сделать `developers` группой-владельцем файла.
-   `chown alice:developers file.txt` - Сделать `alice` владельцем и `developers` группой-владельцем.

## Особые права доступа

### SUID (Set User ID)

-   **Назначение:** Устанавливается на исполняемые файлы. Позволяет выполнять файл с правами владельца файла.
-   **Обозначение:** `s` в поле прав выполнения для владельца (`-rwsr-xr-x`).
-   **Установка:** `chmod u+s filename` или `chmod 4755 filename`.
-   **Пример:** Утилита `passwd` имеет SUID бит, что позволяет обычным пользователям изменять свой пароль, хранящийся в системных файлах.

### SGID (Set Group ID)

-   **Назначение:**
    -   Для файлов: выполняются с правами группы-владельца.
    -   Для директорий: новые файлы, созданные в директории, наследуют группу директории.
-   **Обозначение:** `s` в поле прав выполнения для группы (`-rwxr-sr-x`).
-   **Установка:** `chmod g+s filename` или `chmod 2755 filename`.
-   **Пример:** Директория с общими файлами для группы разработчиков.

### Sticky bit

-   **Назначение:** Обычно используется для директорий. Предотвращает удаление файлов другими пользователями. Только владелец файла, владелец директории или `root` может удалить файл.
-   **Обозначение:** `t` в поле прав выполнения для остальных (`drwxrwxrwt`).
-   **Установка:** `chmod +t directory` или `chmod 1777 directory`.
-   **Пример:** Директория `/tmp`.

## `sudo` и `su`

### `su`

Команда `su` (switch user) позволяет переключиться на другого пользователя.

-   `su <имя_пользователя>`: Переключиться на указанного пользователя.
-   `su -`: Переключиться на пользователя `root` с полным изменением окружения.

### `sudo`

Команда `sudo` (superuser do) позволяет выполнять команды от имени другого пользователя (по умолчанию `root`).

-   `sudo <команда>`: Выполнить команду с правами `root`.
-   `sudo -i`: Запустить интерактивную сессию от имени `root` с полным изменением окружения.
-   `sudo -s`: Запустить shell от имени `root`, не меняя окружение.
-   `sudo -l`: Посмотреть список разрешенных команд для текущего пользователя.

### Файл `/etc/sudoers`

Этот файл определяет, какие пользователи и группы могут использовать `sudo` и какие команды им разрешено выполнять.

**Пример строки:** `user ALL=(ALL:ALL) ALL`

-   `user`: Имя пользователя или `%group` для группы.
-   Первое `ALL`: Правило применяется ко всем хостам.
-   Второе `ALL`: Пользователь может выполнять команды от имени всех пользователей.
-   Третье `ALL`: Пользователь может выполнять команды от имени всех групп.
-   Четвертое `ALL`: Правило применяется ко всем командам.

## Управление группами

### Просмотр групп

-   `groups <имя_пользователя>`: Узнать, в каких группах состоит пользователь.

### Добавление пользователя в группу

-   `sudo usermod -aG <имя_группы> <имя_пользователя>`: Добавить пользователя в группу.

### Изменение группы-владельца директории

-   `sudo chgrp -R <новая_группа> /path/to/directory`: Рекурсивно изменить группу-владельца для директории и всех вложенных файлов.

## Флаг неизменяемости (immutable)

Файл или директория с этим флагом становятся "неприкосновенными". Их нельзя:
-   Удалить
-   Переименовать
-   Изменить
-   Создавать на них жёсткие ссылки

Даже пользователь `root` не сможет выполнить эти действия, пока флаг не будет снят.

### Управление флагом с помощью `chattr`

Для управления атрибутами используется утилита `chattr`.

**Установка флага неизменяемости:**

-   **Для файла:**
    ```sh
    # Сделать файл /path/to/file.txt неизменяемым
    sudo chattr +i /path/to/file.txt
    ```

-   **Для директории и всего её содержимого (рекурсивно):**
    ```sh
    # -R — рекурсивно
    sudo chattr +i -R /path/to/directory/
    ```

**Снятие флага неизменяемости:**

-   **Для файла:**
    ```sh
    sudo chattr -i /path/to/file.txt
    ```

-   **Для директории и содержимого:**
    ```sh
    sudo chattr -i -R /path/to/directory/
    ```

### Просмотр атрибутов

Чтобы увидеть установленные атрибуты, используйте команду `lsattr`:
```sh
lsattr /path/to/file_or_directory
```
Файл с флагом `i` будет выглядеть так: `----i---------e---- /path/to/file.txt`

# ACL (Access Control Lists) в Linux

Стандартные права доступа в Linux (`rwx` для владельца, группы и остальных) не всегда позволяют гибко настроить доступ. Например, если нужно дать права на файл двум разным пользователям, не объединяя их в одну группу. Для таких случаев используются **Списки контроля доступа (ACL)**.

ACL — это расширенный механизм прав, который позволяет назначать разрешения для любого пользователя или группы, дополняя стандартные права.

Чтобы использовать ACL, файловая система должна быть смонтирована с опцией `acl`. 

Для работы с ACL могут потребоваться утилиты `getfacl` и `setfacl`. Если их нет, установите пакет `acl`

Команда `getfacl` показывает текущие права ACL для файла или директории.
```sh
getfacl /path/to/file
```
**Пример вывода для файла без ACL:**

Если для файла установлены расширенные права, в выводе `ls -l` появится знак `+`:
```
-rw-r--r--+ 1 user1 developers 0 Jul 13 10:00 my_file.txt
```

Команда `setfacl` используется для добавления, изменения или удаления правил ACL.

**Ключевые опции:**
-   `-m` (modify): Изменить или добавить правило.
-   `-x` (remove): Удалить правило.
-   `-b` (remove-all): Удалить все расширенные правила ACL.
-   `-R` (recursive): Применить рекурсивно к файлам и директориям.
-   `-d` (default): Установить ACL по умолчанию для директории.

**Примеры использования:**

1.  **Дать пользователю `alice` права на чтение и запись:**
    ```sh
    setfacl -m u:alice:rw- /path/to/file
    ```

2.  **Дать группе `testers` права на чтение:**
    ```sh
    setfacl -m g:testers:r-- /path/to/file
    ```

3.  **Удалить права для пользователя `alice`:**
    ```sh
    setfacl -x u:alice /path/to/file
    ```

4.  **Удалить все расширенные права ACL:**
    ```sh
    setfacl -b /path/to/file
    ```

Особая возможность ACL — установка **прав по умолчанию** для директории. Все новые файлы и поддиректории, созданные внутри неё, будут автоматически наследовать эти права.

**Пример:**

Установим для директории `/shared` права по умолчанию, чтобы все новые файлы были доступны для чтения и записи пользователю `bob` и группе `project`.
```sh
# d - default, u - user, g - group
setfacl -m d:u:bob:rw-,d:g:project:rw- /shared
```
Теперь любой файл, созданный в `/shared`, автоматически получит эти ACL.

Маска в ACL определяет **максимально возможные права** для всех именованных пользователей, групп и группы-владельца. Она работает как ограничитель.

-   **Что это?** Запись `mask::r--` означает, что даже если вы дали пользователю `alice` права `rw-`, его эффективные права будут только `r--` (чтение).
-   **Как это работает?** Эффективные права вычисляются как логическое "И" между назначенными правами и маской.
-   **Зачем это нужно?** Маска позволяет быстро ограничить доступ для всех дополнительных пользователей и групп, не изменяя каждое правило по отдельности. Например, чтобы временно запретить всем запись, достаточно изменить только маску: `setfacl -m m::r-- file`.

При изменении ACL с помощью `setfacl` маска пересчитывается автоматически, если не указана опция `--no-mask`.

## Восстановление пароля root

Если вы потеряли пароль от пользователя `root`, его можно сбросить, получив доступ к системе в однопользовательском режиме или с помощью `init`-шелла. Этот процесс требует физического доступа к машине или консоли управления.

**Процесс основан на редактировании параметров загрузки ядра в GRUB.**

### Шаг 1: Перезагрузка и вход в меню GRUB

1.  Перезагрузите компьютер.
2.  Когда появится меню загрузчика GRUB, нажмите клавишу `e`, чтобы отредактировать параметры загрузки для выбранной записи (обычно первой).

### Шаг 2: Редактирование параметров загрузки

1.  Вы увидите текстовый редактор с конфигурацией загрузки. Найдите строку, которая начинается с `linux` или `linuxefi`. Эта строка определяет ядро для загрузки и его параметры.

2.  Переместите курсор в конец этой строки.

3.  Добавьте один из следующих параметров:
    *   **`init=/bin/bash`** (или `init=/bin/sh`)
        *   Это самый прямой способ. Он указывает ядру запустить `/bin/bash` в качестве первого процесса (PID 1) вместо `systemd` или `init`. В результате вы сразу получите корневую оболочку.

    *   **`rd.break`** (для систем с `systemd`, таких как CentOS/RHEL 7+ и Ubuntu 18.04+)
        *   Этот параметр останавливает процесс загрузки на раннем этапе, до того как `systemd` передаст управление реальной корневой файловой системе. Вы попадете в `emergency mode` с корневой оболочкой.

### Шаг 3: Запуск с измененными параметрами

-   После добавления параметра нажмите `Ctrl+X` или `F10`, чтобы загрузить систему с измененными параметрами.

### Шаг 4: Сброс пароля

Теперь вы находитесь в корневой оболочке с правами `root`. Дальнейшие действия зависят от того, какой параметр вы использовали.

**Если вы использовали `init=/bin/bash`:**

1.  Корневая файловая система (`/`) смонтирована в режиме "только для чтения" (`ro`). Ее нужно перемонтировать в режим "чтение-запись" (`rw`):
    ```sh
    mount -o remount,rw /
    ```

2.  Измените пароль пользователя `root`:
    ```sh
    passwd
    ```
    Система попросит вас ввести и подтвердить новый пароль.

3.  (Опционально, для систем с SELinux) Если у вас включен SELinux (например, в CentOS/RHEL), создайте пустой файл `.autorelabel` в корне, чтобы система выполнила перемаркировку файлов при следующей загрузке.
    ```sh
    touch /.autorelabel
    ```

4.  Перезагрузите систему. Так как `systemd` не запущен, обычная команда `reboot` может не сработать. Используйте одну из этих команд для принудительной перезагрузки:
    ```sh
    exec /sbin/init 6
    # или
    reboot -f
    ```

**Если вы использовали `rd.break`:**

1.  Корневая файловая система находится в `/sysroot` и смонтирована в режиме "только для чтения" (`ro`). Перемонтируйте ее в режим "чтение-запись" (`rw`):
    ```sh
    mount -o remount,rw /sysroot
    ```

2.  Переключитесь в `chroot`-окружение, чтобы корневой директорией стала `/sysroot`:
    ```sh
    chroot /sysroot
    ```

3.  Теперь вы можете изменить пароль:
    ```sh
    passwd
    ```

4.  (Опционально, для систем с SELinux) Создайте файл для перемаркировки:
    ```sh
    touch /.autorelabel
    ```

5.  Выйдите из `chroot`-окружения:
    ```sh
    exit
    ```

6.  Перезагрузите систему:
    ```sh
    reboot
    ```
