# SSH (Secure Shell)

SSH — это сетевой протокол, позволяющий безопасно управлять удалённой системой. Вся информация, включая пароли, передаётся в зашифрованном виде.

## 1. Генерация SSH-ключей

Для аутентификации по ключу (вместо пароля) необходимо сгенерировать пару ключей: публичный и приватный.

```sh
ssh-keygen -t ed25519
```
- `-t ed25519`: Указывает тип ключа. `ed25519` является современным и безопасным алгоритмом.

## 2. Управление ключами с помощью ssh-agent

`ssh-agent` — это фоновый процесс, который хранит приватные ключи в памяти и избавляет от необходимости вводить пароль от ключа при каждом подключении.

Запуск агента:
```sh
eval "$(ssh-agent -s)"
```

Добавление ключа в агент:
```sh
ssh-add ~/.ssh/id_ed25519
```
*Замените `~/.ssh/id_ed25519` на путь к вашему приватному ключу.*

## 3. Настройка SSH-клиента (`~/.ssh/config`)

Файл `~/.ssh/config` позволяет задать псевдонимы и параметры для различных хостов, чтобы упростить подключение.

Пример содержимого файла:
```ini
Host kei
  HostName 93.1.24.58
  User root
  Port 15134
  IdentityFile ~/.ssh/id_ed25519
```
Теперь для подключения достаточно выполнить команду `ssh kei`.

## 4. Настройка SSH-сервера

### Копирование публичного ключа на сервер

Содержимое вашего **публичного** ключа (например, `~/.ssh/id_ed25519.pub`) необходимо добавить в файл `~/.ssh/authorized_keys` на сервере.

```sh
# На сервере
mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
# Вставьте сюда содержимое вашего .pub файла
```

### Настройка прав доступа

Крайне важно установить правильные права доступа для директории `.ssh` и файла с ключами, иначе SSH-сервер может отказать в подключении.

```sh
# На сервере
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

### Конфигурация SSH-демона (`/etc/ssh/sshd_config`)

Для повышения безопасности рекомендуется изменить стандартные настройки SSH-сервера.

```sh
# На сервере
sudo nano /etc/ssh/sshd_config
```

Основные параметры для изменения:
- `Port 22`: Измените стандартный порт на другой (например, `Port 15134`), чтобы уменьшить количество автоматических атак.
- `PermitRootLogin yes`: Запретите вход от имени пользователя `root`, установив значение `no`.
- `PasswordAuthentication yes`: Отключите аутентификацию по паролю (`no`), оставив только вход по ключам.

После внесения изменений перезапустите SSH-сервис:
```sh
sudo systemctl restart sshd
```

## 5. SSH-туннелирование

SSH-туннелирование — это метод создания зашифрованного канала, который позволяет перенаправлять сетевой трафик между локальной машиной и удаленным сервером. Это полезно для:
- Обхода ограничений файрвола.
- Безопасного доступа к внутренним сервисам.

### Локальный проброс портов (Local Port Forwarding)

Позволяет перенаправить трафик с локального порта на удалённый хост через SSH-сервер.

```sh
ssh -L <локальный_порт>:<целевой_хост>:<целевой_порт> user@ssh_server
```
**Пример:** Доступ к веб-серверу `example.com`, который доступен только с `ssh_server`.
```sh
ssh -L 8080:example.com:80 user@ssh_server
```
Теперь, открыв `http://localhost:8080` в браузере на локальной машине, вы увидите сайт `example.com`.

### Удаленный проброс портов (Remote Port Forwarding)

Позволяет перенаправить трафик с порта на удалённом сервере на локальную машину.

```sh
ssh -R <удалённый_порт>:<локальный_хост>:<локальный_порт> user@ssh_server
```
**Пример:** Показать локальный веб-сервер, работающий на порту `3000`, внешнему миру через `ssh_server`.
```sh
ssh -R 8080:localhost:3000 user@ssh_server
```
Теперь любой, кто зайдёт на `http://<IP_адрес_ssh_server>:8080`, попадёт на ваш локальный сервис.
