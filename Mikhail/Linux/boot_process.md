# Процесс загрузки Linux

Процесс загрузки Linux — это последовательность шагов от включения компьютера до запуска полнофункциональной операционной системы. Каждый этап выполняет свою задачу и передает управление следующему.

## Ключевые этапы загрузки

### 1. Инициализация оборудования (BIOS/UEFI)

-   **Задача:** Проверить и инициализировать аппаратное обеспечение.
-   **Процесс:**
    1.  При включении питания запускается базовая система ввода-вывода (**BIOS**) или ее современный аналог (**UEFI**).
    2.  Выполняется самотестирование при включении (**POST**), которое проверяет исправность ключевых компонентов: процессора, памяти, дисков.
    3.  После успешного POST прошивка ищет загрузочное устройство (жесткий диск, SSD, USB) в соответствии с порядком загрузки.
    4.  Управление передается загрузчику, найденному на этом устройстве.

### 2. Загрузчик ОС (Bootloader)

-   **Задача:** Загрузить ядро операционной системы в память.
-   **Компоненты:**
    -   **MBR/GPT:** Схема разметки диска. В первом секторе находится код, который указывает на местоположение загрузчика.
    -   **GRUB2 (GRand Unified Bootloader 2):** Наиболее распространенный загрузчик в Linux.
-   **Процесс:**
    1.  GRUB2 считывает свою конфигурацию и отображает меню для выбора операционной системы или версии ядра.
    2.  Загружает в оперативную память выбранное **ядро Linux** и временную файловую систему **`initramfs`**.
    3.  Передает управление ядру.

### 3. Ядро (Kernel) и `initramfs`

-   **Задача:** Подготовить систему к монтированию основной корневой файловой системы.
-   **Процесс:**
    1.  Ядро, получив управление, распаковывается и инициализируется в памяти.
    2.  Монтируется **`initramfs` (Initial RAM File System)** — это временная корневая ФС в оперативной памяти. Она представляет собой архив `cpio`, сжатый с помощью `gzip`.
    3.  `initramfs` содержит минимальный набор драйверов (например, для LVM, RAID, NVMe, USB) и утилит, которые необходимы для доступа к основной ("реальной") корневой файловой системе.
    4.  После того как основная ФС найдена и смонтирована, `initramfs` выгружается из памяти, и управление передаётся процессу инициализации на реальной ФС.

#### Пересборка `initramfs`

Иногда, после изменения конфигурации хранилища (например, LVM) или установки драйверов, может потребоваться пересобрать `initramfs`, чтобы включить в него новые модули. Команды для этого различаются в зависимости от дистрибутива:

-   **Debian/Ubuntu:**
    ```bash
    sudo update-initramfs -u
    ```

-   **RHEL/CentOS/Fedora/AlmaLinux:**
    ```bash
    sudo dracut -f
    ```

-   **Arch Linux:**
    ```bash
    sudo mkinitcpio -P
    ```

### 4. Система инициализации (`init`/`systemd`)

-   **Задача:** Запустить все системные процессы и службы.
-   **Процесс:**
    1.  Ядро запускает самый первый процесс в пользовательском пространстве — `/sbin/init`, который имеет **PID 1**.
    2.  В большинстве современных дистрибутивов Linux это **`systemd`**.
    3.  `systemd` анализирует свои конфигурационные файлы (юниты) и запускает системные службы в соответствии с их зависимостями.

### 5. Запуск пользовательского окружения (Targets)

-   **Задача:** Достичь конечного состояния системы, определенного "целью" (target).
-   **Процесс:**
    -   `systemd` использует **цели (targets)** для группировки юнитов. Это аналог "уровней выполнения" (runlevels) в старых системах SysVinit.
    -   Основные цели:
        -   `rescue.target`: Режим восстановления (однопользовательский).
        -   `multi-user.target`: Стандартный многопользовательский режим без графики.
        -   `graphical.target`: Многопользовательский режим с графическим интерфейсом.
        -   `reboot.target`: Перезагрузка.
        -   `poweroff.target`: Выключение.
