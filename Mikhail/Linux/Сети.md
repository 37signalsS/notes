# **Port/DNS**

- Список процессов которые слушают сетевые порты( -t: Показывает TCP-соединения. -u: Показывает UDP-соединения.-l: Показывает только прослушиваемые (listening) соединения.-n: Отображает адреса и порты в числовом формате.-p: Показывает PID и имя процесса.):

``` sh
ss -tulpn
```

- Узнать какой процесс занял порт(процесс потом можно убить)

``` sh
ss -tuln | grep 4000
```

- Инфа о сетевых маршрутах

``` sh
netstat -rn
```

- Проверка dns resolve(должен выдать ip)

``` sh
ping git.nnstd.dev
```

- Путь пакетов к точке назанчения(mtr 8.8.8.8, тоже самое но в интерактивном режиме

Если выводяться *** это значит: 1.что промежуточный сервер не принимает ICMP-запросы(ping), 2. сервер недоступен/выключен, 3.устройство не успевает ответить за определенное время.

Можно улучшить результаты traceroute при помощи: флогом -T -U (TCP UDP), и флагом -w 10(таймаут, 5 по дефолту)

``` sh
traceroute 8.8.8.8
```

- Ответы/скорость DNS серверов(dig @8.8.8.8 git.nnstd.dev спрашиваем у гугла)

``` sh
dig git.nnstd.dev
```

dig -t <тип записи которую хотим получить> git.nnst.dev(например, почта)

- Какие пакеты проходят через опредленные интерфейсы

``` sh
tcpdump -i any port 9000 -nn
```

(-i все интрейфейсы, 9000 порт, --nn без доменных имен)

# **Iptables**

- Узнать текущие правила 

``` sh
iptables -L -v -n
```

- Очистить текущие правила

``` sh
iptables -F
```

``` sh
iptables -X
```

- Разрешить локальные соединения 

``` sh
iptables -A INPUT -i lo -j ACCEPT
```

``` sh
iptables -A OUTPUT -o lo -j ACCEPT
```

- Добавляет правило которое разрешить входящий tcp трафик на 22 порт от айпи адреса

``` sh
iptables -A INPUT -p tcp --dport 22 -s 172.16.238.15 -j ACCEPT
```

- Заблокировать входящий трафик 

``` sh
iptables -A INPUT -j DROP
```

- Заблокировать исходящий трафик

``` sh
iptables -P OUTPUT DROP
```

- Добавляет правило которое разрешить исходящий tcp трафик на 22 порт от айпи адреса

``` sh
iptables -A OUTPUT -p tcp --dport 80 -d 172.16.238.15 -j ACCEPT
```

- Узнать айпи адрес сайта

``` sh
nslookup google.com
```

-  I вставляет правило в начало цепочки OUTPUT на первой позиции

``` sh
sudo iptables -I OUTPUT 1 -p tcp --dport 443 -d google.com -j ACCEPT
```

- Удалить правило 

``` sh
iptables -D INPUT -p tcp --dport 22 -j ACCEPT
```

- Сохранить правила

``` sh
service iptables save
```

# **Time_wait**

Что такое `TIME_WAIT`?
- Когда TCP-соединение закрывается, оно переходит в состояние TIME_WAIT. Это часть протокола TCP, которая гарантирует, что все пакеты, отправленные в рамках этого соединения, будут доставлены или отброшены.
- В этом состоянии соединение остается на определенный промежуток времени (обычно 60 секунд) для обработки возможных задержанных пакетов.

Как решить проблему?

#### 1. Настройка параметров ядра Linux:
   - Уменьшение времени, в течение которого соединение находится в состоянии TIME_WAIT:  

```
 sysctl -w net.ipv4.tcp_fin_timeout=30
```

Это сократит время до 30 секунд (по умолчанию 60).

   - Разрешение повторного использования соединений в состоянии TIME_WAIT:  

```
sysctl -w net.ipv4.tcp_tw_reuse=1
```

Параметр tcp_tw_reuse позволяет использовать соединения в состоянии TIME_WAIT для новых запросов.

#### 2. Оптимизация приложения:
   - Если сервер обрабатывает множество коротких HTTP-запросов, можно использовать:
     - HTTP Keep-Alive: Позволяет повторно использовать одно TCP-соединение для нескольких запросов, уменьшая количество новых соединений.
     - Connection Pooling: Использование пула соединений для повторного использования уже установленных соединений.

#### 3. Увеличение лимита портов:
   - По умолчанию диапазон портов для исходящих соединений ограничен. Его можно увеличить:

```
 sysctl -w net.ipv4.ip_local_port_range="1024 65535"
```
