# Управление и диагностика сетей в Linux

---

## 1. Управление сетевыми интерфейсами (`ip`)

Команда `ip` — это основной современный инструмент для управления сетевыми интерфейсами, IP-адресами и маршрутизацией.

-   **Посмотреть все IP-адреса и состояние интерфейсов:**
    ```bash
    ip a
    # или
    ip addr show
    ```

-   **Включить или выключить интерфейс:**
    ```bash
    # Выключить
    sudo ip link set dev eth0 down
    # Включить
    sudo ip link set dev eth0 up
    ```

-   **Добавить или удалить IP-адрес:**
    ```bash
    # Добавить
    sudo ip addr add 192.168.1.100/24 dev eth0
    # Удалить
    sudo ip addr del 192.168.1.100/24 dev eth0
    ```

## 2. Базовая диагностика: Связность и DNS

### Проверка доступности хоста (`ping`)

`ping` отправляет ICMP-запросы для проверки доступности хоста и измерения задержки.

-   **Анализ ответов `ping`:**
    -   **`Destination Host Unreachable`**: Ваш локальный маршрутизатор не знает, как добраться до цели. Проблема в вашей сети (нет маршрута, кабель отключен).
    -   **`Request Timed Out`**: Ответ не пришел вовремя. Причины: файрвол, перегрузка сети, хост выключен.
    -   **`TTL expired in transit`**: Пакет превысил лимит "прыжков". Чаще всего указывает на **петлю маршрутизации**.

-   **Тестирование MTU:**
    Отправка пакета, который не должен фрагментироваться. Помогает выявить проблемы с MTU на пути.
    ```bash
    # 1472 байта данных + 28 байт заголовков = 1500 байт
    ping -c 4 -s 1472 -M do 8.8.8.8
    ```

### Диагностика DNS (`dig`)

`dig` — мощный инструмент для опроса DNS-серверов.

```bash
# Получить A-запись для домена
dig example.com

# Запросить MX-запись (почта)
dig -t MX example.com

# Опросить конкретный DNS-сервер
dig @8.8.8.8 example.com
```

## 3. Анализ соединений и портов

### Активные соединения (`ss`)

Утилита `ss` — быстрая и современная замена `netstat`.

-   **Показать все слушающие TCP и UDP порты и процессы, которые их используют:**
    ```bash
    sudo ss -tulpan
    ```
    -   `-t`: TCP, `-u`: UDP, `-l`: слушающие сокеты, `-p`: процессы, `-n`: числовой вывод, `-a`: все сокеты.

-   **Узнать, какой процесс занял определённый порт:**
    ```bash
    sudo ss -lntp 'sport = :443'
    ```

### Сканирование портов (`nmap`)

`nmap` — незаменимый инструмент для аудита безопасности и исследования сети.

-   **Быстрое сканирование популярных портов на хосте:**
    ```bash
    nmap scanme.nmap.org
    ```

-   **Проверить, открыт ли конкретный порт:**
    ```bash
    nmap -p 80,443 192.168.1.1
    ```

-   **Определить версии служб, работающих на портах:**
    ```bash
    sudo nmap -sV 192.168.1.1
    ```

## 4. Маршрутизация и анализ пути

-   **Посмотреть таблицу маршрутизации:**
    ```bash
    ip route show
    ```

-   **Трассировка маршрута (`traceroute`):**
    Показывает путь (последовательность маршрутизаторов) до цели.
    ```bash
    traceroute example.com
    ```
    -   Если на узле отображаются `* * *`, он может блокировать ICMP. Попробуйте трассировку через TCP:
        ```bash
        sudo traceroute -T example.com
        ```

## 5. Анализ сетевого трафика (`tcpdump`)

Перехватывает и анализирует сетевые пакеты в реальном времени. Это мощный инструмент для глубокой диагностики.

-   **Прослушивать трафик на всех интерфейсах на порту 443:**
    ```bash
    sudo tcpdump -i any port 443 -nn
    ```
    -   `-i any`: все интерфейсы, `-nn`: не преобразовывать адреса и порты в имена.

## 6. Измерение производительности (`iperf3`)

`iperf3` — утилита для измерения пропускной способности сети между двумя хостами.

-   **На хосте-сервере:**
    ```bash
    iperf3 -s
    ```

-   **На хосте-клиенте:**
    ```bash
    # Прямой канал (клиент -> сервер)
    iperf3 -c <IP_адрес_сервера>

    # Обратный канал (сервер -> клиент)
    iperf3 -c <IP_адрес_сервера> -R
    ```

## 7. Управление файрволом (`iptables`)

`iptables` — классический инструмент для управления файрволом Netfilter. Он работает с **цепочками** правил.

-   **Основные цепочки:**
    -   `INPUT`: Входящий трафик, адресованный самому серверу.
    -   `OUTPUT`: Исходящий трафик с сервера.
    -   `FORWARD`: Транзитный трафик, проходящий через сервер.

-   **Посмотреть текущие правила:**
    ```bash
    sudo iptables -L -v -n
    ```

Очистить все правила (будьте осторожны, это может заблокировать вам доступ):
```sh
# Удалить все правила
sudo iptables -F
# Удалить все пользовательские цепочки
sudo iptables -X
```

### Базовые правила

Разрешить весь трафик на локальном интерфейсе `lo` (важно для работы многих приложений):
```sh
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A OUTPUT -o lo -j ACCEPT
```

Установить политику по умолчанию (что делать с трафиком, который не подошел ни под одно правило):
```sh
# Блокировать весь входящий трафик по умолчанию
sudo iptables -P INPUT DROP
# Блокировать весь исходящий трафик по умолчанию
sudo iptables -P OUTPUT DROP
```
**Внимание:** После установки политики `DROP` вам нужно будет явно разрешать все необходимые соединения.

### Примеры правил

Разрешить входящие SSH-соединения с определённого IP:
```sh
sudo iptables -A INPUT -p tcp --dport 22 -s 172.16.238.15 -j ACCEPT
```

Разрешить исходящие HTTP/HTTPS соединения:
```sh
sudo iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT
```

Удалить правило из цепочки по его номеру:
```sh
sudo iptables -D INPUT <номер_правила>
```

### Сохранение правил

Правила `iptables` сбрасываются при перезагрузке. Для их сохранения установите пакет `iptables-persistent`.
```sh
sudo apt-get install iptables-persistent
```
Во время установки вам будет предложено сохранить текущие правила. В дальнейшем для сохранения можно использовать команду:
```sh
sudo netfilter-persistent save
```

### Взаимодействие iptables и Docker

> **Ключевой момент:** Docker управляет своими правилами `iptables` и направляет трафик к контейнерам через цепочку **`FORWARD`**, а не `INPUT`.

- **Трафик к контейнерам идёт через `FORWARD`:** Когда вы пробрасываете порт с хоста в контейнер (например, `docker run -p 8080:80`), Docker добавляет правила в таблицу `nat`, чтобы перенаправлять трафик. Этот перенаправленный трафик обрабатывается цепочкой `FORWARD`, а не `INPUT`, как можно было бы ожидать.

**Проблема:** Если вы установили политику по умолчанию `sudo iptables -P FORWARD DROP`, вы не сможете получить доступ к опубликованным портам контейнеров.

**Правильное решение:** Docker создал специальную цепочку `DOCKER-USER`, которая выполняется раньше всех остальных правил Docker. Все кастомные правила для контейнеров следует добавлять в нее.

-   **Пример: разрешить доступ к порту 8080 с определенного IP:**
    ```bash
    # Трафик на все остальные порты будет обработан стандартными правилами Docker или заблокирован
    sudo iptables -I DOCKER-USER -i ext_if -p tcp --dport 8080 -s 1.2.3.4 -j ACCEPT
    ```
    - `-I DOCKER-USER`: Вставить правило в начало цепочки `DOCKER-USER`.
    - `-i ext_if`: Укажите ваш внешний сетевой интерфейс.

## 8. Продвинутые темы

### Проблема `TIME_WAIT`

Когда TCP-соединение закрывается, оно на некоторое время (обычно 60 секунд) переходит в состояние `TIME_WAIT` для гарантии доставки всех пакетов. На высоконагруженных серверах (например, прокси) большое количество таких сокетов может исчерпать лимит доступных портов.

-   **Диагностика:**
    ```bash
    ss -tan 'state time-wait' | wc -l
    ```

-   **Решение (настройка ядра):**
    Для постоянного применения добавьте эти строки в `/etc/sysctl.conf` и выполните `sudo sysctl -p`.
    ```ini
    # Разрешить повторное использование сокетов в состоянии TIME_WAIT для новых соединений (безопасно)
    net.ipv4.tcp_tw_reuse=1

    # Уменьшить время ожидания в TIME_WAIT (по умолчанию 60)
    net.ipv4.tcp_fin_timeout=30
    ```

### Что такое сокет?

**Сокет** — это программный интерфейс (представленный как файл в ОС) для обмена данными между процессами. Эти процессы могут выполняться как на одной машине, так и в сети.

### Основные типы сокетов

1.  **Сетевые сокеты (AF_INET, AF_INET6):**
    *   Используются для коммуникации по сети (например, через интернет).
    *   Они привязаны к IP-адресу и порту.
    *   Пример: веб-сервер, который "слушает" порт 80 для входящих HTTP-запросов.

2.  **Unix-сокеты (AF_UNIX):**
    *   Используются для обмена данными между процессами **на одной и той же машине**.
    *   Они не используют сетевой стек (IP-адреса и порты), а вместо этого создают специальный файл в файловой системе.
    *   **Преимущество:** Работают значительно быстрее сетевых сокетов, так как данные не проходят через сетевой интерфейс. Это делает их идеальными для локального IPC (Inter-Process Communication).

**Пример: Docker Socket (`/var/run/docker.sock`)**
Это Unix-сокет, который демон Docker (`dockerd`) использует как API. Клиент `docker` подключается к этому файлу для отправки команд. Доступ к этому файлу равносилен root-доступу к хост-системе.
