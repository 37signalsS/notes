# Диагностика и управление сетями в Linux

Этот документ содержит основные команды и концепции для диагностики, анализа и управления сетями в Linux.

## 1. Базовая диагностика сети

Инструменты для повседневной проверки состояния сети, IP-адресов, портов и DNS.

### Просмотр IP-адресов и интерфейсов (`ip`)

Команда `ip` — это основной современный инструмент для управления сетевыми интерфейсами и маршрутизацией.

-   **Посмотреть все IP-адреса и состояние интерфейсов:**
    ```sh
    ip a
    # или
    ip addr show
    ```

-   **Посмотреть таблицу маршрутизации:**
    ```sh
    ip route show
    ```

### Анализ активных соединений и портов (`ss`)

Утилита `ss` — это быстрая и современная замена `netstat`.

Показать все процессы, которые слушают TCP и UDP порты:
```sh
sudo ss -tulpn
```
- `-t`: TCP-соединения.
- `-u`: UDP-соединения.
- `-l`: Только прослушиваемые (listening) сокеты.
- `-p`: Показать имя процесса, использующего сокет.
- `-n`: Не преобразовывать IP-адреса и порты в имена.

Узнать, какой процесс занял определённый порт:
```sh
sudo ss -tuln | grep :4000
```

### Проверка доступности хоста (`ping`)

`ping` отправляет ICMP-запросы для проверки доступности хоста и измерения задержки.

-   **Анализ ответов `ping`:**
    -   **`Destination Host Unreachable`**: Ваш локальный маршрутизатор не знает, как добраться до цели. Проблема в вашей сети (нет маршрута, кабель отключен).
    -   **`Request Timed Out`**: Ответ не пришел вовремя. Причины: файрвол, перегрузка сети, хост выключен.
    -   **`TTL expired in transit`**: Пакет превысил лимит "прыжков". Чаще всего указывает на **петлю маршрутизации**.
    -   **`General Failure`**: Проблема с сетевым стеком на вашем компьютере.
    -   **`Ping request could not find host...`**: Ошибка DNS. Ваша система не смогла преобразовать имя в IP-адрес.

-   **Тестирование MTU:**
    Отправка пакета размером 1500 байт (1472 + 28) без фрагментации. Если он не проходит, есть проблема с MTU на пути.
    ```sh
    ping -c 4 -s 1472 -M do 8.8.8.8
    ```

### Диагностика DNS (`dig`)

`dig` — мощный инструмент для опроса DNS-серверов.

```sh
# Получить A-запись для домена
dig example.com

# Запросить MX-запись (почта)
dig -t MX example.com

# Опросить конкретный DNS-сервер
dig @8.8.8.8 example.com
```

## 2. Анализ маршрутов и трафика

Инструменты для глубокого анализа пути пакетов и содержимого трафика.

### Трассировка маршрута (`traceroute`)

Показывает путь (последовательность маршрутизаторов), который проходят пакеты до цели.

```sh
traceroute example.com
```

-   Если на узле отображаются `* * *`, он может блокировать ICMP-запросы. Попробуйте трассировку через TCP:
    ```sh
    sudo traceroute -T example.com
    ```

### Анализ сетевого трафика (`tcpdump`)

Перехватывает и анализирует сетевые пакеты в реальном времени.

-   **Прослушивать трафик на всех интерфейсах на порту 9000:**
    ```sh
    sudo tcpdump -i any port 9000 -nn
    ```
    -   `-i any`: все интерфейсы, `-nn`: не преобразовывать адреса и порты в имена.

## 4. Замер скорости сети (`iperf3`)

`iperf3` — утилита для измерения пропускной способности сети между двумя хостами.

На одном хосте (сервере) запустить в режиме сервера:
```sh
iperf3 -s
```

На втором хосте (клиенте) подключиться к серверу:
```sh
iperf3 -c <IP_адрес_сервера>
```
Для проверки обратного канала (от сервера к клиенту):
```sh
iperf3 -c <IP_адрес_сервера> -R
```

## 5. Основы файрвола (iptables)

`iptables` — утилита для управления файрволом Netfilter. Она работает с **цепочками** правил.

-   **Основные цепочки:**
    -   `INPUT`: Входящий трафик, адресованный самому серверу.
    -   `OUTPUT`: Исходящий трафик с сервера.
    -   `FORWARD`: Транзитный трафик, проходящий через сервер.

### Управление правилами

-   **Посмотреть текущие правила:**
    ```sh
    sudo iptables -L -v -n
    ```

Очистить все правила (будьте осторожны, это может заблокировать вам доступ):
```sh
# Удалить все правила
sudo iptables -F
# Удалить все пользовательские цепочки
sudo iptables -X
```

### Базовые правила

Разрешить весь трафик на локальном интерфейсе `lo` (важно для работы многих приложений):
```sh
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A OUTPUT -o lo -j ACCEPT
```

Установить политику по умолчанию (что делать с трафиком, который не подошел ни под одно правило):
```sh
# Блокировать весь входящий трафик по умолчанию
sudo iptables -P INPUT DROP
# Блокировать весь исходящий трафик по умолчанию
sudo iptables -P OUTPUT DROP
```
**Внимание:** После установки политики `DROP` вам нужно будет явно разрешать все необходимые соединения.

### Примеры правил

Разрешить входящие SSH-соединения с определённого IP:
```sh
sudo iptables -A INPUT -p tcp --dport 22 -s 172.16.238.15 -j ACCEPT
```

Разрешить исходящие HTTP/HTTPS соединения:
```sh
sudo iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT
```

Удалить правило из цепочки по его номеру:
```sh
sudo iptables -D INPUT <номер_правила>
```

### Сохранение правил

Правила `iptables` сбрасываются при перезагрузке. Для их сохранения установите пакет `iptables-persistent`.
```sh
sudo apt-get install iptables-persistent
```
Во время установки вам будет предложено сохранить текущие правила. В дальнейшем для сохранения можно использовать команду:
```sh
sudo netfilter-persistent save
```

### Взаимодействие iptables и Docker

> **Ключевой момент:** Docker управляет своими правилами `iptables` и направляет трафик к контейнерам через цепочку **`FORWARD`**, а не `INPUT`.

- **Трафик к контейнерам идёт через `FORWARD`:** Когда вы пробрасываете порт с хоста в контейнер (например, `docker run -p 8080:80`), Docker добавляет правила в таблицу `nat`, чтобы перенаправлять трафик. Этот перенаправленный трафик обрабатывается цепочкой `FORWARD`, а не `INPUT`, как можно было бы ожидать.

**Частая ошибка:** Если на сервере установлена политика безопасности по умолчанию, блокирующая пересылку пакетов:
```sh
sudo iptables -P FORWARD DROP
```
...то доступ к опубликованным портам контейнеров извне будет заблокирован. Пакеты будут отбрасываться на этапе `FORWARD`.

**Решение:** Необходимо явно разрешить Docker управлять трафиком.

-   **Простой способ:** Разрешить трафик, связанный с интерфейсом `docker0`.
    ```sh
    sudo iptables -A FORWARD -i docker0 -j ACCEPT
    sudo iptables -A FORWARD -o docker0 -j ACCEPT
    ```

-   **Более строгий способ:** Разрешать только установленные и связанные соединения.
    ```sh
    # Разрешить ответы от контейнеров наружу
    sudo iptables -A FORWARD -i docker0 -o eth0 -j ACCEPT
    # Разрешить входящий трафик для уже установленных или связанных соединений
    sudo iptables -A FORWARD -i eth0 -o docker0 -m state --state RELATED,ESTABLISHED -j ACCEPT
    ```
    *Примечание: Замените `eth0` на ваш реальный сетевой интерфейс.*

## 6. Проблема TIME_WAIT

### Что такое `TIME_WAIT`?
Когда TCP-соединение закрывается, оно на некоторое время (обычно 60 секунд) переходит в состояние `TIME_WAIT`. Это необходимо для гарантии доставки всех пакетов. На высоконагруженных серверах большое количество сокетов в состоянии `TIME_WAIT` может исчерпать лимит доступных портов.

### Как решить проблему?

1.  **Настройка параметров ядра Linux:**
    *   Разрешить повторное использование сокетов в состоянии `TIME_WAIT` для новых соединений (безопасно):
        ```sh
        sudo sysctl -w net.ipv4.tcp_tw_reuse=1
        ```
    *   Ускорить "переработку" сокетов `TIME_WAIT` (используйте с осторожностью):
        ```sh
        sudo sysctl -w net.ipv4.tcp_tw_recycle=1
        ```
    *   Уменьшить время ожидания в `TIME_WAIT`:
        ```sh
        sudo sysctl -w net.ipv4.tcp_fin_timeout=30
        ```

2.  **Оптимизация приложения:**
    *   **HTTP Keep-Alive:** Позволяет использовать одно TCP-соединение для нескольких HTTP-запросов.
    *   **Connection Pooling:** Использование пула соединений для переиспользования уже установленных.

3.  **Увеличение лимита портов:**
    Расширить диапазон портов для исходящих соединений:
    ```sh
    # Добавить в /etc/sysctl.conf и применить через `sysctl -p`
    net.ipv4.tcp_tw_reuse=1
    ```

### Что такое сокет?

**Сокет** — это специальный файл в операционной системе, который служит конечной точкой для отправки и получения данных между процессами. Эти процессы могут выполняться как на одном и том же компьютере, так и на разных машинах в сети.

### Основные типы сокетов

1.  **Сетевые сокеты (AF_INET, AF_INET6):**
    *   Используются для коммуникации по сети (например, через интернет).
    *   Они привязаны к IP-адресу и порту.
    *   Пример: веб-сервер, который "слушает" порт 80 для входящих HTTP-запросов.

2.  **Unix-сокеты (AF_UNIX):**
    *   Используются для обмена данными между процессами **на одной и той же машине**.
    *   Они не используют сетевой стек (IP-адреса и порты), а вместо этого создают специальный файл в файловой системе.
    *   **Преимущество:** Работают значительно быстрее сетевых сокетов, так как данные не проходят через сетевой интерфейс. Это делает их идеальными для локального IPC (Inter-Process Communication).

**Пример: Docker Socket (`/var/run/docker.sock`)**
Это Unix-сокет, который демон Docker (`dockerd`) использует как API. Клиент `docker` подключается к этому файлу для отправки команд. Доступ к этому файлу равносилен root-доступу к хост-системе.
