# Файловая система Linux

## Стандартная иерархия каталогов (FHS)

-   `/bin`: Основные утилиты командной строки, необходимые для работы системы.
-   `/boot`: Файлы, необходимые для загрузки, включая ядро Linux и конфигурацию загрузчика.
-   `/dev`: Файлы устройств, представляющие аппаратные компоненты.
-   `/etc`: Файлы конфигурации системы и приложений.
-   `/home`: Домашние каталоги пользователей.
-   `/lib`: Библиотеки, необходимые утилитам из `/bin` и `/sbin`.
-   `/media`: Точки монтирования для съёмных носителей (CD, USB).
-   `/mnt`: Точка для временного монтирования файловых систем.
-   `/opt`: Пакеты стороннего программного обеспечения.
-   `/proc`: Виртуальная файловая система с информацией о процессах и ядре.
-   `/root`: Домашний каталог пользователя `root`.
-   `/sbin`: Системные исполняемые файлы, используемые для администрирования.
-   `/sys`: Виртуальная файловая система, предоставляющая интерфейс к драйверам ядра.
-   `/tmp`: Временные файлы.
-   `/usr`: Пользовательские утилиты, библиотеки и данные.
-   `/var`: Переменные данные, такие как логи, почта и базы данных.

## Псевдофайловые системы

Это виртуальные файловые системы, которые не хранят данные на диске, а предоставляют доступ к структурам ядра и системной информации в виде файлов.

-   **procfs (`/proc`)**: Информация о процессах (`/proc/<PID>`), процессоре (`/proc/cpuinfo`), памяти (`/proc/meminfo`) и настройках ядра (`/proc/sys`).
-   **sysfs (`/sys`)**: Информация об устройствах, драйверах и их иерархии. Позволяет управлять питанием (`/sys/power`).
-   **tmpfs (`/dev/shm`, `/run`)**: Хранит файлы в оперативной памяти для сверхбыстрого доступа. Используется для разделяемой памяти и временных файлов служб.
-   **cgroupfs (`/sys/fs/cgroup`)**: Управление ресурсами (CPU, память, I/O) для групп процессов. Основа для контейнеризации (Docker, Kubernetes).

## Файловые дескрипторы

Файловый дескриптор — это целое неотрицательное число, которое ядро использует для идентификации открытого файла или другого ресурса ввода-вывода (сокет, канал).

-   `0` – `stdin` (стандартный ввод)
-   `1` – `stdout` (стандартный вывод)
-   `2` – `stderr` (стандартный вывод ошибок)

Посмотреть открытые файловые дескрипторы для процесса:
```sh
ls -l /proc/<PID>/fd/
```
Или с помощью `lsof`:
```sh
lsof -p <PID>
```

## Анализ дискового пространства

### Свободное место (`df`)

```sh
# Показать свободное место в человекочитаемом формате
df -h

# Показать использование inode (индексных дескрипторов)
df -i
```
Если `inode` используется на 100%, вы не сможете создавать новые файлы, даже если на диске есть свободное место.

### Занятое место (`du`)

```sh
# Показать размер текущей директории
du -sh .

# Показать размер всех поддиректорий на один уровень вглубь
du -h --max-depth=1
```

**Разница между `df` и `du`**: `df` показывает использование диска с точки зрения файловой системы, а `du` — суммарный размер существующих файлов. Расхождения могут возникнуть, если файл был удалён, но всё ещё используется каким-либо процессом. Чтобы найти такие файлы:
```sh
sudo lsof | grep deleted
```

## Мониторинг нагрузки на диски

-   **`iostat`**: Статистика по вводу/выводу для устройств.
-   **`iotop`**: Показывает использование диска процессами в реальном времени (аналог `top` для I/O).
    ```sh
    sudo iotop -oP
    ```
    - `-o`: Показывать только активные процессы.
    - `-P`: Не разделять нагрузку по потокам.
-   **`pidstat`**: Отчёт по использованию ресурсов процессами, включая I/O.
    ```sh
    pidstat -dl 1
    ```

## Ссылки: жёсткие и символические

### Жёсткая ссылка (Hard Link)

-   Это дополнительное имя для существующего файла.
-   Указывает на тот же **inode**, что и оригинал.
-   Не занимает дополнительного места.
-   Нельзя создать для директорий и на разделах других файловых систем.
-   Файл будет удалён с диска только тогда, когда будет удалена последняя жёсткая ссылка на него.
```sh
ln /path/to/original /path/to/hardlink
```

### Символическая ссылка (Symbolic Link / Symlink)

-   Это специальный файл, который содержит **путь** к другому файлу или директории.
-   Имеет свой собственный **inode**.
-   Может указывать на файлы и директории на любых файловых системах.
-   Если оригинал удалить, ссылка станет "битой" (dangling).
```sh
ln -s /path/to/original /path/to/symlink
```

## LVM (Logical Volume Manager)

LVM — это технология управления дисками, которая добавляет слой абстракции между физическими дисками и файловыми системами.

-   **Physical Volume (PV)**: Физический диск или раздел.
-   **Volume Group (VG)**: Группа из одного или нескольких PV, образующая единый пул пространства.
-   **Logical Volume (LV)**: "Раздел", созданный из пространства VG, на котором можно создать файловую систему.

**Преимущества:**
-   Гибкое изменение размера томов (LV) на лету.
-   Создание "снимков" (snapshots) для бэкапов.
-   Объединение нескольких дисков в один большой том.

## RAID (Redundant Array of Independent Disks)

RAID — технология объединения нескольких дисков в один логический массив для повышения производительности или отказоустойчивости.

-   **RAID 0 (Striping)**: Максимальная производительность, нет отказоустойчивости.
-   **RAID 1 (Mirroring)**: Полная отказоустойчивость (зеркалирование), но теряется 50% ёмкости.
-   **RAID 5 (Striping with Parity)**: Баланс между скоростью и надёжностью. Выдерживает отказ одного диска. Минимум 3 диска.
-   **RAID 6 (Striping with Double Parity)**: Повышенная надёжность. Выдерживает отказ двух дисков. Минимум 4 диска.
-   **RAID 10 (1+0)**: Комбинация зеркалирования и чередования. Высокая скорость и надёжность. Минимум 4 диска.

Проверка состояния программного RAID в Linux:
```sh
cat /proc/mdstat
```
