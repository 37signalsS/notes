- /bin — содержит основные утилиты командной строки, необходимые для функционирования системы.
- /boot - содержит файлы, необходимые для загрузки системы, включая файлы конфигурации ядра Linux и загрузчика.
- /dev — содержит файлы устройств, представляющие различные устройства и аппаратные компоненты в системе.
- /etc - содержит файлы конфигурации системы и различных приложений.
- /home - содержит домашние каталоги отдельных пользователей.
- /lib - содержит библиотеки, необходимые утилитам в /bin и /sbin
- /media — точка монтирования для сменных носителей, таких как CD, DVD и USB-накопители.
- /mnt — точка монтирования для временного монтирования файловых систем
- /opt - содержит пакеты стороннего программного обеспечения
- /proc — виртуальная файловая система, содержащая информацию о системном процессе и ядре.
- /root - домашний каталог пользователя root
- /sbin - содержит системные исполняемые файлы, аналогично /bin
- /sys — виртуальная файловая система, которая обеспечивает интерфейс для драйверов устройств ядра.
- /tmp — содержит временные файлы, которые могут быть удалены системой при необходимости освободить место.
- /usr - содержит пользовательские утилиты и библиотеки, а также данные, совместно используемые несколькими пользователями.
- /var — содержит переменные данные, такие как файлы журналов, почтовые спулы и файлы баз данных.

При создании директории внутри нее всегда создается путь до предыдущей директории и путь до текущей директории.

# **Место на диске**

- Свободное место 

``` sh
df -h
```

- Сколько место занимает директория

``` sh
du -s /tmp
```

- inode (служебная инфа о файле), если 100% то плохо

``` sh
df -i
```

Часто бывает что df и du показывают разные значения, это происходит из-за того что du - показывает размер **существующих** файлов, а df - реальное использование дискового пространства(включая удаленные но открытые процессами файлы). Решение проблемы:

```sh
lsof | grep deleted
```

# **Состояние дисков**

- Общая инфа о дисках

``` sh
lsblk
```

- Smart отчет о состоянии жесткого диска или nvme

``` sh
smartctl -a /dev/sda
```

- RAID проверка состояния(надо UU)

``` sh
cat /proc/mdstst
```

# **Нагрузка на диски**

- Сколько данных на диск пишется и так далее

``` sh
iostat
```

``` sh
iotop -o -P
```

-o — показывает только те процессы, которые реально используют диск (без фоновых процессов с нулевой активностью).
-P — группирует потоки процессов, чтобы было видно нагрузку целиком.

В случае отсутствие рута:

```sh
pidstat -dl 1
```


# **LVM**

Это технология управления дисками, которая позволяет создавать гибкие логические тома поверх физических дисков. Она предоставляет следующие преимущества:
1. Гибкость:  
   - Можно легко изменять размер файловых систем без необходимости переформатирования или перезагрузки.
2. Снапшоты:  
   - Поддержка создания моментальных снимков (snapshots), что полезно для резервного копирования.
3. Агрегация дисков:  
   - Можно объединять несколько физических дисков в один логический том.
### Основные компоненты LVM:
1. Physical Volume (PV):  
   - Физический диск или раздел, который добавляется в LVM.
2. Volume Group (VG):  
   - Группа физических томов, объединенных в единый пул дискового пространства.
3. Logical Volume (LV):  
   - Логический том, созданный из пространства Volume Group. На LV можно создавать файловые системы (например, ext4, xfs).

### Пример использования LVM в DevOps:
1. Разделение ресурсов между проектами:  
   - Создание отдельных Logical Volumes для разных проектов или сервисов. Например:

```
 lvcreate -L 10G -n project1 vg_data
   mkfs.ext4 /dev/vg_data/project1
```

Это позволит ограничить доступное место для каждого проекта и избежать "захватывания" всего дискового пространства одним сервисом.

2. Масштабирование:  
   - Если одному из проектов нужно больше места, можно увеличить размер Logical Volume:

```
lvextend -L +5G /dev/vg_data/project1
   resize2fs /dev/vg_data/project1
```


2. Создание снапшотов для резервного копирования:  
   - Снапшоты позволяют зафиксировать состояние файловой системы на определенный момент времени:

```
lvcreate --size 1G --snapshot --name project1_snapshot /dev/vg_data/project1
```

# **Inode** 

Inode(индексный дескриптор) — это структура данных в Unix-подобных файловых системах, которая хранит метаданные о файле. Однако сам inode не содержит имени файла или его содержимого. Вместо этого он хранит следующую информацию:

- Номер inode  
- UID  
- GID  
- Размер  
- Atime (время последнего доступа)  
- Mtime (время последней модификации)  
- Ctime (время последнего изменения метаданных)  
- Размер блока  
- Режим (права доступа и тип файла)  
- Количество жёстких ссылок  
- ACL (списки контроля доступа)  

Имя файла и inode связаны через запись в директории. Это позволяет иметь несколько имен (хардлинков) для одного и того же inode, что делает хардлинки эффективными, так как они ссылаются на одни и те же данные.

# **Жесткая ссылка (hard link)**

- Жесткая ссылка — это дополнительное имя для существующего файла. Она указывает на тот же inode, что и оригинальный файл.
- Удаление оригинального файла не влияет на жесткую ссылку, так как она является независимой точкой доступа к данным.
- Жесткие ссылки могут создаваться только для файлов, но не для директорий.
- Пример команды для создания жесткой ссылки:  
  
```
 ln original_file hard_link
```

# **Символическая ссылка (symlink)**

- Символическая ссылка — это отдельный файл, который содержит путь к другому файлу или директории.
- Если оригинальный файл удаляется, символическая ссылка становится "битой" (dangling symlink), так как она просто хранит путь.
- Символические ссылки могут указывать как на файлы, так и на директории.
- Пример команды для создания символической ссылки:  
  
```
  ln -s original_file symlink
```

### Основные различия:
1. inode: Жесткая ссылка указывает на тот же inode, что и оригинальный файл, а символическая ссылка — это отдельный файл с собственным inode.
2. Поведение при удалении: Жесткая ссылка продолжает работать даже после удаления оригинального файла, а символическая ссылка становится недействительной.
3. Ограничения: Жесткие ссылки нельзя создавать для директорий, а символические ссылки могут ссылаться на что угодно.

# **RAID**

RAID (Redundant Array of Independent Disks) — это технология объединения нескольких физических дисков в один логический том для повышения производительности, отказоустойчивости или их комбинации. RAID может быть реализован как программно (через операционную систему), так и аппаратно (с помощью специальных RAID-контроллеров).

1. RAID 0 (Striping):
- Данные распределяются ("размазываются") по нескольким дискам.
- Преимущества:
  - Высокая производительность чтения/записи.
  - Полное использование дискового пространства.
- Недостатки:
  - Нет избыточности: если один диск выходит из строя, теряются все данные.
- Использование: Подходит для задач, где важна скорость, а отказоустойчивость не критична.

2. RAID 1 (Mirroring):
- Данные дублируются на два или более дисков.
- Преимущества:
  - Отказоустойчивость: если один диск выходит из строя, данные остаются доступными.
- Недостатки:
  - Используется только половина дискового пространства (или меньше, при большем количестве дисков).
- Использование: Подходит для задач, где важна надежность.

3. RAID 5 (Striping with Parity):
- Данные и контрольная сумма (parity) распределяются по всем дискам.
- Преимущества:
  - Баланс между производительностью и отказоустойчивостью.
  - Возможность восстановления данных при выходе из строя одного диска.
- Недостатки:
  - Требуется минимум 3 диска.
  - Скорость записи ниже из-за вычисления контрольной суммы.
- Использование: Подходит для серверов, где важны и производительность, и отказоустойчивость.

4. RAID 6 (Striping with Double Parity):
- Аналогично RAID 5, но с двойной контрольной суммой.
- Преимущества:
  - Возможность восстановления данных при выходе из строя двух дисков.
- Недостатки:
  - Требуется минимум 4 диска.
  - Производительность записи еще ниже.
- Использование: Подходит для больших массивов данных с высокими требованиями к отказоустойчивости.

5. RAID 10 (1+0, Mirroring + Striping):
- Комбинация RAID 1 и RAID 0: данные дублируются и распределяются по нескольким дискам.
- Преимущества:
  - Высокая производительность и отказоустойчивость.
- Недостатки:
  - Требуется минимум 4 диска.
  - Используется только половина дискового пространства.
- Использование: Подходит для критически важных систем, где важны и скорость, и надежность.

### Как проверить RAID?

В Linux можно использовать следующие команды:
1. `cat /proc/mdstat`:
   - Показывает состояние программного RAID.
2. `mdadm --detail /dev/mdX`:
   - Детальная информация о конкретном RAID-массиве.
3. `lsblk`:
   - Показывает все блочные устройства, включая RAID.
