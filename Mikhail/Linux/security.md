# Безопасность в Linux

## Capabilities

Традиционная модель прав в Unix делит все процессы на две категории: непривилегированные (обычные пользователи) и полностью привилегированные (`root`, UID 0). Такой подход "всё или ничего" небезопасен. Механизм **capabilities** решает эту проблему, разделяя всемогущество `root` на отдельные, гранулярные привилегии.

**Как это работает:**
Процесс может иметь только тот набор "способностей", который ему действительно необходим для работы, не получая полных прав суперпользователя. Например, веб-серверу для работы на порту 80 нужна только привилегия `CAP_NET_BIND_SERVICE`, а не полный доступ к системе.

**Преимущества:**
-   **Повышение безопасности:** Если процесс с ограниченным набором capabilities будет скомпрометирован, злоумышленник не получит полные права `root`.
-   **Принцип наименьших привилегий:** Процессы работают с минимально необходимым набором прав.

**Управление capabilities:**

-   **`getcap`**: Показывает capabilities, установленные для файла.
    ```bash
    getcap /usr/bin/ping
    ```

-   **`setcap`**: Устанавливает или удаляет capabilities для файла.
    ```bash
    # Дать бинарному файлу право слушать порты ниже 1024
    sudo setcap 'cap_net_bind_service=+ep' /path/to/binary
    ```
    - `+ep` означает "добавить в набор Effective и Permitted".

## Системный аудит с помощью `auditd`

**`auditd`** — это подсистема аудита в ядре Linux, которая позволяет отслеживать и записывать события, связанные с безопасностью. Она может логировать доступ к файлам, системные вызовы, команды, выполняемые пользователями, и многое другое.

**Основные компоненты:**
-   **`auditd`**: Демон, который собирает информацию из ядра и записывает её в лог-файл (обычно `/var/log/audit/audit.log`).
-   **`auditctl`**: Утилита для управления правилами аудита "на лету".
-   `/etc/audit/audit.rules`**: Файл, в котором хранятся постоянные правила аудита.
-   **`ausearch`**: Утилита для поиска событий в логах аудита.
-   **`aureport`**: Утилита для создания сводных отчётов на основе логов.

**Пример правила аудита:**

Следующее правило будет отслеживать все попытки записи и изменения атрибутов для файла `/etc/passwd`:

```
# /etc/audit/rules.d/auth.rules
-w /etc/passwd -p wa -k passwd_changes
```
-   `-w /etc/passwd`: Установить "наблюдение" за файлом `/etc/passwd`.
-   `-p wa`: Отслеживать операции записи (`w`) и изменения атрибутов (`a`).
-   `-k passwd_changes`: Присвоить ключ `passwd_changes` всем событиям, сгенерированным этим правилом, для удобства поиска.

После добавления правил необходимо перезапустить сервис `auditd`:
```bash
sudo systemctl restart auditd
```

**Поиск событий:**
```bash
# Найти все события с ключом 'passwd_changes'
sudo ausearch -k passwd_changes
```

## GTFOBins: Повышение привилегий в Linux

**GTFOBins** — это не инструмент, а курируемый список (база знаний) Unix-бинарных файлов, которые могут быть использованы для обхода локальных ограничений безопасности и повышения привилегий.

**Зачем это нужно:**
-   **Для атакующих (Red Team):** Это готовый справочник по поиску путей для эскалации привилегий в системе. Если у злоумышленника есть доступ от имени пользователя с правом на `sudo` для `find`, он может посмотреть в GTFOBins и сразу найти команду для получения root-шелла: `sudo find . -exec /bin/sh \; -quit`.
-   **Для защищающихся (Blue Team):** Понимая, какие бинарные файлы могут быть использованы не по назначению, системные администраторы могут:
    -   Ограничивать права `sudo` на эти утилиты.
    -   Настраивать правила аудита (`auditd`) для отслеживания подозрительного использования этих команд.

## traitor: Автоматизация повышения привилегий

**traitor** — этот инструмент сканирует систему на наличие распространенных векторов атак и неправильных конфигураций и пытается их эксплуатировать для получения root-доступа.

**Методы эксплуатации:**
`traitor` использует базу данных известных техник, включая:
-   **GTFOBins:** Автоматически применяет техники из этой базы.
-   **Известные уязвимости ядра:** Например, `dirty_pipe` (CVE-2022-0847).
-   **Уязвимости системных служб:** Например, `pwnkit` (CVE-2021-4034).
-   **Неправильные конфигурации:** Например, права на запись в `docker.sock`.

## Сканеры IOC (Индикаторов Компрометации)

Сканеры IOC предназначены для поиска следов вредоносной активности в системе. Они используют базы данных сигнатур, хэшей, правил и других индикаторов для выявления потенциально скомпрометированных систем.

### Loki

**Loki** — это простой и быстрый сканер IOC, который использует следующие методы обнаружения:
-   **Имена файлов:** Поиск по регулярным выражениям, соответствующим известным вредоносным файлам.
-   **YARA-правила:** Применение YARA-правил к файлам и памяти запущенных процессов.
-   **Хэши:** Сверка хэшей файлов с базами известных вредоносных файлов (MD5, SHA1, SHA256).
-   **Проверка C2:** Обнаружение подключений к известным командным центрам (Command & Control).

**Важно:** Проект больше не находится в активной разработке. Автор рекомендует использовать более современный аналог — THOR Lite.

### THOR Lite

**THOR Lite** — это бесплатная версия мощного сканера THOR от компании Nextron Systems. Он является прямым наследником Loki и предлагает более продвинутые возможности, актуальные базы сигнатур и регулярные обновления.

## Wazuh: Платформа SIEM и XDR

**Wazuh** — это бесплатная open-source платформа для обеспечения кибербезопасности, которая объединяет функциональность **SIEM** (Security Information and Event Management) и **XDR** (Extended Detection and Response). Она предназначена для защиты конечных точек (серверов, рабочих станций), облачных сред и контейнеров.

**Архитектура:**
Платформа состоит из нескольких ключевых компонентов:
-   **Wazuh Agent:** Легковесный агент, который устанавливается на конечные точки для сбора логов, мониторинга событий и выполнения команд от сервера.
-   **Wazuh Server:** Центральный компонент, который анализирует данные от агентов, обрабатывает их с помощью правил и декодеров, и генерирует алерты.
-   **Wazuh Indexer:** Распределенный поисковый и аналитический движок, основанный на OpenSearch. Он индексирует и хранит все сгенерированные алерты и события.
-   **Wazuh Dashboard:** Веб-интерфейс (на базе OpenSearch Dashboards) для визуализации данных, анализа алертов и управления платформой.

**Ключевые возможности:**
-   **Сбор и анализ логов:** Централизованный сбор и анализ логов из различных источников.
-   **Мониторинг целостности файлов (FIM):** Отслеживание изменений в файлах и каталогах.
-   **Обнаружение уязвимостей:** Сканирование систем на наличие известных уязвимостей (CVE).
-   **Оценка конфигурации безопасности (SCA):** Проверка систем на соответствие стандартам безопасности (например, CIS Benchmarks).
-   **Обнаружение вторжений:** Анализ логов для выявления подозрительной активности и атак.
-   **Активное реагирование (Active Response):** Автоматическое выполнение действий на агенте в ответ на определенные триггеры (например, блокировка IP-адреса).
