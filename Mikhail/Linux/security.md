# Безопасность в Linux

## Capabilities

Традиционная модель прав в Unix делит все процессы на две категории: непривилегированные (обычные пользователи) и полностью привилегированные (`root`, UID 0). Такой подход "всё или ничего" небезопасен. Механизм **capabilities** решает эту проблему, разделяя всемогущество `root` на отдельные, гранулярные привилегии.

**Как это работает:**
Процесс может иметь только тот набор "способностей", который ему действительно необходим для работы, не получая полных прав суперпользователя. Например, веб-серверу для работы на порту 80 нужна только привилегия `CAP_NET_BIND_SERVICE`, а не полный доступ к системе.

**Преимущества:**
-   **Повышение безопасности:** Если процесс с ограниченным набором capabilities будет скомпрометирован, злоумышленник не получит полные права `root`.
-   **Принцип наименьших привилегий:** Процессы работают с минимально необходимым набором прав.

**Управление capabilities:**

-   **`getcap`**: Показывает capabilities, установленные для файла.
    ```bash
    getcap /usr/bin/ping
    ```

-   **`setcap`**: Устанавливает или удаляет capabilities для файла.
    ```bash
    # Дать бинарному файлу право слушать порты ниже 1024
    sudo setcap 'cap_net_bind_service=+ep' /path/to/binary
    ```
    - `+ep` означает "добавить в набор Effective и Permitted".

## Системный аудит с помощью `auditd`

**`auditd`** — это подсистема аудита в ядре Linux, которая позволяет отслеживать и записывать события, связанные с безопасностью. Она может логировать доступ к файлам, системные вызовы, команды, выполняемые пользователями, и многое другое.

**Основные компоненты:**
-   **`auditd`**: Демон, который собирает информацию из ядра и записывает её в лог-файл (обычно `/var/log/audit/audit.log`).
-   **`auditctl`**: Утилита для управления правилами аудита "на лету".
-   `/etc/audit/audit.rules`**: Файл, в котором хранятся постоянные правила аудита.
-   **`ausearch`**: Утилита для поиска событий в логах аудита.
-   **`aureport`**: Утилита для создания сводных отчётов на основе логов.

**Пример правила аудита:**

Следующее правило будет отслеживать все попытки записи и изменения атрибутов для файла `/etc/passwd`:

```
# /etc/audit/rules.d/auth.rules
-w /etc/passwd -p wa -k passwd_changes
```
-   `-w /etc/passwd`: Установить "наблюдение" за файлом `/etc/passwd`.
-   `-p wa`: Отслеживать операции записи (`w`) и изменения атрибутов (`a`).
-   `-k passwd_changes`: Присвоить ключ `passwd_changes` всем событиям, сгенерированным этим правилом, для удобства поиска.

После добавления правил необходимо перезапустить сервис `auditd`:
```bash
sudo systemctl restart auditd
```

**Поиск событий:**
```bash
# Найти все события с ключом 'passwd_changes'
sudo ausearch -k passwd_changes
```
