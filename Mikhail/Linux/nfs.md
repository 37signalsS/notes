# NFS (Network File System)

**NFS (сетевая файловая система)** — это протокол, который позволяет "расшарить" директорию на сервере, а затем подключить (смонтировать) её на клиенте. Клиент сможет работать с файлами в этой директории так, как если бы они были локальными.

## 1. Принцип работы

NFS работает по клиент-серверной модели:
-   **NFS-сервер**: Экспортирует (делает доступными) одну или несколько своих директорий в сети.
-   **NFS-клиент**: Монтирует экспортированные директории к себе в файловую систему.

Для обмена данными используется протокол **RPC (Remote Procedure Call)**. Служба `rpcbind` (или `portmap`) на сервере действует как диспетчер, сообщая клиентам, на каких портах работают нужные службы NFS.

## 2. Настройка NFS-сервера

### Шаг 1: Установка

Установите пакет `nfs-kernel-server`.

```sh
# Для Debian/Ubuntu
sudo apt update
sudo apt install nfs-kernel-server
```

### Шаг 2: Создание экспортируемой директории

Создайте директорию, которую вы хотите сделать доступной для клиентов.

```sh
sudo mkdir -p /srv/nfs/shared
sudo chown nobody:nogroup /srv/nfs/shared
```
> **Важно:** Изменение владельца на `nobody:nogroup` — это стандартная практика безопасности, которая предотвращает проблемы с правами доступа.

### Шаг 3: Настройка экспорта в `/etc/exports`

Основной файл конфигурации — `/etc/exports`. Он определяет, какие директории экспортировать и кто имеет к ним доступ.

**Формат:**
```
<директория> <клиент1>(<опции>) <клиент2>(<опции>)
```

**Пример:**
```
# Сделать директорию доступной для клиента 10.0.0.10 с правами на чтение/запись
/srv/nfs/shared 10.0.0.10(rw,sync,no_subtree_check)
```

**Основные опции:**

| Опция | Описание |
| :--- | :--- |
| `ro` | Только чтение (по умолчанию). |
| `rw` | Разрешить чтение и запись. |
| `sync` | Сервер подтверждает запись только после сохранения данных на диск. Надёжно, но медленнее. |
| `async` | Сервер подтверждает запись до сохранения на диск. Быстрее, но есть риск потери данных при сбое. |
| `root_squash` | **(По умолчанию, безопасно)**. Запросы от пользователя `root` на клиенте выполняются от имени анонимного пользователя `nobody` на сервере. |
| `no_root_squash` | **(Небезопасно)**. Разрешает `root` на клиенте иметь полные права `root` на сервере в экспортируемой директории. |
| `no_subtree_check` | Отключает проверку поддиректорий, что может повысить производительность. |

### Шаг 4: Применение конфигурации

После изменения `/etc/exports` примените конфигурацию:

```sh
sudo exportfs -a
```

И перезапустите сервис NFS:
```sh
sudo systemctl restart nfs-kernel-server
```

## 3. Настройка NFS-клиента

### Шаг 1: Установка

Установите пакет `nfs-common`.

```sh
# Для Debian/Ubuntu
sudo apt update
sudo apt install nfs-common
```

### Шаг 2: Просмотр доступных ресурсов

Чтобы узнать, какие директории экспортирует сервер, используйте `showmount`.

```sh
showmount -e <IP_адрес_сервера>
```

### Шаг 3: Создание точки монтирования

Создайте пустую директорию на клиенте, куда будет монтироваться сетевая папка.

```sh
sudo mkdir -p /mnt/nfs/shared
```

### Шаг 4: Временное монтирование

Используйте команду `mount` для проверки.

```sh
sudo mount -t nfs <IP_сервера>:<путь_на_сервере> <локальная_точка_монтирования>
# Пример:
sudo mount -t nfs 10.0.0.5:/srv/nfs/shared /mnt/nfs/shared
```

### Шаг 5: Автоматическое монтирование (`/etc/fstab`)

Чтобы директория монтировалась автоматически при загрузке, добавьте запись в `/etc/fstab`.

**Формат:**
```
<сервер>:<путь>  <точка_монтирования>  nfs  <опции>  0  0
```

**Пример:**
```
10.0.0.5:/srv/nfs/shared  /mnt/nfs/shared   nfs   defaults,nofail,noatime  0  0
```

**Полезные опции для `fstab`:**

| Опция | Описание |
| :--- | :--- |
| `defaults` | Набор стандартных опций (`rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`). |
| `nofail` | Система не будет останавливать загрузку, если NFS-сервер недоступен. |
| `noatime` | Отключает обновление времени доступа к файлам, что повышает производительность. |
| `hard` | **(По умолчанию)**. Если сервер перестаёт отвечать, процесс, обращающийся к файлу, "зависнет" до восстановления связи. |
| `soft` | Если сервер не отвечает, процесс получит ошибку ввода-вывода через некоторое время. **Может привести к повреждению данных.** |
| `intr` | (Устарело, но встречается). Позволяло прерывать "зависший" процесс. В современных ядрах это поведение включено по умолчанию. |

## 4. Устранение неполадок

-   **Монтирование "зависает" или команда `df` не отвечает:**
    -   **Причина:** NFS-сервер стал недоступен, а клиент использует опцию `hard` (по умолчанию).
    -   **Решение:** Убедитесь, что сервер доступен и служба NFS на нём запущена. Если проблема возникает часто, рассмотрите добавление опции `nofail` в `fstab`.

-   **Ошибка `Permission denied`:**
    -   **Причина:** IP-адрес клиента не указан в `/etc/exports` на сервере, либо указан с неправильными правами (например, `ro` вместо `rw`).
    -   **Решение:** Проверьте конфигурацию `/etc/exports` на сервере и убедитесь, что файрвол не блокирует доступ.
