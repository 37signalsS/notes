# NFS (Network File System): Настройка и лучшие практики

**NFS (сетевая файловая система)** — это протокол, который позволяет сделать директорию на сервере доступной по сети. Клиенты могут монтировать эту директорию и работать с файлами так, как если бы они были локальными. Это стандартное решение для создания общего хранилища в Unix-подобных системах.

---

## 1. Ключевые концепции

-   **Клиент-серверная модель**: 
    -   **NFS-сервер**: Экспортирует (делает доступными) свои директории.
    -   **NFS-клиент**: Монтирует экспортированные директории к себе в файловую систему.

-   **RPC (Remote Procedure Call)**: Механизм, который NFS использует для коммуникации. Служба `rpcbind` сообщает клиентам, на каких портах работают службы NFS. Для NFSv4+ это менее критично, так как он стремится использовать один порт (2049).

-   **`root_squash` (Подавление root)**: Важнейшая функция безопасности. Если `root` на клиенте пытается создать файл в NFS-директории, сервер автоматически понижает его права до анонимного пользователя (`nobody:nogroup`). Это предотвращает получение полного контроля над файловой системой сервера.

-   **Версии NFS**: Рекомендуется использовать **NFSv4**, так как она более производительна, безопасна и лучше работает с файрволами.

## 2. Настройка NFS-сервера

### Шаг 1: Установка

```bash
# Для Debian/Ubuntu
sudo apt update
sudo apt install nfs-kernel-server
```

### Шаг 2: Создание экспортируемой директории

```bash
sudo mkdir -p /srv/nfs/shared
# Устанавливаем безопасного владельца
sudo chown nobody:nogroup /srv/nfs/shared
```

### Шаг 3: Настройка экспорта в `/etc/exports`

Это главный конфигурационный файл сервера. Он определяет, *что* и *кому* разрешено монтировать.

**Формат:** `<директория> <клиент>(<опции>)`

**Пример:**
```ini
# Разрешить доступ клиенту 10.0.0.10
/srv/nfs/shared 10.0.0.10(rw,sync,no_subtree_check)

# Разрешить доступ всей подсети 10.0.0.0/24
/srv/nfs/data 10.0.0.0/24(rw,sync,no_subtree_check)
```

**Основные опции:**

| Опция             | Описание                                                                                             |
| :---------------- | :--------------------------------------------------------------------------------------------------- |
| `ro` / `rw`       | Только чтение / Чтение и запись.                                                                     |
| `sync`            | **(Надежно)** Сервер подтверждает запись только после сохранения на диск. Немного медленнее.          |
| `async`           | **(Быстро, рискованно)** Сервер подтверждает запись до сохранения. Риск потери данных при сбое.        |
| `root_squash`     | **(Безопасно, по умолчанию)** Запросы от `root` на клиенте выполняются от имени `nobody`.             |
| `no_root_squash`  | **(ОПАСНО)** Позволяет `root` на клиенте иметь полные права `root` на сервере в экспортируемой папке. |
| `no_subtree_check`| Отключает проверку поддиректорий, что может повысить производительность. Рекомендуется.              |

### Шаг 4: Настройка файрвола

Чаще всего проблемы с NFS связаны с файрволом. Разрешите доступ к службе NFS.

```bash
# Пример для ufw
sudo ufw allow from 10.0.0.0/24 to any app NFS
```

### Шаг 5: Применение конфигурации

```bash
# Применить изменения из /etc/exports
sudo exportfs -a

# Перезапустить сервис NFS
sudo systemctl restart nfs-kernel-server
```

## 3. Настройка NFS-клиента

### Шаг 1: Установка

```bash
# Для Debian/Ubuntu
sudo apt update
sudo apt install nfs-common
```

### Шаг 2: Просмотр доступных ресурсов

Узнайте, какие директории экспортирует сервер.

```bash
showmount -e <IP_адрес_сервера>
```

### Шаг 3: Монтирование

1.  **Создайте точку монтирования:**
    ```bash
    sudo mkdir -p /mnt/nfs/shared
    ```

2.  **Временное монтирование (для проверки):**
    ```bash
    sudo mount -t nfs 10.0.0.5:/srv/nfs/shared /mnt/nfs/shared
    ```

3.  **Автоматическое монтирование через `/etc/fstab` (рекомендуется):**
    Добавьте строку в `/etc/fstab` для автоматического монтирования при загрузке.

    **Пример надежной конфигурации:**
    ```ini
    # <сервер>:<путь>             <точка_монтирования>  <тип>  <опции>                      <dump> <pass>
    10.0.0.5:/srv/nfs/shared    /mnt/nfs/shared       nfs    hard,nofail,noatime,_netdev    0      0
    ```

    **Ключевые опции для `fstab`:**

    | Опция     | Описание                                                                                                   |
    | :-------- | :--------------------------------------------------------------------------------------------------------- |
    | `hard`    | **(Надежно)** Если сервер перестает отвечать, процесс "зависнет" до восстановления связи, предотвращая потерю данных. |
    | `soft`    | **(Рискованно)** Процесс получит ошибку ввода-вывода. Может привести к повреждению данных. Не рекомендуется. |
    | `nofail`  | Система не будет останавливать загрузку, если NFS-сервер недоступен.                                        |
    | `noatime` | Отключает обновление времени доступа к файлам, что повышает производительность.                             |
    | `_netdev` | **(Важно!)** Указывает системе монтировать этот ресурс только после того, как будет поднята сеть.            |

## 4. Устранение неполадок

-   **Монтирование "зависает" или команда `df` не отвечает:**
    -   **Причина:** NFS-сервер стал недоступен, а клиент использует опцию `hard` (правильное поведение).
    -   **Решение:** Проверьте сетевое соединение и доступность сервера. Убедитесь, что служба `nfs-kernel-server` запущена на сервере: `systemctl status nfs-kernel-server`.

-   **Ошибка `Permission denied` при монтировании или доступе к файлам:**
    -   **Причина №1 (Сервер):** IP-адрес клиента не указан в `/etc/exports` или указан с неправильными правами (например, `ro` вместо `rw`).
    -   **Причина №2 (Файрвол):** Файрвол на сервере блокирует подключения. Проверьте правила `ufw` или `iptables`.

-   **Ошибка `mount.nfs: Connection timed out`:**
    -   **Причина:** Почти всегда проблема в сети или файрволе. Клиент не может достучаться до RPC-портов сервера.
    -   **Решение:** Проверьте `ping` до сервера и убедитесь, что файрвол на сервере настроен правильно.
