# **Имя отчество (PID PPID)**

Здесь все довольно очевидно: PID (Process ID) — это уникальный номер, присваиваемый процессу ядром для контроля его выполнения и предоставления ресурсов. Каждый процесс также имеет атрибут PPID (Parent Process ID), который совпадает с идентификатором PID родительского процесса, то есть процесса, который его инициировал. 

Вариант получения PID и PPID:

```sh
pstree -p
```

# **Сигналы**

 Это программные прерывания, которые отправляются процессам для уведомления об определенных событиях. Они используются для управления поведением процессов (например, завершения, приостановки или перезапуска).

Примеры распространенных сигналов(kill + сигнал + PID, или pkill имя_сервиса):
- SIGTERM (15): Запрос на завершение процесса (по умолчанию).Может быть проигнорирован процессом
- SIGKILL (9): Принудительное завершение процесса. Обязателене для исполнения процессом
- SIGSTOP (17/19/23): Приостановка процесса.
- SIGCONT (18): Возобновление остановленного процесса.
- SIGHUP (1): Уведомление о потере терминала (часто используется для перечитывания конфигурации, например, nginx -s reload’).
- SIGINT(2): Ctrl+C(похож на SIGTERM)

# **Процессор**

- Вывод top: 

us - сколько потратили времени на операции в пользовательском режиме

sy - время потраченное на выполнение операций системы ядра

ni - процент времени на выполнение операций с изменненым приоритетом через команду nice

id - сколько процессор простаивает

wa - процент времени когда система ожидает завершения операций ввода/вывода, увеличение - проблемы и дисками или сетью

si - аппаратные и программные прерывания

load average - показывает среднее кол-во процессов и операция ввода/вывода в процессорной очереди 

# **OOM_killer**

Очки негодности  - чем выше это значение, тем вероятнее, что процесс будет убит. 

``` sh
cat /proc/<PID>/oom_adj

cat /proc/<PID>/oom_score_adj

cat /proc/<PID>/oom_score
```

1. **oom_adj —** числовой модификатор от -17 до 15. Является более старым подходом для определения приоритетов киллера.
2. **oom_score_adj  —** более новый файл для настройки приоритетов. Используется для настройки через systemd. Его изменение приводит к автоматическому перерасчету параметра **oom_adj**. 
3. **oom_score —** текущий OOM-счет для процесса. Его значение варьируют от 0 до 1000.

Можно повысить или понизить репутацию для процесса: для выставления репутации -1000:

``` sh
 sudo echo -1000 > /proc/174244/oom_score_adj
```

Но правильнее задать очки в самом systemd, в юните для сервиса, этот параметр:

```
[Service]  
OOMScoreAdjust=-1000
```

# **Как посмотреть файлы, используемые процессом?**

lsof — это утилита, которая показывает список открытых файлов для каждого процесса в системе      

```
lsof -p <PID>
```

-u user: Показать файлы, открытые определённым пользователем.
-c nginx | grep config: Показать файлы, используемые nginx в качестве конфиг файла.
+D directory: Показать процессы, использующие файлы в указанной директории.

Пример использования lsof 

- Вы заметили, что процесс потребляет много ресурсов или "завис". Используйте `lsof` или `/proc/<PID>/fd/`, чтобы проверить, какие файлы он использует. Возможно, процесс застрял на чтении большого файла или заблокирован из-за отсутствия доступа к файлу.

- Если вы удалили файл, но место на диске не освободилось, это может быть связано с тем, что файл всё ещё открыт каким-то процессом. Команда `lsof | grep deleted` поможет найти такие процессы.

- Если вы подозреваете, что процесс был скомпрометирован, проверьте, какие файлы он открывает. Например, если процесс читает `/etc/passwd` или записывает в `/tmp`, это может быть признаком атаки.

- В контейнерах Docker или Kubernetes вы можете использовать `lsof` или `/proc` для анализа, какие файлы контейнер использует из хостовой системы (например, mounted volumes или configmaps).

- При миграции или обновлении программного обеспечения важно знать, какие файлы и библиотеки использует процесс, чтобы избежать поломок.

# **Exit code**

**Exit code**(экзит код) (код завершения) — это целочисленное значение, которое программа или команда возвращает после своего завершения.

```sh
echo $0
```

- Стандартные значения exit codes, когда все гуд:

0

- Ненулевые значения:

`1`: Общая ошибка.
`2`: Неправильное использование команды (например, неверные аргументы).
`126`: Команда не может быть выполнена (например, из-за отсутствия прав). `127`: Команда не найдена.
`128 + N`: Ошибки, связанные с сигналами (например, `130` — прерывание через `Ctrl+C`).


# **Утечки памяти**

Использование cgroups

- В Linux контроль групп (control groups) позволяет ограничивать использование ресурсов.

```
systemd-run --scope -p MemoryMax=500M your-command
```

valgrind

- Инструмент для обнаружения утечек памяти.

```
valgrind --leak-check=full ./your-program
```

strace

- Отслеживание системных вызовов процесса для анализа его поведения.

```
strace -e trace=mmap,munmap -p <PID>
```
