# Управление логами в Linux


## 1. Классическая система: `rsyslog` и текстовые файлы

Эта система записывает события в текстовые файлы, обычно в директории `/var/log`. Она проста, надежна и легко интегрируется со скриптами.

### Основные файлы

-   `/var/log/syslog` (Debian/Ubuntu) или `/var/log/messages` (CentOS/RHEL): Главный системный лог.
-   `/var/log/auth.log` (Debian/Ubuntu) или `/var/log/secure` (CentOS/RHEL): События аутентификации (входы, `sudo`).
-   `/var/log/dmesg`: Сообщения ядра при загрузке (диагностика оборудования).
-   `/var/log/boot.log`: Лог процесса загрузки.

### Инструменты для анализа

-   **`tail`**: Просмотр конца файла в реальном времени.
    ```bash
    # Показать последние 50 строк и следить за обновлениями
    tail -f -n 50 /var/log/syslog
    ```

-   **`less`**: Мощный просмотрщик с поиском и фильтрацией.
    ```bash
    less /var/log/syslog
    ```
    **Полезные команды в `less`:**
    -   `Shift + F`: Режим `tail -f`.
    -   `/шаблон`: Поиск вперед.
    -   `?шаблон`: Поиск назад.
    -   `&шаблон`: Показать только строки, содержащие "шаблон".
    -   `&!шаблон`: Скрыть строки, содержащие "шаблон".

### Ротация логов (`logrotate`)

Чтобы лог-файлы не занимали все место на диске, утилита `logrotate` периодически их архивирует и удаляет.
-   **Основной конфиг:** `/etc/logrotate.conf`
-   **Конфиги для отдельных служб:** `/etc/logrotate.d/`

## 2. Современная система: `systemd-journald`

`journald` — это централизованная служба, которая собирает логи от всех компонентов системы в структурированном бинарном формате. Основной инструмент для работы — `journalctl`.

### Ключевые команды `journalctl`

-   **Просмотр в реальном времени:**
    ```bash
    # Следить за всеми логами
    journalctl -f
    ```

-   **Фильтрация по службе (unit):**
    ```bash
    # Показать логи только для nginx и следить за ними
    journalctl -u nginx.service -f
    ```

-   **Фильтрация по времени:**
    ```bash
    # Логи за последний час
    journalctl --since "1 hour ago"

    # Логи за определённый период
    journalctl --since "2024-10-20 10:00:00" --until "2024-10-20 11:00:00"
    ```

-   **Фильтрация по уровню приоритета:**
    ```bash
    # Показать только ошибки (err) и более критичные сообщения
    journalctl -p err
    ```
    **Уровни (от высшего к низшему):** `emerg` (0), `alert` (1), `crit` (2), `err` (3), `warning` (4), `notice` (5), `info` (6), `debug` (7).

-   **Просмотр логов ядра (аналог `dmesg`):**
    ```bash
    journalctl -k
    ```

-   **Структурированный вывод:**
    `journald` хранит метаданные для каждого сообщения. Их можно вывести в формате JSON.
    ```bash
    # Вывести последние 5 сообщений в формате JSON
    journalctl -n 5 -o json-pretty
    ```

**Примечание:** По умолчанию `journald` хранит логи в `/run/log/journal`, и они очищаются при перезагрузке. Для постоянного хранения создайте директорию: `sudo mkdir -p /var/log/journal`.

## 3. Аудит доступа: `auditd`

`auditd` — это система, которая отслеживает события на уровне ядра (системные вызовы). Она отвечает на вопросы: **кто, когда, что и с каким файлом сделал**.

### Пример: отслеживание изменений файла

1.  **Установить правило для отслеживания.**
    Отследим, кто изменяет (`w`) или меняет атрибуты (`a`) файла `/etc/hosts`.
    ```bash
    # -w /path/to/file: путь к файлу
    # -p wa: права доступа (w - write, r - read, x - execute, a - attribute change)
    # -k key_name: уникальный ключ для поиска
    sudo auditctl -w /etc/hosts -p wa -k hosts_file_changes
    ```

2.  **Найти события в логе.**
    Для поиска по ключу используется `ausearch`.
    ```bash
    sudo ausearch -k hosts_file_changes
    ```
    Вывод покажет `uid` (ID пользователя), `pid` (ID процесса) и команду, которая изменила файл.

3.  **Сгенерировать отчет (опционально).**
    Утилита `aureport` помогает создавать сводные отчеты из логов аудита.
    ```bash
    # Отчет о событиях аутентификации
    sudo aureport -au
    ```

**Важно:** Правила, добавленные через `auditctl`, сбрасываются после перезагрузки. Для постоянного хранения добавляйте их в файл `/etc/audit/rules.d/audit.rules`.
