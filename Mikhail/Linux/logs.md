# Логи в Linux


## 1. Традиционные лог-файлы (rsyslog)

Эта система записывает логи в текстовые файлы, обычно расположенные в директории `/var/log`.

### Основные файлы

-   `/var/log/syslog` (Debian/Ubuntu) или `/var/log/messages` (CentOS/RHEL): Основной системный лог для сообщений от ядра и служб.
-   `/var/log/auth.log` (Debian/Ubuntu) или `/var/log/secure` (CentOS/RHEL): Лог аутентификации (попытки входа, `sudo`).
-   `/var/log/dmesg`: Сообщения ядра, сгенерированные при загрузке. Полезно для диагностики оборудования.
-   `/var/log/boot.log`: Лог процесса загрузки системы.

### Инструменты для просмотра

-   **`tail`**: Показывает конец файла. Идеально для просмотра логов в реальном времени.
    ```sh
    # Показать последние 50 строк и следить за обновлениями
    tail -f -n 50 /var/log/syslog
    ```

-   **`head`**: Показывает начало файла.
    ```sh
    # Показать первые 50 строк
    head -n 50 /var/log/syslog
    ```

-   **`less`**: Мощный инструмент для просмотра всего файла с возможностью навигации и поиска.
    ```sh
    less /var/log/syslog
    ```
    **Полезные команды в `less`:**
    -   `Shift + F`: Режим `tail -f` (просмотр в реальном времени).
    -   `/шаблон`: Поиск строк, содержащих "шаблон".
    -   `&шаблон`: Отобразить только строки, содержащие "шаблон".
    -   `&!шаблон`: Отобразить строки, НЕ содержащие "шаблон".
    -   `-N`: Запустить `less` с нумерацией строк.

## 2. Современная система логирования (journald)

`systemd-journald` — это демон, который собирает и хранит логи в структурированном бинарном формате. Основной инструмент для работы с ним — `journalctl`.

### Основные команды `journalctl`

-   **Просмотр всех логов (аналог `less`):**
    ```sh
    journalctl
    ```

-   **Просмотр логов в реальном времени:**
    ```sh
    journalctl -f
    ```

-   **Фильтрация по службе (unit):**
    ```sh
    # Показать логи только для nginx и следить за ними
    journalctl -u nginx -f
    ```

-   **Фильтрация по времени:**
    ```sh
    # Логи за последний час
    journalctl --since "1 hour ago"

    # Логи за определённый день
    journalctl --since "2024-10-20 10:00:00" --until "2024-10-20 11:00:00"
    ```

-   **Фильтрация по уровню приоритета:**
    ```sh
    # Показать только ошибки и более критичные сообщения
    journalctl -p err
    ```

### Уровни логирования

| Уровень | Ключевое слово | Описание                  |
| :------ | :------------- | :------------------------ |
| **0**   | `emerg`        | Аварийная ситуация        |
| **1**   | `alert`        | Тревога                   |
| **2**   | `crit`         | Критическая ошибка        |
| **3**   | `err`          | Ошибка (Error)            |
| **4**   | `warning`      | Предупреждение (Warning)  |
| **5**   | `notice`       | Уведомление               |
| **6**   | `info`         | Информация                |
| **7**   | `debug`        | Отладочные сообщения      |

## 3. Аудит доступа к файлам (auditd)

`auditd` — это система аудита, которая отслеживает события на уровне ядра, такие как системные вызовы. Она позволяет точно узнать, **кто, когда и как** взаимодействовал с файлами или системой.

### Пример использования: отслеживание изменений файла

1.  **Установить правило для отслеживания.**
    Мы хотим знать, кто изменяет (`w`) конфигурацию Nginx.
    ```sh
    # -w /path/to/file: путь к файлу
    # -p w: права доступа для отслеживания (w - write, r - read, x - execute, a - attribute change)
    # -k key_name: уникальный ключ для удобного поиска
    sudo auditctl -w /etc/nginx/nginx.conf -p wa -k nginx_config_changes
    ```

2.  **Найти события в логе аудита.**
    Когда файл будет изменён, можно найти запись в логе с помощью `ausearch`.
    ```sh
    # Искать события по нашему ключу
    sudo ausearch -k nginx_config_changes
    ```
    Вывод покажет `uid` (ID пользователя), `pid` (ID процесса) и команду, которая внесла изменения.

**Важно:** Правила, добавленные через `auditctl`, сбрасываются после перезагрузки. Для постоянного хранения их нужно добавлять в файл `/etc/audit/rules.d/audit.rules`.
