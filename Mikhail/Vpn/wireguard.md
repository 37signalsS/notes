# Автоматическое обновление WireGuard при смене IP-адреса сервера

Этот документ описывает решение проблемы, при которой VPN-соединение WireGuard перестает работать после смены динамического IP-адреса на сервере.

---

## 1. Описание проблемы

Если WireGuard-сервер находится за NAT или имеет динамический публичный IP-адрес, который периодически меняется, клиенты теряют к нему доступ. Это происходит потому, что WireGuard при запуске кэширует IP-адрес, на котором он принимает входящие подключения. После смены внешнего IP-адреса сервер продолжает "слушать" старый, уже неактуальный адрес.

## 2. Решение

Решение заключается в создании systemd-таймера, который будет периодически выполнять скрипт. Скрипт принудительно переинициализирует слушающий сокет WireGuard, заставляя его "узнать" новый IP-адрес сервера без полного перезапуска службы.

---

## 3. Реализация

### Шаг 1: Создание скрипта

Создайте исполняемый файл `/usr/local/bin/wg-rebind.sh`. Этот скрипт выполняет команду, которая заставляет WireGuard перепривязать свой сокет.

```bash
#!/bin/bash
#
# Скрипт для переинициализации слушающего сокета WireGuard.
# Необходим для серверов с динамическим IP-адресом.

# --- НАСТРОЙКИ ---
# Имя вашего WireGuard-интерфейса
IFACE="wg0"
# Порт, который слушает WireGuard
PORT="51820"
# --- КОНЕЦ НАСТРОЕК ---

# Команда `wg set ... listen-port` заставляет WireGuard перепривязать сокет,
# что позволяет ему определить новый публичный IP-адрес сервера.
echo "Rebinding WireGuard interface '$IFACE' to port $PORT..."
wG set "$IFACE" listen-port "$PORT"
echo "Done."
```

Сделайте скрипт исполняемым:
```bash
sudo chmod +x /usr/local/bin/wg-rebind.sh
```

### Шаг 2: Создание systemd-сервиса

Создайте файл юнита `/etc/systemd/system/wg-rebind.service`, который будет запускать скрипт.

```ini
[Unit]
Description=Rebind WireGuard listening port
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/wg-rebind.sh
```

### Шаг 3: Создание systemd-таймера

Создайте файл таймера `/etc/systemd/system/wg-rebind.timer`, который будет запускать сервис каждые 5 минут.

```ini
[Unit]
Description=Run wg-rebind.service every 5 minutes

[Timer]
# Запустить через 1 минуту после загрузки системы
OnBootSec=1min
# Запускать каждые 5 минут
OnUnitActiveSec=5min

[Install]
WantedBy=timers.target
```

### Шаг 4: Активация таймера

Перезагрузите конфигурацию systemd, а затем включите и запустите таймер.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now wg-rebind.timer
```

---

## 4. Проверка

Вы можете убедиться, что таймер активен и запланирован для запуска, с помощью следующей команды:

```bash
systemctl list-timers | grep wg-rebind
```

Вывод должен показать, что таймер `wg-rebind.timer` активен и ожидает следующего запуска.

## 5. Важное замечание: Файрвол

Это решение только обновляет IP-адрес на стороне WireGuard. Если вы используете файрвол (например, `ufw`, `iptables`) или правила безопасности вашего хостинг-провайдера, **не забудьте обновить их**, чтобы разрешить входящий трафик на порт WireGuard (`51820/udp`) с нового IP-адреса. Этот процесс, как правило, требует автоматизации с помощью API вашего провайдера.
