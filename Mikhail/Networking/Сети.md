# IP-адрес и маска подсети

IP (Internet Protocol) — межсетевой протокол модели OSI, уникальный внутри подсети идентификатор устройства третьего (сетевого) уровня. Его главная задача — адресация узлов сети и маршрутизация пакетов до них. Ключевые сущности для межсетевого протокола: IP-адрес, маска подсети и маршрут. IP-адрес состоит из четырех октетов (4-байтовое или 32-битное число), последний из которых указывает номер хоста в сети.

Маска подсети (32-битное число) — служит для разделения сетевой части (адреса подсети) и части хоста IP-адреса.

# MAC-адрес

MAC-адрес – это уникальный 48-битный аппаратный номер компьютера, который встроен в сетевую карту на стадии производства. MAC-адрес также известен как физический адрес сетевого устройства. В стандарте IEEE 802, канальный уровень (второй уровень) разделен на два подуровня:

*   Подуровень управления логическим каналом (LLC)
*   Подуровень управления доступом к среде (MAC)

MAC-адрес используется подуровнем управления доступом к среде (MAC) канального (второго) уровня модели OSI.

# Что происходит, когда вы вводите адрес сайта

**Первый этап: DNS-запрос и поиск IP-адреса**

Когда вы вводите URL в адресную строку браузера, первым делом начинается процесс поиска IP-адреса, соответствующего этому доменному имени.

Чтобы найти IP-адрес, браузер выполняет поиск в следующем порядке:
*   Локальный кеш браузера
*   Кеш операционной системы
*   Роутер или ближайший DNS-сервер провайдера
*   Если ни в одном из кешей нет нужного IP-адреса, запрос уходит дальше — к DNS-серверам в сети, включая авторитативные DNS-серверы, которые могут предоставить окончательный ответ.

**Установление соединения с сервером**

**TCP-handshake (тройное рукопожатие)**

Установка TCP соединения:
*   **SYN (synchronize)** — Клиент отправляет на сервер специальный пакет SYN, уведомляя о намерении установить соединение и передавая начальный порядковый номер для передачи данных.
*   **SYN-ACK (synchronize-acknowledgment)** — Сервер, получив пакет SYN, отправляет ответный пакет SYN-ACK. Этот пакет подтверждает получение запроса и также содержит свой начальный номер для синхронизации.
*   **ACK (acknowledgment)** — Клиент отправляет пакет ACK для подтверждения получения пакета SYN-ACK. После этого соединение считается установленным, и данные могут передаваться.

**Порты и протоколы**

При установлении соединения браузер также определяет, какой порт будет использоваться для связи.
*   **Порт 80** используется для передачи данных по протоколу HTTP (HyperText Transfer Protocol), который отвечает за передачу веб-страниц в незашифрованном виде.
*   **Порт 443** применяется для HTTPS (HTTP Secure) — защищённой версии HTTP, которая шифрует передаваемые данные с помощью SSL/TLS, обеспечивая их конфиденциальность и защиту.

После успешного установления TCP-соединения браузер готов отправить HTTP-запрос для получения содержимого сайта.

**Шифрование и установка безопасного соединения (TLS/SSL)**

**TLS-handshake**

Чтобы установить защищённое соединение, браузер и сервер проходят через процесс, известный как TLS-handshake. В ходе этого процесса стороны обмениваются сертификатами, ключами и устанавливают параметры шифрования. Это позволяет создать зашифрованный канал для передачи данных.

Основные шаги в процессе TLS-handshake:
*   Обмен сертификатами
*   Проверка сертификатов и установление зашифрованного канала

После завершения TLS-handshake браузер и сервер переходят к передаче данных, используя сессионный ключ для шифрования и расшифровки всей информации.

**Отправка HTTP-запроса**

После установления соединения и настройки безопасного канала браузер отправляет на сервер HTTP-запрос, чтобы получить данные для отображения страницы.

**Формат HTTP-запроса**

HTTP-запрос имеет стандартный формат, который включает:
*   **Метод запроса.** Указывает серверу, какое действие требуется. В данном случае — GET (также бывают POST, PUT, DELETE, PATCH и др.).
*   **Заголовки.** Передают дополнительную информацию: User-Agent, Accept-Language, Cookies и т.д.

**GET-запрос к серверу**

Когда браузеру нужно загрузить страницу, он отправляет GET-запрос на сервер по указанному URL. В случае успешной обработки сервер отвечает данными: HTML-кодом, стилями CSS, изображениями, скриптами и другими ресурсами.

После получения HTTP-запроса сервер формирует и отправляет браузеру ответ.

**Структура ответа**
*   **Статус-код (код ответа HTTP).** Трехзначное число, указывающее на результат обработки запроса.
*   **Заголовки ответа.** Содержат информацию о типе контента, настройках кеша и параметрах соединения (Content-Type, Cache-Control, Set-Cookie).
*   **Тело ответа.** Основное содержимое — HTML-документ, который браузер будет отображать.

# Порт

Это числовое значение (от 0 до 65535), которое используется для идентификации конкретного процесса или службы на устройстве. Когда компьютер обменивается данными по сети, он использует IP-адрес для определения устройства и номер порта для определения конкретной службы или приложения.

Порты делятся на три категории:
1.  **Well-known ports (0–1023):** Зарезервированы для стандартных служб (например, HTTP, HTTPS, SSH).
2.  **Registered ports (1024–49151):** Используются для пользовательских или менее распространенных служб.
3.  **Dynamic/private ports (49152–65535):** Используются для временных соединений (например, клиентские порты).

# DNS (Domain Name System)

Это система, которая переводит доменные имена (например, google.com) в IP-адреса (например, 142.250.72.174). Это необходимо, потому что компьютеры работают с IP-адресами, а людям удобнее использовать понятные имена.

DNS работает по принципу иерархии:
1.  **Корневые серверы** — отвечают за верхний уровень системы.
2.  **TLD-серверы (Top-Level Domain)** — отвечают за домены первого уровня (например, .com, .org).
3.  **Авторитетные серверы** — содержат информацию о конкретных доменах.

Файл `/etc/resolv.conf` содержит настройки DNS-серверов, которые используются системой. Вы можете просмотреть его содержимое:
```bash
cat /etc/resolv.conf
```
Пример вывода:
```
nameserver 8.8.8.8
nameserver 8.8.4.4
```

**Процесс DNS-запроса**

DNS использует 53 порт (TCP/IP).

Если запрос доходит до внешней сети, ближайший DNS-сервер выполняет рекурсивный запрос. Он последовательно обращается к другим DNS-серверам, пока не найдет IP-адрес. Процесс выглядит так:
*   Запрос идет на корневой DNS-сервер, который сообщает, какой сервер отвечает за домен верхнего уровня (например, `.com`).
*   Запрос передается на сервер домена верхнего уровня, который указывает на авторитативный сервер для конкретного домена.
*   Авторитативный сервер возвращает IP-адрес искомого домена рекурсивному серверу, а тот, в свою очередь, отправляет его браузеру.

Проще говоря: если у вашего провайдера нет DNS-записи, запрос идет к корневому серверу. Тот направляет к DNS-серверу нужной зоны (например, `.ru`). Сервер зоны указывает на хост, которому принадлежит домен, и уже этот хост через DNS-сервер провайдера отдает свой IP-адрес.

# Что такое TTL

Time to live (TTL) – это время жизни пакета. TTL показывает максимальный период времени существования набора данных (пакета).

В IPv4 TTL представляет собой восьмиразрядное поле IP-заголовка. Параметр TTL считается верхней границей времени существования IP-дейтаграммы в сети. Поле TTL устанавливается отправителем и уменьшается на каждом маршрутизаторе на 1.

Основное назначение – не допустить "зацикливания" пакета в сети.

При условии, что значение TTL на каком-либо из узлов достигнет 1, пакет данных уничтожается, а на исходный сервер посылается ICMP-сообщение с кодом 11 — «Превышение временного интервала». Маршрутизатор не пропускает пакеты с нулевым значением TTL.

**TTL у DNS**

В контексте DNS, TTL – это параметр, отвечающий за время кеширования записей DNS-зоны на серверах. По истечении этого времени, кеширующий сервер запрашивает обновление у авторитативного DNS-сервера.

# QoS

QoS (Quality of Service, качество обслуживания) – функция маршрутизации, которая позволяет определять приоритеты полосы пропускания для определенных программ, клиентов или служб. QoS резервирует определенный объём пропускной способности для критичных приложений.

# Proxy

Прокси выполняет роль промежуточного звена между пользователем и интернетом, перенаправляя трафик через себя. Прокси позволяют ускорять загрузку страниц за счет кэширования, контролировать трафик и фильтровать нежелательный контент.

**Как прокси защищают от DDoS-атак?**

Ключевым методом является маскировка подлинного IP-адреса хоста. Злоумышленники взаимодействуют с прокси, а не с реальным сервером, что исключает прямую атаку.

Дополнительно прокси могут:
*   Фильтровать вредоносный трафик.
*   Ограничивать число запросов с одного IP (rate limiting).
*   Балансировать нагрузку, распределяя трафик между несколькими серверами.
*   Кэшировать контент для снижения нагрузки на основной сервер.
*   Блокировать ботов и применять гео-блокировку.

**Протоколы и виды прокси**

Прокси-серверы классифицируются по протоколам и функциональному назначению.

**По протоколам:**
*   **HTTP-прокси:** Специализируются на обработке HTTP-запросов, могут кэшировать контент для ускорения загрузки.
*   **HTTPS-прокси:** Аналогичны HTTP, но используют шифрование для защиты передаваемых данных.
*   **SOCKS-прокси:** Универсальны, поддерживают различные типы трафика (HTTP, FTP, P2P, игры), но обычно не кэшируют данные.

**По функциональному назначению:**
*   **Анонимные прокси:** Скрывают IP-адрес клиента для повышения приватности.
*   **Прозрачные прокси:** Не скрывают IP-адрес, используются для мониторинга и контроля трафика в корпоративных или образовательных сетях.

# NAT (network address translation)

NAT — это технология, позволяющая перенаправлять трафик между локальной и глобальной сетями. Благодаря ей несколько устройств в локальной сети могут выходить в интернет, используя один "белый" IP-адрес, выданный провайдером.

**Виды NAT**
*   **Статический NAT:** Каждому локальному адресу присваивается уникальный глобальный адрес. Часто применяется для серверов, к которым нужен постоянный удаленный доступ.
*   **Динамический NAT:** Маршрутизатор выдаёт устройству случайный глобальный адрес из доступного пула.
*   **PAT (Port Address Translation) или перегруженный NAT:** Самый распространённый тип. Несколько устройств с уникальными локальными адресами используют один глобальный IP-адрес. Различение устройств происходит по номерам портов.

**Принцип работы PAT:**
1.  Устройство с локальным IP (например, 192.168.0.3) отправляет запрос в интернет.
2.  Роутер с глобальным IP (например, 208.135.26.4) подменяет локальный IP на свой глобальный, запоминая в таблице, какому устройству и порту соответствует этот запрос.
3.  Внешний сервер отвечает на глобальный IP роутера.
4.  Роутер, получив ответ, смотрит в свою таблицу и перенаправляет трафик на исходное устройство в локальной сети.

# DHCP

DHCP (Dynamic Host Configuration Protocol) — протокол динамической настройки узла. Он предназначен для автоматической выдачи устройствам IP-адресов и других сетевых параметров (маска подсети, шлюз по умолчанию).

**Способы назначения IP-адресов**
*   **Статическое назначение:** IP-адрес вручную закрепляется за MAC-адресом конкретного устройства. Используется в небольших сетях для устройств, требующих постоянного адреса.
*   **Динамическое назначение:** DHCP-сервер выдает IP-адрес из пула свободных адресов на определенное время (срок аренды).
*   **Автоматическое назначение:** Похоже на динамическое, но срок аренды не ограничен. IP остается за клиентом, пока он сам от него не откажется.

**Архитектура протокола DHCP**

DHCP использует архитектуру «клиент-сервер».
*   **Сервер DHCP:** Раздает IP-адреса и следит за их уникальностью.
*   **Клиент DHCP:** Любое устройство, запрашивающее сетевые настройки.
*   **Агенты ретрансляции DHCP:** Позволяют DHCP работать через несколько подсетей, пересылая запросы между ними.

**Принцип работы протокола DHCP (DORA)**

1.  **Discovery:** Клиент (еще без IP) отправляет широковещательное сообщение `DHCPDISCOVER` для поиска DHCP-сервера.
2.  **Offer:** DHCP-сервер (или несколько) отвечает сообщением `DHCPOFFER`, предлагая IP-адрес в аренду.
3.  **Request:** Клиент выбирает одно из предложений и отправляет `DHCPREQUEST`, сообщая всем, что адрес принят.
4.  **Acknowledgement:** Сервер подтверждает выделение адреса сообщением `DHCPACK`, передавая также срок аренды и другие настройки.

**Другие сообщения DHCP:**
*   `DHCPNAK`: Отказ в аренде IP-адреса.
*   `DHCPINFORM`: Запрос на получение дополнительных настроек сети (когда IP уже есть).
*   `DHCPRELEASE`: Досрочное освобождение IP-адреса клиентом.
*   `DHCPDECLINE`: Сообщение от клиента, если предложенный IP-адрес уже занят.

**Срок аренды IP-адреса**

IP-адрес выдается на определенное время. По умолчанию — 24 часа, но это настраивается. По истечении половины срока аренды клиент пытается его продлить.
