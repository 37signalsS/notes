# 1. Настройка окружения

## Файл конфигурации ansible.cfg

Создайте в корне проекта файл `ansible.cfg`. Он позволяет централизованно управлять настройками Ansible.

```ini
[defaults]
# Путь к файлу инвентаризации (списку хостов)
inventory = inventory

# Путь к директории с ролями
roles_path = roles

# Отключение проверки SSH-ключа хоста
# Отключает проверку ключа хоста, что упрощает первое подключение.
host_key_checking = False
```

## 2. Файл инвентаризации (inventory)

Файл `inventory` содержит список хостов, которыми управляет Ansible.

**Пример с авторизацией по SSH-ключу:**

```ini
[servers]
195.2.73.85 ansible_user=root ansible_port=2414 ansible_ssh_private_key_file=~/.ssh/id_rsa
```

**Пример с группами и паролями:**

> **ВНИМАНИЕ:** Хранение паролей в открытом виде небезопасно. Используйте `ansible-vault` для шифрования чувствительных данных.

```ini
[nodes]
192.168.0.139
192.168.0.140

[master]
192.168.0.138

[master:vars]
ansible_user=master
ansible_ssh_pass=master
ansible_become_pass=master

[nodes:vars]
ansible_user=vagrant
ansible_ssh_pass=vagrant
ansible_become_pass=vagrant
```

## 3. Проверка подключения (Ad-Hoc команды)

Ad-hoc команды — это быстрый способ выполнить одну задачу на одном или нескольких хостах. Они полезны для простых действий, таких как проверка подключения или перезагрузка серверов.

Для проверки подключения используется модуль `ping`.

```bash
# Проверить доступность хостов в группе master
ansible master -m ping

# Проверить доступность всех хостов
ansible all -m ping
```

## 4. Выполнение команд

Модуль `shell` позволяет выполнять shell-команды на удаленных серверах. Для простых команд, не требующих возможностей shell (например, `|`, `>`, `&`), рекомендуется использовать модуль `command`.

```bash
# Пример использования модуля shell
ansible all -m shell -a "ls -la /"

# Пример использования модуля command
ansible all -m command -a "uptime"
```

## 5. Плейбуки (Playbooks)

Плейбук — это YAML-файл, который определяет последовательность задач для выполнения на управляемых узлах. Это основной способ использования Ansible для оркестрации сложных задач.

**Ключевые компоненты плейбука:**

*   **`hosts`**: Определяет целевые хосты или группы из файла инвентаризации.
*   **`tasks`**: Список задач, которые необходимо выполнить на хостах.
*   **`vars`**: Переменные, используемые в плейбуке.
*   **`handlers`**: Обработчики, которые выполняются только при получении уведомления от задачи.
*   **`roles`**: Список ролей для включения в плейбук.

**Пример плейбука:**

Этот плейбук копирует файл `authorized_keys` на все серверы и перезапускает службу SSH, если файл был изменен.

```yaml
- name: Configure SSH access
  hosts: all
  become: true # Выполнять задачи с повышенными привилегиями (sudo)

  tasks:
    - name: Copy authorized_keys
      copy:
        src: /root/.ssh/authorized_keys
        dest: /root/.ssh/authorized_keys
        owner: "{{ ansible_user }}"
        group: "{{ ansible_user }}"
        mode: '0600'
      notify: Restart SSHD

  handlers:
    - name: Restart SSHD
      service:
        name: sshd
        state: restarted
```

# Принципы Ansible

## Идемпотентность

Идемпотентность — это ключевой принцип Ansible, который гарантирует, что повторное выполнение операции не изменит состояние системы, если она уже находится в желаемом состоянии. Ansible проверяет текущее состояние и вносит изменения, только если это необходимо.

*   **`ok`** (зеленый): Состояние соответствует желаемому, никаких действий не предпринято.
*   **`changed`** (желтый): Состояние не соответствовало желаемому, были внесены изменения.

## Роли

Роли — это способ организации и переиспользования кода в Ansible. Они позволяют упаковать задачи, переменные, файлы и шаблоны в модульную структуру.

### Сравнение плейбуков и ролей

| Аспект | Плейбук | Роль |
| :--- | :--- | :--- |
| **Назначение** | Оркестрация: определяет, **что** и **где** делать. | Модульность: описывает, **как** выполнить задачу. |
| **Структура** | YAML-файл. | Стандартизированная структура каталогов. |
| **Хосты** | Определяет хосты (`hosts`). | Не определяет хосты. |
| **Переиспользование** | Низкое. | Высокое. |

### Структура роли

Создать структуру роли можно с помощью команды `ansible-galaxy init <имя_роли>`.

*   `tasks/main.yml`: Основной файл с задачами роли.
*   `handlers/main.yml`: Обработчики.
*   `defaults/main.yml`: Переменные по умолчанию (низкий приоритет).
*   `vars/main.yml`: Переменные роли (высокий приоритет).
*   `files/`: Статические файлы.
*   `templates/`: Шаблоны Jinja2 (`.j2`).
*   `meta/main.yml`: Метаданные и зависимости роли.

### Шаблоны (Jinja2)

Шаблоны позволяют создавать динамические файлы с помощью переменных, циклов и условий. Для работы с шаблонами используется модуль `template`.

```yaml
- name: Create config from template
  template:
    src: config.j2
    dest: /etc/app/config.conf
```

### Ansible Galaxy

[Ansible Galaxy](https://galaxy.ansible.com) — это публичный репозиторий для обмена ролями.

# Продвинутые темы

## Установка Python на удаленных хостах

Для работы большинства модулей Ansible требуется Python. Если он отсутствует, его можно установить с помощью процесса "bootstrapping".

### Модуль `raw`

Модуль `raw` выполняет команду без использования стандартной системы модулей Ansible. Это позволяет установить Python на "голую" систему.

```bash
# Установка Python3 на Debian/Ubuntu
ansible my-raw-node -m raw -a "apt-get update && apt-get install -y python3" --become
```

### Модуль `script`

Модуль `script` выполняет локальный скрипт на удаленном хосте.

1.  **Создайте скрипт `install_python.sh`:**

    ```sh
    #!/bin/sh
    set -e
    if ! command -v python3 >/dev/null 2>&1; then
      # Определяем пакетный менеджер и устанавливаем Python
      if command -v apt-get >/dev/null 2>&1; then
        apt-get update && apt-get install -y python3
      elif command -v yum >/dev/null 2>&1; then
        yum install -y python3
      else
        echo "Ошибка: не удалось определить пакетный менеджер."
        exit 1
      fi
    fi
    ```

2.  **Запустите скрипт через Ansible:**

    ```bash
    ansible my-raw-node -m script -a "./install_python.sh" --become
    ```

## Рекомендации

*   **Ansible Vault:** Всегда используйте `ansible-vault` для шифрования секретов (паролей, ключей API).
    ```bash
    # Создать зашифрованный файл
    ansible-vault create secrets.yml

    # Редактировать зашифрованный файл
    ansible-vault edit secrets.yml

    # Запустить плейбук с зашифрованным файлом
    ansible-playbook my_playbook.yml --ask-vault-pass
    ```

*   **Ansible Lint:** Используйте `ansible-lint` для проверки плейбуков и ролей на соответствие лучшим практикам.
    ```bash
    # Проверить плейбук
    ansible-lint my_playbook.yml
    ```
