Создаем папку, в ней создаем файл ansible.cfg и добавляем в него:

```ini
[defaults]
# Путь к файлу инвентаризации
inventory = inventory

# Путь к папке с ролями
roles_path = roles

# Отключение проверки SSH-ключей.

Необходимо, чтобы при первом запуске плейбука не подтверждать добавление хоста в список известных хостов на каждом сервере.

host_key_checking = False
```

## 2. Создание файла инвентаризации

Далее создайте файл `inventory`, в котором перечислите все необходимые для работы серверы.

**Пример с авторизацией по SSH-ключу:**

```ini
[rei]
195.2.73.85 ansible_user=root ansible_port=2414 ansible_ssh_private_key_file=~/.ssh/id_rsa
```

**Пример с разделением на группы и использованием паролей:**

```ini
[nodes]
192.168.0.139
192.168.0.140

[master]
192.168.0.138

[master:vars]
ansible_ssh_user=master
ansible_ssh_pass=master
ansible_become_pass=master # Пароль для sudo

[nodes:vars]
ansible_ssh_user=vagrant
ansible_ssh_pass=vagrant
ansible_become_pass=vagrant
```

## 3. Тестирование подключения

После создания файлов `ansible.cfg` и `inventory` можно протестировать подключение к серверам. Для этого используется модуль `ping`.

*   **К конкретной группе:** `ansible master -m ping`
*   **Ко всем нодам:** `ansible nodes -m ping`
*   **Ко всем серверам из файла инвентаризации:** `ansible all -m ping`

## 4. Выполнение команд

Модуль `shell` позволяет выполнять shell-команды на удаленных серверах.

**Пример:**

```bash
ansible all -m shell -a "ls -la /"
```

## 5. Плейбуки (Playbooks)

Playbook — это YAML-файл, который определяет последовательность задач для выполнения на управляемых узлах. Это точка входа для запуска автоматизации (`ansible-playbook`).

**Ключевые характеристики:**
*   **Цель:** Оркестрация и запуск процесса автоматизации. Он отвечает на вопросы "что делать?" и "где делать?".
*   **Структура:** Состоит из одной или нескольких "пьес" (plays). Каждая пьеса определяет:
    *   `hosts`: Целевые серверы или группы.
    *   `tasks`: Список задач для выполнения.
    *   `vars`: Переменные.
    *   `handlers`: Обработчики.
    *   `roles`: Список ролей для применения.

**Пример плейбука:**

Ниже приведен пример плейбука, который копирует `authorized_keys` на все серверы и перезапускает службу SSHD при необходимости.

```yaml
- name: authorized_keys to servers
  hosts: all
  become: yes
  tasks:
    - name: Copy the updated authorized_keys file
      copy:
        src: /root/.ssh/authorized_keys
        dest: /root/.ssh/authorized_keys
        owner: "{{ ansible_user }}"
        group: "{{ ansible_user }}"
        mode: '0600'
      notify:
        - Restart SSHD if necessary

  handlers:
    - name: Restart SSHD if necessary
      service:
        name: sshd
        state: restarted
      when: sshd_service is defined and sshd_service.changed
```

# Роли в Ansible

Роль в Ansible — это способ организации и структурирования кода для автоматизации. Она позволяет группировать связанные задачи, переменные, файлы и обработчики в повторно используемые модульные компоненты.

**Playbook vs Role**

| Аспект | Playbook | Role |
| :--- | :--- | :--- |
| **Назначение** | Оркестрация. Определяет, **что** и **где** делать. | Переиспользование и модульность. Описывает **как** выполнить конкретную функцию. |
| **Структура** | Один или несколько YAML-файлов. | Стандартизированная структура каталогов (`tasks`, `vars` и т.д.). |
| **Целевые хосты** | **Определяет** хосты (`hosts: ...`). | **Не определяет** хосты. Применяется к хостам, указанным в плейбуке. |
| **Повторное использование** | Низкое. | Высокое. Роли созданы для многократного использования. |
| **Точка входа** | Является точкой входа для команды `ansible-playbook`. | Вызывается из Playbook. |

**Шаблоны (Templates)**

Шаблоны в Ansible используются для создания динамических конфигурационных файлов. Они написаны на языке шаблонов **Jinja2**, что позволяет вставлять в статические файлы переменные, выражения, циклы и условные операторы.

*   **Динамический контент:** Вы можете использовать переменные из инвентаря, плейбуков или собранных фактов для вставки динамических значений в файлы. Переменные заключаются в двойные фигурные скобки, например: `{{ variable_name }}`.
*   **Логика и управление:** Вы можете использовать циклы для итерации по спискам и условные операторы (if/else) для создания более сложных конфигураций.
*   **Модуль `template`:** Модуль `template` в Ansible используется для рендеринга и развертывания этих файлов шаблонов на управляемых узлах.

**Структура роли:**

Ansible ожидает определённую структуру каталогов для корректной работы роли. Вы можете создать базовую структуру с помощью команды `ansible-galaxy init <имя_роли>`.

*   `tasks/`: Содержит основной список задач, которые выполняет роль (`main.yml` — точка входа).
*   `handlers/`: Содержит обработчики, которые могут быть вызваны задачами.
*   `defaults/`: Содержит переменные по умолчанию для роли (имеют самый низкий приоритет).
*   `vars/`: Содержит другие переменные, необходимые для роли.
*   `files/`: Содержит статические файлы, которые роль будет копировать на целевые хосты.
*   `templates/`: Содержит файлы шаблонов (с расширением `.j2`), использующие синтаксис Jinja2.
*   `meta/`: Содержит метаданные для роли, такие как зависимости от других ролей.

**Ansible Galaxy**

Ansible Galaxy — это публичный репозиторий для поиска, загрузки и обмена ролями, созданными сообществом. Вы можете искать и устанавливать роли с помощью команды `ansible-galaxy`.
