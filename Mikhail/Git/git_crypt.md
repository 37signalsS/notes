Основы работы с ключами GPG
----------

Пара ключей GPG содержит пару ключей, открытый ключ и закрытый ключ. Как и в случае с ключами SSH, закрытый ключ является очень важным секретом и должен тщательно храниться.

Если у вас нет ключа GPG, его легко создать с помощью:

```sh
gpg --full-gen-key
```

Убедитесь, что ключи, известные системе, теперь включают ваш вновь созданный ключ, используя:

```sh
gpg --list-key
```

основы git-crypt
----------

Вам нужно будет установить git-crypt — подробные инструкции доступны в [репозитории git-crypt на GitHub](https://github.com/AGWA/git-crypt/blob/master/INSTALL.md?ref=blog.ktz.me ). Это руководство будет продолжено после установки git-crypt.

Войдите в свой каталог git-repo. Убедитесь, что вы находитесь в ветке main/master без каких-либо существенных изменений, инициализируйте git-crypt и добавьте ключ в репозиторий. Например:

```
$ cd gctest
$ git-crypt init
$ git-crypt add-gpg-user bob@bob.com
```

git-crypt уже зафиксировал изменение (новый файл.gpg в каталоге .git-crypt), поэтому теперь запустите:

```
$ git-push
```

инструкции по шифрованию git-crypt
----------

Файлы, которые вы выбираете для шифрования, управляются содержимым файла ".gitattributes".

Следующий пример файла автоматически зашифрует любой файл, содержащий ".enc" в любом месте его имени. Это может быть "secrets.enc" или "secrets.enc.yaml" — оба будут сохранены на GitHub как зашифрованные файлы, все будет прозрачно для вас.

```
.gitattributes !filter !diff
**/*.enc.* filter=git-крипта, diff=git-крипта
**/*.enc/** filter=git-крипта, diff=git-крипта
```

Зафиксируйте файл ".gitattributes", а затем создайте файл шаблона, соответствующий выбранному вами шаблону фильтра шифрования (в моем случае ".enc").

Сначала вы можете задаться вопросом, выполняет ли git-crypt какие-либо действия. Но как только вы зафиксируете и отправите свой enc-файл, он будет автоматически зашифрован и сможет быть просмотрен только тем, у кого есть ваш PGP-ключ (я надеюсь, что это будете только вы!). Вам будет предложено ввести кодовую фразу в дополнение к ключу, поэтому сохраните и ее.

Вы можете добавить дополнительных соавторов в репозиторий с помощью git-crypt, но это выходит за рамки данной статьи — полезно, если вы работаете в команде разработчиков!

Если вы хотите сохранить содержимое этого файла зашифрованным на локальном диске, мы можем сделать это с помощью git-crypt, используя `git-crypt lock". 

Несколько автомобилей
----------

Вероятно, вам потребуется получить доступ к этому репозиторию git с нескольких компьютеров. Вам нужно будет скопировать свой ключ GPG или добавить этот идентификатор GPG в репозиторий. Если вы скопируете ключ, экспортируйте закрытый ключ (осторожно!) с помощью:

```
$ gpg --export-secret-key -a > secretkey.asc
```

Затем скопируйте этот файл туда, где он вам нужен, и импортируйте его на другом конце с помощью

```
$ gpg --import secretkey.asc
```

После того, как ключевые файлы выполнят свою задачу, безопасно удалите их с помощью:

```
$ shred secretkey.asc
$ rm secretkey.asc
``
