# Справочник по Git

Этот справочник содержит набор команд и советов по работе с системой контроля версий Git, от основ до продвинутых техник.

## I. Основы Git

### 1. Первоначальная настройка

Перед началом работы необходимо указать ваше имя и адрес электронной почты.

```sh
git config --global user.name "Ваше Имя"
git config --global user.email "ваш@email.com"
```

### 2. Создание репозитория

Инициализация нового репозитория в существующей папке:

```sh
git init
```

При создании можно сразу указать имя основной ветки (например, `main` или `develop`):

```sh
git init --initial-branch=main
```

Клонирование существующего репозитория:

```sh
git clone <url>
```

### 3. Основной рабочий процесс

Жизненный цикл файлов в Git:
1.  **Неотслеживаемый (untracked)** — Git не знает о файле.
2.  **Изменён (modified)** — файл изменён, но не добавлен в коммит.
3.  **Подготовлен (staged)** — файл отмечен для включения в следующий коммит.
4.  **Зафиксирован (committed)** — изменения сохранены в репозитории.

Проверка статуса файлов:

```sh
git status
git status -s # Короткий формат
```

Добавление файлов в область подготовленных (индексация):

```sh
git add <имя_файла> # Добавить конкретный файл
git add .           # Добавить все новые и изменённые файлы в текущей директории
```

Фиксация изменений (коммит):

```sh
git commit -m "Краткое описание изменений"
git commit -am "Описание" # Добавляет все отслеживаемые файлы и сразу делает коммит
```

### 4. Просмотр истории (git log)

Просмотр истории коммитов:

```sh
git log
```

Полезные флаги для `git log`:
*   `-p`: Показывает изменения (diff) для каждого коммита.
*   `--stat`: Отображает статистику изменённых файлов.
*   `--graph --oneline`: Показывает историю в виде компактного графа.
*   `-n <число>`: Ограничивает вывод указанным числом коммитов.
*   `--since="YYYY-MM-DD"` и `--until="YYYY-MM-DD"`: Фильтрует коммиты по дате.
*   `--pretty=format:"%h %s"`: Позволяет настроить формат вывода.
*   `--grep <паттерн>`: Поиск коммитов по сообщению.
*   `-S <текст>`: Поиск коммитов, в которых было добавлено или удалено указанное слово (например, имя функции).
*   `master..test`: Показывает коммиты, которые есть в ветке `test`, но нет в `master`.
*   `--no-merges`: Исключает коммиты слияния.
*   `--name-only`: Показывает имена изменённых файлов.
*   `--follow <файл>`: Показывает историю изменений конкретного файла, включая переименования.
*   `log -1 --pretty=format:"%s" -- <файл>`: Показывает комментарий последнего коммита для указанного файла.

### 5. Сравнение изменений (git diff)

*   `git diff`: Сравнение рабочей директории с областью подготовленных файлов.
*   `git diff --staged` (или `--cached`): Сравнение подготовленных файлов с последним коммитом (HEAD).

### 6. Управление файлами

Перемещение или переименование файла:

```sh
git mv <старое_имя> <новое_имя>
```

Удаление файла из контроля версий и с диска:

```sh
git rm <файл>
```

Удаление файла только из контроля версий (оставить на диске):

```sh
git rm --cached <файл>
```

## II. Работа с ветками

### 1. Создание и управление ветками

*   `git branch`: Показывает список локальных веток.
*   `git branch -a`: Показывает все ветки (локальные и удалённые).
*   `git branch -vv`: Показывает локальные ветки и их связь с удалёнными.
*   `git branch <имя_ветки>`: Создаёт новую ветку.
*   `git branch <новая> <существующая>`: Создаёт новую ветку как копию существующей.
*   `git branch -d <имя_ветки>`: Удаляет ветку (только если она полностью слита).
*   `git branch -D <имя_ветки>`: Принудительно удаляет ветку.

### 2. Переключение между ветками

Переключение на другую ветку:

```sh
git switch <имя_ветки>
# или старый вариант
git checkout <имя_ветки>
```

Создание новой ветки и переключение на неё:

```sh
git switch -c <имя_ветки>
# или старый вариант
git checkout -b <имя_ветки>
```

### 3. Слияние веток (merge)

Перейдите на ветку, в которую хотите влить изменения, и выполните:

```sh
git merge <имя_ветки_для_слияния>
```

*   `--squash`: Объединяет все коммиты из сливаемой ветки в один, не перенося историю.
*   `--abort`: Отменяет слияние, если возникли конфликты.
*   `--allow-unrelated-histories`: Разрешает слияние веток с несвязанной историей.

Для разрешения конфликтов слияния можно использовать визуальный инструмент:
```sh
git mergetool
```

### 4. Перебазирование (rebase)

Перемещение или объединение коммитов для создания более линейной истории.

Интерактивное перебазирование для последних 3 коммитов:

```sh
git rebase -i HEAD~3
```

В редакторе можно выбрать действие для каждого коммита:
*   `pick`: использовать коммит.
*   `squash`: объединить коммит с предыдущим.
*   `fixup`: объединить с предыдущим, отбросив сообщение коммита.
*   `reword`: изменить сообщение коммита.
*   `drop`: удалить коммит.

### 5. Сравнение веток

Показать коммиты, которые есть в одной ветке, но нет в другой:

```sh
git log master..test
```

Показать список коммитов в текущей ветке, которых нет в ветке `master`:

```sh
git cherry -v master
```

## III. Удалённые репозитории

### 1. Управление удалёнными репозиториями

*   `git remote -v`: Список удалённых репозиториев.
*   `git remote add <имя> <url>`: Добавить новый удалённый репозиторий.
*   `git remote remove <имя>`: Удалить репозиторий.
*   `git remote rename <старое> <новое>`: Переименовать репозиторий.
*   `git remote set-url <имя> <url>`: Изменить URL репозитория.
*   `git remote show <имя>`: Показать подробную информацию о репозитории.

### 2. Синхронизация с удалённым репозиторием

*   `git fetch <имя>`: Загружает изменения из удалённого репозитория, но не сливает их.
*   `git pull <имя> <ветка>`: Загружает и сливает изменения.
*   `git push <имя> <ветка>`: Отправляет локальные изменения в удалённый репозиторий.

Связать локальную ветку с удалённой и отправить изменения:

```sh
git push --set-upstream origin <имя_ветки>
```

Принудительная отправка (используйте с осторожностью!):
*   `git push --force`: Перезаписывает историю в удалённой ветке. Может удалить чужие изменения.
*   `git push --force-with-lease`: Более безопасная версия. Отклоняет push, если кто-то другой внёс изменения в ветку.

### 3. Работа с SSH-ключами

Создание нового SSH-ключа:

```sh
ssh-keygen -t ed25519 -C "ваш@email.com" -f ~/.ssh/id_ed25519_project
```

Добавление ключа в ssh-agent:

```sh
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_project
chmod 600 ~/.ssh/id_ed25519_obsidian
chmod 700 ~/.ssh
```

Для управления несколькими ключами для разных репозиториев (например, GitHub) создайте или отредактируйте файл `~/.ssh/config`:

```
# Стандартный ключ
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519

# Ключ для конкретного проекта
Host project-alias
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_project
```

После этого можно клонировать и добавлять удалённые репозитории, используя псевдоним:

```sh
git clone git@project-alias:user/repo.git
```

## IV. Продвинутые инструменты и техники

### 1. Отмена и исправление изменений

**Отмена `git add` (убрать файл из индекса):**

```sh
git reset <имя_файла>
```

**Отмена локальных изменений в файле:**

```sh
git restore <имя_файла>
```

**Отмена коммитов (`reset` vs `revert`):**
*   `git revert <хэш>`: Создаёт **новый** коммит, который отменяет изменения указанного коммита. Безопасный способ для опубликованной истории.
*   `git reset <хэш>`: **Перемещает** указатель HEAD на другой коммит, изменяя историю. Используйте с осторожностью для коммитов, которых нет в удалённом репозитории.

**Режимы `git reset`:**
*   `--soft HEAD~1`: Отменяет коммит, но оставляет изменения в индексе (staged).
*   `--mixed HEAD~1` (по умолчанию): Отменяет коммит и убирает изменения из индекса, но оставляет их в рабочей директории.
*   `--hard HEAD~1`: Полностью удаляет коммит и все связанные с ним изменения.

**Изменение последнего коммита:**

```sh
git commit --amend -m "Новое сообщение коммита"
```

**Полный сброс локального состояния до удалённого:**

Если вы хотите полностью отменить все локальные изменения и коммиты, приведя репозиторий в точное соответствие с удалённой веткой:

```sh
git fetch --all
git reset --hard origin/main # Замените main на нужную ветку
```

**Полная очистка рабочей директории:**

```sh
git clean -n      # Показать, какие файлы будут удалены
git clean -fd     # Удалить неотслеживаемые файлы и директории
```

### 2. Восстановление данных

**`git reflog`**: Показывает журнал всех изменений HEAD. Помогает найти хэши "потерянных" коммитов (например, после `reset --hard`).

```sh
git reflog
git reset --hard HEAD@{индекс} # Восстановиться к нужному состоянию
```

**`git fsck`**: Проверяет целостность базы данных и может найти "висячие" коммиты, на которые не ссылается ни одна ветка или тег.

```sh
git fsck --lost-found
```

**Восстановление удалённого файла:**

```sh
# 1. Найти хэш последнего коммита, где файл существовал
git rev-list -n 1 HEAD -- <путь_к_файлу>

# 2. Восстановить файл из этого коммита
git checkout <хэш>^ -- <путь_к_файлу>
```

**Возврат одного файла к состоянию из другого коммита:**

```sh
git checkout <хэш_коммита> -- <имя_файла>
```

### 3. Временное сохранение (Stash)

Сохранить незакоммиченные изменения:

```sh
git stash save "сообщение"
git stash # Короткий вариант
```

*   `git stash list`: Показать список сохранённых изменений.
*   `git stash pop`: Применить последние изменения и удалить их из списка.
*   `git stash apply`: Применить изменения, но оставить их в списке.
*   `git stash clear`: Удалить все сохранённые изменения.

### 4. Метки (Tags)

Используются для обозначения релизов (например, `v1.0`).

*   `git tag <имя_тега>`: Создать лёгкий тег.
*   `git tag -a <имя_тега> -m "сообщение" <хэш_коммита>`: Создать аннотированный тег для конкретного коммита.
*   `git show <имя_тега>`: Показать информацию о теге.
*   `git tag -f -a <имя_тега> <хэш_коммита>`: Принудительно переместить (заменить) аннотированный тег на другой коммит.
*   `git push origin <имя_тега>`: Отправить тег в удалённый репозиторий.
*   `git push --tags`: Отправить все теги.
*   `git push --delete origin <имя_тега>`: Удалить тег из удалённого репозитория.

### 5. Перенос коммитов (Cherry-pick)

Применение коммита из другой ветки в текущую.

```sh
git cherry-pick <хэш_коммита_1> <хэш_коммита_2>
```
*   `--no-commit`: Применяет изменения, но не создаёт коммит, позволяя внести правки.

### 6. Поиск ошибок (Bisect)

Инструмент для автоматического поиска коммита, который внёс ошибку.

```sh
git bisect start
git bisect bad <хэш_плохого_коммита>  # Коммит, где ошибка уже есть
git bisect good <хэш_хорошего_коммита> # Коммит, где ошибки еще не было
```
Git будет переключаться между коммитами. На каждом шаге проверяйте наличие ошибки и выполняйте `git bisect bad` или `git bisect good`. Когда проблемный коммит будет найден, завершите процесс:
```sh
git bisect reset
```

### 7. Игнорирование файлов

**`.gitignore`**: Создайте файл `.gitignore` в корне проекта, чтобы исключить файлы и папки из отслеживания.

**Временное игнорирование отслеживаемых файлов:**

```sh
git update-index --assume-unchanged <файл> # Игнорировать изменения
git update-index --no-assume-unchanged <файл> # Вернуть отслеживание
```

### 8. Переписывание истории

**Внимание: эти команды изменяют историю. Не используйте их для коммитов, уже отправленных в общий репозиторий.**

Удаление файла из всей истории коммитов (например, для удаления случайно закоммиченного секрета):

```sh
git filter-branch --tree-filter 'rm -f <путь_к_файлу>' -- --all
```

### 9. Верификация коммитов (GPG)

Вы можете подписывать свои коммиты с помощью GPG-ключа для подтверждения их подлинности. Это особенно полезно в больших проектах и проектах с открытым исходным кодом.

Для настройки верификации коммитов можно ознакомиться с подробной инструкцией:
[Habr: Верификация коммитов GPG](https://habr.com/ru/articles/754128/)

### 10. Шифрование файлов (Git Crypt)

Расширение для шифрования конфиденциальных файлов в репозитории.

1.  **Установка и инициализация:** `git-crypt init`
2.  **Добавление GPG ключа:** `git-crypt add-gpg-user "ваш@email.com"`
3.  **Настройка шифрования:** Создайте файл `.gitattributes` и укажите, какие файлы шифровать (например, `secret.json filter=git-crypt diff=git-crypt`).
4.  **Блокировка/разблокировка:** `git-crypt lock` / `git-crypt unlock`.

### 11. Работа с большими файлами (Git LFS)

Расширение для хранения больших файлов вне основного репозитория.

```sh
git lfs install # Установить один раз
git lfs track "*.psd" # Указать типы файлов для отслеживания
git add .gitattributes # Добавить файл конфигурации в коммит
```

### 12. Подпроекты (Submodules и Subtree)

*   **Submodule**: Включение одного репозитория в другой как ссылку на конкретный коммит. Полезно для библиотек и зависимостей.
*   **Subtree**: Полное копирование истории другого репозитория в ваш. Код становится частью вашего проекта.

### 13. Полезные настройки и псевдонимы

**Сохранение пароля для HTTPS:**

```sh
git config --global credential.helper 'cache --timeout=3600' # Запомнить на час
```

**Настройка Fast-forward слияния для `pull`:**

```sh
git config --global pull.ff only # Разрешить только fast-forward
```

**Псевдонимы (Aliases):**

```sh
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status
git config --global alias.hist "log --graph --oneline"
```
Теперь можно использовать `git st` вместо `git status`.
