# Pod

**Pod** (Под) — это наименьшая и самая простая развертываемая единица в Kubernetes. Под представляет собой группу из одного или нескольких контейнеров, которые разделяют общее хранилище, сетевое пространство и спецификацию для их запуска.

### Ключевые особенности:

*   **Общий сетевой Namespace:** Все контейнеры внутри одного пода находятся в одном сетевом пространстве имен. Это означает, что у них общий IP-адрес и они могут общаться друг с другом через `localhost`.
*   **Общие тома (Volumes):** Контейнеры в поде могут совместно использовать тома, что позволяет им обмениваться данными.
*   **Атомарность:** Под — это атомарная единица. Он либо работает целиком, либо нет. Kubernetes управляет подами как единым целым.

---

### "Pause" контейнер

Когда Kubernetes создает под, он сначала запускает специальный "инфраструктурный" контейнер, который часто называют **"pause" контейнером**. Этот контейнер выполняет минимальную работу: он создает сетевое пространство имен и "держит" его, пока работают основные контейнеры пода. Все остальные контейнеры в поде присоединяются к этому сетевому пространству.

Именно поэтому под является основной единицей масштабирования и управления в Kubernetes, а не отдельный контейнер.

---

### Пример манифеста Pod

Этот манифест описывает простой под с одним контейнером Nginx.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-nginx-pod
  labels:
    app: web
spec:
  containers:
    - name: nginx-container
      image: nginx:latest
      ports:
        - containerPort: 80

  # nodeName: worker-node-1 # Можно жестко указать узел для запуска, но это не рекомендуется.
                           # Лучше использовать nodeSelector или affinity.
```

### Связанные концепции

*   **[[ConfigMap]]**: Для передачи конфигурации в поды.
*   **[[Secret]]**: Для передачи чувствительных данных (пароли, токены).
*   **[[Probes]]**: Для проверки состояния (жизнеспособности и готовности) контейнеров.
*   **[[QOS, limit and requests]]**: Для управления ресурсами CPU и памяти.

### Команды для работы с подами

```bash
# Создать под из файла
kubectl apply -f pod.yaml

# Получить информацию о подах
kubectl get pods

# Получить подробную информацию о конкретном поде
kubectl describe pod my-nginx-pod

# Удалить под
kubectl delete pod my-nginx-pod
```
