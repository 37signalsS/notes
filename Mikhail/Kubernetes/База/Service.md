# Service

**Service** — это объект Kubernetes, который предоставляет стабильную сетевую точку входа для группы подов. Он решает проблему непостоянства IP-адресов подов: поды могут умирать и пересоздаваться с новыми IP, но `Service` предоставляет постоянный IP-адрес и DNS-имя, через которые можно к ним обращаться.

`Service` находит поды, на которые нужно направлять трафик, с помощью **селектора** по меткам (`labels`).

---

### Типы сервисов

1.  **`ClusterIP`:**
    *   **Описание:** Предоставляет внутренний IP-адрес, доступный только внутри кластера. Это тип по умолчанию.
    *   **Использование:** Для внутренней коммуникации между сервисами в кластере (например, бэкенд обращается к базе данных).

2.  **`NodePort`:**
    *   **Описание:** Открывает статический порт на каждом узле кластера (`NodePort`). Трафик, приходящий на этот порт на любом из узлов, перенаправляется на `Service`.
    *   **Использование:** Для предоставления внешнего доступа к сервису на время разработки или для приложений, не требующих сложной балансировки нагрузки.

3.  **`LoadBalancer`:**
    *   **Описание:** Создает внешний балансировщик нагрузки у облачного провайдера (AWS, GCP, Azure) и направляет трафик с него на `Service`. Является расширением `NodePort`.
    *   **Использование:** Стандартный способ предоставления доступа к сервисам извне в облачных средах.

4.  **`ExternalName`:**
    *   **Описание:** Создает CNAME-запись в DNS кластера, которая указывает на внешний сервис (например, `my.database.example.com`).
    *   **Использование:** Для доступа к внешним сервисам изнутри кластера по внутреннему имени.

5.  **`Headless`:**
    *   **Описание:** Сервис без `ClusterIP`. Вместо балансировки он возвращает DNS-записи для всех подов, подпадающих под селектор.
    *   **Использование:** Для `StatefulSet` и сценариев, где требуется прямое обращение к конкретным подам.

---

### Пример: Service типа ClusterIP и NodePort

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
spec:
  # Тип сервиса. Если не указан, по умолчанию ClusterIP.
  type: NodePort

  # Селектор для выбора подов, на которые пойдет трафик.
  # Должен соответствовать меткам в шаблоне Deployment/ReplicaSet.
  selector:
    app: my-app

  ports:
    - name: http
      protocol: TCP
      # Внутренний порт, на котором сервис слушает внутри кластера.
      port: 80
      # Порт на подах, куда будет перенаправляться трафик.
      targetPort: 8080
      # Статический порт на узлах (для типа NodePort). Диапазон по умолчанию: 30000-32767.
      # Если не указать, будет выбран случайный.
      nodePort: 30080
```
