# Сетевая модель в Kubernetes

Сетевая модель Kubernetes основана на наборе фундаментальных принципов, которые обеспечивают простую и предсказуемую коммуникацию между компонентами кластера.

### Основные принципы:

1.  **Каждый под получает свой уникальный IP-адрес:** Все контейнеры внутри одного пода разделяют один и тот же IP-адрес и сетевое пространство имен. Они могут общаться друг с другом через `localhost`.
2.  **Поды могут общаться с подами на других узлах:** Любой под может напрямую связаться с любым другим подом в кластере, используя его IP-адрес, без необходимости в NAT (Network Address Translation).
3.  **Агенты на узле (например, kubelet) могут общаться с подами на этом же узле.**

---

### CNI (Container Network Interface)

Kubernetes не реализует сетевую модель самостоятельно. Вместо этого он делегирует эту задачу **CNI-плагинам**. CNI — это стандарт, который определяет, как среда выполнения контейнеров (например, `containerd`) должна настраивать сетевые интерфейсы для контейнеров.

При запуске пода `kubelet` вызывает CNI-плагин, который выполняет необходимые действия:

1.  **Выделяет IP-адрес** для пода из заранее определенного диапазона.
2.  **Создает сетевой интерфейс** для пода (например, виртуальную Ethernet-пару `veth`).
3.  **Подключает этот интерфейс** к сетевому мосту (`bridge`) на узле.
4.  **Настраивает маршрутизацию** так, чтобы трафик мог ходить между подами на разных узлах.

Популярные CNI-плагины: **Flannel**, **Calico**, **Cilium**, **Weave Net**.

### Примерная схема трафика (с Flannel)

1.  **Внутри узла:**
    *   Под `Pod A` на `Node 1` хочет отправить пакет поду `Pod B` на том же узле.
    *   Трафик идет от `Pod A` через его `veth` интерфейс на сетевой мост `cni0`.
    *   Мост `cni0` видит, что IP-адрес назначения принадлежит `Pod B` на этом же узле, и напрямую отправляет трафик на его `veth` интерфейс.

2.  **Между узлами:**
    *   `Pod A` на `Node 1` хочет отправить пакет поду `Pod C` на `Node 2`.
    *   Трафик снова попадает на мост `cni0`.
    *   Мост видит, что IP-адрес назначения находится в другой подсети, и, согласно таблице маршрутизации, отправляет трафик на виртуальный туннельный интерфейс, созданный Flannel (например, `flannel.1`).
    *   Flannel инкапсулирует исходный пакет в новый UDP-пакет (используя VXLAN) и отправляет его на IP-адрес `Node 2`.
    *   На `Node 2` Flannel распаковывает пакет и направляет его на мост `cni0`, который доставляет его до `Pod C`.
