Etcd(хранит всю инфу о кластере, необходимо нечетное кол-во нод где он запущен минимум 3, порт 2380 для общения между нодами с etcd, порт 2379 для подключения клиентов, требует быстрых дисков, требует широкого линка)

Api server(единственный кто общается с etcd если один etcd сдох то Api обратиться к другому, работает по REST API, критическая точка отказа) 

Controller-manager(набор контролеров, у каждой абстракции есть контролер) 

Scheduler(назначает поды на ноды учитывая:priority class, requested resources, affinity/not-affinity, QoS) 

Kubelet(работает на всех nodes, не привязан к конкретному container runtime, отдает команды контейнерному runtime , создает pod-ы, не работает с swap, отвечает за health checking, обновление состояния pod'ов, монтирование volumes , управление сетевыми интерфейсами, поддерживает cgroups для ограничения ресурсов)

Kube-proxy(стоит на всех nodes, управляет сетевыми правилами на nodes, реализует Service iptables или ipvs)(трафик приходящий на определенный айпи адрес на определенный порт перенаправлять на цепочку, в цепочке два правила, первое правило - 50% трафика в другую цепочку, второе правило - в другую цепочку, обе цепочки ссылаются на айпи адреса подов)

Для создания отказоустойчивых kubelet и kube-proxy, необходимо перед ними поставить nginx-proxy контейнер которому надо скормить в upstream айпишники всех Api server, потому что если Api сервер упал то kubelet и kube-proxy которые имебт связь только с этим Api сервером ждут пока он снова поднимиться
