``` yaml
apiVersion: v1
kind: Pod
metadata:
  name: resource-limits-pod
  labels:
    app: resource-limits-app
spec:
  containers:
    - name: example-container
      image: nginx:latest
      ports:
        - containerPort: 80
      resources:
        requests:
          memory: "128Mi"  # Минимальный объем памяти, который требуется контейнеру
          cpu: "250m"      # Минимальный объем процессорного времени(милицпу, в кубере проц это 100 милицпу) 
        limits:
          memory: "256Mi"  # Максимальный объем памяти, который контейнер может использовать
          cpu: "500m"      # Максимальный объем процессорного времени

```

В кубере есть три вида QOS-классов: Guaranteed, Burstable, BestEffort

1. Guaranteed (Гарантированный)

Условия: 

Все контейнеры в поде должны иметь указанные requests и limits для CPU и Memory.
Значения requests и limits для каждого ресурса должны быть одинаковыми.

Поведение:

Поды этого класса имеют самый высокий приоритет.
Kubernetes никогда не выберет этот под для эвакуации (termination) из-за нехватки ресурсов, если это возможно.

2. Burstable (Эластичный)

Условия:

У хотя бы одного контейнера в поде указаны requests, но limits и requests не совпадают.
Либо у некоторых контейнеров вообще отсутствуют ресурсы requests или limits.

Поведение:

Поды этого класса имеют средний приоритет.
Они получают гарантированные ресурсы, указанные в requests, но могут использовать больше, если ресурсы на узле доступны (до значения limits).
Такие поды могут быть эвакуированы, если узел перегружен, но только после эвакуации менее приоритетных подов (BestEffort).

3. BestEffort (Наилучшее усилие)

Условия: 

У пода не указаны ни requests, ни limits для CPU и памяти.

Поведение:

Поды этого класса имеют самый низкий приоритет.
Они получают ресурсы только при наличии свободных на узле.
Если узел перегружен, такие поды эвакуируются первыми.
