# Probes (Пробы)

**Probes** — это механизм диагностики, который `kubelet` использует для проверки состояния контейнера. Это ключевой инструмент для повышения надежности и отказоустойчивости приложений в Kubernetes.

Существует три типа проб:

1.  **`livenessProbe` (Проба жизнеспособности):** Проверяет, работает ли контейнер. Если проба завершается неудачно, `kubelet` убивает контейнер, и он будет перезапущен в соответствии со своей `restartPolicy`.

2.  **`readinessProbe` (Проба готовности):** Проверяет, готов ли контейнер принимать трафик. Если проба не проходит, эндпоинт пода удаляется из объектов `Service`, и трафик на него больше не направляется. Как только проба снова становится успешной, эндпоинт возвращается.

3.  **`startupProbe` (Проба запуска):** Проверяет, запустилось ли приложение в контейнере. Все остальные пробы отключаются до тех пор, пока `startupProbe` не завершится успешно. Это полезно для медленно стартующих приложений, чтобы они не были убиты `livenessProbe` до того, как успеют запуститься.

---

### Механизмы проверки

Каждая проба может использовать один из трех механизмов:

*   **`httpGet`:** Выполняет HTTP GET-запрос к указанному порту и пути. Если ответ имеет код от 200 до 399, проба считается успешной.
*   **`tcpSocket`:** Пытается открыть TCP-соединение с указанным портом. Если соединение установлено, проба успешна.
*   **`exec`:** Выполняет указанную команду внутри контейнера. Если команда завершается с кодом возврата 0, проба считается успешной.

### Конфигурация и параметры

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: probe-example
spec:
  containers:
    - name: my-app
      image: my-app-image
      ports:
        - containerPort: 8080

      # Проба запуска: дает приложению до 5 минут на старт (30 * 10s)
      startupProbe:
        httpGet:
          path: /api/health/startup
          port: 8080
        failureThreshold: 30
        periodSeconds: 10

      # Проба жизнеспособности: перезапустит контейнер, если он завис
      livenessProbe:
        httpGet:
          path: /api/health/liveness
          port: 8080
        initialDelaySeconds: 15 # Начать проверку через 15 секунд после старта
        periodSeconds: 20       # Проверять каждые 20 секунд
        timeoutSeconds: 5         # Таймаут для запроса
        failureThreshold: 3       # 3 неудачные попытки = перезапуск

      # Проба готовности: уберет под из сервиса, если он не готов принимать трафик
      readinessProbe:
        exec:
          command:
            - /bin/sh
            - -c
            - check_db_connection.sh
        initialDelaySeconds: 5
        periodSeconds: 10
        successThreshold: 1 # 1 удачная попытка = готов
```

*   `initialDelaySeconds`: Задержка в секундах перед запуском первой пробы.
*   `periodSeconds`: Как часто (в секундах) выполнять пробу.
*   `timeoutSeconds`: Таймаут для выполнения пробы (в секундах).
*   `failureThreshold`: Количество неудачных попыток, после которого проба считается проваленной.
*   `successThreshold`: Количество удачных попыток, после которого проба (после провала) снова считается успешной.
