# Horizontal Pod Autoscaler (HPA)

**Horizontal Pod Autoscaler (HPA)** — это стандартный ресурс Kubernetes, который автоматически масштабирует количество подов в репликации, развертывании или StatefulSet на основе наблюдаемых метрик, таких как использование CPU или памяти.

Это ключевой компонент для создания эластичных и отказоустойчивых приложений, способных адаптироваться к переменной нагрузке без ручного вмешательства.

## Принцип работы

HPA периодически проверяет метрики, указанные в его конфигурации. Если текущее значение метрики превышает заданный порог, HPA увеличивает количество реплик (`replicas`) у целевого ресурса (например, у Deployment). Если нагрузка падает, количество реплик уменьшается до указанного минимума.

Для работы с метриками ресурсов (CPU, память) в кластере должен быть установлен **Metrics Server**.

## Пример конфигурации

Вот пример манифеста HPA, который масштабирует `Deployment` с именем `my-app` на основе среднего использования CPU.

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: my-app-hpa
  namespace: default
spec:
  # Ссылка на масштабируемый ресурс
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app

  # Границы масштабирования
  minReplicas: 2
  maxReplicas: 10

  # Метрики для масштабирования
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization # Тип цели — среднее использование
          averageUtilization: 50 # Порог в 50%
```

### Ключевые поля

-   `spec.scaleTargetRef`: Указывает на ресурс, который нужно масштабировать (например, `Deployment`, `StatefulSet`).
-   `spec.minReplicas`: Минимальное количество подов, которое должно быть всегда запущено.
-   `spec.maxReplicas`: Максимальное количество подов, до которого HPA может масштабировать приложение.
-   `spec.metrics`: Список метрик, на основе которых принимается решение о масштабировании.
    -   `type: Resource`: Используются стандартные метрики ресурсов (CPU или память).
    -   `resource.name`: Имя ресурса (`cpu` или `memory`).
    -   `target.averageUtilization`: Целевое среднее значение использования ресурса по всем подам в процентах.

## Важные замечания

❗️ **Необходимость Metrics Server**: Для работы HPA с метриками `cpu` и `memory` в кластере должен быть развернут **Metrics Server**. Без него HPA не сможет получать данные о потреблении ресурсов подами.

❗️ **Лимиты и запросы (limits/requests)**: Чтобы HPA корректно рассчитывал `averageUtilization`, у контейнеров в подах должны быть установлены запросы на ресурсы (`requests`). Например, `requests.cpu: "200m"`.

❗️ **Другие типы метрик**: HPA поддерживает масштабирование по кастомным метрикам (например, количество запросов в секунду из Prometheus) и по метрикам объектов (например, длина очереди в RabbitMQ).
