# Istio: компоненты и архитектура

Istio реализует модель сетевого уровня поверх Kubernetes, разделяя обязанности на две плоскости: плоскость данных (data plane) и плоскость управления (control plane). Такой подход обеспечивает единообразный контроль трафика, наблюдаемость и безопасность без внедрения логики сети в сами приложения.

## Плоскость данных

Плоскость данных состоит из прокси Envoy, работающих рядом с каждым приложением в виде sidecar-контейнеров, а также из специализированных шлюзов:

-   **Sidecar-прокси** перехватывают входящий и исходящий трафик пода, применяют правила маршрутизации, балансировки, ретраев, таймаутов и политику безопасности.
-   **Ingress Gateway** обеспечивает публикацию сервисов наружу кластера, терминацию TLS и маршрутизацию по HTTP(S)/TCP.
-   **Egress Gateway** контролирует исходящий трафик к внешним ресурсам, позволяя централизовать политику доступа.

Перехват трафика выполняется с помощью iptables или CNI-плагина, переадресующего потоки в Envoy (типично на порты 15006 inbound и 15001 outbound). Прокси собирают метрики, трассировки и логи, а также реализуют mTLS между сервисами.

## Плоскость управления

Современные версии Istio используют единый компонент **istiod**, который объединяет прежние роли (Pilot, Citadel, части Galley):

-   **Конфигурация и сервис-дискавери**: преобразует Kubernetes-объекты и CRD Istio в динамические xDS-конфигурации (LDS/RDS/CDS/EDS) и распространяет их в прокси.
-   **Безопасность**: выпускает и ротирует сертификаты на основе SPIFFE-идентичностей, обеспечивает SDS (Secret Discovery Service) для Envoy.
-   **Политики и телеметрия**: включает механизмы авторизации/аутентификации и интеграцию с системами мониторинга и трейсинга через фильтры Envoy.

Прокси устанавливают защищённое соединение с istiod и получают обновления конфигурации в потоковом режиме, что обеспечивает реактивность и консистентность сети.

## Модель конфигурации (CRD)

Istio расширяет Kubernetes через набор CRD, формируя декларативную модель сетевого поведения:

-   `VirtualService` — определяет HTTP/TCP-маршруты, канареечные переводы, ретраи и таймауты.
-   `DestinationRule` — политики для целевых служб: балансировка, подсеты (subsets), TLS-параметры.
-   `Gateway` — конфигурация входных/исходящих шлюзов на уровне L7.
-   `ServiceEntry` — объявление внешних или нестандартных сервисов для дискавери.
-   `Sidecar` — ограничения видимости и зональность конфигурации для конкретных workloads.
-   `PeerAuthentication`, `RequestAuthentication` — mTLS и JWT-аутентификация.
-   `AuthorizationPolicy` — правила доступа L3/L4/L7.
-   `EnvoyFilter` — тонкая настройка фильтров Envoy при необходимости.

## Потоки трафика

-   **Входящий (inbound)**: iptables перенаправляет пакеты в Envoy sidecar, который проверяет политику, выполняет TLS-рукопожатие и проксирует запрос в приложение.
-   **Исходящий (outbound)**: трафик приложения идёт в Envoy, который применяет VirtualService/DestinationRule, балансирует по эндпоинтам, шифрует и отправляет.
-   **Граничный трафик**: Ingress/Egress Gateways выступают точками контроля и наблюдаемости для периметра.

## Краткая сводка компонентов

| Компонент | Плоскость | Назначение |
| :--- | :--- | :--- |
| **Envoy sidecar** | Data | Перехват, маршрутизация, mTLS, телеметрия |
| **Ingress/Egress GW**| Data | Контроль периметра и внешних направлений |
| **istiod** | Control | xDS, CA/SDS, политики, дискавери |

Пример минимальной конфигурации маршрутизации с подсетами версий сервиса:

```yaml
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: reviews
spec:
  host: reviews.default.svc.cluster.local
  subsets:
  - name: v1
    labels: { version: v1 }
  - name: v2
    labels: { version: v2 }

---
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: reviews
spec:
  hosts: [ "reviews.default.svc.cluster.local" ]
  http:
  - match:
    - headers:
        x-user:
          exact: canary
    route:
    - destination: { host: reviews.default.svc.cluster.local, subset: v2 }
  - route:
    - destination: { host: reviews.default.svc.cluster.local, subset: v1 }
```
