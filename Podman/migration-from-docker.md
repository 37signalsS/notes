# Миграция с Docker на Podman

## Определения

**Миграция на Podman** — процесс перевода контейнеризированных приложений с Docker на Podman, включающий замену демона `dockerd` на daemonless-архитектуру, переход в rootless-режим и адаптацию конфигураций (Compose → Quadlet).

**Quadlet** — инструмент Podman для нативной интеграции с `systemd`. Он преобразует декларативные конфигурации контейнеров в системные юниты.

**podlet** — утилита для автоматической конвертации файлов `docker-compose.yaml` в юниты Quadlet.

**Linger** — настройка `systemd`, позволяющая пользовательским процессам (и контейнерам Podman) продолжать работу после завершения SSH-сессии.

## Основные концепции

### Зачем мигрировать

1. **Безопасность**: Устранение «единой точки отказа» в виде рутового демона. В Podman контейнеры по умолчанию работают без привилегий (rootless).
2. **Надёжность**: При сбое демона Docker все контейнеры могут остановиться. В Podman каждый контейнер — независимый процесс.
3. **Интеграция с ОС**: Контейнеры управляются через стандартные `systemctl` и `journalctl`.
4. **Ресурсы**: Podman потребляет меньше RAM и CPU в режиме ожидания (idle), так как не требует постоянно запущенного демона.

Подробное сравнение архитектур: **[Podman vs Docker](./podman_vs_docker.md)**.

## Практические сценарии

### Шаг 1: Подготовка хоста

Для корректной работы в rootless-режиме необходимо выполнить две настройки.

#### 1. Разрешение портов < 1024

По умолчанию обычный пользователь не может открывать порты ниже 1024. Чтобы разрешить использование, например, порта 80:

```bash
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/90-unprivileged-ports.conf
sudo sysctl -p /etc/sysctl.d/90-unprivileged-ports.conf
```

*Теперь порты 0–79 доступны только root, а от 80 и выше — обычным пользователям.*

#### 2. Включение Linger

Чтобы контейнеры не «умирали» при закрытии терминала:

```bash
sudo loginctl enable-linger $USER
```

*Это заставляет systemd запускать менеджер пользователя при старте системы и сохранять его процессы активными.*

### Шаг 2: Установка и настройка API

```bash
# Установка (Debian/Ubuntu)
sudo apt install podman

# Включение эмуляции Docker API через сокет (опционально)
systemctl --user enable --now podman.socket
```

*Путь к сокету для Docker-совместимых инструментов: `/run/user/$(id -u)/podman/podman.sock`.*

### Шаг 3: Запуск Compose-файлов

Перед полной конвертацией в Quadlet можно использовать существующие `docker-compose.yml` напрямую.

**Вариант А: podman-compose (Python)**
Нативная реализация, не требующая Docker-компонентов.

```bash
sudo apt install podman-compose
podman-compose up -d
```

**Вариант Б: Podman Compose (Wrapper)**
Использование оригинального `docker-compose` через сокет Podman.

```bash
systemctl --user enable --now podman.socket
export DOCKER_HOST="unix://$XDG_RUNTIME_DIR/podman/podman.sock"
podman compose up -d
```

Подробнее о различиях и настройке: **[Podman Compose](./podman-compose.md)**.

### Шаг 4: Конвертация в Quadlet (Рекомендуется)

Для долгосрочной эксплуатации и нативной интеграции с ОС рекомендуется переходить на Quadlet. Для автоматизации используйте `podlet`.

Автоматическая конвертация не всегда идеальна. Типичные исправления:

1. **Сети (Networks)**: Если в Compose используются внешние сети, блок `networks` часто приходится удалять и прописывать `Network=name.network` в секции `[Container]`.
2. **Зависимости и Healthchecks**: Podman не поддерживает `depends_on` напрямую.
   - Используйте зависимости systemd (`Requires=`, `After=`) в сочетании с **`Notify=healthy`** в Quadlet-юнитах.
   - Используйте ручную wait-логику (циклы проверки `until`) в `entrypoint` или команде запуска.
   - Подробнее: **[Зависимости и Healthchecks в Podman](./podman_healthchecks.md#зависимости-через-notifyhealthy)**.
3. **Объёмы (Volumes)**: Пути маппинга UID/GID в rootless-режиме могут потребовать уточнения. Подробнее: **[Podman: Хранилище](./podman_volumes_and_storage.md)**.

## Дополнительная информация

### Нюансы и ограничения

- **Docker Socket в контейнере**: Приложения, пробрасывающие `/var/run/docker.sock` внутрь контейнера (например, Portainer), потребуют настройки прав доступа к сокету Podman или работы в rootful-режиме.
- **Отсутствие systemd**: На дистрибутивах без systemd (Alpine с OpenRC) Quadlet недоступен.
- **Привилегированные порты**: Если приложение жестко завязано на порты < 80, потребуется либо `sysctl` (см. Шаг 1), либо использование Reverse Proxy (Nginx/Angie).
