# Подман: Хранилище и работа с файловой системой

## Определения

**Файловая система контейнера** — комбинированная файловая система, состоящая из слоев образа (только для чтения, реализовано через OverlayFS) и записываемого слоя конкретного контейнера.

**Bind Mount (Привязанное монтирование)** — механизм прямого монтирования директории или файла с хостовой машины в файловую систему контейнера.

**Named Volume (Именованный том)** — хранилище, жизненным циклом которого управляет Podman. Физическое расположение на хосте скрыто от пользователя за абстракцией имени тома.

**tmpfs Mount** — временное хранилище, создаваемое в оперативной памяти (**RAM**). Данные теряются при остановке контейнера.

**UID (User ID)** — уникальный идентификатор пользователя в операционной системе.

**GID (Group ID)** — уникальный идентификатор группы в операционной системе.

## Основные концепции

### Расположение данных в системе

В Podman пути к образам и томам зависят от режима запуска (rootful или rootless).

| Режим запуска | Метаданные и образы | Именованные тома |
| :--- | :--- | :--- |
| **Rootless (Безрутовый)** | `~/.local/share/containers/storage` | `~/.local/share/containers/storage/volumes/` |
| **Rootful (Системный)** | `/var/lib/containers/storage` | `/var/lib/containers/storage/volumes/` |

### Управление томами (CLI)

Основные команды для работы с именованными томами:

```bash
# Создание нового тома
podman volume create mydata

# Просмотр списка всех томов
podman volume ls

# Получение детальной информации о томе (путь на хосте)
podman volume inspect mydata --format '{{.Mountpoint}}'
# → /home/user/.local/share/containers/storage/volumes/mydata/_data

# Очистка неиспользуемых томов
podman volume prune
```

### Типы монтирования

Podman поддерживает те же типы монтирования, что и Docker, но добавляет специфические флаги для управления безопасностью (SELinux) и правами доступа в rootless-режиме.

## Практические сценарии

### 1. Работа с SELinux (флаги z и Z)

На дистрибутивах с включенным **SELinux** (RHEL, Fedora, CentOS) прямое монтирование директорий хоста может быть заблокировано. Для корректной автоматической разметки контекста безопасности используются флаги:

- **`:z`**: Общий доступ. Контекст переразмечается так, чтобы несколько контейнеров могли одновременно использовать эту директорию.
- **`:Z`**: Приватный доступ. Контекст переразмечается исключительно для данного контейнера.

```bash
# Пример монтирования с приватным контекстом
podman run --rm -v ~/my_data:/data:Z alpine touch /data/test.txt
```

### 2. Управление владельцем файлов (флаг U)

В rootless-режиме пользователь `root` внутри контейнера сопоставляется с обычным пользователем на хосте. При монтировании директорий часто возникают проблемы с правами доступа (`Permission denied`). Флаг **`:U`** (unshare) автоматически выполняет `chown` для монтируемой директории на хосте, подстраивая владельца под UID/GID внутри контейнера.

```bash
# Автоматическая корректировка прав владельца на хосте
podman run --rm -v ./configs:/etc/app:U my_app_image
```

### 3. Использование временного оверлея (флаг O)

Флаг **`:O`** позволяет монтировать директорию хоста в режиме "копии при записи" (Copy-on-Write). Все изменения, внесенные контейнером, сохраняются во временном слое и не отражаются на реальных файлах хоста.

```bash
# Монтирование исходного кода без риска его изменения контейнером
podman run --rm -it -v $(pwd)/src:/app:O alpine sh
```

### 4. Монтирование только для чтения (ro)

Для повышения безопасности конфигурационные файлы рекомендуется монтировать в режиме `read-only`.

```bash
podman run -v /etc/config.json:/app/config.json:ro my_app
```

## Дополнительная информация

### Сводная таблица специфических флагов

| Флаг | Назначение | Контекст использования |
| :--- | :--- | :--- |
| `:z` | Общий доступ SELinux | Несколько контейнеров к одной папке |
| `:Z` | Приватный доступ SELinux | Эксклюзивный доступ контейнера |
| `:U` | Смена владельца (Chown) | **Rootless** режим, решение проблем с правами |
| `:O` | Временный Overlay | Тестирование без изменения файлов хоста |
| `:ro` | Только чтение | Защита конфигураций от изменения |
