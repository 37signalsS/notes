# Подман: Переменные окружения

## Определения

**Переменные окружения (Environment Variables, ENV)** — динамические значения, определяющие параметры работы процессов внутри контейнера. В Podman они используются для конфигурации приложений (адреса БД, порты), переключения режимов работы и передачи настроек без изменения образа.

**ARG (Build Arguments)** — переменные, доступные исключительно в процессе сборки образа. В отличие от `ENV`, они не сохраняются в итоговом образе и не видны при его запуске, если не были явно присвоены переменной `ENV`. Подробнее о синтаксисе в Containerfile: **[Переменные: ENV и ARG](../Docker/Dockerfile/Instructions/environment_variables.md)**.

**Quadlet** — инструмент Podman для интеграции контейнеров с **systemd**, позволяющий описывать переменные окружения в декларативном виде.

## Основные концепции

### Способы передачи переменных

В Podman существует несколько способов передачи переменных окружения в контейнер:

| Метод | Параметр / Опция | Описание |
| :--- | :--- | :--- |
| **CLI (Прямой)** | `-e KEY=VALUE` | Задание значения непосредственно в команде запуска. |
| **CLI (Проброс)** | `-e HOST_VAR` | Значение переменной берется из текущей оболочки хоста. |
| **Файл переменных** | `--env-file .env` | Массовая загрузка ключей и значений из внешнего файла. |
| **Инструкция ENV** | `ENV KEY=VALUE` | Переменная зашивается в метаданные образа при сборке. |

### Приоритет переопределения

При наличии конфликтующих определений Podman применяет значения в следующем порядке (от высшего к низшему):

1. **Флаг `-e`** в командной строке (extra-vars).
2. **Значения из файла `--env-file`** (последний указанный файл имеет приоритет).
3. **Инструкция `ENV`** внутри образа (Containerfile).
4. **Значения по умолчанию** внутри кода приложения.

Пример: `podman run --env-file .env -e APP_NAME=true myapp` — значение `-e` перезапишет то, что указано в файле `.env`.

## Практические сценарии

### 1. Подготовка приложения (Python)

**app.py**:
```python
import os
name = os.getenv("APP_NAME", "Unknown App")
print(f"Hello from {name}!")
```

**Containerfile**:
```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY app.py .
CMD ["python", "app.py"]
```

**Сборка и запуск**:
```bash
podman build -t myapp .
# С параметром
podman run --rm -e APP_NAME="Podman Demo" myapp # → Hello from Podman Demo!
# Без параметров (default)
podman run --rm myapp # → Hello from Unknown App!
```

### 2. Запуск с конфигурационным файлом (.env)

Использование файлов позволяет избежать "раздувания" командной строки.

**Файл `.env`**:
```ini
APP_NAME="Podman Demo"
HTTP_PORT=8080
LOGIN=admin
PASSWORD=pa$$w0rd
```

**Запуск**:
```bash
podman run --rm --env-file .env myapp
```
*Совет: Добавьте `.env` в `.gitignore`, чтобы случайно не закоммитить данные. Используйте `env.example` как шаблон для репозитория.*

### 3. Определение переменных в Quadlet (systemd)

Для сервисов, управляемых через **systemd**, переменные описываются в секции `[Container]`.

**Файл `app.container`**:
```ini
[Container]
Image=localhost/myapp:latest
# Прямое определение
Environment=APP_NAME=QuadletApp
Environment=DEBUG=false
# Загрузка из файла
EnvironmentFile=%h/dev/app/.env
```
`%h` — путь к домашнему каталогу. Переопределение работает так же: `Environment=DEBUG=true` в юните перезапишет значение из `EnvironmentFile`.

*Нюанс: Если прав на файл `.env` не хватит (особенно при включенном SELinux), переменные не будут переданы. Проверяйте логи на наличие варнингов.*

## Рекомендации (Best Practices)

- **Не хардкодьте**: Не прописывайте значения переменных в `Containerfile`, если они могут измениться.
- **Безопасность**: Не храните секреты (пароли, ключи) в `.env` файлах или `Environment`. Используйте для этого **[Секреты Podman](./podman_secrets.md)**.
- **Шаблоны**: Всегда создавайте `.env.example` с тестовыми значениями для совместной работы.
- **Разделение окружений**: Используйте разные файлы для разных сред (например, `.env.dev`, `.env.prod`).
- **Инспекция**: Проверяйте итоговое окружение через `podman inspect` или `podman exec <id> env`.

### 3. Раскрытие переменных в командах запуска

Если переменная окружения должна быть использована как часть команды запуска (например, в `CMD`), необходимо использовать вызов через оболочку (`shell form`), иначе переменная не будет интерпретирована.

**Dockerfile / Containerfile**:

```dockerfile
ENV APP_PORT=8080
# Правильно (интерпретируется оболочкой)
CMD sh -c "python app.py --port $APP_PORT"

# Ошибка (переменная не будет раскрыта)
CMD ["python", "app.py", "--port", "$APP_PORT"]
```

## Дополнительная информация

### Безопасность и секреты

**Критическое правило:** Не используйте переменные окружения для передачи чувствительных данных (пароли, токены, ключи).

- Значения переменных видны в выводе `podman inspect`.
- Переменные окружения могут попадать в логи систем мониторинга и CI/CD.
- Процессы на хосте могут прочитать окружение контейнера через `/proc`.

Для безопасного управления конфиденциальными данными используйте специализированный механизм: **[Секреты Podman](./podman_secrets.md)**.
