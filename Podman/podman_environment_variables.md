# Podman: Переменные окружения

## Определения

**Переменные окружения (Environment Variables, ENV)** — динамические значения, которые влияют на поведение процессов внутри контейнера. Используются для конфигурации (порты, адреса БД), управления режимами (debug/prod) и передачи настроек без изменения образа.

**ARG (Build Arguments)** — переменные, доступные только на этапе сборки образа (`podman build`). Не сохраняются в итоговом образе и не доступны запущенному контейнеру, если не были явно переданы в `ENV`.

## Основные концепции

### Способы передачи переменных

| Метод | Команда / Параметр | Описание |
| :--- | :--- | :--- |
| **Командная строка** | `-e KEY=VALUE` | Прямая передача при запуске |
| **Файл переменных** | `--env-file .env` | Чтение списка `KEY=VALUE` из текстового файла |
| **Наследование** | `-e HOST_VAR` | Проброс переменной из текущей оболочки хоста |
| **Containerfile** | `ENV KEY=VALUE` | Жесткое прописывание в слое образа |

### Приоритет переопределения (от высшего к низшему)

1. Флаг `-e` в командной строке (перекрывает всё).
2. Значения из файла `--env-file`.
3. Инструкция `ENV` в `Containerfile`.
4. Значения по умолчанию в коде приложения.

## Практические сценарии

### 1. Базовый запуск с переменными

```python
# app.py
import os
name = os.getenv("APP_NAME", "Unknown")
print(f"Hello from {name}!")
```

```bash
# Запуск с передачей переменной
podman run --rm -e APP_NAME="Podman Demo" myapp
# → Hello from Podman Demo!
```

### 2. Использование .env файлов

Создайте файл `.env`:

```ini
APP_NAME="Production App"
HTTP_PORT=8080
DEBUG=false
```

Запуск:

```bash
podman run --rm --env-file .env myapp
```

> **Best Practice:** Добавляйте `.env` в `.gitignore`, чтобы не скомпрометировать настройки в репозитории. Используйте `.env.example` как шаблон для команды.

### 3. Интеграция с Quadlet (Systemd)

В файле юнита (`/etc/containers/systemd/*.container`) переменные описываются в секции `[Container]`:

```ini
[Container]
Image=nginx
# Одиночные переменные
Environment=DEBUG=true
Environment=LOG_LEVEL=info
# Путь к файлу (рекомендуется для больших списков)
EnvironmentFile=%h/dev/app/.env
```

`%h` — спецификатор systemd для домашнего каталога пользователя.

### 4. Использование переменных в CMD/ENTRYPOINT

Для использования переменных внутри команд запуска необходимо использовать shell-форму:

```dockerfile
# Правильно (shell form)
CMD ["sh", "-c", "echo Running on port $PORT"]

# Не сработает (exec form — переменная не будет раскрыта)
CMD ["echo", "Running on port $PORT"]
```

## Дополнительная информация

### ARG vs ENV в процессе сборки

```dockerfile
ARG VERSION=1.0
ENV APP_VERSION=$VERSION
```

- `ARG` используется для параметризации сборки: `podman build --build-arg VERSION=2.0 .`
- `ENV` делает значение доступным приложению во время работы контейнера.

### Безопасность

**Никогда не передавайте пароли, токены и ключи через обычные переменные окружения.**

- Они видны в выводе `podman inspect`.
- Они могут попасть в логи системы и CI/CD.
- Для чувствительных данных используйте **[Podman Secrets](./podman_secrets.md)**.
