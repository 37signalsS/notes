# Podman: Переменные окружения

## Определения

**Переменные окружения (Environment Variables, ENV)** — динамические пары "ключ-значение", доступные процессам внутри контейнера. В Podman они являются основным механизмом конфигурации приложений без модификации их кода или образа.

**ARG (Build Arguments)** — переменные времени сборки. Они доступны только во время выполнения `podman build` и не сохраняются в метаданных запущенного контейнера, если не были явно переданы в `ENV`. Подробнее: **[Переменные в Containerfile](../Docker/Dockerfile/Instructions/environment_variables.md)**.

**Environment File (.env)** — текстовый файл, содержащий список переменных, который Podman может загрузить массово для настройки контейнера.

---

## Основные концепции

### Способы передачи переменных

Podman предоставляет гибкие методы управления окружением в зависимости от сценария использования:

| Метод | Параметр | Описание |
| :--- | :--- | :--- |
| **CLI (Прямой)** | `-e KEY=VAL` | Задание значения непосредственно в команде `run`. |
| **CLI (Проброс)** | `-e HOST_VAR` | Передача переменной из текущей оболочки пользователя (без знака `=`). |
| **Файл переменных** | `--env-file f.env` | Загрузка списка переменных из внешнего файла. |
| **Метаданные образа** | `ENV` | Значения, жестко заданные в Containerfile при сборке. |
| **Динамическое (5.x)** | `podman update` | Изменение переменных у **уже запущенного** контейнера. |

### Иерархия приоритетов (Precedence)

При совпадении имен переменных Podman применяет их в следующем порядке (от высшего к низшему):

1.  **Флаг `-e` / `--env`**: Командная строка всегда имеет наивысший приоритет.
2.  **Файл `--env-file`**: Если указано несколько файлов, последний имеет преимущество над предыдущими.
3.  **Инструкция `ENV`**: Значения, вшитые в образ.
4.  **Значения в коде**: Дефолтные настройки самого приложения.

## Практические сценарии

### 1. Использование конфигурационных файлов (.env)
Рекомендуется для локальной разработки и разделения настроек сред (Dev/Prod).

**Файл `web.env`**:
```ini
NODE_ENV=production
API_URL=http://api.internal:8080
LOG_LEVEL=info
```

**Запуск**:
```bash
podman run -d --name web-server --env-file web.env nginx:alpine
```

### 2. Динамическое обновление (Podman 5.x+)
В версиях 5.x появилась возможность менять окружение без пересоздания контейнера.

```bash
# Добавление или изменение переменной на лету
podman update --env DEBUG=true my-running-app

# Проверка применения изменений
podman exec my-running-app env | grep DEBUG
```
*Примечание: Приложение должно поддерживать перечитывание переменных (или горячую перезагрузку), иначе изменения вступят в силу только после рестарта процесса внутри контейнера.*

### 3. Переменные в Quadlet (systemd)
Quadlet позволяет использовать спецификаторы systemd для динамического формирования путей.

**Файл `app.container`**:
```ini
[Container]
Image=localhost/api-server:latest

# Прямое задание
Environment=APP_PORT=3000
Environment=DATA_DIR=/data/%u

# Загрузка из файла (относительно домашней папки пользователя)
EnvironmentFile=%h/.config/app/prod.env

[Service]
# Автоматический рестарт при изменении конфига
Restart=on-failure
```
`%u` — имя пользователя, `%h` — путь к домашней директории. Это делает конфигурацию переносимой между пользователями.

## Рекомендации и безопасность

### Разграничение ENV и Secrets
**Критическое правило:** Никогда не передавайте пароли, API-ключи или сертификаты через переменные окружения.

- **Риск**: Переменные видны в `podman inspect`, `ps`, а также в логах систем мониторинга и через `/proc/<pid>/environ` на хосте.
- **Решение**: Используйте нативный механизм секретов.

```bash
# Правильный подход (Secret)
podman secret create db_pass -
podman run --secret db_pass my-db-app
```
Подробнее: **[Секреты Podman](./podman_secrets.md)**.

### Раскрытие переменных в командах
Для использования переменной внутри `CMD` или `ENTRYPOINT` всегда используйте shell-форму или явный вызов оболочки:

```dockerfile
# Верно (интерпретируется /bin/sh)
CMD ["sh", "-c", "echo $MY_VAR"]

# Ошибка (переменная не будет раскрыта)
CMD ["echo", "$MY_VAR"]
```
