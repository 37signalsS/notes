# Podman: Основные команды CLI

## Определения

**Podman CLI** — интерфейс командной строки для управления контейнерами, образами, подами и томами. В отличие от Docker, Podman не требует фонового демона (**daemonless**) и ориентирован на работу без привилегий root (**rootless**).

**OCI (Open Container Initiative)** — набор стандартов для форматов образов и сред выполнения контейнеров, которым полностью соответствует Podman.

**Pod** — группа из одного или нескольких контейнеров, разделяющих сетевые ресурсы и хранилище. Концепция заимствована из Kubernetes и реализована в Podman нативно.

## Основные концепции

### Информация о системе и настройка

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| Версия | `podman --version` | Краткая информация о версии бинарного файла |
| Инфо | `podman info` | Детальные данные о хосте, хранилище и сетевом стеке |
| Логин | `podman login <registry>` | Аутентификация в реестре образов |
| Поиск | `podman search <term>` | Поиск образов в настроенных реестрах |

### Управление образами

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| Список | `podman images` | Показать все локальные образы |
| Загрузка | `podman pull <image>` | Скачать образ (рекомендуется указывать полный путь) |
| Сборка | `podman build -t <tag> .` | Сборка образа по Containerfile/Dockerfile |
| Удаление | `podman rmi <image>` | Удалить образ (флаг `-f` для принудительного) |
| История | `podman history <image>` | Показать слои и команды сборки образа |
| Мультиплатформа | `podman farm build ...` | (Podman 5.x) Сборка для нескольких архитектур одновременно |

### Управление контейнерами

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| Запуск | `podman run [flags] <image>` | Создать и запустить новый контейнер |
| Список | `podman ps [-a]` | Список запущенных (или всех) контейнеров |
| Логи | `podman logs -f <name>` | Просмотр логов в реальном времени |
| Исполнение | `podman exec -it <name> sh` | Запуск команды в работающем контейнере |
| Остановка | `podman stop [-t 10] <name>` | Плавная остановка (SIGTERM, затем SIGKILL) |
| Удаление | `podman rm -f <name>` | Принудительное удаление контейнера |
| Обновление | `podman update [flags] <id>` | (Podman 5.x) Изменение лимитов и параметров на лету |
| Изменения | `podman diff <id>` | Показать изменения в ФС контейнера относительно образа |

### Управление подами (Pods)

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| Создание | `podman pod create --name <n>` | Создать пустой под с инфраструктурным контейнером |
| Список | `podman pod ps` | Список всех подов и количество контейнеров в них |
| Запуск в поде | `podman run --pod <n> ...` | Запустить контейнер внутри существующего пода |
| Остановка | `podman pod stop <n>` | Остановить все контейнеры внутри пода |

## Практические сценарии

### 1. Запуск изолированного веб-стека в поде
Поды позволяют контейнерам взаимодействовать через `localhost`, имитируя поведение Kubernetes.

```bash
# Создаем под с пробросом порта
podman pod create --name web-app -p 8080:80

# Добавляем БД (PostgreSQL)
podman run -d --pod web-app --name db -e POSTGRES_PASSWORD=secret postgres:alpine

# Добавляем сервер (Nginx), который может обращаться к БД по localhost:5432
podman run -d --pod web-app --name server nginx:alpine
```

### 2. Динамическое обновление параметров (Podman 5.x)
В версии 5.0 появилась возможность менять конфигурацию запущенного контейнера без его пересоздания.

```bash
# Ограничиваем CPU и память для уже работающего контейнера
podman update --cpus 0.5 --memory 512m my-container

# Включаем политику перезапуска
podman update --restart always my-container
```

### 3. Экспорт и импорт в Kubernetes
Podman является идеальным мостом между локальной разработкой и кластером.

```bash
# Генерируем YAML для существующего пода
podman kube generate web-app > deployment.yaml

# Запускаем локально из YAML (воспроизведение среды)
podman kube play deployment.yaml
```

## Дополнительная информация

### Очистка ресурсов (Pruning)
Регулярная очистка помогает избежать переполнения диска, особенно в Rootless-режиме, где квоты могут быть ограничены.

```bash
# Удалить все неиспользуемые объекты (контейнеры, сети, образы без тегов)
podman system prune -a

# Удалить только старые тома
podman volume prune
```

### Полезные флаги запуска (`podman run`)
- `-d`: Запуск в фоновом режиме (detached).
- `--rm`: Автоматическое удаление контейнера после завершения процесса.
- `-v /host:/cont:Z`: Монтирование тома с коррекцией меток SELinux.
- `--network=pasta`: (Podman 5.0) Использование высокопроизводительного сетевого стека для Rootless.
- `--replace`: Автоматически удаляет существующий контейнер с тем же именем перед запуском.
