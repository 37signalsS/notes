# Подман: Секреты (Secrets)

## Определения

**Podman Secrets** — это встроенное хранилище конфиденциальных данных (паролей, API-ключей, сертификатов), обеспечивающее их безопасную передачу в контейнеры. В отличие от переменных окружения, секреты не отображаются в логах и выводе команды `podman inspect`.

**tmpfs mount** — механизм монтирования секретов. По умолчанию секреты монтируются как временные файлы в директорию `/run/secrets/` внутри контейнера. При остановке контейнера данные автоматически исчезают из оперативной памяти контейнера.

## Основные концепции

### Управление секретами через CLI

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| **Создать** | `echo "pass" \| podman secret create <имя> -` | Создание секрета из стандартного ввода (stdin) |
| **Список** | `podman secret ls` | Показать все доступные секреты |
| **Инспекция** | `podman secret inspect <имя>` | Показать метаданные секрета (без самого значения) |
| **Удаление** | `podman secret rm <имя>` | Удалить секрет из хранилища |

### Особенности безопасности

- **Доступ только для чтения**: Секреты монтируются в контейнер в режиме `read-only`.
- **Локальное хранилище**: В Podman секреты доступны в обычном режиме работы, в отличие от Docker, где для этой функции требуется инициализация Swarm-кластера.
- **Интеграция с OCI**: Поддержка стандарта **OCI (Open Container Initiative)** обеспечивает совместимость с различными средами выполнения.

## Практические сценарии

### 1. Создание и использование секрета

```bash
# Создание секрета из строки
echo "super_secret_password" | podman secret create db_password -
# → 5a4b3c2d1e... (ID секрета)

# Запуск контейнера с подключенным секретом
podman run --rm --secret db_password alpine cat /run/secrets/db_password
# → super_secret_password
```

### 2. Чтение секрета в приложении (Python)

Приложение должно считывать секрет как обычный файл из файловой системы:

```python
import os

def get_secret(secret_name):
    # Путь по умолчанию внутри контейнера
    secret_path = f"/run/secrets/{secret_name}"
    if os.path.exists(secret_path):
        with open(secret_path, "r") as f:
            return f.read().strip()
    return None

db_pass = get_secret("db_password")
```

### 3. Настройка пути монтирования (target)

Если приложение ожидает секрет по специфическому пути:

```bash
podman run --secret db_password,target=/etc/db/pass.txt myapp
```

### 4. Использование в юнитах Quadlet (systemd)

Для автоматизации через **Quadlet** секреты указываются в секции `[Container]`.

**Файл:** `/etc/containers/systemd/app.container`

```ini
[Container]
Image=nginx
Secret=db_password
Secret=api_key,target=/app/key
```

## Дополнительная информация

### Сравнение с переменными окружения

| Характеристика | Environment Variables | Podman Secrets |
| :--- | :--- | :--- |
| **Безопасность** | Низкая (видны в `inspect` и `ps`) | Высокая (защищены в памяти) |
| **Видимость в логах** | Высокий риск утечки | Защищено |
| **Формат доступа** | Переменная окружения (`$VAR`) | Файл в `/run/secrets/` |
| **Назначение** | Нечувствительная конфигурация | Пароли, ключи, сертификаты |

### Резюме по хранению данных

- **Хранить в Secrets:** Пароли БД, приватные ключи SSH, токены API, SSL-сертификаты.
- **Хранить в Env:** Номера портов, IP-адреса, флаги отладки (DEBUG=true), имена сервисов.
