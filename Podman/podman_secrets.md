# Секреты в Podman

## Определения

**Podman Secrets** — это встроенный механизм управления конфиденциальными данными (паролями, API-ключами, сертификатами), обеспечивающий их безопасную доставку в контейнеры. В отличие от переменных окружения, секреты не сохраняются в истории слоев образа и не видны в выводе команд `podman inspect` или `podman ps`.

**tmpfs mount** — основная технология доставки секретов. По умолчанию Podman монтирует секреты во временную файловую систему в оперативной памяти контейнера. Это гарантирует, что чувствительные данные никогда не будут записаны на диск внутри контейнера.

---

## Основные концепции

### Механизм хранения и драйверы

По умолчанию Podman использует драйвер **file**, который сохраняет секреты в незашифрованном виде на диске хоста.

- **Путь хранения (Rootful)**: `/var/lib/containers/storage/secrets/`
- **Путь хранения (Rootless)**: `$HOME/.local/share/containers/storage/secrets/`

**Критическое замечание по безопасности**: Хотя секреты защищены внутри контейнера (через tmpfs), на самом хосте они хранятся как обычные файлы. Для обеспечения безопасности "at rest" необходимо использовать шифрование диска (LUKS) или внешние драйверы (например, драйвер `pass`).

### Управление через CLI

| Операция | Команда | Описание |
| :--- | :--- | :--- |
| **Создать** | `podman secret create <имя> <файл>` | Создание из файла или `-` для stdin |
| **Список** | `podman secret ls` | Просмотр всех доступных секретов |
| **Инспекция** | `podman secret inspect <имя>` | Метаданные (дата создания, драйвер) |
| **Удаление** | `podman secret rm <имя>` | Удаление из хранилища хоста |

## Практические сценарии

### 1. Создание секрета и права доступа

При подключении секрета можно явно указать владельца и права доступа внутри контейнера.

```bash
# Создание секрета из строки
echo "my-secure-token" | podman secret create api_token -

# Запуск с настройкой UID, GID и прав (mode)
podman run -d \
  --name app-container \
  --secret api_token,target=/etc/api/token,uid=1000,gid=1000,mode=0400 \
  my-app-image
```

### 2. Использование бинарных секретов

Podman поддерживает передачу бинарных данных (например, SSL-сертификатов или SSH-ключей).

```bash
# Создание секрета из бинарного файла
podman secret create ssl_cert ./server.crt

# Подключение в стандартный путь (/run/secrets/ssl_cert)
podman run --rm --secret ssl_cert alpine ls -l /run/secrets/
```

### 3. Использование в Quadlet (systemd)

Quadlet позволяет декларативно описывать секреты для сервисов.

**Файл:** `~/.config/containers/systemd/db.container`

```ini
[Container]
Image=docker.io/library/postgres:16
Environment=POSTGRES_PASSWORD_FILE=/run/secrets/db_pass
# Подключение секрета
Secret=db_pass
# Подключение с изменением пути
Secret=app_key,target=/app/certs/key.pem
```

## Сравнение механизмов доставки

| Характеристика | Переменные окружения | Монтирование файлов (Bind Mount) | Podman Secrets |
| :--- | :--- | :--- | :--- |
| **Видимость на хосте** | Высокая (`inspect`, `/proc`) | Видны в `mount` | Средняя (скрыты в `inspect`) |
| **Видимость в контейнере** | Доступны всем процессам (`env`) | Постоянные файлы на диске | Файлы в `tmpfs` (память) |
| **След в образе** | Могут попасть в слои | Нет | Нет |
| **Обновление** | Требует перезапуска | Требует перезапуска | Поддерживается динамически |

## Нюансы и ограничения

- **Лимит размера**: Максимальный размер секрета по умолчанию ограничен 512 КБ.
- **Rootless специфика**: В rootless-режиме секреты одного пользователя невидимы для другого, так как хранятся в их домашних директориях.
- **Удаление**: Команда `podman secret rm` не удаляет секрет из уже запущенных контейнеров (он остается смонтированным до остановки).
- **Драйвер Pass**: Вы можете использовать `podman secret create --driver pass ...` для интеграции с менеджером паролей `pass` (требует предварительной настройки GPG).

## Дополнительная информация

### Рекомендации по безопасности

1. **Минимальные права**: Всегда используйте `mode=0400` для секретов, чтобы их мог читать только основной процесс приложения.
2. **Очистка stdin**: При создании секретов из командной строки используйте файлы или пайпы, чтобы пароли не сохранялись в `~/.bash_history`.
3. **Использование суффиксов `_FILE`**: Многие официальные образы (Postgres, MariaDB) поддерживают переменные типа `DATABASE_PASSWORD_FILE`, что идеально сочетается с монтированием секретов в `/run/secrets/`.
