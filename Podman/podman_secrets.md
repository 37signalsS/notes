# Podman: Секреты (Secrets)

## Определения

**Podman Secrets** — это встроенное хранилище конфиденциальных данных (паролей, API-ключей, сертификатов), обеспечивающее их безопасную передачу в контейнеры. В отличие от переменных окружения, секреты не отображаются в логах и выводе `podman inspect`.

**tmpfs mount** — механизм монтирования секретов. По умолчанию секреты монтируются как временные файлы в директорию `/run/secrets/` внутри контейнера. При остановке контейнера данные автоматически исчезают из памяти контейнера.

## Основные концепции

### Команды управления секретами

| Операция | Команда |
| :--- | :--- |
| **Создать** | `echo "my_secret_pass" \| podman secret create <имя> -` |
| **Список** | `podman secret ls` |
| **Инспекция** | `podman secret inspect <имя>` |
| **Удаление** | `podman secret rm <имя>` |

### Особенности работы

- **Безопасность**: Секреты хранятся в зашифрованном виде (при настройке драйвера) или в защищенной директории на хосте.
- **Доступ только для чтения**: Секреты монтируются в контейнер в режиме read-only.
- **Локальная работа**: В Podman секреты доступны без использования кластерных оркестраторов (в отличие от Docker, где требуется Swarm).

## Практические сценарии

### 1. Создание и использование секрета

```bash
# 1. Создаем секрет из строки
echo "super_secret_password" | podman secret create db_password -

# 2. Запускаем контейнер с подключенным секретом
podman run --rm --secret db_password alpine cat /run/secrets/db_password
# → super_secret_password
```

### 2. Использование секретов в приложении (Python)

Приложение должно читать секрет как обычный файл:

```python
import os

def get_secret(secret_name):
    secret_path = f"/run/secrets/{secret_name}"
    if os.path.exists(secret_path):
        with open(secret_path, "r") as f:
            return f.read().strip()
    return None

db_pass = get_secret("db_password")
```

### 3. Индивидуальный путь монтирования

Если приложение ожидает файл в другом месте:

```bash
podman run --secret db_password,target=/etc/db/pass.txt myapp
```

### 4. Использование в Quadlet (Systemd)

В файле `/etc/containers/systemd/*.container`:

```ini
[Container]
Image=nginx
Secret=db_password
Secret=api_key,target=/app/key
```

## Дополнительная информация

### Что хранить в секретах?

| Хранить (Sensitive) | НЕ хранить (Config) |
| :--- | :--- |
| Пароли БД | Номера портов |
| Приватные SSH ключи | IP-адреса сервисов |
| API токены | Режимы работы (Debug=true) |
| SSL сертификаты | Имена контейнеров |

### Сравнение с переменными окружения

| Характеристика | Environment Variables | Podman Secrets |
| :--- | :--- | :--- |
| **Безопасность** | Низкая (видны в `inspect`) | Высокая (не видны) |
| **Видимость в логах** | Может попасть случайно | Защищено |
| **Формат доступа** | Переменная `$VAR` | Файл в `/run/secrets/` |
| **Назначение** | Конфигурация | Секретные данные |

### Очистка секретов

Если секрет больше не нужен, удалите его:

```bash
podman secret rm db_password
```

Это не удалит секрет из уже запущенных контейнеров до их перезапуска, но предотвратит использование в новых.
