# Изоляция процессов в Linux: cgroups и namespaces

Современные контейнеры, включая созданные с помощью Podman, опираются на два ключевых механизма ядра Linux: **namespaces** и **cgroups**. Первый обеспечивает изоляцию *видимости* объектов, второй — *учет и контроль* потребления ресурсов. В сочетании они создают для каждого процесса иллюзию работы в самостоятельной системе.

## Namespaces: изоляция пространства объектов

**Namespace** — это “контекст” ядра, в котором процесс видит ограниченный набор системных ресурсов. Разные типы namespaces отвечают за изоляцию разных подсистем.

**Основные типы и их назначение:**

| Namespace | Что изолируется | Примеры объектов |
| :--- | :--- | :--- |
| `pid` | Дерево процессов | PID, родительские/дочерние связи |
| `mnt` | Таблица монтирования | Точки монтирования, корень FS |
| `net` | Сетевой стек | Интерфейсы, маршруты, iptables |
| `uts` | Узловое имя и домен | hostname, NIS domain |
| `ipc` | Межпроцессное взаимодействие | POSIX/System V очереди, семафоры |
| `user` | Идентичности и права | UID/GID, capabilities |
| `cgroup` | Привязка к иерархии cgroups | Видимость cgroup-дерева |

> Ключевой нюанс **user namespace** позволяет реализовать модель “root внутри, не-root снаружи”: процесс получает административные права (capabilities) внутри своего user-namespace, не имея их в хостовой системе. Это основа rootless-режима в Podman.

**Практические примеры:**

*   **Наблюдение собственных namespaces:**
    ```bash
    ls -l /proc/$$/ns
    ```

*   **Запуск процесса в новых пространствах имен:**
    ```bash
    # Команда unshare создает новые namespaces для процесса
    unshare --uts --pid --net --mount --ipc --fork /bin/bash
    
    # Внутри новой оболочки:
    hostname container  # Имя хоста изменится только внутри этого namespace
    ps -ef              # Вы увидите собственное, изолированное дерево процессов
    ip link             # Будут видны только изолированные сетевые интерфейсы (обычно lo)
    ```

*   **Изоляция пользователей (rootless):**
    ```bash
    unshare -U -r bash
    id  # Внутри этой оболочки вы будете root, но снаружи — останетесь обычным пользователем
    ```

**Важно:** Сами по себе namespaces не являются полноценной границей безопасности. Для надежного снижения привилегий их используют совместно с `capabilities`, `seccomp` и `AppArmor/SELinux`.

## cgroups: распределение и лимитирование ресурсов

**Control Groups (cgroups)** — это иерархический механизм ядра для учета, установки лимитов и приоритизации системных ресурсов (CPU, память, I/O). В современной версии **cgroup v2** используется единая иерархия, что упрощает управление.

**Типичные контроллеры cgroups v2:**

*   `memory`: `memory.max` (жесткий лимит), `memory.high` (мягкий лимит), `memory.current` (текущее потребление).
*   `pids`: `pids.max` (лимит на количество процессов).
*   `cpu`: `cpu.max` (лимит на время CPU), `cpu.weight` (приоритет).
*   `io`: `io.max` (лимиты на операции ввода-вывода).

**Пример ручной настройки cgroup v2:**

```bash
# Требуются привилегии root
cd /sys/fs/cgroup

# Включаем контроллеры pids и memory для дочерних групп
echo "+pids +memory" > cgroup.subtree_control

# Создаем новую группу
mkdir -p demo/sandbox

# Устанавливаем лимиты
echo 50 > demo/sandbox/pids.max       # не более 50 процессов
echo 200M > demo/sandbox/memory.max  # не более 200 МБ памяти

# Помещаем текущий процесс в созданную группу
echo $$ > demo/sandbox/cgroup.procs

# Проверяем текущее потребление
cat demo/sandbox/memory.current
cat demo/sandbox/pids.current
```

## Как Podman использует эти механизмы вместе

При запуске контейнера `podman run` происходит схожий с Docker процесс, но с архитектурными отличиями:

1.  **Создание Namespaces:** Podman создает для контейнера новые пространства имен. Для **rootless-контейнеров** в обязательном порядке используется **user namespace**, что является ключевым отличием и преимуществом в безопасности.
2.  **Применение Cgroups:** Процессы контейнера помещаются в cgroup, управляемую через `systemd` (в современных системах) или напрямую. Лимиты задаются флагами `--memory`, `--cpus`, `--pids-limit`.
3.  **Настройка сети:** В rootful-режиме Podman использует `netavark` для настройки `bridge`-сетей. В rootless-режиме применяется `slirp4netns` или `pasta`, которые создают сетевой стек в пространстве пользователя, не требуя привилегий `root`.
4.  **Снижение привилегий:** Podman по умолчанию работает с минимальным набором `capabilities` и тесно интегрируется с `SELinux`, обеспечивая более строгую изоляцию "из коробки".

Комбинация `namespaces` и `cgroups` позволяет Podman достигать высокого уровня изоляции, особенно в rootless-режиме, который является его основной парадигмой.
