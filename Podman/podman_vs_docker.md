# Podman vs Docker: Ключевые различия

## Определения

**Podman** и **Docker** — инструменты управления контейнерами, поддерживающие стандарты **OCI (Open Container Initiative — открытая инициатива по стандартам контейнеров)**. Это обеспечивает совместимость образов и сред выполнения. Различаются архитектурой, философией безопасности и интеграцией с операционными системами.

**CLI (Command Line Interface — интерфейс командной строки)** — основной способ взаимодействия с обоими инструментами.

**Актуально для:** Podman 5.x, Docker 27.x

## Основные концепции

### Архитектурные различия

| Критерий | Docker | Podman |
| :--- | :--- | :--- |
| **Архитектура** | **Клиент-серверная (`daemon`)**: CLI отправляет команды демону `dockerd`, который управляет контейнерами. | **Без демона (`daemonless`)**: Podman напрямую взаимодействует со средой выполнения. Подробнее: [Daemonless архитектура Podman](./podman_daemonless_architecture.md). |
| **Безопасность** | Изначально ориентирован на root, поддерживает `rootless` режим (требует настройки). | `Rootless-first` дизайн. Контейнеры по умолчанию запускаются от обычного пользователя, используя [user namespaces](../Docker/Concepts/linux_isolation.md#роль-механизмов-ядра-в-контейнеризации). Подробнее: [Rootless режим](./podman_rootless.md). |
| **Среда выполнения** | `containerd` + `runc` | `crun` (быстрее) или `runc`. |
| **Интеграция с ОС** | Ограниченная. Для автозапуска требуются собственные systemd-юниты. | Глубокая. Контейнеры описываются как юниты **Quadlet**. Подробнее: [Daemonless архитектура](./podman_daemonless_architecture.md#интеграция-с-systemd). |
| **Healthcheck** | Выполняется центральным демоном. | Выполняется через **systemd** или `podman healthcheck run`. Подробнее: [Healthchecks в Podman](./podman_healthchecks.md). |
| **Зависимости** | Прямая поддержка `depends_on` в Docker Compose. | Нативная поддержка отсутствует. Заменяется зависимостями **systemd**. Подробнее: [Настройка через Quadlet и зависимости](./podman_healthchecks.md#настройка-через-quadlet-и-зависимости). |
| **Автообновление** | Требует внешних инструментов (Watchtower). | Встроенное через `podman auto-update`. Подробнее: [Автообновление](./podman_auto_update.md). |
| **Группы контейнеров** | `docker-compose`. | **[Podman Compose](./podman-compose.md)** или концепция **Pods** (групп контейнеров). |
| **Интеграция с K8s** | Нет встроенной генерации манифестов. | `podman kube generate` / `podman kube play` для работы с **K8s (Kubernetes)**. |
| **Сеть** | `libnetwork` | `Netavark` (rootful) или `slirp4netns`/`pasta` (rootless). Подробнее: [Изоляция в Podman](./linux_isolation.md). |
| **Философия** | Монолит — один инструмент для всех задач. | **Unix-философия** — набор специализированных утилит. Подробнее: [Альтернативные среды выполнения](../Docker/alternative_runtimes_and_tools.md). |

### Бенчмарки производительности

| Операция | Docker 27.x | Podman 5.x | Победитель |
| :--- | :--- | :--- | :--- |
| **Запуск контейнера** | 150–180 мс | 180–220 мс | Docker (на 15% быстрее) |
| **Pull образа (1 ГБ)** | 1,9 с | 2,1 с | Docker (на 10% быстрее) |
| **RAM (Random Access Memory)** | 140–180 МБ | 0 МБ | Podman (экономия 65%) |
| **100 контейнеров** | 3,2–4,1 ГБ | 2,1–2,6 ГБ | Podman (на 30% меньше RAM) |
| **CPU (Central Processing Unit)** | 0,5–1,2% | 0,1–0,3% | Podman (на 70% меньше) |

**Вывод:** Docker быстрее для отдельных операций, Podman эффективнее для масштабирования и экономии ресурсов.

## Практические сценарии

### 1. Совместимость команд

Для большинства базовых операций достаточно заменить `docker` на `podman`.

```bash
# Запуск контейнера в Podman
podman run -d --name web -p 8080:80 nginx
# → a1b2c3d4e5f6... (ID контейнера)

# Проверка списка запущенных контейнеров
podman ps
# → CONTAINER ID  IMAGE                           COMMAND               CREATED        STATUS            PORTS                 NAMES
# → a1b2c3d4e5f6  docker.io/library/nginx:latest  nginx -g daemon o...  5 seconds ago  Up 5 seconds ago  0.0.0.0:8080->80/tcp  web

# Сборка образа
podman build -t app:1.0 .
# → STEP 1/3: FROM alpine
# → STEP 2/3: RUN echo "hello"
# → STEP 3/3: COMMIT app:1.0
# → app:1.0 (ID образа)
```

### 2. Сценарии выбора

- **Podman** рекомендуется для:
  - Серверов с фокусом на безопасность и интеграцию с `systemd`.
  - Сред, где требуется работа без привилегий root.
  - Разработки и тестирования приложений для Kubernetes.

- **Docker** рекомендуется для:
  - **CI/CD (Continuous Integration / Continuous Deployment — непрерывная интеграция и доставка)**, завязанных на `docker-compose`.
  - Разработки на Windows/macOS с использованием **UX (User Experience — пользовательский опыт)** Docker Desktop.
  - Экосистем с большим количеством плагинов, ориентированных на Docker API.

### 3. Экосистема инструментов (Buildah, Skopeo)

Podman разделяет функционал на отдельные утилиты:

- **Podman**: Управление контейнерами (запуск, остановка).
- **Buildah**: Сборка образов без демона.
- **Skopeo**: Инспекция и копирование образов между реестрами без их скачивания.

## Дополнительная информация

### Матрица выбора

| Сценарий | Рекомендация | Обоснование |
| :--- | :--- | :--- |
| **Безопасность** | Podman | Rootless по умолчанию. Подробнее: [Rootless режим](./podman_rootless.md). |
| **Работа с Kubernetes** | Podman | Нативная поддержка подов. |
| **Экосистема** | Docker | Зрелая экосистема образов. Подробнее: [Обзор Docker](../Docker/docker_overview.md). |
| **Docker Swarm** | Docker | Единственный с поддержкой Swarm. |
| **Desktop UX** | Docker | Docker Desktop предоставляет более зрелый интерфейс. |
| **RHEL (Red Hat Enterprise Linux)** | Podman | Контейнерный движок по умолчанию. |
| **Экономия ресурсов** | Podman | Нет фонового демона. |
