# Podman vs Docker: Ключевые различия

## Definitions

**Podman** и **Docker** — инструменты управления контейнерами, поддерживающие стандарты [Open Container Initiative (OCI)](../Docker/docker_overview.md#open-container-initiative-oci-spec), что обеспечивает совместимость образов и сред выполнения. Различаются архитектурой, философией безопасности и интеграцией с системами.

**Актуально для:** Podman 5.x, Docker 27.x

## Basic Concepts

### Архитектурные различия

| Критерий | Docker | Podman |
| :--- | :--- | :--- |
| **Архитектура** | **Клиент-серверная (`daemon`)**: `docker` CLI отправляет команды демону `dockerd`, который управляет контейнерами. | **Без демона (`daemonless`)**: `podman` напрямую взаимодействует со средой выполнения, запуская контейнеры как дочерние процессы. Подробнее: [Daemonless архитектура Podman](./podman_daemonless_architecture.md). |
| **Безопасность** | Изначально `root-centric`, поддерживает `rootless` режим (требует настройки). Безопасность зависит от защиты демона. | `Rootless-first` дизайн. Контейнеры по умолчанию запускаются от имени обычного пользователя, используя [user namespaces](../Docker/Concepts/linux_isolation.md#1-пространства-имён-namespaces). Работает «из коробки». Подробнее: [Rootless режим](./podman_rootless.md). |
| **Среда выполнения** | `containerd` + `runc` | `crun` (часто по умолчанию, быстрее) или `runc`. |
| **Интеграция с ОС** | Ограниченная. Для автозапуска требуются собственные systemd-юниты. Подробнее: [Docker и systemd](../Docker/docker_systemd.md). | Глубокая. Команда `podman generate systemd` автоматически создаёт unit-файлы. Подробнее: [Daemonless архитектура](./podman_daemonless_architecture.md#интеграция-с-systemd). |
| **Автообновление** | Требует внешних инструментов (Watchtower). | Встроенное через `podman auto-update` + systemd-таймеры. Подробнее: [Автообновление](./podman_auto_update.md). |
| **Группы контейнеров** | `docker-compose` (официальный инструмент). | `podman-compose` (сторонняя утилита) или концепция **Pods** — групп контейнеров с общими ресурсами. |
| **Интеграция с K8s** | Отсутствует встроенная генерация манифестов. | `podman generate kube` / `podman play kube` для прямого взаимодействия с Kubernetes-манифестами. |
| **Сеть** | `libnetwork` | `Netavark` и `Aardvark-dns` (rootful) или `slirp4netns`/`pasta` (rootless). Подробнее: [Изоляция в Podman](./linux_isolation.md). |
| **Философия** | «Monolith» — один инструмент с большим количеством функций. | **Unix-философия** — набор специализированных утилит (Podman, Buildah, Skopeo). Подробнее: [Альтернативные среды выполнения](../Docker/alternative_runtimes_and_tools.md). |

### Бенчмарки производительности

| Операция | Docker 27.x | Podman 5.x | Победитель |
| :--- | :--- | :--- | :--- |
| **Запуск контейнера** | 150–180 мс | 180–220 мс | Docker (на 15% быстрее) |
| **Pull образа (1 ГБ)** | 1,9 с | 2,1 с | Docker (на 10% быстрее) |
| **Использование памяти (idle)** | 140–180 МБ | 0 МБ | Podman (экономия 65%) |
| **100 контейнеров** | 3,2–4,1 ГБ | 2,1–2,6 ГБ | Podman (на 30% меньше) |
| **CPU (idle)** | 0,5–1,2% | 0,1–0,3% | Podman (на 70% меньше) |

> **Вывод:** Docker быстрее для отдельных операций, Podman эффективнее для масштабирования и экономии ресурсов.

## Practical Scenarios

### 1. Совместимость команд (CLI)

Для большинства базовых операций достаточно заменить `docker` на `podman`. Многие пользователи создают псевдоним `alias docker=podman` для полной прозрачности.

```bash
# Запуск контейнера
docker run -d --name web -p 8080:80 nginx
podman run -d --name web -p 8080:80 nginx

# Сборка образа
docker build -t app:1.0 .
podman build -t app:1.0 .

# Работа с реестром
docker login registry.example.com
podman login registry.example.com
```

### 2. Сценарии выбора

- **Podman** — идеальный выбор для:
  - Linux-серверов с фокусом на безопасность и интеграцию с `systemd`.
  - Многопользовательских сред, где изоляция пользователей критична (`rootless`).
  - Разработки и тестирования Kubernetes-приложений (`podman play kube`).

- **Docker** — остается сильным выбором для:
  - Устоявшихся CI/CD пайплайнов, сильно завязанных на `docker-compose`.
  - Кросс-платформенной разработки (Windows/macOS), где `Docker Desktop` предоставляет более зрелый UX.
  - Экосистем с большим количеством плагинов и инструментов, ориентированных на Docker API.

### 3. Rootless-режим

Podman поддерживает rootless-режим «из коробки» благодаря daemonless-архитектуре, тогда как Docker требует дополнительной настройки. Подробности механизмов, ограничений и практических сценариев: [Rootless режим в Podman](./podman_rootless.md).

### 4. Экосистема инструментов (Buildah, Skopeo)

В отличие от Docker (монолит), Podman следует Unix-философии, разделяя функционал на отдельные утилиты:

- **Podman**: Управление контейнерами (запуск, остановка, удаление).
- **Buildah**: Сборка образов. Позволяет создавать образы без демона, с использованием стандартных инструментов Linux. Подробнее: [Альтернативные среды выполнения](../Docker/alternative_runtimes_and_tools.md).
- **Skopeo**: Управление реестрами. Копирование, синхронизация и инспекция образов без загрузки их на локальную машину. Подробнее: [Альтернативные среды выполнения](../Docker/alternative_runtimes_and_tools.md).

> При установке модуля `container-tools` в RHEL-подобных системах все эти инструменты устанавливаются вместе.

## Additional Information

### Когда выбирать

| Сценарий | Рекомендация | Обоснование |
| :--- | :--- | :--- |
| **Безопасность production** | Podman | Rootless по умолчанию, нет привилегированного демона. Подробнее: [Rootless режим](./podman_rootless.md). |
| **Kubernetes workflow** | Podman | Нативная поддержка подов и `podman play kube`. |
| **Экосистема и интеграции** | Docker | Зрелая экосистема, больше готовых образов. Подробнее: [Обзор Docker](../Docker/docker_overview.md). |
| **Docker Swarm** | Docker | Единственный с поддержкой Swarm. |
| **Разработка (Windows/macOS)** | Docker | Docker Desktop с лучшим UX. |
| **RHEL/OpenShift** | Podman | Контейнер по умолчанию в RHEL 8+. |
| **CI/CD с docker-compose** | Docker | Устоявшиеся пайплайны. |
| **Edge устройства** | Podman | Экономия ресурсов (на 65% меньше памяти). |
