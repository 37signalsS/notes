# Мониторинг и логирование в Docker: Обзор

Этот документ представляет собой высокоуровневый обзор основных концепций и инструментов для мониторинга и централизованного логирования Docker-контейнеров и приложений в них. Для более подробной информации по конкретным темам смотрите соответствующие документы.

## 1. Зачем нужны мониторинг и логирование в Docker?

Среда Docker, особенно в кластерных конфигурациях (Docker Swarm, Kubernetes), является динамичной и распределенной. Традиционные методы мониторинга и сбора логов часто оказываются неэффективными. Мониторинг и логирование критически важны для:

*   **Обеспечения стабильности и производительности:** Выявление "узких мест", деградации производительности, утечек ресурсов.
*   **Быстрого реагирования на инциденты:** Обнаружение ошибок, сбоев и аномалий в реальном времени.
*   **Отладки и анализа первопричин:** Использование логов для понимания происходящего внутри контейнеров.
*   **Оптимизации ресурсов:** Анализ потребления ресурсов для более эффективного планирования.

## 2. Лучшие практики логирования в Docker

Основная рекомендация — **всегда направлять логи приложений в `STDOUT` и `STDERR`**. Docker оптимизирован для сбора данных из этих стандартных потоков. Избегайте записи логов в файлы внутри контейнера, так как это усложняет их сбор и ротацию.

*   **Подробнее о логировании и командах:** [Основы: docker logs](./docker_logs_and_metrics.md#основы-docker-logs)

## 3. Драйверы логирования Docker

Docker предоставляет различные драйверы для обработки логов. Выбор драйвера зависит от ваших требований к хранению, обработке и централизации логов.

*   **Локальные драйверы:**
    *   **`json-file` (по умолчанию):** Хранит логи в JSON-файлах на хост-машине. Удобен для разработки, но не рекомендуется для production без правильной ротации.
    *   **`local`:** Хранит логи в компактном кастомном формате, минимизирующем накладные расходы.
*   **Драйверы для централизованного сбора:**
    *   **`journald`:** Интегрируется с `systemd-journald` для сбора логов в Journal.
    *   **`syslog`:** Отправляет логи на Syslog-сервер.
    *   **`gelf`:** Отправляет структурированные логи на GELF-совместимый сервер (Graylog, Logstash).
    *   **`fluentd`:** Отправляет логи на сервер-агрегатор Fluentd.

*   **Подробнее о работе драйверов и их настройке:** [Как работает логирование](./docker_logs_and_metrics.md#как-работает-логирование)
*   **Централизованное логирование:** [Централизованное логирование в Production](./docker_logs_and_metrics.md#централизованное-логирование-в-production)

## 4. Ротация логов Docker

Для локально хранимых логов (например, с драйверами `json-file` или `local`) критически важна настройка ротации, чтобы избежать переполнения диска. Утилита `logrotate` с опцией `copytruncate` является стандартным решением.

*   **Подробнее о ротации логов:** [Ротация логов Docker (Logrotate)](./docker_logs_and_metrics.md#ротация-логов-docker-logrotate)

## 5. Мониторинг ресурсов Docker

Docker предоставляет встроенные инструменты для базового мониторинга ресурсов, но для полноценной картины требуются специализированные решения.

*   **`docker stats` и `docker system df`:** Команды для быстрой диагностики потребления ресурсов контейнерами и дискового пространства Docker.
*   **cAdvisor:** Стандартный инструмент от Google для сбора детальных метрик производительности каждого контейнера (CPU, память, сеть, диск) и экспорта их в формате Prometheus.
*   **Prometheus:** Система мониторинга, которая собирает метрики от Docker Engine, cAdvisor и непосредственно от приложений.
*   **Grafana:** Используется для визуализации собранных метрик, создания дашбордов и алертов.

*   **Подробнее о сборе метрик:** [Сбор метрик для Prometheus](./docker_logs_and_metrics.md#сбор-метрик-для-prometheus)
*   **Обзор Prometheus:** [Prometheus/overview.md](../../Prometheus/overview.md)
*   **Обзор Grafana:** [Grafana/grafana_overview.md](../../Grafana/grafana_overview.md)
