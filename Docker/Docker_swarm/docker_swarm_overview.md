# Docker Swarm Mode

Docker Swarm Mode предоставляет нативную функциональность для создания и управления кластером Docker-движков. Он превращает группу Docker-хостов в единый виртуальный Docker-движок, позволяя развертывать приложения как сервисы, состоящие из множества контейнеров, распределенных по всему кластеру.

**Важно:** Не следует путать **Docker Swarm Mode** с устаревшим проектом **Docker Classic Swarm**, который больше не активно разрабатывается. Docker Swarm Mode является встроенной частью Docker Engine. Он часто рассматривается как "золотая середина" между простым запуском контейнеров на одном хосте и сложной оркестрацией Kubernetes, предлагая баланс между функциональностью и простотой использования.

*   **Простота использования:** Интегрирован в Docker CLI, что упрощает освоение.
*   **Встроенное обнаружение сервисов:** Автоматическое назначение DNS для сервисов и внутреннее балансирование нагрузки.
*   **Высокая доступность:** Автоматическое восстановление сервисов при сбое узла и перезапуск сбойных задач на здоровых узлах.
*   **Масштабируемость:** Легкое горизонтальное масштабирование сервисов.
*   **Декларативное управление:** Описание желаемого состояния приложения.
*   **Встроенная безопасность:** Автоматическая TLS-шифрование между узлами и интегрированное управление секретами и конфигурациями.
*   **Гибкое развертывание:** Поддержка скользящих обновлений и откатов, а также планирование контейнеров на основе доступности ресурсов (CPU, память) и заданных ограничений (constraints).

## Docker Swarm vs. Docker Compose

Часто возникает путаница между `docker compose` и `docker swarm`. Важно понимать их фундаментальное различие:

*   **Docker Compose:** Это инструмент для определения и запуска **многоконтейнерных приложений на одном хосте**. Он идеален для локальной разработки и простых одноузловых развертываний.
*   **Docker Swarm:** Это инструмент для **оркестрации контейнеров в кластере из нескольких хостов**. Он берет на себя задачи распределения контейнеров (сервисов) по разным машинам, обеспечивает отказоустойчивость и масштабирование.

> **Простое правило:** Если у вас один сервер — используйте `docker compose`. Если у вас несколько серверов, которые нужно объединить в кластер, — используйте `docker swarm`. При этом Swarm может использовать синтаксис `docker-compose.yml` для развертывания приложений с помощью команды `docker stack deploy`.
