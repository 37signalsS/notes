# Сеть в Docker Swarm

Docker Swarm использует **оверлейные сети (overlay networks)** для обеспечения связи между контейнерами, запущенными на разных узлах Swarm. В основе этой технологии часто лежит инкапсуляция трафика с помощью **VXLAN**, что позволяет создавать виртуальную Layer 2 сеть поверх существующей Layer 3 инфраструктуры.

*   **Простота:** Автоматически создаются и управляются Swarm.
*   **Изоляция:** Сетевой трафик между сервисами изолирован.
*   **Балансировка нагрузки:** Встроенная DNS-балансировка нагрузки для сервисов.

### Создание оверлейной сети

```sh
docker network create --driver overlay --attachable --opt encrypted my-overlay-network
```
*   Флаг `--attachable` позволяет автономным контейнерам (не Swarm-сервисам) подключаться к этой сети.
*   Опция `--opt encrypted` включает IPsec-шифрование трафика, но может повлиять на производительность.

### Системные сети в Swarm: ingress и docker_gwbridge

Помимо пользовательских overlay-сетей, в Swarm-кластере по умолчанию создаются две важные системные сети:

*   **`ingress`:** Используется для маршрутизации входящего трафика к сервисам Swarm. Когда вы публикуете порт сервиса (например, `-p 8080:80`), Swarm Routing Mesh направляет трафик с порта `8080` *любого* из хостов кластера на нужный контейнер, даже если он работает на другой машине. Балансировка нагрузки выполняется с помощью IPVS. Эта сеть не является `attachable` по умолчанию.
*   **`docker_gwbridge`:** Служит шлюзом для исходящего трафика из контейнеров Swarm-сервисов во внешний мир (например, когда контейнер обращается к внешнему API или базе данных в интернете).

### Использование сети в сервисе

```sh
docker service create --name my-service --network my-overlay-network --replicas 3 my-image
```
