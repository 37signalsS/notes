# Интеграция Docker с Prometheus

## Определения

**Интеграция Docker с Prometheus** — процесс настройки экспорта метрик Docker Engine и запущенных контейнеров в формате, совместимом с Prometheus. Это позволяет централизованно собирать, хранить и анализировать данные о состоянии инфраструктуры, производительности демона Docker и работе приложений.

## Основные концепции

Эффективный мониторинг контейнеризированной среды требует сбора данных на трех независимых уровнях:

1.  **Уровень Docker Engine:** Статистика самого демона (количество контейнеров, образов, ошибки сборки, состояние пула памяти). Сбор выполняется через встроенный экспортер.
2.  **Уровень инфраструктуры контейнеров:** Детальные метрики потребления ресурсов (CPU, RAM, Network, I/O) каждым отдельным контейнером. Сбор выполняется через **[cAdvisor](../../Prometheus/Exporters/cadvisor.md)**.
3.  **Уровень приложения:** Внутренние показатели бизнес-логики (количество запросов, время ответа, ошибки). Сбор выполняется путем инструментирования кода приложения.

Для полной видимости системы эти уровни дополняются **[Node Exporter](../../Prometheus/Exporters/node_exporter.md)** для мониторинга ресурсов хост-машины.

## Практические сценарии

### 1. Настройка встроенного экспортера Docker Engine

Docker Engine имеет встроенный эндпоинт метрик в формате Prometheus (по умолчанию порт `9323`).

**Настройка (`/etc/docker/daemon.json`):**
Для активации необходимо отредактировать файл конфигурации:

```json
{
  "metrics-addr": "0.0.0.0:9323",
  "experimental": true
}
```

*   `metrics-addr` — адрес и порт, на которых будут доступны метрики.
*   `experimental: true` — требуется для активации некоторых продвинутых метрик (например, статистики сборщика образов).

**Перезапуск службы:**
```bash
sudo systemctl restart docker
```

**Проверка:**
```bash
curl -s http://localhost:9323/metrics | grep docker_engine_cpus
# → docker_engine_cpus_total 8
```

### 2. Конфигурация Prometheus для сбора данных

Для того чтобы Prometheus начал собирать метрики, их необходимо добавить в раздел `scrape_configs` файла `prometheus.yml`.

```yaml
scrape_configs:
  - job_name: 'docker-engine'
    static_configs:
      - targets: ['192.168.1.10:9323'] # IP хоста с Docker
```

### 3. Мониторинг в режиме Docker Swarm

В режиме Swarm встроенный экспортер также доступен на каждом узле. Для сбора метрик со всего кластера рекомендуется использовать механизмы Service Discovery Prometheus.

*   Метрики Swarm-менеджера содержат данные о состоянии сервисов, задач и узлов кластера.
*   Для мониторинга Swarm обычно требуется запуск Prometheus в виде `global` сервиса или использование `dns_sd_configs` для обнаружения узлов.

### 4. Сбор метрик контейнеров (cAdvisor)

Встроенный экспортер Docker Engine предоставляет лишь общую статистику. Для глубокого анализа потребления ресурсов каждым контейнером **обязательно** использование cAdvisor.

**Запуск через Docker:**
```bash
docker run \
  --volume=/:/rootfs:ro \
  --volume=/var/run:/var/run:ro \
  --volume=/sys:/sys:ro \
  --volume=/var/lib/docker/:/var/lib/docker:ro \
  --publish=8080:8080 \
  --detach=true \
  --name=cadvisor \
  google/cadvisor:latest
```

## Безопасность

*   **Ограничение доступа:** Не оставляйте порт `9323` открытым для всей сети. Используйте `127.0.0.1:9323`, если Prometheus запущен на том же хосте, или настройте Firewall (iptables/ufw).
*   **Специфические метрики:** Некоторые метрики могут содержать чувствительную информацию (имена образов, названия контейнеров).
*   **Ресурсы:** Сбор метрик (особенно через cAdvisor) создает небольшую нагрузку на CPU и память. На высоконагруженных системах следует увеличить интервал скрейпинга (`scrape_interval`).
