## Определения

**Интеграция Docker с Prometheus** — это процесс настройки окружения Docker для экспорта метрик производительности и состояния в формате, совместимом с [Prometheus](../..//Prometheus/overview.md). Это позволяет централизованно собирать, хранить и анализировать данные о работе демона Docker, отдельных контейнеров и запущенных в них приложений.

## Основные концепции

Для полноценного мониторинга Docker-хоста с помощью Prometheus необходимо собирать метрики с трех уровней:

1. **Метрики Docker Engine**: Статистика о работе самого демона Docker (например, количество запущенных контейнеров, используемых образов, ошибки сборки).
2. **Метрики контейнеров**: Детальные данные о потреблении ресурсов (CPU, память, сеть, I/O) каждым отдельным контейнером.
3. **Метрики приложений**: Внутренние показатели работы сервисов, запущенных в контейнерах (например, количество обработанных запросов, время ответа API, число активных пользователей).

Каждый из этих уровней требует своего инструмента для сбора метрик.

## Практические сценарии

### 1. Сбор метрик Docker Engine

Современные версии Docker Engine могут нативно экспортировать метрики в формате Prometheus.

- **Назначение**: Мониторинг состояния и производительности самого демона Docker.
- **Настройка**: Необходимо добавить параметр `metrics-addr` в конфигурационный файл Docker `/etc/docker/daemon.json` и перезапустить сервис.

    ```json
    {
      "metrics-addr": "0.0.0.0:9323",
      "experimental": true
    }
    ```

    После этого метрики будут доступны по адресу `http://<host-ip>:9323/metrics`.

### 2. Сбор метрик контейнеров с помощью cAdvisor

Для сбора детальных метрик производительности *каждого* контейнера используется **[cAdvisor (Container Advisor)](https://github.com/google/cadvisor)** от Google, ставший стандартом де-факто.

- **Назначение**: Собирает, агрегирует и отдает в формате Prometheus детальную информацию о потреблении CPU, памяти, сети и диска для всех контейнеров на хосте.
- **Запуск**: cAdvisor наиболее удобно запускать как еще один Docker-контейнер.

    ```yaml
    # Пример запуска cAdvisor в docker-compose.yml
    services:
      cadvisor:
        image: gcr.io/cadvisor/cadvisor:v0.53.0
        container_name: cadvisor
        ports:
          - "8080:8080"
        volumes:
          - /:/rootfs:ro
          - /var/run:/var/run:rw
          - /sys:/sys:ro
          - /var/lib/docker/:/var/lib/docker:ro
        restart: unless-stopped
    ```

    Метрики всех контейнеров на хосте будут доступны по адресу `http://<host-ip>:8080/metrics`.

### 3. Сбор метрик приложений

Этот уровень требует инструментирования кода вашего приложения с помощью клиентских библиотек Prometheus.

- **Принцип работы**: Приложение само отдает специфичные для него метрики (бизнес-логика, производительность) по HTTP-эндпоинту `/metrics`.
- **Настройка**: Убедитесь, что порт, на котором приложение отдает метрики, доступен для скрейпера Prometheus.

## Дополнительная информация

### Связка с Node Exporter

Для получения полной картины мониторинга хоста, `cAdvisor` (метрики контейнеров) обычно используется в связке с **`node-exporter`** (метрики хост-системы). `node-exporter` собирает данные о потреблении ресурсов самой операционной системой (загрузка CPU, использование диска, состояние сети), которые не относятся напрямую к контейнерам.

Иногда стандартного набора метрик от `cAdvisor` бывает недостаточно. В таких случаях можно использовать дополнительные инструменты, например, [draganm/missing-container-metrics](https://github.com/draganm/missing-container-metrics), для экспорта специфичных или недостающих данных.
