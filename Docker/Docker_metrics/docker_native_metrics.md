# Нативные метрики Docker

## Определения

**Нативные метрики Docker** — встроенные средства для оценки потребления ресурсов контейнерами. Они предоставляют базовую статистику без необходимости установки внешних инструментов мониторинга и подходят для оперативной диагностики.

## Основные концепции

### Источник данных: cgroups

Ключевой источник данных — механизм ядра Linux **[контрольные группы (cgroups)](../../Linux/Core/cgroups.md)**. Docker использует cgroups для изоляции, ограничения ресурсов и сбора статистики потребления.

Сырые метрики доступны в псевдофайловой системе `cgroupfs`:

- **Память:** `/sys/fs/cgroup/memory/docker/<container_long_id>/memory.stat`
- **CPU (Центральный процессор):** `/sys/fs/cgroup/cpu/docker/<container_long_id>/cpuacct.stat`
- **I/O (Ввод-вывод):** `/sys/fs/cgroup/blkio/docker/<container_long_id>/blkio.throttle.io_service_bytes`

Эти файлы читает демон Docker (Docker daemon) для формирования вывода команды `docker stats`.

## Практические сценарии

### Динамическая статистика: docker stats

Команда `docker stats` предоставляет обновляемый в реальном времени обзор производительности всех запущенных контейнеров.

**Основные команды:**

```bash
# Статистика по CPU, памяти, сети и I/O для всех контейнеров
docker stats

# Статистика для указанного контейнера
docker stats <id_контейнера>

# Однократный снимок статистики без потокового обновления
docker stats --no-stream
```

**Вывод `docker stats` содержит следующие столбцы:**

- `CONTAINER ID`, `NAME` — идентификатор и имя контейнера
- `CPU %` — процент использования CPU хоста
- `MEM USAGE / LIMIT` — использованная память и общий лимит
- `MEM %` — процент использования памяти
- `NET I/O` — объем данных, полученных и отправленных по сети
- `BLOCK I/O` — объем данных, прочитанных и записанных на диск
- `PIDS` (Process IDs) — количество процессов внутри контейнера

### Анализ использования диска: docker system df

Команда `docker system df` позволяет оценить объем дискового пространства, занятого объектами Docker.

```bash
docker system df
# → TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
# → Images          10        5         1.5GB     1.2GB (79%)
# → Containers      8         3         500MB     450MB (90%)
# → Local Volumes   4         2         300MB     150MB (50%)
# → Build Cache     0         0         0B        0B
```

`RECLAIMABLE` — объем, который можно освободить путем удаления неиспользуемых объектов (остановленные контейнеры, "висячие" образы).
