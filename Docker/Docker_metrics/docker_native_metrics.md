## Определения

**Нативные метрики Docker** — это встроенные средства для быстрой оценки потребления ресурсов контейнерами и самим Docker. Они предоставляют базовую статистику без необходимости установки внешних инструментов мониторинга и идеально подходят для оперативной диагностики.

## Основные концепции

### Источник данных: cgroups

Ключевым источником данных для нативных метрик является механизм ядра Linux — **[контрольные группы (cgroups)](../../Linux/Core/cgroups.md)**. Docker использует `cgroups` не только для изоляции и ограничения ресурсов контейнеров, но и для сбора статистики по их потреблению.

Сырые метрики производительности можно найти напрямую в псевдофайловой системе `cgroupfs`. Пути к ним обычно выглядят так:

- **Память:** `/sys/fs/cgroup/memory/docker/<container_long_id>/memory.stat`
- **CPU:** `/sys/fs/cgroup/cpu/docker/<container_long_id>/cpuacct.stat`
- **I/O:** `/sys/fs/cgroup/blkio/docker/<container_long_id>/blkio.throttle.io_service_bytes`

Именно эти файлы читает Docker daemon для формирования вывода команды `docker stats`.

## Практические сценарии

### Динамическая статистика: `docker stats`

Команда `docker stats` предоставляет динамический, обновляемый в реальном времени обзор производительности всех запущенных контейнеров.

| Команда | Описание |
| :--- | :--- |
| `docker stats` | Показать динамическую статистику по CPU, памяти, сети и I/O для всех контейнеров. |
| `docker stats <id_контейнера>` | Показать статистику только для указанного контейнера. |
| `docker stats --no-stream` | Показать однократный снимок статистики и выйти. |

**Описание вывода `docker stats`:**

- **`CONTAINER ID` & `NAME`**: Идентификатор и имя контейнера.
- **`CPU %`**: Процент использования CPU хоста.
- **`MEM USAGE / LIMIT`**: Количество использованной оперативной памяти и общий лимит.
- **`MEM %`**: Процент использования памяти.
- **`NET I/O`**: Объем данных, полученных и отправленных по сети.
- **`BLOCK I/O`**: Объем данных, прочитанных с диска и записанных на диск.
- **`PIDS`**: Количество процессов, запущенных внутри контейнера.

### Анализ использования диска: `docker system df`

```bash
# Вывод команды покажет размер, занимаемый образами, контейнерами и томами
docker system df
```

Примерный вывод:

```
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          10        5         1.5GB     1.2GB (79%)
Containers      8         3         500MB     450MB (90%)
Local Volumes   4         2         300MB     150MB (50%)
Build Cache     0         0         0B        0B
```

- `RECLAIMABLE` — показывает, какой объем можно освободить, удалив неиспользуемые объекты (например, остановленные контейнеры или "висячие" образы).

## Дополнительная информация

Хотя `docker stats` и `docker system df` полезны для быстрой диагностики, для полноценного производственного мониторинга рекомендуется использовать более мощные решения. Они позволяют собирать, агрегировать и анализировать метрики в долгосрочной перспективе, а также настраивать оповещения.

- **Интеграция с Prometheus**: Docker может предоставлять метрики в формате Prometheus для их сбора и анализа. Подробнее см. в разделе **[Интеграция Docker с Prometheus](./docker_prometheus_integration.md)**.
- **Специализированные агенты**: Инструменты, такие как **[cAdvisor](../../Prometheus/Exporters/cadvisor.md)**, **[Vector](../../Vector/Concepts/vector_overview.md)** или **[Filebeat](../../ELK_Stack/filebeat_overview.md)**, собирают метрики напрямую из `cgroups` или логов и отправляют их в системы мониторинга (Prometheus, ClickHouse, Elasticsearch).
