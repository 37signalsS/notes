# Управление часовым поясом в контейнерах

## Определения

**UTC (Coordinated Universal Time)** — всемирное координированное время, стандарт, по которому общество регулирует часы и время. По умолчанию почти все базовые образы контейнеров (Alpine, Debian, Ubuntu, CentOS) используют UTC.

**tzdata (Time Zone Database)** — база данных часовых поясов, содержащая информацию о смещениях времени и правилах перехода на летнее/зимнее время для различных регионов.

**Переменная окружения `TZ`** — стандартный механизм POSIX для указания часового пояса приложению без изменения системных файлов.

## Базовые концепции

### Разделение времени: Ядро vs Пользовательское пространство

В контейнерной среде важно понимать, как ОС обрабатывает время:

1.  **Системное время (Ядро):** Ядро Linux всегда работает в формате Unix Timestamp (количество секунд с 1 января 1970 года UTC). Все контейнеры на одном хосте используют **одно и то же ядро**, поэтому системное время у них идентично. Контейнер не может изменить системное время без привилегий `CAP_SYS_TIME`.
2.  **Отображаемое время (Пользовательское пространство):** То, как приложение отображает время, зависит от настроек библиотек (glibc, musl) внутри контейнера. Именно эти настройки мы изменяем для "смены часового пояса".

### Механизмы определения пояса

Приложения и библиотеки ищут настройки в следующем порядке:

-   **Переменная `TZ`:** Если задана (например, `TZ=Europe/Moscow`), библиотеки используют её для расчета смещения. Это самый быстрый и надежный способ.
-   **Файл `/etc/localtime`:** Если `TZ` не задана, библиотеки читают этот файл (обычно это символическая ссылка на файл из `/usr/share/zoneinfo/`).

### Особенности базовых образов

-   **Alpine Linux:** Использует библиотеку `musl`. Пакет `tzdata` не установлен по умолчанию для минимизации размера.
-   **Debian/Ubuntu:** Используют `glibc`. Пакет `tzdata` обычно установлен, но может быть удален в "slim" версиях.
-   **Distroless/UBI:** Могут не иметь установленной базы `tzdata`, что требует её добавления на этапе сборки.

## Практические сценарии

### 1. Использование переменной окружения `TZ` (Рекомендуемый способ)

Это наиболее чистый метод, не требующий монтирования файлов хоста.

#### Docker CLI
```bash
docker run -d --name my-app -e TZ=Europe/Moscow nginx
```

#### Docker Compose
```yaml
services:
  web:
    image: nginx
    environment:
      TZ: Europe/Moscow
```

#### Kubernetes
```yaml
spec:
  containers:
  - name: app
    image: nginx
    env:
    - name: TZ
      value: "Europe/Moscow"
```

### 2. Монтирование файлов часового пояса с хоста

Используется для автоматического наследования настроек хоста.

```bash
docker run -d \
  -v /etc/localtime:/etc/localtime:ro \
  -v /etc/timezone:/etc/timezone:ro \
  nginx
```

**Важные нюансы:**
-   **Проблема символических ссылок:** Если на хосте `/etc/localtime` — это симлинк (например, на `../usr/share/zoneinfo/Europe/Moscow`), то при монтировании как файла внутри контейнера ссылка может оказаться битой, если в контейнере нет базы `/usr/share/zoneinfo`.
-   **Решение:** Монтировать всю директорию `/usr/share/zoneinfo` (избыточно) или использовать `TZ`.

### 3. Настройка в Dockerfile (Неизменяемый подход)

Позволяет зафиксировать часовой пояс внутри образа.

#### Для Alpine Linux
```dockerfile
FROM alpine:latest
RUN apk add --no-cache tzdata
ENV TZ=Europe/Moscow
```

#### Для Debian/Ubuntu
```dockerfile
FROM ubuntu:latest
RUN apt-get update && \
    apt-get install -y tzdata && \
    ln -snf /usr/share/zoneinfo/Europe/Moscow /etc/localtime && \
    echo "Europe/Moscow" > /etc/timezone && \
    rm -rf /var/lib/apt/lists/*
ENV TZ=Europe/Moscow
```

### 4. Специфические настройки приложений

Некоторые технологии требуют дополнительной настройки, так как могут игнорировать системные переменные.

| Технология | Настройка |
| :--- | :--- |
| **Java (JVM)** | Добавить `-Duser.timezone=Europe/Moscow` в параметры запуска. |
| **Python** | Использовать библиотеки `pytz` или встроенный `zoneinfo` (Python 3.9+). |
| **PostgreSQL** | Настроить параметр `timezone` в `postgresql.conf` или через переменную `PGTZ`. |
| **Cron** | Демон `cron` считывает `TZ` при запуске. Если пояс изменен на лету, демон нужно перезапустить. |
| **PHP** | Задать `date.timezone` в `php.ini` или через переменную окружения. |

### 5. Проверка времени в контейнере

Чтобы убедиться, что настройки применились корректно, выполните:

```bash
# Проверка текущего времени и пояса
docker exec <container_id> date

# Проверка значения переменной TZ
docker exec <container_id> printenv TZ

# Проверка содержимого /etc/localtime (для образов с glibc)
docker exec <container_id> zdump /etc/localtime
```

## Дополнительная информация

### Рекомендации (Best Practices)

1.  **Приоритет UTC:** В распределенных системах и микросервисах всегда используйте UTC. Локализацию времени выполняйте на уровне интерфейса (Frontend) или при анализе логов.
2.  **Использование TZ:** Предпочитайте переменную `TZ` монтированию `/etc/localtime`.
3.  **Очистка образов:** Если вы устанавливаете `tzdata` в Dockerfile, убеждайтесь, что удаляете кэш пакетного менеджера для уменьшения размера образа.
