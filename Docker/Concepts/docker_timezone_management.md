# Управление часовым поясом в контейнерах

## Определения

**UTC (Coordinated Universal Time)** — всемирное координированное время. По умолчанию большинство контейнерных образов (Alpine, Debian, Ubuntu) настроены на использование UTC.

**Проблема расхождения времени:** если хост-система работает в локальном часовом поясе (например, `Europe/Moscow`), а контейнеры в UTC, возникает путаница при анализе логов, выполнении заданий по расписанию (`cron`) и обработке временных меток в приложении.

**Цель:** обеспечить предсказуемую работу приложений с временем, выбрав между стандартизацией на UTC или локализацией под конкретный регион.

## Базовые концепции

### Принципы работы времени в Linux

В Linux разделяют системное время (ядро) и время пользователя (приложения):
1. **Ядро:** всегда отсчитывает время в формате Unix Timestamp (количество секунд с 01.01.1970 UTC).
2. **Библиотеки (glibc, musl):** преобразуют системное время в человекочитаемый формат, используя:
   - Переменную окружения **`TZ`** (имеет наивысший приоритет).
   - Файл **`/etc/localtime`** (обычно символическая ссылка на файл из `/usr/share/zoneinfo/`).

### Стратегии управления

| Стратегия | Описание | Когда использовать |
| :--- | :--- | :--- |
| **Standard UTC** | Все контейнеры работают в UTC. Логи агрегируются и конвертируются в локальное время на уровне UI (Grafana, Kibana). | **Рекомендуемый стандарт** для Cloud Native систем. |
| **Localization** | В контейнер передается конкретный часовой пояс через `TZ` или файлы конфигурации. | Когда логи читаются вручную (`docker logs`) или приложение жестко привязано к локальному времени. |

## Практические сценарии

### 1. Использование переменной окружения `TZ`

Самый чистый и переносимый способ. Требует наличия пакета `tzdata` в образе.

#### Docker CLI
```bash
docker run -d --name app -e TZ=Europe/Moscow nginx
```

#### Docker Compose
```yaml
services:
  web:
    image: nginx
    environment:
      - TZ=Europe/Moscow
```

#### Kubernetes
```yaml
spec:
  containers:
  - name: app
    image: nginx
    env:
    - name: TZ
      value: "Europe/Moscow"
```

### 2. Монтирование часового пояса с хоста

Позволяет контейнеру автоматически наследовать настройки времени хост-системы.

```bash
docker run -d \
  -v /etc/localtime:/etc/localtime:ro \
  -v /etc/timezone:/etc/timezone:ro \
  nginx
```
*   **Плюс:** полная синхронизация с хостом без изменения переменных.
*   **Минус:** нарушает портативность (на другом хосте может быть другой пояс); требует наличия файлов на хосте.

### 3. Подготовка Dockerfile

Если базовый образ (например, Alpine) не содержит базу часовых поясов, её нужно установить.

#### Alpine Linux
```dockerfile
FROM alpine:latest
RUN apk add --no-cache tzdata
ENV TZ=Europe/Moscow
```

#### Debian / Ubuntu
```dockerfile
FROM ubuntu:latest
RUN apt-get update && apt-get install -y tzdata && rm -rf /var/lib/apt/lists/*
ENV TZ=Europe/Moscow
```

### 4. Особенности конкретных технологий

| Технология | Особенность | Решение |
| :--- | :--- | :--- |
| **Java (JVM)** | Часто игнорирует системный `/etc/localtime`. | Передать `-Duser.timezone=Europe/Moscow` в `JAVA_OPTS`. |
| **PostgreSQL** | Использует собственный параметр `timezone`. | Настроить `PGTZ=Europe/Moscow` или `SET timezone = 'Europe/Moscow';`. |
| **Nginx** | Для использования `TZ` в логах требует проброса переменной. | Добавить `env TZ;` в начало `nginx.conf`. |
| **PHP** | Имеет собственную настройку в `php.ini`. | Задать `date.timezone = Europe/Moscow`. |
