# Docker Registry: Хранение и распространение образов

## Определения

*   **Docker Registry (Реестр)**: Сервис для хранения и распространения Docker-образов. Это централизованное хранилище, откуда можно скачивать (pull) и куда можно загружать (push) образы. Docker Hub — самый известный публичный реестр.
*   **Репозиторий (Repository)**: Коллекция образов с одинаковым названием, но разными тегами (например, `ubuntu`). Репозиторий находится внутри реестра.
*   **Тег (Tag)**: Метка, идентифицирующая конкретный образ внутри репозитория (например, `18.04`, `latest`). Полное имя образа имеет формат: `<домен_реестра>/<проект_или_пользователь>/<имя_репозитория>:<тег>`.
*   **Частный (Private) реестр**: Реестр, развернутый в изолированной сети (on-premise) или с ограниченным доступом. Используется компаниями для хранения проприетарных образов. Примеры: Harbor, GitLab Registry, Nexus.

## Основные концепции

Работа с реестрами — ключевая часть жизненного цикла контейнеров. Основной воркфлоу включает аутентификацию, тегирование, отправку и получение образов.

### Аутентификация: `docker login`

Для работы с частными реестрами или приватными репозиториями требуется аутентификация.

```bash
# Команда для входа в реестр
docker login <домен_реестра>

# Пример
docker login my-registry.example.com
# Username: myuser
# Password: ...
```

После успешного входа Docker сохраняет токен доступа в файле `~/.docker/config.json`.

Для выхода из реестра используется команда `docker logout <домен_реестра>`.

### Тегирование образов: `docker tag`

Перед отправкой в удаленный реестр локальный образ необходимо "тегировать", указав в теге адрес реестра и целевой репозиторий.

```bash
# Формат: docker tag <локальный_образ>:<тег> <реестр>/<проект>/<образ>:<тег>
docker tag my-app:latest my-registry.example.com/my-project/my-app:1.0.0
```

### Отправка образов: `docker push`

Команда `docker push` загружает образ в реестр.

```bash
docker push my-registry.example.com/my-project/my-app:1.0.0
```
Docker эффективно отправляет только те слои, которых еще нет в реестре.

### Получение образов: `docker pull`

Команда `docker pull` скачивает образ из реестра.

```bash
docker pull my-registry.example.com/my-project/my-app:1.0.0
```
Если реестр не указан (например, `docker pull ubuntu:22.04`), по умолчанию используется Docker Hub.

## Практические сценарии

### Пример: Harbor — корпоративный реестр образов

**Harbor** — это популярный open-source проект [CNCF](../../Kubernetes/cncf_overview.md), который предоставляет функциональность частного реестра с расширенными возможностями для корпоративного использования.

#### Ключевые возможности Harbor

*   **Управление доступом (RBAC)**: Проекты, пользователи и роли для гранулярного контроля доступа.
*   **Сканирование уязвимостей**: Интеграция со сканерами (например, Trivy, Clair) для автоматического анализа образов на известные уязвимости.
*   **Подпись образов**: Обеспечение целостности и происхождения образов с помощью Notary или Cosign.
*   **Репликация**: Автоматическая синхронизация образов между несколькими инстансами Harbor (например, для геораспределенных команд).
*   **Веб-интерфейс**: Удобный UI для управления проектами, пользователями и образами.
*   **Аудит**: Детальное логирование всех действий пользователей.

#### Установка Harbor

Harbor обычно устанавливается с помощью Docker Compose.

1.  **Скачать инсталлятор**: Загрузите офлайн-инсталлятор с [официального сайта](https://github.com/goharbor/harbor/releases).
2.  **Настроить `harbor.yml`**:
    ```yaml
    hostname: harbor.yourdomain.com
    http:
      port: 80
    https:
      port: 443
      certificate: /path/to/tls.crt
      private_key: /path/to/tls.key
    harbor_admin_password: <YourAdminPassword>
    # ... другие настройки
    ```
3.  **Запустить установку**:
    ```bash
    sudo ./install.sh
    ```

#### Работа с Harbor

1.  **Аутентификация**:
    ```bash
    docker login harbor.yourdomain.com
    # Username: admin
    # Password: <YourAdminPassword>
    ```
2.  **Тегирование и отправка образа**:
    ```bash
    # В Harbor образы организованы по проектам (например, 'library')
    docker tag my-app:latest harbor.yourdomain.com/library/my-app:v1
    docker push harbor.yourdomain.com/library/my-app:v1
    ```
3.  **Получение образа**:
    ```bash
    docker pull harbor.yourdomain.com/library/my-app:v1
    ```

## Дополнительная информация

### Безопасность при работе с реестрами

*   **Используйте токены доступа**: Для автоматизации (CI/CD) и работы с API реестра используйте токены с ограниченным сроком действия и минимальными привилегиями вместо пароля пользователя.
*   **Защищайте `config.json`**: Файл `~/.docker/config.json` содержит учетные данные для доступа к реестрам. Убедитесь, что права доступа к этому файлу ограничены.
*   **Используйте HTTPS**: Всегда подключайтесь к реестрам по HTTPS, чтобы защитить учетные данные и образы от перехвата.
*   **Проверяйте сертификаты**: Убедитесь, что TLS-сертификат реестра является доверенным для Docker-демона.
*   **Credential Helpers**: Для безопасного хранения учетных данных используйте [credential helpers](https://docs.docker.com/engine/reference/commandline/login/#credential-helpers), которые позволяют хранить пароли и токены в системных хранилищах (например, Keychain в macOS, Pass в Linux).
