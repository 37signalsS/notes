# Работа с реестрами (Registries) в Docker

## Типы реестров

- **Публичные реестры:** Наиболее известный — **Docker Hub**. Содержит огромное количество официальных и пользовательских образов.
- **Приватные реестры:** Решения для корпоративного или частного использования. Позволяют хранить образы в изолированной среде. Популярные примеры:
    - **Harbor:** Open-source проект CNCF с функциями сканирования уязвимостей, репликации и управления доступом.
    - **GitLab Container Registry:** Интегрирован в GitLab CI/CD.
    - **Nexus Repository Manager:** Универсальный менеджер артефактов, поддерживающий Docker-образы.
    - **Docker Registry:** Официальный легковесный образ `registry:3.0.0` для быстрого развертывания собственного реестра.

## Docker Hub: Основные операции

Docker Hub является реестром по умолчанию для клиента Docker.

### Аутентификация (`docker login`)

Для загрузки (push) приватных образов или для увеличения лимита на скачивание публичных образов необходима аутентификация.

```sh
docker login -u <dockerhub_username>
```
После ввода команды система запросит пароль. Для повышения безопасности рекомендуется использовать **Access Token** вместо пароля. Его можно сгенерировать в настройках аккаунта Docker Hub (`Account Settings` -> `Security`).

### Именование и загрузка образа (`docker tag` и `docker push`)

Чтобы загрузить образ в ваш репозиторий на Docker Hub, его необходимо правильно именовать в формате `<имя_пользователя>/<имя_репозитория>:<тег>`.

1.  **Тегирование существующего образа:**

    ```sh
    # docker tag <локальный_образ>:<тег> <username>/<имя_репозитория>:<тег>
    docker tag my-app:1.2.0 myusername/my-app:1.2.0
    ```

2.  **Загрузка образа в репозиторий:**

    ```sh
    docker push myusername/my-app:1.2.0
    ```

### Ограничения (Rate Limits)

Docker Hub ограничивает количество скачиваний образов с одного IP-адреса:

-   **Анонимные пользователи:** 100 скачиваний за 6 часов.
-   **Аутентифицированные пользователи (бесплатный план):** 200 скачиваний за 6 часов.

## Конфигурация демона Docker (`/etc/docker/daemon.json`)

Для продвинутой настройки взаимодействия с реестрами используется конфигурационный файл Docker-демона `/etc/docker/daemon.json`.

### Зеркала реестров (`registry-mirrors`)

**Назначение:** Ускорение скачивания образов и снижение нагрузки на Docker Hub.
**Принцип работы:** Docker-демон сначала пытается скачать образ из указанного зеркала. Если образ там отсутствует, демон обращается к основному реестру (Docker Hub), скачивает образ и **кэширует его в зеркале** для будущих запросов.

Это особенно полезно в корпоративных сетях и CI/CD, где одни и те же базовые образы скачиваются многократно.

**Пример конфигурации:**

```json
{
  "registry-mirrors": [
    "https://my-local-registry-mirror.example.com",
    "https://another-mirror.example.com"
  ]
}
```

### Незащищенные реестры (`insecure-registries`)

**Назначение:** Разрешить Docker-демону взаимодействовать с реестрами по незащищенному протоколу HTTP. По умолчанию Docker требует HTTPS.

**Сценарий использования:** Необходимо для работы с локальными или внутренними реестрами в полностью изолированной и доверенной сети, где настройка TLS-сертификатов избыточна.

**Предупреждение о безопасности:** Использовать эту опцию следует с большой осторожностью. При взаимодействии с `insecure-registry` все данные, включая учетные данные для входа (`docker login`) и слои образов, передаются в **открытом тексте**. Это создает риск перехвата и компрометации.

**Пример конфигурации:**

```json
{
  "insecure-registries": ["my-local-registry:5000"]
}
```

После внесения изменений в `/etc/docker/daemon.json` необходимо перезапустить Docker-демон:
```sh
sudo systemctl restart docker
```
