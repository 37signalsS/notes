# SBOM: Спецификация Программного Обеспечения

Создание и анализ SBOM является важной частью общей стратегии безопасности, описанной в документе **[Безопасность Docker](./docker_security.md)**.

**Программная спецификация (Software Bill of Materials, SBOM)** — это формальный, машиночитаемый перечень всех компонентов, из которых состоит программное обеспечение. Его можно представить как "список ингредиентов" для приложения.

В этот список входят:

-   Все прямые и транзитивные зависимости (библиотеки, модули, фреймворки).
-   Информация о версиях каждого компонента.
-   Данные о лицензиях.
-   Уникальные идентификаторы компонентов (например, PURL, CPE).

---

## Зачем нужен SBOM?

SBOM является краеугольным камнем безопасности цепочки поставок программного обеспечения (Software Supply Chain Security).

-   **Прозрачность:** Вы точно знаете, из чего состоит ваше приложение. Нет "черных ящиков".
-   **Управление уязвимостями:** При появлении новой уязвимости (как, например, Log4Shell), вы можете мгновенно проверить, затронуты ли ваши системы, просто просканировав SBOM, вместо того чтобы сканировать все производственные системы.
-   **Управление лицензиями:** SBOM помогает отслеживать лицензии всех зависимостей, предотвращая юридические риски, связанные с несовместимыми или ограничительными лицензиями.
-   **Целостность ПО:** Наличие SBOM — первый шаг к проверке того, что компоненты, из которых было собрано ПО, не были изменены или подменены.

## Форматы SBOM

Существует два основных стандарта, оба из которых машиночитаемы и широко поддерживаются инструментами:

| Формат | Основной фокус | Кем разработан |
| :--- | :--- | :--- |
| **SPDX (Software Package Data Exchange)** | **Соответствие лицензиям (Compliance).** | Linux Foundation |
| **CycloneDX** | **Безопасность и уязвимости.** | OWASP |

-   **SPDX:** Более старый и зрелый формат, изначально созданный для решения юридических вопросов, связанных с лицензиями. Он очень подробный. Является стандартом ISO/IEC 5962:2021.
-   **CycloneDX:** Более современный и легковесный формат, созданный специально для нужд кибербезопасности. Он сфокусирован на анализе уязвимостей и отлично подходит для автоматизации в CI/CD.

На практике многие инструменты поддерживают оба формата. Для задач DevSecOps часто предпочитают **CycloneDX** из-за его легковесности и фокуса на безопасности.

## Syft: Генерация SBOM из Docker-образов

**Syft** — это инструмент командной строки от Anchore, который позволяет легко генерировать SBOM для образов контейнеров и файловых систем.

### Установка (Linux)

```bash
# Загружаем и устанавливаем последнюю версию Syft
curl -sSfL https://get.anchore.io/syft | sudo sh -s -- -b /usr/local/bin
```

### Основные команды

-   **Простая генерация SBOM для образа:**
    Syft проанализирует образ и выведет результат в табличном виде.

    ```bash
    syft python:3.9-slim
    ```

-   **Генерация в формате CycloneDX JSON:**
    Это самый распространенный сценарий для интеграции с другими инструментами.

    ```bash
    syft python:3.9-slim -o cyclonedx-json > sbom.json
    ```
    *   `-o cyclonedx-json`: Указывает формат вывода.
    *   `> sbom.json`: Перенаправляет вывод в файл `sbom.json`.

-   **Генерация в формате SPDX JSON:**

    ```bash
    syft python:3.9-slim -o spdx-json > sbom.spdx.json
    ```

## Рабочий процесс: Syft + Grype + Copacetic

Генерация SBOM — это только половина дела. Настоящая польза раскрывается, когда этот SBOM используется для полного цикла управления уязвимостями: от обнаружения до исправления.

Связка **Syft + Grype + Copacetic** представляет собой продвинутый DevSecOps-пайплайн:

1.  **Сборка образа:** В CI/CD собирается новый образ приложения (`my-app:1.2.3`).

2.  **Генерация SBOM (`Syft`):** Сразу после сборки `Syft` создает SBOM для этого образа. Этот SBOM сохраняется как артефакт сборки.

    ```bash
    syft my-app:1.2.3 -o cyclonedx-json > sbom.json
    ```
3.  **Сканирование SBOM (`Grype`):** `Grype` сканирует SBOM и генерирует отчет об уязвимостях в формате JSON.

    ```bash
    grype sbom:sbom.json -o json > report.json
    ```
4.  **Автоматическое исправление (`Copacetic`):** Если в отчете найдены уязвимости, CI/CD пайплайн передает его `Copacetic`, который автоматически создает исправленную версию образа без полной пересборки.

    ```bash
    copa patch -i my-app:1.2.3 -r report.json -t my-app:1.2.3-patched
    ```
    Исправленный образ `my-app:1.2.3-patched` затем может быть отправлен на дальнейшее тестирование и развертывание.
