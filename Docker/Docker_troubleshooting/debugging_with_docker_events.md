# Отладка с помощью системных событий Docker

## Определения

**`docker events`** — это команда, которая позволяет в реальном времени просматривать поток системных событий от демона Docker. Она предоставляет информацию о действиях, происходящих на уровне демона, а не внутри конкретного контейнера.

## Основные концепции

Зачастую проблемы с контейнерами вызваны не самим приложением, а внешними факторами, управляемыми демоном Docker. Стандартные команды, такие как `docker logs` или `docker exec`, не всегда помогают, особенно если контейнер перезапускается слишком быстро. В таких случаях `docker events` становится основным инструментом диагностики.

События, которые можно отслеживать, включают:
- **Жизненный цикл контейнера:** `create`, `start`, `stop`, `die`, `restart`, `kill`.
- **Состояние здоровья:** `health_status: unhealthy`.
- **Действия с образами:** `pull`, `push`, `tag`, `delete`.
- **Сетевые события:** `network create`, `network connect`.
- **События томов:** `mount`, `unmount`.

## Практические сценарии

#### 1. Диагностика постоянно перезапускающегося контейнера

**Симптомы:** Контейнер постоянно перезапускается, `docker logs` пуст, `docker exec` не работает.

**Решение:**
Отфильтровать события для конкретного контейнера, чтобы понять причину его остановки.

```sh
# Фильтруем события по имени или ID контейнера
docker events --filter container=<your_container_id>
```

**Пример вывода, указывающий на проблему с Healthcheck:**
```
2025-10-03T18:20:01.123Z container create ...
2025-10-03T18:20:02.456Z container start ...
2025-10-03T18:20:03.789Z container health_status: unhealthy ...
2025-10-03T18:20:04.123Z container kill signal=SIGTERM actor.name=healthcheck
2025-10-03T18:20:04.456Z container die ...
2025-10-03T18:20:04.789Z container restart ...
```
Из вывода видно, что контейнер был остановлен (`kill`) из-за проваленной проверки `healthcheck`, после чего сработала политика перезапуска (`restart`). Эта информация недоступна в логах приложения.

#### 2. Другие сценарии использования

-   **Проваленные Healthchecks:** Как в примере выше.
-   **OOM Kills:** Обнаружение контейнеров, "убитых" ядром из-за нехватки памяти (`oom-kill`).
-   **Проблемы с томами (Volumes):** Анализ событий `mount` и `unmount`.
-   **Падающие init-контейнеры или сайдкары:** Отслеживание их жизненного цикла отдельно от основного приложения.
-   **Общий аудит безопасности:** Просмотр всех действий в Docker (`image pull`, `network create`) во время расследования инцидента.

## Дополнительная информация

#### Полезные флаги `docker events`

| Флаг | Описание |
| :--- | :--- |
| `--filter <key>=<value>` | Фильтрует события (например, `container=...`, `event=start`, `image=...`). |
| `--since <timestamp>` | Показывает события, произошедшие *после* указанного времени (например, `30m`, `2025-10-03T18:00:00`). |
| `--until <timestamp>` | Показывает события, произошедшие *до* указанного времени. |
| `--format '{{json .}}'` | Выводит каждое событие как структурированную JSON-строку для машинной обработки. |
