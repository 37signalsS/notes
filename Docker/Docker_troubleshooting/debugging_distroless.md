# Отладка контейнеров без shell (distroless)

`Distroless`-образы — лучшая практика безопасности, но стандартная отладка через `docker exec -it <container> /bin/sh` в них не работает.

### `docker exec` с другим пользователем

Если в образе есть shell, но он недоступен текущему пользователю, попробуйте зайти как `root`:

```sh
docker exec -it --user root <container_name> /bin/sh
```

### Эфемерный отладочный контейнер (рекомендуемый способ)

Запуск временного контейнера с полным набором утилит в пространствах имён целевого контейнера.

*   **Анализ сети:**

    ```sh
    # nicolaka/netshoot содержит множество сетевых утилит (ss, tcpdump и т.д.)
    docker run -it --rm --network=container:<target_container_name> nicolaka/netshoot
    ```

*   **Анализ процессов:**

    ```sh
    # Позволяет видеть процессы целевого контейнера (ps, top, strace)
    docker run -it --rm --pid=container:<target_container_name> alpine
    ```

#### Дебаг контейнера через `nsenter` с полным набором утилит (универсальный подход)

Если контейнер падает или внутри нет нужных утилит (`ps`, `curl`, `strace`), не всегда нужно срочно менять `Dockerfile`. Можно подключиться к контейнеру через отдельный `debug`-контейнер с полным набором Linux-инструментов, используя `nsenter`. Этот подход особенно полезен, когда `docker exec` не работает или недоступен.

**Преимущества:**
- Не меняет образ, не ломает production-среду.
- Позволяет увидеть процессы, сетевую конфигурацию, файловую систему и права доступа изнутри проблемного контейнера.
- Помогает быстро понять корневую проблему (DNS, порты, диски, лимиты и т.д.).

**Шаги:**
1.  **Узнайте PID контейнера:**
    ```bash
    PID=$(docker inspect -f '{{.State.Pid}}' <container>)
    ```
2.  **Зайдите в его namespaces через "богатый" debug-образ:**
    Используйте привилегированный образ (`ubuntu`, `alpine` с установленными утилитами или специализированный `nicolaka/netshoot`), чтобы получить доступ ко всем пространствам имен целевого контейнера.
    ```bash
    docker run --rm -it --pid=host --net=host --privileged ubuntu bash -lc \
    "nsenter -t $PID -m -u -i -n -p bash"
    ```
    *   `--pid=host --net=host --privileged`: Эти флаги дают `debug`-контейнеру доступ к PID и сетевому пространству имен хоста, а также расширенные привилегии, необходимые для `nsenter`.
    *   `nsenter -t $PID -m -u -i -n -p bash`: Команда `nsenter` переносит вашу оболочку в пространства имен целевого контейнера: `-m` (mount), `-u` (UTS), `-i` (IPC), `-n` (network), `-p` (PID).
3.  **Теперь вы внутри целевого контейнера, но с нормальными утилитами:**
    Вы можете использовать любые установленные утилиты (например, `ps aux`, `ip a`, `ss -lntp`, `df -h`) для диагностики.

### Копирование файлов с помощью `docker cp`

Для анализа логов или конфигураций просто скопируйте их на хост:

```sh
docker cp <container_name>:/path/to/file /local/path/
```

### Использование `docker debug`

Эта команда (доступна в Docker Desktop версии 4.27.0 и выше) является современным решением для отладки. Она создает копию контейнера, но с возможностью переопределить `entrypoint` или добавить инструменты.

```sh
# Создаст копию контейнера my-app и запустит в ней /bin/sh из образа alpine
docker debug my-app -it --image=alpine --entrypoint=/bin/sh
```
