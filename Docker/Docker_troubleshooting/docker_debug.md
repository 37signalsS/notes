# Отладка контейнеров (Docker Debug)

## Определения

**`docker debug`** — CLI-команда для интерактивной отладки контейнеров и образов. Она создаёт эфемерную среду (sidecar-контейнер), которая подключается к целевому объекту, предоставляя полноценный shell и набор инструментов, даже если в исходном образе ничего нет (например, в distroless или scratch).

**Gordon (Docker AI)** — интегрированный интеллектуальный помощник (GA с мая 2026), доступный внутри сессии `docker debug`. Помогает анализировать логи, ошибки конфигурации и предлагает команды для исправления в реальном времени.

**Ключевое преимущество:** Безопасная отладка "на лету" без раздувания production-образов лишними утилитами.

## Основные концепции

### Принцип работы

При запуске `docker debug`:
- Создаётся временный контейнер с собственной ФС, содержащей **Toolbox**.
- Файловая система целевого контейнера/образа монтируется в эту среду.
- Процессы отладки запускаются в изолированном пространстве имен (namespaces), но с доступом к контексту цели.
- Изменения в ФС **запущенного** контейнера видны основному приложению.
- После выхода из сессии все изменения в отладочной среде (установленные пакеты) удаляются.

### Инструментарий (Toolbox)

Среда отладки по умолчанию содержит: `vim`, `nano`, `htop`, `curl`, `dig`, `jq`.

**Управление инструментами через Nix:**

| Команда | Описание |
| :--- | :--- |
| `install <pkg>` | Установить любой пакет из репозитория Nix |
| `uninstall <pkg>` | Удалить установленный пакет |
| `entrypoint --print` | Вывести текущий Entrypoint/CMD |
| `entrypoint --lint` | Проверить скрипт entrypoint на типичные ошибки |
| `entrypoint --run` | Тестовый запуск entrypoint в среде отладки |
| `ai <вопрос>` | Задать вопрос Gordon AI о состоянии контейнера |

### Доступность и требования

- **Версия:** Docker CLI 27.0+ / Docker Desktop 4.33+.
- **Лицензия:** Бесплатно для всех уровней подписки (Personal, Pro, Team, Business) с 2026 года.
- **Сеть:** Для `install` требуется доступ к `https://cache.nixos.org`.

## Практические сценарии

### Сценарий 1: Отладка distroless-контейнера

**Задача:** Получить доступ к ФС образа, в котором нет `/bin/sh`.

```bash
docker debug my-distroless-app:latest
# → Вы попадаете в zsh/bash среду с монтированной ФС образа
```

### Сценарий 2: Горячее исправление конфигурации Nginx

**Задача:** Изменить `nginx.conf` в работающем контейнере без перезапуска.

```bash
docker debug web-server

# Внутри сессии debug:
# Редактируем файл
vim /etc/nginx/nginx.conf

# Проверяем синтаксис (команда nginx берется из целевого контейнера)
nginx -t
# → nginx: the configuration file /etc/nginx/nginx.conf syntax is ok

# Перезагружаем конфиг
nginx -s reload
```

### Сценарий 3: Автоматическая диагностика с Gordon AI

**Задача:** Понять, почему контейнер падает с ошибкой сегментации.

```bash
docker debug failing-app

# Внутри сессии debug:
ai "Почему приложение завершилось с SIGSEGV?"
# → Gordon AI анализирует dmesg и логи, указывает на ошибку в библиотеке libssl
```

### Сценарий 4: Анализ сетевых соединений

**Задача:** Проверить доступность БД из контейнера приложения.

```bash
docker debug app-container

# Устанавливаем недостающий инструмент
install nmap
# → [nix] Installing nmap... Done.

# Проверяем порт
nmap -p 5432 db-host
# → 5432/tcp open  postgresql
```

### Сценарий 5: Удалённая отладка через SSH

**Задача:** Отладить контейнер на сервере staging.

```bash
docker debug --host ssh://admin@staging-server my-container
```

## Дополнительная информация

### Сохранение состояния

| Объект | Сохранение изменений |
| :--- | :--- |
| **Файлы приложения** | Сохраняются в работающем контейнере (до его удаления) |
| **Утилиты (install)** | Удаляются при выходе из `docker debug` |
| **Образы** | Никогда не изменяются напрямую |

### Параметры запуска (Флаги)

| Флаг | Описание | Пример |
| :--- | :--- | :--- |
| `--shell <type>` | Принудительный выбор оболочки (`bash`, `zsh`, `fish`, `auto`) | `--shell fish` |
| `--command "<cmd>"` | Выполнить одну команду и выйти | `--command "ls -l /data"` |
| `--ai-off` | Отключить интеграцию с Gordon AI | `--ai-off` |

### Ограничения и особенности

- **Безопасность:** `docker debug` требует привилегий для создания sidecar-контейнера. В сильно ограниченных средах (Hardened Runtime) может потребоваться настройка политик.
- **Архитектура:** Отладочная среда должна соответствовать архитектуре хоста (x86_64/arm64).
- **Производительность:** Использование Nix для динамической установки пакетов может быть медленным на медленных интернет-каналах.
