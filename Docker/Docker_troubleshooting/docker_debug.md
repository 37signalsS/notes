# Отладка и редактирование контейнеров с помощью Docker Debug

## Определения

**`docker debug`** — это команда Docker CLI, предназначенная для интерактивной отладки запущенных контейнеров. Она позволяет подключаться к контейнеру, монтировать его файловую систему и использовать временный образ с отладочными инструментами (например, `vim`, `curl`) для инспекции и изменения файлов в реальном времени, не останавливая и не пересобирая основной образ.

## Базовые концепции

Основной принцип работы `docker debug` заключается в создании эфемерного отладочного контейнера, который использует пространства имен (PID, network и др.) и файловую систему целевого контейнера. Это позволяет "зайти" внутрь работающего приложения с полным набором утилит, которые могут отсутствовать в оригинальном минималистичном образе.

Все изменения, внесенные во время debug-сессии, являются **эфемерными** — они применяются только к запущенному контейнеру и будут утеряны при его перезапуске или пересоздании.

## Практические сценарии

### Сценарий 1: Редактирование файлов в реальном времени

1. **Запускаем контейнер:**

    ```sh
    docker run -d --name my-nginx -p 8080:80 nginx:latest
    ```

2. **Подключаемся для отладки:**
    Команда откроет интерактивную оболочку. Docker автоматически предоставит доступ к утилитам вроде `vim`, `nano`, `curl`.

    ```sh
    docker debug my-nginx
    ```

3. **Редактируем файл:**
    Находим и изменяем `index.html`.

    ```sh
    # Открываем файл в редакторе
    vi /usr/share/nginx/html/index.html

    # Меняем содержимое, например:
    # <h1>Файл отредактирован через Docker Debug!</h1>
    ```

    После сохранения и выхода из сессии `debug` обновленная страница будет доступна на `http://localhost:8080`.

### Сценарий 2: Изменение конфигурации и перезагрузка сервиса

1. **Подключаемся к контейнеру:**

    ```sh
    docker debug my-nginx
    ```

2. **Редактируем конфигурацию:**

    ```sh
    vi /etc/nginx/nginx.conf
    ```

3. **Применяем изменения без перезапуска контейнера:**
    `nginx -s reload` выполнит горячую перезагрузку конфигурации.

    ```sh
    nginx -s reload
    ```

## Дополнительная информация

### Сохранение изменений

Поскольку изменения эфемерны, для их сохранения следует использовать один из подходов:

1. **Создание нового образа из контейнера (быстрое решение):**

    ```sh
    docker commit my-nginx my-nginx:edited
    ```

    Этот способ не считается лучшей практикой, так как изменения не задокументированы в коде.

2. **Обновление Dockerfile (рекомендуемый способ):**
    Перенесите изменения в `Dockerfile`, чтобы они стали частью сборки.

    ```dockerfile
    FROM nginx:latest
    COPY custom-index.html /usr/share/nginx/html/index.html
    COPY custom-nginx.conf /etc/nginx/nginx.conf
    ```

### Ограничения

* **Минималистичные образы:** Отладка образов на базе `scratch` или `distroless` может быть затруднена, так как даже с `docker debug` в них могут отсутствовать базовые зависимости. Подробнее см. в заметке об [отладке distroless-контейнеров](./debugging_distroless.md).
