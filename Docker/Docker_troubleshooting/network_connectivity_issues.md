# Устранение проблем с доступом Docker-контейнеров к локальной сети

Иногда контейнеры работают, но не могут получить доступ к хосту или другим устройствам в той же сети. Часто причина кроется не в самом Docker, а в конфигурации сетевого стека хост-машины.

## Основные причины и решения

### 1. Конфликт версий iptables (legacy vs nft)

**Проблема:** Если хост-система использует `nftables` в качестве бэкенда для файрвола, а Docker пытается использовать старые (`legacy`) правила `iptables`, то часть сетевых правил может не применяться. В результате NAT и сетевой мост (`bridge`) работают некорректно, изолируя контейнеры от внешней сети.

**Диагностика:**
Проверьте используемую версию `iptables`:
```bash
iptables -V
```

Проверьте, какой режим `iptables` активен в системе:
```bash
update-alternatives --config iptables
```

Изучите конфигурацию сети `bridge` в Docker, чтобы увидеть, какие драйверы и опции используются:
```bash
docker network inspect bridge
```

**Решение:**
Переключите систему на использование `iptables-legacy`. Это наиболее частое решение проблемы.
```bash
sudo update-alternatives --set iptables /usr/sbin/iptables-legacy
sudo update-alternatives --set ip6tables /usr/sbin/ip6tables-legacy
```
После этого перезапустите службу Docker.

### 2. NetworkManager управляет мостом `docker0`

**Проблема:** `NetworkManager` может ошибочно начать управлять сетевым интерфейсом `docker0`, который Docker создает для своего внутреннего моста. Это приводит к сбросу или изменению правил маршрутизации, установленных Docker.

**Диагностика:**
Проверьте, управляет ли `NetworkManager` интерфейсом `docker0`:
```bash
nmcli dev show | grep docker
```
Если в выводе есть `docker0`, значит, `NetworkManager` его контролирует.

**Решение:**
Запретите `NetworkManager` управлять интерфейсом `docker0`. Создайте файл `/etc/NetworkManager/conf.d/docker.conf` со следующим содержимым:
```ini
[keyfile]
unmanaged-devices=interface-name:docker0
```
Затем перезапустите `NetworkManager`.

### 3. Отключен IPv4 forwarding

**Проблема:** Для того чтобы контейнеры могли обращаться к внешним сетям, ядро хоста должно разрешать пересылку IP-пакетов (IP forwarding). Если эта опция отключена, Docker не сможет маршрутизировать трафик из контейнеров наружу.

**Диагностика:**
Проверьте текущее значение параметра `net.ipv4.ip_forward`:
```bash
sysctl net.ipv4.ip_forward
```
Если вывод `net.ipv4.ip_forward = 0`, пересылка отключена.

**Решение:**
Включите `ip_forward` немедленно:
```bash
sudo sysctl -w net.ipv4.ip_forward=1
```
Чтобы настройка сохранилась после перезагрузки, добавьте `net.ipv4.ip_forward=1` в файл `/etc/sysctl.conf` или в новый файл в директории `/etc/sysctl.d/`.
