# Host Aliases in Docker Containers

## Определения

**Host-алиасы в контейнере** — использование alias'ов и функций из `.bashrc` хост-системы внутри Docker-контейнера. По умолчанию изоляция Docker предотвращает автоматическую загрузку конфигурации оболочки хоста.

## Основные концепции

### Почему алиасы не работают по умолчанию

| Уровень | Файлы конфигурации | Загрузка в контейнере |
| :--- | :--- | :--- |
| **Login shell** | `~/.bash_profile`, `~/.profile` | Нет |
| **Interactive shell** | `~/.bashrc` | Нет |
| **Non-interactive shell** | `$BASH_ENV` | Нет |

Docker запускает оболочку в изолированном окружении — файлы хоста не монтируются автоматически.

### Методы решения

1. **Монтирование `.bashrc`** — для интерактивных сессий
2. **Кастомный образ** — для постоянных алиасов
3. **`docker exec` с ENV** — для разовых команд

## Практические сценарии

### Сценарий 1: Монтирование `.bashrc` (интерактивная отладка)

**Задача:** Использовать алиасы хоста в интерактивной сессии.

```bash
docker run -it \
  -v ~/.bashrc:/root/.bashrc:ro \
  ubuntu bash
```

**Параметры:**

- `-v ~/.bashrc:/root/.bashrc:ro` — монтирование только для чтения (безопасность)
- `:ro` — предотвращает случайную модификацию хост-файла из контейнера

**Ограничения:**

- Алиасы хоста могут ссылаться на команды, отсутствующие в контейнере
- Пути к файлам хоста недоступны из контейнера

### Сценарий 2: Кастомный образ с алиасами

**Задача:** Постоянные алиасы для всех контейнеров команды.

```dockerfile
FROM ubuntu:24.04

# Алиасы для всех пользователей
RUN echo 'alias ll="ls -la"' >> /etc/bash.bashrc && \
    echo 'alias gs="git status"' >> /etc/bash.bashrc && \
    echo 'alias docker-ps="docker ps --format \"table {{.Names}}\\t{{.Status}}\""' >> /etc/bash.bashrc

CMD ["bash"]
```

**Использование:**

```bash
docker run -it my-ubuntu bash
```

**Преимущества:**

- Алиасы доступны во всех контейнерах
- Версионируется в Git вместе с Dockerfile
- Не зависит от хост-окружения

### Сценарий 3: Разовые алиасы через ENV

**Задача:** Временные алиасы для CI/CD или скриптов.

```bash
# Через docker run
docker run -it \
  --env BASH_ENV=/tmp/aliases \
  -v <(echo 'alias ll="ls -la"'):/tmp/aliases:ro \
  ubuntu bash -c 'source $BASH_ENV && bash'

# Через docker exec
docker exec -it mycontainer bash -c 'alias ll="ls -la"; bash'
```

**Примечание:** `BASH_ENV` работает для non-interactive shell. Для интерактивных требуется явный `source`.

### Сценарий 4: Функции и сложные алиасы

**Задача:** Перенос сложных функций из `.bashrc`.

```bash
# ~/.bashrc на хосте
alias kubectl-debug='kubectl debug -it --image=nicolaka/netshoot'
docker-ssh() { docker exec -it "$1" bash; }

# Монтирование в контейнер
docker run -it -v ~/.bashrc:/root/.bashrc:ro ubuntu bash
```

**Предупреждение:** Функции требуют наличия зависимых команд в контейнере.

### Сценарий 5: `.zshrc` для Zsh

**Задача:** Использование `.zshrc` вместо `.bashrc`.

```bash
docker run -it \
  -v ~/.zshrc:/root/.zshrc:ro \
  -v ~/.oh-my-zsh:/root/.oh-my-zsh:ro \
  --env ZDOTDIR=/root \
  ubuntu zsh
```

**Требования:**

- Образ должен содержать Zsh (`apt install zsh`)
- Пути к плагинам должны быть доступны

## Дополнительная информация

### Сравнение методов

| Метод | Применимость | Безопасность | Переносимость |
| :--- | :--- | :--- | :--- |
| **Монтирование `.bashrc`** | Отладка, разовые сессии | Средняя (зависит от хоста) | Низкая |
| **Кастомный образ** | Production, команды | Высокая | Высокая |
| **ENV + BASH_ENV** | CI/CD, скрипты | Высокая | Средняя |

### Предупреждения

- **Безопасность:** Не монтируйте `.bashrc` с секретами (API keys, пароли)
- **Пути:** Алиасы с абсолютными путями хоста не работают в контейнере
- **Зависимости:** Команды алиасов должны быть установлены в контейнере
- **`:ro` флаг:** Всегда монтируйте конфигурацию только для чтения

- Для interactive bash `.bashrc` загружается автоматически при монтировании
- `BASH_ENV` эффективен только для non-interactive shell
- В production предпочтительнее кастомные образы с задокументированными алиасами
