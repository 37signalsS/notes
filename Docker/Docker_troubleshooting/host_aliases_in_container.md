# Использование host-алиасов в контейнерах Docker

### Определения

**Host-алиасы в контейнере** — это возможность использовать в командной оболочке внутри Docker-контейнера те же сокращения (alias'ы) и функции, что и в файле `.bashrc` или аналогичных файлах инициализации оболочки вашей хостовой операционной системы.

### Основные концепции

По умолчанию, при запуске Docker-контейнера его окружение изолировано от хостовой системы. Это означает, что конфигурационные файлы оболочки хоста, такие как `~/.bashrc`, `~/.profile` или `~/.zshrc`, не загружаются автоматически внутри контейнера. В результате привычные alias'ы и пользовательские функции, определенные на хосте, недоступны при работе в интерактивном режиме внутри контейнера.

Для решения этой проблемы необходимо явно указать Docker'у, чтобы он монтировал файл инициализации оболочки с хоста внутрь контейнера и использовал его при запуске оболочки.

### Практические сценарии

#### Использование .bashrc с хоста в контейнере

**Проблема:** Недоступность привычных alias'ов и функций из `~/.bashrc` при работе в интерактивном режиме внутри контейнера.

**Решение:** При запуске контейнера смонтировать файл `.bashrc` с хоста в соответствующее место внутри контейнера и указать переменную окружения `BASH_ENV` для его автоматической загрузки.

```sh
docker run -it \
  -v ~/.bashrc:/root/.bashrc \
  --env BASH_ENV=/root/.bashrc \
  ubuntu bash
```

**Пояснения:**
-   `-it`: Запускает контейнер в интерактивном режиме с псевдо-TTY.
-   `-v ~/.bashrc:/root/.bashrc`: Монтирует файл `.bashrc` из домашней директории пользователя на хосте в `/root/.bashrc` внутри контейнера.
-   `--env BASH_ENV=/root/.bashrc`: Устанавливает переменную окружения `BASH_ENV`, которая указывает Bash загружать указанный файл при каждом запуске неинтерактивной оболочки. В данном случае это эффективно для интерактивных сессий тоже, так как `~/.bashrc` часто читается.
-   `ubuntu bash`: Запускает контейнер на основе образа `ubuntu` и выполняет команду `bash`.
