# Доступ к контейнеру через `nsenter`

**`nsenter`** — это утилита командной строки, которая позволяет войти в одно или несколько пространств имён (namespaces) запущенного процесса. Она используется для отладки контейнеров, когда стандартные методы, такие как `docker exec`, неэффективны или недоступны (например, если в контейнере нет оболочки или он постоянно падает).

`nsenter` "переносит" вашу оболочку внутрь контейнера, используя его файловую систему, сеть, процессы и другие системные ресурсы.

**Принцип работы:**

1.  **Определение PID процесса:** Необходимо узнать PID (идентификатор процесса) основного процесса контейнера на хост-машине.
2.  **Вход в пространства имён:** С помощью `nsenter` вы подключаетесь к выбранным пространствам имён этого процесса (mount, UTS, IPC, network, PID).

**Базовые шаги:**

1.  **Узнайте PID контейнера на хосте:**
    ```bash
    PID=$(docker inspect --format '{{.State.Pid}}' <container_id_or_name>)
    ```
2.  **Подключитесь к пространствам имён контейнера:**
    ```bash
    sudo nsenter --target $PID --mount --uts --ipc --net --pid
    ```
    После выполнения этой команды вы окажетесь внутри окружения контейнера, как в обычном `chroot`, но с доступом к его сетевому стеку и процессам.

> **Для более детальной информации и практического использования `nsenter` с "богатыми" отладочными образами, включая примеры для решения проблем с отсутствующими утилитами в `distroless` контейнерах, смотрите раздел «Дебаг контейнера через `nsenter` с полным набором утилит» в документе [Отладка контейнеров без shell (distroless)](./debugging_distroless.md).**
