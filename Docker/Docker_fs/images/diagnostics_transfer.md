# Перенос и импорт/экспорт образов: save, load, export, import

## Определения

Docker предоставляет два набора команд для сериализации данных в `tar`-архивы, которые служат разным целям и работают с разными объектами.

- **`docker save` / `docker load`**: Пара команд для работы с **образами (images)**.
  - **`docker save`**: Сохраняет один или несколько Docker-образов в `tar`-архив, **сохраняя всю их структуру**: слои, теги, историю и метаданные.
  - **`docker load`**: Загружает образы из `tar`-архива, созданного `docker save`, восстанавливая их в локальном хранилище Docker.

- **`docker export` / `docker import`**: Пара команд для работы с **файловой системой контейнера (container's filesystem)**.
  - **`docker export`**: Создает "плоский" (flattened) `tar`-архив файловой системы контейнера. Вся информация о слоях и истории теряется.
  - **`docker import`**: Создает **новый, однослойный** образ из `tar`-архива файловой системы.

## Основные концепции

### Ключевые различия и сценарии использования

| Критерий | `save` / `load` | `export` / `import` |
| :--- | :--- | :--- |
| **Что обрабатывает** | **Образ (Image)** | **Файловая система контейнера** |
| **Слои** | ✅ **Сохраняются** | ❌ Теряются (объединяются в один) |
| **История и метаданные** | ✅ **Сохраняются** | ❌ Теряются |
| **Основное назначение** | 1. Перенос образов в изолированные (air-gapped) среды.<br>2. Создание локальных бэкапов образов.<br>3. Передача образа для отладки. | 1. Миграция из других систем виртуализации.<br>2. Создание "чистого" базового образа из настроенного контейнера (редкий сценарий). |

### Когда что использовать?

- **Используйте `docker save` и `docker load`, когда вам нужно:**
  - Переместить готовый, протестированный образ на сервер без доступа к интернету или Docker Registry.
  - Быстро передать коллеге точную копию образа со всеми слоями для совместной отладки.
  - Сделать простую резервную копию важного образа.

- **Используйте `docker export` и `docker import`, когда вам нужно:**
  - "Вытащить" файловую систему из контейнера, чтобы использовать ее в другом месте (например, для анализа или миграции на ВМ).
  - Создать новый базовый образ с нуля, но на основе содержимого другого контейнера. Это экзотический сценарий, и почти всегда лучше использовать `Dockerfile`.

## Практические сценарии

### Сценарий 1: Перенос образа в изолированную среду (`save`/`load`)

1.  **На машине с доступом к сети:** Сохраняем нужный образ в архив.
    ```bash
    docker pull nginx:latest
    docker save -o nginx-image.tar nginx:latest
    ```

2.  **Переносим архив:** Копируем `nginx-image.tar` на целевую машину (например, через `scp` или USB-накопитель).

3.  **На изолированной машине:** Загружаем образ из архива.
    ```bash
    docker load -i nginx-image.tar
    
    # Проверяем, что образ загрузился
    docker images | grep nginx
    ```

### Сценарий 2: Создание "плоского" образа (`export`/`import`)

1.  **Создаем контейнер и вносим изменения:**
    ```bash
    docker run --name temp-container ubuntu:22.04 touch /my-new-file
    ```

2.  **Экспортируем файловую систему контейнера:**
    ```bash
    docker export temp-container > container-fs.tar
    ```

3.  **Импортируем как новый образ:**
    ```bash
    cat container-fs.tar | docker import - my-flat-image:1.0
    ```

4.  **Проверяем результат:** У нового образа нет истории, и он состоит из одного слоя.
    ```bash
    docker history my-flat-image:1.0
    
    # Вывод покажет только один слой и пустую колонку "CREATED BY"
    # IMAGE          CREATED         CREATED BY          SIZE      COMMENT
    # f9e4b5b8129c   1 minute ago                        4.09kB    Imported from -
    ```

## Дополнительная информация

- **Docker Registry — предпочтительный способ**: Для всех стандартных рабочих процессов (разработка, CI/CD, production) правильным способом распространения образов является **[Docker Registry](../../Docker/Docker_registries/docker_registries.md)**. Команды `save`/`load` следует использовать только для исключительных случаев.

- **Сжатие архивов**: `tar`-архивы, создаваемые `docker save`, могут быть большими. Их можно сжимать на лету для экономии места.
  - **Сохранение со сжатием:**
    ```bash
    docker save my-image:latest | gzip > my-image.tar.gz
    ```
  - **Загрузка из сжатого архива:**
    ```bash
    gunzip -c my-image.tar.gz | docker load
    ```
