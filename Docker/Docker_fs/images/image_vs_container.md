# Docker: Сравнение образа и контейнера

Разграничение понятий образа и контейнера является фундаментальным для понимания архитектуры Docker. Образ представляет собой статический шаблон, в то время как контейнер — это его динамическое, исполняемое воплощение.

## Определения

- **Образ (Image)** — неизменяемый (read-only) пакет, содержащий всё необходимое для запуска приложения: код, среду выполнения, системные библиотеки и настройки. Является "чертежом" или снимком файловой системы.
- **Контейнер (Container)** — запущенный экземпляр образа. Это изолированный процесс (или группа процессов), который использует ресурсы хоста, но имеет собственное изолированное окружение (файловую систему, сеть, дерево процессов).
- **Записываемый слой (Writable Layer)** — тонкий слой файловой системы, который добавляется поверх неизменяемых слоев образа при запуске контейнера. Все изменения, внесенные в работающем контейнере, сохраняются именно здесь.

## Основные концепции

### Сборка (Build-time) против Выполнения (Run-time)

- **Build-time (Этап сборки)**: Вы описываете инструкции в `Dockerfile` и выполняете `docker build`. Результатом является **образ** — артефакт, который можно хранить в реестре и передавать между серверами.
- **Run-time (Этап выполнения)**: Вы выполняете `docker run`. Docker берет образ и запускает на его основе один или несколько **контейнеров**.

### Механизм Copy-on-Write (CoW)

Docker использует стратегию "Копирование при записи" для эффективного управления ресурсами.
1. Все слои образа доступны только для чтения.
2. Если процесс в контейнере хочет изменить файл, существующий в образе, Docker копирует этот файл из нижних слоев (image layers) в верхний записываемый слой (writable layer).
3. Изменения происходят в копии, не затрагивая исходный образ.
4. Это позволяет запускать сотни контейнеров на базе одного образа, потребляя минимум дискового пространства. Подробнее см. в разделе **[OverlayFS в Docker](../docker_overlayfs.md)**.

### Эфемерность и состояние (Statelessness)

Контейнеры по своей природе **эфемерны** (временны). 
- При удалении контейнера (`docker rm`) его записываемый слой уничтожается навсегда. 
- **Лучшая практика**: Контейнеры должны быть "без сохранения состояния" (stateless). Любые важные данные (базы данных, логи, пользовательские загрузки) должны храниться во внешних хранилищах — **[томах (Volumes)](../docker_volumes.md)**.

### Сравнение характеристик

| Характеристика | Образ (Image) | Контейнер (Container) |
| :--- | :--- | :--- |
| **Изменяемость** | Неизменяемый (Read-Only) | Изменяемый (через Writable Layer) |
| **Жизненный цикл** | Собирается, хранится, удаляется | Запускается, останавливается, уничтожается |
| **Идентификатор** | Дайджест (SHA256), теги | ID контейнера, имя |
| **Дисковое пространство** | Занимает место постоянно | Занимает место только для изменений (CoW) |
| **Назначение** | Шаблон для доставки ПО | Среда для выполнения ПО |

## Практические сценарии

### Жизненный цикл: от сборки до удаления

1. **Сборка образа**:
   ```bash
   docker build -t my-app:1.0 .
   ```
   *Результат:* Создан статический артефакт `my-app:1.0`.

2. **Запуск нескольких контейнеров из одного образа**:
   ```bash
   docker run -d --name app-worker-1 my-app:1.0
   docker run -d --name app-worker-2 my-app:1.0
   ```
   *Результат:* Работают два независимых процесса. Изменения в `app-worker-1` никак не повлияют на `app-worker-2`.

3. **Просмотр изменений в контейнере**:
   Команда `docker diff` показывает, что изменилось в записываемом слое относительно образа.
   ```bash
   docker diff app-worker-1
   # → C /root (изменение директории)
   # → A /root/log.txt (добавление нового файла)
   ```

4. **Удаление и потеря данных**:
   ```bash
   docker stop app-worker-1 && docker rm app-worker-1
   ```
   *Результат:* Файл `/root/log.txt` удален вместе с контейнером. Образ `my-app:1.0` остался неизменным.
