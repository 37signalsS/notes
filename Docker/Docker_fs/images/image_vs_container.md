# Docker: Сравнение образа и контейнера

Разграничение понятий образа и контейнера является фундаментальным для понимания архитектуры Docker. Образ представляет собой статический шаблон, в то время как контейнер — это его динамическое воплощение.

## Определения

- **Образ (Image)**: Декларативный шаблон или "чертёж".
  - **Аналогия**: Класс в объектно-ориентированном программировании или рецепт блюда.
  - **Сущность**: Пассивный, неизменяемый (read-only) пакет, содержащий всё необходимое для запуска приложения: код, среду выполнения (runtime), системные утилиты, библиотеки и настройки.

- **Контейнер (Container)**: Работающий экземпляр или запущенный процесс.
  - **Аналогия**: Объект (экземпляр класса) или готовое блюдо, приготовленное по рецепту.
  - **Сущность**: Изолированная среда выполнения (согласно стандарту OCI — Open Container Initiative), созданная на основе образа. Обычно реализуется как изолированный процесс Linux, использующий механизмы пространств имён (namespaces) и контрольных групп (cgroups). Контейнер обладает собственным жизненным циклом, состоянием и записываемым слоем файловой системы. Подробнее см. в разделе **[Альтернативные среды выполнения](../../alternative_runtimes_and_tools.md)**.

> Коротко: **Образ — это то, что собирается (`build`). Контейнер — это то, что запускается (`run`).**

## Основные концепции

### Этап сборки против этапа выполнения

- **Этап сборки (Build-time)**: Образ создаётся командой `docker build` на основе файла `Dockerfile`. Он является артефактом, который хранится в локальном хранилище или удалённом реестре (Registry).
- **Этап выполнения (Run-time)**: Контейнер создаётся командой `docker run` из конкретного образа. Из одного образа можно запустить неограниченное количество независимых контейнеров.

### Сравнение характеристик

| Характеристика | Образ (Image) | Контейнер (Container) |
| :--- | :--- | :--- |
| **Состояние** | Неизменяемый (Read-Only) | Изменяемый (записываемый слой) |
| **Жизненный цикл** | `build`, `pull`, `push`, `tag`, `rmi` | `create`, `run`, `start`, `stop`, `rm` |
| **Идентификатор** | Дайджест (Digest), теги (Tags) | ID контейнера, имя (Name) |
| **Файловая система** | Набор неизменяемых слоёв | Слои образа + слой записи (Writable Layer) |
| **Назначение** | Шаблон и способ доставки | Исполняемая среда приложения |
| **Данные** | Статические зависимости | Изменяемые данные (удаляются вместе с контейнером) |

## Практические сценарии

### Жизненный цикл: от сборки до удаления

Процесс трансформации образа в контейнер и его последующее удаление.

1. **Создание образа**:
   Сборка образа из `Dockerfile` с присвоением тега.

   ```bash
   docker build -t my-app:1.0 .
   # → Успешная сборка образа с ID a1b2c3d4e5f6
   ```

2. **Просмотр доступных образов**:
   Проверка наличия созданного шаблона в локальной базе.

   ```bash
   docker images | grep my-app
   # → my-app       1.0      a1b2c3d4e5f6   10 seconds ago   150MB
   ```

3. **Запуск контейнера**:
   Создание работающего экземпляра на основе образа.

   ```bash
   docker run -d --name my-running-app my-app:1.0
   # → f0e1d2c3b4a5... (вывод ID запущенного контейнера)
   ```

4. **Проверка статуса контейнера**:
   Просмотр активных процессов контейнеризации.

   ```bash
   docker ps | grep my-running-app
   # → f0e1d2c3b4a5   my-app:1.0   "npm start"   5 seconds ago   Up 4 seconds   my-running-app
   ```

5. **Остановка и удаление контейнера**:
   Завершение работы процесса и очистка ресурсов.

   ```bash
   docker stop my-running-app
   # → my-running-app
   docker rm my-running-app
   # → my-running-app
   ```
   *Примечание: образ `my-app:1.0` при этом остаётся в системе и может быть использован снова.*
