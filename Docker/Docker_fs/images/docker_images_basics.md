# Образы Docker: Основы

## Определение

**Образ (Image)** — это неизменяемый (immutable) шаблон, логическая группировка слоев и метаданных, содержащий все необходимое для запуска приложения и инструкции по его сборке и работе.

## Концепция слоев (Layers)

Образ Docker состоит из набора слоев, которые накладываются друг на друга. Каждый слой представляет собой результат выполнения одной из команд в `Dockerfile` (например, `RUN`, `COPY`, `ADD`), которая изменяет файловую систему.

- **Неизменяемость (Read-Only)**: Все слои образа, кроме самого верхнего, являются неизменяемыми (read-only). Они кэшируются и могут переиспользоваться между разными образами, что экономит место и ускоряет сборку.
- **Наложение**: Слои образуют единую файловую систему благодаря технологии **OverlayFS**. Если файл существует в нескольких слоях, будет видна версия из самого верхнего слоя.
- **Слой контейнера (Writable Layer)**: Когда из образа запускается контейнер, поверх всех слоев образа добавляется еще один, тонкий **записываемый слой (writable layer)**.

Эта архитектура позволяет:
1. **Экономить место**: Десятки контейнеров, запущенных из одного образа, переиспользуют общие слои
2. **Обеспечивать изоляцию**: Изменения в одном контейнере не затрагивают ни образ, ни другие контейнеры
3. **Быстро запускать контейнеры**: Не нужно копировать всю файловую систему

Команда `docker history <имя_образа>` позволяет увидеть все слои, из которых состоит образ.

## Многоархитектурные образы (Multi-Arch)

Современные CI/CD-системы позволяют собирать образы, которые могут работать на разных архитектурах процессоров (например, `amd64` и `arm64`).

**Пример сборки:**

```sh
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t my-app:1.1.0 \
  --push .
```

Docker-демон на хосте автоматически выберет и запустит версию образа, соответствующую его архитектуре.

Команда `docker manifest` позволяет инспектировать и управлять манифестами — документами, описывающими мультиархитектурные образы.
