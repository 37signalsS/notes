# Docker: Основы образов (Images)

## Определения

- **Образ (Image)**: Неизменяемый пакет (только для чтения — read-only), содержащий всё необходимое для запуска приложения: программный код, среду выполнения, библиотеки, переменные окружения и конфигурационные файлы. Образ является "чертежом" или шаблоном для создания контейнеров.

- **Слой (Layer)**: Docker-образ состоит из упорядоченного набора слоёв. Каждый слой представляет собой результат выполнения одной инструкции в файле `Dockerfile` (например, `RUN`, `COPY`) и является набором изменений файловой системы относительно предыдущего слоя.

- **Тег (Tag)**: Человекочитаемый изменяемый указатель (псевдоним) на конкретную версию образа, например `nginx:1.21` или `my-app:latest`. Один и тот же тег (особенно `latest`) со временем может указывать на разные образы.

- **Дайджест (Digest)**: Уникальный неизменяемый идентификатор образа, представляющий собой криптографический хеш `SHA256 (Secure Hash Algorithm 256-bit)` его манифеста (конфигурации и содержимого). Дайджест гарантирует, что используется побайтово идентичный образ. Пример: `sha256:f6a02b669bf8...`.

## Основные концепции

### Анатомия образа: слои и OverlayFS

Образ можно представить как стопку прозрачных слоёв файловой системы.

- **Базовый образ (`FROM`)**: Самый нижний слой, обычно содержащий операционную систему или среду выполнения.
- **Инструкции `Dockerfile`**: Каждая команда `RUN`, `COPY`, `ADD` добавляет сверху новый слой с изменениями.
- **Объединённое представление**: Итоговая файловая система формируется путём наложения слоёв друг на друга с помощью драйвера хранения, такого как **[OverlayFS (Overlay File System)](../docker_overlayfs.md)**.
- **Слой контейнера**: При запуске контейнера (`docker run`) поверх всех неизменяемых слоёв образа добавляется один тонкий записываемый слой (writable layer). Все изменения в контейнере записываются в него, не затрагивая исходный образ.

### Эффективность за счёт общих слоёв

Если несколько образов основаны на одном и том же базовом слое (например, `FROM ubuntu:22.04`), Docker хранит эти общие слои на диске в единственном экземпляре.

**Практический пример переиспользования слоёв:**

Представим два приложения на Python, использующих одинаковый стек:

1. Слой 1: `debian:bookworm` — базовая операционная система.
2. Слой 2: `RUN apt update && apt install -y python3` — установка среды.

Оба приложения переиспользуют эти слои. Уникальными будут только верхние слои с кодом приложений:

- Слой 3 (Приложение 1): Код приложения `A`.
- Слой 3 (Приложение 2): Код приложения `B`.

Это снижает потребление дискового пространства и ускоряет скачивание образов (pull).

### Тег против дайджеста: изменяемость и неизменяемость

Разграничение этих понятий критично для надёжности развёртывания.

- **Тег (`ubuntu:latest`)**: Работает как указатель ветки в системе контроля версий. Сегодня `latest` может указывать на один образ, а завтра — на другой. Использование `latest` в промышленной эксплуатации (production) приводит к непредсказуемым обновлениям.
- **Дайджест (`ubuntu@sha256:...`)**: Работает как идентификатор коммита. Он навсегда и однозначно определяет конкретную версию образа.

> **Рекомендация:** Для стабильных систем всегда используйте дайджесты или зафиксированные версии тегов (например, `1.2.3-alpine`).

## Практические сценарии

### Сценарий 1: Исследование слоёв образа

Команда `docker history` позволяет увидеть структуру слоёв и команды, которые их создали.

```bash
docker history nginx:latest
# → IMAGE          CREATED        CREATED BY                                      SIZE
# → <missing>      3 weeks ago    /bin/sh -c #(nop)  CMD ["nginx" "-g" "daem…      0B
# → <missing>      3 weeks ago    /bin/sh -c #(nop)  STOPSIGNAL SIGQUIT             0B
# → <missing>      3 weeks ago    /bin/sh -c #(nop)  EXPOSE 80                      0B
# → <missing>      3 weeks ago    /bin/sh -c #(nop) COPY file:e6e33c7e0e754b…      4.62kB
```

### Сценарий 2: Поиск дайджеста образа

Получение уникального идентификатора для конкретного образа.

```bash
# Способ 1: использование docker inspect
docker inspect nginx:latest --format '{{index .RepoDigests 0}}'
# → nginx@sha256:f6a02b669bf8e59b20d361e148045a5f15915a7704b4df915340156f4a883a45

# Способ 2: использование флага --digests
docker images --digests | grep nginx
# → nginx    latest    sha256:f6a02b...    605c77e624dd    2 weeks ago    141MB
```

### Сценарий 3: Запуск контейнера по дайджесту

Запуск гарантирует использование именно той версии образа, которая была протестирована.

```bash
docker run -d --name my-guaranteed-nginx nginx@sha256:f6a02b669bf8e59b20d361e148045a5f15915a7704b4df915340156f4a883a45
# → f0e1d2c3b4a5... (ID запущенного контейнера)
```

## Дополнительная информация

- **Многоархитектурные образы**: Образы могут содержать манифест `OCI (Open Container Initiative)`, ссылающийся на версии для разных архитектур процессоров (`amd64`, `arm64`). Docker автоматически выбирает нужную версию для текущего хоста.
