# Docker: Основы образов (Images)

## Определения

- **Образ (Image)**: Неизменяемый (read-only) пакет, содержащий все необходимое для запуска приложения: код, runtime-среду, библиотеки, переменные окружения и конфигурационные файлы. Образ является "чертежом" для создания контейнеров.

- **Слой (Layer)**: Образ состоит из упорядоченного набора слоев. Каждый слой представляет собой результат выполнения одной инструкции в `Dockerfile` (например, `RUN`, `COPY`) и является лишь набором изменений относительно предыдущего слоя.

- **Тег (Tag)**: Человекочитаемый, изменяемый указатель (алиас) на конкретную версию образа, например `nginx:1.21` или `my-app:latest`. Один и тот же тег (особенно `latest`) со временем может указывать на разные образы.

- **Дайджест (Digest)**: Уникальный, неизменяемый идентификатор образа, представляющий собой SHA256-хеш его манифеста (конфигурации и содержимого). Дайджест — это гарантия того, что вы используете байт в байт идентичный образ. Пример: `sha256:f6a02b669bf8...`.

## Основные концепции

### Анатомия образа: слои и OverlayFS

Представьте образ как стопку прозрачных пленок. Каждая пленка — это слой.
- **Базовый образ (`FROM`)**: Нижний, самый толстый слой.
- **Инструкции `Dockerfile`**: Каждая `RUN`, `COPY`, `ADD` команда добавляет сверху новую "пленку" с изменениями.
- **Объединенное представление**: Когда вы смотрите на стопку сверху, вы видите итоговую файловую систему. Это достигается с помощью драйвера хранения, такого как **[OverlayFS](./docker_overlayfs.md)**.
- **Слой контейнера**: При запуске контейнера (`docker run`) поверх всех неизменяемых слоев образа добавляется один тонкий, **записываемый слой**. Все изменения, которые происходят в контейнере, записываются именно в него, не затрагивая сам образ.

### Эффективность за счет общих слоев

Если у вас есть несколько образов, основанных на одном и том же базовом образе (например, `FROM ubuntu:22.04`), Docker будет хранить эти общие слои на диске **только один раз**. Это значительно экономит дисковое пространство.

### Тег vs. Дайджест: изменяемость vs. неизменяемость

Это ключевая концепция для надежного развертывания.

- **Тег (`ubuntu:latest`)**: Похож на указатель Git-ветки (`main`). Его можно "передвинуть" на новый коммит. Сегодня `ubuntu:latest` может указывать на один образ, а завтра, после обновления, — на совершенно другой. Использование `latest` в production — распространенная причина неожиданных сбоев.
- **Дайджест (`ubuntu@sha256:...`)**: Похож на хеш коммита в Git. Он навсегда и однозначно идентифицирует один конкретный образ.

> **Лучшая практика**: Для production-развертываний всегда используйте дайджесты или, как минимум, очень конкретные теги (например, `1.2.3-alpine`), но никогда не `latest`.

## Практические сценарии

### Сценарий 1: Исследование слоев образа

Команда `docker history` позволяет увидеть слои, из которых состоит образ, и команды, их создавшие.

```bash
docker history nginx:latest

# <missing>      3 weeks ago   /bin/sh -c #(nop)  STOPSIGNAL SIGQUIT             0B        
# <missing>      3 weeks ago   /bin/sh -c #(nop)  EXPOSE 80                      0B        
# <missing>      3 weeks ago   /bin/sh -c #(nop)  ENTRYPOINT ["/docker-ent…      0B        
# <missing>      3 weeks ago   /bin/sh -c #(nop) COPY file:e6e33c7e0e754b…      4.62kB    
# <missing>      3 weeks ago   /bin/sh -c #(nop) COPY file:abbc9233383842…      1.31kB    
# ... и так далее
```
*Каждая строка — это слой. Видно, какая команда его создала и сколько места он занимает.*

### Сценарий 2: Поиск дайджеста образа

Вы можете найти уникальный дайджест для любого вашего образа.

```bash
# Способ 1: docker inspect
docker inspect nginx:latest --format '{{index .RepoDigests 0}}'
# my-registry/nginx@sha256:f6a02b669bf8...

# Способ 2: docker images с флагом
docker images --digests | grep nginx
```

### Сценарий 3: Запуск контейнера по дайджесту

Использование дайджеста гарантирует, что вы запускаете именно тот образ, который тестировали.

```bash
docker run -d --name my-guaranteed-nginx nginx@sha256:f6a02b669bf8e59b20d361e148045a5f15915a7704b4df915340156f4a883a45
```

## Дополнительная информация

- **Многоархитектурные образы (Multi-Arch)**: Современные образы могут содержать "манифест", который ссылается на версии образа, собранные для разных процессорных архитектур (например, `amd64` и `arm64`). Docker-клиент автоматически выбирает и загружает слой, соответствующий архитектуре хоста.
