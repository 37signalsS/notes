# Шифрование томов в Docker (Encryption at Rest)

## Определения

- **Шифрование «на покое» (Encryption at Rest)** — процесс преобразования данных в зашифрованный формат в момент их хранения на физическом носителе (HDD, SSD). Это фундаментальная практика безопасности, защищающая данные от несанкционированного доступа при физической краже носителя или получении доступа к файловой системе хоста.

- **Контекст Docker** — шифрование томов необходимо для защиты чувствительных данных приложений: баз данных, конфигураций и секретов. Это является обязательным требованием многих стандартов безопасности, таких как GDPR (General Data Protection Regulation) и PCI-DSS (Payment Card Industry Data Security Standard).

## Основные концепции

### Отсутствие встроенного шифрования в Docker

Важно понимать, что **Docker не предоставляет нативного встроенного механизма для шифрования томов**. Docker делегирует эту задачу либо операционной системе хоста, либо специализированным драйверам (плагинам) хранения. Ответственность за выбор и реализацию стратегии шифрования полностью лежит на администраторе системы.

### Основные подходы к шифрованию

1. **Шифрование на уровне хост-системы (Host-level Encryption)**
    Наиболее распространенный метод, при котором Docker работает поверх уже зашифрованного слоя файловой системы.
    - **Блочное шифрование (Full Disk Encryption):** Использование технологий LUKS (Linux Unified Key Setup) или dm-crypt для шифрования целого раздела диска, где расположена директория Docker (`/var/lib/docker/`).
    - **Файловое шифрование:** Использование `fscrypt` (для ext4) или нативного шифрования в ZFS. Позволяет шифровать отдельные директории томов.

2. **Шифрование через драйверы и облачные сервисы**
    - **Volume Plugins:** Специализированные плагины (например, Portworx) могут предоставлять шифрование «из коробки», управляемое через Docker API.
    - **Облачные провайдеры:** При использовании облаков (AWS, GCP, Azure) шифрование обычно реализуется на уровне сетевых дисков (например, AWS EBS с включенным шифрованием).

### Управление ключами

Ключи шифрования должны храниться отдельно от самих данных. Рекомендуется использовать:

- **KMS (Key Management Service)** — облачные сервисы управления ключами.
- **HSM (Hardware Security Module)** — аппаратные модули безопасности.
- **Менеджеры секретов** — например, [HashiCorp Vault](../../Vault/overview.md).

## Практические сценарии

### Сценарий 1: Шифрование директории томов с помощью LUKS

Этот метод обеспечивает прозрачное шифрование всех данных в `/var/lib/docker/volumes`.

1. **Подготовка блочного устройства:** Создание loop-устройства для демонстрации (на практике используется реальный раздел диска).

    ```bash
    dd if=/dev/zero of=/secure-docker-volumes.img bs=1G count=10
    losetup /dev/loop0 /secure-docker-volumes.img
    ```

2. **Инициализация LUKS:**

    ```bash
    cryptsetup luksFormat /dev/loop0
    ```

3. **Открытие зашифрованного устройства:**

    ```bash
    cryptsetup open /dev/loop0 docker_volumes_encrypted
    ```

4. **Создание файловой системы и монтирование:**

    ```bash
    mkfs.ext4 /dev/mapper/docker_volumes_encrypted
    mount /dev/mapper/docker_volumes_encrypted /var/lib/docker/volumes
    ```

Подробности работы с блочными устройствами см. в **[Обзоре хранилищ Linux](../../Linux/FileSystems/storage_overview.md)**.

### Сценарий 2: Использование облачного шифрования (AWS EBS)

Самый простой способ для облачных сред:

1. При создании тома EBS в консоли AWS выберите опцию **Encrypt this volume**.
2. Выберите ключ из AWS KMS.
3. Примонтируйте зашифрованный диск к инстансу и настройте Docker на использование этого диска для хранения данных.

### Сценарий 3: Использование плагинов (Volume Plugins)

Если плагин поддерживает шифрование, создание тома выглядит так:

```bash
docker volume create \
  --driver secure-storage \
  --opt encryption=true \
  --opt key_id="alias/my-app-key" \
  my-encrypted-db-volume
```

## Дополнительная информация

- **Производительность:** Современные процессоры с поддержкой AES-NI (Advanced Encryption Standard New Instructions) минимизируют накладные расходы на шифрование, однако небольшое падение производительности (обычно 1–3%) неизбежно.
- **Резервное копирование:** Бэкапы зашифрованных томов на уровне ФС будут зашифрованы. Для их восстановления необходимо иметь доступ к ключам.
- **Сетевые хранилища:** При использовании NFS или [iSCSI](../../Linux/Networking/iSCSI/index.md) следует комбинировать шифрование «на покое» с шифрованием трафика (TLS/IPsec).
