# Docker: Шифрование томов (Encryption at Rest)

## Определения

- **Шифрование "на покое" (Encryption at Rest)**: Процесс шифрования данных, когда они хранятся на физическом носителе (HDD, SSD). Это фундаментальная практика безопасности для защиты данных от несанкционированного доступа в случае физической кражи сервера, диска или доступа к файловой системе хоста.

- **Контекст Docker**: Шифрование томов необходимо для защиты чувствительных данных, которые хранят приложения в контейнерах: базы данных клиентов, секреты, конфигурации и т.д. Это также является требованием многих стандартов безопасности (например, GDPR, HIPAA, PCI-DSS).

## Основные концепции

### У Docker нет встроенного шифрования томов

Это самый важный момент, который нужно понимать: **Docker не предоставляет нативного, встроенного механизма для шифрования томов**. Docker делегирует эту задачу либо операционной системе хоста, либо специализированным драйверам (плагинам) хранения.

Ответственность за выбор и реализацию шифрования полностью лежит на администраторе системы.

### Основные подходы к шифрованию

Существует два стратегических подхода к шифрованию Docker-томов:

1. **Шифрование на уровне хост-системы (Host-level Encryption)**
    Это наиболее распространенный и надежный метод. Docker работает поверх зашифрованного слоя, ничего не зная о нем.
    - **Блочное шифрование (Full Disk Encryption):** Используются технологии вроде **LUKS/dm-crypt** для шифрования целого дискового раздела, на котором расположена директория Docker (`/var/lib/docker/` или только `/var/lib/docker/volumes/`). Все операции записи/чтения прозрачно шифруются/дешифруются ядром.
    - **Файловое шифрование:** Используются технологии вроде **`fscrypt`** (для `ext4`) или нативное шифрование в **ZFS**. Позволяет шифровать отдельные директории, обеспечивая более гранулярный контроль.

2. **Шифрование через драйверы и облака (Docker-level Abstraction)**
    Этот подход абстрагирует сложность от пользователя, интегрируясь с Docker через API.
    - **Volume Plugins**: Специализированные драйверы томов (например, Portworx, NetApp) могут предоставлять функциональность шифрования "из коробки". Управление происходит через Docker API, но реальную работу выполняет плагин.
    - **Облачные провайдеры**: При запуске Docker в облаке (AWS, GCP, Azure) самый простой способ — использовать нативные зашифрованные диски (например, EBS с шифрованием). Шифрование полностью управляется облачной платформой.

### Управление ключами шифрования

Независимо от выбранного метода, управление ключами — критически важный аспект. Если вы теряете ключ, вы теряете данные. Ключи должны храниться безопасно, отдельно от данных, например, в аппаратных модулях безопасности (HSM), облачных KMS (Key Management Service) или менеджерах секретов (Vault).

## Практические сценарии

### Сценарий 1: Шифрование директории томов с помощью LUKS

Этот подход обеспечивает полное шифрование всех Docker-томов на выделенном разделе.

**Концептуальный план действий:**

1. **Подготовить блочное устройство**: Создать новый раздел на диске (например, `/dev/sdb1`) или loop-устройство.

    ```bash
    # Пример с loop-устройством
    dd if=/dev/zero of=/secure-docker-volumes.img bs=1G count=10
    losetup /dev/loop0 /secure-docker-volumes.img
    ```

2. **Отформатировать с помощью LUKS**: Создать зашифрованный LUKS-контейнер. Вам будет предложено ввести парольную фразу.

    ```bash
    cryptsetup luksFormat /dev/loop0
    ```

3. **Открыть контейнер**: Открыть LUKS-контейнер, который создаст отмапленное устройство в `/dev/mapper/`.

    ```bash
    cryptsetup open /dev/loop0 docker_volumes_encrypted
    ```

4. **Создать файловую систему и смонтировать**:

    ```bash
    mkfs.ext4 /dev/mapper/docker_volumes_encrypted
    mkdir -p /var/lib/docker/volumes
    mount /dev/mapper/docker_volumes_encrypted /var/lib/docker/volumes
    ```

    *Эти действия нужно выполнять до первого запуска Docker или после его остановки и переноса существующих томов.*

5. **Автоматизация**: Для автоматического монтирования при загрузке системы необходимо настроить файлы `/etc/crypttab` и `/etc/fstab`.

### Сценарий 2: Использование облачного шифрования (самый простой подход)

При запуске Docker на виртуальной машине в облаке:

1. **AWS**: При создании инстанса EC2 создайте новый том EBS. В настройках тома просто поставьте галочку **"Encrypt this volume"** и выберите ключ шифрования из AWS KMS (можно использовать ключ по умолчанию).
2. **GCP**: При создании Compute Engine VM создайте Persistent Disk и в настройках шифрования выберите "Google-managed key" или "Customer-managed key (CMEK)".
3. **Azure**: Для Managed Disks шифрование на стороне сервера (Server-Side Encryption) включено по умолчанию.

После создания зашифрованного диска смонтируйте его на ВМ как `/var/lib/docker/volumes` или другой каталог, который Docker будет использовать для хранения.

### Сценарий 3: Использование Volume Plugin (концептуальный пример)

Если у вас установлен плагин, поддерживающий шифрование, вы можете создавать зашифрованные тома одной командой:

```bash
# Пример для гипотетического плагина 'secure-storage'
docker volume create \
  --driver secure-storage \
  --opt encryption=true \
  --opt key_id="alias/my-app-key" \
  my-encrypted-db-volume
```

*Вся сложность по работе с ключами и шифрованию скрыта внутри плагина.*

## Дополнительная информация

- **Производительность**: Современные процессоры имеют аппаратную поддержку инструкций AES (AES-NI), что значительно снижает накладные расходы на шифрование. Тем не менее, небольшое падение производительности неизбежно.
- **Резервное копирование**: Бэкапы зашифрованных данных также будут зашифрованы. Это безопасно, но требует, чтобы у вас был доступ к ключам шифрования для их восстановления.
- **Сетевые тома**: При использовании сетевых хранилищ (NFS, [iSCSI](../../Linux/Networking/iSCSI/index.md)) необходимо комбинировать шифрование "на покое" с шифрованием "в пути" (in-transit) с помощью TLS или [IPsec](../../Networking/Tunnels/ipsec/ipsec.md).
