# Справочник команд Docker

## Контейнеры

**Жизненный цикл:**

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker run <образ>` | Создает и запускает контейнер. | `-d` (фоновый режим), `--rm` (удалить после завершения). |
| `docker start <контейнер>` | Запускает остановленный контейнер. | |
| `docker stop <контейнер>` | Корректно останавливает контейнер. | Сначала `SIGTERM`, затем `SIGKILL`. |
| `docker restart <контейнер>` | Перезапускает контейнер. | |
| `docker pause / unpause` | "Замораживает" и "размораживает" процессы. | |
| `docker rm <контейнер>` | Удаляет остановленный контейнер. | `-f` для принудительного удаления запущенного контейнера. |

### `docker stop` vs `docker pause`

- **`docker pause`** "замораживает" все процессы в контейнере. Состояние процессов сохраняется в оперативной памяти, но они перестают потреблять CPU. Используйте эту команду, чтобы временно освободить процессорные ресурсы, не теряя текущего состояния приложения.

- **`docker stop`** инициирует корректное завершение работы контейнера, отправляя процессу сигнал `SIGTERM`. Если процесс не завершается сам за 10 секунд, Docker принудительно "убивает" его сигналом `SIGKILL`. Память и CPU полностью освобождаются. Это стандартный способ остановить контейнер.

**Получение информации:**

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker ps` | Показывает запущенные контейнеры. | `-a` для отображения всех контейнеров. |
| `docker logs <контейнер>` | Показывает логи. | `-f` (в реальном времени), `--tail N` (последние N строк). |
| `docker inspect <контейнер>` | Выводит подробную информацию в JSON. | Получить IP-адрес: `-f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'` |
| `docker stats <контейнер>` | Показывает потребление ресурсов в реальном времени. | |
| `docker top <контейнер>` | Показывает процессы внутри контейнера. | |
| `docker port <контейнер>` | Отображает маппинг портов. | |

**Взаимодействие:**

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker exec -it <контейнер> <команда>` | Выполняет команду внутри контейнера. | Например, `docker exec -it my-container bash`. |
| `docker attach <контейнер>` | Подключается к основному процессу (PID 1). | Для отсоединения без остановки: **`Ctrl+P`, `Ctrl+Q`**. |
| `docker cp <откуда> <куда>` | Копирует файлы между хостом и контейнером. | `docker cp my-container:/app/log.txt .` |
| `docker update` | Динамически обновляет ресурсы. | `docker update --memory 1G my-container` |

| :--- | :--- | :--- |

| `docker pull <образ>:<тег>` | Скачивает образ из registry. | |

## Очистка системы

**"Висячие" образы (dangling images)** — это слои, на которые больше не ссылается ни один тегированный образ. В списке `docker images` они отображаются как `<none>:<none>`. Каждый образ в Docker состоит из слоев, и имеет дочерние связи с другими слоями. Эти образы являются промежуточными и возникают, когда существующий образ пересобирается (например, с тем же тегом или с изменением базового слоя), и старые, неиспользуемые слои остаются без ссылки. Их можно увидеть с помощью команды `docker images -a`.

**Причины появления `none:none`:**
- **Пересборка образа:** Когда вы собираете новый образ из `Dockerfile` с тем же тегом, что и существующий образ. Новый образ получает этот тег, а старый образ, который теперь не имеет тега, становится "висячим" (`<none>:<none>`).
- **Промежуточные слои:** Во время сборки образа Docker создает временные слои для каждой инструкции в `Dockerfile`. Если эти слои не используются последующими инструкциями или не являются частью финального тегированного образа, они также могут стать "висячими".
- **Изменение базового образа:** Если вы пересобираете образ, например, с иной версией операционной системы в `FROM` инструкции, старые слои предыдущего базового образа могут стать обособленными.

**Очистка "висячих" образов:**

| Команда | Описание |
| :--- | :--- |
| `docker container prune` | Удаляет все остановленные контейнеры. |
| `docker image prune` | Удаляет "висячие" (dangling) образы. |
| `docker rmi $(docker images -f "dangling=true" -q)` | Удаляет все "висячие" образы (аналогично `docker image prune`). |
| `docker image prune -a` | Удаляет все неиспользуемые образы (не только висячие). |
| `docker volume prune` | Удаляет все неиспользуемые (не привязанные к контейнерам) тома. |
| `docker network prune` | Удаляет все неиспользуемые (не используемые контейнерами) сети. |
| `docker system prune` | **Основная команда.** Удаляет все неиспользуемые объекты: остановленные контейнеры, висячие образы, неиспользуемые сети. |
| `docker system prune -a --volumes` | **(Опасно)** Глобальная очистка: удаляет всё, что не используется — контейнеры, все неиспользуемые образы, сети и тома. |

### **Подключение к контейнеру (`attach`)**

Команда `docker attach` подключает ваш терминал к стандартному вводу/выводу/ошибкам (STDIN/STDOUT/STDERR) основного процесса (PID 1) в контейнере.

```sh
docker attach <container_name>
```

**Важно:** Если вы выйдете из сессии `attach` с помощью `Ctrl+C`, это отправит сигнал `SIGKILL` и остановит контейнер. Чтобы отсоединиться, не останавливая контейнер, используйте последовательность `Ctrl+P`, `Ctrl+Q`.

### **Инспекция объектов (`inspect`)**

`docker inspect` предоставляет подробную информацию о любом объекте Docker (контейнере, образе, томе, сети) в формате JSON.

```sh
# Получить IP-адрес контейнера
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' my-container
```
### **История образа (`history`)**

`docker history` показывает все слои, из которых состоит образ, их размер и команды, которыми они были создани. Это очень полезно для анализа и оптимизации `Dockerfile`.

```sh
docker history my-image:1.0.0
```

## Перенос образов: `save`/`load` vs `export`/`import`

Для переноса образов и контейнеров между системами без использования registry существуют две пары команд с принципиальными различиями.

### `docker save` и `docker load`

Эти команды работают с **образами**, сохраняя всю их структуру, включая слои, историю и метаданные.

- **`docker save`**: Создает `.tar`-архив из одного или нескольких образов.

  ```sh
  docker save -o my_images.tar my-image:1.1.0 another-image:1.1
  ```

- **`docker load`**: Загружает образы из `.tar`-архива, восстанавливая их в исходном виде.

  ```sh
  docker load -i my_images.tar
  ```

### `docker export` и `docker import`

Эти команды работают с **файловой системой контейнера**, а не с образом. Они создают "плоский" (flattened) архив без истории слоев.

- **`docker export`**: Создает `.tar`-архив файловой системы запущенного или остановленного контейнера.

  ```sh
  docker export my-container > my_container.tar
  ```

- **`docker import`**: Создает **новый** образ из `.tar`-архива файловой системы.

  ```sh
  cat my_container.tar | docker import - my-new-image:1.1.0
  ```

### Ключевые различия

| Критерий | `save`/`load` | `export`/`import` |
| :--- | :--- | :--- |
| **Объект** | Образ (Image) | Файловая система контейнера |
| **Слои** | Сохраняются | Теряются (объединяются в один) |
| **История** | Сохраняется (`docker history`) | Теряется |
| **Метаданные** | Сохраняются (CMD, EXPOSE и т.д.) | Теряются |
| **Назначение** | Перенос/бекап образов | Создание "чистого" базового образа |
