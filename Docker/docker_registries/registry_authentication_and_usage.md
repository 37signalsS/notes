# Аутентификация и использование Docker-реестров

## Обзор

Этот документ описывает процесс аутентификации в Docker-реестрах, а также команды для тегирования и публикации образов. В нем рассматриваются практические примеры работы с частными реестрами, включая Harbor.

## Аутентификация в Docker-реестрах

Для работы с приватными Docker-реестрами необходимо пройти аутентификацию. Это позволяет получить доступ к приватным образам и публиковать новые образы в реестр.

### Команда `docker login`

Для аутентификации используется команда `docker login`:

```bash
docker login <домен_реестра>
```

Пример для Harbor:
```bash
docker login reg.yourdomain.com
```

После выполнения команды будет предложено ввести логин и пароль. Для безопасности рекомендуется использовать токены доступа вместо паролей.

После успешной аутентификации Docker создает токен аутентификации, который сохраняется в файле `~/.docker/config.json`. Этот токен используется для последующих операций с реестром.

### Выход из реестра

Для выхода из реестра используется команда `docker logout`:

```bash
docker logout <домен_реестра>
```

Пример:
```bash
docker logout reg.yourdomain.com
```

## Тегирование образов

Перед публикацией образа в реестр его необходимо "затегировать" с указанием адреса реестра. Формат тега следующий:

```
<домен_реестра>/<пространство_имен>/<имя_образа>:<тег>
```

Пример тегирования образа для публикации в Harbor:
```bash
docker tag my-go-app:latest reg.yourdomain.com/library/my-go-app:latest
```

## Публикация образов

Для публикации образа в реестр используется команда `docker push`:

```bash
docker push <имя_образа_с_тегом>
```

Пример:
```bash
docker push reg.yourdomain.com/library/my-go-app:latest
```

При выполнении команды Docker отправляет образ в указанный реестр по слоям. Если образ уже существует в реестре, Docker отправит только новые или измененные слои.

## Получение образов из реестра

Для получения образа из реестра используется команда `docker pull`:

```bash
docker pull <имя_образа_с_тегом>
```

Пример:
```bash
docker pull reg.yourdomain.com/library/my-go-app:latest
```

## Практический пример: работа с Harbor

Ниже приведен полный пример работы с Harbor-реестром:

1. **Аутентификация в Harbor:**
   ```bash
   docker login reg.yourdomain.com
   # Введите логин и пароль
   # Логин: admin
   # Пароль: Harbor12345 (по умолчанию)
   ```

2. **Создание или тегирование образа:**
   ```bash
   # Предположим, у нас есть локальный образ my-go-app:latest
   docker tag my-go-app:latest reg.yourdomain.com/library/my-go-app:latest
   ```

3. **Публикация образа в Harbor:**
   ```bash
   docker push reg.yourdomain.com/library/my-go-app:latest
   ```

4. **Проверка публикации через веб-интерфейс:**
   - Откройте веб-браузер и перейдите на `https://reg.yourdomain.com`
   - Войдите с использованием учетных данных
   - Найдите проект `library` и убедитесь, что образ `my-go-app` опубликован

5. **Получение образа на другом хосте:**
   ```bash
   # На другом хосте, предварительно аутентифицировавшись
   docker login reg.yourdomain.com
   docker pull reg.yourdomain.com/library/my-go-app:latest
   ```

## Работа с приватными и публичными репозиториями

### Приватные репозитории

Для доступа к приватным репозиториям необходимо быть аутентифицированным в реестре:

```bash
# Без аутентификации доступ к приватному репозиторию будет запрещен
docker pull reg.yourdomain.com/private/my-private-app:latest
# Ошибка: unauthorized: authentication required
```

После аутентификации доступ к приватным репозиториям будет разрешен.

### Публичные репозитории

Публичные репозитории доступны без аутентификации:

```bash
docker pull reg.yourdomain.com/library/my-public-app:latest
# Команда выполнится успешно без аутентификации
```

## Безопасность при работе с реестрами

1. **Использование токенов доступа**: Вместо паролей рекомендуется использовать токены доступа с ограниченным сроком действия.

2. **Хранение учетных данных**: Учетные данные для аутентификации хранятся в файле `~/.docker/config.json`. Убедитесь, что этот файл защищен от несанкционированного доступа.

3. **Проверка сертификатов**: При использовании HTTPS убедитесь, что сертификаты реестра действительны и доверены.

4. **Ограничение прав доступа**: Используйте минимально необходимые права доступа для учетных записей, используемых для работы с реестрами.
