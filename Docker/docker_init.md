# Инициализация проекта: docker init

## Определения

**docker init** — это специализированная интерактивная утилита командной строки (CLI), входящая в состав Docker, которая автоматизирует процесс создания конфигурационных файлов для контейнеризации приложений. Она анализирует структуру проекта (наличие `package.json`, `requirements.txt`, `main.go` и т.д.) и генерирует оптимальные заготовки `Dockerfile`, `compose.yaml` и `.dockerignore`, следуя современным стандартам безопасности и производительности.

## Основные концепции

### Доступность и установка

- **Docker Desktop:** Доступна начиная с версии v4.18 (macOS, Windows, Linux).
- **Docker Engine (Linux):** В современных дистрибутивах поставляется как плагин `docker-init`. Проверить наличие можно командой `docker init --version`.
- **Статус:** С 2024 года является общедоступным (GA) инструментом и рекомендованным способом «быстрого старта».

### Генерируемые артефакты

Инструмент создает четыре ключевых файла:
1.  **Dockerfile:** Оптимизированный многоэтапный (multi-stage) процесс сборки.
2.  **.dockerignore:** Списки исключений для уменьшения контекста сборки.
3.  **compose.yaml:** Базовая конфигурация для локального запуска сервиса и (опционально) связанных БД.
4.  **README.Docker.md:** Автоматически сгенерированная документация с инструкциями по запуску конкретно этого контейнеризированного стека.

### Поддерживаемые платформы (актуально на 2025-2026)

Утилита распознает следующие стеки и предлагает для них специализированные шаблоны:
- **Node.js:** Поддержка npm, yarn, pnpm. Оптимизация под Node 20/22+.
- **Python:** Поддержка pip, poetry, pipenv. Использование образов `slim`.
- **Go:** Автоматическая настройка бинарной сборки.
- **Java:** Поддержка Maven (генерация Dockerfile для сборки JAR).
- **Rust:** Создание минимальных образов через multi-stage.
- **ASP.NET Core:** Оптимизация под .NET 8/9+.
- **PHP:** Шаблоны для PHP с Apache и другими серверами.
- **General Purpose:** Универсальный шаблон для любых других языков.

### Стандарты безопасности по умолчанию

`docker init` автоматически применяет лучшие практики:
- **USER:** В `Dockerfile` создается и используется непривилегированный пользователь для запуска приложения.
- **Pinning Versions:** Образы привязываются к конкретным версиям (например, `python:3.12-slim`), а не к `latest`.
- **Multi-stage builds:** Разделение среды сборки и среды выполнения для минимизации размера итогового образа.

## Практические сценарии

### Сценарий 1: Интерактивная инициализация Node.js

Для проекта с `package.json` процесс выглядит так:

1. **Запуск:**
   ```bash
   docker init
   ```
2. **Интерактивные вопросы:**
   - Выбор платформы (обычно определяется автоматически).
   - Уточнение версии (например, `22.x`).
   - Команда запуска (например, `npm start`).
   - Порт (например, `3000`).
3. **Обработка существующих файлов:**
   Если в директории уже есть `Dockerfile`, утилита спросит: `Dockerfile already exists. Overwrite? [y/N]`.

### Сценарий 2: Контейнеризация Python (FastAPI) с базой данных

При обнаружении Python-проекта `docker init` может предложить структуру, готовую к работе с Compose.

**Результат в `compose.yaml`:**
```yaml
services:
  server:
    build:
      context: .
    ports:
      - 8000:8000
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16-alpine
    # Настройки томов и паролей генерируются автоматически в закомментированном виде
```

## Дополнительная информация

### Важное различие: docker init vs --init

Часто возникает путаница между двумя разными механизмами:

1.  **Команда `docker init`:** Инструмент генерации файлов (описан выше).
2.  **Флаг `--init` (`docker run --init`)**: Механизм внутри Docker, который запускает внутри контейнера легковесный процесс инициализации (обычно `tini`) как PID 1. Это необходимо для корректной обработки сигналов (SIGTERM) и очистки «зомби-процессов».
    - В `compose.yaml` это настраивается через `init: true`.

**Рекомендация:** Используйте команду `docker init` для создания структуры проекта, а флаг `--init` в рантайме, если ваше приложение само не умеет корректно работать как PID 1 (например, Node.js или Python без специальных оберток).

### Ограничения
- **Сложные монолиты:** Если проект требует специфических системных библиотек (например, для обработки изображений или работы с GPU), сгенерированный `Dockerfile` потребует ручной правки в секции `RUN apt-get install...`.
- **Docker Engine на Linux:** Если команда не найдена, убедитесь, что установлен пакет `docker-ce-cli` актуальной версии.
