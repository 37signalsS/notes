# Режим `watch` в Docker Compose

## Обзор

Режим `watch` в Docker Compose позволяет автоматически отслеживать изменения файлов в локальной файловой системе и синхронизировать их с контейнером, а также перезапускать контейнеры при изменении исходного кода. Это значительно упрощает процесс разработки, так как разработчику не нужно вручную пересобирать образ и перезапускать контейнер при каждом изменении кода.

## Использование

Режим `watch` включается в конфигурации `docker-compose.yml` с помощью секции `develop` или через определенные настройки в сервисах. Ниже приведен пример использования:

```yaml
services:
  web:
    build: .
    ports:
      - "8000:8000"
    develop:
      watch:
        # Синхронизировать изменения в директории ./src с контейнером
        - path: ./src
          action: sync
          target: /app/src
        # Перезапускать контейнер при изменении Dockerfile
        - path: Dockerfile
          action: rebuild
```

## Основные параметры

- `path`: Путь к файлу или директории, за которыми нужно наблюдать
- `action`: 
  - `sync` - синхронизировать изменения файлов в реальном времени
  - `rebuild` - пересобрать образ при изменении файлов
  - `recreate` - пересоздать контейнер при изменении файлов
- `target`: Путь в контейнере, куда будут синхронизированы файлы (для действия `sync`)

## Практический пример

Вот пример использования режима `watch` для разработки Python-приложения:

```yaml
services:
  app:
    build: .
    ports:
      - "5000:5000"
    develop:
      watch:
        # Синхронизировать исходный код приложения
        - path: ./app
          action: sync
          target: /app
        # Перезапускать контейнер при изменении зависимостей
        - path: requirements.txt
          action: rebuild
```

## Преимущества

1. **Ускорение разработки**: Изменения в коде сразу же отражаются в работающем контейнере
2. **Удобство отладки**: Нет необходимости вручную перезапускать контейнеры
3. **Экономия времени**: Автоматическая пересборка при изменении конфигурационных файлов

## Ограничения и рекомендации

1. **Не использовать в production**: Режим `watch` предназначен только для разработки
2. **Производительность**: Частая синхронизация может влиять на производительность
3. **Конфликты файлов**: Следует быть осторожным при одновременной работе с файлами в хостовой системе и контейнере
