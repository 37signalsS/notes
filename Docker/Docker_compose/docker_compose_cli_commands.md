# Справочник команд Docker Compose CLI

## Определения

**Docker Compose CLI** — это интерфейс командной строки для управления многоконтейнерными приложениями. Он предоставляет декларативный способ взаимодействия со всем стеком (проектом), определенным в файле `compose.yml`, абстрагируясь от управления отдельными контейнеров.

В современных системах (Compose v5+) CLI реализован как нативный Go-плагин к Docker, вызываемый через `docker compose`. Старая Python-утилита `docker-compose` (с дефисом) официально признана устаревшей (EOL).

## Базовые концепции

### Глобальные флаги (перед командой)

Глобальные флаги влияют на то, как Docker Compose интерпретирует проект и файлы конфигурации:

- **`-f`, `--file`**: Путь к файлу конфигурации. Можно указывать несколько раз для наложения (override).
- **`-p`, `--project-name`**: Явное задание имени проекта (по умолчанию — имя директории).
- **`--env-file`**: Путь к альтернативному файлу переменных окружения.
- **`-v`, `--version`**: Вывод версии Docker Compose.
- **`--dry-run`**: (Compose v5+) Проверить команды без реального выполнения (имитация).

### Управление жизненным циклом проекта

- **`docker compose up`**: Главная команда для развертывания стека.
  - **Действие**: Создает сети, тома и запускает контейнеры.
  - **Флаги**:
    - `-d` / `--detach`: Запуск в фоновом режиме.
    - `--build`: Собрать образы перед запуском (даже если они существуют).
    - `--wait`: Дождаться, пока все сервисы перейдут в состояние `healthy` перед возвратом управления CLI.
    - `--remove-orphans`: Удалить контейнеры сервисов, исключенных из `compose.yml`.
    - `--force-recreate`: Пересоздать контейнеры, даже если их конфигурация и образ не изменились.

- **`docker compose down`**: Остановка и удаление ресурсов.
  - `-v` / `--volumes`: Удалить именованные тома (опасно для персистентных данных).
  - `--rmi all`: Удалить все образы, использованные в проекте.
  - `--remove-orphans`: Удалить контейнеры, не описанные в текущем файле.

- **`docker compose wait`**: (Compose v2.21+) Блокирует выполнение до тех пор, пока сервисы не достигнут определенного состояния (например, `healthy`). Идеально для автоматизации и CI/CD.

- **`docker compose start / stop / restart`**: Управление состоянием существующих контейнеров без их пересоздания.

### Разработка и мониторинг

- **`docker compose watch`**: Запуск режима автоматической синхронизации кода и горячей перезагрузки (см. [**Режим watch**](./docker_compose_watch_mode.md)).

- **`docker compose logs`**: Просмотр вывода контейнеров.
  - `-f`: Потоковый вывод (follow).
  - `--tail`: Количество строк с конца.
  - `--no-log-prefix`: Скрыть имена сервисов в логах.

- **`docker compose ps`**: Список контейнеров проекта и их статус.
  - `--format json`: Вывод в формате JSON для программной обработки.
  - `-a`, `--all`: Показать все контейнеры (включая остановленные).

- **`docker compose top`**: Вывод запущенных процессов внутри контейнеров сервиса.

- **`docker compose stats`**: Мониторинг потребления ресурсов (CPU, RAM, Сеть) сервисами в реальном времени.

- **`docker compose port [SERVICE] [PORT]`**: Выводит публичный порт, на который проброшен указанный порт сервиса.

- **`docker compose attach [SERVICE]`**: (Compose v2.24+) Подключает локальный терминал к стандартным потокам (stdin/stdout/stderr) работающего сервиса.

### Выполнение команд и отладка

- **`docker compose exec`**: Выполнение команды в **запущенном** контейнере.
  - Пример: `docker compose exec db psql -U user`

- **`docker compose run`**: Запуск **нового** контейнера для разовой задачи.
  - `--rm`: Удалить контейнер после завершения.
  - `-T`: Отключить выделение TTY (важно для CI/CD).
  - Пример: `docker compose run --rm web npm test`

- **`docker compose config`**: Валидация и отображение итоговой конфигурации (после слияния всех `include` и `override`).

### Управление образами

- **`docker compose build`**: Сборка образов. Поддерживает `--no-cache` и `--pull`.
- **`docker compose images`**: Список всех образов, используемых текущим проектом, с указанием их ID и размеров.
- **`docker compose pull / push`**: Взаимодействие с удаленными реестрами образов.

## Практические сценарии

### Работа с несколькими файлами конфигурации

Наложение конфигурации (например, для разных окружений):

```bash
docker compose -f compose.yml -f compose.prod.yml up -d
# → Docker Compose объединит оба файла. Флаги во втором файле имеют приоритет.
```

### Выборочный запуск через профили

Если в файле заданы `profiles`, сервисы запускаются только при явном указании:

```bash
docker compose --profile debug up -d
# → Запускаются основные сервисы + сервисы профиля debug
```

### Масштабирование в реальном времени

Изменение количества реплик без остановки стека:

```bash
docker compose up -d --scale worker=5
# → Добавляет или удаляет воркеры до достижения указанного числа
```
