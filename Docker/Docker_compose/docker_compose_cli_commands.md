# Справочник команд Docker Compose CLI

**Актуально для:** Docker Compose v2.20.0+ (Compose Specification)

## Определения

**Docker Compose CLI** — это интерфейс командной строки для управления жизненным циклом многоконтейнерных приложений, декларированных в `compose.yml`. Он предоставляет единый инструмент для развертывания, масштабирования, отладки и сопровождения стеков, абстрагируясь от управления отдельными контейнерами через Docker Engine API.

В современных системах CLI реализован как **нативный Go-плагин** к Docker, вызываемый через `docker compose`. Устаревшая Python-утилита `docker-compose` (с дефисом) официально признана EOL в 2025 году.

## Архитектура и принципы работы

### CLI Plugin Architecture

Docker Compose v2+ работает как **Docker CLI plugin** (плагин расширения), а не как отдельный бинарный файл:

1. **Парсинг:** Docker CLI определяет, что подкоманда `compose` является плагином, и передает управление бинарному файлу `docker-compose`.
2. **Загрузка проекта:** Compose загружает указанные файлы (`-f` или `include`), разрешает переменные окружения и сливает конфигурации по правилам deep merge.
3. **Валидация:** Проверка синтаксиса YAML и типов значений. На этом этапе можно использовать `--dry-run` для имитации без реального выполнения.
4. **Вызов API:** Собранная конфигурация преобразуется в вызовы Docker Engine API (создание сетей, томов, контейнеров).
5. **Мониторинг:** Compose отслеживает события контейнеров (создание, старт, остановка, падение) через драйвер событий Docker.

### Идемпотентность

Команда `docker compose up` является **идемпотентной**: повторный запуск пересоздает только те компоненты, чья конфигурация или образы изменились. Это позволяет использовать один и тот же скрипт для развертывания без предварительной очистки окружения.

## Базовые концепции

### Глобальные флаги (перед подкомандой)

Глобальные флаги влияют на обработку проекта и файлов конфигурации:

- **`-f`, `--file`**: Путь к файлу конфигурации. Можно указывать несколько раз для наложения (override). Порядок файлов определяет приоритет: последующие файлы переопределяют значения из предыдущих.
- **`-p`, `--project-name`**: Явное задание имени проекта (по умолчанию — имя директории). Используется как префикс для контейнеров, сетей и томов.
- **`--env-file`**: Путь к альтернативному файлу переменных окружения. Поддерживается список файлов (Compose v2.24+).
- **`--project-directory`**: Альтернативная рабочая директория (по умолчанию — путь первого указанного compose-файла).
- **`--profile`**: Профиль для выборочного запуска сервисов. Можно указывать несколько раз.
- **`--dry-run`**: (Compose v2.20.3+) Имитация команды без реального изменения стека. Показывает все шаги, которые Compose выполнит при реальном запуске. Поддерживается большинством команд, изменяющих состояние стека (`up`, `down`, `build`, `run`, `exec` и др.). Не поддерживается для команд только для чтения (`ps`, `logs`, `config`).
- **`--ansi`**: Управление ANSI-escapes в выводе (`auto`, `never`, `raw`).
- **`--progress`**: Тип прогресс-вывода (`auto`, `tty`, `plain`, `json`, `quiet`).
- **`--parallel`**: Максимальная степень параллелизма операций (`-1` для неограниченной).
- **`--compatibility`**: Режим обратной совместимости с Compose v1 (имена контейнеров с `_` вместо `-`).
- **`-v`, `--version`**: Вывод версии Docker Compose.

### Категории команд

| Категория | Команды | Назначение |
| :--- | :--- | :--- |
| **Жизненный цикл** | `up`, `down`, `start`, `stop`, `restart` | Управление запуском и остановкой стека |
| **Создание и сборка** | `build`, `create`, `pull`, `push` | Управление образами |
| **Мониторинг** | `ps`, `logs`, `stats`, `top`, `events`, `port` | Наблюдение за состоянием |
| **Выполнение команд** | `exec`, `run`, `attach` | Взаимодействие с контейнерами |
| **Управление ресурсами** | `cp`, `kill`, `pause`, `unpause`, `rm` | Работа с контейнерами и файлами |
| **Инвентаризация** | `ls`, `images`, `volumes`, `config` | Просмотр метаданных |
| **Разработка** | `watch` | Горячая синхронизация кода |
| **Экспериментальные** | `alpha generate`, `alpha publish`, `alpha viz`, `alpha scale` | Продвинутые возможности |

### Переменные окружения

Compose поддерживает переменные окружения для глобальной настройки поведения:

| Переменная | Назначение |
| :--- | :--- |
| **`COMPOSE_PROJECT_NAME`** | Имя проекта (эквивалент `-p`). |
| **`COMPOSE_FILE`** | Путь к compose-файлам (эквивалент `-f`). |
| **`COMPOSE_ENV_FILES`** | Список файлов переменных окружения (Compose v2.24+). |
| **`COMPOSE_BAKE`** | Включить экспериментальную сборку через Docker Bake. |
| **`COMPOSE_IGNORE_ORPHANS`** | Игнорировать предупреждения об orphan-контейнерах. |
| **`COMPOSE_PARALLEL_LIMIT`** | Ограничение параллелизма (эквивалент `--parallel`). |
| **`COMPOSE_DOCKER_CLI_BUILD`** | Использовать встроенный сборщик Docker CLI. |

## Операции и команды

### Управление жизненным циклом проекта

#### `docker compose up`

Главная команда для развертывания стека. Создает сети, тома и запускает контейнеры в порядке, определенном графом зависимостей.

**Флаги:**

| Флаг | Назначение |
| :--- | :--- |
| `-d`, `--detach` | Запуск в фоновом режиме. |
| `--build` | Собрать образы перед запуском (даже если они существуют). |
| `--no-build` | Пропустить сборку образов. |
| `--pull` | Скачать новые версии образов перед сборкой. |
| `--quiet-pull` | Подавлять вывод при скачивании образов. |
| `--wait` | (Compose v2.2.0+) Дождаться, пока все сервисы перейдут в состояние `running\|healthy` перед возвратом управления CLI. Подразумевает detached mode. |
| `--wait-timeout` | (Compose v2.17.0+) Таймаут для `--wait` (по умолчанию `0` — ожидание без таймаута; в CI задавайте явно). |
| `--abort-on-container-exit` | Остановить все контейнеры, как только любой из них прекратил работу. |
| `--abort-on-container-failure` | (Compose v2.27+) Остановить все контейнеры, если любой завершился с ненулевым кодом. В сочетании с `--exit-code-from` исключает прерывание по успешным side-service. |
| `--exit-code-from <service>` | Завершиться с кодом возврата указанного сервиса. Подразумевает `--abort-on-container-exit`. |
| `--force-recreate` | Пересоздать контейнеры, даже если их конфигурация и образ не изменились. |
| `--no-recreate` | Не пересоздавать существующие контейнеры. |
| `--renew-anon-volumes` | Пересоздать анонимные тома. |
| `--remove-orphans` | Удалить контейнеры сервисов, исключенных из `compose.yml`. |
| `--scale <service>=<count>` | Изменить количество реплик сервиса. |
| `--attach <service>` | Ограничить вывод логами указанных сервисов. |
| `--attach-dependencies` | Автоматически подключаться к логам зависимых сервисов. |
| `--always-recreate-deps` | Пересоздавать зависимые контейнеры. |
| `--no-start` | Создать контейнеры, но не запускать. |
| `--init` | Запускать `tini` как init-процесс внутри контейнеров. |
| `--use-aliases` | Использовать сетевые псевдонимы в DNS. |

**Пример:**
```bash
docker compose up -d --build --wait --remove-orphans
# → Собрать образы, запустить в фоне, дождаться healthy, очистить orphans
```

#### `docker compose down`

Остановка и удаление ресурсов проекта.

**Флаги:**

| Флаг | Назначение |
| :--- | :--- |
| `-v`, `--volumes` | Удалить именованные тома (опасно для персистентных данных). |
| `--rmi all` | Удалить все образы, использованные в проекте. |
| `--rmi local` | Удалить только локальные образы. |
| `--remove-orphans` | Удалить контейнеры, не описанные в текущем файле. |
| `--timeout` | Таймаут graceful shutdown (по умолчанию 10 секунд). |

**Пример:**
```bash
docker compose down -v --remove-orphans --timeout 30
# → Полная очистка с увеличенным таймаутом для баз данных
```

#### `docker compose wait`

(Compose v2.20.0+) Блокирует выполнение до остановки контейнеров всех (или указанных) сервисов. Возвращает код выхода каждого сервиса. Идеально для автоматизации и CI/CD.

**Пример:**
```bash
docker compose up -d database
docker compose wait database
# → Блокирует до остановки контейнера database
```

#### `docker compose start / stop / restart`

Управление состоянием существующих контейнеров без их пересоздания.

- **`start`**: Запускает остановленные контейнеры.
- **`stop`**: Останавливает запущенные контейнеры (отправляет SIGTERM, затем SIGKILL после таймаута).
- **`restart`**: Перезапускает контейнеры с сохранением их конфигурации.

**Флаг `--timeout`**: Таймаут перед принудительной остановкой (SIGKILL).

### Мониторинг и отладка

#### `docker compose ps`

Список контейнеров проекта и их статус.

**Флаги:**
- `-a`, `--all`: Показать все контейнеры (включая остановленные).
- `--format json`: Вывод в формате JSON для программной обработки.
- `--orphans`: Показать orphan-контейнеры (Compose v2.24+).

**Пример:**
```bash
docker compose ps --format json --all
# → JSON со всеми контейнерами проекта для автоматизации
```

#### `docker compose logs`

Просмотр вывода контейнеров.

**Флаги:**
- `-f`, `--follow`: Потоковый вывод (follow).
- `--tail`: Количество строк с конца.
- `--no-log-prefix`: Скрыть имена сервисов в логах.
- `--since`: Показать логи после указанного времени.
- `--timestamps`: Показать временные метки.

#### `docker compose stats`

Мониторинг потребления ресурсов (CPU, RAM, сеть) сервисами в реальном времени.

**Пример:**
```bash
docker compose stats --no-stream
# → Однократный снимок потребления ресурсов
```

#### `docker compose top`

Вывод запущенных процессов внутри контейнеров сервиса.

**Пример:**
```bash
docker compose top web
# → Процессы внутри контейнеров сервиса web
```

#### `docker compose events`

Получение событий контейнеров в реальном времени (создание, смерть, изменение состояния).

**Пример:**
```bash
docker compose events --json --since 5m
# → JSON-события за последние 5 минут
```

#### `docker compose port [SERVICE] [PORT]`

Выводит публичный порт, на который проброшен указанный порт сервиса.

**Пример:**
```bash
docker compose port web 80
# → 0.0.0.0:8080
```

### Выполнение команд и отладка

#### `docker compose exec`

Выполнение команды в **запущенном** контейнере.

**Флаги:**
- `--index`: Выбрать конкретный контейнер по индексу (для сервисов с несколькими репликами).
- `--user`: Пользователь для выполнения команды.
- `--workdir`: Рабочая директория внутри контейнера.
- `-T`: Отключить выделение TTY (важно для CI/CD).
- `-e`, `--env`: Переменные окружения для команды.
- `--detach-keys`: Клавиши для detached mode.

**Пример:**
```bash
docker compose exec -T db psql -U user -c "SELECT 1"
# → НетTY, подходит для CI/CD
```

#### `docker compose run`

Запуск **нового** контейнера для разовой задачи.

**Флаги:**
- `--rm`: Удалить контейнер после завершения.
- `--entrypoint`: Переопределить entrypoint образа.
- `--user`: Пользователь для запуска.
- `--workdir`: Рабочая директория.
- `-e`, `--env`: Переменные окружения.
- `--label`: Метки контейнера.
- `-v`, `--volume`: Дополнительные тома.
- `-p`, `--publish`: Дополнительные пробросы портов.
- `--network`: Сеть для подключения.
- `--use-aliases`: Использовать сетевые псевдонимы сервиса.
- `--init`: Запускать `tini` как init-процесс.
- `--cap-add`, `--cap-drop`: Linux capabilities.
- `--security-opt`: SELinux/AppArmor/Seccomp опции.
- `--device`: Устройства хоста.
- `--gpus`: Проброс GPU.
- `--sysctl`: Параметры ядра Linux.
- `--tmpfs`: Временные файловые системы в памяти.
- `--mount`: Дополнительные монтирования.
- `--shm-size`: Размер разделяемой памяти.
- `--ulimit`: Лимиты ресурсов ядра.
- `--dns`, `--dns-search`: DNS-серверы и поисковые домены.
- `--add-host`: Добавление записей в `/etc/hosts`.
- `--mac-address`: MAC-адрес контейнера.
- `--read-only`: Только для чтения корневая ФС.
- `--stop-signal`: Сигнал для остановки (по умолчанию SIGTERM).
- `--stop-timeout`: Таймаут перед SIGKILL.
- `--log-driver`, `--log-opt`: Драйвер и опции логирования.
- `--label-file`: Файл с метками.

**Пример:**
```bash
docker compose run --rm -T -e NODE_ENV=test web npm test
# → Запуск тестов с переменной окружения, без TTY
```

#### `docker compose attach`

(Compose v2.24.0+) Подключает локальный терминал к стандартным потокам (stdin/stdout/stderr) работающего сервиса. Аналог `docker attach` для Compose.

**Пример:**
```bash
docker compose attach web
# → Подключение к логам и stdin запущенного сервиса web
```

### Управление образами и реестрами

#### `docker compose build`

Сборка образов.

**Флаги:**
- `--no-cache`: Игнорировать кэш сборки.
- `--pull`: Скачивать новые версии базовых образов.
- `--builder`: Указать билдер Buildx.
- `--parallel`: Степень параллелизма сборки.

#### `docker compose pull / push`

Взаимодействие с удаленными реестрами образов.

#### `docker compose images`

Список всех образов, используемых текущим проектом, с указанием их ID и размеров.

#### `docker compose commit`

Создание нового образа из изменений в контейнере сервиса.

**Пример:**
```bash
docker compose commit web my-web:modified
# → Зафиксировать изменения в контейнере как новый образ
```

### Управление контейнерами

#### `docker compose cp`

Копирование файлов между хостом и контейнером (или между контейнерами).

**Пример:**
```bash
docker compose cp ./local/file web:/app/file
docker compose cp web:/app/file ./local/
# → Двустороннее копирование
```

#### `docker compose kill`

Принудительная остановка контейнеров (SIGKILL или указанный сигнал). Используется для зависших контейнеров, не реагирующих на SIGTERM.

**Флаги:**
- `--signal`: Сигнал для отправки (по умолчанию SIGKILL).
- `--all`: Убить все контейнеры проекта, включая зависимости.

#### `docker compose pause / unpause`

Приостановка и возобновление процессов в контейнерах через cgroup freezer. Полезно для заморозки состояния во время обслуживания хоста.

**Пример:**
```bash
docker compose pause web cache
docker compose unpause web cache
```

#### `docker compose rm`

Удаление остановленных контейнеров проекта.

**Флаги:**
- `-a`, `--all`: Удалить все контейнеры, включая Running и Paused.
- `-f`, `--force`: Не запрашивать подтверждение.
- `-s`, `--stop`: Остановить контейнеры перед удалением.

**Пример:**
```bash
docker compose rm -f
# → Принудительное удаление всех остановленных контейнеров
```

### Инвентаризация и метаданные

#### `docker compose ls`

Список проектов Compose, запущенных на хосте.

**Флаги:**
- `--all`: Показать все проекты, включая остановленные.
- `--format json`: Вывод в JSON.

**Пример:**
```bash
docker compose ls --format json --all
# → Все проекты для аудита
```

#### `docker compose volumes`

Список томов проекта.

#### `docker compose images`

Список образов, используемых проектом.

#### `docker compose config

Валидация и вывод итоговой конфигурации (после слияния всех файлов).

**Флаги:**
- `--dry-run: Проверка без реального запуска.
- `--no-interpolate: Не подставлять переменные окружения.
- `--resolve-image-digests: Показать дайджесты образов.

**Пример:**
```bash
docker compose config --dry-run
# → Валидация конфигурации перед деплоем
```

#### `docker compose version`

Вывод версии Docker Compose.

### Экспериментальные команды (Alpha)

> **Примечание:** Alpha-команды находятся в стадии активной разработки и могут изменяться между версиями. Проверить наличие: `docker compose alpha --help`.

#### `docker compose alpha generate`

(Compose v2.27.0+) Генерация `compose.yml` из запущенных контейнеров. Полезно для документирования существующей инфраструктуры или миграции с ручного управления на Compose.

**Пример:**
```bash
docker compose alpha generate
# → Генерация compose-файла из всех запущенных контейнеров
```

#### `docker compose alpha publish`

(Compose v2.27.0+) Публикация стека как OCI-артефакта в реестр. Позволяет распространять готовые стеки как единые артефакты.

**Флаги:**
- `--app`: Включить referenced images в артефакт.
- `--with-env`: Включить переменные окружения.
- `--resolve-image-digests: Закрепить теги образов дайджестами.
- `--oci-version`: Версия OCI-спецификации.
- `-y`, `--yes`: Не запрашивать подтверждение.

**Пример:**
```bash
docker compose alpha publish -y my-registry.com/project/stack:v1.0
# → Публикация стека в OCI-реестр
```

#### `docker compose alpha viz`

(Compose v2.28.0+) Генерация графа зависимостей сервисов в формате GraphViz.

**Пример:**
```bash
docker compose alpha viz | dot -Tpng -o stack.png
# → Визуализация архитектуры стека
```

#### `docker compose alpha scale`

(Compose v2.27.0+) Масштабирование сервисов. Устаревшая в пользу `docker compose up --scale`.

**Пример:**
```bash
docker compose alpha scale worker=5
# → Устаревший способ масштабирования
```

### Устаревшие команды

- **`docker-compose` (с дефисом)**: Python-утилита, EOL в 2025 году. Используйте `docker compose`.
- **`docker compose alpha scale`**: Устарела в пользу `docker compose up --scale <service>=<count>`.

## Практические сценарии

### Сценарий 1: Идемпотентный деплой с валидацией

Сценарий для SRE: деплой стека с предварительной проверкой конфигурации и автоматической очисткой ресурсов.

```bash
# Валидация без реального запуска
docker compose config --dry-run
if [ $? -ne 0 ]; then
  echo "Ошибка конфигурации"
  exit 1
fi

# Деплой с пересборкой и ожиданием готовности
docker compose up -d --build --wait --remove-orphans

# Проверка статуса
docker compose ps --format json --all
```

### Сценарий 2: Экстренная очистка окружения

Сценарий для SRE: полная остановка и удаление всех ресурсов проекта с сохранением логов.

```bash
# Сохранение логов перед удалением
docker compose logs > /var/log/compose_$(date +%Y%m%d_%H%M%S).log

# Полная очистка
docker compose down -v --rmi all --remove-orphans --timeout 30
```

### Сценарий 3: Многопроектный аудит хоста

Сценарий для SRE: инвентаризация всех Compose-проектов на хосте.

```bash
# Список всех проектов
docker compose ls --all --format json

# Для каждого проекта: статус, тома, образы
for project in $(docker compose ls -q); do
  echo "=== Проект: $project ==="
  docker compose -p "$project" ps --all
  docker compose -p "$project" volumes
  docker compose -p "$project" images
done
```

### Сценарий 4: Диагностика контейнера без остановки

Сценарий для SRE: копирование логов и артефактов из работающего контейнера для отладки.

```bash
# Копирование логов приложения
docker compose cp web:/app/logs/app.log ./debug/

# Выполнение диагностической команды
docker compose exec -T web sh -c 'cat /proc/meminfo | grep -i "memtotal\|memfree"'

# Просмотр процессов
docker compose top web
```

### Сценарий 5: Генерация документации стека

Сценарий для SRE: создание документации существующего стека из запущенных контейнеров.

```bash
# Генерация compose-файла
docker compose alpha generate > documented_stack.yml

# Визуализация зависимостей
docker compose alpha viz | dot -Tpng -o stack_dependencies.png
```

## Устранение неполадок

### Типичные ошибки CLI

| Ошибка / Симптом | Причина | Решение |
| :--- | :--- | :--- |
| **`no configuration file`** | Compose не находит `compose.yml` | Укажите путь через `-f` или убедитесь, что файл существует в текущей директории. |
| **`service [...] has neither an image nor a build context`** | Отсутствует `image` или `build` в сервисе | Добавьте одну из директив в `compose.yml`. |
| **`port is already allocated`** | Порт занят другим процессом | Освободите порт (`lsof -i :PORT`), измените маппинг или удалите старый контейнер (`docker compose down`). |
| **`No such service`** | Указан несуществующий сервис | Проверьте имя сервиса в `compose.yml` с учетом регистра. |
| **`container name is already in use`** | Конфликт имен контейнеров | Удалите старый контейнер (`docker compose down`) или используйте уникальное `--project-name`. |
| **`deadline exceeded`** при `--wait` | Сервис не переходит в `healthy` за таймаут | Увеличьте `--wait-timeout` или проверьте `healthcheck` в `compose.yml`. |
| **`permission denied`** при `cp` | Нет прав на чтение/запись файла | Проверьте права на хосте и внутри контейнера, используйте `--user`. |
| **`unknown flag: --dry-run`** | Устаревшая версия Compose | Обновите Docker Compose до v2.20.3+. |
| **`--abort-on-container-exit` не работает** | Используется вместе с `-d` | Флаг несовместим с detached mode. Уберите `-d`. |
| **`orphan containers found`** | Контейнеры от предыдущего запуска | Используйте `--remove-orphans` или удалите вручную через `docker compose down`. |
| **`network [...] declared as external`** | Внешняя сеть не существует | Создайте сеть вручную (`docker network create`) или уберите `external: true`. |
| **`Cannot connect to the Docker daemon`** | Docker не запущен или нет прав | Запустите Docker, проверьте membership в группе `docker`. |

### Диагностический процесс

При возникновении проблем с CLI выполните последовательность:

1. **Проверить версию:** `docker compose version` — убедитесь, что используется v2.20.0+.
2. **Валидировать конфигурацию:** `docker compose config` — проверьте итоговый YAML.
3. **Проверить статус:** `docker compose ps` — найти сервис в состоянии `exited` или `restarting`.
4. **Изучить логи:** `docker compose logs <service>` — искать ключевые слова `ERROR`, `failed`, `cannot`.
5. **Инспектировать контейнер:** `docker inspect <container>` — проверить `Mounts`, `Config`, `HostConfig`.
6. **Проверить ресурсы:** `docker compose stats` — убедиться, что сервису выделено достаточно CPU и RAM.

## Рекомендации

### Безопасность

- **Не используйте в production:** Команды `watch`, `alpha generate` предназначены только для разработки.
- **Ограничьте доступ к Docker socket:** На shared-хостах используйте группу `docker` с осторожностью — membership дает root-доступ к хосту.
- **Проверяйте сгенерированные файлы:** `alpha generate` может не включить `healthcheck` и сложные зависимости. Всегда проверяйте результат перед использованием.

### Надежность

- **Используйте `--wait` для production-деплоев:** Гарантирует готовность сервисов перед приемом трафика. Для CI/CD используйте `--exit-code-from` и `--abort-on-container-failure`.
- **Фиксируйте версии образов:** Избегайте тега `latest` в production; используйте дайджесты или SHA-хэши.
- **Настраивайте `--timeout`:** Для баз данных с долгой инициализацией увеличивайте таймаут graceful shutdown (например, `--timeout 60`).
- **Используйте `--remove-orphans`:** Автоматически очищает контейнеры от предыдущих запусков, предотвращая конфликты.

### Производительность

- **Контролируйте параллелизм:** Используйте `--parallel` для ограничения одновременных операций сборки на слабых хостах.
- **Используйте `--quiet-pull` в CI:** Подавляет лишний вывод при скачивании образов, ускоряя сборку логов.
- **Мониторьте через `stats`:** `docker compose stats --no-stream` в скриптах для автоматического сбора метрик.
- **Используйте `--no-recreate` для быстроты:** При повторных запусках без изменений конфигурации ускоряет деплой.

### Поддержка и эксплуатация

- **Версионируйте CLI:** Фиксируйте версию Docker Compose в `docker compose version` для reproducibility.
- **Используйте `COMPOSE_PROJECT_NAME`:** Для изоляции параллельных запусков на общем хосте (например, в CI/CD).
- **Документируйте скрипты:** Все сложные команды с множеством флагов оформляйте как shell-скрипты с комментариями.
- **Мониторинг inotify:** Для SRE: настройте алерты на `node_filefd_allocated` (prometheus_node_exporter) при использовании `watch`.
