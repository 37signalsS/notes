# Основные команды docker compose

Этот документ представляет собой справочник по основным командам `docker compose`.

## Управление жизненным циклом

### `docker compose up`

Создает и запускает контейнеры, сети и тома в соответствии с файлом `compose.yml`.

-   **Поведение по умолчанию**: `docker compose up` работает «интеллектуально». Он пересоздаст контейнер только в том случае, если его конфигурация или образ изменились. В противном случае он просто запустит остановленные контейнеры.
-   `-d` или `--detach`: Запускает контейнеры в фоновом (detached) режиме.
-   `--build`: Принудительно выполняет сборку образов перед запуском сервисов. Полезно, когда вы внесли изменения в `Dockerfile`, но не в `compose.yml`.
-   `--force-recreate`: Принудительно пересоздаёт все контейнеры, даже если их конфигурация или образ не изменились. **Внимание:** данные, не сохраненные в томах, будут утеряны.
-   `--no-recreate`: Никогда не пересоздает контейнеры, даже если их конфигурация изменилась; только запускает существующие.
-   `--scale`: Используется для горизонтального масштабирования. Подробнее см. в [Продвинутых возможностях Docker Compose](./docker_compose_advanced_topics.md).
-   Флаги для CI/CD: Для использования в сценариях тестирования существуют специальные флаги `--exit-code-from` и `--abort-on-container-exit`. Подробнее см. в руководстве [Использование Docker Compose для тестирования в CI/CD](./docker_compose_ci_cd_testing.md).

### `docker compose down`

Останавливает и удаляет контейнеры, сети, созданные командой `up`.

-   `-v` или `--volumes`: Удаляет именованные тома, связанные с сервисами. **Используйте с осторожностью**, так как это приведет к потере данных, хранящихся в томах. Подробнее о томах можно прочитать [здесь](../../Docker/Docker_fs/docker_volumes.md).
-   `--rmi all`: Удаляет образы, используемые сервисами.

### `docker compose ps`

Показывает статус контейнеров, управляемых Compose в текущем проекте.

### `docker compose logs`

Выводит логи запущенных сервисов.

-   `-f` или `--follow`: Выводит логи в реальном времени.
-   `--tail="50"`: Показывает последние 50 строк логов.
-   Можно указать имя конкретного сервиса, чтобы видеть только его логи: `docker compose logs -f web`.

## Выполнение команд

### `docker compose exec`

Выполняет команду внутри **уже работающего** контейнера. Это основной способ получить интерактивный доступ к сервису.

```bash
# Получить интерактивную оболочку в контейнере сервиса 'web'
docker compose exec web sh

# Выполнить команду без входа в контейнер
docker compose exec db psql -U user -d dbname
```

### `docker compose run`

Запускает **новый, одноразовый контейнер** для выполнения команды. Этот контейнер создается на основе конфигурации сервиса, но не является частью управляемого стека. Отлично подходит для выполнения задач, таких как миграции базы данных или запуск утилит.

-   `--rm`: Автоматически удаляет контейнер после выполнения команды.

**Разница между `exec` и `run`:**
-   `exec`: Работает с существующим, запущенным контейнером.
-   `run`: Создает новый контейнер для одноразовой задачи.

## Управление образами и конфигурацией

### `docker compose build`

Собирает или пересобирает образы для сервисов, у которых в конфигурации указан `build`.

-   `--no-cache`: Запрещает использование кэша сборки.
-   `--pull`: Всегда пытаться скачать более новые версии базовых образов.

### `docker compose pull`

Скачивает последние версии образов для всех сервисов, указанных в `compose.yml`.

### `docker compose config`

Проверяет, объединяет и отображает итоговую конфигурацию после применения всех файлов, переменных окружения и шаблонов. Очень полезно для отладки и проверки того, какую конфигурацию на самом деле "видит" Docker Compose.
