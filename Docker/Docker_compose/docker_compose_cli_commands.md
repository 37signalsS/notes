# Справочник команд Docker Compose

## Определения

**Docker Compose CLI** — это интерфейс командной строки для управления многоконтейнерными приложениями Docker. Он позволяет определять и запускать приложения с помощью файла `compose.yml`, упрощая координацию между сервисами, сетями и томами. Этот документ представляет собой справочник по основным командам `docker compose`.

## Базовые концепции (Основные команды)

### Управление жизненным циклом

- **`docker compose up`**: Создает и запускает контейнеры, сети и тома.
  - **Поведение**: Пересоздает контейнер только при изменении его конфигурации или образа. В противном случае запускает остановленные контейнеры.
  - **Флаги**:
    - `-d` / `--detach`: Запуск в фоновом (detached) режиме.
    - `--build`: Принудительная сборка образов перед запуском.
    - `--force-recreate`: Принудительное пересоздание всех контейнеров.
    - `--no-recreate`: Никогда не пересоздавать контейнеры, только запускать существующие.

- **`docker compose down`**: Останавливает и удаляет контейнеры и сети, созданные `up`.
  - **Флаги**:
    - `-v` / `--volumes`: Удаляет именованные тома, связанные с сервисами. **(Внимание: потеря данных)**.
    - `--rmi all`: Удаляет образы, используемые сервисами.

- **`docker compose ps`**: Показывает статус контейнеров в текущем проекте.

- **`docker compose logs`**: Выводит логи сервисов.
  - **Флаги**:
    - `-f` / `--follow`: Вывод логов в реальном времени.
    - `--tail="50"`: Показ последних 50 строк.
    - `[service_name]`: Показ логов конкретного сервиса (например, `docker compose logs -f web`).

### Выполнение команд

- **`docker compose exec`**: Выполняет команду внутри **уже работающего** контейнера. Основной способ получить интерактивный доступ к сервису.

    ```bash
    # Получить интерактивную оболочку в контейнере сервиса 'web'
    docker compose exec web sh
    ```

- **`docker compose run`**: Запускает **новый, одноразовый контейнер** для выполнения команды. Идеально для задач вроде миграций базы данных.
  - **Флаги**:
    - `--rm`: Автоматически удаляет контейнер после выполнения.

### Управление образами и конфигурацией

- **`docker compose build`**: Собирает или пересобирает образы для сервисов.
  - **Флаги**:
    - `--no-cache`: Запрещает использование кэша сборки.
    - `--pull`: Пытаться скачать более новые версии базовых образов.

- **`docker compose pull`**: Скачивает последние версии образов для всех сервисов.

- **`docker compose config`**: Проверяет и отображает итоговую конфигурацию проекта. Полезно для отладки.

## Практические сценарии

### Сценарий: Отладка и выполнение задачи

Представим, что вам нужно запустить приложение, проверить его логи, а затем выполнить миграцию базы данных.

1. **Запуск приложения в фоновом режиме:**

    ```bash
    docker compose up -d --build
    ```

    Это соберет образы (если нужно) и запустит все сервисы.

2. **Проверка логов веб-сервиса:**

    ```bash
    docker compose logs -f web
    ```

    Вы увидите логи сервиса `web` в реальном времени. Нажмите `Ctrl+C` для выхода.

3. **Проверка статуса всех контейнеров:**

    ```bash
    docker compose ps
    ```

    Команда покажет, какие контейнеры запущены.

4. **Выполнение миграции базы данных:**
    Для этого используется `run`, чтобы создать временный контейнер, который выполнит задачу и будет удален.

    ```bash
    docker compose run --rm web python manage.py migrate
    ```

5. **Вход в контейнер для ручной отладки:**
    Если что-то пошло не так, можно получить доступ к оболочке работающего контейнера.

    ```bash
    docker compose exec web sh
    ```

### Разница между `exec` и `run`

- **`exec`**: Работает с **существующим**, запущенным контейнером.
- **`run`**: Создает **новый** контейнер для одноразовой задачи.
