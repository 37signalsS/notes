# Обзор Docker Compose

## Определения

**Docker Compose** — инструмент для определения и запуска многоконтейнерных Docker-приложений на основе декларативного YAML-файла. Он позволяет описывать всю инфраструктуру приложения (сервисы, сети, тома, переменные окружения, секреты и AI-модели) как единый стек.

**Ключевая идея:** вместо ручного управления каждым контейнером через `docker run`, вы определяете состояние всего приложения в файле `compose.yml` и управляете его жизненным циклом единой командой `docker compose`.

**Compose Specification (Compose v5+):** Современный Docker Compose (начиная с 2025 года — версия 5) полностью базируется на открытом стандарте Compose Specification. Это превратило его из простой утилиты в мощную платформу для оркестрации локальных сред и интеграции с облачными провайдерами через официальный Go SDK.

> **Примечание:** Устаревшая Python-утилита `docker-compose` (с дефисом) официально признана EOL (End of Life) в 2025 году и более не поддерживается. Актуальным инструментом является плагин к Docker CLI — `docker compose`.

## Основные концепции

### Проблемы ручного управления контейнерами

При использовании отдельных команд `docker run` для каждого компонента мультиконтейнерного приложения возникают критические сложности:

- **Трудозатратность:** каждый сервис (frontend, backend, база данных) требует отдельной длинной команды с уникальными флагами
- **Сложность зависимостей:** ручной запуск требует соблюдения строгой последовательности (база данных должна быть готова раньше приложения)
- **Сетевая изоляция:** необходимость вручную создавать сети и связывать контейнеры через псевдонимы DNS
- **Фрагментация конфигурации:** настройки портов, томов и переменных окружения разбросаны по разным скриптам или истории команд
- **Отсутствие модульности:** сложно переиспользовать части конфигурации между разными проектами или окружениями (Dev/Prod)

### Ключевые механизмы работы

Современный Docker Compose решает проблемы ручного управления через следующие механизмы:

- **Декларативность:** файл `compose.yml` является "чертежом" системы. Docker гарантирует, что текущее состояние контейнеров соответствует описанному.
- **Сетевая автоматизация:** для каждого проекта Compose по умолчанию создает изолированную сеть типа `bridge`. Сервисы могут обращаться друг к другу по именам, указанным в YAML, которые автоматически преобразуются в IP через встроенный DNS-сервер Docker.
- **Управление данными:** Compose упрощает работу с томами (`volumes`). Вы можете определить именованные тома для персистентности данных (базы данных) или использовать `bind mounts` для проброса кода из хост-системы.
- **Иерархия конфигураций:** поддержка `.env` файлов и интерполяция переменных окружения позволяют динамически изменять настройки без правки основного файла. Приоритет переменных: OS Environment > `.env` файл > значения в `compose.yml`.
- **Умное управление зависимостями:** расширенная директива `depends_on` позволяет ждать не просто старта контейнера, а его полной готовности (`service_healthy`) или успешного завершения (`service_completed_successfully`).
- **Модульность (Include):** возможность импортировать конфигурации из других файлов или удаленных OCI-репозиториев (Compose v2.20+), что позволяет разделять большие проекты на части.
- **Режим разработки (Watch):** автоматическая синхронизация изменений кода между хостом и контейнером в реальном времени без необходимости пересборки образа.
- **AI/ML интеграция:** нативная поддержка AI-моделей (секция `models`), позволяющая подключать LLM и другие веса как зависимости приложения (Compose v5+).
- **Идемпотентность:** команда `docker compose up` пересоздает только те компоненты, чья конфигурация или образы изменились.

### Терминология

В экосистеме Docker Compose используются следующие базовые понятия:

| Термин | Описание |
| :--- | :--- |
| **Сервис (Service)** | Абстракция над контейнером. Определяет образ, конфигурацию запуска и ресурсы. |
| **Проект (Project)** | Группа связанных сервисов, управляемых как единое целое. Имя проекта по умолчанию берется из имени директории или флага `-p`. |
| **Сеть (Network)** | Изолированный сегмент связи. По умолчанию создается одна сеть `default` для всех сервисов проекта. |
| **Том (Volume)** | Хранилище данных. Может быть именованным (управляется Docker) или примонтированным (`bind mount`). |
| **Стек (Stack)** | Совокупность запущенных ресурсов (сервисов, сетей, томов), определенных в одном проекте. |
| **compose.yml** | Основной файл конфигурации. Поле `version` в современных версиях является необязательным и устаревшим. |
| **Модель (Model)** | (Compose v5+) Описание весов AI-моделей как зависимостей проекта. |
| **Фрагмент (Include)** | Часть конфигурации, импортируемая для переиспользования кода. |

## Практические сценарии

### Пример: современный стек приложения

Пример файла `compose.yml`, демонстрирующий лучшие практики (лимиты ресурсов, проверки здоровья и сетевую изоляцию):

```yaml
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    secrets:
      - db_password
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      retries: 5
    networks:
      - backend_net
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 512M

  app:
    build: 
      context: ./app
      dockerfile: Dockerfile
    depends_on:
      db:
        condition: service_healthy
    develop:
      watch:
        - action: sync
          path: ./app/src
          target: /app/src
    networks:
      - frontend_net
      - backend_net

networks:
  frontend_net:
  backend_net:
    internal: true

secrets:
  db_password:
    file: ./secrets/db_pass.txt
```

### Командный интерфейс (CLI)

Основные команды для управления жизненным циклом проекта:

- `docker compose up -d` — запуск всех сервисов в фоновом режиме.
- `docker compose watch` — запуск в режиме автоматической синхронизации кода.
- `docker compose down` — остановка и удаление контейнеров, сетей и образов проекта.
- `docker compose ps` — отображение статуса всех контейнеров в текущем проекте.
- `docker compose config` — валидация синтаксиса и вывод итоговой конфигурации.
- `docker compose logs -f` — просмотр логов всех сервисов в реальном времени.
