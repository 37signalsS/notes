# Обзор Docker Compose

## Определения

**Docker Compose** — инструмент для определения и запуска многоконтейнерных Docker-приложений с помощью одного YAML-файла (`compose.yml`). Позволяет декларативно описывать все сервисы приложения, их зависимости, сети, тома и переменные окружения.

**Ключевая идея:** вместо ручного запуска каждого контейнера отдельными командами `docker run`, вы определяете весь стек приложения в одном файле и управляете им единой командой `docker compose up`.

> **Примечание:** Современный `docker compose` — это плагин к Docker CLI (команда `docker compose`). Устаревшая версия `docker-compose` (Python-утилита) больше не поддерживается. Подробнее: [Версии Compose](./docker_compose_versions_comparison.md).

## Основные концепции

### Проблемы ручного управления контейнерами

При использовании отдельных команд `docker run` для каждого контейнера мультиконтейнерного приложения возникают следующие трудности:

- **Трудозатратность:** каждый сервис (frontend, backend, база данных, кеш) требует отдельной команды с уникальными флагами и конфигурацией
- **Порядок запуска:** приложения часто зависят друг от друга — backend не запустится без базы данных. Ручной запуск требует соблюдения правильной последовательности
- **Сетевая настройка:** необходимо вручную создавать сети (`docker network create`), подключать контейнеры, назначать DNS-имена (`--network-alias`)
- **Масштабирование:** для увеличения количества экземпляров сервиса нужно дублировать команды `docker run` с разными портами и именами
- **Управление данными:** каждый контейнер требует отдельной настройки volumes/bind mounts для персистентности данных
- **Переменные окружения:** настройка ENV-переменных для каждого контейнера через флаги `-e` ведёт к ошибкам и дублированию
- **Останов и очистка:** удаление стека требует остановки и удаления каждого контейнера отдельно, плюс ручной очистки сетей и томов

**Пример ручного запуска стека Nginx + Node.js + Redis:**

```bash
# 1. Создание сети
docker network create sample-app

# 2. Запуск Redis
docker run -d --name redis \
  --network sample-app \
  --network-alias redis \
  redis:latest

# 3. Запуск первого бэкенда
docker run -d --name web1 \
  --hostname web1 \
  --network sample-app \
  --network-alias web1 \
  -p 5001:5000 \
  web:latest

# 4. Запуск второго бэкенда
docker run -d --name web2 \
  --hostname web2 \
  --network sample-app \
  --network-alias web2 \
  -p 5002:5000 \
  web:latest

# 5. Запуск балансировщика Nginx
docker run -d --name nginx \
  --network sample-app \
  -p 80:8080 \
  enginex:latest
```

Каждый раз при развёртывании, остановке или очистке необходимо выполнять последовательность из 5+ команд. Ошибки в порядке запуска или опечатки во флагах приведут к неработоспособности стека.

### Преимущества Docker Compose

Docker Compose решает проблемы ручного управления:

- **Централизация конфигурации:** весь стек приложения описан в одном `compose.yml` файле
- **Управление зависимостями:** директива `depends_on` с `condition: service_healthy` гарантирует правильный порядок запуска. Сервис стартует только после готовности зависимостей
- **Автоматическая сеть:** Docker Compose создаёт изолированную сеть для проекта и настраивает DNS-разрешение по именам сервисов
- **Масштабирование:** запуск нескольких экземпляров сервиса одной командой (`docker compose up --scale worker=3`)
- **Персистентность данных:** volumes объявляются на уровне проекта и переиспользуются сервисами
- **Переменные окружения:** поддержка `env_file` и интерполяции переменных из `.env` файлов
- **Единый жизненный цикл:** команды `up` и `down` управляют всем стеком — запуск, остановка, удаление сетей и томов
- **Идемпотентность:** повторный запуск `docker compose up` пересоздаёт только изменённые контейнеры

### Терминология

В контексте Docker Compose используются следующие термины:

| Термин | Описание |
| :--- | :--- |
| **Сервис (Service)** | Контейнер в рамках Compose-проекта. Определяет образ, порты, тома, сети, переменные |
| **Проект (Project)** | Набор связанных сервисов, определяемых одним или несколькими compose-файлами. Имя проекта берётся из имени директории или задаётся через `name` |
| **compose.yml** | YAML-файл с декларативным описанием сервисов, сетей, томов, секретов |
| **Override-файл** | Дополнительный файл (`compose.override.yml`, `compose.prod.yml`) для переопределения базовой конфигурации |

## Практические сценарии

### Пример: ручная миграция на Docker Compose

Рассмотрим стек из примера выше (Nginx + Node.js + Redis). Эквивалентная конфигурация в `compose.yml`:

```yaml
services:
  redis:
    image: redis:latest
    networks:
      - app-network

  web1:
    build: ./web
    hostname: web1
    ports:
      - "5001:5000"
    networks:
      - app-network

  web2:
    build: ./web
    hostname: web2
    ports:
      - "5002:5000"
    networks:
      - app-network

  nginx:
    build: ./nginx
    ports:
      - "80:8080"
    networks:
      - app-network
    depends_on:
      - web1
      - web2

networks:
  app-network:
    driver: bridge
```

Запуск всего стека одной командой:

```bash
docker compose up -d --build
# → Создаётся сеть app-network
# → Собираются образы из ./web и ./nginx (если отсутствуют локально)
# → Запускаются 4 контейнера в правильном порядке
```

Остановка и очистка:

```bash
docker compose down
# → Останавливаются все контейнеры
# → Удаляются контейнеры и сеть
```

> **Примечание:** данный пример упрощён для демонстрации концепции. Production-конфигурация с healthcheck, volumes, секретами и масштабированием представлена в [Примере файла compose.yml](./docker_compose_file_example.md).

### Использование в CI/CD

Docker Compose применяется в пайплайнах сборки для развёртывания эфемерных тестовых окружений. Он позволяет поднять необходимые зависимости (базы данных, брокеры сообщений) перед запуском интеграционных тестов. Детальный разбор: [Docker Compose CI/CD Testing](./docker_compose_ci_cd_testing.md).
