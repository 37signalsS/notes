# Сравнение версий Docker Compose: от v2/v3 к Compose Spec

## Определения

**Форматы Docker Compose** прошли эволюцию от специфичных для Python-утилиты `docker-compose` версий (v2.x, v3.x) до единого стандарта **Compose Specification**.

- **Устаревший подход**: обязательное указание `version: '3.8'` в начале файла. Возможности были жестко ограничены версией схемы.
- **Современный подход (Compose Spec)**: директива `version` не обязательна. Современный `docker compose` (плагин на Go) реализует общую спецификацию, объединяющую возможности линеек 2.x и 3.x.

## Базовые концепции

### Эволюция управления зависимостями (`depends_on`)

Это наиболее частое место путаницы при переходе между версиями.

- **Версия 2.x**: поддерживала `condition: service_healthy`.
- **Ранние версии 3.x (3.0–3.3)**: поддержка `condition` была удалена. `depends_on` гарантировал только *порядок запуска*, но не *готовность* приложения. Это привело к популярности внешних скриптов вроде `wait-for-it.sh`.
- **Compose Specification**: вернула и расширила поддержку `condition`. Использование внешних скриптов-ожиданий теперь считается **антипаттерном**.

**Доступные условия (`condition`):**

- `service_started`: запуск после старта контейнера (по умолчанию).
- `service_healthy`: запуск только после успешного прохождения `healthcheck` зависимым сервисом.
- `service_completed_successfully`: ожидание успешного завершения контейнера (например, для миграций).

### Ограничение ресурсов

- **Линейка 2.x**: параметры `cpu_shares`, `mem_limit` находились в корне сервиса.
- **Линейка 3.x и Compose Spec**: параметры перенесены в секцию `deploy.resources`. Современный Docker Compose умеет применять эти лимиты даже без использования Docker Swarm.

## Практические сценарии

### Ожидание готовности базы данных (Современный метод)

Пример конфигурации, исключающий необходимость в `wait-for-it.sh`.

```yaml
services:
  database:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=secret
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
  
  web:
    build: .
    depends_on:
      database:
        condition: service_healthy
```

**Результат**: Сервис `web` не начнёт работу, пока PostgreSQL не отрапортует о полной готовности принимать соединения.
