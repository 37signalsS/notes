# Продвинутые возможности Docker Compose

## Определения

**Продвинутые возможности Docker Compose** — это набор технологий и методов для управления сложными инфраструктурными стеками, обеспечивающий гибкость конфигурации под разные окружения, минимизацию дублирования кода и оркестрацию локальных ресурсов.

## Базовые концепции

### Интерполяция переменных

Docker Compose позволяет динамически изменять значения в `compose.yml` на основе переменных окружения.

- **Синтаксис и условия:**
  - `${VAR}` — простая подстановка значения.
  - `${VAR:-default}` — подставить `default`, если переменная пуста или не задана.
  - `${VAR-default}` — подставить `default`, только если переменная не задана (пустое значение допускается).
  - `${VAR:?error}` — завершить выполнение с ошибкой `error`, если переменная не задана.

- **Приоритет источников (от высокого к низкому):**
  1. Переменные системного окружения (Shell).
  2. Переменные, заданные через флаг `--env-file` в CLI.
  3. Файлы, указанные в директиве `env_file` (поддерживается список файлов, Compose v2.24+).
  4. Файл `.env` в текущей директории.
  5. Переменные, заданные в секции `environment` сервиса (используются внутри контейнера, но не для интерполяции в самом YAML).

### Модульность через Include

Директива **`include`** (Compose v2.20+) — основной инструмент декомпозиции в современной инфраструктуре.

- **Преимущества:**
  - Полная изоляция ресурсов (сети и тома импортируемого файла не конфликтуют с текущими).
  - Поддержка относительных путей для вложенных структур.
- **Импорт из OCI-реестров:** (Compose v2.20+) Compose позволяет импортировать конфигурации, упакованные как OCI-артефакты.
  ```yaml
  include:
    - oci: my-registry.com/my-project/common-config:v1.2.0
  ```
- **Сравнение с `extends`:** В отличие от `extends`, который наследует только свойства сервиса, `include` импортирует всю инфраструктуру файла. `extends` теперь рекомендуется только для точечного переиспользования внутри одного файла.

### Расширенные поля (Extension Fields)

Расширенные поля начинаются с префикса `x-` и позволяют определять фрагменты конфигурации, которые игнорируются парсером Docker Compose, но могут использоваться через YAML-якоря.

- **Назначение:** централизованное определение общих настроек (логирование, метки, ресурсы).
- **Пример:**
  ```yaml
  x-common-labels: &labels
    project: "my-app"
    team: "devops"

  services:
    web:
      image: nginx
      labels: *labels
  ```

### Длинный синтаксис (Long Syntax)

Для точного управления ресурсами (томами, сетями, секретами) рекомендуется использовать "длинный синтаксис" вместо сокращенных строк.

- **Секреты (Secrets):** управление правами доступа и путем монтирования.
  ```yaml
  services:
    db:
      secrets:
        - source: db_password
          target: /run/secrets/pg_pass
          uid: '101'
          gid: '101'
          mode: 0400
  ```
- **Тома (Volumes):** настройка драйверов и режимов монтирования (`consistency`, `bind.propagation`).

### Профили (Profiles)

Профили позволяют объединять сервисы в логические группы, которые не запускаются автоматически при выполнении `docker compose up`.

- **Назначение:** разделение сервисов для разработки, тестирования, инструментов мониторинга или отладки внутри одного файла.
- **Пример использования:**
  ```yaml
  services:
    app:
      image: app:latest
    
    admin-panel:
      image: admin:latest
      profiles: ["admin", "tools"]
  ```
- **Запуск:** `docker compose --profile admin up -d`. Сервисы без профиля запускаются всегда.

### Работа с внешними ресурсами (External)

Для взаимодействия с инфраструктурой, созданной вне текущего проекта (например, общей сетью прокси), используются внешние ресурсы.

```yaml
services:
  web:
    networks:
      - global_proxy_net

networks:
  global_proxy_net:
    external: true
    name: common-ingress-network
```

### Секреты на этапе сборки (Build Secrets)

Для безопасной передачи конфиденциальных данных (API-ключи, токены) в процессе сборки образа без сохранения их в слоях:

```yaml
services:
  app:
    build:
      context: .
      secrets:
        - npm_token

secrets:
  npm_token:
    file: ~/.npmrc
```

## Практические сценарии

### Сценарий: Мульти-стейджинг (Dev/Prod) через наложение

Использование базового файла и специфичных переопределений для разных окружений.

1. **`compose.yml`** (базовая логика):
   ```yaml
   services:
     web:
       image: myapp:base
       ports: ["80:80"]
   ```

2. **`compose.override.yml`** (локальная разработка):
   ```yaml
   services:
     web:
       build: .
       volumes: ["./src:/app/src"]
       develop:
         watch:
           - action: sync
             path: ./src
             target: /app/src
   ```

3. **`compose.prod.yml`** (продакшн):
   ```yaml
   services:
     web:
       deploy:
         replicas: 5
         resources:
           limits:
             memory: 1G
   ```

**Запуск для продакшна:** `docker compose -f compose.yml -f compose.prod.yml up -d`
