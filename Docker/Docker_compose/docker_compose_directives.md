# Директивы Docker Compose

### Определения

**Директивы Docker Compose** — это ключевые инструкции в файле `docker-compose.yml`, которые определяют, как Docker должен управлять запуском, конфигурацией и взаимодействием многоконтейнерных приложений. Они описывают всё: от используемого образа и сетевых настроек до политик перезапуска и проверки состояния сервисов.

### Основные концепции

Ключевые директивы, используемые внутри секции `services`:

- **`image` vs. `build`**:
  - `image`: Указывает готовый образ из registry (например, `postgres:16.3`).
  - `build`: Указывает путь к `Dockerfile` для сборки образа локально (`build: .`).

- **`ports`**: Пробрасывает порты в формате `IP:ХОСТ_ПОРТ:КОНТЕЙНЕР_ПОРТ`.

- **`environment` и `env_file`**:
  - `environment`: Задает переменные окружения прямо в YAML (`environment: [ "POSTGRES_USER=user" ]`). **Не используйте для секретов.**
  - `env_file`: Загружает переменные из файла. **Предпочтительный способ.**

- **`depends_on`**: Определяет порядок запуска сервисов. В современных версиях гарантирует только последовательность запуска, но не полную готовность зависимого сервиса к работе.

- **`command` и `entrypoint`**: Позволяют переопределить инструкции `CMD` и `ENTRYPOINT` из `Dockerfile` образа. `command` заменяет `CMD`, а `entrypoint` заменяет `ENTRYPOINT`.

- **`user`**: Запускает процесс внутри контейнера от имени указанного пользователя (`user:group` или `user`). Использование `user: "0:0"` (root) может быть небезопасно.

- **`restart`**: Определяет политику перезапуска контейнера.

| Политика | Описание |
| :--- | :--- |
| `no` | Не перезапускать (по умолчанию). |
| `on-failure` | Перезапускать только при завершении с ошибкой. Можно добавить `:<число_попыток>`. |
| `always` | Перезапускать всегда, кроме случаев, когда контейнер остановлен вручную. |
| `unless-stopped` | Перезапускать всегда, даже после перезагрузки демона, кроме остановки вручную. |

- **`healthcheck`**: Позволяет Docker проверять работоспособность приложения внутри контейнера. Эта директива аналогична инструкции [`HEALTHCHECK` в `Dockerfile`](../Dockerfile/dockerfile_instructions.md#healthcheck).

### Практические сценарии

Пример файла `docker-compose.yml` для запуска веб-приложения и базы данных, демонстрирующий использование нескольких директив:

```yaml
version: '3.8'

services:
  database:
    image: postgres:16.3
    restart: unless-stopped
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=secret
      - POSTGRES_DB=app_db
    ports:
      - "127.0.0.1:5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d app_db"]
      interval: 10s
      timeout: 5s
      retries: 5

  web_app:
    build: .
    restart: on-failure:3
    ports:
      - "8000:8000"
    env_file:
      - ./.env.web
    depends_on:
      - database
    command: >
      sh -c "./wait-for-it.sh database:5432 --
             python manage.py migrate &&
             python manage.py runserver 0.0.0.0:8000"

```

В этом примере `depends_on` гарантирует, что сервис `web_app` запустится после сервиса `database`. Однако для ожидания полной готовности базы данных к приему соединений используется дополнительный скрипт `wait-for-it.sh`, который опрашивает порт `database:5432` перед выполнением миграций и запуском приложения.
