# Использование Docker Compose для тестирования в CI/CD

## Определения

При использовании Docker Compose в конвейерах непрерывной интеграции/непрерывного развертывания (CI/CD) возникает задача адекватного управления жизненным циклом тестовых сервисов. По умолчанию `docker compose up` запускает сервисы в фоновом режиме и работает бесконечно, что не подходит для CI/CD. Цель состоит в том, чтобы запустить задачу (например, тесты), дождаться ее завершения, получить код завершения (для определения успеха или провала) и корректно остановить все связанные сервисы.

## Базовые концепции

Для достижения этой цели используется комбинация флагов `docker compose up`:

### `--exit-code-from <имя-сервиса>`

Этот флаг указывает `docker compose` возвращать **код завершения (exit code)** от указанного сервиса. Это критически важно для CI/CD, так как системы сборки ориентируются на код завершения для определения успеха шага.

### `--abort-on-container-exit`

Этот флаг предписывает `docker compose` остановить **все** контейнеры, как только **любой** из них остановится. Это гарантирует, что вспомогательные сервисы (базы данных, кэши) не будут продолжать работать после завершения тестов, обеспечивая чистоту среды выполнения.

## Практические сценарии

### Пример: Запуск интеграционных тестов

Рассмотрим сценарий, где веб-сервис `web` взаимодействует с базой данных `db`, и нам необходимо запустить интеграционные тесты.

**Файл `compose.yml` (базовая конфигурация):**

```yaml
services:
  web:
    build: .
    depends_on:
      - db
    environment:
      - DB_HOST=db

  db:
    image: postgres:16
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
```

**Файл `compose.test.yml` (переопределение для тестов):**

```yaml
services:
  web:
    # Переопределяем команду по умолчанию на запуск тестов
    command: ["npm", "test"]
```

**Команда для запуска в CI/CD:**

```bash
docker compose -f compose.yml -f compose.test.yml up \
  --build \
  --abort-on-container-exit \
  --exit-code-from web
```

**Пояснение:**

* `-f ...`: Загружает и объединяет обе конфигурации.
* `--build`: **Критически важный флаг в CI.** Гарантирует, что образ будет пересобран с последними изменениями из репозитория, а не взят из кэша. Это обеспечивает тестирование актуального кода.
* `--abort-on-container-exit`: Остановит `db` и `web` сразу после завершения тестовой команды в `web`.
* `--exit-code-from web`: Передаст код завершения от `web` (успех/провал тестов) как код завершения всей команды `docker compose`.

После выполнения этой команды система CI/CD может проверить код завершения: `0` — успех, ненулевое значение — провал.

## Дополнительная информация

### Сравнение с Testcontainers

| Критерий | Docker Compose | Testcontainers |
|---|---|---|
| **Управление** | CLI, декларативно | Программно, из кода тестов |
| **Изоляция** | Общие контейнеры на все тесты | Отдельные контейнеры на каждый тест |
| **Жизненный цикл** | Ручной или через CLI | Автоматический (до/после тестов) |
| **Параметризация** | Через env и volumes | Динамическая, из кода |
| **Когда использовать** | Локальное тестирование, простые сценарии | Интеграционные тесты в CI/CD |

Подробнее о Testcontainers см. в [обзоре Testcontainers](../../Testing/testcontainers_overview.md). Общие практики интеграции тестов в CI/CD описаны в [интеграции тестов в CI/CD](../../Testing/testing_cicd_integration.md).
