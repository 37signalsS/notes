# Использование Docker Compose для тестирования в CI/CD

## Определения

При использовании Docker Compose в конвейерах непрерывной интеграции/непрерывного развертывания (CI/CD) возникает задача адекватного управления жизненным циклом тестовых сервисов. По умолчанию `docker compose up` запускает сервисы в фоновом режиме и работает бесконечно, что не подходит для CI/CD. Цель состоит в том, чтобы запустить задачу (например, тесты), дождаться ее завершения, получить код завершения (для определения успеха или провала) и корректно остановить все связанные сервисы.

## Базовые концепции

Для достижения этой цели используется комбинация двух флагов `docker compose up`:

### Флаг `--exit-code-from <имя-сервиса>`

Этот флаг указывает `docker compose` возвращать **код завершения (exit code)** от указанного сервиса. Это критически важно для CI/CD, так как системы сборки ориентируются на код завершения команды для определения успешности или неудачи шага.

* Если сервис, указанный во флаге (например, сервис с тестами), завершается с кодом `0` (успех), то и вся команда `docker compose up` завершится с кодом `0`.
* Если сервис завершается с ненулевым кодом (например, `1` в случае ошибки тестов), то и команда `docker compose up` вернет этот ненулевой код, сигнализируя об ошибке в конвейере CI/CD.

### Флаг `--abort-on-container-exit`

Этот флаг предписывает `docker compose` остановить **все** контейнеры в проекте, как только **любой** из них остановится. Это гарантирует, что вспомогательные сервисы (например, базы данных, кэши и т.п.) не будут продолжать работать после того, как тестовый сервис завершит свою работу. Это обеспечивает чистоту среды выполнения и предотвращает утечки ресурсов, что особенно важно в динамических средах CI/CD.

## Практические сценарии

### Пример: Запуск интеграционных тестов

Рассмотрим сценарий, где у нас есть веб-сервис `web`, который взаимодействует с базой данных `db`, и нам необходимо запустить интеграционные тесты для `web`.

**Файл `docker-compose.yml` (базовая конфигурация):**

```yaml
services:
  web:
    build: .
    depends_on:
      - db
    environment:
      - DB_HOST=db

  db:
    image: postgres:16.3
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
```

**Файл `docker-compose.test.yml` (переопределение для запуска тестов):**

Для запуска тестов мы используем отдельный файл переопределения, который изменяет команду по умолчанию для сервиса `web` на команду запуска тестов.

```yaml
services:
  web:
    # Переопределяем команду по умолчанию на запуск тестов
    command: ["npm", "test"]
```

**Команда для запуска в CI/CD:**

Объединив базовую конфигурацию и переопределение для тестов, а также используя упомянутые флаги, мы получаем команду, идеально подходящую для среды CI/CD:

```bash
docker compose -f docker-compose.yml -f docker-compose.test.yml up --build --abort-on-container-exit --exit-code-from web
```

**Пояснение:**

* `docker compose -f docker-compose.yml -f docker-compose.test.yml`: Загружает и объединяет обе конфигурации.
* `up --build`: Запускает сервисы, при необходимости собирая образ для `web`.
* `--abort-on-container-exit`: Остановит `db` и `web` сразу после завершения тестовой команды в `web`.
* `--exit-code-from web`: Передаст код завершения сервиса `web` (результат выполнения тестов) как код завершения всей команды `docker compose`.

После выполнения этой команды ваша система CI/CD может проверить код завершения:

* **`0`**: Тесты прошли успешно.
* **Ненулевое значение**: Тесты провалились.
