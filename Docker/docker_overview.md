# Обзор Docker — платформа контейнеризации

## Определения

- **Docker:** Платформа для разработки, доставки и запуска приложений в контейнерах. Использует механизмы изоляции ядра Linux для создания легковесных, переносимых окружений.
- **Контейнер (Container):** Изолированный экземпляр образа, запускающий один процесс (точку входа) в изолированной среде. Включает в себя код, среду выполнения, системные библиотеки и настройки.
- **Образ (Image):** Неизменяемый многослойный шаблон, служащий чертежом для создания контейнеров. Каждый слой соответствует инструкции в `Dockerfile` и реализуется через механизм Copy-on-Write.
- **Реестр (Registry):** Сервис для хранения и распространения образов (Docker Hub, Harbor, GitHub Packages).
- **Docker Engine:** Основной программный компонент, работающий по клиент-серверной архитектуре (демон `dockerd`, API и CLI).
- **containerd:** Высокоуровневая среда выполнения (runtime), управляющая жизненным циклом контейнеров, скачиванием образов и сетевым взаимодействием.

## Основные концепции

### Решение проблемы зависимостей и изоляция

Docker упаковывает приложение вместе с его окружением, устраняя конфликты версий библиотек между разными сервисами и хост-системой. Изоляция обеспечивается на уровне:
1. **Внутренней среды:** Все зависимости фиксированы внутри образа.
2. **Внешних ресурсов:** Доступ к сети, портам и файловой системе строго контролируется через конфигурацию запуска.

### Ключевые преимущества

1.  **Согласованность (Consistency):** Гарантия идентичного поведения приложения на всех этапах жизненного цикла (разработка, тестирование, продакшн).
2.  **Эффективность ресурсов:** Контейнеры используют общее ядро ОС, запускаются за миллисекунды и потребляют значительно меньше ресурсов по сравнению с виртуальными машинами.
3.  **Изоляция:** Каждый контейнер работает в собственном пространстве имен, что повышает безопасность и предотвращает влияние процессов друг на друга.
4.  **Масштабируемость:** Малый размер образов и высокая скорость запуска позволяют динамически изменять количество экземпляров приложения под нагрузку.

### Архитектура и компоненты (2025–2026)

Современная архитектура Docker модульная и соответствует стандартам **OCI (Open Container Initiative)**.

```
docker CLI ←[REST API]→ dockerd ←[gRPC]→ containerd → runc/crun/wasmer → контейнер
```

- **Docker CLI:** Интерфейс командной строки для взаимодействия с пользователем.
- **dockerd (Docker Daemon):** Обеспечивает высокоуровневое управление (сети, тома, API), делегируя работу с процессами нижестоящим компонентам.
- **containerd:** Проект CNCF, управляющий образами и жизненным циклом контейнеров. Начиная с версии 2.0+ (Docker 29.1+), использует **containerd image store** по умолчанию, что обеспечивает нативную совместимость с Kubernetes.
- **runc / crun:** Низкоуровневые рантаймы, создающие пространства имен (namespaces) и контрольные группы (cgroups). `crun` (на языке C) является более быстрым и эффективным аналогом стандартного `runc`.
- **BuildKit / Buildx:** Современный движок сборки, поддерживающий параллельное выполнение стадий, расширенное кэширование и мультиплатформенные сборки.

### Технологии изоляции ядра Linux

Функционирование контейнеров базируется на трех фундаментальных механизмах ядра:

1.  **Namespaces (Пространства имен):** Виртуализируют системные ресурсы для процесса (`pid`, `net`, `mnt`, `ipc`, `uts`, `user`). Подробнее см. **[Изоляция в Linux: Namespaces и Cgroups](./Concepts/linux_isolation.md)**.
2.  **Cgroups v2 (Контрольные группы):** Ограничивают и учитывают потребление ресурсов (CPU, RAM, I/O), предотвращая «захват» всей системы одним контейнером.
3.  **Union File Systems (OverlayFS):** Объединяют слои образа в единую файловую систему. Реализуют механизм **Copy-on-Write (CoW)** — данные копируются в записываемый слой контейнера только при необходимости их модификации.

### Слоеная файловая система и хранение

Образы Docker состоят из неизменяемых слоев (Read-Only). При запуске контейнера сверху добавляется записываемый слой (Writable Layer).
- **Эффективность:** Слои переиспользуются между разными образами, что экономит место на диске.
- **Lazy Pulling:** Поддержка «ленивой загрузки» образов в современных рантаймах позволяет запускать контейнер до того, как весь образ будет физически скачан.

## Практические сценарии

### Анализ процесса запуска (docker run)

При выполнении `docker run -it --rm ubuntu:24.04 bash` происходят следующие этапы:
1. **Pull:** Поиск образа локально или скачивание из реестра.
2. **Create:** Создание файловой системы контейнера через `containerd`.
3. **Network:** Настройка сетевого стека (IP, интерфейсы, маршруты).
4. **Start:** Запуск процесса через `runc` внутри изолированных пространств имен.

### Сравнение с виртуальными машинами

| Характеристика | Контейнеры | Виртуальные машины |
|:---|:---|:---|
| **Абстракция** | Уровень ОС (Shared Kernel) | Аппаратный уровень (Hypervisor) |
| **Изоляция** | Уровень процессов (Namespaces) | Полная (Гостевая ОС) |
| **Вес образа** | Десятки/сотни МБ | Гигабайты |
| **Накладные расходы** | Минимальные | Значительные (ресурсы на гостевую ОС) |

**Когда использовать:**
- **Контейнеры:** микросервисы, CI/CD, высокая плотность размещения приложений.
- **ВМ:** полная изоляция на уровне ядра, запуск приложений на другой ОС, работа с монолитами, требующими прямого доступа к ядру.

### Рабочий процесс сборки и доставки

1.  **Написание `Dockerfile`:** Описание желаемого состояния образа.
2.  **Сборка (Build):** Использование `docker buildx` для создания многослойного артефакта.
3.  **Публикация (Push):** Отправка образа в централизованный реестр.
4.  **Развертывание (Run):** Запуск контейнеров на целевых хостах.

## Дополнительная информация

### Инструменты и альтернативы

- **Docker Desktop:** Полноценная среда для разработки с поддержкой K8s и Docker Scout.
- **Rootless Docker:** Режим запуска без привилегий суперпользователя (повышение безопасности).
- **Docker Scout:** Интегрированная система анализа безопасности, SBOM и поиска уязвимостей.
- **Colima / OrbStack:** Альтернативные рантаймы для macOS/Linux.
