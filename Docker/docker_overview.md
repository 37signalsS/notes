# Обзор Docker

## Определения

- **Docker:** Платформа для разработки, доставки и запуска приложений в контейнерах. Использует механизмы изоляции ядра Linux для создания легковесных, переносимых окружений.
- **Контейнер:** Изолированный экземпляр образа, запускающий один процесс (точку входа) в изолированной среде (от других контейнеров и хост-системы). Включает всё необходимое для запуска ПО: код, среду выполнения, библиотеки и настройки.
- **Образ (Image):** Неизменяемый многослойный шаблон с кодом, библиотеками и системными инструментами. Служит чертежом для создания контейнеров. Каждый слой образа соответствует определённой инструкции в `Dockerfile`.
- **Реестр (Registry):** Хранилище образов (Docker Hub, Harbor, GitLab Registry).
- **Docker Engine:** Клиент-серверное приложение, включающее демон `dockerd`, API и CLI.
- **containerd:** Стандартная среда выполнения (runtime) жизненного цикла контейнеров. С версии 29.1 является основным хранилищем образов (containerd image store) по умолчанию.

## Основные концепции

### Проблема зависимостей и изоляция

Docker решает фундаментальную проблему "на моей машине работает", упаковывая приложение вместе со всем его окружением. Изоляция достигается на двух уровнях:
1. **Внутренние зависимости:** Библиотеки, рантаймы (JRE, Python), конфигурационные файлы упакованы в образ.
2. **Внешние ресурсы:** Доступ к сети, портам и файловой системе хоста явно ограничивается и "пробрасывается" только при необходимости.

### Ключевые преимущества

1.  **Согласованность (Consistency):** Гарантия идентичной работы приложения в dev, test и prod окружениях («работает одинаково везде»).
2.  **Эффективность ресурсов:** Контейнеры используют общее ядро ОС, они легкие, запускаются за секунды и потребляют значительно меньше памяти, чем виртуальные машины.
3.  **Изоляция:** Каждый контейнер работает в своей изолированной среде, что минимизирует риски взаимодействия с другими процессами и повышает безопасность.
4.  **Масштабируемость:** Благодаря малому размеру и быстрому запуску, контейнеры легко масштабируются вверх или вниз в зависимости от нагрузки.
5.  **Портативность и быстрое развертывание:** Один и тот же образ работает на локальном ноутбуке и в облаке; развертывание занимает считанные секунды.

### Архитектура и компоненты

Современный Docker (2026+) базируется на модульной архитектуре, полностью интегрированной со стандартами OCI и CNCF.

```
docker CLI ←[REST API]→ dockerd ←[gRPC]→ containerd → runc/crun/wasmer → контейнер
```

- **Docker CLI:** Командный интерфейс, отправляющий команды демону.
- **dockerd (Docker Daemon):** Высокоуровневый менеджер, управляющий сетями, томами и API.
- **containerd:** Управляет скачиванием образов и их выполнением. С версии 29.1 заменяет старые "graph drivers" (overlay2) на унифицированное хранилище.
- **runc / crun:** Низкоуровневые среды выполнения, создающие namespaces и cgroups.
- **Wasm Runtime:** Позволяет запускать WebAssembly-модули напрямую через Docker.

### Технологии изоляции (Linux Kernel Features)

Использование контейнеров стало возможным благодаря трем ключевым функциям ядра Linux:

1.  **Namespaces (Пространства имен):** Обеспечивают изоляцию процессов. Основные типы: `pid` (процессы), `net` (сеть), `mnt` (файловая система), `ipc` (межпроцессное взаимодействие), `uts` (имена хостов) и `user` (пользователи).
2.  **Cgroups v2 (Контрольные группы):** Отвечают за лимиты ресурсов. Ограничивают потребление CPU, RAM, I/O и защищают систему от монополизации ресурсов одним контейнером.
3.  **Union File Systems (OverlayFS):** Позволяют объединять несколько файловых систем в одну, реализуя механизм **Copy-on-Write (CoW)** для эффективного хранения и изменения слоев образов.

Подробнее: **[Изоляция в Linux: Namespaces и Cgroups](./Concepts/linux_isolation.md)**.


### Слоеная файловая система (OverlayFS)

Образы Docker состоят из слоев, доступных только для чтения. При запуске контейнера сверху добавляется тонкий записываемый слой (writable layer).
- **Многослойность:** Каждая инструкция в `Dockerfile` создает новый уровень. Это делает создание и распространение образов эффективным, так как при обновлении необходимо скачивать или передавать только измененные слои.
- **Принцип Copy-on-Write (CoW):** Если файл из образа нужно изменить, он копируется в записываемый слой контейнера.
- **containerd image store (v29+):** Поддерживает нативную мультиплатформенность и "ленивую загрузку" (lazy pulling), позволяя контейнеру стартовать до завершения скачивания всего образа.

Подробнее: **[OverlayFS в Docker](./Docker_fs/docker_overlayfs.md)**.

## Практические сценарии

### Разбор запуска контейнера (docker run)

Команда `docker run -it --rm ubuntu:24.04 bash` выполняет следующие шаги:
1. **Pull:** Проверка локального кэша и скачивание образа, если он отсутствует.
2. **Create:** Создание структуры контейнера в хранилище (containerd store).
3. **Network:** Выделение IP-адреса и настройка виртуального сетевого интерфейса.
4. **Start:** Вызов рантайма (`runc`), создание namespaces и запуск процесса `bash`.

**Флаги:**
- `-i`: Интерактивный режим (STDIN).
- `-t`: Выделение псевдо-терминала (TTY).
- `--rm`: Автоматическое удаление контейнера после завершения процесса.

### Контейнеры против Виртуальных машин

Ключевое различие заключается в **уровне абстракции**:
- **Виртуальные машины** абстрагируют **аппаратный уровень**. Гипервизор создает виртуальное оборудование, на котором работает полноценная гостевая ОС со своим ядром, библиотеками и системными процессами. Это делает ВМ «тяжелыми» и медленными в загрузке.
- **Контейнеры** абстрагируют **уровень операционной системы**. Они работают на общем ядре хостовой ОС и упаковывают только код приложения и его специфические зависимости. Отсутствие необходимости загружать ядро ОС делает их легкими, быстрыми (запуск за секунды) и эффективными по ресурсам.

| Характеристика | Контейнеры | Виртуальные машины |
|:---|:---|:---|
| **Уровень абстракции** | Операционная система (Shared Kernel) | Аппаратное обеспечение (Hypervisor) |
| **Изоляция** | Уровень процессов (Namespaces) | Уровень ОС (Полная изоляция) |
| **Скорость запуска** | Секунды | Минуты |
| **Потребление ресурсов** | Минимальное | Высокое (накладные расходы на ОС) |
| **Вес образа** | Мегабайты | Гигабайты |

#### Когда использовать

- **Контейнеры:** микросервисы, быстрое и последовательное развертывание, высокая масштабируемость, эффективное использование ресурсов CI/CD.
- **Виртуальные машины:** запуск приложений на разных типах ОС, необходимость в полной изоляции на уровне ядра, запуск монолитных приложений, требующих всех ресурсов ОС.

Подробное сравнение: **[Контейнеры vs Виртуальные машины](../Linux/Virtualization/virtualization_overview.md)**.

### Рабочий процесс контейнеризации

Контейнеризация — это процесс упаковки приложения и его зависимостей в стандартизированный образ. Базовый рабочий процесс (workflow) состоит из трех этапов:

1.  **Создание `Dockerfile`:** Текстовый файл-инструкция, содержащий все команды, необходимые для сборки образа (от базовой ОС до установки зависимостей и кода).
2.  **Сборка образа (Build):** Использование Docker CLI для преобразования `Dockerfile` в исполняемый образ (используя `docker build`).
3.  **Запуск контейнера (Run):** Создание и запуск живого экземпляра (контейнера) из образа (`docker run`).

Этот процесс гарантирует, что приложение будет работать идентично в любой среде — от ноутбука разработчика до продакшн-кластера.

## Дополнительная информация

### Docker Desktop и альтернативы

- **Docker Desktop:** GUI-платформа для Windows/macOS/Linux с интегрированным Kubernetes и Docker Scout.
- **Colima / OrbStack:** Легковесные альтернативы для macOS.
- **Rootless Docker:** Запуск без демона с правами root, стандарт безопасности для многопользовательских систем.

### Безопасность (Docker Scout)

Docker перестал быть просто рантаймом и стал платформой анализа. **Docker Scout** (интегрирован в CLI) позволяет анализировать SBOM (Software Bill of Materials) и уязвимости образов на лету.
