# Обзор команд Docker CLI

## 1. Управление жизненным циклом контейнера

### Определения

- **Жизненный цикл контейнера**: Процесс от создания и запуска до остановки и удаления контейнера.
- **Интерактивные команды**: Команды, позволяющие взаимодействовать с запущенным контейнером.

### Основные команды

#### Создание, запуск и остановка

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker run <образ>` | Создает и запускает контейнер. | `-d` (фоновый режим), `--rm` (удалить после завершения). |
| `docker start <контейнер>` | Запускает остановленный контейнер. | |
| `docker stop <контейнер>` | Корректно останавливает контейнер. | Сначала `SIGTERM`, затем `SIGKILL`. |
| `docker restart <контейнер>` | Перезапускает контейнер. | |
| `docker pause / unpause` | "Замораживает" и "размораживает" процессы. | |
| `docker rm <контейнер>` | Удаляет остановленный контейнер. | `-f` для принудительного удаления запущенного контейнера. |

#### Взаимодействие с контейнером

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker exec -it <контейнер> <команда>` | Выполняет команду внутри контейнера. | Например, `docker exec -it my-container bash`. |
| `docker attach <контейнер>` | Подключается к основному процессу (PID 1). | Для отсоединения без остановки: **`Ctrl+P`, `Ctrl+Q`**. |
| `docker cp <откуда> <куда>` | Копирует файлы между хостом и контейнером. | `docker cp my-container:/app/log.txt .` |
| `docker update <контейнер>` | Динамически обновляет ресурсы (CPU, память, I/O) запущенного контейнера **без его остановки**. Это крайне полезно в production-среде. |

### Продвинутые детали

#### `docker stop` vs `docker pause`

- **`docker pause`** "замораживает" все процессы в контейнере. Состояние процессов сохраняется в оперативной памяти, но они перестают потреблять CPU. Используйте эту команду, чтобы временно освободить процессорные ресурсы, не теряя текущего состояния приложения.

- **`docker stop`** инициирует корректное завершение работы контейнера, отправляя процессу сигнал `SIGTERM`. Если процесс не завершается сам за 10 секунд, Docker принудительно "убивает" его сигналом `SIGKILL`. Память и CPU полностью освобождаются. Это стандартный способ остановить контейнер.

#### Подключение к контейнеру (`attach`)

Команда `docker attach` подключает ваш терминал к стандартному вводу/выводу/ошибкам (STDIN/STDOUT/STDERR) основного процесса (PID 1) в контейнере.

```sh
docker attach <container_name>
```

**Важно:** Если вы выйдете из сессии `attach` с помощью `Ctrl+C`, это отправит сигнал `SIGKILL` и остановит контейнер. Чтобы отсоединиться, не останавливая контейнер, используйте последовательность `Ctrl+P`, `Ctrl+Q`.

#### Динамическое обновление ресурсов (`update`)
В production-среде контейнер может потреблять слишком много RAM. Для ограничения памяти без остановки используйте `docker update --memory 1G my-container` (где `1G` — новый лимит памяти). Также можно использовать `--cpus`, `--cpu-shares` и другие флаги.

## 2. Управление образами

### Определения

- **Образ (Image)**: Неизменяемый шаблон, содержащий все необходимое для запуска приложения.
- **Тег (Tag)**: Метка-алиас, обычно обозначающая версию образа (например, `1.2.0`, `latest`).
- **Слой (Layer)**: Часть файловой системы образа, создаваемая одной инструкцией в `Dockerfile`.

### Основные команды

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker images` или `docker image ls` | Показывает все образы на хосте. | |
| `docker build -t <имя образа>:<тег> .` | Собирает образ из `Dockerfile`. | |
| `docker pull <образ>:<тег>` | Скачивает образ из registry. | |
| `docker push <образ>:<тег>` | Загружает образ в registry. | |
| `docker rmi <образ>` | Удаляет образ. | |
| `docker tag <source> <target>` | Создает новый тег (алиас) для образа. | `docker tag my-app:1.0 my-repo/my-app:1.0` |
| `docker history <образ>` | Показывает слои, из которых состоит образ. | Полезно для анализа и оптимизации `Dockerfile`. |

### Продвинутые детали

#### Анализ слоев образа (`history`)

Команда `docker history` показывает все слои, из которых состоит образ, их размер и команды, которыми они были созданы. Это очень полезный инструмент для отладки и оптимизации `Dockerfile`, так как он позволяет выявить "тяжелые" слои или ненужные файлы, добавленные в процессе сборки.

**Пример вывода:**
```
IMAGE          CREATED         CREATED BY                                      SIZE      COMMENT
a2491d99c52f   3 weeks ago     /bin/sh -c #(nop)  CMD ["/bin/sh"]              0B
<missing>      3 weeks ago     /bin/sh -c #(nop) ADD file:7d565a58bb...       5.53MB
```

## 3. Инспекция и мониторинг

### Определения

- **Инспекция**: Процесс получения детальной низкоуровневой информации об объектах Docker.
- **Мониторинг**: Процесс наблюдения за метриками производительности и логами работающих контейнеров.

### Основные команды

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker ps` | Показывает запущенные контейнеры. | `-a` для отображения всех контейнеров. |
| `docker logs <контейнер>` | Показывает логи. | `-f` (в реальном времени), `--tail N` (последние N строк). |
| `docker inspect <контейнер>` | Выводит подробную информацию в JSON. | Получить IP-адрес: `-f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'` |
| `docker stats <контейнер>` | Показывает потребление ресурсов в реальном времени. | |
| `docker top <контейнер>` | Показывает процессы внутри контейнера. | |
| `docker port <контейнер>` | Отображает маппинг портов. | |

### Продвинутые детали

#### Детальная инспекция объектов (`inspect`)

Команда `docker inspect` предоставляет исчерпывающую информацию о любом объекте Docker (контейнере, образе, томе, сети) в формате JSON. Это мощный инструмент для отладки и автоматизации.

С помощью флага `-f` (`--format`) и синтаксиса Go-шаблонов можно извлекать конкретные поля из JSON-вывода.

**Пример: Получение IP-адреса контейнера**
```bash
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' my-container
```

## 4. Управление сетями и томами

### Определения

- **Сеть (Network)**: Обеспечивает сетевую изоляцию и возможность коммуникации между контейнерами.
- **Том (Volume)**: Механизм для персистентного хранения данных вне жизненного цикла контейнера.

### Основные команды

| Команда | Описание | Примеры / Примечания |
| :--- | :--- | :--- |
| `docker network ls` | Показывает сети. | |
| `docker network inspect <сеть>` | Выводит подробную информацию о сети. | |
| `docker network create <сеть>` | Создает новую сеть (например, `bridge`). | |
| `docker volume ls` | Показывает тома. | |
| `docker volume inspect <том>` | Выводит подробную информацию о томе. | |
| `docker volume create <том>` | Создает именованный том. | |

### Дальнейшее изучение

## 5. Управление и очистка системы

### Определения

- **Очистка (Prune)**: Процесс удаления неиспользуемых объектов Docker (контейнеров, образов, томов, сетей) для освобождения дискового пространства.

### Основные команды

| Команда | Описание |
| :--- | :--- |
| `docker container prune` | Удаляет все остановленные контейнеры. |
| `docker image prune` | Удаляет "висячие" (dangling) образы. |
| `docker image prune -a` | Удаляет все неиспользуемые образы (не только висячие). |
| `docker volume prune` | Удаляет все неиспользуемые (не привязанные к контейнерам) тома. |
| `docker network prune` | Удаляет все неиспользуемые (не используемые контейнерами) сети. |
| `docker system prune` | **Основная команда.** Удаляет все неиспользуемые объекты: остановленные контейнеры, висячие образы, неиспользуемые сети. |
| `docker system prune -a --volumes` | **(Опасно)** Глобальная очистка: удаляет всё, что не используется — контейнеры, все неиспользуемые образы, сети и тома. |

### Продвинутые детали: "Висячие" образы (Dangling Images)

**"Висячие" образы (dangling images)** — это слои образа, которые существуют на хосте, но на них больше не ссылается ни один тегированный образ. В выводе команды `docker images` они обычно отображаются с именем и тегом `<none>:<none>`.

Эти образы являются промежуточными и возникают, когда существующий образ пересобирается. Docker не удаляет старые слои автоматически, так как они могут быть частью кэша сборки или использоваться другими образами.

**Основные причины появления:**

1.  **Пересборка образа с тем же тегом:** Когда вы собираете новый образ из `Dockerfile` с тем же тегом, что и у существующего (`docker build -t my-app:latest .`). Новый образ получает этот тег, а старый образ, который теперь не имеет тега, становится "висячим".
2.  **Промежуточные слои:** Во время сборки `Dockerfile` Docker создает временные слои для каждой инструкции. Если сборка прерывается или последующие инструкции делают эти слои ненужными, они могут остаться без ссылок.
3.  **Изменение базового образа:** Если вы обновили версию базового образа в инструкции `FROM` и пересобрали свое приложение, старые слои, зависимые от предыдущего базового образа, могут стать "висячими".

**Практические сценарии:**

"Висячие" образы безвредны, но занимают дисковое пространство. Их рекомендуется периодически удалять.

- **Как найти "висячие" образы:**
  ```bash
  docker images -f "dangling=true"
  ```

- **Как удалить "висячие" образы:**
  Самый простой способ — использовать команду `docker image prune`.
  ```bash
  docker image prune
  ```
  Эта команда специально предназначена для поиска и удаления всех "висячих" образов.
