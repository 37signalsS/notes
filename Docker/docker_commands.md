# Команды Docker CLI

## Определения

- **Docker CLI:** Интерфейс командной строки для управления всеми компонентами экосистемы Docker (контейнеры, образы, сети, тома).
- **Docker API:** REST-интерфейс, через который CLI взаимодействует с демоном `dockerd`.
- **Контекст (Context):** Набор параметров подключения к конкретному экземпляру Docker (локальному или удаленному).

## Основные концепции

### Идентификация объектов

Для большинства команд можно использовать либо **имя** (`--name`), либо **ID**. Для ID достаточно указать первые 3–12 символов, если они уникальны.

```bash
# Остановка по ID (достаточно префикса)
docker stop a1f
# → a1f

# Остановка по имени
docker stop my-web-app
# → my-web-app
```

### Публикация портов (Port Mapping)

Связывает порт хоста с портом внутри контейнера.
- Формат: `-p <хост>:<контейнер>`
- **Важно:** Приложение внутри контейнера должно слушать именно тот порт, который указан в правой части маппинга.

```bash
# Проброс 8080 на 80 порт Nginx
docker run -d -p 8080:80 nginx
# → result: контейнер запущен, доступен по http://localhost:8080

# Проверка маппинга
docker port <container_name>
# → 80/tcp -> 0.0.0.0:8080
```

### Автоматизация скелета проекта (Docker Init)

Современный способ быстро создать необходимые файлы (`Dockerfile`, `.dockerignore`, `compose.yaml`) для нового проекта.

```bash
# Запуск интерактивного помощника
docker init
# → result: создание конфигурационных файлов на основе анализа исходного кода
```

## Практические сценарии

### 1. Управление жизненным циклом контейнеров

| Команда | Описание | Пример вывода |
|:---|:---|:---|
| `docker run -d <image>` | Создать и запустить в фоне | `a1f74...` (Full ID) |
| `docker stop <container>` | Корректная остановка (SIGTERM) | `my-container` |
| `docker rm -f <container>` | Принудительное удаление | `my-container` |
| `docker exec -it <id> sh` | Интерактивный вход в контейнер | `/app #` |
| `docker logs -f <id>` | Слежение за логами в реальном времени | `[INFO] Application started` |

### 2. Сборка и управление образами

Современный стандарт сборки — **Buildx**. Он поддерживает мультиплатформенность и расширенные проверки.

```bash
# Проверка Dockerfile перед сборкой (Build Checks)
docker buildx build --check .
# → result: список предупреждений о неоптимальных инструкциях

# Сборка под несколько архитектур
docker buildx build --platform linux/amd64,linux/arm64 -t my-app:latest .
```

Подробнее: **[Docker Buildx: Мультиплатформенная сборка](./Dockerfile/docker_buildx.md)**.

### 3. Безопасность и аудит (Docker Scout)

Анализ уязвимостей (CVE) и рекомендации по оптимизации базовых образов.

```bash
# Краткий отчет по безопасности образа
docker scout quickview nginx:latest
# → result: 0 critical, 2 high, 15 medium vulnerabilities

# Поиск конкретных CVE
docker scout cves nginx:latest
# → result: подробный список уязвимостей с ID и описанием
```

### 4. Отладка сложных случаев (Docker Debug)

Позволяет войти в контейнер, даже если в нем нет оболочки (например, Distroless-образы), предоставляя встроенный инструментарий (`vim`, `curl`, `htop`).

```bash
# Запуск отладочной оболочки в работающем контейнере
docker debug <container_id>
# → result: запуск изолированной среды с инструментами администрирования
```

Подробнее об отладке "пустых" образов: **[Debugging Distroless](./Docker_troubleshooting/debugging_distroless.md)**.

### 5. Ограничение и мониторинг ресурсов

| Флаг / Команда | Описание | Пример использования |
|:---|:---|:---|
| `--memory 512m` | Лимит RAM | `docker run -m 512m ...` |
| `--cpus 0.5` | Лимит CPU (в ядрах) | `docker run --cpus 0.5 ...` |
| `docker stats` | Потребление в реальном времени | `CPU %: 12.5, MEM: 100MiB` |

```bash
# Динамическое обновление лимитов без перезапуска
docker update --memory 1g --cpus 1.0 my-running-container
# → my-running-container
```

### 6. Переменные окружения и секреты

```bash
# Передача переменных через флаги
docker run -e DB_USER=admin -e DB_PASS=secret my-app

# Загрузка из файла
docker run --env-file production.env my-app
```

**Безопасность:** Не передавайте пароли через `-e` в production, используйте механизмы секретов. См. **[Управление секретами](./Docker_security/secrets_management.md)**.

### 7. Очистка системы

Освобождение дискового пространства от неиспользуемых данных.

```bash
# Удаление всех неиспользуемых данных (включая неиспользуемые образы)
docker system prune -a
# → result: Total reclaimed space: 1.2GB

# Удаление только "зависших" (dangling) слоев
docker image prune
```

## Дополнительная информация

### Политики перезапуска (--restart)

Определяют поведение контейнера при падении процесса или перезагрузке хоста:
- `no`: Не перезапускать (по умолчанию).
- `on-failure`: Только если код выхода не равен 0.
- `always`: Всегда перезапускать.
- `unless-stopped`: Перезапускать всегда, если контейнер не был остановлен вручную (**рекомендуется для prod**).

### Работа с контекстами

Позволяет управлять удаленными серверами так же просто, как локальным Docker.

```bash
# Список доступных подключений
docker context ls

# Переключение на удаленный сервер (через SSH)
docker context use remote-vps
```

Подробнее: **[Docker Context: Удаленное управление](./docker_context.md)**.

### Различия stop vs pause

- **Stop:** Отправляет `SIGTERM`, процесс завершается, ресурсы (RAM) освобождаются.
- **Pause:** Использует `cgroups freezer`, процесс "замораживается" в текущем состоянии, RAM **не освобождается**, CPU не потребляется.
