# Команды Docker CLI

## Определения

- **Docker CLI:** Интерфейс командной строки для управления всеми компонентами экосистемы Docker (контейнеры, образы, сети, тома, AI-модели).
- **Docker API:** REST-интерфейс, через который CLI взаимодействует с демоном `dockerd`. В версии v28+ API оптимизирован для уменьшения объема JSON-ответов (пропуск пустых полей).
- **Контекст (Context):** Набор параметров подключения к конкретному экземпляру Docker (локальному или удаленному).
- **Gordon:** Встроенный AI-ассистент Docker для генерации Dockerfile и отладки ошибок.

## Основные концепции

### Идентификация объектов

Для большинства команд можно использовать либо **имя** (`--name`), либо **ID**. Для ID достаточно указать первые 3–12 символов, если они уникальны.

```bash
# Остановка по ID (достаточно префикса)
docker stop a1f
# → a1f
```

### Публикация портов и сетевая безопасность (v28+)

Связывает порт хоста с портом внутри контейнера.
- Формат: `-p <хост>:<контейнер>`
- **Важно (v28+):** По умолчанию Docker блокирует доступ к любым портам, которые не были явно опубликованы через `-p`. Трафик к неопубликованным портам сбрасывается (DROP).
- Для возврата к старому поведению (не рекомендуется) используется флаг `--ip-forward-no-drop`.

### Инициализация проекта (docker init)

Современный способ быстро создать необходимые файлы (`Dockerfile`, `.dockerignore`, `compose.yaml`) для нового проекта. Подробнее см. **[Инициализация проекта: docker init](./docker_init.md)**.

```bash
# Запуск интерактивного помощника
docker init
# → result: создание конфигурационных файлов на основе анализа исходного кода
```

## Практические сценарии

### 1. Управление жизненным циклом контейнеров

| Команда | Описание | Пример вывода / Результат |
|:---|:---|:---|
| `docker run -d <image>` | Создать и запустить в фоне | `a1f74...` (Full ID) |
| `docker stop <container>` | Корректная остановка (SIGTERM) | `my-container` |
| `docker rm -f <container>` | Принудительное удаление | `my-container` |
| `docker exec -it <id> sh` | Интерактивный вход в контейнер | `/app #` |
| `docker logs -f <id>` | Слежение за логами в реальном времени | `[INFO] Application started` |
| `docker inspect <id>` | Получение детальной информации (JSON) | `{ "Id": "...", ... }` |

### 2. Сборка и управление образами

Современный стандарт сборки — **Buildx** с использованием **containerd image store** (удаление старых graphdrivers в v28).

```bash
# Проверка Dockerfile перед сборкой (Build Checks)
docker buildx build --check .
# → result: список предупреждений о неоптимальных инструкциях

# Визуализация иерархии слоев (v27+)
docker image ls --tree
# → result: дерево слоев и платформ

# Очистка образов
docker image prune -a
```

### 3. Работа с AI-моделями (Docker Model CLI)

Начиная с 2025 года, Docker поддерживает запуск LLM локально как нативных артефактов.

```bash
# Установка движка инференса
docker model install-runner

# Загрузка и запуск модели в режиме чата
docker model run ai/smollm2
# → ai/smollm2: Hello! How can I help you today?

# Список загруженных моделей
docker model ls
```

### 4. Управление сетями и томами

| Команда | Описание | Пример использования |
|:---|:---|:---|
| `docker network create` | Создать виртуальную сеть | `docker network create my-net` |
| `docker network ls` | Список всех сетей | `NAME: bridge, DRIVER: bridge` |
| `docker volume create` | Создать именованный том | `docker volume create pg_data` |
| `docker volume ls` | Список томов | `DRIVER: local, VOLUME NAME: pg_data` |

### 5. Безопасность и аудит (Docker Scout)

```bash
# Краткий отчет по безопасности образа
docker scout quickview nginx:latest
# → result: 0 critical, 2 high, 15 medium vulnerabilities

# Интеграция с AI-агентами (MCP)
docker agent serve mcp
# → result: запуск сервера для интеграции с AI-клиентами (Claude/Gemini)
```

### 6. Отладка и диагностика (docker debug)

Позволяет войти в контейнер, даже если в нем нет оболочки (Distroless), предоставляя встроенный инструментарий (`vim`, `curl`, `htop`).

```bash
# Запуск отладочной оболочки с поддержкой AI
docker debug <container_id>

# Внутри debug-сессии (запрос к помощнику Gordon)
ai "Почему база данных не отвечает?"
```

### 7. Мониторинг и лимиты ресурсов

| Флаг / Команда | Описание | Пример использования |
|:---|:---|:---|
| `--memory 512m` | Лимит RAM | `docker run -m 512m ...` |
| `--cpus 0.5` | Лимит CPU (в ядрах) | `docker run --cpus 0.5 ...` |
| `docker stats` | Потребление в реальном времени | `CPU %: 12.5, MEM: 100MiB` |
| `docker system df` | Анализ использования диска | `Images: 1.2GB, Containers: 50MB` |

## Дополнительная информация

### Политики перезапуска

- `no`: Не перезапускать (по умолчанию).
- `on-failure`: Только если код выхода не равен 0.
- `always`: Всегда перезапускать.
- `unless-stopped`: Перезапускать всегда, если контейнер не был остановлен вручную (**рекомендуется для prod**).

### Управление контекстами

```bash
# Список доступных подключений
docker context ls

# Создание контекста для удаленного сервера через SSH
docker context create remote-srv --docker "host=ssh://user@host"
```

### Различия между stop и pause

- **Stop:** Отправляет `SIGTERM` (или сигнал из `STOPSIGNAL`), процесс завершается, ресурсы освобождаются.
- **Pause:** Использует `cgroups freezer`, процесс "замораживается", память (RAM) **не освобождается**.
