# Harbor: Обзор реестра

## Определения

* **Harbor**: Open-source реестр контейнерных образов с расширенными возможностями для корпоративного использования. Разработан компанией VMware, с 2018 года находится под эгидой CNCF.
* **Проект (Project)**: Логическое пространство имен в Harbor для группировки образов. Аналог репозитория в Docker Hub. Проекты могут быть публичными или приватными.
* **Робот-аккаунт (Robot Account)**: Специальная учётная запись для автоматизации доступа к Harbor из CI/CD-систем. Имеет ограниченные права и срок действия.
* **Репликация (Replication)**: Механизм автоматической синхронизации образов между несколькими инстансами Harbor или другими реестрами.

## Основные концепции

Harbor предоставляет функциональность частного реестра с расширенными возможностями для корпоративного использования. В отличие от базовых реестров (Docker Registry), Harbor включает встроенные инструменты безопасности и управления.

### Ключевые возможности

| Возможность | Назначение |
| :--- | :--- |
| **Управление доступом (RBAC)** | Проекты, пользователи и роли для гранулярного контроля доступа |
| **Сканирование уязвимостей** | Интеграция с Trivy/Clair для автоматического анализа образов на CVE |
| **Подпись образов** | Обеспечение целостности через Notary или Cosign |
| **Репликация** | Синхронизация между инстансами Harbor для геораспределённых команд |
| **Хранение Helm-чартов** | Единое хранилище для Docker-образов и Helm-пакетов |
| **Веб-интерфейс** | UI для управления проектами, пользователями и образами |
| **Аудит** | Детальное логирование всех действий пользователей |

### Проект `library`

При установке Harbor автоматически создаёт публичный проект `library`. Образы в этом проекте доступны для скачивания (`pull`) без аутентификации, но для загрузки (`push`) требуются права администратора или участника проекта. Удобно для хранения общих или вспомогательных образов.

### Архитектура безопасности

Harbor реализует многоуровневую защиту:

1. **Аутентификация**: Поддержка локальной БД, LDAP/AD, OIDC.
2. **Авторизация**: Ролевая модель (Admin, Developer, Guest, Maintainer).
3. **Сканирование**: Автоматическая проверка образов при push или по расписанию.
4. **Подпись**: Криптографическая верификация происхождения образов.
5. **Секреты**: Робот-аккаунты с ограниченным сроком жизни для CI/CD.

## Практические сценарии

### Сценарий 1: Выбор редакции Harbor

| Редакция | Назначение |
| :--- | :--- |
| **Docker Compose** | Тестовые среды, небольшие развертывания на одном хосте |
| **Helm (Kubernetes)** | Продакшен-среды, масштабируемые кластеры с внешними БД и кэшем |

Подробности см. в [установке Harbor](./installation.md).

### Сценарий 2: Настройка доступа для CI/CD

Для автоматизации используйте робот-аккаунты:

1. Создайте робот-аккаунт в UI Harbor (Project → Robot Accounts → New Robot Account).
2. Выберите права (push, pull, scan) и срок действия.
3. Используйте сгенерированный токен в CI/CD:

```bash
docker login harbor.example.com -u 'robot$<имя>' -p '<токен>'
```

### Сценарий 3: Работа с образами

**Аутентификация:**

```bash
docker login harbor.example.com
# Username: admin
# Password: <YourAdminPassword>
```

**Тегирование и отправка:**

```bash
docker tag my-app:latest harbor.example.com/library/my-app:v1
docker push harbor.example.com/library/my-app:v1
```

**Получение образа:**

```bash
docker pull harbor.example.com/library/my-app:v1
```

Подробнее см. в [работе с Harbor](./usage.md).

### Сценарий 4: Оффлайн-режим

Для закрытых контуров без доступа к интернету:

1. Отключите автоматическое обновление Trivy (`skip_update: true`).
2. Вручную загрузите базы уязвимостей на машину с интернетом.
3. Перенесите базы на изолированный хост Harbor.

Инструкция см. в [оффлайн-обновлении Trivy](./offline_trivy_update.md).
