# Harbor: Обзор реестра

## Определения

* **Harbor**: Open-source реестр артефактов корпоративного уровня. Входит в состав проектов CNCF (Cloud Native Computing Foundation) со статусом Graduated.
* **Проект (Project)**: Основная единица организации в Harbor. Группирует репозитории, пользователей и политики. Может быть публичным или приватным.
* **OCI-реестр (Open Container Initiative Registry)**: Реестр, поддерживающий спецификации OCI для хранения не только образов контейнеров, но и Helm-чартов, SBOM, сигнатур и других артефактов.
* **Proxy Cache**: Режим работы проекта, при котором Harbor выступает прозрачным прокси-сервером для внешних реестров (Docker Hub, Quay), кэшируя артефакты локально.
* **P2P Дистрибуция**: Технология распределения образов между узлами кластера минуя центральный реестр (интеграция с Dragonfly или Kraken), что критично для крупных инсталляций.

## Основные концепции

Harbor расширяет возможности стандартного Docker Registry, предоставляя инструменты для управления безопасностью, жизненным циклом и производительностью доставки артефактов.

### Ключевые возможности

| Возможность | Назначение |
| :--- | :--- |
| **Управление доступом (RBAC)** | Гибкая ролевая модель для пользователей и групп (LDAP/AD, OIDC) |
| **Сканирование уязвимостей** | Анализ образов на наличие CVE с помощью Trivy (основной сканер) |
| **Управление SBOM** | Генерация, хранение и визуализация Software Bill of Materials для артефактов |
| **Proxy Cache** | Ускорение загрузки из внешних реестров и обход лимитов (например, Docker Hub Rate Limit) |
| **Репликация** | Синхронизация данных между разными инстансами Harbor (Push/Pull модели) |
| **Политики очистки** | Автоматическое удаление старых тегов (Retention) и сборка мусора (GC) |
| **Неизменяемые теги** | Запрет перезаписи (overwrite) определенных тегов для обеспечения стабильности сред |
| **P2P Дистрибуция** | Интеграция с внешними системами для ускорения доставки на тысячи узлов |

### Проектная модель

Вся работа в Harbor строится вокруг проектов. Проект определяет:
1. **Доступ**: Кто может скачивать и загружать образы.
2. **Безопасность**: Порог уязвимостей, при котором блокируется `docker pull`.
3. **Квоты**: Лимиты на объем дискового пространства и количество образов.
4. **Retention**: Правила автоматического удаления (например, «хранить 10 последних тегов»).

### Архитектура безопасности

Harbor реализует концепцию доверенного реестра через:
* **Аутентификацию**: Интеграция с корпоративными системами идентификации.
* **Доверие (Content Trust)**: Подпись образов через Cosign или Notary.
* **Изоляцию**: Робот-аккаунты для CI/CD с ограниченными привилегиями и временем жизни.
* **Аудит**: Логирование всех операций с артефактами (кто, когда и какой образ скачал/запушил).

## Практические сценарии

### Развертывание в различных окружениях

Harbor является гибким инструментом и может быть развернут как на одном сервере через Docker Compose (для малых сред), так и в кластере Kubernetes через Helm (для высокодоступных систем).
Подробности см. в [установке Harbor](./installation.md).

### Интеграция в CI/CD пайплайны

Типовое использование включает автоматическую сборку образов, их сканирование в Harbor и последующую доставку в K8s. Harbor выступает в роли «врат безопасности», не позволяя образам с критическими уязвимостями попасть в Production.
Примеры команд и настройки доступа см. в [работе с Harbor](./usage.md).

### Работа в изолированных сетях (Air-gapped)

В закрытых контурах Harbor становится центральным узлом для хранения всех доверенных образов. Для поддержания актуальности баз уязвимостей используется механизм оффлайн-обновления.
Инструкции см. в [обновлении Trivy](./offline_trivy_update.md).
