# Harbor: Обзор

**Harbor** — это бесплатный open-source реестр для хранения Docker-образов, запущенный в 2016 году командой VMware. В 2018 году Harbor перешел под контроль организации [CNCF](../../../Kubernetes/kubernetes_overview.md) и с тех пор активно развивается (новые релизы выходят несколько раз в месяц). Он предоставляет функциональность частного реестра с расширенными возможностями для корпоративного использования, включая сканирование образов на уязвимости.

## Ключевые возможности Harbor

* **Управление доступом (RBAC)**: Проекты, пользователи и роли для гранулярного контроля доступа. Подходит для больших команд с разграничением полномочий.
* **Проект `library` по умолчанию**: При установке Harbor автоматически создает публичный проект с именем `library`. Образы в этом проекте доступны для скачивания (`pull`) без аутентификации, однако для загрузки (`push`) требуются права администратора или участника проекта. Это удобно для хранения общих или вспомогательных образов.
* **Хранение артефактов**: Помимо Docker-образов, Harbor может хранить [Helm-чарты](https://helm.sh/), обеспечивая единое место для всех артефактов Kubernetes.
* **Сканирование уязвимостей**: Интеграция со сканерами (например, Trivy, Clair) для автоматического анализа образов на известные уязвимости.
* **Подпись образов**: Обеспечение целостности и происхождения образов с помощью Notary или Cosign.
* **Репликация**: Автоматическая синхронизация образов между несколькими инстансами Harbor (например, для геораспределенных команд).
* **Веб-интерфейс**: Удобный UI для управления проектами, пользователями и образами.
* **Аудит**: Детальное логирование всех действий пользователей.

## Назначение Harbor

В то время как Docker Hub удобен для публичного хранения образов, большинство компаний предпочитают хранить свои контейнерные образы приватно на собственных серверах. Harbor разработан для решения этой задачи, особенно в условиях закрытого контура компании (без доступа к интернету). Данное руководство фокусируется именно на такой установке, где ключевыми отличиями являются настройка переменных для отключения автоматического обновления сканера уязвимостей Trivy и необходимость ручного обогащения его баз.
