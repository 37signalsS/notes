# Безопасность при работе с публичными registry

Публичные registry упрощают доставку образов, но открывают вектор атаки на цепочку поставки. Основные угрозы: подмена образа, «typo‑squatting» (похожие имена репозиториев), уязвимые зависимости, утечка секретов в слоях, использование изменяемых тегов.

## Ключевые понятия

-   **Digest** — криптографический идентификатор слоя/образа (sha256), гарантирующий неизменность содержимого.
-   **Подпись образа** — криптографическое подтверждение издателя и целостности (Docker Content Trust/Notary, OCI‑подписи, cosign).
-   **SBOM (Software Bill of Materials)** — перечень компонентов образа, необходимый для оценки уязвимостей и соответствия требованиям.

## Практики минимизации рисков

1.  **Фиксация на digest, а не тег.** Теги изменяемы, digest неизменен.
2.  **Использование подписей** и проверка издателя (DCT/Notary, cosign, OCI‑подписи).
3.  **Сканы уязвимостей** до допуска в CI/CD и на этапе «admission» в кластере.
4.  **Белые списки registry** и пространств имён (namespace) с контролем, кто может добавлять источники.
5.  **Локальный proxy‑кэш/зеркало** (Harbor/Nexus) с политиками: запрет mutable‑тегов, автоматический рескан, блокировка по тяжести CVE.
6.  **Предпочтение официальных и верифицированных репозиториев**, минимальных баз (alpine, distroless) и регулярные обновления.
7.  **Управление метаданными**: хранение SBOM и аттестаций (provenance) рядом с образом.
8.  **Исключение секретов из слоёв**; проверка слоёв на наличие ключей и токенов.

## Примеры практик в командах

-   **Фиксация на digest и отказ от `latest`**:

    ```bash
    # Получить digest и зафиксировать
    docker pull nginx:1.25
    docker inspect --format='{{index .RepoDigests 0}}' nginx:1.25
    # Использовать в манифестах/Compose:
    # image: nginx@sha256:2a1d...c9e
    ```

-   **Включение Docker Content Trust** для обязательной проверки подписей издателя:

    ```bash
    export DOCKER_CONTENT_TRUST=1
    docker pull docker.io/library/nginx:1.25
    # Неподписанные образы будут отклонены
    ```

-   **Проверка OCI‑подписи с помощью cosign**:

    ```bash
    # Проверка подписи публичным ключом
    cosign verify --key cosign.pub ghcr.io/org/app:1.4.3
    # Верификация аттестаций (например, SBOM)
    cosign verify-attestation --type=spdx --key cosign.pub ghcr.io/org/app:1.4.3
    ```

-   **Сканирование на уязвимости (пример с Trivy)**:

    ```bash
    trivy image --severity HIGH,CRITICAL --ignore-unfixed 
      --exit-code 1 ghcr.io/org/app@sha256:2a1d...c9e
    ```

## Политики в CI/CD и на платформе

-   Разрешать образы только из утверждённых registry и namespace.
-   Требовать подписи и успешную проверку аттестаций (provenance, SBOM).
-   Отклонять сборки/деплой при наличии критических CVE.
-   Применять «immutable tags» на зеркале и хранить «golden images» с неизменными digest.
-   Логирование всех pull/push событий, аудит изменений политик и ключей подписи.

## Таблица сопоставления рисков и мер

| Риск | Меры контроля |
| :--- | :--- |
| Подмена/изменение образа | Pull по digest, DCT/Notary, cosign |
| Typo‑squatting | Allowlist namespace, код‑ревью источников |
| Уязвимости в слоях | Обязательный скан, регулярные обновления |
| Секреты внутри образа | Скан секретов, процессы сборки без секретов |
| Drift тега `latest` | Запрет `latest`, только семвер + digest |
| Непрозрачность состава | SBOM и аттестации, хранение рядом с образом |
