# Обзор системы логирования в Docker

## Определения

**Лог-драйвер (Logging Driver)** — это встроенный в Docker Engine механизм, который перехватывает стандартные потоки вывода контейнера (`STDOUT` и `STDERR`) и направляет их в указанное место назначения. Этот механизм позволяет отделить логику приложения от логики сбора и отправки логов.

## Базовые концепции

В основе системы логирования Docker лежит принцип **"приложение пишет в стандартные потоки"**. Приложение внутри контейнера не должно заботиться о файлах логов; оно просто отправляет весь вывод в `STDOUT` и `STDERR`. Docker Engine, в свою очередь, через настроенный лог-драйвер решает, что с этим выводом делать.

Существует две фундаментальные архитектуры сбора логов:

1. **Агентный сбор (Agent-based)**
    * **Принцип**: Docker использует локальный драйвер (`json-file` или `local`) для записи логов в файлы на хост-машине. Отдельное приложение-агент (например, Vector, Filebeat, Fluentd) отслеживает эти файлы и отвечает за их обработку и надежную доставку в централизованную систему хранения (Loki, Elasticsearch).
    * **Схема**: `Приложение → STDOUT → Docker Engine (`json-file`) → Локальный файл → Агент → Система хранения`
    * **Подробное руководство**: **[Агентный сбор логов Docker](./docker_agent_based_logging.md)**

2. **Прямая отправка (Driver-mediated)**
    * **Принцип**: Docker Engine использует специализированный лог-драйвер (`loki`, `fluentd`, `syslog`), который напрямую отправляет логи по сети в систему агрегации.
    * **Схема**: `Приложение → STDOUT → Docker Engine (драйвер`loki`) → Система хранения`
    * **Подробное руководство**: **[Централизованное логирование: Лог-драйверы](./docker_centralized_logging.md)**

## Практические сценарии

### Сравнение архитектур

| Критерий | Агентный сбор (рекомендуемый) | Прямая отправка через драйвер |
| :--- | :--- | :--- |
| **Надежность** | **Высокая.** Логи сначала сохраняются на диск. Агент обеспечивает буферизацию и повторные попытки отправки, предотвращая потерю данных при сбоях сети или системы хранения. | **Низкая/Средняя.** Большинство сетевых драйверов работают в блокирующем режиме. При недоступности приемника контейнер может "зависнуть", либо логи будут утеряны (зависит от настроек). |
| **Производительность** | Нагрузка на Docker daemon минимальна. Основную работу выполняет отдельный процесс-агент. | Увеличивает нагрузку на Docker daemon, так как он сам занимается сериализацией и отправкой логов по сети. |
| **Гибкость** | **Высокая.** Агенты позволяют выполнять сложную фильтрацию, обогащение и маршрутизацию логов перед отправкой. | **Ограниченная.** Возможности по обработке логов определяются конкретным лог-драйвером и обычно минимальны. |
| **Простота настройки**| Средняя. Требует развертывания и настройки дополнительного компонента (агента). | Высокая. Настраивается только `daemon.json` или параметры `docker run`. |
| **Совместимость** | Полная. Работает с любыми системами хранения, которые поддерживает агент. | Ограничена набором существующих лог-драйверов. |

## Дополнительная информация

### Совместимость с командой `docker logs`

Возможность использовать команду `docker logs` напрямую зависит от выбранного лог-драйвера. Она работает только с теми драйверами, которые кэшируют или хранят логи локально на хосте.

* **Работает с**: `json-file` (по умолчанию), `local`, `journald`.
* **Не работает с**: `fluentd`, `syslog`, `gelf`, `loki`, `awslogs` и другими драйверами-экспортерами. При их использовании `docker logs` вернет ошибку, так как Docker daemon больше не имеет доступа к потоку логов после его отправки в стороннюю систему.
