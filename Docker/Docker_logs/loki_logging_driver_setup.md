# Настройка драйвера логирования Loki для Docker

Чтобы отправлять логи из Docker-контейнеров напрямую в Loki, можно использовать официальный плагин (драйвер логирования) от Grafana Labs. Этот подход позволяет организовать централизованный сбор логов без необходимости устанавливать на хост дополнительные агенты вроде Promtail или Fluentd.

## 1. Установка плагина Loki

Плагин необходимо установить на каждой Docker-ноде, с которой вы хотите собирать логи.

```bash
docker plugin install grafana/loki-docker-driver:latest --alias loki --grant-all-permissions
```

*   `docker plugin install ...`: Команда для установки плагинов в Docker.
*   `grafana/loki-docker-driver:latest`: Имя плагина. Рекомендуется указывать конкретную версию вместо `latest` для production-систем.
*   `--alias loki`: Задает короткое и удобное имя (`loki`) для драйвера, которое будет использоваться в конфигурациях.
*   `--grant-all-permissions`: Предоставляет плагину необходимые права для работы.

Проверить установленные плагины можно командой `docker plugin ls`.

## 2. Настройка сервиса в Docker Compose

После установки плагина вы можете настроить любой сервис в `docker-compose.yml` на его использование.

Для этого используется секция `logging`. Чтобы не дублировать конфигурацию для каждого сервиса, удобно определить её один раз с помощью YAML-якорей.

```yaml
# docker-compose.yml для вашего приложения

version: '3.8'

x-default-logging: &default-logging
  driver: loki # Используем установленный плагин
  options:
    loki-url: "http://<IP_АДРЕС_LOKI_СЕРВЕРА>:3100/loki/api/v1/push"
    loki-batch-size: "400"
    loki-retries: "3"
    loki-max-backoff: "1s"
    loki-timeout: "1s"

services:
  my-app:
    image: my-app-image:latest
    logging: *default-logging # Применяем конфигурацию логирования
    # ... другие настройки сервиса

  my-database:
    image: postgres:14
    logging: *default-logging # Применяем ту же конфигурацию
    # ... другие настройки сервиса
```

### Объяснение конфигурации:

*   **`x-default-logging: &default-logging`**: Определяет YAML-якорь с именем `default-logging`.
*   **`driver: loki`**: Указывает, что нужно использовать драйвер с алиасом `loki`.
*   **`options`**:
    *   **`loki-url`**: Полный URL-адрес эндпоинта Loki для приема логов. Замените `<IP_АДРЕС_LOKI_СЕРВЕРА>` на IP вашего сервера мониторинга, где запущен Loki.
    *   **`loki-batch-size`**: Размер пачки логов (в байтах), которая будет отправляться за один раз.
    *   **`loki-retries`**: Количество попыток повторной отправки в случае ошибки.
    *   **`loki-max-backoff`**: Максимальное время ожидания между попытками.
    *   **`loki-timeout`**: Таймаут для отправки логов.
*   **`logging: *default-logging`**: Применяет созданный якорь к сервису.

## 3. Просмотр логов в Grafana

После перезапуска ваших сервисов с новой конфигурацией логирования (`docker-compose up -d --force-recreate`), драйвер начнет отправлять все, что пишется в `STDOUT` и `STDERR` контейнеров, в Loki.

Чтобы просмотреть логи:

1.  Откройте Grafana.
2.  Перейдите в раздел **Explore**.
3.  Выберите источник данных **Loki**.
4.  Используйте "Log-браузер" (`Log browser`) для фильтрации логов по меткам, которые драйвер добавляет автоматически (например, `container_name`, `filename`, `job`).
5.  Или напишите запрос на языке LogQL, например: `{job="<имя_проекта_docker_compose>"}`.

Этот метод является простым и эффективным способом наладить централизованное логирование для Docker-окружения.
