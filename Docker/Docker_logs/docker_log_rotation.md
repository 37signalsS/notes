# Ротация логов Docker

При использовании драйверов логирования, которые сохраняют логи на хост-машине (например, `json-file` или `local`), важно настроить ротацию логов, чтобы предотвратить переполнение дискового пространства. Для этого можно использовать стандартную утилиту `logrotate`.

Вот пример конфигурации `logrotate` для логов Docker:

```ini
/var/lib/docker/containers/*/*.log {
    rotate 5
    daily
    copytruncate
    missingok
    compress
    # size 5M
    # dateext
    # create 644 root root
}
```

**Пояснения к параметрам:**

-   `/var/lib/docker/containers/*/*.log`: Указывает путь к файлам логов Docker. Звездочки (`*`) используются для обработки логов всех контейнеров.
-   `rotate 5`: Хранить до 5 старых файлов логов.
-   `daily`: Производить ротацию ежедневно.
-   `copytruncate`: **Критически важный параметр для Docker-логов.** Он указывает `logrotate` сначала скопировать текущий файл логов, затем обрезать (очистить) оригинал. Это позволяет Docker-демону продолжать писать в тот же файловый дескриптор, не требуя его перезапуска. Без `copytruncate` `logrotate` переместит оригинальный файл, и Docker продолжит писать в несуществующий файл, фактически теряя логи до перезапуска контейнера или Docker-демона.
-   `missingok`: Не выдавать ошибку, если файл логов отсутствует.
-   `compress`: Сжимать ротированные файлы логов для экономии места.
-   `# size 5M`: (Закомментировано в примере) Альтернативный параметр: ротировать файл, если его размер превысит 5 МБ, независимо от параметра `daily`.
-   `# dateext`: (Закомментировано в примере) Добавлять к имени ротированного файла текущую дату (например, `myapp.log-20230101`).
-   `# create 644 root root`: (Закомментировано в примере) Создавать новый пустой файл с указанными правами и владельцем после ротации.

**Рекомендация:** Создайте отдельный файл конфигурации `logrotate` (например, `/etc/logrotate.d/docker-logs`) с этим содержимым.
