# Управление ротацией логов Docker

## Определения

**Ротация логов** — процесс управления файлами журналов для предотвращения их бесконтрольного роста. Включает архивацию, сжатие и удаление старых записей для экономии дискового пространства.

## Базовые концепции

По умолчанию Docker использует драйвер `json-file`, который записывает логи в JSON-формате на диск. **Критическая проблема:** по умолчанию Docker не ограничивает размер этих файлов. Без настройки ротации логи могут занять все свободное место, что приведет к отказу системы.

### Основные драйверы для локального хранения
*   **`json-file`**: Дефолтный драйвер. Хранит логи в текстовом виде. Требует явной настройки ротации.
*   **`local`**: Рекомендуемый драйвер (с версии 20.10+). Оптимизирован для производительности, хранит логи в бинарном формате и **имеет ротацию по умолчанию** (100MB, 5 файлов).

## Практические сценарии

### Сценарий 1: Глобальная настройка через `daemon.json` (Рекомендуемый)

Настройка в файле `/etc/docker/daemon.json` применяется ко всем **новым** контейнерам.

**Пример конфигурации для `json-file`:**
```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3",
    "compress": "true"
  }
}
```

*   `max-size`: Максимальный размер одного файла (например, `10m`, `100m`).
*   `max-file`: Количество хранимых архивных файлов.
*   `compress`: Сжатие (gzip) старых логов (настоятельно рекомендуется).

**Применение изменений:**
1.  Перезапустить Docker: `sudo systemctl restart docker` # → OK.
2.  **Важно:** Настройки не применяются к уже запущенным контейнерам. Их необходимо пересоздать:
    ```bash
    docker-compose up -d --force-recreate
    ```

**Проверка текущих лимитов контейнера:**
```bash
docker inspect --format '{{.HostConfig.LogConfig}}' <container_id>
# → {json-file map[max-file:3 max-size:10m]}
```

### Сценарий 2: Настройка для конкретного контейнера

Если для отдельного сервиса нужны уникальные лимиты, их можно задать при запуске.

**Через Docker CLI:**
```bash
docker run -d \
  --log-driver json-file \
  --log-opt max-size=10m \
  --log-opt max-file=3 \
  nginx
```

**Через Docker Compose:**
```yaml
services:
  web:
    image: nginx
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "5"
```

### Сценарий 3: Экстренная очистка логов

Если диск уже переполнен, можно обнулить файлы логов без остановки контейнеров:

```bash
# Обнуление всех json-логов
sudo truncate -s 0 /var/lib/docker/containers/*/*-json.log
```

## Дополнительная информация

### Высокая нагрузка и режим `non-blocking`

В высоконагруженных системах запись логов может блокировать работу приложения. Для предотвращения этого используется режим `non-blocking`:

```json
"log-opts": {
  "mode": "non-blocking",
  "max-buffer-size": "4m"
}
```
*Внимание: в этом режиме при переполнении буфера новые логи будут отбрасываться для сохранения работоспособности приложения.*

### Сравнение подходов к ротации

| Критерий | Встроенная ротация Docker | Внешний `logrotate` |
| :--- | :--- | :--- |
| **Надежность** | **Высокая.** Работает на уровне ядра Docker. | **Средняя.** Риск потери данных при `copytruncate`. |
| **Производительность** | **Высокая.** Нет лишних операций копирования. | **Низкая.** Нагрузка на I/O при обработке больших файлов. |
| **Удобство** | Централизованно в `daemon.json`. | Требует настройки внешних конфигов. |
| **Особенности** | Ротация только по размеру. | Гибкая настройка по дате, скрипты `post-rotate`. |

**Итог:** Для 99% случаев используйте встроенный механизм Docker. `logrotate` полезен только при специфических требованиях к периодичности (например, «строго раз в сутки»).
