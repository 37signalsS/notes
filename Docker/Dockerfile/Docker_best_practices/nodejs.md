# Dockerfile: Лучшие практики для Node.js

## Определения

- **`package.json`:** Манифест проекта, описывающий его атрибуты и зависимости.
- **`package-lock.json`:** Файл, который "замораживает" дерево зависимостей, записывая точные версии каждого установленного пакета.
- **`npm ci` (Clean Install):** Команда, которая удаляет `node_modules` и устанавливает зависимости **строго** в соответствии с `package-lock.json`. Гарантирует воспроизводимость сборок.
- **`dependencies`:** Зависимости, необходимые для работы приложения в production (например, `express`, `axios`).
- **`devDependencies`:** Зависимости, необходимые только для разработки и тестирования (например, `typescript`, `jest`, `eslint`).

## Основные концепции

### Концепция 1: Воспроизводимость сборок

Для production-сборок **всегда следует использовать `npm ci` вместо `npm install`**.

- **`npm install`**: Может изменять `package-lock.json`, если `package.json` был обновлен. Это удобно для локальной разработки, но опасно для CI/CD, так как сборки становятся непредсказуемыми.
- **`npm ci`**: Гарантирует **детерминированную и воспроизводимую сборку**. Команда устанавливает зависимости, точно совпадающие с версиями в `package-lock.json`, и никогда не изменяет этот файл. Если `package.json` и `package-lock.json` не синхронизированы, `npm ci` завершится с ошибкой, предотвращая сборку с некорректными зависимостями.

### Концепция 2: Минимизация образа

Флаг `--only=production` (или переменная окружения `NODE_ENV=production`) указывает `npm` устанавливать **только** пакеты из раздела `dependencies`. Это критически важно для Docker-образов, так как исключает ненужные инструменты разработки (`devDependencies`), делая итоговый образ значительно меньше и безопаснее. Эта практика реализуется с помощью многоэтапной сборки.

## Практический сценарий: Оптимизированный Dockerfile

Этот пример демонстрирует **многоэтапную сборку** для типичного Node.js-приложения, которое требует компиляции (например, TypeScript, React, Vue).

```dockerfile
# --- Этап 1: Сборка (Builder) ---
# На этом этапе используется полный образ, содержащий все devDependencies для сборки.
FROM node:22-alpine AS builder
WORKDIR /app

# Кешируем зависимости
COPY package.json package-lock.json ./
RUN npm ci

# Копируем исходники и собираем production-билд
COPY . .
RUN npm run build

# --- Этап 2: Финальный образ (Final) ---
# Начинаем с чистого, легковесного образа
FROM node:22-alpine
WORKDIR /app

# Создаем непривилегированного пользователя для повышения безопасности
RUN adduser -D nonroot
USER nonroot

# Копируем package.json, чтобы установить ТОЛЬКО production-зависимости
COPY package.json package-lock.json ./
RUN npm ci --only=production

# Копируем скомпилированное приложение из этапа "builder"
COPY --from=builder /app/dist ./dist

EXPOSE 3000
CMD [ "node", "dist/index.js" ]
```

1. **Этап `builder`:**
    - Устанавливаются **все** зависимости, включая `devDependencies`.
    - Выполняется команда `npm run build` для компиляции TypeScript в JavaScript, сборки фронтенда и т.д.
2. **Этап `final`:**
    - Создается **[непривилегированный пользователь](./security.md)**.
    - Устанавливаются **только** `dependencies`, необходимые для запуска. `devDependencies` (компиляторы, линтеры) не попадают в конечный образ.
    - Результат сборки (папка `dist`) копируется из `builder`-а.
    - В итоге получается минималистичный и безопасный образ.
