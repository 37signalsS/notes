# Dockerfile: Лучшие практики для Go

## Определения

- **Статически скомпонованный бинарник (Statically Linked Binary):** Исполняемый файл, который содержит в себе все необходимые библиотеки и не зависит от разделяемых библиотек в операционной системе. Это делает его полностью переносимым.

## Основные концепции

### Подход к созданию образов для Go

Экосистема Go идеально подходит для **[многоэтапных сборок](./build_optimization.md)**. Благодаря способности компилятора Go создавать полностью автономные статические бинарники, стандартным паттерном является:

1. **Этап "builder":** Использование полного `golang` образа, содержащего SDK и все инструменты для компиляции и сборки зависимостей.
2. **Этап "final":** Копирование единственного скомпилированного бинарника в минималистичный финальный образ, такой как **[`scratch`](./security.md)** или **[`distroless`](./security.md)**.

### Проблема совместимости `glibc` и `musl`

При многоэтапной сборке, когда на этапе сборки используется стандартный дистрибутив (например, `golang:1.26-bookworm` на базе Debian с `glibc`), а на финальном — `alpine` (который использует `musl libc`), может возникнуть ошибка `no such file or directory`. Это происходит из-за несовместимости системных библиотек. Решение — компиляция полностью статического бинарника с флагами `-ldflags '-extldflags "-static"'`.

## Практические сценарии

### Сценарий 1: Сборка с `scratch` (Максимальная минимальность)

Это идеальный выбор для полностью статических бинарников. Образ будет содержать только ваше приложение и ничего лишнего, обеспечивая минимальный размер и поверхность атаки. Подробнее о выборе минималистичных базовых образов см. **[Безопасность в Dockerfile](./security.md)**.

```dockerfile
# --- Этап 1: Сборка бинарного файла (builder) ---
FROM golang:1.26-alpine AS builder
# Устанавливаем git для скачивания приватных модулей, если нужно
RUN apk update && apk add --no-cache git
# Создаем непривилегированного пользователя
RUN adduser -D -u 10001 appuser
WORKDIR /app
COPY go.mod go.sum ./
# Кешируем зависимости
RUN go mod download
RUN go mod verify
COPY . .
# Собираем статически скомпонованный бинарник без C-зависимостей
# -ldflags "-w -s" удаляет отладочную информацию и символы, уменьшая размер
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags "-w -s" -o /app/main .

# --- Этап 2: Финальный образ ---
# Начинаем с абсолютно пустого образа
FROM scratch
# Копируем информацию о пользователе из builder-а, чтобы USER работало
COPY --from=builder /etc/passwd /etc/passwd
COPY --from=builder /etc/group /etc/group
# Копируем только скомпилированный бинарник
COPY --from=builder /app/main /main
# Переключаемся на непривилегированного пользователя
USER appuser
EXPOSE 9292
ENTRYPOINT ["/main"]
```

### Сценарий 2: Сборка с `distroless` (Прагматичный выбор)

`distroless`-образы — отличный компромисс. Они немного больше, чем `scratch`, но включают базовые вещи, которые могут понадобиться приложению, например, CA-сертификаты для работы с TLS/HTTPS и информацию о часовых поясах, сохраняя при этом высокий уровень безопасности (в них нет shell). Отсутствие shell усложняет отладку — руководство по решению этой проблемы см. **[Отладка distroless-контейнеров](../../Docker_troubleshooting/debugging_distroless.md)**.

```dockerfile
# --- Этап 1: Сборка ---
FROM golang:1.26-bookworm as builder
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o my-app .

# --- Этап 2: Создание финального образа ---
# Используем distroless-образ для статически скомпонованных приложений
FROM gcr.io/distroless/static-debian12
COPY --from=builder /app/my-app /
CMD ["/my-app"]
```

### Сценарий 3: Решение проблемы совместимости с Alpine (`musl`)

Если вы хотите использовать `alpine` в качестве финального образа, но собираете приложение на `glibc`-окружении, необходимо скомпилировать **полностью статически связанный** бинарный файл. Проблема несовместимости `glibc` (Debian) и `musl` (Alpine) решается флагами статической линковки. Общие принципы оптимизации сборки см. **[Оптимизация сборки Docker-образов](./build_optimization.md)**.

```dockerfile
# --- Этап 1: Сборка ---
FROM golang:1.26 AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
# Флаг -a принудительно пересобирает пакеты
# -ldflags '-extldflags "-static"' обеспечивает статическую линковку
RUN CGO_ENABLED=0 GOOS=linux go build -a -ldflags '-extldflags "-static"' -o /app/main .

# --- Этап 2: Финальный образ ---
FROM alpine:3.23
COPY --from=builder /app/main /main
RUN chmod +x /main
ENTRYPOINT ["/main"]
```
