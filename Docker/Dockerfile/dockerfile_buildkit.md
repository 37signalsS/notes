# BuildKit: Современный движок сборки Docker

### Определения

**BuildKit** — это современный бэкенд для выполнения `docker build`, который заменяет старый движок сборки. Он предлагает значительные улучшения в производительности, управлении кэшем и безопасности.

В современных версиях Docker (Docker Desktop, Docker Engine v23.0+) BuildKit **включен по умолчанию**.

### Основные концепции

#### Ключевые преимущества
-   **Параллельное выполнение:** Этапы сборки, которые не зависят друг от друга (например, разные ветки `FROM` в многоэтапной сборке), выполняются параллельно.
-   **Улучшенное кэширование:** Более интеллектуально определяет, какие слои можно переиспользовать, что значительно ускоряет повторные сборки.
-   **Безопасная работа с секретами:** Позволяет монтировать секреты во время сборки без их сохранения в истории или слоях финального образа.
-   **Расширяемый синтаксис:** Позволяет использовать новые возможности в `Dockerfile`, например `RUN --mount=type=cache`.

### Мультиплатформенная сборка образов (Multi-platform Builds)

BuildKit позволяет создавать образы, которые поддерживают несколько архитектур (например, `amd64`, `arm64`) из одного Dockerfile, используя флаг `--platform`. Это решает проблему несовместимости образов, собранных под одну архитектуру (например, ARM на Apple M-чипах) и запускаемых на серверах с другой (например, x86_64 в AWS).

#### Проблема: "cannot execute binary file: Exec format error"

Типичная ситуация: образ собран на ARM-машине (Apple M1/M2), но запущен на x86_64 серверах AWS. Результат — ошибка "cannot execute binary file: Exec format error", так как бинарный файл несовместим с целевой архитектурой.

#### Сборка образа для конкретной платформы

С помощью `docker build` и флага `--platform` можно явно указать целевую архитектуру:

```bash
# Собираем для AMD64 (классические серверы)
docker build --platform linux/amd64 -t myapp:amd64 .

# Собираем для ARM64 (Apple M1/M2, AWS Graviton)
docker build --platform linux/arm64 -t myapp:arm64 .
```

#### Dockerfile для мультиплатформенной сборки

BuildKit предоставляет специальные аргументы и переменные для создания адаптивных Dockerfile:

```dockerfile
# syntax=docker/dockerfile:1.4
# Этап 1: Сборщик. Используем платформу ХОСТА для скорости.
FROM --platform=$BUILDPLATFORM golang:1.21-alpine AS builder
# TARGETOS и TARGETARCH автоматически установлены BuildKit
ARG TARGETOS TARGETARCH
WORKDIR /app
COPY . .
# Компиляция под ЦЕЛЕВУЮ ОС и архитектуру
RUN CGO_ENABLED=0 GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o /app/myapp .

# Этап 2: Финальный образ. Используем ЦЕЛЕВУЮ платформу.
FROM --platform=$TARGETPLATFORM alpine:3.18
RUN apk --no-cache add ca-certificates
COPY --from=builder /app/myapp /usr/local/bin/myapp
USER nobody
CMD ["myapp"]
```

*   `BUILDPLATFORM`: Платформа хоста, на котором происходит сборка.
*   `TARGETPLATFORM`: Платформа, для которой собирается финальный образ (указывается через `--platform`).
*   `TARGETOS`, `TARGETARCH`: Автоматически парсятся BuildKit из `TARGETPLATFORM`.

#### Проверка архитектуры образа

Архитектуру уже собранного образа можно проверить с помощью `docker inspect`:

```bash
docker inspect myapp:amd64 | grep Architecture
# Пример вывода: "Architecture": "amd64",
```

#### Преимущества мультиплатформенной сборки

*   Нативная работа на различных архитектурах (Apple M1/M2, x86_64, AWS Graviton) без эмуляции.
*   Оптимальная производительность за счет использования нативных сборок.
*   Поддержка IoT и Edge-устройств.
*   Единый образ для всей инфраструктуры, упрощающий версионирование и развертывание.

Для более продвинутых сценариев мультиплатформенной сборки, включая сборку нескольких архитектур одной командой и управление манифестами, рекомендуется использовать инструмент **`buildx`**.

#### Активация (для старых версий Docker)
В версиях, где BuildKit не включен по умолчанию, его можно активировать, установив переменную окружения:
```bash
export DOCKER_BUILDKIT=1
docker build .
```

### Практические сценарии

#### Использование build-time секретов
BuildKit предоставляет безопасный способ использования секретов (токенов, паролей) во время сборки.

> Подробное описание и примеры использования этой возможности находятся в документе **[Безопасное управление секретами в Docker](../Docker_security/secrets_management.md#3-секреты-на-этапе-сборки-buildkit)**.

#### Интерактивная отладки
Для пошаговой отладки `Dockerfile` с использованием BuildKit можно применять инструмент **[buildg](../alternative_runtimes_and_tools.md#инструменты-для-сборки-и-отладки)**.
