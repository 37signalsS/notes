# BuildKit: Современный движок сборки Docker

## Определения

**BuildKit** — это современный бэкенд для выполнения `docker build`, который заменяет старый движок сборки. Он предлагает значительные улучшения в производительности, управлении кэшем и безопасности.

В современных версиях Docker (Docker Desktop, Docker Engine v23.0+) BuildKit **включен по умолчанию**.

### Основные концепции

#### Ключевые преимущества BuildKit

- **Параллельное выполнение:** Этапы сборки, которые не зависят друг от друга (например, разные ветки `FROM` в многоэтапной сборке), выполняются параллельно.
- **Улучшенное кэширование:** Более интеллектуально определяет, какие слои можно переиспользовать, что значительно ускоряет повторные сборки.
- **Безопасная работа с секретами:** Позволяет монтировать секреты во время сборки без их сохранения в истории или слоях финального образа.
- **Расширяемый синтаксис:** Позволяет использовать новые возможности в `Dockerfile`, например `RUN --mount=type=cache`.

#### Преимущества мультиплатформенной сборки

- **Нативная работа:** Запуск образов на различных архитектурах (Apple M1/M2, x86_64, AWS Graviton) без эмуляции.
- **Оптимальная производительность** за счет использования нативных сборок.
- **Широкая поддержка:** Возможность создавать образы для IoT и Edge-устройств.
- **Унификация:** Единый тег образа для всей инфраструктуры, что упрощает версионирование и развертывание.

### Практические сценарии

#### Сценарий: Мультиплатформенная сборка

BuildKit позволяет легко создавать образы, которые поддерживают несколько архитектур (например, `linux/amd64`, `linux/arm64`) из одного `Dockerfile`. Это решает проблему `cannot execute binary file: Exec format error`, которая возникает при запуске образа на несовместимой архитектуре.

**1. Сборка для конкретной платформы**

Используйте флаг `--platform`, чтобы указать целевую архитектуру:

```bash
# Собираем для AMD64 (классические серверы)
docker build --platform linux/amd64 -t myapp:latest .

# Собираем для ARM64 (Apple M1/M2, AWS Graviton)
docker build --platform linux/arm64 -t myapp:latest .
```

**2. Адаптивный Dockerfile**

BuildKit предоставляет автоматические переменные для создания мультиплатформенных сборок:

- `TARGETPLATFORM`: Целевая платформа, указанная в `--platform`.
- `TARGETOS` и `TARGETARCH`: ОС и архитектура, извлеченные из `TARGETPLATFORM`.
- `BUILDPLATFORM`: Платформа, на которой выполняется сборка.

```dockerfile
# syntax=docker/dockerfile:1.4
# Этап 1: Сборщик. Используем платформу ХОСТА ($BUILDPLATFORM) для скорости.
FROM --platform=$BUILDPLATFORM golang:1.21-alpine AS builder
# TARGETOS и TARGETARCH автоматически установлены BuildKit
ARG TARGETOS TARGETARCH
WORKDIR /app
COPY . .
# Компиляция под ЦЕЛЕВУЮ архитектуру ($TARGETARCH)
RUN CGO_ENABLED=0 GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o /app/myapp .

# Этап 2: Финальный образ. Обязательно используем ЦЕЛЕВУЮ платформу.
FROM --platform=$TARGETPLATFORM alpine:3.18
RUN apk --no-cache add ca-certificates
COPY --from=builder /app/myapp /usr/local/bin/myapp
USER nobody
CMD ["myapp"]
```

**3. Проверка архитектуры**

```bash
docker inspect myapp:latest | grep Architecture
# "Architecture": "amd64",
```

#### Сценарий: Использование build-time секретов

BuildKit позволяет безопасно использовать секреты (токены, пароли) во время сборки, монтируя их без сохранения в слоях образа.

> Подробное описание и примеры см. в документе **[Безопасное управление секретами в Docker](../Docker_security/secrets_management.md#4-секреты-на-этапе-сборки-buildkit)**.

#### Сценарий: Интерактивная отладка

Для пошаговой отладки `Dockerfile` с использованием BuildKit можно применять инструмент **[buildg](../alternative_runtimes_and_tools.md#инструменты-для-сборки-и-отладки)**.

### Дополнительная информация

#### Продвинутая мультиплатформенная сборка (buildx)

Для более сложных сценариев, включая сборку под несколько архитектур одной командой и управление манифестами, рекомендуется использовать `docker buildx`.

#### Активация BuildKit (для старых версий Docker)

В версиях, где BuildKit не был включен по умолчанию, его можно было активировать через переменную окружения:

```bash
export DOCKER_BUILDKIT=1
docker build .
```
