# Инструкции Dockerfile: Переменные (ENV и ARG)

## Определения

**`ARG` (Build Argument)** — временная переменная, предназначенная для передачи данных в процесс сборки образа (`docker build`). Она доступна только во время сборки и не сохраняется в итоговом образе или его метаданных.

**`ENV` (Environment Variable)** — переменная окружения, которая доступна как на этапе сборки, так и во время работы контейнера (runtime). Значения `ENV` сохраняются в конфигурации образа и наследуются всеми последующими слоями и запущенными контейнерами.

## Основные концепции

### Инструкция ENV: Настройка рантайма

Используется для определения системных настроек и параметров приложения.

**Синтаксис:**
```dockerfile
# Рекомендуемая форма (несколько переменных в одном слое)
ENV APP_VERSION=1.0.0 \
    APP_HOME=/opt/app
```

**Особенности:**
- **Персистентность:** Значения видны через `docker inspect` и доступны приложению внутри контейнера.
- **Переопределение:** Значения можно заменить при запуске через `docker run -e` или в Docker Compose.
- **Инвалидация кэша:** Изменение значения `ENV` приводит к пересборке всех последующих инструкций.

### Инструкция ARG: Параметризация сборки

Позволяет изменять поведение сборки без модификации самого Dockerfile.

**Синтаксис:**
```dockerfile
# С указанием значения по умолчанию
ARG BUILD_VERSION=latest

# Без значения (требует передачи через --build-arg)
ARG API_KEY
```

**Область видимости в Multi-stage:**
1. **Глобальная (до `FROM`):** Переменная доступна только в инструкциях `FROM`.
2. **Внутри стадии:** Чтобы использовать глобальный `ARG` внутри стадии, его нужно объявить повторно без указания значения.

```dockerfile
ARG VERSION=3.11
FROM python:${VERSION}-slim
# Повторное объявление для доступа в этой стадии
ARG VERSION
RUN echo "Building with Python ${VERSION}"
```

### Синтаксис подстановки и значения по умолчанию

Docker поддерживает bash-подобный синтаксис для работы с переменными:

- `${variable:-word}`: если переменная не задана, использовать `word`.
- `${variable:+word}`: если переменная задана, использовать `word`, иначе пустую строку.

Инструкции, поддерживающие подстановку: `ADD`, `COPY`, `ENV`, `EXPOSE`, `FROM`, `LABEL`, `STOPSIGNAL`, `USER`, `VOLUME`, `WORKDIR`, `ONBUILD`.

### Безопасность и секреты

| Инструкция | Где видны данные | Рекомендация |
| :--- | :--- | :--- |
| **ARG** | В истории слоев (`docker history`) | **Запрещено** для паролей/ключей |
| **ENV** | В конфигурации образа (`docker inspect`) | **Запрещено** для паролей/ключей |

Для безопасной передачи секретов используйте монтирование BuildKit:
`RUN --mount=type=secret,id=my_secret ...`

## Практические сценарии

### Сценарий 1: Предопределенные переменные BuildKit

При использовании BuildKit доступны автоматические переменные для мультиплатформенных сборок (требуется `# syntax=docker/dockerfile:1`).

```dockerfile
FROM alpine
# TARGETPLATFORM, TARGETOS, TARGETARCH подставляются автоматически
ARG TARGETARCH
RUN echo "Building for architecture: ${TARGETARCH}"
```

### Сценарий 2: Оптимизация слоев через ENV

Объединение переменных в одну инструкцию уменьшает количество промежуточных слоев.

```dockerfile
FROM node:20-alpine
ENV NODE_ENV=production \
    NPM_CONFIG_LOGLEVEL=warn \
    APP_DEBUG=false
```

### Сценарий 3: Условные пути сборки

Использование значений по умолчанию для гибкости локальной и CI сборки.

```dockerfile
ARG SOURCE_DIR=./src
COPY ${SOURCE_DIR} /app/code
```

### Сценарий 4: Связка ARG и ENV

Паттерн для задания настроек при сборке, которые можно изменить при запуске.

```dockerfile
ARG DEFAULT_PORT=8080
ENV PORT=${DEFAULT_PORT}
EXPOSE ${PORT}
```

## Дополнительная информация

- **Приоритет:** Если имена `ARG` и `ENV` совпадают, `ENV` перекрывает `ARG` после точки своего объявления.
- **Кэширование:** Значения `ARG` влияют на кэш инструкций `RUN`. Разные значения `--build-arg` приведут к разным хэшам слоев.
