# Инструкции Dockerfile: Обзор

## Определения

**Инструкции Dockerfile** — зарезервированные ключевые слова, используемые в файле `Dockerfile` для описания процесса сборки образа. Каждая инструкция представляет собой отдельный шаг, который либо создает новый слой файловой системы, либо изменяет метаданные образа.

## Базовые концепции

### Категории инструкций

### Сводная таблица характеристик

| Инструкция | Создает слой | Влияет на кэширование | Описание |
| :--- | :--- | :--- | :--- |
| `FROM` | Да | Да | Инициализирует стадию сборки |
| `RUN` | Да | Да | Выполняет команду в новом слое |
| `COPY` | Да | Да | Копирует файлы в образ |
| `ADD` | Да | Да | Копирует/распаковывает файлы |
| `WORKDIR` | Нет | Да | Устанавливает рабочую директорию |
| `ENV` | Нет | Да | Устанавливает переменную окружения |
| `ARG` | Нет | Да | Задает переменную для сборки |
| `EXPOSE` | Нет | Нет | Описывает сетевой интерфейс |
| `VOLUME` | Нет | Да | Создает точку монтирования |
| `LABEL` | Нет | Нет* | Добавляет метаданные |
| `USER` | Нет | Да | Устанавливает **UID/GID (User ID / Group ID — идентификатор пользователя и группы)** |
| `SHELL` | Нет | Да | Меняет оболочку по умолчанию |
| `STOPSIGNAL` | Нет | Нет | Указывает сигнал завершения |
| `CMD` | Нет | Нет | Задает команду по умолчанию |
| `ENTRYPOINT` | Нет | Нет | Задает точку входа |
| `HEALTHCHECK` | Нет | Нет | Настраивает мониторинг контейнера |

> **\* `LABEL` и `EXPOSE` не влияют на кэш сборки (build cache), но изменяют `config.json` образа → итоговый дайджест (**SHA256 — Secure Hash Algorithm 256-bit**) будет другим. Два Dockerfile, идентичных во всём, кроме `LABEL`, дадут разные image digest. Подробнее: [Как LABEL влияет на дайджест](../../Docker_fs/images/docker_images_basics.md#сценарий-4-влияние-метаданных-label-на-дайджест).

## Практические сценарии

### Сценарий 1: Минимальный статичный образ

Демонстрация базовых инструкций для запуска простого приветствия.

```dockerfile
FROM alpine:3.20
LABEL maintainer="dev@example.com"
CMD ["echo", "Hello World"]
```

### Сценарий 2: Типовое веб-приложение (Python)

Демонстрация структуры Dockerfile с учетом кэширования и безопасности.

```dockerfile
FROM python:3.11-slim
WORKDIR /app

# Копируем зависимости отдельно для кэширования слоя
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Копируем код приложения
COPY . .

# Настройка метаданных и безопасности
EXPOSE 8000
USER appuser

HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8000/health || exit 1

CMD ["python", "app.py"]
```

## Дополнительная информация

### Правила именования и расположения

- **Имя файла:** по умолчанию `Dockerfile` (без расширения, первая буква заглавная).
- **Расположение:** рекомендуется размещать в корне проекта (контексте сборки).
- **Игнорирование файлов:** используйте `.dockerignore` для исключения ненужных файлов из контекста сборки.

### Автоматизация: `docker init`

Утилита `docker init` позволяет автоматически сгенерировать `Dockerfile`, `docker-compose.yml` и `.dockerignore` на основе анализа файлов в текущей директории. Это рекомендуемый способ для быстрого старта новых проектов.

### Кэширование и порядок инструкций

Порядок инструкций критически влияет на время сборки. Изменение данных в верхних слоях (например, `COPY . .`) инвалидирует кэш всех последующих слоев. Рекомендуется сначала копировать файлы зависимостей и выполнять их установку, и только затем копировать часто меняющийся исходный код.
