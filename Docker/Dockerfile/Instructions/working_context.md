# Инструкции Dockerfile: WORKDIR и SHELL

## Определения

**`WORKDIR`** — инструкция Dockerfile, устанавливающая текущий рабочий каталог для всех последующих инструкций `RUN`, `CMD`, `ENTRYPOINT`, `COPY` и `ADD`. Она действует аналогично команде `cd` в командной строке, но сохраняется для всех последующих слоев сборки.

**`SHELL`** — инструкция Dockerfile, позволяющая переопределить оболочку (shell) по умолчанию, которая используется для выполнения команд в инструкциях `RUN`, `CMD` и `ENTRYPOINT` (в формате shell).

## Основные концепции

### Рабочая директория: WORKDIR

Инструкция устанавливает контекст выполнения для команд. Если указанная директория не существует, Docker создаст ее автоматически (аналог `mkdir -p`).

**Синтаксис:**

```dockerfile
WORKDIR /path/to/directory
```

**Особенности поведения:**

- **Абсолютные и относительные пути:** Если путь относительный, он будет разрешен относительно пути предыдущей инструкции `WORKDIR`.
- **Множественное использование:** Можно использовать несколько раз. Пути будут накапливаться, если они относительные.
- **Переменные окружения:** Поддерживает подстановку переменных, определенных через **[ENV](./environment_variables.md)**.

**Взаимодействие с USER и права доступа:**

Поведение при автоматическом создании директории зависит от сборщика:
| Сборщик | Поведение при наличии `USER` | Владелец директории |
| :--- | :--- | :--- |
| **Classic Builder** | Игнорирует текущего пользователя | `root:root` |
| **BuildKit** | Наследует текущего пользователя | Текущий `USER` |

> **Рекомендация:** Для обеспечения переносимости и безопасности всегда явно создавайте директорию и устанавливайте владельца через `RUN mkdir && chown` перед использованием `WORKDIR`, если ваше приложение работает от имени непривилегированного пользователя.

### Оболочка выполнения: SHELL

Инструкция полезна, когда требуется изменить оболочку по умолчанию или задать специфические параметры ее выполнения (например, для повышения безопасности).

**Синтаксис (только Exec-форма):**

```dockerfile
SHELL ["executable", "parameters"]
```

**Особенности поведения:**

- **Область действия:** Влияет на все последующие инструкции `RUN`, `CMD` и `ENTRYPOINT`, написанные в формате строки (shell form).
- **Платформенные значения по умолчанию:**
  - Linux: `["/bin/sh", "-c"]`
  - Windows: `["cmd", "/S", "/C"]`

**Безопасность (pipefail):**
В Linux-образах критически важно использовать `set -o pipefail`. Это гарантирует, что сборка упадет, если любая часть конвейера (`pipe |`) завершится с ошибкой.

```dockerfile
# Рекомендуемая настройка для Linux
SHELL ["/bin/bash", "-o", "pipefail", "-c"]
```

## Практические сценарии

### Сценарий 1: Явное управление правами (Best Practice)

Гарантирует отсутствие ошибок `Permission Denied` независимо от настроек сборщика.

```dockerfile
FROM python:3.11-slim
RUN useradd -m appuser
WORKDIR /app
# Владелец будет root, если не создать папку заранее
# Поэтому явно меняем владельца
RUN chown appuser:appuser /app
USER appuser
COPY --chown=appuser:appuser . .
```

### Сценарий 2: Переключение на PowerShell в Windows

```dockerfile
FROM mcr.microsoft.com/windows/servercore:ltsc2022
SHELL ["powershell", "-Command", "$ErrorActionPreference = 'Stop';"]
# Теперь можно использовать нативные команды PowerShell
RUN New-Item -ItemType Directory -Path C:\Setup
```

### Сценарий 3: Накопление путей и Multi-stage

Использование относительных путей для структурирования монорепозитория.

```dockerfile
# Стадия сборки
FROM golang:1.22 AS builder
WORKDIR /src
WORKDIR api          # Итог: /src/api
COPY . .
RUN go build -o /app/main .

# Финальный образ
FROM scratch
WORKDIR /            # Сброс в корень
COPY --from=builder /app/main .
ENTRYPOINT ["/main"]
```

## Дополнительная информация

- **Избегайте `cd`:** Команда `RUN cd /path` меняет директорию только внутри одного слоя. Следующая инструкция `RUN` снова начнется в корне или в последнем `WORKDIR`.
- **Идемпотентность:** `WORKDIR` гарантирует существование папки, что избавляет от лишних `mkdir -p`.
- **Multi-stage:** При каждой новой инструкции `FROM` рабочая директория сбрасывается к значению по умолчанию (`/`).
