# Инструкция Dockerfile: RUN

## Определения

**Инструкция `RUN`** — директива Dockerfile, которая выполняет команды в новом слое поверх текущего образа и фиксирует (commit) результаты. Это основной инструмент для установки пакетов, компиляции кода и настройки системного окружения на этапе сборки.

## Основные концепции

### Формы записи: Shell и Exec

| Характеристика | Shell-форма | Exec-форма (рекомендуется) |
| :--- | :--- | :--- |
| **Синтаксис** | `RUN команда аргумент` | `RUN ["команда", "аргумент"]` |
| **Оболочка** | `/bin/sh -c` (Linux) | Выполняется напрямую (`execve`) |
| **Переменные** | Поддерживает подстановку `$VAR` | Не поддерживает подстановку напрямую |
| **PID 1** | Процесс запущен внутри оболочки | Процесс запущен напрямую |

> **Важно:** Для большинства системных команд (установка пакетов) используется Shell-форма, так как она позволяет использовать конвейеры (`|`) и переменные окружения.

### Надежность и безопасность скриптов

При использовании Shell-формы для цепочек команд рекомендуется использовать флаги оболочки для повышения надежности:

```dockerfile
# set -e: остановить сборку при ошибке любой команды
# set -o pipefail: вернуть код ошибки, если упала любая часть пайпа
# set -x: выводить выполняемые команды в лог (для отладки)
RUN set -ex; \
    apt-get update; \
    apt-get install -y --no-install-recommends curl; \
    rm -rf /var/lib/apt/lists/*
```

### Расширенные возможности BuildKit

Движок **[BuildKit](../dockerfile_buildkit.md)** значительно расширяет функционал `RUN` через флаги монтирования и управления окружением. Для использования требуется заголовок `# syntax=docker/dockerfile:1`.

#### Флаг `--mount` (Типы монтирования)

| Тип | Назначение | Особенности |
| :--- | :--- | :--- |
| **`type=cache`** | Кэширование зависимостей | Сохраняет кэш пакетных менеджеров (apt, pip, npm) между сборками. |
| **`type=secret`** | Безопасная передача секретов | Монтирует файлы (ключи API, токены) без сохранения их в слоях образа. |
| **`type=ssh`** | Использование SSH-агента | Позволяет клонировать приватные репозитории через SSH-агент хоста. |
| **`type=bind`** | Прямое монтирование | Доступ к файлам контекста или других стадий без их копирования. |
| **`type=tmpfs`** | Временная ФС в RAM | Для записи временных данных, которые не должны попасть на диск. |

#### Управление сетью и безопасностью

- **`--network=<mode>`**:
  - `none`: Полная изоляция (запрет доступа в интернет во время выполнения команды).
  - `host`: Использование сетевого стека хоста.
- **`--security=insecure`**: Позволяет выполнять команды с расширенными привилегиями (требует разрешения `security.insecure` в сборщике).

## Практические сценарии

### Сценарий 1: Эффективная установка пакетов

Объединение команд и очистка кэша в одном слое — залог минимального размера образа.

```dockerfile
FROM alpine:3.20
# --no-cache в Alpine эквивалентно удалению /var/cache/apk/*
RUN apk add --no-cache \
    python3 \
    py3-pip \
    && pip install --break-system-packages --no-cache-dir requests
```

### Сценарий 2: Кэширование пакетов (Python + BuildKit)

Использование `type=cache` предотвращает повторную загрузку одних и тех же библиотек при изменении исходного кода.

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
# Кэш pip сохраняется локально в сборщике
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt
COPY . .
```

### Сценарий 3: Сборка без доступа к сети (Air-gapped)

Гарантирует, что во время сборки не подтянутся несанкционированные зависимости извне.

```dockerfile
# syntax=docker/dockerfile:1
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
# Запрещаем любой сетевой доступ во время компиляции
RUN --network=none npm run build
```

## Дополнительная информация

### Кэширование слоев

Docker кэширует результат выполнения каждой инструкции `RUN`. Кэш инвалидируется, если:
1. Изменился текст самой инструкции.
2. Изменились файлы, скопированные ранее (через `COPY` или `ADD`), от которых зависит результат команды.
3. Используется флаг `--no-cache` при запуске `docker build`.
