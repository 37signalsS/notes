# Инструкции Dockerfile: Базовый образ и Метаданные

## Определения

**Базовый образ (Base Image)** — фундамент файловой системы образа. Инструкция `FROM` инициализирует новую стадию сборки и задает основу, на которую будут накладываться последующие слои.

**Метаданные (Metadata)** — структурированные данные об образе (версия, автор, лицензия, описание), которые не влияют на выполнение кода, но используются системами автоматизации, реестрами и сканерами безопасности для идентификации артефакта.

## Основные концепции

### Инструкция FROM: Инициализация сборки

Инструкция `FROM` должна быть первой значащей командой в Dockerfile (за исключением `ARG` и директив парсера).

**Синтаксис:**
```dockerfile
# По тегу (рекомендуется фиксировать версию)
FROM alpine:3.20

# По дайджесту (наивысшая степень безопасности и воспроизводимости)
FROM debian@sha256:722978484501...

# Именование стадии для Multi-stage сборки
FROM golang:1.23-alpine AS builder

# С указанием целевой платформы (требуется BuildKit)
FROM --platform=linux/amd64 ubuntu:24.04
```

**Особенности применения:**
- **Глобальные переменные:** Инструкция `ARG`, объявленная *до* первого `FROM`, может использоваться в качестве переменной в самой инструкции `FROM`.
- **Пустой образ (scratch):** Специальный зарезервированный образ `FROM scratch` используется для создания максимально компактных образов, содержащих только один статический бинарный файл.
- **Множественный FROM:** Позволяет реализовать [Multi-stage сборки](../Docker_best_practices/build_optimization.md), где каждая стадия может использовать свой базовый образ.

### Инструкция LABEL: Аннотирование образа

Директива `LABEL` добавляет метаданные в формате «ключ-значение». Эти данные сохраняются в манифесте образа и доступны через команду `docker inspect`.

**Рекомендованные ключи (стандарт OCI):**
Для обеспечения совместимости с инструментами мониторинга и безопасности рекомендуется использовать ключи из спецификации [Open Container Initiative](https://github.com/opencontainers/image-spec):
- `org.opencontainers.image.title` — краткое название приложения.
- `org.opencontainers.image.version` — версия ПО.
- `org.opencontainers.image.vendor` — владелец или издатель образа.
- `org.opencontainers.image.source` — ссылка на репозиторий с исходным кодом.
- `org.opencontainers.image.description` — детальное описание назначения образа.

**Влияние на Image Digest:** Любое изменение текста `LABEL` (даже пробела) изменяет `config.json` образа. Поскольку **Image Digest** является SHA256-хэшем этого конфига, дайджест изменится, даже если слои файловой системы остались прежними.

### Устаревшие инструкции

Инструкция **`MAINTAINER`** официально признана устаревшей (deprecated). Вместо неё для указания контактных данных автора следует использовать:
`LABEL org.opencontainers.image.authors="Name <email@example.com>"`

## Практические сценарии

### Сценарий 1: Динамическое управление версиями

Использование `ARG` перед `FROM` позволяет централизованно управлять версиями базовых образов во всей инфраструктуре.

```dockerfile
ARG BASE_OS=alpine:3.20
FROM ${BASE_OS}
# Внутри стадии переменную нужно объявить повторно, если она нужна в RUN
ARG BASE_OS
RUN echo "Base image was: ${BASE_OS}"
```

### Сценарий 2: Многоэтапная сборка с именованием

Именование стадий (`AS`) упрощает поддержку Dockerfile и предотвращает ошибки при копировании артефактов.

```dockerfile
# Стадия сборки
FROM golang:1.23 AS compiler
WORKDIR /app
COPY . .
RUN go build -o app .

# Стадия выполнения
FROM alpine:3.20
# Копируем из именованной стадии вместо индекса (0, 1)
COPY --from=compiler /app/app /usr/local/bin/
ENTRYPOINT ["app"]
```

### Сценарий 3: Группировка меток

Объединение всех `LABEL` в одну инструкцию делает манифест чище (однако в BuildKit это не влияет на количество слоев данных).

```dockerfile
LABEL org.opencontainers.image.title="API Gateway" \
      org.opencontainers.image.version="2.1.0" \
      org.opencontainers.image.created="2026-07-19"
```
