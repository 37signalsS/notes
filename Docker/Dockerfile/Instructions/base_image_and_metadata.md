# Инструкции Dockerfile: Базовый образ и Метаданные

## Определения

**Базовый образ (Base Image)** — начальный уровень файловой системы, на котором строится новый образ. Инструкция `FROM` задает фундамент, включая операционную систему и предустановленное системное окружение.

**Метаданные (Metadata)** — информационные метки, прикрепляемые к образу для описания его свойств (автор, версия, описание, источник). Инструкция `LABEL` позволяет структурировать эти данные для упрощения поиска и автоматизации управления образами.

## Основные концепции

### Инструкция FROM

Определяет базовый образ для сборки. Это первая значащая инструкция в Dockerfile (за исключением директив парсера и комментариев).

**Синтаксис:**

```dockerfile
# По имени и тегу
FROM <image>[:<tag>]

# По уникальному хэшу (наиболее безопасно)
FROM <image>@sha256:<digest>

# С указанием платформы (требуется BuildKit)
FROM --platform=linux/amd64 <image>
```

**Рекомендации:**

- **Избегайте `latest`:** Всегда указывайте конкретную версию образа для обеспечения воспроизводимости сборки.
- **Использование Digest:** Применение хэша (`sha256`) гарантирует, что базовый образ не был изменен в реестре после публикации.
- **Multi-stage:** Инструкция `FROM` может встречаться в Dockerfile несколько раз для создания многоэтапных сборок. Каждая новая инструкция `FROM` сбрасывает состояние предыдущего этапа.

### Инструкция LABEL

Добавляет метаданные к образу в формате «ключ-значение». Эти данные можно увидеть с помощью команды `docker inspect`.

**Синтаксис:**

```dockerfile
LABEL <key>=<value> <key>=<value> ...
```

**Влияние на дайджест:** `LABEL` изменяет `config.json` образа → итоговый дайджест (SHA256) будет отличаться, даже если файловая система идентична. Подробнее: [как LABEL влияет на дайджест](../../Docker_fs/images/docker_images_basics.md#сценарий-4-как-label-влияет-на-дайджест-результат-сборки).

**Стандарты именования (OCI):**
Рекомендуется использовать ключи, соответствующие спецификации [OCI Image Spec](https://github.com/opencontainers/image-spec), для совместимости с внешними инструментами:

- `org.opencontainers.image.title` — название приложения.
- `org.opencontainers.image.version` — версия ПО.
- `org.opencontainers.image.description` — краткое описание.
- `org.opencontainers.image.source` — ссылка на репозиторий с исходным кодом.

### Устаревшая инструкция MAINTAINER

Директива `MAINTAINER` помечена как **deprecated** (устаревшая). Вместо нее для указания автора следует использовать `LABEL`:

```dockerfile
# Устаревший формат
MAINTAINER Ivan Ivanov <ivan@example.com>

# Рекомендуемый формат
LABEL org.opencontainers.image.authors="Ivan Ivanov <ivan@example.com>"
```

## Практические сценарии

### Сценарий 1: Гарантированная стабильность через Digest

Фиксация базового образа по хэшу предотвращает автоматическое обновление системных библиотек при пересборке, что критично для стабильности в production.

```dockerfile
# Фиксация конкретной сборки Ubuntu 24.04
FROM ubuntu@sha256:722978484501ed6f3d9d30009c919741b069d2d0f04c6023243912da61386d26
```

### Сценарий 2: Группировка метаданных

Для уменьшения количества слоев метаданных (хотя `LABEL` не создает тяжелых слоев ФС) рекомендуется объединять метки в одну инструкцию.

```dockerfile
LABEL version="1.0" \
      description="Web server for static content" \
      org.opencontainers.image.vendor="Acme Corp"
```

## Дополнительная информация

- **Порядок инструкций:** `FROM` инициализирует стадию сборки. Изменение базового образа инвалидирует кэш всех последующих слоев.
- **Просмотр метаданных:** Используйте `docker inspect --format='{{json .Config.Labels}}' <image_id>` для извлечения меток.
- **Безопасность:** Регулярно обновляйте базовые образы для получения патчей безопасности.
- **Обзор инструкций:** Полный список команд сборки см. в **[Инструкции Dockerfile: Обзор](./overview_definitions.md)**.
- **Оптимизация:** Принципы выбора легковесных базовых образов (Alpine, Scratch) описаны в **[Оптимизации сборки](../Docker_best_practices/build_optimization.md)**.
