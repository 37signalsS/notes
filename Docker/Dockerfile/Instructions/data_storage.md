# Инструкции Dockerfile: Данные и Хранилища

### Данные и хранилища

#### `VOLUME`

Директива `VOLUME` в Dockerfile позволяет прямо в образе указать, что и куда монтировать, обеспечивая автоматическое создание и управление томами для персистентности данных. Это декларативная инструкция, которая сообщает Docker о том, что указанный путь внутри контейнера должен быть внешним томом.

**Синтаксис:**

```dockerfile
VOLUME /path/to/directory/inside/container
```

Или для нескольких точек монтирования:

```dockerfile
VOLUME ["/path1", "/path2"]
```

**Примеры использования:**

- **Для логов веб-сервера:**

    ```dockerfile
    FROM nginx:alpine
    VOLUME /var/log/nginx
    ```

    Эта директива говорит Docker создать анонимный том с уникальным ID и автоматически примонтировать его к `/var/log/nginx` внутри контейнера. Данные в таком томе переживут смерть и воскрешение контейнера.
- **Для пользовательских файлов и кеша:**

    ```dockerfile
    FROM node:16
    WORKDIR /app
    VOLUME ["/app/uploads", "/app/cache"]
    ```

    Здесь создаются две точки монтирования для `/app/uploads` и `/app/cache`.

**Важно:** Директива `VOLUME` создает **анонимные тома**, которыми Docker управляет автоматически. Это отличается от `bind mount` (например, через флаг `-v` в `docker run`), где вы вручную указываете, что и куда монтировать. Анонимные тома удобны для стандартизации и "защиты от дурака", так как гарантируют персистентность данных без дополнительных действий пользователя при запуске.

**Зачем это нужно?**

- **Автоматическая персистентность данных:** Гарантирует, что данные (например, логи, пользовательские загрузки) будут сохраняться независимо от жизненного цикла контейнера, даже если пользователь забыл явно указать тома при запуске.
- **Стандартизация точек монтирования:** Позволяет стандартизировать, куда должны сохраняться определенные типы данных (например, логи в `/var/log/app`, конфигурации в `/etc/app/`, изображения в `/app/images`). Это упрощает управление множеством однотипных сервисов.
- **Упрощение оркестрации:** В контексте Docker Compose или Kubernetes, `VOLUME` в Dockerfile работает как значение по умолчанию. Даже если в файле `docker-compose.yml` не прописаны тома, они все равно будут созданы Docker, обеспечивая базовую персистентность.
- **Изоляция данных от слоя контейнера:** Данные, хранящиеся в томах, не являются частью записываемого слоя контейнера. Это важно при бэкапировании состояния контейнера через `docker export`, так как данные томов не будут включены в экспорт, что позволяет гибко управлять данными и образами отдельно.

Директива `VOLUME` тесно связана с концепцией [томов в Docker](../../Docker_fs/docker_volumes.md), секцией `volumes` в [Docker Compose](../../Docker_compose/docker_compose_file_example.md) и директивой [COPY и ADD](#копирование-файлов) для копирования данных в образ.

В целом, `VOLUME` служит отличной "защитой от дурака", минимизируя количество необходимых флагов или инструкций при запуске контейнера и упрощая рабочие процессы.
