# Инструкция Dockerfile: VOLUME

## Определения

**Инструкция `VOLUME`** — директива в Dockerfile, которая создает точку монтирования с указанным именем и помечает ее как содержащую внешне монтируемые тома (volumes) из нативного хоста или других контейнеров. При запуске контейнера для этой точки автоматически создается анонимный том, если не указано иное монтирование.

Для понимания общей концепции томов, их типов и преимуществ см. **[Docker Volumes](../../Docker_fs/docker_volumes.md)**.

## Основные концепции

### Синтаксис

Инструкция поддерживает формат JSON-массива (рекомендуется) и строковый формат. При использовании JSON-массива обязательны двойные кавычки.

```dockerfile
# JSON-массив (рекомендуется)
VOLUME ["/var/log/"]

# Строковый формат с несколькими путями
VOLUME /var/log /var/db

# Несколько путей в JSON-формате
VOLUME ["/app/data", "/app/cache"]
```

### Механизм инициализации данных

При создании тома инструкция `VOLUME` инициализирует его данными, которые уже существуют в базовом образе в указанной точке монтирования.

```dockerfile
FROM ubuntu
RUN mkdir -p /myvol
RUN echo "hello" > /myvol/greeting
VOLUME /myvol
```

При запуске контейнера:
1. Docker создает новый анонимный том (управляется Docker, имя генерируется автоматически).
2. Файл `greeting` копируется из образа в этот том.
3. Если при запуске контейнера (`docker run -v ...`) в эту же точку монтируется другой том, данные из образа не копируются, а становятся доступны данные из монтируемого тома.

### Особенности и ограничения

| Аспект | Описание |
| :--- | :--- |
| **Тип монтирования** | Инструкция всегда создает **анонимные тома**. Именованные тома и bind mounts задаются только на этапе запуска контейнера. |
| **Портативность** | В Dockerfile **нельзя** указать путь на хосте (bind mount). Это ограничение обеспечивает переносимость образа между разными средами. |
| **BuildKit vs Legacy** | В стандартном сборщике (legacy) любые изменения в директории тома *после* инструкции `VOLUME` отбрасываются. В BuildKit эти изменения сохраняются в образе. |
| **Windows** | При работе с контейнерами Windows точка монтирования должна быть либо пустой/несуществующей директорией, либо диском, отличным от `C:`. |

### Отличие от монтирования при запуске

В отличие от флагов `-v` или `--mount` в команде `docker run`, инструкция в Dockerfile только подготавливает инфраструктуру для хранения данных. Подробное сравнение способов хранения данных приведено в разделе **[Сравнение Volumes и Bind Mounts](../../Docker_fs/docker_volumes.md#сравнение-volumes-bind-mounts-и-tmpfs)**.

## Практические сценарии

### Сценарий 1: Гарантированная персистентность логов

Использование `VOLUME` в Dockerfile является «страховкой»: если пользователь забудет примонтировать внешний том, Docker все равно вынесет данные за пределы записываемого слоя контейнера в анонимный том.

```dockerfile
FROM nginx:alpine
# Гарантируем, что логи не потеряются при удалении контейнера
VOLUME /var/log/nginx
```

### Сценарий 2: Подготовка данных в BuildKit

Современный сборщик BuildKit позволяет изменять содержимое директории даже после объявления ее томом в Dockerfile.

```dockerfile
# syntax=docker/dockerfile:1
FROM ubuntu
VOLUME /data
# В BuildKit этот файл сохранится и попадет в том при первом запуске
RUN echo "initial config" > /data/config.json
```

### Сценарий 3: Переопределение в Docker Compose

Директиву `VOLUME` из Dockerfile можно переопределить в файле конфигурации Docker Compose, сопоставив точку монтирования с именованным томом или путем на хосте.

```yaml
services:
  db:
    build: .
    volumes:
      - postgres_data:/var/lib/postgresql/data # Переопределяет анонимный том
volumes:
  postgres_data:
```
