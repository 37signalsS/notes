# Инструкция Dockerfile: VOLUME

## Определения

**Инструкция `VOLUME`** — директива в Dockerfile, которая создает точку монтирования с указанным именем и помечает ее как содержащую внешне монтируемые тома (volumes). 

Основные функции:
1. **Метаданные:** Добавляет в манифест образа информацию о том, что указанные пути предназначены для хранения персистентных данных.
2. **Автоматизация:** При запуске контейнера Docker автоматически создает **анонимный том** для этой точки, если пользователь не указал явное монтирование (через `-v`, `--mount` или в Compose).
3. **Безопасность данных:** Гарантирует, что данные будут вынесены за пределы эфемерного записываемого слоя контейнера, предотвращая их случайную потерю при удалении контейнера.

Для понимания общей концепции томов, их типов и преимуществ см. **[Docker Volumes](../../Docker_fs/docker_volumes.md)**.

## Основные концепции

### Синтаксис

Инструкция поддерживает формат JSON-массива (рекомендуется) и строковый формат.

```dockerfile
# JSON-массив (рекомендуется)
VOLUME ["/var/log/"]

# Строковый формат с несколькими путями
VOLUME /var/log /var/db

# Несколько путей в JSON-формате
VOLUME ["/app/data", "/app/cache"]
```

### BuildKit vs Legacy Builder

Поведение `VOLUME` во время сборки образа (инструкции `RUN`, `COPY`, `ADD` после объявления тома) радикально различается в зависимости от используемого сборщика.

| Характеристика | Legacy Builder (Старый) | BuildKit (Современный) |
| :--- | :--- | :--- |
| **Логика работы** | Создает реальный временный том для каждого шага `RUN`. | Воспринимает `VOLUME` только как метаданные для рантайма. |
| **Изменения после `VOLUME`** | **Отбрасываются.** Файлы, созданные после объявления тома, не попадут в образ. | **Сохраняются.** Все изменения записываются в слои образа. |
| **Применение `chown`** | Не сработает для папки тома в последующих слоях. | Работает корректно. |

**Пример различия:**
```dockerfile
FROM alpine
VOLUME /data
RUN touch /data/test.txt
```
*   **Legacy:** В итоговом образе файла `/data/test.txt` **не будет**.
*   **BuildKit:** В итоговом образе файл `/data/test.txt` **будет** существовать и скопируется в анонимный том при старте.

> **Рекомендация:** Для обеспечения совместимости и предсказуемости всегда объявляйте `VOLUME` **в самом конце** Dockerfile, после того как все данные записаны, а права доступа (`chown`) настроены.

### Особенности и ограничения

1. **Необратимость:** Если в базовом образе объявлен `VOLUME`, дочерние образы (`FROM ...`) не могут его «отменить» или сделать эту директорию обычной частью файловой системы.
2. **Портативность:** В Dockerfile нельзя указать путь на хосте (bind mount). Это сделано для того, чтобы образ можно было запустить на любой системе без привязки к конкретной структуре папок хоста.
3. **Взаимодействие с USER:** Если `VOLUME` объявлен до инструкции `USER`, анонимный том может быть создан с правами `root`. Рекомендуется сначала настроить пользователя и права на директорию, а затем объявлять её томом.
4. **Утечка места:** Если пользователь часто запускает и удаляет контейнеры с `VOLUME` без флага `--rm` или явного монтирования, в системе накапливается множество "забытых" анонимных томов. Требуется регулярная очистка через `docker volume prune`.

## Практические сценарии

### Сценарий 1: Гарантированная персистентность

Использование `VOLUME` — это «страховка» для баз данных и приложений со стейтом.

```dockerfile
FROM postgres:16-alpine
# Даже если пользователь забудет -v, данные БД будут в безопасности в анонимном томе
VOLUME /var/lib/postgresql/data
```

### Сценарий 2: Передача данных между стадиями (Multi-stage)

Инструкция `VOLUME` не влияет на сборку в BuildKit, но важно помнить, что при копировании данных из предыдущей стадии (`COPY --from`) метаданные тома не наследуются, их нужно объявлять заново в финальном образе.

```dockerfile
# Стадия сборки
FROM node:20 AS builder
WORKDIR /app
COPY . .
RUN npm run build

# Финальный образ
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
# Объявляем тома только в финальном образе
VOLUME ["/var/cache/nginx", "/var/log/nginx"]
```
