# Инструкции Dockerfile: Сеть и Порты

## Определения

**`EXPOSE`** — инструкция Dockerfile, информирующая Docker о том, что контейнер прослушивает указанные сетевые порты во время выполнения.

## Основные концепции

### Декларативная природа `EXPOSE`

> `EXPOSE` — исключительно **декларативная** инструкция. Она **не открывает** и **не публикует** порты автоматически.

**Синтаксис:**

```dockerfile
EXPOSE <port> [<port>/<protocol>...]
```

**Примеры:**

```dockerfile
EXPOSE 80
EXPOSE 443
EXPOSE 8080/tcp
EXPOSE 53/udp
EXPOSE 80/udp  # Для одного порта TCP+UDP нужны две строки
```

**Параметры:**

| Параметр | Описание | По умолчанию |
| :--- | :--- | :--- |
| `<port>` | Номер порта | — |
| `<protocol>` | Протокол (`tcp` или `udp`) | `tcp` |

**Функции `EXPOSE`:**

1. **Документация:** Подсказка пользователю о назначенных портах
2. **Автоматическая публикация:** При использовании флага `-P` в `docker run`, Docker использует эту информацию
3. **Метаданные образа:** Сохраняется в конфигурации образа, видно через `docker inspect`

### Различия: `EXPOSE` vs `-p` vs `-P`

| Параметр | `EXPOSE` (Dockerfile) | `-p` (docker run) | `-P` (docker run) |
| :--- | :--- | :--- | :--- |
| **Функция** | Документирование портов | Фактическая публикация и маппинг | Публикация всех `EXPOSE` портов |
| **Когда применяется** | При сборке образа | При запуске контейнера | При запуске контейнера |
| **Влияние на сеть** | Не открывает порты | Открывает и маппит порты на хост | Открывает на случайные порты хоста |
| **Переопределение** | Можно переопределить флагом `-p` | Имеет приоритет над `EXPOSE` | Использует порты из `EXPOSE` |

**Примеры использования:**

```bash
# EXPOSE только документирует порт
docker run -p 80:80/tcp -p 80:80/udp <image>

# Флаг -P публикует все EXPOSE порты на случайные высокоуровневые порты хоста
docker run -P <image>

# Проверка маппинга портов
docker port <container>
```

### Важные замечания

| Утверждение | Пояснение |
| :--- | :--- |
| **Контейнеры в одной сети могут общаться без `EXPOSE`** | `EXPOSE` не требуется для связи между контейнерами в одной Docker-сети |
| **`EXPOSE` не обеспечивает безопасность** | Порты всё равно требуют `-p` для доступа извне; для изоляции используйте сети |
| **TCP + UDP для одного порта** | Требует двух отдельных строк: `EXPOSE 80/tcp` и `EXPOSE 80/udp` |
| **Последняя инструкция имеет приоритет** | При нескольких `EXPOSE` в Dockerfile все порты добавляются к метаданным |
| **`EXPOSE` не гарантирует порт приложения** | `EXPOSE` лишь документирует порт; реальный порт определяется аргументами команды запуска в `CMD`/`ENTRYPOINT`. Если `EXPOSE 5000`, а приложение в `CMD` запускается на `8080` — слушать будет `8080` |

## Практические сценарии

### Сценарий 1: Базовое документирование портов

```dockerfile
FROM nginx:alpine
EXPOSE 80
EXPOSE 443
CMD ["nginx", "-g", "daemon off;"]
```

При запуске `docker run -P my-nginx` порты 80 и 443 будут проброшены на случайные порты хоста.

### Сценарий 2: Публикация портов при запуске

| Метод | Команда | Результат |
| :--- | :--- | :--- |
| Не публиковать | `docker run my-image` | Порт недоступен снаружи |
| Проброс на случайный порт | `docker run -P my-image` | Docker выбирает свободный порт хоста |
| Проброс на конкретный порт | `docker run -p 8080:80 my-image` | Порт 80 контейнера на `localhost:8080` |
| Проброс с указанием IP | `docker run -p 127.0.0.1:8080:80 my-image` | Порт доступен только с localhost |

### Сценарий 3: TCP и UDP для одного порта

```dockerfile
FROM dns-server:latest
EXPOSE 53/tcp
EXPOSE 53/udp
```

```bash
# Запуск с публикацией обоих протоколов
docker run -p 53:53/tcp -p 53:53/udp dns-server
```

### Сценарий 4: Docker Compose

```yaml
services:
  web:
    image: nginx
    ports:
      - "80:80"           # Явный проброс
      - "443:443"
      - "127.0.0.1:8080:8080"  # Только localhost
```

Подробнее о синтаксисе Compose см. **[Docker Compose file example](../../Docker_compose/docker_compose_file_example.md)**.

### Сценарий 5: Проверка опубликованных портов

```bash
# Запуск контейнера
docker run -d -p 8080:80 --name my-nginx nginx:alpine

# Проверка маппинга портов
docker port my-nginx
# Вывод: 80/tcp -> 0.0.0.0:8080

# Проверка через inspect
docker inspect --format='{{json .NetworkSettings.Ports}}' my-nginx
```

## Дополнительная информация

Для постоянного проброса портов используйте флаг `-p` в `docker run` или секцию `ports` в `docker-compose.yml`. `EXPOSE` не заменяет настройку сетевых драйверов Docker — это метаданные. Подробнее о сетях см. **[Docker Network](../../Docker_network/docker_network.md)**.

Практические примеры публикации портов, эфемерных портов и флага `-P` — в **[Командах Docker CLI](../../docker_commands.md)**.
