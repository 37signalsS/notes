# Инструкция Dockerfile: EXPOSE

## Определения

**`EXPOSE`** — инструкция Dockerfile, которая информирует Docker о том, что контейнер будет прослушивать указанные сетевые порты во время выполнения. Это декларативный механизм документирования сетевого интерфейса приложения.

## Основные концепции

### Декларативная природа EXPOSE

Инструкция `EXPOSE` является исключительно **документационной** (метаданными). Она:

- Служит **договоренностью** (контрактом) между автором Dockerfile и пользователем: «приложение внутри будет слушать этот порт».
- **Не открывает** порты автоматически на хост-машине.
- **Не создает** правила `iptables` или перенаправления портов.
- Поставляет метаданные, которые можно увидеть через `docker inspect`.

**Синтаксис:**

```dockerfile
# Единичный порт (TCP по умолчанию)
EXPOSE <port>

# Порт с протоколом
EXPOSE <port>/<protocol>

# Диапазон портов
EXPOSE <port_start>-<port_end>/<protocol>

# Несколько портов в одной строке
EXPOSE 80 443 8000-8010/udp
```

> **Важно:** Чтобы один и тот же порт прослушивал и TCP, и UDP, необходимо указать две записи: `EXPOSE 53/tcp` и `EXPOSE 53/udp`.

### Функции инструкции

1. **Документация**: Позволяет через `docker inspect` узнать ожидаемые порты приложения без изучения исходного кода.
2. **Автоматическая публикация (`-P`)**: Если при запуске контейнера используется флаг `docker run -P`, Docker автоматически пробросит все порты, указанные в `EXPOSE`, на случайные свободные порты хоста.
3. **Оркестрация**: Информацию из `EXPOSE` используют системы мониторинга и Service Discovery для обнаружения эндпоинтов приложения.

### Взаимодействие с IPv6 и Rootless Docker

- **IPv6**: Инструкция `EXPOSE` не зависит от версии IP. Она определяет только порт и протокол (L4). Поддержка IPv6 настраивается на уровне Docker Daemon и сетевых драйверов.
- **Rootless Docker**: Хотя `EXPOSE` в Dockerfile не вызывает ошибок, в Rootless-режиме публикация портов ниже 1024 (например, `-p 80:80`) на хост-машине запрещена по умолчанию из-за отсутствия прав root.

### Сравнение: EXPOSE, -p и -P

| Метод | Где задается | Действие | Тип |
| :--- | :--- | :--- | :--- |
| **`EXPOSE`** | `Dockerfile` | Документирует порты в метаданных образа | Декларативный |
| **`-p`** | `docker run` | Явно пробрасывает порт хоста на порт контейнера | Императивный |
| **`-P`** | `docker run` | Пробрасывает все `EXPOSE` порты на случайные порты хоста | Автоматический |

**Важное замечание по Kubernetes:**
Kubernetes игнорирует инструкцию `EXPOSE`. Вместо нее в спецификации Pod используется параметр `containerPort`. Однако наличие `EXPOSE` в Dockerfile остается хорошей практикой для документирования образа.

## Практические сценарии

### Сценарий 1: Подготовка веб-сервера (Диапазоны)

Если приложение использует динамические порты для передачи данных (например, FTP или медиа-стриминг).

```dockerfile
FROM nginx:alpine
# Стандартные порты и диапазон для динамических соединений
EXPOSE 80 443 8000-8010/tcp
CMD ["nginx", "-g", "daemon off;"]
```

### Сценарий 2: Использование переменных

Порт можно передавать через аргументы сборки для гибкости.

```dockerfile
ARG APP_PORT=8080
ENV PORT=${APP_PORT}
EXPOSE ${PORT}
```

### Сценарий 3: Docker Compose и изоляция

В Docker Compose секция `expose` позволяет сделать порты доступными только внутри сети Compose (между контейнерами), не публикуя их на хосте.

```yaml
services:
  app:
    build: .
    expose:
      - "8080" # Виден базе данных, но закрыт снаружи
  db:
    image: postgres
```

## Дополнительная информация

### Безопасность

- **Внутренняя сеть**: Контейнеры в одной сети Docker могут общаться по любым портам, даже если они не указаны в `EXPOSE`.
- **Защита интерфейсов**: При использовании `-p` рекомендуется явно указывать IP хоста (например, `-p 127.0.0.1:80:80`), чтобы не открывать доступ ко всему интернету по умолчанию.
- **Минимализм**: Не документируйте порты, которые не предназначены для внешнего или межконтейнерного взаимодействия (например, отладочные порты в production-образе).
