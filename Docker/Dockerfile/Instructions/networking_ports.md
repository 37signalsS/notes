# Инструкция Dockerfile: EXPOSE

## Определения

**`EXPOSE`** — инструкция Dockerfile, которая информирует Docker о портах, которые контейнер будет прослушивать во время выполнения. Это декларативный механизм документирования сетевого интерфейса приложения.

## Основные концепции

### Декларативная природа EXPOSE

Инструкция `EXPOSE` является исключительно **документационной**. Она:

- **Не открывает** доступ к портам из внешней сети автоматически.
- **Не создает** правила `iptables` или перенаправления портов на хосте.
- Служит метаданными для взаимодействия человека и инструментов (например, Docker CLI или оркестраторов).

**Синтаксис:**

```dockerfile
EXPOSE <port> [<port>/<protocol>...]
```

**Примеры:**

```dockerfile
# TCP порт 80 по умолчанию
EXPOSE 80

# Явное указание протоколов
EXPOSE 80/tcp
EXPOSE 53/udp

# Несколько портов в одной инструкции
EXPOSE 80 443 8080/tcp
```

> **Важно:** Чтобы один и тот же порт прослушивал и TCP, и UDP, необходимо указать две отдельные строки: `EXPOSE 53/tcp` и `EXPOSE 53/udp`.

### Функции инструкции

1. **Документация**: Подсказывает разработчикам и администраторам, какие порты ожидает приложение.
2. **Автоматическая публикация (-P)**: Если при запуске контейнера используется флаг `docker run -P`, Docker автоматически пробросит все порты, указанные в `EXPOSE`, на случайные свободные порты хоста.
3. **Метаданные**: Информация о портах сохраняется в конфигурации образа и доступна через команду `docker inspect`.

### Сравнение: EXPOSE, -p и -P

| Метод | Где задается | Действие | Тип |
| :--- | :--- | :--- | :--- |
| **`EXPOSE`** | `Dockerfile` | Документирует порты в метаданных образа | Декларативный |
| **`-p`** | `docker run` | Явно пробрасывает порт хоста на порт контейнера | Императивный |
| **`-P`** | `docker run` | Пробрасывает все `EXPOSE` порты на случайные порты хоста | Автоматический |

Подробное описание использования флагов `-p` и `-P` приведено в **[Командах Docker CLI](../../docker_commands.md)**.

## Практические сценарии

### Сценарий 1: Подготовка веб-сервера

Инструкция позволяет пользователям образа сразу понять, какой порт пробрасывать.

```dockerfile
FROM nginx:alpine
# Документируем стандартные порты
EXPOSE 80 443
CMD ["nginx", "-g", "daemon off;"]
```

### Сценарий 2: Использование переменной окружения

Номер порта может быть задан динамически через `ARG` и `ENV`.

```dockerfile
ARG APP_PORT=8080
ENV PORT=${APP_PORT}
EXPOSE ${PORT}
```

### Сценарий 3: Работа в Docker Compose

В Docker Compose секция `expose` позволяет определить порты, которые будут доступны только связанным сервисам (link/network), но не будут опубликованы на хост-машине.

```yaml
services:
  web:
    image: my-app
    expose:
      - "8080" # Порт доступен другим контейнерам в сети, но не хосту
```

Подробнее см. **[Директивы Docker Compose](../../Docker_compose/docker_compose_directives.md)**.

## Дополнительная информация

### Безопасность и сетевое взаимодействие

- **Связь между контейнерами**: Контейнеры, находящиеся в одной пользовательской сети, могут взаимодействовать по любым портам без использования `EXPOSE`. Инструкция не влияет на внутреннюю маршрутизацию в сетях Docker.
- **Публикация портов**: Для доступа к приложению из внешней сети (или с хоста) порты должны быть опубликованы через `-p` или `-P`.
- **Риски безопасности**: Ошибки при публикации портов могут привести к несанкционированному доступу к сервисам (БД, кэши). Критически важные рекомендации по защите портов описаны в разделе **[Безопасность публикации портов](../../Docker_network/docker_network.md#безопасность-публикации-портов)**.
