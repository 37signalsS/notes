# Инструкции Dockerfile: COPY и ADD

## Определения

**Инструкция `COPY`** — базовая директива Dockerfile для копирования файлов и директорий из контекста сборки (или других стадий сборки) в файловую систему создаваемого образа.

**Инструкция `ADD`** — расширенная версия `COPY`, которая помимо обычного копирования поддерживает загрузку файлов по URL, автоматическую распаковку локальных архивов и клонирование Git-репозиториев.

**Контекст сборки (Build Context)** — набор локальных файлов и директорий, которые Docker-клиент передает демону Docker для выполнения сборки. Инструкции `COPY` и `ADD` могут обращаться только к ресурсам внутри этого контекста. Подробнее см. **[Контекст сборки и .dockerignore](../dockerfile_build_context.md)**.

## Основные концепции

### Синтаксис

Обе инструкции поддерживают два формата записи. Если пути содержат пробелы, обязателен формат JSON-массива.

```dockerfile
# Формат оболочки (Shell form)
COPY [OPTIONS] <src> ... <dest>

# Формат JSON-массива (Exec form)
COPY [OPTIONS] ["<src>", ... "<dest>"]
```

### Сравнение возможностей

| Функция | COPY | ADD |
| :--- | :--- | :--- |
| Копирование из контекста сборки | Да | Да |
| Копирование из других стадий (`--from`) | Да | Нет |
| Автоматическая распаковка tar-архивов | Нет | Да (только локальные) |
| Загрузка файлов по HTTP/HTTPS URL | Нет | Да |
| Клонирование Git-репозиториев | Нет | Да |
| Сохранение структуры (`--parents`) | Да | Нет |

**Рекомендация:** Всегда используйте `COPY`, если вам не требуются специфические функции `ADD`. Инструкция `COPY` более прозрачна и предсказуема. Для загрузки и распаковки ресурсов в production-образах предпочтительнее использовать `RUN curl/wget` с последующей очисткой в одном слое для минимизации размера образа.

### Доступные опции (флаги)

Использование большинства современных флагов требует включенного **[BuildKit](../dockerfile_buildkit.md)**.

| Опция | Инструкция | Описание |
| :--- | :--- | :--- |
| `--from` | `COPY` | Указывает источник: стадию сборки (multi-stage) или именованный образ. |
| `--chown` | `COPY`, `ADD` | Устанавливает владельца и группу (`user:group`). |
| `--chmod` | `COPY`, `ADD` | Устанавливает права доступа (например, `755` или `u+x`). |
| `--link` | `COPY`, `ADD` | Позволяет копировать файлы в независимый слой, что улучшает кэширование и ускоряет сборку. |
| `--parents` | `COPY` | Сохраняет родительские директории источника при копировании. |
| `--exclude` | `COPY`, `ADD` | Позволяет исключить файлы по шаблону (аналог `.dockerignore` внутри инструкции). |
| `--unpack` | `ADD` | Позволяет явно управлять распаковкой архивов (при значении `false` архив копируется как есть). |

## Практические сценарии

### Сценарий 1: Копирование с настройкой прав и владельца

Это позволяет избежать создания лишних слоев через `RUN chown/chmod`, которые увеличивают размер образа.

```dockerfile
# Копирование скрипта с предоставлением прав на исполнение
COPY --chmod=755 run.sh /usr/local/bin/

# Копирование приложения для конкретного непривилегированного пользователя
COPY --chown=node:node . /app
```

### Сценарий 2: Использование Multi-stage сборок

Копирование артефактов из промежуточных стадий — ключ к созданию минимальных образов.

```dockerfile
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY . .
RUN go build -o main .

FROM scratch
# Копируем только бинарный файл из стадии builder
COPY --from=builder /app/main /main
ENTRYPOINT ["/main"]
```

### Сценарий 3: Оптимизация кэширования через `--link`

Флаг `--link` помещает копируемые файлы в отдельный слой, не связанный с предыдущими. Это позволяет избежать инвалидации кэша, если изменились только предыдущие слои, но не копируемые файлы.

```dockerfile
# Файлы копируются в независимый слой
COPY --link config/ /etc/myapp/config/
```

### Сценарий 4: Сохранение структуры директорий

При использовании `--parents` структура каталогов от источника будет воспроизведена в месте назначения.

```dockerfile
# Результат: /app/src/api/main.go
COPY --parents src/api/main.go /app/
```

### Сценарий 5: Особенности путей назначения

Важно учитывать наличие завершающего слэша в пути назначения:

```dockerfile
# Если /target не существует:
COPY file.txt /target   # Создаст файл с именем target
COPY file.txt /target/  # Создаст директорию /target и положит туда file.txt
```
