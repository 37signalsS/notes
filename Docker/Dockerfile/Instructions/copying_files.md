# Инструкции Dockerfile: COPY и ADD

## Определения

**Инструкция `COPY`** — основная директива для копирования файлов и директорий из контекста сборки (или других стадий/образов) в файловую систему образа. Это наиболее прозрачный и рекомендуемый способ для большинства задач.

**Инструкция `ADD`** — расширенная версия `COPY`, которая поддерживает:
- Автоматическую распаковку локальных архивов (tar, gzip, bzip2 и др.).
- Загрузку файлов по HTTP/HTTPS URL (с поддержкой верификации через `--checksum`).
- Прямое клонирование Git-репозиториев (включая конкретные ветки, теги и коммиты).

**Контекст сборки (Build Context)** — набор файлов, передаваемых сборщику (BuildKit). Инструкции могут обращаться только к ресурсам внутри этого контекста. Подробнее см. **[Контекст сборки и .dockerignore](../dockerfile_build_context.md)**.

## Основные концепции

### Синтаксис

Обе инструкции поддерживают два формата. Формат JSON-массива обязателен, если пути содержат пробелы.

```dockerfile
# Формат оболочки (Shell form)
COPY [OPTIONS] <src> ... <dest>

# Формат JSON-массива (Exec form)
COPY [OPTIONS] ["<src>", ... "<dest>"]
```

> **Важно:** Путь назначения `dest` всегда интерпретируется относительно текущей рабочей директории (**[WORKDIR](./working_context.md)**).

### Сравнение возможностей (Актуально для 2025-2026)

| Функция | COPY | ADD |
| :--- | :--- | :--- |
| Локальное копирование | Да | Да |
| Multi-stage (`--from`) | Да | Да |
| Распаковка локальных архивов | Нет | Да (автоматически) |
| Загрузка по HTTP/HTTPS | Нет | Да |
| Клонирование Git-репозиториев | Нет | Да |
| Верификация по `--checksum` | Нет | Да (SHA256 или Git Commit SHA) |

**Рекомендация:** Используйте `COPY` для всех локальных операций. Используйте `ADD` только для Git-клонирования или верификации внешних ресурсов. 

**Нюансы с удаленными ресурсами:**
* **Раздувание образа**: Использование `ADD <URL>` создает слой с загруженным файлом. Если файл нужно распаковать и удалить исходник, `ADD` оставит его в слое навсегда. Для распаковки удаленных архивов часто эффективнее использовать `RUN --mount=type=cache curl ... | tar ...`, чтобы избежать лишнего веса.
* **Безопасность**: При использовании `ADD` для скачивания рекомендуется всегда фиксировать версию и использовать флаг `--checksum` для предотвращения Supply Chain атак.

### Сравнение возможностей (Актуально для 2025-2026)
Флаг `--link` (Docker 25.0+) копирует файлы в **независимый слой**, который не зависит от состояния предыдущих слоев.
- **Преимущество:** Если предыдущий слой (например, установка ОС) изменился, Docker просто заменит этот независимый слой в манифесте, не пересобирая его.
- **Ограничение:** Не поддерживает следование по симлинкам в пути назначения (`dest`).

### Сохранение структуры: `--parents`
Позволяет копировать файлы с сохранением их иерархии из источника.
```dockerfile
# syntax=docker/dockerfile:1.7-labs
COPY --parents app1/config.json /dist/
# Результат: /dist/app1/config.json
```

### Хирургическое исключение: `--exclude`
Позволяет задавать шаблоны исключения непосредственно в инструкции, не затрагивая глобальный `.dockerignore`.
```dockerfile
# syntax=docker/dockerfile:1.7-labs
COPY --exclude=**/*.tmp --exclude=tests/ . /app/
```

### Управление правами: `--chmod` и `--chown`
Установка прав и владельца в один шаг, что критично для безопасности и минимизации слоев.
```dockerfile
COPY --chown=appuser:appgroup --chmod=0755 script.sh /usr/local/bin/
```

## Нюансы поведения

### Копирование директорий
- При копировании папки (`COPY src/ /dest/`) копируется **содержимое** папки, а не она сама.
- Чтобы скопировать саму папку, используйте `COPY src /dest/src/` или флаг `--parents`.

### Работа с симлинками
- По умолчанию `COPY` и `ADD` копируют симлинк как есть (как ссылку).
- Если требуется копировать содержимое, на которое указывает ссылка, это необходимо делать через промежуточный `RUN`.
- **Внимание:** Флаг `--link` игнорирует симлинки в директории назначения.

### Подстановочные знаки (Wildcards)
Поддерживаются Go-шаблоны:
- `*` — любое количество символов.
- `?` — любой один символ.
```dockerfile
COPY requirements*.txt /tmp/  # Копирует requirements.txt, requirements-dev.txt и т.д.
```

## Безопасность и целостность

### Защита от Supply Chain атак
Инструкция `ADD` поддерживает флаг `--checksum` для верификации загружаемых ресурсов.
- **Для файлов:** SHA256 хеш.
- **Для Git:** Полный Git Commit SHA.
```dockerfile
ADD --checksum=sha256:d67... https://example.com/tool.tar.gz /tmp/
ADD --checksum=1a2b3c4d... https://github.com/org/repo.git#main /src
```

### Секреты
**Запрещено:** Копировать файлы с секретами (ключи, токены) через `COPY`/`ADD`. Они навсегда останутся в истории слоев.
**Решение:** Используйте секретные монтирования:
`RUN --mount=type=secret,id=api_key curl -H "Authorization: Bearer $(cat /run/secrets/api_key)" ...`

## Практические сценарии

### Сценарий 1: Эффективный Multi-stage для монорепозитория
Копирование только необходимых конфигов с сохранением структуры.

```dockerfile
# syntax=docker/dockerfile:1.7-labs
FROM alpine AS base
COPY --parents **/package.json /build/
# Теперь в /build/ лежат все package.json в своих папках для npm install
```

### Сценарий 2: Клонирование Git без установки зависимостей
Позволяет получить исходный код напрямую из репозитория, не захламляя образ утилитой `git`.

```dockerfile
# Клонирование конкретного тега без истории .git
ADD --keep-git-dir=false https://github.com/user/app.git#v2.1.0 /app
```

### Сценарий 3: Независимый слой с конфигурацией
Использование `--link` для статических конфигов, которые редко меняются.

```dockerfile
FROM nginx:alpine
# Изменение базового образа nginx не приведет к повторному копированию конфига
COPY --link nginx.conf /etc/nginx/nginx.conf
```
