# Инструкции Dockerfile: COPY и ADD

## Определения

**Инструкция `COPY`** — основная директива для копирования файлов и директорий из контекста сборки (или других стадий/образов) в файловую систему образа. Это предпочтительный способ для большинства задач.

**Инструкция `ADD`** — расширенная версия `COPY`, которая поддерживает:
- Загрузку файлов по HTTP/HTTPS URL (с поддержкой верификации через `--checksum`).
- Автоматическую распаковку локальных архивов (`.tar`, `.tar.gz`, `.bz2` и др.).
- Клонирование Git-репозиториев напрямую (включая поддержку веток и коммитов).

**Контекст сборки (Build Context)** — набор файлов, передаваемых демону Docker. Инструкции могут обращаться только к ресурсам внутри этого контекста. Подробнее см. **[Контекст сборки и .dockerignore](../dockerfile_build_context.md)**.

## Основные концепции

### Синтаксис

Обе инструкции поддерживают два формата. При наличии пробелов в путях обязателен формат JSON-массива.

```dockerfile
# Формат оболочки (Shell form)
COPY [OPTIONS] <src> ... <dest>

# Формат JSON-массива (Exec form)
COPY [OPTIONS] ["<src>", ... "<dest>"]
```

> **Важно:** Все пути `dest` являются относительными к текущей рабочей директории (**[WORKDIR](./working_context.md)**).

### Сравнение возможностей

| Функция | COPY | ADD |
| :--- | :--- | :--- |
| Локальное копирование | Да | Да |
| Multi-stage (`--from`) | Да | Да (с версии 1.7+) |
| Распаковка локальных архивов | Нет | Да (автоматически) |
| Загрузка по URL | Нет | Да |
| Клонирование Git-репозиториев | Нет | Да |
| Верификация контрольных сумм | Нет | Да (`--checksum`) |

**Рекомендация:** Используйте `COPY` для локальных файлов. Используйте `ADD` только для Git-клонирования или верификации внешних ресурсов. Для распаковки удаленных архивов часто эффективнее использовать `RUN curl ... | tar ...` в одном слое.

### Опции BuildKit

Использование новейших флагов требует включенного **[BuildKit](../dockerfile_buildkit.md)** и директивы `# syntax=docker/dockerfile:1` в начале файла.

| Опция | Инструкция | Описание |
| :--- | :--- | :--- |
| `--chown` | Обе | Устанавливает владельца:группу (`root:root` по умолчанию). |
| `--chmod` | Обе | Устанавливает права доступа (например, `0755`). |
| `--link` | Обе | Копирует файлы в **независимый слой**. Изменения в предыдущих слоях не инвалидируют кэш этой инструкции. |
| `--parents` | Обе | Сохраняет структуру родительских директорий источника. |
| `--exclude` | Обе | Исключает файлы по шаблону (аналог `.dockerignore` для одной команды). |
| `--checksum` | `ADD` | Проверяет SHA256 загружаемого URL. |
| `--unpack` | `ADD` | Явное управление распаковкой (при `false` архив не распакуется). |
| `--keep-git-dir`| `ADD` | Сохраняет папку `.git` при клонировании репозитория. |

## Нюансы поведения

### Копирование директорий
- Если вы копируете директорию (`COPY src/ /dest/`), Docker копирует **содержимое** директории, а не саму папку.
- Если вам нужно сохранить папку `src`, используйте `COPY src /dest/src/` или флаг `--parents`.

### Подстановочные знаки (Wildcards)
Docker поддерживает шаблоны Go (filepath.Match):
```dockerfile
COPY hom* /mydir/        # Копирует все файлы, начинающиеся на "hom"
COPY test?.json /app/    # ? заменяет любой один символ
```

### Слеш в пути назначения
- `COPY file.txt /app` → создаст файл `/app` (если папки нет).
- `COPY file.txt /app/` → создаст файл `/app/file.txt`.

## Безопасность

**Утечка секретов:** Никогда не копируйте файлы с секретами (ключи, токены) через `COPY`. Они останутся в истории слоев образа, даже если вы удалите их позже через `RUN rm`. 
- **Решение:** Используйте секретные монтирования: 
  `RUN --mount=type=secret,id=my_token ...`

## Практические сценарии

### Сценарий 1: Независимые слои (`--link`)
Это значительно ускоряет сборку в CI/CD, так как слой с файлами не зависит от базового образа.

```dockerfile
# syntax=docker/dockerfile:1
FROM alpine
# Слой с конфигами будет переиспользован, даже если базовый образ обновится
COPY --link config/ /etc/app/config/
```

### Сценарий 2: Клонирование Git напрямую
Позволяет избежать установки `git` в образ и сокращает время сборки.

```dockerfile
# Клонирование конкретного тега без истории .git
ADD --keep-git-dir=false https://github.com/user/repo.git#v1.0.0 /app/src
```

### Сценарий 3: Multi-stage и сохранение структуры
Копирование бинарных файлов из разных стадий с сохранением путей.

```dockerfile
FROM golang:1.22-alpine AS builder
WORKDIR /build
COPY . .
RUN go build -o /out/usr/bin/app .

FROM scratch
# Сохранит структуру /usr/bin/ внутри финального образа
COPY --from=builder --parents /out/./usr/bin/app /
```
