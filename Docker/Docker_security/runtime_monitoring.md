# Мониторинг безопасности контейнеров в Runtime

Данный документ описывает подходы к наблюдению за состоянием запущенных контейнеров для обнаружения аномалий и атак в реальном времени.

## Определения

**Мониторинг безопасности в Runtime (Runtime Security Monitoring)** — процесс непрерывного наблюдения за поведением запущенных контейнеров для выявления аномалий, подозрительной активности и несанкционированного доступа.

**eBPF (Extended Berkeley Packet Filter)** — технология ядра Linux для глубокого мониторинга системных вызовов, сетевых пакетов и файловых операций с минимальными накладными расходами. Подробнее см. в [**eBPF — виртуальная машина ядра**](../../Linux/Core/kernel/ebpf.md).

## Базовые концепции

### Проблема «слепой зоны» стандартного логирования

Стандартные системные логи хоста (`/var/log/syslog`, `auth.log`) не обеспечивают достаточной видимости событий внутри контейнеров. При совершении побега из контейнера (**container escape**) злоумышленник может изменять файлы на хосте (например, `/etc/shadow`), но логи не позволят однозначно связать это действие с конкретным контейнером. Команда `docker logs` в таких сценариях бесполезна, так как она собирает только stdout/stderr приложения.

### Ограничения auditd для контейнеров

Утилита **auditd** отслеживает системные вызовы и доступ к файлам, но имеет существенный недостаток в контексте Docker: она фиксирует низкоуровневый процесс (например, `runc` или `containerd`), инициировавший событие, но не предоставляет контекст контейнера (Container ID, имя образа). Подробнее о работе инструмента см. в **[`auditd`: Аудит событий безопасности](../../Linux/SystemAdministration/Logging/auditd.md)**.

### Решения на базе eBPF

Для полноценного мониторинга необходимо использовать инструменты, понимающие контекст контейнеров (Namespaces, Cgroups):

* **[Falco](../../Security/Tools/falco.md)** — стандартное решение для обнаружения угроз в runtime. Позволяет создавать гибкие правила для алертинга на подозрительные события.
* **Tetragon** — инструмент от команды Cilium. Помимо глубокого мониторинга, поддерживает блокировку вредоносных действий (**enforcement**) непосредственно на уровне ядра (например, завершение процесса при попытке чтения чувствительных файлов).
* **Cilium** — используется для мониторинга и фильтрации сетевого взаимодействия на уровнях L3–L7.

> **Важно:** Инструментам на базе eBPF требуются расширенные привилегии и доступ к пространствам имен хоста (например, `--pid=host`).

## Практические сценарии

### События, подлежащие обязательному мониторингу

Для обнаружения компрометации (установка майнеров, кража учетных данных, закрепление в системе) необходимо отслеживать:

1. **Доступ к критичным файлам:**
    * Чтение `/etc/shadow` или попытки модификации `/etc/passwd`.
    * Доступ к директориям SSH-ключей (`~/.ssh/`).
2. **Манипуляции с логами:**
    * Очистка истории команд (`.bash_history`) или системных журналов для сокрытия следов.
3. **Повышение привилегий (Privilege Escalation):**
    * Использование утилит `su`, `sudo` или запуск бинарников с установленным SUID-битом.
4. **Сетевые аномалии:**
    * Сканирование внутренних сетей из контейнера (**Lateral Movement**).
    * Неожиданные исходящие соединения к майнинг-пулам или командным серверам (C2).
