# Обзор безопасности Docker

Демон Docker (`dockerd`) по умолчанию работает от `root`. Любой процесс с доступом к Docker API получает полный `root`-доступ к хосту. Данный документ описывает основные векторы угроз и служит отправной точкой для изучения безопасности в экосистеме Docker.

## Определения

**Поверхность атаки (Attack Surface)** — совокупность точек входа, через которые злоумышленник может скомпрометировать Docker-инфраструктуру (демон, образы, контейнеры, реестры).

**Группа `docker`** — системная группа, пользователи которой могут выполнять команды `docker` без `sudo`. Предоставляет неконтролируемый доступ к Docker API, что эквивалентно правам `root` на хосте.

**Docker Socket (`/var/run/docker.sock`)** — **[Unix-сокет](../../Networking/Concepts/socket_api.md#unix-сокеты-af_unix)** для локального взаимодействия с демоном `dockerd`.

## Базовые концепции

Безопасность Docker можно разделить на несколько основных уровней:

### 1. Безопасность демона и хоста

Ошибки конфигурации демона или хостовой системы могут привести к полной компрометации сервера:
- Открытый сокет Docker (`/var/run/docker.sock` принадлежит `root:docker` с правами `660`).
- Открытый сетевой доступ по незашифрованному TCP порту `2375`. Должен использоваться только порт `2376` с TLS-аутентификацией.
- Запуск демона с избыточными правами. Для снижения рисков используются **User Namespaces** и **Rootless Docker**.

### 2. Безопасность внутри контейнера

Контейнеры используют общее ядро хоста. Неправильная конфигурация может позволить злоумышленнику совершить "побег из контейнера" (container escape):
- Работа от имени пользователя `root` внутри контейнера.
- Использование флага `--privileged`, отключающего механизмы изоляции ядра (Namespaces, Cgroups, Capabilities).
- Монтирование критичных директорий хоста (например, `/`, `/etc`) или проброс Docker Socket.

### 3. Безопасность образов и цепочки поставок

Использование уязвимых или вредоносных образов — частый вектор атаки:
- Наличие известных CVE в базовом образе или зависимостях приложения.
- Секреты (пароли, токены), запеченные в слоях образа.
- Подмена образов (решается проверкой цифровых подписей через Docker Content Trust / Cosign).
