# Подписание и верификация Docker-образов

Данный документ описывает методы обеспечения безопасности цепочки поставок для контейнерных образов через механизмы контроля целостности и подтверждения подлинности.

## Определения

**Подписание и верификация образов** — криптографический процесс, гарантирующий, что образ был создан доверенным источником и не подвергался изменениям в процессе хранения или передачи.

* **Целостность (Integrity)** — гарантия того, что содержимое образа (слои, конфигурация) соответствует оригиналу. Обеспечивается через неизменяемые идентификаторы — дайджесты.
* **Подлинность (Authenticity)** — подтверждение авторства образа. Реализуется с помощью цифровых подписей, привязанных к доверенным ключам или идентичностям (**OIDC — OpenID Connect**).
* **Аттестация (Attestation)** — подписанные метаданные, описывающие процесс сборки (**Provenance**) или состав программного обеспечения (**[SBOM — Software Bill of Materials](./docker_sbom.md)**). Соответствует уровням спецификации **SLSA (Supply-chain Levels for Software Artifacts)**.

## Базовые концепции

### 1. Гарантия целостности через дайджесты (Digest Pinning)

Docker и другие **OCI (Open Container Initiative)**-совместимые среды используют контентно-адресуемое хранилище. Каждый образ имеет уникальный идентификатор — дайджест (хеш-сумма `sha256`).

В отличие от тегов (например, `latest`, `v1.2`), которые являются мутабельными (их можно переназначить на другой образ), дайджест всегда указывает на один и тот же набор байтов. Использование дайджестов в файлах конфигурации защищает от атак подмены тега.

### 2. Гарантия подлинности через цифровые подписи

Подписи позволяют настроить политики запуска, разрешая выполнение только тех контейнеров, которые прошли проверку безопасности и были подписаны в доверенном пайплайне.

| Технология | Описание | Применимость |
| :--- | :--- | :--- |
| **Sigstore/Cosign** | Стандарт для OCI-артефактов. Поддерживает "keyless" подпись и аттестации. | **Рекомендуемый** |
| **Notary v1 / DCT** | Механизм **Docker Content Trust (DCT)**. Встроен в клиент Docker, использует GPG-подобную модель управления ключами. | Нативный, но устаревающий |
| **Simple Signing** | Механизм для сред на базе Podman и Skopeo, использующий GPG-подписи. | Специфичен для RHEL-систем |

## Практические сценарии

### 1. Использование дайджестов (Digest Pinning)

Для обеспечения максимальной безопасности в продуктивных средах следует фиксировать образ по его дайджесту.

```bash
# 1. Получение дайджеста для конкретного тега
docker inspect --format='{{index .RepoDigests 0}}' my-app:latest
# Результат: my-registry.com/my-app@sha256:4f32...

# 2. Запуск образа по дайджесту
docker run my-registry.com/my-app@sha256:4f32...
```

### 2. Генерация аттестаций при сборке (Docker Buildx)

Современный инструментарий сборки **BuildKit** позволяет автоматически создавать аттестации о происхождении и составе образа прямо во время сборки.

```bash
# Сборка образа с генерацией SLSA Provenance и SBOM
docker buildx build \
  --tag my-registry.com/my-app:1.0 \
  --provenance=true \
  --sbom=true \
  --push .
```

Эти метаданные сохраняются в реестре рядом с образом и могут быть проверены инструментами безопасности.

### 3. Политики верификации клиента (Podman/Skopeo)

В Linux-дистрибутивах (особенно RHEL/CentOS) политики доверия настраиваются глобально через файл `/etc/containers/policy.json`. Это позволяет запретить запуск любых образов, не подписанных доверенным ключом.

```json
{
    "default": [{"type": "reject"}],
    "transports": {
        "docker": {
            "my-registry.com": [
                {
                    "type": "sigstoreSigned",
                    "keyPath": "/etc/containers/keys/release-key.pub"
                }
            ]
        }
    }
}
```

### 4. Верификация подписей через Cosign

Подробное руководство по установке и работе с **Cosign** приведено в разделе **[Sigstore: Безопасность цепочки поставок](../../Security/Tools/sigstore.md)**.

```bash
# Проверка подписи образа перед развертыванием
cosign verify --key release-key.pub my-registry.com/my-app:1.0
```

## Дополнительная информация

**Docker Content Trust (DCT):**
Активируется переменной окружения `export DOCKER_CONTENT_TRUST=1`. При включении Docker будет автоматически подписывать образы при `push` и проверять подписи при `pull`. Однако сложность управления иерархией ключей в DCT делает Sigstore более предпочтительным выбором для современных систем.
