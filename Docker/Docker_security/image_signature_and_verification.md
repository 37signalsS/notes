# Подписание и верификация Docker-образов

## Определения

*   **Подписание и верификация образов** — это криптографический процесс, который гарантирует, что образ получен из доверенного источника (**подлинность**) и не был изменен в процессе доставки (**целостность**).
*   **Целостность (Integrity)**: Гарантия того, что контент образа не был изменен. Обеспечивается сверкой дайджестов (`sha256`) слоев и манифеста.
*   **Подлинность (Authenticity)**: Гарантия того, что образ был создан и опубликован доверенным лицом. Обеспечивается цифровыми подписями.
*   **Аттестация (Attestation)**: Подписанные метаданные, прикрепленные к образу. Аттестации содержат информацию о происхождении (provenance), составе (**[SBOM](./docker_sbom.md)**) или результатах сканирования.

## Основные концепции

### 1. Целостность: Фиксация по дайджесту (Digest Pinning)

Docker и другие OCI-совместимые среды выполнения по умолчанию проверяют дайджесты слоев при скачивании образа. Использование полного дайджеста образа (`image@sha256:...`) вместо изменяемого тега (`image:latest`) является базовой практикой для обеспечения целостности.

### 2. Подлинность: Цифровые подписи

Цифровые подписи доказывают, кто именно подписал артефакт. Это позволяет администраторам кластеров настраивать политики, разрешающие запуск только тех образов, которые подписаны доверенными ключами или идентификаторами.

| Технология | Описание | Статус |
| :--- | :--- | :--- |
| **Sigstore/Cosign** | Современный стандарт для подписи OCI-артефактов, поддерживающий keyless-подход. **[Подробнее о Sigstore](../../Security/Tools/sigstore.md)**. | **Рекомендуемый** |
| **Notary v1 / DCT** | Устаревший механизм Docker (Docker Content Trust). | Устарел (Legacy) |
| **Simple Signing (GPG)**| Механизм на основе GPG, используется в экосистеме Podman/Skopeo. | Специфичен для инструментов |

Общая концепция подписания артефактов подробно раскрыта в документе **[Artifact Signing](../../Security/Supply_Chain_Security/artifact_signing.md)**.

## Практические сценарии

### 1. Фиксация по дайджесту (гарантия целостности)

```bash
# 1. Получить дайджест для образа
docker inspect alpine:latest --format '{{index .RepoDigests 0}}'
# Вывод: docker.io/library/alpine@sha256:21a3deaa...

# 2. Использовать дайджест в production
# image: alpine@sha256:21a3deaa...
```

### 2. Проверка подписи с помощью Cosign и Sigstore

**[Cosign](../../Security/Tools/sigstore.md)** — это основной инструмент для подписания и проверки OCI-артефактов в экосистеме Sigstore.

```bash
# Подписать образ (например, в CI/CD)
cosign sign --key my-key.pem my-registry/my-app:1.0

# Проверить подпись образа перед запуском
cosign verify --key my-key.pub my-registry/my-app:1.0
```

### 3. Создание аттестаций о происхождении (SLSA Provenance)

BuildKit может автоматически генерировать и прикреплять к образу аттестации, соответствующие спецификации **[SLSA](https://slsa.dev/)**, что позволяет отследить всю цепочку сборки.

```bash
docker buildx build \
  --tag my-registry/my-app:1.0 \
  --provenance=true \
  --sbom=true \
  .
```
Аттестации `provenance` и `sbom` будут подписаны и прикреплены к манифесту образа.

### 4. Принудительная проверка в Podman (`policy.json`)

Инструменты `podman` и `skopeo` используют системный файл `/etc/containers/policy.json` для определения политик доверия.

```json
// /etc/containers/policy.json
{
  "default": [{"type": "insecureAcceptAnything"}],
  "transports": {
    "docker": {
      "my-registry.example.com": [
        {
          "type": "sigstoreSigned",
          "keyPath": "/etc/containers/cosign.pub"
        }
      ]
    }
  }
}
```
При такой политике `podman pull my-registry.example.com/app` автоматически провалится, если образ не подписан ключом `cosign.pub`.

## Дополнительная информация

### Устаревший механизм: Docker Content Trust (Notary v1)

Активируется через `export DOCKER_CONTENT_TRUST=1`. Принудительно проверяет подписи для всех операций `pull`, `push`, `build`. **Не рекомендуется** для новых систем в пользу Sigstore/Cosign из-за сложностей с управлением ключами и отсутствия поддержки для аттестаций.

### Сводка механизмов

*   **Целостность (Digest)**: Встроена в Docker/containerd. Защищает от случайных или умышленных изменений контента.
*   **Подлинность (Signature)**: Проверяет источник. Требует настройки политик (например, через admission-контроллеры в Kubernetes или `policy.json` в Podman).
*   **Происхождение (Attestation)**: Расширяет доверие за счет подписанных метаданных о процессе сборки.
