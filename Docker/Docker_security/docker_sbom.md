# Программная спецификация (SBOM) в Docker

## Определения

**Программная спецификация (Software Bill of Materials, SBOM)** — это формальный, машиночитаемый перечень всех компонентов, из которых состоит программное обеспечение. Его можно представить как "список ингредиентов" для приложения.

В этот список входят:
-   Все прямые и транзитивные зависимости (библиотеки, модули, фреймворки).
-   Информация о версиях каждого компонента.
-   Данные о лицензиях.
-   Уникальные идентификаторы компонентов (например, PURL, CPE).

## Базовые концепции

### Назначение SBOM

SBOM является краеугольным камнем безопасности цепочки поставок программного обеспечения (Software Supply Chain Security).
-   **Прозрачность:** Вы точно знаете, из чего состоит ваше приложение.
-   **Управление уязвимостями:** При появлении новой уязвимости (например, Log4Shell) можно мгновенно проверить, затронуты ли системы, просканировав SBOM, вместо сканирования всех производственных систем.
-   **Управление лицензиями:** SBOM помогает отслеживать лицензии всех зависимостей, предотвращая юридические риски.
-   **Целостность ПО:** Наличие SBOM — первый шаг к проверке того, что компоненты не были изменены или подменены.

### Стандартные форматы

Существует два основных стандарта, оба из которых машиночитаемы и широко поддерживаются:

| Формат | Основной фокус | Кем разработан |
| :--- | :--- | :--- |
| **SPDX (Software Package Data Exchange)** | Соответствие лицензиям (Compliance) | Linux Foundation |
| **CycloneDX** | Безопасность и уязвимости | OWASP |

-   **SPDX:** Более старый и зрелый формат, изначально созданный для решения юридических вопросов, связанных с лицензиями. Он очень подробный. Является стандартом ISO/IEC 5962:2021.
-   **CycloneDX:** Более современный и легковесный формат, созданный специально для нужд кибербезопасности. Он сфокусирован на анализе уязвимостей и отлично подходит для автоматизации в CI/CD.

## Практические сценарии

### 1. Генерация SBOM с помощью Syft

**Syft** — это инструмент командной строки от Anchore для генерации SBOM из образов контейнеров.

**Установка (Linux):**
```bash
curl -sSfL https://get.anchore.io/syft | sudo sh -s -- -b /usr/local/bin
```

**Примеры генерации:**
-   **В формате CycloneDX JSON (самый частый сценарий):**
    ```bash
    syft python:3.9-slim -o cyclonedx-json > sbom.json
    ```
-   **В формате SPDX JSON:**
    ```bash
    syft python:3.9-slim -o spdx-json > sbom.spdx.json
    ```

### 2. Интеграция в CI/CD: Syft + Grype + Copacetic

Генерация SBOM — это только половина дела. Настоящая польза раскрывается при полном цикле управления уязвимостями.

1.  **Генерация SBOM (`Syft`):** После сборки образа `Syft` создает его SBOM.
    ```bash
    syft my-app:1.2.3 -o cyclonedx-json > sbom.json
    ```
2.  **Сканирование SBOM (`Grype`):** `Grype` сканирует SBOM и генерирует отчет об уязвимостях.
    ```bash
    grype sbom:sbom.json -o json > report.json
    ```
3.  **Автоматическое исправление (`Copacetic`):** `Copacetic` анализирует отчет и создает исправленную версию образа без полной пересборки.
    ```bash
    copa patch -i my-app:1.2.3 -r report.json -t my-app:1.2.3-patched
    ```
