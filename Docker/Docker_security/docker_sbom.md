# Программная спецификация (SBOM) в Docker

## Определения

* **Программная спецификация (Software Bill of Materials, SBOM)** — это формальный, машиночитаемый перечень всех компонентов, из которых состоит программное обеспечение. Его можно представить как "список ингредиентов" для Docker-образа. В SBOM входят все прямые и транзитивные зависимости, их версии, лицензии и уникальные идентификаторы (PURL, CPE).
* **Назначение SBOM**: SBOM — это фундаментальный элемент **[безопасности цепочки поставок ПО](../../Security/Supply_Chain_Security/overview.md)**, который обеспечивает:
  * **Прозрачность**: Точное знание состава программного артефакта.
  * **Управление уязвимостями**: Быстрый поиск затронутых систем при появлении новых угроз (например, Log4Shell) путем анализа SBOM, а не производственных систем.
  * **Контроль лицензий**: Автоматизированный аудит лицензий всех зависимостей.

## Основные концепции

### Стандартные форматы SBOM

Существует два основных формата, каждый со своим фокусом:

| Формат | Основной фокус | Разработчик | Примечание |
| :--- | :--- | :--- | :--- |
| **SPDX** | Соответствие лицензиям | Linux Foundation | Зрелый, детальный, стандарт ISO/IEC 5962:2021. |
| **CycloneDX** | Безопасность, уязвимости | OWASP | Легковесный, ориентирован на безопасность и CI/CD. |

### Место SBOM в экосистеме безопасности

SBOM сам по себе является лишь списком. Его истинная ценность раскрывается в связке с другими инструментами:

1. **Генерация**: Инструменты вроде `Syft` или `docker buildx` создают SBOM.
2. **Анализ**: SBOM становится входными данными для **[сканеров уязвимостей](./vulnerability_scanning.md)** (например, `Grype`, `Trivy`), которые находят в компонентах известные CVE.
3. **Подтверждение**: SBOM может быть криптографически подписан как аттестация, подтверждая его целостность и происхождение, что является частью процесса **[подписания образов](./image_signature_and_verification.md)**.

## Практические сценарии

### 1. Генерация SBOM с помощью Syft

**Syft** — популярный инструмент от Anchore для генерации SBOM из образов контейнеров.

```bash
# Генерация SBOM в формате CycloneDX JSON (рекомендуется для безопасности)
syft python:3.9-slim -o cyclonedx-json > sbom.json

# Генерация SBOM в формате SPDX JSON (для анализа лицензий)
syft python:3.9-slim -o spdx-json > sbom.spdx.json
```

### 2. Генерация SBOM при сборке с Docker BuildKit

Начиная с `docker buildx` v0.10+, SBOM можно генерировать как аттестацию прямо во время сборки и прикреплять к манифесту образа в реестре.

```bash
# Собрать образ и прикрепить к нему SBOM-аттестацию
docker buildx build \
  --tag my-registry/my-app:1.0.0 \
  --provenance=true \
  --sbom=true \
  .

# Проверить наличие аттестации в реестре
docker buildx imagetools inspect my-registry/my-app:1.0.0 --format '{{ json .SBOM }}'
```

Этот метод является предпочтительным, так как упрощает CI/CD-пайплайны.

### 3. CI/CD-пайплайн: Генерация, сканирование и исправление

Полный цикл управления уязвимостями может выглядеть так:

1. **Генерация SBOM (`Syft`):**

    ```bash
    syft my-app:1.2.3 -o cyclonedx-json > sbom.json
    ```

2. **Сканирование SBOM на уязвимости (`Grype`):**

    ```bash
    grype sbom:sbom.json -o json > report.json
    ```

3. **Автоматическое исправление (`Copacetic`):**

    ```bash
    copa patch -i my-app:1.2.3 -r report.json -t my-app:1.2.3-patched
    ```

## Дополнительная информация

Создание и анализ SBOM являются частью более широкой темы **[безопасности цепочки поставок ПО (Supply Chain Security)](../../Security/Supply_Chain_Security/overview.md)**. Для полной защиты необходимо также внедрить:

* **[Сканирование уязвимостей](./vulnerability_scanning.md)** на всех этапах жизненного цикла ПО.
* **[Подписание и верификацию образов](./image_signature_and_verification.md)** для гарантии целостности и происхождения.
