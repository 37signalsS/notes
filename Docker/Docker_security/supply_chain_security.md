# Безопасность цепочки поставок (Supply Chain Security)

## 1. Подписание образов

Цифровая подпись гарантирует две вещи:
1.  **Целостность:** Образ не был изменен с момента его подписания.
2.  **Происхождение:** Вы можете быть уверены, кто именно создал и подписал образ.

### Docker Content Trust (DCT)

**Docker Content Trust (DCT)** — это встроенный в Docker механизм, основанный на проекте **Notary**. Он позволяет подписывать и верифицировать образы.

DCT включается установкой переменной окружения:
```sh
export DOCKER_CONTENT_TRUST=1
```
После этого `docker pull` будет скачивать только подписанные образы, а `docker push` потребует от вас подписать образ перед загрузкой.

**Проблема:** DCT, хотя и является встроенным, считается несколько устаревшим и сложным в настройке (требует развертывания сервера Notary). Индустрия в основном перешла на более гибкое решение — Sigstore/Cosign.

### Sigstore/Cosign: Современная альтернатива

**Cosign** — это инструмент проекта **Sigstore**, который стал стандартом де-факто для подписи OCI-совместимых артефактов.

**Почему Cosign лучше:**
-   **Независимость:** Работает с любым OCI-реестром (Docker Hub, Harbor, GCR и т.д.).
-   **Простота:** Хранит подписи прямо в реестре рядом с образом, не требуя отдельного сервера.
-   **Keyless Signing:** Поддерживает "безключевую" подпись через OIDC-провайдеров (Google, GitHub), что идеально подходит для автоматизации в CI/CD.

**Пример процесса подписи и верификации с Cosign:**
1.  **Установка:**
    ```bash
    # Загружаем конкретную версию (например, v2.6.0)
    curl -sL -o cosign "https://github.com/sigstore/cosign/releases/download/v2.6.0/cosign-linux-amd64"
    sudo mv cosign /usr/local/bin/cosign
    sudo chmod +x /usr/local/bin/cosign
    ```
2.  **Генерация ключевой пары (классический способ):**
    ```bash
    cosign generate-key-pair # Создаст cosign.key и cosign.pub
    ```
3.  **Подпись образа:**
    ```bash
    cosign sign --key cosign.key your-registry/your-app:1.0.0
    ```
4.  **Верификация образа:**
    ```bash
    cosign verify --key cosign.pub your-registry/your-app:1.0.0
    ```

## 2. Статический анализ образов (SAST)

### Инструменты

-   **Trivy:** Очень популярный и простой в использовании сканер.
    ```bash
    # Сканирование образа на критические и высокие уязвимости
    trivy image --severity HIGH,CRITICAL python:3.13-slim
    # Сканирование Dockerfile на плохие практики
    trivy config /path/to/your/Dockerfile
    ```
-   **Grype:** Альтернатива от Anchore, также широко используется.
    ```bash
    # Завершить выполнение с ошибкой, если найдены уязвимости уровня "high" или выше (полезно для CI)
    grype python:3.13-slim --fail-on high
    ```
-   **Clair:** Серверный сканер, который часто интегрируется с Docker-реестрами (Harbor, Quay) для сканирования образов при их загрузке.
-   **Docker Scout:** Встроенный инструмент Docker для анализа уязвимостей.
    ```bash
    docker scout quickview ваш-образ:тег
    ```
-   **GitHub Dependabot:** Автоматически отслеживает и предлагает обновить уязвимые базовые образы в `Dockerfile` прямо в вашем репозитории.
-   **Copacetic:** Инструмент для "горячего" исправления уязвимостей в образах без полной пересборки. Он анализирует отчет сканера (например, Trivy) и применяет патчи к пакетам.
    ```bash
    # 1. Сканируем и получаем отчет
    trivy image --format json --output report.json my-app:1.0
    # 2. Исправляем образ на основе отчета
    copa patch -i my-app:1.0 -r report.json -t my-app:1.0-patched
    ```

## 3. Динамический анализ (Runtime Security)

Динамический анализ отслеживает поведение контейнеров во время их работы и обнаруживает аномалии.

-   **Falco:** Проект [CNCF](../../Concepts/SRE/cncf_overview.md), который стал стандартом де-факто для мониторинга безопасности во время выполнения.
    -   **Как работает:** `Falco` подключается к ядру Linux через eBPF или модуль ядра и отслеживает системные вызовы (`syscalls`). На основе набора правил он обнаруживает подозрительное поведение (например, запуск shell в контейнере, запись в `/etc`, неожиданное сетевое соединение) и генерирует оповещение.

## 4. Аудит конфигураций и образов

-   **Dive:** Инструмент для послойного анализа Docker-образа. Помогает найти и устранить "раздутые" слои, уменьшая размер и поверхность атаки.
    ```sh
    dive my-app:1.0.0
    ```
-   **Docker Bench Security:** Скрипт, который проверяет вашу конфигурацию Docker на соответствие лучшим практикам безопасности от CIS (Center for Internet Security).
    ```sh
    git clone https://github.com/docker/docker-bench-security.git
    cd docker-bench-security
    sudo sh docker-bench-security.sh
    ```

## 5. Анализ IaC (Infrastructure as Code)

-   **KICS (Keeping Infrastructure as Code Secure):** Бесплатный open-source статический анализатор, который сканирует файлы IaC (Terraform, Kubernetes, **Docker**, Ansible) на наличие уязвимостей и неправильных конфигураций.
