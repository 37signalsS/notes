# Драйвер сети: ipvlan

## Определения

**Драйвер IPvlan** — это сетевой драйвер Docker, который похож на `macvlan`, но позволяет контейнерам использовать MAC-адрес хоста, распределяя IP-адреса на уровнях L2 или L3. Это может упростить сетевые политики в некоторых средах.

## Базовые концепции

Принцип работы драйвера `ipvlan` заключается в создании виртуальных сетевых интерфейсов для контейнеров, которые подключаются к родительскому сетевому интерфейсу хоста. В отличие от `macvlan`, `ipvlan` не присваивает контейнерам уникальные MAC-адреса; вместо этого все контейнеры, подключенные к одному родительскому интерфейсу через `ipvlan`, используют MAC-адрес этого хостового интерфейса.

`ipvlan` поддерживает два режима работы:

*   **L2-режим (Bridge Mode):** Контейнеры могут напрямую общаться друг с другом, как если бы они находились в одной L2-сети.
*   **L3-режим (Routed Mode):** Трафик между контейнерами маршрутизируется хостом. Этот режим обеспечивает большую гибкость в маршрутизации и сегментации сети.

<h2>Практические сценарии</h2>

Создание `ipvlan`-сети аналогично созданию `macvlan`-сети. Для создания `ipvlan`-сети требуется указать драйвер `-d ipvlan` и родительский интерфейс `-o parent=eth0`.

1.  **Определить параметры сети и родительский интерфейс:**
    Аналогично `macvlan`, определите имя основного сетевого интерфейса хоста и его параметры (подсеть, шлюз).

    ```bash
    ip addr show
    ```

2.  **Создать `ipvlan`-сеть:**
    Используем полученные данные для создания сети.

    ```bash
    docker network create -d ipvlan 
      --subnet=192.168.1.0/24 
      --gateway=192.168.1.1 
      -o parent=eth0 
      ipvlan-net
    ```

3.  **Запустить контейнер в созданной сети:**

    ```bash
    docker run -d --name my-ipvlan-app --network ipvlan-net --ip 192.168.1.51 alpine sleep infinity
    ```

## Дополнительная информация

*   **Упрощение сетевых политик:** Использование MAC хоста может упростить управление сетевыми политиками, так как коммутаторам не нужно обрабатывать множество MAC-адресов от разных контейнеров.
*   **Тонкости маршрутизации:** `ipvlan` предоставляет больше контроля над маршрутизацией на L3-уровне, что может быть полезно в сложных сетевых инфраструктурах.
*   Как и `macvlan`, `ipvlan` не всегда доступен в Docker Desktop из-за особенностей виртуализации.
