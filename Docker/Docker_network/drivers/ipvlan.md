# Драйвер сети: ipvlan

## Определения

**Драйвер `ipvlan`** — это сетевой драйвер Docker, который предоставляет контейнерам уникальные IP-адреса в локальной сети, при этом все контейнеры используют **один MAC-адрес** родительского сетевого интерфейса хоста.

Это позволяет избежать проблем с безопасностью на коммутаторах, которые могут блокировать порт при появлении множества MAC-адресов.

## Основные концепции

**Режимы работы:**

- **L2 (по умолчанию):** Контейнеры находятся в том же L2-сегменте, что и хост. Все контейнеры и хост должны быть в одной подсети. Подходит для плоских сетей.
- **L3:** Маршрутизация L3 между контейнерами и сетью хоста. L2-коммуникации (ARP, broadcast) отключены. Каждый контейнер может быть в своей подсети.
- **L3S:** Режим L3 с валидацией источника (source validation). Совместим с iptables chain FORWARD.

**Сравнение с [`macvlan`](./macvlan.md):**

- **MAC-адрес:** `ipvlan` использует MAC хоста, `macvlan` назначает уникальный MAC каждому контейнеру.
- **Совместимость:** `ipvlan` имеет высокую совместимость с коммутаторами и Wi-Fi. `macvlan` может блокироваться на портах с "port security".
- **Производительность:** Одинаково высокая у обоих драйверов (близка к нативной).
- **Изоляция от хоста:** По умолчанию контейнеры не могут общаться с хостом в обоих режимах.

**Рекомендация:** Начинайте с `ipvlan` — он универсален и реже вызывает проблемы с сетевым оборудованием. Используйте `macvlan`, только если требуется уникальный MAC-адрес для каждого контейнера.

## Практические сценарии

**Создание сети ipvlan в режиме L2:**

1. Определите параметры сети хоста:

    ```bash
    ip addr show eth0
    ip route show default
    ```

2. Создайте сеть `ipvlan`:

    ```bash
    docker network create \
      -d ipvlan \
      --subnet=192.168.1.0/24 \
      --gateway=192.168.1.1 \
      -o parent=eth0 \
      my_ipvlan_net
    ```

3. Запустите контейнер в этой сети:

    ```bash
    docker run -d --name my-ipvlan-app \
      --network my_ipvlan_net \
      --ip 192.168.1.101 \
      nginx:alpine
    ```

Контейнер доступен по адресу `192.168.1.101` с любого устройства в локальной сети.

## Дополнительная информация

**Ограничение связи с хостом:** По умолчанию контейнеры на `ipvlan` и `macvlan` не могут обмениваться трафиком с хостом. Требуется создание дополнительных сетевых интерфейсов.

**Поддержка VLAN:** Драйвер работает с VLAN через sub-интерфейсы (например, `eth0.100` для VLAN 100):

```bash
docker network create -d ipvlan -o parent=eth0.100 ...
```
