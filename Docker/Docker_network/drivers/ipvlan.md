# Docker: Сетевой драйвер `ipvlan`

## Определения

**Драйвер `ipvlan`** — это сетевой драйвер Docker, который предоставляет контейнерам уникальные IP-адреса в локальной сети, но при этом все они используют **один и тот же MAC-адрес** родительского сетевого интерфейса хоста.

Это дает контейнерам полный доступ к локальной сети, как и `macvlan`, но позволяет избежать проблем с безопасностью на коммутаторах, которые могут блокировать порт при появлении на нем множества MAC-адресов.

## Основные концепции

### Режимы работы `ipvlan`

`ipvlan` предлагает два основных режима работы, которые определяют, как трафик передается между контейнерами и сетью.

- **L2 Mode (Режим L2, по умолчанию)**:
  - **Принцип**: Контейнеры ведут себя так, как будто они подключены к тому же L2-сегменту (broadcast domain), что и хост-интерфейс.
  - **Адресация**: Все контейнеры и хост должны находиться в одной подсети.
  - **Использование**: Наиболее распространенный режим, простой в настройке для плоских сетей.

- **L3 Mode (Режим L3)**:
  - **Принцип**: Этот режим обеспечивает маршрутизацию L3 между контейнерами и сетью хоста. Он отключает L2-коммуникации (ARP-запросы, broadcast-трафик) между контейнерами.
  - **Адресация**: Каждый контейнер может находиться в своей собственной, изолированной подсети. Драйвер `ipvlan` выступает в роли маршрутизатора.
  - **Использование**: Продвинутый сценарий для сложной сетевой сегментации и маршрутизации, когда требуется полная изоляция на канальном уровне.

### Сравнение с `macvlan`

Выбор между `ipvlan` и `macvlan` — это ключевое решение при интеграции контейнеров в физическую сеть.

| Характеристика | `ipvlan` | `macvlan` |
| :--- | :--- | :--- |
| **MAC-адрес** | Все контейнеры **используют MAC-адрес хоста** | Каждый контейнер получает **уникальный MAC-адрес** |
| **Совместимость** | ✅ **Высокая.** Большинство коммутаторов и Wi-Fi точек доступа без проблем работают с одним MAC на порту. | ⚠️ **Могут быть проблемы.** Некоторые коммутаторы с включенным "port security" или Wi-Fi сети могут блокировать порт, если с него приходит трафик от множества MAC-адресов. |
| **Производительность** | Очень высокая (близка к нативной) | Очень высокая (близка к нативной) |
| **Изоляция от хоста** | По умолчанию контейнеры **не могут** общаться с хостом | По умолчанию контейнеры **не могут** общаться с хостом |
| **Простота** | Считается более современным и гибким | Проще для понимания (каждый контейнер — как отдельная ВМ) |

> **Рекомендация:** Начинайте с `ipvlan`, так как он более универсален и реже вызывает проблемы с сетевым оборудованием. Используйте `macvlan` только если вам по какой-то причине требуется, чтобы каждый контейнер имел уникальный MAC-адрес.

## Практические сценарии

### Создание сети `ipvlan` в режиме L2

Этот сценарий позволяет выдать контейнеру IP-адрес из вашей домашней или офисной сети.

1. **Определите параметры сети хоста:**
    Найдите имя вашего основного сетевого интерфейса (`eth0`, `enp3s0` и т.д.), его IP-адрес и шлюз.

    ```bash
    ip addr show eth0
    ip route show default
    ```

    *Допустим, наша сеть `192.168.1.0/24`, шлюз `192.168.1.1`, а интерфейс хоста — `eth0`.*

2. **Создайте сеть `ipvlan`:**

    ```bash
    docker network create \
      -d ipvlan \
      --subnet=192.168.1.0/24 \
      --gateway=192.168.1.1 \
      -o parent=eth0 \
      my_ipvlan_net
    ```

    - `-d ipvlan`: Указываем, что используем драйвер `ipvlan`.
    - `--subnet`, `--gateway`: Задаем параметры подсети, чтобы Docker мог управлять IP-адресами.
    - `-o parent=eth0`: **Обязательный параметр**, который привязывает `ipvlan`-сеть к физическому интерфейсу хоста.

3. **Запустите контейнер в этой сети:**
    Можно позволить Docker выдать IP автоматически или указать его вручную.

    ```bash
    # Запуск с указанием статического IP
    docker run -d --name my-ipvlan-app \
      --network my_ipvlan_net \
      --ip 192.168.1.101 \
      nginx:alpine
    ```

Теперь контейнер `my-ipvlan-app` доступен по адресу `192.168.1.101` с любого другого устройства в вашей локальной сети.

## Дополнительная информация

- **Ограничение связи с хостом**: По умолчанию, из соображений безопасности, контейнеры, использующие драйверы `ipvlan` или `macvlan`, **не могут** обмениваться трафиком с хост-системой, на которой они запущены. Для обхода этого ограничения требуется создание дополнительных сетевых интерфейсов.

- **Поддержка VLAN**: Драйвер `ipvlan` (как и `macvlan`) отлично работает с VLAN. Для этого на хосте нужно создать sub-интерфейс для нужного VLAN (например, `eth0.100` для VLAN 100) и использовать его в качестве `parent`.

  ```bash
  # Указываем VLAN-интерфейс как родительский
  docker network create -d ipvlan -o parent=eth0.100 ...
  ```
