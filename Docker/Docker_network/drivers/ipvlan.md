# Сетевой драйвер ipvlan

## Определения

- **Драйвер ipvlan** — это высокопроизводительный сетевой драйвер Docker, позволяющий контейнерам иметь уникальные IP-адреса, разделяя при этом **единый MAC-адрес** родительского физического интерфейса хоста.
- **Network L3 Routing** — режим передачи данных, при котором пакеты направляются на основе IP-адресов без использования ARP-запросов и широковещательных рассылок уровня L2.

## Основные концепции

В 2026 году (Docker v28+, ядра Linux 6.x) `ipvlan` стал основным выбором для высокоплотных микросервисных архитектур и публичных облаков (AWS, Azure, GCP), где использование нескольких MAC-адресов на одном порту часто заблокировано или ограничено.

### Режимы работы

1. **L2 (Layer 2 — по умолчанию)**:
   - Контейнеры находятся в том же широковещательном домене, что и хост.
   - Требуется наличие внешнего шлюза в той же подсети.
   - Поддерживает стандартный ARP.
2. **L3 (Layer 3 — маршрутизация)**:
   - Работает как маршрутизатор: трафик между контейнерами и внешней сетью передается на уровне IP.
   - **Преимущество**: Полное отсутствие ARP-штормов и широковещательного трафика, что критично при запуске более 1000 контейнеров на одном хосте.
   - **Особенности**: Не поддерживает DHCP; требует статической настройки или внешнего IPAM-контроллера.
3. **L3S (Layer 3 Symmetric)**:
   - Симметричный режим L3, который пропускает трафик через сетевой стек хоста.
   - **Зачем нужен**: Позволяет использовать **Stateful Firewalls** (iptables/nftables) и политики безопасности для фильтрации трафика контейнеров.
   - Совместим с современными CNI-плагинами (Cilium, Calico) в режиме `ipvlan`.

### Производительность и масштабируемость (Состояние на 2026 год)

- **Ядро Linux 6.x**: Начиная с ядер 6.8+, `ipvlan` поддерживает технологии **BIG TCP** (пакеты до 512 КБ) и **Hardware GRO**, что позволяет достигать скорости передачи данных свыше 100 Гбит/с с минимальной нагрузкой на CPU.
- **Облачная совместимость**: В отличие от `macvlan`, `ipvlan` идеально работает в облаках, так как не меняет MAC-адрес отправителя, проходя через проверки безопасности облачных гипервизоров.
- **Плотность**: Позволяет запускать десятки тысяч контейнеров на одном порту коммутатора, не переполняя его CAM-таблицу.

### Сравнение с [macvlan](./macvlan.md)

| Характеристика | ipvlan | [macvlan](./macvlan.md) |
| :--- | :--- | :--- |
| **MAC-адрес** | MAC хоста (общий) | Уникальный для каждого контейнера |
| **Совместимость** | Высокая (Cloud, Wi-Fi, Port Security) | Низкая (часто блокируется) |
| **Связь Хост-Контейнер**| Работает в режиме L3/L3S | Требует настройки sub-interface |
| **L2 Трафик (ARP)** | Только в режиме L2 | Полноценная поддержка |
| **Масштабируемость** | Экстремальная | Ограничена коммутатором |

## Практические сценарии

### Сценарий 1: Создание сети ipvlan L3 для высокой плотности

Используется для исключения накладных расходов на L2-трафик.

```bash
docker network create -d ipvlan \
  --subnet=10.100.0.0/24 \
  -o parent=eth0 \
  -o ipvlan_mode=l3 \
  --ipv6 --subnet=2001:db8:abc::/64 \
  ipvlan_l3_net
# → Сеть ipvlan_l3_net создана с поддержкой Dual-Stack
```

### Сценарий 2: Запуск контейнера в облачной среде

Контейнер получает IP, доступный из внешней сети облачного провайдера.

```bash
docker run -d --name cloud-app \
  --network ipvlan_l3_net \
  --ip 10.100.0.50 \
  nginx:alpine
# → Контейнер запущен, MAC-адрес совпадает с eth0 хоста
```

Проверка интерфейса внутри контейнера:
```bash
docker exec cloud-app ip link show eth0
# → eth0@if2: <BROADCAST,MULTICAST,NOARP,UP,LOWER_UP> mtu 1500 ...
# → Обратите внимание на флаг NOARP в режиме L3
```

### Сценарий 3: Использование VLAN (802.1Q)

Разделение трафика на уровне тегированных VLAN.

```bash
# Привязка к VLAN 20 через родительский интерфейс eth0.20
docker network create -d ipvlan \
  --subnet=172.20.0.0/24 \
  -o parent=eth0.20 \
  vlan20_net
# → Трафик этой сети будет тегироваться ID 20
```

## Дополнительная информация

### Связь с хост-системой

В классическом режиме L2 контейнеры изолированы от IP-адреса хоста (защита от "петли"). Однако в режимах **L3 и L3S** связь между хостом и контейнерами работает "из коробки" без дополнительных настроек, так как трафик проходит через таблицу маршрутизации ядра хоста.

### Ограничения

- **DHCP**: В сетях `ipvlan` классический DHCP не работает (пакеты DHCPDISCOVER часто блокируются или не находят ответа из-за общего MAC). Рекомендуется использовать статические IP или внешние IPAM-системы.
- **Port Security**: Несмотря на общую совместимость, некоторые корпоративные коммутаторы могут блокировать трафик, если заметят передачу IP-пакетов, адреса которых не были получены через DHCP/Snooping.
