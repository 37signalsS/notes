# Сетевой драйвер ipvlan

## Определения

**Драйвер ipvlan** — это сетевой драйвер Docker, который предоставляет контейнерам уникальные IP-адреса (Internet Protocol) в локальной сети, при этом все контейнеры используют **один MAC-адрес** (Media Access Control) родительского сетевого интерфейса хоста.

Это позволяет избежать проблем с безопасностью на коммутаторах (port security), которые могут блокировать порт при обнаружении множества MAC-адресов на одном физическом разъеме.

## Основные концепции

### Режимы работы

- **L2 (Layer 2 — уровень канала данных) (по умолчанию):** Контейнеры находятся в том же L2-сегменте, что и хост. Все контейнеры и хост должны находиться в одной подсети. Режим подходит для простых ("плоских") сетей.
- **L3 (Layer 3 — сетевой уровень):** Реализует маршрутизацию сетевого уровня между контейнерами и сетью хоста. Трафик L2 (ARP (Address Resolution Protocol), широковещательные рассылки) отключен. Контейнеры могут находиться в разных подсетях.
- **L3S:** Режим L3 с поддержкой валидации источника (source validation). Совместим с цепочкой FORWARD в iptables.

### Сравнение с [macvlan](./macvlan.md)

| Характеристика | ipvlan | [macvlan](./macvlan.md) |
| :--- | :--- | :--- |
| **MAC-адрес** | Использует MAC-адрес хоста | Уникальный MAC для каждого контейнера |
| **Совместимость** | Высокая (работает с Wi-Fi и port security) | Возможны блокировки на коммутаторах |
| **Производительность** | Нативная | Нативная |
| **Изоляция** | Контейнеры изолированы от хоста | Контейнеры изолированы от хоста |

**Рекомендация:** Начинайте с `ipvlan`, так как он более универсален и реже вызывает конфликты с сетевым оборудованием. Используйте `macvlan` только при явной необходимости иметь уникальный MAC-адрес для каждого контейнера.

## Практические сценарии

### Создание сети ipvlan в режиме L2

1. **Определение параметров сетевого интерфейса хоста:**

    ```bash
    ip addr show eth0
    # → Отобразит текущий IP и маску подсети интерфейса eth0
    ip route show default
    # → Отобразит шлюз по умолчанию
    ```

2. **Создание сети в Docker:**

    ```bash
    docker network create \
      -d ipvlan \
      --subnet=192.168.1.0/24 \
      --gateway=192.168.1.1 \
      -o parent=eth0 \
      my_ipvlan_net
    # → Сеть my_ipvlan_net создана
    ```

3. **Запуск контейнера со статическим IP:**

    ```bash
    docker run -d --name my-ipvlan-app \
      --network my_ipvlan_net \
      --ip 192.168.1.101 \
      nginx:alpine
    # → Контейнер запущен и доступен в локальной сети по адресу 192.168.1.101
    ```

## Дополнительная информация

### Особенности и ограничения

- **Связь с хостом:** По умолчанию контейнеры в сетях `ipvlan` и `macvlan` не могут взаимодействовать с IP-адресом хоста, на котором они запущены. Для решения этой задачи требуется создание дополнительного моста или использование sub-интерфейсов.
- **Поддержка VLAN (Virtual Local Area Network):** Драйвер поддерживает работу с тегированным трафиком через родительские sub-интерфейсы.

**Пример создания сети для конкретного VLAN:**

```bash
# Использование VLAN 100 через интерфейс eth0.100
docker network create -d ipvlan -o parent=eth0.100 --subnet=10.100.0.0/24 my_vlan100_net
# → Сеть привязана к VLAN 100
```
