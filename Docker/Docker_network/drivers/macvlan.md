# Docker: Сетевой драйвер `macvlan`

## Определения

**Драйвер `macvlan`** — это сетевой драйвер Docker, который позволяет назначать каждому контейнеру **уникальный MAC-адрес**. Это делает контейнер полноценным участником локальной сети, видимым для других устройств так, как если бы он был отдельным физическим устройством, подключенным к тому же коммутатору.

Трафик от контейнера поступает в сеть напрямую с его виртуального интерфейса, минуя NAT и сетевой стек хоста, что обеспечивает высокую производительность.

## Основные концепции

### Как это работает?

Драйвер `macvlan` создает несколько виртуальных подинтерфейсов, привязанных к одному родительскому физическому интерфейсу хоста (например, `eth0`). Каждому такому подинтерфейсу присваивается собственный уникальный MAC-адрес, и он передается в сетевое пространство имён контейнера.

В результате контейнер может получать IP-адрес из той же подсети, что и хост, в том числе от DHCP-сервера в локальной сети.

### Сравнение с `ipvlan`

Выбор между `macvlan` и `ipvlan` — это ключевое решение при интеграции контейнеров в физическую сеть.

| Характеристика | `macvlan` | `ipvlan` |
| :--- | :--- | :--- |
| **MAC-адрес** | Каждый контейнер получает **уникальный MAC-адрес** | Все контейнеры **используют MAC-адрес хоста** |
| **Совместимость**| ⚠️ **Могут быть проблемы.** Некоторые коммутаторы с включенным "port security" или Wi-Fi сети могут блокировать порт, если с него приходит трафик от множества MAC-адресов. | ✅ **Высокая.** Большинство коммутаторов и Wi-Fi точек доступа без проблем работают с одним MAC на порту. |
| **Производительность**| Очень высокая (близка к нативной) | Очень высокая (близка к нативной) |
| **Изоляция от хоста**| По умолчанию контейнеры **не могут** общаться с хостом | По умолчанию контейнеры **не могут** общаться с хостом |
| **Простота** | Проще для понимания (каждый контейнер — как отдельная ВМ) | Считается более современным и гибким |

> **Рекомендация:** Используйте `macvlan`, когда вам необходимо, чтобы контейнеры идентифицировались в сети по уникальным MAC-адресам (например, для интеграции с легаси-системами или специфическими инструментами мониторинга). В остальных случаях предпочтительнее начинать с **[`ipvlan`](./ipvlan.md)**.

## Практические сценарии

### Создание сети `macvlan`

Этот сценарий позволяет выдать контейнеру IP-адрес из вашей домашней или офисной сети и сделать его видимым как отдельное устройство.

1.  **Определите параметры сети хоста:**
    Найдите имя вашего основного сетевого интерфейса (`eth0`, `enp3s0` и т.д.), его IP-адрес и шлюз.
    ```bash
    ip addr show eth0
    ip route show default
    ```
    *Допустим, наша сеть `192.168.1.0/24`, шлюз `192.168.1.1`, а интерфейс хоста — `eth0`.*

2.  **Создайте сеть `macvlan`:**
    ```bash
    docker network create \
      -d macvlan \
      --subnet=192.168.1.0/24 \
      --gateway=192.168.1.1 \
      -o parent=eth0 \
      my_macvlan_net
    ```
    - `-d macvlan`: Указываем, что используем драйвер `macvlan`.
    - `--subnet`, `--gateway`: Задаем параметры подсети.
    - `-o parent=eth0`: **Обязательный параметр**, который привязывает `macvlan`-сеть к физическому интерфейсу хоста.

3.  **Запустите контейнер и проверьте его MAC-адрес:**
    ```bash
    # Запуск с указанием статического IP
    docker run -d --name my-macvlan-app \
      --network my_macvlan_net \
      --ip 192.168.1.102 \
      alpine sleep 3600
      
    # Проверяем MAC-адрес внутри контейнера
    docker exec my-macvlan-app ip addr show eth0
    # 3: eth0@if2: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    #     link/ether 02:42:ac:11:00:02 brd ff:ff:ff:ff:ff:ff
    ```
    Контейнер `my-macvlan-app` теперь доступен по адресу `192.168.1.102` и имеет в сети свой уникальный MAC-адрес.

## Дополнительная информация

- **Ограничение связи с хостом**: По умолчанию, из соображений безопасности, контейнеры, использующие драйверы `macvlan` или `ipvlan`, **не могут** обмениваться трафиком с хост-системой, на которой они запущены.
- **Ограничения Wi-Fi**: Большинство беспроводных адаптеров не поддерживают создание нескольких MAC-адресов на одном интерфейсе, поэтому `macvlan` в таких сетях, как правило, не работает. Драйвер предназначен для Ethernet-сетей.
- **"Неразборчивый режим" (Promiscuous Mode)**: В некоторых случаях для корректной работы `macvlan` может потребоваться перевод родительского интерфейса хоста в promiscuous режим, чтобы он принимал пакеты, предназначенные для MAC-адресов контейнеров.
- **Поддержка VLAN**: Драйвер `macvlan` поддерживает VLAN. Для этого на хосте нужно создать sub-интерфейс для нужного VLAN (например, `eth0.100` для VLAN 100) и использовать его в качестве `parent`.
