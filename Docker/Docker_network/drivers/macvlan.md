# Сетевой драйвер macvlan

## Определения

- **Драйвер macvlan** — это сетевой драйвер Docker, позволяющий назначать каждому контейнеру уникальный MAC-адрес. Это делает контейнер полноценным узлом физической сети, видимым для коммутаторов и роутеров как отдельное устройство.
- **Parent Interface (Родительский интерфейс)** — физический или виртуальный сетевой интерфейс хоста (например, `eth0` или `bond0`), на базе которого создаются подинтерфейсы для контейнеров.
- **Promiscuous Mode (Смешанный режим)** — режим работы сетевой карты, при котором она принимает все пакеты, независимо от того, какому MAC-адресу они адресованы. Необходим для корректной работы `macvlan` на виртуальных машинах и некоторых коммутаторах.

## Основные концепции

Драйвер `macvlan` обеспечивает минимально возможные задержки (latency) и максимальную пропускную способность, так как трафик передается напрямую между контейнером и физической сетью, минуя стандартный мост Docker (`docker0`) и механизмы NAT.

### Режимы работы macvlan

При создании сети можно указать режим работы через параметр `-o macvlan_mode=`:

1. **`bridge` (по умолчанию)**: Контейнеры, подключенные к одному родительскому интерфейсу на одном хосте, могут обмениваться данными напрямую через внутренний программный коммутатор.
2. **`vepa` (Virtual Ethernet Port Aggregator)**: Весь трафик (даже между контейнерами одного хоста) отправляется на физический коммутатор. Требуется поддержка режима "hairpin" (отражение трафика) на стороне коммутатора.
3. **`private`**: Контейнеры на одном хосте полностью изолированы друг от друга, даже если находятся в одной подсети.
4. **`passthru`**: Весь физический интерфейс отдается одному контейнеру. Это обеспечивает максимальную производительность, но исключает использование этого интерфейса хостом или другими контейнерами.

### Производительность (Состояние на 2026 год)

В современных ядрах Linux (6.x+) `macvlan` поддерживает технологии **XDP (eXpress Data Path)** и **Zero-copy**, что позволяет обрабатывать пакеты на скорости 40/100 Гбит/с с минимальной нагрузкой на CPU. Это делает его идеальным для телекоммуникационных систем (VNF) и высоконагруженных баз данных.

### Сравнение с [ipvlan](./ipvlan.md)

| Характеристика | macvlan | [ipvlan](./ipvlan.md) |
| :--- | :--- | :--- |
| **MAC-адрес** | Уникальный для каждого контейнера | Общий (MAC-адрес хоста) |
| **Уровень OSI** | L2 (Ethernet) | L2 или L3 (IP) |
| **Совместимость** | Низкая (блокируется Wi-Fi и Port Security) | Высокая (работает в облаках и Wi-Fi) |
| **DHCP** | Полноценная поддержка | Ограничена (требует Relay) |

**Рекомендация**: Используйте `macvlan`, если вашим приложениям критически важны уникальные MAC-адреса (например, для систем лицензирования по MAC, DHCP-резерваций или легаси-мониторинга). В современных облачных средах и Wi-Fi сетях используйте **[ipvlan](./ipvlan.md)**.

## Практические сценарии

### Сценарий 1: Создание сети и запуск контейнера

```bash
# 1. Создание сети macvlan
docker network create -d macvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  -o parent=eth0 \
  my_macvlan_net

# 2. Запуск контейнера со статическим IP
docker run -d --name legacy-app \
  --network my_macvlan_net \
  --ip 192.168.1.55 \
  nginx:alpine
```

### Сценарий 2: Использование в Docker Compose

Пример настройки для сервиса, требующего прямой видимости в локальной сети.

```yaml
services:
  app:
    image: my-legacy-app:latest
    networks:
      public_net:
        ipv4_address: 192.168.1.55

networks:
  public_net:
    driver: macvlan
    driver_opts:
      parent: eth0
    ipam:
      config:
        - subnet: 192.168.1.0/24
          gateway: 192.168.1.1
```

### Сценарий 3: Решение проблемы связи Хост-Контейнер (Shim Interface)

По умолчанию ядро Linux запрещает родителю (`eth0`) общаться со своими детьми (`macvlan`). Для решения этой задачи используется создание интерфейса-посредника (shim).

```bash
# 1. Создание shim-интерфейса
sudo ip link add macv-shim link eth0 type macvlan mode bridge

# 2. Настройка IP и маршрутов
sudo ip addr add 192.168.1.200/32 dev macv-shim
sudo ip link set macv-shim up
sudo ip route add 192.168.1.55/32 dev macv-shim
```

## Дополнительная информация

### Настройка Promiscuous Mode на гипервизорах

Если Docker запущен внутри виртуальной машины, необходимо разрешить смешанный режим на уровне гипервизора:
- **VMware ESXi**: Настройки vSwitch или Port Group → Security → Promiscuous Mode: **Accept**.
- **VirtualBox**: Settings → Network → Advanced → Promiscuous Mode: **Allow All**.
- **Proxmox/KVM**: По умолчанию мосты Linux поддерживают это, но для специфичных карт может потребоваться `ip link set eth0 promisc on`.

### Особенности и ограничения

1. **Wi-Fi адаптеры**: Режим `macvlan` практически не работает с Wi-Fi (ограничение IEEE 802.11 на количество MAC на одну ассоциацию).
2. **Безопасность**:
   - **ARP Spoofing**: В режиме `bridge` контейнеры могут атаковать друг друга через ARP. Рекомендуется использовать режим `private`, если изоляция критична.
   - **MAC Exhaustion**: Злоумышленник может попытаться занять все MAC-адреса на порту коммутатора. Настраивайте `Port Security` на физическом оборудовании.
3. **VLAN**: Для работы с тегированным трафиком родительским интерфейсом должен быть VLAN-интерфейс (например, `eth0.10`).
