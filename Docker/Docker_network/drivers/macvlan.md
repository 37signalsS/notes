# Драйвер сети: macvlan

### 1. Определения

**Драйвер Macvlan** — это сетевой драйвер Docker, который позволяет назначать контейнеру MAC-адрес, делая его видимым в физической сети как полноценное устройство, а не как порт на хосте.

### 2. Основные концепции

#### Принцип работы
Контейнер, использующий драйвер `macvlan`, подключается через виртуальный подинтерфейс к физическому сетевому интерфейсу хоста (например, `eth0`). Благодаря этому:
- Каждому контейнеру присваивается уникальный MAC-адрес.
- Контейнер получает IP-адрес из той же подсети, что и хост, например, от DHCP-сервера в локальной сети.
- С точки зрения сети, трафик от контейнера приходит напрямую от его MAC-адреса, а не от MAC-адреса хоста.

#### Сценарии использования
- **Легаси-приложения:** для старых приложений, которые ожидают прямого подключения к физической сети.
- **Сетевой мониторинг:** для запуска инструментов, которым необходимо отслеживать сетевой трафик и которые должны идентифицироваться в сети как отдельные хосты.
- **Внешнее управление IP-адресами:** когда требуется, чтобы IP-адреса контейнеров управлялись внешними системами (например, корпоративным DHCP-сервером), а не Docker.

### 3. Практические сценарии

#### Создание Macvlan-сети

Создание `macvlan`-сети требует знания топологии вашей физической сети.

1.  **Определить параметры сети и родительский интерфейс:**
    Найдите имя основного сетевого интерфейса хоста и его параметры.
    ```bash
    ip addr show
    # Пример вывода для eth0:
    # 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
    #     inet 192.168.1.10/24 brd 192.168.1.255 ...
    ```
    Из вывода нам нужны:
    - Родительский интерфейс: `eth0`
    - Подсеть: `192.168.1.0/24`
    - Шлюз: обычно `.1` в подсети, т.е. `192.168.1.1` (можно проверить командой `ip route`).

2.  **Создать `macvlan`-сеть:**
    Используем полученные данные для создания сети.
    ```bash
    docker network create -d macvlan \
      --subnet=192.168.1.0/24 \
      --gateway=192.168.1.1 \
      -o parent=eth0 \
      my-macvlan-net
    ```

3.  **Запустить контейнер в созданной сети:**
    Можно указать статический IP-адрес или позволить Docker назначить его.
    ```bash
    docker run -d --name my-macvlan-app --network my-macvlan-net --ip 192.168.1.50 alpine sleep infinity
    ```
    Теперь контейнер `my-macvlan-app` виден в локальной сети по адресу `192.168.1.50` как отдельное устройство.

### 4. Дополнительная информация

- **Связь хоста с контейнером:** По умолчанию хост-машина **не может** обмениваться трафиком с контейнерами в `macvlan`-сети. Это ограничение безопасности. Для включения такой связи требуется создать дополнительный `macvlan`-интерфейс на самом хосте.
- **Ограничения Wi-Fi:** Большинство Wi-Fi-адаптеров не поддерживают `macvlan`, так как их драйверы не позволяют создавать несколько MAC-адресов на одном физическом устройстве. Драйвер предназначен для работы с Ethernet-интерфейсами (`ethX`).
