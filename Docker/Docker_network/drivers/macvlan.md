# Сетевой драйвер macvlan

## Определения

**Драйвер macvlan** — это сетевой драйвер Docker, который позволяет назначать каждому контейнеру **уникальный MAC-адрес** (Media Access Control). Это делает контейнер полноценным участником локальной сети, видимым для других устройств как отдельное физическое устройство, подключенное к тому же коммутатору.

Трафик от контейнера поступает в сеть напрямую с его виртуального интерфейса, минуя NAT (Network Address Translation) и сетевой стек хоста, что обеспечивает максимально высокую производительность.

## Основные концепции

### Принцип работы

Драйвер `macvlan` создает виртуальные подинтерфейсы, привязанные к физическому сетевому интерфейсу хоста (например, `eth0`). Каждому подинтерфейсу присваивается собственный уникальный MAC-адрес, который передается в сетевое пространство имен (network namespace) контейнера.

Это позволяет контейнеру получать IP-адрес (Internet Protocol) из той же подсети, что и хост, в том числе через DHCP (Dynamic Host Configuration Protocol) в локальной сети.

### Сравнение с [ipvlan](./ipvlan.md)

Выбор между `macvlan` и `ipvlan` является ключевым при интеграции контейнеров в физическую инфраструктуру.

| Характеристика | macvlan | [ipvlan](./ipvlan.md) |
| :--- | :--- | :--- |
| **MAC-адрес** | Уникальный для каждого контейнера | Общий (MAC-адрес хоста) |
| **Совместимость**| Ограниченная (проблемы с port security или Wi-Fi) | Высокая совместимость |
| **Производительность**| Нативная | Нативная |
| **Изоляция** | Контейнеры изолированы от хоста | Контейнеры изолированы от хоста |

> **Рекомендация:** Используйте `macvlan`, если требуется идентификация контейнеров по уникальным MAC-адресам (например, для легаси-систем или специфического мониторинга). В остальных случаях предпочтительнее использовать **[ipvlan](./ipvlan.md)**.

## Практические сценарии

### Создание сети macvlan

Сценарий позволяет выдать контейнеру IP-адрес из физической сети и сделать его видимым как отдельный узел.

1. **Определение параметров сети хоста:**

    ```bash
    ip addr show eth0
    # → Просмотр текущего IP и маски
    ip route show default
    # → Определение шлюза по умолчанию
    ```

    *Пример: сеть `192.168.1.0/24`, шлюз `192.168.1.1`, интерфейс `eth0`.*

2. **Создание сети в Docker:**

    ```bash
    docker network create \
      -d macvlan \
      --subnet=192.168.1.0/24 \
      --gateway=192.168.1.1 \
      -o parent=eth0 \
      my_macvlan_net
    # → Сеть my_macvlan_net успешно создана
    ```

3. **Запуск контейнера и проверка MAC-адреса:**

    ```bash
    # Запуск со статическим IP
    docker run -d --name my-macvlan-app \
      --network my_macvlan_net \
      --ip 192.168.1.102 \
      alpine sleep 3600
    # → Контейнер запущен
      
    # Проверка MAC-адреса внутри контейнера
    docker exec my-macvlan-app ip addr show eth0
    # → link/ether 02:42:ac:11:00:02 brd ff:ff:ff:ff:ff:ff
    ```

## Дополнительная информация

### Особенности и ограничения

- **Изоляция от хоста:** По умолчанию контейнеры в сетях `macvlan` и `ipvlan` не могут обмениваться трафиком с хост-системой.
- **Ограничения Wi-Fi:** Большинство беспроводных адаптеров не поддерживают несколько MAC-адресов на одном интерфейсе. `macvlan` предназначен преимущественно для проводных Ethernet-сетей.
- **Промискуитетный режим (Promiscuous Mode):** Для работы драйвера может потребоваться перевод физического интерфейса хоста в режим приема всех пакетов.
- **Поддержка VLAN (Virtual Local Area Network):** Драйвер поддерживает работу через родительские sub-интерфейсы (например, `eth0.100`).
