# Драйвер сети: bridge

### Определения

**Bridge** — сетевой драйвер Docker, работающий по принципу сетевого моста. Он создает изолированную внутреннюю сеть на хосте, позволяя контейнерам взаимодействовать друг с другом и с внешним миром через NAT. Это драйвер по умолчанию для контейнеров.

### Основные концепции

#### Принцип работы
При запуске Docker создает на хосте виртуальный сетевой мост (по умолчанию `docker0`), который функционирует как коммутатор и шлюз для контейнеров. Каждому контейнеру, подключенному к этой сети, назначается IP-адрес из внутренней подсети.

Для каждого контейнера создается пара виртуальных Ethernet-интерфейсов (`veth`):
- Один конец (`eth0`) помещается в сетевое пространство имен контейнера.
- Другой конец подключается к мосту `docker0` на хосте.

Эти `veth`-пары действуют как виртуальные "патч-корды", соединяя контейнер с мостом `docker0` и обеспечивая сетевую связность.

#### Виды bridge-сетей
1.  **Сеть по умолчанию (`bridge`)**: Создается автоматически. В этой сети разрешение имен контейнеров по DNS не работает, и взаимодействие возможно только по IP-адресам. Межконтейнерное взаимодействие (`icc`) разрешено.
2.  **Пользовательские сети (`user-defined bridge`)**: Создаются вручную командой `docker network create`. **Это рекомендуемый подход**. Они предоставляют встроенный DNS-сервер для разрешения имен контейнеров и лучшую изоляцию.

#### Связь и доступ
- **Внутренняя связь**: Контейнеры в одной пользовательской bridge-сети могут общаться друг с другом по именам. В сети по умолчанию — только по IP-адресам.
- **Доступ извне**: Для предоставления доступа к сервису извне требуется явный проброс портов с хоста в контейнер (`-p ХОСТ:КОНТЕЙНЕР` или `-P`).

### Практические сценарии

#### Анализ bridge-сетей с помощью `brctl`
Для детального анализа сетевых мостов на хосте можно использовать утилиту `brctl`.

1.  **Установка (если требуется):**
    ```bash
    sudo apt-get update && sudo apt-get install -y bridge-utils
    ```

2.  **Просмотр мостов:**
    Команда `brctl show` отображает все активные мосты и подключенные к ним интерфейсы.
    ```sh
    brctl show
    # Вывод:
    # bridge name     bridge id               STP enabled     interfaces
    # docker0         8000.0242ac110002       no              veth1a2b3c4
    ```
    - `bridge name`: Имя моста (`docker0` или другой).
    - `interfaces`: Список `veth`-интерфейсов, соответствующих подключенным контейнерам.

### Дополнительная информация

#### Производительность
Проброс портов в режиме `bridge` осуществляется через userspace-прокси-процесс (`docker-proxy`). Этот процесс может создавать значительные накладные расходы для приложений с высокой частотой коротких запросов (high QPS), например, для баз данных. В таких сценариях падение производительности может достигать 50% и более.

Для критичных к производительности приложений рекомендуется использовать сетевой режим `host` или `macvlan`.

> См. также: **[Запуск MySQL в Docker: Лучшие практики и производительность](../../../Databases/mysql.md#342-сетевой-режим-bridge-vs-host)**.

#### Ограничения
- В сети `bridge` по умолчанию отсутствует разрешение имен контейнеров через DNS.
- Производительность может быть ниже по сравнению с `host` из-за `docker-proxy` и NAT.
