### Bridge: Сеть по умолчанию

Это режим по умолчанию, который создает для контейнеров изолированную внутреннюю сеть. Для того чтобы сделать сервис доступным извне, необходимо "пробросить" порты с хоста в контейнер.

- **Принцип работы:** Создает на хосте виртуальный сетевой мост (обычно `docker0`), который действует как шлюз для контейнеров. Каждому контейнеру выдается IP-адрес из внутренней подсети.
- **Связь:** Контейнеры в одной bridge-сети могут общаться друг с другом по IP-адресам. В пользовательских сетях (`docker network create`) — и по именам.
- **Доступ извне:** Требуется явный проброс портов (`-p ХОСТ:КОНТЕЙНЕР`).
- **Реализация:** Для каждого контейнера создается пара виртуальных Ethernet-интерфейсов (`veth`): один конец находится в сетевом пространстве имен контейнера (`eth0`), а другой подключен к мосту `docker0` на хосте.

> **Примечание о производительности:** Проброс портов в режиме `bridge` осуществляется через userspace-прокси (`docker-proxy`), который может создавать значительные накладные расходы для приложений с высокой частотой запросов (QPS), таких как базы данных. В некоторых сценариях это может приводить к падению производительности до 50% и более. Для чувствительных к производительности приложений рекомендуется использовать режим `host`. Подробнее см. в заметке **[Запуск MySQL в Docker: Лучшие практики и производительность](../../../Databases/MySQL/mysql_in_docker.md)**.
