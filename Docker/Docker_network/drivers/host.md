# Драйвер сети: host

## Определения

**Host-режим** — это сетевой драйвер Docker, при котором контейнер отказывается от собственной сетевой изоляции и напрямую использует сетевой стек хост-машины.

## Основные концепции

Сетевая изоляция полностью отключается. Контейнер получает доступ к сетевым интерфейсам хоста, как если бы запущенный в нем процесс выполнялся на самом хосте. Любой порт, который "слушает" приложение внутри контейнера, открывается непосредственно на IP-адресе хост-машины.

**Преимущества:**

- **Максимальная производительность:** Отсутствует `docker-proxy` и NAT, что исключает сетевые накладные расходы. Критично для приложений, чувствительных к задержкам ([базы данных](../../../Databases/MySQL/docker.md), балансировщики нагрузки).
- **Простота доступа:** Не требуется проброс портов (`-p`). Сервисы в контейнере сразу доступны по `localhost`.

**Недостатки:**

- **Низкая безопасность:** Снижается уровень изоляции. Контейнер получает доступ ко всем сетевым службам хоста.
- **Конфликты портов:** Невозможно запустить несколько контейнеров, использующих один и тот же порт.

## Практические сценарии

**Запуск контейнера в режиме host:**

1. Запустить веб-сервер:

    ```bash
    docker run -d --name my-nginx --network host nginx
    ```

2. Проверить доступ:

    ```bash
    curl localhost
    ```

3. Продемонстрировать конфликт портов:

    ```bash
    docker run --rm --name another-nginx --network host nginx
    ```

## Дополнительная информация

**Ограничения платформы:**

- Режим `--network host` работает только в Docker на Linux.
- Не поддерживается в Docker Desktop для Windows и macOS из-за особенностей виртуализации.

**Сценарии использования:**

- Достижение максимальной сетевой производительности в контролируемой среде.
- Приложения, где снижение изоляции и риск конфликта портов приемлемы.
- Мониторинг и отладка сети.
