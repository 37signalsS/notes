# Сетевой драйвер host

## Определения

**Host-режим** — это сетевой драйвер Docker, при котором контейнер отказывается от собственной сетевой изоляции и напрямую использует сетевой стек хост-машины.

## Основные концепции

При использовании этого драйвера сетевая изоляция между контейнером и хостом полностью отключается. Процесс внутри контейнера получает доступ к сетевым интерфейсам хоста напрямую. Любой порт, который "слушает" приложение, открывается непосредственно на IP-адресе (Internet Protocol) хост-машины.

### Особенности режима

- **Производительность:** Максимально возможная, так как отсутствует `docker-proxy` и NAT (Network Address Translation). Это исключает накладные расходы на пересылку пакетов.
- **Управление портами:** Флаг публикации портов `-p` игнорируется. Сервисы доступны на портах хоста по умолчанию.
- **Безопасность:** Минимальная изоляция. Контейнер может видеть все сетевые службы хоста и потенциально влиять на них.
- **Конфликты:** Невозможно запустить два контейнера на одном и том же порту хоста.

## Практические сценарии

### Запуск веб-сервера в режиме host

Запуск Nginx без проброса портов:

```bash
docker run -d --name my-nginx --network host nginx:alpine
# → Контейнер запущен, порт 80 открыт на хосте
```

Проверка доступности:

```bash
curl -I localhost:80
# → HTTP/1.1 200 OK
```

### Демонстрация конфликта портов

Попытка запуска второго экземпляра на том же порту:

```bash
docker run --rm --name another-nginx --network host nginx:alpine
# → docker: Error response from daemon: driver failed programming external connectivity ...
# → Bind for 0.0.0.0:80 failed: port is already allocated.
```

## Дополнительная информация

### Ограничения и рекомендации

- **Платформа:** Режим `--network host` полноценно работает только в Docker на Linux. В Docker Desktop (Windows/macOS) он не поддерживается из-за архитектуры виртуализации.
- **Применение:** Рекомендуется для высоконагруженных систем, требующих минимальных задержек (базы данных, системы мониторинга, балансировщики трафика).
- **Связь с другими контейнерами:** Контейнеры в режиме `host` не могут использовать встроенный DNS (Domain Name System) сервер Docker для обращения к контейнерам в других сетях по имени.
