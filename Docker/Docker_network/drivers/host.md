# Драйвер сети: host

### 1. Определения

**Host-режим** — это сетевой драйвер Docker, при котором контейнер отказывается от собственной сетевой изоляции и напрямую использует сетевой стек хост-машины.

### 2. Основные концепции

#### Принцип работы
Сетевая изоляция полностью отключается. Контейнер получает доступ к сетевым интерфейсам хоста, как если бы запущенный в нем процесс выполнялся на самом хосте. Любой порт, который "слушает" приложение внутри контейнера, открывается непосредственно на IP-адресе хост-машины.

#### Преимущества и недостатки
-   **(+) Максимальная производительность:** Отсутствует `docker-proxy` и NAT, что исключает сетевые накладные расходы. Это критично для приложений, чувствительных к задержкам (например, [базы данных](../../../Databases/MySQL/docker.md) или балансировщики нагрузки).
-   **(+) Простота доступа:** Не требуется проброс портов (`-p`). Сервисы в контейнере сразу доступны по `localhost`.
-   **(-) Низкая безопасность:** Снижается уровень изоляции. Контейнер получает доступ ко всем сетевым службам хоста.
-   **(-) Конфликты портов:** Невозможно запустить несколько контейнеров, использующих один и тот же порт.

### 3. Практические сценарии

#### Запуск контейнера в режиме host

1.  **Запустить веб-сервер:**
    Запустим `nginx` в фоновом режиме. Он попытается использовать порт 80 хост-машины.
    ```bash
    docker run -d --name my-nginx --network host nginx
    ```

2.  **Проверить доступ:**
    Обратимся к `nginx` через `localhost` хоста.
    ```bash
    curl localhost
    # Вывод покажет приветственную страницу Nginx
    ```

3.  **Продемонстрировать конфликт портов:**
    Попытка запустить второй контейнер `nginx` завершится ошибкой, так как порт 80 уже занят первым контейнером.
    ```bash
    docker run --rm --name another-nginx --network host nginx
    ```
    ```
    docker: Error response from daemon: driver failed programming external connectivity ...:
    Bind for 0.0.0.0:80 failed: port is already allocated.
    ```

### 4. Дополнительная информация

- **Ограничения платформы:** Режим `--network host` работает только в Docker на Linux. Он не поддерживается в Docker Desktop для Windows и macOS из-за особенностей виртуализации.
- **Сценарии использования:** Основное применение — достижение максимальной сетевой производительности в контролируемой среде, где снижение изоляции и риск конфликта портов приемлемы.
