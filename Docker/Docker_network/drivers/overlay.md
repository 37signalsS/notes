# Сетевой драйвер overlay

## Определения

- **Драйвер overlay**: Сетевой драйвер Docker, предназначенный для создания виртуальных сетей, охватывающих несколько хостов. Он позволяет контейнерам на разных узлах взаимодействовать напрямую в едином плоском L2-сегменте (Layer 2 — канальный уровень), абстрагируясь от физической топологии.
- **VXLAN (Virtual Extensible LAN)** — технология инкапсуляции, которая упаковывает Ethernet-кадры контейнеров в UDP-пакеты (порт 4789 по умолчанию) для передачи через L3-сеть.
- **VTEP (VXLAN Tunnel End Point)** — логическая точка входа/выхода туннеля, отвечающая за инкапсуляцию и декапсуляцию трафика.

## Основные концепции

Драйвер `overlay` является стандартом для построения сетевой связности в кластерах Docker Swarm. Он позволяет масштабировать приложения горизонтально, сохраняя прозрачность сетевых имен и IP-адресов.

### Механизм инкапсуляции и порты

Весь трафик overlay-сети проходит через инкапсуляцию VXLAN. Для корректной работы кластера необходимо открыть следующие порты:
- **2377/TCP**: Управление кластером Swarm.
- **7946/TCP+UDP**: Gossip-протокол (обнаружение узлов).
- **4789/UDP**: Плоскость данных (VXLAN). При конфликтах в облаках порт можно изменить через `--data-path-port`.

### Технологии и стабильность (Состояние на 2026 год)

1. **IPv6 Dual-Stack (v27+)**: Полная поддержка IPv6. При создании сети без явного указания подсети Docker генерирует уникальный локальный префикс (ULA).
2. **Secure by Default (v28+)**: Введена политика автоматической изоляции. Трафик к неопубликованным портам контейнеров блокируется на уровне ядра, если не настроены соответствующие политики доступа.
3. **Hardware Offloading**: Современные сетевые карты с поддержкой VXLAN Offloading позволяют перенести нагрузку по сборке/разборке пакетов с CPU на железо, что снижает задержки (latency) и потребление ресурсов.
4. **Шифрование IPsec**: Использование опции `--opt encrypted` активирует шифрование трафика между узлами. В 2026 году накладные расходы на шифрование составляют менее 5% благодаря аппаратным инструкциям **AES-NI**.

### Проблема MTU в облаках

Инкапсуляция VXLAN добавляет **50 байт** оверхеда. 
- Если физический MTU равен 1500, то MTU overlay-сети **должен быть 1450**.
- В облаках с Jumbo Frames (MTU 9000) оверлей может использовать 1500 или выше без потерь производительности.

## Практические сценарии

### Сценарий 1: Создание отказоустойчивой сети с шифрованием

Используется для передачи чувствительных данных между узлами в публичном облаке.

```bash
docker network create \
  --driver overlay \
  --opt encrypted \
  --opt com.docker.network.driver.mtu=1450 \
  --attachable \
  app-net
# → [ID_сети]
```
- `--attachable`: Позволяет обычным контейнерам (не сервисам Swarm) подключаться к этой сети, что полезно для отладки или гибридных нагрузок.

### Сценарий 2: Развертывание стека приложений (Stack)

Пример описания в `docker-compose.yml` для Swarm:

```yaml
version: '3.8'
services:
  web:
    image: nginx:alpine
    networks:
      - backend

networks:
  backend:
    driver: overlay
    attachable: true
    driver_opts:
      com.docker.network.driver.mtu: 1450
```

### Сценарий 3: Сравнение с сетью Ingress

| Параметр | Индивидуальная Overlay | Системная Ingress |
| :--- | :--- | :--- |
| **Назначение** | Связь между сервисами | Входящий трафик (Routing Mesh) |
| **Создание** | Вручную | Автоматически при `swarm init` |
| **Особенности** | Поддерживает `--opt encrypted` | Не поддерживает шифрование |

## Дополнительная информация

### Диагностика VXLAN связности

Если сервисы на разных узлах не видят друг друга:
1. Проверьте UDP 4789: `nc -zvu <REMOTE_IP> 4789`.
2. Проверьте MTU: выполните `ping -M do -s 1422 <REMOTE_CONTAINER_IP>` внутри контейнера. Если ping не проходит, MTU завышен.
3. Проверьте gossip-статус: `docker node ls` и убедитесь, что все узлы в статусе `Ready`.

### Ограничения

- **Windows-узлы**: Шифрование (`--opt encrypted`) не поддерживается на Windows до версии Server 2025.
- **Производительность**: При большом количестве сетей (>500) протокол gossip может создавать значительную нагрузку на Control Plane. Рекомендуется группировать сервисы в общие сети.
