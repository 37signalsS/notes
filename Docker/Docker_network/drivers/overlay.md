### Overlay: Сети для кластеров

Overlay-сети используются в [Docker Swarm Mode](../../Docker_swarm/docker_swarm.md) для связи контейнеров, запущенных на разных хостах. Виртуальная сеть "накладывается" поверх физической, позволяя контейнерам на разных машинах общаться так, будто они находятся в одной подсети.

Когда вы запускаете сервис в Swarm, по умолчанию к нему присоединяется несколько сетей, каждая из которых решает свои задачи.

#### Принцип работы Overlay и VXLAN

Overlay-сеть создает общую подсеть для контейнеров, даже если они запущены на разных физических хостах. Это достигается с помощью технологии **VXLAN (Virtual Extensible LAN)**.

**Как работает VXLAN:**

1.  Docker инкапсулирует L2-фреймы (Ethernet-кадры) от контейнеров в L4-пакеты (UDP/IP).
2.  Эти UDP-пакеты отправляются между хостами Swarm через стандартную физическую сеть. Docker использует для этого порт `4789`.
3.  На принимающем хосте Docker "распаковывает" UDP-пакет, извлекает из него исходный Ethernet-кадр и направляет его в нужный контейнер.

Для контейнеров этот процесс полностью прозрачен — они видят друг друга так, будто подключены к одному виртуальному свитчу.

**Пример на практике:**

Если запустить `tcpdump` на одном из хостов Swarm во время пинга между контейнерами на разных машинах, можно увидеть два слоя трафика:
-   **Внешний слой:** UDP-трафик между IP-адресами хостов по порту 4789.
-   **Внутренний слой:** ICMP-трафик (пинг) между IP-адресами контейнеров.

#### Создание Overlay-сетей

```bash
# Создание обычной overlay-сети для сервисов Swarm
docker network create --driver overlay my-overlay-network

# Создание attachable overlay-сети для подключения автономных контейнеров
# Флаг --attachable позволяет автономным контейнерам (не Swarm-сервисам) подключаться к этой сети.
docker network create --driver overlay --attachable my-attachable-overlay
```

#### Шифрование Overlay-сетей

По умолчанию трафик внутри VXLAN-туннелей не шифруется. Это значит, что любой, кто может перехватить трафик между хостами, увидит и трафик между контейнерами.

Чтобы это исправить, Docker позволяет включить автоматическое IPSec-шифрование при создании сети:

```bash
docker network create --driver overlay --opt encrypted my-secure-overlay
```
**Важно:** Шифрование с использованием IPSec может негативно сказаться на производительности сети. Не рекомендуется использовать его для высокопроизводительных или чувствительных к задержкам сервисов, таких как базы данных.

#### Системные сети в Swarm: ingress и docker_gwbridge

Помимо пользовательских overlay-сетей, в Swarm-кластере по умолчанию создаются две важные системные сети.

1.  **`ingress`**
    -   **Тип:** `overlay`.
    -   **Назначение:** Обработка **входящего трафика из внешнего мира** к сервисам кластера.
    -   **Балансировка нагрузки:** Когда вы публикуете порт сервиса (например, `-p 8080:80`), Swarm Routing Mesh направляет трафик с порта `8080` *любого* из хостов кластера на нужный контейнер, даже если он работает на другой машине. Балансировка нагрузки выполняется с помощью **IPVS (IP Virtual Server)**, который работает внутри специального контейнера, подключенного к `ingress`-сети. Эта сеть не является `attachable` по умолчанию.

2.  **`docker_gwbridge`**
    -   **Тип:** `bridge`.
    -   **Назначение:** Служит шлюзом для **исходящего трафика** из контейнеров Swarm-сервисов во внешний мир (например, когда контейнер обращается к внешнему API или базе данных в интернете).
    -   На каждом хосте кластера создается свой bridge-интерфейс `docker_gwbridge`, который соединяет overlay-сети с физической сетью хоста.

#### Заключение

Контейнер, запущенный в Swarm, обычно подключен к нескольким сетям одновременно:

-   **Пользовательская `overlay`-сеть:** Для прямой связи между контейнерами одного сервиса на разных хостах.
-   **`ingress` (overlay):** Для получения трафика извне и его балансировки.
-   **`docker_gwbridge` (bridge):** Для доступа контейнеров во внешний мир.
