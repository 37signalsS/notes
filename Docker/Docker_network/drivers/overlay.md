# Сетевой драйвер overlay

## Определения

- **Драйвер overlay**: Сетевой драйвер Docker, предназначенный для создания виртуальных сетей, охватывающих несколько хостов. Он позволяет контейнерам, запущенным на разных машинах, взаимодействовать друг с другом напрямую, как если бы они находились в одной плоской сети уровня L2 (Layer 2).
- **VXLAN (Virtual Extensible LAN)**: Технология инкапсуляции и туннелирования, лежащая в основе overlay-сетей. VXLAN "упаковывает" Ethernet-кадры (L2) от контейнеров в UDP-пакеты (User Datagram Protocol) уровня L4, что позволяет им проходить через существующую сеть уровня L3 (например, корпоративную сеть или Интернет).

## Основные концепции

### Проблема: Связь контейнеров на разных хостах

Сетевые драйверы, работающие в рамках одного хоста (например, `bridge`), не позволяют контейнерам на разных узлах (`Host-A` и `Host-B`) общаться напрямую без публикации портов и внешней маршрутизации. Драйвер `overlay` создает абстракцию единой сети поверх физической инфраструктуры.

### Механизм работы

1. **Плоскость данных (Data Plane)**: Когда контейнер на одном узле отправляет пакет контейнеру на другом узле, Docker-демон инкапсулирует этот трафик в VXLAN-туннель (используя стандартный UDP-порт 4789). На принимающей стороне демон распаковывает пакет и доставляет его целевому контейнеру.
2. **Плоскость управления (Control Plane)**: Для работы overlay-сети узлы должны обладать информацией о расположении всех контейнеров. В Docker Swarm эта задача решается с помощью встроенного хранилища "ключ-значение" (Key-Value Store) и gossip-протокола для синхронизации состояния между менеджерами кластера.

### Системные сети в Docker Swarm

При инициализации Swarm-кластера автоматически создаются служебные сети:

- **`ingress`**: Сеть типа `overlay` для приема входящего трафика и его распределения между сервисами кластера (механизм Routing Mesh).
- **`docker_gwbridge`**: Сеть типа `bridge` на каждом узле, выполняющая роль шлюза для исходящего трафика контейнеров во внешние сети.

## Практические сценарии

Overlay-сети используются преимущественно в **Docker Swarm**.

### Создание и использование overlay-сети

1. **Инициализация Swarm (на мастере):**

    ```bash
    docker swarm init
    # → Swarm initialized: current node is now a manager.
    ```

2. **Создание сети с расширенными опциями:**

    ```bash
    docker network create \
      --driver overlay \
      --opt encrypted \
      --attachable \
      my-multihost-net
    # → [ID созданной сети]
    ```

    - `--driver overlay`: Указываем тип драйвера.
    - `--opt encrypted`: Включает шифрование трафика внутри сети с помощью IPsec (Internet Protocol Security).
    - `--attachable`: Позволяет подключать к сети не только сервисы Swarm, но и обычные автономные контейнеры.

3. **Запуск сервиса в сети:**

    ```bash
    docker service create \
      --name my-api \
      --network my-multihost-net \
      --replicas 3 \
      nginx:alpine
    # → [ID созданного сервиса]
    ```

4. **Проверка связности через автономный контейнер:**

    ```bash
    docker run -it --rm --network my-multihost-net busybox ping -c 2 my-api
    # → PING my-api (10.0.1.2): 56 data bytes
    # → 64 bytes from 10.0.1.2: seq=0 ttl=64 time=0.123 ms
    # → 64 bytes from 10.0.1.2: seq=1 ttl=64 time=0.145 ms
    ```

    Встроенный DNS (Domain Name System) Swarm-кластера разрешит имя сервиса в IP-адреса его реплик.

## Дополнительная информация

### Требования и ограничения

- **Открытые порты**: Для работы драйвера между узлами должны быть открыты:
  - **TCP 2377**: Управление кластером.
  - **TCP/UDP 7946**: Обнаружение узлов (gossip).
  - **UDP 4789**: Трафик VXLAN.
- **MTU (Maximum Transmission Unit)**: Инкапсуляция VXLAN добавляет оверхед (около 50 байт). В сетях с MTU 1500 эффективный MTU для контейнеров должен составлять 1450. Настройка производится в `daemon.json` (формат JSON — JavaScript Object Notation).
- **Производительность**: Шифрование (`--opt encrypted`) создает дополнительную нагрузку на CPU (Central Processing Unit).

### Диагностика

- `docker network inspect my-multihost-net`: Детальная информация о сети и подключенных эндпоинтах.
- `tcpdump -ni any udp port 4789`: Мониторинг инкапсулированного VXLAN-трафика на физическом интерфейсе.
