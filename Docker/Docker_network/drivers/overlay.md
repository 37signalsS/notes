# Сетевой драйвер overlay

## Определения

- **Драйвер overlay**: Сетевой драйвер Docker, предназначенный для создания виртуальных сетей, охватывающих несколько хостов. Он позволяет контейнерам на разных узлах взаимодействовать напрямую в едином плоском L2-сегменте (Layer 2 — канальный уровень), абстрагируясь от физической топологии.
- **VXLAN (Virtual Extensible LAN — виртуальная расширяемая локальная сеть)**: Технология инкапсуляции, которая упаковывает Ethernet-кадры контейнеров в UDP-пакеты (User Datagram Protocol — протокол пользовательских датаграмм) уровня L4, передавая их через существующую L3-инфраструктуру (IP-сеть).
- **MTU (Maximum Transmission Unit — максимальный размер полезного блока данных)**: Максимальный размер пакета, который может быть передан по сети без фрагментации.
- **IPsec (Internet Protocol Security — безопасность IP-протокола)**: Набор протоколов для обеспечения защиты данных, передаваемых по сетям IPv4 и IPv6, путем их шифрования и аутентификации.

## Основные концепции

Драйвер `overlay` является фундаментом сетевого взаимодействия в кластерах Docker Swarm. Он создает логическую сеть поверх физических узлов, обеспечивая связность контейнеров без необходимости сложной настройки маршрутизации на хостах.

### Механизм работы и плоскости управления

1. **Data Plane (Плоскость данных)**: Реализована через VXLAN-туннели. Весь трафик между контейнерами на разных хостах инкапсулируется в UDP-пакеты. По умолчанию используется порт **4789/UDP**.
2. **Control Plane (Плоскость управления)**: Docker Swarm использует протокол gossip (сплетен) для автоматического обнаружения узлов и синхронизации состояния сети. Это исключает необходимость во внешнем Key-Value хранилище (в отличие от устаревших реализаций standalone-overlay).

### Обновления и стабильность (Состояние на 2026 год)

- **IPv6 Dual-Stack (v27+)**: Начиная с Docker v27, поддержка IPv6 в overlay-сетях стала стабильной. При включении IPv6 без указания подсети Docker автоматически генерирует префикс **ULA** (Unique Local Address — уникальный локальный адрес).
- **Secure by Default (v28+)**: Введена жесткая политика фильтрации трафика. Трафик к неопубликованным портам контейнеров теперь блокируется по умолчанию на уровне сетевого стека, что повышает безопасность в мультиарендных средах.
- **Аппаратное ускорение**: Современные сетевые карты (NIC) с поддержкой VXLAN Offloading позволяют перенести инкапсуляцию на аппаратный уровень, снижая нагрузку на CPU (Central Processing Unit — центральный процессор).

### Нюансы облачных сред и MTU

Основная проблема overlay-сетей в облаках (AWS, Azure, GCP) — накладные расходы на инкапсуляцию.
- **MTU 1450**: VXLAN добавляет 50 байт заголовка. Если MTU физического интерфейса хоста равен 1500, то MTU overlay-сети **должен быть установлен в 1450**. Несоблюдение этого правила приводит к обрывам TLS-соединений и SCP-сессий.
- **Конфликт порта 4789**: В средах VMware и некоторых облачных провайдерах порт 4789 зарезервирован для внутренней инфраструктуры. В таких случаях необходимо менять порт данных при инициализации кластера:
  ```bash
  docker swarm init --data-path-port 7789
  ```

## Практические сценарии

### Сценарий 1: Создание защищенной overlay-сети для облака

Создание сети с учетом ограничений MTU и шифрования трафика.

```bash
docker network create \
  --driver overlay \
  --opt com.docker.network.driver.mtu=1450 \
  --opt encrypted \
  --attachable \
  prod-secure-net
# → [ID созданной сети]
```
- `--opt encrypted`: Включает шифрование трафика через IPsec. В современных ядрах (6.x) накладные расходы минимизированы благодаря инструкциям **AES-NI**.

### Сценарий 2: Запуск отказоустойчивого сервиса

```bash
docker service create \
  --name web-app \
  --network prod-secure-net \
  --replicas 5 \
  --update-delay 10s \
  nginx:latest
# → [ID созданного сервиса]
```

### Сценарий 3: Диагностика связности между нодами

Если контейнеры не видят друг друга на разных хостах, проверьте доступность портов данных.

```bash
# Проверка порта VXLAN на удаленном узле
nc -zvu <IP_NODE_B> 4789
# → Connection to <IP_NODE_B> 4789 port [udp/*] succeeded!
```

Мониторинг прохождения VXLAN-пакетов на физическом интерфейсе:
```bash
tcpdump -ni any udp port 4789
# → [Time] IP <Node_A>.56789 > <Node_B>.4789: VXLAN, flags [I] (0x08), vni 4096
```

## Дополнительная информация

### Требуемые порты (Firewall)

Для корректной работы overlay-сети в кластере должны быть открыты:
- **2377/TCP**: Управление кластером Swarm.
- **7946/TCP+UDP**: Обнаружение узлов и gossip.
- **4789/UDP**: Плоскость данных (может быть изменен через `--data-path-port`).

### Ограничения

- **Шифрование и производительность**: Использование `--opt encrypted` снижает пропускную способность на 15-20% и несовместимо с Windows-узлами в Swarm (до 2026 года поддержка ограничена).
- **Маршрутизация Ingress**: Сеть `ingress` также является overlay-сетью и наследует все ее особенности, включая проблемы с MTU.
