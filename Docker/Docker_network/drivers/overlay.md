# Docker: Сетевой драйвер `overlay`

## Определения

- **Драйвер `overlay`**: Сетевой драйвер Docker, предназначенный для создания виртуальных сетей, которые охватывают несколько хостов. Он позволяет контейнерам, запущенным на разных машинах, общаться друг с другом напрямую, как если бы они находились в одной плоской L2-сети.
- **VXLAN (Virtual Extensible LAN)**: Технология туннелирования, лежащая в основе `overlay`-сетей. VXLAN "упаковывает" Ethernet-кадры (L2) от контейнеров в UDP-пакеты (L4), что позволяет им беспрепятственно проходить через существующую L3-сеть (например, корпоративную сеть или интернет).

## Основные концепции

### Проблема: Связь контейнеров на разных хостах

Сетевые драйверы по умолчанию (например, `bridge`) ограничены одним хостом. Если запустить один контейнер на `Host-A`, а другой на `Host-B`, они не смогут общаться друг с другом напрямую. Драйвер `overlay` решает именно эту проблему.

### Решение: Виртуальная сеть поверх физической

Драйвер `overlay` создает виртуальную сеть, которая "накладывается" поверх физической.

1. **Плоскость данных (Data Plane)**: Когда контейнер `C1` на `Host-A` отправляет пакет контейнеру `C2` на `Host-B`, Docker-демон на `Host-A` инкапсулирует этот пакет в VXLAN-туннель (используя **UDP-порт 4789**) и отправляет его на `Host-B`. Демон на `Host-B` распаковывает пакет и доставляет его в `C2`. Для контейнеров этот процесс полностью прозрачен.
2. **Плоскость управления (Control Plane)**: Чтобы этот механизм работал, Docker-хосты должны знать, на какой машине находится каждый контейнер. Эту задачу решает **встроенный в Docker Swarm key-value store**. Менеджеры Swarm поддерживают актуальную карту сети (какие контейнеры где находятся), используя для этого gossip-протокол.

### Системные сети в Docker Swarm

Помимо пользовательских `overlay`-сетей, в Swarm-кластере автоматически создаются две служебные сети:

- **`ingress`**: Сеть типа `overlay`, которая отвечает за прием трафика из внешнего мира и его маршрутизацию на нужные сервисы внутри кластера. Это основа механизма **Routing Mesh**.
- **`docker_gwbridge`**: Сеть типа `bridge`, которая создается на каждом узле. Она служит шлюзом для **исходящего трафика** из контейнеров во внешний мир (например, для доступа к `google.com`).

## Практические сценарии

`Overlay`-сети — ключевой компонент **Docker Swarm**. Все действия выполняются в контексте существующего Swarm-кластера.

### Создание и использование `overlay`-сети

1. **Инициализируйте Swarm (если не сделано):**
    На машине-менеджере выполните:

    ```bash
    docker swarm init
    ```

2. **Создайте `overlay`-сеть:**

    ```bash
    docker network create \
      --driver overlay \
      --opt encrypted \
      --attachable \
      my-multihost-net
    ```

    - `--driver overlay`: Указываем тип драйвера.
    - `--opt encrypted`: Включает шифрование трафика внутри сети с помощью [IPsec](../../../Networking/Tunnels/ipsec/ipsec.md).
    - `--attachable`: Позволяет не только сервисам, но и обычным (`standalone`) контейнерам подключаться к этой сети, что удобно для отладки.

3. **Создайте сервис в этой сети:**
    Docker Swarm распределит 3 реплики этого сервиса по узлам кластера. Все они будут в одной сети и смогут общаться друг с другом.

    ```bash
    docker service create \
      --name my-api \
      --network my-multihost-net \
      --replicas 3 \
      nginx:alpine
    ```

4. **Подключитесь для отладки:**
    Благодаря флагу `--attachable`, вы можете запустить временный контейнер и проверить связь с сервисом по его имени. Встроенный в Swarm DNS разрешит имя `my-api` в IP-адреса контейнеров сервиса.

    ```bash
    docker run -it --rm --network my-multihost-net busybox

    # Внутри контейнера busybox
    / # ping my-api
    # PING my-api (10.0.0.5): 56 data bytes
    # 64 bytes from 10.0.0.5: seq=0 ttl=64 time=0.082 ms
    ```

## Дополнительная информация

- **Требования к сети**: Для корректной работы `overlay`-сетей между всеми узлами Swarm-кластера должны быть открыты следующие порты:
  - **TCP 2377**: Для управления кластером (только для менеджеров).
  - **TCP/UDP 7946**: Для обнаружения узлов и обмена данными (gossip).
  - **UDP 4789**: Для трафика VXLAN (Data Plane).

- **Производительность и MTU**: Инкапсуляция VXLAN добавляет около 50 байт к размеру каждого пакета. В сетях с нестандартным MTU (например, 1450 в некоторых облаках) это может вызывать фрагментацию. При необходимости MTU можно настроить в конфигурации Docker-демона (`/etc/docker/daemon.json`).

- **Диагностика**:
  - `docker network inspect my-multihost-net`: Показывает, какие контейнеры и сервисы подключены к сети.
  - `tcpdump -ni any udp port 4789`: Позволяет отслеживать инкапсулированный VXLAN-трафик на хосте.
- **Сравнение с другими драйверами**: [Обзор сетевых моделей Docker](../docker_network.md) содержит сравнение `overlay` с [`host`](./host.md) (альтернатива для максимальной производительности на одном хосте) и другими драйверами.
