# Overlay-сеть

### Определения

**Overlay-сеть** — это тип виртуальной сети в Docker, предназначенный для организации взаимодействия между контейнерами, запущенными на разных хостах в составе кластера [Docker Swarm](../../Docker_swarm/docker_swarm_overview.md). Она создает единое сетевое пространство (виртуальную L2-сеть), "накладывая" его поверх существующей физической L3-сети.

Помимо пользовательских overlay-сетей, в Swarm существуют две системные сети:

1.  **`ingress`**
    -   **Тип:** `overlay`.
    -   **Назначение:** Обработка **входящего трафика из внешнего мира** к сервисам кластера. Когда порт сервиса публикуется, **Routing Mesh** (маршрутизирующая сетка) Swarm направляет трафик с этого порта *любого* из узлов кластера на нужный контейнер, используя для балансировки **IPVS (IP Virtual Server)**.
2.  **`docker_gwbridge`**
    -   **Тип:** `bridge`.
    -   **Назначение:** Служит шлюзом для **исходящего трафика** из контейнеров во внешний мир (например, для доступа к внешним API или базам данных). На каждом узле кластера создается свой bridge-интерфейс `docker_gwbridge`, соединяющий overlay-сети с физической сетью хоста.

### Основные концепции

#### Принцип работы: VXLAN-инкапсуляция

Связь между хостами в overlay-сети достигается с помощью технологии **VXLAN (Virtual Extensible LAN)**, которая инкапсулирует L2-кадры (Ethernet) от контейнеров в L4-пакеты (UDP).

1.  Контейнер отправляет стандартный Ethernet-кадр (L2).
2.  Docker на хосте-отправителе "заворачивает" этот кадр в UDP-пакет и отправляет его на хост-получатель через физическую сеть. Для этого используется **порт `4789/udp`**.
3.  Docker на хосте-получателе "распаковывает" UDP-пакет, извлекает исходный кадр и направляет его в контейнер назначения.

Для контейнеров этот процесс полностью прозрачен — они видят друг друга так, будто подключены к одному виртуальному коммутатору.

#### Шифрование трафика

По умолчанию трафик внутри VXLAN-туннелей не шифруется. Для защиты данных можно включить автоматическое IPSec-шифрование при создании сети.

```bash
docker network create --driver overlay --opt encrypted my-secure-overlay
```
> **Важно:** Шифрование IPSec создает дополнительную нагрузку и может негативно сказаться на производительности сети. Его не рекомендуется использовать для сервисов, чувствительных к задержкам.

### Практические сценарии

#### Создание overlay-сетей

```bash
# Создание стандартной overlay-сети для сервисов Swarm
docker network create --driver overlay my-overlay-network

# Создание "присоединяемой" (attachable) overlay-сети
# Флаг --attachable позволяет не только сервисам, но и отдельным 
# (standalone) контейнерам подключаться к этой сети.
docker network create --driver overlay --attachable my-attachable-overlay
```

#### Подключение сервиса к сети

Созданный сервис подключается к указанной сети. Встроенный в Swarm DNS-сервер обеспечивает обнаружение контейнеров сервиса по его имени.

```bash
docker service create \
  --name my-service \
  --network my-overlay-network \
  --replicas 3 \
  my-image
```

### Дополнительная информация

Контейнер, запущенный как сервис в Swarm, обычно подключен к нескольким сетям одновременно:
-   **Пользовательская `overlay`-сеть:** Для прямой связи с другими контейнерами в кластере.
-   **`ingress` (overlay):** Для получения трафика извне через опубликованные порты.
-   **`docker_gwbridge` (bridge):** Для доступа контейнера во внешний мир.
