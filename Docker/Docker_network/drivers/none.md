# Сетевой драйвер none

## Определения

- **Драйвер none (`--network none`)** — это сетевая модель Docker, при которой контейнер получает изолированный сетевой стек (Network Namespace), но лишается всех внешних сетевых интерфейсов.
- **Air-Gapped Isolation (Физическая изоляция)** — концепция безопасности, при которой информационная система не имеет соединений с внешними сетями (интернетом или локальной сетью) для предотвращения утечек данных.

## Основные концепции

Драйвер `none` обеспечивает максимальный уровень сетевой изоляции, доступный в Docker. В отличие от других драйверов, он не создает `veth`-пару и не подключает контейнер к программному мосту (bridge).

### Механизм работы

При использовании `--network none` Docker настраивает сетевое пространство имен контейнера следующим образом:
- **Loopback (`lo`)**: Интерфейс `127.0.0.1` создается и переводится в состояние `UP`. Процессы внутри контейнера могут взаимодействовать друг с другом через локальные сокеты.
- **Отсутствие внешних интерфейсов**: Интерфейс `eth0` не создается.
- **Пустая таблица маршрутизации**: В контейнере отсутствует шлюз по умолчанию (Default Gateway), что делает невозможным любой входящий или исходящий трафик за пределы контейнера.

### Применение в 2026 году

1. **Confidential Computing (Конфиденциальные вычисления)**: Режим `none` является стандартом для работы внутри аппаратных анклавов (AWS Nitro Enclaves, Intel TDX). Связь с внешним миром в таких средах осуществляется не через TCP/IP, а через защищенный протокол **VSOCK** (`AF_VSOCK`), что исключает атаки на сетевой стек ядра.
2. **Zero-Trust Batch Processing**: Выполнение критических задач (обработка персональных данных, генерация ключей), где контейнер взаимодействует только с примонтированными **[томами](../../Docker_fs/docker_volumes.md)** или именованными каналами (pipes).
3. **Защита от Supply Chain атак**: Запуск инструментов сборки и линтинга в CI/CD пайплайнах без доступа к сети гарантирует, что сторонние зависимости не смогут отправить секреты (API-ключи) на удаленные серверы.
4. **Минимизация поверхности атаки**: Отключение сетевых системных вызовов защищает систему от 0-day уязвимостей в сетевой подсистеме ядра Linux (например, в Netfilter или стеке IPv6).

## Практические сценарии

### Сценарий 1: Проверка изоляции и loopback

Запуск контейнера для выполнения локальных вычислений без риска утечки.

```bash
docker run -d --name secure-calc --network none alpine sleep 3600
# → Контейнер запущен в полностью изолированном пространстве
```

Проверка состояния интерфейсов:
```bash
docker exec secure-calc ip addr
# → 1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN qlen 1000
# →     inet 127.0.0.1/8 scope host lo
# → Другие интерфейсы (eth0) отсутствуют
```

### Сценарий 2: Продвинутая настройка (ручная инъекция veth)

Используется инженерами для создания кастомных топологий, обходящих стандартные механизмы Docker.

```bash
# 1. Запуск контейнера с none
docker run -d --name custom-net-app --network none alpine sleep 3600

# 2. Создание veth-пары на хосте (требуются права root)
sudo ip link add veth-h type veth peer name veth-c

# 3. Перенос конца veth в сетевое пространство имен контейнера
PID=$(docker inspect -f '{{.State.Pid}}' custom-net-app)
sudo ip link set veth-c netns $PID

# 4. Настройка интерфейса внутри контейнера
docker exec -u 0 custom-net-app ip link set veth-c up
docker exec -u 0 custom-net-app ip addr add 10.0.0.2/24 dev veth-c
# → Контейнер получил вручную настроенный интерфейс, не контролируемый Docker
```

### Сценарий 3: Анализ малвари (Sandboxing)

Запуск подозрительного кода без возможности связи с C2 (Command & Control) сервером.

```bash
docker run --rm --network none --memory 512m malware-analyzer ./analyze_sample.sh
# → Любая попытка сетевого запроса завершится ошибкой "Network is unreachable"
```

## Дополнительная информация

### Ограничения

- **Отсутствие DNS**: Встроенный DNS-сервер Docker не работает, так как он требует сетевой связности с виртуальным IP `127.0.0.11`, которая в режиме `none` часто ограничена или не имеет смысла из-за отсутствия маршрутов.
- **Hostname Resolution**: Разрешение имен других контейнеров невозможно.
- **Port Mapping**: Параметры `-p` и `-P` не имеют эффекта и игнорируются при запуске.

### Сравнение с `--internal`
В отличие от режима `--internal` (доступен в драйвере `bridge`), который позволяет контейнерам общаться друг с другом в рамках одной сети, но запрещает выход в интернет, драйвер `none` запрещает **любое** сетевое взаимодействие, включая общение между контейнерами на одном хосте (если не используются общие IPC-пространства или VSOCK).
