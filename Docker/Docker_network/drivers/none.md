# Docker: Сетевой драйвер `none`

## Определения

**Драйвер `none`** — это сетевой драйвер Docker, который полностью отключает сетевой стек для контейнера. Контейнер, запущенный с этим драйвером, не имеет внешних сетевых интерфейсов и полностью изолирован от сетей хоста и других контейнеров.

## Основные концепции

### Как это работает?

Когда контейнер запускается с опцией `--network none`, Docker по-прежнему создает для него собственное, изолированное сетевое пространство имён (network namespace). Однако, в отличие от других драйверов, Docker не выполняет никакой дополнительной настройки:

- Внешние сетевые интерфейсы не создаются.
- IP-адрес не назначается.
- Маршруты по умолчанию отсутствуют.

Единственный интерфейс, доступный внутри контейнера, — это `lo` (loopback), который позволяет процессам внутри этого же контейнера общаться друг с другом.

### Когда использовать `none`?

Несмотря на свою простоту, драйвер `none` полезен в нескольких сценариях:

1. **Полностью изолированные задачи**: Для запуска контейнеров, которым сеть не нужна в принципе. Например, для batch-заданий, которые выполняют вычисления, обрабатывая данные только из подключенного **[тома](../../Docker_fs/docker_volumes.md)**.
2. **Безопасность**: Когда требуется гарантировать, что контейнер не будет иметь никакого сетевого доступа.
3. **Пользовательская настройка сети**: В продвинутых сценариях, когда вы хотите самостоятельно настроить сеть для контейнера, используя сторонние инструменты или скрипты, которые будут работать с его сетевым пространством имён. `none` предоставляет "чистый лист" для таких манипуляций.

## Практические сценарии

### Запуск и проверка изолированного контейнера

1. **Запустите контейнер с драйвером `none`:**

    ```bash
    docker run -d --name isolated-container --network none alpine sleep 3600
    ```

2. **Проверьте сетевые интерфейсы внутри контейнера:**
    Команда покажет только интерфейс `lo`.

    ```bash
    docker exec isolated-container ip addr
    
    # Вывод:
    # 1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN qlen 1000
    #     link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    #     inet 127.0.0.1/8 scope host lo
    #        valid_lft forever preferred_lft forever
    ```

3. **Попытайтесь подключиться к внешнему ресурсу:**
    Попытка выполнить `ping` завершится ошибкой, подтверждая отсутствие сети.

    ```bash
    docker exec isolated-container ping -c 1 8.8.8.8
    
    # Вывод:
    # ping: bad address '8.8.8.8' 
    # или "Network is unreachable"
    ```
