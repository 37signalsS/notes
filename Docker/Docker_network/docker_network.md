# Сетевые модели Docker

## Определения

**Сетевые драйверы Docker** — это плагины, которые предоставляют различные способы организации сетевого взаимодействия для контейнеров. Каждый драйвер реализует свою модель изоляции, производительности и функциональности, позволяя выбирать оптимальное решение для конкретной задачи.

По умолчанию Docker при установке создает три сети: `bridge`, `host` и `none`.

### Основные концепции: Сетевые Драйверы

| Драйвер                                               | Изоляция                | Производительность  | Основной сценарий использования                                                                              |
| :---------------------------------------------------- | :---------------------- | :------------------ | :----------------------------------------------------------------------------------------------------------- |
| [`bridge`](./drivers/bridge.md)                       | Высокая (своя подсеть)  | Хорошая (через NAT) | **Сеть по умолчанию.** Изолированные контейнеры на одном хосте, локальная разработка.                         |
| [`host`](./drivers/host.md)                           | Отсутствует             | Максимальная        | Для контейнеров, которым требуется высокая производительность и прямой доступ к сети хоста (например, мониторинг).  |
| [`none`](./drivers/none.md)                           | Полная                  | N/A                 | Для задач, где требуется полная сетевая изоляция или используется кастомная сетевая конфигурация.          |
| [`overlay`](./drivers/overlay.md)                     | Высокая (между хостами) | Хорошая             | **Docker Swarm.** Для связи контейнеров, запущенных на разных хостах в распределенных системах.                |
| [`macvlan`](./drivers/macvlan.md)                     | Средняя (на уровне L2)  | Высокая             | Контейнеры становятся полноценными участниками физической сети, получая свой MAC-адрес и IP.                 |
| [`ipvlan`](./drivers/ipvlan.md)                       | Средняя (на уровне L3)  | Высокая             | Похоже на `macvlan`, но с управлением IP-адресами на уровне L3, подходит для сложных сценариев маршрутизации. |

### Практические сценарии

#### Управление сетями

Основные команды для работы с сетями Docker собраны в руководстве по [управлению сетями](./management/cli.md).

1. **Просмотр всех сетей:**

    ```bash
    docker network ls
    ```

2. **Создание новой сети:**
    Для большинства приложений рекомендуется создавать собственную `bridge`-сеть. Это обеспечивает работу [встроенного DNS](./concepts/dns_and_service_discovery.md) для разрешения имен контейнеров.

    ```bash
    docker network create my-app-net
    ```

3. **Проверка настроек сети:**
    Команда `inspect` позволяет увидеть детальную информацию о сети, включая подключенные контейнеры и их IP-адреса.

    ```bash
    docker network inspect my-app-net
    ```

### Дополнительная информация

- **Разрешение имен (DNS):** В пользовательских `bridge`-сетях Docker автоматически включает [DNS-сервер](./concepts/dns_and_service_discovery.md), который позволяет контейнерам обращаться друг к другу по именам. В сети `bridge`, созданной по умолчанию, эта функция отсутствует.
- **Интеграция с файрволом:** Docker активно управляет правилами `iptables` на хосте для обеспечения сетевой изоляции и проброса портов. Подробнее об этом можно прочитать в разделе [Решение проблем: Docker и `iptables`](./troubleshooting/iptables_integration.md).
- **Совместное использование сети:** Для тесной интеграции нескольких контейнеров (например, в паттерне "sidecar") можно использовать [режим совместного использования сетевого пространства имен](./special_modes/container_network.md) (`--network container:<name>`).
