# Сетевые модели Docker

### 1. Определения

**Сетевые драйверы Docker** — это плагины, которые предоставляют различные способы организации сетевого взаимодействия для контейнеров. Каждый драйвер реализует свою модель изоляции, производительности и функциональности, позволяя выбирать оптимальное решение для конкретной задачи.

По умолчанию Docker предоставляет три сети: `bridge`, `host` и `none`.

### 2. Основные концепции: Сравнительный обзор драйверов

| Драйвер   | Изоляция                | Производительность  | Основной сценарий использования                                              |
| :-------- | :---------------------- | :------------------ | :--------------------------------------------------------------------------- |
| `bridge`  | Высокая (своя подсеть)  | Хорошая (через NAT) | **Сеть по умолчанию.** Изолированные контейнеры на одном хосте, локальная разработка. |
| `host`    | Отсутствует             | Максимальная        | Для контейнеров, которым требуется высокая производительность и прямой доступ к сети хоста (например, мониторинг). |
| `none`    | Полная                  | N/A                 | Для задач, где требуется полная сетевая изоляция. |
| `overlay` | Высокая (между хостами) | Хорошая             | **Docker Swarm.** Для связи контейнеров, запущенных на разных хостах в распределенных системах. |
| `macvlan` | Средняя (на уровне L2)  | Высокая             | Контейнеры становятся полноценными участниками физической сети, получая свой MAC-адрес и IP. |
| `ipvlan`  | Средняя (на уровне L3)  | Высокая             | Похоже на `macvlan`, но с управлением IP-адресами на уровне L3, подходит для сложных сценариев маршрутизации. |
