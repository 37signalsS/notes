# DNS и Service Discovery в Docker

## Определения

- **DNS (Domain Name System — система доменных имён)**: Служба, преобразующая буквенные имена хостов в IP-адреса.
- **Встроенный DNS-сервер (Embedded DNS)**: Внутренний резолвер Docker (доступен по адресу `127.0.0.11`), работающий в пользовательских сетях для обеспечения связи между контейнерами.
- **Service Discovery (Обнаружение сервисов)**: Автоматический процесс поиска IP-адреса контейнера по его имени, сетевому алиасу или имени сервиса в кластере.
- **Network Alias (Сетевой псевдоним)**: Дополнительное имя, назначенное контейнеру в конкретной сети, позволяющее обращаться к нему независимо от основного имени.
- **DNS Round-Robin (Циклический DNS)**: Метод распределения нагрузки, при котором DNS-сервер возвращает список IP-адресов всех контейнеров с одинаковым алиасом в меняющемся порядке.

## Основные концепции

### Механизм работы в пользовательских сетях

В отличие от стандартной сети `bridge`, пользовательские сети (bridge, overlay, macvlan) предоставляют полноценный DNS-резолвинг.

1. **Резолвер (127.0.0.11)**: Docker автоматически настраивает `/etc/resolv.conf` внутри контейнера. Все запросы сначала попадают к демону Docker.
2. **Приоритет поиска**:
   - **Имя контейнера**: Например, `my-app`.
   - **Network Alias**: Имя, заданное через `--network-alias`.
   - **Имя сервиса (Swarm)**: Имя, под которым запущен сервис в кластере.
3. **Рекурсивный поиск**: Если имя не найдено внутри Docker, запрос проксируется на внешние DNS-серверы хоста.

### Опции конфигурации резолвера

Docker позволяет настраивать поведение DNS через параметры `docker run`:

| Параметр | Назначение | Пример |
| :--- | :--- | :--- |
| `--dns` | Задает внешний резолвер (в обход хостового). | `--dns 1.1.1.1` |
| `--dns-search` | Задает суффиксы для коротких имен. | `--dns-search dev.local` |
| `--dns-opt` | Добавляет опции в `resolv.conf` (`ndots`, `timeout`). | `--dns-opt ndots:1` |

**Особенности ndots (2026):**
В Docker по умолчанию используется `ndots:0`. Это означает, что любое имя без точки в конце считается абсолютным. В Kubernetes по умолчанию `ndots:5`, что часто вызывает лишние запросы. Знание этой разницы критично при миграции нагрузок.

### IPv6 и современные протоколы (v28+)

Начиная с версии Docker v28, встроенный DNS полноценно поддерживает **AAAA записи** (IPv6) даже в гибридных сетях. Если используется `gateway_mode_ipv6=routed`, контейнеры могут разрешать глобальные IPv6 имена напрямую через инфраструктуру провайдера.

## Практические сценарии

### Сценарий 1: Балансировка нагрузки через Alias

Запуск группы идентичных воркеров под одним DNS-именем.

```bash
# Запуск двух узлов
docker run -d --name node-1 --network-alias worker --network app-net my-worker
docker run -d --name node-2 --network-alias worker --network app-net my-worker

# Проверка резолвинга из клиента
docker run --rm --network app-net alpine nslookup worker
# → Name:      worker
# → Address 1: 172.18.0.2 (node-1)
# → Address 2: 172.18.0.3 (node-2)
```

### Сценарий 2: Динамическое обнаружение в Nginx (Swarm/Compose)

Nginx кэширует IP при старте. Чтобы он видел изменения в Docker-сети без перезагрузки, используйте встроенный резолвер.

```nginx
# Внутри конфигурации Nginx
location /api/ {
    resolver 127.0.0.11 valid=5s;
    set $backend "api-service";
    proxy_pass http://$backend:8080;
}
```
*Инструкция `set` заставляет Nginx выполнять DNS-запрос при каждом обращении (с учетом TTL в 5 секунд).*

### Сценарий 3: Использование внешнего DNS в закрытом контуре

Если контейнеру нужно видеть ресурсы во внутренней сети компании.

```bash
docker run -d \
  --network corp-net \
  --dns 10.0.0.53 \
  --dns-search internal.company.ru \
  my-business-app
```

## Дополнительная информация

### Особенности и лимиты

- **Сеть по умолчанию (default bridge)**: Разрешение имен **не работает**. Контейнеры могут общаться только по IP или через `--link` (deprecated).
- **TTL (Time To Live)**: Встроенный DNS возвращает записи с TTL 0. Это предотвращает кэширование устаревших IP-адресов приложениями, но может создавать нагрузку на демон Docker при миллионах запросов в секунду.
- **Взаимодействие с systemd-resolved**: На Linux-хостах с `systemd-resolved` Docker автоматически обнаруживает файл `/run/systemd/resolve/resolv.conf`, чтобы избежать "петель" при проксировании запросов на `127.0.0.53`.
