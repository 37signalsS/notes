# DNS и Service Discovery в Docker

## Определения

- **DNS (Domain Name System — система доменных имён)**: Служба, преобразующая буквенные имена хостов в IP-адреса.
- **Встроенный DNS-сервер (Embedded DNS)**: Внутренний резолвер Docker (доступен по адресу `127.0.0.11`), работающий в пользовательских сетях для обеспечения связи между контейнерами.
- **Service Discovery (Обнаружение сервисов)**: Автоматический процесс поиска IP-адреса контейнера по его имени или сетевому алиасу.
- **Network Alias (Сетевой псевдоним)**: Дополнительное имя, назначенное контейнеру в конкретной сети, позволяющее обращаться к нему независимо от основного имени контейнера.
- **DNS Round-Robin (Циклический DNS)**: Метод распределения нагрузки, при котором DNS-сервер возвращает список IP-адресов всех контейнеров с одинаковым алиасом в меняющемся порядке.

## Основные концепции

### Механизм работы в пользовательских сетях

В отличие от стандартной сети `bridge`, пользовательские сети предоставляют полноценный DNS-резолвинг.

1. **Резолвер**: Docker автоматически настраивает файл `/etc/resolv.conf` внутри контейнера, указывая `nameserver 127.0.0.11`.
2. **Локальный поиск**: Запросы к именам других контейнеров в той же сети перехватываются встроенным DNS-сервером.
3. **Рекурсивный поиск**: Если имя не найдено внутри Docker, запрос пересылается на внешние DNS-серверы, настроенные на хосте (или указанные через флаг `--dns`).

### Использование Network Alias для балансировки

Параметр `--network-alias` позволяет группе контейнеров отвечать на одно и то же DNS-имя.

```bash
# Запуск двух контейнеров с общим алиасом 'web'
docker run -d --name web-node1 --network-alias web --network prod-net nginx:alpine
docker run -d --name web-node2 --network-alias web --network prod-net nginx:alpine
```

При выполнении запроса `ping web`, встроенный DNS будет поочередно возвращать IP-адреса `web-node1` и `web-node2`. Это обеспечивает простейшую балансировку нагрузки на уровне L3.

### Конфигурация через параметры запуска

Docker позволяет гибко настраивать поведение резолвера для каждого контейнера:

| Параметр | Описание | Пример |
| :--- | :--- | :--- |
| `--dns` | Устанавливает IP-адрес внешнего DNS-сервера. | `--dns 8.8.8.8` |
| `--dns-search` | Задает домены поиска для коротких имен (не содержащих точек). | `--dns-search example.com` |
| `--dns-opt` | Добавляет опции в `resolv.conf` (например, `ndots` или `timeout`). | `--dns-opt ndots:2` |

**Опция ndots:** Определяет количество точек в имени, начиная с которого запрос сразу считается абсолютным (FQDN) и не дополняется доменами поиска. По умолчанию в Docker `ndots:0`.

## Практические сценарии

### Сценарий 1: Связка Frontend и Backend по имени

1. **Создание сети:**
   ```bash
   docker network create app-stack
   ```

2. **Запуск БД:**
   ```bash
   docker run -d --name db-server --network app-stack redis:alpine
   ```

3. **Проверка связи из приложения:**
   ```bash
   docker run --rm --network app-stack alpine ping -c 2 db-server
   # → PING db-server (172.18.0.2): 56 data bytes
   # → 64 bytes from 172.18.0.2: seq=0 ttl=64 time=0.081 ms
   ```

### Сценарий 2: Использование внешнего DNS-сервера в изолированной сети

Если контейнеру нужен доступ к внутренним ресурсам компании через корпоративный DNS.

```bash
docker run -it --rm \
  --network private-net \
  --dns 10.50.0.10 \
  --dns-search internal.corp \
  alpine nslookup gitlab
```

### Сценарий 3: Настройка Nginx для работы с динамическим DNS

Nginx кэширует IP-адреса при старте. Если контейнер-бекенд перезапустится с новым IP, Nginx может выдавать ошибку 502.

**Решение через resolver:**
```nginx
# Внутри nginx.conf
resolver 127.0.0.11 valid=5s;
set $backend_service "api-server";

location / {
    proxy_pass http://$backend_service:8080;
}
```
*Использование переменной заставляет Nginx выполнять DNS-запрос при каждом обращении (с учетом TTL).*

## Дополнительная информация

### Особенности и ограничения

- **Сеть по умолчанию**: В стандартной сети `bridge` разрешение имен **не работает**. Единственный способ связи — использование устаревшего (legacy) флага `--link`, который не рекомендуется для новых проектов.
- **Windows/macOS**: В Docker Desktop встроенный DNS интегрирован с системой виртуализации, что иногда требует сброса кэша DNS на хосте при проблемах.
- **TTL (Time To Live)**: Встроенный DNS Docker возвращает записи с TTL 0 или очень маленьким значением, чтобы минимизировать проблемы при пересоздании контейнеров.
