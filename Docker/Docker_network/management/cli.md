# Управление сетями Docker: CLI

## Определения

- **Сеть Docker (Docker Network)**: Виртуальная сеть, обеспечивающая изоляцию и коммуникацию между контейнерами, а также связь с внешним миром. Docker предоставляет различные [сетевые драйверы](../docker_network.md) (`bridge`, `host`, `overlay`, `macvlan`, `none`) для разных сценариев использования.

### Основные команды

#### Создание и удаление

- `docker network create <имя>`: Создать новую сеть. По умолчанию используется драйвер `bridge`.
- `docker network rm <имя>`: Удалить одну или несколько сетей.
- `docker network prune`: Удалить все неиспользуемые сети (сети, к которым не подключен ни один контейнер).

#### Просмотр и анализ

- `docker network ls`: Показать все сети.
- `docker network inspect <имя>`: Показать детальную информацию о сети, включая подключенные контейнеры и их IP-адреса.

#### Подключение и отключение контейнеров

- `docker run --network <сеть> ...`: Запустить контейнер, сразу подключив его к указанной сети.
- `docker network connect <сеть> <контейнер>`: Подключить уже работающий контейнер к дополнительной сети.
- `docker network disconnect <сеть> <контейнер>`: Отключить контейнер от сети.

### Практические сценарии

Рассмотрим полный жизненный цикл управления сетью на примере двух контейнеров.

1. **Просмотр сетей:**
    Посмотрим, какие сети уже существуют.

    ```bash
    docker network ls
    ```

2. **Создание сети:**
    Создадим свою `bridge`-сеть для изоляции приложения.

    ```bash
    docker network create my-app-net
    ```

3. **Запуск контейнера в сети:**
    Запустим `nginx` в новой сети.

    ```bash
    docker run -d --name server --network my-app-net nginx
    ```

4. **Анализ сети:**
    Убедимся, что контейнер `server` подключен к `my-app-net`.

    ```bash
    docker network inspect my-app-net
    # В выводе JSON в секции "Containers" будет информация о контейнере "server".
    ```

5. **Подключение существующего контейнера:**
    Запустим второй контейнер `alpine` без подключения к `my-app-net`, а затем подключим его "на лету".

    ```bash
    docker run -d --name client alpine sleep infinity
    docker network connect my-app-net client
    ```

    Теперь `client` может обращаться к `server` по имени.

6. **Отключение и очистка:**
    Отключим `client` и удалим неиспользуемую сеть.

    ```bash
    docker network disconnect my-app-net client
    docker stop server client && docker rm server client
    docker network prune 
    # Docker запросит подтверждение на удаление my-app-net
    ```

### Дополнительная информация

- **Расширенная конфигурация:** При создании сети с помощью `docker network create` можно указывать драйвер (`--driver`), подсеть (`--subnet`), шлюз (`--gateway`) и другие параметры, что особенно важно для `macvlan` и `overlay` сетей.
- **Мульти-сетевые контейнеры:** Один контейнер может быть подключен к нескольким сетям одновременно. Это позволяет организовывать сложные сценарии маршрутизации, например, когда контейнер имеет доступ к изолированной backend-сети и публичной frontend-сети.
