# DNS и Service Discovery в Docker

> **Цель:** Обеспечение автоматического обнаружения и взаимодействия контейнеров друг с другом по именам, а не по IP-адресам.

## Определения

- **Встроенный DNS-сервер:** Docker предоставляет DNS-сервер по адресу `127.0.0.11` в каждой пользовательской `bridge`-сети. Его задача — разрешать имена контейнеров в их внутренние IP-адреса, реализуя таким образом механизм Service Discovery.
- **`veth`-интерфейс:** Сокращение от Virtual Ethernet. Это [виртуальные "патч-корды"](../../../Linux/Networking/Concepts/linux_network_interfaces.md), которые создаются парами. Один конец пары подключается к сетевому пространству имен контейнера (виден как `eth0`), а другой — к сетевому мосту на хосте (например, `docker0`).

### Основные концепции

Когда контейнер подключается к **пользовательской** (user-defined) `bridge`-сети, происходит следующее:

1. **Настройка DNS в контейнере:** Docker автоматически прописывает адрес своего встроенного DNS-сервера (`127.0.0.11`) в файл `/etc/resolv.conf` внутри контейнера.
2. **Запрос на разрешение имени:** Когда один контейнер (например, `web`) пытается обратиться к другому (например, `db`) по имени, он формирует DNS-запрос на адрес `127.0.0.11`.
3. **Ответ DNS-сервера:** Встроенный DNS-сервер Docker находит IP-адрес, присвоенный контейнеру `db` в данной сети, и возвращает его контейнеру `web`.
4. **Установка соединения:** Получив IP-адрес, `web` устанавливает прямое соединение с `db` через [сетевой мост](../drivers/bridge.md), к которому они оба подключены.

### Практические сценарии

Рассмотрим пример, где один контейнер (`client`) обращается к другому (`server`) по имени.

1. **Создать пользовательскую сеть:**

    ```bash
    docker network create my-app-net
    ```

2. **Запустить серверный контейнер:**
    Запустим контейнер с `nginx` и дадим ему имя `server`.

    ```bash
    docker run -d --name server --network my-app-net nginx
    ```

3. **Запустить клиентский контейнер и обратиться к серверу:**
    Запустим временный контейнер и из него выполним `ping` к `server`. Docker DNS разрешит имя `server` в его IP-адрес в сети `my-app-net`.

    ```bash
    docker run --rm --network my-app-net alpine ping -c 4 server
    ```

    В выводе будет виден успешный обмен пакетами с IP-адресом контейнера `server`.

### Дополнительная информация

> **Важно:** В сети `bridge`, созданной **по умолчанию**, разрешение имен контейнеров не работает. Для корректного взаимодействия сервисов по именам всегда создавайте собственные `bridge`-сети для приложений.
>
> ```bash
> docker network create my-app-net
> ```
