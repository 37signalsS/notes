## Определения

**Проблемы с DNS в Docker** — это сбои при разрешении доменных имен из-за особенностей работы встроенного DNS-сервера Docker (`127.0.0.11`), который может терять связь с DNS-серверами хоста при изменении сетевой конфигурации.

### Основные концепции

#### Причина проблемы: рассинхронизация с хостом

По умолчанию Docker использует **встроенный DNS-сервер**, который проксирует DNS-запросы от контейнеров к DNS-серверам, настроенным на хост-системе (из `/etc/resolv.conf`).

Проблема заключается в том, что эта конфигурация **не всегда обновляется динамически**. Docker-демон может не отследить изменения DNS на хосте, если они произошли *после* запуска контейнера.

**Типичные ситуации:**

- Переподключение к другой сети (Wi-Fi, VPN).
- Перезапуск сетевых служб на хосте (`systemd-resolved`, `NetworkManager`).

В результате встроенный DNS-сервер Docker продолжает использовать старые, уже недоступные адреса, и контейнеры теряют возможность разрешать внешние доменные имена.

### Практические сценарии

#### Диагностика

1. **Проверить `resolv.conf` внутри контейнера:**
    Убедитесь, что контейнер использует встроенный DNS.

    ```bash
    docker exec -it my_container cat /etc/resolv.conf
    # nameserver 127.0.0.11 <-- это указывает на использование встроенного DNS
    ```

2. **Попытаться разрешить доменное имя:**
    Выполните `nslookup` или `dig` внутри контейнера. Ошибка разрешения укажет на проблему.

    ```bash
    docker exec -it my_container dig ya.ru
    # Ответ SERVFAIL или таймаут свидетельствует о проблеме
    ```

#### Решения

##### Решение 1: Глобальная настройка DNS для Docker (рекомендуется)

Это наиболее надежный способ, который отключает проксирование и заставляет все контейнеры использовать указанные DNS-серверы напрямую.

Отредактируйте файл `/etc/docker/daemon.json` (создайте, если его нет):

```json
{
  "dns": ["1.1.1.1", "8.8.8.8"]
}
```

* `dns`: Список IP-адресов стабильных DNS-серверов.

После изменения файла перезапустите Docker-демон:

```bash
sudo systemctl restart docker
```

##### Решение 2: Настройка DNS для конкретного контейнера

Если необходимо переопределить DNS только для одного контейнера, используйте флаг `--dns` при запуске.

```bash
docker run --dns=1.1.1.1 my_image
```

### Дополнительная информация

- **Опция `dns-opt`:** Позволяет передавать дополнительные параметры резолверу. Например, `"dns-opt": ["use-vc"]` заставляет использовать TCP вместо UDP, что может быть полезно в нестабильных сетях.
- **Проблемы с `iptables`:** В редких случаях DNS-трафик может блокироваться из-за некорректных правил SNAT в `iptables`. Для диагностики проверьте вывод команды `iptables -t nat -L -n -v`.
- **Сервис-дискавери:** Встроенный DNS также отвечает за разрешение имен других контейнеров в той же сети. Подробнее см. в [DNS и Service Discovery](../concepts/dns_and_service_discovery.md).
