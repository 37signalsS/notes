# Проблемы с DNS-резолвингом в контейнерах

## Потеря DNS при смене сети хоста

По умолчанию Docker использует **встроенный (embedded) DNS-сервер**, который слушает на адресе `127.0.0.11` внутри каждого сетевого пространства имен (network namespace) контейнера. Этот сервер проксирует DNS-запросы от контейнеров к DNS-серверам, настроенным на хост-системе (обычно из `/etc/resolv.conf`).

Проблема заключается в том, что эта связка **не всегда динамически обновляется**:

-   При смене сети на хосте (например, переподключение к Wi-Fi, `ifdown`/`ifup`) `dockerd` не всегда корректно пересобирает DNS-конфигурацию для уже запущенных контейнеров.
-   При перезапуске `systemd-resolved` или `NetworkManager` на хосте, upstream-адреса DNS-серверов могут измениться, но встроенный DNS-сервер Docker может продолжать использовать старые, уже недоступные адреса.
-   В результате контейнер продолжает отправлять DNS-запросы на `127.0.0.11`, но получает таймаут или пустой ответ.

### Как лечить

1.  **Отключить встроенный DNS и прописать внешние DNS-серверы:**
    Это самый надежный способ. Отредактируйте `daemon.json` (обычно в `/etc/docker/daemon.json`) и укажите DNS-серверы, которые будут использоваться всеми контейнерами.

    ```json
    {
      "dns": ["1.1.1.1", "8.8.8.8"],
      "dns-opt": ["use-vc"]
    }
    ```
    *   `dns`: Список IP-адресов DNS-серверов.
    *   `dns-opt`: Дополнительные опции, например, `use-vc` заставляет использовать TCP вместо UDP, что может быть полезно в некоторых сетях.

    После изменения файла не забудьте перезапустить Docker-демон:
    ```bash
    sudo systemctl restart docker
    ```

2.  **Прописать резолверы явно при запуске контейнера:**
    Если вы хотите переопределить DNS только для конкретного контейнера, используйте флаги `--dns` и `--dns-opt` в команде `docker run`.

    ```bash
    docker run --dns=1.1.1.1 --dns-opt=use-vc my_image
    ```

### Диагностика

1.  **Проверьте резолвинг внутри контейнера:**
    Выполните `nslookup` или `dig` внутри контейнера, чтобы убедиться, что он может резолвить внешние имена.

    ```bash
    docker exec -it my_container sh
    # внутри контейнера:
    dig ya.ru
    # или
    nslookup google.com
    ```

2.  **Проверьте `resolv.conf` внутри контейнера:**
    Посмотрите, какой DNS-сервер использует контейнер.

    ```bash
    docker exec -it my_container cat /etc/resolv.conf
    # nameserver 127.0.0.11 <-- это встроенный DNS
    ```

3.  **Следите за правилами `iptables`:**
    В некоторых случаях проблема может быть связана с некорректными правилами SNAT в bridge-сетях, которые "ломают" DNS-трафик. Проверьте вывод `iptables -t nat -L -n -v`.
