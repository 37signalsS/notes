# Решение проблем с DNS в Docker

## Определения

- **DNS (Domain Name System)** — система доменных имён, используемая для преобразования человекочитаемых имён хостов в IP-адреса.
- **Встроенный DNS-сервер Docker** — служба по адресу `127.0.0.11`, которая обеспечивает разрешение имён внутри контейнеров.
- **Проблемы с DNS в Docker** — сбои при разрешении доменных имён из-за особенностей работы встроенного сервера, который может терять связь с вышестоящими серверами при изменении сетевой конфигурации хоста.

## Основные концепции

### Причина проблемы: рассинхронизация с хостом

По умолчанию Docker использует встроенный DNS-сервер, который проксирует запросы от контейнеров к DNS-серверам, настроенным на хост-системе (указанным в файле `/etc/resolv.conf`).

Проблема заключается в том, что эта конфигурация **не всегда обновляется динамически**. Docker-демон может не отследить изменения DNS на хосте, если они произошли *после* запуска контейнера.

**Типичные ситуации:**

- Переподключение к другой сети (Wi-Fi, **VPN (Virtual Private Network)**).
- Перезапуск сетевых служб на хосте (`systemd-resolved`, `NetworkManager`).

В результате встроенный DNS-сервер продолжает использовать старые, уже недоступные адреса, и контейнеры теряют возможность разрешать внешние доменные имена.

## Практические сценарии

### Диагностика

1. **Проверка `resolv.conf` внутри контейнера:**
   Убедитесь, что контейнер использует встроенный DNS.
   ```bash
   docker exec -it my_container cat /etc/resolv.conf
   # nameserver 127.0.0.11 <-- указывает на использование встроенного DNS
   ```

2. **Проверка разрешения имени:**
   Выполните запрос через `nslookup` или `dig` (утилиты из пакета `dnsutils` или `bind9-host`).
   ```bash
   docker exec -it my_container dig ya.ru
   # Ответ SERVFAIL или таймаут свидетельствует о проблеме
   ```

### Методы решения

#### Сценарий 1: Глобальная настройка DNS (рекомендуется)

Наиболее надёжный способ, который заставляет все контейнеры использовать стабильные общедоступные или корпоративные серверы напрямую, игнорируя настройки хоста.

Отредактируйте файл `/etc/docker/daemon.json` (создайте его, если он отсутствует):

```json
{
  "dns": ["1.1.1.1", "8.8.8.8"]
}
```

Параметр `dns` принимает список **IP (Internet Protocol)** адресов стабильных серверов.

После изменения конфигурации перезапустите Docker-демон:
```bash
sudo systemctl restart docker
```

#### Сценарий 2: Настройка DNS для конкретного контейнера

Если переопределение требуется только для одного сервиса, используйте флаг `--dns` при запуске через **CLI (Command Line Interface)**:

```bash
docker run --dns=1.1.1.1 my_image
```

#### Сценарий 3: Использование TCP вместо UDP

Опция `dns-opt` позволяет передавать параметры резолверу. Параметр `use-vc` заставляет использовать **TCP (Transmission Control Protocol)** вместо **UDP (User Datagram Protocol)**, что полезно в нестабильных сетях или при больших DNS-ответах.

```json
{
  "dns": ["1.1.1.1", "8.8.8.8"],
  "dns-opt": ["use-vc"]
}
```

#### Сценарий 4: Проверка правил межсетевого экрана

В редких случаях трафик может блокироваться из-за некорректных правил **SNAT (Source Network Address Translation)** в `iptables`.

```bash
sudo iptables -t nat -L -n -v
```

Подробная диагностика и методы решения проблем с **NAT (Network Address Translation)** и файрволом описаны в документе **[Интеграция с iptables](./iptables_integration.md)**.
