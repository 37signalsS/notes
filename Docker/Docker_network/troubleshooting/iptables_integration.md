# Интеграция Docker с iptables и nftables

## Определения

- **`iptables`** — классическая утилита и фреймворк для управления правилами фильтрации пакетов Netfilter в ядре Linux. Docker исторически активно использует `iptables` для реализации сетевой изоляции и проброса портов.
- **`nftables`** — современный фреймворк, пришедший на смену `iptables`. В новых дистрибутивах Linux (Debian 10+, Ubuntu 20.04+) используется по умолчанию.
- **`iptables-nft`** — слой совместимости, позволяющий использовать синтаксис `iptables` для управления правилами `nftables`.
- **`iptables-legacy`** — классический режим работы `iptables`, который управляет правилами Netfilter напрямую, в обход `nftables`.
- **Цепочка `DOCKER-USER`** — специальная цепочка в `iptables`, создаваемая Docker. Предназначена для добавления пользовательских правил, которые должны выполняться *перед* любыми правилами, автоматически созданными Docker.
- **IP (Internet Protocol)** — межсетевой протокол, используемый для маршрутизации пакетов.
- **NAT (Network Address Translation)** — механизм преобразования сетевых адресов.

## Основные концепции

Взаимодействие Docker с сетевым стеком хоста основано на фреймворке Netfilter. Подробно о его работе и утилитах управления рассказано в заметке **[Основы iptables](../../../Linux/Networking/Settings/tools/iptables_basics.md)**.

Docker для обеспечения сетевой функциональности (проброс портов, изоляция сетей) добавляет в `iptables` собственные правила. Ключевые моменты взаимодействия:

1. **Проброс портов:** Трафик, предназначенный для опубликованных портов контейнеров, проходит через цепочки `PREROUTING` и `OUTPUT` в таблице `nat`, а затем маршрутизируется через цепочку `FORWARD` в таблице `filter`.
2. **Пользовательские правила:** Docker ожидает, что администратор будет добавлять свои правила файрвола в цепочку `DOCKER-USER`, а не в `FORWARD`. Это позволяет избежать конфликтов и гарантирует, что пользовательские правила будут обработаны в первую очередь.
3. **Автоопределение бэкенда:** Начиная с версии 20.10, Docker автоматически определяет, какой бэкенд используется в системе (`iptables-legacy` или `iptables-nft`), и взаимодействует с ним.

## Практические сценарии

### Сценарий 1: Доступ к контейнерам при политике `FORWARD DROP`

**Проблема:** Файрвол настроен с политикой по умолчанию `DROP` для цепочки `FORWARD`. Контейнер с пробросом порта (например, `-p 8080:80`) доступен по `localhost:8080`, но недоступен извне.

**Причина:** Трафик, перенаправляемый в контейнер, должен пройти через цепочку `FORWARD`. Политика `DROP` блокирует эти пакеты до того, как они достигнут цепочек Docker.

**Диагностика:**

Проверьте счетчики пакетов через **CLI (Command Line Interface)**:

```sh
sudo iptables -L FORWARD -v -n
```

Растущие счётчики в цепочке `FORWARD` свидетельствуют о блокировке.

**Решение:**

Добавьте разрешающие правила в цепочку `DOCKER-USER`. Это наиболее безопасный и рекомендуемый способ, так как он не ослабляет основную политику `FORWARD DROP`.

```sh
# Разрешить установленные и связанные соединения к контейнерам
sudo iptables -I DOCKER-USER -i <внешний_интерфейс> -o docker0 -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT

# Разрешить трафик из контейнеров наружу (если необходимо)
sudo iptables -I DOCKER-USER -i docker0 -o <внешний_интерфейс> -j ACCEPT
```

Замените `<внешний_интерфейс>` на имя реального сетевого интерфейса (например, `eth0`).

### Сценарий 2: Конфликт `iptables-nft` со сторонними службами

**Проблема:** В системах, использующих `nftables` (например, с `firewalld`), правила, добавленные Docker через слой совместимости `iptables-nft`, могут периодически затираться или конфликтовать с правилами, управляемыми `firewalld` напрямую.

**Решение:**

Принудительно переключите Docker на использование `iptables-legacy` для изоляции его правил от `nftables`.

1. **Переключите системные утилиты на `iptables-legacy`:**

    ```bash
    # Для Debian/Ubuntu
    sudo update-alternatives --set iptables /usr/sbin/iptables-legacy
    sudo update-alternatives --set ip6tables /usr/sbin/ip6tables-legacy
    ```

2. **Перезапустите Docker:**

    ```bash
    sudo systemctl restart docker
    ```

После этого Docker будет создавать и управлять своими правилами исключительно в `iptables-legacy`, не конфликтуя с другими службами, управляющими `nftables`.
