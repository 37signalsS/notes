# Режим сети `container:<name>`

## Определения

**`--network container:<имя>`** — специальный режим в Docker, позволяющий запустить контейнер в сетевом пространстве имен (network namespace) другого, уже существующего контейнера. Это приводит к тому, что они разделяют один и тот же сетевой стек, включая IP-адрес и сетевой интерфейс `localhost`.

### Основные концепции

При запуске второго контейнера с флагом `--network container:<имя>`, Docker не создает для него новый сетевой стек, а помещает его процессы в пространство имен первого, "целевого" контейнера.

В результате оба контейнера:

- Имеют **общий IP-адрес**.
- Могут взаимодействовать друг с другом через `localhost`.
- **Полностью лишены сетевой изоляции** между собой.

Основной вариант использования — паттерн **Sidecar**, когда к основному приложению присоединяется вспомогательный контейнер для отладки, мониторинга или проксирования трафика.

### Практические сценарии

#### Отладка с помощью Sidecar-контейнера

Этот пример позволяет анализировать трафик основного контейнера, не устанавливая в его образ дополнительные утилиты.

1. **Запуск основного контейнера:**

    ```bash
    # Запускаем Nginx, имя контейнера - my-app
    docker run -d --name my-app nginx
    ```

2. **Запуск "sidecar" для отладки:**
    Присоединяем контейнер с набором сетевых утилит (например, `nicolaka/netshoot`) к сетевому пространству `my-app`.

    ```bash
    # Запускаем sidecar в том же network namespace
    docker run --rm -it --network container:my-app nicolaka/netshoot
    ```

    Теперь внутри контейнера `netshoot` можно выполнять команды `tcpdump -i lo` или `netstat -tulpn` и видеть сетевую активность контейнера `my-app` так, как если бы они выполнялись в нем самом.

- **Зависимость жизненного цикла:** Если основной контейнер останавливается или перезапускается, сетевой стек для sidecar-контейнера исчезает, и он теряет связь.
- **Проброс портов:** Флаги проброса портов (`-p` или `-P`) на sidecar-контейнере **игнорируются**. Все порты должны быть открыты на основном, "целевом" контейнере.
- **Связь с Kubernetes:** Эта концепция является основой сетевой модели в **Kubernetes Pods**, где все контейнеры внутри одного пода также разделяют общее сетевое пространство имен.
