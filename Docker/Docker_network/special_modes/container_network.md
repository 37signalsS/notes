### Совместное использование сетевого пространства имен: `--network container:`

Помимо стандартных драйверов, Docker предоставляет мощную возможность запустить контейнер в сетевом пространстве имен (network namespace) другого, уже существующего контейнера. Это позволяет им разделять один и тот же сетевой стек, включая IP-адрес и интерфейс `localhost`.

```bash
docker run --network container:<имя_или_ID_целевого_контейнера> ...
```

**Как это работает:**

1.  Вы запускаете первый, "целевой" контейнер (например, `my-app`). Docker создает для него сетевое пространство имен.
2.  Вы запускаете второй, "присоединяемый" контейнер с флагом `--network container:my-app`. Docker не создает для него новый сетевой стек, а помещает его процессы в пространство имен контейнера `my-app`.

**Результат:**

*   Оба контейнера имеют один и тот же IP-адрес.
*   Процессы из одного контейнера могут обращаться к портам, открытым в другом контейнере, через `localhost`. Например, если `my-app` слушает порт `8080`, второй контейнер может подключиться к нему по `localhost:8080`.
*   Сетевая изоляция между этими двумя контейнерами отсутствует.

**Практические кейсы:**

1.  **Sidecar-контейнеры для отладки и мониторинга:**

    *   Вы можете запустить контейнер с набором сетевых утилит (`tcpdump`, `netstat`, `ping`) и присоединить его к работающему контейнеру приложения, чтобы анализировать его трафик, не устанавливая эти утилиты в основной образ.
    *   **Пример:**
        ```bash
        # Запускаем основной контейнер(имя контейнера будет my-app и собираеться он из образа nginx:1.25.5)
        docker run -d --name my-app nginx:1.25.5

        # Запускаем "sidecar" для отладки в том же network namespace
        # Утилита nicolaka/netshoot содержит множество сетевых инструментов
        docker run --rm -it --network container:my-app nicolaka/netshoot:v0.12.0
        ```
        Теперь внутри контейнера `netshoot` вы можете выполнять команды вроде `tcpdump -i lo` или `netstat -tulpn` и видеть сетевую активность контейнера `my-app`. Для более детального анализа сетевого трафика с использованием `tcpdump` и Wireshark, см. [Wireshark и анализ сетевого трафика](../../../Networking/ServicesAndTools/wireshark_and_packet_capture.md).
