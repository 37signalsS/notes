# Определения

**`--network container:`** — специальный режим в Docker, позволяющий запустить контейнер в сетевом пространстве имен (network namespace) другого, уже существующего контейнера. Это приводит к тому, что они разделяют один и тот же сетевой стек, включая IP-адрес и сетевой интерфейс `localhost`.

# Основные концепции

## Как это работает

1.  Запускается первый, "целевой" контейнер (например, `my-app`). Docker создает для него собственное сетевое пространство имен.
2.  Запускается второй, "присоединяемый" контейнер с флагом `docker run --network container:my-app ...`. Docker не создает для него новый сетевой стек, а помещает его процессы в пространство имен контейнера `my-app`.

## Результат

*   **Общий IP-адрес:** Оба контейнера имеют один и тот же IP-адрес и видят сетевые интерфейсы друг друга.
*   **Взаимодействие через `localhost`:** Процессы из одного контейнера могут обращаться к портам, открытым в другом, через `localhost`. Например, если `my-app` слушает порт `8080`, второй контейнер может подключиться к нему по `localhost:8080`.
*   **Отсутствие сетевой изоляции:** Сетевая изоляция между этими двумя контейнерами полностью отсутствует.

# Практические сценарии

## Sidecar-контейнеры для отладки и мониторинга

Основной вариант использования — присоединение к работающему контейнеру вспомогательного "sidecar"-контейнера с инструментами для отладки или мониторинга. Это позволяет анализировать трафик и состояние основного контейнера, не устанавливая в его образ дополнительные утилиты.

### Пример

1.  **Запуск основного контейнера:**
    ```bash
    # Запускаем Nginx в фоновом режиме, имя контейнера - my-app
    docker run -d --name my-app nginx:1.25.5
    ```

2.  **Запуск "sidecar" для отладки:**
    Присоединяем контейнер с набором сетевых утилит (например, `nicolaka/netshoot`) к сетевому пространству `my-app`.
    ```bash
    # Запускаем sidecar в том же network namespace
    docker run --rm -it --network container:my-app nicolaka/netshoot:v0.12.0
    ```
    Теперь внутри контейнера `netshoot` можно выполнять команды `tcpdump -i lo` или `netstat -tulpn` и видеть сетевую активность контейнера `my-app`.
