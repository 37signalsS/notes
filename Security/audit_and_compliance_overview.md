# Аудит и Комплаенс (Audit & Compliance): Обзор

## Определения

**Аудит (Audit)** — это процесс независимой проверки и оценки систем, процессов или данных для определения их соответствия установленным критериям. В IT аудит проверяет безопасность, производительность и соответствие политикам.

**Комплаенс (Compliance)** — это соответствие определенным требованиям, стандартам или законам. В IT это часто относится к стандартам безопасности, таким как PCI DSS, GDPR, ISO 27001, и внутренним политикам компании.

Журналы (логи) являются основным источником доказательств для обеих практик.

## Основные концепции

### Цели аудита и комплаенса

* **Безопасность:** Обнаружение и расследование инцидентов, подтверждение работы контролей безопасности.
* **Соответствие требованиям:** Предоставление доказательств для внешних и внутренних аудиторов (например, SOC 2, ISO 27001).
* **Подотчетность:** Ответ на вопросы "кто, что, когда и почему сделал" в системе.
* **Устранение неполадок:** Анализ событий, приведших к сбоям.

### Ключевые стандарты комплаенса

* **PCI DSS (Payment Card Industry Data Security Standard):** Стандарт безопасности для организаций, работающих с данными платежных карт.
* **GDPR (General Data Protection Regulation):** Регламент по защите персональных данных граждан ЕС.
* **HIPAA (Health Insurance Portability and Accountability Act):** Стандарт для защиты конфиденциальной медицинской информации в США.
* **SOC 2 (Service Organization Control 2):** Стандарт для отчета о контролях в сервисных организациях, касающихся безопасности, доступности, целостности обработки, конфиденциальности и приватности.
* **ISO/IEC 27001:** Международный стандарт по управлению информационной безопасностью.

### Ключевые свойства аудиторских логов

Для того чтобы логи имели доказательную силу, они должны обладать следующими свойствами:

* **Полнота**: Фиксируются все существенные события (аутентификация, авторизация, изменения конфигурации, доступ к данным).
* **Точность времени**: Синхронизация по NTP, единый формат времени (UTC).
* **Неизменяемость и целостность**: Использование WORM-хранилищ, контрольные суммы, цифровые подписи.
* **Контекст и структурированность**: Единая схема, идентификаторы корреляции (`trace_id`).
* **Безопасность**: Централизованная доставка по защищенным каналам, шифрование.
* **Конфиденциальность**: Маскирование персональных данных (PII) и секретов.

## Практические сценарии

### Что логировать для аудита

| Тип события | Что фиксировать | Зачем аудиту |
| :--- | :--- | :--- |
| Аутентификация/сессии | субъект, метод, источник, результат | доказательство контроля доступа |
| Привилегированные действия | команда/операция, объект, контекст | подотчетность и неотказуемость |
| Изменения конфигурации/IaC | кто, что, из какой ветки/релиза | прослеживаемость изменений |
| Доступ к данным | тип данных, объем, цель, статус | соблюдение принципов минимизации |
| Выпуск и операции CI/CD | пайплайн, артефакт, среда, одобрения | соответствие процессам change management |
| Сетевые и K8s политики | правило, субъект, эффект | соответствие сегментации и RBAC |

### Пример структурированного события

```json

  "ts": "2025-04-12T10:15:30Z",

  "trace_id": "4f2b8c1f...",
  "env": "prod",
  "reason": "pipeline#248",
  "integrity_hash": "sha256:9a..."
}
```

### Специфичные реализации аудита

* **Аудит на уровне ОС:** Для детального отслеживания системных вызовов и доступа к файлам используется [**`auditd`**](../Linux/SystemAdministration/Logging/auditd.md).
* **Аудит в Kubernetes:** Настраивается через политики аудита для отслеживания всех запросов к API-серверу.
* **Аудит в GitOps:** Реализуется через анализ коммитов в Git, который служит единым источником правды об изменениях. Подробнее см. в [ведении логов аудита при GitOps](../GitOps/Concepts/audit_logs.md).
* **Аудит зависимостей:** Проверка библиотек на наличие уязвимостей с помощью [инструментов анализа зависимостей](Supply_Chain_Security/dependency_and_sbom_analysis.md).

### Инструменты для аудита и комплаенса

* **[Lynis](Tools/lynis.md):** Инструмент для аудита безопасности и hardening'а Unix-подобных систем.
* **[Wazuh](Tools/wazuh.md):** Платформа SIEM и XDR с открытым исходным кодом, помогающая в сборе логов, обнаружении вторжений и обеспечении комплаенса.

## Дополнительная информация

* **Централизация логов:** Для эффективного аудита логи должны собираться в централизованном, защищенном хранилище (SIEM-система, например, ELK Stack, Splunk, Wazuh).
* **Политики хранения:** Политики хранения логов (retention policies) должны соответствовать требованиям стандартов и законодательства.
