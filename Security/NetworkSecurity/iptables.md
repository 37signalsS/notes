# IPTables: Основы и настройка файрвола

`iptables` — это утилита командной строки, которая позволяет настраивать правила фильтрации пакетов в ядре Linux. Она является интерфейсом для управления подсистемой `NetFilter`.

## Основные концепции

### NetFilter и путь пакета

`NetFilter` — это фреймворк в ядре Linux, который позволяет перехватывать и манипулировать сетевыми пакетами. Пакеты, проходящие через сетевой стек, пересекают определённые точки, называемые "хуками" (hooks). `iptables` использует эти хуки для применения правил, сгруппированных в **цепочки (chains)**.

Понимание пути пакета — ключ к правильной настройке `iptables`.

![NetFilter Packet Flow](https://upload.wikimedia.org/wikipedia/commons/3/37/Netfilter-packet-flow.svg)

1.  **`PREROUTING`**: Самый первый этап для входящего пакета. Здесь принимается решение, предназначен ли пакет для локального процесса или его нужно направить дальше (маршрутизировать). Используется для NAT (DNAT).
2.  **Маршрутизация (Routing Decision)**: Ядро определяет, куда направить пакет.
    - Если пакет предназначен для локального сервера (например, для вашего веб-сервера), он переходит в цепочку `INPUT`.
    - Если пакет предназначен для другой сети (сервер выступает в роли маршрутизатора), он переходит в цепочку `FORWARD`.
3.  **`INPUT`**: Цепочка для пакетов, адресованных локальным приложениям. **Это основная цепочка для настройки файрвола на обычном сервере.**
4.  **`FORWARD`**: Цепочка для пакетов, которые проходят через сервер транзитом в другую сеть. Используется, например, в Docker.
5.  **`OUTPUT`**: Цепочка для пакетов, сгенерированных локальными приложениями на вашем сервере.
6.  **`POSTROUTING`**: Последний этап перед отправкой пакета в сеть. Используется для NAT (SNAT/Masquerading).

### Таблицы (Tables)

Правила в `iptables` организованы в таблицы. Каждая таблица предназначена для определённого типа обработки пакетов. При вызове `iptables` без указания таблицы используется `filter` по умолчанию.

-   **`filter`**: Основная и самая используемая таблица. Содержит цепочки `INPUT`, `FORWARD` и `OUTPUT`. Именно здесь настраивается основная логика файрвола (разрешить/запретить).
-   **`nat`**: Используется для преобразования сетевых адресов (Network Address Translation). Полезна для маршрутизаторов и для проброса портов (например, в Docker). Содержит цепочки `PREROUTING`, `POSTROUTING`, `OUTPUT`.
-   **`mangle`**: Для продвинутой модификации заголовков пакетов (например, изменение TTL, ToS).
-   **`raw`**: Для работы с пакетами до того, как система начнёт отслеживать их состояние (connection tracking). Используется для исключения пакетов из системы отслеживания соединений.

## Диагностика сети перед настройкой

Перед тем как начать настраивать файрвол, важно понять, какие службы уже запущены и какие порты они слушают.

- **Проверка открытых портов (TCP и UDP)**:
  Современная утилита `ss` (`Socket Statistics`) является заменой `netstat`.
  ```bash
  # -n: числовой вывод (не резолвить имена)
  # -t: TCP, -u: UDP
  # -l: только слушающие сокеты
  # -p: показать процессы, использующие сокет
  sudo ss -ntulp
  ```
  *Обратите внимание на `Local Address:Port`. Если адрес `0.0.0.0` или `::`, служба слушает на всех интерфейсах и потенциально доступна извне.*

- **Просмотр сетевых интерфейсов**:
  ```bash
  ip a
  ```
  *Запомните имена ваших интерфейсов (например, `enp0s3`, `eth0`), они понадобятся для создания специфичных правил.*

## Пошаговая настройка файрвола для веб-сервера

**Золотое правило конфигурации файрвола:** сначала создаются разрешающие (`ACCEPT`) правила для всего необходимого трафика, и только после этого устанавливается запрещающая (`DROP`) политика по умолчанию. Такой подход гарантирует, что вы не потеряете доступ к серверу в процессе настройки.

**Предупреждение:** При настройке файрвола по SSH всегда начинайте с правила, разрешающего ваше собственное подключение. Иначе вы рискуете заблокировать себе доступ.

1. **Просмотр текущих правил**:
   Убедитесь, что файрвол в исходном состоянии (все политики в `ACCEPT` и нет правил).
   ```bash
   # -L: показать правила
   # -v: подробный вывод (счетчики пакетов и байт)
   # -n: числовой вывод
   sudo iptables -L -v -n
   ```

2. **Разрешить SSH-подключения (самое важное правило!)**:
   ```bash
   # -A INPUT: добавить правило в конец цепочки INPUT
   # -p tcp: протокол TCP
   # --dport 22: порт назначения 22 (SSH)
   # -j ACCEPT: действие "принять"
   sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
   ```
   *Если вы используете нестандартный порт SSH, укажите его вместо `22`.*

3. **Разрешить трафик на loopback-интерфейсе**:
   Это критически важно для корректной работы многих локальных приложений.
   ```bash
   # -i lo: для трафика, входящего на интерфейс lo (loopback)
   sudo iptables -A INPUT -i lo -j ACCEPT
   sudo iptables -A OUTPUT -o lo -j ACCEPT
   ```

4. **Разрешить уже установленные и связанные соединения**:
   Это "умное" правило, которое позволяет автоматически пропускать ответный трафик для соединений, инициированных вашим сервером (например, при скачивании обновлений).
   ```bash
   # -m state: использовать модуль отслеживания состояний
   # --state ESTABLISHED,RELATED: для пакетов, которые являются частью уже установленного или связанного с ним соединения
   sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
   ```

5. **Разрешить ICMP (ping)**:
   Позволяет диагностировать доступность сервера.
   ```bash
   sudo iptables -A INPUT -p icmp -j ACCEPT
   ```

6. **Разрешить веб-трафик (HTTP и HTTPS)**:
   ```bash
   sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
   sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
   ```

7. **Изменить политику по умолчанию на `DROP` (финальный шаг)**:
   После того как вы добавили все разрешающие правила, можно безопасно "закрыть" все остальное.
   ```bash
   # -P INPUT: установить политику по умолчанию для цепочки INPUT
   # DROP: молча отбрасывать пакеты
   sudo iptables -P INPUT DROP
   sudo iptables -P FORWARD DROP
   sudo iptables -P OUTPUT DROP
   ```
   *Если после выполнения этой команды ваше SSH-соединение не прервалось — поздравляем, базовая настройка прошла успешно!*

## `DROP` vs `REJECT`

При блокировке трафика у вас есть два основных варианта:

- `DROP`: Пакеты молча отбрасываются. Отправитель не получает никакого ответа и видит `Connection timed out`. Это предпочтительный способ: он не раскрывает информацию о том, что за портом есть хост, и экономит ресурсы, так как не генерирует ответные пакеты.
- `REJECT`: Отправителю отправляется ICMP-сообщение об ошибке (`connection refused`). Это явно информирует о том, что порт закрыт файрволом. Используется редко, в основном для отладки.

## Сохранение правил

Правила `iptables` по умолчанию сбрасываются при перезагрузке. Чтобы сделать их постоянными:

- **Временное сохранение и восстановление вручную**:
  ```bash
  # Сохранить текущие правила в файл
  sudo iptables-save > ~/iptables.rules
  # Восстановить правила из файла (все текущие правила будут удалены)
  sudo iptables-restore < ~/iptables.rules
  ```

- **Постоянное сохранение (Debian/Ubuntu)**:
  Используйте пакет `iptables-persistent`.
  ```bash
  sudo apt-get update
  sudo apt-get install iptables-persistent netfilter-persistent
  ```
  При установке будет предложено сохранить текущие правила для IPv4 и IPv6. Они будут сохранены в `/etc/iptables/rules.v4` и `/etc/iptables/rules.v6`.

  Для управления правилами в дальнейшем используйте `netfilter-persistent`:
  ```bash
  # Сохранить текущие (активные) правила iptables в файл
  sudo netfilter-persistent save

  # Загрузить правила из файла в ядро
  sudo netfilter-persistent start
  ```

## Частые операции

### Управление правилами

- **Очистить все правила**:
  Будьте осторожны, это может заблокировать вам доступ, если политика по умолчанию `DROP`.
  ```bash
  # Удалить все правила из всех цепочек
  sudo iptables -F
  # Удалить все пользовательские цепочки
  sudo iptables -X
  ```

- **Удалить правило по номеру**:
  ```bash
  # Посмотреть правила с номерами
  sudo iptables -L INPUT --line-numbers
  # Удалить правило №3 из цепочки INPUT
  sudo iptables -D INPUT 3
  ```

### Примеры правил

- **Блокировка конкретного IP-адреса**:
  Если вы видите вредоносную активность с определённого IP, его можно заблокировать.
  ```bash
  # -I INPUT 1: вставить правило в начало цепочки INPUT (чтобы оно сработало раньше разрешающих правил)
  # -s 1.2.3.4: IP-адрес источника
  sudo iptables -I INPUT 1 -s 1.2.3.4 -j DROP
  ```

- **Разрешить входящие SSH-соединения с определённого IP**:
  ```bash
  sudo iptables -A INPUT -p tcp --dport 22 -s 172.16.238.15 -j ACCEPT
  ```

- **Разрешить исходящие HTTP/HTTPS соединения (если политика OUTPUT в DROP)**:
  ```bash
  sudo iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT
  sudo iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT
  ```

- **Правила для конкретного интерфейса**:
  Иногда полезно применять правила только к трафику, который приходит на определённый сетевой интерфейс.
  ```bash
  # Разрешить SSH только на внутреннем интерфейсе
  # Замените enp0s3 на имя вашего интерфейса
  sudo iptables -A INPUT -i enp0s3 -p tcp --dport 22 -j ACCEPT
  ```
  - `-i enp0s3`: указывает входящий интерфейс.

## Взаимодействие iptables и Docker

> **Ключевой момент:** Docker управляет своими правилами `iptables` и направляет трафик к контейнерам через цепочку **`FORWARD`**, а не `INPUT`.

- **Трафик к контейнерам идёт через `FORWARD`:** Когда вы пробрасываете порт с хоста в контейнер (например, `docker run -p 8080:80`), Docker добавляет правила в таблицу `nat`, чтобы перенаправлять трафик. Этот перенаправленный трафик обрабатывается цепочкой `FORWARD`, а не `INPUT`, как можно было бы ожидать.

**Проблема:** Если вы установили политику по умолчанию `sudo iptables -P FORWARD DROP`, вы не сможете получить доступ к опубликованным портам контейнеров.

**Правильное решение:** Docker создал специальную цепочку `DOCKER-USER`, которая выполняется раньше всех остальных правил Docker. Все кастомные правила для контейнеров следует добавлять в нее.

-   **Пример: разрешить доступ к порту 8080 с определенного IP:**
    ```bash
    # Трафик на все остальные порты будет обработан стандартными правилами Docker или заблокирован
    sudo iptables -I DOCKER-USER -i ext_if -p tcp --dport 8080 -s 1.2.3.4 -j ACCEPT
    ```
    - `-I DOCKER-USER`: Вставить правило в начало цепочки `DOCKER-USER`.
    - `-i ext_if`: Укажите ваш внешний сетевой интерфейс.

### Ограничение количества подключений

```bash
# Ограничить количество подключений к порту 22 (SSH) до 3 с одного IP-адреса
sudo iptables -A INPUT -p tcp --syn --dport 22 -m connlimit --connlimit-above 3 --connlimit-mask 32 -j REJECT --reject-with tcp-reset
```
-   `--syn`: Применять правило только к пакетам, инициирующим новое соединение.
-   `--connlimit-above 3`: Срабатывает, если количество соединений превышает 3.
-   `--connlimit-mask 32`: Применять лимит для каждого отдельного IP-адреса источника (для IPv4).
-   `-j REJECT --reject-with tcp-reset`: Отклонить соединение с отправкой TCP RST пакета. Можно использовать `-j DROP` для молчаливого отбрасывания.

Это правило позволяет предотвратить атаки типа "отказ в обслуживании" (DoS) и ограничить количество одновременных сессий для сервисов.
