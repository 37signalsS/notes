# MFA (Multi-Factor Authentication) и TOTP (Time-Based One-Time Password)

## Definitions

### MFA (Multi-Factor Authentication)

**MFA** — метод аутентификации, требующий ≥2 факторов из разных категорий:

| Фактор | Описание | Примеры |
|--------|----------|---------|
| **Знание** (Knowledge) | Что-то, что знает пользователь | Пароль, PIN, ответ на секретный вопрос |
| **Владение** (Possession) | Что-то, чем владеет пользователь | Смартфон, USB-токен (YubiKey), смарт-карта |
| **Сущность** (Inherence) | Биометрические данные | Отпечаток пальца, скан лица, голос |
| **Местоположение** (Location) | Геопозиция/сеть | IP-адрес, GPS-координаты |

**2FA** — подмножество MFA с ровно двумя факторами.

### TOTP (Time-Based One-Time Password)

**TOTP** — алгоритм генерации временных одноразовых кодов ([RFC 6238](https://datatracker.ietf.org/doc/html/rfc6238)), основанный на:

- **Секретном ключе** (shared secret) — известен серверу и клиенту
- **Текущем времени** — стандартный интервал 30 с
- **HMAC-SHA1/SHA256/SHA512** — для генерации кода

Формула: `TOTP = Truncate(HMAC-SHA(K, T))`, где:

- `K` — секретный ключ
- `T = (UnixTime - T0) / X` — номер временного интервала (`T0 = 0`, `X = 30`)
- Результат усекается до 6–8 цифр

### HOTP (HMAC-Based One-Time Password)

**HOTP** ([RFC 4226](https://datatracker.ietf.org/doc/html/rfc4226)) — аналог TOTP, использующий **счётчик** вместо времени. Формула: `HOTP = Truncate(HMAC-SHA(K, C))`, где `C` — монотонно растущий счётчик.

## Basic Concepts

### Принцип работы TOTP

1. **Provisioning:** сервер генерирует `secret`, передаёт пользователю через QR-код (OTP Auth URI: `otpauth://totp/Issuer:user?secret=SECRET&issuer=Issuer`)
2. **Генерация:** клиент вычисляет `T = floor(now / 30)`, применяет `HMAC-SHA(K, T)`, усекает до 6–8 цифр
3. **Верификация:** сервер вычисляет код для `T` и соседних интервалов (`T ± 1` — grace period), сравнивает с введённым

### Сравнение MFA-методов

| Метод | Тип | Плюсы | Минусы |
|-------|-----|-------|--------|
| **TOTP** (Google Authenticator, Authy) | Владение | Оффлайн-генерация, нет зависимости от сети | Требует синхронизации времени |
| **SMS/Email коды** | Владение | Простота | Уязвимы к SIM-swapping, перехвату |
| **Push-уведомления** | Владение | Удобство (нет ввода кода) | Требуют интернета |
| **U2F/FIDO2** (YubiKey) | Владение | Наивысшая безопасность, защита от фишинга | Стоимость, риск потери |
| **Биометрия** | Сущность | Удобство | Невозможность ротации при компрометации |

## Practical Scenarios

### Генерация и верификация TOTP (Python)

```python
import pyotp

# Генерация секрета
secret = pyotp.random_base32()

# OTP Auth URI для QR-кода
totp = pyotp.TOTP(secret)
uri = totp.provisioning_uri(name="user@example.com", issuer_name="MyApp")

# Верификация (с grace period ±1 окно по умолчанию)
is_valid = totp.verify(user_input_code)
```

### Рекомендации по внедрению

- **Резервные коды:** генерировать 8–10 одноразовых кодов при настройке; хранить **хеш** (bcrypt/argon2), не plaintext
- **Grace period:** допускать `T ± 1` для компенсации рассинхронизации часов
- **Резервный метод:** предусмотреть альтернативу при утере устройства (не SMS)
- **Хранение секретов:** шифровать на rest (KMS, HSM, Vault TOTP engine)
- **Rate limiting:** ограничить число попыток верификации для защиты от брутфорса

## Additional Information

### Безопасность TOTP

- **Оффлайн-генерация:** код создаётся локально, без связи с сервером
- **Одноразовость:** код валиден только в текущем временном окне
- **Фишинг:** TOTP **не защищён** от фишинга — код можно перехватить и использовать в течение окна валидности. Митигация: [WebAuthn/FIDO2](https://fidoalliance.org/fido2/), привязанный к домену через криптографию

### Уязвимости и митигация

| Угроза | Митигация |
|--------|-----------|
| Фишинг TOTP | Переход на WebAuthn/FIDO2 |
| Кража секрета | Хранение в HSM/KMS, шифрование на rest |
| Рассинхронизация | Grace period `±1` окно |
| SIM-swapping | Исключить SMS как фактор |
| Брутфорс кода | Rate limiting, блокировка после N попыток |
