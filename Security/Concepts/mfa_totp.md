# MFA и TOTP — многофакторная аутентификация

## Определения

### MFA (Multi-Factor Authentication)

**MFA** — метод аутентификации, требующий предоставления двух или более независимых факторов подтверждения личности из разных категорий:

| Категория фактора | Описание | Примеры |
| :--- | :--- | :--- |
| **Знание** (Knowledge) | То, что пользователь знает | Пароль, PIN-код, ответ на секретный вопрос |
| **Владение** (Possession) | То, чем пользователь владеет | Смартфон, USB-токен (YubiKey), смарт-карта |
| **Сущность** (Inherence) | То, чем пользователь является (биометрия) | Отпечаток пальца, скан лица, голос |
| **Местоположение** (Location) | Географическая позиция или сеть | Доверенный IP-адрес, GPS-координаты |

**2FA** (Two-Factor Authentication) — частный случай MFA, использующий ровно два фактора.

### TOTP (Time-Based One-Time Password)

**TOTP** — алгоритм генерации временных одноразовых паролей ([RFC 6238](https://datatracker.ietf.org/doc/html/rfc6238)), основанный на общем секрете и текущем времени.

Ключевые параметры:

- **Shared Secret** (K) — секретный ключ, известный серверу и приложению.
- **Time Step** (X) — интервал времени (обычно 30 секунд).
- **HMAC** — функция хеширования (SHA-1, SHA-256 или SHA-512).

Формула: `TOTP = Truncate(HMAC-SHA(K, T))`, где `T = floor((UnixTime - T0) / X)`.

### HOTP (HMAC-Based One-Time Password)

**HOTP** ([RFC 4226](https://datatracker.ietf.org/doc/html/rfc4226)) — предшественник TOTP, использующий монотонно растущий счётчик (counter) вместо времени. Код меняется только при успешной попытке аутентификации или нажатии кнопки на токене.

## Основные концепции

### Механизм работы TOTP

1. **Инициализация (Provisioning):** Сервер генерирует секретный ключ и передаёт его пользователю (обычно через QR-код с URI `otpauth://`).
2. **Генерация кода:** Клиент вычисляет номер временного интервала на основе системных часов и применяет HMAC к секретному ключу.
3. **Верификация:** Сервер выполняет тот же расчет. Для компенсации рассинхронизации часов обычно используется **Grace Period** (допуск кодов из предыдущего и следующего окна, `T ± 1`).

### Сравнение методов второго фактора

| Метод | Плюсы | Минусы |
| :--- | :--- | :--- |
| **TOTP** (Apps) | Бесплатно, работает оффлайн, стандарт индустрии | Зависимость от времени, риск утери устройства |
| **SMS / Email** | Не требует установки ПО, доступно везде | Уязвимость к SIM-swapping, задержки доставки |
| **Push** | Максимальное удобство (клик вместо ввода кода) | Требует интернет-соединения, проприетарные решения |
| **FIDO2 / WebAuthn** | Защита от фишинга на уровне протокола | Стоимость аппаратных ключей, поддержка в браузере |

## Практические сценарии

### Реализация TOTP на Python

Использование библиотеки `pyotp` для генерации и проверки кодов:

```python
import pyotp
import time

# 1. Генерация секрета (Base32)
secret = pyotp.random_base32()
print(f"Secret: {secret}")

# 2. Создание объекта TOTP
totp = pyotp.TOTP(secret)

# 3. Генерация текущего кода
current_code = totp.now()
print(f"Current OTP: {current_code}")

# 4. Верификация кода
# valid_window=1 позволяет учитывать T-1 и T+1 интервалы
is_valid = totp.verify(current_code)
print(f"Is valid: {is_valid}")
```

### Рекомендации по внедрению

- **Резервные коды:** При включении MFA обязательно генерируйте 5–10 одноразовых кодов восстановления. Храните их хеши в БД.
- **Безопасность секрета:** Секретные ключи должны шифроваться в базе данных (at rest).
- **Rate Limiting:** Обязательно ограничивайте количество попыток ввода OTP (например, блокировка на 15 минут после 5 неудачных попыток) для предотвращения брутфорса.
- **Синхронизация:** Используйте [NTP](../../Linux/Core/systemd/time_synchronization.md) для поддержания точного времени на серверах.

## Дополнительная информация

### Безопасность и уязвимости

- **Защита от фишинга:** TOTP **не защищает** от продвинутого фишинга (Adversary-in-the-Middle), когда злоумышленник перехватывает и пароль, и OTP-код в реальном времени. Для защиты от таких атак рекомендуется использовать **FIDO2/WebAuthn**.
- **Кража устройства:** Если устройство с аутентификатором не защищено паролем/биометрией, злоумышленник получит доступ к кодам.

### Инструменты и библиотеки

- **Приложения:** Google Authenticator, Microsoft Authenticator, Authy (облачный бекап), Aegis (Open Source, Android), Raivo (iOS).
- **Библиотеки:** `pyotp` (Python), `speakeasy` (Node.js), `otpnet` (.NET).
- **Интеграция:** [HashiCorp Vault TOTP engine](../../Vault/concepts.md) позволяет превратить Vault в сервер аутентификации.
