# Kerberos

## Definitions

**Kerberos** — система сетевой аутентификации, разработанная в MIT в 1980-х. Названа в честь трёхглавого пса Цербера по аналогии с тремя компонентами: клиент, сервер, центр распределения ключей.

Основной принцип: **пароли никогда не передаются по сети** — вместо них используются зашифрованные билеты (tickets).

## Basic Concepts

### Ключевые компоненты

| Компонент | Описание |
| :--- | :--- |
| **Client** | пользователь или сервис, запрашивающий доступ |
| **KDC (Key Distribution Center)** | центр распределения ключей; состоит из AS и TGS |
| **AS (Authentication Server)** | проверяет подлинность клиента, выдаёт TGT |
| **TGS (Ticket Granting Server)** | выдаёт сервисные билеты для доступа к службам |
| **SS (Service Server)** | целевой сервис, к которому клиент хочет получить доступ |

### Процесс аутентификации

**Шаг 1 — Получение TGT (Ticket-Granting Ticket):**

1. Client → AS: запрос с идентификатором
2. AS → Client:
   - **TGT** (зашифрован ключом TGS)
   - **Session key** для связи с TGS (зашифрован секретным ключом клиента, производным от пароля)
3. Client расшифровывает session key паролем → получил TGT и ключ сессии

**Шаг 2 — Получение сервисного билета (Service Ticket):**

1. Client → TGS: TGT + идентификатор целевого сервиса + **аутентификатор** (зашифрован session key)
2. TGS расшифровывает TGT, извлекает session key, проверяет аутентификатор
3. TGS → Client:
   - **Сервисный билет** (зашифрован секретным ключом целевого сервиса)
   - Новый **session key** для связи с сервисом

**Шаг 3 — Доступ к сервису:**

1. Client → SS: сервисный билет + аутентификатор (зашифрован новым session key)
2. SS расшифровывает билет своим ключом, проверяет аутентификатор
3. Доступ предоставлен; опционально выполняется **взаимная аутентификация** (сервер подтверждает подлинность клиенту)

## Practical Scenarios

- **Active Directory:** основа аутентификации в доменных сетях Windows
- **FreeIPA:** централизованное управление идентификацией в Linux-средах
- **Hadoop:** защита распределённых кластеров
- **SSH:** аутентификация через GSSAPI
- **NFSv4:** контроль доступа в сетевых файловых системах

## Additional Information

### Технические особенности

| Особенность | Детали |
| :--- | :--- |
| **Шифрование** | Симметричное; современные реализации используют AES (DES устарел) |
| **Время жизни билетов** | Обычно 8-24 часа для снижения риска компрометации |
| **Синхронизация времени** | Требуется точная синхронизация через [NTP](../../Linux/Core/systemd/time_synchronization.md); расхождение приводит к сбою аутентификации |
| **Mutual Authentication** | Клиент и сервер взаимно подтверждают подлинность друг друга |

### Безопасность

- **Уязвимость:** компрометация TGT позволяет злоумышленнику запрашивать сервисные билеты от имени пользователя до истечения срока TGT
- **Митигация:** ограничение времени жизни билетов, мониторинг аномалий, строгий контроль KDC
