# Kerberos — сетевая аутентификация

## Определение

**Kerberos** — протокол сетевой аутентификации, обеспечивающий защищённую передачу данных в ненадёжных сетях с помощью симметричного шифрования и системы билетов (tickets). Разработан в MIT в 1980-х годах. Назван в честь трёхглавого пса Цербера, что символизирует три стороны процесса: клиент, сервер и центр распределения ключей.

Основной принцип: **пароли никогда не передаются по сети** — вместо них используются зашифрованные билеты с ограниченным временем жизни.

## Основные концепции

### Ключевые термины

| Термин | Описание |
| :--- | :--- |
| **Principal** | Уникальный идентификатор пользователя или сервиса в формате `name[/instance]@REALM` |
| **Realm** | Область аутентификации (домен), обычно совпадает с DNS-именем в верхнем регистре (например, `EXAMPLE.COM`) |
| **Ticket** | Зашифрованная структура данных, подтверждающая идентичность владельца для конкретного ресурса |
| **Authenticator** | Временный токен, зашифрованный сессионным ключом, для защиты от атак повторного воспроизведения |

### Компоненты инфраструктуры

| Компонент | Описание |
| :--- | :--- |
| **Client** | Пользователь или служба, запрашивающая доступ |
| **KDC (Key Distribution Center)** | Центр распределения ключей, состоит из AS и TGS |
| **AS (Authentication Server)** | Сервер первичной аутентификации, выдаёт TGT |
| **TGS (Ticket Granting Server)** | Сервер выдачи сервисных билетов |
| **SS (Service Server)** | Целевой сервер, предоставляющий услугу |

### Процесс аутентификации

**1. Получение TGT (Ticket-Granting Ticket):**

- Клиент отправляет запрос к **AS**.
- AS возвращает **TGT** (зашифрован ключом TGS) и **Session Key** (зашифрован секретным ключом клиента на основе пароля).
- Клиент расшифровывает ключ сессии своим паролем.

**2. Получение сервисного билета (Service Ticket):**

- Клиент отправляет к **TGS** свой TGT и аутентификатор.
- TGS проверяет TGT и возвращает **Service Ticket** (зашифрован ключом целевого сервиса) и новый сессионный ключ.

**3. Доступ к сервису:**

- Клиент отправляет сервисный билет и новый аутентификатор к **SS**.
- SS расшифровывает билет своим ключом и предоставляет доступ.
- Опционально: **взаимная аутентификация** (сервер подтверждает свою подлинность клиенту).

## Практические сценарии

- **Active Directory:** Kerberos является стандартом аутентификации в доменах Windows.
- **FreeIPA:** централизованное управление Linux-инфраструктурой (LDAP + Kerberos + DNS).
- **Hadoop:** обеспечение безопасности в распределённых кластерах данных.
- **SSH:** беспарольный вход через механизм GSSAPI.
- **NFSv4:** безопасное монтирование сетевых папок с параметрами `sec=krb5/krb5i/krb5p`.

## Дополнительная информация

### Технические особенности

- **Шифрование:** использует симметричные алгоритмы. Современный стандарт — AES-256 (DES и 3DES считаются небезопасными).
- **Порты:** по умолчанию использует порт `88` (TCP/UDP).
- **Синхронизация времени:** критически важна для работы. Расхождение часов клиента и KDC более чем на 5 минут приводит к ошибкам. Используется [Chrony/NTP](../../Linux/Core/systemd/time_synchronization.md).
- **Реализации:** MIT Kerberos (основная), Heimdal (альтернативная, часто в BSD).

### Безопасность

- **Срок жизни билетов:** обычно составляет 8–24 часа, что минимизирует ущерб при краже билета.
- **Keytab:** файлы, содержащие секретные ключи сервисов, позволяют автоматизировать аутентификацию без ручного ввода пароля.
- **Угрозы:** компрометация KDC (полный контроль над сетью) или кража TGT (позволяет выдавать себя за пользователя до истечения срока билета).
