# Kerberos

## 1. Определения

**Kerberos** — это [система аутентификации](https://web.mit.edu/kerberos/krb5-current/doc/) для ненадёжных сетей, разработанная в MIT в 1980-х годах. Названа в честь трёхглавого пса Цербера из греческой мифологии по аналогии с тремя основными компонентами системы: клиентом, сервером и центром распределения ключей.

## 2. Основные концепции

Основная идея Kerberos заключается в том, чтобы **никогда не передавать пароли по сети в открытом виде**. Вместо этого используются зашифрованные "билеты" (tickets), которые подтверждают личность пользователя.

### Ключевые компоненты

* **Client** — пользователь или сервис, запрашивающий доступ.
* **Key Distribution Center (KDC)** — центр распределения ключей, который обычно состоит из двух логических частей:
  * **AS (Authentication Server)** — сервер аутентификации. Проверяет подлинность клиента и выдает ему билет на получение других билетов (TGT).
  * **TGS (Ticket Granting Server)** — сервер выдачи билетов. Выдает сервисные билеты для доступа к конкретным службам.
* **SS (Service Server)** — целевой сервис, к которому клиент хочет получить доступ.

### Процесс аутентификации

1. **Аутентификация и получение TGT (Ticket-Granting Ticket)**
    * Клиент отправляет запрос на сервер аутентификации (AS), содержащий свой идентификатор.
    * AS проверяет, существует ли такой клиент в базе данных. Если да, он возвращает клиенту два сообщения:
        1. **TGT**, зашифрованный секретным ключом TGS.
        2. **Ключ сессии (session key)** для общения между клиентом и TGS, зашифрованный секретным ключом клиента (производным от его пароля).
    * Клиент расшифровывает ключ сессии своим паролем. Теперь у него есть TGT и ключ сессии для TGS.

2. **Получение сервисного билета (Service Ticket)**
    * Клиент отправляет запрос на сервер выдачи билетов (TGS), содержащий свой TGT, идентификатор целевого сервиса и аутентификатор, зашифрованный ключом сессии.
    * TGS расшифровывает TGT своим ключом, извлекает ключ сессии и им расшифровывает аутентификатор.
    * Если все проверки пройдены, TGS генерирует **сервисный билет**, зашифрованный секретным ключом целевого сервиса, и новый ключ сессии для общения клиента с сервисом. Оба сообщения шифруются ключом сессии TGS и отправляются клиенту.

3. **Доступ к сервису**
    * Клиент отправляет на целевой сервис (SS) сервисный билет и новый аутентификатор, зашифрованный новым ключом сессии.
    * Сервис расшифровывает билет своим секретным ключом, извлекает ключ сессии и им проверяет аутентификатор.
    * Если все верно, сервис предоставляет доступ. Опционально может быть выполнена взаимная аутентификация, когда сервис подтверждает свою подлинность клиенту.

## 3. Практические сценарии

### Где используется

* **Active Directory**: Является основой аутентификации в доменных сетях Windows.
* **Hadoop**: Используется для обеспечения безопасности в распределенных кластерах.
* **SSH**: Аутентификация через GSSAPI (Generic Security Service Application Program Interface).
* **NFSv4**: Защита доступа к файлам в сетевых файловых системах.
* **FreeIPA**: Централизованное управление идентификацией и политиками доступа в Linux-средах.

## 4. Дополнительная информация

### Технические особенности

* **Шифрование**: Использует симметричное шифрование (современные реализации предпочитают AES вместо устаревшего DES).
* **Время жизни билетов**: Билеты имеют ограниченный срок действия (обычно 8-24 часа) для снижения риска их компрометации.
* **Синхронизация времени**: Требует точной синхронизации времени между всеми участниками (клиентами и серверами). Расхождение во времени может привести к сбою аутентификации. Для этого используется протокол [NTP](../../Linux/Core/systemd/time_synchronization.md).
* **Взаимная аутентификация (Mutual Authentication)**: Kerberos поддерживает взаимную аутентификацию, при которой не только клиент подтверждает свою личность серверу, но и сервер — клиенту.

Kerberos — это промышленный стандарт для корпоративных сетей, обеспечивающий надежную аутентификацию без передачи паролей по сети. Несмотря на свою сложность в настройке, он остается одним из самых безопасных протоколов.
