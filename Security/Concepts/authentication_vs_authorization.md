# Authentication vs Authorization

## Definitions

В контексте безопасности **аутентификация** и **авторизация** — два фундаментальных, но различных процесса.

- **Аутентификация (Authentication)** отвечает на вопрос: "**Кто ты?**"
- **Авторизация (Authorization)** отвечает на вопрос: "**Что тебе можно?**"

## Basic Concepts

### Аутентификация

- **Назначение:** подтверждение личности пользователя
- **Механизмы:** учётные данные (логин/пароль), биометрия, токены, X.509-сертификаты
- **Результат:** система идентифицирует пользователя

### Авторизация

- **Назначение:** определение прав доступа аутентифицированного пользователя к ресурсам и действиям
- **Механизмы:** роли ([RBAC](../../Kubernetes/Security/rbac/rbac_overview.md)), списки контроля доступа (ACL), политики, протоколы делегирования ([OAuth 2.0](./oauth2_overview.md))
- **Результат:** разрешение или запрет на доступ к ресурсу/действию

### Сводная таблица

| Характеристика | Аутентификация | Авторизация |
| :--- | :--- | :--- |
| **Вопрос** | Кто ты? | Что тебе можно? |
| **Цель** | Проверка личности | Проверка прав доступа |
| **Порядок** | **До** авторизации | **После** аутентификации |
| **Примеры** | Логин/пароль, отпечаток, Face ID, токен | Роли, группы, права на файлы, политики доступа |

## Practical Scenarios

- **Вход на сайт:** ввод логина и пароля — **аутентификация**; система сверяет данные с БД. Для защиты канала используется [TLS](../../Networking/Protocols/tls.md).
- **Доступ к профилю:** после входа попытка открыть свой профиль — **авторизация**; система проверяет права на конкретный ресурс.
- **SSO в корпоративной среде:** сотрудник единожды проходит аутентификацию через IdP (Keycloak, AD), затем получает доступ к множеству сервисов (Jira, Confluence, GitLab) без повторного ввода пароля — федеративная идентификация.

## Additional Information

### Протоколы комплексной аутентификации и авторизации

- **[Kerberos](./kerberos.md):** система аутентификации для ненадёжных сетей, основа Active Directory
- **[MFA/TOTP](./mfa_totp.md):** многофакторная аутентификация для повышения безопасности

### Федеративная идентификация и SSO

- **Федеративная идентификация:** доверительные отношения между Identity Provider (IdP) и Service Provider (SP) позволяют использовать одну учётную запись в множестве приложений
- **Single Sign-On (SSO):** результат федеративной идентификации — пользователь аутентифицируется один раз и получает доступ ко всем разрешённым ресурсам

### Стандарты и протоколы

- **SAML 2.0:** XML-стандарт обмена данными аутентификации/авторизации между IdP и SP; распространён в корпоративных средах
- **OpenID Connect (OIDC):** протокол идентификации поверх OAuth 2.0; позволяет верифицировать личность пользователя и получать данные профиля; стандарт для веб-приложений
- **OAuth 2.0:** протокол делегирования авторизации; предоставляет ограниченный доступ к ресурсам без передачи учётных данных ([подробнее](./oauth2_overview.md))
