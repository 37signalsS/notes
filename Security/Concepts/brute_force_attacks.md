# Атаки методом перебора (Brute-force)

## Определение

**Brute-force (Метод «грубой силы»)** — метод несанкционированного доступа к защищенным данным (паролям, криптографическим ключам, хешам) путем систематического перебора всех возможных комбинаций символов до нахождения корректного значения.

**Математическая сложность:** определяется формулой `S = N^L`, где `N` — размер алфавита, `L` — длина пароля. Время взлома растет экспоненциально при линейном увеличении длины пароля.

## Основные концепции

### Типы и стратегии атак

| Тип | Технический термин | Описание |
| :--- | :--- | :--- |
| **Полный перебор** | Exhaustive search | Последовательный перебор всех комбинаций алфавита. Гарантирует результат при неограниченном времени. |
| **Словарная атака** | Dictionary attack | Использование баз популярных паролей и данных из прошлых утечек (например, RockYou). |
| **Атака на распыление** | Password Spraying | Перебор одного популярного пароля (например, `Password123`) по большому списку имен пользователей. Позволяет обходить блокировку Account Lockout. |
| **Credential Stuffing** | Перебивка учетных данных | Автоматизированная проверка пар «логин:пароль», полученных из утечек на одном сервисе, против других популярных ресурсов. |
| **Радужные таблицы** | Rainbow Tables | Использование предвычисленных хешей для быстрого обратного поиска пароля. Эффективны только против хешей без «соли». |
| **Атака по времени** | Timing Attack | Анализ микроскопических задержек в ответе системы при сравнении строк для частичного угадывания секретов. |

### Математика стойкости (Энтропия)

Стойкость пароля измеряется в битах энтропии. Для защиты от современных GPU-кластеров в 2026 году рекомендуется уровень не менее **80 бит** для пользовательских паролей и **128 бит** для системных ключей.

## Практические сценарии

### Инструменты анализа защищенности

- **Online-перебор:** [THC Hydra](../Tools/hydra.md) (SSH, HTTP, RDP), Medusa, Nmap (NSE скрипты).
- **Offline-взлом хешей:** [John the Ripper](../Tools/jtr.md) (гибкие правила мутаций), Hashcat (максимальная скорость за счет GPU).
- **Сетевой анализ:** Responder (перехват и перебор NetNTLM хешей в сетях Windows).

### Методы защиты и контрмеры

1.  **Rate Limiting (Ограничение скорости):** блокировка IP-адреса после N неудачных попыток. Инструмент: [fail2ban](../../Linux/Security/Tools/fail2ban.md).
2.  **MFA (Multi-Factor Authentication):** использование [TOTP или FIDO2](./mfa_totp.md). Делает подбор пароля бесполезным без доступа ко второму фактору.
3.  **Account Lockout vs Progressive Delay:** временная блокировка аккаунта или экспоненциальное увеличение задержки между попытками ввода.
4.  **CAPTCHA:** использование интеллектуальных систем (Cloudflare Turnstile, hCaptcha) для отделения ботов от людей.
5.  **Honeypots (Ловушки):** использование SSH-tarpits (например, Endlessh), которые удерживают соединение атакующего бесконечно долго, расходуя его ресурсы.
6.  **WAF (Web Application Firewall):** обнаружение аномальных всплесков запросов к эндпоинтам аутентификации.

## Дополнительная информация

### Безопасное хранение секретов

Для предотвращения офлайн-перебора в случае кражи БД необходимо использовать современные «медленные» хеш-алгоритмы с адаптивной сложностью:
- **Argon2id:** (стандарт RFC 9106) наиболее устойчив к атакам на GPU/ASIC.
- **bcrypt:** классический проверенный вариант на базе Blowfish.
- **Scrypt:** требует большого объема памяти, что затрудняет аппаратное ускорение взлома.

Обязательные параметры хранения:
- **Salt (Соль):** уникальная случайная строка для каждого пользователя (защита от Rainbow Tables).
- **Pepper (Перец):** секретный ключ приложения, добавляемый к хешу, который хранится отдельно от БД.
