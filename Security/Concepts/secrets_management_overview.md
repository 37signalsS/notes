# Управление секретами: Стратегии и инструменты

## 1. Определения

**Управление секретами (Secrets Management)** — это процесс безопасного хранения, контроля доступа, аудита и ротации чувствительных данных (паролей, API-ключей, токенов, сертификатов) в ИТ-инфраструктуре.

## 2. Основные концепции

Ключевая задача — избежать хранения секретов в открытом виде в коде, системах контроля версий (Git) или в конфигурационных файлах без шифрования.

Существуют различные стратегии управления секретами:
- **Централизованные хранилища:** Секреты хранятся в одном защищенном месте (например, Vault).
- **Шифрование в Git (GitOps):** Секреты шифруются и хранятся в Git-репозитории вместе с кодом.
- **Нативные решения платформы:** Использование встроенных средств (например, Kubernetes Secrets).
- **Переменные окружения в CI/CD:** Секреты управляются CI/CD-системой.

## 3. Практические сценарии

Ниже представлены популярные подходы и инструменты.

### 1. HashiCorp Vault
**Лучший вариант для масштабных и зрелых проектов.**
[Vault](../Tools/vault_overview.md) — это полноценное, централизованное решение, которое обеспечивает хранение, аудит, динамическую генерацию и ротацию секретов.

- **Пример использования через CLI:**
  ```bash
  # Записать секрет
  vault kv put secret/db password="SuperSecret123"
  # Прочитать секрет
  vault kv get secret/db
  ```

### 2. Kubernetes Secrets
**Нативный способ для приложений в Kubernetes.**
Ресурсы `Secret` предназначены для хранения чувствительных данных. По умолчанию они хранятся в etcd в base64, поэтому их **необходимо** шифровать с помощью внешних инструментов.

- **Инструменты для шифрования K8s Secrets в Git:**
    - **[Sealed Secrets](../Tools/sealed_secrets_overview.md)**: Шифрует секреты так, что расшифровать их может только контроллер в кластере.
    - **[SOPS](../Tools/sops_overview.md)**: Инструмент от Mozilla для шифрования файлов с использованием KMS, PGP или age.

### 3. SOPS + GitOps
**Подход для хранения зашифрованных секретов непосредственно в Git.**
[SOPS (Secrets OPerationS)](../Tools/sops_overview.md) — это редактор зашифрованных файлов, который позволяет безопасно коммитить их в Git, шифруя только значения, но не ключи.

### 4. Переменные окружения в CI/CD (например, GitLab CI)
Один из самых простых способов. Секреты хранятся в настройках CI/CD системы и передаются в сборочное окружение как переменные окружения.

## 4. Продвинутые детали

### Сравнение подходов

| Критерий | Переменные CI/CD | SOPS | HashiCorp Vault | Kubernetes Secrets (с шифрованием) |
| :--- | :--- | :--- | :--- | :--- |
| **Простота** | Высокая | Средняя | Низкая | Средняя |
| **Безопасность** | Средняя | Высокая | Очень высокая | Высокая |
| **Централизация** | Низкая | Средняя (в рамках репозитория) | Высокая | Средняя (в рамках кластера) |
| **GitOps-совместимость** | Нет | Да | Частично (интеграция) | Да (через Sealed Secrets / SOPS) |
| **Динамические секреты** | Нет | Нет | Да | Нет (только статические) |
| **Аудит** | Ограниченный (в CI/CD) | Да (через Git) | Да (детальный) | Да (через K8s аудит/Git) |

### Вывод
Выбор инструмента зависит от масштаба проекта и требований к безопасности. Для небольших проектов может быть достаточно переменных CI/CD. SOPS является отличным выбором для команд, практикующих GitOps. Vault — это индустриальный стандарт для крупных и сложных систем.
