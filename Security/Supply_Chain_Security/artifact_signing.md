# Подпись артефактов

## Определения

* **Artifact Signing (Подпись артефактов):** Процесс криптографического подтверждения аутентичности (авторства) и целостности программных объектов (образов, бинарных файлов, аттестаций, SBOM, весов ИИ-моделей).
* **Identity-based Signing (Keyless):** Подпись на основе идентичности (через OIDC), исключающая необходимость управления долгоживущими закрытыми ключами.
* **Timestamping (Метка времени):** Подтверждение того, что подпись была создана в период действия сертификата. Критично для долгосрочной валидации (Long-Term Validity, LTV).
* **Transparency Log (Журнал прозрачности):** Публичный, доступный только для добавления (append-only) реестр всех событий подписи, обеспечивающий аудит и обнаружение компрометации (например, Rekor в Sigstore).
* **Post-Quantum Cryptography (PQC) Readiness:** Способность алгоритмов подписи противостоять атакам с использованием квантовых компьютеров. В 2026 году является обязательным требованием для критической инфраструктуры.

## Основные концепции

В 2026 году подпись артефактов перешла от "желательной практики" к "блокирующему требованию" (EU CRA, NIST SSDF).

### Современные модели подписи

| Модель | Технология | Плюсы | Минусы |
| :--- | :--- | :--- | :--- |
| **Identity (Keyless)** | Sigstore / Fulcio | Нет управления ключами, OIDC-интеграция | Зависимость от доступности Log-сервисов |
| **OCI Native** | Notation (Notary v2) | Совместимость с реестрами (X.509), стандарт OCI | Требует PKI/HSM инфраструктуры |
| **Legacy / Git** | GPG / SSH | Универсальность для кода, локальное управление | Риск утечки ключей, сложность ротации |

### Стек технологий (2026)

*   **Sigstore (Cosign):** Де-факто стандарт для облачных сред. Использует эфемерные ключи и прозрачные журналы.
*   **Notation:** Отраслевой стандарт для подписи в реестрах (Azure, AWS, Google Cloud), ориентированный на корпоративные PKI.
*   **TUF (The Update Framework):** Фундаментальный слой защиты от компрометации систем распространения ПО, интегрированный в Sigstore.

## Практические сценарии

### Подпись через Sigstore Cosign (Keyless)

Основной метод для автоматизированных пайплайнов (GitHub, GitLab, Jenkins).

```bash
# 1. Подписание образа (OIDC токен подхватывается автоматически в CI)
cosign sign --yes ghcr.io/my-org/my-app:v1.0.0

# 2. Верификация с проверкой политики (идентичность + провайдер)
cosign verify \
  --certificate-identity "https://github.com/my-org/my-repo/.github/workflows/release.yml@refs/heads/main" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  ghcr.io/my-org/my-app:v1.0.0
```

### Подпись через Notation (OCI-артефакты)

Применяется в корпоративных реестрах с использованием сертификатов из Key Vault / HSM.

```bash
# Добавление доверенного сертификата CA
notation cert add --type ca --store my-corp-ca ./ca.crt

# Подпись образа с использованием ключа из HSM (например, Azure Key Vault)
notation sign --key "my-hsm-key" my-registry.com/my-app:v1.0.0

# Верификация
notation verify my-registry.com/my-app:v1.0.0
```

### Подпись ИИ-моделей (Model Signing)

В 2026 году веса моделей рассматриваются как критические артефакты.

```bash
# Подпись файла модели (.safetensors / .onnx)
cosign sign-blob --key cosign.key --tlog-upload=false ./model.safetensors > model.sig

# Верификация перед загрузкой в Inference Engine
cosign verify-blob --key cosign.key --signature model.sig ./model.safetensors
```

## Дополнительная информация

### Проактивная защита и долгосрочная валидация

*   **Timestamping:** Всегда используйте серверы меток времени (TSA). Это гарантирует, что артефакт будет считаться валидным даже после истечения срока действия сертификата подписи (если на момент подписи он был валиден).
*   **Hardware Security:** Для уровня SLSA 4 обязательно использование **HSM (Hardware Security Module)** или **Cloud KMS** для хранения корневых ключей.
*   **PQC Migration:** Начинайте переход на алгоритмы, устойчивые к квантовым вычислениям (например, **Dilithium** или **Falcon**), поддерживаемые в современных реализациях Sigstore.

### Рекомендации по внедрению

1.  **OCI-First:** Храните подписи как OCI-аттестации рядом с образами.
2.  **Verify on Deploy:** Внедрите `Ratify` или `Kyverno` в кластер для блокировки неподписанных артефактов.
3.  **Audit Logs:** Регулярно проверяйте журналы прозрачности (Rekor) на предмет подозрительных подписей от вашей идентичности.
