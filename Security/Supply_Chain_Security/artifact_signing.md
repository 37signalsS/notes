# Подпись артефактов

## Определения

* **Artifact Signing (Подпись артефактов):** Криптографический процесс обеспечения проверяемой аутентичности (происхождение от доверенного субъекта) и целостности (отсутствие изменений) программных артефактов: контейнерные образы, бинарные файлы, SBOM (Software Bill of Materials — состав программного обеспечения), аттестации, Git-теги.
* **Authenticity (Аутентичность):** Гарантия создания артефакта доверенным источником (разработчик, CI/CD-система).
* **Integrity (Целостность):** Гарантия неизменности артефакта с момента подписания.
* **Keyless Signing (Бесключевая подпись):** Модель подписи с использованием короткоживущих OIDC (OpenID Connect) сертификатов вместо долгоживущих ключей. Запись о подписи публикуется в публичный неизменяемый лог прозрачности.

## Основные концепции

Подпись артефактов — один из столпов безопасности цепочки поставок. Позволяет выстраивать политики допуска, блокируя развёртывание неподписанных или подделанных артефактов.

### Модели подписи

| Модель | Управление ключами | Сценарий применения |
| :--- | :--- | :--- |
| **Keyless (OIDC/Sigstore)** | Короткоживущие сертификаты на основе OIDC-идентичности | CI/CD-пайплайны (рекомендуется) |
| **GPG/PKI** | Долгоживущие ключи, управляемые вручную | Git-теги, файлы, классические системы |

### Инструменты

| Инструмент | Область применения | Модель ключей | Ссылка |
| :--- | :--- | :--- | :--- |
| **Cosign (Sigstore)** | Контейнеры, файлы, аттестации, Helm-чарты | Keyless или ключи | [Sigstore](../Tools/sigstore.md) |
| **Notary v2 / notation** | Контейнерные образы | PKI/сертификаты | — |
| **GPG (GNU Privacy Guard)** | Файлы, Git-теги | Ручные ключи | [GPG](../../Linux/Security/Tools/gpg_and_openpgp.md) |

### Архитектура Sigstore

Sigstore является современным стандартом для автоматизации подписей. Основные компоненты:

* **Fulcio:** Выдаёт короткоживущие сертификаты на основе OIDC.
* **Rekor:** Публичный журнал прозрачности для аудита подписей.
* **Cosign:** Утилита командной строки для работы с артефактами.

Подробное описание инструментов Sigstore приведено в [обзоре Sigstore](../Tools/sigstore.md).

## Практические сценарии

### Подпись контейнерного образа через Cosign (Keyless)

Рекомендуемый метод для CI/CD, не требующий хранения секретных ключей.

```bash
# 1. Подписание образа с использованием OIDC-токена среды выполнения
cosign sign --yes ghcr.io/my-org/my-app:v1.0.0

# 2. Верификация с проверкой OIDC-идентичности (issuer и subject)
cosign verify \
  --certificate-identity-regexp "https://github.com/my-org/my-repo/.github/workflows/release.yml" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  ghcr.io/my-org/my-app:v1.0.0
```

### Подпись релизного Git-тега через GPG

```bash
# Создание подписанного тега
git tag -s v1.0.0 -m "Release v1.0.0"

# Верификация подписи тега
git verify-tag v1.0.0
```

### Настройка политики допуска в Kubernetes (Kyverno)

Политика запрещает запуск образов, не прошедших верификацию подписи.

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-image-signature
spec:
  validationFailureAction: Enforce
  rules:
  - name: verify-cosign
    match:
      any:
      - resources:
          kinds: ["Pod"]
    verifyImages:
    - imageReferences: "ghcr.io/my-org/my-app:*"
      attestors:
      - entries:
        - keyless:
            issuer: "https://token.actions.githubusercontent.com"
            subjectRegExp: "https://github.com/my-org/my-repo/.github/workflows/release.yml@refs/heads/main"
```

## Дополнительная информация

### Рекомендации

* **Предпочитайте Keyless для CI/CD:** Это исключает риски утечки долгоживущих ключей и упрощает ротацию.
* **Подписывайте все артефакты:** Не только образы, но и SBOM-отчёты, аттестации и Helm-чарты.
* **Верифицируйте на каждом этапе:** Проверка должна происходить как в пайплайне перед релизом, так и в кластере перед запуском.
* **Используйте дайджесты:** Фиксируйте образы по неизменяемому хешу (`image@sha256:...`) вместе с проверкой подписи.
