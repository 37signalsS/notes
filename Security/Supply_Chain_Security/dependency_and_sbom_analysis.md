# Анализ зависимостей и SBOM

## Определения

* **SCA (Software Composition Analysis — анализ состава ПО):** Автоматизированный процесс идентификации сторонних компонентов (open-source библиотек, коммерческих модулей) и оценки связанных с ними рисков безопасности, лицензионной чистоты и качества.
* **SBOM (Software Bill of Materials — состав программного обеспечения):** Машиночитаемый инвентарный перечень всех компонентов программного продукта. В 2026 году SBOM рассматривается как динамический граф (Living SBOM), а не статический файл.
* **VEX (Vulnerability Exploitability eXchange):** Сопроводительный документ к SBOM, в котором производитель ПО указывает статус уязвимостей (например, "не влияет", "исправлено", "в процессе анализа"), что позволяет фильтровать ложные срабатывания (FP).
* **AI-BOM / ML-BOM:** Специализированный профиль SBOM для ИИ-систем, включающий данные об обучающих выборках (datasets), архитектуре моделей, весах и гиперпараметрах.
* **CBOM (Cryptographic BOM):** Перечень всех используемых криптографических алгоритмов, ключей и библиотек. Критичен для перехода на **Post-Quantum Cryptography (PQC)**.

## Основные концепции

В 2026 году анализ зависимостей стал обязательным этапом в соответствии с **EU Cyber Resilience Act (CRA)**. Основной фокус сместился с простого обнаружения уязвимостей на управление их эксплуатируемостью.

### Сравнение форматов SBOM (2026)

| Формат | Текущая версия | Ключевые особенности | Сфера применения |
| :--- | :--- | :--- | :--- |
| **SPDX** | 3.0+ | Модульная архитектура, профили (Security, AI, Build), JSON-LD (Linked Data). | Юридический комплаенс, AI/ML, сложные графы. |
| **CycloneDX** | 1.6/1.7 | Встроенная поддержка VEX, CBOM, аттестаций соответствия (CDXA). | DevSecOps, автоматизация безопасности, PQC. |

### Концепция "Living SBOM"

Современный SBOM — это не результат разового сканирования, а непрерывно обновляемый поток данных:
1.  **Build Phase:** Генерация базового SBOM во время сборки.
2.  **Enrichment:** Добавление данных VEX и аттестаций SLSA.
3.  **Runtime:** Сопоставление SBOM с реально загруженными в память библиотеками (Runtime SBOM).
4.  **Observability:** Агрегация всех SBOM организации в графовые системы типа **GUAC**.

### Категории инструментов SCA

*   **Сканеры (Scanners):** `Trivy`, `Grype`, `osv-scanner`.
*   **Генераторы (Generators):** `Syft`, `cdxgen`, `CycloneDX CLI`.
*   **Платформы управления (ASOC/SBOM):** `Dependency-Track`, `Harbor` (v2.10+), `Snyk`.
*   **Наблюдаемость (Observability):** `GUAC` (Graph for Understanding Artifact Composition).

## Практические сценарии

### Генерация и фильтрация через VEX (Trivy)

Использование VEX позволяет игнорировать уязвимости, которые присутствуют в коде библиотеки, но не могут быть эксплуатированы в вашем приложении.

```bash
# Генерация SBOM в формате CycloneDX
trivy fs --format cyclonedx --output sbom.json .

# Сканирование SBOM с применением VEX-отчета для фильтрации шума
trivy sbom --vex vex-report.json sbom.json
```

### Инвентаризация криптографии (CBOM через CycloneDX)

Подготовка к переходу на квантово-устойчивые алгоритмы требует понимания текущего ландшафта.

```bash
# Генерация CBOM для проекта на Java (пример через cdxgen)
cdxgen -t java --output-format json --output cbom.json
# Анализ выявит использование устаревших алгоритмов типа RSA-1024 или SHA-1
```

### Безопасная установка зависимостей в CI/CD

**Золотое правило:** В CI/CD-пайплайне никогда не используйте команды, разрешающие диапазоны версий (типа `npm install` или `pip install`). Используйте только детерминированные методы.

| Язык | Команда | Файл фиксации | Примечание |
| :--- | :--- | :--- | :--- |
| **Node.js** | `npm ci` | `package-lock.json` | Удаляет `node_modules` перед установкой. |
| **Python** | `pip install --require-hashes -r requirements.txt` | `requirements.txt` | Требует хеши для каждого пакета. |
| **Go** | `go mod download` | `go.sum` | Проверяет хеши через checksum database. |
| **Rust** | `cargo fetch --locked` | `Cargo.lock` | Гарантирует идентичность сборки. |

### Автоматическое управление обновлениями (Renovate)

Renovate является более гибким аналогом Dependabot, поддерживающим VEX и группировку обновлений.

```json
{
  "extends": ["config:base"],
  "packageRules": [
    {
      "matchUpdateTypes": ["minor", "patch"],
      "groupName": "all non-major dependencies",
      "automerge": true
    }
  ],
  "vulnerabilityAlerts": {
    "enabled": true
  }
}
```

## Дополнительная информация

### Рекомендации по обеспечению безопасности зависимостей

1.  **Pinning by Digest:** В Docker-файлах фиксируйте базовые образы по дайджесту (`FROM alpine@sha256:...`), а не по тегам.
2.  **Private Proxy:** Используйте приватные реестры (Harbor, Nexus, Artifactory) в качестве кэширующих прокси для предотвращения атак типа **Dependency Confusion**.
3.  **VEX-First:** Требуйте от поставщиков ПО (ISV) предоставления VEX-файлов вместе с SBOM для снижения нагрузки на команду безопасности.
4.  **License Compliance:** Настройте блокировку сборки при обнаружении зависимостей с "вирусными" лицензиями (GPL v3), если это противоречит политике компании.
