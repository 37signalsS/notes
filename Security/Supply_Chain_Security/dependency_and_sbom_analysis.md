# Анализ зависимостей и SBOM

## Определения

**Анализ состава программного обеспечения (Software Composition Analysis, SCA)** — это процесс автоматического сканирования зависимостей проекта для выявления известных уязвимостей, конфликтов лицензий и проблем с качеством.

**Спецификация программного обеспечения (Software Bill of Materials, SBOM)** — это структурированный, машиночитаемый список всех компонентов, библиотек и модулей, которые требуются для сборки и запуска программного обеспечения. Это "инвентарный список" вашего ПО в форматах, таких как CycloneDX или SPDX.

## Основные концепции

Отслеживание зависимостей — ключевая часть [безопасности цепочки поставок](./overview.md), поскольку большинство уязвимостей попадает в продукт через сторонние библиотеки.

### Категории инструментов
*   **Аудиторы экосистем:** Встроенные в менеджеры пакетов (`npm audit`, `cargo audit`).
*   **Универсальные SCA-сканеры:** Анализируют код и образы (`Trivy`, `Grype`, `osv-scanner`).
*   **SBOM-генераторы:** Создают список компонентов (`Syft`, `CycloneDX CLI`).
*   **Боты обновлений:** Автоматизируют создание PR для обновления зависимостей (`Dependabot`, `Renovate`).

### Роль Lock-файлов
Lock-файлы (`package-lock.json`, `yarn.lock`, `go.sum`, `Cargo.lock`) являются основой для SCA, так как они фиксируют точные версии и хэши зависимостей, делая сборку воспроизводимой и сканируемой.

### Базы уязвимостей
SCA-инструменты сопоставляют найденные компоненты с базами данных уязвимостей, такими как **NVD (National Vulnerability Database)** и **OSV (Open Source Vulnerability format)**.

## Практические сценарии

### Аудит зависимостей в коде
```bash
# JavaScript/Node.js
npm audit --production

# Python
pip-audit -r requirements.txt

# Go
govulncheck ./...

# Rust
cargo audit
```

### Сканирование и генерация SBOM для контейнерного образа
```bash
# 1. Сгенерировать SBOM из образа в формате CycloneDX
syft my-image:latest -o cyclonedx-json > sbom.json

# 2. Просканировать SBOM на уязвимости с высоким и критическим уровнем
grype sbom:sbom.json --fail-on high

# Альтернатива: Trivy сканирует образ напрямую
trivy image --ignore-unfixed --severity HIGH,CRITICAL my-image:latest
```

### Интеграция в CI/CD (GitLab CI)
```yaml
sca-job:
  image: alpine:3.19
  script:
    - apk add --no-cache curl
    - curl -sSfL https://raw.githubusercontent.com/anchore/grype/main/install.sh | sh -s -- -b /usr/local/bin
    # Сканируем файловую систему на уязвимости и лицензии
    - grype . --fail-on high --only-fixed
  cache:
    paths:
      - .grype/db
```

## Дополнительная информация

### Рекомендации по внедрению
*   **Инвентаризация:** Регулярно генерируйте SBOM для всех ключевых артефактов и храните их вместе со сборками.
*   **Политики:** Определите пороги срабатывания (например, блокировать сборку при наличии критических уязвимостей) и управляйте исключениями.
*   **Автоматизация:** Внедрите сканирование в CI/CD на ранних этапах и используйте ботов (Dependabot/Renovate) для автоматического обновления зависимостей.
*   **Сквозное покрытие:** Сканируйте не только исходный код, но и готовые артефакты, включая контейнерные образы в реестре.
