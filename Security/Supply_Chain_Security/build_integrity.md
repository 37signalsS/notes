# Контроль целостности на этапах сборки

## Определения

* **Воспроизводимая сборка (Reproducible Build):** Процесс, при котором из одинаковых входных данных (исходный код, версии зависимостей, инструменты) всегда получается бит-в-бит идентичный артефакт.
* **Герметичная сборка (Hermetic Build):** Сборка, выполняемая в изолированной среде без неконтролируемого доступа к сети. Все зависимости должны быть заранее загружены и верифицированы.
* **Аттестация (Provenance):** Проверяемые метаданные о процессе сборки, отвечающие на вопросы: кто, что, когда и из чего собрал. Является частью стандарта [SLSA](./overview.md).

## Основные концепции

Контроль целостности гарантирует, что артефакт, который вы разворачиваете, соответствует исходному коду, прошел все проверки и не был подменен. Это ключевой элемент [безопасности цепочки поставок](./overview.md).

### Ключевые подходы

| Подход           | Цель                               | Преимущества                    |
| ---------------- | ---------------------------------- | ------------------------------- |
| **Хеш-суммы**    | Проверка неизменности файла        | Простота и универсальность      |
| **Подписи**      | Подтверждение автора и целостности | Криптографическая неотказуемость |
| **Аттестации**   | Доказуемое происхождение сборки    | Полная трассируемость           |
| **Воспроизводимость**| Выявление недетерминизма и подмен  | Высокая степень доверия         |

## Практические сценарии

### Фиксация версий и хешей

Закрепляйте версии зависимостей и базовых образов с помощью хешей (дайджестов), чтобы избежать неожиданных обновлений.

```dockerfile
# Закрепление базового образа по дайджесту
FROM python@sha256:1f2a3b...c9d
```

```bash
# Проверка хеша загруженной зависимости
expected_sha="3b7c..."; file="lib.tar.gz"
actual_sha=$(sha256sum "$file" | awk '{print $1}')
if [ "$expected_sha" != "$actual_sha" ]; then
  echo "Checksum mismatch!"
  exit 1
fi
```

### Обеспечение детерминизма сборки

Устраняйте источники изменчивости (время, случайные числа, различия в файловых системах), чтобы сделать сборки воспроизводимыми.

```bash
# Пример для компиляции Go
export CGO_ENABLED=0
export SOURCE_DATE_EPOCH=$(date +%s)
go build -trimpath -buildvcs=false -ldflags="-w -s" .
```

### Герметизация сборочной среды

Ограничивайте сетевой доступ во время сборки, чтобы предотвратить загрузку неконтролируемых зависимостей.

```bash
# Пример запрета исходящих соединений в Docker-сборке
RUN --network=none pip install --no-index --find-links=./wheels -r requirements.txt
```

### Подпись и проверка артефактов

Подписывайте артефакты, чтобы гарантировать их происхождение.

```bash
# Подпись образа по дайджесту с помощью Cosign
cosign sign my-registry/app@sha256:ab12...

# Проверка подписи и дайджеста в CI перед развертыванием
cosign verify my-registry/app@sha256:ab12...
```

## Дополнительная информация

### Рекомендации

* **Исходный код:** Используйте подписанные Git-теги для релизов.
* **Зависимости:** Фиксируйте версии и хеши в lock-файлах (`package-lock.json`, `go.sum`).
* **Сборка:** Используйте герметичные и воспроизводимые сборки, где это возможно. Создавайте и подписывайте аттестации (provenance).
* **Артефакты:** Храните подписи и SBOM рядом с артефактами.
* **Развертывание:** Проверяйте подписи перед развертыванием с помощью политик допуска (например, в Kyverno).
