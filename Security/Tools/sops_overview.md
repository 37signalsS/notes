# SOPS (Secrets OPerationS) — обзор и руководство

**Актуально для:** Mozilla SOPS v3.13.3

## Определения

- **SOPS (Secrets OPerationS)** — инструмент с открытым исходным кодом для управления секретами, изначально разработанный Mozilla. Представляет собой редактор зашифрованных файлов, который позволяет безопасно хранить структурированные данные (YAML, JSON, `.env`, INI, BINARY) в системах контроля версий, таких как Git. Проект передан в CNCF.
- **Конвертная криптография (Envelope Encryption)** — модель шифрования, при которой данные шифруются симметричным ключом данных (DEK), а сам DEK шифруется одним или несколькими мастер-ключами (KEK). Позволяет ротацию мастер-ключей без перешифрования данных.
- **Ключ данных (DEK — Data Encryption Key)** — случайный 256-битный симметричный ключ (AES-256-GCM или ChaCha20-Poly1305), которым непосредственно зашифрованы значения в файле.
- **Мастер-ключ (KEK — Key Encryption Key)** — ключ, используемый для шифрования DEK. Может быть age-ключом, PGP-ключом или ключом из HashiCorp Vault.
- **age (Actually Good Encryption)** — современный инструмент и формат асимметричного шифрования (ключи X25519), используемый как компактная, надёжная и быстрая альтернатива PGP для SOPS.
- **PGP / GPG** — классическая реализация OpenPGP. Подходит для подписей Git и шифрования файлов, но менее удобна в управлении ключами по сравнению с `age`.
- **Мульти-рецепиентное шифрование (Multi-recipient)** — возможность SOPS шифровать один файл для нескольких получателей одновременно. Каждый получатель может расшифровать файл с помощью своего мастер-ключа.
- **MAC (Message Authentication Code)** — HMAC, вычисляемый SOPS для обнаружения несанкционированных изменений зашифрованного файла вне SOPS. Если файл был повреждён или изменён вручную, расшифровка завершится ошибкой.
- **`.sops.yaml`** — файл конфигурации, позволяющий автоматизировать выбор мастер-ключей на основе пути к файлу. Должен находиться в корне репозитория.
- **Секция `sops`** — метаданные внутри зашифрованного файла, содержащие информацию о мастер-ключах (получателях), алгоритме шифрования и MAC.

## Основные концепции

### Модель шифрования

Ключевая особенность SOPS — использование **конвертной модели шифрования (envelope encryption)**:

1. Для каждого файла генерируется уникальный 256-битный симметричный **ключ данных (DEK)**.
2. Данные шифруются этим DEK с использованием алгоритма AES-GCM (или ChaCha20-Poly13ь5).
3. Сам DEK шифруется одним или несколькими **мастер-ключами**.
4. Зашифрованный DEK и метаданные (информация о мастер-ключах) хранятся в секции `sops` внутри самого файла.

Эта модель позволяет:
- **Ротацию мастер-ключей без перешифрования данных** — `sops updatekeys` создаёт новый DEK и перешифровывает его новыми KEK, не меняя сами значения.
- **Полное перешифрование данных** — `sops rotate` генерирует новый DEK и перешифровывает все значения в файле.

### Мастер-ключи

В качестве мастер-ключей могут выступать:

- **age:** современный, простой и быстрый способ шифрования. Рекомендуется для локальной разработки и командной работы.
- **PGP / GPG:** традиционный метод, постепенно вытесняемый `age` из-за сложности управления ключевыми парами.
- **HashiCorp Vault (Transit Engine):** централизованное управление ключами с аудитом и ротацией. Подходит для on-premise инфраструктур.

### Поддерживаемые форматы

SOPS шифрует **только значения** (values), оставляя **ключи** (keys) в открытом виде. Это сохраняет читаемость структуры файлов и позволяет использовать стандартные инструменты сравнения (`git diff`) без риска утечки данных.

| Формат | Расширения | Описание |
|--------|-----------|----------|
| YAML | `.yaml`, `.yml` | Используется для Kubernetes-манифестов, конфигураций |
| JSON | `.json` | Структурированные конфигурации |
| ENV | `.env` | Переменные окружения |
| INI | `.ini` | Конфигурационные файлы в формате INI |
| BINARY | `.bin` | Двоичные файлы (без парсинга структуры) |

## Установка и настройка

### Установка

```bash
# Загрузка бинарного файла (Linux amd64)
curl -LO https://github.com/getsops/sops/releases/download/v3.13.3/sops-v3.13.3.linux.amd64
sudo install sops-v3.13.3.linux.amd64 /usr/local/bin/sops
chmod +x /usr/local/bin/sops

# Проверка версии
sops --version
# → sops version v3.13.3
```

Для macOS через Homebrew:

```bash
brew install sops
```

### Настройка age-ключа

```bash
# Создание директории конфигурации
mkdir -p ~/.config/sops/age

# Генерация ключевой пары (приватный ключ защищается правами 0600)
age-keygen -o ~/.config/sops/age/keys.txt
# → # created: 2026-10-18T10:00:00Z
# → # public key: age15k3fuv983z5r77l04r432k428j7y6tqq77p4088x33e50w2c59esf5afl6
# → PUBLIC KEY: AgB3...

chmod 0600 ~/.config/sops/age/keys.txt
```

## Практические сценарии

### Шифрование файла

```bash
# Зашифровать YAML с использованием age-ключа из ~/.config/sops/age/keys.txt
sops --encrypt --age age1... secrets.yaml > secrets.enc.yaml

# Зашифровать на месте (перезаписать исходный файл)
sops --encrypt --age age1... --in-place secrets.yaml
```

### Расшифровка файла

Для расшифровки не требуется указывать ключи вручную — SOPS считывает метаданные из секции `sops`:

```bash
sops --decrypt secrets.enc.yaml > secrets.yaml
```

### Редактирование зашифрованного файла «на лету»

SOPS расшифровывает файл во временную директорию (обычно в `/dev/shm` или `tmpfs` для безопасности) и открывает его в `$EDITOR`. После сохранения файл автоматически зашифровывается обратно:

```bash
sops secrets.enc.yaml
```

### Запуск команд с секретами (`exec-env` и `exec-file`)

**`exec-env`** расшифровывает файл и передаёт его содержимое как переменные окружения дочернему процессу. Это предотвращает запись расшифрованных секретов на диск:

```bash
sops exec-env secrets.enc.yaml 'my-command --with-args'
```

**`exec-file`** создаёт временный файл с расшифрованным содержимым и передаёт путь к нему в команду:

```bash
# Временный файл создаётся в безопасном временном каталоге и удаляется после выполнения
sops exec-file secrets.enc.yaml 'my-command --config {}'
```

### Точечное редактирование значений (`--set`)

Позволяет изменить одно вложенное значение без открытия редактора. Удобно для скриптовой ротации секретов:

```bash
# Изменить значение db.password
sops --set '["db"]["password"] "new-secret-value"' secrets.enc.yaml

# Комбинирование с -e/-i для шифрования на месте
SOPS_AGE_RECIPIENTS=age1<id> sops -e -i --set '["api"]["key"] "new-key"' secrets.yaml
```

Синтаксис пути — JSON-подобный массив ключей. Значение указывается после пути в кавычках. Файл перешифровывается на месте.

### Конвертация форматов

SOPS позволяет на лету менять формат представления данных:

```bash
# Зашифровать YAML и сохранить как JSON
sops --encrypt --input-type yaml --output-type json secrets.yaml > secrets.json

# Расшифровать JSON и вывести как YAML
sops --decrypt --input-type json --output-type yaml secrets.json > secrets.yaml

# Преобразовать зашифрованный YAML в формат .env (без шифрования результата)
sops --decrypt --input-type yaml --output-type dotenv secrets.enc.yaml > secrets.env
```

### Автоматизация выбора ключей: `.sops.yaml`

Файл конфигурации позволяет автоматизировать выбор мастер-ключей на основе пути к файлу. Должен находиться в корне репозитория:

```yaml
# .sops.yaml
creation_rules:
  # Для prod-файлов — age-ключ и резервный age-ключ
  - path_regex: prod/.*\.yaml$
    age: >-
      age15k3fuv983z5r77l04r432k428j7y6tqq77p4088x33e50w2c59esf5afl6,
      age1backupdr983z5r77l04r432k428j7y6tqq77p4088x33e50w2c59esdrkey0

  # Для dev-файлов — только age
  - path_regex: dev/.*\.yaml$
    age: age1devkey983z5r77l04r432k428j7y6tqq77p4088x33e50w2c59esdevkey1

  # Для всех остальных .env файлов — PGP
  - path_regex: \.env$
    pgp: "YOUR_PGP_FINGERPRINT"
```

После настройки `.sops.yaml` шифрование достаточно вызвать без указания ключа:

```bash
sops --encrypt --in-place secrets.yaml
```

SOPS прочитает конфигурацию и выберет нужный age/PGP-ключ на основе пути к файлу.

### Мульти-рецепиентное шифрование (Multi-recipient)

SOPS поддерживает шифрование для нескольких получателей одновременно. Это позволяет команде использовать разные ключи (например, личные `age`-ключи участников) для доступа к одному и тому же файлу без передачи общих секретов:

```bash
# Зашифровать файл для трёх получателей: два age-ключа и один PGP-ключ
sops --encrypt \
  --age age1user1... \
  --age age1user2... \
  --pgp YOUR_PGP_FINGERPRINT \
  secrets.yaml > secrets.enc.yaml
```

Люб из трёх получателей может расшифровать файл, имея соответствующий мастер-ключ.

## Операции и команды

| Категория | Команда | Назначение |
|-----------|---------|------------|
| **Шифрование** | `sops --encrypt --age age1... file.yaml > file.enc.yaml` | Зашифровать файл с указанием получателя |
| **Шифрование (на месте)** | `sops --encrypt --in-place file.yaml` | Зашифровать, используя правила из `.sops.yaml` |
| **Расшифровка** | `sops --decrypt file.enc.yaml` | Расшифровать и вывести в stdout |
| **Редактирование** | `sops file.enc.yaml` | Открыть в `$EDITOR`, автоматически зашифровать после сохранения |
| **Точечное изменение** | `sops --set '["db"]["password"] "new-value"' file.enc.yaml` | Изменить одно значение без редактора |
| **Перешифровка KEK** | `sops updatekeys -y file.enc.yaml` | Обновить метаданные получателей из `.sops.yaml` без перешифрования значений |
| **Ротация DEK** | `sops rotate -i --add-age age1new... file.enc.yaml` | Сгенерировать новый DEK и перешифровать все значения |
| **exec-env** | `sops exec-env secrets.enc.yaml 'cmd'` | Передать секреты как env-переменные дочернему процессу |
| **exec-file** | `sops exec-file secrets.enc.yaml 'cmd --conf {}'` | Передать секреты как временный файл |
| **Проверка MAC** | `sops --decrypt --mac-only secrets.enc.yaml` | Проверить целостность без вывода расшифрованного текста |
| **Конвертация форматов** | `sops --encrypt --input-type yaml --output-type json file.yaml` | Сменить формат представления данных |

### Массовое обновление файлов при ротации ключей

При увольнении сотрудника или выводе из эксплуатции скомпрометированного age-ключа системный администратор обновляет `.sops.yaml` и выполняет массовое обновление файлов:

```bash
# Массовое обновление метаданных получателей во всех зашифрованных файлах
find clusters/ -type f -name "*.enc.yaml" -exec sops updatekeys -y {} \;
# → [INFO] File clusters/prod/database-secret.enc.yaml updated successfully.
# → [INFO] File clusters/dev/api-secret.enc.yaml updated successfully.

# Проверка изменённых файлов перед коммитом
git status --short
# →  M clusters/prod/database-secret.enc.yaml
# →  M clusters/dev/api-secret.enc.yaml
```

## Устранение неполадок

| Симптом | Причина | Диагностика | Решение |
|--------|---------|-------------|---------|
| `sops: no key found` | Отсутствует мастер-ключ (age или PGP) в окружении или в `.sops.yaml` | `sops --encrypt file.yaml` | Указать `SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt` или `--age` флаг |
| `MAC mismatch / error decrypting MAC` | Нарушена целостность файла (повреждение при ручном merge-конфликте в Git) | `sops -d file.enc.yaml` завершается ошибкой MAC | 1. Восстановить из коммита до слияния.<br>2. Разрешить конфликт в открытом тексте и зашифровать заново.<br>3. Аварийный просмотр: `sops -d --ignore-mac file.enc.yaml` |
| `could not find a valid recipient` | Мастер-ключ в метаданных файла не соответствует доступным ключам | `sops -d file.enc.yaml` с `--verbose` | Проверить, что получатель в секции `sops` совпадает с доступным age/PGP-ключом |
| `exec-env: command not found` | Аргумент-команда не передан или содержит специальные символы | `sops exec-env file 'echo $VAR'` | Экранировать кавычки и специальные символы; использовать одинарные кавычки для обёртки команды |
| `sops rotate: file does not exist` | Команда `rotate` не может добавить/удалить ключи для несуществующего файла | `sops rotate -i --add-age age1... file.yaml` | Создать файл и зашифровать его через `sops --encrypt --in-place file.yaml`, затем применить `rotate` |
| `sops: input type could not be determined` | SOPS не может определить формат файла по расширению | `sops --encrypt file.bin` | Явно указать тип: `--input-type binary --output-type binary` |
| `--set: invalid path` | Синтаксис JSON-пути указан неверно | `sops --set '[wrong' file.enc.yaml` | Использовать корректный JSON-путь: `["db"]["password"] "value"` |

## Лучшие практики

1. **Предпочитайте `age` PGP** — `age` проще в управлении, быстрее и использует современную криптографию (X25519). PGP оставляйте только для обратной совместимости с существующей инфраструктурой.
2. **Автоматизируйте выбор ключей через `.sops.yaml`** — исключает ошибки ручного выбора получателя и обеспечивает единообразие внутри репозитория.
3. **Не редактируйте зашифрованные файлы вручную** — любые изменения в base64-блоках могут нарушить MAC-проверку. Используйте `sops edit` или `sops --set`.
4. **Регулярная ротация DEK** — используйте `sops rotate` для периодической смены ключа данных. Рекомендуемый интервал — 90–180 дней для production-файлов.
5. **Ротация мастер-ключей без перешифрования данных** — `sops updatekeys -y` добавляет новых получателей и удаляет бывших, не меняя DEK. Используйте при увольнении сотрудников.
6. **Резервное копирование age-ключей** — файл `~/.config/sops/age/keys.txt` никогда не должен теряться. Храните резервную копию в безопасном офлайн-хранилище (зашифрованный USB-носитель, HSM).
7. **Проверка целостности** — перед выкладыванием зашифрованного файла в CI используйте `sops --decrypt --mac-only` для проверки MAC без вывода расшифрованного текста.
8. **Ограничение доступа в Git** — используйте pre-commit хуки (`gitleaks`, `detect-secrets`) для предотвращения случайного коммита открытых секретов.

## Очистка и ротация

### Ротация DEK (`rotate`)

Команда `sops rotate` генерирует новый ключ данных (DEK) и перешифровывает все значения в файле. Это полное перешифрование — используется при подозрении на компрометацию или по расписанию:

```bash
# Перешифровать файл с новым DEK и добавить новый age-ключ получателя
sops rotate -i --add-age age1new_recipient... secrets.enc.yaml
# → [INFO] File secrets.enc.yaml updated successfully.
```

Флаги `--add-age` и `--rm-age` позволяют одновременно с ротацией DEK изменить набор получателей.

### Обновление мастер-ключей (`updatekeys`)

В отличие от `rotate`, команда `sops updatekeys` не генерирует новый DEK. Она только обновляет метаданные получателей в секции `sops` согласно правилам из `.sops.yaml`:

```bash
# Добавить нового получателя и удалить уволенного
sops updatekeys -y secrets.enc.yaml
# → [INFO] File secrets.enc.yaml updated successfully.
```

Эта операция **не перешифровывает значения** — используется, когда нужно сменить доступ без изменения данных.

### Аварийная проверка MAC

Если расшифровка завершается ошибкой MAC, можно выполнить аварийный просмотр только для чтения:

```bash
sops --decrypt --ignore-mac secrets.enc.yaml
```

> **Внимание:** `--ignore-mac` отключает проверку целостности. Используйте только для восстановления данных, если остальной вариант недоступен.
