# Sealed Secrets

## 1. Определения

**Sealed Secrets** — это инструмент для Kubernetes от Bitnami, предназначенный для безопасного хранения секретов (паролей, токенов, ключей) в публичных Git-репозиториях. Он решает проблему хранения стандартных `Secrets` Kubernetes, которые по умолчанию закодированы в `base64`, но не зашифрованы.

## 2. Основные концепции

Sealed Secrets использует **асимметричное шифрование** (public-key cryptography).

1.  **Контроллер в кластере**: В кластере Kubernetes разворачивается контроллер Sealed Secrets. При первом запуске он генерирует пару ключей: приватный и публичный.
2.  **Приватный ключ**: Хранится только внутри кластера в `etcd` и недоступен извне.
3.  **Публичный ключ**: Используется для шифрования секретов. Его можно безопасно выгрузить и передать разработчикам.
4.  **Шифрование**: Разработчик создает обычный `Secret` в формате YAML, а затем использует утилиту `kubeseal` и публичный ключ для его шифрования. Результатом является новый объект Kubernetes — `SealedSecret`.
5.  **Дешифрование**: Зашифрованный `SealedSecret` можно безопасно хранить в Git. Когда он применяется в кластере, контроллер Sealed Secrets обнаруживает его, расшифровывает с помощью своего приватного ключа и создает на его основе обычный `Secret`, который уже могут использовать поды.

## 3. Практические сценарии

### Установка
Контроллер устанавливается в кластер, например, с помощью Helm.
```bash
helm repo add sealed-secrets https://bitnami-labs.github.io/sealed-secrets
helm install sealed-secrets/sealed-secrets --name-template sealed-secrets -n kube-system
```

### Шифрование секрета
1.  **Создать обычный секрет в YAML:**
    ```yaml
    # my-secret.yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: mysecret
      namespace: default
    data:
      password: "SuperSecretPassword" # Перед шифрованием кодируется в base64
    ```

2.  **Зашифровать с помощью `kubeseal`:**
    Утилита `kubeseal` "запечатывает" секрет, превращая его в `SealedSecret`.
    ```bash
    # Установить kubeseal (macOS)
    brew install kubeseal

    # Зашифровать файл, результат направить в stdout
    kubeseal < my-secret.yaml --format yaml

    # Зашифровать и сохранить в файл
    kubeseal < my-secret.yaml --format yaml > my-sealed-secret.yaml
    ```
    Полученный `my-sealed-secret.yaml` можно безопасно коммитить в Git.

## 4. Продвинутые детали

### Ротация ключей
Приватный ключ контроллера по умолчанию не имеет срока действия. Однако его можно и нужно периодически ротировать для повышения безопасности. Новая пара ключей может быть сгенерирована контроллером, и в течение некоторого времени он будет способен расшифровывать секреты, зашифрованные как старым, так и новым публичным ключом.

### Область действия (Scope)
По умолчанию `SealedSecret` может быть расшифрован только в том же `namespace`, в котором он был создан. Это предотвращает случайное или намеренное использование секрета в другом пространстве имен. Область действия можно изменить с помощью аннотаций:
- `sealedsecrets.bitnami.com/namespace-wide: "true"`: Секрет будет доступен в любом `namespace`.
- `sealedsecrets.bitnami.com/cluster-wide: "true"`: Секрет будет доступен во всем кластере.
