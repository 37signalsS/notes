# John the Ripper (JtR): Аудит паролей

## Определение

**John the Ripper (JtR)** — кроссплатформенный инструмент с открытым исходным кодом для офлайн-аудита безопасности и восстановления паролей. Он предназначен для обнаружения слабых паролей путём перебора хешей, извлечённых из операционных систем (например, `/etc/shadow`), дампов баз данных, зашифрованных архивов и ключей.

JtR отличается высокой адаптивностью, автоматическим определением типов хешей и мощным движком правил для модификации словарей.

## Базовые концепции

Процесс работы JtR строится на сравнении хеша кандидата в пароли с целевым хешем. Если они совпадают, пароль считается взломанным.

### Режимы атак

1.  **Wordlist mode (Словарная атака):** Самый быстрый метод. Инструмент проверяет слова из указанного файла-словаря.
2.  **Single crack mode:** Режим «умного» подбора. JtR использует метаданные пользователя (имя, логин, домашний каталог) для генерации вероятных паролей. Очень эффективен на начальном этапе.
3.  **Incremental mode (Полный перебор):** Классический [брутфорс](../Concepts/brute_force_attacks.md). Перебирает все возможные комбинации символов. Для оптимизации используются статистические данные о частоте появления символов (цепи Маркова).
4.  **Mask mode (Масочная атака):** Перебор по заданному шаблону (например, «слово + 2 цифры»). Баланс между скоростью словаря и полнотой брутфорса.
5.  **External mode:** Использование внешних функций, написанных на языке C-подобном синтаксисе в конфигурационном файле, для генерации сложных последовательностей.

### Управление сессиями

JtR позволяет приостанавливать и возобновлять процесс перебора, что критично для длительных атак:
-   `--session=name`: Задаёт имя текущей сессии.
-   `--restore=name`: Возобновляет работу сессии после прерывания.
-   Файл `john.pot`: Хранит уже взломанные пары «хеш:пароль». При повторном запуске JtR автоматически пропускает хеши, которые уже есть в этом файле.

## Практические сценарии

### Аудит системных паролей Linux

Для работы с `/etc/shadow` необходимо объединить его с `/etc/passwd` для получения контекста имен пользователей:

```bash
# Объединение файлов
unshadow /etc/passwd /etc/shadow > myhashes.txt

# Запуск атаки в режиме Single crack (первичный аудит)
john --single myhashes.txt

# Словарная атака с правилами трансформации
john --wordlist=/usr/share/wordlists/rockyou.txt --rules myhashes.txt
```

### Взлом зашифрованных файлов и архивов

JtR поставляется с набором утилит `*2john`, которые извлекают хеши из различных форматов:

```bash
# SSH-ключи
ssh2john id_rsa > rsa_hash.txt
john rsa_hash.txt

# ZIP-архивы
zip2john data.zip > zip.hash
john zip.hash

# Документы MS Office
office2john document.docx > office.hash
john office.hash

# PDF-файлы
pdf2john book.pdf > pdf.hash
john pdf.hash
```

### Использование масок

Маски позволяют точно настроить перебор, если известна часть структуры пароля:

```bash
# ?l - строчные, ?u - заглавные, ?d - цифры, ?s - символы, ?a - всё вместе
# Пример: пароль начинается на 'Admin', далее 3 цифры
john --mask='Admin?d?d?d' hashes.txt
```

### Ускорение через GPU (Jumbo John)

Версия Jumbo поддерживает OpenCL для вычислений на видеокартах, что в десятки раз ускоряет перебор простых хешей (MD5, SHA-1):

```bash
# Список доступных устройств OpenCL
john --list=opencl-devices

# Атака на MD5 хеши с использованием GPU
john --format=raw-md5-opencl --wordlist=dict.txt hashes.txt
```

### Просмотр результатов

```bash
# Показать все взломанные пароли для конкретного файла
john --show myhashes.txt

# Статистика текущей сессии (нажать любую клавишу во время работы или выполнить):
john --status
```

## Дополнительная информация

### Конфигурация (john.conf)

Поведение JtR настраивается в файле `john.conf` (или `john.local.conf` для пользовательских правок). Здесь определяются:
-   **Rules:** Правила мутации слов (например, `$[0-9]` добавляет цифру в конец).
-   **Incremental:** Параметры для режима полного перебора.
-   **External:** Пользовательские скрипты генерации.

### Оптимизация производительности

1.  **Формат хеша:** Всегда указывайте формат явно через `--format`, если он известен. Автоопределение замедляет старт и может ошибиться.
2.  **Параллелизм:** Используйте `--fork=N` для запуска N параллельных процессов на многоядерных CPU.
3.  **Порядок атак:** Рекомендуемая последовательность: `Single Crack` → `Wordlist + Rules` → `Mask` → `Incremental`.

### Сравнение с Hashcat

| Характеристика | John the Ripper | Hashcat |
| :--- | :--- | :--- |
| **Сильная сторона** | Сложные правила, CPU-оптимизация, автоопределение | Экстремальная скорость на GPU, поддержка 300+ форматов |
| **Удобство** | Выше (режим Single, unshadow) | Ниже (требует точного указания типа хеша) |
| **Форматы** | Уникальные (SSH, PDF, Zip2john) | В основном стандартные хеши БД и систем |
