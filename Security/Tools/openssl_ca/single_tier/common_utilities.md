# Утилиты и диагностика одноуровневого CA

## Определения

Базовые понятия PKI (Public Key Infrastructure, Инфраструктура открытых ключей), такие как **CSR (Certificate Signing Request, Запрос на подпись сертификата)**, **CRL (Certificate Revocation List, Список отзыва сертификатов)** и **Цепочка доверия (Chain of Trust)**, подробно описаны в **[обзоре PKI](../../../Concepts/pki_overview.md)**.

В контексте одноуровневой архитектуры цепочка доверия максимально проста и состоит из двух звеньев: конечного сертификата сервиса и корневого сертификата CA (Certificate Authority, Центр сертификации) — `ca.crt`.

## Базовые концепции

### Категории диагностических команд

Все команды OpenSSL для работы с сертификатами можно разделить на три функциональные группы:

- **Просмотр** — чтение содержимого и метаданных сертификатов, запросов CSR и списков CRL (команды `x509`, `req`, `crl`).
- **Верификация** — проверка криптографических подписей и соответствия пар «ключ — сертификат» (команды `verify`, `-modulus`).
- **Подключение** — имитация клиента для проверки доступности и корректности настройки TLS-серверов (Transport Layer Security) в реальном времени (команда `s_client`).

### Контекст одноуровневого CA

В данной архитектуре все операции верификации выполняются напрямую относительно корневого сертификата `ca/ca.crt`. Это отличает её от двухуровневых схем, где требуется использование промежуточных цепочек — подробнее см. **[утилиты двухуровневого CA](../two_tier/common_utilities.md)**.

## Практические сценарии

### Просмотр содержимого сертификата

```bash
openssl x509 -in my-service.crt -noout -text
```

Команда выводит все значимые поля: Subject (Субъект), Issuer (Издатель), сроки действия, серийный номер и расширения, такие как SAN (Subject Alternative Name, Альтернативное имя субъекта).

### Просмотр содержимого запроса CSR

```bash
openssl req -in my-service.csr -noout -text
```

Позволяет проверить DN-информацию (Distinguished Name, Отличительное имя) и открытый ключ до момента подписи запроса администратором CA.

### Проверка соответствия ключа и сертификата

Для корректной работы TLS-сервера приватный ключ RSA (Rivest-Shamir-Adleman) должен соответствовать открытому ключу в сертификате. Проверка выполняется через сравнение хешей модулей (modulus) с использованием алгоритма MD5 (Message Digest 5):

```bash
openssl rsa -noout -modulus -in my-service.key | openssl md5
openssl x509 -noout -modulus -in my-service.crt | openssl md5
```

**Хеши должны быть идентичны.** Если они различаются, сервер не сможет инициализировать TLS-сессию.

### Просмотр списка отозванных сертификатов CRL

```bash
openssl crl -in ca/crl.pem -noout -text
```

Отображает серийные номера аннулированных сертификатов и дату генерации списка. Подробнее о процедуре отзыва — в **[управлении сертификатами](./service_certificate_management.md#отзыв-скомпрометированного-сертификата)**.

### Проверка срока действия

```bash
openssl x509 -in my-service.crt -noout -enddate
# → notAfter=Apr  9 12:00:00 2027 GMT
```

Краткий вывод даты истечения (`notAfter`) удобен для использования в скриптах мониторинга.

### Верификация цепочки доверия

```bash
openssl verify -CAfile ca/ca.crt my-service.crt
```

Проверяет, что сертификат `my-service.crt` действительно подписан ключом, соответствующим `ca.crt`. Результат `OK` подтверждает целостность цепочки.

### Диагностика удаленного TLS-сервера

```bash
openssl s_client -connect my-service.local:443 -showcerts </dev/null
```

Команда позволяет увидеть сертификаты, которые сервер передаёт клиенту во время рукопожатия (handshake).

**Полезные флаги отладки:**

- `-servername my-service.local` — передача SNI (Server Name Indication) для проверки виртуальных хостов.
- `-CAfile ca/ca.crt` — использование локального корневого сертификата для проверки доверия к серверу.
