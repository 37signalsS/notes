# Утилиты и диагностика (одноуровневый CA)

## Определения

**CSR (Certificate Signing Request)** — запрос на подпись сертификата. Содержит открытый ключ и DN-информацию владельца (страна, организация, CN). Отправляется администратору CA для выпуска подписанного сертификата.

**CRL (Certificate Revocation List)** — список отозванных сертификатов, сгенерированный CA. Клиенты проверяют этот список перед тем как доверять сертификату.

**Цепочка доверия (Chain of Trust)** — путь от конечного сертификата к корневому CA. В одноуровневой архитектере цепочка проста: `сертификат → ca.crt`.

## Базовые концепции

### Категории диагностических команд

Все команды openssl для работы с сертификатами делятся на группы:

- **Просмотр** — чтение содержимого сертификатов, CSR, CRL (`x509`, `req`, `crl`)
- **Верификация** — проверка подписи и соответствия ключей (`verify`, `modulus`)
- **Подключение** — проверка TLS-серверов в реальном времени (`s_client`)

### Контекст одноуровневого CA

В одноуровневой архитектуре все команды работают напрямую с корневым сертификатом `ca/ca.crt`. Для двухуровневой архитектуры пути отличаются — см. [утилиты двухуровневого CA](../two_tier/common_utilities.md).

## Практические сценарии

### Просмотр содержимого сертификата

```bash
openssl x509 -in my-service.crt -noout -text
```

Выводит все поля: subject, issuer, срок действия, расширения (SAN, Key Usage, Extended Key Usage), серийный номер. Полезно для проверки корректности выпущенного сертификата.

### Просмотр содержимого CSR

```bash
openssl req -in my-service.csr -noout -text
```

Показывает DN-информацию запроса (C, ST, O, OU, CN) и открытый ключ. Используется для проверки данных до подписи CSR администратором CA.

### Проверка соответствия ключа и сертификата

```bash
openssl rsa -noout -modulus -in my-service.key | openssl md5
openssl x509 -noout -modulus -in my-service.crt | openssl md5
```

Хеши модулей должны совпадать. Это критично при переустановке сертификатов — если ключ и сертификат не соответствуют друг другу, TLS-сервер не запустится. Типичные ситуации:

- Ключ перегенерирован, а сертификат остался старый
- Перепутаны файлы ключей при миграции
- Сертификат выпущен на другой CSR

### Просмотр содержимого CRL

```bash
openssl crl -in ca/crl.pem -noout -text
```

Показывает список отозванных сертификатов: серийные номера, даты отзыва, CRL issuer. Используется администратором CA после генерации списка отзыва. Подробнее об отзыве — в [управлении сертификатами](./service_certificate_management.md#отзыв-скомпрометированного-сертификата).

### Проверка даты окончания срока действия сертификата

```bash
openssl x509 -in my-service.crt -noout -enddate
# notAfter=Apr  9 12:00:00 2027 GMT
```

Быстрая проверка срока действия без вывода полного содержимого. Полезно для мониторинга и автоматизации (скрипты, алерты).

### Проверка цепочки доверия

```bash
openssl verify -CAfile ca/ca.crt my-service.crt
```

Проверяет, что сертификат сервиса подписан корневым CA. Ожидаемый вывод: `my-service.crt: OK`. В одноуровневой архитектуре цепочка всегда состоит из одного звена — корневого сертификата.

Подробнее о выпуске и проверке: [управление сертификатами](./service_certificate_management.md).

### Подключение к TLS-серверу и просмотр его сертификатов

```bash
openssl s_client -connect my-service.local:443 -showcerts </dev/null
```

Показывает все сертификаты, которые отдаёт сервер (конечный + промежуточные). В одноуровневой архитектере сервер должен отдавать только свой сертификат — корневой CA уже установлен на клиенте.

Флаги для отладки:

- `-verify 1` — показать процесс верификации
- `-servername my-service.local` — SNI для виртуальных хостов
- `-CAfile ca/ca.crt` — указать корневой CA для проверки
