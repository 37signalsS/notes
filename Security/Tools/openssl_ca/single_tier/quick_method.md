# Быстрый метод выпуска сертификатов (одноуровневый CA)

## Определения

**Быстрый метод** — упрощённый способ подписи CSR напрямую через `openssl x509 -req`, без создания базы данных CA (`db/index.txt`, `db/serial`). Не требует конфигурационного файла и не ведёт учёт выпущенных сертификатов.

**Формальный метод** — полноценный подход с иерархической структурой и базой данных. Описан в [обзоре одноуровневого CA](./overview.md#формальный-метод-создание-структуры-ca).

## Базовые концепции

### Когда применять

Быстрый метод подходит для:

- Разовых тестов и прототипирования
- Временных сертификатов для локальной разработки
- Ситуаций, когда не требуется отзыв сертификатов

### Когда НЕ применять

- **Production-сервисы** — нет возможности вести учёт и отзыв
- **Долгосрочные сертификаты** — без базы данных невозможно отследить, что и когда было выпущено
- **Командная работа** — при коллективном использовании быстро возникает хаос с версиями ключей

Для этих случаев используйте [формальный метод](./overview.md#формальный-метод-создание-структуры-ca).

## Практические сценарии

### Базовая подпись CSR (без SAN)

```bash
# 1. Создаём ключ и CSR для тестового сайта
openssl req -new -newkey rsa:2048 -nodes \
    -keyout test.key -out test.csr \
    -subj "/C=RU/ST=Test/L=Test/O=Test/CN=test.local"

# 2. Подписываем CSR корневым CA напрямую
openssl x509 -req -in test.csr \
    -CA ca/ca.crt -CAkey ca/ca.key -CAcreateserial \
    -out test.crt -days 90 -sha256
```

Разбор флагов:

- `-CA ca/ca.crt` — указать корневой сертификат CA для проверки подлинности.
- `-CAkey ca/ca.key` — приватный ключ CA для подписи.
- `-CAcreateserial` — создать файл `ca.srl` (если отсутствует) для хранения последнего серийного номера. Это упрощённая замена `db/serial`.
- `-days 90` — срок действия сертификата (90 дней).
- `-sha256` — алгоритм хеширования при подписи.

### Выпуск сертификата с SAN (через extfile)

Для добавления Subject Alternative Name необходимо создать временный файл расширений и передать его через `-extfile`:

```bash
# 1. Создаём файл расширений
cat > san.ext <<EOF
subjectAltName = DNS:test.local,DNS:www.test.local,IP:192.168.1.10
EOF

# 2. Подписываем CSR с применением расширений
openssl x509 -req -in test.csr \
    -CA ca/ca.crt -CAkey ca/ca.key -CAcreateserial \
    -out test.crt -days 90 -sha256 \
    -extfile san.ext

# 3. Удаляем временный файл
rm san.ext
```

Проверить наличие SAN в полученном сертификате:

```bash
openssl x509 -in test.crt -noout -text | grep -A1 "Subject Alternative Name"
```

### Проверка выпущенного сертификата

```bash
# Проверить цепочку доверия
openssl verify -CAfile ca/ca.crt test.crt

# Просмотреть содержимое
openssl x509 -in test.crt -noout -text
```

## Дополнительная информация

### Сравнение методов

| Критерий | Быстрый метод | Формальный метод |
| :--- | :--- | :--- |
| База данных | Нет | `db/index.txt`, `db/serial` |
| Учёт сертификатов | Отсутствует | Полная база с статусами |
| Отзыв (CRL) | Невозможен | Поддерживается |
| SAN | Через `-extfile` | Через `openssl.cnf` |
| Сложность | Минимальная | Требует подготовки |
