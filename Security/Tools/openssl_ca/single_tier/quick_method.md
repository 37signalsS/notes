# Быстрый метод выпуска сертификатов

## Определения

**Быстрый метод** — упрощённый способ подписи сертификата напрямую через команду `openssl x509 -req`. В отличие от формального метода, он не требует ведения базы данных CA (Certificate Authority, Центр сертификации) и конфигурационного файла, но ограничивает возможности по учёту и отзыву.

**CA (Certificate Authority, Центр сертификации)** — доверенная сторона, подтверждающая подлинность открытых ключей путём выпуска цифровых сертификатов.

**CSR (Certificate Signing Request, Запрос на подпись сертификата)** — электронный документ, содержащий открытый ключ и информацию о владельце (Subject), отправляемый в CA для генерации сертификата.

**X.509** — стандарт, определяющий формат сертификатов открытых ключей.

**OpenSSL 3.0+** — современная версия инструментария, в которой многие команды подписи были упрощены, а поддержка алгоритмов на эллиптических кривых (ECDSA/Ed25519) стала стандартной практикой.

## Базовые концепции

### Области применения

Быстрый метод ориентирован на сценарии, где скорость и простота приоритетнее строгого аудита:

- Прототипирование и разовые тесты (например, настройка Nginx в Docker-контейнере).
- Временные сертификаты для локальных сред разработки.
- Окружения, где механизмы отзыва (CRL/OCSP) не требуются.
- Генерация mTLS-сертификатов для краткосрочных сессий.

### Ограничения

- **Отсутствие учёта:** невозможно отследить историю выпусков, так как данные не фиксируются в `index.txt`.
- **Невозможность отзыва:** без ведения базы данных нельзя сформировать полноценный CRL (Certificate Revocation List).
- **Ручное управление SAN:** добавление альтернативных имён субъекта требует передачи параметров через CLI или временные файлы расширений.

Для долгосрочных проектов и производственных сред (production) используйте **[формальный метод управления CA](./overview.md#формальный-метод-подготовка-инфраструктуры)**.

## Практические сценарии

### Однострочная генерация «Ключ + Самоподписанный сертификат»

Самый быстрый способ создать пару для локального веб-сервера.

```bash
# Генерация ключа RSA 4096 и сертификата на 1 год
openssl req -x509 -newkey rsa:4096 -sha256 -nodes \
    -keyout server.key -out server.crt \
    -days 365 \
    -subj "/C=RU/ST=Moscow/L=Moscow/O=Dev/CN=localhost"
```

### Базовая подпись запроса (Flow: Key -> CSR -> CRT)

Процесс состоит из генерации пары «ключ + запрос» и последующей подписи вашим внутренним CA.

#### Шаг 1: Подготовка запроса

```bash
# Вариант А: RSA 4096 (Классика)
openssl req -new -newkey rsa:4096 -nodes \
    -keyout service.key -out service.csr \
    -subj "/CN=service.local"

# Вариант Б: ECDSA P-384 (Современно, 2026)
openssl req -new -newkey ec:<(openssl ecparam -name secp384r1) -nodes \
    -keyout service.key -out service.csr \
    -subj "/CN=service.local"
```

#### Шаг 2: Подпись корневым сертификатом

```bash
openssl x509 -req -in service.csr \
    -CA ca/ca.crt -CAkey ca/ca.key -CAcreateserial \
    -out service.crt -days 90 -sha384
```

- `-CAcreateserial` — автоматически создаёт файл `.srl` для хранения следующего серийного номера (упрощённый аналог `db/serial`).

### Выпуск сертификата с SAN через CLI

В OpenSSL 3.x можно передать альтернативные имена напрямую в командной строке, не создавая временный `.ext` файл.

```bash
openssl x509 -req -in service.csr \
    -CA ca/ca.crt -CAkey ca/ca.key -CAcreateserial \
    -out service.crt -days 90 -sha384 \
    -extfile <(printf "subjectAltName=DNS:service.local,DNS:www.service.local,IP:10.0.0.5")
```

### Верификация результата

После выпуска необходимо убедиться в корректности цепочки доверия:

```bash
# Проверка цепочки (service.crt должен быть подписан ca.crt)
openssl verify -CAfile ca/ca.crt service.crt
# → service.crt: OK

# Просмотр расширений и алгоритма подписи
openssl x509 -in service.crt -noout -text | grep -E "Signature Algorithm|Subject Alternative Name" -A 1
```

## Дополнительная информация

### Сравнение методов управления

| Характеристика | Быстрый метод | Формальный метод |
| :--- | :--- | :--- |
| **База данных** | Отсутствует | Обязательна (`index.txt`) |
| **Учёт статусов** | Нет | Да (Valid, Revoked, Expired) |
| **Поддержка CRL** | Нет | Да |
| **Сложность** | Низкая | Средняя |
| **Рекомендация** | Локальные тесты, Docker | Инфраструктурные сервисы, mTLS |
