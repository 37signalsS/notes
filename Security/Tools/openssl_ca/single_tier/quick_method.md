# Быстрый метод выпуска сертификатов

## Определения

**Быстрый метод** — упрощённый способ подписи сертификата напрямую через команду `openssl x509 -req`. В отличие от формального метода, он не требует ведения базы данных CA (Certificate Authority, Центр сертификации) и конфигурационного файла, но ограничивает возможности по учёту и отзыву.

**CA (Certificate Authority, Центр сертификации)** — доверенная сторона, подтверждающая подлинность открытых ключей путём выпуска цифровых сертификатов.

**CSR (Certificate Signing Request, Запрос на подпись сертификата)** — электронный документ, содержащий открытый ключ и информацию о владельце (Subject), отправляемый в CA для генерации сертификата.

**X.509** — стандарт, определяющий формат сертификатов открытых ключей.

## Базовые концепции

### Области применения

Быстрый метод ориентирован на сценарии, где скорость и простота приоритетнее строгого аудита:

- Прототипирование и разовые тесты.
- Временные сертификаты для локальных сред разработки.
- Окружения, где механизмы отзыва (CRL/OCSP) не требуются.

### Ограничения

- **Отсутствие учёта:** невозможно отследить историю выпусков, так как данные не фиксируются в `index.txt`.
- **Невозможность отзыва:** без ведения базы данных нельзя сформировать полноценный CRL (Certificate Revocation List).
- **Сложность управления SAN:** добавление альтернативных имён субъекта требует использования внешних файлов расширений.

Для долгосрочных проектов и производственных сред (production) используйте **[формальный метод управления CA](./overview.md#формальный-метод-создание-структуры-ca)**.

## Практические сценарии

### Базовая подпись запроса

Процесс состоит из генерации пары «ключ + запрос» и немедленной подписи корневым сертификатом.

```bash
# 1. Генерация ключа и CSR для тестового домена
openssl req -new -newkey rsa:2048 -nodes \
    -keyout test.key -out test.csr \
    -subj "/C=RU/ST=Test/L=Test/O=Test/CN=test.local"

# 2. Подпись запроса корневым сертификатом
openssl x509 -req -in test.csr \
    -CA ca/ca.crt -CAkey ca/ca.key -CAcreateserial \
    -out test.crt -days 90 -sha256
```

**Разбор параметров подписи:**

- `-CA ca/ca.crt` — путь к сертификату вашего CA.
- `-CAkey ca/ca.key` — путь к приватному ключу вашего CA.
- `-CAcreateserial` — автоматически создаёт файл `.srl` для хранения следующего серийного номера (упрощённый аналог `db/serial`).
- `-days 90` — срок действия выпускаемого сертификата.

### Выпуск сертификата с SAN

Современные браузеры требуют наличия расширения SAN (Subject Alternative Name, Альтернативное имя субъекта). При быстром методе оно передаётся через временный файл:

```bash
# 1. Формирование файла расширений
cat > san.ext <<EOF
subjectAltName = DNS:test.local,DNS:www.test.local,IP:192.168.1.10
EOF

# 2. Подпись с применением расширений
openssl x509 -req -in test.csr \
    -CA ca/ca.crt -CAkey ca/ca.key -CAcreateserial \
    -out test.crt -days 90 -sha256 \
    -extfile san.ext
```

### Верификация результата

После выпуска необходимо убедиться в корректности цепочки доверия и наличии требуемых расширений:

```bash
# Проверка цепочки (test.crt должен быть подписан ca.crt)
openssl verify -CAfile ca/ca.crt test.crt

# Просмотр расширений SAN
openssl x509 -in test.crt -noout -text | grep -A1 "Subject Alternative Name"
```

## Дополнительная информация

### Сравнение методов управления

| Характеристика | Быстрый метод | Формальный метод |
| :--- | :--- | :--- |
| **База данных** | Отсутствует | Обязательна (`index.txt`) |
| **Учёт статусов** | Нет | Да (Valid, Revoked, Expired) |
| **Поддержка CRL** | Нет | Да |
| **Масштабируемость** | Низкая | Высокая |
