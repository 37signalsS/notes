# Обзор одноуровневого центра сертификации (CA) на OpenSSL

## Определения

**CA (Certificate Authority, Центр сертификации)** — доверенная сущность, выпускающая цифровые сертификаты.

**Одноуровневый CA** — архитектура центра сертификации, в которой корневой CA напрямую подписывает сертификаты конечных сущностей (серверов, клиентов) без промежуточного звена. Подходит для тестовых сред и небольших организаций.

**Форматы файлов и расширения** — базовые понятия PKI (Public Key Infrastructure, Инфраструктура открытых ключей), такие как CSR (Certificate Signing Request, Запрос на подпись сертификата), расширение SAN (Subject Alternative Name, Альтернативное имя субъекта), механизмы отзыва CRL (Certificate Revocation List, Список отзыва сертификатов) и протокол OCSP (Online Certificate Status Protocol, Протокол онлайн-проверки статуса сертификата) подробно описаны в **[обзоре PKI](../../../Concepts/pki_overview.md)**.

**mTLS (Mutual TLS, Взаимный TLS)** — механизм взаимной аутентификации, при котором клиент и сервер проверяют сертификаты друг друга ([подробнее](../../../../WebServers/Nginx/Security/TLS_SSL/nginx_tls_ssl_overview.md#mutual-tls-mtls)).

## Базовые концепции

### Назначение одноуровневого CA

OpenSSL CA необходим для выпуска доверенных SSL/TLS-сертификатов для внутренних сервисов, разработки, тестирования и реализации mTLS. Одноуровневая архитектура — простейший вариант, где один ключ выполняет функции и корневого, и выпускающего CA.

### Сравнение с двухуровневой архитектурой

| Критерий | Одноуровневый CA | Двухуровневый CA |
| :--- | :--- | :--- |
| **Безопасность** | Низкая — один ключ для всего | Высокая — Root CA офлайн |
| **Сложность** | Минимальная | Средняя |
| **Отзыв сертификатов** | Да (через формальный метод) | Да, с изоляцией уровней |
| **Применение** | Тесты, dev, малые сети | Production, enterprise |

Для production-сред настоятельно рекомендуется **[двухуровневая архитектура](../two_tier/overview.md)**, где корневой ключ используется только для подписи промежуточных CA и хранится в изолированной среде (air-gapped).

### Подходы к управлению CA

В рамках одноуровневого CA доступны два подхода:

1. **Формальный метод** — полноценная структура CA с базой данных сертификатов. Рекомендуется для долгосрочного управления, так как поддерживает учёт и отзыв сертификатов.
2. **Быстрый метод** — упрощённая подпись CSR напрямую через `openssl x509 -req` без ведения базы данных. Подходит для разовых тестов.

## Практические сценарии

### Формальный метод: создание структуры CA

Для работы формального метода необходимо подготовить иерархию директорий и файлы базы данных:

```bash
# Основная директория
mkdir -p ca

# Вложенная структура для базы данных и сертификатов
mkdir -p ca/db/{newcerts,crl}
touch ca/db/index.txt        # База данных выданных сертификатов
echo "1000" > ca/db/serial   # Начальный серийный номер в hex
echo "1000" > ca/db/crlnumber # Начальный номер для CRL
```

**Назначение файлов базы данных:**

- `db/index.txt` — главная база данных CA. Содержит статус (V — действителен, R — отозван), срок истечения и данные субъекта каждого сертификата.
- `db/serial` — файл, содержащий серийный номер для следующего выпускаемого сертификата.
- `db/crlnumber` — счетчик для порядковых номеров списков отзыва (CRL).
- `db/newcerts/` — архив всех выданных сертификатов в формате `<serial>.pem`.

**Итоговая структура проекта:**

```
ca/
├── ca.key         # Приватный ключ CA
├── ca.crt         # Корневой сертификат
├── openssl.cnf    # Правила работы CA (конфигурация)
├── crl.pem        # Текущий список отзыва (после генерации)
└── db/
    ├── index.txt  # База сертификатов
    ├── serial     # Счётчик серийных номеров
    ├── crlnumber  # Счётчик CRL
    ├── newcerts/  # Архив выданных сертификатов
    └── crl/       # Директория для сгенерированных CRL
```

После подготовки структуры выполняются следующие этапы:

1. **[Настройка CA и создание корня](./ca_setup.md)**
2. **[Выпуск сертификатов сервисов](./service_certificate_management.md)**
3. **[Утилиты и диагностика](./common_utilities.md)**

### Быстрый метод: упрощённая подпись

Выпуск сертификата без ведения базы данных, полезен для быстрой проверки гипотез. Подробные инструкции приведены в разделе **[быстрый метод выпуска](./quick_method.md)**.
