# Утилиты и диагностика (двухуровневый CA)

## Определения

**CSR (Certificate Signing Request)** — запрос на подпись сертификата. Содержит открытый ключ и DN-информацию владельца (страна, организация, CN). Отправляется администратору Intermediate CA для выпуска подписанного сертификата.

**CRL (Certificate Revocation List)** — список отозванных сертификатов, сгенерированный Intermediate CA. В двухуровневой архитектуре CRL публикуется промежуточным CA, а не корневым. Клиенты скачивают CRL по URL из расширения `crlDistributionPoints` сертификата.

**Цепочка доверия (Chain of Trust)** — путь от конечного сертификата к корневому CA через промежуточный. В двухуровневой архитектуре: `сертификат → intermediate-ca.crt → root-ca.crt`. Файл `ca-chain.crt` содержит оба сертификата CA и используется для верификации.

## Базовые концепции

### Категории диагностических команд

Все команды openssl для работы с сертификатами делятся на группы:

- **Просмотр** — чтение содержимого сертификатов, CSR, CRL (`x509`, `req`, `crl`)
- **Верификация** — проверка подписи и соответствия ключей (`verify`, `modulus`)
- **Подключение** — проверка TLS-серверов в реальном времени (`s_client`)

### Контекст двухуровневого CA

Ключевое отличие от [одноуровневого CA](../../single_tier/common_utilities.md) — все команды верификации используют **цепочку** `ca-chain.crt` (промежуточный + корневой), а не только корневой сертификат:

| Операция | Одноуровневый CA | Двухуровневый CA |
|---|---|---|
| Верификация | `-CAfile ca/ca.crt` | `-CAfile intermediate-ca/ca-chain.crt` |
| CRL | `ca/crl.pem` | `intermediate-ca/crl/crl.pem` |
| Полная цепочка сервиса | `service.crt` | `service.fullchain.crt` (сервис + intermediate) |

Корневой CA хранится офлайн и не участвует в повседневных операциях.

## Практические сценарии

### Просмотр содержимого сертификата

```bash
openssl x509 -in my-service.crt -noout -text
```

Выводит все поля: subject, issuer, срок действия, расширения (SAN, Key Usage, Extended Key Usage), серийный номер. Полезно для проверки корректности выпущенного сертификата.

### Просмотр содержимого CSR

```bash
openssl req -in my-service.csr -noout -text
```

Показывает DN-информацию запроса (C, ST, O, OU, CN) и открытый ключ. Используется для проверки данных до подписи CSR администратором Intermediate CA.

### Проверка соответствия ключа и сертификата

```bash
openssl rsa -noout -modulus -in my-service.key | openssl md5
openssl x509 -noout -modulus -in my-service.crt | openssl md5
```

Хеши модулей должны совпадать. Это критично при переустановке сертификатов — если ключ и сертификат не соответствуют друг другу, TLS-сервер не запустится. Типичные ситуации:

- Ключ перегенерирован, а сертификат остался старый
- Перепутаны файлы ключей при миграции
- Сертификат выпущен на другой CSR

### Просмотр содержимого CRL

```bash
openssl crl -in intermediate-ca/crl/crl.pem -noout -text
```

Показывает список отозванных сертификатов: серийные номера, даты отзыва, CRL issuer. В двухуровневой архитектуре CRL генерируется промежуточным CA. Подробнее об отзыве — в [управлении сертификатами](./service_certificate_management.md#отзыв-скомпрометированного-сертификата).

### Подключение к TLS-серверу и просмотр его сертификатов

```bash
openssl s_client -connect my-service.local:443 -showcerts </dev/null
```

Показывает все сертификаты, которые отдаёт сервер (конечный + промежуточные). В двухуровневой архитектуре сервер должен отдавать **полную цепочку** (`fullchain.crt`): сертификат сервиса + промежуточный CA. Корневой CA уже установлен на клиенте.

Флаги для отладки:

- `-verify 1` — показать процесс верификации
- `-servername my-service.local` — SNI для виртуальных хостов
- `-CAfile intermediate-ca/ca-chain.crt` — указать цепочку CA для проверки

### Проверка цепочки доверия

```bash
openssl verify -CAfile intermediate-ca/ca-chain.crt my-service.fullchain.crt
```

Проверяет полную цепочку: сертификат сервиса → промежуточный CA → корневой CA. В двухуровневой архитектуре **нельзя** использовать только `root-ca/ca.crt` — цепочка будет неполной.

### Проверка даты окончания срока действия сертификата

```bash
openssl x509 -in my-service.crt -noout -enddate
# notAfter=Apr  9 12:00:00 2027 GMT
```

Быстрая проверка срока действия без вывода полного содержимого. Полезно для мониторинга и автоматизации (скрипты, алерты).
