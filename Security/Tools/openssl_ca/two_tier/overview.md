# Обзор двухуровневого центра сертификации (CA) на OpenSSL

> **Рекомендация:** Двухуровневая архитектура (Root CA + Intermediate CA) — стандарт для production-сред. Для тестов и dev-окружений см. [одноуровневый CA](../single_tier/overview.md).

Двухуровневый CA — рекомендуемый подход для создания и управления внутренней PKI-инфраструктурой. Позволяет выпускать доверенные SSL/TLS-сертификаты для внутренних сервисов, разработки, тестирования и реализации взаимной аутентификации (mTLS).

## Определения

**Двухуровневый CA** — архитектура центра сертификации с двумя уровня: корневой CA (Root CA), хранящийся офлайн (air-gapped), и промежуточный CA (Intermediate CA), используемый для повседневного выпуска сертификатов.

**Root CA (корневой CA)** — вершина иерархии доверия. Самоподписанный сертификат, используется только один раз для подписи Intermediate CA, после чего ключ убирается в защищённое офлайн-хранилище. Подробнее — в [обзоре PKI](../../../../Concepts/pki_overview.md#иерархия-доверия).

**Intermediate CA (промежуточный CA)** — рабочий CA, подписанный Root CA. Выполняет повседневные операции: выпуск, отзыв, перевыпуск сертификатов. При компрометации его ключа — отзыв затрагивает только промежуточный уровень, Root CA остаётся доверенным.

**Цепочка доверия (Chain of Trust)** — путь верификации от конечного сертификата до корневого CA: `сервис → Intermediate CA → Root CA`. Клиент доверяет сервису, потому что доверяет Root CA. Форматы и теория — в [обзоре PKI](../../../../Concepts/pki_overview.md#цепочка-доверия-chain-of-trust).

**ca-chain.crt** — файл цепочки сертификатов, объединяющий `intermediate.crt + root-ca/ca.crt`. Используется TLS-серверами для отправки полной цепочки клиентам и для верификации.

> Базовые определения PKI (ключ, CSR, сертификат, форматы .pem/.der/.p12, CRL, OCSP) — в [обзоре PKI](../../../../Concepts/pki_overview.md#definitions).

## Базовые концепции

### Архитектура двухуровневого CA

```
Root CA (самоподписанный, air-gapped, 10 лет)
    └── Intermediate CA (подписан Root CA, 3–5 лет)
            ├── Сертификаты сервисов (serverAuth)
            └── Сертификаты клиентов (clientAuth)
```

**Изоляция Root CA:** после подписи Intermediate CA приватный ключ Root CA (`ca.key`) переносится на зашифрованный офлайн-носитель и больше не используется в повседневных операция.

**Повседневные операции:** все запросы CSR обрабатываются Intermediate CA. Его ключ хранится онлайн, но в защищённом месте (Vault, CI/CD-система с MFA).

### Сравнение с одноуровневым CA

| Критерий | Одноуровневый CA | Двухуровневый CA |
| :--- | :--- | :--- |
| **Безопасность** | Низкая — один ключ для всего | Высокая — Root CA офлайн |
| **Сложность** | Минимальная | Средняя |
| **Риск компрометации** | Катастрофический | Локализован (Intermediate CA) |
| **Отзыв** | Прямой через один CA | Через Intermediate CA, Root CA стабилен |
| **Применение** | Тесты, dev, малые сети | Production, enterprise |

### Компоненты двухуровневого CA

**Структура директорий:**

```
project/
├── root-ca/                    # Корневой CA (air-gapped)
│   ├── openssl.cnf             # Конфигурация Root CA
│   ├── ca.key                  # Приватный ключ Root CA (убирается в офлайн)
│   ├── ca.crt                  # Корневой сертификат
│   └── db/                     # База данных (только Intermediate CA)
│       ├── index.txt
│       ├── serial
│       └── newcerts/
│
└── intermediate-ca/            # Промежуточный CA (онлайн)
    ├── openssl.cnf             # Конфигурация Intermediate CA
    ├── intermediate.key        # Приватный ключ Intermediate CA
    ├── intermediate.crt        # Сертификат, подписанный Root CA
    ├── ca-chain.crt            # intermediate.crt + root-ca/ca.crt
    ├── db/                     # База данных сервисных сертификатов
    │   ├── index.txt
    │   ├── serial
    │   └── crlnumber
    ├── certs/                  # Архив выпущенных сертификатов
    ├── crl/                    # Списки отзыва (crl.pem)
    └── csr/                    # Входящие запросы CSR
```

### Расширения и ограничения

- **`pathlen:1`** (Root CA) — допускает один уровень промежуточных CA
- **`pathlen:0`** (Intermediate CA) — запрещает подписывать другие CA, только leaf-сертификаты
- **`crlDistributionPoints`** — URL для автоматической проверки отзыва клиентами
- **`subjectAltName` (SAN)** — доменные имена/IP в сертификате (CN устарел для этой цели)

## Практические сценарии

### Порядок развёртывания двухуровневого CA

Полный цикл создания и использования двухуровневого CA выполняется в следующем порядке:

**1. Создание Root CA**

Генерация корневого ключа и самоподписанного сертификата. Ключ после создания убирается в офлайн-хранилище.
→ [Создание Root CA](./root_ca_setup.md)

**2. Создание Intermediate CA**

Подготовка структуры, конфигурации, генерация CSR и подпись корневым CA. Создание цепочки `ca-chain.crt`.
→ [Настройка Intermediate CA](./intermediate_ca_setup.md)

**3. Выпуск сертификатов сервисов**

Приём CSR от сервисов, подпись через Intermediate CA, настройка SAN и CRL distribution points.
→ [Управление сертификатами](./service_certificate_management.md)

**4. Диагностика и утилиты**

Просмотр сертификатов, CSR, CRL. Проверка цепочки доверия, соответствия ключей, подключение к TLS-серверам.
→ [Утилиты и диагностика](./common_utilities.md)

### Типичные сценарии использования

- **Внутренние сервисы** — выпуск TLS-сертификатов для микросервисов, API-шлюзов, баз данных
- **mTLS** — взаимная аутентификация между сервисами (серверные + клиентские сертификаты)
- **Разработка и тестирование** — сертификаты для staging-окружений без зависимости от публичных CA
- **IoT и embedded** — сертификаты для устройств без публичных доменов
