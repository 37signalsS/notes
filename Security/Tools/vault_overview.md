# Vault

## 1. Определения

**HashiCorp Vault** — это централизованная система для управления всеми типами секретов (пароли, API-ключи, токены, сертификаты, ключи шифрования) в ИТ-инфраструктуре. Vault обеспечивает безопасное хранение, строгий контроль доступа и предоставляет детальный журнал аудита всех операций.

## 2. Основные концепции

Архитектура Vault основана на нескольких ключевых компонентах:

- **Хранилище (Storage Backend)**: Физическое место, где Vault хранит зашифрованные данные. Vault не хранит данные сам, а делегирует это другим системам, таким как Consul, дисковое хранилище, S3, PostgreSQL и др.
- **Аутентификация (Auth Methods)**: Vault использует методы аутентификации для проверки личности клиентов (пользователей, машин, приложений). Поддерживаются различные методы: по токену, логину/паролю, AppRole, AWS IAM, Kubernetes, LDAP.
- **Движки Секретов (Secret Engines)**: Компоненты, которые управляют секретами. Они могут просто хранить данные (KV), генерировать их "на лету" (динамические секреты для баз данных, облаков) или предоставлять сервисы (PKI, шифрование).
- **Политики (Policies)**: Правила, которые определяют, что аутентифицированный клиент может делать в Vault. Политики реализуют принцип наименьших привилегий.
- **Seal / Unseal (Запечатывание / Распечатывание)**: При запуске Vault находится в "запечатанном" состоянии. Чтобы начать работу, его необходимо "распечатать" с помощью набора ключей (Unseal Keys), которые генерируются при инициализации и распределяются между несколькими операторами по алгоритму Шамира.

## 3. Практические сценарии

### Запуск Vault в dev-режиме
Для разработки и тестирования Vault можно запустить в режиме `dev`, где он использует хранилище в памяти и автоматически распечатывается одним ключом.
```bash
# Запуск dev-сервера
vault server -dev

# В другом терминале установите переменные окружения
export VAULT_ADDR='http://127.0.0.1:8200'
export VAULT_TOKEN='...' # Копировать Root Token из вывода команды выше
```

### Работа с KV-хранилищем
KV (Key-Value) — это простейший движок для хранения статических секретов.
```bash
# Включить KV-движок версии 2
vault secrets enable -path=secret kv-v2

# Записать секрет
vault kv put secret/db/my-app password="SuperSecretPassword123"

# Прочитать секрет
vault kv get secret/db/my-app
```

### Динамические секреты для PostgreSQL
Vault может генерировать временные учетные данные для баз данных.
```bash
# 1. Включить движок баз данных
vault secrets enable database

# 2. Настроить подключение к PostgreSQL
vault write database/config/my-postgres plugin_name=postgresql-database-plugin \
    allowed_roles="my-role" \
    connection_url="postgresql://user:pass@host:port/db"

# 3. Создать роль, которая описывает, как генерировать учетные данные
vault write database/roles/my-role \
    db_name=my-postgres \
    creation_statements="CREATE ROLE \"{{name}}\" WITH LOGIN PASSWORD '{{password}}' VALID UNTIL '{{expiration}}'; GRANT SELECT ON ALL TABLES IN SCHEMA public TO \"{{name}}\";" \
    default_ttl="1h" \
    max_ttl="24h"

# 4. Получить динамический секрет
vault read database/creds/my-role
```

## 4. Продвинутые детали

### Шифрование как сервис (Transit Engine)
Движок `transit` позволяет шифровать и расшифровывать данные без их хранения в Vault. Приложения отправляют данные в Vault по API, а Vault возвращает их в зашифрованном виде, управляя при этом ключами шифрования.

### Высокая доступность (High Availability)
В production-среде Vault настраивается в режиме высокой доступности (HA) с несколькими репликами. Одна нода является активной и обрабатывает все запросы, а остальные находятся в режиме ожидания и берут на себя нагрузку в случае отказа активной ноды.

### Идентификация на основе приложений (AppRole)
Метод аутентификации `AppRole` позволяет машинам и приложениям аутентифицироваться в Vault, используя `RoleID` (аналог логина) и `SecretID` (аналог пароля). Это предпочтительный способ для автоматизированных процессов в CI/CD.
