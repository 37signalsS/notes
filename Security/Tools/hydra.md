# THC Hydra

## Definitions

**THC Hydra** — высокопроизводительный параллелизированный инструмент для онлайн-перебора учётных данных. Поддерживает 50+ сетевых протоколов и проводит атаки методом брутфорса или по словарю против живых сервисов.

Связано: [brute-force атаки](../Concepts/brute_force_attacks.md)

## Basic Concepts

### Принцип работы

Hydra подключается к целевому сервису и последовательно проверяет комбинации из списков логинов и паролей. Ключевое отличие от офлайн-инструментов (например, [John the Ripper](./jtr.md)) — работа напрямую с живыми службами аутентификации.

### Ключевые особенности

- **Параллелизация** — одновременное выполнение множества попыток входа (потоки `-t`), что ускоряет перебор.
- **Поддержка протоколов** — `ssh`, `ftp`, `http-post-form`, `http-get`, `smb`, `smtp`, `rdp`, `vnc`, `telnet`, `mysql`, `postgresql`, `imap`, `pop3`, `ldap` и другие.
- **Гибкость входных данных** — один логин + файл паролей, один пароль + файл логинов, или пара файлов.

### Общий синтаксис

```bash
hydra [[-l LOGIN|-L FILE] [-p PASS|-P FILE]] [-C FILE] [options] service://target
```

| Параметр | Описание |
|---|---|
| `-l LOGIN` | Один логин |
| `-L FILE` | Файл со списком логинов |
| `-p PASS` | Один пароль |
| `-P FILE` | Файл со списком паролей |
| `-C FILE` | Файл комбинированных пар `login:pass` |
| `-t TASKS` | Количество параллельных потоков |
| `-w SECONDS` | Таймаут ожидания ответа от сервера |
| `-o FILE` | Файл для записи найденных учётных данных |
| `-f` | Остановить после нахождения первой пары |
| `-vV` | Подробный вывод (вербозность) |
| `-s PORT` | Нестандартный порт целевого сервиса |

## Practical Scenarios

### Атака на SSH

Подбор пароля для пользователя `root` из файла `pass.list`:

```bash
hydra -l root -P pass.list -t 4 -v ssh://192.168.1.1
```

### Атака на веб-форму (HTTP POST)

Подбор логина и пароля для формы входа:

```bash
hydra -L user.list -P pass.list 192.168.1.1 http-post-form "/login.php:username=^USER^&password=^PASS^:Login failed"
```

- `^USER^` / `^PASS^` — плейсхолдеры, заменяемые значениями из списков.
- `Login failed` — строка-маркер ошибки аутентификации. Hydra определяет неудачу по её наличию в ответе.
- Для форм с CSRF-токенами требуется предварительное извлечение токена (флаг `-m` или модуль `http-form-post`).

### Атака на RDP

```bash
hydra -l administrator -P /usr/share/wordlists/rockyou.txt rdp://10.10.10.1
```

### Атака на FTP с сохранением результатов

```bash
hydra -L users.txt -P passwords.txt -t 8 -f -o found.txt ftp://192.168.1.100
```

- `-f` — остановка после первого успешного результата.
- `-o found.txt` — запись найденных пар в файл.

## Additional Information

### Графический интерфейс

`xhydra` (`hydra-gtk`) — графическая оболочка на базе GTK, упрощающая настройку параметров атаки через GUI.

### Опции производительности

| Опция | Рекомендация |
|---|---|
| `-t TASKS` | Значения >16 могут вызвать блокировку (IPS/WAF) или нестабильность сервиса. Начинать с 4–8. |
| `-w SECONDS` | Увеличить до 10–30 при работе с медленными сервисами или через прокси. |

### Использование с прокси

Hydra поддерживает работу через прокси-серверы:

```bash
# HTTP-прокси
export HYDRA_PROXY=http://proxy.example.com:8080

# SOCKS5-прокси
export HYDRA_PROXY=socks5://proxy.example.com:1080
```

### Защита от Hydra

- Отключение парольной аутентификации в пользу ключей ([SSH-ключи](../../Linux/Security/ssh/server/ssh_hardening_best_practices.md)).
- [fail2ban](../../Linux/Security/Tools/fail2ban.md) — автоматическая блокировка IP после N неудачных попыток.
- Rate limiting на уровне приложения и сети.
- [MFA](../Concepts/mfa_totp.md) — компроментация пароля недостаточна для входа.
- CAPTCHA для веб-форм.
