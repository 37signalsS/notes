# THC Hydra: Онлайн-аудит учётных данных

## Определения

**THC Hydra** — высокопроизводительный, параллелизированный инструмент для проведения атак методом перебора (brute-force) или по словарю против живых сетевых служб (online cracking). Он позволяет специалистам по безопасности проверять устойчивость систем аутентификации к атакам на подбор паролей в реальном времени.

Поддерживает более 50 протоколов и является стандартом де-факто для сетевого аудита паролей наряду с Medusa и Ncrack.

## Базовые концепции

### Принцип работы

Hydra устанавливает сетевое соединение с целевым сервисом и имитирует процесс аутентификации, последовательно перебирая комбинации из предоставленных списков. В отличие от офлайн-инструментов (например, [John the Ripper](./jtr.md)), Hydra ограничена скоростью ответа сервера и механизмами защиты на стороне цели (Rate Limiting, WAF).

### Ключевые возможности

- **Высокая параллелизация:** одновременное выполнение множества попыток входа (флаг `-t`) для максимальной загрузки канала и сервиса.
- **Модульная архитектура:** поддержка `ssh`, `rdp`, `smb`, `mysql`, `postgresql`, `http-post-form`, `http-get`, `snmp`, `ldap`, `vnc`, `smtp` и многих других.
- **Управление сессиями:** автоматическое сохранение прогресса. Если атака прервана, её можно возобновить с того же места командой `hydra -R`.
- **Гибкость верификации:** возможность определения успешного или неудачного входа по строкам в HTTP-ответе, кодам состояния или специфическим ответам протоколов.

### Общий синтаксис

```bash
hydra [[-l LOGIN|-L FILE] [-p PASS|-P FILE]] [-C FILE] [options] [service://]target[:port][/module_options]
```

| Параметр | Описание |
| :--- | :--- |
| `-l LOGIN` | Использовать один конкретный логин. |
| `-L FILE` | Путь к файлу со списком логинов. |
| `-p PASS` | Использовать один конкретный пароль. |
| `-P FILE` | Путь к файлу со списком паролей (например, `rockyou.txt`). |
| `-C FILE` | Путь к файлу с парами `user:pass` (разделитель — двоеточие). |
| `-t TASKS` | Количество параллельных потоков на каждую цель (по умолчанию 16). |
| `-f` | Немедленная остановка после нахождения первой валидной пары. |
| `-o FILE` | Запись найденных результатов в файл. |
| `-R` | Возобновление прерванной сессии (использует файл `hydra.restore`). |
| `-s PORT` | Указать нестандартный порт. |
| `-u` | По умолчанию Hydra перебирает пароли для первого логина, затем для второго. `-u` заставляет перебирать логины для каждого пароля. |

## Практические сценарии

### Аудит SSH-сервера

Проверка пароля для пользователя `admin` с использованием 4 потоков:

```bash
hydra -l admin -P /usr/share/wordlists/fasttrack.txt -t 4 -vV ssh://192.168.1.50
```

### Сложный аудит веб-форм (HTTP POST)

Для веб-форм требуется указать путь к скрипту, тело запроса и строку, указывающую на ошибку:

```bash
hydra -L users.txt -P pass.txt 192.168.1.10 http-post-form "/admin/login.php:user=^USER^&pass=^PASS^:F=Login failed"
```
- `^USER^` / `^PASS^` — плейсхолдеры для данных из списков.
- `F=Login failed` — префикс `F=` указывает, что наличие строки означает неудачу. Если используется `S=`, то наличие строки означает успех.
- Если форма использует Cookie или дополнительные заголовки:
```bash
hydra ... http-post-form "/index.php:u=^USER^&p=^PASS^:F=Error:H=Cookie: sessionid=123"
```

### Аудит баз данных (PostgreSQL)

```bash
hydra -L internal_users.txt -P common_pass.txt -s 5432 10.0.0.15 postgres
```

### Перебор RDP (Windows Remote Desktop)

```bash
hydra -l Administrator -P custom_wordlist.txt -t 1 rdp://192.168.1.100
```
*Примечание: для RDP рекомендуется использовать минимальное количество потоков (`-t 1`) из-за специфики протокола и возможной блокировки сессий.*

## Дополнительная информация

### Оптимизация производительности

1. **Количество потоков (`-t`):** Слишком высокое значение может привести к DoS-состоянию сервиса или срабатыванию систем защиты. Для SSH оптимально 4-8, для HTTP — 16-32 (в зависимости от канала).
2. **Таймауты (`-w`):** При работе через медленные каналы или прокси увеличьте время ожидания ответа (например, `-w 30`).
3. **Exit codes:** Hydra возвращает `0`, если найден хотя бы один пароль, и `1` в противном случае, что полезно для Bash-скриптов.

### Использование прокси

Для обхода ограничений по IP можно использовать переменные окружения:

```bash
# SOCKS5-прокси
export HYDRA_PROXY=socks5://127.0.0.1:9050
hydra -l admin -P pass.txt ssh://target.onion
```

### Методы защиты от атак Hydra

- **Аутентификация по ключам:** Полное отключение паролей для критических сервисов ([Настройка SSH](../../Linux/Security/ssh/server/ssh_hardening_best_practices.md)).
- **Fail2ban:** Автоматическое динамическое блокирование IP-адресов на уровне файрвола ([fail2ban](../../Linux/Security/Tools/fail2ban.md)).
- **MFA / 2FA:** Внедрение многофакторной аутентификации ([MFA: концепции](../Concepts/mfa_totp.md)).
- **Rate Limiting:** Ограничение количества запросов к API и формам входа на уровне Nginx или Ingress.
