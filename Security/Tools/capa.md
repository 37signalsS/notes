# Capa

## 1. Определения

**Capa** ([fireeye/capa](https://github.com/fireeye/capa)) — это инструмент от Mandiant (ранее FireEye) для выявления возможностей исполняемых файлов. Он помогает аналитикам быстро понять, что делает та или иная программа.

## 2. Основные концепции

* **Идентификация возможностей**: Определяет, что программа может делать (например, устанавливать службу, использовать HTTP, являться бэкдором).
* **Статический и динамический анализ**: Анализирует исполняемые файлы (PE, ELF, .NET) и может обрабатывать отчеты из песочниц (динамический анализ).
* **Сопоставление с ATT&CK**: Связывает обнаруженные возможности с тактиками и техниками из матрицы MITRE ATT&CK.

* **Язык**: Python.
* **Ключевая технология**: Анализ на основе правил. Правила пишутся в формате, похожем на YAML, и легко расширяются.
* **Интеграции**: Имеет плагины для IDA Pro и Ghidra, что позволяет проводить анализ непосредственно в среде реверс-инжиниринга.

## 3. Практические сценарии

Основной сценарий — быстрый анализ неизвестного исполняемого файла для получения общего представления о его поведении.

### Базовый анализ

```bash
# Проанализировать файл my_malware.exe
capa my_malware.exe
```

### Пример вывода

`capa` предоставляет структурированный отчет, в котором перечислены обнаруженные возможности, сгруппированные по пространствам имен и сопоставленные с техниками MITRE ATT&CK.

```
+------------------------+-------------------------------------------------------------
| ATT&CK Tactic          | ATT&CK Technique                                            
|------------------------+-------------------------------------------------------------
| DEFENSE EVASION        | Obfuscated Files or Information [T1027]                     
| DISCOVERY              | Query Registry [T1012]                                      
| EXECUTION              | Command and Scripting Interpreter: Windows Command Shell [T1059.003]
+------------------------+-------------------------------------------------------------

+------------------------+-------------------------------------------------------------
| CAPABILITY             | NAMESPACE                                                   
|------------------------+-------------------------------------------------------------
| run command            | host-interaction/cli                                        
| read registry value    | host-interaction/registry                                   
| create process         | host-interaction/process                                    
| check for sandbox      | anti-analysis/sandbox/vm-detection                          
| contain obfuscated data| data-manipulation/obfuscation                               
+------------------------+-------------------------------------------------------------
```

Этот вывод показывает, что программа может выполнять команды, работать с реестром, создавать процессы, а также содержит обфусцированные данные и пытается обнаружить песочницу.

## 4. Продвинутые детали

### Правила Capa

Сила `capa` заключается в его наборе правил, которые хранятся в [отдельном репозитории](https://github.com/mandiant/capa-rules). Правила написаны на языке, похожем на YAML, и описывают признаки для обнаружения той или иной возможности.

* **Структура правила**: Каждое правило содержит метаданные (имя, автор, описание) и секцию `features`, где с помощью логических операторов (`and`, `or`, `not`) описываются признаки.
* **Признаки**: Правила могут ссылаться на:
  * Вызовы API (`api: kernel32.CreateProcessA`)
  * Строки (`string: "cmd.exe"`)
  * Числовые константы (`number: 4`)
  * Байтовые последовательности (`bytes: 55 8B EC`)
  * Другие правила (`match: create process`)

### Создание собственных правил

Аналитики могут создавать собственные правила для обнаружения специфических техник или семейств вредоносного ПО, что делает `capa` гибким и расширяемым инструментом.
