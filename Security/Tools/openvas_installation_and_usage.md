# OpenVAS (GVM): Установка и использование на Ubuntu 22.04

**Greenbone Vulnerability Management (GVM)**, ранее известный как **OpenVAS**, — это мощный фреймворк с открытым исходным кодом для сканирования и управления уязвимостями. Он позволяет автоматизировать поиск проблем безопасности в сетевых узлах и веб-приложениях.

Это руководство описывает процесс установки GVM на Ubuntu 22.04 с использованием PPA (Personal Package Archive), что является наиболее простым и надежным способом.

## Системные требования

Для стабильной работы GVM, особенно в процессе синхронизации фидов, рекомендуется использовать машину со следующими характеристиками:

- **ОЗУ:** Минимум 4 ГБ, рекомендуется 8 ГБ или больше.
- **Дисковое пространство:** Минимум 20 ГБ, рекомендуется 60 ГБ свободного места для фидов и отчетов.
- **Процессор:** 2 или более ядер.

## Шаг 1: Подготовка системы

Перед началом установки убедитесь, что ваша система обновлена, и установите СУБД PostgreSQL, которую GVM использует для хранения данных.

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install postgresql -y
```

## Шаг 2: Установка GVM из PPA

Мы будем использовать PPA, поддерживаемый сообществом, для установки GVM.

1. **Добавьте PPA репозиторий:**

    ```bash
    sudo add-apt-repository ppa:mrazavi/gvm -y
    sudo apt update
    ```

2. **Установите GVM:**
    Эта команда установит все необходимые компоненты: Greenbone Vulnerability Manager (gvmd), сканер (ospd-openvas) и веб-интерфейс Greenbone Security Assistant (gsad).

    ```bash
    sudo apt install gvm -y
    ```

3. **Создайте каталог для Notus-сканера:**

    ```bash
    sudo mkdir -p /var/lib/notus
    sudo chown gvm:gvm /var/lib/notus
    ```

## Шаг 3: Синхронизация фидов (Feeds)

Это самый важный и длительный этап. GVM загрузит актуальные данные об уязвимостях (NVT), информацию о безопасности (CERT, SCAP) и другие данные. **Процесс может занять от 30 минут до нескольких часов.** Не прерывайте его.

Выполните команды синхронизации от имени системного пользователя `gvm`.

```bash
sudo -u gvm -g gvm greenbone-nvt-sync
sudo -u gvm -g gvm greenbone-feed-sync --type CERT
sudo -u gvm -g gvm greenbone-feed-sync --type SCAP
sudo -u gvm -g gvm greenbone-feed-sync --type GVMD_DATA
```

## Шаг 4: Настройка веб-интерфейса (GSA)

По умолчанию веб-интерфейс GSA может быть доступен только с локальной машины (`127.0.0.1`). Чтобы сделать его доступным по сети, отредактируйте файл конфигурации.

```bash
sudo nano /etc/default/gsad
```

Измените значение `GSAD_ADDRESS` на `0.0.0.0`, чтобы разрешить подключения со всех сетевых интерфейсов.

```
# /etc/default/gsad
GSAD_ADDRESS=0.0.0.0
```

Сохраните файл и закройте редактор.

## Шаг 5: Запуск и проверка служб

После завершения синхронизации и настройки перезапустите все службы GVM.

```bash
sudo systemctl restart gsad
sudo systemctl restart gvmd
sudo systemctl restart ospd-openvas
```

Проверьте, что все три службы успешно запустились и работают:

```bash
systemctl status gsad
systemctl status gvmd
systemctl status ospd-openvas
```

Вывод каждой команды должен содержать строку `active (running)`.

## Шаг 6: Первый вход и смена пароля

Теперь вы можете получить доступ к веб-интерфейсу GVM.

1. Откройте браузер и перейдите по адресу: `https://<IP_вашего_сервера>:9392`
    (Вам нужно будет принять предупреждение о самоподписанном SSL-сертификате).

2. Используйте учетные данные по умолчанию для входа:
    - **Пользователь:** `admin`
    - **Пароль:** `admin`

3. **Сразу же смените пароль!** Перейдите в `Administration` -> `Users`, нажмите на иконку редактирования пользователя `admin` и установите новый, сложный пароль.

4. Проверьте статус фидов в веб-интерфейсе: `Administration` -> `Feed Status`. Все фиды должны иметь статус `Current`. Если это не так, вернитесь к Шагу 3.

## Шаг 7: Проведение первого сканирования

Процесс сканирования в GVM состоит из двух основных этапов: определения цели и запуска задачи.

1. **Создание цели (Target):**
    - Перейдите в `Scans` -> `Targets`.
    - Нажмите на иконку "New Target" (синий значок со звездочкой).
    - **Name:** Дайте цели осмысленное имя (например, `My Web Server`).
    - **Hosts:** Введите IP-адрес или доменное имя хоста, который вы хотите просканировать.
    - Остальные настройки можно оставить по умолчанию. Нажмите `Save`.

2. **Создание и запуск задачи (Task):**
    - Перейдите в `Scans` -> `Tasks`.
    - Нажмите "New Task".
    - **Name:** Дайте задаче имя (например, `Scan Web Server Weekly`).
    - **Scan Target:** Выберите цель, созданную на предыдущем шаге.
    - **Scanner:** Оставьте `OpenVAS Default`.
    - **Scan Config:** Выберите профиль сканирования. `Full and fast` является хорошим выбором для начала.
    - Нажмите `Save`.

3. **Запуск сканирования:**
    - Вы вернетесь к списку задач. Найдите свою новую задачу и нажмите на кнопку "Start" (зеленый треугольник).
    - Статус задачи изменится на `Running`, и начнется процесс сканирования.

4. **Анализ результатов:**
    - После завершения сканирования (статус изменится на `Done`), нажмите на дату в колонке `Last Report`.
    - Вы увидите отчет со списком найденных уязвимостей, отсортированных по уровню критичности (Severity).
    - Нажав на уязвимость, вы получите подробное описание, возможные пути решения и ссылки на внешние ресурсы (CVE, CPE).

## Устранение неполадок

- **Службы не запускаются:** Проверьте логи с помощью `journalctl -u <имя_службы>`. Например, `journalctl -u gvmd`. Часто проблемы связаны с незавершенной синхронизацией фидов или проблемами с PostgreSQL.
- **Фиды не обновляются:** Убедитесь, что у сервера есть доступ в интернет и DNS работает корректно. Попробуйте запустить команды синхронизации вручную еще раз.
- **Веб-интерфейс недоступен:** Проверьте, что служба `gsad` запущена, и файрвол на сервере (например, `ufw` или `iptables`) не блокирует порт `9392`.
