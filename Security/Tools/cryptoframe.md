# CryptoFrame — стеганография зашифрованных данных в видео

## 1. Определения

**CryptoFrame** ([github.com/x011/CryptoFrame](https://github.com/x011/CryptoFrame)) — это консольный инструмент для скрытия текстовых сообщений внутри видеофайлов. Инструмент сочетает в себе методы стеганографии (LSB) и многослойного шифрования (AES-256 + RSA-4096), что обеспечивает как защиту содержимого, так и сокрытие самого факта передачи информации.

## 2. Основные концепции

### Принцип работы: LSB-стеганография в видео
Метод **LSB (Least Significant Bit — наименее значимый бит)** заключается в замене младшего бита цветовых каналов пикселей видеокадров битами скрываемого сообщения.
- **Процесс:** Видео разбивается на отдельные кадры, каждый из которых представляет собой матрицу пикселей (RGB). Биты зашифрованного сообщения распределяются по пикселям разных кадров.
- **Визуальная незаметность:** Изменение младшего бита приводит к ничтожному изменению цвета, которое невозможно заметить человеческим глазом при воспроизведении видео.

### Многослойная криптография
CryptoFrame использует агрессивную модель шифрования для защиты данных:
- **Данные:** Содержимое шифруется с использованием **семи слоев AES-256-CBC**.
- **Ключи:** Симметричные ключи AES шифруются с помощью **RSA-4096**. Это гарантирует, что даже при успешном извлечении данных из видео их расшифровка без приватного RSA-ключа будет практически невозможна.

### Требование к кодекам (Lossless)
Критическим условием работы инструмента является использование кодеков сжатия **без потерь (lossless)**.
- **Lossless (FFV1, HFYU):** Сохраняют значения пикселей в исходном виде, что позволяет полностью восстановить внедренные LSB-данные.
- **Lossy (H.264, H.265, VP9):** Алгоритмы сжатия с потерями оптимизируют видео, отбрасывая «маловажную» информацию, включая младшие биты. Это приводит к необратимому уничтожению скрытых данных.

## 3. Практические сценарии

### Установка
Для работы требуется Python 3.x и установленный в системе OpenSSL.

```bash
git clone https://github.com/x011/CryptoFrame.git
cd CryptoFrame
pip install -r requirements.txt
```

### Подготовка ключей (RSA-4096)
Генерация ключей выполняется с помощью стандартных средств OpenSSL:

```bash
# Создание приватного ключа
openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:4096

# Извлечение публичного ключа
openssl rsa -pubout -in private_key.pem -out public_key.pem
```

### Внедрение сообщения (Hide)
При внедрении сообщения на выходе всегда получается файл в контейнере MKV, AVI или MOV с использованием lossless-кодека.

```bash
# Внедрение прямой строки
python CryptoFrame.py hide input.mp4 \
  --output secret_video.mkv \
  --message "Top Secret Message 2026" \
  --codec FFV1 \
  --public_key public_key.pem

# Внедрение содержимого текстового файла
python CryptoFrame.py hide input.mp4 \
  --output secret_video.mkv \
  --message secret.txt \
  --codec HFYU \
  --public_key public_key.pem
```

### Извлечение сообщения (Unhide)
Для восстановления данных необходим приватный RSA-ключ.

```bash
python CryptoFrame.py unhide secret_video.mkv --private_key private_key.pem
```

## 4. Дополнительная информация

### Сравнение выходных форматов
| Кодек | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **FFV1** | Высокая степень сжатия (для lossless), стандартизирован для архивации. | Требует больше вычислительных ресурсов. |
| **HFYU** | Очень высокая скорость обработки, максимальная совместимость. | Огромный размер выходного файла. |

### Ограничения и риски
- **Аномальный размер:** Видео в формате lossless весит в 10–50 раз больше, чем сжатое H.264. Это является главным демаскирующим признаком при передаче через интернет.
- **Чувствительность к транскодированию:** Любая попытка видеохостинга (например, YouTube) или мессенджера перекодировать видео для экономии трафика мгновенно уничтожит скрытое сообщение.
- **Стеганализ:** Несмотря на псевдослучайное распределение, современные методы статистического анализа (RS-анализ) могут выявить аномалии в распределении шума младших битов.
