# File Hider: Скрытие файлов через логическую невидимость

## Определения

**File Hider** ([github.com/x011/File_Hider](https://github.com/x011/File_Hider)) — специализированный инструмент для внедрения одного файла («гостевого») внутрь другого («хоста») с использованием уникальных маркеров-идентификаторов.

Инструмент формально относится к [стеганографии](../Concepts/steganography.md), однако использует метод **логической невидимости** вместо физической модификации данных контейнера (как в LSB или DCT). Данные внедряются как структурированный блок, который большинство стандартных приложений-парсеров игнорирует, считывая только оригинальный контент хост-файла.

## Основные концепции

### Многослойная архитектура защиты

File Hider обеспечивает высокую стойкость скрытых данных за счет комбинации симметричного и асимметричного шифрования:

1.  **Подготовка:** Скрываемый файл сжимается для уменьшения объема и снижения энтропии, что затрудняет статистическое обнаружение.
2.  **Симметричное шифрование:** Данные проходят 7 последовательных слоев шифрования алгоритмом **AES-256-CBC**. Для каждого слоя генерируется уникальный сессионный ключ.
3.  **Асимметричная защита ключей:** Результирующий набор ключей шифруется с помощью алгоритма **RSA** (поддерживаются ключи до 4096 бит). Это позволяет безопасно передавать файл-хост, так как извлечь данные сможет только обладатель соответствующего закрытого ключа.
4.  **Внедрение:** Зашифрованный массив данных кодируется в Base64 и помещается между двумя уникальными строковыми маркерами в конец или в свободные области файла-хоста.

### Ключевые особенности

- **Агностичность к формату:** В качестве хоста может выступать любой файл (исполняемый файл `.exe`, документ `.docx`, изображение `.jpg`, архив `.zip`).
- **Отсутствие артефактов стеганоанализа:** Поскольку биты оригинального изображения/аудио не меняются, классические методы стеганализа (анализ младших бит, LSB) не фиксируют изменений.
- **Целостность данных:** Инструмент гарантирует 100% извлечение байт-в-байт за счет использования Base64 и жестких маркеров.

## Практические сценарии

### Установка и зависимости

Инструмент написан на Python 3 и требует установки криптографических библиотек.

```bash
# Установка необходимых зависимостей
pip install pycryptodome tk

# Клонирование репозитория
git clone https://github.com/x011/File_Hider.git
cd File_Hider
```

### Внедрение файла (Скрытие)

При запуске утилиты в GUI или CLI режиме необходимо указать файл-хост, скрываемый файл и публичный ключ RSA.

```bash
# Концептуальный пример запуска (зависит от версии реализации)
python3 file_hider.py --hide --host image.jpg --guest secret.zip --key public.pem
```

### Извлечение данных

Для извлечения требуется файл-хост с внедренным контентом и закрытый ключ RSA.

```bash
python3 file_hider.py --extract --host image.jpg --key private.pem --out recovered_secret.zip
```

## Дополнительная информация

### Сравнение с классическими методами

| Характеристика | LSB/DCT Стеганография | File Hider (Маркеры) |
| :--- | :--- | :--- |
| **Место данных** | Внутри младших бит контента | Вне основной логики парсинга (Appending/Injection) |
| **Риск искажения** | Может вызвать шум или артефакты | Не искажает оригинальный контент |
| **Детектирование** | Статистический анализ (RS-анализ) | Поиск сигнатур маркеров и аномальной энтропии |
| **Объем** | Сильно ограничен (1-3% от контейнера) | Ограничен только здравым смыслом (Base64 +33%) |

### Методы обнаружения и форензика

Хотя File Hider обходит классический стеганализ, он уязвим для других методов поиска:

1.  **Сигнатурный анализ:** Поиск предустановленных или пользовательских строковых маркеров, обрамляющих Base64-блок.
2.  **Анализ структуры файла:** Детектирование данных за пределами EOF (End Of File) или в нестандартных секциях (например, после секции `.resource` в PE-файлах).
3.  **Энтропийный анализ:** Резкий скачок энтропии в конце файла (характерный для зашифрованных данных) является явным признаком наличия скрытых объектов.
