# Поиск руткитов в Linux: chkrootkit

**Актуально для:** chkrootkit 0.59

## Определения

- **Rootkit** — набор программ, скрывающий присутствие злоумышленника в системе: маскирует процессы, файлы, сетевые соединения, перехватывает системные вызовы.
- **chkrootkit** — локальный сканер признаков руткитов: shell-скрипт-обёртка плюс набор компилируемых C-утилит. Проверяет системные бинарники на модификацию, удаления записей из логов входа, интерфейсы в promiscuous mode и признаки LKM-троянов. Распространяется под GPL, официальный дом — [chkrootkit.org](https://www.chkrootkit.org); автор — Nelson Murilo, соавтор — Klaus Steding-Jessen.
- **LKM-троян (LKM trojan)** — вредоносный загружаемый модуль ядра, перехватывающий системные вызовы (обычно `kill` и `getdents`) для маскировки процессов, файлов и самого себя.
- **chkproc** — тест chkrootkit, сравнивающий вывод `ps` с содержимым `/proc`; расхождение (процесс есть в ядре, но отсутствует в `ps`) — признак LKM-трояна.
- **Expert mode (`-x`)** — режим, в котором тесты выводят дополнительную информацию (например, подозрительные строки в бинарниках); окончательная интерпретация остаётся за администратором.

## Основные концепции

### Как работает chkrootkit

chkrootkit — shell-скрипт, вызывающий вспомогательные C-утилиты (ставятся в `/usr/lib/chkrootkit`):

| Утилита | Что проверяет |
| :--- | :--- |
| `chkrootkit` (скрипт) | проверка системных бинарников на известные сигнатуры руткитов (например, строка `/dev/ptyp` в трояном `ps`) |
| `chkproc.c` | признаки LKM-троянов: сравнение вывода `ps` с `/proc` |
| `chkdirs.c` | признаки LKM-троянов: сравнение `readdir` с `/proc` |
| `ifpromisc.c` | сетевой интерфейс в promiscuous mode (сниффер) |
| `chklastlog.c` / `chkwtmp.c` / `chkutmp.c` | удаления записей из `lastlog` / `wtmp` / `utmp` (стирание следов входа) |
| `check_wtmpx.c` | то же для `wtmpx` (только Solaris) |
| `strings.c` | быстрая замена `strings` |

Проверяемые системные команды: `netstat`, `named`, `passwd`, `pidof`, `pop2`, `pop3`, `ps`, `pstree`, `rpcinfo`, `rlogind`, `rshd`, `slogin`, `sendmail`, `sshd`, `syslogd`, `tar`, `tcpd`, `tcpdump`, `top`, `telnetd`, `timed`, `traceroute`, `vdir`, `w`, `write`, `nologin` (0.59+). Актуальный список детектируемых руткитов, червей и LKM (75 позиций, от `lrk3`/`t0rn`/`Adore LKM` до `Mumblehard`, `Linux.Xor.DDoS`, `Umbreon`, `BPFDoor`, `Kovid`, `Syslogk`) — на сайте проекта.

**Модель доверия.** chkrootkit работает, вызывая системные команды (`awk`, `cut`, `echo`, `egrep`, `find`, `head`, `id`, `ls`, `netstat`, `ps`, `strings`, `sed`, `uname`). На скомпрометированной системе они могут быть подменены руткитом, и результаты проверки станут ненадёжными. Ключи `-p` (путь к доверенным бинарникам) и `-r` (альтернативный корень) решают эту проблему — см. раздел «Устранение неполадок».

### Механизм обнаружения скрытых процессов

Тест `chkproc` — ключевое отличие chkrootkit от rkhunter в конфигурации по умолчанию. Он сравнивает список процессов из вывода `ps` с содержимым `/proc`: процесс, присутствующий в ядре, но отсутствующий в выводе `ps`, сигнализирует о LKM-трояне (руткит перехватил системный вызов, скрывающий процесс). Тест включён по умолчанию — в отличие от теста `hidden_procs` в rkhunter, который в поставляемом конфиге отключён.

Ограничение: на серверах с большим числом короткоживущих процессов `chkproc` может давать ложные срабатывания — процесс, созданный или убитый в момент сравнения, будет указан как подозрительный.

## Установка и настройка

```bash
# Debian / Ubuntu
sudo apt install chkrootkit
# → result: Setting up chkrootkit (0.58b-5+b7) ...

# Fedora
sudo dnf install chkrootkit

# RHEL / CentOS — проверьте наличие в подключённых репозиториях
# (dnf search chkrootkit); при отсутствии — сборка из исходников
# (tarball с chkrootkit.org: make в каталоге с исходниками)
```

Пакеты дистрибутивов могут отставать от upstream-версии (Debian stable — 0.58b, Fedora — 0.58; upstream — 0.59). Нововведения 0.59:

- **Process executed from memory** — проверка `/proc/*/exe` на симлинки вида `/memfd:.*(deleted)`, обнаруживающие программы, загруженные в анонимную память через `memfd_create(2)` (техника fileless-мalware); выводит `INFECTED: Possible process running from memory:`.
- **`nologin`** — новая команда в списке проверяемых (`TROJAN`): ищет строку `/bin/*sh` в бинарнике `nologin`, признак встраивания backdoor-оболочки в эту утилиту.
- **Bootkitty (UEFI bootkit)** — в expert mode проверяет наличие `LD_PRELOAD` в конфигурации GRUB (`/boot/grub/grub.cfg`, `/etc/grub.d/*`), техника, используемой UEFI-буткитом для инъекции кода в загрузку.
- **XZ Backdoor** — упомянуто в changelog, но конкретных проверок в исходном коде 0.59 не идентифицировано (поиск по исходным файлам не выявил кода, сопоставимого с обнаружением backdoor в `xz-utils`/CVE-2024-3094).

Часть тестов (`chkproc`, проверка `lastlog`/`wtmp`) требует прав root — запускайте `sudo chkrootkit`.

### Конфигурация и автоматизация

chkrootkit не имеет собственного конфигурационного файла: все параметры задаются через командную строку. Дистрибутивы добавляют автоматизацию поверх пакета.

**Debian / Ubuntu (0.58b+):** пакет устанавливает `chkrootkit-daily` — systemd-таймер (`chkrootkit.timer` + `chkrootkit.service`) или cron-скрипт (`/etc/cron.daily/chkrootkit`), который ежедневно запускает chkrootkit в quiet-режиме и отправляет результаты по почте. Параметры задаются в `/etc/chkrootkit/chkrootkit.conf`:

| Переменная | По умолчанию | Назначение |
| :--- | :--- | :--- |
| `RUN_DAILY` | `false` | запускать ли ежедневную проверку |
| `RUN_DAILY_OPTS` | `-q` | опции для ежедневного запуска |
| `DIFF_MODE` | `false` | сравнивать текущий лог с эталоном (`log.expected`) |
| `REPORT_EMAIL` / `MAILTO` | `root` | получатель отчёта |

Журналы: `/var/log/chkrootkit/chkrootkit.log`, `/var/log/chkrootkit/log.today`, `/var/log/chkrootkit/log.expected` (при включённом `DIFF_MODE`).

Проверить статус таймера:

```bash
systemctl list-unit-files 'chkrootkit*' --no-pager
systemctl list-timers 'chkrootkit*' --all --no-pager
```

Другие дистрибутивы (RHEL, Fedora, Arch) не включают `chkrootkit-daily` — настраивают cron вручную:

```bash
# /etc/cron.daily/chkrootkit
#!/bin/sh
/usr/sbin/chkrootkit -q
```

## Практические сценарии

### Базовая проверка

```bash
sudo chkrootkit                  # все тесты
sudo chkrootkit -q               # только сообщения о заражении
sudo chkrootkit ps ls sniffer    # только указанные тесты
```

### Экспертный режим

```bash
sudo chkrootkit -x | more        # развёрнутый вывод всех тестов
sudo chkrootkit -x | egrep '^/'  # только пути внутри системных команд
```

В expert mode администратор сам анализирует подозрительные строки в бинарниках — автоматического вердикта нет.

### Обнаружение LKM-руткита Diamorphine (сравнение с rkhunter)

Практический сценарий: реальный LKM-руткит Diamorphine собирается, маскируется и обнаруживается средствами chkrootkit и rkhunter — наглядно показывая, почему инструменты комплементарны.

**Diamorphine** ([m0nad/Diamorphine](https://github.com/m0nad/Diamorphine)) — LKM-руткит для ядер Linux 2.6.x–6.x (x86/x86_64, ARM64). Возможности:

- при загрузке модуль невидим;
- скрытие/показ любого процесса — сигнал `31` (`SIGINVIS`);
- переключение видимости самого модуля — сигнал `63` любому pid (`SIGMODINVIS`);
- выдача прав root любому пользователю — сигнал `64` (`SIGSUPER`);
- скрытие файлов и каталогов с префиксом `diamorphine_secret` (`MAGIC_PREFIX`).

**Prerequisites** (модуль ядра — нужны заголовки ядра и компилятор; набор пакетов различается в дистрибутивах):

```bash
# RHEL / CentOS
sudo dnf install kernel-devel gcc make
# Debian / Ubuntu
sudo apt install linux-headers-$(uname -r) build-essential
```

**Ход демонстрации:**

1. Сборка от обычного пользователя — сборка ПО под суперпользователем плохая практика с точки зрения ИБ:

```bash
git clone https://github.com/m0nad/Diamorphine
cd Diamorphine
make
```

2. Загрузка модуля (нужны права root; у модуля нет параметров):

```bash
sudo insmod diamorphine.ko
```

3. Модуль скрыт — `lsmod` его не показывает:

```bash
lsmod | grep diamorphine
# → result: (пустой вывод)
```

4. Переключение видимости модуля — сигнал 63 любому процессу (даже несуществующему):

```bash
kill -63 1
lsmod | grep diamorphine
# → result: diamorphine  13155  0
kill -63 1   # повторный сигнал — модуль снова скрыт
```

5. Скрытие процесса (в демо — системный cron, PID 408):

```bash
ps aux | grep cron    # процесс виден
kill -31 408          # процесс исчезает из вывода ps
ps aux | grep cron
# → result: (пустой вывод, кроме строки самого grep)
kill -31 408          # повторный сигнал — процесс снова виден
```

6. **rkhunter в конфигурации по умолчанию ничего не находит:**

```bash
sudo rkhunter --check --skip-keypress --report-warnings-only
# → result: предупреждений нет
```

Причины (по исходному коду rkhunter 1.4.6):

- скрытый процесс не обнаруживается, потому что тест `hidden_procs` (сравнение `ps` с `/proc` через утилиту `unhide`) отключён в поставляемом конфиге: `DISABLE_TESTS="suspscan hidden_ports hidden_procs deleted_files packet_cap_apps"`;
- скрытый модуль не попадает в проверку `loaded_modules`: при маскировке Diamorphine делает только `list_del(&THIS_MODULE->list)` — модуль исчезает из `lsmod` и `/proc/modules` согласованно, а проверка известных имён (`LKM_BADNAMES`, включая `diamorphine.ko`) ищет файлы в дереве модулей, а не в выводе `lsmod`.

7. После переключения видимости модуля (`kill -63 <pid>`) rkhunter обнаруживает руткит по сигнатуре — в выводе появляется предупреждение о нахождении «Diamorphine LKM». Проверка ищет символы ядра `diamorphine`, `module_hide`, `module_hidden`, `is_invisible`, `hacked_getdents`, `hacked_kill` в файле символов (`/proc/ksyms` → `/proc/kallsyms` → `/boot/System.map-$(uname -r)`) и имя файла `diamorphine.ko`. Поскольку при маскировке символы остаются в `/proc/kallsyms`, результат символной проверки зависит от конкретной системы — в демонстрации обнаружение произошло после переключения видимости модуля.

8. **chkrootkit обнаруживает скрытый процесс:**

```bash
sudo chkrootkit
# → result: в выводе — процесс, скрытый от вывода ps
#           (в демо — один процесс, PID 408); это интерпретируется
#           как признак LKM-трояна / руткита
```

Тест `chkproc` находит PID, присутствующий в ядре, но отсутствующий в выводе `ps`.

9. В расширенном режиме chkrootkit выводит длинный лог проверки, в конце которого — информация о PID (в демо — 408), отсутствующем в выводе `ps`:

```bash
sudo chkrootkit -x
```

**Вывод:** инструменты комплементарны и их имеет смысл настраивать и использовать на системе одновременно. rkhunter силён в сигнатурах, свойствах файлов и проверке конфигурации, но в конфигурации по умолчанию не проверяет скрытые процессы; chkrootkit по умолчанию ловит скрытые процессы, но не ведёт базу свойств файлов. LKM-руткит, пропущенный rkhunter (скрытый модуль + скрытый процесс), обнаруживается chkrootkit.

**Очистка** (модуль нужно сначала сделать видимым):

```bash
kill -63 0          # сигнал 63 pid 0 — модуль становится видимым
sudo rmmod diamorphine
```

## Операции и команды

| Ключ | Назначение |
| :--- | :--- |
| `-h` | справка |
| `-V` | версия |
| `-l` | список доступных тестов |
| `-d` | debug-режим: все шаги, включая `set -x` |
| `-q` | quiet mode: только сообщения о заражении |
| `-x` | expert mode: дополнительный вывод тестов |
| `-e "FILE1 [FILE2 ...]"` | исключить файлы из результатов части тестов; ключ можно повторять несколько раз |
| `-s REGEXP` | фильтр для теста `sniffer`: исключает из вывода строки, соответствующие регулярному выражению (egrep); применяется к выводу теста `ifpromisc` |
| `-r dir` | использовать `dir` как корневой каталог (диск проверяемой системы смонтирован в доверенной) |
| `-p dir1:dir2:...:dirN` | путь к доверенным бинарникам вместо системных; можно указывать несколько путей через `:` |
| `-n` | пропускать NFS-монтированные каталоги |
| `-T FSTYPE` | пропускать файловые системы указанного типа (через `find -fstype`) |

Ключи нельзя комбинировать: пишите `-q -x`, а не `-qx`.

## Устранение неполадок

### Коды вывода

chkrootkit выводит следующие сообщения (кроме режимов `-x` и `-q`). Статусы кодируются числовыми кодами в исходном коде (`INFECTED=0`, `NOT_INFECTED=1`, `NOT_TESTED=2`, `NOT_FOUND=3`, `VULNERABLE_BUT_DISABLED=4`):

| Сообщение | Код | Значение |
| :--- | :--- | :--- |
| `INFECTED` | 0 | тест обнаружил команду, вероятно, изменённую известным руткитом |
| `not infected` | 1 | сигнатуры руткитов не найдены |
| `not tested` | 2 | тест не выполнен (OS-специфичный, внешняя утилита недоступна, или заданы опции `-r`/`-n`) |
| `not found` | 3 | проверяемая команда отсутствует в системе |
| `infected but disabled` | 4 | команда инфицирована, но не используется (not running or commented in `inetd.conf`) |

**Важно:** chkrootkit не использует код возврата скрипта для сигнализации заражения. При использовании в cron/monitoring следует парсить вывод на наличие `INFECTED`:

```bash
# в cron-скрипте или мониторинге:
sudo chkrootkit -q 2>&1 | grep INFECTED && echo "ALERT: rootkit detected"
```

### Ложные срабатывания chkproc

Симптом: `chkproc` указывает на PID как подозрительный. Причина: на серверах с большим числом короткоживущих процессов процесс может быть создан или убит в момент сравнения вывода `ps` с `/proc`. Диагностика: повторный запуск; ручная проверка PID (`ls /proc/<PID>`, `ps -p <PID>`).

### Подменённые системные утилиты

chkrootkit вызывает системные `ps`, `ls`, `netstat` и др. Если они подменены руткитом, результаты ненадёжны. Решения:

```bash
sudo chkrootkit -p /cdrom/bin   # бинарники с доверенного носителя
sudo chkrootkit -r /mnt         # диск проверяемой системы смонтирован в доверенной
```

### Ложные срабатывания теста `sniffer`

Симптом: тест `sniffer` (утилита `ifpromisc`) помечает обычные сетевые менеджеры как packet sniffer. Это происходит потому, что `systemd-networkd`, `NetworkManager` и `wpa_supplicant` используют promiscuous mode для перехвата трафика. Решение — фильтр `-s`:

```bash
sudo chkrootkit -s '(systemd-networkd|NetworkManager|wpa_supplicant)'
```

Этот регулярный фильтр (egrep) применяется к каждой строке вывода теста `ifpromisc`. Дополнительные ложные срабатывания описаны в `/usr/share/doc/chkrootkit/README.FALSE-POSITIVES`.

## Лучшие практики

- **Комбинируйте с rkhunter:** chkrootkit по умолчанию ловит скрытые процессы (`chkproc`), rkhunter — сигнатуры, свойства файлов и конфигурацию; оба сигнатурные и дополняют, а не заменяют друг друга (см. [rkhunter](./rkhunter.md)).
- **Доверенные бинарники:** при подозрении на компрометацию запускайте с `-p`/`-r` с доверенного носителя.
- **Регулярность:** запуск по cron (Debian/Ubuntu — `chkrootkit-daily` из `/etc/chkrootkit/chkrootkit.conf`, см. «Конфигурация и автоматизация»); каждое сообщение о заражении расследуйте, а не игнорируйте.
- **Границы возможностей:** ни chkrootkit, ни rkhunter не обнаруживают современные eBPF-руткиты — для них используйте [ghostscan](./ghostscan.md); для мониторинга в реальном времени — [Falco](./falco.md) и [Wazuh](./wazuh.md).
