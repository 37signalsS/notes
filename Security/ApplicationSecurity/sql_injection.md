# SQL-инъекции

## 1. Определения

**SQL-инъекция (SQLi)** — это один из самых старых и опасных видов атак на веб-приложения, который заключается во внедрении вредоносного SQL-кода в запрос, отправляемый приложением в базу данных.

Успешная атака может позволить злоумышленнику обойти аутентификацию, получить, изменить или удалить данные, а в некоторых случаях — выполнить команды на уровне операционной системы.

## 2. Основные концепции

Атака эксплуатирует недостаточную обработку пользовательского ввода, который напрямую вставляется в SQL-запрос.

Рассмотрим типичный небезопасный код для проверки логина и пароля:
```php
$sql = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";
```

Если злоумышленник введет в поле имени пользователя строку `' OR '1'='1`, то итоговый SQL-запрос превратится в:
```sql
SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '...';
```
Условие `OR '1'='1'` всегда истинно, что позволяет обойти проверку пароля и получить доступ.

## 3. Практические сценарии

Основная стратегия защиты — никогда не доверять пользовательскому вводу и всегда отделять данные от исполняемого кода.

### Подготовленные выражения (Prepared Statements)
Это самый надежный метод защиты. SQL-запрос отправляется в базу данных с "плейсхолдерами" (`?` или `:name`), а данные передаются отдельно.

**Пример (Python с `psycopg2` для PostgreSQL):**
```python
# НЕПРАВИЛЬНО (уязвимо)
cursor.execute(f"SELECT * FROM users WHERE username = '{username}'")

# ПРАВИЛЬНО (безопасно)
cursor.execute("SELECT * FROM users WHERE username = %s", (username,))
```

## 4. Дополнительная информация

### Другие методы защиты

- **Валидация и очистка ввода (Input Validation & Sanitization)**
    - **Валидация:** Проверяйте, что вводимые данные соответствуют ожидаемому формату (например, ID — это число).
    - **Очистка (Sanitization):** Экранируйте специальные символы. Этот метод менее надежен, чем подготовленные выражения.

- **Принцип наименьших привилегий (Principle of Least Privilege)**
  Пользователь базы данных, от имени которого работает веб-приложение, должен иметь только минимально необходимые права (например, только `SELECT` к определенным таблицам). Это не предотвратит инъекцию, но ограничит ее последствия.
