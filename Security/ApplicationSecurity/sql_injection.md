# SQL-инъекции (SQL Injection)

**Reliability Score: 10** (SSoT, соответствует стандартам OWASP Top 10:2021 и актуальным практикам безопасной разработки)

## Определение

**SQL-инъекция (SQLi)** — это тип атаки на веб-приложения, при которой злоумышленник внедряет вредоносный SQL-код в запрос к базе данных через входные данные приложения. Если приложение недостаточно очищает ввод или неправильно формирует запрос, база данных может исполнить этот код как часть легитимной команды.

**Последствия успешной атаки:**
- Полная компрометация данных (кража личной информации, паролей, финансовых данных).
- Обход механизмов аутентификации и авторизации.
- Несанкционированное изменение или удаление информации (нарушение целостности).
- В некоторых случаях — выполнение команд на уровне операционной системы (RCE) через функции СУБД (например, `xp_cmdshell` в MSSQL).

## Классификация типов SQL-инъекций

| Тип | Механизм | Особенности |
| :--- | :--- | :--- |
| **In-band (Классическая)** | Тот же канал используется для атаки и получения результата. | Самый быстрый метод. Включает **Error-based** (через сообщения об ошибках) и **UNION-based** (объединение результатов). |
| **Inferential (Blind / Слепая)** | Ответ приложения не содержит данных напрямую, но меняется в зависимости от условий. | **Boolean-based** (ответ True/False) или **Time-based** (задержка ответа через `SLEEP()`). |
| **Second-order (Второго порядка)** | Нагрузка сохраняется в БД и срабатывает позже при другом запросе. | Трудно обнаружить сканерами, так как инъекция "спит" до обращения к сохраненным данным. |
| **Out-of-band (OOB)** | Данные выводятся через внешний канал (DNS-запрос, HTTP-запрос от СУБД). | Применяется, когда другие каналы вывода заблокированы, но СУБД имеет доступ вовне. |

## Механизм атаки и примеры

### Уязвимый код (Конкатенация строк)

Проблема возникает, когда ввод пользователя напрямую склеивается со строкой запроса:

```php
// PHP (УЯЗВИМО)
$query = "SELECT * FROM users WHERE username = '" . $_POST['user'] . "'";
```

Если пользователь введет `' OR '1'='1`, запрос превратится в:
`SELECT * FROM users WHERE username = '' OR '1'='1'` — условие всегда истинно, и атакующий авторизуется без пароля.

### Специфика популярных СУБД

1.  **MySQL / MariaDB:** Использование комментариев `#` или `-- ` для отсечения остатка запроса.
    - `admin' #`
2.  **PostgreSQL:** Поддержка "склеенных" запросов через `;`.
    - `'; DROP TABLE logs; --`
3.  **MSSQL:** Выполнение системных процедур.
    - `'; EXEC xp_cmdshell 'powershell ...'; --`
4.  **Oracle:** Работа с системными таблицами `DUAL` и `ALL_TABLES`.
    - `' UNION SELECT username, password FROM users --`

## Методы защиты

### 1. Подготовленные выражения (Prepared Statements)

**Это основной и наиболее надежный метод защиты.** Код запроса и данные разделяются на уровне протокола СУБД. Плейсхолдеры (`?` или `:name`) гарантируют, что ввод всегда будет трактоваться как литерал, а не как команда.

**Python (библиотека `psycopg2` для PostgreSQL):**
```python
# ПРАВИЛЬНО
cursor.execute("SELECT * FROM users WHERE email = %s", (user_email,))
```

**Java (Spring Data JPA / Hibernate):**
```java
// Spring Data JPA автоматически использует Prepared Statements
@Query("SELECT u FROM User u WHERE u.email = :email")
User findByEmail(@Param("email") String email);
```

**Go (`database/sql`):**
```go
// ПРАВИЛЬНО
rows, err := db.Query("SELECT id FROM users WHERE age > ?", minAge)
```

### 2. Использование ORM (Object-Relational Mapping)

Современные ORM (SQLAlchemy, Django ORM, GORM, Eloquent) по умолчанию используют параметризованные запросы. 

**Критическая ошибка:** использование "сырых" (raw) запросов внутри ORM без параметров:
```python
# ОПАСНО (Django)
User.objects.raw("SELECT * FROM users WHERE name = %s" % user_name) 

# БЕЗОПАСНО
User.objects.raw("SELECT * FROM users WHERE name = %s", [user_name])
```

### 3. Принцип наименьших привилегий

Учетная запись, от которой приложение подключается к БД, должна иметь только необходимые права:
- Запрет на `DROP`, `TRUNCATE`, `ALTER`.
- Доступ только к конкретным таблицам/схемам.
- Отключение функций выполнения команд ОС (`xp_cmdshell` и др.).
- Ограничение доступа к системным каталогам (напр. `pg_authid`).

### 4. Валидация и санитизация

- **Allowlisting:** Если нужно передать имя таблицы или колонки (которые нельзя параметризовать), используйте белый список разрешенных имен.
- **Типизация:** Приведение ввода к ожидаемому типу (напр. `int(user_id)`).

## Инструменты анализа и защиты

| Инструмент | Категория | Назначение |
| :--- | :--- | :--- |
| **sqlmap** | DAST / Exploitation | Автоматизированный поиск и эксплуатация SQLi-уязвимостей. |
| **Semgrep / SonarQube** | SAST | Статический анализ кода на наличие опасной конкатенации строк в запросах. |
| **OWASP ZAP / Burp Suite** | DAST | Сканирование работающего приложения на наличие инъекций. |
| **ModSecurity (WAF)** | Runtime Protection | Блокировка запросов, содержащих SQL-инъекции, по сигнатурам. |

## Связанные уязвимости

- **NoSQL Injection:** Аналогичная атака на нереляционные БД (MongoDB, Redis). Вместо SQL внедряются операторы фильтрации (напр. `{$gt: ""}`).
- **LDAP Injection:** Инъекция в запросы к каталогам.
- **OS Command Injection:** Внедрение команд в системные вызовы через СУБД.

### WAF как виртуальный патч

Если уязвимость обнаружена в "боевой" среде, а исправление кода требует времени, WAF может временно блокировать попытки эксплуатации:

```apache
# Пример правила ModSecurity для блокировки типичных SQL-сигнатур
SecRule REQUEST_COOKIES|ARGS|XML:/* "@detectSQLi" \
    "id:942100,phase:2,deny,status:403,msg:'SQL Injection Attack Detected'"
```
