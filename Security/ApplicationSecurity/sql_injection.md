# SQL-инъекции: Понимание и методы защиты

**SQL (Structured Query Language)** — это декларативный язык со строгими синтаксическими правилами, используемый для управления реляционными базами данных. SQL-инъекция (SQLi) — это один из самых старых и опасных видов атак на веб-приложения, который заключается во внедрении вредоносного SQL-кода в запрос, отправляемый приложением в базу данных.

Успешная SQL-инъекция может позволить злоумышленнику обойти аутентификацию, получить, изменить или удалить данные, а в некоторых случаях — выполнить команды на уровне операционной системы.

---

## Как работает SQL-инъекция?

Рассмотрим типичный пример небезопасного кода, который проверяет логин и пароль пользователя.

**Небезопасный код (например, на PHP/Python):**
```php
$username = $_POST['username'];
$password = $_POST['password'];

$sql = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";
// Выполнение запроса...
```

Злоумышленник может ввести в поле имени пользователя следующую строку:
`' OR '1'='1`

В результате SQL-запрос превратится в:
```sql
SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '...';
```
Условие `OR '1'='1'` всегда истинно, что позволяет обойти проверку пароля и получить доступ к данным первого пользователя в таблице.

## Методы защиты

Основная стратегия защиты — никогда не доверять пользовательскому вводу и всегда отделять данные от исполняемого кода.

### 1. Подготовленные выражения (Prepared Statements)

Это самый надежный метод защиты. Суть в том, что SQL-запрос отправляется в базу данных с "плейсхолдерами" (например, `?` или `:name`) вместо реальных данных. Затем данные отправляются отдельно. База данных обрабатывает шаблон и данные раздельно, что делает невозможным внедрение исполняемого кода.

**Пример (Python с `psycopg2` для PostgreSQL):**
```python
# НЕПРАВИЛЬНО (уязвимо)
cursor.execute(f"SELECT * FROM users WHERE username = '{username}'")

# ПРАВИЛЬНО (безопасно)
cursor.execute("SELECT * FROM users WHERE username = %s", (username,))
```

### 2. Валидация и очистка ввода (Input Validation & Sanitization)

-   **Валидация:** Проверяйте, что вводимые данные соответствуют ожидаемому формату (например, что ID — это число, а email — валидный адрес).
-   **Очистка (Sanitization):** Экранируйте специальные символы (например, кавычки) перед тем, как вставлять их в запрос. Этот метод менее надежен, чем подготовленные выражения, и его легко реализовать с ошибками. Используйте его только в крайнем случае.

### 3. Принцип наименьших привилегий (Principle of Least Privilege)

Пользователь базы данных, от имени которого работает веб-приложение, должен иметь только те права, которые ему абсолютно необходимы. Например, если приложению нужен только доступ на чтение к определенным таблицам, не давайте ему права на запись (`INSERT`, `UPDATE`, `DELETE`) или выполнение административных команд (`DROP TABLE`).

Это не предотвратит саму инъекцию, но значительно ограничит ущерб, который может нанести злоумышленник.
