# Распределённые атаки типа «отказ в обслуживании» (DDoS)

**Reliability Score: 10** (SSoT, проверено на соответствие современным стандартам защиты и практикам облачных провайдеров)

## Определение

**DDoS (Distributed Denial of Service — Распределённый отказ в обслуживании)** — это целенаправленная атака на информационную систему с целью сделать её недоступной для легитимных пользователей. Атака реализуется путём генерации огромного объёма трафика или ресурсоёмких запросов с множества распределённых источников (обычно ботнетов), что приводит к исчерпанию ресурсов сервера, канала связи или приложения.

В отличие от DoS (атаки с одного источника), DDoS практически невозможно заблокировать простым ограничением по IP, так как источники географически распределены и легитимно имитируют поведение реальных пользователей.

## Классификация атак по уровням OSI

Эффективная защита требует понимания того, на какой уровень модели OSI направлен удар.

### 1. Сетевой и транспортный уровни (L3/L4 — Volumetric)
Цель — переполнение полосы пропускания (bandwidth) или ресурсов сетевого оборудования.

- **UDP Flood:** Массовая отправка UDP-пакетов на случайные порты. Сервер тратит ресурсы на проверку приложения и отправку ICMP Destination Unreachable.
- **ICMP Flood:** Заваливание сервера запросами ICMP Echo Request (ping).
- **SYN Flood:** Использование особенностей «трёхэтапного рукопожатия» TCP. Злоумышленник шлёт SYN-пакеты, но не отвечает на SYN-ACK, забивая очередь соединений сервера.
- **Атаки усиления (Amplification):** Использование публичных сервисов (DNS, NTP, Memcached) для многократного увеличения объёма вредоносного трафика, направленного на жертву.

### 2. Прикладной уровень (L7 — Application Layer)
Цель — исчерпание ресурсов самого приложения (CPU, RAM, подключения к БД). Эти атаки наиболее сложны для обнаружения, так как трафик выглядит как легитимный.

- **HTTP Flood:** Массовые GET или POST запросы к тяжёлым страницам или API-эндпоинтам.
- **Slowloris:** Удержание HTTP-соединений открытыми максимально долго путём медленной отправки заголовков.
- **Slow POST (R.U.D.Y):** Медленная отправка тела запроса, что заставляет сервер держать соединение активным.
- **Атаки на бизнес-логику:** Массовые попытки авторизации, тяжёлые поисковые запросы или злоупотребление функционалом корзины/бронирования.

## Архитектура эшелонированной защиты

Защита от DDoS должна быть многоуровневой (**Defense in Depth**).

1.  **Внешний периметр (Cloud/Provider):**
    *   **Traffic Scrubbing:** Центры очистки трафика, отсекающие L3/L4 флуд до того, как он попадёт в вашу сеть.
    *   **CDN (Content Delivery Network):** Поглощение волюметрических атак за счёт Anycast-архитектуры и кэширования статики.
2.  **Периметр сети (Edge):**
    *   **WAF (Web Application Firewall):** Анализ L7 трафика, блокировка известных паттернов атак и поведенческая фильтрация. См. подробнее: **[WAF: Web Application Firewall](./waf.md)**.
    *   **BGP Flowspec:** Передача правил фильтрации на уровень апстрим-провайдера.
3.  **Инфраструктурный слой (Load Balancer):**
    *   **Rate Limiting:** Ограничение частоты запросов.
    *   **Connection Limiting:** Ограничение количества одновременных сессий.
    *   **Health Checks:** Автоматическое исключение "упавших" узлов из балансировки.
4.  **Слой ОС и Ядра (Kernel):**
    *   **SYN Cookies:** Защита от SYN-флуда на уровне ядра Linux.
    *   **XDP/eBPF:** Высокопроизводительный сброс пакетов на уровне драйвера сетевой карты. См. подробнее: **[eBPF — виртуальная машина ядра](../../Linux/Core/kernel/ebpf.md)**.

## Методы и инструменты защиты

| Уровень | Метод / Инструмент | Описание |
| :--- | :--- | :--- |
| **L3/L4** | **SYN Cookies** | `sysctl -w net.ipv4.tcp_syncookies=1`. Позволяет устанавливать соединения без хранения состояния в памяти до завершения рукопожатия. |
| **L3/L4** | **XDP (eXpress Data Path)** | Обработка пакетов до того, как они попадут в сетевой стек ядра. Позволяет сбрасывать миллионы пакетов в секунду с минимальной нагрузкой. |
| **L7** | **Rate Limiting** | Модуль `limit_req` в Nginx. Ограничивает RPS (Requests Per Second) для защиты от HTTP-флуда. |
| **L7** | **Challenge (JS/Captcha)** | Проверка "человечности" запроса. Современные WAF используют невидимые JS-челленджи. |
| **L7** | **Behavioral Analysis** | Анализ цепочек запросов и отпечатков (fingerprinting) для выявления ботов. |

## Практические примеры

### Тюнинг ядра Linux для защиты от DoS (sysctl)

```bash
# Включение SYN Cookies
sysctl -w net.ipv4.tcp_syncookies=1

# Уменьшение времени ожидания закрытия соединения (защита от забивания таблицы)
sysctl -w net.ipv4.tcp_fin_timeout=15

# Увеличение очереди SYN-пакетов
sysctl -w net.ipv4.tcp_max_syn_backlog=4096

# Защита от атак через изменение маршрутов (ICMP Redirect)
sysctl -w net.ipv4.conf.all.accept_redirects=0
```

### Настройка Rate Limiting в Nginx

```nginx
# Определение зоны для хранения состояний (10MB хранит ~160k IP)
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

server {
    location /api/ {
        # Лимит 10 зап/сек с возможностью кратковременного всплеска (burst) до 20
        limit_req zone=api_limit burst=20 nodelay;
        proxy_pass http://backend;
    }
}
```

### Динамическая блокировка через fail2ban

Fail2ban анализирует логи и автоматически вносит IP нарушителей в правила файрвола (ipset). Подробная настройка описана в SSoT-файле: **[fail2ban — Инструменты защиты](../../Linux/Security/Tools/fail2ban.md)**.

## Лучшие практики (Checklist)

1.  **Origin Protection:** Никогда не выставляйте реальный IP сервера в интернет. Используйте CDN или проксирующие сервисы.
2.  **Hide the Toplogy:** Ограничивайте доступ к Origin только с IP-диапазонов вашего провайдера защиты (CloudFlare, Akamai и др.).
3.  **Monitoring:** Настройте алертинг на аномальные всплески трафика, рост ошибок 5xx и задержек (Latency).
4.  **Capacity Planning:** Имейте запас по CPU и полосе пропускания, чтобы пережить "микро-атаки" до срабатывания автоматики.
5.  **Incident Response:** Имейте готовый план переключения трафика (BGP или DNS) на резервные каналы или облачные сервисы очистки.
