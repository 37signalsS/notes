# Стратегии хранения и доступа к секретам в DevOps

В DevOps и Kubernetes критически важно безопасно хранить секретные данные (пароли, API-ключи, токены). Категорически нельзя хранить их в открытом виде в коде, в системе контроля версий (Git) или в `.env` файлах без шифрования.

Вот три популярных и надёжных подхода:

## 1. HashiCorp Vault

**Лучший вариант для масштабных и зрелых проектов.**

Vault — это полноценное, централизованное решение для управления секретами.

- **Возможности**:
    - Хранение, аудит и контроль доступа к секретам.
    - Динамическая генерация и ротация секретов (например, временные пароли к БД).
    - Шифрование "на лету" и в состоянии покоя.
    - Интеграция с провайдерами идентификации (LDAP, K8s, облачные IAM).
    - Удобный API-доступ и интеграции с CI/CD системами.

- **Пример использования через CLI:**
  ```bash
  # Записать секрет
  vault kv put secret/db password="SuperSecret123"

  # Прочитать секрет
  vault kv get secret/db
  ```

- **Пример интеграции с Jenkins:**
  ```groovy
  // Используем плагин HashiCorp Vault
  withVault([vaultSecrets: [[path: 'secret/db', secretValues: [['envVar': 'DB_PASS', 'vaultKey': 'password']]]]]) {
      // Переменная $DB_PASS доступна только внутри этого блока
      sh 'echo "Пароль получен: $DB_PASS"'
  }
  ```

## 2. Kubernetes Secrets

**Нативный способ для приложений, работающих в Kubernetes.**

Ресурсы `Secret` в Kubernetes предназначены для хранения небольших объёмов чувствительных данных.

- **Возможности**:
    - Простая интеграция с экосистемой Kubernetes (управление через `kubectl`).
    - Доступ к секретам для подов через переменные окружения или монтирование в виде файлов.
    - По умолчанию секреты хранятся в etcd в base64, что не является шифрованием. Для безопасности их **необходимо** шифровать с помощью внешних инструментов.

- **Инструменты для шифрования K8s Secrets в Git:**
    - **Sealed Secrets**: Шифрует секреты с помощью асимметричного ключа, так что расшифровать их может только контроллер, запущенный в кластере.
    - **SOPS**: Инструмент от Mozilla для шифрования файлов (включая YAML/JSON) с использованием KMS, PGP или age.

- **Пример создания секрета:**
  ```bash
  kubectl create secret generic db-secret --from-literal=password='SuperSecret123'
  ```

- **Пример использования в Deployment:**
  ```yaml
  apiVersion: apps/v1
  kind: Deployment
  # ...
  spec:
    template:
      spec:
        containers:
        - name: my-app
          image: my-app-image
          env:
            - name: DB_PASS
              valueFrom:
                secretKeyRef:
                  name: db-secret
                  key: password
  ```

## 3. SOPS + GitOps

**Подход для хранения зашифрованных секретов непосредственно в Git.**

[SOPS (Secrets OPerationS)](https://github.com/mozilla/sops) — это редактор зашифрованных файлов, который позволяет безопасно коммитить их в Git.

- **Возможности**:
    - Идеально подходит для GitOps-подхода (ArgoCD, Flux).
    - Поддерживает шифрование с помощью облачных KMS (AWS KMS, GCP KMS, Azure Key Vault), PGP и `age`.
    - Сохраняет структуру файла (YAML, JSON), шифруя только значения (values), а не ключи (keys).

- **Пример шифрования файла:**
  ```bash
  # secrets.yaml -> secrets.enc.yaml
  sops --encrypt --age YOUR_PUBLIC_KEY secrets.yaml > secrets.enc.yaml
  ```

- **Пример расшифровки:**
  ```bash
  # Требуется доступ к приватному ключу
  sops --decrypt secrets.enc.yaml
  ```
  В CI/CD-пайплайне (например, в ArgoCD) процесс расшифровки происходит автоматически при наличии ключа.
