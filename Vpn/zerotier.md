# ZeroTier: Виртуальные сети поверх интернета

ZeroTier — это платформа, которая позволяет создавать защищенные виртуальные сети (L2-сети) между устройствами, где бы они ни находились. Она решает проблему NAT-траверсала, позволяя устройствам общаться напрямую друг с другом, как если бы они были в одной физической локальной сети.

- **Сайт:** [zerotier.com](https://www.zerotier.com/)
- **Исходный код:** [github.com/zerotier/ZeroTierOne](https://github.com/zerotier/ZeroTierOne)

ZeroTier создает виртуальный Ethernet-свитч (называемый "контроллером сети"), к которому подключаются устройства ("узлы"). Каждый узел получает уникальный адрес в виртуальной сети и может напрямую связываться с другими узлами, используя стандартные протоколы. Соединения устанавливаются по принципу P2P, а если прямое соединение невозможно, трафик ретранслируется через корневые серверы ZeroTier.

- **Открытый исходный код:** Основной движок написан на C++. Для самостоятельно размещенных контроллеров существует альтернативный веб-интерфейс с открытым кодом — [ztncui](https://github.com/key-networks/ztncui).
- **Кроссплатформенность:** Серверная часть и клиенты доступны для Linux, Windows, macOS, BSD, а также для мобильных платформ (iOS, Android) и встраиваемых систем.
- **Надежное шифрование:** Все соединения шифруются end-to-end с использованием потокового шифра Salsa20, кода аутентификации Poly1305 и эллиптической кривой Curve25519 для обмена ключами.
- **Масштабируемость:** Одна сеть может поддерживать до ~16.7 миллионов устройств.
- **Собственный хостинг:** Можно развернуть собственный сетевой контроллер для полной независимости от инфраструктуры ZeroTier.

## Архитектура

### Контроллер сети

Контроллер — это центральная компонента ZeroTier, которая управляет виртуальной сетью. При использовании облачного сервиса ZeroTier контроллер размещается на инфраструктуре провайдера. При самостоятельном хостинге используется [ztncui](https://github.com/key-networks/ztncui) или собственный контроллер на базе открытого кода.

Контроллер отвечает за:
- Выделение IP-адресов узлам (Managed IPs)
- Аутентификацию и авторизацию устройств
- Обмен метаданными сети между узлами

### Узлы и интерфейсы

Каждое подключенное устройство получает виртуальный сетевой интерфейс (обычно `zt+` или `ztt0` в Linux). На узле интерфейс работает как обычный Ethernet-адаптер: можно назначать IP-адреса, маршруты и применять правила `iptables`/`nftables`.

## Базовая настройка

### 1. Создание сети в облачной панели

1. Зарегистрируйтесь на [zerotier.com](https://www.zerotier.com/) и подтвердите email.
2. В личном кабинете создайте новую сеть. Сохраните **Network ID** — он потребуется для подключения устройств.
3. По умолчанию новая сеть использует диапазон `10.0.0.0/24`, но его можно изменить в настройках.

### 2. Установка клиента на Linux-сервер

```bash
# Установка клиента ZeroTier
curl -s https://install.zerotier.com | sudo bash
# → Выполняется скрипт установки...

# Проверка установки
zerotier-cli info
# → <id> <version> <browser>
```

### 3. Подключение к сети

```bash
# Join в сеть (замените <NETWORK_ID> на ваш идентификатор)
sudo zerotier-cli join <NETWORK_ID>
# → 200 join OK
```

После выполнения команды узел появится в списке устройств сети в веб-интерфейсе.

### 4. Авторизация устройства

В админке сети найдите новое устройство и нажмите **Auth**. После авторизации узел получит IP-адрес из диапазона сети.

### 5. Подключение клиентского устройства

Установите клиент ZeroTier на рабочую станцию (Windows, macOS, Linux, iOS, Android). В клиенте введите **Network ID** для подключения и запросите авторизацию в админке.

### 6. Назначение статических IP (Managed IPs)

По умолчанию ZeroTier выдает адреса через DHCP. Для серверов рекомендуется зарезервировать адреса вручную:

1. В админке откройте устройство.
2. В поле **Managed IPs** пропишите желаемый статический адрес из диапазона сети.
3. На клиенте выполните переподключение:

```bash
sudo zerotier-cli leave <NETWORK_ID>
sudo zerotier-cli join <NETWORK_ID>
```

## Настройка firewall и Docker

По умолчанию ZeroTier открывает полный доступ между всеми авторизованными узлами. Для ограничения доступа настраивается `iptables` на каждом узле.

### Принцип безопасности

- **Внешний интерфейс** (`ens3` / `eth0` и т.д.): открываются только необходимые порты (например, 80 и 443 для веб-трафика).
- **Интерфейс ZeroTier** (`zt+` / `ztt0`): полный доступ между узлами приватной сети.
- **Docker-контейнеры:** доступ извне блокируется, доступ из ZeroTier-сети разрешается через цепочку `DOCKER-USER`.

> **Важно:** Имена интерфейсов (`ens3`, `zt+`) зависят от дистрибутива и версии ZeroTier. Уточните актуальные имена через `ip link show`.

### Пример правил iptables

```bash
# Резервное копирование текущих правил
sudo iptables-save > /root/iptables.backup.$(date +%F_%H%M).rules

# Базовые allow (добавляем в начало)
sudo iptables -I INPUT 1 -i zt+ -j ACCEPT
sudo iptables -I INPUT 2 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -I INPUT 3 -i lo -j ACCEPT

# Публичные порты через внешний интерфейс
sudo iptables -I INPUT 4 -i ens3 -p tcp --dport 80  -j ACCEPT
sudo iptables -I INPUT 5 -i ens3 -p tcp --dport 443 -j ACCEPT

# Политика по умолчанию: DROP для всего остального входящего трафика
sudo iptables -P INPUT DROP
```

### Правила для Docker

```bash
# Очистка цепочки DOCKER-USER
sudo iptables -F DOCKER-USER

# Разрешение установленных соединений
sudo iptables -A DOCKER-USER -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT

# Полный доступ через ZeroTier
sudo iptables -A DOCKER-USER -i zt+ -j ACCEPT
sudo iptables -A DOCKER-USER -o zt+ -j ACCEPT

# Контейнерам разрешено инициировать соединения наружу
sudo iptables -A DOCKER-USER -i docker0 -j ACCEPT

# Из внешней сети (ens3) только 80 и 443
sudo iptables -A DOCKER-USER -i ens3 -p tcp --dport 80 -j ACCEPT
sudo iptables -A DOCKER-USER -i ens3 -p tcp --dport 443 -j ACCEPT

# Остальной трафик из внешней сети в Docker — DROP
sudo iptables -A DOCKER-USER -i ens3 -j DROP

# Возврат обработки остальных пакетов
sudo iptables -A DOCKER-USER -j RETURN
```

### Сохранение правил

```bash
# Установка утилиты для персистентности
sudo apt-get update
sudo apt-get install -y iptables-persistent

# Сохранение текущих правил
sudo netfilter-persistent save
```

## Валидация

После применения правил проверьте, что:

1. Публичные порты доступны извне:
```bash
# С внешнего хоста
curl -I http://<external-ip>
curl -I https://<external-ip>
```

2. Порты Docker-контейнеров недоступны извне (если не опубликованы):
```bash
# С внешнего хоста
nmap <external-ip> -p 6379 -PN
# → PORT     STATE  SERVICE
# → 6379/tcp filtered
```

3. Порты доступны только из ZeroTier-сети:
```bash
# С устройства в сети ZeroTier
nmap <zerotier-ip> -p 6379
# → PORT     STATE SERVICE
# → 6379/tcp open  redis
```

## Особенности и ограничения

- **MTU:** ZeroTier добавляет overhead (~40–60 байт). Если используются VPN поверх ZeroTier или большие фреймы, может потребоваться снижение MTU на интерфейсе `zt+` (по умолчанию 2800, часто достаточно 1500 или даже 1420).
- **Производительность:** В облачном режиме трафик проходит через relay-серверы ZeroTier при невозможности P2P-соединения. Для продакшн-сред с высокой нагрузкой рекомендуется размещать собственный контроллер и мониторить качество связи.
- **Безопасность:** Авторизация устройств происходит вручную в веб-интерфейсе. Не авторизованные устройства не получают доступ к сети, но пытаются подключиться к контроллеру.
