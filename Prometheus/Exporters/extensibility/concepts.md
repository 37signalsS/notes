# Расширяемость экспортеров Prometheus — Концепции

## Определения

**Расширяемость экспортеров** — архитектурная возможность добавления пользовательских метрик в систему мониторинга через внешние агенты, скрипты, прямую инструментацию или интеграцию по протоколу OTLP.

**Collector (Коллектор)** — внутренний интерфейс в экспортере или клиентской библиотеке, отвечающий за сбор группы связанных метрик (например, `cpuCollector` в `node_exporter`). В Prometheus 3.0 коллекторы могут возвращать Native Histograms.

**Exporter-Toolkit** — стандартный набор инструментов для разработки экспортеров на Go, обеспечивающий поддержку TLS, базовой аутентификации и динамической конфигурации.

**OTLP (OpenTelemetry Protocol)** — протокол передачи сигналов (метрик, логов, трейсов), ставший нативным для Prometheus 3.0 через встроенный OTLP-receiver.

**См. также:** [Обзор экспортеров](../overview.md), [Типы метрик](../../concepts/metric_types/overview.md), [Формат экспозиции](../../concepts/metric_types/exposition_format.md).

## Основные концепции

Механизмы расширения мониторинга в 2026 году делятся на пять основных категорий:

### 1. Textfile Collector (Пассивный сбор)

Встроенный модуль `node_exporter`, читающий файлы формата `.prom` из локальной директории.
- **Когда:** периодические задачи (cron), однострочные bash-скрипты, системные отчеты о состоянии RAID или бэкапов.
- **Плюсы:** экстремальная простота, не требует постоянно запущенного кастомного процесса.
- **Минусы:** риск «протухания» данных (stale data), если скрипт перестал обновлять файл.
- **Подробнее:** [Textfile Collector](./textfile_collector.md).

### 2. Script Exporter (Активный сбор)

Внешний сервис, который запускает произвольные скрипты в ответ на HTTP-запрос от Prometheus.
- **Когда:** проверки на месте (on-demand), имитация действий пользователя, сложные проверки сетевой доступности.
- **Плюсы:** данные собираются ровно в момент скрапинга, высокая актуальность.
- **Минусы:** нагрузка на CPU при частом запуске «тяжелых» скриптов (например, Python с импортами).

### 3. Собственные экспортеры (Sidecar / Агенты)

Отдельные приложения на базе клиентских библиотек для систем без нативной поддержки Prometheus (Legacy БД, проприетарное сетевое оборудование).
- **Когда:** требуется сложная трансформация данных, кэширование, поддержка TLS/Auth или Remote Write 2.0.
- **Архитектура:** обычно реализуется как отдельный процесс или Sidecar-контейнер в Kubernetes.
- **Руководство:** [Создание собственных экспортеров](./custom_exporters.md).

### 4. Прямая инструментация (Client Libraries)

Встраивание сбора метрик непосредственно в исходный код приложения.
- **Когда:** мониторинг бизнес-логики, внутренних очередей, времени обработки запросов, использование Native Histograms.
- **Плюсы:** максимальная точность, минимальные задержки, поддержка экземпляров (exemplars) для связки с трейсами.
- **Подробнее:** [Клиентские библиотеки](./client_libraries.md).

### 5. Интеграция через OTLP (Push/Pull)

Использование протокола OpenTelemetry для прямой отправки данных в Prometheus 3.0.
- **Когда:** Cloud-Native приложения, инструментированные OTel SDK, Serverless-функции (Push-модель).
- **Плюсы:** вендор-нейтральность, нативная поддержка UTF-8 имен (например, `http.server.duration`), унификация с трейсами и логами.
- **Включение:** Активируется флагом `--web.enable-otlp-receiver`.

## Практические сценарии

### Именование метрик (Prometheus 3.0+)

С появлением поддержки UTF-8 в Prometheus 3.x, правила именования стали более гибкими, но рекомендации по консистентности сохраняются:

* **Регистр и символы:** Рекомендуется нижний регистр `[a-z0-9_.]`. Точки (`.`) теперь официально разрешены и рекомендуются при интеграции с OpenTelemetry.
* **Namespace:** Префикс должен указывать на имя приложения или экспортера (например, `haproxy_`, `nginx_`, `system.`).
* **Суффиксы типа:**
  * `_total` — для Counter (обязательно).
  * `_created` — время создания серии.
  * `_info` — для метаданных (значение всегда `1`).
* **Базовые единицы:** Обязательны в названии (базовые единицы СИ): `_seconds`, `_bytes`, `_joules`, `_celsius`.

**Примеры именования:**
```text
# Старый стиль (v2): process_memory_working_set_bytes
# OTel стиль (v3): process.memory.working_set.bytes
```

### Дизайн лейблов и ресурсных атрибутов

* **Кардинальность:** Основной риск стабильности мониторинга. Никогда не используйте динамические данные (ID сессий, email, полные URL) в лейблах.
* **Resource Attributes (OTLP):** При использовании OTLP атрибуты ресурса (`service.name`, `k8s.pod.name`) автоматически преобразуются в лейблы или метаданные.
* **Service Discovery:** Экспортер должен отдавать только «сырые» данные. Лейблы инфраструктуры (`env`, `zone`, `cluster`) добавляются через [Relabeling](../../service_discovery_and_relabeling.md) на стороне Prometheus.

### Использование Native Histograms

В 2026 году при разработке экспортеров рекомендуется переходить от классических гистограмм к Native Histograms:
* **Точность:** Не требуют ручного подбора бакетов.
* **Эффективность:** Занимают в 3–5 раз меньше места в TSDB при гораздо большей точности квантилей.
* **Библиотеки:** Используйте последние версии `client_golang` или `client_python` с поддержкой экспоненциальных бакетов.

## Дополнительная информация

### Выбор протокола: OpenMetrics vs OTLP

| Сценарий | Рекомендуемый протокол | Причина |
| :--- | :--- | :--- |
| **Legacy / Infra** | OpenMetrics (Pull) | Простота, совместимость с Service Discovery. |
| **Cloud-Native** | OTLP (Pull/Push) | Унификация с трейсами, гибкость имен (UTF-8). |
| **Edge / IoT** | OTLP (Push) | Работа за NAT, отсутствие входящих соединений. |

### Типичные ошибки (Anti-patterns)

- **Timestamp в экспортере:** По умолчанию Prometheus сам ставит время скрапинга. Указывайте timestamp вручную только для исторических данных или Textfile Collector (через `_last_run_seconds`).
- **Отсутствие метаданных:** Пропуск `# HELP` и `# TYPE` затрудняет использование данных и ломает интеграцию с инструментами визуализации.
- **Игнорирование кардинальности:** Создание тысяч временных рядов на один инстанс ведет к деградации производительности Prometheus.
