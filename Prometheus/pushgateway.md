# Pushgateway

## Определения

**Pushgateway** — это промежуточный сервис (receiver) в экосистеме Prometheus, предназначенный для сбора метрик от кратковременных (ephemeral) или пакетных (batch) задач. Он позволяет реализовывать push-модель в системах, где стандартный pull-метод невозможен из-за короткого времени жизни процесса или сетевых ограничений.

Pushgateway не является заменой стандартному сбору метрик. Его основная роль — служить временным хранилищем данных, которые Prometheus сможет собрать (scrape) в своем обычном темпе.

| Характеристика | Значение |
| :--- | :--- |
| **Порт по умолчанию** | `9091` |
| **Протокол приема** | HTTP (текстовый формат Prometheus) |
| **Репозиторий** | [prometheus/pushgateway](https://github.com/prometheus/pushgateway) |

> **Установка:** Детальные инструкции по развертыванию приведены в разделе **[Установка Pushgateway](./installation/pushgateway_installation.md)**.

## Основные концепции

### Принцип работы

Pushgateway преобразует push-события в pull-эндпоинт:

1.  **Push:** Завершающаяся задача отправляет свои метрики в Pushgateway через HTTP API.
2.  **Storage:** Pushgateway сохраняет полученные метрики в памяти (и опционально на диске).
3.  **Pull:** Prometheus опрашивает Pushgateway по расписанию и забирает все накопленные данные.

### Группировка данных (Grouping Key)

Метрики в Pushgateway организуются в группы. Каждая группа определяется ключом группировки (grouping key), который состоит из обязательной метки `job` и произвольного количества дополнительных меток (например, `instance`).

**Примеры путей API:**
- `/metrics/job/backup_job` — группа только с меткой `job`.
- `/metrics/job/backup_job/instance/db1` — группа с метками `job` и `instance`.

Если значения меток содержат спецсимволы (например, пути к файлам), используется кодирование **base64**. В URL такие метки помечаются суффиксом `@base64`:
`/metrics/job/my_job/path@base64/L3Zhci9sb2c=`

### Жизненный цикл метрик

**Критически важно:** Pushgateway не удаляет метрики автоматически после того, как Prometheus их собрал. Они хранятся в нем "вечно" до тех пор, пока:
1.  В ту же группу не будет прислан новый набор данных (перезапись).
2.  Группа не будет удалена явным HTTP DELETE запросом.

### Опасности и антипаттерны

Использование Pushgateway сопряжено с рисками, которые могут исказить результаты мониторинга:

| Проблема | Описание |
| :--- | :--- |
| **Устаревшие данные (Staleness)** | Если задача упала и не прислала новые данные, Prometheus продолжит собирать старые значения, считая их актуальными. |
| **Потеря метрики `up`** | Метрика `up{job="pushgateway"}` всегда равна 1, пока жив сам шлюз, что не позволяет отслеживать работоспособность самих задач. |
| **Единая точка отказа** | Падение Pushgateway блокирует сбор метрик от всех подключенных к нему эфемерных задач. |
| **Отсутствие TTL** | Официальный Pushgateway не поддерживает автоматическую очистку по времени (TTL). Очистка должна быть реализована на стороне клиента. |

## Практические сценарии

### Отправка метрик из скрипта (Bash)

Типовой сценарий для мониторинга CronJob. Используется метод POST для добавления данных.

```bash
# Генерация метрик и отправка в Pushgateway
cat <<EOF | curl --data-binary @- http://localhost:9091/metrics/job/daily_backup/instance/app-server-01
# HELP backup_duration_seconds Длительность выполнения бэкапа.
# TYPE backup_duration_seconds gauge
backup_duration_seconds 154.5
# HELP backup_last_success_time Время последнего успешного запуска (Unix timestamp).
# TYPE backup_last_success_time counter
backup_last_success_time $(date +%s)
EOF
```

### Настройка Prometheus (honor_labels)

Для корректного сбора данных с Pushgateway в `prometheus.yml` необходимо установить параметр `honor_labels: true`. Это заставляет Prometheus доверять меткам, пришедшим из Pushgateway, вместо того чтобы перезаписывать их своими (например, `job="pushgateway"`).

```yaml
scrape_configs:
  - job_name: 'pushgateway'
    honor_labels: true
    static_configs:
      - targets: ['localhost:9091']
```

### Безопасность и ограничение доступа

Начиная с версии **1.4.0**, Pushgateway поддерживает нативный TLS и аутентификацию через файл `web-config.yml`.

```yaml
# web-config.yml
tls_server_config:
  cert_file: /etc/pushgateway/server.crt
  key_file: /etc/pushgateway/server.key

basic_auth_users:
  admin: "$2y$12$hNf2lSsxfm0.i4a.1kVpSOVyBCfIB51VRjgBUyv6kdnyTlgWj81Ay"
```

Запуск с защитой:
```bash
./pushgateway --web.config.file=web-config.yml
```

## Дополнительная информация

### Управление через API

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| **POST** | `/metrics/job/<JOBNAME>[/<L1>/<V1>]` | Добавляет метрики. Существующие в группе метрики с другими именами сохраняются. |
| **PUT** | `/metrics/job/<JOBNAME>[/<L1>/<V1>]` | Заменяет все метрики в группе. |
| **DELETE** | `/metrics/job/<JOBNAME>[/<L1>/<V1>]` | Удаляет всю группу метрик. |

### Ключевые параметры запуска

| Флаг | Описание |
| :--- | :--- |
| `--persistence.file` | Путь к файлу для сохранения данных при перезапуске сервиса. |
| `--persistence.interval` | Интервал сброса данных из памяти на диск (по умолчанию 5 минут). |
| `--web.enable-admin-api` | Разрешает использование Admin API для очистки всех данных (`PUT /api/v1/admin/wipe`). |
| `--push.disable-consistency-check` | Отключает проверку консистентности имен метрик (не рекомендуется). |
