# PromTool и лучшие практики Prometheus

В этом документе рассматривается инструмент PromTool для валидации конфигураций Prometheus и метрик, а также даются рекомендации по работе с Prometheus.

## PromTool

PromTool — это утилита командной строки, входящая в состав Prometheus, предназначенная для проверки валидности конфигураций, правил оповещений (rules) и метрик.

### Назначение PromTool

*   **Валидация конфигураций:** Проверка синтаксической и логической корректности файлов конфигурации Prometheus.
*   **Валидация правил:** Проверка правил записи (recording rules) и правил оповещений (alerting rules).
*   **Валидация метрик:** Проверка метрик, отдаваемых приложениями, на соответствие стандартам Prometheus. Это полезно для разработчиков при создании новых экспортеров или метрик в своих приложениях.
*   **Интеграция в CI:** PromTool может быть встроен в конвейеры CI/CD для автоматической проверки изменений в конфигурации Prometheus перед их развертыванием.
*   **Troubleshooting:** Инструмент также может использоваться для анализа TSDB (Time Series Database) и получения отладочной информации.

### Установка PromTool

PromTool не всегда доступен в стандартных репозиториях пакетов. Рекомендуемый способ установки — загрузка архива Prometheus с официального сайта и извлечение бинарного файла `promtool`.

1.  **Загрузка архива Prometheus:**
    Перейдите на [Prometheus.io](https://prometheus.io/download/) и скачайте последний релиз для вашей операционной системы (например, Linux).

2.  **Извлечение PromTool:**
    ```bash
    # Пример: скачивание в /tmp
    cd /tmp
    wget https://github.com/prometheus/prometheus/releases/download/vX.Y.Z/prometheus-X.Y.Z.linux-amd64.tar.gz
    tar -zxvf prometheus-X.Y.Z.linux-amd64.tar.gz
    ```
    После извлечения бинарный файл `promtool` будет находиться внутри распакованной директории (например, `prometheus-X.Y.Z.linux-amd64/promtool`).

3.  **Копирование в PATH (опционально):**
    Для удобства использования можно скопировать `promtool` в директорию, которая находится в вашей переменной окружения `PATH` (например, `/usr/local/bin` или `/usr/bin`).
    ```bash
    sudo cp prometheus-X.Y.Z.linux-amd64/promtool /usr/local/bin/
    ```
    Проверьте установку:
    ```bash
    promtool --help
    ```

### Использование PromTool

#### 1. Проверка конфигурации Prometheus (`check config`)

Эта команда позволяет проверить основной файл конфигурации Prometheus на валидность.

```bash
promtool check config /path/to/prometheus.yml
```

Пример ошибки: если в YAML-файле есть некорректный отступ, PromTool сообщит об этом, указав строку и характер ошибки.

#### 2. Проверка правил оповещений (`check rules`)

Используется для проверки синтаксиса и структуры файлов с правилами оповещений и записи.

```bash
promtool check rules /path/to/alert_rules.yml
```

#### 3. Проверка метрик (`check metrics`)

PromTool может валидировать метрики, которые отдают приложения. Это особенно полезно для разработчиков, чтобы убедиться, что их приложения экспортируют метрики в корректном формате Prometheus.

Пример проверки метрик с `kube-state-metrics`:

```bash
# Получаем IP-адрес пода kube-state-metrics
# kubectl describe pod <kube-state-metrics-pod-name> -n <namespace>

# Предположим, IP-адрес 10.42.0.10 и порт 8080
curl -s http://10.42.0.10:8080/metrics | promtool check metrics
```

PromTool выведет любые предупреждения или ошибки, связанные с форматом метрик.

#### 4. Другие возможности

*   **Дамп TSDB:** `promtool tsdb dump` позволяет делать дамп данных из базы данных Prometheus для анализа.
*   **Отладочная информация:** `promtool debug` предоставляет отладочную информацию о Prometheus.

## Лучшие практики работы с Prometheus

### 1. Управление ресурсами (Resource Management)

Всегда определяйте `requests` и `limits` для подов Prometheus (и его компонентов) в Kubernetes. Prometheus может быть очень требователен к оперативной памяти, и отсутствие лимитов может привести к нестабильности кластера.

```yaml
resources:
  requests:
    memory: "2Gi"
    cpu: "500m"
  limits:
    memory: "4Gi"
    cpu: "1000m"
```

### 2. Версионирование образов Docker

Избегайте использования тега `latest` для образов Docker Prometheus и его компонентов. Всегда указывайте конкретную, проверенную версию (например, `prometheus:v2.47.0`). Синтаксис конфигурации и флаги запуска могут меняться между версиями, что может привести к неожиданным сбоям.

### 3. Отказоустойчивость и долгосрочное хранение

*   **Отказоустойчивость:** Prometheus, даже при работе в нескольких репликах, имеет ограниченную встроенную отказоустойчивость. [Федерация Prometheus](./scaling/federation.md) может помочь, но не обеспечивает полного решения. Распространенный подход — запуск нескольких независимых экземпляров Prometheus и дублирование сбора метрик, а также их экспорт во внешнее хранилище.
*   **Долгосрочное хранение метрик:** TSDB Prometheus не предназначена для долгосрочного хранения метрик. Параметр `retention.time` в конфигурации Prometheus определяет срок хранения данных. Не рекомендуется устанавливать его более 15 дней без достаточных ресурсов, так как это значительно увеличивает потребление ресурсов и снижает производительность. Для долгосрочного хранения используйте внешние решения, такие как [VictoriaMetrics](../VictoriaMetrics/victoria_metrics_overview.md), Thanos или [Mimir](../Mimir/mimir_overview.md). Подробную информацию о настройке удаленной записи (`remoteWrite`) с помощью Helm-чарта можно найти в документе [Детальная настройка Helm-чарта Prometheus](./kubernetes/helm_chart_configuration.md). Также [Федерация Prometheus](./scaling/federation.md) может быть использована для сбора метрик с пониженной детализацией для долгосрочного хранения.

### 4. Мониторинг в Production

Данный документ является введением в PromTool и базовые аспекты Prometheus. Для настройки мониторинга в production-кластере Kubernetes необходимо глубокое понимание того, какие метрики собирать, какие алерты настраивать и как их эффективно управлять. Эти темы будут рассмотрены в контексте подготовки production-ready кластера Kubernetes.
