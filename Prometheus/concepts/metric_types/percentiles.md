# Percentiles and Quantiles: Theory and Practice

## Definitions

**Перцентиль (percentile)** — значение, ниже которого лежит определённый процент наблюдений из набора данных. Например, 95-й перцентиль времени обработки запросов = 5 секунд означает, что 95% запросов были обработаны за 5 секунд или быстрее.

**Квантиль (quantile)** — обобщение перцентиля, где уровень указывается в долях единицы (0–1), а не в процентах (0–100). Например, 0.95-квантиль эквивалентна 95-му перцентилю. В Prometheus функция `histogram_quantile()` принимает квантили (0.95, 0.99, 0.50).

**Медиана** — 50-й перцентиль (0.5-квантиль), делит упорядоченный массив пополам.

**Зачем нужны перцентили:** Они описывают распределение данных одним числом, устойчивы к выбросам. В мониторинге производительности редкие «залипания» запросов не должны искажать картину — среднее арифметическое чувствительно к выбросам, перцентили — нет.

> **Пример:** Если 99% запросов обрабатываются за 100ms, но 1% «висит» по 10 секунд, среднее покажет ~200ms (вводит в заблуждение), а 95-й перцентиль останется ~120ms, что отражает типичный пользовательский опыт.

## Basic Concepts

### Статистические меры центральной тенденции и разброса

| Метрика | Определение | Устойчивость к выбросам | Когда использовать |
|---------|-------------|------------------------|-------------------|
| **Среднее арифметическое (mean)** | `sum(x) / len(x)` | Низкая | Равномерные распределения без аномалий |
| **Медиана (p50)** | Средний элемент упорядоченного массива | Высокая | «Типичное» значение в системе |
| **95-й перцентиль (p95)** | 95% наблюдений ≤ этому значению | Высокая | Производительность «для большинства» |
| **99-й перцентиль (p99)** | 99% наблюдений ≤ этому значению | Высокая | «Хвосты» распределения, редкие деградации |
| **Максимум (p100)** | Наибольшее наблюдение | Отсутствует | Обнаружение аномалий, отладка |

### Пример расчёта на наборе данных

```
a = [10, 20, 15, 12, 18, 100, 14]
sorted = [10, 12, 14, 15, 18, 20, 100]

mean   = (10+12+14+15+18+20+100) / 7 ≈ 27  ← искажён выбросом 100
median = sorted[3] = 15                     ← устойчив к выбросу
p95    ≈ 75 (интерполяция)                 ← отражает «хвост»
max    = 100                                ← показывает аномалию
```

### Словарь терминов

| Термин | Определение | Примеры уровней |
|--------|-------------|-----------------|
| **Квантиль** | Значение, ниже которого лежит φ-доля наблюдений (φ ∈ [0,1]) | 0.25, 0.50, 0.95, 0.99 |
| **Перцентиль** | Частный случай квантили, выраженный в процентах (0–100) | 25-й, 50-й, 95-й, 99-й |
| **Квартиль** | Квантили, делящие данные на 4 части | Q1=25%, Q2=50% (медиана), Q3=75% |
| **Дециль** | Квантили, делящие данные на 10 частей | D1=10%, D5=50%, D9=90% |

> **Примечание:** «Процентиль» — синоним «перцентиля» (вариант перевода percentile). В Prometheus и PromQL используется термин «quantile» (квантиль).

## Practical Scenarios

### Сценарий 1: Выбор уровня квантили для мониторинга

| Уровень | Что показывает | Для кого подходит |
|---------|---------------|------------------|
| **p50 (медиана)** | «Типичный» пользователь | Общая картина производительности |
| **p95** | 95% запросов быстрее | SLA для большинства клиентов |
| **p99** | 99% запросов быстрее | Строгие SLA, выявление деградаций |
| **p99.9** | 99.9% запросов быстрее | Критичные системы (финансы, медицина) |

**Рекомендация:** Мониторьте **одновременно p50, p95, p99**. Большая разница между p50 и p99 указывает на нестабильность системы (выбросы, «хвосты»).

### Сценарий 2: Вычисление перцентилей в Prometheus

Два типа метрик поддерживают перцентили, с фундаментальным различием:

| Тип | Где вычисляется | Агрегируемость | Точность |
|-----|----------------|---------------|----------|
| **[Histogram](./histogram.md)** | Сервер (Prometheus, `histogram_quantile()`) | **Можно** суммировать по инстансам | Приблизительная, зависит от корзин |
| **[Summary](./summary.md)** | Клиент (экспортёр) | **Нельзя** агрегировать | Точная для одного инстанса |

**Ключевое правило:** Для распределённых систем используйте **Histogram**, потому что его перцентили корректно агрегируются: `sum by (le) (rate(..._bucket[5m]))` → `histogram_quantile(0.95, ...)`. Summary-квантили от разных реплик математически не суммируются.

Подробные примеры PromQL: [Histogram — перцентили](./histogram.md#сценарий-1-95-й-перцентиль-латентности-по-кластеру), [Summary — прямой доступ к квантилям](./summary.md).

### Сценарий 3: Почему Summary нельзя агрегировать

```
Реплика A: [9, 9, 9, 9, 9] → p95 = 9
Реплика B: [1, 1, ..., 1] (100 значений) → p95 = 1

# НЕКОРРЕКТНО:
avg(p95) = (9 + 1) / 2 = 5  ← математически бессмысленно

# Корректно (если всё же нужно):
max(p95) = 9  ← покажет худший сценарий
```

**Причина:** Квантиль — это позиция в упорядоченном наборе. Усреднение позиций из разных наборов не даёт позицию объединённого набора. Histogram решает эту проблему, храня сырые корзины, которые можно сложить _до_ вычисления квантили.

## Additional Information

### Интерполяция квантилей

Prometheus вычисляет квантили через **линейную интерполяцию** между границами корзин Histogram. Если корзина `le="1"` содержит 100 запросов, а `le="5"` — 200, то p95 будет интерполирован между 1 и 5 секундами. Чем плотнее корзины в интересующем диапазоне, тем точнее результат.

### Ограничения `histogram_quantile()`

- Результат — **приближение**, точность ограничена granularity корзин
- Функция предполагает **монотонность** корзин (каждая следующая ≥ предыдущей) — это гарантирует клиентская библиотека Prometheus
- При агрегации `sum by (le)` лейбл `le` обязателен — без него невозможно вычисление распределения

### Рекомендации по выбору типа для перцентилей

| Ситуация | Тип | Обоснование |
|----------|-----|-------------|
| Распределённая система (микросервисы) | Histogram | Агрегация по инстансам |
| Один процесс, точные квантили критичны | Summary | Точность для одного инстанса |
| Не знаете корзины Histogram | Начните с Summary, затем переходите на Histogram | Быстрый старт, затем миграция |
| Нужны _sum и_count для анализа | Histogram или Summary | Оба типа предоставляют |

> **Важно:** Не агрегируйте Summary-квантили через `avg()` или `sum()` — используйте `max()` для отображения худшего сценария или агрегируйте только `_sum` и `_count`. Подробности параметров сэмплирования — в документации клиентской библиотеки.
