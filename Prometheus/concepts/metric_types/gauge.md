# Gauge (Измеритель)

## Определения

**Gauge** — метрика в [Prometheus](../../overview.md), представляющая одно числовое значение, способное произвольно увеличиваться и уменьшаться. Gauge используется для измерения текущего состояния: температуры, использования памяти, размера очереди, числа активных соединений.

## Основные концепции

### Поведение Gauge

| Свойство | Описание |
|---|---|
| **Направление** | Произвольное (растёт и убывает) |
| **Сброс** | Не обрабатывается — значение сразу актуально после рестарта |
| **Агрегация** | Суммирование возможно, но не всегда осмысленно |
| **Суффикс** | Нет обязательных суффиксов |
| **Отрицательные значения** | Допустимы |

### Почему Gauge — это «моментальный снимок»

Gauge показывает состояние «здесь и сейчас». В отличие от [Counter](./counter.md), не требует вычисления скорости — значение само по себе информативно. Однако для анализа трендов и прогнозирования требуются функции PromQL.

### Функции PromQL для Gauge

| Функция | Назначение | Формула |
|---|---|---|
| `deriv(v[range])` | Производная (скорость изменения) через линейную регрессию | `Δv / Δt` (регрессия) |
| `predict_linear(v[range], t)` | Прогноз значения через `t` секунд | Линейная экстраполяция |
| `delta(v[range])` | Разница между первым и последним значением | `v_last - v_first` |
| `changes(v[range])` | Количество изменений значения | Подсчёт переходов |

**Ключевые особенности:**

- `deriv()` — аналог `rate()` для Gauge, но **не учитывает сбросы в 0**. При рестарте приложения может дать некорректный результат.
- `predict_linear()` — полезен для [алертинга](../../rules.md): прогноз нехватки ресурсов (диск, память).
- `delta()` — отбрасывает промежуточные значения, можно пропустить резкий всплеск с быстрым откатом.
- `changes()` — обнаружение нестабильности (часто меняющееся значение).

### Поведение при рестарте

В отличие от Counter, Gauge **не требует специальной обработки сбросов**. После перезапуска приложения экспортер сразу отдаёт актуальное значение — производная не нужна. Однако `deriv()` может работать некорректно, если в окне запроса оказался момент сброса в 0.

## Практические сценарии

### Сценарий 1: Процент использования памяти

```promql
# Использование памяти в %
(1 - node_memory_mem_available_bytes / node_memory_mem_total_bytes) * 100
```

**Применение:** Дашборды утилизации ресурсов, алерт при превышении порога в 90%. См. [Примеры алертов](./alerts.md).

### Сценарий 2: Прогноз нехватки диска

```promql
# Прогноз свободного места через 4 часа (в секундах: 4 * 3600)
predict_linear(node_filesystem_free_bytes{mountpoint="/"}[1h], 3600 * 4) < 0
```

**Применение:** Алерт на истощение диска — срабатывает до того, как место закончится.

### Сценарий 3: Скорость изменения памяти

```promql
# Производная использования памяти (байт/сек)
deriv(process_resident_memory_bytes[5m])
```

**Применение:** Выявление утечек памяти (memory leak) — стабильный положительный тренд.

### Сценарий 4: Активные соединения

```promql
# Текущее количество активных подключений
nginx_connections_active{state="reading"}
```

**Применение:** Мониторинг нагрузки на веб-сервер в реальном времени.

### Сценарий 5: Количество изменений состояния пода в Kubernetes

```promql
# Сколько раз под менял фазу за последний час
changes(kube_pod_status_phase{namespace="default"}[1h])
```

**Применение:** Обнаружение нестабильных подов (CrashLoop, частые рестарты).

## Дополнительная информация

### Формат экспорта

В формате Prometheus Gauge объявляется следующим образом:

```text
# HELP node_memory_mem_available_bytes Available memory in bytes.
# TYPE node_memory_mem_available_bytes gauge
node_memory_mem_available_bytes{instance="server-1"} 4294967296
```

Директива `# TYPE` должна быть объявлена до первого использования метрики.

### Сравнение с Counter

Gauge произвольно меняется, в то время как Counter только растёт (за исключением сбросов). Для метрик типа CPU-утилизации следует использовать Counter (`node_cpu_seconds_total`) совместно с функцией `rate()`, а не Gauge.

### Типовые ошибки

- Использование `rate()` — данная функция предназначена для Counter и ожидает монотонно возрастающее значение.
- Использование `deriv()` при рестартах — функция не учитывает сбросы в 0, что может привести к скачкам.
- Необоснованное суммирование по инстансам — агрегация Gauge через `sum()` не всегда имеет физический смысл (например, средняя температура по дата-центру).

### Gauge vs Histogram

Для измерения распределений (латентность, размеры пакетов) предпочтительнее использовать Histogram или Summary. Gauge подходит только для фиксации мгновенных значений ресурсов или физических параметров.
