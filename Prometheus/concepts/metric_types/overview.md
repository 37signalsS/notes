# Типы метрик в Prometheus: Обзор

## Определения

**Типы метрик** в [Prometheus](../../overview.md) — это классификация временных рядов по их семантике, определяющая способ изменения значений во времени. Prometheus выделяет четыре основных типа метрик: [Counter](./counter.md), [Gauge](./gauge.md), [Histogram](./histogram.md) и [Summary](./summary.md).

Правильный выбор типа метрики критичен для корректного анализа данных, агрегации и построения запросов на языке [PromQL](../promql/functions.md).

## Основные концепции

### Четыре основных типа метрик

| Тип | Описание | Когда использовать |
|:---|:---|:---|
| **[Counter](./counter.md)** | Кумулятивная метрика, значение которой только растет или сбрасывается в 0 | Счётчики запросов, ошибок, завершённых задач |
| **[Gauge](./gauge.md)** | Метрика, значение которой может произвольно увеличиваться и уменьшаться | Температура, использование памяти, активные соединения |
| **[Histogram](./histogram.md)** | Распределение значений по настраиваемым корзинам (buckets) | Латентность, размеры запросов, время выполнения операций |
| **[Summary](./summary.md)** | Распределение с расчётом квантилей на стороне клиента | Мониторинг одного процесса, когда требуются точные квантили |

### Ключевые свойства

- **Counter**: Единственный тип метрик, который можно безопасно суммировать по нескольким инстансам. Использование `sum(rate(http_requests_total[5m]))` дает корректную общую скорость.
- **Gauge**: Показывает мгновенное состояние «здесь и сейчас». Для анализа трендов используются функции PromQL, такие как `deriv()` или `predict_linear()`.
- **Histogram**: Создает группу временных рядов (`_bucket`, `_sum`, `_count`). Позволяет вычислять перцентили на стороне сервера через функцию `histogram_quantile()`.
- **Summary**: Вычисляет квантили в коде приложения. Квантили от разных инстансов **нельзя агрегировать** (усреднение квантилей математически некорректно).

## Практические сценарии

### Сценарий 1: Выбор типа для новых метрик

| Задача | Тип | Пример имени |
|:---|:---|:---|
| Подсчёт HTTP-запросов | Counter | `http_requests_total` |
| Текущее использование памяти | Gauge | `node_memory_usage_bytes` |
| Время ответа API (SLA) | Histogram | `http_request_duration_seconds` |
| Латентность одного процесса | Summary | `process_request_latency_seconds` |

### Сценарий 2: Histogram против Summary в распределенных системах

- **Histogram**: Подходит для агрегации по кластеру. Сначала суммируются корзины: `sum by (le) (rate(http_duration_seconds_bucket[5m]))`, затем применяется `histogram_quantile(0.95, ...)`.
- **Summary**: Не предназначен для агрегации. Если нужно отобразить данные по нескольким репликам на одном графике, рекомендуется использовать `max()` вместо `avg()`, чтобы увидеть худший результат.

### Сценарий 3: Формат экспозиции (Exposition Format)

Каждая метрика в формате Prometheus должна сопровождаться метаданными `# HELP` и `# TYPE`. Подробности: [Формат экспозиции](./exposition_format.md).

```text
# HELP http_requests_total Total number of HTTP requests
# TYPE http_requests_total counter
http_requests_total{method="GET",status="200"} 1024
```

## Дополнительная информация

### Функции PromQL по типам метрик

| Тип | Рекомендуемые функции | Недопустимо |
|:---|:---|:---|
| Counter | `rate()`, `increase()`, `resets()` | `deriv()` |
| Gauge | `deriv()`, `predict_linear()` | `rate()`, `increase()` |
| Histogram | `histogram_quantile()`, `rate()` для `_bucket` | Чтение `_bucket` без `rate()` |
| Summary | Прямой доступ к лейблу `quantile` | `avg()` по квантилям |

### Правила именования

- **Counter**: Обязательный суффикс `_total` (например, `errors_total`).
- **Histogram**: Автоматические суффиксы `_bucket`, `_sum`, `_count`.
- **Summary**: Автоматические суффиксы `_sum`, `_count` и лейбл `quantile`.
- **Gauge**: Суффиксы не регламентированы, рекомендуется использовать единицы измерения (например, `_bytes`).
- **Инфо-метрики**: Суффикс `_info` используется для передачи метаданных (например, версии ПО).
