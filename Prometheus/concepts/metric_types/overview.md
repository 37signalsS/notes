# Metric types in Prometheus: Overview

## Definitions

**Типы метрик** в [Prometheus](../../overview.md) — это классификация временных рядов по их семантике, то есть по тому, как их значения изменяются с течением времени. Prometheus выделяет четыре основных типа метрик: [Counter](./counter.md), [Gauge](./gauge.md), [Histogram](./histogram.md), [Summary](./summary.md). Правильный выбор типа является ключевым для корректного анализа данных, агрегации и построения запросов в [PromQL](../promql/).

Лейблы и кардинальность описаны отдельно: [Лейблы и кардинальность](../labels_and_cardinality.md).

## Basic Concepts

### Четыре основных типа метрик

| Тип | Описание | Когда использовать |
|-----|----------|-------------------|
| **[Counter](./counter.md)** | Кумулятивная метрика, растёт или сбрасывается в 0 | Счётчики запросов, ошибок, завершённых задач |
| **[Gauge](./gauge.md)** | Метрика с произвольными изменениями | Температура, использование памяти, активные соединения |
| **[Histogram](./histogram.md)** | Распределение с корзинами (buckets) | Латентность, размеры запросов, время выполнения операций |
| **[Summary](./summary.md)** | Распределение с готовыми квантилями на стороне клиента | Мониторинг одного процесса, когда нужны точные квантили |

### Ключевые свойства

- **Counter** — единственный тип метрик, который можно безопасно суммировать по всем инстансам: `sum(rate(http_requests_total[5m]))` даёт корректную общую скорость.
- **Gauge** — показывает состояние «здесь и сейчас», не требует вычисления скорости, но для анализа трендов нужны функции PromQL (`deriv()`, `predict_linear()`).
- **Histogram** — создаёт множество временных рядов (`_bucket`, `_sum`, `_count`), позволяет вычислять перцентили на стороне сервера через `histogram_quantile()`.
- **Summary** — вычисляет квантили на стороне клиента, **нельзя агрегировать** по нескольким инстансам (`avg()` по квантилям некорректен).

## Practical Scenarios

### Сценарий 1: Выбор типа для новых метрик приложения

| Задача | Тип | Пример |
|--------|-----|--------|
| Подсчёт HTTP-запросов | Counter | `http_requests_total{method="GET", status="200"}` |
| Текущее использование памяти | Gauge | `app_memory_usage_bytes` |
| Время ответа API | Histogram | `http_request_duration_seconds{le="0.1"}` |
| P95 латентность для одного инстанса | Summary | `rpc_duration_seconds{quantile="0.95"}` |

### Сценарий 2: Почему Histogram предпочтительнее Summary для распределённых систем

- **Histogram** можно суммировать по инстансам: `sum by (le) (rate(http_duration_seconds_bucket[5m]))`, затем `histogram_quantile(0.95, ...)` даст корректный перцентиль по всей системе.
- **Summary** — квантили уже вычислены на стороне клиента, `avg()` по ним математически некорректен. Для отображения одного графика используйте `max()` вместо `avg()`.

### Сценарий 3: Формат экспозиции метрик

Каждая метрика в ответе `/metrics` должна иметь `# HELP` и `# TYPE` перед первым использованием. Подробности спецификации: [Формат экспозиции](./exposition_format.md).

```
# HELP http_requests_total Total number of HTTP requests
# TYPE http_requests_total counter
http_requests_total{method="GET",status="200"} 1024
```

## Additional Information

### Функции PromQL по типям метрик

| Тип | Функции PromQL | Нельзя использовать |
|-----|---------------|-------------------|
| Counter | `rate()`, `increase()`, `resets()` | `deriv()` |
| Gauge | `deriv()`, `predict_linear()` | `rate()`, `increase()` |
| Histogram | `histogram_quantile()`, `rate()` для `_bucket` | Прямое чтение без `rate()` |
| Summary | Прямой доступ к `{quantile="X"}` | `avg()` по квантилям |

### Именование метрик

- **Counter:** суффикс `_total` обязателен (например, `http_requests_total`)
- **Histogram:** суффиксы `_bucket{le="..."}`, `_sum`, `_count`
- **Summary:** суффиксы `{quantile="..."}`, `_sum`, `_count`
- **Gauge:** нет зарезервированных суффиксов
- **Зарезервированные:** `_info` — для информации о версии
