# Типы метрик в Prometheus: Обзор

## Определения

**Типы метрик** в [Prometheus](../../overview.md) — это классификация временных рядов по их семантике, определяющая логику изменения значений во времени. Prometheus использует эти типы для правильной обработки данных (например, корректного учета сбросов счетчиков при рестартах).

Правильный выбор типа метрики критичен для корректности вычислений в [PromQL](../promql/functions.md), точности [алертинга](../../rules.md) и эффективности хранения в TSDB.

## Основные концепции

### Фундаментальные типы метрик

Начиная с версии 3.0, Prometheus выделяет пять основных типов данных для метрик (включая современные нативные гистограммы).

| Тип | Описание | Основное применение | SSoT файл |
|:---|:---|:---|:---|
| **Counter** | Кумулятивный счетчик: только растет или сбрасывается в 0. | Подсчет событий (запросы, ошибки). | [Counter](./counter.md) |
| **Gauge** | Измеритель: произвольно увеличивается и уменьшается. | Текущее состояние (CPU, RAM, темп.). | [Gauge](./gauge.md) |
| **Histogram** | Классическая гистограмма: распределение по корзинам. | Латентность, размеры ответов. | [Histogram](./histogram.md) |
| **Native Histogram** | Экспоненциальная гистограмма: высокая точность. | Высокоточные распределения (v3.0+). | [Histogram](./histogram.md) |
| **Summary** | Сводка: квантили на стороне приложения. | Точные квантили одного процесса. | [Summary](./summary.md) |

### Ключевые свойства и выбор

1.  **Counter**: Всегда используйте `rate()` или `increase()` перед агрегацией. Это единственный тип, который безопасно суммировать по инстансам (`sum(rate(...))`).
2.  **Gauge**: Используйте для мгновенных величин. Никогда не применяйте `rate()` к Gauge — используйте `deriv()` или `predict_linear()`.
3.  **Histogram vs Summary**:
    *   **Histogram**: Рекомендуется для распределенных систем (K8s, микросервисы), так как позволяет агрегировать данные.
    *   **Summary**: Используйте только если нужна экстремальная точность квантилей для одиночного инстанса и агрегация не планируется.
4.  **Native Histograms (v3.0+)**: Современная альтернатива классическим гистограммам. Не требуют ручной настройки корзин (buckets), потребляют меньше ресурсов и обеспечивают на порядок более высокую точность перцентилей.

### Совместимость с OpenTelemetry (OTel)

Prometheus v3.0 обеспечивает нативную совместимость с протоколом OTLP. Соответствие типов данных:

| Prometheus Type | OpenTelemetry Instrument | Temporality |
|:---|:---|:---|
| **Counter** | Counter / Sum | Cumulative (monotonic) |
| **Gauge** | Gauge / Asynchronous Gauge | Delta / Cumulative |
| **Histogram** | Histogram (Explicit Buckets) | Cumulative |
| **Native Histogram** | Exponential Histogram | Cumulative |
| **Summary** | Summary (Legacy) | — |

## Практические сценарии

### Сценарий 1: Выбор типа для инструментации приложения

| Ситуация | Рекомендуемый тип | Пример метрики |
|:---|:---|:---|
| Нужно знать количество обработанных заказов | **Counter** | `orders_processed_total` |
| Нужно знать текущее количество заказов в очереди | **Gauge** | `orders_in_queue` |
| Нужно знать время ответа API (SLA 95%) | **Native Histogram** | `http_request_duration_seconds` |
| Нужно знать версию приложения (Info-метрика) | **Gauge** | `app_info` (значение всегда 1) |

### Сценарий 2: Порядок агрегации в PromQL

Неверный порядок функций — самая частая причина ошибок в дашбордах.

*   **Правильно (Counter):** `sum by (job) (rate(http_requests_total[5m]))`
*   **Неправильно (Counter):** `rate(sum by (job) (http_requests_total)[5m])` — приводит к потере данных о сбросах (resets) при рестартах подов.

### Сценарий 3: Переход на Native Histograms

В Prometheus v3.0 нативные гистограммы включены по умолчанию. Они позволяют отказаться от ручного подбора корзин (`buckets`) в коде приложения, что упрощает эксплуатацию и повышает качество данных.

## Дополнительная информация

### Правила именования

- **Счетчики (Counter)**: Обязательный суффикс `_total` (например, `http_requests_total`).
- **Единицы измерения**: Используйте базовые единицы (seconds, bytes, meters).
- **Метаданные**: В Prometheus v3.0 (PRW 2.0) информация о типах и единицах измерения передается нативно, что улучшает интеграцию с Grafana и внешними хранилищами.

### Функции PromQL по типам метрик

| Тип | Разрешено / Рекомендуется | Запрещено |
|:---|:---|:---|
| **Counter** | `rate()`, `increase()`, `resets()` | `deriv()`, `delta()` |
| **Gauge** | `deriv()`, `predict_linear()`, `delta()` | `rate()`, `increase()` |
| **Histogram** | `histogram_quantile()`, `histogram_fraction()` | Сравнение сырых корзин |
