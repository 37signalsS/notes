# Типы метрик Prometheus

Метрики в Prometheus описывают измеримые характеристики систем и сервисов. Корректный выбор типа метрики и аккуратный экспорт определяют качество анализа, построение дашбордов и корректность алертинга. Важно различать семантику типов, придерживаться соглашений именования и тщательно относиться к меткам, чтобы избегать избыточной кардинальности.

## Типы метрик Prometheus

*   **Counter (счетчик)**
    *   Только увеличивается и может обнуляться при рестарте.
    *   Подходит для подсчета событий: HTTP-запросы, ошибки, обработанные задачи.
    *   Анализируется через функции `rate()`/`irate()`; не используйте для «текущего значения».
*   **Gauge (измеритель)**
    *   Может увеличиваться и уменьшаться.
    *   Подходит для текущих значений: использование памяти, размер очереди, температуру.
    *   Допустимы отрицательные значения при корректной семантике.
*   **Histogram (гистограмма)**
    *   Накопительные корзины (`_bucket` с меткой `le`), плюс `_sum` и `_count`.
    *   Эффективен для латентности и размеров, агрегируется по инстансам; позволяет рассчитывать квантили в PromQL через `histogram_quantile()`.
    *   Требует продуманного набора корзин; неверные границы ведут к грубой оценке.
*   **Summary (сводка)**
    *   Локальные квантили (`quantile`) плюс `_sum` и `_count` на стороне экспортера.
    *   Не агрегируется корректно по множеству инстансов; удобен для одиночного процесса.
    *   При кластерном анализе обычно предпочтительнее Histogram.

**Рекомендация:** для латентности в распределенной системе чаще выбирают Histogram с едиными корзинами по всем сервисам.

## Формат экспорта (text exposition format)

Экспортер отдает текст по HTTP (обычно `/metrics`). Каждая серия может сопровождаться служебными директивами:

*   Комментарии/директивы: строки с `#` (например, `HELP`, `TYPE`).
*   Образец: `name{label="value",...} value [timestamp_ms]`

**Ключевые элементы:**

*   `# HELP` Описание метрики в одном предложении.
*   `# TYPE` `counter|gauge|histogram|summary|untyped`
*   Метки — пары ключ-значение в фигурных скобках; значения — в кавычках.
*   Не используйте высококардинальные метки (`user_id`, `request_id`). Имена метрик — `snake_case` с суффиксом единицы: `_seconds`, `_bytes`, `_total` (для Counter).

**Пример фрагмента экспозиции:**
```perl
# HELP http_requests_total Количество HTTP-запросов
# TYPE http_requests_total counter
http_requests_total{method="GET",code="200"} 12345 1711711710000

# HELP request_duration_seconds Латентность запросов
# TYPE request_duration_seconds histogram
request_duration_seconds_bucket{le="0.1"} 240
request_duration_seconds_bucket{le="0.5"} 980
request_duration_seconds_bucket{le="1"} 1200
request_duration_seconds_bucket{le="+Inf"} 1210
request_duration_seconds_sum 75.3
request_duration_seconds_count 1210
```
