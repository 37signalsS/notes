# Селекторы и операторы PromQL

## Definitions

**Селектор (Selector)** — выражение для выбора временных рядов по имени метрики и [лейблам](../labels_and_cardinality.md). Селектор определяет набор временных рядов, над которыми выполняются дальнейшие операции PromQL.

**Матчер (Matcher)** — оператор сравнения внутри селектора (`{...}`), фильтрующий временные ряды по значениям лейблов.

**Оператор** — математическая, сравнительная или логическая операция, применяемая к векторам и скалярам.

## Basic Concepts

### Типы векторов в селекторах

**Instant Vector (вектор мгновенных значений)** — набор временных рядов с одним значением (последним) на каждый ряд. Единственный тип, который можно напрямую отобразить на графике.

```promql
# Instant Vector — одно значение на ряд
node_memory_mem_available_bytes{job="node-exporter"}
```

**Range Vector (вектор диапазона значений)** — набор рядов со всеми значениями за указанный интервал. Задаётся синтаксисом `[duration]`. Нельзя отобразить на графике напрямую — используется как аргумент функций (`rate()`, `delta()`, `increase()`).

```promql
# Range Vector — все значения за 5 минут
node_network_receive_bytes_total[5m]
```

**Единицы времени:** `s` (секунды), `m` (минуты), `h` (часы), `d` (дни), `w` (недели), `y` (годы).

### Матчеры лейблов

Для фильтрации по лейблам внутри селектора используются четыре типа матчеров:

| Матчер | Описание | Пример |
|--------|----------|--------|
| `=` | Точное равенство | `job="node-exporter"` |
| `!=` | Неравенство | `method!="GET"` |
| `=~` | Соответствие регулярному выражению | `job=~"api-server\|web-server"` |
| `!~` | Несоответствие регулярному выражению | `status!~"5.."` |

```promql
# Комбинированный селектор: job = api-server или web-server, метод не GET
http_requests_total{job=~"api-server|web-server", method!="GET"}
```

### Модификаторы времени

| Модификатор | Описание | Пример |
|-------------|----------|--------|
| `offset <duration>` | Сдвиг запроса в прошлое | `http_requests_total offset 1d` |
| `@ <timestamp>` | Фиксация на конкретное время (Unix timestamp) | `node_memory_MemAvailable_bytes @ 1609459200` |

```promql
# Значение метрики 1 день назад
sum(http_requests_total) offset 1d

# Значение метрики на конкретную дату
node_memory_MemAvailable_bytes @ 1609459200
```

### Математические операторы

Применяются к скалярам и векторам:

| Оператор | Описание |
|----------|----------|
| `+` | Сложение |
| `-` | Вычитание |
| `*` | Умножение |
| `/` | Деление |
| `%` | Остаток от деления |
| `^` | Возведение в степень |

```promql
# Конвертация байт в гигабайты
node_memory_MemTotal_bytes / 1024 / 1024 / 1024
```

### Операторы сравнения

`==`, `!=`, `>`, `<`, `>=`, `<=`. Применяются к скалярам и векторам. С модификатором `bool` возвращают `0` или `1` вместо фильтрации рядов.

```promql
# Фильтрация: только ряды где значение > 3
node_cpu_seconds_total > 3

# Сравнение с возвратом 0/1
node_cpu_seconds_total > bool 3
```

### Логические операторы

Работают только с **instant vector**. Выполняют операции над множествами временных рядов по лейблам:

| Оператор | Описание |
|----------|----------|
| `and` | Ряды из левого вектора, для которых есть совпадения по лейблам в правом |
| `or` | Все ряды из левого вектора + уникальные ряды из правого |
| `unless` | Ряды из левого вектора, для которых нет совпадений в правом |

```promql
# Только ряды, существие в обоих векторах
up{job="api"} and http_requests_total

# Все ряды из обоих векторов (уникальные лейблы)
up{job="api"} or up{job="web"}

# Ряды из левого вектора, которых нет в правом
up unless http_requests_total
```

## Practical Scenarios

### Фильтрация метрик по окружению и сервису

```promql
# Только production-инстансы API-сервера
up{env="production", job="api-server"}
```

### Исключение определённых лейблов

```promql
# Все метрики кроме kube-system namespace
kube_pod_info{namespace!="kube-system"}
```

### Сравнение с порогом для алертинга

```promql
# Доступная память меньше 10% — критический алерт
node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100 < 10
```

### Процент ошибок HTTP 5xx

```promql
sum(rate(http_requests_total{code=~"5.."}[5m]))
/
sum(rate(http_requests_total[5m]))
* 100
```

### Вчерашний трафик для сравнения

```promql
# Тещий RPS vs RPS вчера
sum(rate(http_requests_total[5m]))
# vs
sum(rate(http_requests_total[5m])) offset 1d
```

### Проверка доступности на конкретный момент

```promql
# Был ли сервис доступен на 1 января 2021?
up{job="api"} @ 1609459200
```

## Additional Information

### Взаимосвязь с типами данных

- **Instant vector** — единственный тип, который рисуется на графиках напрямую ([Типы данных](./data_types.md))
- **Range vector** — аргумент функций (`rate()`, `increase()`), возвращают instant vector ([Функции PromQL](./functions.md))
- Логические операторы (`and`, `or`, `unless`) работают только с **instant vector**

### Векторные операции (many-to-one, group_left/group_right)

Для сложных операций между векторами с разными наборами лейблов используются модификаторы `on()`, `ignoring()`, `group_left()`, `group_right()` — см. [Операции с векторами](./vector_operations.md).

### Предостережения

- **Range vector на графике** — нельзя отобразить напрямую, сначала обрабатывается функцией
- **Регулярные выражения в `=~`** — матчер соответствует **всей строке**, используйте `.*` для частичного совпадения
- **`offset` за пределами retention** — если данные удалены, запрос вернёт пустой результат
- **Логические операторы без лейблов** — `and`/`or`/`unless` без совпадающих лейблов вернут пустой результат или полный набор
