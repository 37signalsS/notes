# Операции с векторами в PromQL

## Definitions

**Vector Matching (сопоставление векторов)** — механизм PromQL, определяющий, какие элементы двух векторов комбинируются при выполнении бинарных операций. По умолчанию сопоставление происходит по **полному совпадению всех лейблов**.

**Label Manipulation Functions** — встроенные функции PromQL для создания, изменения и объединения лейблов (`label_replace`, `label_join`). Используются для нормализации лейблов перед векторными операциями или агрегацией.

**Subquery (подзапрос)** — синтаксис, позволяющий применить функции диапазона (`..._over_time`) к функциям instant vector, указывая собственный шаг вычисления.

## Basic Concepts

### Vector Matching — стратегии сопоставления

При выполнении бинарной операции между двумя векторами PromQL сопоставляет элементы по лейблам:

#### One-to-one

Каждый элемент левого вектора сопоставляется **одному** элементу правого вектора с **идентичным** набором лейблов. Это поведение по умолчанию.

```promql
# Сопоставление по всем лейблам: method, path, instance
http_requests_total / http_errors_total
```

Если в левом векторе есть ряд `{method="GET", path="/api"}`, он сопоставится только с `{method="GET", path="/api"}` из правого.

#### Many-to-one и one-to-many

Когда у одного вектора **больше** лейблов, чем у другого, используются модификаторы `group_left` и `group_right`:

| Модификатор | Когда использовать | Какие лейблы сохраняются |
|-------------|-------------------|--------------------------|
| `group_left` | В правом векторе меньше лейблов (many-to-one) | Из левого (many) + указанные из правого (one) |
| `group_right` | В левом векторе меньше лейблов (one-to-many) | Из правого (many) + указанные из левого (one) |

```promql
# Many-to-one: node_cpu (много лейблов: cpu, mode) * up (мало лейблов: instance)
# Сохраняем лейбл job из up
node_cpu_seconds_total * on(instance) group_left(job) up
```

#### Фильтрация сопоставления

По умолчанию сравниваются **все** лейблы. Модификаторы сужают набор лейблов для сопоставления:

| Модификатор | Описание |
|-------------|----------|
| `on(<label_list>)` | Сопоставлять **только** по указанным лейблам |
| `ignoring(<label_list>)` | Сопоставлять по всем, **кроме** указанных |

```promql
# Сопоставление только по instance, игнорируя cpu и mode
node_cpu_seconds_total * on(instance) group_left(job) up

# Игнорировать лейбл cpu при сопоставлении
node_cpu_seconds_total * ignoring(cpu) node_boot_timestamp_seconds
```

### Функции для работы с лейблами

#### `label_replace`

Создаёт новую метку, применяя регулярное выражение к исходной:

```
label_replace(v, dst_label, replacement, src_label, regex)
```

| Параметр | Описание |
|----------|----------|
| `v` | Вектор |
| `dst_label` | Имя новой метки |
| `replacement` | Шаблон замены (поддерживает `$1`, `$2` для групп захвата) |
| `src_label` | Исходная метка |
| `regex` | Регулярное выражение (соответствие **всей строке**) |

```promql
# Шаблонизация URL: /api/users/123 → /api/users/:id
label_replace(
  http_requests_total,
  "templated_path",
  "/api/users/:id",
  "path",
  "/api/users/[^/]+"
)
```

#### `label_join`

Объединяет значения нескольких меток в одну через разделитель:

```
label_join(v, dst_label, separator, src_label_1, src_label_2, ...)`

```promql
# Объединение namespace и pod в одну метку
label_join(kube_pod_info, "pod_fqdn", "/", "namespace", "pod")
```

### Subqueries (подзапросы)

Синтаксис: `function(vector[range])[total_range:step]`

Позволяет применить `..._over_time` к функциям instant vector. Шаг (`step`) определяет, как часто вычисляется внутренняя функция.

```promql
# Среднее значение rate за последний час, вычисление каждые 5 минут
avg_over_time(rate(http_requests_total[5m])[1h:5m])
```

| Параметр | Описание |
|----------|----------|
| `5m` | Интервал внутреннего `rate()` |
| `1h` | Общий интервал subquery |
| `5m` | Шаг вычисления (как часто берётся `rate()`) |

Если шаг не указан, используется `scrape_interval` по умолчанию.

## Practical Scenarios

### Many-to-one: обогащение метрик информацией из другого источника

```promql
# Добавляем лейбл role из метрики up к node_cpu_seconds_total
node_cpu_seconds_total * on(instance) group_left(role) up
```

Без `group_left` лейбл `role` из `up` потерялся бы — `group_left` сохраняет его в результате.

### One-to-many: применение порога к группе метрик

```promql
# Скалярный порог применяется ко всем рядам вектора
node_cpu_seconds_total > 0.8
```

Здесь левый вектор — скаляр (0.8, без лейблов), правый — множество рядов. Каждый ряд сравнивается с порогом.

### Фильтрация по subset лейблов

```promql
# Сопоставление только по instance и job, игнорируя cpu, mode
node_cpu_seconds_total * on(instance, job) group_left() up
```

Полезно, когда правый вектор не содержит детализацию левого (например, `up` не имеет лейбла `cpu`).

### Шаблонизация URL для снижения кардинальности

```promql
# Замена ID пользователей на шаблонный лейбл
label_replace(
  http_requests_total,
  "route",
  "/api/users/:id",
  "path",
  "/api/users/[^/]+"
)
```

Результат можно использовать для агрегации без взрыва кардинальности ([Лейблы и кардинальность](../labels_and_cardinality.md)).

### Прогнозирование тренда с subquery

```promql
# Средний rate за последний час, вычисление каждые 5 минут → прогноз на 4 часа
predict_linear(
  avg_over_time(node_filesystem_free_bytes[5m])[1h:5m],
  3600 * 4
) < 0
```

Вложенная subquery сглаживает шум отдельных точек перед экстраполяцией.

### Объединение лейблов для алертинга

```promql
# Создание fqdn-метки для уведомления
label_join(kube_pod_info, "target", ".", "namespace", "pod", "node")
```

Результат используется в [Alertmanager](../../alertmanager.md) для маршрутизации уведомлений.

## Additional Information

### Взаимосвязь с другими типами операций

- **Селекторы и матчеры** — базовая фильтрация перед векторными операциями ([Селекторы и операторы](./selectors_operators.md))
- **Агрегация `by`/`without`** — группировка внутри одного вектора, `on`/`ignoring` — сопоставление двух векторов ([Агрегация](./aggregation.md))
- **Функции PromQL** — принимают range vector, возвращают instant vector ([Функции PromQL](./functions.md))

### Предостережения

- **Множество результатов many-to-many** — если оба вектора содержат несколько рядов с одинаковыми лейблами, PromQL вернёт ошибку. Используйте `group_left`/`group_right` для однозначности
- **`label_replace` и полная строка** — регулярное выражение в `label_replace` должно соответствовать **всей строке**, используйте `.*` для частичного совпадения
- **Subquery и производительность** — вложенные вычисления увеличивают нагрузку. Указывайте минимальный достаточный шаг
- **`ignoring` vs `on`** — `ignoring` удобнее, когда лейблов много, `on` — когда нужно сопоставить по конкретным

### Производительность subqueries

| Шаг subquery | Вычислений за 1h | Нагрузка |
|--------------|-------------------|----------|
| `1m` | 60 | Высокая |
| `5m` | 12 | Средняя |
| `15m` | 4 | Низкая |

Рекомендуемый шаг — 4–5× `scrape_interval` для баланса точности и нагрузки.
