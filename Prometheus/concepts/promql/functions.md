# Функции PromQL

## Определения

**Функции PromQL** — встроенные операции для обработки временных рядов в Prometheus. В отличие от [операторов агрегации](./aggregation.md), большинство функций принимают **range vector** и возвращают **instant vector**. Функции классифицируются по типу метрик, для которых они предназначены ([Counter](../metric_types/counter.md), [Gauge](../metric_types/gauge.md), [Histogram](../metric_types/histogram.md), [Summary](../metric_types/summary.md)), а также по функциональным группам (математические, временные, строковые, метаданные).

Актуально для **Prometheus v3.0+** (включая экспериментальные функции).

## Базовые концепции

### Функции для счётчиков (Counters)

Предназначены для работы с монотонно увеличивающимися значениями. Автоматически обрабатывают сбросы (counter resets).

| Функция | Описание | Тип входа | Особенности |
|---------|----------|-----------|-------------|
| `rate(v)` | Средняя скорость роста в секунду | range-vector | Рекомендуется для алертинга и долгосрочных графиков. |
| `irate(v)` | Мгновенная скорость (по 2 последним точкам) | range-vector | Показывает пики, чувствительна к шуму. Не для алертов. |
| `increase(v)` | Абсолютный прирост за интервал | range-vector | Экстраполирует результат, может возвращать дробные числа. |
| `resets(v)` | Количество сбросов счётчика | range-vector | Полезно для детекции рестартов приложений. |

**Ключевые особенности:**

- `rate()` и `increase()` требуют как минимум две точки в интервале для вычисления.
- `irate()` лучше использовать на коротких интервалах для отладки («зум» графиков).
- Все функции этой группы ожидают, что значение только растёт (кроме сбросов в 0).

**Пример:**

```promql
# Средний RPS за последние 5 минут
rate(http_requests_total[5m])
# → {method="GET", path="/api"} 10.5

# Общее количество запросов за последний час
increase(http_requests_total[1h])
# → {method="POST"} 3600

# Детекция рестарта пода (сброс времени старта)
resets(process_start_time_seconds[1h]) > 0
# → {instance="node-1"} 1
```

### Функции для измерителей (Gauges)

Работают со значениями, которые могут как расти, так и уменьшаться. Не учитывают сбросы в 0.

| Функция | Описание | Тип входа | Применение |
|---------|----------|-----------|------------|
| `deriv(v)` | Производная (скорость изменения) | range-vector | Расчёт наклона линии (линейная регрессия). |
| `predict_linear(v, t)` | Прогноз значения через `t` секунд | range-vector, scalar | Прогноз исчерпания ресурсов (диск, память). |
| `delta(v)` | Разница между первым и последним значением | range-vector | Расчёт изменения значения за период. |
| `idelta(v)` | Мгновенная разница (2 последние точки) | range-vector | Аналог `irate()` для Gauge. |
| `changes(v)` | Количество изменений значения | range-vector | Детекция нестабильности («флаппинг») метрики. |

**Пример:**

```promql
# Прогноз: через сколько секунд закончится место на диске
predict_linear(node_filesystem_free_bytes{mountpoint="/"}[1h], 3600 * 4) < 0
# → {device="/dev/sda1"} 1

# Скорость изменения температуры (градусов в секунду)
deriv(node_hwmon_temp_celsius[5m])
# → {sensor="cpu"} 0.05
```

### Функции для гистограмм (Histograms)

Используются для вычисления квантилей и обработки распределений. Поддерживают как классические (bucket-based), так и нативные гистограммы.

| Функция | Описание | Тип входа | Версия |
|---------|----------|-----------|---------|
| `histogram_quantile(φ, b)` | Вычисляет φ-квантиль (0 ≤ φ ≤ 1) | scalar, instant-vector | — |
| `histogram_avg(v)` | Среднее значение в нативной гистограмме | instant-vector | v2.40+ |
| `histogram_sum(v)` | Сумма значений в нативной гистограмме | instant-vector | v2.40+ |
| `histogram_count(v)` | Количество сэмплов в нативной гистограмме | instant-vector | v2.40+ |
| `histogram_fraction(l, u, v)` | Доля сэмплов между нижним (l) и верхним (u) порогами | scalar, scalar, instant-vector | v2.40+ |
| `histogram_stddev(v)` | Среднеквадратичное отклонение (нативные) | instant-vector | v2.40+ |
| `histogram_stdvar(v)` | Дисперсия (нативные) | instant-vector | v2.40+ |

**Ключевые особенности:**

- `histogram_quantile` требует агрегации `sum by (le)` перед вычислением для обычных гистограмм.
- Нативные гистограммы (Native Histograms) стабильны в Prometheus v3.0 и позволяют вычислять квантили точнее без лейбла `le`.

**Пример:**

```promql
# 99-й перцентиль латентности (классическая гистограмма)
histogram_quantile(0.99, sum by (le) (rate(http_request_duration_seconds_bucket[5m])))
# → {} 0.15

# Доля запросов быстрее 200мс (нативная гистограмма)
histogram_fraction(0, 0.2, http_request_duration_seconds[5m])
# → {} 0.98

# Средняя латентность (нативная гистограмма)
histogram_avg(http_request_duration_seconds[5m])
# → {} 0.045
```

### Агрегация по времени (Over time)

Функции `..._over_time` принимают **range vector** и возвращают **instant vector**, выполняя агрегацию внутри временного окна каждого ряда.

| Функция | Описание |
|---------|----------|
| `avg_over_time(v)` | Среднее значение за интервал |
| `min_over_time(v)` / `max_over_time(v)` | Минимальное / Максимальное значение |
| `sum_over_time(v)` | Сумма всех значений |
| `count_over_time(v)` | Количество точек в интервале |
| `quantile_over_time(φ, v)` | φ-квантиль за интервал |
| `stddev_over_time(v)` | Среднеквадратичное отклонение |
| `last_over_time(v)` | Последнее значение в интервале |
| `present_over_time(v)` | Возвращает 1 для каждого ряда, имеющего точки в интервале |
| `absent_over_time(v)` | Возвращает 1, если в интервале *нет* точек |

### Сортировка и специальные функции

Используются для упорядочивания результатов и работы с отсутствующими данными.

| Функция | Описание | Тип входа | Версия |
|---------|----------|-----------|---------|
| `sort(v)` | Сортировка по значению (возрастание) | instant-vector | — |
| `sort_desc(v)` | Сортировка по значению (убывание) | instant-vector | — |
| `sort_by_label(v, l, ...)` | Сортировка по значениям лейблов | instant-vector | v3.0+ (exp) |
| `absent(v)` | Проверка отсутствия данных (возвращает 1, если вектор пуст) | instant-vector | — |
| `timestamp(v)` | Возвращает Unix timestamp для каждой точки | instant-vector | — |
| `info(v, [labels])` | Обогащение метками из инфо-метрик | instant-vector | v3.0+ (exp) |

**Пример:**

```promql
# Топ-5 инстансов по загрузке CPU, отсортированных по имени инстанса
sort_by_label(topk(5, rate(node_cpu_seconds_total[5m])), "instance")

# Алерт, если метрика `up` отсутствует (сервис не найден)
absent(up{job="my-job"})
# → {job="my-job"} 1

# Время с момента последнего скрейпа
time() - timestamp(up)
```

### Математические и тригонометрические функции

Применяются к instant-vector или скалярам.

- **Арифметические:** `abs(v)`, `sqrt(v)`, `exp(v)`, `ln(v)`, `log2(v)`, `log10(v)`, `round(v, to)`, `ceil(v)`, `floor(v)`.
- **Тригонометрические:** `sin(v)`, `cos(v)`, `tan(v)`, `asin(v)`, `acos(v)`, `atan(v)`.
- **Специальные:**
  - `sgn(v)` — возвращает знак числа (1, -1 или 0).
  - `clamp(v, min, max)` — ограничивает значение в заданном диапазоне.
  - `scalar(v)` — преобразует вектор из одного элемента в скаляр.
  - `vector(s)` — преобразует скаляр в вектор без лейблов.

### Побитовые операции (Bitwise)

Используются для анализа флагов и масок. В стандартном Prometheus v3.0 побитовые операции находятся в стадии предложения (Proposal).

- `bitwise_and(v, mask)`
- `bitwise_or(v, mask)`
- `bitwise_xor(v, mask)`
- `bitwise_not(v)`

> **Примечание:** Для работы с флагами в стандартном PromQL часто используются математические операции `round()`, `/` и `%`.

### Подзапросы (Subqueries)

Позволяют использовать функции, принимающие range vector, для результатов мгновенных вычислений.

**Синтаксис:** `<instant_query> [<range>:<resolution>]`

**Пример:**

```promql
# Максимальный пятиминутный RPS за последние 24 часа с шагом в 1 минуту
max_over_time(sum(rate(http_requests_total[5m]))[24h:1m])
# → {} 50.2
```

### Временные функции

Используются для создания условий, зависящих от времени.

| Функция | Описание | Пример |
|---------|----------|--------|
| `time()` | Текущее время (Unix timestamp) | `time() - process_start_time_seconds` |
| `hour()` | Час суток (0–23 UTC) | `hour() > 9 and hour() < 18` |
| `day_of_week()` | День недели (0–6, 0=Воскресенье) | `day_of_week() == 0` |
| `days_in_month()` | Количество дней в месяце | `days_in_month(year(), month())` |

### Манипуляции с лейблами (Labels)

Позволяют изменять или создавать новые лейблы на лету. Часто используются для нормализации данных перед агрегацией.

- **`label_replace(v, dst, replacement, src, regex)`**: Извлекает часть значения из лейбла `src` по `regex` и записывает в `dst`.
- **`label_join(v, dst, separator, src1, src2, ...)`**: Объединяет значения нескольких лейблов через разделитель.

**Примеры:**

```promql
# 1. Шаблонизация URL: /api/users/123 -> /api/users/:id
label_replace(
  http_requests_total,
  "templated_path",
  "/api/users/:id",
  "path",
  "/api/users/[^/]+"
)
# → {path="/api/users/123", templated_path="/api/users/:id"}

# 2. Извлечение версии: "app:v1.2" -> "v1.2"
label_replace(up, "version", "$1", "image", ".*:(.*)")
# → {image="myapp:v1.2", version="v1.2"}

# 3. Объединение лейблов: namespace="prod", pod="api-1" -> "prod/api-1"
label_join(kube_pod_info, "pod_fqdn", "/", "namespace", "pod")
# → {namespace="prod", pod="api-1", pod_fqdn="prod/api-1"}
```

## Практические сценарии

### Расчёт доступности (Uptime SLA)

```promql
# Процент времени, когда сервис был доступен (up==1) за 30 дней
avg_over_time(up[30d]) * 100
# → {} 99.95
```

### Алерт на аномальный всплеск (Z-Score)

```promql
# Значение отклоняется более чем на 3 стандартных отклонения от среднего за час
(
  rate(http_requests_total[5m]) - avg_over_time(rate(http_requests_total[5m])[1h:5m])
) 
/ 
stddev_over_time(rate(http_requests_total[5m])[1h:5m]) > 3
```

### Динамическое ограничение значений

```promql
# Ограничить метрику сверху значением 100 для чистоты графиков
clamp_max(node_load1, 100)
# → {instance="node-1"} 100
```

## Дополнительная информация

### Предостережения

- **Экстраполяция:** `rate()` и `increase()` экстраполируют данные до границ временного окна. Это может привести к нецелым числам в `increase()`, даже если метрика целочисленная. Подробнее в [Реальное поведение метрик](./real_world_behavior.md).
- **Интервал сбора:** Окно функции (например, `[5m]`) должно быть как минимум в 4 раза больше `scrape_interval` для стабильных результатов.
- **Порядок выполнения:** Функции манипуляции лейблами выполняются после фильтрации селекторами.
- **Экспериментальные фичи:** Функции `info` и `sort_by_label` требуют флага `--enable-feature=promql-experimental-functions`.

### Взаимосвязь с типами данных

- Большинство аналитических функций ожидают **Range Vector** ([Типы данных](./data_types.md)).
- Математические функции работают с **Instant Vector** или **Scalar**.
- Результатом почти всех функций является **Instant Vector**, что позволяет строить графики и настраивать алерты.
