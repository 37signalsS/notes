# Типы данных PromQL

## Определения

**PromQL (Prometheus Query Language)** — функциональный язык запросов для работы с многомерными временными рядами в [Prometheus](../../overview.md). Оптимизирован для вычислений и агрегаций над временными рядами в реальном времени.

Актуально для **Prometheus v3.0+**, включая поддержку имен в формате UTF-8 и нативную совместимость с OpenTelemetry (OTLP).

**Типы данных в PromQL** — четыре базовых типа, с которыми оперирует движок выполнения запросов, плюс расширенный тип нативных гистограмм:

| Тип | Описание | Отображение на графике | Основное назначение |
|-----|----------|------------------------|---------------------|
| **Instant vector** | Набор рядов с одной точкой данных на каждый ряд | Да | Алертинг, визуализация, агрегация |
| **Range vector** | Набор рядов с массивом точек за промежуток времени | Нет (требует функции) | Вход для функций `rate()`, `increase()`, `..._over_time()` |
| **Scalar** | Числовое значение с плавающей точкой (float64) | Нет | Константы, пороговые значения, арифметика |
| **String** | Строковое значение (литерал) | Нет | Аргументы функций (`label_replace`, regex) |
| **Native Histogram** | Расширенный вектор с разреженными экспоненциальными корзинами | Да | Высокоточные квантили без лейбла `le` |

> В Prometheus v3.0+ **Native Histograms** являются стабильной технологией и официально поддерживаются как расширенный тип данных внутри векторов.

## Базовые концепции

### Instant vector — мгновенные векторы

Массив пар key-value, где key — метрика с набором лейблов, а value — значение в конкретный момент времени (evaluation time). Это основной тип данных для алертинга и визуализации.

**Внутреннее устройство:**
- **Структура:** Каждая уникальная комбинация лейблов образует отдельный временной ряд. Движок PromQL сопоставляет лейблы для бинарных операций по полному совпадению, если не указаны модификаторы `on` / `ignoring` ([Операции с векторами](./vector_operations.md)).
- **Timestamp:** Все точки в одном векторе привязаны к одному и тому же моменту времени.
- **Поддержка UTF-8 (v3.0):** Имена метрик и лейблов могут содержать любые символы (например, `"трафик_в_байтах"` или `"http.method"`).
- **Staleness (Устаревание):** Если в момент запроса данных нет, Prometheus ищет последнюю точку в пределах **lookback delta** (по умолчанию 5 минут). Если таргет явно передает маркер `stale nan`, ряд помечается как отсутствующий немедленно. Подробнее о поведении устаревших данных см. [Реальное поведение метрик](./real_world_behavior.md).

**Особенности отображения:**
- Графики Grafana и API `/query` возвращают именно Instant vector.
- Агрегационные операторы (`sum`, `avg`, `max` по `by`/`without`) принимают Instant vector и возвращают Instant vector.

### Range vector — векторы диапазона

Набор временных рядов, содержащих массив данных за определенный интервал времени. Синтаксис: `metric_name[5m]`.

**Влияние интервала и сдвига:**
- **Offset:** Позволяет получить данные со сдвигом в прошлое: `http_requests_total[5m] offset 1h`. Отрицательный сдвиг (`offset -1h`) сдвигает запрос в будущее.
- **Минимальный интервал:** В окне должно гарантированно находиться минимум 4 точки скрейпинга (правило 4 точек) для корректной обработки сбросов счетчиков в функциях `rate()` и `increase()`.
- **Шаг в range query:** При запросе через `/api/v1/query_range` параметр `step` определяет дискретность возвращаемых точек. Чем меньше шаг, тем выше нагрузка на сервер.

**Визуализация:**
- Range vector не может быть отображен на графике напрямую. Требуется функция, возвращающая Instant vector (`rate()`, `avg_over_time()` и т.д.).

**Применение:**
- Входные данные для функций скорости изменения (`rate`, `increase`).
- Агрегация во времени (`sum_over_time`, `avg_over_time`).
- Детекция изменений (`changes()`, `resets()`).

### Scalar — скалярные значения

Чистое числовое значение без меток, хранящееся как 64-битное число с плавающей запятой (float64).

**Способы получения:**
- Литералы: `-1.23`, `42`, `3.14e2`.
- Агрегация без `by`/`without`: `count(up)` возвращает вектор из одного элемента, который в выражениях ведет себя как скаляр.
- `scalar(vector)`: явное преобразование вектора из одного элемента в скаляр.
- `time()`: текущее Unix-время.
- Результат математических функций при применении к скаляру (`abs(-5)`).

**Ограничения:**
- `NaN` и `Inf` допустимы как значения, но могут приводить к неожиданному поведению в сравнениях.
- При делении на скаляр `0` Prometheus возвращает `+Inf` или `-Inf`, а не ошибку.

**Пример:**
```promql
# Перевод байтов в мегабайты (1048576 — скаляр)
node_memory_MemFree_bytes / 1048576
# → {instance="node-1"} 2048.0
```

### String — строковые значения

Строковые литералы, заключаемые в двойные или обратные апострофы. Используются как аргументы в функциях манипуляции лейблами (`label_replace`, `label_join`) и в регулярных выражениях.

**Особенности:**
- Не сохраняются в TSDB как значения метрик.
- Не участвуют в бинарных операциях (за исключением конкатенации в `label_replace` через regex).
- Поддерживают экранирование: `"path=\"/api/v1\""`.

### Native Histograms — нативные гистограммы

В Prometheus v3.0 стали стабильной технологией. В отличие от классических гистограмм с лейблом `le`:

| Характеристика | Классическая гистограмма | Native Histogram |
|----------------|--------------------------|------------------|
| **Хранение** | Много рядов (по одному на корзину `le`) | Один ряд с разреженными корзинами |
| **Кардинальность** | Высокая (линейный рост с числом корзин) | Низкая (экспоненциальные корзины) |
| **Точность квантилей** | Зависит от выбора корзин | Высокая, адаптивное разрешение |
| **Лейбл `le`** | Обязателен | Отсутствует |
| **Совместимость** | Полная | Требует Prometheus 2.40+ / v3.0+ |

**Внутреннее устройство:**
- Используют **разреженные экспоненциальные корзины** (sparse exponential buckets), где плотность корзин адаптируется под распределение данных.
- Каждая корзина содержит `count` (количество сэмплов) и опционально `sum` (сумма значений).
- При арифметических операциях (`+`, `-`, `*`, `/`) Prometheus v3.0 автоматически согласовывает разрешение корзин (bucket reconciliation).

**Практическое значение для SRE:**
- Снижение кардинальности на порядки при сохранении точности p99/p999.
- Уменьшение объема данных в TSDB и ускорие запросов `histogram_quantile()`.
- Миграция требует обновления экспортеров и дашбордов.

## Правила неявного преобразования типов

PromQL автоматически приводит типы в бинарных операциях. Понимание этих правил позволяет избегать типичных ошибок.

### Матрица совместимости

| Левая часть | Правая часть | Результат | Примечание |
|-------------|--------------|-----------|------------|
| Scalar | Instant vector | Instant vector | Скаляр применяется к каждому элементу |
| Instant vector | Scalar | Instant vector | Скаляр применяется к каждому элементу |
| Instant vector | Instant vector | Instant vector | Требуется сопоставление лейблов |
| Range vector | Range vector | Недопустимо | Бинарные операции между range vector запрещены |
| Scalar | Scalar | Scalar | Обычная арифметика |
| String | String | String | Только для литералов в функциях |

### Правила сопоставления векторов

При бинарных операциях между двумя Instant vector:
1. **По умолчанию:** сопоставление по **полному совпадению всех лейблов**.
2. **`on(<labels>)`:** сопоставление только по указанным лейблам.
3. **`ignoring(<labels>)`:** сопоставление по всем лейблам, кроме указанных.
4. **`group_left` / `group_right`:** разрешают многие-к-одному сопоставление с добавлением лейблов из "справочного" вектора. Недоступны для логических операторов (`and`, `or`, `unless`).

### Ошибки несовместимости типов

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `vector cannot contain metrics with the same labelset` | Два ряда в одном векторе имеют идентичные лейблы после применения `on`/`ignoring` | Уберите дубликаты через агрегацию или добавьте уникальный лейбл |
| `many-to-many matching not allowed` | Сопоставление многих ко многим без `group_left` | Добавьте `group_left` или предварительно агрегируйте векторы |
| `expected type range vector` | Функция ожидает `[range]`, а передан instant vector | Добавьте указание диапазона: `metric[5m]` |
| `expected type instant vector` | Функция ожидает instant vector, а передан range vector | Оберните в функцию: `rate(metric[5m])` |

## Семантика подзапросов (Subqueries)

Подзапрос `<instant_query>[<range>:<resolution>]` создает **range vector** из результатов мгновенных вычислений.

**Тип возврата:**
- Внутренний запрос `<instant_query>` должен возвращать **instant vector**.
- Результат подзапроса — **range vector**, который можно передавать в функции, ожидающие диапазон (`max_over_time`, `avg_over_time`).

**Правила проектирования:**
- **Правило 4 точек:** `range` должен покрывать минимум 4 точки скрейпинга для стабильности.
- **Шаг (`resolution`):** Рекомендуется не менее `4 * scrape_interval`. Слишком мелкий шаг создает избыточную нагрузку на CPU.
- **Производительность:** Подзапрос вычисляет внутренний запрос для каждого шага. При `range=24h` и `step=1m` это 1440 вычислений.

**Пример потока типов:**
```promql
# rate(http_requests_total[5m]) → instant vector
# [24h:1m] → range vector из 1440 instant vectors
# max_over_time(...) → instant vector (пик за сутки)
max_over_time(rate(http_requests_total[5m])[24h:1m])
```

## Практические сценарии

### Запрос Instant vector через API

Используется для получения текущего состояния системы.

```bash
# Мгновенный запрос — возвращает resultType: vector
curl 'http://localhost:9090/api/v1/query?query=node_load1'
# → {"status":"success","data":{"resultType":"vector","result":[...]}}
```

### Запрос Range vector через API

Используется для получения сырых данных за период.

```bash
# Запрос диапазона — возвращает resultType: matrix
curl 'http://localhost:9090/api/v1/query_range?query=up&start=2026-07-29T10:00:00Z&end=2026-07-29T11:00:00Z&step=1m'
# → {"status":"success","data":{"resultType":"matrix","result":[...]}}
```

### Применение скаляров в расчетах

```promql
# Перевод байтов в мегабайты (1048576 — скаляр)
node_memory_MemFree_bytes / 1048576
# → {instance="node-1"} 2048.0
```

### Использование подзапросов (Subqueries)

```promql
# Максимальный пятиминутный RPS за последние 24 часа с шагом 1 минута
max_over_time(sum(rate(http_requests_total[5m]))[24h:1m])
# → {} 150.5
```

### Диагностика: почему запрос возвращает пустой результат

| Причина | Тип проблемы | Проверка | Решение |
|---------|--------------|----------|---------|
| Метрика отсутствует | Нет данных в TSDB | `up{job="..."}` | Проверьте scrape targets |
| `rate()` на instant vector | Ошибка типа | В логе PromQL: `expected type range vector` | Добавьте `[5m]` |
| Слишком маленькое окно | Меньше 2 точек | `count_over_time(metric[1m])` | Увеличьте окно до `4 * scrape_interval` |
| Несовпадение лейблов | Пустое множество | `count(metric)` vs `count(metric * on() group_left() other)` | Проверьте модификаторы `on`/`ignoring` |
| Staleness | Данные устарели | `timestamp(metric) < time() - 600` | Проверьте доступность таргета |

### Валидация миграции на Native Histograms

```promql
# Проверка: корзины присутствуют, лейбла le нет
count(http_request_duration_seconds_bucket)
# → 0 (ожидаемо для native histogram)

# Экспоненциальные корзины видна в сырых данных
http_request_duration_seconds
# → {instance="..."} <number of samples> (без le)
```

### Определение "свежести" данных по типу

```promql
# Разница между текущим временем и последней точкой (в секундах)
time() - timestamp(up{job="critical-service"})
# → {instance="app-1"} 12.5 (данные свежие)

# Алерт: данные устарели более чем на 10 минут
time() - timestamp(up{job="critical-service"}) > 600
```

### Сравнение RPS через подзапрос и прямой rate

```promql
# Прямой rate (instant vector на каждый scrape)
rate(http_requests_total[5m])

# Подзапрос: агрегирует rate за час с шагом 1 минута (range vector → max_over_time)
max_over_time(rate(http_requests_total[5m])[1h:1m])
# Полезно для поиска пиковой нагрузки за период
```

### Обработка точности float64 в сравнениях

```promql
# Из-за float64 погрешности сравнение на точное равенство ненадежно
# ПРАВИЛЬНО: использование диапазона или порога
abs(node_load1 - expected_load) < 0.001

# НЕПРАВИЛЬНО: может не сработать из-за погрешности представления
node_load1 == 0.85
```

## Дополнительная информация

### Результаты API: vector против matrix

В контексте [HTTP API Prometheus](../../prometheus_api.md) существует соответствие между типами данных PromQL и форматом JSON-ответа:

| Контекст | resultType: vector | resultType: matrix |
|----------|--------------------|--------------------|
| **Instant Query (`/query`)** | Возвращает мгновенные значения рядов. | Неприменимо. |
| **Range Query (`/query_range`)** | Неприменимо. | Всегда возвращает матрицу (набор мгновенных точек для каждого шага). |

### Взаимосвязь с типами данных

- **Range Vector → Instant Vector:** Функции `rate()`, `increase()`, `delta()`, `deriv()`, `..._over_time()`.
- **Instant Vector → Instant Vector:** Агрегация `sum()`, `avg()`, `max()` и математические функции.
- **Scalar → Scalar:** `abs()`, `sqrt()`, `ceil()`, `floor()` при применении к скаляру.
- **Instant Vector → Range Vector:** Подзапрос `[range:step]`.

### Производительность по типам

| Тип | Стоимость хранения | Стоимость запроса | Рекомендация |
|-----|--------------------|-------------------|--------------|
| **Instant vector** | Низкая (одна точка на ряд) | Низкая | Безопасно использовать в алертах. |
| **Range vector** (большое окно) | Высокая (много точек) | Высокая | Избегайте окон >24h для высококардинальных метрик. |
| **Native histogram** | Средняя (разреженные корзины) | Средняя/Высокая | Сначала агрегируйте `sum by (le)`, затем вычисляйте квантиль. |
| **Подзапрос** | Высокая (вычисления на каждом шаге) | Высокая | Ограничьте `range` и увеличьте `step`. |

### Типовые ошибки и диагностика

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Запрос возвращает пустой результат | Нет данных или несовпадение лейблов | Проверьте `up`, `count(metric)` |
| `rate()` возвращает пустой результат | В окне меньше 2 точек | Увеличьте `[range]` или проверьте `scrape_interval` |
| `expected type range vector` | Функции скорости применены к instant vector | Добавьте `[5m]` к селектору |
| `many-to-many matching not allowed` | Дубликаты лейблов при сопоставлении | Добавьте `group_left` или агрегируйте |
| Дробные значения в `increase()` | Экстраполяция к границам окна | Используйте `round()` или проверяйте `> 0` |
| `NaN` в результатах | Деление на ноль или пустой вектор | Проверьте делитель на `> 0` |

### Выбор типа данных под задачу

| Задача | Тип | Пример |
|--------|-----|--------|
| Алерт на порог | Instant vector | `rate(http_requests_total[5m]) > 100` |
| График тренда | Range vector через `/query_range` | `rate(...)` с `step=1m` |
| Прогноз ресурсов | Range vector + `predict_linear` | `predict_linear(node_free[1h], 3600*4)` |
| Детект рестартов | Range vector + `resets` | `resets(process_start_time_seconds[1h])` |
| Анализ распределения | Native Histogram | `histogram_quantile(0.99, sum by (le) (rate(...)))` |
| Проверка наличия данных | Instant vector + `absent` | `absent(up{job="critical"})` |
