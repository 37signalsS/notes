# Типы данных PromQL

## Определения

**PromQL (Prometheus Query Language)** — функциональный язык запросов для работы с многомерными временными рядами в [Prometheus](../../overview.md). Оптимизирован для вычислений и агрегаций над временными рядами в реальном времени.

Актуально для **Prometheus v3.0+**, включая поддержку имен в формате UTF-8 и нативную совместимость с OpenTelemetry (OTLP).

**Типы данных в PromQL** — четыре базовых типа, с которыми оперирует движок выполнения запросов:

| Тип | Описание | Отображение на графике |
|-----|----------|---------------------------|
| **Instant vector** | Набор рядов с одной точкой данных на каждый ряд | Да |
| **Range vector** | Набор рядов с массивом точек за промежуток времени | Нет (требует функции) |
| **Scalar** | Числовое значение с плавающей точкой (float64) | Нет |
| **String** | Строковое значение (литерал) | Нет |

> В Prometheus v3.0+ также официально поддерживаются **Native Histograms** как расширенный тип данных внутри векторов.

## Базовые концепции

### Instant vector — мгновенные векторы

Массив пар key-value, где key — метрика с набором лейблов, а value — значение в конкретный момент времени. Это основной тип данных для алертинга и визуализации.

**Особенности:**
- **Структура:** Каждая уникальная комбинация лейблов образует отдельный временной ряд.
- **Timestamp:** Все точки в одном векторе привязаны к одному и тому же моменту времени (evaluation time).
- **Поддержка UTF-8 (v3.0):** Имена метрик и лейблов теперь могут содержать любые символы (например, `"трафик_в_байтах"` или `"http.method"`).
- **Staleness (Устаревание):** 
  - Если в момент запроса данных нет, Prometheus ищет последнюю точку в пределах **lookback delta** (по умолчанию 5 минут).
  - **Explicit Staleness:** Если таргет при скрейпинге передает маркер `stale nan`, ряд помечается как отсутствующий немедленно. Это предотвращает "хвосты" на графиках после удаления подов.

### Range vector — векторы диапазона

Набор временных рядов, содержащих массив данных за определенный интервал времени. Синтаксис: `metric_name[5m]`.

**Назначение:**
- Входные данные для функций скорости изменения (`rate`, `increase`).
- Агрегация во времени (`sum_over_time`, `avg_over_time`).
- Не могут быть отображены на графике напрямую.

**Влияние интервала и сдвига:**
- **Offset:** Позволяет получить данные со сдвигом в прошлое: `http_requests_total[5m] offset 1h`.
- **Минимальный интервал:** Рекомендуется использовать минимум 4 точки скрейпинга (правило 4 точек) для корректной обработки сбросов счетчиков в функциях рейта.

### Scalar — скалярные значения

Чистое числовое значение без меток.

**Способы получения:**
- Литералы: `-1.23`, `42`.
- `count(up)` — агрегация без группировки возвращает вектор с одним элементом, который ведет себя как скаляр.
- `scalar(vector)`: преобразует вектор из одного элемента в скаляр.
- `time()`: текущее Unix-время.

**Пример:**
```promql
# Умножение вектора на скаляр
node_load1 * 100
# → {instance="node-1"} 85.0 (при node_load1=0.85)
```

### String — строковые значения

Строковые литералы, заключаемые в кавычки или обратные апострофы. Используются только как аргументы в некоторых функциях (например, `label_replace`). Не сохраняются в TSDB как значения метрик.

### Native Histograms — нативные гистограммы

В Prometheus v3.0 стали стабильной технологией. В отличие от классических гистограмм:
- Хранятся в **одном** временном ряду (без лейбла `le`).
- Используют разреженные корзины с динамическим разрешением.
- Обеспечивают высокую точность перцентилей при меньшем объеме данных.

## Практические сценарии

### Запрос Instant vector через API

Используется для получения текущего состояния системы (Table view).

```bash
# Мгновенный запрос — возвращает resultType: vector
curl 'http://localhost:9090/api/v1/query?query=node_load1'
# → {"status":"success","data":{"resultType":"vector","result":[...]}}
```

### Запрос Range vector через API

Используется для получения сырых данных за период.

```bash
# Запрос диапазона — возвращает resultType: matrix
curl 'http://localhost:9090/api/v1/query_range?query=up&start=2026-07-29T10:00:00Z&end=2026-07-29T11:00:00Z&step=1m'
# → {"status":"success","data":{"resultType":"matrix","result":[...]}}
```

### Применение скаляров в расчетах

```promql
# Перевод байтов в мегабайты (1048576 — скаляр)
node_memory_MemFree_bytes / 1048576
# → {instance="node-1"} 2048.0
```

### Использование подзапросов (Subqueries)

Подзапросы позволяют динамически создавать range vector из мгновенных векторов.

```promql
# Максимальный пятиминутный RPS за последние 24 часа с шагом 1 минута
max_over_time(sum(rate(http_requests_total[5m]))[24h:1m])
# → {} 150.5
```

## Дополнительная информация

### Результаты API: vector против matrix

В контексте [Prometheus API](../../prometheus_api.md) существует путаница между типами данных PromQL и форматом JSON-ответа:

| Контекст | resultType: vector | resultType: matrix |
|----------|--------------------|--------------------|
| **Instant Query (`/query`)** | Возвращает мгновенные значения рядов. | Возвращает ряды с интервалом `[d]`. |
| **Range Query (`/query_range`)** | Неприменимо. | Всегда возвращает матрицу (набор мгновенных точек для каждого шага). |

### Взаимосвязь с функциями

- **Range vector -> Instant vector:** Функции `rate()`, `increase()`, `delta()`, `deriv()`.
- **Instant vector -> Instant vector:** Операторы агрегации `sum()`, `avg()`, `max()` ([Агрегация](./aggregation.md)) и математические функции `abs()`, `ceil()`.
- **Subqueries:** Позволяют использовать функции диапазона над результатами мгновенных вычислений.
