# Типы метрик в Prometheus

Prometheus определяет четыре основных типа метрик. Понимание их различий критически важно для корректного использования и интерпретации данных.

---

## 1. Counter (Счётчик)

**Counter** — это кумулятивная метрика, значение которой может только увеличиваться или сбрасываться до нуля при перезапуске сервиса. Он никогда не уменьшается.

*   **Назначение:** Подсчёт событий, которые накапливаются со временем.
*   **Примеры:**
    *   Количество обработанных HTTP-запросов (`http_requests_total`).
    *   Число выполненных задач.
    *   Количество байт, прочитанных с диска.

**Ключевая идея:** Сам по себе счётчик малоинформативен, так как он просто показывает накопленное значение. Его истинная ценность раскрывается при использовании с функциями `rate()` или `increase()` в PromQL, которые позволяют вычислить **скорость** изменения за определённый интервал.

**Пример метрики:**
```
# HELP node_cpu_seconds_total Seconds the cpus spent in each mode.
# TYPE node_cpu_seconds_total counter
node_cpu_seconds_total{cpu="0",mode="idle"} 8.376965e+06
```

---

## 2. Gauge (Измеритель)

**Gauge** — это метрика, которая представляет одно числовое значение, способное произвольно увеличиваться и уменьшаться.

*   **Назначение:** Измерение текущего состояния, которое может меняться в любую сторону.
*   **Примеры:**
    *   Текущая загрузка процессора.
    *   Использование оперативной памяти.
    *   Температура.
    *   Количество активных пользователей.
    *   Свободное место на диске.

**Ключевая идея:** Gauge показывает "моментальный снимок" значения. Его можно напрямую отображать на графиках без использования специальных функций.

**Пример метрики:**
```
# HELP node_memory_mem_available_bytes Memory information field MemAvailable_bytes.
# TYPE node_memory_mem_available_bytes gauge
node_memory_mem_available_bytes 1.8868224e+08
```

---

## 3. Histogram (Гистограмма)

**Histogram** — это метрика, которая сэмплирует наблюдения (например, длительность запроса) и группирует их в настраиваемые **корзины (buckets)**. Гистограмма также предоставляет сумму всех наблюдений и их количество.

*   **Назначение:** Анализ распределения значений. Позволяет понять, какая доля наблюдений укладывается в определённые рамки.
*   **Примеры:**
    *   Длительность HTTP-запросов.
    *   Размеры ответов.
    *   Время выполнения запроса к базе данных.

Гистограмма генерирует несколько временных рядов:
*   `_bucket{le="<upper_bound>"}`: Кумулятивный счётчик для наблюдений, значение которых меньше или равно `<upper_bound>`. `le` означает "less than or equal to".
*   `_bucket{le="+Inf"}`: Счётчик всех наблюдений (его значение равно `_count`).
*   `_sum`: Сумма всех наблюдаемых значений.
*   `_count`: Общее количество наблюдений.

**Ключевая идея:** Гистограммы позволяют вычислять квантили на стороне сервера с помощью функции `histogram_quantile()`. Это основной способ использования гистограмм.

**Пример метрики:**
```
# HELP http_request_duration_seconds_bucket Request duration in seconds.
# TYPE http_request_duration_seconds_bucket histogram
http_request_duration_seconds_bucket{le="0.1"} 432
http_request_duration_seconds_bucket{le="0.5"} 10808
http_request_duration_seconds_bucket{le="1"} 12270
http_request_duration_seconds_bucket{le="+Inf"} 12948
http_request_duration_seconds_sum 5423.4
http_request_duration_seconds_count 12948
```
*Из примера видно, что 432 запроса выполнились за 0.1 секунды или быстрее.*

## 4. Summary (Сводка)

**Summary**, как и гистограмма, сэмплирует наблюдения. Однако, в отличие от гистограммы, она вычисляет и хранит **квантили** непосредственно на стороне клиента (в опрашиваемом приложении).

*   **Назначение:** Анализ распределения, когда агрегация с разных инстансов не требуется или когда нужны точные значения квантилей без вычислений на сервере.
*   **Примеры:**
    *   Перцентили времени отклика API.

Summary генерирует несколько временных рядов:
*   `{quantile="<φ>"}`: Значение для заданного квантиля (0 ≤ φ ≤ 1).
*   `_sum`: Сумма всех наблюдаемых значений.
*   `_count`: Общее количество наблюдений.

**Ключевая идея и отличие от Histogram:**
*   **Вычисление квантилей:** Summary вычисляет их на клиенте, Histogram позволяет вычислять их на сервере Prometheus.
*   **Агрегация:** Квантили из Summary **нельзя** корректно усреднять по разным инстансам. Вы не можете усреднить 95-й перцентиль с нескольких серверов и получить осмысленный результат. Гистограммы, напротив, можно агрегировать (суммируя счётчики в бакетах), и уже после этого вычислять общий квантиль.

**Пример метрики:**
```
# HELP rpc_duration_seconds A summary of the RPC duration in seconds.
# TYPE rpc_duration_seconds summary
rpc_duration_seconds{quantile="0.5"} 0.01
rpc_duration_seconds{quantile="0.9"} 0.05
rpc_duration_seconds{quantile="0.99"} 0.2
rpc_duration_seconds_sum 5423.4
rpc_duration_seconds_count 12948
```
