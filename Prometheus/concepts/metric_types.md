# Типы метрик в Prometheus

Prometheus поддерживает четыре основных типа метрик, которые позволяют эффективно представлять различные виды данных мониторинга. Понимание этих типов критически важно для правильного инструментирования приложений и анализа систем.

1.  **Счётчик (Counter)**
    *   **Описание:** Монотонно возрастающее значение, которое может только увеличиваться или сбрасываться до нуля (например, при перезапуске приложения). Он не может уменьшаться или принимать отрицательные значения. Используется для подсчета событий, которые происходят с течением времени.
    *   **Примеры:** Общее количество обращений к сервису, число обработанных HTTP-запросов, общее количество ошибок, число отправленных байтов. **Не подходит** для показателей, которые могут уменьшаться (например, свободная память на сервере).
    *   **Использование:** Подходит для отображения суммарных значений. Для получения скорости изменения (например, запросов в секунду) используются функции `rate()` или `irate()` в PromQL.
    *   **Пример из транскрипта:** "число страховых там полисов например оформенных всего за время существования вашей системы".

2.  **Измеритель (Gauge)**
    *   **Описание:** Метрика, значение которой может как увеличиваться, так и уменьшаться. Она отражает текущее состояние или значение чего-либо в определенный момент времени.
    *   **Примеры:** Текущая температура, текущее использование памяти, количество активных пользователей онлайн, количество процессов в системе.
    *   **Использование:** Идеально подходит для отображения мгновенных значений или для метрик, которые могут колебаться в обоих направлениях.
    *   **Пример из транскрипта:** "температура и давление пользователей онлайн времени там задержки ответа число переданных байт".

3.  **Гистограмма (Histogram)**
    *   **Описание:** Распределяет наблюдаемые значения (например, длительность запросов, размер ответов) по настраиваемым диапазонам (бакетам). Prometheus хранит несколько временных рядов для гистограммы:
        *   `_bucket`: кумулятивные счетчики для каждого бакета.
        *   `_sum`: общая сумма всех наблюдаемых значений.
        *   `_count`: общее количество всех наблюдаемых значений.
    *   **Использование:** 
        *   Позволяет вычислять квантили (перцентили) на стороне сервера с помощью функции `histogram_quantile()` в PromQL, что очень важно для анализа производительности (например, 99-й перцентиль времени ответа).
        *   Позволяет рассчитать среднее значение наблюдаемой величины, так как есть сумма (`_sum`) и количество (`_count`).
        *   Идеально подходит для отслеживания пропорций и настройки индикаторов качества обслуживания (SLI), например, "какой процент запросов выполняется быстрее 200мс?".
    *   **Пример из транскрипта:** "с помощью гистограмма считают всякие разные там перцентили с помощью гистограмм допустим считают количество там запросов с ошибкой либо без ошибки".

4.  **Сводка (Summary)**
    *   **Описание:** Похожа на гистограмму, но ключевое отличие в том, что перцентили (квантили) для нее **вычисляются на стороне клиента** (в инструментируемом приложении) за определенный скользящий период времени и экспортируются уже готовыми. Она также хранит общее количество наблюдений (`_count`) и сумму всех наблюдаемых значений (`_sum`).
    *   **Использование:** Подходит для измерения продолжительности событий (например, время ответа на запросы), но менее гибка для агрегации на стороне сервера, чем гистограммы.
    *   **Преимущества/Недостатки:**
        *   **Плюс:** Перцентили точны для каждого отдельного экземпляра (instance).
        *   **Минус:** Сложности с агрегацией перцентилей между несколькими экземплярами (инстансами) приложения, поскольку перцентили уже вычислены и их нельзя просто так усреднить. Расчет квантилей на клиенте также потребляет больше ресурсов.
    *   **Пример из транскрипта:** "сам ли очень дорого считать он требует больше времени ресурсов на прошет потому что там более точные цифры там используется флот из двойной точностью".

5.  **Вектор (Labels/Tags)**
    *   **Описание:** Хотя "вектор" не является отдельным типом метрики в том же смысле, что и предыдущие четыре, этот термин из транскрипта, вероятно, относится к использованию **лейблов (labels)**. Лейблы представляют собой пары ключ-значение, которые позволяют добавлять к метрикам многомерный контекст.
    *   **Использование:** С их помощью можно фильтровать, группировать и агрегировать метрики по различным измерениям (например, `http_requests_total{method="POST", instance="server1"}`). Лейблы делают модель данных Prometheus очень гибкой.
    *   **Пример из транскрипта:** "это некий словарь или мапа из описанных выше типов то есть это как бы метрики со страховые метками или ну как бы метрики создаваемые на лету".
