# Karma Dashboard для Alertmanager

**Karma** — это дашборд (dashboard) для [Alertmanager](./alertmanager.md), который помогает визуализировать и управлять алертами в системах мониторинга. В то время как стандартный UI Alertmanager'а функционален, Karma предоставляет более продвинутый и удобный интерфейс, особенно при работе с большим количеством алертов из разных источников.

## 1. Основные возможности

- **Агрегация**: Если у вас несколько экземпляров Alertmanager (например, в разных кластерах), Karma может собирать алерты со всех из них в едином интерфейсе.
- **Продвинутая фильтрация и поиск**: Позволяет быстро находить нужные алерты по меткам (`labels`), статусу и другим параметрам.
- **Удобная группировка**: Группирует алерты, делая интерфейс чище и понятнее.
- **Управление алертами**: Позволяет создавать "тишину" (silences) прямо из интерфейса для временного подавления алертов.
- **Темная/Светлая тема**: Поддерживает темы для удобства работы.
- **Отсутствие бэкенда**: Все настройки хранятся локально в браузере, Karma не требует собственной базы данных для хранения состояния.

## 2. Установка

### 2.1. Установка через Helm

Установка Karma в Kubernetes проще всего выполняется с помощью Helm-чарта.

**Конфигурация**

Ключевым параметром конфигурации является указание URL вашего Alertmanager.

**Пример `values.yaml` для чарта Karma:**

```yaml
# values.yaml

# Указываем, к какому Alertmanager подключаться
alertmanager:
  servers:
    - name: "main" # Имя для инстанса Alertmanager
      uri: "http://alertmanager-operated.monitoring.svc.cluster.local:9093" # URL вашего Alertmanager

# Включаем Ingress для доступа к дашборду
ingress:
  enabled: true
  hosts:
    - name: "karma.my-domain.com"
      path: "/"
  # tls, annotations и другие параметры Ingress...

# Позволяем вносить изменения (например, создавать silences)
readonly: false

# Другие стандартные параметры чарта
replicaCount: 1
resources:
  limits:
    cpu: 100m
    memory: 128Mi
  requests:
    cpu: 50m
    memory: 64Mi
```

**Развертывание**

Установка может быть выполнена как напрямую командой `helm install`, так и через системы GitOps, например, ArgoCD. При использовании ArgoCD достаточно создать `Application` ресурс, указывающий на репозиторий с чартом и файлом `values.yaml`.

После установки Karma будет доступна по адресу, указанному в Ingress, и начнет отображать алерты, поступающие в сконфигурированный Alertmanager.

### 2.2. Установка через манифесты

В качестве альтернативы Helm, Karma может быть развернута с помощью набора стандартных манифестов Kubernetes. Этот подход дает полный контроль над всеми аспектами развертывания.

Процесс включает создание следующих ресурсов:

- **`ConfigMap`**: Содержит конфигурацию Karma, в основном URL для подключения к Alertmanager.
- **`Deployment`**: Управляет подами Karma.
- **`Service`**: Предоставляет внутренний сетевой доступ к подам Karma.
- **`Ingress`**: (Опционально) Открывает доступ к веб-интерфейсу Karma извне кластера.
