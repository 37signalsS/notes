# Дашборд Karma

## Определения

**Karma** — дашборд с открытым исходным кодом для [Alertmanager](./alertmanager.md), предоставляющий расширенный пользовательский интерфейс для визуализации и управления оповещениями. В отличие от стандартного интерфейса Alertmanager, Karma ориентирована на работу в больших средах с сотнями оповещений и несколькими кластерами мониторинга.

На 2026 год Karma остается стандартом де-факто для визуализации алертов в экосистеме Prometheus благодаря своей легкости, гибкости фильтрации и поддержке агрегации из множества источников.

| Характеристика | Описание |
|---|---|
| **Тип приложения** | Stateless (без сохранения состояния на бэкенде) |
| **Язык разработки** | Go (бэкенд), React (фронтенд) |
| **Порт по умолчанию** | `8080` |
| **Лицензия** | Apache-2.0 |

> **См. также:** [Alertmanager](./alertmanager.md), [Обзор Prometheus](./overview.md), [Service Discovery](./service_discovery_and_relabeling.md)

## Основные концепции

### Агрегация и дедупликация

Karma может собирать данные из неограниченного количества экземпляров Alertmanager. Если один и тот же алерт (с идентичными метками) присутствует на нескольких серверах (например, в HA-паре Alertmanager), Karma автоматически объединяет их в одну карточку в интерфейсе, указывая источники.

### Продвинутая фильтрация

Ключевая особенность Karma — мощный язык запросов для поиска алертов. Фильтры могут быть как простыми (по меткам), так и специальными (мета-фильтры):

*   `severity=critical` — поиск по точному совпадению метки.
*   `cluster!=prod` — исключение по метке.
*   `instance=~.*-web-.*` — поиск по регулярному выражению.
*   `@state=active` — фильтрация по состоянию (active, suppressed, unprocessed).
*   `@age>1h` — фильтрация по времени существования алерта.
*   `@receiver=slack` — фильтрация по получателю уведомлений.

### Управление замалчиваниями (Silences)

Karma позволяет не только просматривать существующие замалчивания, но и создавать новые, используя текущие фильтры как основу. Она проксирует запросы на создание/редактирование в Alertmanager.

### Контроль доступа (ACL)

Karma поддерживает гибкую настройку прав (Access Control Lists). Можно ограничить создание замалчиваний для определенных групп алертов или требовать подтверждения для критических инстансов.

## Практические сценарии

### Конфигурация через переменные окружения

В контейнеризированных средах Karma часто настраивается через ENV-переменные. Это удобно для простых инсталляций.

```bash
# Пример запуска в Docker
docker run -d \
  -p 8080:8080 \
  -e ALERTMANAGER_URI="http://alertmanager:9093" \
  -e ALERTMANAGER_NAME="Main-Cluster" \
  -e KARMA_NAME="Monitoring Dashboard" \
  ghcr.io/prymitive/karma:latest
```

### Настройка ACL (Access Control Lists)

Пример конфигурации в `config.yaml` для ограничения возможности создания замалчиваний на продуктивном кластере.

```yaml
# config.yaml
acl:
  silences:
    - action: allow
      # Разрешить всем создавать silences для не-prod алертов
      filters:
        - cluster!=prod
    - action: block
      # Запретить всем, кроме администраторов (если настроен Auth)
      filters:
        - cluster=prod
      reason: "Создание тишины на prod разрешено только через дежурного инженера."
```

### Развёртывание в Kubernetes через Helm

Использование официального чарта — рекомендуемый способ для промышленной эксплуатации.

**values.yaml:**
```yaml
alertmanager:
  servers:
    - name: "Production"
      uri: "http://alertmanager.monitoring.svc:9093"
      proxy: true # Разрешить Karma проксировать запросы к API Alertmanager
    - name: "Staging"
      uri: "http://alertmanager-staging.monitoring.svc:9093"

labels:
  # Скрывать технические метки из общего списка для чистоты UI
  strip: ["prometheus", "instance"]
  # Порядок отображения меток в карточке алерта
  keep: ["alertname", "severity", "cluster", "service"]

resources:
  limits:
    memory: 256Mi
  requests:
    cpu: 100m
    memory: 128Mi
```

## Дополнительная информация

### Мониторинг самой Karma

Karma экспортирует метрики в формате Prometheus по пути `/metrics`. Ключевые метрики для отслеживания:

*   `karma_alertmanager_errors_total` — количество ошибок при опросе бэкендов Alertmanager.
*   `karma_collected_alerts_count` — общее количество собранных алертов.
*   `karma_alertmanager_requests_duration_seconds` — время ответа от Alertmanager.

### Безопасность

Karma не имеет встроенного механизма аутентификации пользователей (в базовой версии). Рекомендуется:
1.  Использовать **Reverse Proxy** (Nginx, OAuth2 Proxy) с авторизацией (OIDC/LDAP).
2.  Настраивать сетевые политики (**Network Policies**) для ограничения доступа к порту 8080.
3.  Использовать Read-Only режим (`readonly: true`), если не требуется создание замалчиваний.

> **Практическое руководство**: пошаговые инструкции по развёртыванию через манифесты (Deployment, ConfigMap) находятся в разделе [Alertmanager + Karma в Kubernetes: манифесты](./kubernetes/examples/alertmanager-karma-manifests-tutorial/intro.md).
