# Prometheus Remote Read/Write API

## Определения

**Remote Read/Write API** — это ключевой механизм Prometheus для масштабирования и интеграции с внешними системами хранения. Он позволяет делегировать задачи долгосрочного хранения метрик, решая проблемы, описанные в заметке о [масштабировании Prometheus](./overview.md).

## Основные концепции

-   **`remote_write`**: Prometheus отправляет собранные метрики в удаленное хранилище в режиме реального времени. При такой схеме локальный экземпляр Prometheus часто выступает в роли "агента", ответственного только за сбор данных.
-   **`remote_read`**: Prometheus запрашивает данные из удаленного хранилища при выполнении запросов, которые охватывают исторические данные, отсутствующие в локальной TSDB.

Вся обработка данных (агрегация, выполнение функций PromQL) по-прежнему производится на стороне Prometheus. Это означает, что для "тяжелых" запросов за длительный период может потребоваться значительный объем "сырых" данных из удаленного хранилища, что создает нагрузку на CPU и память.

## Практические сценарии

Конфигурация `remote_read` и `remote_write` задается в файле `prometheus.yml`.

### `remote_write`: Отправка метрик

Секция `remote_write` настраивает отправку метрик из Prometheus в одно или несколько удаленных хранилищ.

**Ключевые параметры:**
-   `url`: URL-адрес эндпоинта удаленного хранилища.
-   `remote_timeout` (default: `30s`): Таймаут для одного запроса на удаленную запись.
-   `write_relabel_configs`: Позволяет модифицировать или фильтровать метки перед отправкой. Синтаксис аналогичен `relabel_configs`.
-   **Аутентификация:**
    -   `basic_auth`:
        -   `username`: Имя пользователя для Basic-аутентификации.
        -   `password`: Пароль для Basic-аутентификации.
    -   `bearer_token`: Токен для Bearer-авторизации.
    -   `bearer_token_file`: Файл, содержащий токен для Bearer-авторизации.
    -   `proxy_url`: Адрес proxy-сервера.
    -   `tls_config`: Конфигурация TLS для безопасного подключения.
        -   `insecure_skip_verify` (default: `false`): Проверять ли валидность сертификата.
        -   `ca_file`: Путь к файлу с корневыми сертификатами (CA).
        -   `cert_file`: Путь к файлу с клиентским сертификатом.
        -   `key_file`: Путь к файлу с клиентским ключом.
        -   `server_name`: Имя сервера для проверки в сертификате.

### `remote_read`: Чтение метрик

Секция `remote_read` позволяет настроить Prometheus на чтение данных из удаленного хранилища.

**Ключевые параметры:**
-   `url`: URL-адрес эндпоинта для удаленного чтения.
-   `remote_timeout` (default: `1m`): Максимальное время ожидания ответа.
-   `read_recent` (default: `false`): Определяет, нужно ли запрашивать данные, которые уже есть в локальном хранилище. Включение может быть полезно для заполнения пробелов, но создает дополнительную нагрузку.
-   `required_matchers`: Список меток, которые должны присутствовать в запросе, чтобы он был направлен в удаленное хранилище. Позволяет ограничить запросы к внешним системам.
-   **Аутентификация и безопасность:** Аналогичны `remote_write` (`basic_auth`, `bearer_token`, `tls_config` и т.д.).

## Дополнительная информация

### Управление очередью `remote_write`

Для обеспечения надежной доставки метрик `remote_write` использует внутреннюю очередь. Ее поведением можно управлять через блок `queue_config`.

-   `capacity` (default: `500`): Количество сэмплов, буферизуемых в памяти перед отправкой.
-   `max_shards` (default: `1000`): Максимальное количество параллельных потоков (шардов) для отправки данных. Увеличение повышает пропускную способность, но и потребление ресурсов.
-   `min_shards` (default: `1`): Минимальное количество шардов.
-   `max_samples_per_send` (default: `100`): Максимальное число сэмплов в одном батче.
-   `batch_send_deadline` (default: `5s`): Максимальное время ожидания сэмпла в буфере.
-   `min_backoff` (default: `30ms`): Начальная задержка перед повторной попыткой после сбоя. Удваивается с каждой неудачной попыткой.
-   `max_backoff` (default: `100ms`): Максимальная задержка между повторными попытками.

### Экосистема: Поддерживаемые хранилища

Prometheus может интегрироваться с большим количеством систем. Некоторые из них:

-   AppOptics: `write`
-   Azure Data Explorer: `read` and `write`
-   Chronix: `write`
-   Cortex: `read` and `write`
-   CrateDB: `read` and `write`
-   Elasticsearch: `write`
-   Gnocchi: `write`
-   Graphite: `write`
-   InfluxDB: `read` and `write`
-   IRONdb: `read` and `write`
-   Kafka: `write`
-   M3DB: `read` and `write`
-   OpenTSDB: `write`
-   PostgreSQL/TimescaleDB: `read` and `write`
-   SignalFx: `write`
-   Splunk: `read` and `write`
-   TiKV: `read` and `write`
-   **Thanos**: `write` (и `read` через Query-компонент)
-   **VictoriaMetrics**: `write` (и `read`)
-   Wavefront: `write`
