# Logstash

Logstash является частью Elastic Stack и представляет собой серверный конвейер обработки данных (Dataflow Engine), который позволяет принимать, обрабатывать и отправлять данные из множества источников.

## Основные характеристики

- **Модульность:** Функциональность расширяется с помощью плагинов. Практически все в Logstash является плагином (вводы, фильтры, выводы, кодеки).
- **Масштабируемость и отказоустойчивость:** Logstash может работать в кластере. Он не хранит данные постоянно, но может использовать персистентную очередь на диске для предотвращения потери сообщений при сбоях.
- **Централизованная обработка:** Позволяет вынести тяжелые операции по обработке (парсинг, обогащение) с агентов на выделенный пул серверов Logstash.

## Архитектура конвейера (Pipeline)

Каждый конвейер в Logstash состоит из трех основных секций:

1.  **Input (Ввод):** Описывает, откуда и как получать данные. Может быть несколько вводов.
2.  **Filter (Фильтр):** Опциональная секция для обработки, изменения и обогащения данных.
3.  **Output (Вывод):** Описывает, куда отправлять обработанные данные.

В одном инстансе Logstash может быть запущено несколько конвейеров.

### Input-плагины

Некоторые популярные плагины:
- `beats`: Для приема данных от агентов Elastic (Filebeat, Metricbeat и т.д.).
- `file`: Чтение из файлов.
- `kafka`: Чтение из топиков Kafka.
- `jdbc`: Получение данных из баз данных через JDBC.
- `syslog`: Прием данных по протоколу Syslog.
- `http`: Прием данных по HTTP.
- `tcp`/`udp`: Прием данных по TCP/UDP.

### Filter-плагины

Наиболее распространенные фильтры:
- **`grok`**: Мощный инструмент для парсинга неструктурированных текстовых данных с помощью регулярных выражений и готовых паттернов.
- **`dissect`**: Более простой и быстрый способ парсинга структурированных строк на основе разделителей.
- **`mutate`**: Позволяет выполнять общие преобразования: переименование, удаление, добавление полей.
- **`json`**: Парсинг JSON-строк в структуру Logstash.
- **`geoip`**: Обогащение данных геолокационной информацией на основе IP-адреса.
- **`aggregate`**: Агрегация нескольких событий в одно.

### Output-плагины

Популярные плагины для вывода:
- `elasticsearch`: Отправка данных в Elasticsearch (основной сценарий использования).
- `kafka`: Отправка данных в Kafka.
- `file`: Запись в файл.
- `http`: Отправка данных на HTTP-эндпоинт.
- `s3`: Запись в Amazon S3.
- `zabbix`: Отправка данных в Zabbix (через zabbix trapper).

## Конфигурация

- **`logstash.yml`**: Основной конфигурационный файл для настроек самого Logstash (настройки API, количество воркеров, пути).
- **`pipelines.yml`**: Определяет, какие конвейеры запускать и где находятся их конфигурационные файлы.
- **`*.conf`**: Файлы с описанием логики конвейеров (секции `input`, `filter`, `output`).
- **`jvm.options`**: Настройки Java Virtual Machine (например, размер хипа `Xms`, `Xmx`).

## Производительность и недостатки

- **Ресурсоемкость:** Logstash написан на Java и работает на JVM, что делает его довольно требовательным к CPU и оперативной памяти.
- **Сложность:** Конфигурация и отладка, особенно с использованием `grok`, может быть сложной.

## Сравнение с Vector

- **Функциональность:** Logstash обладает значительно более богатым набором плагинов и возможностей "из коробки".
- **Производительность:** Существенно уступает Vector в скорости обработки данных и потреблении ресурсов.

**Вывод:** Logstash является мощным и гибким решением, которое подходит для сложных сценариев обработки логов, где требуется богатая функциональность, и есть возможность выделить под него значительные ресурсы.

Для более детального сравнения см. заметку **[Сравнение Logstash и Vector](./logstash_vs_vector.md)**.

## Использование для извлечения метрик

Logstash, как часть стека ELK/Elastic, часто используется в стратегии сбора метрик из логов. С помощью фильтров (`grok`, `dissect`, `mutate`) он может парсить текстовые логи, извлекать из них числовые значения и преобразовывать их в метрики, которые затем можно агрегировать и визуализировать в Kibana или Grafana.

**Пример:**
Из строки лога Nginx можно извлечь код ответа, и Logstash может посчитать количество 5xx ошибок за определенный промежуток времени.

Несмотря на гибкость, этот подход является **самым ресурсоемким** по сравнению с Push- и Pull-моделями сбора метрик.

> Подробное сравнение различных стратегий сбора метрик рассмотрено в заметке: **[Стратегии сбора метрик](../Concepts/metrics_collection_strategies.md)**.
