# Сравнение Logstash и Vector

Эта заметка основана на лекции курса "Observability: мониторинг, логирование, трейсинг".

## Ключевые концепции

И Logstash, и Vector являются агрегаторами данных, предназначенными для сбора, обработки и перенаправления логов и других событий в централизованные системы хранения. Они выступают в роли промежуточного слоя, который позволяет выполнять сложные манипуляции с данными, не нагружая агентов, работающих непосредственно на источниках.

---

## Logstash

**Logstash** — это компонент Elastic Stack, написанный на Java (JRuby). Он представляет собой dataflow engine, который обрабатывает данные в рамках пайплайнов.

### Архитектура

Пайплайн Logstash состоит из трех основных секций:

1.  **Input**: Определяет, откуда и как получать данные. Существует множество плагинов для различных источников:
    *   `beats`: для приема данных от Filebeat, Metricbeat и т.д.
    *   `kafka`, `rabbitmq`: для чтения из брокеров сообщений.
    *   `file`: для чтения из файлов.
    *   `syslog`, `tcp`/`udp`: для приема сетевых логов.
    *   `jdbc`: для получения данных из баз данных.
    *   И многие другие (облачные провайдеры, HTTP и т.д.).

2.  **Filter**: Опциональная секция для преобразования данных. Это самая мощная часть Logstash.
    *   **Парсинг**: `grok` (на основе regex), `dissect` (на основе разделителей), `json`, `csv`, `xml`.
    *   **Обогащение**: `geoip` (добавление гео-информации по IP), `mutate` (добавление, удаление, переименование полей).
    *   **Трансформация**: `aggregate` (объединение нескольких событий в одно), `throttle` (ограничение потока сообщений).

3.  **Output**: Определяет, куда отправлять обработанные данные.
    *   `elasticsearch`: основное хранилище в ELK стеке.
    *   `kafka`, `rabbitmq`: отправка в брокеры сообщений.
    *   `file`, `s3`: сохранение в файлы или объектное хранилище.
    *   `email`, `exec`: для систем оповещений или выполнения внешних скриптов.

### Сильные стороны

*   **Богатая экосистема**: Огромное количество официальных и сторонних плагинов для любых источников, преобразований и хранилищ.
*   **Гибкость**: Мощные фильтры, особенно `grok`, позволяют парсить практически любые неструктурированные форматы логов.
*   **Интеграция**: Бесшовная интеграция с Elastic Stack (Elasticsearch, Kibana).

### Слабые стороны

*   **Производительность**: Будучи написанным на JRuby и работая на JVM, Logstash потребляет значительно больше CPU и RAM по сравнению с конкурентами.
*   **Сложность**: Конфигурация и отладка, особенно сложных `grok`-паттернов, может быть трудоемкой.

## Vector

**Vector** — это высокопроизводительный инструмент для сбора, преобразования и маршрутизации логов и метрик, написанный на Rust.

### Архитектура

Топология Vector состоит из трех компонентов:

1.  **Sources**: Источники данных (аналог Inputs в Logstash).
    *   `file`, `journald`, `kafka`, `prometheus`, `syslog`, `tcp`, `udp` и др.

2.  **Transforms**: Компоненты для обработки и изменения данных (аналог Filters в Logstash).
    *   `remap`: Основной язык преобразований в Vector (VRL - Vector Remap Language), позволяет парсить (`parse_json`, `parse_grok`), изменять, фильтровать данные.
    *   `filter`: Простое удаление событий по условию.
    *   `throttle`: Ограничение потока.

3.  **Sinks**: Получатели данных (аналог Outputs в Logstash).
    *   `elasticsearch`, `clickhouse`, `loki`, `kafka`, `aws_s3` и др.

### Сильные стороны

*   **Высокая производительность**: Написан на Rust, что обеспечивает минимальное потребление ресурсов (CPU/RAM) и высокую пропускную способность. Значительно превосходит Logstash по скорости обработки.
*   **Надежность**: Встроенные механизмы буферизации (на диске или в памяти) для предотвращения потери данных.
*   **Простота**: Более простая и декларативная конфигурация в формате TOML, YAML или JSON.

### Слабые стороны

*   **Меньшая функциональность**: Хотя количество интеграций постоянно растет, оно все еще уступает Logstash. Некоторые сложные или экзотические сценарии могут быть нереализуемы.
*   **Молодая экосистема**: Сообщество и количество готовых решений меньше, чем у Logstash.

## Сравнение и выводы

| Характеристика      | Logstash                               | Vector                                       |
| ------------------- | -------------------------------------- | -------------------------------------------- |
| **Язык**            | JRuby (на JVM)                         | Rust                                         |
| **Производительность** | Низкая                                 | Очень высокая (в разы быстрее Logstash)      |
| **Потребление ресурсов** | Высокое (CPU, RAM)                     | Низкое                                       |
| **Функциональность**  | Очень высокая, огромное число плагинов | Хорошая, но уступает Logstash                |
| **Конфигурация**    | Собственный формат, может быть сложной | TOML, YAML, JSON, более простая и декларативная |
| **Экосистема**      | Зрелая, часть Elastic Stack            | Растущая, сильное сообщество                 |

### Когда что выбирать?

*   **Logstash**:
    *   Если вы уже глубоко интегрированы в **Elastic Stack**.
    *   Если вам нужна **экзотическая функциональность** или плагин, которого нет в Vector.
    *   Если производительность и потребление ресурсов **не являются критическим** фактором.

*   **Vector**:
    *   Если **производительность и низкое потребление ресурсов** являются главным приоритетом (например, при работе в качестве агента на хостах или в resource-constrained окружениях).
    *   Для большинства **стандартных сценариев** сбора, обработки и перенаправления логов.
    *   Если вам нужна гибкая маршрутизация данных в **различные системы хранения** (не только Elasticsearch).
