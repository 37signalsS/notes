# Гарантии доставки в очередях сообщений

Гарантии доставки — это фундаментальная концепция в мире брокеров сообщений, определяющая компромисс между надежностью и производительностью. Общие принципы работы очередей описаны в соответствующем документе:

* **[Принципы работы очередей сообщений](./message_queues_principles.md)**

## Определения

* **At-most-once (не более одного раза)**: Сообщение доставляется 0 или 1 раз. При сбоях возможны потери, но дубликаты исключены.
  * **Приоритет**: Минимальная задержка и производительность.
  * **Риск**: Потеря данных.

* **At-least-once (не менее одного раза)**: Сообщение гарантированно будет доставлено 1 или более раз. Потери исключены, но возможны дубликаты.
  * **Приоритет**: Надёжность доставки.
  * **Требование**: Идемпотентность на стороне потребителя.

* **Exactly-once (ровно один раз)**: Каждое сообщение влияет на состояние системы ровно один раз. Это семантика, а не "магический" протокол; она достигается комбинацией идемпотентности, транзакций и специальных механизмов брокера.
  * **Приоритет**: Строгая консистентность.
  * **Требование**: Сложная настройка и поддержка со стороны всей системы.

### Сравнительная таблица

| Гарантия | Риск потери | Риск дубликатов | Нагрузка/Латентность | Типичные случаи |
| :--- | :--- | :--- | :--- | :--- |
| **At-most-once** | Да | Нет | Минимальная | Сбор некритичных метрик, телеметрия с допускаемой потерей. |
| **At-least-once**| Нет | Да | Средняя | Оркестрация задач, обработка заказов, биллинг с идемпотентным обновлением. |
| **Exactly-once** | Нет | Нет | Высокая | Критически важные финансовые транзакции, консистентные пайплайны обработки событий. |

## Основные концепции

### Достижение гарантий в RabbitMQ

* **At-most-once**:
  * **Продьюсер**: Отправка без ожидания подтверждения (`publisher confirms` выключен).
  * **Консьюмер**: `auto_ack=true`. Брокер считает сообщение доставленным сразу после отправки. Если консьюмер упадёт до завершения обработки, сообщение будет утеряно.

* **At-least-once**:
  * **Продьюсер**: Включает `publisher confirms`, чтобы гарантировать доставку до брокера.
  * **Консьюмер**: `auto_ack=false` (ручное подтверждение). Консьюмер отправляет `ack` только после полной и успешной обработки. Если он падает, брокер повторно доставит сообщение другому (или этому же после перезапуска) консьюмеру.

* **Exactly-once**:
  * RabbitMQ **не обеспечивает** семантику "ровно один раз" на уровне брокера. Эта гарантия достигается исключительно на прикладном уровне за счёт **идемпотентности** консьюмера:
    * Дедупликация по уникальному ключу сообщения (message ID).
    * Использование транзакций в базе данных или `UPSERT` операций.
    * Применение паттерна **Outbox** для атомарного обновления состояния в БД и отправки сообщения.

### Достижение гарантий в Kafka

* **At-most-once**:
  * **Консьюмер**: Коммит оффсета *до* обработки сообщения. Если во время обработки произойдёт сбой, сообщение будет считаться прочитанным и потеряется.

* **At-least-once**:
  * **Продьюсер**: Включает идемпотентность (`enable.idempotence=true`), чтобы избежать дублей при ретраях отправки.
  * **Консьюмер**: Коммит оффсета *после* успешной обработки сообщения. При сбое до коммита, сообщение будет обработано повторно.

* **Exactly-once (EOS)**:
  * Достигается на уровне Kafka для сценариев "чтение-обработка-запись" (`read-process-write`).
  * **Компоненты**:
    1. **Идемпотентный продюсер** (`enable.idempotence=true`): Предотвращает дубли при отправке.
    2. **Транзакции**: Продюсер оборачивает цикл "прочитал-обработал-отправил" в транзакцию.
    3. **Атомарный коммит**: В рамках одной транзакции продюсер отправляет новые сообщения в выходной топик и коммитит оффсеты прочитанных сообщений из входного топика.
  * **Настройка**:
    * **Producer**: `transactional.id` должен быть уникален. `acks` должен быть `all`.
    * **Consumer**: `enable.auto.commit=false`. Для чтения данных, записанных в рамках EOS, используется `isolation.level=read_committed`, чтобы не видеть "грязных" данных из незавершённых транзакций.

## Практические сценарии

### RabbitMQ: At-least-once консьюмер

```python
import pika

conn = pika.BlockingConnection(pika.ConnectionParameters('mq'))
ch = conn.channel()
ch.basic_qos(prefetch_count=1) # Обрабатывать по одному сообщению за раз

def handle(ch, method, properties, body):
    # process(body) - это идемпотентная функция
    try:
        process(body)
        # Отправляем подтверждение только после успеха
        ch.basic_ack(delivery_tag=method.delivery_tag)
    except:
        # Не подтверждаем сообщение, чтобы оно было доставлено повторно
        # Можно отправить nack с requeue=False для отправки в DLQ
        pass

ch.basic_consume(queue='tasks', on_message_callback=handle, auto_ack=False)
ch.start_consuming()
```

### Kafka: Exactly-once обработка

```python
from confluent_kafka import Producer, Consumer

# Продюсер с поддержкой транзакций
producer = Producer({
    'bootstrap.servers': 'kafka:9092',
    'enable.idempotence': True,
    'acks': 'all',
    'transactional.id': 'my-transactional-app-1'
})
producer.init_transactions()

# Консьюмер с ручным коммитом и чтением только завершенных транзакций
consumer = Consumer({
    'bootstrap.servers': 'kafka:9092',
    'group.id': 'my-group-1',
    'enable.auto.commit': False,
    'isolation.level': 'read_committed'
})
consumer.subscribe(['input-topic'])

while True:
    msg = consumer.poll(1.0)
    if not msg:
        continue
    
    producer.begin_transaction()
    try:
        # 1. Обработка сообщения
        processed_value = transform(msg.value())
        
        # 2. Отправка результата в другой топик
        producer.produce('output-topic', value=processed_value)
        
        # 3. Коммит оффсета в рамках той же транзакции
        producer.send_offsets_to_transaction(
            [consumer.position(msg.topic(), msg.partition())],
            consumer.consumer_group_metadata()
        )
        
        # 4. Фиксация транзакции
        producer.commit_transaction()
    except Exception as e:
        # Откат транзакции при ошибке
        producer.abort_transaction()

```
