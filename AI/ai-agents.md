# ИИ-агенты (AI Agents)

## Определения

**ИИ-агент (AI Agent)** — автономная система на базе больших языковых моделей (LLM), способная самостоятельно планировать действия, использовать внешние инструменты (tools) и взаимодействовать с окружением для достижения поставленной цели. В отличие от простого чата, агент обладает циклом рассуждений и может изменять состояние систем.

**React (Reason-Act) Loop** — цикл «Рассуждение-Действие», в котором модель сначала обдумывает следующий шаг (`Think/Reason`), затем выполняет действие (`Act`), анализирует результат (`Observe`) и повторяет процесс до достижения результата (`Conclude`).

**Model Context Protocol (MCP)** — открытый стандарт для подключения ИИ-моделей к внешним источникам данных и инструментам. Позволяет один раз описать интерфейс инструмента (например, доступ к логам или Kubernetes API) и использовать его в любых агентских системах.

## Базовые концепции

### 1. Отличие Агента от Чата
*   **Чат:** Модель отвечает на запрос, сохраняя контекст только в рамках текущего диалога. Не имеет прямого доступа к инструментам (без внешних оберток).
*   **Агент:** Работает самостоятельно. Использует инструменты, контролирует цикл выполнения, обладает памятью и стремится к заданной цели (например, «исправь падение пода в namespace production»).

### 2. Память агента
Эффективному агенту требуется два типа памяти:
*   **Краткосрочная (Short-term memory / STM):** контекст текущей сессии или инцидента. Хранит историю вызовов инструментов и промежуточные рассуждения в рамках одного «забега» (run).
*   **Долгосрочная (Long-term memory / LTM):** хранение фактов, извлеченных из предыдущих сессий. Позволяет агенту «обучаться» на основе обратной связи (фидбека) и запоминать специфику инфраструктуры (например, «база данных X требует больше времени на прогрев»). Реализуется через векторные БД или внешние хранилища стейта (например, PostgreSQL). Для реляционного состояния, checkpointer/store, очередей и связанных настроек MVCC см. **[PostgreSQL для памяти ИИ-агентов](../Databases/PostgreSQL/Operations/agent-memory.md)**.

### 3. MCP (Model Context Protocol) — стандарт 2026
С версии 2026 протокол MCP претерпел важные изменения:
*   **Stateless (Без сохранения состояния):** Серверы MCP стали полностью stateless. Сессионные ID больше не привязаны к конкретным инстансам, что упрощает масштабирование (не требуются Sticky Sessions) и позволяет запускать MCP в Serverless-средах (AWS Lambda и др.).
*   **MCP Gateway:** Использование шлюзов для федерации инструментов. Позволяет объединять сотни MCP-серверов в единый каталог с централизованной аутентификацией (OAuth) и аудитом.
*   **Безопасность:** Инструменты должны следовать принципу наименьших привилегий. Рекомендуется использовать MCP-серверы только в режиме Read-Only для диагностических агентов.

## Практические сценарии

### RCA (Root Cause Analysis) агент
Использование агента для автоматического разбора инцидентов (MTTR сокращение с 45 до 6 минут):
1.  **Триггер:** Алерт из системы мониторинга (CloudWatch, Prometheus).
2.  **Сбор контекста:** Агент через MCP запрашивает логи, описание подов, архитектурную документацию из RAG.
3.  **Анализ:** Модель сопоставляет симптомы с известными проблемами (постмортемы в RAG) и ранбуками (Runbooks).
4.  **Результат:** Remediation Plan (план исправления) с доказательной базой для инженера.

#### Пример архитектуры (DKT 2026)
*   **Ядро:** AWS Bedrock Agent Core (Serverless).
*   **MCP Gateway:** Центральный узел с OAuth-авторизацией для доступа к:
    *   `Kubernetes MCP Server` (описание ресурсов, логи).
    *   `CloudWatch MCP Server` (метрики).
    *   `Knowledge Base (RAG) MCP Server` (доступ к архитектурным схемам и ранбукам).
*   **Хранилище стейта:** DynamoDB для сохранения сессий и отчетов об инцидентах.
*   **Observability:** Трассировка вызовов инструментов через AWS X-Ray или специализированные платформы (например, LangFuse) для анализа «хода мыслей» агента.

### Качество данных в RAG
Агенты критично зависят от качества данных в RAG-системе.
*   **Проблема «Garbage In, Garbage Out»:** Импорт устаревшей документации (Jira 10-летней давности) ведет к галлюцинациям агента.
*   **Решение:** Регулярная очистка и актуализация данных. Качество (релевантность) важнее количества документов.

## Дополнительная информация

### Безопасность и ограничения
*   **Циклические зависимости:** Необходим контроль количества итераций в React Loop для предотвращения бесконечных циклов и перерасхода токенов.
*   **Недетерминизм:** Ответы модели могут отличаться; критические действия (удаление ресурсов, изменение лимитов) всегда должны подтверждаться человеком или жесткими техническими гейтами.
*   **Токены:** Общение с моделью на английском языке эффективнее (экономит токены) по сравнению с русским из-за особенностей токенизации.
