# Определения

**Consul** — это облачно-нативная платформа от HashiCorp для обнаружения, конфигурации и обеспечения безопасности сервисов в гибридных и мультиоблачных средах. Он предоставляет единую панель управления для микросервисных архитектур, позволяя соединять сервисы, запущенные в Kubernetes, виртуальных машинах или на "голом железе" (bare metal).

# Основные концепции

Consul объединяет несколько критически важных функций для управления современной инфраструктурой:

- **[Архитектура на базе агентов](./consul_architecture.md):** Система состоит из **серверов**, поддерживающих состояние кластера через [протокол Raft](./consul_consensus.md), и **клиентов** (агентов), работающих на каждом узле. Агенты используют **Gossip Protocol (на базе Serf)** для быстрого обнаружения сбоев и управления членством в кластере без нагрузки на серверы.

- **[Каталог служб (Service Catalog)](./consul_service_catalog.md):** Центральный реестр "здоровых" экземпляров сервисов. Обнаружение происходит через DNS (Domain Name System) или HTTP API (Application Programming Interface), что исключает использование жестко прописанных IP (Internet Protocol) адресов.

- **[Проверки состояния (Health Checking)](./consul_health_checks.md):** Гибкие механизмы мониторинга (HTTP, TCP, gRPC, скрипты), которые позволяют Consul автоматически изолировать неисправные инстансы от трафика.

- **[KV-хранилище (Key/Value Store)](./consul_kv_store.md):** Иерархическое распределенное хранилище для динамической конфигурации, координации лидеров и управления флагами функций (`feature flags`).

- **Сервисная сетка (Consul Service Mesh):** Обеспечивает безопасное взаимодействие между сервисами с использованием mTLS (mutual Transport Layer Security). Для обработки трафика используются современные прокси-серверы (Envoy) или облегченный **Consul Dataplane**. Управление доступом осуществляется через политики **Service Intentions**. Подробнее в [обзоре Service Mesh](../Service_Mesh/service_mesh_concepts.md).

- **Безопасность (ACL):** Система контроля доступа (Access Control List) обеспечивает аутентификацию и авторизацию для всех операций в Consul (чтение KV, регистрация сервисов, доступ к API).

- **Мультикластерность и Multi-DC:** Поддерживает объединение нескольких дата-центров через WAN (Wide Area Network) федерацию или современный механизм **Cluster Peering**, обеспечивая глобальное обнаружение сервисов и [высокую доступность (High Availability)](../Concepts/High_Availability/ha_overview.md).

# Практические сценарии

### Динамическое обнаружение и балансировка

1. **Регистрация:** Приложение при запуске сообщает агенту Consul свои параметры (IP, порт, теги).
2. **Проверка:** Consul проверяет эндпоинт `/health` приложения.
3. **Обнаружение:** Другие сервисы запрашивают `api.service.consul` через DNS.
4. **Балансировка:** Consul возвращает список только тех IP, которые прошли проверку состояния, обеспечивая клиентскую балансировку нагрузки.

### Управление конфигурацией без перезагрузки

Consul KV позволяет хранить параметры приложения (например, уровень логирования или адрес БД). Приложения могут использовать утилиту `consul-template` для автоматического обновления конфигурационных файлов и перезапуска процессов при изменении данных в KV, либо подписываться на изменения через API.
