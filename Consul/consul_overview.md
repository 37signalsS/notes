# Определения

**Consul** — это комплексное решение от HashiCorp для обнаружения, подключения и защиты сервисов в динамических, распределенных средах, от физических серверов до Kubernetes.

# Базовые концепции

- **[Архитектура](./consul_architecture.md):** Consul работает на основе **агентов**, которые запускаются на каждом узле. **Серверы** поддерживают состояние кластера с помощью [протокола консенсуса Raft](./consul_consensus.md), а **клиенты** выполняют локальные задачи и проксируют запросы.

- **[Обнаружение сервисов (Service Discovery)](./consul_service_catalog.md):** Предоставляет централизованный **каталог служб** для регистрации и обнаружения сервисов через DNS или HTTP API, устраняя необходимость в статических IP-адресах.

- **[Проверка состояния (Health Checking)](./consul_health_checks.md):** Постоянно отслеживает работоспособность сервисов и узлов. Неработоспособные экземпляры автоматически исключаются из списка доступных.

- **[Хранилище "ключ-значение" (Key/Value Store)](./consul_kv_store.md):** Распределенное иерархическое хранилище для динамической конфигурации, флагов функций (`feature flags`) и координации сервисов.

- **Сервисная сетка (Service Mesh):** Через компонент **Consul Connect** обеспечивает безопасное mTLS-шифрование трафика, L7-маршрутизацию и политики контроля доступа (Intentions).

- **Поддержка нескольких ЦОД:** Изначально спроектирован для работы в географически распределенных средах, объединяя сервисы из разных дата-центров через WAN-федерацию.

# Практические сценарии

### Динамическое обнаружение сервиса

1. **Регистрация:** Сервис `backend` при старте регистрируется в Consul, сообщая свой IP и порт.
2. **Проверка:** Агент Consul на узле `backend` периодически проверяет его работоспособность.
3. **Обнаружение:** Сервис `frontend` запрашивает у Consul адрес `backend`.
4. **Ответ:** Consul возвращает актуальный адрес работоспособного экземпляра `backend`. Если их несколько, `frontend` получает список и может балансировать нагрузку.
