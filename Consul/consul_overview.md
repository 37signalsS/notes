# Определения

**Consul** — это комплексное решение от HashiCorp для обнаружения, подключения и защиты сервисов в динамических, распределенных средах, от физических серверов до Kubernetes.

# Базовые концепции

## Архитектура

Consul работает на основе **агентов**, которые запускаются на каждом узле и поставляются в виде одного бинарного файла. Агенты могут работать в двух режимах:

*   **Сервер (Server):** Отвечает за хранение состояния кластера, информации о сервисах и данных K/V-хранилища. Серверы образуют кворум на основе алгоритма консенсуса [Raft](../Concepts/raft_consensus_algorithm.md) для обеспечения отказоустойчивости. Рекомендуется от 3 до 5 серверов в кластере.
*   **Клиент (Client):** Легковесный агент, который перенаправляет запросы серверам, выполняет проверки состояния локальных сервисов и кэширует результаты для ускорения работы.

## Ключевые возможности

*   **Обнаружение сервисов (Service Discovery):** Предоставляет централизованный реестр для регистрации сервисов. Другие приложения могут находить актуальные IP-адреса и порты через DNS-интерфейс или HTTP API, что устраняет необходимость жестко прописывать сетевые адреса.
*   **Проверка состояния (Health Checking):** Постоянно отслеживает работоспособность сервисов с помощью различных проверок (от TCP-соединения до выполнения скриптов). Неработоспособные экземпляры автоматически исключаются из списка доступных.
*   **Хранилище "ключ-значение" (Key/Value Store):** Распределенное иерархическое хранилище для динамической конфигурации, флагов функций (feature flags) и координации сервисов. Может использоваться как бэкенд для [Vault](../Vault/overview.md).
*   **Сервисная сетка (Service Mesh):** Через компонент **Consul Connect** обеспечивает безопасное mTLS-шифрование трафика между сервисами, L7-маршрутизацию и политики контроля доступа (Intentions).
*   **Поддержка нескольких ЦОД:** Изначально спроектирован для работы в географически распределенных средах, объединяя сервисы из разных дата-центров.

## Управление и безопасность

*   **Веб-интерфейс (UI):** Предоставляет удобный интерфейс для мониторинга состояния сервисов, узлов и просмотра K/V-хранилища.
*   **Токены безопасности:** Используются для контроля доступа и предотвращения несанкционированного присоединения узлов к кластеру.

# Практические сценарии

### Динамическое обнаружение сервиса

1.  **Регистрация:** Сервис `backend` при старте регистрируется в Consul, сообщая свой IP и порт.
2.  **Проверка:** Агент Consul на узле `backend` периодически проверяет его работоспособность.
3.  **Обнаружение:** Сервис `frontend` запрашивает у Consul адрес `backend`.
4.  **Ответ:** Consul возвращает актуальный адрес работоспособного экземпляра `backend`. Если их несколько, `frontend` получает список и может балансировать нагрузку.
