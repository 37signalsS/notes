# Определения

**Механизм консенсуса** в Consul отвечает за поддержание согласованного (consistent) и отказоустойчивого состояния между серверами кластера. Для этой цели Consul использует протокол **Raft**. Это фундаментальный механизм для обеспечения [высокой доступности (High Availability)](../Concepts/High_Availability/ha_overview.md) в распределенных системах.

Все критичные данные — [каталог сервисов](./consul_service_catalog.md), [KV-хранилище](./consul_kv_store.md), ACL, конфигурация Connect — проходят через реплицируемый лог Raft, что гарантирует их целостность при сбоях отдельных серверов.

# Основные концепции

## Принципы Raft в Consul

- **Кворум:** Только **серверы** Consul участвуют в Raft-кворуме. Для отказоустойчивости кластера из `N` серверов необходимо, чтобы `(N/2)+1` серверов были работоспособны. Рекомендуемое число серверов — 3 или 5.
- **Лидер и последователи:** В каждый момент времени в кворуме есть только один **лидер** (`Leader`), который принимает все запросы на запись. Остальные серверы являются **последователями** (`Followers`) и пассивно реплицируют данные от лидера.
- **Термы и выборы:** Жизненный цикл кластера разделен на **термы** (`terms`) — периоды времени с монотонно возрастающим номером. Если последователи перестают получать "хартбиты" от лидера, они инициируют новые выборы, становясь **кандидатами** (`Candidate`).

## Процесс репликации записи

1. Запрос на изменение (например, `consul kv put`) поступает на лидера.
2. Лидер добавляет операцию в свой локальный лог.
3. Лидер рассылает запись (`AppendEntries` RPC) всем последователям.
4. Последователи подтверждают получение и запись в свой лог.
5. Когда лидер получает подтверждение от большинства (кворума), запись считается **закоммиченной** (`committed`).
6. Лидер применяет изменение к своей конечной машине состояний (state machine) и уведомляет клиента об успехе.

## Безопасность и целостность

Raft обеспечивает следующие гарантии:

- **Единственность лидера (Leader Safety):** В одном терме не может быть двух лидеров.
- **Защита от split-brain:** В случае сетевого разделения только та часть кластера, которая сохранила кворум, сможет выбрать лидера и продолжить обрабатывать запросы на запись.
- **Согласованность лога (Log Matching):** Если записи в логах разных серверов имеют одинаковый индекс и терм, то все предыдущие записи также совпадают.

## Снапшоты и компакция лога

Чтобы реплицируемый лог не рос бесконечно, Consul периодически создает **снапшоты** (снимок текущего состояния) и удаляет старые записи лога (**компакция**), которые уже были включены в снапшот.

# Практические сценарии

## Режимы согласованности чтения

Consul предоставляет несколько режимов для чтения данных:

- `default`: Оптимизированный режим, балансирующий между скоростью и актуальностью. Запрос может быть обслужен любым сервером.
- `stale`: Чтение с любого сервера без проверки у лидера. Самый быстрый, но может вернуть устаревшие данные.
- `consistent`: Чтение, направленное к лидеру. Гарантирует получение самой последней закоммиченной версии данных.

```bash
# Чтение с гарантированной согласованностью
consul kv get -consistent my-key
```

## Управление кластером

Команды для диагностики и управления Raft-кластером.

```bash
# Посмотреть список участников кворума и текущего лидера
consul operator raft list-peers

# Удалить "мертвый" узел из кворума (если Autopilot не справился)
consul operator raft remove-peer <NodeID>
```

## Конфигурация сервера

Пример минимальной конфигурации для серверного узла:
```json
{
  "server": true,
  "bootstrap_expect": 3,
  "datacenter": "dc1",
  "retry_join": ["10.0.1.1", "10.0.1.2", "10.0.1.3"]
}
```

- `bootstrap_expect`: Указывает Consul ожидать указанное количество серверов перед тем, как инициировать кворум.

Современные версии Consul включают механизм **Autopilot**, который автоматизирует многие задачи по управлению кластером, такие как очистка неработающих серверов и управление обновлениями.

Подробнее о том, как консенсус вписывается в общую архитектуру Consul, см. в [обзоре архитектуры](./consul_architecture.md). Детали реализации от HashiCorp доступны в [официальной документации](https://developer.hashicorp.com/consul/docs/architecture/consensus), а визуализация алгоритма Raft — на [raft.github.io](https://raft.github.io/).
