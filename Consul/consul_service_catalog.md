# Определения

**Каталог служб (Service Catalog)** в Consul — это централизованный реестр, содержащий информацию обо всех зарегистрированных сервисах, их экземплярах (инстансах), метаданных, сетевых адресах (IP, порт) и [статусах работоспособности](./consul_health_checks.md). Каталог является фундаментом для механизма обнаружения сервисов (Service Discovery).

# Основные концепции

## Ключевые сущности каталога

| Сущность | Описание | Основные поля |
| :--- | :--- | :--- |
| **Datacenter (DC)** | Логическая группа узлов, обычно соответствующая физическому ЦОД или региону облака. | `name` |
| **Admin Partition** | (Enterprise) Высший уровень изоляции для разделения административных границ внутри одного DC. | `name` |
| **Namespace** | Логическая изоляция внутри раздела (Partition) для разных команд или окружений. | `name`, `partition` |
| **Node** | Узел (хост), на котором запущен агент Consul. | `Node`, `Address`, `Meta` |
| **Service** | Логическое определение приложения. Один сервис может иметь множество инстансов. | `Name`, `ID`, `Address`, `Port`, `Tags`, `Meta` |

**Имя (Name) vs Идентификатор (ID):**
- `Name` — общее имя сервиса (например, `api-gateway`). Инстансы с одинаковым `Name` формируют пул для балансировки.
- `ID` — уникальный ключ конкретного инстанса на узле (например, `api-gateway-node-1`).

## Мультипортовые сервисы (Consul 1.22+)

Современные версии Consul поддерживают регистрацию нескольких портов для одного сервиса. Это позволяет обращаться к разным эндпоинтам (например, `http`, `grpc`, `metrics`) через одно имя сервиса, используя именованные порты в DNS или API.

## Изоляция и многоарендность (Multi-tenancy)

Для управления сложными инфраструктурами Consul использует иерархическую модель изоляции:
1. **Admin Partitions:** Позволяют разным организациям или крупным подразделениям использовать один кластер Consul, сохраняя полную независимость настроек и ACL.
2. **Namespaces:** Используются внутри разделов для группировки микросервисов. Возможна автоматическая синхронизация пространств имен из Kubernetes.
3. **Sameness Groups:** Позволяют объединять идентичные сервисы из разных разделов или пиринговых кластеров в единую логическую сущность для упрощения маршрутизации.

## Регистрация и синхронизация

Регистрация данных в каталоге может выполняться:
- **Статически:** через конфигурационные файлы HCL при запуске агента.
- **Динамически:** через HTTP API или CLI локального агента.
- **Автоматически (Catalog Sync):** Специализированные компоненты (например, `consul-k8s`) могут автоматически синхронизировать сервисы из Kubernetes в каталог Consul и обратно.

# Практические сценарии

## Регистрация сервиса (HCL)

Пример определения сервиса в файле `web.hcl`:

```hcl
service {
  name    = "web"
  id      = "web-1"
  address = "10.0.1.12"
  port    = 80
  tags    = ["frontend", "v2"]
  meta    = { team = "webapp", version = "2.1.0" }

  check {
    name     = "http-health"
    http     = "http://10.0.1.12/health"
    interval = "10s"
    timeout  = "2s"
  }
}
```

Команда для регистрации:
```bash
consul services register ./web.hcl
```

## Способы обнаружения

### HTTP API

- **Список всех сервисов:** `GET /v1/catalog/services`
- **Все инстансы конкретного сервиса:** `GET /v1/catalog/service/<service_name>`
- **Только работоспособные (passing) инстансы:** `GET /v1/health/service/<service_name>?passing`

Для критически важных систем рекомендуется использовать параметр `?consistent` для получения данных от лидера Raft, иначе Consul может вернуть данные в режиме `stale` (с минимальной задержкой).

### DNS Интерфейс

Consul предоставляет встроенный DNS-сервер (порт 8600):
- **A-записи:** `web.service.consul` — возвращает IP всех здоровых инстансов.
- **SRV-записи:** `_web._tcp.service.consul` — возвращает IP, порты и веса инстансов.
- **Теги:** `v2.web.service.consul` — поиск по конкретному тегу.

Пример проверки через `dig`:
```bash
dig @127.0.0.1 -p 8600 web.service.consul
```

### Фильтрация и запросы

API поддерживает мощный язык фильтрации. Пример запроса инстансов с определенной версией в метаданных:
```bash
curl "http://localhost:8500/v1/catalog/service/web?filter=Service.Meta.version==\"2.1.0\""
```
