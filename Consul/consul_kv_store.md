**Актуально для:** Consul 1.22.x / 1.20.x / 1.19.x

# Consul KV Store

## Определения

**Consul KV (Key-Value Store)** — встроенное распределённое иерархическое хранилище для динамической конфигурации, управления флагами функций (`feature flags`), координации распределённых систем и реализации паттерна выбора лидера (Leader Election). Все записи реплицируются между серверами через [протокол консенсуса Raft](./consul_consensus.md) и хранятся в состоянии [Finite State Machine (FSM)](./consul_consensus.md) на серверных узлах.

В инфраструктуре Consul KV выполняет роль «распределённого `/etc`», обеспечивая строгую согласованность и высокую доступность для критически важных метаданных.

## Основные концепции

### Модель данных

- **Иерархические ключи:** Ключи формируют плоское пространство имён с использованием разделителя `/` для организации (аналогично S3, а не файловой системе). Пример: `config/prod/database/url`.
- **Значения:** Непрозрачные бинарные данные. Лимит размера — **512 КБ** на один ключ. Для хранения больших объектов используйте внешние артефакты, оставляя в KV только ссылки или хеши.
- **Флаги (`Flags`):** Беззнаковое 64-битное целое (`0` – `2^64-1`), сохраняемое вместе со значением. Consul не интерпретирует флаги; используется приложениями для хранения метаданных (версия схемы, тип контента, кодировка).
- **Система индексов:**
  - `CreateIndex` — номер записи в логе Raft на момент создания ключа.
  - `ModifyIndex` — номер последнего изменения. Является основой для механизмов `watch` и атомарных операций CAS. Совпадает с заголовком `X-Consul-Index` в HTTP-ответах.
  - `LockIndex` — количество успешных захватов ключа сессией.

### Согласованность чтения

Consul предоставляет три режима для операций чтения:

- `default` — баланс производительности и согласованности. Запрос обрабатывается лидером, который подтверждает свой статус внутренним тайм-аутом. Гарантирует строгую согласованность в отсутствие разделения сети.
- `stale` — максимальная производительность. Чтение выполняется любым сервером, включая последователей. Допускает задержку данных на несколько миллисекунд, но снижает нагрузку на Raft-кворум.
- `consistent` — максимальная надёжность. Требует подтверждения лидерства через кворум для каждого запроса. Гарантирует отсутствие «грязного» чтения.

### Атомарность и транзакции

- **Check-And-Set (CAS):** Обновление ключа выполняется только при совпадении переданного `ModifyIndex` с текущим значением. Предотвращает состояние гонки при конкурентных изменениях.
- **Транзакции (`/v1/txn`):** Атомарный блок до **64 операций** (`set`, `cas`, `delete`, `delete-tree`, `lock`, `unlock`, `check-session` и др.). При ошибке любой операции весь блок отклоняется.

### Сессии и блокировки

Механизм **сессий** обеспечивает распределённые блокировки и семафоры:

1. **Создание сессии:** Указываются `Name`, `Node`, `Checks` (зависимости от health checks) и `TTL` (от 10 секунд до 24 часов).
2. **Поддержание:** Клиент обязан периодически продлевать сессию (`renew`), иначе она истекает по `TTL` или при отказе связанных проверок.
3. **Захват (`acquire`):** Запись с параметром `?acquire=<session_id>`. При успехе ключ привязывается к сессии, `LockIndex` увеличивается.
4. **Освобождение (`release`):** Очистка привязки сессии без изменения значения ключа. `LockIndex` не меняется.
5. **Поведение при истечении (`Behavior`):**
   - `release` (по умолчанию) — блокировка снимается, ключ сохраняется.
   - `delete` — ключ автоматически удаляется. Полезно для временных записей.

Это основа для паттерна **выбора лидера (Leader Election)**.

### Изоляция (Enterprise)

В Enterprise-версии доступны **Namespaces** и **Admin Partitions** для логического разделения KV-пространств между командами или окружениями в рамках одного кластера. Порядок разрешения namespace при запросе:

1. Параметр запроса `ns`
2. Заголовок `X-Consul-Namespace`
3. Namespace токена, использованного в запросе
4. `default`

### Валидация ключей (Consul 1.22+)

Начиная с Consul 1.22.0, по умолчанию запрещены:
- экранирование путей (`..`, `//`)
- ведущие и завершающие пробелы

Для обратной совместимости используйте параметр конфигурации `disable_kv_key_validation = true`.

## Практические сценарии

### Предварительные требования

- Работающий кластер Consul (серверы и клиенты)
- ACL включены и загружены политики для целевых префиксов
- Доступ к `data_dir` на серверах для резервного копирования
- Права на перезапуск служб Consul при изменении конфигурации агентов

### Управление ключами через CLI

```bash
# Запись значения с флагом
consul kv put -flags=42 config/app/max_connections 100

# Чтение в режиме stale
consul kv get -stale config/app/max_connections

# Рекурсивное чтение метаданных
consul kv get -recurse -detailed config/app/

# Только перечисление ключей без значений
consul kv get -keys config/app/

# Рекурсивное удаление ветки
consul kv delete -recurse config/app/

# Атомарное обновление (CAS)
consul kv put -cas -modify-index=148 config/app/max_connections 200

# Импорт/экспорт дерева
consul kv export config/app/ > app_config_backup.json
consul kv import @app_config_backup.json
```

### Транзакции через HTTP API

```bash
curl -X PUT --data '[
  { "KV": { "Verb": "delete", "Key": "config/old_key" } },
  { "KV": { "Verb": "set", "Key": "config/new_key", "Value": "YmFzZTY0X2VuY29kZWRfdmFsdWU=" } }
]' http://127.0.0.1:8500/v1/txn
```

### Распределённые блокировки

```bash
# 1. Создание сессии
curl -X PUT -d '{"Name": "lock-session", "TTL": "15s"}' http://127.0.0.1:8500/v1/session/create
# -> {"ID": "adf4238a-882b-9ddc-4a9d-5b6758e4159e"}

# 2. Захват ключа
curl -X PUT http://127.0.0.1:8500/v1/kv/service/leader?acquire=adf4238a-882b-9ddc-4a9d-5b6758e4159e
# -> true

# 3. Освобождение ключа
curl -X PUT http://127.0.0.1:8500/v1/kv/service/leader?release=adf4238a-882b-9ddc-4a9d-5b6758e4159e
# -> true
```

Для упрощения блокировок используйте команду `consul lock`, которая управляет жизненным циклом сессии автоматически.

### Long Polling (блокирующие запросы)

```bash
# Получение текущего индекса
curl -s http://127.0.0.1:8500/v1/kv/config/app/max_connections | jq -r '.[0].ModifyIndex'
# -> 148

# Ожидание изменений до 5 минут
curl "http://127.0.0.1:8500/v1/kv/config/app/max_connections?index=148&wait=5m"
```

### Автоматизация через consul-template

```go-template
# app.conf.ctmpl
{{ range tree "config/app/features/" }}
{{ .Key }} = {{ .Value }}
{{ end }}

max_conns = {{ keyOrDefault "config/app/max_connections" "50" }};
```

После обновления конфигурации отправьте приложению сигнал `SIGHUP` для перезагрузки настроек без полного рестарта.

### ACL для KV

Политики настраиваются на уровне ключей и префиксов. Пример политики:

```hcl
key_prefix "config/app/" {
  policy = "read"
}

key "config/app/maintenance_mode" {
  policy = "write"
}

key_prefix "config/billing/" {
  policy = "deny"
}
```

Полное описание системы ACL приведено в **[Системе управления доступом (ACL)](./consul_acl.md)**.

## Устранение неполадок

### Ошибки CAS (409 Conflict)

При конкурентном обновлении CAS возвращает `false`.
- **Решение:** Стратегия «Retry with Exponential Backoff». Перед повторной попыткой прочитайте актуальный `ModifyIndex`.

### Сетевое разделение (Network Partition)

Consul является CP-системой. При потере кворума:
- Записи в KV становятся невозможными.
- `consistent` и `default` чтения возвращают ошибку.
- Только `stale` чтения продолжают работать, но могут возвращать устаревшие данные.

### Деградация производительности Raft

Частые записи или значения близкие к 512 КБ увеличивают размер снапшотов и логи Raft.
- **Симптомы:** Рост latency, высокая загрузка CPU на серверах, частые перевыборы лидера.
- **Решение:** Храните в KV только метаданные. Крупные объекты вынесите в S3/ Nexus/artifact registry, оставив в Consul ссылки.

### Агент не может записать ключ

- **Проверка:** Убедитесь, что токен агента имеет политику с `key:write` или `key:write` на префикс.
- **Проверка:** Для блокировок сессия должна быть активна и иметь `TTL` больше нуля.

### Истечение сессии при блокировке

- **Симптом:** Захваченный ключ освобождается без явного `release`.
- **Причина:** Сессия истекла по `TTL` или из-за отказа проверки здоровья (`Checks`), от которой она зависела.
- **Решение:** Увеличьте `TTL` или добавьте механизм автоматического продления (`renew`) со стороны держателя блокировки.

## Лучшие практики

- **Иерархия:** Организуйте ключи по префиксам: `config/env/app/service/setting`. Упрощает ACL и рекурсивное чтение.
- **Stale чтения:** Для конфигураций, где задержка до нескольких секунд допустима, используйте `-stale`.
- **Минимизация watches:** Наблюдайте за префиксом, а не за отдельными ключами.
- **Кэширование агентом:** Включите `use_cache: true` в конфигурации агента для локального обслуживания частых чтений.
- **Ротация токенов:** Используйте короткоживущие токены для сервисов; Vault — для динамической выдачи.
- **Sentinel (Enterprise):** Для сложной логики доступа (время суток, геолокация) используйте Sentinel-политики.
- **Бэкапы:** Регулярно выполняйте `consul snapshot save` для резервного копирования KV-данных.

## Граничные случаи

- **Атомарность транзакций:** Если в блоке 64 операции превышены, API вернёт ошибку. Разбейте изменения на несколько транзакций.
- **Empty keys:** Пустые значения допустимы. Ключ без данных может использоваться как распределённый флаг присутствия.
- **Режим Dataplane (Consul 1.14+):** При использовании Consul Dataplane in Kubernetes классические клиенты могут не иметь прямого доступа к серверам. Убедитесь, что маршруты к HTTP API открыты для агентов, если они работают с KV напрямую.
- **Multi-Datacenter:** Встроенной репликации KV между датацентрами нет. Для этого используйте [Consul Replicate](https://github.com/hashicorp/consul-replicate) или периодический экспорт/импорт.
- **Анонимный доступ:** При включённых ACL без явной настройки анонимного токена все неаутентифицированные запросы отклоняются.
