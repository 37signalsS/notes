# Определения

**Consul KV** — это встроенное распределённое хранилище типа "ключ-значение", предназначенное для хранения конфигурации, динамических переменных и координации распределённых сервисов.

# Базовые концепции

## Модель данных и согласованность

- **Ключи:** Организуются иерархически, подобно путям в файловой системе (например, `app/frontend/config/feature_x`).
- **Значения:** Непрозрачные бинарные данные (байты). Рекомендуется для хранения небольших объемов данных.
- **Индексы:** Каждый ключ имеет `createIndex` и `modifyIndex`, которые инкрементируются при создании и изменении. Это используется для отслеживания версий.
- **Согласованность:**
    - **Stale (по умолчанию):** Чтения могут обслуживаться любым сервером, что обеспечивает низкую задержку, но данные могут быть неактуальными.
    - **Consistent:** Чтения направляются к лидеру Raft, гарантируя получение самой последней версии данных.
- **Check-And-Set (CAS):** Атомарная операция, которая позволяет записать новое значение только в том случае, если `modifyIndex` ключа совпадает с ожидаемым. Это защищает от гонок обновлений.

## Сессии и блокировки

Consul KV поддерживает механизм **сессий**, который позволяет реализовать распределенные блокировки (`distributed locks`):
1.  Клиент создает сессию с определенным TTL.
2.  Ключ в KV захватывается с привязкой к этой сессии.
3.  Если сессия истекает (например, из-за сбоя клиента), блокировка автоматически освобождается.

Это позволяет строить примитивы для выбора лидера (`leader election`) и взаимного исключения (`mutex`).

# Практические сценарии

## Операции через CLI

```bash
# Запись значения
consul kv put app/prod/db/url "postgres://db:5432/app"

# Чтение значения
consul kv get app/prod/db/url

# Рекурсивное чтение по префиксу
consul kv get -recurse app/prod/

# Удаление ключа
consul kv delete app/prod/db/url

# Рекурсивное удаление
consul kv delete -recurse app/prod/
```

## Операции через HTTP API

```bash
# Запись значения
curl --request PUT --data 'enabled=true' http://127.0.0.1:8500/v1/kv/app/prod/featureA

# Чтение (значение в формате base64)
curl http://127.0.0.1:8500/v1/kv/app/prod/featureA

# Чтение "сырого" значения
curl http://127.0.0.1:8500/v1/kv/app/prod/featureA?raw
```

## Отслеживание изменений (Blocking Queries)

Вместо постоянного опроса (polling), клиенты могут использовать блокирующие запросы, которые ожидают изменения `modifyIndex` ключа.

```bash
# 1. Выполнить первый запрос и сохранить значение заголовка X-Consul-Index
curl -i http://127.0.0.1:8500/v1/kv/app/prod/featureA

# 2. Выполнить блокирующий запрос с полученным index, ожидая до 10 минут
curl "http://127.0.0.1:8500/v1/kv/app/prod/featureA?index=<prev_index>&wait=10m"
```
Сервер вернет ответ, как только значение изменится или по истечении таймаута.

Альтернатива — использование `consul watch` на агенте:
```bash
consul watch -type=keyprefix -prefix=app/prod/ 'bash -c "date; echo changed"'
```

## Транзакции

Consul поддерживает атомарные транзакции, которые могут объединять несколько операций (`set`, `get`, `cas`, `delete`).

```bash
# Пример транзакции с операцией CAS
curl --request PUT http://127.0.0.1:8500/v1/txn -d '
[
  {
    "KV": {
      "Verb": "cas",
      "Key": "app/prod/version",
      "Value": "MQ==", # "1" в base64
      "Index": 42
    }
  }
]'
```

# Дополнительная информация

## Рекомендации

- **Структурируйте ключи:** Используйте префиксы для разделения по окружениям, сервисам и компонентам (`env/service/component/param`).
- **Используйте CAS:** Применяйте операции Check-and-Set для предотвращения гонок при конкурентной записи.
- **Избегайте polling:** Предпочитайте `blocking queries` или `consul watch` для реакции на изменения.
- **Не храните большие данные:** KV-хранилище не предназначено для больших бинарных объектов.
- **Не храните секреты в открытом виде:** Для чувствительных данных интегрируйте Consul с [Vault](../Vault/overview.md).
- **Используйте ACL:** Ограничивайте доступ к ключам с помощью ACL-токенов.
