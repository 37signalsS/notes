# Определения

**Consul KV (Key-Value Store)** — это встроенное распределённое иерархическое хранилище, предназначенное для динамической конфигурации, управления флагами функций (`feature flags`), координации распределённых систем и реализации механизмов выбора лидера. Все данные в KV-хранилище реплицируются между серверами через [протокол консенсуса Raft](./consul_consensus.md).

# Основные концепции

## Модель данных и индексы

- **Иерархические ключи:** Ключи организуются в виде дерева, аналогично файловой системе (например, `config/prod/database/url`).
- **Значения:** Непрозрачные бинарные данные (байты). По умолчанию размер ограничен 512 КБ на один ключ.
- **Flags:** Беззнаковое 64-битное целое число, которое можно сохранить вместе со значением. Используется приложениями для хранения метаданных (например, типа контента или версии схемы).
- **Индексы (`ModifyIndex`):** Каждое изменение в KV-хранилище инкрементирует глобальный индекс состояния. `ModifyIndex` ключа позволяет отслеживать его изменения и реализовывать механизмы `watch`.

## Согласованность и атомарность

Consul предоставляет гибкие настройки согласованности для операций чтения:
- `default`: Режим по умолчанию, обеспечивающий строгую согласованность в большинстве случаев.
- `stale`: Чтение с любого сервера (включая последователей), что снижает задержку, но может вернуть данные с задержкой в несколько миллисекунд.
- `consistent`: Чтение с подтверждением лидерства через кворум, гарантирующее максимальную актуальность.

Для обеспечения целостности данных используются:
- **Check-And-Set (CAS):** Позволяет выполнить запись только в том случае, если текущий `ModifyIndex` ключа совпадает с ожидаемым.
- **Транзакции:** Группировка до 64 операций (`put`, `get`, `delete`, `cas`) в единый атомарный блок.

## Сессии и блокировки

Механизм **сессий** позволяет реализовать распределенные блокировки (`distributed locks`) и семафоры:
1. Клиент создает сессию с определенным TTL (Time To Live).
2. Клиент "захватывает" ключ (`acquire`), привязывая его к сессии.
3. Если клиент падает или не обновляет сессию, она истекает, и ключ автоматически освобождается.
Это является основой для паттерна **выбора лидера (Leader Election)**.

# Практические сценарии

## Использование CLI для управления конфигурацией

```bash
# Запись значения с флагом
consul kv put -flags=42 config/app/max_connections 100
# -> Success! Data written to: config/app/max_connections

# Чтение значения
consul kv get config/app/max_connections
# -> 100

# Рекурсивное чтение метаданных всех ключей в директории
consul kv get -recurse -detailed config/app/
# -> config/app/max_connections:
# ->   CreateIndex: 145
# ->   ModifyIndex: 148
# ->   LockIndex: 0
# ->   Flags: 42
# ->   Value: 100
```

## Автоматизация через consul-template

Наиболее распространенный способ использования Consul KV — утилита **consul-template**, которая подписывается на изменения ключей и обновляет конфигурационные файлы на лету.

Пример шаблона `app.conf.ctmpl`:
```hcl
{{ with service "web" }}
{{ range . }}
server {{ .Address }}:{{ .Port }};
{{ end }}
{{ end }}

max_conns = {{ keyOrDefault "config/app/max_connections" "50" }};
```

## Блокирующие запросы (Long Polling)

Клиенты могут эффективно ожидать изменений, используя заголовок `X-Consul-Index`.

```bash
# Получаем текущий индекс
curl -v http://127.0.0.1:8500/v1/kv/config/app/max_connections
# < X-Consul-Index: 148

# Ожидаем изменений (запрос "висит" до изменения данных или таймаута)
curl "http://127.0.0.1:8500/v1/kv/config/app/max_connections?index=148&wait=5m"
```

## Реализация блокировки через API

```bash
# 1. Создание сессии
curl -X PUT -d '{"Name": "lock-session", "TTL": "15s"}' http://127.0.0.1:8500/v1/session/create
# -> {"ID": "adf4238a-882b-9ddc-4a9d-5b6758e4159e"}

# 2. Захват ключа
curl -X PUT http://127.0.0.1:8500/v1/kv/service/leader?acquire=adf4238a-882b-9ddc-4a9d-5b6758e4159e
# -> true (если захват удался)
```

# Дополнительная информация

- **Лимиты:** Рекомендуется хранить только небольшие объемы данных. Большие значения (>512 КБ) и частые изменения в KV могут негативно влиять на стабильность [Raft-консенсуса](./consul_consensus.md) из-за увеличения размера логов и времени репликации.
- **Безопасность:** Доступ к ключам и префиксам должен ограничиваться через [систему ACL](./consul_architecture.md).
- **Связанные документы:** [Обзор Consul](./consul_overview.md), [Хранение секретов Vault](../Vault/guides/vault_with_consul_backend.md).
