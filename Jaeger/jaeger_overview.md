# Обзор Jaeger

> **Важно:** Документация описывает **Jaeger v2** (текущая версия). Jaeger v1 достиг **EOL (End of Life)**.

**Jaeger** — распределенная система трассировки с открытым исходным кодом для мониторинга и устранения неполадок в микросервисных архитектурах. Проект **CNCF (Cloud Native Computing Foundation)**, изначально разработанный в Uber.

Основная задача — помочь разработчикам и **SRE-инженерам (Site Reliability Engineering)** понимать потоки выполнения запросов, выявлять узкие места производительности и анализировать задержки.

---

## Определения

| Термин | Описание |
| :--- | :--- |
| **Распределенная трассировка** | Метод мониторинга приложений, позволяющий отслеживать путь запроса через множество микросервисов |
| **Trace (Трасса)** | Полный путь прохождения запроса через систему, состоящий из набора спанов |
| **Span (Спан)** | Единица работы в рамках трассы (например, HTTP-запрос, запрос к БД, выполнение функции). Имеет имя, время начала и длительность |

## Базовые концепции

### Архитектура и компоненты

Jaeger v2 полностью построен на базе **OpenTelemetry Collector**, что обеспечивает унификацию сбора данных. Подробное описание компонентов, их взаимодействия и схем потоков данных приведено в основном архитектурном файле:

* **[Детальная архитектура Jaeger](./jaeger_architecture.md)**

### Сравнение с Grafana Tempo

Jaeger и **[Grafana Tempo](../Tempo/index.md)** — ключевые решения для трассировки с разной философией:

| Критерий | Jaeger | Grafana Tempo |
| :--- | :--- | :--- |
| **Индексация и поиск** | Индексирует метаданные спанов (теги). Мощный и гибкий поиск | Индексирует только по `trace_id`. Экономичен для больших объемов |
| **Зависимости** | Требует внешнюю базу данных (Elasticsearch, Cassandra) | Опирaется на объектное хранилище (S3, GCS, MinIO) |
| **Экосистема** | Имеет собственный **UI (User Interface)** | Тесно интегрирован с Grafana для корреляции с метриками и логами |

## Практические сценарии

### Анализ задержек в микросервисах

**Ситуация:** Пользователи жалуются на медленную обработку заказов.

| Шаг | Действие | Результат |
| :--- | :--- | :--- |
| **1** | Открыть **Jaeger UI**, отфильтровать трассы по сервису `orders` и эндпоинту `/checkout` со статусом "error" или высокой длительностью | Найден медленный трейс |
| **2** | Открыть диаграмму Ганта для медленной трассы | 90% времени занимает спан сервиса `inventory` |
| **3** | Проверить спаны внутри `inventory` | Обнаружен медленный запрос к базе данных |
| **4** | Изучить атрибуты спана и логи | Выявлен отсутствующий индекс на таблице |

**Итог:** Jaeger позволил быстро найти корневую причину без последовательной отладки каждого сервиса. Подробнее о методиках анализа: **[Анализ производительности](./jaeger_performance_analysis.md)**.
