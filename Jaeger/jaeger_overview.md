# Jaeger

Jaeger — это распределенная система трассировки (distributed tracing system) с открытым исходным кодом, предназначенная для мониторинга и устранения неполадок в сложных микросервисных архитектурах. Изначально разработанный компанией Uber Technologies и выпущенный в опенсорс в 2017 году, Jaeger стал инкубируемым проектом Cloud Native Computing Foundation (CNCF).

Jaeger помогает разработчикам и операторам понимать потоки выполнения запросов между множеством сервисов, выявлять узкие места производительности, анализировать задержки и отлаживать распределенные транзакции.

## Основные концепции

*   **Трассировка (Trace):** Представляет собой полный жизненный цикл одного запроса или транзакции, проходящего через различные сервисы в распределенной системе. Трассировка состоит из одного или нескольких спанов, связанных между собой.
*   **Спан (Span):** Фундаментальная единица работы в трассировке. Спан представляет собой одну операцию, например, HTTP-вызов, запрос к базе данных, вызов метода. Каждый спан имеет имя операции, время начала, длительность и набор тегов (ключ-значение) для дополнительного контекста. Спаны формируют иерархическую структуру (родитель-потомок), отображая причинно-следственные связи.
*   **Контекст трассировки (Trace Context):** Информация, которая передается между сервисами (обычно через HTTP-заголовки) для связывания спанов в одну трассировку. Включает `trace_id` (уникальный идентификатор всей трассировки) и `span_id` (идентификатор текущего спана).

## Архитектура Jaeger

Jaeger имеет клиент-серверную микросервисную архитектуру, позволяющую горизонтально масштабироваться и адаптироваться к высоким нагрузкам. Основные компоненты Jaeger включают:

1.  **Jaeger Client (Клиент Jaeger):**

    *   **Описание:** Библиотеки для инструментирования приложений на различных языках программирования (Go, Java, Python, Node.js, C++ и др.).
    *   **Функция:** Создают спаны, устанавливают контекст трассировки и передают его между сервисами, а затем отправляют собранные спаны на Jaeger Agent или Collector.
    *   **Стандарт:** Изначально использовал OpenTracing API, но активно переходит на поддержку [OpenTelemetry](../OpenTelemetry/opentelemetry_overview.md) в соответствии с новыми стандартами.

2.  **Jaeger Agent (Агент Jaeger):**

    *   **Описание:** Сетевой демон, который обычно запускается как sidecar-контейнер рядом с приложением (например, в Kubernetes) или как локальный процесс на хосте.
    *   **Функция:** Принимает спаны от Jaeger Client, буферизует их, выполняет локальную обработку (например, сэмплирование) и пересылает их на Jaeger Collector.
    *   **Преимущества:** Снижает нагрузку на клиентские библиотеки и инкапсулирует логику отправки данных.

3.  **Jaeger Collector (Коллектор Jaeger):**

    *   **Описание:** Серверный компонент, который получает трассировки от агентов (или напрямую от клиентов), выполняет валидацию, обработку, индексацию и сохраняет их в постоянное хранилище.
    *   **Функция:** Может быть развернут в нескольких экземплярах для обеспечения высокой доступности и масштабируемости.

4.  **Storage (Хранилище):**

    *   **Описание:** Jaeger поддерживает различные бэкенды для хранения трассировок.
    *   **Примеры:** Elasticsearch, Cassandra, Kafka (как промежуточный буфер), Badger (для небольших инсталляций). В отличие от реляционных баз данных, Jaeger использует NoSQL-решения, оптимизированные для больших объемов данных.
    *   **Контекст из транскрипта:** "позгришься под капотом никто не использует соответственно у нас из ной с койл это косандра и ластик все".

5.  **Jaeger Query (Сервис запросов):**

    *   **Описание:** Серверный компонент, который предоставляет API для извлечения трассировок из хранилища.
    *   **Функция:** Отвечает на запросы UI или внешних инструментов для поиска и отображения трассировок.

6.  **Jaeger UI (Пользовательский интерфейс):**

    *   **Описание:** Веб-интерфейс для поиска, просмотра и анализа трассировок. Написан на React.
    *   **Функция:** Позволяет визуализировать трассировки в виде "диаграмм Ганта" (Gantt chart), показывать временные рамки, зависимости между спанами, атрибуты и логи.
    *   **Контекст из транскрипта:** "имеют встроенный реакт у юай написаны на реакте".

## Jaeger и OpenTelemetry

Транскрипт вебинара подчеркивает, что мир трассировки активно переходит на новый стандарт — [OpenTelemetry](../OpenTelemetry/opentelemetry_overview.md). Хотя Jaeger исторически использовал OpenTracing, он активно развивает поддержку OpenTelemetry, и OpenTelemetry Collector часто используется как агент или коллектор для сбора данных, которые затем могут быть отправлены в Jaeger бэкенд.

## Сравнение с Grafana Tempo

Jaeger и [Grafana Tempo](../Tempo/tempo_overview.md) являются конкурирующими решениями для хранения и анализа трассировок. Основные отличия:

*   **Архитектура:** Оба используют микросервисный подход, но Tempo оптимизировано для хранения в объектных хранилищах (S3, MinIO) для экономичности.
*   **UI:** Jaeger имеет собственный UI, тогда как Tempo интегрируется с Grafana для визуализации.
*   **Фокус:** Tempo сфокусировано на экономичном хранении большого объема трассировок, часто без индексации содержимого спанов, полагаясь на `trace_id` для поиска. Jaeger предлагает более гибкие возможности поиска по атрибутам спанов за счет индексации в хранилище.
