# Jaeger

> **Важно:** Документация описывает **Jaeger v2** (текущая версия). Jaeger v1 достиг EOL.

**Jaeger** — распределенная система трассировки с открытым исходным кодом для мониторинга и устранения неполадок в микросервисных архитектурах. Проект CNCF, изначально разработанный в Uber.

Основная задача — помочь разработчикам и SRE-инженерам понимать потоки выполнения запросов, выявлять узкие места производительности и анализировать задержки. Ключевые концепции (Trace, Span) описаны в документе **[Traces Deep Dive](../Concepts/Observability_and_Monitoring/traces_deep_dive.md)**.

---

## Определения

| Компонент | Назначение |
| :--- | :--- |
| **OpenTelemetry SDK / Jaeger Client** | Библиотека для инструментирования кода приложения. Отвечает за создание спанов и их отправку. Рекомендуется использовать [OpenTelemetry SDK](../OpenTelemetry/opentelemetry_overview.md) |
| **OpenTelemetry Collector** | В v2 компоненты Agent и Collector объединены в OTel Collector. Принимает данные от приложений, обрабатывает и экспортирует в хранилище |
| **Jaeger Collector (v2)** | Специализированный OTel Collector с дополнительными возможностями для работы с данными Jaeger |
| **Storage** | Бэкенд для постоянного хранения данных трассировки. Поддерживаемые хранилища: Elasticsearch, OpenSearch, Cassandra, ClickHouse (v2), Badger (all-in-one) |
| **Jaeger Query** | Сервис, предоставляющий API для извлечения трасс из хранилища |
| **Jaeger UI** | Веб-интерфейс для поиска, визуализации и анализа трассировок |

## Базовые концепции

### Поток данных

Типичный поток данных в Jaeger v2:

1. **Инструментированный сервис** с помощью **OpenTelemetry SDK** создает спаны.
2. Спаны отправляются в **OpenTelemetry Collector** (заменяет Jaeger Agent).
3. **Collector** обрабатывает, валидирует и сохраняет трассы в **Storage**.
4. **Jaeger UI** через **Jaeger Query** запрашивает и отображает данные из **Storage**.

### Интеграция с OpenTelemetry

Jaeger v2 **полностью построен** на базе OpenTelemetry Collector. OTel SDK — основной способ сбора данных. OpenTelemetry Collector является центральным компонентом, собирающим телеметрию и отправляющим ее напрямую в бэкенд Jaeger. Это позволяет унифицировать сбор данных в полиглотных системах.

### Сравнение с Grafana Tempo

Jaeger и [Grafana Tempo](../Tempo/index.md) — ключевые решения для трассировки с разной философией:

| Критерий | Jaeger | Grafana Tempo |
| :--- | :--- | :--- |
| **Индексация и поиск** | Индексирует метаданные спанов (теги). Мощный и гибкий поиск | Индексирует только по `trace_id`. Экономичен для больших объемов |
| **Зависимости** | Требует внешнюю базу данных (Elasticsearch, Cassandra) | Опирaется на объектное хранилище (S3, GCS, MinIO) |
| **Экосистема** | Имеет собственный UI | Тесно интегрирован с Grafana для корреляции с метриками и логами |

## Практические сценарии

### Анализ производительности

**Ситуация:** Пользователи жалуются на медленную обработку заказов.

| Шаг | Действие | Результат |
| :--- | :--- | :--- |
| **1** | Открыть Jaeger UI, отфильтровать трассы по сервису `orders` и эндпоинту `/checkout` со статусом "error" или высокой длительностью | Найден медленный трейс |
| **2** | Открыть диаграмму Ганта для медленной трассы | 90% времени занимает спан сервиса `inventory` |
| **3** | Проверить спаны внутри `inventory` | Обнаружен медленный запрос к базе данных |
| **4** | Изучить атрибуты спана и логи | Выявлен отсутствующий индекс на таблице |

**Итог:** Jaeger позволил быстро найти корневую причину без последовательной отладки каждого сервиса.
