# Анализ производительности с помощью Jaeger

> **Важно:** Документация описывает **Jaeger v2**. Jaeger v1 достиг EOL.

**Анализ производительности в Jaeger** — процесс интерпретации данных трассировки для выявления узких мест, анализа задержек и диагностики ошибок. Описывает практические методики использования Jaeger UI и API.

---

## Определения

| Термин | Описание |
| :--- | :--- |
| **Timeline (Gantt Chart)** | Каскадная диаграмма, показывающая последовательность и длительность спанов. Основной инструмент для визуального анализа задержек |
| **Критический путь** | Последовательность спанов, которая напрямую влияет на общую длительность трассы |
| **Паттерн N+1** | Проблема производительности: множество одинаковых запросов к БД вместо одного батча |
| **Tail-based Sampling** | Стратегия сэмплирования, при которой решение о сохранении трассы принимается после её полного завершения |

---

## Базовые концепции

### Ключевые элементы Jaeger UI

| Элемент | Назначение |
| :--- | :--- |
| **Панель поиска** | Фильтрация трасс по сервису, операции, тегам (`error=true`, `http.status_code=500`), диапазону времени и длительности |
| **Визуализация трейса (Timeline)** | Каскадная диаграмма для визуального анализа задержек |
| **Детали спана** | Панель с информацией о спане: атрибуты (теги), события (логи), метаданные процесса |

### Методика анализа трейса

1. **Оцените общую длительность:** Найдите корневой спан и посмотрите на общую задержку запроса.
2. **Определите критический путь:** Последовательность спанов, напрямую влияющая на общую длительность. Оптимизация спанов вне критического пути не даст эффекта.
3. **Ищите "длинные" спаны:** Найдите спаны, вносящие наибольший вклад в задержку.
4. **Анализируйте параллелизм:** Ищите спаны, которые могли бы выполняться параллельно, но выполняются последовательно (эффект "водопада").

### Типовые паттерны проблем

| Паттерн | Описание |
| :--- | :--- |
| **Проблема N+1** | Множество одинаковых коротких запросов (например, к БД), которые можно объединить в один |
| **"Болтливые" вызовы (Chatty I/O)** | Большое количество мелких последовательных сетевых вызовов между двумя сервисами |
| **Каскадные повторы (Retries)** | Несколько попыток выполнить один и тот же спан — признак проблем с доступностью зависимого сервиса |

## Практические сценарии

### Сценарий 1: Фильтрация и поиск аномалий

Используйте панель поиска для быстрого нахождения проблемных трейсов.

| Задача | Параметры поиска |
| :--- | :--- |
| Найти все ошибочные трейсы для сервиса `checkout` | `Service`: `checkout`, `Tags`: `error=true` |
| Найти медленные запросы на создание заказа | `Service`: `orders`, `Operation`: `createOrder`, `Min Duration`: `1.5s` |

### Сценарий 2: Корреляция с метриками и логами

**От метрик к трейсам:** Если на графике в Grafana виден всплеск задержки, а система мониторинга поддерживает exemplars, можно перейти напрямую к трейсу, вызвавшему всплеск.

**От логов к трейсам:** Включите `trace_id` в логи приложения. При анализе логов в Loki или Elasticsearch скопируйте `trace_id` и вставьте его в Jaeger UI для просмотра полного контекста запроса.

### Сценарий 3: Автоматизация через API

Jaeger Query API позволяет автоматизировать анализ. Пример получения последних 20 медленных и ошибочных трейсов для сервиса `checkout`:

```bash
curl 'http://jaeger-query:16686/api/traces?service=checkout&operation=PlaceOrder&lookback=1h&limit=20&minDuration=500ms&tags=%7B%22error%22%3Atrue%7D'
```

### Сценарий 4: Настройка Tail-based Sampling для ценных трейсов

Чтобы анализировать только самые важные трейсы (ошибочные, медленные), настройте Tail-based Sampling в OpenTelemetry Collector. Это сэкономит место в хранилище. Подробнее: **[Jaeger Architecture](./jaeger_architecture.md)**.

```yaml
processors:
  tail_sampling:
    policies:
      # Сохранять все ошибочные трейсы
      - name: errors
        type: status_code
        status_code: { status_codes: [ERROR] }
      # Сохранять трейсы дольше 800мс
      - name: slow_requests
        type: latency
        latency: { threshold_ms: 800 }
```

## Дополнительная информация

**Рекомендуемые атрибуты для анализа:**
- HTTP: `http.method`, `http.route`, `http.status_code`
- БД: `db.system`, `db.statement` (без чувствительных данных)
- Очереди: `messaging.system`, `messaging.destination`
- Бизнес-контекст: `user.id`, `tenant.id` (в хешированном виде)
