# Варианты развертывания Jaeger

Jaeger предлагает два основных подхода к развертыванию: **all-in-one** и **production (распределенный)**. Выбор модели определяет отказоустойчивость, масштабируемость и операционную сложность системы трассировки.

---

## Определения

* **All-in-one:** Единый бинарный файл или Docker-образ, в котором все компоненты Jaeger (Agent, Collector, Query, UI) запущены в одном процессе. Хранилище, как правило, встроено (in-memory или Badger).
* **Production (Distributed):** Распределенная архитектура, где каждый компонент (Collector, Query, Agent) развертывается как отдельный, масштабируемый сервис. Требует внешнего отказоустойчивого хранилища (например, Elasticsearch или Cassandra).

---

## Основные концепции

### Сравнение моделей

#### All-in-one

* **Назначение:** Локальная разработка, демонстрации, CI/CD-пайплайны.
* **Архитектура:** Все компоненты в одном процессе.
* **Хранилище:** В оперативной памяти (данные теряются при перезапуске) или локальный файл (Badger).
* **Масштабируемость:** Отсутствует. Рассчитан на одного пользователя и небольшой объем данных.
* **Надежность:** Низкая. Сбой процесса ведет к потере всей системы.

#### Production (Distributed)

* **Назначение:** Staging и production-окружения, где важны надежность и производительность.
* **Архитектура:** Компоненты развернуты как независимые сервисы, что позволяет их масштабировать по отдельности. Подробности см. в [**Архитектуре Jaeger**](./jaeger_architecture.md).
* **Хранилище:** Внешние, отказоустойчивые системы, такие как Elasticsearch или Cassandra.
* **Масштабируемость:** Высокая. Collector и Query могут быть горизонтально смасштабированы для обработки больших нагрузок.
* **Надежность:** Высокая. Отсутствует единая точка отказа.

### Критерии выбора

* **Начните с all-in-one**, если вам нужно быстро запустить трассировку для отладки в локальном окружении.
* **Переходите на production-модель**, когда вам требуются:
  * Долговременное хранение трасс.
  * Горизонтальное масштабирование для обработки высоких нагрузок.
  * Отказоустойчивость.
  * Разделение прав доступа и политики безопасности (TLS, аутентификация).

## Практические сценарии

### Сценарий 1: Быстрый старт с All-in-one

Запуск Jaeger в Docker для локальной разработки. Все порты компонентов доступны на хост-машине.

```bash
docker run -d --name jaeger \
  -e COLLECTOR_ZIPKIN_HOST_PORT=:9411 \
  -p 16686:16686 \   # UI
  -p 14268:14268 \   # Collector (HTTP)
  -p 6831:6831/udp \ # Agent (UDP)
  jaegertracing/all-in-one:latest
```

*В этом режиме данные трассировки хранятся в памяти и будут утеряны при перезапуске контейнера.*

### Сценарий 2: Production-установка в Kubernetes

Для production-окружений существует два основных подхода: использование **Jaeger Operator** или **Helm-чартов**.

#### Подход 1: Jaeger Operator (Рекомендуемый)

Jaeger Operator автоматизирует развертывание и управление жизненным циклом компонентов Jaeger.

Пример Custom Resource для создания распределенной инсталляции с Elasticsearch в качестве хранилища:

```yaml
apiVersion: jaegertracing.io/v1
kind: Jaeger
metadata:
  name: jaeger-prod
spec:
  strategy: production # Указывает на распределенную архитектуру
  storage:
    type: elasticsearch
    options:
      es:
        server-urls: http://elasticsearch:9200
    # Настройка автоматической очистки старых индексов
    esIndexCleaner:
      enabled: true
      numberOfDays: 7
  # Масштабирование коллекторов для обработки нагрузки
  collector:
    replicas: 3
  # Агент развертывается на каждом узле кластера
  agent:
    strategy: DaemonSet
```

#### Подход 2: Helm-чарты (Альтернатива)

Хотя Operator является мощным инструментом, в некоторых ситуациях он может оказаться недостаточно гибким или вызвать проблемы совместимости.

**Когда стоит рассмотреть Helm:**
*   **Проблемы с Operator:** Встречаются случаи, когда Jaeger Operator не может корректно развернуть компоненты в определенных окружениях (например, на ванильных версиях Kubernetes, таких как 1.25).
*   **Необходимость полного контроля:** Операторы могут скрывать сложность, но когда что-то идет не так, отладка превращается в анализ "черного ящика". Helm-чарты и манифесты, в свою очередь, легко инспектировать и модифицировать.
*   **Ограничения официальных чартов:** Некоторые публичные чарты (например, от Bitnami) могут иметь ограничения, такие как поддержка только одного типа хранилища (например, только Cassandra), что требует их значительной доработки.

В таких случаях хорошей альтернативой является использование форка старого официального чарта Jaeger или создание собственного, что дает полный контроль над конфигурацией всех компонентов.
