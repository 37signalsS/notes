# Варианты развертывания Jaeger

> **Важно:** Документация описывает **Jaeger v2** (текущая версия). Jaeger v1 достиг **EOL (End of Life)**.

Jaeger v2 предлагает два основных подхода к развертыванию: **all-in-one** (все-в-одном) и **production** (распределенный). Вторая версия полностью построена на базе **OpenTelemetry Collector**, что упрощает интеграцию и унифицирует сбор телеметрии.

---

## Определения

| Вариант | Назначение | Хранилище |
| :--- | :--- | :--- |
| **All-in-one** | Единый Docker-образ, в котором все компоненты Jaeger (Collector, Query, UI) работают совместно с OpenTelemetry Collector | In-memory (в оперативной памяти, данные теряются при перезапуске) или Badger (локальный файл) |
| **Production (Distributed)** | Распределенная архитектура, где компоненты развертываются как отдельные масштабируемые сервисы | Внешние отказоустойчивые системы: Elasticsearch, OpenSearch, Cassandra, ClickHouse |

---

## Базовые концепции

### Сравнение моделей развертывания

| Критерий | All-in-one | Production |
| :--- | :--- | :--- |
| **Назначение** | Локальная разработка, демонстрации, **CI/CD (Continuous Integration / Continuous Deployment)** пайплайны | Среды тестирования (Staging) и промышленной эксплуатации (Production) |
| **Архитектура** | Все компоненты в одном процессе | Компоненты развернуты как независимые сервисы. Подробности: **[Архитектура Jaeger](./jaeger_architecture.md)** |
| **Масштабируемость** | Отсутствует. Рассчитан на одного пользователя и небольшой объем данных | Высокая. Collector и Query могут быть горизонтально масштабированы |
| **Надежность** | Низкая. Сбой процесса ведет к потере доступности всей системы | Высокая. Отсутствует единая точка отказа за счет распределенности |

### Критерии выбора стратегии

**Используйте all-in-one**, если:

- Необходимо быстро запустить трассировку для отладки в локальном окружении разработчика.
- Требуется временное окружение для демонстрации или модульного тестирования.

**Переходите на production-модель**, когда требуются:

- Долговременное хранение и анализ исторических данных трассировки.
- Горизонтальное масштабирование для обработки высоких нагрузок и больших объемов спанов.
- Обеспечение высокой доступности и отказоустойчивости.
- Применение политик безопасности и шифрования **TLS (Transport Layer Security)**, а также аутентификации.

## Практические сценарии

### Сценарий 1: Быстрый старт с All-in-one в Docker

Запуск Jaeger для локальной разработки. Порты компонентов пробрасываются на хост-машину для доступа к **UI (User Interface)** и приема данных:

```bash
docker run -d --name jaeger \
  -e COLLECTOR_ZIPKIN_HOST_PORT=:9411 \
  -p 16686:16686 \   # UI (веб-интерфейс)
  -p 14268:14268 \   # Collector (HTTP приемник)
  -p 6831:6831/udp \ # Agent (UDP приемник для обратной совместимости)
  jaegertracing/all-in-one:latest
```

**Примечание:** В данном режиме данные хранятся в оперативной памяти и будут безвозвратно утеряны при остановке или перезапуске контейнера.

### Сценарий 2: Развертывание в Kubernetes

Для сред Kubernetes рекомендуется использовать специализированные инструменты управления, такие как **Jaeger Operator** или **Helm-чарты**. Эти инструменты автоматизируют установку и масштабирование компонентов.

Детальные инструкции и примеры конфигурации приведены в документе **[Интеграция с Kubernetes](./jaeger_kubernetes_integration.md)**.
