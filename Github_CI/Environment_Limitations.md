# GitHub Actions: Среды выполнения (Runners) и ограничения

Выбор среды выполнения (`runner`) — ключевое архитектурное решение в GitHub Actions. От него зависят доступные ресурсы, скорость, безопасность и стоимость CI/CD пайплайнов.

## Определения

- **GitHub-hosted runner**: Виртуальная машина, управляемая GitHub. Предоставляется по запросу с предустановленным ПО. Среда эфемерная — уничтожается после завершения задачи (`job`).
- **Self-hosted runner**: Ваш сервер (физический, VM, контейнер) с установленным агентом GitHub Actions. Вы контролируете окружение и несёте ответственность за обслуживание.

## Основные концепции

### Ключевые различия

| Категория | GitHub-hosted | Self-hosted |
| :--- | :--- | :--- |
| **Обслуживание** | Управляется GitHub | Ваша ответственность |
| **Окружение** | Стандартное, обновляется GitHub | Кастомное, настраивается вами |
| **Ресурсы** | Фиксированные (см. спецификации ниже) | Ограничены только вашим хостом |
| **Сеть** | Публичные IP из пула GitHub | Контролируемый доступ (в т.ч. приватная сеть) |
| **Безопасность** | Высокая изоляция, риски при работе с форками | Полная ответственность на вас, риски доступа к внутренней сети |
| **Стоимость** | Тарифицируется поминутно (снижение цен до 39% с января 2026) | Бесплатно (платформа отложена) + стоимость инфраструктуры |

### Спецификации GitHub-hosted runners (2026)

**Standard runners**:

| ОС | CPU | RAM | SSD |
| :--- | :--- | :--- | :--- |
| Ubuntu Linux | 2 ядра | 7 ГБ | 14 ГБ |
| Windows | 2 ядра | 7 ГБ | 14 ГБ |
| macOS | 3–4 ядра (M1/Intel) | 7 ГБ | 14 ГБ |

**Single-CPU runners** (контейнеры на общей VM):

- 1 ядро, меньше RAM, дешевле на ~50%

**Larger runners** (Team/Enterprise Cloud):

- До 96 vCPU, GPU-ускорители
- Тарифицируются отдельно

### Лимиты времени

- **Максимальная длительность job**: 6 часов
- **Ожидание в очереди (триггер)**: 30 минут — запуск отменяется
- **Ожидание в очереди (обработка)**: 45 минут — запуск отменяется
- **Таймаут по умолчанию**: 360 минут (настраивается через `timeout-minutes`)

### Изменения ценообразования 2026

**GitHub-hosted runners** (с 1 января 2026):

- Снижение цен до 39% в зависимости от типа машины
- Платформа $0.002/мин включена в стоимость

**Self-hosted runners**:

- Планировалась плата $0.002/мин с 1 марта 2026
- **Отложено** на неопределённый срок для переоценки подхода
- Минуты self-hosted usage по-прежнему бесплатны

### Сеть и безопасность

- **Доступ к приватным ресурсам**: Hosted-runner'ы имеют динамические IP, что усложняет доступ к ресурсам за файрволом. Self-hosted runner'ы размещаются в приватной сети.
- **Безопасность Self-hosted**: Self-hosted runner'ы имеют доступ к вашей сети — используйте только в приватных репозиториях или с `workflow_run` / ручным подтверждением для PR.
- **Минимальная версия агента**: Для совместимости с новыми функциями рекомендуется использовать актуальную версию агента (отслеживайте [официальные анонсы](https://github.blog/changelog/)).
- **Права доступа (`permissions`)**: Всегда выдавайте `GITHUB_TOKEN` только минимально необходимые права через ключ `permissions` в воркфлоу.

## Практические сценарии

### Сценарий 1: Доступ к приватной сети

**Проблема**: Тестам нужен доступ к staging-базе данных в приватной подсети (VPC).

**Решение**: Self-hosted runner, развернутый на ВМ в той же подсети.

### Сценарий 2: Управление правами для деплоя

**Проблема**: Для публикации требуется OIDC-токен, но другие задачи не должны иметь к нему доступ.

**Решение**: Использовать `permissions` на уровне задачи для выдачи `id-token: write` только нужному job.

```yaml
jobs:
  build-and-deploy:
    runs-on: macos-latest
    timeout-minutes: 90
    permissions:
      contents: read
      id-token: write
    steps:
      - name: Authenticate to Yandex Cloud
        uses: yandex-cloud/actions/auth@v0
        with:
          service-account-id: 'sa-xxxxxxxxxxxxxxxxx'
      # ... шаги деплоя
```

**Примечание**: Для локального аринта используйте self-hosted runner'ы с прямой аутентификацией через `yc` CLI или kubeconfig.
