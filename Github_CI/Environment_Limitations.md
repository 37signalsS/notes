# Ограничения окружения GitHub Actions

GitHub Actions выполняет ваши workflows на раннерах, и от типа раннера зависят ресурсы, уровень изоляции, сеть и доступные привилегии. Понимание ограничений окружения помогает проектировать надежные и воспроизводимые пайплайны.

## Типы раннеров и их особенности

Существует два базовых варианта:

*   **GitHub-hosted runners** — управляются провайдером, предоставляют преднастроенную среду (Ubuntu, Windows, macOS). Среда эфемерна: после завершения job состояние не сохраняется. Версии инструментов и образов периодически обновляются.
*   **Self-hosted runners** — запускаются на ваших серверах/VM. Позволяют устанавливать любые зависимости, управлять сетью и ресурсами, но требуют администрирования, обновлений и защиты.

| Категория | GitHub-hosted | Self-hosted |
| :--- | :--- | :--- |
| Изоляция job | Эфемерная VM/контейнер | Зависит от вашей конфигурации |
| Обновления инструментов | Автоматические, по расписанию | Ваша ответственность |
| Сеть | Исходящие IP нефиксированы | Можно зафиксировать egress |
| Ресурсы | Стандартизированы, ограничены | Настраиваемы, зависят от хоста |
| Привилегии | Ограничены, без доступа к ядру | Полный контроль при аккуратной настройке |
| Стоимость/лимиты | Зависит от тарифа | Зависит от вашей инфраструктуры |

## Ресурсы и выполнение

*   Время выполнения job ограничено; при превышении задания прерываются. Настраивается на уровне job.
*   Параллельность и очередь регулируются тарифом и настройками репозитория/организации. Для предотвращения гонок использовать concurrency-группы.
*   CPU, RAM и диск фиксированы для хостед-раннеров; интенсивные сборки, большие базы данных и кэши могут упираться в лимиты. Для тяжелых задач используйте self-hosted.
*   Файловая система эфемерна: GITHUB_WORKSPACE и временные директории очищаются после job. Для передачи результатов применяются артефакты и кэши.

Пример управления временем, правами и параллельностью:

```yaml
name: ci
on: [push]
concurrency:
  group: ${{ github.ref }}-build
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - run: make build
```

## Сеть и безопасность

*   Исходящие IP-адреса GitHub-hosted динамические; доступ к приватным ресурсам по IP-спискам усложнен. Для статических egress используйте self-hosted или прокси/NAT.
*   Доступ к GitHub API и ресурсам ограничен rate limit. При интенсивном использовании кэшируйте ответы и снижайте частоту запросов.
*   GITHUB_TOKEN имеет минимально необходимые права по умолчанию; расширение разрешений выполняется через секцию permissions.
*   Secrets недоступны для событий из форков по умолчанию, чтобы исключить утечки. Для внешних вкладов используйте стратегию изоляции: временные токены, разрешения только на чтение, отдельные workflow для pull_request_target с учетом рисков.

## Контейнеры и виртуализация

*   Docker доступен, но низкоуровневые функции (например, настройка ядра, специфичные драйверы) недоступны на хостед-раннерах. Гнездовая виртуализация и запуск собственных гипервизоров не поддерживаются.
*   Service containers в job удобны для зависимостей (БД, брокеры), но интенсивные I/O и долгоживущие состояния нужно выносить во внешние сервисы или self-hosted.

## Артефакты, кэш и логи

*   Артефакты и кэши имеют ограничения по размеру и сроку хранения. Большие директории следует чистить, исключать неиспользуемые файлы и использовать тарирование/сжатие.
*   Логи шагов ограничены по объему; чрезмерный вывод обрезается. Рекомендуется настраивать уровень логирования и собирать подробные логи как артефакты.
*   Кэш восстанавливается по ключам; при несовпадении используется ближайшее совпадение (restore-keys). Это не гарантия детерминизма сборки, поэтому фиксируйте версии зависимостей.
