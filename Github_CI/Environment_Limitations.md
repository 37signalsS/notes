# GitHub Actions: Среды выполнения и ограничения

Выбор среды выполнения (исполнителя, или runner) является фундаментальным архитектурным решением в GitHub Actions. От этого выбора напрямую зависят доступные вычислительные ресурсы, скорость выполнения этапов, уровень безопасности и итоговая стоимость конвейеров CI/CD (Continuous Integration / Continuous Deployment — непрерывная интеграция и непрерывное развертывание).

## Определения

- **GitHub-hosted runner (Облачный исполнитель)**: Виртуальная машина (VM — Virtual Machine), полностью управляемая GitHub. Предоставляется по требованию с предустановленным программным обеспечением. Среда является эфемерной — она создается для конкретной задачи и полностью уничтожается после её завершения.
- **Self-hosted runner (Собственный исполнитель)**: Выделенный сервер (физический, виртуальная машина или контейнер), на котором установлен агент GitHub Actions. Пользователь самостоятельно управляет операционной системой (OS — Operating System), аппаратными ресурсами и сетевым доступом.
- **Actions Cloud Platform Charge**: Базовый сбор за использование облачной платформы оркестрации ($0.002 за минуту), введенный в 2026 году для всех запусков в приватных репозиториях.

## Основные концепции

### Различия между типами исполнителей

| Категория | GitHub-hosted | Self-hosted |
| :--- | :--- | :--- |
| **Обслуживание** | Полностью на стороне GitHub | Ответственность пользователя |
| **Окружение** | Стандартные образы (Ubuntu 26.04, macOS 26) | Полностью настраиваемое пользователем |
| **Ресурсы** | Фиксированные спецификации | Ограничены только мощностью хоста |
| **Сеть** | Публичные IP-адреса из пулов GitHub | Контролируемый доступ (включая VPC) |
| **Безопасность** | Высокая изоляция каждой задачи | Риски доступа к внутренней сети |
| **Стоимость** | Поминутная тарификация (включает Platform Charge) | Сбор за платформу ($0.002/мин) для приватных репозиториев |

### Технические характеристики (спецификации июля 2026)

**Стандартные исполнители (Standard runners)**:

| Репозиторий | Тип OS | CPU (Центральный процессор) | RAM (Оперативная память) | SSD |
| :--- | :--- | :--- | :--- | :--- |
| **Публичный** | Linux / Windows | 4 ядра | 16 ГБ | 14 ГБ |
| **Публичный** | macOS (M1/Intel) | 3–4 ядра | 7–14 ГБ | 14 ГБ |
| **Приватный** | Linux / Windows | 2 ядра | 7 ГБ | 14 ГБ |

**Специализированные решения**:

- **Linux Slim**: Контейнерные исполнители с 1 ядром CPU и 5 ГБ RAM. Стоимость в два раза ниже стандартных.
- **Larger runners**: Доступны для планов Team и Enterprise. Предлагают до 64 ядер процессора, поддержку архитектуры ARM64 и графические ускорители (GPU) для задач машинного обучения.
- **Scale Set Client**: Новый агент на базе Go для автоматического масштабирования исполнителей на любой инфраструктуре (VM, Bare Metal) без обязательного использования Kubernetes.

### Временные ограничения и лимиты

- **Максимальная длительность задачи (Job)**: 6 часов.
- **Время ожидания в очереди**: Если задача не принята в течение 45 минут, запуск отменяется.
- **Таймаут по умолчанию**: 360 минут (рекомендуется ограничивать через `timeout-minutes` для экономии бюджета).

### Тарификация в 2026 году

GitHub перешел на прозрачную модель "Actions Cloud Platform":
1.  **Публичные репозитории**: Использование любых стандартных и собственных исполнителей остается **бесплатным**.
2.  **Приватные репозитории**:
    *   Применяется поминутная тарификация в зависимости от типа ОС (Linux — от $0.006, Windows — от $0.010, macOS — от $0.062).
    *   Все цены для GitHub-hosted уже включают сбор за платформу ($0.002).
    *   Для Self-hosted исполнителей в приватных репозиториях взимается только сбор за платформу ($0.002/мин).

### Сетевое взаимодействие и безопасность

- **Доступ к ресурсам в VPC (Virtual Private Cloud)**: Собственные исполнители могут быть размещены непосредственно внутри приватной сети организации для доступа к БД или внутренним API без открытия внешних портов.
- **Безопасность PR (Pull Request)**: Использование собственных исполнителей в публичных репозиториях по-прежнему требует ручного подтверждения (`approval`) для защиты внутреннего периметра от вредоносного кода из форков.
- **Минимальные права доступа**: Рекомендуется всегда ограничивать права временного токена `GITHUB_TOKEN` через секцию `permissions` на уровне задачи.

## Практические сценарии

### Сценарий 1: Экономия бюджета при использовании Self-hosted

**Проблема**: В приватном репозитории выполняется множество легких задач (линтинг, проверка синтаксиса), за которые взимается полная стоимость облачных минут.

**Решение**: Использование собственных исполнителей. В этом случае оплачивается только сбор за платформу ($0.002/мин), что значительно дешевле аренды полноценной VM у GitHub ($0.006+).

### Сценарий 2: Ограничение ресурсов для критических деплоев

```yaml
jobs:
  deploy-to-production:
    runs-on: ubuntu-latest
    timeout-minutes: 60 # Предотвращение зависания и перерасхода бюджета
    permissions:
      contents: read
      id-token: write    # Разрешение на использование OIDC
    steps:
      - name: Authenticate to Cloud Provider
        uses: cloud-provider/auth-action@v1
        with:
          workload-identity-provider: 'projects/123/locations/global/workloadIdentityPools/my-pool/providers/my-provider'
```
