# GitHub Actions: Ограничения и Среды Выполнения (Runners)

Выбор среды выполнения (`runner`) — ключевое архитектурное решение в GitHub Actions. От него зависят доступные ресурсы, скорость, безопасность и возможности ваших CI/CD пайплайнов.

## Определения

- **GitHub-hosted runner**: Виртуальная машина, управляемая и обслуживаемая GitHub. Предоставляется по запросу с предустановленным набором ПО (ОС, утилиты, языковые рантаймы). Среда является эфемерной и уничтожается после завершения задачи (`job`).
- **Self-hosted runner**: Ваш собственный сервер (физический, VM, контейнер), на котором установлено ПО агента GitHub Actions. Вы полностью контролируете его окружение, ресурсы и сетевой доступ, но также несете ответственность за его обслуживание.

## Основные концепции

### Ключевые различия

| Категория | GitHub-hosted | Self-hosted |
| :--- | :--- | :--- |
| **Обслуживание** | Нет, управляется GitHub | Полностью ваша ответственность |
| **Окружение** | Стандартное, обновляется GitHub | Кастомное, настраивается вами |
| **Ресурсы** | Фиксированные (2-core CPU, 7GB RAM) | Ограничены только вашим хостом |
| **Сеть** | Динамические публичные IP | Контролируемый доступ, статические IP |
| **Безопасность** | Высокая изоляция, но риски для публичных репозиториев | Ваша ответственность |
| **Стоимость** | Включено в тариф (с лимитами) | Стоимость вашей инфраструктуры |

### Ограничения ресурсов

- **Время выполнения**: Задачи (`jobs`) на hosted-runner'ах ограничены по времени (до 6 часов). Для долгих задач используйте `timeout-minutes` или self-hosted runner'ы.
- **CPU и RAM**: Фиксированные ресурсы могут быть недостаточны для "тяжелых" сборок, компиляции или интенсивных тестов.
- **Дисковое пространство**: Место на диске ограничено. Для работы с большими артефактами или кэшем требуется оптимизация.

### Сеть и Безопасность

- **Доступ к приватным ресурсам**: Hosted-runner'ы имеют динамические IP-адреса, что усложняет доступ к базам данных или серверам за файрволом. Эту проблему решают self-hosted runner'ы, размещенные в вашей приватной сети.
- **Права доступа**: По умолчанию `GITHUB_TOKEN` имеет ограниченные права. Используйте секцию `permissions`, чтобы явно выдавать только необходимые разрешения. Для self-hosted runner'ов риски выше, так как они имеют доступ к вашей внутренней инфраструктуре.

## Практические сценарии

### Сценарий 1: Требуется доступ к приватной сети

**Проблема**: Тестам нужен доступ к staging-базе данных, которая находится за файрволом и доступна только из внутренней сети компании.

**Решение**: Использовать **self-hosted runner**, развернутый на виртуальной машине в той же приватной сети (VPC), что и база данных.

### Сценарий 2: Управление временем выполнения и правами

**Проблема**: Сборка мобильного приложения может занимать много времени, а для публикации в Google Play требуется OIDC-токен.

**Решение**: Использовать `timeout-minutes`, чтобы прервать "зависшую" сборку, и выдать разрешение `id-token: write` только для конкретной задачи.

```yaml
jobs:
  build-and-deploy:
    runs-on: macos-latest # Сборка под iOS/macOS
    timeout-minutes: 90
    permissions:
      contents: read
      id-token: write # Разрешение на получение OIDC-токена
    steps:
      - name: Build app
        run: ./build-app.sh
      - name: 'Authenticate to Google Cloud'
        uses: 'google-github-actions/auth@v2'
        with:
          workload_identity_provider: 'projects/123/locations/global/workloadIdentityPools/my-pool/providers/my-provider'
          service_account: 'my-service-account@my-project.iam.gserviceaccount.com'
      # ... шаги для деплоя
```
