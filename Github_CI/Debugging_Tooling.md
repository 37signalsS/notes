# GitHub Actions: Инструменты разработки и отладки воркфлоу

**Актуально для:** GitHub Actions, октябрь 2026 (actionlint v1.7.12, zizmor v1.30.1, act v0.2.89, action-tmate v3.24)

Проверка воркфлоу до пуша и интерактивная отладка падений экономят часы итераций «коммит → ожидание → лог». Блок охватывает локальный запуск, статический анализ, аудит безопасности и SSH-отладку.

## Определения

- **act**: Локальный раннер воркфлоу (проект nektos/act): исполняет задачи в Docker-контейнерах на собственной машине без push в GitHub.
- **actionlint**: Статический анализатор воркфлоу: проверяет выражения `${{ }}`, контексты, матрицы, типы событий; интегрирует shellcheck для `run`-шагов.
- **zizmor**: Аудитор безопасности воркфлоу: находит template injection, опасные `pull_request_target`, избыточные permissions и другие антипаттерны.
- **pre-commit Hook**: Локальный хук Git, запускающий проверки перед коммитом; экосистема pre-commit фреймворка описывает хуки декларативно.
- **tmate-сессия**: Интерактивный SSH-доступ к живому раннеру внутри упавшей задачи (экшен `mxschmitt/action-tmate`).
- **Debug-секреты**: Зарезервированные имена `ACTIONS_STEP_DEBUG`/`ACTIONS_RUNNER_DEBUG`, включающие расширенное логирование (детали — в [Управлении секретами](./secrets_management.md)).

## Основные концепции

### Уровни проверки до пуша

| Уровень | Инструмент | Что ловит | Время |
| :--- | :--- | :--- | :--- |
| Схема YAML | IDE + SchemaStore | Опечатки ключей, неверные типы | мгновенно |
| Семантика | actionlint | Несуществующие контексты, ошибки выражений, битые матрицы | секунды |
| Безопасность | zizmor | Инъекции, permissions, опасные триггеры | секунды |
| Исполнение | act | Реальное поведение run-шагов локально | минуты |
| Продакшен | hosted-раннер + debug-логи | Всё остальное (интеграции, сервисы) | минуты |

Экономика: статика бесплатна и должна стоять раньше всего; act полезен для итерации по shell-шагам, но не эмулирует платформенные особенности (см. ниже).

### Возможности и границы `act`

```bash
brew install act
act -l                                    # список воркфлоу и задач для события
act push -j test                          # прогнать задачу test события push
act pull_request --secret-file .secrets   # секреты из файла вне git
act workflow_dispatch -e event.json        # payload события из файла (--eventpath)
-P ubuntu-latest=catthehacker/ubuntu:act-24.04    # маппинг образа метки (пин по версии ОС)
```

- Поддерживаются только Linux-контейнеры: задачи с `windows-*`/`macos-*` и GPU-раннеры локально невоспроизводимы.
- На Apple Silicon образы `ubuntu-latest` собраны под `linux/amd64`: если контейнер не стартует, добавьте `--container-architecture=linux/amd64`.
- Часть платформенного окружения отсутствует или отличается: предустановленный софт hosted-образов, service containers (частично), OIDC-токены. Артефакты поддерживаются, но artifact-сервер не поднимается автоматически — его включает `--artifact-server-path`. Результат «зелёный в act» не гарантирует зелёный CI — инструмент для быстрой итерации, а не для вердикта.
- Постоянные флаги (маппинг образов, архитектура, `-e`) удобно хранить по одному на строку в `.actrc` — файл читается автоматически.
- Для приватных сценариев, зависящих от `GITHUB_TOKEN`, токен передаётся секретом: `act -s GITHUB_TOKEN="$(gh auth token)"`.
- Секреты никогда не кладите в репозиторий: `.secrets` добавляется в `.gitignore`.

### actionlint: что именно проверяется

- Выражения `${{ }}`: несуществующие контексты/поля, типовые ошибки сравнения строк с boolean, недопустимые в конкретном ключе контексты;
- Матрицы: обращение к несуществующим измерениям;
- Триггеры: опечатки событий, недопустимые комбинации;
- YAML-конструкции: неподдерживаемый merge-ключ `<<`, неиспользуемые и неопределённые anchors (`&anchor`/`*anchor`);
- `run:` скрипты прогоняются через **shellcheck**, а inline-Python — через **pyflakes** (если установлены);
- Ложные срабатывания подавляются `-ignore '<regex>'`; внешние интеграции отключаются `-shellcheck=` и `-pyflakes=`;
- Коды возврата: `0` — замечаний нет, `1` — найдены замечания, `2` — ошибка аргументов, `3` — фатальная ошибка;
- Локально: `actionlint` в корне репозитория; в CI — Docker-образ `rhysd/actionlint` (несёт в себе shellcheck и pyflakes) либо готовый workflow-экшен проекта.

### zizmor: категории аудита

- Template injection: пользовательский ввод в `run:` без env-прослойки (правило непрямой подстановки — разобрано в [Синтаксисе](./Workflow_Syntax.md));
- Dangerous triggers: `pull_request_target` без изоляции кода форка;
- Excessive permissions: отсутствие минимального блока `permissions`;
- Hardcoded credentials: `hardcoded-container-credentials` — учётные данные внутри `container:`/`services:`;
- Persisted credentials: `artipacked` — `actions/checkout` без `persist-credentials: false` оставляет токен в `.git/config`;
- Непинованные зависимости: `unpinned-uses` — обращение к экшену по плавающему тегу вместо commit SHA.

Запуск: `zizmor .` в корне. Ключевые опции:

- `--fix` (`safe`/`unsafe-only`/`all`) — автоисправление находок; `--fix=all` может изменить логику, поэтому требует ревью диффа;
- `--persona=regular|pedantic|auditor` — уровень чувствительности анализа (`--pedantic` — алиас);
- `--format=plain|json|sarif|github` — `sarif` для code scanning (Advanced Security), `github` для аннотаций прямо в PR;
- `--min-severity`/`--min-confidence` — порог фильтрации находок.

Подавление — точечно комментарием `# zizmor: ignore[rule]` либо через конфиг `zizmor.yml`. Коды возврата зависят от максимальной severity находки (`11` informational … `14` high), поэтому в CI не требуется парсить вывод — шаг падает сам при находке выше порога. Аудит включается в обязательные проверки так же, как линтеры кода.

### tmate: интерактивная отладка живого раннера

- Экшен открывает SSH-сессию в середину задачи: можно смотреть файлы workspace, процессы, повторять команды вручную.
- Обязательные предохранители: шаг только при падении (`if: failure()`), таймаут (`timeout-minutes`), ограничение доступа (`limit-access-to-actor: true`). Публичный URL сессии = шелл на вашей инфраструктуре: на публичных репозиториях без ограничений включать запрещено политикой безопасности (модель угроз self-hosted — в [Сетевой безопасности](./network-security.md)).
- Альтернатива без интерактива: архив workspace артефактом прямо перед точкой падения.

## Практические сценарии

### Сценарий 1: Быстрая итерация над задачей через act

**Предварительные требования**: Docker запущен локально; act установлен.

```bash
# 1. Файл секретов ВНЕ git
cat > .secrets <<'EOF'
NPM_TOKEN=fake-local-token
EOF
echo ".secrets" >> .gitignore

# 2. Прогон одной задачи текущей рабочей копии (без push)
act -j lint --secret-file .secrets
# → [lint/lint] ⭐ Run main → eslint .
# → [lint/lint] ✅ Success

# 3. Отладка конкретного шага с verbose-логами
act -j test -v --step "Run integration tests"
```

- Каждый параметр: `-j` выбирает задачу (без него исполнятся все); `--step` фильтрует по имени шага; `-v` включает debug-вывод, аналог `ACTIONS_STEP_DEBUG`.
- **Валидация**: вывод шага совпадает с поведением в CI на уровне команд; отличия окружения фиксируются осознанно (версия node в локальном образе vs матрица).
- Границы применимости: если задача использует `services:` или OIDC — проверять их только на hosted-раннере.

### Сценарий 2: Метаворкфлоу — линт всех воркфлоу репозитория

```yaml
name: Workflow Lint
on:
  pull_request:
    paths: ['.github/workflows/**', '.github/actions/**']
jobs:
  lint:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v7
      - name: actionlint
        uses: docker://rhysd/actionlint:1.7.12
        with:
          args: -color
      - name: zizmor
        run: |
          pipx install zizmor
          zizmor --format=github --min-severity medium .github/workflows/
```

- Запуск по путям: линт крутится только когда меняются сами воркфлоу; находки zizmor блокируют мерж, если проверка объявлена обязательной (механика required checks — в [Оптимизации](./Optimization.md)).
- `--format=github` превращает находки zizmor в аннотации прямо в диффе PR и не требует расширенных прав. Альтернативный поток — `zizmor --format=sarif` + `github/codeql-action/upload-sarif` для вкладки code scanning (Security → Code scanning): тогда в блок `permissions` добавляют `security-events: write`.
- **Валидация**: PR с опечаткой в контексте (`github.event.pullrequest`) получает красную задачу с указанием файла и строки; инъекционный шаг ловится zizmor'ом с severity high.

### Сценарий 3: pre-commit hook с actionlint

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/rhysd/actionlint
    rev: v1.7.12                    # пин версии хука
    hooks:
      - id: actionlint              # локально установленный бинарь (нужен Go/Docker-вариант ниже)
        args: ["-color"]
```

```bash
pipx install pre-commit && pre-commit install
pre-commit run actionlint --all-files
# → actionlint............................................Passed
```

- Хук останавливает сломанный воркфлоу ещё до коммита; ревью хука версионируется вместе с репозиторием.
- Если Go-бинарь не нужен, в том же репозитории есть хуки `actionlint-docker` (образ `rhysd/actionlint`) и `actionlint-system` (подхватывает уже установленный бинарь из `$PATH`).
- Версию хука обновляют `pre-commit autoupdate`; общая механика Git Hooks и фреймворка pre-commit — в [Git Hooks](../Git/git_hooks.md).
- **Валидация**: внести синтаксическую ошибку в workflow, попытаться закоммитить — коммит блокируется выводом линтера.

### Сценарий 4: SSH-сессия в упавшей задаче

```yaml
      - name: Debug session on failure
        if: failure()                       # только при провале предыдущих шагов
        uses: mxschmitt/action-tmate@v3
        with:
          limit-access-to-actor: true       # SSH только для инициатора прогона
          timeout-minutes: 15               # жёсткий потолок сессии
```

- Сессия выдаёт публичный SSH-адрес в лог; соединение доступно до таймаута или ручного создания файла `/continue`.
- **Валидация**: воспроизвести падение на ветке, подключиться по адресу из лога, проверить состояние workspace (`ls /home/runner/work/<repo>`), выйти созданием `/continue` — задача продолжится и завершится штатно.
- Правило эксплуатации: включать точечно на feature-ветках при разборе необъяснимых падений; постоянное присутствие в main-пайплайне запрещено.

## Устранение неполадок

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `Cannot connect to the Docker daemon` у act | Docker не запущен локально | Стартовать демон; проверить `docker ps` |
| act падает на задаче с windows/macos | Локально только Linux-контейнеры | Прогонять такие задачи только в CI |
| «В act зелёное, в CI красное» | Расхождение образов/окружения | Сверить версии инструментов; использовать `-P` с образом ближе к hosted |
| actionlint ложный shellcheck-варнинг | Динамика `${{ }}` мешает статическому разбору | `# shellcheck disable=SC2086` точечно либо `--shellcheck=` отключение |
| act падает с `exec format error` на Apple Silicon | Образ `ubuntu-latest` собран под `linux/amd64`, хост — arm64 | `act --container-architecture=linux/amd64` (или строка в `.actrc`) |
| act не выгружает артефакты | artifact-сервер не стартует автоматически | Добавить `--artifact-server-path $PWD/.artifacts` |
| zizmor ругается на легитимный паттерн | Осознанное исключение | Точечно `# zizmor: ignore[rule]` или правило в `zizmor.yml`; зафиксировать в ревью |
| Шаг zizmor «внезапно» падает в CI | Код возврата ненулевой при находке (по severity `11`–`14`) | Это ожидаемо: поднять `--min-severity`, исправить или подавить находку |
| tmate-сессия зависла, джоб висит | Нет таймаута шага | Всегда задавать `timeout-minutes`; завершать сессию файлом `/continue` |
| Секреты не видны в act | act читает их из файла/окружения, не из GitHub | `--secret-file .secrets` вне git |

## Лучшие практики

1. Соблюдайте порядок shift-left: IDE-схема → actionlint/zizmor в pre-commit → метаворкфлоу в PR → продакшен.
2. Линтер воркфлоу делайте обязательной проверкой — сломанный YAML должен блокировать мерж так же, как сломанный код. Находки показывайте аннотациями в PR (`--format=github`) или заливайте SARIF в code scanning.
3. act используйте для итерации по шагам, а не как замену CI-верификации: платформенные интеграции проверяются только на hosted-раннере.
4. Каждая находка zizmor либо исправляется, либо подавляется с письменным обоснованием (`# zizmor: ignore[rule]` или `zizmor.yml`) — молчаливых исключений быть не должно.
5. tmate — инструмент разбора инцидентов, а не элемент конвейера; доступ ограничивать актором, время — таймаутом.
6. Debug-секреты (`ACTIONS_STEP_DEBUG`) включать точечно и удалять после диагностики (чеклист диагностики TTR — в [Оптимизации](./Optimization.md)).
7. Пините версии инструментов и образов (actionlint `1.7.12`, zizmor, act): «плавающий» `latest` в шаге CI делает результат невоспроизводимым и ломает сборку при выпуске новой мажорной версии.
