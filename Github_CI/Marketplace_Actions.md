# GitHub Actions: Готовые действия и Marketplace

Готовые действия (`actions`) — это переиспользуемые блоки автоматизации, составляющие основу экосистемы GitHub Actions. Они позволяют использовать проверенные решения для типовых задач, сокращая время на разработку и поддержку процессов CI/CD (Continuous Integration / Continuous Deployment — непрерывная интеграция и непрерывное развертывание).

## Определения

- **Action (Действие)**: Автономный, переиспользуемый программный компонент, который можно встроить как отдельный шаг (`step`) в задачу (`job`).
- **GitHub Marketplace**: Централизованный публичный реестр для поиска, обмена и публикации готовых действий.
- **Verified Creator (Проверенный автор)**: Значок (синяя галочка), подтверждающий, что автор действия является проверенным партнером GitHub или официальной организацией.

## Основные концепции

### Типы реализации действий

1. **JavaScript Action**: Выполняется непосредственно в среде исполнителя (`runner`) с использованием Node.js. Самый производительный и распространенный тип. С 2026 года стандартом является использование Node.js 24.
2. **Docker Action**: Запускается внутри изолированного Docker-контейнера. Гарантирует идентичность окружения, но имеет накладные расходы на запуск контейнера. Работает только на Linux-исполнителях.
3. **Composite Action**: Объединяет несколько шагов рабочего процесса (включая `run` и другие `uses`) в один компонент. Позволяет создавать сложные цепочки автоматизации на базе YAML без написания кода.

### Местоположение и доступность

- **Публичные действия**: Доступны в GitHub Marketplace для всех пользователей.
- **Локальные действия**: Определяются непосредственно в репозитории проекта (обычно в `.github/actions/`). Вызываются через относительный путь: `uses: ./.github/actions/my-action`.
- **Внутренние (Internal) действия**: Доступны только внутри организации или Enterprise-аккаунта. Позволяют безопасно делиться наработками между приватными репозиториями без публикации в открытый доступ.

### Версионирование и безопасность

При выборе действий следует отдавать предпочтение официальным репозиториям (`actions/*`) и проверенным авторам.

**Стратегии указания версии:**

- **Мажорный тег** (например, `uses: actions/checkout@v7`): Рекомендуемый способ. Обеспечивает получение критических обновлений и исправлений безопасности в рамках мажорной версии.
- **Хеш коммита (SHA)** (например, `uses: actions/checkout@5a4ac90...`): Самый безопасный метод, защищающий от подмены тега (Immutable). Рекомендуется для сред с высокими требованиями к безопасности.
- **Ветка** (например, `uses: actions/checkout@main`): Крайне не рекомендуется, так как поведение пайплайна может измениться непредсказуемо.

## Безопасное использование

1. **Минимизация привилегий**: Всегда настраивайте секцию `permissions` для ограничения прав `GITHUB_TOKEN`.
2. **Аудит кода**: Перед использованием стороннего действия изучите его исходный код на предмет скрытых сетевых вызовов или некорректной обработки секретов.
3. **Защита от Fork-атак**: Начиная с `actions/checkout@v7`, по умолчанию блокируется получение кода из форков в привилегированных воркфлоу (`pull_request_target`, `workflow_run`). Для изменения этого поведения требуется явный флаг `allow-unsafe-pr-checkout: true`.
4. **Использование официальных инструментов**: Для мониторинга сетевой активности действий рекомендуется использовать **[Harden-Runner](./network-security.md)**.

## Практические сценарии

### Настройка окружения с актуальными версиями действий

Пример рабочего процесса с использованием стандартов 2026 года:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      # Загрузка кода (версия v7 с улучшенной безопасностью)
      - name: Checkout code
        uses: actions/checkout@v7

      # Настройка Node.js (версия v7 с поддержкой Node 24)
      - name: Setup Node.js
        uses: actions/setup-node@v7
        with:
          node-version: '24'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test
```
