# Использование Actions из GitHub Marketplace

GitHub Marketplace предоставляет готовые переиспользуемые шаги для автоматизации типовых задач: получение кода, настройка окружений, кэширование зависимостей, публикация артефактов, уведомления. Подключение происходит через директиву uses в steps. Ключевой навык — осознанный выбор, корректная фиксация версий и безопасная интеграция.

## Виды Actions и отличия

| Тип | Как работает | Плюсы | Особенности |
| :--- | :--- | :--- | :--- |
| JavaScript (Node) | Запускается на хосте раннера | Быстро, кроссплатформенно | Доступ к файловой системе раннера |
| Docker | Выполняется в контейнере | Изоляция, воспроизводимость среды | Требует Docker на раннере; медленнее cold start |
| Composite | Комбинация нескольких шагов | Прозрачность, без доп. рантайма | Зависит от установленного в раннере софта |

Выбор типа влияет на скорость, изоляцию и совместимость с ОС/архитектурой раннера.

## Версионирование и фиксация

Action можно подключать по тегу, ветке или commit SHA. Для предсказуемости рекомендуется пиннинг на commit SHA, при этом допускается использование мажорного тега для регулярного обновления вручную.

Примеры:

```bash
# Мажорный тег (удобно, но обновляется автором)
uses: actions/checkout@v4

# Жесткая фиксация (рекомендуется для критичных цепочек)
uses: actions/checkout@3df4f17a7b...
```

Поддерживайте внутренний реестр «доверенных» версий и периодически обновляйте их после проверки изменений.

## Входы и выходы (with/outputs)

Большинство Actions принимает параметры через with и публикует outputs. Для использования outputs присвойте шагу id и обращайтесь через steps..outputs..

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Cache NPM
        id: cache
        uses: actions/cache@v4
        with:
          path: ~/.npm
          key: npm-${{ runner.os }}-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            npm-${{ runner.os }}-

      - run: npm ci

      - name: Проверка кэша
        if: steps.cache.outputs.cache-hit == 'true'
        run: echo "Кэш восстановлен"
```

## Критерии выбора в Marketplace

*   Поддержка платформ: linux/windows/macos, x86_64/arm64, self-hosted.
*   Популярность и активность: количество установок, частота релизов, закрытые issues/PR.
*   Прозрачность: открытый исходный код, чёткие релизы и changelog.
*   Минимальные разрешения: не требует лишнего доступа к репозиторию и секретам.
*   Совместимость с вашим стеком: версии языков, менеджеры пакетов, требуемый софт.

## Безопасное использование

*   Ограничайте GITHUB_TOKEN через permissions в уровне job или workflow, выдавая только необходимые скоупы.
*   Для действий, работающих с кодом, используйте浅кую историю при checkout и отключайте автоматическую запись учётных данных.
*   Проверяйте Dockerfile/entrypoint у Docker Actions, оцените устанавливаемые пакеты и сетевые обращения.

Пример минимальных разрешений:

```yaml
permissions:
  contents: read
  packages: read
```

## Распространённые Actions и паттерны

*   actions/checkout для получения кода.
*   actions/setup-<язык> для подготовки рантайма.
*   actions/cache для ускорения сборок.
*   upload-artifact/download-artifact для обмена артефактами между job’ами.

Комбинируя эти компоненты, формируют воспроизводимые и быстрые конвейеры, где внешние Actions остаются контролируемой и безопасной зависимостью.
