# GitHub Actions: Готовые Действия (Actions) и Marketplace

Готовые действия (`actions`) — это переиспользуемые блоки автоматизации, которые являются основой экосистемы GitHub Actions. Они позволяют не изобретать велосипед для типовых задач.

## Определения

- **Action (Действие)**: Инкапсулированный, переиспользуемый скрипт, который можно встроить как шаг (`step`) в задачу (`job`).
- **GitHub Marketplace**: Централизованный репозиторий для поиска и публикации готовых `actions`.

## Основные концепции

### Типы Actions

- **JavaScript Action**: `Action` на Node.js, который выполняется непосредственно на `runner`. Это самый быстрый и распространенный тип.
- **Docker Action**: `Action`, который запускается внутри Docker-контейнера. Обеспечивает максимальную изоляцию, но работает медленнее.
- **Composite Action**: `Action`, который объединяет несколько шагов (`steps`) в один. Позволяет создавать более сложные `actions` без написания кода.

### Выбор и Версионирование

- **Поиск**: Основной источник — [GitHub Marketplace](https://github.com/marketplace?type=actions). Критерии: популярность, активность поддержки, открытый исходный код.
- **Версионирование**: Рекомендуется использовать мажорный тег (`@v4`), чтобы получать обновления без ломающих изменений. Для максимальной стабильности можно закрепить версию за хешем коммита.
  - `uses: actions/checkout@v4` (Рекомендуется)
  - `uses: actions/checkout@main` (Нестабильно)
  - `uses: actions/checkout@5a4ac90...` (Максимально стабильно)

### Безопасное Использование

1.  **Ограничивайте права**: Всегда используйте секцию `permissions`, чтобы выдать `GITHUB_TOKEN` только минимально необходимые права.
2.  **Изучайте исходный код**: Проверяйте код `action` на предмет подозрительных вызовов или работы с секретами.
3.  **Остерегайтесь `pull_request_target`**: Событие `pull_request` от форка выполняется с токеном только для чтения и без доступа к секретам. Однако `pull_request_target` выполняется в контексте базовой ветки и имеет доступ к секретам. Вредоносный PR с этим триггером может их похитить.

### Входы и Выходы (`with` и `outputs`)

- **`with`**: Позволяет передавать параметры (входные данные) в `action`.
- **`outputs`**: Позволяет `action` возвращать результат. Для доступа к нему шагу нужно присвоить `id`.

## Практический сценарий: Использование Actions

Этот пример использует три популярных `action` для настройки CI-пайплайна.

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    permissions:
      contents: read # Даем права только на чтение кода
    steps:
      # 1. Action для клонирования репозитория
      - name: Checkout code
        uses: actions/checkout@v4

      # 2. Action для настройки Node.js со встроенным кешированием
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test
```
В данном примере `actions/setup-node` использует свою встроенную функциональность для кеширования, что является предпочтительным способом.
