# GitHub Actions: Сетевая безопасность и контроль трафика

Контроль исходящего сетевого трафика CI-раннеров позволяет устранить "слепую зону" в безопасности пайплайнов, предотвращая утечку секретов и загрузку вредоносного кода.

## Определения

| Термин | Описание |
|--------|----------|
| **Egress Policy** | Политика управления исходящим трафиком (разрешение/блокировка соединений) |
| **Harden-Runner** | Решение от Step Security для мониторинга и ограничения сетевой активности GitHub-раннеров |
| **Audit Mode** | Режим мониторинга, при котором все соединения логируются, но не блокируются |
| **Block Mode** | Режим защиты, блокирующий любые соединения, не входящие в белый список |

## Базовые концепции

### Зачем нужен контроль трафика

1. **Предотвращение утечки данных:** Блокировка попыток отправить `GITHUB_TOKEN` или другие секреты на сторонние серверы.
2. **Защита от атак на цепочку поставок:** Ограничение доступа только доверенными репозиториями и реестрами (npm, PyPI, GitHub).
3. **Видимость (Visibility):** Понимание того, какие внешние ресурсы требуются для сборки.

### Стратегия внедрения

Рекомендуется использовать постепенный подход:

1. **Этап "Audit":** Сбор данных о реальном сетевом профиле пайплайна в течение недели.
2. **Анализ:** Определение минимально необходимого списка эндпоинтов.
3. **Этап "Block":** Переключение на блокирующий режим с белым списком.

## Практические сценарии

### Интеграция Harden-Runner

Для активации контроля трафика необходимо добавить шаг с `harden-runner` первым в каждую задачу (`job`).

#### Пример конфигурации (Audit)

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Harden Runner
        uses: step-security/harden-runner@v2
        with:
          egress-policy: audit # Только логирование для анализа трафика
```

#### Пример конфигурации (Block)

После анализа логов можно ограничить трафик только необходимыми эндпоинтами:

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Harden Runner
        uses: step-security/harden-runner@v2
        with:
          egress-policy: block
          allowed-endpoints: >
            github.com:443
            registry.npmjs.org:443
            objects.githubusercontent.com:443

      - uses: actions/checkout@v4
      - run: npm ci
```

Любое неожиданное соединение (например, с вредоносным сервером) приведет к немедленному падению билда.
