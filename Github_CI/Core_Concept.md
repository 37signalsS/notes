# GitHub Actions: Ключевые концепции

**GitHub Actions** — встроенная в GitHub платформа для автоматизации полного жизненного цикла разработки ПО (CI/CD). Основная идея — «автоматизация как код»: все сценарии описываются в YAML-файлах, хранятся в репозитории и запускаются в ответ на события.

## Определения

- **Workflow (Рабочий процесс)**: Автоматизированный сценарий, состоящий из одной или нескольких задач (`jobs`). Описывается в `.yml` файле в директории `.github/workflows`.
- **Event (Событие)**: Триггер, который запускает workflow. Например: `push` в ветку, создание `pull request`, запуск по расписанию (`schedule`), вызов через API или вручную (`workflow_dispatch`).
- **Job (Задача)**: Набор шагов (`steps`), который выполняется на одной среде исполнения (`runner`). Задачи могут выполняться параллельно или последовательно (с явными зависимостями).
- **Step (Шаг)**: Отдельная команда или действие (`action`). Шаги внутри одной задачи выполняются последовательно.
- **Action (Действие)**: Переиспользуемый компонент, который можно подключить в шаге. Это может быть простая shell-команда или готовый модуль из [GitHub Marketplace](https://github.com/marketplace?type=actions).
- **Runner (Исполнитель)**: Среда выполнения для задач. GitHub предоставляет готовые виртуальные машины (GitHub-hosted) или позволяет использовать собственные (self-hosted).

## Основные концепции

### Модель выполнения

1. **Событие**: Происходит триггер (например, `git push`).
2. **Запуск Workflow**: GitHub Actions находит соответствующий workflow-файл.
3. **Выделение Runner'а**: Для каждой задачи (`job`) выделяется свежая виртуальная среда (`runner`).
4. **Выполнение Job**: Runner последовательно выполняет шаги (`steps`) задачи.
5. **Завершение**: После выполнения всех задач runner уничтожается (для GitHub-hosted).

Эта модель обеспечивает изоляцию и чистоту окружения для каждой задачи.

### Автоматизация как код

Хранение конфигурации CI/CD вместе с кодом (`.github/workflows/ci.yml`) дает ключевые преимущества:

- **Версионирование**: Изменения в пайплайнах отслеживаются через Git.
- **Прозрачность**: Любой участник команды может видеть и предлагать улучшения для процессов автоматизации.
- **Воспроизводимость**: Конфигурация привязана к конкретному коммиту.

### Типы Runner'ов

**GitHub-hosted runners**:
- Предоставляются и поддерживаются GitHub
- Свежие образы ОС (Ubuntu, Windows, macOS) с предустановленным ПО
- Изоляция: каждый job запускается на чистой VM
- Тарификация: поминутно, с бесплатным лимитом для публичных репозиториев

**Self-hosted runners**:
- Разворачиваются в вашей инфраструктуре (on-premise, private cloud, VPC)
- Полный контроль над конфигурацией, сетевым доступом, секретами
- Экономия минут для приватных репозиториев
- Требуют самостоятельного обслуживания и обновления

**Actions Runner Controller (ARC)**:
- Kubernetes-нативный контроллер для управления self-hosted runners
- Автоматическое масштабирование (ephemeral runners)
- Интеграция с GitHub Enterprise

### Безопасность

**GITHUB_TOKEN**:
- Автоматически генерируемый токен для доступа к ресурсам репозитория
- Область действия ограничена текущим workflow и репозиторием
- Рекомендуется использовать с минимальными правами через `permissions`

**OpenID Connect (OIDC)**:
- Бессекретная аутентификация в облачных провайдерах (AWS, Azure, GCP)
- Токены OIDC заменяют долгосрочные секреты
- Повышенная безопасность деплоев в облако

**Secrets**:
- Шифруемые переменные для хранения чувствительных данных
- Не отображаются в логах
- Могут быть на уровне репозитория, организации или окружения

## Практические сценарии

### Минимальный CI-пайплайн

Базовый workflow для Node.js проекта с кешированием зависимостей:

```yaml
name: CI

on:
  push:
    branches: [ main ]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test
```

### Матричные сборки

Параллельное тестирование на нескольких версиях Node.js:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18, 20, 22]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      - run: npm test
```
