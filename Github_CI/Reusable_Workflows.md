# GitHub Actions: Переиспользуемые рабочие процессы

Переиспользуемые рабочие процессы (Reusable Workflows) — это архитектурный механизм в GitHub Actions, позволяющий одному воркфлоу вызывать другой. Это ключевой инструмент для соблюдения принципа DRY (Don't Repeat Yourself), централизации логики CI/CD и стандартизации процессов безопасности во всей организации.

## Определения

- **Reusable Workflow (Переиспользуемый процесс)**: Воркфлоу, предназначенный для вызова. Содержит триггер `on: workflow_call`.
- **Caller Workflow (Вызывающий процесс)**: Воркфлоу, который инициирует выполнение переиспользуемого процесса через ключ `uses`.
- **Workflow Call**: Событие-триггер, активируемое внешним вызовом.
- **`secrets: inherit`**: Механизм автоматической передачи всех доступных секретов вызывающего процесса в переиспользуемый.

## Основные концепции

### Создание переиспользуемого процесса

Для того чтобы файл стал доступным для вызова, он должен находиться в директории `.github/workflows` и содержать триггер `workflow_call`.

**Параметры конфигурации:**
- **`inputs`**: Входные данные (строки, числа, логические значения). Обязательно указывается `type`.
- **`secrets`**: Определение необходимых секретов. Могут быть помечены как `required: true`.
- **`outputs`**: Данные, передаваемые обратно вызывающему процессу на уровне задач.

### Сравнение: Reusable Workflows vs Composite Actions

Понимание различий критично для выбора правильной архитектуры:

| Характеристика | Reusable Workflows | Composite Actions |
| :--- | :--- | :--- |
| **Уровень** | Задача (`job`) целиком | Шаги (`steps`) внутри задачи |
| **Логирование** | Отдельные задачи в UI GitHub | Все шаги внутри одного блока Action |
| **Секреты** | Доступны через `secrets: inherit` | Требуют явной передачи как `inputs` |
| **Исполнитель** | Можно задать `runs-on` внутри | Использует `runs-on` вызывающей задачи |
| **Окружения** | Поддержка `environment` | Не поддерживают `environment` напрямую |

### Безопасность и права доступа

- **Наследование секретов**: Использование `secrets: inherit` удобно в рамках одной организации, но требует осторожности в публичных репозиториях. Рекомендуется явно перечислять секреты для повышения прозрачности.
- **Права GITHUB_TOKEN**: Переиспользуемый процесс наследует права от вызывающей задачи. Однако он может запрашивать собственные `permissions`, если они не превышают права вызывающего процесса.
- **Изоляция**: Задачи в переиспользуемом воркфлоу выполняются в изолированных средах, что предотвращает утечку временных файлов между ними.

## Практические сценарии

### Сценарий 1: Шаблон деплоя в облако (Node.js 24)

Пример переиспользуемого процесса (`reusable-deploy.yml`), который стандартизирует деплой с использованием OIDC.

```yaml
name: Standard Deployment

on:
  workflow_call:
    inputs:
      env:
        required: true
        type: string
    secrets:
      deploy_token:
        required: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: ${{ inputs.env }}
    steps:
      - uses: actions/checkout@v7
      - name: Setup Node
        uses: actions/setup-node@v7
        with:
          node-version: '24'
      - name: Deploy
        run: ./scripts/deploy.sh --token ${{ secrets.deploy_token }}
```

### Сценарий 2: Вызов процесса из другого репозитория

Для использования процессов внутри организации рекомендуется создать центральный репозиторий `.github` или `ci-templates`.

```yaml
jobs:
  call-external:
    uses: my-org/ci-templates/.github/workflows/reusable-build.yml@v1
    with:
      build-type: 'release'
    secrets: inherit
```

### Сценарий 3: Использование матриц с переиспользуемыми воркфлоу

Матрица позволяет запускать один и тот же переиспользуемый воркфлоу для разных конфигураций параллельно.

```yaml
jobs:
  cross-test:
    strategy:
      matrix:
        version: [20, 22, 24]
    uses: ./.github/workflows/node-test.yml
    with:
      node-version: ${{ matrix.version }}
```

## Ограничения

- **Глубина вызовов**: Максимум 4 уровня (цепочка `caller -> r1 -> r2 -> r3 -> r4`).
- **Локальные файлы**: Нельзя вызывать Reusable Workflow, созданный динамически в том же запуске.
- **Синтаксис**: Ключ `uses` на уровне задачи несовместим с ключами `steps` или `container` в той же задаче.
