# GitHub Actions: Синтаксис рабочего процесса (Workflow)

Файлы рабочих процессов (workflows) в GitHub Actions описываются с использованием языка разметки YAML. Они обладают строго определенной структурой, включающей ключи верхнего уровня, контексты и выражения для управления логикой автоматизации.

## Определения

- **Workflow-файл**: Конфигурационный файл в формате YAML (с расширением `.yml` или `.yaml`), расположенный в директории `.github/workflows/` репозитория.
- **Синтаксис выражений (`${{...}}`)**: Механизм, позволяющий динамически подставлять значения переменных, обращаться к контекстной информации и выполнять условную логику.
- **Интерполяция**: Процесс замены плейсхолдеров в строках на их фактические значения во время выполнения.
- **Командные файлы (Workflow Commands)**: Специальный синтаксис строк (через `echo`), позволяющий шагам взаимодействовать с раннером (установка переменных, маскирование секретов, создание выводов).

## Основные концепции

### Ключи верхнего уровня

Данные ключи определяют общую структуру и поведение рабочего процесса:

- **`name`**: Имя рабочего процесса, отображаемое в UI GitHub.
- **`on`**: Определяет триггеры запуска. Поддерживает списки событий, фильтры веток (`branches`), путей (`paths`) и тегов (`tags`).
- **`permissions`**: Настройка прав доступа для `GITHUB_TOKEN` на уровне всего воркфлоу или конкретной задачи.
- **`env`**: Переменные окружения, доступные всем задачам.
- **`defaults`**: Настройки по умолчанию для всех задач (например, `shell: bash` или `working-directory: ./src`).
- **`concurrency`**: Управляет очередями выполнения, позволяя отменять старые запуски при поступлении новых коммитов.

### Иерархия переменных окружения

Переменные могут быть определены на трех уровнях (приоритет от нижнего к верхнему):
1. **Workflow уровень**: Ключ `env` на верхнем уровне файла. Доступны всем задачам.
2. **Job уровень**: Ключ `env` внутри конкретной задачи. Доступны всем шагам этой задачи.
3. **Step уровень**: Ключ `env` внутри конкретного шага.

**Различия в синтаксисе обращения:**
- **`${{ env.VAR_NAME }}`**: Контекст GitHub Actions. Значение подставляется *до* выполнения скрипта (на этапе парсинга YAML). Используется в ключах `if`, `with` или для передачи в `run`.
- **`$VAR_NAME`** или **`${VAR_NAME}`**: Системная переменная окружения в shell. Используется внутри блока `run`.

**Динамическая установка переменных ($GITHUB_ENV):**
Для установки или обновления переменных во время выполнения шага используется запись в специальный файл среды. Переменная станет доступна во всех *последующих* шагах текущей задачи:
```bash
run: echo "VERSION=1.0.0" >> $GITHUB_ENV
```

### Контексты

Контексты — это объекты, содержащие данные о выполнении. К ним можно обращаться в любой части YAML, где поддерживаются выражения.

- **`github`**: Метаданные о событии.
  - `github.ref`: Ссылка на ветку или тег (например, `refs/heads/main`).
  - `github.event_name`: Тип события (push, pull_request, workflow_dispatch).
  - `github.actor`: Имя пользователя, инициировавшего запуск.
- **`env`**: Значения переменных окружения, определенных в YAML.
- **`vars`**: Переменные конфигурации репозитория.
- **`secrets`**: Зашифрованные данные.
- **`runner`**: Информация о среде выполнения.
  - `runner.os`: Операционная система (Linux, Windows, macOS).
  - `runner.name`: Имя раннера.
- **`steps`**: Содержит `outputs` и статус выполнения (`outcome`, `conclusion`) каждого шага в текущей задаче.

### Функции и выражения

Выражения `${{ <expression> }}` позволяют использовать программную логику для управления выполнением.

- **Условная логика (`if`)**:
  Может применяться на уровне задачи (`job`) или шага (`step`). Если условие ложно, элемент пропускается (Skipped).
  - Пример для задачи: `if: github.ref == 'refs/heads/main'` (запуск только в главной ветке).
  - Пример для шага: `if: runner.os == 'Windows'` (выполнение только на Windows).
- **Логические функции**: `success()`, `failure()`, `always()`, `cancelled()`. Позволяют обрабатывать результаты выполнения предыдущих шагов.
- **Строковые и системные функции**:
  - `contains(search, item)`: Проверка наличия подстроки (например, в сообщении коммита).
  - `toJSON(value)`: Преобразование объекта в строку JSON (удобно для отладки контекстов).
  - `fromJSON(value)`: Парсинг JSON-строки (необходимо для работы с динамическими матрицами).
- **Операторы**: Сравнение (`==`, `!=`, `>`, `<`), логические (`&&`, `||`, `!`).

### Взаимодействие между шагами и задачами

1. **Выходы шага ($GITHUB_OUTPUT)**:
   Используются для передачи строковых данных между шагами одной задачи.
   ```yaml
   - id: generate
     run: echo "val=hello" >> $GITHUB_OUTPUT
   - run: echo "${{ steps.generate.outputs.val }}"
   ```

2. **Выходы задачи (Job Outputs)**:
   Позволяют передавать данные между зависимыми задачами через контекст `needs`.
   ```yaml
   jobs:
     job1:
       outputs:
         build_id: ${{ steps.step1.outputs.id }}
       steps:
         - id: step1
           run: echo "id=123" >> $GITHUB_OUTPUT
     job2:
       needs: job1
       run: echo "Using ID: ${{ needs.job1.outputs.build_id }}"
   ```

3. **Артефакты (Artifacts)**:
   Механизм для передачи файлов и больших объемов данных между задачами, так как задачи выполняются на изолированных виртуальных машинах.
   - **`actions/upload-artifact`**: Загружает файлы в хранилище GitHub, делая их доступными для других задач и пользователя.
   - **`actions/download-artifact`**: Скачивает ранее загруженные артефакты в текущую задачу.
   - **Лимиты**: По умолчанию артефакты хранятся 90 дней (см. [Среды выполнения и ограничения](./Environment_Limitations.md)).

4. **Файл путей ($GITHUB_PATH)**:
   Позволяет добавить директорию в системную переменную `PATH` для всех последующих шагов текущей задачи:
   ```bash
   run: echo "$HOME/.local/bin" >> $GITHUB_PATH
   ```

## Практические сценарии

### Динамический воркфлоу с условной логикой и фильтрами

Пример демонстрирует использование фильтров путей, условий на уровне шагов и динамических переменных.

```yaml
name: Advanced Syntax Demo

on:
  push:
    branches: [ main ]
    paths: [ 'src/**', 'package.json' ]
  workflow_dispatch:
    inputs:
      logLevel:
        description: 'Log level'
        required: true
        default: 'info'
        type: choice
        options: [info, warning, debug]

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    env:
      BUILD_MODE: ${{ github.event_name == 'workflow_dispatch' && 'manual' || 'auto' }}
    
    outputs:
      artifact_id: ${{ steps.upload.outputs.id }}

    steps:
      - uses: actions/checkout@v7
      
      - name: Dynamic Env Setup
        run: |
          echo "TIMESTAMP=$(date +'%Y-%m-%d_%H-%M')" >> $GITHUB_ENV
          echo "::add-mask::${{ secrets.INTERNAL_ID }}"
          
      - name: Conditional Build
        if: github.event.inputs.logLevel != 'debug'
        run: npm run build --mode=${{ env.BUILD_MODE }}
        
      - name: Generate Output
        id: meta
        run: echo "sha_short=$(git rev-parse --short HEAD)" >> $GITHUB_OUTPUT

      - name: Summary
        if: always()
        run: |
          echo "Build finished at ${{ env.TIMESTAMP }}"
          echo "Git SHA: ${{ steps.meta.outputs.sha_short }}"
```
