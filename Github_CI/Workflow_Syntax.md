# GitHub Actions: Синтаксис рабочего процесса (Workflow)

Файлы рабочих процессов (workflows) в GitHub Actions описываются с использованием языка разметки YAML (Yet Another Markup Language). Они обладают строго определенной структурой, включающей ключи верхнего уровня, контексты и выражения для управления логикой автоматизации.

## Определения

- **Workflow-файл (Рабочий процесс)**: Конфигурационный файл в формате YAML (с расширением `.yml` или `.yaml`), расположенный в директории `.github/workflows/` репозитория.
- **Синтаксис выражений (`${{...}}`)**: Специальный механизм, позволяющий динамически подставлять значения переменных, обращаться к контекстной информации и выполнять условную логику непосредственно в YAML-файле.

## Основные концепции

### Ключи верхнего уровня

Данные ключи определяют общую структуру и поведение рабочего процесса:

- **`name`** (опционально): Имя рабочего процесса, отображаемое в интерфейсе (User Interface — UI) GitHub.
- **`on`** (обязательно): Определяет триггеры — события, которые инициируют запуск процесса. Подробнее в разделе **[События, Задачи и Шаги](./Events_Jobs_Steps.md)**.
- **`jobs`** (обязательно): Группирует одну или несколько задач, которые будут выполняться.
- **`env`** (опционально): Определяет глобальные переменные окружения, доступные для всех задач и шагов данного процесса.
- **`permissions`** (опционально): Настраивает права доступа для временного токена безопасности `GITHUB_TOKEN`. Согласно принципу минимальных привилегий, рекомендуется явно указывать только необходимые права (например, `contents: read`).
- **`concurrency`** (опционально): Управляет конкурентностью, позволяя ограничивать одновременное выполнение нескольких экземпляров одного процесса. Это критично для оптимизации ресурсов, например, при автоматической отмене устаревших сборок в Pull Request (запросах на слияние). Подробнее в разделе **[Оптимизация воркфлоу](./Optimization.md)**.

### Контексты

Контексты представляют собой наборы данных (объекты), доступные в процессе выполнения. Обращение к ним осуществляется через синтаксис выражений.

- **`github`**: Содержит метаданные о текущем запуске (ветка, хеш коммита, инициатор события).
- **`secrets`**: Предоставляет доступ к зашифрованным секретам. Описано в **[Управлении секретами](./secrets_management.md)**.
- **`env`**: Содержит переменные окружения, определенные в файле или в настройках окружения.
- **`steps`**: Позволяет получать выходные данные (`outputs`) от предыдущих шагов в рамках одной задачи.
- **`matrix`**: Содержит значения текущей итерации при использовании матричных стратегий. Описано в **[Матричных сборках](./Matrix_Builds.md)**.
- **`inputs`**: Входные параметры, передаваемые в **[Переиспользуемые воркфлоу](./Reusable_Workflows.md)**.

## Практические сценарии

### Комплексная демонстрация синтаксиса

Пример файла, объединяющего основные элементы управления:

```yaml
name: Syntax Overview

on:
  push:
    branches: [ main ]
  workflow_dispatch: # Позволяет запускать вручную из UI

permissions:
  contents: read

concurrency:
  group: syntax-check-${{ github.ref }}
  cancel-in-progress: true

env:
  APPLICATION_TARGET: "Production"

jobs:
  validate-and-report:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
      
      - name: Global environment access
        run: echo "Target environment is ${{ env.APPLICATION_TARGET }}"

      - name: Conditional execution based on context
        if: github.event_name == 'push'
        run: echo "This step was triggered by a code push."
        
      - name: Generating step output
        id: producer
        run: echo "status=success" >> $GITHUB_OUTPUT

      - name: Consuming step output
        run: echo "Previous status was ${{ steps.producer.outputs.status }}"
```
