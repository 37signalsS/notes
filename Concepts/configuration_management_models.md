# Обзор классических моделей конфигурации

Управление конфигурацией оперирует представлением о «желаемом состоянии» систем и механизме его достижения. Классические модели описывают, как формулировать желаемое состояние, как его распространять и как обеспечить устойчивость к дрейфу. Понимание этих моделей позволяет выбирать инструменты и выстраивать процессы, соответствующие требованиям надежности, скорости изменений и контроля.

## Императивная и декларативная парадигмы

-   **Императивная**: Описывает последовательность шагов, которые нужно выполнить.
-   **Декларативная**: Фиксирует целевое состояние; механизм сам выбирает, что изменить.

**Пример императивного подхода:**
```bash
apt-get update
apt-get install -y nginx
sed -i 's/listen 80/listen 8080/' /etc/nginx/sites-enabled/default
systemctl enable --now nginx
```

**Пример декларативного описания цели:**
```yaml
packages:
  - name: nginx
    state: present
services:
  - name: nginx
    enabled: true
    state: started
files:
  - path: /etc/nginx/sites-enabled/default
    state: template
    mode: "0644"
    variables:
      listen_port: 8080
```
Сильные стороны декларативного подхода — идемпотентность и предсказуемость; императивный ближе к «операционным рецептам» и удобен для одноразовых процедур и отладки.

## Push и Pull модели распространения

| Критерий | Push | Pull |
| :--- | :--- | :--- |
| **Инициатор** | Центральный контроллер отправляет изменения | Агенты на узлах периодически запрашивают состояние |
| **Масштабируемость** | Требует тщательного планирования фан-аута | Горизонтально масштабируется за счет агентов |
| **Устойчивость** | Зависит от доступности контроллера | Узлы самовосстанавливаются при временных сбоях сети |
| **Безопасность** | Централизованные исходящие соединения | Требуются входящие соединения/PKI для доверия |
| **Время реакции** | Мгновенная доставка команд | С задержкой до следующего цикла опроса |

На практике часто используется гибрид: критичные изменения доставляются push, периодическая конвергенция — pull.

## Изменяемая и неизменяемая инфраструктура

-   **Изменяемая (mutable)**: Конфигурация узла меняется «на месте». Плюсы — гибкость, минусы — риск дрейфа, сложность отката.
-   **Неизменяемая (immutable)**: Создается новый образ или инстанс с нужным состоянием, старый заменяется. Плюсы — воспроизводимость, быстрый rollback; минусы — необходимость зрелого пайплайна образов и оркестрации.

Связанная метафора: «домашние питомцы» (ручная забота об уникальных серверах) против «стада» (взаимозаменяемые экземпляры).

## Конвергенция и идемпотентность

-   **Конвергенция**: Периодическое приведение фактического состояния к желаемому до совпадения (или до заданной погрешности).
-   **Идемпотентность**: Повторное применение не меняет результат, если система уже соответствует цели.

Шаблон идемпотентного действия:
```python
if not present("nginx"):
  install("nginx")
ensure_service("nginx", enabled=True, running=True)
render_template("/etc/nginx/default", data)  # изменяет только при разнице
```

## Дрейф конфигурации и его контроль

Дрейф — расхождение между задекларированным и фактическим состоянием из‑за ручных правок, неполных развёртываний или различий окружений. Контроль включает:

-   периодические проверки и отчеты соответствия;
-   запрет «ручных» изменений на продакшене;
-   подписанные артефакты и контроль целостности;
-   уведомления и автоматическое восстановление при обнаружении отклонений.

## Слои описания и источники данных

Классические модели предполагают композицию слоев:

-   глобальные политики (безопасность, базовые пакеты);
-   окружение/регион;
-   роль/профиль (web, db);
-   специфично для узла (минимум или вовсе отсутствует).

Данные параметризуются через инвентари, переменные окружения, шаблоны; приоритеты слоев должны быть детерминированными и прозрачно документированными.

## Выбор комбинации моделей

-   Быстрые one‑shot операции: императив + push.
-   Регулярная поддержка состояния: декларатив + pull + конвергенция.
-   Массовые обновления с требованиями к воспроизводимости: декларатив + immutable + оркестрация смены экземпляров.
