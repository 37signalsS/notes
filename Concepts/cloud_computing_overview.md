# Облачные вычисления (Cloud Computing) — Обзор

Облачные вычисления — это модель предоставления повсеместного и удобного сетевого доступа к общему пулу настраиваемых вычислительных ресурсов (например, сетей, серверов, хранилищ, приложений и сервисов), которые могут быть оперативно предоставлены и освобождены с минимальными эксплуатационными затратами или обращениями к провайдеру.

## Определения

Согласно стандарту **NIST (National Institute of Standards and Technology)**, облако характеризуется пятью ключевыми признаками:

1.  **Самообслуживание по требованию (On-demand self-service):** потребитель может самостоятельно выделять мощности (процессор, хранилище) через программные интерфейсы (API) или веб-панель управления без участия персонала провайдера.
2.  **Широкий доступ по сети (Broad network access):** ресурсы доступны через стандартные механизмы и протоколы с различных платформ (ПК, смартфоны, планшеты, IoT-устройства).
3.  **Объединение ресурсов (Resource pooling):** физические и виртуальные ресурсы провайдера динамически распределяются между множеством клиентов (**мультитенантность**). Клиент обычно не знает точного местоположения ресурсов, но может управлять ими на уровне регионов или зон доступности.
4.  **Мгновенная эластичность (Rapid elasticity):** возможность практически мгновенно наращивать мощности под нагрузкой (scale-up/scale-out) и автоматически освобождать их при её снижении, что позволяет избегать избыточного резервирования.
5.  **Измеряемость сервиса (Measured service):** системы управления облаком автоматически ведут учёт потреблённых ресурсов (процессорное время, объём данных, количество запросов), обеспечивая прозрачность биллинга по модели **Pay-as-you-go** (оплата за фактическое потребление).

## Базовые концепции

### Архитектура облачной платформы
Современная облачная платформа состоит из двух основных уровней:
*   **Control Plane:** уровень управления, отвечающий за логику работы облака, API, биллинг, аутентификацию и оркестрацию ресурсов.
*   **Data Plane:** уровень исполнения, где непосредственно работают рабочие нагрузки клиентов (ВМ, контейнеры) и передаётся пользовательский трафик.

### Модели обслуживания (Service Models)
Модели различаются уровнем абстракции и зоной ответственности между провайдером и клиентом.

| Модель | Название | Что предоставляет провайдер | Типовые ресурсы |
| :--- | :--- | :--- | :--- |
| **IaaS** | Infrastructure as a Service | «Сырые» вычислительные мощности | ВМ (EC2/Compute Cloud), сети, диски |
| **CaaS** | Container as a Service | Среда для запуска контейнеров | Managed Kubernetes (EKS/GKE/MKS) |
| **PaaS** | Platform as a Service | Готовая среда исполнения и ПО | Managed БД, очереди сообщений, рантаймы |
| **FaaS** | Function as a Service | Выполнение кода по событию (Serverless) | AWS Lambda, Cloud Functions |
| **SaaS** | Software as a Service | Готовое ПО для конечных пользователей | Google Workspace, Microsoft 365, Jira |

*Специализированные модели:* **DBaaS** (Database as a Service), **GPUaaS** (аренда GPU для AI), **SECaaS** (Security as a Service).

Подробнее о разделении ответственности: [Модель разделяемой ответственности](./shared_responsibility_model.md).

### Модели развёртывания (Deployment Models)
*   **Публичное облако (Public Cloud):** инфраструктура принадлежит провайдеру и доступна любому клиенту (AWS, Azure, Yandex Cloud).
*   **Частное облако (Private Cloud):** выделенная инфраструктура, используемая исключительно одной организацией. Может размещаться как on-premise, так и у провайдера (Bare Metal).
*   **Гибридное облако (Hybrid Cloud):** объединение публичного и частного облаков, позволяющее перемещать данные и приложения между ними.
*   **Мультиоблако (Multi-cloud):** стратегия использования нескольких независимых публичных провайдеров для повышения отказоустойчивости и избегания **vendor lock-in**.
*   **Суверенное облако (Sovereign Cloud):** облако, работающее в строгом соответствии с национальным законодательством в области защиты данных (например, ФЗ-152 в РФ или Gaia-X в ЕС).

### Современные тренды (2025-2026)
*   **Cloud Native:** проектирование приложений специально для облачной среды с использованием микросервисов, контейнеров и принципов **Twelve-Factor App**.
*   **FinOps (Cloud Economics):** культура и практика управления облачными затратами через тесную интеграцию финансовых, инженерных и бизнес-команд.
*   **GreenOps (Sustainable IT):** оптимизация использования облака с целью снижения углеродного следа и повышения энергоэффективности дата-центров.
*   **Edge Computing:** обработка данных на периферии сети, максимально близко к источнику, для минимизации задержек. Подробнее: [Обзор Edge Computing](./edge_computing_overview.md).
*   **Confidential Computing:** защита данных в процессе обработки с помощью аппаратных сред исполнения (TEE) и шифрования в памяти.
*   **Репатриация облаков (Cloud Repatriation):** процесс частичного возврата нагрузок из публичных облаков на собственные мощности (on-premise) или в частные облака по соображениям экономики или безопасности.

## Практические сценарии

### Трансформация затрат (CAPEX vs OPEX)
Переход в облако позволяет сменить модель капитальных инвестиций в железо (**CAPEX**) на модель операционных расходов (**OPEX**). Это снижает порог входа для новых проектов и позволяет платить только за то, что реально используется.

### Ускорение Time-to-Market
Использование IaC (Infrastructure as Code) и готовых сервисов (PaaS) сокращает время развёртывания окружений с недель до минут.
*   *Пример:* Поднятие кластера PostgreSQL с репликацией и бэкапами одной командой Terraform вместо ручной настройки ОС и СУБД.

### Примеры использования
*   **Масштабируемые Web-приложения:** автоматическое увеличение числа инстансов при росте трафика.
*   **AI/ML инференс:** использование специализированных чипов (TPU/NPU) в облаке для обучения и работы нейросетей.
*   **DRP (Disaster Recovery Plan):** использование облака как резервной площадки для быстрого восстановления бизнеса при аварии в основном дата-центре.

## Дополнительная информация

### История развития
*   **1960-е:** Джон Маккарти выдвигает идею вычислений как «коммунальной услуги» (utility computing).
*   **2006:** Запуск Amazon S3 и EC2 — рождение современного IaaS.
*   **2014:** Релиз Kubernetes и AWS Lambda, запуск тренда на Cloud Native и Serverless.
*   **2023-2024:** Массовое внедрение AI-сервисов (LLM as a Service) и фокус на аппаратной безопасности.
*   **2026:** Расцвет децентрализованных облаков и систем автоматизированного FinOps на базе ИИ.

### Плюсы и риски
*   **Преимущества:** глобальная доступность, высокая скорость инноваций, соответствие стандартам безопасности (SOC2, PCI DSS).
*   **Риски:** сложность прогнозирования затрат при неконтролируемом росте, зависимость от стабильности интернета, риск блокировок со стороны глобальных провайдеров.
