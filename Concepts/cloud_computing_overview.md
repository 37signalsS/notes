# Облачные вычисления (Cloud Computing) — Обзор

Данный файл является SSoT (Single Source of Truth) для общих понятий облачных технологий: определений, моделей обслуживания и развёртывания, а также истории развития.

## Определения и стандарты (NIST)

Согласно определению NIST (National Institute of Standards and Technology), облачные вычисления — это модель обеспечения удобного сетевого доступа по требованию к общему пулу настраиваемых вычислительных ресурсов.

Облако характеризуется пятью ключевыми признаками:

1. **Самообслуживание по требованию (On-demand self-service):** потребитель может самостоятельно выделять ресурсы (процессорное время, хранилище) через панель управления или API без взаимодействия с персоналом провайдера.
2. **Широкий доступ по сети (Broad network access):** ресурсы доступны из любой точки мира через стандартные протоколы и различные устройства.
3. **Объединение ресурсов (Resource pooling / Мультитенантность):** физическое железо провайдера динамически распределяется между множеством клиентов. Клиенты изолированы друг от друга и не знают о соседстве.
4. **Мгновенная эластичность (Rapid elasticity):** возможность быстро наращивать мощности под нагрузкой и автоматически сжимать их при её снижении.
5. **Измеряемость сервиса (Measured service):** оплата за фактическое потребление (Pay-as-you-go) — секунды процессора, гигабайты трафика, количество запросов.

## История развития

- **1961 год:** Джон Макарти (MIT) предсказал, что вычисления станут коммунальной услугой (как вода или электричество).
- **1960-е:** Появление мейнфреймов и технологии **Time-sharing** (разделение времени работы одной машины между пользователями) — прообраз мультитенантности.
- **1970-е:** IBM внедряет виртуальные машины.
- **1999 год:** Salesforce запускает доставку бизнес-ПО через браузер (прото-SaaS).
- **2006 год:** Amazon запускает **S3** (хранилище) и **EC2** (виртуалки). Точка отсчёта современного публичного облака.
- **2008 год:** Выход на рынок Google и Microsoft.
- **2013-2014 годы:** Массовое внедрение Docker, открытие Kubernetes (Google), запуск AWS Lambda (начало эпохи Serverless).

## Модели обслуживания (Service Models)

Модели различаются уровнем ответственности, которую берет на себя провайдер.

| Модель | Название | Что дает провайдер | Ответственность клиента | Примеры |
| :--- | :--- | :--- | :--- | :--- |
| **IaaS** | Infrastructure as a Service | Железо, сеть, виртуализация | ОС, рантаймы, код, данные | AWS EC2, Yandex Compute |
| **PaaS** | Platform as a Service | ОС, рантаймы, БД, очереди | Код приложения, настройки | Managed БД, Managed K8s |
| **FaaS** | Function as a Service (Serverless) | Полный стек исполнения функций | Только код функции (бизнес-логика) | AWS Lambda, Cloud Functions |
| **SaaS** | Software as a Service | Готовое приложение | Только данные пользователя | Gmail, Slack, Salesforce |

Подробнее о разделении зон ответственности: [Модель разделяемой ответственности](./shared_responsibility_model.md).

## Модели развёртывания (Deployment Models)

- **Публичное облако (Public Cloud):** общая инфраструктура провайдера, доступная всем (AWS, Yandex Cloud). Максимально быстрый старт.
- **Частное облако (Private Cloud):** облачная инфраструктура внутри одной организации (на базе OpenStack, VMware). Используется для чувствительных данных.
- **Гибридное облако (Hybrid Cloud):** связка публичного и частного облака. Стабильные нагрузки — в приватном, пиковые и эксперименты — в публичном.
- **Мультиоблако (Multi-cloud):** использование нескольких публичных провайдеров одновременно для отказоустойчивости и избегания vendor lock-in.

## Преимущества и недостатки

### Плюсы
- **CAPEX → OPEX:** отсутствие капитальных затрат на покупку железа, переход к операционным расходам по мере использования.
- **Скорость (Time-to-market):** развертывание сервера за минуты.
- **Эластичность:** автоматическая реакция на скачки трафика.
- **Глобальность:** запуск в любой точке мира в несколько кликов.

### Минусы
- **Vendor Lock-in:** глубокая привязка к проприетарным API провайдера затрудняет миграцию.
- **Стоимость при масштабе:** при стабильно высокой нагрузке 24/7 облако может быть дороже собственного железа.
- **Стоимость трафика:** загрузка в облако обычно бесплатна, а выгрузка (Egress) — дорога.

## Когда выбирать облако?
- **Облако:** стартапы, новые продукты, неравномерная нагрузка, разработка и тесты.
- **Своё железо:** стабильная высокая нагрузка, жёсткие требования по задержкам, юридические ограничения (хранение данных).
