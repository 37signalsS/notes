# Облачные вычисления (Cloud Computing) — Обзор

Облачные вычисления — это модель предоставления повсеместного и удобного сетевого доступа к общему пулу настраиваемых вычислительных ресурсов (например, сетей, серверов, хранилищ, приложений и сервисов), которые могут быть оперативно предоставлены и освобождены с минимальными эксплуатационными затратами или обращениями к провайдеру.

## Определения

Согласно стандарту **NIST (National Institute of Standards and Technology)**, облако характеризуется пятью ключевыми признаками:

1.  **Самообслуживание по требованию (On-demand self-service):** потребитель может самостоятельно выделять мощности (процессор, хранилище) через API или панель управления.
2.  **Широкий доступ по сети (Broad network access):** ресурсы доступны через стандартные протоколы с любых устройств (ПК, смартфоны).
3.  **Объединение ресурсов (Resource pooling):** физические ресурсы провайдера динамически распределяются между множеством клиентов (**мультитенантность**).
4.  **Мгновенная эластичность (Rapid elasticity):** возможность быстро наращивать мощности под нагрузкой и автоматически освобождать их при её снижении.
5.  **Измеряемость сервиса (Measured service):** оплата за фактическое потребление (**Pay-as-you-go**).

## Базовые концепции

### Модели обслуживания (Service Models)

Модели различаются уровнем ответственности, которую берет на себя провайдер.

| Модель | Название | Что предоставляет провайдер | Ответственность клиента |
| :--- | :--- | :--- | :--- |
| **IaaS** | Infrastructure as a Service | Виртуальное железо, сеть, диски | ОС, рантаймы, код, данные |
| **PaaS** | Platform as a Service | ОС, рантаймы, Managed БД/K8s | Код приложения, настройки |
| **FaaS** | Function as a Service | Среда исполнения функций (Serverless) | Только код бизнес-логики |
| **SaaS** | Software as a Service | Готовое приложение | Только данные и настройки доступа |

Подробнее о разделении ответственности: [Модель разделяемой ответственности](./shared_responsibility_model.md).

### Модели развёртывания (Deployment Models)

*   **Публичное облако (Public Cloud):** инфраструктура доступна широкой публике (AWS, Yandex Cloud).
*   **Частное облако (Private Cloud):** выделенная инфраструктура для одной организации (OpenStack, VMware).
*   **Гибридное облако (Hybrid Cloud):** сочетание публичного и частного облаков для балансировки нагрузки и безопасности.
*   **Мультиоблако (Multi-cloud):** одновременное использование нескольких провайдеров для избегания зависимости от одного поставщика (vendor lock-in).
*   **Общественное облако (Community Cloud):** инфраструктура, разделяемая сообществом организаций со схожими задачами (например, государственные органы или научные институты).

### Современные тренды

*   **Cloud Native:** подход к разработке приложений, изначально спроектированных для жизни в облаке (микросервисы, контейнеризация, динамическое управление).
*   **FinOps:** культура управления облачными расходами, направленная на оптимизацию затрат при сохранении производительности.
*   **Edge Computing:** перенос вычислений ближе к источнику данных для снижения задержек. Подробнее: [Обзор Edge Computing](./edge_computing_overview.md).

## Практические сценарии

### Переход от CAPEX к OPEX
Облако позволяет отказаться от капитальных затрат (**CAPEX**) на покупку серверов в пользу операционных расходов (**OPEX**). Это критично для стартапов и проектов с неопределенной нагрузкой.

### Ускорение выхода на рынок (Time-to-market)
Развертывание сложной инфраструктуры (БД, кластеры, балансировщики) занимает минуты через терраформ-скрипты или панель управления, вместо недель на закупку и монтаж железа.

### Примеры использования
*   **Разработка и тестирование:** быстрое создание временных окружений.
*   **Big Data и ML:** аренда мощных GPU на несколько часов для обучения моделей.
*   **Сезонные нагрузки:** автоматическое масштабирование интернет-магазина в период распродаж.

## Дополнительная информация

### История развития
*   **1960-е:** Концепция "вычислений как коммунальной услуги" (Джон Маккарти).
*   **2006:** Запуск Amazon AWS (S3, EC2) — начало эпохи современного публичного облака.
*   **2014:** Анонс Kubernetes и AWS Lambda (популяризация Cloud Native и Serverless).
*   **2020-е:** Фокус на суверенных облаках (Gaia-X) и специализированном "железе" для AI.

### Плюсы и минусы
*   **Преимущества:** глобальный охват, высокая доступность (SLA), отсутствие затрат на утилизацию старого железа.
*   **Риски:** зависимость от канала связи, скрытые расходы на выгрузку трафика (egress), сложности с комплаенсом (ФЗ-152 в РФ).
