# Граничные вычисления (Edge Computing) — Обзор

## Определения

**Граничные вычисления (Edge Computing)** — это распределенная вычислительная модель, в которой обработка данных и выполнение логики приложения происходят максимально близко к источнику данных или конечному пользователю. 

В отличие от традиционной облачной модели, где вычисления сосредоточены в централизованных дата-центрах, Edge Computing переносит их на «границу» сети: на оборудование пользователя, **IoT (Internet of Things)**-шлюзы или инфраструктуру **CDN (Content Delivery Network)**.

**Цели использования:**
*   **Минимизация задержек (Latency):** ответ формируется в той же точке присутствия (PoP), где находится пользователь, исключая RTT до облачного региона.
*   **Экономия трафика:** предварительная фильтрация данных (особенно в IoT) снижает нагрузку на магистральные каналы и затраты на Egress-трафик.
*   **Автономность:** возможность работы при временном отсутствии связи с центральным облаком (Local Survivability).
*   **Комплаенс:** обработка персональных данных внутри конкретной юрисдикции без их передачи в глобальные облака.

## Базовые концепции

### Ключевые свойства граничных сред

*   **Низкая задержка:** ответ формируется за 1–10 мс.
*   **Эфемерность:** воркеры запускаются по запросу и уничтожаются сразу после выполнения (Serverless 2.0).
*   **Изоляция на уровне песочницы:** использование технологий с мгновенным стартом (WASM) вместо тяжелых контейнеров.

| Характеристика | Облако (Центр) | Edge (Граница) |
| :--- | :--- | :--- |
| **Задержка** | 50–200 мс | **1–10 мс** |
| **Модель вычислений** | ВМ, контейнеры, Bare Metal | **Функции, WASM-компоненты** |
| **Оркестрация** | Kubernetes, OpenStack | **Nomad, K3s, SpinKube** |
| **Работа с состоянием**| SQL/NoSQL, Очереди | **KV-хранилища, Durable Objects** |

### Туманные вычисления (Fog Computing)

Концепции Edge и Fog часто пересекаются, но имеют иерархическое различие:
*   **Edge:** фокусируется на конечных устройствах (датчики, смартфоны) и локальных шлюзах.
*   **Fog:** промежуточный уровень (микро-ЦОД, серверы в филиалах), который объединяет ресурсы нескольких Edge-узлов перед отправкой агрегированных данных в облако.

### Технологический стек 2026

*   **WebAssembly (WASM):** промышленный стандарт для Edge. WASM-модули запускаются за микросекунды (без "холодного старта") и обеспечивают строгую изоляцию.
*   **WASI 0.3 (Preview 3):** стандарт 2026 года с нативной поддержкой асинхронного I/O, что критично для высокопроизводительных граничных сервисов.
*   **AI Inference на Edge:** использование рантаймов вроде **WasmEdge** для запуска квантованных LLM (Llama 3/4) напрямую на границе с использованием аппаратных ускорителей (NPU/GPU).

## Практические сценарии

### Типичные задачи

*   **Динамическая маршрутизация:** выбор бэкенда на основе заголовков, весов или геолокации.
*   **A/B тестирование и Feature Toggles:** применение флагов на границе для исключения задержек при рендеринге.
*   **Безопасность (Edge WAF):** фильтрация ботов, проверка JWT-подписей и защита от L7 DDoS до попадания трафика в инфраструктуру.
*   **Индустриальный IoT:** детекция аномалий на конвейере в реальном времени с использованием локальных ML-моделей.

### Пример Edge-обработчика (WASM/JavaScript)

Современные платформы (Cloudflare Workers, Fastly Compute, Akamai Edge) используют схожий API для обработки событий:

```javascript
// Пример на базе стандарта Service Workers / Fetch API
async function handleRequest(request) {
  const { country, city } = request.cf || {}; // Геоданные от провайдера
  
  // 1. Локальная проверка авторизации (без запроса к БД)
  const authHeader = request.headers.get('Authorization');
  if (!isValidJWT(authHeader)) {
    return new Response('Unauthorized', { status: 401 });
  }

  // 2. Персонализация на границе
  if (country === 'RU') {
    return fetch('https://origin-ru.example.com/api', request);
  }

  // 3. Ответ из глобального кэша Edge
  const cache = caches.default;
  let response = await cache.match(request);
  
  return response || fetch(request);
}
```

## Дополнительная информация

### Безопасность на границе

*   **Zero Trust Edge:** каждый узел считается недоверенным. Безопасность строится на **mTLS** и аттестации оборудования.
*   **Capability-based Security:** в WASM-средах приложение не имеет доступа к системным ресурсам (файлам, сети) по умолчанию — только через явно предоставленные «способности» (capabilities).
*   **Confidential Computing:** защита данных в памяти Edge-узла с использованием аппаратных анклавов (Intel SGX, AMD SEV).

### Наблюдаемость (Observability)

*   **OTLP over MQTT/HTTP:** устройства отправляют телеметрию в ближайший коллектор (например, Grafana Alloy на Edge), который агрегирует данные и передает их в центральное хранилище.
*   **Edge Tracing:** использование облегченных библиотек трассировки для сопоставления пути запроса от браузера через Edge-узел до глубоких слоев бэкенда.
