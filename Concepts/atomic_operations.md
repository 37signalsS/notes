# Атомарные операции

## Определения → Базовые концепции → Практические сценарии → Дополнительная информация

## Определения

**Атомарная операция (Atomic Operation)** — операция, которая выполняется как единое целое: она либо завершается полностью и успешно, либо не выполняется вовсе. Промежуточные состояния операции не видны сторонним наблюдателям.

**Атомарность (Atomicity)** — свойство системы, гарантирующее, что никакое стороннее вмешательство или сбой не оставят систему в полуизменённом состоянии.

## Базовые концепции

### Уровни атомарности

1. **Аппаратный уровень:** процессорные инструкции, которые выполняются за один цикл или защищены блокировкой шины (например, `Compare-and-Swap` — CAS).
2. **Уровень ОС:** системные вызовы, гарантирующие неделимость действия. Например, создание файла через `open` с флагом `O_EXCL`.
3. **Уровень файловой системы:** переименование файла (`mv`) в пределах одного раздела диска.
4. **Уровень баз данных:** транзакции (буква **A** в ACID).
5. **Уровень распределённых систем:** распределённые транзакции и протоколы консенсуса (Raft, Paxos).

### Почему атомарность важна?

Без атомарности возникают **состояния гонки (Race Conditions)**. 
*Пример:* Два процесса одновременно читают значение `X=10`, прибавляют `1` и записывают `11`. Ожидалось `12`, но из-за неатомарности цикла «чтение-изменение-запись» одно обновление потерялось.

## Практические сценарии

### Сценарий 1: Атомарное обновление конфигурации
Чтобы избежать ситуации, когда приложение читает наполовину записанный файл конфигурации:
1. Записать новый конфиг в новый временный файл на том же диске.
2. Использовать системный вызов `rename()` (команда `mv`) для замены старого файла новым.
Операция `rename` на Linux атомарна — приложение либо увидит старый файл целиком, либо новый целиком.

### Сценарий 2: Блокировки (Locks) через файловую систему
Атомарное создание директории или файла может служить примитивом блокировки:
```bash
if mkdir /var/lock/mylock; then
  echo "Lock acquired"
else
  echo "Locked by another process"
fi
```
Операция `mkdir` атомарна на уровне ядра: если два процесса вызовут её одновременно, только один получит успех.

### Сценарий 3: Атомарные операции в базах данных (Redis)
В Redis команды `INCR` или `SETNX` атомарны. Это позволяет безопасно реализовывать счетчики или распределенные локи без сложной синхронизации на стороне приложения.

## Дополнительная информация

### Ограничения атомарности файловых систем
- Команда `cp` **не атомарна**. Процесс может начать читать файл, пока `cp` ещё пишет в него.
- `mv` между разными разделами (mount points) **не атомарна**, так как превращается в `cp` + `rm`.

### Атомарность в программировании
Языки предоставляют специальные типы (например, `std::atomic` в C++, `AtomicInteger` в Java) для выполнения безопасных операций над переменными без использования тяжелых мьютексов.
