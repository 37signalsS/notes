# Атомарные операции

## Определения

**Атомарная операция** — операция, которая выполняется как единое неделимое целое: она либо завершается полностью и успешно, либо не выполняется вовсе. Промежуточные состояния операции не видны сторонним наблюдателям.

**Атомарность** — свойство системы, гарантирующее, что никакое стороннее вмешательство или сбой не оставят систему в промежуточном (полуизменённом) состоянии. В программировании и системном администрировании атомарность является фундаментом для построения конкурентных и распределенных систем.

## Базовые концепции

### Уровни атомарности

1.  **Аппаратный уровень:** процессорные инструкции, выполняемые неделимо.
    *   **CAS (Compare-and-Swap):** сравнение с обменом. Инструкция записывает новое значение только в том случае, если текущее совпадает с ожидаемым.
    *   **LL/SC (Load-Link / Store-Conditional):** пара инструкций для реализации атомарного обновления без блокировок.
2.  **Уровень ОС:** системные вызовы ядра.
    *   Создание файла с флагом `O_EXCL` (ошибка, если файл уже существует).
    *   Системный вызов `rename()` для атомарной замены файлов.
3.  **Уровень файловой системы:**
    *   Создание жестких (hard links) и символических ссылок.
    *   Операции в журналируемых ФС или CoW-системах (ZFS, Btrfs).
4.  **Уровень баз данных:** транзакции, соответствующие принципу **Atomicity** в модели [ACID](../Databases/Concepts/acid.md).
5.  **Уровень распределённых систем:** протоколы консенсуса (Raft, Paxos) и механизмы в KV-хранилищах (etcd, Consul).

### Почему атомарность важна?

Без атомарности возникают **состояния гонки (Race Conditions)** — ситуации, когда результат выполнения программы зависит от непредсказуемого порядка планирования потоков или процессов. Атомарность позволяет избежать повреждения данных при одновременном доступе нескольких акторов к одному ресурсу.

### Атомарность и отсутствие блокировок (Lock-free)

Использование атомарных операций на аппаратном уровне позволяет создавать алгоритмы и структуры данных (например, Lock-free очереди или стеки), которые не требуют использования мьютексов:
*   **Lock-free:** гарантирует, что хотя бы один поток в системе будет продолжать работу за конечное число шагов. Это исключает взаимные блокировки (Deadlocks).
*   **Wait-free:** более строгая гарантия — каждый поток гарантированно завершит свою операцию за конечное число шагов, независимо от действий других потоков.

## Практические сценарии

### Сценарий 1: Атомарное обновление конфигурации (метод rename)

Чтобы приложение не прочитало поврежденный или частично записанный файл:
1.  Записать новые данные во временный файл в той же директории (например, `config.new`).
2.  Выполнить `mv config.new config.conf`.
В Linux вызов `rename` атомарно переключает индексный дескриптор (inode). Приложение получит либо старую версию, либо новую целиком.

### Сценарий 2: Использование символических ссылок (K8s style)

Метод позволяет обновлять целые наборы файлов одновременно:
1.  Создать директорию `v1` и `v2` с конфигурациями.
2.  Создать симлинк `current -> v1`.
3.  Для обновления атомарно заменить симлинк: `ln -sfn v2 current`.
Этот механизм используется в Kubernetes для обновления ConfigMap и Secret внутри подов.

### Сценарий 3: Атомарные счетчики в Redis

Команда `INCR` в Redis выполняется в однопоточном ядре, что гарантирует её атомарность:
```bash
redis-cli INCR page_views
```
Даже если тысячи клиентов одновременно вызовут эту команду, каждый вызов будет учтен корректно, в отличие от цикла "чтение-инкремент-запись" в обычном приложении.

### Сценарий 4: Compare-and-Swap в etcd/Consul

Для предотвращения перезаписи чужих изменений в распределенной системе используется `Check-and-Set` (CAS). Операция записи успешна только если текущая версия (ModifyIndex) совпадает с той, что была прочитана клиентом ранее.

## Дополнительная информация

### Ограничения атомарности

*   **Команда cp:** не атомарна. Процесс может начать чтение целевого файла, пока данные в него ещё дописываются.
*   **Междисковые операции:** `mv` между разными разделами (mount points) не атомарен, так как превращается в `cp` + `rm`.
*   **Многошаговые действия:** Большинство shell-скриптов не атомарны по умолчанию и требуют явного использования примитивов блокировки (например, `flock`).
