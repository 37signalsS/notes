# Атомарные операции

## Определения

**Атомарная операция (Atomic Operation)** — операция, которая выполняется как единое неделимое целое: она либо завершается полностью и успешно, либо не выполняется вовсе. Промежуточные состояния операции не видны сторонним наблюдателям.

**Атомарность (Atomicity)** — свойство системы, гарантирующее, что никакое стороннее вмешательство или сбой не оставят систему в промежуточном (полуизменённом) состоянии.

## Базовые концепции

### Уровни атомарности

1. **Аппаратный уровень:** процессорные инструкции, выполняемые за один цикл или защищенные блокировкой шины. Пример: `CAS (Compare-and-Swap)` — сравнение с обменом.
2. **Уровень ОС (Операционная система):** системные вызовы, гарантирующие неделимость действия. Например, создание файла через `open` с флагом `O_EXCL`.
3. **Уровень ФС (Файловая система):** переименование файла (`mv`) в пределах одного раздела диска.
4. **Уровень баз данных:** транзакции, соответствующие принципам `ACID (Atomicity, Consistency, Isolation, Durability)`.
5. **Уровень распределённых систем:** распределённые транзакции и протоколы консенсуса (Raft, Paxos).

### Почему атомарность важна?

Без атомарности возникают **состояния гонки (Race Conditions)** — ситуации, когда результат зависит от непредсказуемого порядка выполнения операций.

*Пример:* Два процесса одновременно читают значение `X=10`, прибавляют `1` и записывают результат. Если цикл «чтение-изменение-запись» не атомарен, оба могут прочитать `10`, вычислить `11` и записать `11`. В итоге одно обновление будет потеряно, хотя ожидалось значение `12`.

## Практические сценарии

### Сценарий 1: Атомарное обновление конфигурации

Чтобы приложение не прочитало поврежденный или частично записанный файл конфигурации:

1. Записать новые данные во временный файл в той же директории.
2. Использовать системный вызов `rename()` (команда `mv`) для замены старого файла новым.
В ОС Linux операция `rename` атомарна: приложение увидит либо старую версию файла, либо новую целиком.

### Сценарий 2: Блокировки (Locks) через файловую систему

Атомарное создание директории или файла может служить примитивом блокировки:

```bash
if mkdir /var/lock/mylock; then
  echo "Lock acquired"
else
  echo "Locked by another process"
fi
```

Операция `mkdir` атомарна на уровне ядра: при одновременном вызове несколькими процессами только один получит подтверждение успеха.

### Сценарий 3: Атомарные операции в Redis

В Redis команды `INCR` или `SETNX` атомарны. Это позволяет безопасно реализовывать распределенные счетчики или механизмы блокировки без сложной синхронизации на стороне приложения.

## Дополнительная информация

### Ограничения атомарности файловых систем

- Команда `cp` **не атомарна**. Процесс может начать чтение файла, пока он еще копируется.
- Команда `mv` между разными разделами (mount points) **не атомарна**, так как выполняется через копирование и последующее удаление (`cp` + `rm`).

### Атомарность в программировании

Современные языки предоставляют специальные типы (например, `std::atomic` в C++, `AtomicInteger` в Java) для выполнения безопасных операций над переменными без использования тяжелых механизмов блокировки (мьютексов).
