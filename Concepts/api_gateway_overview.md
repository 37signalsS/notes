# Обзор API Gateway

## Определения

**API Gateway** (Application Programming Interface Gateway — шлюз прикладного программного интерфейса) — это специализированный сервер, выступающий единой точкой входа (Single Point of Entry) для всех внешних клиентов. Он управляет взаимодействием между потребителями API и набором внутренних микросервисов, инкапсулируя внутреннюю структуру системы.

Шлюз работает преимущественно на **L7 (прикладном уровне)** модели OSI и обрабатывает так называемый **North-South трафик** (трафик между внешним клиентом и дата-центром/кластером).

## Базовые концепции

API Gateway централизует сквозную функциональность (Cross-Cutting Concerns), избавляя микросервисы от необходимости реализовывать её самостоятельно:

*   **Маршрутизация запросов:** перенаправление входящих вызовов на нужные сервисы на основе путей, заголовков, версии API или параметров запроса.
*   **Агрегация запросов (API Composition):** объединение данных из нескольких сервисов в один ответ для оптимизации клиентских запросов и снижения количества RTT (Round Trip Time).
*   **Безопасность и управление доступом:**
    *   Аутентификация (JWT, OAuth2, OIDC).
    *   Авторизация на уровне API (RBAC/ABAC).
    *   Защита от атак (WAF, SQL-инъекции, Cross-Site Scripting).
    *   Терминация TLS/SSL.
    *   **AI Security:** фильтрация PII-данных (персональной информации) в промптах и ответах LLM.
*   **Управление нагрузкой (Resiliency):**
    *   **Балансировка нагрузки:** распределение трафика (Round Robin, Least Connections, Weighted) с учетом состояния бэкендов (Health Checks).
    *   Ограничение скорости (Rate Limiting) и Throttling (защита от перегрузок и DDoS).
    *   Circuit Breaker (автоматическое отключение дефектных сервисов).
    *   **Кэширование:** локальное и распределенное кэширование ответов (включая семантическое кэширование для LLM).
*   **Трансформация протоколов и данных:**
    *   Трансляция REST/HTTP в gRPC, AMQP или Dubbo.
    *   Модификация заголовков, тел запросов и ответов (XML в JSON).
    *   Поддержка **MCP (Model Context Protocol)** для интеграции AI-агентов.
*   **Наблюдаемость (Observability):**
    *   Централизованное логирование.
    *   Сбор метрик (Golden Signals: Latency, Traffic, Errors, Saturation).
    *   Распределенная трассировка (интеграция с OpenTelemetry/Jaeger).

### Отличие от обратного прокси и балансировщика

Хотя API Gateway включает функции Reverse Proxy и Load Balancer, он обладает более глубоким пониманием бизнес-логики API (контент-маршрутизация, агрегация данных, сложная аутентификация), в то время как классические прокси (Nginx, HAProxy) чаще фокусируются на эффективной передаче байтов на уровнях L4/L7.

## Практические сценарии

*   **Backend for Frontend (BFF):** создание отдельных шлюзов для разных типов клиентов (Mobile, Web, IoT), предоставляющих оптимизированные для конкретной платформы API.
*   **Миграция с монолита (Strangler Fig pattern):** постепенный вынос функциональности в микросервисы, где шлюз прозрачно перенаправляет трафик между старым монолитом и новыми сервисами.
*   **Безопасность на периметре:** централизованная валидация сессий и токенов, чтобы внутренние сервисы могли доверять уже проверенным запросам (Zero Trust Edge).
*   **Управление релизами:** реализация Canary Deployment и Blue-Green развертываний через управление весами трафика на уровне шлюза.
*   **AI Gateway:** управление доступом к LLM-моделям, управление токенами, монетизация AI-сервисов и защита от инъекций в промпты.

## Современные тренды (2026)

### Kubernetes Gateway API
Стандарт `Ingress` признан устаревшим. В 2026 году доминирует **Gateway API (v1.4+)**, который разделяет ответственность между администраторами инфраструктуры (ресурс `Gateway`) и разработчиками приложений (ресурсы `HTTPRoute`, `GRPCRoute`, `TCPRoute`).

### AI-ориентированные шлюзы (AI Gateways)
Gateways эволюционировали в управляющий слой для генеративного ИИ:
*   **Semantic Caching:** кэширование ответов LLM на основе семантической близости промптов, что снижает затраты и задержки.
*   **LLM Load Balancing:** балансировка между провайдерами (OpenAI, Anthropic, локальные модели) на основе доступности квот и стоимости токенов.
*   **Tool Governance:** управление доступом AI-агентов к инструментам (tools) через Model Context Protocol (MCP).

## Дополнительная информация

### Популярные инструменты

1.  **Kong:** лидер в области AI Connectivity. Обладает мощной экосистемой плагинов и поддержкой AI Gateway функций.
2.  **Tyk:** фокус на GraphQL Federation и суверенных инсталляциях (air-gapped). Поддерживает AI Studio для управления агентами.
3.  **Envoy Gateway:** официальный CNCF-стандарт реализации Gateway API. Высокопроизводительный, расширяемый через WASM.
4.  **kgateway:** современный преемник Gloo Edge, полностью построенный на базе Kubernetes Gateway API.
5.  **Cloud Native:** AWS API Gateway, Google Apigee (интеграция с Gemini), Azure API Management.
