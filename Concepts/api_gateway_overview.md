# Обзор API Gateway

## Определения

**API Gateway** (Application Programming Interface Gateway — шлюз прикладного программного интерфейса) — это единая точка входа для всех клиентов, которая управляет тем, как внешние потребители взаимодействуют с набором внутренних сервисов (часто микросервисов). Он действует как «привратник», контролирующий и направляющий взаимодействие между различными частями системы.

## Базовые концепции

API Gateway выполняет множество функций, которые помогают упростить управление API, повысить безопасность и улучшить производительность распределенных систем, особенно в микросервисной архитектуре:

* **Маршрутизация запросов:** перенаправляет входящие запросы к соответствующим внутренним сервисам.
* **Агрегация запросов:** позволяет клиентам отправлять один запрос к шлюзу, который затем обращается к нескольким внутренним сервисам и агрегирует их ответы.
* **Балансировка нагрузки:** распределяет нагрузку между несколькими экземплярами внутренних сервисов.
* **Безопасность и аутентификация:** проверяет подлинность пользователей и авторизует запросы перед их передачей внутренним сервисам. Централизует логику безопасности.
* **Ограничение скорости (Rate Limiting):** защищает внутренние сервисы от перегрузок, ограничивая количество запросов от клиентов.
* **Кэширование:** кэширует ответы от внутренних сервисов для сокращения задержек и снижения нагрузки.
* **Мониторинг и логирование:** собирает метрики и логи всех входящих запросов, предоставляя централизованное представление о работе API.
* **Преобразование протоколов:** может преобразовывать запросы из одного протокола в другой (например, HTTP в gRPC).

## Практические сценарии

* **Микросервисные архитектуры:** API Gateway широко используются в архитектурах микросервисов, где есть множество независимых служб. Они упрощают клиентскую логику, скрывая сложность внутренней архитектуры.
* **Мобильные и веб-приложения:** позволяют оптимизировать взаимодействие для разных типов клиентов, предоставляя им специфичные API.
* **Управление публичными API:** централизованное управление доступом, версионированием и монетизацией программных интерфейсов.

## Дополнительная информация

Использование API Gateway позволяет организациям:

* Упростить разработку клиентских приложений, предоставляя им единый и согласованный интерфейс.
* Обеспечить согласованную безопасность и управление для всех API.
* Улучшить производительность и масштабируемость внутренних сервисов.
* Эффективно развивать и поддерживать свои API, внедряя новые функции и изменения без влияния на клиентов.

### Связанные концепции и инструменты

* **Микросервисы и монолиты:** API Gateway является ключевым компонентом для перехода на [микросервисную архитектуру](./monolith_vs_microservices.md).
* **SOA:** шлюз также применяется в [сервис-ориентированной архитектуре (SOA)](./soa_overview.md).
* **Kubernetes Ingress:** специализированная реализация шлюза для L7-маршрутизации в Kubernetes. Подробнее: [Обзор Ingress](../Kubernetes/Networking/Ingress/overview.md).
* **Kubernetes Gateway API:** следующее поколение API для управления трафиком в Kubernetes. Подробнее: [Gateway API — определения](../Kubernetes/Networking/gateway_api/definitions.md).
* **Протоколы:** для работы используются стандартные [HTTP-методы](../Networking/Protocols/HTTP/http_methods.md) (GET, POST, PUT, PATCH, DELETE).

Более детальное сравнение прокси-решений доступно в разделе [Proxy Server](../Networking/Concepts/proxy.md).
