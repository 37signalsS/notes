# Обзор API Gateway

## Определения

**API Gateway** (Application Programming Interface Gateway — шлюз прикладного программного интерфейса) — это специализированный сервер, выступающий единой точкой входа (Single Point of Entry) для всех внешних клиентов. Он управляет взаимодействием между потребителями API и набором внутренних микросервисов, инкапсулируя внутреннюю структуру системы.

Шлюз работает преимущественно на **L7 (прикладном уровне)** модели OSI и обрабатывает так называемый **North-South трафик** (трафик между клиентом и дата-центром/кластером).

## Базовые концепции

API Gateway централизует сквозную функциональность (Cross-Cutting Concerns), избавляя микросервисы от необходимости реализовывать её самостоятельно:

*   **Маршрутизация запросов:** перенаправление входящих вызовов на нужные сервисы на основе путей, заголовков или версии API.
*   **Агрегация запросов (API Composition):** объединение данных из нескольких сервисов в один ответ для оптимизации клиентских запросов.
*   **Безопасность и аутентификация:** проверка JWT-токенов, интеграция с OAuth2/OIDC, базовая проверка прав доступа (RBAC).
*   **Ограничение скорости (Rate Limiting) и Throttling:** защита системы от перегрузок и DDoS-атак путем ограничения количества запросов.
*   **Преобразование протоколов:** например, прием внешних REST/HTTP запросов и их трансляция во внутренние gRPC или AMQP вызовы.
*   **Управление жизненным циклом API:** версионирование, публикация документации и монетизация.
*   **Кэширование:** временное хранение ответов для снижения нагрузки на бэкенд.

### Отличие от Reverse Proxy и Load Balancer

Хотя API Gateway включает функции обратного прокси и балансировщика, он обладает более глубоким пониманием бизнес-логики API (контент-маршрутизация, агрегация данных, сложная аутентификация), в то время как классические прокси (Nginx, HAProxy) чаще фокусируются на эффективной передаче трафика на уровне L4/L7.

## Практические сценарии

*   **Backend for Frontend (BFF):** создание отдельных шлюзов для разных типов клиентов (Mobile, Web, IoT), предоставляющих оптимизированные для конкретной платформы API.
*   **Миграция с монолита (Strangler Fig pattern):** постепенный вынос функциональности в микросервисы, где шлюз прозрачно перенаправляет трафик между старым монолитом и новыми сервисами.
*   **Безопасность на периметре:** централизованная валидация сессий и токенов, чтобы внутренние сервисы могли доверять уже проверенным запросам.
*   **Canary и Blue-Green развертывания:** управление распределением трафика между разными версиями сервисов для безопасного релиза.

## Дополнительная информация

### Популярные инструменты

1.  **Kong:** облачный API Gateway на базе Nginx с мощной системой плагинов.
2.  **Tyk:** современный шлюз на языке Go с открытым исходным кодом.
3.  **Envoy:** высокопроизводительный L7-прокси, часто используемый как основа для других шлюзов (например, Gloo, Istio Ingress Gateway).
4.  **Облачные решения:** AWS API Gateway, Google Apigee, Azure API Management.
