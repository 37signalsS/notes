# Сценарии использования Unikernel

## Определения

**Сценарии использования юникернелов** (Unikernel Use Cases) — это совокупность практических областей применения, где архитектурные особенности технологии (минимализм, отсутствие переключения контекста, аппаратная изоляция) обеспечивают критическое преимущество перед традиционными виртуальными машинами и контейнерами.

Основные технические характеристики и архитектура Library OS описаны в [Обзоре Unikernel](./unikernel_overview.md).

## Основные концепции

### Почему выбирают юникернелы
Эффективность применения юникернелов в 2026 году определяется следующими факторами:

- **Минимальная база доверия (TCB):** Отсутствие шелла, SSH и лишних драйверов минимизирует поверхность атаки.
- **Мгновенный старт (Just-in-Time):** Время загрузки (10–50 мс) позволяет развертывать инфраструктуру в ответ на конкретный запрос.
- **Экстремальная плотность:** Возможность запускать тысячи изолированных инстансов на одном физическом сервере благодаря потреблению памяти <10 МБ.
- **Предсказуемость производительности:** Отсутствие фоновых процессов и планировщика ОС общего назначения гарантирует детерминированные задержки.

## Практические сценарии

### 1. Граничные вычисления и Интернет вещей (Edge & IoT)
Юникернелы стали стандартом для устройств с жесткими ограничениями по ресурсам и узлов, находящихся вне защищенного периметра.

- **Космические технологии (SpaceOS):** Использование формально верифицированных юникернелов (на базе MirageOS) для управления спутниковыми полезными нагрузками. Это блокирует до 70% уязвимостей нулевого дня при размере образа в 20 раз меньше контейнера.
- **Телекоммуникации (5G/6G):** Развертывание Virtual Network Functions (VNF) и систем обработки сигналов в реальном времени, где важна предсказуемая задержка.
- **Сетевые службы:** DNS, NTP и DHCP серверы в образах размером 1–5 МБ.

### 2. Доверенные вычисления (Confidential Computing)
Минимальный размер кода позволяет проводить полный аудит системы, что критично для безопасности.

- **Изоляция баз данных (Prisma Case):** Запуск выделенных инстансов БД для каждого клиента внутри юникернела (например, Unikraft). Это обеспечивает изоляцию уровня VM при производительности bare-metal.
- **Защищенные анклавы (TEE):** Выполнение кода внутри Intel SGX или AMD SEV с минимальной доверенной базой.
- **Архитектура Zero Trust:** Юникернел как базовая единица микросегментации, исключающая возможность горизонтального перемещения атакующего (lateral movement) из-за отсутствия инструментов ОС.

### 3. Serverless и эфемерный ИИ (Ephemeral AI)
Юникернелы решают проблему «холодного старта», делая FaaS-платформы более экономичными.

- **AI Inference по требованию:** Запуск легковесных моделей машинного обучения для обработки одного запроса с последующим моментальным уничтожением инстанса.
- **Виртуализация GPU:** Проекты (например, Cricket) позволяют юникернелам безопасно использовать аппаратное ускорение для ИИ-нагрузок.
- **Just-in-Time инфраструктура:** Создание микро-ВМ в ответ на входящий пакет (например, через AWS Firecracker или KubeVirt с поддержкой юникернелов).

### 4. Высокопроизводительные сети
Отсутствие переключений между User Space и Kernel Space позволяет обрабатывать трафик на скорости физической линии.

- **CDN и кэширующие прокси:** Узлы с экстремально низкой задержкой, работающие напрямую с сетевым стеком через io_uring или DPDK.
- **Балансировщики нагрузки:** Программные решения, интегрированные в юникернел, способные обрабатывать миллионы запросов в секунду на минимальном оборудовании.

### 5. Гибридные среды (Wasm + Unikernel)
Трендом 2025–2026 годов стала синергия WebAssembly и юникернелов.

- **Двойная изоляция:** WASM обеспечивает песочницу на уровне приложения, а юникернел — безопасный и минималистичный интерфейс к оборудованию.
- **Портативность:** Возможность запускать скомпилированные WASM-модули в любой среде с гарантированной безопасностью юникернела.
