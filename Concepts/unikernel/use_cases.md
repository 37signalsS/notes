# Сценарии использования Unikernel

## Определения

**Unikernel Use Cases** — это набор практических областей применения технологии юникернелов, где их специфические свойства (минимализм, скорость, изоляция) дают значимое преимущество над традиционными виртуальными машинами и контейнерами.

Основные технические характеристики и архитектура описаны в [Обзоре Unikernel](./unikernel_overview.md).

## Основные концепции

### Почему выбирают Unikernel
Эффективность применения юникернелов определяется следующими факторами:

- **Минимальная база доверия (TCB):** Отсутствие лишнего кода делает систему идеальной для безопасности.
- **Мгновенный старт:** Возможность запускать инфраструктуру «по требованию» (Just-in-Time).
- **Высокая плотность:** Возможность запускать тысячи изолированных инстансов на одном физическом сервере.
- **Предсказуемость:** Отсутствие фоновых процессов ОС гарантирует детерминированную производительность.

## Практические сценарии

### 1. Edge Computing и IoT
Юникернелы идеально подходят для устройств с жесткими ограничениями по ресурсам и узлов, находящихся вне защищенного периметра дата-центра.

- **Сетевые службы:** DNS, NTP, DHCP серверы в компактных образах (1–5 МБ).
- **Граничные шлюзы:** SSL/TLS терминация трафика с минимальными задержками.
- **Безопасность IoT:** Изоляция кода прошивки от аппаратных ресурсов через гипервизор.
- **Пример:** Использование [Unikraft](./popular_unikernels.md) для создания легковесных сетевых функций (VNF).

### 2. Доверенные вычисления (Confidential Computing)
Это одна из самых перспективных ниш. Малый размер кода позволяет проводить аудит всей системы и минимизировать риски утечки данных.

- **Защищенные анклавы (TEE):** Запуск юникернелов внутри Intel SGX или AMD SEV.
- **Zero Trust:** Юникернел как единица микросегментации, где каждый сервис имеет собственное изолированное «ядро».

### 3. Serverless и FaaS 2.0
Юникернелы устраняют проблему «холодного старта», которая характерна для тяжелых контейнерных сред.

- **Just-in-Time инфраструктура:** Запуск микро-ВМ в ответ на входящий пакет и моментальное уничтожение после обработки.
- **Пример:** Архитектура MicroVM в **AWS Firecracker** (хотя это не «чистый» юникернел, концепция идентична). Подробнее см. [Инструменты и будущее](./tools_future.md).

### 4. Высокопроизводительный Networking
Отсутствие переключений между пространством пользователя и ядра позволяет обрабатывать пакеты на скорости, близкой к физической линии.

- **CDN узлы:** Кэширующие прокси с экстремально низкой задержкой.
- **Load Balancers:** Балансировщики нагрузки, работающие напрямую с сетевым стеком.

```
Диаграмма: Сравнение плотности и старта
┌──────────────────┬──────────────┬──────────────┐
│ Технология       │ Время старта │ Плотность    │
├──────────────────┼──────────────┼──────────────┤
│ Linux VM         │ 10–30 сек    │ Десятки      │
│ Docker Container │ 1–3 сек      │ Сотни        │
│ Unikernel        │ 10–50 мс     │ Тысячи       │
└──────────────────┴──────────────┴──────────────┘
```
