# Unikernels: Сценарии использования

## Определения

В данном документе описываются практические сценарии, в которых применение **unikernels** наиболее оправдано и эффективно. Эти сценарии обусловлены ключевыми преимуществами unikernels: малым размером, быстрым стартом и высокой степенью изоляции.

Для введения в технологию обратитесь к [общему обзору Unikernels](./unikernel_overview.md).

## Практические сценарии

### 1. Edge Computing и IoT

Unikernels идеально подходят для устройств с ограниченными ресурсами и для сетевых функций на границе сети.

* **Примеры:**
  * Легковесные DNS-серверы.
  * SSL/TLS-терминаторы.
  * Сетевые экраны (firewalls) и шлюзы безопасности.
  * Программное обеспечение для IoT-устройств.
* **Почему это эффективно:**
  * **Мгновенный старт:** Позволяет быстро разворачивать и масштабировать функции на edge-локациях.
  * **Малый размер:** Экономит дисковое пространство и память на устройствах с ограниченными ресурсами.
  * **Безопасность:** Минимальная поверхность атаки критически важна для устройств, развернутых вне защищенного периметра дата-центра.


### 2. Serverless / Function-as-a-Service (FaaS)

Хотя большинство FaaS-платформ используют контейнеры, unikernel-подобный подход (например, MicroVMs) является следующим шагом эволюции.

* **Пример:** **AWS Firecracker**, технология, лежащая в основе AWS Lambda и AWS Fargate, использует MicroVMs, которые по своей сути очень близки к unikernels.
* **Почему это эффективно:**
  * **Быстрый "холодный старт":** Запуск функции за миллисекунды, что решает одну из главных проблем serverless.
  * **Высокая плотность:** Возможность запускать тысячи изолированных функций на одном физическом хосте.
  * **Надежная изоляция:** Каждая функция работает в своей собственной MicroVM, что обеспечивает более надежную изоляцию по сравнению с контейнерами, разделяющими общее ядро ОС.

### 3. Высокопроизводительные сетевые приложения (High-Performance Networking)

Сетевые функции, требующие минимальной задержки и высокой пропускной способности.

* **Примеры:**
  * Балансировщики нагрузки.
  * Кэширующие прокси-серверы.
  * Компоненты кастомных CDN.
* **Почему это эффективно:**
  * Отсутствие переключений между ядром и пользовательским пространством позволяет обрабатывать сетевой трафик с минимальными задержками.

### 4. Специализированные устройства безопасности

Создание "закаленных" (hardened) виртуальных устройств.

* **Примеры:**
  * VPN-концентраторы.
  * Системы обнаружения/предотвращения вторжений (IDS/IPS).
* **Почему это эффективно:**
  * Устранение всех ненужных компонентов ОС и утилит делает систему чрезвычайно сложной для взлома.
