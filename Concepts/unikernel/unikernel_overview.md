# Unikernel: Обзор

## Определения

**Unikernel** — это специализированный, легковесный образ операционной системы, созданный для запуска одного конкретного приложения. Он создается путем компиляции исходного кода приложения вместе с минимально необходимыми библиотеками и драйверами ОС в единый исполняемый файл, который может работать непосредственно на гипервизоре (или, реже, на "голом железе").

Ключевая идея: вместо развертывания приложения поверх полнофункциональной ОС общего назначения (например, Linux), unikernel объединяет приложение и ОС в одно целое.

### Архитектура: Традиционный подход vs Unikernel

| **Традиционная VM** | **Unikernel** |
| :--- | :--- |
| 1. Приложение | 1. Приложение + Библиотеки ОС |
| 2. Библиотеки User-space (libc, др.) | 2. Гипервизор / "Железо" |
| 3. Ядро ОС (со всеми драйверами) | |
| 4. Гипервизор / "Железо" | |
| **Размер:** сотни МБ - ГБ | **Размер:** единицы МБ |
| **Время старта:** десятки секунд | **Время старта:** миллисекунды |
| **Поверхность атаки:** Огромная | **Поверхность атаки:** Минимальная |

## Основные концепции

### Типы Unikernels

Существуют различные подходы к созданию unikernels:

* **"Чистый" подход (Clean-slate):** Написаны с нуля на типобезопасных языках. Пример: [MirageOS](./popular_unikernels.md) (OCaml).
* **Совместимые с POSIX:** Частично или полностью поддерживают POSIX API, что упрощает портирование существующих приложений. Пример: [OSv](./popular_unikernels.md).
* **На базе существующих ОС:** Используют компоненты (например, драйверы) из существующих ядер, таких как NetBSD или Linux. Пример: [Rumprun](./popular_unikernels.md).

### Ключевые преимущества и недостатки

Unikernels предлагают значительные улучшения в безопасности и производительности за счет своей минималистичной природы, но это сопряжено с компромиссами в гибкости и простоте разработки.
