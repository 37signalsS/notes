# Обзор Unikernel

## Определения

**Unikernel** (Юникернел) — это специализированный, минималистичный образ операционной системы, скомпилированный вместе с приложением в единый бинарный файл. В отличие от традиционных ОС общего назначения, юникернел предназначен для выполнения ровно одной задачи (одного процесса) в изолированной среде.

### Техническая суть
Юникернел реализует концепцию **Library OS** (библиотечная ОС). Вместо того чтобы полагаться на внешнее ядро и системные вызовы, приложение линкуется с библиотеками, реализующими только необходимые функции (сеть, файловая система, планировщик).

**Ключевые технические характеристики:**
- **Single Address Space:** Отсутствие разделения на User Space и Kernel Space. Приложение и «ядро» работают в одном адресном пространстве.
- **Ring 0 Execution:** Весь код выполняется на высшем уровне привилегий процессора (в контексте виртуализации).
- **No Context Switches:** Отсутствие переключений контекста между режимом пользователя и ядра, что радикально снижает оверхед.
- **Immutable Infrastructure:** Образ является неизменяемым; любые изменения требуют пересборки.

### Сравнение: VM vs Container vs Unikernel (2026)

| Характеристика | Традиционная VM | Контейнер (Docker) | Unikernel |
| :--- | :--- | :--- | :--- |
| **Изоляция** | Аппаратная (Сильная) | Программная (Средняя) | Аппаратная (Сильная) |
| **Состав образа** | Приложение + ОС | Приложение + Rootfs | Приложение + Library OS |
| **Размер образа** | 500 МБ — 5 ГБ | 50 МБ — 500 МБ | 1 МБ — 50 МБ |
| **Время старта** | 30–60 сек | 1–5 сек | 5–50 мс |
| **Системные вызовы** | Syscalls (trap) | Syscalls (proxy) | Прямые вызовы функций |
| **Поверхность атаки** | Огромная | Значительная | Минимальная |
| **Плотность на хост** | Десятки | Сотни | Тысячи |

## Основные концепции

### Архитектура Library OS
Традиционные ОС предоставляют абстракции «для всех». Юникернелы позволяют выбрать модули:
1.  **Сетевой стек:** Если приложению не нужен UDP, подключается только TCP-модуль.
2.  **Драйверы:** Только для конкретного гипервизора (например, Virtio).
3.  **Управление памятью:** Оптимизированное под конкретный тип нагрузки (например, Garbage Collection для JVM).

### Типы Unikernel-систем

- **Clean-slate (Специфичные):** Написаны с нуля, обеспечивают максимальную безопасность.
  - *Пример:* **MirageOS** (OCaml) — де-факто стандарт для безопасных сетевых шлюзов.
- **POSIX-совместимые:** Позволяют запускать существующий код с минимальными правками.
  - *Пример:* **OSv** — оптимизирован для облачных вычислений и JVM. В 2026 году добавлена полноценная поддержка ASLR.
- **Модульные (Modern frameworks):** Позволяют собирать образы из независимых компонентов.
  - *Пример:* **Unikraft** (Linux Foundation) — самый динамичный проект. Релиз 11 «Metis» (2026) внедрил поддержку мгновенных снапшотов и плагинов AI-инференса.
- **Rust-based:** Новое поколение высокопроизводительных систем.
  - *Пример:* **HermitOS** (поддержка GPU для HPC), **Microsoft Hyperlight** (CNCF Sandbox, 2025).

### Преимущества и недостатки
Юникернелы обеспечивают беспрецедентную безопасность и производительность, но требуют изменения подхода к DevOps (отладка, мониторинг).

Подробный анализ представлен в [Преимуществах и ограничениях](./unikernel_advantages_disadvantages.md).

## Практические сценарии

Благодаря характеристикам «быстрый старт + малый размер + высокая изоляция», юникернелы стали стандартом в таких областях, как **Edge Computing**, **Confidential Computing**, **Serverless (FaaS)** и высокопроизводительные сетевые функции. В 2026 году технология также активно применяется для эфемерного ИИ-инференса и в космических разработках.
