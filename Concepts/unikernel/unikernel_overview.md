# Обзор Unikernel

## Определения

**Unikernel** (Юникернел) — это специализированный, минималистичный образ операционной системы, скомпилированный вместе с конкретным приложением в единый исполняемый бинарный файл. В отличие от ОС общего назначения (Linux, Windows), юникернел предназначен для выполнения ровно одной задачи в изолированной среде гипервизора.

### Техническая суть: Библиотечная ОС (Library OS)
Юникернел реализует концепцию **Library OS**. Вместо того чтобы полагаться на внешнее ядро и системные вызовы через прерывания, приложение линкуется с библиотеками, которые реализуют только те функции ядра, которые необходимы данному приложению (например, стек TCP/IP без поддержки файловой системы).

**Ключевые технические характеристики:**
- **Единое адресное пространство (Single Address Space):** Отсутствие разделения на User Space и Kernel Space. Это исключает дорогостоящие переключения контекста (context switches).
- **Выполнение в Ring 0:** Весь код приложения работает на высшем уровне привилегий процессора в контексте виртуальной машины.
- **Неизменяемая инфраструктура (Immutable Infrastructure):** Образ создается один раз. Любое изменение конфигурации или кода требует полной пересборки бинарного файла.
- **Минимализм:** Отсутствие шелла (bash), SSH, пакетных менеджеров и лишних драйверов.

## Требования для использования

Для развертывания юникернелов необходима следующая инфраструктура:
- **Аппаратная поддержка:** Процессор с инструкциями виртуализации (Intel VT-x / AMD-V).
- **Гипервизор:** KVM/QEMU, Xen, AWS Firecracker или специализированные облачные платформы (KraftCloud).
- **Инструментарий сборки:** Зависит от выбранного фреймворка (например, `kraft` для Unikraft, `ops` для Nanos, `dune` для MirageOS).

## Основные концепции

### Сравнение технологий виртуализации и изоляции (2026)

| Характеристика | Традиционная VM | Контейнер (Docker) | Unikernel |
| :--- | :--- | :--- | :--- |
| **Изоляция** | Аппаратная (Сильная) | Программная (Средняя) | Аппаратная (Сильная) |
| **Состав образа** | Приложение + ОС + Deps | Приложение + Rootfs | Приложение + Library OS |
| **Размер образа** | 500 МБ — 10 ГБ | 50 МБ — 500 МБ | **1 МБ — 50 МБ** |
| **Время старта** | 30–60 сек | 1–3 сек | **5–50 мс** |
| **Взаимодействие с ядром** | Syscalls (trap) | Syscalls (proxy) | **Прямые вызовы функций** |
| **Поверхность атаки** | Огромная | Значительная | **Минимальная** |
| **Плотность на хост** | Десятки | Сотни | **Тысячи** |

### Жизненный цикл юникернела
В отличие от контейнеров, жизненный цикл юникернела тесно связан с процессом компиляции:
1.  **Выбор компонентов:** Разработчик указывает необходимые модули (сеть, драйверы гипервизора).
2.  **Компиляция:** Приложение и модули ядра собираются в единый ELF-файл.
3.  **Специализация:** Образ упаковывается для конкретного гипервизора (например, создается загрузочный диск для QEMU).
4.  **Запуск:** Гипервизор запускает образ напрямую, минуя стадию загрузки традиционной ОС.

### Основные типы систем

- **Специфичные (Clean-slate):** Написаны с нуля на типобезопасных языках. Обеспечивают максимальную безопасность. 
  - *Пример:* **MirageOS** (OCaml).
- **POSIX-совместимые:** Позволяют переносить существующие приложения на C/C++/Go с минимальными изменениями. 
  - *Пример:* **Unikraft**, **Nanos**.
- **Специализированные рантаймы:** Оптимизированы под конкретные виртуальные машины (например, JVM).
  - *Пример:* **OSv**.

## Практические сценарии

Юникернелы эффективно решают задачи в областях, где критична скорость и безопасность:
- **Edge Computing:** Устройства с малым объемом памяти и жесткими требованиями к безопасности.
- **Serverless (FaaS):** Устранение проблемы «холодного старта» благодаря запуску за миллисекунды.
- **Confidential Computing:** Минимальная база кода позволяет легко проводить аудит безопасности всей системы.
- **Высокопроизводительные сети:** Обработка трафика с минимальными задержками (Zero-copy).

Подробные примеры использования см. в документе [Сценарии использования Unikernel](./use_cases.md).

## Валидация и проверка работоспособности

Для подтверждения успешного развертывания юникернела используются следующие методы:
- **Проверка размера бинарного файла:** Убедитесь, что образ не содержит лишних артефактов (например, образ веб-сервера на Go должен быть в пределах 10-20 МБ).
- **Замер времени старта:** Интервал от команды `run` до появления первой записи в логах приложения. Ожидаемое значение для 2026 года: <100 мс.
- **Сканирование портов:** Внешнее сканирование (nmap) должно показывать открытыми только те порты, которые явно прописаны в логике приложения.

## Устранение неполадок

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Ошибка "No bootable device"** | Неверный формат образа или отсутствие загрузчика | Проверить целевую платформу (target) при сборке. |
| **Тайм-аут сетевого соединения** | Не подключен модуль стека протоколов | Убедиться, что библиотеки типа `lib-lwip` включены в сборку. |
| **Высокое потребление ресурсов** | Включены неиспользуемые отладочные символы или модули | Собрать образ в режиме `Release` с удалением символов (strip). |
| **Нестабильная работа на KVM** | Несоответствие версии Virtio драйвера | Проверить параметры гипервизора и совместимость с `virtio-net`. |
