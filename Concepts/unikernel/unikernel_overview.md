# Обзор Unikernel

## Определения

**Unikernel** (Юникернел) — это специализированный, минималистичный образ операционной системы, предназначенный для запуска ровно одного приложения. В отличие от традиционных ОС, юникернел не разделяет пространство пользователя (user space) и пространство ядра (kernel space).

Ключевая концепция: приложение компилируется вместе с минимально необходимым набором библиотек ОС (Library OS) и драйверов в единый бинарный файл (образ), который запускается напрямую на гипервизоре без промежуточной гостевой ОС.

### Сравнение: Традиционная VM vs Unikernel

| Характеристика | Традиционная VM | Unikernel |
| :--- | :--- | :--- |
| **Состав образа** | Приложение + Либы + Полноценная ОС (ядро, шелл, утилиты) | Приложение + Библиотеки Library OS |
| **Размер образа** | Сотни МБ — ГБ | Единицы МБ |
| **Время старта** | Десятки секунд | Миллисекунды |
| **Изоляция** | Сильная (аппаратная через гипервизор) | Сильная (аппаратная через гипервизор) |
| **Поверхность атаки** | Огромная (лишние службы, драйверы, шелл) | Минимальная (только код приложения) |
| **Ресурсы** | Высокие накладные расходы на ОС | Минимальные накладные расходы |

## Основные концепции

### Как работает Unikernel (Library OS)
В традиционной архитектуре приложение вызывает функции ОС через системные вызовы (syscalls). В юникернелах эти функции предоставляются в виде обычных библиотек, которые линкуются к приложению на этапе сборки. Если приложению не нужна файловая система или стек протоколов USB, они просто не включаются в итоговый образ.

### Типы Unikernel-систем

- **Clean-slate (Чистые):** Написаны с нуля, часто на типобезопасных языках. 
  - *Пример:* [MirageOS](./popular_unikernels.md) (OCaml).
- **POSIX-совместимые:** Стремятся поддерживать стандартные API для упрощения портирования существующих приложений.
  - *Пример:* [OSv](./popular_unikernels.md).
- **Модульные и бинарно-совместимые:** Современные фреймворки, позволяющие собирать образы из существующих компонентов или запускать немодифицированные бинарные файлы.
  - *Пример:* [Unikraft](./popular_unikernels.md) (Linux Foundation), [Nanos/Ops](./popular_unikernels.md).

### Преимущества и недостатки
Юникернелы обеспечивают беспрецедентную безопасность и производительность, но усложняют процессы разработки и эксплуатации.

Подробный анализ представлен в [Преимуществах и ограничениях](./unikernel_advantages_disadvantages.md).

## Практические сценарии

Благодаря характеристикам "быстрый старт + малый размер + высокая изоляция", юникернелы находят применение в следующих областях:

1. **Edge Computing:** Запуск легких функций на границе сети с минимальными задержками. См. [Edge Computing](../edge_computing_overview.md).
2. **Микросервисы:** Высокая плотность размещения сервисов на одном хосте. См. [Микросервисы](../monolith_vs_microservices.md).
3. **Serverless (FaaS):** Моментальный запуск функции в ответ на событие.
4. **Сетевые функции (VNF):** Быстрые и безопасные программные роутеры, файрволы.

Дополнительные примеры — в [Сценариях использования](./use_cases.md) и [Популярных проектах](./popular_unikernels.md).
