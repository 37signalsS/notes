# Юникернелы: Инструменты и будущее

## Определения

В данном документе рассматриваются современные инструменты для работы с юникернелами, а также смежные технологии — **MicroVM** и **WebAssembly (Wasm)**. Эти направления определяют вектор развития легковесных и безопасных вычислений в облачных и граничных (Edge) средах.

Базовые концепции технологии описаны в [Обзоре Unikernel](./unikernel_overview.md).

## Основные концепции

### 1. AWS Firecracker (MicroVMs)
**MicroVM** — это эволюционный шаг в виртуализации, сочетающий безопасность традиционных ВМ со скоростью контейнеров. 

- **Firecracker:** Минималистичный гипервизор (VMM), написанный на Rust. Использует KVM для создания легковесных виртуальных машин.
- **Роль в экосистеме:** Firecracker не является юникернелом в строгом смысле (он запускает минимизированные ядра Linux), но решает те же задачи: мгновенный холодный старт и высокая плотность размещения.
- **Применение:** Основа для AWS Lambda и AWS Fargate.

### 2. WebAssembly (Wasm) и WASI
WebAssembly перестал быть технологией только для браузеров и превратился в универсальную среду выполнения (runtime) для серверных задач.

- **WASI (WebAssembly System Interface):** Стандартный интерфейс, позволяющий Wasm-модулям взаимодействовать с системными ресурсами (файлы, сеть) в изолированной «песочнице».
- **Сравнение с Unikernel:**
  * Wasm обеспечивает еще большую портативность (один бинарник для всех архитектур).
  * Юникернелы предоставляют более низкоуровневый доступ к ресурсам и аппаратную изоляцию через гипервизор.

### Сравнительная таблица технологий

| Характеристика | Контейнер | Unikernel | MicroVM (Firecracker) | Wasm + WASI |
| :--- | :--- | :--- | :--- | :--- |
| **Изоляция** | Программная (ядро хоста) | Аппаратная (гипервизор) | Аппаратная (гипервизор) | Программная (Sandbox) |
| **Размер образа** | 100+ МБ | 1–10 МБ | 5–50 МБ | < 1 МБ |
| **Время старта** | ~1 сек | ~10–50 мс | ~100–150 мс | < 1 мс |
| **Портативность** | Высокая (Linux/Windows) | Низкая (под платформу) | Средняя (KVM) | Экстремальная (Any OS/Arch) |

## Практические сценарии

### Современный инструментарий
Для практической реализации юникернелов рекомендуется использовать следующие инструменты (подробные примеры — в [Популярных проектах](./popular_unikernels.md)):

1.  **OPS / Nanos:** Самый простой способ запустить существующее приложение (Go, Node.js) как юникернел.
2.  **Kraft (Unikraft):** Профессиональный инструмент для сборки высокооптимизированных образов с модульной структурой.
3.  **Wasmtime / WasmEdge:** Популярные рантаймы для запуска WebAssembly модулей на сервере или edge-узлах.

### Сценарии «Будущего»
*   **Гибридные среды:** Использование Wasm-модулей внутри юникернелов для обеспечения максимальной портативности и безопасности одновременно.
*   **Serverless 2.0:** Переход от контейнерных лямбда-функций к MicroVM и Wasm для устранения задержек холодного старта.
