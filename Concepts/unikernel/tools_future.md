# Юникернелы: Инструменты и будущее

## Определения

В данном документе рассматриваются современные инструменты для работы с юникернелами, а также смежные технологии изоляции — **MicroVM** и **WebAssembly (Wasm)**. Эти направления определяют вектор развития легковесных и безопасных вычислений в облачных (Cloud Native) и граничных (Edge) средах 2026 года.

Базовые концепции технологии описаны в [Обзоре Unikernel](./unikernel_overview.md).

## Основные концепции

### 1. AWS Firecracker (MicroVM) и Kata Containers
**MicroVM** — это технология виртуализации, сочетающая безопасность традиционных ВМ со скоростью контейнеров. В 2026 году стандарт де-факто для serverless-платформ.

*   **AWS Firecracker:** Минималистичный гипервизор (VMM) на Rust. Использует KVM для создания легковесных ВМ.
    *   **Снимки состояния (Snapshots):** Поддержка мгновенного восстановления за ~25–30 мс через механизмы отложенной загрузки памяти (`userfaultfd`).
    *   **Безопасность:** Процесс **Jailer** изолирует VMM, применяя жесткие seccomp-профили и cgroups v2.
*   **Kata Containers 4.0:** Инструмент для запуска контейнеров в изолированных microVM.
    *   В версии 4.0 используется Rust-runtime (`runtime-rs`), что снизило накладные расходы на память до 50–100 МБ на под.
    *   Полная совместимость с OCI и Kubernetes через `RuntimeClass`.

### 2. WebAssembly (Wasm) и компонентная модель
WebAssembly (Wasm) превратился в универсальную среду выполнения для серверных и Edge-задач, предлагая изоляцию на уровне песочницы приложения.

*   **WASI 0.3 (WASI Preview 3):** Стандарт 2026 года, привнесший **нативную асинхронность** (`future`, `stream`) в Wasm, что решило проблемы с производительностью I/O.
*   **Component Model:** Позволяет собирать Wasm-приложения из независимых модулей (компонентов), написанных на разных языках, обеспечивая высокую переиспользуемость.
*   **Интеграция с Kubernetes:**
    *   **runwasi:** Проект CNCF, предоставляющий shim-интерфейсы для запуска Wasm-модулей в `containerd`.
    *   **SpinKube:** Популярный стек для запуска serverless-приложений на базе Wasm внутри K8s с холодным стартом < 10 мс.

### Сравнительная таблица технологий (2026)

| Характеристика | Контейнеры (OCI) | Unikernel (Unikraft) | MicroVM (Firecracker) | Wasm (WASI 0.3) |
| :--- | :--- | :--- | :--- | :--- |
| **Изоляция** | Программная (Kernel) | Аппаратная (VMM) | Аппаратная (VMM) | Программная (Sandbox) |
| **Размер образа** | 100+ МБ | 5–50 МБ | 5–50 МБ | < 1–10 МБ |
| **Холодный старт** | ~200–500 мс | **~10–20 мс** | ~25–50 мс (Snapshot) | **< 1 мс** |
| **Ресурсы (RAM)** | ~50–200 МБ | < 10 МБ | ~20–50 МБ | **< 5 МБ** |
| **Портативность** | Высокая | Средняя (под платформу) | Средняя (KVM) | **Экстремальная** |

## Практические сценарии

### Современный инструментарий
1.  **Kraft / KraftCloud:**
    *   `kraft` CLI позволяет собирать и запускать юникернелы (Nginx, Go, Node.js) одной командой.
    *   **KraftCloud** обеспечивает масштабирование до нуля (scale-to-zero) с временем пробуждения в миллисекундах.
2.  **OPS (NanoVMs):** Самый быстрый путь для запуска существующих Linux-бинарников как юникернелов без перекомпиляции.
3.  **Wasmtime / WasmEdge:** Рантаймы для выполнения Wasm-компонентов. WasmEdge лидирует в задачах **AI Inference** (Llama 3/4) благодаря поддержке GPU.

### Сценарии развития
*   **AI Agent Sandboxing:** Использование Firecracker для изоляции недоверенного кода, генерируемого ИИ, с мгновенным запуском среды выполнения.
*   **Zero-Trust Edge:** Развертывание Wasm-модулей на граничных узлах (CDN, IoT) с гарантированной безопасностью через capability-based security.
*   **Serverless 2.0:** Устранение "холодных стартов" в K8s с помощью Wasm-компонентов, управляемых через `SpinKube`.
