# Infrastructure as Code (IaC): Обзор

## Определения

**Инфраструктура как код (Infrastructure as Code, IaC)** — это подход к управлению и предоставлению вычислительной инфраструктуры (серверы, сети, балансировщики, базы данных), при котором ее конфигурация описывается с помощью машинно-читаемых файлов (кода), а не настраивается вручную.

Этот код хранится в системе контроля версий (например, Git) наравне с кодом приложения, что позволяет автоматизировать, версионировать и воспроизводить инфраструктуру.

## Основные концепции

### Ключевые принципы

* **Декларативность:** Вы описываете *желаемое состояние* инфраструктуры ("что должно быть"), а инструмент IaC сам определяет, *как* этого достичь.
* **Идемпотентность:** Повторное применение одного и того же кода не приводит к изменению состояния, если оно уже соответствует описанному. Это делает операции безопасными и предсказуемыми.
* **Версионируемость:** Вся история изменений инфраструктуры хранится в Git. Любое изменение можно отследить, проанализировать и, при необходимости, откатить.
* **Источник истины (Source of Truth):** Код в репозитории является единственным достоверным источником информации о том, какой должна быть инфраструктура. Ручные изменения на серверах запрещены.

### Декларативный vs. Императивный подходы

| Аспект | Декларативный (IaC-подход) | Императивный (Скриптовый подход) |
| :--- | :--- | :--- |
| **Что описываем?**| **Что** должно быть (цель) | **Как** это сделать (шаги) |
| **Пример** | `resource "server" { state = "running" }` | `if !server_exists(); then create_server(); fi` |
| **Идемпотентность**| Встроена в инструмент | Требует ручной реализации |
| **Предсказуемость**| Высокая (план изменений) | Низкая (зависит от текущего состояния) |

Хотя императивный подход полезен для одноразовых задач, декларативный является стандартом для IaC благодаря своей надежности.

## Практические сценарии

### Зачем нужен IaC?

* **Воспроизводимость:** Гарантия того, что окружения для разработки, тестирования и продакшена идентичны.
* **Автоматизация:** Полное устранение ручного труда при создании и обновлении инфраструктуры, что многократно ускоряет процесс.
* **Прозрачность и аудит:** Все изменения проходят через code review, и всегда известно, кто, когда и зачем изменил инфраструктуру.
* **Надежность:** Автоматическое обнаружение "дрейфа" (расхождения между кодом и реальным состоянием) и его исправление.

### Жизненный цикл изменений

1. **Код:** Разработчик описывает инфраструктуру в виде кода (например, в HCL для Terraform).
2. **План:** Инструмент IaC анализирует код и создает "план" — список изменений, которые нужно внести.
3. **Ревью:** План проверяется коллегами.
4. **Применение (Apply):** После одобрения инструмент автоматически применяет изменения.

### Пример 1: Создание VM (Terraform)

Декларативное описание виртуальной машины и сети.

```hcl
// main.tf
resource "yandex_vpc_network" "default" {
  name = "app-network"
}

resource "yandex_vpc_subnet" "default" {
  name           = "app-subnet"
  zone           = "ru-central1-a"
  network_id     = yandex_vpc_network.default.id
  v4_cidr_blocks = ["10.5.0.0/24"]
}

resource "yandex_compute_instance" "app" {
  name        = "web-app-server"
  platform_id = "standard-v2"
  zone        = "ru-central1-a"

  resources {
    cores  = 2
    memory = 2
  }

  boot_disk {
    initialize_params {
      image_id = "fd8vj3j1l015********" // Ubuntu 22.04 LTS
    }
  }

  network_interface {
    subnet_id = yandex_vpc_subnet.default.id
    nat       = true
  }
}
```

### Пример 2: Настройка сервера (Ansible)

Декларативное описание состояния пакета и сервиса.

```yaml
# playbook.yml
- hosts: webservers
  become: yes
  tasks:
    - name: Ensure nginx is at the latest version
      apt:
        name: nginx
        state: latest
    
    - name: Ensure nginx is running and enabled on boot
      service:
        name: nginx
        state: started
        enabled: yes
```

## Дополнительная информация

Применение IaC превращает инфраструктуру из набора хрупких, настроенных вручную серверов в предсказуемый, воспроизводимый и управляемый программный артефакт, который развивается вместе с приложением.
