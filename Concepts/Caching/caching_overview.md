# Кэширование: Обзор

## Определения

**Кэширование** — это процесс хранения копий данных в более быстром и близком к потребителю слое (кэше) для ускорения последующих запросов к этим данным. Основная цель — значительно уменьшить задержку (latency) и снизить нагрузку на основное, более медленное хранилище данных (например, базу данных или внешний API (Application Programming Interface)).

Использование кэша вводит компромисс между скоростью и риском получения устаревших данных (*staleness*).

## Основные концепции

### Ключевые метрики

* **Hit Ratio (Коэффициент попаданий):** Доля запросов, успешно обслуженных из кэша. `Hits / (Hits + Misses)`.
* **Miss Penalty (Штраф за промах):** Дополнительные затраты (время, ресурсы) при промахе в кэше, когда требуется обращение к основному источнику данных.

### Управление жизненным циклом данных

* **Time-To-Live (TTL):** Срок жизни записи в кэше, по истечении которого она считается устаревшей и подлежит удалению или обновлению.
* **Инвалидация кэша:** Процесс принудительного удаления или пометки данных в кэше как недействительных. Обычно выполняется при изменении исходных данных.
* **[Паттерны кэширования](./caching_patterns.md):** Стратегии чтения и записи данных, такие как Cache-Aside, Read-Through, Write-Through.
* **[Политики вытеснения](./caching_eviction_policies.md):** Алгоритмы (LRU (Least Recently Used), LFU (Least Frequently Used)), которые решают, какие данные удалить из кэша при нехватке места.

### Другие важные аспекты

* **Сериализация:** Формат, в котором данные хранятся в кэше. Влияет на производительность и использование памяти.
* **Пространства имен (Namespaces):** Использование префиксов в ключах для группировки связанных данных и упрощения массовой инвалидации.

## Практические сценарии

* **Предотвращение "собачьей конуры" (Cache Stampede):** Добавляйте случайную вариативность (джиттер) к TTL, чтобы избежать массового истечения срока действия ключей и одновременной нагрузки на источник данных.
* **Обеспечение консистентности:** При критической важности свежих данных используйте паттерн *write-through* или явную инвалидацию по событиям изменения источника.
* **Оптимизация хранения:** Храните в кэше компактные, сериализованные структуры данных, избегая сохранения "тяжелых" объектов.
* **Негативное кэширование:** Кэшируйте ответы об отсутствии данных (например, HTTP (HyperText Transfer Protocol) 404) на короткое время, чтобы защитить источник от повторных запросов к несуществующим ресурсам.

## Дополнительная информация

Для успешной эксплуатации системы кэширования крайне важен мониторинг. Ключевые метрики для отслеживания:

* `hit ratio` (в среднем и для критичных ключей);
* `latency` (p95/p99) как для попаданий, так и для промахов;
* количество промахов в единицу времени;
* ошибки подключения к серверу кэша.

Кэширование на границе сети (Edge Computing) используется для снижения задержек — см. [обзор Edge Computing](../edge_computing_overview.md).
