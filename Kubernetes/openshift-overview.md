# Обзор Red Hat OpenShift

## Определения

**Red Hat OpenShift** — коммерческий дистрибутив Kubernetes корпоративного уровня от Red Hat (подразделение IBM). Представляет собой платформу класса PaaS (Platform as a Service) с интегрированными инструментами жизненного цикла разработки (DevSecOps), усиленной безопасностью и долгосрочной коммерческой поддержкой. Базируется на RHEL и оптимизирован для гибридных облачных сред.

**OKD (Origin Kubernetes Distribution)** — community-версия OpenShift с открытым исходным кодом. Служит upstream-проектом для всех коммерческих редакций OpenShift, содержит те же технологии, но без официальной поддержки и сертификации Red Hat.

**Версия 4.19 (Июнь 2025):** актуальный релиз, базирующийся на **Kubernetes 1.32** и **CRI-O 1.32**. Основной фокус на интеграции AI-инструментов и продвинутом сетевом взаимодействии.

## Основные концепции

### Ключевые отличия от ванильного Kubernetes

| Параметр | OpenShift | Kubernetes (vanilla) |
| :--- | :--- | :--- |
| **Безопасность** | SCC (Security Context Constraints) — строгие политики по умолчанию; Secrets Store CSI (GA) | PSS (Pod Security Standards) — требует ручной настройки |
| **Среда выполнения (Runtime)** | CRI-O (единственный поддерживаемый) | containerd / CRI-O / Docker (через адаптеры) |
| **Интерфейс командной строки (CLI)** | `oc` — надмножество над `kubectl`; `odo` для разработчиков | `kubectl` — базовое управление ресурсами |
| **Веб-интерфейс (Web UI)** | Полнофункциональная консоль (Admin + Developer Topology) | Требует отдельной установки (Dashboard) |
| **CI/CD и GitOps** | Встроенные OpenShift Pipelines (Tekton) и GitOps (ArgoCD) | Требует самостоятельной интеграции |
| **Виртуализация** | OpenShift Virtualization (KubeVirt) — глубокая интеграция VM | Требует ручной настройки KubeVirt |
| **Сетевой плагин (CNI)** | OVN-Kubernetes (стандарт); Gateway API (GA в 4.19) | Любой совместимый (Calico, Cilium, Flannel) |
| **Обновления** | Over-the-Air (OTA) — автоматизированы через Operators | Ручное или полуавтоматическое обновление |

### Архитектура и ключевые компоненты

- **RHCOS (Red Hat CoreOS)** — специализированная неизменяемая ОС, управляемая кластером. Изменения конфигурации применяются через Machine Config Operator (MCO).
- **OLM (Operator Lifecycle Manager)** — механизм управления жизненным циклом операторов. В 4.19 полностью стабилизирован OLM v1 с декларативным API.
- **Routes и Gateway API** — Routes (на базе HAProxy) остаются стандартом для простых задач, в то время как **Gateway API (GA в 4.19)** предоставляет более гибкое управление трафиком.
- **Image Streams** — абстракция для автоматизации деплоя при обновлении образов в реестре.
- **Hosted Control Planes (HCP)** — возможность запуска Control Plane как нагрузки в другом кластере, что сокращает расходы на инфраструктуру до 30%.
- **OpenShift Lightspeed (GA в 4.19)** — виртуальный помощник на базе Generative AI, интегрированный в консоль для диагностики и помощи в написании YAML.

### Сетевое взаимодействие и безопасность

- **User Defined Networks (UDN):** Позволяет создавать изолированные L2/L3 сегменты для групп приложений или виртуальных машин.
- **Интеграция с BGP:** Нативная поддержка Border Gateway Protocol для анонсирования IP-адресов подов и виртуальных машин во внешнюю сеть ЦОД.
- **Compliance Operator:** Автоматизирует проверку кластера на соответствие стандартам PCI DSS, HIPAA и NIST.
- **Secrets Store CSI Driver:** Позволяет подключать секреты из внешних хранилищ (HashiCorp Vault, Azure Key Vault) без их создания внутри Kubernetes.

### Хранение данных

- **OpenShift Data Foundation (ODF):** Программно-определяемое хранилище на базе Ceph/Rook, интегрированное в консоль управления.
- **Live Migration для хранилищ VM:** Возможность перемещения дисков виртуальных машин между разными Storage Class без остановки работы (GA в 4.18).

### Методы установки кластера

1.  **Installer-Provisioned Infrastructure (IPI):** Полностью автоматизированная установка, где инсталлятор сам создает ресурсы в облаке или виртуализации (AWS, Azure, vSphere).
2.  **User-Provisioned Infrastructure (UPI):** Установка на заранее подготовленную инфраструктуру (Bare Metal, сложные сетевые топологии).
3.  **Agent-Based Installer (ABI):** Гибридный метод для Edge и Bare Metal сред, использующий единый загрузочный образ (ISO) для автоматической настройки узлов.

### Редакции OpenShift

| Редакция | Среда развёртывания и особенности |
| :--- | :--- |
| **OpenShift Container Platform (OCP)** | Основная редакция для On-premise и частных облаков. |
| **OpenShift Virtualization Engine (OVE)** | Специализированная редакция (4.18+) для замены VMware. |
| **Managed Services (ROSA, ARO, OSD)** | Управляемые сервисы в AWS, Azure и Google Cloud с поддержкой SRE Red Hat. |
| **MicroShift** | Сверхлегкий дистрибутив для Edge-устройств с минимальными ресурсами. |

## Требования к ресурсам

OpenShift требует значительных ресурсов для работы встроенных сервисов (мониторинг, логирование, реестр):

- **Control Plane (3 узла):** минимум 4 vCPU / 16 GB RAM на узел.
- **Worker Nodes:** минимум 2 узла (рекомендуется от 3). Для ODF/Virtualization требования возрастают.
- **Дисковая подсистема:** Низкая задержка (low latency) обязательна для etcd. Минимум 100 GB на узел.

## Практические сценарии

### Когда выбирать OpenShift

- **Миграция с VMware:** Использование OpenShift Virtualization как современной альтернативы традиционным гипервизорам.
- **Enterprise-стандарт:** Необходимость в единой платформе с гарантированной поддержкой и соблюдением ИБ-стандартов "из коробки".
- **Ускорение разработки:** Использование S2I (Source-to-Image) и встроенного CI/CD для команд, не имеющих глубокой экспертизы в Kubernetes.

### Ограничения и альтернативы

- **Малые проекты:** Для небольших приложений OpenShift может быть избыточен по стоимости и ресурсам (лучше рассмотреть Managed K8s).
- **Экстремальная кастомизация:** Если требуется замена базовых компонентов (например, замена OVN на специфичный CNI), OpenShift может ограничивать гибкость из-за жесткой связки с операторами.
