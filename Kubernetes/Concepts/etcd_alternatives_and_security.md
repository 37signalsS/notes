# Etcd: альтернативы и безопасность

## Альтернативы etcd: Kine и k3s

**k3s** — облегчённый дистрибутив Kubernetes для тестирования и встроенных сред, где etcd может быть избыточен.

**Kine** (Kine Is Not etcd) — прокладка-совместимости, которая транслирует вызовы API etcd в SQL-запросы. Это позволяет заменить etcd на:

* **SQLite** (по умолчанию в k3s) — ультралёгкая встроенная БД, не требует отдельного управления кластером
* **MySQL** — для production-сред с существующей инфраструктурой
* **PostgreSQL** — аналогично MySQL

### Зачем это нужно

1. **Упрощение:** Не нужно управлять отдельным кластером etcd
2. **Существующая экспертиза:** Команды с опытом администрирования SQL-БД могут использовать свои навыки
3. **Managed-решения:** Можно использовать управляемые БД от облачных провайдеров

### Ограничения Kine

* Производительность и доступность могут быть ниже, чем у etcd
* Модель данных etcd проста (ключ-значение), поэтому перевод в SQL относительно прост, но не оптимален для сложных сценариев

### Пример SQL-запроса Kine

Kine использует единственную таблицу с ключами, значениями и метаданными. Запросы с префиксом переводятся в SQL `LIKE` запросы:

```sql
SELECT (%s), (%s), %s
FROM kine AS kv
JOIN (
  SELECT MAX(mkv.id) AS id
  FROM kine AS mkv
  WHERE mkv.name LIKE ?
  GROUP BY mkv.name
) maxkv ON maxkv.id = kv.id
WHERE (kv.deleted = 0 OR ?)
ORDER BY kv.id ASC
```

## Безопасность и отказоустойчивость

### TLS

TLS является обязательным для защиты трафика как между клиентами и серверами, так и между самими узлами `etcd`.

### Ограничение доступа

* Ограничение доступа по сети
* Использование сертификатов с правильными `CN/OU` для разделения ролей

### Потеря кворума

Потеря кворума требует восстановления кластера из последнего снапшота.

## Шифрование данных на лету (at-rest)

Для защиты секретов в `etcd`, `kube-apiserver` может быть настроен на их шифрование перед записью.

### Конфигурация EncryptionConfiguration

```yaml
# encryption-provider-config.yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
    - secrets
    providers:
    - aescbc:
        keys:
        - name: key1
          secret: <BASE64_ENCODED_SECRET_KEY>
    - identity: {} # Оставляет возможность читать незашифрованные секреты
```

### Пояснение

* **aescbc** — провайдер шифрования AES-CBC
* **keys** — список ключей шифрования (можно указать несколько для ротации)
* **identity** — провайдер без шифрования (для чтения старых данных)
