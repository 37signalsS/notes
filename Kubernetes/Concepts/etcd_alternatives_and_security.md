# etcd: альтернативы и безопасность

## Определения

**Kine** (Kine Is Not etcd) — прослойка совместимости, которая транслирует вызовы **API (Application Programming Interface)** etcd в **SQL (Structured Query Language)** запросы. Позволяет использовать внешние реляционные базы данных вместо etcd.

**k3s** — облегчённый дистрибутив Kubernetes, оптимизированный для тестовых и встроенных сред. По умолчанию использует Kine в связке с SQLite для минимизации потребления ресурсов.

## Основные концепции

### Альтернативы etcd через Kine

Kine позволяет подключать популярные **СУБД (Системы Управления Базами Данных)**:

| СУБД | Сценарий использования |
| :--- | :--- |
| **SQLite** | Одноузловые кластеры, IoT-устройства, локальная разработка. |
| **PostgreSQL** | Высоконагруженные среды при наличии готовой инфраструктуры БД. |
| **MySQL** | Аналогично PostgreSQL, для команд с соответствующей экспертизой. |

**Ограничения решения:**

* Производительность watch-событий ниже, чем в нативном etcd.
* Отсутствие строгих гарантий консенсуса Raft (зависит от настроек внешней БД).
* Повышенная сложность диагностики при возникновении задержек в SQL-запросах.

### Безопасность etcd

**Транспортная безопасность:**
Для защиты данных при передаче обязательно использование **TLS (Transport Layer Security)**. В продуктивных средах применяется **mTLS (mutual Transport Layer Security)** для взаимной аутентификации API-сервера и узлов etcd.

**Шифрование данных (Encryption at Rest):**
Сами данные в etcd хранятся в открытом виде (base64 для секретов). Для их защиты используется механизм `EncryptionConfiguration` на уровне API-сервера. Это предотвращает компрометацию данных при краже физических носителей или снапшотов БД.

## Практические сценарии

### Реализация Watch через SQL

Kine эмулирует механизм watch-событий etcd, выполняя периодические опросы (polling) таблицы `kine`. Пример логики выборки последних изменений:

```sql
SELECT * FROM kine 
WHERE id > ? AND name LIKE ? 
ORDER BY id ASC 
LIMIT 1000;
```

### Восстановление при потере кворума

Если в кластере etcd потеряно большинство узлов (кворум), требуется процедура аварийного восстановления из снапшота. При использовании Kine через внешнюю БД отказоустойчивость обеспечивается средствами самой СУБД (например, репликация PostgreSQL).
