# Etcd: альтернативы и безопасность

## Определения

**Kine** (Kine Is Not etcd) — прокладка совместимости, которая транслирует вызовы API etcd в SQL-запросы. Позволяет заменить etcd на внешнюю базу данных.

**k3s** — облегчённый дистрибутив Kubernetes для тестирования и встроенных сред, где etcd может быть избыточен. По умолчанию использует Kine + SQLite.

## Основные концепции

### Альтернативы etcd через Kine

Kine позволяет использовать следующие СУБД вместо etcd:

| СУБД | Сценарий использования |
| :--- | :--- |
| **SQLite** | Тестовые среды, встроенные решения, не требует отдельного управления |
| **MySQL** | Production-среды с существующей инфраструктурой |
| **PostgreSQL** | Аналогично MySQL, при наличии экспертизы |

**Преимущества замены etcd:**

* **Упрощение:** Не нужно управлять отдельным кластером etcd
* **Существующая экспертиза:** Использование навыков администрирования SQL-БД
* **Managed-решения:** Возможность использования управляемых БД от облачных провайдеров

**Ограничения Kine:**

* Производительность и доступность ниже, чем у etcd
* Модель данных etcd проста (ключ-значение), поэтому перевод в SQL относительно прост, но не оптимален для сложных сценариев

### Безопасность etcd

**Шифрование данных (Encryption at Rest):** Для защиты Secret в etcd используется механизм шифрования на уровне `kube-apiserver` (EncryptionConfiguration). Подробнее: [Хранение Secret в etcd](../Base/secrets/etcd_storage.md).

**TLS и ограничение доступа:**

* TLS обязателен для всего трафика (клиенты ↔ серверы, серверы ↔ серверы)
* Ограничение доступа по сети
* Использование сертификатов с правильными `CN/OU` для разделения ролей

**Потеря кворума:** Восстановление после потери кворума требует процедуры disaster recovery. Подробнее: [Кластеризация и восстановление etcd](../../etcd/clustering_and_recovery.md).

## Практические сценарии

### SQL-запрос Kine

Kine использует единственную таблицу с ключами, значениями и метаданными. Запросы с префиксом переводятся в SQL `LIKE`-запросы:

```sql
SELECT (%s), (%s), %s
FROM kine AS kv
JOIN (
  SELECT MAX(mkv.id) AS id
  FROM kine AS mkv
  WHERE mkv.name LIKE ?
  GROUP BY mkv.name
) maxkv ON maxkv.id = kv.id
WHERE (kv.deleted = 0 OR ?)
ORDER BY kv.id ASC
```

## Дополнительная информация

* **Механизм работы Kine:** Транслирует etcd API (ключ-значение, watch, ревизии) в SQL-запросы, сохраняя семантику etcd на уровне логики приложения, а не СУБД.
