# Мульти-тенантность в Kubernetes

## Определения

**Тенант (tenant)** — это группа пользователей, команда, проект или приложение, которые используют общий кластер Kubernetes, но должны быть изолированы друг от друга.

**Мульти-тенантность (multi-tenancy)** — это модель работы, при которой один Kubernetes-кластер используется несколькими тенантами. Вместо создания отдельных физических или виртуальных кластеров для каждой команды, они разделяют ресурсы одного большого кластера.

## Основные концепции

Основная задача мульти-тенантности — обеспечить надежную **изоляцию** между тенантами на разных уровнях: ресурсы, сеть, безопасность и доступ к API (Application Programming Interface).

### Уровни и инструменты изоляции

1. **Изоляция на уровне API и объектов (Logical Isolation)**
    * **Пространства имён ([`Namespaces`](../Base/namespace.md))**: Основной механизм для логического разделения ресурсов. Объекты (Pods, Services, Deployments) в одном namespace изолированы от объектов в другом по именам.
    * **Права доступа ([`RBAC - Role-Based Access Control`](../Security/rbac/rbac_overview.md))**: Определяют действия пользователей или групп.
        * `Role` и `RoleBinding`: Права в рамках одного Namespace.
        * `ClusterRole` и `ClusterRoleBinding`: Права на уровне всего кластера.

2. **Изоляция ресурсов (Resource Isolation)**
    * **Квоты на ресурсы ([`ResourceQuota`](../Scheduling/qos_limit_and_requests.md))**: Ограничивают потребление CPU, памяти и количество объектов в Namespace.
    * **Диапазоны лимитов (`LimitRange`)**: Задают значения ресурсов по умолчанию для контейнеров.

3. **Сетевая изоляция ([Network Isolation](../Networking/Network/network_overview.md))**
    * **Сетевые политики ([`NetworkPolicy`](../Networking/Network/network_overview.md))**: Контролируют трафик между подами на уровне IP и портов (L3/L4). Требуют поддержки со стороны CNI (Container Network Interface).

4. **Изоляция на уровне выполнения и безопасности (Runtime & Security Isolation)**
    * **Политики безопасности подов ([`Pod Security Admission`](../Security/pod_security_context.md))**: Ограничивают привилегии контейнеров (host network, privileged mode).
    * **Изоляция хранилища**: Использование разных `StorageClass` и изоляция через `PersistentVolumeClaim`.

### Admission Control и политики

**Admission Control** — механизм перехвата запросов к API перед сохранением объектов.
* **Validating Webhook**: Валидация объектов (например, запрет `hostNetwork`). Использование инструментов вроде [Kyverno](../Security/kyverno/policies/practical_scenarios.md).
* **Mutating Webhook**: Автоматическая модификация объектов (например, injection sidecar-контейнеров).

### Управление Node-level ресурсами

Параметры kubelet для защиты узлов:
* `maxPods`: Максимум подов на узле.
* `podPidsLimit`: Защита от PID (Process ID) exhaustion (исчерпания идентификаторов процессов).

## Практические сценарии

### Сценарий 1: Изоляция команд разработки

**Задача:** Разделить 5 команд разработки в одном кластере.

**Решение:**
1. Создать namespace для каждой команды.
2. Настроить RBAC для доступа только к своему namespace.
3. Установить `ResourceQuota`.

```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: team-alpha-quota
  namespace: team-alpha
spec:
  hard:
    requests.cpu: "4"
    requests.memory: 8Gi
    limits.cpu: "8"
    limits.memory: 16Gi
```

### Сценарий 2: Разделение сред (Dev/Staging/Prod)

**Задача:** Запустить среды разработки и продакшена в одном кластере.

**Решение:**
1. Разделение по namespace (`myapp-dev`, `myapp-prod`).
2. Физическая изоляция Prod через `taints` и `tolerations` на выделенных `NodePool`.
3. Строгие политики `PodSecurity` для Prod.

### Сценарий 3: Мультитенантность для SaaS-платформы

**Задача:** Изоляция клиентов SaaS (Software as a Service) платформы.

**Решение:**
1. Namespace на каждого клиента.
2. Полная изоляция трафика через `NetworkPolicy`.
3. Выделенные `StorageClass` для данных клиентов.

## Дополнительная информация

**Преимущества мульти-тенантности:**
* **Эффективное использование ресурсов**: Консолидация нагрузок снижает издержки.
* **Централизованное управление**: Упрощение администрирования одного кластера.
* **Скорость развертывания**: Быстрое получение изолированных окружений.

**Важные принципы:**
1. **Kubernetes не обеспечивает мульти-тенантность "из коробки"** — требуется настройка всех уровней изоляции.
2. **CPU/RAM — не единственные ресурсы** — диск, сеть, PID, Ingress требуют контроля.
3. **Облако — это "чужой компьютер"** — ресурсы разделяются на уровне гипервизора и ЦОД (Центр Обработки Данных).
4. **Мониторинг и квотирование** — залог стабильности "коммунальной квартиры" ресурсов.
