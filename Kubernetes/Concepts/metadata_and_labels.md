# Метаданные, метки и аннотации

## Определения

**Метаданные (Metadata)** — это данные, которые предоставляют информацию о других данных. В Kubernetes каждый объект (Pod, Service, Deployment и т.д.) содержит поле `metadata`, которое используется для его идентификации и организации.

Ключевые поля метаданных:

* `name`: Уникальное имя объекта в пределах одного namespace.
* `namespace`: Пространство имен, в котором находится объект.
* `uid`: Уникальный идентификатор, генерируемый системой для каждого объекта.
* `labels`: Набор пар ключ-значение для организации и выбора объектов.
* `annotations`: Произвольные данные в формате ключ-значение, не предназначенные для идентификации, а для хранения дополнительной информации для инструментов и людей.

## Метки (Labels) и Селекторы (Selectors)

### Метки (Labels)

**Метки** — это пары ключ-значение, которые прикрепляются к объектам Kubernetes. Они предназначены для указания идентифицирующих атрибутов объектов, которые важны и значимы для пользователей.

**Назначение:**

* **Группировка:** Объекты можно организовывать по меткам (например, все поды одного приложения или компоненты одного окружения).
* **Выборка (Selection):** API-клиенты и контроллеры (как, например, Service или ReplicaSet) используют метки для выбора набора объектов, с которыми они должны работать.

**Пример:**

```yaml
metadata:
  labels:
    environment: production
    app: nginx
```

В отличие от имен и UID, метки не обязаны быть уникальными. Один объект может иметь несколько меток, и одна и та же метка может быть у множества объектов.

### Селекторы (Selectors)

**Селектор** — это способ фильтрации и выбора объектов Kubernetes на основе их меток. Селекторы являются ядром механизма группировки в Kubernetes.

API Kubernetes поддерживает два типа селекторов:

1. **На основе равенства (Equality-based):** Фильтрует по точному совпадению ключа и значения.
    * `key=value` (равно)
    * `key!=value` (не равно)
    * Можно использовать несколько выражений через запятую (логическое "И"): `app=nginx,tier=frontend`.
2. **На основе множеств (Set-based):** Фильтрует по набору значений для одного ключа.
    * `key in (value1, value2)` (ключ имеет одно из перечисленных значений)
    * `key notin (value1, value2)`
    * `exists key` (у объекта есть метка с указанным ключом, независимо от значения)

**Пример использования в Service:**

```yaml
spec:
  selector:
    app.kubernetes.io/name: my-app # Селектор на основе равенства
```

Этот Service будет направлять трафик на все поды, у которых есть метка `app.kubernetes.io/name` со значением `my-app`.

## Рекомендуемые метки (Recommended Labels)

Kubernetes предлагает [стандартный набор меток](https://kubernetes.io/docs/concepts/overview/working-with-objects/common-labels/) для упрощения управления приложениями. Использование этих меток позволяет инструментам, таким как Helm или `kubectl`, работать согласованно.

Основные рекомендуемые метки:

| Ключ метки                     | Описание                                                            | Пример                 |
| ------------------------------ | ------------------------------------------------------------------- | ---------------------- |
| `app.kubernetes.io/name`       | Имя приложения.                                                     | `mysql`                |
| `app.kubernetes.io/instance`   | Уникальное имя экземпляра приложения.                               | `mysql-abcxzy`         |
| `app.kubernetes.io/version`    | Текущая версия приложения.                                          | `5.7.21`               |
| `app.kubernetes.io/component`  | Компонент в рамках архитектуры приложения.                          | `database`             |
| `app.kubernetes.io/part-of`    | Имя приложения более высокого уровня, частью которого является этот компонент. | `wordpress`            |
| `app.kubernetes.io/managed-by` | Инструмент, используемый для управления приложением.                 | `helm`                 |

Использование этих меток не является обязательным, но считается хорошей практикой.

## Аннотации (Annotations)

**Аннотации** — это тоже пары ключ-значение, но в отличие от меток, они не используются для идентификации и выбора объектов.

**Назначение:**

* Хранение произвольных, неидентифицирующих метаданных.
* Информация для инструментов, контроллеров или операторов: описание сборки, ссылка на тикет в баг-трекере, контактные данные ответственного лица и т.д.
* Управление поведением контроллеров (например, аннотации `cert-manager.io/cluster-issuer` для Ingress).

**Пример:**

```yaml
metadata:
  annotations:
    description: "Nginx deployment for the main website"
    prometheus.io/scrape: "true"
    prometheus.io/port: "9113"
```

В этом примере аннотация `description` предназначена для человека, а аннотации `prometheus.io/scrape` и `prometheus.io/port` являются инструкциями для Prometheus Operator.
