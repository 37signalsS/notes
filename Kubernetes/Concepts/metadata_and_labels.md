# Метаданные, метки и аннотации в Kubernetes

## Определения

**Метаданные (Metadata)** — данные, предоставляющие информацию о других данных. В Kubernetes каждый объект содержит поле `metadata` для идентификации и организации.

Ключевые поля метаданных:
* **`name`**: уникальное имя объекта в рамках одного **Namespace** (пространство имен).
* **`namespace`**: логическое пространство имен, в котором находится объект.
* **`uid` (Universal Unique Identifier)**: уникальный идентификатор, генерируемый системой для каждого объекта.
* **`labels`**: набор пар "ключ-значение" для организации и выбора объектов.
* **`annotations`**: произвольные данные для хранения дополнительной информации, не используемой для идентификации.

## Основные концепции

### Метки (Labels)

**Метки** — это пары "ключ-значение", прикрепляемые к объектам. Они предназначены для указания идентифицирующих атрибутов, значимых для пользователей.

**Назначение:**
* **Группировка:** организация объектов по логическим признакам (например, `environment: production`).
* **Выборка (Selection):** API (Application Programming Interface) клиенты и контроллеры используют метки для фильтрации объектов.

Метки не обязаны быть уникальными: один объект может иметь несколько меток, а одна метка может быть у множества объектов.

### Селекторы (Selectors)

**Селектор** — механизм фильтрации и выбора объектов на основе их меток. Является ядром группировки в Kubernetes.

Типы селекторов:
1. **На основе равенства (Equality-based):** фильтрация по точному совпадению.
    * `key=value` (равно).
    * `key!=value` (не равно).
    * Можно указывать несколько условий через запятую (логическое "И").
2. **На основе множеств (Set-based):** фильтрация по набору значений.
    * `key in (value1, value2)` (ключ соответствует одному из значений).
    * `key notin (value1, value2)`.
    * `exists key` (наличие ключа у объекта).

### Рекомендуемые метки (Recommended Labels)

Kubernetes предлагает стандартный набор меток для согласованной работы инструментов (например, **Helm** или `kubectl`).

| Ключ метки | Описание |
| :--- | :--- |
| `app.kubernetes.io/name` | Имя приложения |
| `app.kubernetes.io/instance` | Уникальное имя экземпляра приложения |
| `app.kubernetes.io/version` | Текущая версия приложения |
| `app.kubernetes.io/component` | Компонент архитектуры (например, `database`) |
| `app.kubernetes.io/part-of` | Имя родительского приложения |
| `app.kubernetes.io/managed-by` | Инструмент управления (например, `helm`) |

### Аннотации (Annotations)

**Аннотации** — пары "ключ-значение", используемые для хранения неидентифицирующих метаданных. В отличие от меток, они не используются селекторами.

**Назначение:**
* Хранение вспомогательной информации для инструментов, контроллеров или людей (описание сборки, ссылки на тикеты).
* Управление поведением контроллеров (например, конфигурация **Ingress** через аннотации).

### Синтаксис и ограничения

* **Ключ:** формат `<prefix>/<name>` (префикс опционален).
  * **Префикс:** допустимый **DNS (Domain Name System)** поддомен, макс. 253 символа. Зарезервированы: `kubernetes.io/`, `k8s.io/`.
  * **Имя:** макс. 63 символа, начинается и заканчивается на букву или цифру.
* **Значение:** макс. 63 символа, должно быть строкой (например, `"true"`, а не `true`).

## Практические сценарии

### Управление через CLI

Для работы с метками используется **CLI (Command Line Interface)** инструмент `kubectl`.

```bash
# Просмотр меток объекта
kubectl get <resource> <name> --show-labels

# Добавление или изменение метки
kubectl label <resource> <name> environment=production --overwrite

# Удаление метки (указывается ключ с минусом в конце)
kubectl label <resource> <name> environment-

# Выбор объектов по селектору
kubectl get pods -l 'app=nginx,environment=production'
```

### Примеры использования

1. **Планирование подов:** использование `nodeSelector` для размещения подов на узлах с определенными метками.
2. **Сетевые политики:** ограничение трафика между подами на основе меток в **NetworkPolicy**.
3. **Мониторинг:** аннотации для **Prometheus** (например, `prometheus.io/scrape: "true"`) указывают на необходимость сбора метрик.

## Дополнительная информация

### Рекомендации (Best Practices)

* Стандартизируйте соглашения об именовании меток между командами.
* Используйте рекомендованные префиксы `app.kubernetes.io/*`.
* Не храните чувствительные данные (пароли, ключи) в метках или аннотациях, так как они доступны в открытом виде через API.
* Автоматизируйте проставление меток через **CI/CD (Continuous Integration / Continuous Deployment)** пайплайны.
