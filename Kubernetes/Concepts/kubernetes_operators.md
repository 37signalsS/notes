# Kubernetes-операторы: автоматизация управления приложениями

## Определения

**Kubernetes-оператор** — это доменно-специфический [контроллер](./control_plane_architecture.md), который расширяет **API (Application Programming Interface)** Kubernetes для создания, настройки и управления жизненным циклом сложных приложений с сохранением состояния (stateful) от имени пользователя. Он инкапсулирует операционные знания в программный код.

**Custom Resource Definitions (CRD)** — механизм Kubernetes для расширения API. Подробнее: [CRD](./kubernetes_crd.md).

## Основные концепции

Операторы решают проблему управления приложениями, которые требуют специфических действий (резервное копирование, восстановление, обновления, кластеризация), выходящих за рамки стандартных контроллеров.

### Принципы операторского паттерна

* **Декларативность:** пользователь описывает желаемое состояние в **CR (Custom Resource)**, а не последовательность действий.
* **Контур управления (Reconciliation Loop):** постоянное наблюдение за текущим состоянием и приведение его к желаемому.
* **Идемпотентность:** каждый цикл согласования безопасен при повторах и не вызывает побочных эффектов, если система уже в нужном состоянии.

### Составные части и механизмы

* **Контроллер:** процесс, реализующий логику согласования на базе библиотеки `controller-runtime`.
* **RBAC (Role-Based Access Control):** права доступа для управления ресурсами.
* **Лидер-элекция:** механизм, гарантирующий активность только одной реплики оператора для отказоустойчивости.
* **Informer и Cache:** механизмы эффективного получения событий от API-сервера и хранения состояния в памяти.
* **Reconcile:** центральная функция, которая сравнивает `spec` (желаемое) и `status` (фактическое) и выполняет действия.

### Модель зрелости операторов

1. **L1 (Basic Install):** автоматизация установки.
2. **L2 (Seamless Upgrades):** управление обновлениями.
3. **L3 (Full Lifecycle):** резервное копирование и восстановление.
4. **L4 (Deep Insights):** продвинутый мониторинг и аналитика.
5. **L5 (Autopilot):** автоматическое масштабирование и самовосстановление.

## Практические сценарии

### Сравнение подходов к управлению

| Критерий | Стандартные контроллеры (Deployment) | Operator |
| :--- | :--- | :--- |
| **Жизненный цикл** | Только управление подами | Полный цикл: конфиг, миграции, бэкапы |
| **Реакция на события** | Ограничена уровнем объекта | Доменная логика и постоянный цикл |
| **Состояние** | Низкоуровневые проверки | Доменные статусы и проверки готовности |

### Пример Custom Resource

Описание кластера базы данных для оператора:

```yaml
apiVersion: db.example.com/v1
kind: PostgresCluster
metadata:
  name: prod-db
spec:
  version: "15.3"
  instances: 3
  storage:
    size: 200Gi
    className: fast-ssd
  backup:
    enabled: true
    schedule: "0 */6 * * *"
```

## Дополнительная информация

* **Инструменты разработки:**
    * [Kubebuilder](https://book.kubebuilder.io/) — фреймворк для создания операторов на Go.
    * [Operator SDK](https://sdk.operatorframework.io/) — поддержка Go, Ansible и Helm.
* **Популярные операторы:**
    * **Prometheus Operator** — автоматизация мониторинга.
    * **Cert Manager** — управление **SSL/TLS (Secure Sockets Layer / Transport Layer Security)** сертификатами.
    * **Cloud Native PostgreSQL (CNPG)** — управление кластерами PostgreSQL.
* **[Архитектура Control Plane](./control_plane_architecture.md)** — основы работы контроллеров.
