# Pod Terminating — основные определения и механизмы

## Определения

**`Terminating` (Состояние завершения)** — статус Pod, отображаемый в CLI, который указывает на то, что объект получил `deletionTimestamp`, но ещё не был полностью удалён из API-сервера. Технически Pod может оставаться в фазе `Running` или `Unknown`, пока процесс завершения не будет подтверждён `kubelet`.

**`deletionTimestamp`** — временная метка, устанавливаемая в метаданных объекта при получении команды на удаление. Её наличие переводит Pod в режим «корректного завершения» (graceful shutdown) и блокирует его выборку сервисами (Service) и контроллерами.

**`terminationGracePeriodSeconds`** — время (по умолчанию 30 секунд), выделяемое поду на самозавершение. Отсчёт начинается сразу после установки `deletionTimestamp`.

**`PreStop Hook`** — специальная команда или HTTP-запрос, выполняемый `kubelet` непосредственно перед отправкой сигнала `SIGTERM`. Используется для завершения транзакций или уведомления внешних систем.

**`SIGTERM` (Signal Termination)** — стандартный сигнал POSIX, отправляемый основному процессу (PID 1) в каждом контейнере для инициации корректной остановки.

**`SIGKILL` (Signal Kill)** — принудительный сигнал завершения, отправляемый процессам, если они не завершились по истечении `terminationGracePeriodSeconds`. Не может быть перехвачен процессом.

**Финализатор (Finalizer)** — строка в `metadata.finalizers`, которая сообщает Kubernetes, что объект нельзя удалять из базы данных `etcd` до тех пор, пока не будут выполнены специфические условия (например, отмонтирование диска или очистка ресурсов в облаке).

**Терминальная фаза (Terminal Phase)** — состояние, при котором Pod достиг конечного статуса (`Succeeded` или `Failed`). Начиная с Kubernetes 1.29+, `kubelet` гарантированно переводит поды в терминальную фазу перед удалением, что важно для корректной работы Job и Sidecar-контейнеров.

**Принудительное удаление (Force Deletion)** — удаление объекта из API без ожидания подтверждения от `kubelet`. Выполняется командой `kubectl delete pod --force --grace-period=0`. Рискованно при использовании `StatefulSet`.

## Базовые концепции

### Процесс удаления Pod

```
Пользователь/Контроллер → kubectl delete pod
    ↓
API устанавливает metadata.deletionTimestamp
    ↓
EndpointSlice/Service → Pod исключается из трафика
    ↓
Kubelet на узле получает уведомление
    ↓
Исполнение PreStop hook (если настроен)
    ↓
Отправка SIGTERM основному процессу (PID 1)
    ↓
[Ожидание завершения или истечение terminationGracePeriodSeconds]
    ↓
Отправка SIGKILL (если процессы всё ещё активны)
    ↓
Размонтирование томов (Volumes) и очистка сетевых ресурсов
    ↓
Kubelet сообщает API о переводе в фазу Succeeded/Failed
    ↓
Снятие системных финализаторов
    ↓
Удаление объекта из etcd
```

Подробное описание процесса: [Graceful Shutdown](./graceful_shutdown.md).

### Стандартные финализаторы (Finalizers)

| Финализатор | Назначение |
| :--- | :--- |
| `kubernetes.io/pod-protection` | Гарантирует, что Pod не будет удалён из API до подтверждения от Kubelet. |
| `node.kubernetes.io/out-of-service` | (K8s 1.24+) Позволяет принудительно удалить Pod с недоступного узла после наложения taints. |
| `external-attacher/<csi-driver>` | Ожидает, пока CSI-контроллер подтвердит отсоединение тома от узла. |
| `kubernetes.io/pvc-protection` | Предотвращает удаление PVC, если он используется активным подом. |

Проверка финализаторов: `kubectl get pod <name> -o jsonpath='{.metadata.finalizers}'`

### Основные причины зависания в состоянии Terminating

| Категория | Причина | Описание |
| :--- | :--- | :--- |
| **Инфраструктура** | **Проблемы CSI/Томов** | Том не может быть отмонтирован из-за блокировки на уровне ОС или ошибки облачного провайдера. |
| **Узел** | **Node NotReady/Lost** | Kubelet не выходит на связь и не может подтвердить удаление контейнеров. |
| **Приложение** | **Игнорирование SIGTERM** | Приложение (или PID 1) не обрабатывает сигнал и ждёт SIGKILL, либо зависло в бесконечном цикле. |
| **Сеть** | **Zombies/Stuck Mounts** | Процессы в состоянии `D` (uninterruptible sleep) блокируют завершение контейнера. |
| **Политики** | **Блокировка через PDB** | PodDisruptionBudget запрещает удаление, если оно нарушает минимальный порог доступности. |

## Практические сценарии

### Быстрая диагностика зависшего пода

```bash
# 1. Проверка наличия deletionTimestamp и фазы
kubectl get pod <pod-name> -o jsonpath='{.metadata.deletionTimestamp} {.status.phase}'

# 2. Поиск зависших финализаторов
kubectl get pod <pod-name> -o jsonpath='{.metadata.finalizers}'

# 3. Анализ событий (Events) для выявления ошибок CSI или Kubelet
kubectl describe pod <pod-name> | grep -A 10 Events

# 4. Проверка состояния узла, на котором запущен Pod
kubectl get node $(kubectl get pod <pod-name> -o jsonpath='{.spec.nodeName}')
```

### Принудительное завершение на выключенном узле

Если узел окончательно вышел из строя (Non-graceful node shutdown), используйте механизм `out-of-service` (для K8s 1.24+):

```bash
# 1. Пометить узел как окончательно недоступный
kubectl taint nodes <node-name> node.kubernetes.io/out-of-service=NoExecute:NoExecute

# 2. Дождаться автоматического удаления подов (финализатор снимется контроллером)
```

## Дополнительная информация

### Сборщик мусора подов (Pod Garbage Collector)

**Pod Garbage Collector (Pod GC)** — контроллер в `kube-controller-manager`, который очищает завершённые объекты, чтобы они не перегружали `etcd`.

**Типы очистки:**
1. **По количеству:** Удаляет старые завершённые поды (фазы `Succeeded`/`Failed`), если их число превышает `--terminated-pod-gc-threshold` (по умолчанию 12500).
2. **Бесхозные поды:** Удаляет поды, привязанные к несуществующим узлам.
3. **Зависшие поды:** Пытается очистить поды в состоянии `Terminating`, если узел был удалён или находится в специфическом состоянии ошибки.

**Важно:** Если Pod завис в `Terminating` из-за финализатора, Pod GC не удалит его принудительно, так как это нарушило бы гарантии безопасности данных (например, риск одновременной записи в один том с двух узлов).
