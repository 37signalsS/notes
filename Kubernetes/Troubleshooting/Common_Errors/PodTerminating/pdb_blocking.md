# Pod Terminating — блокировка через PDB

## Определения

**Блокировка удаления через PDB** — состояние, возникающее при использовании Eviction API (например, при выполнении `kubectl drain`), когда API-сервер отклоняет запрос на удаление пода, так как это приведет к падению количества доступных реплик ниже порога, установленного в Pod Disruption Budget.

**Eviction API** — программный интерфейс, предназначенный для «мягкого» удаления подов с учетом политик доступности. В отличие от стандартного `DELETE`, запрос на Eviction возвращает ошибку `429 Too Many Requests`, если бюджет PDB нарушен.

**Добровольные прерывания (Voluntary Disruptions)** — плановые действия по удалению подов (слив узла, масштабирование вниз, обновление конфигурации), которые регулируются механизмами PDB.

**Недобровольные прерывания (Involuntary Disruptions)** — непредвиденные события (отказ оборудования, kernel panic, сетевой раздел), которые PDB предотвратить не может.

---

## Базовые концепции

### Механизм блокировки

PDB защищает приложение только от тех действий, которые используют Eviction API. Если пользователь выполняет `kubectl delete pod`, бюджет PDB игнорируется, и под удаляется немедленно.

Блокировка обычно проявляется в следующих сценариях:
1.  **Обслуживание узлов**: Команда `kubectl drain` зависает, ожидая удаления пода.
2.  **Cluster Autoscaler**: Автоскейлер не может освободить узел, так как PDB запрещает выселение последнего пода.
3.  **Descheduler**: Инструмент балансировки нагрузки не может переместить поды между узлами.

### Политика выселения нездоровых подов (K8s 1.27+)

Начиная с Kubernetes 1.27 (бета в 1.26), появилось поле `spec.unhealthyPodEvictionPolicy`. Оно определяет, как PDB обрабатывает поды, которые не находятся в состоянии `Ready`:
- `IfHealthyBudget` (по умолчанию): Нездоровые поды могут быть выселены, только если бюджет позволяет (сохраняется `minAvailable`).
- `AlwaysAllow`: Нездоровые поды выселяются всегда, даже если бюджет нарушен. Это критично для приложений, которые «застряли» в нездоровом состоянии и блокируют обслуживание узлов.

## Практические сценарии

### Диагностика блокировки выселения

#### Этап 1: Идентификация блокирующего бюджета

Если `kubectl drain` выдаёт ошибку `Cannot evict pod`, найдите соответствующий PDB:

```bash
# Просмотр всех PDB в текущем пространстве имен
kubectl get pdb

# Анализ конкретного бюджета
kubectl describe pdb <pdb-name>
```

#### Этап 2: Проверка метрик доступности

Изучите вывод `kubectl get pdb`:

```text
NAME      MIN AVAILABLE   MAX UNAVAILABLE   ALLOWED DISRUPTIONS   AGE
web-app   2               N/A               0                     15d
```

Если `ALLOWED DISRUPTIONS` равен `0`, выселение заблокировано.

### Методы разрешения ситуации

#### Вариант 1: Увеличение количества реплик

Самый безопасный способ. Добавление новой реплики позволит «освободить» бюджет для удаления старой:

```bash
kubectl scale deployment <deployment-name> --replicas=<current+1>
```

#### Вариант 2: Изменение параметров PDB

Если вы уверены, что кратковременное снижение доступности допустимо:

```bash
# Временное разрешение одного прерывания через maxUnavailable
kubectl patch pdb <pdb-name> -p '{"spec":{"maxUnavailable":1}}' --type=merge

# Или через уменьшение minAvailable
kubectl patch pdb <pdb-name> -p '{"spec":{"minAvailable":0}}' --type=merge
```

#### Вариант 3: Обход через прямое удаление

Команда `delete` не проверяет PDB. Если процесс `drain` застрял, удалите под вручную в другом терминале:

```bash
kubectl delete pod <pod-name> --grace-period=30
```

*Риск:* Это может привести к нарушению SLA и кратковременной недоступности сервиса.

#### Вариант 4: Использование UnhealthyPodEvictionPolicy (для новых кластеров)

Если проблема вызвана тем, что поды уже «лежат» и блокируют бюджет, обновите PDB (K8s 1.27+):

```yaml
spec:
  unhealthyPodEvictionPolicy: AlwaysAllow
  minAvailable: 1
  selector:
    matchLabels:
      app: web
```

## Дополнительная информация

### Типовые ошибки конфигурации PDB

- **`minAvailable: 100%`**: Блокирует любые прерывания, даже если запущено 10 реплик. Лучше использовать конкретное число.
- **`maxUnavailable: 0`**: Полная блокировка выселения. Часто используется ошибочно вместо `maxUnavailable: 1`.
- **Селектор не совпадает**: PDB создан, но не «видит» поды из-за опечатки в лейблах. Проверяйте поле `CURRENT` в `kubectl get pdb`.
