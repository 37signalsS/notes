# Pod Evicted: Определения и концепции

## Определения

**`Evicted` (Выселен)** — конечное состояние (phase: Failed) пода, означающее, что Kubernetes принудительно завершил его работу на узле. Выселение инициируется компонентом `kubelet` для защиты стабильности узла или через API для планового обслуживания.

**Менеджер выселения (Eviction Manager)** — внутренний модуль `kubelet`, который непрерывно отслеживает использование системных ресурсов (память, диск, PID) и сравнивает их с установленными порогами (**eviction thresholds**).

**Порог выселения (Eviction Threshold)** — правило, определяющее условие, при котором `kubelet` должен начать освобождение ресурсов. Состоит из названия ресурса, оператора сравнения и значения (например, `memory.available < 10%`).

## Основные концепции

### Типы выселения (eviction)

| Тип | Инициатор | Механизм | Примеры |
|:---|:---|:---|:---|
| **Node-Pressure** | `kubelet` | Автоматический | Нехватка RAM, переполнение диска |
| **API-Initiated** | Пользователь / Контроллер | `Eviction API` | `kubectl drain`, работа `Descheduler` |
| **Taint-Based** | `Control Plane` | Контроллер узлов | Реакция на `NoExecute` taint при сбое узла |

### Жесткое (Hard) и Мягкое (Soft) выселение

Kubelet поддерживает два режима реакции на дефицит ресурсов:

1. **Hard Eviction (`eviction-hard`)**:
   - Срабатывает мгновенно при достижении порога.
   - Под завершается сразу (сигнал `SIGKILL` после короткого ожидания).
   - `terminationGracePeriodSeconds` пода **игнорируется**.
2. **Soft Eviction (`eviction-soft`)**:
   - Требует удержания порога в течение времени `eviction-soft-grace-period`.
   - Поду дается время на корректное завершение (`SIGTERM`).
   - Если дефицит ресурсов критический, мягкое выселение может быть проигнорировано в пользу жесткого.

### Различия между Eviction и Preemption

Эти термины часто путают, но они относятся к разным механизмам кластера:

| Характеристика | Eviction (Выселение) | Preemption (Вытеснение) |
|:---|:---|:---|
| **Кто инициирует** | `kubelet` (агент на узле) | `kube-scheduler` (планировщик) |
| **Причина** | **Дефицит ресурсов** на живом узле | **Нехватка места** для запуска нового пода |
| **Цель** | Спасти узел от краша/зависания | Запустить высокоприоритетный под |
| **Приоритет** | На основе классов **QoS** | На основе **PriorityClass** |

> Подробнее о вытеснении: **[Приоритеты подов (PriorityClass)](../../../Concepts/priorityclass.md)**.

### Классификация давлений на узле (Node Conditions)

При достижении порогов выселения узел переходит в соответствующие состояния:

- **`MemoryPressure`**: Доступная память узла ниже порога.
- **`DiskPressure`**: Свободное место на диске или количество `inode` ниже порога.
- **`PIDPressure`**: Количество доступных идентификаторов процессов исчерпано (предотвращает fork-бомбы).

```bash
kubectl describe node <node-name>
# → Conditions:
# → Type             Status  Reason
# → MemoryPressure   False   KubeletHasSufficientMemory
# → DiskPressure     True    KubeletHasDiskPressure
```

## Визуализация статуса выселенного пода

Когда под выселен, его статус в API содержит причину и подробное сообщение.

```bash
kubectl get pod <pod-name> -o jsonpath='{.status.reason}: {.status.message}'
# → Evicted: The node was low on resource: memory. Container app was using 1024Ki, which is over its request of 0.
```

| Поле в YAML | Значение | Описание |
|:---|:---|:---|
| `status.phase` | `Failed` | Под завершен и не будет перезапущен на этом узле |
| `status.reason` | `Evicted` | Основная причина завершения |
| `status.message` | (текст) | Детали: какой ресурс был в дефиците и порог срабатывания |

## Дополнительная информация

### Сравнение Eviction и OOMKilled

| Признак | Eviction | OOMKilled |
|:---|:---|:---|
| **Виновник** | `kubelet` | Ядро Linux |
| **Объект** | Весь под | Конкретный контейнер |
| **Логика** | Предиктивная (до краша ОС) | Реактивная (память уже кончилась) |
| **Сигнал** | SIGTERM/SIGKILL | SIGKILL (мгновенно) |
