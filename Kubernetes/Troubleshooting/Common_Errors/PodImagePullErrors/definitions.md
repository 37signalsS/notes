# Ошибки загрузки образов (Image Pull Errors): Определения

## Определения

**`ErrImagePull`** — начальная фазовая ошибка, означающая, что агент `kubelet` не смог успешно завершить операцию `PullImage` через интерфейс CRI (Container Runtime Interface). Это состояние возникает при первой неудачной попытке получения образа.

**`ImagePullBackOff`** — состояние ожидания (waiting state) контейнера, в которое он переходит после повторных неудачных попыток загрузки. В этом состоянии Kubernetes временно прекращает попытки скачивания, чтобы избежать избыточной нагрузки на реестр и сеть.

**Экспоненциальная задержка (Backoff):** алгоритм, при котором время ожидания между попытками увеличивается: 10s → 20s → 40s → 80s → 160s → 300s. Максимальная задержка составляет 5 минут (300 секунд).

**`kubelet`** — основной агент узла, который взаимодействует с Container Runtime для управления жизненным циклом образов. Он инициирует запросы на скачивание и сообщает о статусе выполнения в Control Plane.

**CRI (Container Runtime Interface)** — стандартный интерфейс взаимодействия `kubelet` с рантаймами контейнеров (например, `containerd`, `CRI-O`). Ошибки загрузки часто транслируются из CRI в события Kubernetes.

**Container Registry (Реестр образов)** — внешняя или внутренняя служба (Docker Hub, Harbor, Nexus, GCR/ECR), хранящая манифесты и слои образов.

**Image Digest (SHA256)** — уникальный неизменяемый идентификатор содержимого образа. Использование digest (например, `image@sha256:...`) гарантирует, что будет скачана именно та версия, которая была протестирована, исключая проблемы "плавающих" тегов.

**`imagePullSecret`** — объект типа `Secret` (обычно `kubernetes.io/dockerconfigjson`), содержащий учетные данные для авторизации в приватных реестрах.

**`AlwaysPullImages`** — Admission Controller в Kubernetes, который может принудительно изменять `imagePullPolicy` всех подов на `Always`. Это используется в многопользовательских средах для обеспечения безопасности.

## Основные концепции

### Жизненный цикл загрузки образа

Процесс инициируется при создании пода или обновлении образа в спецификации:

1. **Планирование:** Pod назначается на узел.
2. **Запрос:** `kubelet` проверяет наличие образа в локальном хранилище (кэше) рантайма (например, `/var/lib/containerd`).
3. **Решение:**
   - Если образ найден и политика позволяет — переход к запуску.
   - Если образа нет или политика требует обновления — запрос в Registry.
4. **Аутентификация:** Проверка наличия и валидности `imagePullSecrets`.
5. **Скачивание:** Загрузка манифеста и недостающих слоев (layers). Слои кэшируются и могут использоваться повторно другими образами.
6. **Распаковка:** Рантайм распаковывает слои в файловую систему снимков (snapshots).

### Переход ErrImagePull → ImagePullBackOff

Это каскадный процесс, отражающий нарастание проблемы:

1. **Первая попытка:** Ошибка → статус контейнера `ErrImagePull`.
2. **Вторая попытка:** Ожидание 10с → Ошибка → статус `ImagePullBackOff`.
3. **Последующие попытки:** Ожидание увеличивается (x2) до 300с. Статус остается `ImagePullBackOff`, но в событиях (Events) фиксируются новые ошибки `ErrImagePull`.

### Классификация ошибок по уровню возникновения

| Уровень | Типовые сообщения | Возможная причина |
| :--- | :--- | :--- |
| **Реестр (Registry)** | `manifest unknown`, `404 Not Found` | Неверное имя образа или тег. Образ удален. |
| **Авторизация** | `unauthorized`, `access denied` | Ошибка в `imagePullSecret`, отсутствие прав, истёк токен. |
| **Инфраструктура** | `connection timed out`, `no such host` | Проблемы DNS, отсутствие маршрута к реестру, Proxy. |
| **Ресурсы узла** | `no space left on device` | Переполнение диска `/var/lib/containerd` или `/var/lib/docker`. |
| **Runtime (CRI)** | `rpc error: code = Unknown ...` | Внутренняя ошибка `containerd` или несовместимость версий. |

### Политики загрузки образов (imagePullPolicy)

Политика определяет, когда `kubelet` должен обращаться к реестру:

| Политика | Поведение | Применение |
| :--- | :--- | :--- |
| **`Always`** | Всегда проверяет digest в реестре перед запуском. | Рекомендуется для безопасности и тега `:latest`. |
| **`IfNotPresent`** | Скачивает только если образа нет на узле. | По умолчанию для конкретных версий (теги кроме `:latest`). |
| **`Never`** | Никогда не скачивает; использует только локальный кэш. | Air-gapped среды или локальная разработка. |

**Важно:** Если образ указан по SHA256 digest, `IfNotPresent` работает максимально эффективно, так как digest гарантирует идентичность.

### Уровни настройки imagePullSecrets

Существует три способа предоставить учетные данные для загрузки образа:

1. **Спецификация Pod (`spec.imagePullSecrets`):** Явное указание в манифесте. Самый распространенный способ.
2. **ServiceAccount:** Привязка секрета к ServiceAccount. Все поды, использующие этот SA, автоматически получают доступ к секрету.
3. **Конфигурация узла (Node-level):** Настройка `config.json` (Docker) или конфигурации `containerd` на уровне ОС узла. Позволяет подам скачивать образы без указания секретов в K8s.

### Ограничения публичных реестров (Rate limiting)

Современные публичные реестры ограничивают количество анонимных загрузок для предотвращения злоупотреблений. При превышении лимитов возникает ошибка `429 Too Many Requests`.

- **Docker Hub:** Ограничения зависят от типа аккаунта (анонимный vs авторизованный).
- **Решение:** Использование `imagePullSecret` даже для бесплатных аккаунтов или настройка локальных зеркал (Pull-through Cache).

## Практические сценарии

### Сценарий 1: Проверка статуса через kubectl

Определение того, в какой фазе находится загрузка, по выводу статуса:

```bash
# Проверка общего состояния
kubectl get pods

# Результат может быть:
# NAME    READY   STATUS             RESTARTS   AGE
# my-app  0/1     ImagePullBackOff   0          5m
```

### Сценарий 2: Детализация ошибки в событиях

Использование `describe` для понимания конкретной причины `ErrImagePull`:

```bash
kubectl describe pod <pod-name>
```

**Анализ раздела Events:**
- `Failed to pull image "..."`: указывает на то, что именно не удалось скачать.
- `rpc error: code = NotFound`: подтверждает проблему с манифестом или тегом в реестре.
