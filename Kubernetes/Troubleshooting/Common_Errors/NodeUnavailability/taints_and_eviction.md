# Недоступность узла: Taints и выселение

Механизм **Taint-based Eviction** является основным способом автоматического восстановления доступности приложений при отказах инфраструктуры. Kubernetes использует метки («отравления») узлов для идентификации проблем и принятия решения о переносе нагрузки.

## Основные определения

**Taints (отравления)** — свойства узла, которые позволяют ему «отталкивать» поды. При недоступности узла система накладывает taints с эффектом `NoExecute`, что инициирует удаление подов.

**Toleration (терпимость)** — параметр спецификации пода (`spec.tolerations`), позволяющий ему игнорировать конкретные taints.

**TolerationSeconds** — период времени (в секундах), в течение которого под может оставаться на узле с эффектом `NoExecute` после появления соответствующего taint.

**DisruptionTarget (Stable в 1.31)** — условие (Condition) пода, указывающее на то, что он был выбран для удаления в результате добровольного или вынужденного прерывания.

## Основные концепции

### Автоматические Taints при сбоях

Контроллер жизненного цикла узлов (`node-controller`) автоматически накладывает следующие метки:

| Taint | Триггер (Condition) | Описание |
| :--- | :--- | :--- |
| **`node.kubernetes.io/unreachable`** | `Ready=Unknown` | Узел перестал отвечать (тайм-аут Lease API). |
| **`node.kubernetes.io/not-ready`** | `Ready=False` | Kubelet сообщает о неисправности узла. |

### Таймлайн жизненного цикла выселения

Процесс переноса нагрузки при потере связи с узлом следует строгому графику:

1.  **Обнаружение (40с)**: Контроллер ждет время `node-monitor-grace-period`. Если обновлений статуса нет, узел переходит в `Unknown`.
2.  **Маркировка**: На узел накладывается taint `unreachable:NoExecute`.
3.  **Ожидание (300с)**: Запускается отсчет `tolerationSeconds`. По умолчанию Kubernetes автоматически добавляет всем подам толерантность к `unreachable` и `not-ready` на **5 минут**.
4.  **Удаление**: По истечении таймера API-сервер помечает объект Pod как удаленный.
5.  **Планирование**: Планировщик видит дефицит реплик и назначает новые поды на здоровые узлы.

## Практические сценарии

### Сценарий 1: Настройка устойчивости к сетевым «морганиям»

Для критических приложений (например, баз данных) рекомендуется увеличивать время ожидания, чтобы избежать дорогостоящих переездов при кратковременных сбоях сети.

```yaml
spec:
  tolerations:
  - key: "node.kubernetes.io/unreachable"
    operator: "Exists"
    effect: "NoExecute"
    tolerationSeconds: 900 # ждать 15 минут до выселения
  - key: "node.kubernetes.io/not-ready"
    operator: "Exists"
    effect: "NoExecute"
    tolerationSeconds: 900
```

### Сценарий 2: Блокировка выселения через PDB (Kubernetes 1.31)

**Проблема**: Узел недоступен, время ожидания истекло, но поды не удаляются, так как `kubectl get pdb` показывает `ALLOWED DISRUPTIONS: 0`.

**Решение (New в 1.31)**: Используйте поле `unhealthyPodEvictionPolicy` в PDB, чтобы "мертвые" поды не блокировали процесс обслуживания или выселения:
```yaml
spec:
  unhealthyPodEvictionPolicy: AlwaysAllow
```
Это позволит выселять поды, которые и так не проходят Readiness-пробы, даже если бюджет нарушен.

### Сценарий 3: Риски StatefulSet и Split-brain

**Проблема**: При потере связи с узлом поды StatefulSet не пересоздаются автоматически на других узлах сразу (даже после эвикции), чтобы избежать одновременной записи в одно хранилище с двух узлов.

**Опасный метод**: `kubectl delete pod <name> --force --grace-period=0`.
- **Риск**: Если старый узел все еще жив и пишет на диск, принудительный запуск второй копии на другом узле приведет к порче данных.

**Безопасный метод (K8s 1.24+)**: Использование taint `out-of-service`.
1. Убедитесь, что узел физически выключен.
2. Наложите метку:
   ```bash
   kubectl taint nodes <node-name> node.kubernetes.io/out-of-service=nodeshutdown:NoExecute
   ```
3. Это даст сигнал контроллеру StatefulSet, что старые поды можно безопасно удалить и пересоздать.

### Мониторинг выселений
Для отслеживания событий выселения используйте фильтр по причине:
```bash
kubectl get events -A --field-selector reason=TaintManagerEviction
```
