# Недоступность узла: Давление ресурсов

## Основные определения

**Давление ресурсов (Resource Pressure)** — критическое состояние, при котором агент `kubelet` фиксирует дефицит аппаратных ресурсов узла и устанавливает соответствующие условия (`Conditions`). В этом режиме узел может перестать принимать новые поды и начать принудительное выселение существующих для сохранения стабильности системы.

**Выселение (Eviction)** — превентивное завершение работы подов компонентом `kubelet`. В отличие от планового обслуживания, выселение инициируется автоматически при достижении критических порогов (Thresholds).

**Типы ресурсов**:
- **Несжимаемые (Incompressible)**: Память (RAM), дисковое пространство, PID. При их нехватке единственный выход — остановка процессов (выселение).
- **Сжимаемые (Compressible)**: CPU. При дефиците ресурсы распределяются через throttling (замедление), что не вызывает немедленного выселения, но снижает производительность.

## Основные концепции

### Состояния нехватки ресурсов (Conditions)

| Состояние | Ресурс | Описание |
| :--- | :--- | :--- |
| **`MemoryPressure`** | Память | Доступная оперативная память ниже порога. |
| **`DiskPressure`** | Диск | Свободное место или количество Inodes на диске ниже порога. |
| **`PIDPressure`** | Процессы | Количество доступных PID в ОС недостаточно для новых задач. |

### Пороги и механизмы выселения

Kubernetes различает два типа порогов в конфигурации `kubelet` (файл `/var/lib/kubelet/config.yaml`):

1.  **Жесткие пороги (Hard Thresholds)**: При их достижении `kubelet` немедленно завершает поды без периода ожидания (Grace Period).
    - Пример: `memory.available < 100Mi`, `nodefs.available < 5%`.
2.  **Мягкие пороги (Soft Thresholds)**: Позволяют задать период ожидания (`eviction-soft-grace-period`), в течение которого узел пытается восстановить баланс перед выселением.

### Влияние на планировщик (Scheduler)

Когда на узле установлен любой флаг `Pressure=True`, планировщик Kubernetes помечает узел как неподходящий для новых подов. Исключение — поды с соответствующими `tolerations`.

## Практические сценарии

### Сценарий 1: Критическая нехватка памяти (MemoryPressure)

**Диагностика**:
```bash
# 1. Проверка состояния узла
kubectl describe node <node-name> | grep -A 5 Conditions

# 2. Поиск процессов-потребителей (локально на узле)
top -o %MEM -b -n 1 | head -n 20
```

**Решение**:
Подробный регламент очистки и настройки лимитов доступен в разделе:
**[Выселение по памяти (Memory Eviction)](../PodEvicted/memory_eviction.md)**.

### Сценарий 2: Дефицит диска и Inodes (DiskPressure)

Условие `DiskPressure` срабатывает не только при заполнении объема, но и при исчерпании индексных дескрипторов (inodes).

**Диагностика**:
```bash
# 1. Проверка свободного места
df -h

# 2. Проверка количества Inodes
df -i
# → Если IUse% > 90%, это причина DiskPressure
```

**Решение**:
1.  **Агрессивная очистка образов**:
    ```bash
    crictl rmi --prune
    ```
2.  **Поиск директорий с миллионами мелких файлов**:
    ```bash
    du -h --inodes /var/lib/kubelet/pods | sort -rh | head -n 10
    ```
Подробности: **[Выселение по диску (Disk Eviction)](../PodEvicted/disk_eviction.md)**.

### Сценарий 3: Исчерпание PID (PIDPressure)

**Симптомы**: Ошибки `fork: Resource temporarily unavailable` при выполнении любых команд.

**Диагностика**:
```bash
# 1. Проверка текущего количества процессов
ps -eLf | wc -l

# 2. Проверка системного лимита
sysctl kernel.pid_max
# → kernel.pid_max = 32768 (часто недостаточно для K8s)
```

**Решение**:
1.  **Временное**: `sysctl -w kernel.pid_max=4194304`.
2.  **Постоянное**: Добавить `kernel.pid_max=4194304` в `/etc/sysctl.d/99-kubernetes.conf`.
3.  **Ограничение в Kubelet**: Настройте параметр `podPidsLimit` в `KubeletConfiguration` для защиты узла от "вилок-бомб" в контейнерах.
