# Недоступность узла: Определения

## Основные определения

**`NodeNotReady`** — статус узла (`Node`), означающий, что `kubelet` на узле работает, но сообщает, что узел не готов принимать новые поды (условие `Ready` равно `False`).

**`Node Unreachable`** — состояние, при котором `control plane` (в частности `kube-controller-manager`) не может связаться с `kubelet` на узле. В списке узлов такой узел отображается со статусом `Unknown`.

**Важно:** Эти состояния описывают здоровье самого узла как инфраструктурной единицы. Они напрямую влияют на жизненный цикл всех подов, размещённых на данном узле.

## Механизмы отслеживания и состояния

### Состояния узла (Node Conditions)

Kubernetes использует объект `Node` для хранения текущих условий его работы. Наиболее критичные из них:

| Условие | Описание | Норма (Healthy) |
| :--- | :--- | :--- |
| **`Ready`** | Узел готов к работе и приёму подов | `True` |
| **`MemoryPressure`** | Критическая нехватка оперативной памяти | `False` |
| **`DiskPressure`** | Критическая нехватка места на диске | `False` |
| **`PIDPressure`** | Исчерпание лимита идентификаторов процессов | `False` |
| **`NetworkUnavailable`** | Проблемы с сетевой связностью (CNI) | `False` |

### Механизмы Heartbeats (Lease API)

В современных версиях Kubernetes (1.17+) для мониторинга здоровья узлов используются два механизма:

1.  **Обновление статуса Node**: `kubelet` периодически отправляет полную структуру состояния (`NodeStatus`). Частота по умолчанию — раз в 10 секунд (регулируется `--node-status-update-frequency`).
2.  **Node Lease**: Легковесные объекты в пространстве имён `kube-node-lease`. `kubelet` обновляет свой Lease каждые 10 секунд. Это основной и менее ресурсоёмкий сигнал «я жив» для API-сервера.

Если `control plane` не видит обновлений Lease или NodeStatus в течение заданного времени (`node-monitor-grace-period`), узел помечается как `Unknown`.

### Статусы планирования

| Статус | Condition | Описание |
| :--- | :--- | :--- |
| **`Ready`** | `Ready=True` | Узел полностью функционален. |
| **`NotReady`** | `Ready=False` | `kubelet` доступен, но сообщает о внутренних проблемах. |
| **`Unknown`** | `Ready=Unknown` | Связь с узлом потеряна (Lease не обновляется). |
| **`SchedulingDisabled`** | `unschedulable=true` | Узел в режиме `Cordon` (новые поды не назначаются). |

## Практические сценарии

### Когда требуется диагностика

- Узел в выводе `kubectl get nodes` имеет статус `NotReady` или `Unknown`.
- Поды «зависли» в статусе `Terminating` или `Unknown`.
- Система мониторинга сообщает об алерте `NodeNotReady`.
- После перезагрузки или технических работ узел не возвращается в кластер.

### Основные причины (Root Causes)

| Причина | Типичный статус | Ссылка на решение |
| :--- | :--- | :--- |
| Сбой или остановка `kubelet` | `NotReady` / `Unknown` | [Проблемы Kubelet](./kubelet_issues.md) |
| Давление ресурсов (Pressure) | `NotReady` | [Давление ресурсов](./resource_pressure.md) |
| Сетевая изоляция узла | `Unknown` | [Проблемы с сетью](./network_issues.md) |
| Сбой CRI-рантайма (containerd, CRI-O) | `NotReady` | [Проблемы рантайма](./runtime_issues.md) |
| Плановое обслуживание | `SchedulingDisabled` | [Обслуживание узлов](./maintenance.md) |
