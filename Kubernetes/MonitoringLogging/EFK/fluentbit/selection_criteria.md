# Критерии выбора: Fluent Bit vs Fluentd

## Fluent Bit

Идеален для роли агента на узлах Kubernetes. Он производителен, потребляет мало ресурсов и покрывает 99% задач по сбору, базовой обработке и обогащению логов.

## Fluentd

Незаменим в роли центрального агрегатора, если требуется сложная маршрутизация, дедупликация, тяжелые трансформации или интеграция с экзотическими системами, для которых плагины есть только у Fluentd.

## Гибридный подход

Самый распространенный и надежный сценарий:

**Fluent Bit** на всех узлах кластера собирает логи и отправляет их в единый сервис-агрегатор на базе **Fluentd**, который уже отвечает за сложную логику и доставку в конечные системы хранения.

```
┌─────────────────────────────────────────────────────────────┐
│                    KUBERNETES CLUSTER                       │
│                                                             │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │  Fluent Bit │    │  Fluent Bit │    │  Fluent Bit │     │
│  │  (Node 1)   │    │  (Node 2)   │    │  (Node N)   │     │
│  └──────┬──────┘    └──────┬──────┘    └──────┬──────┘     │
│         │                  │                  │            │
│         └──────────────────┼──────────────────┘            │
│                            │ Forward protocol             │
│                   ┌────────▼────────┐                     │
│                   │     Fluentd     │                     │
│                   │  (Aggregator)   │                     │
│                   └────────┬────────┘                     │
│                            │                              │
│         ┌──────────────────┼──────────────────┐           │
│         │                  │                  │           │
│    ┌────▼────┐       ┌────▼────┐       ┌────▼────┐       │
│    │    ES   │       │   S3    │       │  Kafka  │       │
│    └─────────┘       └─────────┘       └─────────┘       │
└─────────────────────────────────────────────────────────────┘
```

## Когда что использовать

| Сценарий | Рекомендация |
|----------|-------------|
| Сбор логов на Kubernetes узлах | **Fluent Bit** |
| Ограниченные ресурсы (IoT, Edge) | **Fluent Bit** |
| Центральная агрегация | **Fluentd** |
| Сложная маршрутизация | **Fluentd** |
| Дедупликация и тяжелые трансформации | **Fluentd** |
| Экзотические output плагины | **Fluentd** |
| Производственный Kubernetes | **Fluent Bit → Fluentd** |
