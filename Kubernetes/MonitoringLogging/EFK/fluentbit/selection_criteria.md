# Критерии выбора: Fluent Bit vs Fluentd

## Определения

**Агент сбора логов** — компонент, развернутый на каждом узле для чтения, парсинга и первичной обработки логов.

**Центральный агрегатор** — компонент, принимающий логи от агентов, выполняющий сложную маршрутизацию и отправку в хранилища.

**Edge-сценарий** — развертывание на узлах с ограниченными ресурсами (IoT, embedded-системы).

## Основные концепции

### Роли компонентов

Детальное сравнение архитектур и возможностей см. в [fluent_comparison.md](./fluent_comparison.md).

### Ключевые факторы выбора

| Фактор | Рекомендация |
|--------|--------------|
| Ресурсы узла | Fluent Bit для ограниченных ресурсов (<100MB RAM) |
| Сложность обработки | Fluentd для дедупликации, сложных трансформаций |
| Экзотические назначения | Fluentd (больше плагинов output) |
| Отказоустойчивость | Гибрид: Fluent Bit → Fluentd |

## Практические сценарии

### Сценарий 1: Малый кластер Kubernetes (<10 узлов)

**Выбор**: Fluent Bit напрямую в Elasticsearch

Обоснование:
- Нет необходимости в сложной маршрутизации
- Экономия ресурсов
- Проще эксплуатация

### Сценарий 2: Производственный кластер (>50 узлов)

**Выбор**: Fluent Bit → Fluentd

Обоснование:
- Буферизация при недоступности хранилищ
- Централизованная настройка маршрутизации
- Возможность добавления новых назначений без переконфигурации агентов

### Сценарий 3: IoT/Edge-устройства

**Выбор**: Fluent Bit

Обоснование:
- Минимальное потребление ресурсов (~5MB RAM)
- Встроенная поддержка ограниченных архитектур (ARM, MIPS)

### Сценарий 4: Compliance и архивирование

**Выбор**: Fluent Bit → Fluentd → (S3 + Elasticsearch)

Обоснование:
- Fluentd плагин `copy` для дублирования потока
- Разные политики буферизации для разных назначений

### Матрица принятия решений

| Сценарий | Рекомендация |
|----------|-------------|
| Сбор логов на Kubernetes узлах | **Fluent Bit** |
| Ограниченные ресурсы (IoT, Edge) | **Fluent Bit** |
| Центральная агрегация | **Fluentd** |
| Сложная маршрутизация | **Fluentd** |
| Дедупликация и тяжелые трансформации | **Fluentd** |
| Экзотические output плагины | **Fluentd** |
| Производственный Kubernetes | **Fluent Bit → Fluentd** |
