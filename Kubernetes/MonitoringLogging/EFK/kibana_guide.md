# Kibana: Практическое руководство

## Определения

Данное руководство сфокусировано на практическом использовании Kibana для анализа логов в среде Kubernetes, собранных с помощью Fluent Bit. Для общего обзора см. [Kibana: Обзор и ключевые концепции](../../../ELK_Stack/Kibana/kibana_overview.md).

## Практические сценарии

### 1. Создание индекс-паттерна для логов Kubernetes

1. Откройте веб-интерфейс Kibana.
2. В боковом меню выберите **Stack Management** → **Index Patterns**.
3. Нажмите **Create index pattern**.
4. В поле "Index pattern name" введите шаблон, соответствующий префиксу логов (например, `mycluster-*` или `myapp-*`). Этот шаблон позволяет агрегировать логи из нескольких индексов (например, ежедневных индексов, создаваемых Fluentd/Fluent Bit).
5. На следующем шаге в выпадающем списке **Time field** выберите `@timestamp` (поле, содержащее временную метку события). Это поле Kibana будет использовать для фильтрации по времени.
6. Нажмите **Create index pattern**.

### 2. Поиск и фильтрация логов пода

Перейдите в **Discover** и выберите нужный индекс-паттерн (например, `mycluster-*` или `myapp-*`).

- **Найти все логи конкретного пода:**

    ```kql
    kubernetes.pod_name: "my-app-pod-xyz123"
    ```

- **Найти все логи подов определенного приложения (по лейблу):**

    ```kql
    kubernetes.labels.app: "my-app"
    ```

- **Показать все ошибки (HTTP 5xx) из неймспейса `production`:**

    ```kql
    kubernetes.namespace_name: "production" and http.status_code: >=500
    ```

### 3. Кастомизация отображения полей

В Discover по умолчанию каждая запись лога отображается как JSON-документ (если JSON не был разобран). Для удобства анализа и для отображения разобранных полей можно настроить табличное представление:

1. В списке полей слева найдите интересующие вас поля (например, `log`, `kubernetes.container_name`, `kubernetes.namespace_name`, а также разобранные поля из JSON-лога, такие как `method`, `path`, `status`).
2. Наведите курсор на поле и нажмите кнопку `+`, чтобы добавить его в виде колонки в основной области.
3. После добавления нескольких полей Kibana автоматически построит таблицу, которую легко читать.

#### Проблемы с парсингом JSON-логов

Если логи в Elasticsearch остаются в виде неразобранной JSON-строки (например, в поле `log` вместо отдельных полей `method`, `status` и т.д.), это указывает на проблему с парсингом на этапе сбора.

*   **Причина**: Fluentd (или Fluent Bit) не смог корректно разобрать JSON-структуру лога. Это может произойти из-за смешанных форматов логов (JSON и обычный текст) или из-за сложности вложенных JSON-структур.
*   **Решение**: Необходимо донастроить Fluentd/Fluent Bit, используя кастомные парсеры и фильтры. В Rancher для этого можно использовать опцию "Edit As File" в конфигурации логирования, чтобы вручную задать правила парсинга (например, с использованием плагина `parser` для Fluent Bit).
