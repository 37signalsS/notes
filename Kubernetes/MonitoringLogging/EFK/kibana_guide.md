> **Примечание:** Данный файл описывает практическое использование Kibana в среде Kubernetes. Общий обзор инструмента и его базовых концепций приведен в документе [Kibana: Обзор](../../../ELK_Stack/Kibana/kibana_overview.md).

## Определения

**Discover (Обнаружение)** — основной инструмент Kibana для интерактивного исследования, поиска и фильтрации необработанных записей (логов).

**Data View (ранее Index Pattern)** — логический шаблон, который указывает Kibana, из каких индексов Elasticsearch (ES) следует запрашивать данные. В Kubernetes обычно настраивается с использованием подстановочных знаков (например, `my-cluster-*`).

**KQL (Kibana Query Language)** — специализированный язык запросов для фильтрации данных в строке поиска.

## Основные концепции

Базовые принципы работы с интерфейсом и синтаксис KQL подробно описаны в [Kibana: Обзор](../../../ELK_Stack/Kibana/kibana_overview.md). В контексте Kubernetes работа с Kibana строится вокруг анализа метаданных, которые добавляют агенты сбора логов (например, Fluent Bit).

## Практические сценарии

### Создание Data View для логов Kubernetes

Для визуализации логов, собираемых стеком EFK (Elasticsearch, Fluent Bit, Kibana):

1. Откройте **Stack Management** → **Data Views**.
2. Нажмите **Create data view**.
3. В поле **Name** введите шаблон, соответствующий префиксу в конфигурации Fluent Bit (параметр `Logstash_Prefix`). Например: `kube-logs-*`.
4. В поле **Timestamp field** выберите `@timestamp`.
5. После сохранения данные станут доступны в разделе **Discover**.

### Поиск и фильтрация логов Kubernetes

Использование KQL (Kibana Query Language) позволяет эффективно изолировать проблемы в конкретных частях кластера.

**Примеры запросов:**

* **Логи конкретного пода (Pod):**

  ```kql
  kubernetes.pod_name: "my-app-v1-84fb6d-xyz"
  ```

* **Все поды определенного приложения (по метке):**

  ```kql
  kubernetes.labels.app: "api-gateway"
  ```

* **Ошибки в конкретном пространстве имен (Namespace):**

  ```kql
  kubernetes.namespace_name: "production" and log.level: (error or critical)
  ```

* **Исключение успешных HTTP-ответов:**

  ```kql
  not http.response.status_code: [200 to 299]
  ```

* **Поиск по тексту сообщения:**

  ```kql
  message: "connection refused"
  ```

### Настройка табличного вида

Для удобства анализа в **Discover** рекомендуется переключиться с просмотра сырого JSON (JavaScript Object Notation) на табличный вид:

1. В боковой панели `Available fields` найдите ключевые поля метаданных.
2. Добавьте их в список выбранных (`Selected fields`), нажав на иконку `+`. Рекомендуемый набор:
   * `kubernetes.namespace_name`
   * `kubernetes.pod_name`
   * `log` (или `message`)
3. Это позволит быстро сканировать поток логов без раскрытия каждой записи.

### Решение проблем: неразобранные JSON-логи

**Симптом:** Содержимое лога отображается как одна длинная строка в поле `log`, а структурированные поля (например, `level`, `request_id`) отсутствуют.

**Причина:** Агент (Fluent Bit) не смог распознать JSON во входящем потоке и передал его как обычный текст.

**Решение:**

1. Проверьте конфигурацию фильтра `kubernetes` в Fluent Bit. Параметр `Merge_Log` должен быть установлен в `On`.
2. Если приложение пишет логи в нестандартном формате, примените аннотацию к поду: `fluentbit.io/parser: "custom_json_parser"`.
3. Подробности настройки парсинга приведены в [Парсинг логов во Fluent Bit](./fluentbit/parsing.md).
