# Практическое руководство по работе с Kibana

Это руководство описывает основы работы с Kibana для анализа логов. При возникновении проблем с компонентами стека EFK обратитесь к руководству по [устранению неполадок](./efk_stack_troubleshooting.md).

## 1. Понимание и создание Индекс-Паттернов (Index Patterns)

[Elasticsearch](../../../ELK_Stack/Elasticsearch/elasticsearch_sharding_replication_cluster.md) хранит данные в **индексах**. Fluent Bit, при использовании `Logstash_Format`, создает новый индекс на каждый день для каждого типа логов. Имена этих индексов обычно включают префикс (который мы задали в `Logstash_Prefix`) и дату.

Например:

-   `kube-2025.11.11`
-   `kube-2025.11.12`
-   `node-2025.11.11`
-   `node-2025.11.12`

Чтобы Kibana могла работать с этими данными как с единым источником, необходимо создать **индекс-паттерн**. Индекс-паттерн — это шаблон, который использует wildcards (`*`) для объединения нескольких индексов. Например, паттерн `kube-*` объединит все логи приложений за все дни.

### Шаги по созданию/обновлению индекс-паттерна:

1.  **Перейдите в раздел управления:**

    *   Откройте веб-интерфейс Kibana.
    *   В боковом меню выберите **Stack Management**.

2.  **Откройте управление Индекс-Паттернами:**

    *   В разделе **Kibana** выберите **Index Patterns**.

3.  **Удаление старых индекс-паттернов (при необходимости):**

    *   Если вы меняли префиксы логов в Fluent Bit (например, с `logstash-*` на `kube-*` или `node-*`), старые индекс-паттерны могут быть неактуальны. Выберите их и нажмите "Delete".

4.  **Создайте новый паттерн:**

    *   Нажмите **Create index pattern**.
    *   В поле "Index pattern name" введите шаблон, соответствующий префиксу, заданному в конфигурации Fluent Bit. Например, для логов контейнеров введите `kube-*`, а для логов хостов — `node-*`. Kibana покажет, что соответствующие индексы найдены.
    *   Нажмите **Next step**.
    *   В выпадающем списке **Time field** выберите `@timestamp`. Это поле используется Kibana для фильтрации логов по времени.
    *   Нажмите **Create index pattern**.

Повторите этот процесс для всех типов логов (например, для логов хост-систем с префиксом `node-*`).

## 2. Просмотр и анализ логов в Discover

Вкладка **Discover** — это основной инструмент для поиска и просмотра логов в реальном времени.

1.  **Перейдите в Discover:**

    *   Нажмите на иконку меню и выберите **Discover** (обычно находится вверху в секции Analytics).

2.  **Выберите Индекс-Паттерн:**

    *   В левом верхнем углу под названием "Discover" находится выпадающий список. Выберите в нем паттерн, логи которого вы хотите посмотреть (например, `kube-*`).

3.  **Анализ логов:**

    *   Вы увидите поток логов, отсортированных по времени.
    *   Каждая запись лога — это документ, который можно развернуть, чтобы увидеть все поля, добавленные Fluent Bit:
        -   `log`: само сообщение лога.
        -   `kubernetes.pod_name`: имя пода.
        -   `kubernetes.namespace_name`: неймспейс.
        -   `kubernetes.labels.*`: лейблы пода.
        -   И многие другие.
    *   Сверху находится строка поиска (KQL - Kibana Query Language), где можно фильтровать логи по определенным полям.
    *   Также доступен фильтр по времени в правом верхнем углу.

## 3. Язык Запросов Kibana (KQL)

KQL позволяет эффективно фильтровать и анализировать логи.

### Фильтрация по Полям

Для поиска логов конкретного приложения в кластере Kubernetes можно использовать поля. Например, чтобы найти логи подов Kibana:

```kql
kubernetes.pod_name: kibana*
```

*   **Использование подстановочных знаков**: Звездочка (`*`) может использоваться в значениях полей для частичного совпадения.
*   **Объединение выражений**: Запросы можно объединять с помощью логических операторов `and`, `or`, `not`. Для создания более сложных выражений используйте скобки.

Пример сложного запроса:

```kql
kubernetes.pod_name: kibana* and (status_code: 200 or not status_code: 500)
```

### Фильтрация Числовых Значений

Для числовых полей можно использовать операторы сравнения (меньше, больше):

```kql
status_code: <500
status_code: >200
```

### Вывод Определенных Полей

В левой панели интерфейса "Discover" можно выбрать, какие поля отображать в результатах поиска. Например, чтобы видеть только поле `log`:

1.  Найдите поле `log` в списке.
2.  Нажмите кнопку `+` рядом с ним.

Добавление нескольких полей в "Selected fields" позволяет Kibana автоматически построить табличное представление.

## 4. Дашборды Kibana

Kibana позволяет создавать собственные дашборды для визуализации логов. Для качественной работы с дашбордами логи необходимо парсить. Простейший способ упростить парсинг логов – настроить приложение на запись логов в формате JSON.

### Создание Дашборда

1.  Нажмите "Создать новый дашборд".
2.  Выберите тип визуализации (например, график).
3.  Перетащите нужное поле (например, `REC.Method` или `Request method`) на дашборд.
4.  Выберите вариант отображения (например, "Overtime") для просмотра запросов по типам за определенный период.

Дашборд можно сохранить и добавить на него несколько визуализаций для отображения информации из логов.
