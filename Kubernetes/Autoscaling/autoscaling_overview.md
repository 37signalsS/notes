# Автоматическое масштабирование в Kubernetes

## Horizontal Pod Autoscaler (HPA)

**Уровень:** Поды (Pods)

**Что делает:** Автоматически увеличивает или уменьшает количество подов в `Deployment`, `ReplicaSet` или `StatefulSet`.

**На чем основано решение:**

-   **Метрики ресурсов:** Среднее потребление CPU или RAM.
-   **Кастомные метрики:** Метрики, специфичные для приложения (например, количество запросов в секунду на под).
-   **Внешние метрики:** Метрики из внешних систем (например, длина очереди в RabbitMQ).

HPA является основным инструментом для масштабирования нагрузки вашего приложения.

**Подробнее:** [Horizontal Pod Autoscaler (HPA)](./horizontal_pod_autoscaler.md)

## Vertical Pod Autoscaler (VPA)

**Уровень:** Контейнеры (Containers)

**Что делает:** Автоматически настраивает запросы (`requests`) и лимиты (`limits`) на CPU и RAM для контейнеров в подах. Это помогает оптимизировать использование ресурсов.

**Режимы работы:**

-   **`Recreate` (по умолчанию):** Если VPA решает, что поду нужны другие ресурсы, он перезапускает под с новыми `requests` и `limits`.
-   **`Initial`:** VPA устанавливает `requests` только при создании пода и больше их не меняет.
-   **`Off`:** Режим "только рекомендации". VPA анализирует потребление и записывает рекомендуемые значения, но не применяет их.

VPA полезен для подбора оптимальных значений `requests`, что делает работу HPA более предсказуемой.

**Подробнее:** [Vertical Pod Autoscaler (VPA)](./vertical_pod_autoscaler.md)

## 3. Cluster Autoscaler (CA)

**Уровень:** Узлы кластера (Nodes)

**Что делает:** Автоматически добавляет или удаляет узлы (виртуальные машины) в кластере.

**На чем основано решение:**

-   **Масштабирование вверх (Scale-Up):** Если в кластере есть поды в состоянии `Pending` из-за нехватки ресурсов (CPU, RAM), Cluster Autoscaler запрашивает у облачного провайдера новый узел.
-   **Масштабирование вниз (Scale-Down):** Если узел в течение определенного времени используется слабо и все его поды могут быть безопасно перемещены на другие узлы, Cluster Autoscaler удаляет этот узел для экономии средств.

## Как они работают вместе: Синергия

Эти три механизма создают полную цепочку автоматического масштабирования:

1.  **Резко возрастает трафик.**
2.  **HPA** замечает рост потребления CPU подами и решает увеличить их количество с 3 до 10.
3.  Новые 7 подов переходят в состояние `Pending`, так как на существующих узлах кластера нет свободных ресурсов.
4.  **Cluster Autoscaler** видит "зависшие" поды и запрашивает у облака 2 новых узла.
5.  Когда новые узлы готовы, Kubernetes размещает на них ожидающие поды.
6.  **VPA** (в режиме `Off`) параллельно анализирует работу приложения и рекомендует увеличить `requests` для CPU, чтобы в будущем HPA реагировал еще точнее.
