# Vertical Pod Autoscaler (VPA)

**Vertical Pod Autoscaler (VPA)** — это компонент Kubernetes, который автоматически подбирает оптимальные значения запросов (`requests`) и лимитов (`limits`) на CPU и память для контейнеров в подах. Его главная цель — повысить эффективность использования ресурсов в кластере.

VPA помогает решить две проблемы:
1.  **Перерасход ресурсов (Overprovisioning):** Когда для подов запрашивается значительно больше ресурсов, чем им реально нужно, что ведет к лишним тратам.
2.  **Нехватка ресурсов (Underprovisioning):** Когда запрошено слишком мало ресурсов, что приводит к снижению производительности или `OOMKilled` сбоям.

---

## Компоненты VPA

VPA состоит из трех основных компонентов:

1.  **VPA Recommender:**
    *   Следит за историей потребления ресурсов подами.
    *   На основе этих данных строит модель и предлагает новые, оптимальные значения для `requests`.
    *   Сохраняет свои рекомендации в поле `status` объекта VPA.

2.  **VPA Updater:**
    *   Отвечает за применение рекомендаций.
    *   Если VPA работает в режиме, который требует перезапуска пода, `Updater` выселяет (`evicts`) под, чтобы его контроллер (например, `Deployment`) пересоздал его с новыми, обновленными `requests`.

3.  **VPA Admission Controller:**
    *   Это вебхук, который перехватывает запросы на создание новых подов.
    *   Если для пода есть активный VPA, Admission Controller подменяет в манифесте пода значения `requests` на те, что рекомендованы `Recommender`-ом.

---

## Режимы работы (`updateMode`)

VPA может работать в одном из четырех режимов, которые определяют, как он будет применять свои рекомендации.

*   **`Off` (Режим "только рекомендации"):**
    *   VPA только анализирует потребление и записывает рекомендации в `status` объекта VPA. Никакие изменения к подам не применяются.
    *   **Это самый безопасный и рекомендуемый режим для начала.** Он позволяет оценить, какие ресурсы действительно нужны вашим приложениям, без риска неожиданных перезапусков.

*   **`Initial`:**
    *   VPA применяет рекомендации **только в момент создания пода**.
    *   Admission Controller устанавливает рекомендованные `requests` для новых подов, но `Updater` не будет перезапускать уже работающие поды для обновления их ресурсов.

*   **`Recreate`:**
    *   VPA применяет рекомендации как при создании, так и для уже работающих подов.
    *   Если `Updater` решает, что работающему поду нужны другие ресурсы, он **перезапустит** этот под, чтобы применить новые `requests`.
    *   **Внимание:** Этот режим может вызывать простои, если ваше приложение состоит из одной реплики. Используйте его с [PodDisruptionBudget (PDB)](../../Base/pod_disruption_budget.md).

*   **`Auto`:**
    *   В будущем этот режим позволит применять изменения без перезапуска пода (in-place update), но на данный момент он работает так же, как `Recreate`.

## Анатомия манифеста VPA

```yaml
apiVersion: "autoscaling.k8s.io/v1"
kind: VerticalPodAutoscaler
metadata:
  name: my-app-vpa
spec:
  # 1. Ссылка на целевой контроллер (например, Deployment)
  targetRef:
    apiVersion: "apps/v1"
    kind:       Deployment
    name:       my-app

  # 2. Политика обновления
  updatePolicy:
    # Режим работы: "Off", "Initial", "Recreate"
    updateMode: "Off"

  # 3. (Опционально) Ограничения на ресурсы
  resourcePolicy:
    containerPolicies:
      - containerName: '*' # Применить ко всем контейнерам в поде
        minAllowed: # Минимально допустимые значения
          cpu: 100m
          memory: 50Mi
        maxAllowed: # Максимально допустимые значения
          cpu: "1"
          memory: 500Mi
        controlledResources: ["cpu", "memory"] # Какие ресурсы контролировать
```

1.  **`targetRef`**: Указывает, для какого `Deployment`, `StatefulSet` или другого контроллера VPA будет давать рекомендации.
2.  **`updatePolicy.updateMode`**: Определяет режим работы (см. выше).
3.  **`resourcePolicy`**: Позволяет задать "коридор" для рекомендаций, чтобы VPA не предлагал слишком низкие или слишком высокие значения.

## VPA и Horizontal Pod Autoscaler (HPA)

**Внимание:** Не используйте VPA в режимах `Initial` или `Recreate` для управления CPU или памятью, если для этих же метрик настроен [Horizontal Pod Autoscaler (HPA)](./horizontal_pod_autoscaler.md). Это приведет к конфликту: HPA будет пытаться масштабировать количество подов, а VPA — их ресурсы, что вызовет нестабильное поведение.

**Рекомендуемая стратегия совместного использования:**

1.  **VPA в режиме `Off`:** Используйте VPA для получения точных рекомендаций по `requests` для CPU и памяти.
2.  **Ручная настройка `requests`:** На основе рекомендаций VPA установите адекватные `requests` в манифесте вашего `Deployment`.
3.  **HPA для масштабирования:** Настройте HPA для масштабирования подов по утилизации CPU или памяти. Поскольку `requests` теперь заданы корректно, HPA будет работать гораздо точнее и предсказуемее.

Эта связка позволяет достичь высокой эффективности использования ресурсов и эластичности.
