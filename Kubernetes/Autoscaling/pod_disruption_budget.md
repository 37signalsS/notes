# Pod Disruption Budget (PDB)

## Определения

**Pod Disruption Budget (PDB)** — объект Kubernetes, ограничивающий количество подов, которые могут быть одновременно недоступны в результате добровольных прерываний.

**Добровольные прерывания (Voluntary Disruptions)** — плановые операции, инициируемые пользователем или системой: drain узла, обновление Deployment, освобождение узла Cluster Autoscaler.

**Недобровольные прерывания (Involuntary Disruptions)** — непредвиденные события: аппаратные сбои, паника ядра, сетевые проблемы.

## Основные концепции

### Принцип работы

PDB проверяет соблюдение бюджета перед выполнением операций, приводящих к добровольным прерываниям. Если выселение пода нарушит бюджет, операция приостанавливается до восстановления доступности.

### Параметры конфигурации

- **`selector`** — метки подов, подпадающих под защиту
- **`minAvailable`** — минимальное количество/процент доступных подов
- **`maxUnavailable`** — максимальное количество/процент недоступных подов

### Ограничения

PDB **не защищает** от:
- Аппаратных сбоев
- Паники ядра
- Проблем с сетью
- Недобровольных прерываний любого типа

## Практические сценарии

### Базовый манифест

```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: web-pdb
spec:
  minAvailable: 80%
  selector:
    matchLabels:
      app: web
```

### Варианты конфигурации

**Фиксированное количество:**
```yaml
minAvailable: 3
```

**Процентное соотношение:**
```yaml
minAvailable: 50%
```

**Максимум недоступных:**
```yaml
maxUnavailable: 1
```

### Когда создавать PDB

Обязательно для:
- Критически важных приложений в production
- Stateful сервисов с ограниченным количеством реплик
- Приложений с длительным временем запуска

## Дополнительная информация

### Сценарии использования

- **Обновления узлов** — предотвращение одновременной недоступности всех реплик при drain
- **Масштабирование узлов** — защита при освобождении узлов Cluster Autoscaler
- **Обновления приложений** — контроль Rolling Update Deployment
- **Вертикальное масштабирование** — [VPA](vpa_detailed.md) использует PDB для минимизации прерываний при перезапуске подов
- **Горизонтальное масштабирование** — [HPA](hpa_detailed.md) при масштабировании вниз учитывает PDB

### Лучшие практики

- Создавайте PDB для production-сервисов с критичными требованиями к доступности
- Учитывайте время запуска пода при выборе значений `minAvailable`/`maxUnavailable`
- Тестируйте PDB перед применением в production
- Используйте совместно с [Pod Anti-Affinity](pod_distribution.md) для максимальной отказоустойчивости
