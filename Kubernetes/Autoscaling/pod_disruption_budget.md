# PodDisruptionBudget (PDB)

**PodDisruptionBudget (PDB)** — это объект Kubernetes, который ограничивает количество подов, которые могут быть одновременно недоступны в результате **добровольных прерываний** (`voluntary disruptions`). Это критически важный механизм для обеспечения высокой доступности приложений.

Добровольные прерывания включают в себя:
-   Слив (draining) узла для обслуживания.
-   Удаление пода, управляемого `Deployment`, для выполнения обновления.
-   Удаление пода с узла для его освобождения `Cluster Autoscaler`.

PDB **не защищает** от **недобровольных прерываний**, таких как аппаратный сбой, паника ядра или проблемы с сетью.

## Как работает PDB

В спецификации PDB вы указываете:
1.  **`selector`**: Метки подов, которые нужно защитить.
2.  **`minAvailable`** или **`maxUnavailable`**:
    -   `minAvailable`: Минимальное количество или процент подов, которые должны оставаться доступными.
    -   `maxUnavailable`: Максимальное количество или процент подов, которые могут быть недоступны.

Когда выполняется операция, приводящая к добровольному прерыванию (например, `kubectl drain`), Kubernetes проверяет PDB. Если выселение пода нарушит бюджет (например, количество доступных подов станет меньше `minAvailable`), операция будет приостановлена до тех пор, пока бюджет не будет снова соблюден.

## Пример манифеста

Этот PDB гарантирует, что как минимум 80% подов с меткой `app: web` будут доступны в любой момент времени во время добровольных прерываний.

```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: web-pdb
spec:
  minAvailable: 80%
  selector:
    matchLabels:
      app: web
```

**Рекомендация:** Всегда создавайте PDB для критически важных, stateless и stateful приложений в продакшене, чтобы предотвратить простои во время планового обслуживания кластера или автоматического масштабирования узлов.
