# Horizontal Pod Autoscaler (HPA)

Horizontal Pod Autoscaler (HPA) — механизм автоматического масштабирования количества подов в Kubernetes на основе метрик потребления ресурсов или пользовательских показателей.

## Определения

**Horizontal Pod Autoscaler (HPA)** — контроллер в составе `kube-controller-manager`, который автоматически изменяет количество реплик в Deployment, ReplicaSet или StatefulSet. Он работает по принципу «петли управления» (control loop), по умолчанию сверяя метрики каждые 15 секунд.

**Масштабирование по горизонтали** — процесс увеличения или уменьшения количества экземпляров приложения (подов) для обработки изменяющейся нагрузки.

**Metrics Server** — компонент кластера, агрегирующий метрики использования ресурсов (CPU, память) и предоставляющий их через Metrics API (`metrics.k8s.io`). Является обязательным для базовых сценариев автомасштабирования.

## API-версии

Существует две основные версии API для HPA:

-   **`autoscaling/v1`**: Первая стабильная версия, поддерживает масштабирование только на основе метрики CPU. Проста в использовании, но ограничена в возможностях.
-   **`autoscaling/v2`**: Стабильная (GA) версия, начиная с Kubernetes 1.23. Является рекомендуемой. Расширяет возможности HPA, позволяя использовать:
    -   Масштабирование по нескольким метрикам одновременно (включая CPU и память).
    -   Пользовательские метрики (`Custom Metrics`) от Prometheus и других систем.
    -   Внешние метрики (`External Metrics`) из источников вне кластера (например, длина очереди в Kafka).
    -   Поле `behavior` для тонкой настройки скорости и шагов масштабирования.

## Базовые концепции

Логика HPA основана на расчёте необходимого количества реплик для достижения целевого значения метрики.

### Ключевые аспекты

-   **Алгоритм расчета:** `желаемое количество = ceil[текущее количество * (текущее значение метрики / целевое значение метрики)]`.
-   **Типы метрик:**
    -   `Resource`: CPU и память.
    -   `Pods` (Custom): Метрики, привязанные к подам (например, запросов в секунду на под).
    -   `Object` (Custom): Метрики, привязанные к другому объекту Kubernetes.
    -   `External`: Метрики из внешних систем.
-   **Компоненты:** HPA Controller, Metrics API, адаптеры для пользовательских метрик (например, Prometheus Adapter, KEDA).
-   **Поведение (`behavior`):** Функция API `v2`, позволяющая настроить политику стабилизации и скорость масштабирования (scale up/down).

[Подробное описание основных концепций](./hpa_concepts.md)

## Практические сценарии

Настройка HPA требует наличия установленных `resources.requests` у контейнеров (для масштабирования по CPU/Memory) и корректно настроенного источника метрик.

### Примеры использования

-   **Масштабирование по CPU/Memory:** базовый сценарий для stateless-приложений.
-   **Использование внешних метрик:** масштабирование воркеров на основе длины очереди (Kafka, RabbitMQ, SQS).
-   **Продвинутое поведение:** использование `stabilizationWindowSeconds` для предотвращения «флаттеринга» (колебаний количества реплик).

[Смотреть практические сценарии и примеры YAML](./hpa_scenarios.md)

## Дополнительная информация

### Ограничения и особенности

-   HPA не масштабирует ресурсы ниже `minReplicas`. Для масштабирования до нуля (scale-to-zero) используется KEDA.
-   Конфликтует с Vertical Pod Autoscaler (VPA) при использовании одних и тех же метрик (CPU/Memory) в активных режимах.
-   Не поддерживает `DaemonSet` и `Job`.

### Диагностика и мониторинг

Для проверки состояния HPA используйте команды `kubectl get hpa` и `kubectl describe hpa`. Мониторинг осуществляется через `kube-state-metrics` в связке с Prometheus.
