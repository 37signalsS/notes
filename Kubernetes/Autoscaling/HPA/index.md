# Horizontal Pod Autoscaler (HPA)

Horizontal Pod Autoscaler (HPA) — механизм автоматического масштабирования количества подов в Kubernetes на основе метрик потребления ресурсов или пользовательских показателей.

## Определения

**Horizontal Pod Autoscaler (HPA)** — контроллер Kubernetes, который автоматически изменяет количество реплик в Deployment, ReplicaSet или StatefulSet. Работает по принципу «петли управления» (control loop) с интервалом опроса 15 секунд (по умолчанию).

**Масштабирование по горизонтали** — процесс увеличения или уменьшения количества экземпляров приложения (подов) для обработки изменяющейся нагрузки.

**Metrics Server** — обязательный компонент кластера для работы HPA с базовыми метриками, предоставляющий данные через Metrics API (`metrics.k8s.io`).

## Базовые концепции

Основная логика работы HPA строится на расчёте необходимого количества реплик на основе отклонения текущей метрики от целевого значения.

### Ключевые аспекты

- **Алгоритм расчета:** желаемые реплики вычисляются как отношение текущей утилизации к целевой.
- **Типы метрик:** Resource (CPU/Memory), Custom (RPS), External (очереди).
- **Компоненты:** HPA Controller, Metrics API, адаптеры (Prometheus Adapter, KEDA).
- **Поведение (Behavior):** тонкая настройка скорости масштабирования вверх и вниз.

[Подробное описание основных концепций](./hpa_concepts.md)

## Практические сценарии

Настройка HPA требует наличия установленных `resources.requests` у контейнеров и корректно настроенного источника метрик.

### Примеры использования

- **Масштабирование по CPU/Memory:** базовый сценарий для stateless-приложений.
- **Использование внешних метрик:** масштабирование воркеров на основе длины очереди (Kafka, SQS).
- **Продвинутое поведение:** использование `stabilizationWindowSeconds` для предотвращения «флаппинга» (дребезга).

[Смотреть практические сценарии и примеры YAML](./hpa_scenarios.md)

## Дополнительная информация

### Ограничения и особенности

- HPA не масштабирует ресурсы ниже `minReplicas` (для масштабирования до нуля используйте KEDA).
- Конфликтует с VPA при использовании одних и тех же метрик (CPU/Memory) в активных режимах.
- Не поддерживает DaemonSet и Job.

### Диагностика и мониторинг

Для проверки состояния HPA используйте команды `kubectl get hpa` и `kubectl describe hpa`. Мониторинг осуществляется через `kube-state-metrics` в связке с Prometheus.
