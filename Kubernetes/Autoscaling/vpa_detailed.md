# Vertical Pod Autoscaler (VPA)

## Определения

**Vertical Pod Autoscaler (VPA)** — механизм Kubernetes для автоматического изменения ресурсов (CPU/memory) запросов подов на основе истории потребления.

**Overprovisioning** — ситуация, когда запрошено значительно больше ресурсов, чем реально используется.

**Underprovisioning** — ситуация, когда запрошено недостаточно ресурсов, приводящая к OOMKilled или снижению производительности.

## Основные концепции

#### Компоненты VPA

1. **VPA Recommender:** Следит за историей потребления ресурсов и предлагает новые, оптимальные значения `requests`.
2. **VPA Updater:** Отвечает за применение рекомендаций, выселяя (`evicts`) поды для обновления их ресурсов.
3. **VPA Admission Controller:** Вебхук, который перехватывает запросы на создание подов и подменяет в них `requests` на рекомендованные.

### Режимы работы (`updateMode`)

* **`Off` (Режим "только рекомендации"):** Самый безопасный режим для начала. VPA только анализирует потребление и записывает рекомендации, не применяя их.
* **`Initial`:** VPA применяет рекомендации **только в момент создания пода**. Уже работающие поды не затрагиваются.
* **`Recreate`:** VPA применяет рекомендации как при создании, так и для уже работающих подов, **перезапуская** их при необходимости. Однако, с появлением In-Place Pod Resize (стабильно с Kubernetes 1.35), простои для приложений с одной репликой могут быть минимизированы. Для сервисов, чувствительных к прерываниям, рекомендуется использовать плановые окна обновлений и [PodDisruptionBudget](../../Base/pod_disruption_budget.md).
* **`Auto`:** Работает так же, как `Recreate`, но, **начиная с Kubernetes 1.35 и стабилизации In-Place Pod Resize**, может применять изменения без перезапуска пода.

### Принцип работы

VPA анализирует исторические данные о потреблении ресурсов и рассчитывает оптимальные значения requests. При изменении рекомендаций в активных режимах поды перезапускаются с новыми лимитами.

## Практические сценарии

### Базовая конфигурация

```yaml
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: my-app-vpa
spec:
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app
  updatePolicy:
    updateMode: "Off"
  resourcePolicy:
    containerPolicies:
      - containerName: '*'
        minAllowed:
          cpu: 100m
          memory: 50Mi
        maxAllowed:
          cpu: "1"
          memory: 500Mi
```

### Рекомендуемый подход внедрения

1. **Начните с режима `Off`** — соберите рекомендации без риска
2. **Проанализируйте рекомендации** — проверьте соответствие ожиданиям
3. **Переходите к `Initial` или `Recreate`** — применяйте изменения постепенно
4. **Для критичных сервисов** — используйте окна обслуживания

### Совместное использование с HPA

**Конфликт:** Не используйте VPA в режимах `Initial` или `Recreate` для CPU/memory одновременно с HPA по тем же метрикам.

**Решение:**

* VPA в режиме `Off` для получения рекомендаций
* Ручная настройка requests на основе рекомендаций
* HPA для горизонтального масштабирования по утилизации

## Дополнительная информация

### Ограничения

* VPA требует перезапуска подов для применения изменений (до Kubernetes 1.35)
* **Конфликт с HPA**: не используйте VPA в режимах `Initial`, `Recreate` или `Auto` для CPU/memory одновременно с [HPA](hpa_detailed.md) по тем же метрикам — используйте режим `Off` для получения рекомендаций с последующей ручной настройкой
* Рекомендации основываются на исторических данных — требуется время для обучения

### Интеграции

Для минимизации прерываний при обновлении ресурсов используйте [Pod Disruption Budget](pod_disruption_budget.md). [Паттерны масштабирования](scaling_patterns.md) помогают выбрать оптимальный подход.
