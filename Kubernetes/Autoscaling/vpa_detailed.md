# Vertical Pod Autoscaler (VPA)

### Vertical Pod Autoscaler (VPA)

VPA решает две проблемы:

1. **Перерасход ресурсов (Overprovisioning):** Когда для подов запрашивается значительно больше ресурсов, чем им реально нужно.
2. **Нехватка ресурсов (Underprovisioning):** Когда запрошено слишком мало ресурсов, что приводит к снижению производительности или `OOMKilled`.

#### Компоненты VPA

1. **VPA Recommender:** Следит за историей потребления ресурсов и предлагает новые, оптимальные значения `requests`.
2. **VPA Updater:** Отвечает за применение рекомендаций, выселяя (`evicts`) поды для обновления их ресурсов.
3. **VPA Admission Controller:** Вебхук, который перехватывает запросы на создание подов и подменяет в них `requests` на рекомендованные.

#### Режимы работы (`updateMode`)

* **`Off` (Режим "только рекомендации"):** Самый безопасный режим для начала. VPA только анализирует потребление и записывает рекомендации, не применяя их.
* **`Initial`:** VPA применяет рекомендации **только в момент создания пода**. Уже работающие поды не затрагиваются.
* **`Recreate`:** VPA применяет рекомендации как при создании, так и для уже работающих подов, **перезапуская** их при необходимости. Однако, с появлением In-Place Pod Resize (стабильно с Kubernetes 1.35), простои для приложений с одной репликой могут быть минимизированы. Для сервисов, чувствительных к прерываниям, рекомендуется использовать плановые окна обновлений и [PodDisruptionBudget](../../Base/pod_disruption_budget.md).
* **`Auto`:** Работает так же, как `Recreate`, но, **начиная с Kubernetes 1.35 и стабилизации In-Place Pod Resize**, может применять изменения без перезапуска пода.

### Дополнительная информация

### Совместное использование VPA и HPA

**Внимание:** Не используйте VPA в режимах `Initial` или `Recreate` для управления CPU или памятью, если для этих же метрик настроен HPA. Это приведет к конфликту.

**Рекомендуемая стратегия совместного использования:**

1. **VPA в режиме `Off`:** Используйте для получения точных рекомендаций по `requests`.
2. **Ручная настройка `requests`:** На основе рекомендаций VPA установите адекватные `requests` в манифесте.
3. **HPA для масштабирования:** Настройте HPA для масштабирования подов по утилизации ресурсов. Корректно заданные `requests` сделают работу HPA гораздо точнее.

## Практические сценарии

### Настройка VPA

#### Анатомия манифеста VPA

```yaml
apiVersion: "autoscaling.k8s.io/v1"
kind: VerticalPodAutoscaler
metadata:
  name: my-app-vpa
spec:
  # 1. Ссылка на целевой контроллер
  targetRef:
    apiVersion: "apps/v1"
    kind:       Deployment
    name:       my-app

  # 2. Политика обновления
  updatePolicy:
    updateMode: "Off"

  # 3. Ограничения на ресурсы
  resourcePolicy:
    containerPolicies:
      - containerName: '*'
        minAllowed:
          cpu: 100m
          memory: 50Mi
        maxAllowed:
          cpu: "1"
          memory: 500Mi
```
