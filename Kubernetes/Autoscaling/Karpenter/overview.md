# Обзор и основные концепции Karpenter

> **Важно:** Karpenter предназначен для облачных провайдеров (AWS (Amazon Web Services), Azure, GCP (Google Cloud Platform)). Для локальных окружений (on-premise, bare-metal) используйте **[Cluster Autoscaler](../cluster_autoscaler_detailed.md)** с группами узлов или **Volcano** для пакетных (batch) нагрузок.

## Определения

**Karpenter** — оператор Kubernetes для автоматического масштабирования кластера, который динамически создаёт узлы оптимального размера под требования ожидающих подов. Разработан в AWS (Amazon Web Services), передан в CNCF (Cloud Native Computing Foundation). Текущая стабильная версия — v1.10.

**Node Pool** (ранее **Provisioner**) — объект Karpenter, определяющий параметры создаваемых узлов (типы инстансов, зоны, метки, теги).

**Consolidation** — механизм оптимизации затрат, который автоматически заменяет узлы на более дешёвые или объединяет несколько слабо утилизированных узлов в один.

**EC2NodeClass** (AWS) / **NodeClass** — шаблон конфигурации узла: AMI (Amazon Machine Image), диск, сеть, IAM-роль (Identity and Access Management).

## Основные концепции

### Отличия от Cluster Autoscaler

| Характеристика | Cluster Autoscaler (CA) | Karpenter |
|----------------|-------------------|-----------|
| **Подход** | Работает с предопределёнными группами узлов (Node Groups) | Создаёт узлы «точно в срок», управляет каждым узлом индивидуально |
| **Скорость** | 1–3 минуты на масштабирование | 30–60 секунд (мгновенное создание) |
| **Эффективность** | Выбор из готовых шаблонов | Оптимальный подбор типа инстанса (amd64/arm64, GPU (Graphics Processing Unit), специализированные) |
| **Гибкость** | Ограничена группами узлов | Динамический выбор из сотен типов инстансов, контроль лимитов по стоимости, выбор spot/on-demand |
| **Consolidation** | Базовое уменьшение масштаба (scale-down) | Умная консолидация (замена и объединение) |
| **Сложность** | Средняя | Выше, требует настройки CRD (Custom Resource Definition): NodePool, NodeClass |

### Ключевые преимущества

**Скорость** — Karpenter не ждёт освобождения ресурсов на существующих узлах, а сразу создаёт новый, подходящий под требования пода. Это критично для взрывных (burst) нагрузок и пакетных задач.

**Гибкость** — позволяет точно контролировать типы используемых узлов, задавать лимиты по стоимости, выбирать между spot и on-demand, а также учитывать `topologySpreadConstraints` для распределения по зонам.

**Отказ от групп узлов** — в отличие от Cluster Autoscaler, которому нужны предопределённые группы, Karpenter управляет каждым узлом индивидуально. Это упрощает конфигурацию и снимает ограничения на размер группы.

### Принцип работы

1. **Мониторинг ожидающих подов** — Karpenter отслеживает поды в состоянии `Pending`.
2. **Анализ требований** — анализирует запросы ресурсов (`requests`), правила близости (`affinity`), допуски (`tolerations`), селекторы узлов (`nodeSelector`) и ограничения распределения топологии (`topologySpreadConstraints`).
3. **Подбор инстанса** — выбирает оптимальный тип инстанса из доступных в облаке (архитектура amd64/arm64, зона доступности, GPU (Graphics Processing Unit)).
4. **Создание узла** — запускает новый узел через API (Application Programming Interface) облачного провайдера за секунды.
5. **Планирование** — после готовности узла Kubernetes размещает на нём поды.
6. **Консолидация** — автоматически удаляет неэффективные узлы и перепаковывает поды на другие, оптимизируя заполнение кластера.

### Архитектурные компоненты

**Karpenter Controller** — оператор, работающий как Deployment в пространстве имён (namespace) `kube-system` или `karpenter`.

**Node Pool** — определяет параметры создаваемых узлов (аналог Node Group).

**EC2NodeClass** (AWS) / **NodeClass** — шаблон конфигурации узла (AMI, диск, сеть).

**Consolidation Controller** — компонент для оптимизации затрат.

## Практические сценарии

### Масштабирование по длине очереди Kafka

Karpenter подходит для рабочих нагрузок, масштабируемых по внешним метрикам. Этот сценарий показывает объединение KEDA (Kubernetes Event-driven Autoscaling), HPA (Horizontal Pod Autoscaler) и Karpenter.

**Архитектура решения:**

1. **Экспортёр метрик**: Специализированный экспортер (например, `kafka-exporter`) собирает метрику `kafka_consumergroup_lag` и предоставляет её для Prometheus.
2. **KEDA (`ScaledObject`)**: KEDA настраивается для отслеживания этой метрики в Prometheus.
3. **HPA**: KEDA автоматически создает и управляет объектом HPA на основе `ScaledObject`. При превышении порога очереди HPA увеличивает количество реплик подов.
4. **Karpenter**:
    * Обнаруживает новые поды в состоянии `Pending`, созданные HPA.
    * Анализирует их ресурсные запросы и требования (affinity, tolerations).
    * Напрямую обращается к API облачного провайдера (например, AWS EC2) и создает узел оптимального размера.
    * После готовности узла `kube-scheduler` размещает на нем поды.

**Преимущества подхода:**

**Эффективность** — ресурсы создаются только при реальной нагрузке.

**Скорость** — Karpenter быстрее Cluster Autoscaler, что важно для быстрой обработки всплесков.

**Оптимизация затрат** — подбор наиболее дешевого типа инстанса, включая spot-инстансы.

## Дополнительная информация

### Интеграции

**[HPA (Horizontal Pod Autoscaler)](../HPA/index.md)** — Karpenter реагирует на поды, созданные HPA.

**[VPA (Vertical Pod Autoscaler)](../vpa_detailed.md)** — помогает оптимизировать запросы для лучшего подбора узлов.

**[KEDA (Kubernetes Event-driven Autoscaling)](../keda/keda_concepts.md)** — создаёт HPA, который активирует Karpenter.

**[Cluster Autoscaler](../cluster_autoscaler_detailed.md)** — альтернатива Karpenter, не рекомендуется использовать одновременно.

**[Pod Disruption Budget (PDB)](../pod_disruption_budget.md)** — Karpenter учитывает PDB при консолидации.

### Ограничения

**Только облачные провайдеры** — AWS (полная поддержка), Azure, GCP (в разработке).

**Отсутствие поддержки bare-metal** — требует API облачного провайдера.

**Сложность настройки** — требует понимания облачной инфраструктуры.

**Риски стоимости** — неправильная настройка лимитов может привести к лишним затратам.
