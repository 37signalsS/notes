# In-Place Pod Resize

### In-Place Pod Resize (Kubernetes 1.35)

Ранее для обновления ресурсов пода требовался перезапуск всех контейнеров, что приводило к простоям, потере состояния и дополнительной нагрузке на кластер. Теперь можно изменять значения `requests` и `limits` на лету, и `kubelet` применит их без перезагрузки контейнеров.

**Преимущества:**

* **Корректировка ресурсов без сбоев:** Можно увеличивать или уменьшать ресурсы пода без перезапуска приложения, например, при изменении нагрузки или для удовлетворения временных потребностей в ресурсах (пиковые нагрузки, ночные задачи).
* **Более эффективное автоматическое масштабирование:** [Vertical Pod Autoscaler (VPA)](./vpa_detailed.md) теперь может работать эффективнее, изменяя ресурсы подов на лету, а не только рекомендуя изменения, требующие перезапуска.

**Подробнее:** [Официальный блог Kubernetes: In-Place Pod Resize GA in Kubernetes 1.35](https://kubernetes.io/blog/2025/12/19/kubernetes-v1-35-in-place-pod-resize-ga/)

## Практические сценарии

### In-Place Pod Resize (Практические сценарии)

* **Ручное увеличение памяти для пода:**

    ```bash
    kubectl patch pod my-app-pod --type='merge' -p '{"spec":{"containers":[{"name":"app","resources":{"requests":{"memory":"512Mi"},"limits":{"memory":"1Gi"}}}]}}'
    ```

* **Обновление ресурсов через Deployment:**
    Просто отредактируйте `resources` в манифесте `Deployment` и примените через `kubectl apply`. Поды обновятся на месте, если это поддерживается.
* **Использование с VPA:**
    Настройте VPA с режимом `Auto` или `Recreate` (теперь с минимальными перезапусками), и он будет автоматически подбирать ресурсы на основе метрик.
