# Паттерны шардирования: Мониторинг и best practices

## Мониторинг

| Метрика | Описание | Алерт |
|---------|----------|-------|
| `request_latency` | Задержка обработки по шардам | >5 секунд |
| `error_rate` | Процент ошибок по шардам | >1% |
| `replica_count` | Количество реплик в шарде | Отклонение от baseline |
| `resource_utilization` | Использование CPU/memory | >80% |

## Сценарии использования

| Сценарий | Обоснование |
|----------|-------------|
| Мультирегиональное приложение | Локальность данных, compliance (GDPR) |
| Требования к изоляции клиентов | Изоляция сбоев, безопасность |
| Обработка платежей | Изоляция + консистентность данных |
| Real-time аналитика | Разделение по временным окнам |

## Best Practices

### Проектирование шардов

1. **Выбор ключа шардирования:**
   - Равномерное распределение трафика
   - Минимизация перекосов (hot spots)
   - Учёт бизнес-логики

2. **Изоляция шардов:**
   - Отдельные Deployment для каждого шарда
   - Независимое масштабирование
   - Раздельные базы данных при необходимости

3. **Маршрутизация:**
   - Явное указание шарда в Ingress
   - Использование Service Mesh для сложной маршрутизации
   - Клиентская логика для определения шарда

### Масштабирование

1. **Автоматическое масштабирование:**
   - HPA для каждого шарда
   - Разные пороги для разных шардов
   - Учёт часовых поясов и пиков нагрузки

2. **Распределение по узлам:**
   - Pod Anti-Affinity для отказоустойчивости
   - Zone-aware распределение
   - Pod Disruption Budget для защиты

### Ребалансировка

1. **Планирование:**
   - Постепенное перемещение данных
   - Мониторинг нагрузки во время миграции

2. **Consistent Hashing:**
   - Минимизация перемещений при изменении количества шардов
   - Виртуальные шарды для гибкости

3. **Dual-write:**
   - Запись в старый и новый шард во время миграции
   - Проверка консистентности данных
