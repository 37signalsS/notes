# Паттерны масштабирования

## Определения

**Шардирование (Sharding)** — разделение рабочей нагрузки на изолированные группы (шарды) с независимым масштабированием.

**Workers + Queue** — архитектурный паттерн для асинхронной обработки задач через очередь сообщений.

**Producer** — сервис, генерирующий задачи и помещающий их в очередь.

**Consumer (Worker)** — под, извлекающий и обрабатывающий задачи из очереди.

## Основные концепции

### Шардирование

Разделение трафика по ключу позволяет:
- Изолировать сбои между шардами
- Обеспечить локальность данных
- Обойти ограничения отдельных компонентов

**Ключи шардирования:**
- Регион пользователя
- ID клиента
- Тип подписки
- Хеш данных

### Workers + Queue

Архитектура для фоновой обработки:
- Очередь сглаживает пиковые нагрузки
- Workers масштабируются по длине очереди
- Гарантируется доставка сообщений

**Требования к задачам:**
- Идемпотентность — повторная обработка не приводит к ошибкам
- Дедупликация — предотвращение двойной обработки
- Ограничение параллелизма — контроль нагрузки на внешние системы

## Практические сценарии

### Шардирование: реализация

```yaml
# Deployment для шарда A
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webapp-shard-a
spec:
  selector:
    matchLabels:
      app: webapp
      shard: a
  template:
    metadata:
      labels:
        app: webapp
        shard: a
    spec:
      containers:
      - name: app
        image: myapp:latest
        env:
        - name: SHARD_ID
          value: "a"
---
apiVersion: v1
kind: Service
metadata:
  name: service-a
spec:
  selector:
    app: webapp
    shard: a
  ports:
  - port: 80
```

### Workers + Queue: интеграция с HPA

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: workers-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: workers
  minReplicas: 1
  maxReplicas: 50
  metrics:
  - type: External
    external:
      metric:
        name: queue_messages_ready
      target:
        type: AverageValue
        averageValue: "100"
```

### Выбор паттерна

| Сценарий | Рекомендуемый паттерн |
|----------|----------------------|
| Видео-обработка, отчеты | Workers + Queue |
| Мультирегиональное приложение | Шардирование |
| Пиковые нагрузки с непредсказуемым трафиком | Workers + Queue |
| Требования к изоляции клиентов | Шардирование |

## Дополнительная информация

### Интеграция с Kubernetes

- [Horizontal Pod Autoscaler](hpa_detailed.md) — используется для масштабирования workers по длине очереди через внешние метрики
- [Распределение подов](pod_distribution.md) — критически важно для шардирования для обеспечения отказоустойчивости
- [Pod Disruption Budget](pod_disruption_budget.md) — защита workers при масштабировании узлов

### Технологии очередей

- **RabbitMQ** — традиционные очереди с подтверждением доставки
- **Apache Kafka** — потоковая обработка с высокой пропускной способностью
- **AWS SQS** — управляемая очередь без инфраструктурных затрат

### Дополнительные соображения

- **Маршрутизация шардов** — реализуется на уровне Ingress, API Gateway или клиента
- **Ребалансировка** — планирование миграции данных при изменении количества шардов
- **Мониторинг** — отдельные метрики для каждого шарда и длины очереди
