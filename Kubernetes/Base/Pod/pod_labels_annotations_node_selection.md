## Определения

### Метки (Labels)

**Метки** — это пары "ключ-значение", прикрепляемые к объектам Kubernetes (подам, сервисам, деплойментам). Предназначены для **идентификации и группировки** ресурсов.

### Аннотации (Annotations)

**Аннотации** — это пары "ключ-значение", также прикрепляемые к объектам Kubernetes. В отличие от меток, **не предназначены для идентификации**. Используются для хранения **неидентифицирующей служебной информации** и метаданных.

### Привязка подов к узлам (Node Selection)

**Node Selection** — механизм влияния на размещение подов в кластере. Позволяет привязывать поды к определённым узлам или группам узлов.

---

## Основные концепции

### Сравнение Меток и Аннотаций

| Характеристика | Метки (Labels) | Аннотации (Annotations) |
| :--- | :--- | :--- |
| **Назначение** | Идентификация и селекция объектов | Неидентифицирующие метаданные |
| **Использование** | `selector` в `Service`, `Deployment` | Чтение инструментами (Prometheus, Ingress-контроллеры, service mesh) |
| **Ограничения** | Строгие правила синтаксиса | Гибкие, могут содержать любые данные |
| **Влияние на поведение** | Косвенное (через селекторы) | Прямое (управление поведением инструментов) |

### Механизмы привязки к узлам

#### nodeSelector

Простейший способ привязки пода к узлам с определёнными метками. Под запустится только на узлах, имеющих все указанные метки.

#### nodeName

Прямая привязка пода к конкретному узлу по имени. Планировщик попытается разместить под на этом узле.

> **ВНИМАНИЕ:** Использование `nodeName` не рекомендуется для большинства сценариев, так как снижает гибкость и отказоустойчивость.

## Практические сценарии

### Использование `nodeSelector`

`nodeSelector` — это простейший способ ограничить запуск пода только теми узлами, которые имеют определенные метки.

**Рекомендация:** Всегда создавайте собственные осмысленные метки для узлов. Не рекомендуется привязываться к стандартной метке `kubernetes.io/hostname`, так как имена узлов могут меняться, что сделает ваши манифесты хрупкими.

**Сценарий:** Ограничить запуск `DaemonSet` только двумя из трех узлов в кластере.

**Шаг 1: Добавление меток к узлам**

Присвоим нужным узлам пользовательскую метку `special=ds-only`.

```bash
kubectl label nodes control-plane-1 special=ds-only
kubectl label nodes worker-2 special=ds-only
```

**Шаг 2: Просмотр меток**

Убедимся, что метки применились.

```bash
kubectl get nodes --show-labels
```

**Шаг 3: Добавление `nodeSelector` в манифест**

В спецификацию пода (`spec` или `spec.template.spec` для контроллеров) добавляется раздел `nodeSelector`.

```yaml
# daemonset-with-nodeselector.yaml
apiVersion: apps/v1
kind: DaemonSet
# ...
spec:
  template:
    spec:
      nodeSelector:
        special: ds-only # Под будет запущен только на узлах с меткой special=ds-only
      containers:
      # ...
```

После применения манифеста `DaemonSet` запустит поды только на узлах `control-plane-1` и `worker-2`.

**Шаг 4: Удаление метки**

Удаление метки приведет к тому, что узел перестанет удовлетворять условию `nodeSelector`. `DaemonSet` автоматически удалит под с этого узла.

```bash
# Для удаления метки используется тот же ключ с дефисом в конце
kubectl label nodes worker-2 special-
```

### Применение меток

* Размещение подов в определённых зонах доступности
* Выделение узлов с GPU или SSD для определённых workloads
* Группировка подов по окружению (dev/staging/prod)

### Применение аннотаций

Аннотации используются для передачи метаданных инструментам и контроллерам, расширяющим функциональность Kubernetes:

* **Service Mesh (Istio, Linkerd):** Управление внедрением sidecar-прокси
  ```yaml
  metadata:
    annotations:
      sidecar.istio.io/inject: "false"  # Запретить Istio внедрять sidecar
  ```
* **Сбор метрик (Prometheus):** Указание пути и порта для скрейпинга
  ```yaml
  metadata:
    annotations:
      prometheus.io/scrape: "true"
      prometheus.io/port: "8080"
      prometheus.io/path: "/metrics"
  ```
* **Ingress-контроллеры:** Настройка балансировки, SSL, rewrite rules
* **Внешние системы:** Интеграция с Vault, ArgoCD, внешними CI/CD
