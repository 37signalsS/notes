## Определения

### Метки (Labels)

**Метки** — это пары "ключ-значение", прикрепляемые к объектам Kubernetes (подам, сервисам, деплойментам). Предназначены для **идентификации и группировки** ресурсов.

### Аннотации (Annotations)

**Аннотации** — это пары "ключ-значение", также прикрепляемые к объектам Kubernetes. В отличие от меток, **не предназначены для идентификации**. Используются для хранения **неидентифицирующей служебной информации** и метаданных.

### Привязка подов к узлам (Node Selection)

**Node Selection** — механизм влияния на размещение подов в кластере. Позволяет привязывать поды к определённым узлам или группам узлов.

---

## Основные концепции

### Сравнение Меток и Аннотаций

| Характеристика | Метки (Labels) | Аннотации (Annotations) |
| :--- | :--- | :--- |
| **Назначение** | Идентификация и селекция объектов | Неидентифицирующие метаданные |
| **Использование** | `selector` в `Service`, `Deployment` | Чтение инструментами (Prometheus, Ingress-контроллеры) |
| **Ограничения** | Строгие правила синтаксиса | Гибкие, могут содержать любые данные |

### Механизмы привязки к узлам

#### nodeSelector

Простейший способ привязки пода к узлам с определёнными метками. Под запустится только на узлах, имеющих все указанные метки.

#### nodeName

Прямая привязка пода к конкретному узлу по имени. Планировщик попытается разместить под на этом узле.

> **ВНИМАНИЕ:** Использование `nodeName` не рекомендуется для большинства сценариев, так как снижает гибкость и отказоустойчивость.

---

## Практические сценарии

### Использование nodeSelector

Размещение подов на узлах с определёнными характеристиками:

```bash
# Добавление метки к узлу
kubectl label nodes worker-1 disktype=nvme zone=eu-1a
```

```yaml
# Пример пода с nodeSelector
spec:
  nodeSelector:
    disktype: nvme
    gpu: "true"
```

### Применение меток

* Размещение подов в определённых зонах доступности
* Выделение узлов с GPU или SSD для определённых workloads
* Группировка подов по окружению (dev/staging/prod)
