# Продвинутые темы Pod в Kubernetes

## Определения

**Immutable fields** — поля спецификации Pod, которые запрещено изменять после создания объекта. Попытки модификации таких полей отклоняются API сервером Kubernetes.

**Fully Qualified Image Name** — абсолютный путь к образу container, включающий адрес реестра, путь к репозиторию и тег или дайджест (например, `docker.io/library/nginx:1.28.0`).

---

## Базовые концепции

### Редактирование работающего Pod

Команда `kubectl edit pod <pod-name>` позволяет вносить изменения в ограниченный набор полей работающего Pod. Большинство параметров спецификации фиксируются в момент создания.

**Доступные для редактирования поля:**

| Поле | Описание |
| :--- | :--- |
| `spec.containers[*].image` | Имена и теги образов для основных и init-container |
| `spec.tolerations` | Позволяет добавлять новые исключения для Taints |
| `spec.activeDeadlineSeconds` | Установка или изменение лимита времени жизни Pod |

**Неизменяемые поля (примеры):**

| Поле | Причина |
| :--- | :--- |
| `spec.containers` (кроме `image`) | Запрещено добавлять/удалять container, изменять их имена, порты, переменные окружения, лимиты ресурсов или монтирования томов |
| `spec.volumes` | Конфигурация томов фиксируется при запуске |
| `metadata.name`, `metadata.namespace` | Уникальные идентификаторы объекта в кластере |

Для изменения других полей необходимо удалить Pod и создать его заново. В промышленной эксплуатации этот процесс автоматизируется контроллерами, такими как [Deployment](../Deployment/index.md).

### Полные имена образов

При использовании современных рантаймов (например, CRI-O) рекомендуется всегда указывать полные пути к образам. Это исключает двусмысленность и повышает безопасность.

| Формат | Пример | Статус |
| :--- | :--- | :--- |
| **Полное имя** | `docker.io/library/nginx:1.28.0` | **Рекомендуется** |
| **Короткое имя** | `nginx` | Не рекомендуется |

**Механизм поиска образов:**
Если указано короткое имя, Kubernetes пытается найти образ, используя следующие приоритеты:

1. Секреты, указанные в `imagePullSecrets`.
2. Настройки реестров по умолчанию в конфигурации Node.
3. Общедоступный реестр Docker Hub (`docker.io`).

Использование полных имен предотвращает ошибки скачивания, если реестр по умолчанию не настроен или содержит конфликтующие версии.

## Практические сценарии

### Пример 1: Обновление версии образа без пересоздания объекта

```bash
# Проверка текущего образа
kubectl get pod my-app -o jsonpath='{.spec.containers[*].image}'

# Редактирование манифеста в реальном времени
kubectl edit pod my-app

# В открывшемся редакторе замените тег образа:
# image: nginx:1.27 -> image: nginx:1.28

# Сохраните и закройте редактор. Kubelet перезапустит container с новым образом.
```

### Пример 2: Настройка доступа к приватному реестру

Для использования образов из закрытых репозиториев необходимо создать Secret и указать его в спецификации Pod:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: private-app
spec:
  containers:
  - name: app
    image: my-registry.com/project/api:v2.1.0
  imagePullSecrets:
  - name: registry-creds
```

Подробную информацию о создании секретов см. в [Создание Docker Registry Secret](../secrets/creating_secrets.md#docker-registry-secret).
