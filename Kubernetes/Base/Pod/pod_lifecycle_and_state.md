# Жизненный цикл и состояния Pod в Kubernetes

## Определения

**Pod Phase (фаза пода)** — высокоуровневое состояние Pod в кластере, определяемое полем `status.phase` в объекте `PodStatus`. Отражает общую стадию жизненного цикла объекта.

**Pod Conditions (условия пода)** — массив в `status.conditions`, предоставляющий детализированную информацию о различных аспектах состояния Pod (например, готовность к приёму трафика или успешное завершение инициализации).

**Container States (состояния контейнеров)** — текущий статус каждого container (контейнера) внутри Pod: `Waiting` (ожидание), `Running` (выполнение) или `Terminated` (завершено).

**Graceful Shutdown (корректное завершение)** — процедура штатной остановки Pod, при которой приложению отправляется сигнал `SIGTERM` для сохранения данных и завершения активных соединений до принудительного удаления процесса.

**terminationGracePeriodSeconds (период грациозного завершения)** — интервал времени (по умолчанию 30 секунд), выделяемый container на корректное завершение после получения `SIGTERM` до принудительной остановки сигналом `SIGKILL`.

## Базовые концепции

### Фазы Pod

Фаза Pod отражает его положение в жизненном цикле оркестрации.

| Фаза | Описание | Основные причины |
| :--- | :--- | :--- |
| `Pending` | Pod принят системой, но не все container запущены. | Ожидание назначения на Node (узел), скачивание образов, работа init-контейнеров. |
| `Running` | Pod привязан к Node, все container созданы. | Хотя бы один основной container запущен или находится в процессе перезапуска. |
| `Succeeded` | Все container завершены успешно. | Характерно для объектов `Job`, когда работа выполнена с кодом выхода 0. |
| `Failed` | Container завершены, есть ошибки. | Хотя бы один container завершился с ненулевым кодом выхода. |
| `Unknown` | Статус не определен. | Потеря связи с Node, компонент `kubelet` не сообщает о состоянии. |

### Условия Pod (Pod Conditions)

Позволяют понять, почему Pod находится в той или иной фазе.

| Условие | Описание |
| :--- | :--- |
| `PodScheduled` | Pod успешно назначен на конкретную Node. |
| `Initialized` | Все инициализирующие container успешно завершили работу. |
| `ContainersReady` | Все container в Pod готовы к работе. |
| `Ready` | Pod готов принимать трафик (прошел все проверки и готов к включению в Service). |
| `PodReadyToStartContainers` | (K8s 1.29+) Сетевое окружение и sandbox (песочница) настроены. |

### Состояния контейнеров

Внутри одного Pod разные container могут находиться в разных состояниях.

*   **Waiting:** ожидание запуска (например, из-за `ImagePullBackOff` или отсутствия ConfigMap).
*   **Running:** процесс выполняется. Если настроен `postStart` hook, он уже запущен.
*   **Terminated:** выполнение завершено (успешно или с ошибкой). Содержит `Exit Code` (код выхода) для диагностики.

### Политика перезапуска (Restart Policy)

Определяет поведение `kubelet` при завершении работы container. Указывается в `spec.restartPolicy`.

| Политика | Описание | Применение |
| :--- | :--- | :--- |
| `Always` | Перезапуск при любом завершении. | Микросервисы, веб-серверы (по умолчанию). |
| `OnFailure` | Перезапуск только при коде выхода != 0. | Задачи обработки данных, скрипты. |
| `Never` | Перезапуск не выполняется. | Инструменты отладки, разовые тесты. |

Подробности о механизмах перезапуска см. в [Перезапуск Pod в Kubernetes](./pod_restarts.md).

### Обработчики жизненного цикла (Lifecycle Hooks)

Позволяют выполнять команды в ключевые моменты работы container.

1.  **postStart:** выполняется сразу после создания container. Не гарантирует запуск до `entrypoint` приложения. Блокирует переход Pod в состояние `Running` до завершения.
2.  **preStop:** выполняется перед отправкой сигнала `SIGTERM`. Используется для подготовки к выключению (например, завершение транзакций).

### Graceful Shutdown (Корректное завершение)

Процесс удаления Pod включает следующие этапы:
1.  Объект помечается на удаление (устанавливается `deletionTimestamp`).
2.  Выполняется `preStop` hook (если настроен).
3.  Отправляется сигнал `SIGTERM` процессам в container.
4.  Pod исключается из Endpoints (точки доступа) сервисов.
5.  По истечении `terminationGracePeriodSeconds` отправляется `SIGKILL`.

Полное описание процесса приведено в [Pod Terminating: Graceful Shutdown](../../Troubleshooting/Common_Errors/PodTerminating/graceful_shutdown.md).

## Практические сценарии

### Пример 1: Использование Lifecycle Hooks

Пример настройки Pod для корректного завершения Nginx:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-graceful
spec:
  containers:
  - name: nginx
    image: nginx:1.25
    lifecycle:
      preStop:
        exec:
          command: ["/bin/sh", "-c", "sleep 10 && nginx -s quit"]
  terminationGracePeriodSeconds: 45
```

### Пример 2: Диагностика фазы и условий

```bash
# Просмотр фазы и краткого статуса
kubectl get pod <name>

# Детальный просмотр условий (Conditions)
kubectl describe pod <name>

# Получение статуса в формате JSON для автоматизации
kubectl get pod <name> -o jsonpath='{.status.phase}'
```
