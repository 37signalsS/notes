# Kubernetes Secrets: Основы

## Определение

**Secret** — это объект Kubernetes, предназначенный для хранения небольших объемов чувствительных данных, таких как пароли, токены или ключи.

> **Важно:** По умолчанию данные в `Secret` хранятся в `etcd` в кодировке **Base64**, а не в зашифрованном виде. Base64 — это не шифрование, и данные могут быть легко раскодированы.

## Что отличает Secret от ConfigMap

| Признак | Secret | ConfigMap |
| :--- | :--- | :--- |
| **Назначение** | Конфиденциальные данные (пароли, токены, ключи) | Некритичные конфигурационные данные |
| **Доступ** | Подчиняется строгим политикам RBAC | Более открытый доступ |
| **Хранение** | Рекомендуется шифрование в etcd | Хранится в открытом виде |
| **Представление** | `data` (Base64), `stringData` (открытый текст) | `data`, `binaryData` |
| **Типы** | Типизированные форматы (`tls`, `dockerconfigjson`) | Нет специальных типов |

## Типы секретов

*   **Opaque**: Тип по умолчанию, используется для хранения произвольных пар ключ–значение
*   **kubernetes.io/service-account-token**: Автоматически создаются для аутентификации с API-сервером
*   **kubernetes.io/dockerconfigjson**: Применяются для хранения учётных данных Docker Registry
*   **kubernetes.io/basic-auth**: Содержат логины и пароли для базовой аутентификации
*   **kubernetes.io/ssh-auth**: Хранят приватные SSH-ключи
*   **kubernetes.io/tls**: Включают TLS-сертификаты и приватные ключи
*   **bootstrap.kubernetes.io/token**: Используются при подключении новых нод к кластеру
