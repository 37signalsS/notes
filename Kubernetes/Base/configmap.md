# ConfigMap в Kubernetes

## Определения

**ConfigMap** — это объект API Kubernetes, предназначенный для хранения неконфиденциальных данных в формате пар «ключ-значение». Он позволяет отделить конфигурацию приложения от его программного кода (**Separation of Concerns**), обеспечивая переносимость (Portability) образов контейнеров между различными окружениями (dev, staging, production) без их пересборки.

**Ключевое правило:** ConfigMap не предназначен для хранения секретов (паролей, токенов, ключей доступа). Для таких данных следует использовать [Secret](./secrets/secrets_basics.md).

## Основные концепции

### Преимущества внешнего управления конфигурацией

*   **Неизменяемость образов:** Один и тот же артефакт (Docker-образ) используется во всех средах, что гарантирует идентичность кодовой базы.
*   **Динамическое управление:** Настройки можно обновлять независимо от жизненного цикла приложения.
*   **GitOps и Config-as-Code:** Все параметры инфраструктуры версионируются в Git, обеспечивая прозрачность изменений.
*   **Гибкость доставки:** Данные предоставляются приложению как переменные окружения, аргументы командной строки или файлы.

### Ограничения и лимиты

*   **Размер:** Максимальный размер одного объекта ConfigMap ограничен **1 MiB** (жесткий лимит etcd). Для хранения больших объемов данных рекомендуется использовать `PersistentVolume`.
*   **Типы данных:** 
    *   `data`: Текстовые данные в кодировке UTF-8.
    *   `binaryData`: Бинарные файлы, закодированные в **Base64** (автоматически обрабатываются `kubectl`).
*   **Область видимости:** Ресурс уровня **Namespace**. Поды могут использовать только ConfigMap из своего пространства имен.

### Структура объекта

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-settings
data:
  LOG_LEVEL: "DEBUG"
  config.yaml: |
    database:
      host: "db.local"
binaryData:
  favicon.ico: "iVBORw0KGgoAAAANSUh..."
```

## Практические сценарии

### Способы подключения и обновления

| Метод | Особенности | Обновление «на лету» (Hot Reload) |
| :--- | :--- | :--- |
| **Переменные окружения** | Через `env` или `envFrom`. Просты в использовании. | **Нет** (требуется рестарт пода) |
| **Смонтированные тома** | ConfigMap монтируется как директория с файлами. | **Да** (через ~60–90 секунд) |
| **subPath монтирование** | Позволяет монтировать файл в существующую папку. | **Нет** (файл не обновится без рестарта) |

### Механизм атомарного обновления (Atomic Symlink Swap)

При монтировании как тома `kubelet` использует систему символических ссылок:
1. Создается новая директория с данными.
2. Ссылка `..data` атомарно переключается на новую директорию.
Это гарантирует, что приложение не прочитает файл в промежуточном состоянии.

### Флаг необязательности (Optional)

Параметр `optional: true` позволяет поду успешно запуститься, даже если ConfigMap или указанный ключ отсутствуют. По умолчанию этот флаг равен `false`, и отсутствие ресурса приведет к ошибке `CreateContainerConfigError`.

### Взаимодействие с Native Sidecars (v1.29+)

Нативные sidecar-контейнеры (init-контейнеры с `restartPolicy: Always`) могут использовать ConfigMap для настройки прокси или агентов. Они запускаются первыми, поэтому ConfigMap должен существовать до старта пода.

## Безопасность и производительность

### Контроллер NodeRestriction

 Admission-контроллер **NodeRestriction** ограничивает доступ `kubelet` только к тем ConfigMap и Secret, которые используются подами, запущенными на конкретном узле, снижая радиус поражения при компрометации узла.

### Неизменяемые (Immutable) ConfigMap

Начиная с Kubernetes v1.21, поддерживается поле `immutable: true`. 
**Преимущества:**
1.  **Производительность:** `kubelet` отключает `watch` для этого ресурса, что существенно снижает нагрузку на API-сервер и etcd в больших кластерах.
2.  **Защита:** Предотвращает случайные изменения конфигурации вручную. Обновление происходит через создание нового объекта (паттерн хеширования имен в Helm/Kustomize).

Подробнее см. в разделе **[Неизменяемые ConfigMap](./ConfigMap/immutable.md)**.
