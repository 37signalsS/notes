# ConfigMap

## Определения

**ConfigMap** — это объект API Kubernetes, предназначенный для хранения неконфиденциальных данных в формате пар «ключ-значение». Он позволяет отделить конфигурацию приложения от его программного кода (**Separation of Concerns**), обеспечивая переносимость (Portability) образов контейнеров между различными окружениями (dev, staging, production) без их пересборки.

**Ключевое правило:** ConfigMap не предназначен для хранения секретов (паролей, токенов, ключей доступа). Для таких данных следует использовать [Secret](./secrets/secrets_basics.md).

## Основные концепции

### Преимущества внешнего управления конфигурацией

Использование ConfigMap решает ряд критических проблем традиционной упаковки настроек внутрь образа:

*   **Неизменяемость образов:** Один и тот же Docker-образ используется во всех средах, что гарантирует идентичность кодовой базы.
*   **Динамическое управление:** Настройки можно обновлять независимо от жизненного цикла приложения.
*   **Централизация:** Все параметры инфраструктуры и приложений хранятся и версионируются в одном месте (например, в Git через GitOps).
*   **Гибкость доставки:** Данные могут предоставляться приложению как переменные окружения, аргументы командной строки или файлы в смонтированных томах.

### Ограничения и лимиты

*   **Размер:** Максимальный размер одного объекта ConfigMap ограничен **1 MiB** (лимит etcd).
*   **Типы данных:** 
    *   Поле `data`: Строки в кодировке UTF-8.
    *   Поле `binaryData`: Бинарные данные (сертификаты, изображения), закодированные в **Base64**.
*   **Область видимости:** ConfigMap является ресурсом уровня **Namespace**. Поды могут использовать только те ConfigMap, которые находятся в том же пространстве имен.

### Структура объекта

Объект не содержит секции `spec`. Все данные описываются непосредственно в полях `data` или `binaryData`.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-settings
data:
  # Простой ключ
  LOG_LEVEL: "DEBUG"
  # Многострочный файл
  config.yaml: |
    database:
      host: "db.local"
      port: 5432
binaryData:
  favicon.ico: "iVBORw0KGgoAAAANSUh..."
```

## Практические сценарии

### Основные способы подключения к Pod

| Метод | Особенности | Обновление «на лету» |
| :--- | :--- | :--- |
| **Переменные окружения** | Через `env` или `envFrom`. Значения фиксируются при старте процесса. | Нет (нужен рестарт Pod) |
| **Смонтированные тома** | ConfigMap монтируется как директория с файлами. | Да (через ~60с) |
| **Projected Volume** | Агрегация нескольких ConfigMap/Secret в одну папку. | Да |

### Флаг необязательности (Optional)

При подключении ConfigMap можно указать параметр `optional: true`. В этом случае, если ресурс ConfigMap отсутствует в кластере, Kubernetes позволит поду запуститься (переменные окружения будут пустыми, а файлы в томе не появятся). По умолчанию этот флаг равен `false`, и отсутствие ConfigMap заблокирует запуск пода (`CreateContainerConfigError`).

```yaml
env:
  - name: FEATURE_FLAG
    valueFrom:
      configMapKeyRef:
        name: optional-config
        key: feature-x
        optional: true
```

### Взаимодействие с Native Sidecars (v1.29+)

При использовании нативных sidecar-контейнеров (init-контейнеры с `restartPolicy: Always`) важно учитывать, что они запускаются первыми. Если sidecar-контейнер требует ConfigMap для своей работы, этот ресурс должен существовать до попытки запуска пода. Обновление ConfigMap в смонтированном томе sidecar-контейнера происходит по тем же правилам, что и для основных контейнеров.

## Безопасность и производительность

### Контроллер NodeRestriction

В целях безопасности в Kubernetes часто включен Admission-контроллер **NodeRestriction**. Он ограничивает доступ `kubelet` только к тем объектам ConfigMap и Secret, которые явно используются подами, запущенными на конкретном узле. Это предотвращает компрометацию всех конфигураций кластера при взломе одного узла.

### Неизменяемые (Immutable) ConfigMap

Начиная с Kubernetes v1.21, поддерживается поле `immutable: true`. 
**Преимущества:**
1.  **Производительность:** Kubelet перестает отслеживать изменения (Watch) этого ресурса, что существенно снижает нагрузку на API-сервер в больших кластерах.
2.  **Надежность:** Защита от случайного изменения конфигурации вручную. Обновление происходит путем создания нового объекта с новым именем (хеширование имен).

Подробнее см. в разделе **[Неизменяемые ConfigMap](./ConfigMap/immutable.md)**.
