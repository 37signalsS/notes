# Неизменяемые (Immutable) ConfigMap

## Определения

**Immutable ConfigMap** (неизменяемый ConfigMap) — это объект API (Application Programming Interface) Kubernetes, в спецификации которого установлен флаг `immutable: true`. После создания такого объекта его данные (`data` и `binaryData`) невозможно изменить.

## Основные концепции

### Назначение

Механизм неизменяемых ресурсов используется для конфигураций, которые остаются статичными на протяжении всего жизненного цикла приложения. Это исключает риск случайной порчи настроек и гарантирует, что все поды (Pods) используют идентичную конфигурацию.

### Преимущества

* **Безопасность:** предотвращение несанкционированного или случайного изменения критических настроек даже пользователями с правами на редактирование.
* **Производительность:** значительно снижает нагрузку на `kube-apiserver` и `kubelet`. Для обычных ресурсов `kubelet` устанавливает наблюдение (watch) за изменениями. Для неизменяемых ресурсов это не требуется, что экономит вычислительные ресурсы и снижает трафик в больших кластерах.
* **Предсказуемость:** любые изменения конфигурации требуют полноценного процесса `rollout` (развёртывания), что позволяет проходить все стадии CI/CD (Continuous Integration / Continuous Deployment) и аудита.

## Практические сценарии

### Создание неизменяемой ConfigMap

Пример манифеста для создания неизменяемого ресурса:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config-v1
immutable: true # Установка флага неизменяемости
data:
  LOG_LEVEL: "info"
  MAX_CONNECTIONS: "100"
```

**Применение манифеста:**
```bash
kubectl apply -f configmap-v1.yaml
# → configmap/app-config-v1 created
```

### Попытка изменения

Если попытаться изменить поле `data` в существующем неизменяемом объекте:

```bash
kubectl patch configmap app-config-v1 -p '{"data":{"LOG_LEVEL":"debug"}}'
```

**Ожидаемый результат:**
```text
Error from server (BadRequest): error when patching "configmap/app-config-v1": cannot modify fields other than 'metadata' for immutable configmap
```

> **Примечание:** Изменение метаданных (например, `labels` или `annotations`) по-прежнему разрешено.

### Обновление конфигурации

Поскольку данные ресурса нельзя изменить, для обновления конфигурации используется один из двух подходов:

1. **Создание нового ресурса (рекомендуемый подход):** создаётся ConfigMap с новым именем (например, на основе хэша содержимого или версии `app-config-v2`), и ссылка на него обновляется в `Deployment` или `StatefulSet`. Это инициирует контролируемый перезапуск подов.
2. **Принудительное пересоздание:**
   ```bash
   kubectl apply -f configmap-v1.yaml --force
   # → configmap/app-config-v1 configured
   ```
   *Примечание: флаг `--force` удаляет и заново создаёт объект.*

## Дополнительная информация

### Сравнение типов ConfigMap

| Характеристика | Изменяемый (Mutable) | Неизменяемый (Immutable) |
| :--- | :--- | :--- |
| **Изменение данных** | Разрешено в любое время | Запрещено после создания |
| **Обновление в поде** | Автоматически (при монтировании тома) | Требует перезапуска пода |
| **Нагрузка на Control Plane** | Постоянное наблюдение (Watch) | Минимальная (только чтение) |
| **Рекомендуемая среда** | Разработка, эксперименты | Production, критические системы |

### Рекомендации по использованию

- **Используйте для:** версионированных конфигураций, статических файлов настроек, релизных циклов.
- **Не используйте для:** динамических параметров, Feature Flags (флагов функций) или настроек, которые должны применяться мгновенно без перезапуска приложения.
