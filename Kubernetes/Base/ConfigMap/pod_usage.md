# Способы использования ConfigMap в подах

## Определения

**ConfigMap** — объект API (Application Programming Interface) Kubernetes для хранения конфигурационных данных, которые могут быть предоставлены подам (Pods) различными способами.

**Пользовательские сценарии использования:**
- **Переменные окружения** (`env`, `envFrom`) — передача простых параметров и флагов.
- **Смонтированные тома** (`volume`) — монтирование конфигурационных файлов в файловую систему контейнера.
- **Projected volumes** (проектируемые тома) — объединение нескольких источников данных в одну точку монтирования.

## Основные концепции

### Двухэтапный процесс подключения через тома

Для использования ConfigMap как файлов в контейнере необходимо выполнить два последовательных действия в манифесте Pod:

1.  **Объявление тома (Volumes)** — на уровне спецификации пода (`spec.volumes`) создаётся виртуальный диск, источником которого является указанный ConfigMap.
2.  **Монтирование тома (VolumeMounts)** — внутри описания конкретного контейнера (`spec.containers[*].volumeMounts`) указывается путь в файловой системе, куда будет подключен объявленный ранее том.

**Аналогия:** Процесс идентичен подключению внешнего накопителя к серверу: сначала устройство подключается к физическому порту (Volumes), затем монтируется в конкретную директорию ОС (VolumeMounts).

### Сравнение способов подключения

| Способ | Типичные сценарии | Автоматическое обновление | Особенности |
| :--- | :--- | :--- | :--- |
| **`env` / `envFrom`** | Флаги запуска, логины, настройки приложения | **Нет** (требуется рестарт Pod) | Простота настройки, значения фиксируются при старте. |
| **`volume`** | Сложные файлы конфигурации (`.yaml`, `.conf`, `.xml`) | **Да** (атомарное обновление в течение ~1 минуты) | Самый гибкий и мощный способ. |
| **`subPath`** | Подмена одного файла в существующей директории | **Нет** (блокирует автоматическое обновление) | Позволяет не скрывать остальные файлы в целевой папке. |
| **`projected`** | Комбинация ConfigMap, Secret и Downward API | **Да** (аналогично `volume`) | Единая точка доступа для разных типов ресурсов. |

## Практические сценарии

### Переменные окружения (`env`, `envFrom`)

Подходит для передачи небольших строковых параметров, которые приложение считывает из окружения (environment variables).

```yaml
spec:
  containers:
    - name: my-app
      image: my-app:1.2.0
      env:
        # 1. Передача значения конкретного ключа
        - name: APP_COLOR_SETTING
          valueFrom:
            configMapKeyRef:
              name: app-config # Имя ConfigMap
              key: APP_COLOR    # Ключ в ConfigMap
              optional: false   # Ошибка при отсутствии ресурса
      # 2. Передача всех ключей ConfigMap как переменных
      envFrom:
        - configMapRef:
            name: app-config
```

### Файлы в томе (`volume`)

ConfigMap монтируется как директория, где каждый ключ становится отдельным файлом, а значение — его содержимым.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-config-pod
spec:
  containers:
    - name: nginx
      image: nginx:1.29.0
      volumeMounts:
        - name: config-storage
          mountPath: /etc/nginx/conf.d
          readOnly: true
  volumes:
    - name: config-storage
      configMap:
        name: app-config
        defaultMode: 0644 # Права доступа к файлам
        items:
          - key: nginx.conf
            path: site.conf # Переименование ключа при монтировании
```

### Использование `subPath`

Позволяет смонтировать файл из ConfigMap в директорию, в которой уже есть другие файлы, не скрывая их.

```yaml
volumeMounts:
  - name: extra-config
    mountPath: /etc/app/override.conf
    subPath: override.conf
volumes:
  - name: extra-config
    configMap:
      name: custom-settings
```

> **Важно:** При использовании `subPath` автоматическое обновление файла в контейнере при изменении ConfigMap **не происходит**. Требуется перезапуск пода (например, через `kubectl rollout restart`).

### Проектируемые тома (Projected volumes)

Используются для объединения данных из разных ConfigMap и Secret в одну директорию.

```yaml
volumes:
  - name: unified-config
    projected:
      sources:
        - configMap:
            name: app-settings
        - secret:
            name: db-credentials
        - downwardAPI:
            items:
              - path: "labels"
                fieldRef:
                  fieldPath: metadata.labels
```

## Дополнительная информация

### Рекомендации по выбору

- Используйте **`volume`** для большинства случаев, так как это обеспечивает атомарное обновление данных без перезапуска контейнера (если приложение поддерживает перечитку конфигов).
- Используйте **`envFrom`** для массового импорта настроек, если приложение не поддерживает чтение из файлов.
- Избегайте **`subPath`**, если вам критично обновление конфигурации «на лету» без рестарта подов.
- Всегда устанавливайте **`readOnly: true`** в `volumeMounts` для предотвращения случайного изменения смонтированных данных процессом внутри контейнера.
