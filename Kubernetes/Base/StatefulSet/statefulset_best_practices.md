# StatefulSet: Лучшие практики

## Определения

**StatefulSet** — это Kubernetes-контроллер для управления stateful-приложениями с гарантиями порядка, стабильных идентификаторов и постоянного хранилища.

## Основные рекомендации

### Высокая доступность

*   **Используйте [PodDisruptionBudget](../high_availability.md)** для защиты от плановых выселений при обслуживании нод. Это критически важно для баз данных и брокеров сообщений.
*   **Настраивайте `podAntiAffinity`** для распределения подов по разным зонам доступности. Это обеспечит отказоустойчивость при выходе из строя одной зоны. Подробнее в статье [Affinity и Anti-Affinity](../../Scheduling/affinity.md).

### Управление хранилищем

*   **[Настройте `volumeBindingMode: WaitForFirstConsumer`](../../Storage/pv_and_pvc.md)** в StorageClass. Это предотвращает создание томов до того, как под будет запланирован на узел, гарантируя совместимость по zone constraints.
*   **Используйте подходящий StorageClass** — выбирайте классы хранилища с поддержкой snapshots, replication и multi-AZ для production-нагрузок.
*   **Регулярно делайте бэкапы PVC**, несмотря на их постоянство. Политика `reclaimPolicy: Retain` защищает данные, но не является заменой резервного копирования.

### Проверка состояния

*   **Настройте `readinessProbe`** для корректного определения готовности пода к приему трафика. Без этого StatefulSet может начать создавать следующий под до того, как текущий будет готов принимать запросы.
*   **Настройте `livenessProbe`** для перезапуска зависших контейнеров.

### Управление жизненным циклом

*   **Используйте `whenScaled` policy** (Kubernetes 1.27+) для управления поведением PVC при уменьшении масштаба:
    *   `Retain` (по умолчанию) — PVC остается после удаления пода
    *   `Delete` — PVC удаляется вместе с подом
*   **Удаляйте StatefulSet аккуратно** — при удалении StatefulSet поды удаляются в обратном порядке, но PVC **не удаляются автоматически**. Это защита от случайной потери данных.
*   **Тестируйте операции масштабирования** в staging-среде перед production. Масштабирование StatefulSet медленнее, чем Deployment, из-за упорядоченного создания подов.

### Обновления

*   **Используйте `partition` в `updateStrategy`** для канареечных развертываний. Обновятся только поды с индексом ≥ partition.
*   **Избегайте частых перезапусков** подов — это влияет на доступность, особенно для приложений с одним экземпляром.
