# StatefulSet: Обзор

## Определения

**StatefulSet** — основной контроллер Kubernetes для управления приложениями с состоянием (stateful). В отличие от **[Deployment](../Deployment/index.md)**, который рассматривает поды как взаимозаменяемые экземпляры (stateless), StatefulSet обеспечивает уникальность, предсказуемость и стабильную идентичность для каждого пода.

Данный контроллер необходим приложениям, которым требуются:
*   **Стабильные сетевые идентификаторы:** имена подов сохраняются при перезапусках и миграциях между узлами.
*   **Стабильное хранилище:** каждый под привязан к конкретному диску через **[PersistentVolumeClaim (PVC)](../../Storage/pv_and_pvc.md)**.
*   **Упорядоченность:** строгий порядок развертывания, масштабирования и обновления.

Базовые концепции архитектур см. в разделе **[Stateful vs Stateless](../../../Concepts/stateful_vs_stateless.md)**.

## Основные концепции

### Архитектурные компоненты

Для полноценной работы StatefulSet требует взаимодействия четырех ключевых объектов:

1.  **StatefulSet Controller:** Управляет жизненным циклом подов на основе шаблона.
2.  **Headless Service:** Обеспечивает прямые DNS-записи для каждого пода. Подробнее: **[Headless Service](../../Networking/Service/service_type_headless.md)**.
3.  **VolumeClaimTemplates:** Шаблон, по которому контроллер автоматически создает уникальный PVC для каждого индекса пода.
4.  **PersistentVolume (PV):** Физические или облачные диски, к которым подключаются PVC.

### Ключевые гарантии и механизмы

| Механизм | Описание |
| :--- | :--- |
| **Стабильные имена** | Поды именуются как `name-0`, `name-1` и т.д. Эти имена не меняются никогда. |
| **Стабильный DNS** | Запись вида `pod-index.service.namespace.svc.cluster.local` всегда ведет на конкретный экземпляр. |
| **Липкое хранилище** | Если под `db-0` упал и поднялся на другом конце кластера, он автоматически получит тот же диск `data-db-0`. |
| **Порядок операций** | По умолчанию создание идет от 0 до N-1, а удаление — в обратном порядке (LIFO). |

Подробнее о внутренних механизмах: **[Ключевые концепции StatefulSet](./statefulset_core_concepts.md)**.

## Практические сценарии

### Когда выбирать StatefulSet

1.  **Кластерные базы данных:** PostgreSQL (Patroni), MySQL (Galera), MongoDB (ReplicaSet), Redis (Cluster).
2.  **Брокеры сообщений:** Kafka (требует стабильных ID брокеров), RabbitMQ.
3.  **Системы координации:** ZooKeeper, etcd, Consul.
4.  **Специфические нагрузки:** Приложения, требующие строгой привязки лицензий к имени хоста или IP.

### Базовые команды управления

```bash
# Создание или обновление
kubectl apply -f statefulset.yaml

# Наблюдение за последовательным запуском
kubectl get pods -w

# Масштабирование (Scale up/down)
kubectl scale statefulset web --replicas=5

# Удаление (диски PVC по умолчанию останутся в кластере!)
kubectl delete statefulset web
```

## Дополнительная информация

### Современные возможности (v1.31+)

*   **Политика удержания PVC (`persistentVolumeClaimRetentionPolicy`):** Позволяет настроить автоматическое удаление дисков при удалении контроллера или уменьшении реплик (GA в 1.32).
*   **Произвольный старт индексов (`ordinals`):** Возможность начать нумерацию, например, с 5 (GA в 1.31).
*   **Метки индексов:** Каждый под автоматически получает метку `apps.kubernetes.io/pod-index` (GA в 1.31), что упрощает фильтрацию логов и маршрутизацию.

### Ограничения

*   **Split-brain:** При отказе узла Kubernetes не переносит поды StatefulSet автоматически, чтобы избежать одновременной записи двух процессов на один диск. Требуется ручное вмешательство или настройка **Non-Graceful Node Shutdown**.
*   **Скорость:** Из-за последовательного запуска масштабирование больших наборов (например, 100 подов) может занимать длительное время.
