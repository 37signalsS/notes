# Kubernetes Job

**Job** в Kubernetes — это объект, который создаёт один или несколько подов и гарантирует, что определённое количество из них успешно завершит свою работу. В отличие от `Deployment` или `ReplicaSet`, которые поддерживают постоянную работу подов, `Job` предназначен для выполнения задач, которые должны начаться, выполниться и успешно завершиться

### Когда использовать Job?

Если вам нужно выполнять `Job` по расписанию, используйте [CronJob](./cron_job.md).

- **Миграции базы данных:** Применение схемы или перенос данных при развёртывании новой версии приложения.
- **Резервное копирование:** Создание бэкапов данных из томов (`PersistentVolume`).
- **Обработка данных:** Запуск скриптов для анализа, очистки или ETL-процессов.
- **Тестирование:** Выполнение тестов в изолированном окружении.

## Структура Job

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: my-job
spec:
  # --- Шаблон пода ---
  template:
    spec:
      containers:
      - name: my-container
        image: busybox:1.36.1
        command: ["sh",  "-c", "echo 'Hello, Kubernetes!' && sleep 15 && echo 'Done.'"]
      # --- Политика перезапуска ---
      # Never: Не перезапускать под, если он завершился (успешно или с ошибкой).
      # OnFailure: Перезапускать контейнер внутри пода, если он завершился с ошибкой.
      restartPolicy: Never

  # --- Управление выполнением и отказами ---

  # Количество успешных завершений, которое должно быть достигнуто.
  # По умолчанию: 1
  completions: 1

  # Количество подов, которые могут выполняться параллельно.
  # По умолчанию: 1
  parallelism: 1

  # Количество повторных попыток перед тем, как пометить Job как неудавшийся (failed).
  backoffLimit: 4

  # Ограничение по времени (в секундах), в течение которого Job может быть активен.
  # Если время истекло, Job будет помечен как failed.
  # activeDeadlineSeconds: 60

  # Автоматическое удаление Job через N секунд после его завершения (успешного или неудачного).
  # Полезно для очистки "мусора".
  ttlSecondsAfterFinished: 100
```

### Ключевые поля в `spec`:

- `template`: Это обязательное поле, которое описывает шаблон пода для запуска. Структура полностью аналогична шаблонам в `Deployment` или `ReplicaSet`.
- `restartPolicy`: Определяет, как поступать с подами. Для `Job` допустимы только значения `Never` или `OnFailure`. `Never` — самый распространённый вариант, так как задача должна завершиться, а не работать вечно.
- `backoffLimit`: Если под завершается с ошибкой, Kubernetes будет пытаться создать новый под. Этот параметр ограничивает количество таких попыток.
- `completions`: Сколько подов должны успешно завершиться. По умолчанию `1`.
- `parallelism`: Сколько подов могут работать одновременно. Полезно для пакетной обработки данных.
- `ttlSecondsAfterFinished`: Отличная функция для автоматической очистки. Kubernetes удалит объект `Job` (и связанные с ним поды) через указанное время после завершения.

## Управление Job

1.  **Создать Job:**

    ```bash
    kubectl apply -f my-job.yaml
    ```

2.  **Проверить статус:**

    ```bash
    # Посмотреть список всех Job
    kubectl get jobs

    # Получить детальную информацию о конкретном Job
    kubectl describe job my-job
    ```

3.  **Посмотреть логи:**

    Сначала найдите имя пода, созданного `Job`:

    ```bash
    kubectl get pods --selector=job-name=my-job
    ```

    Затем посмотрите его логи:

    ```bash
    kubectl logs <имя-пода>
    ```

4.  **Удалить Job:**

    При удалении `Job` также удаляются все созданные им поды.

    ```bash
    kubectl delete job my-job
    ```

    Если вы использовали `ttlSecondsAfterFinished`, Kubernetes сделает это за вас.
