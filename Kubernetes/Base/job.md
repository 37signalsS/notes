# Job и CronJob

## Определения

**Job** в Kubernetes — это объект, который создаёт один или несколько подов и гарантирует, что определённое количество из них успешно завершит свою работу. Это **одноразовая задача**. В отличие от [Deployment](./deployment.md), который поддерживает постоянную работу подов, `Job` предназначен для выполнения задач, которые должны начаться, выполниться и успешно завершиться.

**CronJob** — это объект, который управляет `Job` и запускает их по заданному расписанию (например, `каждый день в 3 часа ночи`).

### Ключевые сценарии использования

*   **Миграции базы данных:** Применение схемы или перенос данных.
*   **Резервное копирование:** Создание бэкапов данных из томов (`PersistentVolume`).
*   **Обработка данных:** Запуск скриптов для анализа, очистки или ETL-процессов.
*   **Запуск тестов:** Выполнение тестов в изолированном окружении.
*   **Регулярные отчеты** или отправка email-сообщений.

## Основные концепции

### Концепции Job

- **`template`**: Обязательное поле, описывающее шаблон пода для запуска.
- **`restartPolicy`**: Определяет политику перезапуска контейнеров в поде. Для `Job` допустимы только:
    - `OnFailure`: Перезапускать контейнер, если он завершился с ошибкой.
    - `Never`: Никогда не перезапускать контейнер. `Job` сам управляет созданием новых подов в случае неудачи.
- **`completions`**: Количество подов, которые должны успешно завершиться. По умолчанию `1`.
- **`parallelism`**: Сколько подов могут работать одновременно. По умолчанию `1`.
- **`backoffLimit`**: Количество повторных попыток перед тем, как `Job` будет помечен как неудавшийся (`failed`).
- **`ttlSecondsAfterFinished`**: Kubernetes автоматически удалит объект `Job` (и его поды) через указанное время после завершения, чтобы избежать "замусоривания" кластера.

### Концепции CronJob

`CronJob` создаёт объекты `Job` на основе `jobTemplate` по расписанию.

- **`schedule`**: Расписание в формате `cron` (например, `"0 2 * * *"` — каждый день в 2 часа ночи).
- **`jobTemplate`**: Шаблон для создания `Job`.
- **`startingDeadlineSeconds`**: Максимальное время в секундах для запуска `Job`, если он пропустил запланированное время.
- **`concurrencyPolicy`**: Политика параллелизма:
    - `Allow` (по умолчанию): Позволяет запускать несколько `Job` одновременно.
    - `Forbid`: Запрещает параллельный запуск. Если предыдущий `Job` еще не завершен, новый будет пропущен.
    - `Replace`: Заменяет текущий активный `Job` новым.
- **`successfulJobsHistoryLimit`**: Количество успешно завершенных `Job` для хранения (по умолчанию `3`).
- **`failedJobsHistoryLimit`**: Количество неудачно завершенных `Job` для хранения (по умолчанию `1`).

## Практические сценарии

### Пример манифеста Job

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: my-job
spec:
  ttlSecondsAfterFinished: 100
  backoffLimit: 4
  template:
    spec:
      containers:
      - name: my-container
        image: busybox:1.36.1
        command: ["sh",  "-c", "echo 'Hello, Kubernetes!' && sleep 15 && echo 'Done.'"]
      # --- Политика перезапуска ---
      # Never: Не перезапускать под, если он завершился (успешно или с ошибкой).
      # OnFailure: Перезапускать контейнер внутри пода, если он завершился с ошибкой.
      restartPolicy: Never

  # --- Управление выполнением и отказами ---

  # Количество успешных завершений, которое должно быть достигнуто.
  # По умолчанию: 1
  completions: 1

  # Количество подов, которые могут выполняться параллельно.
  # По умолчанию: 1
  parallelism: 1

  # Количество повторных попыток перед тем, как пометить Job как неудавшийся (failed).
  backoffLimit: 4

  # Ограничение по времени (в секундах), в течение которого Job может быть активен.
  # Если время истекло, Job будет помечен как failed.
  # activeDeadlineSeconds: 60

  # Автоматическое удаление Job через N секунд после его завершения (успешного или неудачного).
  # Полезно для очистки "мусора".
  ttlSecondsAfterFinished: 100
```

### Пример манифеста CronJob

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-cronjob
spec:
  # Запускать каждый день в 2 часа ночи
  schedule: "0 2 * * *"
  jobTemplate: # Это шаблон для создания Job
    spec:
      template:
        spec:
          containers:
          - name: backup-container
            image: backup-tool
            command: ["/bin/sh", "-c", "run-backup.sh"]
          restartPolicy: OnFailure
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
```

### Управление через kubectl

1.  **Создать:**
    ```bash
    kubectl apply -f my-job.yaml
    kubectl apply -f my-cronjob.yaml
    ```

2.  **Проверить статус:**
    ```bash
    # Посмотреть список
    kubectl get jobs
    kubectl get cronjobs

    # Получить детальную информацию
    kubectl describe job my-job
    kubectl describe cronjob backup-cronjob
    ```

3.  **Посмотреть логи:**
    Сначала найдите имя пода, созданного `Job`:
    ```bash
    kubectl get pods --selector=job-name=my-job
    ```
    Затем посмотрите его логи:
    ```bash
    kubectl logs <имя-пода>
    ```

4.  **Удалить:**
    При удалении `Job` также удаляются все созданные им поды. При удалении `CronJob` удаляются все `Job`, которые он создал.
    ```bash
    kubectl delete job my-job
    kubectl delete cronjob backup-cronjob
    ```
