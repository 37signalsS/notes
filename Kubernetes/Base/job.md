# Kubernetes Job и CronJob

**Job** в Kubernetes — это объект, который создаёт один или несколько подов и гарантирует, что определённое количество из них успешно завершит свою работу. Это **одноразовая задача**. Если что-то завершается с ошибкой, `Job` будет запускать новые копии подов, пока количество успешных выполнений не будет равно заданному. В отличие от `Deployment` или `ReplicaSet`, которые поддерживают постоянную работу подов, `Job` предназначен для выполнения задач, которые должны начаться, выполниться и успешно завершиться.

**CronJob** — это объект, который управляет `Job` и запускает их по заданному расписанию (например, `каждый день в 3 часа ночи`).

Они идеально подходят для таких задач, как:
- **Миграции базы данных:** Применение схемы или перенос данных при развёртывании новой версии приложения.
- **Резервное копирование:** Создание бэкапов данных из томов (`PersistentVolume`).
- **Обработка данных:** Запуск скриптов для анализа, очистки или ETL-процессов.
- **Запуск тестов:** Выполнение тестов в изолированном окружении.
- **Регулярные отчеты** или отправка email-сообщений.
- **Выполнение одноразовых скриптов.**

## Job

`Job` обеспечивает выполнение задачи до её успешного завершения.

### Структура Job

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: my-job
spec:
  # --- Шаблон пода ---
  template:
    spec:
      containers:
      - name: my-container
        image: busybox:1.36.1
        command: ["sh",  "-c", "echo 'Hello, Kubernetes!' && sleep 15 && echo 'Done.'"]
      # --- Политика перезапуска ---
      # Never: Не перезапускать под, если он завершился (успешно или с ошибкой).
      # OnFailure: Перезапускать контейнер внутри пода, если он завершился с ошибкой.
      restartPolicy: Never

  # --- Управление выполнением и отказами ---

  # Количество успешных завершений, которое должно быть достигнуто.
  # По умолчанию: 1
  completions: 1

  # Количество подов, которые могут выполняться параллельно.
  # По умолчанию: 1
  parallelism: 1

  # Количество повторных попыток перед тем, как пометить Job как неудавшийся (failed).
  backoffLimit: 4

  # Ограничение по времени (в секундах), в течение которого Job может быть активен.
  # Если время истекло, Job будет помечен как failed.
  # activeDeadlineSeconds: 60

  # Автоматическое удаление Job через N секунд после его завершения (успешного или неудачного).
  # Полезно для очистки "мусора".
  ttlSecondsAfterFinished: 100
```

### Ключевые поля `Job` в `spec`:

- `template`: Обязательное поле, описывающее шаблон пода для запуска.
- `restartPolicy`: Для `Job` допустимы только `Never` или `OnFailure`. `Never` — самый частый вариант.
- `backoffLimit`: Ограничивает количество повторных попыток при сбое пода.
- `completions`: Сколько подов должны успешно завершиться.
- `parallelism`: Сколько подов могут работать одновременно.
- `ttlSecondsAfterFinished`: Kubernetes удалит объект `Job` через указанное время после завершения, чтобы избежать "замусоривания" кластера.

## CronJob: Запуск Job по расписанию

`CronJob` создаёт объекты `Job` в соответствии с заданным расписанием в формате `cron`.

### Пример `CronJob`

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-cronjob
spec:
  # Запускать каждый день в 2 часа ночи
  schedule: "0 2 * * *"
  jobTemplate: # Это шаблон для создания Job
    spec:
      template:
        spec:
          containers:
          - name: backup-container
            image: backup-tool
            command: ["/bin/sh", "-c", "run-backup.sh"]
          restartPolicy: OnFailure
```

### Важные параметры `CronJob` (spec)

Помимо расписания (`schedule`), `CronJob` имеет несколько ключевых параметров:

- **`startingDeadlineSeconds`**: Максимальное время в секундах, в течение которого `CronJob` может запустить `Job`, если он пропустил запланированное время. Если время упущено, запуск считается пропущенным.

- **`concurrencyPolicy` (Политика параллелизма)**:
    - **`Allow` (по умолчанию):** Позволяет запускать несколько `Job` одновременно.
    - **`Forbid`:** Запрещает параллельный запуск. Если предыдущий `Job` еще не завершен, новый будет пропущен.
    - **`Replace`:** Заменяет текущий активный `Job` новым.

- **`successfulJobsHistoryLimit`**: Количество успешно завершенных `Job` для хранения (по умолчанию `3`).
- **`failedJobsHistoryLimit`**: Количество неудачно завершенных `Job` для хранения (по умолчанию `1`). Полезно для отладки.

## Управление Job и CronJob

1.  **Создать:**

    ```bash
    kubectl apply -f my-job.yaml
    kubectl apply -f my-cronjob.yaml
    ```

2.  **Проверить статус:**

    ```bash
    # Посмотреть список всех Job и CronJob
    kubectl get jobs
    kubectl get cronjobs

    # Получить детальную информацию
    kubectl describe job my-job
    kubectl describe cronjob backup-cronjob
    ```

3.  **Посмотреть логи:**

    Сначала найдите имя пода, созданного `Job` (который, в свою очередь, мог быть создан `CronJob`):

    ```bash
    # Для Job
    kubectl get pods --selector=job-name=my-job
    # Для CronJob (имя Job будет сгенерировано)
    kubectl get jobs # найти имя джоба, созданного кронджобом
    kubectl get pods --selector=job-name=<generated-job-name>
    ```

    Затем посмотрите его логи:

    ```bash
    kubectl logs <имя-пода>
    ```

4.  **Удалить:**

    При удалении `Job` также удаляются все созданные им поды. При удалении `CronJob` удаляются все `Job`, которые он создал.

    ```bash
    kubectl delete job my-job
    kubectl delete cronjob backup-cronjob
    ```
