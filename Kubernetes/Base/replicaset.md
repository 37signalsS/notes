# ReplicaSet

## Определения

**ReplicaSet** — это объект **API (Application Programming Interface)** Kubernetes, основная задача которого — гарантировать, что указанное количество идентичных подов (**Pod**, реплик) всегда будет запущено в кластере. `ReplicaSet` постоянно отслеживает количество подов, соответствующих его селектору (`selector`):

- Если подов меньше, чем указано в поле `replicas`, он создает новые из шаблона (`template`).
- Если подов больше, он удаляет лишние.
- Если под, управляемый `ReplicaSet`, выходит из строя (например, из-за сбоя узла), контроллер автоматически создает замену.

`ReplicaSet` является преемником `ReplicationController`. Хотя его можно использовать и самостоятельно, сегодня он в основном применяется как механизм для оркестровки подов в составе высокоуровневого объекта [Deployment](./Deployment/index.md). `Deployment` управляет объектами `ReplicaSet`, которые, в свою очередь, управляют подами, что позволяет реализовать декларативные обновления и откаты.

## Основные концепции

### Анатомия манифеста

- **`replicas`**: Указывает желаемое количество реплик (подов), которое `ReplicaSet` должен поддерживать.
- **`selector`**: Определяет, как `ReplicaSet` находит поды, которыми он должен управлять. Использует метки (**labels**). **Важно:** Метки в `spec.selector.matchLabels` должны в точности совпадать с метками в `spec.template.metadata.labels`.
- **`template`**: Шаблон, по которому создаются поды. Содержит метаданные и спецификацию контейнеров, аналогично описанию [пода](./Pod/pod_overview.md).

### Системная метка pod-template-hash

При управлении через `Deployment` контроллер автоматически добавляет метку `pod-template-hash` в `ReplicaSet` и создаваемые им поды.

**Назначение:**

- **Уникальность имен**: Гарантирует уникальность имен объектов при обновлениях, предотвращая конфликты.
- **Связь с контроллером**: Позволяет однозначно определить принадлежность пода к конкретной версии `ReplicaSet`.
- **Контроль версий**: Используется `Deployment` для отслеживания ревизий и управления процессом плавного обновления.

**Важно:** Запрещено изменять или удалять метку `pod-template-hash` вручную. Это может нарушить механизмы обновления и отката.

## Практические сценарии

### Пример манифеста

Манифест ниже создает `ReplicaSet` для поддержания 2 экземпляров веб-сервера.

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
  labels:
    run: nginx
spec:
  # Количество реплик
  replicas: 2
  # Селектор для связи с подами
  selector:
    matchLabels:
      run: nginx
  # Шаблон пода
  template:
    metadata:
      labels:
        run: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.28.0
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "64Mi"
            cpu: "100m" # CPU (Central Processing Unit)
          limits:
            memory: "128Mi"
            cpu: "250m"
```

### Создание и проверка статуса

```bash
# Применение манифеста
kubectl apply -f nginx-replicaset.yaml

# Просмотр созданных объектов
kubectl get rs,pods
# NAME             DESIRED   CURRENT   READY   AGE
# replicaset.apps/nginx-rs   2         2         2       10s
#
# NAME                 READY   STATUS    RESTARTS   AGE
# pod/nginx-rs-a9z7d   1/1     Running   0          10s
# pod/nginx-rs-b8x6k   1/1     Running   0          10s
```

### Самовосстановление

При ручном удалении пода `ReplicaSet` мгновенно создаст новый экземпляр.

```bash
# Удаление одного пода
kubectl delete pod nginx-rs-a9z7d

# Проверка: новый под запускается немедленно
kubectl get pods
# NAME                 READY   STATUS              RESTARTS   AGE
# pod/nginx-rs-b8x6k   1/1     Running             0          2m
# pod/nginx-rs-c1v5f   0/1     ContainerCreating   0          2s
```

## Дополнительная информация

### Ограничения и альтернативы

Основной недостаток использования `ReplicaSet` напрямую — **отсутствие декларативных обновлений**. Для смены версии образа потребуется ручное удаление старого `ReplicaSet` и создание нового, что приведет к простою (**downtime**).

Рекомендуется использовать [Deployment](./Deployment/index.md), который автоматизирует управление `ReplicaSet`-ами, обеспечивая:
- Плавные обновления (**Rolling Update**).
- Возможность мгновенного отката (**Rollback**).
- Хранение истории версий.
