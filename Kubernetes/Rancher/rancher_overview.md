# Rancher: Обзор платформы

## Определения

**Rancher** — это открытая платформа для управления кластерами Kubernetes корпоративного уровня. Она предоставляет единую панель управления (Control Plane) для развертывания, обеспечения безопасности и эксплуатации нескольких кластеров Kubernetes в любом окружении.

**MCM (Multi-Cluster Management)** — ключевая функциональность Rancher, позволяющая централизованно управлять жизненным циклом множества кластеров, включая их создание, обновление и удаление.

**Fleet** — интегрированный в Rancher инструмент для реализации подхода GitOps в масштабе тысяч кластеров. Fleet является основным механизмом доставки приложений в современной экосистеме Rancher.

## Базовые концепции

### Назначение и возможности

1.  **Управление жизненным циклом кластеров**: поддержка дистрибутивов RKE2 (рекомендовано), K3s (для edge) и RKE1 (Legacy).
2.  **Унифицированная безопасность**: централизованная аутентификация через LDAP, AD, SAML (Security Assertion Markup Language) и управление доступом на основе ролей (RBAC) через все подключенные кластеры.
3.  **Политики и соответствие**: применение OPA (Open Policy Agent) или Kyverno политик централизованно.
4.  **Каталог приложений (Apps & Marketplace)**: управление Helm-чартами и партнерскими приложениями через удобный UI.

### Архитектурная модель

Rancher разделяет инфраструктуру на два типа кластеров:
*   **Local Cluster**: кластер, в котором установлен сам Rancher Server. Используется для управления платформой и хранения метаданных. Не рекомендуется запускать пользовательские нагрузки в этом кластере.
*   **Downstream Clusters**: управляемые кластеры, в которых запускаются пользовательские приложения. Связь с ними осуществляется через Rancher Agents.

### Технологический стек

| Категория | Технология | Примечание |
| :--- | :--- | :--- |
| **Оркестрация** | Kubernetes | Поддержка версий 1.30+ |
| **Дистрибутивы** | RKE2, K3s, RKE | RKE2 — стандарт по умолчанию |
| **GitOps** | Fleet | Заменяет [Rancher Pipelines](./rancher_pipelines.md) |
| **Мониторинг** | Prometheus / Grafana | Пакет [rancher-monitoring](./rancher_monitoring.md) |
| **Логирование** | Logging Operator | Пакет `rancher-logging` |

## Практические сценарии

### Типовой жизненный цикл эксплуатации

1.  **Развертывание Rancher Server**: установка в выделенный Kubernetes-кластер через Helm. Подробности: [rancher_installation](./rancher_installation.md).
2.  **Создание и импорт кластеров**: развертывание новых узлов через RKE2 или подключение существующих (EKS, AKS, GKE). Подробности: [rancher_rke](./rancher_rke.md).
3.  **Настройка RBAC и проектов**: логическое объединение Namespace и назначение прав командам. Подробности: [rancher_rbac](./rancher_rbac.md).
4.  **Внедрение GitOps (Fleet)**: подключение Git-репозиториев для автоматической доставки манифестов в группы кластеров.
5.  **Организация наблюдаемости**: активация стеков мониторинга и логирования для оперативного реагирования на инциденты. Подробности: [rancher_monitoring](./rancher_monitoring.md) и [rancher_logging](./rancher_logging.md).

### Миграция с Rancher Pipelines

Встроенный механизм Rancher Pipelines полностью **удален** начиная с версии v2.7.0. Для всех новых и обновляемых проектов требуется переход на современные решения. Подробности и примеры см. в [Rancher Pipelines (Legacy)](./rancher_pipelines.md).

**Рекомендации:**
*   Использовать **Fleet** для декларативной доставки ресурсов и реализации GitOps.
*   Интегрировать внешние CI-системы (GitLab CI, GitHub Actions) для сборки образов.

| :--- | :--- | :--- | :--- |

| **RKE2** | v1.32+ | Актуально | Использовать для всех новых сред |
| **RKE1** | Legacy | Поддержка | Только для существующих инсталляций |
