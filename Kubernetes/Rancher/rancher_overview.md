# Rancher: Обзор платформы

## Определения

**Rancher** — это открытая платформа для управления кластерами Kubernetes, предоставляющая единый интерфейс для развертывания, настройки, мониторинга и администрирования нескольких кластеров в различных средах (облачная инфраструктура, локальные центры обработки данных, edge-устройства).

## Базовые концепции

### Назначение платформы

1. **Централизованное управление**: управление множеством кластеров Kubernetes в различных облаках (AWS (Amazon Web Services), GCP (Google Cloud Platform), Azure) и на собственных серверах из одной точки.
2. **Упрощенная эксплуатация**: инструменты для быстрого развертывания кластеров с использованием дистрибутивов RKE (Rancher Kubernetes Engine) и RKE2.
3. **Безопасность и контроль доступа**: интеграция с внешними методами аутентификации, такими как LDAP (Lightweight Directory Access Protocol), Active Directory, GitHub.
4. **Наблюдаемость (Observability)**: встроенная поддержка стека мониторинга (Prometheus, Grafana) и систем сбора логов (Fluentd).
5. **Каталог приложений**: упрощенное развертывание сервисов с использованием Helm-чартов.

### Архитектура Rancher

* **Rancher Server**: центральный компонент системы, предоставляющий UI (User Interface) и API (Application Programming Interface) для управления кластерами.
* **Управляемые кластеры**: могут быть развернуты силами Rancher (RKE, RKE2, K3s) или импортированы из облачных провайдеров (EKS, AKS, GKE).
* **Rancher Agents**: специализированные агенты, запускаемые в каждом управляемом кластере для установления обратного соединения с Rancher Server.

## Практические сценарии

### Типовые рабочие процессы

1. **Развёртывание Rancher Server**: установка в существующий кластер Kubernetes через Helm или в режиме одного узла (single-node). Подробности: [rancher_installation](./rancher_installation.md).
2. **Подключение и создание кластеров**: импорт существующих мощностей или развёртывание новых узлов. Подробности: [rancher_rke](./rancher_rke.md).
3. **Настройка прав доступа**: управление пользователями, проектами и ролями через механизмы RBAC (Role-Based Access Control). Подробности: [rancher_rbac](./rancher_rbac.md).
4. **Внедрение мониторинга**: активация встроенного стека для сбора метрик и визуализации состояния ресурсов. Подробности: [rancher_monitoring](./rancher_monitoring.md).
5. **Сбор логов**: настройка маршрутизации логов через Fluent Bit и Fluentd в системы хранения. Подробности: [rancher_logging](./rancher_logging.md).
6. **Автоматизация доставки (CI/CD)**: интеграция с внешними пайплайнами или использование встроенных механизмов (примечание: встроенные пайплайны деприкейтрованы). Подробности: [rancher_pipelines](./rancher_pipelines.md).
