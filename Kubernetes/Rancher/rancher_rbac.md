# Управление пользователями и RBAC в Rancher

## Определения

**Пользователь Rancher** — учётная запись (локальная или внешняя), предоставляющая доступ к интерфейсу Rancher и управляемым кластерам Kubernetes.

**Global Role (Глобальная роль)** — набор прав, определяющий доступ пользователя к административным функциям самой платформы Rancher.

**Cluster Role (Роль уровня кластера)** — набор разрешений, действующих в рамках всего конкретного кластера.

**Project (Проект)** — логическая группа одного или нескольких пространств имён (namespaces) в Rancher, используемая для совместного управления ресурсами и доступом.

**Project/Namespace Role (Роль уровня проекта/неймспейса)** — набор разрешений, действующих только внутри конкретного проекта или пространства имён.

**Auth Provider (Провайдер аутентификации)** — внешняя система управления идентификацией, такая как LDAP (Lightweight Directory Access Protocol), Active Directory или GitHub.

## Базовые концепции

### Взаимосвязь с нативным Kubernetes RBAC

Rancher не заменяет стандартный [Kubernetes RBAC](../Security/rbac/rbac_overview.md), а надстраивается над ним. Платформа управляет высокоуровневыми сущностями (пользователи, проекты) и транслирует их в нативные объекты кластера: `Role`, `ClusterRole`, `RoleBinding` и `ClusterRoleBinding`.

### Уровни доступа

1. **Глобальный (Global)**: управление настройками Rancher, пользователями и облачными учетными данными.
2. **Кластерный (Cluster)**: управление узлами, версиями Kubernetes и общекластерными ресурсами (например, `StorageClass`).
3. **Проектный (Project)**: группировка ресурсов приложений. Владельцы проекта могут управлять всеми пространствами имён внутри него.

### Проекты и пространства имён

Проект в Rancher является "контейнером" для пространств имён. Это позволяет:

* Назначать права доступа сразу на группу пространств имён.
* Устанавливать общие ресурсные квоты (Resource Quotas).
* Применять общие политики безопасности.

**Важно:** пространства имён, созданные через `kubectl` в обход интерфейса Rancher, не привязываются к проектам автоматически. Для корректного управления правами их следует создавать внутри проекта через веб-интерфейс.

## Практические сценарии

### Назначение глобальных прав пользователю

1. Перейдите в **Global Settings** → **Users & Authentication** → **Users**.
2. При создании или редактировании пользователя выберите одну из ролей в разделе **Global Permissions**:
    * **Standard User**: позволяет создавать новые кластеры и управлять собственными ресурсами.
    * **User-Base**: минимальный доступ только для входа в систему и просмотра доступных ресурсов.

### Управление доступом на уровне проекта

1. Перейдите в нужный кластер → **Projects/Namespaces**.
2. Выберите проект и нажмите **Edit**.
3. В разделе **Members** добавьте пользователя и назначьте роль:
    * **Project Owner**: полный контроль над ресурсами и участниками проекта.
    * **Project Member**: возможность управления приложениями и ресурсами внутри проекта.
    * **Read-only**: только просмотр конфигураций (без доступа к секретам).

### Настройка ресурсных квот проекта

1. При создании или редактировании проекта перейдите в раздел **Resource Quotas**.
2. Установите общие лимиты для проекта (**Project Limits**) по CPU и памяти.
3. Установите лимиты по умолчанию для новых пространств имён (**Namespace Default Limits**). Это гарантирует, что сумма лимитов всех пространств имён не превысит общую квоту проекта.

### Использование кастомных ролей

Если стандартных ролей недостаточно, можно создать собственные:

1. Перейдите в **Global Settings** → **Role Based Access Control**.
2. Выберите уровень (**Cluster Roles** или **Project Roles**) и нажмите **Create**.
3. Определите правила доступа, используя стандартные ресурсы и глаголы (get, list, create) Kubernetes.

## Дополнительная информация

### Статус компонентов

| Компонент | Текущее состояние | Рекомендация |
|-----------|-------------------|--------------|
| Global/Cluster/Project Roles | Стабильно | Основной метод управления доступом |
| Auth Providers (LDAP, AD) | Актуально | Рекомендуется для корпоративных сред |
| Custom Roles | Гибкая настройка | Использовать при необходимости гранулярного контроля |
