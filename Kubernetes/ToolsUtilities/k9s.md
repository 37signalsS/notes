# k9s — терминальный UI для Kubernetes

**Актуально для:** k9s 0.51.x

## Определения

**k9s** — терминальный интерфейс (TUI) для Kubernetes: непрерывно отслеживает ресурсы кластера и предоставляет клавиатурную навигацию, просмотр логов, describe, редактирование YAML и удаление ресурсов без отрыва от консоли. Использует локальный kubeconfig, поэтому права в k9s — это права текущего пользователя/контекста (принцип наименьших привилегий работает «из коробки»).

**Ресурсный вид (view)** — режим k9s, показывающий список ресурсов одного типа (`:pods`, `:svc`). Переключается через `:` и имя ресурса или его алиас.

## Основные концепции

### Модель работы

k9s держит watch-соединение с API server и обновляет список ресурсов в реальном времени. Все действия (логи, describe, shell, удаление) выполняются через тот же kubeconfig, что и `kubectl` — отдельной аутентификации нет. Конфигурация хранится в `~/.config/k9s/` (алиасы, цвета, skin).

### Навигация

| Действие | Клавиша | Комментарий |
|:---|:---|:---|
| Переключить тип ресурса | `:` затем имя (`pod`, `svc`, `deploy`, `ns`, `helmreleases`, `kustomizations`) | Полный список — `:` + Tab |
| Фильтр по имени | `/` затем паттерн | `Esc` — сброс фильтра |
| Фильтр по метке | `: <ресурс> / <label>=<value>` | Например `: deploy / app=myapp` |
| Describe ресурса | `d` | Аналог `kubectl describe` |
| Логи пода | `l` | `0` — все контейнеры, `w` — перенос строк |
| Shell в под | `s` | Использует первый контейнер пода |
| Редактировать YAML | `e` | Открывает `$EDITOR` |
| Удалить ресурс | `Ctrl+D` | С подтверждением (`Enter`) |

## Практические сценарии

### Запуск в контексте конкретного кластера и namespace

```bash
# Один namespace — меньше шума при отладке
k9s -n my-app

# Конкретный kubeconfig-контекст
k9s --context prod-cluster

# Комбинация: контекст + namespace
k9s --context prod-cluster -n kube-system
```

### Быстрая диагностика пода

```text
# 1. :pods — список подов
# 2. /<имя-пода> — фильтр по имени
# 3. d — describe (события, условия, образы)
# 4. l — логи (0 — все контейнеры, w — перенос длинных строк)
# 5. s — shell в под, если в образе есть shell
```

### Работа с GitOps-ресурсами

```text
# Просмотр HelmRelease (Flux) и Kustomization (Flux)
:helmreleases
:kustomizations

# События кластера
:ev

# Переключение namespace без выхода
:ns
```

### Фильтрация по статусу и меткам

```text
# Поды с 0/1 Ready (регулярное выражение в фильтре)
/^0/

# Деплои с меткой app=myapp
: deploy / app=myapp
```

## Устранение неполадок

| Проблема | Причина | Решение |
|:---|:---|:---|
| `k9s: cannot connect to cluster` | Неверный контекст или недоступен API | `kubectl cluster-info`; проверить `KUBECONFIG`, срок действия токена |
| Логи не отображаются | Контейнер не запущен или stdout пустой | `kubectl logs pod -c container`; проверить драйвер логирования |
| Нет прав на namespace | RBAC ограничения | `kubectl auth can-i list pods -n <ns>`; назначить RoleBinding |
| Горячие клавиши не работают | Терминал без 256 цветов | Установить `TERM=xterm-256color` |

## Лучшие практики

- **Права текущего пользователя:** никогда не запускайте k9s с `cluster-admin` kubeconfig — интерфейс наследует права контекста, что удобно для аудита, но опасно при ошибочном удалении (`Ctrl+D`).
- **Алиасы для частых ресурсов:** `~/.config/k9s/config.yaml` (секция `alias:`), например `pods: po`, `deployments: deploy`.
- **Автодополнение:** `echo 'source <(k9s completion bash)' >> ~/.bashrc`.
- **Очистка:** `rm -rf ~/.config/k9s` при сбросе конфигурации.
