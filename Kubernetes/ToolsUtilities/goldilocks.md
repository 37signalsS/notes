# Goldilocks

# Определения

Goldilocks — это инструмент для Kubernetes, который помогает автоматически генерировать рекомендации по `resources.limits` и `resources.requests` для подов на основе их реального потребления ресурсов. Он использует метрики Vertical Pod Autoscaler (VPA) для определения оптимальных значений, помогая достичь "золотой середины" между избыточным выделением и нехваткой ресурсов.

## Основные концепции

*   **Анализ метрик:** Goldilocks анализирует метрики потребления CPU и памяти подов, обычно получаемые через Prometheus.
*   **Генерация рекомендаций:** На основе анализа потребления генерирует предложения для `resources.limits` и `resources.requests`.
*   **Режимы работы:**
    *   **"recommend"**: Предоставляет рекомендации без внесения изменений в манифесты. Позволяет просмотреть предложенные значения.
    *   **"set"**: Автоматически применяет сгенерированные рекомендации, обновляя манифесты подов.
*   **Выборочный анализ:** Поддерживает фильтрацию по лейблам (например, по `namespace` или `app`) для выборочного анализа и применения рекомендаций к определённым группам подов.
*   **Контроллер в кластере:** Goldilocks разворачивается в кластере Kubernetes как контроллер, часто с использованием Helm-чартов.
*   **Интеграция с VPA:** Использует рекомендации, предоставляемые VPA, но предлагает более простой и гибкий механизм их применения и визуализации.

### Практические сценарии

*   **Оптимизация расходов:** Позволяет избежать перерасхода облачных ресурсов путём точного определения необходимых `limits` и `requests`.
*   **Повышение стабильности:** Предотвращает нехватку ресурсов, которая может приводить к сбоям и деградации производительности приложений.
*   **Автоматическое управление ресурсами:** Автоматизирует процесс подбора оптимальных `resources.limits` и `resources.requests` на основе фактической нагрузки, снижая ручную работу инженеров.
*   **Улучшение плотности размещения подов:** За счёт более точного распределения ресурсов позволяет размещать больше подов на одном узле, оптимизируя использование инфраструктуры.

#### Дополнительная информация

*   **Безопасность:** Не вносит изменения в манифесты подов без явного разрешения и настройки режима "set".
*   **Отчётность:** Рекомендации Goldilocks можно просматривать в Grafana (при соответствующей интеграции) или получать через стандартные команды `kubectl get vpa`.
*   **Open-source:** Проект является открытым исходным кодом и активно поддерживается компанией Fairwinds.
*   **Репозиторий:** Более подробную информацию и исходный код можно найти на [GitHub](https://github.com/FairwindsOps/goldilocks).
