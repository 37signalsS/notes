# Kustomize — Overview and Core Concepts

## 1. Definitions

**Kustomize** — нативный инструмент Kubernetes для декларативного управления конфигурациями. В отличие от шаблонизаторов (Helm), настраивает Kubernetes-объекты без изменения оригинальных манифестов через механизм наложения патчей (overlays).

**kubectl kustomize** — встроенная команда, доступна в kubectl начиная с версии 1.14. Отдельный CLI `kustomize` устанавливается независимо.

**kustomization.yaml** — манифест, описывающий все трансформации, ресурсы и генераторы. Делает конфигурацию версионируемой, отслеживаемой и повторяемой.

## 2. Basic Concepts

### Принцип наложения (Overlays)

Создание окружение-специфичных конфигураций путём наложения патчей на общую базовую конфигурацию:

```
                    ┌─────────────────┐
                    │      base/      │
                    │  (общая конф.)  │
                    └────────┬────────┘
                             │
            ┌────────────────┼────────────────┐
            │                │                │
            v                v                v
     ┌────────────┐  ┌────────────┐  ┌────────────┐
     │  staging/  │  │ production/│  │   local/   │
     │  (overlay) │  │  (overlay) │  │  (overlay) │
     └────────────┘  └────────────┘  └────────────┘
```

### Ключевые возможности

| Возможность | Описание |
| :--- | :--- |
| **Генерация ресурсов** | Создание ConfigMap и Secret из файлов или литералов |
| **Манипуляция метаданными** | Добавление префиксов/суффиксов к именам ресурсов |
| **Общие метки** | Добавление labels ко всем ресурсам |
| **Патчи** | Изменение существующих ресурсов (JSON/RFC 6902, strategic merge) |
| **Компоненты** | Переиспользуемые фрагменты конфигурации (alpha) |

### Концепция управления манифестами

Работа с "сырыми" YAML-файлами в реальных проектах сталкивается с проблемами разграничения окружений (Sandbox vs Prod) и управления секретами. Использование Kustomize или Helm привносит структуру и документированность, аналогично переходу от настройки серверов Shell-скриптами к использованию **Ansible**:
- **Shell-скрипты (Raw YAML)**: последовательность команд, отсутствие структуры, сложность поддержки.
- **Ansible (Kustomize/Helm)**: декларативность, стандартные модули, разделение логики и данных, повторяемость.

### Сравнение с Helm и альтернативами

| Характеристика | Kustomize | Helm | Jsonnet / Tanka |
| :--- | :--- | :--- | :--- |
| **Принцип** | Наложение патчей (Overlays) | Шаблонизация (Go templates) | Программируемый JSON |
| **Тип** | Декларативный | Шаблонизатор | Язык программирования |
| **Deployment** | ❌ Нет (нужен `kubectl apply`) | ✅ Да (отслеживает состояние) | ❌ Нет |
| **Условная логика** | ❌ Нет | ✅ Есть | ✅ Есть (полноценный код) |
| **Сложность** | Низкая (KISS) | Средняя/Высокая | Высокая |

**Helm** выделяется тем, что выполняет две функции: генерацию манифестов и их деплой (отслеживание ресурсов в кластере). Kustomize и Jsonnet — это только генераторы, требующие внешнего инструмента для деплоя (ArgoCD, Flux или `kubectl apply`).

Kustomize придерживается принципа **KISS (Keep It Simple, Stupid)** — манифесты остаются читаемыми Kubernetes-объектами, а не превращаются в сложные шаблоны.

### Ограничения

- **Нет условной логики** — в отличие от Helm templates
- **Нет циклов** — нельзя генерировать множество одинаковых ресурсов
- **Простые трансформации** — сложные изменения требуют множественных патчей

Подробнее о типах патчей и overlays: [Наложения и патчи](./kustomize_overlays_and_patches.md).

## 3. Practical Scenarios

### 3.1. Просмотр результата (dry-run)

```bash
# Просмотр сгенерированных манифестов
kubectl kustomize overlays/production/

# Сохранение в файл
kubectl kustomize overlays/production/ > manifests.yaml
```

### 3.2. Применение к кластеру

```bash
# Применение staging конфигурации
kubectl apply -k overlays/staging/

# Применение production конфигурации
kubectl apply -k overlays/production/
```

### 3.3. Удаление ресурсов

```bash
kubectl delete -k overlays/staging/
```

### 3.4. Установка kustomize CLI

```bash
# Linux
curl -s "https://raw.githubusercontent.com/kubernetes-sigs/kustomize/master/hack/install_kustomize.sh" | bash
sudo mv kustomize /usr/local/bin/

# macOS
brew install kustomize

# Проверка версии
kustomize version
```

## 4. Additional Information

### Версии API Kustomize

| API Version | Kubernetes | Примечание |
| :--- | :--- |
| **kustomize.config.k8s.io/v1beta1** | 1.14+ | Текущая стабильная |
| **kustomize.config.k8s.io/v1alpha1** | 1.14–1.20 | Устаревшая |

### Требования

| Компонент | Минимальная версия | Примечание |
| :--- | :--- |
| kubectl | 1.14+ | Встроенная версия |
| kustomize CLI | 5.0+ | Отдельная установка |

### Лучшие практики

1. **Храните base в отдельной директории** — изоляция общей конфигурации
2. **Используйте именованные патчи** — понятные имена файлов патчей
3. **Избегайте сложной логики** — для сложных случаев рассмотрите Helm
4. **Валидируйте результат** — используйте [kubeconform](../kubeconform/index.md) перед применением
5. **Версионируйте всё в Git** — полный аудит изменений
