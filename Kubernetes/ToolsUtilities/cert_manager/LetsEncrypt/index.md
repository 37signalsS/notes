# Let's Encrypt: Публичные сертификаты через ACME в Kubernetes

## Определения

**Let's Encrypt** — бесплатный, автоматизированный и открытый центр сертификации (CA), использующий протокол ACME (RFC 8555) для выдачи TLS-сертификатов.

**ACME (Automatic Certificate Management Environment)** — протокол для автоматизированного получения и продления сертификатов через проверку владения доменом.

**ARI (ACME Renewal Information)** — расширение протокола ACME (RFC 9773), позволяющее центру сертификации рекомендовать клиенту (cert-manager) оптимальное временное окно для продления сертификата. Это критически важно для предотвращения перегрузки API, соблюдения лимитов и оперативной обработки массовых отзывов сертификатов.

**cert-manager** — нативный для Kubernetes контроллер, автоматизирующий жизненный цикл сертификатов через ресурсы `Issuer`, `Certificate`, `Order` и `Challenge`.

## Основные концепции

### Ограничения Let's Encrypt (Rate Limits)

Соблюдение лимитов обязательно для обеспечения стабильности сервиса. Превышение лимитов в Production может привести к блокировке выдачи на срок до 7 дней.

| Лимит | Значение | Период | Особенности |
| :--- | :--- | :--- | :--- |
| **Certificates per Domain** | 50 | 7 дней | На основной зарегистрированный домен (например, `example.com`) |
| **Duplicate Certificates** | 5 | 7 дней | Для идентичного набора имен (SAN). ARI помогает оптимизировать этот процесс. |
| **Failed Validations** | 5 | 1 час | На аккаунт и имя хоста. Критично при отладке. |
| **New Orders** | 300 | 3 часа | Общий лимит на аккаунт |
| **Срок действия** | 90 дней | — | Планируется поэтапный переход на **45 дней** в 2025–2026 гг. |

### ACME ARI (Информация о продлении)

Поддержка ARI стала стабильной в cert-manager v1.15. В версиях v1.21+ функционал расширен для лучшей совместимости с различными CA.
- **Динамика:** cert-manager больше не полагается на статичное значение `renewBefore` (например, за 30 дней), а опрашивает эндпоинт `/acme/renewal-info`.
- **Отказоустойчивость:** Если Let's Encrypt обнаружит проблему в цепочке доверия, он через ARI даст команду всем клиентам немедленно обновить сертификаты.
- **Настройка:** При использовании ARI рекомендуется удалять поле `renewBefore` из ресурса `Certificate`, чтобы передать управление контроллеру.

### ACME Solvers (Методы проверки владения)

| Метод | Принцип | Wildcard | Требования |
| :--- | :--- | :--- | :--- |
| **HTTP-01** | Токен по адресу `http://<domain>/.well-known/acme-challenge/` | ❌ Нет | Публичный порт 80, Ingress или LoadBalancer |
| **DNS-01** | TXT-запись `_acme-challenge.<domain>` | ✅ Да | Доступ к API DNS-провайдера (Cloudflare, AWS Route53, Yandex Cloud и др.) |
| **TLS-ALPN-01** | TLS-соединение на порт 443 с использованием специального протокола | ❌ Нет | Прямой доступ к 443 порту, отсутствие прокси-серверов (L7) перед подом |

### Окружения Let's Encrypt

| Окружение | URL API (Directory) | Назначение |
| :--- | :--- | :--- |
| **Production** | `https://acme-v02.api.letsencrypt.org/directory` | Боевые сертификаты, доверенные браузерами. Строгие лимиты. |
| **Staging** | `https://acme-staging-v02.api.letsencrypt.org/directory` | Тестирование конфигурации. Лимиты в сотни раз выше, сертификаты не доверены. |

> **Профессиональный подход:** Всегда проверяйте новую конфигурацию (особенно DNS-01) через Staging, чтобы не исчерпать лимиты продакшена при ошибках настройки.

## Дополнительная информация

### Лучшие практики (2025–2026)

1. **Версия контроллера**: Используйте cert-manager v1.15+. Это обязательное требование для поддержки ARI и корректной работы с будущими 45-дневными сертификатами.
2. **Отказ от Email-уведомлений**: Let's Encrypt постепенно сокращает использование email для алертов. Настройте мониторинг Prometheus на базе метрики `cert_manager_certificate_expiration_timestamp_seconds`.
3. **Высокая доступность (HA)**: Запускайте `cert-manager-webhook` как минимум в 2–3 репликах. Его недоступность блокирует создание и обновление любых ресурсов в кластере Kubernetes.
4. **Минимизация прав DNS API**: При использовании DNS-01 создавайте API-токены с правами только на редактирование конкретных зон (например, Cloudflare API Tokens вместо Global API Key).
5. **Использование ECDSA**: Переходите на использование ключей ECDSA (P-256/P-384) вместо RSA. Они обеспечивают аналогичный уровень безопасности при меньшем размере ключа и меньшей нагрузке на CPU.
