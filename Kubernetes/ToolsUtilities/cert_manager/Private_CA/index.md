# Приватный CA для внутренних сервисов

## Определения

**Приватный CA (Private CA)** — собственный центр сертификации, развернутый внутри инфраструктуры (обычно в Kubernetes) для выпуска сертификатов, доверенных только внутри периметра организации или конкретного кластера.

**trust-manager** — аддон для cert-manager, решающий проблему дистрибуции доверия. Он автоматически распространяет публичную часть (CA bundle) в ConfigMap по всем необходимым пространствам имен кластера.

**Bundle** — основной ресурс trust-manager, который объединяет системные сертификаты и локальные Private CA в единый источник доверия для приложений.

---

## Основные концепции

### Современный рабочий процесс (Workload Trust)

В 2024–2025 годах стандартом является связка cert-manager и trust-manager:

```
SelfSigned Issuer → Root CA Certificate → CA Issuer → [Сертификаты сервисов]
                                ↓
                          trust-manager (Bundle) → [ConfigMap в Namespaces]
```

1. **Создание иерархии:** Self-signed Issuer подписывает корневой сертификат (Root CA).
2. **Управление выпуском:** CA Issuer использует Root CA для подписи сертификатов приложений.
3. **Дистрибуция доверия:** trust-manager подхватывает публичную часть Root CA и копирует её в ConfigMap во все namespace.
4. **Потребление:** Приложения монтируют ConfigMap и используют его как Trust Store / CA Bundle.

### Лучшие практики (Best Practices 2025)

- **Алгоритмы:** Рекомендуется переход с RSA на **ECDSA (P-256 или P-384)**. Это обеспечивает высокую стойкость при меньшем размере ключа и снижает нагрузку на CPU при TLS-handshake.
- **Политика ротации:** Использование `rotationPolicy: Always` в ресурсе Certificate. При каждом обновлении сертификата cert-manager будет генерировать новый закрытый ключ, что повышает безопасность.
- **Изоляция:** Корневой CA (Root CA) и соответствующие секреты должны находиться в защищенном пространстве имен (например, `cert-manager`), доступ к которому строго ограничен через RBAC.
- **Разделение полномочий:** Используйте промежуточные (Intermediate) Issuer для разных доменов или команд, ограничивая область компрометации одного ключа.

## Дополнительная информация

### Сравнение источников доверия

| Аспект | Приватный CA (Self-signed) | CA кластера (K8s API) |
| :--- | :--- | :--- |
| **Источник доверия** | Свой Root CA в cert-manager | `/etc/kubernetes/pki/ca.crt` |
| **Контроль** | Полный контроль жизненного цикла | Привязан к жизненному циклу кластера |
| **Масштабируемость** | Легко создавать иерархии CA | Ограничен одной цепочкой кластера |
| **Безопасность** | Изолирован от control-plane | Компрометация ключа = взлом всего кластера |
| **Рекомендация** | **Для приложений и mTLS** | Только для системных компонентов K8s |

| Аспект | Оценка | Обоснование |
