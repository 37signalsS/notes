# vCluster — обзор и архитектура

## Определения

**vCluster (Virtual Cluster)** — инструмент для создания легковесных виртуальных Kubernetes-кластеров, работающих внутри отдельных пространств имен (namespaces) хостового кластера. Каждый виртуальный кластер имеет собственный Control Plane (API Server, Controller Manager, Scheduler, etcd) и полностью изолирован от других vCluster.

**Host Cluster (Хост-кластер)** — физический или основной Kubernetes-кластер, на котором разворачиваются и функционируют виртуальные кластеры.

**vCluster Syncer (Синхронизатор)** — ключевой компонент, отвечающий за синхронизацию ресурсов (Pods, Services, PVC) между виртуальным и хостовым кластером. Он имитирует наличие узлов (nodes) внутри vCluster, перенося фактическую нагрузку на узлы хост-кластера.

**vcluster.yaml** — современный формат конфигурации (введен в v0.20+), который объединяет настройки Control Plane, параметры синхронизации и расширенные функции в единую структуру, заменяя разрозненные Helm-значения.

**Sleep Mode (Режим сна)** — функция автоматической или ручной остановки виртуального кластера для экономии ресурсов. В режиме сна все поды нагрузок масштабируются до нуля, а при обращении к API-серверу vCluster работа автоматически возоновляется (Auto-Wakeup).

## Основные концепции

### Архитектура системы

```text
┌─────────────────────────────────────────────────────────────────┐
│                      Host Cluster                                │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐ │

│  │  │ vCluster  │  │  │  │ vCluster  │  │  │  │ vCluster  │  │ │
│  │  │ Control   │  │  │  │ Control   │  │  │  │ Control   │  │ │
│  │  │ Plane     │  │  │  │ Plane     │  │  │  │ Plane     │  │ │
│  │  │ (pods)    │  │  │  │ (pods)    │  │  │  │ (pods)    │  │ │
```

### Компоненты виртуального кластера

| Компонент | Описание |
| :--- | :--- |
| **Control Plane** | Включает API Server, Controller Manager и хранилище (etcd/SQLite). Работает как обычный Pod в хост-кластере. |
| **Syncer** | Копирует поды из vCluster в хост-кластер и обновляет их статус обратно. Синхронизирует только необходимые ресурсы для работы нагрузок. |
| **Backing Store** | Хранилище состояния. v0.20+ поддерживает etcd (по умолчанию для K8s), SQLite (по умолчанию для K3s) и внешние БД (PostgreSQL/MySQL). |
| **etcd / SQLite** | База данных для хранения состояния виртуального кластера (объекты API). |
| **CoreDNS** | Обеспечивает разрешение имен внутри виртуального кластера, работая независимо от DNS хост-кластера. |

### Дистрибутивы Control Plane

| Дистрибутив | Особенности | Рекомендуемое использование |
| :--- | :--- | :--- |
| **K3s** | SQLite по умолчанию, минимальное потребление. | Разработка, CI/CD, легкие окружения. |
| **Kubernetes (Vanilla)** | Полноценный etcd, поддержка всех функций K8s. | Продакшн, тестирование сложных операторов. |
| **K0s** | Облегченный, без зависимостей от ОС. | Изолированные окружения с минимальным оверхедом. |

### Сравнение: Namespace vs vCluster

| Характеристика | Namespace (Пространство имен) | vCluster (Виртуальный кластер) |
| :--- | :--- | :--- |
| **API Server** | Общий для всех | Собственный для каждого кластера |
| **Глобальные ресурсы (CRD)** | Общие (требуют прав администратора) | Изолированные внутри vCluster |
| **Изоляция RBAC** | Ограничена рамками namespace | Полная (ClusterRoles, RoleBindings) |
| **Изоляция etcd** | Нет | Да (своя база данных) |
| **Управление через kubectl** | Частично (нужен контекст хоста) | Полностью (свой kubeconfig) |
| **Конфигурация** | `values.yaml` (Helm) | `vcluster.yaml` (Unified Config) |
| **Ресурсы** | Минимальные | ~300-500Mi RAM на Control Plane |
| **Время развёртывания** | Мгновенно | 30–60 секунд |

## Практические сценарии

### Основные варианты использования

- **Разработка операторов и контроллеров:** изоляция CRD и возможность тестирования с правами ClusterAdmin.
- **Мультитенантность (Hard Multi-tenancy):** обеспечение высокого уровня изоляции между командами.
- **Оптимизация затрат:** использование Sleep Mode для автоматического отключения окружений.
- **Тестирование обновлений K8s:** запуск разных версий API на одном физическом кластере.
- **CI/CD пайплайны:** создание временных чистых кластеров для каждого прогона тестов.

### Требования к окружению

| Компонент | Требование | Примечание |
| :--- | :--- | :--- |
| **Kubernetes Host** | v1.27+ | Проверено на версиях до 1.32. |
| **vCluster CLI** | v0.20+ | Необходим для поддержки `vcluster.yaml`. |
| **Helm** | v3.10+ | Для установки через чарты. |

### Ресурсы Control Plane (Kubernetes Vanilla)

Подробные требования для полноценного дистрибутива (vanilla):

| Компонент | CPU Request | Memory Request | CPU Limit | Memory Limit |
| :--- | :--- | :--- | :--- | :--- |
| **API Server** | 200m | 256Mi | 500m | 512Mi |
| **etcd** | 100m | 128Mi | 200m | 256Mi |
| **Controller Manager** | 50m | 64Mi | 100m | 128Mi |
| **Scheduler** | 50m | 64Mi | 100m | 128Mi |
| **CoreDNS** | 50m | 32Mi | 100m | 64Mi |
| **Syncer** | 100m | 128Mi | 200m | 256Mi |
| **Итого** | **~550m** | **~672Mi** | **~1200m** | **~1.3Gi** |

*Для K3s/K0s значения CPU и RAM могут быть на 30–50% ниже.*
