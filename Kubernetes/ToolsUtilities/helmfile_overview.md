### Определения

Helmfile — это декларативный спецификатор для Helm. Он не заменяет Helm, а действует как "обертка" или "оркестратор" над ним. Вы описываете желаемое состояние ваших релизов в файле `helmfile.yaml`, а Helmfile берет на себя задачу по выполнению соответствующих команд `helm`.

По мере роста количества приложений и окружений, управление релизами с помощью команд `helm` становится громоздким. Helmfile решает эту проблему, позволяя декларативно описывать, развертывать и управлять Helm-чартами в разных окружениях. Это позволяет версионировать всю конфигурацию вашего окружения (или нескольких окружений) в одном Git-репозитории, реализуя подход Infrastructure as Code (IaC).

### Basic Concepts

#### Ключевые возможности

1.  **Декларативное описание (`helmfile.yaml`):** Все релизы, их чарты, версии, значения (`values`) и пространства имен описываются в одном YAML-файле. Это упрощает ревью и аудит конфигураций.
2.  **Шаблонизация и управление окружениями:** `helmfile.yaml` сам по себе является шаблоном Go. Это позволяет динамически генерировать конфигурации в зависимости от окружения (например, `staging` vs `production`), передавать значения из переменных окружения и использовать условную логику.
3.  **Предварительный просмотр изменений (`diff`):** Команда `helmfile diff` показывает, какие изменения будут применены к кластеру, интегрируясь с плагином `helm-diff`. Это критически важно для безопасного развертывания в production.
4.  **Параллельное выполнение:** Helmfile может устанавливать и обновлять несколько релизов параллельно, что значительно ускоряет процесс развертывания.
5.  **Интеграция с `helm-secrets`:** Позволяет хранить секретные значения в зашифрованном виде прямо в Git-репозитории, следуя лучшим практикам GitOps.

#### Основные команды

*   `helmfile repos`: Синхронизирует репозитории, указанные в `helmfile.yaml`.
*   `helmfile diff`: Показывает запланированные изменения для всех релизов.
*   `helmfile apply`: Применяет изменения (устанавливает или обновляет релизы). Эквивалент `sync`.
*   `helmfile sync`: Псевдоним для `apply`.
*   `helmfile destroy`: Удаляет все релизы, описанные в файле.

*   Применение изменений только для релиза с именем `loki`:
    ```bash
    helmfile -l name=loki apply
    ```


### Практические сценарии

#### Пример `helmfile.yaml`

```yaml
# helmfile.yaml

# Глобальные настройки, применяемые ко всем релизам
helmDefaults:
  wait: true
  waitForJobs: true
  timeout: 300
  atomic: true

# Список репозиториев Helm
repositories:
  - name: grafana
    url: https://grafana.github.io/helm-charts
  - name: prometheus-community
    url: https://prometheus-community.github.io/helm-charts

# Список релизов для развертывания
releases:
  # Пример релиза Loki
  - name: loki
    namespace: logging
    chart: grafana/loki-stack
    version: 2.9.10
    # Переопределение values
    values:
      - loki:
          auth_enabled: false

  # Пример релиза Prometheus с условным включением
  - name: prometheus
    namespace: monitoring
    chart: prometheus-community/kube-prometheus-stack
    version: 45.2.1
    # Релиз будет установлен, только если переменная окружения $PROMETHEUS_ENABLED равна "true"
    installed: '{{ env "PROMETHEUS_ENABLED" | default "false" }}'
    values:
      - grafana:
          enabled: true
          adminPassword: '{{ requiredEnv "GRAFANA_ADMIN_PASSWORD" }}' # Обязательная переменная
```


#### Управление секретами через переменные окружения

Helmfile позволяет безопасно управлять секретами, передавая их через переменные окружения, вместо того чтобы хранить их в `values.yaml`.

**Сценарий:** Задать пароль для Redis.

1.  **`helmfile.yaml`:**

    Используйте функцию `env` или `requiredEnv` для чтения переменной окружения.

    ```yaml
    # helmfile.yaml
    releases:
      - name: redis
        chart: bitnami/redis
        values:
          - auth:
              # Функция env() вернет пустую строку, если переменная не установлена.
              # Можно задать значение по умолчанию: {{ env "REDIS_PASSWORD" | default "default-password" }}
              password: '{{ requiredEnv "REDIS_PASSWORD" }}'
    ```

    `requiredEnv` прервет выполнение, если переменная `REDIS_PASSWORD` не будет установлена.

2.  **Запуск `helmfile`:**

    Экспортируйте переменную перед запуском.

    ```bash
    export REDIS_PASSWORD="my-secret-password"
    helmfile apply
    ```

#### Выборочное развертывание с помощью селекторов

При работе с большим количеством релизов часто бывает необходимо применить изменения только к одному из них. Для этого используются селекторы (`-l` или `--selector`).

**Сценарий:** Обновить только релиз `loki`.

1.  **`helmfile.yaml`:**

    Убедитесь, что у ваших релизов есть уникальные имена.

    ```yaml
    releases:
      - name: loki
        # ...
      - name: prometheus
        # ...
      - name: grafana
        # ...
    ```

2.  **Запуск `helmfile` с селектором:**

    Используйте флаг `-l` с форматом `key=value`. Для выбора по имени релиза используется ключ `name`.

    ```bash
    # Показать изменения только для loki
    helmfile -l name=loki diff

    # Применить изменения только для loki
    helmfile -l name=loki apply
    ```
    Это значительно ускоряет работу и снижает риск случайного воздействия на другие компоненты системы.
