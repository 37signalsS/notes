# Основные команды и рабочий процесс Helm

### Определения

Ключевые концепции, такие как **Репозиторий**, **Чарт** и **Релиз**, описаны в [обзорном документе](./helm_overview.md#определения).

### Базовые концепции

* **Идемпотентность развертывания**: Команда `helm upgrade --install` устанавливает релиз, если он не существует, или обновляет существующий. Это обеспечивает предсказуемый результат при многократных вызовах, что критично для CI/CD.
* **Атомарность обновлений**: Helm гарантирует надежность развертываний с помощью флагов `--atomic` и `--timeout`. В случае сбоя (`поды не переходят в состояние Ready`), Helm автоматически откатывается (`helm rollback`) к предыдущей стабильной версии, предотвращая деградацию работающего приложения.

### Практические сценарии

Представлен полный жизненный цикл управления приложением на примере `kube-ops-view`.

* **Управление репозиториями**:
  * **Добавление**: `helm repo add stable https://charts.helm.sh/stable`
  * **Обновление**: `helm repo update`

* **Поиск чарта**:
  * **В Artifact Hub (глобальный поиск)**: `helm search hub kube-ops-view`
  * **В локальных репозиториях**: `helm search repo kube-ops-view`

* **Установка и кастомизация**:
    1. **Просмотр настроек**: `helm show values stable/kube-ops-view`
    2. **Кастомизация**: Сохраните `values.yaml` для внесения изменений (`helm show values stable/kube-ops-view > values.yaml`).
    3. **Установка/Обновление**: Примените изменения в кластере, используя `helm upgrade --install ops-view stable/kube-ops-view --namespace kube-system -f values.yaml --create-namespace --atomic`. Рекомендуется использовать плагин [helm-diff](./helm_plugins.md#helm-diff) для предпросмотра изменений.

* **Управление релизом**:
  * **Просмотр списка релизов**: `helm list -n kube-system`
  * **Проверка статуса релиза**: `helm status ops-view -n kube-system`
  * **Откат к предыдущей версии**: `helm rollback ops-view 1`
  * **Удаление релиза**: `helm uninstall ops-view -n kube-system`. **Важно**: Удаляйте приложения только этой командой для корректного удаления всех связанных ресурсов (например, `ClusterRole`).

### Рабочий процесс разработки чарта

Этот процесс описывает шаги создания, отладки и тестирования собственного чарта.

1.  **Создание скелета чарта**:
    Команда `helm create <chart-name>` генерирует стандартную структуру директорий и файлов, включая `Chart.yaml`, `values.yaml` и примеры шаблонов. Это — отправная точка для разработки.
    ```bash
    helm create my-chart
    ```

2.  **Отладка и рендеринг шаблонов**:
    Команда `helm template` — ключевой инструмент разработчика. Она рендерит шаблоны локально и выводит итоговые YAML-манифесты в консоль, не обращаясь к кластеру. Это позволяет быстро проверять корректность логики шаблонов.
    ```bash
    # Рендеринг с values по умолчанию
    helm template my-release ./my-chart

    # Рендеринг с кастомными values и выводом в файл
    helm template my-release ./my-chart -f my-values.yaml > rendered.yaml
    ```

3.  **Переопределение `values.yaml`**:
    Существует два основных способа задать кастомные значения при установке или рендеринге:

    *   **Файл со значениями (`-f` или `--values`)**: Предпочтительный способ для множества изменений. Создается кастомный YAML-файл, содержащий только те параметры, которые нужно переопределить.
        ```bash
        # my-values.yaml
        replicaCount: 3
        image:
          tag: "1.25.0"
        ```
        ```bash
        helm install my-release ./my-chart -f my-values.yaml
        ```

    *   **Прямое указание (`--set`)**: Удобно для единичных изменений из командной строки.
        ```bash
        helm install my-release ./my-chart --set replicaCount=5 --set image.tag="1.26.0"
        ```

4.  **Валидация чарта**:
    Команда `helm lint` проверяет чарт на соответствие лучшим практикам и наличие синтаксических ошибок.
    ```bash
    helm lint ./my-chart
    ```

5.  **Установка и удаление**:
    После локальной отладки чарт можно установить в кластер для реального тестирования.
    ```bash
    # Установка
    helm install my-release ./my-chart -n my-namespace --create-namespace

    # Удаление
    helm uninstall my-release -n my-namespace
    ```

### Дополнительная информация

* **Инспектирование локального чарта**: Команда `helm pull stable/kube-ops-view --untar` скачивает и распаковывает архив чарта (`.tgz`) для локального изучения, создавая папку `kube-ops-view` в текущей директории.
