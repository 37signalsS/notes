# Основные команды и рабочий процесс Helm

В этом документе описан базовый рабочий процесс с Helm и основные команды. Определения ключевых концепций, таких как **Репозиторий**, **Чарт** и **Релиз**, находятся в [обзорном документе](./helm_overview.md#определения).

## Базовые концепции

### Идемпотентность развертывания

Команда `helm upgrade --install` является **идемпотентной**: она установит релиз, если он не существует, или обновит его, если он уже развернут. Это основной способ управления приложениями в CI/CD, так как один и тот же вызов команды обеспечивает предсказуемый результат.

### Атомарность обновлений

Helm обеспечивает надежность развертываний с помощью флагов `--atomic` и `--timeout`.

Если обновление релиза с флагом `--atomic` завершается сбоем (например, поды не переходят в состояние `Ready` за указанный `--timeout`), Helm автоматически выполняет откат (`helm rollback`) к предыдущей стабильной ревизии. Это гарантирует, что работающее приложение не будет заменено неисправной версией.

## Практический сценарий: установка `kube-ops-view`

Этот сценарий демонстрирует полный жизненный цикл управления приложением.

### 1. Управление репозиториями

*   **Добавление:**
    ```bash
    helm repo add stable https://charts.helm.sh/stable
    ```
*   **Обновление:**
    ```bash
    helm repo update
    ```

### 2. Поиск чарта

*   **Поиск в Artifact Hub (глобальный поиск):**
    ```bash
    helm search hub kube-ops-view
    ```
*   **Поиск в локальных репозиториях:**
    ```bash
    helm search repo kube-ops-view
    ```

### 3. Установка и кастомизация

1.  **Просмотр настроек:** Изучение настраиваемых параметров (`values`) чарта.
    ```bash
    helm show values stable/kube-ops-view
    ```
2.  **Кастомизация:** Сохранение `values.yaml` для внесения изменений.
    ```bash
    helm show values stable/kube-ops-view > values.yaml
    # <... редактирование values.yaml ...>
    ```
3.  **Установка/Обновление:** Применение изменений в кластере. Рекомендуется использовать плагин [helm-diff](./helm_plugins.md#helm-diff) для предпросмотра изменений.
    ```bash
    helm upgrade --install ops-view stable/kube-ops-view \
      --namespace kube-system \
      -f values.yaml \
      --create-namespace \
      --atomic
    ```
    *   `ops-view`: Имя релиза.
    *   `--install`: Создает релиз, если он не существует.
    *   `--atomic`: Гарантирует атомарный откат в случае сбоя.
    *   `--create-namespace`: Создает пространство имен, если оно отсутствует.

### 4. Управление релизом

*   **Просмотр списка релизов:**
    ```bash
    helm list -n kube-system
    ```
*   **Проверка статуса релиза:**
    ```bash
    helm status ops-view -n kube-system
    ```
*   **Откат к предыдущей версии:**
    ```bash
    # helm rollback [RELEASE_NAME] [REVISION]
    helm rollback ops-view 1 
    ```
*   **Удаление релиза:**
    ```bash
    helm delete ops-view -n kube-system
    ```
    > **Важно:** Удалять приложения, установленные через Helm, следует именно командой `helm delete`, чтобы гарантировать корректное удаление всех связанных ресурсов (например, `ClusterRole`).

## Дополнительная информация

### Инспектирование локального чарта

Команда `helm pull` скачивает архив чарта (`.tgz`) из репозитория. Флаг `--untar` позволяет сразу же его распаковать для изучения.

```bash
helm pull stable/kube-ops-view --untar
```
В текущей директории появится папка `kube-ops-view`.
