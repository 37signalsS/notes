# Пакетный подход к развёртыванию приложений

Пакетный подход трактует развёртывание как поставку версии приложения вместе с его инфраструктурными манифестами и зависимостями в виде единого артефакта. В контексте Kubernetes эта роль чаще всего выполняется **Helm-чартом**: набором шаблонов, значений конфигурации и метаданных, объединённых версией, историей релизов и управляемых командами установки/обновления/отката.

Helm — это пакетный менеджер для Kubernetes, который автоматизирует **темплейтизацию** и **создание версионированных релизов**, решая проблему управления большим количеством YAML-файлов для разных окружений.

## Определения

*   **Чарт (Chart)** – пакет с преднастроенными ресурсами Kubernetes.
*   **Релиз (Release)** – экземпляр чарта, развернутый в кластере.
*   **Репозиторий (Repository)** – HTTP-сервер для хранения и распространения чартов.

## Зачем нужен пакетный подход (Ключевые преимущества)

*   **Повторяемость и переиспользуемость**: Один и тот же артефакт разворачивается во всех средах с минимальными изменениями (через `values`). См. [Шаблонизация в Helm](./helm_templating.md).
*   **Версионирование**: Четкая связь между версиями приложения и инфраструктуры. См. [Управление версиями релизов](./helm_release_versioning.md).
*   **Управление зависимостями**: База данных, кэш или ingress-контроллер оформляются как субчарты с собственной версией. См. [Зависимости и Library Charts](./helm_dependencies_and_library_charts.md).
*   **Атомарные операции**: Обновления могут быть атомарными с автотранзакционным откатом при сбое (`--atomic`).
*   **История релизов**: Хранится состояние и диффы, что облегчает анализ изменений и откаты.
*   **Конфигурационная изоляция**: Разные окружения имеют отдельные `values`-файлы без дублирования шаблонов.
*   **Архитектура без Tiller (Helm 3)**: Исключительно клиентский инструмент, что безопаснее. См. [Сравнение Helm v2 и v3](./helm_v2_vs_v3.md).
*   **Хуки и тесты**: Возможность выполнять действия на определенных этапах жизненного цикла релиза. См. [Хуки и тестирование](./helm_hooks_and_tests.md).

## Сравнение подходов

| Критерий | Обычные манифесты (kubectl apply) | Пакетный подход (Helm) |
| :--- | :--- | :--- |
| **Единица поставки** | Набор файлов без версии | Чарт с версией |
| **Параметризация** | Ограниченная, вручную | Шаблоны и values |
| **Зависимости** | Управляются отдельно | Субчарты и lock-файл |
| **Порядок ресурсов**| Ручной контроль | Управляется шаблонами/хуками |
| **Откат** | Требует ручных диффов | Исторический rollback |
| **Публикация** | Git-репозиторий | Репозиторий чартов/OCI |

## Жизненный цикл релиза

1.  **Сборка**: Чарт собирается и публикуется в репозиторий.
2.  **Установка**: Создаётся релиз с конкретными `values`.
3.  **Обновление**: Применяются изменения с созданием новой ревизии.
4.  **Откат**: Возвращение к предыдущему номеру ревизии.
5.  **Удаление**: Корректное освобождение ресурсов.

Детально рабочий процесс описан в [документе об основных командах](./helm_commands_and_workflow.md).
