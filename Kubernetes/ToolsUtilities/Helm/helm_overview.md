# Обзор Helm

Helm — пакетный менеджер для Kubernetes, автоматизирующий параметризацию, версионирование и управление жизненным циклом приложений. Начиная с версии v4 (ноябрь 2025), Helm перешёл на модель **Server-Side Apply (SSA)** и внедрил поддержку плагинов на базе **WebAssembly (WASM)**.

---

## Определения

| Термин | Описание |
|--------|----------|
| **Chart (Чарт)** | Пакет с преднастроенными ресурсами Kubernetes. См. [Структура Helm-чарта](./helm_chart_structure.md). |
| **Release (Релиз)** | Экземпляр чарта, развёрнутый в кластере. В v4 управляется через Server-Side Apply. |
| **OCI Registry** | Современный стандарт (Open Container Initiative) для хранения чартов как артефактов. |
| **Values (Значения)** | Параметры конфигурации (`values.yaml`). В v4 поддерживаются многодокументные YAML-файлы. |
| **WASM Plugin** | Плагин, скомпилированный в WebAssembly, работающий в изолированной среде Helm CLI. |

---

## Базовые концепции

### Эволюция архитектуры

Helm v4 сохраняет клиентскую модель (без серверного компонента), но радикально меняет способ взаимодействия с Kubernetes API.

1.  **Server-Side Apply (SSA) по умолчанию**: Вместо клиентского "трёхстороннего слияния" (three-way merge), Helm передаёт управление полями ресурсов самому Kubernetes. Это минимизирует конфликты с внешними контроллерами (Argo CD, Flux, Kyverno).
2.  **Мониторинг через kstatus**: Helm v4 использует библиотеку `kstatus` для точного определения готовности ресурсов, поддерживая новые аннотации готовности (`helm.sh/readiness-success`).
3.  **Безопасный SDK**: Обновлённый SDK v4 обеспечивает стабильность API для разработчиков инструментов автоматизации.

### Пакетный подход vs Plain YAML

| Аспект | Стандартные манифесты | Helm (Пакетный подход) |
|--------|-----------------------|------------------------|
| **Управление полями** | Ручное / kubectl | **Server-Side Apply** (v4+) |
| **Параметризация** | Отсутствует (hardcoded) | Динамические шаблоны (Go templates) |
| **Зависимости** | Внешние инструкции | Автоматические субчарты |
| **Безопасность** | Plain text секреты | Интеграция с **SOPS/KMS** (`helm-secrets`) |

### Преимущества Helm v4

-   **Кроссплатформенные плагины**: WASM позволяет запускать одни и те же расширения на любой ОС и архитектуре (x86/ARM).
-   **OCI-First**: Полноценная поддержка OCI-реестров с возможностью установки по **дигесту (digest)** для максимальной безопасности.
-   **Детерминизм**: Улучшенное кэширование на основе хешей контента предотвращает коллизии версий.

## Установка CLI

> **Актуальная версия:** Helm v4.2.0 (май 2026). Helm v3 считается устаревшим (EOL в ноябре 2026).

**Установка через скрипт:**

```bash
curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-4
chmod 700 get_helm.sh
./get_helm.sh
```

**Проверка версии:**

```bash
helm version
# → version.BuildInfo{Version:"v4.2.0", ...}
```

## Практические сценарии

### Работа с OCI-реестрами (v4 стандарт)

Публикация и установка чарта напрямую из реестра контейнеров.

```bash
# Логин в реестр (только домен)
helm registry login registry.example.com -u user

# Установка по дигесту (максимальная безопасность)
helm install my-app oci://registry.example.com/charts/my-chart@sha256:abcd...

# Установка с использованием Server-Side Apply (по умолчанию в v4)
helm upgrade --install my-app ./my-chart --atomic
```

### Генерация манифестов (GitOps Workflow)

Использование Helm только как генератора для последующей обработки другими инструментами.

```bash
# Генерация с рендерингом всех шаблонов
helm template my-release ./my-chart -f values.yaml > all-manifests.yaml
```

### Использование WASM-плагинов

```bash
# Установка WASM-плагина из OCI
helm plugin install oci://registry.example.com/plugins/my-wasm-plugin:v1.0.0
```
