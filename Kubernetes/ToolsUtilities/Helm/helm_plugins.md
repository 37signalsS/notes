# Плагины Helm

Расширение функциональности Helm CLI через сторонние скрипты, исполняемые файлы и модули WebAssembly (WASM).

---

## Определения

| Термин | Описание |
|--------|----------|
| **Plugin (Плагин)** | Автономный инструмент, интегрируемый в `helm` CLI для расширения его возможностей. |
| **WASM Plugin** | (Helm v4+) Плагин, скомпилированный в WebAssembly, обеспечивающий кроссплатформенность и изоляцию. |
| **Metadata (`plugin.yaml`)** | Файл манифеста плагина, определяющий его имя, версию и команды. |

---

## Базовые концепции

### Управление плагинами

Плагины устанавливаются в директорию `$HELM_PLUGINS` (по умолчанию `~/.local/share/helm/plugins` в Linux).

| Команда | Описание |
|---------|----------|
| `helm plugin install <url\|path>` | Установка плагина (например, из GitHub или локальной папки) |
| `helm plugin list` | Вывод списка всех установленных плагинов |
| `helm plugin update <name>` | Обновление конкретного плагина до последней версии |
| `helm plugin uninstall <name>` | Удаление плагина из системы |

### Архитектура плагинов

1.  **Классические плагины (Helm v2/v3):** Используют локальные бинарные файлы или Bash-скрипты. Требуют наличия установленных зависимостей в ОС.
2.  **WASM-плагины (Helm v4+):** Распространяются как артефакты в OCI-реестрах. Запускаются в изолированной среде, не зависят от архитектуры процессора (x86/ARM).

## Практические сценарии

### helm-diff: Визуализация изменений

Самый востребованный плагин для GitOps и безопасного деплоя. Показывает разницу между текущим состоянием ресурсов в кластере и тем, что определено в чарте.

```bash
# Просмотр изменений перед апгрейдом
helm diff upgrade my-app ./charts/my-app --values values.yaml
# → Output: показывает добавленные/удаленные строки в YAML манифестах

# Сравнение двух ревизий релиза
helm diff revision my-app 10 11
```

### helm-secrets: Управление секретами

Интеграция с **Mozilla SOPS** для шифрования `secrets.yaml` с использованием KMS (AWS/GCP/Azure) или PGP. Позволяет безопасно хранить секреты в Git.

```bash
# Установка плагина
helm plugin install https://github.com/jkroepke/helm-secrets

# Просмотр зашифрованных значений
helm secrets view secrets.yaml

# Деплой с расшифровкой на лету
helm secrets upgrade --install my-app ./chart -f values.yaml -f secrets.yaml
```

### helm-unittest: Юнит-тестирование чартов

Позволяет писать BDD-тесты на YAML для проверки корректности рендеринга шаблонов без подключения к живому кластеру.

```bash
# Запуск тестов в папке чарта
helm unittest ./my-chart
# → Output: PASSED: 12, FAILED: 0
```

### helm-mapkubeapis: Исправление устаревших API

Незаменим при обновлении Kubernetes. Автоматически находит в метаданных релизов ссылки на удаленные API (например, `extensions/v1beta1`) и обновляет их до актуальных (например, `apps/v1`).

```bash
# Проверка и исправление релиза
helm mapkubeapis my-release
# → Output: Release "my-release" updated to support new K8s version
```

### trivy: Сканирование безопасности

Использование `trivy` как плагина для поиска уязвимостей в образах и ошибок конфигурации в манифестах чарта перед деплоем.

```bash
# Сканирование чарта на misconfigurations
helm trivy ./my-chart
```

### helm-docs: Автогенерация документации

Автоматически создает `README.md` для чарта на основе комментариев в `values.yaml`.

```bash
# Обновление документации
helm docs ./charts/my-app
# → Result: файл README.md обновлен таблицей параметров
```

## Дополнительная информация

### Устаревшие и специфичные плагины

*   **helm 2to3:** Использовался для миграции с Helm v2. В 2026 году актуален только для глубоко архивных систем.
*   **helm-monitor:** Ранее использовался для автоматического отката на основе метрик Prometheus. В современной практике заменен на прогрессивный деплой (Argo Rollouts, Flagger).
