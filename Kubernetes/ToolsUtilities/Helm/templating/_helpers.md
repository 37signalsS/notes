# Именованные шаблоны и хелперы

---

## Определения

**Именованные шаблоны** — переиспользуемые блоки кода, определяемые через `{{ define }}` и вызываемые через `{{ include }}`.

**Хелперы (Helpers)** — именованные шаблоны, традиционно размещаемые в файле `templates/_helpers.tpl`, предназначенные для генерации имён, меток и других повторяющихся конструкций.

---

## Базовые концепции

### Назначение префикса подчеркивания

Helm не рендерит файлы, имена которых начинаются с `_`, как манифесты Kubernetes. Файл `_helpers.tpl` обрабатывается только как источник определений (definitions), но не создаёт ресурсов в кластере при `helm install`.

### Передача контекста (Scope)

При вызове шаблона через `{{ include "template" . }}` необходимо явно передать контекст через второй аргумент (обычно точка `.`):

| Объект | Содержимое |
|--------|------------|
| `.Chart` | Метаданные из `Chart.yaml` |
| `.Release` | Информация о текущем релизе |
| `.Values` | Пользовательские значения из `values.yaml` |
| `.Capabilities` | Сведения о возможностях API кластера |

### Соглашения по именованию

Стандартная практика: `<имя-чарта>.<назначение>`. Например, для чарта `myapp`:

- `myapp.name` — краткое имя (используется `nameOverride`)
- `myapp.fullname` — полное имя (с учётом имени релиза)
- `myapp.labels` — стандартные метки Kubernetes
- `myapp.selectorLabels` — метки для селекторов (неизменяемые)

### Сравнение функций вызова

| Функция | Синтаксис | Особенности |
|---------|-----------|-------------|
| `include` | `{{ include "name" . }}` | Возвращает строку. Можно передавать в пайплайн (например, `| nindent 4`). **Рекомендуемый способ**. |
| `template` | `{{ template "name" . }}` | Выводит результат напрямую. Не поддерживает пайплайны. |
| `tpl` | `{{ tpl "string" . }}` | Рендерит произвольную строку как шаблон. Используется для динамических значений из `values.yaml`. |

## Практические сценарии

### Создание стандартных хелперов

Типовое содержимое `templates/_helpers.tpl`:

```go
{{/* Полное имя ресурса с ограничением в 63 символа */}}
{{- define "myapp.fullname" -}}
{{- if .Values.fullnameOverride -}}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" -}}
{{- else -}}
{{- $name := default .Chart.Name .Values.nameOverride -}}
{{- printf "%s-%s" $name .Release.Name | trunc 63 | trimSuffix "-" -}}
{{- end -}}
{{- end -}}

{{/* Стандартные метки (labels) */}}
{{- define "myapp.labels" -}}
app.kubernetes.io/name: {{ include "myapp.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end -}}
```

**Использование в манифесте:**

```yaml
metadata:
  name: {{ include "myapp.fullname" . }}
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
```

### Организация меток для многокомпонентных чартов

Если чарт содержит несколько независимых сервисов (например, `frontend` и `backend`), для каждого создаются свои хелперы меток:

```go
{{/* Метки для компонента backend */}}
{{- define "myapp.backend.labels" -}}
app.kubernetes.io/name: {{ include "myapp.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/component: backend
{{- end -}}
```

Это обеспечивает корректную работу селекторов и изоляцию компонентов внутри одного релиза.

### Применение в сетевых политиках

Использование хелперов критично для `NetworkPolicy`, где селекторы должны строго совпадать с метками подов. Подробный пример реализации см. в разделе [Шаблонизация NetworkPolicy](./scenarios/networkpolicy.md).

## Дополнительная информация

### Лучшие практики

- **Неизменяемость селекторов:** никогда не меняйте `selectorLabels` после первого деплоя, так как Kubernetes запрещает изменение `spec.selector` для многих ресурсов (например, Deployment).
- **Пайплайны:** всегда отдавайте предпочтение `include`, чтобы иметь возможность управлять отступами через `nindent`.
- **Лимиты Kubernetes:** всегда используйте `trunc 63 | trimSuffix "-"`, чтобы имена ресурсов не превышали допустимую длину.
- **Комментарии:** используйте блоки `{{/* ... */}}` для документирования сложных хелперов.

### Устранение неисправностей

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `wrong type for value` | Передан пустой или неверный контекст | Убедитесь, что вторым аргументом передана точка `.` |
| `nil pointer evaluating` | Обращение к отсутствующему ключу | Используйте функцию `default` или проверяйте существование ключа через `if` |
| Ошибка отступов (YAML) | Неверное использование `indent` / `nindent` | Используйте `nindent` для автоматического переноса строки и отступа |
| Хелпер не найден | Ошибка в имени или файл не в `templates/` | Проверьте соответствие имени в `define` и `include` |
