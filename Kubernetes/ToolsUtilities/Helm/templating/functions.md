# Функции Helm-шаблонов

---

## Определения

**Функции Go Templates** — базовые функции движка шаблонов Go (стандартная библиотека `text/template`), такие как `and`, `or`, `not`, `index`, `print`. Они обеспечивают фундаментальную логику и манипуляцию данными.

**Функции Sprig** — библиотека из более чем 100 функций (строковых, математических, коллекционных, криптографических), интегрированная в Helm для расширения возможностей стандартного движка Go.

**Helm-функции** — специализированные функции (`required`, `fail`, `lookup`, `tpl`, `include`), предназначенные для взаимодействия с инфраструктурой Kubernetes и управления процессом рендеринга шаблонов.

**Функции преобразования типов** — функции (`int`, `int64`, `float64`, `toString`, `kindIs`, `typeIs`, `must`), обеспечивающие строгое соответствие типов данных и предотвращающие ошибки парсинга YAML.

---

## Основные концепции

### Конвейеры (Pipelines)

Функции в Helm вызываются либо напрямую, либо через конвейер (`|`). При использовании пайплайна результат предыдущего выражения передаётся в следующую функцию в качестве последнего аргумента.

```yaml
# Использование пайплайна (предпочтительно)
name: {{ .Values.name | default "myapp" | lower | quote }}

# Прямой вызов
name: {{ quote (lower (default "myapp" .Values.name)) }}
```

### Область видимости и контекст (Scope)

Символ точки (`.`) указывает на текущий контекст. Внутри циклов (`range`) и блоков `with` контекст меняется. Для доступа к глобальным объектам (`.Release`, `.Values`) из любой точки шаблона следует использовать префикс `$`.

```go
{{- range .Values.env }}
  - name: {{ .name }}
    value: {{ $.Release.Name | quote }} # Доступ к корню через $
{{- end }}
```

### Побочные эффекты и чистота функций

Большинство функций Sprig **чистые** (pure): они возвращают новое значение и не изменяют аргументы. Исключения:
- `merge` / `mergeOverwrite` — модифицируют первый аргумент.
- `set` / `unset` — изменяют словарь на месте.
- `deepCopy` — создаёт независимую копию, предотвращая непреднамеренные мутации.

Для вызова функций с побочными эффектами внутри пайплайна используется паттерн `$_ :=`:

```go
{{- $cfg := deepCopy .Values.defaults -}}
{{- $_ := mergeOverwrite $cfg .Values.overrides -}}
data: {{ $cfg | toYaml | nindent 2 }}
```

### Производительность функций

Некоторые функции выполняются ресурсоёмко при больших объёмах данных:
- `toYaml` / `toJson` — сериализация крупных объектов (>1 МБ) увеличивает время рендеринга.
- `sha256sum` / `sha512sum` — хеширование больших строк в циклах.
- `range` по словарю — порядок ключей не гарантирован и может меняться между рендерингами.

Рекомендация: выносите тяжёлые вычисления за пределы циклов или кэшируйте результаты в переменных.

## Ключевые функции по категориям

### Строковые функции

| Функция | Назначение | Пример |
|---------|------------|--------|
| `quote` / `squote` | Оборачивание в двойные/одинарные кавычки | `{{ .Values.val | quote }}` |
| `default` | Значение по умолчанию, если переменная пуста | `{{ .Values.tag | default "latest" }}` |
| `cat` | Объединение строк через пробел | `{{ cat "v" .Chart.AppVersion }}` |
| `trunc` | Обрезка строки (важно для лимитов DNS в K8s) | `{{ .Release.Name | trunc 63 | trimSuffix "-" }}` |
| `trimSuffix` / `trimPrefix` | Удаление суффикса или префикса | `{{ "v1-app" | trimPrefix "v1-" }}` |
| `trimAll` | Удаление заданного символа с обоих концов строки | `{{ "  text  " | trimAll " " }}` |
| `replace` | Замена всех вхождений подстроки | `{{ "a+b" | replace "+" "-" }}` |
| `lower` / `upper` | Смена регистра символов | `{{ .Values.name | lower }}` |
| `printf` | Форматирование по шаблону (стиль Go/C) | `{{ printf "%s-%s" .Chart.Name .Release.Name }}` |
| `ternary` | Тернарный оператор (условие ? истина : ложь) | `{{ .Values.debug | ternary "on" "off" }}` |
| `coalesce` | Возвращает первый не пустой аргумент | `{{ coalesce .v1 .v2 "fallback" }}` |
| `plural` | Выбор формы слова в зависимости от числа | `{{ .Values.count | plural "item" "items" }}` |
| `base` | Извлечение имени файла из пути | `{{ base "configs/app.yaml" }}` |
| `contains` | Проверка наличия подстроки | `{{ if contains "prod" .Values.env }}` |
| `empty` | Проверка на пустоту (строка, список, словарь, nil) | `{{ if empty .Values.name }}` |
| `repeat` | Повторение строки N раз | `{{ repeat 3 "=" }}` |
| `split` / `rsplit` | Разбиение строки по разделителю | `{{ split "/" .Values.image }}` |

### Коллекции и словари

| Функция | Назначение | Пример |
|---------|------------|--------|
| `dict` | Создание словаря (key-value) | `{{ dict "k1" "v1" "k2" "v2" }}` |
| `list` | Создание списка элементов | `{{ list "a" "b" "c" }}` |
| `index` | Доступ к элементу списка или ключу словаря | `{{ index .Values.data "config.yaml" }}` |
| `has` | Проверка наличия элемента в списке | `{{ if has "prod" .Values.tags }}` |
| `hasKey` | Проверка наличия ключа в словаре | `{{ if hasKey .Values "config" }}` |
| `merge` | Слияние словарей (модифицирует первый) | `{{ merge $dest $src }}` |
| `mergeOverwrite` | Слияние с перезаписью существующих ключей | `{{ mergeOverwrite $dest $src }}` |
| `deepCopy` | Полная копия объекта (защита от мутаций) | `{{ $copy := deepCopy .Values.orig }}` |
| `omit` / `pick` | Исключение или выбор конкретных ключей | `{{ omit $dict "key1" "key2" }}` |
| `set` / `unset` | Установка или удаление значения в словаре | `{{ set $dict "new" "val" }}` |
| `compact` | Удаление пустых элементов из списка | `{{ list "a" "" "b" | compact }}` |
| `uniq` | Удаление дубликатов из списка | `{{ .Values.tags | uniq }}` |

### YAML, JSON и сериализация

| Функция | Назначение | Пример |
|---------|------------|--------|
| `toYaml` | Сериализация объекта в YAML-строку | `{{ toYaml .Values.resources }}` |
| `toPrettyYaml` | Сериализация с отступами и многострочными значениями | `{{ toPrettyYaml .Values.config }}` |
| `fromYaml` | Парсинг YAML-строки в объект | `{{ $obj := fromYaml .Values.raw }}` |
| `nindent` | Отступ с новой строкой в начале (рекомендуется) | `{{ toYaml . | nindent 8 }}` |
| `indent` | Только отступ (без новой строки) | `{{ toYaml . | indent 4 }}` |
| `toJson` / `fromJson` | Сериализация и парсинг JSON | `{{ .Values.data | toJson }}` |
| `toToml` | Сериализация в формат TOML | `{{ .Values.config | toToml }}` |

### Преобразование типов и валидация

| Функция | Назначение | Пример |
|---------|------------|--------|
| `toString` | Принудительное преобразование в строку | `{{ toString .Values.port }}` |
| `int` / `int64` / `float64` | Приведение к числовому типу | `{{ int .Values.replicas }}` |
| `kindIs` | Проверка типа значения во время рендеринга | `{{ if kindIs "map" .Values.config }}` |
| `typeIs` | Проверка типа (строки, числа, массивы) | `{{ if typeIs "string" .Values.name }}` |
| `must` | Строгий аналог `required` с паникой при nil | `{{ must .Values.replicas }}` |

### Helm-специфичные функции

| Функция | Назначение | Пример |
|---------|------------|--------|
| `required` | Обязательный параметр (ошибка при отсутствии) | `{{ required "Field X is required" .Values.X }}` |
| `fail` | Принудительная остановка рендеринга с ошибкой | `{{ if .Values.bad }}{{ fail "Error!" }}{{ end }}` |
| `tpl` | Рендеринг строки как шаблона | `{{ tpl .Values.config . }}` |
| `include` | Вызов именованного шаблона (возвращает строку) | `{{ include "chart.fullname" . }}` |
| `lookup` | Чтение ресурсов напрямую из кластера | `{{ lookup "v1" "Secret" .Namespace "my-sec" }}` |

### Криптография и хеширование

| Функция | Назначение | Пример |
|---------|------------|--------|
| `sha256sum` | Вычисление SHA256 хеша (для аннотаций) | `{{ .Values.config | sha256sum }}` |
| `sha512sum` | Вычисление SHA512 хеша | `{{ .Values.data | sha512sum }}` |
| `b64enc` / `b64dec` | Кодирование и декодирование в Base64 | `{{ .Values.pass | b64enc }}` |
| `genPrivateKey` | Генерация приватного ключа (rsa, ed25519) | `{{ genPrivateKey "rsa" }}` |
| `derivePassword` | Детерминированная генерация пароля | `{{ derivePassword 1 "long" .Pass .User .Site }}` |
| `htpasswd` | Генерация хеша пароля для nginx/apache | `{{ htpasswd .User .Pass }}` |

### Регулярные выражения (Regex)

| Функция | Назначение | Пример |
|---------|------------|--------|
| `regexMatch` | Проверка соответствия шаблону | `{{ if regexMatch "^v[0-9]" .val }}` |
| `regexReplaceAll` | Замена всех совпадений | `{{ .val | regexReplaceAll "\\." "-" }}` |
| `regexFind` | Поиск первой подстроки по шаблону | `{{ regexFind "[0-9]+" .val }}` |

### Математика и даты

| Функция | Назначение | Пример |
|---------|------------|--------|
| `add`, `sub`, `mul`, `div`, `mod` | Арифметика | `{{ add 1 2 }}` |
| `max`, `min`, `floor`, `ceil`, `round` | Округление и сравнение | `{{ max 1 5 10 }}` |
| `until` | Генерация диапазона чисел для циклов | `{{ range until 5 }}` |
| `now` | Текущее время | `{{ now | date "2006-01-02" }}` |
| `dateModify` | Модификация даты (например, `+24h`) | `{{ now | dateModify "+24h" }}` |
| `unixEpoch` | Время в формате Unix timestamp | `{{ unixEpoch now }}` |

### Версионирование

| Функция | Назначение | Пример |
|---------|------------|--------|
| `semverCompare` | Сравнение версий по стандарту SemVer | `{{ if semverCompare ">=1.23-0" .Capabilities.KubeVersion.Version }}` |

## Практические сценарии

### Использование nindent для корректного YAML

Функция `nindent` является «золотым стандартом» для вставки блоков данных, так как она автоматически вставляет символ новой строки перед отступом.

```yaml
spec:
  template:
    spec:
      {{- if .Values.affinity }}
      affinity:
        {{- toYaml .Values.affinity | nindent 8 }}
      {{- end }}
```

### Безопасное слияние с deepCopy

Функции `merge` и `mergeOverwrite` модифицируют свой первый аргумент. Чтобы не повредить глобальный объект `.Values` или другие данные, всегда используйте `deepCopy`.

```go
{{- $config := deepCopy .Values.defaultConfig -}}
{{- $overrides := .Values.overrides -}}
{{- $_ := mergeOverwrite $config $overrides -}}
data:
  {{- toYaml $config | nindent 2 }}
```

### Безопасное использование lookup

Функция `lookup` возвращает `nil` в режимах `helm template` или `--dry-run`. Необходимо всегда предусматривать fallback-логику.

```yaml
{{- $secret := (lookup "v1" "Secret" .Release.Namespace "my-secret") -}}
{{- if $secret }}
password: {{ index $secret.data "password" }}
{{- else }}
password: {{ "default-pass" | b64enc }}
{{- end }}
```

### Динамическая оценка строк (tpl)

Позволяет рендерить значения из `values.yaml` так, как если бы они сами были шаблонами Helm.

```yaml
# values.yaml:
# custom_config: "app-{{ .Release.Name }}"

# template.yaml:
config_name: {{ tpl .Values.custom_config . | quote }}
```

### Валидация обязательных параметров через required

Используйте `required` для критичных полей, чтобы прервать установку с понятным сообщением.

```yaml
image:
  repository: {{ required "image.repository is required" .Values.image.repository }}
  tag: {{ .Values.image.tag | default .Chart.AppVersion | quote }}
```

### Сложная валидация через fail

`fail` останавливает рендеринг при обнаружении небезопасной комбинации параметров.

```go
{{- if and .Values.ingress.enabled (not .Values.ingress.tls) }}
  {{- if .Values.enforceTls }}
    {{- fail "TLS must be enabled if ingress is enabled and enforceTls is true" -}}
  {{- end }}
{{- end }}
```

### Строгая валидация через must

`must` вызывает панику при `nil` или пустом значении. Это строгий аналог `required` без кастомного сообщения.

```yaml
replicas: {{ must .Values.replicas }}
```

### Проверка типов через kindIs и typeIs

Защита от неверных типов в `values.yaml` на этапе рендеринга.

```go
{{- if kindIs "map" .Values.resources }}
resources:
  {{- toYaml .Values.resources | nindent 2 }}
{{- else }}
{{- fail "resources must be a map" -}}
{{- end }}
```

### Семантические версии и адаптивные шаблоны

Используйте `semverCompare` для выбора API-версии или поведения в зависимости от версии Kubernetes.

```yaml
apiVersion: {{ if semverCompare ">=1.25-0" .Capabilities.KubeVersion.Version }}policy/v1{{ else }}policy/v1beta1{{ end }}
kind: PodDisruptionBudget
```

### Аннотации для перезапуска (Restart on Change)

Используйте `sha256sum` для генерации аннотаций, которые триггерят Rolling Update при изменении ConfigMap или Secret.

```yaml
metadata:
  annotations:
    checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}
```

### TLS-секрет через b64enc

Кодирование сертификатов и ключей для ресурсов типа `kubernetes.io/tls`.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: {{ include "mychart.fullname" . }}-tls
type: kubernetes.io/tls
data:
  tls.crt: {{ .Files.Get "certs/tls.crt" | b64enc }}
  tls.key: {{ .Files.Get "certs/tls.key" | b64enc }}
```

### Фильтрация полей через omit

Удаление служебных полей (например, `enabled`) из финального YAML.

```yaml
{{- with .Values.livenessProbe }}
{{- if .enabled }}
livenessProbe:
  {{- omit . "enabled" | toYaml | nindent 12 }}
{{- end }}
{{- end }}
```

### Условные значения через ternary

Компактное указание параметров, зависящих от окружения.

```yaml
replicas: {{ .Values.global.env | ternary 3 1 }}
debug: {{ .Values.debug | ternary "on" "off" }}
```

### Цепочка fallback через coalesce

Возврат первого непустого значения из цепочки. Полезно для многоуровневой параметризации.

```yaml
image:
  tag: {{ coalesce .Values.image.tag .Values.global.image.tag .Chart.AppVersion | quote }}
```

### Очистка списков через compact и uniq

Удаление пустых строк и дубликатов из списка тегов.

```yaml
tags: {{ .Values.tags | compact | uniq | sortAlpha | quote }}
```

### Генерация диапазона через until

Создание списка портов или порядковых номеров.

```yaml
ports:
{{- range until 5 }}
  - port: {{ add 8000 . }}
    name: "port-{{ . }}"
{{- end }}
```

### Форматирование дат для сертификатов

Проверка срока действия сертификатов в шаблонах.

```yaml
certExpiry: {{ now | dateModify "+3650h" | date "2006-01-02" }}
```

### Вставка многострочного текста через indent

Альтернатива `nindent` для случаев, когда новая строка уже есть в шаблоне.

```yaml
data: |
  {{ .Values.rawConfig | indent 4 }}
```

## Ограничения и производительность

### Лимиты функций в конвейерах

Длина пайплайна не ограничена явно, но каждый этап добавляет накладные расходы на парсинг и выделение памяти. При очень глубоких цепочках (10+ функций) время рендеринга заметно растёт.

### Ограничения toYaml и toJson

- **Размер:** При сериализации объектов, превышающих 1 МБ, итоговый ConfigMap или Secret может превысить лимит Kubernetes (1 МБ для etcd).
- **Бинарные данные:** `toYaml` корректно сериализует строки и числа, но не предназначен для прямого хранения бинарных файлов. Для бинарных данных используйте `.Files.Get` + `b64enc`.
- **Ссылки:** `toYaml` не сохраняет якоря и ссылки YAML.

### Ограничения tpl

- **Рекурсия:** Глубокая вложенность `tpl` (более 10 уровней) приводит к ошибке `template: ...: recursive template parsing aborted`.
- **Инъекция:** Значения из `values.yaml`, пропущенные через `tpl`, выполняются как код. Никогда не передавайте в `tpl` непроверенные пользовательские данные.

### Ограничения lookup

- Режимы `helm template` и `--dry-run` не подключаются к API-серверу. `lookup` всегда возвращает `nil`.
- Требует RBAC-прав (разрешения `get`, `list`, `watch` на соответствующие ресурсы).

### Ограничения regexMatch

- Регулярные выражения в Helm используют синтаксис RE2 (Google). Поддерживаются POSIX-классы, но отсутствуют некоторые Perl-расширения (lookahead, backreference).

### Ограничения date

- Функция `date` требует строгого формата ссылочного времени `2006-01-02 15:04:05` (день недели, месяц, число, год, часы, минуты, секунды). Любое отклонение от этого шаблона приводит к панике рендеринга.

### Производительность range

- Итерация по словарю (`map`) через `range` **не гарантирует** порядок ключей. Если порядок критичен (например, для `initContainers`), используйте `list` в `values.yaml`.
- Итерация по большому списку (>100 элементов) внутри шаблона замедляет рендеринг. Рассмотрите предварительную фильтрацию данных в CI/CD.

## Безопасность

### Инъекция шаблонов (Template Injection)

Функция `tpl` выполняет произвольный Helm-код из `values.yaml`. Это создаёт риск:
- **ПриSide-эффекты:** Пользователь может получить доступ к `.Files`, `.Capabilities` и другим встроенным объектам.
- **Утечка данных:** Через `{{ .Files.Get "/etc/passwd" }}` внутри `tpl`.

**Рекомендации:**
- Используйте `tpl` только для внешних конфигурационных файлов, загружаемых через `.Files.Get`.
- Никогда не пропускайте через `tpl` данные из непроверенных источников.
- Для динамических блоков в `NOTES.txt` ограничьте доступ к опасным функциям через `tpl`.

### Секреты в значениях

- **Не храните** секреты в `values.yaml`. Используйте `helm-secrets` (SOPS) или внешние источники (Vault, Sealed Secrets).
- **Не логируйте** вывод `helm template` с секретами в CI/CD. Используйте `--set` с переменными окружения или `--values` из защищённых хранилищ.

### RBAC и lookup

При использовании `lookup` Helm действует от имени ServiceAccount (в Helm v4) или конфигурации кластера. Убедитесь, что политики RBAC минимальны и не предоставляют лишних прав.

## Лучшие практики

- **`required` для критичных данных:** Всегда помечайте обязательные параметры (пароли, домены, образы), чтобы прервать деплой при их отсутствии.
- **`fail` для сложной логики:** Используйте для проверки конфликтующих параметров (например, `ingress.enabled` без `ingress.tls` при включённом `enforceTls`).
- **`must` для необъявляемых критичных полей:** Если параметр не описан в `values.schema.json` и его отсутствие фатально, используйте `must`.
- **`nindent` вместо `indent`:** Избегайте `indent`, так как он требует ручного управления переносом строки перед вызовом.
- **`trunc 63 | trimSuffix "-"`:** Используйте для имён ресурсов, чтобы соответствовать DNS-1123 (максимум 63 символа для меток).
- **`quote` vs `squote`:** Используйте `quote` для YAML-строк (двойные кавычки) и `squote` для JSON-секций или однострочных конфигов, где важна точность.
- **`deepCopy` перед `merge`:** Всегда копируйте объект перед слиянием, чтобы не повредить исходные `.Values`.
- **`lookup` с fallback:** Предусматривайте значения по умолчанию для dry-run режимов.
- **`tpl` только для конфигов:** Не используйте `tpl` для генерации имён ресурсов или меток — это затрудняет статический анализ.
- **`kindIs`/`typeIs` для защиты от nil:** Проверяйте типы перед вызовом `toYaml`, `index` или итерации.
- **Избегайте тяжёлых функций в циклах:** Кэшируйте `sha256sum`, `toYaml` вне `range`, если результат не зависит от итерации.
- **Кавычьте все внешние строки:** Значения из `values.yaml` могут содержать пробелы или специальные символы; используйте `| quote` для строковых полей.
- **Используйте `coalesce` для fallback-цепочки:** Упрощает иерархию значений (значение → глобальное значение → дефolt).
- **Документируйте хелперы:** Каждый `define` в `_helpers.tpl` должен иметь однозначное имя и комментарий о назначении.

## Устранение неисправностей

| Ошибка | Вероятная причина | Решение |
|--------|-------------------|---------|
| `nil pointer evaluating...` | Обращение к полю несуществующего объекта | Используйте `if` или `default` для проверки наличия данных. |
| `wrong type for value` | Тип данных в пайплайне не соответствует ожидаемому функцией | Проверьте входные данные (например, `toYaml` требует словарь/список). |
| `can't evaluate field... in type string` | Попытка доступа к вложенному полю строки | Проверьте путь к значению в `values.yaml`; используйте `index` для ключей с точками. |
| `wrong number of args` | Ошибка в синтаксисе функции или пайплайна | Проверьте количество аргументов (например, `eq $a $b`, а не `eq $a == $b`). |
| `template: ...: unexpected "}" in command` | Незакрытая скобка или кавычка в выражении | Проверьте баланс `{{ }}` и кавычек внутри пайплайна. |
| `invalid value; expecting map` | Передача списка вместо словаря в `toYaml` или `with` | Проверьте тип данных в `values.yaml`. |
| `template parsing aborted: recursive` | Циклическая зависимость через `tpl` или `include` | Уберите рекурсию или упростите цепочку вызовов. |
| `lookup` возвращает пустой объект | Режим отладки или неверные права RBAC | Помните об ограничениях `--dry-run` и проверьте ServiceAccount. |
| Ошибка парсинга YAML | Неверное количество отступов или лишние пустые строки | Проверьте значение в `nindent` и наличие `{{-` в управляющих блоках. |
| `range over map: недетерминированный порядок` | Итерация по словарю, где важен порядок | Замените `map` на `list` в `values.yaml` или сортируйте данные до рендеринга. |
| Значение `0` игнорируется в `if` | Логика истинности Helm (0 = false) | Используйте `{{ if ne (int .Values.val) 0 }}` или проверку на nil. |
| `values.schema.json` validation failed | Несоответствие типа или отсутствие обязательного поля | Проверьте схему и значения в `values.yaml`. |
