# Встроенные объекты Helm

---

## Определения

**Встроенные объекты** — предопределённые переменные, доступные во всех шаблонах Helm. Они предоставляют доступ к конфигурационным значениям пользователя, метаданным релиза, характеристикам самого чарта, а также к информации о кластере Kubernetes.

**Контекст (Scope)** — область видимости данных, доступная через символ точки (`.`). При использовании управляющих конструкций (циклов или условий) контекст может изменяться, смещая «точку» на вложенные элементы.

---

## Основные концепции

### Обзор доступных объектов

| Объект | Краткое описание |
|--------|------------------|
| `.Values` | Значения из `values.yaml` и флагов `--set` / `--values` |
| `.Release` | Информация о текущем релизе (имя, пространство имён, статус) |
| `.Chart` | Метаданные чарта из файла `Chart.yaml` |
| `.Capabilities` | Характеристики кластера Kubernetes и версии API |
| `.Files` | Доступ к не-шаблонным файлам в директории чарта |
| `.Template` | Информация о текущем обрабатываемом файле шаблона |
| `.Subcharts` | Доступ к данным и значениям вложенных чартов |

### Механизм слияния .Values

Объект `.Values` формируется путём объединения данных из нескольких источников. Более высокий приоритет перезаписывает значения:

1.  **Default values:** `values.yaml` в субчартах.
2.  **Parent values:** `values.yaml` родительского чарта.
3.  **User files:** Файлы, переданные через `-f` или `--values`.
4.  **CLI sets:** Параметры, переданные через `--set` или `--set-string`.

**Удаление ключей:** Чтобы полностью удалить ключ, определённый на уровне по умолчанию, при обновлении релиза ему следует присвоить значение `null` (в YAML) или использовать `--set key=null`.

### Глобальный контекст ($)

Переменная `$` всегда указывает на корневой контекст (объект верхнего уровня). Это критически важно внутри блоков `range` и `with`, где «точка» (`.`) меняет своё значение и перестаёт видеть `.Values` или `.Release`.

```go
{{- range .Values.items }}
  # . — текущий элемент списка
  # $ — доступ к глобальному объекту .Release
  name: {{ . }}-{{ $.Release.Name }}
{{- end }}
```

## Детальное описание объектов

### Объект .Release

Содержит данные о жизненном цикле и состоянии текущего релиза.

*   **.Release.Name**: Имя релиза (например, `my-app`).
*   **.Release.Namespace**: Целевое пространство имён в Kubernetes.
*   **.Release.IsInstall**: `true`, если выполняется `helm install`.
*   **.Release.IsUpgrade**: `true`, если выполняется `helm upgrade` или `helm rollback`.
*   **.Release.IsRollback**: `true`, если текущая операция является откатом.
*   **.Release.Revision**: Номер ревизии (инкрементируется при каждом обновлении).
*   **.Release.Service**: Название службы рендеринга (всегда `Helm`).

### Объект .Chart

Предоставляет доступ к полям файла `Chart.yaml`.

*   **.Chart.Name**: Имя чарта.
*   **.Chart.Version**: Версия чарта в формате SemVer.
*   **.Chart.AppVersion**: Версия приложения (может использоваться как тег образа).
*   **.Chart.Type**: Тип чарта (`application` или `library`).
*   **.Chart.IsRoot**: Показывает, является ли данный чарт корневым.

### Объект .Capabilities

Используется для создания адаптивных чартов, работающих в разных версиях Kubernetes.

*   **.Capabilities.KubeVersion**: Версия API Kubernetes (`Major`, `Minor`, `GitVersion`).
*   **.Capabilities.APIVersions.Has**: Проверка доступности API-ресурса. Например: `{{ if .Capabilities.APIVersions.Has "networking.k8s.io/v1/Ingress" }}`.
*   **.Capabilities.HelmVersion**: Версия клиента Helm.

### Объект .Files

Позволяет считывать содержимое файлов из директории чарта.

*   **.Files.Get**: Чтение файла как строки (`{{ .Files.Get "config.json" }}`).
*   **.Files.GetBytes**: Чтение файла как массива байтов (для бинарных данных).
*   **.Files.Glob**: Поиск файлов по маске (`{{ range .Files.Glob "files/*.txt" }}`).
*   **.Files.AsConfig**: Форматирует файлы для вставки в `ConfigMap`.
*   **.Files.AsSecrets**: Форматирует файлы для вставки в `Secret` (Base64).

**Ограничения:**
*   Не видит файлы в `templates/`.
*   Не видит файлы, указанные в `.helmignore`.
*   Максимальный размер файла — 1 МБ (из-за ограничений etcd в Kubernetes).

### Объект .Template

Информация о самом шаблоне.

*   **.Template.Name**: Путь к текущему файлу шаблона относительно корня чарта (например, `mychart/templates/deployment.yaml`).
*   **.Template.BasePath**: Путь к директории шаблонов (обычно `mychart/templates`).

## Практические сценарии

### Динамический выбор API-версии

Обеспечение совместимости чарта с кластерами разных поколений.

```yaml
apiVersion: {{ if .Capabilities.APIVersions.Has "policy/v1/PodDisruptionBudget" -}}
policy/v1
{{- else -}}
policy/v1beta1
{{- end }}
kind: PodDisruptionBudget
```

### Массовое добавление конфигурационных файлов

Автоматизация наполнения ConfigMap из папки.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-configs
data:
{{ (.Files.Glob "configs/**").AsConfig | indent 2 }}
```

### Использование .Chart.AppVersion для тегирования

Синхронизация версии манифеста с версией приложения.

```yaml
spec:
  containers:
  - name: app
    image: "myreg.com/app:{{ .Values.image.tag | default .Chart.AppVersion }}"
```

## Дополнительная информация

### Лучшие практики

*   **Всегда используйте $ в циклах:** Обращение к `.Values` внутри `range` без `$` — самая частая причина ошибок рендеринга.
*   **Глобальные значения (global):** Используйте раздел `.Values.global` для передачи данных между родительским и дочерними чартами (например, имя окружения или registry).
*   **Инкапсуляция субчартов:** Помните, что субчарты не видят `.Values` родителя, если только они не переданы через `global` или не переопределены в блоке имени субчарта.

### Устранение неисправностей

| Ошибка | Вероятная причина | Решение |
|--------|-------------------|---------|
| `nil pointer evaluating field Release` | Потеря контекста внутри `range` или `with` | Используйте `$.Release` вместо `.Release` |
| `.Files.Get` возвращает пустую строку | Файл в `templates/` или ошибка в пути | Переместите файл в корень чарта или проверьте `.helmignore` |
| Неверная версия API в манифесте | Использование `helm template` без подключения к кластеру | Добавьте `--api-versions` или используйте `helm install --dry-run` |
| `.Values` не обновляются | Конфликт приоритетов `--set` и файлов `-f` | Проверьте порядок аргументов в CLI (последний имеет приоритет) |
