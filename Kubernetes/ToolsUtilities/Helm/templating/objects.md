# Встроенные объекты Helm

---

## Определения

**Встроенные объекты** — предопределённые переменные, доступные во всех шаблонах Helm, которые предоставляют доступ к конфигурационным значениям, метаданным релиза, характеристикам чарта и возможностям Kubernetes-кластера.

**Контекст (Scope)** — область видимости, определяющая набор данных, доступных через точку (`.`).

---

## Основные концепции

### Обзор объектов

| Объект | Назначение |
|--------|------------|
| `.Values` | Пользовательские значения из `values.yaml` и флагов `--set` |
| `.Release` | Сведения о текущем релизе и его состоянии |
| `.Chart` | Метаданные чарта, определённые в `Chart.yaml` |
| `.Capabilities` | Информация о версии Kubernetes и поддерживаемых API |
| `.Files` | Доступ к не-шаблонным файлам внутри директории чарта |
| `.Template` | Метаданные текущего файла шаблона |
| `.Subcharts` | (Для родительских чартов) Доступ к данным вложенных чартов |

### Управление контекстом и областью видимости

Объекты доступны через символ точки (`.`), который представляет текущий контекст.

- **Смена контекста:** Конструкции `range` и `with` изменяют значение точки.
- **Глобальный контекст (`$`):** Переменная `$`, объявленная в начале рендеринга, всегда ссылается на корневой контекст. Это позволяет обращаться к глобальным объектам (например, `$.Release.Name`) изнутри циклов.

### Приоритет формирования .Values

Значения в объекте `.Values` объединяются из нескольких источников. Источник с более высоким номером перезаписывает значения предыдущих:

1.  `values.yaml` вложенных чартов (Subcharts).
2.  `values.yaml` родительского чарта.
3.  Файлы значений, переданные через `-f` или `--values`.
4.  Индивидуальные параметры, переданные через `--set`.

## Детальное описание объектов

### Объект .Values

Предоставляет доступ к параметрам конфигурации.

- **`.Values.<key>`**: Доступ к значению по ключу.
- **`.Values.global`**: Специальный зарезервированный раздел для передачи общих значений между родительским и дочерними чартами.

### Объект .Release

Содержит данные о текущем выполнении команды Helm.

- **`.Release.Name`**: Имя релиза, присвоенное при установке.
- **`.Release.Namespace`**: Пространство имён, в которое устанавливается релиз.
- **`.Release.IsInstall`**: Возвращает `true`, если выполняется первая установка (`helm install`).
- **`.Release.IsUpgrade`**: Возвращает `true`, если выполняется обновление (`helm upgrade`).
- **`.Release.IsRollback`**: Возвращает `true`, если выполняется откат версии (`helm rollback`).
- **`.Release.Revision`**: Номер ревизии (начинается с 1 и инкрементируется при каждом изменении).
- **`.Release.Service`**: Имя сервиса, обрабатывающего релиз (всегда `Helm`).

### Объект .Chart

Предоставляет доступ к содержимому `Chart.yaml`.

- **`.Chart.Name`**: Название чарта.
- **`.Chart.Version`**: Версия чарта (SemVer).
- **`.Chart.AppVersion`**: Версия приложения, упакованного в чарт.
- **`.Chart.Type`**: Тип чарта (`application` или `library`).
- **`.Chart.IsRoot`**: Флаг, указывающий, является ли чарт корневым.

### Объект .Capabilities

Позволяет адаптировать шаблоны под конкретную среду исполнения.

- **`.Capabilities.KubeVersion`**: Версия Kubernetes. Содержит поля `Version`, `Major`, `Minor`, `GitVersion`.
- **`.Capabilities.APIVersions.Has "group/version/kind"`**: Проверка наличия поддержки конкретной версии API (например, `networking.k8s.io/v1/Ingress`).
- **`.Capabilities.HelmVersion`**: Версия самого клиента Helm. Содержит поля `Version` и `GitCommit`.

### Объект .Files

Методы для работы с файлами, не являющимися шаблонами.

- **`.Files.Get <path>`**: Возвращает содержимое файла в виде строки.
- **`.Files.GetBytes <path>`**: Возвращает содержимое файла в виде массива байтов (важно для бинарных данных).
- **`.Files.Glob <pattern>`**: Возвращает объект `Files` со списком файлов, соответствующих маске.
- **`.Files.AsConfig`**: Удобная обертка для вставки файлов в блок `data` для ConfigMap.
- **`.Files.AsSecrets`**: Удобная обертка для вставки файлов в блок `data` для Secret (автоматически кодирует в Base64).

**Ограничения:** `.Files` не имеет доступа к файлам в директории `templates/` и к файлам за пределами текущего чарта.

## Практические сценарии

### Использование .Capabilities для совместимости API

```yaml
apiVersion: {{ if .Capabilities.APIVersions.Has "networking.k8s.io/v1/Ingress" -}}
networking.k8s.io/v1
{{- else -}}
networking.k8s.io/v1beta1
{{- end }}
kind: Ingress
```

### Динамическое создание ConfigMap из набора файлов

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-config
data:
{{ (.Files.Glob "configs/*.yaml").AsConfig | indent 2 }}
```

### Передача данных между чартами через .Values.global

В родительском `values.yaml`:
```yaml
global:
  environment: production
```

В шаблоне дочернего чарта:
```yaml
metadata:
  labels:
    env: {{ .Values.global.environment }}
```

## Дополнительная информация

### Лучшие практики

- **Использование $:** При итерации (`range`) всегда используйте `$` для обращения к глобальным объектам (`$.Release.Name`), чтобы избежать ошибок `nil pointer`.
- **Проверка API:** Используйте `.Capabilities` для поддержки обратной совместимости чартов с разными версиями Kubernetes.
- **Версионирование:** Используйте `.Chart.AppVersion` для тегов образов в манифестах Deployment, если они совпадают с версией приложения в чарте.
- **Откат:** Используйте `.Release.IsRollback` для специфической логики, которая должна срабатывать только при возврате к предыдущей версии.

### Устранение неисправностей

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `can't evaluate field Release in type string` | Попытка обращения к `.Release` внутри `range` без `$` | Замените на `$.Release` |
| `.Files.Get` возвращает пустой результат | Файл находится в `templates/` или путь указан неверно | Переместите файл в корень или в другую директорию (не `templates/`) |
| `.Capabilities` не видит API в `helm template` | `helm template` по умолчанию не обращается к кластеру | Используйте флаг `--api-versions` или выполняйте команду с `--validate` |
