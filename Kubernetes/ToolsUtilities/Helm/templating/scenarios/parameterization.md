# Параметризация через values.yaml в Helm

---

## Определения

**Параметризация** — архитектурный паттерн Helm, заключающийся в отделении конфигурационных данных от логики манифестов. Позволяет трансформировать статические манифесты в динамические шаблоны, адаптируемые под разные окружения без изменения кода чарта.

**.Values** — ключевой встроенный объект Helm, представляющий собой объединенную карту (map) параметров. Формируется в процессе рендеринга путем слияния значений из нескольких источников.

**values.schema.json** — файл спецификации (JSON Schema), используемый для декларативной валидации структуры, типов данных и ограничений в `values.yaml` перед началом выполнения шаблонов.

---

## Базовые концепции

### Проблема хардкода и технические риски

Использование жестко заданных значений в шаблонах снижает гибкость и создает риски для стабильности кластера.

| Проблема | Технический риск |
| :--- | :--- |
| **Дублирование портов** | Ошибка маршрутизации трафика при рассинхронизации порта в Deployment и Service. |
| **Статичные имена** | Коллизии ресурсов при попытке развернуть несколько релизов в одном пространстве имен. |
| **Хардкод образов** | Невозможность автоматического обновления версий через CI/CD или использования разных реестров. |
| **Жесткие лимиты** | Риск OOMKill или CPU Throttling из-за невозможности адаптации под ресурсы конкретных узлов. |

### Иерархия и приоритеты слияния

Helm выполняет глубокое слияние (deep merge) для словарей, но **замещает** списки целиком. Приоритет источников (от низшего к высшему):

1.  **Дефолтные значения субчартов:** `values.yaml` внутри зависимостей.
2.  **Дефолтные значения основного чарта:** Корневой `values.yaml`.
3.  **Пользовательские файлы:** Переданные через `-f` или `--values`.
4.  **CLI-параметры:** `--set`, `--set-string`, `--set-file` или `--set-json` (наивысший приоритет).

**Удаление ключей:** Чтобы полностью удалить ключ при слиянии, установите его значение в `null` в файле с более высоким приоритетом.

### Глобальные значения (global)

Раздел `global` является зарезервированным. Значения внутри него автоматически становятся доступны всем субчартам без необходимости явного проброса через переменные.

```yaml
global:
  registry: registry.example.com
  environment: production
```

## Практические сценарии

### Структурирование values.yaml

Рекомендуется группировать параметры по функциональным блокам и использовать кавычки для потенциально неоднозначных типов (теги, версии).

**values.yaml:**
```yaml
app:
  replicas: 2
  port: 8080

image:
  repository: my-app
  tag: "1.2.0" # Кавычки предотвращают интерпретацию 1.20 как числа 1.2
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80
```

### Синхронизация ресурсов через единый порт

Использование общего источника прав (`.Values.app.port`) гарантирует связность Deployment и Service.

**templates/deployment.yaml:**
```yaml
spec:
  containers:
    - name: app
      ports:
        - containerPort: {{ .Values.app.port }}
```

**templates/service.yaml:**
```yaml
spec:
  ports:
    - port: {{ .Values.service.port }}
      targetPort: {{ .Values.app.port }} # Ссылка на тот же параметр
```

### Локальные переменные и сложные пути

Использование `$var := ...` сокращает код и повышает читаемость. Функция `index` помогает обращаться к ключам с динамическими именами или спецсимволами.

```yaml
{{- $image := .Values.image -}}
{{- $fullName := include "myapp.fullname" . -}}
{{- $envConfig := index .Values.envConfigs .Values.global.environment -}}

metadata:
  name: {{ $fullName }}
spec:
  containers:
    - name: web
      image: "{{ $image.repository }}:{{ $image.tag | default .Chart.AppVersion }}"
```

### Работа со списками (Environment Variables)

Цикл `range` позволяет динамически генерировать блоки переменных окружения.

```yaml
env:
{{- range $name, $value := .Values.envVars }}
  - name: {{ $name | upper }}
    value: {{ $value | quote }}
{{- end }}
```

### Обязательные параметры (Required) и tpl

Используйте `required` для критических данных и `tpl` для рендеринга шаблонов, находящихся внутри строк `values.yaml`.

```yaml
# Прерывание установки, если URL не задан
{{- $dbUrl := required "Database URL is required!" .Values.db.url -}}

# Рендеринг шаблона из values
{{ tpl .Values.config.template . | nindent 4 }}
```

## Валидация и тестирование

### Проверка через JSON Schema

Файл `values.schema.json` обеспечивает строгую типизацию и валидацию данных перед рендерингом.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "properties": {
    "app": {
      "type": "object",
      "required": ["replicas"],
      "properties": {
        "replicas": { "type": "integer", "minimum": 1, "maximum": 10 }
      }
    }
  }
}
```

### Команды для проверки чарта

| Команда | Назначение |
| :--- | :--- |
| `helm lint .` | Статический анализ структуры и синтаксиса шаблонов. |
| `helm template .` | Рендеринг манифестов в stdout для визуального аудита. |
| `helm install --dry-run` | Валидация сгенерированных манифестов на стороне Kubernetes API. |

## Дополнительная информация

### Лучшие практики

1.  **Принцип SSoT (Single Source of Truth):** Каждый уникальный параметр (порт, домен) должен определяться в `values.yaml` ровно один раз.
2.  **Явное кавычивание:** Всегда используйте `| quote` для строковых параметров, чтобы избежать ошибок с числами (`08`) или булевыми значениями.
3.  **Иерархия ресурсов:** Старайтесь не превышать глубину вложенности в 3–4 уровня для удобства использования `--set`.
4.  **Значения по умолчанию:** Обеспечьте работоспособность чарта с дефолтным `values.yaml` «из коробки», где это возможно.

### Устранение неисправностей

| Ошибка | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `nil pointer evaluating` | Ошибка в пути к параметру или регистре | Проверьте точность пути (например, `.Values.App` vs `.Values.app`). |
| Значение не изменилось | Нарушен приоритет переопределения | Проверьте порядок `-f` и наличие переопределений в `--set`. |
| `YAML parse error` | Спецсимволы в строке или ошибка отступов | Оберните значение в кавычки или используйте `| quote` + `nindent`. |
| `schema validation failed` | Несоответствие типов данных | Проверьте `values.yaml` на соответствие правилам в `values.schema.json`. |
