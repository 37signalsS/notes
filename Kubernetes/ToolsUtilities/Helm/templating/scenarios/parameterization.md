# Параметризация через values.yaml в Helm

---

## Определения

**Параметризация** — архитектурный паттерн Helm, заключающийся в отделении конфигурационных данных от логики манифестов. Позволяет трансформировать статические манифесты в динамические шаблоны, адаптируемые под разные окружения без изменения кода чарта.

**.Values** — ключевой встроенный объект Helm, представляющий собой объединенную карту (map) параметров. Формируется в процессе рендеринга путем слияния значений из нескольких источников.

**values.schema.json** — файл спецификации (JSON Schema), используемый для декларативной валидации структуры, типов данных и ограничений в `values.yaml` перед началом выполнения шаблонов.

**Глубокое слияние (Deep Merge)** — механизм объединения словарей (maps), при котором вложенные ключи сливаются рекурсивно. В отличие от словарей, списки (lists) замещаются целиком.

**Subchart Isolation** — принцип изоляции значений субчартов: дочерний чарт по умолчанию не видит `.Values` родителя, если значения не переданы явно через `global`, вложенную секцию или `import-values`.

## Базовые концепции

### Механика слияния значений

Helm выполняет **глубокое слияние (deep merge)** для словарей, но **полностью замещает** списки. Это критично для понимания поведения мультиокружных деплоев:

| Тип данных | Правило слияния | Пример |
| :--- | :--- | :--- |
| **Словарь (map)** | Рекурсивное слияние | `parent: {a: 1, b: 2}` + `parent: {b: 3}` → `{a: 1, b: 3}` |
| **Список (list)** | Полная замена | `env: [A, B]` + `env: [C]` → `[C]` |
| **Скаляр** | Перезапись | `replicas: 3` + `replicas: 5` → `5` |

**Удаление ключей:** Чтобы полностью удалить ключ, определённый на уровне дефолта, установите его значение в `null` в файле с более высоким приоритетом. Это единственный способ добиться отсутствия ключа в итоговом `.Values`.

```yaml
# values-production.yaml
service:
  type: null  # Удалит service.type из дефолтного values.yaml
```

### Иерархия и приоритеты слияния

Helm объединяет значения по строгой иерархии (от низшего к высшему):

1.  **Дефолтные значения субчартов:** `values.yaml` внутри зависимостей.
2.  **Дефолтные значения основного чарта:** Корневой `values.yaml`.
3.  **Пользовательские файлы:** Переданные через `-f` или `--values`.
4.  **CLI-параметры:** `--set`, `--set-string`, `--set-file` или `--set-json` (наивысший приоритет).

**Важно:** При использовании нескольких файлов `-f`, последний файл в цепочке имеет более высокий приоритет и перезаписывает совпадающие ключи.

### CLI-инструменты для параметризации

| Инструмент | Назначение | Особенности |
| :--- | :--- | :--- |
| `--set key=value` | Быстрое переопределение одного параметра | Поддерживает точечную нотацию (`image.tag=1.2.0`). Имеет ограничения на спецсимволы. |
| `--set-string key=value` | Принудительная интерпретация как строка | Полезно для номеров портов (`--set-string service.port=8080`), чтобы избежать преобразования в число с потерей ведущих нулей. |
| `--set-file key=path` | Вставка содержимого файла | Заменяет значение на содержимое файла. Идеально для конфигурационных блоков (например, JSON-конфиг). |
| `--set-json key=json` | Вставка JSON-строки как структуры | Helm парсит JSON и вставляет как нативный объект/список в `.Values`. |

**Ограничения `--set`:**
- **Списки:** Невозможно изменить отдельный элемент списка. `--set env[0].name=FOO` работает только если список уже определён как `[]`.
- **Спецсимволы:** Ключи с точками или скобками требуют кавычек: `--set "my\.key=value"`.
- **Вложенность:** Для глубокой вложенности точечная нотация становится нечитаемой (`server.config.database.host`).

### Глобальные значения (global)

Раздел `global` является зарезервированным. Значения внутри него автоматически становятся доступны всем субчартам без необходимости явного проброса через переменные.

```yaml
global:
  registry: registry.example.com
  environment: production
```

### Наследование в субчартах

При работе с зависимыми чартами (subcharts) действуют правила изоляции:
- **Вложенная секция:** Родительский чарт переопределяет значения дочернего через секцию с именем зависимости (или `alias`).
- **Global:** Значения из `global` автоматически наследуются всеми зависимостями.
- **import-values:** Механизм для экспорта значений из дочернего чарта в область видимости родительского.

```yaml
# parent-chart/values.yaml
postgresql:
  primary:
    persistence:
      enabled: true
      size: 20Gi
```

### Безопасность: секреты в values.yaml

**Категорически запрещено** хранить пароли, токены, ключи SSH/TLS и другие чувствительные данные в `values.yaml`, особенно если чарт хранится в Git.

| Риск | Последствие | Рекомендация |
| :--- | :--- | :--- |
| Утечка в Git-истории | Секрет доступен любому с доступом к репозиторию | Используйте Kubernetes Secrets с `existingSecret`, HashiCorp Vault, SOPS/helm-secrets |
| Слив при деплое | Секрет виден в `helm get values` и истории релизов | Инжектируйте секреты через CI/CD переменные окружения во время `helm upgrade` |
| Избыточные права | `values.yaml` часто коммитят с открытыми секретами | Разделите конфигурацию: `values.yaml` (несекретные параметры) + `secrets.yaml` (шифрованный через SOPS) |

## Практические сценарии

### Структурирование values.yaml

Рекомендуется группировать параметры по функциональным блокам и использовать кавычки для потенциально неоднозначных типов (теги, версии).

**values.yaml:**
```yaml
app:
  replicas: 2
  port: 8080

image:
  repository: my-app
  tag: "1.2.0" # Кавычки предотвращают интерпретацию 1.20 как числа 1.2
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80
```

### Многоокружная стратегия через values-файлы

Паттерн «один чарт — много окружений» требует организации слоёв конфигурации:

```
my-chart/
├── Chart.yaml
├── values.yaml            # Дефолты (dev)
├── values-staging.yaml    # Переопределения staging
├── values-production.yaml # Переопределения production
└── templates/
```

**Применение:**
```bash
# Development
helm upgrade --install app ./chart -f values.yaml

# Staging
helm upgrade --install app ./chart \
  -f values.yaml \
  -f values-staging.yaml \
  --namespace staging

# Production
helm upgrade --install app ./chart \
  -f values.yaml \
  -f values-production.yaml \
  --namespace production
```

**Правило:** Каждый файл `-f` перезаписывает совпадающие ключи из предыдущих. Используйте `helm template` для проверки итогового слияния.

### Инспекция слиянных значений

Для отладки и аудита используйте команды интроспекции:

```bash
# Просмотр финальных merged values релиза
helm get values my-release -n production

# Просмотр с учетом дефолтов чарта (включая не переопределённые ключи)
helm get values my-release -n production --all

# Сравнение желаемых и фактических значений
helm get values my-release -n production -o yaml > actual-values.yaml
diff expected-values.yaml actual-values.yaml
```

### Синхронизация ресурсов через единый порт

Использование общего источника прав (`.Values.app.port`) гарантирует связность Deployment и Service.

**templates/deployment.yaml:**
```yaml
spec:
  containers:
    - name: app
      ports:
        - containerPort: {{ .Values.app.port }}
```

**templates/service.yaml:**
```yaml
spec:
  ports:
    - port: {{ .Values.service.port }}
      targetPort: {{ .Values.app.port }} # Ссылка на тот же параметр
```

### Локальные переменные и сложные пути

Использование `$var := ...` сокращает код и повышает читаемость. Функция `index` помогает обращаться к ключам с динамическими именами или спецсимволами.

```yaml
{{- $image := .Values.image -}}
{{- $fullName := include "myapp.fullname" . -}}
{{- $envConfig := index .Values.envConfigs .Values.global.environment -}}

metadata:
  name: {{ $fullName }}
spec:
  containers:
    - name: web
      image: "{{ $image.repository }}:{{ $image.tag | default .Chart.AppVersion }}"
```

### Работа со списками (Environment Variables)

Цикл `range` позволяет динамически генерировать блоки переменных окружения.

```yaml
env:
{{- range $name, $value := .Values.envVars }}
  - name: {{ $name | upper }}
    value: {{ $value | quote }}
{{- end }}
```

### Обязательные параметры (Required) и tpl

Используйте `required` для критических данных и `tpl` для рендеринга шаблонов, находящихся внутри строк `values.yaml`.

```yaml
# Прерывание установки, если URL не задан
{{- $dbUrl := required "Database URL is required!" .Values.db.url -}}

# Рендеринг шаблона из values
{{ tpl .Values.config.template . | nindent 4 }}
```

### Валидация через values.schema.json

Файл `values.schema.json` обеспечивает строгую типизацию и валидацию данных перед рендерингом. Начиная с Helm 3, валидация выполняется автоматически при `helm install`, `helm upgrade` и `helm lint`.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "properties": {
    "app": {
      "type": "object",
      "required": ["replicas"],
      "properties": {
        "replicas": { "type": "integer", "minimum": 1, "maximum": 10 },
        "port": { "type": "integer", "exclusiveMinimum": 0, "exclusiveMaximum": 65536 }
      }
    },
    "image": {
      "type": "object",
      "required": ["repository", "tag"],
      "properties": {
        "repository": { "type": "string", "pattern": "^[a-zA-Z0-9._/-]+(:[0-9]+)?/[a-zA-Z0-9._-]+$" },
        "tag": { "type": "string", "pattern": "^[a-zA-Z0-9._-]+$" }
      }
    }
  }
}
```

### Валидация в CI/CD пайплайне

Интеграция статической валидации в pipeline снижает риск деплоя нерабочих конфигураций:

```bash
#!/bin/bash
set -euo pipefail

CHART_DIR="./my-chart"
VALUES_FILE="values.yaml"

# 1. Линтинг и валидация схемы
helm lint "$CHART_DIR" --strict -f "$VALUES_FILE"

# 2. Рендеринг с проверкой YAML
helm template test-release "$CHART_DIR" -f "$VALUES_FILE" | kubeconform --strict

# 3. Проверка секретов на наличие в values.yaml
if grep -q "password\|secret\|token\|key" "$VALUES_FILE"; then
  echo "WARNING: Possible secrets found in values.yaml"
  exit 1
fi

echo "All validation checks passed"
```

### Использование --set в автоматизации

В CI/CD скриптах `--set` удобен для точечных переопределений, но требует осторожности:

```bash
# Правильно: переопределение образа и реплик
helm upgrade --install app ./chart \
  --set image.tag=${CI_COMMIT_SHORT_SHA} \
  --set app.replicas=${REPLICA_COUNT} \
  --namespace production

# Опасно: секреты через --set (видимы в процессах и логах)
helm upgrade --install app ./chart \
  --set db.password=${DB_PASSWORD} # ЗАПРЕЩЕНО
```

## Валидация и тестирование

### Команды для проверки чарта

| Команда | Назначение |
| :--- | :--- |
| `helm lint .` | Статический анализ структуры и синтаксиса шаблонов, включая валидацию `values.schema.json`. |
| `helm template .` | Рендеринг манифестов в stdout для визуального аудита слияния значений. |
| `helm install --dry-run` | Валидация сгенерированных манифестов на стороне Kubernetes API. |
| `helm show values .` | Вывод дефолтного `values.yaml` чарта для аудита доступных параметров. |
| `helm get values <release>` | Просмотр фактически применённых значений в релизе. |

## Дополнительная информация

### Лучшие практики

1.  **Принцип единственного источника правды:** Каждый уникальный параметр (порт, домен, версия) должен определяться в `values.yaml` ровно один раз. Все ссылки в шаблонах должны указывать на этот источник.
2.  **Явное кавычивание:** Всегда используйте `| quote` для строковых параметров, чтобы избежать ошибок с числами (`08`) или булевыми значениями.
3.  **Иерархия ресурсов:** Старайтесь не превышать глубину вложенности в 3–4 уровня для удобства использования `--set`.
4.  **Значения по умолчанию:** Обеспечьте работоспособность чарта с дефолтным `values.yaml` «из коробки», где это возможно.
5.  **Защита от секретов:** Никогда не коммитьте `values.yaml` с открытыми секретами. Используйте `existingSecret` или внешние системы (Vault, SOPS).
6.  **Версионирование:** Фиксируйте версии образов и чартов в `values.yaml`. Избегайте тегов `latest` в production.
7.  **Идемпотентность:** `helm upgrade --install` с фиксированными параметрами должен давать одинаковый результат при повторном запуске.
8.  **Режим --atomic:** Используйте `--atomic` для автоматического отката при ошибках деплоя. В сочетании с `--wait` это гарантирует, что релиз либо успешен, либо не виден.

### Устранение неисправностей

| Ошибка | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `nil pointer evaluating` | Ошибка в пути к параметру или регистре | Проверьте точность пути (например, `.Values.App` vs `.Values.app`). |
| `unknown flag: --set` | Устаревшая версия Helm | Убедитесь, что используется Helm 3+. |
| Значение не изменилось | Нарушен приоритет переопределения | Проверьте порядок `-f` и наличие переопредежений в `--set`. |
| `YAML parse error` | Спецсимволы в строке или ошибка отступов | Оберните значение в кавычки или используйте `| quote` + `nindent`. |
| `schema validation failed` | Несоответствие типов данных | Проверьте `values.yaml` на соответствие правилам в `values.schema.json`. |
| `cannot patch` (Secret > 1MB) | Слишком большие значения в NOTES или values | Вынесите большие блоки в ConfigMap. |
| `--set` не применяется к списку | Замена списка работает только целиком | Используйте файл `-f` для изменения конкретных элементов списка. |
| Секрет виден в `helm get values` | Секрет передавался через `--set` или в `values.yaml` | Переместите секрет в Kubernetes Secret и используйте `valueFrom`/`existingSecret`. |
