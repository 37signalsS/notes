# Работа с ConfigMap и внешними файлами

---

## Определения

**.Files** — встроенный объект Helm, предназначенный для доступа к любым файлам внутри директории чарта, за исключением файлов в `templates/` и путей, указанных в `.helmignore`.

**Экранирование шаблонизатора** — метод сохранения символов `{{` и `}}` в результирующем файле без их интерпретации движком Go Templates.

---

## Базовые концепции

### Особенности объекта .Files

- **Доступность:** Файлы должны находиться внутри структуры чарта.
- **Ограничения:** Доступ к файлам в `templates/` через `.Files` невозможен, так как они зарезервированы для рендеринга манифестов.
- **Лимиты:** Общий размер ресурсов ConfigMap и Secret в Kubernetes ограничен 1 МБ. Массовая вставка тяжелых бинарных файлов может привести к ошибке `request is too large`.
- **Пути:** Все пути к файлам указываются относительно корня чарта.

### Методы работы с файлами

| Метод | Описание |
|-------|----------|
| `.Files.Get "path"` | Возвращает содержимое файла в виде строки. |
| `.Files.Glob "pattern"` | Возвращает словарь (map), где ключи — пути к файлам, соответствующие glob-шаблону. |
| `.Files.AsConfig` | Автоматически формирует блок `data` для ConfigMap из результатов Glob. |
| `.Files.AsSecrets` | Автоматически кодирует содержимое в Base64 для использования в Secret. |
| `.Files.Lines "path"` | Построчное чтение файла (полезно для итерации в `range`). |

## Практические сценарии

### Вставка содержимого отдельного файла

Типовой пример для вставки конфигурации Nginx или JSON-настроек.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "myapp.fullname" . }}-config
data:
  nginx.conf: |
    {{ .Files.Get "configs/nginx.conf" | nindent 4 }}
```

### Массовая вставка файлов через Glob

Используется, когда в чарте есть целая директория с конфигурациями (например, `sql/` или `scripts/`).

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "myapp.fullname" . }}-scripts
data:
{{ (.Files.Glob "scripts/*.sh").AsConfig | nindent 2 }}
```

### Динамический рендеринг внешних файлов (Files + tpl)

Если внешний файл сам содержит шаблоны (например, переменные окружения), необходимо комбинировать `.Files.Get` с функцией `tpl`.

```yaml
data:
  templated_config.conf: |
{{ tpl (.Files.Get "files/app.conf") . | nindent 4 }}
```

### Создание Secret из бинарных файлов

Метод `.Files.AsSecrets` автоматически выполняет Base64-кодирование.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: {{ include "myapp.fullname" . }}-certs
type: Opaque
data:
{{ (.Files.Glob "certs/*.crt").AsSecrets | nindent 2 }}
```

### Экранирование управляющих символов `{{ }}`

Для файлов конфигурации Prometheus или Postfix, где синтаксис совпадает с Helm, используйте «разрыв» кавычками.

```yaml
data:
  prometheus-rule.yaml: |
    groups:
      - name: example
        rules:
          - alert: HighCpu
            expr: job:node_cpu:avg5min > `{{` .Values.threshold `}}`
```
*Результат после рендеринга: `job:node_cpu:avg5min > {{ .Values.threshold }}`*

## Дополнительная информация

### Лучшие практики

1. **Использование .helmignore:** Всегда исключайте временные файлы, документацию и `.git` из чарта, чтобы они не попали в объект `.Files.Glob` и не увеличивали размер релиза.
2. **Проверка существования:** Перед вызовом `.Files.Get` рекомендуется проверять наличие файла, чтобы избежать ошибок при рендеринге.
3. **Безопасность:** Не храните чувствительные данные (пароли, ключи) в открытом виде в директории чарта. Используйте Helm Secrets или внешние Secret-менеджеры.
4. **Кодировка:** Убедитесь, что все текстовые файлы сохранены в кодировке UTF-8 для корректной обработки шаблонизатором.

### Устранение неисправностей

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `file not found` | Неверный путь относительно корня чарта | Путь должен начинаться от корня (например, `files/config.json`, а не `../files/`). |
| `request is too large` | Превышен лимит 1 МБ для Secret/ConfigMap | Уменьшите количество файлов или их размер. Используйте внешние хранилища для больших данных. |
| Неверные отступы в YAML | Использование `indent` вместо `nindent` | Используйте `nindent` для автоматического добавления новой строки перед блоком данных. |
