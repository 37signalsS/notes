# Обзор сценариев шаблонизации Helm

---

## Определения

**Сценарии шаблонизации** — это типовые архитектурные паттерны и практические приёмы использования движка шаблонов Helm для решения конкретных задач развёртывания. Они включают в себя подходы к параметризации, управлению жизненным циклом ресурсов и адаптации манифестов под различные окружения.

**Best Practices в шаблонизации** — набор правил и подходов (например, принцип DRY — Don't Repeat Yourself), направленных на создание читаемых, поддерживаемых и расширяемых Helm-чартов.

---

## Базовые концепции

Сценарии в данном разделе разделены на категории по решаемым задачам. Каждый сценарий представляет собой изолированный пример с описанием проблемы, предлагаемым решением и разбором кода.

### Принципы построения сценариев:
- **Типизация:** использование оптимальных типов данных в `values.yaml`.
- **Безопасность:** защита чувствительных данных и предотвращение ошибок рендеринга.
- **Гибкость:** возможность адаптации чарта без изменения его внутренней логики.
- **Валидация:** проверка входных данных на этапе генерации манифестов.

## Практические сценарии

### Фундаментальные паттерны
- [**Параметризация**](./parameterization.md) — базовый сценарий выноса конфигурации в `values.yaml`. Рассматривает работу с глобальными переменными, структурами данных и типами параметров.
- [**Условная логика**](./conditionals.md) — управление составом релиза через `if/else`, использование логических функций (`and`, `or`, `not`) и тернарных операторов для гибкого включения ресурсов.

### Работа с конфигурацией и данными
- [**ConfigMap и внешние файлы**](./configmap_files.md) — методы вставки содержимого файлов через объект `.Files`. Использование функций `.Files.Get`, `.Files.Glob` и автоматическое кодирование в Base64 для ресурсов Secret.
- [**Restart on Change**](./restart_on_change.md) — паттерн автоматического перезапуска подов (rolling update) при обновлении ConfigMap или Secret с помощью аннотаций контрольной суммы (`checksum/config`).

### Инфраструктурная адаптация
- [**API-версии и возможности кластера**](./api_versions.md) — использование объекта `.Capabilities` для создания чартов, совместимых с разными версиями Kubernetes. Динамический выбор API-групп для Ingress и других ресурсов.
- [**Сетевые политики (NetworkPolicy)**](./networkpolicy.md) — шаблонизация правил доступа к сервисам, условное создание правил для различных окружений и управление трафиком.

### Инструкции и обратная связь
- [**Динамические заметки (NOTES.txt)**](./notes_txt.md) — формирование информативных сообщений для пользователя после установки чарта. Включает примеры вывода URL-адресов, паролей и команд для проверки статуса приложения.
