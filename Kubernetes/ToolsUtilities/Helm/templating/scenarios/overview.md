# Обзор сценариев шаблонизации Helm

---

## Определения

**Сценарии шаблонизации** — практические примеры применения Helm-шаблонов к типовым задачам, таким как параметризация, условная логика, адаптация под кластер, работа с файлами и конфигурацией.

---

## Базовые концепции

Сценарии сгруппированы по области применения. Каждый файл в данном разделе посвящён одной конкретной задаче и содержит практические примеры кода с подробными пояснениями.

---

## Практические сценарии

### Основы шаблонизации

[**Параметризация**](./parameterization.md) — вынос жестко заданных значений (hardcode) в `values.yaml`, использование централизованной конфигурации, работа с различными типами параметров.  
[**Условная логика**](./conditionals.md) — применение `if/else`, условное создание ресурсов Kubernetes, составные условия с использованием функций `and` и `eq`.

### Работа с данными и файлами

[**ConfigMap и файлы**](./configmap_files.md) — вставка содержимого файлов из директории `files/` через объект `.Files.Get`, массовая вставка файлов через `.Files.Glob`, экранирование управляющих символов `{{ }}`.

### Адаптация под кластер

[**API-версии**](./api_versions.md) — использование объекта `.Capabilities` для автоматической адаптации манифестов под доступные версии API (Application Programming Interface) в конкретном кластере Kubernetes.  
[**Restart on Change**](./restart_on_change.md) — реализация автоматического пересоздания подов (rolling update) при изменении ConfigMap с помощью аннотаций контрольной суммы (checksum).

### Инструкции и документация

[**NOTES.txt**](./notes_txt.md) — формирование динамических пост-установочных инструкций для пользователя, использование функции `lookup` для получения текущего состояния кластера.

### Сетевые политики

[**NetworkPolicy**](./networkpolicy.md) — шаблонизация сетевых политик Kubernetes с применением именованных шаблонов, условное включение правил, управление трафиком между пространствами имен (namespaces).
