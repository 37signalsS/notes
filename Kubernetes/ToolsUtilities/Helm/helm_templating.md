# Шаблонизация в Helm

Helm использует движок **Go Templates** (стандартная библиотека `text/template`) в сочетании с библиотекой **Sprig** для динамической генерации манифестов Kubernetes. Шаблонизация позволяет превратить статические YAML-файлы в гибкие конфигурационные пакеты, которые адаптируются к различным окружениям (dev, staging, prod) без дублирования кода.

---

## Определения

| Термин | Описание |
|--------|----------|
| **Go Templates** | Движок шаблонизации на языке Go, используемый Helm для рендеринга манифестов на основе логики и данных. |
| **Библиотека Sprig** | Набор из 100+ функций (строковых, математических, криптографических), расширяющий возможности Go Templates. |
| **Контекст (Scope)** | Текущая область видимости данных, обозначаемая точкой (`.`). Влияет на доступность переменных объекта. |
| **Встроенные объекты** | Предопределённые переменные (`.Values`, `.Release`, `.Chart`, `.Capabilities`), предоставляющие доступ к метаданным. |
| **Именованные шаблоны** | Переиспользуемые фрагменты кода (partial), определяемые в `_helpers.tpl` через конструкцию `define`. |
| **Whitespace Control** | Механизм удаления лишних пробелов и переносов строк с помощью дефисов (`{{-` и `-}}`). |
| **Pipeline (Пайплайн)** | Цепочка функций, где результат выполнения одной передаётся в качестве аргумента следующей через символ `|`. |
| **Immutable Release** | Концепция, при которой шаблоны не содержат хардкода окружных значений (имена, неймспейсы, образы). Все параметры должны приходить из `values.yaml` или встроенных объектов. |
| **Двухпроходный рендеринг** | Механизм Helm: сначала парсинг всех шаблонов в AST, затем подстановка значений и генерация итоговых YAML-манифестов. |
| **Глубокое слияние (Deep Merge)** | Алгоритм объединения словарей в Helm, при котором вложенные ключи сливаются рекурсивно, а списки замещаются целиком. |

## Базовые концепции

### Движок Go Templates и синтаксис

Все инструкции шаблонизатора заключаются в двойные фигурные скобки `{{ }}`. Helm обрабатывает все файлы в директории `templates/`, за исключением файлов, начинающихся с нижнего подчеркивания (например, `_helpers.tpl`).

*   **Вставка значений**: `{{ .Values.image.tag }}`.
*   **Функции**: `{{ quote .Values.name }}` или в стиле пайплайна: `{{ .Values.name | quote }}`.
*   **Условная логика**: `if/else` блоки для включения или исключения ресурсов.
*   **Циклы**: `range` для генерации списков (env, volumes, ports).

### Управление контекстом (Scope)

Понимание контекста — критический навык при разработке чартов.
1.  **Точка (`.`)** : Ссылается на текущий контекст. В начале рендеринга это корень чарта.
2.  **Смена контекста**: Конструкции `with` и `range` меняют значение точки. Внутри `range` точка ссылается на текущий элемент списка.
3.  **Глобальный контекст (`$`)** : Символ `$` всегда ссылается на корневой объект. Это необходимо для доступа к `.Release` или `.Values` внутри циклов.

### Управление пробелами (Whitespace Control)

YAML крайне чувствителен к отступам. Helm предоставляет инструменты для точного контроля:
- `{{- ` (с пробелом после дефиса) — удаляет все пробелы и переносы строк **слева** от блока.
- ` -}}` (с пробелом перед дефисом) — удаляет пробелы и переносы строк **справа**.
- **Функция `nindent`** : Самый надежный способ вставки многострочных YAML-блоков. В отличие от `indent`, она всегда добавляет перенос строки перед вставкой, гарантируя корректность структуры.

### Двухпроходный рендеринг и порядок загрузки

Helm выполняет рендеринг в два этапа:
1.  **Парсинг:** Все файлы в `templates/` загружаются в алфавитном порядке и проверяются на синтаксическую корректность. Файлы с префиксом `_` загружаются первыми, поэтому их определения `define` могут быть переопределены позже загруженными файлами.
2.  **Выполнение:** Движок Go templates обходит AST, вычисляет выражения, подставляет значения из объединённой карты `.Values` и генерирует итоговые YAML-манифесты.

**Важно для SRE:** При конфликте имён `define` побеждает последнее загруженное определение. Используйте префикс имени чарта (`mychart.labels`) для избежания коллизий с субчартами.

### Механизм слияния .Values

Объект `.Values` формируется путём объединения данных из нескольких источников. Helm выполняет **глубокое слияние (deep merge)** для словарей, но **замещает** списки целиком. Более высокий приоритет перезаписывает значения:
1.  **Default values (субчарты)** : `values.yaml` внутри зависимостей.
2.  **Default values (родитель)** : `values.yaml` корневого чарта.
3.  **User files** : Файлы, переданные через `-f` или `--values`.
4.  **CLI sets** : Параметры, переданные через `--set`, `--set-string`, `--set-file` или `--set-json` (наивысший приоритет).

**Удаление ключей:** Чтобы полностью удалить ключ, определённый на уровне по умолчанию, в файле с более высоким приоритетом присвойте ему значение `null`.

## Встроенные объекты и функции

### Ключевые объекты

- **`.Values`** : Параметры из `values.yaml` или переданные через `--set`.
- **`.Release`** : Метаданные релиза (`.Release.Name`, `.Release.Namespace`, `.Release.IsUpgrade`).
- **`.Chart`** : Данные из `Chart.yaml` (`.Chart.Name`, `.Chart.Version`).
- **`.Capabilities`** : Возможности кластера (`.Capabilities.KubeVersion`, `.Capabilities.APIVersions.Has`).
- **`.Files`** : Доступ к не-шаблонным файлам в чарте (например, конфиги или сертификаты).
- **`.Template`** : Информация о текущем обрабатываемом файле шаблона (`.Template.Name`, `.Template.BasePath`).
- **`.Subcharts`** : Доступ к значениям и данным вложенных чартов (зависимостей).

### Важные функции Helm

1.  **`include`** : Вставляет именованный шаблон. В отличие от стандартной директивы `template`, `include` возвращает строку, что позволяет передавать её в пайплайны (например, `| nindent 4`).
2.  **`required`** : Помечает параметр как обязательный. Если значение пустое, Helm прервет установку с описанием ошибки.
3.  **`tpl`** : Рендерит строку как шаблон. Позволяет пользователям использовать объекты Helm внутри значений в `values.yaml`.
4.  **`lookup`** : Позволяет запрашивать существующие ресурсы из кластера (не работает в режиме `helm template` и `--dry-run`).

## Практические сценарии

### Комплексный пример: ConfigMap и Deployment

Этот пример демонстрирует объединение функций, объектов и логики.

**templates/configmap.yaml:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "mychart.fullname" . }}-config
data:
  # Динамический рендер внешнего файла
  {{- range $path, $_ := .Files.Glob "configs/**.conf" }}
  {{ base $path }}: |-
    {{ $.Files.Get $path | nindent 4 }}
  {{- end }}
  # Использование tpl для значений из values.yaml
  custom_config: |-
    {{ tpl .Values.customConfig . | nindent 4 }}
```

**templates/deployment.yaml:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "mychart.fullname" . }}
spec:
  replicas: {{ .Values.replicaCount | default 1 }}
  template:
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ required "Image repository is required" .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          {{- with .Values.resources }}
          resources:
            {{- toYaml . | nindent 12 }}
          {{- end }}
          env:
            {{- range $name, $value := .Values.env }}
            - name: {{ $name }}
              value: {{ $value | quote }}
            {{- end }}
```

### Работа с YAML-блоками (toYaml и nindent)

Паттерн для вставки сложных структур данных (например, `affinity`, `tolerations`):
```yaml
{{- with .Values.affinity }}
affinity:
  {{- toYaml . | nindent 2 }}
{{- end }}
```

### Валидация через fail

Прерывание процесса, если конфигурация небезопасна или некорректна:
```yaml
{{- if and .Values.ingress.enabled (not .Values.ingress.tls) }}
  {{- if .Values.enforceTls }}
    {{- fail "TLS must be enabled if ingress is enabled and enforceTls is true" }}
  {{- end }}
{{- end }}
```

### Динамическая генерация имён ресурсов

Ограничение Kubernetes на длину имён (DNS-1123 label, макс. 63 символа) требует аккуратной работы с комбинацией `namespace-release-chart-name`. Паттерн `trunc 63 | trimSuffix "-"` используется в хелперах для гарантии соответствия:

```yaml
metadata:
  name: {{ include "mychart.fullname" . | trunc 63 | trimSuffix "-" }}
```

### Checksum-аннотации и Rolling Update

Используйте `sha256sum` для генерации аннотаций, которые триггерят Rolling Update при изменении ConfigMap или Secret:

```yaml
metadata:
  annotations:
    checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}
```

### Шаблонизация для air-graded сред

В изолированных сетях (on-premise, банк, госсектор) отсутствует доступ к API-серверу во время `helm template`. Это влияет на:
- `.Capabilities.APIVersions.Has` — возвращает дефолтные значения, а не реальные возможности кластера.
- `lookup` — всегда возвращает `nil`.

**Решение:** Используйте флаги `--kube-version` и `--api-versions` для эмуляции целевой среды, а для `lookup` реализуйте fallback-логику:

```yaml
{{- $secret := (lookup "v1" "Secret" .Release.Namespace "my-secret") -}}
{{- if $secret }}
password: {{ index $secret.data "password" }}
{{- else }}
password: {{ "default-pass" | b64enc }}
{{- end }}
```

## Дополнительная информация

### Отладка и валидация

1.  **`helm template`** : Рендерит чарт локально. Помогает проверить структуру YAML и подстановку значений.
2.  **`helm install --dry-run --debug`** : Имитирует установку в кластере. Позволяет увидеть ошибки, связанные с API Kubernetes (например, неверные типы ресурсов).
3.  **JSON Schema (`values.schema.json`)** : Позволяет задать строгую типизацию для `values.yaml`. Если пользователь передаст строку вместо числа, Helm выдаст ошибку до начала рендеринга шаблонов.
4.  **`helm lint --strict`** : Проверяет синтаксис шаблонов и типы значений. В сочетании с `values.schema.json` блокирует установку при невалидных типах.
5.  **`kubeconform`** : Внешний валидатор YAML-манифестов по JSON-схемам Kubernetes API. Используется в CI/CD после `helm template` для проверки корректности ресурсов без доступа к кластеру.

### Валидационная pipeline (CI/CD)

Для SRE и DevOps-инженеров обязательный минимум проверок перед деплоем:

```bash
# 1. Статический анализ: синтаксис, структура, типы
helm lint ./my-chart --strict

# 2. Локальный рендеринг: визуальный аудит YAML
helm template my-release ./my-chart -f values.yaml > rendered.yaml

# 3. Валидация манифестов: проверка по JSON-схемам K8s API
helm template my-release ./my-chart -f values.yaml | kubeconform --strict

# 4. Сухой запуск: валидация через API-сервер (проверка версий API, RBAC)
helm install my-release ./my-chart -f values.yaml --dry-run --debug
```

### Лучшие практики

*   **Используйте `nindent`** : Вместо `indent` всегда предпочитайте `nindent <число>`, так как она автоматически добавляет новую строку, что упрощает управление пробелами.
*   **Всегда кавычьте строки** : Используйте `| quote` для всех строковых значений, приходящих извне, чтобы избежать проблем с именами вроде `true` или `12345`.
*   **Проверка вложенности** : Если вы обращаетесь к `.Values.a.b.c`, сначала проверьте `if .Values.a`, чтобы избежать ошибки `nil pointer evaluating`.
*   **Используйте `must` для критичных параметров** : Для необъявляемых через `required` критических данных используйте `must`, чтобы получить детализированную ошибку.
*   **deepCopy перед merge** : Функции `merge` и `mergeOverwrite` мутируют первый аргумент. Всегда копируйте `.Values` перед слиянием.
*   **Объединяйте логику в `_helpers.tpl`** : Если фрагмент шаблона используется более двух раз или сложен для чтения — выносите его в именованный шаблон.
*   **Глобальный контекст в циклах** : Всегда используйте `$.Release`, `$.Chart`, `$.Values` внутри `range` и `with`, чтобы избежать потери scope.

### Ограничения

*   **Оффлайн-рендеринг (`helm template`)** : Helm не подключается к кластеру и использует дефолтные значения `.Capabilities`. Для эмуляции целевой среды используйте `--kube-version` и `--api-versions`.
*   **Функция `lookup`** : Работает только при установке чарта в кластер. В `helm template` и `--dry-run` всегда возвращает `nil`.
*   **Функция `tpl`** : Поддерживает рекурсию с ограничениями. Слишком глубокая вложенность (более 10 уровней) приводит к ошибке `recursive template parsing aborted`. Никогда не передавайте в `tpl` непроверенные пользовательские данные.
*   **Размер `.Files`** : Максимальный размер файла — 1 МБ (ограничение etcd/Kubernetes на размер ConfigMap и Secret).
*   **Длина имён релизов** : 53 символа (DNS-1123). Длинные комбинации `namespace-chart-name` требуют `nameOverride` или `fullnameOverride`.
*   **Порядок ключей в `range`** : Итерация по словарю (`map`) через `range` не гарантирует порядок ключей. Если порядок критичен, используйте список (`list`) в `values.yaml`.
