# Хуки и тестирование в Helm

Хуки позволяют вмешиваться в жизненный цикл релиза Helm для выполнения вспомогательных задач (миграции, бэкапы, уведомления), а механизм тестирования обеспечивает автоматизированную проверку работоспособности развёрнутого приложения.

---

## Определения

| Термин | Описание |
|--------|----------|
| **Hook (Хук)** | Ресурс Kubernetes, помеченный аннотацией `helm.sh/hook`, который запускается Helm на определенных этапах жизненного цикла релиза |
| **Test (Тест)** | Специализированный хук с аннотацией `helm.sh/hook: test`, предназначенный для проверки состояния приложения после установки/обновления |
| **Hook Weight (Вес)** | Параметр `helm.sh/hook-weight`, определяющий порядок выполнения нескольких хуков на одном этапе (по возрастанию) |
| **Delete Policy (Политика удаления)** | Аннотация `helm.sh/hook-delete-policy`, управляющая моментом удаления ресурсов хука из кластера |
| **Resource Policy (Политика ресурсов)** | Аннотация `helm.sh/resource-policy: keep`, указывающая Helm не удалять ресурс при удалении релиза |

## Базовые концепции

### Точки входа (Lifecycle Events)

Helm предоставляет возможность запускать хуки на следующих этапах:

| Событие | Описание |
|---------|----------|
| `pre-install` | Выполняется после рендеринга шаблонов, но до создания каких-либо ресурсов в кластере |
| `post-install` | Выполняется после того, как все ресурсы релиза были созданы |
| `pre-delete` | Выполняется перед удалением любых ресурсов из релиза |
| `post-delete` | Выполняется после завершения удаления всех ресурсов релиза |
| `pre-upgrade` | Выполняется перед обновлением ресурсов существующего релиза |
| `post-upgrade` | Выполняется после успешного завершения обновления всех ресурсов |
| `pre-rollback` | Выполняется перед началом процесса отката на предыдущую ревизию |
| `post-rollback` | Выполняется после завершения процесса отката |

### Управление порядком и очисткой

#### Веса (Hook Weight)
Если на одном этапе (например, `pre-install`) определено несколько хуков, Helm запускает их в порядке возрастания веса, указанного в аннотации `helm.sh/hook-weight` (тип: строка, значение: целое число). Если веса равны, ресурсы сортируются по имени.

#### Политики удаления (Hook Delete Policy)
По умолчанию Helm удаляет созданный хук только в случае его замены новым хуком на том же этапе. Аннотация `helm.sh/hook-delete-policy` позволяет изменить это поведение:
- `before-hook-creation`: (по умолчанию) удаление старого ресурса перед запуском нового.
- `hook-succeeded`: удаление ресурса сразу после успешного завершения работы (Exit Code 0).
- `hook-failed`: удаление ресурса только в случае ошибки выполнения.

### Механизм тестирования (Helm Test)

Тесты — это поды (Pod) или задания (Job), расположенные в директории `templates/tests/`. Они не устанавливаются вместе с релизом обычным способом, а запускаются только по требованию командой `helm test <release_name>`.

- Тест считается пройденным, если контейнер завершился с кодом 0.
- Флаг `--cleanup` позволяет автоматически удалять ресурсы тестов после их завершения.

## Практические сценарии

### Миграция базы данных (pre-upgrade)

Использование `Job` для выполнения миграций перед обновлением приложения. Это гарантирует, что схема данных обновится до того, как новые поды приложения начнут работу.

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: "{{ .Release.Name }}-db-migration"
  labels:
    {{- include "mychart.labels" . | nindent 4 }}
  annotations:
    "helm.sh/hook": pre-upgrade
    "helm.sh/hook-weight": "10"
    "helm.sh/hook-delete-policy": hook-succeeded
spec:
  template:
    spec:
      containers:
        - name: migrate
          image: my-app:{{ .Values.image.tag }}
          command: ["/app/bin/migrate", "up"]
          envFrom:
            - configMapRef:
                name: {{ include "mychart.fullname" . }}-config
      restartPolicy: Never
```

### Сложный тест работоспособности

Проверка не только доступности порта, но и корректности ответа API.

**`templates/tests/test-api-health.yaml`:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ .Release.Name }}-api-health"
  annotations:
    "helm.sh/hook": test
spec:
  containers:
    - name: check-health
      image: curlimages/curl
      command: ['curl']
      args: ['-f', 'http://{{ include "mychart.fullname" . }}:{{ .Values.service.port }}/healthz']
  restartPolicy: Never
```

### Сохранение ресурса при удалении релиза

Полезно для баз данных или логов, которые нельзя удалять вместе с приложением.

```yaml
kind: PersistentVolumeClaim
metadata:
  name: {{ .Release.Name }}-data
  annotations:
    "helm.sh/resource-policy": keep
```

## Дополнительная информация

### Важные нюансы
- **Тайм-ауты:** Если хук (например, `Job`) не завершается в течение времени, указанного в `--timeout`, выполнение всей команды Helm прерывается с ошибкой.
- **CRD Hooks:** В Helm 2 существовал хук `crd-install`. В Helm 3 он **устарел**. CRD теперь должны располагаться в директории `crds/` в корне чарта.
