# Хуки и тестирование в Helm

## Определения

**Хуки (Hooks)** — это ресурсы Kubernetes с аннотацией `helm.sh/hook`, которые позволяют выполнять действия на определенных этапах жизненного цикла релиза. Они используются для задач, не являющихся частью основного приложения, например, для миграций баз данных, резервного копирования или выполнения тестов.

**Тесты (Tests)** — это специальный вид хуков, предназначенный для проверки корректности развертывания релиза. Они запускаются по команде `helm test` и не являются частью основного развертывания.

## Основные концепции

### Жизненный цикл хуков

Ресурс становится хуком, если в его метаданные добавлена аннотация `helm.sh/hook`.

**Доступные хуки:**

* `pre-install`: Перед загрузкой ресурсов релиза.
* `post-install`: После установки всех ресурсов релиза.
* `pre-delete`: Перед удалением ресурсов релиза.
* `post-delete`: После удаления всех ресурсов релиза.
* `pre-upgrade`: Перед обновлением релиза.
* `post-upgrade`: После обновления релиза.
* `pre-rollback`: Перед откатом релиза.
* `post-rollback`: После отката релиза.

### Управление хуками

* **Вес (`helm.sh/hook-weight`):** Упорядочивает выполнение нескольких хуков на одном этапе. Хуки выполняются в порядке возрастания веса (отрицательные значения разрешены).
* **Политика удаления (`helm.sh/hook-delete-policy`):** Определяет, когда удалять ресурс хука, так как они не удаляются вместе с релизом.
  * `before-hook-creation`: Удаляет предыдущий хук перед запуском нового (поведение по умолчанию).
  * `hook-succeeded`: Удаляет хук после его успешного завершения.
  * `hook-failed`: Удаляет хук, если он завершился с ошибкой.

### Механизм тестирования

1. **Расположение:** Тестовые манифесты (обычно `Pod` или `Job`) размещаются в директории `templates/tests/`.
2. **Аннотация:** Ресурсы помечаются аннотацией `helm.sh/hook: test`.
3. **Запуск:** Тесты выполняются командой `helm test <release_name>`.
4. **Результат:** Тест считается успешным, если под-исполнитель завершается с кодом `0`.

## Практические сценарии

### Пример: Тест соединения с сервисом

Этот `Pod` проверяет, что сервис `my-service` доступен внутри кластера.

**`templates/tests/test-connection.yaml`**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ .Release.Name }}-connection-test"
  annotations:
    "helm.sh/hook": test
spec:
  containers:
    - name: wget
      image: busybox
      command: ['wget']
      args: ['{{ .Release.Name }}-my-service:{{ .Values.service.port }}']
  restartPolicy: Never
```

### Пример: Хук для выполнения задачи после установки

Этот `Job` запускается после успешной установки релиза, выполняет команду и удаляется в случае успеха.

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: "{{ .Release.Name }}-post-install-job"
  annotations:
    "helm.sh/hook": post-install
    "helm.sh/hook-weight": "-5"
    "helm.sh/hook-delete-policy": hook-succeeded
spec:
  template:
    spec:
      containers:
        - name: post-install-container
          image: alpine:3.3
          command: ["/bin/sleep", "{{ default "10" .Values.sleepyTime }}"]
      restartPolicy: Never
  backoffLimit: 4
```

## Дополнительная информация

Хуки и тесты являются важной частью лучших практик Helm, так как они позволяют автоматизировать проверку и управление сложными развертываниями.
