# Паттерны и устранение неисправностей Helm

## Определения

**Паттерны Helm** — это проверенные архитектурные и конфигурационные решения, обеспечивающие масштабируемость, безопасность и простоту сопровождения сложных чартов.

**Устранение неисправностей (Troubleshooting)** — процесс диагностики и исправления ошибок на этапах рендеринга шаблонов, линтинга, а также восстановления работоспособности релизов при сбоях в кластере Kubernetes.

---

## Основные концепции

### Продвинутые паттерны проектирования

1.  **Библиотечные чарты (Library Charts)**: Централизация общих хелперов и именованных шаблонов. Позволяет избежать дублирования логики формирования меток, селекторов и политик безопасности в сотнях микросервисов.
2.  **Зонтичные чарты (Umbrella Charts)**: Агрегация множества независимых чартов в единый стек (например, стек логирования ELK). Позволяет управлять жизненным циклом связанных компонентов как единым целым.
3.  **Идемпотентные миграции**: Использование Helm Jobs в связке с хуками (`pre-install`, `pre-upgrade`) для выполнения миграций баз данных. Паттерн требует строгой идемпотентности кода миграции, так как Job может быть запущен повторно.
4.  **Управление ресурсами через SSA (Helm v4)**: Переход к модели Server-Side Apply позволяет Helm делить владение ресурсом с другими контроллерами (например, Истио-инъекторами), предотвращая конфликты "пинг-понга" конфигураций.

### Антипаттерны (Чего следует избегать)

-   **Использование `latest` тегов**: Приводит к невозможности детерминированного отката (`helm rollback`), так как образ контейнера может измениться без смены версии чарта.
-   **Злоупотребление функцией `tpl`**: Динамический рендеринг строк из `values.yaml` через `tpl` затрудняет статический анализ и поиск ошибок в шаблонах.
-   **Хранение секретов в `values.yaml`**: Даже если репозиторий приватный, это нарушает принципы безопасности. Используйте `helm-secrets` или External Secrets Operator.
-   **Игнорирование `.helmignore`**: Включение в пакет чарта лишних файлов (например, директории `.git` или `node_modules`) увеличивает размер чарта и может привести к превышению лимита размера Secret релиза.

## Практические сценарии

### 1. Проблема лимита размера релиза (Secret size limit)

**Проблема:** При хранении большой истории ревизий или использовании очень тяжелых чартов, Secret, в котором Helm хранит данные релиза, может превысить лимит Kubernetes в 1MB. Это приводит к ошибке: `etcdserver: request is too large`.

**Решение:**
1.  **Ограничение истории**: Всегда используйте флаг `--history-max`.
    ```bash
    helm upgrade --install my-app ./chart --history-max 5
    ```
2.  **Оптимизация состава**: Проверьте `.helmignore`, уберите тяжелые README, картинки и статические файлы, которые не нужны для рендеринга шаблонов.
3.  **Сжатие**: Настройте уровень сжатия в конфигурации Helm (если используется SQL-бэкенд для хранения).

### 2. Восстановление "зависшего" релиза (`pending-install`)

**Проблема:** Если процесс установки был прерван, релиз может остаться в статусе `pending-install` или `pending-upgrade`. Повторные попытки будут выдавать ошибку: `another operation (install/upgrade/rollback) is in progress`.

**Решение:**
1.  **Принудительный откат/удаление**: В некоторых случаях помогает `helm rollback` к последней успешной версии.
2.  **Ручная очистка**: Если Helm заблокирован, необходимо вручную удалить Secret последней (неудачной) ревизии:
    ```bash
    kubectl get secret -n <namespace> -l owner=helm,name=<release-name>
    # Найдите секрет с типом sh.helm.release.v1.<release-name>.v<last-revision>
    kubectl delete secret <secret-name> -n <namespace>
    ```
    После удаления "зависшего" секрета Helm позволит запустить новую операцию.

### 3. Отладка пробельных символов (Whitespace Hell)

**Проблема:** Некорректные отступы в YAML после рендеринга Go-шаблонов.

**Решение:**
1.  **Управляющие символы `{{-` и `-}}`**: Используйте дефис для удаления пробелов и символов переноса строки слева или справа от тега.
2.  **Функция `nindent`**: Всегда предпочитайте `nindent` функции `indent`, так как `nindent` гарантированно добавляет символ переноса строки перед отступом.
    ```yaml
    spec:
      {{- toYaml .Values.resources | nindent 6 }}
    ```
3.  **Визуальная проверка**: Используйте `helm template` для проверки итоговой структуры YAML перед деплоем.

### 4. Конфликты владения полями в Helm v4

**Проблема:** При переходе на v4 SSA выдает конфликты, если поля уже управляются другими инструментами.

**Решение:**
1.  **Проверка владельца**: Используйте `kubectl get <resource> -o yaml` для анализа секции `managedFields`.
2.  **Захват управления**:
    ```bash
    helm upgrade --install my-app ./chart --force-conflicts
    ```
