# Обзор Reloader

## Определения

**Reloader** — контроллер Kubernetes (K8s) от компании Stakater, предназначенный для автоматизации процесса обновления рабочих нагрузок (workloads) при изменении связанных с ними конфигурационных данных.

**Основные задачи контроллера:**
- Отслеживание изменений в объектах `ConfigMap` и `Secret`.
- Автоматическое инициирование плавного обновления (Rolling Upgrade) для `Deployment`, `StatefulSet`, `DaemonSet`, `Argo Rollout` и `DeploymentConfig`.
- Решение проблемы "зависших" конфигураций, когда изменение `ConfigMap` не подхватывается приложением без перезапуска пода (Pod), особенно при использовании переменных окружения (Environment Variables) или `subPath`.

**Текущее состояние (июль 2026):**
- **Версия приложения:** `v1.4.19`
- **Версия Helm-чарта:** `v2.2.14`
- **Лицензирование:** Доступны версии Open Source Software (OSS) и Enterprise (с поддержкой подписанных образов и SBOM).

**Связанные файлы:** [Установка и настройка](./reloader_installation.md) · [Практические сценарии](./reloader_usage_scenarios.md) · [Мониторинг и лучшие практики](./reloader_monitoring_and_best_practices.md)

## Основные концепции

### Принцип работы

```text
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  ConfigMap /    │ ──> │    Reloader      │ ──> │  Rolling Upgrade│
│    Secret       │     │   (watch API)    │     │   подов (Pods)  │
│   (изменение)   │     │                  │     │                 │
└─────────────────┘     └──────────────────┘     └─────────────────┘
```

1. **Отслеживание (Watch):** Reloader подписывается на события Kubernetes API Server для мониторинга изменений ресурсов.
2. **Анализ зависимостей:** При обнаружении изменения контроллер сканирует аннотации рабочих нагрузок и находит те, которые ссылаются на изменённый ресурс.
3. **Обновление:** В зависимости от выбранной стратегии, Reloader модифицирует шаблон пода (`PodTemplateSpec`), что заставляет Kubernetes инициировать стандартный процесс Rolling Update.

### Способы обнаружения ресурсов

- **Автоматический (`auto`):** Reloader сканирует спецификацию пода и автоматически находит все используемые `ConfigMap` и `Secret` (через `env`, `envFrom`, `volumes`).
- **Явный (Explicit):** В аннотациях рабочей нагрузки указывается конкретный список ресурсов для отслеживания. Рекомендуется для минимизации лишних перезапусков.
- **Поиск по совпадению (Match):** Синхронизация происходит только если аннотация в `ConfigMap`/`Secret` совпадает с аннотацией в рабочей нагрузке.

### Управляющие аннотации

| Аннотация | Значение | Описание |
| :--- | :--- | :--- |
| `reloader.stakater.com/auto` | `"true"` | Включает автоматическое отслеживание всех зависимостей. |
| `configmap.reloader.stakater.com/reload` | `"name1,name2"` | Отслеживать только указанные ConfigMap. |
| `secret.reloader.stakater.com/reload` | `"name1,name2"` | Отслеживать только указанные Secret. |
| `reloader.stakater.com/ignore` | `"true"` | Игнорировать данную рабочую нагрузку. |

### Стратегии обновления

| Стратегия | Механизм | Применение |
| :--- | :--- | :--- |
| **`env-vars`** (Default) | Добавляет переменную `STAKATER_RELOADER_...` с хешем данных. | Универсальный метод, работает везде. |
| **`annotations`** | Добавляет аннотацию `reloader.stakater.com/last-reloaded-from`. | **Рекомендовано для GitOps (ArgoCD)**, минимизирует diff манифестов. |
| **`restart`** | Выполняет `rollout restart` через API. | Идеально для Argo Rollouts, предотвращает состояние OutOfSync. |

## Новые возможности v1.4+ (2026)

### Интеграция с Secrets Store CSI Driver

Reloader v1.4+ полноценно поддерживает отслеживание объектов `SecretProviderClass`.
- При включении `--enable-csi-integration=true` контроллер следит за ротацией секретов во внешних хранилищах (HashiCorp Vault, AWS Secrets Manager, Azure Key Vault).
- Как только CSI-драйвер обновляет локальный объект в кластере, Reloader инициирует перезагрузку приложений.

### Уведомления и алертинг (Webhooks)

В версии 2026 года добавлена нативная поддержка отправки уведомлений о событиях перезагрузки:
- **Поддерживаемые каналы:** Slack, Microsoft Teams, Google Chat.
- **Данные в алерте:** Имя ресурса, пространство имён (Namespace), время и результат операции.

### Высокая доступность (HA) и Синхронизация

- **Флаг `--sync-after-restart`**: Позволяет новому лидеру (после Leader Election) провести полную сверку состояния кластера, чтобы не пропустить изменения, произошедшие во время смены лидера.
- **Поддержка User Namespaces**: Возможность запуска контроллера в изолированных пространствах имён пользователей для повышения безопасности (Kernel isolation).

## Практические сценарии

### Сценарий 1: Выбор инструмента для обновления конфигурации

| Характеристика | Reloader | Helm Checksum | Kustomize Hash |
| :--- | :--- | :--- | :--- |
| **Тип** | Динамический (Controller) | Статический (Template) | Статический (Build) |
| **Trigger** | Изменение ресурса в K8s API | `helm upgrade` | `kubectl apply` |
| **GitOps Friendly** | Да (с `annotations` strategy) | Да | Да |
| **Сложность** | Требует установки контроллера | Не требует дополнений | Не требует дополнений |

### Сценарий 2: Оптимизация для больших кластеров

При наличии более 5000 секретов в кластере рекомендуется ограничивать область видимости Reloader:

```bash
# Запуск с ограничением по пространствам имён
reloader --namespaces-to-select=prod,staging --namespaces-to-ignore=kube-system
# → result: Reloader будет обрабатывать только prod и staging
```

## Дополнительная информация

### Ограничения

- **subPath**: При монтировании файлов через `subPath` изменения не синхронизируются внутри контейнера (ограничение ядра Linux). Перезагрузка пода через Reloader — единственный надежный способ обновить конфиг в этом случае.
- **RBAC**: Контроллеру необходимы права на `update` и `patch` для всех типов отслеживаемых ресурсов.

### Enterprise vs Open Source (OSS)

В 2026 году Stakater предлагает расширенную версию для корпоративных пользователей:
- **Signed Images:** Все образы подписаны через Cosign для защиты цепочки поставок (Supply Chain Security).
- **SBOM (Software Bill of Materials):** Предоставляется детальный состав пакетов для комплаенса.
- **FIPS Compliance:** Поддержка стандартов безопасности для государственных и банковских систем.
