## Kubeconform: быстрая валидация на основе схем

**`kubeconform`** — это высокопроизводительный валидатор, который проверяет ваши YAML-файлы на соответствие официальным схемам Kubernetes API. Это обязательный инструмент для любого CI/CD пайплайна, работающего с Kubernetes.

*   **Высокая производительность:** Работает значительно быстрее аналогов (например, `kubeval`) за счет параллельной обработки файлов и кэширования схем в памяти.
*   **Интеграция в CI/CD:** Легко встраивается в пайплайны для автоматической проверки манифестов перед развертыванием. Возвращает ненулевой код выхода при обнаружении ошибок.
*   **Поддержка CRD:** Может валидировать Custom Resources, если указать ему путь к их OpenAPI схемам.
*   **Офлайн-режим:** Может работать без доступа к интернету, если предварительно скачать схемы.
*   **Гибкость:** Позволяет валидировать файлы из локальной директории, `stdin` или даже из Helm-чартов.

Установить `kubeconform` можно через популярные пакетные менеджеры:

*   **Go:**
    ```bash
    go install github.com/yannh/kubeconform/cmd/kubeconform@latest
    ```

**Локальная валидация:**

Проверить один или несколько файлов:

```bash
kubeconform my-deployment.yaml another-file.yaml
```

Проверить все YAML-файлы в директории рекурсивно:

```bash
kubeconform -R .
```

Пример шага в `.gitlab-ci.yml`, который проверяет все манифесты в репозитории:

```yaml
validate-k8s-manifests:
  image: ghcr.io/yannh/kubeconform:v0.7.0 # Официальный образ kubeconform
  stage: test
  script:
    - echo "Validating Kubernetes manifests..."
    - kubeconform -summary -output tap 'manifests/**/*.yaml'
```

*   `-summary`: Показывает краткий отчет о проверенных файлах.
*   `-output tap`: Форматирует вывод в Test Anything Protocol, который хорошо парсится CI-системами.

**Валидация Helm-чарта:**

Вы можете передать отрендеренные шаблоны Helm-чарта напрямую в `kubeconform`:

```bash
helm template my-chart | kubeconform -
```

## Kor: обнаружение неиспользуемых ресурсов

**`kor`** — это инструмент на Go для обнаружения и удаления неиспользуемых ресурсов в кластере Kubernetes. Он помогает поддерживать чистоту и сокращать затраты, выявляя такие ресурсы, как старые ConfigMaps, Secrets, Services и другие, которые больше не связаны с какими-либо активными рабочими нагрузками.

*   **Широкий охват:** Поддерживает множество типов ресурсов Kubernetes.
*   **Интеграция с CI/CD:** Может использоваться в пайплайнах для регулярной очистки.
*   **Уведомления:** Интегрируется со Slack для отправки отчетов о неиспользуемых ресурсах.
*   **Безопасность:** Позволяет сначала просмотреть неиспользуемые ресурсы перед их удалением.

**Ссылка на проект:** [yonahd/kor](https://github.com/yonahd/kor)

**Установка:**

Установить `kor` можно через `go install`:

```bash
go install github.com/yonahd/kor/cmd/kor@latest
```

**Примеры использования:**

Вывести все неиспользуемые ресурсы в кластере (для текущего контекста kubeconfig):

```bash
kor --all
```

Вывести неиспользуемые ConfigMaps и Secrets:

```bash
kor configmap secret
```

Для удаления найденных ресурсов можно использовать флаг `--delete`:

```bash
kor --all --delete
```
