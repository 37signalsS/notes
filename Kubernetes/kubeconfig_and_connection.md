# Kubeconfig: Подключение к кластеру Kubernetes

Для подключения к кластеру Kubernetes и управления им с помощью `kubectl` используется специальный файл конфигурации — **`kubeconfig`**.

Этот YAML-файл содержит всю необходимую информацию для аутентификации и определения адреса API-сервера кластера.

### Получение Kubeconfig при использовании Kubespray (Bare Metal)

При развертывании кластера на bare-metal серверах с помощью **Kubespray**, процесс получения `kubeconfig` является частью работы самого Ansible-сценария.

1.  **Генерация на мастер-ноде:** Kubespray использует `kubeadm` для инициализации кластера. В процессе `kubeadm` создает на первой мастер-ноде файл `/etc/kubernetes/admin.conf`. Этот файл является `kubeconfig` с правами администратора кластера.

2.  **Копирование на узел управления:** Сценарий Kubespray автоматически копирует этот файл с мастер-ноды на тот узел, с которого вы запускали Ansible (ваш "bastion" или узел управления). 
    *   Kubespray сохраняет его в директорию вашего инвентаря, обычно по пути: `<inventory_dir>/artifacts/admin.conf`.
    *   Имя файла может быть также `admin.kubeconfig`.

3.  **Перенос на локальную машину:** Ваша задача — скопировать этот файл с узла управления Kubespray на вашу рабочую станцию, где вы будете использовать `kubectl`.

    ```bash
    # Пример копирования с узла, где запускался Kubespray, на вашу машину
    scp <user>@<kubespray-control-node-ip>:<путь-до-inventory>/artifacts/admin.conf ~/.kube/config
    ```

    После этого `kubectl` на вашей локальной машине будет автоматически использовать этот файл для доступа к вашему bare-metal кластеру.

### Структура файла Kubeconfig

Файл состоит из трех основных блоков:

1.  **`clusters` (Кластеры):**
    *   Описывает кластеры, к которым можно подключиться.
    *   Содержит `name`, адрес API-сервера (`server`) и сертификат центра сертификации (`certificate-authority-data`).

2.  **`users` (Пользователи):**
    *   Описывает пользователей и их креды для аутентификации (обычно клиентский сертификат и ключ).

3.  **`contexts` (Контексты):**
    *   **Связывает пользователя с кластером.** Контекст — это комбинация `cluster`, `user` и (опционально) `namespace` по умолчанию.
    *   Именно контексты позволяют легко переключаться между разными кластерами.

Файл также содержит поле `current-context`, которое указывает `kubectl`, какой контекст использовать по умолчанию.

### Другие способы получения

Хотя для вас наиболее актуален метод с Kubespray, для полноты картины существуют и другие способы:

*   **Облачные провайдеры (GKE, EKS, AKS):** Конфигурация генерируется автоматически с помощью CLI-утилит провайдера (`gcloud`, `aws`, `az`).
*   **Локальные кластеры (Minikube, Kind):** Инструменты автоматически создают и помещают `kubeconfig` в `~/.kube/config`.
