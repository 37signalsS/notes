# NetworkPolicy: Определения и концепции

## Определения

**NetworkPolicy** — ресурс Kubernetes (API-группа `networking.k8s.io`), предназначенный для декларативного управления сетевым доступом на уровнях L3 (сетевой) и L4 (транспортный) модели OSI. Позволяет ограничивать трафик между Pod (подами) и внешними сетевыми сущностями на основе селекторов и IP-диапазонов.

**Сетевая изоляция (Network Isolation)** — состояние, при котором сетевой стек пода переходит в режим «запрещено по умолчанию» (Default Deny) для входящего или исходящего трафика. В стандартной конфигурации Kubernetes поды не изолированы (Default Allow).

**AdminNetworkPolicy (ANP)** — расширение сетевой модели (API-группа `policy.networking.k8s.io`), позволяющее администраторам кластера задавать глобальные правила безопасности с более высоким приоритетом, чем у стандартных NetworkPolicy.

**CNI (Container Network Interface)** — интерфейс сетевого плагина, ответственный за фактическую реализацию правил фильтрации. Поддержка NetworkPolicy не является обязательной для CNI (например, Flannel не поддерживает их без дополнительных компонентов).

## Базовые Концепции

### Сетевая модель и принцип Default Deny

В Kubernetes по умолчанию действует «плоская» сеть: любое пространство имен (Namespace) и любой Pod могут общаться друг с другом. Изоляция активируется только при наличии политики:

1.  **Неизолированный под:** К поду не применяется ни одна политика. Весь трафик разрешен.
2.  **Изолированный под:** Под выбран селектором `spec.podSelector` хотя бы в одной политике. Теперь разрешен только тот трафик, который явно указан в правилах `ingress` или `egress` текущей или других применимых политик.

### Иерархическая модель безопасности (3-Tier Model)

Современный подход к сетевой безопасности в Kubernetes предполагает три уровня управления:

*   **Tier 1: AdminNetworkPolicy (ANP):** Кластерный уровень. Администратор задает жесткие запреты или обязательные разрешения (например, доступ к мониторингу). Имеет действия `Allow`, `Deny` и `Pass`.
*   **Tier 2: NetworkPolicy (NP):** Уровень пространства имен. Разработчики настраивают доступ для своих приложений.
*   **Tier 3: BaselineAdminNetworkPolicy (BANP):** Кластерный уровень «последней надежды». Задает поведение по умолчанию, если ни ANP, ни NP не сработали.

### Структура и протоколы

Стандартная политика поддерживает фильтрацию по следующим протоколам L4:
*   **TCP** (Transmission Control Protocol).
*   **UDP** (User Datagram Protocol).
*   **SCTP** (Stream Control Transmission Protocol) — статус Stable (GA) с версии 1.20.

**Основные поля манифеста:**
*   **`spec.podSelector`**: Определяет целевые поды (Target).
*   **`spec.policyTypes`**: Направления изоляции (`Ingress`, `Egress`). **Важно:** если направление не указано здесь, но соответствующие правила присутствуют в `spec`, поведение может зависеть от версии Kubernetes и CNI.
*   **`spec.ingress.from` / `spec.egress.to`**: Селекторы источников и назначений.

### Терминология: Target, Source, Destination

*   **Target (Цель):** Поды, к которым применяется политика (выбираются через `spec.podSelector`). Именно их сетевой стек будет изолирован.
*   **Source (Источник):** Сущности, которым разрешено инициировать соединение к Target (в правилах `ingress`).
*   **Destination (Назначение):** Сущности, к которым Target разрешено инициировать соединение (в правилах `egress`).

## Практические Сценарии

Основные шаблоны использования:
*   **Изоляция «Default Deny»:** Блокировка всего трафика для Namespace как база для построения Zero Trust сети.
*   **Разрешение системных служб:** Обеспечение доступа к CoreDNS для работы Service Discovery.
*   **Микросервисная сегментация:** Разрешение доступа только между зависимыми сервисами (например, Frontend → Backend).

*Детальные примеры манифестов: [NetworkPolicy: Практические сценарии](./practical_scenarios.md)*

## Дополнительные Сведения

### Ограничения стандартных политик
*   **L7 (Прикладной уровень):** Отсутствие поддержки фильтрации по HTTP-путям, методам или заголовкам.
*   **FQDN/DNS:** Невозможность создания правил на основе доменных имен (требуются расширения CNI).
*   **Локальный трафик:** Трафик внутри пода через `localhost` (между контейнерами) не фильтруется.
*   **Service-абстракции:** Политики применяются к IP-адресам подов, а не к виртуальным IP сервисов (ClusterIP).

### Расширенные возможности и альтернативы
*   **Cilium:** Фильтрация L7 (HTTP/gRPC) и FQDN на базе eBPF.
*   **Calico:** Глобальные сетевые политики и интеграция с внешними файрволами.
*   **Istio / Linkerd (Service Mesh):** mTLS, тонкая авторизация на уровне L7 и наблюдаемость.
*   **AdminNetworkPolicy API:** Официальный путь для реализации кластерных правил безопасности без дублирования политик в каждом Namespace.
