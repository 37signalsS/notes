# IPVS (IP Virtual Server) в Kubernetes

## Определения

**IPVS (IP Virtual Server)** — высокопроизводительный балансировщик нагрузки транспортного уровня (L4), реализованный в виде модуля ядра Linux. Является частью проекта LVS (Linux Virtual Server). В Kubernetes используется `kube-proxy` для обеспечения эффективной маршрутизации трафика сервисов.

**VIP (Virtual IP)** — виртуальный IP-адрес, назначаемый сервису (`ClusterIP`). IPVS перехватывает трафик, направленный на VIP, и пересылает его на реальные IP-адреса подов (backend).

## Основные концепции

### Балансировка нагрузки L4

IPVS работает на уровне TCP, UDP и SCTP. В отличие от `iptables`, который обрабатывает правила последовательно, IPVS использует хеш-таблицы, что обеспечивает константное время поиска правил $O(1)$ независимо от их количества.

### Алгоритмы балансировки

IPVS поддерживает множество алгоритмов распределения трафика:

| Алгоритм | Код | Описание |
| :--- | :--- | :--- |
| **Round Robin** | `rr` | Циклическое равномерное распределение. |
| **Weighted Round Robin** | `wrr` | Учитывает веса серверов (производительность). |
| **Least Connection** | `lc` | Направляет трафик на сервер с наименьшим числом активных соединений. |
| **Weighted Least Connection** | `wlc` | Учитывает веса и текущую загрузку. |
| **Source Hashing** | `sh` | Привязка клиента к серверу по хешу IP источника (Sticky Sessions). |
| **Destination Hashing** | `dh` | Распределение на основе хеша IP-адреса назначения. |

### Методы перенаправления (Forwarding Methods)

В контексте Kubernetes чаще всего используется режим **NAT**, но технология поддерживает и другие методы:

- **NAT (Network Address Translation):** IPVS подменяет адрес назначения на IP пода. Ответный трафик должен проходить через тот же узел.
- **DR (Direct Routing):** Балансировщик подменяет MAC-адрес. Ответ идёт напрямую клиенту (DSR — Direct Server Return). Требует нахождения всех узлов в одном L2-сегменте.
- **Tunneling (IP-IP):** Инкапсуляция пакетов в IP-туннели. Позволяет работать через маршрутизируемые сети.

### Сравнение с iptables

| Характеристика | IPVS | iptables |
| :--- | :--- | :--- |
| **Масштабируемость** | Высокая (хеш-таблицы) | Низкая (последовательный поиск) |
| **Количество сервисов** | До десятков тысяч | Рекомендуется до 1000 |
| **Балансировка** | Множество алгоритмов | Только случайный выбор |
| **Health Checking** | Поддерживается ядром | Внешняя (через `kube-proxy`) |

## Практические сценарии

### Настройка kube-proxy в режиме IPVS

Для работы IPVS необходимо убедиться, что соответствующие модули ядра загружены на каждом узле.

#### 1. Загрузка модулей ядра

```bash
cat <<EOF | sudo tee /etc/modules-load.d/ipvs.conf
ip_vs
ip_vs_rr
ip_vs_wrr
ip_vs_sh
nf_conntrack
EOF

sudo modprobe ip_vs
sudo modprobe ip_vs_rr
sudo modprobe ip_vs_wrr
sudo modprobe ip_vs_sh
```

#### 2. Конфигурация Kubernetes

В `KubeProxyConfiguration` установите режим `ipvs`:

```yaml
apiVersion: kubeproxy.config.k8s.io/v1alpha1
kind: KubeProxyConfiguration
mode: "ipvs"
ipvs:
  strictARP: true
```

> **Примечание:** `strictARP: true` критически важен при использовании MetalLB.

### Диагностика и мониторинг

Для анализа работы IPVS используется утилита `ipvsadm`.

| Задача | Команда |
| :--- | :--- |
| **Просмотр всех правил** | `sudo ipvsadm -Ln` |
| **Просмотр статистики** | `sudo ipvsadm -Ln --stats` |
| **Просмотр соединений** | `sudo ipvsadm -Lnc` |
| **Скорость пакетов/сек** | `sudo ipvsadm -Ln --rate` |

## Дополнительные сведения

### Важные ограничения

1. **Зависимость от модулей:** Если модули ядра не загружены, `kube-proxy` может автоматически переключиться обратно в режим `iptables`.
2. **Сложность отладки:** Правила `iptables` можно увидеть через `iptables-save`, а для IPVS требуется дополнительный инструмент (`ipvsadm`).
