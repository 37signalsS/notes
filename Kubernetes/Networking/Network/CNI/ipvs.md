# IPVS (IP Virtual Server) в Kubernetes

## Определения

**IPVS (IP Virtual Server)** — модуль ядра Linux, реализующий балансировку нагрузки на транспортном уровне (Layer 4) в рамках подсистемы Linux Virtual Server (LVS). Позволяет создавать высокопроизводительные отказоустойчивые сервисы путём распределения входящих запросов между backend-серверами.

**VIP (Virtual IP)** — виртуальный IP-адрес, на который приходит трафик сервиса и который транслируется IPVS в реальные IP-адреса backend-серверов.

## Основные концепции

### Балансировка нагрузки L4

IPVS работает на уровне TCP/UDP/SCTP, анализируя IP-адреса и порты:

- Перехватывает входящие соединения на VIP
- Перенаправляет трафик на backend-серверы согласно алгоритму балансировки
- Поддерживает таблицу сессий для отслеживания активных соединений

### Алгоритмы балансировки

| Алгоритм | Код | Описание |
|----------|-----|----------|
| **Round Robin** | `rr` | Равномерное распределение запросов по кругу |
| **Weighted Round Robin** | `wrr` | Round Robin с учётом весов серверов |
| **Least Connection** | `lc` | Отправка на сервер с наименьшим числом соединений |
| **Weighted Least Connection** | `wlc` | Least Connection с учётом весов |
| **Source Hashing** | `sh` | Привязка клиента к серверу по хешу IP источника (sticky sessions) |
| **Destination Hashing** | `dh` | Распределение по хешу IP адреса назначения |

### Методы перенаправления (Forwarding Methods)

| Метод | Описание | Требования |
|-------|----------|------------|
| **NAT** | IPVS модифицирует IP-адреса в пакетах | Стандартный режим, работает везде |
| **DR (Direct Routing)** | Backend отвечает клиенту напрямую, минуя IPVS | Требуется настройка loopback на backend |
| **IP-IP Tunneling** | Инкапсуляция пакетов в IP-IP туннели | Поддержка туннелей на backend |
| **Full NAT** | Двусторонний NAT | Backend в разных подсетях |

### Преимущества перед iptables

| Критерий | IPVS | iptables |
|----------|------|----------|
| **Время поиска правил** | O(1) (хеш-таблицы) | O(n) (последовательный перебор) |
| **Производительность** | Высокая при >1000 сервисов | Падает при большом числе правил |
| **Алгоритмы балансировки** | 8+ алгоритмов | Случайный выбор |
| **Session Affinity** | Встроенная поддержка | Требует дополнительных правил |
| **Health Checking** | Встроенная (в современных реализациях) | Через kube-proxy |

## Практические сценарии

### Использование IPVS в Kubernetes

`kube-proxy` в режиме `ipvs` использует IPVS для реализации абстракции `Service`.

#### Требования

- Загруженный модуль ядра `ip_vs` и зависимости (`ip_vs_rr`, `ip_vs_wrr`, `ip_vs_sh`, `ip_vs_lc`, etc.)
- Установленная утилита `ipvsadm` для диагностики

#### Проверка и загрузка модулей

```bash
# Проверка загруженных модулей
lsmod | grep ip_vs

# Загрузка модуля
modprobe ip_vs

# Загрузка модулей алгоритмов балансировки
modprobe ip_vs_rr
modprobe ip_vs_wrr
modprobe ip_vs_sh
modprobe ip_vs_lc
```

#### Диагностика IPVS в Kubernetes

```bash
# Просмотр правил балансировки
ipvsadm -Ln

# Просмотр правил с детализацией
ipvsadm -Ln --stats

# Проверка режима kube-proxy
kubectl -n kube-system get configmap kube-proxy -o yaml | grep mode
```

### Выбор режима kube-proxy

| Сценарий | Рекомендуемый режим |
|----------|---------------------|
| Кластер до 1000 сервисов | `iptables` |
| Крупный кластер (>1000 сервисов) | `ipvs` |
| Требуется session affinity | `ipvs` |
| Ограничения ядра (нет IPVS) | `iptables` |
