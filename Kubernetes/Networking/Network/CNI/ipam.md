# IPAM (IP Address Management) в CNI

## Определения

**IPAM (IP Address Management)** — компонент CNI-плагина, отвечающий за выделение, учёт и освобождение IP-адресов для подов в кластере Kubernetes.

**podCIDR** — диапазон IP-адресов, выделенный для подов в кластере. Делится на поддиапазоны (блоки) для каждого узла.

## Основные концепции

CNI-плагин отвечает не только за маршрутизацию, но и за управление IP-адресами. Существует два основных подхода к IPAM в Kubernetes.

### Стандартный механизм Kubernetes (`host-local` IPAM)

`kube-controller-manager` выделяет каждому узлу префикс (обычно `/24`) из общего `podCIDR` кластера и записывает его в спецификацию объекта `Node`. CNI-плагин на узле использует стандартный IPAM-плагин `host-local`.

**Принцип работы:**

- Плагин считывает выделенный `podCIDR` для своей ноды
- Управляет выдачей IP-адресов из этого диапазона
- Сохраняет информацию о занятых IP в локальных файлах на диске узла (обычно в `/var/lib/cni/networks/`)

**Преимущества:**

- Простота настройки и использования
- Самый распространённый механизм
- Не требует дополнительных компонентов

### IPAM, интегрированный в CNI (например, `calico-ipam`)

Альтернатива `host-local`. Для активации (в случае Calico) необходимо запустить `kube-controller-manager` с флагом `--allocate-node-cidrs=false`. В этом режиме Calico полностью берёт на себя управление IP-адресами.

#### Ресурс `IPPool` в Calico

`calico-ipam` управляет адресами через кастомный ресурс `IPPool`:

```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: default-ipv4-ippool
spec:
  cidr: 192.168.0.0/16
  blockSize: 26
  natOutgoing: true
  disabled: false
```

| Параметр | Описание |
|----------|----------|
| **`cidr`** | Общий пул адресов для подов, аналог `podCIDR` |
| **`blockSize`** | Размер блока адресов, выделяемого узлу. По умолчанию `26` (64 адреса). Позволяет гибко распределять адреса по сравнению с жёстким `/24` в Kubernetes |
| **`natOutgoing`** | При `true` для трафика из подов во внешнюю сеть применяется `MASQUERADE` (NAT) для скрытия внутренних IP-адресов |

**Диагностика:**

```bash
calicoctl ipam show
```

## Практические сценарии

### Настройка Dual-Stack (IPv4/IPv6)

Kubernetes и CNI-плагины (Calico, Cilium) поддерживают **dual-stack** режим, позволяя подам иметь одновременно IPv4 и IPv6 адреса.

#### Настройка Kubernetes

При инициализации кластера укажите два диапазона `pod-network-cidr`:

```bash
kubeadm init --pod-network-cidr=10.244.0.0/16,fd00:10:244::/48
```

Также необходимо указать `service-cluster-ip-range` для обоих семейств.

#### Настройка CNI

| IPAM-плагин | Настройка dual-stack |
|-------------|----------------------|
| **`host-local`** | Управляет двумя отдельными файлами состояний для каждого семейства адресов |
| **`calico-ipam`** | Требуется создать два ресурса `IPPool` (IPv4 и IPv6). Calico автоматически назначит поду по одному адресу из каждого пула |

**Пример `IPPool` для IPv6:**

```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: default-ipv6-ippool
spec:
  cidr: fd00:10:244::/48
  blockSize: 122
  natOutgoing: false
  disabled: false
```

> **Примечание:** NAT обычно не используется в IPv6, так как адресное пространство достаточно велико.
