# IPAM (IP Address Management) в CNI

## Определения

**IPAM (IP Address Management)** — компонент CNI-плагина, отвечающий за выделение, учёт и освобождение IP-адресов для подов в кластере Kubernetes.

**podCIDR** — диапазон IP-адресов, выделенный для подов во всём кластере (например, `10.244.0.0/16`).

**Node CIDR (nodeCIDR)** — поддиапазон (блок), выделенный конкретному узлу из общего `podCIDR` для распределения между запущенными на нём подами.

**blockSize** — размер блока адресов, выделяемого узлу. Позволяет гибко управлять плотностью подов на узлах (например, `/26` даёт 64 адреса на узел).

---

## Основные концепции

Управление IP-адресами может выполняться как стандартными средствами Kubernetes, так и расширенными механизмами CNI-плагинов.

### Стандартный механизм Kubernetes (`host-local` IPAM)

`kube-controller-manager` выделяет каждому узлу префикс (обычно `/24`) из общего `podCIDR` кластера и записывает его в спецификацию объекта `Node` (`spec.podCIDR`). CNI-плагин на узле использует стандартный плагин `host-local`.

**Принцип работы:**

- Плагин считывает выделенный `podCIDR` для своей ноды.
- Управляет выдачей IP-адресов из этого диапазона.
- Сохраняет информацию о занятых IP в локальных файлах на диске узла (обычно `/var/lib/cni/networks/`).

**Особенности:**

- **Плюсы:** Простота, отсутствие внешних зависимостей.
- **Минусы:** Фиксированный размер подсети на узел (обычно `/24`), сложность изменения размера пула «на лету».

### Интегрированный IPAM (например, `calico-ipam`)

В этом режиме CNI-плагин полностью берет на себя управление адресами, игнорируя `spec.podCIDR` объекта `Node`. Для активации (в Calico) требуется флаг `--allocate-node-cidrs=false` в `kube-controller-manager`.

#### Ресурс `IPPool` в Calico

Управление адресами осуществляется через кастомный ресурс `IPPool`, который позволяет гибко настраивать параметры сети:

```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: default-ipv4-ippool
spec:
  cidr: 192.168.0.0/16
  blockSize: 26
  natOutgoing: true
  disabled: false
```

| Параметр | Описание |
| :--- | :--- |
| **`cidr`** | Общий пул адресов для подов. |
| **`blockSize`** | Размер блока, выделяемого узлу (по умолчанию `26` — 64 адреса). |
| **`natOutgoing`** | Включает `MASQUERADE` для трафика из подов во внешнюю сеть. |
| **`nodeSelector`** | Позволяет назначать пулы адресов конкретным группам узлов (например, для разных зон). |

## Практические сценарии

### 1. Настройка Dual-Stack (IPv4/IPv6)

Kubernetes и современные CNI (Calico, Cilium) поддерживают одновременную работу IPv4 и IPv6.

**Настройка кластера:**
При инициализации через `kubeadm` указываются оба диапазона:

```bash
kubeadm init --pod-network-cidr=10.244.0.0/16,fd00:10:244::/48
```

**Настройка IPAM:**

- **host-local:** Работает прозрачно, создавая отдельные файлы состояний для каждого семейства.
- **calico-ipam:** Требует создания двух ресурсов `IPPool` (один для IPv4, другой для IPv6). Calico автоматически назначит поду адреса из обоих пулов.

### 2. Диагностика и мониторинг

Для проверки распределения адресов в Calico используются специализированные утилиты:

```bash
# Просмотр использования пулов и блоков
calicoctl ipam show

# Детальная информация по конкретному пулу
calicoctl get ippool -o wide
```

В режиме `host-local` проверку можно выполнить непосредственно на узле:

```bash
ls /var/lib/cni/networks/last-reserved-ip/
```
