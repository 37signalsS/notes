# Выбор CNI и внешние типы доступа в Kubernetes

## Определения

**IP Advertisement** — функция Calico для анонсирования ClusterIP сервисов через BGP внешним маршрутизаторам, позволяющая направлять трафик к сервисам без NodePort.

**Direct Service Return (DSR)** — оптимизация в режиме eBPF, при которой ответ от пода идёт напрямую клиенту, минуя ноду-получатель, с подменой source IP на ClusterIP сервиса.

**externalTrafficPolicy: Local** — настройка сервиса, при которой трафик обрабатывается только на узлах с запущенными подами, что сохраняет исходный IP клиента и исключает cross-node хоппинг.

## Основные концепции

### Выбор CNI-плагина

| Критерий | Flannel | Calico | Calico (eBPF) / Cilium |
| :--- | :--- | :--- | :--- |
| **Сложность настройки** | Простая | Средняя | Средняя/Высокая |
| **NetworkPolicy** | Нет | Да | Да (более эффективно) |
| **Производительность** | Средняя (overlay) | Высокая (BGP) | Очень высокая |
| **Замена kube-proxy** | Нет | Нет | Да |
| **Режим работы** | Overlay (VXLAN) | Overlay/BGP | eBPF/Direct Routing |

### Внешние типы доступа в Kubernetes

Доступ к сервисам кластера извне может быть организован несколькими способами:

| Метод | Описание | Применение |
|-------|----------|------------|
| **NodePort** | Открывает порт на каждой ноде кластера | Development, тестирование |
| **LoadBalancer** | Требует внешнего балансировщика облака/железа | Production в облаке |
| **Ingress** | L7-маршрутизация HTTP/HTTPS трафика | Production, мультитенант |
| **IP Advertisement (Calico)** | Анонсирование ClusterIP через BGP | Bare-metal, DC |

## Практические сценарии

### IP Advertisement через BGP (Calico-specific)

Calico предоставляет возможность **анонсирования сервисных IP-адресов** через BGP внешним маршрутизаторам.

**Стандартное поведение (без IP Advertisement):**

- ClusterIP (`10.2.0.0/16`) невидим для внешней сети
- Обращение к ClusterIP извне невозможно даже при наличии маршрута
- Пакеты отбрасываются, так как интерфейс не знает о внутренней сетке

**С IP Advertisement:**

- Calico анонсирует ClusterIP сервисов через BGP внешнему роутеру
- Внешний роутер направляет трафик напрямую на нужную ноду
- Трафик попадает на сервис без NodePort

**Преимущества:**

- Прямая маршрутизация к сервисам без NAT
- Балансировка на уровне BGP (ECMP)
- Эффективная доставка трафика

#### externalTrafficPolicy: Local + IP Advertisement

Комбинация функций даёт максимальную эффективность:

- Calico анонсирует сервис **только с тех нод, где есть поды**
- BGP-роутер распределяет трафик (ECMP) между активными нодами
- При падении пода/ноды анонс снимается, трафик перенаправляется
- **Отсутствие cross-node трафика:** пакет приходит на ноду и сразу на локальный под
- **Direct Service Return (DSR):** ответ от пода идёт напрямую клиенту через eBPF

> **Риск:** При неравномерном распределении подов по нодам трафик распределяется между нодами, а не между подами.

### Direct Service Return (DSR) через eBPF

Calico в режиме eBPF реализует оптимизацию **Direct Service Return**.

**Проблема классического режима:**

1. Трафик приходит на ноду 1, перенаправляется на под на ноде 2
2. Ответ от пода идёт обратно через ноду 2 с NAT
3. Два хопа, дополнительная задержка

**Решение eBPF DSR:**

1. Трафик приходит на ноду 1, через eBPF перенаправляется на под на ноде 2
2. Под отвечает **напрямую клиенту**, подменяя source IP на ClusterIP сервиса
3. Ответ идёт напрямую, минуя ноду-получатель

**Преимущества:**

- Снижение задержки (no extra hop)
- Уменьшение нагрузки на ноды
- Сохранение IP клиента без SNAT

**Требования:**

- Calico в режиме eBPF
- Ядро Linux 4.19+ с поддержкой eBPF

### Архитектура Load Balancer + Ingress Controller

Детальное описание архитектурных паттернов связки внешних балансировщиков (L4/L7, ALB, NLB) и Ingress-контроллеров перенесено в SSoT-файл: **[Обзор Ingress: Архитектурные паттерны связки LB и Ingress](../../Ingress/overview.md#архитектурные-паттерны-связка-lb-ingress-и-alb)**.

**Роль Calico в таких архитектурах:**

- Обеспечивает маршрутизацию между ingress-нодами и backend-нодами
- Реализует [NetworkPolicy](../NetworkPolicy/best_practices.md#1-начинайте-с-default-deny) для изоляции ingress от backend
- В режиме eBPF оптимизирует cross-node трафик
