# eBPF в Kubernetes: Замена kube-proxy

## Определения

**eBPF (Extended Berkeley Packet Filter)** — технология в ядре Linux, позволяющая запускать программы в изолированной среде внутри ядра без переключения контекста между пространством пользователя и ядра. Подробнее об общей технологии см. [eBPF в Linux](../../../../Linux/Core/kernel/ebpf.md).

**eBPF для сети Kubernetes** — использование eBPF-программ для реализации функций сетевого стека кластера: балансировки нагрузки (замена `kube-proxy`), фильтрации трафика (NetworkPolicy) и наблюдения за сетевыми событиями.

## Основные концепции

### Принцип работы eBPF в сети

В контексте Kubernetes eBPF позволяет "прикреплять" программы к хукам (точкам перехвата) в сетевом стеке ядра (например, `TC`, `XDP`). Это позволяет обрабатывать пакеты до того, как они попадут в стандартные подсистемы вроде `iptables` или `IPVS`.

### Преимущества и недостатки eBPF

| Категория | Преимущество | Описание |
|-----------|--------------|----------|
| **Производительность** | Высокая скорость | Обработка пакетов на уровне ядра без накладных расходов `iptables` O(n) |
| **Функциональность** | Замена `kube-proxy` | Полная реализация балансировки Service-to-Pod в ядре |
| **Безопасность** | Эффективные политики | `NetworkPolicy` реализуются через eBPF-карты, что быстрее `iptables` |
| **Видимость** | Глубокий мониторинг | Возможность отслеживать прохождение каждого пакета через хуки ядра |

| Категория | Недостаток | Описание |
|-----------|------------|----------|
| **Требования** | Ядро Linux | Требуется современное ядро (обычно 4.19+ или 5.4+ для полной поддержки) |
| **Сложность** | Отладка | Требует специальных инструментов (bpftool) и глубоких знаний ядра |
| **Совместимость** | Конфликты | Может конфликтовать с другими инструментами, использующими `iptables` |

## Практические сценарии

### Реализация через Cilium

**Cilium** — это CNI-плагин, изначально спроектированный для работы на базе eBPF. Он является наиболее зрелым решением для полной замены `kube-proxy`.

- **Режим замены kube-proxy:** Cilium может работать без `kube-proxy`, реализуя ClusterIP и NodePort через eBPF.
- **Масштабируемость:** Поддерживает десятки тысяч сервисов без деградации производительности.

### Настройка Calico в режиме eBPF

Calico позволяет переключить стандартный режим (iptables) на eBPF для повышения производительности.

#### Шаг 1: Подготовка кластера (без kube-proxy)

При использовании `kubeadm` рекомендуется инициализировать кластер без аддона `kube-proxy`:

```bash
sudo kubeadm init --skip-phases=addon/kube-proxy
```

#### Шаг 2: Включение режима eBPF в Calico

После установки Calico создайте или обновите ресурс `FelixConfiguration`:

```yaml
apiVersion: projectcalico.org/v3
kind: FelixConfiguration
metadata:
  name: default
spec:
  bpfEnabled: true
  bpfKubeProxyIptablesCleanupEnabled: true
```

#### Шаг 3: Проверка состояния

| Метод проверки | Команда | Ожидаемый результат |
|----------------|---------|---------------------|
| **Статус Felix** | `kubectl get pods -n kube-system -l k8s-app=calico-node` | Поды запущены и логи показывают `BPF enabled` |
| **Монтирование BPF** | `mount | grep bpf` | Наличие точки монтирования `/sys/fs/bpf` |
| **Просмотр карт NAT** | `kubectl exec -it -n kube-system <calico-node-pod> -- calico-node bpf nat dump` | Список правил трансляции адресов |

## Дополнительные сведения

### Direct Service Return (DSR)

В режиме eBPF поддерживается оптимизация **DSR**, при которой ответный трафик от пода идёт напрямую клиенту, минуя ноду-балансировщик. Это снижает задержки и нагрузку на сеть. Подробнее см. в [Внешние типы доступа](./selection_and_external_access.md#direct-service-return-dsr-через-ebpf).
