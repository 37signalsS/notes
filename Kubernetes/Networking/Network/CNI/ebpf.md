# Решения на базе eBPF: Замена kube-proxy

Современные CNI-плагины, такие как **Calico** и **Cilium**, могут использовать технологию **eBPF (Extended Berkeley Packet Filter)** для полной замены `kube-proxy`. Это позволяет достичь более высокой производительности и упростить сетевой стек.

## Что такое eBPF?

**eBPF** — это революционная технология в ядре Linux, которая позволяет запускать пользовательские программы в изолированной "песочнице" непосредственно в пространстве ядра (`kernel space`). Это устраняет необходимость в дорогостоящих переключениях контекста между ядром и пользовательским пространством (`user space`).

В контексте сети eBPF позволяет "прикреплять" эти программы к различным точкам (хукам) в сетевом стеке ядра, где они могут с высокой скоростью проверять, изменять или отбрасывать сетевые пакеты.

## Преимущества eBPF в Calico

- **Высокая производительность:** Обработка пакетов происходит на уровне ядра, что значительно снижает задержки и нагрузку на CPU по сравнению с `iptables` или `ipvs`.
- **Замена `kube-proxy`:** Calico в режиме eBPF полностью берет на себя функции `kube-proxy`, включая трансляцию адресов (DNAT) для сервисов.
- **Эффективные сетевые политики:** Правила `NetworkPolicy` также реализуются через eBPF, что работает быстрее, чем `iptables`.

## Недостатки eBPF

- **Сложность:** Отладка проблем с eBPF требует специальных знаний и инструментов.
- **Требования к ядру:** Требуется относительно свежая версия ядра Linux.
- **Золотое правило:** Если существующая сетевая подсистема справляется с нагрузкой, переход на eBPF может быть излишним усложнением.

## Установка Calico с eBPF (для нового кластера)

> **Внимание:** Приведенные ниже команды и конфигурации являются примером. Всегда сверяйтесь с официальной документацией Calico для получения актуальной версии манифестов и инструкций, соответствующих вашей версии Kubernetes.

Миграция существующего кластера на eBPF является сложной и рискованной процедурой. Рекомендуемый подход — установка нового кластера сразу в режиме eBPF.

### Шаг 1: Инициализация кластера без `kube-proxy`

При инициализации master-ноды с помощью `kubeadm`, необходимо пропустить установку `kube-proxy`.

```bash
sudo kubeadm init --skip-phases=addon/kube-proxy
```

### Шаг 2: Подготовка манифеста Calico

1. Скачайте официальный манифест `calico.yaml` с сайта проекта Calico.
2. **Настройте `podCIDR`**: Убедитесь, что `CALICO_IPV4POOL_CIDR` в манифесте соответствует `pod-network-cidr`, указанному при инициализации кластера.
3. **Включите VXLAN**: Для максимальной совместимости и лучшей производительности с eBPF рекомендуется использовать режим VXLAN.

    ```yaml
    # В ConfigMap 'calico-config'
    - name: CALICO_IPV4POOL_IPIP
      value: "Never"
    - name: CALICO_IPV4POOL_VXLAN
      value: "Always"
    ```

### Шаг 3: Развертывание Calico

Примените модифицированный манифест `calico.yaml`.

```bash
kubectl apply -f calico.yaml
```

### Шаг 4: Включение режима eBPF

Создайте ресурс `FelixConfiguration`, чтобы активировать eBPF.

```yaml
# felix-config.yaml
apiVersion: projectcalico.org/v3
kind: FelixConfiguration
metadata:
  name: default
spec:
  bpfEnabled: true
```

Примените его с помощью утилиты `calicoctl` или `kubectl`.

```bash
# Убедитесь, что у вас настроен calicoctl
calicoctl apply -f felix-config.yaml
# или
kubectl apply -f felix-config.yaml
```

После этого Calico перезапустит свои компоненты (`calico-node`) и начнет работать в режиме eBPF.

### Диагностика и проверка

1. **Проверка отсутствия `kube-proxy`**: Убедитесь, что в `kube-system` нет подов `kube-proxy`.
2. **Проверка отсутствия `ipvs`**: На узлах кластера не должен быть виден интерфейс `kube-ipvs0`.
3. **Проверка файловой системы BPF**: Убедитесь, что на узлах смонтирована файловая система `bpf`.

    ```bash
    mount | grep bpf
    # Ожидаемый вывод: none on /sys/fs/bpf type bpf (rw,relatime)
    ```

4. **Просмотр NAT-таблицы eBPF**: Для отладки можно зайти в под `calico-node` и выполнить команду, чтобы увидеть, как eBPF обрабатывает трансляцию адресов.

    ```bash
    kubectl exec -it -n kube-system <calico-node-pod> -- calico-node bpf nat dump
    ```
