# Тип Service — NodePort

## Определения

**NodePort** — тип Service в Kubernetes, который обеспечивает внешний доступ к приложению, резервируя статический порт на каждом узле кластера (worker и control-plane, если на них нет специальных ограничений). Трафик, поступающий на любой узел по этому порту (`NodeIP:NodePort`), перенаправляется на соответствующие поды.

NodePort является логической надстройкой над [ClusterIP](./service_type_clusterip.md). При его создании Kubernetes автоматически выделяет внутренний IP-адрес кластера для маршрутизации трафика внутри сети CNI.

## Основные концепции

### Механика работы

При создании Service типа NodePort выполняются следующие действия:

1. **Резервирование порта:** На каждом узле кластера открывается порт из диапазона `30000–32767`.
2. **Kube-proxy и правила NAT:** Компонент `kube-proxy` (в режимах `iptables`, `IPVS` или `nftables`) создает правила трансляции адресов (DNAT). Входящий пакет на `NodeIP:NodePort` перенаправляется на виртуальный `ClusterIP:Port` сервиса.
3. **Маршрутизация CNI:** Пакет передается внутри кластерной сети к конкретному поду, выбранному согласно `selector`.

### Политики трафика (Traffic Policies)

#### externalTrafficPolicy

Управляет обработкой трафика, приходящего извне (на NodePort).

| Режим | Описание | SNAT | Сохранение Source IP |
| :--- | :--- | :--- | :--- |
| **Cluster** (Default) | Трафик может быть перенаправлен на под на другом узле. | Да | Нет (виден IP узла) |
| **Local** | Трафик направляется только на поды, запущенные на текущем узле. | Нет | Да (виден реальный IP клиента) |

**Особенности `Local`:**
- Если на узле нет подходящих подов, трафик отбрасывается.
- Используется с **Health Check NodePort**: Kubernetes открывает дополнительный порт (по умолчанию случайный, можно задать в `healthCheckNodePort`), по которому внешние балансировщики могут проверять наличие живых подов на конкретном узле.

#### internalTrafficPolicy

Управляет трафиком, инициированным *внутри* кластера (при обращении к NodePort или ClusterIP).

- **Cluster:** Внутренний трафик может уходить на любой под в кластере.
- **Local:** Внутренний трафик направляется только на поды внутри того же узла. Если их нет — запрос завершится ошибкой.

### Параметры конфигурации

- **nodePort:** Можно задать вручную. Если не указан, Kubernetes выберет свободный из диапазона.
- **service-node-port-range:** Настройка API-сервера (флаг `--service-node-port-range`) позволяет изменить стандартный диапазон (например, на `80-32767`).
- **allocateLoadBalancerNodePorts:** Поле в `spec` (для типа `LoadBalancer`), позволяющее отключить автоматическое выделение NodePort, если облачный провайдер поддерживает прямую доставку в поды.

## Практические сценарии

### Стандартный манифест (Cluster Policy)

Типовой пример для публикации веб-приложения в тестовой среде.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-nodeport
spec:
  type: NodePort
  selector:
    app: nginx
  ports:
    - name: http
      protocol: TCP
      port: 80         # Порт внутри ClusterIP
      targetPort: 80   # Порт в контейнере
      nodePort: 32080  # Явно заданный порт на узлах
```

### Сценарий с сохранением Source IP (Local Policy)

Необходимо для систем логирования и защиты (WAF), когда важно знать реальный IP клиента.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend-local
spec:
  type: NodePort
  externalTrafficPolicy: Local
  healthCheckNodePort: 31234 # Порт для проверки состояния узла балансировщиком
  selector:
    app: api
  ports:
    - port: 8080
      targetPort: 8080
      nodePort: 30001
```

### Мультипортовый сервис

NodePort позволяет открывать несколько портов в рамках одного сервиса.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: multi-port-service
spec:
  type: NodePort
  selector:
    app: database
  ports:
    - name: data
      port: 5432
      targetPort: 5432
      nodePort: 30432
    - name: metrics
      port: 9187
      targetPort: 9187
      nodePort: 30187
```

## Дополнительная информация

### Безопасность и сетевая изоляция

- **Слушает везде:** По умолчанию NodePort открывается на всех интерфейсах всех узлов. Это включает в себя публичные IP, если узлы имеют прямой выход в интернет.
- **Firewall:** Необходимо ограничивать доступ к диапазону 30000-32767 на уровне сетевых экранов (Security Groups, iptables на хосте).
- **Control Plane:** Если мастера (control-plane) не имеют специальных запрещающих правил, порты будут открыты и на них, даже если там нет подов приложения.

### Dual-stack (IPv4/IPv6)

Kubernetes поддерживает NodePort для обоих семейств протоколов. В режиме Dual-stack сервис может иметь `ipFamilyPolicy: PreferDualStack` или `RequireDualStack`, что создаст правила проброса как для IPv4, так и для IPv6 адресов узлов.

### Сравнение с альтернативами

| Характеристика | NodePort | LoadBalancer | Ingress (L7) |
| :--- | :--- | :--- | :--- |
| **Уровень OSI** | L4 (TCP/UDP/SCTP) | L4 (TCP/UDP) | L7 (HTTP/HTTPS) |
| **Диапазон портов** | 30000–32767 | Любые | 80, 443 (стандарт) |
| **Масштабируемость** | Ручное управление IP | Автоматика провайдера | Централизованная |
| **SNAT** | Зависит от policy | Зависит от policy | Обычно да (Proxy) |
