### `NodePort`

- **Описание:** Открывает статический порт (`NodePort`) в диапазоне 30000-32767 на **каждом узле** кластера. Трафик, приходящий на `NodeIP:NodePort`, перенаправляется на `Service`. Это позволяет публиковать приложение "из коробки". При использовании `NodePort` на каждой ноде кластера открывается порт из этого диапазона (например, 31000), и обращаясь на внешний IP-адрес ноды и этот порт (например, `NodeIP:31000`), можно попасть в ваше приложение.
- **Недостатки:**
  - **Неудобство для пользователей:** Использование высоконумерованных портов (30000-32767) неудобно для конечных пользователей, так как требует явного указания порта в URL (например, `mysite.com:31000`).
  - **Ограниченный диапазон портов:** Диапазон портов ограничен, что может стать проблемой при большом количестве сервисов.
  - **Зависимость от IP-адреса ноды:** Если IP-адрес ноды изменится, доступ к приложению будет потерян.
- **Использование:**
  - Для предоставления внешнего доступа к сервису на время разработки, для демо или для приложений, не требующих сложной балансировки.
  - В качестве бэкенда для внешнего балансировщика нагрузки, который перенаправляет трафик на `NodeIP:NodePort`.
  - Для публикации не-HTTP приложений (например, TCP-сервисов, таких как RabbitMQ, базы данных).

**Пример манифеста `NodePort` Service:**

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service-np
spec:
  # 1. Тип сервиса. Если не указан, по умолчанию используется ClusterIP.
  type: NodePort

  # 2. Селектор для выбора Pod'ов, на которые пойдет трафик.
  #    Должен соответствовать меткам в шаблоне Deployment, ReplicaSet и т.д.
  selector:
    app: my-app

  # 3. Описание портов.
  ports:
    - name: http
      protocol: TCP
      # port: Внутренний порт, на котором Service принимает трафик внутри кластера.
      port: 80
      # targetPort: Порт на Pod'ах, куда будет перенаправляться трафик.
      targetPort: 80
      # nodePort: Статический порт на узлах (только для типа NodePort).
      # Если не указать, будет выбран случайный из диапазона 30000-32767.
      # nodePort: 30080
```

**Как это работает:**

1. Трафик, отправленный на `любой_узел_кластера:<NodePort>`, будет принят.
2. `kube-proxy` перенаправит этот трафик на внутренний IP-адрес `Service` на порт `80`.
3. `Service` выберет один из `Pod`-ов с меткой `app: my-app` и отправит трафик на его порт `80`.
