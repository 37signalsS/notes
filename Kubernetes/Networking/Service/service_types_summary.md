# Сводка по типам Service

## Определения

**Сводка по типам Service** — это сравнительный анализ всех доступных типов сервисов в Kubernetes, предназначенный для выбора оптимальной стратегии публикации и связности компонентов приложения.

Для понимания базовой архитектуры и жизненного цикла сетевых объектов см. [Обзор Service](./service_overview.md).

## Основные концепции

### Иерархия и взаимосвязь типов

Большинство типов сервисов в Kubernetes построены по принципу наследования функциональности:

1. **ClusterIP** (базовый) — обеспечивает виртуальный IP внутри кластера.
2. **NodePort** (расширяет ClusterIP) — резервирует порт на каждом узле для проброса трафика к ClusterIP.
3. **LoadBalancer** (расширяет NodePort) — инициирует создание внешнего балансировщика у провайдера, который направляет трафик на NodePort.

Исключениями являются `ExternalName` (только DNS-проксирование) и `Headless` (сервис без ClusterIP для прямого доступа к подам).

### Сравнительные характеристики уровней доступа

| Тип | Доступность | Уровень OSI | Основной сценарий |
| :--- | :--- | :--- | :--- |
| **[ClusterIP](./service_type_clusterip.md)** | Внутри кластера | L4 (TCP/UDP/SCTP) | Межсервисное взаимодействие |
| **[NodePort](./service_type_nodeport.md)** | Снаружи (через узлы) | L4 | On-premise, среды разработки |
| **[LoadBalancer](./service_type_loadbalancer.md)** | Снаружи (через IP/DNS LB) | L4 | Production в облаках или с MetalLB |
| **[Headless](./service_type_headless.md)** | Прямой доступ к IP подов | L4 | StatefulSet, кастомная балансировка |
| **[ExternalName](./service_type_externalname.md)** | Псевдоним DNS | DNS | Доступ к внешним БД или API по имени |
| **[Ingress](../Ingress/overview.md)** | Снаружи (L7 прокси) | L7 (HTTP/HTTPS) | Балансировка по путям и доменам |
| **Gateway API** | Снаружи (L7/L4) | L7/L4 | Современная замена Ingress (CRD-based) |

### Технические ограничения и нюансы

| Тип | Критическая особенность |
| :--- | :--- |
| **ClusterIP** | Недоступен извне. Требует `ingress` или `proxy` для внешнего доступа. |
| **NodePort** | По умолчанию диапазон 30000–32767. Порты открыты на всех узлах. |
| **LoadBalancer** | Требует контроллер (cloud controller manager или MetalLB). |
| **Headless** | Нет балансировки kube-proxy. Зависит от кеширования DNS на клиенте. |
| **ExternalName** | Не поддерживает селекторы подов. Работает только на уровне DNS. |

## Практические сценарии

### Матрица выбора типа публикации

| Задача / Требование | Рекомендуемое решение |
| :--- | :--- |
| Изолированный микросервис (только внутренний API) | **ClusterIP** |
| База данных в кластере (требуется кворум и имена) | **Headless Service** (для StatefulSet) |
| Публикация HTTP/HTTPS порта в облаке (AWS, GCP, Azure) | **Ingress** (поверх ClusterIP) или **LoadBalancer** |
| Публикация TCP/UDP приложения (не HTTP) в облаке | **LoadBalancer** |
| Локальная отладка доступа без внешнего LB | **NodePort** |
| Переезд с внешней БД в кластер (сохранение DNS-имени) | **ExternalName** |
| Сложная маршрутизация (несколько доменов, TLS, Canary) | **Ingress** или **Gateway API** |

## Дополнительная информация

### Механизмы управления трафиком

Для тонкой настройки распределения запросов используются дополнительные атрибуты в `spec`:

| Атрибут | Описание | Применимость |
| :--- | :--- | :--- |
| **externalTrafficPolicy** | Управляет сохранением Source IP (Cluster vs Local). | NodePort, LoadBalancer |
| **internalTrafficPolicy** | Ограничивает внутренний трафик пределами узла. | ClusterIP, NodePort |
| **Topology Aware Hints** | Направляет трафик в ту же зону доступности (AZ). | Все типы с ClusterIP |
| **publishNotReadyAddresses** | Разрешает DNS-ответы для не готовых (Ready) подов. | Headless Service |
| **Session Affinity** | Привязка клиента к конкретному поду (ClientIP). | ClusterIP, NodePort |

### Сравнение Service vs Ingress vs Gateway API

- **Service (L4):** Работает на уровне TCP/UDP. Не умеет заглядывать в HTTP-заголовки или пути URL.
- **Ingress (L7):** Специализированный контроллер для HTTP. Поддерживает SSL-терминацию и виртуальные хосты.
- **Gateway API:** Новое поколение сетевых объектов в Kubernetes. Более гибкое разделение ответственности между администратором кластера и разработчиком. Поддерживает как L7, так и расширенные сценарии L4.
