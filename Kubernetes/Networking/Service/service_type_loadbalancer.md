# Тип Service — LoadBalancer

## Определения

**LoadBalancer** — тип Service в Kubernetes, который автоматически создает внешний балансировщик нагрузки в инфраструктуре облачного провайдера (AWS, Google Cloud, Azure). Балансировщик получает публичный IP-адрес и направляет трафик на поды кластера.

LoadBalancer является расширением типов [NodePort](./service_type_nodeport.md) и [ClusterIP](./service_type_clusterip.md). Путь трафика выглядит следующим образом:
`Внешний запрос → Облачный LB → NodePort → ClusterIP → Pod`

**Основная задача:** Автоматизация публикации приложений в облачных средах с предоставлением единой и стабильной точки входа из интернета.

## Основные концепции

### Принцип работы

При развертывании сервиса типа LoadBalancer:

1. Kubernetes отправляет запрос API облачного провайдера через компонент `cloud-controller-manager`.
2. Провайдер создает физический или виртуальный балансировщик (например, AWS NLB/ALB, GCP LB).
3. Балансировщику назначается внешний IP-адрес.
4. Kubernetes автоматически резервирует `NodePort` на всех узлах кластера.
5. Облачный балансировщик настраивается на пересылку трафика на эти `NodePort`.
6. `kube-proxy` на узлах перенаправляет трафик на конечные поды.

### Требования

- **Облачный провайдер:** Полноценная поддержка требует наличия интеграции кластера с облаком.
- **On-premise (bare-metal):** "Из коробки" данный тип в локальных кластерах переходит в состояние `Pending` для внешнего IP. Требуется установка [MetalLB](../metallb.md) для эмуляции облачного балансировщика.

### Политика внешнего трафика (externalTrafficPolicy)

Для управления сохранением исходного IP-адреса клиента используется поле `externalTrafficPolicy`.

| Режим | Описание | Сохранение IP |
| :--- | :--- | :--- |
| **Cluster** (default) | Трафик может быть перенаправлен на другой узел. Выполняется SNAT. | Нет |
| **Local** | Трафик идет только на локальные поды узла. SNAT отсутствует. | Да |

Подробный разбор механики и ограничений см. в разделе [externalTrafficPolicy в NodePort](./service_type_nodeport.md#политика-внешнего-трафика-externaltrafficpolicy).

### Статический IP-адрес

Для назначения конкретного IP-адреса (если он зарезервирован у провайдера) ранее использовалось поле `loadBalancerIP`. Однако в современных версиях Kubernetes оно депрецировано.

**Рекомендация:** Используйте аннотации, специфичные для вашего облачного провайдера, или переходите на использование [Gateway API](../gateway_api/definitions.md).

## Практические сценарии

### Пример манифеста

```yaml
apiVersion: v1
kind: Service
metadata:
  name: cloud-app-lb
spec:
  type: LoadBalancer
  selector:
    app: cloud-app
  ports:
    - name: http
      protocol: TCP
      port: 80         # Внешний порт балансировщика
      targetPort: 8080 # Порт приложения в контейнере
```

### Пример с сохранением IP клиента

Используется для приложений, которым критично знать реальный адрес пользователя (логирование, безопасность, геоаналитика).

```yaml
apiVersion: v1
kind: Service
metadata:
  name: cloud-app-lb-local
spec:
  type: LoadBalancer
  externalTrafficPolicy: Local
  selector:
    app: cloud-app
  ports:
    - name: http
      port: 80
      targetPort: 8080
```

### Сценарии использования

- **Публикация production-приложений:** Основной способ в публичных облаках.
- **TCP/UDP трафик:** Публикация не-HTTP сервисов (базы данных, игровые серверы, брокеры сообщений).
- **Прямой доступ:** Когда не требуется сложная L7-маршрутизация, предоставляемая Ingress.

## Дополнительная информация

### Ограничения

- **Стоимость:** Каждый созданный сервис типа LoadBalancer обычно оплачивается как отдельный ресурс у облачного провайдера.
- **Уровень OSI:** Работает на уровне L4 (транспортный). Не поддерживает маршрутизацию на основе путей (`/api`) или доменных имен в рамках одного IP.
- **Зависимость:** Требует внешней поддержки (облако или MetalLB).

### Сравнение: LoadBalancer vs Ingress

| Критерий | LoadBalancer | Ingress |
| :--- | :--- | :--- |
| **Уровень OSI** | L4 (TCP/UDP) | L7 (HTTP/HTTPS) |
| **IP-адреса** | Один сервис = один IP | Один IP на множество сервисов |
| **SSL/TLS** | На уровне провайдера/сервиса | Централизованно в контроллере |
| **Маршрутизация** | Только по портам | По хостам, путям, заголовкам |

### Альтернативы для bare-metal

1. **[MetalLB](../metallb.md):** Позволяет использовать тип `LoadBalancer` в локальных сетях (режимы L2 или BGP).
2. **NodePort + Внешний LB:** Настройка внешнего аппаратного или программного (F5, Nginx, HAProxy) балансировщика на узлы кластера.
3. **[Gateway API](../gateway_api/definitions.md):** Современный стандарт управления трафиком, объединяющий возможности LB и Ingress.
