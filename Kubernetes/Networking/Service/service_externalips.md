# ExternalIPs

## Определения

**ExternalIPs** — это поле в спецификации `Service`, которое позволяет привязать один или несколько внешних, но статически известных IP-адресов к сервису. Трафик, поступающий на эти IP-адреса, будет маршрутизироваться `kube-proxy` на поды, обслуживаемые данным сервисом.

Это не тип сервиса, а **свойство**, которое можно использовать с такими типами, как `ClusterIP` или `NodePort`.

## Основные концепции

### Принцип работы
Когда вы указываете IP-адреса в поле `externalIPs`, `kube-proxy` на каждом узле кластера создает правила (`iptables` или `IPVS`). Эти правила "ловят" трафик, предназначенный для одного из внешних IP, и перенаправляют его на `ClusterIP` сервиса, который, в свою очередь, балансирует его между подами.

Это позволяет "завести" в кластер трафик, который приходит на заранее известный IP-адрес, находящийся под вашим управлением.

### Ключевые отличия
- **От `NodePort`:** `NodePort` открывает порт на *всех* узлах, а `ExternalIPs` привязывается к конкретному IP, который может быть не связан с узлами напрямую.
- **От `LoadBalancer`:** `LoadBalancer` динамически запрашивает IP у облачного провайдера, в то время как `ExternalIPs` использует IP, который вы предоставляете и конфигурируете сами.

## Практические сценарии

### Пример манифеста
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
spec:
  selector:
    app: my-app
  ports:
    - name: http
      protocol: TCP
      port: 80
      targetPort: 8080
  # Привязываем сервис к внешнему IP, который вы контролируете
  externalIPs:
    - 203.0.113.10
```
Трафик, приходящий на `203.0.113.10:80`, будет направлен на порт `8080` подов с меткой `app: my-app`.

### Распространенные use-case
- **Интеграция с существующей инфраструктурой:** Если у вас есть выделенные IP-адреса и настроенная маршрутизация до узлов кластера, `ExternalIPs` позволяет направить этот трафик в нужный сервис.
- **Отказоустойчивые IP (VIP):** В паре с протоколами вроде VRRP или Keepalived, где виртуальный IP-адрес "мигрирует" между машинами. Вы назначаете этот VIP в `externalIPs`, и Kubernetes будет корректно обрабатывать трафик независимо от того, через какой узел он пришел.
- **Bare-metal кластеры:** Когда нет облачного провайдера для создания `LoadBalancer`, `ExternalIPs` является одним из способов публикации сервисов.

## Дополнительная информация

### Вопросы безопасности
Использование `externalIPs` может быть рискованным, так как сервис, получивший такой IP, может "перехватить" трафик, предназначенный для других приложений. В некоторых кластерах эта функция может быть отключена администраторами с помощью политик доступа.
