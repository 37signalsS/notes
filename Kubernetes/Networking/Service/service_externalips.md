# ExternalIPs в Service

## Определения

**ExternalIPs** — поле в спецификации `Service`, позволяющее привязать сервис к одному или нескольким статическим внешним IP-адресам, контролируемым администратором. Трафик, поступающий на эти IP-адреса, маршрутизируется компонентом `kube-proxy` на поды, обслуживаемые данным сервисом.

ExternalIPs не является типом сервиса; это свойство, применимое к типам `ClusterIP`, `NodePort` и `LoadBalancer`.

**Важное примечание: депрекация в v1.36**
Поле `externalIPs` депрецируется в Kubernetes v1.36 (ноябрь 2025). Причина — уязвимость безопасности CVE-2020-8554 (атака Man-in-the-Middle). Рекомендуется планировать миграцию на альтернативы: LoadBalancer, Ingress или MetalLB.
Подробности в [KEP-5707](https://github.com/kubernetes/enhancements/blob/master/keps/sig-network/5707-deprecate-service-externalips/README.md).

## Основные концепции

### Принцип работы

При указании IP-адресов в поле `externalIPs`, `kube-proxy` на каждом узле создает правила (iptables или IPVS), которые перехватывают трафик для данных IP и перенаправляют его на `ClusterIP` сервиса.

**Требования и ограничения:**
- Внешние IP должны маршрутизироваться на узлы кластера сетевой инфраструктурой.
- Настройка маршрутизации является ответственностью администратора; Kubernetes не управляет выделением этих IP.
- Требуется предварительная настройка внешней сетевой среды.

### Сравнение с другими механизмами доступа

| Характеристика | ExternalIPs | NodePort | LoadBalancer |
| :--- | :--- | :--- | :--- |
| **Доступ** | Конкретный внешний IP | Порт на всех узлах | Публичный IP от облака |
| **Управление IP** | Вручную (администратор) | Не требуется | Автоматически (провайдер) |
| **Сложность** | Высокая (настройка сети) | Низкая | Низкая (в облаке) |
| **Статус** | Депрецируется v1.36 | Стабилен | Стабилен |

## Практические сценарии

### Пример манифеста

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
spec:
  selector:
    app: my-app
  ports:
    - name: http
      protocol: TCP
      port: 80
      targetPort: 8080
  # Привязка сервиса к внешнему IP
  externalIPs:
    - 203.0.113.10
```

Трафик на `203.0.113.10:80` будет перенаправлен на порт `8080` соответствующих подов.

### Рекомендуемые альтернативы

| Сценарий | Решение |
| :--- | :--- |
| Bare-metal окружение | [MetalLB](../metallb.md) |
| HTTP/HTTPS приложения | [Ingress](../Ingress/overview.md) |
| Облачная инфраструктура | [LoadBalancer](./service_type_loadbalancer.md) |
| Разработка и отладка | [NodePort](./service_type_nodeport.md) или `kubectl port-forward` |

## Дополнительная информация

### Безопасность и CVE-2020-8554

Уязвимость CVE-2020-8554 позволяет злоумышленнику с правами на создание сервисов перехватывать трафик других приложений кластера через манипуляцию с `externalIPs`.

**Меры защиты:**
- Ограничение прав на создание/редактирование Service через [RBAC](../../Security/rbac/rbac_overview.md).
- Использование [NetworkPolicy](../Network/NetworkPolicy/definitions.md) для изоляции трафика.
- Валидация ресурсов через политики [Kyverno](../../Security/kyverno/concepts.md) или [Pod Security Admission](../../Security/pod_security_context.md).
- Полное отключение функции на уровне кластера флагом `--feature-gates=ExternalIPs=false`.
