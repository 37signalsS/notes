# ExternalName

## Определения

**ExternalName** — это специальный тип `Service`, который не проксирует трафик, а возвращает CNAME-запись во внутреннем DNS кластера. Он сопоставляет сервис с внешним DNS-именем, позволяя приложениям внутри кластера обращаться к внешнему ресурсу через внутреннее имя сервиса.

## Основные концепции

### Принцип работы
При обращении к сервису типа `ExternalName` по его имени (например, `my-external-db`), DNS-сервер кластера (CoreDNS) возвращает CNAME-запись с адресом, указанным в поле `externalName` манифеста. Весь последующий трафик идет напрямую к внешнему ресурсу, минуя `kube-proxy` и внутреннюю балансировку нагрузки Kubernetes.

Это эффективный способ скрыть реальный адрес внешнего ресурса и упростить конфигурацию.

### Ключевые особенности
- **Нет `ClusterIP`:** Сервисы `ExternalName` не имеют внутреннего IP-адреса, так как они не занимаются проксированием.
- **Нет селекторов:** Для `ExternalName` не используются селекторы, поскольку они не привязаны к подам внутри кластера.
- **Работа только на уровне DNS:** Весь механизм основан исключительно на DNS-разрешении.

## Практические сценарии

### Пример манифеста
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-external-service
  namespace: default
spec:
  type: ExternalName
  externalName: my.database.example.com
```
В данном примере запросы к `my-external-service.default.svc.cluster.local` будут перенаправлены на `my.database.example.com`.

### Распространенные use-case
- **Доступ к управляемым базам данных:** Предоставление доступа к внешним базам данных (например, AWS RDS, Google Cloud SQL) по внутреннему имени.
- **Интеграция с внешними API:** Обращение к сторонним API, как если бы они были внутренними сервисами кластера.
- **Плавная миграция:** Во время миграции приложений в Kubernetes можно использовать `ExternalName` для временного обращения к компонентам, которые все еще работают вне кластера.

## Дополнительная информация

### Сравнение с другими типами
В отличие от `ClusterIP` или `NodePort`, `ExternalName` не имеет отношения к маршрутизации трафика на поды. Его единственная задача — разрешение имен.
