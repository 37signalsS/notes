# ClusterIP

## Определения

**ClusterIP** — тип Service, который предоставляет внутренний IP-адрес, доступный **только внутри кластера**. Это тип **по умолчанию** для всех сервисов Kubernetes.

ClusterIP создает стабильную виртуальную точку доступа к группе Pod, позволяя внутренним компонентам приложения взаимодействовать друг с другом без привязки к конкретным IP-адресам подов.

## Основные концепции

### Принцип работы

При создании Service типа ClusterIP:

1. Kubernetes назначает виртуальный IP-адрес из диапазона `ClusterIP` (по умолчанию 10.96.0.0/12)
2. Создается DNS-запись вида `service.namespace.svc.cluster.local`
3. `kube-proxy` настраивает правила маршрутизации (`iptables` или `IPVS`) для перенаправления трафика с виртуального IP на реальные Pod

### Ключевые правила

1. **Селектор меток:** Service выбирает Pod только по механизму `selector`. Селектор должен точно совпадать с метками подов
2. **Namespace:** Под и Service должны находиться в одном namespace для прямого взаимодействия (между namespace используется FQDN)

### Особенности

| Особенность | Описание |
|-------------|----------|
| **DNS-имя** | `service.namespace.svc.cluster.local` (доступно внутри кластера) |
| **Балансировка** | Распределение через `kube-proxy` (режимы `iptables` или `IPVS`) |
| **Session Affinity** | Поддержка `sessionAffinity` для привязки сессии к конкретному поду |

## Практические сценарии

Пошаговый пример создания сервиса `ClusterIP` и его последующего преобразования в `NodePort` см. в документе **[Практический сценарий: публикация приложения](./service_practical_scenarios.md)**.

### Пример манифеста

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  type: ClusterIP  # Можно не указывать — значение по умолчанию
  ports:
    - name: http
      protocol: TCP
      port: 80        # Порт сервиса внутри кластера
      targetPort: 8080 # Порт на Pod
```

### Распространенные use-case

- **Backend-to-Database:** Веб-приложение обращается к PostgreSQL через ClusterIP
- **Microservices communication:** Сервисы внутри приложения взаимодействуют друг с другом
- **Internal APIs:** API, не предназначенные для внешнего доступа

## Дополнительная информация

### Доступ для отладки

Для временного доступа к ClusterIP сервису извне кластера используйте:

- **`kubectl port-forward`** — проброс порта на локальную машину. Подробнее см. [Troubleshooting](../../../Troubleshooting/troubleshooting_overview.md#kubectl-port-forward-доступ-к-приложению)

**Важно:** Эти методы предназначены только для отладки и разработки, **не для production**.

### Сравнение с другими типами

ClusterIP является базовым типом, который используется как фундамент для:

- [NodePort](./service_type_nodeport.md) — добавляет публикацию через порт узла
- [LoadBalancer](./service_type_loadbalancer.md) — добавляет облачный балансировщик

Полная сводка типов сервисов: [service_types_summary.md](./service_types_summary.md)
