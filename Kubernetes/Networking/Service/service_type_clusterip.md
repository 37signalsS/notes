## Практические сценарии: Типы сервисов

В Kubernetes доступны следующие типы сервисов:

- **ClusterIP**
- **NodePort**
- **LoadBalancer**
- **ExternalName**
- **ExternalIPs**
- **Headless Service**

### `ClusterIP`

- **Описание:** Предоставляет внутренний IP-адрес, доступный **только внутри кластера**. Это тип **по умолчанию**.
- **Использование:** Для внутренней коммуникации между компонентами приложения (например, бэкенд обращается к базе данных или кэшу).

**Два ключевых правила работы Service:**

1. **Совпадение селектора с метками:** `Service` понимает, на какие поды отправлять трафик, только по механизму **селектора меток** (`selector`). Селектор сервиса должен точно совпадать с метками подов, на которые он должен направлять трафик.
2. **Один и тот же Namespace:** Под и сервис должны работать в одном и том же `namespace`, иначе они не смогут найти друг друга.

**Пример манифеста `ClusterIP` Service:**

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  type: ClusterIP # Явно указываем тип ClusterIP, хотя это и значение по умолчанию
  ports:
    - name: http
      protocol: TCP
      port: 80
      targetPort: 8080
```

**Публикация `ClusterIP` сервиса наружу (только для отладки/разработки):**
Чисто технически, `ClusterIP` сервис не предназначен для публикации наружу. Однако, для целей отладки или локальной разработки можно использовать следующие методы:

1. **`kubectl proxy`**: Создает прокси-сервер, который позволяет обращаться к API Kubernetes и, через него, к сервисам.

    ```bash
    kubectl proxy --port=8080
    # Затем можно обратиться по адресу:
    # http://localhost:8080/api/v1/namespaces/default/services/my-service/proxy/
    ```

    Этот метод открывает доступ через API-сервер Kubernetes и **категорически не рекомендуется для использования в продакшене** из-за соображений безопасности и масштабируемости.

2. **`kubectl port-forward`**: Пробрасывает порт с локальной машины на порт пода или сервиса в кластере.

    ```bash
    kubectl port-forward service/my-service 10000:80
    # Теперь трафик на localhost:10000 на вашей локальной машине будет перенаправлен на порт 80 сервиса my-service в кластере.
    ```

    Это удобный способ для локальной отладки и разработки, но **не предназначен для постоянной публикации приложения или использования в продакшн-средах**.
