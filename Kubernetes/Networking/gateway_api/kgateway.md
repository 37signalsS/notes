# KGateway — реализация Gateway API

## Определения

**KGateway** — контроллер Gateway API с открытым исходным кодом на базе Envoy Proxy. Проект является преемником Gloo Gateway (разработка Solo.io) и находится в статусе CNCF Sandbox.

**Gateway API First** — архитектурный подход, при котором Gateway API является основным и единственным способом конфигурации контроллера без использования промежуточных или проприетарных интерфейсов.

## Базовые концепции

### Архитектура

KGateway разделяет уровни управления и обработки данных:

- **Control Plane:** отслеживает ресурсы Gateway API в кластере Kubernetes и динамически генерирует конфигурацию для Envoy.
- **Data Plane (Envoy):** высокопроизводительный прокси-сервер, который выполняет непосредственную обработку и маршрутизацию трафика.

### Ключевые преимущества

- **Высокая производительность:** благодаря использованию Envoy контроллер эффективно обрабатывает большое количество маршрутов и динамических обновлений.
- **Готовность к эксплуатации (Production-ready):** встроенная поддержка ролевой модели Gateway API (разделение ответственности между сетевыми администраторами и разработчиками приложений).
- **Нативность:** полная реализация спецификаций Gateway API без необходимости использования специфических аннотаций или кастомных ресурсов (CRD) для базовых функций.

## Практические сценарии

### Установка через Helm

Установка KGateway выполняется в два этапа: сначала устанавливаются определения ресурсов (CRD), затем компоненты контроллера.

```bash
# 1. Добавление репозитория и установка CRD
helm repo add kgateway https://kgateway-dev.github.io/kgateway/
helm install kgateway-crds kgateway/kgateway-crds --namespace kgateway --create-namespace

# 2. Установка Control Plane
helm install kgateway kgateway/kgateway --namespace kgateway
```

### Проверка работоспособности

После установки необходимо убедиться, что компоненты запущены и зарегистрирован соответствующий класс шлюза:

```bash
kubectl get pods -n kgateway
kubectl get gatewayclass
# → должен появиться класс с именем kgateway
```

### Базовый пример Gateway

Создание шлюза, который принимает HTTP-трафик на порту 80 изо всех пространств имен:

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: my-gateway
  namespace: kgateway
spec:
  gatewayClassName: kgateway
  listeners:
  - name: http
    protocol: HTTP
    port: 80
    allowedRoutes:
      namespaces:
        from: All
```

## Дополнительная информация

### Нюансы эксплуатации

- **Управление метриками:** KGateway генерирует детальную статистику для Prometheus. На высоконагруженных кластерах это может привести к значительному потреблению ресурсов CPU и оперативной памяти. Рекомендуется фильтрация и настройка параметров Observability.
- **Диагностика через Status Conditions:** контроллер активно обновляет статус ресурсов Gateway API. Первым шагом при возникновении проблем всегда должен быть осмотр ресурсов через `kubectl describe gateway` или `kubectl describe httproute`.
