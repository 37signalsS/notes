# Gateway API — Определения и концепции

## Определения

**Gateway API** — унифицированный стандарт Kubernetes для управления сетевым трафиком (L4 и L7). Это эволюционное развитие Ingress, объединяющее управление внешним доступом (North-South) и мессервисным взаимодействием (East-West/Service Mesh) в рамках единой объектной модели. Стандарт полностью базируется на Custom Resource Definitions (CRD).

**Gateway API Controller** — программный компонент (например, Envoy Gateway, Istio, Traefik), который отслеживает ресурсы Gateway API и транслирует их в конфигурацию для Data Plane (прокси-серверов).

**GAMMA (Gateway API for Mesh Management and Administration)** — инициатива внутри Gateway API, определяющая стандарты для Service Mesh. Она позволяет использовать те же ресурсы (например, `HTTPRoute`) для управления трафиком внутри кластера, привязывая их непосредственно к `Service` (режим East-West).

**Direct Pod Targeting** — механизм, при котором контроллер направляет трафик напрямую на IP-адреса подов (Endpoints), минуя виртуальный IP сервиса (ClusterIP) и `kube-proxy`. Это снижает задержки и позволяет реализовать сложные алгоритмы балансировки на стороне прокси.

## Базовые концепции

### Ролевая модель управления

Спецификация ориентирована на разделение ответственности между тремя ролями, что позволяет масштабировать управление сетью в крупных организациях:

- **Администраторы инфраструктуры:** управляют `GatewayClass`. Определяют политики безопасности, типы доступных контроллеров и глобальные параметры провайдера.
- **Операторы кластера:** управляют ресурсами `Gateway` и `ListenerSet`. Отвечают за сетевые точки входа, выделение IP-адресов, портов и общие настройки TLS-терминации.
- **Разработчики приложений:** управляют ресурсами маршрутизации (`HTTPRoute`, `GRPCRoute`, `TCPRoute`). Настраивают логику своих приложений (пути, заголовки, веса), не затрагивая общую инфраструктуру шлюзов.

### Механизм Policy Attachment

Gateway API вводит стандартизированный способ расширения функционала через **политики** (например, `RetryPolicy`, `TimeoutPolicy`, `SecurityPolicy`). Политики прикрепляются к ресурсам через `targetRef`, что избавляет от необходимости использовать разрозненные аннотации и обеспечивает типизацию настроек.

### Сравнение с Ingress (Legacy)

К середине 2026 года Gateway API полностью заменил Ingress в промышленной эксплуатации. Основные отличия:

| Характеристика | Ingress (Legacy) | Gateway API (Standard) |
| :--- | :--- | :--- |
| **Область применения** | Только North-South (входящий) | North-South и East-West (GAMMA) |
| **Ролевая модель** | Монолитный ресурс `Ingress` | Разделение на `GatewayClass`, `Gateway`, `Route` |
| **Расширяемость** | Хаотичные аннотации | Типизированные фильтры и Policy Attachment |
| **Безопасность** | Дублирование секретов в namespaces | `ReferenceGrant` (безопасные кросс-ссылки) |
| **Масштабируемость** | Лимиты слушателей в одном объекте | `ListenerSet` для мультитенентности |
| **Протоколы** | Преимущественно HTTP/HTTPS | Нативная поддержка gRPC, TLS, TCP, UDP |
| **Производительность** | Балансировка через Service VIP | Direct Pod Targeting (напрямую на поды) |

### Типы трафика

1. **North-South (Входящий):** Трафик от внешних клиентов к сервисам внутри кластера. Цепочка: `Gateway` -> `HTTPRoute` -> `Service` -> `Pod`.
2. **East-West (Мессервисный):** Взаимодействие между подами внутри кластера. В рамках спецификации GAMMA трафик управляется через `HTTPRoute` с `parentRef`, указывающим на целевой `Service`.

## Практические сценарии

### Выбор реализации (2026)

Выбор контроллера зависит от архитектурных требований:

- **Envoy Gateway:** Официальное решение CNCF, рекомендуемый стандарт для большинства сред.
- **Cilium:** Оптимально для сред с высокими требованиями к производительности (использование eBPF).
- **Istio Gateway Controller:** Рекомендуется при использовании Istio Service Mesh для глубокой интеграции с mTLS.
- **Traefik (v3.3+):** Простота настройки и нативная поддержка Gateway API v1.2+.
- **NGINX Gateway Fabric:** Стабильность NGINX в современной обертке Gateway API.

Сравнение популярных решений: [Envoy Gateway](./envoy_gateway.md), [Traefik](./traefik.md), [KGateway](./kgateway.md).

### Диагностика: Метод Status Conditions

Gateway API предоставляет детализированную обратную связь через поле `status.conditions`. Это основной инструмент отладки конфигурации:
- **Accepted:** Ресурс синтаксически корректен и принят контроллером.
- **Programmed:** (только для Gateway) Инфраструктура шлюза успешно настроена в Data Plane.
- **ResolvedRefs:** Все ссылки на зависимости (сервисы, секреты) найдены и валидны (учитывая `ReferenceGrant`).

```bash
# Проверка состояния всех ресурсов Gateway API в кластере
kubectl get gateway,httproute,gatewayclass,referencegrant -A
```
