# Gateway API — Определения и концепции

**Надёжность:** 10 (SSoT + Официальная спецификация v1.5)

## Определения

**Gateway API** — унифицированный стандарт Kubernetes для управления сетевым трафиком. Это эволюционное развитие Ingress, объединяющее управление внешним доступом (North-South) и мессервисным взаимодействием (East-West/Service Mesh) в рамках единой объектной модели.

**Gateway API Controller** — программный компонент (например, Envoy Gateway, Istio, Traefik), который отслеживает ресурсы Gateway API и транслирует их в конфигурацию для Data Plane.

**GAMMA (Gateway API for Mesh Management and Administration)** — инициатива внутри Gateway API, определяющая стандарты для Service Mesh. Она позволяет использовать те же ресурсы (например, `HTTPRoute`) для управления трафиком внутри кластера, привязывая их непосредственно к `Service`.

## Базовые концепции

### Ролевая модель управления

Спецификация ориентирована на разделение ответственности между ролями, что критично для больших организаций:

- **Администраторы инфраструктуры:** управляют `GatewayClass`. Определяют политики безопасности и типы доступных шлюзов.
- **Операторы кластера:** управляют `Gateway` и `ListenerSet`. Отвечают за выделение IP-адресов, портов и общие настройки TLS.
- **Разработчики приложений:** управляют ресурсами маршрутизации (`HTTPRoute`, `GRPCRoute`). Настраивают логику своих приложений, не затрагивая общую инфраструктуру.

### Ключевые преимущества перед Ingress

К середине 2026 года Gateway API полностью заменил Ingress в новых инсталляциях благодаря следующим факторам:

| Характеристика | Ingress (Legacy) | Gateway API (Standard) |
| :--- | :--- | :--- |
| **Унификация** | Только North-South | North-South и East-West (GAMMA) |
| **Расширяемость** | Хаотичные аннотации | Типизированные фильтры и Policy Attachment |
| **Безопасность** | Дублирование секретов | `ReferenceGrant` (безопасные кросс-ссылки) |
| **Масштабируемость** | Лимиты слушателей | `ListenerSet` для мультитенентности |
| **Протоколы** | Ограничено HTTP/HTTPS | HTTP, gRPC, TLS, TCP, UDP |
| **Производительность** | Через Service VIP | Direct Pod Targeting (напрямую на поды) |

### Типы трафика

1. **North-South (Входящий):** Трафик от внешних клиентов к сервисам внутри кластера. Управляется через связку `Gateway` -> `*Route`.
2. **East-West (Мессервисный):** Взаимодействие между подами внутри кластера. В рамках GAMMA управляется через `*Route` с `parentRef`, указывающим на `Service`.

## Практические сценарии

### Выбор реализации

В 2026 году выбор контроллера зависит от архитектурных предпочтений:

- **Envoy Gateway:** Рекомендуемый стандарт для облачных и on-premise сред.
- **Istio / Linkerd:** Если требуется полноценный Service Mesh с поддержкой GAMMA.
- **Cilium:** Если важна максимальная производительность за счёт eBPF и интеграция с CNI.
- **Traefik (v3.1+):** Для сред, где важна простота настройки и нативная поддержка v3.

Сравнение популярных решений: [Envoy Gateway](./envoy_gateway.md), [Traefik](./traefik.md), [KGateway](./kgateway.md).

### Диагностика: Метод Status Conditions

Gateway API предоставляет стандартизированную обратную связь через `status.conditions`. Основные состояния:
- **Accepted:** Конфигурация валидна.
- **Programmed:** (Gateway) Шлюз успешно развернут.
- **ResolvedRefs:** (Route) Все зависимости (сервисы, секреты) найдены.

```bash
# Быстрая проверка состояния
kubectl get gateway,httproute -A
```
