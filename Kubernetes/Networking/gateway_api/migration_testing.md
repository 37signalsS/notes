# Миграция на Gateway API: тестирование и перенос трафика

## Определения

**Валидация конфигурации** — проверка корректности созданных ресурсов Gateway API перед переносом трафика.

**Поэтапный перенос** — стратегия миграции с постепенным переключением трафика с Ingress NGINX на Gateway API, начиная с non-production окружений.

## Базовые концепции

### Этапы тестирования

1. **Валидация конфигурации** — проверка ресурсов Gateway API
2. **Проверка маршрутизации** — тестирование HTTP/HTTPS-запросов
3. **Проверка TLS** — верификация сертификатов
4. **Мониторинг** — отслеживание метрик и логов

## Практические сценарии

### Валидация конфигурации

```bash
kubectl get gateway,httproute -A
kubectl describe gateway external-gateway -n infra
```

### Проверка маршрутизации

```bash
curl -H "Host: app.example.com" http://<GATEWAY_IP>/api/health
```

### Проверка TLS

```bash
curl -v https://app.example.com
```

### Поэтапный перенос трафика

- Начните с non-production окружений
- Используйте DNS для переключения трафика (canary через весовые коэффициенты)
- Мониторьте метрики контроллера

### Мониторинг

- Метрики Gateway API-контроллера (запросы, ошибки, латентность)
- Логи контроллера на предмет ошибок маршрутизации
- Доступность конечных точек (health checks)
