# Ingress-контроллеры — сравнение и выбор

## Определения

**Ingress-контроллер** — это приложение (обычно `Deployment` или `DaemonSet`), которое реализует правила маршрутизации, описанные в объекте `Ingress`. Он отслеживает изменения API Kubernetes и настраивает нижележащий прокси-сервер (NGINX, Envoy, HAProxy, Traefik). Без Ingress-контроллера объект `Ingress` не функционирует.

**Критерии выбора контроллера:**

- **Производительность** — способность обрабатывать высокий RPS с минимальной задержкой
- **Функциональность** — поддержка TLS, аутентификации, rate limiting, WebSocket, gRPC
- **Простота эксплуатации** — автоматизация, мониторинг, обновление конфигурации
- **Экосистема** — интеграция с Service Mesh, Gateway API, CI/CD
- **Ресурсоемкость** — потребление CPU и памяти

## Основные концепции

### Классификация по архитектуре

| Тип | Примеры | Прокси | Характеристика |
| :--- | :--- | :--- | :--- |
| **Специализированные** | Traefik, Kong | Собственный / NGINX+Lua | Разработаны для Kubernetes, автоматическое обнаружение сервисов |
| **Envoy-based** | Contour, Cilium, Istio | Envoy (C++) | Высокая производительность, интеграция с Service Mesh |
| **Традиционные** | HAProxy, ingress-nginx | HAProxy / NGINX | Проверенные решения, максимальная стабильность |

### Gateway API — новый стандарт

**Gateway API** — официальная замена Ingress, принятая сообществом Kubernetes. Ключевые преимущества:

- **Стандартизация** — единая спецификация для всех вендоров
- **Ролевая модель** — разделение ответственности (инфраструктура / приложения)
- **Расширенные функции** — канареечные развертывания, gRPC, TCP/UDP из коробки

> **Статус ingress-nginx (март 2026):** Сообщество Kubernetes прекратило поддержку `kubernetes/ingress-nginx`. Контроллер остается работоспособным, но не получает обновлений. Для новых проектов рекомендуется выбирать контроллеры с полной поддержкой Gateway API: **Cilium**, **Contour**, **Traefik**, **Kong**.

### Обзор популярных контроллеров

#### Traefik

Современный, облачно-ориентированный ("cloud-native") прокси-сервер, разработанный специально для динамических сред и микросервисов.

- **Основа:** Написан на Go.
- **Философия:** Простота и автоматизация.

**Особенности и преимущества:**

- **Автоматическое обнаружение сервисов (Service Discovery):** Traefik постоянно отслеживает API Kubernetes и автоматически обновляет маршруты при появлении новых `Ingress` или изменении сервисов.
- **Встроенная поддержка Let's Encrypt:** Автоматическое получение и обновление TLS-сертификатов.
- **Middleware:** Гибкая концепция "посредников" для настройки запросов: добавление заголовков, аутентификация, ограничение частоты запросов (rate limiting).
- **Поддержка Gateway API:** Наряду с Ingress, активно поддерживает новую спецификацию Gateway API.
- **Веб-интерфейс:** Встроенная панель управления для визуализации маршрутов и состояния.

**Недостатки:**

- **Производительность:** В сценариях с экстремально высокими нагрузками может уступать решениям на базе Envoy или HAProxy.
- **Ограничения бесплатной версии:** Некоторые продвинутые функции доступны только в платной версии Traefik Enterprise.

#### Решения на базе Envoy (Contour, Cilium)

Envoy — это высокопроизводительный прокси, служащий основой для многих современных контроллеров и Service Mesh.

- **Основа:** Envoy (написан на C++).
- **Философия:** Производительность, расширяемость и API-ориентированная конфигурация (xDS).

**Особенности и преимущества:**

- **Высокая производительность:** Эффективность и низкие задержки.
- **Продвинутое управление трафиком:** Зеркалирование, повторные попытки (retries), канареечные развертывания.
- **Расширяемость:** Поддержка фильтров WebAssembly (WASM).
- **Нативная поддержка Gateway API:** Большинство современных Envoy-based контроллеров используют Gateway API как основной способ конфигурации.

**Недостатки:**

- **Сложность настройки:** Требуется глубокое понимание работы Envoy.
- **Ресурсоемкость:** В сложных конфигурациях может потреблять больше CPU и памяти.

#### Istio Ingress Gateway

Стандартный компонент Service Mesh Istio для обработки входящего трафика.

- **Основа:** Envoy.
- **Философия:** Полная интеграция с Service Mesh.

**Особенности и преимущества:**

- **Единая конфигурация:** Управление трафиком через одни и те же CRD (`Gateway`, `VirtualService`).
- **Продвинутая безопасность:** Автоматическая mTLS-аутентификация, JWT-валидация.
- **Глубокая наблюдаемость:** Трассировка и метрики интегрированы с остальной частью сервисной сетки.

**Недостатки:**

- **Избыточность без Service Mesh:** Устанавливать Istio только ради Ingress-контроллера нецелесообразно.

#### Cilium Ingress Controller

Часть экосистемы Cilium, использующая технологию eBPF.

- **Основа:** Envoy (для L7), eBPF (для L3/L4).
- **Философия:** Производительность и безопасность через eBPF.

**Особенности и преимущества:**

- **Высокая производительность:** eBPF обрабатывает пакеты в ядре Linux, снижая задержки.
- **Интеграция с политиками безопасности:** Глубокая интеграция с CiliumNetworkPolicy.
- **Замена kube-proxy:** Может полностью заменить стандартный механизм проксирования Kubernetes.

**Недостатки:**

- **Требования к ядру Linux:** Требуется свежая версия ядра.

#### Kong

Контроллер на базе популярного API Gateway.

- **Основа:** NGINX с модулями на Lua (OpenResty).
- **Философия:** Расширяемость через плагины, фокус на управлении API.

**Особенности и преимущества:**

- **Архитектура плагинов:** Огромное количество плагинов для аутентификации, безопасности и управления трафиком.
- **Функциональность API Gateway:** Предоставляет расширенные возможности управления API.

**Недостатки:**

- **Сложность:** Требует понимания архитектуры Kong.
- **Зависимость от БД:** В некоторых режимах может требоваться внешняя база данных (PostgreSQL).

#### HAProxy

Один из самых надежных и производительных прокси-серверов.

- **Основа:** HAProxy (написан на C).
- **Философия:** Максимальная производительность и надежность.

**Особенности и преимущества:**

- **Экстремальная производительность:** Способен обрабатывать огромные объемы трафика при низком потреблении ресурсов.
- **Надежность:** Проверенное десятилетиями решение.
- **Гибкие проверки состояния:** Настраиваемые проверки работоспособности бэкендов.

**Недостатки:**

- **Ограниченная экосистема:** Меньше готовых плагинов по сравнению с Kong или Traefik.

## Практические сценарии

### Сценарий 1 — стартап или малая команда

**Требования:** Быстрый старт, минимальные операционные затраты, автоматический SSL.

**Рекомендация: Traefik**

- Простая настройка через CRD
- Автоматический Let's Encrypt
- Встроенный интерфейс для отладки

### Сценарий 2 — высоконагруженная система

**Требования:** Максимальная производительность, зеркалирование трафика.

**Рекомендация: Решения на базе Envoy (Cilium) или HAProxy**

- HAProxy — для экстремальных нагрузок без требований к Service Mesh
- Cilium — при использовании eBPF для сети

### Сценарий 3 — архитектура, ориентированная на API

**Требования:** Управление API, аутентификация, ограничение частоты запросов.

**Рекомендация: Kong**

- Готовые плагины для OAuth2, JWT
- Функциональность API Gateway "из коробки"

### Сценарий 4 — использование Service Mesh

**Требования:** Единое управление трафиком, mTLS, трассировка.

**Рекомендация: Istio Ingress Gateway**

- Единая конфигурация через политики меша
- Глубокая наблюдаемость
