# HA кластер Kubernetes: Требования к среде

## Определения

**HA кластер (High Availability)** — отказоустойчивая конфигурация Kubernetes с избыточностью узлов Control Plane (обычно 3, 5 или более), обеспечивающая непрерывную доступность API-сервера и сохранность данных при выходе из строя отдельных серверов.

**Control Plane** — «мозг» кластера, включающий `kube-apiserver`, `etcd`, `kube-controller-manager` и `kube-scheduler`.

**Кворум etcd** — минимальное количество работоспособных узлов в кластере `etcd`, необходимое для принятия решений и записи данных. Рассчитывается как `(n/2) + 1`.

**VIP (Virtual IP)** — плавающий IP-адрес, обеспечивающий единую точку входа для API-сервера. Переключается между мастерами с помощью протоколов VRRP (Keepalived) или BGP (Kube-vip).

## Основные концепции

### Аппаратные требования

#### Control Plane узлы (мастеры)

| Ресурс | Минимум | Рекомендация (Production) | Техническое обоснование |
| :--- | :--- | :--- | :--- |
| **CPU** | 2 ядра | 4–8 ядер | Обработка API-запросов и работа etcd. |
| **RAM** | 4 ГБ | 8–16 ГБ | Кэширование данных etcd и стабильность API. |
| **Disk** | 40 ГБ SSD | 100 ГБ+ NVMe SSD | **Критично:** etcd требует низкой задержки (fsync < 10ms). |
| **Network** | 1 Гбит/с | 10 Гбит/с | Минимизация джиттера и задержек репликации etcd. |

**Количество узлов**: Строго нечётное (3, 5) для обеспечения кворума.

#### Worker узлы

| Ресурс | Минимум | Рекомендация | Примечание |
| :--- | :--- | :--- | :--- |
| **CPU** | 2 ядра | 4+ ядра | Масштабируется в зависимости от нагрузки. |
| **RAM** | 4 ГБ | 16–64 ГБ | Зависит от требований запускаемых приложений. |
| **Disk** | 40 ГБ | 100 ГБ+ (SSD/NVMe) | Под хранение образов и эфемерных данных. |

#### Дисковая подсистема etcd (Критический фактор)

Для стабильности HA-кластера задержка `fdatasync` диска на мастер-узлах должна быть стабильно **менее 10 мс**.
- **Рекомендуется**: Локальные NVMe SSD.
- **Запрещено**: Сетевые диски (NFS, iSCSI, Ceph RBD) для раздела с данными etcd из-за высокого джиттера задержек.

## Практические сценарии

### Программные требования

#### Матрица совместимости ОС

| ОС | Версия | Статус |
| :--- | :--- | :--- |
| **Ubuntu** | 22.04 LTS, 24.04 LTS | Основная платформа (рекомендуется) |
| **Debian** | 11, 12 | Полная поддержка |
| **RHEL / Rocky / Alma** | 8.x, 9.x | Рекомендуется для Enterprise сред |

**Требования к ядру и среде**:
- Ядро Linux: 5.4+ (рекомендуется 6.x для лучшей поддержки eBPF/Cilium).
- Менеджер ресурсов: `systemd` (использование cgroups v2 обязательно для K8s 1.25+).
- Рантайм: `containerd` 1.6+ (совместим с K8s v1.35).

### Сетевое планирование

#### Порты Control Plane (Обязательно к открытию)

| Порт | Протокол | Назначение |
| :--- | :--- | :--- |
| 6443 | TCP | Kubernetes API Server (входящий для всех) |
| 2379-2380 | TCP | etcd client & peering (только между мастерами) |
| 10250 | TCP | Kubelet API (входящий от API-сервера) |
| 10257 | TCP | kube-controller-manager (healthz) |
| 10259 | TCP | kube-scheduler (healthz) |

#### Порты балансировщика (Keepalived/HAProxy)

| Порт | Протокол | Назначение |
| :--- | :--- | :--- |
| 6443 | TCP | Внешний порт VIP (проксирует на мастера) |
| 9000 | TCP | Статистика HAProxy (опционально) |
| VRRP | Protocol 112 | Сигнализация Keepalived (внутри L2 сегмента) |

#### Планирование CIDR (Подсети)

1.  **Node Network**: Физические IP серверов.
2.  **Pod Network**: Например, `10.244.0.0/16`. Не должна пересекаться с Node Network.
3.  **Service Network**: Например, `10.96.0.0/12`. Виртуальные IP внутри кластера.
4.  **MTU**: При использовании инкапсуляции (VXLAN) MTU интерфейсов подов должен быть на 50 байт меньше физического (например, 1450 при стандартном 1500).

## Дополнительная информация

### Предварительная готовность инфраструктуры

- **Синхронизация времени**: `chrony` или `ntp` обязательны. Разница более 500мс между мастерами разрывает кворум etcd.
- **DNS**: Узлы должны резолвить имена друг друга. Рекомендуется прописать статические записи в `/etc/hosts` в качестве fallback.
- **SSH**: Доступ по ключам с правами `sudo` на все узлы для инструментов автоматизации (kubeadm, ansible).

### Freshness и актуальность (v1.35+)

- **Kubernetes**: v1.35 (актуально на 2026 год).
- **containerd**: v1.7.x / v2.0 (поддержка CDI и WASM).
- **Cilium**: v1.16+ (предпочтительный CNI для Bare Metal с BGP).
