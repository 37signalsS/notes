# Быстрый старт с kind

`kind` — это инструмент для запуска локальных кластеров Kubernetes с использованием Docker-контейнеров в качестве узлов кластера. Это чрезвычайно удобный способ для тестирования приложений и изучения Kubernetes без необходимости в полноценных виртуальных машинах.

## Основные принципы

*   **Каждый узел — это Docker-контейнер:** `kind` запускает `kubelet` и другие компоненты внутри контейнеров.
*   **Быстрое создание и удаление:** Кластеры создаются и уничтожаются за считанные минуты.
*   **Поддержка Multi-node:** Позволяет имитировать более реалистичные сценарии с несколькими рабочими узлами.

## Установка

Инструкции по установке можно найти на [официальном сайте](https://kind.sigs.k8s.io/docs/user/quick-start/#installation).

## Команды

### 1. Создание простого кластера

Самый быстрый способ запустить кластер с одним управляющим узлом (control-plane):

```bash
kind create cluster
```

### 2. Создание кластера из конфигурационного файла

Для более сложных настроек, таких как создание кластера с несколькими узлами или проброс портов, используется конфигурационный файл.

**Пример `kind-config.yaml` для кластера с 1 control-plane и 2 worker-нодами:**

В данном примере также показано, как пробросить порт `80` с хост-машины на порт `30950` NodePort-сервиса внутри кластера.

```yaml
# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
  # Проброс портов с хоста в этот узел (control-plane)
  extraPortMappings:
  - containerPort: 30950 # Порт, который будет слушать сервис типа NodePort
    hostPort: 80       # Порт на хост-машине (localhost)
    protocol: TCP
- role: worker
- role: worker
```

**Команда для создания кластера с использованием конфига:**

```bash
kind create cluster --name multi-node --config kind-config.yaml
```

### 3. Просмотр кластеров

```bash
kind get clusters
```

### 4. Удаление кластера

```bash
# Удалить кластер по имени
kind delete cluster --name multi-node

# Удалить кластер по умолчанию (если имя не было задано)
kind delete cluster
```

### 5. Загрузка Docker-образов в кластер

Поскольку кластер работает в Docker, он не имеет прямого доступа к локально собранным образам на хост-машине. Чтобы использовать локальный образ, его нужно сначала загрузить в кластер:

```bash
kind load docker-image my-app:latest --name multi-node
```
