# Локальный кластер Kubernetes с помощью Talos

## 1. Определения

* **Talos** — это современная, безопасная и минималистичная ОС для запуска [Kubernetes](../../Kubernetes/kubernetes_overview.md). Она управляется исключительно через API, что исключает необходимость в SSH и обеспечивает предсказуемость конфигурации.
* **`talosctl`** — утилита командной строки для взаимодействия с Talos. Позволяет быстро разворачивать локальные кластеры, используя [Docker](../../Docker/docker_overview.md) для запуска узлов, что представляет собой простую и эффективную альтернативу таким инструментам, как [kind](../Installation/kind_quickstart.md) или [minikube](https://minikube.sigs.k8s.io/docs/).
* **[kubeconfig](../../Kubernetes/Operations/kubeconfig_and_connection.md)**: YAML-файл, который используется утилитой `kubectl` и другими клиентами для подключения к кластеру Kubernetes.
* **[kubectl](../../Kubernetes/kubernetes_overview.md)**: Основной инструмент командной строки для взаимодействия с API-сервером Kubernetes и управления объектами кластера.

## 2. Основные концепции

Ключевая идея Talos — это предоставление иммутабельной и полностью API-управляемой платформы для [Kubernetes](../../Kubernetes/kubernetes_overview.md). При локальном развертывании с помощью `talosctl` эта концепция реализуется следующим образом:

* **Узлы как контейнеры:** Каждый узел кластера ([control-plane](../../Kubernetes/Concepts/control_plane_architecture.md) и [worker](../../Kubernetes/Concepts/control_plane_architecture.md)) запускается как отдельный [Docker-контейнер](../../Docker/docker_overview.md).
* **Автоматическая конфигурация:** После создания кластера `talosctl` автоматически обновляет файлы `~/.kube/config` ([kubeconfig](../../Kubernetes/Operations/kubeconfig_and_connection.md)) и `~/.talos/config`, обеспечивая немедленную готовность к работе как с [kubectl](../../Kubernetes/kubernetes_overview.md), так и с самим `talosctl`.
* **API-First:** Все взаимодействие с ОС узла происходит через gRPC API, а не через SSH, что повышает безопасность и автоматизируемость.

## 3. Практические сценарии

### 3.1. Подготовка к работе

#### Предварительные требования

1. **[Docker](../../Docker/docker_overview.md)**: Убедитесь, что у вас установлен Docker (версия 18.03+).
2. **`talosctl`**: Утилита командной строки для взаимодействия с Talos.

#### Установка `talosctl`

Установить `talosctl` можно с помощью скрипта:

```bash
curl -sL https://talos.dev/install | sh
```

Это скачает последнюю версию и переместит бинарный файл в текущую директорию. Рекомендуется переместить его в каталог, входящий в `$PATH`, например `/usr/local/bin`.

### 3.2. Создание и кастомизация кластера

```bash
# Создает кластер с 1 control-plane нодой и 1 worker нодой
talosctl cluster create --wait
```

* Команда автоматически скачает необходимый Docker-образ, создаст контейнеры для узлов и развернет в них кластер.
* Флаг `--wait` указывает команде дождаться полной готовности кластера.
* После успешного создания, `talosctl` автоматически обновит ваш `~/.kube/config` и `~/.talos/config`, чтобы вы могли сразу начать работу с кластером.

**Кастомизация кластера при создании:**

* **Имя кластера**:

    ```bash
    talosctl cluster create --name my-cluster
    ```

* **Количество worker-нод**:

    ```bash
    talosctl cluster create --workers 3
    ```

### 3.3. Взаимодействие с кластером через `kubectl`

После создания кластера конфигурация `kubectl` будет обновлена автоматически. Вы можете использовать `kubectl` как обычно:

```bash
# Проверить статус узлов
kubectl get nodes

# Развернуть тестовое приложение, например, nginx
kubectl run nginx --image=nginx:latest
kubectl expose pod nginx --port=80 --type=NodePort
```

### 3.4. Использование утилиты `talosctl`

#### Встроенный Dashboard

`talosctl` предоставляет встроенный веб-интерфейс для мониторинга состояния кластера в реальном времени.

```bash
talosctl dashboard
```

Эта команда запускает локальный веб-сервер и открывает в браузере дашборд, где отображаются нагрузка на CPU, использование памяти, диска, запущенные процессы и логи.

#### Просмотр ресурсов Talos

`talosctl` позволяет просматривать низкоуровневые ресурсы самого Talos.

```bash
# Показать запущенные сервисы (в пространстве имен Talos)
talosctl services

# Показать запущенные контейнеры (в пространстве имен k8s.io)
talosctl containers -k
```

### 3.5. Уничтожение кластера

Когда кластер больше не нужен, его можно легко удалить одной командой:

```bash
# talosctl cluster destroy --name <имя_кластера>
# Если имя не указано, будет удален кластер по умолчанию ('talos-default')
talosctl cluster destroy
```

Эта команда остановит и удалит все контейнеры Docker, связанные с кластером.
