# Kubespray: Развертывание HA-кластера

Индексный документ и обзор методов развертывания высокодоступного (High Availability) кластера Kubernetes с использованием Kubespray.

## Определения

**HA-кластер (High Availability)** — конфигурация Kubernetes с несколькими узлами управления (Control Plane), обычно 3 или 5, предназначенная для устранения единой точки отказа (SPoF). Она обеспечивает непрерывную работу API-сервера и etcd при выходе из строя одного или нескольких узлов.

**Control Plane HA** — архитектурный подход, при котором доступ к API-серверу осуществляется через балансировщик нагрузки (Load Balancer) или плавающий IP (VIP), распределяющий запросы между всеми мастерами.

**Kubespray HA** — набор встроенных Ansible-ролей и переменных, автоматизирующих настройку компонентов отказоустойчивости (Keepalived, HAProxy, kube-vip).

## Основные концепции

Kubespray поддерживает три основных метода обеспечения высокой доступности. Выбор метода зависит от инфраструктуры и требований к сетевой связности.

### Методы обеспечения отказоустойчивости

1.  **kube-vip (Рекомендуемый):**
    *   **Принцип:** Запускается как Static Pod на каждом мастере.
    *   **Функции:** Управляет плавающим IP (VIP) и выполняет роль L4-балансировщика.
    *   **Режимы:** L2 (ARP/Layer 2) — для локальных сетей; L3 (BGP) — для интеграции с маршрутизаторами.
    *   **Преимущества:** Cloud-native подход, отсутствие зависимости от системных демонов ОС.

2.  **Keepalived + HAProxy (Классический):**
    *   **Принцип:** Использует стандартные Linux-сервисы. Keepalived обеспечивает VIP через протокол VRRP, а HAProxy балансирует трафик на порт 6443.
    *   **Преимущества:** Проверенная временем стабильность в Enterprise-средах.
    *   **Особенности:** Требует настройки `ip_nonlocal_bind` в ядре ОС.

3.  **Локальный nginx-proxy:**
    *   **Принцип:** На каждом рабочем узле (Worker) запускается контейнер с Nginx, который проксирует запросы на список всех мастеров.
    *   **Особенности:** Не создает единую точку входа (VIP). Используется преимущественно в тестовых средах или при невозможности использования VIP/BGP.

### Сравнение методов

| Характеристика | kube-vip | Keepalived + HAProxy | nginx-proxy (local) |
| :--- | :--- | :--- | :--- |
| **Среда выполнения** | Kubernetes (Static Pods) | Systemd (Linux services) | Docker / Containerd |
| **Наличие VIP** | Да | Да | Нет |
| **Сложность настройки** | Низкая | Средняя | Низкая |
| **Рекомендация** | Production (Bare-metal) | Production (Legacy/Enterprise) | Dev / Test / Edge |

## Практические сценарии

### Алгоритм выбора метода HA

1.  **Есть возможность использовать плавающий IP в подсети мастеров?**
    *   Да → Используйте **kube-vip** (L2 режим).
    *   Нет → Переходите к пункту 2.
2.  **Есть поддержка BGP в сети?**
    *   Да → Используйте **kube-vip** (BGP режим).
    *   Нет → Используйте **nginx-proxy** (локальный прокси на воркерах).

> [!NOTE]
> При использовании любого метода HA критически важно иметь нечетное количество узлов в группе `etcd` (3 или 5) для обеспечения кворума.
