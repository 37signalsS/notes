# Kubespray: Offline установка — Шаг 1: Подготовка виртуальных серверов

## Определения

**Подготовка виртуальных машин (VM Preparation)** — процесс первичной настройки узлов перед развёртыванием Kubernetes, включающий выделение ресурсов, установку ОС, конфигурацию SSH и системных параметров ядра.

**k8s-ans-bootstrap** — вспомогательный Ansible-плейбук для автоматизации базовой подготовки узлов (отключение swap, настройка сетевых модулей, установка python3-apt и т.д.).

---

## Основные концепции

### Инфраструктура offline-кластера

Специфика offline-установки требует наличия выделенных узлов для локального реестра (Harbor) и шлюза управления (pc-inet). Детальное описание ролей и IP-адресации приведено в **[практических сценариях offline-установки](./offline_practical.md#инфраструктурный-план-кластера)**.

### Минимальная конфигурация виртуальных машин

Параметры ресурсов (CPU/RAM/SSD) для каждого узла должны соответствовать **[Инфраструктурному плану](./offline_practical.md#инфраструктурный-план-кластера)**. Использование SSD обязательно для стабильной работы `etcd`.

### Предварительные требования

Перед началом автоматизированной подготовки необходимо обеспечить:

1. **ОС Ubuntu 24.04 LTS** на всех узлах.
2. **Пользователь с правами sudo** без пароля (рекомендуется `admin`).
3. **SSH-доступ** по ключам с узла `master-1` (Ansible Control Node) ко всем остальным узлам.

---

## Практические сценарии

### Настройка SSH-доступа

Все операции по установке запускаются с `master-1`. Необходимо сгенерировать и распространить SSH-ключи на все узлы инфраструктуры.

**1. Генерация ключа на master-1:**

```bash
ssh-keygen -t rsa -b 4096 -N "" -f ~/.ssh/id_rsa
# → Generating public/private rsa key pair.
```

**2. Добавление ключа в ssh-agent:**

```bash
eval $(ssh-agent -s)
ssh-add ~/.ssh/id_rsa
# → Identity added: /home/admin/.ssh/id_rsa
```

**3. Копирование ключа на все узлы (согласно IP-плану):**

```bash
# Инфраструктурные узлы
ssh-copy-id admin@192.168.1.99   # pc-inet
ssh-copy-id admin@192.168.1.100  # harbor

# Узлы Kubernetes
ssh-copy-id admin@192.168.1.101  # master-1 (self)
ssh-copy-id admin@192.168.1.102  # master-2
ssh-copy-id admin@192.168.1.103  # master-3
ssh-copy-id admin@192.168.1.104  # node-1
ssh-copy-id admin@192.168.1.105  # node-2
```

### Автоматизация подготовки через k8s-ans-bootstrap

Для минимизации ручных операций используется плейбук, который приводит ОС к требованиям Kubernetes.

1. **Клонирование репозитория (выполняется на pc-inet):**

   ```bash
   git clone https://github.com/ZM56/k8s-ans-bootstrap.git
   # → Cloning into 'k8s-ans-bootstrap'...
   ```

2. **Запуск плейбука:**
   Перенесите директорию на `master-1` (если они разделены) и запустите:

   ```bash
   cd k8s-ans-bootstrap
   # Настройте inventory.ini, указав IP всех узлов из таблицы
   ansible-playbook -i inventory.ini play.yml -u admin -b
   # → PLAY RECAP ***************** master-1 : ok=15 changed=10 ...
   ```

### Обязательные ручные проверки

Несмотря на автоматизацию, проверьте критические параметры на любом из узлов:

**Проверка версии ОС:**
```bash
lsb_release -rs
# → 24.04
```

**Проверка статуса SWAP:**
```bash
swapon --show
# → (пусто или 0 записей)
```

**Проверка беспарольного sudo:**
```bash
ssh admin@192.168.1.102 "sudo whoami"
# → root
```

Подробный алгоритм глубокой настройки ОС доступен в **[SSoT: Подготовка узлов](../../HA_Cluster_Bare_Metal/k8s_ha_node_preparation.md)**.
