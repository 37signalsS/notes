# Kubespray: Offline установка — Определения

## Определения

**Offline-кластер (Air-gapped)** — кластер Kubernetes, развёртываемый в изолированной среде без доступа к интернету. Требует предварительной подготовки всех зависимостей и их физического переноса в закрытую сеть.

**Закрытый контур** — изолированная сетевая инфраструктура без прямого доступа к публичному интернету. Требует наличия локальных зеркал (Harbor, репозитории ОС) для работы приложений и инфраструктуры.

**Открытый контур** — сетевой сегмент с доступом к интернету, используемый в качестве «точки сбора» для предварительной загрузки артефактов и формирования бандлов установки.

**Локальный кэш Kubespray** — промежуточное хранилище на узле с интернетом (pc-inet), используемое механизмом `download` для сохранения бинарных файлов и образов перед их упаковкой.

**Артефакты** — совокупность всех компонентов, необходимых для развёртывания: Python-зависимости, бинарные файлы Kubernetes, контейнерные образы и Helm-чарты.

Общие определения базовых технологий приведены в соответствующих основных разделах:

- **Kubespray** — инструмент автоматизации на базе Ansible (**[глоссарий Kubespray](../kubespray_install/definitions.md)**).
- **Harbor** — реестр образов (**[Harbor overview](../../../../Docker/Docker_registries/Harbor/overview.md)**).
- **CNI (Cilium)** — сетевой плагин (**[CNI definitions](../../../Networking/Network/CNI/definitions.md)**).
- **MetalLB** — балансировщик нагрузки (**[MetalLB](../../../Networking/metallb.md)**).

## Основные концепции

### Архитектура offline-развёртывания

Процесс строится на разделении подготовки ресурсов и их применения. Узел `pc-inet` выступает мостом между интернетом и изолированной средой.

```text
┌─────────────────────────────────────────────────────────────┐
│                   Открытый контур (INET)                    │
│  ┌─────────────┐                                            │
│  │   pc-inet   │ ──┐ Загрузка артефактов:                  │
│  │ 192.168.1.99│   │ - Python зависимости                  │
│  └─────────────┘   │ - Образы контейнеров                  │
│        │           │ - Helm чарты                          │
│        ▼           │ - Бинарные файлы (kubeadm, helm)      │
│  ┌─────────────────┴─────────────────────────────────────┐  │
│  │        /opt/kubespray-cache/                          │  │
│  │        /opt/kubespray-releases/                       │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                          │
                          │ Перенос архивов (SCP/USB/Veeam)
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Закрытый контур (NO INET)                 │
│  ┌─────────────┐     ┌─────────────────────────────────┐    │
│  │ Harbor      │     │  master-1-k8s (Ansible control) │    │
│  │192.168.1.100│◄────┤  192.168.1.101                  │    │
│  │  - k8s/*    │     │  - Kubespray inventory          │    │
│  │  - helm/*   │     │  - group_vars                   │    │
│  └─────────────┘     └──────────┬──────────────────────┘    │
│                                 │                            │
│              ┌──────────────────┼──────────────────┐         │
│              ▼                  ▼                  ▼         │
│       master-2,3           node-1,2        MetalLB VIP       │
│      192.168.1.102-103   192.168.1.104-105   192.168.1.200   │
└─────────────────────────────────────────────────────────────┘
```

### Версии компонентов (базовый гайд)

Для обеспечения совместимости в рамках данного руководства используются следующие версии:

| Компонент | Версия |
| :--- | :--- |
| Kubespray | v2.29.1 |
| Kubernetes | v1.34.3 |
| Cilium | v1.18.5 |
| MetalLB | v0.13.9 |
| Ingress-nginx | v1.13.3 |
| Helm | 3.18.4 |

> **Важно:** При использовании других версий обязательно проверяйте матрицу совместимости в файле `roles/download/defaults/main.yml` репозитория Kubespray.

## Практические сценарии

### Роли узлов и распределение задач

- **pc-inet:** выполняет загрузку артефактов и упаковку архивов.
- **master-1-k8s:** управляющий узел (Ansible Control Node), с которого запускается установка.
- **Harbor:** обеспечивает хранение образов и чартов в закрытом контуре.
- **Control Plane / Workers:** целевые узлы кластера.

Детальное распределение ролей приведено в **[практических сценариях offline-установки](./offline_practical.md#инфраструктура)**.
