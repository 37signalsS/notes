## Основные концепции

### Принципы offline-развёртывания

Основная концепция offline-установки заключается в полном разрыве зависимости целевых узлов от внешних ресурсов. Все данные, которые обычно загружаются «на лету» (из Docker Hub, GitHub, Google Registry), должны быть доставлены в закрытый контур заранее.

#### Ключевые отличия от online-установки

| Аспект | Online | Offline |
| :--- | :--- | :--- |
| **Доступ к интернету** | Требуется на всех узлах | Не требуется |
| **Загрузка образов** | Динамически из публичных реестров | Предварительная загрузка в локальный Harbor |
| **Python зависимости** | Установка через `pip` при запуске | Перенос готового `venv` или бандла зависимостей |
| **Helm чарты** | Прямая загрузка через `helm pull` | Размещение в локальном OCI-реестре |
| **Подготовка** | Минимальная (inventory + vars) | Значительная (загрузка и тегирование ~20 образов) |

#### Этапы offline-установки

1. **Этап 1: Сбор артефактов (Открытый контур).** Клонирование репозитория, загрузка Python-библиотек, системных бинарных файлов и образов контейнеров на машину с интернетом.
2. **Этап 2: Подготовка инфраструктуры (Закрытый контур).** Развёртывание локального реестра (Harbor), импорт и тегирование образов, настройка локальных репозиториев ОС.
3. **Этап 3: Развёртывание кластера.** Запуск Ansible-плейбуков с перенаправлением всех запросов на локальные ресурсы.

### Технологический стек

#### Container Runtime: containerd vs CRI-O

Для offline-установки в данном руководстве выбран **containerd** по следующим причинам:

- **Нативность:** является runtime по умолчанию в современных версиях Kubespray.
- **Стабильность:** механизмы кэширования и импорта образов для containerd лучше отлажены в Ansible-ролях.
- **Минимум зависимостей:** требует меньше системных пакетов по сравнению с CRI-O.

#### CNI плагин: Cilium

Cilium выбран как современное решение на базе eBPF, заменяющее устаревший `kube-proxy`.

**Требуемые параметры конфигурации:**

```yaml
kube_network_plugin: cilium
cilium_version: "1.18.5"
cilium_kube_proxy_replacement: true
cilium_tunnel_mode: geneve  # Рекомендуется для виртуальных сред (VMware/Proxmox)
cilium_mtu: "1450"
```

#### Балансировщик нагрузки: MetalLB

Обеспечивает работу сервисов типа `LoadBalancer` в bare-metal средах без облачного провайдера. Настраивается через переменную `metallb_enabled: true`.

## Дополнительная информация

### Справочник переменных Kubespray для offline-режима

#### Глобальные настройки кэширования

Файл: `group_vars/all/offline.yml`

```yaml
---
download_run_once: true           # Загрузка артефактов один раз на управляющий узел
download_localhost: true          # Сохранение кэша на локальной машине (pc-inet)
download_keep_remote_cache: true  # Сохранение временных файлов для ускорения повторных запусков
download_force_cache: true        # Принудительное использование кэша при отсутствии сети
download_cache_dir: /opt/kubespray-cache  # Путь к локальному хранилищу
```

#### Переопределение реестров (Harbor)

Файл: `group_vars/all/offline.yml`

```yaml
registry_host: "harbor.domain.local"
kube_image_repo: "{{ registry_host }}/k8s/registry.k8s.io"
gcr_image_repo: "{{ registry_host }}/k8s/gcr.io"
docker_image_repo: "{{ registry_host }}/k8s/docker.io"
quay_image_repo: "{{ registry_host }}/k8s/quay.io"

# Настройка Cilium для работы с локальным OCI-реестром
cilium_install_extra_flags: "--repository oci://{{registry_host}}/helm/cilium"
```

#### Авторизация в приватном реестре

Файл: `group_vars/all/containerd.yml`

```yaml
containerd_registry_auth:
  - registry: harbor.domain.local
    prefix: harbor.domain.local
    username: admin
    password: <password_ot_harbor>
```

> **Важно:** Для упрощения развёртывания системный проект `k8s` в Harbor рекомендуется делать **публичным**, чтобы избежать ошибок авторизации containerd на этапе инициализации узлов.

### Отключение проверки Digest

При переносе образов через `docker save/load` и последующем push в Harbor, оригинальный digest образа может измениться. Для корректной установки Cilium необходимо отключить проверку digest в файле `group_vars/k8s_cluster/k8s-net-cilium.yml` (см. детальный пример в разделе **[Troubleshooting](./troubleshooting.md#проблема-cilium-image-с-sha-digest)**).
