# Kubespray: Установка — Основные концепции

## Определения

**Машина управления (Control Node)** — узел (физический сервер, виртуальная машина или контейнер), с которого инициируется процесс развертывания через Ansible. Требует наличия Python 3.10+, установленного Ansible и SSH-доступа к целевым узлам по ключам.

**Целевые узлы (Target Nodes)** — серверы, на которые развертываются компоненты Kubernetes. В рамках Kubespray узлы классифицируются по ролям:
- **Control Plane** — управление состоянием кластера (API, Scheduler, Controller Manager).
- **Worker** — запуск пользовательских контейнерных нагрузок.
- **etcd** — хранение данных кластера (могут быть совмещены с Control Plane или выделены на отдельные узлы для повышения производительности).

**Основные термины Kubespray** — детальное описание Inventory, Group vars и плейбуков доступно в разделе **[Определения](./definitions.md)**.

## Основные концепции

### Логика работы

Kubespray является высокоуровневой автоматизированной оберткой над инструментом [kubeadm](../kubeadm/index.md), дополняя его возможностями по настройке ОС, сети и хранилищ. Основные принципы:

1. **Идемпотентность:** плейбуки спроектированы так, что их повторный запуск приводит систему к целевому состоянию без нежелательных побочных эффектов.
2. **Декларативность:** вся целевая конфигурация кластера (версии компонентов, параметры CNI, runtime) описывается в YAML-файлах `group_vars`.
3. **Модульность:** гибкий выбор компонентов (Container Runtime, сетевые плагины, DNS-решения) путем переопределения переменных.

### Архитектурные требования

- **Сетевая связность:** машина управления должна иметь устойчивый SSH-доступ ко всем узлам кластера.
- **Привилегии:** выполнение задач на целевых узлах требует прав `root` или корректно настроенного `sudo` (рекомендуется `NOPASSWD`).
- **Cgroups v2:** современные версии Kubespray и Kubernetes ориентированы на полную поддержку Cgroup v2, что является стандартом для актуальных дистрибутивов Linux.
- **Соответствие версий:** версии Kubespray, Ansible и Kubernetes связаны. Актуальные требования зафиксированы в `requirements.txt` репозитория.

## Практические сценарии

### Требования к инфраструктуре

#### Узлы кластера (Target Nodes)

| Параметр | Требование |
| :--- | :--- |
| **ОС** | Ubuntu (22.04, 24.04), Debian (11, 12), Rocky Linux (8, 9), AlmaLinux (8, 9) |
| **Память** | Минимум 2 ГБ RAM (для Control Plane рекомендуется 4 ГБ+) |
| **Ядра** | Минимум 2 vCPU |
| **Сеть** | IPv4 (поддержка Dual-stack), отключенный Firewall или открытые порты согласно документации |
| **Безопасность** | SELinux в режиме `permissive` (для RHEL-подобных), **обязательно** отключенный SWAP |

#### Машина управления (Control Node)

- **Python 3.10+** и менеджер пакетов `pip`.
- **Ansible 2.14+** (зависит от версии Kubespray).
- **Git** для управления конфигурациями и версионирования.
- **SSH-ключи:** публичная часть должна быть предварительно размещена на всех узлах (например, через `ssh-copy-id`).

### Подготовка узлов

Хотя Kubespray автоматизирует многие аспекты, базовая подготовка инфраструктуры критична для стабильности. Рекомендуется следовать руководству **[Подготовка узлов](../../HA_Cluster_Bare_Metal/k8s_ha_node_preparation.md)**.

Основные системные требования:
1. **Модули ядра:** должны быть загружены модули `overlay` и `br_netfilter` для корректной работы Container Runtime и CNI.
2. **Параметры sysctl:** настройка `net.bridge.bridge-nf-call-iptables = 1` и `net.ipv4.ip_forward = 1`.
3. **Container Runtime:** по умолчанию устанавливается **containerd**, требующий предварительной настройки параметров ядра.

### Алгоритм развертывания

Процесс установки включает следующие этапы:

1. **Подготовка инфраструктуры:** развертывание серверов, настройка сети и SSH-доступа.
2. **Подготовка окружения:** клонирование репозитория Kubespray и установка зависимостей из `requirements.txt`.
3. **Конфигурация инвентаря:** копирование шаблона `inventory/sample` и генерация `hosts.yaml` (рекомендуется использовать `inventory.py`).
4. **Настройка переменных:** определение параметров кластера в каталоге `group_vars` (сеть, версии, аддоны).
5. **Запуск развертывания:** выполнение команды `ansible-playbook -i inventory/my_cluster/hosts.yaml cluster.yml`.
6. **Валидация:** проверка состояния узлов (`kubectl get nodes`) и системных подов.

Подробные инструкции по командам и примеры конфигураций приведены в **[Практических сценариях](./practical_scenarios.md)**.
