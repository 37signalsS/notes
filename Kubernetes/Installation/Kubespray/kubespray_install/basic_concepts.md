# Kubespray: Установка — Основные концепции

## Определения

**Машина управления (Control Node)** — узел (физический сервер или виртуальная машина), с которого запускается процесс установки через Ansible. Требует наличия Python, Ansible и SSH-ключей.

**Целевые узлы (Target Nodes)** — серверы, на которые будет развернут Kubernetes. Делятся на роли: Control Plane (мастер-узлы), Worker (рабочие узлы) и etcd (хранилище).

**Основные термины Kubespray** — детальное описание Inventory, Group vars и Плейбуков доступно в разделе **[Определения](./definitions.md)**.

## Основные концепции

### Логика работы

Kubespray выступает в роли автоматизированной обертки над [kubeadm](../kubeadm/index.md). Основные принципы:

1. **Идемпотентность:** плейбуки можно запускать многократно для достижения или проверки желаемого состояния кластера.
2. **Декларативность:** конфигурация кластера (версии, CNI, плагины) описывается в YAML-файлах `group_vars`.
3. **Модульность:** возможность выбора компонентов (Runtime, сетевые плагины, DNS) через изменение переменных без изменения кода плейбуков.

### Архитектурные требования

- **Сетевая связность:** машина управления должна иметь SSH-доступ ко всем узлам кластера.
- **Привилегии:** выполнение задач на целевых узлах требует прав `root` или возможности выполнения `sudo` без пароля.
- **Соответствие версий:** версия Kubespray жестко привязана к поддерживаемым версиям Kubernetes и Ansible. Проверка совместимости — в `requirements.txt` и `roles/download/defaults/main.yml`.

## Практические сценарии

### Требования к инфраструктуре

#### Узлы кластера (Target Nodes)

| Параметр | Требование |
| :--- | :--- |
| **ОС** | Ubuntu, CentOS, Rocky Linux, Debian, AlmaLinux |
| **Память** | Минимум 2 ГБ RAM (для Control Plane рекомендуется 4 ГБ+) |
| **Ядра** | Минимум 2 CPU |
| **Сеть** | Отключенный Firewall (или открытые [порты Kubespray](https://kubespray.io/#/docs/ports)) |
| **Безопасность** | SELinux в режиме `permissive` или `disabled`, отключенный SWAP |

#### Машина управления (Control Node)

- **Python 3.9+** и менеджер пакетов `pip`.
- **Git** для клонирования репозитория.
- **SSH-ключ** (публичная часть должна быть распространена на все целевые узлы).

### Подготовка узлов

Большинство системных настроек (модули ядра, sysctl) Kubespray выполняет автоматически. Однако для стабильной работы и предотвращения конфликтов рекомендуется выполнить базовую подготовку вручную согласно **[SSoT: Подготовка узлов](../../HA_Cluster_Bare_Metal/k8s_ha_node_preparation.md)**.

Основные шаги включают:

1. **Отключение SWAP** (обязательно для kubelet).
2. **Отключение Firewall и настройка SELinux** (предотвращение блокировок трафика и доступа к ресурсам).
3. **Загрузка сетевых модулей** (`br_netfilter`, `overlay`).

### Алгоритм развертывания

Процесс установки разделен на логические этапы:

1. **Подготовка инфраструктуры:** создание ВМ/серверов и настройка SSH.
2. **Установка окружения:** клонирование Kubespray и установка Python-зависимостей.
3. **Создание Inventory:** генерация списка хостов и распределение ролей.
4. **Настройка переменных:** выбор параметров кластера в `group_vars`.
5. **Запуск плейбука:** выполнение `ansible-playbook cluster.yml`.
6. **Валидация:** проверка работоспособности подов и доступности API.

Подробные инструкции по командам приведены в **[Практических сценариях](./practical_scenarios.md)**.
