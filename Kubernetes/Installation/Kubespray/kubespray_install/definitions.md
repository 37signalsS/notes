# Kubespray: Установка — Определения

## Определения

**Kubespray** — инструмент для автоматизации развертывания и управления жизненным циклом кластеров Kubernetes на базе Ansible. Полное описание — в [обзоре Kubespray](../overview.md).

**Inventory (Инвентарь)** — конфигурационный файл (обычно в формате YAML или INI), описывающий узлы кластера, их IP-адреса и распределение по ролям. В современных версиях рекомендуется использовать `hosts.yaml`.

**Group vars (Групповые переменные)** — иерархия YAML-файлов в директории `group_vars/` (например, `all/all.yml`, `k8s_cluster/k8s-cluster.yml`), определяющая параметры установки: версии компонентов, сетевые плагины, настройки облачных провайдеров.

**Container Runtime (CRI)** — среда выполнения контейнеров. В Kubespray по умолчанию используется **containerd**. Для диагностики состояния контейнеров и подов на узлах используется утилита `crictl`.

**Kubeadm** — базовый инструмент Kubernetes, который Kubespray использует для инициализации компонентов кластера, управления сертификатами и настройки статических подов Control Plane.

**Плейбуки Kubespray** — набор Ansible-сценариев для управления кластером:

- `cluster.yml` — полная установка кластера.
- `scale.yml` — добавление новых узлов в существующий кластер.
- `upgrade-cluster.yml` — обновление версии Kubernetes.
- `remove-node.yml` — вывод узла из эксплуатации.
- `reset.yml` — полная очистка узлов от компонентов Kubernetes (сброс состояния).

**Control Plane** — плоскость управления кластером. Подробное описание архитектуры — в [Архитектура Control Plane](../../../Concepts/control_plane_architecture.md).

**Worker Node** — узлы для запуска пользовательских нагрузок. Обзор компонентов узла — в [обзоре Kubernetes](../../../kubernetes_overview.md).

**etcd** — распределенное хранилище состояния кластера. Подробности — в [Обзор etcd](../../../Concepts/etcd_overview.md).

**CNI (Container Network Interface)** — стандарт интерфейса для настройки сети между подами. Реализация в Kubespray и взаимодействие с компонентами — в [Роли CNI и kube-proxy](../../../Networking/Network/cni_kube_proxy_roles.md).

**kubeconfig** — файл с параметрами аутентификации для доступа к API Kubernetes (в Kubespray по умолчанию может быть скопирован в `inventory/<cluster_name>/artifacts/admin.conf`).

---

## Основные концепции

Термины, описанные выше, формируют логическую модель установки Kubespray:

1. **Inventory** связывает физические/виртуальные серверы с логическими ролями (Control Plane, Worker, etcd).
2. **Group vars** определяют, как именно будут настроены эти роли и какие компоненты (CNI, Runtime) будут установлены.
3. **Плейбуки** последовательно применяют конфигурацию к узлам, используя `kubeadm` и другие инструменты автоматизации.

## Практические сценарии

Определения находят применение в следующих задачах:

- **Подготовка инвентаря:** создание файла `hosts.yaml` на основе шаблона `inventory/sample`.
- **Кастомизация:** редактирование `group_vars/k8s_cluster/k8s-cluster.yml` для выбора сетевого плагина (например, Calico или Cilium).
- **Развертывание:** запуск `ansible-playbook -i inventory/my_cluster/hosts.yml cluster.yml`.
- **Диагностика:** использование `crictl pods` и `crictl ps` на узлах после завершения установки.
