# Kubespray: Установка — Дополнительная информация

## Определения

**Артефакты установки (Artifacts)** — файлы конфигурации, сертификаты и ключи доступа, генерируемые или копируемые Kubespray в процессе развертывания. Хранятся локально на машине управления для обеспечения административного доступа к кластеру.

**kubeconfig_localhost** — параметр в `group_vars`, который при значении `true` инициирует автоматическое копирование файла административного доступа (`admin.conf`) в директорию инвентаря на машине управления.

**Credentials** — директория в составе артефактов (обычно `inventory/<cluster_name>/credentials`), содержащая сгенерированные сертификаты (CA, etcd, kubelet) и пароли, если они создавались плейбуком.

**CRI (Container Network Interface)** — в контексте Kubespray это runtime-среда (обычно **containerd**), через которую Kubernetes управляет жизненным циклом контейнеров.

## Основные концепции

### Результаты установки

После успешного завершения работы плейбука `cluster.yml`:

1. **Функциональный кластер:** все компоненты Control Plane и Worker узлов развернуты, настроены и связаны через выбранный CNI-плагин.
2. **Административный доступ:** файл `admin.conf` (kubeconfig) содержит необходимые сертификаты и адрес API-сервера для управления кластером через `kubectl`.
3. **Состояние компонентов:** компоненты Kubernetes (kube-apiserver, etcd, kubelet) работают в режиме высокой доступности (если настроено) под управлением `containerd`.

### Методы управления

- **Локальный (на узлах):** использование `kubectl` непосредственно на Control Plane узлах. Конфигурация по умолчанию находится в `/etc/kubernetes/admin.conf`.
- **Удаленный (с Control Node):** использование скопированного артефакта `admin.conf`. Требует сетевой доступности внешнего IP или DNS-имени API-сервера.

## Практические сценарии

### Проверка работоспособности

Для верификации кластера рекомендуется выполнить комплекс тестов, описанных в руководстве **[Проверка работоспособности кластера](../../HA_Cluster_Bare_Metal/k8s_ha_cluster_verification.md)**.

Базовые проверки:
1. **Статус узлов:** `kubectl get nodes -o wide` (все узлы должны быть в статусе `Ready`).
2. **Системные поды:** `kubectl get pods -n kube-system` (все поды, включая Calico/Cilium и CoreDNS, должны быть `Running`).
3. **Сетевая связность:** проверка доступности сервисов и DNS внутри кластера.

### Использование административного конфига

Если включено копирование артефактов, файл доступа доступен по пути:
`inventory/my_cluster/artifacts/admin.conf`

Пример использования:
```bash
# Проверка доступа без изменения системных переменных
kubectl --kubeconfig=inventory/my_cluster/artifacts/admin.conf cluster-info
```

Более подробно о работе с контекстами и аутентификацией — в **[Kubeconfig и подключение](../../Operations/kubeconfig_and_connection.md)**.

### Низкоуровневая диагностика (crictl)

Поскольку Kubespray устанавливает `containerd` без Docker, для работы с контейнерами на уровне ОС используется `crictl`.

| Задача | Команда |
| :--- | :--- |
| Список контейнеров | `sudo crictl ps -a` |
| Состояние подов | `sudo crictl pods` |
| Просмотр логов | `sudo crictl logs <container_id>` |
| Инспекция образа | `sudo crictl inspecti <image_id>` |

Типовые ошибки среды выполнения и способы их решения разобраны в разделе **[Диагностика Runtime](../../Troubleshooting/Common_Errors/NodeUnavailability/runtime_issues.md)**.
