# RKE: Основные концепции

> [!WARNING]
> **RKE1 достигает конца жизненного цикла (EOL) 31 июля 2025 года.** 
> Основное внимание Rancher Labs переключено на **RKE2**. Рекомендуется планировать миграцию.

## Определения

**RKE (Rancher Kubernetes Engine)** — Docker-ориентированный дистрибутив Kubernetes. Все компоненты (kubelet, apiserver, etcd и др.) запускаются как Docker-контейнеры.

**RKE2 (RKE Government)** — следующее поколение RKE. Основные отличия: отсутствие зависимости от Docker (использует containerd), фокус на безопасности (FIPS, CIS hardening) и запуск компонентов через статические поды (аналогично kubeadm).

## Базовые концепции

### Отличия RKE от kubeadm и RKE2

| Аспект | RKE (RKE1) | RKE2 | kubeadm |
| :--- | :--- | :--- | :--- |
| **Среда выполнения** | Docker | containerd | Любой CRI (обычно containerd) |
| **Развертывание** | RKE CLI (`rke up`) | Binary/Script (systemd) | `kubeadm init/join` |
| **Архитектура** | Контейнеры Docker | Статические поды | Статические поды |
| **Безопасность** | Стандартная | Hardened по умолчанию | Требует ручной настройки |
| **Поддержка** | EOL (Июль 2025) | Активная | Активная |

### Типы дистрибутивов Rancher

* **RKE2** — основной дистрибутив для production. Поддерживает запуск в "воздушном зазоре" (air-gap) и соответствует строгим стандартам безопасности.
* **K3s** — сверхлегкий дистрибутив (один бинарный файл < 100MB). Идеален для edge-вычислений, CI/CD и разработки.

### Сетевые плагины (CNI)

* **Canal (Flannel + Calico)** — стандартный выбор для RKE. Сочетает простоту Flannel и политики безопасности Calico.
* **Calico** — рекомендуется для сложных топологий и использования BGP.
* **Cilium** — современный выбор для RKE2, использующий eBPF для высокой производительности и глубокого мониторинга сети.

### Особенности узлов RKE

* **Роли узлов:** Узел может иметь одну или несколько ролей: `etcd`, `controlplane`, `worker`. 
* **Кворум etcd:** Для отказоустойчивости требуется нечетное количество узлов с ролью `etcd` (минимум 3).
* **Ingress:** По умолчанию устанавливается `nginx-ingress-controller` как DaemonSet на worker-узлах.

## Практические сценарии

### Выбор метода управления

| Метод | Использование | Когда выбирать |
| :--- | :--- | :--- |
| **Rancher UI** | Веб-интерфейс | Ежедневное управление, мониторинг, мультикластерность |
| **RKE CLI** | Инструмент командной строки | Первоначальное создание, автоматизация, восстановление |
| **Terraform** | Провайдер `rancher2` | Полное описание инфраструктуры как кода |

## Дополнительная информация

### Жизненный цикл и миграция

В связи с EOL RKE1, пользователям рекомендуется переходить на RKE2. Прямого обновления "на месте" (in-place) не существует из-за смены Docker на containerd.
**Стратегия миграции:**
1. Развертывание нового кластера RKE2.
2. Перенос нагрузок (Workloads) с помощью GitOps (ArgoCD/Flux) или Rancher Backup/Restore.
