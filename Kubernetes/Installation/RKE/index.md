# RKE (Rancher Kubernetes Engine)

> [!WARNING]
> **RKE1 достигает конца жизненного цикла (EOL) 31 июля 2025 года.** 
> После этой даты поддержка и обновления безопасности прекратятся. Для всех новых проектов рекомендуется использовать **RKE2**. Подробности в разделе [RKE2 документация](https://docs.rke2.io/).

## Определения

**RKE (Rancher Kubernetes Engine)** — сертифицированный дистрибутив Kubernetes от Rancher Labs, предназначенный для развертывания production-кластеров на bare-metal серверах и виртуальных машинах. Полностью запускается внутри Docker-контейнеров.

**Rancher** — платформа для управления несколькими Kubernetes-кластерами (RKE, RKE2, K3s, EKS, GKE), предоставляющая централизованный интерфейс для управления доступом (RBAC), мониторинга и эксплуатации.

## Базовые концепции

### Архитектурные особенности

* **Docker-based:** RKE1 использует Docker как среду выполнения контейнеров для всех компонентов Kubernetes (control plane, worker, etcd).
* **Декларативность:** Конфигурация кластера описывается в одном YAML-файле (`cluster.yml`).
* **Idempotency:** Запуск `rke up` приводит текущее состояние кластера в соответствие с конфигурацией.

Подробное описание архитектуры, отличий от других дистрибутивов и типов сетевых плагинов (CNI) вынесено в документ: **[RKE: Основные концепции](./rke_concepts.md)**.

## Практические сценарии

### Методы развертывания

1. **Через Rancher UI:** Самый простой способ с визуальным управлением. Инструкции: [RKE в Rancher](../../Rancher/rancher_rke.md).
2. **Через RKE CLI:** Рекомендуется для автоматизации и инфраструктуры как кода (IaC). Подробности: **[RKE: Управление и поиск неисправностей](./rke_management_scenarios.md#управление-кластером-через-rke-cli)**.

### Настройка доступа (kubectl)

Для взаимодействия с кластером необходимо установить `kubectl` и получить файл конфигурации `kubeconfig`. Пошаговое руководство: **[RKE: Установка kubectl и настройка доступа](./rke_kubectl_setup.md)**.

### Эксплуатация и Troubleshooting

* **Ротация сертификатов:** Автоматическая через Rancher или вручную через CLI.
* **Резервное копирование etcd:** Настройка снимков в S3 или локально.
* **Диагностика:** Специфические для RKE методы поиска неисправностей описаны в: **[RKE: Поиск и устранение неисправностей](./rke_management_scenarios.md#поиск-и-устранение-неисправностей-специфика-rke)**.

## Дополнительная информация

### Рекомендации по безопасности

* **Права доступа:** Ограничивайте права на файл `kubeconfig` (`chmod 600`).
* **Минимальные привилегии:** Используйте ServiceAccounts вместо глобальных конфигов администратора.
* **Узлы управления:** Изолируйте Control Plane узлы от пользовательских нагрузок с помощью taints.
