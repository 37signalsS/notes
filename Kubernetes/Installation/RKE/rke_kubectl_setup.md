# RKE: Установка kubectl и настройка доступа

## Определения

**kubectl** — стандартный интерфейс командной строки для взаимодействия с API-сервером Kubernetes. Позволяет создавать, просматривать и удалять ресурсы внутри кластера.

**kubeconfig** — файл (обычно `~/.kube/config`), содержащий данные для аутентификации на одном или нескольких кластерах. RKE автоматически генерирует этот файл при завершении установки.

**Контекст (Context)** — элемент конфигурации, объединяющий параметры кластера, пользователя и пространство имен. Позволяет быстро переключаться между разными окружениями (dev, prod).

**kube_config_cluster.yml** — файл конфигурации доступа, создаваемый утилитой RKE CLI в текущей директории после выполнения команды `rke up`.

## Базовые концепции

### Взаимодействие с RKE

Для полноценного управления кластером RKE необходимо обеспечить связку между локальной машиной администратора и API-сервером кластера (порт 6443). Основные этапы:
1. **Установка клиента:** Наличие бинарного файла `kubectl`, версия которого должна отличаться от версии кластера не более чем на одну минорную версию (правило +/-1).
2. **Получение данных доступа:** Извлечение сертификатов и адресов из Rancher UI или из локальных файлов после работы RKE CLI.
3. **Изоляция конфигурации:** Настройка прав доступа к файлам конфигов для предотвращения кражи токенов и ключей.

Подробная информация о структуре YAML-конфигурации доступна в разделе **[Kubeconfig: Подключение к кластеру Kubernetes](../../Operations/kubeconfig_and_connection.md)**.

## Практические сценарии

### Шаг 1: Установка kubectl

Для установки `kubectl` используйте официальное руководство, соответствующее вашей операционной системе:
**[Инструкция по установке kubectl](../kubectl_installation.md)**

### Шаг 2: Получение конфигурации

#### Метод А: Через RKE CLI (Автономный кластер)
После успешного выполнения команды `rke up`, в той же директории создается файл `kube_config_cluster.yml`. Это ваш основной административный доступ.

```bash
# Проверка наличия файла
ls -l kube_config_cluster.yml

# Использование файла напрямую без перемещения в ~/.kube
kubectl --kubeconfig kube_config_cluster.yml get nodes
```

#### Метод Б: Через Rancher UI (Управляемый кластер)
Если кластер импортирован или создан через Rancher:
1. Перейдите в **Cluster Management**.
2. Выберите ваш кластер.
3. Нажмите кнопку **Kubeconfig File** в верхней части панели.
4. Скопируйте содержимое или скачайте файл.

### Шаг 3: Настройка локального окружения

Рекомендуется объединять конфигурации в стандартный путь для удобства работы.

```bash
# Создание структуры директорий
mkdir -p $HOME/.kube

# Если у вас еще нет основного конфига:
cp kube_config_cluster.yml $HOME/.kube/config

# Установка жестких прав доступа (обязательно!)
chmod 600 $HOME/.kube/config
```

**Использование переменной окружения для временного доступа:**
Если вы работаете с несколькими файлами одновременно:
```bash
export KUBECONFIG=~/.kube/config:~/projects/rke-prod/kube_config_cluster.yml
kubectl config view --flatten > ~/.kube/merged_config
mv ~/.kube/merged_config ~/.kube/config
```

### Шаг 4: Проверка связи и совместимости

```bash
# Проверка версии клиента и сервера
kubectl version --short
# → Client Version: v1.30.0
# → Server Version: v1.28.10 (RKE1 обычно отстает от upstream)

# Проверка базовой работоспособности
kubectl get nodes -o wide
# → node-01  Ready  controlplane,etcd,worker  10d  v1.28.10  192.168.1.10
```

## Дополнительная информация

### Устранение неисправностей при подключении

* **Ошибка: "Unable to connect to the server: x509: certificate has expired"**
  Указывает на то, что сертификаты кластера RKE истекли. Необходимо выполнить ротацию через RKE CLI: `rke cert rotate`.
* **Ошибка: "connection refused"**
  Проверьте доступность порта 6443 на узлах с ролью `controlplane`. Если кластер за NAT, убедитесь, что в `cluster.yml` указан корректный `public_address`.
* **Ошибка: "unauthorized"**
  Возможно, файл `kubeconfig` устарел или был перегенерирован с другими ключами (например, после `rke up` с изменениями в CA).

### Рекомендации по безопасности

* **Контексты:** Всегда проверяйте текущий контекст перед выполнением деструктивных команд (`kubectl config current-context`).
* **Токены:** Избегайте хранения `kubeconfig` в git-репозиториях, даже приватных. Используйте менеджеры секретов.
