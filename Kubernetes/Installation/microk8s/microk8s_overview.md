# MicroK8s: обзор

## Определения

**MicroK8s** — сертифицированный CNCF легковесный дистрибутив Kubernetes от компании Canonical. Представляет собой полноценный upstream-кластер (zero-ops), упакованный в Snap-пакет с изолированными компонентами и встроенной системой аддонов. Идеально подходит для edge-вычислений, IoT и локальной разработки.

### Ключевые отличия

- **Упаковка:** Snap-пакет — каждый компонент работает как отдельный systemd-процесс со своими зависимостями.
- **Хранилище:** по умолчанию используется DQLite — встроенная распределённая БД на основе SQLite с алгоритмом Raft, исключающая необходимость в `etcd`.
- **Архитектура:** максимально близка к классическому K8s — отдельные процессы для apiserver, scheduler, controller-manager.
- **Сеть по умолчанию:** из коробки используется Calico CNI.

## Основные концепции

### Отказоустойчивость (High Availability)

MicroK8s автоматически включает режим высокой доступности (HA) при объединении **3 и более узлов**.
- Не требуется внешних балансировщиков или ручной настройки БД.
- Узлы динамически распределяют роли (Voter, Standby) для базы данных DQLite.
- Если один из Voter-узлов выходит из строя, Standby-узел автоматически повышается.

### Требования к ресурсам

| Ресурс | Минимум | Рекомендуется |
|:-------|:--------|:--------------|
| RAM | 2 ГБ | 4+ ГБ |
| CPU | 2 ядра | 4+ ядра |

Из-за оверхеда Snap и раздельных процессов пустой кластер потребляет 2–4 ГБ RAM. На устройствах с 1–2 ГБ RAM (например, Raspberry Pi) предпочтителен K3s.

### Система аддонов

MicroK8s предоставляет встроенную систему управления аддонами — не требуется искать и применять манифесты вручную. Аддоны разделены на официальные (`core`) и поддерживаемые сообществом (`community`).

```bash
# Включение стандартных компонентов
microk8s enable dns
microk8s enable ingress
microk8s enable hostpath-storage

# Просмотр доступных аддонов
microk8s status
```

### Сравнение с K3s

| Параметр | MicroK8s | K3s |
|:---------|:---------|:----|
| Размер | Snap-пакет (сотни МБ) | Один бинарник <100 МБ |
| RAM (idle) | 2–4 ГБ | ~512 МБ |
| Хранилище | DQLite | SQLite (Kine) |
| Процессы | Раздельные systemd | Единый процесс |
| Система аддонов | Встроенная (`microk8s enable`) | Нет (auto-deploy dir) |
| Разработчик | Canonical | SUSE / Rancher |

## Практические сценарии

### Установка и настройка

```bash
# Установка через snap
sudo snap install microk8s --classic

# Добавление пользователя в группу для работы без sudo
sudo usermod -a -G microk8s $USER
newgrp microk8s

# Создание алиаса для удобства
snap alias microk8s.kubectl kubectl
```

### Базовое управление

```bash
# Статус кластера и аддонов
microk8s status

# Запуск и остановка кластера (экономия ресурсов)
microk8s stop
microk8s start

# Диагностика состояния
microk8s inspect

# Просмотр конфигурации для внешнего доступа
microk8s config > ~/.kube/config
```

### Создание кластера из нескольких узлов (HA)

```bash
# На первой ноде (мастере): генерация токена
microk8s add-node
# → result: выведет команду для подключения, например: microk8s join 10.0.0.1:25000/<token>

# На второй и последующих нодах: подключение
microk8s join 10.0.0.1:25000/<token>
```
*Примечание: При добавлении третьего узла кластер автоматически переходит в режим HA.*
