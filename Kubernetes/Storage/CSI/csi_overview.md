# Обзор Container Storage Interface (CSI)

## Определения

**Container Storage Interface (CSI)** — это открытый стандарт, который определяет универсальный API (Application Programming Interface) для взаимодействия систем оркестрации контейнеров (таких как Kubernetes) с СХД (системами хранения данных).

Основная цель CSI — стандартизировать подключение систем хранения к контейнерам, что позволяет разработчикам легко интегрировать различные решения для управления данными.

**Ключевые задачи, решаемые CSI:**

- Динамическое выделение и удаление томов хранения.
- Монтирование и отмонтирование томов к подам.
- Создание снапшотов (Volume Snapshots) и клонирование томов.
- Расширение томов (Volume Expansion) — онлайн и офлайн.
- Управление жизненным циклом томов с учётом топологии (Topology Aware).

> **Продвинутые возможности:** [CSI Advanced Features](./csi_advanced.md)

## Базовые концепции

### Проблемы до-CSI (In-Tree плагины)

До появления CSI вся логика для работы с различными СХД (например, AWS EBS, GCE PD, Ceph) была встроена непосредственно в код Kubernetes. Это создавало ряд проблем:

- **Медленное развитие:** Добавление поддержки новой СХД требовало внесения изменений в основную кодовую базу Kubernetes и было привязано к его циклам релиза.
- **Раздувание кодовой базы:** Код Kubernetes содержал большое количество специфичных драйверов для разных вендоров.
- **Сложность поддержки:** Исправление ошибок или добавление функционала в одном драйвере требовало обновления всего кластера.

CSI решил эти проблемы, полностью отделив логику работы с хранилищами от Kubernetes, перейдя к модели **Out-of-Tree** плагинов (плагинов вне основного кода).

### Архитектура CSI-драйвера

CSI-драйвер для конкретной СХД обычно состоит из двух основных компонентов, которые развертываются в кластере как отдельные поды:

1. **Controller Plugin**
    - **Описание:** Централизованный компонент, который обычно работает как `Deployment` или `StatefulSet` с одной репликой. Он отвечает за высокоуровневые операции по управлению томами.
    - **Функции:**
        - Создание и удаление томов (`CreateVolume`, `DeleteVolume`).
        - Подключение и отключение томов к узлам (`ControllerPublishVolume`, `ControllerUnpublishVolume`).
        - Создание снапшотов и клонирование.
        - Изменение размера томов.
    - **Взаимодействие:** Напрямую с API системы хранения данных.

2. **Node Plugin**
    - **Описание:** Этот компонент работает на **каждом узле** кластера в виде `DaemonSet`. Он отвечает за низкоуровневые операции на конкретном узле.
    - **Функции:**
        - Монтирование (`NodeStageVolume`, `NodePublishVolume`) и размонтирование тома.
        - Форматирование файловой системы.
    - **Взаимодействие:** `kubelet` на каждом узле взаимодействует с Node Plugin через локальный сокет.

### Преимущества использования CSI

Переход на CSI-драйверы предоставляет значительно более широкие возможности по сравнению со старыми встроенными плагинами:

- **Динамическое создание томов:** Автоматическое создание PV (PersistentVolume) по запросу через `StorageClass`.
- **Создание снапшотов (Snapshots):** Возможность создавать "снимки" состояния томов для резервного копирования.
- **Клонирование томов:** Создание новых томов, являющихся точной копией существующих через PVC (PersistentVolumeClaim).
- **Изменение размера томов (Resize):** Увеличение размера PersistentVolume "на лету" (online expansion).
- **Сбор метрик:** Предоставление метрик для мониторинга производительности и использования хранилища.
- **Поддержка топологии (Topology Aware):** Планировщик учитывает физическое расположение данных (например, AZ — зоны доступности) при размещении подов.

## Практические сценарии

### Ceph CSI

В качестве примера можно рассмотреть распределенную систему хранения данных [Ceph](https://ceph.io/en/). Драйвер **Ceph CSI** предоставляет доступ к двум типам хранилищ:

1. **RBD (RADOS Block Device)**
    - **Тип:** Блочное устройство.
    - **Режим доступа:** `ReadWriteOnce` (RWO).
    - **Аналогия:** Виртуальный жесткий диск, используемый одним подом.
    - **Применение:** Базы данных, Stateful-приложения.
    - **См. также:** [Настройка Ceph CSI для RBD](../Ceph/ceph_csi_rbd_driver_setup.md).

2. **CephFS (Ceph File System)**
    - **Тип:** Распределенная файловая система, совместимая с POSIX (Portable Operating System Interface).
    - **Режим доступа:** `ReadWriteMany` (RWX).
    - **Аналогия:** Общая сетевая папка, доступная нескольким подам одновременно.
    - **Применение:** Общие данные для веб-серверов, CMS.
    - **См. также:** [Настройка CSI для CephFS](../Ceph/ceph_csi_cephfs_driver_setup.md).

> **Пример использования со снапшотами:** [CSI Advanced Features](./csi_advanced.md#ceph-rbd-с-снапшотами-volume-snapshots-для-postgresql)

### Драйвер Secrets Store CSI

Этот драйвер используется для безопасного управления секретами.

- **Задача:** Монтировать секреты из внешних хранилищ (например, HashiCorp Vault) напрямую в файловую систему пода как тома.
- **Преимущества:**
  - **Централизованное управление:** Секреты хранятся во внешнем KMS (Key Management Service).
  - **Безопасность:** Секреты не сохраняются в `etcd` в открытом виде.

> **Подробно:** [Драйвер Secrets Store CSI — сравнение и примеры](./csi_drivers_comparison.md#драйвер-secrets-store-csi)
