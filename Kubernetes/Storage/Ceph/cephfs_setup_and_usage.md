# Настройка и использование CephFS

## Определения

*   **CephFS**: POSIX-совместимая файловая система, построенная поверх объектного хранилища Ceph (RADOS). Она позволяет монтировать себя одновременно на множество клиентов, предоставляя одновременный доступ на чтение и запись, и функционирует как общая сетевая папка.

## Основные концепции

*   **Архитектура**: CephFS требует как минимум один Metadata Server (MDS) для управления метаданными файлов. Данные и метаданные хранятся в отдельных пулах RADOS. Для более глубокого понимания архитектуры Ceph и ее компонентов, включая CephFS, обратитесь к [Обзору Ceph](ceph_overview.md).
*   **Особенности использования пространства**:
    *   **Видимый размер**: При монтировании CephFS часто отображается размер, равный общей доступной емкости кластера, деленной на фактор репликации. Например, для кластера 30 ГБ с `size=3` будет видно ~9-10 ГБ свободного места.
    *   **Общее пространство**: Пространство в кластере Ceph является общим для всех сервисов (RBD, CephFS). Если вы записываете данные в RBD-образ, свободное место, видимое в CephFS, также будет уменьшаться.
*   **Модель прав доступа**: Для разделения прав доступа в CephFS используются каталоги. Вы можете создать пользователя и предоставить ему доступ только к определенному каталогу внутри файловой системы, изолируя его от остальной части ФС.
*   **Требования к пулам**: При ручной установке CephFS необходимо сначала создать пулы для данных и метаданных, а затем саму файловую систему.

## Практические сценарии: Настройка и монтирование

### 1. Создание файловой системы CephFS (при ручной установке)

Если вы устанавливали Ceph вручную (а не через `ceph-ansible`), вам необходимо сначала создать пулы для данных и метаданных, а затем саму файловую систему.

1.  **Создание пулов:**
    ```bash
    # Пул для данных
    ceph osd pool create cephfs_data 32

    # Пул для метаданных
    ceph osd pool create cephfs_metadata 32
    ```
    *`32` — это количество Placement Group (PG). Это значение следует подбирать в соответствии с размером вашего кластера. См. [Расчет количества Placement Group (PG) в Ceph](ceph_placement_groups.md).*

2.  **Создание файловой системы:**
    ```bash
    ceph fs new cephfs cephfs_metadata cephfs_data
    ```
    Эта команда создает новую файловую систему с именем `cephfs`, используя ранее созданные пулы.

3.  **Проверка созданной файловой системы:**
    ```bash
    ceph fs ls
    ```
    Вывод покажет имя файловой системы и используемые ею пулы.

### 2. Создание пользователя Ceph и подготовка каталога

Для разделения прав доступа в CephFS используются каталоги. Вы можете создать пользователя и предоставить ему доступ только к определенному каталогу внутри файловой системы.

1.  **Создание пользователя:**
    Следующая команда создает пользователя `fs_user` и предоставляет ему полный доступ (`rwp`) к каталогу `/data_pes` в пулах данных (`cephfs_data`) и метаданных.
    ```bash
    ceph auth get-or-or-create client.fs_user mon 'allow r' mds 'allow r, allow rw path=/data_pes' osd 'allow rw pool=cephfs_data'
    ```
    *   `mon 'allow r'`: Разрешает пользователю подключаться к мониторам.
    *   `mds 'allow r, allow rw path=/data_pes'`: Разрешает чтение и запись только в пределах каталога `/data_pes`.
    *   `osd 'allow rw pool=cephfs_data'`: Разрешает чтение и запись в пул данных.

2.  **Получение ключа пользователя:**
    После создания команда вернет имя пользователя (`client.fs_user`) и его ключ, который понадобится для монтирования.

3.  **Подготовка каталога (монтирование от имени администратора):**
    Так как мы предоставили пользователю права на каталог `/data_pes`, этот каталог нужно сначала создать. Для этого необходимо смонтировать корневой каталог (`/`) файловой системы CephFS от имени администратора (`admin`).

    1.  **Создание точки монтирования:**
        ```bash
        sudo mkdir -p /mnt/cephfs
        ```
    2.  **Монтирование корня CephFS:**
        ```bash
        # Получаем ключ администратора
        ADMIN_SECRET=$(sudo ceph auth get-key client.admin)

        # Монтируем
        sudo mount -t ceph 172.21.0.10:6789:/ /mnt/cephfs -o name=admin,secret=$ADMIN_SECRET
        ```
        *   `172.21.0.10:6789:/`: IP-адрес и порт одного из мониторов, за которым следует двоеточие и путь (`/` для корня). Можно перечислить несколько мониторов через запятую.
        *   `-o name=admin,secret=$ADMIN_SECRET`: Указывает имя пользователя и его ключ.

    3.  **Создание каталога для пользователя:**
        ```bash
        sudo mkdir /mnt/cephfs/data_pes
        ```
    4.  **Размонтирование:**
        ```bash
        sudo umount /mnt/cephfs
        ```

### 3. Монтирование CephFS на клиенте

#### 3.1. Ручное монтирование от имени пользователя

Теперь клиент может смонтировать выделенный ему каталог.

1.  **Создание точки монтирования на клиенте:**
    ```bash
    sudo mkdir -p /mnt/shared_fs
    ```

2.  **Получение ключа пользователя (если нужно):**
    Если вы потеряли ключ, его можно снова получить на узле с правами администратора:
    ```bash
    sudo ceph auth get-key client.fs_user
    ```

3.  **Монтирование каталога пользователя:**
    ```bash
    # Ключ, полученный на предыдущем шаге
    USER_SECRET="AQB..."

    # Монтируем, указывая конкретный путь в CephFS
    sudo mount -t ceph 172.21.0.10:6789:/data_pes /mnt/shared_fs -o name=fs_user,secret=$USER_SECRET
    ```
    *   Обратите внимание, что после адреса монитора теперь указан путь `/data_pes`. Пользователь `fs_user` не сможет смонтировать корень (`/`), так как у него нет на это прав.

4.  **Проверка:**
    Теперь в каталоге `/mnt/shared_fs` можно создавать и изменять файлы. Этот же каталог можно смонтировать на множестве других серверов, и все они будут видеть одни и те же данные в реальном времени.

#### 3.2. Автоматическое монтирование CephFS (fstab)

Чтобы файловая система CephFS монтировалась автоматически при загрузке сервера, необходимо добавить соответствующую запись в `/etc/fstab`.

1.  **Создание файла с секретным ключом:**
    Вместо того чтобы указывать ключ прямо в `fstab`, что небезопасно, лучше сохранить его в отдельный файл.
    ```bash
    # Получаем ключ пользователя
    USER_SECRET=$(sudo ceph auth get-key client.fs_user)

    # Записываем ключ в файл и устанавливаем права
    echo $USER_SECRET | sudo tee /etc/ceph/fs_user.secret
    sudo chmod 600 /etc/ceph/fs_user.secret
    ```

2.  **Добавление записи в `/etc/fstab`:**
    Откройте `/etc/fstab` и добавьте следующую строку:

    ```
    # <device>                                     <mountpoint>    <filesystem_type> <options>                                            <dump> <pass>
    172.21.0.10,172.21.0.11,172.21.0.12:/data_pes   /mnt/shared_fs  ceph              name=fs_user,secretfile=/etc/ceph/fs_user.secret,_netdev,noatime   0      0
    ```

3.  **Разбор записи `fstab`:**
    *   **Device:** IP-адреса мониторов через запятую, затем двоеточие и путь к каталогу в CephFS (`/data_pes`).
    *   **Mountpoint:** Локальный каталог, куда монтируется система (`/mnt/shared_fs`).
    *   **Filesystem Type:** `ceph`.
    *   **Options:**
        *   `name=fs_user`: Имя пользователя для монтирования.
        *   `secretfile=/etc/ceph/fs_user.secret`: Путь к файлу с ключом. Это безопаснее, чем опция `secret=...`.
        *   `_netdev`: **Критически важная опция!** Она указывает системе, что это сетевое устройство и его следует монтировать только *после* полной активации сетевого стека. Без этой опции система может зависнуть при загрузке, пытаясь смонтировать сетевой диск до того, как появится сеть.
        *   `noatime`: Опционально, для повышения производительности (не обновлять время доступа к файлам).

## Дополнительная информация

*   **Важное замечание о пути в fstab:** Если в `fstab` в качестве устройства указать корень (`172.21.0.10:/`), то будет смонтирован корень файловой системы CephFS. Даже если у пользователя `fs_user` есть права только на подкаталог `/data_pes`, корень все равно смонтируется. Однако записать данные можно будет только в тот каталог, на который есть права. Чтобы избежать путаницы и потенциальных проблем, всегда указывайте в `fstab` тот путь, который действительно нужен пользователю.
*   **Расчет Placement Groups**: Для оптимальной производительности и распределения данных важно правильно рассчитать количество PG. Подробности см. в [Расчет количества Placement Group (PG) в Ceph](ceph_placement_groups.md).
