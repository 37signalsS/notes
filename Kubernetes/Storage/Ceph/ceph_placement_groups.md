# Расчет количества Placement Group (PG) в Ceph

## Определения

*   **Placement Group (PG)**: Логический контейнер для объектов, распределяемый по OSD.
*   **Эмпирическое правило для OSD**: 1 ГБ RAM на 1 ТБ дискового пространства.

## Основные концепции

Оптимальное количество PG критично для производительности и стабильности кластера Ceph. Необходим баланс между количеством PG на OSD и их размером:
*   **Много PG на OSD**: Требует больше оперативной памяти (RAM) для хранения информации о расположении PG.
*   **Мало PG на OSD**: Увеличивает размер каждой PG, замедляя ребалансировку из-за большего объема перемещаемых данных.

### Формула для расчета общего количества PG

Формула стремится к 100-300 PG на OSD (калькуляторы часто используют 100 как базовое значение):
`Total PGs = (Total number of OSDs * 100) / max_replication_factor`

### Распределение PG по пулам

Общее количество PG распределяется между пулами.

#### Проблема простого подхода (равномерного распределения)

Равномерное распределение не учитывает разный объем данных в пулах. Это приводит к неэффективному различию в размерах отдельных PG (например, в 10 раз) при неравномерной нагрузке на пулы.

#### Использование степеней двойки для PG

Для облегчения и ускорения ребалансировки рекомендуется устанавливать количество PG в пулах равным степеням двойки (например, 32, 64, 128, 256). При увеличении PG (например, с 32 до 64) Ceph делит каждую существующую PG пополам: половина данных остается, вторая переносится согласно карте CRUSH, что упрощает и ускоряет ребалансировку.

## Практические сценарии

### Пример расчета общего количества PG

Для кластера с 3 OSD и фактором репликации `3`:
`Total PGs = (3 * 100) / 3 = 100`
Рекомендуемое общее количество PG для кластера — около 100.

### Пример простого подхода (равномерного распределения)

При 3 пулах (`rbd`, `cephfs_data`, `cephfs_metadata`) и 100 общих PG, каждый пул получает примерно 33 PG (100 / 3).

### Рекомендуемый подход (пропорциональное распределение)

Распределение PG пропорционально **ожидаемому объему данных** в каждом пуле. Например, пулу, где ожидается 50% всех данных, выделяется 50% общих PG. Этот подход требует прогнозирования будущего использования дискового пространства.

### Динамическое изменение количества PG

Ceph позволяет динамически изменять количество PG в пуле:
*   **Увеличение**: При добавлении OSD можно увеличить общее количество PG в кластере, а затем увеличить их число в самых больших пулах.
*   **Уменьшение**: В последних версиях Ceph появилась возможность уменьшать количество PG при сокращении объема данных в пуле.

## Дополнительная информация

**Внимание**: Операция изменения количества PG **дорогостоящая**. Она вызывает ребалансировку данных, что создает высокую нагрузку на кластер и может снизить производительность. Злоупотреблять этой функцией не стоит.

Для общего понимания компонентов Ceph, включая PG, обратитесь к [Обзор Ceph](Kubernetes/Storage/Ceph/ceph_overview.md).
