# Администрирование Ceph

## 1. Проверка состояния кластера: Команда `ceph status`

Команда `ceph status` является ключевым инструментом для быстрого получения информации о здоровье и текущем состоянии всех компонентов кластера Ceph. Ее вывод содержит сводную информацию о мониторах, менеджерах, OSD, пулах и размещении групп.

```
$ ceph status

  cluster:
    id:     <cluster_id>
    health: HEALTH_OK

  services:
    mon: 3 daemons, quorum node1,node2,node3 (age 2m)
    mgr: ingress1(active, since 2m), standbys: node1, node2
    mds: cephfs:1 {0=ingress1=up:active} 2 up:standby
    osd: 3 osds: 3 up (since 2m), 3 in (since 2m)

  data:
    pools:   2 pools, 64 pgs
    objects: 0 objects, 0 B
    usage:   3.0 GiB used, 27 GiB / 30 GiB avail
    pgs:     64 active+clean
```

### 1.1. Анализ вывода команды

1.  **`cluster`**:
    *   **`id`**: Уникальный идентификатор кластера в шестнадцатеричном формате.
    *   **`health`**: Общее состояние кластера. `HEALTH_OK` — идеальное состояние, говорящее, что с кластером все в порядке. Другие состояния (например, `HEALTH_WARN`, `HEALTH_ERR`) указывают на проблемы.

2.  **`services`**:
    *   **`mon`**: Состояние демонов-мониторов. `3 daemons, quorum ...` означает, что все три монитора работают и достигли кворума, что необходимо для их корректной работы.
    *   **`mgr`**: Состояние демонов-менеджеров. Один менеджер всегда находится в состоянии `active`, остальные — в `standby`, готовые взять на себя управление в случае отказа активного.
    *   **`mds`**: Состояние серверов метаданных для CephFS. Аналогично менеджерам, один MDS активен, остальные в режиме ожидания. `cephfs:1` говорит о том, что для файловой системы `cephfs` активен один MDS.
    *   **`osd`**: Состояние демонов хранения. `3 osds: 3 up, 3 in` означает, что в кластере 3 OSD, все они запущены (`up`) и участвуют в распределении данных (`in`).

3.  **`data`**:
    *   **`pools`**: Сводка по пулам. `2 pools, 64 pgs` показывает, что в кластере 2 пула и 64 Placement Group (PG) в сумме. Подробнее о PG см. [Расчет количества Placement Group (PG) в Ceph](ceph_placement_groups.md).
    *   **`objects`**: Количество объектов, хранящихся в кластере. `0 objects, 0 B` в свежеустановленном кластере.
    *   **`usage`**: Использование дискового пространства.
        *   `3.0 GiB used`: Место, занятое служебными данными Ceph (например, для CephFS).
        *   `27 GiB / 30 GiB avail`: `30 GiB` — это общая "сырая" емкость всех OSD-дисков. `27 GiB` — доступное пространство.
        *   **Важно:** Доступное пространство — это не то же самое, что полезное пространство для записи. Из-за фактора репликации (по умолчанию `size=3`), запись 1 ГБ данных займет 3 ГБ на дисках. Таким образом, из 27 ГБ доступного пространства полезными для записи будут только 9 ГБ (27 / 3).
    *   **`pgs`**: Состояние Placement Group.
        *   `64 active+clean`: Идеальное состояние. Все 64 PG активны и "чисты" (все реплики в порядке).
        *   При проблемах (ребалансировка, восстановление) здесь будут отображаться другие состояния PG (например, `recovering`, `backfilling`, `degraded`).
