# Мониторинг и обслуживание Ceph

## Определения

**Мониторинг Ceph** — процесс непрерывного сбора и анализа метрик здоровья, производительности и утилизации ресурсов распределенного кластера.

**Обслуживание Ceph** — выполнение регламентных работ по проверке целостности данных, оптимизации их размещения и управлению правами доступа.

> **Базовые концепции и архитектура:** [Администрирование Ceph — Обзор](./index.md)

---

## Базовые концепции

### Источники и инструменты мониторинга

Ceph аккумулирует данные через **MGR (Manager)**, который предоставляет несколько интерфейсов доступа:

| Инструмент | Тип | Назначение |
|:-----------|:----|:-----------|
| **Prometheus Exporter** | Метрики | Сбор временных рядов (latency, IOPS, throughput) для Grafana. |
| **Ceph Dashboard** | GUI | Визуальный контроль здоровья, производительности и логов. |
| **Native CLI** | Команды | Оперативная диагностика и низкоуровневая проверка (`ceph status`). |
| **Orchestrator CLI** | Команды | Проверка статуса демонов на уровне контейнеров (`ceph orch ps`). |

### Механизмы самоочистки и проверки (Scrubbing)

Для предотвращения незаметной порчи данных (bit rot) Ceph использует два уровня проверки:
- **Scrub (Light Scrub)**: Ежедневная проверка метаданных объектов (размер, контрольные суммы на уровне ФС).
- **Deep Scrub**: Еженедельная побитовая проверка содержимого объектов и сравнение всех реплик.

## Практические сценарии

### Мониторинг использования пространства и лимитов

Превышение порогов заполнения дисков блокирует операции записи во всем кластере.

```bash
# Просмотр текущих порогов (Full Ratios)
ceph osd dump | grep -E "full_ratio|nearfull_ratio"

# Утилизация пространства по пулам
ceph df

# Поиск самых заполненных дисков (OSD)
ceph osd df | sort -nk 8 | tail
```

**Критические пороги по умолчанию:**
- **Nearfull (85%)**: Генерируется предупреждение `HEALTH_WARN`. Необходимо планировать расширение или очистку.
- **Backfillfull (90%)**: Остановка процесса перебалансировки данных на этот диск.
- **Full (95%)**: Кластер переходит в `HEALTH_ERR`, запись блокируется (IO error для клиентов).

### Диагностика производительности

Если клиенты жалуются на задержки, необходимо проанализировать производительность конкретных OSD.

```bash
# Задержки (Latency) на чтение/запись в реальном времени
ceph osd perf

# Статус дисковых устройств и предсказание отказов (Drive Life)
ceph device ls

# Проверка загруженности очередей (IOPS)
ceph osd pool stats
```

### Управление проверкой целостности (Scrubbing)

Иногда интенсивный `deep-scrub` может снижать производительность приложений. Его можно контролировать:

```bash
# Проверка текущего статуса проверок (какие PG сейчас проверяются)
ceph pg dump | grep scrub

# Временное отключение проверок (например, при аварии)
ceph osd set noscrub
ceph osd set nodeep-scrub

# Принудительный запуск проверки для конкретной группы
ceph pg deep-scrub <pg_id>
```

### Проверка здоровья демонов через Orchestrator

В современных кластерах (cephadm) статус процесса важен так же, как и статус данных.

```bash
# Список всех сервисов и их состояние (running/expected)
ceph orch ps

# Просмотр логов конкретного демона (например, osd.5)
ceph orch device ls --hostname <node_name>
ceph orch log <service_name>
```

### Управление доступом (`ceph auth`)

```bash
# Создание пользователя для Kubernetes с правами на конкретный пул
ceph auth get-or-create client.kubernetes \
  mon 'allow r' \
  osd 'allow rw pool=k8s_pool' \
  mgr 'allow r'

# Обновление прав существующего пользователя
ceph auth caps client.kubernetes mon 'allow r' osd 'allow rw pool=new_pool'
```

## Регламентное обслуживание

| Задача | Регулярность | Команда / Метод |
|:-------|:-------------|:----------------|
| **Проверка статуса** | Ежедневно | `ceph health detail` |
| **Анализ задержек** | Ежедневно | Grafana Dashboard / `ceph osd perf` |
| **Анализ Drive Health** | Еженедельно | `ceph device ls` |
| **Аудит авторизации** | Ежемесячно | `ceph auth list` |
| **Тестовое восстановление** | Ежеквартально | Проверка целостности бэкапов (не из снапшотов) |
