# CephFS: Продвинутые темы

## Определения

**Subtree Pinning (Привязка поддеревьев)** — механизм статического распределения нагрузки между несколькими активными MDS путем жесткого закрепления определенных директорий за конкретными рангами (Rank).

**Scrubbing (Фоновая очистка)** — процесс проверки целостности файловой системы, при котором MDS сверяет метаданные в памяти с объектами в RADOS и проверяет соответствие индексов реальным данным.

**LazyIO** — расширение POSIX, позволяющее приложениям осознанно обходить строгие гарантии когерентности кэша для повышения производительности при чтении/записи одного файла из множества узлов (используется в HPC).

**MDS Cache Memory Limit** — лимит оперативной памяти, которую MDS может использовать под кэш метаданных (inodes, dentries).

**Caps (Capabilities) Recall** — процесс, при котором MDS запрашивает у клиентов возврат выданных ранее прав (caps) на кэширование, когда MDS достигает лимита памяти или другой клиент запрашивает монопольный доступ.

## Основные концепции

### Многопользовательская балансировка MDS

В кластерах с `max_mds > 1` Ceph использует динамический балансировщик метаданных. Однако в высоконагруженных средах он может вызывать "миграционную тряску" (flickering).

*   **Динамическая балансировка**: MDS обмениваются фрагментами дерева каталогов на основе текущей нагрузки (CPU/Memory).
*   **Статическая привязка (Pinning)**: Администратор явно указывает, что `/home` обрабатывается `mds.0`, а `/data` — `mds.1`. Это исключает накладные расходы на миграцию метаданных.

### Иерархия кэширования метаданных

Кэширование происходит на двух уровнях:
1.  **MDS Side**: Кэширует всю структуру ФС. Размер регулируется `mds_cache_memory_limit`.
2.  **Client Side**: Кэширует только те части, к которым клиент обращался. Регулируется параметрами ядра (для Kernel) или `mdscache` (для FUSE).

### Messenger v2 и безопасность трафика

Messenger v2 (порт 3300) поддерживает три режима работы (`ms_mode`):
- `legacy`: Использование v1 (порт 6789).
- `crc`: Проверка целостности данных без шифрования (минимальные накладные расходы).
- `secure`: Полное шифрование AES-GCM трафика между клиентом и кластером.

## Практические сценарии

### 1. Тюнинг производительности MDS

#### Настройка лимитов кэша

Если MDS потребляет слишком много памяти или часто сбрасывает кэш, необходимо настроить лимиты.

```bash
# Установка лимита в 16 ГБ для конкретного MDS
ceph config set mds.a mds_cache_memory_limit 17179869184

# Настройка предупреждений при превышении (MDS_HEALTH_CACHE_OVER_LIMIT)
# По умолчанию предупреждение при 150% от лимита
ceph config set mds mds_health_cache_threshold 1.2
```

#### Статическая привязка поддеревьев (Subtree Pinning)

```bash
# Привязка каталога к рангу 0
setfattr -n ceph.dir.pin -v 0 /mnt/cephfs/high_load_dir

# Привязка к рангу 1
setfattr -n ceph.dir.pin -v 1 /mnt/cephfs/backup_dir

# Проверка распределения поддеревьев
ceph tell mds.0 dump tree | jq '.subtrees'
```

### 2. Обслуживание и проверка целостности (Scrubbing)

Scrubbing необходим для выявления "битых" метаданных.

```bash
# Запуск проверки конкретной директории (рекурсивно)
ceph tell mds.a scrub start /data_path recursive,repair

# Проверка статуса выполнения
ceph tell mds.a scrub status

# Принудительная очистка зависших сессий перед обслуживанием
ceph tell mds.a session evict id=12345
```

### 3. Оптимизация Kernel Client

Параметры модуля ядра `ceph` влияют на то, как клиент взаимодействует с MDS.

```bash
# Увеличение максимального количества Caps (предотвращает частые recall)
echo 16384 | sudo tee /sys/module/ceph/parameters/mds_max_caps_per_client

# Настройка времени ожидания ответа MDS
# По умолчанию 60 сек. Полезно увеличить для медленных сетей.
sudo mount -t ceph :/ /mnt/cephfs -o name=user,secretfile=...,mount_timeout=120
```

### 4. Использование LazyIO

Применяется для специфических баз данных или HPC-приложений, которые сами управляют блокировками.

```bash
# Монтирование с поддержкой LazyIO (только для FUSE или специализированных libcephfs клиентов)
ceph-fuse -m 192.168.1.10:6789 /mnt/lazy --lazyio
```
*Примечание: При использовании LazyIO приложение должно явно вызывать `fsync()` для синхронизации данных между узлами.*

### 5. Безопасность и TLS (Messenger v2)

```bash
# Включение принудительного шифрования на уровне всей ФС
ceph fs set mycephfs ms_mode secure

# Монтирование с проверкой режима на клиенте
sudo mount -t ceph 192.168.1.10:3300:/ /mnt/shared \
  -o name=admin,secretfile=...,ms_mode=secure
```

## Дополнительная информация

### Диагностика глубоких проблем

| Инструмент / Команда | Описание |
|----------------------|----------|
| `ceph daemon mds.a cache status` | Детальный отчет о содержимом кэша (inodes, caps). |
| `ceph tell mds.a ops` | Список текущих выполняемых операций (In-flight ops). |
| `ceph daemon mds.a objecter_requests` | Запросы от MDS к OSD (помогает найти затыки в RADOS). |
| `cat /sys/kernel/debug/ceph/<cluster_id>/caps` | (Kernel) Список всех выданных прав на данном клиенте. |

### Ограничения продвинутых функций

- **Subtree Pinning**: Привязка не переносится автоматически при изменении количества рангов (max_mds). Требует ручного пересмотра.
- **Scrubbing**: Создает существенную нагрузку на CPU MDS и I/O OSD. Рекомендуется запускать в часы минимальной нагрузки.
- **Messenger v2 Secure**: Потребляет до 10-20% ресурсов CPU на шифрование при высоких скоростях передачи (10GbE+).
