# CephFS: Определения и базовые концепции

## Определения

**CephFS** — POSIX-совместимая распределенная файловая система, построенная поверх объектного хранилища Ceph (RADOS). Поддерживает одновременный доступ на чтение/запись с множества клиентов.

**MDS** (Metadata Server) — демон для управления метаданными файлов (имена, права, атрибуты).

**Quota (Квота)** — ограничение на объем данных или количество файлов в каталоге.

**Snapshot (Снапшот)** — моментальная копия каталога или всей файловой системы.

## Основные концепции

### Архитектура CephFS

```
Клиенты → MDS (метаданные) → RADOS (данные + метаданные)
              ↓
        CephFS Metadata Pool
              ↓
        CephFS Data Pool
```

### Требования

| Компонент | Требование | Примечание |
|-----------|------------|------------|
| **MDS** | Минимум 1 | Для HA: 1 active + N standby |
| **Пулы** | 2 пула | Данные + метаданные |
| **Клиент** | Ядро 5.4+ или FUSE | Kernel модуль производительнее |

### Особенности использования пространства

- **Видимый размер**: При монтировании отображается размер = (емкость кластера / replication_factor)
- **Общее пространство**: RBD и CephFS используют общее хранилище
- **Квоты**: Можно устанавливать на отдельные каталоги

### Модель прав доступа

CephFS поддерживает детализированные права:

| Уровень | Описание |
|---------|----------|
| **Пул** | Доступ к пулу данных/метаданных |
| **Файловая система** | Доступ ко всей ФС |
| **Каталог** | Доступ к конкретному пути (path-based) |

### Протоколы доступа

| Протокол | Производительность | Сценарий |
|----------|-------------------|----------|
| **Kernel module** | Высокая | Production, Linux-клиенты |
| **FUSE** | Средняя | Тестирование, нестандартные ядра |
