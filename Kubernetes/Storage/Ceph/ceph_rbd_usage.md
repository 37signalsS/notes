# Подключение и работа с RBD-образами

## Определения

*   **RADOS Block Device (RBD)**: Блочное устройство, которое хранится в виде объектов в кластере Ceph. Позволяет предоставлять дисковое пространство (образы) клиентским машинам, аналогично физическим дискам.

## Основные концепции

Для использования RBD-образа на клиентской машине необходимо выполнить три основных шага:
1.  **Установить клиентское ПО Ceph (`ceph-common`)**: Оно предоставляет утилиты для взаимодействия с кластером. Рекомендуется использовать ту же версию, что и на серверах Ceph.
2.  **Настроить подключение**: Клиенту требуются конфигурационный файл (`/etc/ceph/ceph.conf`) с адресами мониторов кластера и ключ доступа (`/etc/ceph/ceph.client.<user>.keyring`).
3.  **Замапить (map) образ**: Процесс, при котором RBD-образ становится доступен в операционной системе клиента как стандартное блочное устройство (например, `/dev/rbd0`).

## Практические сценарии

### 1. Установка и настройка клиента

На клиентской машине выполните следующие действия:

1.  **Установите `ceph-common`**:
    ```bash
    # Пример для CentOS (замените `luminous` на актуальный релиз)
    sudo yum install -y centos-release-ceph-luminous
    sudo yum install -y ceph-common
    ```
2.  **Настройте `ceph.conf`**:
    Создайте файл `/etc/ceph/ceph.conf` с адресами мониторов.
    ```ini
    # /etc/ceph/ceph.conf
    [global]
    mon_host = 172.21.0.10,172.21.0.11,172.21.0.12
    ```
3.  **Добавьте `keyring`**:
    Поместите файл с ключом доступа в `/etc/ceph/`, например, `/etc/ceph/ceph.client.user.keyring`.

### 2. Маппинг и использование RBD-образа

1.  **Замапьте образ**:
    ```bash
    # rbd map <имя_образа> --pool <имя_пула> --id <имя_пользователя>
    sudo rbd map disk1 --pool kube --id user
    ```
    После этого в системе появится устройство, например `/dev/rbd0`.

2.  **Создайте и смонтируйте файловую систему**:
    ```bash
    # Создание ФС (только один раз для нового образа)
    sudo mkfs.ext4 /dev/rbd0

    # Монтирование
    sudo mkdir /mnt/rbd
    sudo mount /dev/rbd0 /mnt/rbd
    ```

3.  **Проверьте результат**:
    ```bash
    df -h
    ```
    Команда покажет смонтированное устройство.

### 3. Автоматическое монтирование

Для автоматического монтирования при загрузке системы сначала необходимо настроить автоматический маппинг образа (например, через `rbdmap.service`), а затем добавить запись для устройства (например, `/dev/rbd0`) в `/etc/fstab`, используя опцию `_netdev`. Подробный пример можно найти в разделе [Автоматическое монтирование CephFS](Kubernetes/Storage/Ceph/cephfs_setup_and_usage.md#5-автоматическое-монтирование-cephfs-fstab).

### 4. Устранение ошибок: `RBD image features set mismatch`

Эта ошибка означает, что ядро клиентской системы не поддерживает функции, включенные в образе.
Для исправления выполните на сервере с доступом к кластеру Ceph команду, предложенную в сообщении об ошибке:
```bash
# rbd feature disable <пул>/<образ> <функция1>,<функция2>,...
sudo rbd feature disable kube/disk1 layering,striping
```
После этого повторите команду `rbd map` на клиенте.
