# RBD: Определения и базовые концепции

## Определения

**RADOS Block Device (RBD)** — блочное устройство, хранящееся в виде объектов в кластере Ceph. Предоставляет дисковое пространство клиентским машинам как виртуальный диск (LUN).

**Image (Образ)** — основной объект RBD, виртуальный диск, распределенный по объектам в кластере.

**Pool (Пул)** — логическая группировка образов RBD. Пулы определяют параметры репликации, правила размещения (CRUSH) и права доступа.

**Snapshot (Снапшот)** — неизменяемая копия образа на определенный момент времени. Используется для бэкапов и создания клонов.

**Clone (Клон)** — дочерний образ, созданный на основе снапшота. Использует механизм "copy-on-write" для экономии места.

## Основные концепции

### Архитектура и компоненты

RBD работает на уровне пользователя через библиотеку `librbd` или на уровне ядра через модуль `rbd`.

- **librbd** — библиотека для прямого взаимодействия приложений (QEMU/KVM, Ceph CSI) с кластером. Поддерживает расширенное кэширование.
- **Модуль ядра rbd** — позволяет маппировать образы как стандартные блочные устройства в `/dev/rbdX`.
- **rbd-mirror** — демон для асинхронной репликации образов между разными кластерами Ceph (DR-сценарии).

### Особенности технологии

| Характеристика | Описание |
|----------------|----------|
| **Thin Provisioning** | "Тонкое" выделение: место в кластере занимает только реально записанный объем данных. |
| **Стрипинг (Striping)** | Данные образа разбиваются на части (объекты) и распределяются по всем OSD в пуле для параллелизации I/O. |
| **Кэширование** | Поддержка Read-ahead и Write-back кэширования на стороне клиента (librbd cache). |
| **Шифрование** | Поддержка LUKS-шифрования на уровне образа (LUKS1/LUKS2) через Ceph CSI. |

### Требования к среде

- **Ядро Linux**: Рекомендуется 5.4 и выше. Для полной поддержки всех современных функций (например, шифрования) — 6.1+.
- **Сетевая связность**: Низкая задержка и высокая пропускная способность (рекомендуется 10GbE+).
- **Конфигурация**: Наличие файлов `/etc/ceph/ceph.conf` и ключей доступа (keyring) на клиенте.

### Функции образов (image-features)

Современные образы RBD используют набор функций для оптимизации работы.

| Функция | Описание | Важность |
|---------|----------|----------|
| `layering` | Базовая поддержка слоев для клонирования. | Обязательно |
| `exclusive-lock` | Механизм эксклюзивной блокировки одним клиентом. | Обязательно для CSI |
| `object-map` | Ускоряет операции за счет отслеживания занятых объектов. | Рекомендуется |
| `fast-diff` | Позволяет мгновенно вычислять разницу между снапшотами. | Рекомендуется |
| `deep-flatten` | Позволяет удалять снапшоты без влияния на клоны. | Рекомендуется |
