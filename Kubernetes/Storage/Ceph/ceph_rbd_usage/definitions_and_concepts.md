# RBD: Определения и фундаментальные концепции

Документ является основным источником (SSoT) для понимания архитектуры, механизмов работы и ключевых терминов блочного хранилища Ceph (RBD).

## Определения

**RADOS Block Device (RBD)** — программный интерфейс для предоставления распределенного блочного хранилища в кластере Ceph. Позволяет использовать объекты RADOS как виртуальные диски для операционных систем и гипервизоров.

**Image (Образ)** — абстракция виртуального диска. С точки зрения Ceph, образ — это метаданные (размер, функции) и набор фрагментированных данных, распределенных по множеству объектов.

**Pool (Пул)** — логический контейнер для образов RBD. Определяет параметры отказоустойчивости (количество реплик или профиль Erasure Coding) и правила размещения данных (CRUSH-правила).

**Namespace (Пространство имен)** — механизм логической изоляции образов внутри одного пула. Используется для разделения доступа между разными приложениями или клиентами (например, разными кластерами Kubernetes).

## Базовые концепции

### Архитектура и уровни взаимодействия

Блочное хранилище Ceph работает на трех основных уровнях:
1.  **RADOS Layer**: Нижний уровень хранения, где данные представлены в виде объектов фиксированного размера.
2.  **librbd**: Библиотека пользовательского пространства (C++), реализующая логику блочного устройства. Используется QEMU/KVM и Ceph CSI.
3.  **krbd (Kernel RBD)**: Модуль ядра Linux, позволяющий мапировать образы как стандартные блочные устройства (`/dev/rbdX`).

### Механизм распределения данных (Striping)

Для обеспечения высокой производительности и параллелизма Ceph разбивает образ на части:
*   **Object Size**: По умолчанию 4 МиБ. Каждый блок данных образа становится отдельным объектом в RADOS.
*   **Stripe Unit**: Минимальный квант данных, записываемый в один объект перед переходом к следующему.
*   **Stripe Count**: Количество объектов, по которым распределяются данные в рамках одного страйпа.
Этот механизм позволяет выполнять операции ввода-вывода (I/O) параллельно на сотни OSD-демонов.

### Снапшоты и клонирование (Copy-on-Write)

Ceph RBD реализует эффективные механизмы копирования при записи:
*   **Snapshots**: Используют механизм **Redirect-on-Write (RoW)**. Создание снимка происходит мгновенно и не потребляет место до тех пор, пока данные в основном образе не изменятся.
*   **Clones**: Полноценные записываемые образы, созданные на основе снапшота. Используют **Copy-on-Write (CoW)**: чтение происходит из родительского снапшота, а запись новых данных — в новый объект клона.
*   **Flattening**: Процесс разрыва связи между клоном и родителем путем копирования всех данных родителя в клон.

### Функции образов (Image Features)

Современные возможности RBD определяются набором флагов. Несоответствие флагов версии ядра клиента может привести к ошибкам монтирования.

| Функция | Описание | Поддержка |
| :--- | :--- | :--- |
| **layering** | Позволяет создавать клоны на основе снапшотов. | Базовая |
| **exclusive-lock** | Гарантирует, что только один клиент может писать в образ. | Обязательно для CSI |
| **object-map** | Хранит карту занятых объектов, ускоряя операции `ls`, `du`, `resize`. | Рекомендуется |
| **fast-diff** | Позволяет мгновенно вычислять разницу между снапшотами. | Рекомендуется |
| **deep-flatten** | Позволяет удалять снапшоты без потери данных в дочерних клонах. | Рекомендуется |
| **journaling** | Необходима для работы `rbd-mirror` (асинхронная репликация). | Для DR |

## Практические сценарии

### Жизненный цикл блочного устройства

Основные этапы работы с RBD описаны в специализированных руководствах:

1.  **Подготовка окружения**: Установка `ceph-common` и настройка прав доступа (CephX).
    > См. подробнее: **[Установка и настройка клиента](./installation_and_setup.md)**
2.  **Управление образами**: Создание, изменение размера, управление снапшотами и клонами.
    > См. подробнее: **[Управление образами RBD](./image_management.md)**
3.  **Подключение к ОС**: Маппинг устройства и создание файловой системы.
    > См. подробнее: **[Маппинг и монтирование образов](./mapping_and_mounting.md)**
4.  **Тонкая настройка**: Оптимизация кэширования, QoS и зеркалирование.
    > См. подробнее: **[Продвинутая настройка RBD](./advanced_topics.md)**
