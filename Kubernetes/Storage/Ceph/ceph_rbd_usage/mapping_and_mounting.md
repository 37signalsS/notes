# RBD: Маппинг, монтирование и поиск неисправностей

## Определения

**Маппинг (Mapping)** — процесс привязки удаленного образа RBD к локальному блочному устройству в пространстве ядра (обычно `/dev/rbdX`). После маппинга образ воспринимается операционной системой как обычный жесткий диск.

**Файловая система (Filesystem)** — структура данных, создаваемая на блочном устройстве для хранения файлов. Для RBD наиболее подходят современные ФС с поддержкой `trim/discard` (ext4, xfs).

**Точка монтирования (Mount Point)** — директория в файловой системе ОС, через которую обеспечивается доступ к данным замапленного RBD-образа.

## Основные концепции

### Взаимодействие с ядром
Маппинг выполняется модулем ядра `rbd.ko`. Если образ использует функции (image-features), не поддерживаемые текущей версией ядра, маппинг завершится ошибкой.

### Тонкое выделение и Discard
Поскольку RBD использует **Thin Provisioning**, физическое место в кластере Ceph освобождается только тогда, когда файловая система отправляет команду `discard` (TRIM). Без включения этой опции при монтировании, удаление файлов внутри RBD не приведет к освобождению места в пуле Ceph.

### Автоматизация через rbdmap
Стандартный способ автоматического подключения образов при загрузке ОС — использование сервиса `rbdmap.service` и конфигурационного файла `/etc/ceph/rbdmap`. Это решение надежнее ручных правил udev, так как оно интегрировано с циклом загрузки системы и сетью.

## Практические сценарии

### Подключение образа (Маппинг)

```bash
# Маппинг образа под конкретным пользователем
sudo rbd map kube/my-image --id client.user

# Просмотр списка подключенных устройств
rbd showmapped
# → /dev/rbd0  kube  my-image  -
```

### Подготовка и монтирование

**1. Создание файловой системы:**
Для RBD рекомендуется использовать `discard` при форматировании.
```bash
# Для XFS (рекомендуется)
sudo mkfs.xfs -K /dev/rbd0

# Для ext4
sudo mkfs.ext4 -E nodiscard /dev/rbd0
```

**2. Монтирование с оптимизациями:**
Использование `noatime` снижает количество записей в кластер при чтении файлов.
```bash
sudo mkdir -p /mnt/rbd
sudo mount -o noatime,discard /dev/rbd0 /mnt/rbd
```

### Отключение и очистка

```bash
# 1. Размонтирование
sudo umount /mnt/rbd

# 2. Размаппинг (освобождение устройства)
sudo rbd unmap /dev/rbd0

# Принудительный размаппинг (если устройство занято)
sudo rbd unmap /dev/rbd0 --force
```

### Автоматизация через rbdmap (Рекомендуется)

Этот метод является стандартом для Debian/Ubuntu/RHEL.

**1. Отредактируйте `/etc/ceph/rbdmap`:**
Добавьте строку в формате: `pool_name/image_name id=user,keyring=/path/to/key`
```text
kube/my-image id=user
```

**2. Включите сервис:**
```bash
sudo systemctl enable rbdmap.service
sudo systemctl start rbdmap.service
```

## Поиск неисправностей

### Ошибка: RBD image features set mismatch
Возникает, когда образ создан с функциями (например, `object-map`, `fast-diff`), которые не поддерживает ваше ядро.
**Решение:** Отключите проблемные функции для образа.
```bash
rbd feature disable kube/my-image object-map,fast-diff,deep-flatten,exclusive-lock
```

### Ошибка: Image is busy / Лимиты подключений
RBD по умолчанию поддерживает маппинг только на один узел (RWO). Если вы пытаетесь подключить образ, который уже замаплен в другом месте, вы получите ошибку блокировки.
**Решение:** Проверьте статус владельца блокировки:
```bash
rbd status kube/my-image
# → Watchers: 192.168.1.10:0 client.12345 cookie=1
```

### Ошибка: Read-only file system
Обычно указывает на потерю связи с кластером Ceph или проблемы на уровне OSD.
**Решение:** Проверьте `dmesg` на наличие ошибок модуля `rbd` и статус кластера через `ceph -s`.
