# RBD: Расширенные темы и оптимизация

## Определения

**RBD Mirroring** — механизм асинхронной репликации образов между кластерами Ceph для обеспечения катастрофоустойчивости (Disaster Recovery).

**QoS (Quality of Service)** — набор параметров для ограничения пропускной способности (BPS) и количества операций ввода-вывода (IOPS) для конкретных образов.

**Живая миграция (Live Migration)** — процесс перемещения данных RBD-образа между пулами или кластерами без прерывания операций ввода-вывода клиента.

**Стрипинг (Striping)** — метод распределения данных образа по объектам RADOS для параллелизации нагрузки.

## Основные концепции

### Оптимизация производительности

Производительность RBD зависит от нескольких уровней:

1.  **Клиентское кэширование (librbd cache)**:
    *   `rbd_cache_enabled`: включение кэша на стороне клиента.
    *   `rbd_cache_writethrough_until_flush`: безопасный режим, переключающийся в write-back только после первой команды flush от приложения.
2.  **Параметры очереди (Queue Depth)**: Настройка глубины очереди запросов в модуле ядра или гипервизоре.
3.  **Стрипинг v2**: Позволяет настроить размер объекта и количество страйпов для оптимизации под специфические нагрузки (например, большие последовательные записи).

### Отказоустойчивость и репликация

**rbd-mirror** поддерживает два режима репликации:
- **Journal-based**: На основе журналов событий (более старый, точный метод).
- **Snapshot-based**: На основе периодических снапшотов (рекомендуется для Squid/Reef, менее ресурсозатратный).

### Безопасность

**Шифрование RBD** реализуется на стороне клиента (через Ceph CSI или cryptsetup). Это гарантирует, что данные уходят в сеть и хранятся на OSD в зашифрованном виде. Используется стандарт LUKS1 или LUKS2.

## Практические сценарии

### Настройка QoS для образа

Ограничения применяются мгновенно и не требуют перезагрузки клиента (при использовании `librbd`).

```bash
# Ограничение IOPS (до 1000) и пропускной способности (до 50 МБ/с)
rbd config image set kube/my-image rbd_qos_iops_limit 1000
rbd config image set kube/my-image rbd_qos_read_bps_limit 52428800

# Проверка установленных параметров
rbd config image list kube/my-image | grep qos
```

### Живая миграция между пулами

Позволяет переместить образ (например, с HDD-пула на SSD-пул) без остановки ВМ.

```bash
# Шаг 1: Инициация миграции
rbd migration prepare kube/my-image fast-pool/my-image

# Шаг 2: Выполнение копирования данных (образ доступен для записи)
rbd migration execute fast-pool/my-image

# Шаг 3: Завершение миграции (фиксация изменений)
rbd migration commit fast-pool/my-image
```

### Инкрементальный бэкап

Для эффективного бэкапа используются дифференциальные снимки.

```bash
# Экспорт разницы между двумя снапшотами
rbd export-diff kube/my-image@snap2 --from-snap snap1 /backup/diff_1_2.rbd

# Импорт дифференциального бэкапа на удаленный кластер
rbd import-diff /backup/diff_1_2.rbd remote-pool/my-image
```

### Тестирование производительности

Для замеров IOPS и Latency рекомендуется использовать `fio` с движком `rbd`. Подробные примеры конфигураций доступны в разделе **[`Бенчмаркинг RBD через fio`](../../../../Linux/Diagnostics/Filesystem/fio.md#тестирование-ceph-rbd)**.
