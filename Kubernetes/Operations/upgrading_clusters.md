# Порядок обновления кластера Kubernetes

- **1. Изучение Change Log:**
  - Внимательно изучите список изменений (`change log`) и `release notes` для новой версии. Обратите особое внимание на секции "Known Issues" (Известные проблемы) и "Urgent Upgrade Notes" (Срочные примечания по обновлению). Это поможет выявить потенциальные проблемы и несовместимости с вашими приложениями или конфигурацией.

- **2. Создание тестового кластера:**
  - Разверните новый тестовый кластер, конфигурация которого максимально приближена к производственному окружению.

- **3. Обновление тестового кластера:**
  - Выполните процедуру обновления на тестовом кластере. Это позволит отработать сам процесс и выявить любые технические сложности в безопасной среде.

- **4. Деплой и тестирование приложений:**
  - Разверните ваши приложения в обновленном тестовом кластере. Проведите полное регрессионное тестирование, чтобы убедиться, что все сервисы работают корректно с новой версией Kubernetes API.

- **5. Планирование времени обновления:**
  - Выберите время с наименьшей нагрузкой на систему для проведения работ на производственном кластере. Согласуйте это время со всеми заинтересованными сторонами.

- **6. Создание бекапов:**
  - Перед началом обновления создайте полные резервные копии всех критически важных компонентов:
    - **etcd:** Хранилище состояния кластера.
    - **Persistent Volumes (PV):** Данные ваших приложений.
    - **Конфигурации:** Манифесты, Helm-чарты и другие конфигурационные файлы.

- **7. Постепенное обновление Production-кластера:**
  - Обновляйте производственный кластер **по одной ноде за раз** (rolling update), начиная с master-узлов. Такой подход позволяет сохранить работоспособность кластера во время обновления и минимизирует влияние на запущенные приложения.

- **8. Проверка работоспособности после каждой ноды:**
  - После обновления каждой ноды тщательно проверяйте состояние кластера и работоспособность приложений. Убедитесь, что нода успешно присоединилась к кластеру, а поды на ней запускаются и работают корректно. Только после этого переходите к следующей ноде.

## Компоненты, затрагиваемые при обновлении

- **База данных etcd:**
  - Обновление хранилища ключ-значение, в котором содержится всё состояние кластера.

- **Компоненты Control Plane:**
  - **kube-apiserver:** API-сервер.
  - **kube-controller-manager:** Менеджер контроллеров.
  - **kube-scheduler:** Планировщик.
  - **kubelet:** Компонент на master-нодах.

- **Компоненты Worker-нод:**
  - **kubelet:** Основной агент Kubernetes на рабочих нодах.
  - **kube-proxy:** Управляет сетевыми правилами на нодах.

- **Сетевые компоненты и сервисы:**
  - **CNI-плагин (например, kube-flannel, Calico):** Обеспечивает сетевое взаимодействие между подами.
  - **CoreDNS и nodelocaldns:** Сервисы для разрешения DNS-имен внутри кластера.
  - **Ingress-контроллер (например, ingress-nginx-controller):** Управляет внешним доступом к сервисам в кластере.

- **Сертификаты:**
  - Обновление или перевыпуск TLS-сертификатов, используемых для безопасного взаимодействия между компонентами кластера.
