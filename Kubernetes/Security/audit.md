# Аудит в Kubernetes

## Определения

**Аудит (Auditing)** — механизм Kubernetes, предоставляющий набор записей, которые документируют последовательность действий в кластере. Аудит позволяет ответить на вопросы: что произошло, кто это сделал, когда и с какого устройства.

---

## Основные концепции

### Включение аудита
Аудит настраивается через флаги командной строки `kube-apiserver`. Основные параметры:

- `--audit-log-path`: путь к файлу лога аудита (например, `/var/log/kubernetes/audit.log`).
- `--audit-policy-file`: путь к файлу политики аудита, определяющему, какие события записывать.

### Уровни аудита (Audit Levels)
Политика аудита определяет, сколько данных записывается для каждого события:

- **None:** события не записываются.
- **Metadata:** записываются только метаданные запроса (пользователь, время, ресурс), но не тело запроса/ответа.
- **Request:** записываются метаданные и тело запроса.
- **RequestResponse:** записываются метаданные, тело запроса и тело ответа.

## Практические сценарии

### Пример политики аудита для RBAC
Рекомендуется детально логировать все изменения, связанные с управлением доступом.

```yaml
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
  # 1. Регистрировать все запросы API, связанные с RBAC (роли, привязки)
  - level: Metadata
    verbs: ["create", "update", "patch", "delete", "get", "list", "watch"]
    resources:
      - group: "rbac.authorization.k8s.io"
        resources: ["roles", "rolebindings", "clusterroles", "clusterrolebindings"]

  # 2. Записывать все решения об авторизации
  - level: Metadata
    resources:
      - group: "authorization.k8s.io"
        resources: ["*"]

  # 3. Логировать изменения ConfigMap (могут влиять на RBAC косвенно)
  - level: Request
    resources:
      - group: ""
        resources: ["configmaps"]

  # 4. Правило по умолчанию: не логировать остальное
  - level: None
```

### Сочетание инструментов (Synergy)
Для обеспечения максимальной безопасности рекомендуется сочетать **Аудит** (декларативный анализ действий в API) и **[Falco](../../Security/Tools/falco.md)** (мониторинг поведения в реальном времени на уровне ядра). Аудит фиксирует "кто и что сделал", а Falco — "как система на это отреагировала в runtime".

## Дополнительная информация

### Регулярная проверка
Аудит и проверка политик доступа должны проводиться регулярно. Это позволяет выявлять:
- Неправильные конфигурации.
- Попытки несанкционированного доступа.
- Аномальную активность пользователей.
