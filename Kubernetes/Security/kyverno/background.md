# Фоновое сканирование (Background Scans) в Kyverno

## Определения

**Фоновое сканирование (Background Scan)** — механизм периодической проверки существующих ресурсов в кластере на соответствие установленным политикам Kyverno.

**Важно**: Механизм фонового сканирования **не применяет** политики мутации или валидации к уже существующим ресурсам активно (не изменяет их и не блокирует). Он предназначен исключительно для генерации отчетов о соответствии. Политики блокировки (`enforce`) срабатывают только на этапе **Admission** (допуска) для новых или изменяемых ресурсов.

---

## Основные концепции

### Параметр background в политиках

В манифесте политики (YAML, Yet Another Markup Language) за это отвечает поле `spec.background`:

| Значение | Описание |
|----------|----------|
| `true` (по умолчанию) | Фоновое сканирование включено. Ресурсы проверяются, и результаты заносятся в отчеты. |
| `false` | Фоновое сканирование отключено. Отчеты формируются только в момент создания или изменения ресурсов. |

### Принцип работы

1. **Background Controller**: Специализированный компонент Kyverno периодически итерирует по всем ресурсам в кластере.
2. **Сопоставление**: Для каждой активной политики проверяются ресурсы, соответствующие условиям `match`.
3. **Генерация отчетов**: Результаты записываются в ресурсы `PolicyReport` или `ClusterPolicyReport` (отчеты по политикам).
4. **Режим Audit**: Если политика находится в режиме `Audit`, нарушения просто фиксируются.
5. **Режим Enforce**: Даже если политика требует блокировки (`Enforce`), существующий ресурс **не будет удален или изменен**; информация о нарушении попадет в отчет для последующего исправления администратором.

### Матрица режимов и результатов

| Background | Failure Action | Результат для существующих ресурсов |
|------------|----------------|-------------------------------------|
| `true` | `Enforce` | Только генерация отчетов (Reports). |
| `true` | `Audit` | Только генерация отчетов (Reports). |
| `false` | `Enforce` | Отчеты для существующих ресурсов не создаются. |
| `false` | `Audit` | Отчеты для существующих ресурсов не создаются. |

> **Ключевое правило**: Фоновое сканирование — это инструмент **аудита** и **отладки** политик перед их переводом в режим строгой блокировки.

## Практические сценарии

### Настройка фонового сканирования в политике

Пример политики с отключенным сканированием для экономии ресурсов:

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-run-as-non-root
spec:
  background: false  # Отключение фонового сканирования
  validationFailureAction: Enforce
  rules:
    - name: run-as-non-root
      match:
        resources:
          kinds:
            - Pod
      validate:
        message: "Container must run as non-root"
        pattern:
          spec:
            securityContext:
              runAsNonRoot: true
```

### Просмотр результатов сканирования

Для анализа состояния кластера используются отчеты ([подробнее об отчетах](./reports.md)):

```bash
# Просмотр сводки отчетов в пространстве имен
kubectl get policyreports -n <namespace>
# → NAME           PASS   FAIL   WARN   ERROR   SKIP   AGE
# → policyreport   10     2      0      0       0      15m

# Просмотр детальной информации о нарушениях
kubectl describe policyreport <name> -n <namespace>

# Список всех нарушений в кластере через JSONPath
kubectl get policyreports -A -o jsonpath='{range .items[?(@.summary.fail>0)]}{"Namespace: "}{.metadata.namespace}{" - Fail: "}{.summary.fail}{"\n"}{end}'
```

### Оптимизация производительности

Если в кластере тысячи ресурсов, фоновое сканирование может создавать нагрузку на API-сервер.

**Рекомендации**:

1. Отключайте `background: true` для политик, которые актуальны только при создании (например, проверка лейблов при деплое).
2. Используйте `exclude` для системных пространств имен, чтобы не сканировать служебные поды:

```yaml
spec:
  background: true
  rules:
    - name: check-security-context
      match:
        resources:
          kinds:
            - Pod
      exclude:
        resources:
          namespaces:
            - kube-system
            - kube-public
            - kyverno
```

## Дополнительная информация

### Важные параметры контроллера

Частота сканирования настраивается в аргументах запуска `background-controller` (параметр `--background-scan-interval`). По умолчанию интервал составляет 1 час.
