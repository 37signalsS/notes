# Фоновое сканирование в Kyverno

## Определения

**Фоновое сканирование (Background Scan)** — процесс периодической проверки ресурсов кластера на соответствие политикам безопасности. В отличие от Admission-контроля, который работает в момент создания или изменения ресурса, фоновое сканирование анализирует уже существующие объекты.

Основными целями фонового сканирования являются:
1.  **Аудит и отчетность**: Выявление ресурсов, нарушающих новые или обновленные политики.
2.  **Активная мутация**: Приведение существующих ресурсов к желаемому состоянию (через правила `mutateExisting`).
3.  **Генерация ресурсов**: Создание недостающих объектов (через правила `generate`), например, секретов или сетевых политик для новых пространств имен.

---

## Основные концепции

### Архитектура контроллеров (v1.12+)

В современных версиях Kyverno задачи фоновой обработки разделены между специализированными компонентами:

| Контроллер | Задача |
| :--- | :--- |
| **Reports Controller** | Сканирование ресурсов для формирования `PolicyReports`. Обрабатывает правила `validate` и `verifyImages`. |
| **Background Controller** | Выполнение активных действий: фоновая мутация (`mutateExisting`) и генерация ресурсов (`generate`). |

### Ключевые параметры политик

В манифесте политики за фоновую активность отвечают следующие поля:

*   **`spec.background`**: (по умолчанию `true`) — включает создание отчетов о соответствии для существующих ресурсов.
*   **`spec.mutateExistingOnPolicyUpdate`**: (устаревает в v1.13+) — инициирует немедленную мутацию существующих ресурсов при обновлении политики. Рекомендуется переходить на явное использование правил `mutateExisting`.
*   **`spec.rules[].mutate.mutateExisting`**: Современный способ описания мутаций, которые должны применяться к уже созданным объектам.

### Режимы работы и результаты

| Режим (Failure Action) | Состояние ресурса | Результат в PolicyReport |
| :--- | :--- | :--- |
| **Audit** | Без изменений | `fail` (при нарушении) |
| **Enforce** | Без изменений | `fail` (при нарушении) |

**Важно**: Даже в режиме `Enforce` фоновое сканирование **не блокирует** и **не удаляет** существующие ресурсы. Оно лишь фиксирует нарушение в отчете. Единственное исключение — правила мутации (`mutateExisting`), которые активно изменяют объект.

## Практические сценарии

### Настройка интервала сканирования

По умолчанию сканирование происходит каждые 1 час. В больших кластерах (более 5000 ресурсов) рекомендуется увеличить интервал для снижения нагрузки на API-сервер.

Настройка через переменные окружения `background-controller` и `reports-controller`:

```yaml
# Пример настройки через Helm values.yaml
backgroundController:
  envVars:
    - name: BACKGROUND_SCAN_INTERVAL
      value: "6h" # Сканирование раз в 6 часов
reportsController:
  envVars:
    - name: BACKGROUND_SCAN_INTERVAL
      value: "6h"
```

### Фоновая мутация существующих ресурсов

Пример политики, которая добавляет метку ко всем существующим пространствам имен, если она отсутствует:

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: add-org-label
spec:
  rules:
    - name: add-label-to-existing-ns
      match:
        any:
          - resources:
              kinds:
                - Namespace
      mutate:
        # Указываем, что мутация должна применяться к существующим ресурсам
        targets:
          - selector:
              matchLabels:
                org: null # Выбираем те, где метка отсутствует
        patchStrategicMerge:
          metadata:
            labels:
              org: "my-company"
```

### Исключение ресурсов для оптимизации

Для снижения шума в отчетах и нагрузки на контроллер следует исключать системные пространства имен:

```yaml
spec:
  background: true
  rules:
    - name: check-labels
      match:
        resources:
          kinds: [Pod]
      exclude:
        resources:
          namespaces:
            - kube-system
            - kyverno
            - kube-public
```

## Дополнительная информация

### Производительность и воркеры

Если очередь сканирования растет слишком медленно, можно увеличить количество параллельных воркеров через аргументы запуска контроллера:
*   `--backgroundScanWorkers`: количество потоков для обработки ресурсов (по умолчанию 10).

### Решение проблем

*   **Отчеты не обновляются**: Проверьте права доступа (RBAC) у `reports-controller`. Ему необходимы права `get`, `list`, `watch` на сканируемые ресурсы.
*   **Мутация не срабатывает**: Убедитесь, что `background-controller` имеет права на `patch` целевых ресурсов. Подробнее см. в разделе **[Агрегированные роли](./additional.md)**.
