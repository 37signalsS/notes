# Практические сценарии Kyverno

## Определения

**Практические сценарии** — набор типовых и специализированных руководств по использованию Kyverno для реализации концепции «Политики как код» (Policy as Code). Сценарии охватывают задачи от базовой гигиены безопасности до сложной автоматизации мультиарендных (multi-tenancy) окружений и защиты цепочек поставок.

---

## Основные концепции

### Категории сценариев (2024–2025)

В современных инфраструктурах использование Kyverno структурировано по следующим ключевым направлениям:

| Категория | Описание | Основной источник |
| :--- | :--- | :--- |
| **Безопасность (PSS)** | Внедрение Pod Security Standards (Baseline, Restricted) и лучших практик. | [Сценарии безопасности](./security_policies.md) |
| **Автоматизация & Платформа** | Автогенерация ресурсов для новых пространств имен и мутация объектов. | [Автоматизация и compliance](./automation_compliance.md) |
| **Compliance & NIS2** | Обеспечение соответствия регуляторным требованиям (CIS, NIST, NIS2). | [Автоматизация и compliance](./automation_compliance.md) |
| **Supply Chain Security** | Проверка подписей образов (Cosign), аттестаций и SBOM через ImageValidatingPolicy. | [Очистка и верификация](./cleanup_verification.md) |
| **Управление ресурсами** | Автоматическая очистка временных объектов по расписанию или TTL. | [Очистка и верификация](./cleanup_verification.md) |

## Практические сценарии

### Навигация по специализированным руководствам

Каждый раздел содержит детальные YAML-манифесты и инструкции по их применению:

1.  **[Политики безопасности](./security_policies.md)**:
    *   Ограничение привилегий и использование CEL-валидации.
    *   Запрет небезопасных типов томов и сетевых протоколов.
    *   Контроль использования `root` пользователей.
2.  **[Автоматизация и соответствие](./automation_compliance.md)**:
    *   Автоматическая генерация `NetworkPolicy` и `ResourceQuota` для новых Namespace.
    *   Синхронизация секретов и ConfigMap.
    *   Интеграция с CI/CD через Kyverno CLI.
3.  **[Очистка и верификация](./cleanup_verification.md)**:
    *   **Cleanup**: Удаление старых ресурсов по TTL-меткам.
    *   **Software Supply Chain**: Верификация цепочки поставок ПО через Sigstore/Cosign.

## Дополнительная информация

### Рекомендации по внедрению сценариев

*   **Audit-First**: Любой новый сценарий должен начинаться в режиме `validationFailureAction: Audit`.
*   **Исключения**: Используйте ресурс `PolicyException` вместо прямого редактирования блоков `exclude` в политиках сценариев.
*   **Использование CEL**: При адаптации сценариев отдавайте предпочтение CEL-политикам для повышения производительности кластера.
*   **Интеграция**: Связывайте результаты сценариев с [Policy Reporter](../reporter.md) для получения визуальной аналитики в Grafana.
