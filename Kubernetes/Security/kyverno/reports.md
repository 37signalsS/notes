# Отчеты Kyverno (Policy Reports)

## Определения

**Отчет о политиках (Policy Report)** — структурированный документ, содержащий результаты проверки ресурсов кластера на соответствие установленным правилам безопасности. На 2026 год в экосистеме Kyverno сосуществуют два основных стандарта отчетности:

1.  **Классический (wgpolicyk8s.io)**: Разработан рабочей группой Kubernetes Policy WG. Используется для обратной совместимости с большинством инструментов визуализации.
2.  **Современный (openreports.io)**: Новый стандарт (начиная с Kyverno 1.15+), ориентированный на высокую производительность и глубокую интеграцию с CEL-политиками.

**Типы ресурсов отчетности:**
- **PolicyReport** — отчет по ресурсам внутри конкретного Namespace (пространства имен).
- **ClusterPolicyReport** — глобальный отчет по ресурсам уровня кластера (Nodes, Namespaces, ClusterRoles).
- **EphemeralReport** — временный отчет, генерируемый во время Admission-запроса (используется для немедленной обратной связи).

## Основные концепции

### Масштабирование и хранение: Reports Server

В крупных кластерах (более 500 узлов) хранение отчетов в **etcd** может привести к деградации производительности API-сервера. Для решения этой проблемы Kyverno 1.18+ использует архитектуру **Reports Server**:

| Характеристика | Описание |
| :--- | :--- |
| **API Aggregation** | Запросы к PolicyReport перехватываются специальным агрегатором. |
| **Внешняя БД** | Результаты проверок сохраняются в реляционную базу данных (например, **PostgreSQL**). |
| **Производительность** | Снижение нагрузки на etcd до 80%, возможность хранения истории изменений. |
| **Прозрачность** | Для конечного пользователя работа через `kubectl get policyreports` остается неизменной. |

### Жизненный цикл отчета

1.  **Триггер**: Создание/изменение ресурса или плановое фоновое сканирование ([см. background.md](./background.md)).
2.  **Анализ**: Контроллер `reports-controller` (или Admission Controller для эфемерных отчетов) сопоставляет ресурс с активными политиками.
3.  **Запись**: Результат заносится в отчет. Если ресурс удаляется, связанный с ним результат автоматически вычищается из отчета.
4.  **Агрегация**: Несколько результатов проверок одного ресурса объединяются в одну запись в рамках `PolicyReport` для минимизации объема данных.

## Практические сценарии

### Структура отчета (Стандарт OpenReports)

Пример манифеста, отражающего проверку CEL-политики:

```yaml
apiVersion: openreports.io/v1alpha1
kind: PolicyReport
metadata:
  name: app-security-report
  namespace: production
scope:
  apiVersion: apps/v1
  kind: Deployment
  name: web-server
results:
  - source: kyverno
    policy: restrict-root-access
    rule: check-run-as-non-root
    category: Security
    severity: Critical
    result: fail
    message: "Контейнер пытается запуститься от имени root (UID 0)"
    properties:
      engine: CEL
      timestamp: "2026-07-21T10:00:00Z"
summary:
  pass: 12
  fail: 1
  warn: 0
  error: 0
  skip: 2
```

### Статусы результатов проверки

| Статус | Техническое описание |
| :--- | :--- |
| **pass** | Ресурс полностью соответствует требованиям политики. |
| **fail** | Обнаружено нарушение. В режиме `audit` это не блокирует ресурс, но требует внимания. |
| **warn** | Незначительное отклонение или использование устаревших параметров (deprecated). |
| **skip** | Проверка пропущена (например, из-за условий `exclude` или `preconditions`). |
| **error** | Сбой в работе движка Kyverno при обработке данного ресурса (например, ошибка в синтаксисе CEL). |

### Работа с отчетами через интерфейс командной строки (CLI)

```bash
# Просмотр сводки по всем пространствам имен
kubectl get policyreports -A

# Поиск критических нарушений в кластерных ресурсах
kubectl get clusterpolicyreports -o jsonpath='{range .items[*].results[?(@.severity=="Critical")]}{"Policy: "}{.policy}{" Resource: "}{.resource}{"\n"}{end}'

# Получение отчета в формате JSON для внешней обработки
kubectl get policyreport my-report -n prod -o json
```

## Дополнительная информация

### Интеграция с мониторингом и визуализацией

Для полноценной работы с отчетами в промышленной среде рекомендуется связка:

1.  **Policy Reporter**: Специализированный UI для визуализации отчетов, поиска дрифта конфигураций и настройки алертинга (Slack, Telegram) ([подробнее](./reporter.md)).
2.  **Prometheus & Grafana**: Kyverno экспортирует метрики состояния отчетов (например, `kyverno_policy_results_total`), что позволяет строить графики динамики безопасности кластера.
3.  **Loki / ELK**: Рекомендуется экспортировать результаты отчетов в системы сбора логов для долгосрочного хранения истории, так как стандартные `PolicyReport` отражают только текущее состояние.

### Оптимизация производительности

- **Частота сканирования**: Регулируйте интервал фонового сканирования в `background-controller`, чтобы избежать пиковых нагрузок на API-сервер.
- **Очистка отчетов**: Регулярно проверяйте наличие "осиротевших" (orphaned) отчетов, оставшихся после удаления политик или ресурсов в аномальных ситуациях.
- **Внешняя БД**: Обязательно настраивайте индексацию в PostgreSQL для таблиц с результатами проверок, если количество записей превышает 100,000.
