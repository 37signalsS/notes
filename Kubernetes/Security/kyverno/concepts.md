# Основные концепции Kyverno

## Определения

**Kyverno** — современный policy-движок (движок политик), разработанный специально для Kubernetes. Он функционирует как **Admission Controller** (контроллер допуска), перехватывая запросы к API (Application Programming Interface, интерфейс программирования приложений) серверу для обеспечения безопасности, комплаенса и автоматизации конфигураций. 

На 2026 год Kyverno является индустриальным стандартом для управления политиками в K8s, благодаря нативной поддержке **CEL (Common Expression Language)** и глубокой интеграции с цепочками поставок ПО (верификация подписей и SBOM (Software Bill of Materials)).

## Основные концепции

### Механизм работы (Admission Webhooks)

Kyverno встраивается в жизненный цикл запроса к Kubernetes через механизмы вебхуков:

1.  **Запрос к API**: Пользователь или автоматизированная система (CI/CD) отправляет манифест.
2.  **Mutating Admission Webhook (мутирующий вебхук)**: Kyverno проверяет и, если необходимо, изменяет манифест (например, внедряет Sidecar-контейнеры или устанавливает `securityContext` по умолчанию) перед сохранением в базу.
3.  **Validating Admission Webhook (валидирующий вебхук)**: Проверяет итоговый манифест на соответствие правилам безопасности и разрешает или отклоняет операцию.
4.  **Сохранение в etcd**: Объект сохраняется в кластере только после успешного прохождения всех этапов.

> **Важно**: Kyverno управляет конфигурациями на уровне деклараций. Для защиты на уровне выполнения процессов внутри контейнеров (Runtime Security) используйте [Falco](../../../Security/Tools/falco.md).

### Архитектурные компоненты и движок CEL

В актуальных версиях (1.17+) Kyverno использует архитектуру **CEL-first**, что позволяет генерировать нативные политики Kubernetes (**ValidatingAdmissionPolicies**), которые исполняются самим API-сервером без обращения к внешним вебхукам, что критично для производительности.

| Компонент | Назначение в современной архитектуре |
| :--- | :--- |
| **Admission Controller** | Основной узел обработки. Управляет нативными CEL-политиками и верификацией образов в реальном времени. |
| **Background Controller** | Выполняет аудит существующих ресурсов и управляет мутацией/генерацией объектов в фоновом режиме. |
| **Cleanup Controller** | Реализует логику `DeletingPolicy`: автоматическое удаление устаревших ресурсов по расписанию. |
| **Reports Controller** | Агрегирует результаты проверок. В больших кластерах поддерживает экспорт данных во внешние БД (PostgreSQL) для разгрузки etcd. |

### Управление исключениями (PolicyException)

Вместо сложного редактирования блоков `exclude` в каждой политике, Kyverno использует специализированный ресурс — **PolicyException (POLE)**. Это позволяет:
- **Разделять полномочия**: Группа безопасности владеет политиками, а команды разработки — исключениями (после апрува).
- **Временные допуски**: Устанавливать срок действия исключения (TTL), после которого оно автоматически удалится.
- **Точность**: Применять исключение к конкретному правилу, а не ко всей политике.

## Практические сценарии

### Ключевой функционал

| Функция | Описание | Применение в 2026 году |
| :--- | :--- | :--- |
| **Валидация** | Проверка манифестов. | Использование CEL для высокопроизводительных проверок. |
| **Мутация** | Изменение ресурсов. | Внедрение технических меток и параметров безопасности "на лету". |
| **Генерация** | Создание новых объектов. | Автоматическое создание `NetworkPolicy` и `Quotas` для новых Namespace. |
| **Верификация** | Supply Chain Security. | Проверка подписей Cosign и содержимого **SBOM** (CycloneDX/SPDX). |
| **Очистка** | Ресурсный менеджмент. | Удаление подов в статусе `Succeeded` старше 24 часов. |

### Сравнение с альтернативными инструментами

| Инструмент | Основной подход | Критерий выбора |
| :--- | :--- | :--- |
| **Kyverno** | YAML + CEL. Нативно для K8s. | Лучший выбор для платформ на базе Kubernetes. |
| **[OPA Gatekeeper](../opa_gatekeeper_overview.md)** | Язык Rego. | Универсальный движок для разных систем (не только K8s). |
| **[Falco](../../../Security/Tools/falco.md)** | Анализ системных вызовов. | Защита от угроз внутри запущенных контейнеров. |

## Дополнительная информация

### Отказоустойчивость (High Availability)

Поскольку Admission Controller является блокирующим компонентом (при недоступности Kyverno создание новых подов может быть остановлено), критически важно:
- Использовать **3 реплики** `admission-controller` в разных зонах доступности.
- Настраивать `PriorityClass: system-cluster-critical` для предотвращения вытеснения подов Kyverno.
- Тщательно конфигурировать `failurePolicy` (Ignore/Fail) в зависимости от критичности контура.

### Интеграции и экосистема

- **GitOps**: Полная совместимость с Argo CD (через Server-Side Apply) и Flux.
- **Визуализация**: **Policy Reporter** — графический интерфейс для анализа отчетов и алертинга ([подробнее](./reporter.md)).
- **Observability**: Экспорт метрик в Prometheus для мониторинга количества нарушений и производительности вебхуков.
