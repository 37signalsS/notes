# Основные концепции Kyverno

## Определения

**Kyverno** — специализированный policy-движок (движок политик) для Kubernetes, функционирующий как **Admission Controller** (контроллер допуска). Он перехватывает запросы к API (Application Programming Interface, интерфейс программирования приложений) серверу и применяет к ним заданные политики безопасности, ограничения или автоматические изменения.

---

## Основные концепции

### Механизм работы (Admission Webhooks)

Kyverno интегрируется в жизненный цикл запроса к Kubernetes через механизмы вебхуков:

1. **Запрос к API**: Пользователь или сервис отправляет манифест (YAML/JSON) в Kubernetes.
2. **Цепочка Webhooks**: Запрос проходит через серию проверок.
3. **Kyverno Webhooks**:
   - **Mutating Admission Webhook (мутирующий вебхук)**: Может изменять (мутировать) манифест (например, добавлять лейблы или настройки безопасности) перед сохранением.
   - **Validating Admission Webhook (валидирующий вебхук)**: Проверяет манифест на соответствие правилам и разрешает или отклоняет запрос.
4. **Сохранение в etcd**: После успешного прохождения всех проверок объект сохраняется в etcd (распределенное хранилище состояния кластера).

> **Важно**: Kyverno работает на уровне манифестов (уровень управления). Для мониторинга активности внутри запущенных контейнеров (уровень выполнения) используйте [Falco](../../../Security/Tools/falco.md).

### Архитектурные компоненты

При установке через Helm (менеджер пакетов Kubernetes) разворачиваются следующие компоненты ([подробнее об установке](./install.md)):

| Компонент | Назначение |
|-----------|------------|
| **Admission Controller** | Основной компонент для обработки входящих запросов мутации и валидации. |
| **Background Controller** | Выполняет фоновое сканирование существующих ресурсов и применяет политики генерации. |
| **Cleanup Controller** | Отвечает за автоматическое удаление ресурсов по заданному расписанию. |
| **Reports Controller** | Формирует отчеты о соответствии ресурсов политикам ([подробнее об отчетах](./reports.md)). |

## Практические сценарии

### Ключевой функционал

Kyverno предоставляет пять основных типов действий ([детальное описание правил](./rules.md)):

| Функция | Описание | Типичный пример |
|---------|----------|-----------------|
| **Валидация** | Проверка ресурсов на соответствие стандартам. | Запрет запуска контейнеров от имени `root`. |
| **Мутация** | Автоматическое исправление или дополнение манифестов. | Добавление `imagePullSecrets` во все новые поды. |
| **Генерация** | Создание новых ресурсов при появлении триггера. | Создание `NetworkPolicy` при создании нового `Namespace`. |
| **Верификация образов** | Проверка цифровых подписей контейнеров. | Запуск только образов, подписанных через Cosign/Sigstore. |
| **Очистка (Pruning)** | Автоматическое удаление устаревших объектов. | Удаление старых заданий (Jobs) или завершенных подов. |

### Сравнение с альтернативными инструментами

| Инструмент | Этап работы | Основной подход |
|------------|-------------|-----------------|
| **Kyverno** | Admission (Допуск) | YAML-подобные политики, нативно для K8s. |
| **[OPA Gatekeeper](../opa_gatekeeper_overview.md)** | Admission (Допуск) | Использование языка программирования Rego. |
| **[kubesec](../kubesec.md)** | CI/CD (Пайплайны) | Статический анализ YAML-файлов до деплоя. |
| **[Falco](../../../Security/Tools/falco.md)** | Runtime (Выполнение) | Анализ системных вызовов в реальном времени. |

## Дополнительная информация

### Ограничения системы

- **Фоновое сканирование**: По умолчанию политики мутации и генерации не применяются к уже существующим ресурсам автоматически — они только фиксируются в отчетах ([подробнее](./background.md)).
- **Точки отказа**: Если Admission Controller недоступен, создание новых ресурсов может быть заблокировано (зависит от настройки `failurePolicy`).
- **Режимы работы**: Политики могут работать в режиме `audit` (только запись в лог/отчет) или `enforce` (блокировка нарушения).

### Интеграции и экосистема

- **GitOps**: Совместим с Argo CD и Flux при условии корректной настройки сравнения ресурсов ([подробнее](./argo-cd.md)).
- **Compliance**: Помогает в обеспечении соответствия стандартам PCI DSS (Payment Card Industry Data Security Standard) и GDPR (General Data Protection Regulation).
- **Визуализация**: Интеграция с **Policy Reporter** для получения графического интерфейса (Web UI) и алертинга ([подробнее](./reporter.md)).

### Исторический контекст

Kyverno является основной альтернативой устаревшим **PSP (Pod Security Policies)**, которые были удалены в Kubernetes 1.25. В отличие от нативного механизма **PSA (Pod Security Admission)**, Kyverno позволяет создавать гораздо более гибкие и специфичные правила.
