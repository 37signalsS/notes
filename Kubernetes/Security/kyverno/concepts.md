# Основные концепции Kyverno

## Определения

**Kyverno** — policy-движок для Kubernetes, функционирующий как **Admission Controller**. Перехватывает запросы к API-серверу и применяет к ним заданные политики безопасности, ограничения или рекомендации.

**Документация структурирована**: [Основные концепции](./concepts.md) → [Типы правил](./rules.md) → [Написание политик](./policies.md) → [Практические сценарии](./scenarios.md)

## Basic Concepts

### Как работает Kyverno (Admission Webhooks)

При деплое манифеста в Kubernetes:

1. **Манифест отправляется в Kubernetes API**
2. **Манифест проходит через цепочку webhook-ов**
3. **Kyverno подключается к двум типам webhook**:
   - **Mutating Admission Webhook**: Может изменять (мутировать) манифест перед сохранением в etcd
   - **Validating Admission Webhook**: Проверяет манифест на соответствие политикам
4. **После прохождения цепочки манифест сохраняется в etcd**

> **Важно**: Kyverno работает **только с манифестами**, а не с запущенными приложениями. Для runtime-мониторинга используйте [Falco](../../../Security/Tools/falco.md).

### Архитектурные компоненты

При установке через Helm разворачиваются **4 компонента** ([подробнее](./install.md)):

| Компонент | Назначение |
|-----------|------------|
| **Admission Controller** | Обрабатывает mutating и validating admission webhook-запросы |
| **Background Controller** | Обрабатывает создание и обновление ресурсов в фоновом режиме |
| **Cleanup Controller** | Удаляет ресурсы, помеченные на очистку |
| **Reports Controller** | Генерирует отчеты о применении политик |

## Practical Scenarios

### Ключевой функционал

| Функция | Описание | Пример использования |
|---------|----------|---------------------|
| **Валидация манифестов** | Проверка ресурсов (подов, деплойментов и т.д.) на соответствие правилам безопасности | Требование `securityContext` с `runAsNonRoot: true` |
| **Мутация ресурсов** | Автоматическое изменение параметров перед сохранением в etcd | Добавление `securityContext`, лейблов, `imagePullSecrets` |
| **Генерация ресурсов** | Создание новых ресурсов на основе существующих | Автоматическая генерация `NetworkPolicy` для новых namespace |
| **Очистка ресурсов (Pruning)** | Удаление устаревших или неиспользуемых объектов | Удаление старых Pod после обновления Deployment |
| **Встроенный аудит** | Детальные отчеты о применении политик и нарушениях | [Policy Reports](./reports.md) |
| **Внекластерное использование** | CLI, CI/CD пайплайны, JSON-интерфейс | Проверка манифестов до деплоя через `kyverno cli` |

### Практические сценарии использования

- **Применение политик безопасности в реальном времени**: В отличие от [kubesec](../kubesec.md), который проверяет YAML-манифесты *до* развертывания, Kyverno проводит валидацию и мутацию *во время* развертывания через Admission Controller
- **Автоматизация соответствия стандартам**: Обеспечение непрерывного соблюдения PCI DSS, GDPR через политики
- **Внедрение лучших практик**: Автоматическое добавление `securityContext` к подам ([подробнее](../pod_security_context.md))
- **Инфраструктура как код**: Политики как YAML-файлы в репозитории с версионированием и тестированием
- **Управление сетевыми политиками**: Автоматическая генерация `NetworkPolicy` для изоляции namespace ([подробнее](../network_policies.md))
- **Управление секретами Docker Registry**: Автоматическое копирование `Secret` с credentials при создании namespace

### Сравнение с другими инструментами

| Инструмент | Когда работает | Назначение |
|------------|----------------|------------|
| **Kyverno** | Во время деплоя (Admission) | Применение политик к ресурсам |
| **[kubesec](../kubesec.md)** | До деплоя (статический анализ) | Проверка манифестов на уязвимости |
| **[kube-bench](../kube-bench.md)** | Периодический аудит | Проверка конфигурации кластера на CIS Benchmark |
| **[Falco](../../../Security/Tools/falco.md)** | Runtime (после деплоя) | Мониторинг поведения приложений |

## Additional Information

### Ограничения

- **Background scan не применяет политики к существующим ресурсам** — только генерирует отчеты ([подробнее](./background.md))
- Политики срабатывают только при **CREATE/UPDATE** ресурсов
- По умолчанию политики работают в режиме **audit** — для блокировки необходимо `failureAction: Enforce`

### Интеграции

- **Argo CD**: Требуется специальная настройка для избежания конфликтов ([подробнее](./argo-cd.md))
- **Sigstore**: Проверка подписей образов через `verifyImages` ([подробнее](../../../Security/Tools/sigstore.md))
- **Policy Reporter**: Web UI, метрики Prometheus, уведомления ([подробнее](./reporter.md))

### Историческая справка

В Kubernetes 1.25 были удалены **Pod Security Policies (PSP)**. Kyverno рассматривается как одна из альтернатив для замены PSP, наряду с OPA Gatekeeper.
