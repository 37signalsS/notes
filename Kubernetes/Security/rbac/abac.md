# Управление доступом на основе атрибутов (ABAC)

## Определения

**ABAC (Attribute-Based Access Control)** — альтернативный метод авторизации в Kubernetes, который принимает решения на основе комбинации атрибутов (пользователь, ресурс, объект, действие), а не фиксированных ролей.

В отличие от RBAC, политики ABAC обычно определяются в виде JSON-файлов на диске мастера и требуют перезагрузки API-сервера для применения (в стандартной реализации).

---

## Основные концепции

### Динамический контроль
ABAC позволяет реализовать более гибкие правила, основанные на:
- Ролях пользователей во внешних системах.
- Принадлежности к конкретным проектам.
- Метках или метаданных ресурсов.

### Приоритет использования
В современной инфраструктуре Kubernetes **RBAC является стандартом де-факто**. ABAC используется реже, в специфических сценариях или как дополнение к RBAC для реализации сложных условий доступа.

---

## Практические сценарии

### Пример политики ABAC (JSON)
Политика, разрешающая конкретному пользователю получать информацию о подах в пространстве имен `dev`.

```json
{
  "apiVersion": "abac.authorization.kubernetes.io/v1beta1",
  "kind": "Policy",
  "spec": {
    "user": "jane.doe@example.com",
    "namespace": "dev",
    "resource": "pods",
    "verb": "get"
  }
}
```

## Дополнительная информация

### Принцип наименьших привилегий
Независимо от выбранного метода (ABAC или RBAC), всегда следуйте принципу **минимальных привилегий (PoLP)**: предоставляйте пользователям и приложениям только те разрешения, которые необходимы для выполнения их текущих задач.
