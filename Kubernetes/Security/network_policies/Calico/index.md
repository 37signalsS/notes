# Calico HostEndpoint и GlobalNetworkPolicy

**Calico** расширяет стандартные сетевые политики Kubernetes, предоставляя возможности управления трафиком на уровнях узлов (host protection), всего кластера (GlobalNetworkPolicy) и внешних сетей. Это позволяет реализовать полноценный распределенный файрвол, интегрированный в инфраструктуру Kubernetes и поддерживающий высокопроизводительные механизмы обработки трафика, такие как eBPF и VPP.

> Основная документация: [NetworkPolicy: Сетевая безопасность](../../network_policies.md)

## Определения

**Felix** — основной агент Calico (DaemonSet), работающий на каждом узле кластера. Он отвечает за программирование маршрутов, ACL (правил фильтрации) и управление сетевыми интерфейсами. Felix транслирует политики в правила конкретного data plane (iptables, eBPF, nftables или VPP).

**Typha** — промежуточный прокси-агент (fan-out proxy), который используется в крупных кластерах (обычно более 100 узлов). Felix подключается к Typha вместо прямого обращения к Kubernetes API, что значительно снижает нагрузку на Control Plane при обновлении политик или состоянии подов.

**BIRD (BGP)** — встроенный демон маршрутизации, используемый Calico для распространения маршрутов между узлами по протоколу BGP. Это позволяет кластеру работать без оверлейных сетей (например, VXLAN) при наличии поддержки BGP в физической инфраструктуре.

**HostEndpoint** — ресурс Calico, представляющий сетевой интерфейс физического или виртуального узла. Позволяет применять политики безопасности к трафику самого хоста, защищая его от внешних угроз и контролируя административный доступ (SSH, API).

**GlobalNetworkPolicy** — кластерная политика, область действия которой не ограничена одним Namespace. Она применяется ко всем подам и узлам кластера, подходящим под селектор.

**GlobalNetworkSet** — глобальный набор IP-адресов или CIDR-диапазонов, к которому можно обращаться из политик по меткам. Удобен для группировки внешних ресурсов (например, "доверенные офисные сети", "публичные облака").

**WireGuard** — современный протокол шифрования, интегрированный в Calico для обеспечения безопасной передачи трафика между подами и узлами с минимальными накладными расходами на производительность.

## Архитектура и компоненты

Архитектура Calico построена на модульном принципе для обеспечения масштабируемости до тысяч узлов:

1.  **Хранилище данных (Datastore)**: Calico может использовать `etcd` напрямую или работать в режиме `Kubernetes API datastore` (рекомендуется).
2.  **Felix**: Инсталлирует правила в ядро Linux.
3.  **BIRD (BGP Client)**: Отвечает за обмен маршрутами. В режиме VXLAN/IPIP может быть отключен.
4.  **Confd**: Служба, которая мониторит изменения в конфигурации Calico и обновляет конфигурационные файлы BIRD.
5.  **Typha**: Опциональный компонент для горизонтального масштабирования доступа к API.

## Основные концепции

### Механизмы обработки трафика (Data Planes)

Calico поддерживает несколько режимов работы, выбираемых в зависимости от требований к производительности и версии ядра:

1.  **iptables**: Классический режим, обеспечивающий максимальную совместимость. Использует стандартные цепочки Linux для фильтрации.
2.  **eBPF**: Высокопроизводительный режим (Kernel 5.3+). Позволяет полностью заменить `kube-proxy`, снижает нагрузку на CPU, обеспечивает нативное сохранение Source IP и поддерживает DSR (Direct Server Return).
3.  **nftables**: Современная альтернатива iptables (введена в Calico 3.29). Обеспечивает лучшую производительность и совместимость с современными дистрибутивами Linux (например, RHEL 9).
4.  **VPP (Vector Packet Processing)**: Режим для сверхвысоких нагрузок (телеком), обеспечивающий обработку пакетов в User Space.

### Приоритеты, иерархия и Tiers

В отличие от стандартных NetworkPolicy Kubernetes, Calico предоставляет продвинутые механизмы управления порядком правил:

*   **Order**: Поле, определяющее приоритет. Чем ниже значение, тем выше приоритет.
*   **Policy Tiers**: Группировка политик по уровням (например, `security`, `platform`, `application`). Политики в уровне `security` всегда оцениваются раньше, чем в `application`, что позволяет администраторам задавать глобальные "гарды" (guardrails), которые нельзя переопределить на уровне приложения.
*   **Admin Network Policy (ANP)**: Поддержка стандартного Kubernetes API для управления кластерными политиками безопасности с четким разделением ролей.

### Расширенные селекторы

*   **ServiceAccount**: Выбор подов на основе связанного с ними SA.
*   **Wildcards**: Поддержка подстановочных знаков в метках.
*   **Host Selection**: Применение политик к узлам на основе меток (например, `kubernetes.io/hostname` или кастомных меток ролей).

### Фильтрация до NAT (preDNAT)

При использовании `HostEndpoint` Calico позволяет фильтровать трафик до того, как Kubernetes применит трансляцию адресов (DNAT) для NodePort или LoadBalancer. Это критически важно для защиты сервисов, открытых наружу, так как позволяет блокировать трафик на основе реальных внешних IP-адресов.

| Параметр | Описание |
| :--- | :--- |
| `preDNAT: true` | Политика применяется в цепочке PREROUTING, до DNAT. |
| `applyOnForward: true` | Применяется к транзитному трафику, проходящему через узел. |

### Безопасные порты (Failsafe Ports)

Для предотвращения случайной самоблокировки узла (lockout) Calico по умолчанию держит открытыми критические порты управления. Настройка осуществляется в ресурсе `FelixConfiguration`:
*   SSH (22)
*   BGP (179)
*   Kubernetes API (6443)

### Шифрование (WireGuard)

Calico позволяет включить прозрачное шифрование трафика между подами одной командой. В режиме eBPF поддерживается также шифрование трафика между самими хостами (Host-to-Host). Это обеспечивает соответствие требованиям безопасности (Zero Trust) без необходимости внедрения Service Mesh.

## Практические сценарии

*   **Защита периметра**: Блокировка несанкционированного доступа к узлам через `HostEndpoint`.
*   **Кластерный Default Deny**: Обеспечение изоляции всех пространств имен через `GlobalNetworkPolicy`.
*   **Микросегментация**: Тонкая настройка доступа между уровнями приложения (Tiered Policies).

*Подробные примеры конфигураций: [Практические сценарии Calico](./scenarios.md)*

## Дополнительная информация

### Диагностика и обслуживание

Для управления ресурсами Calico используется утилита **`calicoctl`**. Она позволяет просматривать состояние BGP-сессий, HostEndpoints и проверять корректность применения политик.
