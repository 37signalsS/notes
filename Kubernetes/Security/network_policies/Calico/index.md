# Calico HostEndpoint и GlobalNetworkPolicy

**Calico** расширяет стандартные сетевые политики Kubernetes, предоставляя возможности управления трафиком на уровнях узлов, всего кластера и внешних сетей. Это позволяет реализовать полноценный микросегментированный файрвол, интегрированный в инфраструктуру Kubernetes.

> Основная документация: [NetworkPolicy: Сетевая безопасность](../../network_policies.md)

## Определения

**Felix** — основной агент Calico, работающий на каждом узле кластера. Он отвечает за считывание политик из хранилища данных и их трансляцию в правила фильтрации в сетевом стеке узла (iptables, eBPF или VPP).

**HostEndpoint** — ресурс Calico, представляющий сетевой интерфейс физического или виртуального узла. Позволяет применять политики безопасности к трафику самого узла, защищая его от внешних угроз и контролируя административный доступ.

**GlobalNetworkPolicy** — кластерная политика, область действия которой не ограничена одним пространством имен (Namespace). Она применяется ко всем подам и узлам кластера, подходящим под селектор.

**GlobalNetworkSet** — глобальный набор IP-адресов или CIDR-диапазонов, к которому можно обращаться из политик по меткам. Удобен для группировки внешних ресурсов (например, "доверенные офисные сети", "публичные облака").

**NetworkSet** — аналогичный `GlobalNetworkSet` ресурс, но ограниченный конкретным пространством имен.

## Основные концепции

### Механизмы обработки трафика (Data Planes)

Calico поддерживает несколько режимов работы с трафиком:

1. **iptables**: Классический режим, обеспечивающий максимальную совместимость. Использует стандартные цепочки Linux для фильтрации.
2. **eBPF**: Современный высокопроизводительный режим. Позволяет полностью отказаться от `kube-proxy`, снижает нагрузку на CPU и обеспечивает сохранение Source IP клиента без использования `externalTrafficPolicy: Local`.
3. **VPP (Vector Packet Processing)**: Режим для сверхвысоких нагрузок (телеком, 5G), обеспечивающий обработку пакетов в пространстве пользователя.

### Приоритеты и порядок выполнения (order)

В отличие от стандартных NetworkPolicy Kubernetes, политики Calico поддерживают поле `order`:
* Чем ниже значение `order`, тем выше приоритет политики.
* Значение `order` позволяет выстраивать иерархию правил, например: сначала разрешить системный трафик, затем логировать подозрительную активность, и в конце запретить всё остальное.

### Расширенные селекторы

Calico позволяет использовать селекторы, недоступные в стандартном Kubernetes:
* **ServiceAccount**: Выбор подов на основе связанного с ними ServiceAccount.
* **Wildcards**: Поддержка подстановочных знаков в метках и именах.
* **Интеграция с HostEndpoint**: Применение политик к узлам на основе их меток (например, `role == 'worker'`).

### Фильтрация до NAT (preDNAT)

При использовании `HostEndpoint` Calico позволяет фильтровать трафик до того, как Kubernetes применит трансляцию адресов (DNAT) для NodePort или LoadBalancer. Это критически важно для защиты сервисов, открытых наружу.

| Параметр | Описание |
|----------|----------|
| `preDNAT: true` | Политика применяется в цепочке PREROUTING, до DNAT. |
| `applyOnForward: true` | Применяется к транзитному трафику, проходящему через узел. |

### Безопасные порты (Failsafe Ports)

Для предотвращения случайной самоблокировки узла (lockout) Calico по умолчанию держит открытыми критические порты управления (SSH: 22, BGP: 179, K8s API: 6443). Настройка портов осуществляется в ресурсе `FelixConfiguration`.

### Поддержка ICMP и протоколов L4

Calico позволяет явно разрешать или запрещать ICMP-трафик (пинги, сообщения о недоступности), что невозможно сделать стандартными средствами Kubernetes. Также поддерживаются TCP, UDP и SCTP.

## Практические сценарии

* **Защита периметра**: Настройка политик для `HostEndpoint` для блокировки несанкционированного доступа к узлам.
* **Кластерный Default Deny**: Использование `GlobalNetworkPolicy` для обеспечения безопасности во всех пространствах имен одновременно.
* **Логирование трафика**: Применение действия `action: Log` для аудита безопасности.

*Подробные примеры конфигураций: [Практические сценарии Calico](./scenarios.md)*

## Дополнительная информация

### Диагностика и обслуживание

Для управления ресурсами Calico используется утилита **`calicoctl`**. Она позволяет просматривать состояние BGP-сессий, HostEndpoints и проверять корректность применения политик.

*Руководство по диагностике: [Операции Calico: Диагностика и обслуживание](./operations.md)*
