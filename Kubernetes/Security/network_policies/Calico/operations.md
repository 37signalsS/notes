# Операции Calico: Диагностика и обслуживание

В данном разделе описаны процедуры проверки состояния, отладки и технического обслуживания специфичных ресурсов Calico, таких как HostEndpoint и GlobalNetworkPolicy.

> Основная документация: [Calico HostEndpoint и GlobalNetworkPolicy](./index.md)

## Определения

**Calico Operations** — регламентированные процедуры мониторинга, отладки и устранения неисправностей в сетевой подсистеме Calico, выходящие за рамки стандартных объектов Kubernetes.

**calicoctl** — специализированная CLI-утилита для управления ресурсами Calico (HostEndpoint, GlobalNetworkPolicy, FelixConfiguration, GlobalNetworkSet).

**Felix** — агент Calico, работающий на каждом узле кластера. Felix считывает информацию из базы данных Calico и формирует правила в сетевом стеке узла (iptables, eBPF).

**Data Store (Хранилище данных)** — база данных, в которой Calico хранит свою конфигурацию. Поддерживаются два типа:
* **Kubernetes API (kdd)**: Использование CRD (Custom Resource Definitions) внутри Kubernetes. Рекомендуемый режим.
* **etcd**: Прямое подключение к выделенному кластеру etcd.

## Основные концепции

### Инструменты диагностики

Для эффективного обслуживания кластера используются:

1. **calicoctl**: Позволяет работать с объектами в формате `projectcalico.org/v3`, которые недоступны через обычный `kubectl`.
2. **Статус Felix**: Проверка состояния агента, включая статус BGP-соседства и прогресс применения политик.
3. **Логи Felix**: Находятся в поде `calico-node` (контейнер `calico-node`) или в системном журнале узла.

### Сетевые параметры (MTU)

Неправильная настройка MTU (Maximum Transmission Unit) — частая причина проблем со связностью в Calico, особенно при использовании инкапсуляции (VXLAN/IPIP). MTU Calico должен быть на 20-50 байт меньше, чем MTU физического интерфейса.

## Практические сценарии

### Проверка состояния компонентов

Основные команды для аудита текущей конфигурации через `calicoctl`:

```bash
# Просмотр всех HostEndpoint
calicoctl get hostendpoints -o wide
# → Название, узел, интерфейс, IP-адреса

# Просмотр статуса BGP и узла
calicoctl node status
# → IPv4 BGP status: Established (указывает на успешное соединение с соседями)

# Проверка конфигурации Felix
calicoctl get felixconfiguration default -o yaml
# → Выводит параметры логирования, MTU, Failsafe порты
```

### Устранение неисправностей

| Проблема | Причина | Решение |
|----------|---------|---------|
| Потеря доступа по SSH после создания HostEndpoint | Не применены разрешающие политики или отсутствует метка на интерфейсе | Проверить наличие метки на HostEndpoint и существование политики с `action: Allow` для порта 22 |
| Политики не влияют на NodePort | Не включен режим `preDNAT` | Убедиться, что в GlobalNetworkPolicy установлено `preDNAT: true` |
| Ошибки BGP-соседства | Трафик на порт 179/TCP заблокирован файрволом | Разрешить порт 179 между всеми узлами кластера |
| Проблемы с большими пакетами (Timeout при передаче данных) | Несоответствие MTU | Настроить MTU в `FelixConfiguration` или `IPPool` (обычно 1430-1450 для VXLAN) |

### Изменение уровней логирования

Для детальной отладки можно временно повысить уровень логирования Felix:

```bash
# Установка уровня логирования в Debug
calicoctl patch felixconfiguration default --patch '{"spec": {"logSeverityScreen": "Debug"}}'
# → Felix начнет выводить детальную информацию о применении каждого правила
```

### Особенности фильтрации NodePort

Для корректной фильтрации трафика `NodePort` на уровне узла необходимо использовать политики с флагом `preDNAT: true`. Это позволяет заблокировать трафик до того, как он будет перенаправлен во внутреннюю сеть кластера.
