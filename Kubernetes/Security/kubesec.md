# Kubesec: Анализ рисков и сканер безопасности в Kubernetes

## Определения

**Kubesec** — это мощный инструмент с открытым исходным кодом, предназначенный для анализа рисков безопасности в конфигурациях и манифестах Kubernetes. Его цель — помочь администраторам и разработчикам выявлять потенциальные уязвимости и улучшать безопасность кластеров.

Kubesec (<https://github.com/controlplaneio/kubesec>) проверяет YAML-манифесты Kubernetes на рискованные настройки безопасности и возвращает score (оценку) + список сработавших правил.

**Важно:** Kubesec работает **до деплоя** (статический анализ). Для проверок во время деплоя используйте [Kyverno](./kyverno.md), для аудита инфраструктуры — [kube-bench](./kube-bench.md).

## Основные концепции

* **Проверка конфигураций Kubernetes:** Анализ манифестов YAML для оценки безопасности различных объектов (Pod, Deployment, Service, DaemonSet, StatefulSet, CronJob и др.), включая сканирование нескольких документов YAML из одного файла.
* **Гибкие способы использования:** Может быть установлен через образ контейнера, двоичный файл или как плагин для `kubectl`. Есть возможность запуска в качестве контроллера допуска (Admission Controller) в Kubernetes для блокировки небезопасных развертываний на уровне кластера.
* **Kubesec-as-a-Service:** Облачное сканирование через HTTPS по адресу: `v2.kubesec.io/scan` для быстрой проверки манифестов без локальной установки.
* **Встроенный HTTP-сервер:** Локальный сервер, доступный по умолчанию на порту `8080`, для анализа манифестов по запросу. Это удобно для интеграции в локальные скрипты или CI-пайплайны.
* **Оценка риска (score):** Анализ манифестов с присвоением оценки, где более высокий балл указывает на лучшую безопасность.
* **Детальный JSON-отчёт:** Предоставляет информацию о выявленных проблемах, причинах и рекомендациях по исправлению, с указанием конкретных правил.
* **Просмотр правил оценки:** Доступ к правилам, по которым начисляются/снимаются баллы, что способствует пониманию лучших практик безопасности.
* **Интеграция в CI/CD:** Возможность блокировать сборку при низком score, внедряя "ворота качества" (Quality Gates) для обеспечения безопасности.

## Практические сценарии

### Установка Kubesec

* **Через контейнер (рекомендуется для CI/CD и быстрого использования):**

    ```bash
    docker run kubesec/kubesec:latest
    ```

    Это обеспечивает запуск сканирования без установки зависимостей на хост-системе.

* **Через двоичный файл:**
    1. Загрузите соответствующий пакет с официального репозитория Kubesec для вашей операционной системы (Linux, macOS, Windows).
    2. Сделайте файл исполняемым:

        ```bash
        chmod +x ./kubesec
        ```

* **Для `kubectl` (как плагин):**
    Добавьте Kubesec как плагин для `kubectl` для прямого вызова через `kubectl kubesec ...`.

    ```bash
    kubectl krew install kubesec # Если у вас установлен krew
    # Или ручная установка:
    # kubectl plugin add kubesec
    ```

### Примеры использования

* **Сканирование локального файла YAML:**

    ```bash
    kubesec scan pod.yaml
    ```

    Эта команда просканирует указанный файл `pod.yaml` и выведет отчет о безопасности.

* **Сканирование через HTTP-сервер (локально):**
    Запустите Kubesec как сервер, а затем отправьте манифест на сканирование:

    ```bash
    docker run -p 8080:8080 kubesec/kubesec:latest serve
    curl -X POST --data-binary @pod.yaml http://localhost:8080/scan
    ```

    Это подходит для автоматизированных систем.

* **Облачный анализ (Kubesec-as-a-Service):**
    Манифесты можно загрузить через веб-интерфейс на `v2.kubesec.io` или отправить через API для анализа. **Внимание:** Не отправляйте конфиденциальные манифесты на публичные сервисы.

    ```bash
    curl -sS --request POST --data-binary @pod.yaml https://v2.kubesec.io/scan
    ```

### Интеграция в CI/CD

**GitLab CI пример**:

```yaml
security-scan:
  stage: test
  image: kubesec/kubesec:latest
  script:
    - kubesec scan k8s/ | jq '.score' | grep -q '^^2$' || exit 1
```

**Пороговые значения**:
- **score < 0** — критические уязвимости, блокировка деплоя
- **score 0–5** — предупреждения, рекомендуется исправление
- **score > 5** — приемлемый уровень
