# Kubesec: Анализ рисков и сканер безопасности в Kubernetes

## 1. Определения

**Kubesec** — это мощный инструмент с открытым исходным кодом, предназначенный для анализа рисков безопасности в конфигурациях и манифестах Kubernetes. Его цель — помочь администраторам и разработчикам выявлять потенциальные уязвимости и улучшать безопасность кластеров.

Kubesec (https://github.com/controlplaneio/kubesec) проверяет YAML-манифесты Kubernetes на рискованные настройки безопасности и возвращает score (оценку) + список сработавших правил.

Инструмент помогает быстро находить небезопасные параметры (например, запуск контейнеров с `privileged: true`, использование `hostPath`, `capabilities`, `runAsRoot` и отсутствие `securityContext`) ещё до развертывания — локально или в CI/CD.

## 2. Основные концепции и ключевые возможности

### 2.1. Ключевые возможности Kubesec

1.  **Проверка конфигураций Kubernetes:**
    *   Анализ манифестов YAML для оценки безопасности объектов (Pod, Deployment, Service, DaemonSet, StatefulSet, CronJob и др.).
    *   Сканирование нескольких документов YAML из одного файла.
2.  **Гибкие способы использования:**
    *   Установка через образ контейнера, двоичный файл или плагин для `kubectl`.
    *   Возможность запуска как контроллера допуска (Admission Controller) в Kubernetes, что позволяет блокировать развертывание небезопасных ресурсов на уровне кластера.
3.  **Kubesec-as-a-Service:** Облачное сканирование через HTTPS по адресу: `v2.kubesec.io/scan`. Позволяет быстро проверить манифесты без локальной установки.
4.  **Встроенный HTTP-сервер:**
    *   Локальный сервер для анализа манифестов по запросу.
    *   По умолчанию доступен на порту `8080`.
    *   Полезно для интеграции в локальные скрипты или в CI-пайплайны.

### 2.2. Основной функционал (повторение и уточнение)

*   Анализ манифестов (Deployment/Pod/DaemonSet и др.) с оценкой риска (score), где более высокий балл указывает на лучшую безопасность.
*   Детальный JSON-отчёт: что именно не так и почему, с указанием конкретных правил и рекомендаций по исправлению.
*   Просмотр правил оценки (за что начисляются/снимаются баллы), что способствует пониманию лучших практик безопасности.
*   Интеграция в CI/CD: возможность блокировать сборку при низком score, внедряя "ворота качества" (Quality Gates) для безопасности.

## 3. Практические сценарии

### 3.1. Как установить Kubesec?

Kubesec можно установить несколькими способами в зависимости от ваших потребностей:

*   **Через контейнер (рекомендуется для CI/CD и быстрого использования):**
    ```bash
    docker run kubesec/kubesec:latest
    ```
    Это самый простой способ запустить сканирование без установки зависимостей на хост-системе.

*   **Через двоичный файл:**
    1.  Загрузите соответствующий пакет с официального репозитория Kubesec для вашей операционной системы (Linux, macOS, Windows).
    2.  Сделайте его исполняемым:
        ```bash
        chmod +x ./kubesec
        ```

*   **Для `kubectl` (как плагин):**
    Добавьте Kubesec как плагин для `kubectl`. Это позволяет вызывать `kubesec` напрямую через `kubectl kubesec ...`.
    ```bash
    kubectl krew install kubesec # Если у вас установлен krew
    # Или ручная установка:
    # kubectl plugin add kubesec
    ```

### 3.2. Примеры использования

*   **Сканирование локального файла YAML:**
    ```bash
    kubesec scan pod.yaml
    ```
    Эта команда просканирует указанный файл `pod.yaml` и выведет отчет о безопасности.

*   **Сканирование через HTTP-сервер (локально):**
    Запустите Kubesec как сервер:
    ```bash
    docker run -p 8080:8080 kubesec/kubesec:latest serve
    # Затем отправьте манифест на сканирование:
    curl -X POST --data-binary @pod.yaml http://localhost:8080/scan
    ```
    Это удобно для автоматизированных систем, которые могут отправлять манифесты на анализ.

*   **Облачный анализ (Kubesec-as-a-Service):**
    Вы можете загрузить файл манифеста через веб-интерфейс на `v2.kubesec.io` или отправить его через API для анализа. **Внимание:** Не отправляйте конфиденциальные манифесты на публичные сервисы.
    ```bash
    # Пример отправки на публичный сервис (используйте с осторожностью!)
    curl -sS --request POST --data-binary @pod.yaml https://v2.kubesec.io/scan
    ```

## 4. Зачем использовать Kubesec?

*   **Отладка и тестирование:** Выявление проблем безопасности на ранних этапах разработки и тестирования.
*   **Оптимизация безопасности:** Улучшение общей безопасности кластера Kubernetes путем устранения выявленных уязвимостей.
*   **Соответствие стандартам:** Помогает придерживаться лучших практик безопасности и соответствовать нормативным требованиям.
*   **Автоматизация:** Интеграция в CI/CD пайплайны для автоматического сканирования и предотвращения развертывания небезопасных конфигураций.
