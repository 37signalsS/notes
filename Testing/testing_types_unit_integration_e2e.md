# Виды тестирования: Unit, Integration, E2E

## 1. Определения

**Пирамида тестирования (Testing Pyramid)** — классическая модель, описывающая иерархию тестов. Основание составляют многочисленные быстрые Unit-тесты, середину — интеграционные, вершину — минимальное количество E2E-тестов.

**Тестовый трофей (Testing Trophy)** — современная модель (популярна в Frontend и микросервисах), где основной фокус смещен на интеграционные тесты, дающие максимальный баланс между скоростью и уверенностью.

**Unit-тесты (Модульные)** — проверка минимально изолированной части кода (функции, метода) в полной изоляции с использованием дублёров (Mocks/Stubs).

**Integration-тесты (Интеграционные)** — проверка взаимодействия между несколькими компонентами (например, код + БД) или между микросервисами.

**Contract Testing (Контрактное тестирование)** — верификация совместимости между потребителем (Consumer) и поставщиком (Provider) API без запуска всей системы.

**End-to-End (E2E) тесты (Сквозные)** — имитация реальных сценариев пользователя через все слои системы (UI → API → DB).

## 2. Основные концепции

### Сравнение моделей: Пирамида vs Трофей

Выбор стратегии зависит от архитектуры приложения:

| Модель | Фокус | Сценарий использования |
| :--- | :--- | :--- |
| **Пирамида** | Unit-тесты | Монолиты, сложные алгоритмы, тяжелая бизнес-логика. |
| **Трофей** | Интеграционные тесты | Frontend (React/Vue), микросервисная архитектура. |
| **Ромб (Diamond)** | Интеграционные + Unit | Сбалансированные системы с умеренным количеством внешних связей. |

### Современные виды тестирования (2025–2026)

*   **Contract Testing (Pact):** Позволяет избежать "Breaking Changes" в микросервисах. В 2026 году стандартом стало **Bi-directional Contract Testing**, где контракты сравниваются статически на основе спецификаций OpenAPI.
*   **Visual AI Regression:** Использование AI для сравнения интерфейсов. В отличие от пиксельного сравнения, Visual AI понимает структуру DOM и игнорирует незначительные сдвиги (1px) или динамические данные.
*   **Trace-based Testing (Observability-driven):** Использование OpenTelemetry для проверки "внутренностей" процесса. Тест проверяет не только HTTP-ответ, но и наличие конкретных спанов (spans) в трейсе (например, "был ли сделан запрос к БД").

### Сравнение уровней тестирования

| Критерий | Unit | Integration | E2E | Contract |
| :--- | :--- | :--- | :--- | :--- |
| **Объект** | Функция / Класс | Группа модулей | Бизнес-сценарий | API Интерфейс |
| **Зависимости** | Дублёры (Mocks) | Реальные (Docker) | Полный стек | Спецификации |
| **Скорость** | Миллисекунды | Секунды | Минуты | Секунды |
| **Надёжность** | Детерминированная | Высокая | Подвержены Flaky | Высокая |
| **Инструменты** | pytest, Jest | Testcontainers | Playwright | Pact, MockServer |

## 3. Практические сценарии

### Интеграционный тест с БД (Python + Testcontainers)

Вместо моков используется реальная БД в контейнере, что повышает достоверность теста.

```python
from testcontainers.postgres import PostgresContainer
import sqlalchemy

def test_user_persistence():
    with PostgresContainer("postgres:16") as postgres:
        engine = sqlalchemy.create_engine(postgres.get_connection_url())
        # Логика проверки записи в реальную БД
        with engine.connect() as conn:
            conn.execute(sqlalchemy.text("CREATE TABLE users (name TEXT)"))
            conn.execute(sqlalchemy.text("INSERT INTO users VALUES ('admin')"))
            result = conn.execute(sqlalchemy.text("SELECT name FROM users")).scalar()
            assert result == "admin"
```

### Сквозной тест с Visual AI (Playwright)

Проверка визуальной целостности страницы.

```javascript
// playwright.config.ts
import { expect, test } from '@playwright/test';

test('visual regression check', async ({ page }) => {
  await page.goto('/dashboard');
  // Сравнение снимка с эталоном (AI-алгоритмы игнорируют динамические даты)
  await expect(page).toHaveScreenshot('dashboard-main.png', {
    maxDiffPixelRatio: 0.05 
  });
});
```

## 4. Дополнительная информация

### AI-Augmented Testing (2026)

Современные инструменты тестирования активно используют AI для снижения стоимости поддержки:
*   **Self-healing (Самолечение):** Тесты автоматически обновляют CSS/XPath локаторы при изменении верстки, если функциональная суть элемента не изменилась.
*   **Agentic QA:** Использование ИИ-агентов для исследования "неисследованных путей" (exploratory testing) и автоматической генерации тестовых сценариев на основе User Stories.
*   **Intelligent Reruns:** Автоматический анализ падений (RCA) и классификация: реальный баг или нестабильность (flaky).

### Принципы надежности (FIRST)

Каждый тест, независимо от уровня, должен быть:
*   **Fast** (Быстрым): не тормозить пайплайн.
*   **Independent** (Независимым): порядок запуска не важен.
*   **Repeatable** (Повторяемым): стабилен в CI и локально.
*   **Self-validating** (Самопроверяемым): четкий Pass/Fail без участия человека.
*   **Timely** (Своевременным): написан вместе с кодом.
