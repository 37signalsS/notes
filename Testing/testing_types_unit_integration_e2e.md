# Виды тестов: unit, integration, e2e

## Обзор

Три основных уровня автоматизированного тестирования решают разные задачи качества и скорости обратной связи. Баланс между ними образует «пирамиду тестирования»: максимум быстрых и изолированных unit-тестов, меньше интеграционных и ещё меньше, но самых реалистичных e2e.

## Сравнение уровней

| Критерий | Unit | Integration | E2E |
|----------|------|-------------|-----|
| Цель | Проверка отдельной функции/класса | Взаимодействие модулей и внешних систем | Поведение всей системы «как пользователь» |
| Гранулярность | Мелкая | Средняя | Крупная |
| Зависимости | Изолируются дублёрами | Ограниченно реальны (DB, очередь) | Максимально реальны (UI, API, сеть) |
| Скорость | Миллисекунды | Секунды | Минуты |
| Надёжность | Высокая, детерминированная | Средняя | Подвержены флаки |
| Частота запуска в CI | На каждый коммит/PR | По метке, nightly, перед релизом | Ночные/предрелизные пайплайны |
| Сигнал о причине | Точный | Средний | Часто расплывчатый |

## Тестовые дублёры и данные

### Unit-тесты
- Активное использование mocks/stubs для изоляции I/O, часов, сети
- Предпочтительна инъекция зависимостей
- Фикстуры минимальны, данные — маленькие и синтетические

### Integration-тесты
- Минимум моков; допустимы фейки инфраструктуры (in-memory DB, локальный брокер)
- Полезны контрактные тесты для клиент–сервис взаимодействий

### E2E-тесты
- Реальные окружения и данные, но «маскированные» или фабрикованные
- Фокус на happy-path и критические пользовательские сценарии
- Не допускается нестабильность из-за гонок и таймингов — применяются явные ожидания

## Организация проекта

Структура каталогов может отражать уровни:
- `tests/unit/` — быстрая проверка логики
- `tests/integration/` — работа с БД/очередями
- `tests/e2e/` — пользовательские потоки

## Примеры

### Unit-пример на pytest с моками времени и сети

```python
# app/math.py
def add(a, b): return a + b

# tests/unit/test_math.py
from app.math import add

def test_add_simple():
    assert add(2, 3) == 5
```

### Интеграционный тест с реальной БД (sqlite для простоты)

```python
# app/repo.py
import sqlite3
def get_users(conn): return conn.execute("select name from users").fetchall()

# tests/integration/test_repo.py
import sqlite3
from app.repo import get_users

def test_get_users_with_real_db(tmp_path):
    db = tmp_path / "app.db"
    conn = sqlite3.connect(db)
    conn.execute("create table users(name text)")
    conn.execute("insert into users values ('alice')")
    assert get_users(conn) == [('alice',)]
```

### E2E через HTTP-запросы к развернутому сервису

```bash
# tests/e2e/smoke.sh
set -euo pipefail
BASE_URL="${BASE_URL:-http://localhost:8080}"
code=$(curl -s -o /dev/null -w "%{http_code}" "$BASE_URL/health")
[ "$code" = "200" ]
token=$(curl -s -X POST "$BASE_URL/login" -d 'u=demo&p=demo')
[ -n "$token" ]
```
