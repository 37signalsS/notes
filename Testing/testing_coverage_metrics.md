# Метрики тестового покрытия

## Определения

- **Тестовое покрытие (Code Coverage)** — количественная метрика, которая показывает, какой процент исполняемого кода был затронут во время выполнения автоматизированных тестов. Метрика не является прямой оценкой качества тестов, но эффективно подсвечивает нетестированные участки кода.

## Основные концепции

### Виды покрытия

Различные метрики покрытия позволяют анализировать код с разных сторон.

| Тип покрытия | Что измеряет | Сценарий использования |
| :--- | :--- | :--- |
| **Строк (Line)** | Доля исполненных строк кода. | Базовая оценка широты тестов. |
| **Ветвей (Branch)** | Доля пройденных условных ветвлений (`if/else`, `switch`). | Анализ логики и обработки крайних случаев. |
| **Функций/Методов** | Доля вызванных в ходе тестов функций. | Оценка покрытия API (Application Programming Interface) на сервисном уровне. |
| **Мутационное** | Способность тестов обнаруживать искусственно внесённые ошибки (мутации). | Оценка силы и чувствительности тестов. |

Чаще всего на практике используют комбинацию покрытия строк и ветвей.

## Практические сценарии

### Отчётность о покрытии

Инструменты анализа покрытия генерируют отчёты в двух форматах:

1. **HTML (HyperText Markup Language)** — интерактивный отчёт для локального анализа, подсвечивающий непокрытые строки кода.
2. **XML (eXtensible Markup Language) / LCOV** — машиночитаемые форматы (например, Cobertura, JaCoCo) для интеграции с системами CI/CD (Continuous Integration / Continuous Deployment).

### Типовые инструменты

- **Java / Kotlin**: JaCoCo
- **JavaScript / TypeScript**: Istanbul / nyc
- **Python**: `coverage.py` (`pytest-cov`)
- **Go**: `go test -coverprofile`
- **C / C++**: `gcov` + `lcov`

### Интеграция в GitLab CI

Пример демонстрирует запуск тестов с анализом покрытия, публикацию HTML-отчёта как артефакта и использование Cobertura-отчёта для интеграции с GitLab.

```yaml
test:coverage:
  stage: test
  script:
    - pip install pytest pytest-cov
    - pytest \
        --cov=app --cov-branch \
        --cov-report=xml:coverage.xml \
        --cov-report=html \
        --cov-fail-under=80
  artifacts:
    when: always
    reports:
      cobertura: coverage.xml
    paths:
      - htmlcov/
    expire_in: 7 days
```

Такой подход позволяет автоматически контролировать порог покрытия и блокировать слияние веток, если он не достигнут.

## Дополнительная информация

### Мутационное тестирование

Мутационное тестирование — метод оценки качества тестов путём внесения искусственных ошибок (мутаций) в код.

**Процесс:**

1. Инструмент создаёт мутации кода (изменяет операторы, значения).
2. Запускаются тесты на мутировавшем коде.
3. Если тесты падают — мутация «убита» (тесты эффективны).
4. Если тесты проходят — мутация «выжила» (тесты недостаточно чувствительны).

**Инструменты:**

- **Java**: PITest
- **JavaScript**: Stryker
- **Python**: mutmut, cosmic-ray
- **Ruby**: mutant

### Дифф-покрытие (Diff Coverage)

Дифф-покрытие — метрика, измеряющая покрытие только для изменённых строк кода в MR (Merge Request) или PR (Pull Request).

**Преимущества:**

- Не требует высокого покрытия всего унаследованного (legacy) кода.
- Мотивирует покрывать новый код.
- Обеспечивает быструю проверку в CI/CD.

**Инструменты:**

- **diff-cover** (Python) — интеграция с `coverage.py`.
- **Jacoco Diff Coverage** (Java).
- **Codecov** / **Coveralls** — SaaS (Software as a Service) сервисы с дифф-анализом.

### Рекомендации по применению

- **Исключения**: Исключайте из анализа сгенерированный код, миграции базы данных и файлы без логики.
- **Пороги**: Устанавливайте реалистичные пороги. Часто используют два уровня: общий для проекта и более строгий для нового кода в MR.
- **Качество против количества**: Высокое покрытие не гарантирует качества. Тесты должны содержать осмысленные проверки (ассерты), а не просто выполнять код.
