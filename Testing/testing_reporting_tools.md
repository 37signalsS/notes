# Инструменты для генерации отчётов о тестировании

## Определения

- **Тестовый отчёт (Test Report)** — документ, содержащий результаты выполнения тестов. Используется для анализа стабильности продукта и качества релизов.
- **Машиночитаемые отчёты (JUnit XML)** — формат обмена данными, предназначенный для автоматической обработки CI/CD (Continuous Integration / Continuous Deployment) системами.
- **Человекочитаемые отчёты (Allure Report)** — интерактивные HTML-отчёты с глубокой детализацией, предназначенные для аналитики и отладки человеком.

## Основные концепции

### Формат JUnit XML: стандарт для автоматизации

Формат **JUnit XML** является стандартом де-факто для интеграции результатов тестирования с инструментами автоматизации. Большинство современных CI-систем (Jenkins, GitLab CI, GitHub Actions) умеют парсить эти файлы для:

- Визуализации статуса прохождения тестов в интерфейсе пайплайна.
- Сбора статистики по времени выполнения.
- Автоматического блокирования деплоя при наличии падений.

### Allure Report: аналитика и визуализация

**Allure** — это мощный фреймворк для создания отчётов, который агрегирует результаты прогонов и предоставляет:

- **Детализацию прохождения**: дерево тестов, шаги (steps), вложения (скриншоты, логи, дампы ответов).
- **Тренды и историю**: графики изменения качества во времени и стабильности отдельных тестов.
- **Классификацию дефектов**: разделение на продуктовые баги, ошибки инфраструктуры и нестабильные (flaky) тесты.

## Практические сценарии

### Команды генерации отчётов

| Инструмент | Команда | Примечание |
| :--- | :--- | :--- |
| **Pytest** | `pytest --junitxml=report.xml --alluredir=allure-results` | Создаёт XML и сырые данные Allure |
| **Maven** | `mvn test` | Генерирует XML в `target/surefire-reports` |
| **Allure** | `allure generate allure-results -o allure-report --clean` | Собирает HTML-отчёт из сырых данных |

### Интеграция в пайплайны GitLab CI

Использование артефактов позволяет интегрировать результаты тестов непосредственно в интерфейс Merge Request.

```yaml
test_job:
  stage: test
  script:
    - pip install pytest allure-pytest
    - pytest --junitxml=report.xml --alluredir=allure-results
    - allure generate allure-results -o allure-report --clean
  artifacts:
    when: always
    reports:
      junit: report.xml
    paths:
      - allure-report/
    expire_in: 7 days
```

Подробнее о работе с отчётами в GitLab CI читайте в разделе **[Артефакты GitLab CI](../CI-CD/GitLab_CI/Advanced/gitlab_ci_caching/gitlab_ci_artifacts.md)**.

## Дополнительная информация

### Сравнение инструментов отчётности (2025–2026)

| Инструмент | Формат | Сценарий использования |
| :--- | :--- | :--- |
| **Allure Report** | HTML | Основной инструмент для командной аналитики |
| **JUnit HTML Report** | HTML | Быстрая локальная визуализация JUnit XML |
| **pytest-html** | HTML | Легковесный плагин для небольших Python-проектов |
| **ReportPortal** | SaaS (Software as a Service) / On-prem | AI (Artificial Intelligence) аналитика и долгосрочное хранение для Enterprise |
| **TestDino** | SaaS | Автоматический анализ причин падений на базе AI |

### Рекомендации

- **Консистентное именование**: Используйте понятные названия для тестовых наборов и методов, так как они ложатся в основу структуры отчёта.
- **Артефакты отладки**: Настраивайте автоматическое прикрепление скриншотов и логов браузера/API только для упавших тестов, чтобы экономить место.
- **Агрегация в параллели**: При использовании параллельного запуска (например, `pytest-xdist`) убедитесь, что все узлы пишут результаты в одну директорию перед финальной генерацией Allure.
