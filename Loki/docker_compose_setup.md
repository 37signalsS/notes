# Настройка Loki с помощью Docker Compose

## Определения

**[Loki](loki_overview.md)** — это система агрегации логов, разработанная Grafana Labs. Она индексирует только метаданные (метки), а не полный текст логов, что делает ее экономичной и быстрой для большинства задач мониторинга.

## Основные концепции

Для полноценного сбора логов в Docker с использованием Loki, как правило, требуется три компонента:

1.  **Loki**: Сервер, который принимает, хранит и индексирует логи.
2.  **Promtail** (или другой клиент): Агент, который обнаруживает логи контейнеров, прикрепляет к ним метки и отправляет их в Loki. **Без агента-сборщика логи не будут попадать в Loki**.
3.  **Grafana**: Платформа для визуализации, которая используется для отправки запросов (на языке [LogQL](loki_overview.md#язык-запросов-logql)) и анализа логов, хранящихся в Loki.

Эта заметка описывает настройку сервисов `loki` и `grafana`. Настройка агента `promtail` рассматривается отдельно.

## Практические сценарии

### 1. Конфигурация Docker Compose

Добавим сервис `loki` в основной файл `docker-compose.yml` вашего стека мониторинга и обеспечим его интеграцию с Grafana.

#### docker-compose.yml

```yaml
# monitoring/docker-compose.yml

services:
  prometheus:
    # ... (конфигурация Prometheus)

  grafana:
    # ... (конфигурация Grafana)
    # Убедитесь, что Grafana находится в той же сети, что и Loki

  loki:
    image: grafana/loki:latest # Для production рекомендуется фиксировать версию
    container_name: ${PROJECT_NAME}-loki
    ports:
      - "3100:3100"
    command: -config.file=/etc/loki/local-config.yaml
    restart: always

volumes:
  prom_data:
```

- **`image: grafana/loki`**: Используется официальный образ Loki.
- **`ports`**: Публикует стандартный порт Loki `3100`.
- **`command`**: Указывает Loki использовать базовый конфигурационный файл (в данном случае для локального хранения).

#### datasources.yaml для Grafana

Чтобы Grafana могла запрашивать логи из Loki, необходимо добавить Loki как источник данных через провиженинг.

```yaml
# monitoring/grafana/provisioning/datasources/datasources.yaml

apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    url: http://prometheus:9090
    isDefault: true
    editable: true

  - name: Loki
    type: loki
    url: http://loki:3100
    access: proxy
    basicAuth: false
    editable: false
    version: 1
```

- **`type: loki`**: Указывает на тип источника данных.
- **`url: http://loki:3100`**: Адрес сервера Loki, доступный из Grafana по имени сервиса в Docker-сети.
- **`access: proxy`**: Рекомендуемый режим доступа, при котором запросы к источнику данных идут через бэкенд Grafana, а не напрямую из браузера.
- **`editable: false`**: Запрещает редактирование источника данных через UI, так как он управляется кодом.

### 2. Запуск и проверка

1.  Обновите `docker-compose.yml` и `grafana/provisioning/datasources/datasources.yaml`.
2.  Перезапустите стек мониторинга:
    ```bash
    # Сначала остановим и удалим старые контейнеры
    docker-compose down

    # Запускаем обновленную конфигурацию
    docker-compose up -d
    ```
3.  Войдите в Grafana (`http://localhost:3000`) и перейдите в **Connections -> Data sources**. Убедитесь, что `Loki` присутствует в списке.
4.  Откройте вкладку **Explore** и выберите источник данных `Loki`. На данном этапе, пока не настроен сборщик логов (например, Promtail), вы можете проверить доступность, выполнив запрос `{}`. Он должен вернуть пустой результат, а не ошибку.

## Дополнительная информация

### Постоянное хранилище (Persistence)

В приведенной базовой конфигурации не используются персистентные вольюмы для Loki. Это означает, что **логи будут теряться при перезапуске контейнера**. Для production-окружения необходимо настроить хранилище. Подробнее о вариантах конфигурации можно прочитать в официальной документации или в основном обзоре: **[Loki: Конфигурация](loki_overview.md#конфигурация)**.

### Сбор логов (Promtail)

Для того чтобы логи из ваших приложений и контейнеров начали поступать в Loki, необходимо настроить агент-сборщик, например, **Promtail**. Его задача — читать логи, присваивать им метки (например, имя контейнера, сервиса) и отправлять в Loki. Без этого шага Loki будет пуст.
