# Grafana Loki — обзор системы агрегации логов

## Определения

**Grafana Loki** — это горизонтально масштабируемая, высокодоступная, мульти-тенантовая система агрегации логов, вдохновленная принципами Prometheus. В отличие от традиционных систем (например, Elasticsearch), Loki не индексирует полный текст логов, а фокусируется на метаданных (метках). Сами логи сжимаются и хранятся в виде объектов.

**Loki 3.x (Актуальная версия):** Начиная с версии 3.0, в систему добавлена нативная поддержка Bloom-фильтров для ускорения поиска по неиндексированным данным и механизм структурированных метаданных. Это позволяет Loki конкурировать по скорости поиска с полнотекстовыми системами, сохраняя при этом низкую стоимость владения.

## Основные концепции

### Ключевые особенности Loki 3.x

*   **Экономичное хранение:** Индексируются только метки (labels), что на порядок снижает объем индекса. Логи хранятся в объектных хранилищах (S3, GCS, MinIO).
*   **Bloom-фильтры:** Новая технология ускорения запросов. Позволяет быстро определять отсутствие искомой строки в блоке данных, исключая лишние операции чтения. Это значительно ускоряет "grep-подобные" запросы.
*   **Структурированные метаданные (Structured Metadata):** Позволяют прикреплять контекст к строкам логов без создания новых лейблов. Это предотвращает "взрыв кардинальности" (label cardinality explosion), сохраняя возможность фильтрации.
*   **LogQL:** Язык запросов, максимально близкий к PromQL. Позволяет не только искать текст, но и генерировать временные ряды (метрики) из логов на лету.
*   **Корреляция «из коробки»:** Благодаря идентичной модели метаданных с Prometheus, переход от графиков метрик к соответствующим логам в Grafana происходит бесшовно.

### Архитектура компонентов

Loki состоит из набора микросервисов, которые могут работать в монолитном (один процесс) или распределенном режиме.

*   **Gateway:** Единая точка входа (Nginx/Ingress), распределяющая запросы между Read и Write компонентами.
*   **Distributor (Дистрибьютор):** Принимает входящие потоки логов, проверяет их на валидность и распределяет по инжестерам.
*   **Ingester (Инжестер):** Формирует "чанки" логов в памяти и записывает их в постоянное хранилище.
*   **Querier (Запросчик):** Выполняет поиск по логам, запрашивая данные одновременно из памяти инжестеров (свежие логи) и из объектного хранилища (исторические данные).
*   **Query Frontend:** Кэширует результаты запросов и разделяет тяжелые запросы на параллельные подзапросы.
*   **Index Gateway:** Управляет доступом к индексам TSDB.
*   **Bloom Gateway / Builder:** Компоненты для создания и использования Bloom-фильтров (в версии 3.x).
*   **Compactor:** Объединяет файлы индексов и применяет политики удаления данных (retention).

### Язык запросов LogQL

Запрос состоит из селектора потока и конвейера обработки (pipeline).

**Пример структуры:**
`{app="api", env="prod"} |= "error" | json | duration > 500ms`

1.  **Селектор:** `{app="api", env="prod"}` — выбирает нужные потоки логов.
2.  **Текстовый фильтр:** `|= "error"` — оставляет строки, содержащие слово.
3.  **Парсер:** `| json` — извлекает поля из JSON-строки.
4.  **Фильтр по полям:** `duration > 500ms` — математическое условие.

## Практические сценарии

### Выбор способа установки

*   **Kubernetes (Helm):** Рекомендуемый способ для Production. Поддерживает режимы Simple Scalable и Distributed. [Инструкция по установке в K8s](./loki_stack_setup/loki_installation.md).
*   **Docker Compose:** Идеально для локальной разработки и небольших проектов. [Пример настройки Docker Compose](../Grafana/Installation/docker_compose_setup.md).
*   **Бинарный запуск:** Подходит для Bare-metal серверов.

### Конфигурация (Loki 3.x)

Современная конфигурация использует индекс **TSDB** и схему **v13**. Использование BoltDB-shipper считается устаревшим.

**Пример фрагмента `loki.yaml`:**

```yaml
common:
  path_prefix: /loki
  replication_factor: 3
  storage:
    s3:
      endpoint: s3.amazonaws.com
      bucketnames: loki-data

schema_config:
  configs:
    - from: "2024-04-01"
      store: tsdb
      object_store: s3
      schema: v13
      index:
        prefix: index_
        period: 24h

# Активация ускорения запросов (Bloom Filters)
bloom_build_config:
  enabled: true
bloom_gateway:
  enabled: true

limits_config:
  allow_structured_metadata: true
  retention_period: 30d
```

### Сравнение с Elasticsearch (OpenSearch)

| Характеристика | Grafana Loki | Elasticsearch |
| :--- | :--- | :--- |
| **Индексация** | Только метаданные (метки) + Bloom-фильтры | Полнотекстовый инвертированный индекс |
| **Стоимость хранения** | Очень низкая (S3) | Высокая (требуется много дисков под индекс) |
| **Скорость поиска** | Очень высокая для новых данных, средняя для старых | Высокая для всех данных (при наличии RAM) |
| **Сложность** | Низкая (не нужны маппинги) | Высокая (шарды, рефреши, схемы) |
| **Корреляция** | Нативная с Prometheus и Tempo | Требует настройки через Logstash/OTel |
