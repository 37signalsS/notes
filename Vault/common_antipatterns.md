# Антипаттерны управления секретами

## Определения

**Антипаттерн управления секретами** — это распространенная, но неэффективная или опасная практика обработки конфиденциальных данных (паролей, ключей, токенов). Эти ошибки часто приводят к утечкам данных, эскалации привилегий и компрометации систем.

Основной способ борьбы с этими антипаттернами — использование централизованного хранилища, такого как **[HashiCorp Vault](../overview.md)**.

## Основные концепции

Ключевая проблема, объединяющая большинство антипаттернов, — это статическое хранение секретов вместе с кодом или конфигурацией, а также предоставление избыточных привилегий. Это нарушает принципы безопасности, такие как **[Zero Trust](../zero_trust.md)**, и создает большой радиус поражения при компрометации.

### Ключевые принципы безопасного управления секретами

1. **Никогда не хранить секреты в коде или конфигурации**
2. **Использовать динамические секреты с коротким TTL**
3. **Принцип наименьших привилегий для каждого приложения**
4. **Аудит всех операций доступа**
5. **Автоматическая ротация секретов**

## Практические сценарии: Частые антипаттерны

#### 1. Секреты в системе контроля версий (Git)

Самая частая ошибка. Разработчики коммитят файлы `.env`, `kubeconfig` или приватные ключи. Даже если коммит позже удалить, **секрет навсегда остается в истории Git**.

* **Пример обнаружения:** `git grep -nE '(AKIA[0-9A-Z]{16}|BEGIN RSA PRIVATE KEY)' $(git rev-list --all)`
* **Инструменты обнаружения:** GitLeaks, TruffleHog, Vault Radar
* **Решение:** Pre-commit хуки, сканирование репозиториев, немедленная ротация скомпрометированных секретов

#### 2. Кодирование Base64 как шифрование

В Kubernetes Secrets и других системах данные часто кодируются в Base64. Это лишь представление данных в текстовом виде, а не защита.

* **Пример "расшифровки:** `echo 'cGFzc3dvcmQxMjM=' | base64 -d` (результат: `password123`)
* **Решение:** Шифрование etcd в K8s, использование Sealed Secrets или Vault

#### 3. Секреты в переменных окружения

Переменные окружения могут быть прочитаны другими процессами на той же машине и часто утекают в логи или отчеты об ошибках.

* **Пример чтения в Linux:** `cat /proc/<PID>/environ`
* **Риск:** Доступен любому процессу с тем же UID, попадает в core dump
* **Решение:** Монтирование секретов как файлов (tmpfs), использование Vault Agent

#### 4. Секреты в слоях контейнерных образов

Если в `Dockerfile` сначала скопировать файл с ключом, а затем удалить его командой `RUN rm`, он все равно останется в одном из предыдущих слоев образа.

* **Безопасная альтернатива:** Использовать `RUN --mount=type=secret,...` при сборке
* **Решение:** Многостадийная сборка, сканирование образов (Trivy, Clair)

#### 5. Логирование чувствительных данных

Приложения могут случайно выводить в `stdout/stderr` пароли, токены или заголовки `Authorization`, которые затем попадают в системы сбора логов.

* **Решение:** Маскирование в логгере, санитайзеры, структурированное логирование с исключением полей

#### 6. Избыточные права доступа (IAM/RBAC)

Создание "широких" политик (например, `secrets:GetSecretValue` для `Resource: "*"`) или использование одного сервисного аккаунта для нескольких приложений упрощает латеральное перемещение атакующего.

* **Решение:** Принцип наименьших привилегий, регулярный аудит прав, разделение сервисных аккаунтов

#### 7. Секреты в файлах состояния IaC

Инструменты вроде Terraform хранят состояние инфраструктуры, включая значения секретов, в файлах `terraform.tfstate`, которые могут попасть в общее хранилище.

* **Решение:** Шифрование state-файлов, использование remote backend с доступом по ролям (S3 + KMS, Terraform Cloud)

#### 8. Долгоживущие секреты без ротации

Секреты с TTL в месяцы или годы увеличивают риск компрометации и ущерб от неё.

* **Решение:** Vault динамические секреты с TTL от минут до часов, автоматическая ротация

## Дополнительная информация

### Последствия и профилактика

| Ошибка | Риск | Профилактика | Решение с Vault |
| :--- | :--- | :--- | :--- |
| **Коммит в Git** | Неотменяемая утечка. | Pre-commit хуки, сканеры репозиториев. | Динамические секреты, немедленная ротация |
| **Base64 в K8s Secret** | Чтение любым, у кого есть `get` на `Secret`. | Шифрование etcd, **[Sealed Secrets](../../Kubernetes/Security/sealed_secrets_overview.md)**, Vault. | CSI Driver для монтирования секретов из Vault |
| **Слои образа** | Массовая компрометация при публикации. | Многостадийная сборка, `RUN --mount=type=secret`. | Vault Agent для доставки секретов в runtime |
| **Избыточные права** | Эскалация привилегий. | Принцип наименьших привилегий, аудит прав. | Политики Vault с минимальными capabilities |
| **Логи с секретами** | Утечка через системы сбора логов. | Маскирование в логгере, санитайзеры. | Аудит Vault с хэшированием чувствительных полей |
| **Долгоживущие секреты** | Длительный неконтролируемый доступ. | Автоматическая ротация, короткий TTL. | Lease и automatic renewal в Vault |
| **State-файлы IaC** | Утечка через систему контроля версий. | Шифрование state, remote backend. | Интеграция Terraform с Vault для секретов |

### Инструменты для обнаружения уязвимостей

| Инструмент | Назначение |
| :--- | :--- |
| **GitLeaks** | Сканирование Git-репозиториев на наличие секретов |
| **TruffleHog** | Поиск секретов в истории коммитов |
| **Vault Radar** | Обнаружение скомпрометированных секретов в репозиториях и AWS Secrets Manager |
| **Trivy** | Сканирование контейнерных образов на уязвимости и секреты |
| **Gitleaks + pre-commit** | Предотвращение коммитов с секретами |
