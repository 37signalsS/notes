# Антипаттерны управления секретами

## Определения

**Антипаттерн управления секретами** — распространённая, но неэффективная или опасная практика обработки конфиденциальных данных (паролей, ключей, токенов). Эти ошибки приводят к утечкам данных, эскалации привилегий и компрометации систем.

Основной способ предотвращения — использование централизованного хранилища, такого как **[HashiCorp Vault](./overview.md)**.

## Основные концепции

Ключевая проблема большинства антипаттернов — статическое хранение секретов вместе с кодом или конфигурацией и предоставление избыточных привилегий. Это нарушает принципы **[Zero Trust](./zero_trust.md)** и увеличивает радиус поражения при компрометации.

### Ключевые принципы безопасного управления секретами

Для предотвращения антипаттернов следует придерживаться следующих правил:

1. Никогда не хранить секреты в коде или конфигурации.
2. Использовать динамические секреты с коротким TTL (Time to Live).
3. Применять принцип наименьших привилегий для каждого приложения.
4. Обеспечивать аудит всех операций доступа.
5. Использовать автоматическую ротацию секретов.

## Практические сценарии

### 1. Секреты в системе контроля версий (Git)

Самая частая ошибка — коммит файлов `.env`, `kubeconfig`, приватных ключей. Даже при удалении коммита секрет остаётся в истории Git.

- **Инструменты обнаружения:** [Gitleaks](../CI-CD/DevSecOps/secrets_management.md#1-инструменты-для-сканирования-trufflehog-и-gitleaks), [TruffleHog](../CI-CD/DevSecOps/secrets_management.md#1-инструменты-для-сканирования-trufflehog-и-gitleaks).
- **Решение:** Использование pre-commit хуков, сканирование репозиториев, немедленная ротация скомпрометированных секретов.

### 2. Кодирование Base64 как шифрование

В Kubernetes Secrets данные хранятся в Base64 — это лишь способ представления данных, который легко декодируется.

- **Решение:** Включение шифрования в etcd, использование [Sealed Secrets](../Kubernetes/Security/sealed_secrets_overview.md) или интеграция с внешним KMS (Key Management Service) через Vault.

### 3. Секреты в переменных окружения

Переменные окружения могут быть доступны другим процессам, попадать в логи и дампы памяти (core dumps).

- **Риск:** Доступ любому процессу с тем же UID (User ID), утечка через системы мониторинга.
- **Решение:** Монтирование секретов как файлов (через tmpfs), использование [Vault Agent](./guides/vault_agent/basics.md).

### 4. Секреты в слоях контейнерных образов

Файлы, удалённые в последующих инструкциях `RUN`, остаются в предыдущих слоях образа и могут быть извлечены.

- **Решение:** Использование многостадийной сборки (multi-stage builds) и механизмов `RUN --mount=type=secret` в BuildKit.

### 5. Логирование чувствительных данных

Вывод паролей, токенов и заголовков `Authorization` в `stdout` или `stderr`.

- **Решение:** Маскирование данных в логгерах, использование специализированных санитайзеров и структурированного логирования.

### 6. Избыточные права доступа (IAM/RBAC)

Широкие политики доступа (например, `Resource: "*"`) упрощают латеральное перемещение злоумышленника внутри системы.

- **Решение:** Принцип наименьших привилегий, регулярный аудит прав, использование раздельных сервисных аккаунтов.

### 7. Секреты в файлах состояния IaC

Инструменты вроде Terraform хранят секреты в открытом виде в файлах состояния (`terraform.tfstate`).

- **Решение:** Шифрование файлов состояния, использование удалённых бэкендов (Remote Backend) с контролем доступа (S3 + KMS).

### 8. Долгоживущие секреты без ротации

Использование секретов без ограничения по времени увеличивает окно возможностей для злоумышленника.

- **Решение:** Динамические секреты Vault с коротким TTL, автоматизация процесса ротации.

## Дополнительная информация

### Сравнение рисков и способов профилактики

| Ошибка | Риск | Профилактика | Решение с Vault |
| :--- | :--- | :--- | :--- |
| **Коммит в Git** | Неотменяемая утечка | Сканеры репозиториев | Динамические секреты |
| **Base64 в K8s** | Легкое чтение данных | Шифрование etcd | CSI Driver для монтирования |
| **Слои образа** | Утечка при публикации | Multi-stage build | Vault Agent |
| **Избыточные права** | Эскалация привилегий | Принцип наименьших привилегий | Гранулярные политики |
| **Логирование** | Утечка через ELK/Loki | Маскирование | Аудит с хэшированием |
| **Долгоживущие секреты** | Постоянный доступ | Автоматическая ротация | Lease и TTL |
