# Антипаттерны управления секретами

## Определения

**Антипаттерн управления секретами** — распространённая, но неэффективная или опасная практика обработки конфиденциальных данных (паролей, ключей, токенов). Эти ошибки приводят к утечкам данных, эскалации привилегий и компрометации систем.

Основной способ предотвращения — использование централизованного хранилища **[HashiCorp Vault](./overview.md)**.

## Основные концепции

Ключевая проблема большинства антипаттернов — статическое хранение секретов вместе с кодом или конфигурацией и предоставление избыточных привилегий. Это нарушает принципы **[Zero Trust](./zero_trust.md)** и увеличивает радиус поражения при компрометации.

### Ключевые принципы безопасного управления секретами

1. Никогда не хранить секреты в коде или конфигурации
2. Использовать динамические секреты с коротким TTL
3. Принцип наименьших привилегий для каждого приложения
4. Аудит всех операций доступа
5. Автоматическая ротация секретов

## Практические сценарии

### 1. Секреты в системе контроля версий (Git)

Самая частая ошибка — коммит файлов `.env`, `kubeconfig`, приватных ключей. Даже при удалении коммита **секрет остаётся в истории Git навсегда**.

- **Пример обнаружения:** `git grep -nE '(AKIA[0-9A-Z]{16}|BEGIN RSA PRIVATE KEY)' $(git rev-list --all)`
- **Инструменты:** [Gitleaks](../CI-CD/DevSecOps/secrets_management.md#1-инструменты-для-сканирования-trufflehog-и-gitleaks), [TruffleHog](../CI-CD/DevSecOps/secrets_management.md#1-инструменты-для-сканирования-trufflehog-и-gitleaks), Vault Radar
- **Решение:** Pre-commit хуки, сканирование репозиториев, немедленная ротация скомпрометированных секретов

### 2. Кодирование Base64 как шифрование

В Kubernetes Secrets данные хранятся в Base64 — это представление, а не защита.

- **Пример декодирования:** `echo 'cGFzc3dvcmQxMjM=' | base64 -d` → `password123`
- **Решение:** Шифрование etcd, [Sealed Secrets](../Kubernetes/Security/sealed_secrets_overview.md), Vault

### 3. Секреты в переменных окружения

Переменные окружения доступны другим процессам на той же машине, попадают в логи и core dump.

- **Пример чтения:** `cat /proc/<PID>/environ`
- **Риск:** Доступ любому процессу с тем же UID, утечка в core dump
- **Решение:** Монтирование как файлов (tmpfs), [Vault Agent](./guides/vault_agent/basics.md)

### 4. Секреты в слоях контейнерных образов

Файлы, удалённые через `RUN rm`, остаются в предыдущих слоях образа.

- **Безопасная альтернатива:** `RUN --mount=type=secret,...` при сборке
- **Решение:** Многостадийная сборка, сканирование образов (Trivy, Clair)

### 5. Логирование чувствительных данных

Приложения выводят пароли, токены, заголовки `Authorization` в `stdout/stderr`.

- **Решение:** Маскирование в логгере, санитайзеры, структурированное логирование с исключением полей

### 6. Избыточные права доступа (IAM/RBAC)

Широкие политики (`secrets:GetSecretValue` для `Resource: "*"`) и общие сервисные аккаунты упрощают латеральное перемещение.

- **Решение:** Принцип наименьших привилегий, регулярный аудит, разделение сервисных аккаунтов

### 7. Секреты в файлах состояния IaC

Terraform хранит секреты в `terraform.tfstate`, которые могут попасть в общее хранилище.

- **Решение:** Шифрование state-файлов, remote backend с RBAC (S3 + KMS, Terraform Cloud)

### 8. Долгоживущие секреты без ротации

Секреты с TTL в месяцы/годы увеличивают риск и ущерб от компрометации.

- **Решение:** Динамические секреты Vault с TTL от минут до часов, автоматическая ротация

## Дополнительная информация

### Последствия и профилактика

| Ошибка | Риск | Профилактика | Решение с Vault |
| :--- | :--- | :--- | :--- |
| **Коммит в Git** | Неотменяемая утечка | Pre-commit хуки, сканеры репозиториев | Динамические секреты, немедленная ротация |
| **Base64 в K8s Secret** | Чтение при наличии `get` на `Secret` | Шифрование etcd, [Sealed Secrets](../Kubernetes/Security/sealed_secrets_overview.md) | CSI Driver для монтирования из Vault |
| **Слои образа** | Массовая компроментация при публикации | Многостадийная сборка, `RUN --mount=type=secret` | Vault Agent для доставки в runtime |
| **Избыточные права** | Эскалация привилегий | Принцип наименьших привилегий, аудит | Политики Vault с минимальными capabilities |
| **Логи с секретами** | Утечка через системы сбора логов | Маскирование, санитайзеры | Аудит Vault с хэшированием чувствительных полей |
| **Долгоживущие секреты** | Длительный неконтролируемый доступ | Автоматическая ротация, короткий TTL | Lease и automatic renewal |
| **State-файлы IaC** | Утечка через VCS | Шифрование state, remote backend | Интеграция Terraform с Vault |

Инструменты сканирования описаны в [управлении секретами CI/CD](../CI-CD/DevSecOps/secrets_management.md#1-инструменты-для-сканирования-trufflehog-и-gitleaks).
