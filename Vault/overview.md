# HashiCorp Vault

## Обзор

HashiCorp Vault — это инструмент для безопасного управления секретами. Секретами может быть что угодно, к чему вы хотите контролировать доступ, например, ключи API, пароли, сертификаты или токенизированные данные. Vault предоставляет единый интерфейс для доступа к секретам, обеспечивая при этом строгий контроль доступа и ведение подробного журнала аудита.

Он разработан для управления секретами в современных динамичных инфраструктурах, таких как облачные среды, контейнеры и микросервисы.

## Ключевые возможности

*   **Безопасное хранение секретов (Secure Secret Storage):** Vault шифрует секреты перед их записью в постоянное хранилище. В качестве бэкенда хранения могут выступать [Consul](./Guides/vault_with_consul_backend.md), различные облачные хранилища (S3, GCS), базы данных или локальная файловая система.
*   **Динамические секреты (Dynamic Secrets):** Vault может генерировать секреты "на лету" для доступа к таким системам, как базы данных (PostgreSQL, MySQL), облачные платформы (AWS, Azure) и другие. Эти секреты имеют ограниченный срок действия и автоматически отзываются, что снижает риски, связанные с утечкой долгоживущих учетных данных.
*   **Шифрование как услуга (Encryption as a Service):** Vault может шифровать и расшифровывать данные для приложений, не сохраняя их у себя. Это позволяет разработчикам безопасно обрабатывать конфиденциальные данные (например, номера кредитных карт или персональные данные), не реализуя сложную криптографию самостоятельно.
*   **Управление жизненным циклом сертификатов (PKI Certificate Management):** Vault может выступать в роли центра сертификации (CA), генерируя и подписывая сертификаты для установления TLS-соединений между сервисами.
*   **Идентификационно-ориентированный доступ (Identity-Based Access):** Vault аутентифицирует пользователей и приложения через различные источники (LDAP, Active Directory, Kubernetes, облачные IAM) и использует политики для контроля доступа к секретам.

## Процесс работы

1.  **Аутентификация:** Клиент (пользователь или приложение) аутентифицируется в Vault с помощью одного из настроенных методов.
2.  **Авторизация:** Vault возвращает токен, к которому привязаны политики, определяющие права доступа.
3.  **Получение секрета:** Клиент использует свой токен для чтения или записи секрета по определенному пути.
4.  **Аудит:** Все действия клиента записываются в журнал аудита.

## Варианты использования

*   **Централизованное хранилище для CI/CD:** Хранение токенов, паролей и ключей, используемых в пайплайнах.
*   **Управление секретами для микросервисов:** Каждый сервис получает свои уникальные учетные данные для доступа к базам данных и другим сервисам.
*   **Автоматизация PKI:** Автоматическая выдача и ротация TLS-сертификатов для внутренней инфраструктуры.
