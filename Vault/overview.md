# Обзор HashiCorp Vault

## Определения

**HashiCorp Vault** — это централизованная система для безопасного управления жизненным циклом секретов (Security Lifecycle Management, SLM). Она предназначена для защиты чувствительных данных, таких как пароли, API-ключи, токены, сертификаты и ключи шифрования. Vault предоставляет единую точку управления (SSoT) для всей инфраструктуры, обеспечивая строгую идентификацию, гранулярную авторизацию и детальный аудит всех операций.

**Security Lifecycle Management (SLM)** — современный подход Vault (версии 1.16+, 2.0+), выходящий за рамки простого хранения секретов. SLM включает в себя обнаружение утечек в коде, централизованное хранение, автоматическую ротацию и синхронизацию секретов с внешними облачными менеджерами ключей.

## Основные концепции

Архитектура Vault построена на принципах безопасности "Zero Trust" (нулевого доверия) и включает следующие фундаментальные механизмы:

*   **[Процесс Seal/Unseal (Запечатывание)](./concepts.md#процесс-запечатывания-seal-и-распечатывания-unseal):** Механизм защиты главного ключа шифрования. В продуктивных средах рекомендуется использовать **Auto-unseal** через облачные KMS или HSM.
*   **[Интегрированное хранилище (Raft)](./concepts.md#бэкенды-хранения-storage-backends):** Современный стандарт хранения данных Vault, обеспечивающий высокую доступность (HA) без внешних зависимостей.
*   **[Система идентификации (Identity Store)](./concepts.md#система-идентификации-identity-store):** Механизм Entities и Groups, позволяющий связывать различные методы аутентификации с одной личностью.
*   **[Авторизация и политики (Policies)](./authorization.md):** Управление доступом на основе путей API с использованием декларативного языка HCL.
*   **[Движки секретов (Secret Engines)](./concepts.md#движки-секретов-secret-engines):** Компоненты, реализующие логику работы с данными: от статического KV до динамической генерации учетных данных баз данных и облаков.
*   **[Жизненный цикл (Lease & Revoke)](./concepts.md#жизненный-цикл-токены-lease-и-revoke):** Система аренды секретов с ограниченным временем жизни (TTL), обеспечивающая автоматический отзыв доступа.

### Ключевые преимущества

1.  **Централизация (Single Source of Truth):** Исключение разрозненного хранения секретов в коде, конфигурациях и переменных окружения.
2.  **Динамическая безопасность:** Генерация краткоживущих секретов "на лету" минимизирует ущерб при их компрометации.
3.  **Автоматизация ротации:** Встроенные механизмы обновления паролей и ключей без участия человека.
4.  **Синхронизация секретов (Secrets Sync):** Возможность управлять секретами в Vault и автоматически реплицировать их в AWS Secrets Manager, GitHub Secrets, Azure Key Vault и другие платформы.

### Ключевые возможности

| Категория | Возможности |
| :--- | :--- |
| **Управление секретами** | Статическое хранение (KV v1/v2), динамические учетные данные (DB, Cloud, SSH). |
| **Криптография** | Шифрование как сервис (Transit Engine), маскирование данных, управление ключами (KMIP). |
| **Идентификация** | Поддержка OIDC, Workload Identity Federation (WIF), интеграция с LDAP/Okta/Active Directory. |
| **Синхронизация и Обнаружение** | Secrets Sync (Hub-and-spoke модель), Vault Radar (поиск секретов в коде и Slack). |
| **PKI и Сертификаты** | Полноценный центр сертификации (CA), поддержка ACME, выдача TLS и SSH сертификатов. |
| **Комплаенс и Аудит** | Неизменяемые логи, хэширование чувствительных данных в журналах, поддержка FIPS 140-2. |

## Практические сценарии

### Запуск в режиме разработки (Dev Mode)

Для быстрого ознакомления и тестирования Vault можно запустить в режиме, не требующем настройки хранилища и распечатывания (данные хранятся в оперативной памяти).

```bash
# Запуск сервера в dev-режиме
vault server -dev

# Настройка CLI для работы с локальным сервером (выполняется в новом терминале)
export VAULT_ADDR='http://127.0.0.1:8200'
export VAULT_TOKEN='root' # Корневой токен из вывода предыдущей команды

# Проверка статуса
vault status
```

### Примеры использования в инфраструктуре

*   **CI/CD интеграция:** Динамическая выдача временных токенов для пайплайнов GitLab/GitHub, исключающая хранение статических паролей в настройках CI.
*   **Kubernetes Sidecar:** Автоматическое внедрение секретов в поды через Vault Agent Sidecar или Secrets Store CSI Driver.
*   **Database Credentials:** Генерация уникальных логинов для каждого экземпляра микросервиса с автоматическим удалением пользователя в БД после истечения TTL.
*   **Zero Trust Networking:** Выдача краткоживущих TLS-сертификатов для взаимодействия между сервисами.
