# HashiCorp Vault

## Определения

**HashiCorp Vault** — это централизованная система для безопасного управления секретами. Секретами может быть что угодно, к чему требуется контролировать доступ: пароли, API-ключи, токены, сертификаты, ключи шифрования и другие конфиденциальные данные. Vault предоставляет единый программный интерфейс для доступа к секретам, обеспечивая при этом строгий контроль доступа и ведение подробного журнала аудита всех операций.

## Основные концепции

Архитектура Vault основана на нескольких ключевых компонентах. Детальное их описание доступно в заметке [Основные концепции Vault](./concepts.md).

*   **Процесс "запечатывания" (Seal) и "распечатывания" (Unseal):** При запуске Vault находится в "запечатанном" состоянии и не знает, как расшифровать данные. Для начала работы его необходимо "распечатать" с помощью набора ключей. Этот механизм защищает данные даже в случае компрометации самого хранилища. Подробнее см. в [Seal / Unseal](./concepts.md#процесс-запечатывания-seal-и-распечатывания-unseal).
*   **Хранилище (Storage Backend):** Vault не хранит данные сам, а делегирует это персистентным бэкендам. Все данные предварительно шифруются. Рекомендуемым решением для production является [использование Consul](./guides/vault_with_consul_backend.md). Подробнее см. в [Бэкенды хранения](./concepts.md#бэкенды-хранения-storage-backends).
*   **Аутентификация (Auth Methods):** Vault использует различные методы для проверки личности клиентов (пользователей, приложений). После успешной аутентификации клиент получает токен с привязанными политиками. Одним из самых популярных методов для приложений является [AppRole](./guides/vault_auth_approle.md). Подробнее см. в [Методы аутентификации](./concepts.md#методы-аутентификации-auth-methods).
*   **Политики (Policies):** Правила, которые определяют, какие действия (чтение, запись, удаление) аутентифицированный клиент может выполнять по определенным путям. Политики реализуют принцип наименьших привилегий. Подробнее см. в [Политики доступа](./concepts.md#политики-доступа-в-vault).
*   **Движки Секретов (Secret Engines):** Компоненты, управляющие секретами. Основные типы:
    *   **Static Secrets (KV):** Простое хранилище типа "ключ-значение".
    *   **Dynamic Secrets:** Генерируют секреты "на лету" (например, учетные данные для баз данных PostgreSQL, MySQL, облачных платформ AWS, Azure) с ограниченным сроком действия.
    *   **Encryption as a Service (Transit):** Шифруют и расшифровывают данные для приложений, не сохраняя их у себя.
    *   **PKI Certificate Management:** Vault может выступать в роли центра сертификации (CA) для генерации и подписания TLS-сертификатов.

## Практические сценарии

### Быстрый старт в dev-режиме

Для разработки и тестирования Vault можно запустить в режиме `dev`, который использует хранилище в памяти, не требует "распечатывания" и автоматически настраивает адрес и корневой токен.

```bash
# Старт в dev-режиме для локального ознакомления
vault server -dev

# В выводе команды будут указаны адрес и корневой токен.
# Откройте новый терминал и экспортируйте их в переменные окружения:
export VAULT_ADDR='http://127.0.0.1:8200'
export VAULT_TOKEN='...' # Скопируйте токен из вывода

# Подключение KV v2 и запись секрета
vault secrets enable -path=app kv-v2
vault kv put app/config username=alice password=s3cr3t
vault kv get app/config

# Создание политики и ограниченного токена
cat > app.hcl <<'EOF'
path "app/*" { capabilities = ["read", "list"] }
EOF
vault policy write app app.hcl
vault token create -policy=app -ttl=1h

# Пример response wrapping
vault kv get -wrap-ttl=60s app/config
```

### Централизованное хранилище для CI/CD

Vault идеально подходит для хранения токенов, паролей и ключей, используемых в пайплайнах, исключая их хранение в переменных CI/CD.
*   **См. практическое руководство:** [Интеграция GitLab CI с HashiCorp Vault](../CI-CD/GitLab_CI/Tutorials/vault_kubernetes_integration.md).

### Управление секретами для микросервисов и контейнеров

Каждый сервис может получать уникальные, короткоживущие учетные данные для доступа к ресурсам.
*   **См. практическое руководство:** [Интеграция Vault с Docker](./guides/vault_docker_integration.md).

### Автоматизация PKI

Автоматическая выдача и ротация TLS-сертификатов для внутренней инфраструктуры.

## Дополнительная информация

### Высокая доступность (High Availability)

В production-среде Vault настраивается в режиме высокой доступности (HA) с несколькими репликами для обеспечения отказоустойчивости.

### Vault Agent

**Vault Agent** — это легковесный клиентский демон, который упрощает интеграцию приложений с Vault. Он берет на себя задачи аутентификации, управления жизненным циклом токена и рендеринга секретов в файлы.
*   **См. подробнее:** [Vault Agent и шаблоны](./guides/vault_agent_and_templates.md).

### Установка

Для развертывания Vault в production-среде следуйте пошаговому руководству.
*   **См. руководство по установке:** [Установка и базовая настройка Vault](./guides/vault_installation.md).
