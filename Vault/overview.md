# HashiCorp Vault

## Определения

**HashiCorp Vault** — это централизованная система для безопасного управления секретами. Секретами может быть что угодно, к чему требуется контролировать доступ: пароли, API (Application Programming Interface — интерфейс программирования приложений)-ключи, токены, сертификаты, ключи шифрования и другие конфиденциальные данные. Vault предоставляет единый программный интерфейс для доступа к секретам, обеспечивая при этом строгий контроль доступа и ведение подробного журнала аудита всех операций.

## Основные концепции

Архитектура Vault основана на нескольких ключевых компонентах, которые обеспечивают его безопасность и гибкость.

* **[Процесс "запечатывания" и "распечатывания" (Seal/Unseal)](./concepts.md#процесс-запечатывания-seal-и-распечатывания-unseal):** Ключевой механизм безопасности, защищающий главный ключ шифрования.
* **[Бэкенды хранения (Storage Backends)](./concepts.md#бэкенды-хранения-storage-backends):** Персистентные хранилища, где Vault хранит зашифрованные данные (например, Consul, etcd, или встроенный Raft).
* **[Методы аутентификации (Auth Methods)](./concepts.md#методы-аутентификации-и-токены):** Механизмы для проверки идентичности клиентов (людей и машин) и выдачи им токенов.
* **[Авторизация и политики (Policies)](./authorization.md):** Декларативные правила, определяющие, какие операции разрешены для конкретного токена.
* **[Движки Секретов (Secret Engines)](./concepts.md#движки-секретов-secret-engines):** Компоненты, которые хранят, генерируют или шифруют данные. Поддерживают статическое (KV) и динамическое создание секретов.
* **[Токены и жизненный цикл секрета (Tokens, Lease, Revoke)](./concepts.md#жизненный-цикл-секрета-токены-lease-и-revoke):** Все динамические секреты и токены имеют ограниченный срок жизни (lease), что позволяет автоматически отзывать доступ.

Для более детального изучения архитектуры обратитесь к заметке **[Основные концепции Vault](./concepts.md)**.

### Ключевые возможности Vault

| Категория | Возможности |
| :--- | :--- |
| **Статические секреты** | Хранение, ротация и шифрование произвольных строк как пар ключ-значение (KV — Key-Value v1/v2) |
| **Динамические секреты** | Генерация временных учётных данных для БД, облачных провайдеров (AWS — Amazon Web Services, GCP — Google Cloud Platform, Azure) |
| **PKI и сертификаты** | Встроенный центр сертификации (PKI — Public Key Infrastructure (инфраструктура открытых ключей)), управление жизненным циклом сертификатов |
| **Шифрование как сервис** | Движок `transit` для шифрования данных без хранения ключей у приложения |
| **Идентификация** | Identity tokens, OIDC (OpenID Connect), workload identity federation (WIF — федерация идентичности рабочих нагрузок) для Kubernetes |
| **Аудит и compliance** | Неизменяемые логи всех операций, поддержка HSM (Hardware Security Module — аппаратный модуль безопасности), FIPS (Federal Information Processing Standards — федеральные стандарты обработки информации)-архитектура |

## Практические сценарии

### Быстрый старт в dev-режиме

Для разработки и тестирования Vault можно запустить в режиме `dev`, который использует хранилище в памяти и не требует "распечатывания".

```bash
# Старт в dev-режиме
vault server -dev

# В новом терминале экспортируйте переменные окружения из вывода команды
export VAULT_ADDR='http://127.0.0.1:8200'
export VAULT_TOKEN='...' # Корневой токен

# Пример работы с KV-хранилищем
vault secrets enable -path=app kv-v2
vault kv put app/config username=alice password=s3cr3t
vault kv get app/config
```

### Типовые задачи управления секретами

* **Централизованное хранилище для CI/CD (Continuous Integration / Continuous Deployment — непрерывная интеграция и доставка):** Исключение секретов из переменных окружения и конфигурационных файлов пайплайнов.
* **Управление секретами для микросервисов:** Динамическая выдача уникальных, короткоживущих учетных данных для каждого сервиса.
* **Автоматизация PKI:** Использование Vault в качестве внутреннего центра сертификации для автоматической выдачи и ротации TLS (Transport Layer Security — протокол защиты транспортного уровня)-сертификатов.
* **Шифрование как сервис (Encryption as a Service):** Использование движка `transit` для шифрования данных приложений без необходимости управлять ключами шифрования напрямую.
