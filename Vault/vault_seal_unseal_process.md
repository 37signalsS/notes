# Процесс "запечатывания" (Seal) и "распечатывания" (Unseal) в Vault

Одной из ключевых концепций архитектуры безопасности Vault является механизм "Seal" / "Unseal". Этот механизм гарантирует, что даже если злоумышленник получит доступ к физическому хранилищу данных Vault, он не сможет их расшифровать.

## Состояния Vault

Vault может находиться в одном из двух состояний:

### 1. Запечатанное (Sealed)
Это состояние по умолчанию при запуске сервера Vault. В этом состоянии Vault знает, где находится его хранилище данных (например, в файловой системе или в [Consul](./vault_with_consul_backend.md)), но не знает, как их расшифровать.

Когда Vault запечатан:
*   **Доступ к данным невозможен:** Почти все операции с секретами (чтение, запись) блокированы.
*   **Доступны только системные операции:** Можно проверить статус, выполнить распечатывание или эскалацию до `root`.

Vault автоматически переходит в состояние `Sealed` при каждом перезапуске.

### 2. Распечатанное (Unsealed)
Чтобы Vault мог выполнять свои функции, его необходимо "распечатать". В этом состоянии Vault получает в оперативной памяти главный ключ (master key), который позволяет ему расшифровывать данные из хранилища и выполнять запросы клиентов.

Этот главный ключ **никогда не хранится в постоянном хранилище**. Он собирается "на лету" в момент распечатывания.

## Как работает распечатывание: Алгоритм Шамира

При инициализации (`vault operator init`) Vault генерирует главный ключ шифрования. Затем, вместо того чтобы сохранить этот ключ где-либо, Vault использует **алгоритм разделения секрета Шамира (Shamir's Secret Sharing)**.

1.  **Разделение ключа:** Главный ключ делится на `N` частей (по умолчанию `N=5`), которые называются **ключами распечатывания (Unseal Keys)**.
2.  **Пороговое значение (Threshold):** Устанавливается пороговое количество ключей `K` (по умолчанию `K=3`), необходимое для восстановления исходного главного ключа.

Это означает, что для распечатывания Vault необходимо предоставить `K` **любых** из `N` сгенерированных ключей. Даже если злоумышленник получит доступ к одному или двум ключам, он не сможет восстановить главный ключ и получить доступ к данным.

### Операционная безопасность
Этот механизм лежит в основе важной операционной практики:
*   **Распределение ответственности:** `N` ключей распечатывания раздаются разным ответственным сотрудникам (например, системным администраторам, DevOps-инженерам, офицерам безопасности).
*   **Кворум для распечатывания:** Для перезапуска и распечатывания Vault требуется участие нескольких человек ("кворум"). Это предотвращает несанкционированные действия со стороны одного сотрудника.

## Процесс в командах

1.  **Инициализация (выполняется один раз):**
    ```bash
    export VAULT_ADDR='http://127.0.0.1:8200'
    vault operator init
    ```
    В результате будут сгенерированы 5 ключей распечатывания (`Unseal Key 1`...`5`) и начальный корневой токен (`Initial Root Token`). **Их необходимо сохранить в нескольких надежных и раздельных местах.**

2.  **Проверка статуса:**
    ```bash
    vault status
    ```
    ```
    Key             Value
    ---             -----
    Sealed          true  # Vault запечатан
    Total Shares    5
    Threshold       3
    ...
    ```

3.  **Распечатывание:**
    Нужно последовательно выполнить команду `vault operator unseal` с разными ключами, пока не будет достигнуто пороговое значение.
    ```bash
    vault operator unseal <unseal_key_1>
    # Progress: 1/3
    vault operator unseal <unseal_key_3>
    # Progress: 2/3
    vault operator unseal <unseal_key_5>
    # Progress: 3/3. Sealed: false
    ```

4.  **Финальный статус:**
    ```bash
    vault status
    ```
    ```
    Key             Value
    ---             -----
    Sealed          false # Vault распечатан и готов к работе
    ...
    ```
После этого можно входить в систему с помощью токена (`vault login <root_token>`) и работать с секретами.
