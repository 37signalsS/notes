# Политики доступа в Vault

Политики (Policies) — это декларативный способ предоставления или запрета доступа к определенным путям и операциям в Vault. Политики определяют, **что** аутентифицированный субъект (пользователь, приложение) может делать.

Политики пишутся на языке HCL (HashiCorp Configuration Language).

## Структура политики

Политика состоит из одного или нескольких правил `path`.

```hcl
path "path/to/secret/*" {
  capabilities = ["read", "list"]
}
```

*   `path "..."`: Определяет путь, к которому применяется правило. Может содержать wildcards (`*`).
*   `capabilities = [...]`: Список разрешенных операций.

### Основные `capabilities`

*   `create`: Создание секрета по указанному пути.
*   `read`: Чтение секрета.
*   `update`: Обновление существующего секрета.
*   `delete`: Удаление секрета.
*   `list`: Получение списка секретов по указанному пути (если путь является "директорией").
*   `sudo`: Доступ к привилегированным путям.
*   `deny`: Явный запрет на доступ. Имеет наивысший приоритет.

Полный список и описание `capabilities` можно найти в [официальной документации](https://developer.hashicorp.com/vault/docs/concepts/policies#capabilities).

## Пример из урока

В уроке была создана политика `consul-policy`, которая дает доступ на чтение и запись к секретам, хранящимся по пути `devops/data/consul`.

```hcl
# consul-policy.hcl

path "devops/data/consul" {
  capabilities = ["create", "read", "update", "list"]
}
```

*   **Примечание:** Для K/V-хранилища версии 2 (KVv2) пути для API обычно содержат `data` (для операций с данными) и `metadata` (для метаданных). Правила должны это учитывать. Например: `secret/data/my-app/*`. В примере из урока, судя по всему, используется путь `devops` для KV-engine, а внутри него секрет `consul`.

## Создание политики

Политики можно создавать через UI или CLI.

### Через CLI (рекомендуемый способ)

1.  Сохраните HCL-код в файл, например, `consul-policy.hcl`.
2.  Используйте команду `vault policy write`:

    ```bash
    vault policy write consul-policy consul-policy.hcl
    ```
    Где:
    *   `consul-policy` — имя, под которым политика будет храниться в Vault.
    *   `consul-policy.hcl` — файл с кодом политики.

### Через UI

1.  Перейдите в раздел `Policies`.
2.  Нажмите `Create ACL policy`.
3.  Введите имя политики и вставьте HCL-код в текстовое поле.
4.  Нажмите `Create policy`.

После создания политика может быть привязана к токену или [методу аутентификации (например, AppRole)](./vault_auth_approle.md), чтобы предоставить соответствующие права доступа.
