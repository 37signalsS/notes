# Nomad — продвинутые темы

## Определения

**LTS (Long-Term Support)** — версия с расширенным периодом поддержки (обычно 12+ месяцев), рекомендуется для production.

**Enterprise-версия** — коммерческая версия HashiCorp с расширенным функционалом для крупных организаций:
- **Sentinel (Policy as Code)** — тонкая настройка политик безопасности и комплаенса (например, запрет на использование `root` в контейнерах или ограничение образов только из доверенных реестров).
- **Resource Quotas** — ограничение потребления ресурсов (CPU, Memory) на уровне неймспейсов или команд.
- **Multitenancy & Namespaces** — логическая изоляция команд и проектов внутри одного кластера.
- **Dynamic Application Sizing (DAS)** — автоматическая рекомендация и корректировка ресурсов на основе исторических данных.
- **Automated Upgrades** — автоматизация процесса обновления узлов кластера без прерывания нагрузки.
- **Redundancy Zones** — повышение отказоустойчивости за счет распределения серверов по зонам.

Актуальная информация о лицензировании: с апреля 2026 HashiCorp изменила модель выпуска enterprise-версий (включая переход на BSL для исходного кода) — [подробности](https://support.hashicorp.com/hc/en-us/articles/48015293517203).

## Основные концепции

### Версии и поддержка

| Версия | Дата выпуска | Статус |
| :--- | :--- | :--- |
| **v1.11.3** | Март 2026 | **Latest** |
| v1.10.9 | Март 2026 | Поддерживаемая |
| v1.8.21 | Март 2026 | LTS |
| v1.7.x и ранее | — | Устаревшие |

**Ключевые нововведения последних версий:**

- **Workload Identity (v1.6+)** — OIDC-аутентификация для безопасного доступа к ресурсам.
- **Client Identity (v1.8+)** — автоматическая генерация и ротация идентичностей клиентов.
- **Deployments for system jobs** — поддержка полноценных развёртываний для системных задач.
- **Secrets Block** — упрощенное получение секретов из Vault без сложных шаблонов.
- **GPU Fingerprinting** — расширенное обнаружение и учет GPU/FPGA/TPU.
- **Variables** — встроенное хранилище `nomad var` для конфигураций.

### Использование в Production

**Компании в production:** PagerDuty, Target, Citadel, Trivago, SAP, Pandora, Roblox, eBay, Deluxe Entertainment.

## Практические сценарии

### Выбор между Nomad и Kubernetes

Дополнение к [сравнительной таблице](./definitions_and_concepts.md) — критерии выбора:

| Критерий | Nomad | Kubernetes |
| :--- | :--- | :--- |
| **Workload'ы** | Микс контейнеров и legacy (Windows, Java, VM) | Только контейнеры |
| **Команда** | Малые/средние, ограниченные ресурсы | Крупные, выделенная SRE-команда |
| **Среда** | On-premises или гибридная | Преимущественно cloud |
| **Приложения** | Существующие core + новые | Cloud-native greenfield |
| **Приоритет** | Простота и скорость внедрения | Полнота функциональности |
| **Бюджет** | Ограниченный | Значительный |

**Тренд 2025–2026:** сосуществование обоих оркестраторов в крупных предприятиях (Intel, Autodesk, GitHub).

### Диагностика и устранение неисправностей

Основные инструменты и команды для отладки кластера Nomad:

| Команда | Назначение |
| :--- | :--- |
| `nomad node status` | Проверка состояния узлов и их загрузки |
| `nomad job status <job>` | Детальный статус конкретной задачи и причины сбоев |
| `nomad alloc status <alloc>` | Проверка конкретной аллокации (размещения) |
| `nomad alloc logs <alloc>` | Просмотр логов (stdout/stderr) выполняемой задачи |
| `nomad monitor` | Потоковый мониторинг событий в кластере |
| `nomad system gc` | Принудительный запуск сборщика мусора |

**Типовые проблемы:**
- **Placement Failure:** нехватка ресурсов (CPU/RAM) или невыполнение ограничений (`constraints`).
- **Driver Failure:** отсутствие установленного рантайма (Docker, Podman) на целевом узле.
- **Fingerprinting Issue:** некорректное определение характеристик железа (например, GPU).
