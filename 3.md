# Протокол ICMP (Internet Control Message Protocol)

## 1. Введение
В сетях могут возникать ошибки:
*   **Спонтанные:** помехи, переполнение буфера. Решаются повторной отправкой (пакет, скорее всего, дойдет).
*   **Постоянные:** неверная настройка (например, TTL=0). Повторная отправка не поможет, пакет будет отбрасываться на том же узле.

ICMP (RFC 792) помогает определять ошибки на сетевом и транспортном уровнях и является неотъемлемой частью IP.

## 2. Формат заголовка ICMP (32 бита)
1.  **Type (Тип):** категория проблемы (например, Destination unreachable).
2.  **Code (Код):** конкретизация ошибки (например, хост или порт недоступен).
3.  **Checksum (Контрольная сумма):** CRC16.
4.  **Unused (32 бита):** зарезервировано для доп. полей некоторых типов сообщений.
5.  **Data:** заголовок IP + 64 бита данных исходного пакета, вызвавшего ошибку. Это позволяет хосту-отправителю понять, какой именно процесс/пакет пострадал.

---

## 3. Основные типы сообщений

### Тип 3: Destination unreachable (Назначение недостижимо)
Генерируется, если пакет невозможно доставить.
*   **Код 0 (Сеть недоступна):** Маршрутизатор не знает маршрута до целевой сети.
*   **Код 1 (Хост недоступен):** Маршрутизатор знает сеть, но хост не отвечает на ARP-запросы.
*   **Код 2 (Протокол недоступен):** Редко встречается.
*   **Код 3 (Порт недоступен):** Приходит в ответ на UDP-пакет, если целевой порт на хосте закрыт.
*   **Код 4 (Нужна фрагментация, но стоит флаг DF):** Пакет больше MTU канала, а фрагментация запрещена флагом Don’t Fragment.
*   **Код 5 (Маршрут от источника недоступен):** Ошибка при использовании опции Source Routing.

### Тип 11: Time Exceeded (Время истекло)
*   **Код 0 (Time to live exceeded in transit):** TTL пакета стал равен 0 при прохождении через маршрутизатор. Защита от вечных циклов.
*   **Код 1 (Fragment reassembly time exceeded):** Хост не успел собрать все фрагменты IP-пакета за отведенное время.

### Тип 8 и 0: Echo и Echo reply (Утилита Ping)
Диагностические сообщения:
*   **Echo Request (Тип 8, Код 0):** Запрос доступности.
*   **Echo Reply (Тип 0, Код 0):** Ответ на запрос.

### Тип 5: Redirect (Перенаправление)
Рекомендует хосту изменить таблицу маршрутизации для оптимизации пути (отправлять пакеты напрямую или через другой шлюз в той же сети).
*   **Код 0:** Перенаправление для сети.
*   **Код 1:** Перенаправление для хоста.
*   *Примечание:* Часто блокируется из-за соображений безопасности.

### Тип 4: Source Quench (Подавление источника)
Уведомляет отправителя, что узел не успевает обрабатывать пакеты и просит снизить скорость. В современных сетях почти не используется.

---

## 4. Полезные команды и ссылки
*   `ping -l [size] -f [IP]` — отправить пакет заданного размера с запретом фрагментации.
*   `traceroute` (или `tracert` в Win) — использует TTL Exceeded для построения карты маршрута.
*   RFC 792: https://www.rfc-editor.org/rfc/rfc792

# VLAN (Virtual Local Area Network)

VLAN позволяет разделить единую сеть (широковещательный домен) на изолированные друг от друга сегменты. Это необходимо для обеспечения безопасности и управления трафиком (например, разделение сетей разных отделов в одном офисном здании).

VLAN изолирует один сегмент сети от другого путем назначения идентификатора виртуальной сети (**VLAN ID**).

## 1. Access VLAN (по портам)
Реализуется на коммутаторах путем назначения конкретного VLAN ID порту коммутатора.
*   Коммутатор определяет, какому VLAN ID принадлежит порт, и передает пакеты только в рамках этого ID.
*   Даже широковещательные пакеты (FF:FF:FF:FF:FF:FF) не покидают пределов своего VLAN.
*   Этот режим также называют **Port-Based VLAN**.

## 2. Trunk VLAN (по тегам)
Используется для передачи трафика нескольких VLAN по одному физическому соединению (магистрали) между коммутаторами. Для этого используется процедура тегирования трафика согласно стандарту **IEEE 802.1Q**.

### Заголовок 802.1Q (4 байта)
Помещается между MAC-адресом источника и полем Тип/Длина:
1.  **TPID (16 бит):** Идентификатор протокола (0x8100 для 802.1Q).
2.  **TCI (16 бит):**
    *   **PCP (3 бита):** Приоритет трафика (QoS, 0 — низший, 7 — высший).
    *   **DEI (1 бит):** Индикатор допустимости удаления кадра при перегрузке.
    *   **VLAN Identifier (12 бит):** Указывает, какому VLAN ID принадлежит кадр (до 4096 значений).

**Терминация** — процесс удаления VLAN тега из пакета при его передаче в Access-порт.

## 3. Маршрутизация между VLAN
Поскольку VLAN изолируют сети, для связи между ними нужен маршрутизатор.

### Способы маршрутизации:
1.  **Классический:** Маршрутизатор подключается к разным портам коммутатора (Access-порты), каждый из которых находится в своем VLAN. Неэффективно по портам.
2.  **Сабинтерфейсы (Router-on-a-Stick / ROAS):**
    *   Используется одно физическое соединение (**Trunk**).
    *   На маршрутизаторе создаются виртуальные интерфейсы (**sub-interfaces**), каждый из которых привязан к конкретному VLAN ID.
    *   Маршрутизатор принимает тегированный трафик, обрабатывает его и отправляет обратно with нужным тегом другого VLAN.

## 4. Native VLAN
Специальный VLAN по умолчанию (обычно ID 1) для Trunk-порта.
*   Если на Trunk-порт приходит пакет **без тега**, он автоматически приписывается к Native VLAN.
*   Служебные протоколы (например, **STP** — Spanning Tree Protocol) часто обмениваются пакетами через Native VLAN без установки тегов.
*   При включении VLAN на коммутаторе все порты по умолчанию находятся в Native VLAN в режиме Access.

## 5. VLAN и MTU
Максимальный размер стандартного Ethernet фрейма — 1518 байт. Тег 802.1Q добавляет еще 4 байта, увеличивая размер до 1522 байт.
*   **Важно:** менять MTU вручную обычно не требуется, так как современное оборудование поддерживает такие пакеты по умолчанию.

# Туннелирование и VPN

## 1. Введение в туннелирование
В классической модели ISO/OSI данные перемещаются вертикально. Однако при маршрутизации пакеты могут "двигаться вдоль уровней" — подниматься до сетевого уровня и отправляться обратно вниз.

**Туннелирование** — это процесс создания логического соединения между двумя конечными точками посредством инкапсуляции одного протокола в другой (того же или более высокого уровня).
*Пример:* `Ethernet -> IPv4 -> IPv4 -> TCP`.

## 2. Назначение туннелей
1.  **Объединение удаленных офисов:** Связь между сетями с "серыми" IP-адресами через публичный интернет.
2.  **Обход ограничений:** Преодоление ограничений провайдеров или маршрутизация специфических протоколов.
3.  **Безопасность:** Создание защищенных каналов связи (VPN).
4.  **Тестирование:** Эмуляция нахождения в другой географической локации (например, для проверки языковых настроек сайта).

## 3. VPN (Virtual Private Network)
Виртуальная частная сеть — обобщенное название технологий, позволяющих обеспечить сетевые соединения поверх другой сети. Туннелирование — основной метод реализации VPN.

## 4. Протокол IPIP (IP-over-IP)
Самый простой тип туннеля (RFC 2003). Передача IP-пакета внутри другого IP-пакета.
*   **Настройка:** Требует создания виртуального L3-интерфейса и настройки маршрутов.
*   **Минусы:** Данные передаются в открытом виде, нет аутентификации, инкапсулирует только IPv4, не работает через NAT.

## 5. GRE (Generic Routing Encapsulation)
Универсальный протокол инкапсуляции от Cisco (RFC 2784).
*   **Возможности:** Пробрасывает IPv4/IPv6, групповой (multicast) трафик и немаршрутизируемые протоколы (NetBios, IPX, AppleTalk).
*   **Особенности:** Заголовок 4 байта, без состояния (stateless), нет шифрования, не работает через NAT.

## 6. Основные виды VPN-туннелей
*   **OpenVPN:** Работает через TCP/UDP (порт 1194). Проходит через NAT. Режимы: **TUN** (L3) и **TAP** (L2/Ethernet). Поддерживает шифрование и сжатие данных.
*   **IPsec (IP Security):** Набор протоколов для защиты IP-трафика.
    *   **ESP:** Шифрование и аутентификация данных.
    *   **AH:** Проверка целостности и аутентификация источника.
    *   **IKE:** Согласование алгоритмов и обмен ключами.
    *   Режимы: **Транспортный** (шифруются только данные) и **Туннельный** (шифруется весь пакет).
*   **PPTP:** Устаревший протокол. Использует TCP 1723 для управления и GRE для передачи данных. Небезопасен.
*   **L2TP:** Использует UDP (порт 1701), работает через NAT. Часто применяется в связке **L2TP/IPsec** для обеспечения высокого уровня безопасности.

# DHCP (Dynamic Host Configuration Protocol)

## 1. Введение и назначение
DHCP (RFC 2131) — протокол прикладного уровня (L7), предназначенный для автоматической настройки сетевых параметров хостов.
*   **Настраиваемые параметры:** IP-адрес, маска подсети, шлюз по умолчанию (Default Gateway), DNS-серверы и др. (всего около 200 опций).
*   **Преимущества:** Экономия времени администратора, исключение ошибок ручного ввода, автоматическое управление пулом адресов.

## 2. Архитектура и протокол
*   **Модель:** Клиент-серверная.
*   **Транспорт:** UDP.
*   **Порты:**
    *   **67** — DHCP-сервер.
    *   **68** — DHCP-клиент.
*   **Уровни:** Прикладной уровень, но использует IP (сетевой уровень) для доставки сообщений.

## 3. Формат DHCP-пакета
Основные поля:
*   **op (1 байт):** Тип сообщения (1 = Request, 2 = Reply).
*   **xid (4 байта):** Идентификатор транзакции (связывает запрос клиента с ответом сервера).
*   **ciaddr:** Текущий IP-адрес клиента (если есть).
*   **yiaddr (Your IP):** IP-адрес, предлагаемый сервером клиенту.
*   **siaddr:** IP следующего сервера (например, для загрузки по сети).
*   **giaddr:** IP-адрес ретранслятора (Relay Agent).
*   **chaddr:** MAC-адрес клиента (используется сервером для ответа, когда у клиента еще нет IP).
*   **options:** Список параметров (маска, шлюз, время аренды и т.д.).

## 4. Процесс взаимодействия (DORA)
1.  **Discover (Бродкаст):** Клиент ищет сервер (`0.0.0.0 -> 255.255.255.255`).
2.  **Offer (Юникаст/Бродкаст):** Сервер предлагает IP. Перед этим сервер может проверить адрес через ICMP Echo Request.
3.  **Request (Бродкаст):** Клиент выбирает одно из предложений и уведомляет об этом все серверы.
4.  **Ack (Acknowledge):** Сервер подтверждает аренду и передает все настройки.
*   **NACK:** Отрицательный ответ, если сервер не может выделить данный адрес.
*   **Release:** Клиент добровольно освобождает адрес.

## 5. Аренда и обновление адреса
IP-адрес выдается на определенное время (**Lease Time**).
*   **Renewal Time (T1):** Обычно 50% от Lease Time. Клиент шлет `Request` юникастом тому же серверу.
*   **Rebinding Time (T2):** 87.5% от Lease Time. Если сервер не отвечает, клиент шлет бродкаст-запрос любому доступному серверу.

## 6. DHCP Relay (Ретранслятор)
Позволяет клиентам и серверу находиться в разных подсетях.
*   Маршрутизатор (Relay Agent) перехватывает бродкаст-запрос клиента.
*   Вписывает свой IP в поле `giaddr`.
*   Пересылает пакет юникастом на IP DHCP-сервера.
*   Сервер понимает, из какой сети пришел запрос, благодаря полю `giaddr`.

## 7. Безопасность
*   **DHCP Starvation:** Атака поддельными MAC-адресами для исчерпания пула IP.
*   **Rogue DHCP (DHCP Spoofing):** Поддельный сервер выдает неверные настройки (например, свой IP в качестве шлюза для атаки Man-in-the-Middle).
*   **Протокол-предшественник:** BOOTP (использовался для бездисковых станций).

# ARP Proxy

**ARP Proxy** — техника, позволяющая маршрутизатору отвечать на ARP-запросы своим MAC-адресом для узлов, которые находятся в разных канальных сегментах, но в одной логической IP-сети.

### Принцип работы:
1.  **Хост A** считает, что **Хост B** находится в его локальной сети (из-за неверной маски или специфики топологии).
2.  Хост A отправляет ARP-запрос: "Какой MAC у Хоста B?".
3.  **Маршрутизатор**, видя, что Хост B находится за другим интерфейсом, отвечает своим MAC-адресом.
4.  Хост A отправляет пакеты на MAC маршрутизатора, а тот пересылает их Хосту B.

**Результат:** Прозрачное объединение двух физических сегментов в один логический без настройки шлюзов на конечных устройствах.

# NAT (Network Address Translation)

NAT — это процесс преобразования IP-адресов (и часто портов) при прохождении пакета через маршрутизатор.

### Разновидности NAT:

1.  **Full-cone NAT (Статический NAT 1:1)**
    *   Взаимная трансляция: одна пара `внутренний IP:порт` всегда привязана к одной паре `внешний IP:порт`.
    *   Устройство полностью доступно извне по внешнему IP/порту.

2.  **Address-restricted-cone NAT**
    *   Как Full-cone, но с фильтрацией по IP. Извне пакет пройдет, только если внутренний хост ранее отправлял пакет на этот внешний IP.

3.  **Port-restricted-cone NAT**
    *   Добавляет фильтрацию по порту. Внешний хост должен отвечать только с того порта, на который пришел пакет от внутреннего устройства.

4.  **Symmetric NAT (PAT / Port Address Translation)**
    *   Самый строгий тип. Для каждого нового адреса назначения создается новая уникальная трансляция.
    *   Часто используется в корпоративных сетях для безопасности.

5.  **One-to-Many (NAPT / IP Masquerading)**
    *   Самый распространенный вид (домашние роутеры). Множество внутренних адресов транслируются в один внешний белый IP.
    *   Разделение потоков происходит за счет динамической подмены портов источника.

**NAT traversal** — техники (STUN, TURN, ICE) для установки прямого соединения между хостами, находящимися за NAT.

# MTU, Фрагментация и PMTUD

### Основные понятия:
*   **MTU (Maximum Transmission Unit):** Максимальный размер пакета, который может быть передан по каналу. Для Ethernet стандарт — 1500 байт.
*   **L2 MTU (Ethernet MTU):** Размер фрейма с учетом заголовков канального уровня (обычно 1514 или 1518 байт).
*   **TCP MSS (Maximum Segment Size):** Максимальный размер полезных данных в одном TCP-сегменте (обычно `MTU - 20 (IP) - 20 (TCP) = 1460 байт`).

### Проблема фрагментации:
Если пакет больше MTU канала, он разбивается на фрагменты. Это плохо, потому что:
1.  **Нагрузка на CPU:** Маршрутизаторам сложно дробить пакеты, а хостам — собирать их обратно.
2.  **Низкая эффективность:** Если потеряется один фрагмент, придется переотправлять весь исходный пакет.
3.  **Служебная нагрузка:** У каждого фрагмента свой заголовок, что съедает полезную пропускную способность.

### PMTUD (Path MTU Discovery):
Техника автоматического определения минимального MTU на всем пути следования пакета (RFC 1191).
1.  Отправитель ставит в IP-пакете флаг **DF (Don’t Fragment) = 1**.
2.  Если на пути встречается узел с меньшим MTU, он отбрасывает пакет и шлет **ICMP Type 3 Code 4** (Fragmentation needed but DF set), указывая свой MTU.
3.  Отправитель уменьшает размер пакетов до полученного значения.

### Проблема "Черной дыры" (BlackHole):
Если промежуточные узлы или фаерволы блокируют ICMP-сообщения, отправитель не узнает, что пакеты отбрасываются из-за MTU.
*   **Симптом:** TCP-соединение устанавливается (маленькие пакеты проходят), но передача данных (большие пакеты) виснет.
*   **Решение:** Ручное уменьшение **TCP MSS** на маршрутизаторе.
