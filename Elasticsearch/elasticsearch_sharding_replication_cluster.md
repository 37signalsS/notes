# Шардирование, репликация и настройка кластера Elasticsearch 8

Этот документ описывает ключевые концепции шардирования и репликации в Elasticsearch, статусы кластера, а также пошаговый процесс настройки кластера Elasticsearch версии 8, включая распространенные проблемы и их устранение.

## 1. Введение в шардирование и репликацию

### 1.1. Шардирование (Sharding)

Шардирование — это процесс разделения больших объемов данных на более мелкие, управляемые части, называемые шардами (осколками). Каждый шард является независимой единицей хранения и может быть размещен на отдельном узле кластера.

**Преимущества шардирования:**
*   **Распределение нагрузки на запись:** Запросы на запись могут быть распределены между несколькими узлами, что повышает пропускную способность.
*   **Масштабирование хранения:** Позволяет хранить огромные объемы данных, распределяя их по нескольким серверам.
*   **Параллельная обработка:** Поиск и агрегация данных могут выполняться параллельно на нескольких шардах, ускоряя операции.

**Особенности:**
*   Количество шардов для индекса определяется при его создании и **не может быть изменено** без полной реиндексации данных.
*   Шарды одного индекса могут храниться на одном узле, но для распределения нагрузки и отказоустойчивости их размещают на разных узлах.
*   Шардирование реляционных баз данных (например, MySQL) на уровне СУБД крайне неэффективно из-за связей между данными. В таких случаях шардирование реализуется на уровне приложения.

### 1.2. Репликация (Replication)

Репликация — это процесс создания копий шардов (реплик) для обеспечения отказоустойчивости и распределения нагрузки на чтение. Реплика шарда должна храниться на другом узле, отличном от узла, на котором находится первичный шард.

**Преимущества репликации:**
*   **Отказоустойчивость:** При выходе из строя узла с первичным шардом, одна из его реплик автоматически становится первичным шардом, обеспечивая непрерывность работы.
*   **Распределение нагрузки на чтение:** Запросы на чтение могут быть распределены между первичным шардом и его репликами.
*   **Резервное копирование:** Реплики могут служить источником для создания резервных копий.

**Особенности:**
*   Количество реплик для индекса **можно изменять динамически** после его создания.
*   Реплика не имеет смысла, если хранится на том же узле, что и первичный шард.

## 2. Статусы кластера Elasticsearch

Elasticsearch использует цветовую индикацию для отображения состояния кластера:

*   **Green (Зеленый):** Кластер полностью работоспособен. Все первичные шарды и их реплики доступны и распределены корректно. Это идеальное состояние.
*   **Yellow (Желтый):** Кластер работоспособен, но не все реплики доступны. Все первичные шарды доступны, но одна или несколько реплик отсутствуют или не распределены. Кластер может обрабатывать запросы на чтение и запись, но его отказоустойчивость снижена. Часто возникает, если количество узлов меньше, чем требуется для размещения всех реплик (например, 1 узел с 1 репликой).
*   **Red (Красный):** Кластер неработоспособен или частично неработоспособен. Один или несколько первичных шардов недоступны. Это означает потерю данных или невозможность доступа к ним. Требует немедленного вмешательства.

## 3. Настройка кластера Elasticsearch 8

Elasticsearch 8 имеет встроенные механизмы безопасности (TLS, аутентификация), что усложняет начальную настройку по сравнению с предыдущими версиями.

### 3.1. Подготовка узлов

Перед началом установки убедитесь, что на всех узлах установлена Java (рекомендуется OpenJDK).

### 3.2. Установка Elasticsearch

Установите Elasticsearch на каждый узел. В Ubuntu это можно сделать с помощью `apt`:

```bash
sudo apt update
sudo apt install elasticsearch
```

### 3.3. Настройка первого узла (Master Node)

1.  **Отредактируйте файл конфигурации** `/etc/elasticsearch/elasticsearch.yml`:

    ```yaml
    cluster.name: my-es-cluster # Уникальное имя кластера
    node.name: node-1           # Уникальное имя узла
    network.host: 0.0.0.0       # Слушать на всех IP-адресах (для простоты)
    http.port: 9200
    transport.port: 9300
    discovery.seed_hosts: ["192.168.101.64", "192.168.101.65", "192.168.101.63"] # IP-адреса всех узлов кластера
    cluster.initial_master_nodes: ["node-1"] # Имена узлов, которые могут стать мастерами при первом запуске
    ```

    *   `cluster.name`: Все узлы в одном кластере должны иметь одинаковое имя кластера.
    *   `node.name`: Уникальное имя для каждого узла.
    *   `network.host`: `0.0.0.0` позволяет Elasticsearch слушать на всех доступных сетевых интерфейсах. В production-средах рекомендуется указывать конкретные IP-адреса.
    *   `discovery.seed_hosts`: Список IP-адресов узлов, которые Elasticsearch будет использовать для обнаружения других узлов кластера.
    *   `cluster.initial_master_nodes`: Список имен узлов, которые будут участвовать в выборе мастера при первом запуске кластера. **Важно:** Этот параметр используется только при первом запуске кластера. После того как кластер сформирован, его следует удалить или закомментировать, либо обновить, если вы добавляете новые узлы, которые могут стать мастерами.

2.  **Запустите Elasticsearch:**

    ```bash
    sudo systemctl start elasticsearch
    sudo systemctl enable elasticsearch
    ```

3.  **Установите пароль для пользователя `elastic`:**
    После первого запуска Elasticsearch 8 автоматически генерирует пароли и сертификаты. Вы можете изменить пароль для встроенного пользователя `elastic` с помощью команды:

    ```bash
    sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic -i
    # Введите новый пароль, например, 123456
    ```

### 3.4. Добавление новых узлов в кластер

Для добавления второго и последующих узлов выполните следующие шаги:

1.  **На существующем мастер-узле сгенерируйте токен регистрации:**

    ```bash
    sudo /usr/share/elasticsearch/bin/elasticsearch-create-enrollment-token -s node
    # Скопируйте сгенерированный токен
    ```

2.  **На новом узле (который будет присоединяться):**
    *   **Остановите Elasticsearch**, если он был запущен ранее: `sudo systemctl stop elasticsearch`.
    *   **Очистите данные и конфигурацию**, если узел ранее запускался как независимый кластер (это критично для ES 8 из-за сертификатов):
        ```bash
        sudo apt purge elasticsearch # Удалит пакет и конфиги
        sudo rm -rf /var/lib/elasticsearch # Удалит данные
        sudo rm -rf /etc/elasticsearch # Удалит конфиги, если purge не справился
        sudo apt install elasticsearch # Установите заново
        ```
    *   **Отредактируйте файл конфигурации** `/etc/elasticsearch/elasticsearch.yml`:
        ```yaml
        cluster.name: my-es-cluster # Должно совпадать с именем кластера
        node.name: node-2           # Уникальное имя для этого узла
        network.host: 0.0.0.0
        http.port: 9200
        transport.port: 9300
        discovery.seed_hosts: ["192.168.101.64", "192.168.101.65", "192.168.101.63"] # IP-адреса всех узлов кластера
        cluster.initial_master_nodes: ["node-1", "node-2", "node-3"] # Имена всех узлов, которые могут стать мастерами
        ```
        **Важно:** `cluster.initial_master_nodes` должен содержать имена всех узлов, которые могут быть мастер-узлами в кластере. Для кластера из 3 узлов это будут все 3 узла.

    *   **Примените токен регистрации:**
        ```bash
        sudo /usr/share/elasticsearch/bin/elasticsearch-reconfigure-node --enrollment-token <ВАШ_ТОКЕН>
        ```
        Эта команда настроит безопасность и сертификаты на новом узле.

    *   **Запустите Elasticsearch:**
        ```bash
        sudo systemctl start elasticsearch
        sudo systemctl enable elasticsearch
        ```

3.  **Повторите шаги 1-2 для каждого дополнительного узла.**

### 3.5. Проверка состояния кластера

Используйте `curl` для проверки состояния кластера (после установки пароля `elastic`):

```bash
curl -u elastic:123456 -X GET "http://localhost:9200/_cat/nodes?v"
curl -u elastic:123456 -X GET "http://localhost:9200/_cluster/health?pretty"
```

## 4. Кворум и Split-Brain

**Кворум** — это минимальное количество узлов, которые должны быть доступны и связаны друг с другом для того, чтобы кластер считался работоспособным и мог выбрать мастер-узел. Это предотвращает проблему **Split-Brain (расщепление мозга)**, когда из-за сетевых проблем кластер разделяется на несколько независимых частей, каждая из которых считает себя мастером. Это может привести к несогласованности данных.

Для кластера из `N` узлов кворум обычно составляет `(N/2) + 1`. Например, для 3 узлов кворум равен 2.

## 5. Управление шардами и репликами

### 5.1. Создание индекса с шардами и репликами

При создании индекса можно указать количество первичных шардов (`number_of_shards`) и реплик (`number_of_replicas`):

```bash
curl -u elastic:123456 -X PUT "http://localhost:9200/my_test_index?pretty" -H 'Content-Type: application/json' -d'
{
  "settings": {
    "number_of_shards": 1,
    "number_of_replicas": 1
  }
}
'
```

### 5.2. Изменение количества реплик

Количество реплик можно изменить для существующего индекса:

```bash
curl -u elastic:123456 -X PUT "http://localhost:9200/my_test_index/_settings?pretty" -H 'Content-Type: application/json' -d'
{
  "number_of_replicas": 2
}
'
```

### 5.3. Просмотр информации о шардах

```bash
curl -u elastic:123456 -X GET "http://localhost:9200/_cat/shards?v"
```

## 6. Типичные проблемы и отладка

*   **Проблемы с сертификатами:** Elasticsearch 8 активно использует TLS. Если узлы не могут установить доверительные отношения из-за неправильных сертификатов, они не смогут присоединиться к кластеру. Команда `elasticsearch-reconfigure-node` помогает в этом.
*   **Ошибки `duplicate cluster.initial_master_nodes`:** Этот параметр должен быть указан только при первом запуске кластера или при добавлении новых узлов, которые могут стать мастерами. После формирования кластера его следует удалить или закомментировать, либо убедиться, что он содержит актуальный список всех потенциальных мастер-узлов.
*   **Узел не присоединяется к кластеру:**
    *   Проверьте логи Elasticsearch на узле, который не присоединяется.
    *   Убедитесь, что `cluster.name` совпадает на всех узлах.
    *   Проверьте сетевую связность между узлами (порты 9200 и 9300).
    *   Убедитесь, что `discovery.seed_hosts` содержит корректные IP-адреса всех узлов.
    *   Если узел ранее запускался как независимый кластер, выполните полную очистку данных и переустановку.
*   **Кластер в статусе Yellow:** Обычно означает, что не все реплики распределены. Это может произойти, если недостаточно узлов для размещения всех реплик, или если узел с репликой временно недоступен.
*   **Кластер в статусе Red:** Указывает на потерю первичных шардов. Это серьезная проблема, требующая восстановления данных или вмешательства администратора.
*   **Несогласованность с приложениями:** Убедитесь, что приложения, взаимодействующие с Elasticsearch, корректно настроены для работы с кластером, а не с отдельными узлами. Некоторые драйверы могут не понимать кластерную архитектуру и отправлять запросы на конкретные IP-адреса, что приводит к ошибкам при недоступности узла. Например, был случай, когда при отключении одной из трех нод кластера Elasticsearch, приложение, использующее некластерный драйвер, начало получать 30% ошибок, так как драйвер отправлял запросы на конкретные IP-адреса узлов, а не на кластер в целом.

## 7. Рекомендации

*   **Используйте конкретные версии:** Избегайте использования тега `latest` для Docker-образов или версий программного обеспечения. Всегда указывайте конкретную, проверенную версию (например, `elasticsearch:8.11.1`).
*   **Тщательная проверка конфигурации:** Внимательно проверяйте все параметры в `elasticsearch.yml`.
*   **Изучайте логи:** Логи Elasticsearch содержат ценную информацию для диагностики проблем.
*   **Рассмотрите Docker:** Для тестовых и dev-среды использование Docker или Docker Compose может значительно упростить развертывание и управление кластером Elasticsearch.
*   **Согласование с разработчиками:** При работе с распределенными системами важно убедиться, что приложения корректно взаимодействуют с кластером, учитывая его архитектуру и отказоустойчивость.
