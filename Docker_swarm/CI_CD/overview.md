# CI/CD с Docker Swarm: Обзор и концепции

## Определения

- **[Docker Swarm](../docker_swarm_overview.md):** Нативная система оркестровки контейнеров от Docker, позволяющая объединять несколько хостов в единый виртуальный Docker-хост (кластер). Используется для развертывания и масштабирования сервисов.
- **[GitLab CI/CD](../../CI-CD/GitLab_CI/Concepts/gitlab_ci_basics.md):** Встроенный в GitLab инструмент для автоматизации сборки, тестирования и развертывания приложений (CI/CD). Пайплайны описываются в файле `.gitlab-ci.yml`.
- **[Traefik](../../WebServers/Traefik/traefik_overview.md):** Современный обратный прокси и балансировщик нагрузки, который автоматически обнаруживает сервисы (Service Discovery) и управляет маршрутизацией трафика к ним, включая автоматическое управление SSL-сертификатами.
- **[mTLS (mutual TLS)](../../Networking/Protocols/tls.md#сценарий-2-взаимная-аутентификация-mtls):** Протокол взаимной аутентификации на основе сертификатов, обеспечивающий безопасное соединение между GitLab Runner и Docker API.
- **[Environment Scope](../../CI-CD/GitLab_CI/Concepts/gitlab_ci_variables_secrets.md):** Механизм GitLab CI для изоляции переменных окружения (сертификатов, хостов) между различными средами развертывания (development, production).

## Базовые концепции

### Архитектура решения

Решение базируется на интеграции трех компонентов: **GitLab CI** (автоматизация), **Docker Swarm** (оркестрация) и **Traefik** (маршрутизация).

Ключевые принципы:

1. **Безопасное удаленное управление:** GitLab Runner взаимодействует с Docker Engine по протоколу TCP через защищенный порт 2376. Использование **mTLS** исключает необходимость установки агентов напрямую на узлы кластера.
2. **Динамический Ingress:** Traefik автоматически обнаруживает новые сервисы в Swarm через Docker API. Конфигурация маршрутов и выпуск SSL-сертификатов (Let's Encrypt) происходит на основе меток (`labels`) в описании стека.
3. **Изоляция инфраструктуры:** Общие компоненты (балансировщик, базы данных) выделяются в отдельный технологический стек, независимый от жизненного цикла приложений.
4. **Контекстное развертывание:** Использование `environment scope` в GitLab позволяет управлять множеством кластеров из одного пайплайна, динамически подставляя `DOCKER_HOST` и соответствующие сертификаты.

## Практические сценарии

### Сценарий 1: Организация безопасного доступа

Настройка взаимодействия GitLab Runner с кластером:

1. Генерация PKI-инфраструктуры (CA, серверные и клиентские сертификаты) — детали в **[swarm_setup.md](./swarm_setup.md)**.
2. Конфигурация Docker Daemon для прослушивания TCP-порта с проверкой TLS.
3. Настройка **[Docker Context](./docker_context_setup.md)** для абстракции параметров подключения.
4. Безопасное хранение клиентских сертификатов в GitLab CI Variables (тип `File`).

### Сценарий 2: Развертывание базовой инфраструктуры

Управление общими сервисами через отдельный репозиторий:

1. Описание стека Traefik в `docker-compose.yml`.
2. Настройка автоматического развертывания инфраструктурного стека через GitLab CI.
3. Использование `shared-network` для связи Ingress-прокси с будущими приложениями.
4. Подробная инструкция в **[infra_deployment.md](./infra_deployment.md)**.

### Сценарий 3: Пайплайн доставки приложения

Автоматизация жизненного цикла приложения:

1. **Сборка (Build):** Создание Docker-образа с помощью Kaniko (рекомендуется для безопасности).
2. **Развертывание (Deploy):** Выполнение `docker stack deploy` с использованием `--with-registry-auth`.
3. **Маршрутизация:** Использование меток для автоматической настройки Traefik.
4. Подробная инструкция в **[app_deployment.md](./app_deployment.md)**.

### Сценарий 4: Маршрутизация и SSL-терминация

Пример конфигурации сервиса для автоматического получения домена и SSL:

```yaml
deploy:
  labels:
    - "traefik.enable=true"
    - "traefik.http.routers.my-app.rule=Host(`app.example.com`)"
    - "traefik.http.routers.my-app.entrypoints=websecure"
    - "traefik.http.routers.my-app.tls.certresolver=myresolver"
    - "traefik.http.services.my-app.loadbalancer.server.port=3000"
```

**Результат:** Traefik обнаруживает метки, создает маршрут и выпускает сертификат. Детали в **[../swarm_ingress_traefik.md](../swarm_ingress_traefik.md)**.

## Дополнительная информация

### Преимущества подхода

- **Безопасность:** Отсутствие Docker Socket в пайплайнах; шифрование трафика через mTLS.
- **Скорость:** Мгновенная готовность маршрутов при запуске новых контейнеров.
- **Стандартизация:** Единый подход к развертыванию инфраструктуры и кода приложений.

### Рекомендации

- **Безопасность образов:** Всегда используйте флаг `--with-registry-auth` для доступа узлов к приватным реестрам.
- **Версионирование:** Фиксируйте версии образов Traefik и других критических компонентов.
- **Очистка:** Настройте автоматическую очистку неиспользуемых образов и контейнеров на узлах Swarm.
