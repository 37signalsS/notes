# Docker Swarm Overview

## Определения

**Docker Swarm Mode** — нативная функция Docker Engine для оркестрации контейнеров. Позволяет создавать и управлять кластером из нескольких Docker-хостов, объединяя их в один виртуальный Docker-хост для развертывания приложений в виде *сервисов* из множества контейнеров, распределенных по узлам кластера.

**Сервис (Service)** — декларативное описание задачи для выполнения в кластере. Определяет Docker-образ, количество реплик, опубликованные порты и другие параметры. Подробнее в **[swarm_core_concepts.md](./swarm_core_concepts.md)**.

**Routing Mesh** — встроенный механизм балансировки нагрузки, распределяющий входящие запросы между репликами сервиса. Позволяет обратиться к сервису по опубликованному порту на *любом* узле кластера. Подробнее в **[swarm_core_concepts.md](./swarm_core_concepts.md)**.

## Базовые концепции

### Архитектура

Docker Swarm использует архитектуру с двумя типами узлов:

- **Менеджеры (Manager Nodes)** — управляют кластером: поддерживают желаемое состояние, распределяют задачи, обрабатывают API-запросы. Для консенсуса используют алгоритм **Raft**. Рекомендуется нечетное количество (3 или 5) для отказоустойчивости.
- **Рабочие узлы (Worker Nodes)** — выполняют задачи: запускают и останавливают контейнеры по инструкциям менеджеров.

Все узлы общаются через зашифрованный **TLS-канал**.

### Ключевые компоненты

- **Service Discovery** — автоматическое обнаружение сервисов через встроенный DNS. Контейнеры обращаются друг к другу по именам сервисов.
- **Балансировка нагрузки** — распределение трафика между репликами сервиса.
- **Секреты и конфигурации** — встроенные механизмы для безопасного хранения чувствительных данных и конфигурационных файлов. Подробнее в **[swarm_secrets_configs.md](./swarm_secrets_configs.md)**.
- **Оверлейные сети** — создание виртуального сетевого уровня поверх физической инфраструктуры для связи контейнеров на разных узлах. Подробнее в **[swarm_networking.md](./swarm_networking.md)**.

## Дополнительная информация

### Преимущества

- **Низкий порог входа** — прост в освоении для знакомых с Docker и `docker-compose`. Интегрирован в стандартный Docker CLI.
- **Быстрое развертывание** — настройка CI/CD и деплой приложения за несколько часов.
- **Простота для разработчиков** — использование привычных `docker-compose.yml` файлов упрощает вовлечение разработчиков.
- **Встроенные компоненты** — service discovery, балансировка нагрузки, управление секретами.

### Недостатки (в сравнении с Kubernetes)

- **Ограниченная экосистема** — меньше готовых инструментов, плагинов и интеграций.
- **Меньшее сообщество** — сложнее найти решения для нетривиальных проблем.
- **Масштабируемость** — Kubernetes предоставляет более гибкие механизмы автомасштабирования (HPA, VPA, Cluster Autoscaler).
- **Сложность для продвинутых сценариев** — для Canary, Blue-Green или сложных сетевых политик требуются сторонние инструменты.
