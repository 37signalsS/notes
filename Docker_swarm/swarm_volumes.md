# Docker Swarm: управление томами

## Определения

**Local Volume (Локальный том)** — стандартный Docker-том, данные которого хранятся на файловой системе одного конкретного узла Swarm. По умолчанию используется в Swarm-сервисах.

**Persistent Volume (Персистентный том)** — том, данные которого сохраняются при перемещении контейнеров между узлами кластера. Требует использования сетевых файловых систем или плагинов хранения (storage plugins/CSI).

**Cluster Volume (Кластерный том / CSI)** — современный тип томов в Docker Swarm (начиная с версии 23.0), использующий интерфейс CSI для интеграции с внешними хранилищами. Swarm «понимает» топологию таких томов и автоматически управляет их монтированием к нужным узлам.

**Storage Plugin (Плагин хранения)** — программный модуль (Legacy или CSI) для интеграции Docker с внешними системами хранения (Ceph, Portworx, AWS EBS).

## Базовые концепции

### Проблема персистентности в Swarm

По умолчанию тома в Docker Swarm являются **локальными**. Это создает проблему при перемещении задач между узлами:

```
[Узел 1] → [Том: /var/lib/docker/volumes/data]
    ↓ (миграция задачи)
[Узел 2] → [Том: ПУСТО]
```

Если задача сервиса переносится на другой узел (сбой, масштабирование), данные в локальном томе становятся недоступны. Это делает стандартные Docker-тома непригодными для stateful-приложений (базы данных, очереди) без использования распределенных хранилищ.

### Подходы к решению

#### CSI и Cluster Volumes (рекомендуемый подход)

Начиная с **Docker Engine 23.0** и **27.x**, основным способом управления внешними хранилищами стал **CSI (Container Storage Interface)**.

**Преимущества:**
- Автоматическое управление жизненным циклом тома (создание, монтирование, размонтирование).
- Оркестратор знает, где находятся данные, и запускает контейнер на нужном узле.
- Поддержка различных типов доступа: `Single-Writer`, `Multi-Writer`.

#### Сетевые файловые системы (NFS)

**Принцип:** монтирование общей NFS-шары на все узлы Swarm.

| Преимущества | Ограничения |
|---|---|
| Простота реализации | Низкая производительность для I/O-intensive задач |
| Подходит для конфигураций, статики | Единая точка отказа (без HA-NFS) |
| Не требует сложных плагинов | Ручное управление правами доступа |

#### Монтирование привязкой (Bind Mounts)

**Принцип:** монтирование пути с хоста в контейнер.

**Ограничения в Swarm:**
- Путь должен существовать на **всех** узлах кластера.
- Не рекомендуется для продакшена (нарушает абстракцию инфраструктуры).
- Подходит для специфичных системных файлов или логов.

## Практические сценарии

### Использование Cluster Volumes (CSI)

Для работы требуется установленный CSI-плагин (например, для NFS или облачного провайдера).

```yaml
version: '3.8'

services:
  db:
    image: postgres:16-alpine
    volumes:
      - type: cluster
        source: pg_data
        target: /var/lib/postgresql/data
    deploy:
      replicas: 1

volumes:
  pg_data:
    external: true # Том рекомендуется создавать заранее
```

**Создание тома через CLI:**
```bash
docker volume create --driver <csi-driver-name> pg_data
```

### Настройка NFS для общих данных

#### Конфигурация в Stack-файле

```yaml
version: '3.8'

services:
  web:
    image: nginx:1.27-alpine
    deploy:
      replicas: 3
    volumes:
      - nfs-content:/usr/share/nginx/html

volumes:
  nfs-content:
    driver: local
    driver_opts:
      type: nfs
      o: addr=nfs.example.com,rw,nfsvers=4.1
      device: ":/srv/docker/swarm/web-content"
```

**Требования:**
- NFS-сервер доступен со всех узлов Swarm.
- На всех узлах установлен NFS-клиент (`nfs-common` или `nfs-utils`).
- Открыт порт 2049 (TCP/UDP).

### Локальные тома с ограничениями размещения

Если данные могут быть локальными (например, кэш), используйте `placement constraints`:

```yaml
services:
  cache:
    image: redis:7.4-alpine
    volumes:
      - cache-data:/data
    deploy:
      replicas: 1
      placement:
        constraints:
          - node.labels.storage-type == fast-ssd

volumes:
  cache-data:
    driver: local
```

## Устранение неполадок

### Том не монтируется

**Проверка:**
1. Доступность NFS: `showmount -e <server-ip>`.
2. Состояние CSI-плагина: `docker plugin ls`.
3. Логи сервиса: `docker service logs <service-name>`.

**Частые причины:**
- Firewall блокирует порты.
- Несоответствие версий NFS (рекомендуется `nfsvers=4.1`).
- Отсутствие установленных утилит монтирования на хосте.

### Ошибка "volume not found"

Для внешних (`external: true`) томов убедитесь, что они созданы на уровне кластера командой `docker volume create` до запуска стека. Обычные локальные тома создаются автоматически, но Cluster Volumes требуют явного управления.

## Дополнительная информация

### Сравнение решений

| Решение | Персистентность | Сложность | Сценарий (Use Case) |
|---|---|---|---|
| **Local Volume** | Нет | Низкая | Кэш, временные данные |
| **NFS (Local driver)** | Да | Средняя | Конфиги, статический контент |
| **Cluster Volumes (CSI)** | Да | Высокая | Базы данных, облачные диски |

### Лучшие практики

- **Версия Docker:** используйте **27.x** для стабильной работы CSI и Cluster Volumes.
- **Stateful-приложения:** для баз данных предпочитайте CSI-решения с поддержкой топологии.
- **Мониторинг:** проверяйте статус томов через `docker volume inspect`.
- **Права доступа:** при использовании NFS следите за UID/GID внутри контейнера и на сервере.
