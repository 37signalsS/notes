# Сетевое взаимодействие в Docker Swarm

## Определения

Сетевая модель Docker Swarm построена на основе оверлейных сетей, которые создают виртуальный сетевой уровень (Layer 2) поверх существующей инфраструктуры (Layer 3). Это позволяет контейнерам на разных узлах кластера общаться так, будто они находятся в одной локальной сети.

* **Overlay Network (Оверлейная сеть)**: Виртуальная сеть, использующая технологию инкапсуляции (обычно **[VXLAN](../../Networking/Tunnels/vxlan.md)**) для соединения контейнеров на разных хостах. Подробное описание драйвера см. в **[статье о драйвере `overlay`](../../Docker/Docker_network/drivers/overlay.md)**.
* **`ingress`**: Специальная системная `overlay`-сеть, которая управляет входящим трафиком для сервисов Swarm. Она является основой для механизма **[Routing Mesh](./swarm_core_concepts.md)**, распределяя запросы к опубликованным портам по всем репликам сервиса в кластере.
* **`docker_gwbridge`**: Сеть типа `bridge`, которая создается на каждом узле Swarm и соединяет `overlay`-сети (включая `ingress`) с физической сетью хоста, обеспечивая контейнерам доступ во внешние сети (например, в интернет).

## Основные концепции

### Внутреннее и внешнее взаимодействие

1. **Связь между контейнерами**: Контейнеры, подключенные к одной `overlay`-сети, могут напрямую обращаться друг к другу по именам сервисов. Swarm обеспечивает автоматическое **[обнаружение сервисов (Service Discovery)](../../Docker/Docker_network/concepts/dns_and_service_discovery.md)** и балансировку нагрузки через встроенный DNS. Когда один контейнер запрашивает другой по имени, Swarm DNS возвращает IP-адрес одной из его реплик.

2. **Входящий трафик (Ingress)**: Когда запрос поступает на опубликованный порт сервиса на *любом* из узлов кластера, **Routing Mesh** перехватывает его. Трафик сначала попадает в сеть `ingress`, а затем маршрутизируется на подходящую реплику сервиса, даже если она находится на другом узле.

### Изоляция трафика

Каждая `overlay`-сеть является изолированным L2-сегментом. Сервисы, находящиеся в разных оверлейных сетях, не могут общаться друг с другом напрямую, если только они не подключены к одной общей сети. Это обеспечивает базовый уровень сетевой безопасности.

## Практические сценарии

### 1. Создание пользовательской оверлейной сети

Создание зашифрованной `overlay`-сети, к которой могут подключаться не только сервисы, но и обычные контейнеры.

```sh
docker network create \
  --driver overlay \
  --attachable \
  --opt encrypted \
  my-overlay-network
```

* `--attachable`: Позволяет автономным контейнерам (запущенным через `docker run`) подключаться к этой сети.
* `--opt encrypted`: Включает IPsec-шифрование для всего трафика внутри сети.

### 2. Развертывание сервиса в нескольких сетях

Сервис может быть подключен к нескольким сетям одновременно, например, к бэкенд-сети для связи с базой данных и к фронтенд-сети для приема запросов.

```sh
# Создание сетей
docker network create --driver overlay backend-net
docker network create --driver overlay frontend-net

# Развертывание сервиса
docker service create \
  --name my-app \
  --network frontend-net \
  --network backend-net \
  --replicas 3 \
  my-image
```
