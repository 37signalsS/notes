# Docker Swarm: сетевое взаимодействие

## Определения

**Overlay Network (Оверлейная сеть)** — виртуальная сеть уровня L2, созданная поверх физической инфраструктуры уровня L3 с использованием технологии инкапсуляции VXLAN. Позволяет контейнерам на разных узлах кластера взаимодействовать напрямую.

**Ingress Network (Входящая сеть)** — системная оверлейная сеть для управления входящим трафиком. Обеспечивает работу механизма Routing Mesh для балансировки нагрузки.

**docker_gwbridge** — сеть типа `bridge` на каждом узле Swarm, служащая шлюзом для доступа контейнеров во внешние сети (Internet).

**Routing Mesh (Сетчатая маршрутизация)** — механизм Swarm, который направляет входящие запросы на опубликованный порт любого узла кластера к доступной реплике сервиса.

**Virtual IP (VIP)** — виртуальный IP-адрес, назначаемый сервису для балансировки трафика между его репликами на уровне L4.

**DNS Round-Robin (DNSRR)** — метод балансировки, при котором DNS возвращает список IP-адресов всех реплик сервиса без использования VIP.

## Базовые концепции

### Архитектура оверлейных сетей

Оверлейные сети используют VXLAN для передачи данных (Data Plane) и протокол gossip для синхронизации состояния кластера (Control Plane).

| Компонент | Тип | Назначение |
|:---|:---|:---|
| `ingress` | overlay | Прием и балансировка входящего трафика на опубликованные порты. |
| `docker_gwbridge` | bridge | Шлюз для выхода из оверлейной сети во внешний мир. |
| Пользовательские сети | overlay | Изоляция и взаимодействие микросервисов внутри кластера. |

Подробные технические детали инкапсуляции и работы драйвера описаны в SSoT-файле: **[Сетевой драйвер overlay](../Docker/Docker_network/drivers/overlay.md)**.

### Обнаружение сервисов (Service Discovery)

Swarm использует встроенный DNS-сервер (127.0.0.11), доступный во всех контейнерах оверлейной сети.

1. **Endpoint Mode: VIP (по умолчанию)**:
   - Запрос `my-service` возвращает один виртуальный IP.
   - Балансировка выполняется ядром Linux (IPVS).
2. **Endpoint Mode: DNSRR**:
   - Запрос `tasks.my-service` или `my-service` (если режим изменен) возвращает IP всех реплик.
   - Требуется, если балансировщик (например, Nginx) должен сам управлять списком серверов.

### Поддержка IPv6 (версии 27+)

Начиная с Docker 27, поддержка IPv6 в оверлейных сетях стала стабильной. При инициализации сети можно включить Dual-Stack, что критично для современных облачных инфраструктур.

## Практические сценарии

### Создание стабильной сети для облака (MTU 1450)

Стандартный MTU в 1500 часто приводит к проблемам из-за 50-байтового заголовка VXLAN. Для облачных сред (AWS, GCP, Azure) необходимо устанавливать 1450.

```bash
docker network create \
  --driver overlay \
  --opt com.docker.network.driver.mtu=1450 \
  --attachable \
  app-net
```

### Шифрование трафика (IPsec)

Если данные передаются по недоверенным сетям между ЦОД, следует включить шифрование на уровне драйвера.

```bash
docker network create \
  --driver overlay \
  --opt encrypted \
  secure-data-net
```
**Важно:** шифрование снижает производительность на 15-20% и требует открытия протокола ESP (IP protocol 50).

### Разделение трафика управления и данных

Для предотвращения потери связи с мастерами при сетевых штормах рекомендуется разделять интерфейсы управления и данных при инициализации кластера.

```bash
docker swarm init \
  --advertise-addr <IP_MANAGEMENT> \
  --data-path-addr <IP_DATA_TRAFFIC>
```

## Устранение неисправностей

### Требуемые порты (Firewall)

Для корректной работы сети должны быть открыты:
- **2377/TCP**: Управление кластером.
- **7946/TCP+UDP**: Обнаружение узлов (gossip).
- **4789/UDP**: Плоскость данных (VXLAN).
- **IP protocol 50 (ESP)**: Только если используется шифрование (`--opt encrypted`).

### Диагностика связности

Проверка разрешения имен и доступности VIP:
```bash
# Использование netshoot для отладки
docker run --rm -it --network app-net nicolaka/netshoot nslookup my-service

# Проверка портов VXLAN между узлами
nc -zvu <REMOTE_NODE_IP> 4789
```

### Признаки проблем с MTU
- Пакеты малого размера (ping) проходят.
- HTTP-запросы (curl) или передача файлов (SCP) "зависают" на стадии установления TLS-сессии.
- **Решение:** уменьшить MTU до 1450 на всех оверлейных сетях, включая `ingress`.

## Лучшие практики 2025

1. **Всегда задавайте MTU 1450**: Это избавляет от 90% трудноуловимых сетевых проблем в Swarm.
2. **Используйте разные сети**: Создавайте отдельные оверлейные сети для разных стеков приложений (принцип минимальных привилегий).
3. **Мониторинг Gossip**: При большом количестве узлов (>100) следите за нагрузкой на порт 7946, так как трафик gossip растет нелинейно.
4. **Endpoint Mode DNSRR**: Используйте для сервисов, которые сами выполняют балансировку (например, gRPC-клиенты или Ingress-контроллеры).
