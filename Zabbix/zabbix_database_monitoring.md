# Zabbix — мониторинг баз данных

## Определения

**Мониторинг СУБД (Система Управления Базами Данных) в Zabbix** — процесс сбора, анализа и визуализации метрик производительности, доступности и состояния баз данных. Цель — своевременное выявление проблем, оптимизация производительности и обеспечение непрерывной работы БД.

**Уровни мониторинга СУБД:**

- **Инфраструктурный:** CPU (Центральное процессорное устройство), память, диски, сеть на сервере БД.
- **Экземпляр БД:** внутренние метрики СУБД (I/O (Input/Output — ввод-вывод), блокировки, репликация, свободное место в дата-файлах).
- **SQL-синтаксис:** статистика оптимизатора, выявление неоптимальных запросов.
- **Сессии:** активные соединения, сессии с высокой нагрузкой.

## Основные концепции

### Подходы к мониторингу

Мониторинг СУБД должен охватывать все четыре уровня. Необходимость детализации зависит от конкретной системы. Например, проблемы в Oracle часто вызваны нехваткой дискового пространства или сбоями резервного копирования, что заметно на инфраструктурном уровне.

### Методы сбора данных в Zabbix

#### ODBC (Open Database Connectivity)

Универсальный драйвер для прямого подключения Zabbix Server/Proxy к СУБД.

- **Преимущества:** Готовые шаблоны для MySQL, PostgreSQL, Oracle.
- **Недостатки:** Требует прямого сетевого соединения, что может создать риски безопасности в распределенных средах.

#### UserParameter (Zabbix Agent)

Использование кастомных параметров в конфигурации агента. Определение и архитектура метода описаны в разделе **[UserParameter в Zabbix](./definitions_and_concepts.md#определения)**.

- **Преимущества:** Гибкость, безопасность (агент подключается через `localhost`), поддержка любых скриптов.
- **Недостатки:** Требуется поддержка кастомных скриптов на стороне ОС.

#### Zabbix Agent 2

Версия агента на Go со встроенными плагинами для СУБД.

- **Преимущества:** Высокая эффективность, отсутствие необходимости во внешних скриптах для базовых метрик, нативная поддержка плагинов.
- **Примеры:** [Мониторинг PostgreSQL](./zabbix_postgresql_monitoring.md), [Мониторинг MySQL](../Databases/MySQL/monitoring.md).

## Практические сценарии

### Выбор подхода по типу СУБД

| СУБД | Рекомендуемый подход | Документация |
| :--- | :--- | :--- |
| **PostgreSQL** | Zabbix Agent 2 с плагином | [Мониторинг PostgreSQL](./zabbix_postgresql_monitoring.md) |
| **MySQL / MariaDB** | Zabbix Agent + UserParameter | [Мониторинг MySQL](../Databases/MySQL/monitoring.md) |
| **Oracle** | ODBC или специализированные агенты | — |
| **Redis** | Zabbix Agent 2 с плагином | — |

### Рекомендации по настройке

1. **PostgreSQL:** использование **Zabbix Agent 2** является приоритетным методом для получения расширенных метрик (bgwriter, autovacuum).
2. **MySQL:** оптимально использовать **UserParameter** с аутентификацией через файл `.my.cnf` для минимизации прав доступа агента.
3. **Общие советы:** для настройки триггеров и оповещений по результатам мониторинга БД см. раздел **[Лучшие практики настройки Zabbix](./zabbix_best_practices.md)**.
