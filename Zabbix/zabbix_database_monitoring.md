# Мониторинг Баз Данных с помощью Zabbix

> Общее описание архитектуры, компонентов и методов сбора данных Zabbix доступно в основной заметке: **[Обзор Zabbix](./zabbix_overview.md)**.

## Определения

* **Мониторинг Баз Данных с помощью Zabbix**: Процесс сбора, анализа и визуализации метрик производительности, доступности и состояния систем управления базами данных (СУБД) с использованием системы мониторинга Zabbix. Целью является своевременное выявление проблем, оптимизация производительности и обеспечение непрерывной работы баз данных.

## Основные концепции

### Подходы к Мониторингу СУБД

Мониторинг СУБД должен охватывать несколько уровней для обеспечения полной картины состояния. Важно понимать, что необходимость детализации мониторинга зависит от конкретной СУБД. Например, Oracle часто не падает "сам по себе"; проблемы обычно возникают из-за явных недостатков, таких как нехватка дискового пространства, использование файла подкачки или сбои резервного копирования, которые заметны на инфраструктурном уровне. Для других СУБД может быть полезно отслеживать внутренние метрики и статистику, включая статус репликации.

* **Мониторинг на уровне SQL-синтаксиса**:
  * **Цель:** Отслеживание статистики SQL-оптимизатора, выявление неоптимальных запросов.
* **Мониторинг уровня экземпляра Базы Данных**:
  * **Цель:** Контроль внутренних метрик СУБД.
  * **Примеры:** Операции ввода/вывода (количество записей/чтений), заблокированные объекты, состояние репликации, свободное место в дата-файлах.
* **Мониторинг инфраструктуры**:
  * **Цель:** Контроль состояния аппаратных и системных ресурсов, на которых развернута СУБД.
  * **Примеры:** Загрузка CPU, использование памяти, состояние системы хранения (диски), сетевая активность.
* **Мониторинг сессий**:
  * **Цель:** Отслеживание активных сессий, выявление сессий, нагружающих инстанс.

### Варианты Мониторинга СУБД в Zabbix

Zabbix предлагает несколько способов мониторинга баз данных, каждый со своими преимуществами и недостатками:

#### Мониторинг через ODBC

* **Принцип:** Использование универсального драйвера ODBC для прямого подключения Zabbix Server/Proxy к СУБД.
* **Преимущества:** Готовые ODBC-шаблоны для различных СУБД (например, [MySQL](../Databases/MySQL/monitoring.md), [PostgreSQL](../Databases/PostgreSQL/overview.md), Oracle). Удобно для локальных конфигураций (например, в одной подсети).
* **Недостатки:** Требует установки прямого соединения с СУБД. В случае географически распределенной инфраструктуры или использования различных подсетей, это может потребовать проброса портов и дополнительной настройки файрволов, что создает потенциальные риски безопасности и усложняет администрирование. По этой причине такой подход не всегда рекомендуется.

#### Мониторинг через UserParameters Zabbix Agent

* **Принцип:** Определение кастомных параметров (`UserParameter`) в конфигурации Zabbix Agent, которые ссылаются на внешние скрипты или исполняемые файлы. Эти скрипты собирают метрики и возвращают их агенту. Подробный практический пример разобран в заметке о **[мониторинге MySQL с помощью Zabbix Agent](../Databases/MySQL/monitoring.md#мониторинг-mysql-с-помощью-zabbix-agent)**.
* **Преимущества:**
  * **Гибкость:** Позволяет собирать любые кастомные метрики, дополняя или заменяя функционал готовых шаблонов Zabbix.
  * **Безопасность:** Агент работает на том же сервере, что и СУБД, подключаясь через `localhost`. База данных не обязательно должна быть доступна извне, что упрощает сетевую конфигурацию и повышает безопасность.
  * **Поддержка языков:** Скрипты могут быть написаны на любом удобном языке (Python, Bash, Perl и т.д.), обеспечивая кроссплатформенность.
  * **Режимы работы:** Поддерживает как пассивный, так и активный режим агента.
* **Недостатки:**
  * **Разработка и поддержка:** Требуется самостоятельное написание, тестирование и поддержка скриптов, что может быть трудоемко и требовать определенных навыков.
  * **Политики безопасности:** В некоторых компаниях могут существовать строгие политики безопасности, запрещающие размещение сторонних или кастомных скриптов на production-серверах.
  * **Нагрузка:** Неоптимально написанные скрипты могут создавать дополнительную нагрузку на сервер и Zabbix Agent, ухудшая производительность мониторинга и самой СУБД.
  * **Специфичность:** Создание универсального решения для всех СУБД затруднительно; обычно требуется разработка отдельного набора скриптов под каждую конкретную СУБД.

#### Модули для Zabbix Agent и Внешние Агенты

* **Принцип:** Использование специализированных модулей (например, `zabbix.spg.sql` для PostgreSQL) или сторонних агентов (например, Mamonsu для PostgreSQL, Zabbix DBA для MySQL). Современной альтернативой для PostgreSQL является **[мониторинг с помощью Zabbix Agent 2](./zabbix_postgresql_monitoring.md)**, а для MySQL — **[мониторинг через UserParameters](../Databases/MySQL/monitoring.md#мониторинг-mysql-с-помощью-zabbix-agent)**.
* **Преимущества:** Готовые решения для расширенного мониторинга.
* **Недостатки:**
  * **Поддержка и совместимость:** Модули могут не всегда поддерживать последние версии Zabbix Server. Обновление Zabbix Server может привести к несовместимости модуля и потребовать отката или поиска альтернативного решения. (Пример: Zabbix DBA, последние коммиты к которому были 6-7 лет назад, может некорректно работать с новыми версиями Zabbix.)
  * **Установка и компиляция:** Некоторые модули требуют ручной компиляции из исходников. Это усложняет установку и управление, так как нарушает принцип использования пакетных менеджеров в Linux (засорение системы, неуправляемые зависимости).
  * **Зависимость:** Сильная зависимость от сторонних разработчиков и активности их поддержки, что может привести к проблемам в долгосрочной перспективе.

#### Zabbix Agent 2

* **Принцип:** Новая версия Zabbix Agent, написанная на Go. Обладает более модульной структурой.
* **Преимущества:** Эффективный мониторинг СУБД, что наглядно демонстрируется в подходе к **[мониторингу PostgreSQL](./zabbix_postgresql_monitoring.md)**. Относительно кроссплатформенный агент. Разработка плагинов для Zabbix Agent 2 значительно проще, так как они также пишутся на Go (в отличие от плагинов для классического агента на C), что упрощает расширение функционала.

#### Zabbix Agent DBMON

* **Принцип:** Специализированный форк Zabbix Agent, предназначенный для мониторинга широкого перечня СУБД "из коробки" (например, [MySQL](../Databases/MySQL/monitoring.md), [PostgreSQL](../Databases/PostgreSQL/overview.md), Oracle, MS SQL Server). Поставляется с большим количеством готовых шаблонов.
* **Преимущества:** Позволяет существенно упростить развертывание мониторинга для различных СУБД, минимизируя необходимость ручных настроек на сервере.
* **Установка:** Наиболее простой способ установки — это установка стандартного Zabbix Agent, а затем замена его бинарника на скомпилированный бинарник DBMON. Это позволяет избежать сложностей с компиляции всего агента из исходников. Инструкции по сборке доступны в репозитории проекта.
