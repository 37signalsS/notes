# Zabbix — пользовательские макросы

**Актуально для:** Zabbix 7.0 LTS / 7.4

Документ описывает пользовательские макросы (user macros): уровни определения, контекст, секретные значения, порядок разрешения и практическое применение. Связанные темы — **[Элементы данных](./zabbix_items.md)**, **[Триггеры](./zabbix_triggers.md)**, **[Алертинг](./zabbix_alerting_and_escalation.md)**.

---

## Определения

* **Пользовательский макрос (User macro)** — именованное значение с синтаксисом `{$MACRO}`, определяемое администратором; подставляется в поля конфигурации (ключи элементов, выражения триггеров, URL, параметры webhook и т. д.).
* **Уровни определения:** глобальный (Administration → Macros), уровень шаблона и уровень хоста.
* **Контекстный макрос (context macro)** — макрос с уточняющим контекстом: `{$MACRO:"context"}` или `{$MACRO:regex:"regexp"}`.
* **Секретный макрос (secret macro)** — тип значения `Secret text` (маскируется звёздочками) или `Vault secret` (значение берётся из внешнего хранилища секретов).
* **Встроенные макросы (built-in macros)** — предопределённые макросы вида `{HOST.NAME}`, `{TRIGGER.VALUE}`, `{ITEM.LASTVALUE}`, `{HOST.IP}`.
* **LLD-макросы** — макросы `{#MACRO}`, порождаемые правилами низкоуровневого обнаружения.
* **Expression macros** — макросы `{?avg(/host/item,5m)}` для подстановки вычисленных значений в имена/описание событий.

## Основные концепции

### Синтаксис и допустимые символы

Имя пользовательского макроса заключается в фигурные скобки и начинается с `$`:

```default
{$FRONTEND_URL}
{$LOW_SPACE_LIMIT}
{$MYSQL.PORT}
```

В именах допустимы только: заглавные латинские буквы `A-Z`, цифры `0-9`, `_` и `.`. Максимальная длина значения — **2048 символов**.

### Порядок разрешения (precedence)

При совпадении имён Zabbix разрешает макрос в следующем порядке:

1. **Хост** (проверяется первым).
2. Шаблоны **первого** уровня (подключённые напрямую), упорядоченные по ID шаблона.
3. Шаблоны **второго** уровня (шаблоны шаблонов), по ID.
4. Шаблоны **третьего** и более глубоких уровней, по ID.
5. **Глобальный** макрос (проверяется последним).

Если один и тот же макрос есть в нескольких шаблонах одного уровня — берётся макрос шаблона с **наименьшим ID**. Это скрытый риск конфигурации: одинаковые имена в нескольких шаблонах на одном уровне дают неочевидный приоритет.

Если макрос не найден — он **не разрешается**. В разделе Configuration (например, в списке триггеров) макросы намеренно остаются неразрешёнными — чтобы конфигурация была прозрачнее.

### Контекстные макросы

Контекст позволяет переопределять значение макроса под конкретный случай (часто — под элемент, обнаруженный через LLD):

```default
{$LOW_SPACE_LIMIT}                      = 10
{$LOW_SPACE_LIMIT:/home}                = 20     # статический контекст
{$LOW_SPACE_LIMIT:regex:"^/var/log/.*$"} = 30    # контекст-регулярное выражение
{$LOW_SPACE_LIMIT:/tmp}                 = 15
```

Правила:

* Синтаксис статического контекста — `{$MACRO:"static text"}`; если контекст не содержит `}` и не начинается с `"`, кавычки можно опустить: `{$MACRO:/tmp}`.
* Контекст-**регулярное выражение** можно задать **только в конфигурации макроса** (`regex:"..."`). В любом другом месте префикс `regex:` трактуется как обычный статический контекст.
* Если найдено несколько контекстных макросов, сначала сопоставляются простые (статические), затем — регулярные, **в неопределённом порядке**. Нельзя создавать разные контексты, совпадающие с одной и той же строкой.
* Если контекстный макрос не найден (на хосте, в шаблонах, глобально) — ищется макрос **без контекста**.
* В контексте поддерживаются **только LLD-макросы**; остальные макросы трактуются как обычный текст.

### Секретные макросы

Два механизма защиты значений:

* **Secret text** — значение маскируется звёздочками в интерфейсе и хранится в БД Zabbix. Значение **не экспортируется** вместе с шаблоном.
* **Vault secret** — значение хранится во внешнем хранилище (например, HashiCorp Vault), а в макросе задаётся путь/запрос. Zabbix Server получает значение из vault при каждом обновлении конфигурации и кладёт в кэш конфигурации. **Proxy не обращается к vault напрямую** — получает значение из сервера при синхронизации конфигурации (поэтому прокси не может начать сбор после рестарта, пока не получит обновление конфигурации).

Ограничения:

* Секретные макросы **нельзя использовать в выражениях триггеров**.
* URL, содержащий секретный макрос, не работает — макрос разворачивается в `******`.
* Значение секретного макроса может быть раскрыто через элементы данных и скрипты, имеющие доступ к реальному значению (список «unmasked locations» в документации); поскольку Zabbix 7.0.13 косвенные ссылки (`{ITEM.KEY}` и подобные) остаются замаскированными.
* Секретные макросы не используются в триггерных выражениях — для порогов применяйте обычные (Text) макросы.

### Где поддерживаются макросы

Пользовательские макросы поддерживаются в большинстве полей (ключи элементов, параметры функций триггеров, имена/операционные данные, теги, фильтры, параметры webhook/скриптов). Важные ограничения:

* **Actions, Network discovery, Proxies** разрешают **только глобальные** макросы — макросы уровня хоста/шаблона там не работают.
* В выражениях триггеров макрос разрешается **только как параметр или константа**; он **не** разрешается, если ссылается на хост, ключ элемента, функцию, оператор или другое выражение.
* Макросы в ключе trapper-элемента не поддерживаются.
* Теги (имя/значение) разрешают макросы только в момент генерации события.

## Практические сценарии

### Предварительные требования

* Права администратора Zabbix.
* Для vault-макросов — настроенное подключение к хранилищу секретов на стороне Zabbix Server.

### Сценарий 1. Глобальный макрос для общего порога

Administration → Macros → Add:

* `Macro`: `{$CPU_LOAD_MAX}`.
* `Value`: `4`.

Использование в триггере: `avg(/host/system.cpu.load,5m)>{$CPU_LOAD_MAX}`. Изменение порога выполняется в одном месте.

### Сценарий 2. Макрос уровня хоста/шаблона

Host/Template → Macros → Add `{$MYSQL.PORT}` = `3306`. Значение на хосте перекрывает значение из шаблона (host precedence выше).

```default
Key: mysql.ping[tcp://localhost:{$MYSQL.PORT}]
```

### Сценарий 3. Контекстный макрос для LLD

Для обнаруженных файловых систем задать разные пороги:

```default
{$LOW_SPACE_LIMIT}                       = 10
{$LOW_SPACE_LIMIT:/var/log}              = 20
{$LOW_SPACE_LIMIT:regex:"^/data.*$"}     = 5
```

В прототипе триггера использовать контекст из LLD-макроса:

```default
last(/host/vfs.fs.size[{#FSNAME},pfree])<{$LOW_SPACE_LIMIT:"{#FSNAME}"}
```

### Сценарий 4. Секретный макрос для подключения к БД

1. В макросе нажать кнопку в конце поля `Value` и выбрать **Secret text**.
2. Значение становится замаскированным.
3. Использовать в ключе элемента (`mysql.ping[...,{$DB.PASSWORD}]`) — реальное значение подставляется сервером/прокси.

### Сценарий 5. Vault secret

* `Macro`: `{$VAULT.DB.PASSWORD}`.
* `Value type`: **Vault secret**.
* `Value`: путь/запрос к секрету в vault (например, `path/to/secret:password`).

Значение извлечёт Zabbix Server при обновлении конфигурации. Убедиться, что vault доступен серверу; прокси получит значение при синхронизации.

### Валидация

```bash
# Список глобальных макросов через API
curl -s -X POST -H 'Content-Type: application/json-rpc' \
  -H 'Authorization: Bearer <TOKEN>' \
  -d '{"jsonrpc":"2.0","method":"usermacro.get","params":{"globalmacro":true,"output":"extend"},"id":1}' \
  http://zabbix.example.com/zabbix/api_jsonrpc.php
# → список макросов с полями macro/value/type

# Для хоста
# method: usermacro.get, params: {"hostids":["10084"],"output":"extend"}
```

Проверить фактическую подстановку проще всего через кнопку **Test** в элементе/триггере или через Latest data.

## Операции и команды

```bash
# Создать глобальный макрос (globalmacro)
curl -s -X POST -H 'Content-Type: application/json-rpc' \
  -H 'Authorization: Bearer <TOKEN>' \
  -d '{"jsonrpc":"2.0","method":"usermacro.createglobal","params":{"macro":"{$ALERT_THRESHOLD}","value":"85"},"id":1}' \
  http://zabbix.example.com/zabbix/api_jsonrpc.php
# → {"result":{"globalmacroids":["..."]}}

# Создать макрос уровня хоста
# method: usermacro.create, params: {"hostid":"10084","macro":"{$PORT}","value":"8080"}
```

| Поле API | Значение |
|---|---|
| `macro` | Имя макроса, включая `{$...}` |
| `value` | Значение |
| `type` | `0` — Text, `1` — Secret text, `2` — Vault secret |
| `hostid` | Для макросов уровня хоста/шаблона |

## Устранение неисправностей

| Симптом | Причина | Решение |
|---|---|---|
| Макрос отображается как `{$NAME}` | Макрос не найден (нет ни на одном уровне) | Определить макрос; проверить уровни |
| В действии/autoregistration макрос не подставляется | Там поддерживаются только глобальные макросы | Определить макрос глобально |
| Контекстный макрос не срабатывает | Контекст передан как LLD, но правило контекста не совпало | Проверить `regex:` только в конфигурации макроса; избегать пересекающихся контекстов |
| Макрос в триггере не разрешается | Макрос ссылается на хост/ключ/функцию, а не на параметр/константу | Использовать макрос только как параметр/константу |
| Секретный макрос пуст в webhook | Значение не экспортируется; либо URL с masked-значением | Не полагаться на экспорт; не встраивать секрет в URL |
| Vault-макрос пуст после рестарта прокси | Прокси ещё не получил обновление конфигурации | Дождаться синхронизации с сервером; проверить доступ сервера к vault |
| Приоритет макроса неочевиден | Одинаковые имена в нескольких шаблонах одного уровня | Переименовать во избежание недетерминированности; помнить про наименьший ID |

## Лучшие практики

* **Именование:** префикс по области применения, только `A-Z`, `0-9`, `_`, `.` (например, `{$DB.PORT}`, `{$CPU_LOAD_MAX}`).
* **Предпочитать макросы хоста/шаблона глобальным:** изменение глобального макроса запускает инкрементальный пересчёт конфигурации для **всех** хостов.
* **Не дублировать имя макроса в шаблонах одного уровня** — приоритет по наименьшему ID трудно поддерживать.
* **Контексты — только для LLD**, не перекрывать контексты.
* **Пороги в триггерах — через Text-макросы**, а не секретные (секретные в выражениях запрещены).
* **Пароли/токены — Secret text или Vault secret**, не обычный текст.
* **Добавлять макросы в шаблон**, если они используются в шаблонных элементах — иначе при экспорте/импорте XML текстовые макросы могут не сработать (секретные не экспортируются вовсе).
