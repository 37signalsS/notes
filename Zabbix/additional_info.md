# Zabbix: Дополнительная информация

## Определения

**Процесс запуска Zabbix Server** — последовательность инициализации компонентов сервера при старте службы, включающая загрузку конфигурации, проверку БД и запуск рабочих процессов.

**Низкоуровневое обнаружение (LLD) для кастомных метрик** — метод автоматического обнаружения динамических сущностей с использованием пользовательских скриптов и `UserParameter`, расширяющий встроенные возможности LLD.

---

## Основные концепции

### Процесс запуска Zabbix Server

При запуске Zabbix Server выполняет следующую последовательность действий:

1. **Чтение конфигурации** (`zabbix_server.conf`).
2. **Загрузка модулей** и создание кэшей в памяти.
3. **Проверка версии схемы БД**.
4. **Запуск HA-менеджера** (в режиме высокой доступности).
5. **Загрузка конфигурации мониторинга из БД** в кэш. В Zabbix 7.0+ это происходит инкрементально каждые 10 секунд, что снижает нагрузку (до 7.0 — полностью раз в минуту).
6. **Запуск рабочих процессов** (`pollers`, `trappers`, `history syncers` и др.).

Подробнее о настройке кэшей и оптимизации процессов: **[Поиск и устранение неисправностей и тюнинг производительности Zabbix](./zabbix_troubleshooting_and_performance_tuning.md)**.

### Реализация LLD для кастомных метрик

Этот подход обеспечивает максимальную гибкость, позволяя мониторить любые динамические сущности, не поддерживаемые встроенными шаблонами. Базовый принцип LLD описан в разделе **[Низкоуровневое обнаружение](./low_level_discovery.md)**.

#### 1. Скрипт обнаружения

На хосте создаётся скрипт, формирующий JSON для LLD. Пример `my_discovery_script.sh`:

```bash
#!/bin/bash
echo '{ "data": [
  { "{#ITEMNAME}": "CPU_Usage", "{#ITEMDESCRIPTION}": "Загрузка процессора" },
  { "{#ITEMNAME}": "Memory_Free", "{#ITEMDESCRIPTION}": "Свободная память" }
] }'
```

#### 2. UserParameter для агента

В конфигурации Zabbix-агента (`/etc/zabbix/zabbix_agentd.conf.d/`) создаётся `UserParameter` для вызова скрипта:

```
UserParameter=otus.discovery,/usr/local/bin/my_discovery_script.sh
```

#### 3. LLD-правило в Zabbix

В шаблоне создаётся правило обнаружения с ключом `otus.discovery`, которое выполняет `UserParameter` для получения JSON.

#### 4. Прототипы элементов

Создаются прототипы элементов данных с типом **`Zabbix trapper`** и ключами, использующими макросы из JSON:

- **Прототип:** `Custom metric {#ITEMDESCRIPTION}` с ключом `custom.metric[{#ITEMNAME}]`.

#### 5. Отправка данных

Для отправки значений обнаруженных метрик на Zabbix-сервер используется утилита `zabbix_sender` в отдельном скрипте, запускаемом по расписанию (cron). Подробнее об использовании `zabbix_sender`: **[Установка Zabbix Server](./installation.md#отправка-данных-с-помощью-zabbix_sender)**.

## Практические сценарии

### Пример настройки LLD с zabbix_sender

Для отправки значений обнаруженных метрик на Zabbix-сервер используется утилита `zabbix_sender` (подробнее в разделе [отправка данных](./installation.md#отправка-данных-с-помощью-zabbix_sender)), запускаемая по расписанию через cron. Скрипт собирает метрики по ключам, определённым в прототипах элементов, и отправляет их batch-командой:

```bash
#!/bin/bash
# /usr/local/bin/send_custom_metrics.sh
INPUT_FILE="/tmp/zabbix_metrics.txt"
> "$INPUT_FILE"

# Пример: сбор метрик из источников
echo "$(hostname) custom.metric[CPU_Usage] 75.3" >> "$INPUT_FILE"
echo "$(hostname) custom.metric[Memory_Free] 2048" >> "$INPUT_FILE"

# Batch-отправка
zabbix_sender -z 127.0.0.1 -p 10051 -i "$INPUT_FILE"
```
