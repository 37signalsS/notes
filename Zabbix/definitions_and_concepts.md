# Zabbix: Определения и основные концепции

## Определения

* **Zabbix** — свободная, масштабируемая система мониторинга IT-инфраструктур с открытым исходным кодом. Предназначена для отслеживания состояния серверов, сетевого оборудования и приложений в режиме реального времени.
* **Безагентный мониторинг** — совокупность методов сбора данных с хостов и устройств без установки ПО Zabbix. Применяется для сетевого оборудования (коммутаторы, маршрутизаторы), принтеров, специализированных аппаратных хранилищ.
* **SNMP (Simple Network Management Protocol)** — стандартный протокол управления и мониторинга сетевых устройств. Он позволяет Zabbix запрашивать данные у оборудования без установки какого-либо дополнительного ПО. Компоненты:
  * **Сетевой менеджер (Network Manager):** Система, опрашивающая устройства (Zabbix Server).
  * **Агент (Agent):** ПО на управляемом устройстве, отвечающее на запросы менеджера.
  * **MIB (Management Information Base):** Иерархическая БД параметров устройства. Каждое устройство имеет свою MIB-таблицу.
  * **OID (Object Identifier):** Уникальный числовой идентификатор пути к объекту (метрике) в дереве MIB (например, `1.3.6.1.2.1.1.2`).
* **Zabbix Trapper** — специальный элемент данных (`Item`), который не инициирует проверок, а прослушивает входящие данные на определённом порту. Используется для **Push-модели** сбора данных. Для отправки применяется утилита **`zabbix_sender`**.
* **Обнаружение хостов (Network Discovery)** — механизм автоматического нахождения и добавления хостов в мониторинг на основе заданного диапазона IP-адресов и результатов проверок.
* **Низкоуровневое обнаружение (Low-Level Discovery, LLD)** — технология автоматического обнаружения **элементов данных, триггеров и графиков** на хосте. Применяется для динамических сущностей: сетевые интерфейсы, файловые системы, [базы данных](zabbix_postgresql_monitoring.md). Подробное описание принципов работы и практик: **[Низкоуровневое обнаружение (LLD)](./low_level_discovery.md)**.

## Основные концепции

### Ключевые возможности

* **Сбор метрик:** Отслеживание параметров производительности (загрузка ЦПУ, использование диска, сетевая активность, доступность по ICMP).
* **Обнаружение проблем:** Автоматическое определение выхода параметров за пределы нормы.
* **Визуализация:** Построение графиков для анализа тенденций.
* **Оповещения и автоматизация:** Отправка уведомлений о проблемах через различные каналы (Email, SMS, Telegram) и выполнение скриптов. Рекомендации по настройке: **[Лучшие практики настройки Zabbix](./zabbix_best_practices.md)**.
* **Автоматическое обнаружение:** Автоматическое нахождение и постановка на мониторинг новых устройств и ресурсов.
* **Интеграция с внешними системами:** Отправка данных в [Grafana](../Grafana/grafana_overview.md), [Service Desk](./zabbix_best_practices.md), чат-системы.

### Архитектура и компоненты

* **Zabbix Server:** Ядро системы, собирает, хранит и анализирует данные. Взаимодействует с БД (MySQL, PostgreSQL, TimescaleDB). Подробнее: **[Мониторинг Баз Данных с помощью Zabbix](./zabbix_database_monitoring.md)**.
* **Zabbix Proxy:** Опциональный компонент для сбора данных от имени сервера. Снижает нагрузку на ядро, позволяет мониторить изолированные сегменты сети.
* **Zabbix Agent:** Программа, устанавливаемая на хосты для сбора данных. Доступен в двух версиях:
  * **Zabbix Agent (classic):** Классический агент на C.
  * **Zabbix Agent 2:** Агент на Go с модульной архитектурой и плагинами для СУБД (PostgreSQL, MySQL, Oracle).
* **Веб-интерфейс:** Централизованная консоль для настройки, просмотра данных и управления системой.

### Модели и способы сбора данных

#### Модель Pull vs Push

Zabbix поддерживает обе модели сбора данных (гибридный подход).

* **Push-модель (проталкивание):** Zabbix-агент активно собирает метрики и отправляет их на Zabbix-сервер. Используется в **активных проверках (Active checks)**.
* **Pull-модель (затягивание):** Zabbix-сервер сам запрашивает значение метрики у агента. Используется в **пассивных проверках (Passive checks)** и при мониторинге по SNMP.

Сравнение стратегий сбора метрик: **[Стратегии сбора метрик](../Concepts/Observability_and_Monitoring/observability_definitions.md)**.

#### Способы сбора данных

1. **Zabbix Agent:** Основной способ. Доступен в двух версиях:
    * **Zabbix Agent (classic):** Классический агент на C.
    * **Zabbix Agent 2:** Агент на Go с модульной архитектурой и плагинами для СУБД (PostgreSQL, MySQL, Oracle).

    Режимы работы:
    * **Активные проверки:** Агент периодически запрашивает у сервера список элементов данных и самостоятельно отправляет результаты. Предпочтительный, лучше масштабируемый режим.
    * **Пассивные проверки:** Сервер сам запрашивает у агента значение конкретной метрики.

2. **Безагентный мониторинг:** Используется, когда установка агента невозможна или нецелесообразна.
    * **SNMP:** Встроенные шаблоны для сетевого оборудования (Cisco, MikroTik, Huawei и др.).
    * **ICMP:** Проверки доступности (ping).
    * **SSH/Telnet:** Выполнение команд на удаленных хостах.
    * **HTTP/HTTPS:** Проверка доступности и кодов ответа веб-сервисов.

3. **Zabbix Trapper:** **Push-модель**: данные активно отправляются на сервер из внешних источников. Механизм для интеграции с кастомными скриптами, [приложениями](../ELK_Stack/Logstash/logstash_overview.md), бизнес-метриками. Для отправки используется утилита **`zabbix_sender`**.

### Автоматическое обнаружение

#### Обнаружение хостов (Network Discovery)

Процесс состоит из двух частей:

1. **Правило обнаружения (`Discovery rule`):** Задаётся диапазон IP-адресов для сканирования и проверки (например, доступность порта Zabbix-агента).
2. **Действие (`Action`):** Настраивается реакция на успешное обнаружение хоста. Например, при обнаружении Linux-сервера его можно автоматически добавить в нужную группу и привязать к нему соответствующий шаблон мониторинга.

## Практические сценарии

### Выбор стратегии сбора метрик

Для типичной инфраструктуры рекомендуется следующая конфигурация:

| Сценарий | Метод | Обоснование |
|---|---|---|
| Серверы Linux/Windows | Zabbix Agent 2, активные проверки | Масштабируемость, агент сам отправляет данные, снижая нагрузку на сервер |
| Сетевое оборудование (Cisco, MikroTik) | SNMP v2/v3, Pull-модель | Безагентный мониторинг, стандартный протокол |
| Кастомные приложения | Zabbix Trapper + `zabbix_sender` | Приложение само отправляет метрики, см. [отправка данных](./installation.md#отправка-данных-с-помощью-zabbix_sender) |
| Изолированные сегменты сети | Zabbix Proxy + активные проверки | Proxy собирает данные локально и передаёт на сервер, снижая нагрузку и трафик |

Детальное сравнение стратегий: [стратегии сбора метрик](../Concepts/Observability_and_Monitoring/observability_definitions.md).

### Настройка автоматического обнаружения хостов

Пример: автоматическое добавление Linux-серверов в мониторинг.

1. **Discovery rule:** диапазон `192.168.1.0/24`, проверка `system.uname` через Zabbix Agent.
2. **Action:** при обнаружении значения, содержащего `Linux`, хост добавляется в группу `Linux servers` и привязывается к шаблону `Linux by Zabbix agent`.

Подробнее: [установка Zabbix Server](./installation.md#пример-автоматического-добавления-хоста).

### Настройка SNMP-мониторинга

При создании хоста добавляется интерфейс типа SNMP с параметрами:

- **SNMP version:** `2` (наиболее распространён).
- **SNMP community:** строка-пароль (например, `public`), совпадающая с настроенной на устройстве.

Подробнее: [установка Zabbix Server](./installation.md#настройка-snmp-мониторинга).
