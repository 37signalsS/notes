# Zabbix — определения и основные концепции

## Определения

* **Zabbix** — свободная, масштабируемая система мониторинга ИТ-инфраструктур (Информационные технологии) с открытым исходным кодом. Предназначена для отслеживания состояния серверов, сетевого оборудования и приложений в режиме реального времени.
* **Zabbix Server** — центральное ядро системы, отвечающее за сбор, хранение, анализ данных и управление конфигурациями.
* **Zabbix Proxy** — прокси-сервер, который собирает данные от имени Zabbix Server. Снижает нагрузку на основное ядро и позволяет мониторить изолированные сегменты сети.
* **Zabbix Agent** — программное обеспечение, устанавливаемое на целевые объекты мониторинга для сбора метрик.
* **Zabbix Trapper** — специальный элемент данных (Item), который прослушивает входящие данные на определённом порту (Push-модель). Данные отправляются утилитой `zabbix_sender`.
* **UserParameter** — директива в конфигурационном файле Zabbix Agent для определения кастомных метрик. Позволяет агенту выполнять произвольные команды ОС и возвращать результат их выполнения как значение метрики.
* **Безагентный мониторинг** — методы сбора данных без установки ПО Zabbix на целевой хост (например, через SNMP, ICMP, HTTP).
* **SNMP (Simple Network Management Protocol)** — стандартный протокол управления и мониторинга сетевых устройств.
  * **MIB (Management Information Base)** — иерархическая база данных параметров устройства.
  * **OID (Object Identifier)** — уникальный числовой идентификатор пути к метрике в дереве MIB.
* **Триггер (Trigger)** — логическое выражение, определяющее состояние проблемы. Если условие истинно, генерируется событие.
* **Оповещение (Alert/Notification)** — сообщение о событии, отправляемое пользователю через настроенные каналы связи.
* **Низкоуровневое обнаружение (Low-Level Discovery, LLD)** — технология автоматического обнаружения динамических сущностей (интерфейсов, дисков) и создания для них элементов мониторинга. Подробное описание: **[Низкоуровневое обнаружение (LLD)](./low_level_discovery.md)**.

## Основные концепции

### Ключевые возможности

* **Сбор метрик:** отслеживание параметров производительности (ЦПУ (Центральное процессорное устройство), диск, сеть, доступность).
* **Обнаружение проблем:** автоматическое определение отклонений от нормы с помощью триггеров.
* **Визуализация:** построение графиков и дашбордов для анализа тенденций.
* **Оповещения и автоматизация:** уведомления через Telegram, Email, SMS и выполнение автоматических скриптов. Рекомендации: **[Лучшие практики настройки Zabbix](./zabbix_best_practices.md)**.
* **Интеграция:** передача данных во внешние системы, такие как [Grafana](../Grafana/grafana_overview.md).

### Архитектура и компоненты

Система состоит из нескольких взаимодействующих компонентов:

* **Zabbix Server:** выполняет проверки, вычисляет триггеры и отправляет оповещения. Требует базу данных (MySQL, MariaDB или PostgreSQL). При использовании PostgreSQL рекомендуется **TimescaleDB** для оптимизации хранения временных рядов (time-series).
* **Zabbix Proxy:** промежуточное звено для сбора метрик в распределенных сетях.
* **Zabbix Agent:** доступен в двух редакциях:
  * **Zabbix Agent (classic):** написан на C, минимальное потребление ресурсов.
  * **Zabbix Agent 2:** написан на Go, поддерживает расширяемые плагины (например, для глубокого мониторинга PostgreSQL).
* **Веб-интерфейс (Frontend):** консоль управления на базе PHP.

### Модели и способы сбора данных

#### Модели Pull и Push

Zabbix реализует гибридный подход к сбору данных:

* **Push-модель (проталкивание):** агент или внешнее приложение активно отправляет данные на сервер. Используется в **активных проверках (Active checks)** и через Trapper.
* **Pull-модель (затягивание):** сервер или прокси инициирует запрос к агенту или устройству. Используется в **пассивных проверках (Passive checks)** и SNMP.

Теоретические основы: **[Стратегии сбора метрик](../Concepts/Observability_and_Monitoring/observability_definitions.md)**.

#### Способы получения данных

1. **Zabbix Agent:** основной метод. Активный режим лучше масштабируется, так как нагрузка по расписанию проверок перекладывается на агента.
2. **Безагентный мониторинг:**
    * **SNMP:** для сетевого оборудования.
    * **ICMP (Internet Control Message Protocol):** проверка доступности (ping).
    * **SSH (Secure Shell) / Telnet:** выполнение команд на удаленных системах.
    * **HTTP (HyperText Transfer Protocol) / HTTPS (HyperText Transfer Protocol Secure):** мониторинг веб-сервисов и API.
3. **Zabbix Trapper:** прием данных через `zabbix_sender`. Подробнее: **[Отправка данных](./installation.md#отправка-данных-через-zabbix_sender)**.

## Практические сценарии

### Выбор метода мониторинга

| Сценарий | Рекомендуемый метод | Обоснование |
| :--- | :--- | :--- |
| Серверы Linux/Windows | Zabbix Agent 2 (Active) | Высокая производительность, поддержка плагинов. |
| Коммутаторы и роутеры | SNMP v2c/v3 | Стандарт для сетевого оборудования. |
| Мониторинг сайтов | Скрипты (UserParameter) | Гибкость настройки сложных сценариев (авторизация, SLA). Подробнее: **[Мониторинг сайтов](./zabbix_website_monitoring.md)**. |
| Облачные микросервисы | Zabbix Trapper / HTTP | Гибкость интеграции в CI/CD и serverless-среды. |
| Филиальная сеть | Zabbix Proxy | Безопасная передача данных через один порт, буферизация при обрыве связи. |

### Автоматизация через Discovery

* **Network Discovery:** автоматическое нахождение устройств в заданном диапазоне IP-адресов. Концептуальное описание: **[Обнаружение хостов](./installation.md#автоматическое-обнаружение-хостов-network-discovery)**.
* **Low-Level Discovery (LLD):** динамическое создание элементов мониторинга. Подробный разбор: **[Низкоуровневое обнаружение (LLD)](./low_level_discovery.md)**.
