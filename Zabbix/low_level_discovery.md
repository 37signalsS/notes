# Zabbix — низкоуровневое обнаружение (Low-Level Discovery)

## Определения

* **Низкоуровневое обнаружение (LLD)** — технология Zabbix для автоматического обнаружения динамических сущностей на хосте и автоматического создания элементов данных, триггеров и графиков для них. Применяется для файловых систем, сетевых интерфейсов, баз данных и любых объектов, список которых может изменяться.
* **Правило обнаружения (LLD Rule)** — объект в шаблоне или на хосте, выполняющий проверку и возвращающий JSON-данные со списком обнаруженных ресурсов.
* **Прототип (Prototype)** — шаблон объекта мониторинга, использующий LLD-макросы (например, `{#FSNAME}`) для генерации реальных сущностей.

---

## Основные концепции

### Принцип работы

1. **Сбор данных:** LLD-правило выполняет проверку (через агент, SNMP или скрипт) и получает JSON-объект.
2. **Парсинг:** Zabbix извлекает значения макросов из JSON.
3. **Генерация:** На основе прототипов создаются реальные элементы данных, триггеры и графики. Ключи и имена объектов формируются путем подстановки значений макросов.

Если объект исчезает из JSON-ответа, Zabbix помечает созданные на его основе сущности как «потерянные» и удаляет их по истечении заданного периода удержания (Lost resources period).

### Формат JSON

Для корректной работы LLD данные должны быть представлены в виде массива объектов:

```json
{
  "data": [
    { "{#FSNAME}": "/", "{#FSTYPE}": "ext4" },
    { "{#FSNAME}": "/home", "{#FSTYPE}": "xfs" }
  ]
}
```

### Лучшие практики

* **Оптимизация частоты:** Для стабильных объектов (диски, сетевые порты) устанавливайте интервал проверки 1 час или более.
* **Фильтрация:** Используйте регулярные выражения в настройках правила для исключения лишних объектов (например, петлевых интерфейсов или временных ФС).
* **Вложенный LLD:** В Zabbix 7.4+ доступно многоуровневое обнаружение, позволяющее строить иерархические структуры зависимостей.
* **Предобработка:** Используйте JSONPath или JavaScript в шагах Preprocessing для приведения кастомных данных к стандартному формату LLD.

## Практические сценарии

### Использование встроенных правил

Zabbix предоставляет готовые решения для типовых задач:

* **Файловые системы:** Обнаружение разделов и мониторинг их объема.
* **Интерфейсы:** Автоматическое создание графиков трафика для всех активных портов.
* **СУБД:** Обнаружение баз данных и их специфических параметров (см. **[Мониторинг PostgreSQL](./zabbix_postgresql_monitoring.md)**).

### Реализация кастомного обнаружения

Алгоритм создания собственного LLD для нестандартных задач:

#### 1. Подготовка скрипта

Скрипт на стороне агента должен возвращать JSON со списком объектов (например, список запущенных Java-приложений).

#### 2. Настройка UserParameter

В конфигурации агента прописывается команда для вызова скрипта:
`UserParameter=custom.app.discovery,/path/to/script.sh`

#### 3. Создание правила и прототипов

В веб-интерфейсе Zabbix создается LLD-правило с соответствующим ключом. Внутри правила определяются прототипы элементов данных. Если данные будут отправляться принудительно, используйте тип «Zabbix trapper».

#### 4. Наполнение данными

Для передачи значений метрик в созданные объекты используйте утилиту `zabbix_sender`. Подробности и примеры команд приведены в разделе **[Отправка данных через zabbix_sender](./installation.md#отправка-данных-через-zabbix_sender)**.
