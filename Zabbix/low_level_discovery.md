# Zabbix: Низкоуровневое обнаружение (Low-Level Discovery, LLD)

## Definitions

**Низкоуровневое обнаружение (LLD)** — технология Zabbix для автоматического обнаружения динамических сущностей на хосте и создания элементов данных, триггеров и графиков для каждого обнаруженного ресурса. Применяется для файловых систем, сетевых интерфейсов, баз данных и любых сущностей, список которых может изменяться.

**Правило обнаружения (LLD Rule)** — правило в шаблоне Zabbix, выполняющее проверку и возвращающее JSON-объект со списком обнаруженных ресурсов.

**Прототип (Prototype)** — шаблон элемента данных, триггера или графика, использующий макросы из JSON (например, `{#FSNAME}`) для создания реальных объектов.

---

## Basic Concepts

### Принцип работы LLD

1. **Правило обнаружения (LLD Rule)** внутри шаблона выполняет проверку, которая возвращает **JSON-объект** со списком обнаруженных ресурсов.
2. **Прототипы (`Prototypes`)** элементов данных, триггеров и графиков используют специальные макросы из полученного JSON.
3. **Создание реальных объектов:** Zabbix автоматически создаёт настоящие элементы данных, триггеры и графики для каждого обнаруженного ресурса, подставляя значения из JSON в прототипы.

Если ресурс исчезает из JSON при следующей проверке, Zabbix автоматически удаляет связанные с ним метрики и триггеры.

### Формат JSON

Стандартный JSON для LLD содержит массив `data` с объектами, где ключи — макросы:

```json
{
  "data": [
    { "{#FSNAME}": "/", "{#FSTYPE}": "ext4" },
    { "{#FSNAME}": "/boot", "{#FSTYPE}": "ext4" },
    { "{#FSNAME}": "/var/log", "{#FSTYPE}": "xfs" }
  ]
}
```

На основе этих данных Zabbix создаст проверки для каждой файловой системы, используя прототипы, например, `Free disk space on {#FSNAME}` с ключом `vfs.fs.size[{#FSNAME},pfree]`.

### Лучшие практики LLD

* **Интервал выполнения:** Для большинства сущностей (диски, файловые системы, сетевые интерфейсы) достаточно одного раза в день. Частое выполнение создаёт ненужную нагрузку на сервер.
* **Фильтрация:** Используйте фильтры в правилах LLD для исключения ненужных объектов. Например, в шаблоне VMware фильтруйте ВМ по `Power State`, обнаруживая только `poweredOn`.
* **Nested LLD (Zabbix 7.4+):** Поддержка вложенного обнаружения на несколько уровней. Например, Proxmox: ноды → виртуальные машины → диски каждой ВМ.
* **Обработка на сервере:** LLD Workers на сервере получают данные от агентов/прокси и создают элементы/триггеры. Настройка фильтров на уровне правила LLD уменьшает объём передаваемых данных.

## Practical Scenarios

### Встроенные правила LLD

Zabbix поставляется с готовыми правилами обнаружения для типовых сценариев:

* **Файловые системы** — автоматическое обнаружение смонтированных ФС.
* **Сетевые интерфейсы** — обнаружение всех сетевых интерфейсов хоста.
* [**Базы данных**](./zabbix_database_monitoring.md) — автоматическое обнаружение БД на сервере.

### Реализация LLD для кастомных метрик

Пошаговое руководство: [LLD для кастомных метрик](./additional_info.md#реализация-lld-для-кастомных-метрик).

Краткая схема:

1. **Скрипт обнаружения** — формирует JSON со списком ресурсов.
2. **UserParameter** — в конфигурации агента (`/etc/zabbix/zabbix_agentd.conf.d/`) создаётся параметр для вызова скрипта.
3. **LLD-правило** — в шаблоне создаётся правило с ключом `UserParameter`.
4. **Прототипы элементов** — создаются прототипы типа `Zabbix trapper` с макросами из JSON.
5. **Отправка данных** — утилита `zabbix_sender` отправляет значения по расписанию (cron).

Пример настройки с `zabbix_sender`: [LLD с zabbix_sender](./additional_info.md#пример-настройки-lld-с-zabbix_sender).
