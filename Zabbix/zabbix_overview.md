# Zabbix: Обзор системы мониторинга

**Zabbix** – это свободная, масштабируемая система мониторинга IT-инфраструктур с открытым исходным кодом. Она предназначена для отслеживания состояния серверов, сетевого оборудования и приложений в режиме реального времени.

---

## Ключевые возможности

Zabbix представляет собой универсальное решение для мониторинга, которое умеет:

-   **Собирать метрики:** Отслеживать параметры производительности, такие как загрузка ЦПУ, использование дискового пространства, сетевая активность, доступность узлов по ICMP (пинг) и многое другое.
-   **Строить графики:** Визуализировать собранные данные для анализа тенденций.
-   **Обнаруживать проблемы:** Автоматически определять, когда параметры выходят за пределы нормы.
-   **Отправлять оповещения:** Рассылать уведомления о проблемах через различные каналы (Email, SMS, Telegram, Slack и др.).

## Архитектура

Мониторинг в Zabbix может быть организован несколькими способами:

-   **Zabbix Agent:** Установка легковесного агента на наблюдаемые хосты для активного сбора данных.
-   **Безагентный мониторинг:** Использование стандартных протоколов и служб, таких как:
    -   SNMP (Simple Network Management Protocol)
    -   ICMP (для проверки доступности)
    -   Подключения по SSH или Telnet для выполнения команд
    -   Проверка доступности веб-сервисов (HTTP/HTTPS)

Более подробно безагентный мониторинг и автоматическое обнаружение рассматриваются в документе: **[Безагентный мониторинг и автоматическое обнаружение в Zabbix](./zabbix_agentless_monitoring_and_discovery.md)**.

### Модель сбора данных: Push-модель

Zabbix преимущественно использует **Push-модель** сбора данных. Это означает, что Zabbix-агент, установленный на хосте, активно собирает метрики и отправляет ("проталкивает") их на Zabbix-сервер.

-   **Активные проверки (Active checks):** Агент периодически запраширует у сервера список необходимых элементов данных и самостоятельно отправляет результаты. Это основной режим работы.
-   **Пассивные проверки (Passive checks):** Сервер сам запрашивает у агента значение конкретной метрики. Этот режим имитирует Pull-модель, но основная архитектура остается ориентированной на Push.

Такой подход характерен для традиционных систем мониторинга и имеет свои плюсы и минусы по сравнению с Pull-моделью, используемой в [Prometheus](../Prometheus/overview.md).

> Подробное сравнение различных стратегий сбора метрик (Push, Pull, из логов) рассмотрено в заметке: **[Стратегии сбора метрик](../Concepts/metrics_collection_strategies.md)**.

## Компоненты

-   **Zabbix Server:** Ядро системы, которое собирает, хранит и анализирует данные. Он взаимодействует с базой данных (поддерживаются MySQL, PostgreSQL). *Начиная с версии 7.2, Zabbix официально не поддерживает Oracle; рекомендуется использовать PostgreSQL или MySQL.*
-   **Zabbix Proxy:** Опциональный компонент, который может собирать данные от имени сервера, снижая нагрузку на него.
-   **Zabbix Agent:** Программа, устанавливаемая на хосты для сбора данных.
-   **Веб-интерфейс:** Централизованная консоль для настройки, просмотра данных и управления системой.

## Процесс запуска Zabbix Server

При запуске Zabbix Server выполняет следующую последовательность действий для инициализации:

1.  **Чтение конфигурации:** Сервер считывает основной конфигурационный файл (`zabbix_server.conf`) для получения базовых параметров (данные для подключения к БД, размеры кэшей, количество процессов и т.д.).
2.  **Загрузка модулей:** Загружаются необходимые внутренние модули.
3.  **Создание кэшей:** В оперативной памяти создаются и выделяются кэши (`Configuration Cache`, `History Cache`, `Value Cache` и др.).
4.  **Проверка версии БД:** Сервер проверяет, соответствует ли версия схемы базы данных той, с которой он умеет работать. Эту проверку можно отключить специальным параметром, но это не рекомендуется.
5.  **Запуск HA менеджера:** Если Zabbix работает в режиме высокой доступности (High Availability), запускается менеджер, управляющий состоянием узлов кластера.
6.  **Загрузка конфигурации из БД:** Сервер загружает конфигурацию мониторинга (узлы, элементы данных, триггеры) из базы данных в `Configuration Cache`.
    -   **Zabbix 6.x и ниже:** Полная загрузка конфигурации по умолчанию раз в минуту.
    -   **Zabbix 7.0 и выше:** Инкрементальная загрузка изменений каждые 10 секунд, что значительно снижает нагрузку на БД.
7.  **Запуск рабочих процессов:** После полной инициализации запускаются все рабочие процессы: `pollers`, `trappers`, `history syncers` и другие, которые начинают сбор и обработку данных.

## Установка

### Установка сервера (на Ubuntu)

*Инструкции по установке Zabbix сервера на Ubuntu будут добавлены здесь.*

### Установка агента (на Ubuntu)

**Агент Zabbix** – это приложение, которое устанавливается на наблюдаемые хосты для активного сбора данных о состоянии и ресурсах, таких как загрузка ЦПУ, использование памяти, место на диске, доступность портов и т.д.

**1. Добавление репозитория Zabbix:**
Сначала необходимо добавить официальный репозиторий Zabbix, чтобы получить последнюю версию агента.
```bash
# Скачиваем пакет с конфигурацией репозитория для Ubuntu 22.04 (Jammy)
wget https://repo.zabbix.com/zabbix/6.0/ubuntu/pool/main/z/zabbix-release/zabbix-release_6.0-4+ubuntu22.04_all.deb

# Устанавливаем пакет
sudo dpkg -i zabbix-release_6.0-4+ubuntu22.04_all.deb

# Обновляем список пакетов
sudo apt update
```

**2. Установка агента:**
```bash
sudo apt install zabbix-agent
```

**3. Настройка агента:**
Отредактируйте конфигурационный файл `/etc/zabbix/zabbix_agentd.conf`, чтобы указать адрес сервера Zabbix.
```bash
sudo nano /etc/zabbix/zabbix_agentd.conf
```
Найдите и измените следующие параметры:
```ini
# IP-адрес вашего Zabbix-сервера
Server=192.168.1.100

# IP-адрес для активных проверок (обычно тот же)
ServerActive=192.168.1.100

# Имя хоста (должно совпадать с именем хоста в веб-интерфейсе Zabbix)
Hostname=MyUbuntuServer
```

**4. Запуск и включение службы:**
```bash
# Запускаем агент
sudo systemctl start zabbix-agent

# Включаем автозапуск при старте системы
sudo systemctl enable zabbix-agent

# Проверяем статус
sudo systemctl status zabbix-agent
```

**5. Настройка файрвола (если используется):**
Разрешите входящие подключения на порт `10050/tcp` от вашего Zabbix-сервера.
```bash
sudo ufw allow from 192.168.1.100 to any port 10050 proto tcp
```
После этого не забудьте добавить хост в веб-интерфейсе Zabbix.
