## Определения

Для эффективного мониторинга важно понимать ключевые компоненты и архитектуру как PostgreSQL, так и Zabbix. Этот документ фокусируется на специфике их совместного использования.

## Базовые концепции

Существует несколько подходов к мониторингу баз данных, детальное сравнение которых приведено в основной заметке **[Мониторинг Баз Данных с помощью Zabbix](./zabbix_database_monitoring.md)**.

Для PostgreSQL наиболее современным и функциональным подходом является использование **Zabbix Agent 2** со специализированным плагином. Этот метод обеспечивает глубокий мониторинг и высокую производительность благодаря готовым шаблонам.

Ключевые механизмы, используемые в шаблонах для PostgreSQL:

* **Низкоуровневое обнаружение (Low-Level Discovery, LLD):**
  * **Автоматическое обнаружение баз данных:** При создании новой базы данных Zabbix автоматически начинает собирать по ней метрики.
  * **Обнаружение слотов репликации:** Позволяет мониторить состояние и отставание реплик.

* **Макросы:**
  * Позволяют гибко настраивать параметры подключения к PostgreSQL (например, `{$PG.DSN}`, `{$PG.USER}`, `{$PG.PASSWORD}`) непосредственно в Zabbix, без изменения конфигурации агента.

### Практические сценарии

#### 1. Настройка PostgreSQL для мониторинга

Для сбора метрик необходимо выполнить базовые настройки в самой базе данных:

1. **Создание пользователя для мониторинга:**
    Создайте в PostgreSQL специального пользователя (например, `zabbix_monitor`), который будет использоваться для подключения.

    ```sql
    CREATE USER zabbix_monitor WITH PASSWORD 'your_secure_password';
    ALTER USER zabbix_monitor SET search_path TO '"$user", public, pg_catalog';
    GRANT pg_monitor TO zabbix_monitor;
    ```

    Роль `pg_monitor` предоставляет минимально необходимые права для чтения системных представлений статистики.

2. **Конфигурация `pg_hba.conf`:**
    Разрешите подключение для созданного пользователя. Добавьте в `pg_hba.conf` запись, соответствующую вашему типу сети.

    ```
    # TYPE  DATABASE        USER            ADDRESS                 METHOD
    # Для локального подключения с Zabbix Agent
    host    all             zabbix_monitor  127.0.0.1/32            scram-sha-256
    # Для удаленного подключения (замените IP на адрес Zabbix Server/Proxy)
    host    all             zabbix_monitor  <zabbix_server_ip>/32   scram-sha-256
    ```

3. **Тюнинг `postgresql.conf` (опционально, но рекомендуется):**
    Для детального мониторинга запросов включите расширение `pg_stat_statements`.
    * Добавьте `pg_stat_statements` в `shared_preload_libraries`.
    * Примените изменения, перезагрузив сервис PostgreSQL.
    * После перезагрузки выполните в базе команду `CREATE EXTENSION pg_stat_statements;`.

#### 2. Установка плагина PostgreSQL для Zabbix Agent 2

Плагин для PostgreSQL не входит в базовую поставку Zabbix Agent 2 и требует отдельной установки.

* На Linux-системах установите пакет `zabbix-agent2-plugin-postgresql` из официальных репозиториев Zabbix.
* Если плагин не установлен, Zabbix будет сообщать, что ключи элементов данных, связанные с PostgreSQL, не поддерживаются.

#### 3. Ключевые метрики и триггеры

Zabbix Agent 2 собирает обширный набор метрик, используя системные представления PostgreSQL:

* **Состояние соединений (`pg_stat_activity`):**
  * **Метрики:** Количество активных, простаивающих (`idle`), ожидающих (`waiting`) соединений.
  * **Триггеры:** Рост `waiting` соединений (возможные блокировки), пики `active` соединений (высокая нагрузка).

* **Блокировки (`pg_locks`):**
  * **Метрики:** Общее количество блокировок, их типы.
  * **Триггеры:** Превышение порогов `Deadlocks` или `Recovery Conflicts`.

* **Транзакции (`pg_stat_database`):**
  * **Метрики:** Количество зафиксированных (`Commit/s`) и откаченных (`Rollback/s`) транзакций в секунду.
  * **Триггеры:** Аномальный рост откатов, что может указывать на ошибки в логике приложения.

* **Буферный кэш (`pg_stat_bgwriter`):**
  * **Метрики:** Соотношение попаданий в кэш (`buffer hits`) к промахам (`buffer misses`) для оценки эффективности кэширования.
  * **Триггеры:** Низкий `hit rate` может сигнализировать о нехватке памяти, выделенной под `shared_buffers`.

* **Репликация (`pg_stat_replication`):**
  * **Метрики:** Отставание реплик от мастера по WAL (`Streaming Lag`).
  * **Триггеры:** Значительное отставание реплики или остановка процесса репликации.

* **Медленные запросы (`pg_stat_statements`):**
  * **Метрики:** Самые медленные или часто выполняемые запросы (при включенном расширении).
  * **Триггеры:** `Too Many Slow Queries` сигнализирует о необходимости оптимизации.

* **Автовакуум и использование WAL:**
  * **Метрики:** Статистика работы автовакуума, рост объема WAL-файлов.
  * **Триггеры:** Предупреждения об остановке или неэффективности автовакуума, а также о неконтролируемом росте WAL (например, при сломанной репликации).

### Визуализация данных

Для анализа и визуализации собранных метрик можно использовать:

* **Встроенные дашборды Zabbix:** Шаблоны для Zabbix Agent 2 обычно включают предустановленные виджеты и графики.
* **Grafana:** Популярный инструмент для создания информативных дашбордов. Интеграция через **[плагин Zabbix](https://grafana.com/grafana/plugins/alexanderzobnin-zabbix-app/)** с использованием Zabbix API.
