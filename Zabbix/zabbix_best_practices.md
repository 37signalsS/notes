# Лучшие практики настройки Zabbix

> Архитектура и концепции Zabbix: **[Определения и основные концепции](./definitions_and_concepts.md)**.

---

## Определения

* **Триггер (Trigger):** выражение, определяющее пороговое значение элемента данных и генерирующее событие (проблему) при его превышении.
* **Оповещение (Alert/Notification):** сообщение, отправляемое при срабатывании триггера.
* **Гистерезис (Hysteresis):** механизм предотвращения «дребезжания» триггера через разные пороги для состояний «Проблема» и «ОК».
* **Уровни серьёзности (Severity Levels):** классификация проблем (Information, Warning, Average, High, Disaster).
* **Зависимости триггеров (Trigger Dependencies):** связывание триггеров для оповещения только о корневой причине проблемы.

---

## Базовые концепции

Мониторинг в Zabbix основан на сборе метрик и их анализе. Триггеры преобразуют сырые данные в события, а оповещения информируют о проблемах. Грамотная настройка предотвращает «усталость от оповещений» (alert fatigue).

## Практические сценарии

### Настройка триггеров

#### Предотвращение ложных срабатываний

* **Чувствительность:** не настраивайте триггеры на кратковременные колебания (например, 10 секунд недоступности). Срабатывание — после нескольких последовательных неудачных проверок или по истечении времени (например, 5 минут).
* **Гистерезис:** разные условия для `Problem expression` и `OK event generation`. Пример: проблема при > 90 %, восстановление при < 80 %.
* **Функции трендов:** для анализа за длительные периоды (недели, месяцы) используйте `trendavg`, `trendmax` вместо `avg`, `max` — это снижает нагрузку на `Value Cache` и БД.
* **Пример из практики:** триггер «количество абонентов < 1000» генерировал оповещения при 999 абонентах. При реальном падении до 100–200 на аварию среагировали несвоевременно из-за привыкания к «шуму».

#### Приоритизация и зависимости

* **Severity:** настраивайте оповещения для High и Disaster. Остальные — для графиков и информации.
* **Зависимости:** при отказе коммутатора за ним 50 серверов — достаточно одного оповещения о коммутаторе, а не 50 о серверах.

#### Аудит и «шумные» триггеры

* **Регулярный аудит `Monitoring → Problems`:** если события накапливаются без реакции — отключите триггеры.
* **`Reports → Triggers top 100`:** выявляет самые «шумные» триггеры — кандидаты на пересмотр порогов или удаление.
* **`nodata()` не вешать на всё:** при массовом сбое сбора данных такие триггеры генерируют лавину событий. Применяйте только к критичным элементам.

### Каналы оповещений

| Канал | Особенности |
|-------|-------------|
| **Email (SMTP)** | Требует настройки SPF, DKIM, DMARC для доставки. Протокол старый, чувствителен к конфигурации. |
| **Telegram** | Рекомендуемый канал. Простая настройка через бота, push-уведомления уже включены. |
| **Service Desk** | Интеграция с Jira, Redmine для автоматического создания тикетов. |
| **Чат-системы** | Slack, Discord — для командных оповещений. |
| **SMS-шлюзы** | Для критичных уведомлений (Disaster). |

---

### Веб-проверки: Browser vs Web Scenarios

| Подход | Описание |
|--------|----------|
| **Web Scenarios** | Устаревший метод. Последовательность шагов без `if/else`. Проверяет URL, строку, код ответа. Обрабатывается `HTTP Poller`. |
| **Browser Checks** | Рекомендуемый подход. Выполняет JavaScript через Selenium Driver. Поддерживает ветвление, условия, скриншоты. |

**Рекомендация:** для нового веб-мониторинга используйте Browser Checks.

---

### Мониторинг компонентов самого Zabbix

Обязательная настройка — мониторинг собственной инфраструктуры Zabbix:

* **Zabbix Server Health:** кэши, процессы, очередь, производительность.
* **Zabbix Proxy Health:** аналогичный шаблон для каждого прокси.
* **База данных Zabbix:** производительность, размер таблиц, скорость записи.
* **Веб-сервер (Nginx/Apache) + PHP-FPM:** через соответствующие шаблоны.
* **Операционная система:** CPU, память, диск, сеть на серверах Zabbix и прокси.

Без мониторинга собственных компонентов Zabbix Server может упасть, тогда как веб-интерфейс продолжит работать. Подробнее о тюнинге: [поиск и устранение неисправностей](./zabbix_troubleshooting_and_performance_tuning.md).
