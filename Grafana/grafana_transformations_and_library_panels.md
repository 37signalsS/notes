# Grafana: Трансформации, Library Panels и режимы показа

**Актуально для:** Grafana 13.2.x / 12.x (LTS)

Практическое руководство по обработке данных на стороне панели (transformations), переиспользованию панелей между дашбордами (library panels) и режимам показа для стен мониторинга (kiosk/TV). Облачные и ИИ-функции не рассматриваются. Устройство дашборда, переменные и data links описаны отдельно — в [Дашбордах](./grafana-dashboards.md) и [Шаблонизации](./grafana_templating.md).

## Определения

- **Transformation (трансформация)** — обработка результатов запроса перед отрисовкой: фильтрация, объединение, агрегация, переименование. Выполняется на стороне Grafana (в браузере при интерактивном просмотре или на backend при рендеринге/алертинге), а не в источнике данных. Выход одной трансформации служит входом следующей.
- **Panel inspect → Data** — встроенный просмотр «сырых» данных после трансформаций; главный инструмент отладки. Дополняется режимом `Table view`, bug-, eye- и filter-иконками в строках трансформаций.
- **Library panel (библиотечная панель)** — панель, сохранённая как отдельный ресурс организации (в папке); экземпляры на дашбордах связаны с оригиналом: правка оригинала обновляет все связанные панели.
- **Library element** — запись в подсистеме `library-elements`, хранящая определение библиотечной панели. Имеет числовой `id` (уникален в пределах инсталляции) и строковый `uid` (стабилен между инстансами, до 40 символов). Дашборд ссылается на панель по `uid`.
- **Link / Unlink** — привязка library panel к дашборду ссылкой (link) либо превращение экземпляра в независимую копию (unlink). После unlink правки оригинала на эту панель не влияют.
- **Kiosk mode** — полноэкранный режим без UI-обвязки (`?kiosk` или `?kiosk=1`): скрыты верхняя навигация и боковое меню. Вариант `?kiosk=tv` скрывает боковое меню, оставляя верхнюю навигацию без кнопок.
- **autofitpanels** — URL-параметр и горячая клавиша `d a`, подгоняющие высоту панелей под высоту экрана; для стеновых экранов. Задаётся без знака `=`.
- **Playlist (плейлист)** — автоматическая ротация нескольких дашбордов через заданный интервал; штатный механизм для стен из нескольких дашбордов (см. [Дашборды](./grafana-dashboards.md)). С Grafana 12 переведён на API `playlist.grafana.app/v1`, с 12.4 — на unified storage.

## Базовые концепции

### Когда применять трансформации

1. **Источник не умеет нужную агрегацию** (SQL/JSON-источники, Prometheus без recording rule). Правило: всё, что можно посчитать в источнике — считайте в источнике; трансформации — для остального.
2. **Формат не подходит панели**: два запроса надо объединить в таблицу (Join by field), ряды развернуть в колонки (Rows to fields), распарсить строку лога (Extract fields).
3. **Косметика без правки запросов**: скрыть служебные лейблы, переупорядочить колонки, Top-N.

### Порядок применения и конвейер

Трансформации применяются **сверху вниз**: каждая получает выход предыдущей и передаёт свой результат дальше. Порядок напрямую влияет на результат — классическая ошибка сортировать до объединения или фильтровать после Reduce (после свёртки ряда в одно значение фильтровать уже нечего). Тяжёлые цепочки повышают нагрузку на браузер/backend, поэтому агрегируйте данные в источнике там, где это возможно.

### Каталог трансформаций

Grafana предоставляет набор функций обработки (список приведён по официальной документации; доступность отдельных функций зависит от версии и типа панели):

| Трансформация | Назначение |
| :--- | :--- |
| **Add field from calculation** | Новое вычисляемое поле: Reduce row, Binary/Unary operation, Cumulative (Total/Mean), Window (Mean/Stddev/Variance), Row index |
| **Concatenate fields** | Объединить все поля всех фреймов в один результат |
| **Config from query results** | Взять min/max/unit/thresholds из одного запроса и применить к другому; в т.ч. value mappings |
| **Convert field type** | Смена типа: string↔number, time, boolean, enum, JSON |
| **Create heatmap** | Подготовить гистограммные данные к панели Heatmap (X/Y bucket) |
| **Extract fields** | Извлечь поля из строки: JSON, Key+value, RegExp (named groups), Auto |
| **Filter data by query refId** | Скрыть результат одного из запросов панели |
| **Filter data by values** | Include/Exclude по условиям (null, equal, regex, numeric, substring) |
| **Filter fields by name** | Оставить/убрать поля: regex, ручной выбор, из переменной |
| **Format string** | Регистр/оформление строк: upper, lower, title, camel, snake, kebab, trim, substring |
| **Format time** | Формат времени по строкам Moment.js (`YYYY-MM-DD`) |
| **Group by** | Аналог `GROUP BY`: группировка по полю + агрегаты |
| **Group to nested tables** | Группировка с вложенными таблицами |
| **Grouping to matrix** | Свести три поля в матрицу (Column/Row/Cell value) |
| **Histogram** | Построить распределение значений |
| **Join by field** | Inner/Outer join нескольких запросов по полю или времени |
| **Join by labels** | Join по общей метке (label) |
| **Labels to fields** | Метки → колонки (Columns) или строки (Rows) |
| **Limit** | Оставить первые N строк |
| **Lookup fields from resource** | Обогащение spatial-данных (Countries, USA States, Airports) |
| **Merge series/tables** | Объединить серии/таблицы в одну таблицу по совпадающим полям |
| **Organize fields by name** | Переименовать, переставить, скрыть колонки |
| **Partition by values** | Разбить данные по значению поля на отдельные фреймы |
| **Prepare time series** | Преобразовать формат time series (multi/wide/auto) |
| **Reduce** | Свернуть ряд в одно значение (min/max/mean/last/count…) — база для Stat/Gauge |
| **Rename by regex** | Переименовать поля по регулярному выражению |
| **Rows to fields** | Строки → колонки (name field / value field) |
| **Series to rows** | Серии → строки (обратная операция к Labels to fields) |
| **Smoothing** | Сглаживание ряда |
| **Sort by** | Сортировка строк по полю |
| **Spatial** | Пространственные преобразования (только панели карт/geo) |
| **Time series to table transform** | Преобразовать временные ряды в табличную форму (обычно совместно с Reduce для Stat/Gauge) |
| **Transpose** | Транспонирование: строки↔столбцы |
| **Trendline** | Линия тренда по данным |

### Отладка трансформаций

- **Инспектор входа/выхода.** У каждой строки трансформации есть иконка «bug» — она показывает входной и выходной наборы данных этого шага. Это основной способ понять, где «теряются» данные.
- **Отключение шага.** Иконка глаза временно отключает трансформацию, не удаляя её — удобно при отладке цепочки.
- **Фильтр по запросу.** Если у панели несколько запросов, иконка фильтра на строке трансформации позволяет применить её только к выбранному запросу (или к аннотациям/exemplars).
- **Panel inspect → Data** — общий просмотр «сырых» данных и переключение между шагами; **Table view** над визуализацией помогает понять итог, когда система не может построить график из преобразованных данных.

### Library panels: модель двух ресурсов

Ключевой момент, о который чаще всего спотыкаются при переносе дашбордов: **дашборд хранит только ссылку на библиотечную панель, а её определение лежит в отдельной подсистеме** (library elements). В JSON дашборда панель представлена заглушкой вида `libraryPanel: { uid, name }`, а не полной моделью. Следствия:

- Копирование только файла дашборда **не** переносит определение библиотечной панели — нужен и второй ресурс.
- Правка определения в любой панели, где она используется, распространяется на все места (единый источник для повторяющихся панелей).
- Библиотечные панели привязаны к папке (folder-scoped) и поддерживают RBAC, как дашборды.
- Видимый заголовок может браться либо из экземпляра на дашборде, либо из модели библиотечной панели (поведение `preferLibraryPanelTitle`) — при расхождении ориентируйтесь на определение.

### Режимы показа (kiosk/TV)

Для стен мониторинга дашборд открывают без UI-обвязки. Grafana поддерживает два режима kiosk и опцию авто-подгонки панелей:

| URL-параметр | Действие |
| :--- | :--- |
| `?kiosk` / `?kiosk=1` | Полноэкранный режим: скрыты верхняя навигация и боковое меню |
| `?kiosk=tv` | Скрыто боковое меню; верхняя навигация остаётся без кнопок |
| `&autofitpanels` | Подгонка высоты панелей под экран (без знака `=`) |
| `&inactive` | Не проигрывать анимацию перестроения при загрузке (для Sl-экранов и киосков) |

`autofitpanels` учитывает высоту окна и масштабирует высоту панелей; типичная связка для стены — `?kiosk&autofitpanels`. Для ротации нескольких дашбордов используйте плейлист (см. [Дашборды](./grafana-dashboards.md)) — он проигрывается в kiosk-режиме и сохраняет параметры (`kiosk`, `autofitpanels`) между переходами.

## Практические сценарии

### Предварительные требования

- Роль Editor для создания панелей/трансформаций; для HTTP API — сервисный аккаунт с правами Editor/Admin и токен.
- Дашборд с хотя бы двумя запросами для сценариев объединения.
- Для примеров с API: переменные `GRAFANA` (базовый URL) и `TOKEN`:

```bash
export GRAFANA="https://grafana.example.internal"
export TOKEN="<SERVICE_ACCOUNT_TOKEN>"
```

### Сценарий 1. Top-N таблица: Sort by + Limit + Organize

Задача: топ-5 подов по потреблению CPU из Prometheus.

1. Запрос: `topk(5, sum(rate(container_cpu_usage_seconds_total{namespace="prod"}[5m])) by (pod))`.
2. Панель Table, трансформации по порядку:
   - **Sort by** → поле `Value #A`, descending;
   - **Limit** → 5;
   - **Organize fields by name** → переименовать `Value #A` → `CPU cores`, скрыть `Time`.
3. Отладка: Panel inspect → Data — видно вход каждой трансформации (переключатель между шагами).

Проверка: таблица содержит ровно 5 строк, порядок убывающий, заголовки читабельные.

### Сценарий 2. Объединение двух запросов в одну таблицу

Задача: рядом CPU и память одного сервиса.

```promql
# A: rate(container_cpu_usage_seconds_total{pod=~"$pod"}[5m])
# B: container_memory_working_set_bytes{pod=~"$pod"}
```

Трансформации:
- **Join by field** → join по `pod` в режиме **Outer**;
- **Filter fields by name** → оставить `pod`, `Value #A`, `Value #B`.

Проверка: одна таблица, у каждого пода обе метрики; строки без второй метрики видны при outer join (пустые ячейки) — либо переключите в inner, чтобы оставить только совпадения. Если у запросов различаются имена полей-ключей, сначала переименуйте их (**Organize fields by name** / **Rename by regex**), иначе join даст пустой результат.

### Сценарий 3. Rows to fields: ряды → колонки для Stat

Задача: из multi-series сделать отдельные значения для stat-панели с порогами.

- Трансформация **Rows to fields** (config: name field = `metric`, value = `Value`) превращает ряды в именованные поля;
- В Overrides stat-панели задать thresholds по имени поля.

Проверка: каждая серия отображается отдельным значением со своим цветом порога. Если подписи выглядят мусорно, проверьте, что в конфиге трансформации указано поле имени (`metric`), иначе поля получают бессмысленные имена.

### Сценарий 4. Extract fields: разбор логов в таблице

Loki-запрос `{job="app"} | json` уже парсит JSON. Если строки не распарсены, используйте трансформацию:

- **Extract fields** → source = поле `line`/`Line`, format = `JSON`, `Key+value`, `RegExp` (с именованными группами) или `Auto`;
- Опционально **Replace all fields**, чтобы оставить только извлечённые поля; **Keep time** сохранит поле времени.

Проверка: вместо одной текстовой колонки появляются отдельные поля. Формат `Auto` распознаёт структуру сам, RegExp требует named capturing group вида `(?<NewField>.*)`.

### Сценарий 4а. Панель отладки трансформации

Задача: разобраться, почему после цепочки трансформаций «пропали» данные.

1. Откройте панель → **Transform**.
2. У каждой строки трансформации:
   - значок «жучок» — показать вход/выход именно этого шага;
   - значок «глаз» — временно отключить шаг, чтобы локализовать проблему;
   - значок фильтра — применить трансформацию только к одному запросу (при нескольких запросах).
3. Переключитесь в **Table view** над визуализацией, чтобы увидеть итоговый frame.
4. Сверьтесь со сценариями 1–3: чаще всего причина — неверный порядок шагов или несовпадение имён полей-ключей перед join.

### Сценарий 5. Library panel: создать и переиспользовать (UI)

1. Откройте дашборд в режиме редактирования.
2. Наведите на панель → меню действий → **More → New library panel**.
3. Задайте имя, выберите папку (по умолчанию — корень) → **Create library panel** → **Save** дашборда. Панель на этом дашборде становится связанной с оригиналом.
4. На другом дашборде: **New → New dashboard** → добавить панель → **Use library panel** → выбрать из списка.
5. Правка запроса в оригинале обновляет все связанные панели (у связанных панелей отображается значок связи).

Отвязать (без удаления): меню панели → **More → Unlink**. Заменить на другую библиотечную панель: **More → Replace library panel**. Список и удаление — **Dashboards → Library panels**.

### Сценарий 6. Library panel через HTTP API и провиженинг

Библиотечные панели управляются отдельно от дашбордов. Создание/список/обновление выполняются через Library Element API (в Grafana 13 роуты `/api` помечены deprecated в пользу `/apis`, но продолжают работать):

```bash
# Список библиотечных панелей (kind=1). Ответ: {"result":{"elements":[...]}}
curl -sS -H "Authorization: Bearer $TOKEN" \
  "$GRAFANA/api/library-elements?kind=1&perPage=100" \
  | jq '.result.elements[] | {uid, name, connectedDashboards: .meta.connectedDashboards}'

# Создать библиотечную панель (model — полная JSON-модель панели)
curl -sS -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  "$GRAFANA/api/library-elements" \
  -d '{"uid":"cpu-by-pod","folderUid":"","name":"CPU by pod (prod)","model":{ ... },"kind":1}'
# → {"result":{"uid":"cpu-by-pod","version":1,...}}

# Обновить (обязательно передать текущий version; при рассинхроне — 412)
curl -sS -X PATCH -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  "$GRAFANA/api/library-elements/cpu-by-pod" \
  -d '{"name":"CPU by pod (prod)","kind":1,"version":1}'

# Кто использует панель
curl -sS -H "Authorization: Bearer $TOKEN" \
  "$GRAFANA/api/library-elements/cpu-by-pod/connections" \
  | jq '.result[] | {connectionUid}'
```

Ключи: `GET /api/library-elements` (параметры `perPage` — по умолчанию 100, `page`, `kind=1`, `searchString`, `sortDirection`, `folderFilterUIDs`), `GET /api/library-elements/:uid`, `GET /api/library-elements/name/:name`, `POST`, `PATCH`, `DELETE /api/library-elements/:uid` (удалить связанную панель нельзя).

Связывание панели с дашбордом — это ссылка в JSON дашборда, а не отдельный вызов:

```json
"panels": [
  {
    "libraryPanel": { "uid": "cpu-by-pod", "name": "CPU by pod (prod)" },
    "gridPos": { "h": 8, "w": 12, "x": 0, "y": 0 }
  }
]
```

Провиженинг: файловый провайдер дашбордов создаёт сам дашборд, но **не** определение библиотечной панели (в JSON дашборда лежит только ссылка). Определение провижинится отдельно:

- **HTTP API** — как в примере выше;
- **Git Sync (Grafana 13.x)** — библиотечные панели поддерживаются как ресурс провиженинга (по умолчанию выключены);
- **Grafana Operator (Kubernetes)** — ресурс `GrafanaLibraryPanel` (по аналогии с `GrafanaDashboard`).

Для переноса дашборда между инстансами зафиксируйте `uid` библиотечной панели и перенесите определение отдельно, иначе связанные панели останутся заглушками.

### Сценарий 7. Kiosk/TV-режим для стены мониторинга

```bash
# Полноэкранный режим (без верхней навигации и бокового меню)
"$GRAFANA/d/prod-overview/main?kiosk&from=now-6h&to=now&refresh=30s"
# TV: боковое меню скрыто, верхняя навигация без кнопок; панели подгоняются под экран
"$GRAFANA/d/prod-overview/main?kiosk=tv&autofitpanels"
```

Для стены из нескольких дашбордов используйте плейлист Grafana (ротация по интервалу), который запускается в kiosk-режиме и сохраняет параметры между переходами. Внешние киоск-утилиты (например, `grafana-kiosk`) дополнительно умеют скрывать логотип и элементы управления.

Проверка: страница открывается без сайдбара; при `kiosk=tv` доступна верхняя навигация; автообновление работает; `autofitpanels` растягивает панели под высоту окна.

## Дополнительная информация

### Рекомендации по эксплуатации

- Тяжёлые цепочки трансформаций (>3–4 шагов) — сигнал пересмотреть запрос к источнику.
- Для Top-N предпочитайте агрегацию источника (`topk`) трансформации Limit — меньше данных по сети.
- Library panels — стандарт для повторяющихся панелей; копипаста панелей между дашбордами создаёт дрейф конфигурации.
- Фиксируйте `uid` библиотечных панелей и переносите их определения вместе с дашбордами.
- Именуйте library panels по шаблону «метрика (контур)» — их список растёт быстро.
- Kiosk-стены держите на выделенном Viewer-аккаунте (или anonymous read-only), а не на личном.
- Используйте `?kiosk&autofitpanels` и плейлисты, а не сторонние ротаторы, — параметры сохраняются между переходами.

### Типичные ошибки и их решение

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| Трансформация «съедает» данные | Неверный порядок шагов / wrong field | Inspect → Data, значок «жучок» на каждом шаге |
| Join by field даёт пустые строки | Разные имена полей-ключей у запросов | Переименовать поля (Organize/Rename by regex) до Join |
| Изменения library panel не видны | Панель была unlinked ранее | Пересоздать связь или править копию осознанно |
| Связанная панель — заглушка после переноса | Определение не перенесено (в дашборде только ссылка) | Перенести определение через API/провиженинг |
| `DELETE /api/library-elements/:uid` — ошибка | Панель связана с дашбордами | Сначала unlink или удалить из дашбордов |
| `PATCH` возвращает 412 | Устаревший `version` | Перечитать `version` и повторить |
| Stat показывает мусорные подписи | Rows to fields без config name field | Указать поле имени (`metric`) в конфиге трансформации |
| Kiosk просит логин | Анонимный доступ выключен, стена без учётки | Настроить anonymous viewer или вход через OAuth |

### Ограничения и особые случаи

- Трансформации выполняются вне источника: большие объёмы данных лучше фильтровать в запросе.
- Часть трансформаций недоступна для панелей определённых типов (например, Spatial/Lookup — только для карт и geo-панелей).
- Повторяющиеся (repeating) панели нельзя превратить в library panel напрямую; повторение несовместимо с публичными дашбордами (см. [Дашборды](./grafana-dashboards.md)).
- Экспорт дашборда требует отдельного переноса определений библиотечных панелей (JSON содержит ссылки, а не тела).
- В Grafana 13 роуты `/api` deprecated в пользу `/apis`; legacy-роуты не отключаются, но не развиваются.
- `autofitpanels` указывается без знака `=`; при сочетании с kiosk учитывайте, что подгонка выполняется под текущий размер окна.

### Очистка и откат изменений

- Неиспользуемые библиотечные панели удаляются в **Dashboards → Library panels** или `DELETE /api/library-elements/{uid}` — сначала убедитесь, что `connectedDashboards: 0`.
- Откат экспериментов с трансформациями: Ctrl+Z в редакторе панели либо отказ от сохранения дашборда (трансформации не меняют данные в источнике).
- Откат связанной панели к независимой копии: **More → Unlink**.
