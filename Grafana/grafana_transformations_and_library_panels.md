# Grafana: Трансформации, Library Panels и режимы показа

Практическое руководство по обработке данных на стороне панели (transformations), переиспользованию панелей между дашбордами (library panels) и режимам показа (kiosk/TV). Облачные и ИИ-функции не рассматриваются.

## Определения

- **Transformation (трансформация)** — обработка результатов запроса перед отрисовкой: фильтрация, объединение, агрегация, переименование. Выполняется в браузере/Grafana, не в источнике данных.
- **Library panel** — панель, сохранённая как общий ресурс организации; экземпляры на дашбордах связаны с оригиналом: правка оригинала обновляет все связанные панели.
- **Unlink** — отвязать library panel от дашборда: копия становится независимой.
- **Kiosk mode** — полноэкранный режим дашборда без UI-обвязки (`?kiosk`); вариант `tv` скрывает боковое меню, но оставляет навигацию по строкам.
- **Panel inspect → Data** — встроенный просмотр «сырых» данных после трансформаций; главный инструмент отладки.

## Базовые концепции

Когда применять трансформации:

1. **Источник не умеет нужную агрегацию** (SQL/JSON-источники, Prometheus без записи recording rule). Правило: всё, что можно посчитать в источнике — считайте в источнике; трансформации — для остального.
2. **Формат не подходит панели**: два запроса надо объединить в таблицу (Join by field), ряды развернуть в колонки (Rows to fields), распарсить строку лога (Extract fields).
3. **Косметика без правки запросов**: скрыть служебные лейблы, переупорядочить колонки, Top-N.

Порядок важен: трансформации применяются **сверху вниз**, каждая получает выход предыдущей. Классическая ошибка — сортировать до объединения или фильтровать после Reduce.

Library panels решают проблему «50 дашбордов с одной и той же панелью CPU»: чините один раз — обновляется везде. Связь хранится по `uid`; при экспорте дашборда в JSON связанная панель выгружается ссылкой.

## Практические сценарии

### Предварительные требования

- Роль Editor для создания панелей/трансформаций.
- Дашборд с хотя бы двумя запросами для сценариев объединения.

### Сценарий 1. Top-N таблица: Sort by + Limit + Organize

Задача: топ-5 подов по потреблению CPU из Prometheus.

1. Запрос: `topk(5, sum(rate(container_cpu_usage_seconds_total{namespace="prod"}[5m])) by (pod))`.
2. Панель Table, трансформации по порядку:
   - **Sort by** → поле `Value #A`, descending;
   - **Limit** → 5;
   - **Organize fields** → переименовать `Value #A` → `CPU cores`, скрыть `Time`.
3. Отладка: Panel inspect → Data — видно вход каждой трансформации (переключатель между шагами).

Проверка: таблица содержит ровно 5 строк, порядок убывающий, заголовки читабельные.

### Сценарий 2. Объединение двух запросов в одну таблицу

Задача: рядом CPU и память одного сервиса.

```promql
# A: rate(container_cpu_usage_seconds_total{pod=~"$pod"}[5m]) 
# B: container_memory_working_set_bytes{pod=~"$pod"}
```

Трансформации:
- **Merge series to columns / Join by field** → join по `pod` (режим outer);
- **Filter fields by name** → оставить `pod`, `Value #A`, `Value #B`.

Проверка: одна таблица, у каждого пода обе метрики; строки без второй метрики видны при outer join (пустые ячейки) — либо переключите в inner.

### Сценарий 3. Rows to fields: ряды → колонки для Stat

Задача: из multi-series сделать отдельные значения для stat-панели с порогами.

- Трансформация **Rows to fields** (config: name field = `metric`, value = `Value`) превращает ряды в именованные поля;
- В Overrides stat-панели задать thresholds по имени поля.

Проверка: каждая серия отображается отдельным значением со своим цветом порога.

### Сценарий 4. Extract fields: разбор логов в таблице

Loki-запрос `{job="app"} | json` уже парсит JSON; для сырого текста:

- Трансформация **Extract fields** → source = поле `line`, format = logfmt/json/key+value;
- Далее **Organize fields** скрыть исходный `line`.

Проверка: вместо одной колонки текста — отдельные колонки `level`, `method`, `status`.

### Сценарий 5. Library panel: создать и переиспользовать

```bash
# Через UI: меню панели → Share → Create library panel → имя "CPU by pod (prod)"
# API: список библиотечных панелей
curl -sS "$GRAFANA/api/library-elements" -H "Authorization: Bearer $TOKEN" | jq '.elements[] | {uid, name, connectedDashboards}'
# Подключить существующую library panel к дашборду
curl -sS -X POST "$GRAFANA/api/library-elements/<panel-uid>/connect/<dashboard-uid>" \
  -H "Authorization: Bearer $TOKEN"
```

Проверка: на втором дашборде добавить панель через **Add → Library panels**; изменить запрос в оригинале → оба места обновились (у связанных панелей появляется значок связи).

Отвязать (без удаления): меню панели → Unlink — дашборд получает независимую копию.

### Сценарий 6. Kiosk/TV-режим для стены мониторинга

```bash
# Полноэкранный режим
"$GRAFANA/d/prod-overview/main?kiosk&from=now-6h&to=now&refresh=30s"
# TV: скрывает меню, оставляет переключение строк дашборда
"$GRAFANA/d/prod-overview/main?kiosk=tv&autofitpanels"
```

Для стены из нескольких дашбордов используйте ротацию ссылок внешним инструментом (плейлисты Grafana объявлены устаревшими начиная с 11.x).

Проверка: страница открывается без сайдбара и тулбаров; автообновление работает; при `kiosk=tv` доступна навигация клавишами.

### Сценарий 7. Провиженинг библиотечной панели

```yaml
# provisioning/dashboards/library/cpu-panel.yaml
apiVersion: 1
providers: []          # провайдеры дашбордов настраиваются отдельно

# Library panels провижинятся вместе с дашбордами:
# в JSON дашборда панель помечается как библиотечная:
# {"libraryPanel": {"name": "CPU by pod (prod)", "uid": "cpu-by-pod"}}
```

Проверка после рестарта: панель появилась в списке `/api/library-elements`, `connectedDashboards` соответствует.

## Дополнительная информация

### Рекомендации по эксплуатации

- Тяжёлые цепочки трансформаций (>3–4 шагов) — сигнал пересмотреть запрос к источнику.
- Для Top-N предпочитайте агрегацию источника (`topk`) трансформации Limit — меньше данных по сети.
- Library panels — стандарт для повторяющихся панелей; копипаста панелей между дашбордами создаёт дрейф конфигурации.
- Именуйте library panels по шаблону «метрика (контур)» — их список растёт быстро.
- Kiosk-стены держите на выделенном Viewer-аккаунте (или anonymous read-only), а не личном.

### Типичные ошибки и их решение

| Симптом | Причина | Решение |
| --- | --- | --- |
| Трансформация «съедает» данные | Неверный порядок шагов / wrong field | Inspect → Data, смотреть вход каждого шага |
| Join by field даёт пустые строки | Разные имена полей-ключей у запросов | Переименовать поля Organize/Filter до Join |
| Изменения library panel не видны | Панель была unlinked ранее | Пересоздать связь или править копию осознанно |
| Kiosk просит логин | Анонимный доступ выключен, стена без учётки | Настроить anonymous viewer или SA-токен нельзя для UI — использовать анонимный/OAuth |
| Stat показывает мусорные подписи | Rows to fields без config name field | Указать поле имени (`metric`) в конфиге трансформации |

### Ограничения и особые случаи

- Трансформации выполняются вне источника: большие объёмы данных лучше фильтровать в запросе.
- Часть трансформаций недоступна для панелей определённых типов (например, Spatial — только карты).
- Повторяющиеся (repeating) панели несовместимы с публичными дашбордами (см. grafana-dashboards.md).
- Экспорт дашборда с library panels требует переноса самих панелей (JSON содержит ссылки, а не тела).

### Очистка и откат изменений

- Неиспользуемые library panels удаляются в UI (Server Admin → Library panels) или `DELETE /api/library-elements/{uid}` — сначала проверьте `connectedDashboards: 0`.
- Откат экспериментов с трансформациями: Ctrl+Z в редакторе панели либо отказ от сохранения дашборда.

### Актуальность и статус

Набор трансформаций расширяется каждый мажор; перечисленные (Sort/Limit/Organize/Join/Rows to fields/Extract fields/Merge) стабильны в 11.x–13.x. Library panels GA с 8.x, API стабилен. Плейлисты deprecated с 11.x.
