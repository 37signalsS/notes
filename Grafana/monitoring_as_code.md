# Monitoring as Code (MaC): Grafana и GitOps

**Monitoring as Code (MaC)** — подход к управлению системами мониторинга, при котором конфигурации дашбордов, источников данных и правил оповещения описываются в виде кода (обычно JSON или YAML) и управляются через системы контроля версий.

## Определения

- **MaC (Monitoring as Code)**: Расширение концепции Infrastructure as Code (IaC) на слой наблюдаемости (Observability).
- **Dashboard JSON**: Структурированное описание дашборда Grafana, содержащее настройки панелей, запросов и визуализаций.
- **GitOps**: Методология управления конфигурациями, где Git является единственным источником истины (**SSoT**), а изменения синхронизируются с целевой средой автоматически.

## Базовые концепции

### Почему стоит использовать GitOps для мониторинга

| Преимущество | Описание |
| :--- | :--- |
| **Единый источник истины** | Все конфигурации хранятся в Git. История изменений прозрачна и аудируема. |
| **Версионирование** | Возможность мгновенного отката к предыдущей версии дашборда при неудачных правках. |
| **Автоматизация** | Исключение человеческого фактора при переносе дашбордов между окружениями. |
| **Консистентность** | Гарантия того, что дашборды в Dev, Staging и Prod идентичны (или различаются только переменными). |
| **Code Review** | Возможность проверки логики визуализации и запросов коллегами до их применения. |
| **Масштабируемость** | При росте количества сервисов мониторинг для них создается автоматически на основе шаблонов. |

### Архитектура MaC в Kubernetes

Типовой рабочий процесс синхронизации дашбордов строится на связке **ArgoCD** и специализированного **Sidecar** в поде Grafana.

```text
Git-репозиторий (JSON/YAML)
    ↓ (Синхронизация через ArgoCD)
Kubernetes ConfigMap (с меткой grafana_dashboard)
    ↓ (Обнаружение sidecar-контейнером)
Файловая система Grafana (/tmp/dashboards)
    ↓ (Автоматический импорт)
Веб-интерфейс Grafana
```

## Практические сценарии

### 1. Подготовка дашборда
Экспортируйте созданный вручную дашборд из Grafana в формате JSON. Сохраните его в Git-репозитории (например, `monitoring/dashboards/app-metrics.json`).

### 2. Создание манифеста ConfigMap
Оберните JSON-код в ConfigMap. Критически важно добавить метку, которую ожидает Grafana Sidecar.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: grafana-dashboard-app
  namespace: monitoring
  labels:
    grafana_dashboard: "1" # Метка для обнаружения
data:
  app-metrics.json: |
    {
      "dashboard": {
        "title": "Application Metrics",
        ...
      }
    }
```

### 3. Настройка ArgoCD
Создайте приложение в ArgoCD, указывающее на папку с вашими манифестами дашбордов.

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: monitoring-configs
  namespace: argocd
spec:
  project: default
  source:
    repoURL: 'https://github.com/org/infra-repo.git'
    path: kubernetes/monitoring/dashboards
    targetRevision: HEAD
  destination:
    server: 'https://kubernetes.default.svc'
    namespace: monitoring
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

### 4. Проверка результата
1. **ArgoCD**: Убедитесь, что статус приложения `Synced`.
2. **Grafana**: Перейдите в интерфейс. Дашборд должен появиться в папке, указанной в настройках провайдера (по умолчанию `General`).
3. **Логи**: Если дашборд не появился, проверьте логи контейнера `grafana-sc-dashboards`.

## Дополнительная информация

### Рекомендации
- **Неизменяемость**: Установите `editable: false` в настройках провайдера Grafana, чтобы запретить ручные правки в UI, которые будут стерты при следующей синхронизации GitOps.
- **Разделение репозиториев**: Храните код приложений и конфигурации MaC в разных папках или репозиториях для разделения зон ответственности.
- **Шаблонизация**: Для массового создания дашбордов используйте инструменты генерации, такие как **Jsonnet** или **Grafanalib**.
