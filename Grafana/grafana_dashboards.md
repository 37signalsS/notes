# Grafana: Дашборды

Это руководство охватывает создание и управление дашбордами Grafana, включая панели и переменные (шаблоны).

## Дашборды

Дашборд — это набор из одной или нескольких панелей, которые визуализируют данные из различных источников. Каждый дашборд представлен в виде большого объекта JSON, что позволяет легко экспортировать, импортировать и версионировать дашборды.

### Панели

Панель — это основной строительный блок дашборда, используемый для визуализации данных.

**Ключевые особенности панелей:**

*   **Запросы:** Каждая панель содержит один или несколько запросов к источнику данных. Запросы можно создавать как с помощью визуального конструктора (query builder), так и писать вручную в режиме кода, что обеспечивает большую гибкость. Grafana также позволяет просматривать сырые данные, возвращаемые запросом, в табличном виде.
*   **Визуализация:** Доступен широкий спектр типов визуализации:
    *   График (Graph / Time series)
    *   Статистика (Stat)
    *   Датчик (Gauge)
    *   Гистограмма (Bar chart)
    *   Таблица (Table)
    *   Текст (Text)
    *   Тепловая карта (Heatmap)
*   **Кастомизация:** Панели предлагают множество вариантов настройки:
    *   **Пороги (Thresholds):** Установка порогов с цветовой кодировкой (например, красный, желтый, зеленый) для обозначения статуса. В зависимости от значения метрики, график или его фон могут менять цвет.
    *   **Единицы измерения (Units):** Можно указать единицу измерения для данных (например, проценты, байты, секунды), и Grafana автоматически отформатирует значения (например, переведет байты в мегабайты).
    *   **Сопоставление значений (Value Mappings):** Сопоставление числовых или строковых значений с определенным текстом или цветом.
    *   **Стили отображения:** Настройка ширины линий, заливки, сглаживания, осей, легенд и т. д.

### Создание дашборда

Любой дашборд в Grafana представлен в виде большого JSON-объекта. Это позволяет экспортировать, импортировать и версионировать дашборды.

1.  Перейдите в раздел **Dashboards**.
2.  Создайте новую папку (например, `Test`) для организации ваших дашбордов.
3.  Нажмите **New Dashboard** внутри папки.
4.  В настройках дашборда (`Dashboard settings`) вы можете настроить:
    *   **Название и описание** (например, "Our First Dash", "Test, Test, Test").
    *   **Папку** (в какой директории будет находиться дашборд).
    *   **Редактируемость** (режим только для чтения).
    *   **Часовой пояс и параметры автообновления**.
    *   **Аннотации, переменные и ссылки**.
    *   **JSON-модель дашборда** (доступна для просмотра и редактирования).

### Версионирование дашбордов

Grafana поддерживает версионирование дашбордов, что позволяет отслеживать изменения и при необходимости откатываться к предыдущим версиям. История версий доступна в настройках дашборда (`Dashboard settings -> Versions`). Здесь можно просмотреть изменения между версиями и восстановить любую из них.

### Аннотации (Annotations)

Аннотации позволяют добавлять текстовые метки на графики дашборда, отмечая важные события (например, деплоймент, инцидент, изменение конфигурации). Это помогает коррелировать изменения в системе с поведением метрик. Аннотации могут быть добавлены вручную или автоматически из внешних источников.

### Полезные функции для анализа

*   **Shared Crosshair**: В настройках дашборда можно включить опцию "Shared crosshair". Это создаст общее перекрестие, которое будет синхронно отображаться на всех графиках дашборда при наведении мыши. Это чрезвычайно полезно для визуальной корреляции событий и аномалий между разными метриками в один и тот же момент времени.
*   **Time Range Controls**: Grafana предоставляет мощные инструменты для управления временным диапазоном отображаемых данных. Можно быстро выбирать предопределенные интервалы (последние 5 минут, 1 час, 24 часа и т.д.) или задавать точный диапазон с помощью календаря.

### Плейлисты (Playlists)

Плейлисты — это встроенная в Grafana функция, которая позволяет автоматически переключаться между несколькими дашбордами через заданный интервал времени. Это идеально подходит для вывода ключевых показателей на большой экран в офисе или ситуационном центре.

**Создание плейлиста:**
1.  Перейдите в раздел **Dashboards -> Playlists**.
2.  Нажмите **New playlist**.
3.  Задайте имя плейлиста и интервал переключения (например, "1m" для одной минуты).
4.  Добавьте в плейлист дашборды из списка существующих. Их можно переупорядочивать, чтобы задать нужную последовательность.
5.  Сохраните плейлист.

Для запуска плейлиста можно выбрать один из режимов отображения: `Normal` (со всеми элементами интерфейса), `TV` или `Kiosk` (скрывает лишние меню для полноэкранного просмотра и может автоматически подгонять размер графиков под экран).

**Практические рекомендации:**
*   Плейлисты идеально подходят для вывода на большие экраны (например, в NOC или операционных центрах), позволяя показывать последовательность важных дашбордов.
*   При настройке для больших экранов можно использовать режимы `TV` или `Kiosk`, которые скрывают элементы управления Grafana, предоставляя чистый вид дашбордов. Также можно настроить автоматическое подгонку размера графиков.
*   Для тестирования или демонстрации удобно устанавливать короткий интервал ротации.

### Создание панели

1.  Нажмите **Add panel** -> **Add new panel**.
2.  **Настройте панель:**
    *   **Название и описание**.
    *   **Тип визуализации** (например, Graph, Stat, Gauge, Table, Text, Heatmap).
    *   **Источник данных:** Выберите соответствующий источник данных (например, Prometheus). По умолчанию выбирается автоматически.
3.  **Напишите запрос.** Например, чтобы показать доступные реплики развертывания Kubernetes:
    ```promql
    kube_deployment_status_replicas_available
    ```
4.  **Настройте легенду.** Используйте шаблоны для создания более информативных меток. Например, чтобы показать имя развертывания:
    ```
    {{deployment}}
    ```
    Вы можете комбинировать статический текст и метки: `Deployment: {{deployment}}`.
    Для отображения namespace и имени развертывания: `{{ns}}.{{deployment}}`.

5.  **Пример: Мониторинг CPU с использованием `rate()`**

    Многие метрики в Prometheus, особенно из `node-exporter`, являются счетчиками (`counter`) — они только увеличиваются со временем. Примером такой метрики является `node_cpu_seconds_total`, которая показывает, сколько всего секунд процессор провел в определенном состоянии (например, `user`, `system`, `idle`).

    Простое отображение этой метрики на графике даст постоянно растущую линию, что неинформативно. Чтобы получить осмысленное значение, такое как текущее потребление CPU, необходимо вычислить скорость изменения этого счетчика за определенный промежуток времени. Для этого в PromQL используется функция `rate()`.

    *   **Запрос для `rate()`:**
        Чтобы посчитать среднюю скорость изменения потребления CPU за последнюю минуту, используйте следующий запрос:
        ```promql
        rate(node_cpu_seconds_total{mode="user"}[1m])
        ```
        Этот запрос покажет, какую долю секунды в секунду процессор тратил на пользовательские процессы в среднем за последнюю минуту.

    *   **Работа с гистограммами и `rate()`:**
        Функция `rate()` идеально подходит для работы со счетчиками и гистограммами. Она автоматически рассчитывает скорость роста значения, позволяя получить из монотонно растущего счетчика график реального потребления ресурсов.

    *   **Настройка легенды:**
        Чтобы график был более читаемым, можно настроить легенду для отображения, например, конкретного ядра CPU. Если метрика содержит лейбл `cpu`:
        ```
        CPU Core: {{cpu}}
        ```

6.  **Пример визуализации "Gauge" (Спидометр):**
    *   Выберите тип визуализации "Gauge".
    *   Используйте тот же запрос, например, `kube_deployment_status_replicas_available`.
    *   Обратите внимание, что для Gauge метрика приводится к одному числовому значению (например, среднее, минимальное, максимальное или последнее мгновенное значение). Это может привести к нецелым значениям (например, 0.99), если не выбрано "Instant" для работы с последним пришедшим значением.
    *   Настройте подписи для Gauge, чтобы они были информативными.

### Переменные (Variables)

Переменные (ранее известные как шаблоны) позволяют создавать интерактивные и динамические дашборды. Пользователь может изменять значение переменной через выпадающее меню, и все панели, использующие эту переменную, автоматически обновятся. Это чрезвычайно полезно для фильтрации данных.

**Создание переменной:**

1.  Перейдите в **Dashboard settings -> Variables** и нажмите **New**.
2.  **Настройте переменную:**
    *   **Name:** Описательное имя (например, `namespace`).
    *   **Type:** `Query`. Также существуют типы `Custom`, `Constant`, `Data source` (позволяет менять источник данных для дашборда).
    *   **Data source:** Источник значений для переменной (например, Prometheus).
    *   **Refresh:** Когда обновлять значения переменной (например, `On Time Range Change` для обновления при изменении временного диапазона).
    *   **Query:** Запрос для получения значений переменной. Часто используется функция `label_values` для извлечения уникальных значений меток из метрик:
        ```promql
        label_values(kube_deployment_status_replicas_available, namespace)
        ```
        Вы также можете использовать регулярные выражения для сортировки или фильтрации значений.
    *   **Selection Options:** Включите **Multi-value** (возможность выбора нескольких значений) и **Include All option** (добавление опции "Все") для удобства использования.

**Динамические переменные и их модификация:**

Переменные могут быть динамически извлечены из источника данных. Например, для Prometheus часто используется `label_values` для получения списка значений определенного лейбла (например, IP-адресов хостов).

*Пример получения IP-адресов хостов:*
```promql
label_values(node_uname_info, instance)
```

Если требуется изменить отображение этих значений (например, с IP-адресов на читаемые имена хостов), можно модифицировать JSON-модель дашборда. Для этого:
1.  Экспортируйте дашборд в JSON.
2.  Найдите и замените все вхождения `instance` на `nodename` (или другой желаемый лейбл) в запросах (query) внутри JSON.
3.  Импортируйте модифицированный JSON обратно в Grafana.
4.  Обновите определение переменной, чтобы она также использовала `nodename` вместо `instance` для извлечения значений.

**Ограничения:**

Важно отметить, что **переменные (variables) не работают с алертами в Grafana**. Если панель использует переменные, вы не сможете настроить для нее оповещения. Это связано с тем, что Grafana должна иметь возможность однозначно оценить условие алерта без динамического выбора значений.

**Использование переменной в запросе:**

Обновите запросы вашей панели, чтобы использовать переменную для фильтрации. На переменную ссылаются с префиксом `$` (например, `$namespace`).

```promql
kube_deployment_status_replicas_available{namespace=~"$namespace"}
```
**Примечание:** Имена переменных чувствительны к регистру.
После привязки панелей к переменной, вы сможете фильтровать метрики по выбранному значению (например, по `namespace`).

## Управление дашбордами

### Экспорт, импорт и копирование (клонирование)

*   **Экспорт/Импорт JSON**: Дашборды можно экспортировать в JSON-файл и импортировать обратно. Это позволяет переносить дашборды между различными инсталляциями Grafana или восстанавливать их из резервных копий.

*   **Копирование (клонирование) дашборда**:
    Дашборды в Grafana по своей сути являются JSON-объектами, что делает их легко переиспользуемыми и обмениваемыми. При клонировании дашборда важно учитывать, что каждый объект Grafana (дашборд, панель, источник данных) имеет уникальный идентификатор.

    *   **Проблема:** При простом копировании JSON-модели дашборда (например, через `Copy JSON` из настроек) можно столкнуться с конфликтом уникальных идентификаторов (`uid`, `id` панелей, `datasourceId`). Если идентификаторы нового дашборда совпадут с существующими, импорт не удастся, и Grafana может выдать ошибку.
    *   **Решение:** Современные версии Grafana значительно упростили этот процесс. При экспорте дашборда через меню **Share -> Export** имеется специальный переключатель **"Export for sharing externally"** (по сути, "селектор очистки"). При его активации Grafana автоматически очищает из JSON-модели все внутренние идентификаторы (`uid`, `id` дашборда и панелей, `datasourceId`), которые могут вызвать конфликт при импорте. Это позволяет безопасно переносить дашборды между различными инстансами Grafana.
    *   **Процесс:**
        1. Откройте дашборд, который хотите скопировать.
        2. Нажмите **Share -> Export**.
        3. Активируйте **"Export for sharing externally"**.
        4. Скопируйте полученный JSON в буфер обмена или сохраните его в файл.
        5. Для создания нового дашборда, перейдите в **Dashboards -> New -> Import**, вставьте JSON или загрузите файл. Grafana назначит ему новый, уникальный `uid` и предложит выбрать источник данных.

    Таким же образом можно создать редактируемую копию дашборда, который был развернут через провиженинг с флагом `editable: false`. Этот процесс также полезен для создания вариаций дашбордов на основе уже существующих, экономя время на их разработку.

### Хранение в системе контроля версий

Хранение JSON-файлов дашбордов в системе контроля версий (например, Git) является лучшей практикой. Это позволяет:
*   Отслеживать все изменения.
*   Просматривать историю и откатываться к предыдущим версиям.
*   Использовать дашборды в CI/CD пайплайнах для автоматического развертывания (см. [Провиженинг Grafana](./grafana_provisioning.md)).

### Обмен дашбордами (Sharing)

Grafana предоставляет несколько способов поделиться дашбордом:

*   **Прямая ссылка (Link)**: Генерирует URL для прямого доступа к дашборду. Требует, чтобы у получателя был доступ к вашему экземпляру Grafana.

*   **Снимок (Snapshot)**: Создает интерактивный, но **статичный "слепок"** дашборда в определенный момент времени.
    *   **Статичность:** Важно понимать, что снимок — это не "живой" дашборд. Данные в нем зафиксированы на момент создания и не обновляются. Любые интерактивные элементы (переменные, ссылки) на снимке работать не будут.
    *   **Публикация:** Снимок можно опубликовать на общедоступном сервере Grafana (`snapshots.raintank.io`) или **сохранить локально**. Локальный снимок генерирует URL, доступный внутри вашей Grafana без дополнительной авторизации.
    *   **Применение:** Это идеальный способ зафиксировать и поделиться состоянием системы во время инцидента с коллегами, у которых может не быть прямого доступа к Grafana.

*   **Экспорт (Export)**: Позволяет сохранить "чистую" JSON-модель дашборда для импорта в другой экземпляр Grafana, как описано выше.

## Импорт готовых дашбордов

У Grafana большое сообщество и огромная библиотека готовых дашбордов для сотен различных приложений и экспортеров.

1.  Найдите дашборд в официальной библиотеке [Grafana Dashboards](https://grafana.com/grafana/dashboards/). Популярным для мониторинга узлов является **Node Exporter Full** (ID: 1860).
2.  В вашем экземпляре Grafana перейдите в **Dashboards -> New -> Import**.
3.  Вы можете импортировать по:
    *   **ID дашборда:** Вставьте ID из библиотеки (например, `1860`). Grafana автоматически загрузит JSON-модель.
    *   **JSON-модели:** Вставьте JSON напрямую.
    *   **JSON-файлу:** Загрузите файл `.json`.
4.  После загрузки Grafana предложит настроить импорт: можно изменить имя дашборда, назначить его в папку и, что самое важное, выбрать правильный источник данных (Prometheus), к которому будут обращаться панели. Нажмите "Import".

### Провиженинг дашбордов (Configuration as Code)

Помимо ручного создания и импорта через UI, дашборды Grafana могут быть настроены декларативно с использованием провиженинга. Это позволяет управлять дашбордами как кодом, особенно при развертывании Grafana через Helm, обеспечивая автоматизацию и версионирование. Подробнее об этом подходе см. в документе: [Провиженинг Grafana (Configuration as Code)](./grafana_provisioning.md).

### Практический пример: Мониторинг хоста и Docker

Чтобы быстро получить готовую систему мониторинга для хост-машины и запущенных на ней Docker-контейнеров, можно импортировать следующие популярные дашборды:

1.  **Мониторинг хоста с помощью Node Exporter:**
    *   **Название:** Node Exporter Full
    *   **ID:** `1860`
    *   **Описание:** Один из самых полных и популярных дашбордов для визуализации метрик, собранных с помощью `node-exporter`. Включает в себя всё: от загрузки CPU и памяти до использования диска и сетевой активности.

2.  **Мониторинг Docker-контейнеров с помощью cAdvisor:**
    *   **Название:** cAdvisor Exporter
    *   **ID:** `14282`
    *   **Описание:** Дашборд, специально предназначенный для визуализации метрик из `cAdvisor`. Позволяет анализировать потребление ресурсов (CPU, память, сеть, I/O) по каждому контейнеру в отдельности.

**Процесс импорта:**
*   Перейдите в **Dashboards -> New -> Import**.
*   Введите ID нужного дашборда в поле "Import via grafana.com".
*   Нажмите **Load**.
*   В настройках импорта выберите ваш источник данных **Prometheus**.
*   Нажмите **Import**.

Импортировав эти два дашборда, вы получите мощную и детализированную систему для наблюдения за состоянием ваших серверов и контейнеров "из коробки".
