# Источники данных Grafana

.Ключевой особенностью является то, что **Grafana использует нативный язык запросов источника данных**. Это означает, что при работе с Prometheus вы будете писать запросы на PromQL, а при работе с PostgreSQL — на SQL. Grafana не имеет собственного языка запросов, она лишь предоставляет интерфейс для их выполнения и визуализации результатов.

## Структура датасурса

Каждый датасурс состоит из:

*   **Имя:** Уникальное название для идентификации источника данных.
*   **Default:** Параметр, указывающий, является ли данный датасурс используемым по умолчанию. Если при создании дашборда или другого элемента не указан конкретный датасурс, будет выбран тот, который помечен как default.
*   **Type (Тип коннектора):** Определяет тип системы, к которой подключается Grafana. Примеры: Prometheus, MySQL, Clickhouse, Zabbix, системы трассировки (Jagger, Zipkin) и другие.
*   **Кастомные настройки:** Набор специфических параметров подключения, таких как логин, пароль (если требуется авторизация), URL, HTTP-заголовки и т.д.

## Создание первого датасурса в Grafana

Для создания датасурса в Grafana:

1.  Перейдите в раздел "Data Sources".
2.  Нажмите кнопку "Add data source".
3.  Выберите тип источника данных (например, Prometheus, Graphite, OpenTSDB, InfluxDB, сервисы агрегации логов, трассировки, SQL-системы).

## Специальные источники данных

Помимо подключения к внешним системам, Grafana предоставляет несколько встроенных псевдо-источников данных для специальных задач:

*   **`TestData`**: Этот источник данных не подключается к реальной системе, а генерирует случайные временные ряды и другие данные. Он чрезвычайно полезен для:

    *   Тестирования и экспериментов с различными типами визуализаций.
    *   Создания макетов дашбордов, когда реальные данные еще недоступны.
    *   Изучения возможностей Grafana без необходимости разворачивать полноценный бэкенд.

*   **`Mixed` (Смешанный)**: Позволяет объединять данные из нескольких разных источников на одной панели. Например, вы можете на одном графике отобразить метрики из Prometheus и данные из PostgreSQL. Это мощный инструмент для корреляции данных из разрозненных систем. Также он позволяет использовать в качестве источника данных результаты запросов с других дашбордов.

### Провиженинг источников данных (Configuration as Code)

Помимо ручного создания через UI, источники данных Grafana могут быть настроены декларативно с использованием провиженинга, что позволяет управлять ими как кодом, особенно при развертывании Grafana через Helm. Подробнее об этом подходе см. в документе: [Провиженинг Grafana (Configuration as Code)](./grafana_provisioning.md).

**Важно:** При использовании провиженинга следует учитывать, что источники данных, созданные вручную, сохраняются, а провизионированные источники данных могут переопределять значения по умолчанию и обычно не редактируются через UI Grafana. Подробности см. в разделе "Важные замечания по провиженингу источников данных" в [Провиженинг Grafana (Configuration as Code)](./grafana_provisioning.md).

### Пример: Создание Prometheus датасурса

Рассмотрим создание датасурса типа Prometheus:

*   **Имя:** Укажите имя, например, "Prometheus".
*   **Default:** Отметьте, если это будет датасурс по умолчанию.
*   **HTTP-настройки:** Большинство датасурсов являются HTTP-датасурсами.
    *   **URL:** Укажите URL вашего Prometheus-сервера. Например, если Prometheus установлен в кластере Kubernetes в namespace `monitoring` и имеет сервис `prometheus-server`, полный путь будет `http://prometheus-server.monitoring.svc.cluster.local`. Если Grafana и Prometheus запущены локально через Docker Compose, можно использовать `http://prometheus:9090`.
    *   **Access:** Тип доступа (например, "Browser" или "Server").
    *   **Auth:** Параметры авторизации (Basic Auth, куки, кастомные HTTP-заголовки).
    *   **Scrape interval:** Интервал сбора метрик (по умолчанию 15 секунд).
    *   **Query timeout:** Таймаут запроса (по умолчанию 60 секунд).

После ввода всех параметров нажмите "Save & Test". Grafana создаст датасурс в своей базе данных и проверит подключение к указанному endpoint. При успешном подключении появится зеленое уведомление.

### Практическое задание (вне кластера)

Попробуйте подключиться к Prometheus, который находится вне кластера Kubernetes (например, выведен наружу через Ingress). Для этого:

1.  Используйте внешний HTTP endpoint Prometheus.
2.  Настройте параметры Basic авторизации, если она используется.

## Проверка работы датасурса

Для проверки работы подключенного датасурса:

1.  Перейдите в раздел "Explorer" в Grafana.
2.  Выберите созданный датасурс (например, Prometheus).
3.  Введите запрос PromQL, например: `kube_deployment_status_replicas_available`.
4.  Нажмите "Run query".

Вы увидите график и табличное представление полученных метрик. Например, запрос `kube_deployment_status_replicas_unavailable` покажет количество недоступных реплик. Если результат равен нулю, это означает, что с развертываниями все в порядке.

После успешного подключения и проверки датасурса можно приступать к созданию дашбордов и визуализаций.

## Пример: Настройка и интеграция Loki и Tempo

Одной из самых мощных возможностей Grafana является бесшовная интеграция между логами и трейсами. Ниже приведен пример настройки источников данных Loki и Tempo и их связывания.

### Шаг 1: Добавление источников данных

1.  **Добавьте источник данных Loki:**

    *   Перейдите в **Connections -> Data sources -> Add new data source**.
    *   Выберите **Loki**.
    *   Укажите **URL** вашего инстанса Loki (например, `http://loki:3100`).
    *   Нажмите **Save & test**.

2.  **Добавьте источник данных Tempo:**

    *   Перейдите в **Connections -> Data sources -> Add new data source**.
    *   Выберите **Tempo**.
    *   Укажите **URL** вашего инстанса Tempo (например, `http://tempo:3200`).
    *   В секции **Trace to logs** вы можете настроить обратную связь — переход от трейса к логам, указав ваш источник данных Loki.
    *   Нажмите **Save & test**.

### Шаг 2: Настройка связи из логов в трейсы (Derived Fields)

Это ключевой шаг, который позволяет одним кликом переходить из строки лога к соответствующему ей трейсу.

1.  Вернитесь в настройки источника данных **Loki**.
2.  Найдите раздел **Derived Fields**.
3.  Нажмите **Add** и заполните поля:
    *   **Name:** `TraceID` (или имя поля, в котором у вас хранится ID трассировки).
    *   **Regex:** `traceID=([a-zA-Z0-9]+)` или другое регулярное выражение, которое извлекает ID из строки лога. Например, если ваш лог содержит `TraceID: "xyz"`, регулярное выражение может быть `TraceID:\s*"(\w+)"`.
    *   **URL:** `${__value.raw}` (в это поле будет подставлено значение, найденное регулярным выражением).
    *   **Internal Link:** Включите эту опцию.
    *   **Data source:** Выберите ваш источник данных **Tempo**.

4.  Нажмите **Save & test**.

После этой настройки, когда вы будете просматривать логи в Grafana Explorer, все строки, содержащие ID трассировки, будут иметь кликабельную ссылку `TraceID`, которая мгновенно откроет соответствующий трейс в Tempo в том же окне.

## Практика: Настройка Prometheus как источника данных

1. **Подключение к grafana.**

Открываем в браузере: http://<monitoring IP>:3000. Имя пользователя и пароль по умолчанию admin/admin. Рекомендуется установить новый пароль.

2. **Добавляем Prometheus в качестве источника данных.**

На главном экране выбираем **Add data source**. Это также можно сделать, перейдя в **Settings -> Data Source**. В качестве источника данных выбираем **Prometheus**.

Заполняем следующие поля:

*   **Name** – имя источника данных, должно быть уникальным.
*   **URL** – адрес, где располагается Prometheus. Так как Grafana установлена на том же сервере, что и Prometheus, указываем: `http://localhost:9090`.
*   **Access** – способ подключения. **Server** является предпочтительным, так как запросы идут через бэкенд Grafana. **Browser** требует прямого доступа к Prometheus от клиента.
*   **Auth** – учетные данные для подключения к Prometheus, если они требуются.
*   **Scrape interval** – рекомендуется выставить равным глобальному значению `scrape_interval`, установленному в Prometheus.
*   **Query timeout** – максимальное время выполнения запроса к Prometheus.
*   **HTTP Method** – метод для отправки запросов. `POST` поддерживается с версии Prometheus 2.1.0.

После заполнения полей нажмите **Save & Test** для сохранения и проверки подключения.
