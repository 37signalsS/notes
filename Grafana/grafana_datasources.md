# Источники данных Grafana

## Определения

Ключевой особенностью Grafana является то, что она **использует нативный язык запросов источника данных**. Это означает, что при работе с Prometheus вы будете писать запросы на PromQL, а при работе с PostgreSQL — на SQL. Grafana не имеет собственного языка запросов, она лишь предоставляет интерфейс для их выполнения и визуализации результатов.

Каждый источник данных (datasource) состоит из следующих компонентов:

*   **Имя:** Уникальное название для идентификации источника данных.
*   **Default:** Параметр, указывающий, является ли данный датасурс используемым по умолчанию. Если при создании панели не указан конкретный источник, будет выбран тот, который помечен как default.
*   **Type (Тип коннектора):** Определяет тип системы, к которой подключается Grafana. Примеры: Prometheus, MySQL, Clickhouse, Zabbix, системы трассировки (Jaeger, Zipkin) и другие.
*   **Кастомные настройки:** Набор специфических параметров подключения, таких как URL, метод доступа, данные для аутентификации (логин, пароль, токен), HTTP-заголовки и т.д.

## Базовые концепции

### Специальные источники данных

Помимо подключения к внешним системам, Grafana предоставляет несколько встроенных псевдо-источников данных для специальных задач:

*   **`TestData`**: Генерирует случайные временные ряды и другие данные, не подключаясь к реальной системе. Чрезвычайно полезен для тестирования визуализаций, создания макетов дашбордов и изучения возможностей Grafana без развертывания полноценного бэкенда.
*   **`Mixed` (Смешанный)**: Позволяет объединять данные из нескольких разных источников на одной панели. Например, можно на одном графике отобразить метрики из Prometheus и данные из PostgreSQL. Это мощный инструмент для корреляции данных из разрозненных систем. Также он позволяет использовать в качестве источника данных результаты запросов с других дашбордов.

## Практические сценарии

### Ручная настройка источников данных

Ниже приведены примеры ручной настройки и интеграции популярных источников данных через веб-интерфейс Grafana.

#### Настройка и проверка Prometheus

##### Шаг 1: Подключение к Grafana

Откройте в браузере Grafana (например, `http://<monitoring-ip>:3000`). Имя пользователя и пароль по умолчанию: `admin/admin`. Рекомендуется сменить пароль при первом входе.

##### Шаг 2: Добавление Prometheus

1.  На главном экране выберите **Add data source** или перейдите в **Connections (значок шестеренки) -> Data Sources -> Add data source**.
2.  Выберите тип источника данных **Prometheus**.

##### Шаг 3: Настройка параметров

*   **Name**: Уникальное имя, например, "Prometheus".
*   **URL**: Адрес вашего Prometheus-сервера.
    *   В Kubernetes: `http://prometheus-server.monitoring.svc.cluster.local`.
    *   В Docker Compose: `http://prometheus:9090`.
    *   При локальной установке: `http://localhost:9090`.
*   **Access**: Способ подключения. **Server (proxy)** является предпочтительным, так как запросы идут через бэкенд Grafana.
*   **Auth**: Параметры аутентификации (Basic Auth, TLS, токены), если они требуются.
*   **Scrape interval**: Интервал сбора метрик. Рекомендуется выставить равным глобальному значению `scrape_interval` в Prometheus (например, `15s`).
*   **Query timeout**: Таймаут запроса (например, `60s`).
*   **HTTP Method**: Метод для отправки запросов. `POST` предпочтительнее для длинных запросов и поддерживается с версии Prometheus 2.1.0.

##### Шаг 4: Сохранение и проверка

Нажмите **Save & Test**. Grafana проверит подключение к указанному endpoint. При успехе появится зеленое уведомление.

##### Шаг 5: Проверка работы в Explorer
1.  Перейдите в раздел **Explore** (значок компаса) в Grafana.
2.  Выберите созданный источник данных (Prometheus).
3.  Введите запрос PromQL, например: `kube_deployment_status_replicas_available`.
4.  Нажмите **Run query**.

Вы должны увидеть график и табличное представление полученных метрик. Это подтверждает, что источник данных настроен корректно.

#### Интеграция Loki и Tempo для корреляции логов и трейсов

##### Шаг 1: Добавление источников данных
1.  **Добавьте источник данных Loki:**
    *   Перейдите в **Connections -> Data sources -> Add new data source**.
    *   Выберите **Loki**.
    *   Укажите **URL** вашего инстанса Loki (например, `http://loki:3100`).
    *   Нажмите **Save & test**.

2.  **Добавьте источник данных Tempo:**
    *   Перейдите в **Connections -> Data sources -> Add new data source**.
    *   Выберите **Tempo**.
    *   Укажите **URL** вашего инстанса Tempo (например, `http://tempo:3200`).
    *   В секции **Trace to logs** настройте обратную связь: выберите ваш источник данных Loki.
    *   Нажмите **Save & test**.

##### Шаг 2: Настройка связи из логов в трейсы (Derived Fields)
Этот шаг позволяет одним кликом переходить из строки лога к соответствующему ей трейсу.
1.  Вернитесь в настройки источника данных **Loki**.
2.  Найдите раздел **Derived Fields**.
3.  Нажмите **Add** и заполните поля:
    *   **Name:** `TraceID` (или имя поля, в котором у вас хранится ID трассировки).
    *   **Regex:** `traceID=([a-zA-Z0-9]+)` или другое регулярное выражение, которое извлекает ID из строки лога. Например, если ваш лог содержит `TraceID: "xyz"`, регулярное выражение может быть `TraceID:\s*"(\w+)"`.
    *   **URL:** `${__value.raw}` (в это поле будет подставлено значение, найденное регулярным выражением).
    *   **Internal Link:** Включите эту опцию.
    *   **Data source:** Выберите ваш источник данных **Tempo**.
4.  Нажмите **Save & test**.

После этой настройки в разделе **Explore** все строки логов, содержащие `TraceID`, будут иметь кликабельную ссылку, которая мгновенно открывает соответствующий трейс в Tempo.

## Дополнительная информация

### Управление источниками данных как код (Provisioning)

Помимо ручной настройки через UI, источники данных можно настраивать декларативно. Этот подход, называемый **провиженингом (Provisioning)**, позволяет управлять конфигурацией как кодом и является лучшей практикой для автоматизации и версионирования.

Конфигурация источников данных описывается в YAML-файлах, которые Grafana автоматически загружает при старте.

Подробное руководство по провиженингу источников данных, дашбордов и других ресурсов Grafana находится в основном документе: **[Grafana Provisioning](./grafana_provisioning.md)**.
