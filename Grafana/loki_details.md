# Grafana Loki: Детальный обзор

## Общие сведения

*   **Дата анонса:** 2018 год.
*   **General Available (GA):** 2019 год. Grafana Labs считает Loki достаточно зрелым для использования в production-средах с 2019 года.
*   **Язык разработки:** Go.
*   **Лицензия:** AGPLv3 (Affero General Public License v3). Эта лицензия является "вирусной" (copyleft) и требует, чтобы любые модификации или производные работы, распространяемые как сервис, также были доступны под AGPLv3. Это обеспечивает возврат наработок в Open Source сообщество, в отличие от лицензий Apache 2.0, которые позволяют создавать закрытые коммерческие продукты на основе открытого кода (примеры: изменения лицензий у MongoDB, Redis, HashiCorp). Grafana Labs намеренно перешла на AGPLv3 для своих новых продуктов, включая Loki, Mimir, Tempo.

## Хранение данных

*   **Формат данных:** Loki хранит логи в "чанках" (chunks), аналогично тому, как Prometheus хранит метрики в своей Time Series Database (TSDB). Это означает, что для тех, кто знаком с Prometheus, механизм хранения данных в Loki будет интуитивно понятен.
*   **Рекомендуемое хранилище:** Объектное хранилище (S3-совместимое). Loki поддерживает различные S3-совместимые хранилища, такие как AWS S3, Google Cloud Storage, Azure Blob Storage, Yandex Cloud Object Storage, VK Cloud Storage, а также локальные решения на базе MinIO или аппаратные решения с S3-интерфейсом. Допускается использование файловой системы, но не рекомендуется для production-нагрузок.

## Индексирование

*   **Особенность:** Loki индексирует **только метки (labels)**, связанные с сообщениями логов, а не само содержимое логов.
*   **Преимущества:** Значительно сокращает объем хранимых данных и стоимость хранения по сравнению с системами, индексирующими весь лог (например, Elasticsearch).
*   **Поиск по содержимому:** Несмотря на отсутствие индексации содержимого, поиск по тексту логов возможен. Он выполняется как "grep-подобная" операция по уже отфильтрованным по меткам логам. Это позволяет эффективно искать нужную информацию, параллелизуя операцию по множеству Querier-компонентов.

## Мультитенантность

*   **Встроенная поддержка:** Loki имеет встроенную поддержку мультитенантности ("из коробки").
*   **Механизм:** Позволяет разделять логи по "тенантам" (например, командам, департаментам, проектам) с помощью политик доступа. Каждый лог может быть помечен меткой, указывающей на его принадлежность к определенному тенанту.
*   **Отличие от Prometheus:** В отличие от Prometheus, где все метрики доступны любому, кто имеет доступ, Loki позволяет строго контролировать доступ к логам на основе тенантов, что критически важно для безопасности и соблюдения требований (например, при работе с персональными данными).

## Пользовательский интерфейс (UI)

*   **Отсутствие собственного UI:** Loki не имеет собственного фронтенда.
*   **Интеграция с Grafana:** В качестве основного UI для Loki используется Grafana. Это позволяет анализировать логи, строить графики и алерты в едином интерфейсе с метриками и трассировками.
*   **Альтернатива:** Также доступен `Loke CLI` — утилита командной строки для взаимодействия с Loki.

## Агенты для сбора логов

Loki может принимать логи от различных агентов:

*   **Grafana Alloy (рекомендовано):** Новый флагманский агент от Grafana Labs, основанный на OpenTelemetry Collector. Рекомендован для сбора метрик, логов и трассировок.
*   **Grafana Agent (устаревший):** Предыдущая версия агента, будет деприкейтнута после ноября 2025 года.
*   **Promtail (устаревший):** Специализированный агент для Loki, также будет деприкейтнут.
*   **OpenTelemetry Collector:** Универсальный коллектор телеметрии, полностью совместимый с Loki.
*   **Сторонние агенты:**
    *   **FluentBit, FluentD:** Популярные агенты для сбора и пересылки логов.
    *   **Logstash:** Требует установки специального плагина для отправки данных в Loki.
    *   **Vector:** Поддерживает отправку логов в Loki через `loki_sink`.

## Архитектура и развертывание

Loki может быть развернут в двух основных режимах:

1.  **Монолитный (Single Binary):** Все компоненты Loki запускаются в одном бинарном файле. Подходит для небольших инсталляций, изучения или разработки.
2.  **Микросервисный (Distributed):** Loki состоит из восьми основных компонентов, которые могут быть запущены как отдельные сервисы для горизонтального масштабирования и обеспечения высокой доступности:
    *   **Distributor:** Принимает входящие логи, проверяет их на валидность и распределяет по Ingestor-ам.
    *   **Ingestor:** Буферизирует логи в памяти, сжимает их и записывает в хранилище (S3/FS).
    *   **Querier Frontend (опционально):** Балансирует нагрузку на Querier-ы и кеширует результаты.
    *   **Querier Scheduler (опционально):** Помогает Querier-ам более эффективно работать с долгоживущими запросами.
    *   **Querier:** Обрабатывает запросы на чтение логов, извлекая данные из Ingestor-ов и хранилища.
    *   **IndexGateway:** Управляет чтением и записью данных индекса (методанных) в объектное хранилище.
    *   **Compactor:** Периодически оптимизирует и дедублицирует данные в хранилище, а также удаляет устаревшие логи по заданным правилам.
    *   **Ruler:** Оценивает правила оповещения и записи.

Компоненты группируются по функциям:
*   **Компоненты записи (Write Path):** Distributor, Ingestor.
*   **Компоненты чтения (Read Path):** Querier Frontend, Querier Scheduler, Querier.
*   **Вспомогательные компоненты:** IndexGateway, Compactor, Ruler.

Развертывание может быть выполнено:
*   В виде бинарного файла на сервере.
*   С использованием Docker-образов (например, через Docker Compose).
*   В Kubernetes с помощью Helm-чартов или операторов (рекомендуется Grafana Labs для production).

## Конфигурация

*   **Формат:** YAML.
*   **Пример минимальной конфигурации (файловая система):**

    ```yaml
    auth_enabled: false
    server:
      http_listen_port: 3100
    common:
      path_prefix: /loki
      replication_factor: 1
      ring:
        instance_addr: 127.0.0.1
        kvstore:
          store: inmemory
    schema_config:
      configs:
        - from: 2020-10-24
          store: boltdb-shipper
          object_store: filesystem
          schema: v11
          index:
            prefix: index_
            period: 24h
    storage_config:
      boltdb_shipper:
        active_index_directory: /loki/boltdb-shipper-active
        cache_location: /loki/boltdb-shipper-cache
        shared_store: filesystem
      filesystem:
        directory: /loki/chunks
    compactor:
      compaction_interval: 10m
    ruler:
      storage:
        type: local
        local:
          directory: /loki/rules
      rule_path: /loki/rules-temp
      alertmanager_url: http://alertmanager:9093
      ring:
        kvstore:
          store: inmemory
    ```

*   **Конфигурация для S3 (пример):**

    ```yaml
    # ... (общие настройки) ...
    schema_config:
      configs:
        - from: 2020-10-24
          store: boltdb-shipper
          object_store: s3
          schema: v11
          index:
            prefix: index_
            period: 24h
    storage_config:
      boltdb_shipper:
        active_index_directory: /loki/boltdb-shipper-active
        cache_location: /loki/boltdb-shipper-cache
        shared_store: s3
      s3:
        bucketnames: my-loki-bucket
        endpoint: s3.us-east-1.amazonaws.com # или endpoint вашего S3-совместимого хранилища
        region: us-east-1
        access_key_id: ${S3_ACCESS_KEY_ID} # Используйте переменные окружения или Vault
        secret_access_key: ${S3_SECRET_ACCESS_KEY} # Используйте переменные окружения или Vault
    # ... (остальные настройки) ...
    ```

## Язык запросов (LogQL)

*   **Основан на PromQL:** LogQL (Log Query Language) очень похож на PromQL, что облегчает его освоение для пользователей Prometheus.
*   **Работа с метками:** Основная фильтрация происходит по меткам.
*   **Текстовый поиск:** Для поиска по содержимому логов используются операторы фильтрации (аналогичные `grep`).
*   **Примеры запросов:**
    *   `{job="kubernetes-pods", namespace="default", container="application"} ` — Выбрать все логи из контейнера `application` в `default` namespace Kubernetes.
    *   `{job="kubernetes-pods", container="nginx"} |= "error" ` — Выбрать логи из `nginx` контейнеров, содержащие слово "error".
    *   `{job="kubernetes-pods", container="nginx"} |= "error" | logfmt | level="debug" ` — Выбрать `nginx` логи с "error", распарсить их как `logfmt` и отфильтровать по `level="debug"`.

## Алертинг

*   **Совместимость с Prometheus Alertmanager:** Правила оповещения в Loki пишутся в том же формате, что и для Prometheus, и могут быть отправлены в Prometheus Alertmanager (или Grafana OnCall) для обработки.
*   **Ruler-компонент:** Компонент Ruler в Loki отвечает за оценку правил оповещения и запись метрик на основе логов.

## Инструменты командной строки

*   **Loke CLI:** Утилита командной строки для взаимодействия с Loki, позволяющая выполнять запросы LogQL непосредственно из терминала. Доступна для Linux, macOS, FreeBSD и Windows.
*   **loki-tool:** Утилита для управления кластером Loki, валидации правил, проверки целостности индексов и других административных задач.
*   **Loki Canary:** Небольшая утилита для тестирования и мониторинга работоспособности и производительности кластера Loki. Генерирует тестовые логи, отправляет их в Loki и затем считывает для проверки целостности и задержек. Может работать как разово, так и в виде постоянного сервиса для регулярных health-чеков.

## Интеграция с Grafana

Grafana предоставляет бесшовную интеграцию с Loki, позволяя:
*   Визуализировать логи и метрики на одном дашборде.
*   Переходить от метрик к логам для анализа контекста.
*   Использовать мощные функции Grafana для фильтрации, агрегации и отображения логов.
