# Grafana: Дашборды — Дополнительная информация

## Управление дашбордами как код (Provisioning)

Дашборды можно настраивать декларативно, управляя ими как кодом. Это основной подход для автоматизации развертывания в нескольких окружениях.

Подробное описание методов находится в документе **[Grafana Provisioning](../grafana_provisioning.md)**.

## Best Practices

### Проектирование дашбордов

1. **Принцип "от общего к частному":**
   - Обзорный дашборд → дашборд сервиса → диагностический дашборд
   - Drilldown через ссылки с передачей переменных

2. **Единый стиль:**
   - Одинаковые цвета для одинаковых метрик
   - Согласованные единицы измерения
   - Стандартные названия панелей

3. **Документирование:**
   - Описание дашборда в JSON
   - Комментарии к сложным запросам
   - Ссылки на связанные дашборды

### Организация

1. **Папки:**
   - `00-Overview` — обзорные дашборды
   - `10-Platform` — инфраструктура
   - `20-Services` — сервисы по командам
   - `30-Diagnostics` — диагностические

2. **Нейминг:**
   - Формат: `SVC <Название> — <Метрика>`
   - Пример: `SVC Checkout — Latency`

3. **Теги:**
   - `env:prod`, `env:staging`
   - `team:payments`, `team:auth`
   - `layer:frontend`, `layer:backend`

### Версионирование

1. **Git-репозиторий:**
   - Хранение JSON дашбордов
   - Code review изменений
   - Откат к предыдущим версиям

2. **CI/CD:**
   - Автоматическое развертывание
   - Валидация JSON
   - Тестирование на staging

## Типы панелей и их применение

| Тип | Когда использовать | Пример |
|-----|-------------------|--------|
| **Time series** | Тренды, сезонность, корреляции | Запросов в секунду, latency |
| **Stat** | Единичное число, статус | Uptime, текущая ошибка |
| **Gauge** | Прогресс к лимиту | Использование памяти |
| **Table** | Сравнение экземпляров | Топ-10 подов по CPU |
| **Heatmap** | Распределения | Latency buckets |
| **Logs** | Логи рядом с метриками | Ошибки приложения |

## Переменные: лучшие практики

1. **Каскадные переменные:**
   - Сначала `cluster`, затем `namespace`, затем `pod`
   - Каждая переменная зависит от предыдущей

2. **Multi-value:**
   - Включать опцию "All"
   - Использовать `=~` в запросах

3. **Refresh:**
   - `On Dashboard Load` для статичных списков
   - `On Time Range Change` для динамических

## Аннотации

### Источники аннотаций

1. **Grafana:** Встроенные аннотации
2. **Prometheus:** Запросы к метрикам
3. **Loki:** Запросы к логам
4. **API:** Вебхуки от внешних систем

### Примеры использования

- Деплои: версия, автор, изменения
- Инциденты: начало, окончание, статус
- Переключения фич: включение/выключение
