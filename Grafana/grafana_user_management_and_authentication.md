## Определения

**Текущая версия (февраль 2026):** Grafana 12.x

### Роли пользователей

| Роль | Права |
| :--- | :--- |
| **Viewer** | Только просмотр дашбордов (read-only) |
| **Editor** | Создание и редактирование дашбордов, источников данных |
| **Admin** | Полный административный доступ |

### Ключевые понятия

| Понятие | Описание |
| :--- | :--- |
| **Команды (Teams)** | Группы пользователей для управления разрешениями |
| **Организации (Orgs)** | Полная изоляция ресурсов (дашборды, папки, источники) |
| **Сервисные аккаунты** | Учетные записи для API-автоматизации (Grafana 9+) |
| **API-ключи** | Устаревший способ автоматизации (привязан к пользователю) |

## Базовые концепции

### Иерархия доступа

1. **Роли** — базовые права в рамках организации.
2. **Команды** — группировка пользователей для управления разрешениями.
3. **Организации** — полная изоляция ресурсов между проектами/командами.

### Сервисные аккаунты vs API-ключи

| Характеристика | Сервисный аккаунт | API-ключ |
| :--- | :--- | :--- |
| **Привязка** | К организации | К пользователю |
| **Стабильность** | Не зависит от штата | Зависит от пользователя |
| **Токены** | Несколько с настраиваемым TTL | Один на ключ |
| **UI-доступ** | Нет | Нет |
| **Статус** | ✅ Рекомендуется | ⚠️ Устаревает |

### Внешняя аутентификация

Grafana поддерживает внешние провайдеры:

| Провайдер | Тип | Описание |
| :--- | :--- | :--- |
| **GitHub/GitLab** | OAuth | Аутентификация через аккаунт разработчика |
| **Google** | OAuth | Корпоративные аккаунты Google Workspace |
| **LDAP** | Directory | Интеграция с Active Directory/OpenLDAP |
| **SAML/OIDC** | Enterprise | Корпоративные SSO-решения (Grafana Enterprise) |

**Настройка OAuth (GitHub):**

```ini
# grafana.ini или values.yaml
[auth.github]
enabled = true
allow_sign_up = true
scopes = user:email,read:org
client_id = ${VAULT_KEY_CLIENT_ID}
client_secret = ${VAULT_KEY_CLIENT_SECRET}
allowed_organizations = your-github-org
```

> **Важно:** Проверьте `server.root_url` в `grafana.ini` для корректной работы callback-ссылок.

### Создание пользователей и управление правами

1. **Создание пользователя вручную (`New user`)**: Администратор задает логин и пароль. Подходит для создания служебных учетных записей.
2. **Отправка приглашения (`Invite`)**: Пользователь получает ссылку по электронной почте и самостоятельно устанавливает пароль. Рекомендуемый способ с точки зрения безопасности.

### Управление командами и правами доступа к папкам

1. **Создание команды**: В разделе `Configuration` -> `Teams` создается команда, куда добавляются пользователи.
2. **Настройка прав для папок (`Folders`)**: В настройках папки (`Dashboards` -> `Browse` -> `Permissions`) можно управлять доступом для ролей или команд. Права наследуются от папки к дашборду, но могут быть переопределены.

### Управление Сервисными аккаунтами

Сервисные аккаунты и их токены создаются в разделе **Configuration -> Service Accounts**.

**Создание токена:**

1. Выберите сервисный аккаунт.
2. Нажмите **Add new token**.
3. Задайте имя, роль и срок действия токена.
4. Сразу скопируйте и сохраните токен; он отображается только один раз.

### Управление API Ключами (устаревший способ)

API-ключи создаются в разделе **Configuration -> API Keys**.

1. Нажмите **New API key**.
2. Задайте имя, роль (`Admin`, `Editor`, `Viewer`) и срок действия.
3. Скопируйте и сохраните ключ; он отображается только один раз.

Используется для аутентификации в Grafana API, обычно через HTTP-заголовок `Authorization: Bearer <key>`.

### Автоматизация через Grafana API

Для задач, не поддерживаемых файловым провиженингом (например, управление пользователями, командами, организациями), используется Grafana API. Это позволяет реализовать подход "Security as Code".

**Пример автоматизации (с использованием `curl`):**

1. Создайте сервисный аккаунт с административными правами и токен для него.
2. Используйте токен для отправки `curl`-запросов к эндпоинтам Grafana API для создания организаций (`/api/orgs`), пользователей (`/api/admin/users`), команд (`/api/teams`) и добавления пользователей в команды (`/api/teams/{team_id}/members`).

Такие скрипты интегрируются в CI/CD пайплайны для автоматической настройки Grafana.

### Настройка аутентификации через GitHub

Настройка аутентификации через GitHub включает:

1. **Создание OAuth App в GitHub**: В `Settings` -> `Developer settings` -> `OAuth Apps` создайте приложение. Укажите `Authorization callback URL` как `http://<your-grafana-url>/login/github`. Получите `Client ID` и `Client Secret`.
2. **Конфигурация Grafana**: В `grafana.ini` (или `values.yaml` для Helm-чарта) настройте секцию `auth.github`.

    ```yaml
    grafana.ini:
      auth.github:
        enabled: true
        allow_sign_up: true
        scopes: user:email,read:org
        client_id: "${VAULT_KEY_CLIENT_ID}" # Используйте переменные или Vault
        client_secret: "${VAULT_KEY_CLIENT_SECRET}" # Используйте переменные или Vault
        allowed_organizations: "your-github-org"
    ```

3. **Применение конфигурации**: Обновите Helm-релиз. После этого на странице входа Grafana появится кнопка "Sign in with GitHub".

## Дополнительная информация

### Best Practices

- **Сервисные аккаунты** — используйте для автоматизации вместо API-ключей
- **OAuth/LDAP** — предпочтительно для командной работы
- **Минимальные привилегии** — выдавайте роли по принципу least privilege
- **Регулярный аудит** — проверяйте активных пользователей и права
