# Grafana: Шаблонизация (Templating)

## Определения

**Шаблонизация (Templating)** — механизм создания динамических дашбордов через переменные. Значения подставляются в запросы, заголовки, аннотации.

**Текущая версия (март 2026):** Grafana 12.4.2

### Преимущества

| Преимущество | Описание |
| :--- | :--- |
| **Переиспользование** | Один дашборд для множества ресурсов |
| **Навигация** | Быстрое переключение между сервисами |
| **Масштабирование** | Автоматическое повторение панелей |

## Основные концепции

### Типы переменных

| Тип | Назначение | Пример |
| :--- | :--- | :--- |
| **Query** | Список значений из источника данных | `label_values(up, job)` |
| **Custom** | Статический список | `prod,staging,dev` |
| **Constant** | Глобальная константа | `region=eu-central` |
| **Interval** | Временной шаг агрегации | `15s, 1m, 1h` |
| **Datasource** | Выбор источника данных | Переключение Prometheus |
| **Text box** | Произвольный ввод | Префикс имени пода |
| **Ad hoc filters** | Быстрые фильтры по лейблам | `label=value` для Prometheus |

### Глобальные переменные времени

| Переменная | Описание |
| :--- | :--- |
| **`$__interval`** | Автоматический шаг агрегации |
| **`$__range`** | Текущий временной диапазон (`1h`) |
| **`$__rate_interval`** | Рекомендуемый интервал для `rate()` (минимум 4 точки) |

## Практические сценарии

### Сценарий 1: Создание цепочки зависимых переменных

Этот подход позволяет сужать выбор на каждом следующем уровне.

1. **Переменная `cluster`** (тип `Query`):

    ```promql
    label_values(up{job="node-exporter"}, cluster)
    ```

    *Включается опция **Include All** с кастомным значением `.*` для возможности выбора всех кластеров.*

2. **Переменная `namespace`** (тип `Query`), зависимая от `$cluster`:

    ```promql
    label_values(kube_pod_info{cluster=~"$cluster"}, namespace)
    ```

3. **Переменная `pod`** (тип `Query`), зависимая от `$cluster` и `$namespace`:

    ```promql
    label_values(kube_pod_info{cluster=~"$cluster", namespace=~"$namespace"}, pod)
    ```

> **Настройка обновления (Refresh)**:
>
> - **On Dashboard Load**: Для стабильных списков (например, имена окружений).
> - **On Time Range Change**: Если значения зависят от выбранного окна времени.

### Сценарий 2: Использование переменных в запросах и заголовках

Переменные подставляются в запросы с помощью синтаксиса `$имя_переменной`.

**Пример запроса PromQL:**

```promql
rate(container_cpu_usage_seconds_total{
  cluster=~"$cluster",
  namespace=~"$namespace",
  pod=~"$pod"
}[$__rate_interval])
```

*Оператор `=~` используется для поддержки множественных значений (multi-value) и опции "All".*

**Пример запроса LogQL (Loki):**

```logql
sum by (app) (rate({cluster=~"$cluster", namespace=~"$namespace"} |= "ERROR" [5m]))
```

**Динамический заголовок панели:**
`CPU Usage for $pod in $namespace`

### Сценарий 3: Повторение панелей или рядов (Repeating)

Для переменных с опцией **Multi-value** или **All** можно настроить автоматическое создание копий панелей или рядов внутри панели.

- **Repeat by variable**: Опция в настройках панели/ряда.
- **Пример**: Если выбрано несколько `namespace` в переменной `$namespace`, Grafana создаст отдельную строку (row) с панелями для каждого из них.

## Дополнительная информация

### Best Practices

| Правило | Описание |
| :--- | :--- |
| **Оператор `=~`** | Всегда для multi-value и All |
| **Маска для All** | Используйте `.*`, а не `*` |
| **Экранирование** | `$${var:regex}` для спецсимволов |
| **Оптимизация** | Избегайте тяжёлых `label_values` без селекторов |
| **Сортировка** | Включайте `Sort` и `Unique` для очистки списков |

### Частые ошибки

- **`label_values({__name__=~".*"}, pod)`** — перегружает БД метрик
- **`Refresh: On Time Range Change`** — для длинных списков (тысячи подов)
- **Минимальный интервал** — задавайте `Min time interval` для производительности
