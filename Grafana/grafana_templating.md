# Grafana: Шаблонизация (Templating)

## Определения

**Шаблонизация (Templating)** в Grafana — это механизм создания **динамических и интерактивных дашбордов** с помощью переменных. Значения переменных могут подставляться в запросы к источникам данных, заголовки панелей, аннотации и другие элементы. Это позволяет использовать один дашборд для мониторинга множества однотипных ресурсов (сервисов, серверов, окружений), уменьшая дублирование и ускоряя навигацию.

## Основные концепции

### Типы переменных

| Тип | Назначение | Пример использования |
| :--- | :--- | :--- |
| **Query** | Получение списка значений из запроса к источнику данных. | `label_values(up, job)` для списка `job` в Prometheus. |
| **Custom** | Статический, заданный вручную список значений. | `prod,staging,dev` |
| **Constant** | Одиночное, скрытое значение. Полезно для глобальных констант. | `region=eu-central` |
| **Interval** | Временной шаг для агрегации данных. | `15s, 1m, 1h` |
| **Datasource** | Динамический выбор источника данных для панелей. | Переключение между разными экземплярами Prometheus. |
| **Text box** | Произвольная строка, вводимая пользователем. | Фильтр по префиксу имени пода. |
| **Ad hoc filters** | Автоматически создаваемые фильтры по всем доступным лейблам (для некоторых источников, например, Prometheus). | Быстрая фильтрация по `label=value` без объявления переменных. |

### Глобальные переменные времени

Grafana предоставляет встроенные переменные для работы с временными диапазонами в запросах:

- **`$__interval`**: Автоматически рассчитываемый шаг агрегации, который зависит от выбранного диапазона времени и ширины графика.
- **`$__range`**: Текущий временной диапазон (например, `1h`).
- **`$__rate_interval`**: Рекомендуемый интервал для функций типа `rate()` и `irate()`. Гарантирует, что в диапазон попадет как минимум 4 точки данных, что решает проблему с пропуском данных (`sparse data`).

## Практические сценарии

### Сценарий 1: Создание цепочки зависимых переменных

Этот подход позволяет сужать выбор на каждом следующем уровне.

1.  **Переменная `cluster`** (тип `Query`):
    ```promql
    label_values(up{job="node-exporter"}, cluster)
    ```
    *Включается опция **Include All** с кастомным значением `.*` для возможности выбора всех кластеров.*

2.  **Переменная `namespace`** (тип `Query`), зависимая от `$cluster`:
    ```promql
    label_values(kube_pod_info{cluster=~"$cluster"}, namespace)
    ```

3.  **Переменная `pod`** (тип `Query`), зависимая от `$cluster` и `$namespace`:
    ```promql
    label_values(kube_pod_info{cluster=~"$cluster", namespace=~"$namespace"}, pod)
    ```

> **Настройка обновления (Refresh)**:
> - **On Dashboard Load**: Для стабильных списков (например, имена окружений).
> - **On Time Range Change**: Если значения зависят от выбранного окна времени.

### Сценарий 2: Использование переменных в запросах и заголовках

Переменные подставляются в запросы с помощью синтаксиса `$имя_переменной`.

**Пример запроса PromQL:**
```promql
rate(container_cpu_usage_seconds_total{
  cluster=~"$cluster",
  namespace=~"$namespace",
  pod=~"$pod"
}[$__rate_interval])
```
*Оператор `=~` используется для поддержки множественных значений (multi-value) и опции "All".*

**Пример запроса LogQL (Loki):**
```logql
sum by (app) (rate({cluster=~"$cluster", namespace=~"$namespace"} |= "ERROR" [5m]))
```

**Динамический заголовок панели:**
`CPU Usage for $pod in $namespace`

### Сценарий 3: Повторение панелей или рядов (Repeating)

Для переменных с опцией **Multi-value** или **All** можно настроить автоматическое создание копий панелей или рядов внутри панели.

- **Repeat by variable**: Опция в настройках панели/ряда.
- **Пример**: Если выбрано несколько `namespace` в переменной `$namespace`, Grafana создаст отдельную строку (row) с панелями для каждого из них.

## Дополнительная информация

### Лучшие практики и частые ошибки

- **Оператор `=~`**: Всегда используйте `=~` для переменных с опциями **Multi-value** или **All**. Оператор `=` подходит только для одиночных значений.
- **Маска для "All"**: Корректная маска для регулярного выражения — `.*`, а не `*`.
- **Экранирование спецсимволов**: Если значения переменной могут содержать спецсимволы, используйте форматирование `$${var:regex}` (например, `pod=~"$${pod:regex}"`).
- **Оптимизация производительности**:
  - Избегайте "тяжелых" запросов `label_values` без селекторов (например, `label_values({__name__=~".*"}, pod)`), так как это перегружает базу данных метрик.
  - Для длинных списков значений (тысячи подов) используйте опцию **Refresh: On Time Range Change** и задавайте минимальный интервал обновления (`Min time interval`).
- **Сортировка и уникальность**: Используйте опции `Sort` и `Unique` в настройках переменной для очистки и упорядочивания выпадающих списков.
