# Grafana: Шаблонизация

## Определения

**Шаблонизация (Templating)** — механизм создания динамических дашбордов через переменные. Значения переменных подставляются в запросы к источникам данных, заголовки панелей, аннотации и ссылки, позволяя одному дашборду отображать данные для различных ресурсов (серверов, приложений, кластеров) без дублирования панелей.

**Связанные темы:**

- [Дашборды: определения и концепции](./grafana-dashboards.md)
- [Источники данных](./grafana_datasources.md)

## Базовые концепции

### Преимущества шаблонизации

| Преимущество | Описание |
| :--- | :--- |
| **Переиспользование** | Один дашборд обслуживает множество однотипных ресурсов |
| **Удобство навигации** | Быстрое переключение контекста через выпадающие списки |
| **Автоматизация** | Динамическое создание рядов и панелей при добавлении новых сущностей |
| **Условная логика (v12+)**| Возможность скрывать или отображать панели на основе выбранных значений переменных |
| **Git Sync (v12+)** | Возможность версионирования и синхронизации шаблонов напрямую из Git-репозиториев |

### Типы переменных

| Тип | Назначение | Пример / Синтаксис |
| :--- | :--- | :--- |
| **Query** | Список значений, получаемый динамически из БД. В v12+ поддерживает подмешивание статических значений | `label_values(up, job)` |
| **Multi-property (v12.4+)**| Переменная, хранящая объект с несколькими свойствами (например, `ID` и `IP`) | Используется в Infinity и SQL источниках |
| **Custom** | Фиксированный список значений, заданный вручную | `prod,staging,dev` |
| **Constant** | Глобальная константа для дашборда | `region=eu-central` |
| **Interval** | Временной шаг для функций агрегации | `15s, 1m, 1h` |
| **Datasource** | Переключение между разными источниками данных | Выбор между `Prometheus-1` и `Prometheus-2` |
| **Text box** | Поле для ручного ввода произвольного текста | Поиск по части имени пода |
| **Ad hoc filters** | Динамические фильтры по любым лейблам источника | `label=value` |

### Глобальные переменные времени и системы

Grafana предоставляет встроенные переменные для управления контекстом:

| Переменная | Описание |
| :--- | :--- |
| **`$__interval`** | Оптимальный шаг агрегации, вычисляемый на основе размера панели и диапазона |
| **`$__range`** | Текущий выбранный временной диапазон (например, `1h` или `24h`) |
| **`$__rate_interval`** | Рекомендуемый интервал для функции `rate()`, гарантирующий наличие минимум 4 точек |
| **`$__user`** | Данные текущего пользователя (ID, логин, email) |
| **`$__dashboard`** | Метаданные текущего дашборда (название, UID) |
| **`$__org`** | Данные организации (ID, название) |

### Синтаксис форматирования (Variable Formatting)

Для корректной передачи значений переменных в разные типы запросов используется синтаксис `${var_name:format}`:

| Формат | Описание | Пример результата |
| :--- | :--- | :--- |
| **`:regex`** | Для использования в регулярных выражениях (PromQL, LogQL) | `(val1|val2)` |
| **`:glob`** | Формат Graphite | `{val1,val2}` |
| **`:csv`** | Значения через запятую | `val1,val2` |
| **`:sqlstring`**| Экранированные строки для SQL | `'val1','val2'` |
| **`:doublequote`**| Значения в двойных кавычках | `"val1","val2"` |
| **`:percentencode`**| Для использования в URL-адресах | `val%201` |
| **`:pipe`** | Значения через вертикальную черту | `val1|val2` |

## Практические сценарии

### Сценарий 1: Создание цепочки зависимых переменных

Цепочки позволяют фильтровать значения последующих переменных на основе выбора в предыдущих (например: Кластер → Namespace → Pod).

1. **Создание переменной `cluster`** (тип `Query`):
    Запрос для Prometheus:
    ```promql
    label_values(up{job="node-exporter"}, cluster)
    ```
    *Рекомендуется включить опцию **Include All** с регулярным выражением `.*`.*

2. **Создание переменной `namespace`**, зависимой от `$cluster`:
    ```promql
    label_values(kube_pod_info{cluster=~"$cluster"}, namespace)
    ```

3. **Создание переменной `pod`**, зависимой от `$cluster` и `$namespace`:
    ```promql
    label_values(kube_pod_info{cluster=~"$cluster", namespace=~"$namespace"}, pod)
    ```

> **Настройка обновления (Refresh)**:
> - **On Dashboard Load**: Для редко меняющихся списков (имена кластеров).
> - **On Time Range Change**: Если список значений зависит от времени (например, поды, существовавшие только в выбранном интервале).

### Сценарий 2: Подстановка переменных в запросы

Переменные внедряются в запросы с помощью префикса `$`.

**Пример запроса PromQL:**
```promql
# Использование оператора =~ для поддержки Multi-value выбора
rate(container_cpu_usage_seconds_total{
  cluster=~"$cluster",
  namespace=~"$namespace",
  pod=~"$pod"
}[$__rate_interval])
```

**Пример запроса LogQL (Loki):**
```logql
sum by (app) (rate({cluster=~"$cluster", namespace=~"$namespace"} |= "ERROR" [5m]))
```

**Динамические заголовки:**
Заголовок панели: `CPU Usage for $pod (Namespace: $namespace)`

### Сценарий 3: Автоматическое повторение (Repeating)

Для переменных с включенными опциями **Multi-value** или **All** Grafana может автоматически дублировать панели или ряды.

- **Repeat Options**: Находятся в настройках панели (раздел `Repeating`) или ряда.
- **Direction**: `Horizontal` (панели в ряд) или `Vertical` (панели друг под другом).
- **Результат**: Если в переменной `$service` выбрано 5 сервисов, Grafana отобразит 5 идентичных панелей, каждая со своим значением.

### Сценарий 4: Условная видимость панелей (v12+)

Вы можете настроить панель так, чтобы она отображалась только при определенном выборе в переменной.
1. В настройках панели перейдите в раздел **Visibility**.
2. Установите условие, например: `$show_details == 'true'`.
3. Панель будет мгновенно скрыта, если значение переменной не соответствует условию, что позволяет создавать «адаптивные» дашборды.

## Дополнительная информация

### Рекомендации (Best Practices)

| Правило | Описание |
| :--- | :--- |
| **Оператор `=~`** | Всегда используйте его в запросах, если переменная поддерживает множественный выбор или "All" |
| **Регулярные выражения** | Используйте `.*` для значения All, чтобы корректно обрабатывать пустые или специфичные выборки |
| **Экранирование** | Используйте синтаксис `${var:format}` для корректной передачи спецсимволов в зависимости от типа БД |
| **Оптимизация запросов** | Добавляйте селекторы в `label_values`, чтобы ограничить объем данных, сканируемых БД при загрузке дашборда |
| **Сортировка** | Используйте встроенную сортировку в настройках переменной для удобства поиска в списке |

### Типичные ошибки

- **Запросы без селекторов**: `label_values({__name__=~".*"}, pod)` создает колоссальную нагрузку на Prometheus. Всегда указывайте хотя бы один фильтр (например, `job` или `cluster`).
- **Избыточный Refresh**: Установка `On Time Range Change` для переменной со списком из тысяч объектов (например, ID транзакций) приведет к тормозам при каждом скролле времени.
- **Отсутствие Min time interval**: Если переменная `$__interval` становится слишком малой, запросы могут возвращать пустые результаты.

Подробная информация о синтаксисе переменных доступна в [документации Grafana](https://grafana.com/docs/grafana/latest/dashboards/variables/).
