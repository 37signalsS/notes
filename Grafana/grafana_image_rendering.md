# Рендеринг изображений (grafana-image-renderer)

Практическое руководство по компоненту `grafana-image-renderer`, который генерирует изображения дашбордов и панелей. Версии: 13.x актуальная, 12.x LTS, 11.x — EOL (июнь 2026). Облачные и ИИ-функции не рассматриваются.

## Определения

- **grafana-image-renderer** — отдельный сервис (на базе headless Chromium), который Grafana вызывает по HTTP для рендеринга дашборда/панели в PNG. Нужен для изображений в уведомлениях алертинга, снимках (snapshots) и отчётах (reporting).
- **callback URL** — адрес, по которому Grafana сообщает рендереру, какой дашборд рендерить (обычно внешний `root_url`).
- **rendering_* (grafana.ini)** — секция `[rendering]`, управляющая подключением к сервису рендеринга.
- **Headless Chromium** — браузер без GUI, потребляющий заметные CPU/память при рендеринге тяжёлых дашбордов.

## Базовые концепции

Сам Grafana не умеет рисовать дашборд в картинку — это делает внешний сервис `grafana-image-renderer` (ранее был встроенным через плагин/phantomjs, теперь это отдельный deployment). Поток:

1. Grafana получает запрос на изображение (алерт, снимок, отчёт).
2. Отправляет рендереру URL дашборда + параметры (тема, ширина, время).
3. Рендерер открывает дашборд в headless Chromium, дожидается загрузки панелей, делает скриншот, отдаёт PNG.
4. Grafana вкладывает PNG в уведомление/снимок.

Без рендерера алерты и снимки отправляются без графиков (только текст/ссылка). Поэтому в продакшене с алертингом рендерер обязателен и его выносят в отдельный процесс/под, чтобы он не «съедал» память основного инстанса Grafana.

Рендерер должен иметь сетевой доступ к Grafana по `callback_url` (и наоборот — Grafana к рендереру). При неверном `callback_url` рендерер пытается открыть недоступный адрес и возвращает таймаут/пустую картинку.

## Практические сценарии

### Предварительные требования

- Grafana 11.x+ (рендерер как внешний сервис).
- Доступ к сети между Grafana и рендерером (порт рендерера, по умолчанию 8081).
- Рендерер должен резолвить и достигать `root_url` Grafana (callback).

### Сценарий 1. Установка рендерера через Docker Compose

```yaml
services:
  grafana-image-renderer:
    image: grafana/grafana-image-renderer:3.11.0
    ports:
      - "8081:8081"
    environment:
      # Адрес, по которому рендерер дойдёт до Grafana
      - GF_RENDERER_CALLBACK_URL=https://grafana.example.internal/
      # Лимиты ресурсов headless Chromium
      - GF_RENDERER_RENDERING_VIEWPORT_WIDTH=1280
      - GF_RENDERER_RENDERING_VIEWPORT_HEIGHT=720
      - GF_RENDERER_RENDERING_DEVICE_SCALE_FACTOR=2
    deploy:
      resources:
        limits:
          cpus: "1.0"
          memory: 1G
```

### Сценарий 2. Подключение Grafana к рендереру

```ini
[rendering]
# Включить внешний рендеринг
server_url = http://grafana-image-renderer:8081/render
# callback — внешний URL Grafana, который рендерер сможет открыть
callback_url = https://grafana.example.internal/
# Таймаут рендеринга (сек)
timeout = 60
# Ключ, если рендерер требует (опционально)
# rendering_key = ...
```

Через переменные: `GF_RENDERING_SERVER_URL`, `GF_RENDERING_CALLBACK_URL`, `GF_RENDERING_TIMEOUT`.

Проверка — отправить тестовый алерт со включённым «Include image» либо сделать снимок дашборда; в уведомлении/снимке появляется PNG.

### Сценарий 3. Проверка связи вручную

```bash
# Grafana должна видеть рендерер
curl -s http://grafana-image-renderer:8081/render/health
# → {"status":"ok"} (или пустой 200)

# Рендерер должен достигать Grafana по callback
curl -sI https://grafana.example.internal/api/health
# → HTTP/2 200
```

### Сценарий 4. Установка через Helm

```bash
helm upgrade grafana grafana/grafana -n monitoring \
  --set "grafana-image-renderer.enabled=true" \
  --set "grafana-image-renderer.env.GF_RENDERER_CALLBACK_URL=https://grafana.example.internal/"
# → деплоится отдельный Deployment рендерера, Grafana настраивается автоматически
```

## Дополнительная информация

### Рекомендации по эксплуатации

- Выносите рендерер в отдельный процесс/под с лимитами памяти — тяжёлые дашборды могут «съесть» сотни МБ на скриншот.
- `callback_url` должен быть тем же, что и внешний `root_url`, иначе рендерер не откроет дашборд.
- Включайте «Include image» только в тех каналах алертинга, где картинка нужна (Slack/Email/Telegram) — это добавляет нагрузку на рендерер.
- Мониторьте доступность `/render/health` рендерера и его потребление памяти.
- Обновляйте рендерер синхронно с мажорными версиями Grafana.

### Типичные ошибки и их решение

| Симптом | Причина | Решение |
| --- | --- | --- |
| Алерты/снимки без картинки | Рендерер не настроен/недоступен | Проверить `[rendering]`, `/render/health` |
| `timeout` при рендеринге, пустая картинка | Тяжёлый дашборд, медленная загрузка | Увеличить `timeout`, уменьшить число панелей |
| Рендерер не открывает дашборд | Неверный `callback_url` / нет сети до Grafana | Выставить внешний `callback_url`, проверить сеть |
| OOM на узле Grafana | Рендерер в том же процессе/узле | Вынести рендерер отдельно с лимитами |
| Картинка «белая»/недогруз панелей | Панели не успели отрисоваться | Увеличить таймаут, проверить доступность источников данных |
| 502 от рендерера | Он упал/не запущен | `docker compose ps`, логи рендерера |

### Ограничения и особые случаи

- Рендерер требует исходящий доступ к Grafana по `callback_url` и к источникам данных дашборда (он открывает дашборд как браузер).
- Headless Chromium потребляет существенные ресурсы; на малых узлах ограничивайте concurrency.
- Для приватных дашбордов рендерер должен иметь возможность авторизоваться (token/service account) — иначе картинка будет пустой/по правам.
- Версии рендерера и Grafana желательно держать совместимыми (см. release notes).

### Очистка и откат изменений

- Чтобы отключить изображения без удаления рендерера — уберите «Include image» из contact points алертинга.
- Для полного отключения рендеринга удалите секцию `[rendering]` (Grafana вернётся к текстовым уведомлениям).
- Удаление рендерера: `docker compose rm -s grafana-image-renderer` / `helm` отключить `grafana-image-renderer.enabled=false`.

### Актуальность и статус

Модель внешнего `grafana-image-renderer` актуальна для 11.x/12.x/13.x. Образ `grafana/grafana-image-renderer` публикуется синхронно с релизами Grafana.
