# Grafana

Grafana — это open-source решение для визуализации и анализа метрик, поступающих из различных источников данных. Она очень популярна в индустрии, особенно в контексте микросервисов, облачных инфраструктур и инсталляций на собственном железе. Она позволяет строить графики, диаграммы и дашборды, а также генерировать и рассылать алерты. Grafana помогает понимать текущее состояние инфраструктуры и выявлять проблемы. Важно отметить, что Grafana сама по себе не хранит данные, а только запрашивает и визуализирует их из подключенных систем.

## Архитектура и история

Grafana написана на языке Go (бэкенд) и TypeScript/React (фронтенд). Проект был запущен в 2014 году как форк третьей версии Kibana, но быстро пошел по собственному пути развития и стал самостоятельным продуктом. Благодаря открытому исходному коду и активному сообществу, Grafana превратилась в де-факто стандарт для визуализации в области мониторинга. У Grafana есть собственный CLI и API для автоматизации управления. Проект постоянно развивается; например, в будущих версиях (таких как Grafana 12) ожидается глубокая интеграция с Git-репозиториями для расширенного провиженинга (см. также [Провиженинг Grafana](./grafana_provisioning.md)).

## Основные возможности Grafana

*   **Визуализация данных:** Построение интерактивных графиков, диаграмм и дашбордов из различных источников данных.
*   **Подключение источников данных (Data Sources):** Поддержка множества источников данных, таких как Prometheus, Graphite, InfluxDB, [Elasticsearch](../Elasticsearch/elasticsearch_sharding_replication_cluster.md), PostgreSQL, MySQL и многих других.
*   **Анализ логов:** Современные версии Grafana позволяют работать с логами, интегрируясь с системами вроде Loki.
*   **Дашборды:** Создание и управление настраиваемыми дашбордами для отображения ключевых метрик. Подробное руководство: [Создание дашбордов](./grafana_dashboards.md).
*   **Плагины:** Расширение функциональности Grafana с помощью плагинов для новых источников данных, панелей визуализации и приложений. Подробное руководство: [Установка плагинов](./grafana_plugins.md).
*   **Алертинг:** Настройка правил оповещения на основе метрик и отправка уведомлений через различные каналы (email, Slack, PagerDuty и т.д.). Подробное руководство: [Настройка оповещений в Grafana](./grafana_alerting.md).
*   **Управление пользователями и доступом:** Гибкая система управления пользователями, ролями и разрешениями для контроля доступа к дашбордам и источникам данным. Подробное руководство: [Управление пользователями и аутентификация в Grafana](./grafana_user_management_and_authentication.md).
*   **Провиженинг:** Автоматизация создания и обновления дашбордов, источников данных и других конфигураций Grafana с помощью файлов конфигурации (например, через GitOps). Подробное руководство: [Провиженинг Grafana (Configuration as Code)](./grafana_provisioning.md).
*   **Высокая доступность (High Availability):** Возможность развертывания Grafana в отказоустойчивом кластере для обеспечения непрерывной работы. Подробное руководство: [Настройка высокой доступности](./high_availability.md).
*   **Расширенные возможности:** Поддержка аннотаций, переменных шаблонов, сравнения временных диапазонов и других функций для глубокого анализа данных.
*   **Image Render:** Компонент для генерации изображений графиков, используемый для прикрепления к уведомлениям об алертах. Работает на базе Chrome.
*   **Широкое применение:** Изначально ориентированная на IT-мониторинг, Grafana теперь активно используется в самых разных областях, включая **Интернет вещей (IoT)** для мониторинга умного дома, **промышленность** и даже **сельское хозяйство** для отслеживания показателей техники (например, мониторинг движения комбайнов и расхода топлива).

## Grafana как единое окно для Observability: Grafana Stack

Одной из ключевых сильных сторон Grafana является её способность объединять данные из разных источников в едином интерфейсе. В контексте [современной наблюдаемости](../Concepts/Observability_and_Monitoring/observability_overview.md) Grafana выступает как центральный инструмент, позволяющий бесшовно переключаться между тремя основными столпами наблюдаемости: метриками, логами и трассировками. Этот подход реализован в так называемом **Grafana Stack** (ранее LGTM: Loki, Grafana, Tempo, Mimir).

### Единая архитектурная философия

Ключевое преимущество Grafana Stack заключается в том, что его основные бэкенд-компоненты (Mimir, Loki, Tempo) построены на общих принципах и имеют практически идентичную архитектуру.

*   **Язык:** Все компоненты написаны на **Go**.
*   **Режим развертывания:** Каждый компонент может быть запущен как в виде **одного бинарного файла** (монолит) для простых инсталляций, так и в виде набора **горизонтально масштабируемых микросервисов** для обеспечения высокой доступности и производительности.
*   **Хранилище:** Для долгосрочного хранения данных все три системы используют **объектные хранилища** (S3, GCS, Azure Blob Storage, MinIO), что делает хранение данных дешевым и надежным.
*   **Лицензия:** Распространяются под лицензией **AGPLv3**. Эта лицензия является "вирусной" (copyleft), что означает, что любые модификации или производные работы, распространяемые как сервис, также должны быть доступны под AGPLv3. Это обеспечивает возврат наработок в Open Source сообщество и способствует устойчивому развитию проектов. Grafana Labs намеренно выбрала AGPLv3 для своих новых продуктов, включая Mimir, Loki и Tempo, в отличие от более пермиссивных лицензий, которые допускают создание закрытых коммерческих продуктов на основе открытого кода.
*   **Интерфейс:** В качестве пользовательского интерфейса используется **Grafana**.

Такой подход значительно упрощает администрирование всего стека. Изучив архитектуру одного компонента (например, Loki), вы с легкостью поймете, как устроены и как масштабируются остальные. Это снижает порог вхождения и совокупную стоимость владения.

### Преимущества интегрированного подхода

Главная сила Grafana Stack — в бесшовной интеграции между компонентами, которая позволяет легко коррелировать различные типы данных.

**Типичный сценарий отладки:**

1.  **Метрики (Mimir/Prometheus):** Вы замечаете всплеск HTTP 5xx ошибок на дашборде в Grafana.
2.  **Переход к логам (Loki):** Прямо с панели метрик вы одним кликом переходите к логам за тот же период времени, отфильтрованным по соответствующим меткам (например, по имени сервиса и коду ошибки).
3.  **Анализ логов:** В логах вы видите конкретное сообщение об ошибке и находите `TraceID`, связанный с проблемным запросом.
4.  **Переход к трассировке (Tempo):** `TraceID` в логах является кликабельной ссылкой, которая мгновенно открывает полную трассировку запроса в Tempo.
5.  **Анализ трассировки:** Вы видите весь путь прохождения запроса через микросервисы, находите самый медленный участок или компонент, вернувший ошибку, и точно определяете корень проблемы.

Эта возможность быстро переключаться между "что случилось" (метрики), "почему случилось" (логи) и "где случилось" (трассировки) в едином интерфейсе является основой эффективной наблюдаемости и значительно сокращает время на диагностику и устранение инцидентов (MTTR).

### Практическая интеграция: от логов к трейсам

Ключевая возможность стека — бесшовный переход между данными. Например, увидев ошибку в логах, можно мгновенно перейти к соответствующей трассировке, чтобы понять полный контекст запроса.

Это настраивается в Grafana через **Derived Fields** в конфигурации источника данных Loki:

1.  **Перейдите в настройки источника данных Loki.**
2.  **Найдите раздел "Derived Fields".**
3.  **Добавьте новое правило:**
    *   **Name:** `TraceID` (или любое другое имя поля).
    *   **Regex:** `traceID=([a-zA-Z0-9]+)` (регулярное выражение для извлечения ID трассировки из строки лога).
    *   **URL:** `${__value.raw}` (это значение будет подставлено в запрос к Tempo).
    *   **Internal Link:** Укажите, что это внутренняя ссылка, и выберите ваш источник данных **Tempo**.

После этой настройки Grafana будет автоматически находить в логах поле `traceID`, делать его кликабельным и при нажатии выполнять поиск этой трассировки в Tempo, открывая ее в том же рабочем пространстве. Это значительно ускоряет отладку и анализ инцидентов.

## Интеграция с Prometheus: от данных к визуализации

После того как сбор метрик в Prometheus настроен, естественным шагом становится их визуализация. Хотя сам Prometheus имеет встроенный веб-интерфейс, он предназначен в первую очередь для отладки и выполнения разовых запросов на языке PromQL. Создавать в нем полноценные, сохраняемые дашборды для постоянного наблюдения неудобно, так как запросы приходится выполнять каждый раз заново.

Исторически для этих целей существовали другие инструменты, но со временем разработчики Prometheus сфокусировались на тесной интеграции с Grafana, которая стала отраслевым стандартом для визуализации данных.

**Ключевые аспекты интеграции:**

*   **Отличная совместимость:** Grafana имеет встроенный плагин для Prometheus, который обеспечивает глубокую интеграцию. Grafana "понимает" Prometheus "из коробки", позволяя легко подключать его как источник данных и выполнять запросы на PromQL.
*   **Готовые дашборды:** Огромное преимущество этой связки — большое количество готовых дашбордов для всевозможных экспортеров (например, `node-exporter`, `kube-state-metrics`), созданных сообществом. Это позволяет за считанные минуты развернуть полноценный мониторинг, просто импортировав нужный дашборд по его ID с официального сайта Grafana.
*   **Гибкость:** Grafana позволяет объединять на одном дашборде данные из нескольких источников, включая разные экземпляры Prometheus, что делает ее идеальным инструментом для построения единой панели мониторинга.
