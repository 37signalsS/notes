# Grafana

## Определения

**Grafana** — это open-source решение для визуализации и анализа данных, поступающих из различных источников. Она позволяет строить интерактивные графики и дашборды, а также настраивать оповещения (алерты). Ключевой принцип работы Grafana заключается в том, что она **не хранит данные**, а только запрашивает и визуализирует их из подключенных систем-хранилищ.

### Grafana Stack

**Grafana Stack** (ранее известный как LGTM: Loki, Grafana, Tempo, Mimir) — это набор инструментов, который реализует концепцию [современной наблюдаемости (observability)](../Concepts/Observability_and_Monitoring/observability_overview.md). Grafana выступает в роли центрального компонента этого стека, предоставляя единый интерфейс для анализа трех основных столпов наблюдаемости:
*   **Метрики** (собираемые Mimir или Prometheus)
*   **Логи** (собираемые Loki)
*   **Трассировки** (собираемые Tempo)

Основная цель стека — обеспечить бесшовный переход между этими типами данных для быстрой диагностики и решения проблем.

## Базовые концепции

### Архитектура, история и лицензирование

*   **Технологии:** Бэкенд написан на **Go**, фронтенд — на **TypeScript/React**.
*   **История:** Проект был запущен в 2014 году как форк Kibana 3, но быстро стал самостоятельным продуктом и де-факто стандартом для визуализации в сфере мониторинга.
*   **Лицензия:** Основные компоненты стека (Grafana, Mimir, Loki, Tempo) распространяются под лицензией **AGPLv3**. Это "вирусная" (copyleft) лицензия, которая требует, чтобы любые производные работы, предоставляемые как сервис, также были открыты под той же лицензией. Это обеспечивает вклад в Open Source сообщество.

### Единая архитектурная философия стека

Бэкенд-компоненты Grafana Stack (Mimir, Loki, Tempo) построены на общих принципах, что упрощает их администрирование:
*   **Язык:** Все написаны на **Go**.
*   **Режим развертывания:** Поддерживают запуск как в виде **монолита** (один бинарный файл), так и в виде **горизонтально масштабируемых микросервисов**.
*   **Хранилище:** Для долгосрочного хранения используют **объектные хранилища** (S3, GCS, MinIO), что удешевляет и упрощает хранение больших объемов данных.

### Основные возможности Grafana

*   **Визуализация:** Построение интерактивных дашбордов.
*   **Источники данных:** Поддержка множества систем, включая Prometheus, Elasticsearch, PostgreSQL и др. ([см. `grafana_datasources.md`](./grafana_datasources.md)).
*   **Плагины:** Расширение функциональности ([см. `grafana_plugins.md`](./grafana_plugins.md)).
*   **Алертинг:** Настройка и отправка оповещений ([см. `grafana_alerting.md`](./grafana_alerting.md)).
*   **Провиженинг:** Управление конфигурацией как кодом ([см. `grafana_provisioning.md`](./grafana_provisioning.md)).
*   **Управление доступом:** Гибкая система пользователей и ролей ([см. `grafana_user_management_and_authentication.md`](./grafana_user_management_and_authentication.md)).
*   **Высокая доступность:** Возможность развертывания в отказоустойчивом кластере ([см. `high_availability.md`](./high_availability.md)).
*   **Широкое применение:** Используется не только в IT, но и в IoT, промышленности и сельском хозяйстве.

## Практические сценарии

### Интеграция с Prometheus

Хотя Prometheus имеет собственный UI, он предназначен в основном для отладки и разовых запросов. Для постоянного мониторинга и создания полноценных дашбордов используется Grafana.

*   **Совместимость:** Grafana имеет встроенный плагин для Prometheus и "понимает" его "из коробки".
*   **Готовые дашборды:** Существует огромное сообщество и официальный репозиторий с тысячами готовых дашбордов для различных экспортеров (`node-exporter`, `kube-state-metrics`), которые можно импортировать по ID.
*   **Гибкость:** Grafana позволяет объединять на одном дашборде данные из нескольких источников, включая разные экземпляры Prometheus.

### Отладка с использованием Grafana Stack

Главная сила стека — в бесшовной интеграции между компонентами. Типичный сценарий отладки выглядит так:

1.  **Метрики (Mimir/Prometheus):** На дашборде замечен всплеск HTTP 5xx ошибок.
2.  **Переход к логам (Loki):** Одним кликом с панели метрик можно перейти к логам за тот же период времени, отфильтрованным по нужным меткам (имя сервиса, код ошибки).
3.  **Анализ логов:** В логах находится конкретное сообщение об ошибке и `TraceID`, связанный с проблемным запросом.
4.  **Переход к трассировке (Tempo):** `TraceID` в логах является кликабельной ссылкой, которая мгновенно открывает полную трассировку запроса.
5.  **Анализ трассировки:** В трассировке виден весь путь запроса через микросервисы, что позволяет найти самый медленный участок или компонент, вернувший ошибку.

Эта возможность быстро переключаться между "что случилось" (метрики), "почему случилось" (логи) и "где случилось" (трассировки) в едином интерфейсе является основой эффективной наблюдаемости. Технически это настраивается в Grafana через **Derived Fields** в конфигурации источника данных Loki, где с помощью регулярного выражения из лога извлекается `TraceID` и формируется внутренняя ссылка на источник данных Tempo.
